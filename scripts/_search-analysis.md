# Зведений аудит пошуку по сайту

## Що підтвердилось / що сумнівне (перевірка проти коду)

- **A1/C8b — конфлікт позиціювання кнопки** (`search.css:5` `position:fixed` vs скидання в `#reader-controls`): **підтверджено частково**. Fixed-правило в `search.css` реальне. Специфічність A порахував правильно (`#reader-controls > #search-btn` > `#search-btn`), але я **не бачив** `book.css:107-111` у цій сесії — не можу підтвердити, що там саме `position:static` для `#search-btn`. На `index.html` без `#reader-controls` кнопка справді падає на `body` як fixed. **Реалізовність висока, ризик — сумнівний бік (залежить від book.css).**
- **A2 — панель без `margin-bottom`**: **підтверджено** (`search.css:29` `margin:8vh auto 0`, `:28` `max-height:min(80vh,720px)`). 8vh+80vh=88vh — впритул. Реальний ризик обрізання на низькому вьюпорті / з клавіатурою.
- **A3/C3 — нема `@media`, нема мобільної адаптації**: **підтверджено** (жодного `@media` крім `prefers-reduced-motion`).
- **A5/B6 — Рівень-2 без сніпета й підсвітки**: **підтверджено** (`search.js:124` статичний рядок; `docs[i]` — лише токени, сніпет фізично неможливий).
- **A8/B10 — «60 результатів» бреше**: **підтверджено** (`slice(0,60)` на `:147`, а hint рахує `hits.length` **після** зрізу на `:130`). При 200 збігах покаже «60 результатів».
- **A11/C8c — плейсхолдер «ім'я»**: **підтверджено** (`:193` `placeholder="Тема, заголовок, ім’я…"`, а Рівень-1 шукає лише `title`+`h[]`).
- **B1 — Рівень-2 — bag-of-words по токенах, не підрядок/фраза**: **підтверджено** (`docs[i]` = `Array.from(tokens).sort().slice(...).join(" ")`, `build:129`; `searchFull` — `blob.indexOf(w)` по кожному слову з `every`). Це AND по словах без фрази/близькості. Токени <3 літер відсутні.
- **B2 — апострофна асиметрія**: **підтверджено, точний баг**. `norm()` (`search.js:26`) прибирає `'’ʼ`` → «зʼєднання»→«зєднання». `tokenize` (`build:64`) ділить по `[^0-9a-zа-яіїєґ]+`, апостроф = роздільник → «зʼєднання»→«з»(<3, викинуто)+«єднання». Запит «зєднання» не знайде «єднання». **Тихий клас пропущених результатів саме на укр-словах з апострофом.**
- **B3/B14 — гонка при повільному fetch fulltext**: **підтверджено концептуально**. Нема токена запиту/скасування; `loadFull().then(run)` (`:141`) перезапустить `run()` з поточним (можливо новішим) полем — тут переписування *старими* даними малоймовірне, бо `run` бере `el.input.value` наново. Реальніший баг — **подвійний-потрійний `run` у польоті** й миготіння «нічого не знайдено» до приходу FULL. **Пріоритет нижчий, ніж заявлено в B.**
- **B4/C1b — `kindPri` як первинний ключ сортування**: **підтверджено** (`rankSort:83` — `kindPri` первинний, `rank` вторинний). Слабкий guide б'є точний збіг назви книги. Це **дизайн-рішення** («курси головне»), а не баг, але для пошуку контрінтуїтивне.
- **B5 — нема індикатора завантаження Рівня-1**: **підтверджено** (`:134` `indexLoading.then(run)` без хінта при непорожньому запиті).
- **B7 — Enter при `cur<0` нічого не робить**: **підтверджено** (`:243`).
- **B8 — ARIA listbox неповний**: **підтверджено** (`role="listbox"`/`role="option"` є, але нема `aria-selected`/`aria-activedescendant`; `sm-active` — лише клас). Для незрячих навігація німа.
- **B9 — ArrowUp застряє на 0**: **підтверджено** (`:242` `Math.max(cur-1,0)`, не повертає в поле).
- **B11 — мін. 2 літери на слово тихо ріже**: **підтверджено** (`:136`). «pH», «C», одно-двобуквені позначення випадають.
- **C1 — НЕМА фільтра типу (book/guide/catalog)**: **підтверджено, головна проблема ІА**. `bookList()` (`:86-91`) групує лише по `e.b`/`e.bt`, ігноруючи `e.k`. Три типи змішані в одному ряду «книг». При цьому `kindPri` мовчки ранжує тип, яким користувач керувати не може.
- **C2 — `sec` = назва, не slug**: **підтверджено** (`build:150,178` пишуть `sec: sec.title`/`mod.title`). Фільтр по розділу порівнює `e.sec` (`:46,94`). У межах книги умова `e.b===book` рятує від колізій між книгами, але **ярлик «Усі розділи» семантично невірний** для guide (модулі) й catalog (родини).
- **C6 — нема лічильників у чипах, нульові не тьмяняться**: **підтверджено** (чипи будуються без підрахунку збігів).
- **C7 — стрибок висоти при появі ряду розділів**: **підтверджено** (`el.secs.hidden` перемикається, `:110-111`).
- **C8a — укр. форми числівника**: **частково**. У коді вже є трирівнева логіка (`1 результат` / `<5 результати` / інакше `результатів`, `:130`). Це **краще**, ніж описав C (він цитує спрощену форму), але все одно неточне: «22 результати» покаже «22 результатів». **C трохи перебільшив, але суть (неправильна укр-плюралізація по величині, а не по останній цифрі) вірна.**
- **A4 — стан «завантаження» майже невидимий**: **підтверджено** (лише текст у `.sm-hint`).
- **A9 — reflow-хак зайвий при reduced-motion**: **підтверджено, але це шум** (не баг).
- **A10 — `✕` текстовий гліф**: **підтверджено** (`:194`), косметика.
- **A6/C8 — крихта не розрізняє тип**: **підтверджено** (`:122` `bt · sec`, без бейджа типу).
- **B13 — нема укр-ізоморфізмів (і/й, ґ/г), діакритики**: **підтверджено** (`norm` лише lowercase + зняття апострофів). Очікуване обмеження.
- **C5 — фільтри переживають `close()`, нема «Скинути»**: **підтверджено** (`state.book/sec` не скидаються; нема reset-UI).
- **C8d — фасети без `aria-pressed`, без стрілок**: **підтверджено**.

**Дублікати між аудитами:** A1≈C8b (позиція кнопки) · A5≈B6 (Рівень-2 без сніпета) · A8≈B10 (брехливі «60») · A11≈C8c (плейсхолдер «ім'я») · A6≈C8a-badge (тип у крихті) · B4≈C1 (тип у ранжуванні vs фільтрі — різні кути тієї ж діри).

## 3. Рекомендований редизайн (особливо фільтрів)

### Модель фільтрів — дворівнева, типо-свідома

Індекс уже має `e.k` (`book`/`guide`/`catalog`) і `e.b`/`e.bt`. Цього достатньо для типу без зміни білдера.

**Рівень A — сегмент-перемикач типу** (новий, вгорі під полем):

```
[ Усе ]  [ Книги ]  [ Курси ]  [ Каталоги ]
```

- Джерело: унікальні `e.k`. Показувати сегмент лише якщо тип присутній в індексі.
- Обраний тип звужує список Рівня B і **фільтрує результати** (`passesFilter` додає `state.kind`).
- Це прибирає головну діру C1 і робить `kindPri`-ефект (F2) явним і керованим.

**Рівень B — «У межах»** (замість поточного ряду чипів усіх книг):

- Компактний **dropdown** (`<select>` або кастомний), заповнений лише сутностями обраного типу.
- Ярлик за типом: «У межах книги» / «У межах курсу» / «У межах каталогу».

**Рівень C — розділ/модуль/родина** (другий dropdown, з'являється при виборі B):

- Ярлик за типом: **«Розділ»** (book) / **«Модуль»** (guide) / **«Родина»** (catalog).
- Поки `sec` = назва — фільтрувати по назві в межах обраної книги (колізій між книгами нема, бо B звужує). `secSlug` — окремий крок P2-пріоритету, не блокер.

**Активні фасети** — pill-и з `✕` біля поля вводу + кнопка **«Скинути»** (закриває F6). `state` скидати на `close()` або лишати, але завжди **показувати активний стан помітно**.

**Лічильники** (F7) — на кожен чип/опцію рахувати збіги за поточним запитом; нульові — `disabled`+тьмяні. Рахувати дешево: один прохід `searchIndex(words)` без `passesFilter`, згрупувати по `e.k`/`e.b`/`e.sec`.

### «Шукати в тексті» (F5)

Винести **геть із рамки фільтрів** — окремий ряд/тумблер під полем, названий як режим:

```
[поле пошуку.....................]  ⌕
◻ Глибше — шукати й у тексті статей
```

### Структура модалки (згори вниз)

```
┌─ sm-head ────────────────────────────┐
│ ⌕  [input.....................]   ✕  │
├─ sm-mode ────────────────────────────┤   ← тумблер «Глибше»
├─ sm-typebar ─────────────────────────┤   ← сегмент типу (A)
```

# Кут C — «Фільтри й ІА»: проблеми пошуку

Пріоритет згори вниз. Файл/рядок вказано.

## 1. КРИТИЧНЕ: три типи контенту (book/guide/catalog) НЕ мають окремого фільтра — вони змішані в одному списку «книг»
`bookList()` (search.js:86-91) будує чипи з `e.b`/`e.bt` **без огляду на `e.k`**. Курси (`guide`) і каталоги (`catalog`) стоять у тому самому ряду чипів, що й предметні книги, як рівноправні «книги». Для користувача це прямо суперечить ІА сайту, де три теки — три різні сутності (`CLAUDE.md`). Немає способу сказати «шукай лише в курсах» або «лише в каталогах». А `kindPri` (search.js:82) при цьому мовчки штовхає всі guide-результати нагору — тобто тип КОНТЕНТУ впливає на ранжування, але користувач не може ним КЕРУВАТИ. Напрям: додати верхній ряд-перемикач типу (Усе · Книги · Курси · Каталоги) на базі `e.k`, а список «книг» звужувати під обраний тип.

## 2. КРИТИЧНЕ: розділи (`sec`) — це **назви**, не slug'и, тож однойменні розділи різних книг злипаються / чужі не відсіюються коректно
`secList(book)` (search.js:92-96) і `passesFilter` (search.js:44-48) порівнюють `e.sec` — це `sec.title` (build-search-index.js:150,178), не унікальний ключ. Дві книги можуть мати розділ з однаковою назвою (напр. «Основи», «Вступ»), і фільтр по розділу в межах книги ще працює (бо додано умову `e.b===book`), АЛЕ у guide `sec` = `mod.title` — назви модулів курсів довгі й несумісні за природою з «розділами» книг. Сам ярлик «Усі розділи» (search.js:107) семантично невірний для курсу (там модулі) і для каталогу (там родини за функцією). Напрям: індексувати `secSlug` окремо від `secTitle`, фільтрувати по slug, показувати title; ярлик другого рівня робити залежним від типу («Розділи» / «Модулі» / «Родини»).

## 3. Фільтри показані ПОСТІЙНО, ще до вводу запиту — займають місце й пропонують гортати ~15+ книг без контексту
`.sm-filters` рендериться на `open()` (search.js:164) і завжди видимий. При порожньому полі користувач бачить довгий wrap-ряд чипів усіх книг (search.css:55 `flex-wrap`) над порожнім результатом — це шум, а не поміч. Кращий патерн пошуку: фільтри згорнуті/компактні, доки нема запиту, або винесені в один компактний селект «У межах: [Усе ▾]». Напрям: ховати ряди чипів до першого вводу або згорнути у dropdown.

## 4. Взаємодія «шукати в тексті» × фільтри непослідовна для порожнього стану, і чекбокс візуально відірваний
Галочка `.sm-intext` (search.js:199) стоїть у блоці фільтрів, але це НЕ фільтр — це зміна ГЛИБИНИ пошуку (Рівень 1 vs 2). Змішування в одній рамці «Фільтри» вводить в оману: користувач думає, що це ще один фасет. Крім того, при увімкненій галочці й порожньому запиті нічого не відбувається (правильно), але підказка про це мовчить. Напрям: винести галочку з рамки фільтрів (окремий ряд під полем або тумблер «Глибше»), назвати як дію-режим, а не фасет.

## 5. Обрані фільтри «зникають» при закритті модалки лише частково — стан книги/розділу переживає закриття, але користувач не бачить, що фільтр досі активний
`state.book`/`state.sec` (search.js:17) не скидаються на `close()`. Наступне відкриття покаже старий фільтр активним (чип `.on`), але якщо ряд розділів був згорнутий поза видимістю або книга далеко в wrap — легко не помітити, чому результатів мало. Немає зведеного «скинути фільтри» / індикатора «фільтр активний». Напрям: показувати активний фасет як помітний pill з ✕ біля поля вводу, плюс кнопка «Скинути».

## 6. Немає лічильників у чипах — користувач фільтрує наосліп
Чипи книг/розділів (search.js:97-98) не показують, скільки статей у кожній, тож вибір фільтра — здогад. Ба більше, чипи для книг, де за поточним запитом 0 збігів, не притлумлюються — можна тицьнути книгу й отримати порожньо. Напрям: рахувати збіги на фасет для поточного запиту, показувати число, disable/тьмянити нульові.

## 7. Другий ряд (розділи) з'являється лише коли обрано книгу — стрибок висоти панелі
`el.secs.hidden` перемикається в `renderFilters` (search.js:110-111). Вибір книги раптово вставляє новий ряд чипів, зсуваючи результати вниз — смикається лейаут під час читання. Дрібне, але помітне на кожному кліку по книзі. Напрям: резервувати місце або анімувати розкриття.

## 8. Косметика/дрібне
- `renderResults` крихкі укр. форми: `hits.length + ' результати'` дасть «1 результат», «2 результати», але «22 результатів» замість «22 результати» — правило по останній цифрі, не по величині (search.js:130).
- Крихта: `#search-btn` жорстко `right: 3.9rem` під `#theme-btn` (search.css:5) — якщо в `#reader-controls` на index.html інша розкладка, лупа може накластися.
- Плейсхолдер «Тема, заголовок, ім'я…» (search.js:193) обіцяє пошук по «імені», але індекс не має поля осіб — оманлива обіцянка.
- Фільтри не мають клавіатурної навігації (Tab по чипах працює, але стрілки — лише в результатах), і немає `aria-pressed` на активних чипах — доступність фасетів кульгає.
