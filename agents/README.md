# Правила для оркестраторів

Над репозиторієм працюють **два оркестратори**, і кожен має свій спосіб запускати агентів.
Щоб правила не змішувались, вони розкладені так:

```
AUTHORING.md          ← СПІЛЬНИЙ канон письма (§1–§9). Читають ОБИДВА. Єдине джерело правди.
AUTHORING.en.md       ← той самий канон англійською (з нього ріжеться зріз для агентів)
AUTHORING.write.en.md ← зріз канону для письменників (генерований, у .gitignore)

CLAUDE.md             ← точка входу Claude Code (вантажиться автоматично)
AGENTS.md             ← точка входу Antigravity (вантажиться автоматично)

.agents/              ← ОПЕРАЦІЙНІ файли Antigravity: саме їх читає сам інструмент
  rules/*.md          ← правила з `trigger: always_on` — у контексті КОЖНОГО агента, ≤12000 симв.
  agents/<name>/agent.md ← опис сабагента (name, description, tools, subagent, mainAgent, model…)
  workflows/*.md      ← слеш-команди (`/write-batch`)

agents/               ← пояснювальні документи ДЛЯ ЛЮДИНИ, інструмент їх сам не вантажить
  README.md           ← цей файл: карта й спільні правила
  claude/             ← оркестрація Claude Code (воркфлоу-скрипти)
  antigravity/        ← розгорнутий довідник конвеєра (таблиця перевірок, «чому саме так»)
```

⚠️ **Не плутати `.agents/` і `agents/`.** Перша тека — робоча: Antigravity вантажить `rules/`
сам і бачить `agents/` та `workflows/`. Друга — для людини й для другого оркестратора. Якщо
операційне правило лежить лише в `agents/`, воно не діє: інструмент туди не заглядає, доки
йому не скажуть.

**Правило розкладки:** правило, яке стосується **письма чи змісту**, живе в `AUTHORING.md` і
є спільним. Правило, яке стосується **того, як запускати агентів**, живе у відповідній підтеці —
бо механізми в оркестраторів різні й несумісні.

## Спільне для обох — коротко

Повністю — в `AUTHORING.md`. Тут лише те, що ламається найчастіше.

**Маніфест — єдине джерело правди.** Один на книгу. Статуси на КОЖНУ версію: `done` (написано)
· `pending` (треба написати) · `empty` (писати не треба) · `update` (переписати). Міняти статус
одразу після правки. Нова тема заводиться `basic:empty` + `detailed:pending`.

**Обсяги (§3):** базова 500–1200 · детальна 1000–6500 · вставка 400–5000. Виняткова стеля 9000.
Допуск ±10% на смуги **й** на пороги. Скорочувати текст заради проходження гейта — заборонено.

⚠️ **Antigravity має власні множники обсягу: ×1.30 загалом, ×1.40 на детальну, ×1.60 на `api-`**
(детальна: орієнтир 2950–3650; `api-`: 1600–3200). Це не
розходження в каноні, а запас на глибину: рівно стільки, щоб велика тема не билася в стелю. Смуги
підняті в обидва боки, відношення «базова ≤ ½ детальної» лишається як є. Множник в одному
місці — `CHECKS_SCALE` у `scripts/checks/_lib.js`, таблиця — в `agents/antigravity/pipeline.md §4`.
Claude пише за канонними смугами.

Шлях множника: ×1.35 → ×1.15 (2026-08-12) → ×1.30 (2026-08-14). Зрізали, бо зайві відсотки йшли
не в глибину, а в переказ власних вставок — стаття вдруге розповідала те, що вже стоїть у її ж
`hist-` і `proj-`. Повернули, коли коло суду подешевшало в рази (один суддя замість шести,
стеля два кола): тепер довша стаття коштує саме як довша стаття, а не як шість її читань.
Заборона переказувати власні вставки лишається чинною — вона й була справжнім лікуванням.

**Формули (§5): БЕЗ LaTeX узагалі.** У рушії немає математичного рендерера — ні KaTeX, ні MathJax
(`grep -c katex book.js` → 0). Коротке позначення в прозі → інлайн-код; формула → код-блок,
вирівняний по `=`, з підписом кроку у квадратних дужках.

**Код (§5): є C — має бути й C++.** Приклад мовою C завжди дістає сусідню вкладку C++ у тому
самому `:::tabs`, і переклад мусить бути ідіоматичним (`malloc`/`free` → контейнер чи
`unique_ptr`, `goto out` → RAII, `char*` + довжина → `span`). Три винятки, і лише вони: простір
ядра · приклад про сам C як мову · чужий заголовок як цитата. В Antigravity це судить перевірка
17 (судить `check-all`); у Claude правило приходить письменникам зрізом `AUTHORING.write.en.md`, а
локально ловиться тим самим `node scripts/checks/17-cpp.js <тека>`.

**Фігури (§5):** лише в підтеці `img/`, імена kebab-case, генеруються `figs.py` через `svgkit`.
Правити треба `figs.py` і перегенеровувати, а не редагувати `.svg` руками.

**Вставки (§6):** кожна вставка теми мусить бути **згадана в прозі** ref-лінком
`topic:<книга>/<тема>/<файл>.md`. Не згадана — читач її не відкриє ніколи.

**Мова (§4):** жива українська, без русизмів і кальок; один термін на поняття; термін
уводиться **після** механізму, а не перед ним.

## Спільні скрипти — `scripts/`

Ці кличуть обидва оркестратори:

| скрипт | що робить |
|---|---|
| `textcheck.js` | LaTeX · гомогліфи · русизми · **текст усередині SVG** · фігури · обсяг |
| `linkcheck.js` | биті лінки й `topic:`-цілі по всьому корпусу |
| `wordcount.js` | проза за §3 + пари базова↔детальна |
| `svgcheck.py` | геометрія фігур, накладання тексту, `--links` |
| `svgkit.py` | генератор фігур (імпортує `figs.py` кожної теми) |
| `manifest-patch.js` | детермінований редактор маніфесту + попередження про дублі |
| `batch-state.js` | звірка диск↔маніфест після урваного прогону |
| `bookbuild.js` | адаптер маніфест→рушій |
| `make-writer-canon.js` | зріз канону для письменників |

Скрипти, специфічні для одного оркестратора, лежать у `scripts/claude/`, `scripts/antigravity/`
і `scripts/checks/` (конвеєр Antigravity). Чужу теку не чіпає ніхто.

**Маніфест правиться раз на батч і лише наприкінці.** У Claude це фаза «Маніфест» у
`write-batch.js`, в Antigravity — `finish-batch.js` після `gate = 0` по всіх темах. Обидва
кличуть той самий `manifest-patch.js`; руками маніфест не редагує ніхто й ніколи.
