# Оркестрація — Claude Code

Правила запуску агентів **лише для Claude Code**. Правила письма — спільні, у `AUTHORING.md`.
Механізм тут інший, ніж в Antigravity: воркфлоу-скрипт замість `invoke_subagent`.

## Механізм

Багатоагентна робота запускається як **воркфлоу**:

```
Workflow scriptPath="scripts/claude/<name>.js"  args={…}
```

Скрипт — звичайний JS із `export const meta = {name, description, phases}` і тілом, де доступні
`agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`. Кожен `agent()` — окремий сабагент зі
своїм контекстом; `schema` змушує його повернути валідний JSON, а не вільний текст.

**`pipeline()` за замовчуванням, `parallel()` лише коли справді потрібні всі результати разом.**
Бар'єр коштує реального часу: якщо один агент утричі повільніший за інших, решта простоює.

## Воркфлоу репозиторію

| скрипт | що робить |
|---|---|
| `write-batch.js` | повний батч письма: канон → скаут → детальні → базові → вставки → фігури → маніфест → контроль |
| `review-batch.js` | перевірка написаного: агент на теку, механіка + звірки зі змісту |
| `adjudicate-batch.js` | розсуд ескалацій: доводить джерелом і править |
| `svgfix-prep.js` / `svgfix-apply.js` | дешева правка фігур агентами, коли локального замало |
| `recheck-*.js` | кампанія перегляду корпусу за чинними правилами |

## Конкурентність і ліміти

**Пул ≤4 на батч письма.** Навмисно: коли ліміт сесії вичерпується, падає щонайбільше кілька
агентів, а не весь фронт. Історія: 2026-08-02 пул без обмеження дав **285 мертвих агентів із
382** — кожен устигав прочитати канон, упертись у стіну й померти.

Для **перевірки** пул можна піднімати до 16 — вона вчетверо дешевша за письмо (виміряно
2026-08-11: письмо 465k токенів на статтю, перевірка 21k).

**Стіна ліміту = СТОП.** Перша підозра → одна пауза 5 хв і ОДНА повторна спроба; мовчить
удруге → прапорець `WALL`, нові агенти не стартують, прогін завершується `aborted:true`.
Написане лишається на диску; піднімати — `scripts/batch-state.js`.

## Ізоляція

**Маніфест один на книгу → ізоляція по книзі.** Два паралельні прогони можливі лише якщо кожен
у своїй книзі. Двох батчів на одну книгу не запускати — спільний маніфест.

## Відновлення після зриву

```bash
node scripts/batch-state.js --book <slug> --kind <вид>
```

Звіряє **ДИСК** (джерело правди, не журнал прогону: вбитий агент часто вже записав файл, а
результату не повернув) з маніфестом. Показує: статті на диску зі статусом ≠`done` · `pending`
без файлу · вставки на диску, яких нема в маніфесті · вставки, обіцяні в прозі, але ненаписані.
З `--apply` реєструє написане.

## Дисципліна

- **Батчі не запускаються без прямої команди.** Ліміт витрачає користувач; «оціни стан» ≠ «запусти».
- **Комітів не робити й не пропонувати.** Коміти — виключно користувач. `git mv`/`status`/`diff` — можна.
- **Великий крок делегується сабагенту** з повними шляхами; у головну сесію — короткий звіт.
- **Локальні гейти після письма.** Фаза «Контроль» у `write-batch.js` ганяє `wordcount.js`
  (§3-обсяг і пари база↔деталь), `svgcheck.py` (фігури) і `17-cpp.js` (§5: є C — має бути й
  C++). Перевірки з `scripts/checks/` — конвеєр Antigravity, але скрипти спільні: `17-cpp.js`
  запускається окремо по будь-якій теці й нічого від конвеєра не потребує.
- **Локальний оракул б'є агентів.** Є дешевий чек — лагодь у генераторі й ітеруй локально.
  Агент без циклу зворотного зв'язку майже марний: 2026-08-03 локальні проходи дали −1540
  зауважень, агенти без чеку — −16 за 2.35 млн токенів.
