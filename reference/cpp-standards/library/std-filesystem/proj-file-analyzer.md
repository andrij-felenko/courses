# ⚙️ Проект: Кросплатформовий сканер та аналізатор файлової системи

Ця проєктна вставка демонструє розробку законченого, високпродуктивного кросплатформового модуля аналізу дискового простору та аудиту прав доступу на базі модуля файлової системи стандартної бібліотеки. У тексті детально розбирається практична задача побудови службової утиліти для рекурсивного сканування каталогів, обчислення обсягу файлів за їх розширеннями, відстеження небезпечних прав доступу та виявлення циклічних символьних посилань.

## 1. Постановка задачі та системні вимоги до аналізатора

При розробці системних утиліт обробки дискового простору (наприклад, аналогів консольних утиліт аналізу диска або автоматизованих сканерів безпеки) перед розробником виникає ціла низка фундаментальних системних проблем, які вимагають ретельно продуманої архітектури:

1. Необроблені винятки при відмові доступу: Якщо під час рекурсивного обходу деревоподібної структури диска сканер натрапляє на каталог із обмеженими правами читання (наприклад, системний каталог операційної системи або каталог іншого користувача), стандартний виклик ітератора кидає виняток і примусово перериває роботу всього процесу.
2. Зациклення на символьних посиланнях: Якщо каталог містить рекурсивне символьне посилання сам на себе або на один із батьківських каталогів, необдумане слідування посиланнями призводить до безкінечної рекурсії, переповнення обчислювального стеку або вичерпання дескрипторів відкритих файлів ядра операційної системи.
3. Накладні витрати на повторні системні виклики: Застосування окремих операцій перевірки існування файлу та визначення його розміру для кожного знайденого шляху робить окремі виклики до ядра операційної системи, що уповільнює обхід диска в кілька разів порівняно з зчитуванням кешованих даних із елемента каталогу.
4. Кросплатформова підтримка юнікодних імен файлів: Програма повинна коректно обробляти шляхи, що містять символи кирилиці, ієрогліфами та пробіли як у Unix-подібних системах, так і в операційній системі Windows.

Для вирішення усіх цих проблем ми спроєктуємо та реалізуємо клас аналізатора файлової системи, який використовує двокамерний API із кодами помилок без використання винятків, спеціальні прапорці пропуску помилок доступу та кешовані елементи каталогу.

```
Структура роботи сканера аналізатора файлової системи:
Вхідний шлях до об'єкта
  │
  ├──► Перевірка існування та статусу шляху без винятків
  │
  ├──► Отримання метрик загальної ємності та вільного простору диска
  │
  └──► Запуск рекурсивного ітератора обходу каталогів із прапорцем skip_permission_denied
         │
         ├──► Перевірка типізації елемента з внутрішнього кешу
         ├──► Накопичення статистики розмірів за розширеннями у хеш-таблиці
         ├──► Перевірка небезпечних прав доступу для інших користувачів
         └──► Детекція символьних посилань та виявлення висячих посилань
```

## 2. Повна реалізація аналізатора на C++

Нижче наведено повний реальний код модуля аналізу, який розбиває процес обходу дискового накопичувача на декілька послідовних етапів: швидке вимірювання залишку пам'яті на диску та рекурсивне агрегування метрик.

```cpp
#include <iostream>
#include <filesystem>
#include <string>
#include <vector>
#include <unordered_map>
#include <algorithm>
#include <iomanip>
#include <system_error>
#include <sstream>

namespace fs = std::filesystem;

// Структура підсумкових результатів аудиту файлової системи
struct AnalysisResult {
    std::uintmax_t total_bytes{0};
    std::uintmax_t total_files{0};
    std::uintmax_t total_directories{0};
    std::uintmax_t total_symlinks{0};
    std::uintmax_t skipped_errors{0};

    // Розподіл зайнятої пам'яті за розширеннями файлів
    std::unordered_map<std::string, std::uintmax_t> extension_bytes;

    // Список виявлених небезпечних файлів з відкритими правами
    std::vector<fs::path> insecure_files;

    // Найбільший знайдений файл під час сканування
    fs::path largest_file_path;
    std::uintmax_t largest_file_size{0};
};

class FileSystemAnalyzer {
public:
    explicit FileSystemAnalyzer(fs::path target_path)
        : target_root_(std::move(target_path)) {}

    // Головний метод запуску повного сканування
    AnalysisResult analyze() {
        AnalysisResult result;
        std::error_code ec;

        // Крок 1: Перевірка існування та статусу базового шляху
        fs::file_status root_status = fs::status(target_root_, ec);
        if (ec || !fs::exists(root_status)) {
            std::cerr << "[Помилка] Вказаний шлях не існує або недоступний: " 
                      << target_root_ << " (" << ec.message() << ")\n";
            return result;
        }

        // Крок 2: Отримання загальної інформації про дисковий простір
        fs::space_info disk_info = fs::space(target_root_, ec);
        if (!ec) {
            std::cout << "--- Інформація про дисковий розділ ---\n"
                      << " Загальна ємність: " << format_size(disk_info.capacity) << "\n"
                      << " Вільний простір:  " << format_size(disk_info.free) << "\n"
                      << " Доступно користувачу: " << format_size(disk_info.available) << "\n"
                      << "----------------------------------------\n";
        }

        // Якщо переданий шлях вказує на одиночний файл
        if (fs::is_regular_file(root_status)) {
            process_file(target_root_, result);
            return result;
        }

        // Крок 3: Налаштування рекурсивного обходу із захистом від відмови доступу
        auto options = fs::directory_options::skip_permission_denied;
        
        fs::recursive_directory_iterator it(target_root_, options, ec);
        fs::recursive_directory_iterator end_it;

        if (ec) {
            std::cerr << "[Помилка] Неможливо відкрити початковий каталог: " << ec.message() << "\n";
            return result;
        }

        while (it != end_it) {
            const fs::directory_entry& entry = *it;

            // Безпечно отримуємо статус символьного посилання із внутрішнього кешу
            fs::file_status status = entry.symlink_status(ec);
            if (ec) {
                result.skipped_errors++;
                it.increment(ec);
                continue;
            }

            // Обробка символьних посилань
            if (fs::is_symlink(status)) {
                result.total_symlinks++;
                // Перевірка на висяче посилання (dangling symlink)
                fs::file_status target_st = entry.status(ec);
                if (ec || !fs::exists(target_st)) {
                    std::cout << "[Увага] Виявлено висяче символьне посилання: " 
                              << entry.path() << "\n";
                }
            }
            // Обробка звичайних файлів
            else if (fs::is_regular_file(status)) {
                result.total_files++;
                std::uintmax_t sz = entry.file_size(ec);
                if (!ec) {
                    result.total_bytes += sz;
                    
                    // Групування обсягу за розширенням файлу
                    std::string ext = entry.path().extension().string();
                    std::transform(ext.begin(), ext.end(), ext.begin(), ::tolower);
                    if (ext.empty()) ext = "[без розширення]";
                    result.extension_bytes[ext] += sz;

                    // Фіксація найменшого та найбільшого файлу
                    if (sz > result.largest_file_size) {
                        result.largest_file_size = sz;
                        result.largest_file_path = entry.path();
                    }
                }

                // Перевірка безпеки прав доступу: чи відкритий файл на запис для сторонніх
                if ((status.permissions() & fs::perms::others_write) != fs::perms::none) {
                    result.insecure_files.push_back(entry.path());
                }
            }
            // Обробка каталогів
            else if (fs::is_directory(status)) {
                result.total_directories++;
            }

            // Безпечний перехід до наступного елемента без викидання винятків
            it.increment(ec);
            if (ec) {
                result.skipped_errors++;
                ec.clear();
            }
        }

        return result;
    }

    // Допоміжний метод форматування байтів у людський вигляд
    static std::string format_size(std::uintmax_t bytes) {
        constexpr double KB = 1024.0;
        constexpr double MB = KB * 1024.0;
        constexpr double GB = MB * 1024.0;

        std::ostringstream ss;
        ss << std::fixed << std::setprecision(2);
        if (bytes >= GB) ss << (bytes / GB) << " GB";
        else if (bytes >= MB) ss << (bytes / MB) << " MB";
        else if (bytes >= KB) ss << (bytes / KB) << " KB";
        else ss << bytes << " B";
        return ss.str();
    }

private:
    void process_file(const fs::path& p, AnalysisResult& res) {
        std::error_code ec;
        auto sz = fs::file_size(p, ec);
        if (!ec) {
            res.total_files = 1;
            res.total_bytes = sz;
            res.extension_bytes[p.extension().string()] = sz;
            res.largest_file_path = p;
            res.largest_file_size = sz;
        }
    }

    fs::path target_root_;
};
```

## 3. Детальний розбір алгоритмічних кроків аналізатора

Процес сканування побудовано на трьох фундаментальних принципах продуктивності та надійності:

По-перше, використання прапорця пропуску помилок доступу дозволяє ітератору рекурсивного обходу автоматично ігнорувати ті каталоги диска, до яких у поточного користувача немає прав читання. Замість зупинки всієї програми або генерації винятку, ітератор просто пропускає захищену гілку і продовжує обхід сусідніх каталогів.

По-друге, використання методу збільшення ітератора із параметром коду помилки гарантує, що при виникненні будь-яких системних збоїв (наприклад, зникнення файлу безпосередньо під час обходу) код помилки записується у передану змінну, дозволяючи програмі збільшити лічильник пропущених помилок і продовжити сканування.

По-третє, зчитування типу файлу та його розміру виконується безпосередньо з об'єкта кешованого елемента каталогу. Під час сканування системного диска операційна система вже повертає атрибути файлу разом із його іменем у системній структурі обходу. Звернення до методів кешованого елемента не створює нових системних викликів до ядра, що зменшує навантаження на дисковий накопичувач у кілька разів.

Агрегація статистики розмірів за розширеннями файлів виконується через хеш-таблицю. Кожне розширення переводиться у нижній регістр символів для нормалізації однакових типів файлів у різних реєстрах.

## 4. Порівняльний аналіз реалізацій: C++ проти POSIX C API

Для того щоб оцінити переваги сучасного об'єктного підходу стандартної бібліотеки, порівняємо код обходу каталогів із класичною реалізацією мовою C під Unix-подібні системи.

:::tabs
```c
// POSIX C: Рекурсивний розбір каталогу
#include <sys/stat.h>
#include <dirent.h>
#include <stdio.h>
#include <string.h>

void scan_posix_dir(const char* dir_path) {
    DIR* dir = opendir(dir_path);
    if (!dir) return; // Ручне керування ресурсом!

    struct dirent* entry;
    while ((entry = readdir(dir)) != NULL) {
        if (strcmp(entry->d_name, ".") == 0 || strcmp(entry->d_name, "..") == 0)
            continue;

        char full_path[1024];
        snprintf(full_path, sizeof(full_path), "%s/%s", dir_path, entry->d_name);

        struct stat st;
        if (lstat(full_path, &st) == 0) {
            if (S_ISDIR(st.st_mode)) {
                scan_posix_dir(full_path); // Небезпека переповнення стеку
            } else if (S_ISREG(st.st_mode)) {
                printf("File: %s, Size: %lld\n", full_path, (long long)st.st_size);
            }
        }
    }
    closedir(dir); // Обов'язкове звільнення дескриптора!
}
```

Натомість реалізація мовою C++ повністю бере на себе управління ресурсами за принципом зв'язування ресурсів із часом життя об'єктів. Деструктор ітератора автоматично закриває усі відкриті системні дескриптори каталогів при виході з області видимості, а об'єкт шляху автоматично керує пам'яттю під текст шляху.

## 5. Аналіз складних крайових випадків та виробничих пасток

Під час практичної експлуатації аналізатора файлової системи на реальних дискових масивах розробник зустрічається з цілою низкою складних крайових випадків.

Перша виробнича пастка полягає у виявленні висячих символьних посилань. Висяче символьне посилання — це спеціальний файл посилання, який вказує на шлях, що був видалений або переміщений. Якщо програма намагається отримати статус або розмір цільового файлу через таке посилання, операційна система повертає помилку відсутності файлу. У коді нашого аналізатора ми спочатку перевіряємо статус самого посилання через спеціальний метод опитування статусів посилань, і лише переконавшись у тому що це посилання, намагаємося розв'язати його цільовий об'єкт.

Друга пастка пов'язана з так званою гонкою умов у файловій системі. Файлова система є динамічним зовнішнім середовищем, вміст якого постійно змінюється іншими паралельними процесами операційної системи. Між моментом, коли ітератор прочитав ім'я файлу з каталогу, і моментом, коли аналізатор викликає метод отримання розміру цього файлу, файл може бути видалений або переміщений іншою програмою. Якщо використовувати версії методів без коду помилки, програма впаде з винятком. Застосування методів із параметром коду помилки дозволяє програмі перехопити системний збій, збільшити лічильник пропущених помилок і продовжить сканування диска без зупинки.

Третя пастка стосується роботи з монтованими файловими системами та мережевими дисками. У Unix-подібних системах віртуальні файлові системи ядра (такі як системи оперативної інформації про процеси та пристрої) містять файли нульового розміру, які при читанні повертають динамічно згенерований текст. При опитуванні вільного простору на таких віртуальних розділах система може повертати нульову ємність. Сканер повинен коректно обробляти такі значення і не вважати їх критичною помилковою ситуацією.

Четверта пастка стосується обробки прав доступу та виявлення небезпечних файлів. У системі Unix права доступу розбиваються на групи власника, групи та всіх інших користувачів. Наш сканер перевіряє битову маску прав доступу і фіксує ті файли, які мають відкритий прапорець запису для всіх сторонніх користувачів, що дозволяє виконувати автоматизований аудит безпеки дискових масивів.

Завдяки дотриманню викладених архітектурних принципів, побудований модуль аналізу дискового простору демонструє абсолютну стабільність, високу швидкість обходу та повну безпеку роботи на будь-яких операційних системах.
