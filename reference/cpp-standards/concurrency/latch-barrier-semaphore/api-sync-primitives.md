# 📋 Повна довідка API: latch, barrier та semaphore у C++20

Ця довідкова вставка містить вичерпний контрактний опис інтерфейсів примітивів низькорівневої синхронізації стандарту C++20, що містяться у заголовках `<latch>`, `<barrier>` та `<semaphore>`. Для кожного класу наведено точні сигнатури конструкторів, методів та типів-членів, вимоги до параметрів (попередні умови), гарантії результату (постумови), часову складність, безпеку щодо винятків та взаємодію з моделлю пам'яті C++.

---

## 1. Заголовок `<latch>`

Заголовок `<latch>` визначає клас `std::latch` — некопійований і непереміщуваний примітив одноразового зворотного відліку.

### Оголошення класу

```cpp
namespace std {
    class latch {
    public:
        static constexpr ptrdiff_t max() noexcept;

        constexpr explicit latch(ptrdiff_t expected);
        ~latch();

        latch(const latch&) = delete;
        latch& operator=(const latch&) = delete;

        void count_down(ptrdiff_t update = 1);
        bool try_wait() const noexcept;
        void wait() const;
        void arrive_and_wait(ptrdiff_t update = 1);

    private:
        /* implementation-defined стан */
    };
}
```

### Статичні члени

#### `static constexpr ptrdiff_t max() noexcept;`
- **Призначення:** повертає максимальне значення лічильника, яке підтримує поточна реалізація стандартної бібліотеки.
- **Гарантія стандарту:** значення гарантовано не менше ніж `std::numeric_limits<ptrdiff_t>::max() / 2`. На більшості 64-бітних платформ (x86-64, AArch64) це значення збігається з `PTRDIFF_MAX` (тобто `2⁶³ - 1` або приблизно `9.22 × 10¹⁸`).
- **Складність:** `O(1)`, обчислюється під час компіляції (`constexpr`).
- **Безпека винятків:** `noexcept`.

---

### Конструктор та деструктор

#### `constexpr explicit latch(ptrdiff_t expected);`
- **Призначення:** створює об'єкт засува з початковим значенням лічильника `expected`.
- **Попередні умови (Preconditions):**
  1. `expected >= 0` (значення не може бути від'ємним).
  2. `expected <= max()` (значення не перевищує апаратний ліміт реалізації).
- **Поведінка:**
  - Якщо `expected > 0`, засув створюється у зачиненому стані; наступні виклики `wait()` блокуватимуть потоки.
  - Якщо `expected == 0`, засув одразу створюється у відчиненому стані; виклики `wait()` повертатимуться миттєво без блокування.
- **Безпека винятків:** не викидає винятків (`noexcept`).
- **Складність:** `O(1)`, звичайна ініціалізація атомарного поля в пам'яті.

#### `~latch();`
- **Призначення:** знищує об'єкт засува.
- **Попередні умови:** жоден потік виконання не повинен перебувати всередині викликів методів цього засува (`count_down`, `wait`, `try_wait`, `arrive_and_wait`).
- **Невизначена поведінка (UB):** знищення об'єкта `std::latch`, на якому хоча б один потік заблокований у `wait()` або виконує `count_down()`, призводить до невизначеної поведінки системи (спроба звернення до звільненої адреси або пошкодження черги futex ядра).

---

### Методи керування станом

#### `void count_down(ptrdiff_t update = 1);`
- **Параметри:** `update` — ціле число, на яке слід зменшити лічильник (за замовчуванням `1`).
- **Попередні умови:**
  1. `update >= 0`.
  2. `update` не перевищує поточне значення внутрішнього лічильника засува (`update <= counter`).
- **Поведінка:**
  - Атомарно віднімає `update` від внутрішнього лічильника.
  - Якщо в результаті операції лічильник досягає нуля (`0`), розблоковує всі потоки, які перебувають у стані очікування у викликах `wait()`.
  - Потік, що викликав `count_down()`, ніколи не блокується і негайно продовжує виконання.
- **Впорядкування пам'яті:** операція має семантику `memory_order_release`. Вона синхронізується з будь-яким викликом `wait()`, що завершив очікування внаслідок цього обнулення.
- **Складність:** `O(1)` для самого декременту; `O(N)` для системного пробудження `N` сплячих потоків у черзі ядра.
- **Невизначена поведінка:** якщо передано `update > counter` (переповнення лічильника знизу), поведінка програми невизначена.

#### `bool try_wait() const noexcept;`
- **Призначення:** неблокуюча перевірка того, чи досяг лічильник нуля.
- **Повертане значення:**
  - `true` — якщо лічильник дорівнює `0` (засув відчинено).
  - `false` — якщо лічильник строго більший за `0` (засув зачинено).
- **Впорядкування пам'яті:** якщо метод повертає `true`, операція має семантику `memory_order_acquire`. Якщо повертає `false` — `memory_order_relaxed`.
- **Складність:** `O(1)`, одне атомарне читання з пам'яті (затримка 1–3 нс).
- **Безпека винятків:** `noexcept`.

#### `void wait() const;`
- **Призначення:** переводить викликаючий потік у стан очікування до моменту, поки внутрішній лічильник не зменшиться до нуля.
- **Поведінка:**
  - **Швидкий шлях (Fast Path):** якщо лічильник уже дорівнює `0`, метод негайно повертає керування без системних викликів.
  - **Повільний шлях (Slow Path):** якщо лічильник більший за `0`, потік звертається до ядра операційної системи (`futex` у Linux або `WaitOnAddress` у Windows) і переходить у режим сну.
- **Впорядкування пам'яті:** вихід із методу `wait()` має семантику `memory_order_acquire`.
- **Складність:** `O(1)` на швидкому шляху; затримка перемикання контексту ядра при переході в сон.

#### `void arrive_and_wait(ptrdiff_t update = 1);`
- **Призначення:** атомарне зменшення лічильника з подальшим очікуванням відчинення засува.
- **Еквівалентна дія:**
  ```cpp
  count_down(update);
  wait();
  ```
- **Попередні умови:** `update >= 0` та `update <= counter`.

## 2. Заголовок `<barrier>`

Заголовок `<barrier>` визначає клас-шаблон `std::barrier` для фазової синхронізації групи потоків у циклічних обчисленнях.

### Оголошення класу-шаблону

```cpp
namespace std {
    template<class CompletionFunction = /* implementation-defined */>
    class barrier {
    public:
        using arrival_token = /* implementation-defined */;

        static constexpr ptrdiff_t max() noexcept;

        constexpr explicit barrier(ptrdiff_t expected,
                                   CompletionFunction f = CompletionFunction());
        ~barrier();

        barrier(const barrier&) = delete;
        barrier& operator=(const barrier&) = delete;

        [[nodiscard]] arrival_token arrive(ptrdiff_t update = 1);
        void wait(arrival_token&& arrival) const;
        void arrive_and_wait();
        void arrive_and_drop();

    private:
        /* implementation-defined стан (лічильники поточної та наступної фаз) */
    };
}
```

### Тип `arrival_token`

- **Семантика:** об'єкт-маркер, який фіксує факт прибуття потоку до конкретної фази обчислень.
- **Властивості:** тип є рухомим (`MoveConstructible`, `MoveAssignable`), але некопійованим (`Non-Copyable`).
- **Призначення:** дозволяє розділити операцію реєстрації прибуття (`arrive`) та фактичне блокування потоку (`wait`), даючи потоку змогу виконувати незалежну роботу між цими двома викликами.

---

### Конструктор та функція завершення

#### `constexpr explicit barrier(ptrdiff_t expected, CompletionFunction f = CompletionFunction());`
- **Параметри:**
  - `expected` — початкова кількість учасників фази (`expected >= 0` та `expected <= max()`).
  - `f` — об'єкт зворотного виклику (функція або функціональний об'єкт), що виконується в кінці кожної фази.
- **Вимоги до `CompletionFunction`:**
  - Тип `CompletionFunction` повинен задовольняти концепт `std::is_nothrow_invocable_v<CompletionFunction&>`.
  - Функція не повинна звертатися до методів того самого бар'єра, на якому вона викликається (інакше виникає взаємне блокування).
- **Специфікація винятків:** якщо `CompletionFunction` під час виконання генерує виняток, середовище виконання C++ негайно викликає `std::terminate()`.
- **Контекст виконання:** `CompletionFunction` викликається строго один раз за кожну фазу в контексті останнього потоку, що прибув до бар'єра (або внутрішнього допоміжного потоку реалізації), коли всі інші потоки поточної фази заблоковані.

#### `~barrier();`
- **Попередні умови:** жоден потік не повинен перебувати у викликах методів цього бар'єра.

---

### Методи фазової синхронізації

#### `[[nodiscard]] arrival_token arrive(ptrdiff_t update = 1);`
- **Призначення:** реєструє прибуття `update` учасників до поточної фази бар'єра.
- **Попередні умови:** `update > 0` та `update` не перевищує залишок очікуваних учасників поточної фази.
- **Повертане значення:** об'єкт `arrival_token`, пов'язаний із поточною фазою.
- **Поведінка:**
  - Атомарно зменшує лічильник поточної фази на `update`.
  - Якщо лічильник досяг нуля, поточний потік виконує `CompletionFunction()`, після чого переводить бар'єр у фазу `K + 1`, скидає лічильник на початкове значення `expected` і розблоковує всіх очікуючих потоків.
  - Якщо лічильник ще не досяг нуля, потік **не блокується** і негайно повертає `arrival_token`.
- **Впорядкування пам'яті:** виклик `arrive()` має семантику `memory_order_release` і синхронізується з початком виконання `CompletionFunction`.

#### `void wait(arrival_token&& arrival) const;`
- **Параметри:** `arrival` — rvalue-посилання на токен, отриманий з виклику `arrive()` цього самого об'єкта бар'єра.
- **Попередні умови:** токен `arrival` повинен представляти поточну або щойно завершену фазу цього бар'єра.
- **Поведінка:** блокує потік доти, доки фаза, представлена цим токеном, повністю не завершиться (включно з виконанням `CompletionFunction`).
- **Впорядкування пам'яті:** вихід із `wait()` має семантику `memory_order_acquire` і синхронізується із завершенням `CompletionFunction`.

#### `void arrive_and_wait();`
- **Призначення:** атомарне прибуття до бар'єра з негайним переходом у стан очікування завершення фази.
- **Еквівалент:** `wait(arrive())`.
- **Складність:** `O(1)` декремент; блокування до завершення поточної фази всіма учасниками.

#### `void arrive_and_drop();`
- **Призначення:** позначає прибуття потоку до поточної фази **і назавжди зменшує кількість очікуваних учасників для всіх наступних фаз на 1**.
- **Попередні умови:** залишок очікуваних учасників поточної фази строго більший за нуль (`> 0`).
- **Поведінка:**
  - Зменшує лічильник поточної фази на 1.
  - Зменшує базове значення `expected` на 1 для всіх наступних фаз.
  - Якщо цей потік був останнім очікуваним у поточній фазі, виконується `CompletionFunction`, і починається нова фаза з новою зменшеною кількістю учасників.
  - Потік, що викликав `arrive_and_drop()`, більше не зобов'язаний брати участь у наступних фазах бар'єра.

## 3. Заголовок `<semaphore>`

Заголовок `<semaphore>` надає класи `std::counting_semaphore` та `std::binary_semaphore` для обмеження одночасного доступу до пулу спільних ресурсів.

### Оголошення класу-шаблону

```cpp
namespace std {
    template<ptrdiff_t LeastMaxValue = /* implementation-defined */>
    class counting_semaphore {
    public:
        static constexpr ptrdiff_t max() noexcept;

        constexpr explicit counting_semaphore(ptrdiff_t desired);
        ~counting_semaphore();

        counting_semaphore(const counting_semaphore&) = delete;
        counting_semaphore& operator=(const counting_semaphore&) = delete;

        void release(ptrdiff_t update = 1);
        void acquire();
        bool try_acquire() noexcept;

        template<class Rep, class Period>
        bool try_acquire_for(const std::chrono::duration<Rep, Period>& rel_time);

        template<class Clock, class Duration>
        bool try_acquire_until(const std::chrono::time_point<Clock, Duration>& abs_time);
    };

    using binary_semaphore = counting_semaphore<1>;
}
```

### Параметр шаблону `LeastMaxValue`

- **Семантика:** гарантована мінімальна місткість лічильника семафора, яку зобов'язана підтримувати реалізація.
- **Вимоги:** `LeastMaxValue >= 0`.
- **Оптимізація компілятора:** дозволяє компілятору обрати найбільш компактний та швидкий цілочисельний тип для представлення стану. Якщо `LeastMaxValue == 1` (`binary_semaphore`), компілятор може використати 8-бітний або 32-бітний атомарний тип, оптимізований під інструкції процесора `lock bts` або `lock cmpxchg`.

---

### Методи семафора

#### `static constexpr ptrdiff_t max() noexcept;`
- **Призначення:** повертає абсолютний максимум дозволів, підтримуваний цим семафором.
- **Гарантія:** `max() >= LeastMaxValue`.

#### `constexpr explicit counting_semaphore(ptrdiff_t desired);`
- **Попередні умови:** `desired >= 0` та `desired <= max()`.
- **Призначення:** ініціалізує лічильник дозволів початковим значенням `desired`.

#### `void release(ptrdiff_t update = 1);`
- **Параметри:** `update` — кількість повертаних дозволів (`update >= 0`).
- **Попередні умови:** `update <= max() - counter` (значення не повинно перевищити `max()`).
- **Поведінка:**
  - Атомарно додає `update` до лічильника дозволів.
  - Якщо в системі є потоки, заблоковані у викликах `acquire()`, розблоковує щонайбільше `update` потоків.
- **Впорядкування пам'яті:** операція має семантику `memory_order_release`. Вона синхронізується з наступним успішним викликом `acquire()`, який спожив один із вивільнених дозволів.
- **Складність:** `O(1)` для додавання; `O(update)` для системного пробудження потоків у черзі ядра.

#### `void acquire();`
- **Призначення:** атомарно зменшує лічильник дозволів на 1.
- **Поведінка:**
  - Якщо лічильник > 0, декрементує його та негайно повертає керування (Fast Path).
  - Якщо лічильник == 0, блокує потік доти, доки інший потік не викличе `release()` (Slow Path).
- **Впорядкування пам'яті:** операція має семантику `memory_order_acquire`.
- **Складність:** `O(1)` на швидкому шляху; системна затримка сну ядра при блокуванні.

#### `bool try_acquire() noexcept;`
- **Призначення:** неблокуюча спроба отримати 1 дозвіл.
- **Повертане значення:**
  - `true` — якщо дозвіл було успішно декрементовано.
  - `false` — якщо лічильник був нульовим (дозвіл не отримано).
- **Впорядкування пам'яті:** у разі повернення `true` має семантику `memory_order_acquire`; у разі `false` — `memory_order_relaxed`.
- **Складність:** `O(1)`, атомарна операція `compare_exchange_weak` або декремент.

#### `template<class Rep, class Period> bool try_acquire_for(const std::chrono::duration<Rep, Period>& rel_time);`
- **Призначення:** спроба захоплення дозволу з відносним таймаутом `rel_time`.
- **Повертане значення:** `true`, якщо дозвіл отримано до вичерпання часу; `false` при досягненні ліміту.

#### `template<class Clock, class Duration> bool try_acquire_until(const std::chrono::time_point<Clock, Duration>& abs_time);`
- **Призначення:** спроба захоплення дозволу з абсолютним часовим дедлайном `abs_time`.
- **Повертане значення:** `true` у разі успіху; `false` при настанні вказаної часової точки.

## 4. Зведена таблиця гарантій та моделей пам'яті

| Метод | Модель пам'яті (Memory Order) | Системний виклик при успіху | Системний виклик при блокуванні | Поведінка при порушенні умов |
|---|---|---|---|---|
| `std::latch::count_down` | `release` | Немає (крім обнулення) | Ніколи не блокується | Невизначена поведінка (UB при underflow) |
| `std::latch::wait` | `acquire` | Немає (якщо `count == 0`) | `futex(FUTEX_WAIT)` / `WaitOnAddress` | Немає |
| `std::barrier::arrive` | `release` | Немає (якщо не останній) | Ніколи не блокується | Невизначена поведінка (UB при перевищенні) |
| `std::barrier::wait` | `acquire` | Немає (якщо фаза готова) | `futex(FUTEX_WAIT)` / `WaitOnAddress` | Невизначена поведінка (недійсний токен) |
| `std::counting_semaphore::release` | `release` | Немає (якщо нема сплячих) | Ніколи не блокується | Невизначена поведінка (переповнення `max()`) |
| `std::counting_semaphore::acquire` | `acquire` | Немає (якщо `count > 0`) | `futex(FUTEX_WAIT)` / `WaitOnAddress` | Немає |
