# 📋 Довідник синтаксису виразів згортки та операцій над пакетами

Цей довідник містить детальну специфікацію синтаксису, граматичних форм, правил обчислення для порожніх пакетів та перелік допустимих бінарних операторів виразів згортки (Fold Expressions), стандартизованих у C++17, а також формальний перелік контекстів розпакування пакетів параметрів.

---

## 1. Граматика та чотири форми виразів згортки

Вираз згортки (англ. *fold expression*) — це фундаментальна синтаксична конструкція мови C++, яка згортає пакет параметрів або аргументів за допомогою одного з бінарних операторів мови безпосередньо у вузол абстрактного синтаксичного дерева (AST) на етапі трансляції.

> ⚠️ **Обов'язковість круглих дужок:** Згідно зі стандартом ISO C++, будь-який вираз згортки **зобов'язаний бути взятим у круглі дужки** `(...)`. Пропуск зовнішніх круглих дужок є фатальною синтаксичною помилкою парсера на етапі синтаксичного аналізу вихідного тексту.

| Форма згортки | Синтаксис | Еквівалентне семантичне розкриття для пакету `E = {e₁, e₂, ..., eₙ}` | Напрямок асоціативності |
| :--- | :--- | :--- | :--- |
| **Унарна ліва (Unary Left Fold)** | `(... op E)` | `(((e₁ op e₂) op e₃) ... op eₙ)` | Лівоасоціативний (зліва направо) |
| **Унарна права (Unary Right Fold)** | `(E op ...)` | `(e₁ op (e₂ op (... (eₙ₋₁ op eₙ))))` | Правоасоціативний (справа наліво) |
| **Бінарна ліва (Binary Left Fold)** | `(I op ... op E)` | `((((I op e₁) op e₂) op e₃) ... op eₙ)` | Лівоасоціативний із початковим значенням `I` |
| **Бінарна права (Binary Right Fold)** | `(E op ... op I)` | `(e₁ op (e₂ op (... (eₙ op I))))` | Правоасоціативний із кінцевим значенням `I` |

У наведених граматичних шаблонах діють суворі правила розпізнавання елементів:
- `op` позначає будь-який із 32 підтримуваних стандартом бінарних операторів C++.
- `E` є виразом-патерном, що містить хоча б один нерозпакований пакет параметрів (англ. *unexpanded parameter pack*).
- `I` представляє вираз ініціалізатора (початкового чи кінцевого елемента), який **не містить** нерозпакованих пакетів параметрів і виступає базисом індукції для бінарних форм.
- У бінарних конструкціях `(I op1 ... op2 E)` та `(E op1 ... op2 I)` обидва оператори `op1` та `op2` **повинні бути лексично ідентичними**. Спроба використати різні оператори (наприклад, поєднати додавання та множення у вигляді `(0 + ... * args)`) заборонена стандартом мови і призводить до негайної відмови компілятора.

### Різниця між лівою та правою асоціативністю

Вибір між лівою `(... op E)` та правою `(E op ...)` формами є критичним для операторів, які не мають властивості математичної асоціативності (комутативності групування). 

Для операції додавання цілих чисел `(a + b) + c` та `a + (b + c)` дають однаковий математичний результат (за винятком випадків переповнення або специфіки чисел із рухомою комою). Проте для таких операторів, як віднімання (`-`), ділення (`/`), побітовий зсув (`<<`, `>>`), присвоєння (`=`) та оператор коми (`,`), порядок групування докорінно змінює логіку обчислень:

```cpp
// Унарна ліва згортка для віднімання: (... - args)
// Для аргументів (10, 3, 2):
// Розкриття: ((10 - 3) - 2) = (7 - 2) = 5

// Унарна права згортка для віднімання: (args - ...)
// Для аргументів (10, 3, 2):
// Розкриття: (10 - (3 - 2)) = (10 - 1) = 9
```

Як видно з прикладу, ліва згортка послідовно віднімає кожен наступний аргумент від накопиченого результату (що відповідає природній інтуїції накопичувального віднімання), тоді як права згортка рекурсивно обчислює вираз справа наліво.

## 2. Повна специфікація 32 бінарних операторів

Стандарт C++17 формально визначає підтримку виразів згортки для 32 бінарних операторів мови. У стандарті C++20 цей перелік було розширено оператором тристороннього порівняння (триногим оператором `<=>`).

### Арифметичні оператори

Арифметичні згортки застосовуються для математичної редукції числових послідовностей, векторів, матриць та користувацьких типів з перевантаженими операторами.

1. **Оператор додавання (`+`):**
   - Типове використання: підсумовування елементів послідовності, конкатенація рядків `std::string`, об'єднання контейнерів.
   - Особливість: для числових типів із рухомою комою (`float`, `double`) ліва та права згортки можуть давати відмінні результати через накопичення похибок округлення стандарту IEEE 754.
2. **Оператор віднімання (`-`):**
   - Типове використання: обчислення різниць, зміщень координат, коригування лічильників.
   - Особливість: вимагає обов'язкового вибору лівої згортки `(... - args)` для забезпечення послідовного зменшення.
3. **Оператор множення (`*`):**
   - Типове використання: обчислення факторіалів, добутків масивів, визначення сумарного об'єму багатовимірних тензорів (`dim1 * dim2 * dim3`).
4. **Оператор ділення (`/`):**
   - Типове використання: послідовне масштабування величин, перетворення одиниць вимірювання.
5. **Оператор залишку від ділення (`%`):**
   - Типове використання: послідовна редукція за модулем, обчислення хеш-функцій.

### Побітові оператори та оператори зсуву

Побітові згортки є ключовим інструментом системного програмування, низькорівневих драйверів мікроконтролерів та мережевих протоколів.

1. **Побітове І (`&`):**
   - Використовується для знаходження спільного перетину бітових масок, перевірки сумісності апаратних конфігурацій.
2. **Побітове АБО (`|`):**
   - Застосовується для об'єднання конфігураційних прапорців у єдиний регістр керування периферією: `auto flags = (Flag1 | Flag2 | ... | FlagN)`.
3. **Побітове виключне АБО (`^`):**
   - Застосовується для швидкого обчислення бітів парності (Parity Bit), простих контрольних сум або накладання потокових масок шифрування.
4. **Побітовий зсув вліво (`<<`) та вправо (`>>`):**
   - У контексті потоків введення-виведення стандарту C++ (`std::ostream`, `std::istream`) оператори `<<` та `>>` забезпечують ланцюговий друк та десеріалізацію аргументів.
   - Ліва бінарна згортка `(std::cout << ... << args)` розкривається в `(((std::cout << a1) << a2) << a3)`, що є канонічним ідіоматичним способом виведення змінної кількості аргументів.

### Логічні оператори та гарантія короткого замикання (Short-circuit Evaluation)

Логічні згортки `&&` та `||` мають унікальну властивість: вони гарантують виконання за правилом короткого замикання (англ. *short-circuit evaluation*). Обчислення підвиразів зупиняється на першому аргументі, який однозначно визначає підсумок.

1. **Логічне І (`&&`):**
   - Вираз `(is_valid(args) && ...)` розкривається як `(is_valid(a1) && (is_valid(a2) && is_valid(a3)))` (у правій формі) або `(((is_valid(a1) && is_valid(a2)) && is_valid(a3)))` (у лівій формі).
   - Якщо функція `is_valid(a1)` повертає `false`, виклики `is_valid(a2)` та `is_valid(a3)` **не виконуються взагалі**. Це критично важливо, коли наступні виклики перевіряють валідність покажчиків, розіменування яких за нульової адреси призвело б до падіння програми.
2. **Логічне АБО (`||`):**
   - Вираз `(try_handle(args) || ...)` припиняє виконання, щойно один з обробників повертає `true`, сигналізуючи про успішне завершення операції.

### Оператори присвоєння та складеного присвоєння

Оператори присвоєння (`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `^=`, `&=`, `|=`, `<<=`, `>>=`) у мові C++ є природно правоасоціативними. 

У виразах згортки вони найчастіше використовуються разом із бінарною правою або лівою формою для послідовної модифікації зовнішнього накопичувача (акумулятора):

```cpp
template <typename Target, typename... Values>
void push_all_to_queue(Target& queue, Values&&... vals) {
    (queue.push(std::forward<Values>(vals)), ...);
}

template <typename Acc, typename... Deltas>
void accumulate_delta(Acc& acc, Deltas... deltas) {
    (acc += ... += deltas); // Розкриття: (acc += (d1 += (d2 += d3)))
}
```

### Оператори доступу за покажчиками на члени (`.*`, `->*`)

Оператори `.*` та `->*` дозволяють будувати динамічні ланцюжки переходу по вкладених полях структур або викликати методи за послідовністю вказівників на члени класу:

```cpp
struct Engine { int power; };
struct Car { Engine engine; };
struct Garage { Car car; };

template <typename Root, typename... Ptrs>
auto traverse(Root&& root, Ptrs... ptrs) {
    return (std::forward<Root>(root) .* ... .* ptrs);
}
// Виклик: traverse(my_garage, &Garage::car, &Car::engine, &Engine::power);
```

### Оператор коми (`,`)

Оператор коми є найуніверсальнішим інструментом у метапрограмуванні C++. Він забезпечує суворе виконання побічних ефектів зліва направо:

```cpp
template <typename... Functions>
void execute_sequence(Functions&&... funcs) {
    (std::forward<Functions>(funcs)(), ...);
}
```

Кожен виклик функції `funcs()` виконується як окремий вираз, після чого оператор коми відкидає результат повернення і переходить до наступного елемента пакета.

## 3. Семантика для порожніх пакетів (Empty Pack Rules)

Поведінка виразів згортки при передачі порожнього пакета (`sizeof...(args) == 0`) строго регламентована стандартом.

### 3.1. Унарні згортки над порожнім пакетом

Для переважної більшості операторів унарна згортка порожнього пакета є **неприпустимою і призводить до помилки компіляції** (код визнано некоректно сформованим — англ. *ill-formed*).

> **Чому в стандарті немає нейтральних елементів для арифметики:** Комітет ISO C++ відмовився від неявного підставлення нуля для `+` чи одиниці для `*`. Якби компілятор автоматично підставляв `0` у вираз `(... + empty_args)`, виклик функції для конкатенації рядків `std::string` чи користувацьких матриць несподівано отримував би несумісний скалярний тип `int`, що призводило б до важковиправних прихованих дефектів.

Стандарт робить **рівно три винятки**, для яких нейтральні значення однозначно визначені логікою мови:

1. **Логічне І (`&&`):**
   Порожній кон'юнктивний предикат за законами математичної логіки дорівнює істині (нейтральний елемент відносно операції кон'юнкції).
   ```cpp
   template <typename... Args>
   constexpr bool check_all(Args... args) {
       return (args && ...); // Для 0 аргументів компілятор повертає: true
   }
   ```
2. **Логічне АБО (`||`):**
   Порожній диз'юнктивний предикат за законами логіки дорівнює хибності (нейтральний елемент відносно диз'юнкції).
   ```cpp
   template <typename... Args>
   constexpr bool check_any(Args... args) {
       return (args || ...); // Для 0 аргументів компілятор повертає: false
   }
   ```
3. **Оператор коми (`,`):**
   Порожній ланцюжок побічних ефектів за стандартом перетворюється на вираз типу `void()`.
   ```cpp
   template <typename... Args>
   void run(Args... args) {
       (args(), ...); // Для 0 аргументів результат: void()
   }
   ```

### 3.2. Бінарні згортки над порожнім пакетом

Бінарна згортка є універсальним засобом забезпечення безпеки коду для будь-яких операторів. Якщо пакет містить нуль елементів, компілятор відкидає операцію згортки та повертає значення ініціалізатора `I`:

```cpp
template <typename... Args>
auto safe_sum(Args... args) {
    return (0 + ... + args); // Для порожнього пакета повертає точно 0
}

template <typename... Strings>
std::string concatenate(Strings&&... strs) {
    return (std::string{} + ... + std::forward<Strings>(strs));
    // Для 0 аргументів повертає порожній об'єкт std::string{}
}
```

## 4. Повний перелік контекстів розпакування пакетів у граматиці C++

Операція розпакування пакета (англ. *pack expansion*) за допомогою трикрапки `...` дозволена стандартом C++ виключно у тринадцяти строго визначених граматичних контекстах:

1. **Список аргументів функції:**
   `func(std::forward<Args>(args)...)` — розпакування у відокремлений комами список виразів, що передаються у параметри виклику.
2. **Список аргументів шаблону:**
   `std::tuple<std::decay_t<Args>...>` — тиражування патерну перетворення типу для кожного елемента пакета типів.
3. **Список ініціалізації масиву або об'єкта (Braced-init-list):**
   `int data[] = { transform(args)... };` — послідовне заповнення структури чи масиву результатами обчислення патерну.
4. **Список базових класів у визначенні класу:**
   `template <typename... Bases> struct Composite : public Bases... {};` — оголошення множинного успадкування від усіх типів, переданих у пакеті.
5. **Список ініціалізації конструктора (Member initializer list):**
   `Composite(Bases... b) : Bases(b)... {}` — пряма передача аргументів конструкторам відповідних базових класів або полів.
6. **Список захоплення лямбда-виразу (Lambda capture list):**
   - У C++11: `[args...]() { ... }` — захоплення копій або посилань на всі змінні пакета.
   - У C++20: `[...args = std::move(args)]() { ... }` — ініціалізувальне захоплення з переміщенням кожного елемента пакета всередину замикання.
7. **Using-оголошення (Using-declarations у C++17):**
   `using Bases::operator()...;` — введення однойменних перевантажених методів усіх базових класів у поточну область видимості (ключова основа патерну Overloaded).
8. **Специфікатор вирівнювання (alignas):**
   `alignas(alignof(Args)...) char storage[1024];` — встановлення апаратного вирівнювання буфера за максимальним значенням серед усіх типів пакета.
9. **Специфікатор динамічних винятків (історичний) та noexcept-оператор:**
   `noexcept((noexcept(func(args)) && ...))` — статичне обчислення булевого прапорця відсутності винятків для всього набору операцій.
10. **Шаблони псевдонімів (Type alias templates):**
    `template <typename... Ts> using ConstPtrTuple = std::tuple<const Ts*...>;` — масове створення модифікованих типів даних.
11. **Вирази обмежень (Concepts та requires-clauses у C++20):**
    `template <typename... Ts> requires (std::is_integral_v<Ts> && ...) void algo(Ts...);` — верифікація концептів для кожного типу на етапі відбору перевантажень.
12. **Сам вираз згортки (Fold expression у C++17):**
    `(... op E)` — граматичне згортання виразу за бінарним оператором.
13. **Пряма індексація пакетів (Pack Indexing у C++26):**
    `Args...[0] first;` та `auto val = args...[I];` — прямий доступ до елемента пакета за константним індексом.

## 5. Взаємодія з користувацькими перевантаженими операторами (ADL)

Коли вираз згортки застосовується до користувацьких класів (наприклад, структур матриць `Matrix`, поліномів або типів безпечних чисел), компілятор виконує пошук перевантажених операторів за стандартними правилами ADL (Argument Dependent Lookup, пошук за залежністю від аргументів):

```cpp
namespace math {
    struct Vector3D {
        double x, y, z;
    };

    Vector3D operator+(const Vector3D& a, const Vector3D& b) noexcept {
        return { a.x + b.x, a.y + b.y, a.z + b.z };
    }
}

template <typename... Vectors>
auto sum_vectors(const Vectors&... vecs) {
    // Вираз згортки автоматично знаходить math::operator+ через ADL
    return (... + vecs);
}
```

Якщо користувацький тип перевантажує оператор коми `operator,` або логічні оператори `operator&&` / `operator||`, вираз згортки **втрачає властивість короткого замикання (short-circuiting)**. Оскільки перевантажений оператор стає звичайним викликом функції `operator&&(a, b)`, мова C++ зобов'язана обчислити обидва аргументи перед передачею у функцію. З цієї причини в сучасному C++ перевантаження оператора коми та логічних операторів вважається антипатерном.

## 6. Вкладені вирази згортки та багатовимірні структури

Вирази згортки можна вкладати один в одного для обробки матриць, тензорів та багатовимірних списків параметрів. 

Розглянемо випадок обчислення скалярного добутку векторів на етапі компіляції або обходу двовимірного кортежу:

```cpp
template <typename... Rows>
auto sum_matrix(const Rows&... rows) {
    // Зовнішня згортка за додаванням рядків,
    // де кожен рядок розгортається внутрішньою згорткою
    return (std::apply([](auto... cells) {
        return (cells + ...);
    }, rows) + ...);
}
```

Компілятор генерує плоский арифметичний вираз, у якому всі операції додавання елементів матриці об'єднуються в єдину форму без створення проміжних структур даних або викликів функцій.

## 7. Діагностика помилок компіляції та типові пастки

Під час роботи з варіативними шаблонами та виразами згортки розробники найчастіше стикаються з трьома категоріями помилок компілятора:

### Помилка 1: Нерозпакований пакет параметрів (Parameter pack not expanded)
Виникає, коли ім'я пакета використовується у виразі без трикрапки `...` або поза виразом згортки:

```cpp
template <typename... Args>
void bad_print(Args... args) {
    // Помилка: args використовується як єдиний об'єкт
    std::cout << args; // Clang: expression contains unexpanded parameter pack 'args'
}
```
**Виправлення:** Додати вираз згортки `(std::cout << ... << args);` або розпакування в аргументи функції `print(args...);`.

### Помилка 2: Порожній пакет в унарній арифметичній згортці
```cpp
template <typename... Numbers>
auto sum(Numbers... nums) {
    return (... + nums); // Помилка, якщо sum() викликано без аргументів!
}
// GCC: fold-expression has empty expansion for operator '+'
```
**Виправлення:** Використати бінарну форму з явним ініціалізатором `return (0 + ... + nums);`.

### Помилка 3: Неузгоджена довжина кількох пакетів
```cpp
template <typename... Keys, typename... Values>
void map_init(Keys... k, Values... v) {
    auto pairs = { std::make_pair(k, v)... }; 
    // Якщо sizeof...(Keys) != sizeof...(Values)
    // MSVC: error C3520: 'Values': parameter pack must be expanded in this context
}
```
**Виправлення:** Додати статичну перевірку `static_assert(sizeof...(Keys) == sizeof...(Values), "Розміри пакетів мусять збігатися");`.

## 8. Порівняння оператора коми у виразах згортки та списках аргументів

Слід чітко розрізняти семантику оператора коми у виразі згортки та синтаксичну кому, що розділяє аргументи функції:

```cpp
// 1. Згортка за оператором коми:
// Гарантує виконання дій зліва направо строго послідовно
(perform_step(args), ...);

// 2. Розпакування пакета в аргументи функції:
// Порядок обчислення аргументів f(e1, e2, e3) ДО стандарту C++17 був невизначеним!
f(perform_step(args)...);
```

> 🔧 **Навіщо це:** У драйверах апаратних пристроїв, конвеєрах обробки сигналів та системах зневадження згортка за оператором коми `(write_register(args), ...)` гарантує детерміновану послідовність запису в пам'ять регістрів процесора без ризику оптимізаційного перевпорядкування.
