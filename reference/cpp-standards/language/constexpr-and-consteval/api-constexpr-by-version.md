# 📋 Що дозволено в сталому обчисленні за редакціями стандарту

Довідка: яка конструкція з якої редакції C++ проходить крізь обчислювач сталих, яким макросом її перевірити й якими прапорцями обмежені його ресурси. Потрібна щоразу, коли код мусить збиратися не лише найновішим компілятором: те саме тіло функції, законне під `-std=c++23`, під `-std=c++17` може бути помилкою ще до того, як хтось спробує його порахувати.

## Дві різні заборони, які легко сплутати

Обмежень насправді два набори, і перевіряються вони в різні моменти.

**Заборони на тіло** діють у точці визначення функції. Компілятор дивиться на текст і відмовляє відразу — незалежно від того, чи покличе цю функцію хоч хтось у сталому контексті.

**Заборони на обчислення** діють у точці виклику й лише для тих кроків, які обчислювач справді виконує. Функція компілюється, а несталим виявляється конкретний виклик із конкретними аргументами.

```cpp
constexpr int f(int x) {
    try { return x; } catch (...) { return 0; }   // тіло: помилка до C++20
}

constexpr int g(int x) {
    if (x < 0) throw "від'ємне";      // тіло: законне в усіх редакціях
    return x;                          // обчислення: падає лише коли x < 0
}

constexpr int a = g(5);               // 5
constexpr int b = g(-5);              // помилка: виклик не сталий
```

Обидві таблиці нижче читаються з цим поділом: перша каже, що можна **написати**, друга — що можна **виконати**.

## Тіло constexpr-функції

| Конструкція в тілі | З якої редакції | Примітка |
|---|---|---|
| Кілька операторів, локальні змінні, `if`/`switch`, цикли | C++14 | N3652; у C++11 дозволявся єдиний `return` |
| Непорожнє тіло constexpr-конструктора | C++14 | у C++11 усе йшло лише в список ініціалізації |
| Нестатичний constexpr-метод не є неявно `const` | C++14 | N3598; у C++11 `constexpr` на методі мовчки додавав `const` |
| Лямбда, придатна для сталого обчислення | C++17 | P0170R1; замикання стає літеральним типом, якщо такі й захоплення |
| `try`/`catch` | C++20 | P1002R1 |
| `asm` у гілці, яка при сталому обчисленні не виконується | C++20 | P1668R1 |
| Локальна змінна без ініціалізатора | C++20 | P1331R2; читати її під час обчислення однаково не можна |
| `goto` та мітки | C++23 | P2242R3 |
| Локальні `static` і `thread_local` | C++23 | P2242R3 |
| Локальна змінна нелітерального типу | C++23 | P2242R3 |
| Читання локальної `static constexpr` під час обчислення | C++23 | P2647R1 — саме читання, а не лише оголошення |
| Параметри й тип повернення можуть бути нелітеральними | C++23 | P2448R2 |

Останній рядок скасовує ще й вимогу, яка мучила авторів шаблонних бібліотек: до C++23 `constexpr`-функція, не придатна для сталого обчислення **за жодних** аргументів, вважалася хибною програмою. Тепер таке визначення просто законне й ніколи не спрацьовує в сталому контексті.

P2242R3 варто читати уважно: він дозволив ці конструкції **писати**, а не обчислювати. Виконання `goto` чи звернення до локальної `static` (крім випадку з P2647R1) робить вираз несталим. Виграш у тому, що функція, у якої така гілка існує, більше не втрачає права зватися `constexpr` через саме лише її існування.

## Що обчислювач сталих погоджується виконати

| Дія під час обчислення | З якої редакції | Примітка |
|---|---|---|
| Виклик `constexpr`-функції | C++11 | ради цього все й починалося |
| Зміна об'єкта, створеного в цьому ж обчисленні | C++14 | N3652 |
| Виклик віртуальної функції | C++20 | P1064R0 |
| `dynamic_cast` і `typeid` поліморфного об'єкта | C++20 | P1327R1 |
| `new`/`delete`, `std::allocator<T>::allocate` | C++20 | P0784R7; пам'ять мусить бути звільнена до кінця обчислення |
| Виклик `constexpr`-деструктора | C++20 | P0784R7 |
| Зміна активного члена об'єднання | C++20 | P1330R0 |
| Використання посилання чи вказівника на об'єкт, значення якого невідоме | C++23 | P2280R4; `std::size(ref)` більше не потребує самого об'єкта |
| Кинути й перехопити виняток | C++26 | P3068R6 |
| Розміщувальний `new` | C++26 | P2747R2 |
| `static_cast` із `void*` назад у точний тип об'єкта | C++26 | P2738R1 |
| Оголосити `constexpr` структуровані зв'язування | C++26 | P2686R5 |
| Читання неініціалізованої пам'яті, ввід-вивід, звернення до змінної часу виконання | ніколи | суперечить замкненості обчислення |

Про `dynamic_cast` і `typeid` варто пам'ятати, що вони працюють із таблицею віртуальних методів, і саме її обчислювач уміє читати сам, бо будує об'єкти власноруч; докладніше про сам механізм — [RTTI: typeid і dynamic_cast](topic:cpp-standards/rtti-and-dynamic-cast).

Винятки в сталому обчисленні (C++26) з'явилися не заради симетрії з часом виконання. Їх виштовхнула [статична рефлексія](topic:cpp-standards/static-reflection) — набір `consteval`-функцій, що дістають із програми відомості про її власні типи й члени; такі метафункції часто мусять повідомити про невдачу, а іншого способу повернути помилку з негайної функції мова не мала. Кинутий виняток, як і раніше, не перетинає межу обчислення: якщо його не спіймали всередині, вираз лишається несталим.

## Слова й конструкції

| Запис | З якої редакції | Папір |
|---|---|---|
| `constexpr` на функції та на змінній | C++11 | N2235 |
| [`if constexpr`](topic:cpp-standards/constexpr-if) — гілка, якої не існує після компіляції | C++17 | P0292R2 |
| `consteval` — негайна функція | C++20 | P1073R3 |
| [`constinit`](topic:cpp-standards/constinit) — ініціалізація до запуску без незмінності | C++20 | P1143R2 |
| `std::is_constant_evaluated()` з `<type_traits>` | C++20 | P0595R2 |
| `if consteval` | C++23 | P1938R3 |
| Передавання негайності вгору по викликах | C++23 | P2564R3 |

## Стандартна бібліотека

| Що стало придатним до сталого обчислення | З якої редакції |
|---|---|
| `std::array`, ітератори, `std::string_view`, `std::char_traits` | C++17 |
| `<algorithm>` і `<utility>` цілком, `std::construct_at`, `std::destroy_at` | C++20 |
| `std::vector`, `std::string` | C++20 |
| `<cmath>` і `<cstdlib>` (P0533R9), `std::unique_ptr` | C++23 |
| Решта контейнерів і адаптерів — `map`, `set`, `list`, `deque` (P3372R3) | C++26 |
| `std::stable_sort`, `std::inplace_merge` та інші стабільні алгоритми (P2562R1) | C++26 |
| Складніші функції `<cmath>` і `<complex>` (P1383R2) | C++26 |

Ці рядки стосуються вживання **всередині** обчислення. Оголосити `constexpr std::vector<int> v` не можна в жодній редакції: змінна мусить пережити компіляцію, а купа її не переживає.

## Макроси перевірки можливостей

Значення макроса — рік і місяць голосування паперу, тож порівняння завжди `>=`.

| Значення `__cpp_constexpr` | Редакція | Що додано |
|---|---|---|
| `200704L` | C++11 | N2235 |
| `201304L` | C++14 | N3652 |
| `201603L` | C++17 | P0170R1 (лямбди) |
| `201806L` | C++20 | P1064R0 (віртуальні виклики) |
| `201811L` | C++20 | P1002R1, P1327R1 |
| `201907L` | C++20 | P1331R2, P1668R1 |
| `202002L` | C++20 | P1330R0 (активний член об'єднання) |
| `202110L` | C++23 | P2242R3 |
| `202207L` | C++23 | P2448R2 |
| `202211L` | C++23 | P2647R1 |
| `202306L` | C++26 | P2738R1 |
| `202406L` | C++26 | P2747R2 |

Окремі макроси: `__cpp_consteval` — `201811L` (C++20), `202211L` (C++23, передавання негайності); `__cpp_if_consteval` — `202106L`; `__cpp_constinit` — `201907L`.

Мінімальний робочий приклад — таблиця, яку в C++23 можна тримати локальною `static constexpr`, а раніше доводилося виносити з функції:

```cpp
#include <array>

constexpr std::array<int, 4> make_lut() { return {1, 2, 4, 8}; }

#if defined(__cpp_constexpr) && __cpp_constexpr >= 202211L
constexpr int weight(int i) {
    static constexpr auto lut = make_lut();   // одна копія на програму
    return lut[i];
}
#else
constexpr auto g_lut = make_lut();            // до C++23 — лише за межами функції
constexpr int weight(int i) { return g_lut[i]; }
#endif

static_assert(weight(3) == 8);
```

## Межі обчислювача та прапорці

Обчислювач сталих — інтерпретатор усередині компілятора, тож у нього є лічильники, які рятують збірку від нескінченного циклу. Коли велике обчислення впирається в стелю, компілятор скаржиться саме на ліміт, а не на код.

| Компілятор | Прапорець | Типове значення |
|---|---|---|
| GCC | `-fconstexpr-depth=n` | 512 (мінімум за стандартом) |
| GCC | `-fconstexpr-loop-limit=n` | 262144 (1<<18) |
| GCC | `-fconstexpr-ops-limit=n` | 33554432 (1<<25) |
| GCC | `-fconstexpr-cache-depth=n` | 8 |
| Clang | `-fconstexpr-depth=N` | 512 |
| Clang | `-fconstexpr-steps=N` | 1048576 |
| MSVC | `/constexpr:depth<N>` | 512 |
| MSVC | `/constexpr:steps<N>` | 100000 |
| MSVC | `/constexpr:backtrace<N>` | 10 |

Два прапорці стосуються не меж, а діагностики: `-fconstexpr-backtrace-limit` у Clang і `/constexpr:backtrace` у MSVC керують глибиною сліду викликів у повідомленні про помилку — без нього видно лише зовнішній вираз, а не рядок, де обчислення справді зламалося.

Окремої згадки вартий діагностичний прапорець `-Wconstant-evaluated` у Clang (GCC попереджає про те саме без окремої назви): він ловить `if constexpr (std::is_constant_evaluated())` — умову, яка завжди істинна, бо сама обчислюється сталою.
