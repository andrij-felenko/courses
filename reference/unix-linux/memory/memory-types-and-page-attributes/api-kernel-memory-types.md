# 📋 Інтерфейси ядра Linux для атрибутів сторінок і відображення I/O

Ядро Linux надає драйверам пристроїв та підсистемам керування пам'яттю набір функцій для відображення фізичних адрес в адресний простір ядра з точним визначенням апаратних атрибутів кешування. Ці функції абстрагують архітектурні відмінності між x86 PAT та ARM MAIR, гарантують коректний вибір шинних транзакцій та запобігають небезпечним конфліктам аліасингу.

## 1. Заголовні файли та базові типи

Для використання інтерфейсів керування атрибутами пам'яті в коді модуля ядра підключають такі заголовні файли:

```c
#include <linux/io.h>          /* ioremap, ioremap_wc, iounmap */
#include <linux/pgtable.h>     /* pgprot_t, pgprot_writecombine */
#include <linux/set_memory.h>  /* set_memory_wb, set_memory_uc, set_memory_wc */
#include <linux/mm.h>          /* remap_pfn_range, vm_area_struct */
```

Ключові типи даних ядра:
* `pgprot_t` — машинно-залежний тип (обгортка над цілим числом `unsigned long`), що зберігає комбінацію бітових прапорців захисту (доступність запису, доступ користувача, заборона виконання) та бітів вибору типу пам'яті для запису таблиці сторінок (PTE).
* `resource_size_t` / `phys_addr_t` — цілочисельний тип (32 або 64 біти залежно від конфігурації `CONFIG_PHYS_ADDR_T_64BIT`), призначений для зберігання фізичних адрес і розмірів діапазонів на системній шині та в просторі PCI BAR.
* `void __iomem *` — анотований покажчик на віртуальну адресу в просторі адрес вводу-виводу ядра. Анотація `__iomem` використовується статичним аналізатором `sparse` для запобігання прямому розіменовуванню без спеціальних функцій доступу `readl()`/`writel()`.

## 2. Функції відображення простору вводу-виводу (I/O Remap)

Функції сімейства `ioremap` виділяють діапазон у віртуальному просторі `vmalloc` ядра та будують відповідні рівні таблиць сторінок (PTE/PMD/PUD), що вказують на цільовий фізичний діапазон MMIO з відповідними бітами PAT/MAIR.

### `ioremap`

```c
void __iomem *ioremap(resource_size_t offset, unsigned long size);
```

* **Призначення:** Стандартне відображення регістрів керування та пам'яті периферійних пристроїв (MMIO).
* **Апаратний тип пам'яті:**
  * **x86-64:** `Uncacheable (UC)` або `UC-` (суворо некешоване звернення, суворий програмний порядок транзакцій, заборона спекулятивного зчитування).
  * **ARM64:** `Device-nGnRE` (незбиране, невпорядковане заново, з дозволом раннього підтвердження запису мостами шини).
* **Параметри:**
  * `offset` — фізична базова адреса ресурсу на шині (наприклад, базовий регістр BAR пристрою PCI Express). Адреса не обов'язково має бути вирівняною на межу сторінки: функція автоматично округлює вниз до найближчого `PAGE_SIZE`, а повернений покажчик враховує початкове зміщення.
  * `size` — розмір діапазону в байтах.
* **Повертає:** Віртуальну адресу `void __iomem *` у разі успіху; `NULL` у разі нестачі віртуального простору або виникнення нерозв'язного конфлікту типів пам'яті в підсистемі PAT.

### `ioremap_wc`

```c
void __iomem *ioremap_wc(resource_size_t offset, unsigned long size);
```

* **Призначення:** Відображення кадрових буферів (framebuffers), пам'яті текстур GPU, відеопам'яті та потокових буферів DMA на шині PCIe.
* **Апаратний тип пам'яті:**
  * **x86-64:** `Write-Combining (WC)` (записи зливаються в 64-байтових внутрішніх буферах процесора Line Fill Buffers, діє слабка модель черговості, кеші L1/L2/L3 вимкнено).
  * **ARM64:** `Normal Non-Cacheable` (нормальна некешована пам'ять із дозволеним апаратним злиттям і спекулятивними зверненнями).
* **Параметри:** Фізична адреса `offset` та розмір `size`.
* **Повертає:** Віртуальну адресу з атрибутом злиття записів або `NULL`.

### `ioremap_uc`

```c
void __iomem *ioremap_uc(resource_size_t offset, unsigned long size);
```

* **Призначення:** Явне суворе відображення без кешування (Strong Uncacheable) на x86, яке не може бути перевизначене реєстрами MTRR. Використовується для критичних регістрів старих шин ISA/PCI.
* **Апаратний тип пам'яті:**
  * **x86-64:** `Strong Uncacheable (UC)` (поле PA3 у `IA32_PAT`).
  * **ARM64:** `Device-nGnRnE` (найсуворіший режим без раннього підтвердження запису).

### `ioremap_cache` / `ioremap_wt`

```c
void __iomem *ioremap_cache(resource_size_t offset, unsigned long size);
void __iomem *ioremap_wt(resource_size_t offset, unsigned long size);
```

* **Призначення:** `ioremap_cache` відображає пам'ять із повним зворотним записом (`Write-Back`), наприклад системну енергонезалежну пам'ять NVDIMM/CXL або системні таблиці ACPI. `ioremap_wt` призначає тип `Write-Through` (наскрізний запис).

### `ioremap_np`

```c
void __iomem *ioremap_np(resource_size_t offset, unsigned long size);
```

* **Призначення:** Відображення простору I/O з гарантією непідтверджених записів (Non-Posted Writes). На ARM64 це призначає `Device-nGnRnE`. На x86 повертає `NULL`, якщо шина або міст не гарантує непідтверджені транзакції.

### `iounmap`

```c
void iounmap(volatile void __iomem *addr);
```

* **Призначення:** Звільнення віртуального діапазону MMIO, демонтаж записів із таблиць сторінок ядра, видалення діапазону з реєстру відстеження PAT і скидання записів TLB.
* **Параметри:** `addr` — покажчик, раніше отриманий від будь-якої функції `ioremap*`.

## 3. Модифікатори прапорців `pgprot_t`

Під час формування віртуальних областей простору користувача (`vma`) або ручного заповнення PTE драйвери модифікують базові атрибути захисту:

| Функція / Макрос | Призначення | x86-64 PAT індекс | ARM64 MAIR поле |
| :--- | :--- | :--- | :--- |
| `pgprot_writecombine(prot)` | Встановлює атрибут Write-Combining | PAT=1, PCD=1, PWT=1 (`_PAGE_CACHE_MODE_WC`) | `PROT_NORMAL_NC` |
| `pgprot_noncached(prot)` | Встановлює некешований доступ | PAT=0, PCD=1, PWT=1 (`_PAGE_CACHE_MODE_UC`) | `PROT_DEVICE_nGnRE` |
| `pgprot_writethrough(prot)` | Встановлює наскрізний запис | PAT=0, PCD=0, PWT=1 (`_PAGE_CACHE_MODE_WT`) | `PROT_NORMAL_WT` |
| `pgprot_device(prot)` | Строгий доступ до апаратного пристрою | PAT=0, PCD=1, PWT=1 (`_PAGE_CACHE_MODE_UC`) | `PROT_DEVICE_nGnRnE` |
| `pgprot_modify(oldprot, newprot)` | Замінює біти доступу та кешування | Зберігає базові прапорці, оновлює біти типу | Оновлює біти індексу |

## 4. Зміна типу звичайної системної пам'яті (Set Memory API)

Для сторінок, виділених через стандартні алокатори ядра (`alloc_pages()`, `kmalloc()`), ядро за замовчуванням створює відображення Write-Back. Якщо драйверу потрібно передати таку пам'ять пристрою без апаратного snoop-протоколу, тип пам'яті в прямому відображенні ядра (Direct Map) змінюють за допомогою функцій `set_memory_*`:

```c
int set_memory_uc(unsigned long addr, int numpages);
int set_memory_wc(unsigned long addr, int numpages);
int set_memory_wt(unsigned long addr, int numpages);
int set_memory_wb(unsigned long addr, int numpages);
```

* **Механізм роботи:**
  1. Розбиває великі сторінки (2 МБ / 1 ГБ) у прямому відображенні ядра на індивідуальні 4 КіБ сторінки (`split_large_page`), якщо запит стосується частини великої сторінки.
  2. Виконує інструкцію інвалідації та скидання кешу (`wbinvd` на x86 або послідовність `clflushopt` / `dc civac` на ARM64), гарантуючи, що жодних брудних рядків у кеші не залишилося.
  3. Оновлює біти PAT/MAIR у відповідних записах PTE.
  4. Скидає буфери трансляції TLB на всіх процесорних ядрах (TLB Shootdown).
* **Повертає:** `0` у разі успіху або від'ємний код помилки (`-EINVAL` при некоректному вирівнюванні, `-ENOMEM` при нестачі сторінок під нові таблиці).
* **Правило парності:** Будь-який виклик `set_memory_uc()` або `set_memory_wc()` **зобов'язаний** мати парний виклик `set_memory_wb()` перед поверненням сторінок назад у загальний пул алокатора ядра.

## 5. Прокидання пам'яті в простір користувача (`remap_pfn_range`)

Драйвери реалізують операцію файлових операцій `.mmap` для прямого доступу прикладних програм до апаратних буферів або кадрових буферів пристрою:

```c
int remap_pfn_range(struct vm_area_struct *vma,
                    unsigned long addr,
                    unsigned long pfn,
                    unsigned long size,
                    pgprot_t prot);
```

### Приклад реалізації `.mmap` для відеопам'яті (Write-Combining):

```c
static int my_framebuffer_mmap(struct file *filp, struct vm_area_struct *vma)
{
    unsigned long size = vma->vm_end - vma->vm_start;
    unsigned long pfn = my_dev->fb_phys_addr >> PAGE_SHIFT;

    /* 1. Забороняємо вивантаження в swap, розширення та включення в core dump */
    vm_flags_set(vma, VM_IO | VM_DONTEXPAND | VM_DONTDUMP);

    /* 2. Призначаємо сторінкам атрибут Write-Combining */
    vma->vm_page_prot = pgprot_writecombine(vma->vm_page_prot);

    /* 3. Будуємо записи таблиць сторінок процесу */
    if (remap_pfn_range(vma, vma->vm_start, pfn, size, vma->vm_page_prot))
        return -EAGAIN;

    return 0;
}
```

## 6. Діагностика та налагодження атрибутів пам'яті

Ядро Linux надає засоби для інспекції поточного стану таблиць типів сторінок та виявлення конфліктів:

1. **Список зареєстрованих діапазонів PAT (`debugfs`):**
   ```sh
   # cat /sys/kernel/debug/x86/pat_memtype_list
   PAT memtype list:
   write-back @ 0x00000000-0x7fffffff
   write-combining @ 0xe0000000-0xefffffff
   uncached-minus @ 0xfd000000-0xfd003fff
   ```
   Кожен запис показує фізичний діапазон, призначений йому тип кешування та кількість активних відображень. Якщо драйвер забуває викликати `iounmap()` або `set_memory_wb()`, цей список накопичує витоки типів.

2. **Повідомлення ядра про конфлікти аліасингу:**
   Якщо драйвер намагається відобразити ділянку з несумісним типом, у системному журналі `dmesg` з'являється попередження:
   ```
   x86/PAT: my_driver:1422 map pfn expected write-back got write-combining
   ```
   Це свідчить про спробу накладання атрибуту Write-Combining на сторінку, яка вже утримується ядром як Write-Back без попереднього виклику `set_memory_wc()`.
