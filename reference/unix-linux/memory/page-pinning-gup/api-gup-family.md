# 📋 Сімейство закріплення: сигнатури, прапорці, звільнення

Це виклична довідка до функцій ядра, якими драйвер бере сторінки чужого буфера й віддає їх назад. Пару «узяв — віддав» тут не перевіряє ні компілятор, ні тип: помилка в ній не падає одразу, а виявляється через тижні як кадр, що не звільняється, або як пам'ять, віддана комусь під живим пристроєм. Тому контракт варто мати перед очима.

## Дві сім'ї, чотири форми

Сімей дві — за наміром: `get_user_pages*` бере звичайне посилання, `pin_user_pages*` ставить закріплення. Усередині кожної — чотири форми, що різняться лише тим, у чиєму адресному просторі працюють і хто тримає `mmap_lock`. Аргументи в дзеркальних форм збігаються посимвольно.

```c
long get_user_pages(unsigned long start, unsigned long nr_pages,
                    unsigned int gup_flags, struct page **pages);
long pin_user_pages(unsigned long start, unsigned long nr_pages,
                    unsigned int gup_flags, struct page **pages);

long get_user_pages_remote(struct mm_struct *mm,
                           unsigned long start, unsigned long nr_pages,
                           unsigned int gup_flags, struct page **pages,
                           int *locked);
long pin_user_pages_remote(struct mm_struct *mm,
                           unsigned long start, unsigned long nr_pages,
                           unsigned int gup_flags, struct page **pages,
                           int *locked);

long get_user_pages_unlocked(unsigned long start, unsigned long nr_pages,
                             struct page **pages, unsigned int gup_flags);
long pin_user_pages_unlocked(unsigned long start, unsigned long nr_pages,
                             struct page **pages, unsigned int gup_flags);

int  get_user_pages_fast(unsigned long start, int nr_pages,
                         unsigned int gup_flags, struct page **pages);
int  pin_user_pages_fast(unsigned long start, int nr_pages,
                         unsigned int gup_flags, struct page **pages);

int  get_user_pages_fast_only(unsigned long start, int nr_pages,
                              unsigned int gup_flags, struct page **pages);
```

Дві дрібниці в цих рядках варті окремого погляду. У `_unlocked` масив `pages` стоїть **третім**, а прапорці четвертими — порядок протилежний до решти сім'ї; тут компілятор урятує, бо переплутати покажчик із цілим не дасть, але переносити виклик з форми у форму наосліп не вийде. А `_fast` міряє кількість сторінок знаковим `int` і повертає `int`, тоді як решта працює з `unsigned long` і `long` — на діапазонах у мільйони сторінок звуження мовчазне й наслідки в нього неприємні.

| форма | чий простір | `mmap_lock` | може заснути |
|---|---|---|---|
| звичайна | лише `current->mm` | бере на читання сам виклик | так |
| `_remote` | будь-який `mm` | **бере той, хто кличе**, і передає через `locked` | так |
| `_unlocked` | лише `current->mm` | бере й **відпускає** сам виклик | так |
| `_fast` | лише `current->mm` | пробує без замка, при невдачі відступає до повільного шляху | так |
| `_fast_only` | лише `current->mm` | ніколи не бере замка й не відступає | **ні** |

Швидкий шлях іде таблицями сторінок без замків, спираючись на заборону переривань і на відкладене звільнення таблиць — той самий прийом [відкладеного звільнення під читачами](book:unix-linux/rcu-mechanism), що дозволяє читати структуру, яку хтось перебудовує. Саме тому він не може викликати обробку сторінкового збою: сторінки, якої ще немає в таблицях, він не здобуде, а поверне менше, ніж просили. Заснути під час обходу він теж не може — і в цьому вся різниця між `_fast` і `_fast_only`. Перший, недобравши сторінок, спокійно бере `mmap_lock` і доробляє повільним шляхом, тобто спати таки буде; єдиний виклик, придатний під замком чи в [контексті переривання](book:unix-linux/interrupts-bottom-halves), — `_fast_only`, і закріплення (`FOLL_PIN`) у нього немає взагалі.

## Домовленість про `locked`

Форма `_remote` — єдина, що працює в чужому адресному просторі, і саме тому замок з неї винесено назовні. Обидві сторони мусять дотримати трьох умов, і жодну з них тип аргументів не виражає.

Перше: `mmap_lock` для цього `mm` має бути **вже взятий** — на читання досить. Друге: у змінну, чию адресу передають, треба покласти одиницю ще до виклику; нуль означав би, що замка немає, а цього форма `_remote` не приймає. Третє й найважливіше: щоб не тримати замок під час чекання на диск, виклик має право його **відпустити**, і тоді він запише в цю змінну нуль. Тобто після повернення знімати замок можна лише за умови, що там усе ще одиниця.

```c
int locked = 1;

mmap_read_lock(mm);
pinned = pin_user_pages_remote(mm, start, nr_pages,
			       FOLL_WRITE, pages, &locked);
if (locked)
	mmap_read_unlock(mm);   /* нуль означає: замок уже відпущено */
```

Сам `mm` теж треба вміти дотримати живим: чужий адресний простір зникне разом із процесом, тому посилання на нього беруть заздалегідь (`mmget`) і віддають після роботи.

## Прапорці

| прапорець | значення | хто ставить |
|---|---|---|
| `FOLL_WRITE` | вимагати право запису: сторінка має бути придатною до запису, копіювання при записі — розщепленим наперед | той, хто кличе |
| `FOLL_GET` | узяти звичайне посилання (`+1` до лічильника) | ставить сам виклик `get_user_pages*` |
| `FOLL_PIN` | узяти закріплення окремим обліком; **внутрішній**, у заголовках його немає | ставить сам виклик `pin_user_pages*` |
| `FOLL_LONGTERM` | утримання невизначено довге: спершу перенести сторінки геть із рухомих ділянок, потім закріпити | той, хто кличе |
| `FOLL_FORCE` | обійти права ділянки — читати з `PROT_NONE`, писати в приватну ділянку без права запису | той, хто кличе |
| `FOLL_NOFAULT` | не викликати обробку збою: чого немає в таблицях, того й не буде в результаті | той, хто кличе |
| `FOLL_INTERRUPTIBLE` | дозволити звичайним сигналам перервати чекання | той, хто кличе |

Заборонені сполучення перевіряються на вході й дають `WARN_ON_ONCE` разом із відмовою:

```
FOLL_GET | FOLL_PIN              — взаємно виключні в одному виклику
FOLL_LONGTERM без FOLL_PIN       — довге утримання буває лише в закріплення
FOLL_GET або FOLL_PIN, pages=NULL — нема куди складати результат
FOLL_LONGTERM | FOLL_PCI_P2PDMA  — пам'ять пристрою має лишатися виймуваною
```

Виключність стосується **виклику**, а не сторінки: та сама сторінка може одночасно мати і звичайні посилання, і закріплення від різних місць — це обмеження на того, хто кличе, а не на пам'ять.

`FOLL_PIN` ніколи не передають руками, і це не стилістична забаганка. Прапорець живе у внутрішньому заголовку саме для того, щоб намір «беру закріплення» не можна було виставити повз обгортку, яка знає, чим його потім звільняти.

`FOLL_FORCE` теж вужчий, ніж здається з назви. Разом із `FOLL_WRITE` він дозволяє писати лише в приватну ділянку, що копіюється при записі, — тобто розщепити сторінку й писати у **свою** копію; це той механізм, яким налагоджувач ставить точку зупину в коді, відображеному лише для читання. У спільну ділянку без права запису він не пустить: там запис пішов би просто у файл. Без `FOLL_WRITE` він знімає вимогу права читання, але ділянка все одно мусить бути придатною до читання за своїми максимальними правами.

Швидкий шлях приймає вужчий набір: `FOLL_WRITE`, `FOLL_LONGTERM`, `FOLL_FORCE`, `FOLL_PIN`, `FOLL_GET`, `FOLL_NOFAULT`, `FOLL_PCI_P2PDMA`, `FOLL_HONOR_NUMA_FAULT` і службовий `FOLL_FAST_ONLY`. Будь-що інше — одразу `-EINVAL`.

Коли який прапорець потрібен, у ядрі описано п'ятьма випадками. [Прямий ввід-вивід](book:unix-linux/buffered-and-direct-io) — `FOLL_PIN` без `FOLL_LONGTERM`, бо буфер живе мілісекунди. Реєстрація буферів під віддалений доступ до пам'яті — `FOLL_PIN | FOLL_LONGTERM`. Драйвер, що замість закріплення підписався на [сповіщення про зміни відображень](book:unix-linux/mmu-notifiers) і зупиняє передавання за зворотним викликом, не потребує жодного з двох. Робота лише з описом сторінки, без доступу до вмісту, — теж жодного. І окремий випадок, який плутають найчастіше: «закріпив, записав у вміст, відпустив» без будь-якого DMA все одно вимагає `FOLL_PIN`, бо файлова система мусить бачити, що вміст міняють повз таблиці сторінок.

## Що повертається

Повернене число має три різні значення залежно від знака, і **часткова вдача — це норма, а не збій**: діапазон міг упертися в межу ділянки, у нестачу пам'яті, у сторінку, яку не вдалося перенести з рухомої зони.

| виклик | негодящі аргументи | не здобуто жодної | здобуто частину |
|---|---|---|---|
| `get_user_pages*` (усі форми) | `-EINVAL` | `-errno` | `n`, `1 ≤ n < nr_pages` |
| `pin_user_pages`, `_remote`, `_unlocked` | **`0`** | `-errno` | `n`, `1 ≤ n < nr_pages` |
| `pin_user_pages_fast` | `-EINVAL` | `-errno` | `n`, `1 ≤ n < nr_pages` |

Ця розбіжність у першому стовпці справжня: три форми закріплення на негодящих аргументах повертають нуль, а не від'ємний код. Умова `if (ret < 0)` їх не спіймає — перевіряти треба `ret <= 0`. Нуль повертається й тоді, коли попросили нуль сторінок.

Друга пастка сидить у швидкому шляху. Коли він здобув частину сторінок, а повільний доробок далі провалився, повертається **кількість здобутого**, а не помилка: віддати `-errno` тут не можна, бо вже здобуті сторінки хтось мусить відпустити, і зробити це може лише той, хто кличе.

| код | коли |
|---|---|
| `-EFAULT` | адреса поза відображеннями; ділянка `VM_IO`/`VM_PFNMAP` або secretmem; запис у ділянку без права запису й без `FOLL_FORCE`; кінець діапазону вище `TASK_SIZE_MAX` |
| `-EINVAL` | заборонене сполучення прапорців |
| `-EOVERFLOW` | `start + nr_pages · PAGE_SIZE` переповнює адресу (швидкий шлях) |
| `-EOPNOTSUPP` | `FOLL_LONGTERM` на ділянці FS-DAX; `FOLL_SPLIT_PMD` на hugetlb |
| `-ENOMEM`, `-EBUSY` | під `FOLL_LONGTERM` не вдалося перенести сторінки з рухомої ділянки |
| `-EINTR` | чекання перервано сигналом під `FOLL_INTERRUPTIBLE` |

Елементи масиву `pages` понад повернене число залишаються недоторканими — сміття з попереднього вжитку, яке не можна ні читати, ні звільняти. Початок діапазону виклик вирівнює донизу сам, тож `start` посеред сторінки не помилка.

## Чим звільняти

| що взяли | чим віддати | коли |
|---|---|---|
| `get_user_pages*` | `put_page(page)` | по одній сторінці |
| `pin_user_pages*` | `unpin_user_page(page)` | по одній |
| `pin_user_pages*` | `unpin_user_pages(pages, npages)` | масивом, без позначки «брудна» |
| `pin_user_pages*` | `unpin_user_pages_dirty_lock(pages, npages, make_dirty)` | масивом, з позначкою «брудна» |
| `pin_user_pages*` | `unpin_user_page_range_dirty_lock(page, npages, make_dirty)` | суцільним діапазоном від однієї сторінки |
| `memfd_pin_folios` | `unpin_folio` / `unpin_folios` | для фоліо — набору суміжних сторінок з одним описом |

Правило про позначку просте: якщо закріплювали з `FOLL_WRITE` і пристрій справді щось записав — `make_dirty = true`, інакше змінений вміст може не дійти до диска. Виклик сам бере потрібний замок відображення й пропускає сторінки, уже позначені брудними; з `make_dirty = false` він зводиться до `unpin_user_pages`.

`unpin_user_pages` перевіряє свій другий аргумент на схожість до від'ємного коду помилки й у такому разі виводить попередження й нічого не робить. Це рятує від найпоширенішої помилки: передати сюди результат виклику, не перевіривши знак.

Нульова сторінка — виняток, прозорий для того, хто кличе: закріплення на ній лише вдають, лічильників не чіпають, і зняття теж нічого не робить.

## Запити стану

```c
bool folio_maybe_dma_pinned(struct folio *folio);
bool folio_has_pincount(const struct folio *folio);
void folio_add_pin(struct folio *folio);   /* додати закріплення до вже закріпленого */
```

Відповідь `folio_maybe_dma_pinned` наближена **лише в один бік**. «Ні» — точне: сторінка гарантовано не закріплена. «Так» може виявитися хибним, бо для дрібних сторінок закріплення кодується зсувом лічильника посилань:

```
GUP_PIN_COUNTING_BIAS            = 1U << 10 = 1024
розрядів у лічильнику посилань   = 31 (знакове ціле)
лишається під кількість закріплень = 31 − 10 = 21
```

Тобто 1024 звичайні посилання на одну дрібну сторінку виглядатимуть як одне закріплення, а самих закріплень уміщається близько 2²¹. Для великих фоліо `folio_has_pincount` повертає істину — там є окреме поле `_pincount`, і відповідь точна.

## Лічильники в /proc/vmstat

```
nr_foll_pin_acquired   узятих закріплень від завантаження
nr_foll_pin_released   знятих закріплень від завантаження
```

За нормальних умов ці два числа рівні — розходяться вони лише на час переходів і на живі довгі закріплення. Звідси спосіб ловити витік: зняти різницю, коли жоден пристрій не працює, і подивитися, чи вона повертається до сталої.

```sh
$ grep nr_foll_pin /proc/vmstat
nr_foll_pin_acquired 40928
nr_foll_pin_released 40928
```

Різниця, що росте від запуску до запуску того самого драйвера, означає, що він не відпускає закріплень. Це єдиний спосіб побачити такий витік ззовні: закріплення переживає процес, тому в звітах про пам'ять процесу зниклі кадри не видно взагалі.

Облік ведеться в сторінках звичайного розміру. Велика сторінка при закріпленні дає стільки одиниць, скільки в ній звичайних сторінок, а знімати закріплення можна посторінково — тому баланс сходиться навіть тоді, коли брали цілим шматком, а віддавали частинами.

## Облік за межею замкненої пам'яті

Ядро само не рахує закріплені сторінки проти [межі замкненої пам'яті](book:unix-linux/memory-locking) — це робить драйвер, окремим викликом:

```c
int account_locked_vm(struct mm_struct *mm, unsigned long pages, bool inc);
```

Повертає `0` або `-ENOMEM`, якщо `mm->locked_vm + pages` перевищить `RLIMIT_MEMLOCK` із [набору лімітів ресурсів](book:unix-linux/resource-limits). Володарям `CAP_IPC_LOCK` перевірку не роблять. Виклик сам бере `mmap_lock` на запис — це [замок на читання-запис](book:unix-linux/kernel-locking), тож із-під уже взятого замка кликати його не можна; для такого випадку є `__account_locked_vm`, який вимагає, щоб замок на запис уже тримали.

## Мінімальний виклик

```c
int pin_buffer(unsigned long start, int nr_pages, struct page ***out)
{
	struct page **pages;
	int pinned, ret;

	pages = kvmalloc_array(nr_pages, sizeof(*pages), GFP_KERNEL);
	if (!pages)
		return -ENOMEM;

	ret = account_locked_vm(current->mm, nr_pages, true);
	if (ret)
		goto free_pages;

	/* FOLL_LONGTERM: пристрій триматиме буфер, доки живе реєстрація */
	pinned = pin_user_pages_fast(start, nr_pages,
				     FOLL_WRITE | FOLL_LONGTERM, pages);
	if (pinned <= 0) {
		ret = pinned ? pinned : -EFAULT;
		goto unaccount;
	}

	/* часткова вдача — норма: далі працюємо з pinned, а не з nr_pages */
	*out = pages;
	return pinned;

unaccount:
	account_locked_vm(current->mm, nr_pages, false);
free_pages:
	kvfree(pages);
	return ret;
}
```

Звільнення дзеркальне й мусить назвати те саме число, яке повернуло закріплення:

```c
unpin_user_pages_dirty_lock(pages, pinned, true);
account_locked_vm(current->mm, nr_pages, false);
kvfree(pages);
```

`FOLL_LONGTERM` у швидкому виклику не суперечність, хоч і виглядає нею. Обхід без замків уміє лише впізнати сторінку, непридатну до довгого утримання, — наприклад, ту, що лежить у [резерві суцільної пам'яті для пристроїв](book:unix-linux/cma-contiguous-allocator), — і на ній зупинитися. Далі підхоплює повільний шлях: він переносить такі сторінки в звичайну пам'ять і закріплює вже копії. Саме звідти беруться `-ENOMEM` та `-EBUSY`, яких у короткого закріплення не буває ніколи, — і саме тому виклик із цим прапорцем повертає менше, ніж просили, частіше за всі інші.
