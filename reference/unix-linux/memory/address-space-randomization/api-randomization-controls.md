# 🎛 Регулятори рандомізації адрес у Linux: сисктли, personality, ключі збірки

Це перелік усіх місць, де в Linux вирішується, чи будуть адреси в процесі випадковими й наскільки: кожен регулятор — із точною назвою, шляхом, діапазоном значень, потрібними правами і тим моментом, коли ядро його читає. Числа й межі звірено з чинним деревом ядра (`mm/mmap.c`, `mm/memory.c`, `fs/exec.c`, `fs/binfmt_elf.c`, `arch/x86/Kconfig`, `arch/arm64/Kconfig`) та документацією `Documentation/admin-guide/sysctl/`.

## Три моменти, коли регулятор читають

Регулятори не рівноправні — вони діють у різні моменти життя програми, і це визначає, коли зміна набирає чинності.

| Момент | Що вирішується | Хто регулює |
|---|---|---|
| компіляція й лінкування | чи має виконуваний файл право лежати за будь-якою адресою | `-fPIE`/`-pie` проти `-no-pie` |
| збірка ядра | чи є в ядрі відповідний код і які межі в сисктлів | символи `CONFIG_*` |
| завантаження ядра | KASLR образу ядра, стартовий стан кількох перемикачів | параметри командного рядка |
| `execve` | чи тягнути жереб для цього процесу і якої ширини | сисктли + прапорець `personality` |

Головне правило: **сисктли рандомізації читають у момент [`execve`](topic:unix-linux/exec-semantics)** — саме там ядро будує карту пам'яті з нуля. Ядро знімає з `kernel.randomize_va_space` знімок (`READ_ONCE`) і далі користується ним. Отже, зміна сисктла не рухає жодного вже запущеного процесу.

> 🔧 **Навіщо це.** Звідси випливає порядок дій, який часто плутають: після правки `/etc/sysctl.d/…` службу треба **перезапустити**, а не «перечитати конфігурацію». Перечитування конфігурації — це робота самої служби зі своїми файлами; карта пам'яті при цьому не перебудовується, бо `execve` не викликали.

## Сисктли

### kernel.randomize_va_space

| Властивість | Значення |
|---|---|
| шлях | `/proc/sys/kernel/randomize_va_space` |
| режим доступу | `0644` — читати може будь-хто, писати лише root |
| обробник | `proc_dointvec` — **без обмеження діапазону** |
| типове значення | `2`, або `1`, якщо ядро зібране з `CONFIG_COMPAT_BRK` |

| Значення | Що рухається |
|---|---|
| `0` | нічого; ядро не ставить процесові прапорець `PF_RANDOMIZE` |
| `1` | база відображень (усі бібліотеки й безіменні `mmap`), вершина стека, vDSO, а від ядра 4.1 — і власна база переміщуваного виконуваного файлу; **купа (`brk`) не рухається** |
| `2` | те саме плюс початок купи |

Оскільки обробник не обмежує діапазон, запис `3` чи `7` пройде без помилки й поводитиметься як `2`: ядро перевіряє лише «не нуль» для загального жереба й «більше за одиницю» для купи. Покладатися на це не варто — пишіть саме `0`, `1` або `2`.

### vm.mmap_rnd_bits і vm.mmap_rnd_compat_bits

Ці два сисктли задають не «чи рандомізувати», а **скільки бітів** дістає база відображень (і разом з нею база переміщуваного виконуваного файлу).

| Властивість | Значення |
|---|---|
| шляхи | `/proc/sys/vm/mmap_rnd_bits`, `/proc/sys/vm/mmap_rnd_compat_bits` |
| режим доступу | `0600` — навіть **прочитати** може лише root |
| обробник | `proc_dointvec_minmax` з архітектурними межами |
| поза межами | запис повертає `EINVAL` (`sysctl: setting key ...: Invalid argument`) — тихого обрізання немає |
| `compat`-варіант | діє на 32-бітні задачі під 64-бітним ядром ([шар сумісності](topic:unix-linux/compat-32-on-64)) |

Межі й типові значення беруться з конфігурації архітектури: `CONFIG_ARCH_MMAP_RND_BITS_MIN`, `…_MAX` і стартове `CONFIG_ARCH_MMAP_RND_BITS`, яке дорівнює мінімуму, якщо архітектура не задала окремого типового.

| Архітектура | `mmap_rnd_bits`: мін…макс (типово) | `mmap_rnd_compat_bits`: мін…макс (типово) |
|---|---|---|
| x86-64 | 28…32 (28) | 8…16 (8) |
| x86, 32-бітне ядро | 8…16 (8) | — |
| arm64, сторінка 4 КіБ, VA 48 біт | 18…33 (18) | 11…16 (11) |
| arm64, сторінка 16 КіБ, VA 48 біт | 16…31 (16) | 9…16 (9) |
| arm64, сторінка 64 КіБ, VA 48 біт | 14…29 (14) | 7…16 (7) |

На arm64 стеля залежить ще й від налаштованої ширини віртуальної адреси: при `ARM64_VA_BITS=39` максимум 24, при 42 — 27, при 47 — 30. Дистрибутив може задати власне стартове значення, тому «типово» тут — типово для ванільного ядра, а не гарантія на вашій машині.

### Сисктли, що затикають витоки

Ці три нічого не рандомізують — вони закривають канали, крізь які адреса ядра могла б витекти назовні, а без них рандомізація ядра нічого не варта.

| Сисктл | Значення | Дія |
|---|---|---|
| `kernel.kptr_restrict` | `0` | покажчики, друковані через `%pK`, проходять крізь хешування |
| | `1` | замість покажчика нулі, якщо немає `CAP_SYSLOG` ([можливості](topic:unix-linux/capabilities) — дрібні шматки прав root) |
| | `2` | нулі всім, незалежно від прав |
| `kernel.dmesg_restrict` | `0` | журнал ядра читає будь-хто |
| | `1` | для `dmesg(8)` потрібна `CAP_SYSLOG` |
| `kernel.perf_event_paranoid` | `-1` | майже всі події доступні всім |
| | `0` | без `CAP_PERFMON` заборонено трасувальні точки функцій |
| | `1` | без `CAP_PERFMON` заборонено події процесора |
| | `2` (типово) | без `CAP_PERFMON` заборонено профілювати ядро ([підсистема perf](topic:unix-linux/perf-events) вміє віддавати адреси ядра у вибірках) |

Ці два останні зчеплені між собою в неочевидний спосіб. Видимість справжніх адрес у `/proc/kallsyms` вирішує функція `kallsyms_show_value`, і при `kptr_restrict = 0` вона віддає адреси **всім**, якщо `perf_event_paranoid ≤ 1`; при `kptr_restrict = 1` потрібна `CAP_SYSLOG`; при `2` не бачить ніхто. Тобто послаблення `perf_event_paranoid` заради профілювання відкриває заразом і базу ядра.

### Як зробити зміну сталою

```sh
# разово, до перезавантаження
sudo sysctl -w kernel.randomize_va_space=2

# назавжди
echo 'kernel.randomize_va_space = 2' | sudo tee /etc/sysctl.d/60-aslr.conf
sudo sysctl --system

# перевірити чинне (mmap_rnd_bits читається лише з-під root)
cat /proc/sys/kernel/randomize_va_space
sudo cat /proc/sys/vm/mmap_rnd_bits
```

## personality(2): вимикач на один процес

```c
#include <sys/personality.h>

int personality(unsigned long persona);
```

Повертає **попереднє** значення особистості, або `-1` з `errno = EINVAL`. Прав не потрібно: процес шкодить лише собі.

Значення — 32-бітне число, у якому молодший байт (`PER_MASK = 0x00ff`) задає домен виконання, а старші три байти — прапорці поведінки.

| Константа | Значення | Дія |
|---|---|---|
| `ADDR_NO_RANDOMIZE` | `0x0040000` | під час наступного `execve` жереба не буде |
| `ADDR_COMPAT_LAYOUT` | `0x0200000` | стара розкладка `mmap` — знизу вгору від `TASK_UNMAPPED_BASE`; ентропії не забирає, змінює напрямок росту |
| `READ_IMPLIES_EXEC` | `0x0400000` | `PROT_READ` тягне за собою `PROT_EXEC` |
| `MMAP_PAGE_ZERO` | `0x0100000` | нульова сторінка відображається лише для читання |
| `ADDR_LIMIT_32BIT` | `0x0800000` | адресний простір обмежено 32 бітами |
| `ADDR_LIMIT_3GB` | `0x8000000` | адресний простір обмежено трьома гігабайтами |
| `UNAME26` | `0x0020000` | `uname` бреше про версію ядра |
| `PER_LINUX` | `0x0000` | типовий домен (молодший байт) |
| `PER_LINUX32` | `0x0008` | `uname -m` віддає назву 32-бітної архітектури |

Читати чинне значення треба **окремим викликом** з аргументом `0xffffffff` — ядро розпізнає його як «не міняти». Далі новий стан складається з прочитаного, а не пишеться поверх: інакше ви заразом зітрете домен у молодшому байті й чужі прапорці.

:::tabs
```c
#define _GNU_SOURCE
#include <stdio.h>
#include <sys/personality.h>
#include <unistd.h>

int main(int argc, char *argv[])
{
    if (argc < 2) {
        fprintf(stderr, "usage: %s program [args...]\n", argv[0]);
        return 2;
    }

    /* 1. Прочитати чинну особистість, нічого не змінюючи. */
    int cur = personality(0xffffffff);
    if (cur == -1) {
        perror("personality (read)");
        return 1;
    }

    /* 2. Додати один біт, зберігши все інше — і домен у молодшому байті. */
    if (personality((unsigned long)cur | ADDR_NO_RANDOMIZE) == -1) {
        perror("personality (set)");
        return 1;
    }

    /* 3. Карту будує саме execve — і тепер він будуватиме її без жереба. */
    execvp(argv[1], &argv[1]);
    perror("execvp");
    return 1;
}
```

### Що з прапорцем стається при fork і execve

| Подія | Що стається з `ADDR_NO_RANDOMIZE` |
|---|---|
| `fork`, `clone` | успадковується без змін — та й нового жереба немає, карту просто копіюють |
| `execve` звичайного файлу | зберігається; ядро дивиться на нього, вирішуючи, чи ставити `PF_RANDOMIZE` |
| `execve` файлу з бітом setuid або setgid | **стирається** разом із `READ_IMPLIES_EXEC`, `ADDR_COMPAT_LAYOUT`, `MMAP_PAGE_ZERO` |
| `execve` файлу з файловими можливостями, що додають прав | стирається так само |

Стирання — не побічний ефект, а іменована маска `PER_CLEAR_ON_SETID` в `include/uapi/linux/personality.h`; ядро застосовує її в `fs/exec.c` рядком `me->personality &= ~bprm->per_clear`. Сенс прямий: інакше будь-хто вимкнув би рандомізацію привілейованій програмі перед тим, як її атакувати ([setuid і підвищення прав](topic:unix-linux/setuid-and-privilege) — механізм, через який чужий файл виконується з чужими правами).

Умова жереба в `fs/binfmt_elf.c` — кон'юнкція, і це варто тримати в голові:

```
PF_RANDOMIZE ставиться ⟺ (personality & ADDR_NO_RANDOMIZE) == 0
                        ∧ randomize_va_space != 0
```

Історична примітка про сумісність: до виправлення Їржі Косіни (2012) макрос `SET_PERSONALITY` на powerpc64 переписував особистість цілком і стирав прапорці старших байтів; у чинному ядрі він зберігає їх (`PER_LINUX | (current->personality & ~PER_MASK)`). На x86-64 запуск 32-бітного ELF чіпає лише `READ_IMPLIES_EXEC` — `ADDR_NO_RANDOMIZE` переживає його без втрат. Це перевірено за поточним деревом; на дуже старих ядрах поведінка інша.

### Файл `/proc/<pid>/personality`

| Властивість | Значення |
|---|---|
| вміст | чинна особистість шістнадцятковим числом, без префікса `0x` |
| з якого ядра | 2.6.28 |
| доступ | перевіркою `PTRACE_MODE_ATTACH_FSCREDS` — тобто за правилами [ptrace](topic:unix-linux/ptrace-model), який вирішує, кому взагалі можна зазирати в чужий процес |
| запис | неможливий |

## setarch(8): готова обгортка

`setarch` виставляє прапорці особистості й одразу робить `execve` — це весь його зміст. Від util-linux 2.33 аргумент-архітектуру можна не вказувати.

```
setarch [архітектура] [опції] програма [аргументи…]
```

| Коротка | Довга | Дія |
|---|---|---|
| `-R` | `--addr-no-randomize` | `ADDR_NO_RANDOMIZE` |
| `-L` | `--addr-compat-layout` | `ADDR_COMPAT_LAYOUT` |
| `-X` | `--read-implies-exec` | `READ_IMPLIES_EXEC` |
| `-Z` | `--mmap-page-zero` | `MMAP_PAGE_ZERO` |
| `-3` | `--3gb` | `ADDR_LIMIT_3GB` |
| `-B` | `--32bit` | `ADDR_LIMIT_32BIT` |
| `-T` | `--sticky-timeouts` | `STICKY_TIMEOUTS` |
| `-F` | `--fdpic-funcptrs` | `FDPIC_FUNCPTRS` |
| | `--uname-2.6` | `UNAME26` |
| | `--show[=число]` | показати прапорці — чинні або розібрати задане шістнадцяткове |
| `-p` | `--pid=PID` | разом із `--show`: прапорці чужого процесу |
| | `--list` | які назви архітектур програма знає |
| `-v` | `--verbose` | що саме воно робить |

```sh
# одна програма без жереба
setarch -R ./program

# ціла оболонка: прапорець успадкують усі нащадки
setarch -R bash

# подивитися прапорці — свої і чужі
setarch --show
setarch --show -p 1
```

## Параметри командного рядка ядра

| Параметр | Дія |
|---|---|
| `norandmaps` | те саме, що `echo 0 > /proc/sys/kernel/randomize_va_space` — стосується лише простору користувача |
| `nokaslr` | за `CONFIG_RANDOMIZE_BASE` вимикає рандомізацію бази образу ядра й модулів |
| `randomize_kstack_offset=on\|off` | випадковий зсув стека ядра на вході в системний виклик, близько 5 бітів ентропії |
| `kaslr` | **історичний**, лише x86: існував, поки `CONFIG_HIBERNATION` вимикав KASLR типово (2014–2016); з нинішньої документації ядра прибраний |

Куди їх писати — питання [завантажувача](topic:unix-linux/bootloader-and-cmdline), який передає ядру рядок параметрів. Перевірити, з чим система насправді завантажилася:

```sh
cat /proc/cmdline
```

## Символи конфігурації ядра

| Символ | Що вмикає |
|---|---|
| `CONFIG_RANDOMIZE_BASE` | KASLR: випадкова база образу ядра; вимагає `CONFIG_RELOCATABLE`, на x86 типово `y` |
| `CONFIG_RANDOMIZE_MEMORY` | випадкові бази внутрішніх областей ядра — прямого відображення фізичної пам'яті, `vmalloc`, `vmemmap`; лише x86-64, типово дорівнює `RANDOMIZE_BASE` |
| `CONFIG_RANDOMIZE_KSTACK_OFFSET` | зсув стека ядра на кожен системний виклик |
| `CONFIG_RANDOMIZE_KSTACK_OFFSET_DEFAULT` | чи ввімкнено попереднє без параметра завантаження |
| `CONFIG_COMPAT_BRK` | навпаки, **вимикає** рандомізацію купи й робить типовим `randomize_va_space = 1` |
| `CONFIG_HAVE_ARCH_MMAP_RND_BITS` | чи має архітектура настроювану ширину жереба взагалі |
| `CONFIG_ARCH_MMAP_RND_BITS` | стартове значення `vm.mmap_rnd_bits` |
| `CONFIG_ARCH_MMAP_RND_BITS_MIN`, `…_MAX` | межі, за які сисктл не пустить |
| `CONFIG_ARCH_MMAP_RND_COMPAT_BITS`, `…_MIN`, `…_MAX` | те саме для 32-бітних задач |

```sh
# конфігурація чинного ядра — там, де дистрибутив її поклав
zcat /proc/config.gz 2>/dev/null | grep RANDOMIZE
grep RANDOMIZE /boot/config-"$(uname -r)"
```

## Ключі компілятора й лінкера

Це єдиний поверх поза системою: якщо файл зібрано з фіксованою адресою, жоден сисктл його не зрушить.

| Ключ | Етап | Дія |
|---|---|---|
| `-fPIE`, `-fpie` | компіляція | [позиційно-незалежний код](topic:unix-linux/position-independent-code) із припущенням, що символи модуля ніхто не перекриє, тож звертання дешевші |
| `-fPIC`, `-fpic` | компіляція | те саме без цього припущення — для спільних бібліотек |
| `-pie` | лінкування | зібрати переміщуваний виконуваний файл (`ET_DYN` із сегментом `PT_INTERP`) |
| `-no-pie` | лінкування | зібрати `ET_EXEC` за адресою, яку призначив лінкер |
| `-fno-pie` | компіляція | вимкнути PIE-кодогенерацію; **сам собою типу файлу не змінює** |
| `-static-pie` | лінкування | статичний і водночас переміщуваний; потребує `-fPIE` і статичних бібліотек, зібраних як PIC |
| `-shared` | лінкування | `ET_DYN` без `PT_INTERP` — бібліотека, не програма |

Пастка з парністю: `-fno-pie` без `-no-pie` дає `ET_DYN`, і база все одно рухатиметься. Вимикати треба обидва. Типова поведінка залежить від того, як зібрано сам компілятор:

```sh
gcc -v 2>&1 | grep -o -- '--enable-default-pie'
```

Перевірка готового файлу через [заголовок ELF](topic:unix-linux/elf-structure), який оголошує тип образу:

```sh
readelf -h ./program | grep Type
#   DYN (Position-Independent Executable file)   ← PIE, база рухома
#   EXEC (Executable file)                       ← фіксована адреса
#   DYN (Shared object file)                     ← бібліотека, або PIE на старому readelf

readelf -d ./program | grep FLAGS_1     # прапорець PIE у динамічній секції
readelf -l ./program | grep INTERP      # є PT_INTERP → програма, немає → бібліотека
file ./program                          # "pie executable" проти "executable"
```

Окремий рядок для `DYN (Position-Independent Executable file)` з'явився в binutils лише 2021 року, коли `readelf` навчили дивитися на прапорець `DF_1_PIE`. На старіших системах PIE не відрізнити від бібліотеки за самим типом — розрізняє наявність `PT_INTERP`.

## Файли й змінні для спостереження

| Джерело | Формат | Що з нього видно |
|---|---|---|
| `/proc/<pid>/maps` | текст | рядок на ділянку: діапазон адрес, права, зсув у файлі, пристрій, inode, шлях |
| `/proc/<pid>/personality` | шістнадцяткове число | чинні прапорці особистості |
| `/proc/<pid>/auxv` | двійковий | пари `unsigned long` {тип, значення} до `AT_NULL` |
| `/proc/kallsyms` | текст | адреси символів ядра — або нулі, залежно від `kptr_restrict` і `perf_event_paranoid` |
| `/proc/cmdline` | текст | з якими параметрами завантажене ядро |
| `LD_SHOW_AUXV=1` | змінна оточення | завантажувач друкує весь допоміжний вектор іменами; у режимі підвищених прав ігнорується |

Значення з [допоміжного вектора](topic:unix-linux/auxiliary-vector) — того самого каналу, яким ядро передає програмі на старті готові числа, — які стосуються рандомізації:

| Константа | Номер | Значення |
|---|---|---|
| `AT_PHDR` | 3 | адреса таблиці заголовків програми — звідси рахують базу самого виконуваного файлу |
| `AT_BASE` | 7 | база динамічного завантажувача |
| `AT_ENTRY` | 9 | точка входу програми |
| `AT_SECURE` | 23 | чи запущено в режимі підвищених прав |
| `AT_RANDOM` | 25 | адреса шістнадцяти випадкових байтів від ядра |
| `AT_SYSINFO_EHDR` | 33 (x86, x86-64) | база vDSO |

Найкоротший спосіб побачити жереб на власні очі — [`/proc`](topic:unix-linux/proc-filesystem), де кожен процес виглядає як тека з файлами:

```sh
# три запуски — три різні бази
for i in 1 2 3; do head -n1 /proc/self/maps; done

# те саме з вимкненим жеребом — три однакові рядки
for i in 1 2 3; do setarch -R head -n1 /proc/self/maps; done
```

## Матриця покриття: який регулятор рухає що

| Ділянка | Джерело жереба | Ширина на x86-64 | Чим вимикається |
|---|---|---|---|
| база відображень: бібліотеки, `ld.so`, великі шматки купи | `arch_mmap_rnd()` | `vm.mmap_rnd_bits`, типово 28 біт | `randomize_va_space=0`, `ADDR_NO_RANDOMIZE` |
| база переміщуваного виконуваного файлу | окремий `arch_mmap_rnd()` — від ядра 4.1 незалежний | стільки ж | те саме, а також збірка з `-no-pie` (тоді не рухається взагалі) |
| вершина стека | архітектурна маска `STACK_RND_MASK` | 22 біти (11 для 32-бітної задачі) | `randomize_va_space=0`, `ADDR_NO_RANDOMIZE`; **окремого сисктла немає** |
| початок купи (`brk`) | `arch_randomize_brk()`, вікно 1 ГіБ | 18 біт (13 біт при вікні 32 МіБ для 32-бітної задачі) | `randomize_va_space ≤ 1`, `CONFIG_COMPAT_BRK`, `ADDR_NO_RANDOMIZE` |
| vDSO | окремий жереб ядра | окремого регулятора немає | `randomize_va_space=0`, `ADDR_NO_RANDOMIZE` |
| образ ядра й модулі | KASLR під час завантаження | ≈9 біт (вікно ≈1 ГіБ, крок 2 МіБ) | `nokaslr`, `CONFIG_RANDOMIZE_BASE=n` |
| внутрішні області ядра | `CONFIG_RANDOMIZE_MEMORY` | архітектурно | `nokaslr` вимикає разом із базою |
| стек ядра на вході в системний виклик | `randomize_kstack_offset` | ≈5 біт | `randomize_kstack_offset=off` |

## Комбінації, які нічого не дають

- **`randomize_va_space=2` над файлом `ET_EXEC`.** Сам виконуваний файл однаково ляже за адресою з заголовка (на x86-64 традиційно `0x400000`). Рухатимуться бібліотеки, стек і купа — а код програми, з якого зручно збирати шматки, лишиться на місці.
- **Підняти `vm.mmap_rnd_bits` при `randomize_va_space=0`.** Жереба не тягнуть узагалі, тож ширина ні на що не впливає.
- **Записати в `vm.mmap_rnd_bits` більше за архітектурну стелю.** Повернеться `EINVAL`; мовчазного обрізання до максимуму немає.
- **`nokaslr`, щоб «вимкнути ASLR для програми».** Це різні поверхи: `nokaslr` не чіпає простору користувача, `randomize_va_space=0` не чіпає ядра.
- **Правити сисктл «для вже запущеної служби».** Значення читають у момент `execve` — потрібен перезапуск процесу.
- **`setarch -R` над уже запущеним процесом.** Прапорець діє на наступний `execve`, а не на чинну карту; для чужого процесу його взагалі не виставити.
- **Виставити `ADDR_NO_RANDOMIZE` перед запуском setuid-програми.** Ядро зітре прапорець маскою `PER_CLEAR_ON_SETID`, і жереб таки буде.
- **`-fno-pie` без `-no-pie`.** Тип файлу лишиться `ET_DYN`, і база рухатиметься попри намір.
