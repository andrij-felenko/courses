# API: move_pages та migrate_pages

Linux надає спеціалізовані системні виклики для міграції сторінок з простору користувача. Це критично для HPC (High-Performance Computing) додатків, які хочуть самостійно керувати розміщенням пам'яті (NUMA-оптимізація).

## `migrate_pages()`

Цей виклик переміщує *всі* сторінки процесу (або іншого процесу, якщо є права) з одного набору NUMA-вузлів на інший.

```c
#include <numaif.h>

long migrate_pages(int pid, unsigned long maxnode,
                   const unsigned long *old_nodes,
                   const unsigned long *new_nodes);
```

Він намагається знайти всі сторінки в `old_nodes` і перемістити їх у `new_nodes`. Це операція "насипного" (bulk) переміщення.

## `move_pages()`

Дозволяє хірургічну точність: ви вказуєте масив конкретних віртуальних адрес, і для кожної з них — бажаний NUMA-вузол.

```c
#include <numaif.h>

long move_pages(int pid, unsigned long count, void **pages,
                const int *nodes, int *status, int flags);
```

- `pages`: масив вказівників на сторінки.
- `nodes`: масив цільових вузлів (або `NULL`, якщо хочете просто дізнатися, де сторінки зараз).
- `status`: сюди ядро запише результат для кожної сторінки (наприклад, чи вдалося її перенести).
- `flags`: наприклад, `MPOL_MF_MOVE` (переміщувати лише ексклюзивні сторінки) або `MPOL_MF_MOVE_ALL` (переміщувати навіть спільні сторінки, вимагає привілеїв `CAP_SYS_NICE`).

Ці виклики під капотом використовують саме той механізм ізоляції, unmap, копіювання та remap, що був описаний в основній статті.
