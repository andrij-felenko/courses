# KSM: злиття однакових сторінок

<preknowlist>
- [Копіювання при записі](book:unix-linux/copy-on-write) — спільний кадр тримають під забороною запису; перший, хто пише, дістає власну копію.
- [Свопінг і витіснення сторінок](book:unix-linux/swap-and-reclaim) — щоб забрати фізичний кадр, ядро має знайти всіх, хто на нього вказує.
</preknowlist>

Коли на одній машині працюють десятки однакових віртуальних машин або контейнерів, їхня пам'ять заповнена однаковими даними: той самий код `libc`, ті самі системні бібліотеки, однакові базові образи. Зазвичай ядро вміє тримати одну копію в пам'яті лише тоді, коли ці процеси спільно прочитали один файл або успадкували пам'ять через `fork`. Але якщо вони дійшли до однакового вмісту незалежно (наприклад, кожен завантажив свій образ системи), для ядра це різні сторінки, які забирають дорогоцінну RAM.

**KSM (Kernel Samepage Merging)** — це механізм ядра Linux, який знаходить такі сторінки з однаковим вмістом і зливає їх у єдиний фізичний кадр, вивільняючи решту.

## Як працює пошук і злиття

Порівнювати кожну сторінку з кожною неможливо — це трильйони операцій. Замість цього потік ядра `ksmd` періодично сканує пам'ять і будує два дерева пошуку:
1. **Стабільне дерево** — тут лежать сторінки, які вже були злиті. Вони захищені від запису.
2. **Нестабільне дерево** — тут лежать звичайні сторінки-кандидати.

Якщо `ksmd` знаходить дві сторінки з однаковим вмістом, він перенаправляє записи в таблицях сторінок обох процесів на один фізичний кадр. Цей кадр помічається як «лише для читання». Звільнений другий кадр повертається системі.

Далі спільна сторінка живе за правилами [копіювання при записі](book:unix-linux/copy-on-write). Якщо будь-який процес спробує змінити свої дані, станеться сторінковий збій, і ядро мовчки створить для нього окрему копію сторінки. Програма нічого не помітить, окрім невеликої затримки на час збою.

## Ціна дедуплікації

KSM економить гігабайти оперативної пам'яті, але вимагає компромісів:

1. **Витрати процесора.** Сканування пам'яті та хешування сторінок потребує часу CPU. KSM вигідний для довготривалих навантажень (флот ВМ), але не підходить для короткоживучих процесів.
2. **Довгі обходи зворотних відображень.** Коли один кадр використовують 10 000 процесів, ядру потрібно обійти 10 000 записів, щоб витіснити цей кадр у своп. Щоб уникнути зависань, Linux обмежує кількість процесів на один злитий кадр (типово 256), створюючи «двійників» спільної сторінки.
3. **Ризик одночасного розколу.** Зекономлена пам'ять — це лише відкладена обіцянка. Якщо всі 40 віртуальних машин одночасно почнуть оновлювати систему, відбудеться масове копіювання при записі, і система може раптово вичерпати пам'ять (OOM).

## Як увімкнути злиття

KSM обробляє лише **анонімну** пам'ять і лише ту, яку явно дозволили зливати. Сторінки файлового кешу до нього не потрапляють, оскільки вони й так спільні.

Щоб дозволити злиття, програма має викликати `madvise` з прапорцем `MADV_MERGEABLE`:

```c
#include <sys/mman.h>
#include <stdio.h>

int main() {
    size_t size = 100 * 1024 * 1024; // 100 MB
    void *addr = mmap(NULL, size, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    
    // Дозволяємо KSM зливати цю ділянку
    if (madvise(addr, size, MADV_MERGEABLE) == 0) {
        printf("KSM увімкнено для ділянки.\n");
    }
    
    return 0;
}
```

Для чужих програм, які не роблять таких викликів (наприклад, у контейнерах), KSM можна ввімкнути на весь процес за допомогою `prctl(PR_SET_MEMORY_MERGE)`.

## Безпека: атаки через оракул часу

Оскільки запис у злиту сторінку триває трохи довше через копіювання, це відкриває шлях для атак побічним каналом. Зловмисник може створити сторінку з секретними даними (наприклад, вгаданим паролем). Якщо ця сторінка зіллється зі справжньою сторінкою пароля іншого користувача, запис у неї буде повільнішим. Так зловмисник може підтвердити свої здогадки.

Через це KSM варто використовувати лише тоді, коли всі віртуальні машини чи контейнери належать одному власнику, тобто лежать у межах одного кола довіри. У публічних хмарах дедуплікацію між різними клієнтами сьогодні зазвичай вимикають.
