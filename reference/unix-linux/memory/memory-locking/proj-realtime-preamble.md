# ⚙️ Підготовка процесу до роботи з термінами

Це робочий кістяк того, що програма з кінцевим терміном виконує один раз на старті, перш ніж узятися до діла: прибиває пам'ять, розігріває стек і купу, а тоді сама себе міряє — бо повірити, що хвіст розподілу зник, можна тільки цифрам.

## Що саме тут вимірюють

Величина, заради якої все робиться, — не середній час звертання до пам'яті, а найгірший. Різниця між ними в цій задачі не кількісна: типове звертання коштує сотню наносекунд, звертання до сторінки, яку ядро тим часом забрало, — мілісекунди. Одна така подія за годину роботи не зіпсує жодного середнього й одноосібно зірве термін.

Тому програма міряє не «скільки в неї пішло», а «в яку найповільнішу смугу вона потрапила за весь прогін». Це змінює й спосіб перевірки: замір без штучного тиску на пам'ять нічого не показує, бо забирати сторінки ядру немає потреби. Чесний дослід — це два прогони того самого коду на тій самій машині під тим самим тиском, один із прибиванням, другий без.

## Що прослизає повз один рядок

Виклик `mlockall(MCL_CURRENT | MCL_FUTURE)` прибиває все, що вже відображено, і все, що буде відображено далі, — і цього справді досить, щоб жодна сторінка процесу не поїхала у своп. Але передбачний найгірший час вимагає ще двох речей: щоб сторінка вже **існувала** в мить, коли до неї звернуться, і щоб її поява не впиралася в межу, якої не вистачить. Псують це чотири джерела.

*Права колонка — це і є кістяк; далі вона просто записана кодом.*

## Кістяк

Порядок дій усередині має значення: прибивання йде першим, щоб усе, що розігрів створить після нього, потрапляло під `MCL_FUTURE` уже прибитим.

```c
#define _GNU_SOURCE
#include <sys/mman.h>
#include <sys/resource.h>
#include <malloc.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

static void die(const char *what) { perror(what); exit(1); }

/* Скільки байтів прибив саме цей процес: рядок VmLck, у кілобайтах. */
static long vmlck_kib(void)
{
    FILE *f = fopen("/proc/self/status", "r");
    if (!f) return -1;
    char line[256];
    long kib = -1;
    while (fgets(line, sizeof line, f))
        if (sscanf(line, "VmLck: %ld kB", &kib) == 1) break;
    fclose(f);
    return kib;
}

static void lock_everything(void)
{
    if (mlockall(MCL_CURRENT | MCL_FUTURE) == 0)
        return;

    int err = errno;                  /* getrlimit нижче має право його затерти */
    struct rlimit rl = { 0, 0 };
    getrlimit(RLIMIT_MEMLOCK, &rl);

    if (err == ENOMEM)
        fprintf(stderr, "mlockall: уперлися в межу прибитої пам'яті; "
                        "м'яка %llu Б, жорстка %llu Б, уже прибито %ld КіБ\n",
                (unsigned long long) rl.rlim_cur,
                (unsigned long long) rl.rlim_max, vmlck_kib());
    else if (err == EPERM)
        fprintf(stderr, "mlockall: межа нульова, а CAP_IPC_LOCK немає\n");

    errno = err;
    die("mlockall");
}

#define STACK_WARM (64 * 1024)        /* із запасом на найглибший ланцюг викликів */

static void warm_stack(void)
{
    unsigned char buf[STACK_WARM];
    memset(buf, 0, sizeof buf);       /* саме ЗАПИС — чому, див. пастки нижче */
    __asm__ __volatile__("" :: "r"(buf) : "memory");   /* щоб memset не викинули */
}

static void warm_heap(size_t bytes)
{
    if (!mallopt(M_TRIM_THRESHOLD, -1)   /* free() більше не зсуває верх купи вниз */
     || !mallopt(M_MMAP_MAX, 0)          /* великі шматки теж із купи, не окремим mmap */
     || !mallopt(M_ARENA_MAX, 1)) {      /* усі потоки — через одну, розігріту купу */
        fprintf(stderr, "mallopt: розподільник не прийняв налаштування\n");
        exit(1);
    }

    size_t page = (size_t) sysconf(_SC_PAGESIZE);
    unsigned char *p = malloc(bytes);
    if (!p) die("malloc");
    for (size_t i = 0; i < bytes; i += page)
        p[i] = 1;                        /* по одному запису на сторінку */
    free(p);                             /* пам'ять лишається за процесом */
}

static void preamble(size_t working_set)
{
    lock_everything();
    warm_stack();
    warm_heap(working_set);
    fprintf(stderr, "готово: прибито %ld КіБ\n", vmlck_kib());
}
```

Три виклики `mallopt` варті окремого слова. Перший забороняє [розподільникові](book:unix-linux/allocator-and-kernel) віддавати ядру верх купи, коли програма щось звільнила; без нього кожен сплеск і спад робочого обсягу коштує сторінок, за які потім платять збоєм наново. Другий вимикає видачу великих шматків окремим відображенням — інакше кожне таке відображення живе рівно стільки, скільки шматок, і зникає разом із ним. Третій тримає всі потоки в одній купі, і саме він робить одноразовий розігрів корисним не тільки для головного потоку.

Лишається питання, на яке кістяк відповіді не має, бо відповідь залежить від програми: якою має бути межа прибитої пам'яті. Її рахують наперед і виставляють свідомо, а `VmLck` після преамбули звіряють із цим числом.

**Умова.** Демон із робочим обсягом 64 МіБ, чотирма робітниками по 1 МіБ стека, 40 МіБ коду й бібліотек у відображеннях і файловою ділянкою на 256 МіБ.

```
код і бібліотеки                 =  40 МіБ
купа після розігріву             =  64 МіБ
стек головного потоку            ≈ 0.1 МіБ   росте на вимогу, прибито рівно
                                             стільки, скільки заглибив розігрів
стеки 4 робітників × 1 МіБ       =   4 МіБ   відображаються цілими,
                                             тому й прибиваються цілими
файлова ділянка                  = 256 МіБ
                                   ────────
під межу                         ≈ 364 МіБ
```

Типової межі у 8 МіБ не вистачає вже на першому рядку, тож `mlockall` упреться в неї ще до розігріву. Розбіжність між цим підрахунком і `VmLck` теж інформативна: більше за очікуване означає, що прибилося щось непередбачене, менше — що частина запланованого лишилася без гарантії.

## Коли ділянка велика й розріджена

Гігабайтне відображення, з якого програма читатиме мегабайти, прибивати цілком не варто: це гігабайт із диска, гігабайт пам'яті й гігабайт межі заради мегабайта користі. Тут потрібне позначення `MLOCK_ONFAULT` — сторінки з'являються за першим звертанням, як і раніше, але кожна, що з'явилася, лишається.

```c
static void *map_sparse(int fd, size_t bytes)
{
    void *p = mmap(NULL, bytes, PROT_READ, MAP_PRIVATE, fd, 0);
    if (p == MAP_FAILED) die("mmap");
    if (mlock2(p, bytes, MLOCK_ONFAULT) != 0) die("mlock2");
    return p;
}
```

Порядок тут не косметичний. Поки діє `MCL_FUTURE`, кожен новий `mmap` населяють цілком просто в момент відображення — тобто гігабайт прочитають ще до того, як керування дійде до `mlock2`. Отже, розріджену ділянку відображають **до** прибивання, а прибивання тоді викликають як `mlockall(MCL_CURRENT | MCL_FUTURE | MCL_ONFAULT)`: із цим прапорцем воно замикає сторінки, які вже в пам'яті, і не тягне туди відсутні. Ціна вибору чесна — код і бібліотеки, до яких програма ще не зверталася, лишаються ненаселеними, і закривають це кількома холостими обертами робочого циклу перед тим, як умикати термін.

## Вимірювальна частина

Замір складається з проходу по сторінках і гістограми за степенями двійки: смуга `k` збирає звертання, що вклалися в `[2ᵏ, 2ᵏ⁺¹)` наносекунд. Логарифмічні смуги тут доречніші за середні, бо цікавий діапазон розтягнуто на п'ять порядків.

```c
#include <stdint.h>
#include <time.h>
#include <fcntl.h>

static inline uint64_t now_ns(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (uint64_t) ts.tv_sec * 1000000000ull + ts.tv_nsec;
}

static volatile unsigned char sink;

static void probe(const unsigned char *area, size_t bytes, unsigned long hist[64])
{
    size_t page = (size_t) sysconf(_SC_PAGESIZE);
    for (size_t off = 0; off < bytes; off += page) {
        uint64_t t0 = now_ns();
        sink = area[off];
        uint64_t dt = now_ns() - t0;
        unsigned k = 0;
        while (dt >>= 1) k++;
        hist[k]++;
    }
}

static void report(const char *tag, const unsigned long hist[64])
{
    int hi = 63;
    while (hi > 0 && hist[hi] == 0) hi--;
    printf("%s — найгірше звертання у смузі %llu нс\n", tag, 1ull << hi);
    for (int k = 0; k <= hi; k++)
        if (hist[k])
            printf("  %10llu нс  %lu\n", 1ull << k, hist[k]);
}

int main(int argc, char **argv)
{
    if (argc < 2) { fprintf(stderr, "вжиток: %s <файл> [--locked]\n", argv[0]); return 2; }
    int locked = (argc > 2 && strcmp(argv[2], "--locked") == 0);
    size_t bytes = 256u << 20;

    int fd = open(argv[1], O_RDONLY);
    if (fd < 0) die("open");
    unsigned char *area = mmap(NULL, bytes, PROT_READ, MAP_PRIVATE, fd, 0);
    if (area == MAP_FAILED) die("mmap");

    if (locked)
        preamble(64u << 20);        /* mlockall накриє і щойно відображений файл */

    static unsigned long hist[64];
    probe(area, bytes, hist);       /* холостий прохід: сторінки мають бути населені */
    memset(hist, 0, sizeof hist);
    probe(area, bytes, hist);       /* власне замір */
    report(locked ? "прибито" : "як є", hist);
    return 0;
}
```

Підлога заміру — самі виклики `clock_gettime`: пара звертань до `CLOCK_MONOTONIC` коштує кілька десятків наносекунд і не входить у ядро взагалі, бо годинник читають через [спільну сторінку коду vdso](book:unix-linux/vdso). Це якраз на порядок менше за найдешевше звертання до пам'яті, тож смуги не пливуть.

Тиск створюють окремо, і без нього дослід порожній:

```sh
fallocate -l 256M /tmp/probe.bin     # ділянка, по якій ходитиме замір
ulimit -l unlimited                  # інакше mlockall упреться в межу

stress-ng --vm 4 --vm-bytes 85% --vm-keep --timeout 300s &

./preamble /tmp/probe.bin            # прогін як є
./preamble /tmp/probe.bin --locked   # прогін із прибиванням
```

Ділянку тут навмисно взято файлову. Чисту сторінку файлу [збирач](book:unix-linux/swap-and-reclaim) викидає завжди, бо копія лежить на диску; анонімну ж він може забрати тільки у своп, і на машині без свопу вона й так невитіснювана — прибивання анонімної пам'яті там нічого не змінить, і замір покаже дві однакові гістограми. Тиск можна ще й обмежити однією групою процесів через межу пам'яті контрольної групи — тоді решта машини заміру не помітить.

![Дві гістограми: середина розподілу однакова, а хвіст без прибивання доходить до мілісекунд, з прибиванням обривається на десятках мікросекунд](/reference/unix-linux/memory/memory-locking/img/worst-case-tail.svg)

*Форма, якої слід чекати: прибивання не пришвидшує звичайне звертання й не має цього робити — воно відрізає другий горб.*

Той самий риг переносять у справжню програму майже без змін, і тоді він стає постійним наглядом: міряють не звертання до сторінки, а один оберт робочого циклу, тим самим `now_ns` і в ту саму гістограму. Високі смуги при цьому вже не обов'язково про пам'ять, тож поруч читають власні лічильники збоїв процесу — `ru_minflt` і `ru_majflt` із `getrusage`. Оберт, що потрапив у мілісекундну смугу без приросту `ru_majflt`, на диск не їздив, і винне щось інше; приріст `ru_minflt` без диска вказує на сторінку, яку щойно виділили, — тобто на дірку в розігріві.

## Пастки

**Розігрів читанням розігріває не до кінця.** Читання ще не населеної анонімної сторінки не виділяє кадру: [збій](book:unix-linux/page-fault) підставляє одну спільну нульову сторінку, доступну лише на читання. Сторінка ніби є, а перший же запис у неї впаде в збій [копіювання при записі](book:unix-linux/copy-on-write) — уже без диска, але з виділенням і очищенням кадру, тобто одиниці мікросекунд у найнепідхожішу мить. Тому розігрів пише. Сам `mlock` цієї пастки не має: населяючи приватну ділянку, доступну на запис, він одразу просить запису й нульової сторінки не лишає, — а от рукотворний обхід у коді її має цілком.

**Компілятор має право стерти розігрів.** `memset` у локальний масив, який далі ніхто не читає, — мертвий код, і оптимізатор його прибере, лишивши програму без розігріву й без жодної ознаки цього. Порожня асемблерна вставка з позначкою `"memory"` і адресою масиву в операнді робить масив спостережуваним ззовні й закриває питання.

**Після розгалуження прибивання немає.** [Нащадок](book:unix-linux/fork-semantics) успадковує адресний простір, але не прибивання й не саме `MCL_FUTURE`. Спільні сторінки, які для батька невитіснювані, для дитини звичайні, а перший її запис ще й розщепить сторінку в новий, нічим не прибитий кадр. Тому весь кістяк доводиться повторювати в дитині — і тому процес із термінами не розгалужується посеред роботи, а породжує все, що йому треба, до преамбули.

**Одного `mlockall` мало для потоків.** Тут дві окремі біди. Стек нового [потоку](book:unix-linux/threads-as-tasks) відображають на створенні, і `MCL_FUTURE` прибиває його цілим — а типовий розмір стека потоку дорівнює м'якій межі стека, тобто зазвичай 8 МіБ; при типовій же [межі прибитої пам'яті](book:unix-linux/resource-limits) у 8 МіБ другий потік просто не створиться. Розмір стека задають явно, а межу піднімають свідомо. Друга біда тихіша: розігрів пройшов по стеку головного потоку й по головній купі, тож кожен потік мусить розігріти свій стек сам, а `M_ARENA_MAX` дорівнює одиниці саме для того, щоб потокові не дісталася власна, не розігріта купа.

**Перевіряти треба числом, а не наміром.** `VmLck` у [рядку стану процесу](book:unix-linux/proc-filesystem) показує прибиті байти всього процесу, а поле `Locked` у розкладці відображень — по кожній ділянці окремо; ділянка з `MLOCK_ONFAULT` входить у `VmLck` **цілою** довжиною, хоч у пам'яті з неї лежить лише те, чого торкнулися. Тобто `VmLck` каже, скільки з'їдено з межі, а не скільки зайнято пам'яті — друге видно поруч, у `VmRSS`, і саме розбіжність цих двох чисел підтверджує, що ощадний різновид справді працює.

Прибита й розігріта пам'ять знімає з найгіршого випадку одну причину — найдорожчу, але не єдину. Поруч із нею стоять [політика планування](book:unix-linux/priority-nice-realtime), переривання й черга до пристроїв, і кожну міряють тим самим способом: під тиском, за хвостом, двома прогонами.
