# 📋 Інтерфейси керування sysfs, sysctl та метрики /proc/vmstat для memory tiers

Цей довідник містить вичерпний опис інтерфейсів віртуальної файлової системи `sysfs`, параметрів ядра `sysctl`, лічильників підсистеми `/proc/vmstat`, точок трасування (tracepoints), інтерфейсів `debugfs` та контролерів cgroups v2, за допомогою яких здійснюється низькорівнева конфігурація, керування та моніторинг ярусів пам'яті (Memory Tiering), асинхронного витіснення (Demotion) і підвищення (Promotion) сторінок у сучасному ядрі Linux.

## Внутрішні структури ядра та віртуальна файлова система sysfs

Підсистема ярусів пам'яті (`mm/memory-tiers.c`) абстрагує фізичну неоднорідність модулів пам'яті через набір внутрішніх структур:
* `struct memory_tier`: описує конкретний ярус продуктивності, прив'язаний до діапазону абстрактних дистанцій (adist).
* `struct memory_dev_type`: представляє клас пристрою пам'яті (наприклад, стандартна DRAM або CXL-розширювач) із зареєстрованим калькулятором дистанції.
* `struct demote_nodes`: масив бітових масок `nodemask_t`, що визначає пріоритетні цілі витіснення для кожного вузла системи.

Усі зареєстровані яруси експортуються у каталог `/sys/devices/system/node/memory_tiers/`. Кожен окремий ярус отримує власний каталог `memory_tierN`, де індекс `N` призначається відповідно до порядку продуктивності (менший індекс відповідає меншій абстрактній дистанції та вищій швидкодії).

| Файл у sysfs | Права | Опис і семантика |
| :--- | :--- | :--- |
| `/sys/devices/system/node/memory_tiers/max_tier` | `r--r--r--` | Містить максимальний числовий індекс ярусу, що існує в системі на поточний момент. |
| `/sys/devices/system/node/memory_tiers/default_tier` | `r--r--r--` | Символічне посилання або індекс базового ярусу за замовчуванням (Top-tier), до якого належить звичайна оперативна пам'ять DRAM. |
| `/sys/devices/system/node/memory_tiers/memory_tierN/nodes` | `r--r--r--` | Бітова маска у шістнадцятковому форматі, яка визначає всі вузли NUMA, включені до складу цього ярусу. |
| `/sys/devices/system/node/memory_tiers/memory_tierN/nodelist` | `r--r--r--` | Людиночитаний текстовий список діапазонів вузлів NUMA (наприклад, `0-1` або `2,3`), закріплених за цим ярусом. |

Крім глобальної ієрархії, у каталозі кожного окремого вузла NUMA `/sys/devices/system/node/nodeX/` доступні спеціалізовані атрибути:

| Файл у каталозі nodeX | Права | Опис |
| :--- | :--- | :--- |
| `memory_tier` | `r--r--r--` | Символічне посилання на каталог відповідного ярусу у `memory_tiers/memory_tierN`. |
| `distance` | `r--r--r--` | Рядок класичних матричних відстаней ACPI SLIT від цього вузла до всіх інших вузлів системи. |
| `access0/initiators` | `r--r--r--` | Бітова маска процесорних вузлів, які мають прямий апаратний доступ до пам'яті цього вузла згідно з ACPI HMAT. |
| `access0/targets` | `r--r--r--` | Список вузлів пам'яті, доступних для ініціаторів цього вузла. |

## Глобальні параметри ядра sysctl та конфігурація

Керування автоматичним витісненням у пам'ять (Demotion) та автоматичною міграцією гарячих сторінок (Promotion) регулюється через псевдофайли у `/proc/sys/kernel/` та `/sys/kernel/mm/`.

### 1. Перемикач витіснення у пам'ять: /sys/kernel/mm/numa/demotion_enabled

Цей файл контролює глобальну поведінку демона `kswapd` та алгоритму Direct Reclaim під час виникнення дефіциту вільної пам'яті на швидких вузлах.

* **`1` (Enabled):** При падінні вільної пам'яті нижче порогу `WMARK_LOW` на вузлі Top-tier, холодні сторінки зі списків Inactive LRU мігрують у найближчий вузол Slow-tier (CXL/PMEM). Скидання на диск або у swap-розділ не відбувається, доки у Slow-tier є вільні сторінки.
* **`0` (Disabled):** Асинхронний спуск вимкнено. Витіснення з будь-якого вузла здійснюється за класичною схемою: скидання файлових кешів або вивантаження анонімної пам'яті у swap-простір на диску.

### 2. Режими роботи AutoNUMA: /proc/sys/kernel/numa_balancing

Параметр `kernel.numa_balancing` є бітовою маскою, яка визначає, які саме механізми перехоплення звернень та балансування активні в ядрі:

```
Значення numa_balancing = (1 << 0) | (1 << 1) | (1 << 2)
```

| Біт | Десяткове | Константа ядра | Функціональне призначення |
| :--- | :--- | :--- | :--- |
| `0` | `1` | `NUMA_BALANCING_NORMAL` | Базове балансування NUMA між симетричними процесорними сокетами (прив'язка пам'яті до локального CPU). |
| `1` | `2` | `NUMA_BALANCING_MEMORY_TIERING` | Спеціалізований режим підвищення (Promotion) для ярусів пам'яті. Дозволяє міграцію гарячих сторінок із безпроцесорних вузлів CXL у Top-tier DRAM при виникненні NUMA hint faults. |
| `2` | `4` | `NUMA_BALANCING_HOT_PAGE` | Адаптивна фільтрація гарячих сторінок (Tiered Memory Metrics). Вимагає підтвердження частоти звернень перед плануванням міграції, запобігаючи паразитному коливанню (thrashing). |

Типові робочі конфігурації:
* `sysctl -w kernel.numa_balancing=2` — увімкнено виключно промоцію для багаторівневої пам'яті (корисно для серверів із CXL, де між сокетами балансування виконується вручну через `numactl`).
* `sysctl -w kernel.numa_balancing=3` — стандартна комбінація: класичне сокетне балансування (біт 0) + багаторівневе підвищення сторінок (біт 1).
* `sysctl -w kernel.numa_balancing=7` — повний набір: класична NUMA + memory tiering + фільтр гарячості сторінок.

### 3. Регулювання темпу міграції та періодів сканування

Міграція сторінок між CXL та локальною DRAM створює додатковий трафік на шинах PCIe та контролерах пам'яті. Для запобігання деградації продуктивності користувацьких потоків використовуються такі регулятори:

* `/proc/sys/kernel/numa_balancing_rate_limit_mbps` (за замовчуванням `1024`–`2048` МБ/с) — максимальна сумарна пропускна здатність промоції сторінок на кожен вузол. Реалізовано через алгоритм маркерного кошика (Token Bucket): якщо темп міграції перевищує цей ліміт, обробник `do_numa_page()` тимчасово пропускає міграцію і просто відновлює права доступу до сторінки на її поточному місці.
* `/proc/sys/kernel/numa_balancing_scan_delay_ms` — час затримки (у мілісекундах) після створення процесу перед початком першого циклу сканування сторінок (за замовчуванням `1000` мс).
* `/proc/sys/kernel/numa_balancing_scan_period_min_ms` та `/proc/sys/kernel/numa_balancing_scan_period_max_ms` — нижня та верхня межі адаптивного інтервалу сканування адресного простору процесу (за замовчуванням від `1000` до `60000` мс). Якщо потік демонструє високу локальність доступу, ядро зменшує період сканування до мінімуму; якщо звернення рівномірні або рідкісні — період зростає до максимуму, заощаджуючи процесорний час.
* `/proc/sys/kernel/numa_balancing_scan_size_mb` — обсяг пам'яті (у мегабайтах), що сканується фоновим потоком `task_numa_work()` за один прохід (за замовчуванням `256` МБ).

## Метрики продуктивності та лічильники /proc/vmstat

Підсистема ярусів пам'яті експортує детальну статистику про переміщення сторінок у псевдофайл `/proc/vmstat`.

| Назва лічильника у `/proc/vmstat` | Одиниця | Опис події |
| :--- | :--- | :--- |
| `pgdemote_kswapd` | сторінки | Кількість сторінок, успішно переміщених із Top-tier у Slow-tier фоновим потоком `kswapd`. |
| `pgdemote_direct` | сторінки | Кількість сторінок, здемочених потоками додатків під час синхронного витіснення (Direct Reclaim). |
| `pgdemote_khugepaged` | сторінки | Кількість прозорих великих сторінок (THP), здемочених фоновим демоном оптимізації пам'яті. |
| `pgdemote_file` | сторінки | Кількість сторінок файлового кешу, спущених у нижній ярус пам'яті. |
| `pgdemote_anon` | сторінки | Кількість анонімних сторінок (купа, стек), переміщених у нижній ярус. |
| `pgpromote_success` | сторінки | Кількість сторінок, успішно піднятих із повільного ярусу CXL у швидку пам'ять DRAM. |
| `pgpromote_candidate` | сторінки | Кількість сторінок у повільному ярусі, які згенерували NUMA hint fault і були визнані кандидатами на підвищення. |
| `numa_hint_faults` | події | Загальна кількість псевдозбоїв сторінок (Minor Faults), спричинених установкою біта `_PAGE_NUMA`. |
| `numa_hint_faults_local` | події | Кількість NUMA hint faults, що сталися на тому самому вузлі, де вже розміщена сторінка. |
| `numa_pages_migrated` | сторінки | Сумарна кількість сторінок, мігрованих підсистемою AutoNUMA (включаючи сокетні переміщення та промоцію). |

## Точки трасування ядра (Tracepoints)

Для низькорівневого аналізу затримок, контеншну блокувань та черг міграції через `perf`, `ftrace` або eBPF використовуються спеціалізовані точки трасування ядра:

1. **`vmscan:mm_vmscan_kswapd_wake`**
   * *Подія:* Пробудження фонового потоку `kswapd` через падіння рівня вільної пам'яті нижче `WMARK_LOW`.
   * *Формат виводу:* `nid=%d order=%d` (де `nid` — ідентифікатор вузла DRAM, `order` — порядок виділення).

2. **`migrate:mm_migrate_pages`**
   * *Подія:* Виконання пакетного виклику `migrate_pages()`.
   * *Формат виводу:* `mode=%s nr_succeeded=%lu nr_failed=%lu nr_thp_succeeded=%lu nr_thp_failed=%lu` (де `mode` відображає причину: `MR_DEMOTION`, `MR_NUMA_MISPLACED`, `MR_COMPACTION`).

3. **`numa:mm_numa_migrate_ratelimit`**
   * *Подія:* Спрацювання обмежувача швидкості промоції (rate limit).
   * *Формат виводу:* `src_nid=%d dst_nid=%d nr_pages=%lu` (показує кількість сторінок, промоція яких була скасована через вичерпання ліміту пропускної здатності шини).

4. **`migrate:mm_migrate_pages_start` та `migrate:mm_migrate_pages_end`**
   * *Подія:* Початок та завершення циклу копіювання сторінок. Дозволяє виміряти чистий час блокування процесу та латентність RAM-to-RAM передачі даних між сокетом і CXL-картою.

## Інтерфейси налагодження debugfs

Для глибокого аудиту стану планувальника та внутрішніх лічильників міграції ядро надає додаткові інтерфейси у псевдофайловій системі `debugfs` (монтується за адресою `/sys/kernel/debug/`):

* `/sys/kernel/debug/sched/numa_balancing/` — містить розширену статистику щодо кількості сканованих віртуальних областей (VMA), співвідношення локальних та віддалених звернень для окремих процесів та розподілу затримок обробки винятків `do_numa_page()`.
* `/sys/kernel/debug/cxl/` — дозволяє переглядати сирий стан регістрів конфігурації CXL-комутаторів, декодерів адресного простору HDM (Host-managed Device Memory) та журналів апаратних помилок PCIe AER (Advanced Error Reporting).

## Контроль у cgroups v2: memory.demote_enabled

У контейнерних середовищах на базі контролера пам'яті cgroups v2 (`CONFIG_CGROUP_MEMORY`) поведінку демоції можна ізолювати для окремих ієрархій задач за допомогою спеціалізованого файлу:

```
/sys/fs/cgroup/<group_name>/memory.demote_enabled
```

* Значення `1` дозволяє задачам контейнера використовувати вузли CXL для асинхронного спуску сторінок при досягненні локального ліміту `memory.high` або глобального тиску на сокет.
* Значення `0` повністю вимикає спуск сторінок у повільний ярус для обраного контейнера. Це критично для низьколатентних сервісів реального часу (Real-Time DB), де будь-яка затримка доступу понад 100 нс є неприпустимою: такий контейнер у разі вичерпання DRAM одразу піде у класичний swap або отримає OOM, але його гарячі дані ніколи не опиняться на повільній шині CXL.
