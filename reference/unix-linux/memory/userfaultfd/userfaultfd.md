# userfaultfd: сторінкові збої в руках програми

<preknowlist>
- [Сторінковий збій](book:unix-linux/page-fault) — коли чинного запису в таблиці сторінок немає, апаратура спиняє інструкцію на півдорозі й віддає керування ядру.
- [Віртуальний адресний простір процесу](book:unix-linux/virtual-address-space) — простір складається з ділянок (VMA), у кожної свій діапазон адрес і походження вмісту.
- [Файловий дескриптор](book:unix-linux/file-descriptor) — маленьке число, за яким ядро знаходить об'єкт; його можна читати й чекати на ньому подій.
</preknowlist>

Коли потік виконує інструкцію читання або запису за віртуальною адресою, для якої немає фізичного кадру в таблиці сторінок, апаратура генерує сторінковий збій. Зазвичай це прозора робота ядра: воно виділяє нульову сторінку анонімної пам'яті або зчитує необхідний блок із диска. Проте існує клас системних задач, у яких джерело даних відоме лише самій програмі, а ядро про нього не здогадується.

Типовий приклад — жива міграція віртуальної машини методом «після копіювання» ([post-copy](book:programming/live-migration)). Гостя спиняють на старому сервері, миттєво переносять стан його реєстрів на новий сервер із порожньою пам'яттю й одразу запускають. Щойно гість торкається сторінки, якої на новому сервері ще немає, її слід негайно витребувати через мережу зі старого сервера. Ядро Linux не знає мережевого протоколу гіпервізора, а програма-переносник не має прямого доступу до редагування таблиць сторінок.

## Чому сигнал і mprotect не підходять

На перший погляд, це можна скласти зі стандартних механізмів: закрити ділянку правами `PROT_NONE` і перехоплювати сигнал `SIGSEGV`. Однак цей підхід розбивається об три фундаментальні перешкоди:

1. **Контекст сигналу.** Обробник сигналу виконується всередині перерваного потоку, якому доступні лише [асинхронно-безпечні функції](book:unix-linux/async-signal-safety). Викликати мережеві функції, брати м'ютекси або виділяти пам'ять через `malloc` у ньому заборонено: якщо потік спіткнувся всередині розподільника пам'яті, повторний виклик `malloc` в обробнику призведе до довічного самоблокування.
2. **Відсутність неподільности.** Якщо відкрити права через `mprotect`, а потім записувати дані у просторі користувача, виникає небезпечна часова щілина. У цю мить інші потоки процесу вже бачать відкриту сторінку, але замість даних там лежать нулі — вони прочитають хибний вміст без жодного збою.
3. **Чужий процес.** Обслужити збої чужого процесу (наприклад, під час відновлення контейнерів інструментом [CRIU](book:unix-linux/userfaultfd/hist-userfaultfd.md)) через сигнал взагалі неможливо, оскільки сигнал доставляється лише потерпілому.

## Збій як подія у дескрипторі

Механізм `userfaultfd` усуває ці обмеження, перетворюючи сторінковий збій на подію у [файловому дескрипторі](book:unix-linux/everything-is-a-file). Це дозволяє винести обслуговування збою в окремий потік-наглядач (*manager*), що працює у звичайному контексті.

Повний цикл обслуговування збою складається з чотирьох кроків:

1. **Реєстрація:** Програма створює об'єкт викликом `userfaultfd()` і через `ioctl(UFFDIO_REGISTER)` реєструє діапазон віртуальних адрес.
2. **Перехоплення:** Коли потік-винуватець торкається відсутньої сторінки в цьому діапазоні, ядро призупиняє його виконання, формує повідомлення `struct uffd_msg` із точною адресою та типом доступу й кладе його в чергу дескриптора.
3. **Отримання даних:** Потік-наглядач чекає на дескрипторі через [`poll()`](book:unix-linux/select-poll-epoll), зчитує повідомлення звичайним `read()` і приносить вміст сторінки із джерела (мережі, образу на диску чи генератора).
4. **Неподільне заповнення:** Наглядач передає ядру буфер із даними через `ioctl(UFFDIO_COPY)`. Ядро виділяє новий фізичний кадр, копіює туди вміст **до** оновлення таблиці сторінок, атомарно вписує новий запис і будить потерпілий потік. Для винуватця затримка виглядає як звичайне очікування дискового введення-виведення.

:::tabs
```c
/* Створення дескриптора та реєстрація ділянки */
int uffd = syscall(SYS_userfaultfd, O_CLOEXEC | O_NONBLOCK | UFFD_USER_MODE_ONLY);
struct uffdio_api api = { .api = UFFD_API, .features = 0 };
ioctl(uffd, UFFDIO_API, &api);

struct uffdio_register reg = {
    .range = { .start = (unsigned long)area, .len = length },
    .mode  = UFFDIO_REGISTER_MODE_MISSING,
};
ioctl(uffd, UFFDIO_REGISTER, &reg);

/* Наглядач: читання збою та неподільне заповнення */
struct uffd_msg msg;
read(uffd, &msg, sizeof(msg));
unsigned long page = msg.arg.pagefault.address & ~(pagesize - 1);
fetch_page(page, buf);

struct uffdio_copy copy = {
    .dst = page, .src = (unsigned long)buf, .len = pagesize, .mode = 0,
};
ioctl(uffd, UFFDIO_COPY, &copy);
```
```cpp
// Створення дескриптора та реєстрація ділянки
int uffd = ::syscall(SYS_userfaultfd, O_CLOEXEC | O_NONBLOCK | UFFD_USER_MODE_ONLY);
::uffdio_api api{.api = UFFD_API, .features = 0};
::ioctl(uffd, UFFDIO_API, &api);

::uffdio_register reg{
    .range = {.start = reinterpret_cast<std::uintptr_t>(area), .len = length},
    .mode  = UFFDIO_REGISTER_MODE_MISSING,
};
::ioctl(uffd, UFFDIO_REGISTER, &reg);

// Наглядач: читання збою та неподільне заповнення
::uffd_msg msg{};
::read(uffd, &msg, sizeof(msg));
auto page = msg.arg.pagefault.address & ~(pagesize - 1);
fetch_page(page, buf);

::uffdio_copy copy{
    .dst = page, .src = reinterpret_cast<std::uintptr_t>(buf.data()), .len = pagesize, .mode = 0,
};
::ioctl(uffd, UFFDIO_COPY, &copy);
```
:::

Важливе застереження: буфер, із якого наглядач копіює дані, мусить лежати **поза** зареєстрованою ділянкою. Якби наглядач спробував прочитати власне джерело із тієї ж перехоплюваної ділянки, він сам викликав би сторінковий збій і назавжди заснув у черзі, чекаючи на самого себе.

## Три режими роботи

Механізм підтримує три режими реєстрації пам'яті:

1. **`MISSING` (Відсутня сторінка):** Збій виникає при першому зверненні до невиділеної сторінки. Режим працює для анонімної пам'яті, `tmpfs`, `memfd_create` та [великих сторінок (hugetlbfs)](book:unix-linux/huge-pages). Для звичайних відображень файлів цей режим не застосовується, бо ядро саме знає, звідки брати їхній вміст.
2. **`WP` (Захист від запису):** Програма помічає сторінки як захищені від запису (`UFFDIO_WRITEPROTECT`). Спроба запису викликає сповіщення наглядачеві. Це дозволяє створювати точні поступові контрольні точки (інкрементні знімки) та контролювати бар'єри запису у збирачах сміття.
3. **`MINOR` (Малий збій):** Дані вже є у кеші сторінок (наприклад, завантажені в інше відображення того ж файлу чи `memfd`), але запису в таблиці сторінок поточного процесу немає. Наглядач публікує відображення викликом `UFFDIO_CONTINUE` без повторного копіювання байтів у пам'яті.

Крім збоїв пам'яті, дескриптор може транслювати події зміни самого адресного простору — `UFFD_EVENT_FORK`, `UFFD_EVENT_REMAP`, `UFFD_EVENT_UNMAP`. Передавши дескриптор `userfaultfd` через сокет домену Unix іншому процесу, зовні можна повністю супроводжувати динамічний адресний простір піднаглядної програми.

## Накладні витрати та пакетування

Кожен збій через `userfaultfd` супроводжується двома перемиканнями контексту планувальника: винуватець засинає, наглядач прокидається, а після виклику `UFFDIO_COPY` винуватець прокидається знову. На сучасних серверах це коло коштує близько 3–10 мікросекунд.

Якщо переносити віртуальну машину з 8 ГіБ пам'яті поштучно (сторінками по 4 КіБ), самі лише перемикання контексту з'їдять понад 10 секунд чистих накладних витрат. Тому реальні системи застосовують дві оптимізації:

- **Пакетне заповнення:** За один виклик `UFFDIO_COPY` передають одразу кілька сторінок (наприклад, 64 КіБ або 1 МіБ), адже фіксована ціна перемикання контексту сплачується один раз на всю порцію.
- **Попереднє штовхання (*pre-paging*):** Фоновий потік випереджально перекачує сторінки через мережу й наповнює пам'ять до того, як гість до них торкнеться. Сторінкові збої залишаються лише для непередбачуваних промахів.

## Безпека та обмеження

Можливість зупиняти виконання потоку в ядрі на довільний час зробила `userfaultfd` небезпечною зброєю для розтягування часових вікон у нападах типу [TOCTOU (time-of-check to time-of-use)](book:programming/toctou-race). Зловмисник міг передати ядру буфер із запізнілим заповненням і заблокувати ядро посеред перевірки аргументів системного виклику.

Щоб захистити систему, ядро Linux ввело два рівні обмежень:

- Прапорець `UFFD_USER_MODE_ONLY` (із ядра 5.11): дозволяє непривілейованим процесам перехоплювати лише ті збої, що сталися під час виконання коду у просторі користувача. Збої, викликані ядром при копіюванні даних з аргументів системних викликів, цим прапорцем відсікаються.
- Файл пристрою `/dev/userfaultfd` (із ядра 6.1): дозволяє адміністратору гнучко роздавати права на повний механізм (включаючи збої ядра) конкретним групам користувачів або службам через звичайні права файлової системи.
