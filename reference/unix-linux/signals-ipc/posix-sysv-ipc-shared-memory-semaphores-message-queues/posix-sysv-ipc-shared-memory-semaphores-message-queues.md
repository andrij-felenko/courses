# POSIX та System V IPC: Спільна пам'ять, семафори й черги повідомлень

В операційних системах Unix історично склалися два паралельні стандарти для міжпроцесної взаємодії (IPC): **System V** (старіший) та **POSIX** (новіший). Обидва стандарти розв'язують ті самі три задачі: спільну пам'ять, синхронізацію через семафори та обмін даними через черги повідомлень. Хоча їхнє призначення ідентичне, архітектура та підходи суттєво різняться.

Головна відмінність полягає у філософії. System V створювався до того, як принцип «усе є файлом» закріпився повсюдно, тому він використовує власні числові ідентифікатори та простір імен, ізольований від звичайної файлової системи. POSIX IPC, навпаки, тісно інтегрований із файловою системою, використовує звичні файлові дескриптори та імена файлів, що робить його зручнішим і гнучкішим у сучасному програмуванні.

## Спільна пам'ять (Shared Memory)

Спільна пам'ять — це найшвидший спосіб IPC, оскільки процеси безпосередньо читають і пишуть у ті самі ділянки оперативної пам'яті без копіювання даних через ядро.

У **System V** для створення ділянки пам'яті використовується ключ (зазвичай генерується через `ftok`), після чого викликається `shmget()`, а щоб приєднати цю пам'ять до адресного простору процесу — `shmat()`.

У **POSIX** спільна пам'ять виглядає як звичайний файл. Ви викликаєте `shm_open()`, який повертає файловий дескриптор. Далі ви задаєте розмір через `ftruncate()`, а відображаєте в пам'ять стандартним викликом `mmap()`.

**POSIX**
```c
// Створення та відображення POSIX спільної пам'яті
int fd = shm_open("/my_shm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);
void *ptr = mmap(0, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
```

**System V**
```c
// Створення та приєднання System V спільної пам'яті
key_t key = ftok("somefile", 65);
int shmid = shmget(key, 4096, 0666 | IPC_CREAT);
void *ptr = shmat(shmid, NULL, 0);
```

## Семафори (Semaphores)

Семафори потрібні для синхронізації — вони гарантують, що два процеси не почнуть одночасно змінювати спільну пам'ять чи інший ресурс.

**System V** семафори (`semget`, `semop`) сумнозвісні своєю складністю. Вони оперують одразу масивами семафорів, а не поодинокими лічильниками, і вимагають складних структур даних для конфігурації. 

**POSIX** семафори бувають двох видів: іменовані (`sem_open()`) та безіменні (`sem_init()`). Вони набагато простіші: це просто лічильник, який можна зменшувати (`sem_wait()`) та збільшувати (`sem_post()`).

**POSIX**
```c
// Іменований POSIX семафор
sem_t *sem = sem_open("/my_sem", O_CREAT, 0666, 1);
sem_wait(sem); // Захопити ресурс
// ... критична секція ...
sem_post(sem); // Звільнити ресурс
```

**System V**
```c
// System V семафор (спрощено)
int semid = semget(key, 1, 0666 | IPC_CREAT);
struct sembuf sb = {0, -1, 0}; // Зменшити на 1
semop(semid, &sb, 1); // Захопити ресурс
// ... критична секція ...
sb.sem_op = 1; // Збільшити на 1
semop(semid, &sb, 1); // Звільнити ресурс
```

## Черги повідомлень (Message Queues)

Черги дозволяють передавати структуровані блоки даних між процесами в асинхронному режимі. На відміну від байтових потоків (як у пайпах), черги зберігають межі повідомлень.

У **System V** черги створюються через `msgget()`, а повідомлення надсилаються і приймаються викликами `msgsnd()` та `msgrcv()`. Вони підтримують типи повідомлень, що дозволяє отримувачу вибірково читати дані.

**POSIX** черги (`mq_open()`, `mq_send()`, `mq_receive()`) інтегровані з підсистемою сигналів і дозволяють налаштувати асинхронне сповіщення про надходження нового повідомлення, а також підтримують пріоритети для кожного окремого повідомлення.

## Сучасна альтернатива: `memfd_create`

У сучасних системах Linux з'явився ще один механізм — анонімна пам'ять у пам'яті через `memfd_create()`. Цей виклик створює файловий дескриптор, який поводиться як звичайний файл, але існує лише в оперативній пам'яті і не має імені у файловій системі.

Цей підхід об'єднує переваги POSIX (використання звичайних дескрипторів) та безпеку (без імені у файловій системі його не можуть відкрити сторонні процеси, крім тих, кому дескриптор передано явно). `memfd_create` часто використовується разом із `mmap` для створення безпечних ділянок спільної пам'яті для комунікації між процесами.

**Що обрати?** Для нових програм майже завжди рекомендується використовувати POSIX IPC через його простоту, безпеку та кращу інтеграцію з сучасною архітектурою Unix. System V IPC залишається здебільшого для сумісності зі старим кодовим забезпеченням.
