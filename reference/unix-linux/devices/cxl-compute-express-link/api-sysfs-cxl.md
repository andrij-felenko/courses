# 📋 Інтерфейс системної підсистеми /sys/bus/cxl та апаратні регістри HDM

Підсистема CXL в операційній системі Linux надає структуровану ієрархію у файловій системі sysfs для інспектування топології, простеження апаратних регістрів та управління регіонами пам'яті CXL.

## 1. Докладна ієрархія пристроїв у sysfs (`/sys/bus/cxl/devices/`)

Підсистема ядра експортує всі виявлені пристрої CXL через шину `/sys/bus/cxl/`. Усі об'єкти ієрархії мають уніфікований іменований префікс та зв'язані символьними лінками відповідно до фізичної й логічної топології.

Головним кореневим елементом є вузол `root0`, який створюється на основі аналізу системних ACPI-таблиць CEDT (CXL Early Discovery Table). Від цього вузла відгалужуються кореневі декодери (`decoder0.0`), які репрезентують вікна адресації CFMWS (CXL Fixed Memory Window Structures), виділені платформою BIOS під час ініціалізації.

Нижче в ієрархії розміщуються порти комутаторів (`port1`, `port2`), кожен з яких містить власні HDM-декодери комутації. На найнижчому рівні знаходяться кінцеві пристрої `endpointX`, які описують фізичні накопичувачі та розширювачі пам'яті `memX`.

Для управління сформованими пулами пам'яті ядро створює абстракцію CXL Region (`region0`, `region1`). Кожен регіон об'єднує декілька фізичних пристроїв у єдиний контигуальний простір адресації із заданою гранулярністю та кількістю каналів чередування.

### Ключові атрибути та атрибутивний довідник sysfs

- Атрибут `memX/pmem/size` надає розмір енергонезалежної області пам'яті пристрою в байтах. Якщо пристрій підтримує накопичувач NVDIMM чи Flash-медіа, цей атрибут відображає доступний обсяг для DAX-режиму.
- Атрибут `memX/ram/size` повертає розмір енергозалежної оперативної пам'яті (Volatile DRAM) у байтах, яка може бути змонтована у системний пул оперативної пам'яті.
- Атрибут `memX/payload_status` відображає поточний стан виконання команд поштового ящика MBOX (Mailbox Controller), дозволяючи виявляти збої при зверненні до внутрішньої мікропрограми контролера.
- Атрибут `memX/firmware_version` повертає текстовий ідентифікатор та ревізію прошивки апаратного контролера пристрою.
- Атрибут `decoderX.Y/start` визначає початкову системну фізичну адресу (System Physical Address, SPA) у 64-бітному шістнадцятковому форматі, з якої починається декодування даного вікна.
- Атрибут `decoderX.Y/size` містить обсяг адресної області в байтах, призначений даному декодеру.
- Атрибут `decoderX.Y/commit` при записі символу `1` фіксує налаштування декодера в апаратних регістрах HDM пристрою та комутатора, переводячи декодер у робочий стан.
- Атрибут `regionX/mode` задає цільовий режим використання регіону. Значення `"ram"` перетворює регіон у системну оперативну пам'ять (kmem), а значення `"pmem"` створює пристрій прямого доступу devdax.
- Атрибут `regionX/state` керує активацією регіону. Запис значення `"enabled"` ініціалізує створення нового вузла NUMA у ядрі, а значення `"disabled"` відключає регіон і звільняє адреси.

## 2. Специфікація апаратних регістрів CXL HDM (Designated Vendor-Specific Capability)

Кожен пристрій CXL експортує свої інтерфейсні регістри через розширений конфігураційний простір PCIe (DVSEC — Designated Vendor-Specific Extended Capability ID `0x0030`) та CXL Component Registers (BAR0).

Регістри HDM Decoder (Host-managed Device Memory) розміщуються у базовому конфігураційному просторі BAR0 пристрою:
- Регістр `CXL_HDM_DECODER_CAPABILITY` (зміщення `0x00`) відображає апаратну кількість доступних декодерів на пристрої (від 1 до 16).
- Регістри `CXL_HDM_DECODER0_BASE_LOW` (зміщення `0x10`) та `CXL_HDM_DECODER0_BASE_HIGH` (зміщення `0x14`) утримують відповідно молодші 32 біти та старші 32 біти початкової системної адреси SPA.
- Регістри `CXL_HDM_DECODER0_SIZE_LOW` (зміщення `0x18`) та `CXL_HDM_DECODER0_SIZE_HIGH` (зміщення `0x1C`) задають розмір декодованого вікна.
- Регістр `CXL_HDM_DECODER0_CTRL` (зміщення `0x20`) містить прапорці управління, режимів чередування та фіксації.
- Регістри `CXL_HDM_DECODER0_TARGET_LIST_LOW` (зміщення `0x24`) та `CXL_HDM_DECODER0_TARGET_LIST_HIGH` (зміщення `0x28`) визначають ідентифікатори цільових портів комутатора для перенаправлення транзакцій.

### Докладний аналіз регістра управління декодером (`CXL_HDM_DECODER0_CTRL`)

Біт 0 регістра відповідає за біт `Commit`. Встановлення цього біта в `1` наказує апаратурі зафіксувати налаштування адресації. Запис `0` скидає конфігурацію і переводить декодер у незадіяний стан.

Біт 1 регістра є прапорцем `Committed` і доступний лише для читання. Пристрій встановлює цей біт в `1` після того, як усередині кремнієвого кристала повністю завершиться конфігурування внутрішніх таблиць маршрутизації адрес.

Біти 3:1 визначають кількість каналів чередування (`Interleave Ways`). Значення `000b` відповідає 1-way (один пристрій без чередування), `001b` відповідає 2-way інтерлівінгу між двома пристроями, `010b` задає 4-way, `011b` — 8-way, а `100b` — 16-way чередування.

Біти 7:4 визначають гранулярність чередування (`Interleave Granularity`). Значення `0000b` встановлює розмір кроку 256 байтів, `0001b` — 512 байтів, `0010b` — 1 кілобайт, `0011b` — 2 кілобайти, `0100b` — 4 кілобайти, `0101b` — 8 кілобайтів, а `0110b` — 16 кілобайтів.

Біт 9 надає механізм апаратного блокування `Lock`. Після того, як драйвер ядра встановлює цей біт в `1`, апаратні регістри декодера блокуються від будь-яких подальших змін до моменту повного холодного перезавантаження сервера.

## 3. Таблиця команд CXL Mailbox Protocol (MBOX)

Управління внутрішнім станом контролера пам'яті Type 3, таке як зчитування логів помилок, перевірка стану осередків або оновлення мікропрограми, здійснюється через Mailbox-регістри пристрою. Драйвер ядра надсилає командні пакети з 16-бітними кодами операцій (Opcode):

- Команда `Identify Memory Device` (Opcode `0x0100`) є обов'язковою для читання. Вона повертає загальний фізичний обсяг RAM, розмір кеш-пам'яті контролера, а також підтримувані функції гарячої заміни.
- Команда `Get Event Records` (Opcode `0x0101`) дозволяє зчитати накопичені апаратні журнали подій, які поділяються на інформаційні повідомлення, попередження про зношення та критичні сповіщення про збої.
- Команда `Clear Event Records` (Opcode `0x0102`) виконує очищення зчитаних записів журналів подій для звільнення буфера пам'яті контролера.
- Команда `Get Poison List` (Opcode `0x4000`) повертає масив фізичних адрес пристрою (DPA), які були позначені прапорцем пошкодження через виникнення невідновлюваних ECC-помилок.
- Команда `Inject Poison` (Opcode `0x4100`) використовується для тестування підсистеми надійності ядра. Вона штучно позначає вказану сторінку як пошкоджену.
- Команда `Sanitize Media` (Opcode `0x4400`) здійснює апаратне безпечне стирання всіх даних на носіях пам'яті пристрою перед виведенням серверного обладнання з експлуатації.

## 4. Програмний інтерфейс користувацького простору (cxl-cli & libcxl)

Утиліта `cxl` з пакету `ndctl` спирається на C-інтерфейс бібліотеки `libcxl` для взаємодії з драйверами ядра через символьний пристрій `/dev/cxl/memX`.

Основними функціями бібліотеки є:
- Функція `cxl_new()` виділяє та ініціалізує контекст взаємодії з підсистемою CXL ядра Linux.
- Функція `cxl_memdev_get_first()` повертає вказівник на перший виявлений у системі CXL-пристрій пам'яті.
- Функція `cxl_memdev_get_next()` виконує послідовну ітерацію по списку всіх підключених медіа-пристроїв.
- Функції `cxl_memdev_get_ram_size()` та `cxl_memdev_get_pmem_size()` повертають розміри оперативної та енергонезалежної пам'яті пристрою.
- Функція `cxl_decoder_create_region()` створює новий об'єкт CXL Region на базі обраного декодера.
- Функції `cxl_region_set_interleave_granularity()` та `cxl_region_set_interleave_ways()` конфігурують параметри чередування адрес у створюваному пулі.
- Функція `cxl_region_enable()` надсилає ядру команду активації регіону, що призводить до створення нового вузла NUMA у файловій системі sysfs.
