# 🧮 Математичний розрахунок пропускної здатності медіа-конвеєра

Математичне моделювання медіа-конвеєра є необхідним етапом проектування вбудованих систем обробки зображень. Воно дозволяє визначити критичні фізичні обмеження: тактову частоту генераторів пікселів (Pixel Clock), необхідну смугу пропускання послідовної шини MIPI CSI-2, а також навантаження на системну шину пам'яті (RAM DMA) під час передачі кадрів у підсистемі V4L2/Videobuf2.

## 1. Фізична модель розрахунку частоти пікселів та інтервалів гасіння

Формування відеокадру матрицею камери спирається на розгортку кадру. Повний часовий цикл зчитування одного кадру складається з двох компонентів: активної зони пікселів зображення (`W_active × H_active`) та технологічних інтервалів гасіння — горизонтального (`HBLANK`) і вертикального (`VBLANK`).

Інтервал `HBLANK` задає паузу між закінченням зчитування одного рядка та початком наступного, необхідну для скидання сміттєвого заряду та аналого-цифрового перетворення. Інтервал `VBLANK` виконує аналогічну роль між кадрами і додатково використовується сенсором для переналаштування часу експозиції та коефіцієнтів підсилення (Gain).

Базові співвідношення геометрії розгортки:

```
W_total = W_active + HBLANK    [загальна ширина кадру в пікселях]
H_total = H_active + VBLANK    [загальна висота кадру в рядках]
PCLK = W_total × H_total × FPS [необхідна частота піксельного генератора]
```

Де:
- `PCLK` — тактова частота піксельного генератора (Pixel Clock, Гц);
- `W_active`, `H_active` — роздільна здатність активної зони кадру;
- `HBLANK`, `VBLANK` — інтервали гасіння;
- `FPS` — частота зміни кадрів на секунду (Frames Per Second).

### Покроковий розрахунок PCLK для роздільності 1080p при 60 FPS

Розглянемо сенсор камери, налаштований на передачу відеопотоку Full HD (1920×1080) із частотою 60 кадрів/с.

**Вхідні параметри:**
- `W_active` = 1920 пікселів
- `H_active` = 1080 рядків
- `HBLANK` = 280 пікселів
- `VBLANK` = 45 рядків
- `FPS` = 60 кадрів/с

Обчислення тактової частоти пікселів:

```
W_total
= 1920 + 280                    [сума активної ширини та HBLANK]
= 2200 пікселів                 [загальний розмір рядка у пікселях]

H_total
= 1080 + 45                     [сума активної висоти та VBLANK]
= 1125 рядків                   [загальний розмір кадру у рядках]

PCLK
= 2200 × 1125 × 60              [добуток ширини, висоти та частоти кадрів]
= 2475000 × 60                  [кількість пікселів кадру × FPS]
= 148500000 Гц                  [частота пікселів = 148.5 МГц]
```

**Аналіз результату:** Для забезпечення передачі кадру Full HD із заданими інтервалами гасіння піксельний генератор камери повинен працювати на частоті **148.5 МГц**. Скорочення інтервалів `HBLANK` та `VBLANK` дозволяє знизити вимоги до частоти `PCLK`, але зменшує час, доступний алгоритмам автоматичного фокусування та експозиції для переналаштування сенсора.

## 2. Математична модель пропускної здатності шини MIPI CSI-2

Шина MIPI CSI-2 (заснована на фізичному рівні D-PHY) використовує послідовну передачу даних по кількох диференціальних парах (Lanes) у режимі Double Data Rate (DDR — передача інформаційного біта по кожному фронту та зрізу тактового сигналу).

Загальний бітрейт потоку даних та фізична частота тактової лінії CSI-2 обчислюються за формулами:

```
Bitrate_total = PCLK × bpp                  [загальний бітрейт корисного навантаження]
Bitrate_per_lane = Bitrate_total / N_lanes  [бітрейт на одну диференціальну лінію]
CSI_Clock_Freq = Bitrate_per_lane / 2       [фізична тактова частота шини у режимі DDR]
```

Де:
- `bpp` — глибина кольору пікселя в бітах (Bits Per Pixel: RAW8 = 8, RAW10 = 10, RAW12 = 12, YUV422 = 16);
- `N_lanes` — кількість фізично розведених ліній даних MIPI CSI-2 (1, 2 або 4 лінії);
- `CSI_Clock_Freq` — фізична частота лінійного генератора тактування CSI-2 (Гц).

### Покроковий розрахунок параметрів CSI-2 для формату RAW10

Обчислимо необхідну частоту шини MIPI CSI-2 для вищевказаного потоку 1080p60 при глибині кольору 10 біт на піксель (`MEDIA_BUS_FMT_SBGGR10_1X10`) при використанні 2 ліній даних.

**Вхідні параметри:**
- `PCLK` = 148.5 МГц
- `bpp` = 10 біт/піксель
- `N_lanes` = 2 лінії

Покрокове розгортання обчислень:

```
Bitrate_total
= 148500000 × 10                [добуток PCLK на глибину пікселя]
= 1485000000 біт/с              [сумарна швидкість = 1.485 Гбіт/с]

Bitrate_per_lane
= 1485000000 / 2                [ділення загального бітрейту на 2 лінії]
= 742500000 біт/с               [швидкість на лінію = 742.5 Мбіт/с/lane]

CSI_Clock_Freq
= 742500000 / 2                 [ділення бітрейту лінії на 2 для режиму DDR]
= 371250000 Гц                  [тактова частота шини = 371.25 МГц]
```

**Аналіз результату:** Для трансляції потоку RAW10 без втрат передавач MIPI CSI-2 повинен працювати на тактовій частоті **371.25 МГц**, забезпечуючи швидкість передачі **742.5 Мбіт/с** на кожній із двох ліній. Якщо контролер SoC обмежений частотою 300 МГц на лінію, розробник мусить або збільшити кількість ліній до 4, або зменшити частоту кадрів до 45 FPS, або перейти на 8-бітний формат RAW8.

## 3. Розрахунок кроку пам'яті (Stride), вирівнювання та навантаження DMA

Апаратні контролери DMA (Direct Memory Access) здійснюють запис кадрів із приймача CSI-2 / ISP у системну оперативну пам'ять (DRAM). Для забезпечення максимальної ефективності шини AXI / AHB крок кожного рядка у пам'яті (`bytesperline` або Stride) повинен бути вирівняний за межею кеш-ліній або пакетних транзакцій DMA (зазвичай 64, 128 або 256 байтів).

Математичний оператор вирівнювання вгору `align_up(X, A)` задається виразом:

```
align_up(X, A) = ⌊(X + A - 1) / A⌋ × A [вирівнювання величини X до кратності A]
```

Розрахунок розміру плоскості пам'яті здійснюється через вирівняний крок рядка:

```
bytesperline = align_up((W_active × bpp) / 8, ALIGNMENT) [крок рядка в байтах]
Plane_Size = bytesperline × H_active                     [обсяг плоскості у байтах]
```

### Покроковий розрахунок буферів та смуги DMA для 4K Ultra HD NV12

Розглянемо виділення пам'яті підсистемою Videobuf2 для камери 4K Ultra HD (3840×2160) у напівпланарному колірному форматі `V4L2_PIX_FMT_NV12` (YUV 4:2:0) із вирівнюванням рядка за межею 128 байтів при 60 FPS.

Структура NV12 містить дві плоскості у пам'яті:
1. Площина **Y** (Яскравість): `W_active × H_active` байтів.
2. Площина **UV** (Хроматичність): `W_active × (H_active / 2)` байтів (чергування U та V байтів).

**Вхідні параметри:**
- `W_active` = 3840 пікселів
- `H_active` = 2160 рядків
- `ALIGNMENT` = 128 байтів
- `FPS` = 60 кадрів/с

Покрокове розгортання обчислень:

```
bytesperline_Y
= align_up((3840 × 8) / 8, 128) [переведення пікселів Y у байти та вирівнювання]
= align_up(3840, 128)           [перевірка подільності: 3840 / 128 = 30.0]
= 3840 байтів                   [рядок Y вже вирівняний]

bytesperline_UV
= align_up((3840 × 8) / 8, 128) [переведення упакованих пар UV у байти]
= align_up(3840, 128)           [перевірка подільності]
= 3840 байтів                   [рядок UV вирівняний]

Size_Y
= 3840 × 2160                   [добуток кроку рядка Y на кількість рядків]
= 8294400 байтів                [розмір площини Y = 8.294 МБ]

Size_UV
= 3840 × (2160 / 2)             [добуток кроку рядка UV на половину рядків]
= 3840 × 1080                   [множення на висоту UV]
= 4147200 байтів                [розмір площини UV = 4.147 МБ]

Frame_Size_Total
= 8294400 + 4147200             [сума розмірів площин Y та UV]
= 12441600 байтів               [загальний розмір кадру = 12.44 МБ]

DMA_Bandwidth
= 12441600 × 60                 [множення розміру кадру на частоту FPS]
= 746496000 байтів/с            [необхідна смуга DMA = 746.5 МБ/с]

Ring_Buffer_Pool_4
= 12441600 × 4                  [виділення 4 буферів у Videobuf2]
= 49766400 байтів               [сумарна оперативна пам'ять = 49.77 МБ]
```

**Висновок:** Захоплення одного відеопотоку 4K60 NV12 вимагає від шини контролера DRAM безперервної пропускної здатності **746.5 МБ/с** лише для запису кадру камери. Для забезпечення стабільної кільцевої черги з 4 буферів у зоні неперервної пам'яті (CMA) драйвер ядра повинен зарезервувати **49.77 МБ** фізичної ОЗП.
