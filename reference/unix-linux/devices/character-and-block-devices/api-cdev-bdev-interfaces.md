# 📋 Ядерні структури та інтерфейси cdev і bdev

Підсистеми символьних та блочних пристроїв ядра Linux надають драйверам чітко розмежовані набори точного API та системних структур. Символьні пристрої базуються на прямій прив'язці системних викликів VFS до операцій драйвера `struct file_operations`. Блочні пристрої використовують проміжну абстракцію генерального диска `struct gendisk`, операції обробки низькорівневих команд `struct block_device_operations` та підсистему пакетного введення-виведення `blk-mq` з векторами `struct bio`.

Цей довідник містить детальний опис ядерних типів даних, функцій реєстрації, макросів адресації пристроїв та правил роботи з ними у просторі ядра.

## 1. Ідентифікація пристрою: Тип `dev_t` та макроси маніпуляції

У ядрі Linux кожен символьний або блочний пристрій ідентифікується 32-бітним цілим числом типу `dev_t` (визначеним у файлі `<linux/types.h>`). Внутрішня бітова структура `dev_t` розподілена наступним чином:

- **Major (старший номер, 12 біт):** Ідентифікує конкретний драйвер пристрою. Діапазон значень від 0 до 4095. Major-номер використовується VFS для знаходження відповідної таблиці операцій у глобальних реєстрах ядра.
- **Minor (молодший номер, 20 біт):** Ідентифікує конкретний екземпляр пристрою або окремий розділ диска, який обслуговується цим драйвером. Діапазон значень від 0 до 1 048 575.

Для безпечного розпакування та пакування номерів пристроїв заборонено використовувати прямі бітові зсуви. Замість цього розробники драйверів мусять застосовувати спеціалізовані макроси з `<linux/kdev_t.h>`:

```c
// Витягнути major-номер із dev_t
unsigned int MAJOR(dev_t dev);

// Витягнути minor-номер із dev_t
unsigned int MINOR(dev_t dev);

// Сконструювати dev_t із major та minor чисел
dev_t MKDEV(unsigned int major, unsigned int minor);
```

Значення `dev_t` зберігається у полі `i_rdev` структури `struct inode` для спеціальних файлів у каталозі `/dev`. При реєстрації нового драйвера ядро перевіряє, чи не зайнятий потрібний діапазон номерів: для символьних пристроїв — у реєстрі `chrdevs`, для блочних — у реєстрі major-номерів блочного шару.

## 2. Інтерфейси символьних пристроїв (`cdev`)

Для реєстрації символьного пристрою драйвер створює та ініціалізує екземпляр структури `struct cdev` (`<linux/cdev.h>`). Цей об'єкт пов'язує діапазон номерів `dev_t` із таблицею файлових операцій `file_operations`.

### Внутрішня будова структури `struct cdev`

```c
struct cdev {
    struct kobject kobj;              // Об'єкт підсистеми sysfs та обліку посилань
    struct module *owner;             // Вказівник на модуль ядра (THIS_MODULE)
    const struct file_operations *ops;// Таблиця файлових операцій
    struct list_head list;            // Внутрішній список відкритих інодів
    dev_t dev;                        // Перший номер пристрою (Major + Minor)
    unsigned int count;               // Кількість мінорних номерів у діапазоні
};
```

Семантика полів структури `cdev`:
- `kobj`: Внутрішній об'єкт ядра, який відповідає за облік посилань (reference counting) та інтеграцію символьного пристрою в дерево `sysfs`.
- `owner`: Вказівник на модуль, який володіє цим пристроєм (`THIS_MODULE`). Запобігає вивантаженню модуля з пам'яті ядра під час виконання системних викликів.
- `ops`: Таблиця вказівників на функції, які реалізують системні виклики `open`, `read`, `write`, `ioctl` тощо.
- `dev`: Старший та перший молодший номери пристрою, за якими cdev реєструється у хеш-таблиці `chrdevs[]`.
- `count`: Кількість послідовних мінорних номерів, які обслуговуються цією структурою `cdev`.

### Управління життєвим циклом (Lifecycle API) `cdev`

Процес реєстрації символьного пристрою складається з двох етапів: виділення номерів пристроїв та активація об'єкта `cdev`.

```c
// Динамічне виділення діапазону номерів пристроїв (ядро сама обирає вільний Major)
int alloc_chrdev_region(dev_t *dev, unsigned baseminor, unsigned count, const char *name);

// Статична реєстрація заздалегідь відомого діапазону номерів
int register_chrdev_region(dev_t from, unsigned count, const char *name);

// Звільнення раніше виділеного діапазону номерів пристроїв
void unregister_chrdev_region(dev_t from, unsigned count);

// Ініціалізація структури cdev та зв'язування з file_operations
void cdev_init(struct cdev *cdev, const struct file_operations *fops);

// Виділення пам'яті під cdev на купі ядра (динамічний спосіб)
struct cdev *cdev_alloc(void);

// Додавання cdev до системи (робить пристрій активним для системних викликів VFS)
int cdev_add(struct cdev *p, dev_t dev, unsigned count);

// Видалення cdev із системи (деактивація перед деініціалізацією драйвера)
void cdev_del(struct cdev *p);
```

Функція `alloc_chrdev_region()` повертає `0` у разі успіху або від'ємний код помилки (наприклад, `-EBUSY`, якщо діапазон зайнятий). Виклик `cdev_add()` мусить здійснюватися в останню чергу, оскільки одразу після його виконання пристрій стає видимим для користувачів і може отримувати паралельні виклики `read()` та `write()`.

### Таблиця файлових операцій `struct file_operations` (`<linux/fs.h>`)

Таблиця `file_operations` описує контракт між VFS та символьним драйвером. Усі поля є опціональними вказівниками на функції.

```c
struct file_operations {
    struct module *owner;
    loff_t (*llseek) (struct file *, loff_t, int);
    ssize_t (*read) (struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write) (struct file *, const char __user *, size_t, loff_t *);
    __poll_t (*poll) (struct file *, struct poll_table_struct *);
    long (*unlocked_ioctl) (struct file *, unsigned int, unsigned long);
    int (*mmap) (struct file *, struct vm_area_struct *);
    int (*open) (struct inode *, struct file *);
    int (*release) (struct inode *, struct file *);
    int (*fsync) (struct file *, loff_t, loff_t, int datasync);
};
```

Опис ключових методів `file_operations`:
- `.open`: Викликається при відкритті файла пристрою. Використовується для ініціалізації приватних даних у `file->private_data`.
- `.release`: Викликається при останньому закритті файла пристрою (коли лічильник посилань `struct file` стає рівним 0).
- `.read`: Передає дані з драйвера у буфер простору користувача за допомогою `copy_to_user()`.
- `.write`: Приймає дані з простору користувача за допомогою `copy_from_user()`.
- `.unlocked_ioctl`: Реалізує специфічні керуючі команди пристрою без захоплення глобального замка ядра (Big Kernel Lock).
- `.poll`: Забезпечує підтримку мультиплексування введення-виведення для системних викликів `select()`, `poll()` та `epoll()`.

## 3. Інтерфейси блочних пристроїв (`bdev`)

Драйвер блочного пристрою оперує структурою генерального диска `struct gendisk` та чергами запитів `struct request_queue` (`<linux/blkdev.h>`).

### Структура `struct gendisk`

Опис абстракції диска у ядрі містить метадані пристрою, розміри розділів та вказівник на операції диска.

```c
struct gendisk {
    int major;                        // Старший номер пристрою
    int first_minor;                  // Перший молодший номер
    int minors;                       // Максимальна кількість розділів (наприклад, 16)
    char disk_name[DISK_NAME_LEN];    // Назва диска у /dev (наприклад, "sda")
    
    const struct block_device_operations *fops; // Таблиця операцій диска
    struct request_queue *queue;      // Черга запитів I/O (blk-mq)
    void *private_data;               // Вказівник на приватні дані драйвера
    unsigned long state;              // Бітові прапорці стану диска (GD_NEED_PART_SCAN тощо)
};
```

Детальний опис полів `gendisk`:
- `major` та `first_minor`: Задають діапазон номерів `dev_t` для самого диска та його розділів. Якщо `minors = 16`, то `/dev/sda` має minor 0, `/dev/sda1` має minor 1, і так до `/dev/sda15`.
- `disk_name`: Символьний рядок, який визначає ім'я файлу пристрою у каталозі `/dev` та `/sys/block/`.
- `fops`: Вказівник на обробники низькорівневих операцій диска.
- `queue`: Вказівник на мультичергу запитів `blk-mq`, куди VFS та сторінковий кеш відправляють об'єкти `bio`.

### Операції блочного пристрою `struct block_device_operations`

На відміну від символьних пристроїв, ця структура **не містить** методів `.read` або `.write`. Читання та запис блоків реалізуються асинхронно через обробники черги `blk-mq`.

```c
struct block_device_operations {
    int (*open) (struct block_device *, fmode_t);
    void (*release) (struct gendisk *, fmode_t);
    int (*ioctl) (struct block_device *, fmode_t, unsigned, unsigned long);
    int (*getgeo)(struct block_device *, struct hd_geometry *);
    int (*check_events) (struct gendisk *disk, unsigned int clearing);
    void (*unlock_native_capacity) (struct gendisk *);
    struct module *owner;
};
```

Семантика функцій `block_device_operations`:
- `.open` та `.release`: Обробляють моменти монтування/демонтування файлової системи або прямого відкриття диска.
- `.ioctl`: Обробляє низькорівневі керуючі виклики (наприклад, стирання блоків, запуск самодіагностики SMART або форматування).
- `.getgeo`: Повертає згенеровану геометрію диска (циліндри, головки, сектори) для застарілих утиліт розмітки диска.

### Функції управління lifecycle `gendisk`

```c
// Виділення структури gendisk із вказаною кількістю мінорних номерів.
// До ядра 5.15 — саме так; від 5.15 диск створюють разом із чергою
// виклики blk_alloc_disk() / blk_mq_alloc_disk().
struct gendisk *alloc_gendisk(int minors);

// Додавання диска в систему (робить диск видимим у sysfs та /dev)
int add_disk(struct gendisk *disk);

// Видалення диска із системи (деактивація розділів та черг)
void del_gendisk(struct gendisk *gp);

// Зменшення лічильника посилань на gendisk та звільнення пам'яті
void put_disk(struct gendisk *disk);
```

Виклик `add_disk()` реєструє диск у підсистемі `sysfs` і викликає сканування таблиці розділів (MBR або GPT). З цього моменту ядро автоматично створює вузли розділів (наприклад, `/dev/sda1`).

## 4. Структури пакетного вводу-виводу Block I/O Layer

Підсистема блочного введення-виведення описує запити на читання та запис за допомогою об'єктів `struct bio` та `struct bio_vec` (`<linux/blk_types.h>`).

### Структура `struct bio`

Об'єкт `bio` репрезентує один дискретний запит I/O, що перебуває в обробці. Він об'єднує списки фізичних сторінок RAM та номери цільових секторів диска.

```c
struct bio {
    struct bio          *bi_next;     // Наступний bio у списку черги
    struct block_device *bi_bdev;     // Цільовий блочний пристрій
    blk_status_t         bi_status;   // Статус виконання (BLK_STS_OK = 0, BLK_STS_IOERR тощо)
    unsigned int         bi_opf;      // Прапорці операції (REQ_OP_READ, REQ_OP_WRITE, REQ_RAHEAD)
    
    struct bvec_iter     bi_iter;     // Поточний стан ітерації (bi_sector, bi_size)
    
    bio_end_io_t        *bi_end_io;   // Callback-функція завершення I/O
    void                *bi_private;  // Приватний контекст запитувача
    
    unsigned short       bi_vcnt;     // Кількість елементів у масиві bi_io_vec
    struct bio_vec      *bi_io_vec;   // Вектор сторінок пам'яті (page, len, offset)
};
```

Розбір полів `struct bio`:
- `bi_bdev`: Вказівник на об'єкт блочного пристрою, до якого адресовано запит.
- `bi_status`: Поле статусу завершення. Значення `0` означає успішне виконання передачі даних, ненульове значення (наприклад, `BLK_STS_IOERR`) вказує на помилку передачі або носія.
- `bi_iter.bi_sector`: Початковий сектор диска у 512-байтових одиницях.
- `bi_end_io`: Callback-функція, яка викликається драйвером у контексті обробника переривань після того, як контролер диска завершив DMA-передачу.
- `bi_io_vec`: Масив векторів пам'яті, які описують фізичні сторінки оперативної пам'яті для Scatter-Gather DMA.

### Структура вектора пам'яті `struct bio_vec`

Описує один суцільний фрагмент пам'яті у межах однієї фізичної сторінки:

```c
struct bio_vec {
    struct page *bv_page;             // Вказівник на фізичну сторінку RAM (struct page)
    unsigned int bv_len;              // Довжина буфера в байтах
    unsigned int bv_offset;           // Зсув початку даних від початку сторінки
};
```

Завдяки масиву `bio_vec` ядро реалізує Scatter-Gather I/O: дані з одного неперервного діапазону секторів диска можуть бути зчитані або записані безпосередньо у кілька розрізнених сторінок оперативної пам'яті за одну операцію DMA.

## 5. Топологія та атрибути у підсистемі `sysfs`

Ядро Linux автоматично створює ієрархію файлів і каталогів у віртуальній файловій системі `sysfs` для кожного зареєстрованого символьного та блочного пристрою:

- **Символьні пристрої:** Розміщуються за шляхом `/sys/dev/char/<major>:<minor>/`. Цей каталог є символьним посиланням на реальний вузол шини у деревоподібній структурі пристроїв (наприклад, `/sys/devices/pci0000:00/.../tty/ttyS0`).
- **Блочні пристрої:** Розміщуються за шляхом `/sys/dev/block/<major>:<minor>/`. Символьне посилання веде у каталог `/sys/block/<name>/`.

Каталог блочного пристрою у `sysfs` надає важливі атрибути для аналізу та налаштування роботи черги запитів:
- `/sys/block/sda/queue/logical_block_size`: Логічний розмір сектора диска в байтах (512 або 4096).
- `/sys/block/sda/queue/physical_block_size`: Фізичний розмір комірки диска в байтах (4096).
- `/sys/block/sda/queue/minimum_io_size`: Мінімальний рекомендований розмір порції I/O.
- `/sys/block/sda/queue/scheduler`: Перелік підтримуваних та поточного планувальника I/O (`[mq-deadline] bfq kyber none`).
- `/sys/block/sda/queue/rotational`: Прапорець обертання носія (`1` для магнітних HDD, `0` для SSD та NVMe).

Обробка помилок у блочному шарі базується на поверненні кодів `blk_status_t`. Значення `BLK_STS_OK` відповідає успіху, `BLK_STS_TIMEOUT` означає таймаут апаратного відгуку носія, а `BLK_STS_NOSPC` — що на пристрої більше немає місця (типова ситуація для тонко розподілених томів).
