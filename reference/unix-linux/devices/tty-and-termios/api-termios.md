# 📋 `struct termios`: поля, прапорці, функції й коди помилок

Довідка за клавіатурою: що лежить у кожному з чотирьох слів прапорців, які індекси має масив `c_cc`, чим різняться три режими застосування `tcsetattr`, що Linux додав понад POSIX і звідки беруться коди помилок. Питання, на яке ця довідка відповідає найчастіше, звучить так: у яке поле класти потрібний вимикач — і чи погодиться драйвер його взяти.

## Сама структура

```c
#include <termios.h>

/* glibc, Linux; наведено для довідки — оголошено в заголовку */
#define NCCS 32
struct termios {
    tcflag_t c_iflag;    /* що робити з тим, що прийшло  */
    tcflag_t c_oflag;    /* що робити з тим, що йде       */
    tcflag_t c_cflag;    /* сам канал: кадр, лінії, швидкість */
    tcflag_t c_lflag;    /* робота лінійної дисципліни    */
    cc_t     c_line;     /* номер лінійної дисципліни (не POSIX) */
    cc_t     c_cc[NCCS]; /* особливі символи              */
    speed_t  c_ispeed;   /* швидкість прийому  (glibc ≥ 2.42) */
    speed_t  c_ospeed;   /* швидкість передачі (glibc ≥ 2.42) */
};
```

Типи прості: `tcflag_t` і `speed_t` — `unsigned int`, `cc_t` — `unsigned char`. Розмір масиву різний по два боки від межі виклику: у glibc `NCCS` дорівнює 32, у ядра — 19, і бібліотека перекладає масив на кожному виклику. Поле `c_line` ядро зберігає, але дисципліну ним не перемикає — для цього є окремий `ioctl`.

Головне застереження до всієї решти довідки: **числові значення прапорців не переносні навіть між архітектурами того самого Linux**. `ICANON` — це `0x00000002` на x86 й ARM і `0x00000100` на PowerPC; `BOTHER` — `0x00001000` там і `0x0000001f` тут. Тому в коді пишуть імена й ніколи числа, а структуру не будують з нуля: її читають, правлять потрібні біти й записують назад.

Частина імен нижче — не POSIX, і в glibc вони видні лише з `#define _DEFAULT_SOURCE` (до glibc 2.19 — `_BSD_SOURCE`) перед першим `#include`. Це стосується `cfmakeraw`, `cfsetspeed`, `CRTSCTS`, `CMSPAR`, `IUTF8`, `EXTPROC` і всіх полів затримки. Сталі `TCGETS2`, `BOTHER` і `struct termios2` живуть іще далі — у заголовку ядра `<asm/termbits.h>`, який оголошує власну `struct termios` і тому з `<termios.h>` в одній одиниці трансляції не поєднується.

## `c_iflag` — обробка входу

| прапорець | що вмикає | стандарт |
|---|---|---|
| `IGNBRK` | викидати розрив на лінії зовсім | POSIX |
| `BRKINT` | розрив скидає обидві черги й шле `SIGINT` передній групі | POSIX |
| `IGNPAR` | викидати байти з хибною парністю або зламаним кадром | POSIX |
| `PARMRK` | позначати такі байти префіксом `0377 0` замість викидання | POSIX |
| `INPCK` | вмикає саму перевірку парності на вході | POSIX |
| `ISTRIP` | зрізати восьмий біт кожного байта | POSIX |
| `INLCR` | `0x0A` → `0x0D` | POSIX |
| `IGNCR` | викидати `0x0D` | POSIX |
| `ICRNL` | `0x0D` → `0x0A` (діє, лише коли `IGNCR` знято) | POSIX |
| `IXON` | символи `VSTOP`/`VSTART` у вхідному потоці спиняють і пускають **вивід** | POSIX |
| `IXOFF` | ядро само шле `VSTOP` назустріч, коли вхідна черга повниться | POSIX |
| `IXANY` | спинений вивід поновлює будь-який символ, не лише `VSTART` | XSI |
| `IMAXBEL` | дзвінок замість тихої втрати, коли вхідна черга повна | не POSIX |
| `IUCLC` | великі літери на вході робити малими | не POSIX (SVr4) |
| `IUTF8` | вхід у UTF-8: забій прибирає цілий символ, а не один байт | Linux 2.6.4 |

Три прапорці парності читаються разом і поодинці не значать нічого: `INPCK` вмикає перевірку, а `IGNPAR` і `PARMRK` лише вирішують долю знайденого. Без `INPCK` обидва мовчать.

Порядок обробки всередині слова закріплений, і саме він робить `ISTRIP` небезпечним для двійкових даних: спершу парність, потім зрізання восьмого біта, далі перетворення переводів рядка, наприкінці `IXON`. Байт `0x8D` через `ISTRIP` стає `0x0D`, а той через `ICRNL` — `0x0A`. Одне число перетворилося на інше двома незалежними вимикачами, і жоден із них не дав про це знати.

## `c_oflag` — обробка виходу

| прапорець | що вмикає | стандарт |
|---|---|---|
| `OPOST` | головний вимикач: без нього решта слова не діє взагалі | POSIX |
| `ONLCR` | `0x0A` → `0x0D 0x0A` | XSI |
| `OCRNL` | `0x0D` → `0x0A` | POSIX |
| `ONOCR` | не слати `0x0D`, коли каретка вже в нульовому стовпці | POSIX |
| `ONLRET` | вважати, що `0x0A` сам повертає каретку — `0x0D` не додавати | POSIX |
| `OLCUC` | малі літери на виході робити великими | не POSIX |
| `OFILL` | замість паузи слати символи-заповнювачі | POSIX |
| `OFDEL` | заповнювач — `DEL` (`0177`), інакше `NUL` | POSIX |
| `NLDLY`, `CRDLY`, `TABDLY`, `BSDLY`, `VTDLY`, `FFDLY` | поля затримки після відповідного символу | не POSIX |

Шість полів затримки — прямий слід механіки: друкарці треба було встигнути прокрутити папір або довезти каретку, і ядро мовчало рівно стільки, скільки треба. Живим із них лишилося одне значення — `TABDLY` = `XTABS`, за яким ядро розкладає табуляцію на пробіли замість того, щоб віддавати її терміналові.

Для двійкового обміну важить тільки перший рядок: знятий `OPOST` вимикає ціле слово одним бітом, і жоден `ONLCR` уже не додасть вашим даним зайвого байта.

## `c_cflag` — канал

| прапорець | що вмикає | стандарт |
|---|---|---|
| `CSIZE` | поле розміру символу: `CS5`, `CS6`, `CS7`, `CS8` | POSIX |
| `CSTOPB` | два стопові біти замість одного | POSIX |
| `PARENB` | генерувати парність на виході й чекати її на вході | POSIX |
| `PARODD` | парність непарна; без нього — парна | POSIX |
| `CMSPAR` | «липка» парність: біт завжди `1` (з `PARODD`) або завжди `0` | не POSIX |
| `CREAD` | увімкнути приймач; без нього не прийде нічого | POSIX |
| `CLOCAL` | ігнорувати модемні лінії — не чекати несучої на `open` | POSIX |
| `HUPCL` | опустити модемні лінії, коли пристрій закриє останній процес | POSIX |
| `CRTSCTS` | апаратне керування потоком лініями `RTS`/`CTS` | не POSIX |
| `CBAUD`, `CBAUDEX`, `CIBAUD`, `BOTHER` | застаріле кодування швидкости — окрема розмова нижче | не POSIX |

Перший рядок — не прапорець, а **поле**, і плутанина тут коштує години. `CSIZE` — маска з двох бітів, `CS8` — значення в ній, тож правильна форма одна: спершу очистити поле, потім покласти значення.

```c
tio.c_cflag = (tio.c_cflag & ~CSIZE) | CS8;   /* правильно завжди */
tio.c_cflag |= CS8;                            /* працює випадково */
tio.c_cflag |= CS7;                            /* мовчки лишає CS8 */
```

Другий рядок дає вірний результат лише тому, що на більшості архітектур `CS8` збігається з усією маскою `CSIZE`. Третій — уже помилка: `CS7` не накриває поля цілком, старший біт від `CS8` лишається на місці, і кадр виходить не тим, який просили.

Перші чотири рядки таблиці описують кадр [UART](book:communications/uart-frame) — стартовий біт, біти даних, необов'язкову парність і стоповий біт; звична пара `CS8` без `PARENB` і без `CSTOPB` — це і є той формат, який усі звуть 8N1.

## `c_lflag` — лінійна дисципліна

| прапорець | що вмикає | стандарт |
|---|---|---|
| `ICANON` | канонічний режим: рядки, редагування, `VEOF`/`VEOL` | POSIX |
| `ISIG` | звіряти вхід із `VINTR`, `VQUIT`, `VSUSP` і робити з байта сигнал | POSIX |
| `IEXTEN` | розширена обробка: `VLNEXT`, `VREPRINT`, `VWERASE`, `VDISCARD` | POSIX |
| `ECHO` | вертати назад кожен прийнятий символ | POSIX |
| `ECHOE` | забій стирає символ на екрані (потрібен `ICANON`) | POSIX |
| `ECHOK` | символ кілла стирає рядок на екрані | POSIX |
| `ECHONL` | друкувати `0x0A` навіть зі знятим `ECHO` | POSIX |
| `ECHOCTL` | керуючі символи показувати як `^X` | не POSIX |
| `ECHOPRT` | показувати стерте між `\` і `/` — для друку на папері | не POSIX |
| `ECHOKE` | кілл стирає рядок посимвольно, а не одним рухом | не POSIX |
| `NOFLSH` | не скидати черги, коли `ISIG` породив сигнал | POSIX |
| `TOSTOP` | фонова група, що пише в термінал, дістає `SIGTTOU` | POSIX |
| `FLUSHO`, `PENDIN` | стан обробки, а не наказ: читаються, не ставляться | не POSIX |
| `EXTPROC` | обробку рядка робить не ядро, а ведучий кінець псевдотермінала | не POSIX |
| `XCASE` | режим для терміналів лише з великими літерами | не POSIX, мертвий |

Слово зветься «локальним» не тому, що стосується місцевої машини, а тому, що не стосується ані дроту, ані перетворення байтів: тут зібрано власну роботу лінійної дисципліни.

`TOSTOP` і `NOFLSH` мають сенс лише разом із [керуванням завданнями](book:unix-linux/job-control) — термінал пам'ятає одну передню групу процесів, і саме на цій пам'яті тримається питання, кому дістанеться сигнал і хто зупиниться при спробі писати з фону. `EXTPROC` — теж не про дріт: він потрібен, коли [псевдотермінал](book:unix-linux/pseudo-terminal) віддає редагування рядка програмі на ведучому кінці, і ядро має пропускати байти без обробки, але вдавати перед веденим кінцем канонічний режим.

## `c_cc` — особливі символи

| індекс | ім'я | типове | діє при | що робить |
|---|---|---|---|---|
| 0 | `VINTR` | `^C` (`003`) | `ICANON` + `ISIG` | `SIGINT` передній групі |
| 1 | `VQUIT` | `^\` (`034`) | `ICANON` + `ISIG` | `SIGQUIT` і знімок пам'яті |
| 2 | `VERASE` | `^?` (`0177`) | `ICANON` | стерти попередній символ |
| 3 | `VKILL` | `^U` (`025`) | `ICANON` | стерти набраний рядок |
| 4 | `VEOF` | `^D` (`004`) | `ICANON` | віддати накопичене негайно; порожній рядок → `read` = 0 |
| 5 | `VTIME` | — | без `ICANON` | таймаут у десятих частках секунди |
| 6 | `VMIN` | — | без `ICANON` | скільки байтів мусить набратися |
| 7 | `VSWTC` | `NUL` | — | шари оболонки; у Linux не вживається |
| 8 | `VSTART` | `^Q` (`021`) | `IXON`/`IXOFF` | поновити спинений вивід |
| 9 | `VSTOP` | `^S` (`023`) | `IXON`/`IXOFF` | спинити вивід |
| 10 | `VSUSP` | `^Z` (`032`) | `ICANON` + `ISIG` | `SIGTSTP` передній групі |
| 11 | `VEOL` | `NUL` | `ICANON` | додаткова межа рядка |
| 12 | `VREPRINT` | `^R` (`022`) | `ICANON` + `IEXTEN` | передрукувати незчитане |
| 13 | `VDISCARD` | `^O` (`017`) | `IEXTEN` | перемикач «викидати вивід» |
| 14 | `VWERASE` | `^W` (`027`) | `ICANON` + `IEXTEN` | стерти слово |
| 15 | `VLNEXT` | `^V` (`026`) | `ICANON` + `IEXTEN` | наступний символ узяти дослівно |
| 16 | `VEOL2` | `NUL` | `ICANON` | ще одна межа рядка |

Числа в першому стовпці — Linux; POSIX їх не фіксує, і на інших системах вони інші. Практичний наслідок один: `VMIN` і `VTIME` там можуть ділити комірку з `VEOF` і `VEOL`, тому переносний код ніколи не покладається на те, що налаштування канонічного й неканонічного режимів уціліють одночасно. Ставити треба той набір, у якому програма зараз працює.

Вимкнути окремий символ можна значенням `_POSIX_VDISABLE` (у Linux — нуль): комірка перестає збігатися з будь-яким байтом, і той проходить наскрізь як звичайні дані.

`VMIN` і `VTIME` — не символи, а числа, і тип комірки той самий `cc_t`, тобто один байт. Звідси дві жорсткі межі, які нізвідки більше не видно: `VMIN` не буває більший за 255, а `VTIME` — за 25.5 секунди. Ці два числа стосуються тільки [блокуючого режиму](book:unix-linux/blocking-and-nonblocking): з `O_NONBLOCK` виклик повертається негайно, і чекати доводиться зовсім іншими засобами.

Функція `cfmakeraw` заразом чіпає й цей масив — ставить `VMIN` = 1 і `VTIME` = 0. Про це забувають і дивуються, чому ретельно виставлений таймаут зник: його стерли пізнішим викликом `cfmakeraw`.

## Швидкість

![Три способи покласти швидкість у termios: індекс у полі CBAUD, значення BOTHER із числами в c_ispeed/c_ospeed, і числовий speed_t у glibc 2.42](/reference/unix-linux/devices/tty-and-termios/img/baud-encoding.svg)

*Змінилося не поле й не виклик, а те, чим є `speed_t`: був номер рядка в таблиці — стало саме число.*

```c
speed_t cfgetispeed(const struct termios *t);
speed_t cfgetospeed(const struct termios *t);
int     cfsetispeed(struct termios *t, speed_t speed);
int     cfsetospeed(struct termios *t, speed_t speed);
int     cfsetspeed (struct termios *t, speed_t speed);  /* BSD: обидві одразу */
```

Усі п'ять правлять **структуру в пам'яті** й не торкаються пристрою: без наступного `tcsetattr` не станеться нічого. Набір сталих іде від `B0` до `B4000000`, причому `B0` — не швидкість, а наказ опустити модемні лінії, тобто покласти слухавку. Окрема швидкість на прийом і на передачу підтримується рідко, і `cfsetispeed(t, B0)` означає рівно «така сама, як на передачу».

Історично швидкість була номером рядка в таблиці, захованим у полі `CBAUD` слова `c_cflag`, — п'ять бітів, до того ж розірваних: чотири молодші й один старший, `CBAUDEX`. Звідси й стеля: доступними були тільки ті значення, які хтось колись у таблицю вписав. Linux обійшов її значенням `BOTHER` у тому самому полі: воно каже «швидкість не тут», і ядро бере два звичайні 32-бітні числа з полів `c_ispeed`/`c_ospeed` структури `termios2`, яку передають через `ioctl` з `TCSETS2`.

Від glibc 2.42 обхід більше не потрібен: `speed_t` став самим числом швидкости, стала `B115200` тепер дорівнює `115200`, а `tcsetattr` під сподом сам ставить `BOTHER` і кличе `TCSETS2`. Старі значення нікуди не зникли — вони лишилися в бібліотеці під іменами з двома підкресленнями й потрібні їй саме для розмови з ядром.

> 🔧 **Навіщо це.** Перевірка `if (speed == B115200)` у новому коді вірна, а `switch` по всіх `B*` — уже ні: між сусідніми сталими тепер є проміжок, і `250000` не збігається з жодною. Так само зламається код, який брав `cfgetospeed` і шукав його в таблиці відповідностей: значення вже й є відповідь, шукати нічого не треба. Ці два прийоми — головне, що ламає перехід на нову бібліотеку, і обидва тихі.

Швидкість треба ставити з обох боків дроту однакову, і причина не в узгодженні, а в тому, що приймач [не має тактового сигналу](book:communications/baud-rate) й відлічує середини бітів власним годинником від стартового фронту.

## Прочитати, змінити, записати

```c
int tcgetattr(int fd, struct termios *t);
int tcsetattr(int fd, int optional_actions, const struct termios *t);
```

| дія | значення | що робить із тим, що в дорозі |
|---|---|---|
| `TCSANOW` | 0 | міняє негайно; байти з вихідної черги підуть уже за новими правилами |
| `TCSADRAIN` | 1 | чекає, поки вихідна черга спорожніє |
| `TCSAFLUSH` | 2 | чекає виходу **і** викидає непрочитаний ввід |

Правило вибору просте. Міняєте формат кадру або швидкість — треба `TCSADRAIN`, інакше хвіст попереднього повідомлення поїде з новим кадром і на тому кінці стане сміттям. Налаштовуєте порт на старті — треба `TCSAFLUSH`: у вхідній черзі може лежати те, що встигла надіслати плата, поки нею ніхто не цікавився.

Найважливіше в цій парі — угода про повернення. **`tcsetattr` повертає успіх, якщо застосував бодай частину запитаного.** Це не хиба реалізації, а вимога POSIX, і стандарт прямо радить після зміни швидкости прочитати стан назад і подивитися, що з нього вийшло.

```c
struct termios want, got;
if (tcgetattr(fd, &want) < 0) return -1;
/* … правимо потрібні біти в want … */
if (tcsetattr(fd, TCSAFLUSH, &want) < 0) return -1;

if (tcgetattr(fd, &got) < 0) return -1;
if ((got.c_cflag & (CSIZE | PARENB | CSTOPB | CRTSCTS))
        != (want.c_cflag & (CSIZE | PARENB | CSTOPB | CRTSCTS))
    || cfgetospeed(&got) != cfgetospeed(&want)
    || got.c_lflag != want.c_lflag) {
    errno = EINVAL;              /* драйвер узяв не все */
    return -1;
}
```

Звіряють саме поля, а не всю структуру байт у байт. Драйвер має право чесно повернути не те, що ви клали, і при цьому виконати наказ: скажімо, коли обидві швидкості однакові, поле `CIBAUD` вичищають — так робить і сама бібліотека перед викликом `ioctl`. Порівняння через `memcmp` спіткнеться на такій дрібниці й відкине цілком робоче налаштування.

## Черги й потік

```c
int tcdrain(int fd);                       /* чекати, поки вийде вся вихідна черга */
int tcflush(int fd, int queue_selector);   /* TCIFLUSH 0, TCOFLUSH 1, TCIOFLUSH 2 */
int tcflow(int fd, int action);            /* TCOOFF 0, TCOON 1, TCIOFF 2, TCION 3 */
int tcsendbreak(int fd, int duration);
```

| виклик | аргумент | дія |
|---|---|---|
| `tcdrain` | — | заснути, поки все з вихідної черги не піде в дріт |
| `tcflush` | `TCIFLUSH` | викинути прийняте, але не прочитане |
| `tcflush` | `TCOFLUSH` | викинути записане, але не передане |
| `tcflush` | `TCIOFLUSH` | викинути і те, і те |
| `tcflow` | `TCOOFF` / `TCOON` | спинити / поновити вивід у дріт |
| `tcflow` | `TCIOFF` / `TCION` | надіслати на той кінець символ `VSTOP` / `VSTART` |

Імена двох перших плутають постійно, хоча дії протилежні: `tcdrain` **чекає**, доки черга спорожніє сама, `tcflush` — **викидає** її вміст не чекаючи.

Пастка `tcdrain` глибша за назву. Він знає лише про чергу ядра й нічого — про буфер усередині USB-перехідника, який може тримати ще кількасот байтів. Тому «дочекався й закрив» на такому порту здатне обрізати хвіст повідомлення, і робочий код додає коротку паузу перед `close`. Сам виклик — точка скасування потоку, і сигнал перериває його з `EINTR`.

`tcsendbreak` шле [розрив](book:communications/break-signal-uart) — не байт, а стан лінії, довший за цілий кадр, чого при нормальній передачі бути не може. Нульова тривалість означає від 0.25 до 0.5 секунди; додатну glibc тлумачить як мілісекунди й округлює вгору до сотень, бо ядро приймає лише такі одиниці.

## Понад POSIX: `ioctl`-и Linux

Усе, чого не було в дроті або чого POSIX не описав, живе поза `termios` — в окремому [керуючому каналі до драйвера](book:unix-linux/ioctl-interface), де кожна команда має свій номер і свій тип аргументу.

| запит | аргумент | що робить |
|---|---|---|
| `TCGETS2`, `TCSETS2`, `TCSETSW2`, `TCSETSF2` | `struct termios2 *` | те саме, що `TCGETS`/`TCSETS`…, але зі швидкостями числами (Linux 2.6.20) |
| `TIOCGETD`, `TIOCSETD` | `int *` | прочитати / поставити номер лінійної дисципліни |
| `TIOCGWINSZ`, `TIOCSWINSZ` | `struct winsize *` | розмір вікна; запис шле `SIGWINCH` передній групі |
| `TIOCMGET`, `TIOCMSET`, `TIOCMBIS`, `TIOCMBIC` | `int *` | модемні лінії: `TIOCM_DTR`, `TIOCM_RTS`, `TIOCM_CTS`, `TIOCM_CAR`, `TIOCM_DSR`, `TIOCM_RI` |
| `TIOCINQ` (він же `FIONREAD`), `TIOCOUTQ` | `int *` | скільки байтів чекає у вхідній / вихідній черзі |
| `TIOCSBRK`, `TIOCCBRK` | — | тримати розрив / відпустити його вручну |
| `TIOCEXCL`, `TIOCNXCL` | — | виключний доступ: наступний `open` дістане `EBUSY` |

```c
struct winsize {
    unsigned short ws_row, ws_col;        /* у символах */
    unsigned short ws_xpixel, ws_ypixel;  /* у точках; часто нулі */
};
```

Родина з `2` в імені потрібна нечасто: від glibc 2.42 бібліотека кличе її сама. Коли справді доводиться — пам'ятайте, що вона є не скрізь. На PowerPC її немає взагалі, бо там швидкості лежать просто в `struct termios`; на Alpha вона з'явилася аж у ядрі 4.20.

`TIOCSETD` — єдиний спосіб замінити обробку між дротом і `read`: цим викликом на місце типової `N_TTY` стає `N_SLIP`, `N_PPP` або `N_GSM`, і той самий файл починає віддавати не байти, а мережеві кадри.

Пара `TIOCM*` дає ручний доступ до тих ліній, які `c_cflag` уміє лише ігнорувати цілком через `CLOCAL`. Саме нею скидають плату, смикнувши `DTR`, коли треба зробити це навмисно, а не випадковим побічним ефектом відкриття порту.

## Коди помилок

| код | коли | де |
|---|---|---|
| `EBADF` | `fd` не є дійсним дескриптором | усі виклики |
| `ENOTTY` | дескриптор дійсний, але за ним не термінал | усі виклики |
| `EINVAL` | `optional_actions` не з трьох; `queue_selector` або `action` не з переліку; запитане значення драйвер не підтримує | `tcsetattr`, `tcflush`, `tcflow` |
| `EINTR` | сигнал перервав очікування | `tcdrain`, `tcsendbreak`, `tcsetattr` із `TCSADRAIN`/`TCSAFLUSH` |
| `EIO` | процес у фоновій групі осиротілого сеансу, `SIGTTOU` не заблоковано й не знехтувано | усі, що міняють стан |
| `EBUSY` | `open` після того, як інший процес узяв `TIOCEXCL` | `open` |
| `ENODEV`, `EIO` | пристрій зник — перехідник від'єднали | будь-який виклик на вже відкритому `fd` |

Перші дві варто запам'ятати парою, бо їх постійно плутають: `EBADF` каже «такого дескриптора немає», `ENOTTY` — «дескриптор є, але за ним не лінійна дисципліна». На другій відповіді, до речі, побудована вся функція `isatty`: вона просто робить `tcgetattr` і дивиться, чи не прийшло `ENOTTY`.

`EIO` з таблиці — не збій заліза, а політика: [керування завданнями](book:unix-linux/job-control) не дозволяє фоновій програмі мовчки перенастроїти термінал під живою передньою. Звичайний процес у такому разі дістає `SIGTTOU` і зупиняється; `EIO` повертають лише тому, кого зупиняти вже нікому — осиротілій групі, чий керівник помер.

Найпідступніший рядок у таблиці — той, якого в ній немає. Драйвер, що не вміє `CRTSCTS` або не має дільника під запитану швидкість, не поверне жодного коду: він тихо лишить своє й скаже `tcsetattr` успіх. Помилки тут не буде — буде розбіжність, і побачить її лише той, хто прочитав стан назад.
