# API: Прапорці Device Links

Під час створення зв'язку через `device_link_add` можна комбінувати наступні прапорці:

*   **`DL_FLAG_STATELESS`**: Зв'язок не впливає на порядок завантаження/вивантаження драйверів (probe/remove). Він впливає лише на порядок керування живленням. Постачальник та споживач керують своїм життєвим циклом незалежно. Такий зв'язок ядро само не прибирає: його видаляє той, хто створив, — `device_link_del()` або `device_link_remove()`. Несумісний з `DL_FLAG_AUTOREMOVE_CONSUMER`, `DL_FLAG_AUTOREMOVE_SUPPLIER` та `DL_FLAG_AUTOPROBE_CONSUMER`: із будь-яким із них `device_link_add()` поверне `NULL`.
*   **`DL_FLAG_PM_RUNTIME`**: Управління Runtime PM (RPM). Коли споживач активний (RPM active), постачальник також примусово утримується в активному стані.
*   **`DL_FLAG_AUTOREMOVE_CONSUMER`**: Ядро автоматично прибирає **сам зв'язок**, коли споживач не зміг пройти `probe` або згодом відв'язався (unbind), — видаляти його вручну не треба. Дзеркальний `DL_FLAG_AUTOREMOVE_SUPPLIER` робить те саме, коли `probe` не пройшов або відв'язався постачальник. Порядок відв'язування (споживач перед постачальником) забезпечує сам керований зв'язок, а не ці прапорці.
*   **`DL_FLAG_AUTOPROBE_CONSUMER`**: Після успішного `probe` постачальника, ядро автоматично спробує викликати `probe` для споживача (якщо він раніше завершився з `EPROBE_DEFER` через очікування постачальника).
