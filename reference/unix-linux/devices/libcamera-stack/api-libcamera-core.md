# 📋 Довідник класів, елементів керування та IPA-інтерфейсів

Публічний програмний інтерфейс бібліотеки `libcamera` спроєктовано за стандартом C++17 із застосуванням ідіом безпечного керування ресурсами (RAII, розумні вказівники `std::unique_ptr` та `std::shared_ptr`), типізованих контейнерів і механізмів передачі подій через сигнали та слоти. Архітектура бібліотеки відокремлює високорівневу логіку застосунку від низькорівневих дескрипторів ядра Linux, водночас забезпечуючи прямий контроль над кожним окремим кадром за допомогою моделі запитів.

Нижче наведено структурований опис ключових класів ядра бібліотеки, їхніх публічних методів, контрактів взаємодії, таблиць стандартних елементів керування (`libcamera::controls`), статичних фізичних властивостей апаратури (`libcamera::properties`), специфікації ізоляції алгоритмічних модулів обробки зображень (IPA), а також інтерфейсів шарів сумісності та інваріантів обробки системних помилок.

## 1. Базові класи ядра libcamera

Архітектурний каркас бібліотеки складається з кількох взаємопов'язаних абстракцій, які супроводжують життєвий цикл камери від моменту виявлення в системі до завершення потокової передачі кадрів.

```
 ┌─────────────────────────────────────────────────────────────┐
 │                        CameraManager                        │
 │            • start() / stop() / cameras() / get()           │
 └──────────────────────────────┬──────────────────────────────┘
                                │ 1 : N
                                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │                           Camera                            │
 │         • acquire() / release() / configure() / start()     │
 └──────────────┬───────────────────────────────┬──────────────┘
                │ 1 : 1                         │ 1 : N
                ▼                               ▼
 ┌─────────────────────────────┐ ┌─────────────────────────────┐
 │     CameraConfiguration     │ │           Request           │
 │  • at(i) StreamConfiguration│ │  • addBuffer() / controls() │
 └─────────────────────────────┘ └──────────────┬──────────────┘
                                                │ 1 : N
                                                ▼
                                 ┌─────────────────────────────┐
                                 │         FrameBuffer         │
                                 │    • planes() [dma-buf fd]  │
                                 └─────────────────────────────┘
```

### Детальний опис класів ядра

| Клас | Заголовочний файл | Призначення, контракти та ключові методи |
| :--- | :--- | :--- |
| `CameraManager` | `<libcamera/camera_manager.h>` | Керує життєвим циклом підсистеми, виявленням пристроїв і переліком камер.<br>• `start() -> int`: запускає перерахування шин і медіаграфів. Повертає `0` у разі успіху або від'ємний код помилки системи.<br>• `stop()`: зупиняє роботу менеджера, скасовує фонові потоки моніторингу udev.<br>• `cameras() const -> std::vector<std::shared_ptr<Camera>>`: повертає список усіх виявлених камер у системі.<br>• `get(const std::string &id) -> std::shared_ptr<Camera>`: здійснює пошук камери за унікальним рядковим ідентифікатором шляху в дереві пристроїв sysfs.<br>• `eventDispatcher() -> EventDispatcher*`: повертає покажчик на системний цикл обробки асинхронних подій таймерів та дескрипторів. |
| `Camera` | `<libcamera/camera.h>` | Абстракція логічної камери (сенсор + CSI-2 + ISP).<br>• `id() const -> const std::string&`: унікальний рядковий ідентифікатор пристрою.<br>• `acquire() -> int`: встановлює монопольне блокування камери поточним процесом. Повертає `-EBUSY`, якщо камера вже захоплена.<br>• `release() -> int`: звільняє пристрій для інших застосунків.<br>• `generateConfiguration(roles) -> std::unique_ptr<CameraConfiguration>`: генерує рекомендовану конфігурацію для заданого списку ролей потоків.<br>• `configure(config) -> int`: передає узгоджену конфігурацію в апаратний драйвер Pipeline Handler.<br>• `createRequest(cookie) -> std::unique_ptr<Request>`: виділяє новий об'єкт запиту для чергування кадру.<br>• `start(controls) -> int`: запускає апаратний конвеєр захоплення відеопотоку.<br>• `stop() -> int`: зупиняє потік і очищує черги DMA.<br>• `queueRequest(request) -> int`: ставить сформований запит в чергу обробки.<br>• `Signal<Request*> requestCompleted`: сигнал, що випромінюється після завершення апаратної обробки запиту. |
| `CameraConfiguration` | `<libcamera/camera_configurations.h>` | Контейнер конфігурацій потоків конкретної камери.<br>• `at(index) -> StreamConfiguration&`: повертає посилання на параметри потоку за індексом.<br>• `validate() -> Status`: перевіряє сумісність параметрів з апаратурою. Повертає: `Valid` (параметри підтримуються без змін), `Adjusted` (параметри було скориговано драйвером під обмеження ISP), `Invalid` (конфігурація фізично неможлива).<br>• `transform: Transform`: задає апаратне дзеркалювання та поворот кадру (на 90°, 180°, 270°). |
| `StreamConfiguration` | `<libcamera/stream.h>` | Параметри окремого вихідного потоку камери.<br>• `size: Size(width, height)`: роздільна здатність у пікселях.<br>• `pixelFormat: PixelFormat`: формат FourCC (`formats::NV12`, `formats::BGR888`, `formats::SRGGB10` тощо).<br>• `bufferCount: unsigned int`: кількість буферів DMA, виділених під цей потік у ядрі.<br>• `stream() const -> Stream*`: покажчик на логічний об'єкт потоку. |
| `Request` | `<libcamera/request.h>` | Атомарний опис операції захоплення одного кадру.<br>• `addBuffer(stream, buffer) -> int`: прив'язує `FrameBuffer` до відповідного потоку запиту.<br>• `findBuffer(stream) const -> FrameBuffer*`: знаходить буфер за покажчиком на потік.<br>• `controls() -> ControlList&`: контейнер параметрів керування, що мають набути чинності саме під час експонування цього кадру.<br>• `metadata() const -> const ControlList&`: вихідні метадані (фактична витримка, посилення, таймстемпи).<br>• `status() const -> Status`: стан виконання запиту (`RequestPending`, `RequestComplete`, `RequestCancelled`).<br>• `reuse(flags)`: скидає внутрішній стан запиту для повторного використання без перерозподілу пам'яті. |
| `FrameBuffer` | `<libcamera/framebuffer.h>` | Фізичне представлення буфера кадру в пам'яті DMA.<br>• `planes() const -> const std::vector<Plane>&`: перелік площин пам'яті, де кожна площина описується файловим дескриптором `fd`, числовим зміщенням `offset` і довжиною `length`.<br>• `metadata() const -> const FrameMetadata&`: службова інформація кадру (статус `FrameSuccess`/`FrameError`, лічильник послідовності `sequence`, таймстемп `timestamp` у наносекундах та кількість записаних байтів `bytesused`). |
| `FrameBufferAllocator` | `<libcamera/framebuffer_allocator.h>` | Системний виділювач пулу буферів пам'яті dma-buf.<br>• `allocate(stream) -> int`: створює апаратні буфери ядра для обраного потоку.<br>• `free(stream) -> int`: звільняє виділені буфери.<br>• `buffers(stream) const -> const std::vector<std::unique_ptr<FrameBuffer>>&`: надає доступ до виділеного пулу буферів. |

## 2. Ролі потоків (StreamRole)

Під час формування конфігурації через виклик `Camera::generateConfiguration()` розробник передає перелік ролей `StreamRole`. Роль визначає призначення потоку, дозволяючи обробнику Pipeline Handler оптимально розподілити ресурси внутрішніх скалерів і колірних перетворювачів ISP:

- `StreamRole::Raw`: запит на отримання сирих нестиснених даних безпосередньо з виходу сенсора (формати Bayer RAW8, RAW10, RAW12, RAW14). Усі блоки постобробки ISP оминаються, що мінімізує споживання енергії та затримку, забезпечуючи максимальну швидкість для астрофотографії або власної програмної дебайєризації.
- `StreamRole::StillCapture`: потік найвищої доступної роздільної здатності з увімкненням усіх важких алгоритмів постобробки (глибоке шумозаглушення 3DNR, компенсація віньєтування LSC, висока різкість) для збереження статичних фотографій.
- `StreamRole::VideoRecording`: потік високої роздільної здатності з фіксованою частотою кадрів і форматом пікселів, оптимізованим для прямої передачі в апаратні відеоенкодери H.264/HEVC (переважно напівпланарні формати `NV12` або `NV21`).
- `StreamRole::Viewfinder`: потік зниженої або середньої роздільної здатності (наприклад, 720p або 1080p), призначений для виведення інтерактивного попереднього перегляду на екран користувача з мінімальною затримкою.

## 3. Таблиця стандартних елементів керування (libcamera::controls)

Елементи керування передаються в об'єкт запиту через метод `Request::controls()`, визначаючи параметри зйомки конкретного кадру, а також зчитуються у зворотному напрямку через метод `Request::metadata()`, відображаючи фактичні показники апаратури.

Кожен елемент керування має строго типізоване значення, діапазон допустимих величин та чітко визначену семантику перетворення у фізичні одиниці:

| Ідентифікатор елемента | Тип значення | Опис семантики та допустимі діапазони |
| :--- | :--- | :--- |
| `controls::AeEnable` | `bool` | Перемикач алгоритму автоекспозиції (`true` — автоекспозиція активна і розраховується модулем IPA, `false` — ручне встановлення параметрів експонування). |
| `controls::ExposureTime` | `int32_t` | Час витримки матриці в мікросекундах (мкс). У ручному режимі задає бажану тривалість інтеграції фотодіодів; у метаданих повертає фактичний час витримки, розрахований ядром для цього кадру. |
| `controls::AnalogueGain` | `float` | Коефіцієнт аналогового підсилення сигналу на кремнієвій матриці (значення `1.0` відповідає базовій чутливості 0 дБ, `2.0` відповідає підсиленню +6 дБ). |
| `controls::AeMeteringMode` | `int32_t` | Режим зонового зважування яскравості: `MeteringCentreWeighted` (пріоритет центральної зони кадру), `MeteringSpot` (точкова експонометрія за центром), `MeteringMatrix` (оцінка всієї сітки сенсора), `MeteringCustom`. |
| `controls::AeExposureMode` | `int32_t` | Пріоритетний профіль автоекспозиції: `ExposureNormal` (збалансований режим), `ExposureShort` (мінімізація розмиття рухомих об'єктів), `ExposureLong` (максимізація витримки для нічної зйомки), `ExposureCustom`. |
| `controls::AwbEnable` | `bool` | Перемикач автоматичного балансу білого (`true` — динамічний розрахунок колірної температури модулем IPA, `false` — фіксовані коефіцієнти підсилення кольорів). |
| `controls::AwbMode` | `int32_t` | Фіксований профіль колірної температури освітлення: `AwbAuto`, `AwbIncandescent` (лампи розжарювання ~2700K), `AwbTungsten` (~3000K), `AwbFluorescent` (~4000K), `AwbDaylight` (денне сонячне світло ~5500K), `AwbCloudy` (~6500K). |
| `controls::ColourGains` | `Span<const float, 2>` | Ручні коефіцієнти посилення червоного та синього колірних каналів у форматі масиву з двох чисел `[R_gain, B_gain]`. Застосовуються, коли `AwbEnable = false`. |
| `controls::AfMode` | `int32_t` | Режим роботи приводу фокусування лінзи: `AfModeManual` (ручне позиціонування), `AfModeAuto` (одноразове фокусування за тригером), `AfModeContinuous` (постійний автоматичний стежачий фокус). |
| `controls::AfTrigger` | `int32_t` | Команда запуску або скасування циклу автофокусування: `AfTriggerStart` (почати пошук фокусу), `AfTriggerCancel` (зупинити пошук). |
| `controls::LensPosition` | `float` | Фізичне положення оптичної лінзи в діоптріях, що дорівнює оберненій відстані фокусування `1.0 / відстань_у_метрах` (значення `0.0` відповідає фокусу на нескінченність, `10.0` — фокусу на відстань 10 см). |
| `controls::Brightness` | `float` | Зсув яскравості зображення в діапазоні від `-1.0` (повне затемнення) до `1.0` (максимальне освітлення) з нульовим базовим рівнем `0.0`. |
| `controls::Contrast` | `float` | Множник контрастності кривої тонового відображення (значення `1.0` відповідає лінійній передачі контрасту без змін). |
| `controls::Saturation` | `float` | Коефіцієнт колірної насиченості (значення `0.0` перетворює зображення на градації сірого, `1.0` відповідає природній насиченості). |
| `controls::Sharpness` | `float` | Рівень просторового підсилення високих частот апаратними фільтрами ISP (значення `1.0` — стандартне згладжування, значення > `1.0` підсилює чіткість дрібних деталей). |
| `controls::ScalerCrop` | `Rectangle` | Прямокутник цифрового кадрування на площині вихідної матриці пікселів `Rectangle(x, y, width, height)`, що забезпечує плавне апаратне цифрове масштабування (Digital Zoom). |
| `controls::FrameDuration` | `int64_t` | Бажана тривалість кадру в мікросекундах. Визначає максимальну частоту кадрів за формулою `FPS = 1000000 / FrameDuration`. |

## 4. Таблиця статичних властивостей апаратури (libcamera::properties)

Статичні властивості зчитуються через виклик `camera->properties()`. Вони описують незмінні фізичні параметри кремнієвої матриці, геометрію розташування модуля на друкованій платі та прив'язку до системних вузлів ядра Linux:

| Ідентифікатор властивості | Тип | Опис та призначення властивості |
| :--- | :--- | :--- |
| `properties::Model` | `std::string` | Назва та індекс моделі оптичного сенсора відповідно до його внутрішнього ідентифікатора реєстру (наприклад, `"imx477"`, `"imx219"`, `"ov5647"`, `"imx708"`). |
| `properties::Location` | `int32_t` | Фізичне просторове розташування камери на корпусі пристрою: `CameraLocationFront` (фронтальна камера), `CameraLocationBack` (основна задня камера), `CameraLocationExternal` (зовнішня підключена камера). |
| `properties::Rotation` | `int32_t` | Апаратний кут монтажу модуля на платі відносно нормальної орієнтації у градусах (`0`, `90`, `180`, `270`). |
| `properties::PixelArraySize` | `Size` | Повні геометричні розміри матриці пікселів сенсора у пікселях, включно з калібрувальними оптично закритими ділянками (наприклад, `Size(4056, 3040)`). |
| `properties::PixelArrayActiveAreas` | `Span<const Rectangle>` | Координати одного або декількох прямокутників активної світлочутливої зони пікселів, з яких зчитується корисне зображення. |
| `properties::UnitCellSize` | `Size` | Фізичний розмір одиничного пікселя на кремнієвій підкладці в нанометрах (наприклад, `Size(1550, 1550)` відповідає пікселю розміром 1.55 × 1.55 мкм). |
| `properties::SystemDevices` | `Span<const int64_t>` | Масив номерів системних пристроїв (`dev_t major/minor`) для всіх символьних файлів пристроїв у каталозі `/dev` (`/dev/mediaX`, `/dev/videoX`, `/dev/v4l-subdevX`), які формують цю камеру. |

## 5. Специфікація ізоляції та міжпроцесного обміну IPA

Модулі алгоритмів обробки зображень (IPA) можуть виконуватися як у межах адресного простору головного процесу застосунку (для повністю відкритих модулів із відкритим вихідним кодом), так і в ізольованому дочірньому процесі пісочниці під контролем фільтрів системних викликів `seccomp`.

```
 ┌─────────────────────────────────────────────────────────────┐
 │                Головний процес застосунку                   │
 │                                                             │
 │   ┌──────────────────────┐         ┌────────────────────┐   │
 │   │   Pipeline Handler   │         │    IPA Proxy       │   │
 │   └──────────────────────┘         └─────────┬──────────┘   │
 └──────────────────────────────────────────────┼──────────────┘
                                                │ IPC (AF_UNIX)
                                                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │         Ізольований процес IPA (seccomp jail)               │
 │                                                             │
 │   ┌──────────────────────┐         ┌────────────────────┐   │
 │   │      IPA Stub        │────────>│ 3A Алгоритми (C++) │   │
 │   └──────────────────────┘         └────────────────────┘   │
 └─────────────────────────────────────────────────────────────┘
```

### Протокол зв'язку між Pipeline Handler та IPA

Міжпроцесна взаємодія між Pipeline Handler та проксі-обгорткою IPA здійснюється за суворим асинхронним протоколом:
1. **Ініціалізація (`init`):** Pipeline Handler передає модулю структуру `IPASettings` (шлях до конфігураційних файлів калібрування оптичного модуля у форматі YAML/JSON) та структуру `IPACameraSensorInfo` (характеристики матриці, розмір сітки пікселів, базові значення чутливості).
2. **Конфігурація потоків (`configure`):** Передаються розміри буферів та формати вхідних і вихідних потоків ISP. Модуль IPA розраховує таблиці дебайєризатора та створює внутрішні структури стану.
3. **Реєстрація пам'яті (`mapBuffers`):** Pipeline Handler експортує файлові дескриптори спільної пам'яті (`memfd_create` або `dma-buf`), виділені під структури параметрів ISP та буфери апаратної статистики 3A. Завдяки спільній пам'яті обмін великими масивами даних виконується з нульовим копіюванням без навантаження на шину IPC.
4. **Обробка кадру (`processStatsBuffer`):** Після того як апаратний блок ISP завершує формування статистики для кадру з номером `frame`, повідомлення про це надходить у сокет IPA. Модуль виконує розрахунки нових коефіцієнтів і через сигнал `setSensorControls` повертає оновлені параметри витримки та підсилення, які негайно закладаються в чергу запитів для наступного кадру.

## 6. Інтерфейси шарів сумісності: GStreamer libcamerasrc та v4l2-compat

Для безшовної інтеграції з наявною екосистемою мультимедійних програм libcamera надає додаткові програмні інтерфейси:

### Властивості елемента GStreamer `libcamerasrc`

Плагін `libcamerasrc` реєструє елемент-джерело GStreamer і підтримує такі ключові параметри GObject:
- `camera-name: gchararray` — унікальний шлях до камери в дереві пристроїв sysfs або ідентифікатор із `CameraManager`.
- `stream-role: GstLibcameraStreamRole` — явне встановлення ролі потоку (`viewfinder`, `video-recording`, `still-capture`, `raw`). За замовчуванням визначається автоматично на основі узгоджених `GstCaps`.
- `auto-focus-mode: GstLibcameraAfMode` — режим автофокусування лінзи (`manual`, `auto`, `continuous`).

### Контракт емуляції `v4l2-compat.so`

Шар сумісності перехоплює стандартні виклики V4L2 через механізм `LD_PRELOAD`:
- Повертає список підтримуваних форматів через `VIDIOC_ENUM_FMT`, транслюючи їх із внутрішніх можливостей `PipelineHandler`.
- Автоматично перетворює однопотоковий запит `VIDIOC_REQBUFS` на пул об'єктів `libcamera::Request`.
- Емулює блокуючий виклик `ioctl(fd, VIDIOC_DQBUF, &buf)`, очікуючи на сигнал `requestCompleted` від ядра libcamera, що дозволяє застарілим програмам (таким як утиліти OpenCV VideoCapture або браузери) прозоро працювати зі складними сенсорами без жодних змін у їхньому вихідному коді.

## 7. Коди помилок та інваріанти стану

Усі публічні методи libcamera сигналізують про успіх значенням `0`, а в разі помилки повертають стандартні від'ємні коди помилок ядра Linux (POSIX errno):

- `-EBUSY` — пристрій уже захоплено іншим процесом через `acquire()` або зміна конфігурації виконується під час активного стримінгу.
- `-EINVAL` — передано невалідні параметри конфігурації, непідтримуваний формат пікселів або некоректний вказівник на буфер.
- `-EACCES` — процес не має прав доступу до файлів пристроїв `/dev/mediaX` або `/dev/v4l-subdevX` у групі `video`.
- `-ENODEV` — фізичний пристрій було відключено від шини або сенсор не відповідає на команди шини I2C.
- `-ENOMEM` — системі забракло пам'яті ядра або вичерпано пул виділення CMA під час створення буферів DMA.
- `-ETIMEDOUT` — апаратний ISP не згенерував переривання завершення кадру протягом очікуваного інтервалу тайм-ауту.
