# 📋 Реєстр прапорців відхилень USB Core та USB Storage

Цей довідник надає вичерпну специфікацію бітових прапорців відхилень (quirk flags), структур даних ядра та механізмів конфігурування підсистем USB Core (`drivers/usb/core/`) та USB Mass Storage / UAS (`drivers/usb/storage/`) в операційній системі Linux. Він детально розкриває числові шістнадцяткові значення масок, літерні позначення параметрів модуля, задіяні структури даних ядра та точні зміни в алгоритмах взаємодії зі стеком USB, які викликає кожен прапорець.

## 1. Архітектурні прапорці USB Core (`include/linux/usb/quirks.h`)

Підсистема USB Core зберігає активний набір прапорців у полі `udev->quirks` типу `u32` всередині головної структури об'єкта пристрою `struct usb_device`. Значення ініціалізується під час процедури нумерації (enumeration) у функції `usb_detect_quirks()` шляхом зіставлення ідентифікаторів Vendor ID та Product ID зі статичною таблицею ядра або динамічним рядком параметра `usbcore.quirks`.

### Детальний розбір прапорців ядра

- **`USB_QUIRK_STRING_FETCH_255` (маска `0x00000001`, літера `a`):**
  - *Точка перехоплення в ядрі:* функція `usb_string()` у файлі `drivers/usb/core/message.c`.
  - *Механізм дії:* За стандартом USB запит дескриптора рядка передає довжину очікуваного буфера у 255 байтів. Прошивки деяких дешевих мікроконтролерів (зокрема старих звукових карт та сканерів) містять помилку обробки непарної граничної довжини буфера, через що контролер апаратно зависає або скидає з'єднання. Прапорець змушує ядро спочатку зчитувати 2-байтовий заголовок дескриптора для визначення точного розміру рядка і лише потім запитувати рівно потрібну кількість байтів, або запитувати фіксовані 256 байтів.

- **`USB_QUIRK_RESET_RESUME` (маска `0x00000002`, літера `b`):**
  - *Точка перехоплення в ядрі:* функція `usb_resume_both()` у файлі `drivers/usb/core/driver.c`.
  - *Механізм дії:* При виході системи зі стану сну (suspend) стандартний протокол вимагає подачі сигналу Resume Signaling на лініях D+/D-. Проте численні веб-камери, бездротові адаптери та USB-концентратори повністю втрачають свій внутрішній стан конфігурації під час знеструмлення або переходу в низькоспоживаючий режим. Замість звичайного пробудження ядро примусово викликає функцію `usb_reset_and_verify_device()`, яка генерує апаратний імпульс скидання порту тривалістю не менше 50 мс і повторно верифікує збереження дескрипторів.

- **`USB_QUIRK_NO_SET_INTF` (маска `0x00000004`, літера `c`):**
  - *Точка перехоплення в ядрі:* функція `usb_set_interface()` у файлі `drivers/usb/core/message.c`.
  - *Механізм дії:* Під час ініціалізації конфігурації ядро стандартно надсилає керувальний пакет `SET_INTERFACE (Interface = N, AlternateSetting = 0)` для приведення кінцевих точок у вихідний стан. Контролери пристроїв, що мають лише один режим роботи без альтернативних налаштувань, часто не реалізують обробник цього запиту і повертають стан зупинки `STALL` або припиняють відповідати на будь-які подальші запити на кінцевій точці EP0. Наявність прапорця змушує ядро пропустити надсилання команди, якщо пристрій уже перебуває в нульовому налаштуванні.

- **`USB_QUIRK_CONFIG_INTF_STRINGS` (маска `0x00000008`, літера `d`):**
  - *Точка перехоплення в ядрі:* функція `usb_get_configuration()` у файлі `drivers/usb/core/config.c`.
  - *Механізм дії:* Деякі пристрої повертають некоректні індекси строкових дескрипторів для інтерфейсів або конфігурацій (наприклад, посилаються на неіснуючі рядки з індексом більше 250). Спроба ядра прочитати такий рядок призводить до тривалих 5-секундних таймаутів. Цей прапорець блокує опитування текстових описів інтерфейсів, прискорюючи завантаження.

- **`USB_QUIRK_RESET` (маска `0x00000010`, літера `e`):**
  - *Точка перехоплення в ядрі:* функція `usb_reset_device()` у файлі `drivers/usb/core/hub.c`.
  - *Механізм дії:* Забороняє виконання процедури скидання пристрою під час відновлення після збоїв, якщо відомо, що апаратне скидання призводить до повного відключення живлення мікроконтролера або його переходу в невідновлюваний стан блокування.

- **`USB_QUIRK_HONOR_BNUMINTERFACES` (маска `0x00000020`, літера `f`):**
  - *Точка перехоплення в ядрі:* функція `usb_parse_configuration()` у файлі `drivers/usb/core/config.c`.
  - *Механізм дії:* Виробники дешевих комбінованих пристроїв іноді залишають сміттєві байти або залишки дескрипторів від інших ревізій у хвості дескриптора повної конфігурації. Прапорець змушує парсер ядра негайно припинити обробку буфера конфігурації, як тільки було розібрано кількість інтерфейсів, зазначену в полі `bNumInterfaces`.

- **`USB_QUIRK_DELAY_INIT` (маска `0x00000040`, літера `g`):**
  - *Точка перехоплення в ядрі:* функція `hub_port_init()` у файлі `drivers/usb/core/hub.c`.
  - *Механізм дії:* Після подачі імпульсу скидання порту або встановлення живлення повільні мікроконтролери потребують від 100 до 2000 мс для внутрішньої самодіагностики, ініціалізації PLL та завантаження прошивки з EEPROM. Якщо надіслати перший запит `GET_DESCRIPTOR` занадто рано, пристрій проігнорує його, змушуючи хост зафіксувати апаратну помилку. Прапорець додає гарантовану мікропрограмну затримку перед початком опитування.

- **`USB_QUIRK_LINEAR_UFRAME_INTR_BINTERVAL` (маска `0x00000080`, літера `h`):**
  - *Точка перехоплення в ядрі:* функція розрахунку інтервалів опитування у `drivers/usb/core/urb.c`.
  - *Механізм дії:* За стандартом USB 2.0 High-Speed значення поля `bInterval` для переривних точок кодується експоненційно як ступінь двійки: інтервал дорівнює `2^(bInterval-1)` мікрокадрів (де мікрокадр становить 125 мікросекунд). Деякі розробники апаратури помилково вказували пряме лінійне число мікрокадрів. Прапорець вмикає лінійну інтерпретацію, виправляючи некоректну частоту генерації переривань.

- **`USB_QUIRK_DEVICE_QUALIFIER` (маска `0x00000100`, літера `i`):**
  - *Точка перехоплення в ядрі:* функція `usb_get_device_qualifier()` у `drivers/usb/core/hub.c`.
  - *Механізм дії:* Хост-контролер запитує дескриптор `DEVICE_QUALIFIER`, щоб дізнатися параметри роботи High-Speed пристрою у разі його перемикання на швидкість Full-Speed. Багато Full-Speed пристроїв не мають такого дескриптора і фатально зависають на контрольному запиті. Прапорець блокує надсилання запиту.

- **`USB_QUIRK_IGNORE_REMOTE_WAKEUP` (маска `0x00000200`, літера `j`):**
  - *Точка перехоплення в ядрі:* функція керування живленням `usb_disable_remote_wakeup()`.
  - *Механізм дії:* Забороняє надсилання команди активації віддаленого пробудження `SET_FEATURE(DEVICE_REMOTE_WAKEUP)`. Це усуває проблему самовільного пробудження комп'ютера через дефектні сенсори мишей або клавіатур, а також запобігає зависанню шини при вході в глобальний режим сну.

- **`USB_QUIRK_NO_LPM` (маска `0x00000400`, літера `k`):**
  - *Точка перехоплення в ядрі:* функція `usb_disable_lpm()` у файлі `drivers/usb/core/hub.c`.
  - *Механізм дії:* Повністю вимикає протокол Link Power Management (LPM: перехід у стан L1 для USB 2.0 та стани U1/U2 для USB 3.0). Багато аудіоінтерфейсів та мережевих контролерів втрачають буфери даних або викликають переповнення черги DMA при частих переходах між станами низького енергоспоживання.

- **`USB_QUIRK_LINEAR_FRAME_INTR_BINTERVAL` (маска `0x00000800`, літера `l`):**
  - *Точка перехоплення в ядрі:* розрахунок інтервалів опитування для Full-Speed пристроїв.
  - *Механізм дії:* Коригує інтерпретацію інтервалу опитування для специфічних Full-Speed пристроїв, які передають значення в одиницях кадрів замість мілісекунд або порушують специфікацію логарифмічного масштабу.

- **`USB_QUIRK_DISCONNECT_SUSPEND` (маска `0x00001000`, літера `m`):**
  - *Точка перехоплення в ядрі:* функція `usb_port_suspend()`.
  - *Механізм дії:* Симулює логічне відключення пристрою перед засинанням системи, змушуючи ядро виконати повну повторну нумерацію з нуля при відновленні живлення. Застосовується для пристроїв, які не здатні коректно вийти зі стану апаратного знеструмлення.

- **`USB_QUIRK_DELAY_CTRL_MSG` (маска `0x00002000`, літера `n`):**
  - *Точка перехоплення в ядрі:* функція `usb_control_msg()` у `drivers/usb/core/message.c`.
  - *Механізм дії:* Вставляє примусову паузу тривалістю від 5 до 20 мс між послідовними керуючими транзакціями на нульовій кінцевій точці. Запобігає втраті команд на контролерах із малим розміром апаратного FIFO.

- **`USB_QUIRK_HUB_SLOW_RESET` (маска `0x00004000`, літера `o`):**
  - *Точка перехоплення в ядрі:* функція скидання портів концентратора `hub_port_reset()`.
  - *Механізм дії:* Подовжує час утримання шини в стані Single-Ended Zero (SE0) для концентраторів, фізичні трансивери яких повільно перемикають рівні напруги.

- **`USB_QUIRK_SHORT_SET_ADDRESS` (маска `0x00008000`, літера `p`):**
  - *Точка перехоплення в ядрі:* функція призначення адреси `hub_set_address()`.
  - *Механізм дії:* Скорочує інтервал стабілізації адреси після відправки пакета `SET_ADDRESS` для мікросхем, які скидають свій стан при тривалому очікуванні на нульовій адресі.

- **`USB_QUIRK_ENDPOINT_BLACK_LIST` (маска `0x00010000`, літера `q`):**
  - *Точка перехоплення в ядрі:* функція створення дескрипторів кінцевих точок `usb_add_ep_device()`.
  - *Механізм дії:* Дозволяє ядру ігнорувати несправні або зарезервовані виробником кінцеві точки, які викликають збій апаратного контролера при спробі виділення кільця передачі дескрипторів у xHCI/EHCI.

- **`USB_QUIRK_NO_AUTOSUSPEND` (маска `0x00400000`, літера `r`):**
  - *Точка перехоплення в ядрі:* функція динамічного енергозбереження `usb_autosuspend_device()`.
  - *Механізм дії:* Повністю забороняє автоматичне динамічне призупинення пристрою під час простою. Запобігає затримкам відновлення та раптовим втратам зв'язку на USB-модемах, адаптерах Bluetooth та сканерах відбитків пальців.

## 2. Прапорці підсистеми USB Mass Storage (`include/linux/usb_usual.h`)

Підсистема зберігання даних оперує прапорцями `US_FL_*` для драйверів `usb-storage` (протокол Bulk-Only Transport) та `uas` (протокол USB Attached SCSI).

### Детальний розбір прапорців накопичувачів

- **`US_FL_SINGLE_LUN` (маска `0x00000001`, літера `s`):**
  - *Призначення:* Примусово обмежує накопичувач нульовим логічним юнітом (LUN 0). Забороняє відправлення керуючого запиту `GET_MAX_LUN`. Багато дешевих кардридерів та флешок при отриманні запиту `GET_MAX_LUN` повертають помилку `STALL` або вигадують наявність 16 неіснуючих дисків, засмічуючи таблицю блочних пристроїв `/dev/sd*`.

- **`US_FL_NEED_OVERRIDE` (маска `0x00000002`, літера `n`):**
  - *Призначення:* Службовий прапорець ядра, який сигналізує про те, що стандартні прапорці класу пристрою повинні бути заміщені параметрами з таблиці незвичних пристроїв `unusual_devs.h`.

- **`US_FL_IGNORE_RESIDUE` (маска `0x00000004`, літера `r`):**
  - *Призначення:* Змушує драйвер ігнорувати поле залишку даних `dCSWDataResidue` у фінальному статусному блоці CSW (Command Status Wrapper). Деякі флеш-накопичувачі успішно записують усі 512 байтів сектора, але помилково повертають ненульове число залишку, що без цього прапорця змушує ядро вважати запис невдалим і повторювати запит безкінечно.

- **`US_FL_FIXED_COMMAND` (маска `0x00000008`, літера `f`):**
  - *Призначення:* Фіксує довжину командного блоку SCSI Command Descriptor Block (CDB) суворо на рівні 10 або 12 байтів. Запобігає використанню коротких 6-байтових команд `READ_6` / `WRITE_6`, на які контролери старих мостів реагують зависанням.

- **`US_FL_MODE_XLATE` (маска `0x00000010`, літера `m`):**
  - *Призначення:* Автоматично перехоплює та транслює запити `MODE_SENSE_6` та `MODE_SELECT_6` у їхні 10-байтові варіанти `MODE_SENSE_10` / `MODE_SELECT_10`. Потрібно для накопичувачів, що не підтримують старий формат заголовка сторінок конфігурації.

- **`US_FL_CAPACITY_HEURISTICS` (маска `0x00000020`, літера `c`):**
  - *Призначення:* Виправляє критичну апаратну ваду визначення ємності носія. За стандартом SCSI команда `READ_CAPACITY` повертає адресу останнього доступного логічного блоку (LBA), тобто на одиницю менше за загальну кількість секторів. Ряд контролерів помилково повертає повну кількість секторів. При спробі ядра прочитати останній сектор диск видавав помилку вводу-виводу. Прапорець змушує ядро зменшити отримане значення на одиницю.

- **`US_FL_NO_READ_DISC_INFO` (маска `0x00000040`, літера `i`):**
  - *Призначення:* Забороняє надсилання специфічної команди `READ_DISC_INFORMATION`, призначеної для оптичних приводів CD/DVD, якщо USB-накопичувач некоректно емулює інтерфейс ATAPI і зависає на цій команді.

- **`US_FL_NO_WP_DETECT` (маска `0x00000080`, літера `w`):**
  - *Призначення:* Вимикає опитування стану апаратного перемикача захисту від запису (Write Protect) через запити `MODE_SENSE`. Запобігає помилковому монтуванню флешок у режимі «лише для читання».

- **`US_FL_IGNORE_UAS` (маска `0x00000100`, літера `u`):**
  - *Призначення:* **Найважливіший прапорець для мостів USB 3.0 / SATA / NVMe.** Забороняє прив'язку високопродуктивного драйвера `uas.ko` (USB Attached SCSI) і примусово перемикає пристрій на суворо послідовний протокол Bulk-Only Transport драйвера `usb-storage.ko`. Застосовується до ненадійних чипів (таких як ASMedia ASM1051, JMicron JMS567), які втрачають пакети під час паралельної обробки черг NCQ або зависають на командах TRIM.

- **`US_FL_BROKEN_FUA` (маска `0x00000200`, літера `b`):**
  - *Призначення:* Вимикає використання біта Force Unit Access (FUA) у командах запису SCSI. Якщо чип не підтримує прямий запис повз кеш накопичувача, ядро емулює цю функціональність через явні виклики команди `SYNCHRONIZE_CACHE`.

- **`US_FL_NO_SAME` (маска `0x00000400`, літера `o`):**
  - *Призначення:* Забороняє використання команд `WRITE_SAME_10` та `WRITE_SAME_16`. Ці команди часто використовуються операційною системою для швидкого заповнення блоків нулями або виконання операції Discard (TRIM) для твердотілих накопичувачів. Несправні контролери при отриманні цієї команди зависають або пошкоджують таблицю трансляції FTL.

- **`US_FL_MAX_SECTORS_64` (маска `0x00000800`, літера `k`):**
  - *Призначення:* Обмежує максимальний розмір одного I/O запиту до 64 секторів (32 КіБ). Захищає внутрішні буфери простих мікросхем від переповнення.

- **`US_FL_MAX_SECTORS_240` (маска `0x00001000`, літера `d`):**
  - *Призначення:* Обмежує максимальний розмір I/O запиту до 240 секторів (120 КіБ). Відповідає максимальній межі передачі старих контролерів паралельного ATA (IDE).

## 3. Табличні структури та реєстрація в ядрі

Зіставлення пристроїв у ядрі описується масивом структур `struct usb_device_id` у файлі `drivers/usb/core/quirks.c`.

### Приклад запису в таблиці `usb_quirk_list[]`:

```c
static const struct usb_device_id usb_quirk_list[] = {
    // Вебкамера Logitech QuickCam Pro 4000: вимагає скидання при пробудженні
    { USB_DEVICE(0x046d, 0x08b2), .driver_info = USB_QUIRK_RESET_RESUME },

```

Макрос `USB_DEVICE(vend, prod)` ініціалізує поля `idVendor` та `idProduct`, встановлюючи маску `match_flags = USB_DEVICE_ID_MATCH_DEVICE`. Поле `.driver_info` зберігає 32-бітну комбінацію прапорців `USB_QUIRK_*`.

У драйвері `usb-storage` таблиця `unusual_devs.h` використовує спеціалізований макрос:

```c
UNUSUAL_DEV( 0x05e3, 0x0702, 0x0000, 0x9999,
        "Genesys Logic",
        "USB to IDE Bridge",
        USB_SC_DEVICE, USB_PR_DEVICE, NULL,
        US_FL_FIXED_COMMAND | US_FL_MODE_XLATE | US_FL_IGNORE_RESIDUE ),
```

Цей макрос реєструє діапазон ревізій прошивки від `0x0000` до `0x9999` для мікросхеми Genesys Logic GL641USB, призначаючи їй комплексний набір виправлень протоколу SCSI.
