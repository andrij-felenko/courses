Коли ми будуємо високопродуктивні хмарні інфраструктури, ми неминуче стикаємося з проблемою накладних витрат на віртуалізацію мережі та сховищ. Традиційні програмні реалізації virtio, такі як vhost-net або vhost-user, забезпечують чудову гнучкість і міграцію між хостами, але споживають значні ресурси процесора (CPU) для обробки кожного пакета. З іншого боку, пряме прокидання апаратних пристроїв через SR-IOV (Single Root I/O Virtualization) дає максимальну продуктивність і мінімальні затримки, але повністю позбавляє нас гнучкості: віртуальна машина стає прив'язаною до конкретного апаратного забезпечення, що унеможливлює живу міграцію (live migration) без розриву з'єднання. Тут на сцену виходить **vDPA (virtio Data Path Acceleration)** — фреймворк, який дозволяє поєднати найкраще з обох світів: апаратну швидкість передачі даних і програмну гнучкість рівня управління.

У цій статті ми глибоко зануримося в архітектуру vDPA, дослідимо, як драйвери шини vDPA інтегруються з ядром Linux, розберемо інтерфейс `/dev/vhost-vdpa`, подивимося на роль SmartNICs та апаратного offload'у virtqueue, а також навчимося користуватися утилітою `vdpa` з пакету iproute2.

## 1. Концепція vDPA: Розділення Data Path та Control Path

Головна ідея vDPA полягає в архітектурному розділенні шляху передачі даних (Data Path) і шляху управління (Control Path). 

У традиційній моделі virtio віртуальна машина спілкується з гіпервізором (або окремим процесом vhost), який емулює поведінку пристрою, обробляє контрольні команди (наприклад, конфігурацію MAC-адреси, черг) та копіює дані між пам'яттю гостя і хоста.

Завдяки vDPA:
- **Control Path (Шлях управління)** залишається програмним. Гіпервізор (наприклад, QEMU) продовжує емулювати стандартний пристрій virtio для гостьової ОС. Гість "бачить" звичайний virtio-net або virtio-blk пристрій. Контрольні повідомлення перехоплюються гіпервізором і транслюються у специфічні команди для апаратного пристрою (SmartNIC) через фреймворк vDPA в ядрі хоста.
- **Data Path (Шлях даних)** стає апаратним. Гість та апаратний пристрій домовляються про формат кільцевих буферів (virtqueues) і розташування пам'яті. Після цього апаратний пристрій (наприклад, DPU або SmartNIC) читає і пише дані безпосередньо у пам'ять гостьової ОС через DMA (Direct Memory Access), минаючи гіпервізор та CPU хоста. Це і називається *hardware virtqueue offload*.

Такий підхід дозволяє зберегти прозорість для гостьової ОС (їй не потрібні специфічні драйвери від виробника "заліза", лише стандартний драйвер virtio) і забезпечити можливість живої міграції.

## 2. Архітектура vDPA в ядрі Linux (vDPA Bus)

Фреймворк vDPA був інтегрований у ядро Linux, починаючи приблизно з версії 5.7. Він побудований навколо концепції **шини vDPA (vDPA bus)**.

Шина vDPA — це абстракція ядра, яка об'єднує апаратні пристрої (vDPA пристрої) та драйвери, які знають, як працювати з цими пристроями (vDPA драйвери).

### 2.1. vDPA Device (vDPA пристрій)

Апаратний пристрій, такий як мережева карта з підтримкою vDPA (SmartNIC), реєструється на шині vDPA за допомогою специфічного драйвера виробника (наприклад, `mlx5_vdpa` для карток Mellanox/Nvidia або `ifcvf` для Intel). Цей драйвер відповідає за трансляцію стандартних команд vDPA в пропрієтарні команди заліза. 

Драйвер пристрою реалізує набір функцій (ops), які дозволяють ядру керувати станом пристрою, налаштовувати переривання, отримувати і встановлювати стан virtqueue тощо.

### 2.2. vDPA Driver (Драйвери шини vDPA)

Над шиною vDPA працюють драйвери, які споживають (використовують) vDPA пристрої. Існує два основні драйвери споживачі:

1. **`vhost-vdpa`**: Цей драйвер створює символьний пристрій у `/dev/vhost-vdpa-X`, який може бути відкритий гіпервізором (QEMU). QEMU використовує цей інтерфейс, щоб налаштувати пристрій для віртуальної машини, передати йому мапу пам'яті гостя (для DMA) і зв'язати віртуальні переривання.
2. **`virtio-vdpa`**: Цей драйвер дозволяє використовувати vDPA пристрій безпосередньо в хост-системі або в контейнерах. Він "перетворює" vDPA пристрій на звичайний локальний virtio пристрій для хост-ядра, дозволяючи використовувати стандартні virtio драйвери (наприклад, virtio_net) безпосередньо на хості, але з апаратним прискоренням від SmartNIC.

## 3. Інтерфейс /dev/vhost-vdpa

Драйвер `vhost-vdpa` відіграє ключову роль у прокиданні пристрою у віртуальну машину. Він виставляє API у просторі користувача через вузли `/dev/vhost-vdpa-N`.

Цей інтерфейс дуже схожий на традиційний `/dev/vhost-net`, і він базується на `ioctl` викликах. Гіпервізор (QEMU) виконує наступні кроки для налаштування пристрою:

1. **Відкриття пристрою**: QEMU відкриває `/dev/vhost-vdpa-N`.
2. **Узгодження фіч (Feature Negotiation)**: QEMU отримує список можливостей (features), які підтримує апаратний пристрій, порівнює їх із тим, що налаштовано для віртуальної машини, і встановлює фінальний узгоджений набір.
3. **Налаштування пам'яті (Memory Mapping)**: QEMU відправляє таблиці сторінок (memory regions) гостя в vhost-vdpa. Драйвер vhost-vdpa, у свою чергу, програмує IOMMU (Input-Output Memory Management Unit), щоб апаратний пристрій міг виконувати безпечний DMA-доступ до пам'яті віртуальної машини, використовуючи гостьові фізичні адреси (GPA).
4. **Налаштування Virtqueue**: QEMU повідомляє апаратному пристрою адреси (GPA) кілець дескрипторів, кілець доступних і використаних буферів (descriptor area, driver area, device area) для кожної черги.
5. **Налаштування переривань (Interrupts / Eventfd)**: QEMU надає файлові дескриптори `eventfd` для сигналізації про нові пакети (kick) та для отримання сповіщень від пристрою про завершення обробки (call).
6. **Запуск (START)**: QEMU відправляє команду на запуск черг. З цього моменту пристрій починає безпосередньо обробляти дані.

## 4. SmartNICs та Hardware Virtqueue Offload

SmartNIC (або DPU/IPU) — це мережева карта з вбудованим процесором, здатна виконувати складні операції з пакетами, знімаючи навантаження з центрального процесора хоста.

Для роботи vDPA, SmartNIC повинен підтримувати **Hardware Virtqueue Offload**. Це означає, що апаратне забезпечення (ASIC або FPGA на мережевій карті) здатне "розуміти" формат структур даних virtio у пам'яті (кільцеві буфери, дескриптори).

Коли мережевий пакет надходить на SmartNIC, він:
1. Аналізується (наприклад, через програмовані конвеєри, такі як eBPF або P4 на DPU).
2. Якщо пакет призначений для віртуальної машини, SmartNIC звертається до `virtqueue` (яка знаходиться в пам'яті віртуальної машини) через PCIe DMA.
3. Копіює пакет у вільний буфер гостьової ОС.
4. Оновлює індекси у `virtqueue`.
5. Генерує переривання (MSI-X), яке через IOMMU/KVM доставляється віртуальній машині як віртуальне переривання.

Увесь цей процес відбувається без участі CPU хоста.

### Жива міграція (Live Migration)

Справжня суперсила vDPA полягає в можливості живої міграції, що було практично неможливо з чистим SR-IOV.

Оскільки QEMU контролює Control Path, під час міграції QEMU може запитати поточний стан пристрою через `/dev/vhost-vdpa`. Важливим елементом є здатність пристрою відстежувати змінені сторінки пам'яті (Dirty Page Tracking), щоб гіпервізор міг синхронізувати пам'ять між хостами. Деякі сучасні SmartNICs підтримують апаратне відстеження dirty pages; для інших vDPA може тимчасово перемикатися на програмний data path (sw-assisted vDPA) на час міграції.

## 5. Утиліта vdpa (iproute2)

У Linux конфігурація та управління пристроями vDPA здійснюється за допомогою інструменту `vdpa`, який входить до складу пакета `iproute2`. Утиліта працює через інтерфейс Netlink.

Ось базові приклади використання `vdpa`:

### 5.1. Перегляд доступних vDPA-сумісних пристроїв управління
```bash
vdpa mgmtdev show
```
Ця команда покаже базові пристрої (наприклад, PCI-функції), якими керують драйвери виробників (як `mlx5_core` або `ifcvf`), і на основі яких можна створювати екземпляри vDPA-пристроїв.

Приклад виводу:
```
vDPA mgmtdev: pci/0000:03:00.2
  supported_classes: net
```

### 5.2. Створення vDPA пристрою
Щоб створити vDPA пристрій (екземпляр), який потім можна передати ВМ, використовується команда `add`:
```bash
vdpa dev add name vdpa0 mgmtdev pci/0000:03:00.2
```
Це створить логічний пристрій `vdpa0` на базі фізичного `0000:03:00.2`.

### 5.3. Перегляд створених пристроїв
```bash
vdpa dev show
```
Вивід:
```
vdpa0: type network mgmtdev pci/0000:03:00.2 vendor_id 5566 max_vqs 3 max_vq_size 256
```

### 5.4. Перевірка конфігурації
```bash
vdpa dev config show
```
Ця команда показує поточну конфігурацію, включаючи MAC-адресу, статус лінка та узгоджені virtio фічі (features).

Коли пристрій `vdpa0` створено, і завантажено модуль `vhost_vdpa`, у системі з'явиться файл `/dev/vhost-vdpa-0`. QEMU може запустити віртуальну машину з цим пристроєм, додавши параметри:
```bash
-netdev vhost-vdpa,vhostdev=/dev/vhost-vdpa-0,id=hostnet0 \
-device virtio-net-pci,netdev=hostnet0,id=net0,mac=52:54:00:11:22:33
```

## Висновки

vDPA (virtio Data Path Acceleration) — це потужна архітектура в ядрі Linux, що кардинально змінює підхід до мережевої продуктивності у хмарних середовищах. Делегуючи обробку черг даних на апаратний рівень (SmartNIC/DPU) та зберігаючи управління на рівні програмного забезпечення (vhost-vdpa/QEMU), vDPA дозволяє досягти "bare-metal" продуктивності без втрати життєво важливих хмарних функцій, таких як абстракція апаратного забезпечення та жива міграція віртуальних машин. Використання утиліти `vdpa` з `iproute2` робить розгортання цих рішень стандартним і зручним для адміністраторів Linux.
