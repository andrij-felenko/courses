# 🔌 Апаратні архітектури контролерів USB Type-C: TCPM, TCPCI та UCSI

Фізичне управління роз'ємом USB Type-C, визначення орієнтації штекера, керування силовими ключами та обробка сигналів протоколу Power Delivery у сучасних комп'ютерних системах реалізуються через три принципово різні апаратні та програмні моделі розподілу обов'язків між операційною системою Linux, контролером порту та прошивкою платформи.

Вибір конкретної апаратно-програмної моделі визначається архітектурою платформи (ARM, RISC-V чи x86), жорсткістю вимог до часу реакції (real-time constraints) та енергоефективністю пристрою у стані глибокого сну.

## Модель A: TCPM + TCPCI (Софтверний автомат у ядрі + проста мікросхема PHY)

У цій архітектурі (типовій для мобільних ARM SoC, промислових контролерів, одноплатних комп'ютерів та розробницьких планок) фізичний контролер порту являє собою відносно просту мікросхему фізичного рівня (Type-C Port Controller, TCPC), яка підключається до системної шини I2C та лінії переривань GPIO.

### Фізична організація та розподіл обов'язків
- **Апаратна частина (TCPCI):** Специфікація USB Type-C Port Controller Interface (TCPCI) визначає стандартизовану карту регістрів I2C (типові мікросхеми: NXP PTN5110, TI TUSB422; ON Semi FUSB302 карті регістрів TCPCI не відповідає й має власний драйвер `fusb302.c`). Мікросхема містить лише аналогові компаратори напруги ліній CC1/CC2, приймач/передавач BMC-пакетів з буфером FIFO, детектор VBUS та ключі живлення VCONN.
- **Програмний автомат (TCPM):** Весь скінченний автомат станів Type-C та Power Delivery (Type-C Port Manager) виконується безпосередньо в ядрі Linux драйвером `drivers/usb/typec/tcpm/tcpm.c`.

```
+-------------------------------------------------------------------+
|                           Ядро Linux                              |
|   +-----------------------------------------------------------+   |
|   |   Type-C Connector Class Core (/sys/class/typec/)         |   |
|   +-----------------------------------------------------------+   |
|                                 ^                                 |
|                                 | (typec_register_port)           |
|   +-----------------------------------------------------------+   |
|   |   TCPM State Machine (drivers/usb/typec/tcpm/tcpm.c)      |   |
|   +-----------------------------------------------------------+   |
|                                 ^                                 |
|                                 | (I2C регістри & GPIO IRQ)       |
+---------------------------------|---------------------------------+
                                  v
+-------------------------------------------------------------------+
|               Апаратний PHY (TCPCI Chip - I2C)                    |
|   +-----------------------------------------------------------+   |
|   |  CC Comparators | BMC Transceiver | VCONN Switches        |   |
|   +-----------------------------------------------------------+   |
+-------------------------------------------------------------------+
```

### Скінченний автомат TCPM (`tcpm.c`)
Драйвер `tcpm.c` реалізує повну діаграму станів специфікацій USB Type-C та USB PD:
1. `SRC_UNATTACHED` / `SNK_UNATTACHED`: Очікування зміни напруги на лініях CC.
2. `SRC_ATTACH_WAIT` / `SNK_ATTACH_WAIT`: Детекція стійкого сигналу протягом часу tCCDebounce (100–200 мс).
3. `SRC_ATTACHED` / `SNK_ATTACHED`: Подача базової напруги 5 В та активація ліній даних.
4. `SNK_DISCOVERY` / `SRC_NEGOTIATE_CAPABILITIES`: Запуск обміну BMC-пакетами PD.

### Переваги та недоліки моделі TCPM/TCPCI
- **Переваги:** Повний прозорий контроль над алгоритмами PD та таймерами з боку ядра Linux; можливість легкого налагодження через `ftrace` / `debugfs` та виправлення помилок специфікації оновленням ядра без перепрошивки мікросхем.
- **Недоліки:** Жорстка залежність від затримок ядра (latency): якщо обробник переривання I2C через високе завантаження ЦПУ не встигне відповісти на PD-пакет у межах таймаутів специфікації (одиниці мілісекунд на підтвердження GoodCRC, десятки — на відповідь партнера), зв'язок PD розірветься. Крім того, для заряджання вимкненої системи потрібний автономний режим у завантажувачі (U-Boot/TF-A).

## Модель B: UCSI (Абстракція прошивки Embedded Controller / ACPI)

Ця модель є стандартом для сучасних x86-ноутбуків та персональних комп'ютерів (Intel, AMD). Фізичним управлінням роз'ємами, розпізнаванням кабелів та обміном пакетами PD займається вбудований контролер платформи (Embedded Controller, EC), який виконує власний скінченний автомат PD повністю незалежно від операційної системи.

### Фізична організація та специфікація UCSI
- **Інтерфейс UCSI:** USB Type-C System Software Interface (UCSI) — це специфікація, розроблена консорціумом Intel, Microsoft та партнерів, яка описує структуру областей пам'яті (Mailbox) та методів ACPI `_DSM` (Device Specific Method).
- **Взаємодія з Linux:** Драйвер ядра `drivers/usb/typec/ucsi/ucsi.c` спирається на транспортний шар ACPI (`ucsi_acpi.c`). Ядро надсилає у прошивку абстрактні команди (наприклад, `UCSI_SET_CBR`, `UCSI_SET_UOR`) і отримує сповіщення про зміну стану через ACPI-переривання (GPE — General Purpose Events).

```
+-------------------------------------------------------------------+
|                           Ядро Linux                              |
|   +-----------------------------------------------------------+   |
|   |   Type-C Connector Class Core (/sys/class/typec/)         |   |
|   +-----------------------------------------------------------+   |
|                                 ^                                 |
|                                 | (typec_register_port)           |
|   +-----------------------------------------------------------+   |
|   |   UCSI Core Driver (drivers/usb/typec/ucsi/ucsi.c)        |   |
|   +-----------------------------------------------------------+   |
|                                 ^                                 |
|                                 | (ACPI _DSM & Mailbox Memory)    |
+---------------------------------|---------------------------------+
                                  v
+-------------------------------------------------------------------+
|             Прошивка платформи (Embedded Controller / EC)         |
|   +-----------------------------------------------------------+   |
|   |  Hardware PD State Machine | Power Delivery Engine        |   |
|   +-----------------------------------------------------------+   |
+-------------------------------------------------------------------+
```

### Переваги та недоліки моделі UCSI
- **Переваги:** Апаратна надійність і повна незалежність від завантаження процесора хоста; процедура заряджання функціонує навіть тоді, коли операційна система повністю зупинена, перебуває у стані сну чи програмного вимкнення (S3/S5) або зазнала аварійного завершення (Kernel Panic).
- **Недоліки:** Модель «чорної скриньки»: якщо у прошивці EC є апаратна або софтверна помилка в обробці специфічних PD-кабелів, драйвер Linux не має змоги втрутитися у процес низькорівневого узгодження та змушений лише фіксувати результат.

## Модель C: Автономні контролери PMIC (Stand-alone PD Controllers)

Деякі роз'єми керуються повністю автономними мікросхемами управління живленням (наприклад, TI TPS6598x, Cypress/Infineon CCG3), які мають власне ПЗУ з конфігураційною прошивкою.

- **Взаємодія з Linux:** Драйвер ядра (`drivers/usb/typec/tps6598x.c`) виступає у ролі віддаленого спостерігача. Він зчитує поточний стан порту через I2C чи SPI та реєструє об'єкт `typec_port` у Connector Class для того, щоб показати стан простору користувача та передавати мікросхемі команди перемикання ролей.

## Зведена порівняльна таблиця апаратних моделей

| Критерій порівняння | Модель TCPM + TCPCI | Модель UCSI (ACPI / EC) | Stand-alone PMIC (TPS6598x) |
| :--- | :--- | :--- | :--- |
| **Де виконується автомат PD?** | У ядрі Linux (`tcpm.c`) | У прошивці EC / BIOS | У внутрішньому ПЗУ мікросхеми |
| **Шина управління** | I2C + GPIO IRQ | ACPI Mailbox / GPE IRQ | I2C / SPI |
| **Залежність від затримок ОС** | Висока (real-time вимоги) | Нульова (автономна апаратура) | Нульова (автономна апаратура) |
| **Гнучкість налаштувань** | Максимальна (код ядра) | Обмежена контрактом UCSI | Обмежена таблицею конфігурації |
| **Заряджання у вимкненому стані** | Потребує коду у завантажувачі | Працює апаратно з коробки | Працює апаратно з коробки |
| **Типове застосування** | ARM SoC (Rockchip, Allwinner) | x86 Ноутбуки (Intel / AMD) | Док-станції, монітори, вбудовані плати |
