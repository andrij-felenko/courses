# 🧮 Зважена справедлива черга: як придатність перетворює ваги на число

Тут пораховано, чому ваги черг у BFQ дають не побажання, а межу: скільки секторів черга може забрати понад свою частку, перш ніж планувальник перестане її обслуговувати. Уся конструкція тримається на одній нерівності — і правило «бери чергу з найменшим строком», саме по собі, цієї межі не дає взагалі.

## Ідеал, проти якого міряють

Ідеального пристрою не буває, але саме проти нього рахують відхилення. Уявімо носій, який обслуговує всі непорожні черги **одночасно**, віддаючи кожній частку своєї миттєвої продуктивності, пропорційну вазі:

```
wᵢ      — вага черги i (у BFQ від 1 до 1000, типово 100)
W       — сума ваг усіх непорожніх черг у цю мить
S(t)    — усього секторів, які пристрій видав від початку
Sᵢ(t)   — скільки з них дісталося черзі i
Sᵢ*(t)  — скільки дістав би ідеал
```

Означення ідеалу — один рядок:

```
dSᵢ* = ( wᵢ / W ) · dS
```

Праворуч стоїть приріст **виданих секторів**, а не приріст часу, і це не дрібниця. Та сама мілісекунда на диску з головкою переносить від кількох кілобайтів до кількох мегабайтів залежно від того, куди довелося їхати. Частка часу тому не обіцяє нічого, частка роботи обіцяє все — тож далі кожне число тут у секторах.

Відхилення черги від ідеалу позначмо `Δᵢ = Sᵢ − Sᵢ*`. Просумувавши по всіх чергах, дістанемо нуль: обидві суми дорівнюють `S(t)`. Отже, випередження однієї черги — це рівно чиєсь відставання, і обмежити перше означає обмежити друге. Той самий закон збереження на процесорному боці виведено в [арифметиці віртуального часу](book:unix-linux/scheduler-model/math-virtual-time.md).

## Два годинники й одна різниця

Системний віртуальний час `V` означують так, щоб належне черзі читалося з нього простим множенням на вагу:

```
dV = dS / W        ⇒        Sᵢ*(t) = wᵢ · V(t)
```

Тобто `V` — це кількість секторів на одиницю ваги, яку ідеал уже роздав.

Черзі, коли вона стає непорожньою, виставляють **віртуальний початок** `startᵢ`. Діставши носій, вона витрачає бюджет `Bᵢ` секторів, і на цей раунд їй лічать **віртуальний строк**:

```
finishᵢ = startᵢ + Bᵢ / wᵢ
```

Наступний раунд починається там, де скінчився попередній. Тому, поки черга не порожніє, її початок телескопується у власну спожиту роботу:

```
startᵢ = Sᵢ / wᵢ
```

Зіставмо два останні висновки — і означення відхилення згортається в різницю двох годинників:

```
Δᵢ = Sᵢ − Sᵢ* = wᵢ · ( startᵢ − V )
```

Черга випереджає ідеал тоді й лише тоді, коли її власний початок правіше за системний час. Умова **придатності** `startᵢ ≤ V` — це буквально «ти ще не забрала наперед», записана двома числами, які й так лежать у вузлі. У коді ядра відповідний рядок такий самий: `entity->finish = entity->start + bfq_delta(service, entity->weight)`, де `bfq_delta` — те саме ділення на вагу, тільки в нерухомій комі зі зсувом на 22 біти.

Черга, яка спорожніла й повернулася, дістає `start ← max(finish, V)`. Якщо системний час утік уперед, накопичений кредит їй не зберігають — інакше процес, що промовчав хвилину, прокидався б із правом забрати весь носій.

## Три черги, три правила

**Умови задачі.** Три черги, усі весь час непорожні, бюджет кожної сталий:

```
A: вага 100, бюджет 512 секторів → віртуальна тривалість раунду 512/100 = 5.12
B: вага 100, бюджет 512 секторів → 5.12
C: вага 200, бюджет 256 секторів → 256/200 = 1.28

W = 400;   ідеальні частки:   A 25 %,   B 25 %,   C 50 %
```

### Карусель ділить за бюджетом, а не за вагою

За повний оберт кожна черга бере рівно свій бюджет:

```
оберт = 512 + 512 + 256 = 1280 секторів
A: 512/1280 = 40 %     B: 40 %     C: 256/1280 = 20 %
```

Найважча черга дістала найменше. Зв'язати бюджет із вагою й на цьому заспокоїтися не вийде: бюджет у BFQ підбирають під поведінку процесу — послідовному читачеві великий, щоб не ганяти головку туди-сюди, розкиданому малий, щоб він не тримав носій даремно. Документація ядра подає цю свободу як перевагу: планувальник вільний обрати для кожної черги той бюджет, що найкраще пасує її потребам. Отже, правило вибору мусить давати правильну частку **за будь-яких бюджетів**.

### Найменший строк без придатності

Правило: бери чергу з найменшим `finish`, більше нічого. На старті всі `start = 0`, і найменший строк у C — бо її бюджет малий. Обслужили, перелічили, знову найменший:

```
раунд 1: C   S=256   V=0.64    C: start 1.28  finish 2.56
раунд 2: C   S=512   V=1.28    C: start 2.56  finish 3.84
раунд 3: C   S=768   V=1.92    C: start 3.84  finish 5.12

після 768 секторів:  C має 768 при ідеалі 384  →  Δ_C = +384
                     A і B — по нулю при ідеалі 192 кожній
```

У довгому пробігу частка вийде правильна: строки не дадуть C бігти вічно. Брехливе тут — **коли**. І межі на це випередження в числах самої C немає. Замінімо A і B на послідовних читачів із бюджетом 4096 секторів (2 МіБ — звичайна стеля для потокового читання):

```
віртуальна тривалість раунду A і B:  4096/100 = 40.96
C виграє, поки її строк менший:      k · 1.28 < 40.96  →  k = 31 раунд поспіль
Δ_C = 31 · 256 · ( 1 − 200/400 ) = 3968 секторів ≈ 1.9 МіБ
```

Випередження зросло вдесятеро, хоча про саму C ніхто нічого не міняв — воно росте з бюджетами **сусідів**. Саме це й мають на увазі, кажучи, що така схема відстає від ідеалу щонайбільше на один раунд, а випереджати може як завгодно.

### Придатність, а вже тоді строк

Правило B-WF2Q+: серед черг із `start ≤ V` бери ту, чий `finish` найменший. Схему придумали для пакетів у мережі — це WF2Q+ Джона Беннета й Хуея Чжана (Jon C. R. Bennett, Hui Zhang, IEEE/ACM Transactions on Networking, том 5, № 5, 1997); BFQ переліковує ті самі часові позначки в сектори, звідки й буква «B» у назві.

![Три черги на осі віртуального часу: у C найменший строк, але її початок правіше за V, тож обслуговують A або B](/reference/unix-linux/devices/io-schedulers/img/wf2q-eligibility.svg)

*Придатність — це перевірка лівого кінця відрізка, строк — правого. Відсіявши тих, хто вже взяв наперед, планувальник вибирає між рештою.*

Ті самі бюджети 512/512/256, крок за кроком:

```
крок  обрано   S     V=S/400   стан після кроку
 —      —       0     0.00     A[0.00→5.12]  B[0.00→5.12]  C[0.00→1.28]
 1      C      256    0.64     C[1.28→2.56]   ← 1.28 > 0.64, C випадає
 2      A      768    1.92     A[5.12→10.24]  ← найменший строк був у C
 3      C     1024    2.56     C[2.56→3.84]
 4      C     1280    3.20     C[3.84→5.12]   ← знову зачекає
 5      B     1792    4.48     B[5.12→10.24]
 6      C     2048    5.12     C[5.12→6.40]
```

Стан на кроці 6 — це початковий стан, зсунутий рівно на 5.12 віртуальної одиниці; далі картина повторюється точка в точку. За один такий оберт у 2048 секторів черги взяли `A: 512`, `B: 512`, `C: 1024` — тобто 25 %, 25 % і 50 %, точно ваги. Відхилення в проміжних точках оберту:

```
S      Δ_A    Δ_B    Δ_C
 256   −64    −64   +128
 768  +320   −192   −128
1024  +256   −256      0
1280  +192   −320   +128
1792   +64    +64   −128
2048     0      0      0
```

Найбільше відхилення за весь оберт — 320 секторів, тобто 160 КіБ. Випередження C не переходить за 128 ніколи, і саме це число не змінилося б, якби бюджети A і B були по 4096: там, де правило без придатності віддало C 3968 секторів наперед, тут лишається 128.

![Відхилення черги C від ідеалу: без придатності крива вибігає до +384, з придатністю тримається в коридорі ±128](/reference/unix-linux/devices/io-schedulers/img/wf2q-deviation.svg)

*Нахили однакові — черга або набирає, або втрачає пів сектора на кожен виданий. Різниця лише в тому, де крива розвертається вниз.*

## Звідки береться стеля

Два кроки, обидва — підстановка вже виписаного.

**Черга починає раунд, не випереджаючи ідеал.** До обслуговування її беруть лише придатною, тобто `startᵢ ≤ V`; підставивши це в `Δᵢ = wᵢ(startᵢ − V)`, маємо `Δᵢ ≤ 0` у мить початку.

**За раунд вона вибігає вперед щонайбільше на свій бюджет за відрахуванням своєї ж частки від нього.** Поки триває раунд, пристрій видає рівно `Bᵢ` секторів і всі вони йдуть черзі `i`; ідеал із цих самих `Bᵢ` дав би їй `(wᵢ/W)·Bᵢ`. Звідси:

```
Δᵢ ≤ Bᵢ · ( 1 − wᵢ / W )

перевірка: Δ_C ≤ 256·(1 − 0.50) = 128   — таблиця дає рівно 128
           Δ_A ≤ 512·(1 − 0.25) = 384   — таблиця дає 320
```

Межу на **відставання** дає закон збереження: чого бракує одній черзі, те решта взяла наперед, тож `−Δᵢ ≤ Σ Bⱼ(1 − wⱼ/W)` по всіх `j ≠ i`. Для B це `384 + 128 = 512` секторів проти справжніх 320 — оцінка груба, бо на своїх стелях усі черги одночасно не бувають. Але вона скінченна, і в ній немає ані часу, ані швидкості носія: просів пристрій — повільніше йде `V`, повільніше йдуть усі черги, частка й межа лишаються ті самі. Документація ядра формулює обіцянку так само: частка пропорційна вазі навіть тоді, коли пропускна здатність коливається.

Лишається щілина: а якщо придатних немає взагалі, бо всі `start` попереду `V`? Тоді носій простоював би через арифметику. Тому, коли жодну чергу не обслуговують, `V` дозволено підтягнути вперед — до найменшого `start` серед непорожніх, після чого хтось стає придатним негайно.

> 🔧 **Навіщо це.** Різниця між «у середньому колись» і «не далі ніж на стільки-то секторів» — це різниця між налаштуванням, у яке віриш, і налаштуванням, яке перевіряєш. Стелю бюджету BFQ підганяє так, щоб один раунд укладався в тайм-аут бюджету; тоді межа в секторах переводиться в час майже дослівно: черга чекає не довше, ніж по одному такому вікну на кожного суперника. Це те, що можна пообіцяти службі під вагою в `io.bfq.weight`.

## Чому це по кишені на кожному запиті

Запит до планувальника один і той самий: **серед черг зі `start ≤ V` знайти найменший `finish`**. Перебором це `O(N)` на кожному виборі, а виборів тут десятки тисяч за секунду — тобто перебір довелося б робити рідше, ніж треба, і межа поповзла б.

BFQ тримає черги в [червоно-чорному дереві](book:algorithms/red-black-tree), впорядкованому за `finish`, і довішує кожному вузлові додатковий ключ `min_start` — найменший `start` у його піддереві. Спуск деревом тоді відсікає цілі гілки: якщо в піддереві `min_start > V`, придатних там немає й заходити нікуди. Виходить `O(log N)` — і саме тому перевірку роблять на кожному виборі, а не раз на кілька. Прийом не новий: дерево з ключем придатності описали ще для EEVDF — «найранішого придатного віртуального строку» Йона Стойки й Хусейна Абдель-Вахаба (Ion Stoica, Hussein Abdel-Wahab, 1995), тієї самої роботи, за якою згодом переписали й клас справедливого планування процесорного часу в Linux. Ідея віртуального часу, доведена до `O(log N)` один раз, обслуговує тепер обидва боки машини.
