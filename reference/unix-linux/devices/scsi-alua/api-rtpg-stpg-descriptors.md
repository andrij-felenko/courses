# 📋 Специфікація команд RTPG/STPG, сенс-кодів та інтерфейсу sysfs ALUA

Механізм асиметричного доступу до логічних пристроїв (ALUA, *Asymmetric Logical Unit Access*) стандартизовано в документах технічного комітету ANSI INCITS T10 — SPC-3 (*SCSI Primary Commands - 3*) та SPC-4. Стандарт визначає структури двійкових дескрипторів для виявлення можливостей масиву, періодичного опитування станів портів і примусового керування цільовими групами портів (TPG, *Target Port Groups*), набір додаткових сенс-кодів помилок SCSI, а також інтерфейси моніторингу та конфігурації в операційній системі Linux.

---

## 1. Поле TPGS у відповіді стандартної команди INQUIRY

Під час початкового виявлення будь-якого блокового SCSI-пристрою ініціатор надсилає стандартну команду `INQUIRY` (код операції `0x12`, довжина виділення за замовчуванням 36 або 96 байтів). Наявність та апаратний тип підтримки ALUA визначаються за вмістом **байта 5**, у бітах 5 та 4 (двобітове поле `TPGS` — *Target Port Group Support*).

Решта бітів байта 5 містять прапорці `ACC` (підтримка Access Controls Coordinator), `ALUA_SUP` та `SCCS` (наявність вбудованого контролера накопичувача).

| Біти 5..4 (TPGS) | Назва режиму | Детальний опис поведінки масиву |
| :--- | :--- | :--- |
| `00b` | **ALUA не підтримується** | Масив є повністю симетричним (*Active-Active Symmetric*) або використовує застарілі вендорні команди перемикання (наприклад, EMC Trespass чи LSI RDAC). |
| `01b` | **Лише неявний ALUA (Implicit only)** | Сховище змінює стани TPG автономно на основі власної кластерної логіки. Спроба хоста надіслати команду `SET TARGET PORT GROUPS` повертає статус `CHECK CONDITION` із сенс-кодом `ILLEGAL REQUEST / INVALID FIELD IN CDB`. |
| `10b` | **Лише явний ALUA (Explicit only)** | Сховище ніколи не перемикає стани портів самостійно. Зміна стану відбувається виключно за явною командою `SET TARGET PORT GROUPS` від ініціатора. |
| `11b` | **Змішаний ALUA (Both Implicit & Explicit)** | Сховище підтримує обидва режими: воно здатне автономно змінювати стани при внутрішніх відмовах і водночас приймає команди примусового перемикання від хоста. |

Якщо ініціатор виявляє значення `00b`, ядро Linux не підключає спеціалізований модуль `scsi_dh_alua`, і пристрій обслуговується базовим драйвером без створення асиметричних груп пріоритетів.

## 2. Ідентифікація TPG у сторінці життєво важливих даних (VPD Page 0x83)

Для однозначного зв'язування конкретного шляху (пристрою `/dev/sdX`) із відповідною цільовою групою портів дискового масиву ініціатор запитує сторінку життєво важливих даних продукту `0x83` (*Device Identification Vital Product Data*). Масив повертає список дескрипторів ідентифікації, серед яких критично важливими для багатошляховості є два типи записів.

### Дескриптор відносного ідентифікатора порту (Relative Target Port Identifier)
Запис ідентифікує конкретний фізичний або логічний порт контролера, через який надійшов запит:
- **Protocol Identifier (Байт 0, біти 7..4)**: ідентифікатор протоколу канального рівня (наприклад, `0x0` для Fibre Channel, `0x5` для iSCSI, `0x6` для SAS, `0x8` для SRP/RDMA).
- **Code Set (Байт 0, біти 3..0)**: `0x1` (двійковий формат даних).
- **Association (Байт 1, біти 5..4)**: `01b` (ідентифікатор належить цільовому порту, а не логічному тому).
- **Identifier Type (Байт 1, біти 3..0)**: `0x4` (*Relative Target Port Identifier*).
- **Identifier Length (Байт 3)**: `0x04` (довжина тіла ідентифікатора 4 байти).
- **Data (Байти 4..7)**: перші два байти зарезервовані (`0x0000`), а байти 6..7 містять 16-бітне ціле число в порядку *big-endian* — **відносний номер порту цілі** (*Relative Target Port ID*, `0x0001`..`0xFFFF`).

### Дескриптор цільової групи портів (Target Port Group Descriptor)
Запис пов'язує цей порт із групою спільного стану ALUA:
- **Association (Байт 1, біти 5..4)**: `01b` (*Target Port*).
- **Identifier Type (Байт 1, біти 3..0)**: `0x5` (*Target Port Group*).
- **Identifier Length (Байт 3)**: `0x04`.
- **Data (Байти 4..7)**: байти 4..5 зарезервовані (`0x0000`), байти 6..7 містять 16-бітне ціле число — **ідентифікатор цільової групи портів** (*Target Port Group ID*, TPG ID).

## 3. Команда REPORT TARGET PORT GROUPS (RTPG)

Команда RTPG використовується хостом для запиту актуальної карти станів усіх цільових груп портів, призначених для цього логічного тому.

### Блок дескриптора команди (CDB, 16 байтів)

У стандарті SPC-3/SPC-4 команда належить до сімейства команд керування та діагностики `MAINTENANCE IN`:

```
+───────+──────────────────────────────────────────────────────────────────+
| Байт  | Вміст поля                                                       |
+───────+──────────────────────────────────────────────────────────────────+
| 0     | Код операції: 0xA3 (MAINTENANCE IN)                              |
| 1     | Бити 7..5 = Зарезервовано; Бити 4..0 = 0x0A (Service Action: RTPG)|
| 2..5  | Зарезервовано (0x00000000)                                       |
| 6..9  | ALLOCATION LENGTH (Довжина буфера хоста, uint32 big-endian)     |
| 10    | Зарезервовано (0x00)                                             |
| 11    | CONTROL (Керуючий байт: 0x00)                                    |
| 12..15| Зарезервовано (0x00000000)                                       |
+───────+──────────────────────────────────────────────────────────────────+
```

У специфікації SPC-4 також передбачено розширений варіант команди з Service Action `0x0B` (*Extended RTPG*), який повертає додаткові поля очікуваного часу переходу (*Transition Timeout*) та рекомендованого інтервалу між опитуваннями.

### Формат даних параметра відповіді RTPG

Відповідь масиву складається з 4-байтового заголовка та неперервного ланцюжка дескрипторів груп TPG. Кожен дескриптор TPG має змінну довжину `8 + (k × 4)` байтів, де `k` — кількість цільових портів, закріплених за цією групою.

```
+──────────────────────────────────────────────────────────────────────────+
| Байти 0..3: RETURN DATA LENGTH (Загальний розмір наступних дескрипторів) |
+──────────────────────────────────────────────────────────────────────────+
| Дескриптор TPG #1 (довжина 8 + k1 * 4 байтів):                           |
|   Байт 0:   Бит 7 = PREF; Бити 3..0 = Asymmetric Access State            |
|   Байт 1:   Маска підтримуваних станів (AO_SUP, ANO_SUP, SB_SUP тощо)    |
|   Байти 2..3: Target Port Group Identifier (TPG ID, uint16 BE)           |
|   Байт 4:   Status Code (причина зміни стану)                            |
|   Байт 5:   Vendor Specific                                              |
|   Байти 6..7: Target Port Count (k1, uint16 BE)                          |
|   Байти 8..8+k1*4-1: Список дескрипторів цільових портів (Relative IDs)  |
+──────────────────────────────────────────────────────────────────────────+
| Дескриптор TPG #2 (довжина 8 + k2 * 4 байтів)...                         |
+──────────────────────────────────────────────────────────────────────────+
```

### Деталізація полів дескриптора TPG

| Зміщення | Поле | Розмір / Тип | Детальний опис призначення |
| :--- | :--- | :--- | :--- |
| `Байт 0, біт 7` | **PREF** | 1 біт | *Preferred Target Port Group*. Встановлюється виробником масиву в `1`, якщо ця група портів є апаратно бажаною для обслуговування LUN. Хост віддає перевагу шляхам з `PREF=1`. |
| `Байт 0, біти 3..0`| **Access State** | 4 біти | Поточний стан доступу:<br>`0x0` = Active/Optimized (AO)<br>`0x1` = Active/Non-Optimized (ANO)<br>`0x2` = Standby (SB)<br>`0x3` = Unavailable (UN)<br>`0xE` = Standby Offline<br>`0xF` = Transitioning (TO) |
| `Байт 1` | **Supported States**| 8 бітів | Бітова маска допустимих переходів для цієї групи:<br>Бит 0 (`0x01`): AO_SUP (підтримується перехід в Active/Optimized)<br>Бит 1 (`0x02`): ANO_SUP (підтримується Active/Non-Optimized)<br>Бит 2 (`0x04`): SB_SUP (підтримується Standby)<br>Бит 3 (`0x08`): UN_SUP (підтримується Unavailable)<br>Бит 7 (`0x80`): T_SUP (підтримується стан Transitioning) |
| `Байти 2..3` | **TPG ID** | uint16 BE | Унікальний числовий номер цільової групи портів (`0x0001`..`0xFFFF`). |
| `Байт 4` | **Status Code** | 8 бітів | Причина встановлення поточного стану:<br>`0x00` = Штатний стан без попередніх помилок<br>`0x01` = Стан змінено за явною командою хоста STPG<br>`0x02` = Стан змінено внутрішньою логікою дискового масиву (Implicit) |
| `Байт 5` | **Vendor Specific** | 8 бітів | Зарезервовано для внутрішніх діагностичних прапорців виробника. |
| `Байти 6..7` | **Port Count (`k`)**| uint16 BE | Кількість портів цілі, що входять до цієї TPG. |
| `Байти 8..` | **Port List** | `k × 4` байти | Список записів: перші 2 байти зарезервовані (`0x0000`), наступні 2 байти містять відносний номер порту (*Relative Target Port Identifier*). |

## 4. Команда SET TARGET PORT GROUPS (STPG)

Команда STPG надсилається хостом для примусового переведення цільової групи портів у новий стан (Explicit ALUA).

### Блок дескриптора команди (CDB, 16 байтів)

Команда належить до сімейства `MAINTENANCE OUT`:

```
+───────+──────────────────────────────────────────────────────────────────+
| Байт  | Вміст поля                                                       |
+───────+──────────────────────────────────────────────────────────────────+
| 0     | Код операції: 0xA4 (MAINTENANCE OUT)                             |
| 1     | Бити 7..5 = Зарезервовано; Бити 4..0 = 0x0A (Service Action: STPG)|
| 2..5  | Зарезервовано (0x00000000)                                       |
| 6..9  | PARAMETER LIST LENGTH (Довжина тіла параметрів, uint32 BE)       |
| 10    | Зарезервовано (0x00)                                             |
| 11    | CONTROL (0x00)                                                   |
| 12..15| Зарезервовано (0x00000000)                                       |
+───────+──────────────────────────────────────────────────────────────────+
```

### Формат списку параметрів STPG

Хост передає масиву список дескрипторів із запитуваними новими станами:

```
+──────────────────────────────────────────────────────────────────────────+
| Байти 0..3: PARAMETER DATA LENGTH (uint32 BE, значення = 4 + N * 4)      |
+──────────────────────────────────────────────────────────────────────────+
| Дескриптор запиту TPG #1 (4 байти):                                      |
|   Байт 0:   Бити 3..0 = Запитуваний стан (0x0=AO, 0x1=ANO, 0x2=SB)       |
|   Байт 1:   Зарезервовано (0x00)                                         |
|   Байти 2..3: Target Port Group ID (uint16 BE)                           |
+──────────────────────────────────────────────────────────────────────────+
| Дескриптор запиту TPG #2 (4 байти)...                                    |
+──────────────────────────────────────────────────────────────────────────+
```

Якщо дисковий масив не підтримує переведення групи в запитуваний стан (відповідний біт у масці `Supported States` дорівнює нулю), команда STPG завершується помилкою зі статусом `CHECK CONDITION` та кодом `ILLEGAL REQUEST / INVALID FIELD IN PARAMETER LIST`.

## 5. Таблиця кодів SCSI Sense, пов'язаних з ALUA

Під час функціонування асиметричного сховища команди вводу-виводу або команди керування можуть повертати статус `CHECK CONDITION`. Драйвер ядра Linux декодує сенс-дані за такими ключовими комбінаціями:

| Sense Key | ASC / ASCQ | Стандартна назва помилки | Пояснення та реакція підсистеми ядра Linux |
| :--- | :--- | :--- | :--- |
| `02h` (*NOT READY*) | `04h / 0Ah` | `LOGICAL UNIT NOT READY, TARGET PORT IN RAPID TRANSITION` | Масив перебуває у стані міграції кешу та зміни власника LUN. Драйвер `scsi_dh_alua` не передає помилку вгору, а затримує запит на 200 мс і повторює спробу. |
| `02h` (*NOT READY*) | `04h / 0Bh` | `LOGICAL UNIT NOT READY, TARGET PORT IN ASYMMETRIC ACCESS STATE CHANGE` | Відбувається планова реконфігурація цільових груп портів. Запит утримується в черзі. |
| `02h` (*NOT READY*) | `04h / 0Ch` | `LOGICAL UNIT NOT ACCESSIBLE, TARGET PORT IN STANDBY STATE` | Порт перебуває в пасивному резерві. Звичайний ввід-вивід відхиляється. Ядро ініціює виклик STPG або перемикає активний покажчик групи на іншу TPG. |
| `02h` (*NOT READY*) | `04h / 0Dh` | `LOGICAL UNIT NOT ACCESSIBLE, TARGET PORT IN UNAVAILABLE STATE` | Цільовий порт втратив зв'язок із дисковим пулом. Шлях позначається як аварійний (*failed*). |
| `06h` (*UNIT ATTENTION*) | `2Ah / 06h` | `ASYMMETRIC ACCESS STATE CHANGED` | Дисковий масив автономно змінив стан TPG (неявний ALUA). Модуль `scsi_dh_alua` негайно ставить у системну чергу виклик команди RTPG для оновлення топології. |
| `06h` (*UNIT ATTENTION*) | `2Ah / 07h` | `IMPLICIT ASYMMETRIC ACCESS STATE TRANSITION FAILED` | Спроба масиву самостійно перемкнути власника завершилася аварією. Ядро фіксує критичну помилку в системному журналі `dmesg`. |
| `05h` (*ILLEGAL REQUEST*) | `25h / 00h` | `LOGICAL UNIT NOT SUPPORTED` | LUN не налаштований або видалений на цьому порту контролера. |

Особливе місце посідає сенс-код `06h/2Ah/06h`: коли ініціатор отримує його у відповідь на будь-яку звичайну команду читання чи запису, ядро не перериває виконання операції з помилкою. Запит повторюється на іншому доступному шляху, а паралельний потік ядра запускає оновлення карти пріоритетів.

## 6. Інтерфейс ядра Linux sysfs

Підсистема ядра `scsi_dh_alua` експортує повний стан ALUA для кожного виявленого блокового SCSI-диска у віртуальну файлову систему `sysfs` за шляхом `/sys/class/scsi_disk/<H:C:T:L>/device/`:

```
/sys/class/scsi_disk/<H:C:T:L>/device/
├── alua_access_state    # Поточний стан доступу: "optimized", "non-optimized", "standby", "unavailable", "transitioning"
├── alua_access_type     # Підтримуваний тип переходів: "implicit", "explicit", "both", "none"
├── alua_tpg_id          # Десятковий ідентифікатор цільової групи портів (TPG ID)
├── alua_transition_tmo  # Тайм-аут очікування переходу зі стану Transitioning у секундах (за замовчуванням 60)
├── alua_pref            # Ознака Preferred (1 або 0)
└── dh_state             # Стан підключеного обробника: "attached" (scsi_dh_alua) або "detached"
```

Приклад читання та перевірки параметрів у терміналі:

```sh
# Зчитування поточного стану доступу
$ cat /sys/class/scsi_disk/2:0:0:0/device/alua_access_state
optimized

# Перевірка ідентифікатора групи портів
$ cat /sys/class/scsi_disk/2:0:0:0/device/alua_tpg_id
1

# Перевірка ознаки бажаного контролера (Preferred)
$ cat /sys/class/scsi_disk/2:0:0:0/device/alua_pref
1
```

Користувач може вручну змінити тайм-аут переходу через `sysfs`, записавши нове значення в секундах: `echo 120 > /sys/class/scsi_disk/2:0:0:0/device/alua_transition_tmo`. Це дозволяє уникнути передчасного скидання шляхів під час тривалого скидання кешу масивів надвеликої ємності.

## 7. Налаштування ALUA у конфігурації LIO Target (configfs)

Під час створення власного програмного дискового масиву за допомогою підсистеми ядра Linux LIO Target (`targetcli` / `configfs`), групи ALUA налаштовуються у дереві `/sys/kernel/config/target/core/`:

```sh
# Створення групи портів цілі TPG 1 для бекенду iblock
mkdir -p /sys/kernel/config/target/core/iblock_0/lun_0/alua/tpg_1

# Встановлення типу доступу: Active/Optimized (значення 0)
echo 0 > /sys/kernel/config/target/core/iblock_0/lun_0/alua/tpg_1/alua_access_state

# Встановлення біта Preferred
echo 1 > /sys/kernel/config/target/core/iblock_0/lun_0/alua/tpg_1/alua_pref

# Встановлення штучної затримки для стану Non-Optimized (у мілісекундах)
echo 100 > /sys/kernel/config/target/core/iblock_0/lun_0/alua/tpg_1/nonop_delay_msecs

# Встановлення затримки переходу стану Transitioning (у мілісекундах)
echo 500 > /sys/kernel/config/target/core/iblock_0/lun_0/alua/tpg_1/trans_delay_msecs
```

Ці параметри дозволяють емулювати поведінку комерційного асиметричного сховища безпосередньо у тестових стендах та віртуальних лабораторіях.

## 8. Директиви налаштування в multipath.conf

Для забезпечення безвідмовного функціонування ALUA демон `multipathd` використовує такі ключові директиви конфігураційного файла `/etc/multipath.conf`:

```
defaults {
    # Групування шляхів за пріоритетом станів ALUA
    path_grouping_policy    group_by_prio

    # Модуль обчислення пріоритету: зчитування RTPG через scsi_dh або прямий SG_IO
    prio                    "alua"
    prio_args               "exclusive_pref"

    # Драйвер обробника апаратних переходів ALUA в ядрі
    hardware_handler        "1 alua"

    # Метод періодичної перевірки стану шляху командою TEST UNIT READY
    path_checker            tur

    # Поведінка при зникненні всіх шляхів: утримувати запити в черзі
    no_path_retry           queue

    # Негайне повернення на оптимальний шлях після відновлення первинного контролера
    failback                immediate
}
```

Використання аргументу `exclusive_pref` у директиві `prio_args` вказує плагіну `prio_alua` присвоювати найвищий пріоритет виключно тій групі портів, яка має одночасно стан Active/Optimized і виставлений прапорець `PREF=1`. Це запобігає виникненню конкурентних конфліктів у складних гетерогенних SAN-мережах.
