# 📋 Статуси, сенс-коди й CDB: числа SCSI на одну сторінку

Довідка з чисел, які пристрій повертає, а ядро друкує в журнал: байт стану, шістнадцять сенс-ключів, обидві розкладки сенс-даних, найчастіші пари ASC/ASCQ, довжини CDB і байтові карти команд, що ходять до диска щодня. Значення звірено з переліком T10 і заголовками ядра Linux, тож їх можна брати й підставляти, не перепитуючи.

## Байт стану

Число, яким закінчується кожна команда.

| Значення | Назва | Що означає |
|---|---|---|
| `0x00` | GOOD | виконано |
| `0x02` | CHECK CONDITION | не виконано; причина — в сенс-даних |
| `0x04` | CONDITION MET | умову пошуку задоволено (`PRE-FETCH`, старі `SEARCH`) |
| `0x08` | BUSY | пристрій зайнятий цілком, спробуйте пізніше |
| `0x10` | INTERMEDIATE | застаріле (зв'язані команди) |
| `0x14` | INTERMEDIATE-CONDITION MET | застаріле |
| `0x18` | RESERVATION CONFLICT | пристрій зарезервовано іншим ініціатором |
| `0x22` | COMMAND TERMINATED | застаріле |
| `0x28` | TASK SET FULL | черга саме цієї логічної одиниці переповнена |
| `0x30` | ACA ACTIVE | діє блокування після помилки, нові команди не приймаються |
| `0x40` | TASK ABORTED | команду зняв інший ініціатор |

Усі значення парні не випадково: у SCSI-2 код стану лежав у бітах 5–1, а нульовий біт був зарезервований. Звідси й давня пастка Linux — до ядра 5.14 макрос `status_byte()` віддавав `(result >> 1) & 0x7f`, тому в старому коді й старих обговореннях `CHECK CONDITION` трапляється як `0x01`. Починаючи з 5.14 зсуву немає: статус лежить у молодшому байті `cmd->result` як є, байт хоста — у бітах 16–23, а байт драйвера (`driverbyte=DRIVER_SENSE` у старих журналах) прибрано зовсім.

## Шістнадцять сенс-ключів

Молодші чотири біти — увесь простір класів рішення.

| Ключ | Назва | Коли |
|---|---|---|
| `0x0` | NO SENSE | окремої причини немає; на стрічці так позначають мітку файлу чи кінець носія |
| `0x1` | RECOVERED ERROR | вдалося, але з виправленням; статус усе одно `CHECK CONDITION` |
| `0x2` | NOT READY | справний, але поки не готовий |
| `0x3` | MEDIUM ERROR | не читається чи не пишеться сам носій |
| `0x4` | HARDWARE ERROR | зламалося залізо пристрою |
| `0x5` | ILLEGAL REQUEST | команда невідома або поле в ній неприпустиме |
| `0x6` | UNIT ATTENTION | пристрій змінився й нав'язує новину |
| `0x7` | DATA PROTECT | запис заборонено |
| `0x8` | BLANK CHECK | несподівано порожня ділянка (стрічка, оптика) |
| `0x9` | VENDOR SPECIFIC | на розсуд виробника |
| `0xA` | COPY ABORTED | зірвано `EXTENDED COPY` |
| `0xB` | ABORTED COMMAND | команду зірвано на півдорозі, повтор має сенс |
| `0xC` | — | застаріле (колись EQUAL для команд пошуку) |
| `0xD` | VOLUME OVERFLOW | дані не вмістилися на носій |
| `0xE` | MISCOMPARE | звірка `VERIFY` чи `COMPARE AND WRITE` не збіглася |
| `0xF` | COMPLETED | команда завершилась, і сенс-дані несуть звіт про неї, а не помилку |

Останній ключ найменш очевидний і водночас найпомітніший у Linux: саме `0xF` віддає шар трансляції ATA, коли просили повернути регістри диска — і кладе їх в описувач типу `0x09`.

## Фіксований формат: коди відповіді `0x70` і `0x71`

`0x70` — «це про останню команду», `0x71` — «це про давнішу, яку я вже підтвердив» (типово про запис, що осів у кеші й потім не ліг на носій).

```
байт 0      біт 7 VALID · біти 6–0 код відповіді (70h / 71h)
байт 1      застаріле (номер сегмента)
байт 2      біт 7 FILEMARK · біт 6 EOM · біт 5 ILI · біт 4 SDAT_OVFL · біти 3–0 сенс-ключ
байти 3–6   ІНФОРМАЦІЯ — для дискового пристрою номер збійного блока; дійсна лише при VALID=1
байт 7      довжина решти, n−7 (типово 0x0A, тобто всього 18 байтів)
байти 8–11  інформація, специфічна для команди
байт 12     ASC
байт 13     ASCQ
байт 14     код замінного вузла (FRU); 0 — не повідомлено
байти 15–17 біт 7 байта 15 SKSV · далі 23 біти, зміст яких залежить від ключа
байти 18+   додаткові байти виробника
```

Вроджена межа формату — чотирибайтове поле «інформація»: понад 4 294 967 295 блоків номер збійного місця вже не вміщується. Ядро тримає під сенс-дані буфер на 96 байтів, хоч стандарт дозволяє до 252.

Три байти після `SKSV` економлять окремий обмін, коли їх уміють читати:

| Ключ | Що в байтах 15–17 |
|---|---|
| ILLEGAL REQUEST | біт 6 байта 15: `1` — винен CDB, `0` — список параметрів; байти 16–17 — номер винного байта, біти 2–0 байта 15 — номер біта |
| NOT READY, і не тільки | байти 16–17 — поступ як частка від 65536 (наприклад форматування на 50 % дасть `0x8000`) |
| RECOVERED / MEDIUM ERROR | байти 16–17 — скільки разів пристрій перепробував |

## Описовий формат: `0x72` і `0x73`

Той самий поділ на поточне й відкладене, але замість жорсткої розкладки — список описувачів, і номер блока в ньому вже восьмибайтовий.

```
байт 0      код відповіді (72h / 73h)
байт 1      біти 3–0 сенс-ключ
байт 2      ASC
байт 3      ASCQ
байти 4–6   зарезервовано (біт 7 байта 4 — SDAT_OVFL)
байт 7      сумарна довжина всіх описувачів, n−7
байти 8+    описувачі поспіль, кожен: [тип][довжина решти][дані…]
```

| Тип | Описувач |
|---|---|
| `0x00` | інформація (номер блока) |
| `0x01` | інформація, специфічна для команди |
| `0x02` | залежне від сенс-ключа (те саме, що байти 15–17 фіксованого) |
| `0x03` | код замінного вузла |
| `0x04` | команди стрічки |
| `0x05` | команди блокового пристрою |
| `0x06`–`0x08` | об'єктне сховище (OSD) |
| `0x09` | повернені регістри ATA |
| `0x0A` | ще один показник поступу |
| `0x0B` | переадресація сегмента даних |
| `0x0C` | переслані чужі сенс-дані |
| `0x0D` | блоковий пристрій прямого доступу |
| `0x0E` | позначення пристрою |
| `0x0F` | активація мікрокоду |
| `0x80`–`0xFF` | на розсуд виробника |

Найпотрібніший — нульовий, і його розкладку варто знати напам'ять:

```
байт 0      00h — тип «інформація»
байт 1      0Ah — довжина решти
байт 2      біт 7 VALID
байт 3      зарезервовано
байти 4–11  номер блока, 64 біти, старший байт перший
```

## Найчастіші пари ASC/ASCQ

Тексти — офіційні, з переліку T10; праворуч те, що з цього випливає.

| ASC/ASCQ | Офіційний текст | Що робити |
|---|---|---|
| `00/00` | NO ADDITIONAL SENSE INFORMATION | нічого; звіт порожній |
| `04/01` | LOGICAL UNIT IS IN PROCESS OF BECOMING READY | зачекати й повторити: розкручується, збирається |
| `04/02` | LOGICAL UNIT NOT READY, INITIALIZING COMMAND REQUIRED | розбудити `START STOP UNIT` |
| `04/03` | LOGICAL UNIT NOT READY, MANUAL INTERVENTION REQUIRED | сам не оживе |
| `04/04` | LOGICAL UNIT NOT READY, FORMAT IN PROGRESS | іде форматування; поступ — у полі `SKSV` |
| `04/0B` | LOGICAL UNIT NOT ACCESSIBLE, TARGET PORT IN STANDBY STATE | шлях є, але не активний |
| `04/0C` | LOGICAL UNIT NOT ACCESSIBLE, TARGET PORT IN UNAVAILABLE STATE | шлях непридатний |
| `0C/00` | WRITE ERROR | запис не ліг |
| `10/00` | ID CRC OR ECC ERROR | збій контрольної суми захисту даних |
| `11/00` | UNRECOVERED READ ERROR | блок утрачено; повторювати марно |
| `11/04` | UNRECOVERED READ ERROR - AUTO REALLOCATE FAILED | те саме, і підмінити блок резервним не вдалося |
| `1A/00` | PARAMETER LIST LENGTH ERROR | довжина списку параметрів не та |
| `20/00` | INVALID COMMAND OPERATION CODE | пристрій не знає такої команди |
| `21/00` | LOGICAL BLOCK ADDRESS OUT OF RANGE | блок за межами носія |
| `24/00` | INVALID FIELD IN CDB | винний байт назве `SKSV` |
| `25/00` | LOGICAL UNIT NOT SUPPORTED | такої логічної одиниці немає |
| `26/00` | INVALID FIELD IN PARAMETER LIST | помилка не в CDB, а в переданих даних |
| `27/00` | WRITE PROTECTED | запис заборонено |
| `28/00` | NOT READY TO READY CHANGE, MEDIUM MAY HAVE CHANGED | носій підмінили |
| `29/00` | POWER ON, RESET, OR BUS DEVICE RESET OCCURRED | пристрій перезапустився |
| `29/01`–`29/04` | POWER ON OCCURRED · SCSI BUS RESET OCCURRED · BUS DEVICE RESET FUNCTION OCCURRED · DEVICE INTERNAL RESET | те саме з уточненням причини |
| `2A/01` | MODE PARAMETERS CHANGED | налаштування пристрою змінив хтось інший |
| `2A/06` | ASYMMETRIC ACCESS STATE CHANGED | масив перемкнув шляхи |
| `2A/09` | CAPACITY DATA HAS CHANGED | перепитати місткість |
| `3A/00` | MEDIUM NOT PRESENT | кишеня порожня |
| `3E/03` | LOGICAL UNIT FAILED SELF-TEST | самоперевірка провалилася |
| `3F/03` | INQUIRY DATA HAS CHANGED | пристрій відрекомендується інакше |
| `3F/0E` | REPORTED LUNS DATA HAS CHANGED | перечитати перелік логічних одиниць |
| `44/00` | INTERNAL TARGET FAILURE | внутрішня поломка цілі |
| `47/00` | SCSI PARITY ERROR | побилися байти на дроті |
| `4B/00` | DATA PHASE ERROR | збій під час передавання даних |
| `55/03` | INSUFFICIENT RESOURCES | забракло місця чи внутрішніх структур |
| `5D/00` | FAILURE PREDICTION THRESHOLD EXCEEDED | SMART попереджає про близький кінець |

Пари `04/0B`, `04/0C` і `2A/06` — це мова, якою масив керує [багатошляховістю](book:unix-linux/dm-multipath): іншого способу повідомити про перемикання шляху в нього немає.

## Довжина CDB

Група — старші три біти коду операції; вона й задає, скільки байтів читати з дроту. Ядро рахує це одним рядком: `scsi_command_size_tbl[(opcode >> 5) & 7]`.

| Група | Коди операцій | Стандарт | Таблиця Linux |
|---|---|---|---|
| 0 | `00h`–`1Fh` | 6 | 6 |
| 1 | `20h`–`3Fh` | 10 | 10 |
| 2 | `40h`–`5Fh` | 10 | 10 |
| 3 | `60h`–`7Fh` | зарезервовано | 12 |
| 4 | `80h`–`9Fh` | 16 | 16 |
| 5 | `A0h`–`BFh` | 12 | 12 |
| 6 | `C0h`–`DFh` | на розсуд виробника | 10 |
| 7 | `E0h`–`FFh` | на розсуд виробника | 10 |

Дві клітинки в третьому стовпчику варто читати як здогад: для груп виробника ядро припускає десять байтів, бо мусить щось припустити. Жорсткість групи обходять кодом `7Fh` — CDB змінної довжини, де байт 7 несе довжину додаткової частини, повний розмір дорівнює цьому числу плюс вісім, а справжню команду називають два байти службової дії.

Останній байт **кожного** CDB — керуючий: біти 7–6 на розсуд виробника, біт 2 — `NACA` (чи вмикати блокування після помилки), біти 1–0 застарілі. У переважній більшості випадків він нульовий.

## Байтові карти команд

**`TEST UNIT READY` (`00h`, 6 байтів)** — байт 0 і п'ять нулів; єдина корисна відповідь — сам статус. Це найдешевший спосіб спитати «ти живий і готовий».

**`REQUEST SENSE` (`03h`, 6 байтів)**

```
байт 0   03h
байт 1   біт 0 DESC — просимо описовий формат замість фіксованого
байти 2–3  зарезервовано
байт 4   довжина буфера відповіді (типово 252 або 18)
байт 5   керуючий байт
```

**`INQUIRY` (`12h`, 6 байтів)**

```
байт 0    12h
байт 1    біт 0 EVPD — питаємо не візитівку, а сторінку життєвих даних
байт 2    номер сторінки (діє лише при EVPD=1)
байти 3–4 довжина буфера, 16 біт
байт 5    керуючий байт
```

Стандартна відповідь: байт 0 — тип пристрою (біти 4–0) і кваліфікатор (7–5), біт 7 байта 1 — знімний носій, байт 2 — версія стандарту, байт 4 — довжина решти, байти 8–15 — виробник, 16–31 — виріб, 32–35 — версія прошивки. Сторінки при `EVPD=1`: `00h` — перелік доступних, `80h` — серійний номер, `83h` — стійкі позначення пристрою, `B0h` — межі одного запиту, `B1h` — характеристики носія (звідси ядро бере обертовість), `B2h` — розріджене виділення.

**`READ(10)` (`28h`) і `WRITE(10)` (`2Ah`), 10 байтів**

```
байт 0     28h або 2Ah
байт 1     біти 7–5 RDPROTECT/WRPROTECT · біт 4 DPO · біт 3 FUA · біт 2 RARC · біти 1–0 застаріле
байти 2–5  номер першого блока, 32 біти
байт 6     біти 5–0 номер групи для обліку
байти 7–8  скільки блоків, 16 біт; нуль означає «нічого не переносити»
байт 9     керуючий байт
```

`FUA` вимагає, щоб запис не спинявся в кеші, а читання прийшло з носія; `DPO` каже не тримати ці блоки в кеші після операції. Поля `RDPROTECT`/`WRPROTECT` вмикають наскрізний захист даних — те, чим оперує [профіль цілісності блокового рівня](book:unix-linux/block-integrity-profile).

**`READ(16)` (`88h`) і `WRITE(16)` (`8Ah`), 16 байтів** — ті самі прапорці в байті 1, але номер блока займає байти 2–9 (64 біти), кількість блоків — байти 10–13 (32 біти), номер групи — біти 5–0 байта 14, керуючий байт — 15-й. Ядро переходить на шістнадцятибайтову форму, коли номер блока перестає вміщуватися в чотири байти.

**`READ CAPACITY(10)` (`25h`, 10 байтів)** — байт 0, далі нулі, байт 9 керуючий. Відповідь — вісім байтів: байти 0–3 номер **останнього** блока, байти 4–7 розмір блока. Якщо диск більший, ніж уміщується в чотири байти, у перших чотирьох байтах приїде `FF FF FF FF` — це не місткість, а вказівка спитати шістнадцятибайтовою формою.

**`READ CAPACITY(16)` (`9Eh` зі службовою дією `10h`, 16 байтів)**

```
байт 0      9Eh
байт 1      біти 4–0 службова дія = 10h
байти 2–9   застаріле
байти 10–13 довжина буфера відповіді (32 байти)
байт 14     біт 0 PMI (застаріле)
байт 15     керуючий байт
```

Відповідь на 32 байти: байти 0–7 — останній блок, 8–11 — розмір логічного блока, байт 12 біт 0 `PROT_EN` і біти 3–1 `P_TYPE`, байт 13 біти 3–0 — показник двійки, скільки логічних блоків в одному фізичному, байт 14 біт 7 `LBPME` (пристрій уміє розріджене виділення) і біт 6 `LBPRZ` (відкинуте читається нулями), біти 5–0 байта 14 разом із байтом 15 — номер першого вирівняного блока.

**`SYNCHRONIZE CACHE(10)` (`35h`, 10 байтів)**

```
байт 0     35h
байт 1     біт 2 SYNC_NV (застаріле) · біт 1 IMMED
байти 2–5  перший блок
байт 6     номер групи
байти 7–8  скільки блоків; нуль означає «усе від указаного блока до кінця»
байт 9     керуючий байт
```

`IMMED` дозволяє пристроєві відповісти одразу й доводити дані потім — рівно те, чого не можна робити під `fsync`. Шістнадцятибайтова форма — `91h`: блок у байтах 2–9, кількість у 10–13.

**`REPORT LUNS` (`A0h`, 12 байтів)**

```
байт 0      A0h
байт 1      зарезервовано
байт 2      SELECT REPORT: 00h — доступні, крім добре відомих;
                           01h — лише добре відомі; 02h — усі
байти 3–5   зарезервовано
байти 6–9   довжина буфера відповіді, не менша за 16
байт 10     зарезервовано
байт 11     керуючий байт
```

Відповідь: байти 0–3 — довжина переліку (вісім помножити на кількість одиниць), байти 4–7 зарезервовано, далі по вісім байтів на кожну логічну одиницю. Перший запит роблять із буфером на 16 байтів саме щоб дізнатися справжню довжину й перепитати вже правильним розміром.

**`UNMAP` (`42h`, 10 байтів)**

```
байт 0     42h
байт 1     біт 0 ANCHOR
байти 2–5  зарезервовано
байт 6     номер групи
байти 7–8  довжина списку параметрів
байт 9     керуючий байт
```

Самі ділянки їдуть окремим списком:

```
байти 0–1  довжина всього списку, n−1
байти 2–3  довжина ділянки описувачів
байти 4–7  зарезервовано
далі по 16 байтів на описувач:
   байти 0–7    перший блок, 64 біти
   байти 8–11   скільки блоків, 32 біти
   байти 12–15  зарезервовано
```

Скільки описувачів пристрій приймає за раз і якою порцією взагалі має сенс відкидати — у сторінці `B0h`; навіщо носієві знати про звільнені блоки, розібрано у [відкиданні непотрібних блоків](book:unix-linux/discard-and-trim).

## Байт хоста

Вирок нижнього ярусу — не про пристрій, а про доставку. Значення чинного ядра:

| Значення | Назва | Що сталося |
|---|---|---|
| `0x00` | DID_OK | помилки доставки немає |
| `0x01` | DID_NO_CONNECT | до пристрою не достукалися |
| `0x02` | DID_BUS_BUSY | шина була зайнята весь відведений час |
| `0x03` | DID_TIME_OUT | відповіді не дочекалися з іншої причини |
| `0x04` | DID_BAD_TARGET | ціль не та |
| `0x05` | DID_ABORT | команду наказано зняти |
| `0x06` | DID_PARITY | помилка парності |
| `0x07` | DID_ERROR | внутрішня помилка драйвера |
| `0x08` | DID_RESET | зачепило скиданням |
| `0x09` | DID_BAD_INTR | несподіване переривання |
| `0x0a` | DID_PASSTHROUGH | наскрізна команда, середній ярус не втручається |
| `0x0b` | DID_SOFT_ERROR | драйвер сам просить повторити |
| `0x0c` | DID_IMM_RETRY | повторити, не витрачаючи лічильник спроб |
| `0x0d` | DID_REQUEUE | повернути в чергу без негайного повтору |
| `0x0e` | DID_TRANSPORT_DISRUPTED | транспорт обірвався посеред виконання |
| `0x0f` | DID_TRANSPORT_FAILFAST | транспорт відмовився чекати й провалив команду одразу |
| `0x14` | DID_TRANSPORT_MARGINAL | канал працює, але на межі |

Діра між `0x10` і `0x13` — сліди чотирьох кодів, які колись були й пішли: `DID_TARGET_FAILURE`, `DID_NEXUS_FAILURE`, `DID_ALLOC_FAILURE` і `DID_MEDIUM_ERROR`. Усі чотири говорили про пристрій, а не про дріт, тобто робили байтом хоста те, для чого й існують сенс-дані; тепер ці випадки судять за ключем і ASC. Якщо трапиться журнал зі старої системи — числа з цієї діри читаються за наведеними назвами.

## Мінімальний виклик

Надіслати CDB власноруч можна через [наскрізний канал `sg`](book:unix-linux/scsi-generic-passthrough) — байти йдуть у пристрій без жодного тлумачення:

```sh
# READ CAPACITY(16): код 9Eh, службова дія 10h, буфер на 32 байти
sg_raw -r 32 /dev/sdb 9e 10 00 00 00 00 00 00 00 00 00 00 00 20 00 00
```

Коли пристрій відмовляє, той самий засіб друкує розібраний звіт — усі числа з цієї довідки на своїх місцях:

```
SCSI Status: Check Condition
Sense Information:
 Fixed format, current;  Sense key: Medium Error
 Additional sense: Unrecovered read error
 Info fld=0x2003 [8195]
```

Тут `Fixed format, current` — код відповіді `0x70`, `Medium Error` — ключ `0x3`, `Unrecovered read error` — пара `11/00`, а `Info fld` — ті самі байти 3–6, у яких лежить номер блока, що не читається.
