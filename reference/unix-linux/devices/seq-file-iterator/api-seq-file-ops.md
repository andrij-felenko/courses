# 📋 Інтерфейс підсистеми seq_file: структури, операції та допоміжні функції

Підсистема `seq_file` оголошена в заголовковому файлі ядра `<linux/seq_file.h>`, а її базова реалізація розташована у `fs/seq_file.c`. Вона надає уніфікований шар абстракції для послідовного форматування структурованих даних ядра у псевдофайли віртуальних файлових систем `procfs`, `sysfs`, `debugfs` та `kernfs`. Інтерфейс ізолює низькорівневі операції роботи з пам'яттю, пагінацією та системними викликами VFS від конкретної логіки перебору внутрішніх колекцій драйвера.

---

## 1. Таблиця методів ітератора: struct seq_operations

Ключовим елементом підсистеми є таблиця з чотирьох покажчиків на функції `struct seq_operations`. Вона визначає поведінку віртуального курсора під час послідовного читання.

```c
struct seq_operations {
	void * (*start) (struct seq_file *m, loff_t *pos);
	void   (*stop)  (struct seq_file *m, void *v);
	void * (*next)  (struct seq_file *m, void *v, loff_t *pos);
	int    (*show)  (struct seq_file *m, void *v);
};
```

### Метод start: ініціалізація та позиціонування

Метод `start()` викликається на початку кожного системного виклику читання або операції позиціонування. Його завдання — підготувати контекст для обходу колекції та знайти початковий елемент, що відповідає логічному зсуву `*pos`.

- **Параметри:** `m` — покажчик на активну структуру дескриптора послідовності; `pos` — покажчик на 64-бітне ціле число, що позначає логічний індекс шуканого елемента (за замовчуванням `0` при відкритті файлу).
- **Повернене значення:** непрозорий покажчик `void *` на знайдений об'єкт ядра (наприклад, елемент списку або масиву), спеціальний маркер `SEQ_START_TOKEN` (якщо при `*pos == 0` потрібно вивести текстову шапку таблиці), `NULL` (якщо індекс `*pos` перевищує кількість наявних об'єктів або колекція порожня), або покажчик на помилку `ERR_PTR(-errno)` у разі збою виділення ресурсів.
- **Вимоги до блокувань:** саме всередині `start()` драйвер зобов'язаний захопити блокування, що захищають структури даних ядра від змін під час ітерації. Залежно від контексту та архітектури драйвера це може бути вхід у критичну секцію RCU (`rcu_read_lock()`), блокування м'ютексом (`mutex_lock()`) або захоплення спінлока (`spin_lock_irqsave()`).

### Метод stop: очищення ресурсів та розблокування

Метод `stop()` викликається підсистемою VFS **завжди** після завершення чергового циклу ітерації, незалежно від того, як саме завершилося читання — штатним вичерпанням даних (`EOF`), заповненням проміжного буфера, переповненням виводу чи виникненням критичної помилки.

- **Параметри:** `m` — дескриптор послідовності; `v` — покажчик на останній оброблений елемент або `NULL`, якщо ітерація завершилася.
- **Вимоги до блокувань:** драйвер зобов'язаний симетрично звільнити всі блокування, захоплені в методі `start()`. Якщо у `start()` було викликано `rcu_read_lock()`, метод `stop()` виконує `rcu_read_unlock()`. Якщо утримувався м'ютекс або спінлок — він звільняється тут. Невиконання цієї вимоги призведе до взаємного блокування (deadlock) або витоку контексту планувальника.

### Метод next: перехід до наступного об'єкта

Метод `next()` просуває логічний ітератор уперед на один крок послідовності.

- **Параметри:** `m` — дескриптор послідовності; `v` — покажчик на поточний об'єкт, який щойно було передано в `show()`; `pos` — покажчик на логічний індекс.
- **Обов'язкова дія:** функція **зобов'язана** збільшити логічний лічильник, як правило, оператором `(*pos)++`. Якщо драйвер забуде інкрементувати `*pos`, ядро потрапить у нескінченний цикл, що зависне в просторі ядра.
- **Повернене значення:** покажчик на наступний об'єкт колекції або `NULL`, якщо досягнуто кінця послідовності. Якщо попередній виклик `start()` повернув маркер `SEQ_START_TOKEN`, метод `next()` повертає покажчик на перший реальний елемент структури даних.

### Метод show: перетворення об'єкта в текст

Метод `show()` відповідає виключно за генерацію текстового представлення одного елемента послідовності.

- **Параметри:** `m` — дескриптор послідовності, куди спрямовується форматований текст; `v` — покажчик на об'єкт ядра, повернутий функціями `start()` або `next()`.
- **Повернене значення:** `0` у разі успішного запису рядка; ненульовий від'ємний код помилки (`-EFAULT`, `-EIO`) для переривання виклику; або спеціальний код `SEQ_SKIP` (`1`), що інструктує ядро скасувати вивід поточного запису та перейти до наступного елемента.

## 2. Дескриптор сесії: struct seq_file

Структура `struct seq_file` створюється під час відкриття псевдофайлу і прив'язується до поля `file->private_data` структури `struct file` у VFS. Вона зберігає динамічний буфер ядра та поточний стан розбору.

```c
struct seq_file {
	char *buf;
	size_t size;
	size_t from;
	size_t count;
	size_t pad_until;
	loff_t index;
	loff_t read_pos;
	struct mutex lock;
	const struct seq_operations *op;
	int poll_event;
	const struct file *file;
	void *private;
};
```

Поле `buf` вказує на лінійний буфер у пам'яті ядра, виділений за допомогою `kvmalloc()` (спочатку через `kmalloc()`, а для великих обсягів — через `vmalloc()`). Початковий розмір `size` дорівнює одній сторінці пам'яті (`PAGE_SIZE`), але за потреби динамічно подвоюється. Поле `count` фіксує кількість уже згенерованих байтів у буфері, тоді як `from` позначає позицію, починаючи з якої дані копіюються в буфер процесу користувача через `copy_to_user()`.

Поле `lock` є внутрішнім м'ютексом (`struct mutex`), що синхронізує системні виклики `read()` та `lseek()`. Якщо кілька ниток одного процесу намагаються одночасно читати з одного файлового дескриптора, м'ютекс серіалізує доступ до полів `buf`, `from` та `count`, запобігаючи руйнуванню внутрішнього стану буфера. Поле `private` дозволяє драйверу зберігати довільний покажчик на контекст пристрою чи структури даних.

## 3. Функції форматування та виводу

Для наповнення проміжного буфера підсистема надає спеціальний набір функцій виводу. Їхньою головною властивістю є автоматичний контроль переповнення: вони ніколи не записують байти за межі `m->size`.

```c
void seq_printf(struct seq_file *m, const char *fmt, ...);
void seq_puts(struct seq_file *m, const char *s);
void seq_putc(struct seq_file *m, char c);
void seq_write(struct seq_file *m, const void *data, size_t len);
void seq_pad(struct seq_file *m, char c);
int  seq_escape(struct seq_file *m, const char *s, const char *esc);
void seq_hex_dump(struct seq_file *m, const char *prefix_str, int prefix_type,
                  int rowsize, int groupsize, const void *buf, size_t len,
                  bool ascii);
bool seq_has_overflowed(struct seq_file *m);
```

- **`seq_printf`** — основна робоча конячка виводу. Приймає рядок формату та змінний список аргументів (аналогічно до `vsnprintf`). Якщо відформатований рядок перевищує залишок вільного місця в `m->buf`, функція не затирає пам'ять, а встановлює `m->count = m->size`, що переводить структуру в стан переповнення.
- **`seq_puts`** та **`seq_putc`** — оптимізовані варіанти для запису статичних рядків і поодиноких символів (наприклад, символу нового рядка `\n` чи роздільника `\t`). Вони уникають накладних витрат на парсинг рядка формату.
- **`seq_write`** — копіює фіксований бінарний або текстовий блок заданої довжини `len` безпосередньо в буфер ядра.
- **`seq_pad`** — вирівнює рядок пробілами або іншим символом `c` до позиції `m->pad_until`, що зручно для форматування гарних таблиць із фіксованими стовпчиками.
- **`seq_escape`** — безпечно копіює рядок, замінюючи небезпечні символи (наприклад, пробіли, символи повернення каретки або табуляції) на вісімкові послідовності `\ooo`. Це критично для виводу імен файлів чи мережевих ресурсів, які інакше зламають синтаксичний розбір утилітами користувача.
- **`seq_has_overflowed`** — повертає `true`, якщо під час форматування забракло місця. Використовується внутрішніми циклами VFS для ухвалення рішення про подвоєння буфера.

## 4. Спеціальні константи

- **`SEQ_START_TOKEN`** — фіктивний покажчик зі значенням `((void *)1)`. Використовується в методі `start()`, коли `*pos == 0`, якщо таблиця повинна починатися з текстового заголовка. У методі `show()` драйвер перевіряє `if (v == SEQ_START_TOKEN)` і друкує назви колонок. У `next()` при зустрічі маркера повертається покажчик на перший дійсний елемент структури, а `*pos` виставляється в `1`.
- **`SEQ_SKIP`** — ненульове числове значення (зазвичай `1`). Якщо метод `show()` повертає `SEQ_SKIP`, підсистема `seq_file` скасовує всі зміни лічильника `m->count`, зроблені під час цього виклику `show()`, і переходить до наступного елемента через `next()`. Це дозволяє динамічно фільтрувати об'єкти без обриву системного виклику.

## 5. Зв'язування з VFS та обробники операцій файлу

Для реєстрації файлу в традиційних структурах VFS підсистема надає готові обробники для полів `struct file_operations`:

```c
int seq_open(struct file *file, const struct seq_operations *op);
void *seq_open_private(struct file *file, const struct seq_operations *op, int psize);
ssize_t seq_read(struct file *file, char __user *buf, size_t size, loff_t *ppos);
ssize_t seq_read_iter(struct kiocb *iocb, struct iov_iter *iter);
loff_t seq_lseek(struct file *file, loff_t offset, int whence);
int seq_release(struct inode *inode, struct file *file);
int seq_release_private(struct inode *inode, struct file *file);
```

Функція `seq_open()` виділяє пам'ять під дескриптор `struct seq_file`, ініціалізує м'ютекс `lock` і записує результат у `file->private_data`. Якщо модулю потрібна власна структура контексту, `seq_open_private()` виділяє єдиний суцільний блок пам'яті для `struct seq_file` та додаткових `psize` байтів, повертаючи покажчик на виділену приватну область.

Функції `seq_read()` та `seq_read_iter()` реалізують повний цикл взаємодії з процесом: захоплення м'ютексу, виклик ітератора `start/show/next/stop`, розширення буфера при переповненні та безпечне копіювання байтів у простір користувача через `copy_to_user()`. Функція `seq_lseek()` емулює позиціонування всередині згенерованого текстового потоку шляхом повторного обходу послідовності з нульової позиції.

Закриття файлу обробляється функціями `seq_release()` або `seq_release_private()`, які звільняють проміжний текстовий буфер `kvfree(m->buf)` та сам дескриптор `kfree(m)`.

## 6. Високорівневі помічники реєстрації у procfs

Для створення записів у віртуальній файловій системі `/proc` сучасне ядро надає компактні конструктори, що повністю приховують ручне створення структури `file_operations`:

```c
struct proc_dir_entry *proc_create_seq(const char *name, umode_t mode,
                                       struct proc_dir_entry *parent,
                                       const struct seq_operations *ops);

struct proc_dir_entry *proc_create_seq_data(const char *name, umode_t mode,
                                            struct proc_dir_entry *parent,
                                            const struct seq_operations *ops,
                                            void *data);
```

Ці функції створюють вузол каталогу, налаштовують стандартні операції VFS та реєструють таблицю `ops`. Функція `proc_create_seq_data()` додатково передає довільний покажчик `data`, який потім доступний всередині методів через виклик макроса `PDE_DATA(file_inode(m->file))`.

## 7. Інтерфейс для одиничного виводу (Single-shot API)

У багатьох випадках псевдофайл ядра містить лише кілька рядків глобальної статистики або конфігураційних параметрів, які не є списком або масивом однакових записів. Створювати для таких файлів повноцінну таблицю з чотирьох функцій `seq_operations` є зайвим ускладненням.

Для таких задач ядро надає механізм одиничного виводу `single_open`:

```c
int single_open(struct file *file,
                int (*show)(struct seq_file *m, void *v),
                void *data);

int single_open_size(struct file *file,
                     int (*show)(struct seq_file *m, void *v),
                     void *data, size_t size);

int single_release(struct inode *inode, struct file *file);

struct proc_dir_entry *proc_create_single(const char *name, umode_t mode,
                                          struct proc_dir_entry *parent,
                                          int (*show)(struct seq_file *, void *));

struct proc_dir_entry *proc_create_single_data(const char *name, umode_t mode,
                                               struct proc_dir_entry *parent,
                                               int (*show)(struct seq_file *, void *),
                                               void *data);
```

Механізм `single_open()` автоматично створює під капотом мінімальну таблицю `seq_operations`, де метод `start()` повертає переданий покажчик `data` лише один раз (при `*pos == 0`), `next()` повертає `NULL`, а метод `show()` викликає призначену користувацьку функцію. Якщо згенерований текст перевищує початковий розмір буфера, `single_open` автоматично повторить виклик `show()` із подвоєним буфером, забезпечуючи абсолютну безпеку виводу будь-якого розміру без написання коду ітератора.
