# 📋 Специфікація та структури virtio-balloon

Специфікація стандарту OASIS Virtio визначає пристрій традиційного балонінгу як паравіртуалізований інтерфейс перерозподілу пам'яті з ідентифікатором типу `VIRTIO_ID_BALLOON` (`5`). Нижче наведено детальний технічний довідник структур даних ядра Linux, бітів узгодження функціональності, конфігураційного простору, життєвого циклу дескрипторів, джерел телеметрії в ядрі, структури кілець vring та протоколу взаємодії з гіпервізором QEMU/KVM.

## Архітектура та ідентифікація пристрою

На шині PCI або у дереві пристроїв MMIO віртуальний контролер балонінгу ідентифікується за стандартизованими числовими параметрами:
* **Vendor ID:** `0x1AF4` (Red Hat / QEMU Virtio);
* **Device ID (Legacy / Transitional):** `0x1002`;
* **Device ID (Modern Virtio 1.0+):** `0x1045` (`0x1040 + VIRTIO_ID_BALLOON`);
* **Підсистема ядра Linux:** драйвер реєструється як модуль `virtio_balloon.ko` і прив'язується до шини `virtio`.

Пристрій не має власних фізичних каналів DMA чи аналогових портів: його єдиним призначенням є координація розподілу фізичних кадрів між внутрішнім розподілювачем пам'яті гостя та диспетчером адресації хоста.

## Прапорці функціональності (Feature Bits)

Під час ініціалізації пристрою на етапі `probe` драйвер гостя та гіпервізор узгоджують 64-бітну бітову маску можливостей. Гіпервізор оголошує підтримувані властивості через регістри читання, а драйвер записує перетин цих властивостей зі своїми можливостями назад у регістри пристрою.

| Біт | Назва макросу | Значення та призначення |
|:---|:---|:---|
| `0` | `VIRTIO_BALLOON_F_MUST_TELL_HOST` | Гість зобов'язаний сповістити хост через `deflateq` *до того*, як поверне сторінки своєму алокатору пам'яті. Забороняє «ліниве» здування. Якщо біт відсутній, гість може використовувати сторінки одразу, а сповіщення надіслати асинхронно пізніше. |
| `1` | `VIRTIO_BALLOON_F_STATS_VQ` | Активація окремої віртчерги статистики `statsq` (індекс 2) для періодичної передачі метрик споживання пам'яті гостя хосту. Без цього біта хост не може бачити внутрішній стан `MemAvailable` гостя. |
| `2` | `VIRTIO_BALLOON_F_DEFLATE_ON_OOM` | Дозвіл гостю автоматично здувати балон через механізм `shrinker` при виникненні локального дефіциту оперативної пам'яті (запобігання Out-of-Memory). Якщо біт скинуто, гість не має права самовільно зменшувати обсяг балона. |
| `3` | `VIRTIO_BALLOON_F_FREE_PAGE_HINT` | Підтримка підказок про вільні сторінки гостя для прискорення живої міграції віртуальних машин (`free_page_vq`). Гість передає зрізи вільних списків, щоб хост не копіював порожню пам'ять через мережу. |
| `4` | `VIRTIO_BALLOON_F_PAGE_POISON` | Повідомлення хоста про те, що гостьове ядро заповнює звільнені сторінки контрольним патерном (отруєнням під час тестування пам'яті `PAGE_POISONING`), тому хост не повинен оптимізувати їх як нульові сторінки. |
| `5` | `VIRTIO_BALLOON_F_REPORTING` | Активація сучасного механізму Free Page Reporting: асинхронне повернення вільних блоків buddy allocator без блокування сторінок у балоні. Використовує чергу `reporting_vq` (індекс 4). |

## Конфігураційний простір пристрою

Конфігураційний простір пристрою відображається через регістри BAR (PCIe) або MMIO і доступний драйверу ядра через структуру `struct virtio_balloon_config`. Усі числові поля передаються у порядку байтів little-endian.

```c
/* include/uapi/linux/virtio_balloon.h */
struct virtio_balloon_config {
    /* Кількість 4 КіБ сторінок, яку гіпервізор вимагає утримувати в балоні */
    __virtio32 num_pages;

    /* Фактична кількість 4 КіБ сторінок, захоплених драйвером гостя на цей момент */
    __virtio32 actual;

    /* Ідентифікатор команди для узгодження Free Page Hinting або значення отруєння */
    union {
        __virtio32 free_page_hint_cmd_id;
        __virtio32 poison_val;
    };

    /* Запасне поле розширення для майбутніх стандартів */
    __virtio32 free_page_hint_cmd_id_padding;
};
```

Поле `num_pages` записується гіпервізором. Коли хост вимагає змінити обсяг пам'яті, він записує нове числове значення й надсилає гостю переривання конфігурації (Configuration Change Interrupt). Драйвер гостя читає `num_pages`, порівнює його з поточним значенням `actual` і запускає процедуру надування (якщо `num_pages > actual`) або здування (якщо `num_pages < actual`).

Поле `actual` оновлюється гостем по мірі завершення транзакцій у віртчергах. Воно показує хосту реальну кількість сторінок, які зараз фізично заблоковані драйвером.

## Розподіл та призначення віртуальних черг (Virtqueues)

Пристрій `virtio-balloon` використовує до п'яти віртуальних черг залежно від узгоджених прапорців:

| Індекс VQ | Назва черги | Напрямок | Опис формату даних |
|:---|:---|:---|:---|
| `0` | `inflateq` | Гість → Хост | Масив 32-бітних або 64-бітних номерів PFN для передачі захоплених сторінок хосту. |
| `1` | `deflateq` | Гість → Хост | Масив номерів PFN для повернення сторінок гостьовій операційній системі. |
| `2` | `statsq` | Гість ⇄ Хост | Масив структур `struct virtio_balloon_stat` для телеметрії стану пам'яті гостя. |
| `3` | `free_page_vq` | Гість ⇄ Хост | Дескриптори вільних сторінок при активному `VIRTIO_BALLOON_F_FREE_PAGE_HINT`. |
| `4` | `reporting_vq` | Гість → Хост | Scatter-gather списки блоків пам'яті при активному `VIRTIO_BALLOON_F_REPORTING`. |

## Формат пакетів та дескрипторів vring

Для черг `inflateq` та `deflateq` базовою одиницею обміну є масив цілих чисел `__virtio32 pfns[256]`. Кожен елемент масиву представляє номер сторінкового кадру:

```
PFN = Гостьова_Фізична_Адреса / 4096
```

Під час надування драйвер гостя виділяє пам'ять пачками по 256 сторінок (1 МіБ). Він формує дескриптор у таблиці `vring_desc`:
* Поле `addr` містить гостьову фізичну адресу масиву `vb->pfns`;
* Поле `len` дорівнює `256 * sizeof(__virtio32) = 1024` байтів;
* Прапорець `flags` встановлюється у `0` (доступ лише на читання з боку гіпервізора).

Після запису індексу дескриптора в кільце `vring_avail` драйвер виконує апаратний бар'єр пам'яті `virtio_wmb()` і записує індекс черги `0` у регістр сповіщення контролера (Doorbell Register).

Гіпервізор QEMU зчитує масив номерів PFN, транслює кожен номер у віртуальну адресу хоста `HVA` і виконує системний виклик `madvise(hva, 4096, MADV_DONTNEED)`. Після обробки всіх 256 елементів гіпервізор записує дескриптор у кільце `vring_used` і надсилає гостю віртуальне переривання MSI-X.

## Формат телеметрії пам'яті (`statsq`)

Черга статистики `statsq` передає набір тегованих 64-бітних лічильників. Хост надсилає порожній буфер, а драйвер гостя заповнює його масивом структур `struct virtio_balloon_stat`:

```c
/* include/uapi/linux/virtio_balloon.h */
struct virtio_balloon_stat {
    __virtio16 tag;   /* Ідентифікатор метрики */
    __virtio64 val;   /* Значення лічильника в байтах або кількості подій */
} __attribute__((packed));

/* Теги метрик пам'яті */
#define VIRTIO_BALLOON_S_SWAP_IN       0   /* Кількість байтів, прочитаних зі свопу */
#define VIRTIO_BALLOON_S_SWAP_OUT      1   /* Кількість байтів, записаних у своп */
#define VIRTIO_BALLOON_S_MAJFLT        2   /* Кількість важких помилок сторінки (Major Faults) */
#define VIRTIO_BALLOON_S_MINFLT        3   /* Кількість легких помилок сторінки (Minor Faults) */
#define VIRTIO_BALLOON_S_MEMFREE       4   /* Повністю вільна пам'ять (MemFree у байтах) */
#define VIRTIO_BALLOON_S_MEMTOT        5   /* Загальний обсяг фізичної пам'яті гостя (MemTotal) */
#define VIRTIO_BALLOON_S_AVAIL         6   /* Доступна пам'ять без виклику свопу (MemAvailable) */
#define VIRTIO_BALLOON_S_CACHES        7   /* Дисковий кеш і буфери сторінок (Cached + Buffers) */
#define VIRTIO_BALLOON_S_HTLB_ALLOC    8   /* Кількість успішно виділених HugePages */
#define VIRTIO_BALLOON_S_HTLB_FAIL     9   /* Кількість невдалих спроб виділити HugePages */
#define VIRTIO_BALLOON_S_OOM_KILL     10   /* Лічильник спрацьовувань гостьового OOM Killer */
```

### Джерела числових значень у ядрі Linux

Кожна метрика збирається драйвером `virtio_balloon.c` із внутрішніх структур ядра:
1. `VIRTIO_BALLOON_S_SWAP_IN` та `S_SWAP_OUT` зчитуються з глобального лічильника віртуальної пам'яті `all_vm_events()` за індексами `PSWPIN` та `PSWPOUT`, перемножуючись на розмір сторінки `PAGE_SIZE`;
2. `VIRTIO_BALLOON_S_MAJFLT` та `S_MINFLT` фіксують системну кількість сторінкових промахів через лічильники `PGFAULT` та `PGMAJFAULT`;
3. `VIRTIO_BALLOON_S_MEMFREE` та `S_MEMTOT` отримуються безпосередньо з системного виклику підсистеми пам'яті `si_meminfo()`;
4. `VIRTIO_BALLOON_S_AVAIL` розраховується функцією `si_mem_available()`, яка моделює поведінку ядра при вивільненні дискового кешу та неактивних анонімних сторінок;
5. `VIRTIO_BALLOON_S_CACHES` обчислює суму активного й неактивного дискового кешу `global_node_page_state(NR_FILE_PAGES)` разом із буферами файлових систем.

Коли демон оркестрації хоста аналізує стан віртуальної машини, ключовим показником є не `VIRTIO_BALLOON_S_MEMFREE`, а саме `VIRTIO_BALLOON_S_AVAIL`. Показник `MEMFREE` відображає лише абсолютно чисті сторінки, тоді як `AVAIL` враховує дисковий кеш і буфери сторінок (`S_CACHES`), які ядро гостя може миттєво вивільнити без звернення до диска.

## Інтерфейси діагностики в ядрі гостя (Sysfs та Debugfs)

Усередині гостьової системи стан балона та лічильники виділення доступні адміністратору через псевдофайлові системи `sysfs` та `debugfs`.

### Дерево пристрою в /sys/bus/virtio/devices/

Кожен виявлений контролер створює каталог у підсистемі шини virtio (наприклад, `/sys/bus/virtio/devices/virtio0/`):
* `device` — шістнадцятковий код пристрою (`0x0005`);
* `vendor` — код виробника (`0x1af4`);
* `status` — бітова маска стану ініціалізації пристрою за специфікацією Virtio (`DRIVER_OK = 0x4`);
* `features` — шістнадцятковий бітовий рядок узгоджених прапорців функціональності.

### Відлагоджувальна інформація в /sys/kernel/debug/virtio-balloon

Якщо ядро зібрано з увімкненою опцією `CONFIG_DEBUG_FS`, драйвер реєструє файл статистики:

```bash
# Перегляд поточного стану утримання пам'яті балоном усередині гостя
cat /sys/kernel/debug/virtio-balloon
```

Типовий вміст файлу відлагодження:
```text
inflated_pages: 1048576
deflated_pages: 524288
actual_pages:   524288
shrink_scans:   12
shrink_leaks:   16384
```

Поле `shrink_scans` фіксує кількість звернень підсистеми керування пам'яттю ядра до механізму shrinker, а `shrink_leaks` показує, скільки саме сторінок було екстрено повернуто гостю для запобігання Out-of-Memory.

## Інтерфейс керування QEMU Monitor Protocol (QMP)

З боку хоста керування розміром балона та зчитування статистики виконується через сокет QMP у форматі JSON-RPC.

### 1. Зміна розміру балона (встановлення цільової пам'яті)
Команда встановлює цільовий обсяг пам'яті, який *залишається* у віртуальної машини (Target RAM у байтах):

```json
{
  "execute": "balloon",
  "arguments": {
    "value": 4294967296
  }
}
```

Якщо значення `value` перевищує максимальний фізичний розмір віртуальної машини (`total_mem`), QEMU повертає помилку `GenericError: Parameter 'value' expects a value within RAM size`.

### 2. Запит поточного стану балона
Отримання інформації про поточний розмір пам'яті ВМ та ліміти:

```json
{
  "execute": "query-balloon"
}
```

Відповідь QEMU:
```json
{
  "return": {
    "actual": 4294967296,
    "max_mem": 8589934592,
    "total_mem": 8589934592,
    "last_batch_in": 0,
    "last_batch_out": 0
  }
}
```

### 3. Налаштування періоду опитування статистики `statsq`
Встановлення періоду опитування метрик у секундах (наприклад, кожні 3 секунди):

```json
{
  "execute": "qom-set",
  "arguments": {
    "path": "/machine/peripheral/balloon0",
    "property": "guest-stats-polling-interval",
    "value": 3
  }
}
```

### 4. Отримання останнього зрізу гостьової статистики
Зчитування телеметрії гостя через властивість `guest-stats`:

```json
{
  "execute": "qom-get",
  "arguments": {
    "path": "/machine/peripheral/balloon0",
    "property": "guest-stats"
  }
}
```

Відповідь із розпарсеними полями:
```json
{
  "return": {
    "stats": {
      "stat-free-memory": 2147483648,
      "stat-total-memory": 8589934592,
      "stat-available-memory": 3758096384,
      "stat-disk-caches": 1610612736,
      "stat-major-faults": 142,
      "stat-minor-faults": 842109,
      "stat-swap-in": 0,
      "stat-swap-out": 0
    },
    "last-update": 1724238000
  }
}
```
