# 📋 Довідник структур та регістрів Virtio-PCI Capability

Специфікація OASIS Virtio v1.2 використовує механізм **PCI Vendor-Specific Capabilities** (ідентифікатор типии `0x09` у конфігураційному просторі PCI) для структурованого доступу до регістрів конфігурації, управління параавіртуалізованими пристроями та налаштування віртуальних черг. Під час ініціалізації пристрою гостьовий драйвер виконує послідовний обхід зв'язаного списку capabilities у PCI Config Space, витягує зсуви та мапить відповідні регіони у Memory-Mapped I/O (MMIO) простір пам'яті.

## 1. Загальна структура PCI Capability (struct virtio_pci_cap)

Кожна capability Virtio у конфігураційному просторі пристрою починається з базового заголовка специфікації PCI Express, за яким слідують специфічні поля стандарту Virtio.

```c
struct virtio_pci_cap {
    uint8_t  cap_vndr;    /* 0x09: PCI_CAP_ID_VNDR */
    uint8_t  cap_next;    /* Зсув наступної capability у PCI config space */
    uint8_t  cap_len;     /* Загальна довжина цієї capability у байтах */
    uint8_t  cfg_type;    /* Тип структури Virtio (VIRTIO_PCI_CAP_*) */
    uint8_t  bar;         /* Індекс BAR (0..5), у якому розташовані регістри */
    uint8_t  id;          /* Ідентифікатор пристрою (для групування) */
    uint8_t  padding[2];  /* Зарезервовано для вирівнювання на 32-бітний кордон */
    uint32_t offset;      /* Зсув у байтах від початку вказаного BAR */
    uint32_t length;      /* Довжина регіону конфігурації у байтах */
};
```

Поле `cap_vndr` зафіксоване специфікацією PCI і завжди дорівнює `0x09` (Vendor-Specific Capability). Поле `cap_next` вказує зсув у конфігураційному просторі, за яким знаходиться наступний заголовок capability (або `0`, якщо це останній елемент списку). Драйвер ядра Linux сканує цей список під час виконання процедури `virtio_pci_probe()`.

Поле `cfg_type` кодує призначення регіону пам'яті:

- **`VIRTIO_PCI_CAP_COMMON_CFG` (1):** Загальна конфігурація пристрою. Містить регістри скидання пристрою, вибору й узгодження фіч (Feature Bits), обрання активної черги, встановлення її розміру та передачі 64-бітних фізичних адрес структур vring.
- **`VIRTIO_PCI_CAP_NOTIFY_CFG` (2):** Окремий регіон конфігурації дверних дзвоників (Doorbells). Драйвер виконує 16-бітний запис у ці регістри (`kick`), щоб сповістити гіпервізор про появу нових буферів у черзі.
- **`VIRTIO_PCI_CAP_ISR_CFG` (3):** Статус переривань. Використовується при роботі з традиційними перериваннями (INTx) для визначення причини спрацювання (зміна конфігурації або завершення I/O у черзі).
- **`VIRTIO_PCI_CAP_DEVICE_CFG` (4):** Специфічна для типу пристрою область конфігурації (наприклад, MAC-адреса та статус лінку для `virtio-net` або розмір сектора та геометрія для `virtio-blk`).
- **`VIRTIO_PCI_CAP_PCI_CFG` (5):** Альтернативний спосіб доступу до регістрів через PCI Config Space для систем, у яких MMIO мапування недоступне або обмежене прошивкою.
- **`VIRTIO_PCI_CAP_SHARED_MEMORY_CFG` (8):** Області спільної пам'яті (Shared Memory Regions), які використовуються пристроями на кшталт `virtio-fs` або `virtio-gpu` для прямого прокидання сторінок RAM між хостом та гостем.

Поле `bar` вказує, у якому з базових адресних регістрів (Base Address Register, BAR 0..5) розташований даний регіон. Драйвер зчитує фізичну адресу цього BAR із PCI конфігураційного простору, додає зсув `offset` і виконує операцію `ioremap()`, щоб отримати віртуальну адресу в просторі ядра.

## 2. Загальна конфігурація (VIRTIO_PCI_CAP_COMMON_CFG)

Регіон `virtio_pci_common_cfg` є центральним вузлом управління пристроєм. Зсуви регістрів у цьому блоці зафіксовані специфікацією Virtio v1.2:

```c
struct virtio_pci_common_cfg {
    /* Конфігурація Feature Bits */
    uint32_t device_feature_select; /* Читання/Запис: вибір селектора 32-біт слова фіч пристрою (0 або 1) */
    uint32_t device_feature;        /* Читання: 32-бітне слово маски фіч пристрою */
    uint32_t driver_feature_select; /* Запис: вибір селектора фіч драйвера */
    uint32_t driver_feature;        /* Запис: 32-бітне слово узгоджених фіч драйвера */

    /* Конфігурація MSI-X та статусу */
    uint16_t config_msix_vector;    /* Вектор MSI-X для сповіщень про зміну конфігурації */
    uint16_t num_queues;            /* Читання: максимальна кількість доступних черг */
    uint8_t  device_status;         /* Байт статусу пристрою (Device Status Field) */
    uint8_t  config_generation;     /* Лічильник змін конфігураційного простору */

    /* Селектор та параметри віртуальної черги (Virtqueue) */
    uint16_t queue_select;          /* Запис: вибір індексу черги (0..num_queues-1) */
    uint16_t queue_size;            /* Читання/Запис: розмір вибраної черги (N) */
    uint16_t queue_msix_vector;     /* Запис: вектор MSI-X для цієї черги */
    uint16_t queue_enable;          /* Запис: 1 для активації черги */
    uint16_t queue_notify_off;      /* Читання: зсув дверного дзвоника у NOTIFY_CFG */
    uint64_t queue_desc;            /* Запис: 64-бітна фізична адреса Descriptor Table */
    uint64_t queue_driver;          /* Запис: 64-бітна фізична адреса Available Ring */
    uint64_t queue_device;          /* Запис: 64-бітна фізична адреса Used Ring */
    uint16_t queue_notif_config_data;/* Дані для надсилання дверного дзвоника (v1.2) */
    uint16_t queue_reset;           /* Скидання конкретної черги (v1.2) */
};
```

### 2.1. Пояснення роботи з масками фіч (Feature Bits)

Прапорці можливостей (Feature Bits) розділені на два 32-бітних слова:
- Слово 0 (біти 0..31): специфічні фічі конкретного типу пристрою (наприклад, підтримка контрольної суми `VIRTIO_NET_F_CSUM` для мережевої карти або розміру сектора для диска).
- Слово 1 (біти 32..63): загальнотранспортні фічі Virtio стандарту (наприклад, `VIRTIO_F_VERSION_1` під номером 32, `VIRTIO_F_RING_PACKED` під номером 34, `VIRTIO_F_IN_ORDER` під номером 35).

Процедура узгодження:
1. Драйвер записує `0` у `device_feature_select`, після чого зчитує молодші 32 біти фіч пристрою з `device_feature`.
2. Драйвер записує `1` у `device_feature_select`, після чого зчитує старші 32 біти фіч із `device_feature`.
3. Драйвер обирає потрібні йому прапорці і записує їх симетрично через `driver_feature_select` та `driver_feature`.

## 3. Байт статусу пристрою (Device Status Field)

Байт `device_status` реалізує конечний автомат станів ініціалізації:

- **`0x00` (`RESET`):** Початковий стан. Драйвер записує `0`, щоб скинути пристрій. Пристрій скасовує всі операції, очищує черги та переходить у вихідний стан.
- **`0x01` (`ACKNOWLEDGE`):** Гостьова операційна система знайшла PCI пристрій і підтвердила його існування.
- **`0x02` (`DRIVER`):** Операційна система завантажила відповідний модуль драйвера.
- **`0x08` (`FEATURES_OK`):** Драйвер та пристрій узгодили множину Feature Bits. Драйвер повинен перевірити, чи залишився цей біт встановленим пристроєм після запису. Якщо пристрій скинув біт, домовленість не відбулася.
- **`0x04` (`DRIVER_OK`):** Драйвер повністю налаштував усі віртуальні черги (розміри, фізичні адреси `queue_desc`, `queue_driver`, `queue_device`) і пристрій готовий до виконання I/O операцій.
- **`0x40` (`DEVICE_NEEDS_RESET`):** Пристрій виявив внутрішній некритичний збій. Обробка I/O призупиняється до виконання процедури скидання драйвером.
- **`0x80` (`FAILED`):** Фатальна помилка ініціалізації. Драйвер відмовився працювати з пристроєм через несумісність версій або помилку виділення ресурсів.

## 4. Конфігурація сповіщень дверних дзвоників (VIRTIO_PCI_CAP_NOTIFY_CFG)

Для забезпечення максимальної швидкодії під час відправки сповіщень `kick`, кожен пристрій надає структуру `virtio_pci_notify_cap`:

```c
struct virtio_pci_notify_cap {
    struct virtio_pci_cap cap;
    uint32_t notify_off_multiplier; /* Множник зсуву для дверного дзвоника */
};
```

Адреса дверного дзвоника для черги `queue_index` обчислюється за формулою:

```
doorbell_offset = cap.offset + (queue_notify_off * notify_off_multiplier)
doorbell_addr   = bar_base_address + doorbell_offset
```

Значення `queue_notify_off` зчитується зі структури `virtio_pci_common_cfg` після вибору відповідної черги через `queue_select`. 

Завдяки тому, що значення `notify_off_multiplier` зазвичай дорівнює `4` або `4096`, дверний дзвоник кожної черги потрапляє на окрему 32-бітну комірку або на окрему 4 КБ сторінку пам'яті. Це дає змогу гіпервізору KVM прокинути кожен дверний дзвоник у власний файловий дескриптор `ioeventfd`, забезпечуючи обробку `kick` операцій у ядрі хоста без виклику процесу QEMU.

## 5. Доступ до регістру переривань ISR (VIRTIO_PCI_CAP_ISR_CFG)

Структура ISR містить 8-бітний регістр статусу переривань. Зчитування цього регістра є руйнівним (read-to-clear): при зчитуванні біти автоматично скидаються в `0`.

- **Біт 0 (`0x01`):** Завершення I/O запиту хоча б в одній із віртуальних черг пристрою.
- **Біт 1 (`0x02`):** Зміна конфігураційного простору пристрою (например, зміна статусу мережевого лінку або зміна розміру диска на хості).

При використанні MSI-X переривань регістр ISR не зчитується, оскільки кожна черга та подія конфігурації отримують власні унікальні вектори переривань через регістри `config_msix_vector` та `queue_msix_vector`.

## 6. Скидання та перезапуск черг у специфікації Virtio v1.2 (queue_reset)

У специфікації Virtio v1.2 з'явилася підтримка динамічного скидання окремих черг без зупинки всього пристрою:

1. Драйвер обирає чергу через `queue_select`.
2. Драйвер записує `1` у регістр `queue_reset`.
3. Пристрій зупиняє обробку даної черги та підтверджує скидання, повертаючи `1` при читанні `queue_reset`.
4. Драйвер звільняє пам'ять vring, виділяє нові буфери, записує нові фізичні адреси і перезапускає чергу записом `1` у `queue_enable`.

Це дозволяє динамічно змінювати розміри черг під час роботи (queue resizing) та відновлювати завислі черги без перезавантаження всієї віртуальної машини.
