# 📋 Довідник точок керування sysfs, MSR-регістрів та tracepoints вкладеності KVM

Цей довідник містить детальний структурований опис системних точок конфігурації у файловій системі sysfs, спеціальних MSR-регістрів (Model Specific Registers) для керування VMX-можливостями, а також подій трасування (tracepoints) підсистеми KVM, що використовуються для діагностики продуктивності та наналагодження вкладеної віртуалізації.

Інтерфейс розширення вкладеності розподілений між параметрами модулів ядра, таблицями експортованих MSR-регістрів гостя та підсистемою ftrace ядра Linux. Розуміння кожного з цих шарів є необхідним для точного налаштування профілів віртуалізації, аналізу проблем сумісності та вимірювання накладних витрат.

## 1. Параметри модулів ядра у файловій системі sysfs

Файлова система sysfs (`/sys/module/`) експортує глобальні параметри конфігурації підсистеми KVM, які задаються під час завантаження модулів ядра `kvm_intel.ko` або `kvm_amd.ko` чи через файли конфігурації у `/etc/modprobe.d/`.

### Параметри модуля `kvm_intel` (`/sys/module/kvm_intel/parameters/`)

| Параметр | Тип | За замовчуванням | Опис та системний вплив |
| :--- | :--- | :--- | :--- |
| `nested` | bool | `Y` / `1` | Головний перемикач вкладеної віртуалізації (Nested VMX). При `0` спроби виконання інструкцій `VMON`/`VMPTRLD` у гості L1 викликають апаратний виняток `#UD` (Invalid Opcode). |
| `enable_shadow_vmcs` | bool | `Y` / `1` | Дозволяє використання апаратного VMCS Shadowing. Скорочує кількість VM Exits при модифікації VMCS12 з боку L1. При `N` KVM переходить на повільну програмну емуляцію `VMREAD`/`VMWRITE`. |
| `dump_invalid_vmcs` | bool | `N` / `0` | При помилках перевірки полів у `VMLAUNCH`/`VMRESUME` дамплює повний вміст структури VMCS02 у системний журнал `dmesg`. Використовується для глибокого аналізу помилок ядра L0. |
| `nested_early_signalled` | bool | `N` / `0` | Оптимізація обробки переривань у вкладеному режимі перед завантаженням VMCS02. |
| `vmm_exclusive` | bool | `Y` / `1` | Монополізує доступ до розширень VMX на процесорі. Забороняє іншим стороннім гипервізорам у хості використовувати VMX паралельно з KVM. |

Параметр `nested` є ключовим перемикачем підсистеми VMX. Коли його значення встановлено в `0` або `N`, ядро KVM приховує прапорці VMX під час формування відповідей на запити `KVM_GET_SUPPORTED_CPUID`. Якщо гостьова операційна система L1 намагається завантажити модуль `kvm_intel` усередині себе, ядро L1 під час ініціалізації зчитує регістр `CR4.VMXE[bit 13]`. Спроба встановити цей біт за відсутності підтримки з боку L0 генерує апаратний виняток `#GP` (General Protection Fault), і модуль `kvm_intel` у L1 відмовляється від завантаження з помилкою «VMX disabled by CPU/BIOS».

Параметр `enable_shadow_vmcs` безпосередньо впливає на накладні витрати під час модифікації полів контролю. При значенні `Y` ядро L0 виділяє додаткову сторінку пам'яті Shadow VMCS для кожного VCPU і налаштовує покажчик VMCS Shadowing Pointer у VMCS01. Якщо цей параметр вимкнути (`nested.enable_shadow_vmcs=0`), ядро L0 змушене перехоплювати кожну інструкцію `VMREAD` та `VMWRITE`, що викликає додаткові тисячі контекстних перемикань при кожному запуску L2.

### Параметри модуля `kvm_amd` (`/sys/module/kvm_amd/parameters/`)

| Параметр | Тип | За замовчуванням | Опис та системний вплив |
| :--- | :--- | :--- | :--- |
| `nested` | int | `1` | Вмикає або вимикає підтримку Nested SVM (0 — вимкнено, 1 — увімкнено). |
| `npt` | bool | `Y` / `1` | Вмикає підтримку двохрівневих таблиць сторінок (Nested Page Tables). Без NPT KVM переходить на повільну програмну емуляцію Shadow Page Tables. |
| `sev` | bool | `Y` / `1` | Підтримка Secure Encrypted Virtualization (AMD SEV). Впливає на можливість створення конфіденційних вкладених ВМ. |

Для архітектури AMD SVM параметр `npt` має вирішальне значення для продуктивності вкладеності. При увімкненому `npt=1` ядро L0 використовує апаратні NPT для трансляції `L1 GPA → L0 HPA` та будує об'єднані таблиці NPT02. Якщо `npt=0`, KVM повертається до старого програмного алгоритму Shadow Page Tables, який вимагає перехоплення кожного завантаження регістру `CR3` та модифікації записів сторінок, що знижує швидкість роботи пам'яті в L2 у кілька разів.

## 2. MSR-регістри віртуалізації Intel VMX

Коли гостьовий гіпервізор L1 ініціалізує власну підсистему VMX, він виконує читання спеціальних регістрів MSR (Model Specific Registers) за допомогою інструкції `RDMSR`. Ядро KVM L0 перехоплює ці звернення і повертає маску апаратних можливостей, які L0 дозволяє використовувати у L1.

| MSR Адреса | Назва регістру | Опис полів та значення у KVM |
| :--- | :--- | :--- |
| `0x480` | `IA32_VMX_BASIC` | Містить ідентифікатор версії VMCS (VMCS Revision Identifier), розмір VMCS у байтах (зазвичай 4096) та фізичний тип адресації пам'яті (32-bit або 64-bit physical address). |
| `0x481` | `IA32_VMX_PINBASED_CTLS` | Бітова маска дозволених керувань на основі виводів (Pin-based VM-execution controls), включаючи зовнішні переривання, NMI та VMX Preemption Timer. |
| `0x482` | `IA32_VMX_PROCBASED_CTLS` | Бітова маска керувань на основі процесора (Processor-based controls): перехоплення `CR3`, `INVLPG`, `RDTSC`, використання MSR Bitmaps та HLT. |
| `0x483` | `IA32_VMX_EXIT_CTLS` | Бітони контролю виходу (VM-exit controls): збереження/відновлення MSR, розмірність системного середовища (64-bit host), збереження IA32_PAT та IA32_EFER. |
| `0x484` | `IA32_VMX_ENTRY_CTLS` | Бітони контролю входу (VM-entry controls): вхід у 64-бітний режим гостя, впорскування подій та переривань, завантаження IA32_PAT та IA32_EFER. |
| `0x485` | `IA32_VMX_MISC` | Допоміжні можливості: підтримка інструкції `VMFUNC`, масштабування таймера VMX-preemption timer та допустимі стани збереження CR3. |
| `0x486` / `0x487` | `IA32_VMX_CR0_FIXED0 / FIXED1` | Обов'язкові біти регістру `CR0`, які повинні бути встановлені в `1` або `0` під час перебування у VMX Root (наприклад, біти PE та PG повинні бути 1). |
| `0x48B` | `IA32_VMX_PROCBASED_CTLS2` | Вторинні контролери виконання: увімкнення EPT, VPID, VMCS Shadowing, RDTSCP, Unrestricted Guest, APIC-register virtualization. |
| `0x48C` | `IA32_VMX_EPT_VPID_CAP` | Властивості EPT та VPID: підтримка 2MB/1GB сторінок, тип обходу таблиць (4-level / 5-level), методи скидання кешу `INVEPT`/`INVVPID`. |

Регістр `IA32_VMX_BASIC` (адреса `0x480`) віддає гостю 32-бітний ідентифікатор версії VMCS у молодших 31 бітах. Під час виконання `VMPTRLD` ядро L1 звіряє цей ідентифікатор із заголовком своєї структури VMCS. Якщо значення не збігаються, інструкція `VMPTRLD` завершується з встановленим прапорцем помилки `ZF=1` (VMFAIL_INVALID).

Регістр `IA32_VMX_PROCBASED_CTLS2` (адреса `0x48B`) контролює вторинні функції віртуалізації. У ньому біт 1 (`1 << 1`) відповідає за підтримку EPT, біт 5 (`1 << 5`) — за VPID, біт 7 (`1 << 7`) — за Unrestricted Guest, а біт 14 (`1 << 14`) — за VMCS Shadowing. Коли KVM L0 експортує ці MSR у L1, він фільтрує значення згідно з власними можливостями та параметрами sysfs, гарантуючи, що L1 не зможе увімкнути функції, які відсутні у фізичному процесорі.

## 3. Точки трасування (KVM Tracepoints) та діагностика

Для моніторингу подій вкладеної віртуалізації, аналізу причин частих VM Exits та вимірювання затримок у ядрі Linux передбачено набір точок трасування ftrace у підсистемі `kvm`.

### Перелік подій `kvm` для nested-режиму

- `kvm:kvm_nested_vmrun`: Викликається KVM L0 в момент виконання виклику `VMLAUNCH`/`VMRESUME`/`VMRUN` для запуску вкладеного гостя L2. Дамплює rip L2, адресний покажчик `vmcs12` та номери регістрів.
- `kvm:kvm_nested_vmexit`: Викликається при виникненні апаратного VM Exit під час виконання коду L2. Містить код `exit_reason`, `exit_qualification` та стан віртуальних регістрів.
- `kvm:kvm_nested_vmexit_inject`: Фіксує момент, коли L0 вирішує маршрутизувати (впорскати) VM Exit у ядро L1.
- `kvm:kvm_nested_vmentry_failed`: Фіксує відмову апаратури запустити L2 через некоректні значення полів у VMCS02 (найчастіше через порушення фіксованих бітів CR0/CR4 або недопустимі адреси EPT).

### Команди моніторингу та аналізу через ftrace та perf

Для швидкого увімкнення трасування вкладених VM Exits у реальному часі через ftrace виконують:

```bash
echo 1 > /sys/kernel/debug/tracing/events/kvm/kvm_nested_vmexit/enable
echo 1 > /sys/kernel/debug/tracing/events/kvm/kvm_nested_vmrun/enable
cat /sys/kernel/debug/tracing/trace_pipe
```

Аналіз високої частоти VM Exits у підсистемі L2 за допомогою утиліти `perf`:

```bash
perf record -e kvm:kvm_nested_vmexit -e kvm:kvm_nested_vmrun -a sleep 10
perf report --stat
```

Структура полів запису у файловій системі debugfs:

```bash
cat /sys/kernel/debug/tracing/events/kvm/kvm_nested_vmexit/format
```

Значення полів формати підтверджують rip L2, причину виходу (`exit_reason`), значення `exit_qualification` та покажчик на активний `vmcs12`. Аналіз tracepoints дозволяє точно визначити, чи викликане сповільнення часими EPT Violations (код `48`), чи трапами на інструкціях I/O та MSR.
