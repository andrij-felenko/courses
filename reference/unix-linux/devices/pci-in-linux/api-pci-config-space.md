# 📋 PCI Configuration Space: Заголовок і регістри

Кожен PCI та PCIe пристрій має стандартизований конфігураційний простір. Для класичного PCI він складає 256 байтів, де перші 64 байти (0x00 - 0x3F) є обов'язковим стандартизованим заголовком (Type 0 для кінцевих пристроїв, Type 1 для мостів). У PCIe конфігураційний простір розширено до 4096 байтів (4 КБ).

## Структура Type 0 Header (Кінцевий пристрій)

Ось як виглядають перші 64 байти будь-якого PCI-пристрою (кожен рядок — це 32-бітне слово, тобто 4 байти):

| Зсув | Байт 3 (біти 31–24) | Байт 2 (біти 23–16) | Байт 1 (біти 15–8) | Байт 0 (біти 7–0) |
|------|---------------------|---------------------|--------------------|-------------------|
| **0x00** | Device ID | ⟵ | Vendor ID | ⟵ |
| **0x04** | Status | ⟵ | Command | ⟵ |
| **0x08** | Class Code | Subclass | Prog IF | Revision ID |
| **0x0C** | BIST | Header Type | Latency Timer | Cache Line Size |
| **0x10** | Base Address Register 0 (BAR0) | ⟵ | ⟵ | ⟵ |
| **0x14** | Base Address Register 1 (BAR1) | ⟵ | ⟵ | ⟵ |
| **0x18** | Base Address Register 2 (BAR2) | ⟵ | ⟵ | ⟵ |
| **0x1C** | Base Address Register 3 (BAR3) | ⟵ | ⟵ | ⟵ |
| **0x20** | Base Address Register 4 (BAR4) | ⟵ | ⟵ | ⟵ |
| **0x24** | Base Address Register 5 (BAR5) | ⟵ | ⟵ | ⟵ |
| **0x28** | Cardbus CIS Pointer | ⟵ | ⟵ | ⟵ |
| **0x2C** | Subsystem ID | ⟵ | Subsystem Vendor ID | ⟵ |
| **0x30** | Expansion ROM Base Address | ⟵ | ⟵ | ⟵ |
| **0x34** | Reserved (0x00) | Reserved (0x00) | Reserved (0x00) | Capabilities Ptr |
| **0x38** | Reserved (0x00000000) | ⟵ | ⟵ | ⟵ |
| **0x3C** | Max Latency | Min Grant | Interrupt Pin | Interrupt Line |

Знак `⟵` означає, що поле з клітини ліворуч продовжується й тут: `Device ID` займає обидва старші байти слова (зсуви 0x02–0x03), а кожен BAR — усі чотири байти свого слова.

### Ключові поля:

1. **Vendor ID (0x00) / Device ID (0x02):**
   - **Vendor ID:** Унікальний ідентифікатор виробника, виданий консорціумом PCI-SIG (наприклад, 0x10EC = Realtek, 0x10DE = NVIDIA). Значення `0xFFFF` означає, що пристрою за цією адресою немає.
   - **Device ID:** Ідентифікатор конкретної моделі, визначений самим виробником.

2. **Command (0x04):**
   Дозволяє ядру керувати базовою поведінкою пристрою. Найважливіші біти:
   - **Bit 0 (I/O Space):** Дозволяє пристрою відповідати на запити до простору вводу/виводу.
   - **Bit 1 (Memory Space):** Дозволяє пристрою відповідати на запити до MMIO (регістрів у пам'яті). Без цього біта звернення до BAR-пам'яті ігноруватимуться.
   - **Bit 2 (Bus Master):** Дозволяє пристрою ініціювати транзакції DMA (Direct Memory Access).

3. **Status (0x06):**
   Біти статусів помилок (наприклад, Parity Error) та інформації (наприклад, чи підтримуються розширені Capabilities).

4. **Class Code (0x09 - 0x0B):**
   Визначає функцію пристрою. Дозволяє ядру завантажити узагальнений драйвер (наприклад, для NVMe або AHCI).
   - **Base Class (0x0B):** Загальний тип (наприклад, 0x01 = Mass Storage, 0x02 = Network, 0x03 = Display).
   - **Sub-Class (0x0A):** Специфічний тип (наприклад, 0x08 = NVMe для Base Class 0x01).
   - **Programming Interface (0x09):** Інтерфейс програмування на рівні регістрів.

5. **Header Type (0x0E):**
   Визначає формат решти заголовка: 
   - `0x00` — звичайний пристрій (Endpoint).
   - `0x01` — міст PCI-to-PCI.
   - `0x02` — міст CardBus.
   Старший біт (біт 7), якщо встановлений, означає, що цей фізичний пристрій багатофункціональний (Multi-Function Device).

6. **Base Address Registers (BAR0 - BAR5) (0x10 - 0x24):**
   Вікна ресурсів. Молодші біти кожного BAR вказують на тип ресурсу (пам'ять чи I/O), тип адресації (32-бітна чи 64-бітна пам'ять), а також чи пам'ять є Prefetchable. Якщо це 64-бітне вікно, воно займає два сусідні регістри BAR.

7. **Interrupt Line (0x3C):**
   Містить номер IRQ, який BIOS або ядро призначило цьому пристрою для сумісності зі старими системами переривань. Для сучасного PCIe зазвичай використовується механізм MSI/MSI-X (через Capabilities), і це поле не має значення.
