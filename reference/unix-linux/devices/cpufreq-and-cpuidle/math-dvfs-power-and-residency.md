# 🧮 Математична модель динамічного живлення CPU та розрахунок target residency станів простою

Енергоефективність напівпровідникових цифрових мікросхем описується законами фізики КМОН-структур (CMOS). Перемикання транзисторів між логічними станами "0" та "1" вимагає перезарядки паразитних ємностей P-N переходів та затворів, що супроводжується дисипацією електричної енергії у вигляді тепла.

## Динамічна та статична потужність КМОН-транзисторів

Суммарна споживана потужність процесорного ядра складається з двох основних компонентів: динамічної потужності `P_dyn` та статичної потужності витоку `P_stat`.

```
P_total = P_dyn + P_stat
```

1. **Динамічна потужність (`P_dyn`)** виникає лише під час зміни стану логічних елементів (перезарядка ємності `C_eq` та струми короткого замикання) і визначається формулою:

```
P_dyn = P_cap + P_short
P_dyn = (α · C_eq · V_dd² · f) + (α · I_peak · t_sc · V_dd · f)
```

Де:
* `α` — коефіцієнт активності (activity factor), що показує відсоток вентилів, які змінюють стан за один тактовий імпульс (типово від 0.1 до 0.3);
* `C_eq` — еквівалентна ємність усіх напівпровідникових структур ядра;
* `V_dd` — напруга живлення ядра (Supply Voltage);
* `f` — тактова частота процесора (Clock Frequency);
* `I_peak` — піковий струм короткого замикання під час одночасного відкриття P- та N-транзисторів у момент перемикання;
* `t_sc` — тривалість фронту імпульсу перемикання.

Оскільки струм короткого замикання `P_short` зазвичай становить не більше 5–10% від загального динамічного споживання, у практичних розрахунках застосовують спрощену модель:

```
P_dyn ≈ α · C_eq · V_dd² · f
```

2. **Статична потужність (`P_stat`)** зумовлена струмами витоку `I_leak` через тонкий діелектрик затвора (`I_gate`), зворотно-зміщені P-N переходи (`I_subth`) та струми витоку сток-виток (Subthreshold leakage):

```
P_stat = V_dd · I_leak
I_leak = I_subth + I_gate + I_junction
```

Субпороговий струм витоку `I_subth` залежить від температури кристала `T` та порогової напруги відкриття транзистора `V_th` за експоненційним законом:

```
I_subth ∝ T² · exp((V_gs - V_th) / (S · V_t))
```

Зі зменшенням техпроцесу (нижче 10 нм) струми витоку суттєво зростають, роблячи статичне споживання порівнюваним із динамічним при високих температурах кристала.

## Математична залежність напруги від частоти та нелінійність DVFS

Для забезпечення стабільної роботи транзистора при підвищенні частоти `f` час затримки переключення вентиля `t_delay` має бути меншим за період тактового сигналу `1/f`. Згідно з альфа-моделлю Саха (Alpha-power law), затримка залежить від напруги живлення `V_dd` та порогової напруги відкриття транзистора `V_th`:

```
t_delay = (k · V_dd) / (V_dd - V_th)^α
```

Де `α ≈ 1.2 ... 1.5` для сучасних ФінФЕТ (FinFET) транзисторів. Щоб збільшити частоту `f`, необхідно зменшити затримку `t_delay`, що вимагає підвищення напруги живлення `V_dd`.

Оскільки `P_dyn` пропорційна квадрату напруги `V_dd²` та лінійно залежить від `f`, а сама напруга `V_dd` має зростати лінійно або надлінійно з частотою `f`, споживана динамічна потужність має пропорційність третього ступеня від частоти:

```
P_dyn ∝ f³
```

Зниження частоти на 20% дозволяє пропорційно знизити напругу живлення приблизно на 15%, що призводить до зменшення споживаної динамічної потужності майже на 42%:

```
P_new / P_old = (0.85)² · 0.8
= 0.7225 · 0.8
= 0.578              [зменшення споживання на 42.2%]
```

## Енергетично-затримковий добуток (EDP) та метрика ED²P

Просте зменшення частоти зменшує миттєву потужність `P`, але збільшує час виконання програми `t_exec`. Загальна витрачена енергія `E` визначається як добуток потужності на час:

```
E = P · t_exec
```

Якщо потужність падає швидше, ніж зростає час виконання, загальна витрачена енергія на виконання задачі (Energy per Task) зменшується. Для оцінки компромісу між швидкістю та енергоефективністю використовують метрику **EDP (Energy-Delay Product)**:

```
EDP = E · t_exec = P · t_exec²
```

У високопродуктивних обчисленнях (HPC) та серверах застосовують суворішу метрику **ED²P (Energy-Delay-Squared Product)**, яка надає більшої ваги продуктивності:

```
ED²P = E · t_exec² = P · t_exec³
```

Оптимальною робочою точкою для режиму збереження енергії є мінімум функції `EDP(f)`, тоді як для високопродуктивного режиму шукають мінімум `ED²P(f)`.

## Математична модель Target Residency у підсистемі cpuidle

Коли процесор переходить у стан простою (C-стан), він припиняє споживання динамічної потужності, а у глибоких станах (наприклад, `C6`) повністю відключає напругу живлення ядра, зводячи `P_stat` до нуля.

Однак самі процедури входу (збереження регістрів у SRAM, скидання кешу L1/L2) та виходу (подача напруги, стабілізація PLL, відновлення контексту) вимагають додаткових витрат часу та енергії:
* `E_entry` — енергія, витрачена на вхід у C-стан;
* `E_exit` — енергія, витрачена на вихід із C-стану;
* `t_latency` — сумарна затримка пробудження (`t_entry + t_exit`).

Нехай `P_active` — потужність ядра в активному стані `C0`, а `P_idle` — потужність ядра у глибокому стані `C_k`.

Загальна енергія `E_sleep`, витрачена за час простою `t`:

```
E_sleep(t) = P_idle · t + E_entry + E_exit
```

Енергія `E_stay_active`, яка була б витрачена, якби ядро залишилося в стані `C0`:

```
E_stay_active(t) = P_active · t
```

Перехід у стан `C_k` є енергетично доцільним лише тоді, коли `E_sleep(t) < E_stay_active(t)`:

```
P_idle · t + E_entry + E_exit < P_active · t
t · (P_active - P_idle) > E_entry + E_exit
t > (E_entry + E_exit) / (P_active - P_idle)
```

Величина `T_residency` називається **цільовим часом перебування (Target Residency)**:

```
T_residency = (E_entry + E_exit) / (P_active - P_idle)
```

Якщо очікувана тривалість простою `t` менша за `T_residency`, перехід у глибокий C-стан призведе до *збільшення* загального енергоспоживання системи порівняно з перебуванням у мікросекундному стані `C1`.

## Крайові випадки та апаратні обмеження регуляторів

У реальних процесорних архітектурах розрахунок `T_residency` ускладнюється кількома апаратними факторами:

1. **Швидкість наростання напруги VRM (Voltage Regulator Module)**: Регулятор напруги материнської плати має фізичну межу зміни напруги `dV/dt` (типово 100–300 мВ/мкс). Перехід з 0.6 В до 1.2 В забирає кілька мікросекунд незалежно від швидкості внутрішньої логіки CPU.
2. **Час захоплення фази PLL (Phase-Locked Loop)**: Після подачі живлення тактовий генератор PLL вимагає від 5 до 20 мікросекунд для стабілізації частоти та синхронізації фази.
3. **Енергетичний штраф скидання кешу (Cache Flush Overhead)**: Вхід у стан `C6` вимагає записати модифіковані лінії кешів L1/L2 у загальний кеш L3 або DRAM. Якщо обсяг модифікованих даних великий (кілька мегабайт), енергія вимивання кешу `E_flush` може перевищити енергію спокою:

```
E_entry_total = E_entry_base + (N_dirty_lines · E_writeback)
```

## Покроковий обчислювальний приклад

Розрахуємо мінімальний час простою `T_residency` для переходу ядра x86 у стан `C6 Deep Sleep` з урахуванням вимивання брудних ліній кешу при наступних апаратних параметрах:
* Потужність активного ядра `P_active` = 18.0 Вт;
* Потужність ядра у стані `C6` `P_idle` = 0.3 Вт;
* Базова енергія входу `E_entry_base` = 100 мікроджоулів (мкДж);
* Енергія скидання кешу `E_flush` = 50 мікроджоулів (мкДж);
* Енергія виходу `E_exit` = 210 мікроджоулів (мкДж).

Обчислення проводиться за критерієм енергетичного балансу:

```
ΔP = P_active - P_idle
= 18.0 - 0.3         [різниця потужностей активного та сплячого станів]
= 17.7 Вт

E_total_entry = E_entry_base + E_flush
= 100 + 50           [сумарні енергетичні витрати входу з урахуванням кешу]
= 150 мкДж

E_penalty = E_total_entry + E_exit
= 150 + 210          [сумарні накладні енергетичні витрати переходу]
= 360 мкДж = 0.00036 Дж

T_residency = E_penalty / ΔP
= 0.00036 / 17.7     [ділення накладних витрат на різницю потужності]
= 0.00002033 с
≈ 20.33 мкс          [цільовий час перебування]
```

**Висновок**: Якщо регулятор `cpuidle` прогнозує, що наступне переривання відбудеться раніше ніж через 20.33 мікросекунди, ядро не повинно переходити у стан `C6`, оскільки витрати на перезарядку внутрішніх ємностей та скидання кешів перевищать зекономлену енергію.
