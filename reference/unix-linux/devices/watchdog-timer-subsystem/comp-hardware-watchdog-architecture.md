# 🔌 Архітектура апаратних сторожових таймерів

Сторожові таймери (Watchdog Timers) становлять фундаментальний клас апаратних пристроїв забезпечення надійності обчислювальних систем. Вони реалізуються у вигляді автономних мікроелектронних схем у складі мікроконтролерів, систем на кристалі (SoC), південних мостів (PCH) або зовнішніх мікросхем моніторингу живлення. На відміну від звичайних системних таймерів ядра Linux, апаратний Watchdog фізично відокремлений від головних генераторів тактових частот (PLL) і має прямий зв'язок із апаратною лінією скидання `RESET#` процесора або контролера живлення (PMIC). Ця вставка розбирає узагальнену внутрішню схему, режими роботи, ключові реалізації та типові апаратні пастки цього класу пристроїв.

## 1. Структурна схема апаратного Watchdog

Узагальнений апаратний сторожовий таймер складається з п'яти обов'язкових вузлів:

```
+-------------------------------------------------------------------------+
|                    Hardware Watchdog Controller Architecture            |
|                                                                         |
|  +--------------------+        +-------------------+                    |
|  | Independent LPO    | -----> | Decrement Counter |                    |
|  | Oscillator (32kHz) |        | Register (WDCNT)  |                    |
|  +--------------------+        +-------------------+                    |
|                                          |                              |
|                                          v                              |
|  +--------------------+        +-------------------+                    |
|  | Service/Key Control| -----> | Comparator Logic  |                    |
|  | Register (WDKEY)   |        | (Pretimeout & 0)  |                    |
|  +--------------------+        +-------------------+                    |
|                                     /         \                         |
|                                    /           \                        |
|                                   v             v                       |
|                             +----------+   +------------------------+   |
|                             | NMI / IRQ|   | RESET# Line (To CPU)   |   |
|                             +----------+   +------------------------+   |
+-------------------------------------------------------------------------+
```

### Основні блоки та їх функціонал

1. **Незалежний тактовий генератор (LPO / RTC Oscillator)**: Працює на низькій частоті: 32.768 кГц від власного кварцу або кілька десятків кілогерц від внутрішнього RC-ланцюга. Генератор продовжує функціонувати навіть при повній зупинці системної шини, відключенні головних фазових автопідстройок частоти (PLL) або переході процесора у глибокі енергозберігаючі стани (C-states).
2. **Лічильник зворотного відліку (Decrement Counter)**: 16-, 24- або 32-бітовий регістр, що зменшує своє значення з кожним імпульсом тактового генератора.
3. **Захищений регістр перезавантаження (Service / Key Register)**: Для запобігання випадковому скиданню лічильника збійним кодом (через "дикі" вказівники або пошкодження пам'яті) апаратура вимагає запису суворо визначеної послідовності ключів (Magic Sequence). Наприклад, для скидання таймера i.MX WDOG потрібно послідовно записати `0x5555`, а потім `0xAAAA` у регістр `WDOG_WSR`.
4. **Схема порівняння (Comparator & Threshold Logic)**: Фіксує досягнення порогів `T_pretimeout` та `0`.
5. **Формувач вихідного сигналу скидання (Reset Generator)**: Фізичний каскад із відкритим стоком (Open-Drain), підключений до системного сигналу `RESET#` процесора або входу скидання контролера живлення (PMIC). При досягненні лічильником нуля схема примусово заземлює лінію `RESET#` на час, який вимагає специфікація скидання конкретної платформи (від одиниць до сотень мілісекунд), ініціюючи апаратний перезапуск усього обладнання.

## 2. Схематотехніка та фізичне спряження лінії RESET#

Вихідний каскад апаратного сторожового таймера будується на основі транзистора з відкритим стоком (Open-Drain), зашунтованого зовнішнім резистором підтяжки (Pull-Up) до лінії живлення `VCC_IO` (найчастіше 3.3 В або 1.8 В). 

```
               VCC_IO (3.3V)
                 |
                [R_pullup 10k]
                 |
Watchdog Output -+------> Physical CPU RESET# Pin / PMIC Reset Input
                 |
             [FET N-Ch]
                 |
                GND
```

Така топологія гарантує можливість паралельного підключення декількох джерел скидання (наприклад, фізичної кнопки Reset на корпусі, контролера PMIC та апаратного Watchdog) без виникнення короткого замикання між виходами. Для захисту від хибних спрацьовувань через високочастотні наводки на платі лінія `RESET#` оснащується фільтруючим керамічним конденсатором невеликої ємності (100 нФ) та схемою придушення брязкоту контактів (Debounce Circuit).

## 3. Двостадійна обробка та режими Pretimeout

Багатостадійні сторожові таймери ділять вікно таймауту на два інтервали:

```
T_out (Початок)        T_pretimeout (Поріг)           0 (Апаратний скид)
     |--------------------------|----------------------------|
     |   Звичайний стан системи |   Стадія NMI / Pretimeout  |
     |  (Очікування Heartbeat)  |  (Збереження Kdump / dmesg)|
```

* **Стадія 1 (NMI / IRQ)**: Коли лічильник знижується до значення `T_pretimeout`, контролер генерує немасковане переривання (NMI) або високорівневий переривач (System Error IRQ). На цій стадії процесор ще здатний виконувати інструкції і може виконати аварійний дамп регістрів, зберегти лог `dmesg` або ініціювати процедуру kdump.
* **Стадія 2 (Hard Reset)**: Якщо за залишок часу `T_pretimeout` система не відновилася і лічильник досяг `0`, контролер генерує сигнал `RESET#`.

## 4. Естафета передачі керування під час завантаження

Під час старту обчислювального вузла апаратний сторожовий таймер проходить триетапну естафету передачі відповідальності:

1. **Етап прошивки (UEFI / U-Boot)**: Первинний завантажувач умикає апаратний Watchdog із коротким таймаутом (наприклад, 10–60 секунд) для захисту від зависання під час завантаження образу ядра з диска чи мережі.
2. **Етап ядра Linux (`initcall`)**: Під час виконання `watchdog_register_device()` драйвер ядра перехоплює керування апаратним таймером. Якщо драйвер підтримує прапорець `WDOG_HW_RUNNING`, ядро продовжує пингувати апаратуру через внутрішній таймер `watchdog_kworker` до моменту відкриття `/dev/watchdog`.
3. **Етап простору користувача (PID 1)**: Процес ініціалізації (`systemd`) відкриває символьний пристрій `/dev/watchdog` і бере на себе остаточний моніторинг системи.

## 5. Типові представники класу у промисловості

У Linux-екосистемі застосовуються декілька ключових апаратних архітектур Watchdog:

| Драйвер ядра | Апаратна платформа | Особливості архітектури |
| :--- | :--- | :--- |
| `iTCO_wdt` | Intel PCH / Southbridge (LPC/eSPI) | Вбудований у південний міст Intel; використовує регістри TCO (Total Cost of Ownership). Підтримує двостадійне блокування системи та захист NO_REBOOT |
| `sp805_wdt` | ARM PrimeCell SP805 | Стандартний IP-блок ARM для SoC; підключається до шини APB, має один 32-бітний лічильник, що відлічує двічі: після першого нуля — переривання, після другого — сигнал скидання |
| `imx2_wdt` | NXP i.MX (ARM Cortex-A) | Промисловий контролер з виходом `WDOG_B` безпосередньо на контролер живлення PMIC для холодного перезапуску (Cold Reset) |
| `ipmi_watchdog` | Сервери x86 (BMC Controller) | Позадіапазонний контролер Baseboard Management Controller; керується через IPMI-команди по шині KCS/SMIC |
| `softdog` | Будь-який CPU (Ядро Linux) | Програмний емулятор на основі `hrtimer` ядра; не рятує при апаратному блокуванні шини чи зупинці самого процесора |

## 6. Класові апаратні пастки (Edge Cases)

При розробці драйверів та систем супервізії слід враховувати фізичні обмеження апаратного класу:

1. **Апаратне блокування шини (Bus Lockup)**: Якщо внаслідок збою периферії або шторму переривань блокується системна шина (AXI/AHB/PCIe), процесор втрачає здатність виконувати шинні транзакції запису. Навіть якщо ядро намагається відправити Heartbeat, виклик `write()` або `ioctl()` зависає на операції шинного запису, і апаратний таймер успішно дораховує до нуля, рятуючи систему.
2. **Апаратне обмеження розрядності**: Деякі вбудовані контролери мають всього 12- або 16-розрядні лічильники з низьким дільником частоти, що дає максимальний апаратний таймаут 1.6 або 16 секунд. Для підтримки довгих користувацьких таймаутів (наприклад, 60 секунд) ядро Linux задіює механізм HW Keepalive Pinging (`watchdog_kworker`), де ядро прозоро пінгує апаратуру кожні кілька сотень мілісекунд — щонайменше вдвічі частіше за апаратне вікно — від імені користувача.
3. **Енергозберігаючі режими (Suspend to RAM)**: Якщо ядро переводить систему у стан `S3` (Suspend) або `S4` (Hibernate), тактовий генератор CPU зупиняється. Якщо драйвер Watchdog перед сном не вимкне апаратний таймер через регістр керування, незабаром після засинання апаратний Watchdog скине систему. Драйвери зобов'язані реалізовувати обробники `suspend()` та `resume()` для безпечного тимчасового деактивування таймера.
