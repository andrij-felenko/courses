# Відображення процесів у procfs

Файлова система `procfs` (зазвичай монтується в `/proc`) — це не справжня файлова система на диску, а ілюзія, яку динамічно створює ядро Linux. Вона надає користувацькому простору інтерфейс доступу до внутрішніх структур ядра у вигляді звичайних файлів. Кожен активний процес у системі має свою директорію `/proc/[pid]`, де `[pid]` — числовий ідентифікатор процесу. Ця директорія містить набір файлів, які репрезентують стан процесу в реальному часі.

Ядро не зберігає ці файли в оперативній пам'яті як готові рядки. Замість цього, коли програма викликає `read()` для файлу в `/proc/[pid]`, ядро перехоплює цей виклик через спеціальний обробник VFS. Воно читає власні структури даних (наприклад, `task_struct`), форматує їх у текстовий вигляд і повертає читачеві. Саме тому більшість файлів у `/proc` мають нульовий розмір, якщо перевіряти їх через `ls -l` або `stat()`: їхній розмір неможливо дізнатися до моменту фактичної генерації вмісту.

## Структура директорії процесу

### `status` та `stat`: Метадані процесу
Файл `/proc/[pid]/status` містить зрозуміле для людини текстове зведення про стан процесу. Це основний файл, з якого системні адміністратори читають інформацію.
Тут зібрано все найважливіше:
- **State:** Поточний стан процесу (наприклад, `R` — running, `S` — sleeping, `D` — uninterruptible sleep, `Z` — zombie).
- **Tgid та Pid:** Ідентифікатор групи потоків (те, що користувачі звикли називати PID) і внутрішній PID ядра (ідентифікатор конкретного потоку).
- **VmSize, VmRSS:** Використання віртуальної та фізичної (Resident Set Size) пам'яті.
- **Uid, Gid:** Реальні, ефективні, збережені та файлові ідентифікатори користувача й групи, що визначають права доступу.

Поряд зі `status` існує файл `/proc/[pid]/stat`. Він містить ту саму інформацію, але у вигляді одного довгого рядка значень, розділених пробілами. Файл `stat` призначений для швидкого розбору програмами (наприклад, утилітами `ps` або `top`), оскільки не містить текстових міток і форматування, що суттєво зменшує витрати процесора на парсинг.

### `cmdline`: Аргументи запуску
Файл `/proc/[pid]/cmdline` розкриває повний командний рядок, з яким був запущений процес. Це точна копія масиву `argv`, переданого системному виклику `execve()`.
Оскільки аргументи зберігаються як масив, вони розділені нуль-байтами (`\0`), а не пробілами. Це усуває двозначність при парсингу, якщо сам аргумент містить пробіл.
Іноді процеси (особливо демони) навмисно перезаписують цей масив у пам'яті під час виконання, щоб приховати паролі чи змінити своє ім'я у виводі `ps`. Ядро дозволяє таку модифікацію, тому `cmdline` показує те, що лежить у пам'яті процесу в даний момент.

### `fd/`: Відкриті файли
Директорія `/proc/[pid]/fd/` надає доступ до всіх файлових дескрипторів, відкритих процесом.
Кожен об'єкт у цій директорії є "магічним" символічним посиланням, ім'я якого збігається з номером файлового дескриптора (наприклад, `0`, `1`, `2` для stdin, stdout, stderr).
- Якщо дескриптор вказує на звичайний файл, посилання виглядає як шлях до нього.
- Якщо дескриптор вказує на мережевий сокет або канал (pipe), посилання матиме вигляд внутрішнього об'єкта ядра, на зразок `socket:[12345]`.

Читання з такого посилання або запис у нього безпосередньо впливає на оригінальний файл, оскільки ядро направляє запит до того самого об'єкта `struct file`. Цікавий побічний ефект: якщо процес тримає відкритим файл, який інша програма вже видалила (unlink), посилання отримає суфікс ` (deleted)`. Завдяки цьому адміністратор може скопіювати видалений файл назад, просто прочитавши `/proc/[pid]/fd/[n]`.

### `maps`: Адресний простір
Файл `/proc/[pid]/maps` є мапою віртуального адресного простору процесу. Він розкриває всі регіони пам'яті (Virtual Memory Areas, VMA), які наразі виділені процесові.
Кожен рядок репрезентує один регіон і містить:
1. Діапазон віртуальних адрес.
2. Дозволи (`r` - читання, `w` - запис, `x` - виконання, `p` - приватна/Copy-on-Write, `s` - спільна).
3. Зсув (offset), якщо регіон спроектований з файлу на диску.
4. Номер пристрою та номер inode файлу.
5. Шлях до файлу або псевдонім (наприклад, `[heap]`, `[stack]`, `[vdso]`).

Цей файл критично важливий для дебаггерів (GDB), профайлерів та експлойтів, оскільки він дозволяє дізнатися точні адреси завантаження динамічних бібліотек, розташування стеку й купи.

### `ns/`: Простори імен
Директорія `/proc/[pid]/ns/` містить символічні посилання для кожного підтримуваного простору імен (namespaces): `ipc`, `mnt`, `net`, `pid`, `user`, `uts`, `cgroup`.
Ці посилання не вказують на існуючі шляхи у файловій системі. Їхньою ціллю є магічний рядок формату `тип:[inode_number]`. Індексний дескриптор (inode) у цьому рядку унікально ідентифікує конкретний екземпляр простору імен усередині ядра.

Такі файли мають два головні призначення:
1. **Ідентифікація:** Якщо два різні процеси мають однаковий номер inode для `/proc/.../ns/net`, це означає, що вони перебувають у спільному мережевому просторі імен і бачать однакові мережеві інтерфейси.
2. **Збереження та приєднання:** Якщо відкрити такий файл і тримати його файловий дескриптор відкритим, ядро не знищить цей простір імен навіть після того, як завершиться останній процес у ньому. Згодом інший процес може викликати системний виклик `setns()`, передавши цей дескриптор, щоб приєднатися до збереженого простору імен (так працює утиліта `nsenter`).

## Читання інформації

Взаємодія з `procfs` — це звичайне файлове введення-виведення. Проте, через те, що файли генеруються динамічно, читати їх треба акуратно, враховуючи нуль-байти (у `cmdline`) та структуру рядків.

:::tabs
== Bash
```bash
# Читання аргументів процесу з PID 1234
# tr замінює нуль-байти на пробіли для зручного виводу
cat /proc/1234/cmdline | tr '\0' ' '
echo

# Перегляд відкритих файлів поточного оболонки ($$)
ls -l /proc/$$/fd/
```
== C
```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>

int main() {
    pid_t pid = getpid();
    char path[256];
    
    // Формуємо шлях до cmdline поточного процесу
    snprintf(path, sizeof(path), "/proc/%d/cmdline", pid);

    FILE *f = fopen(path, "r");
    if (f) {
        char buf[1024];
        size_t n = fread(buf, 1, sizeof(buf) - 1, f);
        buf[n] = '\0';
        
        // Замінюємо нуль-байти на пробіли, крім останнього
        for(size_t i = 0; i < n; i++) {
            if (buf[i] == '\0') {
                buf[i] = ' ';
            }
        }
        printf("My cmdline: %s\n", buf);
        fclose(f);
    }
    return 0;
}
```
== Python
```python
import os

pid = os.getpid()
filepath = f"/proc/{pid}/cmdline"

# Читаємо як байти, оскільки файл розділений нуль-байтами
with open(filepath, "rb") as f:
    raw_data = f.read()
    
# Замінюємо \x00 на пробіл і декодуємо
cmdline = raw_data.replace(b'\x00', b' ').decode('utf-8').strip()
print(f"My cmdline: {cmdline}")
```
