# 📋 Довідник внутрішньої структури файлів /proc/[pid]/

Цей довідник містить повну технічну специфікацію форматів, полів та внутрішніх структур даних основних файлів у директорії процесу `/proc/[pid]/`. Він призначений для системних програмістів, розробників засобів моніторингу та діагностики, яким потрібне точне розуміння кожного байта інформації, що повертається псевдофайловою системою `procfs`.

Структура файлів у `/proc/[pid]/` відображає внутрішні об'єкти ядра Linux, що описують процес. Усі текстові файли форматовано в ASCII і розроблено для максимальної швидкості розбору або людиною, або автоматичними аналізаторами.

## 1. /proc/[pid]/status — Зведення стану та ресурсів процесу

Файл `/proc/[pid]/status` генерується ядром через функцію `proc_pid_status()` і призначений для швидкого огляду ключових параметрів процесу у форматі текстових пар `Ключ: Значення`. Кожен рядок завершується символом переводу рядка `\n`.

### Семантика показників пам'яті у status
Особливу увагу при системному аналізі слід приділяти блоку `Vm*`. Показник `VmSize` відображає повний обсяг віртуального адресного простору, зарезервованого процесом, включаючи спроектовані файли та неініціалізовану пам'ять. Натомість `VmRSS` (Resident Set Size) показує лише той обсяг, який дійсно підкріплений фізичними сторінками в оперативній пам'яті (RAM).

Співвідношення між компонентами фізичної пам'яті описується тотожністю:

```text
VmRSS = RssAnon + RssFile + RssShmem
```

де `RssAnon` відображає анонімну пам'ять (купа, стек, анонімні мапінги `mmap`), `RssFile` — сторінки дискового кешу, спроектовані з файлів, а `RssShmem` — пам'ять у спільних сегментах (`shmem`, `tmpfs`). Показник `VmSwap` описує обсяг сторінок даного процесу, витиснутих підсистемою витіснення в простір підкачки на диску.

### Семантика привілеїв та розмежування доступу
Блок `Cap*` містить 64-бітні маски привілеїв POSIX Capabilities у 16-ричному форматі. Для декодування цих масок у текстові назви привілеїв (наприклад `CAP_SYS_ADMIN` чи `CAP_NET_ADMIN`) утиліти аналізу виконують побітові операції `AND` з відповідними константами з заголовочного файлу `<linux/capability.h>`.

| `Name` | `string` (до 16 байт) | Ім'я бінарного файлу або потоку з `task_struct->comm`. |

## 2. /proc/[pid]/stat — Детальна специфікація полів рядка стану

Файл `/proc/[pid]/stat` розроблено у ядрі для системних моніторів (`ps`, `top`, `htop`). Він містить 52 поля у єдиному рядку, розділені пробілами.

### Особливість розбору другого поля (comm)
Друге поле (`comm`) взято у круглі дужки. Оскільки назва процесу може містити довільні пробіли та дужки, системні парсери не мають права використовувати розділення рядка за пробілами (`strtok` або `sscanf`). Парсинг обов'язково виконується з шуканням першої дужки `(` від початку рядка та останньої закриваючої дужки `)` від кінця рядка.

### Розрахунок процесорного часу
Поля #14 (`utime`) та #15 (`stime`) містять накопичений процесорний час процесу в тиках системного годинника. Для переведення цих значень у секунди простір користувача ділить отримані числа на системну константу тиків, яка повертається системним викликом `sysconf(_SC_CLK_TCK)` (зазвичай 100 тиків на секунду):

```text
Time_in_Seconds = (utime + stime) / sysconf(_SC_CLK_TCK)
```

## 3. /proc/[pid]/maps та /proc/[pid]/smaps — Специфікація VMA та PSS

Файл `/proc/[pid]/maps` відображає список регіонів пам'яті (VMA). Формат одного рядка:

```text
address           perms offset   dev   inode       pathname
55b8e90a2000-55b8e90a4000 r--p 00000000 08:02 1234567     /usr/bin/cat
55b8e90a4000-55b8e90a9000 r-xp 00002000 08:02 1234567     /usr/bin/cat
7ffc3a5b6000-7ffc3a5d7000 rw-p 00000000 00:00 0           [stack]
```

Поля розшифровуються наступним чином:
- `address`: Початкова та кінцева віртуальні адреси регіону у 16-ричному форматі.
- `perms`: Прапорці доступу: `r` (read), `w` (write), `x` (execute), `p` (private CoW) або `s` (shared).
- `offset`: Зсув у файлі у байтах, з якого завантажено цей регіон.
- `dev`: Мажорний та мінорний номер пристрою у 16-ричному форматі `MAJ:MIN`.
- `inode`: Номер індексного дескриптора на дисковому носії (`0` для анонімних регіонів).
- `pathname`: Шлях до файлу або псевдонім: `[heap]`, `[stack]`, `[vdso]`, `[vvar]`, `[anon_inode:...]`.

### Метрики /proc/[pid]/smaps
Файл `smaps` містить детальне текстове розширення для кожного регіону VMA з `maps`:

- `Size`: Повний віртуальний розмір даного VMA регіону (КіБ).
- `KernelPageSize`, `MMUPageSize`: Розмір сторінки, що використовується ядром та MMU (зазвичай 4 КіБ).
- `Rss`: Фактичний обсяг пам'яті VMA, який знаходиться у RAM (КіБ).
- `Pss`: Пропорційний розмір пам'яті (Proportional Set Size).
- `Shared_Clean`, `Shared_Dirty`: Спільні сторінки, які не змінювалися або були модифіковані.
- `Private_Clean`, `Private_Dirty`: Приватні сторінки процесу.
- `Referenced`: Обсяг пам'яті, до якого здійснювався доступ останнім часом.
- `Anonymous`: Обсяг анонімної пам'яті, не підкріпленої файлом на диску.
- `LazyFree`: Пам'ять, яка була позначена викликом `madvise(MADV_FREE)` і може бути звільнена ядром при дефіциті RAM.
- `AnonHugePages`: Обсяг анонімних прозорих великих сторінок (THP, 2 МіБ).
- `Swap`, `SwapPss`: Обсяг пам'яті VMA, витиснутої у простір підкачки Swap.

## 4. Специфікація допоміжних файлів /proc/[pid]/

### /proc/[pid]/mountinfo
Містить докладно описані точки монтування файлових систем, доступні даному процесу:
```text
36 35 0:30 / /sys rw,nosuid,nodev,noexec,relatime shared:7 - sysfs sysfs rw
```
1. `mount ID` — унікальний ідентифікатор точки монтування.
2. `parent ID` — ідентифікатор батьківської точки монтування.
3. `major:minor` — мажорний та мінорний номери пристрою файлової системи.
4. `root` — корінь файлової системи всередині моунта.
5. `mount point` — шлях до точки монтування відносного кореня процесу.
6. `mount options` — прапорці монтування (`rw`, `ro`, `nosuid`, `nodev`, `noexec`).
7. `optional fields` — мітки поширення подій монтування (`shared:X`, `master:X`, `unbindable`).
8. `filesystem type` — тип файлової системи (`ext4`, `sysfs`, `proc`, `tmpfs`).
9. `mount source` — пристрій або джерело монтування.
10. `super options` — суперблокові параметри монтування.

### /proc/[pid]/io
Містить лічильники накопиченого дискового введення-виведення процесу:
- `rchar`: Кількість прочитаних байтів через системні виклики `read()` та `pread()`.
- `wchar`: Кількість записаних байтів через системні виклики `write()` та `pwrite()`.
- `syscr`: Кількість системних викликів читання.
- `syscw`: Кількість системних викликів запису.
- `read_bytes`: Фактичний обсяг байтів, прочитаних з блокового дискового носія (повминаючи дисковий кеш).
- `write_bytes`: Фактичний обсяг байтів, відправлених на дисковий носій.
- `cancelled_write_bytes`: Запис, який було скасовано (наприклад при видаленні тимчасових файлів до виклику `fsync`).
