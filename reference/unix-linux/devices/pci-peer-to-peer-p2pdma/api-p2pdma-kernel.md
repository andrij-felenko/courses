# 📋 Інтерфейси підсистеми pci-p2pdma: функціональне API ядра та sysfs

Ця довідкова вставка містить вичерпний технічний опис програмних інтерфейсів (C API) підсистеми `pci-p2pdma` у ядрі Linux, а також структуру її атрибутів у файловій системі sysfs. У ній деталізовано виклики ядра для реєстрації пам'яті провайдера, виділення буферів із пулу MMIO, перевірки топологічної сумісності пристроїв, побудови таблиць розсіяного передавання (`scatterlist`) та діагностики стану ресурсів прямого доступу між пристроями PCIe.

## 1. Інтерфейси реєстрації провайдера та керування пулом пам'яті

Драйвер периферійного пристрою (наприклад, NVMe накопичувача з буфером CMB/PMR або відеокарти з VRAM), який надає свою пам'ять для інших периферійних модулів, виступає в ядрі в ролі **Провайдера P2P** (P2P Provider). Для експонування фізичного регіону Base Address Register (BAR) підсистемі ядра використовуються наступні функції.

### `pci_p2pdma_add_resource`

Функція призначена для реєстрації діапазону фізичних адрес пам'яті BAR пристрою у загальній підсистемі `pci-p2pdma` та створення відповідних структур `struct page` у зоні `ZONE_DEVICE`.

```c
int pci_p2pdma_add_resource(struct pci_dev *pdev, int bar, size_t offset, size_t size);
```

- **Призначення та внутрішня логіка:** Функція отримує фізичну базову адресу вказаного BAR, додає зсув `offset` і перевіряє, чи не перекривається запитуваний регіон із записами інших драйверів. Далі ядро викликає `devm_memremap_pages()`, створюючи структури `struct page` для кожної 4-кілобайтної сторінки діапазону. Сторінки позначаються типом `MEMORY_DEVICE_PCI_P2PDMA`. Після цього виділений регіон зв'язується з генератором алокації пам'яті `gen_pool`. Внутрішньо ядро виділяє структуру `struct p2pmem_data`, яка прив'язується до поля `pdev->p2pdma`.
- **Аргументи:**
  - `pdev`: Вказівник на структуру `struct pci_dev` пристрою-провайдера.
  - `bar`: Індекс регіону Base Address Register (значення від `0` до `5`).
  - `offset`: Зсув у байтах від початку регіону BAR, з якого починається P2P-пам'ять.
  - `size`: Розмір зареєстрованого регіону пам'яті в байтах.
- **Повертане значення:** `0` у разі успішного завершення операції, або від'ємний код помилки (`-ENOMEM` при браку пам'яті під структури сторінок, `-EINVAL` при невірно вказаних параметрах BAR, або `-EBUSY` при колізії ресурсів).

### `pci_alloc_p2pmem`

Виділяє суцільний буфер пам'яті потрібного розміру з пулу раніше зареєстрованого провайдера P2PDMA.

```c
void *pci_alloc_p2pmem(struct pci_dev *pdev, size_t size);
```

- **Призначення та внутрішня логіка:** Функція звертається до внутрішнього генератора пулу пам'яті `gen_pool`, прив'язаного до пристрою `pdev`, і знаходить вільну ділянку MMIO відповідного розміру. Повернений віртуальний вказівник відносіться до ядрового мапування MMIO і може бути конвертований у `struct page` за допомогою функції `virt_to_page()`. При виділенні пам'яті ядро автоматично враховує вимоги щодо вирівнювання адрес на межу сторінки (`PAGE_SIZE`).
- **Аргументи:**
  - `pdev`: Вказівник на `struct pci_dev` пристрою-провайдера.
  - `size`: Запитуваний розмір буфера в байтах.
- **Повертане значення:** Віртуальний вказівник ядра (`void*`) на виділений буфер або `NULL`, якщо у пулі провайдера немає достатнього обсягу вільного місця.

### `pci_free_p2pmem`

Повертає раніше виділений буфер у пул вільної P2P-пам'яті провайдера.

```c
void pci_free_p2pmem(struct pci_dev *pdev, void *addr, size_t size);
```

- **Призначення та аргументи:** Звільняє блок пам'яті за віртуальною адресою `addr` розміром `size` байтів, повертаючи його у пул `gen_pool` пристрою `pdev`. Функція скидає лічильники посилань сторінок та повертає біти в бітмап вільних блоків.

### `pci_p2pdma_enable_store`

Допоміжна функція ядра для обробки запису в sysfs-атрибут `published`.

```c
int pci_p2pdma_enable_store(const char *buf, struct pci_dev *pdev, bool *published);
```

- **Призначення:** Розбирає текстове значення у буфері `buf` (рядки `"1"`, `"0"`, `"true"`, `"false"`) і змінює стан доступності провайдера для системного алокатора P2PDMA.

## 2. Інтерфейси аналізу топології та обчислення відстані

Перед програмуванням DMA-рушіїв ядро повинно переконатися, що маршрутизація TLP-пакетів між клієнтом та провайдером не блокується апаратними мостами PCIe та правилами Access Control Services (ACS).

### `pci_p2pdma_distance_many`

Обчислює матрицю топологічної відстані та можливість виконання P2P DMA між одним або кількома пристроями-клієнтами (Initiators) та пристроєм-провайдером (Target).

```c
int pci_p2pdma_distance_many(struct pci_dev *provider, struct device **clients,
                             int num_clients, bool verbose);
```

- **Призначення та внутрішня логіка:** Функція виконує обхід дерева пристроїв PCI від клієнтів вгору до провайдера, перевіряючи прапорці ACS (`P2P Request Redirect`, `Direct Translation`) на кожному проміжному мосту. На основі отриманої карти топології функція обчислює один із типів відстані:
  - `P2PDMA_MAP_BUS_ADDR`: Пристрої підключені до одного PCIe Switch. Пакети проходять локально шиною без задіяння CPU та IOMMU.
  - `P2PDMA_MAP_THRU_HOST_BRIDGE`: Пакети проходять через Root Complex.
  - `P2PDMA_MAP_NOT_SUPPORTED`: P2P DMA між даними пристроями неможливий або блокується правилами безпеки.
- **Аргументи:**
  - `provider`: Вказівник на `struct pci_dev` пристрою-провайдера.
  - `clients`: Масив вказівників на `struct device` пристроїв-клієнтів.
  - `num_clients`: Кількість елементів у масиві `clients`.
  - `verbose`: Якщо `true`, ядро виводить у `dmesg` детальне пояснення причин, якщо P2P-маршрутизація блокується (наприклад, через наявність ACS Redirect на проміжному порті).
- **Повертане значення:** Числове значення відстані або від'ємний код помилки при неможливості P2P.

### `pci_p2pdma_should_map`

Визначає, чи варто підсистемі виконувати P2P-мапування для заданого пристрою на основі раніше обчисленого типу відстані.

```c
bool pci_p2pdma_should_map(struct pci_dev *pdev, struct device *dev,
                           int distance_type);
```

- **Призначення:** Повертає `true`, якщо тип відстані `distance_type` є припустимим для пристрою `dev` (тобто дорівнює `P2PDMA_MAP_BUS_ADDR` або `P2PDMA_MAP_THRU_HOST_BRIDGE` з активною підтримкою IOMMU).

## 3. Мапування буферів та робота зі Scatterlist

Для передачі буферів P2PDMA в апаратні DMA-рушії клієнтських пристроїв використовуються спеціалізовані функції мапування списків розсіювання (`scatterlist`).

### `pci_p2pdma_map_sg`

Підставляє шинні адреси DMA у масив `struct scatterlist`, який містить сторінки `struct page` з P2P-пам'яті.

```c
int pci_p2pdma_map_sg(struct device *dev, struct scatterlist *sg, int nents,
                      enum dma_data_direction dir);
```

- **Призначення та логіка:** На відміну від стандартної `dma_map_sg()`, яка працює з RAM і налаштовує трансляцію IOMMU, `pci_p2pdma_map_sg()` визначає тип відстані між `dev` та провайдером сторінок у `sg`. У випадку `P2PDMA_MAP_BUS_ADDR` функція отримує фізичну адресу BAR провайдера і прямо записує її як DMA-адресу в кожен елемент `sg` (`sg_dma_address(sg)`). Якщо відстань дорівнює `P2PDMA_MAP_THRU_HOST_BRIDGE`, функція викликає `iommu_map_sg_table()` для налаштування сторінок IOMMU.
- **Аргументи:**
  - `dev`: Вказівник на `struct device` пристрою-Ініціатора (Client).
  - `sg`: Вказівник на масив елементів `struct scatterlist`.
  - `nents`: Кількість записів у масиві `sg`.
  - `dir`: Напрямок передачі (`DMA_TO_DEVICE`, `DMA_FROM_DEVICE`, `DMA_BIDIRECTIONAL`).
- **Повертане значення:** Кількість успішно замапованих елементів `sg` або `0` в разі відмови.

### `pci_p2pdma_unmap_sg`

Скасовує DMA-мапування елементів `scatterlist` після завершення операції передачі даних.

```c
void pci_p2pdma_unmap_sg(struct device *dev, struct scatterlist *sg, int nents,
                        enum dma_data_direction dir);
```

- **Призначення:** Звільняє ресурси IOMMU (якщо мапування проходило через Root Complex) та скидає DMA-адреси у розсіяному списку.

### `pci_p2pdma_file_mmap`

Допоміжна функція драйвера для реалізації системного виклику `mmap()` на символьний пристрій `/dev/p2pmemX`.

```c
int pci_p2pdma_file_mmap(struct pci_dev *pdev, struct vm_area_struct *vma);
```

- **Призначення:** Налаштовує віртуальну область пам'яті процесу (`vma`), підставляючи фізичні сторінки MMIO BAR із прапорцями `VM_IO | VM_PFNMAP` та некешованим типом доступу `pgprot_noncached()`.

## 4. Структура файлової системи sysfs

Підсистема P2PDMA експонує атрибути керування у каталозі sysfs для кожного пристрою PCIe, що зареєстрував P2P-пам'ять.

Шлях до атрибутів у системі:
`/sys/bus/pci/devices/<domain>:<bus>:<device>.<func>/p2pmem/`

### Деталізований опис атрибутів sysfs

1. **`available_segments` (Читання):** Текстове поле, яке показує кількість доступних фрагментів та загальний обсяг вільної P2P-пам'яті у байтах. Внутрішньо опитує лічильники алокатора `gen_pool`.
2. **`size` (Читання):** Загальний розмір зареєстрованого пулу P2P-пам'яті пристрою у байтах.
3. **`published` (Читання / Запис):** Логічний прапор (`1` або `0`). При записі `1` пул додається до загальносистемного списку публічних провайдерів, що дозволяє іншим підсистемам (наприклад, NVMe-oF Target) автоматично використовувати цей буфер.
4. **`allocate` (Запис):** При записі розміру в байтах створює екземпляр символьного пристрою у `/dev/p2pmemX` для тестування з простору користувача.

## 5. Зведені коди помилок та діагностичні прапорці

| Код помилки | Назва | Причина виникнення у P2PDMA |
| :--- | :--- | :--- |
| `-ENOMEM` | Out of Memory | Недостатньо вільного місця у пулі `gen_pool` або виснажено структури `struct page` для `ZONE_DEVICE`. |
| `-EINVAL` | Invalid Argument | Невірно вказано номер BAR, зсув або недопустимий напрямок DMA (`DMA_NONE`). |
| `-EIO` | Input/Output Error | Апаратна топологія або налаштування ACS унеможливлюють проходження TLP між пристроями. |
| `-EBUSY` | Resource Busy | Запитуваний діапазон BAR уже зайнятий іншим драйвером без підтримки P2P. |
| `-EOPNOTSUPP` | Operation Not Supported | Спроба P2PDMA на пристрої, мости якого відхиляють TLP через відсутність підтримки Root Complex. |
