# 📜 Еволюція мобільних шин: від I2C та SPI до стандарту MIPI I3C

Початок 2000-х років ознаменувався бурхливим розвитком мобільних пристроїв, який супроводжувався вибуховим зростанням кількості вбудованих сенсорів. Якщо перші мобільні телефони містили лише базові датчики температури та акумулятора, то сучасні смартфони, планшети, ношувані пристрої та плати автомобільних систем оснащені десятками різноманітних периферійних компонентів: акселерометрами, гіроскопами, магнітометрами, датчиками освітленості, вимірювачами наближення, тонометрами, барометрами та сканерами відбитків пальців.

Історично для з'єднання центрального процесора (SoC) з такими периферійними пристроями використовувалися дві базові шини: I2C (Inter-Integrated Circuit), створена компанією Philips у 1982 році, та SPI (Serial Peripheral Interface), розроблена компанією Motorola в середині 1980-х років. Попри свою популярність, обидва стандарти у XXI столітті зіткнулися з фундаментальними обмеженнями апаратної масштабованості.

## 1. Апаратна криза класичних шин I2C та SPI

Шина I2C використовує двопровідну топологію (лінія даних SDA та лінія тактування SCL) на основі відкритого стоку (Open-Drain). Це дозволяє легко об'єднувати десятки пристроїв на двох лініях, але підтягувальні резистори (Pull-Up Resistors) створюють обмеження за швидкістю через тривалий час наростання фронту сигналу (RC-константа кола). Стандартний режим (Standard-mode) забезпечував швидкість лише 100 кбіт/с, Швидкий режим (Fast-mode) — 400 кбіт/с, а Fast-mode Plus — 1 Мбіт/с.

При цьому кожен сенсор вимагав додаткової окремої лінії GPIO для передачі апаратного переривання (Interrupt Line). У системі з 15 сенсорами це вимагало використання 2 ліній шини I2C та 15 окремих фізичних виводів SoC для переривань, що спричиняло дефіцит контактів корпусів (Pin Count Collapse) та підвищувало складність розведення друкованих плат.

З іншого боку, шина SPI пропонувала високу швидкість передачі (десятки мегабіт на секунду) завдяки push-pull виходам та повнодуплексному режиму. Проте SPI вимагає щонайменше чотирьох ліній (SCLK, MOSI, MISO, CS), а для кожного нового пристрою на шині потрібна додаткова виділена лінія вибору чіпа (Chip Select — CS). Для 15 пристроїв шина SPI потребувала б 3 + 15 = 18 фізичних ліній, що абсолютно неприйнятно для мобільних пристроїв із жорсткими обмеженнями на площу кристала та трасування плат.

## 2. Формування ініціативи MIPI Alliance та розробка стандарту

У 2014 році альянс MIPI (Mobile Industry Processor Interface Alliance) сформував робочу групу Sensor Working Group, до складу якої увійшли провідні напівпровідникові компанії, включаючи Intel, Qualcomm, NXP, STMicroelectronics, Synopsys, InvenSense та Cadence. Метою групи стало створення нового уніфікованого стандарту периферійного інтерфейсу, який поєднав би переваги обох старих шин:

- Збереження двопровідної топології I2C (дві лінії SDA/SCL);
- Підвищення швидкості передачі до рівня SPI (понад 10 Мбіт/с) без збільшення кількості провідників;
- Усунення окремих ліній переривань шляхом передачі сигналу переривання прямо по лініях шини (In-Band Interrupts — IBI);
- Відмова від статичних 7-бітних адрес для вирішення проблеми колізій однакових сенсорів різних виробників (Dynamic Address Assignment — DAA);
- Значне зниження енергоспоживання (енергія на переданий біт у 10–100 разів менша за I2C);
- Апаратна зворотна сумісність із класичними пристроями I2C.

У грудні 2016 року було офіційно опубліковано специфікацію MIPI I3C v1.0. Новий стандарт запровадив активний push-pull режим для тактування та даних після завершення процедури адресації, що дозволило досягти базової швидкості SDR (Single Data Rate) до 12.5 МГц. Для забезпечення ще вищої пропускної здатності було додано режими HDR (High Data Rate), зокрема HDR-DDR (Double Data Rate) із передачею по обох фронтах сигналу, досягаючи швидкості до 33.3 Мбіт/с.

Для розширення доступності стандарту поза межами приватного альянсу у 2018 році було опубліковано публічну специфікацію MIPI I3C Basic v1.0. Ця версія поширюється без роялті та ліцензійних відрахувань, що дозволило відкритим проектам та виробникам контролерів без перешкод реалізовувати підтримку I3C у своїх мікроконтролерах.

З появою стандарту MIPI I3C v1.1 у 2019 році та специфікації v1.1.1 у 2021 році специфікація збагатилася підтримкою режиму Secondary Master (передача ролі майстра між кількома контролерами), додатковими командами розширеної діагностики та покращеною підтримкою гарячого підключення (Hot-Join).

## 3. Історія впровадження підсистеми I3C у ядро Linux

У спільноті Linux підтримка I3C почала активне формування в середині 2018 року. До цього моменту виробники розробляли власні закриті або несистемні драйвери для специфічних SoC, що призводило до дублювання коду та відсутності єдиного API.

Інженер Борис Брезійон (Boris Brezillon) із компанії Bootlin (раніше Free Electrons) розробив та запропонував архітектуру підсистеми ядра Linux I3C Subsystem. Архітектура була спроектована з урахуванням досвіду підсистем I2C та SPI, але забезпечувала фундаментальні абстракції для управління динамічними адресами, CCC командами та обробкою IBI у підпрограмах ядра.

Підсистему I3C офіційно прийняли до основного дерева ядра Linux у релізі Linux 5.0 у грудні 2018 року. 

Створення підсистеми I3C в Linux забезпечило чіткий поділ відповідальності: драйвери апаратних контролерів (наприклад, DesignWare або Cadence) відповідають виключно за фізичний транзит байтів та обробку сигналів PHY, тоді як уніфіковане ядро `i3c-core.c` взяло на себе логіку DAA, таблиці динамічних адрес, диспетчеризацію IBI-переривань та створення віртуальних адаптерів I2C для підтримки старих периферійних драйверів. Це дозволило безшовно інтегрувати MIPI I3C у сучасний драйверний каркас Linux.
