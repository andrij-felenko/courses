# 📋 Специфікація .link-файлів та змінні ID_NET_NAME

Файли конфігурації `.link` у підсистемах `systemd-udevd` та `systemd-networkd` визначають низькорівневі декларативні політики іменування, генерації MAC-адрес та параметрів фізичного каналу для кожного мережевого інтерфейсу під час його реєстрації в ядрі.

## Ієрархія та пріоритет файлів .link

Конфігураційні файли зчитуються під час завантаження системи та обробки подій uevent із чотирьох системних каталогів у строгому порядку спадання пріоритету:

| Каталог | Пріоритет | Призначення |
| :--- | :--- | :--- |
| `/etc/systemd/network/` | Найвищий | Локальні налаштування системного адміністратора хоста |
| `/run/systemd/network/` | Високий | Динамічні тимчасові налаштування, згенеровані під час роботи системи |
| `/usr/local/lib/systemd/network/` | Середній | Локально скомпільовані або встановлені адміністратором пакунки |
| `/usr/lib/systemd/network/` | Базовий | Типові правила дистрибутива (постачаються пакунком `systemd`) |

Усі файли в цих каталогах збираються в єдиний список і сортуються за лексикографічним порядком їхніх імен файлів (наприклад, `10-wan.link` обробляється раніше за `99-default.link`) незалежно від каталогу розташування.

Якщо файл з ідентичною назвою міститься в кількох каталогах, використовується лише версія з каталогу з найвищим пріоритетом. Наприклад, створення порожнього файлу або символічного посилання на `/dev/null` за шляхом `/etc/systemd/network/99-default.link` повністю блокує (маскує) системний файл `/usr/lib/systemd/network/99-default.link`.

Для кожного файлу підтримуються каталоги доповнень (drop-in): каталог із назвою `<імен_файлу>.link.d/` може містити додаткові конфігураційні файли з розширенням `.conf`, які перевизначають або доповнюють секції основного файлу.

Типова поведінка операційної системи визначається файлом `/usr/lib/systemd/network/99-default.link`:

```ini
[Match]
OriginalName=*

[Link]
NamePolicy=keep kernel database onboard slot path mac
AlternativeNamesPolicy=database onboard slot path mac
MACAddressPolicy=persistent
```

## Секція [Match]

Секція `[Match]` задає набір критеріїв, яким має відповідати мережевий інтерфейс для застосування параметрів із секції `[Link]`. Якщо зазначено кілька ключів, вони об'єднуються логічною операцією «ТА» — інтерфейс повинен відповідати всім вказаним умовам одночасно.

Під час появи пристрою парсер `systemd-udevd` перебирає завантажені структури конфігурацій і зіставляє параметри пристрою з критеріями секції `[Match]`. Якщо хоча б один параметр не збігається, файл ігнорується, і демон переходить до наступного файлу в списку.

| Параметр | Тип значення | Опис і правила зіставлення |
| :--- | :--- | :--- |
| `MACAddress=` | Список MAC-адрес | Поточна апаратна MAC-адреса інтерфейсу. Підтримуються маски та зіставлення за префіксами OUI (наприклад, `00:11:22:33:44:55` або `00:50:56:*`). |
| `PermanentMACAddress=` | Список MAC-адрес | Початкова постійна MAC-адреса, зашита в EEPROM контролера (зчитується через ethtool), навіть якщо поточна адреса була підмінена. |
| `OriginalName=` | Шаблон рядка | Початкове ім'я пристрою, видане ядром під час реєстрації (`eth*`, `wlan*`, `enp*`). Підтримує символи `*`, `?` та переліки `[a-z]`. |
| `Path=` | Шлях sysfs | Топологічний шлях пристрою в підсистемі шини (наприклад, `pci-0000:03:00.0-*` або `platform-*.usb-*`). |
| `Driver=` | Назва драйвера | Назва драйвера ядра Linux, який обслуговує пристрій (наприклад, `e1000e`, `r8169`, `igb`, `mlx5_core`, `virtio_net`). |
| `Type=` | Тип середовища | Тип мережевого носія (наприклад, `ether`, `wlan`, `wwan`, `infiniband`, `bridge`, `bond`, `veth`). |
| `Kind=` | Тип віртуального пристрою | Тип віртуального інтерфейсу (наприклад, `veth`, `vlan`, `macvlan`, `vxlan`, `wireguard`). |
| `Property=` | `КЛЮЧ=ЗНАЧЕННЯ` | Збіг із властивістю оточення udev (наприклад, `ID_MODEL_ID=0x8168` або `ID_VENDOR_FROM_DATABASE=Intel*`). |
| `Host=` | Рядок імені хоста | Системне ім'я машини (`/etc/hostname`). Дозволяє тримати спільний образ диска для різних серверів. |
| `Virtualization=` | Булеве або тип гіпервізора | Перевірка виконання у віртуальному середовищі (`yes`, `no`, `kvm`, `qemu`, `vmware`, `oracle`, `xen`). |
| `KernelCommandLine=` | Рядок аргументу | Перевірка наявності зазначеного параметра в командному рядку завантаження ядра `/proc/cmdline`. |
| `KernelVersion=` | Шаблон версії | Версія запущеного ядра Linux (наприклад, `>= 6.1` або `6.8.*`). |
| `Architecture=` | Архітектура CPU | Апаратна архітектура (`x86-64`, `arm64`, `riscv64`). |
| `WLANInterfaceType=` | Тип Wi-Fi режиму | Режим бездротового інтерфейсу (`ad-hoc`, `station`, `ap`, `monitor`). |
| `SSID=` | Назва мережі | SSID поточної бездротової мережі для застосування специфічних параметрів каналу. |

## Секція [Link]

Секція `[Link]` містить директиви налаштування іменування, генерації адрес, апаратного розвантаження та фізичного рівня зв'язку.

### Політика вибору імені (NamePolicy=)

Директива `NamePolicy=` приймає список назв схем іменування, розділених пропусками. Демон udev опитує зазначені схеми зліва направо і призначає інтерфейсу перше успішно сформоване ім'я, яке не є порожнім.

Під час виконання `link_config_apply()` кожна схема перевіряється за спеціалізованим алгоритмом:

1. **keep:** udev перевіряє, чи не було пристрій уже перейменовано користувацькими утилітами або попередніми кроками ініціалізації. Якщо прапорець `dev->name_assign_type` дорівнює `NET_NAME_USER`, поточне ім'я залишається без змін.
2. **kernel:** перевіряється, чи вимагає конфігурація зберегти початкове ім'я, призначене ядром під час реєстрації (`NET_NAME_ENUM`).
3. **database:** виконується запит до скомпільованої бази даних обладнання `hwdb` (`/usr/lib/udev/hwdb.bin`) за ключем ідентифікатора вендора та пристрою шини PCI/USB. Якщо виробник зареєстрував спеціальну назву для цієї моделі, вона береться як ім'я.
4. **onboard:** аналізуються таблиці прошивки SMBIOS Type 41 та методи ACPI `_DSM`. Якщо знайдено індекс вбудованого порту на материнській платі, генерується назва `eno<index>`.
5. **slot:** аналізується каталог `/sys/bus/pci/slots/`. Якщо контролер підключено до розніму гарячої заміни PCI Express Hotplug, зчитується номер слота і генерується ім'я `ens<slot>`.
6. **path:** виконується рекурсивний обхід ієрархії шини в sysfs від пристрою до кореневого моста. Будується ім'я на основі домену, номера шини, слота й функції PCI (`enp<bus>s<slot>`) або топології портів USB-хабів.
7. **mac:** зчитується апаратна адреса пристрою. Якщо адреса є глобально адміністрованою (біт локального адміністрування дорівнює нулю), генерується назва `enx<MAC>`.

| Назва схеми | Механізм і джерело топології | Приклад результату |
| :--- | :--- | :--- |
| `keep` | Зберігає наявне ім'я, якщо інтерфейс уже було перейменовано простором користувача. | `custom0`, `wan0` |
| `kernel` | Залишає початкове порядкове ім'я, яке виділило ядро під час виклику `dev_alloc_name()`. | `eth0`, `wlan0` |
| `database` | Зчитує запропоновану назву з апаратної бази udev hwdb на основі ID виробника та пристрою. | `lan0`, `modem0` |
| `onboard` | Зчитує індекс вбудованого пристрою з таблиць SMBIOS Type 41 або методів ACPI `_DSM`. | `eno1`, `eno2` |
| `slot` | Зчитує номер слота гарячої заміни PCI Express Hotplug із `/sys/bus/pci/slots/`. | `ens1`, `ens1f0` |
| `path` | Обчислює фізичний топологічний шлях шини (домен PCI, шина, пристрій, функція, порти USB). | `enp3s0`, `enp0s20f0u1` |
| `mac` | Формує ім'я з дванадцяти шістнадцяткових цифр глобально адміністрованої MAC-адреси. | `enx78e7d1ea46da` |

Якщо жодна зі схем не змогла отримати коректні дані від апаратного забезпечення (наприклад, прошивка не має таблиць SMBIOS, шина не підтримує слоти, а MAC-адреса є локально адміністрованою), ім'я залишається незмінним — у форматі ядра `eth%d`.

### Політика альтернативних імен (AlternativeNamesPolicy=)

Директива `AlternativeNamesPolicy=` формує список додаткових імен інтерфейсу, які реєструються в ядрі Linux через Netlink за допомогою атрибута `IFLA_ALT_IFNAME` (підтримується починаючи з версії `systemd v245` та ядра 5.4).

Директива приймає ті самі схеми, що й `NamePolicy=`. Усі згенеровані назви, окрім основної, автоматично додаються як альтернативні псевдоніми пристрою. Ядро підтримує до 64 альтернативних імен на один інтерфейс, кожне з яких має відповідати обмеженню довжини `IFNAMSIZ - 1` (15 символів).

Коли системна утиліта звертається до ядра за іменем інтерфейсу (наприклад, `ip addr show dev enp3s0`), ядро виконує пошук як за первинною назвою в таблиці `dev_name_head`, так і за хеш-таблицею альтернативних псевдонімів. Це дозволяє уникнути конфліктів у скриптах автоматизації, які можуть звертатися до інтерфейсу за різними найменуваннями.

### Політика генерації MAC-адрес (MACAddressPolicy=)

Директива `MACAddressPolicy=` керує тим, як формується апаратна адреса для віртуальних або динамічно створюваних пристроїв.

Режим `persistent` обчислює сталу псевдовипадкову MAC-адресу на основі криптографічного алгоритму:

1. Зчитується системний ідентифікатор Machine ID з файлу `/etc/machine-id`.
2. Додається назва інтерфейсу, топологічний шлях пристрою або початкова апаратна адреса.
3. Обчислюється хеш за алгоритмом SHA-256 або SipHash-2-4.
4. Перші 6 байтів результату приводяться до формату коректного MAC: біт `unicast` скидається в `0`, а біт `locally administered` встановлюється в `1`.

Завдяки цьому мости (`bridge`), агреговані зв'язки (`bond`) та віртуальні комутатори зберігають однакову MAC-адресу після кожного перезавантаження хоста, що запобігає зміні виданих IP-адрес на серверах DHCP.

| Параметр | Значення | Опис |
| :--- | :--- | :--- |
| `MACAddressPolicy=` | `persistent` | Генерує детерміновану сталу MAC-адресу на основі SHA-256 від Machine ID та імені порту. |
| `MACAddressPolicy=` | `random` | Генерує випадкову локально адміністровану MAC-адресу при кожній появі інтерфейсу. |
| `MACAddressPolicy=` | `none` | Залишає апаратну MAC-адресу без змін (поведінка ядра). |
| `MACAddress=` | Рядок MAC-адреси | Примусово призначає інтерфейсу статичну MAC-адресу. |

### Налаштування канального рівня та апаратного розвантаження

Секція `[Link]` також дозволяє керувати фізичними параметрами трансивера через підсистему ethtool безпосередньо в момент ініціалізації:

| Параметр | Значення | Опис |
| :--- | :--- | :--- |
| `BitsPerSecond=` | Число (`10M`, `100M`, `1G`, `10G`, `40G`, `100G`) | Примусова фіксація швидкості порту. |
| `Duplex=` | `half`, `full` | Режим передачі: напівдуплекс або повний дуплекс. |
| `AutoNegotiation=` | `yes`, `no` | Увімкнення або вимкнення автоматичного узгодження швидкості каналу. |
| `Port=` | `tp`, `aui`, `bnc`, `mii`, `fibre` | Тип фізичного порту та середовища передачі. |
| `MTUBytes=` | Розмір у байтах (наприклад, `9000`) | Розмір максимального блоку передачі (Jumbo Frames). |
| `WakeOnLan=` | `phy`, `unicast`, `multicast`, `broadcast`, `magic`, `off` | Налаштування режиму пробудження комп'ютера через мережевий пакет (WoL). |
| `ReceiveChecksumOffload=` | `yes`, `no` | Апаратна перевірка контрольних сум вхідних пакетів IP/TCP/UDP. |
| `TransmitChecksumOffload=` | `yes`, `no` | Апаратний розрахунок контрольних сум вихідних пакетів. |
| `TCPSegmentationOffload=` | `yes`, `no` | Апаратна сегментація великих TCP-пакетів мережевим чипом (TSO). |
| `GenericSegmentationOffload=` | `yes`, `no` | Узагальнене розвантаження сегментації пакетів (GSO). |
| `LargeReceiveOffload=` | `yes`, `no` | Апаратне об'єднання вхідних TCP-сегментів у великі блоки (LRO). |

## Властивості udev, що генеруються утилітою net_id

Вбудований помічник udev `udev-builtin-net_id.c` сканує ієрархію sysfs і публікує в контекст події набір змінних оточення:

```text
# Дані від DMI Type 41 / ACPI _DSM
ID_NET_NAME_ONBOARD=eno1
ID_NET_LABEL_ONBOARD=Embedded NIC 1

# Дані від PCI Express Hotplug Slot
ID_NET_NAME_SLOT=ens1f0

# Дані від топології шини PCI Express
ID_NET_NAME_PATH=enp3s0f0

# Дані від апаратної MAC-адреси
ID_NET_NAME_MAC=enx78e7d1ea46da

# Версія алгоритму іменування systemd
ID_NET_NAMING_SCHEME=v252

# Підсумкове ім'я, обране помічником net_setup_link
ID_NET_NAME=eno1
```

## Версії схеми іменування (Naming Scheme)

Алгоритм обчислення передбачуваних імен розвивався разом із випусками systemd. Щоб оновлення системного демона не змінювало імена наявних мережевих адаптерів на працюючих серверах, systemd підтримує версіонування схем:

| Версія схеми | Випуск systemd | Ключові зміни та виправлення |
| :--- | :--- | :--- |
| `v238` | systemd 238 | Базовий стабільний алгоритм обчислення PCI-шляхів та індексів слотів. |
| `v239` | systemd 239 | Додано підтримку імен для віртуальних функцій SR-IOV (`v<N>`). |
| `v240` | systemd 240 | Виправлено обробку мостів PCI-to-PCI з розширеними доменами PCI. |
| `v241` | systemd 241 | Додано обробку суфіксів портів NPAR (Network Partitioning). |
| `v245` | systemd 245 | Впроваджено підтримку альтернативних імен `AlternativeNamesPolicy=`. |
| `v250` | systemd 250 | Додано підтримку імен для роз'ємів USB Type-C та інтерфейсів WWAN PCIe. |
| `v252` | systemd 252 | Покращено розпізнавання портів комутаторів DSA (Distributed Switch Architecture). |

Адміністратор може зафіксувати версію схеми через аргумент завантаження ядра `net.naming-scheme=v238` або змінну середовища `SYSTEMD_NET_NAMING_SCHEME=v245`.

## Параметри командного рядка ядра

| Параметр ядра | Допустимі значення | Поведінка |
| :--- | :--- | :--- |
| `net.ifnames=` | `1` (за замовчуванням) | Вмикає генерацію передбачуваних імен у `systemd-udevd`. |
| `net.ifnames=` | `0` | Повністю вимикає генерацію передбачуваних імен; інтерфейси зберігають імена `eth0`, `wlan0`. |
| `biosdevname=` | `0` (за замовчуванням) | Вимикає застарілий рушій Dell `biosdevname`. |
| `biosdevname=` | `1` | Активує генерацію імен за правилами Dell `biosdevname` (`em1`, `p1p2`) для сумісності з RHEL 6. |
| `net.naming-scheme=` | `v238`...`latest` | Примусово задає версію алгоритму побудови імен для всієї системи. |

## Інструменти діагностики та перевірки правил

Для з'ясування того, чому інтерфейс отримав конкретне ім'я, і які правила `.link` застосувалися, використовують засоби діагностики `udevadm` та `networkctl`.

### 1. Тестування генератора net_id без застосування змін

```sh
# Перевірка роботи внутрішнього рушія udev для конкретного інтерфейсу
$ udevadm test-builtin net_id /sys/class/net/enp3s0
```

Команда виконує повну імітацію аналізу топології пристрою, завантажує відповідний `.link`-файл і друкує список усіх розрахованих змінних оточення разом із підсумковим вибором `ID_NET_NAME`.

### 2. Перегляд властивостей інтерфейсу через networkctl

```sh
$ networkctl status enp3s0
● 2: enp3s0
       Link File: /usr/lib/systemd/network/99-default.link
    Network File: /etc/systemd/network/20-wired.network
            Type: ether
           State: routable (configured)
          Driver: e1000e
            Path: pci-0000:03:00.0
      Driver Ver: 6.8.0-40-generic
```
