# 📋 Протоколи та структури SMART: бітові поля ATA, NVMe та SCSI

Для отримання телеметрії та діагностичних журналів операційна система взаємодіє з контролером накопичувача через низькорівневі командні кадри відповідного інтерфейсу: ATA Taskfile, NVMe Admin Command або SCSI CDB. Оскільки діагностичні дані не належать до адресного простору користувацьких секторів, ядро не застосовує до них кешування сторінок або планування блокових черг, а переносить байти наскрізним каналом. Цей довідник описує точні розкладки бінарних структур, зміщення полів, коди операцій, бітові маски та інваріанти протоколів телеметрії для накопичувачів ATA/SATA, NVMe та SCSI/SAS.

---

## 1. Командний інтерфейс ATA SMART (Кадр регістрів Taskfile)

У стандарті ATA (INCITS ACS, *ATA/ATAPI Command Set*) усі операції підсистеми самодіагностики виконуються через надсилання команди з кодом `0xB0` у регістр команд (*Command Register*). Тип конкретної дії та формат обміну даними визначаються байтом у регістрі функцій (*Features Register*).

Щоб захистити накопичувач від випадкового виклику діагностичних функцій через збій адресації, стандарт вимагає обов'язкового запису двох магічних констант у регістри номера циліндра: `LBA Mid = 0x4F` та `LBA High = 0xC2`. Якщо ці значення не збігаються, контролер відхиляє команду зі статусом помилки `ABRT` (*Command Aborted*).

| Регістр ATA | Вхідне значення для запиту | Значення у відповіді диска |
| :--- | :--- | :--- |
| **Command** | `0xB0` (SMART Command) | Регістр стану (*Status*): прапорці `BSY`, `DRDY`, `ERR`, `DF` |
| **Features** | Підкоманда (`0xD0`..`0xDA`) | Регістр помилок (*Error*) у разі відхилення команди |
| **Sector Count** | Параметр підкоманди (номер журналу, кількість секторів) | Лічильник переданих секторів |
| **LBA Low** | Параметр підкоманди (код тесту або номер сторінки) | Специфічно для підкоманди |
| **LBA Mid** | `0x4F` (Обов'язкова сигнатура SMART) | `0x4F` (Норма) або `0xF4` (Поріг відмови перевищено) |
| **LBA High** | `0xC2` (Обов'язкова сигнатура SMART) | `0xC2` (Норма) або `0x2C` (Поріг відмови перевищено) |
| **Device** | `0x00` (Master / LBA mode) | Регістр пристрою |

### Перелік підкоманд ATA SMART (Регістр Features)

Виконання кожної підкоманди переводить протокол ATA в один із трьох режимів обміну: передача даних без блоку (Non-Data), прийом даних від пристрою (PIO Data-In) або передача даних на диск (PIO Data-Out).

| Код (Hex) | Назва підкоманди | Режим обміну | Опис операції та призначення |
| :--- | :--- | :--- | :--- |
| `0xD0` | `SMART READ DATA` | PIO Data-In | Зчитування 512-байтової таблиці значень 30 атрибутів здоров'я накопичувача. |
| `0xD1` | `SMART READ THRESHOLDS` | PIO Data-In | Зчитування 512-байтової таблиці критичних заводських порогів (*Thresholds*). |
| `0xD2` | `SMART ENABLE/DISABLE AUTOSAVE` | Non-Data | Керування періодичним збереженням лічильників з ОЗП контролера у службову пам'ять (`Sector Count = 0xF1` — увімкнено, `0x00` — вимкнено). |
| `0xD3` | `SMART SAVE ATTRIBUTE VALUES` | Non-Data | Примусовий аварійний запис поточних значень лічильників з оперативної пам'яті диска в енергонезалежну службову зону. |
| `0xD4` | `SMART EXECUTE OFF-LINE IMMEDIATE`| Non-Data | Запуск або скасування автономного фонового тесту діагностики (код підрежиму передається в регістрі `LBA Low`). |
| `0xD5` | `SMART READ LOG` | PIO Data-In | Читання 512-байтової сторінки службового журналу (адреса журналу вказується в `LBA Low`, обсяг — у `Sector Count`). |
| `0xD6` | `SMART WRITE LOG` | PIO Data-Out | Запис 512-байтової сторінки службового журналу (використовується заводськими калібраторами). |
| `0xD8` | `SMART ENABLE OPERATIONS` | Non-Data | Активація модуля SMART у мікропрограмі накопичувача. |
| `0xD9` | `SMART DISABLE OPERATIONS` | Non-Data | Повна деактивація функцій SMART (усі спроби опитування блокуються мікрокодом). |
| `0xDA` | `SMART RETURN STATUS` | Non-Data | Експрес-перевірка здоров'я: диск оновлює регістри `LBA Mid` та `LBA High` без надсилання 512 байтів даних. |

### Підкоманда EXECUTE OFF-LINE IMMEDIATE (`0xD4`): коди регістру LBA Low

- `0x00` — запуск фонового збору даних за замовчуванням (*Default Off-line data collection*);
- `0x01` — запуск короткого самотестування в автономному режимі (*Short self-test in off-line mode*);
- `0x02` — запуск повного розширеного тесту поверхні (*Extended self-test in off-line mode*);
- `0x03` — запуск тесту на механічні пошкодження під час транспортування (*Conveyance self-test*);
- `0x04` — запуск вибіркового тестування діапазону секторів (*Selective self-test*);
- `0x7F` — негайне примусове скасування активного тесту самодіагностики (*Abort self-test*);
- `0x81` — запуск короткого тесту в монопольному режимі перехоплення шини (*Captive Short*);
- `0x82` — запуск розширеного тесту в монопольному режимі перехоплення шини (*Captive Extended*).

## 2. Структура 512-байтового сектору ATA SMART READ DATA (`0xD0`)

Відповіддю на команду `SMART READ DATA` є блок даних розміром рівно 512 байтів. Таблиця містить до 30 записів про атрибути здоров'я, кожен із яких займає рівно 12 байтів. Завершується блок байтом контрольної суми.

Математичний інваріант контрольної суми: арифметична сума без знаку всіх 512 байтів сектора за модулем 256 повинна дорівнювати нулю (`sum(byte[0..511]) % 256 == 0`). Якщо молодший байт суми відмінний від нуля, сектор вважається пошкодженим під час передачі шиною.

| Зміщення (Байти) | Довжина (Байти) | Назва поля | Призначення та формат даних |
| :--- | :--- | :--- | :--- |
| `0..1` | 2 | `Structure Version` | Номер версії структури SMART (зазвичай `0x0010` або `0x0004`). |
| `2..361` | 360 | `Attribute Entries` | Масив із 30 записів атрибутів здоров'я (30 × 12 байтів = 360 байтів). |
| `362` | 1 | `Off-line Status` | Байт стану фонового збору даних: біти `[6:0]` показують статус виконання та помилки. |
| `363` | 1 | `Self-test Status` | Байт стану процедури самотестування: біти `[7:4]` кодують результат останнього тесту. |
| `364..365` | 2 | `Off-line Time` | Загальний час у секундах, необхідний для виконання фонового збору даних. |
| `366` | 1 | `Vendor Specific` | Байт конфігурації виробника. |
| `367` | 1 | `Off-line Capability`| Прапорці можливостей фонового збору даних (підтримка призупинення, автозапуску). |
| `368..369` | 2 | `SMART Capabilities` | 16-бітна бітова маска характеристик підсистеми SMART (збереження журналів, автозбереження). |
| `370` | 1 | `Error Logging Cap` | Прапорці підтримки стандартного та розширеного журналів помилок. |
| `371` | 1 | `Vendor Specific` | Байт конфігурації виробника. |
| `372` | 1 | `Short Test Time` | Рекомендований час виконання короткого тесту (у хвилинах). |
| `373` | 1 | `Ext Test Time` | Рекомендований час виконання розширеного тесту (якщо `0xFF`, дивись зміщення 375–376). |
| `374` | 1 | `Conveyance Time` | Рекомендований час виконання тесту транспортування (у хвилинах). |
| `375..376` | 2 | `Ext Test Time (Ext)`| Розширене поле тривалості довгого тесту (для містких дисків понад 2 ТБ). |
| `377..510` | 134 | `Reserved` | Зарезервовано для розширень стандарту та пропрієтарних журналів виробника. |
| `511` | 1 | `Checksum` | Контрольна сума сектора (доповнення до нуля суми байтів 0..510). |

### Формат 12-байтового запису атрибута (Зміщення `2 + i * 12`)

Кожен із 30 слотів атрибутів містить фіксовані поля ідентифікації, прапорців, нормалізованого балу та фізичного лічильника. Якщо байт `ID` дорівнює `0x00`, слот вважається порожнім і пропускається парсером.

| Зміщення у записі | Довжина | Назва поля | Опис та інтерпретація значень |
| :--- | :--- | :--- | :--- |
| `0` | 1 байт | `Attribute ID` | Номер атрибута (1–255). Визначає тип показника (наприклад, `0x05` для Reallocated Sectors). |
| `1..2` | 2 байти | `Status Flags` | 16-бітна бітова маска характеристик атрибута (Pre-fail, Online, Error-rate тощо). |
| `3` | 1 байт | `Current Value` | Поточний нормалізований бал надійності (від 1 до 253; 100 або 200 = новий пристрій). |
| `4` | 1 байт | `Worst Value` | Найгірший показник нормалізації за всю історію експлуатації накопичувача. |
| `5..10` | 6 байтів | `RAW Value` | 48-бітне необроблене значення лічильника (години, температура, кількість збоїв). |
| `11` | 1 байт | `Reserved` | Зарезервований байт постачальника. |

### Бітова маска прапорців Status Flags у записі атрибута

- **Біт 0 (Pre-failure / Advisory):** `0` = Атрибут старіння (*Old-age*), що відбиває природний знос механіки або пам'яті; `1` = Критичний індикатор надійності (*Pre-failure*). Якщо нормалізоване значення такого атрибута падає нижче порогу `Threshold`, накопичувач прогнозує фатальну відмову впродовж найближчих 24 годин.
- **Біт 1 (Online collection):** `0` = Значення оновлюється лише під час виконання автономних тестів; `1` = Значення оновлюється під час звичайних операцій введення-виведення.
- **Біт 2 (Performance):** `1` = Атрибут відбиває продуктивність пристрою (швидкість пошуку доріжки, швидкість розгону).
- **Біт 3 (Error rate):** `1` = Атрибут фіксує частоту виникнення апаратних збоїв.
- **Біт 4 (Event count):** `1` = Атрибут є монотонно зростаючим лічильником фізичних подій (циклів паркування, стартів шпинделя).
- **Біт 5 (Self-preserving):** `1` = Атрибут зберігає накопичені значення в енергонезалежній пам'яті під час перезавантаження.
- **Біти 6..15:** Зарезервовано стандартом.

## 3. Таблиця критичних порогів ATA SMART READ THRESHOLDS (`0xD1`)

Окремим блоком даних розміром 512 байтів накопичувач повертає таблицю заводських порогів відмови, яка завантажується підкомандою `SMART READ THRESHOLDS` (`0xD1`).

Структура цієї таблиці симетрична таблиці атрибутів:
- байти `0..1` містять версію структури порогів;
- байти `2..361` містять 30 12-байтових записів порогів. У кожному записі байт 0 містить `Attribute ID`, байт 1 містить значення `Threshold` (від 0 до 253), а решта 10 байтів зарезервовані;
- байт `511` містить контрольну суму всього сектора.

Правило оцінки працездатності формулюється так: якщо для атрибута з ненульовим `ID` значення `Threshold > 0` і поточне значення `Current Value <= Threshold`, диск перебуває в стані аварійної відмови. Якщо значення `Threshold == 0`, виробник визначає цей атрибут як суто інформаційний без права генерації сигналу SMART Trip.

## 4. Специфікація NVMe SMART / Health Information Log (Log ID `0x02`)

У стандарті NVM Express телеметрія отримується надсиланням адміністративної команди **Get Log Page** (`Opcode = 0x02`) до черги ASQ контролера `/dev/nvme0`. Журнал здоров'я `0x02` має фіксований розмір 512 байтів і суворо стандартизовану бінарну розкладку, де кожна фізична величина займає заздалегідь визначене місце без постачальницьких варіацій.

Команда конструюється заповненням полів командного слова `CDW10`: молодший байт `[7:0]` містить номер журналу `0x02`, а байти `[27:16]` містять кількість подвійних слів (Dwords) мінус один: для 512 байтів (128 Dwords) записується значення `127` (`0x007F0002`).

| Зміщення | Розмір | Назва поля | Формат та фізичний зміст поля |
| :--- | :--- | :--- | :--- |
| `0` | 1 байт | `critical_warning` | Бітова маска аварійних станів накопичувача та масиву пам'яті. |
| `1..2` | 2 байти | `composite_temperature` | Поточна інтегральна температура контролера та носія у Кельвінах (`°C = K - 273.15`). |
| `3` | 1 байт | `available_spare` | Відсоток залишкової резервної місткості NAND (від 0% до 100%). |
| `4` | 1 байт | `available_spare_threshold` | Поріг залишкового резерву (при падінні нижче виставляється тривога). |
| `5` | 1 байт | `percent_used` | Оцінка спожитого ресурсу комірок у відсотках (100% = ліміт TBW; може перевищувати 100%). |
| `6..31` | 26 байтів | `reserved` | Зарезервовано консорціумом NVM Express. |
| `32..47` | 16 байтів | `data_units_read` | 128-бітне число: кількість прочитаних блоків даних (1 блок = 1000 секторів по 512B = 512 000 байтів). |
| `48..63` | 16 байтів | `data_units_written` | 128-бітне число: кількість записаних блоків даних (1 блок = 512 000 байтів). |
| `64..79` | 16 байтів | `host_read_commands` | 128-бітне число: загальна кількість виконаних команд читання хоста. |
| `80..95` | 16 байтів | `host_write_commands` | 128-бітне число: загальна кількість виконаних команд запису хоста. |
| `96..111` | 16 байтів | `controller_busy_time` | 128-бітне число: час у хвилинах, упродовж якого контролер був зайнятий I/O. |
| `112..127` | 16 байтів | `power_cycles` | 128-бітне число: сумарна кількість циклів увімкнення живлення. |
| `128..143` | 16 байтів | `power_on_hours` | 128-бітне число: кількість годин перебування під напругою. |
| `144..159` | 16 байтів | `unsafe_shutdowns` | 128-бітне число: кількість раптових знеструмлень без команди Standby. |
| `160..175` | 16 байтів | `media_errors` | 128-бітне число: кількість невідновних помилок цілісності даних (Unrecovered Data Errors). |
| `176..191` | 16 байтів | `num_err_log_entries` | 128-бітне число: кількість записів у журналі помилок Error Information Log. |
| `192..195` | 4 байти | `warning_temp_time` | Час у хвилинах, проведений за температури, вищої за поріг попередження. |
| `196..199` | 4 байти | `critical_temp_time` | Час у хвилинах, проведений за критичної температури тротлінгу. |
| `200..215` | 16 байтів | `temp_sensor_1..8` | Масив із 8 16-бітних значень температур окремих термодавачів у Кельвінах. |
| `216..511` | 296 байтів| `reserved` | Зарезервовано для розширень специфікації (Thermal Management, Endurance Groups). |

### Бітова маска байта `critical_warning` (Зміщення 0)

| Біт | Прапорець стану | Стан `1` сигналізує про подію |
| :--- | :--- | :--- |
| **0** | `Available Spare Low` | Залишок резервних блоків опустився нижче встановленого порогу `available_spare_threshold`. |
| **1** | `Temperature Threshold` | Температура перевищила критичну межу нагріву або впала нижче робочого мінімуму. |
| **2** | `Reliability Degraded` | Надійність підсистеми NVM катастрофічно знизилася через масові збої кристалів пам'яті. |
| **3** | `Read Only Mode` | Контролер заблокував запис і перевів накопичувач у режим «Тільки для читання». |
| **4** | `Backup Device Failed` | Відмовив пристрій аварійного живлення енергонезалежного кешу (суперконденсатор PLP). |
| **5** | `Persistent Memory RO` | Постійна пам'ять контролера переведена в режим захисту від запису. |
| **6..7**| `Reserved` | Зарезервовано. |

## 5. Інтерфейс SCSI Log Sense (Команда `LOG SENSE` 0x4C)

Для дисків SAS (Serial Attached SCSI) телеметрія запитується 10-байтовою командою `LOG SENSE` (код операції `0x4C`), яка завантажує спеціалізовані діагностичні сторінки (*Log Pages*).

У відповідь накопичувач повертає 4-байтовий заголовок сторінки (код сторінки та довжина), за яким слідує послідовність параметрів. Кожен параметр починається з 4-байтового дескриптора (номер параметра, прапорці формату та довжина значення), що дозволяє уніфіковано транслювати звіти про збої.

### Основні діагностичні сторінки SCSI Log Sense

| Код сторінки | Назва сторінки | Зміст звіту та діагностична роль |
| :--- | :--- | :--- |
| `0x10` | `Self-Test Results` | Журнал останніх 20 тестів самодіагностики із зазначенням статусу, коду помилки та збійного 64-бітного LBA. |
| `0x15` | `Background Scan` | Статистика фонового автономного сканування поверхні пластин (Medium Scan) та перепризначення блоків. |
| `0x2F` | `Informational Exceptions`| Прямий еквівалент SMART Status: повертає код попередження про відмову (ASC/ASCQ `0x5D/0x00` у разі перетину порогу надійності). |
| `0x02` | `Write Error Counter` | Лічильники виправлених апаратно та невиправних помилок під час операцій запису. |
| `0x03` | `Read Error Counter` | Лічильники виправлених алгоритмом ECC та невиправних помилок під час читання. |
| `0x0D` | `Temperature` | Поточна температура корпусу накопичувача та максимальна зафіксована пікова температура. |
| `0x0E` | `Start-Stop Cycle Counter`| Лічильники циклів запуску шпинделя та подачі живлення. |
