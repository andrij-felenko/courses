## Вступ

Підсистема USB (Universal Serial Bus) в ядрі Linux має складну, багаторівневу архітектуру, що забезпечує підтримку тисяч різних пристроїв — від простих мишок до складних мережевих адаптерів та відеокамер. Основне завдання цієї підсистеми полягає у абстрагуванні апаратних деталей USB-контролерів та наданні уніфікованого інтерфейсу для драйверів пристроїв (Device Drivers). 

Підсистема USB в Linux складається з трьох основних рівнів:
1. **Host Controller Drivers (HCD)** — драйвери хост-контролерів (апаратна частина).
2. **USB Core** — ядро USB підсистеми (маршрутизація, управління пристроями).
3. **USB Device Drivers** — драйвери конкретних пристроїв (наприклад, драйвер флешки `usb-storage`).

## Архітектура USB Core

Ядро USB (`USB Core`) діє як посередник між драйверами пристроїв та драйверами хост-контролерів. Воно виконує такі функції:
- Виявлення нових пристроїв (enumeration).
- Управління живленням.
- Маршрутизація даних між драйвером пристрою та HCD за допомогою URB.
- Розбір дескрипторів USB.

## Host Controller Drivers (HCD)

Хост-контролер — це мікросхема на материнській платі (або PCIe карті), яка фізично керує шиною USB. У Linux реалізовано підтримку різних стандартів хост-контролерів:

- **UHCI/OHCI** (USB 1.1) — старі стандарти, швидкість до 12 Мбіт/с.
- **EHCI** (USB 2.0) — High Speed (до 480 Мбіт/с).
- **xHCI** (USB 3.x) — SuperSpeed (5 Гбіт/с і вище). Це домінуючий стандарт на сьогодні.

Драйвер HCD приймає від USB Core абстрактні запити (URB) і перетворює їх у специфічні для апаратного контролера команди.

## USB Request Block (URB)

Будь-який обмін даними між комп'ютером і пристроєм USB у ядрі Linux здійснюється через **USB Request Block (URB)**. Це структура даних (визначена у `include/linux/usb.h`), що описує один запит на передачу даних.

Життєвий цикл URB:
1. **Створення**: Драйвер пристрою виділяє пам'ять для URB.
2. **Ініціалізація**: Драйвер заповнює URB даними.
3. **Відправка**: Драйвер передає URB ядру через функцію `usb_submit_urb()`.
4. **Обробка**: USB Core передає URB до HCD, який взаємодіє з апаратурою. HCD планує передачу даних по шині.
5. **Завершення**: Коли передача завершується (успішно або з помилкою), HCD викликає функцію зворотного виклику (callback), визначену в URB, сповіщаючи драйвер пристрою.

## Дескриптори USB

Кожен пристрій USB містить набір дескрипторів, які описують його характеристики та можливості:

1. **Device Descriptor**: Основна інформація про пристрій (Vendor ID, Product ID, версія USB).
2. **Configuration Descriptor**: Описує одну з можливих конфігурацій пристрою.
3. **Interface Descriptor**: Описує логічну функцію пристрою.
4. **Endpoint Descriptor**: Описує кінцеву точку (endpoint), через яку відбувається передача даних.

Ці дескриптори ядро зчитує під час процесу enumeration.

## Структура usb_driver

Щоб написати драйвер для USB-пристрою в Linux, розробник повинен створити структуру `usb_driver` і зареєструвати її в підсистемі за допомогою `usb_register()`.

```c
static struct usb_driver my_usb_driver = {
    .name       = "my_usb_device",
    .probe      = my_usb_probe,
    .disconnect = my_usb_disconnect,
    .id_table   = my_usb_table,
};
```

- **name**: Ім'я драйвера (відображається в sysfs).
- **id_table**: Таблиця Vendor ID та Product ID пристроїв, які підтримує цей драйвер.
- **probe**: Функція, яка викликається, коли підсистема USB виявляє пристрій.
- **disconnect**: Функція, яка викликається при відключенні пристрою.

## Утиліта lsusb

В просторі користувача найпопулярнішим інструментом для взаємодії з інформацією про USB є утиліта `lsusb` (з пакета `usbutils`). Вона зчитує дані з `/sys/bus/usb/devices/` і `/dev/bus/usb/`.

Команда `lsusb -v` (verbose) дозволяє переглянути детально всі дескриптори підключених пристроїв, включаючи інтерфейси та кінцеві точки, що надзвичайно корисно для розробників драйверів при відлагодженні.
