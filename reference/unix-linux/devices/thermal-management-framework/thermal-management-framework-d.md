# Термальний фреймворк ядра (Linux Thermal Framework)

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

У сучасних комп'ютерних системах, від мобільних пристроїв на базі SoC до високопродуктивних серверів, контроль температури є критично важливим для забезпечення стабільності, довговічності компонентів і оптимальної продуктивності. Термальний фреймворк ядра Linux (Linux Thermal Framework) надає стандартизовану, гнучку та розширювану архітектуру для моніторингу температури та керування охолодженням.

Цей документ детально розглядає архітектуру термального фреймворку, його ключові компоненти, такі як термальні зони (thermal zones), пристрої охолодження (cooling devices), точки спрацьовування (trip points) та регулятори (governors), а також методи їх налаштування та взаємодії через sysfs.

## 1. Архітектура та основні концепції

Linux Thermal Framework спроєктовано як модульну підсистему, яка абстрагує апаратні датчики температури та механізми охолодження, надаючи єдиний інтерфейс для простору користувача (user space) і механізмів внутрішньоядерного керування.

### Основні рівні архітектури:

1. **Апаратний рівень (Hardware):** Фізичні датчики температури (наприклад, термістори, вбудовані датчики в CPU/GPU), а також механізми охолодження (вентилятори, механізми зміни частоти та напруги DVFS для CPU/GPU).
2. **Драйвери пристроїв (Device Drivers):**
   - **Драйвери датчиків:** Зчитують показники температури з апаратного забезпечення і передають їх у термальний фреймворк.
   - **Драйвери охолодження:** Надають інтерфейс для керування станом охолодження (наприклад, драйвер `cpufreq` для масштабування частоти процесора).
3. **Термальне ядро (Thermal Core):** Центральна частина підсистеми, яка реєструє зони та пристрої охолодження, обробляє події, оновлює температури та викликає відповідні регулятори (governors).
4. **Термальні регулятори (Thermal Governors):** Алгоритми, які приймають рішення про те, як і коли активувати пристрої охолодження залежно від поточної температури та заданих точок спрацьовування (trip points).
5. **Інтерфейс користувача (Sysfs):** Розташований у `/sys/class/thermal/`, надає механізм для моніторингу та конфігурації.

## 2. Термальні зони (Thermal Zones)

Термальна зона — це логічне об'єднання датчика температури, набору точок спрацьовування (trip points) та прив'язаних до неї пристроїв охолодження (cooling devices). Вона представляє певну фізичну область системи (наприклад, ядро процесора, акумулятор, графічний чип), температуру якої потрібно контролювати.

У файловій системі sysfs кожна термальна зона представлена у вигляді каталогу `/sys/class/thermal/thermal_zoneN/`, де `N` — це індекс зони (починаючи з 0).

### Основні атрибути термальної зони (у sysfs):

- **`type`:** Рядок, що описує тип зони (наприклад, `x86_pkg_temp`, `cpu-thermal`, `acpitz`).
- **`temp`:** Поточна температура зони в міліградусах Цельсія (m°C). Наприклад, значення `45000` означає 45.0 °C.
- **`policy`:** Поточний термальний регулятор (governor), який керує цією зоною (наприклад, `step_wise`).
- **`available_policies`:** Список доступних регуляторів, які можна призначити цій зоні.
- **`mode`:** Стан зони, зазвичай `enabled` або `disabled`.

### Періодичний моніторинг (Polling)
Деякі апаратні датчики підтримують переривання при досягненні певних температур. Проте, багато простих датчиків вимагають періодичного опитування (polling). Для цього в термальній зоні можна налаштувати `polling_delay` (інтервал опитування в мілісекундах) та `passive_delay` (інтервал опитування, коли температура перевищила пасивну точку спрацьовування і система активно намагається охолодити пристрій).

## 3. Точки спрацьовування (Trip Points)

Точки спрацьовування визначають температурні пороги, при досягненні яких система має вжити певних дій для охолодження або захисту обладнання. Кожна термальна зона може мати кілька точок спрацьовування.

Вони представлені у sysfs як файли `trip_point_M_temp`, `trip_point_M_type`, і `trip_point_M_hyst` (де `M` — індекс точки спрацьовування для даної зони).

### Типи точок спрацьовування:

1. **`passive` (Пасивна):** 
   Коли температура досягає цього порогу, система починає пасивне охолодження. Пасивне охолодження зазвичай означає зниження продуктивності (тротлінг) — наприклад, зниження тактової частоти CPU або GPU (за допомогою драйверів `cpufreq` або `devfreq`). Це дозволяє зменшити тепловиділення без використання активних елементів (вентиляторів) або як доповнення до них.

2. **`active` (Активна):**
   Досягнення цієї точки ініціює активне охолодження. Зазвичай це означає увімкнення вентилятора або збільшення його швидкості. Система може мати кілька активних точок спрацьовування для покрокового збільшення швидкості вентилятора (наприклад, `active[0]`, `active[1]`).

3. **`hot` (Гаряча):**
   Критично висока температура, але ще не настільки, щоб вимкнути систему апаратно. Досягнення цієї точки зазвичай ініціює екстрені заходи з боку ядра, такі як надсилання повідомлення користувацькому простору (через uevent або thermal netlink) для збереження даних або підготовки до сну/гібернації. Якщо система не встигає відреагувати, температура продовжуватиме зростати.

4. **`critical` (Критична):**
   Це поріг апаратного пошкодження. Коли температура досягає критичної точки спрацьовування, термальний фреймворк негайно (і жорстко) вимикає систему або ініціює перезавантаження, щоб запобігти фізичному розплавленню або згорянню компонентів. Ця операція виконується ядром в обхід стандартних процедур зупинки системи.

### Гістерезис (Hysteresis)
Щоб запобігти постійному перемиканню (oscillation) стану охолодження, коли температура коливається навколо точки спрацьовування (наприклад, 70°C), використовується гістерезис (`trip_point_M_hyst`). Якщо точка спрацьовування встановлена на 70000 m°C, а гістерезис на 2000 m°C, охолодження увімкнеться при 70°C, але не вимкнеться, поки температура не впаде нижче 68°C.

## 4. Пристрої охолодження (Cooling Devices)

Пристрій охолодження — це апаратний або програмний компонент, здатний зменшувати тепловиділення або відводити тепло. У sysfs вони представлені в `/sys/class/thermal/cooling_deviceN/`.

### Типові пристрої охолодження:

- **Процесори (CPUFreq / CPUIdle):** Драйвер `cpu_cooling` використовує підсистему `cpufreq` для обмеження максимальної частоти процесора. При пасивному охолодженні губернатор може "затиснути" (throttle) CPU.
- **Вентилятори (Fans):** Апаратні вентилятори з підтримкою керування швидкістю (PWM).
- **GPU (Devfreq):** Зниження частоти графічного ядра.
- **Підсвітка екрана (Backlight):** Зниження яскравості екрана в мобільних пристроях для зменшення нагріву.
- **Powercap / RAPL:** Обмеження лімітів енергоспоживання (power limits) на архітектурах Intel (RAPL).

### Стани охолодження (Cooling States)
Кожен пристрій охолодження має поточний стан (`cur_state`) і максимальний стан (`max_state`).
- Для вентилятора стан `0` може означати "вимкнено", а `max_state` (наприклад, `10`) — максимальну швидкість.
- Для CPU стан `0` означає відсутність тротлінгу (максимальна продуктивність), а `max_state` — мінімально можливу частоту (максимальний тротлінг).

### Прив'язка (Binding)
Пристрої охолодження повинні бути "прив'язані" (bound) до термальної зони та конкретної точки спрацьовування. Наприклад, можна прив'язати `cooling_device0` (CPU) до `trip_point_0` (пасивна) термальної зони `thermal_zone0`, щоб при досягненні цієї точки процесор почав знижувати частоту.

## 5. Термальні регулятори (Governors)

Регулятори — це "мозок" термального фреймворку. Вони аналізують температуру зони, перевіряють точки спрацьовування і вирішують, який стан встановити для кожного прив'язаного пристрою охолодження.

Ядро Linux пропонує кілька різних губернаторів, які можна вибирати динамічно через файл `policy` термальної зони.

### 5.1. `step_wise` (Покроковий)
Це найпоширеніший регулятор, який часто використовується за замовчуванням. Його логіка проста і надійна:
- Якщо температура перевищує точку спрацьовування, він поступово (покроково) збільшує стан охолодження (наприклад, підвищує швидкість вентилятора або рівень тротлінгу на один крок) під час кожного циклу опитування.
- Якщо температура нижче точки спрацьовування, він поступово зменшує стан охолодження.
Цей плавний підхід запобігає різким стрибкам продуктивності або гучному шуму вентиляторів.

### 5.2. `power_allocator` (Розподільник потужності)
Сучасний і складний регулятор, створений переважно для мобільних систем (ARM SoC). Замість простого управління частотою, він працює з бюджетом потужності (в міліватах).
Він використовує PID-регулятор (Proportional-Integral-Derivative) для оцінки того, скільки сумарної потужності може розсіяти пристрій при заданій температурі. Потім він динамічно "розподіляє" цей бюджет потужності між різними компонентами (наприклад, CPU і GPU) на основі їхнього поточного навантаження або пріоритетів.
Для його роботи драйвери повинні підтримувати модель енергоспоживання (Energy Model).

### 5.3. `fair_share` (Справедлива частка)
Використовується, коли до однієї термальної зони прив'язано кілька пристроїв охолодження (наприклад, CPU і GPU нагрівають один і той самий кристал). Governor "справедливо" розподіляє необхідність охолодження між усіма пристроями на основі їхньої "ваги" (weight), щоб не "душити" лише один компонент.

### 5.4. `bang_bang`
Використовується переважно для вентиляторів. Він працює за принципом увімкнено/вимкнено (bang-bang) з використанням гістерезису. Коли температура перевищує поріг — вентилятор вмикається. Коли падає нижче порогу з урахуванням гістерезису — повністю вимикається. Він не використовує проміжні стани швидкості.

### 5.5. `user_space`
Дозволяє передати керування термальною політикою в простір користувача (user space). Ядро лише повідомляє про зміну температури через події (uevents/netlink), а спеціальний демон у просторі користувача (наприклад, `thermald`) читає ці події і сам змінює значення `cur_state` пристроїв охолодження.

## 6. Інтеграція з Device Tree

Для вбудованих систем та ARM SoC конфігурація термальних зон, датчиків, точок спрацьовування та маппінгу охолодження зазвичай задається в Device Tree (DTS).

```dts
thermal-zones {
    cpu_thermal: cpu-thermal {
        polling-delay-passive = <250>; /* Мілісекунди */
        polling-delay = <1000>;
        thermal-sensors = <&tsens 0>; /* Посилання на апаратний датчик */

        trips {
            cpu_alert0: cpu-alert0 {
                temperature = <75000>; /* 75 градусів */
                hysteresis = <2000>;
                type = "passive";
            };
            cpu_crit: cpu-crit {
                temperature = <105000>; /* 105 градусів */
                hysteresis = <2000>;
                type = "critical";
            };
        };

        cooling-maps {
            map0 {
                trip = <&cpu_alert0>;
                cooling-device = <&cpu0 THERMAL_NO_LIMIT THERMAL_NO_LIMIT>;
            };
        };
    };
};
```
У цьому прикладі описано термальну зону процесора. При 75°C (passive) починається пасивне охолодження (за допомогою `cpu0`). При 105°C (critical) система буде екстрено вимкнена ядром.

## 7. Відладка та взаємодія (Простір користувача)

Адміністратори та розробники можуть використовувати sysfs для моніторингу та тестування:

1. **Читання температури:**
   ```bash
   cat /sys/class/thermal/thermal_zone0/temp
   ```

2. **Перегляд точок спрацьовування:**
   ```bash
   cat /sys/class/thermal/thermal_zone0/trip_point_*_temp
   ```

3. **Зміна регулятора (Governor):**
   ```bash
   echo step_wise > /sys/class/thermal/thermal_zone0/policy
   ```

4. **Ручне керування охолодженням (тестування вентилятора):**
   ```bash
   # Відв'язуємо від зони, щоб ядро не перекривало наші команди (якщо потрібно)
   echo 5 > /sys/class/thermal/cooling_device0/cur_state
   ```

### Демон `thermald`
На десктопних системах, особливо ноутбуках Intel, часто працює простір-користувацький демон `thermald`. Він використовує розширені можливості апаратного забезпечення (наприклад, Intel RAPL, P-states) для керування теплом. Якщо ядро використовує `user_space` governor або якщо `thermald` працює поверх `step_wise`, він може забезпечувати кращий баланс продуктивності та температури, використовуючи специфічні для платформи XML-конфігурації (наприклад, `thermal-conf.xml`).

## Висновок

Linux Thermal Framework — це критично важлива підсистема, яка забезпечує модульний підхід до управління теплом. Абстрагуючи датчики від механізмів охолодження через термальні зони, та дозволяючи обирати алгоритми-регулятори, Linux може ефективно працювати як на малопотужних смартфонах з їхніми складними термальними обмеженнями, так і на потужних серверах зі складними системами активного охолодження. Розуміння цієї архітектури є ключовим для системного програмування, налаштування вбудованих пристроїв та діагностики проблем з продуктивністю та перегрівом.
