# 📋 Інтерфейси thermal sysfs та Thermal Netlink Generic API

Цей довідник надає повний опис користувацьких, програмних та системних інтерфейсів взаємодії з термальним фреймворком ядра Linux. У ньому розбирається структура ієрархії віртуальних атрибутів у файловій системі `/sys/class/thermal/`, двійковий сокетний протокол Thermal Generic Netlink, а також C API реєстрації термальних зон та пристроїв охолодження всередині ядра.

## 1. Структура дерев sysfs (`/sys/class/thermal/`)

Віртуальна файлова система sysfs є первинним текстовим інтерфейсом інспекції та конфігурації термального фреймворку. Усі об'єкти підсистеми групуються у піддиректорії віртуальної директорії `/sys/class/thermal/`.

Підсистема термального фреймворку експортує дві основні категорії об'єктів: термальні зони (`thermal_zoneN`) та пристрої охолодження (`cooling_deviceN`), де `N` — це ідентифікатор об'єкта, приписний ядром під час реєстрації.

### Атрибути термальної зони (`/sys/class/thermal/thermal_zoneN/`)

Термальна зона представляє конкретний фізичний або логічний домейн нагріву. Її атрибути дозволяють зчитувати поточну температуру, переглядати та змінювати алгоритми керування теплом, а також контролювати режими опитування датчиків.

- **`type`** (`r--r--r--`, String): Унікальний текстовий ідентифікатор типу термальної зони. Наприклад, `cpu-thermal` для температурного датчика ядра процесора, `x86_pkg_temp` для сумарного пакета Intel x86, `battery` для акумуляторного блоку або `gpu-thermal` для графічного кристала.
- **`temp`** (`r--r--r--`, Integer): Поточне значення температури зони, виражене у міліградусах Цельсія (m°C). Для отримання значення у звичайних градусах Цельсія прочитане число слід поділити на 1000. Наприклад, прочитане значення `48500` відповідає 48.5 °C.
- **`policy`** (`rw-r--r--`, String): Назва поточного активного термального регулятора (governor), який здійснює розрахунок станів охолодження для даної зони. Адміністратор системи або демон користувача може змінити регулятор у реальному часі шляхом запису назви одного з доступних регуляторів у цей файл (наприклад, `echo step_wise > policy`).
- **`available_policies`** (`r--r--r--`, String): Перелік усіх регуляторів, скомпільованих у ядрі або завантажених як модулі, які дозволено призначати для цієї зони (наприклад, `step_wise power_allocator fair_share bang_bang user_space`).
- **`mode`** (`rw-r--r--`, String): Перемикач стану моніторингу зони. Значення `enabled` означає, що ядро активно опитує датчик та розраховує стани охолодження. Значення `disabled` призупиняє обробку точок спрацьовування.
- **`passive_delay`** (`r--r--r--`, Integer): Періодичність опитування датчика зони у мілісекундах (мс), яка застосовується після того, як температура зони перетинала принаймні один пасивний поріг (`passive trip point`).
- **`polling_delay`** (`r--r--r--`, Integer): Базова періодичність опитування датчика зони у мілісекундах у штатному режимі, коли температура знаходиться нижче пасивних порогів. Для датчиків, які працюють виключно на апаратних перериваннях, це значення може дорівнювати `0`.

### Атрибути точок спрацьовування (`trip_point_M_*`)

Кожна точка спрацьовування всередині термальної зони має власний набір файлів атрибутів, де `M` позначає нульовий індекс точки спрацьовування (наприклад, `trip_point_0_temp`, `trip_point_1_temp`):

- **`trip_point_M_temp`** (`rw-r--r--`, Integer): Порогове значення температури спрацьовування у міліградусах Цельсія. Якщо права доступу дозволяють запис, простір користувача може змінювати температурний поріг на льоту.
- **`trip_point_M_hyst`** (`rw-r--r--`, Integer): Значення температурного гістерезису у міліградусах Цельсія. Визначає нижній поріг вимкнення режиму охолодження (`T_trip - T_hyst`), що запобігає релейному осцилюванню.
- **`trip_point_M_type`** (`r--r--r--`, String): Текстове позначення типу точки спрацьовування. Приймає одне з чотирьох стандартних значень: `passive` (пасивне зниження частоти/простою), `active` (увімкнення вентиляторів), `hot` (сповіщення користувацького простору) або `critical` (аварійне вимкнення живлення).

### Атрибути пристрою охолодження (`/sys/class/thermal/cooling_deviceN/`)

Пристрої охолодження уособлюють виконавчі механізми, які зменшують генерацію тепла або збільшують його відведення.

- **`type`** (`r--r--r--`, String): Назва типу виконавчого пристрою. Приклади: `thermal-cpufreq-0` (обмеження частоти першого кластера CPU), `intel_powerclamp` (впорскування циклів простою), `fan` (ШІМ-вентилятор).
- **`max_state`** (`r--r--r--`, Integer): Максимально допустимий цілочисельний стан охолодження, який підтримується цим пристроєм. Значення `0` завжди відповідає вимкненому охолодженню (повній продуктивності).
- **`cur_state`** (`rw-r--r--`, Integer): Поточний активований рівень охолодження у діапазоні від `0` до `max_state`. Запис у цей файл дозволяє вручну керувати пристроєм (наприклад, примусово встановити швидкість вентилятора для тестування).

## 2. Thermal Generic Netlink API

Двосторонній асинхронний інтерфейс обміну повідомленнями між ядром та простором користувача базується на підсистемі Generic Netlink (`genl`). На відміну від sysfs, Netlink відправляє події у реальному часі через сокетний інтерфейс без потреби періодичного текстового опитування файлів.

### Основні константи ядра (`<linux/thermal.h>`)

Під час створення Netlink-сокета користувацька програма знаходить ідентифікатор сімейства за допомогою назви та підписується на відповідні мультикаст-групи:

```c
#define THERMAL_GENL_FAMILY_NAME    "thermal"
#define THERMAL_GENL_VERSION        0x01
#define THERMAL_GENL_EVENT_GROUP    "event"
#define THERMAL_GENL_SAMPLING_GROUP "sampling"
```

### Перелік команд та подій Netlink (`enum thermal_genl_cmd`)

Протокол Thermal Netlink використовує команди для запиту стану та події для сповіщення простору користувача про термальні зміни:

- **`THERMAL_GENL_CMD_TZ_GET_TEMP`**: Команда-запит від користувача до ядра для отримання актуальної температури термальної зони за її ідентифікатором.
- **`THERMAL_GENL_CMD_TZ_GET_TRIP`**: Команда-запит для зчитування конфігурації точок спрацьовування зони.
- **`THERMAL_GENL_EVENT_TZ_TRIP_UP`**: Подія, що генерується ядром, коли температура зони перетнула поріг точки спрацьовування у напрямку зростання.
- **`THERMAL_GENL_EVENT_TZ_TRIP_DOWN`**: Подія, що генерується ядром, коли температура зони впала нижче порога точки спрацьовування з урахуванням гістерезису.
- **`THERMAL_GENL_EVENT_CPU_CAPABILITY_CHANGE`**: Подія, що інформує про зміну максимальної обчислювальної спроможності ядра CPU через термальний тротлінг підсистеми `cpufreq`.

### Атрибути повідомлень Netlink (`enum thermal_genl_attr`)

Повідомлення Thermal Netlink передаються у вигляді вкладених атрибутів типу TLV (Type-Length-Value):

- `THERMAL_GENL_ATTR_TZ_ID` (`U32`): Унікальний цілочисельний ідентифікатор термальної зони (`zone->id`).
- `THERMAL_GENL_ATTR_TZ_TEMP` (`S32`): Значення температури термальної зони у міліградусах Цельсія.
- `THERMAL_GENL_ATTR_TZ_TRIP_ID` (`U32`): Порядковий індекс точки спрацьовування у зоні.
- `THERMAL_GENL_ATTR_TZ_TRIP_TYPE` (`U32`): Числовий тип точки спрацьовування (`passive`, `active`, `hot`, `critical`).
- `THERMAL_GENL_ATTR_TZ_TRIP_TEMP` (`U32`): Температура точки спрацьовування у m°C.
- `THERMAL_GENL_ATTR_CDEV_ID` (`U32`): Унікальний ідентифікатор пристрою охолодження (`cdev->id`).
- `THERMAL_GENL_ATTR_CDEV_CUR_STATE` (`U32`): Поточний рівень пристрою охолодження.
- `THERMAL_GENL_ATTR_CPU_CAPABILITY_CPU` (`U32`): Логічний номер ядра CPU в системі.
- `THERMAL_GENL_ATTR_CPU_CAPABILITY_PERF` (`U32`): Відносна оцінка доступної продуктивності ядра від `0` до `1024`.

## 3. Модель реєстрації в C API ядра (`<linux/thermal.h>`)

Драйвери апаратних датчиків усередині ядра використовують C API для створення об'єктів термальних зон та передачі їх під контроль термального фреймворку.

Основними структурами даного API є `struct thermal_trip`, `struct thermal_zone_device_ops` та функція реєстрації:

```c
struct thermal_trip {
    int temperature;        /* Поріг у m°C */
    int hysteresis;         /* Гістерезис у m°C */
    enum thermal_trip_type type;
    u8 flags;
};

struct thermal_zone_device_ops {
    int (*get_temp) (struct thermal_zone_device *, int *);
    int (*set_trips) (struct thermal_zone_device *, int, int);
    int (*change_mode) (struct thermal_zone_device *, enum thermal_device_mode);
    int (*set_trip_temp) (struct thermal_zone_device *, int, int);
};

struct thermal_zone_device *
thermal_zone_device_register_with_trips(const char *type,
                                        const struct thermal_trip *trips,
                                        int num_trips,
                                        unsigned int mask,
                                        void *devdata,
                                        const struct thermal_zone_device_ops *ops,
                                        const struct thermal_zone_params *tzp,
                                        int passive_delay,
                                        int polling_delay);
```

Функція `thermal_zone_device_register_with_trips()` створює нову термальну зону в ядрі, реєструє відповідну директорію у sysfs та підключає обраний термальний регулятор.
