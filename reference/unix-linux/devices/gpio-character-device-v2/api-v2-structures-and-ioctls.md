# 📋 Довідник структур даних та ioctl-команд GPIO ABI v2

Цей довідник містить вичерпну технічну специфікацію структур даних, бітових прапорів та системних викликів `ioctl()`, визначених у заголовковому файлі ядра `<linux/gpio.h>` для ABI v2 символьного пристрою GPIO (`/dev/gpiochipN`). Специфікація слугує авторитетним джерелом під час розробки низькорівневих системних утиліт, системних демонів та високопродуктивних драйверів простору користувача.

Усі структури ABI v2 спроектовано з урахуванням суворого вирівнювання типів даних (64-бітне вирівнювання полів `__u64` та `__s64`). Це забезпечує абсолютну бінарну сумісність між 32-бітними програмами простору користувача (наприклад, armv7hf) та 64-бітним ядром Linux (arm64/x86_64) без використання проміжних трансляторів або адаптерів сумісності (compat ioctl wrappers).

Кодування команд `ioctl()` спирається на базовий магічний символ підсистеми GPIO — букву `'B'` (`0x42`). Макроси `_IOR`, `_IOW` та `_IOWR` обчислюють унікальний 32-бітний код команди, об'єднуючи напрямок передачі даних (наприклад, read/write), розмір аргументу в байтах, магічний байт `'B'` та порядковий номер команди.

## 1. Запити до головного дескриптора контролера (`/dev/gpiochipN`)

Первинна взаємодія з контролером починається з відкриття символьного пристрою `open("/dev/gpiochipN", O_RDWR | O_CLOEXEC)`. Отриманий файловий дескриптор підтримує такі виклики `ioctl()`:

### 1.1. `GPIO_GET_CHIPINFO_IOCTL`

Отримання загальних метаданих про контролер GPIO, його назву у ядрі, системну мітку та загальну кількість фізичних ліній.

```c
struct gpiochip_info {
    char name[32];   /* Назва чипа в ядрі (наприклад, "gpiochip4" або "3f200000.gpio") */
    char label[32];  /* Назва драйвера або пристрою (наприклад, "pinctrl-bcm2835") */
    __u32 lines;     /* Загальна кількість фізичних ліній GPIO на контролері */
};
```

* **Опис полів:**
  * `name`: Унікальна назва символьного пристрою у системі. Відповідає імені вузла у файловій системі `/dev/`.
  * `label`: Мітка драйвера ядра або назва компонента з Device Tree / ACPI, який зареєстрував цей контролер.
  * `lines`: Загальна кількість доступних пінів на даному чипі (зазвичай від 8 до 128).
* **Сигнатура виклику:** `ioctl(chip_fd, GPIO_GET_CHIPINFO_IOCTL, struct gpiochip_info *info)`
* **Кодування ioctl:** `_IOR('B', 0x01, struct gpiochip_info)`

---

### 1.2. `GPIO_V2_GET_LINEINFO_IOCTL`

Отримання інформації про поточний стан, назву, споживача та конфігурацію конкретної лінії без її захоплення або блокування.

```c
struct gpio_v2_line_info {
    char name[32];      /* Назва лінії з Device Tree або ACPI (наприклад, "GPIO17_SDA") */
    char consumer[32];  /* Назва модуля ядра або процесу, який володіє лінією */
    __u32 offset;       /* Індекс лінії на контролері (0 .. lines-1) */
    __u32 num_attrs;    /* Кількість активних елементів у attrs[] */
    __u64 flags;        /* Бітова маска прапорів стану (GPIO_V2_LINE_FLAG_*) */
    struct gpio_v2_line_attribute attrs[10]; /* Масив розширених атрибутів лінії */
    __u32 padding[4];   /* Резерв для майбутніх розширень ядра */
};
```

* **Опис полів:**
  * `name`: Рядкова назва піна, присвоєна у схемі платформи або дереві пристроїв. Порожній рядок, якщо назва не задана.
  * `consumer`: Текстовий ідентифікатор споживача. Якщо лінію захоплено драйвером ядра або процесом через ABI v2, містить передану назву.
  * `offset`: Вхідний параметр. Перед викликом `ioctl()` додаток повинен записати сюди індекс лінії (0 .. `lines`-1).
  * `num_attrs`: Кількість дійсних атрибутів у масиві `attrs[]`, які описують специфічні параметри (наприклад, дебаунс).
  * `flags`: Активна 64-бітна бітова маска прапорів, яка відображає поточний напрямок, підтяжку та режими роботи лінії.
* **Сигнатура виклику:** `ioctl(chip_fd, GPIO_V2_GET_LINEINFO_IOCTL, struct gpio_v2_line_info *info)`
* **Кодування ioctl:** `_IOWR('B', 0x05, struct gpio_v2_line_info)`

---

### 1.3. `GPIO_V2_GET_LINEINFO_WATCH_IOCTL` та `GPIO_V2_GET_LINEINFO_UNWATCH_IOCTL`

Підписка на асинхронне відстеження змін конфігурації лінії іншими процесами або драйверами ядра.

```c
struct gpio_v2_line_info_changed {
    struct gpio_v2_line_info info; /* Оновлена інформація про лінію */
    __u64 timestamp_ns;             /* Часова мітка зміни у наносекундах */
    __u32 event_type;               /* Тип події: REQUESTED, RELEASED, CONFIG_CHANGED */
    __u32 padding[5];
};
```

* **Типи подій (`event_type`):**
  * `GPIO_V2_LINE_CHANGED_REQUESTED` (`1`): Лінію захоплено новим споживачем у ядрі.
  * `GPIO_V2_LINE_CHANGED_RELEASED` (`2`): Лінію вивільнено, вона повернулася у стан за замовчуванням.
  * `GPIO_V2_LINE_CHANGED_CONFIG_CHANGED` (`3`): Змінено конфігурацію лінії (напрямок, bias, debounce).
* **Сигнатура виклику:** `ioctl(chip_fd, GPIO_V2_GET_LINEINFO_WATCH_IOCTL, struct gpio_v2_line_info *info)`
* **Кодування ioctl:** `_IOWR('B', 0x06, struct gpio_v2_line_info)`
* **Механізм зчитання:** Після оформлення підписки дескриптор `chip_fd` починає сигналізувати про наявність нових даних через `poll()` / `epoll()`. Програма зчитує структури `gpio_v2_line_info_changed` за допомогою системного виклику `read(chip_fd, &changed_info, sizeof(changed_info))`.

## 2. Запит на захоплення ліній (`GPIO_V2_GET_LINE_IOCTL`)

Це головний системний виклик для виділення групи ліній та створення окремого дескриптора керування (Line Request FD).

```c
struct gpio_v2_line_request {
    __u32 offsets[64];              /* Масив індексів ліній на контролері */
    char consumer[32];              /* Назва споживача для ідентифікації в debugfs */
    struct gpio_v2_line_config config; /* Конфігурація для ліній, що запитуються */
    __u32 num_lines;                /* Кількість елементів у offsets[] (1 .. 64) */
    __u32 event_buffer_size;        /* Розмір кільцевого буфера подій переривань */
    __u32 pad[5];
    __s32 fd;                       /* Вихідний файловий дескриптор (Line FD) */
};
```

* **Опис полів:**
  * `offsets`: Список фізичних індексів ліній на даному чипі, які додаток запитує в одного об'єкта захоплення.
  * `consumer`: Текстова назва процесу або модуля, яка буде відображатися у системному інтерфейсі `/sys/kernel/debug/gpio`.
  * `config`: Базові та розширені параметри конфігурації (напрямок, активний рівень, bias, debounce).
  * `num_lines`: Фактична кількість ліній у масиві `offsets[]` (від 1 до 64).
  * `event_buffer_size`: Кількість елементів `struct gpio_v2_line_event` у внутрішньому кільцевому буфері ядра. Якщо передано 0, ядро автоматично виділяє розмір буфера.
  * `fd`: Результуючий файловий дескриптор. При успішному виконанні ядро створює новий файл у VFS та повертає його дескриптор у цьому полі.
* **Сигнатура виклику:** `ioctl(chip_fd, GPIO_V2_GET_LINE_IOCTL, struct gpio_v2_line_request *req)`
* **Кодування ioctl:** `_IOWR('B', 0x07, struct gpio_v2_line_request)`

## 3. Структури конфігурації та атрибутів ліній

Структура `gpio_v2_line_config` задає конфігурацію як для всієї групи ліній за замовчуванням, так і для окремих пінів за допомогою масиву індивідуальних атрибутів.

```c
struct gpio_v2_line_config {
    __u64 flags;        /* Глобальні прапори за замовчуванням для всіх ліній */
    __u32 num_attrs;    /* Кількість активних елементів у attrs[] (до 10) */
    __u32 padding[5];
    struct gpio_v2_line_attribute attrs[10]; /* Перевизначення атрибутів */
};
```

Структура індивідуального атрибута `gpio_v2_line_attribute`:

```c
struct gpio_v2_line_attribute {
    __u32 id;           /* Ідентифікатор атрибута (GPIO_V2_LINE_ATTR_ID_*) */
    __u32 padding;
    __u64 mask;         /* Бітова маска ліній з offsets[], до яких застосовується атрибут */
    union {
        __u64 flags;                /* Нові прапори, якщо id == ATTR_ID_FLAGS */
        __u64 values;               /* Логічні значення, якщо id == ATTR_ID_OUTPUT_VALUES */
        __u32 debounce_period_us;   /* Період придушення брязкоту в мкс, якщо ATTR_ID_DEBOUNCE */
    };
};
```

### 3.1. Детальний розбір ідентифікаторів атрибутів (`id`)

* `GPIO_V2_LINE_ATTR_ID_FLAGS` (`1`): Дозволяє встановити специфічні прапори конфігурації (наприклад, зробити лінію виходом з підтяжкою Pull-Up) лише для тих пінів, чиї біти виставлено в масці `mask`. Бітова маска позиційно прив'язана до масиву `offsets[]`: біт `1 << i` відповідає піну `offsets[i]`.
* `GPIO_V2_LINE_ATTR_ID_OUTPUT_VALUES` (`2`): Встановлює початкові логічні рівні (0 або 1) для вихідних ліній безпосередньо у момент їх захоплення ядром. Це усуває виникнення некоректних проміжних станів (glitches) під час перемикання лінії у режим виходу.
* `GPIO_V2_LINE_ATTR_ID_DEBOUNCE` (`3`): Активує апаратну або програмну фільтрацію брязкоту контакту з затримкою у мікросекундах (`debounce_period_us`) для вказаних у `mask` ліній. Якщо контролер не підтримує апаратний дебаунс, `gpiolib` автоматично створює програмний таймер ядра.

## 4. Бітові прапори конфігурації (`GPIO_V2_LINE_FLAG_*`)

Прапори конфігурації передаються в полі `config.flags` або всередині атрибутів `GPIO_V2_LINE_ATTR_ID_FLAGS`. Вони об'єднуються за допомогою побітового "АБО" (`|`).

| Назва прапора | Значення (Hex) | Опис та призначення |
| :--- | :--- | :--- |
| `GPIO_V2_LINE_FLAG_USED` | `0x0001` | Лінія вже захоплена іншим споживачем у ядрі (прапор лише для читання). |
| `GPIO_V2_LINE_FLAG_ACTIVE_LOW` | `0x0002` | Інверсія логічного рівня: 0 на піні вважається HIGH, 1 — LOW. |
| `GPIO_V2_LINE_FLAG_INPUT` | `0x0004` | Конфігурація лінії як цифрового входу. |
| `GPIO_V2_LINE_FLAG_OUTPUT` | `0x0008` | Конфігурація лінії як цифрового виходу. |
| `GPIO_V2_LINE_FLAG_EDGE_RISING` | `0x0010` | Генерація подій переривання при переході з LOW в HIGH. |
| `GPIO_V2_LINE_FLAG_EDGE_FALLING` | `0x0020` | Генерація подій переривання при переході з HIGH в LOW. |
| `GPIO_V2_LINE_FLAG_OPEN_DRAIN` | `0x0040` | Конфігурація виходу з відкритим стоком (Open Drain). |
| `GPIO_V2_LINE_FLAG_OPEN_SOURCE` | `0x0080` | Конфігурація виходу з відкритим витоком (Open Source). |
| `GPIO_V2_LINE_FLAG_BIAS_PULL_UP` | `0x0100` | Увімкнення внутрішнього підтягуючого резистора до живлення (VCC). |
| `GPIO_V2_LINE_FLAG_BIAS_PULL_DOWN` | `0x0200` | Увімкнення внутрішнього підтягуючого резистора до землі (GND). |
| `GPIO_V2_LINE_FLAG_BIAS_DISABLED` | `0x0400` | Повне вимкнення внутрішніх підтягуючих резисторів (Hi-Z). |
| `GPIO_V2_LINE_FLAG_EVENT_CLOCK_MONOTONIC` | `0x0000` | Використання годинника `CLOCK_MONOTONIC` для міток часу подій. |
| `GPIO_V2_LINE_FLAG_EVENT_CLOCK_REALTIME` | `0x0800` | Використання астрономічного годинника `CLOCK_REALTIME`. |
| `GPIO_V2_LINE_FLAG_EVENT_CLOCK_HTE` | `0x1000` | Використання апаратного модуля міток часу (Hardware Timestamp Engine). |

## 5. Запити до дескриптора ліній (Line Request FD)

Після виклику `GPIO_V2_GET_LINE_IOCTL` подальше керування лініями виконується через повернутий `line_fd`:

### 5.1. `GPIO_V2_LINE_GET_VALUES_IOCTL` та `GPIO_V2_LINE_SET_VALUES_IOCTL`

Структура `gpio_v2_line_values` використовується для масового читання або запису логічних рівнів групи ліній.

```c
struct gpio_v2_line_values {
    __u64 bits; /* Бітова маска значень ліній (1 = HIGH, 0 = LOW) */
    __u64 mask; /* Бітова маска ліній з запиту, які потрібно прочитати/змінити */
};
```

* **Зчитування рівнів:** `ioctl(line_fd, GPIO_V2_LINE_GET_VALUES_IOCTL, struct gpio_v2_line_values *val)`
  * **Кодування ioctl:** `_IOWR('B', 0x0E, struct gpio_v2_line_values)`
  * **Опис:** Додаток записує у `val.mask` біти ліній, стан яких потрібно дізнатися. Ядро повертає актуальні рівні у `val.bits`.
* **Запис рівнів:** `ioctl(line_fd, GPIO_V2_LINE_SET_VALUES_IOCTL, struct gpio_v2_line_values *val)`
  * **Кодування ioctl:** `_IOWR('B', 0x0F, struct gpio_v2_line_values)`
  * **Опис:** Додаток виставляє у `val.mask` біти ліній для зміни, а у `val.bits` — бажані логічні значення.

---

### 5.2. `GPIO_V2_LINE_SET_CONFIG_IOCTL`

Атомарна зміна режимів роботи або конфігурації відкритих ліній без закриття дескриптора `line_fd`.

* **Сигнатура виклику:** `ioctl(line_fd, GPIO_V2_LINE_SET_CONFIG_IOCTL, struct gpio_v2_line_config *cfg)`
* **Кодування ioctl:** `_IOWR('B', 0x0D, struct gpio_v2_line_config)`
* **Опис:** Виклик дозволяє безперервно перемикати лінії між режимами входу та виходу, змінювати затримки дебаунсу або прапори підтяжки без вивільнення володіння лінією у ядрі.

## 6. Зчитування подій переривань (`read(line_fd)`)

Якщо лінії конфігуровано з прапорами відстеження фронтів `GPIO_V2_LINE_FLAG_EDGE_RISING` або `FALLING`, системний виклик `read(line_fd, buffer, count)` повертає масив структур `gpio_v2_line_event`:

```c
struct gpio_v2_line_event {
    __u64 timestamp_ns; /* Часова мітка виникнення переривання у наносекундах */
    __u32 id;           /* Тип фронту: GPIO_V2_LINE_EVENT_GENERAL_RISING (1) або FALLING (2) */
    __u32 offset;       /* Індекс лінії на контролері, де виникла подія */
    __u32 seqno;        /* Глобальний порядковий номер події для даного Line FD */
    __u32 line_seqno;   /* Порядковий номер події конкретно для цієї лінії */
    __u32 padding[6];
};
```

Поля `seqno` та `line_seqno` є критично важливими для діагностики високочастотних сигналів: якщо між двома зчитаними подіями значення `seqno` збільшилося більше ніж на 1, це сигналізує про втрату переривань через переповнення кільцевого буфера ядра.

## 7. Матриця помилок системних викликів ioctl

Під час виконання системних викликів `ioctl()` над символьним пристроєм GPIO ядро може повертати такі стандартні коди помилок у змінній `errno`:

* `EBUSY` ("Device or resource busy"): Щонайменше одна з вказаних у запиті ліній вже захоплена іншим процесом, драйвером ядра або зарезервована підсистемою pinctrl.
* `EINVAL` ("Invalid argument"): Передано некоректний offset лінії (поза межами `0 .. lines-1`), вказано суперечливі прапори (наприклад, одночасно `INPUT` та `OUTPUT`), або перевищено розмір атрибутів.
* `ENODEV` ("No such device"): Символьний пристрій `/dev/gpiochipN` відсутній у системі або відповідний драйвер контролера було розвантажено з ядра.
* `E2BIG` ("Argument list too long"): Передано більше 64 ліній у списку `offsets[]` або кількість атрибутів `num_attrs` перевищує допустимий ліміт 10.
* `EPERM` ("Operation not permitted"): Недостатньо прав доступу VFS для виконання запису у символьний пристрій.
* `ENOMEM` ("Out of memory"): Недокількість системної оперативної пам'яті у ядрі для виділення внутрішнього кільцевого буфера подій `kfifo`.
* `EFAULT` ("Bad address"): Покажчик на структуру даних, переданий у виклик `ioctl()`, посилається на недійсний ділянку адресної пам'яті простору користувача.
