# Протокол атестації пристроїв SPDM на шинах PCIe

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

У сучасних обчислювальних системах, де периферійні пристрої (наприклад, мережеві карти, NVMe-накопичувачі, графічні прискорювачі) мають прямий доступ до оперативної пам'яті через механізм DMA (Direct Memory Access), виникає серйозна загроза безпеці. Зловмисник може підмінити прошивку пристрою або підключити шкідливий пристрій, який буде виконувати несанкціоноване читання чи запис у пам'ять, компрометуючи всю систему (так звані DMA-атаки або атаки Rogue PCIe). Для захисту від таких загроз була розроблена технологія Security Protocol and Data Model (SPDM) у поєднанні з PCIe IDE (Integrity and Data Encryption).

У цій статті ми детально розглянемо архітектуру SPDM, його реалізацію в ядрі Linux (через `libspdm`), механізми захисту від атак та конфігурацію PCIe IDE.

## 1. Загрози з боку периферійних пристроїв

Традиційна архітектура безпеки операційних систем, включно з Linux, зосереджена на захисті пам'яті від процесів користувача (через MMU) та захисті ядра. Проте периферійні пристрої на шині PCIe працюють нижче рівня абстракції ОС.

### DMA-атаки та Rogue PCIe

Пристрій на шині PCIe може генерувати транзакції читання та запису безпосередньо в оперативну пам'ять хоста, минаючи центральний процесор. Це і є суть DMA. Якщо пристрій скомпрометовано, він може:
- Прочитати криптографічні ключі, паролі або інші конфіденційні дані з пам'яті.
- Модифікувати код або структури даних ядра, щоб отримати привілеї (escalation of privileges).
- Обійти механізми захисту, такі як KASLR або Secure Boot.

Для протидії цьому в сучасних системах використовується IOMMU (I/O Memory Management Unit), який обмежує доступ пристроїв лише до певних регіонів пам'яті. Проте IOMMU не вирішує проблему повністю, якщо сам пристрій видає себе за інший (spoofing) або якщо прошивка пристрою була підмінена до завантаження ОС.

## 2. Security Protocol and Data Model (SPDM)

SPDM — це стандарт, розроблений організацією DMTF (Distributed Management Task Force), який надає криптографічні механізми для автентифікації, атестації та обміну ключами з апаратними компонентами.

### Основні цілі SPDM

1. **Автентифікація**: Підтвердження того, що пристрій є тим, за кого себе видає (наприклад, що це справжня мережева карта Intel, а не емулятор зловмисника).
2. **Атестація (Measurement)**: Перевірка цілісності прошивки (firmware) та конфігурації пристрою. Хост може запросити у пристрою криптографічні хеші (measurements) його компонентів.
3. **Обмін ключами**: Встановлення захищеного сеансу зв'язку між хостом і пристроєм для подальшого шифрування трафіку (наприклад, для PCIe IDE).

### Потік виконання SPDM

Процес атестації SPDM включає кілька етапів, як показано на рисунку нижче:

![SPDM Flow](/reference/unix-linux/devices/spdm-device-attestation/img/spdm-flow.svg)
*Рис. 1. Базовий потік повідомлень протоколу SPDM між хостом та пристроєм.*

1. **GET_VERSION / VERSION**: Хост і пристрій узгоджують версію протоколу SPDM (наприклад, 1.0, 1.1 або 1.2).
2. **GET_CAPABILITIES / CAPABILITIES**: Сторони обмінюються інформацією про підтримувані криптографічні алгоритми, можливість атестації, підтримку обміну ключами тощо.
3. **NEGOTIATE_ALGORITHMS / ALGORITHMS**: Вибір конкретних алгоритмів для хешування (наприклад, SHA-384) та цифрових підписів (наприклад, ECDSA або RSA).
4. **GET_DIGESTS / DIGESTS**: Хост запитує хеші сертифікатів пристрою.
5. **GET_CERTIFICATE / CERTIFICATE**: Хост завантажує повний ланцюжок сертифікатів (Certificate Chain) пристрою та перевіряє його кореневий сертифікат (Root of Trust).
6. **CHALLENGE / CHALLENGE_AUTH**: Хост надсилає випадкове число (nonce), а пристрій підписує його своїм приватним ключем, доводячи володіння ним.
7. **GET_MEASUREMENTS / MEASUREMENTS**: Хост запитує криптографічні вимірювання прошивки пристрою. Пристрій повертає підписані дані, які хост може порівняти з еталонними значеннями (Reference Integrity Manifests, RIM).

## 3. Підтримка SPDM у ядрі Linux

Починаючи з версії ядра Linux 6.x, була додана нативна підтримка SPDM для аутентифікації пристроїв на шинах, зокрема PCIe (через протокол CMA - Component Measurement and Authentication над PCIe Data Object Exchange, DOE).

### Архітектура `libspdm`

Linux використовує бібліотеку `libspdm` (вбудовану або підключену як модуль) для реалізації логіки протоколу. Ядро виступає в ролі Requestor (того, хто запитує атестацію), а PCIe пристрій — в ролі Responder.

Підсистема PCI в Linux автоматично ініціює сесію SPDM при виявленні пристрою з підтримкою DOE (Data Object Exchange) та CMA.
Якщо пристрій не проходить атестацію, ядро може застосувати політики:
- Відхилити ініціалізацію драйвера.
- Ізолювати пристрій за допомогою суворих правил IOMMU.
- Згенерувати подію аудиту (audit event) для адміністратора.

## 4. PCIe IDE (Integrity and Data Encryption)

Атестація через SPDM гарантує, що пристрій не був скомпрометований під час завантаження. Але що, якщо зловмисник підключить апаратний сніфер (наприклад, PCIe інтерпозер) до шини під час роботи системи та спробує перехопити або модифікувати TLP-пакети (Transaction Layer Packets)?

Для захисту даних у русі на шині PCIe використовується технологія IDE (Integrity and Data Encryption).

### Як працює IDE

IDE забезпечує конфіденційність (шифрування) та цілісність (захист від модифікації/replay атак) транзакцій на шині PCIe.

![PCIe IDE](/reference/unix-linux/devices/spdm-device-attestation/img/pcie-ide.svg)
*Рис. 2. Шифрування TLP пакетів за допомогою PCIe IDE.*

1. **Встановлення ключів**: Після успішної атестації SPDM хост і пристрій використовують механізм Key Exchange (наприклад, Diffie-Hellman) для генерації спільних сесійних ключів. Ці ключі завантажуються в контролери IDE на обох кінцях з'єднання.
2. **Шифрування TLP**: Коли пристрій або хост надсилають дані, IDE-модуль апаратно шифрує корисне навантаження (payload) пакетів TLP та додає Message Authentication Code (MAC). AES-GCM є типовим алгоритмом.
3. **Перевірка на приймачі**: Отримувач розшифровує TLP, перевіряє MAC та лічильники послідовності. Якщо виявлено модифікацію або повторення пакета (replay attack), з'єднання скидається.

## 5. Практичні аспекти та майбутнє

Впровадження SPDM та IDE кардинально змінює ландшафт безпеки центрів обробки даних (ЦОД). Замість того, щоб довіряти всьому, що підключено до материнської плати, система керується принципом Zero Trust.

Однак, для повноцінної роботи цієї екосистеми потрібна інфраструктура управління ключами (KMS) для розповсюдження та перевірки сертифікатів пристроїв (Device Identity Certificates).

### Висновки

- **SPDM** є стандартом де-факто для криптографічної ідентифікації та перевірки цілісності апаратних компонентів.
- **PCIe IDE** доповнює SPDM, шифруючи трафік на шині для захисту від фізичного перехоплення.
- Ядро Linux активно розвиває підтримку цих технологій, що дозволить створювати системи з безпрецедентним рівнем апаратного захисту від DMA та Rogue PCIe атак.
