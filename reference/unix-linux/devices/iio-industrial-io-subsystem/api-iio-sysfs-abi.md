# 📋 Sysfs ABI та файлова поверхня підсистеми IIO

Цей довідник містить повну технічну специфікацію файлового інтерфейсу sysfs підсистеми Industrial I/O (IIO) в ядрі Linux. Він призначений для розробників системного програмного забезпечення, системних інтеграторів та авторів драйверів ядра, яким потрібне вичерпне розуміння структури атрибутів каталогу `/sys/bus/iio/devices/iio:deviceX/`, правил найменування каналів, стандартизованих фізичних одиниць вимірювання SI, системних масок атрибутів, а також форматів потокової буферизації та асинхронних подій.

## 1. Повна ієрархія та топологія каталогу пристрою IIO

Кожен аналоговий або сенсорний пристрій, зареєстрований у підсистемі IIO, створює власний екземпляр у глобальній ієрархічній системній файловій системі sysfs за шляхом `/sys/bus/iio/devices/iio:deviceX/`, де `X` — це унікальний цілочисельний індекс пристрою, призначений ядром під час реєстрації.

Нижче наведено розгорнуту топологію каталогу з поясненням призначення кожного системного атрибута та підкаталогу:

```
/sys/bus/iio/devices/iio:deviceX/
├── name                      # Текстовий ідентифікатор молі або чипа (наприклад, "ads1115", "mpu6050", "bmp280")
├── dev                       # Старший та молодший номери символьного пристрою у форматі "major:minor" (для /dev/iio:deviceX)
├── uevent                    # Стандартний системний атрибут для генерації подій подсистемі udev
├── current_timestamp_clock   # Джерело системного годинника таймстампів (realtime, monotonic, boottime)
├── sampling_frequency        # Глобальна частота дискретизації сенсора у Геруах (Гц)
├── sampling_frequency_available # Перелік або діапазон доступних частот дискретизації, що підтримуються залізом
│
├── in_voltage0_raw           # Сирий відлік АЦП каналу 0 напруги (необроблений цілочисельний код)
├── in_voltage0_scale         # Множник шкали каналу 0 (переводить скоригований відлік у мілівольти)
├── in_voltage0_offset        # Зсув нуля каналу 0 (апаратне або калібрувальне відхилення нуля)
├── in_voltage1_raw           # Сирий відлік АЦП каналу 1 напруги
├── in_voltage1_scale         # Множник шкали каналу 1
│
├── in_accel_x_raw            # Сире значення лінійного прискорення по осі X
├── in_accel_y_raw            # Сире значення лінійного прискорення по осі Y
├── in_accel_z_raw            # Сире значення лінійного прискорення по осі Z
├── in_accel_scale            # Спільний множник шкали для всіх осей прискорення (м/с²)
│
├── buffer/                   # Підкаталог конфігурації потокового кільцевого буфера
│   ├── enable                # Вмикач/вимикач потокової буферизації (приймає "1" або "0")
│   ├── length                # Максимальна ємність кільцевого буфера kfifo у кількості семплів
│   ├── watermark             # Поріг розбудження процесів у poll()/select() (кількість накопичених семплів)
│   └── data_available        # Поточна кількість семплів, доступних для зчитування з буфера
│
├── scan_elements/            # Прапорці маски селекції каналів для потокового бінарного збору
│   ├── in_voltage0_en        # Прапорець включення каналу voltage0 у бінарний кадр ("1" або "0")
│   ├── in_voltage0_index     # Порядковий зсув (індекс) розташування каналу voltage0 у бінарному кадрі
│   ├── in_voltage0_type      # Специфікація кодування бінарного контейнера (наприклад, le:s16/16msb>>0)
│   ├── in_timestamp_en       # Прапорець включення 64-бітного системного таймстампа
│   └── in_timestamp_type     # Специфікація бінарного контейнера таймстампа (s64/64le)
│
├── trigger/                  # Підкаталог прив'язки апаратного або програмного тригера
│   └── current_trigger       # Текстова назва прив'язаного тригера (наприклад, "sysfstrig0" або "hrtimer_trigger")
│
└── events/                   # Підкаталог конфігурації асинхронних порогових переривань та подій
    ├── in_accel_x_thresh_rising_en     # Активація сповіщення при перевищенні порогу прискорення X
    ├── in_accel_x_thresh_rising_value  # Порогове значення спрацьовування
    ├── in_accel_x_thresh_rising_hysteresis # Гістерезис скидання порогу для запобігання дребезгу
    └── in_accel_mag_falling_en         # Активація події вільного падіння (падіння модуля вектора)
```

## 2. Канонічні правила найменування атрибутів каналів

Імена системних атрибутів у sysfs підпорядковуються суворому алгоритму конструювання рядків, який забезпечує уніфікований доступ до будь-яких пристроїв без знання їхніх внутрішніх апаратних регістрів.

Формат назви атрибута каналу задається наступним шаблоном:

```
[direction]_[type]_[channel]_[modifier]_[attribute]
```

### Напрямок сигналу (`direction`)
- `in`: вхідний аналоговий або цифровий канал (сенсори, аналого-цифрові перетворювачі АЦП / ADC).
- `out`: вихідний аналоговий або цифровий канал (актюатори, цифро-аналогові перетворювачі ЦАП / DAC, генератори сигналів).

### Тип вимірюваної фізичної величини (`type`) та одиниці SI
Ядро Linux IIO встановлює сувору відповідність між типом каналу та канонічними фізичними одиницями вимірювання Міжнародної системи одиниць (SI). Простір користувача завжди отримує значення у цих конкретних одиницях після приводу сирого коду через шкалу та зсув:

| Назва типу у ABI | Фізична величина | Офіційна одиниця вимірювання SI у просторі користувача |
| :--- | :--- | :--- |
| `voltage` | Електрична напруга | Мілівольти (mV) |
| `current` | Електричний струм | Міліампери (mA) |
| `power` | Електрична потужність | Мілівати (mW) |
| `accel` | Лінійне прискорення | Метри за секунду в квадраті (m/s²) |
| `anglvel` | Кутова швидкість (гіроскоп) | Радіани за секунду (rad/s) |
| `magn` | Магнітна індукція (магнітометр) | Гауси (Gauss) |
| `temp` | Температура | Градуси Цельсія (°C) або міліградуси |
| `pressure` | Атмосферний або гідростатичний тиск | Кілопаскалі (kPa) |
| `humidityrelative` | Відносна вологість повітря | Відсотки відносної вологості (%RH) |
| `illuminance` | Освітленість (сенсор амбієнтного світла) | Люкси (Lux) |
| `proximity` | Відстань або наближення об'єкта | Безрозмірна величина або міліметри |
| `resistance` | Електричний опір | Оми (Ohm) |
| `capacitance` | Електрична ємність | Пікофаради (pF) |
| `rot` | Ейлерові кути або квотерніон орієнтації | Радіани (rad) або безрозмірні коефіцінти |
| `incli` | Нахил (інклінометр) | Радіани (rad) |
| `distance` | Лінійна відстань (далекомір) | Метри (m) |
| `velocity` | Лінійна швидкість | Метри за секунду (m/s) |
| `timestamp` | Системний таймстамп ядра | Наносекунди (ns) |

### Модифікатори каналів (`modifier`)
Модифікатори доповнюють тип вимірювання, коли сенсор вимірює векторну величину або має кілька спектральних каналів:
- `x`, `y`, `z`: просторові осей для 3D-акселерометрів, гіроскопів та магнітометрів.
- `light_both`, `light_ir`: спектральні діапазони фотодіодів (широкий спектр видимого світла та інфрачервона область).
- `root_mean_square`: середньоквадратичне значення (RMS) електричного сигналу змінного струму.

## 3. Математика масок та текстового кодування шкал у sysfs

Для переведення цілочисельних відліків АЦП у реальні фізичні величини простір користувача застосовує загальну математичну формулу:

```
Physical_Value = (raw + offset) * scale
```

Де:
- `raw`: цілочисельний сирий відлік АЦП, зчитаний з атрибута `*_raw`.
- `offset`: зсув нульової позначки, зчитаний з атрибута `*_offset` (за замовчуванням дорівнює 0, якщо атрибут відсутній).
- `scale`: множник шкали, зчитаний з атрибута `*_scale`.

### Механізм формування рядків шкали у ядрі

Оскільки ядро Linux у внутрішній реалізації принципово не використовує арифметику з плаваючою крапкою (FPU / Floating Point Unit), розробники драйверів повертають значення шкали у вигляді двох цілих чисел `val` та `val2` через структуру `struct iio_info`.

Ядро форматує ці два числа у текстовий рядок sysfs залежно від константи маски, яку повернула функція `read_raw()`:

1. `IIO_VAL_INT`: Повертає одне ціле число. Рядок у sysfs містить просто значення `val` (наприклад, `2`).
2. `IIO_VAL_INT_PLUS_MICRO`: Повертає дріб із мікро-точністю `(val + val2 / 1000000)`. Якщо `val = 0`, а `val2 = 805664`, ядро згенерує у sysfs текстовий рядок `0.805664062`.
3. `IIO_VAL_INT_PLUS_NANO`: Повертає дріб із нано-точністю `(val + val2 / 1000000000)`. Якщо `val = 0`, а `val2 = 120500`, у sysfs експортується рядок `0.000120500`.
4. `IIO_VAL_FRACTIONAL_LOG2`: Повертає значення дробу `val / 2^val2`. Використовується для АЦП, де рівень шкали прив'язаний до точної розрядності `val2` біт.
5. `IIO_VAL_FRACTIONAL`: Повертає значення прямого дробу `val / val2` (для довільних цілочисельних дільників).

### Системні маски атрибутів драйвера ядра

Під час оголошення масиву `struct iio_chan_spec` розробник драйвера задає рівень доступу до атрибутів через трійку бітових масок:
- `info_mask_separate`: створює унікальний атрибут для кожного каналу окремо (наприклад, `in_voltage0_raw` та `in_voltage1_raw`).
- `info_mask_shared_by_type`: створює єдиний атрибут, спільний для всіх каналів одного типу (наприклад, `in_voltage_scale` для всіх каналів напруги).
- `info_mask_shared_by_dir`: створює єдиний атрибут, спільний для всіх вхідних напрямків (`in_sampling_frequency`).
- `info_mask_shared_by_all`: глобальний атрибут для всього чипа незалежно від каналів.

## 4. Специфікація кодування бінарного кадру в scan_elements

Під час потокового читання через символьний пристрій `/dev/iio:deviceX` дані передаються не текстом, а бінарними масивами. Структура бінарного кадру повністю описується атрибутами підкаталогу `scan_elements/`.

Файл `in_channel_type` містить текстову специфікацію бінарного контейнера каналу, яка складається з п'яти компонентів:

```
[endianness]:[s|u][realbits]/[storagebits][msb|lsb]>>[shift]
```

Розберемо кожен елемент цієї специфікації:
- `endianness`: Порядок байтів у шині даних. Приймає значення `le` (Little-Endian, молодший байт першим) або `be` (Big-Endian, старший байт першим).
- `s` або `u`: Знак числа. `s` означає signed (число зі знаком у доповняльному коді), `u` означає unsigned (беззнакове ціле число).
- `realbits`: Кількість значущих бітів, згенерованих АЦП (наприклад, 12 біт або 18 біт).
- `storagebits`: Розмір контейнера пам'яті у бітах, у якому розміщено виміряне значення (типово 8, 16, 32 або 64 біти).
- `shift`: Кількість бітів, на яку потрібно зсунути прочитаний контейнер вправо для отримання чистих значущих бітів.

### Приклади та розпарсинг специфікацій scan_type:
- `le:s16/16msb>>0`: 16-бітне знакове число у 16-бітному Little-Endian контейнері без зсуву.
- `be:u12/16msb>>4`: 12-бітне беззнакове число у 16-бітному Big-Endian контейнері, вирівняне по старшому біту (MSB) із зсувом на 4 біти вправо.
- `le:s24/32msb>>0`: 24-бітне знакове число у 32-бітному Little-Endian контейнері.
- `be:s32/32msb>>8`: 24-бітне знакове число у 32-бітному Big-Endian контейнері зі зсувом на 8 бітів.

## 5. Специфікація файлового інтерфейсу асинхронних подій

Підкаталог `/sys/bus/iio/devices/iio:deviceX/events/` керує логікою апаратних переривань за пороговими значеннями.

Основні атрибути подій:
- `*_thresh_rising_en`: приймає `1` для включення переривання при зростанні сигналу вище порогу або `0` для вимкнення.
- `*_thresh_rising_value`: настроюване порогове значення в сирих одиницях АЦП або фізичних одиницях.
- `*_thresh_rising_hysteresis`: величини гістерезису, яка запобігає повторним хибним спрацьовуванням переривання при коливанні сигналу поблизу порогової лінії.
- `*_thresh_rising_period`: мінімальний проміжок часу (у секундах), протягом якого сигнал повинен безперервно утримуватися вище порогу для генерації події.

Для зчитування подій додаток відкриває символьний пристрій `/dev/iio:deviceX` та запитує файловий дескриптор подій через системний виклик `ioctl`:

```c
int event_fd;
int ret = ioctl(dev_fd, IIO_GET_EVENT_FD_IOCTL, &event_fd);
```

Отриманий дескриптор `event_fd` підтримує системні виклики `read()`, `poll()` та `select()`. Кожен виклик `read()` повертає 16-байтну структуру `struct iio_event_data`:

```c
struct iio_event_data {
    uint64_t id;        // 64-бітне кодоване число (містить тип каналу, напрямок та тип події)
    int64_t timestamp;  // Системний таймстамп моменту виникнення переривання в наносекундах
};
```
