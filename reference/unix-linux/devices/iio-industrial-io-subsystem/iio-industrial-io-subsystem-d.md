# Підсистема Industrial I/O (IIO) для аналогових сенсорів та ADC/DAC

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

Підсистема Industrial I/O (IIO) у ядрі Linux є стандартизованим фреймворком для підтримки різноманітних сенсорів, аналого-цифрових (ADC) та цифро-аналогових (DAC) перетворювачів. Вона була створена для подолання обмежень старих підходів, таких як використання підсистеми `hwmon` (Hardware Monitoring) або фреймворку `input`, які не були призначені для високошвидкісного збору даних та складних сенсорних пристроїв.

## Архітектура підсистеми IIO

Підсистема IIO складається з кількох ключових компонентів:
1.  **IIO Core**: Ядро підсистеми, яке забезпечує реєстрацію пристроїв та базові функції API для розробників драйверів.
2.  **Sysfs інтерфейс**: Експортує атрибути пристрою у простір користувача через `/sys/bus/iio/devices/`.
3.  **Кільцеві буфери (Ring Buffers)**: Механізм для швидкого та ефективного збору великих обсягів даних із сенсорів.
4.  **Тригери (Triggers)**: Апаратні або програмні події, які ініціюють захоплення даних (наприклад, таймери, переривання від готовності даних).
5.  **Події (Events)**: Механізм для сповіщення простору користувача про певні умови (наприклад, перевищення порогового значення напруги або прискорення).

## Структура iio_dev

Основою будь-якого драйвера IIO є структура `struct iio_dev`. Вона представляє окремий пристрій IIO в ядрі.

```c
struct iio_dev {
    int id;
    int modes;
    int currentmode;
    struct device dev;
    const struct iio_info *info;
    struct mutex info_exist_lock;
    const struct iio_buffer_setup_ops *setup_ops;
    struct cdev chrdev;
    
    // ... інші поля для управління буферами, тригерами та подіями
};
```

Драйвер виділяє цю структуру за допомогою функції `devm_iio_device_alloc()`, заповнює необхідні поля (зокрема `info`, який містить вказівники на функції для читання/запису даних), а потім реєструє пристрій в системі через `devm_iio_device_register()`.

### Структура iio_info

Поле `info` вказує на `struct iio_info`, яка визначає поведінку пристрою:

```c
struct iio_info {
    int (*read_raw)(struct iio_dev *indio_dev,
                    struct iio_chan_spec const *chan,
                    int *val, int *val2,
                    long mask);
    int (*write_raw)(struct iio_dev *indio_dev,
                     struct iio_chan_spec const *chan,
                     int val, int val2,
                     long mask);
    // ... інші callback-функції
};
```

Функція `read_raw` викликається ядром, коли простір користувача запитує дані через sysfs. Параметр `mask` вказує, який саме тип даних запитується (сирі дані, масштаб, зсув тощо).

## Канали IIO

Сенсори та перетворювачі зазвичай мають декілька каналів (наприклад, осі X, Y, Z для акселерометра). У драйвері вони описуються масивом структур `iio_chan_spec`.

```c
static const struct iio_chan_spec my_adc_channels[] = {
    {
        .type = IIO_VOLTAGE,
        .indexed = 1,
        .channel = 0,
        .info_mask_separate = BIT(IIO_CHAN_INFO_RAW) | BIT(IIO_CHAN_INFO_SCALE),
    },
    {
        .type = IIO_VOLTAGE,
        .indexed = 1,
        .channel = 1,
        .info_mask_separate = BIT(IIO_CHAN_INFO_RAW) | BIT(IIO_CHAN_INFO_SCALE),
    }
};
```

## Буфери та Тригери

Для високошвидкісного збору даних безперервне опитування sysfs є неефективним. Тому IIO надає механізм кільцевих буферів та тригерів.

-   **Тригер** визначає, *коли* слід зібрати дані (наприклад, по перериванню або від програмного таймера).
-   **Буфер** зберігає зібрані дані. Простір користувача може читати ці дані масивами через символьний пристрій `/dev/iio:deviceX`.

Щоб використовувати буферизований режим, простір користувача повинен:
1. Включити потрібні канали.
2. Встановити довжину буфера.
3. Вибрати тригер.
4. Увімкнути буфер.
5. Читати дані з `/dev/iio:deviceX`.

## Інтерфейс простору користувача (Sysfs)

Всі пристрої IIO експортуються в директорію `/sys/bus/iio/devices/iio:deviceX`.

Основні атрибути:
-   `name`: Назва пристрою.
-   `in_voltage0_raw`: Сире значення першого каналу напруги (ADC).
-   `in_voltage_scale`: Масштаб, на який треба помножити сире значення для отримання результату у стандартних одиницях (мілівольти).
-   `in_accel_x_raw`: Сире значення прискорення по осі X (акселерометр).
-   `trigger/`: Директорія для конфігурації тригерів.
-   `buffer/`: Директорія для конфігурації буфера (розмір, увімкнення).
-   `scan_elements/`: Директорія для вибору каналів, які будуть записуватись у буфер.

## Висновок

Підсистема IIO надає потужний, стандартизований та гнучкий інтерфейс для роботи з аналоговими сенсорами, ADC та DAC у Linux. Її архітектура з поділом на sysfs для повільного опитування та буфери/тригери для високошвидкісного захоплення даних робить її ідеальним вибором для сучасних вбудованих систем.
