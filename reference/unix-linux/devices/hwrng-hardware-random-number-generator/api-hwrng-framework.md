# Інтерфейс драйверів hwrng та параметри sysfs

Цей довідник надає повний технічний опис внутрішнього API ядра Linux для реєстрації апаратних генераторів випадкових чисел (`struct hwrng`), аналізує механізм роботи фонового потоку `hwrng-fill`, деталізує системні параметри `sysfs` та описує системний інтерфейс `ioctl` для взаємодії між простором користувача та підсистемою ентропії ядра.

---

## Внутрішній API ядра Linux (`linux/hw_random.h`)

Підсистема `hwrng` розроблена для стандартизації взаємодії ядра Linux із різноманітними фізичними генераторами випадкових чисел (TRNG), такими як чіпи TPM (Trusted Platform Module), модулі генерації випадковості у процесорах Intel/AMD, мікроконтролерах Raspberry Pi (Broadcom BCM2835), SoC Allwinner, Rockchip та інших.

Головним об'єктом підсистеми є структура `struct hwrng`, яка описує конкретне апаратне джерело ентропії та набір функцій-зворотного виклику (callbacks), які реалізує драйвер пристрою.

### Детальний розбір структури `struct hwrng`

```c
struct hwrng {
    const char *name;
    int (*init)(struct hwrng *rng);
    void (*cleanup)(struct hwrng *rng);
    int (*data_present)(struct hwrng *rng, int wait);
    int (*data_read)(struct hwrng *rng, u32 *data);
    int (*read)(struct hwrng *rng, void *data, size_t max, bool wait);
    unsigned short quality;
    unsigned long priv;
};
```

#### Призначення полів структури:

1. `name` (`const char *`):
   Унікальний строковий ідентифікатор драйвера. Ця назва відображається у файлах `sysfs` (`/sys/class/misc/hw_random/rng_available` та `rng_current`). Приклади існуючих імен ядра: `"intel-rng"`, `"amd-rng"`, `"tpm-rng-0"`, `"bcm2835-rng"`, `"virtio-rng"`.

2. `init` (`int (*)(struct hwrng *rng)`):
   Функція ініціалізації апаратного забезпечення. Викликається ядром Linux у момент, коли цей конкретний генератор призначається **активним** джерелом випадковості. У цій функції драйвер вмикає живлення генератора, налаштовує тактову частоту, скидає внутрішні регістри або ініціалізує DMA-канали. Повертає `0` при успіху або від'ємний код помилки (наприклад, `-EIO` або `-ENODEV`). Якщо `init()` повертає помилку, ядро скасовує активацію пристрою.

3. `cleanup` (`void (*)(struct hwrng *rng)`):
   Функція деактивації пристрою. Викликається при вигрузці модуля або при переключенні активного генератора на інший пристрій через sysfs. Драйвер переводить мікросхему HWRNG у режим зниженого енергоспоживання (sleep/power-down) для економії енергії та запобігання перегріву аналогових компонентів (таких як кільцеві осцилятори або лавинні діоди).

4. `data_present` (`int (*)(struct hwrng *rng, int wait)`):
   Перевіряє, чи є в апаратному буфері пристрою готова порція випадкових даних. Якщо аргумент `wait = 1`, функція може заблокувати поточний потік виконання до моменту, поки залізо не виробить хоча б одне 32-бітне слово. Повертає `1`, якщо дані готові для зчитання, або `0`, якщо буфер порожній.

5. `data_read` (`int (*)(struct hwrng *rng, u32 *data)`):
   Застарілий callback (legacy interface) для зчитування одного 32-бітного слова випадкових даних. Повертає кількість зчитаних байт (зазвичай 4) або від'ємний код помилки. У сучасних драйверах рекомендується залишати `NULL` і реалізовувати пакетний метод `read()`.

6. `read` (`int (*)(struct hwrng *rng, void *data, size_t max, bool wait)`):
   Основний сучасний метод зчитування даних. Заповнює буфер `data` обсягом до `max` байт. Прапорець `wait` визначає, чи має драйвер блокуватися в очікуванні наповнення буфера апаратури. Повертає фактичну кількість зчитаних байт (від `0` до `max`) або від'ємний код помилки (наприклад, `-EAGAIN`, якщо даних немає і `wait = false`).

7. `quality` (`unsigned short`):
   Оцінка суб'єктивної криптографічної якості ентропії залізобетонного генератора. Значення лежить у діапазоні від `0` до `1024`:
   - `1024`: Максимальна якість (1 біт справжньої непередбачуваної ентропії на кожен 1 біт зчитаних даних).
   - `512`: Середня якість (0.5 біта ентропії на 1 біт даних, тобто дані мають незначне статистичне зміщення або кореляцію).
   - `0`: Джерело вважається сумнівним або непридатним для автоматичного підвищення лічильника ентропії ядра. Дані з такого генератора все одно змішуються у пул, але ядро не збільшує свій лічильник ентропії `entropy_avail`.

## Механізм реєстрації та роботи фонового потоку `hwrng-fill`

Коли драйвер апаратного забезпечення ініціалізує структуру `struct hwrng`, він реєструє її за допомогою функцій:

```c
int hwrng_register(struct hwrng *rng);
void hwrng_unregister(struct hwrng *rng);
```

### Внутрішня логіка `hwrng_register()`:
1. Ядро бере глобальну мутекс-блокування `hwrng_mutex`.
2. Перевіряє унікальність імені `rng->name`.
3. Додає пристрій до зв'язаного списку зареєстрованих генераторів `rng_list`.
4. Якщо в системі ще немає активного генератора, або новий генератор має показник `quality` вищий за поточний активний, ядро робить новий пристрій активним.
5. При виборі нового активного генератора викликається його метод `rng->init()`.
6. Будиться фоновий потік ядра **`kthread`** з іменем `hwrng-fill`.

### Потік ядра `hwrng-fill`:
Потік `hwrng-fill` працює в нескінченному циклі всередині ядра Linux:
- Він періодично викликає метод `rng->read()` активного генератора, зчитуючи порції даних (зазвичай по 64–512 байт).
- Отримані сирі дані передаються у внутрішню функцію ядра `add_hwgenerator_randomness(buffer, bytes, entropy_bits)`.
- Функція `add_hwgenerator_randomness()` пропускає отримані байти через криптографічний змішувач BLAKE2s, інтегруючи їх у загальний стан `crng`.
- Обчислення доданої ентропії відбувається за формулою: `entropy_bits = (bytes * 8 * quality) / 1024`.
- Після передачі даних потік засинає на певний інтервал або чекає, поки рівень ентропії ядра упаде нижче порогового значення.

## Інтерфейс sysfs (`/sys/class/misc/hw_random/`)

Фреймворк `hwrng` створює у віртуальній файловій системі `sysfs` групу атрибутів для моніторингу та ручного керування генераторами.

### Структура файлів sysfs:

```bash
/sys/class/misc/hw_random/
├── rng_available  # [r--r--r--] Перелік усіх зареєстрованих генераторів
├── rng_current    # [rw-r--r--] Поточний активний генератор (можна змінювати)
└── rng_quality    # [rw-r--r--] Поточна оцінка якості ентропії (0..1024)
```

#### Поведінка та використання атрибутів:

- **`rng_available`**: Повертає рядок із назвами всіх виявлених у системі апаратних генераторів, розділених пробілом.
  *Приклад:*
  ```bash
  $ cat /sys/class/misc/hw_random/rng_available
  tpm-rng-0 intel-rng
  ```

- **`rng_current`**: Відображає назву генератора, з якого наразі зчитує дані потік `hwrng-fill`. Адміністратор системи (із правами `root`) може примусово змінити активний генератор, записавши нове ім'я у цей файл:
  ```bash
  $ echo "intel-rng" | sudo tee /sys/class/misc/hw_random/rng_current
  ```
  При цьому ядро автоматично викликає `cleanup()` для попереднього драйвера та `init()` для нового.

- **`rng_quality`**: Відображає або дозволяє змінити значення `quality` для поточного генератора. Якщо адміністратор знає, що конкретний пристрій піддається зовнішнім завадам, він може знизити його якість до 0:
  ```bash
  $ echo "0" | sudo tee /sys/class/misc/hw_random/rng_quality
  ```

## Інтерфейс ioctl для пристрою `/dev/random` (`linux/random.h`)

Користувацькі демони генерації випадковості (такі як `rngd` з пакету `rng-tools`) не покладаються лише на автоматичний потік ядра `hwrng-fill`. Вони зчитують дані з пристроїв `/dev/hwrng` або `/dev/tpm0`, виконують суворі статистичні тести у просторі користувача, після чого передають перевірену ентропію безпосередньо у пул ядра за допомогою системного виклику `ioctl`.

### Основні команди `ioctl`:

1. **`RNDADDENTROPY`**:
   Передає масив випадкових байтів разом із оцінкою ентропії у пул ядра.
   Структура аргументу:
   ```c
   struct rand_pool_info {
       int entropy_count; /* Оцінка якості ентропії в бітах (1 byte = 8 bits) */
       int buf_size;      /* Розмір буфера даних у байтах */
       __u32 buf[0];      /* Гнучкий масив даних (Flexible Array Member) */
   };
   ```
   *Особливості:* Викликати `RNDADDENTROPY` можуть лише процеси з привілеєм `CAP_SYS_ADMIN` (рутові процеси). Якщо `entropy_count > 0`, ядро збільшує внутрішній лічильник `entropy_avail` на вказане значення (але не більше ніж розмір пулу — 256 біт).

2. **`RNDGETENTCNT`**:
   Повертає поточну оцінку ентропії ядра в бітах.
   *Приклад використання:*
   ```c
   int entropy_bits = 0;
   if (ioctl(fd, RNDGETENTCNT, &entropy_bits) == 0) {
       printf("Поточна ентропія ядра: %d біт\n", entropy_bits);
   }
   ```

3. **`RNDCLEARPOOL`**:
   Очищає вхідний пул ентропії та скидає лічильник до нуля. Використовується при тестуванні або при компрометації стану системи (вимагає `CAP_SYS_ADMIN`).

4. **`RNDRESEEDCRNG`**:
   Змушує ядро негайно виконати процедуру `crng_reseed()`, оновивши робочий ключ ChaCha20 з поточного пулу ентропії (доступно з ядра 4.19+).
