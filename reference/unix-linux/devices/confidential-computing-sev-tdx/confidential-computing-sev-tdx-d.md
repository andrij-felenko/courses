# Конфіденційні обчислення: AMD SEV-SNP та Intel TDX

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

У сучасних хмарних інфраструктурах і центрах обробки даних (ЦОД) безпека даних є одним з найважливіших аспектів. Традиційні підходи до безпеки зосереджуються на захисті даних у стані спокою (на дисках) та даних у процесі передачі (по мережі). Однак дані також потребують захисту, коли вони знаходяться у процесі обробки (в оперативній пам'яті). Саме тут на допомогу приходять технології конфіденційних обчислень (Confidential Computing), які забезпечують апаратну ізоляцію та шифрування пам'яті для захисту даних навіть від адміністраторів інфраструктури та самого гіпервізора. 

Двома провідними технологіями в цій галузі є AMD SEV (Secure Encrypted Virtualization) у його найсучаснішій формі SEV-SNP (Secure Nested Paging) та Intel TDX (Trust Domain Extensions). Обидві технології інтегровані в ядро Linux і підтримуються гіпервізором KVM.

## 1. Що таке конфіденційні обчислення?

Конфіденційні обчислення — це захист даних під час їх використання шляхом виконання обчислень у апаратно ізольованому та криптографічно захищеному середовищі, яке часто називають Trusted Execution Environment (TEE). 

У традиційній моделі віртуалізації гіпервізор має повний доступ до пам'яті та стану процесора всіх своїх гостьових віртуальних машин. Це означає, що скомпрометований гіпервізор або зловмисний адміністратор хост-системи може прочитати, змінити або викрасти дані з будь-якої віртуальної машини. Конфіденційні обчислення змінюють цю парадигму, позбавляючи гіпервізор доступу до пам'яті гостьових ВМ.

### 1.1 Модель загроз

Модель загроз для конфіденційних обчислень виходить з припущення, що інфраструктура хмарного провайдера не може вважатися повністю довіреною. 
Атаки можуть включати:
- Адміністраторів хмарного провайдера з доступом до хост-серверів.
- Зловмисне програмне забезпечення, що заразило хостову ОС або гіпервізор.
- Апаратні атаки (наприклад, читання вмісту модулів пам'яті DIMM).
- Атаки типу "холодне завантаження" (cold boot).

### 1.2 Апаратне шифрування пам'яті

Основою конфіденційних обчислень для ВМ є прозоре апаратне шифрування пам'яті. Центральний процесор (CPU) має вбудований криптографічний рушій у своєму контролері пам'яті, який шифрує дані перед їх записом у фізичну пам'ять (DRAM) і розшифровує їх під час зчитування в кеш-пам'ять процесора.

Для цього використовується алгоритм AES (Advanced Encryption Standard). AMD використовує 128-бітний алгоритм AES для початкових версій SEV, тоді як новіші версії та Intel TDX використовують алгоритми, такі як AES-XTS (XEX-based tweaked-codebook mode with ciphertext stealing) з 128-бітними або 256-бітними ключами. Ключі генеруються та зберігаються всередині апаратного співпроцесора безпеки і ніколи не доступні гіпервізору або програмному забезпеченню.

## 2. Еволюція AMD SEV

Компанія AMD стала піонером у впровадженні конфіденційних обчислень на рівні віртуальних машин з технологією SEV. Вона пройшла кілька етапів розвитку.

### 2.1 AMD SME (Secure Memory Encryption)

До впровадження SEV AMD представила SME. SME шифрує всю пам'ять системи за допомогою єдиного ефемерного ключа, який генерується при завантаженні системи. Це захищає від фізичних атак (наприклад, викрадення модулів DIMM), але не ізолює віртуальні машини одна від одної або від гіпервізора.

### 2.2 AMD SEV (Secure Encrypted Virtualization)

SEV була першою версією технології для віртуальних машин. У SEV кожна віртуальна машина отримує свій власний унікальний ключ шифрування пам'яті. Контролер пам'яті використовує ідентифікатор простору адрес (ASID) віртуальної машини для вибору правильного ключа. Гіпервізор також має свій ключ. Оскільки гіпервізор не знає ключа ВМ, він бачить лише зашифровані дані, якщо намагається прочитати її пам'ять. Однак, SEV захищає лише пам'ять, а стан регістрів процесора під час перемикання контексту залишається відкритим для гіпервізора.

### 2.3 AMD SEV-ES (Encrypted State)

SEV-ES розширила захист, зашифрувавши стан регістрів процесора (CPU register state) при виході з віртуальної машини (VM Exit) у гіпервізор. У SEV-ES гіпервізор не може бачити або модифікувати значення регістрів гостьової ВМ, що закриває значну кількість векторів атак, коли гіпервізор міг маніпулювати станом ВМ. Для спілкування з гіпервізором (наприклад, для обробки переривань або вводу-виводу) ВМ використовує спеціальний механізм обміну повідомленнями через GHCB (Guest-Hypervisor Communication Block) - невеликий незашифрований буфер.

### 2.4 AMD SEV-SNP (Secure Nested Paging)

SEV-SNP є найсучаснішою та найзахищенішою ітерацією технології AMD. Попередні версії (SEV і SEV-ES) захищали конфіденційність, але були вразливі до атак на цілісність. Гіпервізор, маючи контроль над таблицями сторінок пам'яті (Nested Page Tables, NPT), міг перенаправити фізичні сторінки ВМ (memory aliasing) або підмінити зашифровані блоки, що призводило до різноманітних атак (наприклад, rollback, memory remapping).

SEV-SNP додає апаратний захист цілісності пам'яті за допомогою структури даних, відомої як RMP (Reverse Map Table). RMP відстежує, кому належить кожна фізична сторінка пам'яті, і не дозволяє гіпервізору призначати сторінки ВМ іншим об'єктам або порушувати їхню цілісність. Також SEV-SNP додає вдосконалені механізми віддаленої атестації.

## 3. Intel TDX (Trust Domain Extensions)

Компанія Intel запровадила свій підхід до конфіденційних обчислень для віртуальних машин під назвою TDX. Віртуальні машини в середовищі TDX називаються Trust Domains (TD).

### 3.1 Intel MKTME (Multi-Key Total Memory Encryption)

Основою для TDX є технологія шифрування пам'яті Intel MKTME (також відома просто як TME-MK). MKTME розширює базову технологію TME, дозволяючи використовувати кілька ключів шифрування пам'яті, де кожен ключ прив'язаний до певного ідентифікатора ключа (KeyID). Для кожної TD гіпервізор (або спеціальний модуль) резервує унікальний KeyID.

### 3.2 Архітектура Intel TDX

У TDX гіпервізор залишається недовіреним. Для забезпечення безпеки TDX використовує спеціальний програмний модуль, підписаний Intel, який називається TDX Module. Цей модуль працює у спеціальному захищеному режимі процесора (SEAM - Secure Arbitration Mode), який розширює можливості VMX (Virtual Machine Extensions).

TDX Module відповідає за управління життєвим циклом Trust Domains (створення, запуск, знищення), налаштування ключів MKTME та обробку перемикань контексту між TD та гіпервізором. Оскільки TDX Module підписаний Intel і завантажується апаратно-захищеним способом, він вважається довіреним компонентом, який гарантує, що гіпервізор не може маніпулювати TD. TDX також забезпечує захист стану регістрів і цілісність таблиць сторінок пам'яті.

## 4. Віддалена атестація (Remote Attestation)

Шифрування пам'яті та ізоляція — це лише половина справи. Клієнт (власник даних) повинен мати можливість переконатися, що його віртуальна машина дійсно запущена на справжньому, безпечному обладнанні AMD або Intel з увімкненими технологіями безпеки, перш ніж надсилати туди конфіденційні дані або ключі. Цей процес називається віддаленою атестацією.

### 4.1 Процес атестації

Процес віддаленої атестації зазвичай виглядає так:
1. **Вимір (Measurement)**: Під час завантаження ВМ (або TD) мікрокод процесора (або модуль безпеки) обчислює криптографічний хеш її початкового стану (включаючи пам'ять ядра, прошивку OVMF/UEFI, параметри конфігурації). Цей хеш називається виміром.
2. **Звіт про атестацію (Attestation Report)**: Гостьова ОС запитує у апаратного забезпечення звіт про атестацію. Звіт містить виміри ВМ та підписується унікальним апаратним ключем, який підтверджує справжність процесора.
3. **Перевірка (Verification)**: Гостьова ОС надсилає цей звіт третій стороні (Relying Party), часто через сервіс атестації (Attestation Service). Сторона перевіряє цифровий підпис за допомогою сертифікатів, виданих AMD або Intel.
4. **Виділення секретів (Secret Injection)**: Якщо звіт є дійсним, а виміри відповідають очікуваним (що гарантує, що ПЗ всередині ВМ не було модифіковано), клієнт встановлює захищений канал зв'язку (наприклад, TLS) і передає в ВМ конфіденційні дані (наприклад, ключі розшифрування дисків).

### 4.2 Підтримка в Linux

У Linux підтримка віддаленої атестації для SEV-SNP та TDX реалізується через спеціальні символьні пристрої, до яких звертається програмне забезпечення в гостьовій системі.

Для AMD SEV-SNP гостьова система взаємодіє з драйвером через пристрій `/dev/sev-guest`. Драйвер використовує спеціальну інструкцію VMPCK (Virtual Machine Privilege Check Key) для спілкування з мікроконтролером AMD Secure Processor (ASP) і запиту звітів про атестацію.

Для Intel TDX гостьова система використовує пристрій `/dev/tdx-guest`. Запити передаються до TDX Module за допомогою спеціальних викликів (TDCALL), який генерує звіт TD Quote, що підписується за допомогою технології Intel SGX (Software Guard Extensions) Quoting Enclave.

## 5. Інтеграція з KVM та Linux

Підтримка технологій SEV-SNP та TDX вимагає масштабних змін у ядрі Linux (хостовому та гостьовому) та в QEMU/KVM.

### 5.1 Зміни в хостовому ядрі та KVM

Хостове ядро повинно підтримувати ініціалізацію апаратних функцій, управління ключами та структурами даних (такими як RMP у SEV-SNP). KVM потребує значних модифікацій, оскільки він більше не може безпосередньо звертатися до пам'яті гостьових машин. Замість прямих записів та читань, KVM використовує нові API для створення та управління захищеними ВМ через виклики мікропрограм (AMD ASP або Intel TDX Module). Для TDX, KVM взаємодіє з модулем через виклики SEAMCALL.

Також значно ускладнюється обробка переривань, міграція ВМ (яка потребує безпечної передачі стану та пам'яті між хостами, що зараз підтримується обмежено) та гаряче підключення пристроїв.

### 5.2 Зміни в гостьовому ядрі Linux

Гостьове ядро має бути "обізнаним" про те, що воно працює в середовищі конфіденційних обчислень. Воно повинно:
- Знати про шифрування сторінок. Деякі сторінки пам'яті, які використовуються для спілкування з гіпервізором (наприклад, буфери virtio, SWIOTLB, GHCB), повинні бути явно позначені як "незашифровані" або "спільні" (shared), щоб гіпервізор міг їх читати і писати.
- Використовувати спеціальні інструкції для запиту атестації або прийняття сторінок пам'яті (PVALIDATE в SEV-SNP, TDG.MEM.PAGE.ACCEPT в TDX).
- Обробляти винятки безпеки, наприклад, коли гіпервізор намагається вставити переривання, що може вимагати особливої перевірки в SEV-SNP.

Ці зміни в Linux були інтегровані поступово, починаючи з ядер серії 5.x і досягаючи зрілості в ядрах 6.x.

## 6. Використання та розгортання

Розгортання віртуальних машин з SEV-SNP або TDX часто здійснюється через платформи управління хмарами, такі як OpenStack, або через публічні хмарні провайдери (AWS, Google Cloud, Azure), які надають "Confidential VMs". 

На рівні низькорівневих інструментів, створення такої ВМ через QEMU вимагає додаткових параметрів. Наприклад, для запуску ВМ з SEV-SNP через QEMU необхідно вказати об'єкт `sev-snp-guest` та параметри прошивки (OVMF), спеціально скомпільованої для підтримки SEV.

```bash
# Приблизний приклад параметрів QEMU для SEV
qemu-system-x86_64 \
    -enable-kvm \
    -cpu EPYC-Rome \
    -machine q35,confidential-guest-support=sev0 \
    -object sev-guest,id=sev0,cbitpos=47,reduced-phys-bits=1 \
    ...
```

Для TDX QEMU використовує об'єкт `tdx-guest`.

### 6.1 Наслідки для продуктивності

Конфіденційні обчислення мають певний вплив на продуктивність. Шифрування пам'яті в контролері пам'яті додає невелику затримку (latency), але завдяки апаратному прискоренню (AES) вплив на пропускну здатність зазвичай становить кілька відсотків. 

Більш суттєвим є вплив переходів між ВМ і гіпервізором (VM Exits), оскільки захист стану регістрів (SEV-ES, TDX) та перевірки безпеки вимагають додаткових мікрооперацій. Операції вводу-виводу (I/O), які часто спричиняють VM Exits, також вимагають копіювання даних (bounce buffering) через спеціальні незашифровані буфери (SWIOTLB), що створює додаткове навантаження на процесор і пам'ять. Однак для багатьох завдань (особливо CPU-bound) загальний вплив залишається в межах 2-10%, що є прийнятним компромісом за значне підвищення рівня безпеки.

## Висновок

AMD SEV-SNP та Intel TDX являють собою фундаментальний зсув у безпеці хмарних обчислень. Завдяки криптографічній ізоляції віртуальних машин від гіпервізора та можливості віддаленої атестації, вони дозволяють розгортати конфіденційні робочі навантаження навіть у недовірених середовищах. Ці технології продовжують розвиватися, пропонуючи кращий захист від нових класів атак і все більш глибоко інтегруючись з екосистемою Linux.
