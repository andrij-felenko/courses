# 🔌 Апаратні рушії шифрування пам'яті: AMD AES-128/256 та Intel MKTME

Апаратний рушій шифрування пам'яті (Memory Encryption Engine) є спеціалізованим блоком криптографічної логіки, який інтегровано безпосередньо в контролер оперативної пам'яті (Memory Controller, MC) центрального процесора. Його функція полягає в прозорому (програмно-невидимому) шифруванні даних перед їх записом у фізичні модулі DRAM та розшифруванні під час зчитування в кеш-пам'ять L3/L2 процесора.

Оскільки всі обчислення та операції з даними виконуються всередині кристалу процесора (CPU core/caches) у відкритому вигляді, межа довіри (Trust Boundary) проходить по зовнішніх шинах процесора. Все, що залишає сокет CPU і прямує до системної шини та модулів DIMM, шифрується «на льоту» (inline encryption) на повній швидкості роботи контролера пам'яті.

---

## 1. Криптографічні режими та математична специфіка AES-XTS

Для шифрування блоків оперативної пам'яті звичайний режим блочного шифрування ECB (Electronic Codebook) або CBC (Cipher Block Chaining) є абсолютно непридатним. 

У режимі ECB однакові 16-байтні блоки відкритих даних завжди перетворюються на однакові блоки зашифрованого тексту. Це створює серйозний витік структури даних: зловмисник, що спостерігає за шиною DRAM, може розпізнати таблиці сторінок, нульові блоки пам'яті або повторювані бітові маски. Режим CBC вимагає послідовного обчислення залежностей між сусідніми блоками, що спричиняє величезні затримки при випадковому доступі до DRAM і унеможливлює паралельне зчитування кеш-ліній (64 байти).

Для вирішення цієї проблеми сучасні рушії шифрування пам'яті застосовують режим **AES-XTS** (XEX-based tweaked-codebook mode with ciphertext stealing):

- **Модифікатор адреси (Tweak Value)**: У якості модифікатора шифрування застосовується фізична адреса сторінки пам'яті (Physical Address). Це гарантує, що два однакові 16-байтні блоки даних, записані за різними фізичними адресами у DRAM, матимуть абсолютно різний криптографічний вигляд.
- **Відсутність міжблокової залежності**: Режим XTS дозволяє шифрувати та розшифровувати будь-яку 64-байтну кеш-лінію незалежно від сусідніх ділянок пам'яті, що дає змогу розпаралелювати криптографічні обчислення у конвеєрі контролера DRAM.
- **Розмір ключа**: У першому поколінні AMD SME/SEV використовувався 128-бітний AES. Сучасні процессори AMD SEV-SNP та Intel TDX застосовують алгоритми **AES-XTS-128** або **AES-XTS-256**.

```
Схема роботи прозорого inline-шифрування в контролері DRAM:

[ Ядро CPU / Кеш L3 ]  <-- (Відкриті дані) -->  [ Контролер пам'яті (MC) ]
                                                      |
                                          +-----------+-----------+
                                          | Апаратний AES-XTS     |
                                          | Таблиця ключів (KeyID)|
                                          +-----------+-----------+
                                                      |
                                            (Зашифрований потік)
                                                      v
                                              [ Модулі DRAM ]
```

## 2. Механізми адресації та виділення ключів

Щоб контролер пам'яті знав, яким саме ключем розшифровувати конкретний блок даних, процесор використовує виділені біти у фізичній адресі сторінки (Physical Address, PA), які екстрагуються блоком MMU під час трансляції таблиць сторінок.

### AMD SEV: Біт шифрування C-bit

У процесорах AMD EPYC один з верхніх бітів фізичної адреси (зазвичай біт 47 або 51, залежно от конфігурації ширини фізичної шини адресації DRAM) виділено як **C-bit** (Encrypted Bit):

- Якщо `C-bit = 1`, контролер пам'яті розшифровує дані за допомогою ключа, прив'язаного до ідентифікатора простору адрес (ASID) поточної віртуальної машини.
- Якщо `C-bit = 0`, дані вважаються відкритими (shared) і зчитуються без розшифрування (використовується для буферів вводу-виводу DMA та обміну з гіпервізором).

При цьому загальний фізичний адресний простір, доступний для адресації оперативної пам'яті, зменшується вдвічі (наприклад, з 52 бітів до 51 біта), оскільки старший біт вилучається з шини адреси і подається на керівний вхід криптографічного селектора. Таблиця ключів зберігається у захищеній пам'яті співпроцесора AMD Secure Processor (ASP) і завантажується в контролер пам'яті при перемиканні контексту ВМ.

### Intel MKTME / TME-MK: Біти KeyID

В архітектурі Intel (Total Memory Encryption - Multi-Key) під ідентифікатор ключа відводиться діапазон старших бітів фізичної адреси — **KeyID** (наприклад, біти 51:46 дозволяють адресувати до 64 унікальних ключів; у нових серверах Xeon — до 512 ключів):

- `KeyID = 0`: Базовий системний ключ TME, який шифрує оперативну пам'ять хостової операційної системи. Цей ключ ґенерується апаратним генератором випадкових чисел (TRNG) при кожному старті сервера і ніколи не покидає сокет процесора.
- `KeyID > 0`: Унікальні ключі, виділені для кожної гостьової ВМ (Trust Domain).

Контролер пам'яті Intel містить апаратну таблицю селекторів ключів (Key Table), яка за значеним KeyID миттєво обирає потрібний AES-ключ для кожного звернення до DRAM.

## 3. Фізичні атаки на DRAM та засоби апаратного захисту

Шифрування оперативної пам'яті на рівні контролера DRAM повністю нейтралізує широкий клас фізичних атак на залізо ЦОД:

1. **Перехоплення сигналів шини (Bus Sniffing)**: Зловмисник, що підключає логічний аналізатор або міжплатний інтерпозер між слотом DIMM та материнською платою, бачить лише псевдовипадковий бінарний шум.
2. **Атаки холодної перезавантаження (Cold Boot Attacks)**: Фізичний викрадення модулів DRAM з охолодженням рідким азотом для збереження електричних зарядів у конденсаторах комірок є марним, оскільки без вмісту SRAM-таблиці ключів усередині вимкненого CPU дані неможливо розшифрувати.
3. **Атаки інверсії бітів (Rowhammer & Bit Flipping)**: Сучасні апаратні рушії додають обчислення криптографічних міток цілісності ICV (Integrity Check Values) та перевірку апаратних дерев Меркла (Merkle Trees). Якщо зловмисник намагається сфокусованим випромінюванням або повторними активаціями рядків DRAM змінити стан бітів у зашифрованому блоці, перевірка ICV поверне помилку цілісності, і процесор негайно зупинить виконання ядер через паніку системи (Machine Check Exception, `#MC`).

## 4. Конвеєризація та апаратна затримка шифрування (Latency Tradeoffs)

Впровадження шифрування на рівні контролера оперативної пам'яті ставить високі вимоги до часу затримки (latency). Для компенсації витрат часу на обчислення розшифрування за алгоритмом AES-XTS контролер пам'яті використовує спеціалізовану криптографічну конвеєризацію (Pipelining):

- Обчислення модифікатора адреси (Tweak) відбувається паралельно із зануленням рядків шини адреси DRAM.
- Коли 64-байтний блок даних надходить із фізичних чіпів DIMM до контролера пам'яті, раундові ключі AES вже підготовлені в апаратних регістрах контролера, що зводить додаткову затримку зчитування в L3-кеш всього до **2–4 наносекунд** (від 3 до 6 тактів шини пам'яті).
- Для операцій запису шифрування виконується повністю асинхронно у буфері запису (Write Buffer), тому операції запису з кешу L3 в DRAM взагалі не сповільнюють виконання процесорних інструкцій.

## 5. Сводна порівняльна характеристика апаратних рушіїв

| Параметр | AMD SME / SEV-SNP | Intel TME / MKTME (TDX) |
| :--- | :--- | :--- |
| **Основа алгоритму** | AES-128 / AES-256-XTS | AES-128-XTS / AES-256-XTS |
| **Маркування сторінок** | Фізичний біт `C-bit` (біт 47 або 51) | Біти `KeyID` у фізичній адресі (біти 51:46) |
| **Максимальна кількість ключів** | До 509 ключів ВМ (на сокет) | До 64 / 512 ключів (на сокет) |
| **Апаратне управління** | AMD Secure Processor (ASP) | Intel TDX Module (SEAM) + MKTME |
| **Захист цілісності пам'яті** | Апаратна таблиця RMP | Механізм Integrity Tree / ICV |
| **Генерація ключів** | Ефемерна генерація в ASP | Апаратний TRNG при завантаженні |
| **Додаткова затримка розшифрування**| ~2-3 наносекунди (~4 такти) | ~3-4 наносекунди (~5 тактів) |
