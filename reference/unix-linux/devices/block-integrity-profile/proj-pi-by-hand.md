# ⚙️ Захисна інформація вручну: порахувати вісім байтів і звірити з носієм

Ця програма на C рахує вартового й посилальний тег для заданого блока власними силами, потім дістає з носія ті вісім байтів, які він зберігає біля цього самого блока, і кладе обидва числа поруч. Сенс не в тому, щоб отримати ще одну утиліту, а в тому, щоб перестати вірити на слово: після неї видно, від яких саме байтів залежить кожне поле кортежу, і — що важливіше — де твоя перевірка не доводить нічого.

Звичайний `read()` службових байтів не показує взагалі: у простір користувача їде лише вміст блока, а теги живуть окремим вантажем запиту й до програми не доїжджають. Дістати їх можна тільки командою, поданою пристроєві навпростець ([наскрізні команди](topic:unix-linux/scsi-generic-passthrough) — механізм, яким програма складає команду протоколу сама й обходить блоковий шар разом з усіма його перетвореннями). Це й задає форму програми: одна команда читання на блок, два буфери, три порівняння.

## Вартовий: многочлен, у якому немає дзеркал

Многочлен 0x8BB7 — це половина опису. Друга половина в тому, чого тут **немає**: початкове значення регістра нульове, вхідні байти не перевертають, результат не перевертають і кінцевим числом не ксорять. Сказати це вголос варто тому, що ходові CRC-16 влаштовані інакше. Modbus, KERMIT і USB — дзеркальні, тобто крутять регістр у протилежний бік; недзеркальний CCITT-FALSE замість нуля починає з 0xFFFF. Узяти будь-яку з цих реалізацій, підмінити в ній самий лише многочлен і думати, що вийшов T10, — найпоширеніша помилка в цій задачі, і код при цьому виглядає бездоганно.

Саме з відсутності дзеркал випливає єдина неочевидна деталь побітового варіанта: байт даних заходить у **старшу** половину регістра, а зсув іде вліво.

```c
#define T10_POLY 0x8BB7

static uint16_t crc_bit(const uint8_t *p, size_t n)
{
    uint16_t crc = 0;                        /* початкове значення — нуль */

    for (size_t i = 0; i < n; i++) {
        crc ^= (uint16_t)p[i] << 8;          /* байт — у СТАРШУ половину */
        for (int b = 0; b < 8; b++)
            crc = (crc & 0x8000) ? (uint16_t)(crc << 1) ^ T10_POLY
                                 : (uint16_t)(crc << 1);
    }
    return crc;                              /* без дзеркалення й без XOR наприкінці */
}
```

Перевірити це можна, не запускаючи нічого на носії. Для кожного каталогізованого CRC є взірцеве число — сума над рядком `123456789`; у CRC-16/T10-DIF це `0xD0DB`. Не зійшлося — далі йти немає сенсу, решта програми лише розмножить помилку.

Табличний варіант виводиться з побітового прямо: рядок таблиці з номером `i` — це CRC одного-єдиного байта `i`, тому таблицю будує та сама функція, і другої реалізації многочлена в програмі не з'являється (звідки береться сам перехід від біта до байта — [реалізації CRC](topic:communications/crc/proj-crc-implementation.md): те саме ділення, згруповане по вісім кроків).

```c
static uint16_t tab[256];

static void tab_init(void)
{
    for (unsigned i = 0; i < 256; i++) {
        uint8_t b = (uint8_t)i;
        tab[i] = crc_bit(&b, 1);
    }
}

static uint16_t crc_tab(const uint8_t *p, size_t n)
{
    uint16_t crc = 0;

    for (size_t i = 0; i < n; i++)
        crc = (uint16_t)(crc << 8) ^ tab[(crc >> 8) ^ p[i]];
    return crc;
}
```

Різниця в ціні не косметична, і на швидкому носії вона вирішує, хто кого чекає.

```
побітово   4096 Б × 8 кроків = 32 768 кроків на блок
таблицею   4096 звернень до таблиці на 512 Б — вона цілком лягає в кеш першого рівня

оцінка побітового на 3 ГГц, приблизно крок за такт:
    32 768 / 3·10⁹        ≈ 11 мкс на блок
    4096 / 11·10⁻⁶        ≈ 370 МБ/с — межа одного ядра
носій на 7 ГБ/с          → потрібно ≈ 19 таких потоків, щоб за ним устигати
```

## Кортеж лежить старшим байтом уперед

Вісім байтів на носії — це не структура мовою C, а формат на дроті, і порядок у ньому мережевий: старший байт першим. Хост же на x86 і на типовому ARM — молодшим уперед. Тому єдиний спосіб не помилитися — тримати поля масивами байтів і збирати числа явно; варіант «оголосити `uint16_t` і зробити `memcpy`» дає переставлені байти, порівняння не сходиться ніколи, а причина не видна ні в коді, ні в друку.

```c
struct pi_tuple {              /* у ядрі це struct t10_pi_tuple: __be16, __be16, __be32 */
    uint8_t guard[2];
    uint8_t app[2];
    uint8_t ref[4];
};

static uint16_t be16(const uint8_t *p) { return (uint16_t)(p[0] << 8 | p[1]); }
static uint32_t be32(const uint8_t *p)
{
    return (uint32_t)p[0] << 24 | (uint32_t)p[1] << 16 | (uint32_t)p[2] << 8 | p[3];
}
```

## Попросити носій віддати службові байти як є

Команда читання NVMe кладе початкову адресу в CDW10–CDW11, кількість блоків мінус один — у молодші шістнадцять бітів CDW12, а вище, у бітах 29:26, сидить поле PRINFO. Ось воно тут і головне, причому потрібне нам значення — нуль, і обидві його половини нульові з різних причин.

Старший біт PRINFO, PRACT, вирішує, хто взагалі має справу з тегами. Одиниця означає «зроби це сам»: при читанні контролер **зніме** захисну інформацію й віддасть хостові самі дані — дивитися буде ні на що. Нуль означає «віддай як є».

Молодші три біти, PRCHK, вмикають перевірку вартового, прикладного й посилального тегів у самому контролері. Здається, що саме цього ми й хочемо, — але ні. Увімкнена перевірка перетворює зіпсований блок на відмову: команда повертає статус 0x282, 0x283 або 0x284 залежно від того, який тег не збігся, а байтів ми не побачимо. Нам потрібне протилежне — узяти навіть заздалегідь неправильний кортеж і роздивитися його, тому перевірку вимикаємо й судимо самі.

```c
static int nvme_read(int fd, uint32_t nsid, uint64_t slba,
                     void *data, uint32_t dlen, void *meta, uint32_t mlen)
{
    struct nvme_passthru_cmd c = {
        .opcode       = 0x02,                    /* Read */
        .nsid         = nsid,
        .addr         = (uint64_t)(uintptr_t)data,
        .data_len     = dlen,
        .metadata     = (uint64_t)(uintptr_t)meta,   /* окремий буфер під теги */
        .metadata_len = mlen,
        .cdw10        = (uint32_t)slba,
        .cdw11        = (uint32_t)(slba >> 32),
        .cdw12        = 0,        /* NLB = 0 → один блок; PRINFO = 0 */
        .timeout_ms   = 5000,
    };
    int rc = ioctl(fd, NVME_IOCTL_IO_CMD, &c);

    if (rc < 0) { perror("NVME_IOCTL_IO_CMD"); return -1; }
    if (rc > 0) {                                /* дійшло, та контролер відмовив */
        fprintf(stderr, "LBA %llu: NVMe SCT=%u SC=0x%02x\n",
                (unsigned long long)slba, ((unsigned)rc >> 8) & 0x7, (unsigned)rc & 0xff);
        return -1;
    }
    return 0;
}
```

Окремий вказівник `metadata` поряд із `addr` — це і є той самий розділений вигляд, у якому дані й теги їдуть двома буферами. Блок за командою тут рівно один: зайвий обіг до пристрою коштує мікросекунди, зате кожен вирок належить своїй адресі, а зіпсований блок не псує читання сусідів.

## Програма

```c
/* pi-check.c — порахувати захисну інформацію самотужки й звірити з носієм.
 *   cc -O2 -Wall -Wextra -std=gnu11 -o pi-check pi-check.c
 *   sudo ./pi-check -s 2099200 /dev/nvme0n1 100 5
 *        ./pi-check -I -b 4096 dump.bin 0 5
 *
 *  -I         шлях — файл-образ із записами по (блок + службові) байтів
 *  -b <Б>     розмір логічного блока (типово питаємо в ядра)
 *  -m <Б>     службових байтів на блок (типово 8)
 *  -s <сект>  початок розділу так, як його дає /sys/class/block/<part>/start,
 *             тобто в секторах по 512 Б незалежно від розміру блока
 *  -F         захист у ПЕРШИХ восьми байтах службових (DPS біт 3), а не в останніх
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <getopt.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <linux/fs.h>
#include <linux/nvme_ioctl.h>

/* — сюди йдуть crc_bit, tab_init, crc_tab, struct pi_tuple, be16, be32, nvme_read — */

static int img_read(int fd, uint64_t rec, unsigned bs, unsigned ms,
                    uint8_t *data, uint8_t *meta)
{
    off_t off = (off_t)rec * (bs + ms);          /* запис = блок + службові байти */

    if (pread(fd, data, bs, off) != (ssize_t)bs) { perror("pread даних"); return -1; }
    if (pread(fd, meta, ms, off + bs) != (ssize_t)ms) { perror("pread тегів"); return -1; }
    return 0;
}

int main(int argc, char **argv)
{
    unsigned bs = 0, ms = 8, count = 1;
    uint64_t part_sect = 0;
    int is_img = 0, pi_first = 0, opt;

    while ((opt = getopt(argc, argv, "Ib:m:s:F")) != -1)
        switch (opt) {
        case 'I': is_img = 1; break;
        case 'b': bs = (unsigned)strtoul(optarg, NULL, 0); break;
        case 'm': ms = (unsigned)strtoul(optarg, NULL, 0); break;
        case 's': part_sect = strtoull(optarg, NULL, 0); break;
        case 'F': pi_first = 1; break;
        default:  return 2;
        }

    if (argc - optind < 2) {
        fprintf(stderr, "вжиток: pi-check [-I] [-b блок] [-m службових] "
                        "[-s зсув-розділу] [-F] <шлях> <LBA> [кількість]\n");
        return 2;
    }
    const char *path = argv[optind];
    uint64_t lba0 = strtoull(argv[optind + 1], NULL, 0);
    if (argc - optind > 2) count = (unsigned)strtoul(argv[optind + 2], NULL, 0);

    int fd = open(path, O_RDONLY);
    if (fd < 0) { perror(path); return 1; }

    uint32_t nsid = 0;
    if (!is_img) {
        int id = ioctl(fd, NVME_IOCTL_ID);        /* заразом і перевірка, що це NVMe */
        if (id < 0) { perror("NVME_IOCTL_ID"); return 1; }
        nsid = (uint32_t)id;
        int sz = 0;
        if (!bs && ioctl(fd, BLKSSZGET, &sz) == 0) bs = (unsigned)sz;
    }
    if (!bs) bs = 4096;
    if (ms < sizeof(struct pi_tuple) || ms > 4096) {
        fprintf(stderr, "службових байтів на блок має бути від 8 до 4096\n");
        return 1;
    }

    /* зсув розділу sysfs дає в секторах по 512 Б — переводимо в логічні блоки */
    uint64_t part_lba = part_sect / (bs / 512);

    uint8_t *data, *meta;                         /* вирівняне — щоб ядро не копіювало */
    if (posix_memalign((void **)&data, 4096, bs)
        || posix_memalign((void **)&meta, 4096, 4096)) {
        fprintf(stderr, "не вистачило пам'яті\n");
        return 1;
    }

    tab_init();
    static const uint8_t probe[] = "123456789";
    printf("самоперевірка CRC-16/0x8BB7 над \"123456789\": %04x побітово, %04x таблицею"
           " (взірець d0db)\n", crc_bit(probe, 9), crc_tab(probe, 9));
    printf("блок %u Б, службових %u Б, зсув розділу %llu блоків\n",
           bs, ms, (unsigned long long)part_lba);
    puts("колонки: LBA · guard з носія · guard порахований · app · ref з носія · ref очікуваний");

    int bad = 0;
    for (unsigned i = 0; i < count; i++) {
        uint64_t lba = part_lba + lba0 + i;

        if (is_img ? img_read(fd, lba0 + i, bs, ms, data, meta)
                   : nvme_read(fd, nsid, lba, data, bs, meta, ms))
            { bad = 1; continue; }

        const struct pi_tuple *t = (const struct pi_tuple *)
                (pi_first ? meta : meta + ms - sizeof(struct pi_tuple));

        uint16_t g_dev = be16(t->guard), g_our = crc_tab(data, bs);
        uint16_t app   = be16(t->app);
        uint32_t r_dev = be32(t->ref), r_our = (uint32_t)lba;
        const char *verdict = "ок";

        if (app == 0xffff) {                         /* стандарт: перевірок для блока нема */
            verdict = "перевірку вимкнено (app=ffff)";
        } else if (g_dev != g_our || r_dev != r_our) {
            bad = 1;
            if (g_dev != g_our && r_dev != r_our) verdict = "✖ вартовий і посилальний";
            else if (g_dev != g_our) verdict = "✖ вартовий: дані не ті, що накривав тег";
            else                     verdict = "✖ посилальний: блок не з цієї адреси";
        }

        printf("%10llu   %04x   %04x   %04x   %08x %08x   %s\n",
               (unsigned long long)lba, g_dev, g_our, app, r_dev, r_our, verdict);
    }
    return bad;
}
```

    262503   1c58   1c58   0000   00030164 00040167   ✖ посилальний: блок не з цієї адреси

Прикладний тег на перших рядках нульовий, і це не збіг: коли теги генерує блоковий шар, він явно вписує туди нуль — два байти віддані власникові вище, а власника немає.

Другий рядок вартий окремої уваги. Нулі в обох колонках вартового не означають, що поле не заповнене: початкове значення регістра нульове, тому CRC від блока з самих нулів теж нуль. Занулений блок із зануленим кортежем проходить перевірку вартового бездоганно — відрізнити його від справжніх даних здатен лише посилальний тег, у якому має стояти адреса, а не нуль.

Третій рядок — класичне тихе спотворення: адреса на місці, дані змінилися після того, як тег порахували. Четвертий — блок, що приїхав із чужого місця: сума від даних сходиться ідеально, бо дані цілі, а от адреса в тезі стара. П'ятий — не помилка взагалі: за стандартом прикладний тег `0xFFFF` вимикає всі перевірки цього блока, і саме так позначені блоки, у які після форматування ще не писали.

> 🔧 **Навіщо це.** Коли носій відхиляє читання через цілісність, нагору доїжджає сам лише код помилки: який тег не зійшовся — видно, а на скільки й чому — ні. Ця програма дає те, чого немає в жодному журналі, — обидва числа поруч, і з їхньої різниці читається діагноз. Розійшовся тільки вартовий: дані змінилися вже після того, як тег порахували, і шукати треба на шляху вниз. Розійшовся тільки посилальний, а різниця дорівнює початку розділу: винна арифметика адрес у того, хто цей блок писав. Розійшлися обидва: на місце блока приїхало щось стороннє цілком.

Звірити саму програму є з чим: ті самі байти дістає `nvme read /dev/nvme0n1 --start-block=262500 --block-count=0 --data-size=4096 --metadata-size=8 --data=blk.bin --metadata=pi.bin`, після чого `xxd pi.bin` покаже той самий кортеж, а `-I`-режим програми розбере злитий у файл образ.

## Пастки

**Порядок байтів.** Найдорожча помилка тут не в CRC, а поруч із ним: посилальний тег на носії лежить старшим байтом уперед, і прочитаний як `uint32_t` на x86 він перетворюється, скажімо, з `0x00040164` на `0x64010400`. Розбіжність виглядає як зіпсовані дані, хоч насправді зіпсована програма.

**Розширений формат блока.** Те, чи їдуть службові байти окремим буфером, вирішує не програма, а формат простору імен: біт 4 поля FLBAS у відповіді `Identify Namespace`. Якщо простір імен відформатований під розширений блок, службові байти йдуть суцільно **всередині** даних, і команду треба складати інакше: `data_len` дорівнює кількість-блоків·(блок+службові), а `metadata` лишається нулем. Переплутаєш — дістанеш або відмову, або зсунуті на вісім байтів дані, у яких вартовий не зійдеться на жодному блоці, і виглядатиме це як суцільно зіпсований носій. Друга половина тієї самої настройки — де в службових байтах лежить сам захист, коли їх більше за вісім: біт 3 поля DPS вибирає перші вісім чи останні (це й робить ключ `-F`; звідки взяти обидва поля — [Identify власними руками](topic:unix-linux/nvme-in-linux/proj-identify-by-ioctl.md), там ці структури розібрані байт за байтом).

**Зсув розділу.** Тег зберігає **абсолютну** адресу в просторі імен, а програма зазвичай дізнається номер блока від файлової системи, тобто відлічений від початку розділу. Порахувати очікуваний тег треба з абсолютного числа, і саме тому в програмі є `-s`.

```
початок розділу, /sys/class/block/nvme0n1p2/start = 2 099 200 (секторів по 512 Б)
у логічних блоках по 4096 Б:  2 099 200 / 8       =   262 400
блок 100 усередині розділу → абсолютний LBA        =   262 500  = 0x00040164
той самий тег, порахований від початку розділу     =   0x00000064
```

Небезпечніша тут не розбіжність, а мовчазний збіг: забувши `-s`, програма прочитає блок 100 усього носія — усередині таблиці розділів або чужого розділу, — і той блок зійдеться сам із собою, бо в його тезі теж стоїть 100. Звідси й межа самого механізму: тег доводить, де блок лежить **зараз**, а не звідки він узявся ([розділи диска](topic:unix-linux/disk-partitions) — де живуть початок і довжина розділу й чому sysfs завжди міряє їх у 512-байтових секторах).

**Носій, де теги генерує контролер.** Коли запит іде вниз без тегів, а простір імен відформатований під захист, драйвер NVMe виставляє в команді PRACT — і кортеж вставляє сам контролер, із тих самих байтів, які щойно отримав. Прочитавши такий блок, програма порівняє CRC контролера з власним CRC над тими самими даними й отримає збіг завжди. Формально перевірка пройшла; насправді вона не накрила нічого, крім арифметики самого носія. Ознака цієї ситуації видна згори: якщо теки `/sys/block/nvme0n1/integrity/` немає, теги народжуються в контролері, і ручна звірка тут — тавтологія.

**Тип захисту.** Порівняння посилального тега з адресою законне лише для типу 1. Для типу 3 тег не пов'язаний з адресою взагалі, і програма чесно надрукує розбіжність на кожному рядку — помилка при цьому в програмі, а не на носії. Для типу 2 початкове значення тега задає команда, тож очікуване число треба брати звідти, а не з адреси. Тип написано в `/sys/block/nvme0n1/integrity/format` і в бітах 2:0 поля DPS.

**Права й чинний носій.** Наскрізна команда потребує повноважень адміністратора, а сам механізм — носія, справді відформатованого під захист. На звичайному споживчому накопичувачі службових байтів на блок немає взагалі, `metadata_len` там нічого не означає, і жодні ключі програми цього не змінять.
