# 📋 Інтерфейси керування призупиненням: dev_pm_ops та sysfs

Керування живленням у ядрі Linux будується на двох взаємопов'язаних контрактах: внутрішньому програмному інтерфейсі структури `dev_pm_ops`, який реалізують драйвери пристроїв, та зовнішньому файловому інтерфейсі у просторі `sysfs`, через який служби користувача ініціюють та конфігурують системний сон.

## Структура зворотних викликів `struct dev_pm_ops`

Головним інтерфейсом між ядром та драйвером для всіх форм керування живленням є структура `struct dev_pm_ops`, оголошена у заголовковому файлі `<linux/pm.h>`. Вона замінила застарілий інтерфейс `pm_ops` та виклики зі структурою повідомлень `pm_message_t` (де тип події `PM_EVENT_SUSPEND` передавався як аргумент), уніфікувавши роботу з шинами PCI, USB, платформою та пристроями I²C/SPI.

Структура об'єднує 23 покажчики на функції, розділені на три функційні групи: системний сон (*System Sleep*), глибокий сон із збереженням образу (*Hibernation*) та динамічне керування живленням на ходу (*Runtime PM*).

```c
struct dev_pm_ops {
    /* Підготовка та фіналізація системного переходу */
    int (*prepare)(struct device *dev);
    void (*complete)(struct device *dev);

    /* Стандартний цикл системного сну (Suspend-to-RAM / s2idle) */
    int (*suspend)(struct device *dev);
    int (*resume)(struct device *dev);

    /* Пізні та ранні виклики (обробка доменів живлення та шин) */
    int (*suspend_late)(struct device *dev);
    int (*resume_early)(struct device *dev);

    /* Виклики з вимкненими перериваннями пристроїв (Atomic Noirq) */
    int (*suspend_noirq)(struct device *dev);
    int (*resume_noirq)(struct device *dev);

    /* Фази заморожування при гібернації (створення знімка RAM) */
    int (*freeze)(struct device *dev);
    int (*thaw)(struct device *dev);
    int (*poweroff)(struct device *dev);
    int (*restore)(struct device *dev);

    int (*freeze_late)(struct device *dev);
    int (*thaw_early)(struct device *dev);
    int (*poweroff_late)(struct device *dev);
    int (*restore_early)(struct device *dev);

    int (*freeze_noirq)(struct device *dev);
    int (*thaw_noirq)(struct device *dev);
    int (*poweroff_noirq)(struct device *dev);
    int (*restore_noirq)(struct device *dev);

    /* Динамічне керування живленням на ходу (Runtime PM) */
    int (*runtime_suspend)(struct device *dev);
    int (*runtime_resume)(struct device *dev);
    int (*runtime_idle)(struct device *dev);
};
```

### Призначення та контекст викликів системного сну

| Зворотний виклик | Контекст виконання | Можливість блокування (сон) | Призначення та типові дії драйвера |
| :--- | :--- | :--- | :--- |
| `prepare(dev)` | Процесний (переривання увімкнені) | Так (`might_sleep()`) | Запобігає реєстрації нових дочірніх пристроїв у підсистемі ядра, виділяє пам'ять під буфери збереження стану. |
| `suspend(dev)` | Процесний (переривання увімкнені) | Так (`might_sleep()`) | Зупиняє активні DMA-передачі, очікує завершення черг команд, переводить мікросхеми в режим спокою. |
| `suspend_late(dev)` | Процесний (переривання увімкнені) | Так (`might_sleep()`) | Виконується після завершення фази `suspend` усіх пристроїв; керує низькорівневими шинами, клоками та доменами genpd. |
| `suspend_noirq(dev)` | Атомарний (переривання пристроїв вимкнені) | **Ні** (заборонено блокуватися) | Зберігає критичні апаратні регістри, переводить пристрій у низькоспоживаючий стан шини `D3hot` або `D3cold`. |
| `resume_noirq(dev)` | Атомарний (переривання пристроїв вимкнені) | **Ні** (заборонено блокуватися) | Відновлює апаратне живлення чіпа та базові регістри конфігурації до вмикання лінії переривання. |
| `resume_early(dev)` | Процесний (переривання увімкнені) | Так (`might_sleep()`) | Відновлює роботу шинних контролерів, ліній тактування та регуляторів напруги. |
| `resume(dev)` | Процесний (переривання увімкнені) | Так (`might_sleep()`) | Переініціалізує кільцеві буфери DMA, перезавантажує прошивку (firmware), запускає черги передачі. |
| `complete(dev)` | Процесний (переривання увімкнені) | Так (`might_sleep()`) | Звільняє тимчасові структури, знімає блокування на додавання дочірніх вузлів. |

### Правила повернення кодів помилок та відкіт стану (*Rollback Contract*)

Ядро вимагає суворого дотримання семантики кодів повернення:
- Повернення `0` сигналізує про успішне виконання фази.
- Повернення будь-якого від'ємного коду помилки (наприклад, `-EBUSY`, `-ETIMEDOUT`, `-EIO`) призводить до **негайного переривання процедури призупинення**.
- У разі виникнення помилки ядро запускає процедуру відкоту (*unwind/rollback*): для всіх пристроїв, які вже встигли успішно виконати поточну фазу або попередні фази, викликаються відповідні парні зворотні виклики відновлення у зворотному порядку (наприклад, збій у `suspend` викликає `resume` для раніше приспаних вузлів і `complete` для всіх підготовлених).

### Допоміжні макроси визначення `dev_pm_ops`

Для оптимізації драйверів та усунення невикористаного коду в конфігураціях ядра без прапорця `CONFIG_PM_SLEEP` застосовують спеціальні макроси:

- `DEFINE_SIMPLE_DEV_PM_OPS(name, suspend_fn, resume_fn)` — створює екземпляр `struct dev_pm_ops`, призначаючи вказані функції як для системного сну (`suspend`/`resume`), так і для гібернації (`freeze`/`thaw`/`restore`).
- `SYSTEM_SLEEP_PM_OPS(suspend_fn, resume_fn)` — заповнює поля системного сну у відкритій структурі.
- `RUNTIME_PM_OPS(suspend_fn, resume_fn, idle_fn)` — призначає функції для динамічного автоприсипляння.
- `pm_sleep_ptr(&ops)` — обгортає покажчик на структуру: якщо `CONFIG_PM_SLEEP` вимкнено, макрос розгортається в `NULL`, що дозволяє оптимізатору компілятора повністю викинути невикористані статичні функції з бінарного файлу модуля.

## Загальносистемні керуючі файли в `/sys/power/`

Простір користувача (зокрема системні демони `systemd-logind` та `upowerd`) взаємодіє з підсистемою ядра через набір псевдофайлів у каталозі `/sys/power/`.

### 1. `/sys/power/state` (Головний важіль ініціації сну)

Читання файлу повертає перелік підтримуваних ядром станів:
```bash
cat /sys/power/state
# freeze standby mem disk
```

- `freeze` — переводить систему в режим `s2idle` (Suspend-to-Idle): процеси заморожуються, пристрої присипляються через `dev_pm_ops`, процесори переходять у найглибший стан простою `cpuidle` (Package C-state / S0ix).
- `standby` — легкий сон (ACPI S1), за якого процесори зупиняють виконання, але напруга на системній шині зберігається.
- `mem` — перехід у режим призупинення в оперативну пам'ять (Suspend-to-RAM / ACPI S3 або s2idle, залежно від значення `/sys/power/mem_sleep`).
- `disk` — гібернація (ACPI S4): запис образу пам'яті в розділ підкачки та повне вимкнення платформи.

Запис одного з рядків (наприклад, `echo mem > /sys/power/state`) є блокуючою операцією: керування повертається процесу лише після повного пробудження системи або аварійного переривання сну.

### 2. `/sys/power/mem_sleep` (Вибір методу для режиму `mem`)

Визначає, яку саме апаратну реалізацію використовує ядро при записі `mem` у `/sys/power/state`:
```bash
cat /sys/power/mem_sleep
# [s2idle] shallow deep
```

- `s2idle` — програмний сон через механізми `cpuidle` та runtime PM (S0ix / Modern Standby).
- `shallow` — перехід у режим `standby` (ACPI S1).
- `deep` — класичний апаратний сон ACPI S3 зі скиданням живлення процесора та самовідновленням DRAM.

Активний режим позначається квадратними дужками. Зміна режиму виконується записом: `echo deep > /sys/power/mem_sleep`.

### 3. `/sys/power/wakeup_count` (Атомарне запобігання перегонам)

Інтерфейс для захисту від втрати подій пробудження, що надходять у момент підготовки до сну:
- Читання (`cat /sys/power/wakeup_count`) повертає монотонний лічильник зареєстрованих подій пробудження в системі. Якщо в цей момент активне хоча б одне блокування пробудження (`wakeup_source`), читання блокується до моменту його зняття.
- Запис (`echo <count> > /sys/power/wakeup_count`) атомарно перевіряє, чи не змінилося значення лічильника. Якщо за час між читанням та записом надійшла нова подія (наприклад, натиснуто клавішу або прийнято мережевий пакет), ядро відхиляє запис із кодом помилки `-EINVAL`, запобігаючи помилковому засинанню.

### 4. `/sys/power/pm_test` (Ізоляція збоїв та налагодовий тестовий режим)

Дозволяє протестувати проходження окремих фаз призупинення без фізичного знеструмлення платформи:
```bash
cat /sys/power/pm_test
# [none] core processors platform devices freezer
```

- `none` — звичайний повний цикл сну.
- `freezer` — заморожує процеси простору користувача та ядерні потоки, витримує паузу 5 секунд і негайно розморожує їх назад.
- `devices` — заморожує процеси та викликає фази `suspend` усіх зареєстрованих пристроїв, після чого виконує зворотний `resume`.
- `platform` — додатково виконує низькорівневі виклики платформи (ACPI/Device Tree) без вимкнення живлення.
- `processors` — заморожує процеси, зупиняє пристрої та відключає всі вторинні процесорні ядра (`disable_nonboot_cpus()`).
- `core` — проходить усі фази аж до вимкнення системних переривань (`syscore_suspend()`), після чого імітує пробудження.

### 5. `/sys/power/pm_async` (Асинхронний сон пристроїв)

Приймає значення `1` (за замовчуванням) або `0`. Якщо увімкнено, ядро викликає зворотні виклики `suspend`/`resume` для незалежних гілок дерева пристроїв паралельно в асинхронних доменах `async_domain`, строго контролюючи залежності між батьківськими та дочірніми вузлами.

### 6. `/sys/power/pm_trace` та `pm_trace_dev_match` (Апаратний хеш-трекер)

Використовується для виявлення драйвера, на якому зависає відновлення з S3 до увімкнення відеокарти чи послідовної консолі. При переході в сон ядро записує хеш назви останнього викликаного пристрою в 1 байт енергонезалежної пам'яті годинника реального часу RTC CMOS. Після примусового перезавантаження читання `/sys/power/pm_trace_dev_match` виводить назву винуватця збою.

## Атрибути керування пристроєм у `/sys/devices/.../power/`

Кожен пристрій у дереві `sysfs` має власний підкаталог `power/`, що містить атрибути індивідуального керування поведінкою під час сну:

- `wakeup` — приймає значення `enabled` або `disabled`. Визначає, чи дозволено даному контролеру генерувати сигнал системного пробудження.
- `wakeup_count` — кількість подій пробудження, згенерованих цим конкретним вузлом.
- `wakeup_active_count` — лічильник незавершених операцій обробки пробудження.
- `wakeup_total_time_ms` — сумарний час у мілісекундах, протягом якого пристрій утримував систему від засинання.
- `wakeup_max_time_ms` — максимальна тривалість одного безперервного блокування сну.
- `wakeup_last_time_ms` — позначка часу останньої активності джерела пробудження.
- `async` — приймає `enabled` або `disabled`; дозволяє вимкнути асинхронний паралельний виклик `dev_pm_ops` для конкретного примхливого драйвера.

## Ядерний API джерел пробудження (*Wakeup Sources*)

Для обліку пристроїв, які мають право будити систему, та для запобігання засинанню під час обробки критичних подій ядро надає підсистему `wakeup_source`.

### Керування можливістю пробудження пристрою

```c
#include <linux/pm_wakeup.h>

/* Ініціалізує внутрішній об'єкт wakeup_source та вмикає/вимикає пробудження */
int device_init_wakeup(struct device *dev, bool enable);

/* Встановлює апаратну здатність пристрою будити платформу */
void device_set_wakeup_capable(struct device *dev, bool capable);

/* Вмикає або вимикає генерацію подій пробудження для пристрою */
int device_set_wakeup_enable(struct device *dev, bool enable);

/* Перевіряє, чи пристрій увімкнено як активне джерело пробудження */
bool device_may_wakeup(struct device *dev);
```

### Блокування сну та фіксація подій у драйвері

```c
/* Забороняє системі засинати (піднімає активне блокування wakeup_source) */
void pm_stay_awake(struct device *dev);

/* Знімає заборону на засинання (опускає блокування wakeup_source) */
void pm_relax(struct device *dev);

/* Фіксує подію пробудження та автоматично утримує систему активною msec мс */
void pm_wakeup_event(struct device *dev, unsigned int msec);
```

### Налаштування ліній переривань для пробудження

```c
#include <linux/interrupt.h>

/* Позначає лінію переривання як здатну вивести платформу зі стану сну */
int enable_irq_wake(unsigned int irq);

/* Знімає статус джерела пробудження з лінії переривання */
int disable_irq_wake(unsigned int irq);
```

Виклик `enable_irq_wake(irq)` налаштовує контролер переривань (APIC, ARM GIC або GPIO-контролер) таким чином, щоб при вимкненні звичайного обслуговування переривань лінія лишалася чутливою до зміни рівня сигналу на контакті та генерувала системний сигнал пробудження (ACPI GPE або Wakeup Event) безпосередньо контролеру живлення платформи.
