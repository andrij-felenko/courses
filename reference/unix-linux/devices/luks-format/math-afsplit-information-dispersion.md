# 🧮 Алгоритм AFSplit: дифузія та ентропія розщеплення ключів

Алгоритм антикриміналістичного розщеплення інформації AFSplit (Anti-Forensic Information Splitting, розроблений австрійським криптографом Клеменсом Фрувіртом на базі концепції Стефана Люкса) вирішує дві ключові проблеми зберігання симетричних ключів шифрування на фізичних блокових носіях:

1. **Гарантоване та незворотне знищення ключа (Secure Erase):** на сучасних твердотілих накопичувачах (SSD, NVMe) мікроконтролер перерозподіляє блоки за допомогою внутрішнього алгоритму зношування (wear-leveling), тому прямий перезапис одного 64-байтового сектора пам'яті не гарантує фізичного знищення старого ключа у флешкомірках. AFSplit рівномірно розсіює ентропію головного ключа по сотнях секторів (зазвичай 4000 смуг сумарним розміром 256 КіБ). Втрата або стирання навіть одного довільного сектора призводить до безповоротного руйнування ключа.
2. **Мультиплікативне збільшення складності перебору (Work Factor Amplification):** зловмисник, який здійснює атаку перебором паролів за словником або методом грубої сили (brute-force), змушений для кожної спроби зчитати всі `N` смуг та виконати над ними повний ланцюг обчислення криптографічного гешу, що збільшує обчислювальні витрати на одну гіпотезу в `N` разів.

---

## 1. Порівняння з класичними схемами розділення секрету

У класичній схемі розділення секрету Шаміра (Shamir Secret Sharing) застосовується порогова схема `(k, n)`: для відновлення таємниці достатньо будь-яких `k` частин із загальної кількості `n`. Метою порогового розділення є стійкість до втрати окремих вузлів (доступність).

Антикриміналістичне розщеплення AFSplit переслідує прямо протилежну мету — **жорстку залежність від усіх компонентів без винятку**:

| Характеристика | Порогова схема Шаміра `(k, n)` | Антикриміналістичний AFSplit `(n, n)` |
| :--- | :--- | :--- |
| **Умова відновлення** | Достатньо будь-яких `k` часток із `n` | Обов'язкова наявність **усіх** `n` часток (100%) |
| **Втрата однієї частки** | Секрет успішно відновлюється | Секрет безповоротно втрачено (ентропія 100%) |
| **Накладні витрати пам'яті** | Лінійне зростання для кожної частки | Фіксоване розширення ключа у `n` смуг |
| **Складність перебору** | Не змінює обчислювальної вартості перевірки | Множить вартість перебору пароля у `n` разів |

AFSplit є граничним випадком порогової схеми `(n, n)` із застосуванням криптографічної дифузійної функції гешування між сусідніми смугами.

## 2. Математична формалізація прямого перетворення (Split)

Нехай задано головний ключ тому `K` довжиною `L` байтів (для алгоритму `aes-xts-plain64` із розміром ключа 512 біт довжина становить `L = 64` байти). Кількість смуг розщеплення позначається як `N` (за замовчуванням `N = 4000`), а `H` — криптографічна геш-функція з виходом довжиною `L` байтів (якщо довжина виходу гешу менша за `L`, вихід розширюється за допомогою лічильника ітерацій HMAC).

### Покроковий алгоритм генерації смуг:

1. **Генерація псевдовипадкового шуму:**
   Формуються `N - 1` незалежних випадкових блоків однакової довжини `L`, розподілених за рівномірним законом:
```
S[1], S[2], ..., S[N-1] ∈_R {0, 1}^(8·L)      [незалежний псевдовипадковий шум]
```

2. **Обчислення ланцюга нелінійної дифузії:**
   Послідовно обчислюється вектор проміжних станів `I[i]`:
```
I[0] = 0^(8·L)                               [початковий нульовий стан]
I[1] = H(I[0] ⊕ S[1])                        [дифузія першої смуги]
I[2] = H(I[1] ⊕ S[2])                        [дифузія другої смуги]
...
I[N-1] = H(I[N-2] ⊕ S[N-1])                  [фінальний дифузійний стан]
```

3. **Формування замикаючої смуги:**
   Остання смуга `S[N]` обчислюється через побітове додавання за модулем 2 (XOR) головного ключа `K` та фінального стану дифузії:
```
S[N] = K ⊕ I[N-1]                            [накладання Master Key на дифузійний стан]
```

Згенерований масив із `N` смуг `(S[1], S[2], ..., S[N])` шифрується ключем шпарини (VKDK) за допомогою блокового шифру AES-XTS і записується в область keyslot на диску.

## 3. Алгоритм злиття та відновлення ключа (Merge)

Під час відкриття шифрованого тома після розшифрування області шпарини ядро та бібліотека `libcryptsetup` виконують злиття смуг у вихідний Master Key.

```
I[0] = 0^(8·L)                               [ініціалізація вектора]
I[i] = H(I[i-1] ⊕ S[i])   для i = 1 .. N-1   [послідовний прохід дифузійного ланцюга]
K = S[N] ⊕ I[N-1]                            [відновлення вихідного ключа K]
```

### Алгебраїчне доведення коректності:

```
S[N] ⊕ I[N-1]
= (K ⊕ I[N-1]) ⊕ I[N-1]                      [заміна S[N] на формулу генерації]
= K ⊕ (I[N-1] ⊕ I[N-1])                      [асоціативність операції XOR]
= K ⊕ 0^(8·L)                                [властивість самоінверсії: X ⊕ X = 0]
= K                                          [нейтральний елемент операції XOR]
```

## 4. Теоретико-інформаційна оцінка ентропії при пошкодженні смуг

Розглянемо випадок, коли зловмисник отримав фізичний доступ до носія, але внаслідок стирання або пошкодження одна довільна смуга `S[m]` (де `1 ≤ m ≤ N`) була втрачена.

### Випадок 1: Втрата останньої смуги `S[N]`

Якщо відсутня остання смуга `S[N]`:
```
K = S[N] ⊕ I[N-1]
```
Оскільки смуга `S[N]` є результатом побітового додавання ключа `K` з нелінійним станом `I[N-1]`, з точки зору теорії інформації Клода Шеннона вона виконує роль одноразового блокнота (One-Time Pad).

Апріорна невизначеність ключа `K` за відсутності `S[N]` дорівнює повній довжині ключа:
```
H(K | S[1], ..., S[N-1]) = H(K) = 8·L бітів
```
Для 512-бітного ключа AES-XTS це становить 512 бітів абсолютної невизначеності.

### Випадок 2: Втрата проміжної смуги `S[m]` (де `1 ≤ m < N`)

Якщо втрачено випадковий блок `S[m]`, зловмисник знає всі інші смуги, а також значення `S[N]`. Щоб знайти `K`, йому необхідно обчислити `I[N-1]`, що вимагає проходження всього ланцюжка гешування через невідомий стан `I[m] = H(I[m-1] ⊕ S[m])`.

Оскільки блок `S[m]` генерувався з рівномірного випадкового розподілу:
```
H_min(S[m]) = 8·L бітів = 512 бітів
```

Криптографічна геш-функція `H` (наприклад, SHA-256) володіє властивістю стійкості до відновлення прообразу (preimage resistance). Неможливо обчислити `I[m]` за відомим `I[m+1]` швидше, ніж повним перебором вхідного значення `S[m]`.

Ймовірність успішного випадкового вгадування відсутнього блоку `S[m]` дорівнює:
```
P(успіху) = 2^(-512) ≈ 7.45 · 10^(-155)      [ймовірність підбору відсутнього блоку]
```

Це число перебуває далеко за межами фізичних можливостей будь-яких обчислювальних систем у Всесвіті, що забезпечує гарантоване знищення інформації.

## 5. Вплив AFSplit на стійкість до атак грубої сили

Загальні часові витрати `T_guess` на перевірку однієї гіпотези пароля під час атаки перебором складаються з витрат на роботу KDF, дешифрування смуг та обчислення дифузії:

```
T_guess = T_kdf + N · T_cipher + (N - 1) · T_hash + T_digest

де:
T_kdf    — час виконання функції розтягування Argon2id (наприклад, 2000 мс);
T_cipher — час розшифрування одного блоку смуги AES-XTS;
T_hash   — час одного кроку криптографічного гешування SHA-256;
T_digest — час перевірки відновленого Master Key через PBKDF2 у словнику digests;
N        — кількість смуг (4000).
```

### Мультиплікативний ефект:

1. **Неможливість конвеєрного відкидання пароля:** зловмисник не може перевірити правильність пароля за першим байтом або першим сектором шпарини. Він зобов'язаний зчитати всі 256 КіБ і виконати 4000 операцій AES та 3999 операцій SHA-256 для кожної спроби.
2. **Вимоги до смуги пропускання пам'яті:** перевірка кожного пароля генерує активний потік зчитування з оперативної пам'яті щонайменше 256 КіБ даних. Для паралельного перебору мільйона паролів на секунду зловмиснику знадобиться нереалістична пропускна здатність шини пам'яті понад 256 ГБ/с лише на передачу смуг AFSplit, що створює додатковий бар'єр для спеціалізованих зломних кластерів.
