# 📋 Інтерфейс перебудови md: параметри --grow, sysfs і суперблок

Підсистема динамічної перебудови програмного RAID у Linux спирається на три пов'язані рівні взаємодії: інтерфейс командного рядка простору користувача утиліти `mdadm`, шар керування та телеметрії ядра через віртуальну файлову систему `sysfs`, і двійкові структури суперблока на фізичних дискових накопичувачах.

Потреба в окремому детальному описі цих інтерфейсів зумовлена тим, що різні рівні оперують різними одиницями виміру та різними протоколами синхронізації. Утиліта `mdadm` приймає параметри в Кілобайтах і Мегабайтах, суперблок зберігає координати в абсолютних 512-байтових секторах дисків, а файли `sysfs` використовують власні формати представлення статусів та блокувальних вікон.

Усі наведені нижче параметри, шляхи файлів та зміщення двійкових структур перевірено за сирцевими кодами ядра Linux (`drivers/md/md.c`, `drivers/md/raid5.c`, `include/uapi/linux/raid/md_p.h`) та вихідними текстами пакета `mdadm`.

## 1. Параметри та семантика команди `mdadm --grow`

Команда `--grow` (або її одномісний еквівалент `-G`) є головним інструментом простору користувача для запуску, модифікації або відновлення процесу перебудови геометрії активного масиву `/dev/mdX`.

Головна відмінність режиму `--grow` від початкового створення масиву (`--create`) полягає в тому, що всі операції виконуються над робочим блоковим пристроєм, який залишається підмонтованим у системі й продовжує обслуговувати синхронні та асинхронні запити введення/виведення від прикладних програм.

Нижче наведено перелік параметрів команди, їхні типи даних та умови застосування:

* `-l`, `--level=` — новий цільовий рівень надлишковості масиву (`0`, `1`, `4`, `5`, `6`, `10`). Цей параметр запускає процедуру міграції рівнів. Перехід між рівнями дозволений лише для математично та структурно сумісних конфігурацій. Наприклад, перетворення дзеркала RAID1 на масив з розподіленою парністю RAID5 вимагає проміжного кроку переведення у 2-дисковий RAID5, де один диск слугує джерелом даних, а другий тимчасово містить дзеркальну парність. Перехід з RAID5 у RAID6 вимагає додавання накопичувача для розміщення другого синдрому парності Q.
* `-n`, `--raid-devices=` — цільова кількість активних накопичувачів-учасників масиву. Збільшення цього значення розширює корисний дисковий простір (для RAID0, RAID5, RAID6). Перед виконанням цієї команди нові фізичні диски мають бути зареєстровані в масиві як резервні (spare) за допомогою команди `mdadm --add /dev/mdX /dev/sdN`. Зменшення кількості дисків вимагає попереднього зменшення розміру файлової системи та вивільняє «зайві» накопичувачі, переводячи їх у стан запасних.
* `-c`, `--chunk=` — розмір блоку чергування (смуги) в Кілобайтах. Розмір обов'язково має бути степенем двійки та кратним сторінці пам'яті (типово від 4 КіБ до 4096 КіБ). Зміна розміру чанка змінює крок нарізання даних і змушує ядро перераховувати зміщення кожного логічного блоку по всіх дисках.
* `-p`, `--layout=` — внутрішній алгоритм розміщення блоків даних та контрольних сум парності всередині смуг. Для масивів RAID5 підтримуються схеми `left-symmetric` (ls, найпродуктивніша для послідовного читання), `right-symmetric` (rs), `left-asymmetric` (la), `right-asymmetric` (ra), а також спеціальні перехідні схеми `parity-first` та `parity-last`. Для RAID10 підтримуються схеми `n2` (near-дзеркало), `f2` (far-рознесення) та `o2` (offset-зсув).
* `--backup-file=` — абсолютний шлях до допоміжного файлу збереження критичної зони перекриття смуг. Цей файл обов'язково повинен розміщуватися на **іншому** фізичному носії або окремій файловій системі, яка не залежить від перебудовуваного масиву. Файл використовується як тимчасовий буфер для запобігання втраті даних при раптовому зникненні живлення в моменти, коли ядро перезаписує старі смуги новими блоками.
* `--continue` — прапорець примусового відновлення перерваного або замороженого процесу перебудови (наприклад, після перезавантаження системи, усунення апаратної помилки шини або ручної зупинки).
* `-z`, `--size=` — встановлює доступну ємність компонентних розділів на кожному диску. Застосовується після того, як усі накопичувачі в масиві було по черзі замінено на диски більшого обсягу.
* `--array-size=` — встановлює видимий ззовні розмір масиву в Кілобайтах (або значення `max` для максимального заповнення). Дозволяє обмежити розмір логічного пристрою `/dev/mdX` перед зміною геометрії для захисту файлової системи від виходу за межі узгодженого простору.

## 2. Керуючі та діагностичні атрибути sysfs (`/sys/block/mdX/md/`)

Ядро Linux взаємодіє з простором користувача через структури віртуальної файлової системи `sysfs`. Для кожного масиву створюється каталог `/sys/block/mdX/md/`, де експортуються атрибути керування поточною фоновою синхронізацією.

Під час виконання перебудови ядро створює спеціалізований потік керування, а файли `sysfs` дозволяють зчитувати детальний прогрес з точністю до одного сектора, регулювати пріоритет фонової роботи відносно призначеного для користувача вводу/виводу або екстрено зупиняти процес.

Нижче наведено детальний розбір ключових атрибутів:

### Стан та керування процесом

* `sync_action` — відображає поточний тип операції фонової синхронізації. Коли масив перебудовується, читання цього файлу повертає рядок `reshape`. Запис рядка `idle` призводить до безпечного призупинення перебудови зі збереженням досягнутої точки в суперблоці. Запис `frozen` повністю блокує будь-які зміни стану до явного розмороження. Запуск перевірки цілісності (`check` або `repair`) є забороненим, доки файл містить значення `reshape`.
* `reshape_position` — головний лічильник прогресу. При читанні повертає 64-бітне ціле число — адресу 512-байтового сектора масиву, до якого завершено перебудову. Якщо перебудова не активна, файл містить рядок `none`. При ручному відновленні через `mdadm` запис у цей файл задає початкову координату, з якої потік ядра має продовжити роботу.
* `reshape_direction` — доступний лише для читання текстовий атрибут, який показує фізичний напрямок обходу адресного простору накопичувачів. Значення `forwards` вказує, що перебудова рухається від початку диска до кінця (від сектора 0 у бік зростання LBA). Значення `backwards` вказує на зворотний рух — від останнього сектора масиву до нульового, що є обов'язковим при розширенні кількості дисків у RAID5 для уникнення затирання ще не вичитаних смуг.
* `sync_completed` — експортує два числа через скісну риску: кількість успішно оброблених секторів та загальну кількість секторів, що підлягають перебудові (наприклад, `20971520 / 104857600`). Слугує основою для побудови індикаторів відсоткового прогресу.

### Захист критичного вікна та синхронізація вводу/виводу

* `suspend_lo` та `suspend_hi` — числові координати меж діапазону секторів (у 512-байтових одиницях), усередині якого ядро тимчасово блокує виконання прикладного вводу/виводу. Коли потік перебудови готується переписати смугу, він записує координати цієї смуги в `suspend_lo` та `suspend_hi`. Якщо прикладний процес намагається прочитати або записати дані в цей інтервал, його запит `bio` заморожується і стає у чергу очікування `mddev->sb_wait`. Після того як ядро перерахувало парність, записало нову смугу й оновило суперблок, межі `suspend` розсуваються, і заблокований процес негайно отримує доступ до даних за новою геометрією.

### Регулювання продуктивності та пропускної здатності

* `sync_speed_min` — гарантована нижня межа швидкості перебудови в Кілобайтах на секунду на один накопичувач (за замовчуванням становить 1 000 КіБ/с). Якщо масив перевантажений запитами користувача, ядро штучно виділяє кванти часу для перебудови, щоб процес не зупинився повністю.
* `sync_speed_max` — верхня межа швидкості в Кілобайтах на секунду на один диск (типово 200 000 КіБ/с). Запобігає повній утилізації шини накопичувачів фоновим процесом у моменти простою системи.
* `sync_speed` — поточна миттєва швидкість перенесення даних, обчислена ядром за останній інтервал часу.

Крім локальних атрибутів масиву, ядро Linux надає загальносистемні регулятори швидкості синхронізації через псевдофайлову систему `procfs`:
* `/proc/sys/dev/raid/speed_limit_min`
* `/proc/sys/dev/raid/speed_limit_max`

## 3. Двійкові структури суперблока 1.x (`struct mdp_superblock_1`)

Формат метаданих 1.x (версії 1.0, 1.1 та 1.2) зберігає стан перебудови в заголовку `struct mdp_superblock_1`, визначеному в заголовному файлі `include/uapi/linux/raid/md_p.h`.

Усі двійкові поля записуються в порядку байтів little-endian. Якщо сервер зазнає збою живлення, утиліта `mdadm` при наступному скануванні дисків зчитує ці поля й точно знає, на якому секторі зупинився процес і яку геометричну конфігурацію мав масив до аварії.

Розглянемо ключові поля суперблока, що відповідають за перебудову:

```
Зсув (байт)   Поле                 Тип      Призначення
---------------------------------------------------------------------------------
8             feature_map          le32     Бітова маска розширених можливостей
100           new_level            le32     Цільовий рівень масиву після перебудови
104           reshape_position     le64     Сектор масиву — поточна лінія межі
112           delta_disks          le32     Зміна кількості дисків (+1, -1 тощо)
116           new_layout           le32     Цільовий числовий код розкладки
120           new_chunk            le32     Цільовий розмір чанка в секторах
124           new_offset           le32     Зсув початку даних (data offset shift)
```

Поле `feature_map` містить бітові прапорці стану:
* `MD_FEATURE_RESHAPE_ACTIVE` (біт `0x04`) — встановлюється в одиницю в момент старту перебудови. Якщо під час збирання масиву знайдено цей біт, ядро відмовляється активувати масив у звичайному режимі та вимагає відновлення процесу `reshape`.
* `MD_FEATURE_RESHAPE_BACKWARDS` (біт `0x08`) — фіксує зворотний напрямок руху перебудови (від кінця диска до початку).
* `MD_FEATURE_NEW_OFFSET` (біт `0x10`) — сигналізує, що перебудова виконується за технологією безпечного зміщення даних (Data Offset Shifting) без використання зовнішнього резервного файлу.

## 4. Програмний моніторинг та взаємодія з sysfs

Для створення системних служб спостереження, моніторингу працездатності сховищ або інтеграції з панелями керування серверами простір користувача реалізує опитування файлів `sysfs`.

Нижче наведено робочий приклад утиліти двома мовами програмування (C та C++), яка зчитує стан масиву, визначає наявність активної перебудови, напрямок руху смуг, поточну швидкість та точні координати оброблених секторів.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static int read_sysfs_value(const char *path, char *out_buf, size_t max_size) {
    FILE *file_ptr = fopen(path, "r");
    if (!file_ptr) {
        return -1;
    }
    if (!fgets(out_buf, (int)max_size, file_ptr)) {
        fclose(file_ptr);
        return -1;
    }
    fclose(file_ptr);
    out_buf[strcspn(out_buf, "\r\n")] = '\0';
    return 0;
}

int main(int argc, char *argv[]) {
    const char *array_name = (argc > 1) ? argv[1] : "md0";
    char file_path[256];
    char action_str[64] = {0};
    char completed_str[128] = {0};
    char speed_str[64] = {0};
    char direction_str[64] = {0};

    snprintf(file_path, sizeof(file_path), "/sys/block/%s/md/sync_action", array_name);
    if (read_sysfs_value(file_path, action_str, sizeof(action_str)) < 0) {
        fprintf(stderr, "Помилка: не вдалося відкрити атрибути пристрою %s у sysfs\n", array_name);
        return 1;
    }

    if (strcmp(action_str, "reshape") != 0) {
        printf("Масив %s не перебудовується (поточний стан: %s)\n", array_name, action_str);
        return 0;
    }

    snprintf(file_path, sizeof(file_path), "/sys/block/%s/md/sync_completed", array_name);
    read_sysfs_value(file_path, completed_str, sizeof(completed_str));

    snprintf(file_path, sizeof(file_path), "/sys/block/%s/md/sync_speed", array_name);
    read_sysfs_value(file_path, speed_str, sizeof(speed_str));

    snprintf(file_path, sizeof(file_path), "/sys/block/%s/md/reshape_direction", array_name);
    read_sysfs_value(file_path, direction_str, sizeof(direction_str));

    printf("Стан масиву %s: активна перебудова (reshape)\n", array_name);
    printf("  Напрямок руху смуг  : %s\n", direction_str[0] ? direction_str : "невідомо");
    printf("  Прогрес у секторах  : %s\n", completed_str);
    printf("  Поточна швидкість   : %s КіБ/с\n", speed_str);

    return 0;
}
```

```cpp
#include <iostream>
#include <fstream>
#include <string>
#include <filesystem>
#include <string_view>

namespace fs = std::filesystem;

class RaidReshapeMonitor {
public:
    explicit RaidReshapeMonitor(std::string device_name)
        : device_name_(std::move(device_name)) {}

    bool inspect_status() const {
        const fs::path sysfs_base = fs::path("/sys/block") / device_name_ / "md";
        
        if (!fs::exists(sysfs_base)) {
            std::cerr << "Помилка: каталог " << sysfs_base << " не існує в системі\n";
            return false;
        }

        const std::string action = query_sysfs_attribute(sysfs_base / "sync_action");
        if (action != "reshape") {
            std::cout << "Масив " << device_name_ 
                      << " не перебудовується (стан: " << action << ")\n";
            return true;
        }

        const std::string completed = query_sysfs_attribute(sysfs_base / "sync_completed");
        const std::string speed = query_sysfs_attribute(sysfs_base / "sync_speed");
        const std::string direction = query_sysfs_attribute(sysfs_base / "reshape_direction");

        std::cout << "Стан масиву " << device_name_ << ": активна перебудова (reshape)\n";
        std::cout << "  Напрямок руху смуг  : " << (direction.empty() ? "невідомо" : direction) << "\n";
        std::cout << "  Прогрес у секторах  : " << completed << "\n";
        std::cout << "  Поточна швидкість   : " << speed << " КіБ/с\n";
        return true;
    }

private:
    std::string device_name_;

    static std::string query_sysfs_attribute(const fs::path &attribute_path) {
        std::ifstream file_stream(attribute_path);
        if (!file_stream.is_open()) {
            return "";
        }
        std::string line_content;
        std::getline(file_stream, line_content);
        return line_content;
    }
};

int main(int argc, char *argv[]) {
    const std::string target_device = (argc > 1) ? argv[1] : "md0";
    const RaidReshapeMonitor monitor(target_device);
    return monitor.inspect_status() ? 0 : 1;
}
```
