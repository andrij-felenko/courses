# 📜 Від fbdev до DRM: Історія графічного стеку

У ранні часи Linux інтерфейс fbdev був проривом. Він забезпечував апаратно-незалежний спосіб виводу графіки. Раніше X-сервер (віконна система) повинен був містити власні низькорівневі драйвери для кожної відеокарти, які безпосередньо маніпулювали регістрами пристрою. fbdev переніс базове управління відеорежимами в ядро.

Проте з часом апаратне забезпечення ускладнювалося. З'явилися вимоги до апаратного прискорення 2D/3D (OpenGL), управління декількома моніторами, композитного рендерингу вікон. fbdev не міг з цим впоратися, адже його дизайн передбачав лише один лінійний буфер. Якщо дві програми намагалися малювати одночасно або віконний менеджер оновлював частину екрана під час промальовування, користувач бачив "розриви" (tearing) або мерехтіння.

Щоб розв'язати ці проблеми, було створено Direct Rendering Manager (DRM). Спочатку він лише керував доступом до 3D-прискорювача, залишаючи управління режимами екрана простору користувача (User Mode Setting, UMS). Згодом управління режимами перенесли в ядро — так з'явився Kernel Mode Setting (KMS), інтегрований у DRM. KMS і DRM забезпечили чистий API для налаштування дисплеїв, підтримки кількох площин (planes), апаратних курсорів та синхронізації з розгорткою монітора, залишивши fbdev лише роль спадщини для простих сценаріїв.
