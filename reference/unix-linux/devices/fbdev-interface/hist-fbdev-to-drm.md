# 📜 Від fbdev до DRM: Історія графічного стеку

У ранні часи Linux інтерфейс fbdev був проривом. Він забезпечував апаратно-незалежний спосіб виводу графіки. Раніше X-сервер (віконна система) повинен був містити власні низькорівневі драйвери для кожної відеокарти, які безпосередньо маніпулювали регістрами пристрою. fbdev переніс базове управління відеорежимами в ядро.

Проте з часом апаратне забезпечення ускладнювалося. З'явилися вимоги до апаратного прискорення 2D/3D (OpenGL), керування кількома моніторами, композитного рендерингу вікон. fbdev не міг з цим впоратися, адже його дизайн передбачав лише один лінійний буфер. Буфер був один і той самий для малювання й для показу: відеоконтролер зчитував його безперервно, тож недомальований кадр потрапляв на екран як є — звідси розриви (tearing) і мерехтіння.

Щоб розв'язати ці проблеми, було створено Direct Rendering Manager (DRM). Спочатку він лише керував доступом до 3D-прискорювача, а налаштування відеорежимів залишалося на боці простору користувача (User Mode Setting, UMS). Згодом керування режимами перенесли в ядро — так з'явився Kernel Mode Setting (KMS), інтегрований у DRM. KMS і DRM забезпечили чистий API для налаштування дисплеїв, підтримки кількох площин (planes), апаратних курсорів та синхронізації з розгорткою монітора, залишивши fbdev лише роль спадщини для простих сценаріїв.
