Коли операційній системі Linux або простій програмі потрібно вивести графіку на екран без використання великих віконних серверів, вона може скористатися кадровим буфером (Framebuffer). У Linux цей інтерфейс представлений файлом `/dev/fb0`.

Кадровий буфер абстрагує відеокарту, дозволяючи програмі бачити відеопам'ять як звичайний масив даних. Замість того, щоб надсилати складні графічні команди, програма дізнається розмір екрана, просить ядро надати прямий доступ до відеопам'яті (через `mmap`) і просто записує туди значення кольорів пікселів. 

![Ліворуч адресний простір процесу, праворуч відеопам'ять пристрою /dev/fb0; стрілка з підписом «Відображення (mmap)» показує, що ділянка в процесі — не копія, а те саме кадрове вікно пам'яті, доступне через вказівник fbp](/reference/unix-linux/devices/fbdev-interface/img/fb-structure.svg)

*Після `mmap` запис за вказівником у процесі потрапляє просто в кадровий буфер — копіювати нічого не треба.*

Сьогодні класичний API `fbdev` вважається застарілим через відсутність апаратного прискорення та погану підтримку сучасних багатомоніторних систем. На зміну йому прийшла підсистема DRM/KMS (Direct Rendering Manager). 

Однак, оскільки безліч існуючих програм (наприклад, консолі, прості інтерфейси терміналів) все ще покладаються на `/dev/fb0`, сучасні драйвери DRM підтримують шар емуляції `DRM_FBDEV_EMULATION`. Цей шар створює звичний пристрій `/dev/fb0`, який працює зі старими програмами, але під капотом використовує сучасні механізми ядра.
