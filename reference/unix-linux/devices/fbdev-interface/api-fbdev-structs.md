# 📋 Структури та ioctl API кадрового буфера

Щоб правильно малювати на екрані, програма повинна знати фізичні параметри кадрового буфера. Для цього використовуються системні виклики `ioctl` та дві ключові структури з `<linux/fb.h>`.

## fb_fix_screeninfo (Фіксована інформація)
Отримується через `ioctl(fd, FBIOGET_FSCREENINFO, &finfo)`. Ця структура містить параметри, які не можна змінити під час роботи, наприклад, базову адресу пам'яті та її загальний розмір.

Найбільш важливий параметр тут — `line_length`. Це довжина одного рядка пікселів у байтах. Вона не завжди дорівнює ширині екрана, помноженій на байти на піксель, оскільки ядро або апаратне забезпечення можуть вирівнювати рядки (padding) для оптимізації доступу до пам'яті.

## fb_var_screeninfo (Змінна інформація)
Отримується через `ioctl(fd, FBIOGET_VSCREENINFO, &vinfo)`. Включає параметри, які можна спробувати змінити (роздільна здатність, глибина кольору тощо). 

Важливі поля:
- `xres` та `yres`: видима роздільна здатність екрана (ширина та висота в пікселях).
- `bits_per_pixel`: глибина кольору (зазвичай 16, 24 або 32 біти на піксель).
- `red`, `green`, `blue`, `transp`: розкладка каналів усередині пікселя. Кожне поле — `struct fb_bitfield` зі зміщенням і довжиною в бітах (`include/uapi/linux/fb.h`). Саме звідси, а не з `bits_per_pixel`, програма дізнається порядок байтів і чи є взагалі альфа-канал: у поширеному 32-бітному `XRGB8888` довжина `transp` нульова, тобто четвертий байт пікселя не використовується.

За допомогою цих двох структур програма точно знає, скільки байтів пам'яті потрібно відобразити (mmap) і як правильно вирахувати адресу кожного пікселя на екрані.
