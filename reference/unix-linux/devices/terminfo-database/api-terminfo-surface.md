# 📋 Поверхня terminfo: імена можливостей, оператори, функції, утиліти

Довідка для того моменту, коли механізм уже зрозумілий, а треба точно: за яким ім'ям питати, що робить конкретний оператор `%…`, що поверне функція, коли термінал такого не вміє, і яким ключем витягти з бази правду. Усе нижче звірене з `terminfo(5)`, `user_caps(5)`, `curs_terminfo(3x)`, `tput(1)`, `tic(1m)`, `infocmp(1m)` і `toe(1m)` з [ncurses](book:unix-linux/ncurses) — вільної реалізації, яку в Linux майже завжди й мають на увазі, кажучи «terminfo».

## Джерельний синтаксис запису

```
ім'я|псевдонім|…|опис для людини,
        булева,  числова#значення,  рядкова=байти,
        скасована@,
        use=інший-запис,
```

Поля розділяє кома; кому всередині значення пишуть як `\,` або `\054`. Булева або є, або її нема — власного значення в неї не буває; числову впізнають за `#`, рядкову за `=`.

`use=` вставляє чужий запис цілком, і три правила злиття варто знати напам'ять: написане в записі явно **перемагає** успадковане; кілька `use=` зливаються **справа наліво**; а `xx@` скасовує можливість `xx`, якщо стоїть **ліворуч** від того `use=`, який її приносить.

Кожна можливість має коротке ім'я для бази й довге ім'я змінної для бібліотеки. Питають завжди коротким — довге стає в пригоді хіба що при читанні чужого коду або виводу `infocmp -L`.

### Клавіші: що термінал надсилає

Ці можливості читають у зворотний бік — вони описують байти, які **приходять** від клавіші, і саме за ними бібліотека впізнає натиск.

| ім'я | довге ім'я | клавіша |
|---|---|---|
| `smkx` / `rmkx` | `keypad_xmit` / `keypad_local` | увійти в режим передавання клавіатури й вийти з нього |
| `kcuu1` `kcud1` `kcub1` `kcuf1` | `key_up` / `_down` / `_left` / `_right` | стрілки |
| `khome` / `kend` | `key_home` / `key_end` | початок і кінець |
| `kpp` / `knp` | `key_ppage` / `key_npage` | сторінка вгору й униз |
| `kbs` / `kdch1` | `key_backspace` / `key_dc` | забій і видалення |
| `kf0`…`kf63` | `key_f0`…`key_f63` | функційні клавіші |
| `kmous` | `key_mouse` | сталася подія миші |

Окремо стоять `u6`–`u9` (`user6`–`user9`). Сама `terminfo(5)` каже про них рівно «рядок користувача #6» — жодного змісту стандарт у них не вкладає. Зміст вклала база ncurses за домовленістю: `u7` — запит позиції курсора, `u6` — формат відповіді на нього. Це конвенція бази, не стандарт, і читати її треба саме так.

## Мова параметрів: повна таблиця операторів

| оператор | що робить |
|---|---|
| `%%` | вивести знак `%` |
| `%p1`…`%p9` | покласти на стек параметр 1…9 |
| `%d` `%s` `%c` | зняти верхівку й вивести числом, рядком, байтом |
| `%[[:]прапорці][ширина[.точність]]doxXs` | вивід як у `printf`; прапорці `-`, `+`, `#`, пробіл |
| `%{nn}` | покласти цілу сталу `nn` |
| `%'c'` | покласти код символу `c` |
| `%l` | зняти рядок і покласти його довжину |
| `%+` `%-` `%*` `%/` `%m` | арифметика; `%m` — остача |
| `%&` `%\|` `%^` | побітові «і», «або», «виключне або» |
| `%=` `%<` `%>` | порівняння |
| `%A` `%O` | логічні «і» та «або» — для умов |
| `%!` `%~` | одномісні: логічне заперечення й побітове доповнення |
| `%i` | додати одиницю до **перших двох параметрів** |
| `%Pa`…`%Pz` / `%ga`…`%gz` | записати / прочитати динамічну змінну |
| `%PA`…`%PZ` / `%gA`…`%gZ` | те саме для статичної |
| `%?` … `%t` … `%e` … `%;` | якщо / то / інакше / кінець |

Чотири речі, на яких спотикаються найчастіше.

**Порядок операндів.** Двомісний оператор бере верхівку правим операндом, а те, що під нею, — лівим. Тому `%p1%{8}%-` — це `p1 − 8`, а `%p1%{8}%<` — це `p1 < 8`, а не навпаки.

**Двокрапка в `%[[:]…]`.** Без неї `%-` прочитається як віднімання. Двокрапка й існує рівно для того, щоб дозволити наступному знакові бути прапорцем `-`.

**`%i` діє на параметри, не на стек.** Він збільшує самі параметри 1 і 2, тому мусить стояти **до** тих `%p1`/`%p2`, які їх читають — саме тому `cup=\E[%i%p1%d;%p2%dH` починається з нього.

**Змінні `a`–`z` і `A`–`Z` — два різні набори.** Слова «динамічна» й «статична» тут оманливі: в ncurses обидва набори **не скидаються між викликами `tparm`**. Інші реалізації цього не обіцяють, тож писати рецепт, що покладається на пережиток попереднього виклику, — значить втратити переносність.

Ланцюжок умов будують без вкладення: `%? c1 %t b1 %e c2 %t b2 %e b3 %;` — усі `%e` йдуть підряд, а `%;` один на весь ланцюжок.

## Затримки

`$<число>` усередині рядкового значення означає паузу в мілісекундах; число має щонайбільше один знак після коми (`$<5.5>`). Суфікси:

- `*` — пауза пропорційна кількості зачеплених рядків (`$<5*>`); саме заради цієї форми `tputs` бере їх число другим аргументом;
- `/` — пауза обов'язкова навіть там, де `xon` каже, що керування потоком є;
- обидва разом теж дозволені: `$<5*/>`.

Паузу бібліотека відтворює байтами-заповнювачами, а їх кількість рахує зі швидкості лінії — тієї самої, що лежить у [налаштуваннях termios](book:unix-linux/tty-and-termios) дескриптора. Байт бере з `pad`, типово NUL; булева `npc` каже, що заповнювача не існує взагалі.

## Функції ncurses

```c
#include <curses.h>
#include <term.h>

int        setupterm(const char *term, int filedes, int *errret);
int        tigetflag(const char *cap);
int        tigetnum(const char *cap);
char      *tigetstr(const char *cap);
char      *tparm(const char *str, long p1 /* … */, long p9);
char      *tiparm(const char *str, ...);
int        tputs(const char *str, int affcnt, int (*putc)(int));
int        putp(const char *str);
TERMINAL  *set_curterm(TERMINAL *nterm);
int        del_curterm(TERMINAL *oterm);
int        restartterm(const char *term, int filedes, int *errret);
```

`setupterm(NULL, …)` бере ім'я з `TERM`; `filedes` — дескриптор термінала, з якого бібліотека, зокрема, дізнається розміри екрана. Повертає `OK` або `ERR`, а в `errret` кладе стан — і читати ці два значення треба **разом**: `OK` разом зі станом `1` означає «все гаразд», а якщо повернуто `ERR`, то стан пояснює, що саме сталося.

| `errret` при `ERR` | що сталося |
|---|---|
| `1` | термінал друкарського роду (немає руйнівного забою) |
| `0` | тип не знайдено або він надто загальний, щоб на ньому працювати |
| `-1` | самої бази terminfo знайти не вдалося |

Якщо `errret` — нульовий вказівник, `setupterm` при помилці друкує повідомлення й **завершує програму**. У бібліотеці, яку хтось у себе вбудує, цей аргумент тому обов'язковий.

`tputs(рядок, affcnt, putc)` пропускає рядок крізь механізм затримок і віддає байти по одному функції `putc`; `affcnt` — кількість зачеплених рядків або `1`, коли це ні до чого. `putp(s)` — це рівно `tputs(s, 1, putchar)`, і вивід його йде в `stdout`, а не в той `filedes`, що подали в `setupterm`.

`del_curterm(oterm)` звільняє запис. Якщо `oterm` — це поточний `cur_term`, то далі звертання до будь-якої можливості можуть потрапити в уже звільнену пам'ять, аж доки `setupterm` не покличуть знову.

### Що повертають, коли можливості немає

| функція | ім'я не того роду | скасовано або відсутня | звичайна відповідь |
|---|---|---|---|
| `tigetflag` | `-1` | `0` | `1` |
| `tigetnum` | `-2` | `-1` | саме число |
| `tigetstr` | `(char *)-1` | `NULL` | вказівник на рядок |

Ця таблиця — головне, заради чого сюди зазирають. Випадків **два**, і плутають їх постійно: `tigetstr("colors")` поверне не `NULL`, а `(char *)-1`, бо `colors` — числова можливість, і наївне `if (s)` пропустить цю помилку далі, у `tparm`. Правильна перевірка рядкової можливості завжди подвійна:

```c
char *s = tigetstr("cup");
if (s == NULL || s == (char *)-1)
    /* цей термінал курсора не ставить */;
```

### Мінімальний робочий виклик

```c
#include <curses.h>
#include <term.h>
#include <stdio.h>

int main(void)
{
    int err;
    if (setupterm(NULL, 1, &err) == ERR) {          /* NULL → узяти з TERM */
        fprintf(stderr, "terminfo: стан %d\n", err);
        return 1;
    }

    char *cup = tigetstr("cup");
    if (cup == NULL || cup == (char *)-1) {
        fprintf(stderr, "термінал не вміє ставити курсор\n");
        return 1;
    }

    char *s = tparm(cup, 9L, 2L);                   /* рядок 9, стовпець 2, від нуля */
    if (s == NULL)                                  /* рецепт хотів інших параметрів */
        return 1;
    tputs(s, 1, putchar);                           /* тут-таки домішається заповнення */

    printf("кольорів: %d\n", tigetnum("colors"));   /* -1 — нема, -2 — не числова */

    del_curterm(cur_term);
    return 0;
}
```

Збирають це `cc … -lncurses`; у дистрибутивах, де роботу з базою винесено в окрему бібліотеку, вистачить `-ltinfo`. Вказівник від `tparm` належить бібліотеці — надсилайте його одразу або копіюйте байти, а не розраховуйте потримати два результати водночас.

## Утиліти

### `tput` — та сама машина з командного рядка

Вжиток: `tput [-T тип] можливість [параметр …]`. Без `-T` тип береться з `TERM`.

Відповідає `tput` по-різному залежно від роду: числову й рядкову друкує (рядкову — вже пропущену крізь `tparm` і `tputs`), а булеву не друкує зовсім — відповідь на неї лежить у коді виходу. Ще з ключів: `-S` читає перелік можливостей зі стандартного входу, щоб не платити за запуск кілька разів поспіль; `-x` не дає `tput clear` чистити ще й буфер прокрутки. Окремими словами йдуть `init`, `reset` і `longname`.

| код виходу | що сталося |
|---|---|
| `0` | булева є, або рядкову успішно виведено |
| `1` | булевої чи числової в записі немає |
| `2` | помилка вжитку або тип термінала не задано |
| `3` | тип термінала невідомий |
| `4` | невідоме ім'я можливості |
| `>4` | системна помилка (`4 + errno`) |

```
$ tput -T xterm-256color cup 9 2 | xxd
00000000: 1b5b 3130 3b33 48                        .[10;3H

$ tput -T xterm-256color bce; echo $?
0
```

### `tic` — зібрати опис у запис

Без `-o` пише туди ж, де база й шукається: спершу за `TERMINFO`, потім у `~/.terminfo`, і аж потім у системну теку. Тому «навчити систему новому терміналові» звичайно зводиться до одного `tic -x опис.ti` від власного імені, без адміністратора.

- `-x` — незнані імена не викидати, а класти як розширені, вгадуючи рід із запису;
- `-1` — вивід в один стовпець;
- `-c` — лише перевірити джерело (синтаксис і `use=`), нічого не писати;
- `-C` / `-I` — перекласти джерело у форму termcap / terminfo;
- `-e імена` — обмежити роботу переліком типів через кому;
- `-a` — зберегти закоментовані можливості (тягне за собою `-x`);
- `-s` — сказати, куди й скільки записів записано;
- `-D` — надрукувати відомі розташування бази й вийти.

### `infocmp` — розібрати запис назад

Без імен або з одним іменем поводиться як `-I`: друкує джерельний опис. З двома й більше — як `-d`: показує лише те, чим записи різняться.

- `-1` — по одній можливості на рядок; `-0` — усе одним рядком;
- `-x` — показувати й розширені можливості (без нього їх просто не видно);
- `-L` — довгі імена змінних замість коротких;
- `-c` — спільне для всіх поданих; `-n` — те, чого немає в жодному;
- `-u` — вивести опис через `use=` на подані записи;
- `-A тека` / `-B тека` — узяти перший запис з однієї бази, решту з іншої;
- `-q` — коротший вивід порівняння, з `-` замість відсутньої можливості.

```
$ infocmp -1x xterm-256color                 # весь запис, розширені теж, по рядку
$ infocmp xterm xterm-256color               # чим другий різниться від першого
$ infocmp -A /usr/share/terminfo -B ~/.terminfo xterm-256color xterm-256color
```

Останній рядок — той самий тип із двох різних баз: так порівнюють системний запис зі своїм, а заразом і дві машини між собою.

### `toe` — що взагалі є в базі

Без аргументів друкує первинні імена й описи всіх доступних типів, по рядку на тип, з першої знайденої бази. `-a` — з усіх тек, які взагалі переглядаються; `-h` — з підписом, звідки що; `-s` — упорядкувати за іменами; `-u файл` і `-U файл` — показати залежності `use=` у поданому джерельному файлі, пряму й зворотну.

## Порядок пошуку бази

1. `TERMINFO` — база, названа змінною (тека або файл-база);
2. `~/.terminfo`;
3. `TERMINFO_DIRS` — перелік тек або файлів-баз через двокрапку;
4. вбудовані розташування, серед них системна тека — звичайно `/usr/share/terminfo`.

## Розширені можливості

`tic -x` кладе нестандартні імена в кінець запису **разом із самими іменами** — тим і відрізняється розширена частина від стандартної. `infocmp -x` їх показує, а програма читає тими самими `tigetflag`/`tigetnum`/`tigetstr`, якщо бібліотеку зібрано з підтримкою розширених імен (`use_extended_names`).

Довідник `user_caps(5)` описує, зокрема, булеву `RGB` (колір задають трійкою «червоний-зелений-синій», а не номером), рядкові `XM` і `xm` (протокол миші), `E3` (очистити буфер прокрутки), булеву `AX` (термінал розуміє `SGR` 39 і 49) та числову `U8`. Імена на кшталт `Ms` чи `Smulx`, що ходять між авторами терміналів і програм, у `user_caps(5)` не описані: це домовленість, зафіксована в самій базі й у документації окремих програм, а не в довіднику ncurses — і поводитися з нею варто відповідно.
