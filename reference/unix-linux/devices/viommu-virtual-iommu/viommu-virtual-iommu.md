# Віртуальний IOMMU (vIOMMU)

Прокидання фізичного PCI-пристрою (наприклад, мережевої карти або графічного прискорювача) у віртуальну машину дозволяє гостьовій системі працювати з обладнанням на майже фізичній швидкості. Для ізоляції пам'яті між пристроями хост використовує апаратний IOMMU (Input/Output Memory Management Unit), який перетворює гостьові фізичні адреси (L1 GPA) у реальні фізичні адреси хоста (HPA).

Однак у середовищі вкладеної віртуалізації — коли всередині першої віртуальної машини (L1) запускається друга віртуальна машина (L2), і той самий пристрій прокидається безпосередньо в L2 — ця схема опиняється перед суттєвою апаратною перешкодою.

## Чому без vIOMMU вкладене прокидання не працює

Коли пристрій виконує DMA-запит за вказівкою L2, він надсилає на шину PCIe адресу вкладеного гостя (L2 GPA). Фізичний IOMMU на хості L0 налаштований гіпервізором лише на розуміння адрес L1 (L1 GPA). 

Отримавши невідому адресу L2 GPA, апаратний IOMMU блокує транзакцію, перериває процесор і генерує збій `DMAR Fault`.

Операційній системі L1 потрібен власний IOMMU, щоб побудувати таблицю перетворення адрес `L2 GPA → L1 GPA`. Оскільки хост L0 не може віддати реальне залізо у користування віртуальній машині (це порушило б безпеку інших віртуальних машин), QEMU створює **віртуальний IOMMU (vIOMMU)** — програмний пристрій, який прикидається апаратним контролером перед ОС L1.

```
[Пристрій PCIe] ──(L2 GPA)──> [vIOMMU в L1] ──(L1 GPA)──> [Фізичний IOMMU L0] ──(HPA)──> [DRAM]
```

Віртуальний IOMMU презентує себе гостю L1 через стандартні системні таблиці: ACPI DMAR для процесорів Intel VT-d або ACPI IORT та Device Tree для архітектури ARM SMMUv3. Під час завантаження ядро L1 знаходить цей пристрій, завантажує стандартні драйвери IOMMU та будує у своїй оперативній пам'яті структури трансляції адрес так само, як це робилося б на реальному залізі.

## Два підходи до трансляції адрес у vIOMMU

Щоб реальний апаратний IOMMU зміг виконати DMA-запит за адресою L2 GPA, гіпервізор L0 застосовує один із двох підходів:

### 1. Тіньові таблиці сторінок (Shadow IOMMU)

У цьому режимі QEMU (L0) постійно стежить за всіма змінами у віртуальних таблицях vIOMMU L1:
- Драйвер L1 заповнює свою таблицю мапінгу `L2 GPA → L1 GPA`.
- QEMU перехоплює ці зміни завдяки спеціальному режиму `caching-mode=on`.
- QEMU математично об'єднує таблицю L1 зі своєю хостовою таблицею (`L1 GPA → HPA`) і отримує підсумковий direct-мапінг: **`L2 GPA → HPA`**.
- QEMU через системний виклик `VFIO_IOMMU_MAP_DMA` записує цю об'єднану тіньову таблицю у фізичний IOMMU.

*Головний недолік:* високі накладні витрати й затримки через постійні зупинки віртуальної машини (VM-exits) при кожній зміні адрес DMA. У підсумку система витрачає значну частину процесорних ресурсів на обслуговування переключень контексту між гіпервізором та гостем.

### 2. Апаратна вкладена трансляція (Two-Stage Translation)

Сучасні контролери IOMMU (Intel VT-d Scalable Mode, ARM SMMUv3) виконують двостадійне перетворення адрес безпосередньо на апаратному рівні:
- **Стадія 1 (Stage 1 / S1):** Перетворює L2 GPA у L1 GPA. Таблицею Стадії 1 керує виключно гостьова ОС L1.
- **Стадія 2 (Stage 2 / S2):** Перетворює L1 GPA у HPA. Таблицею Стадії 2 керує хост L0.

За такого підходу QEMU передає апаратному IOMMU покажчик на кореневі таблиці L1 у пам'яті. Фізичний IOMMU самостійно читає обидві таблиці з RAM під час обробки DMA, що усуває потребу в VM-exits та оновленні тіньових таблиць. Продуктивність вкладеного вводу-виводу наближається до швидкості реального фізичного обладнання.

В архітектурі ARM SMMUv3 це реалізується через розщеплення Stream Table Entries (STE), де Стадія 1 вказує на Context Descriptor (CD) у гості L1, а Стадія 2 спирається на Translation Table Base (TTB) гіпервізора L0.

## Синхронізація кешу IOTLB та ATS

У разі зміни мапінгів у пам'яті L1 застарілі адреси не повинні залишатися у кеші IOMMU (IOTLB) або у внутрішньому кеші пристрою (DevTLB). vIOMMU емулює прийом команд інвалідації від L1 та прокидає їх до апаратного IOMMU та шини PCIe через пакети ATS (Address Translation Services). Це гарантує цілісність даних при високій інтенсивності мережевого обміну.

## Безпека переривань (Interrupt Remapping)

Окрім трансляції адрес для DMA, vIOMMU відповідає за **Interrupt Remapping (vIR)**. Пристрої PCIe надсилають переривання MSI/MSI-X шляхом запису даних за спеціальними адресами у пам'яті.

Без захисту пристрій міг би надіслати підроблене переривання на будь-яке ядро CPU, перехопивши контроль над гіпервізором. vIOMMU надає L1 віртуальну таблицю записів переривань (IRTE). QEMU перехоплює налаштування MSI від L1 і перепрограмовує **фізичну таблицю IRTE** на хості L0. Переривання від пристрою безпечно потрапляють у KVM L0, потім ін'єктуються в L1 і доставляються в L2.

## Сучасний стандарт: virtio-iommu

Альтернативою емуляції складних апаратних контролерів (як-от Intel VT-d) є **`virtio-iommu`** — пара-віртуалізований стандарт IOMMU. 

Замість того щоб примушувати гіпервізор L0 сканувати складні MMIO-регістри та багаторівневі структури сторінок, драйвер `virtio-iommu` в L1 надсилає чіткі команди `MAP` і `UNMAP` через стандартну чергу `virtqueue`. Це забезпечує кросплатформеність (він однаково працює на x86_64, ARM64 та RISC-V) та мінімізує обсяг коду емуляції у просторі користувача.

## Практична діагностика

На хості та у віртуальній машині L1 роботу субсистеми IOMMU можна відстежувати через інтерфейси ядра Linux:

```bash
# Перевірка реєстрації контролера IOMMU в системному журналі
dmesg | grep -i iommu

# Перевірка формування IOMMU-груп у sysfs
ls -la /sys/kernel/iommu_groups/
```

Аналіз виводу дозволяє переконатися, що vIOMMU правильно розпізнаний ядром гостя і що прокинуті пристрої ізольовані у власних групах. При використанні параметра `iommu=pt` (passthrough) ядро L1 налаштовує прямолінійний мапінг для власних пристроїв, зберігаючи трансляцію лише для тих функцій PCIe, які передаються у вкладений гіпервізор L2.

## Підсумок

Віртуальний IOMMU є фундаментальним зв'язуючим ланцюгом у сучасних хмарних обчисленнях. Він дозволяє вкладеним гіпервізорам та контейнерним платформам отримувати прямий доступ до фізичного заліза без компромісів у ізоляції та безпеці пам'яті.
