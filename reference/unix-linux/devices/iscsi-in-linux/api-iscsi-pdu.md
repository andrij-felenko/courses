# 📋 iSCSI PDU: Формат інкапсуляції

Protocol Data Unit (PDU) — це базова одиниця передачі даних в iSCSI. Будь-який обмін між ініціатором і таргетом відбувається у вигляді PDU. Кожен PDU упаковується в один або кілька сегментів TCP і передається по мережі.

## Структура iSCSI PDU

iSCSI PDU має стандартний заголовок розміром 48 байт (BHS — Basic Header Segment), за яким можуть іти додаткові заголовки (AHS — Additional Header Segment), дані (Data Segment) та опціональні контрольні суми (Digests).

```text
+--------------------------------------------------------------+
| Basic Header Segment (BHS) - 48 Bytes                        |
+--------------------------------------------------------------+
| Additional Header Segment (AHS) - (Optional)                 |
+--------------------------------------------------------------+
| Header Digest - (Optional, CRC32C)                           |
+--------------------------------------------------------------+
| Data Segment - (Optional, розмір узгоджується під час Login) |
+--------------------------------------------------------------+
| Data Digest - (Optional, CRC32C)                             |
+--------------------------------------------------------------+
```

### Basic Header Segment (BHS)

Перші 48 байт є завжди, їхня структура залежить від типу PDU (Opcode), але загалом виглядає так:

1.  **Opcode (Код операції):** Вказує тип повідомлення (наприклад, SCSI Command, SCSI Response, Login Request, NOP-Out).
2.  **Flags:** Додаткові прапорці, специфічні для Opcode (наприклад, чи це остання частина даних).
3.  **Data Segment Length:** 24-бітне поле, що вказує розмір Data Segment у байтах.
4.  **LUN (Logical Unit Number):** 64-бітне поле (8 байт), що ідентифікує конкретний диск/том, до якого звертається команда.
5.  **Initiator Task Tag (ITT):** Унікальний номер, який ініціатор присвоює кожній команді. Таргет повертає цей номер у своїй відповіді, що дозволяє ініціатору розпізнати, до якої команди належить відповідь.
6.  **Expected StatSN / CmdSN:** Sequence Numbers (порядкові номери) для гарантування правильного порядку виконання команд та підтвердження отримання повідомлень.
7.  **SCSI CDB (лише для Opcode = SCSI Command):** Саме тут, у BHS, розташовується 16 байт для команди SCSI Command Descriptor Block (CDB).

## Взаємодія PDU та CDB

Якщо ініціатор хоче виконати читання даних з диску (команда READ(10)), він створює SCSI CDB (10 байт). Далі підсистема iSCSI формує iSCSI PDU:
1. Встановлює Opcode = `0x01` (SCSI Command).
2. Вставляє 10 байт SCSI CDB у відповідне поле всередині BHS.
3. Додає LUN та генерує новий ITT.
4. Відправляє 48 байт BHS по TCP.

Коли таргет опрацює запит, він надішле відповідь (Data-In PDU), яка міститиме BHS з тим самим ITT, а у Data Segment будуть фактично прочитані з диска блоки.

## Digests (Контрольні суми)

TCP має власну 16-бітну контрольну суму, але вона не завжди надійна для гігабайтних потоків даних. Тому iSCSI дозволяє увімкнути додаткові 32-бітні контрольні суми (алгоритм CRC32C) для заголовка (Header Digest) та для даних (Data Digest). Це робиться під час фази Login. Якщо помилка виявлена, PDU відкидається і відбувається повторна передача.
