# Підсистема PCI Express в Linux

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

Підсистема PCI Express (PCIe) є однією з найважливіших складових сучасних операційних систем, включаючи Linux. Вона відповідає за виявлення, конфігурацію та керування пристроями, підключеними до шини PCI та PCIe. Архітектура PCIe, хоча і є послідовною, зворотно сумісна на програмному рівні з паралельною шиною PCI, що дозволяє операційним системам використовувати єдину інфраструктуру драйверів.

У цій статті ми детально розглянемо архітектуру підсистеми PCI/PCIe в ядрі Linux, простір конфігурації (PCI Config Space), базові адресні регістри (BARs), механізми переривань (MSI та MSI-X), розширені можливості звітів про помилки (AER), структуру `pci_driver` та використання утиліти `lspci`.

## 1. Архітектура підсистеми PCI/PCIe в ядрі Linux

Підсистема PCI в Linux ділиться на кілька рівнів:

1.  **PCI Core (Ядро PCI):** Це незалежний від апаратної платформи код, який відповідає за ініціалізацію пристроїв, управління конфігураційним простором, розподіл ресурсів (введення-виведення, пам'ять, переривання) та управління живленням.
2.  **PCI Host Controller Drivers (Драйвери хост-контролерів):** Цей рівень специфічний для апаратної архітектури. Він абстрагує доступ до конфігураційного простору PCI, який відрізняється на платформах x86, ARM, PowerPC тощо.
3.  **PCI Device Drivers (Драйвери пристроїв PCI):** Це драйвери конкретних периферійних пристроїв, які взаємодіють з ядром PCI через стандартизований API (`struct pci_driver`).

Коли система завантажується (або коли відбувається гаряче підключення пристрою PCIe Hotplug), ядро ініціює процес перерахування (enumeration) шини PCI. Під час цього процесу ядро опитує конфігураційний простір кожного можливого пристрою на шині, щоб з'ясувати його наявність, тип, вимоги до ресурсів та можливості.

## 2. PCI Configuration Space (Простір конфігурації PCI)

Кожен PCI/PCIe пристрій має стандартизований простір конфігурації. Для класичного PCI цей простір становить 256 байт, а для PCIe (PCI Express Extended Configuration Space) він розширений до 4096 байт. Доступ до цього простору здійснюється до того, як пристрою будуть виділені ресурси (адреси пам'яті або переривання), і саме з нього система дізнається про вимоги пристрою.

Перші 64 байти утворюють стандартний заголовок пристрою (Header Type 0 для кінцевих пристроїв або Header Type 1 для мостів).

![PCI Configuration Space](/reference/unix-linux/devices/pcie-express-bus-subsystem/img/pci-config-space.svg)

Основні поля стандартного заголовка:

*   **Vendor ID / Device ID (0x00):** Унікальні ідентифікатори виробника та конкретної моделі пристрою. Vendor ID призначається консорціумом PCI-SIG, а Device ID призначається самим виробником. Значення Vendor ID = `0xFFFF` означає, що пристрою за цією адресою немає.
*   **Command Register (0x04):** Керує основними функціями пристрою, такими як дозвіл реагувати на транзакції пам'яті (Memory Space Enable), транзакції введення-виведення (I/O Space Enable) або бути ініціатором транзакцій (Bus Master Enable).
*   **Status Register (0x06):** Зберігає статус пристрою, включаючи інформацію про помилки, статус переривань і наявність списку можливостей (Capabilities List).
*   **Class Code / Revision ID (0x08):** Вказує на тип пристрою (наприклад, мережевий контролер, відеокарта, контролер зберігання даних) та його ревізію. Ядро та утиліти (як `lspci`) використовують Class Code для класифікації пристрою, навіть якщо його конкретний Vendor/Device ID невідомий.
*   **Base Address Registers (BARs) (0x10 - 0x24):** Найважливіші регістри для розподілу ресурсів, про які ми поговоримо детальніше.
*   **Capabilities Pointer (0x34):** Вказівник на пов'язаний список додаткових можливостей пристрою, таких як управління живленням (PCI-PM), MSI, MSI-X або PCIe (Express).

У ядрі Linux драйвери можуть читати та записувати цей простір за допомогою функцій родини `pci_read_config_*` та `pci_write_config_*`:

```c
int pci_read_config_byte(const struct pci_dev *dev, int where, u8 *val);
int pci_read_config_word(const struct pci_dev *dev, int where, u16 *val);
int pci_read_config_dword(const struct pci_dev *dev, int where, u32 *val);
```

## 3. Base Address Registers (BARs)

Base Address Registers (BARs) визначають, скільки адресного простору (пам'яті або портів вводу/виводу) вимагає пристрій. Кінцевий пристрій (Type 0) має 6 регістрів BAR (BAR0 до BAR5), кожен по 32 біти. 64-бітна адресація вимагає об'єднання двох сусідніх BAR.

Під час перерахування шини системне ПЗ (BIOS/UEFI або ядро Linux) виконує наступні кроки для кожного BAR:
1. Записує значення `0xFFFFFFFF` у BAR.
2. Зчитує значення назад.
3. Пристрій повертає значення, в якому обнулені молодші біти, що відповідають розміру необхідного адресного простору. Наприклад, якщо пристрій повертає `0xFFFFF000`, це означає, що йому потрібно 4 КБ пам'яті (`~0xFFFFF000 + 1 = 0x1000 = 4096`).
4. Система знаходить вільну ділянку у фізичному адресному просторі відповідного розміру і вирівнювання, і записує базову фізичну адресу назад у BAR.

Різниця між Memory та I/O BAR:
*   **Memory BAR:** Вказує на те, що регістри пристрою будуть відображатися у фізичний адресний простір пам'яті (Memory-Mapped I/O, MMIO). Драйвер використовує функцію `ioremap()`, щоб отримати віртуальну адресу ядра для доступу до цих регістрів за допомогою `readl()` / `writel()`.
*   **I/O BAR:** Використовує застарілий адресний простір портів (на архітектурах x86). Доступ здійснюється за допомогою інструкцій `in` та `out`. Сучасні пристрої PCIe практично повністю відмовилися від I/O BAR на користь MMIO.

У драйвері Linux робота з BAR виглядає так:

```c
// Запит ресурсів ядра, щоб ніхто інший не використовував ці адреси
err = pci_request_regions(pdev, "my_driver");

// Отримання базової фізичної адреси BAR0
resource_size_t mmio_start = pci_resource_start(pdev, 0);

// Відображення фізичної адреси у віртуальну пам'ять ядра
void __iomem *hw_addr = pci_iomap(pdev, 0, 0);
if (!hw_addr)
    // Обробка помилки

// Запис значення в регістр пристрою зі зсувом 0x10
writel(0xDEADBEEF, hw_addr + 0x10);
```

## 4. Переривання: INTx, MSI та MSI-X

Пристрої повинні сигналізувати центральному процесору про події, наприклад, про завершення передачі даних через DMA. У світі PCI/PCIe існує три механізми переривань.

### 4.1 Legacy Interrupts (INTx)
Класичний PCI використовував чотири фізичні лінії переривань: INTA#, INTB#, INTC# та INTD#. Оскільки пристроїв багато, а ліній мало, вони часто ділилися (interrupt sharing). Це неефективно, оскільки при виникненні переривання процесор повинен викликати обробники всіх пристроїв, що розділяють лінію, щоб з'ясувати, який саме пристрій згенерував переривання.
У PCIe фізичних ліній немає; замість цього пристрій генерує повідомлення (Message Signaled Interrupts) In-Band, щоб емулювати стан ліній INTx, але проблема розподілу переривань залишається.

### 4.2 Message Signaled Interrupts (MSI)
MSI вирішує проблеми INTx, дозволяючи пристрою надсилати невелике повідомлення (запис у певну адресу фізичної пам'яті контролера переривань APIC), яке ініціює переривання. Це повністю In-Band механізм.
Переваги:
*   Немає конфліктів (sharing), кожен пристрій має власні, виділені вектори переривань.
*   Дозволяє пристрою запитувати декілька векторів (до 32 в MSI).

### 4.3 MSI-X
Це розширена версія MSI. Вона підтримує до 2048 векторів переривань для одного пристрою і дозволяє кожному вектору мати незалежну адресу і дані. Це критично важливо для високопродуктивних пристроїв (наприклад, мережевих карт 10/40/100 Gbps, NVMe накопичувачів), оскільки дозволяє призначати окремий вектор переривання кожній черзі апаратного пристрою, а кожну чергу прив'язувати до окремого ядра процесора (CPU core affinity). Це мінімізує блокування та збільшує продуктивність.

Включення MSI-X у драйвері:

```c
// Запит у ядра на виділення MSI або MSI-X векторів
int nvec = pci_alloc_irq_vectors(pdev, 1, MAX_VECTORS, PCI_IRQ_MSIX | PCI_IRQ_MSI);
if (nvec < 0) {
    // Відкат до INTx (PCI_IRQ_LEGACY)
}

// Реєстрація обробника для конкретного вектора (наприклад, 0)
int irq = pci_irq_vector(pdev, 0);
err = request_irq(irq, my_interrupt_handler, 0, "my_device", my_dev_ctx);
```

## 5. Advanced Error Reporting (AER)

PCIe значно покращив можливості звітування про апаратні помилки. В класичному PCI помилки сигналізувалися лініями PERR# (Parity Error) та SERR# (System Error), що часто призводило до NMI і паніки ядра (Kernel Panic).

PCIe Advanced Error Reporting (AER) дозволяє системі детально діагностувати помилки на різних рівнях (фізичному, канальному, транзакційному) і часто відновлюватися без перезавантаження.
Помилки діляться на:
*   **Correctable Errors:** Апаратура сама їх виправила (наприклад, за допомогою контрольних сум LCRC). Пристрій може повідомити ядро, але робота не переривається.
*   **Uncorrectable Non-Fatal:** Транзакція не вдалася, але шина і пристрій працюють. Драйвер може спробувати скинути (reset) пристрій або повторити операцію.
*   **Uncorrectable Fatal:** Фатальна помилка, що вимагає скидання всього лінку PCIe (Link Reset).

Щоб драйвер підтримував відновлення після помилок, він повинен реалізувати структуру `pci_error_handlers`:

```c
static const struct pci_error_handlers my_err_handler = {
    .error_detected = my_error_detected, // Повідомлення про помилку
    .mmio_enabled   = my_mmio_enabled,   // Спроба доступу після помилки
    .link_reset     = my_link_reset,     // Викликається під час скидання лінку
    .slot_reset     = my_slot_reset,     // Після скидання слота
    .resume         = my_resume,         // Відновлення нормальної роботи
};
```

## 6. Структура `pci_driver`

Щоб інтегруватися в ядро, драйвер PCI повинен визначити та зареєструвати структуру `pci_driver`. Вона містить колбеки (функції зворотного виклику) для життєвого циклу пристрою.

```c
static const struct pci_device_id my_pci_tbl[] = {
    { PCI_DEVICE(VENDOR_ID, DEVICE_ID_1) },
    { PCI_DEVICE(VENDOR_ID, DEVICE_ID_2) },
    { 0, } // Порожній елемент вказує на кінець масиву
};
MODULE_DEVICE_TABLE(pci, my_pci_tbl); // Експорт для udev

static struct pci_driver my_pci_driver = {
    .name     = "my_pci_driver",
    .id_table = my_pci_tbl,
    .probe    = my_pci_probe,   // Викликається при знаходженні пристрою
    .remove   = my_pci_remove,  // Викликається при вивантаженні драйвера / гарячому відключенні
    .err_handler = &my_err_handler,
#ifdef CONFIG_PM
    .suspend  = my_pci_suspend, // Управління живленням
    .resume   = my_pci_resume,
#endif
};

module_pci_driver(my_pci_driver); // Макрос для ініціалізації модуля
```

### Основні етапи у функції `probe`:
1.  **Включення пристрою:** `pci_enable_device(pdev);`
2.  **Запит регіонів:** `pci_request_regions(pdev, "my_driver");`
3.  **Ініціалізація DMA:** Налаштування маски DMA (32 або 64 біти) `dma_set_mask_and_coherent()`.
4.  **Відображення пам'яті (MMIO):** `pci_iomap()`.
5.  **Налаштування переривань:** `pci_alloc_irq_vectors()`.
6.  **Ініціалізація апаратної частини:** Специфічний для пристрою код.
7.  **Реєстрація у вищій підсистемі:** Наприклад, як мережевий інтерфейс (`register_netdev`), блок-пристрій або символьний пристрій.

## 7. Утиліта `lspci`

`lspci` є стандартною утилітою користувацького простору в Linux (входить до пакету `pciutils`) для відображення інформації про шини PCI/PCIe та підключені до них пристрої. Вона працює, читаючи дані з віртуальної файлової системи `sysfs` (`/sys/bus/pci/devices/`).

*   `lspci`: Відображає короткий список пристроїв.
    ```
    00:1f.2 SATA controller: Intel Corporation 82801IR/IO/IH (ICH9R/DO/DH) 6 port SATA Controller [AHCI mode] (rev 02)
    ```
    Формат `00:1f.2` означає: Bus `00`, Device `1f`, Function `2` (BDF-адресація).
*   `lspci -nn`: Показує також Vendor ID та Device ID у шістнадцятковому форматі.
*   `lspci -v`, `-vv`, `-vvv`: Відображає детальнішу інформацію (ресурси, BARs, IRQ, MSI/MSI-X capabilities).
*   `lspci -t`: Показує пристрої у вигляді дерева, що зручно для розуміння топології (кореневі комплекси, PCIe комутатори, кінцеві пристрої).
*   `lspci -x`: Виводить шістнадцятковий дамп перших 64 байт конфігураційного простору. `-xxx` виводить усі 4096 байт для PCIe.

## Висновок

Підсистема PCI/PCIe в Linux — це зрілий і добре структурований компонент ядра, який ефективно абстрагує складність апаратних шин. Розуміння простору конфігурації, BARs та механізмів переривань є обов'язковою умовою для розробників драйверів пристроїв і системних інженерів, що займаються низькорівневою оптимізацією або налагодженням апаратних збоїв (AER).
