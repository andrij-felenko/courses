# 📋 Команди стирання: коди ATA, SCSI, NVMe і прапорці утиліт

Довідник усіх інтерфейсів, якими носієві наказують знищити власний вміст: код команди, значення кожного її поля, біти, за якими видно, чи пристрій це вміє, і ключ утиліти, що цю команду пакує. Розкладено за транспортами — ATA, SCSI, NVMe — і наприкінці те, чого в цьому переліку немає: блоковий шар Linux.

## Що куди веде

| Спосіб | ATA | SCSI | NVMe |
|---|---|---|---|
| крипто-стирання | `SANITIZE` B4h, feature 0011h | `SANITIZE` 48h, дія 03h | `Sanitize` 84h, SANACT 4 · `Format NVM` 80h, SES 2 |
| блокове стирання | `SANITIZE` B4h, feature 0012h | 48h, дія 02h | SANACT 2 · SES 1 |
| перезапис медіа | `SANITIZE` B4h, feature 0014h | 48h, дія 01h | SANACT 3 |
| стирання з-під замка | `SECURITY ERASE UNIT` F4h | — | — |
| вихід із режиму невдачі | — | 48h, дія 1Fh | SANACT 1 |
| стан операції | `SANITIZE STATUS EXT`, feature 0000h | `REQUEST SENSE` | журнал Sanitize Status |

Рядка «стерти діапазон» у таблиці немає й не буде: усе тут працює над носієм цілком, а `SES` у `Format NVM` — над простором імен. Окремим каналом стоїть TCG Opal, де стирання роблять не командою набору, а транзакцією до модуля безпеки поверх `TRUSTED SEND` / `Security Send` — [самошифрувальні носії](topic:unix-linux/sed-opal-drives).

## ATA: набір SECURITY

| Код | Команда | Що робить |
|---|---|---|
| F1h | `SECURITY SET PASSWORD` | задає пароль користувача або майстра й рівень захисту |
| F2h | `SECURITY UNLOCK` | знімає замок до наступного вимкнення живлення |
| F3h | `SECURITY ERASE PREPARE` | дозвіл на стирання; діє лише **безпосередньо** перед F4h — будь-яка команда між ними скасовує його |
| F4h | `SECURITY ERASE UNIT` | стирання; режим (звичайний чи enhanced) і пароль ідуть у блоці даних |
| F5h | `SECURITY FREEZE LOCK` | до вимкнення живлення пристрій відхиляє F1–F4 і F6 |
| F6h | `SECURITY DISABLE PASSWORD` | знімає пароль, не чіпаючи даних |

Блок даних до F1h і F4h — звичайний сектор на 512 байтів, і значуща в ньому лише перша жменька:

```
слово 0, біт 0   0 = пароль користувача, 1 = пароль майстра
слово 0, біт 1   0 = звичайне стирання, 1 = enhanced        (лише F4h)
слово 0, біт 8   рівень: 0 = high, 1 = maximum              (лише F1h)
слова 1..16      пароль: 32 байти, доповнені нулями
```

Різниця рівнів проста: за `high` замкнений диск відмикає і пароль користувача, і майстра; за `maximum` пароль майстра відмикати не вміє — ним можна лише стерти. П'ять невдалих спроб пароля поспіль — і пристрій до вимкнення живлення відхиляє і відмикання, і стирання.

## ATA: SANITIZE (B4h)

Підкоманду задає поле feature, а в LBA має лежати ключ — не захист, а запобіжник від випадково зібраної команди.

| feature | Підкоманда | LBA(31:0) | Решта полів |
|---|---|---|---|
| 0000h | `SANITIZE STATUS EXT` | — | відповідь у полі COUNT |
| 0011h | `CRYPTO SCRAMBLE EXT` | 43727970h («Cryp») | — |
| 0012h | `BLOCK ERASE EXT` | 426B4572h («BkEr») | — |
| 0014h | `OVERWRITE EXT` | **візерунок**, 32 біти | LBA(47:32) = 4F57h («OW»); COUNT — кількість проходів, де 0 означає 16 |
| 0020h | `SANITIZE FREEZE LOCK EXT` | 46724C6Bh («FrLk») | — |
| 0040h | `SANITIZE ANTIFREEZE LOCK EXT` | 416E7469h («Anti») | — |

Візерунок для перезапису — рівно чотири байти, і повторюється він на всю медіа; довшого шаблону в ATA просто немає куди покласти.

Відповідь `SANITIZE STATUS EXT` читається побітово, а частка виконаного приходить окремим полем у масштабі «65536 = 100 %»:

| Біт | Значення |
|---|---|
| 7 | остання операція завершилася успішно |
| 6 | операція триває просто зараз |
| 5 | пристрій заморожено (`FREEZE LOCK` уже виконано) |
| 4 | діє `ANTIFREEZE LOCK` — наступне заморожування буде відхилено |

Причин відмови, які пристрій називає в тій самій відповіді, всього чотири: команда не вдалася, команда не підтримується, пристрій заморожено, замовлено antifreeze.

## Що читати в IDENTIFY DEVICE

| Слово | Біт | Про що |
|---|---|---|
| 59 | 15 · 14 · 13 | підтримка `BLOCK ERASE EXT` · `OVERWRITE EXT` · `CRYPTO SCRAMBLE EXT` |
| 59 | 12 · 10 | набір `SANITIZE` загалом · `ANTIFREEZE LOCK EXT` |
| 82 · 85 | 1 | набір SECURITY підтримується · увімкнений |
| 89 · 90 | — | оцінка часу для звичайного · enhanced стирання |
| 128 | 0–5 | supported · enabled · locked · frozen · лічильник спроб вичерпано · enhanced erase підтримується |
| 128 | 8 | рівень: 0 — high, 1 — maximum |

Слова 89 і 90 мають два формати, і плутанина між ними — звичайна причина безглуздих чисел у чужих скриптах:

```
біт 15 = 0  →  значення = біти 7:0    (0xFF   означає «понад 508 хв»)
біт 15 = 1  →  значення = біти 14:0   (0x7FFF означає «понад 65532 хв»)

час ≈ значення · 2 хвилини

приклад: 0x8258 → біт 15 = 1, значення = 0x0258 = 600
                → 600 · 2 = 1200 хв = 20 годин
```

## hdparm

| Ключ | Що робить |
|---|---|
| `-I` | IDENTIFY DEVICE у людському вигляді — саме звідси рядки `frozen`, `enhanced erase` і оцінки часу |
| `--user-master u\|m` | який пароль вживати; типово `u` |
| `--security-mode h\|m` | рівень для `--security-set-pass`; типово `h` |
| `--security-set-pass PWD` | F1h. **Небезпечний**: із цієї миті диск замкнеться при першому ж вимкненні живлення |
| `--security-unlock PWD` | F2h |
| `--security-erase PWD` | F3h + F4h, звичайний режим |
| `--security-erase-enhanced PWD` | те саме з бітом enhanced |
| `--security-disable PWD` | F6h — вихід із замкненого стану без стирання |
| `--security-freeze` | F5h; ставлять свідомо, щоб чужа програма не змогла замкнути диск |
| `--security-prompt-for-password` | питати пароль, а не брати з командного рядка (він інакше лишиться в історії оболонки) |
| `--sanitize-status` | feature 0000h |
| `--sanitize-block-erase` · `--sanitize-crypto-scramble` | 0012h · 0011h |
| `--sanitize-overwrite hex:XXXXXXXX` | 0014h із чотирибайтовим візерунком |
| `--sanitize-overwrite-passes N` | кількість проходів; **0 означає 16** |
| `--sanitize-freeze-lock` · `--sanitize-antifreeze-lock` | 0020h · 0040h |

Усі три руйнівні `--sanitize-*` hdparm виконує лише разом із `--yes-i-know-what-i-am-doing`; на `--security-erase` такої вимоги, хоч як це дивно, немає.

```sh
sudo hdparm --sanitize-status /dev/sda
sudo hdparm --yes-i-know-what-i-am-doing --sanitize-crypto-scramble /dev/sda
```

## sg_sanitize (SCSI SANITIZE, 48h)

CDB на 10 байтів, дія — у молодших п'яти бітах першого байта. Утиліта з пакета sg3\_utils сама опитує поступ через `REQUEST SENSE`, доки операція триває.

| Ключ | Що робить |
|---|---|
| `-B, --block` · `-C, --crypto` · `-O, --overwrite` | дія 02h · 03h · 01h |
| `-F, --fail` | дія 1Fh: вивести пристрій із режиму невдалої санітизації |
| `-A, --ause` | дозволити вихід із незавершеної операції без повторного стирання |
| `-c, --count=OC` | кількість проходів перезапису, 1–31; типово 1 |
| `-I, --invert` | інвертувати візерунок між проходами |
| `-i, --ipl=LEN` | довжина візерунка в байтах, 1–65535 |
| `-p, --pattern=FILE` | узяти візерунок із файлу |
| `-z, --zero` | візерунок — нулі |
| `-e, --early` | повернути керування одразу після подання команди, не опитуючи |
| `-w, --wait` | не ставити біт IMMED — чекати на завершення самою командою |
| `-Q, --quick` | пропустити п'ятнадцятисекундну паузу на роздуми |
| `-D, --dry-run` | зібрати команду й не подавати |

Головне обмеження стосується не SCSI, а перекладу: коли під SAT насправді лежить SATA-диск, `--overwrite` перетворюється на `OVERWRITE EXT`, а туди вміщається рівно **чотири байти** візерунка — довший `--ipl` перекласти нікуди.

```sh
sudo sg_sanitize --block --quick --wait /dev/sdb
sudo sg_sanitize --overwrite --zero --ipl=4 --count=1 /dev/sdb
```

## nvme-cli

`Format NVM` (80h) працює над простором імен, `Sanitize` (84h) — над усією підсистемою, тож другу подають керуючому вузлові `/dev/nvme0`, а не `/dev/nvme0n1`.

| `nvme format` | Значення |
|---|---|
| `-s, --ses=0` | без стирання — просто зміна формату |
| `-s, --ses=1` | стерти дані користувача |
| `-s, --ses=2` | крипто-стирання |
| `-n, --namespace-id` | який саме простір імен |
| `-l, --lbaf` | номер формату блока з Identify Namespace |
| `--force` | не питати підтвердження |

Якщо контролер не вміє форматувати окремий простір імен (біт 0 поля `FNA` в Identify Controller), команда на керуючому вузлі відформатує **всі** простори імен одразу.

| `nvme sanitize` | Значення |
|---|---|
| `-a, --sanact=1` | вийти з режиму невдачі |
| `-a, --sanact=2` · `3` · `4` | блокове стирання · перезапис · крипто-стирання |
| `-a, --sanact=5` | вийти зі стану перевірки медіа |
| `-u, --ause` | необмежений режим завершення |
| `-n, --owpass=N` | кількість проходів перезапису |
| `-p, --ovrpat=X` | 32-бітний візерунок для перезапису |
| `-i, --oipbp` | інвертувати візерунок між проходами |
| `-d, --no-dealloc` | не звільняти логічні блоки після завершення |

Що пристрій узагалі вміє, показує поле `SANICAP` в Identify Controller: біт 0 — крипто-стирання, біт 1 — блокове, біт 2 — перезапис. Хід і підсумок читають зі сторінки журналу:

| Поле журналу | Значення |
|---|---|
| `SPROG` | частка виконаного, масштаб 65536 = 100 % |
| `SSTAT` біти 2:0 | 0 — ніколи не санітизували, 1 — успіх, 2 — триває, 3 — невдача |
| `SSTAT` біти 7:3 | скільки проходів перезапису вже зроблено |
| `SSTAT` біт 8 | Global Data Erased: у пам'ять не писали від виготовлення або від останньої вдалої санітизації |

```sh
sudo nvme id-ctrl /dev/nvme0 -H | grep -i -A3 sanicap
sudo nvme sanitize /dev/nvme0 --sanact=4
sudo nvme sanitize-log /dev/nvme0 -H
```

## Блоковий шар: чого тут немає

Три запити [ioctl](topic:unix-linux/ioctl-interface) над блоковим пристроєм беруть діапазон — пару 64-бітних чисел «зсув, довжина» в байтах: `BLKDISCARD`, `BLKSECDISCARD`, `BLKZEROOUT`. Їхні коди, вирівнювання й повний перелік помилок зібрано у [важелях discard](topic:unix-linux/discard-and-trim/api-discard-controls.md); тут важить лише другий із них і його доля.

| `blkdiscard` | Що робить |
|---|---|
| `-o, --offset` · `-l, --length` | межі діапазону в байтах; без них — увесь пристрій |
| `-s, --secure` | `BLKSECDISCARD` замість `BLKDISCARD` |
| `-z, --zeroout` | `BLKZEROOUT`: записати нулі, а не відкинути |

`blkdiscard --secure` на SATA чи NVMe відповідає `EOPNOTSUPP`, і причина видна прямо в ядрі: поле `max_secure_erase_sectors` у межах черги виставляють рівно два драйвери — карт пам'яті та фронтенд блокового пристрою Xen.

```c
/* drivers/mmc/core/queue.c */
if (mmc_card_can_secure_erase_trim(card))
        lim->max_secure_erase_sectors = max_discard;

/* drivers/block/xen-blkfront.c */
if (info->feature_secdiscard)
        lim->max_secure_erase_sectors = UINT_MAX;
```

Скрізь інде поле лишається нулем, і блоковий шар відхиляє запит, навіть не дійшовши до драйвера. Усі команди з таблиць вище йдуть повз цей шар — наскрізним каналом до транспорту ([SG_IO і `NVME_IOCTL_ADMIN_CMD`](topic:unix-linux/scsi-generic-passthrough)), і права на двох дорогах різні: адміністративній команді NVMe досить `CAP_SYS_ADMIN`, а `SG_IO` з такою командою вимагає `CAP_SYS_RAWIO` і пристрою, відкритого на запис.
