# 📜 Історія та еволюція підсистеми введення Linux: від /dev/mouse до уніфікованого evdev

До появи уніфікованої підсистеми введення в ядрі Linux 2.4/2.6 обробка пристроїв введення була фрагментована між десятками спеціалізованих драйверів. Кожен тип апаратного забезпечення — послідовна миша COM-порту, миша PS/2, клавіатура AT/PS/2, аналоговий джойстик Gameport чи спеціалізований графічний планшет — надавав власну псевдофайлову систему чи символьний пристрій у `/dev` (`/dev/inportbm`, `/dev/logibm`, `/dev/psaux`, `/dev/atkbd`). Графічний сервер XFree86 та консольні утиліти мусили містити індивідуальний код для розбору сирих байтових протоколів кожного конкретного пристрою, що створювало високий поріг підтримки нового заліза та унеможливлювало єдине управління подіями.

## Проблема ранніх ядер Linux (до серії 2.4)

Наприкінці 1990-х років системний стек введення Linux зіштовхнувся з трьома фундаментальними обмеженнями:

1. **Відсутність єдиної абстракції події.** Клавіатура генерувала скан-коди i8042 (`Set 1` або `Set 2`), які драйвер консолі `keyboard.c` перетворював безпосередньо в символи TTY. Миша PS/2 через `/dev/psaux` надсилала 3-байтові пакети протоколу BusMouse або PS/2 (де біти відповідали кнопкам, а байти — відносним зсувам `X` та `Y`). Окремі серійні миші використовували протокол Microsoft Serial Mouse (3 байти на 1200 бод), а миші Logitech — протокол MouseMan. Якщо користувач купував нову мишу, йому доводилося вручну правити конфігураційний файл `/etc/X11/XF86Config`, вказуючи конкретний протокол та пристрій.
2. **Поява шини USB та специфікації USB HID.** У 1996–1998 роках організація USB Implementers Forum випустила специфікацію USB Human Interface Device (HID). Один USB-контролер міг одночасно обслуговувати клавіатуру, мишу, мультимедійні клавіші регулювання гучності та ігровий кермовий контролер через єдину шину. Наявна модель ядра Linux, зав'язана на фіксовані мажорні та мінорні номери пристроїв для кожної фізичної шини, не мала місця для динамічного підключення багатофункціональних USB-пристроїв.
3. **Неможливість обробки подій у фоновому режимі кількома програмами.** Запити до `/dev/psaux` були монопольними на рівні читання файлового дескриптора: якщо одна програма відкривала `/dev/psaux`, інші отримували помилку або втрачали частини байтового потоку.

## Реформа Войтеха Павліка (Vojtech Pavlik)

У 1999 році розробник Войтех Павлик (Vojtech Pavlik) запропонував кардинальне переосмислення всієї архітектури введення для ядра Linux. Замість створення окремих файлових інтерфейсів для кожного драйвера шини, він спроектував трирівневу підсистему **Input Subsystem**:

```
[Апаратні пристрої] (USB HID, PS/2, I2C, Serial, Bluetooth)
         │
         ▼
[Драйвери пристроїв] (usbhid, psmouse, atkbd)
         │
         ▼ (стандартизовані виклики input_event)
[Ядро підсистеми введення: input.c]
         │
         ├───► [evdev]      ───► /dev/input/eventX  (універсальний потік input_event)
         ├───► [mousedev]   ───► /dev/input/mice    (емуляція PS/2 для сумісності)
         └───► [joydev]     ───► /dev/input/jsX     (старий API джойстиків)
```

Головні принципи реформи Войтеха Павліка полягали в наступному:

- **Розділення драйвера заліза та обробника подій.** Драйвер шини (наприклад, `usbhid`) більше не знає, хто й навіщо читає події. Його задача — розібрати дескриптор USB HID Report, декодувати байти й передати в ядро підсистеми факт: «клавіша з кодом `KEY_A` натиснута».
- **Стандартизована структура `input_event`.** Усі події введення у системі, незалежно від походження, упаковуються в уніфіковану двійкову структуру з міткою часу, типом (`type`), кодом (`code`) та значенням (`value`).
- **Символьний пристрій `/dev/input/eventX`.** Обробник `evdev.c` став єдиною точкою входу для нових системних компонентів. Через `/dev/input/eventX` простір користувача отримав доступ до сирих подій будь-якого пристрою без втрати контексту.

## Еволюція від Linux 2.4 до сучасного Linux 6.x

У ядрі Linux 2.4 підсистема введення з'явилася як опціональний модуль, але в Linux 2.6 вона стала обов'язковим стандартом.

З роком розвитку підсистема збагатилася ключовими розширеннями:

1. **Багатоточковий ввід (Multi-Touch / MT Protocol, 2009 рік).** З появою сенсорних екранів (смартфонів та планшетів) Генріх Шмідт (Henrik Rydberg) розробив протоколи Multi-touch (Type A для пристроїв без апаратного відстеження пальців і Type B для пристроїв з апаратним присвоєнням слот-ідентифікаторів `ABS_MT_SLOT`). Це дозволило передавати координати десятків одночасних дотиків через `evdev`.
2. **Віртуалізація через `/dev/uinput` (2002 рік).** Арістеу Сержіу Розанскі Філью (Aristeu Sergio Rozanski Filho, aris@cathedrallabs.org) створив модуль `uinput` (версія 0.1 від 2002 року), який дозволив програмам у просторі користувача створювати віртуальні пристрої введення. Це стало основою для демонів віддаленого робочого столу, емуляторів та перепризначувачів клавіш.
3. **Перехід на y2038-безпечні мітки часу.** У ядрі Linux 5.6 двійкову структуру `input_event` було адаптовано для запобігання «проблемі 2038 року» на 32-бітних архітектурах шляхом заміни `struct timeval` на окремі поля `input_event_sec` та `input_event_usec`.

Завдяки уніфікованій архітектурі `evdev`, Linux змог безболісно перейти від стародавніх мишей PS/2 до сучасних сенсорних панелей, VR-контролерів та жестових рукавиць без зміни базового API простору користувача.
