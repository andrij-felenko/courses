# ⚙️ Драйвер із кільцем і дзвінком, а тоді стенд: ламаємо його навмисно

Зберемо платформний модуль ядра, який відображає вікно регістрів контролера, тримає кільце дескрипторів у когерентній пам'яті для прямого доступу, б'є в дзвінок і обробляє переривання — а тоді зробимо з нього вимірювальний стенд, по черзі прибираючи те, що зазвичай пишуть не думаючи. Виявиться, що кожна з трьох дрібниць — бар'єр у `writel`, проштовхувальне читання в обробнику, вибір між `readl` і `readl_relaxed` — має ціну в наносекундах і наслідок, який видно у файлі в `/proc`.

## Задача

Драйвер прив'язується до вузла в [описі плати](book:unix-linux/device-tree) через [платформну шину](book:unix-linux/platform-bus), звідки бере два ресурси: діапазон регістрів і номер лінії переривання. Далі він мусить:

- увімкнути такт блока й лише потім прочитати регістр сигнатури — інакше читання не поверне нічого;
- завести кільце з 64 дескрипторів у пам'яті, яку одночасно бачать процесор і контролер;
- покласти в дескриптор адресу буфера, довжину й прапорець власності, а тоді записом у `REG_TX_KICK` сказати «бери»;
- в обробнику переривання прочитати причину, скинути її й проштовхнути це скидання читанням;
- на вивантаженні заглушити пристрій раніше, ніж зникне обробник.

## Ідея: у драйвері три різні пам'яті, і плутати їх не можна

Найчастіша плутанина в такому коді — думка, що вся пам'ять драйвера однакова. Насправді її тут три ґатунки, і кожен має власні правила.

**Вікно регістрів** — не пам'ять узагалі: `ioremap` дає віртуальну адресу з найсуворішим типом, кожен доступ через неї їде на шину, а порядок доступів — частина протоколу із залізом.

**Кільце дескрипторів** — звичайна оперативна пам'ять, тільки відображена так, щоб те, що написав процесор, контролер побачив без окремої синхронізації. Її дає `dma_alloc_coherent()`, і повертає вона одразу дві адреси: віртуальну, за якою пишемо ми, і `dma_addr_t` — число, яке [контролер прямого доступу](book:unix-linux/dma-and-buffers) виставить на шину. Це два різні числа для однієї й тієї самої пам'яті, і сплутати їх — класична помилка з тихими наслідками.

**Буфер із даними** — теж звичайна пам'ять, але кешована, і перед передачею її треба окремо готувати. Тут ми його не чіпаємо, щоб не заступити головне.

Шов між першими двома і є те, заради чого все затівалося. Записи в кільце мусять лягти раніше, ніж до контролера дійде дзвінок — інакше він прочитає напівзаповнений дескриптор. Бар'єра, що це гарантує, у коді драйвера не видно: його несе всередині себе перший же `writel`.

![Записи в кільце, бар'єр усередині writel, дзвінок у регістр; контролер іде читати те саме кільце за адресою ring_dma. Нижче — таблиця: кільце має віртуальну адресу p->ring для процесора і число p->ring_dma для пристрою, регістр має віртуальну адресу від ioremap для процесора і фізичну 0xe0001018 для пристрою](img/ring-and-doorbell.svg)

*Одна річ під двома адресами — і кільце, і вікно регістрів. Різниця в тому, що обидві адреси кільця драйвер тримає в себе в полях, а фізичну адресу вікна він не тримає ніде: її знає тільки залізо.*

## Код

Мова тут не обирається: регістри, ширина доступу й бар'єри живуть у C і більше ніде.

```c
// SPDX-License-Identifier: GPL-2.0
#include <linux/clk.h>
#include <linux/dma-mapping.h>
#include <linux/interrupt.h>
#include <linux/io.h>
#include <linux/ktime.h>
#include <linux/module.h>
#include <linux/platform_device.h>

#define REG_ID          0x000   /* лише читання: сигнатура блока   */
#define REG_CTRL        0x004
#define REG_IRQ_CAUSE   0x00c   /* запис одиниці скидає біт        */
#define REG_RING_LO     0x010
#define REG_RING_HI     0x014
#define REG_TX_KICK     0x018   /* дзвінок: тут — номер дескриптора */
#define REG_TX_DONE     0x01c

#define MYETH_ID        0x4d594554      /* 'MYET', якщо читати число зі старшого байта */
#define CTRL_ENABLE     BIT(0)
#define IRQ_TX_DONE     BIT(0)

#define RING_LEN        64
#define BUF_LEN         2048

struct tx_desc {
        __le64 addr;
        __le32 len;
        __le32 flags;
};
#define DESC_OWN        cpu_to_le32(BIT(31))

struct myeth {
        struct device  *dev;
        void __iomem   *regs;           /* адреса вікна для процесора */
        struct tx_desc *ring;           /* кільце: адреса для процесора */
        dma_addr_t      ring_dma;       /* кільце: адреса для пристрою  */
        void           *buf;
        dma_addr_t      buf_dma;
        unsigned int    head;
        unsigned int    entries;        /* входів у обробник */
        unsigned int    foreign;        /* з них не наших    */
        unsigned int    sent;           /* дзвінків          */
};

static unsigned int kicks;
module_param(kicks, uint, 0444);
MODULE_PARM_DESC(kicks, "скільки дескрипторів проштовхнути одразу після probe");

static unsigned int bench;
module_param(bench, uint, 0444);
MODULE_PARM_DESC(bench, "скільки читань регістра зробити для заміру");

/* ── гарячий шлях: дескриптор і дзвінок ─────────────────────────────── */

static void myeth_kick(struct myeth *p, dma_addr_t buf, u32 len)
{
        struct tx_desc *d = &p->ring[p->head];

        d->addr = cpu_to_le64(buf);
        d->len  = cpu_to_le32(len);
        /* Прапорець власності — останнім і окремо: до цього рядка
           дескриптор наш, після нього вже пристрою.                */
        d->flags = DESC_OWN;

        /* Бар'єра руками нема — його несе перший writel. Саме він
           гарантує, що три записи вище лягли раніше за дзвінок.    */
        writel(p->head, p->regs + REG_TX_KICK);

        p->head = (p->head + 1) % RING_LEN;
        p->sent++;
}

static irqreturn_t myeth_isr(int irq, void *data)
{
        struct myeth *p = data;
        u32 cause = readl(p->regs + REG_IRQ_CAUSE);

        p->entries++;
        if (!cause) {
                p->foreign++;
                return IRQ_NONE;        /* лінія спільна: озвався не наш блок */
        }

        if (cause & IRQ_TX_DONE)
                readl(p->regs + REG_TX_DONE);   /* тут звільняли б буфери */

        writel(cause, p->regs + REG_IRQ_CAUSE);
        readl(p->regs + REG_IRQ_CAUSE);         /* проштовхнути скидання */

        return IRQ_HANDLED;
}

/* ── замір ціни бар'єрів ────────────────────────────────────────────── */

static void myeth_bench(struct myeth *p, unsigned int n)
{
        unsigned long flags;
        ktime_t t0, t1, t2;
        unsigned int i;
        u32 sink = 0;

        /* Замір, а не робочий код: інакше цикл міряв би планувальник,
           а не шину. Переривання вимкнено на весь прохід, тож n беруть
           таким, щоб не вийти за пару десятків мілісекунд.      */
        local_irq_save(flags);

        t0 = ktime_get();
        for (i = 0; i < n; i++)
                sink += readl(p->regs + REG_ID);
        t1 = ktime_get();
        for (i = 0; i < n; i++)
                sink += readl_relaxed(p->regs + REG_ID);
        t2 = ktime_get();

        local_irq_restore(flags);

        dev_info(p->dev, "%u доступів: readl %lld нс, readl_relaxed %lld нс (сума %#x)\n",
                 n, ktime_to_ns(ktime_sub(t1, t0)),
                 ktime_to_ns(ktime_sub(t2, t1)), sink);
}

/* ── прив'язка ──────────────────────────────────────────────────────── */

static int myeth_probe(struct platform_device *pdev)
{
        struct device *dev = &pdev->dev;
        struct myeth *p;
        struct clk *clk;
        unsigned int i;
        int irq, ret;
        u32 id;

        p = devm_kzalloc(dev, sizeof(*p), GFP_KERNEL);
        if (!p)
                return -ENOMEM;
        p->dev = dev;
        platform_set_drvdata(pdev, p);

        /* Займає діапазон у /proc/iomem, відображає його й вішає
           звільнення на знищення пристрою.                        */
        p->regs = devm_platform_ioremap_resource(pdev, 0);
        if (IS_ERR(p->regs))
                return PTR_ERR(p->regs);

        /* Такт — ПЕРЕД першим читанням регістра, а не після. */
        clk = devm_clk_get_enabled(dev, NULL);
        if (IS_ERR(clk))
                return dev_err_probe(dev, PTR_ERR(clk), "нема такту блока\n");

        id = readl(p->regs + REG_ID);
        if (id != MYETH_ID)
                return dev_err_probe(dev, -ENODEV,
                                     "сигнатура %#010x%s\n", id,
                                     id == 0xffffffff ? " — ніхто не озвався" : "");

        ret = dma_set_mask_and_coherent(dev, DMA_BIT_MASK(32));
        if (ret)
                return ret;

        p->ring = dmam_alloc_coherent(dev, RING_LEN * sizeof(*p->ring),
                                      &p->ring_dma, GFP_KERNEL);
        p->buf  = dmam_alloc_coherent(dev, BUF_LEN, &p->buf_dma, GFP_KERNEL);
        if (!p->ring || !p->buf)
                return -ENOMEM;

        writel(lower_32_bits(p->ring_dma), p->regs + REG_RING_LO);
        writel(upper_32_bits(p->ring_dma), p->regs + REG_RING_HI);

        irq = platform_get_irq(pdev, 0);
        if (irq < 0)
                return irq;

        /* Обробник реєструємо, поки пристрій ще мовчить: після
           наступного рядка переривання прилетить будь-якої миті. */
        ret = devm_request_irq(dev, irq, myeth_isr, IRQF_SHARED,
                               dev_name(dev), p);
        if (ret)
                return ret;

        writel(CTRL_ENABLE, p->regs + REG_CTRL);

        for (i = 0; i < kicks; i++)
                myeth_kick(p, p->buf_dma, 64);
        if (bench)
                myeth_bench(p, bench);

        dev_info(dev, "регістри %p, кільце %p / шинна %pad\n",
                 p->regs, p->ring, &p->ring_dma);
        return 0;
}

static void myeth_remove(struct platform_device *pdev)
{
        struct myeth *p = platform_get_drvdata(pdev);

        /* Порядок протилежний до probe, і в цьому вся суть: спершу
           глушимо джерело, і лише тоді devres знімає обробник.     */
        writel(0, p->regs + REG_CTRL);
        writel(~0u, p->regs + REG_IRQ_CAUSE);
        readl(p->regs + REG_IRQ_CAUSE);

        dev_info(p->dev, "дзвінків %u, входів у обробник %u, з них чужих %u\n",
                 p->sent, p->entries, p->foreign);
}

static const struct of_device_id myeth_of[] = {
        { .compatible = "example,myeth" },
        { }
};
MODULE_DEVICE_TABLE(of, myeth_of);

static struct platform_driver myeth_driver = {
        .probe  = myeth_probe,
        .remove = myeth_remove,
        .driver = {
                .name           = "myeth",
                .of_match_table = myeth_of,
        },
};
module_platform_driver(myeth_driver);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Показовий платформний драйвер: ioremap, кільце, дзвінок");
```

Жодного `iounmap`, `free_irq` чи `dma_free_coherent` у коді немає навмисно. Уся [керована ресурсами родина](book:unix-linux/devres-managed-resources) з префіксом `devm`/`dmam` чіпляє звільнення до життя пристрою, і воно відбувається у зворотному порядку саме собою — зокрема й тоді, коли `probe` обірвався на середині. Тому вихід із помилки тут — просто `return`, без драбинки `goto`.

Функція `.remove` повертає `void`: значення, яке вона колись повертала, ядро однаково ігнорувало, бо відмовитися від'єднатися драйвер не має права.

## Куди дивитися, коли модуль став

Три файли [в `/proc`](book:unix-linux/proc-filesystem) показують три різні боки того самого відображення. Перші два читайте з-під `root`: звичайному користувачеві ядро підмінює всі адреси в них нулями.

```sh
# хто зайняв фізичний діапазон — дерево struct resource
$ sudo grep -i myeth /proc/iomem
  e0001000-e0001fff : e0001000.ethernet

# де це відображення живе у віртуальних адресах ядра
$ sudo grep ioremap /proc/vmallocinfo
0xffff800010800000-0xffff800010802000   8192 devm_ioremap_resource+0x54/0xd0 \
  phys=0x00000000e0001000 ioremap

# лічильник входів у обробник, по одному стовпцю на ядро процесора
$ grep myeth /proc/interrupts
 41:       1024          0     GICv3  62 Level     e0001000.ethernet
```

Перший рядок — запис, який зробив `request_mem_region` усередині обгортки: він лише позначає, що діапазон зайнято. Другий — те саме вікно з протилежного боку: дві сторінки [у службовій області адрес ядра](book:unix-linux/vmalloc-kernel-mappings), позначені як `ioremap`, із фізичною адресою поруч. Третій — [лічильник переривань](book:unix-linux/interrupts-bottom-halves), і саме він буде нашим приладом.

Шукати адресу в журналі марно: з версії 4.15 `%p` друкує не саме число, а його хеш, тож `dev_info` наприкінці `probe` покаже щось стале й неправдиве. Це зроблено навмисно — адреса в ядрі підказує, куди цілитися нападникові. Справжні числа лежать тільки у двох файлах вище, і тільки для `root`.

## Стенд перший: де `writel_relaxed` ставити не можна, а де можна

Найпростіший спосіб «прискорити» гарячий шлях — замінити в `myeth_kick` єдиний `writel` на `writel_relaxed`. Спробуйте: усе працюватиме. На x86 воно й далі буде правильним, бо там бар'єр у `writel` — не інструкція, а лише заборона компіляторові переставляти доступи, тоді як самі записи в некешовану пам'ять архітектура впорядковує сама. На arm64 стенд теж покаже зелене — на малому потоці. А потім, під навантаженням, контролер прочитає дескриптор, у якому вже стоїть прапорець власності, але ще не долетіла довжина, і в мережу піде кадр із випадковим розміром.

Це найгірший ґатунок помилки: вона залежить від завантаженості буфера записів, тобто виявляється рідко, не там, де живе, і не відтворюється на вимогу. Тому правило просте — бар'єр перед дзвінком не прибирають, його переносять.

Переносити є куди. Коли кадрів багато, драйвер заповнює пачку дескрипторів і аж тоді дзвонить: усі записи в кільце йдуть до бар'єра, усі дзвінки — після нього, і бар'єр потрібен один на всю пачку.

```c
static void myeth_kick_batch(struct myeth *p, dma_addr_t buf, u32 len,
                             unsigned int n)
{
        unsigned int i, first = p->head;

        for (i = 0; i < n; i++) {
                struct tx_desc *d = &p->ring[(first + i) % RING_LEN];

                d->addr  = cpu_to_le64(buf);
                d->len   = cpu_to_le32(len);
                d->flags = DESC_OWN;
        }

        /* Один бар'єр на всю пачку: він відділяє ВСІ записи в кільце
           від ВСІХ дзвінків, а дзвінки впорядковані між собою самі. */
        dma_wmb();
        for (i = 0; i < n; i++)
                writel_relaxed((first + i) % RING_LEN, p->regs + REG_TX_KICK);

        p->head = (first + n) % RING_LEN;
        p->sent += n;
}
```

**Умова: відкладений запис до найближчого моста коштує близько 20 нс, бар'єр `dma_wmb()` на вільному ядрі — близько 30 нс, пачка — 8 кадрів, потік — 500 тисяч кадрів на секунду.**

```
по кадру   8 × (30 + 20) = 400 нс на пачку
пачкою      30 + 8 × 20  = 190 нс на пачку
виграш                     210 нс на пачку = 26 нс на кадр

500 000 × 26 нс = 0.013 с щосекунди ≈ 1.3 % одного ядра
```

Трохи більше за відсоток ядра — це помітно для мережевого контролера й ніщо для датчика температури. Тому `_relaxed` ставлять на гарячому шляху й ніде більше, а поруч у ядрі заведено писати коментар, чому саме тут це безпечно: [бар'єри](book:programming/memory-barrier-instructions) — те єдине місце в драйвері, де правильність не видно з коду.

Розмір виграшу залежить від архітектури більше, ніж від драйвера. На arm64 `writel` розкладається на `dma_wmb()` (інструкція `dmb oshst`) і власне запис; колись там стояв важчий `dsb`, і його послабили латкою Вілла Дікона `22ec71615d82` «arm64: io: Relax implicit barriers in default I/O accessors». На x86 тієї інструкції немає взагалі — і та сама переробка дає на ARM відчутний виграш, а на x86 нуль.

## Стенд другий: приберімо проштовхувальне читання

Викиньмо з обробника рядок `readl(p->regs + REG_IRQ_CAUSE)` після скидання й порівняймо два числа: скільки разів ми подзвонили і скільки разів нас покликали.

```
з проштовхувальним читанням
  $ sudo insmod myeth.ko kicks=1000
  $ sudo rmmod myeth && dmesg | tail -1
  myeth: дзвінків 1000, входів у обробник 1000, з них чужих 0

без нього
  myeth: дзвінків 1000, входів у обробник 4312, з них чужих 0
```

Пристрій тримає лінію притиснутою, доки скидання не дійде; поки запис іде мостами, контролер переривань заводить обробник знову й знову з тією самою причиною. У `/proc/interrupts` це видно як лічильник, що росте вчетверо швидше за кількість подій. Показово, що стовпець «чужих» лишається нульовим: кожен зайвий вхід виглядає цілком законним — причина ж справді виставлена, — і жодного попередження в журналі не буде. Драйвер просто робить учетверо більше роботи, і єдиний спосіб це помітити — рахувати самому.

## Стенд третій: скільки коштує бар'єр у циклі

Параметр `bench` ганяє два однакові цикли поспіль — на `readl` і на `readl_relaxed`. Такий цикл — не вигадка: саме так вичитують пачку слів із черги пристрою, і саме там `_relaxed` дає найбільше.

**Умова: оберт до внутрішнього регістра SoC — близько 190 нс, `dma_rmb()` (інструкція `dmb oshld`) — близько 30 нс, у циклі 50 тисяч ітерацій; більше не беремо, бо переривання вимкнено на весь замір.**

```
readl_relaxed   190 нс × 50 000 =  9.5 мс
readl           220 нс × 50 000 = 11.0 мс
різниця                            1.5 мс — 16 %
```

Шоста частина часу за те, чого в цьому циклі ніхто не просив: усередині одного пристрою доступи впорядковані й без бар'єрів, а зі звичайною пам'яттю цикл не взаємодіє взагалі. Один `readl` наприкінці — і контракт відновлено.

## Пастки

**Регістр до такту.** Рядок `devm_clk_get_enabled()` стоїть перед першим `readl` не з естетики. Відображення існує незалежно від живлення блока, і читання вимкненого блока не поверне нулів: на x86 шина віддасть усі одиниці, на ARM це зазвичай зовнішня аварія доступу й падіння ядра. Те саме стосується [присипляння на ходу](book:unix-linux/runtime-power-management): після того, як пристрій відпущено, будь-яке звертання до його регістрів — помилка, і найчастіше вона трапляється в обробнику, який прокинувся невчасно.

**Регістр після `remove`.** У `myeth_remove` пристрій глушиться першим рядком, і це єдиний правильний порядок. Зробіть навпаки — і між зняттям обробника й записом нуля в `REG_CTRL` лишиться вікно, у якому лінія притиснута, а відповідати нікому: ядро побачить переривання, на яке ніхто не зголосився, і врешті вимкне його зі словами `nobody cared`. Симетрична біда чекає на боці [вивантаження модуля](book:unix-linux/kernel-modules): відображення зникає разом із пристроєм, а таймер чи робота в черзі, які ви завели самі, — ні, і вони підуть писати за адресою, якої вже немає.

**`0xffffffff` — не значення, а мовчання.** Перевірка сигнатури в `probe` ловить його окремим повідомленням саме тому, що всі одиниці означають «ніхто не озвався»: і зниклий пристрій, і блок під скиданням, і адреса, помилково зсунута на сторінку. Драйвер, який жодного разу не питає себе, чи це справжні дані, з однаковим виразом обличчя обслуговує пристрій і порожнечу — читає стан «черга повна, помилок сорок вісім» і старанно його обробляє.

**Дві адреси одного кільця.** У `REG_RING_LO`/`REG_RING_HI` іде `p->ring_dma`, а не `virt_to_phys(p->ring)` і тим паче не сам вказівник. На простій платі ці числа можуть збігтися, і код здаватиметься робочим доти, доки між пристроєм і пам'яттю не з'явиться [блок керування пам'яттю введення-виведення (IOMMU)](book:programming/iommu) чи постійний зсув шини. Тоді дескриптор виявиться прочитаним не звідти — тихо, без жодного повідомлення.
