# 📜 Еволюція обробки введення у Linux: від psaux до evdev

У ранніх версіях ядра Linux (серії 0.99, 1.x та 2.0/2.2) єдиного шару абстракції для маніпуляторів не існувало в принципі. Кожна апаратна архітектура та кожен клас периферії обслуговувалися ізольованими драйверами символьних пристроїв. Клавіатура персонального комп'ютера оброблялася безпосередньо у підсистемі віртуальних консолей TTY (`drivers/tty/vt/keyboard.c`). Контролер 8042 на материнській платі генерував переривання IRQ 1, драйвер зчитував 8-бітний сканкод (Set 1 або Set 2), переводив його за таблицею розкладки (`key_maps`) у внутрішній код клавіші та відразу відправляв сформований символьний потік у TTY-буфер.

Миші оброблялися абсолютно незалежним шляхом. Для класичних мишей PS/2 виділявся вузол `/dev/psaux` (символьний пристрій з мажорним номером 10 і мінорним 1), який віддавав простору користувача сирий 3-байтовий потік протоколу PS/2 (або 4-байтовий для мишей із коліщатком Microsoft IntelliMouse). Послідовні миші підключалися до COM-портів (`/dev/ttyS0`, `/dev/ttyS1`), і прикладна програма мала самостійно налаштовувати швидкість 1200 бод, перемикати лінії RTS/DTR та декодувати 3-байтові пакети протоколу MouseMan або Microsoft Serial. Аналогові ігрові джойстики, підключені до DB-15 Gameport, мали власну підсистему і свій вузол `/dev/js0`, що повертав структуру `struct JS_DATA_TYPE`.

Така схема функціонувала доти, доки комп'ютер мав статичний набір портів і не передбачав підключення периферії під час роботи системи (hotplugging). Проте поява шини USB (Universal Serial Bus) наприкінці 1990-х років та специфікації USB HID (Human Interface Device) повністю зламала стару модель. 

Особливість специфікації USB HID полягає у тому, що пристрій більше не жорстко прив'язаний до одного класу. Під час ініціалізації контролер відправляє хосту бінарний опис своїх органів керування — **HID Report Descriptor**. У цьому дескрипторі одна фізична USB-периферія може оголосити себе одночасно клавіатурою, мишею, набором коліщат гучності, клавішами керування медіаплеєром та датчиком нахилу.

Спроба інтегрувати USB-пристрої у ядро Linux 2.2 спричинила архітектурну кризу. Драйверам USB HID доводилося розбирати дескриптор, штучно розбивати його на частини і емулювати 3-байтові пакети PS/2 для `/dev/psaux`, одночасно впроваджуючи синтетичні сканкоди у підсистему TTY. Це призводило до складної плутанини: вимикання USB-клавіатури на ходу залишало підсистему TTY у невизначеному стані, а підключення комбінованої миші з клавіатурою вимагало відкриття двох різних файлів пристроїв з різними бінарними протоколами.

У 1999 році чеський розробник Войтех Павлік (Vojtech Pavlik), який на той час займався розробкою універсального драйвера джойстиків, запропонував повну реорганізацію підсистеми введення для розробницької гілки ядра 2.3. Головна ідея Павліка полягала у створенні трирівневої абстракції з центральним ядром **Input Core** (`drivers/input/input.c`).

Нова архітектура розділила підсистему на три компоненти:
1. **Низькорівневі драйвери шин та пристроїв (`input_dev`):** Займаються лише зчитуванням сирих сигналів з апаратури (USB, PS/2, I2C, SPI) та їх перетворенням на стандартизовані події.
2. **Маршрутизатор подій (Input Core):** Приймає події від драйверів і розсилає їх зареєстрованим обробникам на основі бітових масок можливостей.
3. **Високорівневі обробники подій (`input_handler`):** Формують файлові інтерфейси VFS у просторі користувача.

Замість різнотипних байтових потоків Павлік запровадив уніфікований бінарний кадр `struct input_event`, що описує будь-яку фізичну дію за допомогою чотирьох елементарних полів: штампу часу (`time`), типу події (`type`), коду органу (`code`) та значення (`value`). Для забезпечення сумісності з існуючим програмним забезпеченням шар обробників початково містив як новий універсальний інтерфейс `evdev` (`/dev/input/eventN`), так і емулятори `mousedev` (що зводив події від усіх мишей у `/dev/input/mice`) та `joydev` (`/dev/input/jsN`).

Уніфікована підсистема введення увійшла до стабільного ядра Linux 2.4.0 у січні 2001 року і стала остаточним стандартом у серії Linux 2.6.

Еволюція у просторі користувача тривала ще понад десятиліття. Тривалий час графічна система X11 використовувала фрагментовані драйвери для кожного класу пристроїв (`xf86-input-mouse`, `xf86-input-keyboard`, `xf86-input-synaptics`, `xf86-input-wacom`). Кожен з цих драйверів мав власні конфігураційні файли, власний код згладжування осей та власні помилки при обробці гарячого підключення.

Бібліотеку `libinput` започаткував 2013 року Йонас Одаль (Jonas Ådahl), виділивши обробку введення з композитора Weston в окрему бібліотеку; головним її розробником і супровідником став Пітер Гаттерер (Peter Hutterer) з Red Hat, а перший випуск вийшов 2014 року. Метою `libinput` стала спільна обробка подій `evdev` для графічних серверів Wayland і Xorg. Сьогодні `libinput` бере на себе складання багатьох `struct input_event` у високорівневі події та жестові кадри, відсікання випадкових торкань долонею на тачпаді, розпізнавання жестів двома й трьома пальцями та застосування кривих акселерації миші, залишаючи ядру Linux роль надійного та швидкого постачальника сирих подій через `/dev/input/eventN`.
