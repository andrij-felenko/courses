# 🧮 Математична обробка та фільтрація координат ABS у evdev

Абсолютні пристрої введення — зокрема сенсорні екрани, графічні планшети, оптичні дигітайзери та аналогові джойстики — передають у ядро події типу `EV_ABS`. На відміну від відносних маніпуляторів, де кожне значення виражає дельту зміщення відносно попереднього стану, абсолютний пристрій транслює точну фізичну позицію органу керування у власній внутрішній дискретній сітці апаратного контролера.

Оскільки кожен апаратний сенсор виготовляється за власними технологічними стандартами, його діапазон вимірювання рідко збігається з роздільною здатністю логічного дисплея. Крім того, аналогові сигнали схильні до електричних завад, механічного люфту та зсуву нейтралі. Для приведення сирих координат до придатного для графічного інтерфейсу вигляду застосовується математичний апарат нормалізації, афінних перетворень та фільтрації.

### 1. Лінійне масштабування та нормалізація осей

Параметри апаратної осі зчитуються простором користувача за допомогою системного виклику `ioctl(fd, EVIOCGABS(axis), &absinfo)`, де структура `struct input_absinfo` містить значення `minimum` та `maximum`.

Нехай апаратний сенсор генерує сиру координату `X_raw` у фізичному діапазоні `[minimum, maximum]`. Першим кроком є обчислення безрозмірної нормалізованої координати `X_norm`, яка належить замкненому інтервалу `[0.0, 1.0]`:

```
X_norm = (X_raw - minimum) / (maximum - minimum)
```

Для перетворення нормалізованої координати у піксельну координату дисплея шириною `Width` (де пікселі індексуються від `0` до `Width - 1`) застосовується масштабування:

```
X_screen = X_norm · (Width - 1)
```

Ті самі обчислення у цілій арифметиці — із заокругленням до найближчого замість відкидання дробової частини та із захистом від виходу за межі діапазону (clamping):

```
X_clamped = max(minimum, min(maximum, X_raw))
X_screen = floor( ( (X_clamped - minimum) · (Width - 1) + (maximum - minimum) / 2 ) / (maximum - minimum) )
```

Якщо фізичний сенсор змонтований дзеркально відносно матриці дисплея, координата інвертується перед масштабуванням:

```
X_inverted = maximum - (X_clamped - minimum)
X_screen = floor( ( (X_inverted - minimum) · (Width - 1) + (maximum - minimum) / 2 ) / (maximum - minimum) )
```

### 2. Афінні перетворення для орієнтації та калібрування сенсора

У сенсорних пристроях прямим введенням (наприклад, планшетах та сенсорних моніторах) екран може обертатися на кути 90°, 180° або 270°. Для довільного повороту та компенсації нелінійностей дигітайзера застосовується калібрувальна матриця афінного перетворення розміром 3×3.

Перетворення сирого вектора `(X_raw, Y_raw)` у калібрований вектор `(X_cal, Y_cal)` виконується множенням на калібрувальну матрицю:

```
| X_cal |   | c0  c1  c2 |   | X_raw |
| Y_cal | = | c3  c4  c5 | · | Y_raw |
|   1   |   |  0   0   1 |   |   1   |
```

У розгорнутому вигляді рівняння мають вигляд:

```
X_cal = c0 · X_raw + c1 · Y_raw + c2
Y_cal = c3 · X_raw + c4 · Y_raw + c5
```

Коефіцієнти `c0...c5` знаходять під час калібрування за еталонними точками: три точки дають рівно шість рівнянь на шість невідомих і визначають систему однозначно, п'ять і більше — розв'язують методом найменших квадратів. При повороті екрана на 90° за годинниковою стрілкою матриця набирає вигляду:

```
c0 = 0,   c1 = -1,  c2 = Y_max
c3 = 1,   c4 = 0,   c5 = 0
```

Стала `c2` тут — максимум тієї осі, значення якої підставляють на її місце (`Y_max` для `ABS_Y`): саме він робить `X_cal = Y_max - Y_raw` невід'ємним. Масштабування у пікселі дисплея виконують уже після повороту, за формулами розділу 1.

### 3. Зона нечутливості (Deadzone Filtering via `flat`)

Для аналогових джойстиків та важелів значення осі у нейтральному стані рідко дорівнює точно нулю через механічний люфт або температурний дрейф резисторів. Поле `flat` у структурі `struct input_absinfo` визначає напівширину центральної зони нечутливості навколо нейтральної позиції `X_center`.

Кусочно-лінійна функція фільтрації deadzone реалізується таким чином:

```
ΔX = X_raw - X_center

Якщо |ΔX| ≤ flat:
    X_filtered = X_center
Інакше якщо ΔX > flat:
    X_filtered = X_center + (ΔX - flat) · (maximum - X_center) / (maximum - X_center - flat)
Інакше (ΔX < -flat):
    X_filtered = X_center + (ΔX + flat) · (X_center - minimum) / (X_center - minimum - flat)
```

Ця формула не лише прирівнює до нейтралі все, що потрапило у зону `[X_center - flat, X_center + flat]`, а й розтягує решту діапазону так, що на межі зони значення переходить у `X_center` неперервно — без стрибка при виході з нейтрального положення.

### 4. Фільтрація високочастотного шуму та джитера (`fuzz`)

Цифрові планшети та ємнісні сенсори мають незначні електричні наведення, що спричиняють джитер — коливання зчитуваного значення на 1–3 одиниці навіть при нерухомому пальці. Параметр `fuzz` виступає порогом гістерезису для подій зміщення.

Алгоритм відсікання шумів ядра та `libinput`:

```
ΔX_last = |X_raw - X_emitted|

Якщо ΔX_last ≤ fuzz:
    Подія ігнорується (не відправляється у буфер користувача)
Інакше:
    X_emitted = X_raw
    Відправка події EV_ABS
```

Якщо зміна координати перевищує поріг `fuzz`, нове значення проходить одразу. Це усуває дрібне тремтіння курсора при нерухомому пальці, але зберігає миттєву реакцію при швидкому русі.

### 5. Експоненційне згладжування зчитувань (EMA)

Для досягнення високої плавності руху курсора у графічних редакторах згладжування за порогом `fuzz` доповнюють експоненційним ковзним середнім (Exponential Moving Average, EMA):

```
X_smoothed(t) = α · X_raw(t) + (1 - α) · X_smoothed(t - 1)
```

Де `α` — коефіцієнт згладжування у діапазоні `(0.0, 1.0]`. При `α = 0.2` система відсікає високочастотні коливання від нерухомої руки, але додає затримку приблизно (1 − α)/α ≈ 4 кадри. При швидкому русі `α` динамічно підвищують до `1.0` для усунення лагу.

### 6. Центроїд та геометрія Multi-Touch контакту

У протоколі Multi-Touch Type B для кожного з `N` активних слотів `ABS_MT_SLOT` зчитуються окремі координати `(X_i, Y_i)`. Обчислення геометричного центру (центроїда `C_x, C_y`) та охоплюючого прямокутника (Bounding Box) виконується за формулами:

```
C_x = (1 / N) · ∑_{i=1}^{N} X_i
C_y = (1 / N) · ∑_{i=1}^{N} Y_i

X_min = min(X_1...X_N),   X_max = max(X_1...X_N)
Y_min = min(Y_1...Y_N),   Y_max = max(Y_1...Y_N)
```

Відстань між двома пальцями `D_touch` використовується для розпізнавання жестів масштабування (Pinch-to-Zoom):

```
D_touch = √( (X_2 - X_1)² + (Y_2 - Y_1)² )
Scale_factor = D_touch(t) / D_touch(t0)
```

### 7. Розрахунок фізичної швидкості та інерційного прокручування

Поле `resolution` у структурі `struct input_absinfo` визначає кількість відліків сенсора на один міліметр (units/mm) для координат `ABS_X`, `ABS_Y`, `ABS_Z` або відліків на радіан для кутових осей `ABS_RX`, `ABS_RY`, `ABS_RZ`. 

Обчислення фізичного переміщення `ΔS_mm` між двома подібними кадрами `P1(x1, y1, t1)` та `P2(x2, y2, t2)` виконується за формулою:

```
ΔX_mm = (x2 - x1) / resolution_x
ΔY_mm = (y2 - y1) / resolution_y

ΔS_mm = √( (ΔX_mm)² + (ΔY_mm)² )
Δt_sec = (t2 - t1) / 1 000 000.0
```

Миттєва фізична швидкість `V_mm_s` визначається як:

```
V_mm_s = ΔS_mm / Δt_sec
```

Бібліотека `libinput` використовує обчислену фізичну швидкість у мм/с для розрахунку інерційного зсуву (Kinetic Scroll Friction Decay) після відпускання пальця:

```
V(t) = V_initial · e^(-k · t)
S_inertia(t) = (V_initial / k) · (1 - e^(-k · t))
```

Де `k` — коефіцієнт тертя віртуального середовища, а `V_initial` — фізична швидкість пальця в момент розмикання контакту (`BTN_TOUCH` = 0). Такий математичний підхід робить поведінку тачпада та інерційного прокручування однаково природною на будь-якому обладнанні, незалежно від роздільної здатності апаратного сенсора.
