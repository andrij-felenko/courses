# 📋 Інтерфейс ioctl підсистеми evdev

Системні виклики `ioctl` для символьних файлів `/dev/input/eventN` та контролера `/dev/uinput` розроблені для інспектування апаратних можливостей пристрою, управління його станом та створення віртуальних пристроїв простору користувача. Заголовочний файл `<linux/input.h>` містить усі макроси кодування системних викликів, константи типів подій та описи структур даних.

Усі виклики `ioctl` підсистеми `evdev` дотримуються умовного кодування команд Linux VFS, де перші біти визначають напрямок передачі даних (`_IOR`, `_IOW`, `_IOWR`), тип пристрою (символ `'E'` з кодом `0x45` для evdev, символ `'U'` з кодом `0x55` для uinput) та розмір передаваного буфера.

Обробка усіх цих викликів у ядрі виконується всередині функції `evdev_do_ioctl()` в коді `drivers/input/evdev.c`. У разі успішного виконання системний виклик повертає `0` або додатне значення переданих байтів. У разі помилки повертається `-1`, а системна змінна `errno` встановлюється у відповідний код (`EFAULT` при недійсній вказівниковій адресі буфера, `EINVAL` при неправильному типі події або недостатньому буфері, `ENODEV` якщо пристрій був відключений від шини під час виконання виклику).

### 1. Зчитування паспорта та топології пристрою

Ця група викликів дозволяє зчитати версію ABI, назву пристрою, його апаратний Vendor/Product ID та точне положення у топологічній системі шин.

#### Версія драйвера та ідентифікатори
Виклик `EVIOCGVERSION(int *version)` записує у цілочисельний буфер 32-бітну версію протоколу `evdev` (наприклад, `0x010001` для версії 1.0.1). Якщо версія ядра застаріла відносно очікувань прикладної програми, деякі розширені команди `ioctl` можуть повертати помилку `-EINVAL`.

Виклик `EVIOCGID(struct input_id *id)` повертає структуру з інформацією про виробника, модель та тип шини підключення:

```c
struct input_id {
    __u16 bustype;  /* Тип шини: BUS_USB, BUS_BLUETOOTH, BUS_I2C, BUS_PCI, BUS_HOST */
    __u16 vendor;   /* Унікальний ідентифікатор виробника (Vendor ID) */
    __u16 product;  /* Ідентифікатор конкретної моделі (Product ID) */
    __u16 version;  /* Версія прошивки або ревізії контролера */
};
```

Поле `bustype` приймає значення з переліку `BUS_*` у заголовочному файлі `<linux/input-event-codes.h>`. Для USB-пристроїв це значення дорівнює `BUS_USB` (0x03), для Bluetooth — `BUS_BLUETOOTH` (0x05), для пристроїв на шині I2C — `BUS_I2C` (0x18).

#### Рядкові описувачі пристрою
Для отримання людсько-читаних текстових характеристик периферійного пристрою використовується група макросів `EVIOCGNAME`, `EVIOCGPHYS` та `EVIOCGUNIQ`.

Виклик `EVIOCGNAME(int len, char *name)` записує у наданий буфер довжиною `len` байтів текстову назву пристрою, задекларовану прошивкою або драйвером шини (наприклад, `"Logitech USB Optical Mouse"` або `"AT Translated Set 2 keyboard"`). Якщо реальна назва пристрою доша доша доша більша за передану довжину `len`, ядро обрізає рядок і додає нуль-термінатор `\0`.

Виклик `EVIOCGPHYS(int len, char *phys)` повертає текстову фізичну топологію підключення пристрою у системі (наприклад, `"usb-0000:00:14.0-1/input0"`). Опис топології складається з назви хост-контролера PCI, номера контролера USB та номера порту хаба. Це дозволяє прикладному ПЗ відрізнити два абсолютно однакові за Vendor/Product ID пристрої за точним фізичним портом, у який їх встромлено.

Виклик `EVIOCGUNIQ(int len, char *uniq)` повертає унікальний серійний номер або MAC-адресу пристрою (якщо пристрій підключено через Bluetooth або бездротовий ресивер).

### 2. Запит апаратних можливостей (`EVIOCGBIT`)

Оскільки один файловий вузол `/dev/input/eventN` може репрезентувати будь-який пристрій введення, програма повинна перед початком роботи з'ясувати його можливості. Для цього використовується сімейство системних викликів `EVIOCGBIT(ev_type, max_bytes)`.

Макрос `EVIOCGBIT` приймає перший параметр `ev_type`, який визначає категорію запитуваних даних:
- `EVIOCGBIT(0, len)` — повертає бітову маску **типів подій**, які підтримує даний пристрій (`EV_KEY`, `EV_REL`, `EV_ABS`, `EV_LED`, `EV_SW` тощо).
- `EVIOCGBIT(EV_KEY, len)` — повертає бітову маску конкретних **клавіш та кнопок**, які фізично наявні на пристрої (`KEY_A`...`KEY_Z`, `BTN_LEFT`, `BTN_RIGHT`, `BTN_TOUCH` тощо).
- `EVIOCGBIT(EV_REL, len)` — повертає маску відносних осей (`REL_X`, `REL_Y`, `REL_WHEEL`, `REL_HWHEEL`).
- `EVIOCGBIT(EV_ABS, len)` — повертає маску абсолютних осей (`ABS_X`, `ABS_Y`, `ABS_PRESSURE`, `ABS_MT_POSITION_X`).
- `EVIOCGBIT(EV_LED, len)` — повертає маску світлодіодних індикаторів (`LED_NUML`, `LED_CAPSL`, `LED_SCROLLL`).
- `EVIOCGBIT(EV_SW, len)` — повертає маску фізичних перемикачів (`SW_LID`, `SW_HEADPHONE_INSERT`).

#### Перевірка бітових масок у просторі користувача
Для роботи з бітовими масками, поверненими викликом `EVIOCGBIT`, у просторі користувача застосовується набір макросів, які розраховують індекс елемента масиву та зсув біта:

```c
#define BITS_PER_LONG (sizeof(unsigned long) * 8)
#define NBITS(x) ((((x) - 1) / BITS_PER_LONG) + 1)
#define OFF(x)  ((x) % BITS_PER_LONG)
#define BIT(x)  (1UL << OFF(x))
#define LONG(x) ((x) / BITS_PER_LONG)
#define test_bit(bit, array) ((array[LONG(bit)] >> OFF(bit)) & 1)

unsigned long keybit[NBITS(KEY_MAX)] = {0};
ioctl(fd, EVIOCGBIT(EV_KEY, sizeof(keybit)), keybit);

if (test_bit(KEY_ENTER, keybit)) {
    /* Пристрій підтримує клавішу ENTER */
}
```

#### Додаткові властивості пристрою (`EVIOCGPROP`)
Виклик `EVIOCGPROP(len, unsigned long *propbit)` повертає бітову маску високорівневих властивостей пристрою (`INPUT_PROP_*`), які описують характер використання периферії:
- **`INPUT_PROP_POINTER` (0x01):** Пристрій є традиційним джерелом курсора миші.
- **`INPUT_PROP_DIRECT` (0x02):** Пристрій є сенсорним екраном, змонтованим безпосередньо поверх матриці дисплея (пряме позиціонування).
- **`INPUT_PROP_BUTTONPAD` (0x03):** Пристрій є тачпадом, у якого вся фізична поверхня є однією кнопкою (Clickpad).
- **`INPUT_PROP_SEMI_MT` (0x04):** Спрощений сенсор Multi-Touch, який підраховує кількість пальців, але вміє повертати лише спільний прямокутник охоплення.
- **`INPUT_PROP_TOPBUTTONPAD` (0x05):** Додаткові фізичні кнопки розташовані у верхній частині тачпада (специфічно для серій Lenovo ThinkPad).

### 3. Зчитування та налаштування параметрів осей `EV_ABS` (`EVIOCGABS` / `EVIOCSABS`)

Для кожної абсолютної осі (`ABS_X`, `ABS_Y`, `ABS_PRESSURE`, `ABS_TILT_X` тощо) програма повинна зчитати її фізичний діапазон, роздільну здатність та коефіцієнти фільтрації.

Виклик `EVIOCGABS(axis, struct input_absinfo *absinfo)` зчитує поточний стан та конфігурацію осі `axis`. Виклик `EVIOCSABS(axis, const struct input_absinfo *absinfo)` записує нові параметри дискретизації та фільтрації ядра, які негайно застосовуються обробником `evdev`.

#### Структура `struct input_absinfo`
```c
struct input_absinfo {
    __s32 value;       /* Поточне останнє зчитане значення осі */
    __s32 minimum;     /* Мінімальне абсолютне значення апаратного сенсора */
    __s32 maximum;     /* Максимальне абсолютне значення апаратного сенсора */
    __s32 fuzz;        /* Поріг фільтрації шумів та електричних коливань */
    __s32 flat;        /* Розмір центральної зони нечутливості (deadzone) */
    __s32 resolution;  /* Фізична роздільна здатність у units/mm або units/radian */
};
```

Поле `resolution` задає кількість відліків на один міліметр (units/mm) для лінійних осей або відліків на радіан для кутових осей. Це дозволяє простору користувача обчислювати фізичну швидкість руху пальця чи пера незалежно від роздільної здатності конкретної матриці сенсора.

### 4. Зворотний зв'язок, перехоплення та фільтрація масок

Підсистема `evdev` дозволяє не лише зчитувати події, але й перевіряти миттєвий стан органів керування та змінювати параметри роботи драйвера.

- **`EVIOCGKEY(int len, unsigned long *buf)`:** Зчитує поточний миттєвий стан усіх кнопок та клавіш пристрою (1 — натиснута, 0 — відпущена). Це критично важливо під час старту програми або після виникнення кадру `SYN_DROPPED`, коли буфер подій було скинуто через переповнення.
- **`EVIOCGLED(int len, unsigned long *buf)`:** Зчитує поточний стан світлодіодних індикаторів (`LED_NUML`, `LED_CAPSL`, `LED_SCROLLL`).
- **`EVIOCGSW(int len, unsigned long *buf)`:** Зчитує стан фізичних перемикачів (`SW_LID` — стан кришки ноутбука, `SW_HEADPHONE_INSERT` — підключення навушників у роз'єм).
- **`EVIOCGRAB (int grab)`:** При надсиланні значення `1` перехоплює пристрій у монопольний режим. З цього моменту ядро припиняє передачу подій даного `input_dev` усім іншим відкритим файловим дескрипторам та обробникам. При надсиланні `0` або при закритті дескриптора викликом `close(fd)` монопольний режим скасовується.
- **`EVIOCSCLOCK (int *clock_id)`:** Змінює джерело штампів часу подій у структурі `input_event.time`. За замовчуванням використовується `CLOCK_REALTIME` (стінний час). Додатки можуть переключити пристрій на `CLOCK_MONOTONIC` (монотонний час без стрибків при переведенні годинника) або `CLOCK_BOOTTIME` (монотонний час, що включає тривалість сну системи).
- **`EVIOCGMASK / EVIOCSMASK (struct input_mask *mask)`:** Встановлює маску фільтрації подій для конкретного файлового дескриптора. При цьому ядро відфільтровує небажані `EV_*` події ще у контексті ядра, не витрачаючи пам'ять кільцевого буфера клієнта.

### 5. Перепризначення сканккодів (`EVIOCGKEYCODE` / `EVIOCSKEYCODE`)

Для клавіатур та мультимедійних панелей ядро утримує внутрішню таблицю перетворення сирих апаратних сканккодів (scancodes) у стандартизовані коди клавіш ядра (keycodes):

- **`EVIOCGKEYCODE (unsigned int scancode[2])`:** Зчитує поточний код клавіші, прив'язаний до сканккоду `scancode[0]`, і записує результат у `scancode[1]`.
- **`EVIOCSKEYCODE (const unsigned int scancode[2])`:** Змінює мапінг ядра, прив'язуючи апаратний сканккод `scancode[0]` до нового коду клавіші `scancode[1]`.

Розширена версія викликів використовує структуру `struct input_keymap_entry`, яка підтримує апаратні сканккоди довільної довжини (наприклад, 4-байтові та 8-байтові послідовності USB HID).

### 6. Керування Force Feedback (`EVIOCSFF` / `EVIOCRMFF`)

Пристрої з підтримкою силового зворотного зв'язку (Force Feedback ігрові керма, джойстики та геймпади з вібромоторами) обробляють завантаження ефектів через виклики `ioctl`:

- **`EVIOCSFF (struct ff_effect *effect)`:** Завантажує новий ефект у пам'ять контролера пристрою або оновлює існуючий. Повертає цілочисельний `effect->id`.
- **`EVIOCRMFF (int effect_id)`:** Видаляє ефект із пам'яті пристрою та звільняє слот.

Програвання завантаженого ефекту виконується звичайним викликом `write(fd, &ev, sizeof(ev))`, де `type = EV_FF`, `code = effect_id`, а `value = count` (кількість повторів).

### 7. Інтерфейс контролера uinput (`/dev/uinput`)

Створення віртуальних пристроїв у ядрі через `/dev/uinput` виконується за допомогою окремої серії викликів `ioctl`, визначених у `<linux/uinput.h>`.

| Команда `ioctl` | Тип аргументу | Опис семантики |
| :--- | :--- | :--- |
| `UI_SET_EVBIT` | `int ev_type` | Оголошує підтримку типу подій (`EV_KEY`, `EV_REL`, `EV_ABS`). |
| `UI_SET_KEYBIT` | `int key_code` | Додає конкретну клавішу/кнопку до списку здатностей пристрою. |
| `UI_SET_RELBIT` | `int rel_code` | Додає відносну вісь (`REL_X`, `REL_Y`, `REL_WHEEL`). |
| `UI_SET_ABSBIT` | `int abs_code` | Додає абсолютну вісь (`ABS_X`, `ABS_Y`). |
| `UI_SET_PROPBIT` | `int prop_code` | Додає властивість пристрою (`INPUT_PROP_DIRECT` тощо). |
| `UI_DEV_SETUP` | `struct uinput_setup *` | Записує специфікацію пристрою (назву, Vendor/Product ID). |
| `UI_DEV_CREATE` | `void` | Інструктує ядро зареєструвати `input_dev` та створити `/dev/input/eventN`. |
| `UI_DEV_DESTROY` | `void` | Видаляє віртуальний пристрій з ядра та знищує його `/dev/input/eventN`. |

#### Структура `struct uinput_setup`
```c
struct uinput_setup {
    struct input_id id;                   /* Bustype, Vendor, Product, Version */
    char name[UINPUT_MAX_NAME_SIZE];      /* Текстова назва пристрою */
    __u32 ff_effects_max;                 /* Максимальна кількість Force Feedback ефектів */
};
```
