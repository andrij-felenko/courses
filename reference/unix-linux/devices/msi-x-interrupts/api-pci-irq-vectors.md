# 📋 Довідник API: інтерфейси керування векторами переривань PCI у ядрі Linux

Уніфікований інтерфейс виділення переривань PCI ядра Linux замінив застарілі розрізнені виклики `pci_enable_msi()`, `pci_enable_msix()`, `pci_enable_msix_range()` та `pci_disable_msi()`. Сучасний підхід надає драйверам єдиний набір функцій для автоматичного узгодження між MSI-X, MSI та класичними лініями INTx, а також для автоматичного призначення спорідненості до процесорних ядер.

Нижче наведено повний довідник функцій, структур даних, прапорців конфігурації, механізмів обробки помилок та файлів віртуальної файлової системи `sysfs`.

## Головні функції виділення та звільнення векторів

Усі функції оголошені в заголовному файлі `<linux/pci.h>`. Їхня реалізація спирається на внутрішній шар ієрархічних доменів переривань ядра (`irq_domain`), що зв'язує апаратні структури шини PCI з підсистемою планування процесора.

### `pci_alloc_irq_vectors`

Виділяє діапазон векторів переривань для пристрою PCI з урахуванням апаратних можливостей платформи та запитаних прапорців.

```c
int pci_alloc_irq_vectors(struct pci_dev *dev,
                          unsigned int min_vecs,
                          unsigned int max_vecs,
                          unsigned int flags);
```

#### Параметри

- `dev` — вказівник на структуру дескриптора пристрою `struct pci_dev`. Пристрій має бути попередньо увімкнений через `pci_enable_device()`.
- `min_vecs` — мінімально допустима кількість векторів, без якої драйвер не зможе функціонувати (зазвичай `1`). Якщо платформа не здатна надати навіть таку кількість, виклик зазнає невдачі.
- `max_vecs` — максимально бажана кількість векторів (наприклад, кількість черг або кількість доступних ядер CPU). Ядро намагається виділити якомога ближче до цього числа.
- `flags` — бітова маска дозволених типів переривань (`PCI_IRQ_MSIX`, `PCI_IRQ_MSI`, `PCI_IRQ_LEGACY`, `PCI_IRQ_AFFINITY`).

#### Повернене значення

- `> 0` — кількість фактично виділених векторів (гарантовано лежить у межах `[min_vecs, max_vecs]`).
- `-ENOSPC` — системі не вдалося виділити навіть `min_vecs` векторів (вичерпано вектори в IDT або ліміти переривань контролера).
- `-EINVAL` — передано некоректні аргументи (наприклад, `min_vecs > max_vecs` або не вказано жодного прапорця типу переривання).
- `-ENOMEM` — недостатньо оперативної пам'яті ядра для виділення внутрішніх дескрипторів `struct msi_desc`.
- `-EIO` — апаратна помилка доступу до регістрів конфігураційного простору PCI або таблиць MMIO BAR.

### `pci_alloc_irq_vectors_affinity`

Розширена версія функції виділення, яка дозволяє драйверу передати власні правила автоматичного розподілу векторів по процесорних ядрах та вузлах NUMA.

```c
int pci_alloc_irq_vectors_affinity(struct pci_dev *dev,
                                   unsigned int min_vecs,
                                   unsigned int max_vecs,
                                   unsigned int flags,
                                   struct irq_affinity *affd);
```

#### Параметри

- `dev`, `min_vecs`, `max_vecs`, `flags` — аналогічні функції `pci_alloc_irq_vectors()`.
- `affd` — вказівник на структуру `struct irq_affinity`, що описує бажаний поділ векторів на службові та робочі. Якщо передано `NULL`, поведінка еквівалентна виклику `pci_alloc_irq_vectors()`.

Коли вказано прапорець `PCI_IRQ_AFFINITY`, ядро під час виділення векторів аналізує фізичне розташування пристрою на шині PCIe та його прив'язку до локального вузла NUMA. Вектори черг автоматично розподіляються між процесорними ядрами цього вузла, мінімізуючи затримки доступу до пам'яті та усуваючи передачу даних між різними процесорними сокетами.

---

### `pci_free_irq_vectors`

Звільняє всі вектори переривань, виділені попереднім викликом `pci_alloc_irq_vectors()` або `pci_alloc_irq_vectors_affinity()`.

```c
void pci_free_irq_vectors(struct pci_dev *dev);
```

#### Правила використання

- Перед викликом `pci_free_irq_vectors()` драйвер **зобов'язаний** звільнити всі зареєстровані обробники за допомогою `free_irq()`. Спроба вивільнити вектори з активними обробниками викличе попередження ядра та витік ресурсів.
- Функція очищає внутрішні записи в `MSI-X Table`, обнуляє маски в регістрах `MSI Capability`, повертає вектори в системний пул IDT ядра та вимикає генерацію повідомлень у пристрої.

---

### `pci_irq_vector`

Отримує глобальний системний номер Linux IRQ для вектора пристрою з порядковим номером `nr`.

```c
int pci_irq_vector(struct pci_dev *dev, unsigned int nr);
```

#### Параметри

- `dev` — вказівник на структуру `struct pci_dev`.
- `nr` — порядковий номер вектора всередині пристрою (від `0` до виділеної кількості мінус 1).

#### Повернене значення

- Позитивний номер Linux IRQ, придатний для передачі у `request_irq()` або `request_threaded_irq()`.
- `-EINVAL` — якщо індекс `nr` перевищує кількість виділених векторів.

## Бітові прапорці конфігурації

Прапорці передаються в поле `flags` і визначають пріоритет та доступні механізми доставки переривань.

```
Прапорці типів переривань:
Прапорець            Значення     Опис
──────────────────────────────────────────────────────────────────────────────────────────
PCI_IRQ_LEGACY       (1 << 0)     Дозволяє використання фізичних ліній INTx (active-low).
PCI_IRQ_MSI          (1 << 1)     Дозволяє використання класичного Message Signaled Interrupts.
PCI_IRQ_MSIX         (1 << 2)     Дозволяє використання розширеного MSI-X з таблицею в BAR.
PCI_IRQ_ALL_TYPES    (LEGACY |    Дозволяє будь-який тип. Ядро перевіряє у порядку пріоритету:
                      MSI | MSIX) 1. MSI-X  →  2. MSI  →  3. Legacy INTx.
PCI_IRQ_AFFINITY     (1 << 3)     Автоматично призначає маски спорідненості векторам за NUMA.
PCI_IRQ_NOMSI        0            Забороняє MSI/MSI-X (еквівалентно лише PCI_IRQ_LEGACY).
```

### Логіка узгодження типів (Fallback Mechanism)

Якщо драйвер передає комбінацію прапорців `PCI_IRQ_ALL_TYPES`, ядро послідовно намагається виділити найпродуктивніший доступний механізм:

1. **Спроба MSI-X.** Ядро перевіряє наявність структури MSI-X Capability у пристрої та вільних слотів у системі. Якщо пристрій підтримує MSI-X і вдалося виділити хоча б `min_vecs` векторів, функція повертає результат і завершує роботу.
2. **Спроба класичного MSI.** Якщо MSI-X не підтримується або виділення зазнало невдачі, ядро перевіряє підтримку базового MSI. Оскільки MSI вимагає виділення степеня двійки векторів зі спільною адресою, ядро округлює запитану кількість до найближчого меншого або рівного степеня двійки.
3. **Відкат до Legacy INTx.** Якщо пристрій не підтримує повідомлення або на шині активовано прапорець заборони MSI (через апаратний quirk або параметр ядра `pci=nomsi`), ядро виділяє єдину лінію INTx (повертаючи `1`).

## Структура керування спорідненістю `struct irq_affinity`

Структура `struct irq_affinity` дозволяє драйверу гнучко розділити виділені вектори на три групи: службові вектори на початку діапазону, робочі багаточергові вектори, прив'язані до ядер CPU, та додаткові вектори в кінці.

```c
struct irq_affinity {
    unsigned int pre_vectors;
    unsigned int post_vectors;
    unsigned int nr_sets;
    unsigned int *set_size;
    void (*calc_sets)(struct irq_affinity *, unsigned int nvecs);
    void *priv;
};
```

### Призначення полів та алгоритм розподілу

- `pre_vectors` — кількість векторів на початку списку, які не прив'язуються до черг CPU (наприклад, окремий вектор для апаратних помилок лінку PCIe, керування живленням або скидання стану).
- `post_vectors` — кількість спеціальних векторів у кінці списку (наприклад, окремий вектор для черги керування RDMA чи службових сповіщень).
- `nr_sets` — кількість незалежних наборів черг. Застосовується в мережевих картах, де черги прийому (RX) та передачі (TX) мають різну кількість або незалежне керування.
- `set_size` — масив, де кожен елемент вказує розмір відповідного набору черг.
- `calc_sets` — вказівник на функцію зворотного виклику. Якщо ядро не може виділити повну кількість векторів `max_vecs`, воно викликає `calc_sets()`, щоб драйвер міг пропорційно зменшити розміри наборів `set_size` під фактично доступну кількість `nvecs`.
- `priv` — непрозорий вказівник на внутрішній контекст драйвера.

## Інтерфейси файлової системи `sysfs` та `procfs`

Ядро Linux експортує повний стан виділених переривань через дерево віртуальних файлових систем, дозволяючи засобам моніторингу та оркестрації контейнерів перевіряти топологію зв'язків.

```
Вузли sysfs та procfs для переривань PCI:
Шлях до файлу                            Опис
──────────────────────────────────────────────────────────────────────────────────────────
/sys/bus/pci/devices/<BDF>/msi_irqs/<IRQ> Вміст: "msix" або "msi". Підтверджує виділення
                                         вектора та його тип.

/sys/bus/pci/devices/<BDF>/msi_bus       Вміст: "1" або "0". Ознака дозволу MSI на шині.

/proc/irq/<IRQ>/smp_affinity             Шістнадцяткова бітова маска дозволених ядер CPU
                                         (наприклад, "00000001" для CPU 0).

/proc/irq/<IRQ>/smp_affinity_list        Список ядер CPU у десятковому форматі
                                         (наприклад, "0-3,8").

/proc/irq/<IRQ>/node                     Номер фізичного вузла NUMA, до якого тяжіє переривання.

/proc/irq/<IRQ>/effective_affinity       Фактичне ядро процесора, яке обслуговує вектор зараз.

/proc/interrupts                         Глобальна статистика спрацьовувань переривань
                                         по кожному ядру CPU окремо.
```

## Порядок і правила використання API

Під час інтеграції викликів виділення переривань у драйвер пристрою необхідно суворо дотримуватися послідовності операцій:

1. **Майстеринг шини.** Виклик `pci_set_master(pdev)` повинен передувати генерації переривань пристроєм. Без цього біта транзакції MSI-X Memory Write блокуються на рівні апаратного контролера.
2. **Симетричність реєстрації.** Кожен виклик `request_irq()` повинен мати парний виклик `free_irq()`, що викликається строго **до** виклику `pci_free_irq_vectors()`.
3. **Обробка скороченого виділення.** Драйвер зобов'язаний аналізувати число, повернуте `pci_alloc_irq_vectors()`, оскільки воно може бути меншим за `max_vecs`, але більшим або рівним `min_vecs`. Драйвер повинен динамічно обмежити кількість активних апаратних черг фактично отриманою кількістю векторів.
4. **Очищення ресурсів у remove.** У функції видалення драйвера `remove()` вивільнення переривань виконується у зворотному порядку: спершу зупинка прийому пакетів пристроєм, потім `free_irq()`, потім `pci_free_irq_vectors()`, і лише наприкінці — скасування відображення регістрів `pci_iounmap()` та вимкнення пристрою `pci_disable_device()`.
