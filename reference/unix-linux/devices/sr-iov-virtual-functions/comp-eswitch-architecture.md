# 🔌 Вбудований апаратний комутатор (Embedded eSwitch) у SR-IOV адаптерах

Комутація мережевого трафіку між віртуальними функціями (VF) та фізичним портом (PF) реалізується апаратно на рівні ASIC мережевого адаптера. Щоб комутувати пакети на швидкості лінії й не займати цим процесор хоста, виробники Intel, NVIDIA/Mellanox, Broadcom та Marvell вбудовують у кремній контролерів апаратний комутатор (Embedded eSwitch).

## Принцип роботи та архітектура кремнію

Вбудований комутатор (eSwitch) — це високопродуктивна апаратна схема (ASIC/FPGA), розташована між фізичним оптичним/мідним портом (PHY/MAC) та внутрішньою шиною PCI Express.

Головне завдання eSwitch — апаратно комутувати та фільтрувати мережеві пакети між фізичною лінією (Physical Port), Physical Function (PF) та масивом Virtual Functions (VF) на швидкості каналу (Line Rate 10G/25G/100G+), не залучаючи центральний процесор хоста.

```text
[ Фізична мережева лінія (PHY / MDI) ]
                  │
                  ▼
┌────────────────────────────────────────────────────────┐
│             Embedded eSwitch (ASIC Engine)             │
│  ┌──────────────────────────────────────────────────┐  │
│  │ L2 Lookup Table (MAC / VLAN / Port Filtering)    │  │
│  └──────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────┐  │
│  │ Anti-Spoofing & VLAN Ingress/Egress Engine       │  │
│  └──────────────────────────────────────────────────┘  │
└──────┬──────────────┬──────────────┬─────────────┬─────┘
       │              │              │             │
       ▼              ▼              ▼             ▼
  [ Host PF ]    [ VF 0 Queues ] [ VF 1 Queues ] [ VF N Queues ]
```

## Два класичні режими комутації eSwitch

1. **VEB (Virtual Ethernet Bridge):**
   Режим за замовчуванням у більшості SR-IOV карт. eSwitch працює як традиційний локальний L2-комутатор. Якщо `VF 0` надсилає пакет на MAC-адресу `VF 1`, eSwitch знаходить відповідність у своїй внутрішній MAC-таблиці та передає пакет безпосередньо з Tx-черги `VF 0` в Rx-чергу `VF 1`. Пакет **не виходить** за межі фізичної карти на зовнішній мережевий комутатор.
   - *Перевага:* Мінімальна затримка (субмікросекунди) та відсутність навантаження на зовнішню мережу.
   - *Недолік:* Зовнішні системи виявлення атак (IDS/IPS) або мережевий моніторинг не бачать трафік між ВМ одного сервера.

2. **VEPA (Virtual Ethernet Port Aggregator — IEEE 802.1Qbg):**
   У режимі VEPA локальна комутація всередині картки примусово вимикається. Будь-який пакет від `VF 0` обов'язково відправляється через фізичний порт на зовнішній мережевий комутатор (Physical Switch). Зовнішній комутатор приймає пакет, аналізує його правила безпеки і відправляє назад («петля» / Hairpin turn) на той самий фізичний порт для доставки в `VF 1`.
   - *Перевага:* Повний контроль над трафіком ВМ з боку фізичної мережевої інфраструктури та централізованих фаєрволів.
   - *Недолік:* Подвійне навантаження на фізичну лінію зв'язку та зростання затримки (latency).

## Конвеєр обробки трафіку (Hardware Pipeline)

Кожен кадр проходить апаратним конвеєром за частки мікросекунди:

### Прийом (Ingress Path — з мережі до VF):
1. **Парсер кадру:** Зчитування заголовків L2 (Ethernet), L3 (IP) та L4 (TCP/UDP).
2. **Перевірка тегу VLAN:** Якщо для даної VF налаштовано Port VLAN, eSwitch перевіряє тег 802.1Q. Якщо тег збігається, eSwitch видаляє його (VLAN Strip) перед відправкою у ВМ.
3. **Пошук MAC-адреси:** Карта зіставляє MAC-адресу призначення з таблицею відображення `MAC → VF_ID`.
4. **Вибір черги Rx:** Пакет лягає в апаратне кільце прийому (Rx Descriptor Ring) відповідної VF, і генерується переривання MSI-X у потрібний vCPU.

### Відправка (Egress Path — від VF у мережу):
1. **Перевірка Anti-Spoofing:** eSwitch звіряє вихідний MAC/IP пакета з дозволеними значеннями, виставленими через PF. У разі підробки пакет мовчки скидається (Drop).
2. **Вставка VLAN:** Додавання тегу 802.1Q (VLAN Insert), зафіксованого за цією VF.
3. **Формування швидкості (Tx Rate Limiting / QoS):** Апаратний шейпер (Leaky Bucket / Token Bucket) обмежує пропускну здатність VF згідно з налаштованими лімітами `rate`.

## Апаратні обмеження та класичні пастки

- **Обмежений розмір MAC-таблиці:** Апаратна пам'ять (TCAM або SRAM) чипа eSwitch вміщує фіксовану кількість записів (наприклад, 128 або 512 MAC-адрес). Якщо віртуальна машина спробує підняти всередині себе сотні Docker-контейнерів із власними MAC-адресами, eSwitch вичерпає таблицю і перестане пропускати трафік нових контейнерів.
- **Нерозбірливе приймання (Promiscuous Mode):** Увімкнення `tcpdump` всередині ВМ із SR-IOV за замовчуванням **не покаже** трафік сусідніх ВМ. Вбудований eSwitch ізолює VF на рівні кремнію. Для перехоплення трафіку потрібно явно увімкнути режим `trust on` на PF для даної VF.
