# 📋 Довідник ядерних структур та системних викликів LSM

Цей довідник містить повнотекстову специфікацію інтерфейсів внутрішнього каркасу модулів безпеки Linux (Linux Security Modules, LSM), внутрішньоядерних макросів реєстрації, розподілу пам'яті у спільних блоках контекстів (`security blob`), а також специфікацію системних викликів користувацького простору, запроваджених у ядрі Linux 6.8 для конфліктно-безпечної взаємодії зі стекованими модулями.

## Внутрішньоядерні структури даних (Kernel Space Interface)

### 1. Оголошення модуля: макрос `DEFINE_LSM(name)`

Макрос `DEFINE_LSM` виступає точки входження для кожного статично скомпільованого модуля безпеки в ядрі Linux. Він оголошує екземпляр структури `struct lsm_info` у спеціальній секції ELF двійкового образу ядра `.lsm_info.init`.

```c
#define DEFINE_LSM(lsm) \
	static struct lsm_info __lsm_##lsm \
		__used __section(".lsm_info.init") __aligned(sizeof(unsigned long))
```

Під час завантаження системи підсистема ініціалізації ядра (`do_initcalls`) ітерує по бінарних межах секції `.lsm_info.init`, зчитує конфігураційні прапорці й сортує модулі у відповідності до порядку, заданого параметром завантаження `lsm=` або конфігурацією `CONFIG_LSM`.

Структура `struct lsm_info`:

```c
struct lsm_info {
	const char *name;                /* Унікальне текстове ім'я модуля */
	const struct lsm_id *lsmid;      /* Унікальний ідентифікатор у ядрі */
	int (*init)(void);               /* Вказівник на функцію ініціалізації */
	struct lsm_blob_sizes *blobs;    /* Запитувані розміри блоків пам'яті */
	u32 flags;                       /* Прапорці поведінки модуля (LSM_FLAG_*) */
	int *enabled;                    /* Вказівник на прапор активності */
};
```

### 2. Прапорці модулів LSM (`LSM_FLAG_*`)

Прапорці поведінки контролюють взаємозамінність та пріоритет ініціалізації модулів у стеку.

```c
#define LSM_FLAG_LEGACY_MAJOR	BIT(0)
#define LSM_FLAG_EXCLUSIVE	BIT(1)
```

- `LSM_FLAG_LEGACY_MAJOR`: Позначає класичні «великі» модулі мандатного контролю доступу (SELinux, AppArmor, Smack, TOMOYO). Прапорець зберігається для сумісності зі старими сценаріями моніторингу.
- `LSM_FLAG_EXCLUSIVE`: Вказує на ексклюзивну вимогу щодо контролю за простором мережевих міток або віртуальної файлової системи procfs. До реалізації динамічного стекування атрибутів у Linux 6.8 одночасне включення двох модулів з прапорцем `LSM_FLAG_EXCLUSIVE` блокувалося на етапі стартів ядра.

### 3. Структура ідентифікації: `struct lsm_id`

Починаючи з ядер серії 6.x, кожен модуль безпеки повинен мати унікальний цілочисельний ідентифікатор для розрізнення у користувацькому просторі та в системних викликах.

```c
struct lsm_id {
	const char	*name;
	u64		id;
};
```

Таблиця стабільних ідентифікаторів `LSM_ID_*` (`include/uapi/linux/lsm.h`):

| Константа `LSM_ID_*` | Числове значення | Модуль безпеки |
| :--- | :--- | :--- |
| `LSM_ID_UNDEF` | `0` | Невизначений модуль |
| `LSM_ID_CAPABILITY` | `100` | POSIX Capabilities |
| `LSM_ID_SELINUX` | `101` | Security-Enhanced Linux (SELinux) |
| `LSM_ID_SMACK` | `102` | Simplified Mandatory Access Control (Smack) |
| `LSM_ID_TOMOYO` | `103` | TOMOYO Linux |
| `LSM_ID_APPARMOR` | `104` | AppArmor |
| `LSM_ID_YAMA` | `105` | Yama (ptrace restriction) |
| `LSM_ID_LOADPIN` | `106` | LoadPin |
| `LSM_ID_SAFESETID` | `107` | SafeSetID |
| `LSM_ID_LOCKDOWN` | `108` | Lockdown LSM |
| `LSM_ID_BPF` | `109` | eBPF-LSM |
| `LSM_ID_LANDLOCK` | `110` | Landlock Sandboxing |

### 4. Реєстрація розмірів пам'яті: `struct lsm_blob_sizes`

Для вирішення проблеми конфліктів за єдиний покажчик `void *security` у внутрішніх об'єктах ядра, кожен модуль безпеки реєструє кількість байт, які йому необхідні всередині конкретних структур.

```c
struct lsm_blob_sizes {
	int lbs_cred;
	int lbs_file;
	int lbs_inode;
	int lbs_ipc;
	int lbs_msg_msg;
	int lbs_task;
	int lbs_xattr_count;
	int lbs_key;
	int lbs_sock;
	int lbs_superblock;
};
```

Під час ініціалізації ядро розраховує підсумкові розміри блоків та зберігає динамічні зміщення у глобальних змінних.

Динамічні зміщення у байтах (Offset variables):

```c
extern int lbs_cred_offset;
extern int lbs_file_offset;
extern int lbs_inode_offset;
extern int lbs_ipc_offset;
extern int lbs_msg_msg_offset;
extern int lbs_task_offset;
extern int lbs_sock_offset;
extern int lbs_superblock_offset;
```

Коли модуль звертається до контексту, наприклад, об'єкта `struct file`, він використовує зміщення:

```c
void *my_ctx = file->security + lbs_file_offset;
```

### 5. Структура перехоплення: `struct security_hook_list`

Описує прив'язку конкретної функції-обробника модуля до конкретного гачка в списку `security_hook_heads`.

```c
struct security_hook_list {
	struct hlist_node	list;
	struct hlist_head	*head;
	union lsm_head_funcs	hook;
	const struct lsm_id	*lsmid;
};
```

Обробники додаються до списку за допомогою функції `security_add_hooks()` під час виконання ініціалізатора модуля:

```c
void __init security_add_hooks(struct security_hook_list *hooks,
			       int count,
			       const struct lsm_id *id);
```

## Інтерфейс системних викликів користувацького простору (Linux 6.8+ UAPI)

До версії Linux 6.8 взаємодія з атрибутами LSM виконувалася через файлову систему procfs (`/proc/self/attr/`). У багатошарових середовищах це викликало конфлікти парсингу рядків. У ядрі Linux 6.8 впроваджено три спеціалізовані системні виклики.

### 1. `lsm_list_modules()` — Отримання списку активованих модулів

Повертає масив цілочисельних ідентифікаторів (`u64`) усіх активних у ядрі модулів LSM у порядку їхнього виконання в стеку.

```c
int syscall(__NR_lsm_list_modules, u64 *ids, size_t *size, u32 flags);
```

#### Параметри:
- `ids`: Вказівник на буфер користувацької пам'яті для збереження масиву ідентифікаторів `u64`.
- `size`: Вказівник на розмір буфера. На вході несе розмір переданого масиву в байтах (`sizeof(ids)`). На виході ядро записує фактично необхідну кількість елементів або розмір.
- `flags`: Резервний параметр задел на майбутнє. У поточному ядрі має дорівнювати `0`.

#### Значення, що повертаються:
- `>= 0`: Успіх. Повертає загальну кількість зареєстрованих і записаних модулів у буфер.
- `-E2BIG`: Переданий користувацький буфер занадто малий для вміщення всіх активних модулів. При цьому в `*size` повертається необхідний розмір у байтах.
- `-EFAULT`: Передано недійсний вказівник у просторі користувача.
- `-EINVAL`: Передано некоректні прапорці `flags != 0`.

---

### 2. `lsm_get_self_attr()` — Зчитування атрибутів безпеки поточного процесу

Дозволяє отримати контексти безпеки (мітки, профілі, домени) для поточного процесу від одного або кількох модулів у стеку без конфліктів формату.

```c
int syscall(__NR_lsm_get_self_attr,
            u32 attr,
            struct lsm_ctx *ctx,
            size_t *size,
            u32 flags);
```

#### Параметри:
- `attr`: Описує тип запитуваного атрибута (`LSM_ATTR_*`).
- `ctx`: Вказівник на користувацький буфер пам'яті для розміщення однієї або кількох структур `struct lsm_ctx`.
- `size`: На вході — розмір буфера `ctx` у байтах; на виході — розмір фактично записаних даних.
- `flags`: Прапорці фільтрації. При вказанні `LSM_FLAG_SINGLE` запит здійснюється лише для першого модуля в `ctx`, чий `id` збігається із запитаним.

Константи типів атрибутів `LSM_ATTR_*` (`include/uapi/linux/lsm.h`):

| Атрибут `LSM_ATTR_*` | Значення | Опис |
| :--- | :--- | :--- |
| `LSM_ATTR_UNDEF` | `0` | Невизначений атрибут |
| `LSM_ATTR_CURRENT` | `1` | Поточний контекст процесу (аналог `/proc/self/attr/current`) |
| `LSM_ATTR_EXEC` | `2` | Контекст, що застосується при наступному `execve()` |
| `LSM_ATTR_FSCREATE` | `3` | Контекст для новостворюваних файлів |
| `LSM_ATTR_KEYCREATE` | `4` | Контекст для новостворюваних ключів у keyring |
| `LSM_ATTR_SOCKCREATE` | `5` | Контекст для новостворюваних сокетів |

Структура відгуку `struct lsm_ctx`:

```c
struct lsm_ctx {
	u64 id;         /* Ідентифікатор модуля LSM_ID_* */
	u64 flags;      /* Атрибутивні прапорці відгуку */
	size_t len;     /* Загальний розмір цієї структури разом із даними ctx[] */
	size_t ctx_len; /* Фактична довжина рядка контексту у байтах */
	u8 ctx[];       /* Динамічний масив: нуль-термінований рядок (наприклад "unconfined_t") */
};
```

---

### 3. `lsm_set_self_attr()` — Встановлення атрибутів безпеки

Використовується прикладними програмами та ізоляторами (наприклад, `systemd`, `containerd`) для переходу в новий профіль або обмеження власних привілеїв перед виконанням `execve()`.

```c
int syscall(__NR_lsm_set_self_attr,
            u32 attr,
            struct lsm_ctx *ctx,
            size_t size,
            u32 flags);
```

#### Параметри:
- `attr`: Цільовий атрибут (`LSM_ATTR_CURRENT`, `LSM_ATTR_EXEC` тощо).
- `ctx`: Передана структура `struct lsm_ctx`, яка містить `id` цільового модуля LSM та новий рядок контексту у полі `ctx[]`.
- `size`: Розмір переданої структури `ctx` у байтах.
- `flags`: Модифікатори виконання.

#### Значення, що повертаються:
- `0`: Контекст успішно змінено.
- `-EINVAL`: Передано неприпустимий атрибут, пошкоджену структуру `lsm_ctx` або розмір `len` не відповідає дійсній довжині рядка `ctx_len`.
- `-EPERM`: Модуль LSM відмовив у зміні контексту (наприклад, політика забороняє перехід у запитаний профіль).
- `-EOPNOTSUPP`: Вказаний модуль LSM не підтримує динамічну зміну атрибутів у просторі користувача.

## Інтерфейс у віртуальній файловій системі sysfs

Окрім системних викликів, ядро надає текстовий інтерфейс інспектування у sysfs за шляхом `/sys/kernel/security/lsm`.

Приклад зчитування стану:

```bash
$ cat /sys/kernel/security/lsm
lockdown,yama,loadpin,safesetid,integrity,apparmor,bpf,landlock
```

Файл повертає рядок із назвами всіх зареєстрованих модулів у тому порядку, в якому вони розміщені у списку виконання `security_hook_heads`. Перший модуль у списку отримує управління першим, останнім виконується модуль у кінці рядка.
