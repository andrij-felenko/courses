# 📋 Інтерфейс та структура файлів у `/proc/[pid]/` та `/etc/subuid`

Налаштування та інспектування User Namespaces виконується через спеціальні псевдофайли у файловій системі `procfs` та системні конфігураційні файли підпорядкованих ідентифікаторів.

## Псевдофайли у `/proc/[pid]/`

Підсистема `procfs` надає інтерфейси керування простором імен користувача для кожного конкретного процесу. Робота з цими файлами вимагає суворого дотримання послідовності викликів та формату даних.

### 1. `/proc/[pid]/uid_map` та `/proc/[pid]/gid_map`

Файли задають правила мапінгу ідентифікаторів між внутрішнім user namespace цільового процесу та батьківським простором імен.

#### Формат запису

Файл містить від 1 до 340 рядків (у ядрах до Linux 4.15 — не більш ніж 5 рядків). Кожен рядок має три поля:

```text
ID_inside   ID_outside   count
```

Поля розділяються пробілами або символами табуляції:
- `ID_inside` — початковий UID/GID усередині цільового простору імен.
- `ID_outside` — початковий UID/GID у батьківському просторі імен (або на хості).
- `count` — кількість послідовних ідентифікаторів у діапазоні (`count >= 1`).

#### Внутрішні механізми ядра та обробники procfs

Усередині ядра Linux запис у ці файли обробляється функціями `proc_uid_map_write()` та `proc_gid_map_write()`, які визначені у коді `kernel/user_namespace.c`. Коли процес виконує системний виклик `write(2)` на відкритому дескрипторі псевдофайлу `/proc/[pid]/uid_map`, ядро розбирає текст рядок за рядком просто в обробнику `map_write()` і будує тимчасовий масив екстентів `struct uid_gid_map`.

Після зчитування всіх екстентів ядро здійснює глобальну перевірку цілісності та атомарно замінює вказівник мапінгу в об'єкті `struct user_namespace`.

#### Правила та обмеження запису

1. **Однократність запису**: У файл можна записати дані **лише один раз**. Після першого успішного запису ядро встановлює прапорець незмінності. Відкрити файл на запис можна й далі, а от повторний `write()` повертає помилку `EPERM`.
2. **Права на файл**: Запис дозволений лише процесу, який має привілеї `CAP_SETUID` (або `CAP_SETGID`) у батьківському просторі імен, або самостійно створив цей user namespace.
3. **Обмеження непривілейованого запису**:
   - Якщо процес НЕ має `CAP_SETUID` у батьківському просторі імен, він може записати **лише 1 рядок**, у якому `ID_outside` дорівнює його власній ефективній UID.
   - Спроба записати діапазон `count > 1` або інший `ID_outside` непривілейованим процесом повертає `EPERM`.

### 2. `/proc/[pid]/setgroups`

Файл керує можливістю виклику системного виклику `setgroups(2)` усередині нового простору імен груп (GID).

#### Формат та значення

Файл містить один із двох текстових рядків:

```text
allow   # Виклик setgroups(2) дозволено — стан за замовчуванням у новоствореному просторі
deny    # Виклик setgroups(2) назавжди заблоковано в цьому namespace та нащадках
```

#### Обробка виклику setgroups у ядрі

Внутрішня функція ядра `proc_setgroups_write()` приймає лише точні рядки `"allow"` або `"deny"`. Якщо у файл записано `"deny"`, ядро встановлює внутрішній прапорець `USERNS_SETGROUPS_ALLOWED` у стан `0`. Після цього будь-яка спроба процесу всередині даного user namespace викликати `setgroups(2)` миттєво повертатиме помилку `EPERM`.

#### Вимога безпеки для gid_map

Якщо непривілейований процес бажає налаштувати `/proc/[pid]/gid_map`, ядро **вимагає**, щоб у файл `/proc/[pid]/setgroups` попередньо було записано значення `"deny"`.

Спроба запису в `gid_map` без блокування `setgroups` поверне помилку `EPERM`. Це запобігає атакам із використанням негативних прав груп.

---

### 3. `/proc/[pid]/projid_map`

Файл задає відображення ідентифікаторів проектів (Project IDs), які використовуються для дискових квот у файлових системах XFS та ext4. Формат запису повністю аналогічний `uid_map`. Обробка виконується функцією `proc_projid_map_write()`.

## Системні файли підпорядкованих ідентифікаторів

Для реалізації rootless контейнеризації використовується конфігурація підпорядкованих ідентифікаторів у каталозі `/etc/`.

### 1. `/etc/subuid` та `/etc/subgid`

Файли визначають діапазони UID та GID, якими адміністратор хоста дозволяє розпоряджатися конкретним звичайним користувачам для створення rootless контейнерів.

#### Формат рядка

```text
username:start_id:count
```

Приклад змісту `/etc/subuid`:

```text
alice:100000:65536
bob:165536:65536
```

Опис полів:
- `username` — ім'я користувача на хості або його числовий UID;
- `start_id` — початковий хостовий UID/GID виділеного діапазону;
- `count` — розмір виділеного блоку ідентифікаторів (типово 65536 для підтримки 16-бітних системних UID).

Правила доступу та адміністрування файлів `/etc/subuid` та `/etc/subgid`:
- Файли належать користувачеві `root` і мають права `0644` (`rw-r--r--`): читати їх може будь-хто, а змінювати — лише `root`.
- Модифікувати файли мають право утиліти `usermod`, `useradd` або безпосередньо системний адміністратор.
- Парсинг файлу виконується бібліотекою `libsubid`, яка входить до складу пакунка `shadow`.

## Протокол утиліт-хелперів `newuidmap` та `newgidmap`

Оскільки непривілейований процес не може самостійно записати у `/proc/[pid]/uid_map` діапазон із `/etc/subuid` (через обмеження ядра), використовуються утиліти `newuidmap` та `newgidmap`, що мають встановлений біт `setuid` (`owner root`).

### Сигнатура виклику

```bash
newuidmap PID ns-uid host-uid count [ns-uid2 host-uid2 count2 ...]
newgidmap PID ns-gid host-gid count [ns-gid2 host-gid2 count2 ...]
```

Параметри виклику:
- `PID` — ідентифікатор цільового процесу, для якого налаштовується мапінг;
- `ns-uid` — початковий внутрішній UID усередині простору імен;
- `host-uid` — початковий зовнішній UID на хості;
- `count` — кількість ідентифікаторів у екстенті.

### Детальна послідовність дій утиліти `newuidmap`

1. Зчитує реальний UID викликаючого процесу за допомогою системного виклику `getuid()`.
2. Відкриває та аналізує файл `/etc/subuid`, шукаючи всі записи, що належать даному реальному користувачеві.
3. Перевіряє кожного переданого з командного рядка екстенту:
   - Якщо `host-uid == real_uid` і `count == 1`, запис дозволяється (це прямий мапінг самого користувача).
   - Якщо діапазон `[host-uid, host-uid + count - 1]` повністю лежить усередині одного з виділених у `/etc/subuid` блоків, запис дозволяється.
   - Якщо бодай один ідентифікатор виходить за межі дозволеного в `/etc/subuid`, утиліта скасовує операцію.
4. Якщо всі перевірки пройшли успішно, утиліта відкриває `/proc/PID/uid_map` і від імені `root` записує вказаний мапінг у псевдофайл.
5. У разі помилки `newuidmap` виводить розлогі деталі в `stderr` і завершує роботу з кодом `1`.

## Параметри ядра (sysctl)

Керування функціоналом User Namespaces на рівні всієї системи здійснюється через псевдофайли у піддереві `/proc/sys/`:

| Шлях sysctl | Опис та значення за умовчанням |
| :--- | :--- |
| `/proc/sys/user/max_user_namespaces` | Максимальна кількість user namespaces, яка може існувати у системі. Значення `0` повністю вимикає створення нових просторів. |
| `/proc/sys/kernel/unprivileged_userns_clone` | Патч дистрибутивів (RHEL/Debian). Значення `1` дозволяє непривілейованим користувачам викликати `unshare(CLONE_NEWUSER)`, `0` — забороняє. |
| `/proc/sys/kernel/apparmor_restrict_unprivileged_userns` | Механізм Ubuntu 24.04+. Значення `1` дозволяє userns тільки для додатків з явним профілем AppArmor. |

## Коди помилок ядра при роботі з мапінгом

| Код помилки | Причина виклику |
| :--- | :--- |
| `EPERM` | Спроба повторного запису у `uid_map`/`gid_map`, відсутність `deny` у `setgroups` при непривілейованому записі `gid_map`, або відсутність `CAP_SETUID` у батьківському просторі. |
| `EINVAL` | Некоректний синтаксис запису, вихід за межі типів (`uid_t`), або неперетинні екстенти перетинаються. |
| `EACCES` | Недостатньо прав на відкриття псевдофайлу `/proc/[pid]/uid_map` на запис. |
| `EOVERFLOW` | Стосується не мапінгу, а старих 16-бітних варіантів `stat`: значення не влазить у поле структури. Невідображений хостовий UID помилки не дає — `stat(2)` просто показує `overflowuid` (65534), а `getuid(2)` не може завершитися помилкою взагалі. |
| `ESRCH` | Процес із вказаним `PID` не існує або вже завершив виконання. |
