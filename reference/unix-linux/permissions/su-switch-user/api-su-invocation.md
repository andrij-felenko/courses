# 📋 Контракт su: ключі, оточення, коди виходу

Це довідка на все, що `su` бере на вході й лишає по собі: повний перелік ключів, точний склад оточення в кожному з режимів, налаштування з `/etc/login.defs`, файли PAM і те, що команда повертає викликачеві. Опис — за реалізацією з **util-linux** (гілка 2.4x), тією, що стоїть у Linux-дистрибутивах; чим від неї відрізняються інші, зібрано наприкінці.

Довідка потрібна окремою з простої причини: майже кожен ключ тут міняє не поведінку самої `su`, а обстановку, у якій згодом працюватиме чужа програма. Хибно вибраний ключ не викликає скарги. Він виявляється через кілька команд, коли щось знайшлося не там, де ви думали, або не знайшлося зовсім.

## Виклик

```
su [опції] [-] [користувач [аргумент…]]
```

Без імені ціль — `root`. Аргументи після імені передаються **запущеній оболонці**, а не вашій команді: коли поруч стоїть `-c`, спрацьовує звичайне правило `sh -c КОМАНДА [ім'я [аргумент…]]`, за яким перший додатковий аргумент стає `$0` оболонки, другий — `$1`, і так далі.

| Ключ | Що робить |
|---|---|
| `-`, `-l`, `--login` | вхідний режим: чистка оточення, ініціалізація змінних, перехід у домівку цілі, дефіс у `argv[0]` оболонки |
| `-c`, `--command=КОМАНДА` | віддати рядок оболонці цілі її власним ключем `-c`; додатково заводить [новий сеанс](book:unix-linux/sessions-and-process-groups) через `setsid(2)` |
| `--session-command=КОМАНДА` | те саме без `setsid(2)`; у самій довідці позначене як небажане |
| `-s`, `--shell=ОБОЛОНКА` | запустити вказану оболонку замість типової |
| `-m`, `-p`, `--preserve-environment` | не ставити `HOME`, `SHELL`, `USER`, `LOGNAME` — оточення переходить як є |
| `-P`, `--pty` | видати сеансові окремий [псевдотермінал](book:unix-linux/pseudo-terminal); `su` стає посередником між ним і вашим терміналом і синхронізує потоки |
| `-T`, `--no-pty` | протилежне до `--pty` |
| `-w`, `--whitelist-environment=СПИСОК` | не витирати перелічені через кому змінні при чистці |
| `-g`, `--group=ГРУПА` | задати основну групу; **лише для root** |
| `-G`, `--supp-group=ГРУПА` | додати додаткову групу; **лише для root**; перша така стає й основною, якщо `-g` не задано |
| `-f`, `--fast` | передати оболонці її ключ `-f` (має сенс для `csh`/`tcsh`) |
| `-h`, `--help` · `-V`, `--version` | довідка й версія |

Обмеження на `-g`/`-G` не косметичне: групи задають доступ, а `su` перевіряє знання пароля цілі — якби ключі були відкриті всім, кожен, хто знає один пароль, дописував би собі будь-яке членство понад те, що записане в базі.

Білий список `-w` **не діє** на `HOME`, `SHELL`, `USER`, `LOGNAME` і `PATH`: ці п'ять `su` ставить сама. Типове застосування — протягнути `SSH_AUTH_SOCK` чи `http_proxy`; змінні, що керують [пошуком бібліотек](book:unix-linux/library-search-order), не протягують ніколи, бо у бік підвищення прав це готова дірка.

Сама `su` дивиться на дві власні змінні: `SU_DEBUG=all` вмикає її налагоджувальний вивід, `ULPTY_DEBUG=all` — вивід шару псевдотермінала.

## Оточення: що ставиться в кожному режимі

| Що | Типово (без тире) | `-`, `-l` | `-m`, `-p` |
|---|---|---|---|
| решта успадкованих змінних | переходять усі | **витираються**, лишаються `TERM`, `COLORTERM`, `NO_COLOR` і те, що внесене через `-w` | переходять усі |
| `HOME` | домівка цілі | домівка цілі | ваш, без змін |
| `SHELL` | оболонка цілі | оболонка цілі | ваш, без змін |
| `USER`, `LOGNAME` | ставляться, **лише якщо ціль — не root** | ставляться завжди | ваші, без змін |
| `PATH` | ваш; складається наново тільки при `ALWAYS_SET_PATH=yes` | складається з `login.defs` | ваш, без змін |
| поточна тека | ваша | домівка цілі | ваша |
| `argv[0]` оболонки | ім'я оболонки | ім'я **з дефісом попереду** | ім'я оболонки |

Два режими взаємно виключні, і це перевіряється явно: якщо задати `-l` і `-m` разом, `su` попереджає, що ігнорує `--preserve-environment`, і працює як вхідна. Пари «трохи вхідний режим» не існує.

![Дві драбини правил поруч: ліворуч порядок вибору оболонки — ключ --shell, змінна SHELL при -m, оболонка цілі з бази облікових записів, /bin/sh; праворуч порядок вибору PATH — -m лишає ваш, -l бере з login.defs, інакше вирішує ALWAYS_SET_PATH](/reference/unix-linux/permissions/su-switch-user/img/su-shell-and-path.svg)

*Обидва вибори мовчазні: жодне з правил не повідомляє, що спрацювало саме воно.*

Ліва драбина має ще одну умову, не видну з ключів. Якщо оболонки цілі немає в `/etc/shells`, вона вважається обмеженою — і тоді для всіх, крім root, `--shell` та змінна `SHELL` просто ігноруються. Так адміністратор, що видав службовому запису `/usr/sbin/nologin`, дістає гарантію: обійти цей рядок підстановкою іншої оболонки не вийде.

## Ключі `/etc/login.defs`c

Загальний файл — `/etc/login.defs`, і той самий набір ключів можна перекрити для однієї команди у `/etc/default/su` (для `runuser` — у `/etc/default/runuser`).

| Ключ | Значення |
|---|---|
| `ALWAYS_SET_PATH` | `yes` — складати `PATH` навіть тоді, коли не задано ні `--login`, ні `--preserve-environment` |
| `ENV_PATH` | `PATH` для звичайного користувача; типово `/usr/local/bin:/bin:/usr/bin` |
| `ENV_ROOTPATH`, `ENV_SUPATH` | `PATH` для цілі root; `ENV_SUPATH` має перевагу |
| `FAIL_DELAY` | пауза в секундах після невдалої автентифікації, невід'ємне ціле |

`FAIL_DELAY` — єдиний ключ у цьому переліку, що стосується не оточення, а перебору паролів: без паузи темп спроб обмежувала б лише швидкість машини.

## Файли PAM

`su` не має власного файлу політики, тож усе, що можна вирішити **до** запуску, вирішується в [стеку PAM](book:unix-linux/pam-stack).

| Файл | Коли береться |
|---|---|
| `/etc/pam.d/su` | звичайний запуск |
| `/etc/pam.d/su-l` | запуск із `-`/`-l`/`--login` |
| `/etc/pam.d/runuser` | звичайний запуск `runuser` |
| `/etc/pam.d/runuser-l` | `runuser` із `--login` |

Розділення на чотири файли існує рівно для того, щоб вимоги різнилися: вхідний режим схожий на справжній вхід і часто тягне за собою модулі сеансу (домівка, ліміти, `pam_loginuid`), а разова команда — ні. Чим саме `su-l` відрізняється від `su`, вирішує дистрибутив; часто це просто включення `su` без жодного власного рядка, і файл тримають окремо про запас.

## Код виходу й сигнали

| Що повернула `su` | Що це означає |
|---|---|
| код дитини (0–255) | звичайний випадок: `su` віддає те, що віддала оболонка чи команда |
| `1` | помилка самої `su` до запуску: невідоме ім'я, хибний пароль, відмова PAM |
| `126` | програму знайдено, але запустити не вдалося |
| `127` | програми не знайдено |
| `128 + N` | дитину вбив сигнал з номером N |

Код `1` — місце, де довідка закінчується, а обережність починається. Він однаково означає «пароль не той» і «команда чесно виконалася й повернула невдачу»; за самим числом ці випадки не розрізняються. У скриптах саме тому й беруть `runuser`: не через зручність, а тому що там немає гілки з паролем, і `1` лишається одним-єдиним видом невдачі.

Сигнали `SIGINT`, `SIGQUIT` і `SIGTERM` `su` не пропускає повз себе: діставши будь-який з них, вона вбиває дитину, а потім **убиває тим самим сигналом себе**. Викликач бачить не число, а загибель від сигналу — його оболонка перекладе це в `128+N` за звичайним правилом [коду виходу](book:unix-linux/exit-status), а програма, що чекає через `wait()`, розрізнить обидва випадки чесно. Прибирання дитини тут не ввічливість: батько тримає відкритий сеанс PAM і мусить дожити до його закриття.

## Мінімальний робочий виклик

```sh
# чи справний службовий запис: пароль, домівка, оболонка — усе за один раз
$ su - postgres -c 'id -un; pwd; echo "$0"'
Password:
postgres
/var/lib/postgresql
-bash

# що саме дістанеться службі: вхідне оточення видно цілком
$ su - postgres -c env | sort

# те саме без пароля, з-під root, для скрипта: інший стек PAM, той самий код
# runuser -l postgres -c 'pg_isready'
```

Дефіс у виводі `$0` — не оформлення: це і є той прийом, за яким оболонка розпізнає себе вхідною.

## Розбіжності реалізацій

| Реалізація | Стан і чим відрізняється |
|---|---|
| **util-linux** | усе описане вище; єдина, де є `--pty`, `-w`, `-g`/`-G` і окремі стеки PAM для вхідного режиму |
| **shadow** | історична гілка, ще жива в частині систем; ключів `--pty`, `-w`, `-g`/`-G` немає, зате в `login.defs` свій набір: `SU_NAME`, `SULOG_FILE`, `SU_WHEEL_ONLY`, `SYSLOG_SU_ENAB`, `CONSOLE`, `ENV_HZ`, `ENV_TZ` |
| **GNU coreutils** | більше не існує: типово не встановлювалася з випуску 6.9.90 (1 грудня 2007), а у 8.23 (18 липня 2014) її прибрали з дерева — з поясненням, що util-linux зібрав докупи патчі Suse і Fedora й потреби тримати другу копію немає |
| **busybox** | `su [-] [-m|-p] [-c КОМАНДА] [-s ОБОЛОНКА] [користувач]` — і все: ні псевдотермінала, ні білого списку, ні груп |

`runuser` у цьому переліку не окрема програма, а та сама з іншими типовими значеннями: `setuid`-біта на файлі немає, автентифікації немає взагалі (тому й користуватися нею може лише root), а стек PAM свій — розрахований на те, що живої людини за терміналом немає. Її код походить від тієї самої `su` з coreutils, яку GNU у себе прибрала: спершу як патч Fedora від Дена Волша, потім — у складі util-linux.
