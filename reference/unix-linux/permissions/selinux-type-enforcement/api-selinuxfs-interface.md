# 📋 Низькорівневий інтерфейс selinuxfs та виклики libselinux

Цей довідник містить детальний технічний опис програмних інтерфейсів взаємодії між ядром Linux та простором користувача через віртуальну файлову систему `selinuxfs` (зазвичай змонтовану за шляхом `/sys/fs/selinux`), а також повний контракт низькорівневих викликів системної бібліотеки `libselinux`.

## 1. Архітектура та внутрішні механізми файлової системи `selinuxfs`

Ядро Linux експортує поточний стан підсистеми SELinux у простір користувача через спеціалізовану віртуальну файлову систему `selinuxfs`. Вона ініціалізується під час завантаження ядра у коді `security/selinux/selinuxfs.c` і реєструється у VFS з магічним константним значенням `SELINUX_MAGIC = 0xf97cff8c`. У сучасних системних конфігураціях менеджер служб systemd або ініціалізаційні скрипти монтують її за стандартним абсолютним шляхом `/sys/fs/selinux`.

Файлова система `selinuxfs` не має фізичного носія на дискових накопичувачах. Усі файли та каталоги у цьому дереві є віртуальними точками входу, за якими стоять внутрішні функції обробки VFS. Коли процес простору користувача виконує системні виклики `read()`, `write()`, `open()` або `mmap()` над файлами у `/sys/fs/selinux`, VFS передає управління безпосередньо у Security Server ядра.

Нижче наведено докладний розбір керуючих файлів та каталогів `selinuxfs`:

| Файл / Каталог | Права доступу | Опис та внутрішній механізм ядра |
| :--- | :--- | :--- |
| `/sys/fs/selinux/enforce` | `rw-r--r--` | Перемикач режиму виконання. Зчитування повертає символ `1` (Enforcing) або `0` (Permissive). Запис символу `1` або `0` динамічно перемикає режим захисту ядра у реальному часі. Якщо політика була завантажена з прапорцем `secure_mode`, подальший запис у цей файл блокується ядром до перезавантаження. |
| `/sys/fs/selinux/load` | `-w-------` | Бінарний прийомач політики. Утиліти простору користувача (такі як `semodule` або `init`) відкривають цей файл на запис і передають суцільний бінарний блок скомпільованої політики (формат `policy.33`). Запис викликає внутрішню функцію ядра `security_load_policy()`, яка повністю перебудовує внутрішні таблиці рішень Security Server. |
| `/sys/fs/selinux/access` | `rw-rw-rw-` | Повільний інтерфейс обчислення прав. Процеси простору користувача можуть записати в цей файл рядок формату `scontext tcontext tclass requested_permissions`, а наступний виклик `read()` поверне обчислений вектор векторів доступу (allowed, auditallow, dontaudit, seqno). |
| `/sys/fs/selinux/context` | `rw-rw-rw-` | Канонізація та перевірка контекстів. Запис рядка контексту повертає його канонічну форму або виклик повертає помилку `EINVAL`, якщо тип, роль чи користувач відсутні у завантаженій політиці. |
| `/sys/fs/selinux/status` | `r--r--r--` | Сторінка швидкого моніторингу стану через `mmap()`. Містить структуру `struct selinux_status_t` з номером послідовності (`sequence number`). Дозволяє утилітам простору користувача дізнатися про факт перезавантаження політики без виконання системного виклику. |
| `/sys/fs/selinux/checkreqprot` | `rw-r--r--` | Перемикач перевірки захисту пам'яті. Визначає, чи перевіряє SELinux оригінальні запрошені права привілеїв пам'яті `mmap`/`mprotect` (`1`), чи кінцеві права, виправлені ядрами через події W^X (`0`). На сучасних ядрах Linux цей прапорець зафіксований у `0`. |
| `/sys/fs/selinux/deny_unknown` | `r--r--r--` | Поведінка щодо невідомих дозволів. Повертає `0` (дозволяти невідомі прапорці нових ядер) або `1` (забороняти будь-які невідомі у політиці біти прав). |
| `/sys/fs/selinux/policyvers` | `r--r--r--` | Версія бінарного формату політики, яку підтримує поточне ядро (наприклад, `33`). |
| `/sys/fs/selinux/booleans/` | `dr-xr-xr-x` | Каталог поточних перемикачів. Кожен файл у каталозі відповідає імені булевої змінної (наприклад, `httpd_can_network_connect`). Текст містить два числа: поточне значення та заплановане значення після релабелінгу. |
| `/sys/fs/selinux/avc/` | `dr-xr-xr-x` | Статистика кешу AVC: `hash_stats` (розподіл колізій по кошиках), `cache_stats` (кількість hits, misses, allocations, reclaims, lookups). |

Кожен із зазначених файлів відіграє роль низькорівневого містка. Наприклад, файл `/sys/fs/selinux/status` був доданий у ядрі Linux 2.6.37 для вирішення критичної проблеми продуктивності. До його появи графічні оболонки та мережеві демони були змушені викликати системний виклик `read()` для `/sys/fs/selinux/enforce` або `/sys/fs/selinux/policyvers` тисячі разів на секунду, щоб дізнатися, чи не змінилася політика безпеки. Спеціалізована сторінка статусу дозволяє відвідобразити структуру `struct selinux_status_t` у простір пам'яті процесу за допомогою `mmap()`. Зчитування послідовного номера `sequence number` виконується повністю в узерспейсі за допомогою атомарних операцій CPU без жодного контекстного перемикання у ядро.

Файл `/sys/fs/selinux/load` приймає суцільний масив байтів. Коли демон `semodule` записує новий файл бінарної політики, ядро виділяє тимчасовий блок пам'яті `vmalloc()`, зчитує вміст, виконує синтаксичну перевірку та валідацію всіх типів і замін, після чого атомарно замінює вказівник на активну політику Security Server. Усі існуючі записи в кеші AVC негайно інвалідуються шляхом збільшення системного лічильника послідовності політики.

Каталог `/sys/fs/selinux/booleans/` створюється динамічно під час завантаження політики. Для кожної булевої змінної, оголошеної у політиці, ядро створює окремий віртуальний файл. Зчитування файла повертає два цілих числа: поточний активний стан змінної у ядрі та заплановане значення, яке набере чинності при наступному записі у файл `/sys/fs/selinux/commit_pending_booleans`.

Окрім VFS-інтерфейсів, ядро реалізує сокет сповіщень `NETLINK_SELINUX`. Коли режим системи перемикається з Enforcing у Permissive або завантажується новий модуль політики, ядро надсилає броадкаст-повідомлення по сокету Netlink. Програми простору користувача, які підписалися на цей сокет, негайно отримують сповіщення і скидають власні внутрішні кеші прав без необхідності періодичного опитування файлів.

Слід підкреслити, що прямо працювати з VFS-файлами `/sys/fs/selinux` прикладним програмам не рекомендується. Використання файлового вводу-виводу для зчитування контекстів потребує форматирования рядків та обробки помилок розбору, що ускладнює код. Замість цього розробники повинні використовувати стандартну системну бібліотеку `libselinux`, яка надає стабільний ABI та обробляє всі особливості системних викликів ядра.

Завдяки впровадженню `selinuxfs` системні адміни та автоматизовані скрипти моніторингу дістали можливість прозоро інспектувати стан мандатної системи безпеки звичайними консольними утилітами на кшталт `cat`, `grep` або `stat`, без використання вузькоспеціалізованих бінарних інструментів розбору.

## 2. Програмний контракт та функції `libselinux`

Системна бібліотека `libselinux` надає зручний високоуровневий C/C++ API над інтерфейсами `selinuxfs` та розширеними атрибутами файлових систем. Вона приховує низькорівневі деталі форматування рядків та парсингу файлів системного моніторингу. Основні заголовні файли розташовані за шляхами `<selinux/selinux.h>`, `<selinux/avc.h>` та `<selinux/label.h>`.

### 2.1. Перевірка стану підсистеми безпеки

Функції перевірки стану дозволяють програмам визначати, чи активовано захист SELinux у поточній операційній системі, і в якому режимі працює ядро:

- `int is_selinux_enabled(void);`
  Виконує перевірку наявності точки монтування `selinuxfs` та активності підсистеми у ядрі. Повертає `1` якщо SELinux увімкнено, `0` якщо вимкнено, або `-1` при виникненні помилки доступу до файлової системи VFS.
- `int security_getenforce(void);`
  Зчитує поточний стан із файла `/sys/fs/selinux/enforce`. Повертає `1` для режиму Enforcing (суворе блокування), `0` для режиму Permissive (лише аудит відмов), або `-1` при помилці.
- `int security_setenforce(int value);`
  Намагається записати значення `value` (`0` або `1`) у файл `/sys/fs/selinux/enforce`. Успішне виконання вимагає наявності привілеїв суперкористувача (`CAP_MAC_ADMIN`) та відповідного дозволу `setenforce` у завантаженій політиці.

### 2.2. Управління контекстами процесів та файлів

Функції цієї групи забезпечують читання та встановлення контекстів безпеки для поточних або сторонніх процесів, а також для об'єктів файлової системи:

- `int getcon(char **con);`
  Отримує Security Context поточного процесу шляхом зчитування файлу `/proc/self/attr/current`. Переданий вказівник `*con` ініціалізується адресою динамічно виділеного блоку пам'яті через виклик `malloc()`. Викликаюча сторона зобов'язана звільнити цю пам'ять за допомогою спеціалізованої функції `freecon(*con)`.
- `int getcon_raw(char **con);`
  Аналог `getcon()`, який повертає сирий рядок контексту без виконання автоматичного транслятора MCS-категорій через демон `mcstransd`.
- `int setcon(const char *con);`
  Запитує зміну контексту поточного процесу (записує новий рядок у `/proc/self/attr/current`). Цей виклик широко використовується демонами ініціалізації перед запуском робочих процесів для пониження привілеїв та переходу у цільовий домен.
- `int getfilecon(const char *path, char **con);`
  Зчитує контекст файлу за вказаним шляхом `path` через виклик VFS `getxattr()` для розширеного атрибута `security.selinux`.
- `int fgetfilecon(int fd, char **con);`
  Отримує контекст файлу через вже відкритий файловий дескриптор `fd` за допомогою виклику `fgetxattr()`.
- `int setfilecon(const char *path, const char *con);`
  Встановлює новий контекст безпеки для файлу на диску шляхом виклику `setxattr()`.

Важливе застереження щодо пам'яті: функції `getcon()`, `getfilecon()` та `fgetfilecon()` використовують нестандартний спосіб повернення результату через подвійний вказівник `char **con`. Пам'ять для буфера роздрукованого контексту виділяється у внутрішніх функціях бібліотеки за допомогою `malloc()`. Використання стандартного `free()` замість спеціалізованого `freecon()` є помилкою, оскільки у деяких збірках `libselinux` використовується власний алокатор пам'яті, і невідповідний виклик `free()` спричинить пошкодження кучі (heap corruption).

### 2.3. Юзерспейсний AVC та перевірка прав в додатках (Userspace AVC)

Окрім кешування в ядрі, бібліотека `libselinux` надає повноцінний користувацький кеш векторів доступу (Userspace AVC), оголошений у `<selinux/avc.h>`. Він застосовується у привілейованих демонах (наприклад, DBus, X11, systemd або sudo), які самостійно виконують функції розмежування доступу між клієнтами.

- `int avc_init(const char *msgprefix, const struct avc_memory_callback *mem_callbacks, const struct avc_log_callback *log_callbacks, const struct avc_thread_callback *thread_callbacks, const struct avc_lock_callback *lock_callbacks);`
  Ініціалізує користувацький AVC кеш у пам'яті процесу.
- `int selinux_check_access(const char *scon, const char *tcon, const char *tclass, const char *perm, void *aux);`
  Перевіряє, чи має суб'єкт із контекстом `scon` право виконати дію `perm` над об'єктом класу `tclass` із контекстом `tcon`. Повертає `0` у разі дозволу або `-1` при відмові.

Для забезпечення потокобезпечності у багатопотокових середовищах C++ розробники передають функції зворотного виклику для захоплення м'ютексів через `lock_callbacks`. Викликаючи `selinux_check_access()`, узерспейсний демон запитує ядро через `/sys/fs/selinux/access` лише при першому зверненні, після чого відповідь зберігається у локальній пам'яті процесу.

### 2.4. Визначення та валідація контекстів за базами даних

Система та додатки часто потребують дізнатися, який контекст повинен мати новий файл ще до його фактичного створення на диску. Для цього використовується підсистема сорсингу контекстів:

- `struct selabel_handle *selabel_open(unsigned int backend, const struct selinux_opt *opts, unsigned nopts);`
  Відкриває базу даних контекстів (наприклад, прапорець `SELABEL_CTX_FILE` підключає базу контекстів файлової системи).
- `int selabel_lookup(struct selabel_handle *rec, char **con, const char *key, int type);`
  Здійснює пошук еталонного контексту для шляху `key` за правилами регулярних виразів, завантаженими з файлів конфігурації `/etc/selinux/targeted/contexts/files/file_contexts`.
- `void selabel_close(struct selabel_handle *rec);`
  Закриває дескриптор та звільняє виділені ресурси бази даних контекстів.

При виконанні `selabel_lookup()` бібліотека компілює регулярні вирази з файлу `file_contexts.bin` у структуру тривіального префіксного дерева (trie). Це забезпечує пошук відповідного контексту за `O(K)` кроків, де `K` — довжина шляху до файлу, незалежно від загальної кількості правил у системній базі даних (яких може бути понад 20 000).

Використання `selabel_lookup()` є обов'язковим для системних утиліт монтажу та розпакування (таких як `tar`, `rpm`, `dpkg`). Коли інсталятор розпаковує новий файл у системний каталог, він запитує еталонний контекст через `selabel_lookup()` і встановлює його через `lsetfilecon()`. Це гарантує, що нові файли отримають правильні типи безпеки одразу при їх появі у системі.

### 2.5. Помилки системних викликів та їхнє значення

При виконанні системних викликів бібліотеки `libselinux` або прямих VFS-операцій ядро Linux може повертати спеціалізовані коди помилок через глобальну змінну `errno`. Правильна розшифровка цих кодів є критичною для траблшутингу:

| Код помилки (`errno`) | Джерело помилки | Причина виникнення та спосіб усунення |
| :--- | :--- | :--- |
| `EACCES` | LSM / VFS | Операцію заборонено правилом Type Enforcement SELinux або стандартними правами DAC. Для діагностики перегляньте лог аудиту `/var/log/audit/audit.log`. |
| `EINVAL` | Security Server | Переданий рядок контексту має неприпустимий синтаксис або тип/роль/користувач відсутні в завантаженій політиці ядра. |
| `EOPNOTSUPP` / `ENOTSUP` | VFS Driver | Підстилаюча файлова система (наприклад, FAT32, ISO9660, tmpfs без опції `rootcontext=`) не підтримує розширені атрибути `security.selinux`. |
| `EPERM` | Capability | Процес не має необхідної системної можливості (наприклад, `CAP_MAC_ADMIN` або `CAP_MAC_OVERRIDE`) для зміни режимів чи перепозначення файлів. |
| `ENOENT` | selinuxfs | Файлова система `selinuxfs` не змонтована за шляхом `/sys/fs/selinux` або вказаний файл атрибута відсутній у `/proc/self/attr/`. |

При розробці програмного забезпечення важливо враховувати розрізнення між `EACCES` та `EINVAL`. Якщо виклик `setfilecon()` повертає `EINVAL`, це означає, що програма намагається призначити файлу тип, який взагалі не описаний у поточній політиці ядра (наприклад, через друкарську помилку у назві типу). Якщо ж виклик повертає `EACCES`, тип існує, але поточний домен процесу не має привілею `relabelfrom` або `relabelto` щодо даного об'єкта.

Помилка `EOPNOTSUPP` найчастіше виникає при спробі зберегти файли на зовнішніх накопичувачах з файловими системами exFAT або NTFS. Оскільки ці файлові системи не мають native підтримки розширених атрибутів POSIX, ядро не може зберегти атрибут `security.selinux`. Для вирішення цієї проблеми такі томи монтуються з опцією `context="system_u:object_r:removable_t:s0"`, що наказує VFS виставляти віртуальний контекст для всіх файлів на носії без запису на диск.

## 3. Приклади використання `libselinux`

Наведені нижче програми демонструють практичну роботу з функціями `is_selinux_enabled()`, `getcon()`, `getfilecon()` та звільненням виділеної пам'яті через `freecon()`.

:::tabs
```c
/* C: Зчитування контексту безпеки процесу та файлу через libselinux */
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <selinux/selinux.h>

int main(int argc, char *argv[]) {
    char *process_con = NULL;
    char *file_con = NULL;

    /* 1. Перевірка активності SELinux у ядрі */
    int enabled = is_selinux_enabled();
    if (enabled < 0) {
        perror("Помилка під час перевірки стану SELinux");
        return 1;
    } else if (enabled == 0) {
        printf("SELinux вимкнено або не підтримується на цій системі.\n");
        return 0;
    }

    printf("SELinux активний. Режим Enforcing: %d\n", security_getenforce());

    /* 2. Отримання контексту поточного процесу з /proc/self/attr/current */
    if (getcon(&process_con) < 0) {
        perror("Помилка виконання getcon");
        return 1;
    }
    printf("Контекст поточного процесу: %s\n", process_con);

    /* 3. Отримання контексту файлу через розширений атрибут security.selinux */
    const char *target_file = (argc > 1) ? argv[1] : "/etc/passwd";
    if (getfilecon(target_file, &file_con) < 0) {
        perror("Помилка виконання getfilecon");
        freecon(process_con);
        return 1;
    }
    printf("Контекст файлу (%s): %s\n", target_file, file_con);

    /* 4. Звільнення пам'яті, виділеної бібліотекою libselinux */
    freecon(process_con);
    freecon(file_con);
    return 0;
}
```

```cpp
// C++: Ідіоматична RAII-обгортка над libselinux з використанням std::unique_ptr та std::string_view
#include <iostream>
#include <memory>
#include <string_view>
#include <system_error>
#include <cerrno>
#include <selinux/selinux.h>

namespace selinux {

// RAII-делетор для автоматичного викликання freecon при виході з області видимості
struct context_deleter {
    void operator()(char* ptr) const noexcept {
        if (ptr) {
            freecon(ptr);
        }
    }
};

using scoped_context = std::unique_ptr<char, context_deleter>;

class security_context {
public:
    static bool is_enabled() {
        int res = is_selinux_enabled();
        if (res < 0) {
            throw std::system_error(errno, std::generic_category(), "is_selinux_enabled failed");
        }
        return res > 0;
    }

    static int get_enforce_mode() {
        int mode = security_getenforce();
        if (mode < 0) {
            throw std::system_error(errno, std::generic_category(), "security_getenforce failed");
        }
        return mode;
    }

    static scoped_context get_current_process() {
        char* raw_con = nullptr;
        if (getcon(&raw_con) < 0) {
            throw std::system_error(errno, std::generic_category(), "getcon failed");
        }
        return scoped_context(raw_con);
    }

    static scoped_context get_file(std::string_view path) {
        char* raw_con = nullptr;
        if (getfilecon(path.data(), &raw_con) < 0) {
            throw std::system_error(errno, std::generic_category(), "getfilecon failed");
        }
        return scoped_context(raw_con);
    }
};

} // namespace selinux

int main(int argc, char* argv[]) {
    try {
        if (!selinux::security_context::is_enabled()) {
            std::cout << "SELinux вимкнено або не підтримується.\n";
            return 0;
        }

        std::cout << "SELinux активний. Статус Enforcing: " 
                  << selinux::security_context::get_enforce_mode() << "\n";

        auto proc_con = selinux::security_context::get_current_process();
        std::cout << "Контекст процесу: " << proc_con.get() << "\n";

        std::string_view target_path = (argc > 1) ? argv[1] : "/etc/passwd";
        auto file_con = selinux::security_context::get_file(target_path);
        std::cout << "Контекст файлу (" << target_path << "): " << file_con.get() << "\n";
    } catch (const std::exception& ex) {
        std::cerr << "Помилка SELinux: " << ex.what() << "\n";
        return 1;
    }

    return 0;
}
```
