# 📋 Бінарна структура метаданих SIGSTRUCT в Intel SGX

Ця вставка містить вичерпний побайтовий макет та опис полів заголовка та корисного навантаження криптографічної структури `SIGSTRUCT` (розміром рівно 1808 байтів), яка необхідна для перевірки автентичності та цілісності енклава апаратурою процесора під час виконання інструкції `EINIT`.

## Загальна організація структури SIGSTRUCT

Структура `SIGSTRUCT` створюється розробником або інструментами збірки (наприклад, `sgx_sign`) при підписанні скомпільованого бінарного файлу енклава. Вона складається з п'яти основних функціональних блоків: заголовка (Header), інформації про розробника та версію (ISV metadata), вимірювань коду та атрибутів конфігурації, відкритого ключа RSA-3072 та безпосередньо криптографічного підпису з оптимізаційними параметрами піднесення до степеня.

Усі багатобайтові числа в `SIGSTRUCT` зберігаються у форматі Little-Endian, крім модулів та підписів RSA, які подаються як великі цілі числа без знаку у форматі Big-Endian відповідно до специфікацій PKCS#1 v1.5 та PKCS#1 v2.1.

| Зсув (байтові) | Поле | Розмір (байтів) | Тип / Формат | Опис та функціональне призначення |
| :--- | :--- | :--- | :--- | :--- |
| `0x0000` | `HEADER1` | 16 | Масив байтів | Фіксований заголовок структури. Повинен містити послідовність байтів `06 00 00 00 E1 00 00 00 00 00 01 00 00 00 00 00`. |
| `0x0010` | `VENDOR` | 4 | `uint32_t` | Ідентифікатор постачальника обладнання. Значення `0x00000000` для Intel, `0x00000001` для сторонніх розробників. |
| `0x0014` | `DATE` | 4 | `uint32_t` | Дата створення підпису у форматі BCD (`YYYYMMDD`). Використовується для аудиту безпеки. |
| `0x0018` | `HEADER2` | 16 | Масив байтів | Друга частина фіксованого заголовка (`01 01 00 00 60 00 00 00 60 00 00 00 01 00 00 00`). |
| `0x0028` | `SWDEFINED` | 4 | `uint32_t` | Довільне поле розробника (Software Defined). Процесором не перевіряється. |
| `0x002C` | `RESERVED1` | 84 | Масив байтів | Зарезервовано Intel. Усі байти повинні бути заповнені нулями (`0x00`). |
| `0x0080` | `MODULUS` | 384 | Big-Endian array | Модуль відкритого RSA ключа розробника (`N = p · q`), довжиною 3072 біти (384 байти). |
| `0x0200` | `EXPONENT` | 4 | `uint32_t` | Відкрита експонента RSA (`e`). Апаратура приймає єдине значення — `3`. |
| `0x0204` | `SIGNATURE` | 384 | Big-Endian array | RSA-підпис під структурою, обчислений закритим ключем розробника (`d`). |
| `0x0384` | `MISCSELECT` | 4 | `uint32_t` | Бітова маска для вибору розширених властивостей відображення інфо-структур SSA та винятків. |
| `0x0388` | `MISCMASK` | 4 | `uint32_t` | Маска перевірки `MISCSELECT`. Задає, які біти `MISCSELECT` є обов'язковими для збігу. |
| `0x038C` | `RESERVED2` | 20 | Масив байтів | Зарезервовано для майбутніх розширень архітектури SGX. Нульові байти. |
| `0x03A0` | `ATTRIBUTES` | 16 | `uint64_t[2]` | Бітові атрибути енклава (`FLAGS` та `XFRM`). Визначають режим відлагодження, 64-бітність тощо. |
| `0x03B0` | `ATTRIBUTEMASK` | 16 | `uint64_t[2]` | Маска перевірки атрибутів. Вказує процесору, які біти `ATTRIBUTES` мають суворо перевірятися. |
| `0x03C0` | `ENCLAVEHASH` | 32 | SHA-256 digest | Очікуване значення вимірювання коду та початкового стану енклава (`MRENCLAVE`). |
| `0x03E0` | `RESERVED3` | 32 | Масив байтів | Зарезервовано. Заповнюється нулями. |
| `0x0400` | `ISVPRODID` | 2 | `uint16_t` | Ідентифікатор продукту розробника (Independent Software Vendor Product ID). |
| `0x0402` | `ISVSVN` | 2 | `uint16_t` | Номер версії безпеки розробника (ISV Security Version Number). Використовується для anti-rollback. |
| `0x0404` | `RESERVED4` | 12 | Масив байтів | Зарезервовано. Заповнюється нулями. |
| `0x0410` | `Q1` | 384 | Big-Endian array | Попередньо обчислена частка, що дозволяє перевіряти підпис без ділення: `Q1 = ⌊SIGNATURE² / N⌋`. |
| `0x0590` | `Q2` | 384 | Big-Endian array | Друга попередньо обчислена частка: `Q2 = ⌊(SIGNATURE³ − Q1 · SIGNATURE · N) / N⌋`. |

## Прапори атрибутів ATTRIBUTES та розширене відображення XFRM

Поле `ATTRIBUTES` (зсув `0x03A0`) розбивається на дві 64-бітні частини: `FLAGS` (нижні 8 байтів) та `XFRM` (верхні 8 байтів — XSAVE Feature Request Mask).

Критично важливими прапорами у структурі `FLAGS` є:
- `DEBUG` (Bit 1): Якщо встановлено в `1`, енклав запускається у режимі налагодження. Це дозволяє недовіреному процесу читати та писати пам'ять енклава за допомогою спеціальних інструкцій `EDBGRD` та `EDBGWR`. Для продакшн-енклавів цей біт обов'язково має дорівнювати `0`, інакше апаратура виявить загрозу витоку секретів.
- `MODE64BIT` (Bit 2): Вказує, що енклав виконується у 64-бітному режимі адресації (IA-32e execution mode).
- `KSS` (Bit 7): Key Separation and Sharing. Дозволяє енклаву використовувати розширені механізми генерації ключів на основі додаткових полів конфігурації `CONFIGID` та `CONFIGSVN`.

Частина `XFRM` задає збереження розширеного стану процесора при виконанні інструкцій `XSAVE`/`XRSTOR` під час асинхронного виходу `AEX`:
- `XFRM_LEGACY` (Bits 0–1): Обов'язково встановлені для підтримки базового стану FPU, MMX та SSE.
- `XFRM_AVX` (Bit 2): Дозволяє збереження 256-бітних векторних регістрів `YMM0–YMM15`.
- `XFRM_AVX512` (Bits 5–7): Забезпечує збереження 512-бітних регістрів `ZMM0–ZMM31` та регістрів-масок `k0–k7`.

Маска `ATTRIBUTEMASK` визначає, які саме біти з `ATTRIBUTES` процесор мусить звіряти під час виконання `EINIT`. Якщо в масці біт встановлено в `1`, то значення відповідного біта в `ATTRIBUTES` має суворо збігатися з конфігурацією процесора.

## Криптографічне обчислення підпису SIGNATURE

Апаратний мікрокод інструкції `EINIT` не перевіряє довільний заголовок `SIGSTRUCT`. Підпис `SIGNATURE` обчислюється розробником над двома з'єднаними блоками структури `SIGSTRUCT`:
1. Блок 1 (Header payload): від `HEADER1` (зсув `0x0000`) до `RESERVED1` включно (перші 128 байтів).
2. Блок 2 (Enclave body payload): від `MISCSELECT` (зсув `0x0384`) до `ISVSVN` включно (разом 128 байтів) — `RESERVED4`, `Q1` і `Q2` у підпис не входять.

Схема підпису використовує стандарт RSA-SSA-PKCS1-v1_5 із хеш-функцією SHA-256. Хеш `H` обчислюється як послідовне хешування з'єднаних масивів:

```
H = SHA256( HeaderPayload || BodyPayload )
```

Отримане 32-байтове значення `H` доповнюється (padding) згідно з вимогами PKCS#1 v1.5 для 3072-бітного ключа і підписується закритим ключем розробника `d`:

```
SIGNATURE = (Padding(H))^d mod N
```

Поля `Q1` та `Q2` обчислюються під час підписання інструментом `sgx_sign` для того, щоб мікрокод CPU міг звести перевірку `SIGNATURE³ mod N` до множень і віднімань, не виконуючи ділення з остачею над 3072-бітними числами. Готові частки помітно здешевлюють апаратну перевірку `EINIT` — саме тому їх зберігають просто в структурі.

## Розбіжність ISVPRODID та лічильники версій безпеки ISVSVN

Поле `ISVPRODID` (зсув `0x0400`) надає можливість розробнику розділяти різні продукти, що підписуються одним і тим самим приватним RSA-ключем. При генерації ключів запечатування `Sealing Key` або ключів локальної атестації через інструкцію `EGETKEY`, процесор підставляє `ISVPRODID` у процедуру KDF (Key Derivation Function). Це гарантує, що енклави з різними `ISVPRODID` не зможуть прочитати запечатані дані один одного, навіть якщо вони підписані одним розробником.

Поле `ISVSVN` (зсув `0x0402`) використовується для захисту від відкату версій (Anti-Rollback Protection). Коли у коді енклава виправляється вразливість безпеки, розробник збільшує значення `ISVSVN` у новій збірці `SIGSTRUCT`. При виклику `EGETKEY` процесор дозволяє новій версії енклава із вищим `ISVSVN` зчитувати дані, запечатані старішою версією із меншим `ISVSVN`, однак суворо блокує зворотній доступ — стара вразлива версія коду не зможе прочитати секрети, створені оновленою версією.

## Обробка помилок верифікації в інструкції EINIT

Якщо під час виконання інструкції `EINIT` апаратура виявляє розбіжність у структурі `SIGSTRUCT`, процес ініціалізації переривається із встановленням відповідного коду помилки у регістрі `RAX`:

- `SGX_INVALID_SIG_STRUCT`: Структура `SIGSTRUCT` містить неправильні фіксовані заголовки `HEADER1`/`HEADER2`, непідтримуване значення відкритої експоненти RSA або недійсні зарезервовані байти.
- `SGX_INVALID_ATTRIBUTE`: Прапори атрибутів у `ATTRIBUTES` конфліктують із маскою `ATTRIBUTEMASK` або поточним режимом роботи процесора (наприклад, спроба запуску `DEBUG`-енклава на заблокованому продакшн-процесорі).
- `SGX_INVALID_MEASUREMENT`: Поле `ENCLAVEHASH` у `SIGSTRUCT` не збігається зі значенням `MRENCLAVE`, обчисленим процесором при послідовному виконанні інструкцій `EADD` та `EEXTEND`.
- `SGX_INVALID_SIGNATURE`: RSA-3072 підпис `SIGNATURE` криптографічно недійсний або не відповідає модулю `MODULUS`.
