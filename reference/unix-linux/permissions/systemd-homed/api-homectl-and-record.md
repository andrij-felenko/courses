# 📋 homectl, розкладка образу й шина: поверхня systemd-homed

Це перелік усього, чим служба виглядає назовні: дії `homectl` із їхніми перемикачами, числа й UUID, за якими домівку впізнають на диску, файли ключів підпису, методи шини й параметри модуля PAM. Довідка для того, хто заводить домівку, переносить її на іншу машину або приєднується до служби власним кодом.

## Дії homectl

**Обліковий запис**

| дія | що робить |
|---|---|
| `create USER` | завести обліковий запис і створити домівку |
| `register FILE…` | зареєструвати запис із файла JSON, домівки не створюючи (`-` — зі стандартного входу) |
| `adopt PATH…` | прийняти наявний `*.home` чи `*.homedir/` і дозволити вхід ним локально |
| `unregister USER…` | прибрати запис із машини, домівку лишивши на місці |
| `remove USER` | видалити і запис, і домівку |
| `update USER` | застосувати змінений запис |
| `passwd USER` | змінити пароль, а отже й ключовий слот LUKS2 |
| `firstboot` | при першому завантаженні спитати ім'я й пароль на консолі, якщо звичайних домівок ще немає |

Пара `unregister` / `adopt` і є тим, чим переносять домівку: перша знімає опис із машини, не чіпаючи байтів, друга підбирає байти на новому місці.

**Доступ**

| дія | що робить |
|---|---|
| `activate USER…` | відімкнути й змонтувати |
| `deactivate USER…` | розмонтувати й замкнути |
| `deactivate-all` | те саме для всіх діяльних |
| `lock USER` / `unlock USER` | призупинити доступ, викинувши ключі з пам'яті / відновити |
| `lock-all` | `lock` на всіх придатних домівках |
| `authenticate USER…` | перевірити облікові дані, нічого не монтуючи |
| `with USER COMMAND…` | відімкнути домівку, виконати команду й замкнути назад |

`with` названо оманливо, і це варто знати заздалегідь: команда виконується **від імені того, хто її набрав**, а не від імені USER. Це інструмент резервного копіювання й обслуговування, а не спосіб стати користувачем.

**Огляд і обслуговування**

| дія | що робить |
|---|---|
| `list` | таблиця всіх домівок під керуванням служби |
| `inspect USER…` | подробиці конкретної домівки |
| `resize USER BYTES` | змінити виділене місце |
| `rebalance` | перерозподілити вільне місце між діяльними домівками LUKS2 |

**Ключі підпису**

| дія | що робить |
|---|---|
| `list-signing-keys` | які відкриті ключі машина приймає |
| `get-signing-key [NAME…]` | вивести відкритий ключ у PEM |
| `add-signing-key [FILE…]` | додати відкритий ключ із файла PEM (`-` або нічого — зі стандартного входу) |
| `remove-signing-key NAME…` | прибрати ключ зі списку прийнятих |

Ця четвірка робить те саме, що покласти файл `*.public` у теку ключів руками, — тільки службовим шляхом, з перевіркою формату.

## --storage=: п'ять сховищ

| значення | шлях типово | шифрування | `lock` | облік місця |
|---|---|---|---|---|
| `luks` | `/home/$USER.home` | [LUKS2 в образі](book:unix-linux/dm-crypt) | так | розмір образу |
| `fscrypt` | `/home/$USER.homedir` | [засобами файлової системи](book:unix-linux/fscrypt) | ні | ні |
| `subvolume` | `/home/$USER.homedir` | немає | ні | [квота підтому](book:unix-linux/disk-quotas) |
| `directory` | `/home/$USER.homedir` | немає | ні | ні |
| `cifs` | не визначено | канал [SMB](book:unix-linux/network-filesystems) | ні | ні |

`lock` визначено лише для LUKS2: решті сховищ просто нема чого викидати з пам'яті ядра. Типове значення бере `homed.conf`.

## Перемикачі create та update

**Розмір і файлова система**

| перемикач | значення | типово |
|---|---|---|
| `--disk-size=` | байти з суфіксами `K`/`M`/`G`/`T`, відсоток, `min`, `max` | 85% вільного місця для LUKS2; для решти квоти немає |
| `--fs-type=` | [`btrfs`, `ext4`, `xfs`](book:unix-linux/filesystem-families) — лише всередині LUKS2 | з `homed.conf` |
| `--image-path=` | де покласти образ чи теку | `/home/$USER.home` для LUKS, `/home/$USER.homedir` для решти |
| `--auto-resize-mode=` | `off`, `grow`, `shrink-and-grow` | `shrink-and-grow` для LUKS2 з btrfs, інакше `off` |
| `--rebalance-weight=` | ціле 1…10000 або `off` | `100` |

Одна пастка серед тонких перемикачів LUKS2: `--luks-volume-key-size=` міряє ключ у **байтах** — як `/proc/crypto`, — тоді як `cryptsetup` те саме число подає в бітах. Переписані з чужої інструкції `512` дадуть не вчетверо довший ключ, а помилку.

**Чим відмикати**

| перемикач | значення |
|---|---|
| `--fido2-device=` | шлях до `hidraw`-пристрою, `list` або `auto`; порожній рядок прибирає пристрій |
| `--fido2-credential-algorithm=` | `es256` (типово), `rs256`, `eddsa` |
| `--fido2-with-client-pin=` | вимагати PIN самого токена; типово `yes` |
| `--fido2-with-user-presence=` | вимагати дотику до токена; типово `yes` |
| `--fido2-with-user-verification=` | вимагати, щоб токен сам упізнав людину; типово `no` |
| `--pkcs11-token-uri=` | URI за RFC 7512 до токена (YubiKey, картка PIV) рівно з однією парою «сертифікат X.509 + приватний ключ»; також `list`, `auto` |
| `--recovery-key=` | завести згенерований машиною ключ відновлення на випадок забутого пароля чи втраченого токена |

Жоден із них не заступає пароль — кожен додає ще один спосіб дійти до того самого ключа тому. Пристрої [FIDO2](book:programming/passkeys) тут ужито не для входу на сайт, а для виведення ключа: токен рахує відповідь, з якої й постає ключовий матеріал.

**Прив'язка до машини**

| перемикач | значення | типово |
|---|---|---|
| `--uid=` | номер; радять діапазон 60001…60513 | обирається сама |
| `--seize=` | зривати з поданого запису підписи, а отже підписувати його місцевим `local.private` | `true` для `create`, `false` для `register` |
| `--identity=FILE` | прочитати запис JSON із файла (`-` — зі стандартного входу) | — |
| `--offline` | не чіпати копію запису, вкладену в саму домівку | — |
| `-H HOST`, `-M CONTAINER` | виконати дію на віддаленій машині чи в місцевому контейнері | — |

`--seize=` — єдиний перемикач тут, що змінює не вміст запису, а **власність** над ним.

**Вивід:** `--json=pretty|short|off` (скорочення `-j`), `--export-format=full|stripped|minimal` — три ступені повноти, від запису з усіма місцевими секціями до найкоротшого переносного; `-E` дорівнює `-j --export-format=stripped`, `-EE` — `-j --export-format=minimal`.

## Що лежить на диску

| елемент | значення |
|---|---|
| тип [розділу GPT](book:unix-linux/disk-partitions) | `773f91ef-66d4-49b5-bd83-d683bf40ad16` |
| мітка розділу й мітка файлової системи | ім'я користувача — обов'язково |
| файлова система всередині LUKS2 | `ext4`, `btrfs` або `xfs` |
| образ LUKS2 | `/home/<ім'я>.home` |
| тека решти сховищ | `/home/<ім'я>.homedir` |
| запис усередині домівки | `~/.identity` |

Маркер у заголовку LUKS2 — звичайний [об'єкт JSON](book:programming/json-format) у слоті маркерів, з полем `type`, що дорівнює `systemd-homed`:

```json
{
  "type": "systemd-homed",
  "keyslots": [],
  "record": "eyJ1c2VyTmFtZSI6ImFuZHJpaiIsIuKApiJ9",
  "iv": "3Yx1QW5nZ0hLcE0="
}
```

`record` — обліковий запис, зашифрований **тим самим ключем тому**, що й дані, і закодований у base64; `iv` — власний вектор ініціалізації цього шифрування, теж у base64.

## Файли ключів

Тека `/var/lib/systemd/home/`, усе у форматі PEM:

| файл | що це |
|---|---|
| `local.private` | приватний ключ машини; поки що дозволено рівно один |
| `local.public` | його відкрита пара |
| `*.public` | додаткові відкриті ключі; запис, підписаний будь-яким із них, пускають до локального входу |

Підпис — Ed25519. У записі він лежить у секції `signature`: поле `data` — сам підпис у base64, поле `key` — копія відкритого ключа в PEM. Накрито ним лише секції `regular`, `perMachine` і `privileged`; усе інше перед обчисленням із запису прибирають — інакше [підпис](book:math/hash-and-digital-signature) розсипався б від кожної місцевої дрібниці на кшталт зміненого стану домівки.

Перенесення з машини `foobar` на `quux` — це три команди, і жодна з них не чіпає вмісту образу:

```sh
scp foobar:/var/lib/systemd/home/local.public /tmp/foobar.public
homectl add-signing-key /tmp/foobar.public
homectl adopt /home/andrij.home
```

Ім'я файла з ключем довільне; його беруть таким, щоб було видно походження.

## Секція binding

Ця секція запису — місцева: її пише сама машина під ключем свого машинного ідентифікатора, і саме вона з'єднує переносний опис із цією конкретною файловою системою.

| поле | що тримає |
|---|---|
| `uid`, `gid` | [числа ідентичності](book:unix-linux/uid-gid-model) на цій машині |
| `storage` | яке зі сховищ ужито |
| `imagePath` | шлях до образу чи теки |
| `homeDirectory` | куди домівку [монтують](book:unix-linux/mount-model) |
| `fileSystemType` | `ext4`, `btrfs`, `xfs` |
| `partitionUuid`, `luksUuid`, `fileSystemUuid` | UUID розділу, тому LUKS2 і файлової системи |
| `luksCipher`, `luksCipherMode`, `luksVolumeKeySize` | параметри шифру, якими том створено |

Поруч, уже поза `binding`, лежить `lastChangeUSec` — мікросекунди від епохи 1970 року, за якими вирішують, котра з копій запису свіжіша.

## Шина

| що | значення |
|---|---|
| ім'я на [шині](book:unix-linux/dbus) | `org.freedesktop.home1` |
| об'єкт-керівник | `/org/freedesktop/home1` |
| інтерфейс керівника | `org.freedesktop.home1.Manager` |
| об'єкт однієї домівки | під `/org/freedesktop/home1/home/…` |
| інтерфейс домівки | `org.freedesktop.home1.Home` |

Методи `Manager` беруть ім'я користувача першим аргументом; однойменні методи `Home` цього аргументу не мають — його заміняє сам об'єкт.

| метод | сигнатура |
|---|---|
| `GetHomeByName` | `(s user_name) → (u uid, s state, u gid, s real_name, s home_directory, s shell, o bus_path)` |
| `ListHomes` | `() → (a(susussso) home_areas)` |
| `ActivateHome` | `(s user_name, s secret)` |
| `DeactivateHome` | `(s user_name)` |
| `CreateHome`, `UpdateHome`, `RegisterHome` | `(s user_record)` |
| `RemoveHome`, `UnregisterHome` | `(s user_name)` |
| `ResizeHome` | `(s user_name, t size, s secret)` |
| `ChangePasswordHome` | `(s user_name, s new_secret, s old_secret)` |
| `LockHome`, `UnlockHome` | `(s user_name)` · `(s user_name, s secret)` |
| `AcquireHome` | `(s user_name, s secret, b please_suspend) → (h send_fd)` |
| `AddSigningKey` | `(s name, s pem, t flags)` |

Аргумент `secret` — не голий рядок пароля, а запис JSON, у якому заповнено секцію `secret`: туди кладуть пароль, PIN токена або ключ відновлення. Один формат замість окремого аргументу на кожен спосіб автентифікації.

`AcquireHome` варта окремого рядка, бо не схожа на решту: вона повертає **дескриптор файла**. Поки той відкритий, домівка лишається діяльною; закрився останній — служба її розмонтовує. Саме так `pam_systemd_home` рахує сеанси, не ведучи власного лічильника, який мусив би пережити падіння будь-якого процесу. Дії над **чужою** домівкою проходять через [polkit](book:unix-linux/polkit).

## Решта поверхні

| канал | адреса |
|---|---|
| [userdb](book:unix-linux/userdb-varlink) | сокет `io.systemd.Home` у `/run/systemd/userdb/` |
| [PAM](book:unix-linux/pam-stack) | модуль `pam_systemd_home`; фази `auth`, `account`, `session`, `password` |
| налаштування | `/etc/systemd/homed.conf` і вставки `*.conf` у `homed.conf.d/` під `/etc`, `/run`, `/usr/local/lib`, `/usr/lib` |

Модуль PAM має рівно два параметри:

| параметр | типово | що робить |
|---|---|---|
| `suspend=` | `off` | приспати домівку на час засинання системи, викинувши ключі з пам'яті; після пробудження потрібна повторна автентифікація |
| `debug=` | `off` | писати діагностику модуля в журнал |

Секція `[Home]` в `homed.conf` теж коротка:

| параметр | значення | типово |
|---|---|---|
| `DefaultStorage=` | `luks`, `fscrypt`, `directory`, `subvolume`, `cifs` | `luks`, якщо це не контейнер і `/home` не зашифровано; інакше `subvolume` на Btrfs або `directory` |
| `DefaultFileSystemType=` | `btrfs`, `ext4`, `xfs` | `btrfs` |

Обидва перекриваються перемикачами командного рядка.

## Найкоротший робочий набір

```sh
# завести домівку в образі LUKS2 на 20 ГіБ з ext4 усередині
homectl create andrij --storage=luks --fs-type=ext4 --disk-size=20G

# подивитися, що вийшло, як запис JSON
homectl inspect andrij --json=pretty

# зняти резервну копію, не входячи в систему користувачем
homectl with andrij -- tar -C /home/andrij -cf /srv/andrij.tar .
```

Останній рядок — найкоротший спосіб побачити межу цієї служби на власні очі. `tar` виконується з правами того, хто набрав команду; домівка існує рівно стільки, скільки триває архівування; пароль питають один раз, на початку, — і без нього команда просто не почнеться.
