# 📋 Довідник синтаксису профілів AppArmor: маски, класифікація та переходи

Текстовий профіль AppArmor зберігається у директорії `/etc/apparmor.d/` і визначає межі привілеїв конкретного бінарного файлу або групи процесів. Профіль має чітку блочну структуру, огороджену фігурними дужками `{ }`, із можливістю завантаження зовнішніх абстракцій через директиви `#include`.

Цей довідник містить повний систематизований перелік синтаксичних конструкцій, масок доступу, типів переходів при виконанні бінарних файлів та додаткових обмежень системних ресурсів ядра.

## 1. Заголовок та прапорці профілю

Заголовок профілю зв'язує правила з абсолютним шляхом бінарного файлу або задає ім'я профілю з явним вказуванням прив'язки через атрибут `attach_disconnected`.

```apparmor
#include <tunables/global>

/usr/sbin/nginx flags=(complain, attach_disconnected) {
  #include <abstractions/base>
  # Права доступу...
}
```

Можливі прапорці профілю (`flags`):
- `enforce`: Активний примусовий режим (блокування заперечених операцій із поверненням `-EACCES`). За замовчуванням, якщо прапорець не вказано.
- `complain`: Режим навчання та скарг (дозвіл виконання операцій із записом сповіщень до журналу auditd/journald).
- `audit`: Записувати у системний журнал абсолютно всі операції доступу, включаючи ті, що були явно дозволені.
- `attach_disconnected`: Автоматично прив'язувати файлові дескриптори та шляхи, які знаходяться поза поточним коренем маунт-простору процесу (chroot/namespaces), до кореневого символу `/`.
- `chroot_relative`: Обчислювати файлові шляхи відносно кореня `chroot`, а не відносно глобального кореня маунт-простору системи.

## 2. Маски файлових прав доступу

Права доступу до файлів описуються комбінацією літерних прапорців, які розташовуються після файлового шляху або шаблону. Кожне правило завершується комою.

| Прапорець | Назва | Опис та механіка ядра |
| :--- | :--- | :--- |
| `r` | Read | Дозвіл на зчитування даних з файла (`open` із прапором `O_RDONLY` або `O_RDWR`). |
| `w` | Write | Дозвіл на модифікацію та перезапис вмісту файла (`open` із `O_WRONLY` або `O_RDWR`, `truncate`). |
| `a` | Append | Дозвіл лише на дописування у кінець файла (`open` із прапорцем `O_APPEND`). Не дозволяє перезапис існуючих байтів. |
| `l` | Link | Дозвіл на створення жорстких посилань (`link()`, `linkat()`). Вимагає вказування цільового шляху. |
| `k` | Lock | Дозвіл на блокування файлів за допомогою `flock()`, `fcntl(F_SETLK)` або `lockf()`. |
| `m` | Memory Map | Дозвіл на відображення файла у пам'ять із правом виконання (`mmap()` з `PROT_EXEC`). |

## 3. Режими переходу при виконанні файлів (Exec Transitions)

Коли процес, який перебуває під захистом профілю AppArmor, викликає системний виклик `execve()`, ядро повинно вирішити, під яким политичним контекстом працюватиме новий бінарний файл. Для цього використовуються модифікатори виконання:

| Модифікатор | Назва | Механіка та обробка середовища (`env`) |
| :--- | :--- | :--- |
| `ix` | Inherit | Новий процес успадковує поточний профіль батьківського процесу без змін. |
| `px` | Profile | Перехід у цільовий профіль, визначений для нового бінарника. Зберігає змінні середовища. |
| `Px` | Profile Clean | Перехід у цільовий профіль із примусовим очищенням небезпечних змінних (`LD_PRELOAD`, `LD_LIBRARY_PATH`). |
| `cx` | Child | Перехід у підпрофіль (child profile), вкладений у поточний профіль. |
| `Cx` | Child Clean | Перехід у підпрофіль із очищенням змінних середовища. |
| `ux` | Unconfined | Вихід із-під контролю AppArmor (новий процес працює без обмежень MAC). Зберігає `env`. |
| `Ux` | Unconfined Clean | Вихід із-під контролю AppArmor із примусовим видаленням `LD_PRELOAD` та `LD_LIBRARY_PATH`. |
| `pix` / `pux` | Fallback | Спроба виконати перехід `px` / `ux`; якщо цільовий профіль відсутній — переходить в `ix` чи `ux`. |

## 4. Шаблони шляхів (Wildcards & Globbing)

AppArmor використовує власний синтаксис підстановочних симво символів (globbing) для опису наборів файлів у межат ієрархії VFS:

- `*`: Збігається з будь-якою кількістю символів у межах одного рівня каталогу (не перетинає символ `/`).
- `**`: Збігається з будь-якою кількістю символів на будь-яку глибину ієрархії, включаючи `/` і підкаталоги.
- `?`: Збігається з одним будь-яким символом, крім `/`.
- `[abc]` або `[a-z]`: Збігається з одним символом із вказаної множини або діапазону.
- `{alt1,alt2}`: Альтернативний вибір. Правило розгортається у списки збігів для `alt1` або `alt2`.

Приклад використання масок:
```apparmor
/var/log/nginx/* r,        # Усі файли безпосередньо у /var/log/nginx/
/var/log/nginx/** rw,      # Усі файли та будь-які вкладені каталоги
/etc/{nginx,lighttpd}/* r, # Файли у /etc/nginx/ або /etc/lighttpd/
```

## 5. Правила доступу до системних ресурсів (Capabilities, Network, Signal)

Окрім контролю файлових шляхів, AppArmor регулює доступ процесу до привілеїв ядра Linux:

### POSIX Capabilities
Дозволяють процесу використовувати конкретні привілеї без надання повних прав `root`:
```apparmor
capability net_bind_service, # Дозвіл зв'язування з портами < 1024
capability setuid,           # Дозвіл на зміну UID процесу
capability sys_chroot,       # Дозвіл виклику chroot()
```

### Мережеві сокети (Network Rules)
Обмежують створення сокетів за сімейством та типом:
```apparmor
network inet tcp,    # IPv4 TCP сокети
network inet6 stream,# IPv6 TCP сокети
network raw,         # Сирі RAW сокети (вимагає додаткових привілеїв)
```

### Сигнали, Ptrace та Монтування
Регулюють взаємодію між процесами у системі та операції з файловими системами:
```apparmor
signal (send) set=(kill, term) peer=/usr/sbin/nginx,
ptrace (read, trace) peer=/usr/bin/gdb,
mount options=(ro, remount) -> /mnt/data/,
```

### Системні ліміти (Rlimit Rules)
Дозволяють задавати обмеження ресурсів прямо всередині профілю AppArmor:
```apparmor
setrlimit stack <= 8M,
setrlimit fsize <= 100M,
```

## 6. Змінні та абстракції (Tunables & Abstractions)

Для забезпечення масштабованості AppArmor підтримує використання глобальних змінних та заздалегідь підготовлених модулів правил.

Змінні оголошуються у файлах підсистеми `tunables` (наприклад, `/etc/apparmor.d/tunables/global`) і викличуться в профілях через синтаксис `@{VAR_NAME}`:
- `@{HOME}`: розгортається у списки домашніх каталогів користувачів (`/home/*`, `/root`).
- `@{PROC}`: шлях до віртуальної файлової системи процесора (`/proc/`).
- `@{pid}`: будь-який числовий ідентифікатор процесу.

Абстракції у каталозі `/etc/apparmor.d/abstractions/` містять готові набори правил для типових підсистем:
- `abstractions/base`: правила доступу до базових C-бібліотек, локалей та часових поясів.
- `abstractions/nameservice`: правила доступу до DNS-розділювачів (`/etc/resolv.conf`, `/etc/hosts`, `/etc/nsswitch.conf`).
- `abstractions/python`: правила, необхідні для завантаження та виконання інтерпретатора Python.

## 7. Правила заборони (Deny Rules) та Пріоритети

Правила із ключовим словом `deny` мають абсолютний пріоритет над будь-якими дозволами `allow`, незалежно від порядку їхнього розташування у файлі профілю.

```apparmor
/etc/app/** r,              # Дозволяє читання всіх файлів у /etc/app/
deny /etc/app/secret.key r, # Явно блокує доступ до secret.key
```

Якщо для одного файла збігаються кілька дозволяючих правил із різними масками, AppArmor підсумовує дозволені права за допомогою побітового АБО (`OR`). У разі виникнення конфлікту між маскою явного дозволу та маскою явного заперечення, детермінований автомат DFA завжди надає абсолютне перевагу стану `deny`.
