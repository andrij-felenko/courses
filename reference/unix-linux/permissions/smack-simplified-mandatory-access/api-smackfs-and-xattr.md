# 📋 Поверхня інтерфейсів /sys/fs/smackfs та атрибутів xattr

Ця вставка містить вичерпну технічну специфікацію системних інтерфейсів управління підсистемою SMACK у ядрі Linux. Програмна взаємодія з модулем безпеки здійснюється через два основні канали: віртуальну файлову систему `smackfs` (зазвичай змонтовану в точці `/sys/fs/smackfs`) та розширені атрибути файлових систем (англ. *extended attributes*, xattr) у спеціальному просторі імен `security.SMACK64*`.

## 1. Специфікація псевдо-файлової системи /sys/fs/smackfs

Віртуальна файлова система `smackfs` створюється модулем ядра SMACK під час завантаження системи. Вона надає простір керуючих файлів, через які процеси з належними привілеями (наявність мітки з правом `CAP_MAC_ADMIN`) мають можливість динамічно завантажувати нові правила доступу, конфігурувати мережеві мітки, контролювати системні привілеї та виконувати діагностику підсистеми.

### `load` — Історичний файл завантаження правил
Файл `load` призначений для зчитування поточного списку правил та завантаження нових за застарілим форматом фіксованої довжини.
- **Права доступу:** `rw-rw-rw-` (реальний доступ контролюється хуками SMACK та наявністю привілею `CAP_MAC_ADMIN`).
- **Формат запису:** Кожен рядок правила має сувору фіксовану довжину, а поля доповнюються пробілами до повного розміру:
  - Мітка суб'єкта: 23 байти (доповнюється пробілами праворуч).
  - Мітка об'єкта: 23 байти (доповнюється пробілами праворуч).
  - Маска прав: 4 байти (комбінація літер `r`, `w`, `x`, `a` або `-`).
  - Символ переведення рядка `\n`.
- **Особливості ядра:** Через обмеження довжини мітки у 23 байти використання файлу `load` у сучасних дистрибутивах є застарілим і підтримується виключно для зворотної сумісності зі старими версіями адмін-утиліт.

### `load2` — Сучасний файл завантаження правил змінної довжини
Файл `load2` є основним інтерфейсом динамічного керування політикою доступу у сучасних ядрах Linux.
- **Права доступу:** `rw-rw-rw-`.
- **Формат запису:** Рядок вільної форми з розділювачами-пробілами:
  ```
  SubjectLabel ObjectLabel AccessMask
  ```
  Наприклад: `WebBrowser UserData rwat`.
- **Особливості ядра:** Дозволяє використовувати мітки довжиною до 255 символів. При записі рядка ядро атомарно шукає або створює вузли `struct smack_known` для відповідних міток і додає правило до загального списку `smack_known_list`. Повторний запис правила для тієї ж пари `(Subject, Object)` перезаписує маску прав.

### `access` та `access2` — Інтерфейс підтвердження доступу
Ця пара файлів дозволяє користувацьким демонам (наприклад, `systemd` чи DBus-демону) швидко перевірити, чи має процес із певною міткою право на операцію над об'єктом. Як і в парі `load`/`load2`, старий `access` вимагає полів фіксованої довжини, доповнених пробілами, а сучасний `access2` приймає рядок вільної форми — далі описано саме `access2`.
- **Права доступу:** `rw-rw-rw-`.
- **Протокол взаємодії:**
  1. Процес відкриває файл у режимі `O_RDWR`.
  2. Записує рядок запиту у форматі: `SubjectLabel ObjectLabel AccessMask` (наприклад, `WebBrowser UserData r`).
  3. Переміщує вказівник читання на початок файла (`lseek(fd, 0, SEEK_SET)`).
  4. Виконує читання `read()`. Ядро повертає текстовий рядок `"1"` (якщо доступ дозволено відповідно до поточних правил) або `"0"` (якщо у доступі відмовлено).

### `onlycap` — Обмеження системних привілеїв
Файл `onlycap` є критичним елементом захисту самої підсистеми SMACK від компрометації через привілейовані процеси `root`.
- **Права доступу:** `rw-r--r--`.
- **Семантика роботи:** За замовчуванням файл порожній. Якщо адміністратор записує сюди список текстових міток (наприклад, `"Admin"`), ядро Linux вмикає режим суворого обмеження: право використовувати POSIX capability `CAP_MAC_ADMIN` для зміни правил чи атрибутів xattr зберігають **тільки ті процеси, чия мітка збігається з міткою з файла `onlycap`**. Будь-який інший процес (навіть із UID 0 та всіма іншими capabilities) втрачає можливість модифікувати конфігурацію SMACK.

### `ambient` — Мітка незахищеного мережевого середовища
Файл `ambient` визначає мітку за замовчуванням для вхідного мережевого трафіку.
- **Права доступу:** `rw-r--r--`.
- **Семантика роботи:** За замовчуванням містить мітку `_` (floor). Коли ядро отримує вхідний IP-пакет, який не містить опцій CIPSO і не підпадає під правила NetLabel, йому автоматично призначається мітка з файла `ambient`. Це дозволяє прозоро ізолювати зовнішній мережевий трафік від внутрішніх захищених ресурсів.

### `cipso` — Конфігурація заголовків CIPSO v4
Файл `cipso` керує відповідністю між текстовими мітками SMACK та числовою кодувальною схемою CIPSO (Commercial IP Security Option — інтернет-чернетка IETF, що так і не стала RFC) у заголовках IPv4.
- **Права доступу:** `rw-r--r--`.
- **Формат запису:** `Label Level CategoryCount Category1 Category2 ...`
- **Семантика роботи:** Дозволяє налаштувати вихідні пакети так, щоб мережеві маршрутизатори з підтримкою MLS/CIPSO могли обробляти пакети від Linux-систем із збереженням рівнів секретності.

### `netlabel` — Правила для явних IP-адрес та мереж
Файл `netlabel` задає прив'язку міток SMACK до конкретних IP-адрес або цілих підмереж хостів.
- **Права доступу:** `rw-r--r--`.
- **Формат запису:** `192.168.1.0/24 Label` або `10.0.0.5 Label`.
- **Семантика роботи:** Усі мережеві пакети, що надходять з указаних IP-адрес, отримують задану мітку SMACK незалежно від наявності CIPSO-заголовків.

### `relabel-self` — Перелік міток для самостійної зміни
Файл `relabel-self` визначає, на які мітки процесові дозволено перейти зі своєї власної під час виконання.
- **Права доступу:** `-w--w--w-`.
- **Семантика роботи:** Процес записує сюди перелік міток, а саму зміну виконує записом у `/proc/self/attr/current`. Без привілею `CAP_MAC_ADMIN` перейти можна лише на мітку з цього переліку; з `CAP_MAC_ADMIN` — на будь-яку.

### `revoke-subject` — Екстрене анулювання прав суб'єкта
Файл `revoke-subject` забезпечує миттєве відкликання всіх прав конкретного суб'єкта.
- **Права доступу:** `-w--w--w-`.
- **Семантика роботи:** Запис назви мітки (наприклад, `"CompromisedApp"`) призводить до негайного вилучення з оперативної пам'яті ядра всіх правил, де ця мітка вказана як суб'єкт.

## 2. Специфікація розширених атрибутів файлових систем (security.SMACK64*)

Розширені атрибути (xattr) забезпечують збереження мандатних міток SMACK безпосередньо в метаданих інод файлової системи (ext4, xfs, btrfs, f2fs, squashfs). Атрибути розташовані у спеціальному розширеному просторі імен `security`.

### `security.SMACK64`
- **Призначення:** Основна мітка об'єкта файлової системи.
- **Формат значення:** Рядок друкованих символів ASCII довжиною від 1 до 255 байтів. Нульовий завершальний байт `\0` не додається.
- **Поведінка ядра:** LSM-хук `smack_inode_permission()` зчитує цю мітку під час спроби доступу до файла чи директорії. Якщо атрибут відсутній, об'єкт отримує дефолтну мітку `_` (floor).

### `security.SMACK64EXEC`
- **Призначення:** Забезпечення автоматичного переходу мітки суб'єкта при виконанні файла.
- **Формат значення:** Рядок з назвою нової мітки суб'єкта (наприклад, `"AppRunner"`).
- **Поведінка ядра:** При виклику `execve()` системний хук `smack_bprm_creds_for_exec()` перевіряє цей атрибут. Якщо атрибут встановлено і процес має право на виконання (`x`), нова структура `struct cred` процесу отримує вказану мітку. Це є аналогом механізму `setuid` у мандатному світі.

### `security.SMACK64TRANSMUTE`
- **Призначення:** Прапорець активації трансмутації для директорії.
- **Формат значення:** Суворий рядок `"TRUE"` у верхньому регістрі.
- **Поведінка ядра:** Якщо на директорії встановлено цей атрибут, і процес має право `t` (transmute) щодо мітки цієї директорії, то всі нові файли, створені всередині, отримують мітку директорії, а не мітку процесу. Нові піддиректорії додатково успадковують цей атрибут.

### `security.SMACK64MMAP`
- **Призначення:** Додатковий захист від завантаження виконуваного коду через відображення пам'яті `mmap()`.
- **Формат значення:** Текстовий рядок мітки.
- **Поведінка ядра:** При виклику `mmap()` із прапорцем `PROT_EXEC` ядро перевіряє додаткове правило доступу суб'єкта до мітки з `SMACK64MMAP` з вимогою права `x`.

### `security.SMACK64IPIN` та `security.SMACK64IPOUT`
- **Призначення:** Статичне маркування вхідного та вихідного трафіку для файлів сокетів.
- **Формат значення:** Текстовий рядок мітки SMACK.
- **Поведінка ядра:** Застосовується до файлів сокетів UNIX domain sockets та мережевих сокетів, дозволяючи фіксувати мітки трафіку без зміни вихідного коду мережевих програм.

## 3. Маска прав доступу (Access Rights String)

При описі правил у `load2` або використанні системних утиліт (`smackctl`, `chsmack`) маска прав задається комбінацією з 7 буквених символів:

- `r` (Read) — дозвіл на читання даних з файла, перегляд вмісту директорії, читання з сокета чи каналу IPC.
- `w` (Write) — дозвіл на зміну вмісту файла, видалення об'єктів, запис у сокет чи FIFO.
- `x` (Execute) — дозвіл на виконання файла або відображення у пам'ять із можливістю виконання коду `mmap(PROT_EXEC)`.
- `a` (Append) — специфічне право запису: дозволяє лише доповнення файла у режимі `O_APPEND` без права перезапису існуючих блоків.
- `t` (Transmute) — право активації механізму успадкування мітки директорії при створенні нових об'єктів.
- `l` (Lock) — право взяти блокування на файл (`flock()`, `fcntl(F_SETLK)`) без права читати чи змінювати вміст.
- `b` (Bring-up) — діагностичний прапорець ядер, зібраних із `CONFIG_SECURITY_SMACK_BRINGUP`: доступ дозволяється, а кожне спрацювання додатково записується в журнал; у робочій політиці не вживається.
