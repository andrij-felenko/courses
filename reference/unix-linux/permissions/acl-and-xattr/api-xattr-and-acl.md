# 📋 Атрибути й списки: виклики, простори імен, коди помилок

Довідка за клавіатурою: чотири дії над розширеними атрибутами в чотирьох формах виклику, точне правило доступу до кожного з чотирьох просторів імен, межі згори й межі кожної файлової системи під ними, коди відмови з тим, що кожен означає на ділі, і два шари над викликами — бібліотечний та командний. Питання, на яке ця довідка відповідає найчастіше: чому саме зараз відмовило — і на якому шарі народилася відмова.

Усі чотири дії оголошено в `<sys/xattr.h>`, окремої бібліотеки не треба: обгортки живуть у самій [libc](topic:unix-linux/libc-as-gateway) від glibc 2.3, а виклики — у ядрі від Linux 2.4. Списки доступу мають ще й свою бібліотеку `libacl` (`<sys/acl.h>`, збирання з `-lacl`), але нічого нового в ядра вона не просить: усередині це ті самі чотири виклики над двома іменами атрибутів.

## Чотири дії, чотири форми

| дія | за шляхом | за шляхом, не розкриваючи посилання | за дескриптором | від каталогу-якоря |
|---|---|---|---|---|
| записати | `setxattr` | `lsetxattr` | `fsetxattr` | `setxattrat` |
| прочитати | `getxattr` | `lgetxattr` | `fgetxattr` | `getxattrat` |
| перелічити імена | `listxattr` | `llistxattr` | `flistxattr` | `listxattrat` |
| зняти | `removexattr` | `lremovexattr` | `fremovexattr` | `removexattrat` |

```c
#include <sys/xattr.h>

int     setxattr   (const char *path, const char *name,
                    const void *value, size_t size, int flags);
ssize_t getxattr   (const char *path, const char *name,
                    void *value, size_t size);
ssize_t listxattr  (const char *path, char *list, size_t size);
int     removexattr(const char *path, const char *name);
```

Форми `l*` мають той самий підпис; у формах `f*` перший аргумент — `int fd` замість шляху. Аргумент `flags` бере одне зі значень: `0` — записати байдуже як, `XATTR_CREATE` (`0x1`) — лише створити, і `EEXIST`, якщо атрибут уже є, `XATTR_REPLACE` (`0x2`) — лише замінити, і `ENODATA`, якщо його немає. Обидва біти разом — `EINVAL`.

Родина `*at` прийшла в ядрі 6.13 і, на відміну від решти [викликів із дескриптором каталогу](topic:unix-linux/at-family-syscalls), з'явилася не заради гонок у розборі шляху. Мотив — права: вона дає працювати з атрибутами через дескриптор, відкритий **без** права читання, і не потребує змонтованого `/proc`. Саме це потрібне утиліті `setfiles(8)`, коли та розставляє мітки [SELinux](topic:unix-linux/mac-selinux-apparmor) по щойно розпакованому дереву.

```c
#include <linux/xattr.h>     /* struct xattr_args */
#include <sys/syscall.h>

struct xattr_args {
    __aligned_u64 value;     /* вказівник на значення */
    __u32 size;              /* довжина значення */
    __u32 flags;             /* XATTR_CREATE / XATTR_REPLACE */
};

/* обгорток у glibc ще немає — кличуть через syscall() */
long syscall(SYS_setxattrat,    int dfd, const char *path, unsigned int at_flags,
                                const char *name, struct xattr_args *args, size_t size);
long syscall(SYS_getxattrat,    int dfd, const char *path, unsigned int at_flags,
                                const char *name, struct xattr_args *args, size_t size);
long syscall(SYS_listxattrat,   int dfd, const char *path, unsigned int at_flags,
                                char *list, size_t size);
long syscall(SYS_removexattrat, int dfd, const char *path, unsigned int at_flags,
                                const char *name);
```

Значення, його довжину й команду винесено в окрему структуру з двох причин відразу: шість аргументів системного виклику — стеля, а біти `AT_*` і `XATTR_*` не можна змішувати в одному слові. З `at_flags` ядро приймає рівно два біти — `AT_SYMLINK_NOFOLLOW` і `AT_EMPTY_PATH`; будь-який інший дає `EINVAL`, а не мовчазне ігнорування.

## Простори імен

Правило доступу задає префікс імені, і три з чотирьох рішень ухвалює не VFS.

| префікс | читання | запис | що там лежить |
|---|---|---|---|
| `user.` | право `r` на сам файл | право `w` на сам файл | будь-що від прикладних програм |
| `trusted.` | `CAP_SYS_ADMIN`, інакше атрибута ніби немає | `CAP_SYS_ADMIN` | службові дані поза очима власника файлу |
| `security.` | вирішує завантажений модуль безпеки | вирішує модуль; без жодного — `CAP_SYS_ADMIN` | мітки MAC, [можливості файлу](topic:unix-linux/capabilities), підписи цілісності |
| `system.` | вирішує файлова система | вирішує файлова система | ACL та інші структури самого ядра |

Три уточнення, без яких таблиця вводить в оману.

**VFS не обмежує `security.` і `system.` взагалі.** Це не недогляд, а межа відповідальності: що там лежить, VFS не знає, тож і судити не береться. Для списків доступу рішення ухвалює той самий код, що й для `chmod`: міняти може власник файлу або процес із `CAP_FOWNER`.

**`user.` не чіпляється до чого попало.** Дозволено звичайні файли й каталоги, і більше нічого; на символьному посиланні, файлі пристрою, каналі чи сокеті відмова буде `EPERM` при записі й `ENODATA` при читанні. Причина в обліку місця: байти атрибутів займають носій, а рахують його за власником файлу ([дискові квоти](topic:unix-linux/disk-quotas)), — у посилання ж власні біти прав узагалі не діють. Із цієї самої причини в каталозі з бітом `t` писати `user.`-атрибути може лише власник каталогу.

**Простір `system.` не приймає довільних імен.** Туди беруть тільки ті, для яких у ядрі є обробник; вигадане ім'я з таким префіксом дасть `ENOTSUP`. Списків доступу два:

```
system.posix_acl_access     список для самого об'єкта
system.posix_acl_default    шаблон для майбутніх нащадків, лише на каталозі
```

Від ядра 6.2 ці два імені всередині ядра йдуть окремим шляхом (`vfs_get_acl`, `vfs_set_acl`), а не через загальний механізм атрибутів. Для програми не змінилося нічого: ті самі імена, ті самі виклики, той самий двійковий вигляд значення.

## Межі

| межа | значення | де стоїть |
|---|---|---|
| довжина імені | 255 байтів (`XATTR_NAME_MAX`) | VFS |
| довжина значення | 64 КіБ (`XATTR_SIZE_MAX`) | VFS |
| увесь перелік імен від `listxattr` | 64 КіБ (`XATTR_LIST_MAX`) | VFS |
| ext2/3/4 | усі імена й значення одного файлу мусять уміститися в один блок (1024, 2048 або 4096 байтів) | ФС |
| ext4 з можливістю `ea_inode` | велике значення виноситься в окремий прихований inode-носій | ФС |
| Btrfs | ім'я плюс значення плюс службові байти ≤ nodesize (типово 16 КіБ) | ФС |
| XFS, Reiserfs | практичної межі на кількість немає; значення — до стелі VFS | ФС |
| JFS | значення — до стелі VFS | ФС |

Окремої сталої на кількість записів у списку доступу немає: список — таке саме значення, як усі інші, і його стеля випливає з бюджету файлової системи. У тому вигляді, який віддає `getxattr`, це чотирибайтова шапка з номером версії плюс рівно вісім байтів на запис. На носії ext4 тримає компактніше: чотири записи, яким ідентифікатор ні до чого — `user::`, `group::`, `mask::` й `other::`, — лежать без цього поля, по чотири байти. Тому розмір, який бачить програма, і місце, що його список з'їдає в блоці, — різні числа, і саме друге впирається в межу.

Наслідок для перенесення: «атрибути є» ще не означає «атрибути переживуть переїзд». Межі задає [конкретна файлова система](topic:unix-linux/filesystem-families), а не ядро згори.

## Коди помилок

| код | від кого | що це насправді |
|---|---|---|
| `ENOTSUP` (він же `EOPNOTSUPP`) | VFS або ФС | три різні речі під одним іменем: префікс не з чотирьох відомих; файлова система атрибутів не вміє; том змонтовано без потрібної опції |
| `ENODATA` (він же `ENOATTR`) | ФС | атрибута немає — **або** він є, але процесові його не видно (`trusted.` без привілею). Розрізнити ці два випадки неможливо, і це навмисно |
| `EEXIST` | ФС | `XATTR_CREATE`, а атрибут уже є |
| `ERANGE` | ФС або VFS | від `set*` — ім'я чи значення довше за межу цієї файлової системи; від `get*` і `list*` — замалий буфер програми. Перше лікується меншими даними, друге — більшим буфером |
| `E2BIG` | VFS | значення (або весь перелік імен) більше за все, що взагалі можна віддати. Більший буфер не допоможе — стеля не в ньому |
| `ENOSPC` | ФС | місця на носії під атрибут немає; у ext4 — типово «не влізло в блок» |
| `EDQUOT` | ФС | місце є, вичерпано квоту власника |
| `EPERM` | VFS | файл позначено `immutable` або `append-only` ([прапорці inode](topic:unix-linux/inode-flags-chattr)); або запис у `trusted.` без `CAP_SYS_ADMIN`; або `user.` не на тому типі об'єкта |
| `EACCES` | VFS | звичайна відмова за правами: немає `r` чи `w` на сам файл або права на прохід складником шляху |
| `EINVAL` | VFS | форма виклику: `XATTR_CREATE` разом із `XATTR_REPLACE`, невідомий біт у `at_flags` |

> 🔧 **Навіщо це.** `ENOTSUP` виводиться на екран як «Operation not supported» і читається як вирок файловій системі — а найчастіша його причина зовсім інша: ім'я подали без префікса. Команда `setfattr -n mime -v text/plain f` відмовить саме так, і скільки не переставляй опцій [монтування](topic:unix-linux/mount-model), не допоможе, бо треба `user.mime`. Тому розбір починають з імені, потім дивляться `/proc/mounts` і лише третім кроком підозрюють саму файлову систему.

Читання розміру наперед — окремий контракт: із `size == 0` виклики `getxattr` і `listxattr` нічого не пишуть у буфер, а повертають потрібну довжину. Проміжок між заміром і читанням не захищений нічим, тож повтор на `ERANGE` обов'язковий.

```c
/* значення атрибута в щойно виділеній пам'яті; NULL і errno при відмові */
static void *xattr_dup(const char *path, const char *name, ssize_t *out_len)
{
    for (int tries = 0; tries < 8; tries++) {
        ssize_t need = getxattr(path, name, NULL, 0);   /* лише розмір */
        if (need < 0)
            return NULL;                                /* ENODATA, ENOTSUP … */

        char *buf = malloc((size_t)need ? (size_t)need : 1);
        if (!buf)
            return NULL;

        ssize_t got = getxattr(path, name, buf, (size_t)need);
        if (got >= 0) {
            *out_len = got;
            return buf;
        }
        free(buf);
        if (errno != ERANGE)                            /* не гонка — здаємося */
            return NULL;
    }                                                   /* хтось активно пише — пробуємо ще */
    errno = ERANGE;
    return NULL;
}
```

Перелік імен від `listxattr` приходить одним шматком: рядки з нульовим байтом після кожного, без роздільників і без лічильника. Імена, до яких процес доступу не має, у переліку просто відсутні.

## Бібліотечний шар

`libattr` із пакета `attr` дає команди `getfattr` і `setfattr`, але власного заголовка `<attr/xattr.h>` уживати не варто: усі його функції давно живуть у glibc, і нова програма підключає `<sys/xattr.h>`, не додаючи в збирання нічого зайвого.

`libacl` — інша річ: вона тримає розібраний список як непрозорий об'єкт `acl_t` і бере на себе двійковий вигляд, текстову форму й перевірку повноти.

| виклик | підпис | що робить |
|---|---|---|
| `acl_get_file` | `acl_t acl_get_file(const char *path, acl_type_t type)` | читає `ACL_TYPE_ACCESS` або `ACL_TYPE_DEFAULT` |
| `acl_get_fd` | `acl_t acl_get_fd(int fd)` | те саме за дескриптором; лише access |
| `acl_from_text` | `acl_t acl_from_text(const char *buf)` | розбирає текстову форму |
| `acl_to_text` | `char *acl_to_text(acl_t acl, ssize_t *len)` | назад у текст, із позначками `#effective:` |
| `acl_calc_mask` | `int acl_calc_mask(acl_t *acl_p)` | ставить маску в об'єднання прав `group::` й усіх іменованих записів; якщо запису маски не було — додає |
| `acl_valid` | `int acl_valid(acl_t acl)` | перевіряє повноту |
| `acl_set_file` | `int acl_set_file(const char *path, acl_type_t type, acl_t acl)` | записує |
| `acl_delete_def_file` | `int acl_delete_def_file(const char *path)` | знімає шаблон із каталогу |
| `acl_free` | `int acl_free(void *obj)` | звільняє все, що повернули функції вище |

`acl_valid` вимагає рівно по одному записові `user::`, `group::` й `other::`, неповторних ідентифікаторів серед іменованих і — обов'язково — маски, щойно з'явився хоч один іменований запис. Звідси єдиний правильний порядок дій: спершу маска, потім перевірка.

```c
#include <sys/types.h>
#include <sys/acl.h>          /* збирати з -lacl */

static int set_acl_text(const char *path, const char *spec)
{
    acl_t acl = acl_from_text(spec);
    if (!acl)                       /* EINVAL — рядок не розібрався */
        return -1;

    int rc = -1;
    if (acl_calc_mask(&acl) == 0    /* без цього наступний рядок відмовить */
        && acl_valid(acl) == 0      /* EINVAL — бракує базових записів */
        && acl_set_file(path, ACL_TYPE_ACCESS, acl) == 0)
        rc = 0;

    acl_free(acl);                  /* errno зберігається */
    return rc;
}

/* set_acl_text(path, "u::rw-,u:hanna:rw-,g::r--,o::---"); */
```

## Командний рівень

`getfattr` і `setfattr` працюють з атрибутами, `getfacl` і `setfacl` — зі списками; перші дві бачать те, що роблять другі, бо це одне сховище.

| ключ `getfattr` | дія |
|---|---|
| `-n ім'я` | видати одне значення |
| `-d` (він же `--dump`) | видати всі, що збіглися з `-m` |
| `-m взірець` | фільтр імен регулярним виразом; **типово `^user\.`** |
| `-e text\|hex\|base64` | кодування значення на виводі |
| `-h` | не йти за символьним посиланням |
| `-R` | рекурсивно |
| `--absolute-names` | не зрізати початковий `/` в іменах файлів |

Типовий взірець `-m` — головна пастка цієї команди: `getfattr -d` на файлі зі списком доступу покаже порожньо, бо `system.posix_acl_access` під `^user\.` не підпадає. Потрібне `getfattr -m - -d`.

| ключ `setfattr` | дія |
|---|---|
| `-n ім'я -v значення` | записати |
| `-x ім'я` | зняти |
| `-h` | не йти за символьним посиланням |
| `--restore=файл` | відновити з дампу `getfattr --dump` |

Значення подають у трьох виглядах: у подвійних лапках — текст, з `0x` — шістнадцятковий, з `0s` — base64. Ім'я завжди з префіксом.

| ключ `setfacl` | дія |
|---|---|
| `-m специфікація` | додати або змінити записи |
| `-x специфікація` | зняти записи (поле прав не подають) |
| `-b` | зняти всі іменовані записи й маску, лишити три базові |
| `-k` | зняти шаблон із каталогу |
| `-d` | усе в цій команді стосується шаблону, а не самого списку |
| `-R` | рекурсивно |
| `--set` | замінити список цілком, а не доповнити |
| `-n` | не перераховувати маску |
| `--mask` | перерахувати маску навіть тоді, коли її задано явно |
| `--test` | нічого не міняти, показати наслідок |
| `--restore=файл` | відновити з дампу `getfacl -R` |

Специфікація має вигляд `u:ім'я:права`, `g:ім'я:права`, `m::права`, `o::права`; префікс `d:` робить запис шаблонним, і це рівносильне ключеві `-d`.

Найважливіше правило `setfacl` — про маску, і воно одне: **маска перераховується щоразу, коли команда міняє список, крім випадку, коли маску задано явно в цій самій команді.** Перерахунок ставить її в об'єднання прав `group::` й усіх іменованих записів — тобто піднімає рівно настільки, щоб щойно виданий доступ став чинним.

**Умова.** Файл із маскою `r--` після чужого `chmod g-w`; треба видати Ганні запис.

```sh
$ setfacl -m u:hanna:rw f       # маска підіймається до rw- сама
$ setfacl -n -m u:hanna:rw f    # запис додано, маска лишилася r-- → #effective:r--
$ setfacl -m u:hanna:rw,m::r f  # маска задана явно → r--, право w не діє
$ setfacl --mask -m m::r f      # явну маску все одно перерахує
```

Три з цих чотирьох команд ставлять у список однаковий запис `user:hanna:rw-` — і рівно одна з них дає Ганні змогу писати. Тому `-n` уживають тільки там, де маску тримають під власним наглядом: у відновленні з дампу, де вона вже записана, і в сценаріях, які виставляють увесь список цілком через `--set`.

`getfacl -R` разом із `setfacl --restore` — єдина пара, яка переносить права точно: перша друкує дамп із заголовками `# file:`, `# owner:`, `# group:` і обома списками, друга вкладає його назад. Через це її й уживають перед будь-якою масовою правкою — і на [мережевій файловій системі](topic:unix-linux/network-filesystems), де чужу модель прав переводять у цю з втратами, дамп лишається єдиним чесним записом того, як усе було.
