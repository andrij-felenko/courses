# 📋 Довідник синтаксису політик та SecurityFS TOMOYO Linux

Цей довідник містить точний опис синтаксису конфігураційних файлів TOMOYO Linux, масок шаблонів шляхів, операторів умов та структуру віртуальних файлів у підсистемі SecurityFS. Він є необхідним матеріалом для системних адміністраторів, інженерів з безпеки та розробників примусового контролю доступу під час створення, ручного редагування або програмного аналізу політик примусового контролю доступу (MAC) у ядрі Linux.

---

## 1. Інтерфейси SecurityFS: `/sys/kernel/security/tomoyo/`

Псевдофайлова система SecurityFS є основним мостом керування підсистемою TOMOYO між ядром Linux та користувацьким простором. Усі файли конфігурації у каталозі `/sys/kernel/security/tomoyo/` є віртуальними: запис у них транслюється ядрами у зміну внутрішніх структур даних у оперативній пам'яті (`kmalloc` / `vmalloc`), а зчитування генерує текстове представлення поточного стану внутрішніх таблиць безпеки.

| Файл у SecurityFS | Режим доступу | Призначення та детальний опис |
| :--- | :--- | :--- |
| `domain_policy` | Read / Write | Вміст усіх створених доменів та їхніх конкретних правил доступу (`file`, `network`, `capability`). Перегляд файлу повертає повний список доменів у вигляді дерева та активні правила для кожного з них. Запис одного або кількох рядків у цей файл додає нові дозволи до вказаного домену. |
| `exception_policy` | Read / Write | Глобальні правила винятків та метаструктури. Файл містить оголошення псевдонімів (`alias`), груп шляхів (`path_group`), груп номерів мережевих портів (`number_group`), виключення з автоматичного навчання (`no_learning_domain`), а також списки програм, для яких заборонено створення нових доменів. |
| `profile` | Read / Write | Конфігураційне визначення 256 можливих профілів безпеки. Для кожного профілю задаються режими виконання (`Disabled`, `Learning`, `Permissive`, `Enforcing`), пороги квот використаної пам'яті, ліміти логування та агресивність автоматичного узагальнення шляхів. |
| `manager` | Read / Write | Список доменів або абсолютних шляхів бінарних файлів, яким дозволено записувати у файли `/sys/kernel/security/tomoyo/`. Якщо процес не належить до доменів-менеджерів, будь-яка спроба модифікації конфігурації через SecurityFS блокується з поверненням помилки `EPERM`. |
| `stat` | Read Only | Лічильники статистики внутрішніх блокувань, кількості створених доменів у дереві, використаної обсягом пам'яті під правила доступу, лічильники відхилених запитів та активні квоти. |
| `audit` | Read Only | Потік аудит-повідомлень у реальному часі. У файл виводяться деталізовані записи про події, які були відхилені у режимі `Enforcing` або зафіксовані у режимах `Permissive` та `Learning`. |
| `version` | Read Only | Повертає рядок версії ядерного інтерфейсу TOMOYO (наприклад, `2.5.0` для сучасних ядер Linux). Використовується утилітами `tomoyo-tools` для перевірки сумісності API. |

## 2. Синтаксис та структура файлу domain_policy

Файл `domain_policy` складається з послідовності блоків доменів. Заголовок кожного блоку починається з унікального імені домену, яке відображає абсолютний ланцюжок викликів `execve()` від моменту завантаження ядра. Після імені домену розміщуються служебні директиви домену та список індивідуальних дозволів на файлові, мережеві та системні операції.

```text
<kernel> /sbin/init /usr/sbin/sshd
use_profile 3
use_group 0
file read /etc/ssh/sshd_config
file read /etc/passwd
file read /etc/shadow
file execute /bin/bash
network inet stream listen 22
network inet stream accept 22
capability net_bind_service
```

### Прапорці та директиви домену

Кожен блок домену може містити спеціальні налаштування, які керують успадкуванням та режимами роботи:

- `use_profile <N>` — призначає профіль з номером `N` (від `0` до `255`) для даного домену. Профіль визначає, чи працює домен у режимі навчання, блокування або спостереження.
- `use_group <N>` — вказує групу винятків та стандартних дозволів із `exception_policy`, яка автоматично застосовується до цього домену.
- `quota_exceeded` — прапорець ядра, який автоматично виставляється ядром, якщо в режимі навчання перевищено максимально припустимий обсяг пам'яті, виділений під зберігання нових правил у даному домені. Після встановлення цього прапорця нові правила перестають додаватися до досягнення очищення.
- `transition_failed` — прапорець, що сигналізує про помилку виконання переходу між доменами при виклику `execve()`.

## 3. Маски та шаблони шляхів (Wildcards)

Для запобігання надмірному розростанню політик та створення гнучких правил TOMOYO підтримує спеціальний набір метасимволів у файлових шляхах. Зіставлення масок виконується у внутрішньому коді ядра шляхом посимвольного порівняння канонічного рядка VFS з шаблоном.

| Символ маски | Значення та поведінка зіставлення | Детальний приклад використання |
| :--- | :--- | :--- |
| `\*` | Будь-які символи **в межах одного каталогу**. Не перетинає символ роздільника каталогу `/`. | Шаблон `/var/log/\*` вказує на файли `/var/log/syslog` та `/var/log/messages`, але **не** охоплює підкаталог `/var/log/nginx/access.log`. |
| `\{\*\}` | Рекурсивне зіставлення будь-яких символів, **включаючи роздільники `/`**. | Шаблон `/var/log/\{\*\}` охоплює абсолютно всі файли, підкаталоги та вкладені файли всередині `/var/log/` на будь-яку глибину. |
| `\?` | Рівно один довільний символ (крім роздільника каталогу `/`). | Шаблон `/tmp/file\?` відповідає `/tmp/file1`, `/tmp/fileA`, але не відповідає `/tmp/file12`. |
| `\$` | Збіг із послідовністю десяткових цифр (`0-9`). | Шаблон `/proc/\$/status` відповідає `/proc/1/status`, `/proc/1234/status` для будь-якого числового PID. |
| `\X` | Збіг із послідовністю шістнадцяткових цифр (`0-9`, `a-f`, `A-F`). | Шаблон `/dev/shm/sem.\X` відповідає розділюваній пам'яті або семафорам типу `/dev/shm/sem.a1f4`. |
| `\A` | Збіг із будь-якою буквою алфавіту (`a-z`, `A-Z`). | Шаблон `/tmp/log_\A` відповідає `/tmp/log_a`, `/tmp/log_B`. |

## 4. Категорії правил та оператори дозволів

TOMOYO розділяє правила доступу на кілька основних категорій: файлові операції, мережева взаємодія, POSIX capabilities та системні операції.

### 4.1 Файлові операції (`file`)

Синтаксис файлових правил: `file <operation> <path1> [<path2>] [<mode>]`

- `file read <path>` — право на відкриття файлу для зчитування вмісту (системні виклики `open`, `openat` із прапорцями `O_RDONLY` або `O_RDWR`).
- `file write <path>` — право на відкриття файлу для запису або модифікації даних (прапорці `O_WRONLY` або `O_RDWR`).
- `file append <path>` — право на дописування даних у кінець файлу (режим `O_APPEND`). Вважається більш безпечним ніж `write`, оскільки не дозволяє перезаписувати існуючий вміст.
- `file create <path> <mode>` — право на створення нового файлу з вказаними масками прав доступу `mode` (наприклад, `file create /tmp/\* 0644`).
- `file execute <path>` — право на виконання бінарного файлу (системний виклик `execve()`), що ініціює перехід до нового піддомену.
- `file execute_by_mmap <path>` — право на мапування файлу в оперативну пам'ять із виконанням (системний виклик `mmap` із прапорцем `PROT_EXEC`). Використовується при завантаженні динамічних бібліотек (`.so`).
- `file unlink <path>` — право на видалення файлу з файлової системи (`unlink`, `unlinkat`).
- `file mkdir <path> <mode>` — право на створення нового каталогу (`mkdir`).
- `file rmdir <path>` — право на видалення порожнього каталогу (`rmdir`).
- `file link <target> <link_name>` — право на створення жорсткого посилання (`hardlink`) між `target` та `link_name`.
- `file rename <old_path> <new_path>` — право на перейменування чи переміщення файлу з `old_path` у `new_path`.
- `file mount <device> <dir> <type> <flags>` — право на монтування файлової системи `type` з пристрою `device` у каталог `dir`.
- `file pivot_root <new_root> <old_root>` — право на зміну кореневої файлової системи.
- `file chroot <path>` — право на зміну кореневого каталогу процесу (`chroot`).
- `file ioctl <path> <cmd>` — право на виконання низькорівневих викликів `ioctl` над файлом або пристроєм із конкретним кодом команди.

### 4.2 Мережеві операції (`network`)

Синтаксис мережевих правил: `network <domain> <type> <operation> <address> <port>`

- `network inet stream bind <ip> <port>` — прив'язка TCP-сокета до конкретної IP-адреси та мережевого порту.
- `network inet stream listen <port>` — переведення TCP-сокета у режим прослуховування вхідних з'єднань.
- `network inet stream accept <ip> <port>` — прийняття вхідного TCP-з'єднання від віддаленого вузла `ip` на порт `port`.
- `network inet stream connect <ip> <port>` — встановлення вихідного TCP-з'єднання з віддаленим сервером.
- `network inet dgram send <ip> <port>` — відправка UDP-датаграми на віддалену адресу.
- `network inet dgram recv <ip> <port>` — отримання UDP-датаграми.
- `network unix stream connect <socket_path>` — підключення до UNIX-сокета за вказаним шляхом у файловій системі.

### 4.3 Привілеї та системні операції (`capability` та `misc`)

- `capability <cap_name>` — дозвіл на використання специфічного привілею POSIX Capability (наприклад, `capability net_bind_service`, `capability sys_admin`, `capability dac_override`, `capability sys_chroot`). Якщо у домені відсутній відповідний рядок `capability`, ядро блокує виконання привілейованого виклику навіть для процесів із `UID=0` (`root`).
- `misc env <name>` — право на зчитування або модифікацію конкретної змінної оточення процесу під час виконання.

## 5. Конструкції умов (Conditional Access Control)

TOMOYO підтримує розширений синтаксис контекстних умов, які дозволяють застосовувати правила лише при збігу системних параметрів виконання. Умова додається в кінець правила за допомогою ключового слова `if`.

```text
file read /etc/shadow if task.uid=0
file write /var/log/app.log if task.uid=1000 task.gid=1000
file execute /usr/bin/python3 if exec.realpath="/usr/bin/python3.10"
file read /tmp/\* if file.uid=task.uid
```

### Основні параметри умов:

- `task.uid` / `task.gid` — реальний ідентифікатор користувача (`UID`) або групи (`GID`) процесу, що виконує операцію.
- `task.euid` / `task.egid` — ефективний ідентифікатор користувача (`EUID`) або групи (`EGID`) процесу.
- `file.uid` / `file.gid` — власник цільового файлу або каталогу на диску.
- `file.mode` — числове значення Unix-прав доступу об'єкта (наприклад, `0644`).
- `exec.realpath` — канонізований абсолютний шлях виконуваного файлу при переході `execve()`. Використовується для запобігання підміні символьних посилань.

## 6. Конфігурація профілів (`profile.conf`)

Файл `profile.conf` визначає глобальні параметри для кожного з 256 профілів безпеки TOMOYO. 

```text
0::mode=0
1::mode=1
2::mode=2
3::mode=3

# Деталізоване налаштування параметрів для Профілю 3 (Enforcing)
3:file::mode=3
3:network::mode=3
3:capability::mode=3
3:file:max_learning_entry=2048
3:file:max_audit_log=1024
```

Значення параметрів `mode`:
- `0` — **Disabled** (вимкнено: перевірки відсутні).
- `1` — **Learning** (навчання: дозволяється все з додаванням нових правил).
- `2` — **Permissive** (спостереження: дозволяється все з логуванням порушень).
- `3` — **Enforcing** (захист: заборонені дії блокуються з поверненням помилки).
