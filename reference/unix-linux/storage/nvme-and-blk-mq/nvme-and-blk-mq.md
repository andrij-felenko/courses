# Підсистема NVMe та багаточерговий блочний шар (blk-mq)

NVMe-накопичувачі відрізняються від старих дисків (SATA/SAS) тим, що підтримують до 64 тисяч апаратних черг. Щоб скористатися цим на багатоядерних системах без затримок на блокування, у ядрі Linux використовується архітектура **blk-mq** (Block Multi-Queue).

## Рівні черг

blk-mq вводить два рівні черг для розподілу навантаження:
1. **Програмні черги (Software Staging Queues):** Кожне ядро CPU має свою власну програмну чергу. Процеси відправляють I/O запити у чергу свого процесора, усуваючи необхідність блокування (lock contention) між ядрами.
2. **Апаратні черги (Hardware Dispatch Queues):** Вони відображаються на реальні апаратні черги подачі/завершення (SQ/CQ) NVMe контролера. 

Драйвер NVMe у Linux зазвичай налаштовує пряме відображення 1:1 — одна апаратна черга на кожне логічне ядро CPU. Завдяки підтримці **NUMA Affinity**, переривання обробляються на тому ж вузлі пам'яті, що мінімізує затримки.

## Як проходить запит

Коли запит проходить програмну чергу, blk-mq передає його драйверу NVMe через функцію `queue_rq`. Драйвер формує команду та записує її в Submission Queue пристрою. 

```c
== C (Ядро)
// Формування команди та запис у SQ
nvme_setup_cmd(req, &cmnd);
nvme_sq_copy_cmd(nvmeq, &cmnd);
// Повідомлення пристрою (Doorbell)
nvme_write_sq_db(nvmeq);
== Shell (Перевірка)
# Перегляд черг для nvme0n1
ls /sys/block/nvme0n1/mq/
```

Після виконання контролер сповіщає ядро через MSI-X переривання, або ядро може використовувати механізм опитування (polling) для ультранизьких затримок. Планувальники вводу-виводу для NVMe зазвичай вимикають (режим `none`), оскільки апаратні черги забезпечують максимальну продуктивність.
