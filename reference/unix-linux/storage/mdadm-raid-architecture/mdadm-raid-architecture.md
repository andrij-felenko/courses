# Архітектура програмного RAID (mdadm)

Програмний RAID у Linux реалізується через драйвер **Multiple Devices (MD)** у ядрі. Він дозволяє об'єднувати кілька фізичних блокових пристроїв (дисків або розділів) в один логічний пристрій `/dev/mdX`. Утиліта користувацького простору **`mdadm`** керує цими пристроями, створюючи та налаштовуючи масиви.

## Драйвер MD і рівні RAID

Ядро Linux за допомогою підсистеми MD абстрагує роботу з масивами дисків, реалізуючи логіку різних рівнів RAID. Основна перевага — незалежність від апаратного контролера.

- **RAID 0 (Stripe):** Дані розбиваються на блоки (stripes) і записуються по черзі на всі диски. Максимальна швидкість, але втрата одного диска руйнує весь масив.
- **RAID 1 (Mirror):** Дані дублюються на всі диски масиву. Зчитування може балансуватися, а надійність дуже висока. Об'єм дорівнює розміру найменшого диска.
- **RAID 5:** Дані розбиваються на блоки разом з блоками парності (parity). Дозволяє пережити вихід з ладу одного диска. Запис повільніший через обчислення парності.
- **RAID 6:** Схожий на RAID 5, але використовує два незалежні блоки парності. Дозволяє втратити два диски.
- **RAID 10:** Комбінація RAID 1 та RAID 0. Диски об'єднуються у дзеркала, з яких потім будується страйп. Висока продуктивність та надійність, але потрібна парна кількість дисків (мінімум 4).

## Механізми надійності: Resync, Bitmap та Spare

Коли диск виходить з ладу, масив переходить у режим деградації. Після заміни диска запускається процес **resync** (або rebuild) — відновлення даних на новому пристрої з інших дисків.

Щоб пришвидшити синхронізацію при тимчасовому відключенні диска (наприклад, збій кабелю), використовується **Write-intent bitmap** (карта намірів запису). Це структура даних, яка відстежує, які блоки були змінені під час відсутності диска. Замість повної перевірки всього масиву синхронізуються лише змінені блоки.

Для мінімізації часу деградації застосовують **Spare drives** — гарячі резервні диски. Вони підключені до системи, але не використовуються, поки якийсь диск не вийде з ладу. Тоді драйвер MD автоматично вводить spare-диск у масив і починає відбудову.

## Приклади керування через mdadm

Ось базові операції для роботи з масивами.

```bash
mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sda1 /dev/sdb1
```

Конфігурація масивів зазвичай зберігається у `/etc/mdadm/mdadm.conf`, щоб система могла автоматично збирати їх під час завантаження.
