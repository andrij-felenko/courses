# 📋 Довідник інтерфейсу tracefs та синтаксису фільтрів і тригерів

Файлова система `tracefs` (за замовчуванням змонтована за віртуальним шляхом `/sys/kernel/tracing` або за застарілим шляхом `/sys/kernel/debug/tracing`) надає декларативний текстовий інтерфейс (API) для налаштування, керування та отримання даних підсистеми трасування ядра Linux. На відміну від звичайних файлових систем, файли у `tracefs` є віртуальними вказівниками на внутрішні структури даних ядра. Налаштування підсистеми здійснюється шляхом запису спеціально сформованих текстових рядків у відповідні віртуальні файли керування, а вивантаження результатів трасування — шляхом читання вмісту файлів буфера.

## 1. Головні керуючі файли `/sys/kernel/tracing`

Для керування загальним станом ftrace використовуються файли верхнього рівня у каталозі `/sys/kernel/tracing`. Нижче наведено їхній повний перелік, права доступу та детальні сценарії використання.

### `available_tracers`
Права доступу: `r--r--r--`. Повертає список усіх плагінів-трасерів, які були включені до складу ядра під час компіляції (конфігураційні параметри `CONFIG_FUNCTION_TRACER`, `CONFIG_FUNCTION_GRAPH_TRACER`, `CONFIG_HWLAT_TRACER` тощо). Для перегляду доступних плагінів виконують команду `cat available_tracers`. Стандартний вивід містить такі значення:
- `function`: Трасер входу у C-функції ядра.
- `function_graph`: Трасер входу та виходу з побудовою дерева викликів.
- `hwlat`: Трасер апаратних затримок та переривань SMI.
- `blk`: Трасер блокового вводу-виводу.
- `mmiotrace`: Трасер викликів читання й запису в пам'ять пристроїв MMIO.
- `wakeup`, `wakeup_dl`, `wakeup_rt`: Трасери латентності розбудження процесів.
- `nop`: Порожній трасер за замовчуванням (трасування вимкнено).

### `current_tracer`
Права доступу: `rw-r--r--`. Дозволяє прочитати назву поточного активного плагіна або встановити новий плагін шляхом запису його назви у файл. Наприклад, команда `echo function_graph > current_tracer` активує плагін побудови графіків викликів. Перед зміною активного трасера рекомендується тимчасово вимикати запис подій через файл `tracing_on`.

### `tracing_on`
Права доступу: `rw-r--r--`. Глобальний вимикач запису подій у кільцеві буфери ядра. При записі значення `1` ядро починає записувати події у кільцевий буфер. При записі значення `0` запис подій миттєво призупиняється, але зібраний раніше вміст буфера зберігається у пам'яті. Використовується для атомарного зупинення трасування під час виявлення помилок.

### `trace`
Права доступу: `rw-r--r--`. Текстове представлення накопиченого вмісту кільцевого буфера. Зчитування цього файлу повертає зафіксовані події у зручному для читача форматі із зазначенням імені процесу, PID, номера CPU, часової мітки та назви події. Читання файлу `trace` не видаляє дані з буфера. Запис значення `0` у цей файл (`echo 0 > trace`) виконує повне очищення вмісту кільцевого буфера для всіх ядер CPU.

### `trace_pipe`
Права доступу: `r--r--r--`. Потоковий інтерфейс для моніторингу подій у реальному часі. На відміну від `trace`, читання з `trace_pipe` є блокуючою операцією: потік очікує появи нових подій у ядрі. Зчитування кожної події з `trace_pipe` видаляє її з кільцевого буфера (споживання подій). Якщо файл відкривають кілька процесів одночасно, події розподіляються між ними.

### `trace_marker`
Права доступу: `-w--w--w-`. Інтерфейс для довільного запису з юзерпростору. Будь-який текстовий рядок, записаний у цей файл привілейованим або звичайним (за відповідних прав) процесом, негайно потрапляє у кільцевий буфер ftrace із точною часовою міткою ядра. Застосовується для маркування етапів виконання програм юзерпростору (бенчмарків) на часовій шкалі ядра.

### `buffer_size_kb`
Права доступу: `rw-r--r--`. Задає розмір кільцевого буфера у кілобайтах *в розрахунку на кожне ядро CPU*. За замовчуванням значення становить від 1408 KB до 4096 KB. Запис нового значення (наприклад, `echo 8192 > buffer_size_kb`) призводить до динамічного перерозподілу сторінок пам'яті в ядрі. Якщо у системі присутні 8 ядер, під буфери буде виділено `8 * 8192 KB = 64 MB` оперативної пам'яті.

### `buffer_total_size_kb`
Права доступу: `r--r--r--`. Інформаційний файл, який повертає загальний розмір оперативної пам'яті у кілобайтах, виділений під кільцеві буфери ftrace для всіх ядер процесора сумарно.

### `tracing_cpumask`
Права доступу: `rw-r--r--`. Шістнадцяткова бітова маска, яка визначає, з яких саме ядер CPU дозволено збирати події трасування. Наприклад, маска `0xf` вказує збирати дані лише з перших чотирьох ядер (CPU 0–3). Це дозволяє ізолювати трасування лише на потрібних ядрах і зменшити обсяг даних.

### `set_ftrace_filter` та `set_ftrace_notrace`
Права доступу: `rw-r--r--`. Файли керування білим та чорним списками C-функцій для плагінів `function` та `function_graph`. Запис імені функції у `set_ftrace_filter` дозволяє трасувати лише обрану функцію. Підтримуються шаблони із зірочкою `*` (наприклад, `echo "vfs_*" > set_ftrace_filter`). Файл `set_ftrace_notrace` має протилежну дію і виключає зазначені функції з трасування. Для очищення списку фільтрації у файл записують порожній рядок.

### `set_ftrace_pid` та `set_ftrace_no_pid`
Права доступу: `rw-r--r--`. Дозволяють обмежити трасування функцій лише тими процесами, чий ідентифікатор PID міститься у списку. Це запобігає засміченню буфера подіями від сторонніх системних служб.

### `set_graph_function` та `set_graph_notrace`
Права доступу: `rw-r--r--`. Спеціалізовані файли для плагіна `function_graph`. Запис функції у `set_graph_function` змушує ftrace будувати дерево викликів лише для цієї функції та її внутрішніх підфункцій, ігноруючи решту викликів ядра.

## 2. Фільтрація подій (Event Filtering Syntax)

Для кожної трасувальної точки у каталозі `events/<підсистема>/<подія>/` міститься файл `filter`. Запис виразу у цей файл дозволяє здійснювати фільтрацію подій на рівні ядра до їх потрапляння у кільцевий буфер.

### Оператори та синтаксис фільтрів
- **Порівняння:** `==`, `!=`, `<`, `<=`, `>`, `>=`
- **Побітові оператори:** `&`
- **Логічні зв'язки:** `&&`, `||`
- **Порівняння рядків:** `~` (збіг із маскою), `!~` (невідповідність масці)

### Структура доступних полів
Для перегляду полів, доступних для фільтрації конкретної події, слід прочитати вміст файлу `format` у каталозі відповідної події. Усі події мають загальні поля:
- `common_pid`: PID поточного процесу.
- `common_comm`: Назва поточного процесу.
- `common_type`: Внутрішній числовий тип події.

Крім того, кожна подія має свої специфічні поля. Наприклад, для події `sys_enter_openat` доступні поля `dfd`, `filename`, `flags`, `mode`.

### Приклади побудови виразів фільтрації

```bash
# 1. Фільтрувати події перемикання контексту: лише коли наступний процес має PID 1234
echo "next_pid == 1234" > /sys/kernel/tracing/events/sched/sched_switch/filter

# 2. Фільтрувати системний виклик openat: лише коли прапорці містять O_CREAT (0x40) і назва починається не з /tmp
echo "(flags & 0x40) && filename !~ \"/tmp/*\"" > /sys/kernel/tracing/events/syscalls/sys_enter_openat/filter

# 3. Фільтрувати події виділення сторінок пам'яті: лише для викликів з обсягом більше 8 сторінок
echo "order > 3" > /sys/kernel/tracing/events/kmem/mm_page_alloc/filter

# 4. Повне скасування фільтра
echo 0 > /sys/kernel/tracing/events/sched/sched_switch/filter
```

## 3. Тригери подій (Event Triggers Syntax)

Файл `events/<підсистема>/<подія>/trigger` надає можливість призначити виконання певної автоматичної дії у момент настання події ядра.

### Основні типи тригерів

1. **`traceon` / `traceoff`:** Динамічне увімкнення або вимкнення глобального запису в буфер при виконанні умови.
   ```bash
   # Зупинити трасування, якщо системний виклик read повертає від'ємний код помилки
   echo "traceoff if ret < 0" > /sys/kernel/tracing/events/syscalls/sys_exit_read/trigger
   ```

2. **`snapshot`:** Збереження аварійного знімка кільцевого буфера. При настанні події ядро міняє місцями основний кільцевий буфер і фоновий буфер-знімок, заморожуючи стан траси.
   ```bash
   # Зберегти знімок траси у момент помилки виділення пам'яті
   echo "snapshot" > /sys/kernel/tracing/events/kmem/mm_page_alloc_zone_locked/trigger
   ```

3. **`stacktrace`:** Автоматичний запис повного стеку викликів ядра у буфер під час надання події.
   ```bash
   # Фіксувати стек викликів ядра при кожному створенні дочірнього процесу
   echo "stacktrace" > /sys/kernel/tracing/events/sched/sched_process_fork/trigger
   ```

4. **`enable_event` / `disable_event`:** Динамічне вмикання або вимикання іншої події при настанні поточної.
   ```bash
   # Вмикати трасування мережевих пакетів лише після виклику connect
   echo "enable_event:net:netif_receive_skb" > /sys/kernel/tracing/events/syscalls/sys_enter_connect/trigger
   ```

5. **Гістограми `hist`:** Агрегація статистики подій безпосередньо у пам'яті ядра. Дозволяє підраховувати частоту подій за ключами без виведення потоку логів у юзерпростір.
   ```bash
   # Побудувати гістограму розподілу викликів read за логарифмічним розміром запрошуваного буфера (count)
   echo "hist:keys=count.log2" > /sys/kernel/tracing/events/syscalls/sys_enter_read/trigger

   # Прочитати результати агрегованої гістограми
   cat /sys/kernel/tracing/events/syscalls/sys_enter_read/hist
   ```

## 4. Динамічні точки трасування `kprobe_events` та `uprobe_events`

Дозволяють додавати нові точки трасування "на льоту" у довільні ділянки машинного коду ядра чи юзерпростірних бінарників без перезбирання коду.

### Синтаксис `kprobe_events` (`/sys/kernel/tracing/kprobe_events`)
Формат запису:
`p|r[:[ГРУПА/]ПОДІЯ] [МОДУЛЬ:]СИМВОЛ[+ЗСУВ] [АРГУМЕНТИ]`

- `p`: kprobe (перехоплення входу у функцію)
- `r`: kretprobe (перехоплення виходу та значення, що повертається)
- `АРГУМЕНТИ`: `назва=%регістр`, `*адреса`, `+зсув(%регістр):тип`

```bash
# 1. Трасувати вхід у функцію do_sys_openat2, витягуючи аргумент dfd з регістру %di та шлях до файлу з %si
echo 'p:my_open do_sys_openat2 dfd=%di filename=+0(%si):string' >> /sys/kernel/tracing/kprobe_events

# 2. Трасувати значення, що повертає функція do_sys_openat2 (регістр %ax)
echo 'r:my_open_ret do_sys_openat2 ret=$retval' >> /sys/kernel/tracing/kprobe_events

# 3. Активація створеної динамічної події
echo 1 > /sys/kernel/tracing/events/kprobes/my_open/enable

# 4. Видалення динамічної точки трасування
echo 0 > /sys/kernel/tracing/events/kprobes/my_open/enable
echo '-:kprobes/my_open' >> /sys/kernel/tracing/kprobe_events
```

### Синтаксис `uprobe_events` (`/sys/kernel/tracing/uprobe_events`)
Формат запису:
`p|r[:[ГРУПА/]ПОДІЯ] ШЛЯХ_ДО_БІНАРНИКА:ЗСУВ [АРГУМЕНТИ]`

```bash
# 1. Трасувати виклик функції malloc у спільній бібліотеці libc.so.6 за її інструкційним зсувом
echo 'p:my_malloc /lib/x86_64-linux-gnu/libc.so.6:0x9b120 size=%di' >> /sys/kernel/tracing/uprobe_events

# 2. Увімкнути динамічний uprobe
echo 1 > /sys/kernel/tracing/events/uprobes/my_malloc/enable
```

Для повного видалення всіх створених динамічних точок трасування у файли записують порожній рядок:
`echo > /sys/kernel/tracing/kprobe_events`
`echo > /sys/kernel/tracing/uprobe_events`
