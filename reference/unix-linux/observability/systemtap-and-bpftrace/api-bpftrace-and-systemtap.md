# 📋 Довідник мов SystemTap та bpftrace: синтаксис, проби та агрегації

Цей довідник містить повну технічну специфікацію інтерфейсів, синтаксичних конструкцій, вбудованих змінних, типів проб, специфікацій мап та функцій агрегації для інструментів високорівневого трасування **bpftrace** та **SystemTap**.

## Специфікація мови та CLI bpftrace

Утиліта `bpftrace` використовує предметно-орієнтовану мову (DSL), натхненну мовами AWK та C. Програма складається з одного або декількох блоків прощупування (probes), предикатів (фільтрів) та дій (actions).

### Формат командного рядка CLI

```bash
bpftrace [опції] [файл_скрипта.bt]
bpftrace [опції] -e 'код_скрипта'
```

Основними прапорцями керування `bpftrace` є:
- `-e 'program'`: виконати однорядковий скрипт, переданий безпосередньо в аргументі.
- `-l [search_pattern]`: вивести список усіх доступних точок інструментації (probes), що відповідають масці з використанням wildcards (`*`).
- `-v`: увімкнути вербальний вивід (деталізація розгортання AST, згенерованого LLVM IR та етапів завантаження BPF-програм).
- `-d`: виконати сухий запуск з виводом розкомпільованого байткоду eBPF без його завантаження в ядро (корисно для аналізу роботи верифікатора).
- `-B MODE`: налаштувати режим буферизації виводу (`line` — порядно, `full` — повна буферизація, `none` — без буферизації).
- `-o FILE`: перенаправити результат трасування у вказаний файл замість стандартного виводу.
- `-c 'command'`: запустити вказану команду у дочірньому процесі та автоматично завершити трасування після її завершення.
- `-p PID`: приєднати утиліти до вказаного існуючого процесу за його PID.
- `--usdt-file-activation`: увімкнути активацію USDT проб через аналіз файлових відображень безпосередньо у процесі.

### Загальний синтаксис скрипта

```awk
probe_type:target /predicate/ {
    action_statements;
}
```

Предикат `/predicate/` є опціональним логічним виразом. Обробник у фігурних дужках виконується лише тоді, коли предикат повертає істинне значення (non-zero).

### Система типів у bpftrace

Мова bpftrace підтримує як примітивні, так і складені типи даних:
- **Цілочисельні типи**: `int8`, `int16`, `int32`, `int64`, `uint8`, `uint16`, `uint32`, `uint64`. Значення автоматично приводяться до 64-бітних регістрів eBPF.
- **Рядкові типи (`string`)**: фіксовані масиви символів (за замовчуванням до 64 байтів, регулюється змінною середовища `BPFTRACE_MAX_STRLEN`).
- **Указники (`pointers`)**: типізовані або нетипізовані адреси пам'яті (`uint8*`, `struct task_struct*`). Зчитування з вказівників ядра або користувача автоматично транспонується через безпечні помічники eBPF.
- **Кортежі (`tuples`)**: впорядковані набори типів, що використовуються як складні ключі для мап, наприклад `(pid, comm)`.
- **Структури (`struct`)**: підтримка C-структур ядра або користувацького коду при включенні відповідних заголовочних файлів або зчитуванні з BTF.

### Типи проб (Probe Specifiers)

| Специфікатор проби | Опис та параметри | Приклад використання |
| :--- | :--- | :--- |
| `kprobe:function` | Динамічне перехоплення на вході в функцію ядра | `kprobe:vfs_read` |
| `kretprobe:function` | Динамічне перехоплення при поверненні з функції ядра | `kretprobe:vfs_read` |
| `fentry:function` | Швидке перехоплення на вході в функцію ядра (через BPF trampoline) | `fentry:vfs_read` |
| `fexit:function` | Швидке перехоплення при поверненні з функції ядра (через BPF trampoline) | `fexit:vfs_read` |
| `tracepoint:subsys:event` | Статична точка трасування ядра | `tracepoint:syscalls:sys_enter_openat` |
| `rawtracepoint:event` | Низькорівнева статична точка трасування ядра без обробки `args` | `rawtracepoint:sys_enter` |
| `uprobe:path:fn` | Динамічне перехоплення функції в бінарному файлі/бібліотеці userspace | `uprobe:/lib/x86_64-linux-gnu/libc.so.6:malloc` |
| `uretprobe:path:fn` | Перехоплення при поверненні з функції користувацького простору | `uretprobe:/bin/bash:readline` |
| `usdt:path:provider:name` | Статична точка інструментації простору користувача (USDT) | `usdt:/usr/sbin/mysqld:mysql:query__start` |
| `profile:hz:rate` | Профілювання усіх CPU за таймером з частотою Гц | `profile:hz:99` |
| `interval:s:N` / `ms:N` | Періодичний таймер виконання у просторі користувача | `interval:s:5` |
| `software:event:count` | Перехоплення подій програмних лічильників ядра | `software:page-faults:1` |
| `hardware:event:count` | Перехоплення апаратних подій профілювальника CPU | `hardware:cache-misses:10000` |
| `BEGIN` / `END` | Спеціальні події, що виконуються при старті та завершенні скрипта | `BEGIN { printf("Start\n"); }` |

### Вбудовані змінні (Built-in Variables)

- `pid`: ідентифікатор поточного процесу (Process ID, 32 біти).
- `tid`: ідентифікатор поточного потоку виконання (Thread ID, 32 біти).
- `uid`: ідентифікатор користувача, від імені якого виконується поточний процес.
- `gid`: ідентифікатор групи поточного процесу.
- `nsecs`: поточна позначка часу у наносекундах від моменту завантаження системи (`monotic clock`).
- `elapsed`: час у наносекундах від моменту запуску поточного скрипта bpftrace.
- `cpu`: номер логічного ядра CPU, на якому виконується обробник події.
- `comm`: ім'я поточного процесу (рядковий масив до 16 символів).
- `kstack`: стек викликів ядра (Kernel Stack Backtrace).
- `ustack`: стек викликів користувацького простору (User Stack Backtrace).
- `arg0` .. `arg9`: аргументи функції для `kprobe`/`uprobe` (відповідно до ABI викликів x86_64 чи ARM64).
- `retval`: значення, що повертається функцією у `kretprobe`/`uretprobe`/`fexit`.
- `args`: структура аргументів для статичних `tracepoint` (доступ до полів через `args->field_name`).
- `curtask`: вказівник на структуру ядра `struct task_struct` поточного процесу.
- `username`: ім'я користувача у системі.

### Вбудовані функції дій та роботи з пам'яттю

- `printf(fmt, ...)`: форматований вивід рядка у консоль користувача.
- `time(fmt)`: вивід поточного реального часу (Wall Time) за налаштованим форматом `strftime`.
- `join(array, sep)`: об'єднання елементів масиву рядків через роздільник.
- `str(ptr [, len])`: зчитування занульованого рядка з адреси в пам'яті ядра або користувача.
- `buf(ptr, len)`: зчитування сирого бінарного буфера вказаної довжини.
- `ksym(addr)`: резолюція віртуальної адреси ядра у текстове ім'я символу.
- `usym(addr)`: резолюція віртуальної адреси користувацького простору у ім'я символу.
- `kaddr(symbol_name)`: пошук віртуальної адреси символу ядра за його іменем.
- `uaddr(symbol_name)`: пошук віртуальної адреси символу у виконуваному файлі.
- `system(fmt, ...)`: виконання зовнішньої команди у просторі користувача.
- `override(rc)`: підміна значення, що повертається системним викликом (потрібен режим перебування у безпечному контексті).
- `signal(sig_name_or_num)`: відправка POSIX-сигналу поточному процесу.
- `exit()`: безпечне завершення роботи скрипта bpftrace.

### Функції агрегації BPF Maps

Асоціативні мапи в bpftrace позначаються префіксом `@`. Вони автоматично агрегують дані у ядрі:

- `@map[key] = count()`: підрахунок кількості подій для кожного ключа.
- `@map[key] = sum(val)`: обчислення суми значень `val`.
- `@map[key] = avg(val)`: обчислення середнього арифметичного значення `val`.
- `@map[key] = min(val)`: фіксація мінімального знайденого значення.
- `@map[key] = max(val)`: фіксація максимального знайденого значення.
- `@map[key] = stats(val)`: одночасне обчислення кількості, суми та середнього значення.
- `@map[key] = hist(val)`: побудова логарифмічної гістограми за степенями 2.
- `@map[key] = lhist(val, min, max, step)`: побудова лінійної гістограми у діапазоні від `min` до `max` з кроком `step`.
- `delete(@map[key])`: видалення конкретного ключа з мапи.
- `clear(@map)`: повне очищення всіх елементів мапи.
- `zero(@map)`: скидання всіх лічильників мапи в 0 без видалення ключів.
- `print(@map [, top [, div]])`: примусове форматоване виведення вмісту мапи на екран.

## Специфікація мови та CLI SystemTap

SystemTap використовує мову скриптування, орієнтовану на події. Скрипти мають розширення `.stp` і транслюються у модулі ядра C.

### Формат командного рядка CLI

```bash
stap [опції] [файл_скрипта.stp]
stap [опції] -e 'код_скрипта'
```

Ключові прапорці утиліти `stap`:
- `-e 'script'`: виконати скрипт з аргументу командного рядка.
- `-g`: увімкнути **Guru Mode** (дозволяє мутацію пам'яті та вставки C-коду `%{ ... %}`).
- `-v` / `-vv` / `-vvv`: рівень вербальності (відображення проходження Pass 1 - Pass 5).
- `-p PASS`: зупинити виконання на конкретному етапі Pass (1 - аналіз, 2 - розгортання, 3 - трансляція C, 4 - компіляція `.ko`, 5 - запуск).
- `-m MODULE_NAME`: вказати власне ім'я для згенерованого модуля ядра.
- `-o FILE`: спрямувати вивід у файл.
- `-c 'cmd'`: виконати команду та вивантажити модуль після її завершення.
- `-x PID`: прив'язати змінні скрипта до конкретного PID процесу.
- `-D MACRO=VALUE`: передати макровизначення компілятору C під час Pass 3/4 (наприклад `-DSTAP_BUFFER_SIZE=8192`).

### Системні параметри та обмеження SystemTap (`-D` макроси)

Під час компіляції модуля SystemTap накладає внутрішні обмеження ресурсів для захисту ядра від переповнення. Ці параметри перевизначаються директивами `-D`:
- `STAP_MAXNESTING`: максимальна глибина вкладеності викликів функцій у скрипті (за замовчуванням 8).
- `STAP_MAXACTION`: максимальна кількість операцій у межах одного обробника проби (за замовчуванням 1000).
- `STAP_MAXSTRINGLEN`: максимальна довжина рядкових змінних (за замовчуванням 256 байтів).
- `STAP_MAXMAPENTRIES`: максимальна кількість елементів у глобальних масивах/мапах (за замовчуванням 2048).
- `STAP_BUFFER_SIZE`: розмір буфера RelayFS у байтах на кожний логічний CPU.

### Структура точок інструментації SystemTap

```awk
probe probe_point {
    action_statements
}
```

Категорії точок інструментації (Tapsets):

| Точка прощупування SystemTap | Опис |
| :--- | :--- |
| `kernel.function("pattern")` | Вхід у функцію ядра (підтримує wildcards, наприклад `vfs_*`) |
| `kernel.function("pattern").return` | Вихід з функції ядра |
| `kernel.trace("tracepoint_name")` | Статична точка інструментації ядра |
| `syscall.name` / `syscall.name.return` | Вихідні абстракції системних викликів з розпакованими параметрами |
| `process("path").function("pattern")` | Інструментація точок у бінарних файлах простору користувача |
| `process("path").mark("marker_name")` | Перехоплення статичних USDT-маркерів |
| `timer.s(N)` / `timer.ms(N)` | Періодичний таймер у секундах або мілісекундах |
| `timer.profile` | Профілювальник переривань таймера системи для усіх CPU |
| `begin` / `end` | Події ініціалізації та завершення сесії трасування |

### Вбудовані функції Tapset бібліотеки

- `execname()`: повертає ім'я поточного виконуваного процесу.
- `pid()`: повертає ідентифікатор поточного процесу.
- `tid()`: повертає ідентифікатор поточного потоку.
- `uid()` / `gid()`: повертає ідентифікатор користувача та групи.
- `cpu()`: номер поточного логічного процесора.
- `pp()`: повертає текстовий рядок поточної проби (Probe Point Name).
- `thread_indent(delta)`: повертає відформатований рядок із заглибленнями відповідно до глибини викликів функцій у потоці.
- `print_backtrace()`: виводить стек викликів ядра (Kernel Backtrace).
- `ubacktrace()`: виводить стек викликів користувацького простору.
- `user_string(addr)`: безпечно зчитує рядок із користувацької пам'яті.
- `kernel_string(addr)`: безпечно зчитує рядок із пам'яті ядра.

### Механізм агрегацій та статистичних змінних у SystemTap

У SystemTap накопичення статистики виконується за допомогою оператора `<<<`:

```awk
global latencies;

probe kernel.function("vfs_read").return {
    latencies <<< (gettimeofday_us() - @entry(gettimeofday_us()))
}
```

Зчитування накопичених статистичних даних виконується спеціальними операторами розпакування:
- `@count(variable)`: загальна кількість доданих елементів.
- `@sum(variable)`: сума накопичених значень.
- `@avg(variable)`: середнє значення.
- `@min(variable)` / `@max(variable)`: мінімальне та максимальне значення.
- `@hist_log(variable)`: побудова степенної гістограми.
- `@hist_linear(variable, start, stop, interval)`: побудова лінійної гістограми.

### Вбудований C-код у Guru Mode (`%{ ... %}`)

При запуску з прапорцем `-g` SystemTap дозволяє вставляти чистий код мовою C всередині блоків `%{ ... %}`:

```awk
function get_kernel_flag:long () %{
    STAP_RETVALUE = (long)cputime_one_jiffy;
%}
```

Всередині C-вставок доступні спеціальні макроси:
- `STAP_ARG_param_name`: доступ до вхідного параметра функції SystemTap.
- `STAP_RETVALUE`: присвоєння значення, що повертається функцією.
- `STAP_ERROR(fmt, ...)`: генерація помилки виконання з вивантаженням модуля.

## Зведена таблиця відповідності конструкцій

| Завдання / Концепція | bpftrace | SystemTap |
| :--- | :--- | :--- |
| Вхід у функцію ядра | `kprobe:vfs_read` | `probe kernel.function("vfs_read")` |
| Вихід з функції ядра | `kretprobe:vfs_read` | `probe kernel.function("vfs_read").return` |
| Системний виклик openat | `tracepoint:syscalls:sys_enter_openat` | `probe syscall.openat` |
| Ім'я процесу | `comm` | `execname()` |
| ID процесу | `pid` | `pid()` |
| Зчитування рядка з пам'яті | `str(arg0)` | `user_string(pointer)` |
| Логарифмічна гістограма | `@bytes = hist(arg1);` | `bytes <<< arg1;` (далі `@hist_log(bytes)`) |
| Друк стеку ядра | `print(kstack);` | `print_backtrace();` |
| Виконання при завершенні | `END { print(@map); }` | `probe end { printf("Done\n"); }` |
