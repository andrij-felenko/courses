# 📋 Інтерфейс конфігурації, boot-параметрів та аннотацій KASAN

Цей довідник містить вичерпний опис конфігураційних опцій ядра Linux (`Kconfig`), параметрів завантаження командного рядка ядра (`boot parameters`), а також програмного API аннотацій для розробників драйверів та підсистем ядра.

## 1. Конфігурація ядра (Kconfig)

Для увімкнення та налаштування KASAN у збірці ядра використовуються прапорці підсистеми `Kconfig`. Головною опцією є `CONFIG_KASAN=y`, яка активує підтримку санітайзера пам'яті у системі збірки Kbuild.

### 1.1 Основні режими KASAN

Залежно від цільової архітектури, апаратних можливостей процесора та цілей збірки обирається один із трьох взаємовиключних режимів:

- **`CONFIG_KASAN_GENERIC=y`**
  - **Опис:** Класичний програмний режим KASAN на основі тіньової пам'яті (пропорція відображення 8:1).
  - **Підтримувані архітектури:** x86_64, arm64, riscv, powerpc, s390.
  - **Виявляє:** Out-of-Bounds (OOB) у SLUB, стекі, глобальних змінних, vmalloc, а також Use-After-Free (UAF).
  - **Рекомендація:** Використовується за замовчуванням для розробки, налагодження та фазингу під x86_64.

- **`CONFIG_KASAN_SW_TAGS=y`**
  - **Опис:** Програмний режим на основі тегування вказівників через функцію ARM64 Top-Byte Ignore (TBI).
  - **Підтримувані архітектури:** arm64.
  - **Виявляє:** OOB у SLUB та UAF (ймовірнісний вибір 8-бітних тегів у діапазоні 1 із 255).
  - **Тіньова пам meть:** Пропорція відображення 16:1 (1 байт тегу на 16 байтів RAM).

- **`CONFIG_KASAN_HW_TAGS=y`**
  - **Опис:** Апаратний режим на основі розширення ARMv8.5-A Memory Tagging Extension (MTE).
  - **Підтримувані архітектури:** arm64 (із підтримкою MTE у процесорі).
  - **Виявляє:** Апаратне виявлення OOB та UAF на рівні викликu інструкцій CPU.
  - **Накладні витрати:** Мінімальні (< 5% CPU, 0% програмної тіньової пам'яті).

### 1.2 Опції інструментування компілятора

- **`CONFIG_KASAN_OUTLINE=y`**
  - **Опис:** Компілятор вставляє виклики функцій `__asan_loadN()` / `__asan_storeN()` перед кожним зверненням до пам'яті.
  - **Переваги:** Менший розмір бінарного образу ядра (`vmlinux`).
  - **Недоліки:** Додаткові накладні витрати на виклики функцій (на ~10-20% повільніше за inline).

- **`CONFIG_KASAN_INLINE=y`**
  - **Опис:** Компілятор вбудовує перевірку тіньової пам'яті (побітовий зсув та порівняння) безпосередньо у потік інструкцій.
  - **Переваги:** Максимальна швидкість виконання.
  - **Недоліки:** Збільшення розміру бінарного коду ядра на 15–25%.

### 1.3 Розширений обсяг перевірок

- **`CONFIG_KASAN_STACK=y`**
  - **Опис:** Вмикає інструментування локальних змінних на стекі функцій ядра. Компілятор додає червоні зони навколо кожної локальної змінної та мапує їх у тіньову пам meть при вході/виході з функції.
  - **Попередження:** Збільшує розмір стека функцій, що може виявити баги виходу за межі стека.

- **`CONFIG_KASAN_VMALLOC=y`**
  - **Опис:** Вмикає відстеження та отруєння пам meті, виділеної через `vmalloc()`, `vmap()`, `ioremap()`, а також пам meті модулів ядра.
  - **Втрати:** Додаткові витрати часу при виділенні/звільненні неперервних віртуальних регіонів.

- **`CONFIG_KASAN_KUNIT_TEST=m`**
  - **Опис:** Компілює модуль KUnit-тестів (`kasan_test`), який свідомо виконує недозволені операції з пам'яттю для перевірки працездатності KASAN.

## 2. Параметри командного рядка ядра (Boot Parameters)

При завантаженні ядра через завантажувач (GRUB, systemd-boot, U-Boot) поведінку KASAN можна коригувати за допомогою параметрів у `/proc/cmdline`.

### 2.1 Контроль HW Tag-Based KASAN (`kasan.mode`)

Параметр регулює режим роботи апаратного тегування ARM MTE:

- **`kasan.mode=sync`**
  - **Синхронний режим.** CPU негайно генерує апаратний виняток (tag check fault) на тій самій інструкції `LDR`/`STR`, яка виконала некоректний доступ.
  - **Застосування:** Максимальна точність для налагодження, точний RIP/PC інструкції.

- **`kasan.mode=async`**
  - **Асинхронний режим.** CPU фіксує помилку тегу у спеціальному системному регістрі та генерує переривання пізніше (при контекстному перемиканні або системному виклику).
  - **Застосування:** Мінімальні накладні витрати у production; стек викликів вказує на потік, але може не вказувати на точну інструкцію.

- **`kasan.mode=asymm`**
  - **Асиметричний режим.** Читання перевіряються асинхронно, а записи — синхронно.

### 2.2 Реакція на помилки (`kasan.fault`)

Визначає дію ядра при знаходженні першого порушення пам'яті:

- **`kasan.fault=report`** (за замовчуванням)
  - Друкує звіт KASAN у `dmesg` та дозволяє ядру продовжувати роботу (якщо не встановлено `panic_on_warn`).

- **`kasan.fault=panic`**
  - Негайно викликає `panic()` ядра при першому ж звіті KASAN. Використовується на фазинг-фермах для швидкого скидання стану тестового вузла.

### 2.3 Багаторазові звіти (`kasan_multi_shot`)

- **`kasan_multi_shot`**
  - За замовчуванням KASAN вимикає друк наступних звітів після першого знайденого бага, щоб не заповнювати кільцевий буфер `dmesg` дублікатами. Параметр `kasan_multi_shot` примушує KASAN друкувати звіт для кожного зловмисного доступу.

## 3. Внутрішній програмний API ядра (Annotations & Helper Functions)

Розробники низькорівневих алокаторів, власних пулів пам'яті (custom slab/pool allocators), драйверів з прямою адресацією DMA або коду на асемблері мусять вручну повідомляти KASAN про стан виділених регіонів.

Заголовочний файл: `<linux/kasan.h>`

### 3.1 Ручне отруєння та зняття отрути з тіньової пам'яті

Для Generic KASAN використовуються функції прямого керування байтами тіньової пам'яті:

```c
#include <linux/kasan.h>

/*
 * kasan_poison_shadow - позначає регіон пам'яті як недоступний (poisoned).
 * @addr: початкова віртуальна адреса (мусить бути вирівняна)
 * @size: розмір регіону в байтах
 * @value: код отруєння (наприклад, KASAN_SLAB_FREE або власний тег)
 */
void kasan_poison_shadow(const void *addr, size_t size, u8 value);

/*
 * kasan_unpoison_shadow - позначає регіон пам'яті як доступний (valid).
 * @addr: початкова віртуальна адреса
 * @size: розмір регіону в байтах
 */
void kasan_unpoison_shadow(const void *addr, size_t size);
```

**Приклад використання у власному кільцевому буфері:**
При виділенні елемента буфера розробник робить `kasan_unpoison_shadow(elem_ptr, elem_size)`, а при поверненні елемента до пулу — `kasan_poison_shadow(elem_ptr, elem_size, KASAN_SLAB_FREE)`.

### 3.2 Генерація та скидання тегів (Tag-Based KASAN / MTE)

У режимах SW/HW Tag-Based KASAN операції зі старшим байтом вказівника виконуються за допомогою спеціальних макросів та функцій:

```c
/*
 * kasan_reset_tag - скидає тег вказівника (встановлює старший байт у 0xFF)
 * Повертає чисту канонічну віртуальну адресу ядра.
 */
void *kasan_reset_tag(const void *addr);

/*
 * kasan_random_tag - генерує новий випадковий тег для об'єкта
 */
u8 kasan_random_tag(void);

/*
 * kasan_init_object_tags - призначає тег об'єкту та записує його в тіньову пам'ять/MTE
 */
void kasan_init_object_tags(struct kmem_cache *cache, void *object);
```

### 3.3 Хуки алокаторів пам meті

Низькорівневі підсистеми виклику сторінок ядра інтегровані з KASAN через хуки:

```c
/* Сповіщення KASAN про виділення сторінок у page_alloc */
void kasan_alloc_pages(struct page *page, unsigned int order, gfp_t flags);

/* Сповіщення KASAN про звільнення сторінок */
void kasan_free_pages(struct page *page, unsigned int order);

/* Сповіщення KASAN при виділенні об'єкта у kmalloc/SLUB */
void kasan_kmalloc(struct kmem_cache *cache, const void *object, size_t size, gfp_t flags);
```

## 4. Зведена таблиця кодових значень отруєння тіньової пам'яті (Poison Codes)

При відлагодженні звітів KASAN у дампах тіньової пам'яті трапляються байтові коди. Нижче наведено їх розшифровку з джерельного коду ядра (`mm/kasan/kasan.h`):

| Байтовий код | Символічна константа | Опис стану регіону пам'яті |
| :--- | :--- | :--- |
| `0x00` | `KASAN_PAGE_FREE` / Valid | Усі 8 байтів повністю доступні для читання/запису |
| `0x01` .. `0x07` | Partial Valid | Перші `N` байтів доступні, решта `8 - N` недоступні (вирівнювання) |
| `0xF1` | `KASAN_KMALLOC_REDZONE` | Ліва червона зона навколо об'єкта `kmalloc` |
| `0xF2` | `KASAN_KMALLOC_FREE` | Звільнений об'єкт `kmalloc` (до потрапляння в карантин) |
| `0xF3` | `KASAN_KMALLOC_PAGE_REDZONE` | Червона зона сторінкового алокатора (`alloc_pages`) |
| `0xF5` | `KASAN_GLOBAL_REDZONE` | Червона зона навколо глобальної змінної ядра (`.data`/`.bss`) |
| `0xF8` | `KASAN_STACK_LEFT` | Ліва межа фрейму функції на стекі |
| `0xF9` | `KASAN_STACK_MID` | Проміжна червона зона між локальними змінними стека |
| `0xFA` | `KASAN_STACK_RIGHT` | Права межа фрейму функції на стекі |
| `0xFB` | `KASAN_USE_AFTER_SCOPE` | Змінна стека вийшла за межі своєї області видимості (`{}`) |
| `0xFC` | `KASAN_SLAB_FREE` | Об'єкт SLUB звільнено і він перебуває у карантині (головний маркер UAF) |
| `0xFE` | `KASAN_VMALLOC_INVALID` | Нерозподілена або захисна сторінка у регіоні `vmalloc` |
