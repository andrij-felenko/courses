# 📋 Синтаксис правил auditctl

Ця довідка описує ключові параметри та синтаксис правил для утиліти `auditctl`, що керує підсистемою аудиту ядра.

## Файлові правила (-w)

Файлові правила є синтаксичним цукром над правилами для `open`, `openat`, `execve` та інших.

```bash
auditctl -w <шлях> -p <дозволи> -k <ключ>
```

**Параметри:**
- `-w`: Абсолютний шлях до файлу або директорії (рекурсивно).
- `-p`: Тип доступу:
  - `r`: читання (read).
  - `w`: запис (write).
  - `x`: виконання (execute).
  - `a`: зміна атрибутів (attribute).
- `-k`: Мітка (key) для зручного пошуку подій (макс. 31 символ).

## Правила системних викликів (-a)

Більш гнучкі правила, що дозволяють фільтрувати за аргументами системних викликів та станом системи.

```bash
auditctl -a <дія>,<список> -S <syscall> -F <фільтр> -k <ключ>
```

**Дія (Action):**
- `always`: Генерувати подію, якщо всі фільтри збігаються.
- `never`: Ніколи не генерувати подію (використовується для виключень).

**Список (List):**
- `exit`: Найпоширеніший. Подія генерується на виході з syscall (коли відомий результат і код помилки).
- `task`: Перевірка при створенні процесу (fork/clone).
- `user`: Фільтрація користувацьких повідомлень.
- `exclude`: Для повного ігнорування повідомлень.

**Фільтри (-F):**
- `arch=b64` або `arch=b32`: Архітектура (важливо для номерів syscall).
- `auid` (Audit UID): Оригінальний UID користувача, що зайшов у систему (до `su`/`sudo`).
- `uid`, `euid`, `fsuid`: Поточні UID.
- `exit`: Код виходу (наприклад, `-EACCES`).
- `success`: `1` (успіх) або `0` (помилка).
