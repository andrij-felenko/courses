# Підсистема аудиту ядра: правила, події й auditd

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

У сучасних Unix-подібних операційних системах, зокрема в Linux, безпека та спостережність (observability) відіграють ключову роль у забезпеченні надійності та цілісності даних. **Linux Audit Framework** — це потужна підсистема, інтегрована безпосередньо у ядро, яка дозволяє детально фіксувати події, що відбуваються в системі. Вона забезпечує гнучкий і надійний механізм для відстеження системних викликів (syscalls), доступу до файлів (VFS), змін конфігурації безпеки та інших критичних операцій.

На відміну від звичайних логів (наприклад, `syslog`), які базуються на тому, що сама програма (або демон) вирішить записати, Audit Framework працює на рівні ядра. Це означає, що програма не може приховати свої дії, навіть якщо вона скомпрометована, оскільки всі її взаємодії з системою проходять через ядро, де й перехоплюються підсистемою аудиту.

## 1. Архітектура Linux Audit Framework

Linux Audit Framework складається з двох основних частин: ядерної (Kernel Space) та користувацької (User Space). Ці частини взаємодіють між собою через спеціальний сокет — **Netlink** (зокрема, сімейство `NETLINK_AUDIT`).

### 1.1 Ядерна частина (Kernel Space)

Усередині ядра працює компонент, часто званий **kauditd** (хоча насправді це набір підсистем і потоків ядра). Його основні функції:
1. **Перехоплення подій:** Ядро модифіковане таким чином, щоб у ключових точках (наприклад, при вході та виході з системних викликів, при перевірках прав доступу, під час операцій з VFS) відбувалося звернення до підсистеми аудиту.
2. **Фільтрація за правилами:** Коли подія відбувається, ядро порівнює її з набором правил, завантажених у пам'ять. Якщо подія підпадає під правило, формується запис аудиту (audit record).
3. **Буферизація та відправка:** Згенеровані записи поміщаються в чергу в ядрі (її розмір можна налаштовувати) і відправляються через Netlink сокет у простір користувача.

### 1.2 Користувацька частина (User Space)

Користувацька частина відповідає за прийом, збереження та аналіз подій, а також за конфігурацію ядра.
- **`auditd` (Audit Daemon):** Фоновий процес, який слухає Netlink сокет, отримує повідомлення від `kauditd` і записує їх на диск (зазвичай у `/var/log/audit/audit.log`). Він також обробляє ротацію логів, реакцію на переповнення диска та може пересилати події іншим програмам.
- **`auditctl` (Audit Control):** Утиліта командного рядка для управління конфігурацією аудиту в ядрі. Вона дозволяє динамічно додавати, видаляти правила та перевіряти статус.
- **`aureport` та `ausearch`:** Інструменти для аналізу специфічного формату `audit.log`. Дозволяють шукати конкретні події (наприклад, доступ до певного файлу) та будувати звіти.

## 2. Управління підсистемою: auditctl та конфігурація

Утиліта `auditctl` — це пульт управління підсистемою аудиту. Зазвичай правила завантажуються під час завантаження системи з файлів конфігурації (наприклад, `/etc/audit/audit.rules`), але `auditctl` дозволяє маніпулювати ними динамічно.

### 2.1 Перевірка статусу

**Перевірка статусу**
```bash
sudo auditctl -s
```

**Вивід статусу**
```text
enabled 1
failure 1
pid 823
rate_limit 0
backlog_limit 8192
lost 0
backlog 0
```

- `enabled`: 1 (увімкнено), 0 (вимкнено), 2 (immutable режим, конфігурацію не можна змінити до перезавантаження).
- `failure`: Що робити при помилці. 0 (ігнорувати), 1 (printk), 2 (panic).
- `backlog_limit`: Максимальна кількість записів у черзі ядра. Якщо система надто навантажена подіями, черга може переповнитися, що призведе до втрати записів (`lost`).

## 3. Правила стеження: файли та системні виклики

[Синтаксис правил auditctl](api-auditctl-rules.md) дозволяє детально налаштувати, за чим саме система повинна стежити. Найпоширеніші сценарії — відстеження файлів (`-w`) та системних викликів (`-a`). 

### 3.1 Приклади файлових правил (-w)

Файлові правила — найпростіший спосіб відстежити доступ. Наприклад, ми хочемо знати, хто змінює конфігурацію користувачів, або хто запускає netcat:

```bash
sudo auditctl -w /etc/passwd -p wa -k passwd_changes
```

### 3.2 Приклади системних викликів (-a)

Правила системних викликів дозволяють реалізувати складнішу логіку за допомогою фільтрів (-F). Особливо корисним є поле `auid` (Audit UID), яке зберігає оригінальний UID користувача до ескалації привілеїв (`sudo`).

```bash
sudo auditctl -a always,exit -F arch=b64 -S openat -F exit=-EACCES -k access_denied
sudo auditctl -a always,exit -F arch=b64 -S openat -F exit=-EPERM -k access_denied
```

## 4. Аналіз логів: audit.log, ausearch та aureport

Демон `auditd` записує зібрані події у `/var/log/audit/audit.log`. Формат базується на парах `ключ=значення`. Один логічний запис може складатися з кількох рядків, пов'язаних спільним ідентифікатором події.

### 4.1 Структура запису

Приклад звернення до `/etc/passwd`:

```text
type=SYSCALL msg=audit(1697034567.890:345): arch=c000003e syscall=257 success=yes exit=3 a0=ffffff9c a1=7fffbaf3c9a0 a2=90800 a3=0 items=1 ppid=1234 pid=5678 auid=1000 uid=0 gid=0 euid=0 suid=0 fsuid=0 egid=0 sgid=0 fsgid=0 tty=pts0 ses=3 comm="cat" exe="/usr/bin/cat" key="passwd_changes"
type=PATH msg=audit(1697034567.890:345): item=0 name="/etc/passwd" inode=135043 dev=fc:01 mode=0100644 ouid=0 ogid=0 rdev=00:00 nametype=NORMAL cap_fp=0 cap_fi=0 cap_fe=0 cap_fver=0 cap_frootid=0
type=PROCTITLE msg=audit(1697034567.890:345): proctitle=636174002F6574632F706173737764
```

- **`msg=audit(1697034567.890:345)`:** `345` — унікальний ідентифікатор події (Serial Number). Всі три рядки мають однаковий ID.
- **`type=SYSCALL`:** Контекст виклику (архітектура, `syscall=257` (openat), успішність, `pid`, справжній `auid=1000` та ефективний `uid=0`, команда `cat`).
- **`type=PATH`:** Дає деталі про файл (інод, права).
- **`type=PROCTITLE`:** Повний рядок команди (в HEX).

### 4.2 Інструменти пошуку та звітності

Замість ручного парсингу сирих логів використовуються `ausearch` та `aureport`.

```bash
# Знайти всі події за ключем, автоматично конвертуючи HEX та UID у текст (-i)
sudo ausearch -k passwd_changes -i

# Події від конкретного користувача за сьогодні
sudo ausearch -ts today -ua 1000
```

## 5. Висновки

Linux Audit Framework є фундаментальним інструментом для моніторингу та забезпечення безпеки. Інтеграція на рівні ядра гарантує, що жодна подія не пройде повз `kauditd`, незалежно від привілеїв процесу. Інструменти `auditctl`, `ausearch` та фільтри (такі як `auid`) дозволяють точно налаштувати спостереження, ідентифікувати справжніх винуватців дій і перетворити великі обсяги сирих даних у зрозумілі аналітичні звіти.
