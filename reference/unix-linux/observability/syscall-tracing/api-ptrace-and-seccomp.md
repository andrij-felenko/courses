# 📋 Інтерфейси ptrace та Seccomp User Notification

Цей довідник описує повну специфікацію системного виклику `ptrace()`, підсистеми `seccomp user notification`, двійкові структури даних, константи, прапорці, ioctl-інтерфейси та коди помилок у ядрі Linux. Документ призначено для розробників системного програмного забезпечення, інструментів аналізу безпеки, налагоджувачів та супервізорів пісочниць.

## Системний виклик ptrace

Системний виклик `ptrace()` є базвим інтерфейсом у Unix-подібних операційних системах для спостереження та керування виконанням процесів у просторі користувача. Він надає трасувальнику повний контроль над адрессним простором, регістрами процесора та сигналами трасованого процесу.

### Сигнатура та параметри системного виклику

```c
#include <sys/ptrace.h>

long ptrace(enum __ptrace_request request, pid_t pid, void *addr, void *data);
```

- **`request`**: Системна команда (запит), яка визначає конкретну дію, що повинна бути виконана ядром (наприклад, підключення до процесу, зчитання регістрів, виконання одного системного виклику тощо).
- **`pid`**: Ідентифікатор трасованого процесу (tracee). При використанні команди `PTRACE_TRACEME` цей параметр ігнорується ядром і зазвичай передається як `0`.
- **`addr`**: Віртуальна адреса у пам'яті трасованого процесу або вказувач на структуру даних у пам'яті трасувальника. Значення та інтерпретація цього параметра повністю залежать від обраної команди `request`.
- **`data`**: Значення для запису в пам'ять/регістри або вказувач на буфер у просторі користувача для отримання результату з ядра.

### Повний перелік команд ptrace (request)

Ядро Linux підтримує широкий набір команд `ptrace`, які можна розділити на кілька функціональних категорій: керування станом, інспекція регістрів, зчитання/запис пам'яті та керування трасуванням системних викликів.

#### 1. Команди керування станом та підключення

- **`PTRACE_TRACEME`**: Викликається дочірнім процесом для вказівки ядру, що його батьківський процес має право трасувати його за допомогою `ptrace`. Виклик перевіряє право доступу і повертає `0` у разі успіху. Жодні привілеї superuser не потрібні, якщо батько й дочка належать одному UID.
- **`PTRACE_ATTACH`**: Динамічно приєднується до вже працюючого процесу з ідентифікатором `pid`. Ядро перевіряє привілеї (права доступу `CAP_SYS_PTRACE` та налаштування модуля Yama LSM). Після успішного приєднання ядро надсилає цільовому процесу сигнал `SIGSTOP`, переводячи його у стан `TASK_TRACED`. Трасувальник дістає змогу чекати зупинки через `waitpid()`.
- **`PTRACE_DETACH`**: Від'єднується від трасованого процесу `pid`. Процес відновлює нормальне виконання у просторі користувача. У параметрі `data` можна передати номер сигналу, який ядро має надіслати процесу при відновленні (або `0`, якщо сигнал надсилати не потрібно).
- **`PTRACE_CONT`**: Відновлює виконання зупиненого трасованого процесу. Якщо `data` не дорівнює `0`, процес отримує вказаний сигнал.
- **`PTRACE_KILL`**: Надсилає трасованому процесу сигнал `SIGKILL` для його негайного примусового завершення. Наразі вважається застарілим викликом (рекомендується використовувати `kill()`).
- **`PTRACE_INTERRUPT`**: Асинхронно зупиняє трасований процес без надсилання йому сигналу (Linux 3.4+). Зупинений процес генерує подію `PTRACE_EVENT_STOP`.

#### 2. Команди перехоплення викликів та крокового виконання

- **`PTRACE_SYSCALL`**: Відновлює виконання трасованого процесу до моменту входу в наступний системний виклик (`sys_enter`) або виходу з нього (`sys_exit`). Процес зупиняється ядром і надсилає трасувальнику сигнал `SIGTRAP` (або `SIGTRAP | 0x80`, якщо встановлено опцію `PTRACE_O_TRACESYSGOOD`).
- **`PTRACE_SINGLESTEP`**: Налаштовує прапорець покрокового виконання процесора (Trap Flag у регістрі `rflags` на x86_64). Процесор виконує рівно одну інструкцію і негайно генерує переривання `SIGTRAP`.
- **`PTRACE_SYSEMU`**: Виконує системний виклик у режимі емуляції (Linux 2.6.14+). Процес зупиняється на `sys_enter`, але ядро **не виконує** сам системний виклик у ядрі. Це дозволяє трасувальнику повністю підміняти реалізацію виклику у просторі користувача без виконання коду ядра.
- **`PTRACE_SYSEMU_SINGLESTEP`**: Поєднує емуляцію системного виклику `PTRACE_SYSEMU` з покроковим виконанням інструкцій.

#### 3. Команди читання та запису регістрів

- **`PTRACE_GETREGS`**: Зчитує значення загальних регістрів процесора трасованого процесу у структуру `struct user_regs_struct`, на яку вказує аргумент `data`.
- **`PTRACE_SETREGS`**: Перезаписує значення загальних регістрів процесора трасованого процесу даними зі структури `struct user_regs_struct`, на яку вказує аргумент `data`.
- **`PTRACE_GETFPREGS`**: Зчитує значення регістрів плаваючої крапки (Floating Point Unit / SIMD / SSE / AVX) у структуру `struct user_fpregs_struct`.
- **`PTRACE_SETFPREGS`**: Записує значення регістрів плаваючої крапки зі структури `struct user_fpregs_struct`.
- **`PTRACE_GETREGSET`**: Універсальний інтерфейс (Linux 2.6.34+) для зчитання наборів регістрів (NT_PRSTATUS, NT_PRFPREG, NT_X86_XSTATE) за допомогою вектора `struct iovec`.

#### 4. Команди читання та запису пам'яті

- **`PTRACE_PEEKTEXT` / `PTRACE_PEEKDATA`**: Зчитує один машинерне слово (4 байти на 32-бітних системах, 8 байт на 64-бітних системах) із віртуальної адреси `addr` трасованого процесу. Значення повертається як результат виклику `ptrace()`.
- **`PTRACE_POKETEXT` / `PTRACE_POKEDATA`**: Записує одне машинне слово з аргументу `data` за віртуальною адресою `addr` у пам'яті трасованого процесу.
- **`PTRACE_PEEKUSER` / `PTRACE_POKEUSER`**: Зчитує або записує слово у ділянці `USER` (структура `struct user`), де зберігаються регістви процесора, відлагоджувальні регістри (DR0–DR7) та системна інформація процесу.

### Структури регістрів процесора на архітектурі x86_64

При використанні `PTRACE_GETREGS` та `PTRACE_SETREGS` дані передаються через структуру `struct user_regs_struct`, оголошену в заголовковому файлі `<sys/user.h>`:

```c
struct user_regs_struct {
    unsigned long r15;
    unsigned long r14;
    unsigned long r13;
    unsigned long r12;
    unsigned long rbp;
    unsigned long rbx;
    unsigned long r11;
    unsigned long r10;
    unsigned long r8;
    unsigned long r9;
    unsigned long rax;
    unsigned long rcx;
    unsigned long rdx;
    unsigned long rsi;
    unsigned long rdi;
    unsigned long orig_rax; /* Початковий номер системного виклику */
    unsigned long rip;      /* Вказівник на поточну інструкцію (IP) */
    unsigned long cs;
    unsigned long eflags;   /* Прапорці процесора (rflags) */
    unsigned long rsp;      /* Вказівник на вершину стека (SP) */
    unsigned long ss;
    unsigned long fs_base;
    unsigned long gs_base;
    unsigned long ds;
    unsigned long es;
    unsigned long fs;
    unsigned long gs;
};
```

Поле `orig_rax` відіграє критичну роль при трасуванні системних викликів:
- На точці `sys_enter`: `orig_rax` містить апаратний номер системного виклику. Поле `rax` також містить цей номер.
- Під час виконання у ядрі: `rax` переписується підсумковим кодом повернення.
- На точці `sys_exit`: `orig_rax` зберігає початковий номер виклику, а `rax` містить повернуте значення ядра (наприклад, кількість прочитаних байт або від'ємне значення `-errno`).

### Додаткові опції PTRACE_SETOPTIONS

Виклик `ptrace(PTRACE_SETOPTIONS, pid, 0, options)` дозволяє налаштувати додаткові розширення ядра:

```c
#define PTRACE_O_TRACESYSGOOD   0x00000001
#define PTRACE_O_TRACEFORK      0x00000002
#define PTRACE_O_TRACEVFORK     0x00000004
#define PTRACE_O_TRACECLONE     0x00000008
#define PTRACE_O_TRACEEXEC      0x00000010
#define PTRACE_O_TRACEVFORKDONE 0x00000020
#define PTRACE_O_TRACEEXIT      0x00000040
#define PTRACE_O_TRACESECCOMP   0x00000080
#define PTRACE_O_EXITKILL       0x00001000
#define PTRACE_O_SUSPEND_SECCOMP 0x00002000
```

#### Детальний опис дій прапорців опцій:

1. **`PTRACE_O_TRACESYSGOOD`**: Змушує ядро встановлювати 7-й біт у коді сигналу зупинки при досягненні точки системного виклику. Замість звичайного `SIGTRAP` (значення 5) макрос `WSTOPSIG(status)` повертає `(SIGTRAP | 0x80)` (значення `0x85` або `133`). Це дозволяє трасувальнику гарантовано відрізнити вхід/вихід із системного виклику від генерації сигналу `SIGTRAP` самою програмою (наприклад, через інструкцію `int3`).
2. **`PTRACE_O_TRACEFORK`**: Автоматично приєднує трасувальник до нових дочірніх процесів, створених через системний виклик `fork()`. Новий процес зупиняється із сигналом `SIGTRAP`, а трасувальник отримує подію `PTRACE_EVENT_FORK`.
3. **`PTRACE_O_TRACEVFORK`**: Зупиняє процес при створенні дочірнього процесу через `vfork()`. Подія `PTRACE_EVENT_VFORK`.
4. **`PTRACE_O_TRACECLONE`**: Автоматично приєднує трасувальник до нових ниток виконання (threads), створених через системний виклик `clone()`. Подія `PTRACE_EVENT_CLONE`.
5. **`PTRACE_O_TRACEEXEC`**: Зупиняє процес при успішній заміні образу процесу через системний виклик `execve()`. Подія `PTRACE_EVENT_EXEC`.
6. **`PTRACE_O_TRACEEXIT`**: Зупиняє процес безпосередньо перед його завершенням у ядрі. Подія `PTRACE_EVENT_EXIT`. Значення коду завершення можна прочитати через `PTRACE_GETEVENTMSG`.
7. **`PTRACE_O_TRACESECCOMP`**: Зупиняє процес, якщо його Seccomp-фільтр повертає рішення `SECCOMP_RET_TRACE`. Подія `PTRACE_EVENT_SECCOMP`.
8. **`PTRACE_O_EXITKILL`**: Гарантує, що якщо процес-трасувальник буде примусово вбитий або впаде, ядро автоматично надішле сигнал `SIGKILL` усім його трасованим дочірнім процесам. Запобігає виникненню сирітських трасованих процесів у стані `TASK_TRACED`.

### Структура ptrace_syscall_info (Linux 5.3+)

Для усунення залежності від архітектурно-специфічного розташування регістрів у `struct user_regs_struct` ядро Linux 5.3 ввело уніфікований виклик `ptrace(PTRACE_GET_SYSCALL_INFO, pid, sizeof(info), &info)`:

```c
struct ptrace_syscall_info {
    __u8 op;                    /* Тип події: ENTRY, EXIT або SECCOMP */
    __u32 arch;                 /* Архітектура процесора (AUDIT_ARCH_*) */
    __u64 instruction_pointer;  /* Значення rip / pc */
    __u64 stack_pointer;        /* Значення rsp / sp */
    union {
        struct {
            __u64 nr;           /* Апаратний номер системного виклику */
            __u64 args[6];      /* Масив із 6 чисельних аргументів */
        } entry;
        struct {
            __s64 rval;         /* Повернене значення (код успіху або -errno) */
            __u8 is_error;      /* 1 якщо rval є кодом помилки, 0 якщо успіх */
        } exit;
        struct {
            __u64 nr;           /* Номер системного виклику */
            __u64 args[6];      /* Аргументи виклику */
            __u32 ret_data;     /* 16-бітні дані з BPF розрахунку */
        } seccomp;
    };
};
```

Значення поля `op`:
- `PTRACE_SYSCALL_INFO_ENTRY` (`1`): Зупинка на вході `sys_enter`. Заповнено структуру `entry`.
- `PTRACE_SYSCALL_INFO_EXIT` (`2`): Зупинка на виході `sys_exit`. Заповнено структуру `exit`.
- `PTRACE_SYSCALL_INFO_SECCOMP` (`3`): Зупинка через Seccomp `SECCOMP_RET_TRACE`. Заповнено структуру `seccomp`.

## Інтерфейс Seccomp User Notification

Підсистема Seccomp User Notification надає можливість перехоплювати системні виклики у просторі користувача без використання `ptrace`, спираючись на файлові дескриптори та розширену cBPF-фільтрацію.

### Встановлення Seccomp BPF фільтра

Фільтр Seccomp встановлюється за допомогою системного виклику `seccomp()` або застарілого виклику `prctl(PR_SET_SECCOMP, ...)`:

```c
#include <linux/seccomp.h>
#include <linux/filter.h>
#include <sys/prctl.h>
#include <sys/syscall.h>

int seccomp(unsigned int operation, unsigned int flags, void *args);
```

- **`operation`**: Має значення `SECCOMP_SET_MODE_FILTER`.
- **`flags`**: Поєднання прапорців `SECCOMP_FILTER_FLAG_NEW_LISTENER` (повертає файловий дескриптор сповіщення) та `SECCOMP_FILTER_FLAG_TSYNC` (синхронізує фільтр між усіма нитками процесу).
- **`args`**: Вказувач на структуру `struct sock_fprog`, яка описує cBPF програму.

### Формат класичного BPF інструктиву (cBPF)

Фільтр Seccomp складається з масиву інструкцій `struct sock_filter`:

```c
struct sock_filter {
    __u16 code; /* Код операції (BPF_LD, BPF_JMP, BPF_RET тощо) */
    __u8  jt;   /* Зміщення переходу, якщо умова ІСТИННА (jump true) */
    __u8  jf;   /* Зміщення переходу, якщо умова ХИБНА (jump false) */
    __u32 k;    /* Константа або зміщення у структурі seccomp_data */
};

struct sock_fprog {
    unsigned short len;       /* Кількість інструкцій у масиві */
    struct sock_filter *filter; /* Масив інструкцій */
};
```

При вході у Seccomp ядро подає на вхід BPF-програми структуру `struct seccomp_data`:

```c
struct seccomp_data {
    int nr;                     /* Номер системного виклику */
    __u32 arch;                 /* Архітектура (AUDIT_ARCH_X86_64 тощо) */
    __u64 instruction_pointer;  /* Вказівник на інструкцію */
    __u64 args[6];              /* 6 аргументів системного виклику */
};
```

### Коди повернення BPF-фільтра Seccomp

BPF-програма повертає 32-бітне значення, у якому старші 16 біт визначають дію ядра (`SECCOMP_RET_ACTION_FULL`), а молодші 16 біт містять додаткові дані (`SECCOMP_RET_DATA`):

- **`SECCOMP_RET_ALLOW`** (`0x7fff0000U`): Дозволити виконання системного виклику у ядрі без жодних обмежень.
- **`SECCOMP_RET_ERRNO`** (`0x05000000U`): Заборонити виконання виклику. Ядро негайно повертає значення `-(k & SECCOMP_RET_DATA)` у просторі користувача (наприклад, `SECCOMP_RET_ERRNO | EPERM`).
- **`SECCOMP_RET_KILL_PROCESS`** (`0x80000000U`): Негайно вбити увесь процес примусовим сигналом `SIGSYS`.
- **`SECCOMP_RET_KILL_THREAD`** (`0x00000000U`): Вбити поточну нитку виконання.
- **`SECCOMP_RET_USER_NOTIF`** (`0x7fc00000U`): Перехопити виклик і передати його обробку супервізору через `listener_fd`.
- **`SECCOMP_RET_TRACE`** (`0x7fe00000U`): Повідомити трасувальника `ptrace` про системний виклик.
- **`SECCOMP_RET_LOG`** (`0x7ff00000U`): Дозволити виклик і записати подію у журнал аудіту ядра.

## Ioctl-інтерфейс дескриптора Seccomp Listener FD

Взаємодія між супервізором та ядром здійснюється через `ioctl()` над файловим дескриптором `listener_fd`.

### 1. Зчитання запиту: SECCOMP_IOCTL_NOTIF_RECV

Зчитує перше доступне сповіщення з черги ядра.

```c
#define SECCOMP_IOCTL_NOTIF_RECV _IOWR('!', 0, struct seccomp_notif)

struct seccomp_notif {
    __u64 id;                  /* Унікальний 64-бітний ідентифікатор сповіщення */
    __u32 pid;                 /* PID процесу, який зупинився на виклику */
    __u32 flags;               /* Прапорці сповіщення (зарезервовано ядрами) */
    struct seccomp_data data;  /* Зріз аргументів системного виклику */
};
```

Виклик блокується, якщо черга порожня. Якщо `listener_fd` відкритий із прапорцем `O_NONBLOCK`, виклик повертає `-1` та встановлює `errno = EAGAIN`.

### 2. Надсилання відповіді: SECCOMP_IOCTL_NOTIF_SEND

Відправляє відповідь супервізора заблокованому процесу.

```c
#define SECCOMP_IOCTL_NOTIF_SEND _IOWR('!', 1, struct seccomp_notif_resp)

struct seccomp_notif_resp {
    __u64 id;        /* Унікальний ідентифікатор id із struct seccomp_notif */
    __s64 val;       /* Код повернення виклику (наприклад, 0 або к-сть байт) */
    __s32 error;     /* 0 для успіху, або від'ємне значення -errno (наприклад, -EACCES) */
    __u32 flags;     /* Прапорці поведінки відповіді */
};
```

Прапорці відповіді (`flags`):
- **`0`**: Завершити системний виклик. Ядро повертає цільовому процесу значення `val` (якщо `error == 0`) або значення `error` у змінну `errno`.
- **`SECCOMP_USER_NOTIF_FLAG_CONTINUE`** (`0x00000001U`): Скасувати перехоплення й наказати ядру розблокувати процес і виконати справжній системний виклик у ядрі (Linux 5.5+).

### 3. Перевірка дійсності ID: SECCOMP_IOCTL_NOTIF_ID_VALID

Перевіряє, чи ідентифікатор `id` досі залишається чинним у ядрі.

```c
#define SECCOMP_IOCTL_NOTIF_ID_VALID _IOR('!', 2, __u64)

__u64 id = req.id;
if (ioctl(notify_fd, SECCOMP_IOCTL_NOTIF_ID_VALID, &id) < 0) {
    if (errno == ENOENT) {
        /* Процес скасував системний виклик через сигнал або був убитий! */
    }
}
```

### 4. Інжектування дескрипторів: SECCOMP_IOCTL_NOTIF_ADDFD

Дозволяє супервізору створити файловий дескриптор у власному просторі (наприклад, відкрити файл або сокет) та інжектувати його у таблицю файлових дескрипторів цільового процесу (Linux 5.9+).

```c
#define SECCOMP_IOCTL_NOTIF_ADDFD _IOW('!', 3, struct seccomp_notif_addfd)

struct seccomp_notif_addfd {
    __u64 id;          /* Унікальний id сповіщення */
    __u32 flags;       /* SECCOMP_ADDFD_FLAG_SETFD або 0 */
    __u32 srcfd;       /* Файловий дескриптор у супервізорі */
    __u32 newfd;       /* Конкретний номер FD у цільовому процесі (якщо SETFD) */
    __u32 newfd_flags; /* Прапорці нового FD (наприклад, O_CLOEXEC) */
};
```

Прапорці `flags` для ADDFD:
- **`SECCOMP_ADDFD_FLAG_SETFD`**: Встановити новий дескриптор на чітко вказаний номер `newfd`. Якщо target має відкритий FD на цьому номері, він буде атомарно замінений (подібно до `dup2()`).
- **`SECCOMP_ADDFD_FLAG_SEND`**: Виконати атомарну відправку дескриптора й одразу повернення відповіді цільовому процесу за один `ioctl` виклик.

## Таблиця помилок системних викликів (errno)

При роботі з `ptrace` та `seccomp user notification` системні виклики можуть повертати такі коди помилок у змінній `errno`:

| Код помилки | Джерело виклику | Причина виникнення помилки |
| :--- | :--- | :--- |
| `EPERM` | `ptrace` / `seccomp` | Відсутність потрібних привілеїв (`CAP_SYS_PTRACE`), обмеження Yama LSM `ptrace_scope`, або відсутність `PR_SET_NO_NEW_PRIVS`. |
| `ESRCH` | `ptrace` | Процес із вказаним PID не існує або не перебуває у стані трасування даним трасувальником. |
| `EBUSY` | `ptrace` | Процес вже трасується іншим трасувальником у системі. |
| `ENOENT` | `seccomp notif` | Ідентифікатор сповіщення `id` застарів або перерваний сигналом. |
| `EAGAIN` | `seccomp notif` | Черга сповіщень порожня при роботі в неблокуючому режимі (`O_NONBLOCK`). |
| `EINVAL` | `ptrace` / `seccomp` | Передано недійсний номер запиту, невідомі прапорці або невідповідні розміри структур. |
| `EBADF` | `seccomp notif` | Переданий дескриптор `listener_fd` є закритим або недійсним. |
| `ENOSYS` | `ptrace` | Системний виклик не підтримується даною архітектурою ядра. |
