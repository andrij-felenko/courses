# 📋 Інтерфейс системного виклику ptrace та пов'язані структури

Цей довідник містить повну специфікацію системного виклику `ptrace()`, усіх його команд (`request`), прапорів конфігурації (`ptrace_options`), структур опису регістрів процесора та макросів інтерпретації кодів стану системного виклику `waitpid()`. Матеріал розрахований на розробників системного програмного забезпечення, налагоджувачів, інструментів ін'єкції коду та засобів аналізу безпеки у середовищі Linux.

---

## 1. Загальна сигнатура та параметри системного виклику

Системний виклик `ptrace()` оголошено в заголовочному файлі `<sys/ptrace.h>`:

```c
#include <sys/ptrace.h>

long ptrace(enum __ptrace_request request, pid_t pid, void *addr, void *data);
```

### Призначення параметрів

- `request`: Команда ядра, яка визначає дію, що має бути виконана над цільовим процесом (наприклад, приєднання, прочитання пам'яті, зчитування регістрів, зупинка або відновлення виконання).
- `pid`: Ідентифікатор цільового процесу або окремого потоку виконання (LWP — Light-Weight Process). Для команд, які викликує сам дочірній процес (наприклад, `PTRACE_TRACEME`), цей параметр передається як `0`.
- `addr`: Віртуальна адреса в адресному просторі трасованого процесу (tracee) або зсув у псевдоструктурі `user`. Для команд, які не потребують адреси, параметр ігнорується і зазвичай передається як `NULL` або `0`.
- `data`: Вказівник на буфер у просторі пам'яті трасувальника (tracer) для читання чи запису даних, або числове значення параметра (наприклад, маска прапорів `PTRACE_O_*` або номер сигналу для доставки).

### Правила обробки повернюваного значення та помилок

Більшість команд системного виклику `ptrace()` у разі успішного виконання повертають `0`. Якщо виклик завершується помилкою, повертається значення `-1`, а глобальна змінна `errno` встановлюється у відповідний код помилки.

Винятком із цього правила є запити групи `PTRACE_PEEK` (`PTRACE_PEEKTEXT`, `PTRACE_PEEKDATA`, `PTRACE_PEEKUSER`), які повертають прочитане з пам'яті значення типу `long` безпосередньо як результат функції. Оскільки прочитане з пам'яті слово процесу може мати значення `-1` (що збігається з індикатором помилки), трасувальник зобов'язаний дотримуватися наступного алгоритму перевірки помилок:

1. Обнулити глобальну змінну `errno = 0` безпосередньо перед викликом `ptrace()`.
2. Викликати `long val = ptrace(PTRACE_PEEKDATA, pid, addr, NULL);`.
3. Перевірити, чи `errno != 0`. Якщо `errno` змінила своє значення з нуля, виклик завершився помилкою, а повернуте значення `val` є невалідним.

## 2. Повний каталог команд системного виклику (Requests)

### 2.1. Команди керування сесією та приєднання

- `PTRACE_TRACEME`: Викликається дочірнім процесом перед виконанні виклику `execve()`. Повідомляє ядру, що поточний процес дозволяє своєму батьківському процесу трасувати себе. Будь-який сигнал, доставлений цьому процесу (включно із `SIGTRAP` після `execve`), зупинить його та розбудить батьківський процес у `waitpid()`. Параметри `pid`, `addr` та `data` ігноруються.
- `PTRACE_ATTACH`: Приєднує трасувальник до існуючого працюючого процесу з ідентифікатором `pid`. Ядро перевіряє права доступу (користувач, привілеї та Yama LSM), надсилає цільовому процесу сигнал `SIGSTOP` і робить tracer тимчасовим батьком процесу. Трасувальник повинен зачекати зупинки через `waitpid()`.
- `PTRACE_SEIZE`: Сучасний та більш гнучкий аналог `PTRACE_ATTACH` (доданий у Linux 3.4). Приєднується до процесу без автоматичної надсилання сигналу `SIGSTOP`. Процес продовжує виконання у звичайному режимі до тих пір, поки tracer не надрукує команду зупинки `PTRACE_INTERRUPT`. Дозволяє передавати прапори конфігурації `PTRACE_O_*` безпосередньо в параметрі `data`.
- `PTRACE_DETACH`: Скасовує режим трасування для процесу `pid`. Восстанавливає нормальне виконання процесу, повертає його оригінальне батьківство та скасовує всі встановлені заходи трасування. У параметрі `data` можна передати номер сигналу, який буде доставлено процесу при відновленні виконання (або `0`, якщо сигнал надсилати не потрібно).
- `PTRACE_INTERRUPT`: Зупиняє процес, який був приєднаний за допомогою `PTRACE_SEIZE`. Генерує ptrace-зупинку типу `PTRACE_EVENT_STOP`.
- `PTRACE_LISTEN`: Переводить зупинений процес у стан групової зупинки (Group-stop), дозволяючи йому залишатися зупиненим без блокування роботи трасувальника.

### 2.2. Команди керування виконанням (Execution Control)

- `PTRACE_CONT`: Відновлює виконання зупиненого процесу `pid`. Якщо параметр `data` не дорівнює нулю, ядро інтерпретує його як номер сигналу, який слід доставити цільовому процесу.
- `PTRACE_SINGLESTEP`: Примушує процесор виконати **рівно одну** машинку інструкцію коду і негайно зупинити процес із сигналом `SIGTRAP`. Використовується налагоджувачами для покрокового крокування по інструкціях.
- `PTRACE_SYSCALL`: Відновлює виконання процесу до входу у наступний системний виклик (Syscall-enter-stop) або до виходу з нього (Syscall-exit-stop). На кожній зупинці процес надсилає трасувальнику сигнал `SIGTRAP` (або `SIGTRAP | 0x80` при встановленій опції `PTRACE_O_TRACESYSGOOD`).
- `PTRACE_SYSEMU`: Виконує емуляцію системного виклику. Процес зупиняється на вході у системний виклик, але ядро **не виконує** сам системний виклик. Трасувальник може підставити власне значення повернення в регістр `rax` і відновити виконання.
- `PTRACE_SYSEMU_SINGLESTEP`: Поєднує емуляцію системного виклику та покроковий режим виконання однієї інструкції.
- `PTRACE_KILL`: Надсилає процесу сигнал `SIGKILL` для його негайного знищення. Наразі вважається застарілим викликом (рекомендовано використовувати `kill(pid, SIGKILL)`).

### 2.3. Команди доступу до пам'яті та структури USER

- `PTRACE_PEEKTEXT` / `PTRACE_PEEKDATA`: Зчитує одне машинне слово (розміром `sizeof(long)`, тобто 8 байт на 64-бітних архітектурах) з віртуальної адреси `addr` у процесі `pid`. На сучасних системах Linux пам'ять коду (`TEXT`) та даних (`DATA`) об'єднана, тому ці команди ідентичні.
- `PTRACE_POKETEXT` / `PTRACE_POKEDATA`: Записує одне машинне слово `data` за віртуальною адресою `addr` у процесі `pid`. Застосовується для модифікації коду на льоту (впровадження інструкцій `INT 3`) та зміни змінних.
- `PTRACE_PEEKUSER`: Зчитує слово з псевдоструктури `struct user` за зсувом `addr`. Структура `user` описує збережений стан процесора, включаючи регістри, відлагоджувальні регістри та розміри секцій.
- `PTRACE_POKEUSER`: Записує слово `data` у структуру `struct user` за зсувом `addr`. Найчастіше використовується для модифікації апаратних відлагоджувальних регістрів `DR0`–`DR7`.

### 2.4. Команди доступу до регістрів процесора

- `PTRACE_GETREGS`: Зчитує значення регістрів загального призначення цільового процесу у буфер `struct user_regs_struct`, на який вказує параметр `data`.
- `PTRACE_SETREGS`: Записує нові значення регістрів загального призначення з буфера `struct user_regs_struct`, на який вказує `data`, у процесорні регістри зупиненого процесу.
- `PTRACE_GETFPREGS`: Зчитує значення регістрів з плаваючою крапкою (Floating Point / SSE / AVX) у структуру `struct user_fpregs_struct`.
- `PTRACE_SETFPREGS`: Перезаписує регістри плаваючої крапки з вказаного буфера.
- `PTRACE_GETREGSET`: Сучасний універсальний інтерфейс читання наборі регістрів для різних архітектур (ARM64, x86, RISC-V). Приймає тип набору регістрів у `addr` (наприклад, `NT_PRSTATUS` для загальних регістрів або `NT_X86_XSTATE` для розширених векторних регістрів) та вказівник на `struct iovec` у `data`.
- `PTRACE_SETREGSET`: Сучасний універсальний інтерфейс перезапису наборів регістрів через `struct iovec`.

## 3. Прапори опцій (PTRACE_SETOPTIONS)

Конфігурація поведінки ядра під час трасування здійснюється викликом `ptrace(PTRACE_SETOPTIONS, pid, NULL, (void*)(uintptr_t)options)`, де `options` є бітовою маскою наступних констант:

- `PTRACE_O_TRACESYSGOOD` (0x00000001): Змушує ядро встановлювати 7-й біт у сигналі `SIGTRAP` при зупинках на системних викликах (`PTRACE_SYSCALL`). Сигнал зупинки дорівнює `SIGTRAP | 0x80` (`0x85`). Це дозволяє трасувальнику однозначно відрізняти вхід/вихід із системного виклику від звичайного точки зупину.
- `PTRACE_O_TRACEFORK` (0x00000002): Автоматично починає трасувати дочірній процес при виклику `fork()`. Новий процес зупиняється з подією `PTRACE_EVENT_FORK`, а його PID зчитується через `PTRACE_GETEVENTMSG`.
- `PTRACE_O_TRACEVFORK` (0x00000004): Автоматично трасує дочірній процес при виклику `vfork()`, генеруючи подію `PTRACE_EVENT_VFORK`.
- `PTRACE_O_TRACECLONE` (0x00000008): Автоматично починає трасувати нові потоки, створені через `clone()`. Генерує подію `PTRACE_EVENT_CLONE`.
- `PTRACE_O_TRACEEXEC` (0x00000010): Перехоплює момент успішного виконання системного виклику `execve()`, генеруючи подію `PTRACE_EVENT_EXEC`.
- `PTRACE_O_TRACEVFORKDONE` (0x00000020): Зупиняє процес після завершення виклику `vfork()`, коли дочірній процес звільнив спільну пам'ять.
- `PTRACE_O_TRACEEXIT` (0x00000040): Зупиняє процес безпосередньо перед його реальним знищенням у ядрі (до звільнення ресурсів). Подія — `PTRACE_EVENT_EXIT`.
- `PTRACE_O_TRACESECCOMP` (0x00000080): Зупиняє процес при спрацюванні Seccomp-фільтра із правилом `SECCOMP_RET_TRACE`. Подія — `PTRACE_EVENT_SECCOMP`.
- `PTRACE_O_EXITKILL` (0x00010000): Якщо процес-трасувальник раптово гине, ядро автоматично надсилає `SIGKILL` усім його трасованим дочірнім процесам, запобігаючи появі завислих сирітських процесів.

## 4. Аналіз стану waitpid() та розкодування подій

Після зупинки цільового процесу трасувальник викликає `waitpid(pid, &status, 0)` для отримання цілого числа `status`. Інтерпретація цього числа здійснюється за допомогою стандартних макросів:

- `WIFEXITED(status)`: Повертає істину, якщо процес завершив роботу нормально (через `exit()` або повернення з `main`). Код повернення зчитується через `WEXITSTATUS(status)`.
- `WIFSIGNALED(status)`: Повертає істину, якщо процес було вбито необробленим сигналом. Номер сигналу зчитується через `WTERMSIG(status)`.
- `WIFSTOPPED(status)`: Повертає істину, якщо процес зупинився і перебуває у стані ptrace-stop. Номер сигналу зупинки зчитується через `WSTOPSIG(status)`.

### Розкодування розширених подій ptrace

Якщо `WSTOPSIG(status) == SIGTRAP`, у старших двох байтах числа `status` може міститися код розширеної події ptrace:

:::tabs
```c
int event = (status >> 16) & 0xffff;
```
```cpp
const auto event = static_cast<int>((status >> 16) & 0xffff);
```
:::

Витягти додаткові дані про подію (наприклад, PID нового процесу при `FORK`/`CLONE` або код завершення при `EXIT`) можна викликом `PTRACE_GETEVENTMSG`:

```c
unsigned long event_data = 0;
ptrace(PTRACE_GETEVENTMSG, pid, NULL, &event_data);
```

## 5. Структура user_regs_struct на архітектурі x86_64

У заголовочному файлі `<sys/user.h>` визначено структуру регістрів для x86_64:

```c
struct user_regs_struct {
    unsigned long long r15;
    unsigned long long r14;
    unsigned long long r13;
    unsigned long long r12;
    unsigned long long rbp;
    unsigned long long rbx;
    unsigned long long r11;
    unsigned long long r10;
    unsigned long long r9;
    unsigned long long r8;
    unsigned long long rax;
    unsigned long long rcx;
    unsigned long long rdx;
    unsigned long long rsi;
    unsigned long long rdi;
    unsigned long long orig_rax;
    unsigned long long rip;
    unsigned long long cs;
    unsigned long long eflags;
    unsigned long long rsp;
    unsigned long long ss;
    unsigned long long fs_base;
    unsigned long long gs_base;
    unsigned long long ds;
    unsigned long long es;
    unsigned long long fs;
    unsigned long long gs;
};
```

### Роль регістрів у конвенції системних викликів x86_64:

- `orig_rax`: Зберігає оригінальний номер системного виклику на момент входу. Потрібен тому, що в процесі виконання виклику ядро може перезаписати регістр `rax` кодом помилки `-ENOSYS`.
- `rax`: На вході містить номер системного виклику, на виході — повернуте значення (або від'ємне значення `-ERRNO` при помилці).
- `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`: Передають відповідно 1-й, 2-й, 3-й, 4-й, 5-й та 6-й аргументи системного виклику.
- `rip`: Вказівник на наступну інструкцію для виконання (Instruction Pointer).
- `rsp`: Вказівник на верхівку стека користувацького простору (Stack Pointer).

## 6. Коди помилок системного виклику (errno)

- `EPERM`: Нестача прав для трасування. Цільовий процес виконує setuid-програму, належить іншому користувачеві або заблокований політикою Yama LSM (`/proc/sys/kernel/ptrace_scope`).
- `ESRCH`: Процес із вказаним `pid` не існує або наразі не трасується даним трасувальником.
- `EBUSY`: Спроба приєднатися до процесу (`PTRACE_ATTACH`), який вже знаходиться під трасуванням іншого трасувальника.
- `EIO`: Некоректний номер команди `request`, невалідний номер сигналу або спроба зчитати невирівняні дані.
- `EFAULT`: Спроба зчитати або записати пам'ять за віртуальною адресою `addr`, яка не є мапованою або доступною в адресному просторі процесу.
