# 📋 Довідник API kallsyms, специфікаторів %pS та параметрів sysctl

Поверхня підсистеми `kallsyms` охоплює розширені специфікатори форматування `printk`, параметри безпеки sysctl, віртуальні ноди файлових систем, конфігураційні прапори ядра та внутрішньоядерний програмний API для пошуку символів.

---

## 1. Конфігураційні параметри ядра (Kconfig)

Підсистема `kallsyms` налаштовується під час компіляції ядра Linux у меню `Kernel hacking -> Debug options`. Збірка ядра з різними прапорцями визначає повноту таблиць, можливість спостереження за даними та обсяг оперативної пам'яті, що виділяється у нерозвантажуваній секції `.rodata`.

| Прапор Kconfig | Опис, призначення та вплив на бінарний образ ядра |
| :--- | :--- |
| **`CONFIG_KALLSYMS=y`** | **Базовий прапор підсистеми:** вмикає підсистему kallsyms, генерує двопрохідні таблиці символів для всіх виконуваних функцій ядра (секція `.text`). Якщо цей прапор вимкнено, ядро не зберігає жодного імені символу у RAM, а всі повідомлення про збої (Oops, Panic, dmesg) та трасування стека містять виключно сирі 64-бітні віртуальні адреси. |
| **`CONFIG_KALLSYMS_ALL=y`** | **Розширений режим символів:** включає до таблиці абсолютно всі символи ядра, включаючи статичні та глобальні змінні у секціях `.data`, `.bss`, `.rodata`, а також змінні для кожного процесора (per-CPU). Вмикання цієї опції збільшує розмір образа ядра приблизно на 1.5–3 МБ RAM, але надає можливість системним трасувальникам (ftrace, eBPF, kprobes) звертатися до внутрішніх змінних за іменем. |
| **`CONFIG_KALLSYMS_BASE_RELATIVE=y`** | **Режим відносних зміщень (за замовчуванням у 64-бітних ядрах):** зберігає 32-бітні знакові зміщення відносно базової адреси `_stext` замість 64-бітних абсолютних вказівників. Зменшує розмір масиву адрес у 2 рази, а також забезпечує прозору сумісність із рандомізацією KASLR без необхідності перезапису адрес при завантаженні. |
| **`CONFIG_KALLSYMS_ABSOLUTE_PERCPU=y`** | **Абсолютні per-CPU адреси:** дозволяє зберігати абсолютні значення для специфічних змінних кожного процесора (per-CPU), чий адресний простір обчислюється окремо від базового виконуваного коду ядра і вимагає спеціального декодування адреси. |

## 2. Параметр безпеки sysctl: /proc/sys/kernel/kptr_restrict

Параметр `kptr_restrict` регулює доступ користувацького простору до виводу справжніх вказівників та адрес пам'яті ядра через псевдофайли (`/proc/kallsyms`, `/proc/modules`, `/proc/net/*`, `/proc/slabinfo`) та специфікатор `%pK` у `printk`.

### Детальна матриця режимів доступу та привілеїв

Управління потік даних адрес ядра здійснюється за допомогою системи мандатів POSIX capabilities. Нижче наведено розвернуту матрицю поведінки системи для кожного з трьох режимів `kptr_restrict`.

| Значення | Права користувача | Поведінка виводу адрес у `/proc/kallsyms` | Вплив на безпеку та системний аналіз |
| :---: | :--- | :--- | :--- |
| **`0`** | Будь-який користувач | Виводяться справжні 64-бітні віртуальні адреси ядра в RAM. | **Повна відсутність захисту (Застаріле):** дозволяє звичайному користувачу дізнатися розкладку адрес ядра, спрощуючи обхід KASLR та конструювання атак ROP/JOP. Рекомендується використовувати лише на налагодових тестових стендах. |
| **`1`** | `root` або процес із `CAP_SYSLOG` | Виводяться справжні 64-бітні віртуальні адреси пам'яті. | **Базовий захист (За замовчуванням у багатьох дистрибутивах):** привілейовані системні утиліти моніторингу та діагностики мають повну інформацію, тоді як потенційно компрометовані звичайні користувацькі процеси бачать нулі. |
| **`1`** | Звичайний користувач (без `CAP_SYSLOG`) | Усі адреси маскуються нулями `0000000000000000`. | Унеможливлює зчитування розкладки адрес ядра непідтвердженим користувачем. Запобігає витоку адрес функцій-мішеней для гаджетів ROP. |
| **`2`** | Будь-який процес (включно з `root`) | Усі адреси маскуються нулями `0000000000000000`. | **Максимальний захист:** унеможливлює витік адрес ядра навіть при компрометації процесів із правами суперкористувача або витоку логів у привілейованому контейнері. |

### Механіка перевірки привілеїв у коді ядра

При виконанні системного виклику `read()` для файлу `/proc/kallsyms` шар VFS викликає внутрішню функцію `kallsyms_show_value()`, яка аналізує мандати поточного процесу `current_cred()`:

```c
/* Концептуальна логіка перевірки kptr_restrict у ядрі Linux */
static bool kallsyms_show_value(const struct cred *cred)
{
    switch (kptr_restrict) {
    case 0:
        return true;
    case 1:
        if (has_ns_capability(cred, &init_user_ns, CAP_SYSLOG))
            return true;
        fallthrough;
    case 2:
    default:
        return false;
    }
}
```

Якщо функція `kallsyms_show_value()` повертає `false`, генератор рядків `seq_printf()` замінює дійсне значення віртуальної адреси символу на 64-бітний нульовий заповнювач `0000000000000000`.

## 3. Специфікація псевдофайла /proc/kallsyms та типізація символів

Псевдофайл `/proc/kallsyms` генерується динамічно під час читання шматками за допомогою шару `seq_file`. Кожен рядок представляє один символ ядра або завантаженого модуля.

### Специфікація рядкового формату

```
<адреса_пам'яті> <символ_типу> <ім'я_символу> [<назва_модуля>]
```

Приклад виводу при наявності привілеїв `CAP_SYSLOG`:

```
ffffffff81123456 T vfs_read
ffffffff81123600 t lookup_fast
ffffffff82401000 D sys_call_table
ffffffff82c05120 B jiffies
ffffffffc0201040 t ext4_mkdir [ext4]
```

### Детальна класифікація літерних кодів символів (Symbol Types)

Літерний код символу генерується утилітою `nm` під час збірки ядра або драйвера. Регістр літери є фундаментальним показником видимості символу: **велика літера** означає глобальний або експортований символ, **мала літера** — локальний символ із позначкою `static`.

- **`T` / `t` (Text):** Виконуваний код функцій у секції `.text`. Глобальні символи `T` можна викликати з інших об'єктних файлів, тоді як `t` є внутрішніми функціями конкретного файлу вихідного коду.
- **`D` / `d` (Data):** Ініціалізовані глобальні та статичні змінні у секції `.data`.
- **`B` / `b` (BSS):** Неініціалізовані змінні у секції `.bss`, які при завантаженні ядра заповнюються нульовими байтами.
- **`R` / `r` (Read-only data):** Секція `.rodata`, що містить константи, рядкові літерали, таблиці переривань та структури описувачів.
- **`V` / `v` (Weak object):** Слабий об'єкт даних. Якщо при компонуванні з'являється звичайний символ із таким же іменем, слабий символ замінюється без помилки лінкувальника.
- **`W` / `w` (Weak symbol):** Слаба функція. Дозволяє драйверам надавати стандартну реалізацію функції, яку архітектурний код може перевизначити власною оптимізованою версією.
- **`A` (Absolute):** Абсолютний символ, числове значення якого є фіксованим і не підлягає зсуву при зміщенні секцій у пам'яті.
- **`N` (Debugging symbol):** Символ відлагодження, який використовується інструментами збірки та аналізу.

## 4. Специфікатори форматування printk для символів (%p)

Підсистема `vsprintf` у ядрі Linux розширює стандартний специфікатор `%p` (покажчик) спеціальними модифікаторами. Під час форматування повідомлень логу ядро викликає внутрішню функцію `pointer()`, яка розпізнає модифікатор і звертається до `kallsyms_lookup()`.

### Специфікація модифікаторів формату

| Специфікатор | Синтаксис форматування | Приклад підстановки у лог | Повторна обробка KASLR |
| :--- | :--- | :--- | :---: |
| **`%pS`** | `%pS` | `vfs_read+0x43/0x140` | Так (Автоматично) |
| **`%pS` (модуль)**| `%pS` | `ext4_mkdir+0x12/0x80 [ext4]` | Так (Автоматично) |
| **`%ps`** | `%ps` | `vfs_read` | Так (Автоматично) |
| **`%pB`** | `%pB` | `page_fault_oops+0x170/0x4e0` | Так (Зсув -1 байт) |
| **`%pSR`** | `%pSR` | `vfs_read+0x43/0x140` | Так (Без випрямлення) |
| **`%pK`** | `%pK` | `ffffffff81123456` або `0000000000000000` | Перевіряє `kptr_restrict` |

### Особливості специфікатора %pB для трасування стека

Специфікатор `%pB` (англ. *backtrace*) розроблено спеціально для коректного відображення стека викликів функцій. Під час виклику функції інструкція `CALL` записує у стек адресу повернення — тобто адресу інструкції, яка розташована **одразу після** виклику `CALL`.

Якщо функція, що викликалася, була останньою інструкцією у блоці коду або перед нею сталася помилка адресації, адреса повернення може вказувати на початок **наступної** функції у пам'яті. Використання звичайного специфікатора `%pS` призвело б до помилкового друку імені зовсім іншої функції з оффсетом `+0x0`.

Специфікатор `%pB` автоматично віднімає 1 байт від адреси вказівника перед викликом `kallsyms_lookup()`. Це гарантує, що адреса влучає всередину тіла дійсної функції, яка зробила виклик, після чого відновлює точний оффсет.

## 5. Програмний API ядра (Header: `<linux/kallsyms.h>`)

Підсистема `kallsyms` надає декілька функцій для роботи з символами у внутрішньому коді ядра та драйверах.

### 5.1. `kallsyms_lookup()`

```c
const char *kallsyms_lookup(unsigned long addr,
                            unsigned long *symbolsize,
                            unsigned long *offset,
                            char **modname,
                            char *namebuf);
```

#### Детальний опис роботи:
Функція приймає віртуальну адресу `addr` і шукає символ у вбудованій таблиці `kallsyms_offsets[]`, а також у таблицях усіх завантажених модулів ядра.
- Якщо відповідний символ знайдено, функція копіює розпаковане ім'я у буфер `namebuf`, записує розмір функції у `*symbolsize`, зміщення у `*offset`, а вказівник на назву модуля у `*modname`.
- Якщо символ належить основному образу ядра `vmlinux`, `*modname` встановлюється у `NULL`.
- Якщо адреса поза межами відомих символів, функція повертає `NULL`.

#### Обмеження контексту виконання:
Функція `kallsyms_lookup()` може безпечно викликатися з будь-якого контексту виконання, включаючи контексти апаратних переривань (IRQ) та атомарні секції, оскільки зчитування таблиць `.rodata` виконується без захоплення спадаючих блокувань (lockless execution).

---

### 5.2. `kallsyms_lookup_name()`

```c
unsigned long kallsyms_lookup_name(const char *name);
```

#### Детальний опис роботи:
Приймає рядкову назву символу `name` (наприклад, `"sys_call_table"` або `"vfs_read"`) і виконує розпакування імен символів, порівнюючи їх із запитом.
- При збігу повертає 64-бітну поточну віртуальну адресу символу у пам'яті RAM з урахуванням зсуву KASLR.
- Якщо символ не знайдено, повертає `0`.

> [!WARNING]
> У ядрах Linux 5.7+ функція видалена з експорту (`EXPORT_SYMBOL_GPL`). Прямий виклик з завантажуваних модулів заборонено з міркувань безпеки.

---

### 5.3. `kallsyms_on_each_symbol()`

```c
int kallsyms_on_each_symbol(int (*fn)(void *data, const char *name,
                                      struct module *mod,
                                      unsigned long addr),
                            void *data);
```

#### Детальний опис роботи:
Послідовно обходить усі символи ядра та завантажених модулів. Для кожного символу викликається функція-колбек `fn`.
- Якщо колбек `fn` повертає `0`, обхід продовжується до останнього символу.
- Якщо колбек повертає ненульове значення, обхід негайно припиняється, а повернуте значення стає результатом `kallsyms_on_each_symbol()`.
- Це основний безпечний спосіб пошуку символів за маскою або шаблоном у сучасних ядрах.

## 6. Порівняльна характеристика System.map проти /proc/kallsyms

Нижче наведено підсумкову порівняльну таблицю двох головних джерел символів операційної системи Linux, що систематизує їхні відмінності за п'ятьма ключовими критеріями.

| Критерій порівняння | Файл System.map | Віртуальний файл /proc/kallsyms |
| :--- | :--- | :--- |
| **Формат зберігання** | Статичний текстовий файл на диску (`/boot/System.map-$(uname -r)`). | Віртуальний файл у пам'яті RAM, що генерується через `seq_file`. |
| **Своєчасність та динамічність** | Статичний. Створюється в момент компіляції базового ядра. | Динамічний. Оновлюється при кожному завантаженні або вивантаженні модуля `.ko`. |
| **Підтримка модулів ядра** | **Відсутня:** містить лише символи статичного бінарного образу `vmlinux`. | **Повна:** містить символи базового ядра та всіх завантажених драйверів. |
| **Взаємодія з KASLR** | **Несумісний:** містить фіксовані адреси збірки, які не враховують boot-offset. | **Повна сумісність:** автоматично додає зсув KASLR до адрес під час виконання. |
| **Захист від витоку адрес** | Обмежений правами доступу до файлу у файловій системі (`0600` або `0644`). | Регулюється рубільником `kernel.kptr_restrict` та правами `CAP_SYSLOG`. |
