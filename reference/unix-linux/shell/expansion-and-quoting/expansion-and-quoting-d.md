# Розгортання й лапки: параметр, поділ на слова, глобінг і правило екранування

<preknowlist>
- [Концепції ядра Linux](book:unix-linux/kernel-and-userspace) — базові поняття системних викликів та VFS.
</preknowlist>

Під час роботи з командним рядком (shell) у Unix-подібних операційних системах (таких як Linux або macOS) оболонка (наприклад, bash, zsh, sh) виконує низку перетворень над текстом, який ви вводите, перш ніж передати його на виконання як команду. Цей процес перетворення називається **розгортанням (expansion)**. Разом із розгортанням нерозривно пов'язане поняття **цитування або використання лапок (quoting)**, яке дозволяє керувати тим, як оболонка інтерпретує спеціальні символи.

Розуміння механізмів розгортання та правил використання лапок є критично важливим для ефективного та безпечного написання shell-скриптів і щоденної роботи в терміналі. У цій статті ми детально розглянемо всі етапи розгортання, які визначаються стандартом POSIX, а також механізми екранування та лапок.

## Що таке розгортання в оболонці?

Коли ви натискаєте клавішу Enter після введення команди, оболонка не просто бере цей рядок і виконує його. Вона спочатку розбиває рядок на токени (слова), а потім застосовує до них набір правил, щоб розгорнути змінні, підставити результати виконання інших команд, розкрити шаблони імен файлів тощо. Тільки після того, як усі ці перетворення завершено, оболонка намагається знайти відповідну команду та передати їй розгорнуті аргументи.

Згідно зі стандартом POSIX, процес розгортання відбувається в чітко визначеному порядку:
1. **Розгортання фігурних дужок (Brace Expansion)** — хоча це не є строго частиною стандарту POSIX (це розширення, яке використовується в Bash, Zsh, Ksh), воно виконується першим, якщо підтримується оболонкою.
2. **Розгортання тильди (Tilde Expansion)**.
3. **Розгортання параметрів та змінних (Parameter and Variable Expansion)**.
4. **Підстановка команд (Command Substitution)**.
5. **Арифметичне розгортання (Arithmetic Expansion)**.
6. **Поділ на слова (Word Splitting)**.
7. **Розгортання імен файлів (Filename Expansion / Globbing)**.

Давайте детально розглянемо кожен із цих етапів.

## 1. Розгортання фігурних дужок (Brace Expansion)

Розгортання фігурних дужок дозволяє генерувати довільні рядки. Воно є дуже зручним для створення списків аргументів, які мають спільний префікс або суфікс. Як зазначалося, це не є офіційною частиною POSIX, але широко використовується в сучасних оболонках.

Формат:
- Списки: `{рядок1,рядок2,...}`
- Діапазони: `{початок..кінець}` або `{початок..кінець..крок}`

**Приклади:**

```bash
$ echo a{d,c,b}e
ade ace abe

$ mkdir /usr/local/src/bash/{old,new,dist,bugs}
```

Використання діапазонів (підтримується в Bash 3.0+ та сучасних Zsh):

```bash
$ echo {1..5}
1 2 3 4 5

$ echo {a..e}
a b c d e

$ echo {00..10..2}
00 02 04 06 08 10
```

Розгортання фігурних дужок виконується *до* будь-яких інших розгортань, і в ньому можуть брати участь лише літеральні символи, хоча вкладені дужки також підтримуються.

## 2. Розгортання тильди (Tilde Expansion)

Символ тильди (`~`) на початку слова (або після двокрапки `:` в деяких змінних, як-от `PATH`) розгортається у шлях до домашнього каталогу.

- `~` розгортається у домашній каталог поточного користувача (значення змінної `$HOME`).
- `~user` розгортається у домашній каталог користувача `user`.
- `~+` розгортається в поточний робочий каталог (`$PWD`).
- `~-` розгортається в попередній робочий каталог (`$OLDPWD`).

**Приклади:**

```bash
$ echo ~
/home/alice

$ echo ~root
/root
```

Якщо користувач не існує або оболонка не може виконати розгортання, слово залишається незмінним:

```bash
$ echo ~nonexistentuser
~nonexistentuser
```

## 3. Розгортання параметрів (Parameter Expansion)

Це один з найпотужніших і найскладніших етапів. Змінні та параметри позначаються символом `$`, після якого йде ім'я параметра. Для уникнення неоднозначностей ім'я параметра можна (і часто потрібно) брати у фігурні дужки: `${parameter}`.

**Базове використання:**

```bash
$ name="World"
$ echo "Hello $name"
Hello World
```

### Модифікатори розгортання параметрів

POSIX оболонка підтримує безліч модифікаторів для обробки значень змінних під час їх розгортання:

- **Значення за замовчуванням (Default values):**
  - `${var:-default}` — якщо `var` не встановлена або порожня, повертає `default`.
  - `${var:=default}` — якщо `var` не встановлена або порожня, присвоює їй `default` і повертає `default`. (Не працює для позиційних параметрів).
  
- **Перевірка наявності (Check and Error):**
  - `${var:?message}` — якщо `var` не встановлена або порожня, виводить помилку з текстом `message` і припиняє виконання скрипта.

- **Альтернативне значення (Alternative value):**
  - `${var:+alternative}` — якщо `var` встановлена і не порожня, повертає `alternative`. Інакше нічого не повертає.

### Маніпуляції з рядками

- **Довжина рядка:**
  - `${#var}` — повертає довжину значення змінної.

- **Видалення префікса (Prefix removal):**
  - `${var#pattern}` — видаляє найкоротший збіг шаблону `pattern` з початку рядка.
  - `${var##pattern}` — видаляє найдовший збіг шаблону `pattern` з початку рядка.

- **Видалення суфікса (Suffix removal):**
  - `${var%pattern}` — видаляє найкоротший збіг шаблону `pattern` з кінця рядка.
  - `${var%%pattern}` — видаляє найдовший збіг шаблону `pattern` з кінця рядка.

**Приклади видалення підрядків:**

```bash
$ file="archive.tar.gz"
$ echo ${file#*.}
tar.gz
$ echo ${file##*.}
gz
$ echo ${file%.*}
archive.tar
$ echo ${file%%.*}
archive
```

У Bash та Zsh також доступні **пошук і заміна (Search and Replace)** та **вилучення підрядка (Substring Extraction)**, хоча це не стандарт POSIX:
- `${var/pattern/string}` — замінює перший збіг.
- `${var//pattern/string}` — замінює всі збіги.
- `${var:offset:length}` — вилучає підрядок.

## 4. Підстановка команд (Command Substitution)

Підстановка команд дозволяє виконати команду, перехопити її стандартний вивід (stdout) і підставити його як текст у командний рядок.

Синтаксис POSIX: `$(command)`. Існує також старий синтаксис зі зворотними апострофами (backticks): `` `command` ``. Рекомендується завжди використовувати `$(...)`, оскільки він підтримує вкладеність і має набагато передбачуваніші правила екранування.

**Приклад:**

```bash
$ echo "Сьогоднішня дата: $(date +%F)"
Сьогоднішня дата: 2023-10-25

$ files=$(ls *.txt)
```

Зауважте, що під час підстановки команд оболонка видаляє всі символи нового рядка (newlines) у кінці результату виводу.

## 5. Арифметичне розгортання (Arithmetic Expansion)

Арифметичне розгортання дозволяє оболонці обчислювати цілочисельні математичні вирази.

Синтаксис: `$((вираз))`

**Приклади:**

```bash
$ a=5
$ echo $((a + 3 * 2))
11
$ echo $(((a+3)*2))
16
```

Всередині арифметичного розгортання змінні можна вказувати без символу `$`: `$((var1 + var2))` і `$(( $var1 + $var2 ))` є еквівалентними, якщо змінні містять числа.

## 6. Поділ на слова (Word Splitting)

Це один з найменш зрозумілих для новачків, але найважливіших етапів. Після того, як відбулося розгортання параметрів, підстановка команд або арифметичне розгортання (і *тільки* якщо результати цих розгортань не були взяті в подвійні лапки), оболонка розбиває отриманий текст на окремі слова.

Правила розбиття визначаються спеціальною змінною середовища — **`IFS` (Internal Field Separator)**. За замовчуванням `IFS` містить пробіл, табуляцію та символ нового рядка (`<space><tab><newline>`).

Будь-яка послідовність символів із `IFS` сприймається як роздільник слів.

**Приклад проблеми з поділом на слова:**

```bash
$ file="My Document.txt"
$ ls $file
ls: cannot access 'My': No such file or directory
ls: cannot access 'Document.txt': No such file or directory
```

Що тут сталося?
1. Змінна `$file` розгорнулася у рядок `My Document.txt`.
2. Оскільки результат розгортання не був у лапках, оболонка застосувала поділ на слова. `IFS` містить пробіл, тому рядок був розбитий на два слова: `My` та `Document.txt`.
3. Команді `ls` було передано два аргументи.

Щоб запобігти поділу на слова, необхідно використовувати подвійні лапки (про це нижче).

## 7. Розгортання імен файлів (Globbing / Filename Expansion)

Після того, як відбувся поділ на слова, оболонка сканує кожне слово на наявність символів шаблону: `*`, `?` та `[...]`. Якщо такі символи знайдені (і вони не були екрановані або взяті в лапки), оболонка намагається знайти файли у файловій системі, які відповідають цьому шаблону, і замінює слово на список знайдених файлів.

- `*` — відповідає будь-якій кількості символів (включаючи нуль).
- `?` — відповідає рівно одному будь-якому символу.
- `[...]` — відповідає одному символу з набору, вказаного в дужках (наприклад, `[a-z]`, `[0-9]`).

**Приклади:**

```bash
$ ls *.txt
file1.txt data.txt

$ rm file?.log
```

Якщо файлів, що відповідають шаблону, не знайдено, поведінка залежить від оболонки. За стандартом POSIX, слово з шаблоном залишається незмінним. У Bash можна змінити цю поведінку за допомогою опцій `nullglob` (видаляє слово, якщо нічого не знайдено) або `failglob` (викидає помилку).

> **Важливий момент:** Глобінг не відповідає файлам, ім'я яких починається з крапки (`.`), тобто прихованим файлам. Їх потрібно вказувати явно: `.*` або налаштовувати оболонку (наприклад, `shopt -s dotglob` в Bash).

## Лапки і правило екранування (Quoting)

Отже, ми побачили, що оболонка дуже активно намагається "допомогти", розгортаючи змінні, розбиваючи слова та шукаючи файли. Але що робити, якщо ми хочемо передати команді буквальний рядок, який містить пробіли, символи `$` або `*`?

Тут на допомогу приходять лапки та екранування. Вони дозволяють нам сказати оболонці: "Не інтерпретуй ці символи, сприймай їх буквально".

В оболонці існує три основні механізми квотування: екранування зворотним слешем, одинарні лапки та подвійні лапки.

### Екранування зворотним слешем (Backslash Escaping)

Зворотний слеш (`\`) екранує (зберігає буквальне значення) наступний за ним символ.

**Приклади:**

```bash
$ echo \$HOME
$HOME

$ echo My\ Document.txt
My Document.txt

$ echo \*
*
```

Якщо зворотний слеш стоїть у кінці рядка (перед символом нового рядка), це розглядається як об'єднання рядків: оболонка ігнорує і слеш, і перенесення рядка, дозволяючи розбити довгу команду на кілька фізичних рядків.

### Одинарні лапки (Single Quotes)

Одинарні лапки (`'...'`) — це "найсильніший" вид цитування. Все, що знаходиться між одинарними лапками, зберігає своє буквальне значення. Оболонка **не виконує жодних розгортань** всередині одинарних лапок. Не розгортаються змінні, не працює `$(...)`, ігнорується навіть зворотний слеш.

Єдине обмеження: всередині одинарних лапок неможливо розмістити одинарну лапку, навіть за допомогою зворотного слеша (`\'` не спрацює).

**Приклади:**

```bash
$ echo 'Ваш домашній каталог: $HOME'
Ваш домашній каталог: $HOME

$ echo 'Ціна: $100'
Ціна: $100
```

Щоб вставити одинарну лапку в рядок, зазвичай закривають першу одинарну лапку, екранують одинарну лапку слешем, і відкривають знову: `'I'\''m here'`.

### Подвійні лапки (Double Quotes)

Подвійні лапки (`"..."`) — це "слабкіший" вид цитування. Вони запобігають поділу на слова та глобінгу, але **дозволяють розгортання параметрів (`$`), підстановку команд (`$(...)`) та арифметичне розгортання (`$((...))`)**.

Саме тому золотим правилом написання shell-скриптів є: **завжди беріть розгортання змінних у подвійні лапки, якщо ви навмисно не хочете, щоб відбувся поділ на слова або глобінг**.

**Приклад, що демонструє різницю:**

```bash
$ files="file 1.txt  file 2.txt"

# БЕЗ лапок:
# 1. Розгортається значення: file 1.txt  file 2.txt
# 2. Поділ на слова: "file", "1.txt", "file", "2.txt" (зайві пробіли зникають!)
$ printf "[%s]\n" $files
[file]
[1.txt]
[file]
[2.txt]

# З лапками:
# 1. Розгортається значення.
# 2. Оскільки воно в подвійних лапках, поділ на слова НЕ відбувається.
# Увесь рядок передається як один аргумент.
$ printf "[%s]\n" "$files"
[file 1.txt  file 2.txt]
```

Особливості подвійних лапок:
- Всередині подвійних лапок зворотний слеш зберігає свою екрануючу силу лише перед специфічними символами: `$`, `` ` ``, `"`, `\`, або символом нового рядка. В інших випадках він залишається літеральним символом.

### Спеціальний випадок: розгортання масивів `@` та `*`

Символи `@` і `*` використовуються для розгортання всіх позиційних параметрів скрипта/функції (або всіх елементів масиву в Bash/Zsh). Поведінка їх суттєво відрізняється, коли вони знаходяться в подвійних лапках.

- `$*` і `$@` без лапок поводяться однаково: вони розгортаються у список слів, які потім піддаються поділу на слова і глобінгу. Це рідко буває тим, що вам потрібно.
- `"$*"` (у подвійних лапках) розгортається в **один рядок**, де всі аргументи з'єднані першим символом змінної `IFS` (зазвичай пробілом). Наприклад: `"arg1 arg2 arg3"`.
- `"$@"` (у подвійних лапках) — це магія оболонки. Він розгортається в **окремі слова для кожного аргументу**, при цьому зберігаючи пробіли всередині самих аргументів. Тобто він еквівалентний: `"arg1" "arg2" "arg3"`.

Це найважливіше розрізнення при передачі аргументів далі іншим командам.

```bash
#!/bin/sh
# Демонстрація передачі аргументів

echo "Використання \"\$@\":"
for arg in "$@"; do
    echo "  Аргумент: [$arg]"
done

echo "Використання \"\$*\":"
for arg in "$*"; do
    echo "  Аргумент: [$arg]"
done
```

Якщо запустити цей скрипт як `./script "arg with spaces" arg2`:

```
Використання "$@":
  Аргумент: [arg with spaces]
  Аргумент: [arg2]
Використання "$*":
  Аргумент: [arg with spaces arg2]
```

## Висновок

Командна оболонка (shell) — це потужний інструмент, але її поведінка може здатися непередбачуваною, якщо не розуміти процесу розгортання. Кожного разу, коли ви пишете команду або скрипт, уявляйте цей ланцюжок: від фігурних дужок до глобінгу, з поділом на слова посередині. І завжди пам'ятайте про правило: екрануйте змінні подвійними лапками (`"$var"`), якщо не хочете, щоб оболонка сприйняла пробіли всередині змінної як роздільники аргументів або спробувала розгорнути символи `*` та `?` як імена файлів.
