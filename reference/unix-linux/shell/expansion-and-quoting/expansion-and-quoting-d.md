Операційна система Linux при виконанні системного виклику `execve(2)` вимагає від процесу-ініціатора чітко сформованого вектора аргументів — масиву покажчиків на null-terminated рядки `argv[]`. Ядро не виконує жодного аналізу текстового рядка, не знає про пробіли як роздільники параметрів і не інтерпретує спеціальні символи на кшталт зірочок чи знаків долара. Водночас користувач у терміналі вводить єдиний суцільний рядок символів. Оболонка (shell) виступає в ролі транслятора, чиє головне завдання — розібрати цей сирий текстовий рядок, застосувати до нього серію послідовних системних перетворень, які називаються **розгортанням (expansion)**, та сформувати остаточний масив `argv[]` перед передачею управління ядру.

Якщо у введеному рядку зустрічаються метасимволи оболонки (наприклад, `$`, `*`, `?`, `|`, `&`, `<`, `>`), вони сприймаються інтерпретатором як інструкції для виконання трансляцій. Для того щоб передати ці символи у вихідну програму в їх буквеному (literal) вигляді, застосовується механізм **цитування або використання лапок (quoting)**. Взаємодія розгортання та лапок визначає, де закінчується один аргумент і починається інший, які файли будуть оброблені та які команди будуть виконані операційною системою.

## Фундаментальний конвеєр розгортання POSIX

Процес перетворення введеного рядка у підсумковий масив `argv[]` не є одноразовою заміною символів. Це строго впорядкований фазовий конвеєр. Кожна фаза отримує на вхід результат роботи попереднього етапу і трансформує токени за чітко визначеними правилами POSIX.2. Зміна порядку цих етапів унеможливила б передбачувану обробку рядків.

![Послідовність етапів розгортання рядка в командній оболонці](/reference/unix-linux/shell/expansion-and-quoting/img/expansion-flow.svg)
*Послідовність етапів розгортання рядка від введення користувачем до формування кінцевого вектора argv[].*

Конвеєр обробки складається з шести основних етапів POSIX (та одного початкового розширення, наявного у більшості сучасних оболонок):

1. **Розгортання фігурних дужок (Brace Expansion)** — не-POSIX розширення (Bash, Zsh, Ksh), що генерує додаткові текстові токени до початку будь-яких перевірок.
2. **Розгортання тильди (Tilde Expansion)** — заміна `~` на шляхи домашніх каталогів користувачів.
3. **Потрійне розгортання в один прохід**:
   - **Розгортання параметрів (Parameter Expansion)** — підстановка значень змінних `$VAR`.
   - **Підстановка команд (Command Substitution)** — виконання вкладених команд `$(cmd)` та підстановка їхнього виводу.
   - **Арифметичне розгортання (Arithmetic Expansion)** — обчислення виразів `$((expr))`.
4. **Поділ на слова (Word Splitting)** — розбиття незахищених подвійними лапками результатів етапу 3 на окремі аргументи за роздільниками `IFS`.
5. **Розгортання імен файлів (Filename Expansion / Globbing)** — заміна масок `*`, `?`, `[...]` на реальні шляхи з файлової системи.
6. **Видалення лапок (Quote Removal)** — очищення токенів від екрануючих символів `'`, `"`, `\`, що використовувалися для захисту метасимволів.

### 1. Розгортання фігурних дужок (Brace Expansion)

Розгортання фігурних дужок виконується першим, ще до того, як оболонка перевірить існування змінних чи файлів на диску. Воно приймає токен і генерує з нього список нових слів шляхом комбінування префіксів, списків та суфіксів.

Синтаксис списку:

```bash
префікс{рядок1,рядок2,рядокN}суфікс
```

При виконанні виразу `file_{A,B}.txt` оболонка генерує два окремих слова `file_A.txt` та `file_B.txt`. Завдяки тому що ця фаза передує розгортанню тильди та змінних, згенеровані рядки надалі проходять усі наступні фази конвеєра незалежно.

Фігурні дужки підтримують довільне вкладення:

```bash
echo img_{2025,2026}_{01,02}.png
# Генерує 4 слова: img_2025_01.png img_2025_02.png img_2026_01.png img_2026_02.png
```

Синтаксис діапазонів (Bash 3.0+, Zsh):

```bash
{початок..кінець..крок}
```

Обчислення діапазону `{1..5..2}` генерує рядки `1`, `3`, `5`. Крок може бути й від'ємним, наприклад `{10..0..-2}`. Якщо діапазон містить числа з провідними нулями, наприклад `{01..05}`, оболонка зберігає ширину форматування для кожного згенерованого слова: `01`, `02`, `03`, `04`, `05`. Дійсними є також символьні діапазони: `{a..e}` розгортається у `a b c d e`.

Критична особливість: розгортання фігурних дужок вимагає наявності хоча б однієї некерованої коми або коректного діапазону всередині дужок. Вираз `{single}` не буде розгорнуто, і слово залишиться в початковому вигляді `{single}`.

### 2. Розгортання тильди (Tilde Expansion)

Якщо слово починається з некерованого символу тильди (`~`), оболонка перевіряє всі символи від тильди до першого незахищеного косого слеша (`/`) або кінця слова. Цей шматок називається *префіксом тильди*.

Правила розгортання префікса тильди:

- `~` — розгортається у значення змінної оточення `$HOME`. Якщо `$HOME` не визначено, оболонка звертається до системного бази даних `nsswitch` (файл `/etc/passwd` або PAM) для визначення домашнього каталогу поточного користувача через системні функції `getpwuid(getuid())`.
- `~user` — шукає користувача `user` у системній базі даних через `getpwnam("user")` і замінює префікс на його домашній каталог (наприклад, `/home/alice`). Якщо користувача з таким іменем не існує у системі, розгортання не відбувається, і рядок залишається `~user`.
- `~+` — розгортається у значення змінної `$PWD` (поточний робочий каталог).
- `~-` — розгортається у значення змінної `$OLDPWD` (попередній робочий каталог).

Розгортання тильди також відбувається всередині присвоєнь змінних (після знака `=`) та після двокрапки (`:`) у значеннях змінних, таких як `PATH`. Вираз `PATH=~/bin:~alice/bin` буде успішно розгорнуто в `/home/user/bin:/home/alice/bin`.

### 3. Параметри, команди та арифметика: підстановки в один прохід

Після розгортання тильди оболонка сканує рядок зліва направо за один прохід, виконуючи три види підстановок: розгортання параметрів, підстановку команд та арифметичні обчислення. Ці три операції мають однаковий пріоритет і обробляються в порядку зустрічання у рядку.

#### Розгортання параметрів (Parameter Expansion)

Основна форма розгортання параметрів — `$NAME` або `${NAME}`. Фігурні дужки обов'язкові, якщо після імені параметра йдуть символи, які можуть бути витлумачені як частина імені (наприклад, `${VAR}text` замість `$VARtext`).

POSIX визначає набір розширених модифікаторів для перевірки стану змінних:

- `${VAR:-default}` — якщо `VAR` не встановлено або порожнє, підставити `default`. Сама змінна `VAR` не змінюється.
- `${VAR:=default}` — якщо `VAR` не встановлено або порожнє, присвоїти їй значення `default` і підставити його.
- `${VAR:?error_message}` — якщо `VAR` не встановлено або порожнє, вивести `error_message` в `stderr` та перервати виконання скрипту.
- `${VAR:+alternative}` — якщо `VAR` встановлено і не порожнє, підставити `alternative`; інакше підставити порожній рядок.

Якщо двоїкрапку `:` опущено (наприклад, `${VAR-default}`), перевірка здійснюється лише на факт існування змінної (unset), а порожній рядок вважається дійсним значенням.

Модифікатори обрізання рядків працюють за допомогою зіставлення масок:

- `${VAR#pattern}` — видаляє найкоротший збіг `pattern` з початку значення `VAR`.
- `${VAR##pattern}` — видаляє найдовший збіг `pattern` з початку значення `VAR`.
- `${VAR%pattern}` — видаляє найкоротший збіг `pattern` з кінця значення `VAR`.
- `${VAR%%pattern}` — видаляє найдовший збіг `pattern` з кінця значення `VAR`.

Приклад обробки шляхів до файлів:

```bash
FILE="/var/log/syslog.tar.gz"
echo "${FILE##*/}"   # Виведе: syslog.tar.gz (видалено найдовший префікс */)
echo "${FILE%.*}"    # Виведе: /var/log/syslog.tar (видалено найкоротший суфікс .*)
```

Отримання довжини значення параметра виконується через `${#VAR}`.

Додатково розширення Bash 4.0+ дозволяють змінювати регістр символів та виконувати заміну:
- `${VAR/pattern/replacement}` — замінює перше входження `pattern` на `replacement`.
- `${VAR//pattern/replacement}` — замінює всі входження `pattern` на `replacement`.
- `${VAR^}` — робить першу літеру великою, `${VAR^^}` — переводить весь рядок у верхній регістр.
- `${VAR,}` — робить першу літеру малою, `${VAR,,}` — переводить весь рядок у нижній регістр.

#### Підстановка команд (Command Substitution)

Підстановка команд дозволяє виконати зовнішню команду або підпрограму та підставити її стандартний вивід (`stdout`) безпосередньо у вихідний командний рядок.

POSIX підтримує дві форми синтаксису:

1. **Сучасна форма**: `$(command)`
2. **Застаріла форма (backticks)**: `` `command` ``

Сучасна форма `$(command)` є переважною з міркувань безпеки та читабельності. Вона дозволяє безпроблемне гніздування викликів:

```bash
LOG_DIR="$(dirname "$(realpath "$FILE")")"
```

При використанні застарілої форми зі зворотними апострофами для внутрішніх лапок або гніздування вимагається складне екранування через зворотні слеші: `` `dirname \`realpath "$FILE"\`` ``, що часто призводить до помилок парсингу.

Важлива властивість: оболонка автоматично видаляє всі завершальні символи переведення рядка (`\n`) з виводу виконаної команди. Внутрішні переведення рядка зберігаються, але під час наступного етапу (Word Splitting) вони будуть перетворені на роздільники слів, якщо рядок не взято у подвійні лапки.

#### Підстановка процесів (Process Substitution)

У сучасних оболонках (Bash, Zsh, Ksh93) наявний розширений механізм **підстановки процесів**: `<(command)` та `>(command)`. Вона виконує команду у фоновому режимі та підставляє замість виразу шлях до анонімного іменованого каналу FIFO або файл пристрою `/dev/fd/N`. Це дозволяє передавати вивід команди у програми, які очікують як аргумент шлях до файла на диску:

```bash
diff -u <(sort file1.txt) <(sort file2.txt)
```

#### Арифметичне розгортання (Arithmetic Expansion)

Арифметичне розгортання забезпечує обчислення цілочисельних виразів у форматі:

```bash
$((expression))
```

Всередині арифметичного блоку оболонка обробляє змінні як цілі числа 64-бітної знаковості (`int64_t`). Знак долара перед іменами змінних всередині `$((...))` можна опускати:

```bash
A=5
B=10
RESULT=$(( A * 2 + B ))  # RESULT = 20
```

Арифметика оболонки підтримує базові оператори C: додавання, віднімання, множення, ділення, взяття за модулем, побітові зсуви (`<<`, `>>`), побітові операції (`&`, `|`, `^`) та тернарний оператор `cond ? expr1 : expr2`. Обчислення з плаваючою крапкою стандартною POSIX-оболонкою не підтримуються (для них застосовують зовні утиліти `bc` або `awk`).

### 4. Поділ на слова (Word Splitting)

Поділ на слова — це фаза, на якій скануються результати, отримані **виключно** від Parameter Expansion, Command Substitution та Arithmetic Expansion, якщо вони НЕ перебувають всередині подвійних лапок (`"..."`). Літеральний текст рядка, який був уведений користувачем без лапок, розбивається на токени ще на етапі первинного синтаксичного аналізу.

Поділ на слова керується значенням спеціальної змінної оточення `IFS` (Internal Field Separator). За замовчуванням `IFS` містить три символи: пробіл, табуляцію та новий рядок (`IFS=$' \t\n'`).

Символи `IFS` діляться на дві категорії:
- **Білий простір IFS (IFS whitespace)**: пробіл, табуляція, новий рядок.
- **Небілі символи IFS**: будь-які інші символи (наприклад, двокрапка, кома, вертикальна риска), які користувач вручну записує в `IFS`.

Алгоритм поділу:
1. Послідовності з кількох білих символів `IFS` на початку або в кінці розгорнутого рядка ігноруються.
2. Будь-яка послідовність з одного або кількох білих символів `IFS` всередині рядка слугує роздільником і розбиває рядок на два окремих слова.
3. Кожен небілий символ `IFS` (разом із будь-яким білим простором навколо нього) ділить рядок на слова. Два послідовних небілих символи `IFS` утворюють між собою порожнє слово.

Приклад зміни `IFS` для парсингу файлу `/etc/passwd`:

```bash
LINE="root:x:0:0:System Administrator:/root:/bin/bash"
IFS=":"
set -- $LINE
# Аргументи будуть чітко розділені на $1="root", $2="x", $3="0", $4="0", $5="System Administrator" тощо.
```

Якщо змінну `IFS` скинуто (unset), оболонка поводиться так, ніби `IFS` містить пробіл, табуляцію та новий рядок. Якщо `IFS` присвоєно порожнє значення (`IFS=""`), поділ на слова повністю вимикається, і результати підстановок зберігаються як єдине ціле.

### 5. Розгортання імен файлів (Globbing)

Після того як поділ на слова сформував список окремих токенів, кожен токен сканується на наявність некерованих лапками метасимволів шаблонів файлової системи: `*`, `?`, `[`.

Детальну історію того, як цей механізм еволюціонував від першої версії Unix із зовнішньою програмою `/etc/glob` до вбудованої фази оболонки, викладено в історичному екскурсі [📜 Від /etc/glob до POSIX: Еволюція розгортання та лапок у Unix](book:unix-linux/expansion-and-quoting/hist-glob-and-quoting.md).

Метасимволи глобінгу:

- `*` — відповідає будь-якому рядку символів будь-якої довжини (включаючи порожній рядок).
- `?` — відповідає рівно одному довільному символу.
- `[...]` — відповідає одному символу з указаної множини або діапазону. Наприклад, `[a-z]` означає будь-яку малу літеру, `[0-9]` — цифру. Якщо першим символом всередині дужок є `!` або `^` (наприклад `[!0-9]`), вираз означає заперечення — будь-який символ, що не є цифрою.

Механіка виконання глобінгу:
Оболонка бере токен з маскою і робить системні виклики до VFS (читання каталогів через `opendir(3)` та `readdir(3)`). Якщо маска містить шляхи з косими слешами (наприклад, `/var/log/*.log`), оболонка рекурсивно обходить відповідні каталоги.

Два важливих правила POSIX щодо прихованих файлів:
1. Символ крапки `.` на початку імені файла (наприклад `.bashrc`) вважається прихованим. Зірочка `*` або знак питання `?` ніколи не відповідають провідній крапці. Щоб знайти приховані файли, крапка має бути вказана у шаблоні явно: `.*`.
2. Символ косого слеша `/` у шляхах має завжди збігатися з явно вказаним `/` у шаблоні. Зірочка `*` не може перетнути межу каталогу.

#### Розширений глобінг (Extended Globbing)

При увімкненні опції `shopt -s extglob` у Bash доступний розширений синтаксис масок:

- `?(pattern-list)` — відповідає 0 або 1 входженню вказаних шаблонів.
- `*(pattern-list)` — відповідає 0 або більше входженням.
- `+(pattern-list)` — відповідає 1 або більше входженням.
- `@(pattern-list)` — відповідає рівно одному з вказаних шаблонів.
- `!(pattern-list)` — відповідає будь-якому рядку, що НЕ відповідає вказаним шаблонам.

Приклад виключення файлів при видаленні:

```bash
shopt -s extglob
rm -- !(important.txt|backup.tar) # Видалить усі файли, крім двох вказаних
```

Також опція `shopt -s globstar` дозволяє використовувати маску `**` для рекурсивного обходу всіх підкаталогів довільної глибини (`ls **/*.c`).

Якщо маска не знайшла жодного відповідного файла у файловій системі:
- За стандартом POSIX оболонка залишає шаблон у підсумковому аргументі незмінним у його буквеному вигляді (наприклад, `echo *.nonexistent` виведе `*.nonexistent`).
- У Bash поведінку можна змінити опціями `shopt -s nullglob` (повертати порожній рядок при відсутності збігів) або `shopt -s failglob` (генерувати помилку виконання).

### 6. Видалення лапок (Quote Removal)

Останньою фазою конвеєра є видалення лапок. Оболонка сканує згенеровані слова і видаляє всі некеровані символи одинарних лапок (`'`), подвійних лапок (`"`) та зворотних слешів (`\`), які використовувалися на попередніх етапах для захисту спецсимволів.

Символи лапок виконали свою роль на фазах поділу на слова та глобінгу — вони вказали оболонці, де не потрібно розбивати текст і де не треба шукати файли. На етапі `execve(2)` операційна система не повинна бачити самі захисні лапки, тому вони витираються з пам'яті токена.

Наприклад, слово `"my file".txt` після проходження через фазу видалення лапок перетворюється на чистий рядок `my file.txt`.

## Механіка лапок та екранування (Quoting Mechanics)

Лапки є інструментом скасування спеціальних значень символів. Без лапок будь-який пробіл ділить слово, а будь-яка зірочка викликає пошук у VFS. Лапки дозволяють явно вказувати оболонці, які частини рядка є буквальним текстом, а які — інструкціями для розгортання.

### Зворотний слеш (Escape Character)

Некерований зворотний слеш `\` зберігає буквальне значення наступного за ним ОДИНОЧНОГО символу. Завдяки цьому можна заекранувати будь-який метасимвол:

```bash
echo \$VAR   # Виведе: $VAR (розгортання змінної скасовано)
echo \*      # Виведе: * (глобінг скасовано)
echo "hello\ world" # Виведе: hello world
```

Особливий випадок — зворотний слеш перед символом новим рядком (`\\\n`). Ця комбінація вказує оболонці ігнорувати сам символ переведення рядка і продовжувати читання однієї команди з наступного фізичного рядка файлу або термінала.

### Одинарні лапки (Single Quotes / Strong Quoting)

Одинарні лапки `'...'` забезпечують найжорсткіший захист рядка. Будь-який символ, поміщений усередину одинарних лапок, втрачає своє спеціальне значення і стає буквальним текстом.

```bash
echo '$HOME *.txt $(date)'
# Виведе дослівний рядок: $HOME *.txt $(date)
```

В одинарних лапках не відбувається жоден вид розгортання.

Головне правило одинарних лапок: **всередину одинарних лапок неможливо вставити символ одинарної лапки**, навіть за допомогою зворотного слеша `\'`. Оскільки зворотний слеш усередині одинарних лапок вважається буквальним символом, вираз `'\'` буде витлумачений як відкрита лапка, за якою йде слеш, а друга лапка закриє рядок, залишивши наступний символ поза лапками.

Щоб передати одинарну лапку у складі рядка, доводиться закривати поточний блок одинарних лапок, вставляти заекрановану лапку `\'` або лапку у подвійних лапках `"'"` і знову відкривати одинарні лапки:

```bash
echo 'It'\''s working' # Виведе: It's working
```

### Подвійні лапки (Double Quotes / Weak Quoting)

Подвійні лапки `"..."` забезпечують гнучкий (слабкий) захист рядка. Вони захищають текст від **Word Splitting** (поділу на слова) та **Filename Expansion** (глобінгу), але зберігають можливість виконання розгортання параметрів, підстановки команд та арифметичного розгортання.

Всередині подвійних лапок зберігають своє спеціальне значення лише чотири символи:
1. `$` — для розгортання параметрів, команд та арифметики.
2. `` ` `` — для застарілої підстановки команд.
3. `"` — для закриття блоку подвійних лапок.
4. `\` — для екранування символів `$`, `` ` ``, `"`, `\` та переведення рядка.

Порівняння поведінки рядка без лапок та у подвійних лапках:

```bash
DIR="my docs"
ls $DIR     # Помилка! Розгортається у виклики: ls "my" "docs" (Word Splitting розбив рядок)
ls "$DIR"   # Успіх! Розгортається у виклик: ls "my docs" (Word Splitting пригнічено)
```

Завжди огортайте змінні у подвійні лапки, якщо ви передаєте шляхи до файлів чи дані користувача!

### Спеціальні види цитування (ANSI-C та Locale)

Сучасні POSIX-оболонки надають розширені форми цитування для роботи з бінарними даними та локалізацією:

#### ANSI-C Quoting: `$'...'`

Рядок у форматі `$'...'` обробляє ESC-послідовності аналогічно мові програмування C. Символи всередині розгортаються до підстави в масив аргументів:

- `\n` — новий рядок (LF, ASCII 10).
- `\t` — табуляція (TAB, ASCII 9).
- `\r` — повернення каретки (CR, ASCII 13).
- `\xHH` — шестнадцятковий байт (наприклад `\x1b` — ESC).
- `\0NNN` — вісімковий байт.

```bash
echo $'Line 1\nLine 2\tTabbed'
```

#### Locale Translation: `$"..."`

Рядок `$"..."` використовується у системі GNU gettext. Оболонка шукає переклад зазначеного рядка у каталозі повідомлень поточної локалі. Якщо переклад знайдено, підставляється перекладений рядок, до якого надалі застосовуються правила подвійних лапок.

## Векторні позиційні параметри: "$@" проти "$*"

Найбільш підступною зоною використання розгортання та лапок є обробка позиційних параметрів скрипту або функції (`$1`, `$2`, `$3` ...). Для звернення до всіх параметрів одночасно використовуються спеціальні змінні `$*` та `$@`. Без подвійних лапок обидві змінні поводяться однаково — вони підставляють значення параметрів, які надалі розбиваються на слова за роздільниками `IFS`.

Проте у подвійних лапках їхня поведінка кардинально відрізняється.

### Подвійні лапки із зірочкою: `"$*"`

Вираз `"$*"` підставляє всі позиційні параметри як **єдине слово** (один аргумент). Значення параметрів об'єднуються у суцільний рядок, де роздільником між ними стає **перший символ змінної `IFS`**.

```bash
IFS=":"
set -- "arg 1" "arg 2" "arg 3"
echo "$*"  # Виведе єдиний аргумент: "arg 1:arg 2:arg 3"
```

Якщо `IFS` є порожнім рядком (`IFS=""`), значення параметрів зливаються без жодних роздільників: `"arg 1arg 2arg 3"`. Якщо `IFS` скинуто, використовується пробіл.

### Подвійні лапки із собачкою: `"$@"`

Вираз `"$@"` розгортається у **список окремих слів**, де кожен позиційний параметр огортається у власні подвійні лапки.

Якщо позиційні параметри дорівнюють `$1="a b"`, `$2="c"`, `$3="d e"`, то вираз:

```bash
"$@"
```

еквівалентний точній послідовності окремих аргументів:

```bash
"$1" "$2" "$3"  # Або: "a b" "c" "d e"
```

Зведена таблиця поведінки векторних параметрів:

| Конструкція | Кількість згенерованих слів | Вплив `IFS` | Збереження межі аргументів із пробілами |
| :--- | :--- | :--- | :--- |
| `$*` | Багато (після Word Splitting) | Так (розділяє слова) | Ні (втрачаються межі) |
| `$@` | Багато (після Word Splitting) | Так (розділяє слова) | Ні (втрачаються межі) |
| `"$*"` | **Рівно 1 слово** | Так (перший символ `IFS` стає роздільником) | Ні (все зливається в один рядок) |
| `"$@"` | **Рівно N слів** (де N — кількість $#) | Ні | **Так (ідеальне збереження)** |

Правило для розробників: при делегуванні аргументів з одного скрипту або функції в іншу **завжди використовуйте `"$@"`**:

```bash
# Правильна передача всіх параметрів далі у команду
for arg in "$@"; do
    process_item "$arg"
done
```

Будь-яке інше використання призводить до руйнування аргументів, що містять пробіли або спецсимволи.

## Вразливості безпеки через незахищене розгортання

Ігнорування правил лапок є найпоширенішою джерелом критичних помилок безпеки (security vulnerabilities) та виходу з ладу систем у скриптах Unix.

### 1. Руйнування файлових систем (Unquoted Variable Expansion)

Розглянемо фрагмент коду для видалення тимчасового каталогу:

```bash
TARGET_DIR="/tmp/user data/output"
rm -rf $TARGET_DIR
```

Оскільки `$TARGET_DIR` не взято у подвійні лапки, на етапі Word Splitting команда розгортається у:

```bash
rm -rf "/tmp/user" "data/output"
```

Команда `rm` отримає два окремих аргументи і видалить каталог `/tmp/user`, до якого можуть належати критичні дані інших користувачів, та спробує видалити локальний шлях `data/output`.

Ще більш небезпечний випадок відбувається, коли змінна порожня або містить зірочку:

```bash
TARGET_DIR="*"
rm -rf $TARGET_DIR  # Розгортається у видалення ВСІХ файлів у поточному каталозі!
```

### 2. Вразливості у квадратних дужках тестів

У класичних тестах POSIX `test` або `[` незахищені змінні ламають синтаксис команди:

```bash
VAR=""
if [ $VAR = "admin" ]; then
    echo "Access granted"
fi
```

Після розгортання параметрів та поділу на слова слово `$VAR` перетворюється на ніщо. Команда `[` отримує аргументи `[` `=`, `"admin"`, `]`, що призводить до фатальної синтаксичної помилки оболонки `bash: [: =: unary operator expected`.

Виправлення вимагає використання подвійних лапок `[ "$VAR" = "admin" ]` або використання розширеного тестового оператора Bash `[[ $VAR == "admin" ]]`, у якому розгортання слів та глобінг всередині дужок вимкнено на рівні синтаксичного аналізатора.

### 3. Ін'єкція команд через eval

Команда `eval` змушує оболонку прогнати рядок через повний конвеєр розгортання **двічі**. Якщо у вираз `eval` потрапляють незахищені дані від користувача, це призводить до довільного виконання коду (Remote Code Execution):

```bash
# НЕБЕЗПЕЧНО!
USER_INPUT="file.txt; rm -rf /"
eval "ls -l $USER_INPUT"
```

При першому проході `eval` підставляє `$USER_INPUT`, отримуючи рядок `ls -l file.txt; rm -rf /`. При другому проході оболонка інтерпретує крапку з комою як роздільник команд і виконує видалення всієї файлової системи.

## Системний рівень: розгортання в C та C++ через wordexp(3)

Розгортання командного рядка можна виконувати не лише всередині процесів оболонки, але й у власних програмах на мовах C та C++. Стандарт POSIX надає для цього спеціалізований системний інтерфейс `wordexp(3)`.

Детальні специфікації полів структури `wordexp_t`, прапорів `WRDE_NOCMD`, `WRDE_UNDEF` та функцій глобінгу `glob(3)` наведено у системній довідці [📋 Системні інтерфейси POSIX: wordexp(3), glob(3) та fnmatch(3)](book:unix-linux/expansion-and-quoting/api-wordexp-and-glob.md).

Нижче показано, як виконати розгортання рядка у користувацькій програмі без ризику командної ін'єкції завдяки прапору `WRDE_NOCMD`:

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <wordexp.h>

void safe_expand_example(const char *input_pattern) {
    wordexp_t result;
    /* WRDE_NOCMD блокує виклик $(cmd) та `cmd` для безпеки */
    int status = wordexp(input_pattern, &result, WRDE_NOCMD);
    
    if (status == 0) {
        for (size_t i = 0; i < result.we_wordc; i++) {
            printf("argv[%zu] = %s\n", i, result.we_wordv[i]);
        }
        wordfree(&result);
    } else if (status == WRDE_CMDSUB) {
        fprintf(stderr, "Помилка безпеки: спроба виконання команди всередині рядка!\n");
    } else {
        fprintf(stderr, "Помилка розгортання: %d\n", status);
    }
}

int main(void) {
    safe_expand_example("$HOME/documents/*.txt \"проект 2026\"");
    return 0;
}
```
```cpp
#include <iostream>
#include <string_view>
#include <vector>
#include <stdexcept>
#include <wordexp.h>

class SafeWordExpander {
public:
    explicit SafeWordExpander(std::string_view pattern) {
        std::string null_terminated(pattern);
        int status = wordexp(null_terminated.c_str(), &p_, WRDE_NOCMD);
        if (status != 0) {
            if (status == WRDE_CMDSUB) {
                throw std::runtime_error("Спроба ін'єкції команд заборонена");
            }
            throw std::runtime_error("Помилка розгортання рядка");
        }
    }

    ~SafeWordExpander() noexcept {
        wordfree(&p_);
    }

    SafeWordExpander(const SafeWordExpander&) = delete;
    SafeWordExpander& operator=(const SafeWordExpander&) = delete;

    [[nodiscard]] std::size_t size() const noexcept { return p_.we_wordc; }
    [[nodiscard]] const char* operator[](std::size_t i) const noexcept { return p_.we_wordv[i]; }

private:
    wordexp_t p_{};
};

int main() {
    try {
        SafeWordExpander expander("$HOME/documents/*.txt \"проект 2026\"");
        for (std::size_t i = 0; i < expander.size(); ++i) {
            std::cout << "argv[" << i << "] = " << expander[i] << '\n';
        }
    } catch (const std::exception& ex) {
        std::cerr << "Помилка: " << ex.what() << '\n';
    }
    return 0;
}
```

## Простеження та налагодження розгортання

Щоб побачити, як оболонка розгортає складний рядок крок за кроком, використовуються вбудовані інструменти трасування.

### 1. Трасування оболонки через set -x (xtrace)

Команда `set -x` змушує оболонку виводити кожну команду в `stderr` **після** того, як над нею було виконано всі фази розгортання та видалення лапок, але **до** її реального виконання.

Спеціальна змінна `PS4` визначає префікс рядка трасування. Якщо задати `PS4='+ [$BYTES] '`, можна чітко бачити межі згенерованих аргументів:

```bash
$ set -x
$ FILE="my document.txt"
$ ls -l $FILE
+ ls -l my document.txt
ls: cannot access 'my': No such file or directory
ls: cannot access 'document.txt': No such file or directory

$ ls -l "$FILE"
+ ls -l 'my document.txt'
-rw-r--r-- 1 user user 4096 Aug 14 10:00 'my document.txt'
```

Зверніть увагу: у трасуванні `+ ls -l 'my document.txt'` оболонка Bash сама додає одинарні лапки навколо аргументів у виводі `xtrace`, щоб показати вам, що `my document.txt` передається як один цілісний елемент вектора `argv[]`.

### 2. Системне простеження через strace

Щоб переконатися у підсумковому результаті розгортання на рівні ядра Linux, використовується трасувальник системних викликів `strace`:

```bash
$ strace -f -e execve bash -c 'ls -l "my file.txt"'
execve("/bin/ls", ["ls", "-l", "my file.txt"], 0x7ffc...) = 0
```

Виклики `execve` у виводі `strace` показують точний вміст масиву `argv[]`, який був сформований оболонкою після проходження всіх шести фаз розгортання та витирання всіх захисних лапок.
