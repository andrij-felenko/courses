# 📜 Історія появи трьох стандартних потоків та концепції каналів

Еволюція механізмів введення-виведення в операційних системах пройшла шлях від жорстко заданих файлових аргументів у ранніх обчислювальних системах 1960-х років до створення універсальної тріади файлових дескрипторів `0`, `1`, `2` та лінійних конвеєрів у лабораторіях Bell Labs. Ранні операційні системи не мали єдиного стандарту передачі даних між програмами, що змушувало програмістів прив'язувати кожну утиліту до конкретних накопичувачів або фізичних пристроїв.

## Проблема ранніх систем: файл як жорстка прив'язка

У 1960-х роках більшість операційних систем (таких як IBM OS/360 або Multics) вимагали від програм чіткого знання того, звідки вони читають дані та куди записують результат. Програми приймали ім'я файлу як обов'язковий параметр командного рядка або зв'язувалися з конкретними пристроями перфокарт та друку через складні карти опису завдань (Job Control Language, JCL).

Якщо розробнику потрібно було взяти результат роботи однієї програми (наприклад, сортування) і передати його іншій (наприклад, форматуванню для друку), проміжні дані обов'язково мали бути записані на магнітну стрічку або диск під тимчасовим ім'ям. Це створювало численні проблеми:
1. Необхідність вигадувати унікальні імена для тимчасових файлів та стежити за їх вилученням.
2. Величезні накладні витрати на дискове введення-виведення для проміжних даних.
3. Програми не можна було вільно комбінувати між собою без модифікації їхнього вихідного коду.

## Записка Дага Макілроя та ідея конвеєра (1964)

У 1964 році Дуглас Макілрой (Doug McIlroy), керівник дослідницького відділу обчислювальних систем у Bell Labs, сформулював концепцію, яка згодом стане фундаментом філософії Unix:

> «Ми повинні мати можливість з'єднувати програми разом, мов відрізки шлангів, щоб дані текли від однієї до іншої без проміжних дискових файлів».

Протягом кількох років Макілрой намагався переконати розробників Multics та перших версій Unix реалізувати цю ідею. Однак у Першій (1971) та Другій (1972) редакціях Unix (Unix V1/V2 на PDP-11) програми все ще оперували явними файловими аргументами. Утиліти на кшталт `cat` чи `sort` приймали імена файлів, а за їх відсутності записували результати прямо на консоль термінала.

## Кен Томпсон і революція Unix V3 (1972–1973)

Вирішальний прорив стався під час роботи над Третьою редакцією Unix (Unix V3). В один із днів 1972 року Кен Томпсон (Ken Thompson) за декілька годин реалізував системний виклик `pipe()`, який створював кільцевий буфер у пам'яті ядра з двома файловими дескрипторами: один для читання, один для запису.

Щоб конвеєри працювали без зміни коду існуючих утиліт, Томпсон ввів фундаментальну угоду: **кожен процес під час запуску отримує вже відкритими три базові файлові дескриптори**:
- **Дескриптор 0** — вхідний потік (стандартне введення);
- **Дескриптор 1** — вихідний потік (стандартне виведення).

Томпсон переписав усі основні утиліти утилітного стека Unix (`cat`, `sort`, `pr`, `grep`, `wc`), перевівши їх на використання дескрипторів `0` та `1` за замовчуванням. Це дозволило командній оболонці (Shell) перенаправляти дескриптори `0` та `1` за допомогою `dup2()` до того, як процес розпочне виконання свого коду. Програма `sort` більше не мала знати, читає вона з клавіатури термінала чи з виходу програми `cat`: вона просто викликала `read(0, ...)` і `write(1, ...)`.

Макілрой пізніше згадував це як «один із найважливіших днів в історії обчислювальної техніки»: за один день Unix перетворився з набору окремих програм на гнучкий конструктор.

## Поява дескриптора 2 (stderr): розділення даних і діагностики

У перших версіях з підтримкою перенаправлення існували лише дескриптори `0` та `1`. Помилки та діагностичні повідомлення друкувалися у той самий дескриптор `1`. 

Це швидко призвело до критичного недоліку: коли користувач перенаправляв виведення програми у файл або у конвеєр (наприклад, `make > build.log` або `find / | grep foo`), усі повідомлення про помилки (на кшталт `Permission denied` або `Syntax error`) зникали всередині файлу або потрапляли на вхід наступної утиліти, псуючи результат її обробки.

У Четвертій редакції Unix (Unix V4, 1973 рік) було введено **третій дескриптор — `2` (stderr)**. Його єдиною метою стало транспортування повідомлень про помилки та сповіщень для користувача. За замовчуванням дескриптор `2` завжди залишався підключеним до термінала, навіть якщо дескриптор `1` перенаправлявся у файл.

## Стандартизація в Portable C Library та POSIX

У 1975 році Майк Леск (Mike Lesk) розробив бібліотеку Portable C Library, а у 1979 році для Unix V7 Денніс Рітчі (Dennis Ritchie) переробив її у стандартну бібліотеку введення-виведення для мови C (`stdio.h`). Вона загорнула сирі числові дескриптори ядра `0`, `1`, `2` у високорівневі вказівники на структури `FILE *`:
- `stdin` (для FD 0);
- `stdout` (для FD 1);
- `stderr` (для FD 2).

Бібліотека `stdio` додала шар буферизації користувацького простору для зменшення кількості повільних системних викликів. Згодом у 1988 році ця тріада була остаточно зафіксована міжнародним стандартом POSIX (IEEE Std 1003.1), зробивши дескриптори 0, 1, 2 обов'язковими для будь-якої POSIX-сумісної операційної системи.
