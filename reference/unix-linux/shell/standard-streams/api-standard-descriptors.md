# 📋 Інтерфейс системних викликів та libc для стандартних потоків

Цей довідник надає вичерпний розбір програмних інтерфейсів POSIX, системних викликів ядра Linux та функцій стандартної бібліотеки C (`libc`), призначених для керування файловими дескрипторами `0`, `1`, `2`, потоками `stdin`, `stdout`, `stderr`, їхньою буферизацією, інспекцією та захистом від стану гонитви.

## 1. Системні константи та дескриптори POSIX (`<unistd.h>`)

На найнижчому рівні взаємодії з ядром операційної системи простір користувача оперує числовими файловими дескрипторами. Стандарт POSIX закріплює перші три цілочисельні номери за стандартними потоками та визначає відповідні макроси у заголовному файлі `<unistd.h>`:

| Макрос у коді | Числовий FD | Назва потоку | Призначення за замовчуванням | Режим доступу ядра |
| :--- | :--- | :--- | :--- | :--- |
| `STDIN_FILENO` | `0` | Standard Input | Джерело вхідних даних (клавіатура термінала або канал) | `O_RDONLY` |
| `STDOUT_FILENO` | `1` | Standard Output | Основний вихідний потік (екран термінала або файл/канал) | `O_WRONLY` або `O_RDWR` |
| `STDERR_FILENO` | `2` | Standard Error | Діагностика, журнали та помилки (екран термінала) | `O_WRONLY` або `O_RDWR` |

За угодою POSIX, системний виклик `open()` завжди повертає **найменший доступний цілочисельний дескриптор** у таблиці процесу. Якщо дескриптор `0` закритий, наступний відкритий файл неминуче отримає номер `0`, що є джерелом багатьох підводних каменів.

## 2. Обгортки Standard I/O у C та C++ (`<stdio.h>` / `<cstdio>`)

Стандартна бібліотека C реалізує вищий рівень абстракції над числовими файловими дескрипторами ядра через вказівники на структури `FILE *`. Ці вказівники оголошені у заголовному файлі `<stdio.h>` (або `<cstdio>` у C++) як глобальні змінні:

- **`extern FILE *stdin;`** — потік стандартного введення (обгортка над `STDIN_FILENO`).
- **`extern FILE *stdout;`** — потік стандартного виведення (обгортка над `STDOUT_FILENO`).
- **`extern FILE *stderr;`** — потік виведення помилок (обгортка над `STDERR_FILENO`).

Під час старт-апу процесу бібліотека `glibc` у функції `__libc_start_main()` автоматично ініціалізує структури `FILE` для `stdin`, `stdout` та `stderr`. Кожна структура `FILE` утримує внутрішній буфер пам'яті, вказівник на поточну позицію в буфері, прапорці стану (EOF, помилка) та цілочисельний дескриптор ядра, доступний через макрос або функцію `fileno(stream)`.

### Режими буферизації потоків libc

Поведінка буферизації керується прапорцями у структурі `FILE` і може знаходитися в одному з трьох станів:

1. **`_IOFBF` (Full / Block Buffered — Повна або блокова буферизація):**
   - Дані передаються ядрові через системний виклик `write()` лише тоді, коли внутрішній користувацький буфер заповнюється повністю.
   - Розмір буферизації за замовчуванням визначається викликом `stat()` для файлової системи (зазвичай 4096 або 8192 байти).
   - Застосовується за замовчуванням для `stdout` і `stdin`, якщо вони підключені до звичайних файлів або міжпроцесних каналів (pipes).

2. **`_IOLBF` (Line Buffered — Рядкова буферизація):**
   - Дані накопичуються у користувацькому буфері й передаються ядрові негайно при появі символу нового рядка `\n` або при повному заповненні буфера.
   - Застосовується за замовчуванням для `stdout` і `stdin`, коли дескриптор вказує на пристрій інтерактивного термінала (`isatty(fd) == 1`).

3. **`_IONBF` (Unbuffered — Без буферизації):**
   - Будь-яка операція запису (наприклад, `fprintf()` або `fputc()`) викликає системний виклик `write()` миттєво.
   - Застосовується за замовчуванням для `stderr` незалежно від того, куди спрямовано дескриптор `2`.

## 3. Системні виклики маніпуляції дескрипторами

### `dup`, `dup2` та `dup3`

:::tabs
```c
#include <unistd.h>

int dup(int oldfd);
int dup2(int oldfd, int newfd);
int dup3(int oldfd, int newfd, int flags);
```
```cpp
#include <unistd.h>

int dup(int oldfd) noexcept;
int dup2(int oldfd, int newfd) noexcept;
int dup3(int oldfd, int newfd, int flags) noexcept;
```
:::

#### Механізм роботи `dup(oldfd)`
Системний виклик `dup()` знаходить найменший невільний елемент у таблиці дескрипторів процесу (`fdtable`), копіює туди вказівник на `struct file` з елемента `oldfd` та збільшує лічильник посилань `f_count` у ядрі.

#### Механізм роботи `dup2(oldfd, newfd)`
Системний виклик `dup2()` здійснює атомарне перенаправлення. Якщо `newfd` був відкритий, ядро спочатку закриває його, а потім призначає `newfd` той самий запис `struct file`, що й `oldfd`.
- Якщо `oldfd == newfd` і `oldfd` є коректним дескриптором, `dup2()` нічого не робить і повертає `newfd`.
- Якщо `oldfd` є некоректним дескриптором, виклик завершується помилкою `EBADF`, а `newfd` залишається недоторканим.

#### Механізм роботи `dup3(oldfd, newfd, flags)`
Розширення Linux, яке відрізняється від `dup2()` двома моментами:
- Дозволяє передати прапорець `O_CLOEXEC` у параметрі `flags`, атомарно встановлюючи атрибут close-on-exec для нового дескриптора. Це усуває стан гонитви (race condition) у багатопотокових програмах, де один потік викликає `dup2()`, а інший у цей же момент виконує `execve()`.
- Якщо `oldfd == newfd`, виклик `dup3()` повертає помилку `EINVAL`.

### `read` та `write`

:::tabs
```c
#include <unistd.h>

ssize_t read(int fd, void *buf, size_t count);
ssize_t write(int fd, const void *buf, size_t count);
```
```cpp
#include <unistd.h>
#include <cstddef>

ssize_t read(int fd, void* buf, std::size_t count) noexcept;
ssize_t write(int fd, const void* buf, std::size_t count) noexcept;
```
:::

### `fcntl` (Маніпуляція прапорцями дескрипторів)

:::tabs
```c
#include <fcntl.h>

int fcntl(int fd, int cmd, ... /* arg */ );
```
```cpp
#include <fcntl.h>

int fcntl(int fd, int cmd, ...) noexcept;
```
:::

Команди `fcntl()`, які найчастіше застосовуються до стандартних потоків:
- **`F_GETFL`:** Повертає прапорці стану відкритого файла (маска режимів доступу `O_ACCMODE`, а також прапорці `O_APPEND`, `O_NONBLOCK`, `O_ASYNC`).
- **`F_SETFL`:** Встановлює нові прапорці стану файла. Дозволено змінювати лише `O_APPEND`, `O_NONBLOCK`, `O_ASYNC` та `O_DIRECT`. Спроба змінити режим доступу `O_RDONLY`/`O_WRONLY` ігнорується ядром.
- **`F_GETFD`:** Повертає прапорці самого файлового дескриптора (наразі єдиним POSIX-прапорцем є `FD_CLOEXEC`).
- **`F_SETFD`:** Встановлює прапорці дескриптора. Значення `arg = FD_CLOEXEC` наказує ядрові автоматично закрити цей дескриптор під час виконання `execve()`.

## 4. Керування буферизацією в `libc`

:::tabs
```c
#include <stdio.h>

int setvbuf(FILE *stream, char *buf, int mode, size_t size);
void setbuf(FILE *stream, char *buf);
int fflush(FILE *stream);
```
```cpp
#include <cstdio>

int setvbuf(std::FILE* stream, char* buf, int mode, std::size_t size) noexcept;
void setbuf(std::FILE* stream, char* buf) noexcept;
int fflush(std::FILE* stream) noexcept;
```
:::

### `setvbuf`
Функція `setvbuf()` встановлює тип буферизації, користувацький буфер пам'яті та його розмір для вказаного потоку `stream`. 
- Параметр `mode` має набувати одного з трьох макросів: `_IOFBF`, `_IOLBF` або `_IONBF`.
- Якщо параметр `buf == NULL`, бібліотека `libc` автоматично виділить буфер розміром `size` байтів за допомогою `malloc()`.
- **Важливе правило:** Функція `setvbuf()` повинна викликатися **відразу після відкриття потоку або старт-апу програми**, до виконання будь-яких операцій читання чи запису (`fread`, `fwrite`, `printf`, `scanf`).

### `setbuf`
Застарілий спрощений інтерфейс. Виклик `setbuf(stream, buf)` еквівалентний:
- `setvbuf(stream, buf, _IOFBF, BUFSIZ)` — якщо `buf != NULL`.
- `setvbuf(stream, NULL, _IONBF, 0)` — якщо `buf == NULL`.

### `fflush`
Примусово скидає користувацький буфер запису потоку `stream` у ядро через системний виклик `write()`.
- Якщо `stream == NULL`, функція `fflush()` скидає буфери **всіх відкритих вихідних потоків** поточного процесу.
- Для вхідних потоків (наприклад, `stdin`) поведінка `fflush()` за стандартом POSIX не визначена (у `glibc` це призводить до відкидання прочитаних з ядра, але ще не використаних програмою байтів).

### Зв'язування `FILE *` та числових дескрипторів

:::tabs
```c
#include <stdio.h>

int fileno(FILE *stream);
FILE *fdopen(int fd, const char *mode);
```
```cpp
#include <cstdio>

int fileno(std::FILE* stream) noexcept;
std::FILE* fdopen(int fd, const char* mode) noexcept;
```
:::

- **`fileno(stream)`:** Повертає цілочисельний файловий дескриптор ядра, прихований усередині структури `FILE`. Якщо `stream` є некоректним, повертає `-1` та встановлює `errno = EBADF`.
- **`fdopen(fd, mode)`:** Створює нову обгортку `FILE *` над вже відкритим числове дескриптором `fd`. Параметр `mode` (`"r"`, `"w"`, `"a"`, `"r+"`) повинен відповідати режиму доступу, з яким дескриптор `fd` був початково відкритий у ядрі.

## 5. Перевірка інтерактивного термінала

:::tabs
```c
#include <unistd.h>

int isatty(int fd);
char *ttyname(int fd);
int ttyname_r(int fd, char *buf, size_t buflen);
```
```cpp
#include <unistd.h>
#include <cstddef>

int isatty(int fd) noexcept;
char* ttyname(int fd) noexcept;
int ttyname_r(int fd, char* buf, std::size_t buflen) noexcept;
```
:::

### `isatty(fd)`
Перевіряє, чи посилається файловий дескриптор `fd` на пристрій термінала.
- **Реалізація:** Під капотом `glibc` виконує системний виклик `ioctl(fd, TCGETS, &termios)`. Якщо дескриптор є символьним пристроєм термінала (pty або tty), `ioctl()` повертає `0`, і `isatty()` повертає `1`.
- **Коди помилок:** Якщо дескриптор вказує на звичайний файл, сокет або pipe, `ioctl()` повертає помилку `-1`, а `errno` встановлюється у значення `ENOTTY` (Inappropriate ioctl for device). Якщо `fd` некоректний — `errno = EBADF`.

### `ttyname(fd)` та `ttyname_r(fd, buf, buflen)`
Повертають абсолютний шлях файлової системи до пристрою термінала (наприклад, `/dev/pts/3` або `/dev/tty1`). `ttyname_r()` є реінтерабельною потокобезпечною версією.

## 6. Інспекція через псевдофайлову систему `procfs`

Ядро Linux експонує повний стан дескрипторів будь-якого процесу через файлову систему `/proc`:

| Шлях у `/proc` | Тип об'єкта | Опис та семантика |
| :--- | :--- | :--- |
| `/proc/[pid]/fd/0` | Символьне посилання | Вказує на об'єкт, відкритий як stdin процесу |
| `/proc/[pid]/fd/1` | Символьне посилання | Вказує на об'єкт, відкритий як stdout процесу |
| `/proc/[pid]/fd/2` | Символьне посилання | Вказує на об'єкт, відкритий як stderr процесу |
| `/proc/[pid]/fdinfo/[fd]` | Звичайний текстовий файл | Детальна метаінформація ядра про стан дескриптора |

Структура файлу `/proc/[pid]/fdinfo/[fd]` містить наступні поля:
```text
pos:    1024
flags:  0100002
mnt_id: 28
ino:    140291
```
- **`pos`:** Поточний зсув позиції читання/запису у файлі (у байтах).
- **`flags`:** Вісімкове значення прапорців стану файла (поєднання `O_RDWR`, `O_APPEND`, `O_NONBLOCK` тощо).
- **`mnt_id`:** Ідентифікатор точки монтування файлової системи у `/proc/mounts`.
- **`ino`:** Номер inode об'єкта у файловій системі.

## 7. Коди помилок POSIX при роботі з потоками

Невдалі операції зі стандартними потоками встановлюють глобальну змінну `errno` в один зі стандартних кодів:

| Код `errno` | Назва | Основна причина виникнення |
| :--- | :--- | :--- |
| `EBADF` | Bad file descriptor | Передано закритий або відсутній номер дескриптора |
| `EMFILE` | Too many open files | Процес досяг м'якого ліміту `RLIMIT_NOFILE` на кількість дескрипторів |
| `ENFILE` | System limit reached | Переповнено глобальну таблицю відкритих файлів ядра |
| `EINTR` | Interrupted system call | Системний виклик `read`/`write` було перервано сигналом до передачі даних |
| `EPIPE` | Broken pipe | Спроба запису у `STDOUT_FILENO`, коли читальний кінець каналу закритий |
| `ENOTTY` | Not a typewriter | Виклик `isatty()` або `ioctl(TCGETS)` на файлі або pipe |
