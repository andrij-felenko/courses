# 📋 Довідник структур та релокацій ELF TLS

Цей довідник містить повну технічну специфікацію бінарних структур даних формату ELF, параметрів заголовка `PT_TLS`, внутрішніх структур керування потоками в системній бібліотеці glibc (TCB, DTV), релокаційних записів систем System V ABI для архітектур x86_64 та AArch64, а також низкорівневих системних викликів ядра Linux для маніпуляції регістровими базами пам'яті.

## 1. ELF Program Header та параметри сегмента PT_TLS

У структурах виконуваного файла або спільної динамічної бібліотеки ELF інформація про шаблон локальних даних потоку зберігається у таблиці заголовків програми (Program Header Table). Запис заголовочного блоку TLS визначається константою `PT_TLS` (числове значення `7`).

Динамічний завантажувач `ld.so` зчитує заголовок `PT_TLS` під час стадії завантаження бінарника або виконання системного виклику `dlopen()`. Заголовок описується структурою `Elf64_Phdr`:

```c
typedef struct {
    Elf64_Word  p_type;    /* Тип сегмента: зафіксоване значення PT_TLS = 7 */
    Elf64_Word  p_flags;   /* Права доступу: PF_R (значення 4, читання) */
    Elf64_Off   p_offset;  /* Базове зміщення шаблону .tdata у файлі на диску */
    Elf64_Addr  p_vaddr;   /* Віртуальна адреса шаблону при відображенні у пам'ять */
    Elf64_Addr  p_paddr;   /* Зарезервоване поле стандарту ELF (не використовується) */
    Elf64_Xword p_filesz;  /* Точний розмір ініціалізованих даних (.tdata) у байтах */
    Elf64_Xword p_memsz;   /* Загальний обсяг пам'яті для TLS (.tdata + .tbss) у байтах */
    Elf64_Xword p_align;   /* Максимальне вирівнювання пам'яті (потужність числа 2) */
} Elf64_Phdr;
```

### Детальний функціональний розбір полів `Elf64_Phdr`:

- **Поле `p_type`**: ідентифікує спеціалізований запис заголовка. Завантажувач ядра Linux ігнорує сегмент `PT_TLS` під час первинного створення процесів (оскільки ядро створює лише процес з одним потоком), але передає вказівник на таблицю заголовків через допоміжний вектор `AT_PHDR` у простір користувача. Динамічний завантажувач `ld.so` сканує масив заголовків і знаходить `PT_TLS`.
- **Поле `p_flags`**: для сегмента `PT_TLS` завжди має значення `PF_R` (`4`), оскільки сам шаблон у бінарному файлі є константним джерелом даних для копіювання і не потребує прав на запис (`PF_W`) чи виконання (`PF_X`).
- **Поле `p_offset`**: вказує на точний байтовий зсув у файлі, за яким розташовується вміст секції `.tdata`. Динамічний завантажувач використовує це зміщення при виконанні читання з файла або операції `mmap()`.
- **Поле `p_vaddr`**: віртуальна адреса шаблону `.tdata` у статично зкомпонованому адресній просторі.
- **Поле `p_filesz`**: розмір ініціалізованого блоку даних у байтах. Завантажувач копіює `p_filesz` байтів із файла у новоділений TLS-блок потоку.
- **Поле `p_memsz`**: визначає повну сумарну довжину блоку TLS для даного модуля. Суттєвою деталлю є те, що значення `p_memsz` завжди більше або дорівнює `p_filesz`. Алгебраїчна різниця `p_memsz - p_filesz` дає точний розмір секції неініціалізованих даних `.tbss`. Пам'ять обсягом `p_memsz - p_filesz` заповнюється нулями (`0x00`) одразу після копіювання `.tdata`.
- **Поле `p_align`**: задає вимоги вирівнювання базової адреси TLS-блоку у віртуальній пам'яті. Значення `p_align` розраховується статичним компонувальником як найбідніше вирівнювання серед усіх змішаних у модуль TLS-змінних (наприклад, `8` для 64-бітних цілих чисел або `16`/`32` для SIMD-векторів AVX). Завантажувач під час алокації гарантирує, що `(addr % p_align) == 0`.

## 2. Динамічні теги TLS у секції .dynamic

Окрім Program Header, динамічні бібліотеки містять запис у секції `.dynamic`, який використовується динамічним завантажувачем для оптимізованого обслуговування описувачів TLS (TLSDESC).

```c
typedef struct {
    Elf64_Sxword d_tag;   /* Ідентифікатор тегу */
    union {
        Elf64_Xword d_val; /* Цілочисельне значення */
        Elf64_Addr  d_ptr; /* Адресне значення */
    } d_un;
} Elf64_Dyn;
```

### Ключові теги динамічної секції для TLS:

- **`DT_TLSDESC_PLT` (`0x6ffffef6`)**: віртуальна адреса спеціальної стаб-процедури у PLT, яка обробляє розпізнавання описувачів TLS з лінивою релокацією.
- **`DT_TLSDESC_GOT` (`0x6ffffef7`)**: віртуальна адреса таблиці GOT, виділеної під описувачі TLS.

## 3. Внутрішні структури glibc: TCB та DTV

У системі Linux із бібліотекою glibc на архітектурі x86_64 вказівник потоку (Thread Pointer, TP) збігається з базовою адресою сегментного регістра `FS`. Цей регістр вказує на внутрішню структуру управляючого блоку потоку (Thread Control Block, TCB), яка утворює заголовок структури `struct pthread`.

### 3.1. Заголовочна структура tcbhead_t (x86_64)

Структура `tcbhead_t` розташовується на самому початку TCB. Доступ до її полів здійснюється безпосередньо через префікс сегментації `FS:` з фіксованими байтовими зміщеннями:

```c
typedef struct {
    void *tcb;              /* fs:0x00 — Вказівник на самого себе (self-pointer) */
    dtv_t *dtv;             /* fs:0x08 — Вказівник на Динамічний Вектор Потоку (DTV) */
    void *self;             /* fs:0x10 — Вказівник на управляючу структуру struct pthread */
    int multiple_threads;   /* fs:0x18 — Прапорець наявності багатьох активних потоків */
    int gscope_flag;        /* fs:0x1c — Прапорець синхронізації глобальної області */
    uintptr_t sysinfo;      /* fs:0x20 — Точка входу в системні виклики (для 32-бітних режимів) */
    uintptr_t stack_guard;  /* fs:0x28 — Канарейка захисту стеку від переповнення */
    uintptr_t pointer_guard;/* fs:0x30 — Маска шифрування вказівників функцій (Mangling) */
    unsigned long int vgetcpu_cache[2]; /* fs:0x38 — Кеш системного виклику vgetcpu */
    unsigned int feature_1; /* fs:0x48 — Прапорці апаратних можливостей процесора (CET/IBT) */
} tcbhead_t;
```

#### Детальний розбір значущих полів `tcbhead_t`:

- **`tcb` (`fs:0x00`)**: self-pointer. Поле містить власну 64-бітну віртуальну адресу заголовка `tcbhead_t`. Це дозволяє користувацькому коду швидко дізнатися свою базову адресу `FS` без виконання повільних системних викликів `arch_prctl`, прочитавши значення однією інструкцією `mov rax, QWORD PTR fs:0`.
- **`dtv` (`fs:0x08`)**: вказівник на динамічний вектор потоку. Використовується функцією runtime-підтримки `__tls_get_addr` для знаходження базових адрес TLS-блоків у завантажених динамічних бібліотеках.
- **`stack_guard` (`fs:0x28`)**: канарейка стеку (Stack Canary). Під час створення потоку C-бібліотека записує сюди псевдовипадкове 64-бітне значення. Компілятор генерує перевірку цього значення перед виходом з кожної функції з прапорцем `-fstack-protector`.
- **`pointer_guard` (`fs:0x30`)**: випадкова маска для шифрування вказівників на процедури обробки сигналів та деструктори.

### 3.2. Dynamic Thread Vector (DTV)

Динамічний вектор потоку є масивом об'єднань `dtv_t`, який реалізує індиректний доступ до локальних даних динамічних модулів.

```c
typedef union dtv_elem {
    size_t counter;         /* dtv[0]: Поточна версія генерації модулів (dl_tls_generation) */
    struct {
        void *val;          /* Вказівник на виділений блок TLS конкретного модуля */
        void *to_free;      /* Вказівник на пам'ять для звільнення при виклику dlclose() */
    } pointer;
} dtv_t;
```

#### Індексація та прапорці елементів DTV:

- **Нульовий елемент (`DTV[0]`)**: зберігає значення `counter`, яке дорівнює глобальному лічильнику генерації динамічного завантажувача `dl_tls_generation`. Кожного разу, коли додається нова бібліотека через `dlopen()`, значення генерації зростає. При виклику `__tls_get_addr` порівнюється `DTV[0].counter` з глобальним лічильником: якщо глобальний більший, масив DTV розширюється.
- **Перший елемент (`DTV[1]`)**: завжди призначений для головного виконуваного бінарного файла програми. Поле `val` вказує на блок статичного TLS первинного модуля.
- **Елементи `DTV[N]`**: відповідають динамічному модулю з ідентифікатором `Module ID = N`. 
- **Спеціальні значення**: якщо поле `val` містить значення `TLS_SLOT_UNALLOCATED` (у glibc це `(void *) -1` або `NULL`), це означає, що пам’ять для TLS даного модуля у поточному потоці ще не була виділена (лінива алокація).

### 3.3. Структура tls_index

Структура `tls_index` описує параметр, який передається у функцію `__tls_get_addr` для обчислення кінцевої віртуальної адреси змінної:

```c
typedef struct {
    unsigned long int ti_module; /* Модульний ідентифікатор (Module ID, індекс у DTV) */
    unsigned long int ti_offset; /* Зміщення змінної відносно початку TLS-блоку модуля */
} tls_index;
```

Експортна сигнатура функції обчислення адреси:

```c
extern void *__tls_get_addr(tls_index *ti);
```

## 4. Релокаційні записи ELF TLS (x86_64 System V ABI)

Компонувальник використовує релокаційні записи у секціях `.rela.dyn` та `.rela.plt` для налаштування звернень до TLS у динамічних бібліотеках. Кожен запис описується структурою `Elf64_Rela`:

```c
typedef struct {
    Elf64_Addr  r_offset; /* Віртуальна адреса комірки пам'яті для модифікації (у GOT) */
    Elf64_Xword r_info;   /* Індекс символу у symtab та тип релокації */
    Elf64_Sxword r_addend;/* Постійне доданок зміщення (Addend) */
} Elf64_Rela;
```

### Повна таблиця типів релокацій TLS для x86_64:

| Назва релокації | Код (Hex / Dec) | Опис та формула обчислення | Модель доступу |
| :--- | :--- | :--- | :--- |
| `R_X86_64_TLSGD` | `0x13` / `19` | Створює пару елементів у GOT для збереження `tls_index`. Використовується для виклику `__tls_get_addr`. | General Dynamic |
| `R_X86_64_TLSLD` | `0x14` / `20` | Створює пару елементів у GOT для базової адреси модуля. | Local Dynamic |
| `R_X86_64_DTPOFF32` | `0x15` / `21` | 32-бітне зміщення змінної відносно початку TLS-блоку модуля (`DTPOFF`). | Local Dynamic |
| `R_X86_64_GOTTPOFF` | `0x16` / `22` | Створює запис у GOT, що містить статичне зміщення відносно Thread Pointer (`TPOFF`). | Initial Exec |
| `R_X86_64_TPOFF32` | `0x17` / `23` | 32-бітне константне зміщення відносно Thread Pointer (`TPOFF`), обчислене компонувальником. | Local Exec |
| `R_X86_64_TPOFF64` | `0x12` / `18` | 64-бітне константне зміщення відносно Thread Pointer (`TPOFF`). | Local Exec |
| `R_X86_64_DTPOFF64` | `0x18` / `24` | 64-бітне зміщення відносно початку TLS-блоку модуля (`DTPOFF`). | Local Dynamic |

## 5. Релокаційні записи ELF TLS (AArch64 System V ABI)

На 64-бітній архітектурі ARM (AArch64) застосовується топологія Variant I. Вказівник потоку зберігається у системному регістрі `TPIDR_EL0` і вказує на початок TCB.

### Повна таблиця типів релокацій TLS для AArch64:

| Назва релокації | Код (Hex / Dec) | Опис та адресаційна семантика | Модель доступу |
| :--- | :--- | :--- | :--- |
| `R_AARCH64_TLSGD_ADR_PAGE21` | `0x201` / `513` | ADRP інструкція для обчислення 4Кб сторінки GOT у General Dynamic. | General Dynamic |
| `R_AARCH64_TLSGD_ADD_LO12_NC` | `0x202` / `514` | ADD інструкція для молодших 12 біт адреси GOT у General Dynamic. | General Dynamic |
| `R_AARCH64_TLSLD_ADR_PAGE21` | `0x205` / `517` | ADRP інструкція для обчислення сторінки GOT у Local Dynamic. | Local Dynamic |
| `R_AARCH64_TLSLD_ADD_LO12_NC` | `0x206` / `518` | ADD інструкція для молодших 12 біт GOT у Local Dynamic. | Local Dynamic |
| `R_AARCH64_TLSIE_ADR_GOTTPREL_PAGE21` | `0x21b` / `539` | ADRP інструкція сторінки GOT для зміщення TPREL. | Initial Exec |
| `R_AARCH64_TLSIE_LD64_GOTTPREL_LO12_NC` | `0x21c` / `540` | LDR інструкція зчитування 64-бітного зміщення з GOT. | Initial Exec |
| `R_AARCH64_TLSLE_ADD_TPREL_HI12` | `0x221` / `545` | ADD інструкція для верхніх 12 біт зміщення від `TPIDR_EL0`. | Local Exec |
| `R_AARCH64_TLSLE_ADD_TPREL_LO12_NC` | `0x222` / `546` | ADD інструкція для нижніх 12 біт зміщення від `TPIDR_EL0`. | Local Exec |

## 6. Системний виклик arch_prctl (Linux x86_64)

Ядро Linux забезпечує інтерфейс керування 64-бітними базовими адресами сегментних регістрів `FS` та `GS` за допомогою системного виклику `arch_prctl`.

```c
#include <asm/prctl.h>
#include <sys/prctl.h>

int arch_prctl(int code, unsigned long addr);
int arch_prctl(int code, unsigned long *addr);
```

### Перелік подій та коди команд `code`:

- **`ARCH_SET_FS` (`0x1002`)**: записує 64-бітне значення `addr` у MSR-регістр `IA32_FS_BASE`. Викликається C-бібліотекою під час створення кожного нового потоку виконання (`pthread_create`).
- **`ARCH_GET_FS` (`0x1003`)**: зчитує поточну 64-бітну базову адресу з `IA32_FS_BASE` і записує її за вказаним у `addr` вказівником.
- **`ARCH_SET_GS` (`0x1001`)**: записує 64-бітне значення `addr` у MSR-регістр `IA32_GS_BASE`. У просторі користувача застосовується рідко, оскільки ядро Linux використовує `GS` для per-CPU даних.
- **`ARCH_GET_GS` (`0x1004`)**: зчитує поточну 64-бітну базову адресу `GS`.

### Можливі коди помилок (errno):

- `EINVAL`: вказано невідомий код `code` або базова адреса `addr` виходить за межі канонічного віртуального адресного простору x86_64 (`0x00007FFFFFFFFFFF` ... `0xFFFF800000000000`).
- `EPERM`: спроба встановити недозволену адресу під час суворого виконання політик безпеки.
- `EFAULT`: аргумент `addr` вказує на некоректну або незахищену область пам'яті під час читання базових адрес.
