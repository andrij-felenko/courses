# 📋 Інтерфейси керування HugeTLB та THP у sysfs, procfs та системних викликах

Поверхня налаштування та моніторингу великих сторінок оперативної пам'яті в ядрі Linux складається з параметрів файлових систем sysfs та procfs, контролерів ресурсів cgroups v2, прапорців системних викликів `mmap()`, `shmget()`, `madvise()`, `process_madvise()`, а також полів розширеної статистики процесів.

## Інтерфейси керування явними сторінками HugeTLB

Статична та динамічна конфігурація пулу сторінок HugeTLB здійснюється через глобальне піддерево `/sys/kernel/mm/hugepages/`, вузли NUMA у `/sys/devices/system/node/` та змінні `sysctl`.

### Глобальна структура каталогу /sys/kernel/mm/hugepages/

Для кожного розміру сторінки, підтримуваного апаратним забезпеченням (наприклад, `hugepages-2048kB` або `hugepages-1048576kB`), ядро створює окремий підкаталог зі зчитуваними та записуваними атрибутами:

| Файл атрибута в sysfs | Тип доступу | Опис та функціональне призначення у ядрі |
| :--- | :--- | :--- |
| `nr_hugepages` | Read-Write | Загальна кількість зарезервованих великих сторінок у пулі ядра. Запис нового значення негайно ініціює виділення або звільнення сторінок у Buddy Allocator. |
| `nr_overcommit_hugepages` | Read-Write | Максимальна кількість додаткових («понадлімітних») сторінок, які ядро має право виділити з Buddy Allocator у разі повного вичерпання основного пулу `nr_hugepages`. |
| `free_hugepages` | Read-Only | Кількість сторінок у пулі, які наразі вільні та доступні для створення нових відображень `mmap`. |
| `resv_hugepages` | Read-Only | Кількість сторінок, для яких процес виконав замовлення (через `mmap`), але фізично ще не здійснив перший запис (відкладене виділення пам'яті). |
| `surplus_hugepages` | Read-Only | Поточна кількість понадлімітних сторінок, виділених понад значення `nr_hugepages`. При звільненні такі сторінки негайно повертаються у загальний склад Buddy Allocator. |
| `demote_size` / `demote` | Read-Write | Розмір, до якого можна подрібнити сторінку цього пулу (наприклад, 1 ГіБ → 2 МіБ), і кількість сторінок, які ядро подрібнює за командою. |

### Конфігурація для багатопроцесорних систем NUMA

На багатопроцесорних архітектурах NUMA (*Non-Uniform Memory Access*) ядро експортує індивідуальне керування пулом великих сторінок для кожного фізичного вузла пам'яті:

`/sys/devices/system/node/node0/hugepages/hugepages-2048kB/nr_hugepages`  
`/sys/devices/system/node/node1/hugepages/hugepages-2048kB/nr_hugepages`

Запис значення у ці файли дозволяє уникнути міжвузлових затримок шини QPI/UPI/Infinity Fabric, примусово створюючи великі сторінки саме в тій плашці RAM, яка підключена до локального сокета CPU. Адміністратор може перевіряти статус розподілу за допомогою утиліти `numastat` або аналізувати вміст каталогу `/sys/devices/system/node/node*/meminfo`.

### Обмеження ресурсів у контролерах cgroups v2

У сучасних дистрибутивах Linux обмеження споживання HugeTLB контейнерами виконується через спеціалізований контролер cgroups v2 (`hugetlb`):

- `hugetlb.<size>.max` — абсолютний ліміт споживання сторінок даного розміру контрольованою групою процесів (наприклад, `2GB`).
- `hugetlb.<size>.current` — поточний обсяг пам'яті HugeTLB, зафіксований за контрольною групою.
- `hugetlb.<size>.rsvd.max` — максимальний ліміт зарезервованих відображень пам'яті HugeTLB.
- `hugetlb.<size>.rsvd.current` — поточний обсяг зарезервованих відображень пам'яті HugeTLB.
- `hugetlb.<size>.events` — статистичний звіт про кількість відхилених запитів виділення через перевищення ліміту.

Окремої директиви для HugeTLB у юнітах systemd немає: у файлі `.service` задають лише `LimitMEMLOCK=infinity` (щоб зняти обмеження `RLIMIT_MEMLOCK`), а сам ліміт великих сторінок пишуть у cgroup-файл зрізу служби — наприклад, `hugetlb.2MB.max` у каталозі `/sys/fs/cgroup/system.slice/<юніт>.service/`. Резервацію пулу при завантаженні зазвичай оформлюють окремим юнітом `Type=oneshot`, який записує потрібне число у `nr_hugepages`.

### Параметри sysctl (/proc/sys/vm/)

Параметри керування пам'яттю експортуються у піддереві `sysctl`:

- `vm.nr_hugepages` — глобальний еквівалент запису у `nr_hugepages` для стандартного розміру великої сторінки (2 МіБ на x86_64).
- `vm.nr_overcommit_hugepages` — глобальний еквівалент понадлімітного виділення.
- `vm.nr_hugepages_mempolicy` — той самий пул, але записане число розкладається по вузлах NUMA згідно з чинною політикою пам'яті процесу, який пише (`MPOL_BIND` або `MPOL_INTERLEAVE`); у sysfs відповідника цей параметр не має.
- `vm.hugetlb_shm_group` — ідентифікатор групи користувачів (GID), яким дозволено виділяти пам'ять HugeTLB через виклики розділюваної пам'яті System V (`shmget`).
- `vm.max_map_count` — максимальна кількість відображень VMA будь-якого роду, яку процес може створити в адресовому просторі (за замовчуванням 65530).
- `vm.compaction_proactiveness` — рівень проактивної дефрагментації пам'яті від 0 до 100 для завчасного підготування великих сторінок.

## Прапорці системних викликів для HugeTLB

Для отримання пам'яті з пулу `hugetlbfs` простір користувача використовує системні виклики `mmap()` та `shmget()` зі спеціальними бітовими масками:

:::tabs
```c
// Системний виклик mmap у C для виділення анонімного блоку пам'яті з HugeTLB
void *addr = mmap(NULL, length, 
                  PROT_READ | PROT_WRITE, 
                  MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB | MAP_HUGE_2MB, 
                  -1, 0);
```
```cpp
// Системний виклик mmap у C++ з явним приведенням типу результату
auto* addr = static_cast<uint8_t*>(::mmap(nullptr, length,
                                          PROT_READ | PROT_WRITE,
                                          MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB | MAP_HUGE_2MB,
                                          -1, 0));
```
:::

Значення бітових прапорців у заголовочному файлі `<sys/mman.h>`:
- `MAP_HUGETLB` — вказує ядру виділяти пам'ять із пулу HugeTLB замість стандартних сторінок 4 КіБ.
- `MAP_HUGE_2MB` (`21 << MAP_HUGE_SHIFT`) — вимога виділити сторінки розміром 2 МіБ.
- `MAP_HUGE_1GB` (`30 << MAP_HUGE_SHIFT`) — вимога виділити сторінки розміром 1 ГіБ.
- `MAP_HUGE_64KB` (`16 << MAP_HUGE_SHIFT`) — вимога виділити сторінки розміром 64 КіБ на архітектурі ARM64.

Число перед зсувом — це двійковий логарифм бажаного розміру сторінки (2²¹ = 2 МіБ, 2³⁰ = 1 ГіБ, 2¹⁶ = 64 КіБ), а `MAP_HUGE_SHIFT` дорівнює 26: шість бітів логарифма лягають у поле прапорців, починаючи з 26-го.

Для системного виклику `shmget()` підсистеми System V IPC застосовується прапорець `SHM_HUGETLB`.

## Інтерфейс конфігурації Transparent Huge Pages (THP)

Налаштування прозорих великих сторінок розташовано у каталозі `/sys/kernel/mm/transparent_hugepage/`.

### Головні керуючі файли THP

1. `/sys/kernel/mm/transparent_hugepage/enabled`
   Визначає глобальну політику використання THP у системі:
   - `always` — намагатися виділяти 2 МіБ THP для всіх анонімних відображень процесів.
   - `madvise` — виділяти 2 МіБ THP лише для діапазонів пам'яті, де виконано системний виклик `madvise(..., MADV_HUGEPAGE)`.
   - `never` — повністю вимкнути підсистему THP у ядрі.

2. `/sys/kernel/mm/transparent_hugepage/defrag`
   Контролює поведінку ядра, коли під час сторінкового збою (*page fault*) суцільна сторінка 2 МіБ відсутня у Buddy Allocator:
   - `always` — негайно заблокувати потік процесу та виконати пряму дефрагментацію пам'яті (*direct compaction*).
   - `defer` — виділити стандартну сторінку 4 КіБ у режимі фонового прокидання демона `kswapd`/`kcompactd`.
   - `defer+madvise` — виконувати негайну дефрагментацію лише для областей з `MADV_HUGEPAGE`, для інших — фонове виділення.
   - `madvise` — виконувати негайну дефрагментацію виключно за наявності підказки `MADV_HUGEPAGE`.
   - `never` — ніколи не запускати дефрагментацію при сторінковому збої.

3. `/sys/kernel/mm/transparent_hugepage/shmem_enabled`
   Контролює використання THP для розділюваної пам'яті та ФС `tmpfs` (значення: `always`, `within_size`, `advise`, `never`, `deny`, `force`).

4. `/sys/kernel/mm/transparent_hugepage/use_zero_page`
   Контролює використання єдиної прозорої нульової сторінки 2 МіБ для читання незаповнених відображень (1 — увімкнено, 0 — вимкнено).

5. `/sys/kernel/mm/transparent_hugepage/hpage_pmd_size`
   Відображає апаратний розмір сторінки PMD в байтах (2097152 на x86_64).

6. `/sys/kernel/mm/transparent_hugepage/khugepaged/`
   Параметри фонового демона згортання сторінок:
   - `scan_sleep_millisecs` — інтервал між проходами сканування пам'яті (за замовчуванням 10000 мс).
   - `pages_to_scan` — кількість сторінок, які демон сканує за один крок (за замовчуванням 4096).
   - `alloc_sleep_millisecs` — пауза при невдалій спробі виділення великої сторінки (за замовчуванням 60000 мс).
   - `max_ptes_none` — максимальна кількість порожніх записів PTE у діапазоні 512 сторінок, за якої демон ще погоджується згортати їх у 2 МіБ THP (за замовчуванням 511).
   - `max_ptes_swap` — максимальна кількість сторінок діапазону, витиснутих у swap, за якої демон ще погоджується підняти їх назад і згорнути (за замовчуванням 64).
   - `max_ptes_shared` — максимальна кількість записів PTE, спільних із іншими процесами, за якої згортання ще дозволене (за замовчуванням 256).

### Підказки madvise() та керування пам'яттю процесів

Програма може явно керувати поведінкою THP для конкретних анонімних діапазонів адресового простору через системний виклик `madvise()`:

| Прапорець madvise | Опис дії та функціональне призначення у ядрі |
| :--- | :--- |
| `MADV_HUGEPAGE` | Дозволити або рекомендувати ядру вмикати THP для вказаного діапазону адресового простору. |
| `MADV_NOHUGEPAGE` | Заборонити згортання та виділення THP (гарантує використання виключно 4 КіБ сторінок). |
| `MADV_COLLAPSE` | Синхронно примусити ядро згорнути 512 сторінок 4 КіБ у 2 МіБ сторінку негайно, не чекаючи проходу `khugepaged`. |
| `MADV_DONTNEED` | Звільнити фізичні сторінки пам'яті та скинути відповідні записи у таблиці сторінок. |
| `MADV_DONTDUMP` | Виключити вказаний діапазон пам'яті з автоматичного створення дампу ядра (*core dump*). |

Для керування пам'яттю сторонніх процесів у сучасних ядрах Linux 5.10+ застосовується системний виклик `process_madvise(pidfd, iovec, vlen, advice, flags)`.

## Метрики моніторингу у procfs

### Глобальний стан пам'яті у /proc/meminfo

Файл `/proc/meminfo` надає оперативний зріз стану використання великих сторінок у системі:

```text
HugePages_Total:    1024
HugePages_Free:      512
HugePages_Rsvd:      128
HugePages_Surp:        0
Hugepagesize:       2048 kB
Hugetlb:         2097152 kB
AnonHugePages:   4194304 kB
ShmemHugePages:        0 kB
FilePmdMapped:         0 kB
```

Значення ключових полів:
- `HugePages_Total` — загальна кількість сторінок у пулі HugeTLB.
- `HugePages_Free` — кількість невідображених сторінок HugeTLB.
- `HugePages_Rsvd` — зарезервовані сторінки HugeTLB для відкритих мапінгів.
- `HugePages_Surp` — кількість понадлімітних сторінок HugeTLB.
- `Hugepagesize` — базова величина великої сторінки за замовчуванням (2048 КіБ).
- `Hugetlb` — загальний обсяг пам'яті (у кілобайтах, як і решта полів файлу), виділений під явний пул HugeTLB усіх розмірів.
- `AnonHugePages` — обсяг анонімної пам'яті процесів, виділений під прозорі сторінки THP.
- `ShmemHugePages` — обсяг розділюваної пам'яті (shmem/tmpfs), відображений через THP.
- `FilePmdMapped` — обсяг пам'яті відображених файлів (Page Cache), згорнутих у сторінки 2 МіБ на рівні PMD.

### Аналіз конкретного процесу у /proc/[pid]/smaps

Деталізований звіт про використання сторінок конкретною програмою міститься у файлі `/proc/[pid]/smaps`:

```text
7f8a40000000-7f8a80000000 rw-p 00000000 00:00 0 
Size:            1048576 kB
KernelPageSize:     2048 kB
MMUPageSize:        2048 kB
Rss:             1048576 kB
Pss:             1048576 kB
Shared_Clean:          0 kB
Shared_Dirty:          0 kB
Private_Clean:         0 kB
Private_Dirty:   1048576 kB
Referenced:      1048576 kB
Anonymous:       1048576 kB
AnonHugePages:   1048576 kB
ShmemPmdMapped:        0 kB
FilePmdMapped:         0 kB
Shared_Hugetlb:        0 kB
Private_Hugetlb:       0 kB
Locked:          1048576 kB
```

Поле `AnonHugePages` показує точний обсяг віртуальної пам'яті конкретного відображення VMA, який ядро змогло успішно згорнути у прозорі великі сторінки THP. Поля `Shared_Hugetlb` та `Private_Hugetlb` відображають використання явних сторінок із пулу `hugetlbfs`.

### Системні лічильники у /proc/vmstat

Глобальна статистика роботи системних демонів та лічильників сторінок розкривається у файлі `/proc/vmstat`:

- `thp_fault_alloc` — кількість успішно виділених сторінок THP при обробці сторінкових збоїв.
- `thp_fault_fallback` — кількість випадків, коли через фрагментацію ядро не змогло виділити THP і відкотилося до 4 КіБ.
- `thp_collapse_alloc` — кількість виділених великих сторінок демоном `khugepaged`.
- `thp_collapse_alloc_failed` — кількість невдалих спроб згортання пам'яті демоном `khugepaged`.
- `thp_split_page` — кількість виконаних операцій розщеплення THP на 512 сторінок по 4 КіБ.
- `thp_split_page_failed` — кількість невдалих спроб розщеплення сторінок.
- `thp_deferred_split_page` — кількість сторінок у черзі відкладеного розщеплення при дефіциті RAM.
- `thp_scan_exceed_none_pte` — кількість сканувань `khugepaged`, скасованих через занадто велику кількість порожніх записів PTE.
- `thp_scan_exceed_swap_pte` — кількість сканувань, скасованих через наявність сторінок у swap.
- `thp_scan_exceed_share_pte` — кількість сканувань, скасованих через наявність спільних відображень.
