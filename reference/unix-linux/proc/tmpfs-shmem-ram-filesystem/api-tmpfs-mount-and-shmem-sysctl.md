# 📋 Довідник опцій монтування tmpfs, лічильників /proc/meminfo та sysctl

Цей довідник містить повну специфікацію параметрів монтування файлової системи `tmpfs`, лічильників обліку пам'яті підсистеми `shmem` у `/proc/meminfo`, контролерів ресурсів cgroups v2 та псевдофайлів керування розширеними можливостями ядра (THP/NUMA) через `/sys/kernel/mm/`.

## Повна специфікація параметрів монтування tmpfs

Під час виконання системного виклику `mount -t tmpfs` або при описі точок монтування у файлі конфігурації `/etc/fstab` шар VFS передає опції до внутрішньої функції парсингу ядра `shmem_parse_one()`. Ці параметри парсяться та зберігаються у службовій структурі суперблока `struct shmem_sb_info` (`mm/shmem.c`).

| Параметр монтування | Тип даних / Формат | Опис та значення за замовчуванням |
| :--- | :--- | :--- |
| `size` | Байтові одиниці (`k`, `m`, `g`, `%`) | Максимальний обсяг пам'яті під ФС. За замовчуванням дорівнює **50% фізичної RAM**. Підтримує суфікси `K`, `M`, `G` та відсотки від загальної RAM (наприклад `size=2G` або `size=20%`). |
| `nr_blocks` | Ціле число (кількість блоків) | Точне обмеження кількості сторінок пам'яті (розміром `PAGE_SIZE`, типово 4096 байтів). Альтернатива параметру `size`. Зберігається у `sbinfo->max_blocks`. |
| `nr_inodes` | Ціле число (кількість інодів) | Максимальна кількість доступних індексних вузлів. За замовчуванням дорівнює половині кількості сторінок у момент монтування (`sbinfo->max_inodes`). |
| `mode` | Вісімкова (октальна) маска | Права доступу до кореневого каталогу змонтованого `tmpfs` (наприклад `mode=0755` для службового монтування). За замовчуванням `1777`, тобто `0777` разом зі sticky-бітом (`S_ISVTX`) — саме те, чого потребує спільний `/tmp`. |
| `uid` | Числовий UID | Ідентифікатор власника кореневого каталогу. За замовчуванням — UID процесу, який виконує монтування. |
| `gid` | Числовий GID | Ідентифікатор групи власника кореневого каталогу. За замовчуванням — GID процесу, який виконує монтування. |
| `mpol` | Рядок режиму NUMA | Режим розподілу сторінок у NUMA-архітектурі: `default`, `prefer:node`, `bind:nodelist`, `interleave:nodelist`, `local`. |
| `huge` | Перелічуваний тип (`enum`) | Режим використання великих сторінок (Transparent Huge Pages). Опція монтування приймає рівно чотири значення: `never` (типове), `always`, `within_size`, `advise`. Значення `deny` та `force` існують лише у глобальному sysfs-перемикачі `shmem_enabled`, у рядку `mount` вони помилкові. |
| `nosuid` | Прапор безпеки | Скасовує дію бітів підвищення прав `SUID`/`SGID` на файлах цієї файлової системи. |
| `noexec` | Прапор безпеки | Забороняє виконання будь-яких бінарних файлів зі змонтованого каталогу `tmpfs`. |
| `nodev` | Прапор безпеки | Забороняє інтерпретацію символьних та блокових файлів пристроїв у змонтованому каталозі. |
| `inode64` | Прапор версіонування | Примусово вмикає використання 64-бітних номерів інодів (`ino_t`), що запобігає колізіям у великих файлових системах. |

### Механіка керування політикою NUMA (параметр mpol)

У багатопроцесорних системах з архітектурою нерівномірного доступу до пам'яті (NUMA) виділення фізичних сторінок для `tmpfs` може прив'язуватися до конкретних вузлів процесора. За це відповідає параметр `mpol`, який обробляється підсистемою `mempolicy`:

* `mpol=default` — власної політики `tmpfs` не нав'язує: сторінки виділяються за чинною політикою пам'яті того процесу, який виконує запис;
* `mpol=prefer:node` — ядро віддає перевагу вказаному вузлу `node`, але при його вичерпанні виділяє пам'ять із сусідніх вузлів без повернення помилки;
* `mpol=bind:nodelist` — суворе виділення сторінок виключно з перелічених у списку `nodelist` NUMA-вузлів. Якщо пам'ять на вказаних вузлах закінчується, система повертає помилку `-ENOMEM`;
* `mpol=interleave:nodelist` — рівномірний почерговий циклічний розподіл нових сторінок між вузлами списку. Цей режим є оптимальним для високонавантажених баз даних у пам'яті, оскільки усуває дисбаланс шини пам'яті;
* `mpol=local` — переважне виділення пам'яті на тому NUMA-вузлі, де виконується потік, який звертається до файла (доступний із ядра 4.7).

### Приклади команд монтування та налаштування fstab

Створення тимчасового каталогу з обмеженням розміру у 2 гігабайти, обмеженням у 100 тисяч інодів та захисними прапорцями безпеки:

```bash
mount -t tmpfs -o size=2G,nr_inodes=100000,mode=1777,nosuid,nodev,noexec tmpfs /tmp
```

Відповідний запис у файлі конфігурації статичних монтувань `/etc/fstab`:

```
tmpfs   /tmp   tmpfs   size=2G,nr_inodes=100000,mode=1777,nosuid,nodev,noexec   0 0
```

Створення об'єднаного кешу пам'яті для високонавантаженого вебсервера з балансуванням по NUMA-вузлах 0 та 1 та великими сторінками:

```bash
mount -t tmpfs -o size=8G,mpol=interleave:0,1,huge=within_size tmpfs /var/cache/nginx_ram
```

## Лічильники пам'яті у /proc/meminfo

Підсистема ядра `shmem` та ВФС `tmpfs` повністю інтегровані в глобальний механізм обліку віртуальної пам'яті Linux. Оновлення лічильників відбувається під час кожного виклику виділення або витискання сторінки. Метрики відображаються у псевдофайлі `/proc/meminfo`:

| Лічильник / Поле | Одиниця виміру | Опис та механіка обліку ядра |
| :--- | :--- | :--- |
| `Shmem` | Кілобайти (КБ) | Загальний обсяг пам'яті, виділений під файли `tmpfs`, POSIX shm, System V IPC та анонімний shared `mmap`. **Не скидається** при `drop_caches`. |
| `nr_shmem` (у `/proc/vmstat`, не в `meminfo`) | Кількість сторінок | Той самий облік, але в сторінках: внутрішній лічильник ядра `NR_SHMEM`, із якого й рахується поле `Shmem`. |
| `ShmemHugePages` | Кілобайти (КБ) | Обсяг пам'яті у `tmpfs`/`shmem`, виділений блоками великих сторінок Transparent Huge Pages (2 МБ на x86_64). |
| `ShmemPmdMapped` | Кілобайти (КБ) | Обсяг великих сторінок `tmpfs`, які безпосередньо відображені в таблиці сторінок процесів через PMD-рівень. |
| `Cached` | Кілобайти (КБ) | Загальний обсяг Page Cache ядра. **Увага:** Поле `Cached` включає значення `Shmem`! Формула файлового кешу: `File_Page_Cache = Cached - Shmem`. |
| `SwapTotal` / `SwapFree` | Кілобайти (КБ) | Загальний та вільний обсяг swap; окремого поля `SwapUsed` у `meminfo` немає — зайнятий обсяг рахують як `SwapTotal − SwapFree`. Сторінки `tmpfs`, витиснуті ядерним демоном `kswapd`, займають слоти swap і водночас зменшують `Shmem`. |
| `SwapCached` | Кілобайти (КБ) | Сторінки, які були зчитані зі swap назад у RAM, але слот у swap-просторі для них ще не звільнено. |

### Формули розрахунку реального споживання пам'яті

Під час аналізу стану пам'яті системи важливо не припуститися помилки подвійного врахування. Оскільки `Shmem` є частиною поля `Cached`, розрахунок чистої пам'яті під дисковий кеш та анонімні файли здійснюється за такими формулами:

* **Чистий файловий кеш диска (дискові файли):** `File_Cache = Cached - Shmem`
* **Фактична анонімна пам'ять процесів (Heap + Stack):** поле `AnonPages` ядро друкує в `/proc/meminfo` напряму — його треба читати, а не виводити відніманням; вираз `MemTotal − MemFree − Cached − Buffers − Slab` дає лише грубу перехресну оцінку й розходиться на розмір `KernelStack`, `PageTables` та інших ядерних споживачів
* **Сумарне споживання анонімних ресурсів (Heap + tmpfs):** `Total_Anonymous = AnonPages + Shmem`

## Керування прозорими великими сторінками (THP) у shmem

Налаштування політики керування великими сторінками Transparent Huge Pages (THP) для підсистеми `shmem` на рівні всього ядра виконується через системні інтерфейси `sysctl` та `sysfs`.

### Псевдофайл `/sys/kernel/mm/transparent_hugepage/shmem_enabled`

Глобальна конфігурація виділення великих сторінок контролюється через псевдофайл ядра `/sys/kernel/mm/transparent_hugepage/shmem_enabled`.

Перевірка поточного значення:
```bash
cat /sys/kernel/mm/transparent_hugepage/shmem_enabled
# Поточний активний режим виділено у квадратні дужки: always within_size advise [never] deny force
```

Детальна специфікаційна розшифровка доступних режимів ядра:

1. `always` — підсистема `shmem` намагається виділяти 2-мегабайтні великі сторінки (THP) для всіх без винятку файлів у `tmpfs` та анонімних дескрипторів `memfd`.
2. `never` — повністю забороняє використання великих сторінок для `tmpfs` у всій системі. Виділення здійснюється виключно базовими сторінками по 4 КБ.
3. `deny` — аварійний вимикач: примусово знімає опцію `huge=` з **усіх** змонтованих `tmpfs`, хоч би що було вказано в рядку монтування.
4. `force` — дзеркальний до `deny`: примусово вмикає великі сторінки для всіх монтувань незалежно від їхньої опції `huge=`. Призначений насамперед для тестування ядра.
5. `advise` — виділяє 2 МБ сторінки у `tmpfs` тільки тоді, коли застосунок зробив явний системний виклик `madvise(addr, len, MADV_HUGEPAGE)` для відповідної області відображення.
6. `within_size` — розумний режим, за якого виділення 2 МБ сторінки відбувається лише якщо розмір файла в `tmpfs` гарантовано покриває межу в 2 МБ. Якщо файл менший за 2 МБ, виділяються звичайні сторінки 4 КБ, що запобігає марнотратству RAM.

Динамічне перемикання режиму без перезавантаження операційної системи:

```bash
echo within_size > /sys/kernel/mm/transparent_hugepage/shmem_enabled
```

## Інтеграція tmpfs у підсистему контролерів ресурсів cgroups v2

У сучасній архітектурі cgroups v2 споживання пам'яті файловою системою `tmpfs` обліковується контролером `memory`.

Оскільки сторінки `tmpfs` є анонімним Page Cache, їхнє використання відображається у двох лічильниках контрольної групи:

* `/sys/fs/cgroup/<group>/memory.stat` — поле `shmem`: показує обсяг пам'яті в байтах, використаний об'єктами `tmpfs` та IPC у межах цієї контрольної групи.
* `/sys/fs/cgroup/<group>/memory.stat` — поле `shmem_thp`: обсяг пам'яті `tmpfs`, shm-сегментів та спільних анонімних `mmap`, підпертої великими сторінками THP. Сусіднє поле `file_thp` рахує THP під звичайним дисковим файловим кешем і об'єктів `tmpfs` не включає.

Якщо контрольна група досягає свого ліміту `memory.max`, ядро в першу чергу намагається витиснути сторінки `shmem` цієї групи у swap-простір (за наявності swap). Якщо swap відсутній або заповнений, ядро ініціює OOM-killer для процесів усередині цієї cgroup.

## Простеження та діагностика tmpfs у просторі користувача

Для аналізу стану змонтованих `tmpfs` та виявлення витоків пам'яті застосовуються такі системні утиліти:

1. **Аналіз точок монтування та вільної ємності:**
   ```bash
   df -h -t tmpfs
   # Відображає точку монтування, розмір, зайнятий обсяг та кількість інодів
   ```

2. **Інспекція System V розділюваної пам'яті:**
   ```bash
   ipcs -m
   # Перелік активних сегментів System V IPC із зазначенням shmid, власника та обсягу
   ```

3. **Аналіз виділених сторінок та NUMA-розподілу:**
   ```bash
   numastat -m
   # Деталізована статистика використання пам'яті по NUMA-вузлах, у тому числі поле Shmem
   ```
