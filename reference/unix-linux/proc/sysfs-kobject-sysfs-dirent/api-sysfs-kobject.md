# 📋 Контракт API: макроси та функції kobject і sysfs

У цьому довіднику зафіксовано точний програмний контракт ядра Linux для роботи з ядром об'єктної моделі `kobject`, наборами `kset`, типами `kobj_type` та атрибутами файлової системи `sysfs`. Довідник описує структури даних, сигнатури функцій, макроси оголошення та правила збереження контексту, які є обов'язковими під час розробки підсистем ядра та драйверів пристроїв.

## Головні структури даних та їхні поля

### `struct kobject` (`<linux/kobject.h>`)
Основна атомна структура графа об'єктів ядра. Вона не використовується як самостійний динамічний об'єкт, а вбудовується всередину більших структур драйверів (`struct device`, `struct module`).

```c
struct kobject {
    const char          *name;        /* Ім'я вузла у sysfs */
    struct list_head    entry;       /* Елемент списку в kset */
    struct kobject      *parent;     /* Вказівник на батьківський kobject */
    struct kset         *kset;       /* Вказівник на набір-власник */
    const struct kobj_type *ktype;   /* Таблиця операцій та тип об'єкта */
    struct kernfs_node  *sd;          /* Легковаговий вузол у kernfs/sysfs */
    struct kref         kref;        /* Лічильник посилань */
    unsigned int state_initialized:1;
    unsigned int state_in_sysfs:1;
    unsigned int state_add_uevent_sent:1;
    unsigned int state_remove_uevent_sent:1;
    unsigned int uevent_suppress:1;
};
```
- **Контекст і правила**: Поле `kref` ініціалізується значенням `1` під час первинного створення. Зміна лічильника посилань здійснюється атомарно. Поле `sd` вказує на внутрішній вузол `kernfs_node`, який створюється при реєстрації об'єкта у sysfs. Прапори стану керують повторним надсиланням подій uevent та захищають від подвійного вилучення з деревоподібної ієрархії.

### `struct kobj_type` (`<linux/kobject.h>`)
Визначає специфічну поведінку та способи обробки атрибутів для групи об'єктів одного типу.

```c
struct kobj_type {
    void (*release)(struct kobject *kobj);            /* Зворотний виклик звільнення пам'яті */
    const struct sysfs_ops *sysfs_ops;               /* Операції читання/запису sysfs */
    const struct attribute_group **default_groups;    /* Загальні групи атрибутів */
};
```
- **Контекст і правила**: Вказівник `release` є обов'язковим для всіх стандартних об'єктів. Заборонено залишати `release` порожнім (`NULL`), оскільки це уможливлює витоки пам'яті або фатальні збої ядра при відключенні обладнання. Зворотний виклик `release` здійснюється у контексті процесу, який викликав останній `kobject_put()`.

### `struct sysfs_ops` (`<linux/sysfs.h>`)
Таблиця точок входу для обробки викликів до атрибутів при зверненні з простору користувача.

```c
struct sysfs_ops {
    ssize_t (*show)(struct kobject *kobj, struct attribute *attr, char *buf);
    ssize_t (*store)(struct kobject *kobj, struct attribute *attr, const char *buf, size_t count);
};
```
- **Контекст і правила**: Функції `show` та `store` викликаються у контексті процесу з утриманням внутрішніх блокувань файлової системи `kernfs`. У функції `show` параметру `buf` гарантовано виділяється буфер розміром рівно `PAGE_SIZE` (4096 байтів). Повернене значення має вказувати кількість записаних байтів або від'ємний код помилки (наприклад, `-EINVAL`, `-EIO`).

### `struct attribute` та `struct kobj_attribute` (`<linux/sysfs.h>`)
Базовий та розширений файловий атрибут.

```c
struct attribute {
    const char *name; /* Ім'я файла в sysfs */
    umode_t     mode; /* Права доступу, наприклад 0644 або 0444 */
};

struct kobj_attribute {
    struct attribute attr;
    ssize_t (*show)(struct kobject *kobj, struct kobj_attribute *attr, char *buf);
    ssize_t (*store)(struct kobject *kobj, struct kobj_attribute *attr, const char *buf, size_t count);
};
```
- **Контекст і правила**: Поле `mode` містить стандартні POSIX-прапори доступу (`S_IRUGO`, `S_IWUSR`). Драйвери не повинні надавати атрибутам sysfs права на виконання (`S_IXUGO`) або загальні права на запис для всіх користувачів (`0666`).

## Функції керування життям `kobject`

### `kobject_create_and_add`
Динамічно виділяє пам'ять під `kobject`, ініціалізує його значення за замовчуванням та додає в ієрархію sysfs за вказаним батьківським шляхом.

```c
struct kobject *kobject_create_and_add(const char *name, struct kobject *parent);
```
- **`name`**: текстовий рядок із назвою нового каталогу у файловій системі `/sys`.
- **`parent`**: вказівник на батьківський `kobject`. Якщо передано `NULL`, каталог створюється у корені `/sys`.
- **Повертає**: вказівник на новий виділений `kobject` при успіху або `NULL` при недостатній кількості оперативної пам'яті.
- **Побічні ефекти**: Створює внутрішній вузол `kernfs_node` і виділяє пам'ять зі SLUB-кешу.

### `kobject_init_and_add`
Ініціалізує вже виділений `kobject` (наприклад, розташований всередині власної структури драйвера) із заданим `kobj_type` та додає його в sysfs.

```c
int kobject_init_and_add(struct kobject *kobj, const struct kobj_type *ktype,
                         struct kobject *parent, const char *fmt, ...);
```
- **`kobj`**: вказівник на структуру `kobject`, виділену розробником.
- **`ktype`**: таблиця типів із функцією очищення `release`.
- **`parent`**: батьківський об'єкт в ієрархії sysfs.
- **`fmt`**: форматований рядок імені каталогу з підтримкою специфікаторів `printf`.
- **Повертає**: `0` при успішній реєстрації або від'ємний код помилки (`-ENOMEM`, `-EEXIST`).

### `kobject_get` та `kobject_put`
Збільшення та зменшення лічильника посилань `kref`.

```c
struct kobject *kobject_get(struct kobject *kobj);
void kobject_put(struct kobject *kobj);
```
- **`kobject_get`**: атомарно збільшує значення `kref` на 1 та повертає той самий вказівник `kobj`. Якщо `kobj` дорівнює `NULL`, функція не виконує дій і повертає `NULL`.
- **`kobject_put`**: атомарно зменшує значення `kref` на 1. Якщо лічильник досягає нуля, викликається `ktype->release(kobj)` для остаточного знищення об'єкта.

## Функції та макроси атрибутів sysfs

### Макроси оголошення атрибутів

Для спрощення реєстрації типових атрибутів sysfs та усунення дублювання коду ядро надає макроси автоматичної ініціалізації `struct kobj_attribute`:

- **`__ATTR_RO(name)`**: Створює структуру `struct kobj_attribute` з прапорами доступу `0444` (тільки читання) та прив'язує обробник з ім'ям `name_show`.
- **`__ATTR_WO(name)`**: Створює структуру `struct kobj_attribute` з прапорами доступу `0200` (тільки запис) та прив'язує обробник з ім'ям `name_store`.
- **`__ATTR_RW(name)`**: Створює структуру `struct kobj_attribute` з прапорами доступу `0644` (читання та запис) та прив'язує обидва обробники `name_show` і `name_store`.
- **`__ATTR(name, mode, show, store)`**: Узагальнений макрос із довільним заданням імені, прав доступу та явних функцій-обробників.

### Керування групами атрибутів
Для атомарної реєстрації та вилучення масивів атрибутів у каталозі `kobject` використовуються спеціалізовані функції ядра:

```c
int sysfs_create_group(struct kobject *kobj, const struct attribute_group *grp);
void sysfs_remove_group(struct kobject *kobj, const struct attribute_group *grp);
```
- **`sysfs_create_group`**: Реєструє масив файлів атрибутів у каталозі `kobj`. Створення групи є атомарним: у разі помилки створення будь-якого файла всі раніше створені файли групи автоматично видаляються з sysfs.
- **`sysfs_remove_group`**: Атомарно видаляє всі файли атрибутів зазначеної групи з файлової системи sysfs, звільняючи відповідні вузли `kernfs_node`.

## Генерація подій uevent

### `kobject_uevent`
Надсилає текстові сповіщення про зміну стану об'єкта у простір користувача через сокет Netlink.

```c
int kobject_uevent(struct kobject *kobj, enum kobject_action action);
```
- **`action`**: Константа події гарячого підключення або зміни стану:
  - **`KOBJ_ADD`**: сповіщення про створення та реєстрацію нового пристрою.
  - **`KOBJ_REMOVE`**: сповіщення про відключення або видалення пристрою.
  - **`KOBJ_CHANGE`**: сповіщення про зміну внутрішніх параметрів або стану атрибутів.
  - **`KOBJ_MOVE`**: сповіщення про переміщення об'єкта до іншого батьківського каталогу.
  - **`KOBJ_ONLINE` / `KOBJ_OFFLINE`**: активація або деактивація вузла в системі.
- **Повертає**: `0` при успішній розсилці через сокет Netlink або від'ємний код помилки.
