# 📋 Інтерфейс системного виклику bpf() та параметри bpffs

Системний виклик `bpf()` — єдина точка входу для взаємодії між простором користувача та підсистемою eBPF у ядрі Linux. Для забезпечення персистентності об'єктів у псевдофайловій системі `bpffs` використовуються спеціалізовані команди, параметри структур, функції бібліотеки `libbpf` та опції монтування VFS.

## Низькорівневий інтерфейс системного виклику sys_bpf()

Системний виклик описується сигнатурою `int bpf(int cmd, union bpf_attr *attr, unsigned int size)`. Перший аргумент `cmd` визначає конкретну дію, другий аргумент `attr` є вказівником на уніфіковане об'єднання структур, а `size` вказує розмір переданої структури у байтах для забезпечення зворотної сумісності ABI ядра.

Дві ключові команди присвячені роботі з `bpffs`:

1. **BPF_OBJ_PIN:** Здійснює фіксацію існуючого файлового дескриптора об'єкта eBPF за вказаним шляхом у псевдофайловій системі `bpffs`. Ця операція створює новий VFS-інод і збільшує лічильник посилань `refcnt` структури ядра.
2. **BPF_OBJ_GET:** Знаходить зафіксований об'єкт у `bpffs` за вказаним шляхом, перевіряє права доступу, створює новий файловий дескриптор у просторі користувача та повертає його значення.

### Параметри об'єднання union bpf_attr

Для команд `BPF_OBJ_PIN` та `BPF_OBJ_GET` використовується внутрішня структура об'єднання `bpf_attr`:

```c
struct {
    __aligned_u64 pathname;
    __u32         bpf_fd;
    __u32         file_flags;
    __s32         path_fd;
};
```

Поле `pathname` містить 64-бітну адресу буфера простору користувача, у якому розміщено ASCII-рядок із абсолютним шляхом до файла у `bpffs` (рядок має закінчуватися нульовим байтом `\0`). Ядро зчитує цей рядок за допомогою виклику `strncpy_from_user()`.

Поле `bpf_fd` застосовується виключно при виконанні команди `BPF_OBJ_PIN`. Воно задає дійсний файловий дескриптор об'єкта eBPF (мапи, програми чи `bpf_link`), який вже відкрито у поточному процесі.

Поле `file_flags` визначає спеціальні прапори відкриття об'єкта; два перші з них має сенс подавати лише разом із `BPF_OBJ_GET`:

- `BPF_F_RDONLY` — створює файловий дескриптор з обмеженням "лише для читання". Для мап eBPF це означає заборону модифікації елементів через `bpf_map_update_elem()` або `bpf_map_delete_elem()`.
- `BPF_F_WRONLY` — створює дескриптор з обмеженням "лише для запису". Це корисно для процесів, які лише надсилають дані у мапу, але не повинні читати чужі записи.
- `BPF_F_PATH_FD` — вмикає поле `path_fd` (працює і для `BPF_OBJ_PIN`, і для `BPF_OBJ_GET`). Тоді `pathname` тлумачиться відносно каталогу, на який вказує `path_fd`, — рівно за семантикою `dirfd` у `openat(2)`. Без цього прапора `path_fd` має бути нулем, а шлях резолвиться від `AT_FDCWD`.

## Високорівневий API бібліотеки libbpf

Бібліотека `libbpf` надає два рівні абстракції для роботи з фіксованими об'єктами: низькорівневі C-функції прямого виклику ядра (заголовок `<bpf/bpf.h>`) та об'єктно-орієнтований API керування сутностями `bpf_object` (заголовок `<bpf/libbpf.h>`).

### Низькорівневий C-інтерфейс (<bpf/bpf.h>)

Низькорівневі функції безпосередньо заповнюють об'єднання `bpf_attr` і звертаються до ядра через `syscall(__NR_bpf, ...)`:

```c
int bpf_obj_pin(int fd, const char *pathname);
int bpf_obj_pin_opts(int fd, const char *pathname, const struct bpf_obj_pin_opts *opts);
int bpf_obj_get(const char *pathname);
int bpf_obj_get_opts(const char *pathname, const struct bpf_obj_get_opts *opts);
```

Функція `bpf_obj_pin()` приймає відкритий дескриптор `fd` та абсолютний шлях `pathname`. У разі успішного створення інода повертає `0`. Якщо за вказаним шляхом файл вже існує, функція повертає `-1` і встановлює `errno = EEXIST`.

Функція `bpf_obj_get()` відкриває фіксований файл і повертає новий файловий дескриптор. Розширені версії `bpf_obj_pin_opts()` та `bpf_obj_get_opts()` приймають структури параметрів `struct bpf_obj_pin_opts` і `struct bpf_obj_get_opts` — через них передають `file_flags` та `path_fd` (шлях відносно відкритого каталогу).

### Високорівневий об'єктно-орієнтований інтерфейс (<bpf/libbpf.h>)

При використанні абстракції `bpf_object` бібліотека `libbpf` дозволяє фіксувати ресурси гуртом, не перебираючи їх поодинці:

```c
int bpf_map__pin(struct bpf_map *map, const char *path);
int bpf_map__unpin(struct bpf_map *map, const char *path);
int bpf_program__pin(struct bpf_program *prog, const char *path);
int bpf_program__unpin(struct bpf_program *prog, const char *path);
int bpf_object__pin_maps(struct bpf_object *obj, const char *path);
int bpf_object__unpin_maps(struct bpf_object *obj, const char *path);
int bpf_object__pin_programs(struct bpf_object *obj, const char *path);
int bpf_object__unpin_programs(struct bpf_object *obj, const char *path);
```

Функція `bpf_object__pin_maps()` автоматично обходить усі мапи, виявлені у ELF-файлі, та фіксує їх у вказаній директорії `path`. При цьому назви файлів відповідають назвам мап, оголошених у секції `SEC(".maps")` BPF-об'єктника.

Якщо в оголошенні мапи задано `__uint(pinning, LIBBPF_PIN_BY_NAME)`, бібліотека `libbpf` під час виклику `bpf_object__load()` сама фіксує мапу за іменем у стандартній директорії `/sys/fs/bpf/<map_name>`.

## Налаштування та опції монтування bpffs

Псевдофайлова система `bpffs` реєструється у ядрі під типом `bpf`. Команда монтування VFS дозволяє налаштовувати права доступу до кореневого каталогу:

```bash
mount -t bpf none /sys/fs/bpf -o mode=0770,uid=0,gid=1000
```

### Параметри монтування VFS

- `mode=OCTAL` — задає режим доступу POSIX до кореневого інода файлової системи (восьмеричне число, наприклад `0700` або `0775`).
- `uid=UID` — визначає числовий ідентифікатор користувача-власника кореневої директорії.
- `gid=GID` — визначає числовий ідентифікатор групи-власника.

Автоматичне монтування при завантаженні системи можна записати у файл `/etc/fstab`:

```fstab
none    /sys/fs/bpf    bpf    defaults,mode=0700    0 0
```

## Діагностика утилітою bpftool

Системна утиліта `bpftool` (із комплекту вихідного коду ядра Linux) надає інтерфейс командного рядка для інспектування фіксованих об'єктів у `bpffs`:

```bash
# Перегляд усіх фіксованих мап у системі
bpftool map list

# Дамп елементів мапи, зафіксованої у bpffs
bpftool map dump pinned /sys/fs/bpf/my_map

# Перегляд деталей програми eBPF за її зафіксованим шляхом
bpftool prog show pinned /sys/fs/bpf/my_prog

# Примусова фіксація відкритої програми за її ID
bpftool prog pin id 42 /sys/fs/bpf/my_pinned_prog
```

Утиліта `bpftool` самостійно звертається до системного виклику `bpf()` із командами `BPF_OBJ_GET` та `BPF_OBJ_PIN`, забезпечуючи швидкий аналіз стану системи без написання власного C-коду.

## Коди помилок та інспекція стану

Системний виклик `bpf()` звертається до VFS та підсистеми BPF, тому може повертати як загальні помилки VFS, так і спеціалізовані помилки BPF:

| Код `errno` | Контекст виклику | Детальний опис причини |
| :--- | :--- | :--- |
| `EEXIST` | `BPF_OBJ_PIN` | За вказаним шляхом `pathname` вже існує фіксований інод. Потрібно спочатку виконати `unlink()`. |
| `ENOENT` | `BPF_OBJ_GET` | Файл за вказаним шляхом не існує, або одна з проміжних директорій шляху відсутня у VFS. |
| `EINVAL` | `BPF_OBJ_PIN` / `GET` | Передано недійсний прапор у `file_flags` або непідтримуваний для цієї команди набір полів `bpf_attr`. |
| `EPERM` | `BPF_OBJ_PIN` / `GET` | Цільовий каталог не належить `bpffs`; або процес не має необхідних привілеїв `CAP_BPF` чи `CAP_SYS_ADMIN`; або `kernel.unprivileged_bpf_disabled = 1`. |
| `EACCES` | `BPF_OBJ_GET` | Процес не має прав доступу VFS (r/w) до файлу у `bpffs` відповідно до власника та mode інода. |
| `ENOMEM` | `BPF_OBJ_PIN` | Нестача оперативної пам'яті ядра для виділення нового `struct inode` або елемента `struct dentry`. |
