# 📋 Довідник вузлів та псевдофайлів каталогу /proc/[pid]

Каталог `/proc/[pid]` надає розмежований та безпечний інтерфейс доступу до внутрішніх структур даних ядра `task_struct`, `mm_struct`, `files_struct` та `signal_struct` конкретного процесу. Кожен процес у ядрі Linux отримує власний віртуальний каталог, ім'я якого відповідає числовому ідентифікатору процесу (PID). Нижче наведено розширену специфікацію ключових псевдофайлів, їхні типи, права доступу, формат даних та зв'язок із внутрішніми структури ядра Linux.

## Основні групи вузлів та їхній зв'язок з ядром

Псевдофайли всередині каталогу `/proc/[pid]` не є звичайними файлами на дисковому носієві, а слугують віртуальними точка входу до ядерної пам'яті. Усі псевдофайли можна розділити на чотири основні архітектурні категорії:

1. **Метадані стану та ідентифікації**: Файли `status`, `stat`, `cmdline`, `environ`, `cgroup`. Вони проектують поля структури `task_struct` та пов'язаних із нею контекстів безпеки.
2. **Аналіз віртуальної пам'яті**: Файли `maps`, `smaps`, `statm`, `mem`. Вони транслюють стан структури `mm_struct` та списку областей віртуальної пам'яті `vm_area_struct`.
3. **Ресурси та дескриптори**: Підкаталоги `fd/`, `fdinfo/`, файли `limits`, `io`. Вони розкривають структуру `files_struct` та таблицю відкритих файлів процесу.
4. **Символічні посилання та ієрархії**: Посилання `cwd`, `exe`, `root`, підкаталоги `ns/` та `task/`. Вони представляють контекст файлової системи (`fs_struct`), простори імен (`nsproxy`) та підпорядковані потоки виконання (`thread_group`).

## Специфікація псевдофайлів та підкаталогів /proc/[pid]

| Вузол | Тип | Права | Формат даних | Внутрішнє джерело в ядрі | Опис та призначення |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `cmdline` | Файл | `r--r--r--` | Послідовність `\0`-separated рядків | `mm_struct->arg_start` .. `arg_end` | Повний масив аргументів командного рядка, переданих під час запуску процесу. |
| `environ` | Файл | `r--------` | Послідовність `\0`-separated рядків | `mm_struct->env_start` .. `env_end` | Змінні середовища оточення процесу. Доступ обмежено власником або `CAP_SYS_PTRACE`. |
| `status` | Файл | `r--r--r--` | Текстовий `Key: Value` | `task_struct`, `signal_struct` | Підсумкова людиночитана статистика: стани, PID/TID, UID/GID, ресурси пам'яті (RSS, Peak), маски сигналів. |
| `stat` | Файл | `r--r--r--` | Поле, розділені пробілами | `task_struct`, `sched_entity` | Машинночитаний дамп із 52+ позиційних полів (PID, comm, state, ppid, utime, stime, priority, rss limit). |
| `statm` | Файл | `r--r--r--` | 7 чисел через пробіл | `mm_struct` | Метрики пам'яті в сторінках: size, resident, shared, text, lib, data, dirty. |
| `maps` | Файл | `r--------` | Текстова таблиця діапазонів | `mm_struct->mmap` (список VMA) | Список областей віртуальної пам'яті (VMA): адреси, права (`rwxp`), офсет, пристрій, inode, шлях до файлу. |
| `smaps` | Файл | `r--------` | Розширений текстовий блок | `vm_area_struct` | Деталізація VMA: PSS (Proportional Set Size), RSS, Shared/Private Clean/Dirty, Swap, Locked. |
| `mem` | Файл | `rw-------` | Бінарний потік адресації | `task_struct->mm` | Прямий доступ до віртуального адресного простору процесу. Використовується відлагоджувачем `gdb`. |
| `cwd` | Symlink | `rwx------` | Magic Symlink | `task_struct->fs->pwd` | Посилання на поточний робочий каталог процесу. |
| `exe` | Symlink | `rwx------` | Magic Symlink | `task_struct->mm->exe_file` | Посилання на бінарний виконуваний файл на диску. |
| `root` | Symlink | `rwx------` | Magic Symlink | `task_struct->fs->root` | Кореневий каталог процесу (враховує обмеження `chroot`). |
| `fd/` | Каталог | `r-x------` | Числові symlink `0`, `1`, `2` | `files_struct->fdt->fd[]` | Каталог відкритих файлових дескрипторів. Кожен дескриптор є символічним посиланням на файл, сокет чи FIFO. |
| `fdinfo/N` | Файл | `r--------` | Текстовий `pos: ... flags: ...` | `struct file` | Метадані дескриптора `N`: поточна позиція читання (`pos`), прапори `open()` у вісімковій системі, ePOLL/inotify записи. |
| `task/` | Каталог | `r-x--x--x` | Підкаталоги за TID | `task_struct->thread_group` | Список усіх потоків виконання (LWP) процесу. Кожен підкаталог `/proc/[pid]/task/[tid]` має структуру `/proc/[pid]`. |
| `ns/` | Каталог | `r-x------` | Symlink на namespace id | `nsproxy` | Символічні посилання на ізольовані простори імен Linux: `pid`, `net`, `mnt`, `ipc`, `uts`, `user`, `cgroup`, `time`. |
| `cgroup` | Файл | `r--r--r--` | `hierarchy:subsys:path` | `task_struct->cgroups` | Відображення контрольних груп (cgroups v1/v2), до яких прив'язаний процес. |
| `limits` | Файл | `r--r--r--` | Таблиця `Limit / Soft / Hard` | `signal_struct->rlim[]` | Поточні м'які (soft) та жорсткі (hard) обмеження ресурсів `rlimit` (RLIMIT_NOFILE, RLIMIT_STACK, RLIMIT_NPROC). |
| `io` | Файл | `r--------` | Текстові лічильники байтів | `task_struct->ioac` | Статистика дискового вводу/виводу: `rchar`, `wchar`, `syscr`, `syscw`, `read_bytes`, `write_bytes`, `cancelled_write_bytes`. |
| `oom_score` | Файл | `r--r--r--` | Ціле число від 0 до 1000 | `oom_badness()` calculation | Поточна ймовірність знищення процесу OOM-Killer під час дефіциту оперативної пам'яті. |
| `oom_score_adj`| Файл | `rw-r--r--` | Ціле від -1000 до 1000 | `signal_struct->oom_score_adj` | Коригування пріоритету OOM-Killer. Значення `-1000` повністю забороняє знищення процесу OOM-Killer'ом. |

## Детальний опис ключових метаданих процесу

### Структура файла /proc/[pid]/status

Псевдофайл `/proc/[pid]/status` призначений для отримання зведеної інформації про процес у людиночитаному текстовому форматі `Ключ: Значення`. Він поєднує в собі інформацію з кількох структур ядра і є оптимальним джерелом для системного моніторингу. Основні поля включають:

* `Name` — коротка назва виконуваного файла (до 16 символів із поля `comm` в `task_struct`).
* `State` — поточний стан процесу з літерним кодом (наприклад, `R (running)`, `S (sleeping)`, `D (disk sleep)`, `Z (zombie)`, `T (stopped)`).
* `Tgid` — ідентифікатор групи потоків (Thread Group ID), що відповідає традиційному PID процесу.
* `Pid` — ідентифікатор конкретного потоку (Thread ID), у контексті якого отримано статус.
* `PPid` — ідентифікатор батьківського процесу (Parent PID).
* `Uid` та `Gid` — чотири пари ідентифікаторів користувача та групи: реальний (real), ефективний (effective), збережений (saved) та файлової системи (filesystem UID/GID).
* `VmPeak` та `VmSize` — піковий та поточний обсяг віртуальної пам'яті процесу в кілобайтах.
* `VmRSS` — поточний обсяг фізичної оперативної пам'яті (Resident Set Size), виділеної процесу.
* `RssAnon`, `RssFile`, `RssShmem` — деталізація фізичної пам'яті за типами: анонімні сторінки, файловий кеш, спільна пам'ять.
* `VmData`, `VmStk`, `VmExe` — розміри сегментів даних, стеку та виконуваного коду.
* `Threads` — загальна кількість потоків виконання у даній групі процесів.
* `SigPnd`, `ShdPnd`, `SigBlk`, `SigIgn`, `SigCgt` — шістнадцяткові маски сигналів: очікуючих для потоку, очікуючих для процесу, заблокованих, ігнорованих та тих, що мають зареєстровані обробники.

### Машинночитаний файл /proc/[pid]/stat

Псевдофайл `/proc/[pid]/stat` містить понад 52 позиційні поля, розділені пробілами. Через те, що ім'я виконуваної програми у другому полі `comm` може містити довільні пробіли та дужки, надійний розбір вимагає пошуку останньої закриваючої дужки `)`.

Позиції ключових полів у `/proc/[pid]/stat`:

| Поле | Назва | Тип | Опис |
| :--- | :--- | :--- | :--- |
| 1 | `pid` | `int` | Ідентифікатор процесу. |
| 2 | `comm` | `string` | Назва виконуваного файлу в дужках, наприклад `(cat)` або `(my app)`. |
| 3 | `state` | `char` | Стан процесу: `R` (Running), `S` (Sleeping), `D` (Disk sleep), `Z` (Zombie), `T` (Stopped). |
| 4 | `ppid` | `int` | PID батьківського процесу. |
| 5 | `pgrp` | `int` | ID групи процесів (Process group ID). |
| 6 | `session` | `int` | ID сесії (Session ID). |
| 7 | `tty_nr` | `int` | Управляючий термінал процесу. |
| 8 | `tpgid` | `int` | ID фонової групи процесів терміналу. |
| 9 | `flags` | `unsigned int` | Прапори ядра для процесу (наприклад, `PF_KTHREAD`). |
| 10 | `minflt` | `unsigned long` | Кількість незначних збоїв сторінок (minor page faults). |
| 11 | `cminflt` | `unsigned long` | Сума minor page faults для завершених дочірніх процесів. |
| 12 | `majflt` | `unsigned long` | Кількість значних збоїв сторінок з підтягуванням з диска (major page faults). |
| 13 | `cmajflt` | `unsigned long` | Сума major page faults для завершених дочірніх процесів. |
| 14 | `utime` | `unsigned long` | Час виконання процесу у режимі користувача (в тиках `USER_HZ`). |
| 15 | `stime` | `unsigned long` | Час виконання процесу у режимі ядра (в тиках `USER_HZ`). |
| 16 | `cutime` | `long` | Час у режимі користувача для дочірніх процесів. |
| 17 | `cstime` | `long` | Час у режимі ядра для дочірніх процесів. |
| 18 | `priority` | `long` | Пріоритет планування ядра. |
| 19 | `nice` | `long` | Значення nice (від -20 до 19). |
| 20 | `num_threads` | `long` | Кількість потоків у групі процесів. |
| 21 | `itrealvalue` | `long` | Застарілий інтервальний таймер. |
| 22 | `starttime` | `unsigned long long` | Час запуску процесу після завантаження системи (в тиках). |
| 23 | `vsize` | `unsigned long` | Обсяг віртуальної пам'яті в байтах. |
| 24 | `rss` | `long` | Кількість фізичних сторінок у RAM (Resident Set Size). |

### Структура maps та smaps для аналізу пам'яті

Псевдофайл `/proc/[pid]/maps` транслює список об'єктів `vm_area_struct`, описуючи кожну неперервну область адресації:
```
55e2a1b00000-55e2a1b02000 r--p 00000000 08:02 131078                     /usr/bin/cat
55e2a1b02000-55e2a1b06000 r-xp 00002000 08:02 131078                     /usr/bin/cat
7ffc9a800000-7ffc9a821000 rw-p 00000000 00:00 0                          [stack]
```
Поля рядка `maps`:
1. `адреси` — стартова та кінцева адреса VMA у шістнадцятковій системі.
2. `права` — прапори читання `r`, запису `w`, виконання `x`, приватності `p` (copy-on-write) або спільного використання `s`.
3. `офсет` — зміщення у вихідному файлі, з якого відображено даний діапазон адресації.
4. `пристрій` — мажорний та мінорний номери блокового пристрою (`major:minor`).
5. `inode` — номер іноду файла на диску. Значення `0` вказує на анонімне відображення (наприклад, `malloc` або стек).
6. `шлях` — ім'я завантаженої бібліотеки, бинарника або системний тег (`[stack]`, `[heap]`, `[vdso]`).

Файл `/proc/[pid]/smaps` додає до кожного блоку VMA точний розрахунок фізичної пам'яті:
* `Size` — загальний розмір віртуальної області.
* `Rss` — розмір виділеної оперативної пам'яті.
* `Pss` — пропорційна частка пам'яті (Proportional Set Size). Якщо сторінка розміром 4 КБ розділена між 4 процесами, `Pss` для кожного дорівнюватиме 1 КБ.
* `Shared_Clean` / `Shared_Dirty` — обсяг спільних чистових та змінених (брудних) сторінок.
* `Private_Clean` / `Private_Dirty` — приватні сторінки, що належать виключно даному процесу.

### Каталог файлових дескрипторів fd/ та метадані fdinfo/

Підкаталог `/proc/[pid]/fd/` містить символічні посилання для кожного відкритого файлового дескриптора. Зчитування символічного посилання за допомогою `readlink()` дозволяє визначити цільовий ресурс:
* Для звичайних файлів — абсолютний шлях до файла на диск;
* Для мережевих сокетів — текстову позначку `socket:[inode]`;
* For анонімних каналів — `pipe:[inode]`;
* Для файлових об'єктів eventpoll, signalfd, timerfd — `anon_inode:[eventpoll]`.

Сусідній підкаталог `/proc/[pid]/fdinfo/[N]` надає розширену системну інформацію про дескриптор `N`:
```
pos:    8192
flags:  0100002
mnt_id: 25
ino:    45012
tfd:        4 events:     19 data: 7f8c9000
```
Рядок `pos` відображає поточну позицію читання/запису у файлі; `flags` — вісімковий масив прапорів `open()`; а додаткові рядки `tfd` або `clockid` розкривають внутрішній стан дескрипторів `epoll` та `timerfd`.

### Аналіз статистики вводу-виводу /proc/[pid]/io

Псевдофайл `/proc/[pid]/io` транслює лічильники підсистеми обліку вводу-виводу `task_struct->ioac`:
* `rchar` — кількість байтів, прочитаних процесом через усі системні виклики (`read`, `pread`).
* `wchar` — кількість байтів, записаних процесом через системні виклики (`write`, `pwrite`).
* `syscr` — загальна кількість системних викликів читання.
* `syscw` — загальна кількість системних викликів запису.
* `read_bytes` — кількість байтів, які дійсно спричинили дискове зчитання з фізичного накопичувача (повз сторінковий кеш).
* `write_bytes` — кількість байтів, відправлених на фізичний дисковий накопичувач.
* `cancelled_write_bytes` — обсяг байтів, запис яких було скасовано (наприклад, при видаленні тимчасового файла до скидання кешу).

## Особливості зчитування та розмежування прав доступу

При розробці системного програмного забезпечення, що взаємодіє з `/proc/[pid]`, необхідно враховувати специфічні правила VFS та ядра:

1. **Динамічний розмір файлів**: Спроба отримати розмір псевдофайлів `/proc/[pid]/status` або `cmdline` за допомогою системного виклику `stat()` повертає `st_size = 0`. Буфер читання має виділятися динамічно (типово 4096 байтів).
2. **Атомарність читання**: Один виклик `read()` повертає зліпок стану ядра на момент виконання. Якщо читання розбивається на кілька системних викликів із переміщенням каретки, стан процесу між викликами може змінитися.
3. **Обмеження hidepid**: При встановленні прапора монтування `hidepid=2` звичайний користувач бачитиме лише власні каталоги `/proc/[pid]/`. Для інших процесів спроба виклику `stat()` або `chdir()` повертає помилку `ENOENT` (No such file or directory).
4. **Перевірка ptrace_may_access()**: Доступ до чутливих псевдофайлів, таких як `/proc/[pid]/mem`, `/proc/[pid]/environ` або `/proc/[pid]/pagemap`, додатково контролюється функцією ядра `ptrace_may_access()`. Якщо процес не володіє відповідними ефективними ідентифікаторами користувача (EUID) або привілеєм `CAP_SYS_PTRACE`, ядро відхиляє відкриття файлу з помилкою `EACCES` або `EPERM`.
