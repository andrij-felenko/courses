# 📋 Інтерфейс ядра та конфігураційні параметри devtmpfs

Цей довідник описує повну поверхню взаємодії з файловою системою `devtmpfs`: прапори конфігурації збірки ядра Linux, параметри командного рядка завантаження, внутрішній C API ядра, опції системного виклику мотування у просторі користувача та відображення у псевдо-файлових системах procfs і sysfs.

## Конфігурація збірки ядра (Kconfig)

Параметри файлової системи `devtmpfs` визначаються під час конфігурації ядра Linux у розділі `Device Drivers -> Generic Driver Options`. Вони контролюють ввімкнення коду підсистеми та автоматичне монтування під час завантаження.

### Прапори конфігуратора Kconfig:

1. **`CONFIG_DEVTMPFS`**
   - **Тип:** `tristate` (`y` / `m` / `n`). На практиці завжди компілюється в ядро (`y`).
   - **Опис:** Вмикає компіляцію модуля `drivers/base/devtmpfs.c`. Реєструє внутрішній тип файлової системи `devtmpfs_fs_type` у VFS та запускає фоновий потік ядра `kdevtmpfs`. Без цього прапора ядро позбавлене можливості автоматично створювати вузли у пам'яті.
   - **Залежності:** Вимагає ввімкненої підтримки псевдо-файлових систем у пам'яті (`CONFIG_TMPFS` або `CONFIG_RAMFS`) та інфраструктури пристроїв `CONFIG_SHMEM`.

2. **`CONFIG_DEVTMPFS_MOUNT`**
   - **Тип:** `bool` (`y` / `n`).
   - **Опис:** Передає ядру вказівку автоматично виконати внутрішній монтаж примірника `devtmpfs` у каталог `/dev` під час виконання завантажувальної функції `kernel_init()`. Монтаж відбувається одразу після того, як ядро змонтувало кореневий диск або середовище `initramfs`, але **до** моменту запуску першого користувацького бінарного файлу (такого як `/init`, `/sbin/init` чи `/lib/systemd/systemd`).
   - **Системні наслідки:** Усуває потребу у вручну згенерованих статичних вузлах `/dev/console` та `/dev/null` у середовищі initramfs.

3. **`CONFIG_DEVTMPFS_SAFE`**
   - **Тип:** `bool` (`y` / `n`).
   - **Опис:** Задає суворіші початкові маски маскування прав доступу (umask) під час створення нових файлів пристроїв потоком `kdevtmpfs`. Гарантує, що невідомі або нові символьні пристрої не створюватимуться із загальнодоступними правами запису.

## Параметри командного рядка ядра (BootCmdline)

Налаштування `devtmpfs` можуть бути змінені у динамічному режимі під час завантаження системи без перекомпіляції ядра. Для цього системний завантажувач (GRUB, systemd-boot, U-Boot) передає ядру наступні аргументи:

- **`devtmpfs.mount=1`**: Примусово вмикає автоматичний монтаж `devtmpfs` у точка `/dev` при старті ядра. Перевизначає значення `CONFIG_DEVTMPFS_MOUNT=n`.
- **`devtmpfs.mount=0`**: Примусово вимикає автоматичний монтаж `devtmpfs` ядром. Застосовується у спеціалізованих середовищах розробки, при налагодженні кастомних середовищ `initramfs` або у контейнерних архітектурах, де простір користувача повинен самостійно контролювати вміст `/dev`.

## Внутрішній C API ядра (drivers/base/devtmpfs.h)

Функціональний інтерфейс `devtmpfs` використовується підсистемою `driver core` та не експортується для сторонніх модулів через `EXPORT_SYMBOL` (виклики є внутрішньоядровими).

Заголовочний файл `#include <linux/devtmpfs.h>` оголошує наступні ключові функції:

```c
int devtmpfs_create_node(struct device *dev);
int devtmpfs_delete_node(struct device *dev);
int devtmpfs_mount(const char *mntdir);
int devtmpfs_init(void);
```

### Детальний контракт та сигнатури методів:

#### 1. `int devtmpfs_create_node(struct device *dev)`

- **Параметри:** `dev` — вказівник на структуру пристрою ядра `struct device`, яка повинна містити дійсний номер пристрою `dev->devt` та сформоване ім'я `dev_name(dev)`.
- **Контекст виконання:** Може викликатися з будь-якого контексту, у тому числі з атомарного контексту переривань або під час тримання спін-блокувань драйвера.
- **Внутрішня механіка:** Аллокує структуру запиту `struct req`, копіює ім'я пристрою, мажорний/мінорний номери, режим доступу `mode` та додає запит до двозв'язного списку `req_list`. Після цього викликає `wake_up_process(thread)` для пробудження потоку `kdevtmpfs`.
- **Коди повернення:**
  - `0`: Запит успішно сформовано та поставлено у чергу потоку `kdevtmpfs`.
  - `-ENOMEM`: Не вдалося виділити оперативну пам'ять під структуру запиту `struct req`.
  - `-EINVAL`: Передано недійсний пристрій або номер `devt == 0`.

#### 2. `int devtmpfs_delete_node(struct device *dev)`

- **Параметри:** `dev` — вказівник на вилучений пристрій.
- **Контекст виконання:** Викликається з функції `device_del()` під час відключення обладнання або розвантаження модуля драйвера.
- **Внутрішня механіка:** Формує запит на вилучення вузла та передає його потоку `kdevtmpfs`. Потік виконує системну операцію `vfs_unlink()`. Якщо після видалення файла батьківський каталог порожній, викликається `vfs_rmdir()`.
- **Коди повернення:** `0` при успішній постановці запиту або від'ємний код помилки VFS (`-ENOENT`).

#### 3. `int devtmpfs_mount(const char *mntdir)`

- **Параметри:** `mntdir` — шлях до каталогу у файловій системі VFS, куди має бути змонтовано `devtmpfs` (стандартно `"/dev"` при виклику з `kernel_init`, або довільний каталог при виклику з VFS).
- **Контекст виконання:** Викликається виключно під час ранньої ініціалізації ядра з потоку `kernel_init`.
- **Коди повернення:** `0` при успішному монтажі або код помилки VFS (наприклад, `-EBUSY`, якщо каталог вже змонтовано).

## Системний виклик мотування у просторі користувача

Файлова система `devtmpfs` може бути змонтована інструментами простору користувача (утилітою `mount` або системним викликом `mount()`) у довільний каталог:

```bash
mount -t devtmpfs devtmpfs /dev -o mode=0755,nr_inodes=262144
```

### Доступні опції мотування (`-o`):

- **`mode=octal`**: Встановлює вісімковий режим доступу для кореневого індексу змонтованого каталогу. За замовчуванням значення становить `0755` (`rwxr-xr-x`).
- **`uid=N`**: Числовий ідентифікатор користувача, який стає власником кореневого каталогу `/dev` (за замовчуванням `0` — `root`).
- **`gid=N`**: Числовий ідентифікатор групи-власника кореневого каталогу `/dev` (за замовчуванням `0` — `root`).
- **`nr_inodes=N`**: Задає граничне обмеження на максимальну кількість індексних дескрипторів (об'єктів файлів та каталогів), які дозволено створити у цьому примірнику `devtmpfs`. Запобігає вичерпанню пам'яті ядра при масовій генерації вузлів.
- **`nr_blocks=N`**: Задає максимальний обсяг оперативної пам'яті (у сторінках розміром 4 КБ), який дозволено виділити під вміст файлів цієї файлової системи.

## Точки діагностики у віртуальних файлових системах

Стан та конфігурація `devtmpfs` відображаються у псевдо-файлових системах `procfs` та `sysfs`:

### 1. Перелік файлових систем (`/proc/filesystems`)

Містить рядок реєстрації `devtmpfs`. Відсутність префікса `nodev` вказує на те, що `devtmpfs` є повноцінною файловою системою, яка підтримує створення реальних вузлів пристроїв у пам'яті:

```
nodev   sysfs
nodev   proc
        devtmpfs
```

### 2. Таблиця змонтованих систем (`/proc/self/mountinfo`)

Відображає повний стан змонтованої файлової системи `devtmpfs`, включаючи ідентифікатор пристрою VFS, прапори мотування та обмеження ресурсів:

```
20 26 0:6 / /dev rw,nosuid,relatime shared:2 - devtmpfs devtmpfs rw,size=4042856k,nr_inodes=1010714,mode=0755
```

### 3. Індекси пристроїв у sysfs (`/sys/dev/char/` та `/sys/dev/block/`)

Кожному мажорному й мінорному номеру, що обробляється у `devtmpfs`, відповідає символічне посилання у `sysfs`:

- `/sys/dev/char/<major>:<minor>` — посилання на об'єкт `kobject` символьного пристрою у дереві `/sys/devices/`.
- `/sys/dev/block/<major>:<minor>` — посилання на об'єкт `kobject` блокового пристрою у дереві `/sys/devices/`.
