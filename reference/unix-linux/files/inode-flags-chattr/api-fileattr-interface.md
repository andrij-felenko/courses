# 📋 Інтерфейс прапорців inode: букви, константи, виклики

Ця вставка пояснює 📋 інтерфейс прапорців inode: букви, константи, виклики та дозволяє зрозуміти її детальніше. Це робочий аркуш до поля прапорців: яка буква `chattr` відповідає якій константі ядра, яким із двох наборів `ioctl` її читати й писати, що про неї каже `statx` і який код помилки що означає. Довідка потрібна саме тому, що інтерфейс зростав у двох місцях незалежно — в ext2 і в XFS, — і його половини перетинаються лише частково.

## Поле прапорців: буква ↔ константа ↔ дія

Значення констант — з `<uapi/linux/fs.h>`; буква — та, якою прапорець показує `lsattr` і приймає `chattr`.

| Буква | Константа | Значення | Що робить | Де діє |
|---|---|---|---|---|
| `s` | `FS_SECRM_FL` | `0x00000001` | затирати блоки при видаленні | ⛔ не реалізовано |
| `u` | `FS_UNRM_FL` | `0x00000002` | зберігати вміст для відновлення | ⛔ не реалізовано |
| `c` | `FS_COMPR_FL` | `0x00000004` | стискати вміст | ⛔ в ext2/3/4; діє в Btrfs, F2FS |
| `S` | `FS_SYNC_FL` | `0x00000008` | зміни файлу — синхронно | спільний набір |
| `i` | `FS_IMMUTABLE_FL` | `0x00000010` | жодних змін об'єкта | спільний набір |
| `a` | `FS_APPEND_FL` | `0x00000020` | запис лише в кінець | спільний набір |
| `d` | `FS_NODUMP_FL` | `0x00000040` | не копіювати `dump`-ом | спільний набір |
| `A` | `FS_NOATIME_FL` | `0x00000080` | не оновлювати час доступу | спільний набір |
| `m` | `FS_NOCOMP_FL` | `0x00000400` | не стискати | Btrfs, F2FS |
| `E` | `FS_ENCRYPT_FL` | `0x00000800` | вміст зашифровано | 🔒 лише читання |
| `I` | `FS_INDEX_FL` | `0x00001000` | каталог індексовано деревом | 🔒 лише читання |
| `j` | `FS_JOURNAL_DATA_FL` | `0x00004000` | дані теж через журнал | ext3, ext4 |
| `t` | `FS_NOTAIL_FL` | `0x00008000` | не зшивати хвости блоків | Reiserfs |
| `D` | `FS_DIRSYNC_FL` | `0x00010000` | зміни каталогу — синхронно | каталоги |
| `T` | `FS_TOPDIR_FL` | `0x00020000` | вершина ієрархії для розподільника | ext4 |
| `e` | `FS_EXTENT_FL` | `0x00080000` | файл описано екстентами | 🔒 лише читання |
| `V` | `FS_VERITY_FL` | `0x00100000` | увімкнено перевірку вмісту | 🔒 лише читання |
| `C` | `FS_NOCOW_FL` | `0x00800000` | без копіювання-при-записі | Btrfs |
| `x` | `FS_DAX_FL` | `0x02000000` | прямий доступ до пам'яті пристрою | спільний набір |
| `N` | `FS_INLINE_DATA_FL` | `0x10000000` | дані лежать усередині inode | 🔒 лише читання |
| `P` | `FS_PROJINHERIT_FL` | `0x20000000` | успадковувати проєкт для [квот](book:unix-linux/disk-quotas) | спільний набір |
| `F` | `FS_CASEFOLD_FL` | `0x40000000` | пошук імен без огляду на регістр | ext4, F2FS (порожній каталог) |

**🔒 лише читання** означає, що біт видно в `lsattr`, а `chattr` його не ставить і не знімає: файлова система вмикає його сама (шифрування — при створенні в зашифрованому каталозі, `V` — окремим викликом `FS_IOC_ENABLE_VERITY`). **⛔ не реалізовано** — прапорець дозволено записати, поведінки за ним у mainline немає.

## Гілка ext2: FS_IOC_GETFLAGS / FS_IOC_SETFLAGS

```c
ioctl(fd, FS_IOC_GETFLAGS, &attr);   /* int *attr */
ioctl(fd, FS_IOC_SETFLAGS, &attr);   /* int *attr */
```

Історична назва тієї самої пари — `EXT2_IOC_GETFLAGS`/`EXT2_IOC_SETFLAGS`. Пастка в оголошенні: номер зібрано як `_IOR('f', 1, long)`, тобто в назві стоїть `long`, а передавати треба **вказівник на `int`** — на 64-бітних машинах `long *` дає прочитані сміттєві старші байти. Мінімальний виклик через [дескриптор](book:unix-linux/file-descriptor), відкритий хоч би на читання:

```c
int fd = open(path, O_RDONLY | O_NONBLOCK);
int fl;
ioctl(fd, FS_IOC_GETFLAGS, &fl);          /* прочитали поле цілком */
fl |= FS_IMMUTABLE_FL;                    /* правимо лише свій біт */
ioctl(fd, FS_IOC_SETFLAGS, &fl);          /* записали поле цілком */
```

Запис завжди перекриває **все** поле, тому читання перед записом обов'язкове: інакше знімеш чужі прапорці мовчки.

## Гілка XFS: FS_IOC_FSGETXATTR / FS_IOC_FSSETXATTR

```c
struct fsxattr {
        __u32         fsx_xflags;      /* набір FS_XFLAG_* */
        __u32         fsx_extsize;     /* підказка розміру екстента, байти */
        __u32         fsx_nextents;    /* скільки екстентів — лише читання */
        __u32         fsx_projid;      /* проєкт для квот */
        __u32         fsx_cowextsize;  /* підказка розміру для копії-при-записі */
        unsigned char fsx_pad[8];      /* мусить бути нулями */
};

ioctl(fd, FS_IOC_FSGETXATTR, &fa);   /* struct fsxattr * */
ioctl(fd, FS_IOC_FSSETXATTR, &fa);
```

Прапорці тут інші за номерами й ширші за змістом: `FS_XFLAG_IMMUTABLE` = `0x08`, `FS_XFLAG_APPEND` = `0x10`, `FS_XFLAG_SYNC` = `0x20`, `FS_XFLAG_NOATIME` = `0x40`, `FS_XFLAG_NODUMP` = `0x80`, `FS_XFLAG_PROJINHERIT` = `0x200`, `FS_XFLAG_DAX` = `0x8000`. Поруч живе те, чого в старій гілці немає взагалі: `REALTIME`, `PREALLOC`, `EXTSIZE`, `NODEFRAG`, `FILESTREAM`, `COWEXTSIZE`, `HASATTR`. Аліаси `XFS_IOC_FSGETXATTR`/`XFS_IOC_FSSETXATTR` — та сама пара під давнішим ім'ям.

## Де гілки перетинаються

Спільних прапорців рівно сім, і ядро тримає їх окремими списками — `FS_COMMON_FL` та `FS_XFLAG_COMMON`:

```
SYNC · IMMUTABLE · APPEND · NODUMP · NOATIME · DAX · PROJINHERIT
```

Тільки їх видно з обох боків. Журналювання даних, стиснення, індексованість, екстентність читаються лише старою гілкою; підказки розмірів, ідентифікатор проєкту й лічильник екстентів — лише новою. Запис через будь-яку гілку зачіпає рівно спільну сімку плюс власні біти цієї гілки: перед правкою VFS дочитує решту поля зі старого значення, тож `FS_IOC_SETFLAGS` не збиває налаштований `fsx_extsize`, а `FS_IOC_FSSETXATTR` не гасить `j`.

## Шар fileattr у VFS

2021 року Міклош Середі виніс обидві гілки з `->ioctl()` кожної файлової системи в окремі операції inode (ядро 5.13, червень 2021):

```c
int (*fileattr_get)(struct dentry *dentry, struct fileattr *fa);
int (*fileattr_set)(struct mnt_idmap *idmap,
                    struct dentry *dentry, struct fileattr *fa);
```

`struct fileattr` — спільне подання обох гілок в одній структурі (`flags`, усі поля `fsx_*` і два прапорці чинності, `flags_valid`/`fsx_valid`). Ядро саме розбирає буфер користувача, бере блокування, перевіряє власника й можливості, дочитує незачеплені біти — і кличе файлову систему з готовим значенням. Файлова система без цих операцій відкочується на старий шлях `f_op->ioctl()`.

Виграш стосувався передусім тих систем, що не мають власного диска. Накладена ([overlayfs](book:unix-linux/overlay-filesystems)) і користувацькі ([FUSE](book:unix-linux/fuse-userspace-filesystems)) до того мусили перепаковувати `ioctl` із чужим буфером у просторі користувача, і зробити це чесно було майже неможливо; з `fileattr` вони дістали значення, а не адресу, і обидві перейшли на нього в тому ж 5.13. У 6.17 структуру перейменували на `struct file_kattr`, а поруч з'явилися виклики `file_getattr()`/`file_setattr()` — наступники `FS_IOC_FS*XATTR`, які працюють і з тими об'єктами, куди `ioctl` було не подати (FIFO, сокети, спецфайли).

## Читання без ioctl: statx

[statx](book:unix-linux/statx-extended-stat) віддає частину прапорців бітами `stx_attributes` — без відкриття файлу:

| Біт | Означає | З ядра |
|---|---|---|
| `STATX_ATTR_COMPRESSED` | вміст стиснено | 4.11 |
| `STATX_ATTR_IMMUTABLE` | незмінний | 4.11 |
| `STATX_ATTR_APPEND` | лише доповнюваний | 4.11 |
| `STATX_ATTR_NODUMP` | не для резервної копії | 4.11 |
| `STATX_ATTR_ENCRYPTED` | потрібен ключ | 4.11 |
| `STATX_ATTR_VERITY` | увімкнено [перевірку вмісту](book:unix-linux/fs-verity) | 5.5 |
| `STATX_ATTR_DAX` | прямий доступ | 5.8 |
| `STATX_ATTR_MOUNT_ROOT` | це корінь точки монтування | 5.8 |

```c
struct statx sx;
statx(AT_FDCWD, path, AT_SYMLINK_NOFOLLOW, STATX_BASIC_STATS, &sx);
if (sx.stx_attributes_mask & STATX_ATTR_IMMUTABLE)
        /* тепер біт у stx_attributes справді щось значить */;
```

> 🔧 **Навіщо це.** Маска — не формальність. Нуль у `stx_attributes` без перевірки `stx_attributes_mask` означає «ця пара ядро+файлова система про такий прапорець нічого не каже», а не «прапорця немає». Програма, що перевіряє незмінність лише за `stx_attributes`, на файловій системі без підтримки цього біта тихо вирішить, що файл звичайний.

## Хто має право

| Дія | Потрібно |
|---|---|
| будь-яка зміна поля | збіг UID із власником або `CAP_FOWNER` |
| `i`, `a` (`FS_IMMUTABLE_FL`, `FS_APPEND_FL`) | ще й [`CAP_LINUX_IMMUTABLE`](book:unix-linux/capabilities) |
| `j` (`FS_JOURNAL_DATA_FL`) | ще й `CAP_SYS_RESOURCE` |
| зміна `fsx_projid`, `P` | початковий простір імен користувачів |
| будь-який запис | монтування не в режимі лише для читання |

## Коди помилок

| Код | Коли |
|---|---|
| `EPERM` | не власник і без `CAP_FOWNER`; правка `i`/`a` без `CAP_LINUX_IMMUTABLE`; правка `j` без `CAP_SYS_RESOURCE`; спроба змінити ще щось у вже незмінному inode |
| `ENOTTY` | файлова система не знає цього `ioctl` узагалі (procfs, sysfs, більшість мережевих; tmpfs — до 6.0) |
| `EOPNOTSUPP` | виклик зрозуміло, а конкретний прапорець ця система не підтримує (ext4 на будь-який біт поза своїм набором, `F` без відповідної можливості) |
| `EINVAL` | підказка розміру екстента на об'єкті не того типу; зміна проєкту з неглавного простору імен; ненульовий `fsx_pad` |
| `EROFS` | монтування лише для читання |

## Командний рядок

```
chattr [-RVf] [-v версія] [-p проєкт] [+-=букви] файли...
lsattr [-RVadlpv] файли...
```

`+букви` додає, `-букви` знімає, `=букви` **робить поле рівно таким** — усе не перелічене буде знято, тож `=` без букв гасить усі змінювані прапорці. `-R` — рекурсія по каталогах, `-V` — багатослівний вивід, `-f` — притлумити повідомлення про помилки. Окремо від поля прапорців `-v` ставить номер покоління inode, `-p` — ідентифікатор проєкту.

```
$ lsattr /etc/resolv.conf
----i---------e------- /etc/resolv.conf
$ lsattr -l /etc/resolv.conf
/etc/resolv.conf                 Immutable, Extents
$ lsattr -d /etc            ← сам каталог, а не його вміст
```

Позиції букв у короткому рядку фіксовані, а `-l` друкує повні назви — на нього надійніше спиратися при розборі виводу, ніж на номер позиції.
