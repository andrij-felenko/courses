# 📋 Інтерфейс підсистеми dcache: структури, операції та функції маніпуляції

Підсистема кешування записів каталогів (dcache) надає внутрішній програмний інтерфейс ядра Linux для зв'язування текстових імен файлів, деревоподібної ієрархії каталогів та дискових метаданих `struct inode`. Драйвери файлових систем, модулі віртуалізації, мережеві стеки та системні виклики VFS взаємодіють із dcache через набір структур даних, таблицю зворотних викликів `struct dentry_operations` та спеціалізовані функції виділення, пошуку, валідації й вивільнення пам'яті.

## 1. Головні структури даних

### Швидкий рядок: `struct qstr`

Для мінімізації накладних витрат на регулярне обчислення довжини рядків та їхнє багаторазове хешування шар VFS використовує структуру `struct qstr` (від англ. *quick string*), оголошену в заголовному файлі `<linux/dcache.h>`. Її головне призначення — упакувати метадані рядка так, щоб їх можна було порівнювати без звернення до самого рядка символів у пам'яті:

```c
struct qstr {
    union {
        struct {
            u32 hash;
            u32 len;
        };
        u64 hashlen;
    };
    const unsigned char *name;
};
```

Поле `hashlen` об'єднує 32-бітне значення хешу рядка та його 32-бітну довжину в єдине 64-бітне беззнакове слово. Це дає змогу ядру перевіряти збіг довжини та хешу двох імен за одну атомарну 64-бітну процесорну інструкцію порівняння. Якщо числові значення `hashlen` не збігаються, ядро навіть не починає побайтове порівняння рядків через покажчик `name`, що суттєво заощаджує пропускну здатність шини пам'яті процесора.

### Структура запису каталогу: `struct dentry`

Об'єкт `struct dentry` представляє одиничний компонент шляху в пам'яті ядра. Його внутрішня розкладка ретельно скомпонована розробниками ядра для вирівнювання за межами кеш-ліній процесора (зазвичай займає рівно 192 байти на 64-бітних архітектурах x86_64 та AArch64):

```c
struct dentry {
    /* Прапорці стану запису (DCACHE_*) */
    unsigned int d_flags;

    /* Лічильник послідовності seqlock для перевірок в RCU-walk */
    seqcount_spinlock_t d_seq;

    /* Вузол у глобальній хеш-таблиці dentry_hashtable */
    struct hlist_bl_node d_hash;

    /* Вказівник на батьківський каталог */
    struct dentry *d_parent;

    /* Ім'я запису каталогу */
    struct qstr d_name;

    /* Вказівник на пов'язаний inode (NULL для негативних dentry) */
    struct inode *d_inode;

    /* Вбудований буфер для коротких імен (уникає зайвого kmalloc) */
    unsigned char d_iname[DNAME_INLINE_LEN];

    /* Об'єднаний спінлок d_lock та лічильник посилань d_count */
    struct lockref d_lockref;

    /* Таблиця спеціалізованих операцій файлової системи */
    const struct dentry_operations *d_op;

    /* Вказівник на суперблок файлової системи */
    struct super_block *d_sb;

    /* Часова мітка чинності (використовується NFS/CIFS) */
    unsigned long d_time;

    /* Приватні дані файлової системи */
    void *d_fsdata;

    union {
        /* Список витіснення з пам'яті LRU */
        struct list_head d_lru;
        /* Захист відкладеного вивільнення пам'яті через RCU */
        struct callback_head d_rcu;
    };

    /* Список дочірніх dentry поточного каталогу */
    struct list_head d_subdirs;

    /* Вузол у списку d_subdirs батьківського каталогу */
    struct list_head d_child;

    /* Список псевдонімів (жорстких посилань) одного inode */
    struct hlist_node d_alias;
} __randomize_layout;
```

Кожне поле структури виконує строго визначену функцію в життєвому циклі VFS:

- Поле `d_flags` зберігає бітові прапорці, що визначають тип запису та режим його обробки: `DCACHE_DIRECTORY_TYPE`, `DCACHE_AUTODIR_TYPE`, `DCACHE_SYMLINK_TYPE`, `DCACHE_DISCONNECTED` (для розірваних NFS-дерев), а також спеціальні оптимізаційні маркери на кшталт `DCACHE_RCUACCESS` та `DCACHE_DONTCACHE`.
- Поле `d_seq` типу `seqcount_spinlock_t` є серцем оптимістичної синхронізації RCU-walk. Перед читанням полів dentry процес зчитує лічильник версій; якщо після прочитання номер змінився або став непарним, це означає, що запис у цей самий момент змінювався іншим ядром (наприклад, перейменовувався через `rename()`), і обхід мусить повторити спробу або перейти в безпечний режим Ref-walk.
- Вбудований масив `d_iname` фіксованого розміру (зазвичай 32 або 40 байтів залежно від вирівнювання) дозволяє зберігати переважну більшість імен файлів безпосередньо всередині тіла `struct dentry`. Додаткове динамічне виділення пам'яті через `kmalloc` викликається лише тоді, коли довжина імені перевищує розмір цього внутрішнього буфера.
- Структура `d_lockref` упаковує 32-бітний спінлок `d_lock` та 32-бітний лічильник посилань `d_count` в одне 64-бітне поле. Завдяки цьому взяття та звільнення посилання на dentry (`dget()` / `dput()`) виконуються за допомогою єдиної процесорної інструкції `lock cmpxchg8b` (на x86) без фактичного блокування спінлока, якщо запис перебуває у стабільному стані.

## 2. Таблиця операцій `struct dentry_operations`

Файлові системи, які мають специфічні правила порівняння імен (наприклад, нечутливість до регістру символів у FAT чи NTFS), вимагають періодичної валідації записів через мережу (NFS, CIFS, CephFS) або створюють динамічні псевдофайли (pipefs, sockfs, nsfs), визначають власну таблицю операцій `dentry_operations`. Якщо файлова система не надає власної таблиці, VFS використовує стандартні оптимізовані загальносистемні алгоритми.

| Метод зворотного виклику | Сигнатура методу | Призначення, блокування та особливості |
| :--- | :--- | :--- |
| `d_revalidate` | `int (*d_revalidate)(struct dentry *, unsigned int);` | Перевіряє актуальність кешованого запису. Повертає 1 (запис чинний), 0 (запис застарів, скинути) або `-ECHILD` (неможливо перевірити без взяття блокувань чи мережевого I/O в RCU-walk). |
| `d_weak_revalidate` | `int (*d_weak_revalidate)(struct dentry *, unsigned int);` | Викликається для фінальної перевірки результату обходу, коли шлях перескочив через точку монтування або кореневий каталог (`LOOKUP_JUMPED`). |
| `d_hash` | `int (*d_hash)(const struct dentry *, struct qstr *);` | Генерує спеціалізований хеш імені. Наприклад, переводить усі символи у нижній регістр перед обчисленням хешу для файлових систем, нечутливих до регістру. |
| `d_compare` | `int (*d_compare)(const struct dentry *, unsigned int, const char *, const struct qstr *);` | Виконує побайтове порівняння двох імен із урахуванням правил конкретної ФС (наприклад, порівняння рядків UTF-8 без урахування регістру або зі збереженням канонічної форми). |
| `d_delete` | `int (*d_delete)(const struct dentry *);` | Викликається, коли лічильник посилань `d_count` падає до нуля. Якщо метод повертає 1, запис негайно знищується з пам'яті й не потрапляє до черги витіснення LRU. |
| `d_init` | `int (*d_init)(struct dentry *);` | Викликається відразу після виділення пам'яті під новий dentry для первинної ініціалізації приватних структур драйвера файлової системи. |
| `d_release` | `void (*d_release)(struct dentry *);` | Викликається безпосередньо перед вивільненням пам'яті dentry у slab-алокатор для безпечного очищення динамічних ресурсів у полі `d_fsdata`. |
| `d_prune` | `void (*d_prune)(struct dentry *);` | Сповіщає файлову систему про те, що запис примусово вилучається зі списку LRU під тиском нестачі пам'яті (dcache shrinker). |
| `d_iput` | `void (*d_iput)(struct dentry *, struct inode *);` | Замінює стандартний системний виклик `iput()` на власну логіку драйвера (наприклад, для відкладеного або асинхронного засинання при скиданні зв'язку з inode). |
| `d_dname` | `char *(*d_dname)(struct dentry *, char *, int);` | Формує динамічний псевдошлях для спеціальних псевдофайлів ядра (наприклад, `pipe:[12345]`, `socket:[6789]`, `anon_inode:[eventpoll]`). |
| `d_real` | `struct dentry *(*d_real)(struct dentry *, const struct inode *);` | Повертає реальний underlying dentry у багатошарових файлових системах (OverlayFS) для безпосереднього доступу до нижнього або верхнього шару. |

Особливе значення має метод `d_revalidate`. У локальних дискових файлових системах (ext4, XFS, Btrfs) він зазвичай дорівнює `NULL`, оскільки VFS гарантує узгодженість локального кешу через прямі модифікації в оперативній пам'яті. На противагу цьому, у мережевих файлових системах (NFS, CIFS) файл на віддаленому сервері може бути видалений або змінений іншим клієнтом в обхід локального ядра. Тому `d_revalidate` перевіряє часові мітки або відправляє контрольний RPC-запит до сервера перед тим, як дозволити відкриття файлу з dcache. Якщо вхідний прапорець містить `LOOKUP_RCU`, метод зобов'язаний діяти без засинання та без блокувань; якщо мережевий запит неминучий, він негайно повертає помилку `-ECHILD`, змушуючи VFS безпечно відкотитися в режим Ref-walk.

## 3. Ключові функції ядерного API

### Керування лічильником посилань та життєвим циклом

Ядро Linux надає суворий набір функцій для відстеження використання записів dentry. Помилки у виклику цих функцій призводять або до витоків пам'яті (запис назавжди зависає в пам'яті з ненульовим лічильником), або до передчасного вивільнення пам'яті з подальшим збоєм ядра (use-after-free).

```c
/* Збільшити лічильник посилань dentry (перехід у стан Active) */
struct dentry *dget(struct dentry *dentry);

/* Безпечно отримати посилання на батьківський каталог із захистом від паралельного переміщення */
struct dentry *dget_parent(struct dentry *dentry);

/* Зменшити лічильник посилань. Якщо d_count стає 0, запис переміщується до списку LRU */
void dput(struct dentry *dentry);

/* Зменшити лічильник і перенести dentry у вказаний тимчасовий список для пакетного вивільнення */
void dput_to_list(struct dentry *dentry, struct list_head *list);

/* Примусово вилучити dentry з глобальної хеш-таблиці (позначити як unhashed/застарілий) */
void d_drop(struct dentry *dentry);

/* Позначити dentry як видалений та ініціювати його вивільнення або перетворення на негативний */
void d_delete(struct dentry *dentry);

/* Зробити недійсним dentry та всі його дочірні записи, примусово очищаючи піддерево */
void d_invalidate(struct dentry *dentry);
```

Функція `dget()` виконує атомарний інкремент лічильника посилань і повертає покажчик на той самий об'єкт, що зручно для ланцюжкових викликів. Функція `dput()` є значно складнішою: якщо лічильник посилань падає до нуля, вона перевіряє стан прапорців та викликає метод `d_delete()`. Якщо dentry все ще пов'язаний із inode і є чинним, він поміщається в кінець черги `list_lru` відповідного суперблоку, залишаючись у глобальній хеш-таблиці `dentry_hashtable` як кандидат на майбутнє повторне використання. Якщо ж dentry визнано недійсним або від'єднаним (`d_unhashed`), `dput()` викликає внутрішню процедуру `dentry_kill()`, яка розриває зв'язки з батьківським каталогом, декрементує лічильник посилань inode через `iput()` і планує вивільнення пам'яті через `call_rcu()`.

### Виділення пам'яті та зв'язування з inode

Під час промаху в кеші файлова система створює новий dentry та зв'язує його з прочитаним із диска inode за допомогою таких інтерфейсів:

```c
/* Виділити новий dentry в slab-кеші dentry_cache як нащадка parent із заданим іменем name */
struct dentry *d_alloc(struct dentry *parent, const struct qstr *name);

/* Виділити анонімний dentry, не прив'язаний до батьківського каталогу (для кореня або сокетів) */
struct dentry *d_alloc_anon(struct super_block *sb);

/* Зв'язати новий dentry з існуючим inode (створити позитивний запис) */
void d_instantiate(struct dentry *dentry, struct inode *inode);

/* Додати новий dentry в хеш-таблицю dentry_hashtable та прив'язати до inode (або NULL) */
void d_add(struct dentry *dentry, struct inode *inode);

/* Спеціалізоване додавання для файлових систем без урахування регістру (case-insensitive) */
struct dentry *d_add_ci(struct dentry *dentry, struct inode *inode, struct qstr *name);

/* Прив'язати або підмінити аліас каталогу (критично для NFS та переміщень каталогів) */
struct dentry *d_splice_alias(struct inode *inode, struct dentry *dentry);
```

Функція `d_alloc()` виділяє структуру з кешу пам'яті `dentry_cache`, ініціалізує лічильник посилань значенням 1, копіює рядок імені у буфер `d_iname` (або виділяє окремий буфер через `kmalloc`), встановлює зв'язок `d_parent` та додає новий елемент до списку нащадків батьківського каталогу `d_subdirs`. Функція `d_instantiate()` зв'язує цей dentry з відповідним `struct inode`, додаючи dentry до списку аліасів `i_dentry` цього inode. Якщо у виклику `d_add()` замість покажчика на inode передається `NULL`, VFS реєструє **негативний dentry**, що фіксує відсутність файлу з таким ім'ям.

### Пошук у кеші записів каталогів

Пошук у dcache є головною операцією на гарячому шляху системних викликів `open()`, `stat()`, `execve()`:

```c
/* Знайти дочірній dentry за іменем name у каталозі parent через dentry_hashtable */
struct dentry *d_lookup(const struct dentry *parent, const struct qstr *name);

/* Обчислити хеш рядка та виконати швидкий пошук dentry в каталозі parent */
struct dentry *d_hash_and_lookup(struct dentry *parent, struct qstr *name);

/* Знайти або створити dentry для рядка заданої довжини (вимагає захоплення блокування каталогу) */
struct dentry *lookup_one_len(const char *name, struct dentry *base, int len);

/* Знайти або створити dentry для рядка заданої довжини без блокування батьківського каталогу */
struct dentry *lookup_one_len_unlocked(const char *name, struct dentry *base, int len);
```

Функція `d_lookup()` обчислює слот у хеш-таблиці `dentry_hashtable` за комбінацією покажчика `parent` та хешу імені, після чого проходить по ланцюжку кошика. Якщо запис знайдено, перевіряється збіг довжини, хешу та символів імені. При успішному збігу функція інкрементує лічильник посилань `dget()` і повертає знайдений `struct dentry`. Якщо запис відсутній, повертається `NULL`.

### Перевірка стану запису

Для швидкого з'ясування властивостей запису каталогу ядро використовує набір швидких inline-функцій:

```c
/* Чи є dentry негативним (d_inode == NULL, файл гарантовано відсутній) */
static inline bool d_is_negative(const struct dentry *dentry);

/* Чи є dentry позитивним (d_inode != NULL, файл існує) */
static inline bool d_is_positive(const struct dentry *dentry);

/* Чи представляє dentry каталог (перевіряє прапорець DCACHE_DIRECTORY_TYPE) */
static inline bool d_is_dir(const struct dentry *dentry);

/* Чи представляє dentry символьне посилання (DCACHE_SYMLINK_TYPE) */
static inline bool d_is_symlink(const struct dentry *dentry);

/* Чи вилучено dentry з глобальної хеш-таблиці dentry_hashtable */
static inline int d_unhashed(const struct dentry *dentry);
```

Ці предикати дозволяють спільним алгоритмам VFS приймати рішення про подальший хід обходу шляху без прямого звернення до полів `struct inode`, що зменшує кількість промахів у кеші процесора.

### Відтворення рядка шляху

Оскільки dentry зберігає тільки власне коротке ім'я та покажчик на батька `d_parent`, відтворення повного канонічного шляху здійснюється послідовним рухом угору до вершини дерева:

```c
/* Відтворити абсолютний шлях до об'єкта path (dentry + vfsmount) у наданому буфері buf */
char *d_path(const struct path *path, char *buf, int buflen);

/* Відтворити відносний шлях dentry відносно кореня його файлової системи */
char *dentry_path(const struct dentry *dentry, char *buf, int buflen);

/* Неблокувальне отримання рядка шляху dentry (для ftrace, perf та обробників помилок) */
char *dentry_path_raw(const struct dentry *dentry, char *buf, int buflen);
```

Функція `d_path()` заповнює буфер `buf` з кінця: вона записує ім'я поточного dentry, піднімається за покажчиком `d_parent`, записує ім'я батька, додає розділювач `/` і повторює цей цикл до досягнення кореневого dentry точки монтування або кореня простору імен процесу. Отриманий рядок повертається як покажчик на початок сформованого тексту всередині буфера.

## 4. Прапорці обходу шляхів (Lookup Flags)

Під час виконання розбору шляхів у `fs/namei.c` спільний код VFS передає бітову маску прапорців, яка визначає режим синхронізації, правила обробки переходів та вимоги до кінцевого файлу:

| Прапорець | Числове значення | Семантика та вплив на поведінку dcache |
| :--- | :--- | :--- |
| `LOOKUP_RCU` | `0x0040` | Обхід виконується в безблокувальному режимі RCU-walk без змін лічильників посилань `d_count` та без spinlock. |
| `LOOKUP_FOLLOW` | `0x0001` | Слідувати за символьними посиланнями (розкривати вміст знайденого symlink). |
| `LOOKUP_DIRECTORY` | `0x0002` | Кінцевий об'єкт шляху обов'язково має бути каталогом (інакше ядро повертає помилку `-ENOTDIR`). |
| `LOOKUP_AUTOMOUNT` | `0x0004` | Автоматично викликати монтування при потраплянні на dentry з прапорцем `DCACHE_NEED_AUTOMOUNT`. |
| `LOOKUP_EMPTY` | `0x4000` | Дозволити передачу порожнього рядка шляху (використовується системними викликами із прапорцем `AT_EMPTY_PATH`). |
| `LOOKUP_NO_SYMLINKS` | `0x0100` | Заборонити розкриття будь-яких символьних посилань на всьому шляху (при виявленні symlink повертає `-ELOOP`). |
| `LOOKUP_RENAME_TARGET` | `0x0800` | Спеціальний режим для розв'язання цільового dentry при операції `rename()`, що запобігає створенню зайвих аліасів. |

Усі перелічені інтерфейси утворюють фундамент файлової підсистеми ядра Linux. Вони забезпечують бездоганну цілісність глобальної структури каталогів, гарантуючи водночас екстремальну масштабованість паралельних операцій читання на сучасних багатоядерних обчислювальних вузлах.
