# 🔌 Довідник системних дерев та типів ключів Btrfs

Файлова система Btrfs будується на концепції «лісу дерев» (Forest of Trees). Кожне системне або користувацьке дерево виконує окрему роль у загальній архітектурі зберігання даних, але всі вони використовують єдиний формат вузлів, листків та триплетних ключів `struct btrfs_key`.

Нижче наведено повну специфікацію внутрішніх системних дерев Btrfs, типів ключів, бінарних структур ядра Linux та програмного інтерфейсу розшуку метаданих.

## Каталог системних дерев Btrfs

Кожне дерево в Btrfs має свій унікальний ідентифікатор об'єкта (`owner` або `objectid` у заголовку дерева `struct btrfs_header`). Записи про коріння цих дерев зберігаються у вигляді елементів `BTRFS_ROOT_ITEM_KEY` всередині головного дерева `ROOT_TREE`.

Усі спеціалізовані дерева діляться на чотири фундаментальні категорії за їхньою функціональною відповідальністю:
1. **Дерева метаданих тома (Global Metadata Trees):** `ROOT_TREE`, `CHUNK_TREE`, `DEV_TREE` та `FREE_SPACE_TREE`. Вони управляють цілісністю пулу пристроїв та адресацією.
2. **Дерева субтомів (Subvolume Trees):** `FS_TREE` та його снапшоти (IDs `>= 256`). Вони містять метадані та файли користувача.
3. **Дерева обслуговування ресурсів (Resource Management Trees):** `EXTENT_TREE`, `CSUM_TREE`, `QUOTA_TREE` та `UUID_TREE`. Вони відповідають за облік дискових блоків, контрольних сум, квот та унікальних ідентифікаторів.
4. **Тимчасові операційні дерева (Operational Trees):** `TREE_LOG_TREE` та `DATA_RELOC_TREE`. Вони прискорюють транзакції `fsync()` та балансування чанків.

| Назва дерева | Object ID (`owner`) | Тип вмісту та призначення в ядрі Linux | Життєвий цикл та блокування |
| :--- | :--- | :--- | :--- |
| **`ROOT_TREE`** | `1ULL` | Головне дерево метаданих. Містить записи `BTRFS_ROOT_ITEM_KEY`, які вказують на логічні адреси кореневих вузлів усіх інших дерев у системі (зокрема субтомів, `EXTENT_TREE`, `CSUM_TREE` тощо). | Постійне, оновлюється при кожному `btrfs_commit_transaction()`. |
| **`EXTENT_TREE`** | `2ULL` | Веде облік алокації дискового простору. Містить записи про кожен виділений екстент даних та метаданих, а також лічильники CoW-посилань (reference count) для підтримки дедуплікації та відстеження снапшотів. | Постійне, блокується `extent_root->alloc_sem`. |
| **`CHUNK_TREE`** | `3ULL` | Модуль трансляції адрес (RAID-шар). Перетворює віртуальні 64-бітні логічні адреси Btrfs у фізичні зсуви на конкретних блочних пристроях. Реалізує профілі RAID0, RAID1, RAID10, RAID5, RAID6, DUP та SINGLE. | Змінюється лише при додаванні/видаленні чанків або балансуванні. |
| **`DEV_TREE`** | `4ULL` | Зберігає метадані про всі фізичні та віртуальні блочні пристрої, що входять до складу дискового пулу Btrfs (розміри, геометрія, UUID пристроїв, кількість виділених чанків). | Модифікується при `btrfs device add/remove/ready`. |
| **`FS_TREE`** | `5ULL` | Головне дерево файлової системи за замовчуванням (Default Subvolume, ID 5). Зберігає іноди, елементи директорій, розширені атрибути та вказівники на екстенти даних користувацьких файлів. | Персистентне, має власний ID субтому (зазвичай >= 256). |
| **`CSUM_TREE`** | `7ULL` | База контрольних сум даних. Зберігає послідовності контрольних сум (CRC32c, xxHash, SHA256 або BLAKE2b) для всіх блоків даних файлів із кроком у 4 КБ. Використовується під час читання для виявлення фонового пошкодження («тихої деградації» даних). | Накопичується при записі даних, очищається при видаленні екстентів. |
| **`QUOTA_TREE`** | `8ULL` | Веде облік обмежень дискового простору (квот) для окремих субтомів та їхніх ієрархічних груп (qgroups). | Активне при увімкнених квотах (`btrfs quota enable`). |
| **`UUID_TREE`** | `9ULL` | Швидкий індекс відповідності між 128-бітними UUID субтомів/снапшотів та їхніми внутрішніми числовими ідентифікаторами `objectid`. | Оновлюється при створенні та видаленні снапшотів. |
| **`FREE_SPACE_TREE`**| `10ULL` | Бітова карта та список вільних екстентів на диску. Прискорює пошук вільних блоків при високій заповненості файлової системи, замінюючи застарілі об'єкти `FREE_SPACE_INFO`. | Активне для прискорення алокатора (`space_info`). |
| **`TREE_LOG_TREE`** | `18446744073709551607ULL` (`-10ULL`) | Тимчасове дерево журналу швидкої фіксації `fsync()` (Log Tree). Використовується для прискорення синхронного запису окремих файлів без виконання повного commit всієї транзакції Btrfs. | Тимчасове, скидається та знищується при `btrfs_commit_transaction()`. |
| **`DATA_RELOC_TREE`**| `18446744073709551601ULL` (`-9ULL`) | Спеціалізоване дерево для переміщення та балансування екстентів даних під час виконання команди `btrfs balance`. | Тимчасове, створюється під час розгрузки/балансування чанків. |

## Детальний розбір функціоналу операційних дерев

### Дерево прискореного журналювання (`TREE_LOG_TREE`)

Для забезпечення високої швидкодії при виконанні синхронних операцій `fsync()`, Btrfs виділяє окреме дерево журналу. Замість того, щоб перезаписувати верхні рівня метаданих усього `FS_TREE` і змушувати ядро оновлювати суперблок при кожному `fsync()`, ядро створює тимчасове `TREE_LOG_TREE`. 

У це дерево копіюються лише змінені листки конкретної іноди. У разі аварійного відключення живлення під час монтування файлової системи викликається підсистема `btrfs_replay_log()`. Вона зчитує незафіксовані листки з `TREE_LOG_TREE`, вставляє відповідні ключі в основне `FS_TREE` і гарантує збереження файлів без пошкодження загальної цілісності метаданих.

При виконанні планового commit загальної транзакції Btrfs (за замовчуванням кожні 30 секунд), ядро переносить усі записи з `TREE_LOG_TREE` у відповідні листки `FS_TREE`, після чого звільняє дискові блоки log-дерева через підсистему `btrfs_free_log()`. Цей підхід гарантує повну сумісність із вимогами POSIX стандарту щодо стійкості файлових операцій.

### Дерево прискорення вільних екстентів (`FREE_SPACE_TREE`)

У ранніх версіях Btrfs інформація про вільні дискові блоки зберігалася в окремих застарілих файлах кешу вільних блоків (`FREE_SPACE_INFO`). При заповненні файлової системи на 90% і більше прочитання та оновлення цих файлів створювало суттєву затримку при виділенні дискових екстентів під нові записи.

Починаючи з ядра Linux 4.5, Btrfs впровадила **`FREE_SPACE_TREE`** (ID 10). Це дерево зберігає інформацію про вільні блоки у двох форматах ключів:
- **`BTRFS_FREE_SPACE_EXTENT_KEY`:** Записи про суцільні діапазони вільних блоків (початковий зсув та довжина).
- **`BTRFS_FREE_SPACE_BITMAP_KEY`:** Компактні бітові карти для дуже фрагментованих блочних груп.

Завдяки цьому алокатор Btrfs виконує пошук вільного місця за логарифмічний час `O(log₂ N)` навіть при екстремально високому рівні заповненості накопичувача.

Усі модифікації `FREE_SPACE_TREE` узгоджуються з підсистемою `btrfs_block_group` в оперативній пам'яті, що запобігає виникненню фрагментації метаданих при виділенні нових чанків під дискові екстенти.

У разі виявлення розбіжностей під час монтування, адміністратор може форсувати повну перебудову цього дерева викликом команди монтування `mount -o clear_cache,space_cache=v2`.

## Каталог типів ключів (Key Types)

Ключ Btrfs складено з трьох полів: `objectid` (64 біти), `type` (8 біт) та `offset` (64 біти). Поле `type` визначає семантичне значення запису, що лежить у листку за цим ключем.

### Ключі метаданих файлів та директорій (`FS_TREE`)

Кожен файл усередині `FS_TREE` представлена сукупністю пов'язаних ключів, які лежать поруч у листку в порядку зростання числових кодів `type`:

- **`BTRFS_INODE_ITEM_KEY` (`1`):** 
  - **`objectid`:** Номер іноди файлу або директорії (наприклад, `256`).
  - **`offset`:** Завжди `0`.
  - **Дані:** Структура `struct btrfs_inode_item` (розмір файлу в байтах, права доступу POSIX, UID, GID, кількість жорстких посилань, позначки часу mtime/ctime/atime, прапорці файлу).
- **`BTRFS_INODE_REF_KEY` (`12`):**
  - **`objectid`:** Номер іноди файлу.
  - **`offset`:** Номер іноди батьківської директорії.
  - **Дані:** Ім'я файлу всередині батьківської директорії та порядковий номер запису (index). Дозволяє ядру відновити повний шлях до файлу за його інодою (зворотний резолюшн шляхів).
- **`BTRFS_INODE_EXTREF_KEY` (`13`):**
  - **`objectid`:** Номер іноди файлу.
  - **`offset`:** Хеш імені файлу та іноди батьківської директорії.
  - **Дані:** Розширена форма зворотного посилання для підтримки багатьох тисяч жорстких посилань на один файл в одній директорії.
- **`BTRFS_XATTR_ITEM_KEY` (`24`):**
  - **`objectid`:** Номер іноди файлу.
  - **`offset`:** Хеш назви розширеного атрибута (наприклад, `user.comment` або `security.selinux`).
  - **Дані:** Повне ім'я та значення розширеного атрибута `xattr`.
- **`BTRFS_DIR_ITEM_KEY` (`84`):**
  - **`objectid`:** Номер іноди директорії.
  - **`offset`:** Хеш імені файлу/піддиректорії (обчислений за алгоритмом CRC32c від імені).
  - **Дані:** Елемент директорії: цільовий `objectid` (номер іноди файлу), тип файлу (REG, DIR, LNK), довжина імені та безпосередньо текстове ім'я. У разі колізії хешу двох різних імен файлів, Btrfs зберігає декілька елементів `btrfs_dir_item` підряд усередині одного тіла даних.
- **`BTRFS_DIR_INDEX_KEY` (`96`):**
  - **`objectid`:** Номер іноди директорії.
  - **`offset`:** Порядковий монотонний лічильник елементів у директорії (0, 1, 2, ...).
  - **Дані:** Аналогічний вміст до `DIR_ITEM`, але впорядкований за порядком додавання файлів. Використовується ядром для послідовного сканування директорії системними викликами `readdir()` та `getdents64()`.
- **`BTRFS_EXTENT_DATA_KEY` (`108`):**
  - **`objectid`:** Номер іноди файлу.
  - **`offset`:** Логічний байтовий зсув усередині файлу (наприклад, `0`, `4096`, `1048576`).
  - **Дані:** Структура `struct btrfs_file_extent_item`. Містить фізичну адресу екстента на диску, розпакований та упакований розмір екстента, тип стиснення (NONE, ZLIB, LZO, ZSTD) та прапор inline-даних (якщо малий файл зберігається безпосередньо у листку метаданих).

### Ключі управління ресурсами, екстентами та субтомами (`EXTENT_TREE` та `ROOT_TREE`)

Підсистема алокації дискового простору та обліку CoW-посилань спирається на спеціалізовані типи ключів у системних деревах:

- **`BTRFS_ROOT_ITEM_KEY` (`132`):**
  - **`objectid`:** Ідентифікатор дерева або субтому (наприклад, `256` для користувацького субтому).
  - **`offset`:** Завжди `0` або номер генерації транзакції.
  - **Дані:** Структура `struct btrfs_root_item`: логічна адреса кореневого вузла даного дерева, UUID субтому, generation створення, лічильник CoW-посилань.
- **`BTRFS_EXTENT_ITEM_KEY` (`168`):**
  - **`objectid`:** Логічна адреса екстента на диску (`bytenr`).
  - **`offset`:** Довжина екстента в байтах.
  - **Дані:** Лічильник посилань (`refs`), generation створення та прапорці типу екстента (DATA або TREE_BLOCK).
- **`BTRFS_METADATA_ITEM_KEY` (`169`):**
  - **`objectid`:** Логічна адреса вузла/листка метаданих (`bytenr`).
  - **`offset`:** Рівень вузла в дереві (`level`).
  - **Дані:** Оптимізований запис обліку вузла B-дерева в `EXTENT_TREE` для економії дискового простору.
- **`BTRFS_TREE_BLOCK_REF_KEY` (`176`):**
  - **`objectid`:** Логічна адреса блоку метаданих.
  - **`offset`:** ID дерева-власника (`owner`), яке посилається на цей блок.
  - **Дані:** Пряме зворотне посилання (backreference) для підтримки перевірки цілісності та де-алокації дерев.
- **`BTRFS_SHARED_BLOCK_REF_KEY` (`182`):**
  - **`objectid`:** Логічна адреса блоку метаданих.
  - **`offset`:** Логічна адреса батьківського вузла, який ділить цей блок між кількома снапшотами.
  - **Дані:** Спільне зворотне посилання для алгоритму каскадного CoW-дедуплікаційного видалення.
- **`BTRFS_CHUNK_ITEM_KEY` (`228`):**
  - **`objectid`:** Завжди `BTRFS_FIRST_CHUNK_TREE_OBJECTID` (`256ULL`).
  - **`offset`:** Логічна віртуальна адреса початку чанку в 64-бітному просторі.
  - **Дані:** Структура `struct btrfs_chunk`: розмір чанку, профіль RAID, кількість смуг (stripes) та масив фізичних зсувів на блочних пристроях.

## Фундаментальні бінарні структури ядра (`fs/btrfs/ctree.h`)

Усі структури Btrfs упаковуються без вирівнювання з допомогою прапора `__attribute__((packed))` та зберігають багатобайтові числа в форматі Little-Endian (`__le64`, `__le32`, `__le16`).

```c
// Заголовок кожного вузла або листка Btrfs (101 байт)
struct btrfs_header {
    u8 csum[32];               // Контрольна сума вмісту вузла (CRC32c / xxHash)
    u8 fsid[16];               // UUID файлової системи
    __le64 bytenr;             // Логічна адреса цього вузла на диску
    __le64 flags;              // Прапорування вузла (WRITTEN, RELOC)
    u8 chunk_tree_uuid[16];    // UUID дерева чанків
    __le64 generation;         // Номер транзакції (Transaction ID), коли написано вузол
    __le64 owner;              // ID дерева-власника (наприклад, ROOT_TREE_OBJECTID)
    __le32 nritems;            // Кількість елементів у вузлі/листку
    u8 level;                  // Рівень у дереві (0 = leaf, 1..7 = internal node)
} __attribute__ ((packed));

// Фундаментальний ключ пошуку Btrfs (17 байтів)
struct btrfs_key {
    __le64 objectid;           // ID об'єкта (номер іноди, ID субтому, адреса екстента)
    u8 type;                   // Тип запису (INODE_ITEM, EXTENT_DATA, DIR_ITEM)
    __le64 offset;             // Зсув усередині об'єкта (байтовий зсув, хеш тощо)
} __attribute__ ((packed));

// Заголовок елемента всередині листка (рівень level == 0) — 25 байтів
struct btrfs_item {
    struct btrfs_key key;      // Повний ключ елемента
    __le32 offset;             // Зсув до тіла даних від кінця листка
    __le32 size;               // Розмір тіла даних у байтах
} __attribute__ ((packed));

// Запис у внутрішньому вузлі (рівень level > 0) — 33 байти
struct btrfs_key_ptr {
    struct btrfs_key key;      // Найменший ключ у дочірньому вузлі
    __le64 blockptr;           // Логічна адреса дочірнього вузла на диску
    __le64 generation;         // Generation дочірнього вузла (для CoW перевірки)
} __attribute__ ((packed));

// Опис метаданих іноди файлу в листку (INODE_ITEM, 160 байтів)
struct btrfs_inode_item {
    __le64 generation;         // Транзакція створення або останньої модифікації
    __le64 transid;            // ID транзакції модифікації
    __le64 size;               // Розмір файлу в байтах
    __le64 nbytes;             // Фактично зайнятий обсяг дискового простору
    __le64 block_group;        // Резервне поле
    __le32 nlink;              // Кількість жорстких посилань
    __le32 uid;                // ID власника (User ID)
    __le32 gid;                // ID групи (Group ID)
    __le32 mode;               // Права доступу та тип файлу POSIX
    __le64 rdev;               // Номер пристрою (якщо файл пристрою)
    __le64 flags;              // Прапорування іноди (ROCOMPRESS, NODATATRO, IMMUTABLE)
    __le64 sequence;           // Лічильник модифікацій для NFS
    __le64 reserved[4];
    struct btrfs_timespec atime; // Час останнього доступу
    struct btrfs_timespec mtime; // Час останньої модифікації вмісту
    struct btrfs_timespec ctime; // Час останньої зміни метаданих
    struct btrfs_timespec otime; // Час створення файлу (btime)
} __attribute__ ((packed));

// Опис дискового екстента вмісту файлу (EXTENT_DATA)
struct btrfs_file_extent_item {
    __le64 generation;         // Транзакція запису екстента
    __le64 ram_bytes;          // Розмір екстента після розпакування у RAM
    u8 compression;            // Алгоритм стиснення (0=NONE, 1=ZLIB, 2=LZO, 3=ZSTD)
    u8 encryption;             // Шифрування (0=NONE)
    __le16 compression_type;
    u8 type;                   // Тип екстента (0=INLINE, 1=REGULAR, 2=PREALLOC)
    __le64 disk_bytenr;        // Фізична логічна адреса екстента на диску
    __le64 disk_num_bytes;     // Розмір стисненого екстента на диску
    __le64 offset;             // Зсув усередині дискового екстента
    __le64 num_bytes;          // Довжина ділянки файлу, що покривається цим екстентом
} __attribute__ ((packed));
```

### Прапорці метаданих іноди (`btrfs_inode_item.flags`)

Поле `flags` у структурі `btrfs_inode_item` керує поведінкою підсистем файлової системи на рівні конкретного файлу:

- **`BTRFS_INODE_NODATATRO` (`1`):** Вимикає механізм Copy-on-Write для блоків цього файлу. Запис виконується безпосередньо "на місці" (in-place modification). Застосовується для дискових образів віртуальних машин та баз даних для усунення фрагментації.
- **`BTRFS_INODE_NODATASUM` (`2`):** Вимикає обчислення та перевірку контрольних сум даних у `CSUM_TREE` для даного файлу.
- **`BTRFS_INODE_READONLY` (`4`):** Встановлює прапор лише для читання на рівні метаданих Btrfs.
- **`BTRFS_INODE_COMPRESS` (`8`):** Примусово вмикає стиснення вмісту файлу алгоритмами ZSTD, LZO або ZLIB.
- **`BTRFS_INODE_SYNC` (`32`):** Кожен запис у цей файл обробляється за правилами синхронного запису `O_SYNC`.

## Інтерфейси інспекції метаданих через `ioctl` та sysfs

Для інспекції дерев Btrfs із простору користувача ядро Linux надає спеціалізований виклик `ioctl(BTRFS_IOC_TREE_SEARCH)`. 

Цей виклик дозволяє непривілейованим або адміністративним програмам виконувати прямолінійний пошук ключів у будь-якому дереві Btrfs без монтування сирого дискового пристрою.

```c
#include <linux/btrfs.h>

// Параметри запиту до ioctl(BTRFS_IOC_TREE_SEARCH)
struct btrfs_ioctl_search_args {
    struct btrfs_ioctl_search_key key; // Діапазон пошуку ключів
    u64 buf_size;                       // Розмір наданого буфера
    u8 buf[];                           // Повернуті заголовки та дані
};

struct btrfs_ioctl_search_key {
    u64 tree_id;       // ID дерева (5 для FS_TREE, 1 для ROOT_TREE, 2 для EXTENT_TREE)

    // Мінімальні межі пошукового діапазону
    u64 min_objectid;
    u64 max_objectid;
    u64 min_offset;
    u64 max_offset;
    u32 min_type;
    u32 max_type;
    u32 min_transid;
    u32 max_transid;

    u32 nr_items;      // Повернута кількість знайдених елементів
};
```

Окрім `ioctl`, ядро експортує статусні параметри дерев через файлову систему `/sys/fs/btrfs/`:

- `/sys/fs/btrfs/<UUID>/allocation/data/bytes_used` — загальний обсяг даних у байтах.
- `/sys/fs/btrfs/<UUID>/allocation/metadata/bytes_used` — обсяг метаданих усередині дерев Btrfs.
- `/sys/fs/btrfs/<UUID>/nodesize` — розмір вузла/листка B-дерева (зазвичай `16384` байти).
- `/sys/fs/btrfs/<UUID>/sectorsize` — розмір сектора даних (зазвичай `4096` байтів).

## Простеження та діагностика через утиліти `btrfs-progs`

Утиліта `btrfs inspect-internal` є основним інструментом адміністратора для аналізу вмісту дискових дерев без втручання в роботу ядра.

### Основні режими роботи `btrfs inspect-internal`

- **`btrfs inspect-internal dump-tree <device>`:** Виводить повне текстове дерево метаданих Btrfs. Може фільтруватися прапором `-t <tree_id>` для виводу лише конкретного дерева (наприклад, `-t 2` для `EXTENT_TREE`).
- **`btrfs inspect-internal inode-resolve <ino> <path>`:** Повертає повний шлях до файлу за його числовим ідентифікатором іноди `<ino>`, виконуючи обхід записів `INODE_REF` у `FS_TREE`.
- **`btrfs inspect-internal logical-resolve <bytenr> <path>`:** Здійснює зворотну трансляцію логічної дискової адреси `<bytenr>` у списки файлів та субтомів, які посилаються на цей дисковий екстент.

Завдяки суворій системі типів ключів та бінарній укомплектованості структур, підсистеми ядра Linux можуть виконувати обробку метаданих Btrfs із мінімальними накладними витратами процесорного часу.
