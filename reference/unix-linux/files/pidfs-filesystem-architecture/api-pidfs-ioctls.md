# 📋 Довідник ioctl-інтерфейсів та структур pidfs

У цьому довіднику зібрано повну технічну специфікацію системних викликів `ioctl` над дескрипторами `pidfd`, контракт файлової системи `pidfs`, структуру `struct pidfd_info` та коди помилок у ядрі Linux (версії 6.9–6.11+).

## Заголовні файли та керувальні константи

Для використання `ioctl`-операцій `pidfs` у програмах мовами C та C++ потрібні системні заголовки ядра та стандартної бібліотеки. Магічний байт команд `pidfs` визначено в ядрі як `PIDFS_IOCTL_MAGIC 0xFF`. При роботі з новими версіями ядра додатково включають заголовки `sys/ioctl.h` та `linux/pidfs.h`. Якщо системні заголовки у системі застарілі, макроси операцій визначають у коді програми за стандартними правилами розрахунку команд `_IO` та `_IOWR`.

:::tabs
```c
#include <sys/ioctl.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <linux/pidfs.h> /* додано в Linux 6.9 */
```
```cpp
#include <sys/ioctl.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <linux/pidfs.h> // додано в Linux 6.9
#include <cstdint>
```
:::

## Команди отримання дескрипторів просторів імен

Набір викликів `PIDFD_GET_*_NAMESPACE` дозволяє отримати новий файловий дескриптор відповідного простору імен (англ. *namespace*) цільового процесу безпосередньо з його `pidfd`, повністю оминаючи Віртуальну файлову систему `/proc`.

Кожен такий системний виклик перевіряє права викликача. Для витягування просторів імен процесу, який належить іншому користувачеві або іншому простору користувачів (англ. *User Namespace*), викликач повинен мати привілей `CAP_SYS_PTRACE` у цільовому просторі користувачів. Якщо процес-ціль уже завершився й перебуває в стані зомбі або очищений, виклик повертає помилку `ESRCH`.

Усі команди цієї групи приймають третім аргументом `0` і повертають новий файловий дескриптор при успіху.

| Команда ioctl | Код макросу | Версія ядра | Опис |
| :--- | :--- | :--- | :--- |
| `PIDFD_GET_CGROUP_NAMESPACE` | `_IO(0xFF, 1)` | Linux 6.9 | Повертає дескриптор Cgroup Namespace процесу |
| `PIDFD_GET_IPC_NAMESPACE` | `_IO(0xFF, 2)` | Linux 6.9 | Повертає дескриптор IPC Namespace (міжпроцесна взаємодія) |
| `PIDFD_GET_MNT_NAMESPACE` | `_IO(0xFF, 3)` | Linux 6.9 | Повертає дескриптор Mount Namespace (точки монтування) |
| `PIDFD_GET_NET_NAMESPACE` | `_IO(0xFF, 4)` | Linux 6.9 | Повертає дескриптор Network Namespace (мережеві стек і сокети) |
| `PIDFD_GET_PID_NAMESPACE` | `_IO(0xFF, 5)` | Linux 6.9 | Повертає дескриптор PID Namespace (ієрархія процесів) |
| `PIDFD_GET_PID_FOR_CHILDREN_NAMESPACE` | `_IO(0xFF, 6)` | Linux 6.9 | PID Namespace, який дістануть майбутні діти процесу |
| `PIDFD_GET_TIME_NAMESPACE` | `_IO(0xFF, 7)` | Linux 6.9 | Повертає дескриптор Time Namespace (системні таймери) |
| `PIDFD_GET_TIME_FOR_CHILDREN_NAMESPACE` | `_IO(0xFF, 8)` | Linux 6.9 | Time Namespace, який дістануть майбутні діти процесу |
| `PIDFD_GET_USER_NAMESPACE` | `_IO(0xFF, 9)` | Linux 6.9 | Повертає дескриптор User Namespace (користувачі й мапування UID) |
| `PIDFD_GET_UTS_NAMESPACE` | `_IO(0xFF, 10)` | Linux 6.9 | Повертає дескриптор UTS Namespace (вузол і доменне ім'я) |

Отриманий дескриптор простору імен є звичайним файловим дескриптором псевдофайлової системи `nsfs`. Його можна передавати у системний виклик `setns(2)` для входження в простір імен або використовувати для моніторингу конфігурації. Після завершення роботи з дескриптором програма зобов'язана закрити його через `close(fd)`.

## Отримання метаданих процесу: PIDFD_GET_INFO

З версії Linux 6.11 у ядрі впроваджено команду `PIDFD_GET_INFO`, яка дозволяє витягти бінарні метадані процесу за один атомарний виклик без виділення текстових буферів і без парсингу файлів у `/proc/<pid>/status`.

Традиційний підхід із читанням `/proc/<pid>/status` вимагав формування текстового рядка ядром, виділення сторінки пам'яті, парсингу чисел та обробки помилок форматування. Команда `PIDFD_GET_INFO` працює напряму з внутрішніми структурами ядра й заповнює передану структуру `struct pidfd_info` за один системний виклик, без проміжних текстових буферів.

```c
#define PIDFD_GET_INFO _IOWR(PIDFS_IOCTL_MAGIC, 11, struct pidfd_info)
```

### Структура struct pidfd_info

:::tabs
```c
struct pidfd_info {
    __u64 mask;         /* Маска запитаних та заповнених полів */
    __u64 cgroupid;     /* 64-бітний унікальний ID cgroup v2 */
    __u32 pid;          /* PID процесу у просторі імен викликача */
    __u32 tgid;         /* TGID (ID групи потоків / лідер процесу) */
    __u32 ppid;         /* PPID (PID батьківського процесу) */
    __u32 ruid;         /* Реальний UID */
    __u32 rgid;         /* Реальний GID */
    __u32 euid;         /* Ефективний UID процесу */
    __u32 egid;         /* Ефективний GID процесу */
    __u32 suid;         /* Збережений UID */
    __u32 sgid;         /* Збережений GID */
    __u32 fsuid;        /* UID для доступу до файлів */
    __u32 fsgid;        /* GID для доступу до файлів */
    __s32 exit_code;    /* Код завершення (біт PIDFD_INFO_EXIT, Linux 6.13+) */
};
```
```cpp
struct pidfd_info {
    std::uint64_t mask;      // Маска запитаних та заповнених полів
    std::uint64_t cgroupid;  // 64-бітний унікальний ID cgroup v2
    std::uint32_t pid;       // PID процесу у просторі імен викликача
    std::uint32_t tgid;      // TGID (ID групи потоків / лідер процесу)
    std::uint32_t ppid;      // PPID (PID батьківського процесу)
    std::uint32_t ruid;      // Реальний UID
    std::uint32_t rgid;      // Реальний GID
    std::uint32_t euid;      // Ефективний UID процесу
    std::uint32_t egid;      // Ефективний GID процесу
    std::uint32_t suid;      // Збережений UID
    std::uint32_t sgid;      // Збережений GID
    std::uint32_t fsuid;     // UID для доступу до файлів
    std::uint32_t fsgid;     // GID для доступу до файлів
    std::int32_t  exit_code; // Код завершення (біт PIDFD_INFO_EXIT, Linux 6.13+)
};
```
:::

### Прапорці маски (mask)

Перед викликом `ioctl` програма заповнює поле `mask` бітовою маскою потрібних полів. По поверненню ядро записує у `mask` ті біти, які воно успішно підтримало й заповнило. Це забезпечує зворотну сумісність: якщо новіша програма працює на старішому ядрі, вона може перевірити, які саме поля ядро змогло надати.

- `PIDFD_INFO_PID` (`0x01`): Запитує `pid`, `tgid` і `ppid` у контексті поточного PID namespace викликача.
- `PIDFD_INFO_CREDS` (`0x02`): Запитує повний набір облікових даних — `ruid`/`rgid`, `euid`/`egid`, `suid`/`sgid`, `fsuid`/`fsgid`. Ядро заповнює ці поля завжди, навіть коли біт не запитано.
- `PIDFD_INFO_CGROUPID` (`0x04`): Запитує унікальний 64-бітний ідентифікатор контрольної групи cgroup v2.
- `PIDFD_INFO_EXIT` (`0x08`, Linux 6.13+): Запитує код завершення (`exit_code`) процесу, який уже помер.

## Порівняння тотожності процесів через statx

Файлова система `pidfs` реалізує стандартний VFS-контракт `statx(2)` над дескрипторами `pidfd`. При виконанні системного виклику `statx` з прапорцем `AT_EMPTY_PATH` ядро звертається до inode у внутрішньому монтуванні `pidfs_mnt`.

:::tabs
```c
struct statx stx;
int res = statx(pidfd, "", AT_EMPTY_PATH, STATX_INO, &stx);
```
```cpp
struct statx stx{};
int res = ::statx(pidfd, "", AT_EMPTY_PATH, STATX_INO, &stx);
```
:::

### Ключові поля результату statx

- `stx_dev_major`, `stx_dev_minor`: Унікальний анонімний номер пристрою псевдофайлової системи `pidfs`, який виділяється ядром під час ініціалізації суперблока `pidfs`.
- `stx_ino`: 64-бітний унікальний номер inode у `pidfs`, закріплений за конкретним екземпляром `struct pid`.
- `stx_mask`: Гарантовано містить біт `STATX_INO`.

### Предикат тотожності

Два дескриптори `fd1` та `fd2` посилаються на один і той самий об'єкт ядра `struct pid` тоді й лише тоді, коли збігаються номери пристрою та номера inode:

```
(stx1.stx_dev_major == stx2.stx_dev_major) ∧
(stx1.stx_dev_minor == stx2.stx_dev_minor) ∧
(stx1.stx_ino == stx2.stx_ino)
```

Ця перевірка є абсолютно стійкою до перевикористання чисельних PID, зміни просторів імен чи завершення процесу. Навіть якщо процес помер, його inode в `pidfs` утримує свою унікальність, доки відкритий хоча б один `pidfd`.

## Таблиця кодів помилок та виняткових ситуацій

При виконанні системних викликів `ioctl` над дескрипторами `pidfs` ядро може повертати стандартні коди помилок через систему `errno`.

| Код помилки | Контекст виклику | Причина виникнення |
| :--- | :--- | :--- |
| `ESRCH` | `ioctl(pidfd, PIDFD_GET_*)` | Процес вже завершився (зомбі прибрано), хоча сам `pidfd` лишається відкритим |
| `EBADF` | будь-який виклик | Передано недійсний дескриптор або файловий дескриптор не є `pidfd` |
| `EPERM` / `EACCES` | `PIDFD_GET_*_NAMESPACE` | Викликач не має прав трасування (`CAP_SYS_PTRACE`) щодо цільового процесу |
| `ENOTTY` | `ioctl` | Ядро не підтримує дану команду `ioctl` (версія ядра < 6.9) |
| `EOPNOTSUPP` | `PIDFD_GET_TIME_NAMESPACE` | Простір імен даного типу не увімкнений у конфігурації ядра |
| `EINVAL` | `PIDFD_GET_INFO` | Недійсний розмір структури або передано некоректні зарезервовані прапорці |
