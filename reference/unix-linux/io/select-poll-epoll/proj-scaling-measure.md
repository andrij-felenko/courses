# ⚙️ Виміряти ціну очікування: сто тисяч дескрипторів і один активний

Твердження «`epoll` не залежить від числа з'єднань, а `select` і `poll` залежать» перевіряється не міркуванням, а програмою на півтори сотні рядків: тримаємо N пар сокетів, робимо активною рівно одну й міряємо тривалість одного виклику очікування — при N від сотні до ста тисяч.

## Що саме міряємо

Ціна очікування складається з двох доданків. Перший — ціна **запитати**: скільки роботи метод виконує, перш ніж узагалі дізнатися, чи є події. Другий — ціна **віддати**: скільки припадає на кожну знайдену подію. Другий доданок в усіх трьох способів однакового порядку — подію треба скопіювати користувачеві. І якщо в наборі активна половина дескрипторів, обидва доданки ростуть разом, другий заступає перший, і вимір чесно показує «різниці майже немає». Саме так гинуть недбалі порівняння.

Тому в досліді активний рівно один дескриптор, скільки б їх не лежало в наборі. Ціна віддати стає сталою, і будь-яка залежність від N — це чистий перший доданок. Умова не штучна: у справжній службі мовчить переважна більшість з'єднань, і саме ця пропорція робить питання вартим виміру.

Друге рішення: байт у сокет ми штовхаємо **до** того, як запускаємо годинник. Виклик очікування застає подію вже готовою й повертається негайно, нікого не приспавши. Отже, ми міряємо роботу самого методу — зібрати набір, перенести його через межу, обійти, доповісти, — а не затримку пробудження. Затримка пробудження — величина іншої природи: у ній сидять планувальник, міжпроцесорне переривання й перетягування рядків кешу між ядрами, тобто десятки мікросекунд шуму, у якому потрібний ефект потонув би без сліду.

## Звідки взяти сто тисяч дескрипторів

`socketpair` віддає два дескриптори за раз ([сокети домену Unix](book:unix-linux/unix-domain-sockets) — пара з'єднаних кінців усередині однієї машини, без мережі й без портів), тож сто тисяч пар — це двісті тисяч відкритих дескрипторів плюс кілька службових. Типова м'яка межа `RLIMIT_NOFILE` — 1024: systemd від версії 240 роздає службам саме `1024:524288`, залишивши м'яку межу низькою навмисно, щоб не поламати програми, які досі викликають `select`. Тверда межа при цьому щедра, а підняти м'яку до твердої процес може сам, без жодних привілеїв ([межі ресурсів](book:unix-linux/resource-limits) — пара «м'яка/тверда» на кожен вид ресурсу; тверду вгору рухає лише `CAP_SYS_RESOURCE`). Стелею для твердої межі служить `fs.nr_open`, типово 1048576.

`select` до цих чисел не дійде ніколи. Його маска `fd_set` — це масив із `FD_SETSIZE` = 1024 бітів, і дескриптор із номером 1024 туди не влазить: `FD_SET` мовчки пише повз масив, псуючи сусідню пам'ять. Тому в програмі стоїть перевірка `maxfd < FD_SETSIZE` — не з обережності, а тому що без неї дослід перетворюється на випадкове псування власного стеку. А оскільки кожна пара з'їдає два номери, практична стеля тут — близько 510 пар, а не 1024.

## Програма

Мова тут не обирається: `fd_set`, `struct epoll_event` і `setrlimit` — це двійковий інтерфейс ядра, і будь-яка обгортка додала б до виміру власну ціну.

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <errno.h>
#include <time.h>
#include <sched.h>
#include <poll.h>
#include <sys/select.h>
#include <sys/epoll.h>
#include <sys/resource.h>
#include <sys/socket.h>

enum { SELECT, POLL, EPOLL };

static int *rfd, *wfd;              /* кінці пар: за яким чекаємо / у який штовхаємо */
static struct pollfd *pfds;
static int epfd = -1, maxfd = 0;

static long long now_ns(void) {     /* монотонний годинник: не стрибає від NTP */
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (long long)ts.tv_sec * 1000000000LL + ts.tv_nsec;
}

static void raise_nofile(rlim_t want) {
    struct rlimit rl;
    if (getrlimit(RLIMIT_NOFILE, &rl) != 0) { perror("getrlimit"); exit(1); }
    if (rl.rlim_cur >= want) return;
    if (want > rl.rlim_max) {
        fprintf(stderr, "тверда межа %llu < потрібних %llu — підніміть fs.nr_open\n",
                (unsigned long long)rl.rlim_max, (unsigned long long)want);
        want = rl.rlim_max;         /* беремо все, що дозволено без привілеїв */
    }
    rl.rlim_cur = want;
    if (setrlimit(RLIMIT_NOFILE, &rl) != 0) { perror("setrlimit"); exit(1); }
}

static void make_pairs(int n) {
    rfd  = malloc(n * sizeof *rfd);
    wfd  = malloc(n * sizeof *wfd);
    pfds = malloc(n * sizeof *pfds);
    epfd = epoll_create1(0);
    maxfd = epfd;
    for (int i = 0; i < n; i++) {
        int sv[2];
        /* SOCK_NONBLOCK одразу в socketpair: без O_NONBLOCK дослід зависне */
        if (socketpair(AF_UNIX, SOCK_STREAM | SOCK_NONBLOCK, 0, sv) != 0) {
            perror("socketpair");   /* найчастіше EMFILE: не підняли межу */
            exit(1);
        }
        rfd[i] = sv[0];  wfd[i] = sv[1];
        if (sv[0] > maxfd) maxfd = sv[0];
        if (sv[1] > maxfd) maxfd = sv[1];
        pfds[i].fd = sv[0];  pfds[i].events = POLLIN;
        struct epoll_event ev = { .events = EPOLLIN, .data = { .u32 = i } };
        epoll_ctl(epfd, EPOLL_CTL_ADD, sv[0], &ev);
    }
}

static long long bench(int method, int n, int iters) {
    fd_set master, ready;
    struct epoll_event out[8];
    long long total = 0;
    char b;

    if (method == SELECT) {         /* маску будуємо раз, копіюємо щоразу */
        FD_ZERO(&master);
        for (int i = 0; i < n; i++) FD_SET(rfd[i], &master);
    }

    for (int k = 0; k < iters; k++) {
        int hot = k % n;            /* активний по черзі, а не той самий */
        if (write(wfd[hot], "x", 1) != 1) { perror("write"); exit(1); }

        long long t0 = now_ns();
        int got;
        switch (method) {
        case SELECT:
            ready = master;         /* ядро псує маску на місці — копія обов'язкова */
            got = select(maxfd + 1, &ready, NULL, NULL, NULL);
            break;
        case POLL:
            got = poll(pfds, n, -1);        /* revents ядро перезаписує саме */
            break;
        default:
            got = epoll_wait(epfd, out, 8, -1);
        }
        long long t1 = now_ns();
        if (got != 1) { fprintf(stderr, "чекали рівно одну подію, дістали %d\n", got); exit(1); }
        total += t1 - t0;

        while (read(rfd[hot], &b, 1) > 0) { }   /* до EAGAIN, інакше подія лишиться */
    }
    return total / iters;
}

static int cmp_ll(const void *a, const void *b) {
    long long x = *(const long long *)a, y = *(const long long *)b;
    return (x > y) - (x < y);
}

static long long median(int method, int n, int iters, int runs) {
    long long r[9];
    if (runs > 9) runs = 9;
    for (int i = 0; i < runs; i++) r[i] = bench(method, n, iters);
    qsort(r, runs, sizeof r[0], cmp_ll);
    return r[runs / 2];
}

int main(void) {
    static const int sizes[] = { 100, 500, 1000, 10000, 100000 };
    cpu_set_t cpus;

    raise_nofile(2 * 100000 + 64);          /* дві половини пари плюс запас */
    CPU_ZERO(&cpus);  CPU_SET(0, &cpus);
    sched_setaffinity(0, sizeof cpus, &cpus);   /* без міграцій між ядрами */

    printf("      N    select      poll     epoll   (мкс на одне очікування)\n");
    for (size_t s = 0; s < sizeof sizes / sizeof *sizes; s++) {
        int n = sizes[s], iters = n > 10000 ? 2000 : 20000;
        char sel[16];

        make_pairs(n);
        bench(POLL, n, 1000);               /* прогрів: сторінки, кеші, частота */

        if (maxfd < FD_SETSIZE)
            snprintf(sel, sizeof sel, "%.2f", median(SELECT, n, iters, 7) / 1000.0);
        else
            snprintf(sel, sizeof sel, "%s", "--");

        printf("%7d  %8s  %8.2f  %8.2f\n", n, sel,
               median(POLL,  n, iters, 7) / 1000.0,
               median(EPOLL, n, iters, 7) / 1000.0);
        fflush(stdout);

        for (int i = 0; i < n; i++) { close(rfd[i]); close(wfd[i]); }
        close(epfd);  free(rfd);  free(wfd);  free(pfds);
    }
    return 0;
}
```

Збирати — `cc -O2 -o waitbench waitbench.c`; ніяких бібліотек, ніяких прав.

## Що виходить

**Вивід на пересічній машині x86-64 із ядром 6.x. Абсолютні числа у вас будуть інші — важить форма.**

```
      N    select      poll     epoll   (мкс на одне очікування)
    100      3.10      2.61      0.90
    500     12.42     11.03      0.91
   1000        --     21.54      0.92
  10000        --    215.30      0.95
 100000        --   2181.40      1.02
```

![Три криві в подвійних логарифмічних осях: select і poll ростуть прямими з нахилом 1, epoll лишається горизонтальним](/reference/unix-linux/io/select-poll-epoll/img/scaling-shape.svg)

*Форма результату: дві прямі й одна горизонталь*

Читається це так. Стовпчик `poll` ділиться на N майже точно: 22 наносекунди на дескриптор, плюс близько 0.4 мікросекунди сталої ціни переходу в ядро ([механіка системного виклику](book:unix-linux/syscall-mechanics) — той самий фіксований податок, що дає ненульовий початок прямої). Це і є пряма: удесятеро довший набір — удесятеро довший виклик. `select` іде поруч, трохи дорожче за рахунок трьох масок замість однієї, і просто обривається на стелі. А `epoll` за тисячократного зростання набору дорожчає на тринадцять відсотків — це вже не залежність від N, а слід того, що велике дерево гірше лежить у кеші.

У подвійних логарифмічних осях різниця видно без арифметики: лінійна залежність стає прямою з нахилом одиниця, стала — горизонталлю. Дві прямі й одна горизонталь — це не «на скільки відсотків швидше», а різні закони росту, і жодне вдосконалення `poll` цього не змінить.

> 🔧 **Навіщо це.** Числа перетворюють гасло на проєктне обмеження. Хай службі треба обертати цикл подій десять тисяч разів на секунду при десяти тисячах з'єднань:
> ```
> poll:   10 000 обертів/с · 215 мкс = 2.15 с процесорного часу на секунду
> epoll:  10 000 обертів/с ·   1 мкс = 0.01 с процесорного часу на секунду
> ```
> Перший варіант не влазить не те що в ядро процесора — йому треба понад два ядра, щоб лише **питати**, ще до першого байта корисної роботи. Другий з'їдає один відсоток одного ядра.

## Пастки виміру

**Прогрів обов'язковий.** Перші виклики платять за помилки сторінок на щойно виділених масивах, за холодні кеші, за ще не створені структури ядра й за процесор, який не встиг підняти частоту. Тому в програмі перед кожним заміром іде тисяча відкинутих обертів; без неї малі N виглядають дорожчими за великі й уся картина перевертається ([мікробенчмаркінг](book:programming/microbenchmarking) — чому вимір без прогріву й повторів міряє що завгодно, крім потрібного).

**Кеш видно у стовпчику `poll`.** Масив `pollfd` на сто тисяч записів — це 800 кілобайтів, тобто на більшості машин уже поза кешем другого рівня; частина «22 наносекунд на дескриптор» — не робота ядра, а очікування пам'яті. Із тієї ж причини активним не можна робити щоразу один і той самий дескриптор: його структури залишаться в кеші першого рівня й дадуть красиві, але брехливі числа. Звідси `k % n` у циклі.

**`O_NONBLOCK` не бажаний, а обов'язковий.** Спорожнення сокета написане як «читати, доки не скінчиться», і на блокуючому дескрипторі другий `read` засне назавжди ([блокуючий і неблокуючий режим](book:unix-linux/blocking-and-nonblocking) — що саме повертає `EAGAIN` і чому це не помилка). Оскільки в очікування ми передали `-1` замість тайм-ауту, така помилка не впаде й не діагностується — програма просто мовчки повисне.

**Час виклику — не затримка.** Отримане число не можна називати затримкою відповіді службі: це фіксований податок на один оберт циклу. Реальна затримка додасть до нього пробудження задачі та власне обробник. Дві величини міряються різними дослідами, і плутанина між ними — найчастіша причина суперечок про «швидкість epoll».

**Одного прогону не буває.** Витіснення планувальником, переривання, чужий процес на тому ж ядрі — і один оберт із тисячі дасть викид у сотні мікросекунд, який середнє чесно розмаже по всьому виміру. Тому в програмі медіана семи прогонів, а не середнє, і прив'язка до одного ядра ([прив'язка до процесорів](book:unix-linux/cpu-affinity) — як процес просить планувальник не переносити його між ядрами). Якщо сусідні прогони розходяться більше ніж на кілька відсотків — машина зайнята, і міряти на ній немає сенсу.

**Реєстрацію ми не міряємо навмисно.** `epoll_ctl` для ста тисяч дескрипторів коштує помітних мілісекунд, але платиться один раз на з'єднання, тоді як очікування повторюється мільйони разів. Проте сказати це треба вголос: інакше порівняння виглядає підтасованим, а на короткоживучих з'єднаннях, де одна реєстрація припадає на кілька очікувань, висновок був би вже не таким однозначним.

І ще одне, дрібне, але вперте: годинник має бути `CLOCK_MONOTONIC`. Настінний час стрибає від синхронізації, і посеред довгого виміру ви дістанете від'ємний інтервал ([монотонний час проти настінного](book:programming/monotonic-vs-wall-time) — які саме годинники стрибають і чому тривалості міряють лише монотонним).
