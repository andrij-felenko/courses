# 📋 Інтерфейси очікування: сигнатури, прапорці, помилки

Це довідник виклик-за-викликом: точні сигнатури `select`, `poll` та `epoll` з їхніми сигнальними двійниками, повні таблиці прапорців подій із версією ядра, у якій кожен з'явився, коди помилок із поясненням, що кожен означає на практиці, і ліміти, у які впирається кожен інтерфейс. Усе за чинними man-сторінками Linux; де поведінка Linux розходиться зі стандартом, це позначено окремо.

## select і pselect

```c
#include <sys/select.h>

int select(int nfds, fd_set *readfds, fd_set *writefds,
           fd_set *exceptfds, struct timeval *timeout);

int pselect(int nfds, fd_set *readfds, fd_set *writefds,
            fd_set *exceptfds, const struct timespec *timeout,
            const sigset_t *sigmask);
```

`nfds` — це **не** кількість дескрипторів, а на одиницю більше за найбільший номер у трьох мапах разом. Будь-яку мапу можна передати `NULL`. `timeout` як `NULL` означає чекати без межі, заповнена нулями структура — повернутися негайно.

Мапу будують і читають чотирма макросами; жоден із них не системний виклик, усі працюють з пам'яттю програми.

| макрос | дія |
|---|---|
| `FD_ZERO(&set)` | спорожнити мапу — обов'язково перед кожним заповненням |
| `FD_SET(fd, &set)` | додати дескриптор |
| `FD_CLR(fd, &set)` | прибрати дескриптор |
| `FD_ISSET(fd, &set)` | перевірити після повернення, чи цей дескриптор готовий |

```c
struct timeval  { time_t tv_sec; suseconds_t tv_usec; };   /* мікросекунди */
struct timespec { time_t tv_sec; long        tv_nsec; };   /* наносекунди  */
```

`exceptfds` — найчастіше неправильно прочитана з трьох мап: вона повідомляє не про помилки, а про **виняткові умови**, тобто про позасмугові дані на TCP-сокеті та про зміну стану керування псевдотермінала в пакетному режимі. Помилка на дескрипторі проступає як готовність до читання.

Повертає кількість дескрипторів у трьох повернутих мапах **сумарно** — з'єднання, готове й на читання, і на запис, рахується двічі; `0` при вичерпанні таймауту; `-1` при помилці.

Дві відмінності `pselect` варті окремого рядка. Таймаут у ньому `const` і справді не змінюється, тоді як Linux-овий `select` переписує `struct timeval` на місці, лишаючи там недоспаний залишок, — більшість інших систем цього не роблять, тож переносний код заповнює структуру заново перед кожним викликом. І `sigmask` ставиться атомарно на час чекання, а при поверненні знімається; це закриває гонку «перевірили прапорець від обробника — сигнал прийшов саме тут — заснули назавжди» ([маска сигналів](topic:unix-linux/signal-mask-signalfd) — набір сигналів, доставку яких відкладено; підміна маски рівно на час сну і є вся суть сигнальних варіантів цих викликів).

| помилка | коли |
|---|---|
| `EBADF` | у котрійсь із мап дескриптор, який не відкрито |
| `EINTR` | сигнал спіймав обробник раніше, ніж настала подія ([EINTR і перезапуск](topic:unix-linux/eintr-and-restart) — виклик обривається без результату, і цикл мусить повторити його вручну) |
| `EINVAL` | `nfds` від'ємний або більший за `RLIMIT_NOFILE`; у таймауті недійсне значення |
| `ENOMEM` | не вистачило пам'яті ядра |

## poll і ppoll

```c
#include <poll.h>

int poll(struct pollfd *fds, nfds_t nfds, int timeout);   /* таймаут у мілісекундах */

int ppoll(struct pollfd *fds, nfds_t nfds,
          const struct timespec *tmo_p, const sigset_t *sigmask);

struct pollfd {
    int   fd;        /* дескриптор; від'ємне значення — запис пропустити */
    short events;    /* що просимо — заповнює програма */
    short revents;   /* що сталося — заповнює ядро     */
};
```

`nfds` — довжина масиву. `timeout` = `-1` чекати без межі, `0` повернутися негайно. Від'ємний `fd` — законний спосіб тимчасово вимкнути запис, не пересуваючи масив і не збиваючи індекси: ядро таку позицію не розглядає й кладе в її `revents` нуль.

Колонка «просимо» каже, чи має сенс ставити прапорець в `events`. Те, що ядро ставить само, воно ставить **завжди**, незалежно від запиту.

| прапорець | просимо | значення |
|---|---|---|
| `POLLIN` | так | є дані для читання |
| `POLLOUT` | так | запис зараз не заблокується |
| `POLLPRI` | так | виняткова умова: позасмугові дані TCP, зміна стану псевдотермінала |
| `POLLRDHUP` (2.6.17) | так | інший бік потокового сокета закрив з'єднання або хоча б свою половину на запис; потребує `_GNU_SOURCE` |
| `POLLERR` | ні, ядро само | помилка на об'єкті; на каналі — запис, коли читачів не лишилося |
| `POLLHUP` | ні, ядро само | інший бік відвалився зовсім; читати це не забороняє — у буфері ще може лежати непрочитане |
| `POLLNVAL` | ні, ядро само | у полі `fd` не дескриптор: номер не відкрито |
| `POLLRDNORM` / `POLLWRNORM` | так | у Linux те саме, що `POLLIN` / `POLLOUT` |
| `POLLRDBAND` / `POLLWRBAND` | так | пріоритетна смуга даних; у Linux майже не вживається |
| `POLLMSG` | — | у Linux не вживається |

Асиметрія трьох вихідних прапорців — головне, на чому тут ловляться. Набір, який просить самий лише `POLLIN`, усе одно отримає `POLLERR`, `POLLHUP` чи `POLLNVAL`, коли ті настануть, а обробник, що перевіряє `revents & POLLIN` і більше нічого, на розірваному з'єднанні крутитиметься вічно, не помічаючи причини.

Повертає кількість записів із ненульовим `revents`, `0` при таймауті, `-1` при помилці. Помилки — `EFAULT` (масив поза доступною пам'яттю), `EINTR`, `EINVAL` (`nfds` більший за `RLIMIT_NOFILE`; для `ppoll` — ще й від'ємний таймаут), `ENOMEM`.

`ppoll` відрізняється від `poll` так само, як `pselect` від `select`: наносекундний таймаут і маска сигналів на час сну. Тонкість: сам системний виклик Linux `tmo_p` **змінює**, але обгортка glibc це ховає, підставляючи власну копію, тож на рівні C поведінка виглядає стандартною.

## epoll: створення набору й керування ним

```c
#include <sys/epoll.h>

int epoll_create(int size);     /* size ігнорують з 2.6.8, але він мусить бути > 0 */
int epoll_create1(int flags);   /* 2.6.27; єдиний прапорець — EPOLL_CLOEXEC */

int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);

typedef union epoll_data {
    void    *ptr;
    int      fd;
    uint32_t u32;
    uint64_t u64;
} epoll_data_t;

struct epoll_event {
    uint32_t     events;   /* прапорці подій і режиму */
    epoll_data_t data;     /* вісім байтів, які ядро віддасть назад незміненими */
};
```

`op` — одне з трьох: `EPOLL_CTL_ADD`, `EPOLL_CTL_MOD`, `EPOLL_CTL_DEL`. Для `DEL` аргумент `event` може бути `NULL` (ядра до 2.6.9 вимагали ненульового вказівника, і переносний старий код передає туди порожню структуру).

| прапорець | з ядра | що робить |
|---|---|---|
| `EPOLLIN` | — | готовність до читання |
| `EPOLLOUT` | — | готовність до запису |
| `EPOLLPRI` | — | виняткова умова, як `POLLPRI` |
| `EPOLLRDHUP` | 2.6.17 | інший бік закрив з'єднання або свою половину на запис |
| `EPOLLERR` | — | ставить ядро само: просити не треба, вимкнути не можна |
| `EPOLLHUP` | — | те саме |
| `EPOLLET` | — | сповіщати за фронтом замість типового рівня |
| `EPOLLONESHOT` | 2.6.2 | віддати подію один раз і замовкнути, доки не переозброять через `EPOLL_CTL_MOD` |
| `EPOLLWAKEUP` | 3.5 | не давати системі заснути чи піти в сплячку, поки подія чекає або обробляється |
| `EPOLLEXCLUSIVE` | 4.5 | будити не всіх, хто чекає на цей дескриптор, а одного-кількох |

`EPOLLWAKEUP` діє лише за трьох умов разом: `EPOLLONESHOT` і `EPOLLET` зняті, а процес має право `CAP_BLOCK_SUSPEND` ([можливості процесу](topic:unix-linux/capabilities) — права суперкористувача, роздроблені на окремі дозволи). Без цього права прапорець **мовчки ігнорують**, тож надійна програма перевіряє наявність можливості сама. Подія рахується «в обробці» від повернення з `epoll_wait` до наступного `epoll_wait` на тому самому наборі, до закриття набору, до `EPOLL_CTL_DEL` або до знятого через `EPOLL_CTL_MOD` прапорця.

`EPOLLEXCLUSIVE` обставлено найщільніше. Його приймають тільки в `EPOLL_CTL_ADD`; `EPOLL_CTL_MOD` над парою, доданою з ним, дає `EINVAL`; спроба поставити його на дескриптор, який сам є набором `epoll`, теж дає `EINVAL`. Сусідити з ним дозволено `EPOLLIN`, `EPOLLOUT`, `EPOLLET` і `EPOLLWAKEUP` (плюс `EPOLLERR` і `EPOLLHUP`, які й так завжди є) — будь-що інше, зокрема `EPOLLONESHOT`, знову `EINVAL`. І гарантія в нього слабша, ніж здається з назви: ядро обіцяє не «рівно одного», а «не всіх».

| помилка `epoll_ctl` | коли |
|---|---|
| `EBADF` | `epfd` або `fd` не є відкритим дескриптором |
| `EEXIST` | `ADD` для того, що вже в наборі; ключ — пара «номер + [опис відкритого файлу](topic:unix-linux/open-file-description)», тому копія через `dup` під іншим номером додається як окремий запис |
| `ENOENT` | `MOD` або `DEL` для дескриптора, якого в наборі немає |
| `EINVAL` | `epfd` не є набором `epoll`; `fd` збігається з `epfd`; невідомий `op`; заборонена комбінація з `EPOLLEXCLUSIVE` |
| `EPERM` | об'єкт за `fd` не вміє бути неготовим, і `epoll` його не бере: звичайний файл, тека |
| `ELOOP` | додавання набору в набір дало б цикл або глибину вкладення понад 5 |
| `ENOSPC` | вичерпано `/proc/sys/fs/epoll/max_user_watches` для цього реального UID |
| `ENOMEM` | не вистачило пам'яті ядра |

## epoll: очікування

```c
int epoll_wait(int epfd, struct epoll_event *events,
               int maxevents, int timeout);

int epoll_pwait(int epfd, struct epoll_event *events,
                int maxevents, int timeout,
                const sigset_t *sigmask);                    /* 2.6.19 */

int epoll_pwait2(int epfd, struct epoll_event *events,
                 int maxevents, const struct timespec *timeout,
                 const sigset_t *sigmask);                   /* 5.11 */
```

`maxevents` мусить бути більший за нуль. `timeout` у мілісекундах, `-1` без межі, `0` негайне повернення; час міряють за годинником `CLOCK_MONOTONIC` і округлюють угору до зернистості системного годинника ([відлік часу в ядрі](topic:unix-linux/kernel-timekeeping) — чому монотонний годинник не смикається від переведення системного часу). Уся причина існування `epoll_pwait2` — наносекундна межа замість мілісекундної: `struct timespec` замість `int`. Історична пастка: до 2.6.37 таймаут, більший приблизно за `LONG_MAX / HZ` мілісекунд, тлумачили як `-1`, тобто «назавжди».

Повертає кількість готових записів, `0` при таймауті, `-1` при помилці. Помилки: `EBADF` (`epfd` не відкрито), `EFAULT` (у масив `events` не можна писати), `EINTR`, `EINVAL` (`epfd` не є набором `epoll` або `maxevents` не додатний).

## Ліміти

| межа | значення | що обмежує |
|---|---|---|
| `FD_SETSIZE` | 1024 у glibc | найбільший номер дескриптора, який влазить у `fd_set`; це частина двійкового інтерфейсу, перевизначенню не підлягає, а `FD_SET` за межею псує чужу пам'ять мовчки |
| `RLIMIT_NOFILE` | `ulimit -n`, видно в `/proc/<pid>/limits` | стеля номерів дескрипторів процесу; водночас поріг для `nfds` у `poll` — більше дає `EINVAL` ([ліміти ресурсів](topic:unix-linux/resource-limits) — м'яка й жорстка межі, підняти м'яку до жорсткої може сам процес) |
| `/proc/sys/fs/epoll/max_user_watches` | типово ≈4 % доступної низької пам'яті, поділені на вартість запису | скільки дескрипторів один реальний UID тримає зареєстрованими в усіх своїх наборах разом; запис коштує ≈90 байтів на 32-бітному ядрі й ≈160 на 64-бітному |
| глибина вкладення наборів | 5 | скільки разів набір може лежати в наборі; глибше або по колу — `ELOOP` |
| `/proc/sys/fs/epoll/max_user_instances` | лише до 2.6.29 | скільки наборів на UID; вичерпання давало `EMFILE` з `epoll_create` |

## Найкоротший робочий цикл

```c
#include <sys/epoll.h>
#include <errno.h>
#include <stdio.h>

int ep = epoll_create1(EPOLL_CLOEXEC);
if (ep < 0) { perror("epoll_create1"); return 1; }

struct epoll_event ev = { .events = EPOLLIN | EPOLLRDHUP, .data.fd = fd };
if (epoll_ctl(ep, EPOLL_CTL_ADD, fd, &ev) < 0) { perror("epoll_ctl"); return 1; }

struct epoll_event out[64];
for (;;) {
    int n = epoll_wait(ep, out, 64, -1);
    if (n < 0) {
        if (errno == EINTR) continue;      /* сигнал, не помилка */
        perror("epoll_wait"); break;
    }
    for (int i = 0; i < n; i++) {
        uint32_t e = out[i].events;
        if (e & (EPOLLERR | EPOLLHUP)) { drop(out[i].data.fd); continue; }
        if (e & EPOLLIN)  on_readable(out[i].data.fd);   /* дочитати залишок */
        if (e & EPOLLOUT) on_writable(out[i].data.fd);
        if (e & EPOLLRDHUP) drop(out[i].data.fd);        /* аж після того, як залишок дочитано */
    }
}
```

Три речі в цих рядках не косметичні. `EPOLL_CLOEXEC` ставлять одразу, бо між `epoll_create` і `fcntl` уміщується чужий `fork`, і набір потече в дитину. `EPOLLERR` і `EPOLLHUP` перевіряють **перед** `EPOLLIN`, інакше розірване з'єднання крутитиметься в циклі без поступу, а от `EPOLLRDHUP` — навпаки, після читання: інший бік закрив свою половину, але в буфері прийому ще може лежати непрочитане. І `EINTR` не є помилкою й не має права виводити з циклу.
