# ⚙️ Правильні обгортки навколо перерваних викликів

Ця вставка пояснює ⚙️ правильні обгортки навколо перерваних викликів та дозволяє зрозуміти її детальніше. Це чотири шматки робочого C-коду, які закривають `EINTR` у справжній програмі, і — що важливіше за самі шматки — спосіб переконатися, що вони працюють. Без штучного потоку сигналів гілка обробки переривання роками лишається непройденою й уперше виконується в бою, коли адміністратор натиснув `Ctrl+Z`.

## Одна петля на два випадки

Виклик перервали, чи він просто віддав менше, ніж просили, — для того, хто передає буфер цілком, це та сама подія: робота не закінчена, потрібен ще оберт. Різниця рівно в одному — чи рушить покажчик перед наступним обертом.

```c
#include <errno.h>
#include <unistd.h>

/* Читає len байтів. Менше — тільки якщо дані скінчилися. −1 — справжня помилка. */
ssize_t read_all(int fd, void *buf, size_t len) {
    char  *p    = buf;
    size_t done = 0;
    while (done < len) {
        ssize_t n = read(fd, p + done, len - done);
        if (n > 0)          { done += (size_t) n; continue; }  /* коротко — зсув */
        if (n == 0)         break;                             /* кінець даних   */
        if (errno == EINTR) continue;                          /* без зсуву      */
        return -1;
    }
    return (ssize_t) done;
}

ssize_t write_all(int fd, const void *buf, size_t len) {
    const char *p    = buf;
    size_t      done = 0;
    while (done < len) {
        ssize_t n = write(fd, p + done, len - done);
        if (n >= 0)         { done += (size_t) n; continue; }
        if (errno == EINTR) continue;
        return -1;
    }
    return (ssize_t) len;
}
```

Жодної гілки «а якщо і те, і те одразу» тут не потрібно: `n > 0` рухає покажчик, `EINTR` не рухає, обидва повертаються в ту саму умову циклу. Асиметрія між читанням і записом одна — у читання є кінець даних, у запису його немає, тож `write`, який повернув нуль на ненульовій довжині, означає зламану реалізацію, а не EOF.

Рядок `return -1` після часткової передачі варто прочитати уважно. Частина повідомлення в буфері вже лежить, але викликові вона не годиться: половина протокольного кадру — не дані. Якщо програмі все-таки треба знати, скільки саме встигло піти в мережу до розриву, це число віддають окремим вихідним параметром, а не вгадують із повернутого значення — інакше «дочитав до кінця» і «зламався на середині» стануть нерозрізненними.

Одне обмеження в цих обгорток є, і воно неочевидне: вони не бережуть тайм-аут сокета. Дескриптор із виставленим `SO_RCVTIMEO` перериванням не перезапускають — `recv` віддає `EINTR`, петля йде на новий оберт, і відлік двох обіцяних секунд починається з нуля. Під потоком сигналів обмеження просто зникає. Справжнє вичерпання часу, до речі, приходить не як `EINTR`, а як `EAGAIN`, і обгортка віддасть його викликові звичайним `-1` — розрізняти ці два `-1` доводиться тому, хто викликав ([блокуючий і неблокуючий режим](book:unix-linux/blocking-and-nonblocking) — чи чекає виклик на дані всередині ядра, чи одразу повертає `EAGAIN`). Найнеприємніше, що тайм-аут виставлено в іншому файлі, при створенні сокета, і в місці виклику його не видно взагалі.

## Цикл подій, який переживає переривання

```c
#include <sys/epoll.h>
#include <time.h>

static volatile sig_atomic_t want_stop;    /* виставляє обробник SIGTERM */
static volatile sig_atomic_t want_reload;  /* виставляє обробник SIGHUP  */

static long now_ms(void) {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000L + ts.tv_nsec / 1000000L;
}

int run_loop(int ep, int budget_ms) {
    struct epoll_event ev[64];
    long deadline = now_ms() + budget_ms;

    for (;;) {
        if (want_stop)   return 0;
        if (want_reload) { want_reload = 0; reload_config(); }

        long left = deadline - now_ms();
        if (left < 0) left = 0;

        int n = epoll_wait(ep, ev, 64, (int) left);
        if (n < 0) {
            if (errno == EINTR) continue;   /* не помилка: просто новий оберт */
            return -1;                      /* EBADF, EINVAL, EFAULT — поломка */
        }
        if (n == 0) { on_timeout(); deadline = now_ms() + budget_ms; continue; }
        for (int i = 0; i < n; i++) dispatch(&ev[i]);
    }
}
```

Стійким цей цикл роблять три речі. Перша: `EINTR` веде на новий оберт, а не назовні — це не поломка, а повідомлення «поки ти спав, щось сталося»; назовні виходять лише інші коди, і саме тому перевірка `n < 0` розділена, а не злита в одне `return -1`.

Друга: прапорці, виставлені обробником, перевіряються на початку **кожного** оберту, а не в гілці `EINTR`. Сигнал міг прийти й тоді, коли цикл роздавав уже отримані події, — тоді ніякого `EINTR` не станеться взагалі, а зупинитися програма мусить так само швидко.

Третя, найменш очевидна: залишок часу рахує сама програма. Після переривання `epoll_wait` почав би відлік тайм-ауту з нуля ([select, poll, epoll](book:unix-linux/select-poll-epoll) — виклики, що чекають на готовність багатьох дескрипторів одразу й повертають список готових), тож дедлайн доводиться тримати у власній змінній. Годинник для нього — обов'язково `CLOCK_MONOTONIC`: `CLOCK_REALTIME` стрибає при вирівнюванні часу, і один стрибок назад підвісив би цикл на стільки, на скільки годинник перевели.

## Тайм-аут на блокуючому виклику — і чому він ненадійний

Той самий `EINTR` можна вживати навмисно: якщо завести таймер і **не** ставити `SA_RESTART`, будь-який блокуючий виклик дістає тайм-аут задарма.

```c
#include <signal.h>

static volatile sig_atomic_t alarm_fired;

static void on_alarm(int sig) { (void) sig; alarm_fired = 1; }

ssize_t read_deadline(int fd, void *buf, size_t len, unsigned sec) {
    struct sigaction sa = {0};
    sa.sa_handler = on_alarm;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;                     /* саме тут: БЕЗ SA_RESTART */
    if (sigaction(SIGALRM, &sa, NULL) < 0) return -1;

    alarm_fired = 0;
    alarm(sec);
    ssize_t n     = read(fd, buf, len);  /* один виклик, БЕЗ петлі на EINTR */
    int     saved = errno;               /* alarm() нижче зіпсує errno */
    alarm(0);

    if (n < 0 && saved == EINTR && alarm_fired) { errno = ETIMEDOUT; return -1; }
    errno = saved;
    return n;
}
```

> 🔧 **Навіщо це.** Петлі на `EINTR` тут немає навмисно — і це рівно та петля, яку сюди інстинктивно дописують «щоб було як скрізь». Дописали — і тайм-аут зник: сигнал приходить, виклик повертається, петля заганяє його назад у сон, і так довіку. Один і той самий код у цьому файлі означає протилежні речі залежно від того, хто саме перервав виклик, — тому обгортку з петлею і обгортку з дедлайном тримають окремими функціями з різними іменами.

І тепер про те, чому прийом усе-таки ненадійний. Обробник може відпрацювати за мить **до** входу в `read`: прапорець він виставить, а переривати ще нема чого — виклик тільки починається й спокійно засинає без жодного обмеження.

*Проміжок між перевіркою прапорця й входом у ядро існує завжди; закрити його з простору користувача нічим.*

Побачити перегони можна не чекаючи щасливого збігу — досить вставити затримку саме туди, де процес міг би загубити процесор:

```c
    alarm(1);
    struct timespec gap = { .tv_sec = 2, .tv_nsec = 0 };
    while (nanosleep(&gap, &gap) < 0 && errno == EINTR) { }  /* доспить залишок */
    ssize_t n = read(fd, buf, len);   /* повисне назавжди: сигнал уже був */
```

Заразом цей рядок показує чесний спосіб добирати недоспаний час: `nanosleep` кладе залишок у свій другий аргумент, і той самий буфер подається на наступний оберт.

## Те саме без перегонів

Перегони зникають, коли сигнал перестає бути перериванням і стає байтами в дескрипторі. Заблокований сигнал не доставляють — отже, він нічого не перериває й чекає, доки програма сама його прочитає ([маска сигналів і signalfd](book:unix-linux/signal-mask-signalfd) — як заблокувати сигнали для всіх потоків і читати їх як звичайні структури з дескриптора).

```c
#include <sys/signalfd.h>

int signal_channel(void) {
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGTERM);
    sigaddset(&mask, SIGHUP);

    /* Блокувати ПЕРЕД створенням каналу: сигнал, що прийде між двома
       викликами, піде звичайним шляхом і таки перерве щось під рукою. */
    if (sigprocmask(SIG_BLOCK, &mask, NULL) < 0) return -1;
    return signalfd(-1, &mask, SFD_CLOEXEC | SFD_NONBLOCK);
}

static void drain_signals(int sfd) {          /* виклик із dispatch() на sfd */
    struct signalfd_siginfo si;
    while (read(sfd, &si, sizeof si) == (ssize_t) sizeof si) {
        if (si.ssi_signo == SIGTERM) want_stop = 1;
        if (si.ssi_signo == SIGHUP)  want_reload = 1;
    }
}
```

Заразом зникає й найпідступніше джерело `EINTR` у серверах. `SIGCHLD` від кожного завершеного нащадка приходить тоді, коли його ніхто не чекає, і вириває цикл із `epoll_wait`; заблокований і доданий у той самий канал, він стає звичайною подією в тому самому місці, де й дані, — а прибирання нащадків перестає бути окремою асинхронною історією.

`signalfd` є в Linux із 2.6.22 (2007), робоча підтримка в glibc — з 2.8; прапорці `SFD_CLOEXEC` і `SFD_NONBLOCK` з'явилися в 2.6.27 разом із виправленим викликом `signalfd4`. Там, де їх немає або де потрібна переносність, ту саму роль грає самоканал: обробник записує один байт у неблокуючий канал, а цикл подій читає його як звичайні дані.

```c
static int pipefd[2];                     /* обидва кінці — O_NONBLOCK */

static void on_signal(int sig) {
    int saved = errno;                    /* обробник мусить віддати errno цілим */
    unsigned char b = (unsigned char) sig;
    while (write(pipefd[1], &b, 1) < 0 && errno == EINTR) { }
    errno = saved;
}
```

Збереження `errno` тут не педантизм: обробник виконується посеред довільної точки програми, і `write` усередині нього залюбки затре `errno`, який перерваний виклик щойно поставив для перевірки на `EINTR` ([що можна робити в обробнику сигналу](book:unix-linux/async-signal-safety) — обробник перериває програму в будь-якому місці, тож звідти безпечно робити лише перелічені стандартом речі).

## Як зустріти EINTR навмисно

Написаний код нічого не варт, доки жоден тест не пройшов його гілками. Найдешевший спосіб — залити програму сигналами так, щоб `EINTR` траплявся на кожному виклику.

```c
static void on_tick(int sig) { (void) sig; }

void flood_signals(void) {                /* викликати на старті тестового прогону */
    struct sigaction sa = {0};
    sa.sa_handler = on_tick;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;                      /* без SA_RESTART — інакше нічого не видно */
    sigaction(SIGALRM, &sa, NULL);

    struct itimerval it = {
        .it_interval = { .tv_sec = 0, .tv_usec = 3000 },   /* кожні 3 мс */
        .it_value    = { .tv_sec = 0, .tv_usec = 3000 },
    };
    setitimer(ITIMER_REAL, &it, NULL);
}
```

Тут потрібен саме `ITIMER_REAL`: він рахує астрономічний час, а `ITIMER_VIRTUAL` — процесорний, якого сплячий процес не витрачає, тож із ним сигнал не прийшов би ніколи. Ціна — зайнятий `SIGALRM`, той самий, що й у `alarm()`. POSIX.1-2008 позначив `setitimer` застарілим, а POSIX.1-2024 прибрав зовсім; сучасна заміна — `timer_create` із довільним сигналом ([таймери процесу](book:unix-linux/process-timers) — інтервальні таймери й POSIX-таймери, які надсилають вибраний сигнал).

Коли перебирати код не хочеться, той самий потік влаштовують ззовні. `SIGWINCH` для цього зручний тим, що нічого не значить, — але саме тому в програмі має стояти порожній обробник без `SA_RESTART`: типова диспозиція `SIGWINCH` — ігнорувати, а проігнорований сигнал ядро прикриє прозорим перезапуском, і `EINTR` ви не побачите.

```sh
# 200 сигналів на секунду в живий процес
while kill -WINCH "$PID" 2>/dev/null; do sleep 0.005; done
```

Одного цього потоку, проте, замало: він проганяє гілку `EINTR`, але не гілку короткого результату. Її вмикають інакше — крихітним `SO_SNDBUF` на приймальному боці або читачем, який навмисно бере дані повільно; тоді `write_all` уперше отримує від `write` менше, ніж просив, і зсув покажчика теж стає перевіреним, а не просто написаним.

Лишається довести, що гілки справді виконувались. Найнадійніше — лічильник просто в обгортках (`static unsigned long eintr_hits;` з інкрементом у кожній гілці `EINTR`) і друк його наприкінці прогону: прогін, що завершився з нулем, не перевірив нічого й зеленим вважатися не має. Збоку те саме видно трасувальником ([strace і трасування викликів](book:unix-linux/syscall-tracing) — перехоплення системних викликів чужого процесу через ptrace): рядки з `EINTR` і `ERESTARTSYS` у виводі — це і є пройдені гілки, а їхнє співвідношення одразу показує, які виклики ядро переграло само, а які дійшли до програми.

## Що ламається найчастіше

`errno` живе рівно до наступного виклику libc — тому його зберігають **першим рядком** після перевірки результату, ще до `alarm(0)`, `close` чи `perror`. Маска сигналів переживає `execve`, тож нащадок успадкує заблокований `SIGTERM` і поводитиметься дивно: між `fork` і `exec` маску знімають. У багатопотоковій програмі замість `sigprocmask` вживають `pthread_sigmask` і ставлять маску до створення потоків, бо потік успадковує її від творця. І одне, чого не роблять ніколи: не загортають у петлю `close` — дескриптор у Linux уже закрито, і повтор влучить у чужий файл.
