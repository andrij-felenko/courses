# 📋 Матриця перезапуску: що переграється, а що завжди дає `EINTR`

Довідка для звіряння: повний перелік системних викликів за трьома групами — ті, що ядро переграє під `SA_RESTART`; ті, що віддають `EINTR` завжди; ті, що переживають перерву через блок перезапуску, — плюс контракт `sigaction`, застарілий `siginterrupt`, макрос `TEMP_FAILURE_RETRY` і окремо `close`. Потрібна тоді, коли код уже написано й треба точно знати, чи побачить конкретний виклик `EINTR`.

---

## Розвилка: чотири внутрішні коди на три випадки

Прапорець `SA_RESTART` вирішує не все. Що станеться з перерваним викликом, залежить від пари «внутрішній код, який повернула підсистема» × «що зараз робиться з сигналом». Обидві осі — у ядрі, програма бачить лише результат.

| Внутрішній код | Обробник **не** запускається (сигнал ігнорують, зупинка й `SIGCONT`, `ptrace`) | Обробник із `SA_RESTART` | Обробник без `SA_RESTART` |
|---|---|---|---|
| `ERESTARTSYS` (512) | переграти | переграти | `EINTR` |
| `ERESTARTNOINTR` (513) | переграти | переграти | **переграти** |
| `ERESTARTNOHAND` (514) | переграти | `EINTR` | `EINTR` |
| `ERESTART_RESTARTBLOCK` (516) | переграти через `restart_syscall` | `EINTR` | `EINTR` |

Таблиця не з документації — вона просто списана з двох `switch` у коді ядра, які тільки цим і займаються (`arch/x86/kernel/signal.c`, гілка 6.x):

```c
/* handle_signal() — обробник таки запускається */
switch (syscall_get_error(current, regs)) {
case -ERESTART_RESTARTBLOCK:
case -ERESTARTNOHAND:
    regs->ax = -EINTR;
    break;
case -ERESTARTSYS:
    if (!(ksig->ka.sa.sa_flags & SA_RESTART)) {
        regs->ax = -EINTR;
        break;
    }
    fallthrough;
case -ERESTARTNOINTR:
    regs->ax = regs->orig_ax;   /* номер виклику назад у rax */
    regs->ip -= 2;              /* лічильник на довжину `syscall` назад */
    break;
}

/* arch_do_signal_or_restart() — обробника немає */
switch (syscall_get_error(current, regs)) {
case -ERESTARTNOHAND:
case -ERESTARTSYS:
case -ERESTARTNOINTR:
    regs->ax = regs->orig_ax;
    regs->ip -= 2;
    break;
case -ERESTART_RESTARTBLOCK:
    regs->ax = get_nr_restart_syscall(regs);   /* підміна номера */
    regs->ip -= 2;
    break;
}
```

Звідси головне правило, яке порушують найчастіше: **`SA_RESTART` береться з диспозиції того сигналу, чий обробник щойно відпрацював**, а не з властивостей виклику й не з налаштувань того, хто викликав ([диспозиція сигналу](book:unix-linux/signal-disposition) — набір «обробник, маска, прапорці», який процес призначив кожному номеру сигналу окремо). Стороння бібліотека, що поставила свій обробник `SIGCHLD` без цього прапорця, зробить `EINTR` можливим у вашому `read`, хоч ви його там і не чекали.

## Група 1 — переграються, якщо стоїть `SA_RESTART`

| Виклики | Уточнення |
|---|---|
| `read`, `readv`, `write`, `writev`, `ioctl` | лише на «повільних» пристроях: термінали, канали, сокети, частина символьних пристроїв. звичайний файл на диску сюди не входить: очікування на блоковий пристрій ядро тримає у сні, якого перервати не можна |
| `open` | лише коли може заблокувати (FIFO без читача чи без письменника) |
| `wait`, `wait3`, `wait4`, `waitid`, `waitpid` | уся родина очікування на дитину |
| `accept`, `connect`, `recv`, `recvfrom`, `recvmmsg`, `recvmsg`, `send`, `sendto`, `sendmsg` | **лише якщо на сокеті не виставлено тайм-аут** — інакше група 2 |
| `flock`, `fcntl` з `F_SETLKW` і `F_OFD_SETLKW` | очікування на [файловий замок](book:unix-linux/file-locking) |
| `mq_receive`, `mq_timedreceive`, `mq_send`, `mq_timedsend` | черги повідомлень POSIX |
| `futex` `FUTEX_WAIT` | з ядра 2.6.22; до того — завжди `EINTR` |
| `futex` `FUTEX_WAIT_BITSET` | — |
| `sem_wait`, `sem_timedwait` | з ядра 2.6.22; до того — завжди `EINTR` |
| `pthread_mutex_lock`, `pthread_cond_wait` і споріднені | стоять на тому самому `futex` |
| `getrandom` | перервати тут можна лише першу фазу — очікування на початкове наповнення джерела ([джерела випадковості](book:unix-linux/random-devices) — запит до 256 байтів із уже наповненого `urandom` не блокує взагалі, тож і переривати нема чого) |
| `read` з дескриптора `inotify` | з ядра 3.8; до того — завжди `EINTR` |

Дві речі в цій таблиці варто прочитати уважно.

**Чому виклики з тайм-аутом опинилися серед перезапускних.** `mq_timedreceive` і `sem_timedwait` беруть **абсолютний** момент за годинником `CLOCK_REALTIME`, а не тривалість. Той самий аргумент, поданий удруге, означає той самий строк — годинник відмотувати не треба, тож і прозорий перезапуск чесний. Виклики, які беруть **тривалість**, цієї властивості не мають, і саме тому вони в групах 2 і 3.

**Часткова передача б'є все.** Якщо на мить переривання виклик уже щось переніс, він не дає ані `EINTR`, ані перезапуску, а повертає передану кількість — незалежно від `SA_RESTART` і від групи.

## Група 2 — не переграються ніколи

Ці виклики віддають `EINTR` за будь-якого `SA_RESTART`.

| Виклики | Уточнення |
|---|---|
| `accept`, `recv`, `recvfrom`, `recvmmsg`, `recvmsg` | коли на сокеті виставлено `SO_RCVTIMEO` |
| `connect`, `send`, `sendto`, `sendmsg` | коли на сокеті виставлено `SO_SNDTIMEO` |
| `pause`, `sigsuspend`, `sigtimedwait`, `sigwaitinfo` | очікування на сигнал: запуск обробника і є тим результатом, по який ішли |
| `select`, `pselect`, `poll`, `ppoll`, `epoll_wait`, `epoll_pwait` | [очікування на багато джерел](book:unix-linux/select-poll-epoll) — точка, на якій стоїть цикл подій будь-якого сервера |
| `msgrcv`, `msgsnd`, `semop`, `semtimedop` | черги й семафори System V |
| `nanosleep`, `clock_nanosleep`, `usleep` | сни |
| `io_getevents` | збирання завершень [асинхронного вводу-виводу ядра](book:unix-linux/linux-aio-io-submit) |

Дві примітки до цієї групи.

**`sleep(3)` виламується з переліку.** Він теж не перезапускається, але й помилки не віддає: повертає **кількість недоспаних секунд**, нуль означає «доспав». Код, який ігнорує це число, після `sleep(60)` під потоком сигналів прокидається значно раніше за хвилину й про це не дізнається.

**Друкарська помилка в `signal(7)`.** Обидва «сокетні» пункти в самій сторінці називають `SO_RCVTIMEO`, хоч у вихідних операціях працює `SO_SNDTIMEO`. Ядро тут ні до чого — помилка саме в тексті сторінки; поведінка саме така, як у таблиці вище.

## Група 3 — блок перезапуску й `restart_syscall`

| Виклик | З якої версії ядра |
|---|---|
| `nanosleep` | 2.6 |
| `clock_nanosleep` | 2.6 |
| `futex` `FUTEX_WAIT` | 2.6.22 |
| `poll` | 2.6.24 |
| `futex` `FUTEX_WAIT_BITSET` | 2.6.31 |

Ця група — не третя відповідь для обробників, і в цьому легко помилитися. `poll` стоїть тут і водночас у групі 2, бо `ERESTART_RESTARTBLOCK` з обробником перетворюється на `EINTR` (перший `switch` вище). Блок перезапуску працює рівно там, де обробник **не** запускається: після зупинки з термінала й `SIGCONT` ([керування завданнями](book:unix-linux/job-control) — `Ctrl+Z` шле `SIGTSTP`, `fg` відпускає процес через `SIGCONT`, і жодного обробника при цьому не викликають) або під час зупинки трасувальником. Ядро підміняє номер виклику на `restart_syscall` — виклик без обгортки в libc, який жодна програма не викликає сама, — той дістає з блоку збережений дедлайн, перераховує залишок і засинає вже на нього.

Виклик, який узяв тривалість і такого блоку не має, прозоро перезапустити нема як. Тому програма, що спить у `epoll_wait`, після `Ctrl+Z` і `fg` дістає `EINTR` — без жодного обробника й усупереч POSIX.

---

## `EINTR` без жодного обробника

Перелік того, що в Linux віддає `EINTR` після зупинки й `SIGCONT`, навіть коли в програмі не встановлено жодного обробника:

| Виклики | Умова |
|---|---|
| сокетні операції з `SO_RCVTIMEO`/`SO_SNDTIMEO` | завжди |
| `epoll_wait`, `epoll_pwait` | завжди |
| `semop`, `semtimedop` | завжди |
| `sigtimedwait`, `sigwaitinfo` | завжди |
| `read` з дескриптора `inotify` | ядро 3.7 і старіші |
| `futex` `FUTEX_WAIT`, `sem_wait`, `sem_timedwait` | ядро 2.6.21 і старіші |
| `msgrcv`, `msgsnd` | ядро 2.6.8 і старіші |
| `nanosleep` | ядро 2.4 і старіші |

## Контракт `sigaction` і застарілий `siginterrupt`

```c
#include <signal.h>

struct sigaction {
    void     (*sa_handler)(int);
    void     (*sa_sigaction)(int, siginfo_t *, void *);
    sigset_t   sa_mask;      /* що блокувати на час роботи обробника */
    int        sa_flags;     /* сюди йде SA_RESTART */
    void     (*sa_restorer)(void);   /* службове, програма не заповнює */
};

int sigaction(int signum, const struct sigaction *act,
              struct sigaction *oldact);   /* 0 або -1 з errno */
```

`SA_RESTART` діє рівно на один внутрішній код — `ERESTARTSYS`. На решту трьох він не впливає ніяк, тому переконання «поставив прапорець — `EINTR` зник» хибне навіть у межах власного коду.

Другий інтерфейс до того самого прапорця — застарілий:

```c
/* _XOPEN_SOURCE >= 500 || _POSIX_C_SOURCE >= 200809L (з glibc 2.12)
                        || _BSD_SOURCE (glibc ≤ 2.19) */
#include <signal.h>

[[deprecated]] int siginterrupt(int sig, int flag);   /* 0 або -1 з EINVAL */
```

| `flag` | Що робить | Наслідок |
|---|---|---|
| `0` | ставить `SA_RESTART` для сигналу `sig` | виклики переграються; у Linux це усталений стан |
| `1` | знімає `SA_RESTART` | виклик без переданих даних дає `-1` і `EINTR`; із переданими — повертає передане |

Функція прийшла з 4.3BSD, увійшла в POSIX.1-2001, у POSIX.1-2008 її позначили застарілою на користь `sigaction`, а в POSIX.1-2024 — прибрали зі стандарту. Новий код її не вживає; у чужому вона трапляється й досі, і читати її треба як «тут комусь бракувало `SA_RESTART`».

Третій спосіб потрапити до прапорця — випадковий. Старий `signal()` у glibc з версії 2 не входить у ядро сам, а викликає `sigaction` із заздалегідь вибраними прапорцями, і які саме — вирішує макрос перевірки можливостей:

| Макрос | Семантика | `sa_flags`, які підставить glibc |
|---|---|---|
| `_DEFAULT_SOURCE` (glibc ≥ 2.19) або `_BSD_SOURCE` (≤ 2.19) — **визначено усталено** | BSD | `SA_RESTART` |
| жодного з них (наприклад, під самим `_XOPEN_SOURCE`) | System V | `SA_RESETHAND \| SA_NODEFER` |

Тобто звичайний `signal(SIGCHLD, h)` у типовій збірці мовчки вмикає перезапуск, а той самий рядок під іншим набором макросів — вимикає. Перевірити, що насправді стоїть, можна не читаючи чужих джерел:

```c
struct sigaction old;
if (sigaction(SIGCHLD, NULL, &old) == 0)          /* act = NULL — лише прочитати */
    printf("SIGCHLD: SA_RESTART %s\n",
           (old.sa_flags & SA_RESTART) ? "є" : "немає");
```

Ця перевірка після ініціалізації сторонніх бібліотек — найкоротший спосіб дізнатися, чи побачить ваш `read` `EINTR`.

## `TEMP_FAILURE_RETRY`

```c
#define _GNU_SOURCE
#include <errno.h>
#include <unistd.h>

/* так це визначено в glibc: */
#define TEMP_FAILURE_RETRY(expression)                     \
    (__extension__ ({ long int __result;                   \
       do __result = (long int) (expression);              \
       while (__result == -1L && errno == EINTR);          \
       __result; }))

ssize_t n = TEMP_FAILURE_RETRY(read(fd, buf, len));
```

Три межі, за якими макрос перестає бути корисним:

- **Це розширення glibc**, а не POSIX: воно спирається на вираз-блок `({ … })` від GCC. У musl і в багатьох інших бібліотеках його немає — портабельний код носить власну копію.
- **Результат зводиться до `long int`.** Обгортати ним виклики, що повертають покажчик або 64-бітне зміщення на 32-бітній збірці, не можна — значення обріжеться.
- **Він не бачить часткової передачі.** `read`, який віддав 300 байтів із запитаних 4096, для макроса — успіх; решту 3796 байтів утрачено мовчки. Там, де потрібна саме вся кількість, потрібен цикл із лічильником переданого, а не цей макрос.

І одне місце, де вживати його заборонено, — `close`.

## `close` — окремий контракт

```c
#include <unistd.h>

int close(int fd);   /* 0 або -1 з errno */
```

| Помилка | Причина |
|---|---|
| `EBADF` | `fd` не є відкритим дескриптором — **єдиний випадок, коли дескриптор не закрито** |
| `EINTR` | виклик перервано сигналом; дескриптор у Linux **уже закрито** |
| `EIO` | помилка вводу-виводу під час скидання даних |
| `ENOSPC`, `EDQUOT` | на NFS вичерпано місце чи квоту; помилку попереднього `write` часто видно саме тут |

| Система | Стан дескриптора після `EINTR` | Що робити |
|---|---|---|
| Linux (і більшість інших) | закрито | **не повторювати**; помилку записати в журнал |
| HP-UX | лишається відкритим | повторити, інакше витік |
| POSIX.1-2008 | стан не визначено | портабельного способу немає |
| POSIX.1-2024 | узаконено поведінку HP-UX | Linux свідомо лишився невідповідним і міняти поведінку не планує |

Причина того, що Linux робить саме так: ядро звільняє номер дескриптора **на початку** операції закриття, а кроки, які можуть відмовити — скидання даних у файлову систему чи на пристрій, — ідуть пізніше. Тобто на мить повернення помилки номер уже вільний і його вже могли роздати ([файловий дескриптор](book:unix-linux/file-descriptor) — маленьке число з таблиці процесу; ядро завжди видає найменше вільне). Повторний `close` у багатопотоковій програмі закриє чужий файл, який інший потік щойно відкрив і дістав той самий номер. Помилку варто зафіксувати, але не «виправляти»; хто хоче знати про втрату даних заздалегідь, робить `fsync` **перед** закриттям.

## Дрібниці контракту, на яких спотикаються

**`EINTR` — це 4.** Число однакове на всіх архітектурах Linux, але звірятися з ним має сенс лише після `-1`: у разі успіху `errno` не обнуляють, і там лежить сміття від попередніх викликів.

**Диспозиція одна на процес, маска — у кожного потоку своя.** Прапорець `SA_RESTART` ставиться на сигнал у межах усього процесу, тож увімкнути його «тільки для свого потоку» не можна ([потоки як задачі](book:unix-linux/threads-as-tasks) — з погляду ядра потоки процесу є окремими задачами зі спільною таблицею диспозицій). Обірваним виявиться виклик того потоку, якому ядро віддало сигнал: для сигналу, надісланого процесові, це будь-який потік, що не тримає його в масці.

**`recvmmsg` має власний тайм-аут — і власні правила.** Коли аргумент `timeout` не `NULL`, він належить до групи 2 незалежно від `SO_RCVTIMEO`. Гірше: строк звіряється **лише після прийому чергової дейтаграми**, тож на `n−1` прийнятих повідомленнях і мовчазній мережі виклик чекатиме вічно. А якщо перерва сталася після хоча б одного прийнятого повідомлення, виклик віддає успіх і кількість прийнятих — помилку побачить уже наступний виклик, і то якщо її не перепише стороння мережева подія.

**`epoll_pwait2`** з'явився в ядрі 5.11 і поводиться так само, як решта родини `epoll`: група 2, `EINTR` за будь-яких прапорців.

## Мінімальний робочий виклик

Програма ставить обробник із `SA_RESTART`, заводить таймер на 200 мс і по черзі входить у виклик групи 1 та групи 2:

```c
#define _GNU_SOURCE
#include <errno.h>
#include <poll.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <sys/time.h>
#include <unistd.h>

static volatile sig_atomic_t ticks;
static void on_alarm(int sig) { (void) sig; ticks++; }

static void report(const char *what, long r)
{
    if (r < 0) printf("%-5s = %ld, errno = %d (%s), тиків = %d\n",
                      what, r, errno, strerror(errno), (int) ticks);
    else       printf("%-5s = %ld, помилки немає, тиків = %d\n",
                      what, r, (int) ticks);
}

int main(void)
{
    struct sigaction sa;
    sigemptyset(&sa.sa_mask);
    sa.sa_handler = on_alarm;
    sa.sa_flags   = SA_RESTART;      /* приберіть — і read теж дасть EINTR */
    if (sigaction(SIGALRM, &sa, NULL) == -1) { perror("sigaction"); return 1; }

    struct itimerval it = { { 0, 200000 }, { 0, 200000 } };   /* що 200 мс */
    setitimer(ITIMER_REAL, &it, NULL);

    char buf[64];
    report("read", read(STDIN_FILENO, buf, sizeof buf));       /* група 1 */

    struct pollfd pfd = { STDIN_FILENO, POLLIN, 0 };
    report("poll", poll(&pfd, 1, 5000));                       /* група 2 */
    return 0;
}
```

**Запуск: чекаємо секунду, тиснемо `Enter`.**

```
$ cc -o m m.c && ./m

read  = 1, помилки немає, тиків = 5
poll  = -1, errno = 4 (Interrupted system call), тиків = 6
```

П'ять сигналів прийшло, поки `read` чекав на рядок, — і жодного `EINTR`: ядро щоразу переграло виклик. Наступний же сигнал вибив `poll` із п'ятисекундного тайм-ауту через 200 мс, при тому самому обробнику й тому самому `SA_RESTART`.

Те саме збоку, `strace -e trace=read,poll,rt_sigaction ./m`:

```
read(0, 0x7ffd..., 64)                  = ? ERESTARTSYS (To be restarted if SA_RESTART is set)
--- SIGALRM {si_signo=SIGALRM, si_code=SI_KERNEL} ---
rt_sigreturn({mask=[]})                 = 0
read(0, 0x7ffd..., 64)                  = ? ERESTARTSYS (To be restarted if SA_RESTART is set)
...
read(0, "\n", 64)                       = 1
poll([{fd=0, events=POLLIN}], 1, 5000)  = ? ERESTART_RESTARTBLOCK (Interrupted by signal)
--- SIGALRM {si_signo=SIGALRM, si_code=SI_KERNEL} ---
rt_sigreturn({mask=[]})                 = -1 EINTR (Interrupted system call)
```

Трасувальник стоїть **до** розвилки й показує внутрішній код таким, яким його повернула підсистема: `ERESTARTSYS` для `read`, `ERESTART_RESTARTBLOCK` для `poll`. Знак питання замість числа означає «результату ще немає» (старіші версії `strace` друкували тут `-1`).

Найцікавіший рядок — той, що після сигналу. `rt_sigreturn` не повертає нічого осмисленого; `strace` просто друкує вміст `rax` на виході з обробника, тобто результат тієї самої правки регістрів. Після `ERESTARTSYS` із `SA_RESTART` там лежить відновлений **номер виклику** — на x86-64 `read` має номер 0, звідси й `= 0`. Після `ERESTART_RESTARTBLOCK` там `-EINTR` — те саме число 4, яке за мить дістане програма. Колонку «Обробник із `SA_RESTART`» першої таблиці видно тут буквально, байтом у регістрі: рядок `ERESTARTSYS` дає переграний виклик, рядок `ERESTART_RESTARTBLOCK` — `EINTR`.
