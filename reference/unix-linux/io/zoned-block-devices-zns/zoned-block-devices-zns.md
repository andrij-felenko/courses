# Зоновані блокові пристрої (ZBC/ZAC та zonefs)

- [Модель inode та VFS](book:unix-linux/inode-model) — структура файлових систем, сторінковий кеш та виклики VFS.
</preknowlist>

Зоновані блокові пристрої (Zoned Block Devices, ZBD) — це пристрої зберігання даних, у яких логічний адресний простір (LBA) поділено на окремі ділянки (зони) фіксованого або змінного розміру. На відміну від звичайних накопичувачів, де програма може перезаписувати будь-який сектор у довільному порядку, зоновані пристрої вимагають строго послідовного запису всередині послідовних (Sequential) зон (тоді як Conventional-зони дозволяють довільний запис).

Цей підхід фундаментально змінює розподіл обов'язків між операційною системою та накопичувачем, позбавляючи пристрій необхідності виконувати приховане внутрішнє переміщення даних.

---

## Чому виникли зоновані пристрої

Традиційні накопичувачі намагаються маскувати свої фізичні обмеження за ілюзією довільного доступу. Однак ця ілюзія дорого коштує на сучасних носіях надвисокої щільності:

- **Жорсткі диски SMR (Shingled Magnetic Recording):** Для збільшення місткості магнітні доріжки накладають одна на одну, як черепицю на даху. Записувальна головка фізично ширша за зчитувальну. Спроба перезаписати один сектор у середині групи знищує дані на всіх сусідніх перекритих доріжках.
- **Твердотільні диски NVMe (SSD):** Флеш-пам'ять NAND дозволяє читати й писати сторінками, але стирає дані лише великими блоками стирання. Щоб забезпечити довільний запис, контролер SSD проводить постійний внутрішній збір сміття (Garbage Collection). Це прискорює знос осередків пам'яті та викликає раптові затримки вводу-виводу під навантаженням.

Зонована архітектура вирішує цю проблему шляхом відкриття фізичної структури пристрою для операційної системи. Операційна система бере на себе обов'язок писати в зони послідовно.

---

## Принцип роботи: вказівник запису Write Pointer

Усі зони на накопичувачі поділяються на два основні види:
1. **Conventional (Звичайні зони):** Займають невелику частину ємності диска та дозволяють довільне читання й запис у будь-який сектор (для зберігання таблиць метаданих). Апаратним підґрунтям таких зон є нечерепичні CMR-доріжки на SMR HDD або виділені FTL/SLC-ділянки на ZNS SSD — саме вони й забезпечують довільний перезапис без обмежень вказівника запису.
2. **Sequential Write Required (Зони послідовного запису):** Вимагають запису виключно за поточною позицією вказівника запису.

Вказівник запису (Write Pointer, WP) — це внутрішній регістр зони, який показує на наступний доступний для запису сектор:
- У порожній зоні WP знаходиться на самому початку (сектор `start`).
- При успішному записі даних WP автоматично зміщується вперед на кількість записаних секторів.
- Спроба записати дані за адресою, яка не збігається з поточним значенням WP, відхиляється накопичувачем як апаратна помилка.

Для перетворення заповненої або частково записаної зони знову на порожню операційна система відправляє команду `Reset Zone`. На SSD це дозволяє контролеру фізично стерти відповідні блоки флеш-пам'яті — одразу або відкладено, перед першим новим записом у зону.

## Команда Zone Append для паралельного запису

Якщо декілька ниток або процесів одночасно намагаються записати дані в одну зону, класична команда `WRITE` вимагала б складних блокувань на хості. Обом процесам довелося б читати один і той самий WP, через що один із запитів неминуче зазнав би невдачі через зміщення адреси.

Стандарт NVMe ZNS вводить команду `Zone Append`. Процес надсилає дані, вказуючи лише **початок зони**, а не точний сектор. Контролер SSD сам атомарно призначає запису поточне значення WP, записує дані, зсуває WP та повертає фактично використаний сектор у відповіді. Це дозволяє багатьом ниткам писати в одну зону паралельно без затримок очікування.

## Стани зон та контроль ресурсів контролера

Кожна зона перебуває в одному з визначених станів: `Empty` (порожня), `Implicitly Open` або `Explicitly Open` (відкрита для запису), `Closed` (закрита) або `Full` (повністю заповнена). 

Оскільки пристрій має обмежену кількість апаратних ресурсів SRAM для ведення активних вказівників запису, специфікація обмежує кількість одночасно відкритих зон через атрибут `max_open_zones`. Якщо програма перевищує цей ліміт, пристрій повертає помилку `EBUSY`. Для вивільнення ресурсів розробники повинні примусово закривати або фіналізувати частково записані зони.

## Підтримка в Linux та zonefs

Операційна система Linux містить розширену підтримку ZBD у блоковому шарі та файлових системах:

- **Планувальник `mq-deadline`:** Забезпечує впорядковану видачу класичних запитів до зон без їхнього перевпорядкування у черзі.
- **Файлова система `zonefs`:** Представляє кожну зону пристрою як окремий файл у каталозі `seq/`. Запис у ці файли дозволено лише в кінець файла — з прапорцем `O_APPEND` (при прямому вводі-виводі ядро транслює такий запис в апаратну команду `Zone Append`), а скидання зони здійснюється через системний виклик `ftruncate(fd, 0)`.
- **Нативні ФС та бази даних:** Спеціалізовані файлові системи (`f2fs`, `Btrfs`) та плагіни для баз даних (RocksDB `ZenFS`) пишуть безпосередньо в зони, забезпечуючи нульове посилення запису (WAF = 1.0) та передбачуваний детермінований час відгуку.
