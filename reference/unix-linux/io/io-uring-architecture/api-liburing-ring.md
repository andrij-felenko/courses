# 📋 Інтерфейс та структури даних io_uring

Цей довідник описує бінарний контракт між простором користувача та ядром Linux: структури даних `io_uring_sqe`, `io_uring_cqe`, `io_uring_params`, offset-структури для `mmap()`, прапорці конфігурації та ключові операції API `liburing`.

## Бінарний контракт: SQE та CQE

Фундаментом протоколу взаємодії є дві фіксовані бінарні структури, що розміщуються в кільцевих буферах спільної пам'яті.

### Запит: struct io_uring_sqe (64 байти)

Кожен елемент черги подання (Submission Queue Entry) вирівняний по межі 64 байтів (розмір кеш-лінії більшості сучасних процесорів, що запобігає ефекту false sharing).

```c
struct io_uring_sqe {
    __u8    opcode;       /* Код операції (IORING_OP_*) */
    __u8    flags;        /* Прапорці поведінки запиту (IOSQE_*) */
    __u16   ioprio;       /* Пріоритет I/O (IOPRIO_CLASS_*) */
    __s32   fd;           /* Файловий дескриптор або індекс у масиві */
    union {
        __u64   off;      /* Зміщення у файлі */
        __u64   addr2;    /* Друга адреса для операцій splice/cmd */
    };
    union {
        __u64   addr;     /* Вказівник на буфер користувача або iovec */
        __u64   splice_off_in;
    };
    __u32   len;          /* Довжина буфера або кількість iovec */
    union {
        __kernel_rwf_t  rw_flags; /* Прапорці read/write (RWF_HIPRI, RWF_NOWAIT) */
        __u32           fsync_flags;
        __u16           poll_events;
        __u32           sync_range_flags;
        __u32           msg_flags;
        __u32           timeout_flags;
        __u32           accept_flags;
        __u32           cancel_flags;
        __u32           open_flags;
        __u32           statx_flags;
        __u32           fadvise_advise;
        __u32           splice_flags;
        __u32           rename_flags;
        __u32           unlink_flags;
        __u32           hardlink_flags;
        __u32           xattr_flags;
        __u32           msg_ring_flags;
        __u32           uring_cmd_flags;
    };
    __u64   user_data;    /* 64-бітне значення для ідентифікації запиту розробником */
    union {
        __u16   buf_index;  /* Індекс у масиві зареєстрованих буферів */
        __u16   buf_group;  /* Група наданих буферів (provided buffers) */
    } __attribute__((packed));
    __u16   personality;  /* Ідентифікатор прав (credentials) */
    union {
        __s32   splice_fd_in;
        __u32   file_index; /* Індекс для прямого файлового дескриптора */
    };
    __u64   __pad2[2];    /* Резерв для майбутніх розширень */
};
```

#### Прапорці SQE (поле `flags`)

- `IOSQE_FIXED_FILE` — Використовувати поле `fd` як індекс у попередньо зареєстрованій таблиці файлів ядра. Це оминає процедуру знаходження `struct file` за індексом файлового дескриптора процесу.
- `IOSQE_IO_DRAIN` — Не розпочинати виконання цього SQE, поки всі попередні запити в черзі SQ не будуть повністю завершені.
- `IOSQE_IO_LINK` — Створити ланцюжок: наступний SQE почне виконуватися лише тоді, коли цей SQE завершиться успішно. Якщо поточний запит завершився з помилкою, весь ланцюжок скасовується з результатом `-ECANCELED`.
- `IOSQE_IO_HARDLINK` — Створити суворий ланцюжок: наступний SQE почне виконуватися незалежно від того, чи поточний SQE завершився успішно, чи з помилкою.
- `IOSQE_ASYNC` — Примусово передати запит на виконання в асинхронний пул потоків `io-wq`, оминаючи спробу виконання у швидкому неблокуючому контексті.
- `IOSQE_BUFFER_SELECT` — Автоматично вибирати буфер для зчитування з вказаної групи `buf_group` (provided buffers), заповненої через `IORING_OP_PROVIDE_BUFFERS` або `IORING_REGISTER_PBUF_RING`.
- `IOSQE_CQE_SKIP_SUCCESS` — Не породжувати CQE, якщо операція завершилася успішно (CQE з'явиться лише в разі помилки), що знижує навантаження на чергу завершення.

### Результат: struct io_uring_cqe (16 байтів)

Кожен елемент черги завершення (Completion Queue Entry) має компактний розмір 16 байтів.

```c
struct io_uring_cqe {
    __u64   user_data;    /* Дослівна копія поля user_data з ініціалізуючого SQE */
    __s32   res;          /* Результат: кількість прочитаних/записаних байтів або від'ємний -errno */
    __u32   flags;        /* Додаткові метапрапорці від ядра */
};
```

#### Прапорці CQE (поле `flags`)

- `IORING_CQE_F_BUFFER` — Дані записано в буфер, який ядро обрало з групи `buf_group`. Верхні 16 бітів поля `flags` містять ідентифікатор цього буфера `bid`.
- `IORING_CQE_F_MORE` — Запит згенерував цей CQE, але залишається активним і може згенерувати наступні CQE (наприклад, для багаторазового `accept` або потокового `poll`).
- `IORING_CQE_F_SOCK_NONEMPTY` — Підказка сокета: в сокеті залишилися доступні дані після виконання `recv`.
- `IORING_CQE_F_NOTIF` — Сповіщення про звільнення буфера у zero-copy операціях (`IORING_OP_SEND_ZC`).

## Зміщення пам'яті для mmap(): struct io_sqring_offsets та io_cqring_offsets

При системному виклику `io_uring_setup()` ядро заповнює структуру `io_uring_params` із вказівками зміщень (offsets) для мапінгу пам'яті спільного використання.

```c
struct io_sqring_offsets {
    __u32 head;        /* Зміщення вказівника голови SQ */
    __u32 tail;        /* Зміщення вказівника хвоста SQ */
    __u32 ring_mask;   /* Маска розміру буфера (entries - 1) */
    __u32 ring_entries;/* Кількість елементів у SQ */
    __u32 flags;       /* Прапорці стану SQ (наприклад, IORING_SQ_NEED_WAKEUP) */
    __u32 dropped;     /* Лічильник відкинутих SQE (коли SQ переповнена) */
    __u32 array;       /* Зміщення масиву індексів SQE */
    __u32 resv1;
    __u64 resv2;
};

struct io_cqring_offsets {
    __u32 head;        /* Зміщення вказівника голови CQ */
    __u32 tail;        /* Зміщення вказівника хвоста CQ */
    __u32 ring_mask;   /* Маска розміру буфера CQ */
    __u32 ring_entries;/* Кількість елементів у CQ */
    __u32 overflow;    /* Лічильник втрачених CQE через переповнення черги */
    __u32 cqes;        /* Зміщення масиву структур io_uring_cqe */
    __u32 flags;
    __u32 resv1;
    __u64 resv2;
};
```

Мапінг вимагає двох або трьох окремих викликів `mmap()`:
1. `mmap(NULL, sq_sz, PROT_READ | PROT_WRITE, MAP_SHARED | MAP_POPULATE, ring_fd, IORING_OFF_SQ_RING)` — мапінг структур керування чергами.
2. `mmap(NULL, sqes_sz, PROT_READ | PROT_WRITE, MAP_SHARED | MAP_POPULATE, ring_fd, IORING_OFF_SQES)` — мапінг самого масиву 64-байтних структур SQE.
3. `mmap(NULL, cq_sz, PROT_READ | PROT_WRITE, MAP_SHARED | MAP_POPULATE, ring_fd, IORING_OFF_CQ_RING)` — мапінг черги CQ (якщо не використовується єдиний мапінг `IORING_FEAT_SINGLE_MMAP`).

## Прапорці ініціалізації io_uring_setup()

- `IORING_SETUP_SQPOLL` — Запустити фоновий потік ядра `io_uring-sq`, який виконує поллінг черги SQ без системних викликів `io_uring_enter`.
- `IORING_SETUP_IOPOLL` — Використовувати поллінг драйвера блочного пристрою (NVMe poll) замість апаратних переривань. Вимагає відкриття файлів з прапорцем `O_DIRECT`.
- `IORING_SETUP_SQ_AFF` — Прив'язати потік `SQPOLL` до конкретного ядра CPU (вказується в `params.sq_thread_cpu`).
- `IORING_SETUP_CQSIZE` — Задати власну глибину черги CQ (за замовчуванням у 2 рази більша за SQ).
- `IORING_SETUP_SINGLE_ISSUER` — Оптимізація ядра під умову, що подавати SQE буде лише один конкретний потік простору користувача.
- `IORING_SETUP_DEFER_TASKRUN` — Відкласти обробку `task_work` ядра до моменту, поки процес користувача явно не викличе `io_uring_enter` для очікування подій, що прибирає міжпроцесорні сповіщення (IPI, inter-processor interrupts) зі шляху завершення.
- `IORING_SETUP_REGISTERED_FD_ONLY` — Гарантувати, що нові дескриптори створюватимуться лише як прямі дескриптори (Direct Descriptors) у таблиці `io_uring`, минаючи таблицю файлів процесу.

## Ключові опкоди операцій (opcode)

| Опкод `IORING_OP_*` | Опис та еквівалентний системний виклик |
| :--- | :--- |
| `IORING_OP_NOP` | Порожня операція для вимірювання затримок каркаса |
| `IORING_OP_READV` / `WRITEV` | Векторний ввід-вивід (подібно до `readv`/`writev`) |
| `IORING_OP_READ_FIXED` / `WRITE_FIXED` | Ввід-вивід із заздалегідь замапленими буферами без lock/unlock сторінок |
| `IORING_OP_POLL_ADD` / `POLL_REMOVE` | Реєстрація маски подій сокета (подібно до `epoll_ctl`) |
| `IORING_OP_ACCEPT` | Прийняття мережевого з'єднання (подібно до `accept4`) |
| `IORING_OP_CONNECT` | Встановлення з'єднання (подібно до `connect`) |
| `IORING_OP_SEND_ZC` / `RECV_ZC` | Zero-copy обмін даними з мережевою картою без копіювання їх у проміжні буфери ядра |
| `IORING_OP_PROVIDE_BUFFERS` | Надання ядру пулу буферів для автоматичного вибору при отриманні пакетів |
| `IORING_OP_TIMEOUT` | Встановлення високоточного таймера або таймауту для завершення `N` запитів |
| `IORING_OP_SPLICE` | Передача даних між двома дескрипторами (подібно до `splice`) |
| `IORING_OP_TEE` | Дублювання даних між двома пайпами без копіювання |
| `IORING_OP_CLOSE` | Асинхронне закриття файлового дескриптора |

## Коди помилок системних викликів та операцій res

У разі виникнення помилки під час виконання операції, ядро повертає від'ємний код у полі `cqe->res`:

- `-EAGAIN` / `-EWOULDBLOCK` — Ресурс не готовий. У неблокуючих режимах ядро може автоматично перенаправити операцію у пул `io-wq` або повернути помилку користувачеві.
- `-ECANCELED` — Операцію було скасовано через помилку в попередньому зв'язаному запиті ланцюжка (`IOSQE_IO_LINK`) або через явний виклик `IORING_OP_ASYNC_CANCEL`.
- `-EBADF` — Передано невалідний файловий дескриптор або спроба використати `IOSQE_FIXED_FILE` із виходом за межі таблиці зареєстрованих файлів.
- `-EINVAL` — Непідтримуваний опкод операції, невалідний рівень прапорців або некоректне вирівнювання адреси буфера.
- `-ETIME` — Операцію `IORING_OP_TIMEOUT` перервано за вичерпанням часового інтервалу.
- `-EFAULT` — Передано невалідну адресу пам'яті в полі `addr`.

## Офіційна бібліотека liburing

Офіційна бібліотека `liburing` абстрагує мапінг пам'яті, атомарні інструкції та бар'єри пам'яті (`smp_store_release`/`smp_load_acquire`).

### Основні функції API liburing

- `io_uring_queue_init(entries, ring, flags)` — Повна ініціалізація кільцевих буферів та мапінг `mmap`.
- `io_uring_get_sqe(ring)` — Отримання вказівника на наступну вільну комірку `io_uring_sqe`.
- `io_uring_prep_read(sqe, fd, buf, nbytes, offset)` — Заповнення SQE параметрами читання.
- `io_uring_prep_send_zc(sqe, fd, buf, len, flags, zc_flags)` — Заповнення SQE параметрами Zero-copy відправки.
- `io_uring_sqe_set_data(sqe, data)` — Запис власного маркера контексту в поле `user_data`.
- `io_uring_submit(ring)` — Подання нових SQE в ядро (виклик `io_uring_enter` за потреби).
- `io_uring_wait_cqe(ring, &cqe)` — Блокуюче очікування принаймні одного готового результату у CQ.
- `io_uring_cqe_seen(ring, cqe)` — Зсув головного вказівника (head) CQ після зчитування результату.
- `io_uring_queue_exit(ring)` — Звільнення пам'яті та закриття файлового дескриптора кільця.
