# 📋 Інтерфейс DMA mapping subsystem у ядрі Linux

Підсистема `dma-mapping` ядра Linux нападає на проблему неоднорідності апаратного забезпечення через уніфікований C-інтерфейс, оголошений у заголовочному файлі `<linux/dma-mapping.h>`. Цей довідник описує повний набір системних типів, макросів, прапорців напрямку передачі даних, прапорців атрибутів пам'яті (`DMA_ATTR_*`) та функцій ядра, якими користуються розробники драйверів периферійних пристроїв.

## Переліки та базові типи даних

### 1. Напрямок передачі даних (`enum dma_data_direction`)

Визначення напрямку потокового відображення є суворим контрактом між розробником драйвера та підсистемою керування кеш-пам'яттю central CPU. Залежно від обраного напрямку ядро приймає рішення про виконання операцій очищення (flush) або інвалідації (invalidation) кеш-рядків.

```c
enum dma_data_direction {
    DMA_BIDIRECTIONAL = 0, /* Двонаправлений обмін: і CPU, і пристрій читають та пишуть у буфер */
    DMA_TO_DEVICE     = 1, /* Передача від CPU до пристрою: скидання кешу CPU у RAM перед DMA */
    DMA_FROM_DEVICE   = 2, /* Передача від пристрою до CPU: інвалідація кешу CPU після завершення DMA */
    DMA_NONE          = 3  /* Використовується для діагностики або невизначеного напрямку */
};
```

Вибір неправильного напрямку спричиняє мовчки виникаючі дефекти когерентності. Якщо для операції запису пристроєм (`DMA_FROM_DEVICE`) помилково вказати `DMA_TO_DEVICE`, ядро не виконає інвалідацію кешу CPU, і процесор згодом прочитає зі свого кешу застарілі дані замість нових, записаних периферією у RAM.

### 2. Шинна адреса (`dma_addr_t`)

Тип `dma_addr_t` є спеціальним беззнаковим цілим числом, розрядність якого задекларована конфігурацією ядра (`CONFIG_ARCH_DMA_ADDR_T_64BIT`). На 64-бітних платформах це `u64`, а на 32-бітних системах — `u32` або `u64` (якщо система підтримує розширення PAE чи 64-бітний IOMMU).

Шинна адреса репрезентує координату комірки пам'яті так, як її бачить безпосередньо контролер периферійної шини (PCI Express, AXI, AHB). `dma_addr_t` не можна розраховувати арифметично від віртуального покажчика ядра `void *` — конвертація здійснюється виключно функціями підсистеми `dma-mapping`.

### 3. Макрос розрядності адресної маски (`DMA_BIT_MASK`)

Периферійні контролери шин мають фізичні обмеження на кількість розводящих ліній адреси (наприклад, 32-бітні контролери здатні виставляти адреси лише у діапазоні перших 4 ГБ RAM). Щоб ядро могло відфільтрувати недопустимі адреси або задіяти транзитні буфери SWIOTLB, підсистема вимагає від драйвера явного задекларування розрядності апаратної адресної шини.

Макрос `DMA_BIT_MASK` формує бітову маску заданої ширини в бітах. Вона використовується для повідомлення підсистемі про максимальну кількість адресних ліній, які здатний сформувати периферійний контролер.

```c
#define DMA_BIT_MASK(n) (((n) == 64) ? ~0ULL : ((1ULL << (n)) - 1))
```

Приклади використання:
- `DMA_BIT_MASK(32)` формує маску `0x00000000FFFFFFFFULL` (підтримка перших 4 ГБ RAM);
- `DMA_BIT_MASK(64)` формує маску `0xFFFFFFFFFFFFFFFFULL` (повноцінний 64-бітний доступ).

## Атрибути відображення пам'яті (`DMA_ATTR_*`)

Функції виділення та відображення приймають додатковий побітовий масив прапорців `unsigned long attrs`, які дозволяють коригувати поведінку підсистеми для конкретного драйвера:

- **`DMA_ATTR_NO_KERNEL_MAPPING`:** Вказує ядру не створювати віртуальне відображення ядра (`void *`) під час виділення coherent пам'яті. Використовується, коли буфер потрібен виключно для пристрою або прокидається в простір користувача через mmap, що економить віртуальний адресний простір ядра (kmap).
- **`DMA_ATTR_SKIP_CPU_SYNC`:** Пропускає автоматичну синхронізацію кешу CPU під час мапінгу або унмапінгу. Використовується, коли розробник драйвера бере на себе ручну синхронізацію через виклики `dma_sync_*`.
- **`DMA_ATTR_FORCE_CONTIGUOUS`:** Вимагає від підсистеми виділення строго неперервного блоку фізичних сторінок (через CMA — Contiguous Memory Allocator), навіть якщо в системі присутній апаратний IOMMU.
- **`DMA_ATTR_WRITE_COMBINING`:** Створює віртуальне відображення пам'яті з режимом Write-Combining (буферизований запис без заповнення кешу), що ідеально підходить для фреймбуферів відеокарт та дисплеїв.

## Налаштування маски адресування пристрою

Перш ніж здійснювати будь-які операції виділення або відображення пам'яті, драйвер зобов'язаний узгодити з ядром обмеження розрядності адресної шини конкретного пристрою (`struct device`).

### `dma_set_mask_and_coherent()`

Під час ініціалізації драйвера пристрою ядро зобов'язане узгодити з апаратурою максимальну допустиму розрядність шинних адрес до того, як буде виділено перший буфер пам'яті. Функція `dma_set_mask_and_coherent()` реєструє апаратні обмеження пристрою у системних структурах ядра для зв'язаних та потокових відображень.

```c
int dma_set_mask_and_coherent(struct device *dev, u64 mask);
```

- **Опис механізму:** Одночасно встановлює маску для потокових відображень (`dev->dma_mask`) та для зв'язаних (coherent) виділень пам'яті (`dev->coherent_dma_mask`).
- **Аргументи:**
  - `dev` — вказівник на екземпляр пристрою ядра;
  - `mask` — результат макросу `DMA_BIT_MASK(n)`.
- **Значення повернення:** Повертає `0` у разі успішного узгодження з системною шиною. Якщо шина або архитектурний шар не здатні забезпечити адресацію за такою маскою, повертається від'ємний код помилки `-EIO`.
- **Рекомендований паттерн використання:** Драйвер завжди намагається спочатку встановити максимальну розрядність (64 біти), а у разі збою відкочується до 32 бітів:

```c
if (dma_set_mask_and_coherent(dev, DMA_BIT_MASK(64))) {
    if (dma_set_mask_and_coherent(dev, DMA_BIT_MASK(32))) {
        dev_err(dev, "Система не підтримує жодної сумісної DMA-маски\n");
        return -EIO;
    }
}
```

## Coherent (Зв'язані / Послідовні) відображення

Використовуються для створення довготривалих буферів, які знаходяться у постійному спільному використанні центральним процесором та пристроєм без потреби в проміжних викликах скидання кешу.

### `dma_alloc_coherent()`

Драйверам периферійних пристроїв необхідні довготривалі керуючі буфери (такі як кільцеві черги дескрипторів), де будь-які зміни записуються негайно без вартісного ручного очищення кешу CPU. Для створення такої спільної пам'яті використовується функція `dma_alloc_coherent()`, яка виділяє безкешову або апаратно когерентну ділянку RAM.

```c
void *dma_alloc_coherent(struct device *dev, size_t size,
                        dma_addr_t *dma_handle, gfp_t flag);
```

- **Опис механізму:** Виділяє область пам'яті заданого розміру `size`, яка є фізично або віртуально неперервною (залежно від наявності IOMMU) та гарантовано безкешовою для CPU.
- **Аргументи:**
  - `dev` — пристрій, для якого запитується пам'ять;
  - `size` — розмір буфера у байтах (під час виділення автоматично округлюється вгору до кратності розміру сторінки `PAGE_SIZE`);
  - `dma_handle` — [out] вихідний покажчик, куди ядро записує згенеровану шинну адресу (`dma_addr_t`), призначену для запису у реєстри периферійного пристрою;
  - `flag` — прапорці сторінкового розподільника (`GFP_KERNEL` для звичайного контексту виконання, `GFP_ATOMIC` для виконання в контексті обробника переривань).
- **Значення повернення:** Віртуальна адреса ядра (`void *`) для доступу CPU або `NULL` у разі вичерпання фізичної пам'яті чи простору IOVA.

### `dma_free_coherent()`

Під час зупинки пристрою або вивантаження модуля драйвера всі довготривалі безкешові буфери, виділені викликом `dma_alloc_coherent()`, повинні бути коректно звільнені. Функція `dma_free_coherent()` розформовує відображення та повертає виділені сторінки у системний розподільник ядра.

```c
void dma_free_coherent(struct device *dev, size_t size,
                       void *cpu_addr, dma_addr_t dma_handle);
```

- **Опис механізму:** Повертає ядру область пам'яті, виділену раніше через `dma_alloc_coherent()`.
- **Вимоги контракту:** Значення `size`, `cpu_addr` та `dma_handle` повинні строго відповідати параметрам, отриманим під час виділення, інакше виникає пошкодження структур сторінкового розподільника.

## Streaming (Потокові) відображення

Використовуються для тимчасового надання пристрою доступу до буферів пам'яті, створених у загальному сторінковому пулі ядра.

### `dma_map_single()`

Під час відправки або прийому окремого мережевого пакета чи блоку даних драйвер зобов'язаний тимчасово надати периферійному контролеру шинну адресу звичайного кешованого буфера ядра. Функція `dma_map_single()` створює таке одноразове відображення, виконує необхідну синхронізацію кешу CPU та повертає шинну адресу для обладнання.

```c
dma_addr_t dma_map_single(struct device *dev, void *ptr,
                          size_t size, enum dma_data_direction dir);
```

- **Опис механізму:** Відображає віртуально неперервний буфер ядра (`kmalloc`) для виконання однієї DMA-операції. Якщо пристрій не має IOMMU, а буфер розташований вище межі DMA-маски, функція прозоро виділяє транзитний слот SWIOTLB.
- **Аргументи:**
  - `ptr` — покажчик на віртуальну адресу пам'яті ядра (не можна передавати пам'ять `vmalloc`!);
  - `size` — довжина буфера у байтах;
  - `dir` — напрямок обміну даними (`DMA_TO_DEVICE`, `DMA_FROM_DEVICE`, `DMA_BIDIRECTIONAL`).
- **Обмеження вирівнювання:** Адреса `ptr` та довжина `size` повинні бути вирівняні по межі лінії кешу `ARCH_DMA_MINALIGN` (зазвичай 64 байти) для напрямку `DMA_FROM_DEVICE`, щоб інвалідація кешу не пошкодила сусідні змінні у тому ж кеш-рядку.

### `dma_mapping_error()`

Спроба створити потокове відображення може завершитися невдачею через вичерпання простору IOVA або брак транзитних слотів SWIOTLB. Передача незабезпеченої шинної адреси контролеру пристрою призводить до запису у довільну пам'яті ядра та фатального збою системи, тому ядро вимагає обов'язкової перевірки результату через `dma_mapping_error()`.

```c
int dma_mapping_error(struct device *dev, dma_addr_t dma_addr);
```

- **Опис механізму:** Перевіряє коректність шинної адреси, отриманої від `dma_map_single()` або `dma_map_page()`.
- **Значення повернення:** Повертає ненульове значення (істина), якщо під час відображення сталася помилка (наприклад, вичерпано слоти SWIOTLB або простір IOVA).
- **Обов'язковість перевірки:** Нехтування цією перевіркою є найпоширенішим дефектом у драйверах. Використання помилкової адреси призводить до моментального падіння ядра.

```c
dma_addr_t dma_src = dma_map_single(dev, buf, len, DMA_TO_DEVICE);
if (dma_mapping_error(dev, dma_src)) {
    dev_err(dev, "Збій відображення DMA буфера\n");
    return -ENOMEM;
}
```

### `dma_unmap_single()`

Після завершення апаратного пересилання даних периферійним пристроєм пристрій звільняє буфер, і ядро повинно повернути право володіння пам'яттю процесору. Виклик `dma_unmap_single()` завершує тимчасове відображення, виконує інвалідацію кешу CPU для отриманих даних і дозволяє вищим шарам ядра безпечно читати буфер.

```c
void dma_unmap_single(struct device *dev, dma_addr_t dma_addr,
                      size_t size, enum dma_data_direction dir);
```

- **Опис механізму:** Скасовує потокове відображення, виконує фінальну інвалідацію кешу CPU (для `DMA_FROM_DEVICE`) та звільняє слоти SWIOTLB чи сторінки IOMMU.

## Scatter-Gather (Розсіювання-збирання) відображення

Застосовуються для одночасного відображення масивів розсічених у фізичній RAM сторінок пам'яті (`struct scatterlist`).

### `dma_map_sgtable()`

Для досягнення максимальної продуктивності під час обробки великих масивів даних (наприклад, дискових операцій вводу-виводу) ядро збирає безліч фрагментованих фізичних сторінок пам'яті у єдину таблицю розсіювання-збирання. Функція `dma_map_sgtable()` виконує пакетну обробку цієї таблиці, відображаючи всі її сегменти за один виклик та об'єднуючи суміжні ділянки.

```c
int dma_map_sgtable(struct device *dev, struct sg_table *sgt,
                    enum dma_data_direction dir, unsigned long attrs);
```

- **Опис механізму:** Виконує відображення всіх елементів таблиці розсіювання-збирання `sgt`. Ядро автоматично аналізує фізичні адреси сторінок і, за наявності апаратного IOMMU або послідовних фізичних адрес, зливає декілька сегментів у єдині неперервні вікна IOVA.
- **Значення повернення:** Повертає `0` у разі успіху та від'ємний код помилки у разі збою.

### `sg_dma_address()` та `sg_dma_len()`

Після успішного виконання `dma_map_sgtable()` або `dma_map_sg()` драйвер використовує ці макроси для ітерації по готових шинних адресах:

```c
struct scatterlist *sg;
int i;

for_each_sg(sgt->sgl, sg, count, i) {
    dma_addr_t bus_addr = sg_dma_address(sg);
    unsigned int len    = sg_dma_len(sg);
    /* Запис bus_addr та len у дескриптор апаратури */
}
```

## Ручна синхронізація кешу CPU (`dma_sync_*`)

Використовується у випадках, коли драйвер повторно використовує один і той самий потоковий буфер для серії операцій вводу-виводу без постійного виклику вартісних процедур `dma_map_single()` та `dma_unmap_single()`.

### `dma_sync_single_for_cpu()`

Коли драйвер багаторазово використовує один і той самий потоковий буфер (наприклад, кільцевий буфер прийому кадрів) без його скасування через `dma_unmap_single()`, процесору необхідно прочитати нові дані, записані пристроєм. Функція `dma_sync_single_for_cpu()` тимчасово передає право володіння буфером процесору та інвалідує кеш-рядки CPU для доступу до оновленого вмісту.

```c
void dma_sync_single_for_cpu(struct device *dev, dma_addr_t dma_handle,
                             size_t size, enum dma_data_direction dir);
```

- **Призначення:** Передає право володіння буфером (або його частиною від `offset` розміром `size`) центральному процесору. Ядро виконує інвалідацію кешу CPU, щоб процесор міг прочитати нові дані, записані пристроєм.

### `dma_sync_single_for_device()`

Після того як процесор завершив читання або модифікацію даних у повторно використовуваному потоковому буфері, управління пам'яттю слід знову передати периферійному контролеру. Функція `dma_sync_single_for_device()` виштовхує модифіковані CPU дані з кешу у фізичну RAM та повертає право володіння буфером пристрою перед запуском наступної DMA-транзакції.

```c
void dma_sync_single_for_device(struct device *dev, dma_addr_t dma_handle,
                                size_t size, enum dma_data_direction dir);
```

- **Призначення:** Повертає право володіння буфером периферійному пристрою. Ядро скидає оновлені інструкціями CPU дані з кешу у фізичну RAM перед тим, як пристрій почне новий цикл DMA-читання.
