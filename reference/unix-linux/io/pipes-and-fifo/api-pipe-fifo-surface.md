# 📋 Системний інтерфейс каналів, FIFO та керування буфером

Довідник системних викликів, конфігураційних прапорців, параметрів ядра `sysctl`, контрактів блокування, інтерфейсів нульового копіювання та діагностичних вузлів для анонімних каналів і FIFO в операційній системі Linux.

## Системні виклики створення анонімних каналів

Для виділення односпрямованого каналу передачі даних у пам'яті ядра призначені системні виклики `pipe()` та `pipe2()`. Вони повертають два нові файлові дескриптори, що вказують на єдиний спільний об'єкт керування `struct pipe_inode_info` у просторі ядра.

:::tabs
```c
#define _GNU_SOURCE
#include <unistd.h>
#include <fcntl.h>

int pipe(int pipefd[2]);
int pipe2(int pipefd[2], int flags);
```
```cpp
#include <unistd.h>
#include <fcntl.h>
#include <array>
#include <system_error>

std::array<int, 2> create_pipe(int flags = 0) {
    std::array<int, 2> fds{-1, -1};
    if (::pipe2(fds.data(), flags) < 0) {
        throw std::system_error(errno, std::generic_category(), "pipe2 failed");
    }
    return fds;
}
```
:::

### Параметри системного виклику

Параметр `pipefd` є вказівником на масив із двох цілих чисел, куди ядро записує найменші доступні номери дескрипторів у таблиці поточного процесу:

- `pipefd[0]` — дескриптор кінця читання (*read end*). З нього дозволено виконувати операції зчитування (`read()`, `readv()`, `splice()`, моніторинг через `select()`, `poll()`, `epoll()`). Спроба виконати операцію запису `write()` у цей дескриптор повертає помилку `EBADF` (*Bad file descriptor*);
- `pipefd[1]` — дескриптор кінця запису (*write end*). У нього дозволено виконувати операції запису (`write()`, `writev()`, `splice()`, `vmsplice()`). Спроба виконати читання `read()` з цього дескриптора повертає помилку `EBADF`.

### Прапорці конфігурації `pipe2()`

Виклик `pipe2()` є розширенням стандарту POSIX, реалізованим у ядрі Linux починаючи з версії 2.6.27 та бібліотеці glibc 2.9. Він приймає побітову комбінацію прапорців у параметрі `flags`, що дозволяє атомарно налаштувати поведінку файлових дескрипторів безпосередньо в момент їх створення:

| Прапорець | Числове значення / Біт | Поведінка та семантика ядра |
| :--- | :--- | :--- |
| `O_CLOEXEC` | `02000000` | Встановлює прапорець закриття при виконанні `FD_CLOEXEC` на обох дескрипторах. Це запобігає стану гонитви (*race condition*) у багатопотокових програмах, де паралельний потік міг викликати `fork()` + `execve()` до того, як головний потік встигав викликати `fcntl(fd, F_SETFD, FD_CLOEXEC)`. Дескриптори автоматично закриваються ядром при переході в новий бінарний образ. |
| `O_NONBLOCK` | `00004000` | Встановлює прапорець неблокуючого вводу-виводу `O_NONBLOCK` на обох відкритих файлових описах. Будь-яка операція `read()` з порожнього буфера або `write()` у переповнений буфер повертає код помилки `EAGAIN` (або `EWOULDBLOCK`) замість переведення процесу в стан сну. |
| `O_DIRECT` | `00040000` | Вмикає пакетний режим роботи каналу (з ядра Linux 3.4). Кожен виклик `write()` розглядається як окремий дискретний пакет повідомлення; наступний виклик `read()` зчитує рівно один пакет за раз, навіть якщо розмір запитаного буфера перевищує розмір пакета. Записи, що перевищують розмір сторінки, автоматично розбиваються на пакети розміром у сторінку. |
| `O_NOTIFICATION_PIPE` | `00400000` | Спеціальний режим ядра (з Linux 5.8) для створення черги системних сповіщень `watch_queue`. Використовується підсистемами безпеки ядра для доставки асинхронних подій про зміну ключів шифрування та статусів пристроїв. |

## Створення іменованих каналів (FIFO)

Для створення іменованого каналу, доступного за шляхом у дереві файлової системи довільним процесам, застосовують системні виклики `mkfifo()`, `mkfifoat()` або низькорівневий `mknod()`:

:::tabs
```c
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int mkfifo(const char *pathname, mode_t mode);
int mkfifoat(int dirfd, const char *pathname, mode_t mode);
int mknod(const char *pathname, mode_t mode, dev_t dev);
```
```cpp
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <string_view>
#include <system_error>

void create_named_fifo(std::string_view path, mode_t mode = 0666) {
    if (::mkfifo(path.data(), mode) < 0 && errno != EEXIST) {
        throw std::system_error(errno, std::generic_category(), "mkfifo failed");
    }
}
```
:::

### Деталізація параметрів створення:
- `pathname` — шлях у файловій системі, де створюється спеціальний вузол типу `S_IFIFO`. Файлова система повинна підтримувати спеціальні файли пристроїв (наприклад, ext4, XFS, tmpfs; на файлових системах FAT/exFAT виклик поверне помилку `EPERM`);
- `mode` — маска дозволів доступу POSIX (наприклад, `0660` для читання й запису власником і групою). Реальні права доступу на створеному іноді обчислюються з урахуванням маски створення файлів процесу за формулою `mode & ~umask`;
- `dirfd` (у виклику `mkfifoat`) — дескриптор базового каталогу для обчислення відносних шляхів. Якщо передано спеціальне значення `AT_FDCWD`, шлях `pathname` обчислюється відносно поточного робочого каталогу;
- `dev` (у виклику `mknod`) — числовий ідентифікатор пристрою. Для створення FIFO тип вузла задається бітовим «АБО» `mode | S_IFIFO`, а аргумент `dev` ігнорується ядром і передається як `0`.

## Керування місткістю буфера каналу через `fcntl`

Кільцевий буфер каналу в ядрі Linux не має фіксованого розміру на весь час життя. Його місткість можна динамічно зчитувати та масштабувати за допомогою команд `F_GETPIPE_SZ` та `F_SETPIPE_SZ`:

:::tabs
```c
#define _GNU_SOURCE
#include <fcntl.h>

int fcntl(int fd, int cmd, ... /* int arg */);
```
```cpp
#include <fcntl.h>
#include <system_error>

int get_pipe_capacity(int fd) {
    int sz = ::fcntl(fd, F_GETPIPE_SZ);
    if (sz < 0) throw std::system_error(errno, std::generic_category(), "F_GETPIPE_SZ");
    return sz;
}

int set_pipe_capacity(int fd, int new_capacity) {
    int sz = ::fcntl(fd, F_SETPIPE_SZ, new_capacity);
    if (sz < 0) throw std::system_error(errno, std::generic_category(), "F_SETPIPE_SZ");
    return sz;
}
```
:::

### Правила функціонування `F_SETPIPE_SZ`:
1. **Округлення розміру:** Ядро автоматично округлює передане значення `new_capacity` вгору до найближчого степеня двійки, кратного розміру фізичної сторінки пам'яті (`PAGE_SIZE`, типово 4096 байтів). Наприклад, запит на 5000 байтів встановить розмір у 8192 байти (2 сторінки);
2. **Виділення сторінок за вимогою:** Збільшення місткості буфера змінює лише розмір масиву посилань `struct pipe_buffer`. Самі сторінки оперативної пам'яті виділяються ядром динамічно в момент фактичного запису даних і звільняються під час зчитування;
3. **Зменшення буфера:** Спроба зменшити розмір буфера нижче за обсяг даних, які вже містяться в каналі й очікують читача, завершується помилкою `EBUSY` (*Device or resource busy*);
4. **Привілеї процесу:** Непривілейований процес може збільшувати розмір буфера до межі, вказаної у системному файлі `/proc/sys/fs/pipe-max-size`. Перевищення цього ліміту дозволено лише процесам, що мають можливість ядра `CAP_SYS_RESOURCE`.

## Глобальні параметри ядра: `/proc/sys/fs/`

Ядро Linux надає адміністратору системи три системні файли в ієрархії `sysctl` для глобального контролю споживання пам'яті каналами:

| Системний файл | Дефолтне значення | Опис призначення та алгоритму обліку |
| :--- | :--- | :--- |
| `/proc/sys/fs/pipe-max-size` | `1048576` (1 МіБ) | Верхня межа місткості кільцевого буфера для одного окремого каналу, яку непривілейований процес може встановити через `fcntl(F_SETPIPE_SZ)`. Значення повинно бути кратним `PAGE_SIZE`. |
| `/proc/sys/fs/pipe-user-pages-soft` | `16384` сторінок (64 МіБ) | М'який ліміт сумарної кількості сторінок пам'яті, виділених під буфери каналів одним реальним користувачем (за UID). При перевищенні ліміту створення нового каналу автоматично обмежує його місткість однією сторінкою (4 КіБ), а виклики `fcntl(F_SETPIPE_SZ)` відхиляються з помилкою `EPERM`. |
| `/proc/sys/fs/pipe-user-pages-hard` | `0` (не обмежено) | Жорсткий ліміт сумарної кількості сторінок під канали на одного користувача. При досягненні ліміту будь-яка спроба створити новий канал викликами `pipe()`, `pipe2()` або відкрити FIFO завершується аварійною помилкою `ENOMEM` або `EPERM`. |

## Матриця контрактів поведінки системних викликів

Поведінка системних операцій над каналами й FIFO є повністю детермінованою і регулюється трьома факторами: наявністю активного протилежного кінця, встановленими прапорцями блокування та наповненістю буфера.

### 1. Контракти відкриття іменованого каналу (`open`)

| Режим відкриття | Стан протилежного кінця | Результат виклику `open()` | Пояснення механіки ядра |
| :--- | :--- | :--- | :--- |
| `O_RDONLY` | Немає відкритих процесів на запис | **Блокується** | Процес засинає в черзі `pipe->rd_wait` до появи першого процесу, що виконає відкриття на запис. |
| `O_RDONLY` | Є відкриті процеси на запис | **Успіх** | Повертає дескриптор негайно, оскільки партнер по комунікації вже присутній. |
| `O_RDONLY \| O_NONBLOCK` | Немає процесів на запис | **Успіх** | Повертає дескриптор негайно. Дозволяє читачам запускатися раніше за письменників без блокування. |
| `O_WRONLY` | Немає відкритих процесів на читання | **Блокується** | Процес засинає в черзі `pipe->wr_wait` до моменту, коли читач відкриє цей FIFO. |
| `O_WRONLY` | Є відкриті процеси на читання | **Успіх** | Повертає дескриптор негайно, рукостискання завершено. |
| `O_WRONLY \| O_NONBLOCK` | Немає процесів на читання | **Помилка `-1`, `ENXIO`** | Негайна відмова (*No such device or address*). Ядро захищає процес від марного запису в канал без споживача. |
| `O_WRONLY \| O_NONBLOCK` | Є відкриті процеси на читання | **Успіх** | Повертає дескриптор, готовий до неблокуючого запису. |
| `O_RDWR` | Будь-який стан | **Успіх** | Негайно відкриває дескриптор на читання й запис. Дескриптор сам є партнером для себе; уникає блокування. |

### 2. Контракти операції читання (`read`)

| Стан буфера каналу | Лічильник письменників | Режим дескриптора | Результат `read(fd, buf, count)` |
| :--- | :--- | :--- | :--- |
| Є дані (`n > 0` байтів) | `writers >= 0` (будь-який) | Будь-який | Зчитує `min(count, n)` байтів, повертає кількість зчитаного. Байти видаляються з кільця. |
| Буфер порожній (`0` байтів) | `writers > 0` (партнер є) | Блокуючий | Процес засинає в черзі `rd_wait` до запису нових байтів або закриття всіх письменників. |
| Буфер порожній (`0` байтів) | `writers > 0` (партнер є) | `O_NONBLOCK` | Повертає помилку `-1`, `errno = EAGAIN` (або `EWOULDBLOCK`). |
| Буфер порожній (`0` байтів) | `writers == 0` (партнерів нема) | Будь-який | Повертає `0` (**EOF**, ознака кінця файлу). Читач коректно завершує обробку потоку. |

### 3. Контракти операції запису (`write`)

| Стан читачів | Розмір порції | Вільне місце в буфері | Режим дескриптора | Результат `write(fd, buf, count)` |
| :--- | :--- | :--- | :--- | :--- |
| `readers == 0` | Будь-який | Будь-який стан | Будь-який | Процесу надсилається сигнал `SIGPIPE`. Якщо сигнал перехоплено або проігноровано, повертає `-1`, `errno = EPIPE`. |
| `readers > 0` | `count <= PIPE_BUF` | Достатньо (`>= count`) | Будь-який | **Атомарний запис:** записує всі `count` байтів неподільно. Дані не змішуються з іншими процесами. |
| `readers > 0` | `count <= PIPE_BUF` | Недостатньо (`< count`) | Блокуючий | Процес засинає в черзі `wr_wait` до моменту, коли в буфері звільниться місце під весь пакет `count`. |
| `readers > 0` | `count <= PIPE_BUF` | Недостатньо (`< count`) | `O_NONBLOCK` | Повертає `-1`, `errno = EAGAIN`. Жоден байт не записується в буфер. |
| `readers > 0` | `count > PIPE_BUF` | Є вільне місце (`m > 0`) | Блокуючий | Записує доступні `m` байтів одразу, блокується на запис залишку. Дані можуть чергуватися з іншими записами. |
| `readers > 0` | `count > PIPE_BUF` | Є вільне місце (`m > 0`) | `O_NONBLOCK` | **Частковий запис:** записує `min(count, m)` байтів і повертає кількість реально збережених байтів. |
| `readers > 0` | `count > PIPE_BUF` | Буфер повний (`0` байтів) | `O_NONBLOCK` | Повертає `-1`, `errno = EAGAIN`. |

## Інтерфейси мультиплексування: семантика `poll`, `select` та `epoll`

Під час моніторингу дескрипторів каналів у мультиплексованих циклах подій (*event loops*) ядро генерує такі бітові маски подій:

### Для дескриптора читання (`pipefd[0]`):
- `POLLIN` / `EPOLLIN` — у кільцевому буфері є щонайменше 1 байт даних для зчитування;
- `POLLHUP` / `EPOLLHUP` — усі процеси-письменники закрили свої дескриптори запису. Подія активується автоматично й не вимагає явної реєстрації. Якщо в буфері ще лишилися байти, одночасно встановлюються і `POLLIN`, і `POLLHUP`: читач спочатку вичитує залишок, а при наступному `read()` отримує `0` (EOF);
- `POLLERR` — помилка стану каналу (наприклад, дескриптор відкрито не на читання).

### Для дескриптора запису (`pipefd[1]`):
- `POLLOUT` / `EPOLLOUT` — у кільцевому буфері є вільне місце щонайменше для запису однієї сторінки (4096 байтів) або для запису `PIPE_BUF`;
- `POLLERR` / `EPOLLERR` — усі читачі закрили свої дескриптори читання (`readers == 0`). Спроба запису призведе до `EPIPE`. Зверніть увагу: на дескрипторі запису закриття читачів викликає саме `POLLERR` (або комбінацію з `POLLHUP`), сигналізуючи про неможливість подальшого запису.

## Нульове копіювання: системні виклики `splice()`, `tee()` та `vmsplice()`

Підсистема каналів у ядрі Linux слугує апаратним транзитом для переміщення сторінок пам'яті між довільними дескрипторами без залучення простору користувача:

:::tabs
```c
#define _GNU_SOURCE
#include <fcntl.h>

ssize_t splice(int fd_in, loff_t *off_in, int fd_out, loff_t *off_out,
               size_t len, unsigned int flags);
ssize_t tee(int fd_in, int fd_out, size_t len, unsigned int flags);
ssize_t vmsplice(int fd, const struct iovec *iov, unsigned long nr_segs,
                 unsigned int flags);
```
```cpp
#include <fcntl.h>
#include <system_error>
#include <span>

ssize_t splice_zero_copy(int fd_in, int fd_out, size_t len, unsigned int flags) {
    ssize_t ret = ::splice(fd_in, nullptr, fd_out, nullptr, len, flags);
    if (ret < 0) throw std::system_error(errno, std::generic_category(), "splice failed");
    return ret;
}
```
:::

### Прапорці керування передачею:
- `SPLICE_F_MOVE` — надає підказку ядру спробувати перемістити фізичні сторінки пам'яті замість їх копіювання (з ядра Linux 2.6.21 має рекомендаційний характер);
- `SPLICE_F_NONBLOCK` — робить операцію перекачування неблокуючою: повертає `EAGAIN`, якщо сторінки не готові;
- `SPLICE_F_MORE` — оптимізація для мережевих сокетів: повідомляє ядру, що невдовзі надійдуть додаткові дані, що дозволяє відкласти відправку останнього TCP-пакета (аналог прапорця `MSG_MORE`);
- `SPLICE_F_GIFT` — використовується викликом `vmsplice()`: передає сторінки простору користувача у володіння ядру («дарунок» сторінки), уможливлюючи справжнє zero-copy з юзерспейсу.

## Структура інспекції стану `/proc/[pid]/fdinfo/[fd]`

Діагностичний шар ядра публікує внутрішній стан кільцевого буфера через текстові файли `fdinfo`:

```
pos:    0
flags:  08000
mnt_id: 15
ino:    98412
pipe-head: 28
pipe-tail: 12
pipe-bufs: 16
```

### Призначення та фізичний зміст полів:
- `pos` — поточна позиція у файлі. Для каналів завжди строго дорівнює `0`, оскільки канал є непозиціонованим потоком;
- `flags` — бітова маска прапорців дескриптора у вісімковому форматі (наприклад, `08000` відповідає `O_RDONLY | O_LARGEFILE`, `08001` — `O_WRONLY | O_LARGEFILE`);
- `mnt_id` — унікальний ідентифікатор точки монтування файлової системи, де зареєстровано інод (`pipefs` або диск);
- `ino` — номер інода в ядрі;
- `pipe-head` — поточне значення лічильника голови буфера (індекс наступного запису);
- `pipe-tail` — поточне значення лічильника хвоста буфера (індекс наступного зчитування);
- `pipe-bufs` — загальна виділена місткість буфера у сторінках пам'яті ядра.

Кількість зайнятих наразі слотів сторінок обчислюється як `pipe-head - pipe-tail`. Якщо ця різниця дорівнює значенню `pipe-bufs`, кільцевий буфер заповнений на 100%, і будь-який наступний блокуючий запис зупинить процес-письменник.

## Системні коди помилок (POSIX Errno)

| Символічний код | Номер | Опис першопричини помилки |
| :--- | :--- | :--- |
| `EAGAIN` / `EWOULDBLOCK` | 11 | Неблокуюча операція (`O_NONBLOCK`) не може бути виконана негайно через порожній буфер (читання) або переповнений буфер (запис). |
| `EPIPE` | 32 | Спроба запису в канал, у якому відсутні відкриті дескриптори читання (`readers == 0`). За замовчуванням супроводжується доставкою сигналу `SIGPIPE`. |
| `ENXIO` | 6 | Спроба відкрити іменований канал FIFO на неблокуючий запис (`O_WRONLY | O_NONBLOCK`) за повної відсутності відкритих читачів. |
| `EMFILE` | 24 | Процес досяг максимального дозволеного ліміту відкритих файлових дескрипторів (`RLIMIT_NOFILE`). |
| `ENFILE` | 23 | Вичерпано загальносистемний ліміт відкритої кількості файлів в операційній системі (`/proc/sys/fs/file-max`). |
| `EBUSY` | 16 | Спроба зменшити місткість буфера через виклик `fcntl(F_SETPIPE_SZ)` нижче обсягу даних, що вже очікують зчитування в буфері. |
| `EPERM` | 1 | Непривілейований процес без `CAP_SYS_RESOURCE` спробував встановити розмір буфера понад `/proc/sys/fs/pipe-max-size` або вичерпав квоту `pipe-user-pages-soft`. |
| `EINTR` | 4 | Сплячий системний виклик (`read`, `write` або `open`) було перервано доставкою сигналу процесу до передачі першого байта даних. |
| `ESPIPE` | 29 | Спроба викликати позиціонування зміщення `lseek()` над дескриптором каналу чи FIFO. |
