# 📋 Контракт прямого вводу-виводу: прапорці, числа, помилки

Це довідка по тому, що програма зобов'язується робити, вмикаючи `O_DIRECT`, і що ядро зобов'язується робити у відповідь: прапорці `open`, поля `statx`, з яких беруть вирівнювання, вимоги до буфера, перелік причин `EINVAL` — і окремо перелік випадків, де замість чесної відмови ядро мовчки виконує запит буферизовано. Контракт нерівний: майже всі зобов'язання лежать на програмі, а єдина обіцянка ядра не має гарантії.

Підписують його у трьох місцях, і в кожному є своя пастка.

| крок | чим | пастка |
|---|---|---|
| увімкнути прямий шлях | `open(…, O_DIRECT)` або `fcntl(fd, F_SETFL, …)` | успішний `open` не обіцяє, що обмін буде прямим |
| дізнатися числа вирівнювання | `statx(…, STATX_DIOALIGN, …)` | перевіряти треба `stx_mask`, а не лише код повернення |
| подати кожен запит | вирівняні адреса, зміщення й довжина | одне `EINVAL` на три різні причини, без підказки, яка спрацювала |

---

## Увімкнути й вимкнути

```c
#define _GNU_SOURCE          /* без цього <fcntl.h> не оголосить O_DIRECT */
#include <fcntl.h>

int fd = open(path, O_RDWR | O_DIRECT);
```

Числове значення прапорця залежить від архітектури, тож вписувати його константою не можна ніде — ні в С, ні в обгортках інших мов. Прапорець належить до змінюваних станових прапорців файлу: `fcntl` з `F_SETFL` вмикає й вимикає його на відкритому дескрипторі поряд з `O_APPEND`, `O_ASYNC`, `O_NOATIME` і `O_NONBLOCK` (а от `O_SYNC` і `O_DSYNC` після відкриття вже не змінити).

```c
int fl = fcntl(fd, F_GETFL);
fcntl(fd, F_SETFL, fl | O_DIRECT);   /* і назад, знявши прапорець */
```

Це єдиний спосіб змішати два режими на одному дескрипторі: наприклад, читати індекс буферизовано, а великі порції даних — прямо. Прапорець живе у відкритому описі файлу, тож перемикання видно всім дескрипторам, які цей опис поділяють — і в іншому потоці теж.

| прапорець | що робить | чого не робить |
|---|---|---|
| `O_DIRECT` | прибирає кеш сторінок з дороги даних | не доносить дані до пластини |
| `O_DSYNC` | кожен `write` повертається лише після того, як дані й потрібні для їх читання метадані опинилися на носії | не прибирає кешу |
| `O_SYNC` | те саме плюс решта метаданих (часи доступу) | не прибирає кешу |

Комбінація `O_DIRECT | O_DSYNC` — звичайне поєднання для того, хто хоче і власне керування пам'яттю, і довговічність.

**Коли відмовляє сам `open`:** одне `EINVAL` — «файлова система не вміє прямого обміну». Починаючи з ядра 6.0 перевірка робиться за ознакою `FMODE_CAN_ODIRECT`, яку файлова система виставляє файлові на відкритті (раніше VFS дивився на наявність операції `direct_IO` в адресному просторі). Так відповідає, наприклад, tmpfs: тримати кеш осторонь від файлу, який увесь і є пам'яттю, безглуздо.

## Три числа й де їх спитати

Чесний спосіб один — [statx](topic:unix-linux/statx-extended-stat) (розширений `stat` із маскою: програма просить конкретні поля, а ядро в тій самій масці відповідає, які з них справді заповнило).

```c
#define _GNU_SOURCE
#include <sys/stat.h>

int statx(int dirfd, const char *pathname, int flags,
          unsigned int mask, struct statx *statxbuf);

/* по вже відкритому дескриптору: */
statx(fd, "", AT_EMPTY_PATH, STATX_DIOALIGN, &stx);
```

| поле | тип | маска | з ядра | що означає |
|---|---|---|---|---|
| `stx_dio_mem_align` | `__u32` | `STATX_DIOALIGN` | 6.1 | вирівнювання **адреси буфера** в пам'яті; `0` — прямого обміну на цьому файлі немає |
| `stx_dio_offset_align` | `__u32` | `STATX_DIOALIGN` | 6.1 | вирівнювання **зміщень і довжин**; ненульове тоді й лише тоді, коли ненульове попереднє |
| `stx_dio_read_offset_align` | `__u32` | `STATX_DIO_READ_ALIGN` | 6.14 | окреме, слабше вирівнювання зміщень і довжин **для читання**; `0` означає «те саме, що й для запису» |

Дисципліна перевірки тут з двох кроків, і другий забувають постійно: спершу `statx` має повернути нуль, а тоді в `stx.stx_mask` має стояти запитаний біт. Ядро молодше за 6.1, файлова система без підтримки або блоковий пристрій, який не звітує, — усі ці випадки виглядають як успішний виклик із **знятим** бітом у масці, а не як помилка. Поля в такому разі — сміття або нулі.

Порядок звертань, коли маски немає:

| джерело | інтерфейс | що дає |
|---|---|---|
| ядро ≥ 6.1, ext4 / XFS / f2fs / блокові пристрої | `statx(STATX_DIOALIGN)` | обидва числа, окремо для кожного файлу |
| XFS будь-якого віку | `ioctl(fd, XFS_IOC_DIOINFO, &da)` — [ioctl](topic:unix-linux/ioctl-interface) | `struct dioattr { __u32 d_mem; __u32 d_miniosz; __u32 d_maxiosz; }`: вирівнювання буфера, вирівнювання зміщень і довжин, **стеля розміру запиту** — числа, якого в `statx` немає взагалі |
| сирий [блоковий пристрій](topic:unix-linux/block-device-model) | `ioctl(fd, BLKSSZGET, &n)`, `/sys/block/<пристрій>/queue/logical_block_size` | логічний розмір сектора: те, чим оперує пристрій |
| нічого з переліченого | припущення 4096 | працює скрізь, коштує зайвого читання на файлових системах із меншим блоком |

Числа для блокового пристрою ядро складає з двох різних величин: вирівнювання зміщень — це логічний розмір блока, а вирівнювання буфера — [DMA-вирівнювання](topic:unix-linux/dma-and-buffers) черги пристрою (контролер уміє забирати дані лише з адрес, кратних певному числу), плюс одиниця, бо всередині воно зберігається маскою. Саме тому з ядра 6.0 вимога до пам'яті ослабла: буфер більше не мусить бути вирівняний на сектор, досить DMA-вирівнювання, часто це 512, а подекуди й менше. XFS підтягнув свій `d_mem` до цієї ж величини в 2024 році — після того, як драйвер DASD на s390 підняв свою вимогу й програми, вирівняні «на сектор», раптом перестали працювати.

## Буфер

```c
#include <stdlib.h>

int   posix_memalign(void **memptr, size_t alignment, size_t size);
void *aligned_alloc(size_t alignment, size_t size);   /* C11 */
```

`posix_memalign` повертає код помилки **значенням** і не чіпає `errno`; `aligned_alloc` вимагає, щоб `size` була кратна `alignment`. Звільняють обидва звичайним `free`.

Дві вимоги, які не видно з сигнатур. Перша: `alignment` для `posix_memalign` має бути степенем двійки і **кратним `sizeof(void *)`** — а повідомлене DMA-вирівнювання цілком може виявитися меншим за 8, і виклик відмовить `EINVAL` на цілком правильному числі. Друга: жодне з цих чисел не є оптимальним, воно лише мінімальне. Практичне правило звідси таке: беріть максимум із повідомленого числа й розміру сторінки. Сторінка задовольняє всі три вимоги одразу, зменшує кількість шматків у списку розсіювання для пристрою і не коштує майже нічого.

Для дуже великих буферів пряме `mmap` з `MAP_ANONYMOUS` дає ту саму вирівняність без посередництва розподільника, а `io_uring` дозволяє закріпити буфери один раз наперед і далі посилатися на них номером ([io_uring](topic:unix-linux/io-uring) — кільця подань і завершень у спільній пам'яті; заздалегідь зареєстрований буфер прибирає закріплення сторінок з кожної окремої операції).

## Кожен окремий запит

| що | вимога | чим міряти |
|---|---|---|
| адреса буфера | кратна `stx_dio_mem_align` | і кожен `iov_base` у векторних викликах теж |
| зміщення у файлі | кратне `stx_dio_offset_align` (для читання — `stx_dio_read_offset_align`, якщо ненульове) | зміщення дескриптора після `lseek` рахується так само |
| довжина запиту | кратна тому самому числу | і кожен `iov_len` окремо, а не лише їхня сума |

| помилка | причина |
|---|---|
| `EINVAL` | не збіглося щось одне з трьох; яке саме — ядро не каже |
| `EFAULT` | адреса буфера недоступна процесу |
| `EAGAIN` | `RWF_NOWAIT` і дані не готові негайно |
| `EOPNOTSUPP` | невідомий прапорець `RWF_*` або `RWF_DONTCACHE` там, де його не вміють |
| `EIO`, `ENOSPC` | справжня відмова носія чи файлової системи — до вирівнювання стосунку не має |

**Кратна має бути довжина запиту, а не відповідь.** Читання, що впирається в кінець файлу, законно повертає коротке число — і це не помилка, а звичайна семантика `read`. Дзеркальний випадок із записом складніший: щоб дописати файлу хвіст у 300 байтів, доводиться записати цілий вирівняний блок (доповнивши його чим завгодно) і потім `ftruncate` поставити справжню довжину. Виклик `ftruncate` — це вже зміна метаданих, вона йде звичайним буферизованим шляхом і вимагає `fdatasync`, щоб пережити зникнення живлення.

## Прапорці на окремий запит

`preadv2`/`pwritev2` приймають прапорці на одну операцію, і три з них прямо пов'язані з прямим обміном.

```c
#define _GNU_SOURCE
#include <sys/uio.h>

ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
```

| прапорець | з ядра | що робить |
|---|---|---|
| `RWF_HIPRI` | 4.6 | опитування пристрою замість очікування переривання; **працює лише на дескрипторі з `O_DIRECT`** |
| `RWF_ATOMIC` | 6.11 | запис або відбудеться цілком, або не відбудеться зовсім (без розриву посередині); довжина — степінь двійки в межах `stx_atomic_write_unit_min…max` і природно вирівняна; **вимагає `O_DIRECT`**, буферизованого варіанта немає |
| `RWF_DSYNC`, `RWF_SYNC` | 4.7 | те саме, що `O_DSYNC`/`O_SYNC`, але на один запис |
| `RWF_DONTCACHE` | 6.14 | буферизований обмін, після завершення якого ядро **саме викидає** ті сторінки, яких до операції в кеші не було; `EOPNOTSUPP` там, де не підтримано |

Останній вартий уваги окремо: він дає рівно те, чого хоче копіювання великого файлу — не засмітити чужий кеш, — не вимагаючи ані вирівнювання, ані глибини черги, ані власного кешу. Це не заміна прямому обміну для того, у кого свій буферний пул, але для потокової роботи це дешевша відповідь на те саме питання.

## Де контракт виконують не так, як написано

`O_DIRECT` — прохання, а не гарантія, і мовчазне повернення до буферизованого шляху трапляється частіше, ніж чесна відмова.

| випадок | що буде |
|---|---|
| ext4, `data=ordered` або `data=writeback` (типово) | справжній прямий обмін |
| ext4, `data=journal` | `open` успішний, кожен запит іде через кеш; у самому ядрі цей режим названо підробленим прямим обміном, а записи поводяться як буферизовані `O_DSYNC` |
| ext4, малий файл, укладений в inode (inline data) | те саме: даних поза inode ще немає, обходити нема чого |
| Btrfs, стиснені файли | прямого обміну немає — байти на носії не збігаються з байтами у файлі |
| Btrfs, профіль даних із дублюванням (RAID1, RAID10, RAID56) | **прямий запис** повертається до буферизованого: інакше програма, яка змінить буфер посеред обміну, залишить копії з різним умістом. Зміну внесено в гілці 6.19 |
| зашифровані файли (fscrypt) | прямий обмін можливий лише там, де шифрує сам блоковий шар (inline crypto); інакше `statx` чесно поверне нулі |
| XFS | найповніша підтримка; з 6.14 звітує окреме, слабше вирівнювання для читання |
| NFS | працює, але обходить лише кеш **клієнта**: протокол не має способу передати прохання серверові, і той кешує на власний розсуд |
| tmpfs | `open` відмовляє `EINVAL` |

Питати про це треба `statx`, а не документацію дистрибутива: нулі в обох полях означають «прямого обміну на цьому файлі немає» незалежно від причини. А перевірити результат емпірично дає `fincore` з util-linux — вона показує, скільки сторінок файлу зараз у кеші (через `cachestat(2)` на ядрах від 6.5, інакше через `mincore(2)`). Прочитали файл із `O_DIRECT`, і `fincore` показує ненульове число — прапорець не спрацював.

## Чого прапорець не робить

| хиба | як насправді |
|---|---|
| «прямий запис — це записаний» | контролер накопичувача підтверджує запис, коли дані лягли в його власний енергозалежний буфер; скидає цей буфер `fsync`/`fdatasync` або `O_DSYNC`, і ніяк інакше ([кеш сторінок, fsync і довговічність запису](topic:unix-linux/page-cache-durability) — де саме закінчується обіцянка кожного виклику) |
| «метадані теж ідуть прямо» | ні: виділення блоків, зміна розміру та журнал файлової системи йдуть звичайним шляхом. Тому місце виділяють наперед через `fallocate` ([керування виділенням блоків](topic:unix-linux/file-block-allocation/api-allocation-controls.md) — виклики, прапорці монтування й ручки, якими впливають на розміщення), щоб робочі записи метаданих не чіпали зовсім |
| «можна робити `fork` під час обміну» | не можна: сторінки буфера закріплено, а [копіювання під час запису](topic:unix-linux/copy-on-write) після `fork` розводить батька й дитину по різних фізичних сторінках — і завершений обмін може лягти не в ту з них. Обмін закінчують до `fork` або позначають буфер `MADV_DONTFORK`. На спільних відображеннях (`MAP_SHARED`, `shmat`) обмеження немає |
| «`O_DIRECT` і `mmap` можна поєднати» | документація прямо радить не змішувати їх на одному файлі: два шляхи по-різному відповідають на питання, де лежить справжня копія даних |

## Мінімальний робочий виклик

Читання довільної ділянки прямим шляхом: спитати числа, розширити діапазон до меж, узяти вирівняний буфер, вирізати з нього потрібне.

```c
#define _GNU_SOURCE
#include <fcntl.h>
#include <sys/stat.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

/* 0 у mem — прямого обміну на цьому файлі немає. */
struct dio_align { unsigned mem, off; };

static void dio_query(int fd, struct dio_align *a)
{
    struct statx stx;
    a->mem = a->off = 4096;                       /* безпечне припущення */

    if (statx(fd, "", AT_EMPTY_PATH, STATX_DIOALIGN, &stx) != 0)
        return;                                   /* ядро < 4.11 */
    if (!(stx.stx_mask & STATX_DIOALIGN))
        return;                                   /* ядро < 6.1 або ФС мовчить */

    a->mem = stx.stx_dio_mem_align;               /* 0 — прямого обміну немає */
    a->off = stx.stx_dio_offset_align;
}

/* Кладе в out до len байтів з позиції pos. Повертає, скільки поклав. */
ssize_t dio_pread(int fd, void *out, size_t len, off_t pos,
                  struct dio_align a)
{
    if (a.off == 0) return -1;                    /* прямого обміну на файлі немає */

    size_t page  = (size_t)sysconf(_SC_PAGESIZE);
    size_t align = a.mem > page ? a.mem : page;   /* ≥ sizeof(void*), ≥ сторінки */

    off_t  first = pos - (pos % a.off);                       /* униз до межі */
    off_t  last  = ((pos + (off_t)len + a.off - 1) / a.off) * a.off;
    size_t span  = (size_t)(last - first);

    void *buf;
    if (posix_memalign(&buf, align, span) != 0)   /* код помилки — значенням */
        return -1;

    ssize_t got = pread(fd, buf, span, first);    /* EINVAL — вирівнювання */
    if (got < 0) { free(buf); return -1; }

    size_t skip = (size_t)(pos - first);
    if ((size_t)got <= skip) { free(buf); return 0; }   /* усе за кінцем файлу */

    size_t have = (size_t)got - skip;
    if (have > len) have = len;
    memcpy(out, (char *)buf + skip, have);
    free(buf);
    return (ssize_t)have;
}
```

Копіювання `memcpy` наприкінці — саме те, від чого прямий обмін мав позбавити, і воно тут не випадкове: воно з'являється рівно тоді, коли програма просить невирівняну ділянку. Контракт виконується безкоштовно лише для того, хто сам оперує цілими блоками — тобто хто вже має власний буферний пул із блоками потрібного розміру.
