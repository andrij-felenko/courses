# 📋 Повний довідник параметрів, sysfs-інтерфейсів та прапорців IO polling

Цей довідник містить вичерпний опис системних параметрів ядра, атрибутів sysfs блокових пристроїв, прапорців системних викликів та конфігурацій `io_uring`, які контролюють активацію, налаштування черг та режим опитування (IO polling) у Linux. Орієнтація у цих параметрах необхідна для точного тюнінгу продуктивності дискової підсистеми NVMe.

## 1. Параметри модуля драйвера NVMe (`nvme.ko`)

Підтримка апаратного поллінгу у драйвері `nvme` вимагає виділення окремих апаратних черг (Hardware Queues), на яких драйвер вимикає обробку апаратних переривань (MSI-X IRQ vector = -1). Це налаштовується під час завантаження модуля ядра `nvme`.

### `nvme.poll_queues`
Вказує кількість апаратних poll-черг, що виділяються для кожного контролера NVMe, підключеного до системи. 

* **Тип даних:** `unsigned int`
* **Значення за замовчуванням:** `0` (поллінг-черги не виділяються).
* **Призначення:** Ці черги резервуються виключно для I/O запитів, маркованих прапорцем поллінгу (`RWF_HIPRI` або `IORING_SETUP_IOPOLL`). Вони не отримують векторів переривань MSI-X від контролера переривань APIC.
* **Механізм роботи:** При ініціалізації NVMe контролера драйвер узгоджує з контролером кількість апаратних черг (команда Set Features, Number of Queues). Виділення здійснюється за формулою:
  `default_queues = total_queues - poll_queues - write_queues`
  Якщо `poll_queues=4` на 16-ядерній системі з 16 апаратними чергами, драйвер виділить 12 стандартних черг з перериваннями та 4 черги без переривань для поллінгу.

### `nvme.write_queues`
Вказує кількість виділених апаратних черг виключно для операцій запису.

* **Тип даних:** `unsigned int`
* **Значення за замовчуванням:** `0` (черги читання та запису є спільними).
* **Вплив на поллінг:** Якщо задано `write_queues > 0`, черги запису також не перетинаються з poll-чергами, що дозволяє уникнути взаємних блокувань при інтенсивному змішаному навантаженні.

### `nvme.max_host_mem_size_mb`
Максимальний розмір буфера Host Memory Buffer (HMB) у мегабайтах, який контролер NVMe може використовувати у системній оперативній пам'яті хоста.

* **Тип даних:** `unsigned int`
* **Вплив на поллінг:** Допомагає бюджетним накопичувачам без власної DRAM (DRAM-less NVMe) зберігати внутрішні таблиці трансляції адрес у пам'яті хоста, зменшуючи затримку опитування при високочастотному поллінгу.

### Конфігураційні файли ядра
Для постійного збереження параметрів створюється файл конфігурації у `/etc/modprobe.d/nvme.conf`:

```bash
# Виділити 4 апаратні черги для IO polling на кожен NVMe диск
options nvme poll_queues=4
```

Для того щоб нові параметри застосувалися при завантаженні операційної системи (якщо диск є кореневим), необхідно оновити образ `initramfs`:

```bash
# Для дистрибутивів Ubuntu / Debian
update-initramfs -u

# Для дистрибутивів RHEL / Fedora / Rocky
dracut --force
```

## 2. Атрибути sysfs блокового пристрою (`/sys/block/<dev>/queue/`)

Кожен блоковий пристрій у файловій системі `sysfs` має групу управляючих атрибутів у каталозі `/sys/block/<dev>/queue/`, які дозволяють налаштовувати поведінку поллінгу у реальному часі без перезавантаження драйвера.

### `/sys/block/<dev>/queue/io_poll`
Керує дозволом виконання поллінгу для даного блокового пристрою (наприклад, `nvme0n1`).

* **`0` (Disabled):** Polling повністю вимкнено для даного пристрою. Будь-які запити з прапорцями `RWF_HIPRI` або `IORING_SETUP_IOPOLL` мовчки перенаправляються у звичайні черги з перериваннями.
* **`1` (Enabled):** Polling дозволено. Запити з прапорцем поллінгу маршрутизуються у виділені poll-черги контролера.

Від ядра 5.19 запис у цей файл ігнорується: опитування доступне тоді й лише тоді, коли драйвер виділив poll-черги, тож атрибут лишився фактично для читання.

Приклад читання та зміни атрибута у консолі:
```bash
# Перевірити поточний стан
cat /sys/block/nvme0n1/queue/io_poll

# Увімкнути підтримку поллінгу
echo 1 > /sys/block/nvme0n1/queue/io_poll
```

### `/sys/block/<dev>/queue/io_poll_delay`
Контролює алгоритм затримки перед початком активного опитування (Hybrid Polling).

* **`-1` (Classic Polling, значення за замовчуванням):** Гібридної затримки немає. Потік негайно входить у 100% spin loop в ядрі одразу після відправлення запиту у контролер. Забезпечує мінімально можливу затримку за рахунок максимального споживання CPU.
* **`0` (Hybrid Polling):** Ядро використовує статистичний алгоритм передбачення затримок на основі ковзного середнього (`mean_lat`). Потік засинає за допомогою `hrtimer` приблизно на половину очікуваного часу затримки, після чого входить у цикл активного опитування.
* **`>0` (Fixed Delay in Microseconds):** Задає фіксований час сну потоку у мікросекундах перед початком опитування. Наприклад, якщо встановлено значення `5`, потік завжди засинатиме на 5 мікросекунд, а потім починатиме активно опитувати Completion Queue.

У ядрах від 6.3 гібридне опитування з блокового шару вилучено: сну перед спіном більше немає, а сам атрибут лишився заради сумісності.

Приклад налаштування фіксованої гібридної затримки:
```bash
# Встановити затримку сну 4 мікросекунди
echo 4 > /sys/block/nvme0n1/queue/io_poll_delay
```

## 3. Прапорці системних викликів користувача (Userspace I/O Flags)

Для передачі ядру сигналу про необхідність обробки запиту через поллінг використовуються розширені системні виклики синхронного вводу-виводу.

### `preadv2(2)` та `pwritev2(2)`

Системні виклики дозволяють виконувати векторне читання та запис із передачею додаткових прапорців поведінки у параметрі `flags`.

:::tabs
```c
#include <sys/uio.h>
#include <fcntl.h>

ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
```
```cpp
#include <sys/uio.h>
#include <fcntl.h>

/* Сигнатура POSIX / Linux системного виклику preadv2 */
extern "C" ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                           off_t offset, int flags);
```
:::

#### Опис прапорця `RWF_HIPRI`
* **Константа:** `RWF_HIPRI` (High Priority / Polled I/O).
* **Поведінка:** Сигналізує ядру про необхідність виконання запиту у режимі активного опитування. Системний виклик виконує spin loop у ядрі CPU і повертає керування лише після того, як контролер записав результат у буфер пам'яті.
* **Вимоги:** Файл або блоковий пристрій має бути відкрито з прапорцем `O_DIRECT`. Якщо файл відкрито у режимі буферизованого I/O, виклик повертає `-EOPNOTSUPP` (у старіших ядрах прапорець просто ігнорувався).

#### Взаємодія з іншими прапорцями вводу-виводу
* **`O_DIRECT` + `RWF_HIPRI`**: Стандартна та обов'язкова комбінація для виконання поллінгу. Запит обходить page cache та вирушає прямо у поллінг-чергу.
* **`RWF_DSYNC` + `RWF_HIPRI`**: Гарантує, що операція запису даних на носій буде виконана із застосуванням поллінгу для очікування завершення синхронізації флеш-пам'яті контролера.
* **`RWF_NOWAIT` + `RWF_HIPRI`**: Повертає помилку `-EAGAIN`, якщо виконання операції вимагатиме блокування на рівні файлової системи або виділення пам'яті, уникаючи будь-яких затримок на блокуваннях.

#### Коди помилок при роботі з `RWF_HIPRI`
* **`-EINVAL`**: Повертається при некоректному вирівнюванні буфера `iovec`, довжини або зміщення для `O_DIRECT`.
* **`-EOPNOTSUPP`**: Повертається, якщо підсистема блокового пристрою чи файлова система не підтримують виконання поллінгу.
* **`-EAGAIN`**: Виникає при вичерпанні доступних елементів у черзі відправлення під час неблокувального асинхронного запиту.

## 4. Прапорці та параметри конфігурації `io_uring`

Асинхронний інтерфейс `io_uring` підтримує глибоку інтеграцію з `blk-mq iopoll` через розширені прапорці ініціалізації кільця.

### Поля `struct io_uring_params`

Під час виклику `io_uring_queue_init_params()` застосунок передає структуру параметрів `struct io_uring_params`.

| Прапорець | Опис та семантика |
| :--- | :--- |
| `IORING_SETUP_IOPOLL` | Переводить все кільце `io_uring` у режим IO Polling. Усі запити читання та запису, що надсилаються через це кільце, автоматично маркуються ядром як polled I/O і спрямовуються у poll-черги пристрою. Отримання результатів завершення через `io_uring_enter()` запускає процес опитування. |
| `IORING_SETUP_SQPOLL` | Створює спеціалізований потік ядра `io_uring-sq`, який виконує активний поллінг Submission Queue (SQ) у оперативній пам'яті. Дозволяє подавати I/O запити взагалі без системних викликів `enter`. |
| `IORING_SETUP_SQ_AFF` | Задає прив'язку потоку ядра `SQPOLL` до конкретного фізичного ядра CPU (`params.sq_thread_cpu`). Використовується у комбінації з `IORING_SETUP_SQPOLL` для виключення міжпроцесорного переміщення потоку ядра. |

### Прапорці системного виклику `io_uring_enter(2)`

:::tabs
```c
#include <linux/io_uring.h>

int io_uring_enter(unsigned int fd, unsigned int to_submit,
                   unsigned int min_complete, unsigned int flags,
                   sigset_t *sig);
```
```cpp
#include <linux/io_uring.h>

extern "C" int io_uring_enter(unsigned int fd, unsigned int to_submit,
                              unsigned int min_complete, unsigned int flags,
                              sigset_t *sig);
```
:::

#### Прапорець `IORING_ENTER_GETEVENTS`
При роботі з кільцем, створеним із прапорцем `IORING_SETUP_IOPOLL`, виклик `io_uring_enter()` із прапорцем `IORING_ENTER_GETEVENTS` змушує потік ядра виконувати внутрішній цикл `blk_poll()`, поки у Completion Queue не з'явиться принаймні `min_complete` подій завершення.

## 5. Внутрішні структури даних ядра Linux

Для забезпечення роботи опитування ядро Linux оперує наступними ключовими структурами даних:

### `struct blk_mq_hw_ctx`
Представляє управляючий контекст апаратної черги блокового пристрою.

* **`type`**: Поле типу черги (`HCTX_TYPE_DEFAULT`, `HCTX_TYPE_READ`, `HCTX_TYPE_POLL`).
* **`queue_num`**: Фізичний номер апаратної черги контролера NVMe.
* **`tags`**: Вказівник на таблицю розподілу тегів запитів `struct blk_mq_tags`.

### `blk_qc_t` (block queue cookie)
32-бітне кукі, яке функція `submit_bio()` повертала для запитів із поллінгом. До ядра 5.19 воно пакувало в собі адресу конкретного запиту:

* **Біти 0–15**: Номер тегу запиту (`tag`).
* **Біти 16–30**: Індекс апаратної черги (`hctx_idx`).
* **Біт 31**: Ознака `BLK_QC_T_INTERNAL` — тег належить внутрішньому планувальнику вводу-виводу, а не апаратній черзі.

Від 5.19 опитування стало bio-орієнтованим: кукі звузилося до самого лише індексу апаратної черги, а потрібне завершення драйвер знаходить, розгрібаючи чергу завершень цілком.

## 6. Діагностичні сутності sysfs, debugfs та /proc

Для моніторингу та інспекції стану поллінг-черг у реальному часі використовуються файлові структури `procfs`, `sysfs` та `debugfs`.

### Каталог апаратних черг `/sys/block/<dev>/mq/`
У каталозі `/sys/block/<dev>/mq/` відображаються всі апаратні черги пристрою `hctx0`, `hctx1`, ..., `hctxN`.

* **`/sys/block/<dev>/mq/<N>/type`**: Відображає тип апаратної черги. Значення `default` вказує на чергу з перериваннями, значення `poll` — на виділену чергу без переривань.
* **`/sys/block/<dev>/mq/<N>/cpu_list`**: Список ядер CPU, закріплених за даною апаратною чергою.
* **`/sys/block/<dev>/mq/<N>/tags`**: Відображає статус зайнятості тегів у даній апаратній черзі (активні та резервні теги).
* **`/sys/block/<dev>/mq/<N>/nr_reserved_tags`**: Кількість тегів, резервованих для високопріоритетних системних запитів.

### DebugFS інспекція черг `/sys/kernel/debug/block/`
Якщо файлову систему `debugfs` змонтовано, у `/sys/kernel/debug/block/<dev>/` доступна детальна внутрішня статистика:

* **`state`**: Поточний стан черги (наприклад, `QUIESCED` або `RUNNING`).
* **`hctx*/active`**: Кількість активних I/O запитів, що знаходяться на стадії обробки або опитування.
* **`hctx*/cpu*/rq_list`**: Список запитів, згрупованих по ядрах CPU.

### `/proc/interrupts`
Файл містить лічильники апаратних переривань для всіх векторів MSI-X у системі.

Приклад перевірки відсутності переривань під час виконання поллінгу:
```bash
# Відстежувати динаміку переривань NVMe пристрою
watch -n1 "cat /proc/interrupts | grep nvme"
```
Якщо під час виконання бенчмарку з поллінгом лічильник переривань відповідного вектора NVMe не зростає, це є підтвердженням того, що запити успішно обробляються через поллінг-черги.

## 7. Параметри віртуалізованого вводу-виводу та cgroups

Для віртуальних середовищ та систем із контейнеризацією діють додаткові контрольні точки конфігурації.

### `virtio_blk.poll_queues`
Модульний параметр драйвера `virtio_blk`, який регулює виділення поллінг-черг у гостьових віртуальних машинах KVM.

* **Налаштування:** `options virtio_blk poll_queues=4`
* **Семантика:** Виділяє віртуальні ring-черги `virtqueue` без віртуальних переривань (VIRQ / VM-Exit), дозволяючи гостьовій ОС виконувати прямий поллінг буферів гіпервізора.

### `/sys/fs/cgroup/<group>/io.stat`
Показує метрики вводу-виводу для конкретної cgroup v2 контрольної групи.

* **`rbytes` / `wbytes`**: Кількість прочитаних та записаних байтів.
* **`rios` / `wios`**: Кількість виконаних операцій читання та запису.
* **Аналіз поллінгу:** Затримок дроселювання сам `io.stat` не показує: щоб побачити, що запити групи чекали у `blk-throtl`, а не опитувалися, дивляться на `io.pressure` (PSI) або на трасування `block:block_rq_issue`. Задроселений запит присипляє потік, і прапорець `RWF_HIPRI` для нього не діє.

## 8. Внутрішні поля структур `struct io_uring_sqe` та `struct io_uring_cqe`

При відправленні та отриманні опитуваних I/O запитів через `io_uring` ключову роль відіграють наступні поля бінарних структур двох кілець — подання та завершення:

### `struct io_uring_sqe` (Submission Queue Entry)
* **`opcode`**: Код операції I/O. Для поллінгу використовуються `IORING_OP_READV`, `IORING_OP_WRITEV`, `IORING_OP_READ_FIXED` або `IORING_OP_WRITE_FIXED`.
* **`rw_flags`**: Прапорці специфічні для читання/запису. Дозволяє передавати `RWF_HIPRI` для поодиноких запитів.
* **`user_data`**: 64-бітне користувацьке поле (покажчик або тег), яке без змін повертається у Completion Queue.
* **`ioprio`**: Пріоритет I/O операції. Може використовуватися для пріоритетної вибірки команд у поллінг-чергах.

### `struct io_uring_cqe` (Completion Queue Entry)
* **`user_data`**: Маркер, скопійований із відповідного SQE запиту, який ідентифікує завершену операцію.
* **`res`**: Результат виконання I/O операції. Містить кількість успішно зчитаних/записаних байтів або від'ємний код помилки (наприклад, `-EIO`, `-EAGAIN`).
* **`flags`**: Додаткові прапорці завершення (наприклад, `IORING_CQE_F_MORE` для потокових подій).
