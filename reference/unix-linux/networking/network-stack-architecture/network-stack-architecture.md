# Мережевий стек ядра Linux

<preknowlist>
- [Системні виклики та VFS](topic:unix-linux/kernel-and-userspace) — взаємодія ядра з програмами.
</preknowlist>

Мережевий стек Linux — це складна система, що забезпечує доставку даних від програми (сокета) до мережевого кабелю (NIC) і навпаки. Його головна архітектурна мета — пропустити мільйони пакетів за секунду з мінімальним навантаженням на процесор.

Для цього стек покладається на кілька ключових механізмів: структуру безкопіювання `sk_buff` та гібридну систему переривань і опитування NAPI.

## Структура пакета: `sk_buff`

Кожен мережевий пакет у ядрі представлений структурою `sk_buff` (socket buffer). Вона складається з метаданих та самого буфера з даними. 

Щоб додати чи прибрати заголовки (Ethernet, IP, TCP) під час руху пакета по рівнях моделі OSI, ядро **не копіює дані**. Натомість воно просто зсуває спеціальні вказівники (`data`, `tail`) всередині виділеного буфера. Це кардинально економить ресурси.

## Шлях відправлення (TX)

Коли ви викликаєте `send()` у вашій програмі:
1. **Сокет:** Дані копіюються з програми в пам'ять ядра, формується `sk_buff`.
2. **L4 (TCP/UDP):** Дані розбиваються на сегменти, додається TCP-заголовок.
3. **L3 (IP):** Ядро визначає маршрут (FIB), додає IP-заголовок. Пакет може змінити Netfilter (наприклад, для NAT).
4. **qdisc та Драйвер:** Пакет стає в чергу Traffic Control. Драйвер мережевої карти повідомляє обладнанню (NIC), що є нові дані. NIC через DMA (Direct Memory Access) вичитує пакет з пам'яті та відправляє його в мережу.

## Шлях отримання (RX) та NAPI

Отримання пакетів — найважча робота. Якщо кожен з мільйонів пакетів викликатиме апаратне переривання (HardIRQ), процесор зупиниться (це називається Interrupt Storm).

Тому Linux використовує механізм **NAPI**:
1. Коли приходить перший пакет, NIC генерує переривання.
2. Ядро одразу **вимикає подальші переривання** від цієї карти.
3. Ядро переходить у режим **опитування (polling)**: воно швидко витягує пакети з кільцевого буфера NIC один за одним. 
4. Лише коли черга порожня, переривання знову вмикаються.

Пакети збираються разом (GRO), проходять через L3 (перевірка IP) та L4 (TCP), після чого потрапляють у чергу сокета. Тоді ваша програма (яка чекала на `recv()`) прокидається і читає їх.

## Надшвидкі альтернативи: XDP

Якщо швидкості класичного стека недостатньо, застосовують **XDP (eXpress Data Path)**. Це технологія, що дозволяє запускати eBPF-програми безпосередньо всередині драйвера мережевої карти. 

XDP-програма бачить сирі байти пакета ще до того, як ядро створить `sk_buff`. Це дозволяє відкидати шкідливий трафік (DDoS-захист) або перенаправляти його зі швидкістю, що дорівнює апаратній межі мережевої карти.
