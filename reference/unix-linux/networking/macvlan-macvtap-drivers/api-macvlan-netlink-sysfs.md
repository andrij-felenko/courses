# 📋 Специфікація RTNetlink ABI та sysfs-структур Macvlan/Macvtap

Ця довідкова специфікація надає вичерпний опис бінарного контракту ABI (Application Binary Interface), атрибутів RTNetlink, параметрів файлової системи `sysfs` та системних `ioctl`-команд символьних пристроїв для керування драйверами Macvlan та Macvtap у ядрі Linux.

---

## 1. Атрибути RTNetlink (`linux/if_link.h`)

Під час обміну повідомленнями `RTM_NEWLINK`, `RTM_SETLINK` та `RTM_GETLINK` атрибути драйвера Macvlan передаються всередині вкладеного контейнера `IFLA_INFO_DATA`, коли значення `IFLA_INFO_KIND` дорівнює рядному ідентифікатору `"macvlan"` або `"macvtap"`.

### Детальний опис атрибутів `IFLA_MACVLAN_*`

Підсистема RTNetlink використовує наступний перелік ключів для передачі параметрів конфігурації у ядро:

- **`IFLA_MACVLAN_UNSPEC` (0):** Резервний тип атрибута. Використовується за замовчуванням для маркування порожніх або неініціалізованих блоків пам'яті в масиві атрибутів ядра. Спроба передати цей атрибут під час конфігурації ігнорується парсером ядра.
- **`IFLA_MACVLAN_MODE` (1):** 32-бітове ціле число (`uint32_t`), яке задає режим обробки пакетів драйвером (Private, VEPA, Bridge, Passthrough або Source). Значення визначається константами з переліку `enum macvlan_mode`. Якщо атрибут не вказано при створенні інтерфейсу через `RTM_NEWLINK`, ядро за замовчуванням встановлює режим `MACVLAN_MODE_VEPA`.
- **`IFLA_MACVLAN_FLAGS` (2):** 16-бітове ціле число (`uint16_t`), яке визначає додаткові бітові прапорці поведінки драйвера (наприклад, вимкнення автоматичного переходу батьківського NIC у promiscuous mode).
- **`IFLA_MACVLAN_MACADDR_MODE` (3):** 32-бітове ціле число (`uint32_t`), що задає режим фільтрації MAC-адрес джерел при використанні `MACVLAN_MODE_SOURCE`. Визначає, чи додаються нові адреси до дозволеного списку, чи замінюють увесь наявний список.
- **`IFLA_MACVLAN_MACADDR` (4):** Масив з 6 байтів (`uint8_t[6]`), який містить конкретну Ethernet MAC-адресу для додавання або видалення зі списку дозволених джерел.
- **`IFLA_MACVLAN_MACADDR_DATA` (5):** Вкладений атрибут-контейнер (`nested rtattr`), що містить список усіх зареєстрованих MAC-адрес джерел. Використовується для пакетного оновлення списку фільтрації джерел.
- **`IFLA_MACVLAN_MACADDR_COUNT` (6):** 32-бітове ціле число (`uint32_t`), яке повертає поточну кількість записів у списку фільтрації MAC-адрес (read-only атрибут, який повертається ядром при виконанні команди `RTM_GETLINK`).
- **`IFLA_MACVLAN_BC_QUEUE_LEN` (7):** 32-бітове ціле число (`uint32_t`), яке встановлює максимальну довжину кільцевої черги обробки широкомовних (Broadcast) та багатоадресних (Multicast) пакетів. Значення за замовчуванням становить 1000 пакетів. Збільшення цього значення необхідне у мережах із високою щільністю Multicast-трафіку для запобігання втратам `rx_dropped`.
- **`IFLA_MACVLAN_BC_QUEUE_LEN_USED` (8):** 32-бітове ціле число (`uint32_t`), що вказує поточну кількість пакетів, які перебувають у черзі Broadcast/Multicast (read-only атрибут для моніторингу наповнення черги).

### Бінарний контракт режимів `macvlan_mode`

:::tabs
```c
/* Визначення заголовка linux/if_link.h у C */
enum macvlan_mode {
    MACVLAN_MODE_PRIVATE     = 1, /* Повна ізоляція між віртуальними інтерфейсами */
    MACVLAN_MODE_VEPA        = 2, /* Виштовхування трафіку на зовнішній комутатор */
    MACVLAN_MODE_BRIDGE      = 4, /* Внутрішня комутація L2 між сусідніми інтерфейсами */
    MACVLAN_MODE_PASSTHROUGH = 8, /* Ексклюзивне володіння батьківським NIC (1:1) */
    MACVLAN_MODE_SOURCE      = 16 /* Фільтрація вхідних пакетів за списком джерел */
};
```
```cpp
// Ідіоматичне C++20 представлення режимів Macvlan
#include <cstdint>

enum class MacvlanMode : std::uint32_t {
    Private     = 1,  // Повна ізоляція між віртуальними інтерфейсами
    Vepa        = 2,  // Виштовхування трафіку на зовнішній комутатор (802.1Qbg)
    Bridge      = 4,  // Внутрішня комутація L2 між сусідніми інтерфейсами
    Passthrough = 8,  // Ексклюзивне володіння батьківським NIC (1:1)
    Source      = 16  // Фільтрація вхідних пакетів за списком джерел
};
```
:::

### Додаткові бітові прапорці `MACVLAN_FLAG_*`

Прапорці передаються через атрибут `IFLA_MACVLAN_FLAGS` (тип `uint16_t`):

- **`MACVLAN_FLAG_NOPROMISC` (`0x01`):** Забороняє автоматичне переведення батьківського мережевого адаптера у promiscuous mode під час вичерпання апаратних MAC-фільтрів. При встановленні цього прапорця кадри для додаткових MAC-адрес будуть відкидатися на апаратному рівні NIC, якщо вони не вміщуються у фізичні регістри фільтрації адаптера.
- **`MACVLAN_FLAG_NODFS` (`0x02`):** Вимикає обробку циклів у системі Direct Forwarding System (DFS).

## 2. Структура файлової системи sysfs

Ядро Linux автоматично створює та експортує ієрархію конфігураційних файлів у `sysfs` для кожного створеного інтерфейсу Macvlan/Macvtap за шляхом `/sys/class/net/<ifname>/`.

Кожен інтерфейс репрезентується як окремий каталог у файловій системі `sysfs`, оновлення якого відбувається в момент створення пристрою через `RTM_NEWLINK`.

### Ієрархія вузлів sysfs

```text
/sys/class/net/<ifname>/
├── address           # Поточна MAC-адреса віртуального інтерфейсу (наприклад 52:54:00:12:34:56)
├── ifindex           # Унікальний числовий індекс інтерфейсу в ядрі (наприклад 7)
├── link              # Символічне посилання на батьківський інтерфейс eth0
├── lower_eth0 -> ... # Символічне посилання на нижній підпорядкований пристрій
├── macvlan/
│   ├── mode          # Режим роботи (private, vepa, bridge, passthrough, source)
│   └── flags         # Шістнадцяткове значення прапорців (наприклад 0x0)
├── operstate         # Фізичний стан лінка (up, down, unknown)
└── statistics/       # Лічильники RX/TX пакетів, помилок та скидань
    ├── rx_packets    # Загальна кількість успішно прийнятих пакетів
    ├── rx_bytes      # Загальний обсяг прийнятих даних у байтах
    ├── rx_dropped    # Кількість пакетів, скинутих через переповнення черги
    ├── tx_packets    # Загальна кількість відправлених пакетів
    ├── tx_bytes      # Загальний обсяг відправлених даних у байтах
    └── tx_dropped    # Кількість пакетів, скинутих при помилках передачі
```

### Специфікація значення файлу `/sys/class/net/<ifname>/macvlan/mode`

Файл `mode` повертає один із текстових рядків, які відповідають внутрішньому стану ядра:
- `"private"` — інтерфейс знаходиться у режимі повної ізоляції `MACVLAN_MODE_PRIVATE`.
- `"vepa"` — інтерфейс виштовхує трафік на зовнішній комутатор `MACVLAN_MODE_VEPA`.
- `"bridge"` — увімкнено внутрішню L2-комутацію `MACVLAN_MODE_BRIDGE`.
- `"passthrough"` — ексклюзивне виділення фізичного NIC `MACVLAN_MODE_PASSTHROUGH`.
- `"source"` — фільтрація за списком MAC-адрес джерел `MACVLAN_MODE_SOURCE`.

## 3. Специфікація символьного пристрою Macvtap (`/dev/tapX`)

Для кожного інтерфейсу Macvtap ядро автоматично реєструє символьний пристрій у `/dev/tapX`, де `X` дорівнює системному індексу `ifindex` відповідного пристрою.

Пристрої `Macvtap` обробляються підсистемою `drivers/net/macvtap.c`, яка комбінує логіку `macvlan` із функціональністю символьних пристроїв TAP.

### Заголовок кадри Virtio (`struct virtio_net_hdr`)

Під час системних викликів `read()` та `write()` процеси віртуалізації (QEMU/KVM) передають Ethernet-кадри разом із заголовком апаратного розвантаження `virtio_net_hdr`:

:::tabs
```c
/* Визначення заголовка linux/virtio_net.h у C */
struct virtio_net_hdr {
    uint8_t  flags;      /* VIRTIO_NET_HDR_F_NEEDS_CSUM та ін. */
    uint8_t  gso_type;   /* VIRTIO_NET_HDR_GSO_NONE, TSO4, TSO6, UDP */
    uint16_t hdr_len;    /* Довжина заголовка Ethernet + IP + TCP/UDP */
    uint16_t gso_size;   /* Розмір сегмента при TSO/GSO */
    uint16_t csum_start; /* Зміщення початку обчислення контрольної суми */
    uint16_t csum_offset;/* Зміщення поля для запису контрольної суми */
};
```
```cpp
// Ідіоматичне C++20 представлення VirtioNetHdr
#include <cstdint>

struct VirtioNetHdr {
    std::uint8_t  flags{0};        // Прапорці апаратного розвантаження
    std::uint8_t  gso_type{0};     // Тип сегментації (TSO4, TSO6, UDP GSO)
    std::uint16_t hdr_len{0};      // Загальна довжина заголовків L2/L3/L4
    std::uint16_t gso_size{0};     // Максимальний розмір сегмента MSS
    std::uint16_t csum_start{0};   // Зміщення для обчислення CRC
    std::uint16_t csum_offset{0};  // Зміщення поля запису CRC
};
```
:::

Детальний розбір полів заголовка `virtio_net_hdr`:
- `flags`: містить прапорець `VIRTIO_NET_HDR_F_NEEDS_CSUM`, якщо гостьова ОС відмовилася від обчислення контрольної суми TCP/UDP, покладаючись на апаратний Offload хоста.
- `gso_type`: визначає тип великого сегментації (Generic Segmentation Offload) — `VIRTIO_NET_HDR_GSO_TCPV4`, `VIRTIO_NET_HDR_GSO_TCPV6` або `VIRTIO_NET_HDR_GSO_UDP`.
- `hdr_len`: вказує точний розмір мережевих заголовків L2/L3/L4 в байтах для коректного парсингу пакета мережевою картою.
- `gso_size`: визначає максимальний розмір одного сегмента MSS (Maximum Segment Size), на який мережевий адаптер повинен нарізати великий пакет.

### Системні команди `ioctl()` для управління Macvtap

Взаємодія з відкритим файловим дескриптором `/dev/tapX` здійснюється через виклики `ioctl()` з використанням констант із `<linux/if_tun.h>`:

- **`TUNSETIFF` (`_IOW('T', 202, int)`):** Прив'язує файловий дескриптор до конкретного мережевого інтерфейсу Macvtap. У якості аргументу приймає вказівник на `struct ifreq`.
- **`TUNGETIFF` (`_IOR('T', 210, int)`):** Отримує поточне ім'я інтерфейсу та прапорці, прив'язані до цього файлового дескриптора.
- **`TUNGETFEATURES` (`_IOR('T', 207, unsigned int)`):** Повертає маску 32-бітових прапорців функцій, підтримуваних ядром (наприклад `IFF_TAP`, `IFF_NO_PI`, `IFF_VNET_HDR`).
- **`TUNSETOFFLOAD` (`_IOW('T', 208, unsigned int)`):** Вмикає або вимикає апаратні розвантаження (TSO4, TSO6, Checksum Offloading) для файлового дескриптора.
- **`TUNSETVNETHDRSZ` (`_IOW('T', 216, int)`):** Налаштовує розмір заголовка `virtio_net_hdr` (10 байт для стандартного Virtio або 12 байт при використанні розширеного розміру з підтримою мерджингових буферів `VIRTIO_NET_F_MRG_RXBUF`).
- **`SIOCGIFHWADDR` (`0x8927`):** Запитує поточну апаратну MAC-адресу пристрою Macvtap.

## 4. Коди помилок `errno` при роботі з Macvlan/Macvtap

Під час викликів RTNetlink або маніпуляцій з `sysfs`/`ioctl` ядро може повертати наступні стандартні коди помилок:

- **`EEXIST` (File exists):** Спроба створити інтерфейс Macvlan з ім'ям, яке вже зареєстроване у цій системі.
- **`ENODEV` (No such device):** Вказано неіснуючий індекс батьківського фізичного мережевого адаптера (`IFLA_LINK`).
- **`EINVAL` (Invalid argument):** Передано некоректний режим `IFLA_MACVLAN_MODE` або непідтримувані бітові прапорці.
- **`EBUSY` (Device or resource busy):** Спроба створити другий Macvlan-інтерфейс у режимі `Passthrough` над тим самим батьківським пристроєм.
- **`ENOMEM` (Out of memory):** Нестача системної пам'яті ядра для виділення внутрішньої структури `macvlan_port`.
- **`EPERM` (Operation not permitted):** Нестача прав привілейованості у процесу (вимагається `CAP_NET_ADMIN`).
