# 📋 Довідник структур даних, прапорців та опцій сокета TPACKET_V3

Цей довідник містить повну технічну специфікацію бінарних структур даних, системних констант, опцій сокета `SOL_PACKET` та прапорців статусу, необхідних для розробки та тюнінгу високопродуктивних програм перехоплення та надсилання мережевого трафіку за допомогою кільцевих буферів PACKET_MMAP версії 3 (TPACKET_V3) у ядрі Linux.

---

## 1. Системні заголовки та підготовка середовища

Для роботи з інтерфейсом TPACKET_V3 у програмах мовами C та C++ вимагається включення низки заголовних файлів ядра та стандартної бібліотеки POSIX. Заголовний файл `<linux/if_packet.h>` визначає базові структури та константи `SOL_PACKET`, а `<sys/mman.h>` надає інтерфейси відображення пам'яті `mmap()` та `munmap()`.

Включення необхідних системних заголовків:

```c
#include <sys/socket.h>
#include <sys/mman.h>
#include <arpa/inet.h>
#include <net/if.h>
#include <netinet/if_ether.h>
#include <netinet/ip.h>
#include <linux/if_packet.h>
#include <poll.h>
```

Особливу увагу слід звернути на порядок включення: файл `<linux/if_packet.h>` має завантажуватися після системних файлів сокетів, щоб уникнути конфліктів перевизначення структур у просторі користувача.

## 2. Основні структури конфігурації кільцевого буфера

### 2.1. Конфігураційна структура `struct tpacket_req3`

Структура `struct tpacket_req3` є головним параметром налаштування прийому кадри через системний виклик `setsockopt(fd, SOL_PACKET, PACKET_RX_RING, &req, sizeof(req))`. Вона передає ядру геометрію виділення безперервних блоків оперативної пам'яті.

```c
struct tpacket_req3 {
    unsigned int tp_block_size;       /* Розмір одного блоку в байтах (мусить бути кратним PAGE_SIZE) */
    unsigned int tp_block_nr;         /* Загальна кількість блоків у кільцевому буфері */
    unsigned int tp_frame_size;       /* Верхня межа розміру кадри для перевірок консистентності */
    unsigned int tp_frame_nr;         /* Розрахункова сумарна кількість кадрів */
    unsigned int tp_retire_blk_tov;   /* Тайм-аут віддачі часткового блоку (Retire Block Timeout) у мс */
    unsigned int tp_sizeof_priv;      /* Розмір додаткової приватної області користувача в блоці */
    unsigned int tp_feature_req_word; /* Прапорці запиту додаткових можливостей ядра */
};
```

Детальний аналіз функціонального призначення кожного поля структури `tpacket_req3`:

- **`tp_block_size`**: Визначає обсяг фізично безперервної пам'яті, який ядро замовляє у системного аллокатора сторінок `alloc_pages()` під один блок. Це значення **обов'язково** має бути кратним розміру системної сторінки (`PAGE_SIZE`, що на архітектурах x86_64 становить 4096 байтів). Типовими значеннями у високопродуктивних продуктових системах є 1 MB (`1048576`), 2 MB або 4 MB.
- **`tp_block_nr`**: Кількість блоків у кільцевому масиві. Загальний обсяг оперативної пам'яті, який буде виділено ядром та відображено у простір користувача через `mmap()`, розраховується як добуток `tp_block_size * tp_block_nr`. Наприклад, 64 блоки по 1 MB створюють кільцевий буфер загальним обсягом 64 MB.
- **`tp_frame_size`**: У версії TPACKET_V3 кадрів фіксованого розміру не існує. Проте це поле використовується ядром як орієнтовний максимальний розмір збереженої частини кадри (Snaplen). Його значення зазвичай виставляють у 2048 байтів або 9216 байтів (для підтримки Jumbo-кадрів).
- **`tp_frame_nr`**: Розрахункове значення загальної кількості кадрів у буфері. Воно математично визначається як `(tp_block_size * tp_block_nr) / tp_frame_size`.
- **`tp_retire_blk_tov`**: Таймер примусового закриття блоку (Retire Block Timeout) у мілісекундах. Якщо швидкість вхідного трафіку низька, і активний блок не заповнюється повністю, ядро чекає вказану кількість мілісекунд, після чого примусово закриває блок і передає його у володіння користувачу, встановлюючи прапорець `TP_STATUS_USER`. Значення `0` вимикає таймер (блок передається лише при повному заповненні).
- **`tp_sizeof_priv`**: Обсяг пам'яті (у байтах), який ядро додатково виділяє у заголовочній частині кожного блоку для власних потреб користувацької програми. Якщо програмі не потрібні додаткові метадані на рівні блоку, це поле встановлюють у `0`.
- **`tp_feature_req_word`**: Битва маска запиту додаткових функцій від ядра Linux. Найважливішим прапорцем тут є `TP_FT_REQ_FILL_RXHASH`, який вимагає від ядра записувати апаратний обчислений мережевою картою хеш потоку (RSS hash) у заголовок пакета.

### 2.2. Опис заголовків блоку: `struct tpacket_block_desc` та `struct tpacket_hdr_v1`

Кожен блок у змонтованому масиві починається з бінарного заголовка `struct tpacket_block_desc`. Внутрішньо цей заголовок містить версійну структуру `struct tpacket_hdr_v1`, яка описує поточний стан та вміст блоку.

```c
struct tpacket_bd_ts {
    unsigned int ts_sec;  /* Секунди Epoch */
    unsigned int ts_usec; /* Мікросекунди */
};

struct tpacket_hdr_v1 {
    uint32_t block_status;              /* Прапорець володіння та стану блоку */
    uint32_t num_pkts;                  /* Кількість пакетів, упакованих у цей блок */
    uint32_t offset_to_first_pkt;       /* Зсув у байтах від початку блоку до першого пакета */
    uint32_t blk_len;                   /* Загальний розмір записаних даних у блоці у байтах */
    uint64_t seq_num;                   /* Порядковий номер блоку (монотонний лічильник ядра) */
    struct tpacket_bd_ts ts_first_pkt;  /* Часова мітка першого пакета у блоці */
    struct tpacket_bd_ts ts_last_pkt;   /* Часова мітка останнього пакета у блоці */
};

struct tpacket_block_desc {
    uint32_t version;                   /* Версія заголовка блоку (TPACKET_V3) */
    uint32_t offset_to_priv;            /* Зсув до приватної області користувача */
    struct tpacket_hdr_v1 h1;           /* Внутрішній заголовок інформації про блок */
};
```

Пояснення полів структури заголовка блоку:

- **`h1.block_status`**: Головний атомарний прапорець синхронізації між ядром та користувачем. Якщо значення дорівнює `0` (`TP_STATUS_KERNEL`), ядро має виключне право записувати дані в цей блок. Коли ядро виставляє біт `TP_STATUS_USER` (`1`), блок стає доступним для читання у просторі користувача.
- **`h1.num_pkts`**: Точна кількість мережевих пакетів, які ядро успішно упакувало в цей блок перед його закриттям.
- **`h1.offset_to_first_pkt`**: Зсув у байтах від початку структури `struct tpacket_block_desc` до першого заголовка пакета `struct tpacket3_hdr`.
- **`h1.blk_len`**: Загальна сумарна довжина (у байтах), яку займають заголовок блоку, метадані та всі упаковані пакети.
- **`h1.seq_num`**: Глобальний монотонно зростаючий порядковий номер блоку, який присвоюється ядром. Дозволяє користувацькому процесу відстежувати послідовність отримання блоків та виявляти випадки пропуску даних.
- **`h1.ts_first_pkt` / `h1.ts_last_pkt`**: Апаратні або системні часові мітки надходження першого та останнього пакету, упакованих у цей блок.

### 2.3. Заголовок індивідуального пакета `struct tpacket3_hdr`

Усередині блоку кожен пакет передується заголовком `struct tpacket3_hdr`, який містить повний набір метаданих та зсувів.

```c
struct tpacket3_hdr {
    uint32_t tp_next_offset; /* Зсув у байтах до наступного tpacket3_hdr у блоці (0 = кінець) */
    uint32_t tp_sec;         /* Секунди часової мітки надходження пакета */
    uint32_t tp_nsec;        /* Наносекунди часової мітки */
    uint32_t tp_snaplen;     /* Довжина збереженої частини пакета у буфері */
    uint32_t tp_len;         /* Повна оригінальна довжина пакета у мережевому дріті */
    uint32_t tp_status;      /* Індивідуальні прапорці статусу пакета (VLAN, CSUM) */
    uint16_t tp_mac;         /* Зсув від початку tpacket3_hdr до заголовка канального рівня (L2) */
    uint16_t tp_net;         /* Зсув від початку tpacket3_hdr до заголовка мережевого рівня (L3) */
    union {
        struct tpacket_hdr_variant1 hv1;
    };
    uint8_t  tp_padding[8];  /* Додаткове вирівнювання структури під 64-бітні кордони */
};
```

Деталізація полів `struct tpacket3_hdr`:

- **`tp_next_offset`**: Ключове поле для ітерації по пакетах усередині блоку. Воно містить відносний зсув (у байтах) від початку поточного заголовка `tpacket3_hdr` до початку наступного заголовка `tpacket3_hdr`. Значення `0` показує, що поточний пакет є останнім у даному блоці.
- **`tp_sec` та `tp_nsec`**: Часова мітка захоплення пакета з наносекундною точністю (`struct timespec`).
- **`tp_snaplen`**: Реальна кількість байтів мережевого кадру, які були збережені в буфері (з урахуванням обмеження Snaplen).
- **`tp_len`**: Оригінальна довжина пакета, який пройшов через фізичний мережевий інтерфейс. Якщо `tp_len > tp_snaplen`, пакет був обрізаний при захопленні.
- **`tp_mac`**: Зсув у байтах від початку заголовка `tpacket3_hdr` до першого байта Ethernet-заголовка (`struct ethhdr`).
- **`tp_net`**: Зсув у байтах від початку `tpacket3_hdr` до мережевого заголовка IPv4 (`struct iphdr`) або IPv6 (`struct ipv6hdr`).
- **`tp_status`**: Набір бітових прапорців, які описують результати апаратного аналізу кадра (наприклад, валідність тегів VLAN або стан апаратного обчислення контрольної суми).

### 2.4. Зчитування статистики: `struct tpacket_stats_v3`

Для моніторингу роботи кільцевого буфера та виявлення втрат пакетів використовується структура `struct tpacket_stats_v3`. Зчитування здійснюється системним викликом `getsockopt()` з опцією `PACKET_STATISTICS`.

```c
struct tpacket_stats_v3 {
    unsigned int tp_packets;      /* Загальна кількість пакетів, прийнятих сокетом */
    unsigned int tp_drops;        /* Кількість пакетів, скинутих через переповнення кільця */
    unsigned int tp_freeze_q_cnt; /* Кількість заморозок черги при зміні конфігурації */
};
```

- **`tp_packets`**: Загальний лічильник пакетів, які ядро успішно передало у сокет з моменту його відкриття або останнього виклику `getsockopt()`.
- **`tp_drops`**: Кількість пакетів, які були скинуті ядром через те, що всі блоки у кільцевому буфері мали статус `TP_STATUS_USER`, і ядро не мало вільної пам'яті для запису нових даних.
- **`tp_freeze_q_cnt`**: Кількість випадків, коли чергу сокета було тимчасово заморожено під час перевиділення ресурсів.

*Зверніть увагу:* Кожен виклик `getsockopt(fd, SOL_PACKET, PACKET_STATISTICS, ...)` атомарно обнуляє внутрішні лічильники ядра.

## 3. Специфікація прапорців статусу

### 3.1. Прапорці стану блоку (`block_status`)

Поле `block_status` у заголовку `struct tpacket_hdr_v1` керує атомарною передачею прав між ядром та користувацьким процесом.

```c
#define TP_STATUS_KERNEL          0        /* Блок належить ядру (процес не має права читати) */
#define TP_STATUS_USER            (1 << 0) /* Блок готовий і переданий у простір користувача */
#define TP_STATUS_COPY            (1 << 1) /* Частина даних була скопійована через обмеження пам'яті */
#define TP_STATUS_LOSING          (1 << 2) /* У системі зафіксовано втрати пакетів через переповнення */
#define TP_STATUS_BLK_TMO         (1 << 5) /* Блок віддано за таймаутом retire_blk_tov (частково заповнений) */
```

### 3.2. Прапорці індивідуального пакета (`tp_status`)

Поле `tp_status` у заголовку `struct tpacket3_hdr` передає метадані апаратних offload-функцій NIC:

```c
#define TP_STATUS_CSUMNOTREADY    (1 << 3) /* Апаратна контрольна сума не обчислена (offload) */
#define TP_STATUS_VLAN_VALID      (1 << 4) /* Поле tp_vlan_tci містить дійсний тег 802.1Q VLAN */
#define TP_STATUS_VLAN_TPID_VALID (1 << 6) /* Поле tp_vlan_tpid містить дійсний TPID (наприклад, 0x8100) */
```

## 4. Опції сокета рівня `SOL_PACKET`

Системний виклик `setsockopt()` дозволяє керувати поведінкою сокета `AF_PACKET`. Нижче наведено повний перелік опцій рівня `SOL_PACKET`.

```c
int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);
```

| Назва опції (`optname`) | Тип даних `optval` | Функціональне призначення |
| :--- | :--- | :--- |
| `PACKET_VERSION` | `int` | Встановлює версію API TPACKET. Для V3 значень має бути `TPACKET_V3`. Мусить викликатися **до** `PACKET_RX_RING`. |
| `PACKET_RX_RING` | `struct tpacket_req3` | Замовляє у ядра виділення кільцевого буфера прийому на основі параметрів блоків. |
| `PACKET_TX_RING` | `struct tpacket_req3` | Замовляє виділення кільцевого буфера передачі для zero-copy надсилання пакетів. |
| `PACKET_FANOUT` | `uint32_t` | Приєднує сокет до Fanout-групи багатопотокового балансування трафіку. |
| `PACKET_RESERVE` | `unsigned int` | Замовляє додаткові резервні байти перед кожним кадром для власних потреб програми. |
| `PACKET_TIMESTAMP` | `int` | Налаштовує режим генерації часових міток (`SOF_TIMESTAMPING_*`). |
| `PACKET_STATISTICS` | `struct tpacket_stats_v3` | Отримує статистику прийому та скидань пакетів через `getsockopt()`. |

## 5. Константи та алгоритми PACKET_FANOUT

При підключенні сокета до групи `PACKET_FANOUT` значення аргументу формується бітовим комбінуванням ідентифікатора групи та прапорців алгоритму:

`uint32_t fanout_arg = (group_id & 0xffff) | (type_flags << 16);`

### 5.1. Алгоритми розподілу трафіку (нижні 16 біт типу)

```c
#define PACKET_FANOUT_HASH        0 /* Хешування за 4-tuple (IP src/dst, Port src/dst). Забезпечує flow affinity */
#define PACKET_FANOUT_LB          1 /* Циклічне балансування Round-Robin між сокетами групи */
#define PACKET_FANOUT_CPU         2 /* Прив'язка до сокета за номером ядра CPU, де спрацювало переривання NIC */
#define PACKET_FANOUT_ROLLOVER    3 /* Перенаправлення трафіку на резервний сокет при переповненні поточного */
#define PACKET_FANOUT_RND         4 /* Випадковий вибір сокета для кожного вхідного пакета */
#define PACKET_FANOUT_QM          5 /* Балансування за номером hardware RX-черги мережевої карти */
#define PACKET_FANOUT_CBPF        6 /* Вибір сокета на основі виконання класичної BPF програми */
#define PACKET_FANOUT_EBPF        7 /* Вибір сокета на основі виконання eBPF програми */
```

### 5.2. Додаткові прапорці Fanout (верхні біти)

```c
#define PACKET_FANOUT_FLAG_ROLLOVER (1 << 8) /* Дозволяє роловер на резервний сокет при заповненні цільового */
#define PACKET_FANOUT_FLAG_DEFRAG   (1 << 9) /* Примушує ядро збирати IP-фрагменти перед обчисленням HASH */
```

## 6. Коди помилок системних викликів (`errno`)

При роботі з TPACKET_V3 системні виклики `setsockopt()`, `mmap()` та `bind()` можуть повертати помилки через неправильну конфігурацію:

| Код помилки | Системний виклик | Причина та спосіб усунення |
| :--- | :--- | :--- |
| `EINVAL` | `setsockopt` | `tp_block_size` не є кратним `PAGE_SIZE`, або `PACKET_VERSION` встановлено після `PACKET_RX_RING`. |
| `ENOMEM` | `setsockopt` / `mmap` | Ядро не змогло виділити безперервні фізичні сторінки пам'яті. Зменшіть `tp_block_size` або `tp_block_nr`. |
| `EBUSY` | `setsockopt` | Спроба змінити конфігурацію кільця при наявності активного змонтованого `mmap`. Необхідно спочатку виконати `munmap()`. |
| `EALREADY` | `setsockopt` | Спроба повторно приєднати сокет до групи `PACKET_FANOUT`. |
| `ENOPROTOOPT` | `setsockopt` | Запитана опція не підтримується даною версією ядра Linux. |
