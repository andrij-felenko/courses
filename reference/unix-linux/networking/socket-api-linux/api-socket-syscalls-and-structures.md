# 📋 Повний довідник системних викликів Socket API, ядерних структур та sysctl

Цей довідник містить повну технічну специфікацію програмного інтерфейсу BSD Socket API у ядрі Linux. Тут зведено сигнатури системних викликів із деталізацією параметрів та режимів помилок, описи допоміжних адресних структур, розкладку внутрішніх C-структур ядра (`struct socket`, `struct sock`, `struct tcp_sock`), таблицю опцій сокетів для керування через `setsockopt` та довідник системних параметрів ядерного тюнінгу через `sysctl`.

## 1. Детальний опис системних викликів Socket API

Усі мережеві системні виклики у Linux декларуються у стандартному заголовковому файлі POSIX `<sys/socket.h>` та супутніх заголовках мережевої підсистеми `<netinet/in.h>`, `<netinet/tcp.h>` і `<arpa/inet.h>`.

### `socket()` — створення кінцевої точки комунікації

Системний виклик `socket()` створює новий об'єкт сокета у ядрі, виділяє файловий дескриптор та пов'язує його з VFS-структурою `sockfs`.

```c
int socket(int domain, int type, int protocol);
```

- **`domain` (Сімейство протоколів / адресне сімейство)**:
  - `AF_INET`: Мережевий протокол IPv4 (32-бітні IP-адреси).
  - `AF_INET6`: Мережевий протокол IPv6 (128-бітні IP-адреси).
  - `AF_UNIX` / `AF_LOCAL`: Локальне міжпроцесне сполучення на одній машині через файлові шляхи або абстрактний простір назв.
  - `AF_PACKET`: Прямий доступ до сирих кадрів канального рівня (Layer 2 Ethernet), що використовується утилітами на кшталт `tcpdump` та `Wireshark`.
  - `AF_NETLINK`: Внутрішньоядерний канал зв'язку між простором користувача та підсистемами ядра (маршрутизація, nftables, audit, sock_diag).
- **`type` (Семантика комунікації)**:
  - `SOCK_STREAM`: Надійний, орієнтований на з'єднання двосторонній потік байтів (протокол TCP). Забезпечує контроль послідовності та відсутність дублікатів.
  - `SOCK_DGRAM`: Незалежні датаграми без встановлення з'єднання та без гарантії доставки (протокол UDP).
  - `SOCK_RAW`: Прямий доступ до мережевого рівня (Layer 3 IP), дозволяє формувати власні заголовки IP-пакетів (вимагає привілеїв `CAP_NET_RAW`).
  - **Атомарні прапорці типів (поєднуються через бітове OR `|`)**:
    - `SOCK_NONBLOCK`: Негайно встановлює прапорець `O_NONBLOCK` у VFS-описі файлу, роблячи всі наступні операції читання та запису неблокувальними.
    - `SOCK_CLOEXEC`: Негайно встановлює прапорець `FD_CLOEXEC` для усунення race condition при виконанні системного виклику `execve()`.
- **`protocol` (Специфічний протокол)**:
  - Вказує номер конкретного протоколу у межах сімейства. Зазвичай передається `0`, що вибирає протокол за замовчуванням: `IPPROTO_TCP` для `SOCK_STREAM` або `IPPROTO_UDP` для `SOCK_DGRAM`.
- **Повернене значення та коди помилок**:
  - У разі успіху повертає ціле неотрицательне число — новий файловий дескриптор.
  - У разі помилки повертає `-1` та встановлює змінну `errno`:
    - `EAFNOSUPPORT`: Вказане адресне сімейство не підтримується поточним ядром.
    - `EMFILE`: Досягнуто ліміту відкритих файлових дескрипторів для поточного процесу (`RLIMIT_NOFILE`).
    - `ENFILE`: Досягнуто загальносистемного ліміту відкритих файлів у ядрі.
    - `EACCES` / `EPERM`: Відсутні права на створення сокета даного типу (наприклад, `SOCK_RAW`).

### `bind()` — прив'язка сокета до локальної адреси та порту

Системний виклик `bind()` прив'язує виділений сокет до конкретної локальної адреси та порту у ядрі.

```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

- **`sockfd`**: Файловий дескриптор сокета, отриманий із виклику `socket()`.
- **`addr`**: Вказівник на універсальну структуру `struct sockaddr`. На практиці передається вказівник на специфічну для сімейства структуру (`struct sockaddr_in` для IPv4 або `struct sockaddr_in6` для IPv6), приведений до `const struct sockaddr*`.
- **`addrlen`**: Розмір адресної структури у байтах, виражений через `sizeof(struct sockaddr_in)`.
- **Повернене значення та коди помилок**:
  - У разі успіху повертає `0`.
  - У разі помилки повертає `-1` та встановлює `errno`:
    - `EADDRINUSE`: Зазначена комбінація IP-адреси та порту вже зайнята іншим активним сокетом у ядрі.
    - `EACCES`: Спроба прив'язатися до привілейованого порту (номер < 1024) без права `CAP_NET_BIND_SERVICE`.
    - `EBADF`: Передано невалідний файловий дескриптор.
    - `EINVAL`: Сокет вже прив'язаний до іншої адреси.

### `listen()` — перехід сокета у пасивний режим очікування

Системний виклик `listen()` переводить сокет зі стану активного з'єднання у статус пасивного сервера, готового приймати вхідні підключення.

```c
int listen(int sockfd, int backlog);
```

- **`sockfd`**: Файловий дескриптор сокета, який повинен мати тип `SOCK_STREAM` або `SOCK_SEQPACKET`.
- **`backlog`**: Максимальна кількість повністю встановлених з'єднань у стані `TCP_ESTABLISHED`, які можуть зберігатися у черзі Accept Queue очікуючи виклику `accept()`. Якщо значення `backlog` перевищує системний ліміт ядра `net.core.somaxconn`, воно молчаливо обрізається ядром до значення `somaxconn`.
- **Повернене значення та коди помилок**:
  - У разі успіху повертає `0`.
  - У разі помилки повертає `-1` та встановлює `errno`:
    - `EDESTADDRREQ`: Сокет не прив'язаний до локального порту викликом `bind()`.
    - `EINVAL`: Сокет вже підключений або закритий.
    - `ENOTSOCK`: Переданий дескриптор вказує на файл чи канал, а не на сокет.

### `accept()` та `accept4()` — витягування готового з'єднання з черги

Системні виклики `accept()` та `accept4()` витягують перше готове з'єднання з черги Accept Queue слухаючого сокета і створюють для нього новий файловий дескриптор.

```c
int accept(int sockfd, struct sockaddr *restrict addr, socklen_t *restrict addrlen);
int accept4(int sockfd, struct sockaddr *restrict addr, socklen_t *restrict addrlen, int flags);
```

- **`sockfd`**: Файловий дескриптор слухаючого сокета у стані `TCP_LISTEN`.
- **`addr`**: Вказівник на буфер пам'яті, куди ядро записує мережеву адресу та порт віддаленого клієнта. Якщо інформація про клієнта не потрібна, дозволяється передавати `NULL`.
- **`addrlen`**: Вказівник на змінну типу `socklen_t`. Перед викликом містить розмір бувера `addr`, після повернення містить реальну довжину записаної адреси.
- **`flags`** (лише у `accept4`): Бітова маска прапорців, які атомарно застосовуються до нового дескриптора (`SOCK_NONBLOCK`, `SOCK_CLOEXEC`).
- **Повернене значення та коди помилок**:
  - Повертає новий цілочисельний дескриптор клієнтського сокета або `-1` при помилці:
    - `EAGAIN` / `EWOULDBLOCK`: Черга Accept Queue порожня, а слухаючий сокет працює у неблокувальному режимі.
    - `EINTR`: Виклик перервано надходженням системного сигналу до прийняття з'єднання.
    - `ECONNABORTED`: З'єднання було розірвано клієнтом до того, як сервер викликав `accept()`.
    - `EMFILE`: Процес вичерпав ліміт відкритих файлових дескрипторів.

---

### `connect()` — ініціація 3-way handshake з віддаленим сервером

Системний виклик `connect()` зв'язує активний сокет клієнта з віддаленою адресою та ініціює процедуру триетапного рукостискання.

```c
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

- **`sockfd`**: Файловий дескриптор сокета клієнта.
- **`addr`**: Мережева адреса та порт віддаленого сервера.
- **`addrlen`**: Довжина адресної структури у байтах.
- **Повернене значення та коди помилок**:
  - Повертає `0` при успішному встановленні з'єднання або `-1` при помилці:
    - `EINPROGRESS`: Сокет працює у неблокувальному режимі, і з'єднання зараз встановлюється асинхронно у фоні.
    - `ECONNREFUSED`: Віддалений хост відхилив з'єднання (на вказаному порті немає слухаючого сокета, надіслано TCP RST).
    - `ETIMEDOUT`: Вичерпано таймаут очікування відповіді SYN-ACK від віддаленої сторони.
    - `ENETUNREACH` / `EHOSTUNREACH`: Мережа або хост призначення недоступні згідно з поточними таблицями маршрутизації.

---

### `shutdown()` — керування напівзакритими з'єднаннями

Системний виклик `shutdown()` дозволяє частково або повністю закрити канали прийому та передачі даних сокета без знищення самого дескриптора у VFS.

```c
int shutdown(int sockfd, int how);
```

- **`how` (Режим закриття)**:
  - `SHUT_RD` (0): Вимикає подальше читання із сокета. Будь-які нові байти, що надходять від віддаленої сторони, ігноруються та скидаються ядром.
  - `SHUT_WR` (1): Вимикає передачу даних із сокета. Ядро негайно формує і надсилає віддаленій стороні пакет `TCP FIN`. Переводить сокет у напівзакритий стан, дозволяючи продовжувати читання відповіді.
  - `SHUT_RDWR` (2): Одночасно вимикає прийом та передачу даних (надсилає `FIN` та блокує читання).

---

### `getsockname()` та `getpeername()` — отримання адрес сокета

```c
int getsockname(int sockfd, struct sockaddr *restrict addr, socklen_t *restrict addrlen);
int getpeername(int sockfd, struct sockaddr *restrict addr, socklen_t *restrict addrlen);
```

- **`getsockname()`**: Записує у буфер `addr` локальну IP-адресу та порт, до яких прив'язаний сокет `sockfd`. Особливо корисний після виклику `connect()` без `bind()`, коли порт було виділено ядром автобайндингом.
- **`getpeername()`**: Записує у буфер `addr` віддалену IP-адресу та порт підключеного контрагента.

## 2. Прапорці операцій введення-виведення (`send` / `recv`)

При викликах `send(sockfd, buf, len, flags)` та `recv(sockfd, buf, len, flags)` параметр `flags` дозволяє точково змінювати поведінку передачі даних:

- **`MSG_DONTWAIT`**: Виконує операцію введення-виведення у неблокувальному режимі лише для цього конкретного виклику.
- **`MSG_PEEK`**: Дозволяє зчитати дані з буфера прийому `sk_receive_queue` без їх вилучення (наступний `read` поверне ті самі байти).
- **`MSG_OOB`**: Відправляє або зчитує позасмугові термінові дані TCP (Out-of-band / Urgent Data).
- **`MSG_NOSIGNAL`**: Запобігає надсиланню процесу сигналу `SIGPIPE`, якщо віддалена сторона вже закрила з'єднання. Замість сигналу виклик повертає `-1` та встановлює `errno` в `EPIPE`.
- **`MSG_MORE`**: Повідомляє ядру, що відправник має додаткові дані, і ядро не повинно відправляти кадр до накопичення повної MSS (аналог `TCP_CORK`).

## 3. Детальний довідник опцій сокетів (`setsockopt` / `getsockopt`)

Конфігурація та читання внутрішніх параметрів сокета здійснюються через системні виклики `setsockopt()` та `getsockopt()`.

```c
int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);
int getsockopt(int sockfd, int level, int optname, void *restrict optval, socklen_t *restrict optlen);
```

### Найважливіші опції сокетів у ядрі Linux

| Рівень (`level`) | Назва опції (`optname`) | Тип даних | Опис та призначення у ядрі |
| :--- | :--- | :--- | :--- |
| `SOL_SOCKET` | `SO_REUSEADDR` | `int` (0/1) | Дозволяє повторну прив'язку до локального порту, який знаходиться у стані `TIME_WAIT`. |
| `SOL_SOCKET` | `SO_REUSEPORT` | `int` (0/1) | Вмикає ядрове балансування навантаження між кількома сокетами на точно такому ж порті. |
| `SOL_SOCKET` | `SO_KEEPALIVE` | `int` (0/1) | Вмикає відправку періодичних зондувальних пакетів TCP Keep-Alive для виявлення обривів зв'язку. |
| `SOL_SOCKET` | `SO_RCVBUF` | `int` (байти) | Встановлює максимальний розмір буфера прийому у ядрі. Ядро подвоює це значення під службові заголовки `sk_buff`. |
| `SOL_SOCKET` | `SO_SNDBUF` | `int` (байти) | Встановлює максимальний розмір буфера передачі у ядрі. |
| `SOL_SOCKET` | `SO_LINGER` | `struct linger` | Керує поведінкою `close()`: дозволяє примусово чекати відправки даних або скидати з'єднання пакетом `RST`. |
| `SOL_SOCKET` | `SO_BINDTODEVICE` | `char[]` | Примусово прив'язує сокет до конкретного мережевого інтерфейсу (наприклад, `"eth0"`). |
| `IPPROTO_TCP` | `TCP_NODELAY` | `int` (0/1) | Повністю вимикає алгоритм Нагла (Nagle's algorithm), надсилаючи дрібні пакети негайно без затримки. |
| `IPPROTO_TCP` | `TCP_CORK` | `int` (0/1) | Затримує відправку часткових пакетів до накопичення повного MSS або скидання прапорця (оптимізація для `sendfile`). |
| `IPPROTO_TCP` | `TCP_QUICKACK` | `int` (0/1) | Вимикає режим затриманих підтверджень (Delayed ACK), змушуючи ядро надсилати `ACK` на кожен пакет. |

## 4. Детальна розкладка внутрішніх C-структур ядра

Усередині ядра Linux об'єкт сокета реалізовано через ієрархію C-структур даних.

### `struct socket` (`include/linux/net.h`)
Верхній шар абстракції VFS BSD API.

```c
struct socket {
    socket_state          state;      /* Поточний VFS-стан сокета (SS_UNCONNECTED, SS_CONNECTING, SS_CONNECTED) */
    short                 type;       /* Тип сокета (SOCK_STREAM, SOCK_DGRAM, SOCK_RAW) */
    unsigned long         flags;      /* Внутрішні прапорці ядра (SOCK_NOSPACE, SOCK_SUPPORT_ZC) */
    struct file          *file;       /* Зворотний вказівник на VFS-структуру опису відкритого файлу */
    struct sock          *sk;         /* Вказівник на мережевий об'єкт нижнього рівня struct sock */
    const struct proto_ops *ops;      /* Таблиця високорівневих операцій (inet_stream_ops, inet_dgram_ops) */
    struct socket_wq      wq;         /* Черга очікування (wait queue) для подій epoll/select/poll */
};
```

### `struct sock` (`include/net/sock.h`)
Головна мережева структура транспортного та мережевого рівнів.

```c
struct sock {
    struct sock_common    __sk_common;  /* Мережевий ідентифікатор: IP-адреси, порти, протокол, хеш-ключі */
    unsigned char         sk_shutdown;  /* Прапорці припинення передачі (RCV_SHUTDOWN, SEND_SHUTDOWN) */
    unsigned short        sk_type;      /* Тип сокета */
    int                   sk_rcvbuf;    /* Поточний розмір буфера прийому у байтах */
    int                   sk_sndbuf;    /* Поточний розмір буфера передачі у байтах */
    struct sk_buff_head   sk_receive_queue; /* Двобічний список накопичених мережевих буферів sk_buff */
    struct sk_buff_head   sk_write_queue;   /* Двобічний список вихідних буферів sk_buff */
    struct socket        *sk_socket;    /* Зворотний вказівник на верхній шар struct socket */
    struct proto         *sk_prot;      /* Таблиця протокольних функцій (tcp_prot, udp_prot) */
    void                (*sk_data_ready)(struct sock *sk); /* Зворотний виклик розбудження процесів при надходженні даних */
};
```

### `struct tcp_sock` (`include/linux/tcp.h`)
Повна структура стану для протоколу TCP.

```c
struct tcp_sock {
    struct inet_connection_sock inet_conn; /* Базова структура з'єднань із підтримкою LISTEN-черг */
    u32    rcv_nxt;   /* Порядковий номер (Sequence Number) наступного очікуваного байта */
    u32    snd_nxt;   /* Порядковий номер наступного байта для відправки */
    u32    snd_una;   /* Порядковий номер найпершого непідтвердженого байта у мережі */
    u32    snd_wnd;   /* Поточний розмір вікна відправки, оголошений віддаленою стороною */
    u32    rcv_wnd;   /* Поточний розмір вікна прийому, оголошений нашим ядром */
    u32    srtt_us;   /* Згладжений час кругового затримання пакетів (Smoothed RTT) у мікросекундах */
    const struct tcp_congestion_ops *tss_ca_ops; /* Вказівник на обробник алгоритму керування перевантаженням */
};
```

## 5. Довідник системних параметрів `sysctl`

Системний тюнінг сокетного API та мережевого стеку TCP/IP у Linux здійснюється через псевдофайлову систему `/proc/sys/net/` або команду `sysctl`.

| Параметр sysctl | Значення за замовчуванням | Опис та рекомендації щодо налаштування |
| :--- | :--- | :--- |
