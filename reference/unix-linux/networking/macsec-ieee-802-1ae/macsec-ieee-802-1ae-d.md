## Вступ до MACsec

MACsec (Media Access Control Security, визначений стандартом IEEE 802.1AE) — це протокол захисту даних на канальному (L2) рівні моделі OSI. На відміну від IPsec, який працює на мережевому рівні (L3) і захищає IP-пакети, або TLS, який працює на вищих рівнях і захищає потоки даних TCP, MACsec шифрує і автентифікує самі Ethernet-кадри.

Це означає, що MACsec захищає абсолютно весь трафік, що проходить між двома безпосередньо з'єднаними вузлами в Ethernet-мережі, включаючи не лише IP-трафік (IPv4, IPv6), а й протоколи, такі як ARP, DHCP, LLDP або навіть спеціалізовані промислові протоколи, які не використовують IP.

### Принципи роботи

MACsec працює за принципом "точка-точка" (або "точка-багато точок" у межах одного сегмента мережі). Коли кадр передається від одного вузла до іншого, MACsec-модуль на стороні відправника додає спеціальний заголовок (SecTAG) після заголовка Ethernet (MAC-адрес призначення та джерела). Далі він обчислює криптографічну контрольну суму (ICV — Integrity Check Value) для всього кадру (включно із заголовком Ethernet та SecTAG) і шифрує корисне навантаження кадру. Отриманий кадр відправляється в мережу.

На стороні отримувача MACsec-модуль перевіряє ICV. Якщо перевірка успішна, він дешифрує корисне навантаження, видаляє SecTAG і передає оригінальний кадр вищим рівням мережевого стека. Якщо ж кадр був змінений у дорозі (або підроблений зловмисником), ICV не співпаде, і кадр буде відкинуто ще до того, як він потрапить на обробку до стека протоколів.

### Криптографія

У MACsec використовується алгоритм шифрування GCM-AES (Galois/Counter Mode — Advanced Encryption Standard). Стандарт визначає використання ключів довжиною 128 біт (GCM-AES-128) або 256 біт (GCM-AES-256). GCM є режимом автентифікованого шифрування, що дозволяє одночасно забезпечувати конфіденційність (шифрування даних) і цілісність (захист від підміни або зміни даних).

Для роботи MACsec необхідні криптографічні ключі (SAK - Secure Association Key). Ці ключі можуть бути налаштовані статично (PSK — Pre-Shared Key) або узгоджуватись динамічно за допомогою протоколу MKA (MACsec Key Agreement, стандарт IEEE 802.1X-2010), що працює спільно з EAPOL (Extensible Authentication Protocol over LAN).

## Реалізація MACsec у Linux

Починаючи з версії ядра Linux 4.6, підтримка MACsec була інтегрована безпосередньо в ядро. Вона реалізована у вигляді віртуального мережевого інтерфейсу (`macsecX`), який "прив'язується" до фізичного (або іншого віртуального) інтерфейсу (наприклад, `eth0`).

Коли пакет маршрутизується через інтерфейс `macsec0`, ядро прозоро шифрує його і відправляє через базовий інтерфейс `eth0`. Аналогічно, коли `eth0` отримує кадр із заголовком MACsec, ядро дешифрує його і передає на інтерфейс `macsec0`.

### Управління за допомогою `iproute2`

Для налаштування інтерфейсів MACsec використовується утиліта `ip link` з пакета `iproute2`. Створення MACsec-з'єднання зі статичними ключами вимагає кількох кроків.

#### 1. Створення віртуального інтерфейсу

Спочатку потрібно створити віртуальний інтерфейс `macsec` поверх базового інтерфейсу.

```bash
# ip link add link eth0 macsec0 type macsec encrypt on
```

Ця команда створює інтерфейс `macsec0`, прив'язаний до `eth0`. Опція `encrypt on` вказує, що весь трафік, який виходить з `macsec0`, повинен бути зашифрований.

#### 2. Налаштування ключів передачі (TX)

Кожен пристрій повинен мати ключ для шифрування трафіку, який він відправляє. У MACsec ключі асоціюються із Secure Association (SA).

```bash
# ip macsec add macsec0 tx sa 0 pn 1 on key 01 00112233445566778899aabbccddeeff
```

Тут ми додаємо SA з індексом `0` (SA id). `pn 1` (Packet Number) — це лічильник пакетів, що використовується для захисту від атак відтворення (replay attacks); він починається з 1. `key 01 ...` задає 128-бітний ключ (32 шістнадцяткових символи) та ідентифікатор ключа (Key ID) `01`.

#### 3. Налаштування ключів прийому (RX)

Для розшифровки трафіку пристрій повинен знати MAC-адресу відправника і його ключ.

```bash
# ip macsec add macsec0 rx port 1 address aa:bb:cc:dd:ee:ff
# ip macsec add macsec0 rx port 1 address aa:bb:cc:dd:ee:ff sa 0 pn 1 on key 02 ffeeddccbbaa99887766554433221100
```

Перша команда визначає джерело трафіку за його MAC-адресою. Друга команда додає SA для цього джерела з ключем `02 ...`.

#### 4. Активація інтерфейсу

Після налаштування ключів інтерфейс можна активувати та призначити йому IP-адресу.

```bash
# ip addr add 10.0.0.1/24 dev macsec0
# ip link set macsec0 up
```

## Апаратне розвантаження (Hardware Offload)

Програмне шифрування і дешифрування трафіку (особливо на швидкостях 10, 25, 40 або 100 Гбіт/с) вимагає значних ресурсів процесора. Щоб вирішити цю проблему, багато сучасних мережевих адаптерів (NIC і SmartNIC) підтримують апаратне розвантаження (hardware offload) для MACsec.

Коли ввімкнено апаратне розвантаження, ядро передає ключі SA і правила безпосередньо мережевій карті. Мережева карта сама додає SecTAG, шифрує і дешифрує кадри "на льоту" без участі центрального процесора.

Для ввімкнення апаратного розвантаження використовується параметр `offload` при створенні інтерфейсу:

```bash
# ip link add link eth0 macsec0 type macsec offload mac
```

Опція `offload mac` означає, що розвантаження виконується MAC-рівнем мережевої карти. Якщо карта не підтримує розвантаження MACsec, команда поверне помилку. Перевірити підтримку offload можна за допомогою утиліти `ethtool`.

## Динамічне узгодження ключів (MKA / `wpa_supplicant`)

У великих мережах налаштування статичних ключів є незручним і небезпечним. Для автоматизації цього процесу використовується MACsec Key Agreement (MKA). У Linux MKA реалізовано як частина демона `wpa_supplicant`.

`wpa_supplicant` використовує EAPOL для виявлення інших пристроїв із підтримкою MACsec і узгодження SAK. Замість налаштування ключів через `ip macsec`, адміністратор налаштовує `wpa_supplicant` з CAK (Connectivity Association Key). Цей ключ діє як "майстер-ключ", з якого автоматично генеруються та оновлюються SAK.

Приклад конфігурації `wpa_supplicant.conf` для MACsec із PSK:

```
eapol_version=3
ap_scan=0
fast_reauth=1

network={
    key_mgmt=MACSEC
    eapol_flags=0
    macsec_policy=1
    macsec_integ_only=0
    mka_cak=00112233445566778899aabbccddeeff
    mka_ckn=0123456789abcdef0123456789abcdef
}
```

Тут `mka_cak` — це 128-бітний майстер-ключ, а `mka_ckn` — його ідентифікатор (CKN). Коли `wpa_supplicant` запускається, він самостійно створює інтерфейс `macsec` і керує ключами.

## Висновок

MACsec у ядрі Linux — це потужний інструмент для забезпечення конфіденційності та цілісності даних на другому рівні мережевої моделі. Завдяки інтеграції з утилітою `iproute2` та демоном `wpa_supplicant`, налаштування MACsec є відносно простим. Апаратне розвантаження на сучасних SmartNICs дозволяє використовувати MACsec на швидкостях до 100 Гбіт/с і вище без створення "вузьких місць" у продуктивності.
