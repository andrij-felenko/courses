# 📋 Інтерфейс та структури мережевого io_uring: SendZC, RecvZC та PBUF_RING

Цей довідник описує низькорівневі структури даних, опкоди операцій, прапорці Submission Queue Entry (SQE) та Completion Queue Entry (CQE), а також інтерфейси реєстрації буферних кілець (`IORING_REGISTER_PBUF_RING`), які формують мережеву поверхню підсистеми `io_uring` у ядрі Linux.

Мережевий ввід-вивід в `io_uring` побудовано на основі набору асинхронних опкодів та системних викликів реєстрації ресурсів. Використання спеціалізованих прапорців дозволяє управляти режимами копіювання, реєстрацією фіксованих буферів пам'яті, багаторазовим прийомом пакетизованих даних у режимі Multishot та обробкою двофазних нотифікацій DMA-завершень.

## Опкоди мережевих операцій

Підсистема `io_uring` виділяє окремі константи опкодів у полі `io_uring_sqe.opcode` для ініціалізації асинхронних мережевих викликів. Кожен опкод визначає семантику виконання запиту в ядрі Linux та структуру супутніх прапорців.

:::tabs
```c
/* c */
enum io_uring_op {
    IORING_OP_SEND          = 26,   /* Стандартне копіювальне відправлення */
    IORING_OP_RECV          = 27,   /* Стандартне копіювальне отримання */
    IORING_OP_ACCEPT        = 28,   /* Прийняття нових TCP-з'єднань */
    IORING_OP_CONNECT       = 31,   /* Ініціалізація вихідного TCP-з'єднання */
    IORING_OP_SEND_ZC       = 38,   /* Zero-Copy відправлення даних (Linux 6.0+) */
    IORING_OP_RECV_ZC       = 52,   /* Zero-Copy отримання даних (Linux 6.7+) */
    IORING_OP_URING_CMD     = 46,   /* Passthrough команди до сокетів/пристроїв */
};
```

```cpp
// cpp
#include <cstdint>

enum class IoUringOp : std::uint8_t {
    Send        = 26,   // Стандартне копіювальне відправлення
    Recv        = 27,   // Стандартне копіювальне отримання
    Accept      = 28,   // Прийняття нових TCP-з'єднань
    Connect     = 31,   // Ініціалізація вихідного TCP-з'єднання
    SendZC      = 38,   // Zero-Copy відправлення даних (Linux 6.0+)
    RecvZC      = 52,   // Zero-Copy отримання даних (Linux 6.7+)
    UringCmd    = 46,   // Passthrough команди до сокетів/пристроїв
};
```
:::

### Повний опис семантики мережевих опкодів

- `IORING_OP_SEND` — класичне відправлення даних із копіюванням у ядро (`memcpy`). Ядро виділяє проміжний буфер у `sk_buff`, копіює туди байти з буфера користувача і передає пакет мережевому драйверу. Після повернення CQE буфер користувача можна негайно перевикористовувати.
- `IORING_OP_RECV` — класичне отримання даних із копіюванням із проміжного мережевого буфера ядра у простір користувача.
- `IORING_OP_ACCEPT` — асинхронне прийняття вхідного TCP-з'єднання на слухаючому сокеті. У стандартному режимі генерує один CQE з новим файловим дескриптором. При встановленому прапорці `IORING_ACCEPT_MULTISHOT` працює у багаторазовому режимі.
- `IORING_OP_CONNECT` — асинхронна ініціалізація вихідного TCP-з'єднання. Повертає 0 у `cqe->res` при успішному триетапному узгодженні TCP (Handshake) або `-EINPROGRESS` при неблокуючому виконанні.
- `IORING_OP_SEND_ZC` — відправка даних без копіювання (Zero-Copy Send). Ядро запікає сторінки пам'яті користувача або бере їх із попередньо зареєстрованого масиву `IORING_REGISTER_BUFFERS`, формуючи `sk_buff` без використанні `memcpy()`. Повертає два CQE: результат і нотифікацію.
- `IORING_OP_RECV_ZC` — отримання даних без копіювання (Zero-Copy Receive). Використовує апаратне розділення заголовків (Header-Data Split) та Devmem TCP (`DMABUF`) для запису корисного навантаження безпосередньо у буфери користувача.
- `IORING_OP_URING_CMD` — паснаскрізне виконання прямих команд драйвера сокета чи мережевої карти, оминаючи класичний шар VFS та `sys_ioctl()`.

## Специфікація структури Submission Queue Entry (SQE) для SendZC

Структура `io_uring_sqe` розміром 64 байти заповнюється застосунком для ініціалізації мережевої операції `IORING_OP_SEND_ZC`. Кожне поле виконує чітко визначену роль при взаємодії із мережевим стеком ядра:

:::tabs
```c
/* c */
struct io_uring_sqe {
    __u8   opcode;      /* IORING_OP_SEND_ZC */
    __u8   flags;       /* IOSQE_FIXED_FILE, IOSQE_CQE_SKIP_SUCCESS тощо */
    __u16  ioprio;      /* Прапорці відправки: IORING_RECVSEND_FIXED_BUF тощо */
    __s32  fd;          /* Мережевий файловий дескриптор (сокет) */
    __u64  off;         /* Не використовується або розширений зміщення */
    __u64  addr;        /* Вказівник на буфер користувача (char*) або offset */
    __u32  len;         /* Довжина буфера в байтах */
    __u32  msg_flags;   /* Мережеві прапорці сокета (наприклад, MSG_DONTWAIT) */
    __u64  user_data;   /* Ідентифікатор запиту користувача */
    __u16  buf_index;   /* Індекс зареєстрованого буфера (якщо в іоprio є FIXED_BUF) */
    __u16  personality; /* Права доступу / credentials */
    __u32  file_index;  /* Індекс у таблиці зареєстрованих файлів */
    __u64  addr3;       /* Прапорці нотифікації або розширені параметри */
};
```

```cpp
// cpp
#include <cstdint>

struct alignas(64) IoUringSqe {
    std::uint8_t   opcode;      // IORING_OP_SEND_ZC
    std::uint8_t   flags;       // IOSQE_FIXED_FILE тощо
    std::uint16_t  ioprio;      // Прапорці відправки: IORING_RECVSEND_FIXED_BUF
    std::int32_t   fd;          // Мережевий файловий дескриптор (сокет)
    std::uint64_t  off;         // Зміщення у фіксованому буфері
    std::uint64_t  addr;        // Вказівник на буфер користувача або offset
    std::uint32_t  len;         // Довжина буфера в байтах
    std::uint32_t  msg_flags;   // Мережеві прапорці сокета (MSG_DONTWAIT)
    std::uint64_t  user_data;   // 64-бітний тег користувача
    std::uint16_t  buf_index;   // Індекс фіксованого буфера у реєстрі
    std::uint16_t  personality; // Контекст прав доступу
    std::uint32_t  file_index;  // Індекс фіксованого сокета
    std::uint64_t  addr3;       // Розширені прапорці сповіщення
};
```
:::

#### Детальний аналіз полів SQE:

- `opcode` (1 байт) — код операції. Для Zero-Copy відправки встановлюється значення `IORING_OP_SEND_ZC` (38).
- `flags` (1 байт) — загальні прапорці запиту `io_uring`. Значення `IOSQE_FIXED_FILE` вказує ядру, що поле `fd` містить не прямий системний дескриптор, а індекс сокета у попередньо зареєстрованому масиві файлів `IORING_REGISTER_FILES`.
- `ioprio` (2 байти) — містить спеціалізовані мережеві прапорці `io_uring`:
  - `IORING_RECVSEND_FIXED_BUF` (`1U << 0`) — інформує ядро, що поле `addr` містить зміщення всередині попередньо зареєстрованого буфера з індексом `buf_index` (зареєстрованого через `IORING_REGISTER_BUFFERS`). Це повністю скасовує витрати на `pin_user_pages()` при кожному запиті.
  - `IORING_RECVSEND_NOTIF_FLUSH` (`1U << 1`) — вимагає від ядра негайно згенерувати Notification CQE після завершення передачи, не чекаючи накопичення пакетів у внутрішньому батчі ядра.
  - `IORING_SEND_ZC_REPORT_USAGE` (`1U << 2`) — вказує ядру повернути у другому CQE додаткові метадані про те, чи вдалося мережевому стеку реально використати Zero-Copy, чи ядро змушене було відновити `memcpy()` (копіювальний фолбек).
- `fd` (4 байти) — файловий дескриптор мережевого сокета (або індекс фіксованого файлу).
- `addr` (8 байт) — 64-бітна віртуальна адреса буфера у просторі користувача. Якщо встановлено `IORING_RECVSEND_FIXED_BUF`, це поле інтерпретується як відносне зміщення (offset) від початку зареєстрованого буфера `buf_index`.
- `len` (4 байти) — розмір блоку даних для відправлення у байтах.
- `msg_flags` (4 байти) — стандартні мережеві прапорці сокета POSIX, такі як `MSG_DONTWAIT`, `MSG_MORE`, `MSG_NOSIGNAL`.
- `user_data` (8 байт) — 64-бітна мітка користувача, яка без змін копіюється ядром у відповідні об'єкти CQE для ідентифікації запиту при обробці кольца завершень.

## Прапорці completion-подій CQE

При виконанні Zero-Copy відправки застосунок отримує два об'єкти `struct io_uring_cqe`. Вони розрізняються бітовою маскою в полі `cqe->flags`:

:::tabs
```c
/* c */
struct io_uring_cqe {
    __u64  user_data;   /* Такий самий user_data, як у SQE */
    __s32  res;         /* Кількість відправлених байт (<0 — код помилки) */
    __u32  flags;       /* Бітові прапорці стану CQE */
};
```

```cpp
// cpp
#include <cstdint>

struct IoUringCqe {
    std::uint64_t  user_data;   // 64-бітний тег запиту
    std::int32_t   res;         // Кількість байт або -errno
    std::uint32_t  flags;       // Прапорці статусу (MORE, NOTIF тощо)
};
```
:::

### Повна таблиця прапорців поля flags структури CQE

Мережеві операції `io_uring` використовують бітову маску поля `flags` структури `io_uring_cqe` для передачі метаданих про стан виконання запиту та життєвий цикл пам'яті:

| Прапорець | Бітова маска | Опис семантики прапорця у ядрі |
| :--- | :--- | :--- |
| `IORING_CQE_F_MORE` | `1U << 1` | Сигналізує, що дана операція ще не завершена остаточно, і програма повинен очікувати щонайменше ще один CQE із таким самим `user_data`. У SendZC встановлюється у першому CQE. |
| `IORING_CQE_F_NOTIF` | `1U << 3` | Вказує, що даний CQE є сповіщенням (Notification CQE). Повертається, коли NIC та мережевий стек повністю звільнили буфер пам'яті. Звільняє буфер користувача. |
| `IORING_CQE_F_BUFFER` | `1U << 0` | Вказує, що в старших 16 бітах поля `flags` (`cqe->flags >> 16`) запечений `buffer_id` з кільця Provided Buffers, використаний ядром для запису вхідного пакета. |
| `IORING_CQE_F_SOCK_NONEMPTY` | `1U << 2` | Оптимізація для прийому: інформує застосунок, що в системному буфері сокета лишилися незчитані байти, і можна одразу повторити `recv`. |

```
Перший CQE (Результат IO):
  res = N (байти)
  flags = IORING_CQE_F_MORE
  --> Буфер у користувача все ще заблоковано DMA!

Другий CQE (Сповіщення):
  res = 0
  flags = IORING_CQE_F_NOTIF
  --> Буфер безпечно розблоковано, можна перезаписувати.
```

## Інтерфейс реєстрації буферів: IORING_REGISTER_PBUF_RING

Для ефективного прийому даних (`multishot recv`) ядро потребує доступу до пулу буферів користувача. Замість окремого системного виклику на кожен буфер, `io_uring` використовує кільце буферів у спільній пам'яті (`PBUF_RING`).

Реєстрація здійснюється через системний виклик `io_uring_register` з кодом операції `IORING_REGISTER_PBUF_RING`:

:::tabs
```c
/* c */
struct io_uring_buf_reg {
    __u64 ring_addr;    /* Базова адреса масиву struct io_uring_buf в ОЗП */
    __u32 ring_entries; /* Кількість елементів (мусить бути ступенем двійки) */
    __u16 bgid;         /* Ідентифікатор групи буферів (Buffer Group ID) */
    __u16 flags;        /* Прапорці конфігурації кільця */
    __u64 resv[3];      /* Зарезервовано для майбутніх ядер */
};
```

```cpp
// cpp
#include <cstdint>

struct IoUringBufReg {
    std::uint64_t ring_addr;    // Адреса кольца io_uring_buf в ОЗП
    std::uint32_t ring_entries; // Кількість буферів (2^N)
    std::uint16_t bgid;         // Buffer Group ID
    std::uint16_t flags;        // Конфігураційні прапорці
    std::uint64_t resv[3];      // Резерв ядра
};
```
:::

Один елемент буферного кільця описується структурою `io_uring_buf`:

:::tabs
```c
/* c */
struct io_uring_buf {
    __u64 addr;     /* Фізична або віртуальна адреса буфера користувача */
    __u32 len;      /* Максимальна ємність буфера у байтах */
    __u16 bid;      /* Унікальний ідентифікатор буфера (Buffer ID) */
    __u16 resv;     /* Вирівнювання структури */
};
```

```cpp
// cpp
#include <cstdint>

struct IoUringBuf {
    std::uint64_t addr;     // Вказівник на ОЗП користувача
    std::uint32_t len;      // Ємність у байтах
    std::uint16_t bid;      // Унікальний Buffer ID
    std::uint16_t resv;     // Вирівнювання
};
```
:::

Масив `io_uring_buf` розміщується у пам'яті, до якої мають доступ і ядро, і простір користувача. Наприкінці масиву ядро та застосунок синхронізують покажчики head/tail через структуру `struct io_uring_buf_ring`.

### Додавання буферів у простір PBUF_RING

Для повернення буфера в пул після обробки програма виконує атомарне оновлення покажчика хвоста кільця без жодних системних викликів:

:::tabs
```c
/* c */
void io_uring_buf_ring_add(struct io_uring_buf_ring *br, 
                           void *addr, 
                           unsigned int len, 
                           unsigned short bid, 
                           int mask, 
                           int buf_offset) {
    struct io_uring_buf *buf = &br->bufs[(br->tail + buf_offset) & mask];
    buf->addr = (unsigned long)addr;
    buf->len = len;
    buf->bid = bid;
}

void io_uring_buf_ring_advance(struct io_uring_buf_ring *br, int count) {
    /* Атомарний бар'єр пам'яті гарантує видимість записів для ядра */
    __atomic_store_n(&br->tail, br->tail + count, __ATOMIC_RELEASE);
}
```

```cpp
// cpp
#include <atomic>
#include <cstdint>
#include <span>

struct IoUringBufRingHelper {
    IoUringBuf* bufs;
    std::uint16_t* tail_ptr;

    void add(void* addr, std::uint32_t len, std::uint16_t bid, std::uint16_t mask, int offset) noexcept {
        std::uint16_t current_tail = *tail_ptr;
        auto& buf = bufs[(current_tail + offset) & mask];
        buf.addr = reinterpret_cast<std::uint64_t>(addr);
        buf.len = len;
        buf.bid = bid;
    }

    void advance(std::uint16_t count) noexcept {
        auto* atomic_tail = reinterpret_cast<std::atomic<std::uint16_t>*>(tail_ptr);
        atomic_tail->fetch_add(count, std::memory_order_release);
    }
};
```
:::

## Прапорці та параметри Multishot

При виконанні `IORING_OP_RECV` або `IORING_OP_ACCEPT` у режимі multishot в SQE додаються наступні прапорці:

- `IORING_RECV_MULTISHOT` (у полі `ioprio`) — переводить операцію прийому в багаторазовий режим. Ядро генеруватиме CQE для кожного нового мережевого пакета, вибираючи буфер із `bgid` (Buffer Group ID), поки не виникне помилка або з'єднання не закриється.
- `IORING_ACCEPT_MULTISHOT` (у полі `ioprio`) — переводить операцію прийняття з'єднань у режим безнеперервного генерації CQE для кожного нового сокета в черзі `listen()`.

## Коди помилок та специфічні параметри sysctl

Мережеві операції `io_uring` повертають стандартні POSIX коди помилок у полі `cqe->res` (із від'ємним знаком), а також деякі специфічні для `io_uring` та Zero-Copy статуси:

| Код помилки | Числове значення | Причина виникнення у Zero-Copy |
| :--- | :--- | :--- |
| `-ENOBUFS` | `-105` | У кільці Provided Buffers немає вільних елементів під час надходження пакета (`multishot recv`) або вичерпано `optmem_max`. |
| `-EBUSY` | `-16` | Спроба зареєструвати буфери або викликати операцію при вичерпанні внутрішніх ресурсів ядра. |
| `-EAGAIN` | `-11` | Сокет перебуває у неблокуючому стані, і дані тимчасово відсутні у черзі прийому. |
| `-EFAULT` | `-14` | Передано некоректну або незакріплену адресу буфера у простір ядра. |
| `-EEXIST` | `-17` | Спроба зареєструвати PBUF_RING із `bgid`, який вже зареєстровано в цьому контексті `io_uring`. |

### Системні параметри ядра для налаштування пам'яті ZC

Управління ресурсами пам'яті для нотифікацій та закріплених сторінок регулюється через `/proc/sys/net/`:

- `/proc/sys/net/core/optmem_max` — максимальний обсяг пам'яті у байтах, який дозволено виділяти під мережеві нотифікації та розширені структури управління буферами сокета. При використанні багатьох паралельних `SEND_ZC` за недостатнього `optmem_max` операції можуть завершуватися з помилкою `-ENOBUFS`.
- `/proc/sys/net/core/wmem_default` та `wmem_max` — обмежують ємність буфера відправки сокета, впливаючи на розмір батчингу двофазних сповіщень.
- `/proc/sys/net/core/rmem_default` та `rmem_max` — обмежують максимальний розмір буфера прийому, що визначає ємність кільця `PBUF_RING` під час обробки пікових сплесків трафіку.
