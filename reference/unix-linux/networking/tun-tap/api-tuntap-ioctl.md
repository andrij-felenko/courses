# 📋 Довідник системних викликів та ioctl для TUN/TAP

Цей довідник містить вичерпну специфікацію системних викликів, команд `ioctl`, структур даних, прапорців конфігурації, псевдофайлових систем та системних зауважень щодо роботи із символьним пристроєм `/dev/net/tun` у системі Linux.

## Заголовочні файли та шляхи пристрою

Для роботи з інтерфейсом TUN/TAP у мовах C та C++ необхідно підключити наступні заголовочні файли ядра Linux та системних бібліотек POSIX:

```c
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <sys/socket.h>
#include <linux/if.h>
#include <linux/if_tun.h>
```

Головною точкою взаємодії між простором користувача та драйвером ядра є спеціальний вузол символьного пристрою у файловій системі:
- `/dev/net/tun` (major: 10, minor: 200).

Цей вузол створюється підсистемою `devtmpfs` під час завантаження ядра Linux та контролюється драйвером `drivers/net/tun.c`.

## Ядерні структури даних

### 1. `struct ifreq`

Запит на створення, підключення або зчитування параметрів мережевого інтерфейсу передається через стандартну структуру `struct ifreq` із заголовочного файлу `<linux/if.h>`:

```c
struct ifreq {
    char ifr_name[IFNAMSIZ]; /* Ім'я інтерфейсу (наприклад, "tun0", "tap1") */
    union {
        short ifru_flags;    /* Прапорці режиму TUN/TAP */
        int   ifru_ivalue;   /* Цілочисельне значення параметрів */
        /* ... інші поля union ... */
    } ifr_ifru;
};

#define ifr_flags ifr_ifru.ifru_flags
```

Поля структури мають наступне призначення:
- `ifr_name`: Рядок довжиною до `IFNAMSIZ` (16 байт, включаючи нуль-термінатор `\0`). Якщо передати порожній рядок (перший байт `\0`), ядро автоматично згенерує вільне ім'я за шаблоном `tun%d` або `tap%d`.
- `ifr_flags`: Бітова маска прапорців режиму та опцій, що визначають тип створюваного інтерфейсу та його поведінку (див. розділ Прапорці конфігурації).

### 2. `struct tun_pi` (Packet Information Header)

За замовчуванням перед кожним пакетом, який зчитується з дескриптора `/dev/net/tun` або записується в нього, драйвер ядра додає 4-байтовий заголовок метаданих `struct tun_pi`:

```c
struct tun_pi {
    unsigned short flags;     /* Прапорці пакета (наприклад, TUN_PKT_STRIP) */
    __be16         proto;     /* Протокол мережевого рівня в мережевому порядку байт (EtherType) */
};
```

Поля заголовка пакета:
- `flags`: Бітова маска ядерних прапорців. Зокрема, прапор `TUN_PKT_STRIP` позначає ситуацію, коли зчитаний пакет було обрізано через те, що переданий буфер у просторі користувача виявився меншим за фактичний розмір пакета.
- `proto`: Значення EtherType в форматі Big-Endian (Network Byte Order). Для мережевих IP-пакетів IPv4 це значення `ETH_P_IP` (`0x0800`), для IPv6 — `ETH_P_IPV6` (`0x86DD`), для запитів ARP — `ETH_P_ARP` (`0x0806`).

Якщо при ініціалізації викликом `ioctl(TUNSETIFF)` у масці `ifr_flags` було вказано прапорець `IFF_NO_PI`, заголовок `struct tun_pi` відключається, і додаток зчитує та записує чистий IP-пакет або Ethernet-кадр без 4-байтового префікса.

### 3. `struct virtio_net_hdr` (VirtIO Net Header)

При використанні прапорця `IFF_VNET_HDR` перед кожним пакетом додається заголовок розвантаження VirtIO, який дозволяє гіпервізорам передавати кадри великого розміру без проміжної фрагментації:

```c
struct virtio_net_hdr {
    uint8_t  flags;             /* VIRTIO_NET_HDR_F_NEEDS_CSUM тощо */
    uint8_t  gso_type;          /* VIRTIO_NET_HDR_GSO_TCPV4 тощо */
    uint16_t hdr_len;           /* Довжина заголовка L4 */
    uint16_t gso_size;          /* Розмір MSS для сегментації */
    uint16_t csum_start;        /* Зсув початку обчислення контрольної суми */
    uint16_t csum_offset;       /* Зсув поля збереження контрольної суми */
};
```

Ця структура дає змогу гостьовій операційній системі під час віртуалізації QEMU/KVM передавати пакети розміром до 64 КБ (TCP Segmentation Offload — TSO) прямо через пристрій TAP, перекладаючи задачу фрагментації на фізичну мережеву карту хост-системи.

## Повний перелік команд `ioctl`

Усі маніпуляції з мережевим пристроєм виконуються через системний виклик `ioctl(fd, request, arg)`.

| Команда `ioctl` | Тип аргументу | Опис та поведінка |
| :--- | :--- | :--- |
| `TUNSETIFF` | `struct ifreq *` | Прив'язує відкритий файловий дескриптор до мережевого інтерфейсу TUN або TAP. |
| `TUNSETPERSIST` | `int` (0 або 1) | Встановлює або знімає прапор постійності (persistence) інтерфейсу в ядрі. |
| `TUNSETOWNER` | `uid_t` | Призначає UID користувача-власника для непривілейованого доступу. |
| `TUNSETGROUP` | `gid_t` | Призначає GID групи-власника для непривілейованого доступу. |
| `TUNSETLINK` | `int` | Встановлює тип каналу (ARP hardware type, наприклад `ARPHRD_ETHER`). |
| `TUNSETQUEUE` | `struct ifreq *` | Підключає або відключає чергу у режимі `IFF_MULTI_QUEUE`. |
| `TUNSETOFFLOAD` | `unsigned int` | Налаштовує розвантаження сегментації та контрольних сум (offloads). |
| `TUNGETIFF` | `struct ifreq *` | Зчитує поточні прапорці та ім'я прив'язаного мережевого інтерфейсу. |
| `TUNGETFEATURES` | `unsigned int *` | Зчитує бітову маску підтримуваних драйвером ядра можливостей. |
| `TUNSETVNETHDRSZ`| `int *` | Задає розмір заголовка VirtIO (підтримує розширені версії `virtio_net_hdr_mrg_rxbuf`). |
| `TUNGETVNETHDRSZ`| `int *` | Зчитує поточний розмір заголовка VirtIO. |

### Детальний опис механіки основних команд `ioctl`

#### 1. `TUNSETIFF`

Виклик `TUNSETIFF` є ключовим етапом ініціалізації пристрою:

```c
struct ifreq ifr;
memset(&ifr, 0, sizeof(ifr));
ifr.ifr_flags = IFF_TUN | IFF_NO_PI;
strncpy(ifr.ifr_name, "tun0", IFNAMSIZ);

if (ioctl(fd, TUNSETIFF, (void *)&ifr) < 0) {
    perror("TUNSETIFF failed");
}
```

- **Призначення:** Зв'язує відкритий файловий дескриптор `/dev/net/tun` із мережевим інтерфейсом.
- **Поведінка ядра:** Драйвер шукає мережевий пристрій із вказаним ім'ям `ifr_name`. Якщо пристрій існує і поточний процес має відповідні права, дескриптор підключається до нього. Якщо пристрій відсутній, ядро динамічно виділяє новий об'єкт `struct net_device`, реєструє його в системі та повертає згенероване ім'я у полі `ifr_name`.
- **Вимоги до прав:** Створення нового пристрою або зміна конфігурації вимагає наявності привілеїв `CAP_NET_ADMIN` у поточному просторі імен користувачів (user namespace).

#### 2. `TUNSETPERSIST`

За замовчуванням віртуальний інтерфейс є тимчасовим: як тільки процес закриває файловий дескриптор `fd` (або завершується аварійно), ядро автоматично видаляє мережевий пристрій `tun0` із системи разом із усіма його IP-адресами та маршрутами.

```c
/* Зробити пристрій постійним */
ioctl(fd, TUNSETPERSIST, 1);

/* Видалити статус постійності */
ioctl(fd, TUNSETPERSIST, 0);
```

Виклик `TUNSETPERSIST` із значенням `1` робить пристрій постійним. Він залишається піднятим навіть після закриття дескриптора, що зручно для системних сервісів та гіпервізорів QEMU.

#### 3. `TUNSETOWNER` та `TUNSETGROUP`

Передають права на відкриття і керування створеним постійним інтерфейсом конкретному непривілейованому користувачу або групі POSIX:

```c
uid_t uid = 1000;
ioctl(fd, TUNSETOWNER, uid);
```

Після цього користувач із UID `1000` може відкривати `/dev/net/tun` і виконувати `TUNSETIFF` для підключення до `tun0` без використання `sudo` чи `CAP_NET_ADMIN`.

#### 4. `TUNSETQUEUE`

Використовується в багаточерговому режимі (`IFF_MULTI_QUEUE`) для динамічного підключення або відключення додаткових файлових дескрипторів. У багатопотокових реакторах I/O це дозволяє кожному робочому потоку володіти власним файловим дескриптором для паралельного зчитання пакетів із відповідної черги ЦП.

```c
struct ifreq ifr;
memset(&ifr, 0, sizeof(ifr));
ifr.ifr_flags = IFF_ATTACH_QUEUE;
ioctl(fd, TUNSETQUEUE, (void *)&ifr);
```

#### 5. `TUNSETOFFLOAD`

Використовується для конфігурації програмного розвантаження обчислення контрольних сум та сегментації:

```c
unsigned int offload_flags = TUN_F_CSUM | TUN_F_TSO4 | TUN_F_TSO6;
if (ioctl(fd, TUNSETOFFLOAD, offload_flags) < 0) {
    perror("TUNSETOFFLOAD failed");
}
```

#### 6. `TUNGETFEATURES`

Дозволяє програмі перед викликом `TUNSETIFF` дізнатися, які саме прапорці та можливості підтримуються поточним модулем ядра:

```c
unsigned int features = 0;
if (ioctl(fd, TUNGETFEATURES, &features) >= 0) {
    if (features & IFF_MULTI_QUEUE) {
        printf("Kernel supports Multi-Queue TUN/TAP\n");
    }
}
```

## Прапорці конфігурації (`ifr_flags`)

Бітові маски для поля `ifr_flags` при використанні виклику `TUNSETIFF`:

| Прапорець | Значення | Опис та специфікація |
| :--- | :--- | :--- |
| `IFF_TUN` | `0x0001` | Створити віртуальний інтерфейс L3 (Network Tunnel, IP-пакети). |
| `IFF_TAP` | `0x0002` | Створити віртуальний інтерфейс L2 (Network TAP, Ethernet-кадри). |
| `IFF_NO_PI` | `0x1000` | Не додавати 4-байтовий заголовок `struct tun_pi` до даних. |
| `IFF_ONE_QUEUE` | `0x2000` | Застаріла оптимізація черги: блокувати додавання пакетів при заповненні. |
| `IFF_VNET_HDR` | `0x4000` | Префіксувати кадри заголовком `struct virtio_net_hdr`. |
| `IFF_TUN_EXCL` | `0x8000` | Гарантувати ексклюзивне створення: повернути помилку `EEXIST`, якщо пристрій вже існує. |
| `IFF_MULTI_QUEUE` | `0x0100` | Дозволити прив'язку кількох файлових дескрипторів (черг) до одного пристрою. |

## Файлові операції над `/dev/net/tun`

Після успішного виконання `TUNSETIFF` файловий дескриптор підтримує стандартний семантичний контракт POSIX I/O:

### 1. `read(fd, buf, count)`

- **Опис:** Зчитує пакет із черги відправки (TX queue) мережевого інтерфейсу.
- **Повертає:** Кількість прочитаних байт (включаючи `struct tun_pi` чи `struct virtio_net_hdr`, якщо вони увімкнені).
- **Помилки:**
  - `EAGAIN` / `EWOULDBLOCK`: Пристрій відкрито з `O_NONBLOCK`, а черга прийому порожня.
  - `EINVAL`: Переданий буфер `buf` менший за розмір кадру.
  - `EFAULT`: Вказано некоректну адресу пам'яті буфера `buf`.

### 2. `write(fd, buf, count)`

- **Опис:** Впорскує пакет у приймальну чергу (RX queue) мережевого інтерфейсу. Ядро сприймає цей пакет так, ніби він фізично надійшов із мережевого кабелю.
- **Повертає:** Кількість записаних байт.
- **Помилки:**
  - `EBADFD`: Дескриптор ще не прив'язано до інтерфейсу через `TUNSETIFF`.
  - `EINVAL`: Некоректний розмір пакета або пошкоджені заголовки.
  - `EFAULT`: Вказано некоректну адресу пам'яті буфера `buf`.

## Інспекція через sysfs, procfs та ftrace

Діагностика стану пристроїв TUN/TAP у системі Linux здійснюється через наступні псевдофайлові системи:

- **Інспекція мережевих лічильників у procfs:**
  ```bash
  cat /proc/net/dev | grep tun0
  ```
  Відображає байтові та пакетові лічильники `bytes`, `packets`, `errs`, `drop`, `fifo`, `frame`.

- **Системні параметри sysfs:**
  ```bash
  # Статус інтерфейсу та MTU
  cat /sys/class/net/tun0/operstate
  cat /sys/class/net/tun0/mtu

  # Атрибути пристрою TUN/TAP
  cat /sys/class/net/tun0/tun_flags
  cat /sys/class/net/tun0/owner
  cat /sys/class/net/tun0/group
  cat /sys/class/net/tun0/tx_queue_len
  ```

- **Простеження через ftrace та tracepoints:**
  Для аналізу проходження пакетів усередині драйвера `tun.c` використовують події ядра:
  ```bash
  # Увімкнення трасування проходження пакетів через TUN
  echo 1 > /sys/kernel/tracing/events/net/netif_rx/enable
  echo 1 > /sys/kernel/tracing/events/net/net_dev_xmit/enable
  cat /sys/kernel/tracing/trace_pipe
  ```

## Коди помилок системних викликів

При роботі з `/dev/net/tun` системні виклики можуть повертати наступні значення `errno`:

| Код `errno` | Символічне ім'я | Причина виникнення |
| :--- | :--- | :--- |
| `1` | `EPERM` | Відсутність привілеїв `CAP_NET_ADMIN` для створення або конфігурації пристрою. |
| `14` | `EFAULT` | Некоректна адреса буфера у просторі користувача під час виклику `read()` або `write()`. |
| `16` | `EBUSY` | Інтерфейс вже підключено до іншого процесу без прапорця `IFF_MULTI_QUEUE`. |
| `17` | `EEXIST` | Вказано `IFF_TUN_EXCL`, а мережевий пристрій із таким ім'ям вже існує. |
| `19` | `ENODEV` | Вузол `/dev/net/tun` відсутній або модуль ядра `tun` не завантажено. |
| `22` | `EINVAL` | Передано некоректні прапорці в `struct ifreq` або невалідну команду `ioctl`. |
| `25` | `ENOTTY` | Команда `ioctl` не підтримується цим символьним пристроєм. |
| `77` | `EBADFD` | Спроба виконання `read()` або `write()` до виклику `TUNSETIFF`. |
