# 📋 Довідник API: SOCKMAP, SOCKHASH, sk_skb та sk_msg

Цей довідник містить детальний опис типів BPF-карт, типів програм, системних вердиктів, структур контексту та допоміжних функцій ядра (bpf_helpers) для прискорення сокетів у Linux.

## 1. Типи BPF-карт для збереження сокетів

Для зберігання посилань на відкриті мережеві сокети ядро Linux надає два спеціалізованих типи BPF-карт. Додавання файлового дескриптора сокета до цих карт автоматично ініціалізує внутрішній об'єкт `struct sk_psock` та підміняє таблицю функцій протоколу `struct proto` для цього сокета з `tcp_prot` на BPF-обгортку `tcp_bpf_prot`.

### 1.1 `BPF_MAP_TYPE_SOCKMAP`

Масив сокетів із суцільною цілочисельною індексацією (`__u32`).

* **Тип ключа**: `__u32` (цілочисельний індекс масиву від `0` до `max_entries - 1`).
* **Тип значення**: `__u32` (файловий дескриптор сокета `fd` при оновленні з простору користувача або 64-бітне системне ID сокета у ядрі).
* **Характеристики**: Забезпечує максимально швидкий доступ O(1) за безпосереднім індексом масиву. Ідеально підходить для парних сокетних з'єднань (наприклад, парування сокетів проксі-сервера та бекенду).

Оголошення карти в BPF-програмі (BTF-defined map syntax):

```c
struct {
    __uint(type, BPF_MAP_TYPE_SOCKMAP);
    __uint(max_entries, 65535);
    __type(key, __u32);
    __type(value, __u32);
} sock_map SEC(".maps");
```

### 1.2 `BPF_MAP_TYPE_SOCKHASH`

Хеш-таблиця сокетів із довільним типом ключа, визначеним користувачем.

* **Тип ключа**: Довільна структура даних (найчастіше 5-tuple структура, що описує IP-адреси, порти та ідентифікатор мережевого простору назв).
* **Тип значення**: `__u32` (файловий дескриптор сокета `fd`).
* **Характеристики**: Дозволяє асоціативний пошук сокетів за довільними мережевими атрибутами. Забезпечує динамічне відстеження тисяч TCP-з'єднань у Service Mesh або NAT-шлюзах без необхідності ведення таблиць індексів у простір користувача.

Оголошення карти в BPF-програмі:

```c
struct sock_key {
    __u32 sip;
    __u32 dip;
    __u32 sport;
    __u32 dport;
};

struct {
    __uint(type, BPF_MAP_TYPE_SOCKHASH);
    __uint(max_entries, 102400);
    __type(key, struct sock_key);
    __type(value, __u32);
} sock_hash SEC(".maps");
```

## 2. Типи BPF-програм та точки прикріплення (Attach Targets)

Для управління потоком даних у сокетних картах використовуються два класи BPF-програм: `BPF_PROG_TYPE_SK_SKB` та `BPF_PROG_TYPE_SK_MSG`.

### 2.1 `BPF_PROG_TYPE_SK_SKB`

Програми даного типу оперують буферами сокетів `struct __sk_buff`. Вони прикріплюються до сокетної карти і спрацьовують під час обробки пакетів у ядрі.

#### `BPF_SK_SKB_STREAM_PARSER`
* **Точка прикріплення**: `BPF_SK_SKB_STREAM_PARSER` до карти `SOCKMAP` або `SOCKHASH`.
* **Контекст**: `struct __sk_buff *skb`.
* **Призначення**: Аналізує вхідний потік байтів TCP та визначає довжину логічного кадру (наприклад, HTTP-запиту чи TLS-запису).
* **Повертане значення**:
  * `len > 0`: Довжина сформованого кадру у байтах. Ядро очікує накопичення цієї кількості байтів, після чого передає `skb` програмі вердикту.
  * `0`: Даних недостатньо для визначення довжини, ядро продовжує збір байтів.
  * `< 0`: Помилка парсингу кадру, з'єднання розривається.

#### `BPF_SK_SKB_STREAM_VERDICT`
* **Точка прикріплення**: `BPF_SK_SKB_STREAM_VERDICT` до карти `SOCKMAP` або `SOCKHASH`.
* **Контекст**: `struct __sk_buff *skb`.
* **Призначення**: Приймає рішення про маршрутизацію сформованого кадру `skb`.
* **Повертане значення**: Системний вердикт `SK_PASS`, `SK_DROP` або результати виконання функцій `bpf_sk_redirect_*`.

### 2.2 `BPF_PROG_TYPE_SK_MSG`

Програми даного типу оперують векторами сторінок пам'яті користувача `struct sk_msg_md` безпосередньо у контексті системного виклику `sendmsg()`, до формування `sk_buff`.

* **Точка прикріплення**: `BPF_SK_MSG_VERDICT` до карти `SOCKMAP` або `SOCKHASH`.
* **Контекст**: `struct sk_msg_md *msg`.
* **Призначення**: Перехоплює та перенаправляє дані відправки на найранішому етапі системного виклику.
* **Повертане значення**: Системний вердикт `SK_PASS`, `SK_DROP` або результати виконання функцій `bpf_msg_redirect_*`.

## 3. Таблиця вердиктів BPF-програм (Return Values)

BPF-програми вердикту повертають цілочисельне значення, яке визначає подальшу долю даних у ядрі.

| Вердикт | Числове значення у C | Детальна поведінка ядра Linux |
| :--- | :--- | :--- |
| `SK_DROP` | `0` | Пакет або повідомлення негайно знищується у ядрі. Сокет відправника отримує помилку `EPIPE` або `ECONNABORTED`. Пам'ять звільняється. |
| `SK_PASS` | `1` | Пакет передається далі за стандартним сценарієм ядра через повноцінний стек протоколів TCP/IP. |
| `SK_REDIRECT` | Значення з `bpf_*_redirect_*` | Пакет або вектор сторінок перенаправляється безпосередньо у сокет-отримувач, вказаний у карті, оминаючи стек TCP/IP. |

## 4. Допоміжні функції ядра (bpf_helpers)

Для здійснення операцій перенаправлення та маніпуляції даними eBPF-програми використовують спеціальні функції ядра.

### 4.1 `bpf_sk_redirect_map`

```c
long bpf_sk_redirect_map(struct __sk_buff *skb, void *map, __u32 key, __u64 flags);
```

* **Призначення**: Перенаправляє буфер сокета `skb` у сокет, розташований за індексом `key` у масиві `map` (`SOCKMAP`).
* **Параметри**:
  * `skb`: Вказівник на контекст буфера сокета `struct __sk_buff`.
  * `map`: Вказівник на карту `BPF_MAP_TYPE_SOCKMAP`.
  * `key`: 32-бітний цілочисельний індекс сокета в масиві.
  * `flags`: Прапорці режиму перенаправлення. Основний прапорець **`BPF_F_INGRESS`** спрямовує `skb` безпосередньо у чергу прийому (`sk_receive_queue`) цільового сокета. Значення `0` спрямовує пакет у чергу відправки.
* **Повертане значення**: Повертає статус `SK_REDIRECT` у разі успіху або `SK_DROP` при помилці (наприклад, якщо за вказаним ключем сокет відсутній або закритий).

### 4.2 `bpf_sk_redirect_hash`

```c
long bpf_sk_redirect_hash(struct __sk_buff *skb, void *map, void *key, __u64 flags);
```

* **Призначення**: Аналог `bpf_sk_redirect_map`, але для карт типу `BPF_MAP_TYPE_SOCKHASH`. Вказаний `key` є вказівником на структуру ключа в пам'яті.

### 4.3 `bpf_msg_redirect_map`

```c
long bpf_msg_redirect_map(struct sk_msg_md *msg, void *map, __u32 key, __u64 flags);
```

* **Призначення**: Перенаправляє вектор сторінок даних `msg` під час системного виклику `sendmsg()` у сокет з `SOCKMAP`.
* **Параметри**:
  * `msg`: Вказівник на контекст `struct sk_msg_md`.
  * `map`: Вказівник на карту `BPF_MAP_TYPE_SOCKMAP`.
  * `key`: Індекс цільового сокета.
  * `flags`: Прапорець `BPF_F_INGRESS` для розміщення у черзі прийому сокета.

### 4.4 `bpf_msg_redirect_hash`

```c
long bpf_msg_redirect_hash(struct sk_msg_md *msg, void *map, void *key, __u64 flags);
```

* **Призначення**: Перенаправляє вектор даних `msg` під час виконання `sendmsg()` у цільовий сокет з карти `SOCKHASH`.

### 4.5 Спеціалізовані допоміжні функції для `SK_MSG`

* **`bpf_msg_apply_bytes(struct sk_msg_md *msg, __u32 bytes)`**: Вказує ядру автоматично застосовувати прийнятий вердикт BPF-програми до наступних `bytes` байтів потоку без повторного виклику BPF-програми на кожному виклику `sendmsg`. Це суттєво знижує навантаження на CPU при передачі великих файлів.
* **`bpf_msg_cork_bytes(struct sk_msg_md *msg, __u32 bytes)`**: Затримує виконання BPF-програми та накопичує у ядрі вказану кількість байтів `bytes` перед її викликом (використовується для очікування повного заголовку прикладного протоколу).
* **`bpf_msg_pull_data(struct sk_msg_md *msg, __u32 start, __u32 end, __u64 flags)`**: Гарантує лінійну неперервність буфера даних у діапазоні від `start` до `end` байтів у структурі `sk_msg_md`, дозволяючи BPF-програмі безпечно читати заголовки додатків без виходу за межі пам'яті.

## 5. Системний виклик bpf() та управління з User-Space (libbpf API)

Для завантаження BPF-програм, підключення їх до сокетних карт та додавання сокетів використовується системний виклик `bpf()` або високорівнева бібліотека `libbpf`.

### 5.1 Прикріплення BPF-програм до карт сокетів

Прикріплення BPF-програми до сокетної карти здійснюється за допомогою виклику `bpf_prog_attach()`:

```c
int bpf_prog_attach(int prog_fd, int target_fd, enum bpf_attach_type type, unsigned int flags);
```

Аргументи:
* `prog_fd`: Файловий дескриптор завантаженої BPF-програми.
* `target_fd`: Файловий дескриптор BPF-карти `SOCKMAP` або `SOCKHASH`.
* `type`: Тип токи прикріплення:
  * `BPF_SK_SKB_STREAM_PARSER` — для програм-парсерів потоку;
  * `BPF_SK_SKB_STREAM_VERDICT` — для програм-вердиктів буферів сокетів;
  * `BPF_SK_MSG_VERDICT` — для програм-вердиктів викликів sendmsg.
* `flags`: Додаткові прапорці (зазвичай `0`).

### 5.2 Додавання та видалення сокетів у картах

З простору користувача оновлення сокетної карти виконується стандартною функцією `bpf_map_update_elem()`:

```c
int bpf_map_update_elem(int map_fd, const void *key, const void *value, uint64_t flags);
```

При оновленні карти сокетів:
* `key`: Вказівник на індекс `__u32` (для SOCKMAP) або вказівник на структуру ключа (для SOCKHASH).
* `value`: Вказівник на змінну типу `int`, що містить **файловий дескриптор (fd)** відкритого сокета у просторі користувача.
* `flags`: `BPF_ANY` (створити або оновити), `BPF_NOEXIST` (створити лише новий), `BPF_EXIST` (оновити наявний).

Видалення сокета з карти здійснюється викликом `bpf_map_delete_elem(map_fd, key)`. При закритті сокета викликом `close(fd)` ядро автоматично видаляє його з усіх карт сокетів.
