## 1. Вступ та концепція MPTCP

Multipath TCP (MPTCP) — це розширення традиційного протоколу Transmission Control Protocol (TCP), яке дозволяє одному транспортному з'єднанню використовувати кілька мережевих шляхів (інтерфейсів) одночасно. Оригінальний стандарт MPTCP був описаний у RFC 6824, а його сучасна версія (v1) стандартизована в RFC 8684.

Традиційний TCP тісно прив'язує з'єднання до двох IP-адрес і двох портів. Якщо один з інтерфейсів втрачає зв'язок, TCP-з'єднання обривається. На відміну від нього, MPTCP розв'язує цю проблему, створюючи абстракцію "мета-з'єднання" (MPTCP-з'єднання), в рамках якого може існувати кілька традиційних TCP-з'єднань, що називаються *subflows* (підпотоки). 

## 2. Архітектура та підпотоки (Subflows)

В архітектурі MPTCP додано новий шар між стандартним сокетом додатку та традиційним стеком TCP/IP. Для прикладного програмного забезпечення (браузера, поштового клієнта) MPTCP працює абсолютно прозоро.

![Архітектура MPTCP](/reference/unix-linux/networking/multipath-tcp-mptcp/img/mptcp-arch.svg)
*Рис. 1. Архітектура MPTCP у мережевому стеку*

Кожен підпотік виглядає для маршрутизаторів та NAT-пристроїв як звичайне TCP-з'єднання. Це забезпечує зворотну сумісність (middlebox compatibility). Дані, що надсилаються додатком, розбиваються MPTCP-планувальником і розподіляються між доступними підпотоками, а на приймаючій стороні збираються у правильному порядку завдяки використанню MPTCP Data Sequence Signal (DSS).

## 3. Встановлення з'єднання: MP_CAPABLE та MP_JOIN

MPTCP використовує TCP-опції для обміну метаданими. Процес починається зі стандартного триетапного рукостискання (3-way handshake) з додаванням опції `MP_CAPABLE`.

### 3.1 Опція MP_CAPABLE

Під час першого SYN-пакета клієнт додає опцію `MP_CAPABLE`, що містить криптографічний ключ (Sender's Key). Якщо сервер підтримує MPTCP, він відповідає SYN/ACK пакетом, також включаючи `MP_CAPABLE` та свій ключ. Після цього базовий підпотік вважається MPTCP-з'єднанням. 

### 3.2 Опція MP_JOIN

Коли клієнт має додатковий мережевий інтерфейс (наприклад, перемикається з Wi-Fi на LTE), він ініціює новий підпотік до сервера, надсилаючи SYN-пакет з опцією `MP_JOIN`. Ця опція містить токен, згенерований з ключа сервера (для ідентифікації MPTCP-з'єднання), та випадкове число (nonce) для захисту від атак повторного відтворення.

## 4. Демон mptcpd та управління шляхами (Path Management)

У Linux управління підпотоками та мережевими інтерфейсами часто виконується в просторі користувача за допомогою демона `mptcpd`. 

Демон `mptcpd` відстежує стан мережевих інтерфейсів через події Netlink. Коли з'являється новий інтерфейс (наприклад, підключається кабель Ethernet або активується стільниковий зв'язок), `mptcpd` отримує про це сповіщення та може надіслати команду ядру Linux для створення нового підпотоку (`MP_JOIN`) або оголошення нової IP-адреси віддаленому вузлу за допомогою опції `ADD_ADDR`.

Команди для роботи з `mptcpd`:
```bash
# Перевірка статусу сервісу
systemctl status mptcpd

# Використання ip mptcp для конфігурації лімітів ядра
ip mptcp limits set add_addr_accepted 2 subflows 2
```

## 5. Агрегація Wi-Fi та LTE/5G у ядрі Linux

Одним із найпопулярніших застосувань MPTCP є агрегація пропускної здатності та забезпечення безшовного хендоверу (seamless handover) між Wi-Fi та стільниковими мережами (LTE/5G).

У ядрі Linux MPTCP інтегровано починаючи з версії 5.6. Планувальники ядра Linux (наприклад, `default`, `round-robin`, `redundant`) відповідають за розподіл пакетів:
- **Агрегація**: Пакети паралельно надсилаються через Wi-Fi та LTE, що сумарно збільшує швидкість передачі даних.
- **Хендовер (Failover)**: Основний трафік йде через Wi-Fi (як дешевший і часто швидший канал). При погіршенні сигналу Wi-Fi планувальник миттєво перекидає трафік на LTE/5G підпотік без розриву з'єднання на рівні додатка.

```bash
# Додавання інтерфейсу (наприклад, wlan0) як endpoint для MPTCP
ip mptcp endpoint add 192.168.1.100 dev wlan0 signal
ip mptcp endpoint add 10.0.0.5 dev wwan0 subflow
```

## 6. Висновок

Multipath TCP (RFC 8684) докорінно змінює спосіб роботи TCP, забезпечуючи високу відмовостійкість, мобільність та ефективне використання всіх доступних мережевих ресурсів. З нативною підтримкою в сучасних ядрах Linux та зручними інструментами на кшталт `mptcpd`, розгортання та керування MPTCP стає стандартною частиною сучасних мережевих рішень.
