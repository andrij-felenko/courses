# Довідка: Повідомлення протоколу 9P

Протокол 9P (особливо сучасний стандарт 9P2000) оперує відносно невеликим набором T (запит) та R (відповідь) повідомлень. Вони формують бінарний протокол, де кожне повідомлення починається з 4-байтового розміру, 1-байтового типу повідомлення та 2-байтового тегу (`tag`).

Ось основні пари повідомлень та їхнє призначення:

| Повідомлення | Опис дії |
| :--- | :--- |
| `Tversion` / `Rversion` | **Ініціалізація**. Домовляються про максимальний розмір повідомлення (msize) та версію протоколу (зазвичай "9P2000"). |
| `Tauth` / `Rauth` | **Автентифікація**. Запуск процесу перевірки повноважень. Клієнт пропонує спеціальний `afid` (auth fid), а сервер відповідає `aqid` — описом службового файлу, через читання/запис якого й відбувається обмін ключами. |
| `Tattach` / `Rattach` | **Монтування**. Клієнт приєднується до кореня файлової системи (або до певного дерева), передаючи `afid` (якщо автентифікація пройдена) та пропонуючи новий `fid` для кореня. |
| `Twalk` / `Rwalk` | **Навігація**. Клієнт переходить по шляху. Приймає масив рядків (назв директорій). Це дозволяє уникнути багатьох кругових звернень (round-trips) мережею для переходу в глибоку теку. |
| `Topen` / `Ropen` | **Відкриття**. Відкриває `fid` для читання, запису або виконання. Сервер перевіряє права доступу і повертає `qid` (з оновленою версією) і розмір блоку I/O. |
| `Tcreate` / `Rcreate` | **Створення**. Створює новий файл або директорію в директорії, яку представляє переданий `fid` — і саме тому цей `fid` перед запитом мусить бути ще не відкритим. Після успіху той самий `fid` уже вказує на новостворений файл і відкритий із заданим режимом. |
| `Tread` / `Rread` | **Читання**. Клієнт запитує `count` байтів з певного `offset` з відкритого `fid`. |
| `Twrite` / `Rwrite` | **Запис**. Клієнт передає дані для запису за певним `offset`. |
| `Tclunk` / `Rclunk` | **Закриття**. Клієнт відмовляється від `fid`. Файл закривається, сервер звільняє асоційовані ресурси. |
| `Tstat` / `Rstat` | **Метадані**. Запит інформації про файл (розмір, власник, права доступу, час модифікації — аналог `stat` у POSIX). |
| `Twstat` / `Rwstat` | **Зміна метаданих**. Дозволяє змінити власника, права або перейменувати файл (записати нову структуру `stat`). |

Усі операції з об'єктами (читання, запис, зміна власника) використовують абстракцію `fid`, тому сервер не потребує збереження складного стану імен файлів, а працює з прямими числовими посиланнями.
