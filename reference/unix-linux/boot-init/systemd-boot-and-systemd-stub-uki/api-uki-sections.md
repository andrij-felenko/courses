# 📋 Специфікація секцій PE/COFF образу UKI та конфігурації systemd-boot

Утиліти збірки образів завантаження (`ukify`, `systemd-ukify`, `dracut`, `mkinitcpio`) пакують ядро, початкову файлову систему initramfs та параметри командного рядка у стандартний формат виконуваного файла PE/COFF (Portable Executable / Common Object File Format), який приймає прошивка UEFI. Щоб розпізнати окремі елементи всередині бінарника, заглушка `systemd-stub` орієнтується на строго фіксовані назви та прапорці секцій PE-заголовка.

Ця вставка містить структурний довідник секцій Unified Kernel Image (UKI), детальний розбір їхніх атрибутів, механіку відкликання SBAT та параметри конфігураційних файлів завантажувача `systemd-boot`.

## Будова PE/COFF заголовка та специфікація секцій

Образ UKI є стандартним виконуваним файлом PE/COFF 64-бітної архітектури (x86_64, AArch64 або RISC-V). Перші байти файлу містять заголовок MS-DOS (`DOS_HEADER` із магічним числом `MZ` / `0x5A4D`), за яким за зміщенням `e_lfanew` розташовується заголовок PE (`IMAGE_NT_HEADERS64` із сигнатурою `PE\0\0` / `0x00004550`). За заголовком PE йде таблиця заголовків секцій (`IMAGE_SECTION_HEADER`), де кожна секція описує окремий блок даних.

Кожна секція в UKI має фіксоване ім'я довжиною до 8 символів ASCII, зміщення у файлі диска, віртуальний розмір в оперативній пам'яті та комбінацію прапорців доступу PE.

| Назва секції | Вміст та призначення | Обов'язковість | Прапорці PE |
| :--- | :--- | :--- | :--- |
| `.linux` | Двійковий образ ядра Linux (`vmlinuz` / `zImage`). Містить власну заглушку `EFISTUB`. | Обов'язкова | `READ \| DATA` (`0x40000040`) |
| `.initrd` | Склеєний архів CPIO з початковою файловою системою initramfs та мікрокодом CPU. | Рекомендована | `READ \| DATA` (`0x40000040`) |
| `.cmdline` | Рядок аргументів ядра ASCII/UTF-8 із завершальним нульовим байтом `\0`. | Рекомендована | `READ \| DATA` (`0x40000040`) |
| `.osrel` | Текстовий вміст `/etc/os-release` з вихідної системи (назва ОС, версія, ID). | Рекомендована | `READ \| DATA` (`0x40000040`) |
| `.uname` | Рядок версії ядра, що відповідає виводу команди `uname -r`. | Необов'язкова | `READ \| DATA` (`0x40000040`) |
| `.pcrpkey` | Публічний ключ RSA/ECDSA для перевірки підписів політики TPM2 PCR. | Необов'язкова | `READ \| DATA` (`0x40000040`) |
| `.pcrsig` | Криптографічний підпис політики завантаження TPM2 PCR. | Необов'язкова | `READ \| DATA` (`0x40000040`) |
| `.sbat` | Текст метаданих Secure Boot Advanced Targeting для глобального відкликання. | Обов'язкова для SB | `READ \| DATA` (`0x40000040`) |
| `.splash` | Графічний образ у форматі BMP (24-біт), що показується до запуску ядра. | Необов'язкова | `READ \| DATA` (`0x40000040`) |
| `.profile` | Профілі облікових даних та налаштувань для `systemd-measure` / `systemd-creds`. | Необов'язкова | `READ \| DATA` (`0x40000040`) |

### Детальний опис функціоналу кожної секції

#### 1. Секція .linux
Ця секція містить двійковий код ядра Linux. Вона являє собою компресований або некомпресований образ ядра (наприклад, `vmlinuz`), зібраний із підтримкою `CONFIG_EFI_STUB=y`. Заглушка `systemd-stub` після вимірювання секцій не розпаковує ядро самостійно, а передає вказівник на початок цієї секції в пам'яті до внутрішньої точки входу ядра `efi_pe_entry`.

#### 2. Секція .initrd
Секція містить один або кілька послідовно склеєних архівів формату CPIO. На початку секції зазвичай розміщують нестиснений CPIO-архів із мікрокодом процесора (Intel або AMD), після якого йде стиснутий (за допомогою `gzip`, `xz` або `zstd`) CPIO-архів самої початкової файлової системи initramfs. `systemd-stub` передає адресу цієї секції ядру через структуру `boot_params`, звільняючи завантажувач від необхідності зчитувати файл з диска.

#### 3. Секція .cmdline
Текстовий рядок кодування ASCII або UTF-8, який містить усі параметри завантаження ядра (наприклад, `root=UUID=... ro quiet splash`). Рядок мусить обов'язково завершуватися нульовим байтом `\0`. Оскільки ця секція є складовою частиною підписаного бінарника PE/COFF, зміна будь-якого параметра завантаження руйнує цифровий підпис бінарника.

#### 4. Секція .osrel
Скопійований текстовий вміст файла `/etc/os-release` тієї операційної системи, для якої зібрано UKI. Завантажувач `systemd-boot` зчитує цю секцію без запуску образу й витягує з неї змінні `PRETTY_NAME`, `VERSION_ID` та `LOGO` для формування опису пунктів меню у графічному інтерфейсі.

#### 5. Секції .pcrpkey та .pcrsig
Ці секції використовуються для реалізації механізму політик авторизації TPM2 (TPM2 Policy Authorization). Секція `.pcrpkey` містить відкритий ключ у форматі PEM або DER, яким підписано стан регістрів PCR. Секція `.pcrsig` містить цифровий підпис над очікуваними значеннями регістрів TPM2 PCR (зокрема PCR 11). Якщо підпис збігається, `systemd-stub` дозволяє завантаження навіть при оновленні версії ядра без переконфігурації TPM2.

#### 6. Секція .sbat
Секція містить метадані Secure Boot Advanced Targeting у текстовому форматі CSV. Вона слугує для вибіркового відкликання конкретних версій заглушок чи ядер без додавання великих хешів бінарників у базу `dbx` прошивки.

### Вимоги до вирівнювання секцій (FileAlignment та SectionAlignment)

Прошивка UEFI вимагає суворого дотримання двох параметрів вирівнювання, які описуються в опціональному PE-заголовку (`IMAGE_OPTIONAL_HEADER64`):

- **`FileAlignment`** (зазвичай `0x200` = 512 байтів): визначає, що зміщення та розмір кожної секції у файлі на диску мають бути кратними 512 байтам. Якщо фактичний розмір даних секції становить 130 байтів, у файлі під неї виділяється 512 байтів, а решта заповнюється нулями.
- **`SectionAlignment`** (зазвичай `0x1000` = 4096 байтів): визначає, що під час завантаження бінарника в оперативну пам'ять прошивкою UEFI або `systemd-stub`, кожна секція має розміщуватися на межі сторінки пам'яті розміром 4 КБ.

Для кожної секції встановлюються прапорці доступу `Characteristics`:
- `IMAGE_SCN_CNT_INITIALIZED_DATA` (`0x00000040`) — секція містить ініціалізовані дані.
- `IMAGE_SCN_MEM_READ` (`0x40000000`) — секція доступна для читання.

## Специфікація метаданих відкликання .sbat

Специфікація SBAT (Secure Boot Advanced Targeting) розроблена для вирішення проблеми масштабованості баз відкликання `dbx`. Раніше при виявленні вразливості у завантажувачі його SHA-256 хеш додавався до бази `dbx` прошивки. Оскільки розмір пам'яті NVRAM на материнських платах обмежений (кілька десятків кілобайтів), масове додавання хешів швидко призводило до переповнення пам'яті.

Секція `.sbat` містить CSV-рядок ASCII, де кожен компонент завантаження декларує своє ім'я та версію генерації:

```text
sbat,1,SBAT Version,sbat,1,https://github.com/rhboot/shim/wiki/SBAT
systemd-stub,1,systemd,systemd-stub,256,https://systemd.io
```

Поля запису регулюються специфікацією:
1. **Ідентифікатор компонента** (`systemd-stub`): унікальна назва продукту.
2. **Порядковий номер генерації SBAT** (`1`): ціле число, яке збільшується при виявленні вразливості.
3. **Назва вендора/проекту** (`systemd`): організація, що випустила бінарник.
4. **Назва пакета** (`systemd-stub`): конкретний модуль.
5. **Версія пакета** (`256`): текстова версія релізу.
6. **URL URL-адреса опису** (`https://systemd.io`).

Якщо у версії `systemd-stub` 252 виявлять ваду безпеки, у змінну NVRAM `SbatLevel` вноситься правило `systemd-stub,2`. Після цього прошивка UEFI та `shim` порівнюють номер генерації із секції `.sbat` бінарника й відмовляються запускати будь-який UKI, у якому генерація `systemd-stub` нижча за 2.

## Повний конфігураційний довідник systemd-boot

Завантажувач `systemd-boot` зчитує свої налаштування з розділу ESP. Головний конфігураційний файл розташований за шляхом `/loader/loader.conf` або `/EFI/BOOT/loader/loader.conf`.

### Параметри головного конфігураційного файла loader.conf

Нижче наведено повну таблицю ключів конфігурації `loader.conf` із описом їхньої дії та можливих значень:

```ini
# /loader/loader.conf — повна конфігурація systemd-boot

# Шаблон або назва запису за замовчуванням (* слугує маскою)
default fedora-6.10*

# Затримка показу графічного меню у секундах (0 — завантажити негайно, -1 — чекати нескінченно)
timeout 3

# Режим відеоконсолі прошивки
# 0 — 80x25, 1 — 80x50, 2 — auto, max — максимальна роздільність, keep — зберегти поточну
console-mode max

# Дозволити редагування командного рядка в меню клавішею 'e' (yes / no)
editor no

# Автоматичне автозарахування ключів Secure Boot (off / manual / if-safe / force)
secure-boot-enroll if-safe

# Зберегти стан BitLocker при перезавантаженні у Windows (yes / no)
reboot-for-bitlocker yes

# Генерація випадкового зерна для ядра (full / pdam / off)
random-seed-mode full

# Автоматичне виявлення додаткових систем (yes / no)
auto-entries yes

# Показувати пункт перезавантаження у налаштування прошивки UEFI (yes / no)
auto-firmware yes
```

### Формат традиційних записів Type #1 (/loader/entries/*.conf)

Для систем без використання UKI завантажувач читає описи ядер із окремих конфігураційних файлів у директорії `/loader/entries/`:

```ini
# /loader/entries/2024-08-14_fedora.conf
title      Fedora Workstation 40
version    6.10.3-200.fc40.x86_64
machine-id a1b2c3d4e5f64a5b8c9d0123456789ab
sort-key   fedora
linux      /vmlinuz-6.10.3-200.fc40.x86_64
initrd     /initramfs-6.10.3-200.fc40.x86_64.img
options    root=UUID=8f3c1a2b-3c4d-5e6f-7a8b-9c0d1e2f3a4b ro quiet splash
```

Ключі файла Type #1:
- **`title`**: текстова назва пункту меню, яка відображається користувачеві.
- **`version`**: версія ядра для сортування списку завантаження.
- **`machine-id`**: ідентифікатор машини з `/etc/machine-id` для прив'язки запису до конкретної інсталяції.
- **`sort-key`**: ключ для групування записів одного дистрибутива.
- **`linux`**: шлях до бінарника ядра відносно кореня ESP.
- **`initrd`**: шлях до архіву initramfs відносно кореня ESP.
- **`options`**: рядок параметрів командного рядка ядра.

### Формат записів Type #2 (Автовиявлення UKI у /EFI/Linux/*.efi)

При використанні специфікації UKI створити файли в `/loader/entries/` **не потрібно**. `systemd-boot` під час старту сканує директорію `/EFI/Linux/` на розділах ESP та XBOOTLDR. Для кожного знайденого файла `.efi` завантажувач розбирає секцію `.osrel` і формує динамічний пункт меню.

Назва дистрибутива береться зі значення `PRETTY_NAME`, версія з `VERSION_ID`, а іконка визначається ключем `LOGO`. Це виключає розсинхронізацію між вмістом образу та конфігурацією завантажувача.
