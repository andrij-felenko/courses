# ⚙️ Єдиний образ ядра власноруч: чотири файли в один PE

Єдиний образ ядра (UKI, unified kernel image) виглядає як фокус інструмента `ukify`: одна команда — і замість ядра, initramfs та рядка в конфігурації є один підписаний файл `.efi`. Фокусу там немає. Це звичайний виконуваний файл UEFI, у який дописали кілька шматків із готовим вмістом і кожному дали ім'я та адресу. Складемо його руками через `objcopy`, щоб побачити ці адреси, а потім повторимо те саме через `ukify` — і стане видно, що інструмент лише рахує ті самі числа замість нас.

## Задача

Взяти чотири файли: заглушку `linuxx64.efi.stub` із пакунка systemd, образ ядра `vmlinuz`, архів [initramfs](book:unix-linux/initramfs) — тимчасовий корінь, який працює доти, доки не змонтовано справжній, — і текстовий файл із командним рядком. Скласти з них один `.efi`, підписати ключем Secure Boot, покласти в EFI-розділ і переконатися, що машина завантажилася саме з нього.

Далі перевірити на живій машині головну обіцянку такого образу: при ввімкненому Secure Boot рядок, зашитий усередину, переважає над усім, що спробують передати ззовні.

## Задум: секція — це шматок файлу з іменем і адресою

Виконуваний файл UEFI має формат PE. Влаштований він так само, як [ELF](book:unix-linux/elf-structure) у світі Linux: суцільний файл поділено на іменовані секції, а на початку лежить таблиця, де для кожної секції записано ім'я, довжину, зсув у файлі й адресу, за якою її треба покласти в пам'ять при запуску. Завантажувач образів у прошивці читає цю таблицю, розкладає секції по вказаних адресах і стрибає в точку входу.

Звідси й уся конструкція. Заглушка — це маленька програма, точка входу якої одна-єдина: знайти у **власному** образі секції з наперед відомими іменами й повестися з ними як з ядром, архівом і рядком. Ніяких файлів вона не шукає й файлових систем не читає. Отже, «зібрати UKI» означає буквально: дописати до заглушки чотири секції з потрібними іменами.

Імена цих секцій задокументовані: `.linux` — образ ядра (єдина обов'язкова), `.initrd` — архів, `.cmdline` — командний рядок, `.osrel` — вміст файлу `os-release`. Остання не декоративна: `systemd-boot` читає її, щоб дати запису назву в меню й упорядкувати кілька образів між собою.

У `.linux` при цьому кладуть не абищо. Заглушка не розпаковує ядро сама — вона передає йому керування тим самим шляхом, яким це зробила б прошивка, тобто образ усередині мусить бути ядром із власною EFI-заглушкою, зібраним із `CONFIG_EFI_STUB`. Ядра дистрибутивів такі завжди; своє, зібране з [власної конфігурації](book:unix-linux/kernel-config-and-build), варто перевірити наперед, бо інакше все складеться без помилок і не завантажиться без пояснень.

Робити треба одне: сказати `objcopy`, за якою адресою покласти кожну секцію. Інструмент їх не розкладає сам, бо не знає, які адреси в цьому образі вільні.

![Чотири файли з диска зліва і той самий вміст секціями одного PE-файлу справа, за зростанням адрес](/reference/unix-linux/boot-init/bootloader-and-cmdline/img/uki-layout.svg)

*Секції йдуть за зростанням адрес, проміжки між ними — вирівнювання, а підпис накриває весь файл цілком.*

Адреси беруться з двох чисел, і обидва лежать у заголовку самої заглушки. Перше — `SectionAlignment`, крок, з якого може починатися секція. Друге — кінець останньої секції заглушки: усе, що нижче, вже зайняте її власним кодом. Далі кожну нову секцію кладемо в наступний вільний вирівняний блок.

**Порахуймо всі чотири адреси для конкретної заглушки.** Крок вирівнювання — 0x1000, остання секція заглушки закінчується на 0x1f2a0:

```
.osrel     0x1f2a0 ↑ до межі 0x1000        → 0x20000,  розмір 0x182 (386 Б)
           кінець:  0x20000 + 0x182        = 0x20182
.cmdline   0x20182 ↑ до межі               → 0x21000,  розмір 0x2f (47 Б)
           кінець:  0x21000 + 0x2f         = 0x2102f
.linux     0x2102f ↑ до межі               → 0x22000,  розмір 0xc80000 (12.5 МіБ)
           кінець:  0x22000 + 0xc80000     = 0xca2000
.initrd    0xca2000 вже на межі            → 0xca2000
```

Округлення коштує менш ніж 4 КіБ на кожній секції — стільки платимо за те, що жодна з них не починається посеред чужої сторінки.

## Складання руками

```sh
#!/bin/sh
# uki.sh — зібрати єдиний образ ядра з чотирьох файлів.
set -eu

STUB=/usr/lib/systemd/boot/efi/linuxx64.efi.stub
LINUX=/boot/vmlinuz-linux
INITRD=/boot/initramfs-linux.img
OSREL=/usr/lib/os-release
OUT=uki.efi

# Рядок пишемо printf, а не echo: echo додасть у кінці перевід рядка,
# і той байт стане частиною командного рядка.
printf '%s' 'root=UUID=6f1c8b2a-… ro quiet' > cmdline

# 1. Крок вирівнювання з заголовка PE (objdump друкує його шістнадцятковим).
align=$(objdump -p "$STUB" | awk '$1 == "SectionAlignment" { print $2 }')
align=$((0x$align))

# 2. Кінець останньої секції заглушки: перше, що вже точно вільне.
#    Рядки секцій у «objdump -h» починаються з номера: Idx Name Size VMA …
set -- $(objdump -h "$STUB" |
         awk '$1 ~ /^[0-9]+$/ { size = $3; vma = $4 } END { print size, vma }')
next=$((0x$1 + 0x$2))

# 3. Розкладка. Функція мусить МІНЯТИ next, тому вона не друкує адресу,
#    а присвоює її змінній: виклик через $(…) пішов би в підоболонку
#    і посунутий next загубився б разом з нею.
place() {                       # place <ім'я-змінної> <файл>
  next=$(( (next + align - 1) / align * align ))
  eval "$1=\$next"
  next=$(( next + $(stat -Lc%s "$2") ))
}

place osrel_at   "$OSREL"
place cmdline_at cmdline
place linux_at   "$LINUX"
place initrd_at  "$INITRD"

# 4. Власне склеювання. Порядок аргументів = порядок записів у таблиці
#    секцій, тому подаємо їх у тому ж порядку, у якому зростають адреси.
objcopy \
  --add-section .osrel="$OSREL"   --change-section-vma .osrel=$osrel_at     \
  --add-section .cmdline=cmdline  --change-section-vma .cmdline=$cmdline_at \
  --add-section .linux="$LINUX"   --change-section-vma .linux=$linux_at     \
  --add-section .initrd="$INITRD" --change-section-vma .initrd=$initrd_at   \
  "$STUB" "$OUT"

printf 'osrel %#x  cmdline %#x  linux %#x  initrd %#x\n' \
       "$osrel_at" "$cmdline_at" "$linux_at" "$initrd_at"
```

Результат перевіряють тими самими інструментами, якими складали. `objdump -h uki.efi` показує таблицю секцій — там мусять бути всі чотири, і колонка адрес мусить зростати згори вниз без перекриттів. А вміст `.cmdline` дістають назад:

```sh
objcopy -O binary --only-section=.cmdline uki.efi /dev/stdout | cat -A
# root=UUID=6f1c8b2a-… ro quiet          ← правильно
# root=UUID=6f1c8b2a-… ro quiet$         ← «$» наприкінці: сюди заліз echo
```

## Те саме одним рядком

```sh
ukify build                                                \
  --stub=/usr/lib/systemd/boot/efi/linuxx64.efi.stub       \
  --linux=/boot/vmlinuz-linux                              \
  --initrd=/boot/initramfs-linux.img                       \
  --cmdline='root=UUID=6f1c8b2a-… ro quiet'                \
  --os-release=@/usr/lib/os-release                        \
  --uname="$(uname -r)"                                    \
  --output=uki.efi
```

Це той самий файл. `ukify` рахує ті самі адреси, кладе ті самі секції — і додає ще кілька, яких скрипт вище не робить: `.uname` з версією ядра та `.sbat` із метаданими відкликання, за якими зіпсований образ можна заборонити централізовано, не міняючи ключів. Порівняти обидва результати можна тим самим `objdump -h`.

## Підпис і встановлення

Підпис накриває файл цілком, тож підмінити окремо ядро, архів чи рядок після підписання неможливо:

```sh
sbsign --key db.key --cert db.crt --output uki-signed.efi uki.efi
sbverify --list uki-signed.efi
install -Dm0644 uki-signed.efi /efi/EFI/Linux/arch-linux.efi
```

Ключ `db.key` тут — той, що вже внесено в базу дозволених у прошивці; як [перевірка підпису](book:programming/firmware-secure-boot) вибудовує ланцюг довіри від незмінного кореня, описано окремо. Каталог `EFI/Linux` на EFI-розділі — умовлене місце: `systemd-boot` сам обходить його й робить запис меню з кожного знайденого `.efi`. Без завантажувача образ теж працює — тоді запис створюють у самій прошивці через `efibootmgr`, і [ланцюг завантаження](book:unix-linux/boot-chain) стає на одну ланку коротшим.

Після перезавантаження перевіряють `/proc/cmdline` — [файл, у якому ядро назавжди тримає копію отриманого рядка](book:unix-linux/proc-filesystem). Якщо там саме те, що клали в секцію, збірка вдалася. Який із записів меню при цьому спрацював, покаже `bootctl status`: він читає змінні, які завантажувач лишає в прошивці по собі, тож переплутати новий образ зі старим не вийде.

## Пастки

**Адреси зростають і не перекриваються.** Це єдина умова, яку `objcopy` не перевіряє: він слухняно запише те, що йому сказали. Якщо секції накладуться, образ або не запуститься взагалі, або запуститься з понівеченим вмістом: заглушка знайде на місці ядра хвіст архіву. Пояснення в жодному разі не буде — прошивка не звітує, чому їй не сподобався файл. Порядок імен теж не довільний: специфікація UKI фіксує канонічну послідовність секцій, щоб виміри в TPM для однакових образів збігалися.

**Зайвий байт у кінці рядка.** Секцію `.cmdline` заглушка читає **за довжиною**, а не до нульового байта, тому все, що є у файлі, потрапляє в командний рядок — включно з переводом рядка від `echo`. Сучасна заглушка systemd проганяє вміст через `mangle_stub_cmdline`, який замінює керівні символи пробілами й зрізає хвостові, але покладатися на це не варто: той самий файл читають й інші інструменти.

**Мікрокод, який загубився при переїзді.** У класичній схемі оновлення мікрокоду процесора підкладає завантажувач: він передає ядру два архіви поспіль, і першим — той, що з мікрокодом, бо застосувати його треба до всього іншого. У єдиному образі завантажувача в цьому ланцюжку немає, тому для мікрокоду є окрема секція `.ucode`, вміст якої заглушка подає ядру попереду `.initrd`. Хто складає образ руками й про неї не знає, тихо втрачає оновлення мікрокоду: система працює, у журналі просто немає рядка про застосовану ревізію.

**Рядок, довший за `COMMAND_LINE_SIZE`.** Ядро мовчки обрізає задовгий рядок по своїй стелі — 2048 байтів на x86-64. У звичайній системі це прикро, у UKI боляче: хвіст рядка ви не побачите ані в конфігурації, ані в меню, бо конфігурації немає, а меню показує лише назву запису. Помітно це буде тільки в `/proc/cmdline`.

**Немає запасного запису.** Рядок під підписом виправити на місці неможливо: у меню його не редагують, а перескладання й перепідпис вимагають працездатної системи. Образ із неправильним `root=` перетворює машину на цеглину, яку рятують лише з іншого носія. Тому в `EFI/Linux` тримають щонайменше два образи — робочий і попередній, — а до `.cmdline` ставляться як до частини образу, а не як до налаштування.

**Аварійний люк існує, але він точний.** У документації заглушки сказано прямо: якщо UEFI Secure Boot увімкнено і секція `.cmdline` в образі є, будь-які спроби перевизначити командний рядок параметрами запуску EFI-програми ігноруються; щоб перевизначення працювало, треба або вимкнути Secure Boot, або не класти секцію `.cmdline` в образ. Перевіряється це за півхвилини: натиснути `e` в меню `systemd-boot`, дописати слово й подивитися `/proc/cmdline` після старту. З увімкненим Secure Boot там буде вбудований рядок, з вимкненим — переданий.

І от у цьому «переданий» ховається остання пастка. Переданий рядок не додається до вбудованого, а **заміняє** його цілком: заглушка бере щось одне. Той, хто з вимкненим Secure Boot дописав у меню саме `debug`, отримає командний рядок, у якому є `debug` — і більше нічого, зокрема немає `root=`. Дописувати параметри, не перескладаючи образ, є чим: заглушка вміє підхоплювати окремі підписані додатки, вміст `.cmdline` яких саме дописується до основного рядка й вимірюється в TPM. Але це вже інші файли й інші підписи, а не редагування рядка в меню.
