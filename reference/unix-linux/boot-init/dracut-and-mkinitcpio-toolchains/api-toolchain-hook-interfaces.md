# 📋 Інтерфейси хуків та конфігурації генераторів

Технічна довідка містить структурований опис точок розширення, функцій API, змінних середовища, конфігураційних директив та параметрів командного рядка для трьох провідних інструментаріїв формування initramfs: `dracut`, `mkinitcpio` та `initramfs-tools`.

Розділ слугує швидким орієнтиром при порівняльному аналізі, портуванні хуків або налагодженні раннього простору користувача.

---

## 1. Специфікація API dracut

Взаємодія з dracut на етапі генерації здійснюється через файли `module-setup.sh` в `/usr/lib/dracut/modules.d/NNname/`, а на етапі завантаження — через точки розширення initqueue та служби systemd.

### 1.1 Функції `module-setup.sh` (Фаза генерації)

| Функція | Обов'язкова | Опис та призначення |
| :--- | :--- | :--- |
| `check()` | Ні | Перевіряє доцільність включення модуля у підготовлюваний образ. Повертає `0` (включити), `1` (пропустити) або `255` (критична помилка). |
| `depends()` | Ні | Виводить імена модулів dracut, від яких залежить даний модуль. |
| `cmdline()` | Ні | Виводить додаткові аргументи командного рядка ядра, які необхідно вшити за замовчуванням у `.cmdline`. |
| `install()` | Так | Визначає, які саме файли, бінарники, udev-правила та скрипти копіювати у cpio-архів. |
| `installkernel()` | Ні | Визначає список модулів ядра (`.ko`), які необхідно додати в образ. |

### 1.2 Допоміжні функції інсталяції `dracut-functions.sh`

- `inst_multiple [-o] <prog1> [<prog2> ...]` — додає в образ вказані бінарні файли, автоматично аналізуючи залежності `.so` через `ldd`. Прапорець `-o` ігнорує відсутні файли.
- `inst_hook <initqueue_hook> <prio> <script>` — реєструє shell-скрипт у вказаній фазі завантаження з заданим числовим пріоритетом `prio` (наприклад, `50`).
- `inst_rules <rule1.rules> ...` — копіює та реєструє udev-правила з `/lib/udev/rules.d/` та `/etc/udev/rules.d/`.
- `inst_simple <src> [<dst>]` — копіює один файл у cpio-архів без перевірки динамічних бібліотек.
- `inst_symlink <src> [<dst>]` — створює символьне посилання всередині cpio-архіву.
- `inst_binary <src> [<dst>]` — копіює виконуваний файл разом із двійковими залежностями.
- `dracut_need_initqueue` — сповіщає dracut про те, що модуль вимагає продовження роботи черги `initqueue` для очікування пристроїв.

### 1.3 Точки розширення initqueue (Фаза завантаження)

Виконуються інтерпретатором dracut у вказаному порядку:

1. `cmdline` — зчитування та розбір параметрів ядра `/proc/cmdline`.
2. `pre-udev` — перед запуском демона `systemd-udevd`.
3. `pre-trigger` — після запуску udev, але перед викликом `udevadm trigger`.
4. `initqueue` / `initqueue/online` — асинхронне виконання задач під час приходу нових udev-подій.
5. `initqueue/settled` — виконання після того, як черга udev-подій стабілізувалася (немає нових пристроїв).
6. `initqueue/timeout` — тайм-аут очікування пристроїв (наприклад, для виводу повідомлення про відсутній root-диск).
7. `pre-mount` — після створення всіх блокових пристроїв, безпосередньо перед монтуванням кореня.
8. `mount` — виконання операції монтування кореневої ФС у `/sysroot`.
9. `pre-pivot` — після монтування `/sysroot`, безпосередньо перед очищенням пам'яті та викликом `switch_root`.
10. `cleanup` — замикаюча очистка тимчасових файлових описувачів.

### 1.4 Змінні середовища dracut під час завантаження

- `$BOOTDIR` — директорія завантаження (зазвичай `/sysroot`).
- `$NEWROOT` — директорія нового кореня (синонім `/sysroot`).
- `$initdir` — тимчасова директорія збирання образу під час виконання `dracut`.
- `$moddir` — шлях до директорії поточного модуля dracut під час збирання.

### 1.5 Ключові прапорці CLI `dracut`

- `-f`, `--force` — перезаписати наявний файл образу initramfs.
- `-N`, `--no-hostonly` — згенерувати універсальний (*generic*) образ із підтримкою широкого спектра заліза.
- `-H`, `--hostonly` — згенерувати мінімальний образ лише для поточного апаратного забезпечення.
- `-m`, `--modules "<mod1> <mod2>"` — примусово включити перелічені модулі dracut.
- `-o`, `--omit-modules "<mod1> <mod2>"` — виключити вказані модулі dracut.
- `--add-drivers "<drv1> <drv2>"` — додає вказані драйвери ядра.
- `--omit-drivers "<drv1> <drv2>"` — виключає вказані драйвери ядра.
- `--uefi` — зібрати єдиний виконний файл UKI (Unified Kernel Image) у форматі PE/COFF.

## 2. Специфікація API mkinitcpio

У mkinitcpio розрізняють API інсталяційного файлу `/usr/lib/initcpio/install/name` та рантайм-файлу `/usr/lib/initcpio/hooks/name`.

### 2.1 Функції інсталяційного файлу (Фаза генерації)

Надаються фреймворком `mkinitcpio` у контексті функції `build()`:

| Функція API | Опис та аргументи |
| :--- | :--- |
| `add_binary <binary> [target]` | Додає виконуваний бінарний файл із розпізнаванням та копіюванням залежних `.so` бібліотек. |
| `add_module <module_name>` | Додає модуль ядра за іменем, автоматично затягуючи залежні модулі з `modules.dep`. |
| `add_file <src> [target] [mode]` | Копіює файл за вказаним шляхом з збереженням або зміною прав доступу `mode`. |
| `add_runscript [target]` | Копіює однойменний рантайм-скрипт з `/usr/lib/initcpio/hooks/` у cpio-архів. |
| `add_dir <path>` | Створює порожню директорію всередині образу. |
| `add_symlink <path> <target>` | Створює символьне посилання. |
| `add_full_dir <path>` | Рекурсивно копіює весь вміст директорії у cpio-архів. |
| `add_checked_modules <pattern>` | Додає модулі ядра лише у разі, якщо вони відповідають поточному залізу (використовується в `autodetect`). |

### 2.2 Функції рантайм-файлу (Фаза завантаження)

Виконуються всередині initramfs згідно з порядком у списку `HOOKS`:

- `run_earlyhook()` — виконується дуже рано, до ініціалізації пристроїв udev (наприклад, для налаштування консолі або раннього розпакування).
- `run_hook()` — основна точка виклику, виконується після запуску `udevd` та сканування шини пристроїв.
- `run_latehook()` — виконується після підготовки блокових пристроїв, безпосередньо перед монтуванням кореня.
- `run_cleanuphook()` — виконується останнім перед викликом `switch_root` для закриття тимчасових файлових описувачів чи зупинки фонових процесів.

### 2.3 Змінні конфігурації `/etc/mkinitcpio.conf`

- `MODULES=(...)` — масив модулів ядра, які копіюються в образ беззастережно.
- `BINARIES=(...)` — масив додаткових виконувальних файлів.
- `FILES=(...)` — масив додаткових конфігураційних файлів (наприклад, `/etc/vconsole.conf`).
- `HOOKS=(...)` — впорядкований масив хуків (наприклад, `base udev autodetect modconf block encrypt lvm2 filesystems fsck`).
- `COMPRESSION="zstd"` — алгоритм стиснення cpio-архіву (`zstd`, `gzip`, `bzip2`, `lz4`, `lzma`, `lzo`, `xz`).
- `COMPRESSION_OPTIONS=(...)` — додаткові прапорці для компресора (наприклад, `(-19 --long)`).

### 2.4 Ключові прапорці CLI `mkinitcpio`

- `-g <path>`, `--generate <path>` — вказати вихідний шлях для файла initramfs.
- `-k <kernel_ver>`, `--kernel <kernel_ver>` — зібрати образ для конкретної версії ядра.
- `-c <config>`, `--config <config>` — використати альтернативний файл конфігурації.
- `-p <preset>`, `--preset <preset>` — зібрати образ за пресетом (наприклад, `linux` або `linux-lts`).
- `-P`, `--allpresets` — перебудувати образи для всіх установлених пресетів ядер.
- `-M`, `--analyze` — відобразити список модулів, виявлених на хост-системі.
- `-U <path>`, `--build-uki <path>` — згенерувати Unified Kernel Image.

## 3. Специфікація API initramfs-tools

initramfs-tools спирається на директорії-фази для збирання та виконання shell-скриптів.

### 3.1 Функції фази збирання (`/usr/share/initramfs-tools/hooks/`)

Виклики здійснюються у shell-скриптах збирання:

| Функція | Опис та аргументи |
| :--- | :--- |
| `copy_exec <src> [<dst>]` | Копіює бінарний файл та автоматично трасує всі його динамічні бібліотеки `.so`. |
| `manual_add_modules <mod>` | Додає модуль ядра та всі пов'язані залежні модулі з `modules.dep`. |
| `add_loaded_modules` | Сканує `/proc/modules` та додає всі наразі завантажені у пам'яті модулі ядра. |

### 3.2 Фази скриптів рантайму (`/scripts/`)

Скрипти сортуються за алфавітом у відповідних директоріях:

- `/scripts/init-top` — підготовка середовища, виклики `devtmpfs`, запуск `udevd`.
- `/scripts/init-premount` — перед розпізнаванням блокового пристрою кореня.
- `/scripts/local-top` — розпакування крипто-контейнерів (`cryptroot`), збирання LVM томах та масивів RAID.
- `/scripts/local-block` — очікування готовності конкретного блокового пристрою.
- `/scripts/local-premount` — перед викликом `fsck` на змонтованому блоковому пристрої.
- `/scripts/local-bottom` — після успішного монтування кореневої ФС у `/root`.
- `/scripts/init-bottom` — перед перенесенням службових монтувань та викликом `run-init` (`switch_root`).

### 3.3 Змінні конфігурації `/etc/initramfs-tools/initramfs.conf`

- `BOOT=local` — тип завантаження (`local` для локальних дисків, `nfs` для завантаження з мережі).
- `MODULES=most` — режим відбору модулів:
  - `most` — копіювати більшість стандартних накопичувальних та мережевих драйверів.
  - `dep` — копіювати лише модулі, необхідні для монтування поточного кореня.
  - `list` — копіювати лише модулі, явно перелічені в `/etc/initramfs-tools/modules`.
- `COMPRESS=zstd` — алгоритм стиснення (`zstd`, `gzip`, `xz`, `lz4`).

## 4. Зведена таблиця CLI параметрів ядра (`cmdline`)

Кожен генератор розбирає параметри командного рядка ядра у ранньому просторі користувача за власною схемою.

| Призначення | dracut | mkinitcpio (busybox / systemd) | initramfs-tools |
| :--- | :--- | :--- | :--- |
| **Кореневий пристрій** | `root=UUID=...` або `root=LABEL=...` | `root=UUID=...` | `root=UUID=...` |
| **Том LUKS** | `rd.luks.uuid=LUKS-XXXX` | `cryptdevice=UUID=XXXX:root` / `rd.luks.uuid=...` | `target=root,source=UUID=...` (в `crypttab`) |
| **Том LVM** | `rd.lvm.vg=VolGroup00` | `rd.lvm.vg=VolGroup00` | Автоматичне виявлення `vgchange -ay` |
| **Аварійна оболонка** | `rd.break=pre-mount` | `break=premount` | `break=premount` / `break=bottom` |
| **Режим відладки** | `rd.shell rd.debug` | `debug` | `debug` |
| **Мережева адреса** | `ip=dhcp` або `ip=192.168.1.10::...` | `ip=dhcp` | `IP=dhcp` |
