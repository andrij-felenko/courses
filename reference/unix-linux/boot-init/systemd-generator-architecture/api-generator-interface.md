# 📋 Інтерфейс та специфікація контракту генераторів systemd

Цей довідник містить технічну специфікацію ABI та CLI контракту системних і користувацьких генераторів systemd, каталогів розташування бінарних файлів, внутрішнього порядку перекриття виводу, системних змінних середовища та спеціалізованого C/C++ бібліотечного API з вихідного коду системного менеджера.

## Контракт аргументів командного рядка

Системний менеджер PID 1 під час запуску кожного виконуваного генератора передає **рівно три позиційні аргументи** командного рядка (`argv[1]`, `argv[2]`, `argv[3]`). Ці аргументи містять абсолютні шляхи до тимчасових каталогів оперативної пам'яті (`tmpfs`), у які генератор повинен зберігати згенеровані юніт-файли та символьні посилання залежностей:

| Аргумент | Внутрішня змінна | Шлях у системі за замовчуванням | Назначення та порядок пріоритету завантаження |
|---|---|---|---|
| `$1` | `normal_dir` | `/run/systemd/generator` | Каталог стандартного виводу. Юніти з цього каталогу мають пріоритет вищий за пакетні дистрибутивні файли `/lib/systemd/system`, але нижчий за конфігурації адміністратора `/etc/systemd/system`. |
| `$2` | `early_dir` | `/run/systemd/generator.early` | Каталог найвищого пріоритету. Файли у цьому каталозі перекривають навіть статичні юніти у `/etc/systemd/system` та `/lib/systemd/system`. |
| `$3` | `late_dir` | `/run/systemd/generator.late` | Фолбек-каталог найнижчого пріоритету. Застосовується системним менеджером лише тоді, коли юніт з відповідним ім'ям відсутній у всіх інших каталогах системи. |

Кожен генератор під час виконання повинен коректно обробляти передачу цих аргументів. Якщо програма запускається вручну для відлагодження, їй можна передати шляхи до трьох тимчасових каталогів у `/tmp` (наприклад, `/tmp/dir1 /tmp/dir2 /tmp/dir3`), що дозволяє тестувати генератор у безпечному ізольованому середовищі користувача.

## Каталоги розташування виконуваних генераторів

Системний менеджер сканує декілька стандартних каталогів для пошуку виконуваних бінарників та сценаріїв генераторів. Сканування відбувається в порядку спадання пріоритету. Якщо бінарний файл з однаковим ім'ям (наприклад, `systemd-fstab-generator`) існує у декількох каталогах, системний менеджер виконує виключно версію з каталогу з найвищим пріоритетом.

### Системний режим (`systemd --system` / PID 1)

1. `/run/systemd/system-generators/` — Динамічно згенеровані генератори під час роботи системи. Сюди можна поміщати генератори рантайму.
2. `/etc/systemd/system-generators/` — Каталог кастомних генераторів системного адміністратора. Має найвищий пріоритет серед постійних каталогів файлової системи.
3. `/usr/local/lib/systemd/system-generators/` — Каталог генераторів стороннього або локально скомпільованого програмного забезпечення.
4. `/lib/systemd/system-generators/` або `/usr/lib/systemd/system-generators/` — Системний каталог генераторів з пакетів дистрибутива (зокрема `systemd-fstab-generator`, `systemd-gpt-auto-generator`, `systemd-cryptsetup-generator`).

### Користувацький режим (`systemd --user`)

Для екземплярів системного менеджера користувача (`systemd --user`) генератори шукаються у відокремленому дереві каталогів:

1. `/run/systemd/user-generators/` — Рантайм-генератори сесії користувача.
2. `~/.config/systemd/user-generators/` (або `$XDG_CONFIG_HOME/systemd/user-generators/`) — Особисті генератори користувача.
3. `/etc/systemd/user-generators/` — Системні генератори сесій користувачів, налаштовані адміністратором.
4. `/usr/local/lib/systemd/user-generators/` — Локальні пакетні генератори користувача.
5. `/usr/lib/systemd/user-generators/` — Дистрибутивні генератори користувацьких юнітів.

## Правила маскування та фільтрації генераторів

Системний менеджер застосовує суворі правила фільтрації файлів у каталогах генераторів:

- **Маскування через `/dev/null`**: Якщо у каталозі з вищим пріоритетом (наприклад, у `/etc/systemd/system-generators/systemd-fstab-generator`) створити символьне посилання на `/dev/null`, системний менеджер повністю скасовує виконання генератора `systemd-fstab-generator` з каталогу `/lib/systemd/system-generators/`. Це дозволяє адміністратору легко вимикати будь-які вбудовані генератори.
- **Права доступу та розширення файлів**: Системний менеджер виконує лише ті файли, які мають встановлений прапорець виконання (`0755` або `+x`). Файли, що закінчуються на символи `~`, `.bak`, `.dpkg-new`, `.dpkg-dist`, `.rpmnew` або `.rpmsave`, повністю ігноруються під час сканування.

## Змінні середовища, що передаються системним менеджером

Під час запуску кожного генератора системний менеджер встановлює набір спеціальних змінних оточення, які дозволяють генератору визначити точний контекст свого виконання:

| Змінна оточення | Допустимі значення | Повна функціональна роль у генераторі |
|---|---|---|
| `SYSTEMD_IN_INITRD` | `1`, `0` | Приймає значення `1`, якщо генератор виконується у середовищі початкового RAM-диска (initramfs). Дозволяє розділити логіку монтування раннього кореня від моунтів основної операційної системи. |
| `SYSTEMD_SCOPE` | `system`, `user` | Вказує режим роботи системного менеджера. Для глобального PID 1 значення дорівнює `system`, для користувацької сесії — `user`. |
| `SYSTEMD_LOG_LEVEL` | `debug`, `info`, `warn`, `err` | Визначає поточний рівень деталізації логування системного менеджера. Генератор повинен зчитувати цю змінну для включення відлагоджувального виводу. |
| `SYSTEMD_LOG_TARGET` | `console`, `kmsg`, `journal` | Вказує цільовий потік виводу системного логу (консоль терміналу, кільцевий буфер ядра `/dev/kmsg` або демон `systemd-journald`). |

## Правила безпеки та обмеження виконання

При розробці генераторів необхідно суворо дотримуватися наступних технічних обмежень:

1. **Заборона використання D-Bus IPC**: Під час роботи фази генераторів шина D-Bus та сокет системного менеджера ще не готові до обробки запитів. Будь-які виклики `systemctl`, `busctl` або спроби встановити IPC-з'єднання з PID 1 з усередині генератора спричиняють нескінченний розрив або вічне зависання (deadlock) всієї системи.
2. **Заборона модифікації персистентних каталогів**: Генератор має право створювати файли виключно у наданих каталогах `$1`, `$2`, `$3`. Прямий запис у постійну файлову систему (наприклад, у `/etc` чи `/var`) суворо заборонений.
3. **Обмеження часу виконання**: Виконання генераторів є синхронним процесним бар'єром. Зависання генератора або проведення тривалих мережевих чи обчислювальних операцій безпосередньо затримує завантаження операційної системи.
4. **Ідемпотентність та очищення**: Системний менеджер повністю видаляє вміст каталогів `/run/systemd/generator*` під час виконання `systemctl daemon-reload`. Генератор повинен бути розрахований на багаторазові повторні запуски без накопичення проміжного стану.

## Використання внутрішнього бібліотечного API `sd-generator.h`

У складі вихідного коду systemd розробники використовують спеціалізований внутрішній модуль `src/shared/generator-common.h` / `sd-generator.h`. Цей API спрощує створення юнітів та маніпуляцію символьними посиланнями:

:::tabs
```c
/* Приклад використання внутрішніх C-функцій systemd generator API */
#include "generator.h"

int main(int argc, char *argv[]) {
    const char *normal_dir, *early_dir, *late_dir;
    int r;

    /* Автоматична перевірка argc та витяг каталогів */
    r = generator_open_output_dirs(argc, argv, &normal_dir, &early_dir, &late_dir);
    if (r < 0)
        return EXIT_FAILURE;

    /* Створення unit-файла у normal_dir з автоматичним закриттям файлу */
    _cleanup_fclose_ FILE *f = NULL;
    r = generator_open_unit_file(normal_dir, NULL, "my-gen.service", &f);
    if (r < 0)
        return EXIT_FAILURE;

    fprintf(f,
        "[Unit]\n"
        "Description=Generated via sd-generator API\n");

    /* Автоматичне створення відносного symlink у каталозі .wants/ */
    r = generator_add_symlink(normal_dir, "multi-user.target", "wants", "my-gen.service");
    if (r < 0)
        return EXIT_FAILURE;

    return EXIT_SUCCESS;
}
```
```cpp
// Приклад використання внутрішніх C-функцій systemd generator API у C++
#include <cstdlib>
#include <iostream>

extern "C" {
#include "generator.h"
}

int main(int argc, char *argv[]) {
    const char *normal_dir = nullptr;
    const char *early_dir = nullptr;
    const char *late_dir = nullptr;

    int r = generator_open_output_dirs(argc, argv, &normal_dir, &early_dir, &late_dir);
    if (r < 0) {
        std::cerr << "Не вдалося відкрити каталоги виводу генератора\n";
        return EXIT_FAILURE;
    }

    FILE *f = nullptr;
    r = generator_open_unit_file(normal_dir, nullptr, "my-gen.service", &f);
    if (r < 0 || !f) {
        std::cerr << "Не вдалося створити unit-файл через sd-generator API\n";
        return EXIT_FAILURE;
    }

    std::fprintf(f,
        "[Unit]\n"
        "Description=Generated via sd-generator C++ wrapper\n");
    std::fclose(f);

    r = generator_add_symlink(normal_dir, "multi-user.target", "wants", "my-gen.service");
    if (r < 0) {
        std::cerr << "Не вдалося створити symlink через sd-generator API\n";
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```
