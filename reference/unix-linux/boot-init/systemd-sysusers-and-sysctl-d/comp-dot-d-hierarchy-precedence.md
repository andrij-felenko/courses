# 🔌 Модель ієрархії каталогів .d та механізм перекриття конфігурацій

Модель каталогів розширення `.d` (drop-in directories) — це фундаментальний архітектурний шаблон systemd для розділення заводських налаштувань операційної системи, конфігурацій пакетів та локальних змін адміністратора. Цей підхід застосовується у більшості системних служб systemd, зокрема `systemd-sysusers`, `systemd-sysctl`, `systemd-tmpfiles`, `systemd-binfmt` та підсистемі керування юнітами (`systemd.conf.d`).

## Архітектурний принцип розділення шарів конфігурації

Традиційна конфігураційна модель Unix спиралася на єдині монолітні файли у каталозі `/etc` (наприклад, `/etc/passwd`, `/etc/sysctl.conf`, `/etc/fstab`). Це створювало численні проблеми при автоматичному оновленні пакетів менеджерами `dpkg` або `rpm`, оскільки будь-яка зміна у заставляла інсталяційний скрипт модифікувати єдиний конфігураційний файл, загрожуючи пошкодженням синтаксису або перезаписом локальних змін системного адміністратора.

Концепція `.d` вирішує цю проблему шляхом виділення трьох чітких рівнів відповідальності у файловій системі:

1. **Заводський рівень (Vendor Layer — `/usr/lib/` або `/lib/`)**:
   Належить дистрибутиву та менеджеру пакетів. Файли у цьому каталозі створюються під час збирання пакетів i постачаються у бінарних образах. Системний адміністратор не повинен редагувати файли у `/usr/lib/` вручну, оскільки при найближчому оновленні пакету всі внесені зміни будуть втрачені.

2. **Рівень часу виконання (Runtime Layer — `/run/`)**:
   Динамічний рівень, розміщений у оперативній пам'яті (`tmpfs`). Сюди записують конфігураційні шматочки генератори systemd, контейнерні рантайми (Docker, podman) або тимчасові скрипти ініціалізації мережі. Всі конфігурації з `/run/` існують лише протягом поточного сеансу роботи і зникають при вимкненні чи перезавантаженні системи.

3. **Адміністративний рівень (Administrator Layer — `/etc/`)**:
   Належить виключно системному адміністратору. Будь-який файл, розміщений у `/etc/<subsystem>.d/`, має абсолютний пріоритет над заводськими налаштуваннями та конфігураціями часу виконання, дозволяючи перевизначити будь-який параметр без редагування файлів пакетів.

## Алгоритм зчитування, об'єднання та затінення (Resolution Pipeline)

Коли утиліта systemd (наприклад, `systemd-sysusers` або `systemd-sysctl`) ініціалізує конфігурацію під час завантаження, вона виконує конвеєр обробки у декілька етапів:

1. **Збір файлів з усіх джерел**: Склад парсерів виконує сканування наступних каталогів у порядку зменшення пріоритету:
   `/etc/<name>.d/*.conf` → `/run/<name>.d/*.conf` → `/usr/lib/<name>.d/*.conf`.
2. **Дедуплікація за базовим ім'ям**: Створюється внутрішня хеш-таблиця, де ключем виступає базове ім'я файлу (наприклад, `50-default.conf`). Якщо файл із таким ім'ям вже знайдено у каталозі з вищим пріоритетом (наприклад, `/etc/sysctl.d/50-default.conf`), однойменний файл із `/usr/lib/sysctl.d/50-default.conf` повністю ігнорується (механізм `shadowing` або затінення).
3. **Обробка маскування (Masking)**: Якщо файл у каталозі з вищим пріоритетом має розмір 0 байт або є символічним посиланням на `/dev/null`, параметр вважається замаскованим. Утиліта повністю виключає цей файл та всі його затінені версії нижчих рівнів із подальшої обробки, дозволяючи адміністратору легко вимикати небажані заводські правила.
4. **Лексикографічне сортування**: Залишок унікальних файлів сортується за лексикографічним порядком їхніх імен (за значенням символів у таблиці ASCII). Завдяки цьому файл `10-network.conf` буде застосовано раніше за `20-database.conf`, незалежно від того, з яких каталогів вони були зчитані.

## Типові підводні камені та пастки для адміністратора

- **Числові префікси**: Невірний вибір числового префіксу (`00-`, `50-`, `99-`) може призвести до перезапису налаштувань у небажаному порядку. Зазвичай заводські конфігурації постачаються з префіксами `50-`, тоді як адміністратор використовує префікс `99-` для гарантованого перекриття всіх попередніх параметрів.
- **Залишені замасковані посилання**: Помилкове залишення символічного посилання на `/dev/null` у `/etc/` призведе до того, що оновлення пакетів у `/usr/lib/` не матимуть жодного ефекту, а система працюватиме із заблокованим параметром без виведення помилок у лог.
- **Ігнорування невідповідних розширень**: Файли, що не мають розширення `.conf` (наприклад, `.conf.bak`, `.dpkg-dist` або `.tmp`), повністю ігноруються під час сканування каталогів `.d`, що часто викликає здивування при спробах тимчасово перейменувати файл конфігурації.
