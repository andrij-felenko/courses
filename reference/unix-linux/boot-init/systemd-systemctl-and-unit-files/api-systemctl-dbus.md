# 📋 API та D-Bus-інтерфейс системного менеджера systemd

Системна шина D-Bus (`org.freedesktop.systemd1`) слугує основними воротами міжпроцесного зв'язку (IPC), через які утиліта `systemctl` та зовнішні системні додатки запитують стани юнітів, виконують транзакційні зміни конфігурації та отримують асинхронні сповіщення від процесного менеджера PID 1.

---

## 1. Архітектура IPC-транспорту та адресація об'єктів

Взаємодія з системним менеджером під час роботи системи здійснюється через сокет системної шини D-Bus за адресою `/run/systemd/system/bus` або `/var/run/dbus/system_bus_socket`. Авотентифікація клієнта виконується на рівні сокета за допомогою механізму передачі сокетних креденціалів SO_PEERCRED ядра Linux (UID/GID процесу-клієнта). Для виконання привілейованих методів (наприклад, `StartUnit` або `Reload`) PID 1 перевіряє права викликача за допомогою служб Polkit або вимагає Root-привілеїв (UID 0).

Під час фази раннього завантаження (до підняття системної шини) або у режимі аварійного відновлення PID 1 відкриває власний приватний сокет `/run/systemd/private`. Клієнтська бібліотека `sd-bus` автоматично перемикається на цей сокет при відсутності шини.

### Кодування об'єктних шляхів D-Bus

Оскільки синтаксис специфікації D-Bus дозволяє у шляхах об'єктів лише символи ASCII `[A-Za-z0-9_]`, усі назви юнітів під час формування об'єктних шляхів піддаються екрануванню. Символи, що не входять до дозволеного набору (крапки, дефіси, символи `@`), замінюються на підкреслення з hex-кодом символу:

- Крапка `.` перетворюється на `_2e` (наприклад, `.service` -> `_2eservice`).
- Дефіс `-` перетворюється на `_2d`.
- Символ `@` перетворюється на `_40`.

Приклади сформованих D-Bus шляхів у системі:
- Юніт `nginx.service` -> `/org/freedesktop/systemd1/unit/nginx_2eservice`
- Юніт `app@worker1.service` -> `/org/freedesktop/systemd1/unit/app_40worker1_2eservice`
- Робота транзакції №42 -> `/org/freedesktop/systemd1/job/42`

## 2. Головний інтерфейс менеджера: `org.freedesktop.systemd1.Manager`

Об'єкт керування розміщений за шляхом `/org/freedesktop/systemd1`. Він надає методи для маніпуляцій транзакціями, завантаження юнітів та маніпулювання конфігурацією.

### 2.1 Основні методи D-Bus та їхні параметри

Нижче наведено семантику параметрів та внутрішню поведінку ключових методів інтерфейсу `Manager`:

- **`GetUnit(s name) -> o path`**
  Приймає текстову назву юніта (`nginx.service`). Повертає об'єктний шлях D-Bus завантаженого юніта. Якщо юніт ще не завантажений у пам'ять PID 1, але присутній на диску, метод повертає помилку `NoSuchUnit`.
- **`LoadUnit(s name) -> o path`**
  Примушує PID 1 знайти юніт на диску, розпарсити його INI-файли та завантажити у пам'ять, повертаючи об'єктний шлях.
- **`StartUnit(s name, s mode) -> o job`**
  Ініціює запуск юніта. Аргумент `mode` визначає політику вирішення конфліктів у транзакції:
  - `"replace"` (за замовчуванням у `systemctl start`) — скасовує інші активні роботи, які вступають у конфлікт із замовленою.
  - `"fail"` — якщо транзакція конфліктує з наявними роботами, запит негайно завершується помилкою `TransactionJobConflict`.
  - `"isolate"` — запускає юніт і зупиняє всі інші юніти, не пов'язані з ним залежностями (використовується при перемиканні тарґетів `systemctl isolate`).
  - `"ignore-dependencies"` — примусово запускає юніт без виконання його залежностей `Requires=` або `Wants=`.
  - `"ignore-requirements"` — ігнорує жорсткі вимоги зупинки.
- **`StopUnit(s name, s mode) -> o job`**
  Формує транзакцію зупинки юніта та його залежностей `RequiredBy=`.
- **`ReloadUnit(s name, s mode) -> o job`**
  Надсилає запит на перезавантаження конфігурації без зупинки основного процесу (виконує командний рядок `ExecReload=`).
- **`RestartUnit(s name, s mode) -> o job`**
  Створює атомну транзакцію зупинки та послідовного запуску юніта.
- **`EnableUnitFiles(as files, b runtime, b force) -> (b carries_install_info, a(sss) changes)`**
  Створює символьні посилання автозапуску у `/etc/systemd/system/` (якщо `runtime == false`) або у тимчасовому каталозі `/run/systemd/system/` (якщо `runtime == true`). Прапорець `force` дозволяє перезаписувати наявні симлінки. Масив `changes` повертає кортежі `(type, filename, destination)`, які описують усі створені посилання.
- **`DisableUnitFiles(as files, b runtime) -> a(sss) changes`**
  Видаляє символьні посилання автозапуску для вказаних юнітів.
- **`MaskUnitFiles(as files, b runtime, b force) -> a(sss) changes`**
  Створює символьне посилання на `/dev/null` для кожного з вказаних юнітів.
- **`Reload()`**
  Примушує PID 1 виконати повне сканування каталогів файлової системи, розпарсити unit-файли та оверриди і перебудувати граф залежностей у пам'яті.

### 2.2 Сигнали D-Bus від `Manager`

Зовнішні додатки можуть підписуватися на сигнали системного менеджера для відстеження змін у графі юнітів у реальному часі:

- `JobNew(u id, o job, s unit)` — сповіщає про створення нової транзакційної роботи з унікальним числовим ідентифікатором `id`.
- `JobRemoved(u id, o job, s unit, s result)` — сповіщає про завершення роботи. Рядок `result` вказує на підсумок виконання:
  - `"done"` — робота успішно виконана.
  - `"canceled"` — роботу скасовано через створення нової транзакції.
  - `"timeout"` — час виконання перевищив `TimeoutStartSec=`.
  - `"failed"` — запуск процесу повернув помилку.
  - `"dependency"` — запуск скасовано через збій залежного юніта.
  - `"skipped"` — запуск пропущено через невиконану умову `Condition...=`.
- `UnitNew(s id, o unit)` — сповіщає про завантаження нового юніта у пам'яті PID 1.
- `UnitRemoved(s id, o unit)` — сповіщає про вивантаження юніта з пам'яті.

## 3. Інтерфейси юніта: `org.freedesktop.systemd1.Unit` та `Service`

Кожен завантажений юніт надає властивості станів та метаданих, які зчитуються через виклики D-Bus `org.freedesktop.DBus.Properties.GetAll`.

### 3.1 Властивості станів юніта (`Unit`)

```
Властивість          Тип D-Bus  Детальний опис та значення
-------------------------------------------------------------------------------------------------
Id                  s          Повне унікальне ім'я юніта (наприклад, "nginx.service").
Names               as         Масив усіх імен та аліасів юніта.
Description         s          Текстовий опис із секції [Unit].
LoadState           s          Стан завантаження конфігурації:
                               - "loaded": файл розпарсений успішно;
                               - "not-found": файл відсутній на диску;
                               - "bad-setting": синтаксична помилка в INI;
                               - "error": помилка зчитування файлу;
                               - "masked": юніт замаскований посиланням на /dev/null.
ActiveState         s          Високорівневий стан:
                               - "active": служба функціонує;
                               - "reloading": виконується ExecReload;
                               - "inactive": служба зупинена;
                               - "failed": запуск завершився аварією;
                               - "activating": виконується запуск;
                               - "deactivating": виконується зупинка.
SubState            s          Низькорівневий стан типу (.service: "running", "exited", "dead",
                               "start-pre", "stop-post"; .socket: "listening"; .timer: "waiting").
UnitFileState       s          Стан автозапуску у файловій системі:
                               - "enabled": симлінк створений у .wants/;
                               - "disabled": симлінк відсутній;
                               - "masked": симлінк вказує на /dev/null;
                               - "static": секція [Install] відсутня, запуск лише через залежності;
                               - "indirect": увімкнений через інший юніт у ключі Also=;
                               - "generated": створений динамічним генератором;
                               - "transient": створений динамічно через systemd-run.
InactiveExitTimestamp t        Microseconds timestamp (epoch) переходу з стан inactive.
ActiveEnterTimestamp  t        Microseconds timestamp (epoch) успішного переходу в active.
CanStart            b          true, якщо юніт можна запустити прямо.
CanStop             b          true, якщо юніт можна зупинити.
CanReload           b          true, якщо визначено директиву ExecReload=.
```

### 3.2 Специфічні властивості служби (`Service`)

```
Властивість          Тип D-Bus  Детальний опис
-------------------------------------------------------------------------------------------------
Type                s          Модель виконання: "simple", "exec", "forking", "oneshot", "dbus", "notify", "idle".
Restart             s          Політика автоперезапуску: "no", "always", "on-success", "on-failure", "on-abnormal", "on-abort".
MainPID             u          PID головного процесу служби (0, якщо процес відсутній).
ControlPID          u          PID поточного допоміжного процесу (ExecStartPre/ExecReload/ExecStop).
ExecMainExitTimestamp t        Час завершення останнього головного процесу.
ExecMainExitCode    i          Код завершення або номер сигналу останнього головного процесу.
ExecMainStatus      i          Значення status із виклику waitpid() для головного процесу.
Result              s          Підсумок виконання останньої операції:
                               - "success": успішне завершення;
                               - "protocol": порушено протокол (наприклад, sd_notify);
                               - "timeout": перевищено лиміт часу;
                               - "exit-code": процес повернув некоректний код виходу;
                               - "signal": процес убито сигналом (SIGKILL/SIGSEGV);
                               - "core-dump": процес упав із дампа пам'яті;
                               - "resources": брак системних ресурсів під час запуску.
```

## 4. Мапування команд `systemctl` на D-Bus виклики та коди повернення

Під час виконання у командному рядку утиліта `systemctl` викликами D-Bus формує відповідні коди завершення процесів (exit codes) для командної оболонки Shell:

| Команда `systemctl` | D-Bus виклик та алгоритм | Код успіху | Коди помилок (Exit Status) |
| :--- | :--- | :--- | :--- |
| `systemctl status <unit>` | Викликає `GetUnit`, читає `ActiveState` та `SubState`. | `0` (юніт у стані `active` або `running`) | `1` (юніт `failed` або dead), `3` (юніт `inactive`), `4` (юніт `not-found`) |
| `systemctl is-active <unit>` | Читає властивість `ActiveState`. | `0` (друкує `"active"`) | `3` (друкує `"inactive"` або `"failed"`) |
| `systemctl is-enabled <unit>`| Читає властивість `UnitFileState`. | `0` (друкує `"enabled"`) | `1` (друкує `"disabled"`, `"static"` чи `"masked"`) |
| `systemctl start <unit>` | Викликає `StartUnit(unit, "replace")`, підписується на `JobRemoved`. | `0` (робота завершилась зі статусом `"done"`) | `1` (робота завершилась з умовою `"failed"`, `"timeout"` або `"dependency"`) |
| `systemctl stop <unit>` | Викликає `StopUnit(unit, "replace")`, чекає на `JobRemoved`. | `0` (робота завершилась зі статусом `"done"`) | `1` (помилка скасування або D-Bus) |
| `systemctl daemon-reload` | Викликає метод `Reload()` на об'єкті Manager. | `0` (конфігурація оновлена) | `1` (помилка зчитування або доступу) |

## 5. Канонічні помилки D-Bus (`sd-bus` Error Names)

Під час виклику методів `org.freedesktop.systemd1` системний менеджер повертає стандартні D-Bus помилки, які обробляються утилітою `systemctl` або клієнтським кодом:

- `org.freedesktop.systemd1.NoSuchUnit` — юніт з вказаним ім'ям відсутній у пам'яті та на диску.
- `org.freedesktop.systemd1.UnitMasked` — запуск відхилено, оскільки `LoadState == "masked"`.
- `org.freedesktop.systemd1.TransactionIsDestructive` — замовлена операція руйнує активну транзакцію без прапорця примусового перезапису.
- `org.freedesktop.systemd1.TransactionJobConflict` — замовлена робота суперечить наявним роботам в черзі через ребра `Conflicts=`.
- `org.freedesktop.systemd1.UnitNotLoaded` — юніт знаходиться в стані помилки завантаження (`bad-setting` або синтаксична помилка в INI-файлі).
- `org.freedesktop.systemd1.LoadFailed` — помилка читання юніта з диска або пошкоджені символьні посилання.
