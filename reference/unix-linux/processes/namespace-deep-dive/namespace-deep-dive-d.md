Коли ми говоримо про «контейнеризацію» у Linux, фундаментальним механізмом, який забезпечує ізоляцію, є **простори імен (namespaces)**. На відміну від віртуальних машин, які емулюють апаратне забезпечення й запускають окреме ядро, простори імен працюють на рівні єдиного ядра. Вони не створюють стін чи нових об'єктів — вони створюють **нові ізольовані словники імен** для існуючих глобальних ресурсів.

## Від глобальних таблиць до `nsproxy`

У класичному Unix ресурси ядра — такі як таблиця процесів, дерево монтувань, мережевий стек, IPC об'єкти — були глобальними. Ядро мало єдину структуру для кожного типу ресурсів.

Простори імен змінили цю архітектуру. Замість єдиної глобальної таблиці, ядро тепер тримає ресурси у вигляді структур, на які процеси посилаються. Кожна задача (`struct task_struct`) в ядрі Linux містить вказівник на структуру `nsproxy`.

`nsproxy` — це своєрідний «проксі», що агрегує вказівники на різні простори імен, у яких перебуває процес:

```c
struct nsproxy {
    atomic_t count;
    struct uts_namespace *uts_ns;
    struct ipc_namespace *ipc_ns;
    struct mnt_namespace *mnt_ns;
    struct pid_namespace *pid_ns_for_children;
    struct net           *net_ns;
    struct time_namespace *time_ns;
    struct time_namespace *time_ns_for_children;
    struct cgroup_namespace *cgroup_ns;
};
```

Коли кілька процесів поділяють один простір імен, їхні структури `nsproxy` посилаються на ті самі об'єкти `*_namespace`. Зміна імені ресурсу в такому просторі відобразиться для всіх процесів. Якщо процес створює новий простір, ядро клонує відповідну структуру й оновлює `nsproxy`.

## Базова структура `ns_common`

Будь-який простір імен в ядрі будується навколо спільного заголовка — `struct ns_common`:

```c
struct ns_common {
    atomic_long_t stashed;
    const struct proc_ns_operations *ops;
    unsigned int inum;
};
```

Тут `inum` — це унікальний номер індексного вузла (inode), який генерується ядром для ідентифікації примірника простору імен. Саме цей номер ми бачимо, коли досліджуємо процеси через `procfs`.

## Магія `nsfs` та `/proc/[pid]/ns/`

Простори імен матеріалізуються у файловій системі через `/proc`. Кожен процес має каталог `/proc/[pid]/ns/`, що містить так звані «магічні» символьні посилання на кожен простір імен.

Насправді ці файли не є звичайними лінками; вони належать до внутрішньої віртуальної файлової системи ядра — `nsfs`. Якщо ми виконаємо команду `readlink` або `ls -l`, то побачимо щось на зразок:

```
lrwxrwxrwx 1 root root 0 Сер 10 18:00 net -> net:[4026531992]
```

Число в квадратних дужках — це той самий `inum` зі структури `ns_common`. Це дає найпростіший спосіб перевірити, чи ділять два процеси один простір імен: достатньо порівняти їхні номери індексних вузлів.

Більше того, файл простору імен можна відкрити й отримати файловий дескриптор. Поки цей дескриптор залишається відкритим, ядро не знищить простір імен, навіть якщо всі процеси в ньому вже завершилися. Цей механізм дозволяє створювати «персистентні» простори (наприклад, командою `ip netns add`), монтуючи `nsfs`-посилання в іншу точку (зазвичай `/run/netns/`).

## API просторів імен: `clone`, `unshare`, `setns`

Програмний інтерфейс для роботи з просторами імен складається з трьох ключових системних викликів.

### 1. Створення простору: `clone(2)`

Системний виклик `clone` — це фундамент створення процесів у Linux (який лежить в основі `fork` та створення потоків). Він приймає набір прапорців `CLONE_NEW*`, що вказують, які простори імен слід відв'язати від батька і створити з нуля.

### 2. Ізоляція на льоту: `unshare(2)`

`unshare` дозволяє процесу відв'язатися від поточних просторів імен без створення нового процесу (за винятком `PID` простору, де зміни застосовуються лише до майбутніх дочірніх процесів). 

### 3. Приєднання до наявного простору: `setns(2)`

Коли простір імен уже існує (його утримує інший процес або відкритий файловий дескриптор), процес може приєднатися до нього за допомогою `setns`. Для цього потрібно відкрити файл `/proc/[pid]/ns/[type]` і передати отриманий дескриптор у `setns`.

```bash
# Створити новий простір номерів і монтувань, запустити ізольований bash
unshare --pid --mount --fork --mount-proc /bin/bash

# Приєднатися до мережевого простору існуючого процесу 1234
nsenter --target 1234 --net /bin/bash
```

## Простори імен не є стінами

Найголовніша концептуальна пастка: простори імен не обмежують ресурси й не роздвоюють ядро. Процес у новому `PID` просторі не бачить сусідів, але він і далі може спожити всю пам'ять чи процесорний час (це завдання для cgroups). Процес працює з тим самим ядром, і якщо в ядрі є вразливість, вона однаково доступна всім «контейнерам».

Ізоляція — це не бінарна властивість. Вона складається з набору конкретних словників імен. Правильне питання полягає не в тому, «чи ізольовано процес», а «в яких саме просторах він має власні словники».
