# Простори імен: короткий огляд

<preknowlist>
- [Процес: що це насправді](book:unix-linux/process-model) — задача посилається на зовнішні ресурси.
- [/proc: процеси як файли](book:unix-linux/proc-filesystem) — інструмент читання стану системи.
</preknowlist>

Уяви, що у тебе на комп'ютері працює дві різні програми баз даних. Кожна хоче працювати на порті 5432, кожна бажає бути єдиною на машині. Якби система була єдиною для всіх, вони б конфліктували. Простори імен вирішують цю проблему, видаючи кожній програмі її власний, ізольований "словник", через який вона бачить ресурси.

Замість того, щоб мати єдиний глобальний список портів чи ідентифікаторів процесів (PID), ядро Linux дозволяє клонувати ці списки. Для цього у структурі кожного процесу є вказівник на `nsproxy`. Це набір посилань на різні простори імен (мережевий, користувацький, дерева монтувань). Коли програма виконує дію, ядро перевіряє не глобальний список, а конкретний простір імен, на який посилається `nsproxy`.

Це означає, що програма може працювати в повній впевненості, що вона єдина в системі. Вона бачить процеси, починаючи з номера 1. Однак це ілюзія — ядро просто транслює реальні PID у віртуальні для цього простору імен.

### Управління просторами імен

Робота з просторами зводиться до кількох системних викликів:
- `clone()`: створює новий процес, одночасно поміщаючи його у нові простори.
- `unshare()`: відкріплює існуючий процес від поточних просторів і створює нові.
- `setns()`: дозволяє процесу приєднатись до вже існуючого простору іншого процесу.

Для системи всі ці процеси продовжують працювати під управлінням одного ядра. Простори імен не споживають багато ресурсів і не створюють жорстких "стін", які існують у віртуальних машинах. Якщо процес забажає більше пам'яті, простір імен йому не завадить — обмеженнями займається інший інструмент (cgroups).

:::tabs
== Bash
```bash
# Створення нового простору і вхід у нього
unshare --pid --mount --fork --mount-proc /bin/bash
```
== C
```c
// Запуск процесу в новому просторі
int flags = CLONE_NEWPID | CLONE_NEWNET;
clone(child_func, stack, flags | SIGCHLD, NULL);
```
:::
