# Атомарні операції та бар'єри пам'яті

В ядрі Linux безліч процесів та переривань постійно працюють з одними й тими ж даними. Щоб уникнути пошкодження даних (станів гонитви), потрібна синхронізація. Класичні блокування зупиняють виконання, що часто є надто «дорогою» операцією. Для швидкої роботи з простими лічильниками чи прапорцями використовують **атомарні операції**, які процесор виконує як єдину неподільну дію. Але через оптимізації процесорів для коректної роботи також потрібні **бар'єри пам'яті**.

## Атомарний тип `atomic_t`

Замість звичайних цілих чисел ядро використовує спеціальний тип `atomic_t`. З ним не можна працювати безпосередньо, лише через спеціалізований API. Це зроблено навмисно, щоб унеможливити помилкове звичайне зчитування чи запис.

```c
atomic_t counter = ATOMIC_INIT(0);

atomic_set(&counter, 5);           // Встановити значення
int val = atomic_read(&counter);   // Прочитати
atomic_inc(&counter);              // Неподільно збільшити на 1
```

Операції на кшталт `atomic_inc` (Read-Modify-Write) гарантують, що під час читання, зміни та запису значення жоден інший процесор не зможе втрутитися в цей процес.

## Переупорядкування та бар'єри

Самі по собі атомарні операції не захищають від того, що компілятор або сам процесор змінить порядок виконання інструкцій задля швидкості (Out-of-Order Execution). 

Якщо один потік записує дані, а потім встановлює прапорець `ready`, інший потік може побачити зміну `ready` ще **до** того, як дані дійсно оновляться в пам'яті. Щоб цього уникнути, застосовують **бар'єри пам'яті**:

- **`smp_rmb()`** (Read Barrier) — гарантує порядок операцій читання.
- **`smp_wmb()`** (Write Barrier) — гарантує порядок операцій запису.
- **`smp_mb()`** (Full Barrier) — зупиняє переупорядкування як для читання, так і для запису.

:::tabs
== C (Linux Kernel)
```c
// Потік 1
data = 42;
smp_wmb();  // Дані точно запишуться ДО прапорця
ready = 1;

// Потік 2
if (ready == 1) {
    smp_rmb(); // Читання даних точно буде ПІСЛЯ перевірки прапорця
    print(data);
}
```
== C11 (Userspace)
```c
// Потік 1
data = 42;
atomic_store_explicit(&ready, 1, memory_order_release);

// Потік 2
if (atomic_load_explicit(&ready, memory_order_acquire) == 1) {
    print(data);
}
```
:::

## Acquire та Release

Оскільки класичні бар'єри впливають на весь конвеєр процесора, вони дуже ресурсоємні. У сучасному коді частіше застосовують однобічні бар'єри (Acquire/Release):

- **`smp_load_acquire()`** гарантує, що операції після нього не будуть переміщені вище нього. 
- **`smp_store_release()`** гарантує, що всі попередні операції з пам'яттю завершаться до цього запису.

```c
// Потік 1
data = 42;
smp_store_release(&ready, 1);

// Потік 2
if (smp_load_acquire(&ready) == 1) {
    print(data);
}
```

Використання `smp_store_release` та `smp_load_acquire` є де-факто стандартом для синхронізації «виробник-споживач» у сучасному ядрі Linux. Це швидше і менш схильне до помилок, ніж ручне розставлення бар'єрів запису і читання.
