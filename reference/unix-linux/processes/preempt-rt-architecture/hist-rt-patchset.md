# 📜 Історія створення та 20-річний шлях PREEMPT_RT до мейнлайну

Трансформація ядра Linux із системи розподілу часу на операційну систему жорсткого реального часу розпочалася 2004 року під тиском промислових систем керування, які більше не могли спиратися на закриті рішення або на зв'язку з окремого мікроядра реального часу. Ініціатива розробників Інґо Молнара (Ingo Molnar) та Томаса Ґляйкснера (Thomas Gleixner) започаткувала 20-річну еволюцію, що перетворила монолітне ядро на високодетерміноване середовище.

## Перші спроби: два ядра ОС замість одного

Наприкінці 1990-х років, коли операційна система Linux почала впроваджуватися у промисловій автоматиці та телекомунікаціях, стандартне ядро 2.2/2.4 абсолютно не відповідало вимогам детермінізму. Затримки реагування на переривання під навантаженням могли перевищувати десятки мілісекунд через невитіснюваність ядра, вимкнені переривання у драйверах та відсутність реальних таймерів високої точності.

Першим розв'язанням цієї проблеми став підхід з двома ядрами (dual-kernel approach), втілений у проєктах **RTLinux** (Віктор Йодайкен, Майкл Барабанов і Корт Дуган у New Mexico Institute of Mining and Technology; згодом комерційний продукт FSMLabs) та **RTAI** (Real-Time Application Interface, Політехніка Мілана). Ідея полягала в тому, що просто на апаратному забезпеченні — під ядром Linux — запускалося крихітне мікроядро реального часу, яке повністю перехоплювало таблицю переривань CPU. Звичайне ядро Linux запускалося як найнижче за пріоритетом завдання (idle-loop) поверх цього мікроядра.

```
+-------------------------------------------------------+
|  RT Tasks (RTLinux / RTAI) | Linux Kernel & Userland  |
+----------------------------+--------------------------+
|  Real-Time Microkernel (Hardware Interrupt Intercept) |
+-------------------------------------------------------+
|                   Hardware CPU                        |
+-------------------------------------------------------+
```

Хоча підхід із двома ядрами гарантував мікросекундний детермінізм, він мав колосальні недоліки:
1. **Подвійна програма**: Розробникам доводилося писати спеціальні драйвери реального часу для мікроядра, позбавлені доступу до багатого API Linux (файлових систем, мережевого стека, VFS).
2. **Складність міжпроцесної взаємодії**: Дані між RT-кодом і звичайними процесами Linux передавалися через вузькі FIFO-буфери або спільну пам'ять.
3. **Ліцензійні та патентні конфлікти**: Патентування деяких підходів RTLinux створило юридичні бар'єри для розповсюдження.

## Народження PREEMPT_RT (2004 рік)

Восени 2004 року Інґо Молнар, видатний розробник ядра з Red Hat, започаткував проєкт **PREEMPT_RT**. Його мета була радикальною: не створювати другого ядра, а перетворити саме ядро Linux на систему жорсткого реального часу (in-kernel real-time).

Замість обходу системних викликів і API Linux `PREEMPT_RT` поставив за мету зробити витіснюваним майже весь код ядра — без втрати сумісності з POSIX. До Інґо Молнара незабаром приєдналися Томас Ґляйкснер (засновник Linutronix), Стівен Ростедт (Steven Rostedt) та Свен-Торстен Дітріх (Sven-Thorsten Dietrich).

Перші версії RT-патчсета були революційними: вони замінили класичний `spinlock_t` на сплячий м'ютекс із підтримкою успадкування пріоритетів (`rt_mutex`) і перетворили апаратні обробники переривань на потоки ядра.

## 20-річна стратегія поступової інтеграції (Mainlining)

Спільнота ядра на чолі з Лінусом Торвальдсом відмовилася приймати RT-патчсет гігантським монолітним шматком. Замість цього було обрано стратегію розбиття патчсета на окремі підсистеми та їх поступового вдосконалення для основного дерева ядра (mainline):

1. **Linux 2.6.16 (2006)**: Інтеграція підсистеми високоточних таймерів **hrtimers** (High-Resolution Timers), розробленої Томасом Ґляйкснером. Це дозволило системним викликам `clock_nanosleep()` оперувати наносекундними інтервалами замість дискретних системних тиків (jiffies).
2. **Linux 2.6.18 (2006)**: Впровадження примітива **rt_mutex** і винесення успадкування пріоритетів у простір користувача через PI-futex (операції `FUTEX_LOCK_PI` / `FUTEX_UNLOCK_PI`, на яких стоїть `PTHREAD_PRIO_INHERIT`).
3. **Linux 2.6.30 (2009)**: Додавання інфраструктури **Threaded IRQs** (`request_threaded_irq()`), яка дозволила драйверам явно розділяти обробку переривань на апаратну та потокову частини.
4. **Linux 2.6.32 (2009)**: Інтеграція витіснюваного RCU (**Tree Preemptible RCU**, опція `CONFIG_TREE_PREEMPT_RCU` Пола Мак-Кенні), що дозволило читачам RCU-структур витіснятися, не ламаючи періодів грації.
5. **Linux 3.14 (2014)**: Впровадження планувального класу **SCHED_DEADLINE** за алгоритмом EDF (Earliest Deadline First) з обмеженням ресурсів CBS (Constant Bandwidth Server) — робота Даріо Фаджолі та Юрі Леллі (ReTiS Lab, Scuola Superiore Sant'Anna) разом із Петером Зейлстрою.
6. **Linux 5.10 (2020)**: Переробка підсистеми `printk` та впровадження безблокового кільцевого буфера (lockless ringbuffer) Джона Оґнеса (John Ogness, Linutronix), що прибрало найдовші затримки ядра при консольному виводі під `console_lock`.

## Створення Real-Time Linux Project та фінал у Linux 6.12

Тривалий час підтримка RT-патчсета трималася на ентузіазмі невеликої групи розробників і спонсорстві окремих компаній. У 2015 році під егідою **Linux Foundation** було створено офіційний проєкт **Real-Time Linux (RTL) Collaborative Project**, до якого увійшли великі виробники процесорів, вимірювальної техніки й промислової автоматики разом із OSADL та Linutronix. Це забезпечило стабільне фінансування та ресурси для автоматизованого тестування (CI/CD) підсистеми на різноманітному апаратному забезпеченні.

Восени 2024 року, з виходом ядра **Linux 6.12**, відбулася історична подія: останні фундаментальні шматки `PREEMPT_RT` (зокрема повна інтеграція сплячих спінлоків і конфігураційного прапорця `CONFIG_PREEMPT_RT`) були офіційно злиті у мейнлайн Лінуса Торвальдса. Через 20 років після появи першого патча, Linux став повноцінною системою жорсткого реального часу «із коробки».
