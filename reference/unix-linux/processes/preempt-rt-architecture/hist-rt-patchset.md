# 📜 Історія створення та 20-річний шлях PREEMPT_RT до мейнлайну

Трансформація ядра Linux із системи розподілу часу на операційну систему жорсткого реального часу розпочалася 2004 року під тиском промислових систем керування, які більше не могли спиратися на закриті або двоядерні рішення. Ініціатива розробників Інґо Молнара (Ingo Molnar) та Томаса Ґляйкснера (Thomas Gleixner) започаткувала 20-річну еволюцію, що перетворила монолітне ядро на високодетерміноване середовище.

## Перші спроби: Двоядерні архітектури проти єдиного ядра

Наприкінці 1990-х років, коли операційна система Linux почала впроваджуватися у промисловому автоматикуванні та телекомунікаціях, стандартне ядро 2.2/2.4 абсолютно не відповідало вимогам детермінізму. Затримки реагування на переривання під навантаженням могли перевищувати десятки мілісекунд через невитіснюваність ядра, вимкнені переривання у драйверах та відсутність реальних таймерів високої точності.

Першим розв'язанням цієї проблеми став підхід з двома ядрами (dual-kernel approach), втілений у проєктах **RTLinux** (створеному Віктором Йодаікеном) та **RTAI** (Real-Time Application Interface). Ідея полягала в тому, що під апаратним забезпеченням запускалося крихітне мікроядро реального часу, яке повністю перехоплювало таблицю переривань CPU. Звичайне ядро Linux запускалося як найнижче за пріоритетом завдання (idle-loop) поверх цього мікроядра.

```
+-------------------------------------------------------+
|  RT Tasks (RTLinux / RTAI) | Linux Kernel & Userland  |
+----------------------------+--------------------------+
|  Real-Time Microkernel (Hardware Interrupt Intercept) |
+-------------------------------------------------------+
|                   Hardware CPU                        |
+-------------------------------------------------------+
```

Хоча двоядерний підхід гарантував мікросекундний детермінізм, він мав колосальні недоліки:
1. **Подвійна програма**: Розробникам доводилося писати спеціальні драйвери реального часу для мікроядра, позбавлені доступу до багатого API Linux (файлових систем, мережевого стека, VFS).
2. **Складність міжпроцесної взаємодії**: Дані між RT-кодом і звичайними процесами Linux передавалися через вузькі FIFO-буфери або спільну пам'ять.
3. **Ліцензійні та патентні конфлікти**: Патентування деяких підходів RTLinux створило юридичні бар'єри для розповсюдження.

## Народження PREEMPT_RT (2004 рік)

Восени 2004 року Інґо Молнар, видатний розробник ядра з Red Hat, започаткував проєкт **PREEMPT_RT**. Його мета була радикальною: не створювати другого ядра, а перетворити саме ядро Linux на систему жорсткого реального часу (in-kernel real-time).

Замість обходу системних викликів і API Linux, `PREEMPT_RT` поставив за мету зробити 99% коду ядра витіснюваним без втрати сумісності з POSIX. До Інґо Молнара незабаром приєдналися Томас Ґляйкснер (засновник Linutronix), Стівен Ростедт (Steven Rostedt) та Свен-Торстен Дітріх (Sven-Thorsten Dietrich).

Перші версії RT-патчсета були революційними: вони замінили класичний `spinlock_t` на сплячий м'ютекс із підтримкою успадкування пріоритетів (`rt_mutex`) і перетворили апаратні обробники переривань на потоки ядра.

## 20-річна стратегія поступової інтеграції (Mainlining)

Спільнота ядра на чолі з Лінусом Торвальдсом відмовилася приймати RT-патчсет гігантським монолітним шматком. Замість цього було обрано стратегію розбиття патчсета на окремі підсистеми та їх поступового вдосконалення для основного дерева ядра (mainline):

1. **Linux 2.6.16 (2006)**: Інтеграція підсистеми високоточних таймерів **hrtimers** (High-Resolution Timers), розробленої Томасом Ґляйкснером. Це дозволило системним викликам `clock_nanosleep()` оперувати наносекундними інтервалами замість дискретних системних тиків (jiffies).
2. **Linux 2.6.18 (2006)**: Впровадження примітива **rt_mutex** та розширень успадкування пріоритетів у користувацькому просторі через robust futexes.
3. **Linux 2.6.30 (2009)**: Додавання інфраструктури **Threaded IRQs** (`request_threaded_irq()`), яка дозволила драйверам явно розділяти обробку переривань на апаратну та потокову частини.
4. **Linux 3.0 (2011)**: Інтеграція витіснюваного RCU (**Tree Preemptible RCU**), що дозволило читачам RCU-структур спати та витіснятися без порушення когерентності пам'яті.
5. **Linux 3.14 (2014)**: Впровадження планувального класу **SCHED_DEADLINE**, реалізованого Юрі Ліллі за алгоритмом EDF (Earliest Deadline First) з обмеженням ресурсів CBS (Constant Bandwidth Server).
6. **Linux 5.15 (2021)**: Переробка підсистеми `printk` та впровадження беблокового кільцевого буфера (lockless ringbuffer), що усунуло затримки ядра при консольному виводі під спінлоком `console_lock`.

## Створення Real-Time Linux Project та фінал у Linux 6.12

Тривалий час підтримка RT-патчсета трималася на ентузіазмі невеликої групи розробників і спонсорстві окремих компаній. У 2015 році під егідою **Linux Foundation** було створено офіційний проєкт **Real-Time Linux Collaborative Project**, до якого увійшли такі гіганти, як BMW, Siemens, Red Hat, Intel, OSADL та Linutronix. Це забезпечило стабільне фінансування та ресурси для автоматизованого тестування (CI/CD) підсистеми на різноманітному апаратному забезпеченні.

Восени 2024 року, з виходом ядра **Linux 6.12**, відбулася історична подія: останні фундаментальні шматки `PREEMPT_RT` (зокрема повна інтеграція сплячих спінлоків і конфігураційного прапорця `CONFIG_PREEMPT_RT`) були офіційно злиті у мейнлайн Лінуса Торвальдса. Через 20 років після появи першого патча, Linux став повноцінною системою жорсткого реального часу «із коробки».
