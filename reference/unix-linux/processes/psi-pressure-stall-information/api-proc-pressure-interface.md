# 📋 Специфікація інтерфейсу PSI: файли /proc/pressure та контроль cgroups v2

Підсистема Pressure Stall Information (PSI) надає двохешелонний програмний інтерфейс для моніторингу голодування ресурсів у просторі користувача: системно-широкий рівень через віртуальну файлову систему `procfs` (`/proc/pressure/`) та ізольований рівень контрольних груп через `cgroups v2` (`/sys/fs/cgroup/.../*.pressure`). Цей довідник описує точну структуру експортованих полів, алгоритми їх обчислення, правила налаштування подієвих тригерів, семантику системних викликів та моніторинг дельт.

## Структура файлів /proc/pressure/

Для трьох основних видів ресурсів ядро створює окремі віртуальні вузли у файловій системі procfs:
- `/proc/pressure/cpu` — голодування за процесорним часом (лише рядок `some`).
- `/proc/pressure/memory` — голодування за оперативною пам'яттю (рядки `some` та `full`).
- `/proc/pressure/io` — голодування за вводом/виводом блокових пристроїв та файлових систем (рядки `some` та `full`).

Файли `memory` та `io` містять по два рядки статистичних даних (для рівнів `some` та `full`), тоді як файл `cpu` містить лише один рядок (`some`), оскільки повного голодування процесора в діючій системі не існує.

```text
$ cat /proc/pressure/memory
some avg10=1.25 avg60=0.84 avg300=0.12 total=45210984
full avg10=0.00 avg60=0.00 avg300=0.00 total=1204890
```

### Синтаксис і детальний розбір полів

Кожен рядок даних у файлі PSI розбивається на дві частини: трійку експоненційно згладжених середніх та один кумулятивний лічильник часу.

1. **`avg10`**: Експоненційно згладжене середнє значення відсотка часу голодування за останні **10 секунд**. Метрика швидко реагує на короткочасні сплески ресурсного тиску.
2. **`avg60`**: Експоненційно згладжене середнє значення відсотка часу за останні **60 секунд** (1 хвилина). Відображає середньострокові тренди навантаження.
3. **`avg300`**: Експоненційно згладжене середнє значення відсотка часу за останні **300 секунд** (5 хвилин). Показує довгостроковий стан ресурсного дефіциту.
4. **`total`**: Абсолютний кумулятивний лічильник часу в **мікросекундах (us)**, проведеного системою у відповідному стані голодування з моменту завантаження ядра (або створення відповідної cgroup).

### Математичний розрахунок EWMA та вимірювання дельт

Значення `avg10`, `avg60` та `avg300` обчислюються в ядрі за допомогою формули експоненційно зваженого ковзного середнього (EWMA):

```text
avg_new = avg_old · e^(-dt / T) + stall_pct · (1 - e^(-dt / T))
```

Де:
- `dt = 2` секунди (період виклику внутрішнього ядерного таймера `psi_update_work`).
- `T` — часове вікно згладжування (10, 60 або 300 секунд).
- `stall_pct` — фактична частка часу голодування у поточному 2-секундному інтервалі.

Оскільки ковзні середні загладжують короткі сплески, системи високоточного моніторингу (Prometheus node_exporter, Datadog agent) спираються на кумулятивний лічильник `total`. Поле `total` є монотонно зростаючим. Для розрахунку точного відсотка голодування між двома моментовими замірами `t1` та `t2` використовується наступна формула:

```text
Stall_Percentage = (total(t2) - total(t1)) / ((t2 - t1) в мікросекундах) · 100%
```

#### Покроковий приклад обчислення дельти:

Припустимо, програма моніторингу прочитала поле `total` з `/proc/pressure/memory` у момент часу `t1`, а потім повторно у момент `t2` через 5 секунд:
- `t1 = 10.0` с, `total(t1) = 1 000 000` us.
- `t2 = 15.0` с, `total(t2) = 1 500 000` us.
- Інтервал часу: `t2 - t1 = 5.0` с = `5 000 000` us.
- Дельта затримки: `total(t2) - total(t1) = 500 000` us.
- Розраховане голодування: `500 000 us / 5 000 000 us = 0.10` (або **10.0%** часу).

Це означає, що протягом 5-секундного інтервалу вимірювання процеси чекали на виділення пам'яті точних 10% астрономічного часу.

## Інтеграція з Control Groups (cgroups v2)

У cgroups v2 кожен вузол ієрархії містить власні файли моніторингу PSI:
- `<cgroup_path>/cpu.pressure`
- `<cgroup_path>/memory.pressure`
- `<cgroup_path>/io.pressure`

На відміну від глобальних файлів у `/proc/pressure/`, файли в cgroup відображають голодування лише тих процесів, які належать до цієї конкретної контрольної групи та її підпорядкованих нащадків.

| Файл cgroups v2 | Контролер cgroup | Наявність `some` | Наявність `full` | Опис контрольованого голодування |
| :--- | :--- | :--- | :--- | :--- |
| `cpu.pressure` | `cpu` | Так | Ні | Процеси групи чекають на вільний квант CPU через конкуренцію з іншими cgroups. |
| `memory.pressure` | `memory` | Так | Так | Затримки через direct reclaim, page faults, swapping або очікування memory limit групи. |
| `io.pressure` | `io` | Так | Так | Процеси групи чекають на виконання блокових операцій зчитування/запису. |

Двохрівнева модель дозволяє розділити відповідальність: глобальний `/proc/pressure/` моніторить здоров'я всього вузла (bare-metal чи VM), а `cgroup.pressure` надає метрики для контейнерів (Docker, Podman, LXC, Kubernetes pods).

## Подієвий інтерфейс тригерів (Triggers & Epoll)

Постійний читальний опит (polling) файлів PSI через відкриття та читання рядків створює непотрібні накладні витрати CPU. Для реального часу PSI підтримує підписку на події перевищення порогу через системні виклики `poll()`, `epoll()` або `select()`.

### Синтаксис реєстрації тригера

Щоб налаштувати сповіщення, процес відкриває відповідний файл PSI у режимі читання-запису (`O_RDWR` або `O_WRONLY`) і записує в нього конфігураційний рядок наступного формату:

```text
<some|full> <threshold_us> <window_us>
```

- **`some` / `full`**: тип стану голодування, який відстежується.
- **`threshold_us`**: поріг сумарного часу затримки в мікросекундах.
- **`window_us`**: довжина рухомого часового вікна в мікросекундах (від 500 000 us [0.5с] до 10 000 000 us [10с]).

#### Приклади тригерів:

1. `some 150000 1000000` — розбудити процес, якщо протягом 1-секундного вікна (`1 000 000 us`) хоча б одна задача чекала на ресурс сумарно **150 мс** (`150 000 us`, або 15% часу).
2. `full 50000 1000000` — розбудити процес, якщо протягом 1-секундного вікна ВСІ задачі були заблоковані сумарно протягом **50 мс** (`50 000 us`, або 5% часу).

### Алгоритм роботи ядерного вікна тригера

Коли тригер зареєстровано на відкритому файловому дескрипторі:
1. Ядро створює внутрішню структуру `psi_trigger` і прив'язує її до даного `struct file`.
2. Кожне вікно розбивається на кілька коротких інтервалів оцінки (tracking periods, зазвичай 50 мс).
3. Коли сумарна дельта затримок у межах вікна `window_us` перевищує `threshold_us`, ядро надсилає подію `POLLPRI` (Priority Data) на відповідний файловий дескриптор.
4. Опитувальний виклик `epoll_wait()` повертає прапор `EPOLLPRI`, сповіщаючи процес про критичний тиск.

```
Структура реєстрації тригера PSI:

   Простір користувача                      Ядро Linux (PSI Engine)
+-----------------------+               +----------------------------------+
| open("/proc/pressure/ |               |                                  |
|       memory",O_RDWR) | --- fd ---->  | psi_trigger_create()             |
| write(fd, "some ...") |               | Створення tracking window        |
+-----------------------+               +----------------------------------+
            |                                            |
            v                                            v
+-----------------------+               +----------------------------------+
| epoll_wait(...,       | <--- POLLPRI -| Перевищено threshold_us          |
|            EPOLLPRI)  |               | у вікні window_us!               |
+-----------------------+               +----------------------------------+
```

### Особливості, права доступу та обмеження тригерів

- **Один файловий дескриптор — один тригер:** На одному відкритому `fd` можна зареєструвати лише один тригер. Якщо потрібно відстежувати і `some`, і `full`, програма повинна відкрити файл двічі й отримати два окремих `fd`.
- **Життєвий цикл тригера:** Тригер існує лише доти, доки відкрито відповідний файловий дескриптор `fd`. Закриття `fd` через `close()` автоматично видаляє тригер із ядерного списку відстеження.
- **Права доступу:** Запис тригера у глобальні файли `/proc/pressure/*` вимагає привілеїв `CAP_SYS_RESOURCE` або прав root. У cgroups v2 запис у `<cgroup>/memory.pressure` дозволений власникові файлу в межах делегованого середовища без root-прав.
- **Своєчасне очищення списку подій:** Після спрацювання `epoll_wait()` додаток повинен обов'язково виконати виклик `read(fd)` або `lseek(fd, 0, SEEK_SET)`, щоб ядро скинуло прапор пріоритетної події `POLLPRI`. Якщо цього не зробити, системний виклик `epoll_wait()` буде повертатися негайно у нескінченному циклі, викликаючи зациклення процесора.
