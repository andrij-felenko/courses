# 📋 Параметри завантаження для ізоляції

Щоб налаштувати ізольовані ядра з моменту завантаження, параметри передаються ядру через конфігурацію завантажувача (зазвичай GRUB, файл `/etc/default/grub`, рядок `GRUB_CMDLINE_LINUX_DEFAULT`). Усі ці параметри приймають список ядер (cpulist), наприклад `1-3` (ядра з 1 по 3) або `1,3,5`.

## `isolcpus`
Виключає вказані ядра з доменів балансування навантаження планувальника (scheduler domains).

**Синтаксис:** `isolcpus=<cpulist>`

- **Що робить:** Звичайні процеси більше не можуть потрапити на ці ядра автоматично. Ядро повністю ігнорує їх під час перерозподілу процесів (load balancing).
- **Як запустити туди процес:** Тільки явно, через встановлення affinity (`taskset -c <cpulist> ...` або `sched_setaffinity`).
- **Застереження:** З версії ядра 4.14 параметр вважається застарілим для більшості застосувань на користь контрольних груп `cpuset`, але досі залишається найпростішим і найжорсткішим інструментом для real-time застосунків.

## `nohz_full`
Вмикає режим "повністю tickless" для вказаних ядер.

**Синтаксис:** `nohz_full=<cpulist>`

- **Що робить:** Вимикає періодичні переривання від локального таймера (timer ticks), якщо на ядрі виконується лише один процес.
- **Умова роботи:** Щоб це спрацювало, ядро має бути зібране з опцією `CONFIG_NO_HZ_FULL=y`. Крім того, на ядрі не повинно бути інших процесів у черзі виконання.

## `rcu_nocbs`
Переносить виконання RCU колбеків з вказаних ядер на спеціальні фонові потоки (`rcuop`).

**Синтаксис:** `rcu_nocbs=<cpulist>`

- **Що робить:** Виключає м'які переривання (SoftIRQ) `RCU_SOFTIRQ` на цих ядрах. Замість цього ядро створює процеси `rcuop/<cpu>`, які виконують колбеки очищення. Зазвичай ці потоки `rcuop` працюють на housekeeping ядрах (для цього їхню affinity налаштовують окремо, або ядро автоматично виштовхує їх з ядер `nohz_full`).
- **Умова роботи:** Ядро має бути зібране з опцією `CONFIG_RCU_NOCB_CPU=y`.

## `irqaffinity`
Вказує маску ядер за замовчуванням для обробки апаратних переривань.

**Синтаксис:** `irqaffinity=<cpulist>`

- **Що робить:** Забороняє ядру призначати переривання від пристроїв на ядра, що НЕ входять до цього списку (тобто сюди передають список **housekeeping** ядер, а не ізольованих).
- **Альтернатива:** Найчастіше замість цього параметра використовують службу простору користувача `irqbalance`, передаючи їй список виключених ядер через конфігурацію (`IRQBALANCE_BANNED_CPUS`).

## Приклад конфігурації
Для 4-ядерної системи, де CPU 0 залишається ОС (housekeeping), а CPU 1, 2, 3 виділені під ізоляцію:
```text
GRUB_CMDLINE_LINUX_DEFAULT="... isolcpus=1-3 nohz_full=1-3 rcu_nocbs=1-3 irqaffinity=0"
```
