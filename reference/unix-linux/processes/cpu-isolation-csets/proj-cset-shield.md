# ⚙️ Використання cset shield

`cset` — це фронтенд на Python для роботи з підсистемою `cpuset` (контрольними групами cgroups). Команда `cset shield` створює абстракцію «щита» (shield) — виділеного набору ядер, захищеного від операційної системи. 

Суть у тому, що `cset shield` автоматично створює дві контрольні групи: `system` (для ОС) та `user` (для ваших задач). Усі наявні процеси системи (включно з потоками ядра, наскільки це можливо) переміщуються у групу `system`. Після цього група `user` залишається порожньою та захищеною від планування загальних задач.

## Крок 1. Створення щита

Припустимо, ми маємо 4-ядерний процесор і хочемо ізолювати ядра 1, 2 і 3. Ядро 0 залишиться для ОС.

```bash
# -c вказує ядра для щита (user)
# -k on змушує cset перемістити також і неприв'язані потоки ядра (kthreads)
sudo cset shield -c 1-3 -k on
```

Результат виконання покаже, скільки задач було переміщено з кореневої групи в групу `system`.

## Крок 2. Перевірка статусу

Щоб переконатися, що щит працює і подивитися розподіл задач:

```bash
sudo cset shield
```
Вивід покаже, що ядра 1-3 захищені («shield is active»), і виведе кількість задач у системній групі.

## Крок 3. Запуск застосунку під щитом

Щоб запустити ваш критичний застосунок на ізольованих ядрах, використовуйте прапорець `--exec`:

```bash
sudo cset shield --exec -- ./my_low_latency_app --arg1 value
```

Застосунок `my_low_latency_app` опиниться в групі `user` і матиме право виконуватися лише на ядрах 1, 2 та 3. Ніхто інший його не потурбує (якщо ви також налаштували `irqbalance` та вимкнули таймери).

Якщо ви вже маєте запущений процес і знаєте його PID (наприклад, 4242), ви можете перемістити його під щит:

```bash
sudo cset shield --shield --pid 4242
```

## Крок 4. Зняття щита

Коли експеримент закінчено або вам потрібно повернути всі ядра системі, ви можете зруйнувати щит. Усі процеси, що залишилися в групах `user` і `system`, будуть повернуті до кореневої групи (де дозволені всі ядра), а самі групи будуть видалені.

```bash
sudo cset shield --reset
```
