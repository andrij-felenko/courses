# 📋 Контракт реєстрації binfmt_misc

Один рядок, записаний у файл `register`, — це весь інтерфейс, яким простір користувача навчає ядро запускати чужий формат. Тут зібрано, що саме в тому рядку дозволено, які числа він не сміє перевищити, що робить кожен з чотирьох прапорців, що видно в `/proc/sys/fs/binfmt_misc` і в якому вигляді ті самі відомості записують у `binfmt.d` та `update-binfmts`, щоб вони пережили перезавантаження.

Усі числа й правила нижче звірено з `fs/binfmt_misc.c` та `include/uapi/linux/binfmts.h`; де поведінка залежить від версії ядра, версію названо.

## Граматика рядка

```
:name:type:offset:magic:mask:interpreter:flags
```

**Роздільник — це перший символ рядка**, а не обов'язково двокрапка. Ядро бере найперший символ запису й далі шукає саме його. Двокрапка — звичай, зручний для очей; там, де прикмета містить сам роздільник, беруть щось інше — часто `|`.

Полів сім, роздільників теж сім: по одному **перед** кожним полем. Останнє поле, `flags`, може бути порожнім — але роздільник перед ним обов'язковий. Рядок, що кінчається на `…:/usr/bin/qemu-aarch64-static`, ядро відкидає; правильний кінчається на `…-static:`.

Один завершальний символ переведення рядка дозволено, і рівно в самому кінці — тому `echo` працює як є. Будь-що інше після поля прапорців дає відмову: ядро вимагає, щоб розбір спожив запис до останнього байта.

Довжина запису мусить бути **від 11 до 1920 символів**. Нижня межа підігнана під найкоротший осмислений рядок, який має рівно одинадцять символів:

```
:a:E::b::c:
```

Ім'я `a`, тип «за розширенням», розширення `b`, інтерпретатор `c`; поля `offset` і `mask` для типу `E` пропускають, але їхні роздільники стоять на місці.

## Поля

| Поле | Порожнє можна? | Що приймає | Відмова, коли |
|---|---|---|---|
| `name` | ні | ім'я майбутнього файла в каталозі | порожнє, `.`, `..` або містить `/` |
| `type` | ні | рівно одна літера: `M` (за байтами) або `E` (за розширенням імені) | будь-що інше, або далі не роздільник |
| `offset` | так, тоді 0 | невід'ємне десяткове число — з якого байта файлу починається прикмета | від'ємне, не число, зайві символи; для типу `E` поле просто пропускають |
| `magic` | ні | байти прикмети (тип `M`) або розширення без крапки (тип `E`) | порожнє; для `E` — містить `/` |
| `mask` | так, тоді порівнюють усі біти | байти маски, **точно тієї самої довжини**, що й прикмета | довжина не збіглася з прикметою; для типу `E` поле пропускають |
| `interpreter` | ні | абсолютний шлях до програми, яку підставлять | порожнє |
| `flags` | так | літери `P`, `O`, `C`, `F` у будь-якому порядку й повторенні | будь-яка інша літера |

Прапорці ядро розбирає жадібно: читає літери, доки їх упізнає, а на першій незнайомій зупиняється. Сама зупинка ще не помилка — помилкою її робить наступна перевірка: розбір мусив дійти рівно до кінця запису. Тому `Fx` — не «прапорець `F` і трохи сміття», а просто `EINVAL`. Порядок і повтори при цьому байдужі: `FP`, `PF` і `PPF` дають той самий запис.

### Байти прикмети й маски

Байт можна написати двома способами: **сирим символом** або **екрануванням `\xNN`** — рівно дві шістнадцяткові цифри після `\x`. Одна цифра або жодної — відмова ще на розборі поля.

Три наслідки, які варто тримати в голові:

- **Роздільник усередині прикмети написати сирим не можна** — саме тому його й дозволено міняти. Або беріть інший роздільник, або пишіть цей байт як `\x3a`.
- **Інші зворотні похилі риски лишаються собою.** Ядро розгортає тільки `\xNN`; послідовність `\\` жодного особливого змісту не має й дає два байти.
- **`\x00` — цілком законна частина прикмети** (у рядку QEMU таких байтів одинадцять). А от **сирий нульовий байт**, якщо він якось потрапив у сам запис, обриває розгортання на собі: усе, що після нього, у прикмету не ввійде.

Маска працює як фільтр перед звірянням: ядро бере байт з файлу, накладає на нього байт маски й порівнює з прикметою. Одиничний біт маски означає «цей біт має збігтися», нульовий — «байдуже». Порожня маска рівносильна масці з самих `\xff`.

## Два незалежні бюджети

Обмежень насправді два, і плутати їх не варто: одне рахує **байти** прикмети в буфері ядра, друге — **символи** самого запису.

**Бюджет буфера.** Прикмету звіряють з тими байтами, які `execve` уже прочитав на самому початку; далі кінця цього буфера ядро не бачить. Тому реєстрація вимагає, щоб прикмета вміщалася в буфер цілком разом зі своїм зсувом:

```
offset + довжина_прикмети ≤ BINPRM_BUF_SIZE

BINPRM_BUF_SIZE = 128 байтів   у ядрах до 5.0 включно
BINPRM_BUF_SIZE = 256 байтів   від 5.1 (2019) і донині
```

**Бюджет запису.** Увесь рядок разом із завершальним переведенням рядка не може бути довшим за 1920 символів (`MAX_REGISTER_LENGTH`).

**Приклад: скільки з'їдає справжній рядок QEMU для AArch64.**

```
прикмета: 20 байтів, з них 3 друковані ("ELF") написано сирими
          3 × 1 + 17 × 4                            =  71 символ
маска:    20 байтів, усі екрановані
          20 × 4                                    =  80 символів
ім'я "qemu-aarch64"                                 =  12 символів
шлях "/usr/bin/qemu-aarch64-static"                 =  28 символів
тип "M", прапорець "F", сім роздільників            =   9 символів
                                              разом =  200 символів

бюджет буфера: 0 + 20 = 20 ≤ 256                    → з великим запасом
бюджет запису: 200 ≤ 1920                           → з великим запасом
```

Обидва бюджети водночас упирає лише крайній випадок, і він показовий: прикмета на всі 256 байтів **з маскою** взагалі неможлива. Навіть якщо жодного байта не вдасться написати сирим, це 256 × 4 = 1024 символи на прикмету і стільки ж на маску — 2048, тобто більше за 1920 ще до імені й шляху. Прикмета в повний буфер існує тільки без маски.

![Дві смуги обмежень: угорі бюджет буфера — offset разом із довжиною прикмети мусить уміститися в 256 байтів, унизу бюджет запису — увесь рядок register не довший за 1920 символів; рядок QEMU займає малу частку обох, а повна 256-байтова прикмета з маскою в запис не влазить](img/budgets.svg)

*Байти буфера й символи запису рахуються окремо: перше обмежує, як глибоко в файлі може лежати прикмета, друге — як багато байтів вдасться описати екрануванням.*

## Прапорці

| Прапорець | Що змінює | Від якої версії |
|---|---|---|
| `P` | *preserve argv0* — ядро не викидає початкового `argv[0]`, а **додає** шлях до файлу зайвим аргументом. Без прапорця нульовий аргумент затирають шляхом; з ним він уціліє й стає третім елементом нового `argv` | щонайменше від 2.6.32 (2009) |
| `O` | *open binary* — ядро само́ відкриває початковий файл і передає інтерпретаторові готовий дескриптор через [допоміжний вектор](book:unix-linux/auxiliary-vector), під ключем `AT_EXECFD`. Потрібен там, де файл виконуваний, але недоступний на читання | щонайменше від 2.6.32 |
| `C` | *credentials* — права й мітку безпеки нового процесу обчислюють за початковим файлом, а не за інтерпретатором ([setuid і підвищення прав](book:unix-linux/setuid-and-privilege)). **Вмикає `O` сам собою**: ядро виставляє обидва біти одним присвоєнням | щонайменше від 2.6.32 |
| `F` | *fix binary* — ядро відкриває файл інтерпретатора **у мить реєстрації** й тримає його відкритим, а на кожному запуску клонує вже відкритий файл. Шлях більше не розв'язують, тож зміна кореня чи простору монтувань на запуск не впливає | 4.8 (2016) |

Два уточнення до `P`, які мають значення для того, хто пише інтерпретатор:

- Інтерпретатор мусить знати, у якому з двох виглядів прийшли аргументи. Від версії **5.12** ядро повідомляє про це через допоміжний вектор: у значенні `AT_FLAGS` виставлено біт `AT_FLAGS_PRESERVE_ARGV0`, що дорівнює 1. У ядрах 5.11 і давніших цього біта немає — там доводиться домовлятися наперед.
- `P` не дописує аргументів у кінець — шлях до файлу лягає на початок. Без прапорця готовий масив має вигляд `[інтерпретатор, шлях_до_файлу, аргумент₁, аргумент₂, …]`, з прапорцем — `[інтерпретатор, шлях_до_файлу, початковий_argv0, аргумент₁, …]`. Тобто `P` не переставляє нічого, а лише перестає затирати.

`F` має ще один наслідок, дуже приємний на практиці: **помилковий шлях інтерпретатора виявляється відразу**. Без цього прапорця неіснуючий інтерпретатор дасться взнаки лише при першому запуску, і то оманливим `ENOENT` про начебто відсутній файл. З `F` не проходить сама реєстрація — `write` повертає ту саму помилку, яку повернуло б відкриття. Відкриває ядро при цьому в контексті того процесу, який **пише** в `register`, — з його правами й у його дереві монтувань.

## Порядок перебору

Новий запис ядро додає в **голову** внутрішнього списку, а перебирає список від голови. Отже, записи звіряють у **зворотному до реєстрації порядку: найновіший першим**. Якщо дві прикмети накривають одні й ті самі байти, спрацює та, яку зареєстрували пізніше. Це єдиний важіль пріоритету, який тут є: жодного поля «вага» рядок не має.

Порівняння для типу `M` — побайтове, від позиції `offset` у прочитаному буфері, з маскою або без. Ніякого «частково збіглося» не буває: перший же розбіжний біт відкидає запис, і перебір іде далі.

## Тип `E`: збіг за розширенням

Тип `E` — єдине місце, де рішення ухвалюють за іменем, а не за вмістом, і його правила варто знати точно:

- Розширенням вважають усе, що **після останньої крапки** в шляху. Крапки в самому полі не пишуть: реєструють `jar`, а не `.jar`.
- Порівняння — **точне й чутливе до регістру** (`strcmp`). Запис для `jar` файл `Program.JAR` не перехопить.
- Файл без жодної крапки в шляху жодному запису типу `E` не відповідає.
- Поля `offset` і `mask` для типу `E` ядро пропускає мовчки: хай там що в них стоїть, воно не діє.

## Каталог `/proc/sys/fs/binfmt_misc`

Таблиця живе у власній файловій системі; каталог `/proc/sys/fs/binfmt_misc` — лише звичне місце [монтування](book:unix-linux/mount-model), а не жорстка вимога.

```sh
mount -t binfmt_misc binfmt_misc /proc/sys/fs/binfmt_misc
```

Монтування вимагає `CAP_SYS_ADMIN` ([можливості процесу](book:unix-linux/capabilities)). У системах із systemd робити це руками зазвичай не треба: у комплекті йде юніт автоматичного монтування, і каталог з'являється при першому ж зверненні до нього — інакше `systemctl start proc-sys-fs-binfmt_misc.mount`. Від версії ядра **6.7** файлову систему дозволено монтувати всередині [простору імен користувачів](book:unix-linux/namespaces), і кожен такий простір дістає власний примірник таблиці, незалежний від хостового.

| Файл | [Режим](book:unix-linux/permission-bits) | Що з ним роблять |
|---|---|---|
| `register` | `0200`, тільки запис | пишуть рядок реєстрації; читати нічого — файл не має вмісту |
| `status` | `0644` | читають стан механізму загалом; записом керують **усіма** записами разом |
| `<name>` | `0644` | по одному на зареєстрований формат: читають опис, записом керують саме цим записом |

Керівні записи однакові для `status` і для файла-запису. Приймають рівно три значення, довжина запису — не більше трьох байтів (з дозволеним переведенням рядка):

| Запис | У файл `<name>` | У файл `status` |
|---|---|---|
| `0` | вимкнути цей запис (лишається в таблиці, але не спрацьовує) | вимкнути механізм цілком |
| `1` | увімкнути назад | увімкнути назад |
| `-1` | **видалити** цей запис і його файл | **видалити всі** записи |

Читання `status` дає одне слово — `enabled` або `disabled`. Читання файла-запису дає повний опис, у сталому порядку рядків:

```
$ cat /proc/sys/fs/binfmt_misc/qemu-aarch64
enabled
interpreter /usr/bin/qemu-aarch64-static
flags: F
offset 0
magic 7f454c460201010000000000000000000200b700
mask ffffffffffffff00fffffffffffffffffeffffff
```

Зсув друкують десятковим числом, прикмету й маску — суцільним рядком шістнадцяткових цифр у нижньому регістрі, без пробілів і без `\x`. Це зручно: `cat` показує саме те, що ядро **розгорнуло**, тож помилку в екрануванні видно з першого погляду. Для запису типу `E` замість трьох останніх рядків стоїть один:

```
extension .jar
```

Порожній рядок прапорців виглядає як `flags: ` із самим лише пробілом — це нормально.

## Помилки реєстрації

Усе, що не так у рядку, ядро повертає з `write` у файл `register`.

| Помилка | Причина |
|---|---|
| `EINVAL` | запис коротший за 11 або довший за 1920 символів; бракує роздільника; тип не `M` і не `E`; хибне ім'я; хибний `offset`; порожня прикмета; маска іншої довжини, ніж прикмета; `offset` разом із прикметою не влазить у буфер; `\x` без двох шістнадцяткових цифр; невідома літера в прапорцях; зайві символи після прапорців |
| `EEXIST` | запис із таким `name` уже є — спершу зніміть старий записом `-1` у його файл |
| `EFAULT` | буфер користувача недоступний на читання |
| `ENOMEM` | ядру не стало пам'яті |
| помилка відкриття (`ENOENT`, `EACCES`, `EISDIR`, …) | тільки з прапорцем `F`: ядро відкриває інтерпретатора одразу й повертає те, чим скінчилося відкриття |

Одна річ, якої тут навмисно немає: **існування інтерпретатора без `F` не перевіряють**. Реєстрація з шляхом на порожнє місце проходить успішно й мовчки.

## Щоб пережило перезавантаження

Таблиця живе в пам'яті ядра й зникає при вимкненні. Постійність дають два різні механізми, і на одній машині вони можуть бути обидва.

### systemd: `binfmt.d`

`systemd-binfmt.service` ([модель юнітів systemd](book:unix-linux/systemd-model)) на старті читає файли `*.conf` із чотирьох каталогів у такому порядку старшинства:

```
/etc/binfmt.d/            налаштування адміністратора — найвища перевага
/run/binfmt.d/            те, що поклали під час роботи
/usr/local/lib/binfmt.d/
/usr/lib/binfmt.d/        те, що принесли пакунки — найнижча
```

Файли з однаковим іменем перекриваються цілком: `/etc/binfmt.d/qemu.conf` заступає `/usr/lib/binfmt.d/qemu.conf`. Щоб просто **вимкнути** файл, який приніс пакунок, кладуть у `/etc/binfmt.d/` символьне посилання з тим самим іменем на `/dev/null`.

Усередині — ті самі рядки реєстрації, по одному на рядок, без жодних змін; порожні рядки й рядки, що починаються з `#` або `;`, пропускають.

```
# /etc/binfmt.d/qemu-aarch64.conf — виконувані файли AArch64 через QEMU
:qemu-aarch64:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\xb7\x00:\xff\xff\xff\xff\xff\xff\xff\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/usr/bin/qemu-aarch64-static:F
```

```
# /etc/binfmt.d/jar.conf — тип E, збіг за розширенням
:jar:E::jar::/usr/bin/jarwrapper:
```

Застосувати зміни без перезавантаження — `systemctl restart systemd-binfmt.service`. І ось тут криється пастка, про яку варто знати наперед: **зупинка юніта виконує `systemd-binfmt --unregister`, а він знімає геть усі зареєстровані формати, не лише свої.** Отже, перезапуск — це «спорожнити таблицю й розкласти те, що описано в `binfmt.d`». Усе, що хтось зареєстрував повз ці каталоги, після такого перезапуску зникає безслідно.

### Debian і Ubuntu: `update-binfmts`

Тут той самий рядок ніхто не пише руками: формат описують ключами командного рядка, а програма сама складає запис і стежить, щоб два пакунки не заявили ту саму прикмету.

```sh
# чужа архітектура: прикмета, маска, зсув і постійне відкриття інтерпретатора
update-binfmts --package qemu-user-static \
    --install qemu-aarch64 /usr/bin/qemu-aarch64-static \
    --magic '\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\xb7\x00' \
    --mask  '\xff\xff\xff\xff\xff\xff\xff\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff' \
    --offset 0 \
    --fix-binary yes

# тип E: збіг за розширенням
update-binfmts --package jarwrapper \
    --install jar /usr/bin/jarwrapper --extension jar
```

Одинарні лапки тут обов'язкові: інакше оболонка з'їсть зворотні похилі риски ще до того, як їх побачить `update-binfmts`.

Відповідність між ключами й полями рядка пряма:

| Ключ | Що задає |
|---|---|
| `--magic` | поле `magic` для типу `M` |
| `--mask` | поле `mask` |
| `--offset` | поле `offset` |
| `--extension` | поле `magic` для типу `E` (тип обирається самим цим ключем) |
| `--preserve yes` | прапорець `P` |
| `--credentials yes` | прапорці `C` (і `O` за ним) |
| `--fix-binary yes` | прапорець `F` — вимагає ядра 4.8 або новішого |
| `--package` | ім'я пакунка-власника; без нього формат вважають адміністраторським |

Дії: `--install` заводить формат, `--remove name path` знімає, `--display` показує стан, `--enable` і `--disable` вмикають та вимикають уже заведений, `--import` підхоплює описи, що їх пакунки склали в `/usr/share/binfmts/`.

## Найкоротший повний прохід

```sh
# 1. переконатися, що таблиця змонтована
mountpoint -q /proc/sys/fs/binfmt_misc || \
    mount -t binfmt_misc binfmt_misc /proc/sys/fs/binfmt_misc

# 2. завести формат: файли з розширенням .txt віддавати переглядачеві
echo ':showtext:E::txt::/usr/bin/less:' > /proc/sys/fs/binfmt_misc/register

# 3. перевірити, що ядро розгорнуло саме те, що малося на увазі
cat /proc/sys/fs/binfmt_misc/showtext
#   enabled
#   interpreter /usr/bin/less
#   flags:
#   extension .txt

# 4. спробувати в ділі (у теці, змонтованій без noexec)
printf 'привіт\n' > ./nota.txt && chmod +x ./nota.txt && ./nota.txt

# 5. тимчасово вимкнути, не втрачаючи запису
echo 0 > /proc/sys/fs/binfmt_misc/showtext

# 6. прибрати остаточно — файл зникне разом із записом
echo -1 > /proc/sys/fs/binfmt_misc/showtext
```

Кроки 2–6 вимагають права писати у файли, що належать `root`; крок 1 — ще й `CAP_SYS_ADMIN`.
