# 📋 Довідник API та параметрів sys_futex_waitv

Системний виклик `sys_futex_waitv` надає низькорівневий векторний інтерфейс ядра Linux для одночасного атомарного блокування потоку на масиві примітивів синхронізації `futex`. Цей довідник описує точні сигнатури, константи прапорців, правила вирівнювання структур у пам'яті, системні обмеження та повну специфікацію кодів помилок, необхідних для побудови власних обгорток у рантаймах мов програмування, системних бібліотеках або шарів емуляції чужих системних викликів.

## Заголовочні файли та номер системного виклику

Для здійснення системного виклику у просторі користувача необхідно підключити специфічні заголовки ядра Linux та стандартні заголовки системних викликів POSIX:

```c
#include <linux/futex.h>
#include <sys/syscall.h>
#include <unistd.h>
#include <time.h>
```

На архітектурі x86_64 системний виклик зареєстровано під номером `SYS_futex_waitv` (`449`). Оскільки стандартна бібліотека C (`glibc`) наразі не надає високорівневої обгортки у `<sys/futex.h>`, розробники використовують прямий виклик через функцію `syscall(2)`:

```c
int futex_waitv(struct futex_waitv *waiters, unsigned int nr_futexes,
                unsigned int flags, struct timespec *timeout, clockid_t clockid);
```

## Специфікація структури `futex_waitv`

Кожен елемент очікування у переданому масиві описується структурою `struct futex_waitv`, визначеною в заголовку `<linux/futex.h>`:

```c
struct futex_waitv {
        __u64 val;        /* Очікуване значення futex-змінної */
        __u64 uaddr;      /* Адреса futex-змінної у просторі користувача */
        __u32 flags;      /* Прапорці конкретного futex-об'єкта */
        __u32 __reserved; /* Зарезервовано ядром (мусить бути 0) */
};
```

### Детальний опис полів структури та поведінки ядра

Поле `val` містить 64-бітне значення, з яким ядро порівнює поточний вміст пам'яті за адресою `uaddr`. При обробці 32-бітного futex-а ядро зчитує 32 біти пам'яті користувача і порівнює їх із молодшими 32 бітами поля `val`. Якщо значення у пам'яті дорівнює `val`, ядро вважає, що умова збіглася, і додає потік до черги очікування відповідного хеш-бакета. Якщо ж вміст пам'яті відрізняється хоча б в одного елемента масиву, ядро скасовує операцію: вилучає з черг усі елементи, які вже встигло поставити, і повертає помилку `EAGAIN`. Виняток один: якщо котрийсь із уже поставлених елементів устиг бути розбудженим у цьому вікні, виклик повертає його індекс, а не помилку.

Поле `uaddr` — це 64-бітний числовий еквівалент вказівника на futex-змінну в користувацькому адресному просторі. Адреса зобов'язана бути строго вирівняною на межу розміру типу. Для стандартного `FUTEX_32` це означає вирівнювання на 4 байти (адреса кратна 4). Невирівняна адреса призводить до відмови з кодом `EINVAL`. На 32-бітних архітектурах вказівник у просторі користувача розширюється до 64 бітів із нульовим доповненням старших бітів.

Поле `flags` задає індивідуальні параметри обробки цього futex-а, такі як розмір змінної та режим приватності (scope).

Поле `__reserved` є зарезервованим для майбутніх розширень підсистеми futex2 (наприклад, для вказування специфічних порівнянь, бітових масок чи семантики `WaitAll`). Наразі ядро вимагає, щоб це поле було строго занулене (`0`). Наявність будь-якого ненульового значення у `__reserved` викликає негайну відмову системного виклику з кодом `EINVAL`.

## Прапорці індивідуальних елементів (`flags`)

Поле `flags` у кожній структурі `futex_waitv` приймає комбінацію бітових масок, що визначають тип об'єкта та спосіб обчислення ключа ядра:

### Прапорці розміру (Size Flags)
- `FUTEX_32` (`0x02`): Вказує, що `uaddr` є вказівником на 32-бітне ціле число (`uint32_t`). Це єдиний повністю підтримуваний розмір у поточних ревізіях ядра Linux; усі інші розміри (`FUTEX_8`, `FUTEX_16`, `FUTEX_64`) відхиляються ядром із кодом `EINVAL`. У 5.16 константа звалася `FUTEX_32`, у пізніших UAPI-заголовках канонічне ім'я — `FUTEX2_SIZE_U32`, а старе лишилося синонімом; те саме стосується пари `FUTEX_PRIVATE_FLAG` / `FUTEX2_PRIVATE`.

### Прапорці приватності (Scope Flags)
- `FUTEX_PRIVATE_FLAG` (`0x80`): Повідомляє ядру, що цей futex використовується виключно потоками в межах одного віртуального адресного простору (однієї групи задач `mm_struct`). Це дозволяє ядру оптимізувати обчислення хеш-ключа (використовується віртуальна адреса замість фізичної сторінки / `inode`), суттєво прискорюючи виконання за рахунок обходу важких викликів `get_user_pages()`.
- `0` (Process Shared, за замовчуванням): Якщо прапорець приватності відсутній, futex вважається спільним для кількох процесів. Ядро знаходить фізичну сторінку пам'яті та обчислює унікальний `futex_key` на основі фізичної адреси або індексу `inode`, що дозволяє синхронізувати незалежні процеси через спільну пам'ять (`shm_open`, `mmap`).

## Опис параметрів системного виклику

Параметр `waiters` є вказівником на перший елемент користувацького масиву структур `futex_waitv`. Масив повинен перебувати у дійсному адресному просторі процесу, доступному для читання ядром.

Параметр `nr_futexes` визначає кількість елементів у масиві `waiters`. В ядрі встановлено жорстке обмеження `FUTEX_WAITV_MAX = 128`. Спроба передати значення `nr_futexes > 128` або `nr_futexes == 0` повертає помилку `EINVAL`. Обмеження впроваджено для того, щоб запобігти надмірному виділенню пам'яті у ядрі та обмежити обсяг роботи, яку один системний виклик встигає накопичити, проходячи масив і по черзі захоплюючи блокування бакетів.

Параметр `flags` являє собою глобальні прапорці самого системного виклику `sys_futex_waitv`. Наразі цей параметр зарезервований і повинен строго дорівнювати `0`. Будь-яке ненульове значення спричиняє відмову `EINVAL`.

Параметр `timeout` містить вказівник на структуру `struct timespec`, яка задає абсолютний час закінчення очікування. На відміну від старого системного виклику `futex(2)`, де тайм-аут міг інтерпретуватися як відносний, у `sys_futex_waitv` значення завжди є абсолютним (час відносно обраної епохи). Передача значення `NULL` означає нескінченне очікування.

Параметр `clockid` визначає годинник для відліку абсолютного часу `timeout`. Ядро підтримує `CLOCK_MONOTONIC` (монотонний годинник системи, стійкий до зміни часу) та `CLOCK_REALTIME` (астрономічний/календарний час).

## Коди повернення та системні помилки

При успішному пробудженні системний виклик повертає ціле число в діапазоні від `0` до `nr_futexes - 1`, яке дорівнює **індексу елемента** у масиві `waiters`, чий futex спричинив пробудження потоку.

У разі помилки повертається `-1`, а змінна `errno` набуває одного з таких значень:

- **`EAGAIN`**: Значення за адресою `uaddr` принаймні для одного елемента не дорівнювало очікуваному `val` під час перевірки ядром. Потік повинен повторити перевірку у користувацькому просторі.
- **`ETIMEDOUT`**: Заданий абсолютний час `timeout` минув до того, як хоча б один futex був розбуджений.
- **`EINTR`**: Виклик було перервано доставкою сигналу процесу. Потік повинен перезапустити виклик або обробити сигнал.
- **`EINVAL`**: Неприпустиме значення `nr_futexes` (`0` або більше `128`), ненульовий глобальний `flags`, непідтримуваний `clockid` (відмінний від `CLOCK_MONOTONIC` чи `CLOCK_REALTIME`), невирівняна адреса `uaddr` або ненульове резервне поле `__reserved`.
- **`EFAULT`**: Недійсний вказівник на масив `waiters`, `timeout` або неприпустима адреса пам'яті `uaddr` (помилка мапування сторінок у просторі користувача).
