# ⚙️ Обряд у коді: `daemonize()` з трубою готовності — і та сама служба без жодного `fork`

Тут зібрано робочу функцію `daemonize()` на C — з трубою готовності, чесним звітом про помилку старту й PID-файлом, який справді щось означає, — а поруч ту саму службу, написану сучасно: без розділень, із `sd_notify` і одиницею systemd на дев'ять рядків. Мова одна: обряд складається із самих системних викликів, і будь-яка обгортка ховає рівно те, що тут треба бачити.

## Що функція мусить гарантувати

Обряд легко звести до списку викликів і так само легко зіпсувати, бо його справжня складність — не в кроках, а в тому, що між ними. Тому почнімо не з коду, а з контракту.

Після повернення `daemonize()` викликач мусить бути повноцінним демоном: поза деревом оболонки, без керуючого термінала, без права здобути новий, із власним робочим каталогом, обраною маскою прав, закритим чужим спадком дескрипторів, зайнятими номерами 0–2 і приведеним до типового станом сигналів.

І одна вимога, якої в класичних рецептах немає: **пускач мусить дізнатися правду**. Не «процес розділився», а «служба справді піднялася» — або «не піднялася, ось на якому кроці й ось із якою помилкою». Пускач — останній процес у цій історії, який ще має термінал; якщо повідомлення не віддати йому, воно не дістанеться нікому.

Звідси три ролі, які варто розрізняти від початку. **A** — той, кого запустили: він чекає й помирає з осмисленим кодом виходу. **B** — його дитина: живе кілька мікросекунд, встигає зробити `setsid()` і розділитися вдруге. **C** — онук: власне демон.

## Порядок кроків диктують три обмеження

Порядок в обряді не декоративний, і кожна перестановка ламає щось конкретне.

Труба створюється **до першого `fork`** — інакше в A і C не буде спільного дескриптора: після розділення пам'ять роз'їжджається, а таблиця дескрипторів успадковується, і саме тому кінець запису доїжджає до онука ([канал: дескриптор, у якого два кінці](book:unix-linux/pipe-and-fifo)).

`setsid()` викликається **після першого `fork`** — лідерові групи процесів він відмовляє з `EPERM`, а перше розділення гарантує, що ми не лідер.

Кінець запису труби мусить **пережити прибирання дескрипторів**. Це те місце, де рецепти з інтернету ламаються найтихіше: `close_range(3, ~0U, 0)` акуратно закриває і його теж, після чого пускач чекає вічно. Тому діапазон ріжеться на два, з діркою на потрібному номері.

І остання вимога, суто смислова: байт готовності пишеться **після справжньої ініціалізації** — після того, як конфіг прочитано, порт відкрито, права на каталог даних перевірено. Труба, у яку написали одразу після `setsid()`, — це той самий обман, тільки з додатковим кодом.

## Каркас: труба, дві розвилки, три ролі

```c
/* daemonize.c — повний обряд.
   cc -std=c11 -D_GNU_SOURCE -Wall -Wextra -c daemonize.c            */

#define _GNU_SOURCE
#include <dirent.h>
#include <errno.h>
#include <fcntl.h>
#include <poll.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/file.h>
#include <sys/stat.h>
#include <sys/syscall.h>
#include <sys/wait.h>
#include <unistd.h>

static int close_inherited_fds(int keep);   /* тіла — нижче, порядок викладу */
static int attach_dev_null(void);
static int reset_signals(void);
static int claim_pidfile(const char *path);

/* Повідомлення пускачеві. Обидва кінці — той самий бінарник,
   тож питання вирівнювання полів тут не виникає.               */
struct ready_msg {
    char tag;         /* 'R' — піднялися, 'E' — не змогли */
    int  err;         /* errno, коли tag == 'E'            */
    char stage[24];   /* назва кроку, що не вдався         */
};

static int ready_fd  = -1;   /* кінець запису; живе до сигналу готовності */
static int pidfile_fd = -1;  /* НЕ закривати: замок тримається дескриптором */

/* Єдине місце, звідки говорять у трубу. Після відповіді кінець
   закривається: пускач має побачити або повідомлення, або кінець файлу. */
static void report(char tag, int err, const char *stage)
{
    if (ready_fd < 0) return;

    struct ready_msg m;
    memset(&m, 0, sizeof m);
    m.tag = tag;
    m.err = err;
    snprintf(m.stage, sizeof m.stage, "%s", stage ? stage : "");

    (void)!write(ready_fd, &m, sizeof m);   /* ≤ PIPE_BUF — запис атомарний */
    close(ready_fd);
    ready_fd = -1;
}

void daemon_ready(void)              { report('R', 0, ""); }
void daemon_fail(const char *stage)  { report('E', errno, stage); }
```

Роль A — чекати. Уся цінність труби в тому, що `read` на ній розрізняє три різні події одним викликом: прийшло повідомлення (служба сказала своє слово), прийшов нуль байтів (усі кінці запису зникли, тобто останній їх власник помер), або ми ще чекаємо.

```c
static void parent_wait_and_exit(int rfd, pid_t mid)
{
    struct ready_msg m;
    ssize_t n;

    do {
        n = read(rfd, &m, sizeof m);
    } while (n < 0 && errno == EINTR);     /* сигнал не має ламати очікування */

    int st = 0;
    (void)waitpid(mid, &st, 0);            /* B — ще наша дитина, заберемо код */

    if (n == (ssize_t)sizeof m && m.tag == 'R')
        _exit(0);                          /* єдиний шлях до нуля */

    if (n == (ssize_t)sizeof m && m.tag == 'E')
        fprintf(stderr, "служба не піднялася на кроці «%s»: %s\n",
                m.stage, strerror(m.err));
    else if (n == 0)
        fprintf(stderr, "служба померла на старті, нічого не сказавши\n");
    else
        fprintf(stderr, "невиразна відповідь від служби\n");

    fflush(stderr);
    _exit(1);
}
```

Цикл навколо `read` тут не перестрахування: будь-який сигнал із обробником перерве блокуючий виклик, і без повтору пускач вирішить, що служба мовчить ([EINTR: перервані виклики й перезапуск](book:unix-linux/eintr-and-restart)). А `waitpid` забирає код проміжного процесу B, який на цей момент уже точно вийшов, — щоб після нас не лишилося зомбі.

Тепер сам обряд:

```c
int daemonize(const char *pidpath)
{
    int p[2];
    if (pipe(p) < 0) return -1;            /* ДО першого розділення */

    pid_t pid = fork();
    if (pid < 0) { int e = errno; close(p[0]); close(p[1]); errno = e; return -1; }

    if (pid > 0) {                         /* A: пускач */
        close(p[1]);                       /* ← без цього рядка він чекатиме вічно */
        parent_wait_and_exit(p[0], pid);   /* не повертається */
    }

    /* B: майбутній лідер сеансу */
    close(p[0]);
    ready_fd = p[1];
    fcntl(ready_fd, F_SETFD, FD_CLOEXEC);  /* щоб не протік у чужий образ */

    if (setsid() < 0)  { report('E', errno, "setsid"); _exit(1); }

    pid = fork();                          /* друге розділення */
    if (pid < 0)       { report('E', errno, "fork2");  _exit(1); }
    if (pid > 0) _exit(0);                 /* B іде; його копію труби закриє ядро */

    /* C: власне демон */
    if (chdir("/") < 0) { report('E', errno, "chdir"); _exit(1); }
    umask(0027);                           /* обрано, а не успадковано */

    if (close_inherited_fds(ready_fd) < 0) { report('E', errno, "close-fds"); _exit(1); }
    if (attach_dev_null() < 0)             { report('E', errno, "dev-null");  _exit(1); }
    if (reset_signals() < 0)               { report('E', errno, "signals");   _exit(1); }

    if (pidpath && claim_pidfile(pidpath) < 0) { report('E', errno, "pidfile"); _exit(1); }

    return 0;                              /* далі — справжня ініціалізація */
}
```

Зверніть увагу на `_exit(0)` у B. Це не примха стилю: `exit()` пройшов би по зареєстрованих обробниках завершення й злив буфери stdio — ті самі буфери, копію яких має C. Ті самі байти вийшли б двічі, а обробники — прибрати тимчасовий файл, закрити з'єднання — виконалися б у процесі, який нічого з цим не робив ([буферизація stdio і чому вона переживає fork](book:unix-linux/stdio-buffering)).

Маска `0027` — приклад, а не догма; важить те, що число обрано явно.

## Прибирання спадку

Дескриптори — найтонше місце, і воно ж єдине, де потрібен запасний шлях: `close_range` з'явився в ядрі Linux 5.9 (обгортка в glibc — з версії 2.34), і на старіших системах його просто немає. Щоб не залежати від версії бібліотеки, кличемо системний виклик напряму:

```c
#if defined(__linux__) && defined(SYS_close_range)
static int try_close_range(unsigned lo, unsigned hi)
{
    return (int)syscall(SYS_close_range, lo, hi, 0u);
}
#else
static int try_close_range(unsigned lo, unsigned hi)
{ (void)lo; (void)hi; errno = ENOSYS; return -1; }
#endif

/* Обхід /proc/self/fd — точний список, без вгадування стелі. */
static void close_fds_via_proc(int lo, int keep)
{
    DIR *d = opendir("/proc/self/fd");
    if (!d) {                                  /* немає /proc — лишається вгадувати */
        long max = sysconf(_SC_OPEN_MAX);
        if (max < 0 || max > 65536) max = 65536;
        for (int fd = lo; fd < (int)max; fd++)
            if (fd != keep) (void)close(fd);
        return;
    }
    int dfd = dirfd(d);                         /* його закривати не можна: ще читаємо */
    struct dirent *e;
    while ((e = readdir(d)) != NULL) {
        char *end;
        long fd = strtol(e->d_name, &end, 10);
        if (*end != '\0') continue;             /* «.» і «..» */
        if (fd < lo || fd == dfd || fd == keep) continue;
        (void)close((int)fd);
    }
    closedir(d);
}

/* Дірка на keep — інакше ми закриємо власну трубу готовності. */
static int close_inherited_fds(int keep)
{
    if (keep < 3) { errno = EINVAL; return -1; }

    if (keep > 3 && try_close_range(3u, (unsigned)keep - 1) < 0) goto fallback;
    if (try_close_range((unsigned)keep + 1, ~0u) < 0)            goto fallback;
    return 0;

fallback:
    if (errno != ENOSYS && errno != EPERM && errno != EINVAL) return -1;
    close_fds_via_proc(3, keep);
    return 0;
}
```

Обхід `/proc/self/fd` кращий за наївний цикл до `sysconf(_SC_OPEN_MAX)` з простої причини: він перелічує **справді відкриті** номери, а не пробує закрити мільйон неіснуючих. Різниця помітна, коли ліміт на дескриптори підняли до сотень тисяч — цикл тоді робить сотні тисяч марних викликів у ядро.

Далі — три стандартні номери. Тут є нюанс, який рятує від цілого класу помилок: номери 0–2 ми **не закриваємо**. Прибирання почалося з трійки, тож термінал на них ще висить, і перший же `open` дістане номер 3 або 4 — а не нуль. Дірки, у яку могли б провалитися стандартні потоки, не існує ані на мить.

```c
static int attach_dev_null(void)
{
    int fd = open("/dev/null", O_RDWR);
    if (fd < 0) return -1;

    if (dup2(fd, STDIN_FILENO)  < 0) return -1;
    if (dup2(fd, STDOUT_FILENO) < 0) return -1;
    if (dup2(fd, STDERR_FILENO) < 0) return -1;   /* dup2 сам закриє старе */

    if (fd > STDERR_FILENO) close(fd);
    return 0;
}
```

Сигнали приводимо до типового стану — і одразу ставимо своє:

```c
static int reset_signals(void)
{
    struct sigaction sa;
    memset(&sa, 0, sizeof sa);
    sa.sa_handler = SIG_DFL;
    sigemptyset(&sa.sa_mask);

    for (int s = 1; s < NSIG; s++)
        (void)sigaction(s, &sa, NULL);   /* SIGKILL і SIGSTOP відмовлять — це нормально */

    sigset_t empty;
    sigemptyset(&empty);
    if (sigprocmask(SIG_SETMASK, &empty, NULL) < 0) return -1;

    sa.sa_handler = SIG_IGN;             /* обірваний співрозмовник — не привід умирати */
    if (sigaction(SIGPIPE, &sa, NULL) < 0) return -1;

    return 0;
}
```

Цикл від 1 до `NSIG` навмисно не перевіряє кодів повернення: на двох сигналах він мусить дістати `EINVAL`, і це очікувано. Скидати треба **і диспозиції, і маску**: ігнорування та заблоковані сигнали переживають розділення, а `SIG_IGN` переживає ще й заміну образу — тобто чужий скрипт, який колись заблокував `SIGTERM`, здатний зробити вашу службу нечутливою до команди зупинки ([диспозиція сигналу: обробник, ігнорування, типова дія](book:unix-linux/signal-disposition)).

## PID-файл, який справді щось означає

Звичайний PID-файл — це рядок із числом, і всі його біди від того, що число не пов'язане з процесом нічим, крім домовленості. Замок пов'язаний: його тримає ядро, і воно ж його відпускає.

```c
static int claim_pidfile(const char *path)
{
    int fd = open(path, O_RDWR | O_CREAT | O_CLOEXEC, 0644);
    if (fd < 0) return -1;

    /* Ось тут і вирішується, чи ми єдиний примірник. */
    if (flock(fd, LOCK_EX | LOCK_NB) < 0) {      /* EWOULDBLOCK — хтось уже живий */
        int e = errno; close(fd); errno = e; return -1;
    }

    if (ftruncate(fd, 0) < 0) goto fail;         /* старе число могло бути довшим */

    char buf[32];
    int n = snprintf(buf, sizeof buf, "%ld\n", (long)getpid());
    if (write(fd, buf, (size_t)n) != n) goto fail;

    pidfile_fd = fd;      /* ⚠️ дескриптор лишається відкритим НАЗАВЖДИ */
    return 0;

fail: {
    int e = errno; close(fd); errno = e; return -1;
    }
}
```

Три деталі, кожна з наслідком.

**Дескриптор тримають відкритим**, бо замок `flock` належить не файлу й не процесові, а **опису відкритого файлу** — тій внутрішній структурі ядра, яку створює `open` ([опис відкритого файлу: що спільне після fork](book:unix-linux/open-file-description)). Замок зникає рівно тоді, коли зникає останній дескриптор, що на цей опис указує, — а при смерті процесу ядро закриває їх усі. Тому «чи взявся замок» і є питанням «чи живий примірник», без жодного окремого прибирання ([блокування файлів](book:unix-linux/file-locking)).

**`ftruncate` перед записом**, бо файл відкрито без `O_TRUNC` — обрізати його до перевірки замка означало б зіпсувати чужий файл, якщо примірник уже працює.

**`O_CLOEXEC`** — щоб замок не поїхав у дочірні процеси. Наслідок протікання неприємний і неочевидний: помічник, породжений службою, успадкував би той самий опис відкритого файлу, а отже й замок; служба вмирає, помічник живе — і новий примірник не може стартувати, бо замок нібито зайнятий. Проти `fork` без заміни образу `O_CLOEXEC` не рятує, тож такі дочірні процеси мусять закривати `pidfile_fd` явно.

## Складання докупи

```c
/* main.c — служба, яка вміє обидва режими.
   cc -std=c11 -D_GNU_SOURCE -o echod main.c daemonize.c              */

#include <syslog.h>

int daemonize(const char *pidpath);
void daemon_ready(void);
void daemon_fail(const char *stage);

int main(int argc, char **argv)
{
    int background = !(argc > 1 && strcmp(argv[1], "--foreground") == 0);

    if (background && daemonize("/run/echod.pid") < 0) {
        perror("daemonize");
        return 1;
    }

    int lsock = listen_on(9000);          /* СПРАВЖНЯ ініціалізація */
    if (lsock < 0) {
        daemon_fail("listen");            /* помилка їде в трубу, до термінала */
        return 1;
    }

    openlog("echod", LOG_PID, LOG_DAEMON);
    syslog(LOG_INFO, "піднялися, слухаємо 9000");

    daemon_ready();                       /* аж ТЕПЕР пускач виходить із нулем */

    serve_forever(lsock);                 /* головний цикл */
    return 0;
}
```

Ключ `--foreground` тут не для зручності налагодження, а тому, що з ним ту саму програму можна запхати під менеджер служб без `Type=forking`. Практично кожен пакувальник шукає в чужому демоні саме такий ключ — варто його мати.

Перевірити роботу можна, не чекаючи журналів: `./echod; echo $?` віддає нуль лише тоді, коли порт справді відкрито, а якщо порт зайнято — виводить у термінал рядок про `listen` і `EADDRINUSE` і повертає одиницю. Саме цього від демона неможливо було домогтися без труби ([код виходу як інтерфейс програми](book:unix-linux/exit-status)).

## Та сама служба «по-новому»

А тепер те, заради чого варто було все це прочитати, — той самий бінарник, написаний під менеджер служб.

```c
/* echod.c — жодного розділення.
   cc -std=c11 -o echod echod.c $(pkg-config --libs libsystemd)       */

#include <systemd/sd-daemon.h>

static volatile sig_atomic_t stop_flag = 0;

static void on_term(int sig) { (void)sig; stop_flag = 1; }

int main(void)
{
    struct sigaction sa;
    memset(&sa, 0, sizeof sa);
    sa.sa_handler = on_term;
    sigemptyset(&sa.sa_mask);
    sigaction(SIGTERM, &sa, NULL);        /* БЕЗ SA_RESTART — свідомо */

    sa.sa_handler = SIG_IGN;
    sigaction(SIGPIPE, &sa, NULL);

    int lsock = listen_on(9000);
    if (lsock < 0) {
        fprintf(stderr, "listen: %s\n", strerror(errno));   /* stderr → журнал */
        return 1;
    }
    fprintf(stderr, "піднялися, слухаємо 9000\n");

    sd_notify(0, "READY=1");              /* те саме, що байт у трубу */

    while (!stop_flag)
        serve_once(lsock);                /* accept() поверне EINTR при SIGTERM */

    sd_notify(0, "STOPPING=1");
    close(lsock);
    return 0;
}
```

Обробник поставлено **без** `SA_RESTART` навмисно: інакше ядро саме перезапустило б перерваний `accept()`, прапорець ніхто б не перевірив, і служба стояла б у чеканні до примусового `SIGKILL` за таймаутом. Це рівно та деталь, через яку служби «не зупиняються по-хорошому».

Одиниця, яка робить решту:

```ini
[Unit]
Description=Ехо-служба

[Service]
Type=notify
ExecStart=/usr/local/bin/echod
WorkingDirectory=/var/lib/echod
UMask=0027
User=echod
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Відповідність рядок у рядок видно одразу:

```
перший fork  + setsid    →  менеджер сам народжує службу в чистому сеансі
другий fork              →  керуючого термінала немає взагалі, здобувати нічого
chdir("/")               →  WorkingDirectory=
umask(0027)              →  UMask=
close_inherited_fds()    →  менеджер не передає нічого зайвого
/dev/null на 0,1,2       →  0 → /dev/null, 1 і 2 → журнал (типово)
скидання сигналів        →  служба стартує з типовим станом сигналів
PID-файл із замком       →  головний процес відомий менеджерові за походженням
write(pipe, "R", 1)      →  sd_notify(0, "READY=1")
```

Приблизно двісті рядків обережного коду проти дев'яти рядків налаштування — і жодного з описаних нижче способів вистрелити собі в ногу. `READY=1` менеджер слухає тільки при `Type=notify` (або `notify-reload`); зі `simple` повідомлення просто ігнорується, а служба вважається піднятою одразу після запуску ([життєвий цикл служби й політика перезапуску](book:unix-linux/service-lifecycle)).

Ще одна річ, помітна лише в порівнянні: `sd_notify` повертає нуль, якщо змінної `NOTIFY_SOCKET` в оточенні немає. Тобто той самий бінарник, запущений із рук, працює без жодних умовних гілок — просто нікому не звітує.

## Пастки

**Забутий `close(p[1])` у пускача.** Кінець файлу на трубі настає, коли зникає **останній** відкритий кінець запису. Пускач тримає свою копію — отже, кінця файлу не буде ніколи, навіть коли демон давно помер. Симптом: команда запуску висить, `Ctrl+C` її знімає, служби немає. Той самий рядок, забутий у B перед довгою роботою, дав би те саме.

**Кінець запису, зрізаний прибиранням дескрипторів.** `close_range(3, ~0U, 0)` одним рухом закриває і трубу. Симптом ідентичний попередньому — пускач висить, — але причина протилежна: не «зайвий кінець живий», а «потрібний мертвий». Різниця в тому, що тут висіння настає лише на ядрах ≥ 5.9, бо на старих спрацьовує запасний шлях, який трубу зберігає. Тому дірка в діапазоні — не оптимізація, а обов'язковий рядок.

**Запис у трубу до ініціалізації.** Готовність починає брехати, і бреше вибірково: під навантаженням залежні служби стартують за мілісекунди й натикаються на ще не відкритий порт, а на порожній машині все працює. Це та порода помилок, яку неможливо відтворити на робочому місці розробника.

**`exit()` замість `_exit()` у A та B.** Розділення копіює буфери stdio разом із рештою пам'яті. Якщо в буфері лежав недописаний рядок, `exit()` у батька виведе його — і `exit()` у дитини виведе його ж. Плюс обробники, зареєстровані через `atexit`, виконаються в кожному процесі окремо: видалення тимчасового файлу, звільнення замка, запис до журналу «завершуємо роботу» — усе по два рази. `_exit()` не робить ні першого, ні другого.

**Помилка, віддана одним байтом.** Труба, яка вміє сказати лише «не вдалося», повертає пускачеві рівно ту саму інформацію, що й код виходу без труби. Структура з `errno` і назвою кроку перетворює висіння на діагноз — і віддає його єдиному процесові, який ще має термінал. Різниця між «служба не стартувала» і «на кроці `pidfile` дістали `EACCES`» — це різниця між годиною й хвилиною.

**Пускач без таймауту.** Якщо демон завис усередині ініціалізації — чекає на мережеву файлову систему, наприклад, — він і живий, і не готовий, тож `read` не поверне нічого. Лікується очікуванням із межею:

```c
struct pollfd pfd = { .fd = rfd, .events = POLLIN };
int r = poll(&pfd, 1, 30000);            /* 30 секунд на підйом */
if (r == 0) {
    kill(mid, SIGTERM);                  /* не піднявся — і не мовчатиме далі */
    fprintf(stderr, "служба не озвалася за 30 с\n");
    _exit(1);
}
```

**`kill(pid, 0)` замість замка.** Перевірка існування процесу за номером не заміняє блокування з трьох незалежних причин. Перша: між перевіркою й записом є проміжок, за який другий примірник устигає зробити ту саму перевірку — обидва вирішать, що вільно. Друга: номери процесів перевикористовуються, і за номер із застарілого файлу згодом візьметься чужа програма, якій ваш скрипт зупинки надішле `SIGTERM`. Третя, тонша: `kill(pid, 0)` із помилкою `EPERM` означає «процес існує, але не ваш» — код, що вважає мертвим усе, крім успіху, помиляється саме на цьому випадку, а мертвим слід вважати лише `ESRCH`. Замок не має жодної з цих вад: його перевірка й узяття — одна атомарна операція, а знімає його ядро.

**Закритий `pidfile_fd`.** Акуратний програміст, побачивши відкритий дескриптор, який ніде більше не вживається, закриває його — і разом із ним замок. Файл лишається, число в ньому правильне, усе виглядає справним, а другий примірник спокійно стартує поверх першого. Коментар біля цього рядка — не ввічливість, а частина коду.
