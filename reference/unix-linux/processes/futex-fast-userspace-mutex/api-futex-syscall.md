# 📋 Системний інтерфейс Futex та futex2

Цей довідник описує повний контракт системних викликів `sys_futex` та `sys_futex_waitv`, деталізуючи сигнатури функцій, описи кодових операцій, прапорців модифікації, внутрішніх структур даних ядра та кодів помилок операційної системи Linux.

## Сигнатури системних викликів та передача аргументів

У ядрі Linux підсистема Futex надається двома основними системними викликами: класичним низькорівневим `sys_futex` та новим векторним викликом `sys_futex_waitv`, введеним у версії ядра Linux 5.16.

```c
#include <linux/futex.h>
#include <sys/syscall.h>
#include <unistd.h>
#include <time.h>

// Класичний системний виклик futex (номер виклику SYS_futex)
long syscall(SYS_futex, uint32_t *uaddr, int op, uint32_t val,
             const struct timespec *timeout, uint32_t *uaddr2, uint32_t val3);

// Векторний системний виклик futex2 (номер виклику SYS_futex_waitv)
long syscall(SYS_futex_waitv, struct futex_waitv *waiters, unsigned int nr_futexes,
             unsigned int flags, struct timespec *timeout, clockid_t clockid);
```

### Детальний розбір аргументів `sys_futex`

Кожен параметр системного виклику `sys_futex` виконує строго визначену роль залежно від переданої операції:

1. **`uaddr` (User Address)**: Основна адреса 32-бітної цілочисельної змінної (`uint32_t`) у просторі пам'яті користувача. Адреса обов'язково повинна бути вирівняна за кордоном 4 байтів (`uaddr % 4 == 0`). Передана адреса перевіряється функцією ядра `access_ok()`. Якщо адреса вказує на недоступну область пам'яті, ядро миттєво повертає помилку `EFAULT`.
2. **`op` (Operation & Flags)**: Ціле число, що містить базовий код операції у нижніх 7 бітах (наприклад, `FUTEX_WAIT`, `FUTEX_WAKE`) та прапорці модифікації у старших бітах (`FUTEX_PRIVATE_FLAG`, `FUTEX_CLOCK_REALTIME`).
3. **`val` (Value / Count)**: Значення з подвійним семантичним змістом. Для операцій очікування (`FUTEX_WAIT`) це очікуване значення futex-змінної, з яким порівнюється поточне значення в пам'яті. Для операцій пробудження (`FUTEX_WAKE`) це максимальна кількість потоків, яку ядро повинно розбудити.
4. **`timeout` (Timeout / Value 2)**: Указник на структуру `struct timespec`. Для операцій `FUTEX_WAIT` та `FUTEX_WAIT_BITSET` вказує тривалість очікування. За замовчуванням тайм-аут інтерпретується як відносний інтервал часу. У викликах `FUTEX_REQUEUE` цей параметр перевизначається і кастується ядром у ціле число `val2` (кількість потоків для перепідключення).
5. **`uaddr2` (Secondary Address)**: Друга адреса futex-змінної у просторі користувача. Використовується в операціях перепідключення черг (`FUTEX_REQUEUE`, `FUTEX_CMP_REQUEUE`), а також в операціях атомарної модифікації двох змінних (`FUTEX_WAKE_OP`). Адреса також має бути 32-бітно вирівняною.
6. **`val3` (Bitset / Value 3)**: Додаткове ціле число. Використовується як бітова маска для порівняння у бітсет-операціях (`FUTEX_WAIT_BITSET`), або як очікуване значення контрольного порівняння у `FUTEX_CMP_REQUEUE`.

## Коди операцій (`futex_op`) та їхня семантика

Операція `op` передається у системний виклик як бітова комбінація базового коду та прапорців модифікації.

### Основні операції синхронізації

1. **`FUTEX_WAIT` (Код `0`)**:
   Ядро атомарно перевіряє, чи значення за адресою `*uaddr` дорівнює очікуваному `val`. Якщо значення збігається, потік додається до черги очікування `futex_hash_bucket` і переводиться у стан `TASK_INTERRUPTIBLE`. Якщо значення за адресою `uaddr` змінилося до виконання перевірки, виклик негайно переривається з помилкою `EWOULDBLOCK`. Якщо вказано `timeout` і час вичерпано, повертається `ETIMEDOUT`.

2. **`FUTEX_WAKE` (Код `1`)**:
   Ядро шукає заблоковані потоки у глобальній хеш-таблиці, асоційовані з адресою `uaddr`. Пробуджується щонайбільше `val` потоків (зазвичай `val = 1` для м'ютексів або `val = INT_MAX` для розсилки всім). Системний виклик повертає точну кількість реально розбуджених потоків.

3. **`FUTEX_REQUEUE` (Код `3`)**:
   Здійснює пробудження `val` потоків, що очікують на `uaddr`. Якщо кількість очікуючих потоків перевищує `val`, ядро вилучає решту потоків (до межі `val2`, переданої в параметрі `timeout`) з черги `uaddr` і переміщує їх безпосередньо у чергу очікування за адресою `uaddr2`.

4. **`FUTEX_CMP_REQUEUE` (Код `4`)**:
   Атомарно перевіряє, чи поточне значення `*uaddr == val3`. Якщо умова виконується, ядро розбуджує `val` потоків на `uaddr` і переміщує до `val2` очікуючих потоків із черги `uaddr` до черги `uaddr2`. Якщо значення `*uaddr != val3`, перепідключення не відбувається, і виклик повертає помилку `EWOULDBLOCK`. Ця операція є основою умовної змінної в бібліотеці NPTL.

5. **`FUTEX_WAKE_OP` (Код `5`)**:
   Дозволяє атомарно змінити значення другої адреси `*uaddr2` згідно з арифметичною або логічною інструкцією, закодованою у параметрі `val3`, розбудити `val` потоків на `uaddr` і, якщо результат операції над `uaddr2` задовільняє умову, розбудити додаткові `val2` потоків на `uaddr2`.

### Операції розширеного набору та бітсетів

1. **`FUTEX_WAIT_BITSET` (Код `9`)**:
   Працює аналогічно до `FUTEX_WAIT`, але потік при блокуванні реєструє 32-бітну маску `val3`. Окрім цього, на відміну від `FUTEX_WAIT`, параметр `timeout` у цій операції інтерпретується ядром як **абсолютний час** (Absolute Time), що запобігає дрейфу часу при повторних викликах.

2. **`FUTEX_WAKE_BITSET` (Код `10`)**:
   Ядро шукає потоки, заблоковані на адресі `uaddr`, але розбуджує лише ті потоки, у яких результат побітового AND між маскою виклику `val3` та маскою очікуючого потоку не дорівнює нулю (`(mask1 & mask2) != 0`). Якщо передано `FUTEX_BITSET_MATCH_ANY` (`0xffffffff`), розбуджуються всі потоки незалежно від їхніх масок.

### Операції підтримки Priority Inheritance (PI)

1. **`FUTEX_LOCK_PI` (Код `6`)**:
   Використовується для захоплення м'ютекса з підтримкою інверсії пріоритетів. Якщо м'ютекс зайнятий, ядро прив'язує його до внутрішнього об'єкта `rt_mutex` і тимчасово підвищує пріоритет поточного власника м'ютекса до пріоритету найвищого очікуючого потоку.

2. **`FUTEX_UNLOCK_PI` (Код `7`)**:
   Звільняє PI-м'ютекс. Ядро атомарно віддає права власності наступному за пріоритетом потоку у черзі `rt_mutex` та відновлює початковий пріоритет попереднього власника.

3. **`FUTEX_TRYLOCK_PI` (Код `8`)**:
   Спроба атомарно захопити PI-м'ютекс у просторі користувача. Якщо м'ютекс зайнятий, виклик негайно повертає помилку без засинання у ядрі.

## Прапорці модифікації операцій

Прапорці додаються до значення `op` за допомогою побітового логічного OR (`|`):

```c
#define FUTEX_PRIVATE_FLAG        128
#define FUTEX_CLOCK_REALTIME      256
#define FUTEX_CMD_MASK            ~(FUTEX_PRIVATE_FLAG | FUTEX_CLOCK_REALTIME)
```

### 1. `FUTEX_PRIVATE_FLAG` (Біт `0x80`)
Інформує ядро про те, що futex-змінна використовується виключно між потоками одного й того ж процесу й не розташована у розділюваній пам'яті (shared memory).
- **Механізм прискорення**: При встановленому прапорці ядро не здійснює пошук фізичної сторінки RAM через `get_user_pages_fast()`. Ключем очікування стає комбінація віртуальної адреси `uaddr` та вказівника на структуру пам'яті процесу `mm_struct`. Це зменшує накладні витрати повільного шляху ядра на 20-30%.

### 2. `FUTEX_CLOCK_REALTIME` (Біт `0x100`)
Вказує ядром інтерпретувати параметр `timeout` як абсолютний час за системним астрономічним годинником `CLOCK_REALTIME` (з урахуванням корекцій NTP та стрибків часу), замість монотонного годинника `CLOCK_MONOTONIC`.

## Векторний системний виклик `sys_futex_waitv` (futex2)

Введений у ядрі Linux 5.16 системний виклик `sys_futex_waitv` вирішує проблему очікування на масиві примітивів синхронізації (аналог `WaitForMultipleObjects` у Windows API).

### Сигнатура та параметри `sys_futex_waitv`

```c
long syscall(SYS_futex_waitv, struct futex_waitv *waiters, unsigned int nr_futexes,
             unsigned int flags, struct timespec *timeout, clockid_t clockid);
```

- **`waiters`**: Указник на масив структур `struct futex_waitv`.
- **`nr_futexes`**: Кількість елементів у масиві (від 1 до `FUTEX_WAITV_MAX`, за замовчуванням максимум 128 елементів).
- **`flags`**: Загальні прапорці системного виклику (наразі має бути `0`).
- **`timeout`**: Вказівник на структуру `struct timespec` для тайм-ауту очікування.
- **`clockid`**: Годинник для розрахунку часу (`CLOCK_MONOTONIC` або `CLOCK_REALTIME`).

### Структура `struct futex_waitv`

```c
struct futex_waitv {
    uint64_t val;         /* Очікуване значення futex-змінної */
    uint64_t uaddr;       /* Віртуальна адреса futex-змінної у юзерспейсі */
    uint32_t flags;       /* Прапорці розміру та приватного стану futex */
    uint32_t __reserved;  /* Зарезервовано ядром (має бути 0) */
};
```

### Прапорці елемента `futex_waitv.flags`

- **`FUTEX_32` (`0x2`)**: Вказує на 32-бітну розмірність futex-змінної.
- **`FUTEX_PRIVATE_FLAG` (`0x80`)**: Вказує, що відповідна змінна є приватною для процесу.

### Повертане значення `sys_futex_waitv`

- **При успіху**: повертає 0-базовий індекс елемента (від `0` до `nr_futexes - 1`) у масиві `waiters`, чий стан змінився й спричинив пробудження потоку.
- **При тайм-ауті**: повертає `-1` та встановлює `errno = ETIMEDOUT`.
- **При помилці**: повертає `-1` та встановлює відповідний код помилки в `errno`.

## Детальний розбір кодів помилок (`errno`)

1. **`EWOULDBLOCK` / `EAGAIN` (Код `11`)**:
   Виникає під час виконання `FUTEX_WAIT` або `FUTEX_CMP_REQUEUE`, якщо поточне значення за адресою `*uaddr` не збігається з очікуваним значенням `val` (або `val3`). Це свідчить про те, що стан ресурсу змінився безпосередньо перед викликом ядра. Програма у юзерспейсі повинна повторити атомарну перевірку й спробу захоплення.

2. **`ETIMEDOUT` (Код `110`)**:
   Заданий інтервал очікування `timeout` вичерпано до того, як futex-змінна була розбуджена операцією `FUTEX_WAKE` або перепідключена.

3. **`EFAULT` (Код `14`)**:
   Переданий указник `uaddr`, `uaddr2`, `timeout` або `waiters` вказує на недійсний простір віртуальних адрес, або під час зчитування значення з юзерспейсу виник помилковий Page Fault.

4. **`EINVAL` (Код `22`)**:
   Виникає у разі невірно заданих параметрів:
   - Адреса `uaddr` або `uaddr2` не вирівняна за кордоном 4 байтів (`uaddr % 4 != 0`).
   - Передано невідомий код операції `op` або непідтримувані прапорці.
   - Значення `timeout` містить від'ємні наносекунди або секунди.
   - Для `sys_futex_waitv`: значення `nr_futexes` дорівнює 0 або перевищує межу `FUTEX_WAITV_MAX`.

5. **`EOWNERDEAD` (Код `130`)**:
   Стосується Robust та PI futex: потік-власник аварійно завершив роботу, утримуючи м'ютекс. Ядро перепланувало м'ютекс на новий потік і встановило прапорець `FUTEX_OWNER_DIED`. Новий власник повинен відновити узгодженість даних і викликати `pthread_mutex_consistent()`.

6. **`ENOTRECOVERABLE` (Код `131`)**:
   Robust futex було залишено у пошкодженому стані після того, як попередній власник помер, і потік не відновив цілісність даних перед викликом звільнення.

7. **`ENOSYS` (Код `38`)**:
   Системний виклик не реалізовано у цій версії ядра (наприклад, виклик `sys_futex_waitv` на ядрах, давніших за 5.16).

## Вимоги до вирівнювання пам'яті та атомарності

Для забезпечення коректної роботи підсистеми Futex на рівні апаратного забезпечення процесора діють суворі правила:

1. **Апаратне вирівнювання (Alignment)**: Адреса `uaddr` обов'язково повинна бути вирівняна за 4-байтовою межею у пам'яті (`uaddr % 4 == 0`). Невирівняний доступ до пам'яті при виконанні атомарних інструкцій процесора викликає апаратне виключення Alignment Fault на архітектурах RISC (ARM, MIPS, RISC-V) або призводить до збою шинного блокування на x86.
2. **Вимоги до когерентності кешу**: Усі маніпуляції з futex-змінною у просторі користувача повинні здійснюватися виключно через атомарні інструкції з гарантією когерентності кеш-ліній (MESI/MOESI protocol). Будь-який неатомарний запис у futex-змінну створює Data Race і ламає внутрішню логіку очікування ядра.
