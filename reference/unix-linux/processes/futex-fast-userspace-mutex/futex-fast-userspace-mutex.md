# Futex (Fast Userspace Mutex)

Futex (від *Fast Userspace Mutex*) — це базова концепція і механізм синхронізації в операційній системі Linux, що дозволяє створювати примітиви блокування (наприклад, `pthread_mutex` або семафори) у просторі користувача. Головна ідея futex полягає в оптимізації продуктивності: якщо конкуренції (contention) за ресурс немає, захоплення або звільнення м'ютекса відбувається лише за допомогою швидких атомарних операцій процесора на рівні користувацького простору, без дорогих системних викликів. Системний виклик здійснюється лише тоді, коли необхідно перевести потік у стан очікування (заблокувати) або розбудити інші потоки.

## Принцип роботи

В основі futex лежить 32-бітне ціле число в спільній (shared) пам'яті (між потоками або навіть різними процесами). Це число репрезентує стан м'ютекса (наприклад, `0` — вільний, `1` — зайнятий). Потоки виконують атомарні операції, такі як *Compare-And-Swap (CAS)*, з цією змінною.

Якщо операція вдається (наприклад, потік успішно змінює `0` на `1`), потік продовжує виконання. Якщо ж змінна вже зайнята, потік використовує системний виклик `futex()`, щоб повідомити ядро, що він хоче "заснути", доки значення цієї змінної не зміниться.

### FUTEX_WAIT та FUTEX_WAKE

Усі маніпуляції з futex-змінною на рівні ядра виконуються через системний виклик `futex(int *uaddr, int futex_op, int val, ...)`. Основними операціями (параметр `futex_op`) є:

1. **`FUTEX_WAIT`**: Ядро атомарно перевіряє, чи значення за адресою `uaddr` все ще дорівнює `val`. Якщо так, ядро переводить потік у стан очікування (блокує). Якщо значення вже змінилося (наприклад, інший потік звільнив м'ютекс прямо перед викликом `FUTEX_WAIT`), системний виклик миттєво повертається з помилкою `EWOULDBLOCK`. Це необхідно, щоб уникнути проблеми "втраченого пробудження" (lost wakeup).
2. **`FUTEX_WAKE`**: Пробуджує вказану кількість потоків (передається як параметр), що очікують на адресі `uaddr`.

## futex2 (sys_futex_waitv)

У версії ядра Linux 5.16 було введено нове сімейство системних викликів під умовною назвою `futex2`. Найпомітнішим доповненням став системний виклик `sys_futex_waitv`. Цей виклик дозволяє одному потоку очікувати на кількох futex'ах одночасно (концептуально подібно до системних викликів `select` або `poll`, але для примітивів синхронізації futex). 

Ця можливість значно підвищує ефективність у складних сценаріях паралельного виконання. Наприклад, вона активно використовується в шарах сумісності (таких як Wine та Proton) для оптимізації продуктивності багатопотокових ігор Windows на Linux, дозволяючи точніше імітувати поведінку Windows API.

## Підтримка pthread_mutex

Стандартна реалізація POSIX потоків (`pthreads`) у бібліотеці `glibc` (а саме NPTL - Native POSIX Thread Library) використовує `futex` як фундаментальний будівельний блок для своїх механізмів синхронізації: `pthread_mutex`, `pthread_cond` (умовні змінні), семафорів тощо. 

- Коли програма викликає `pthread_mutex_lock()`, спочатку виконується спроба захоплення за допомогою атомарної операції у просторі користувача. Тільки якщо м'ютекс уже захоплений іншим потоком, `glibc` звертається до ядра з `FUTEX_WAIT`, щоб перевести поточний потік у стан сну.
- При виклику `pthread_mutex_unlock()` відбувається атомарне звільнення м'ютекса. Якщо прапорець стану вказує на те, що інші потоки заблоковані і чекають, виконується виклик `FUTEX_WAKE`, щоб розбудити їх.

## Приклад коду

:::tabs
== C (Низькорівневий Futex)
```c
#include <linux/futex.h>
#include <sys/syscall.h>
#include <unistd.h>
#include <stdatomic.h>
#include <stdio.h>

// Системна обгортка для futex_wait
int futex_wait(int *uaddr, int val) {
    return syscall(SYS_futex, uaddr, FUTEX_WAIT, val, NULL, NULL, 0);
}

// Системна обгортка для futex_wake
int futex_wake(int *uaddr, int count) {
    return syscall(SYS_futex, uaddr, FUTEX_WAKE, count, NULL, NULL, 0);
}

// Примітивний м'ютекс на базі futex
atomic_int mutex = 0; // 0 - вільний, 1 - зайнятий, 2 - зайнятий з очікуючими потоками

void lock() {
    int c = 0;
    // Спроба захопити вільний м'ютекс (атомарна зміна 0 -> 1)
    if (atomic_compare_exchange_strong(&mutex, &c, 1)) {
        return; // Захоплено швидко, без системного виклику
    }
    
    // Якщо м'ютекс зайнятий, очікуємо в ядрі
    while (atomic_exchange(&mutex, 2) != 0) {
        futex_wait((int*)&mutex, 2);
    }
}

void unlock() {
    // Звільняємо м'ютекс і перевіряємо, чи були очікуючі
    if (atomic_fetch_sub(&mutex, 1) != 1) {
        mutex = 0;
        // Будимо 1 очікуючий потік
        futex_wake((int*)&mutex, 1);
    }
}
```
== C (Високорівневий pthread_mutex)
```c
#include <pthread.h>
#include <stdio.h>

// Ініціалізація стандартного м'ютекса (який внутрішньо використовує futex)
pthread_mutex_t my_mutex = PTHREAD_MUTEX_INITIALIZER;

void lock_example() {
    // Якщо м'ютекс вільний - захоплення відбудеться миттєво в просторі користувача.
    // Якщо зайнятий - потік засне в ядрі через FUTEX_WAIT.
    pthread_mutex_lock(&my_mutex);
    
    printf("Виконання критичної секції...\n");
    
    // Звільнення м'ютекса та розбудження інших через FUTEX_WAKE.
    pthread_mutex_unlock(&my_mutex);
}
```
