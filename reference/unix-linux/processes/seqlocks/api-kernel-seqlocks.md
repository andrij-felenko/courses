# 📋 Довідник інтерфейсів seqlock у ядрі Linux

Послідовні замки у ядрі Linux розділені на два фундаментальні рівні абстракції: чисті лічильники послідовності (`seqcount_t`) та повноцінні автономні примітиви блокування з вбудованим спин-замком (`seqlock_t`). Перша категорія застосовується тоді, коли захист письменника від інших письменників вже вибудувано зовнішніми механізмами ядра (наприклад, окремим м'ютексом або спин-замком), а друга надає повністю самодостатній примітив синхронізації.

---

## 1. Архітектурні типи даних та структури

### `seqcount_t` — базовий лічильник послідовності

Являє собою мінімалістичну структуру, яка зберігає лише 32-бітне беззнакове ціле число `sequence`. Цей тип використовують у тих підсистемах ядра, які вже мають власний замок для письменників (наприклад, `spinlock_t` або `struct mutex`). Додавання другого спин-замка всередину seqlock було б надлишковим витрачанням пам'яті та дорогоцінних тактів процесора.

```c
typedef struct seqcount {
    unsigned sequence;
#ifdef CONFIG_DEBUG_LOCKS
    struct lockdep_map lockdep_map;
#endif
} seqcount_t;
```

Коли у конфігурації ядра увімкнено відлагоджувальний режим `CONFIG_DEBUG_LOCKS`, структура розширюється полем відстеження Lockdep (`lockdep_map`), яке фіксує стеки викликів та приналежність до системних контекстів виконання.

### Асоційовані типи `seqcount` для динамічного аналізу Lockdep

Для того щоб підсистема динамічного аналізу коректності блокувань Lockdep мала змогу перевіряти, яким саме замком захищається письменник, у сучасних версіях ядра Linux введено спеціалізовані асоційовані типи лічильників:

- **`seqcount_spinlock_t`:** Лічильник послідовності, прив'язаний до об'єкта `spinlock_t`. Використовується за замовчуванням у більшості стандартних структур ядра.
- **`seqcount_raw_spinlock_t`:** Лічильник, прив'язаний до примітиву `raw_spinlock_t`. Використовується у низькорівневих обробниках переривань та у системному ядрі реального часу `PREEMPT_RT`, де звичайні спин-замки перетворені на м'ютекси із засинанням.
- **`seqcount_mutex_t`:** Лічильник, прив'язаний до стандартного м'ютекса ядра `struct mutex`. Дозволяє потіку-письменнику виконувати тривалі операції або засинати у критичній секції запису, але вимагає спеціального реагування з боку читачів для запобігання нескінченного спінінгу.
- **`seqcount_ww_mutex_t`:** Лічильник, прив'язаний до м'ютекса Wound-Wait (`struct ww_mutex`), який використовується у графічних драйверах (DRM/KMS) та підсистемі буферів виділення пам'яті для уникнення дедлоків при захопленні багатьох ресурсів.

Асоційовані типи дозволяють інструментарію Lockdep здійснювати статичний та динамічний контроль: якщо розробник спробує викликати `write_seqcount_begin()` без попереднього захоплення відповідного прив'язаного замка, ядро надрукує детальний звіт про помилку.

### `seqlock_t` — автономний послідовний замок

Структура `seqlock_t` є повним самодостатнім примітивом, який об'єднує всередині себе `seqcount_spinlock_t` та класичний спин-замок `spinlock_t`.

```c
typedef struct {
    seqcount_spinlock_t seqcount;
    spinlock_t lock;
} seqlock_t;
```

Цей тип застосовується тоді, коли захищається окрема автономна структура даних, що не має власного зовнішнього замка.

## 2. Макроси та функції ініціалізації

Ініціалізація послідовних замків може здійснюватися як статично (на етапі компіляції), так і динамічно (під час виділення пам'яті в списку або структурі).

```c
/* Статичне оголошення та ініціалізація автономного seqlock_t */
DEFINE_SEQLOCK(my_seqlock);

/* Статичне оголошення та ініціалізація голого seqcount_t */
seqcount_t my_seqcount = SEQCNT_ZERO(my_seqcount);

/* Динамічна ініціалізація seqlock_t у виділеній пам'яті */
void seqlock_init(seqlock_t *sl);

/* Динамічна ініціалізація голого seqcount_t */
void seqcount_init(seqcount_t *s);

/* Явна динамічна прив'язка seqcount до зовнішнього спин-замка для Lockdep */
void seqcount_spinlock_init(seqcount_spinlock_t *s, spinlock_t *lock);

/* Динамічна прив'язка seqcount до зовнішнього м'ютекса */
void seqcount_mutex_init(seqcount_mutex_t *s, struct mutex *lock);
```

Під час динамічної ініціалізації макрос `seqlock_init()` автоматично реєструє внутрішній спин-замок у мапі Lockdep та присвоює йому унікальний клас блокування (lock class).

## 3. Інтерфейси письменника (Writer APIs)

Операції письменника вимагають обов'язкового виключного доступу. Функції для `seqlock_t` автоматично виконують дві дії: захоплюють внутрішній спин-замок та збільшують лічильник послідовності `sequence`.

### Сигнатури та вибір контексту для `seqlock_t`

```c
/* Стандартне блокування у контексті процесу (без вимкнення переривань) */
void write_seqlock(seqlock_t *sl);
void write_sequnlock(seqlock_t *sl);

/* Блокування зі збереженням прапорців переривань (IRQ-safe) */
void write_seqlock_irqsave(seqlock_t *sl, unsigned long flags);
void write_sequnlock_irqrestore(seqlock_t *sl, unsigned long flags);

/* Блокування з вимкненням нижніх половин (SoftIRQ-safe) */
void write_seqlock_bh(seqlock_t *sl);
void write_sequnlock_bh(seqlock_t *sl);

/* Блокування з вимкненням апаратних переривань на поточному ядрі */
void write_seqlock_irq(seqlock_t *sl);
void write_sequnlock_irq(seqlock_t *sl);
```

Правило суворого вибору варіанта для письменника:
- Якщо читач може викликатися з обробника апаратного переривання (`hardirq`), письменник зобов'язаний використовувати **`write_seqlock_irqsave()`**, щоб не припуститися взаємного блокування на одному процесорному ядрі.
- Якщо читач викликається з контексту тасклета або м'якого переривання (`softirq`), письменник використовує **`write_seqlock_bh()`**, вимикаючи нижні половини.
- Якщо читач і письменник працюють виключно у контексті процесів, достатньо використовувати **`write_seqlock()`**.

### Сигнатури для `seqcount_t` (Зовнішнє блокування)

Якщо письменник захищений зовнішнім м'ютексом або спин-замком, він викликає безпосередні операції зміни лічильника:

```c
/* Початок запису: перевірка Lockdep + seq++ (стає непарним) + smp_wmb() */
void write_seqcount_begin(seqcount_t *s);

/* Завершення запису: smp_wmb() + seq++ (стає парним) */
void write_seqcount_end(seqcount_t *s);

/* Сирий варіант без перевірок Lockdep (використовується рідко у критичних місцях) */
void raw_write_seqcount_begin(seqcount_t *s);
void raw_write_seqcount_end(seqcount_t *s);

/* Примусова інвалідація лічильника без виконання модифікації полів */
void write_seqcount_invalidate(seqcount_t *s);
```

Макрос `write_seqcount_invalidate()` збільшує `sequence` одразу на 2 (з парного в парне значення через крок), змушуючи всіх активних читачів перезапустити свій цикл `read_seqretry`, не входячи у непарний стан.

## 4. Інтерфейси читача (Reader APIs)

Операції читача є повністю пасивними: вони не захоплюють замків, не модифікують пам'ять і не вимикають переривань.

```c
/* Початок спроби читання. 
   Повертає поточне значення лічильника seq.
   Виконує smp_rmb(). Якщо seq непарне — спінить до парного. */
unsigned read_seqbegin(const seqlock_t *sl);

/* Перевірка цілісності після прочитання даних.
   Виконує smp_rmb().
   Повертає true (1), якщо запис відбувся, вимагаючи повтору циклу. */
unsigned read_seqretry(const seqlock_t *sl, unsigned start_seq);

/* Аналогічні операції для голого seqcount_t */
unsigned read_seqcount_begin(const seqcount_t *s);
unsigned read_seqcount_retry(const seqcount_t *s, unsigned start_seq);
```

### Гібридний варіант `read_seqbegin_or_lock()`

Для уникнення голодування читачів при високій частоті записів застосовується гібридний макрос, який після кількох колізій автоматично переходить на виключне блокування спин-замком:

```c
unsigned seq = 0;
do {
    /* На перших спробах — seqlock, при змаганні — захоплює спин-замок */
    read_seqbegin_or_lock(&my_seqlock, &seq);
    
    /* Зчитування полів даних */
    local_val1 = global_data.val1;
    local_val2 = global_data.val2;
    
} while (need_seqretry(&my_seqlock, seq));

/* Завершення читання та звільнення замка (якщо він брався) */
done_seqretry(&my_seqlock, seq);
```

## 5. Повний практичний приклад у коді ядра Linux

Нижче наведено реалізацію захисту статистики мережевого пристрою в драйвері ядра Linux:

```c
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/seqlock.h>
#include <linux/netdevice.h>

struct net_device_stats_cpu {
    seqlock_t lock;
    u64 rx_packets;
    u64 rx_bytes;
    u64 tx_packets;
    u64 tx_bytes;
};

static struct net_device_stats_cpu my_stats;

/* Ініціалізація при завантаженні модуля */
static int __init my_module_init(void)
{
    seqlock_init(&my_stats.lock);
    my_stats.rx_packets = 0;
    my_stats.rx_bytes = 0;
    return 0;
}

/* Оновлення статистики у контексті переривання мережевої карти (HardIRQ / NAPI) */
void my_net_rx_handler(u32 pkt_len)
{
    unsigned long flags;

    /* Використовуємо irqsave, бо обробник викликається з контексту переривання */
    write_seqlock_irqsave(&my_stats.lock, flags);
    my_stats.rx_packets++;
    my_stats.rx_bytes += pkt_len;
    write_sequnlock_irqrestore(&my_stats.lock, flags);
}

/* Читання статистики у контексті системного виклику (User Context / sysfs) */
void my_get_stats(u64 *packets, u64 *bytes)
{
    unsigned seq;

    /* Оптимістичний цикл читання — не вимикає переривань і не блокує NAPI */
    do {
        seq = read_seqbegin(&my_stats.lock);
        *packets = my_stats.rx_packets;
        *bytes = my_stats.rx_bytes;
    } while (read_seqretry(&my_stats.lock, seq));
}
```

У цій схемі обробник переривання мережевої карти `my_net_rx_handler` ніколи не чекає читача з `sysfs`. Якщо у момент читання статистики через файлову систему приходить мережевий пакет, читач просто фіксує колізію `read_seqretry` і робить другу ітерацію, отримуючи вже оновлені значення пакетів та байтів.

## 6. Діагностика Lockdep, асерти та розшифровка помилок

При включенні параметра конфігурації ядра `CONFIG_PROVE_LOCKING` підсистема Lockdep здійснює суворий контроль за дотриманням правил користування seqlock:

1. **Макрос перевірки захоплення замка:** У коді письменника можна використовувати макрос `lockdep_assert_held(&sl->lock)`, який генерує варнінг у `dmesg`, якщо спин-замок не було захоплено перед модифікацією `seqcount`.
2. **Помилка `unasserted lock`:** Якщо потік викликає `write_seqcount_begin()` на асоційованому `seqcount_spinlock_t`, але при цьому спин-замок не було захоплено через `spin_lock()`, Lockdep надрукує варнінг: `WARNING: held lock variables expected!`. Це означає, що розробник порушив контракт і залишив небезпеку паралельного запису іншим письменником.
3. **Помилка контексту переривань:** Якщо письменник викликав `write_seqlock()`, а читач викликається з контексту апаратного переривання (`hardirq`), Lockdep виявить потенційне взаємне блокування і видасть детальний звіт `in-hardirq-W -> in-process-R`. Це підказує, що письменник повинен перейти на `write_seqlock_irqsave()`.
4. **Виявлення непарності при виході:** Якщо розробник припустився помилки у відгалуженні коду і забув викликати `write_sequnlock()`, Lockdep при поверненні із системного виклику зафіксує незвільнений замок у списку `current->held_locks` і надрукує попередження про витік замка.
