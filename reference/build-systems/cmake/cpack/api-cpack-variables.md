# 📋 Довідник змінних і команд CPack

Конфігурація генератора пакетів CPack базується на встановленні службових змінних CMake перед підключенням модуля `include(CPack)`. Цей довідник містить повну специфікацію глобальних змінних метаданих, параметрів компонентного розбиття та специфічних налаштувань цільових генераторів (DEB, RPM, NSIS, WIX, DMG, архівні бекенди).

## 1. Базові метадані проєкту та ідентифікація пакетів

Змінні цієї групи визначають глобальні атрибути створюваних пакетів для всіх генераторів одночасно. Якщо значення не встановлені явно, CPack запозичує їх із метаданих виклику `project()` у кореневому `CMakeLists.txt`.

### `CPACK_PACKAGE_NAME`
Рядок, що задає офіційну назву пакета. За замовчуванням дорівнює значенню `CMAKE_PROJECT_NAME`. Для системних пакетних менеджерів Linux (DEB та RPM) ім'я має містити виключно малі латинські літери, цифри та дефіси.

### `CPACK_PACKAGE_VERSION`
Повний рядок версії у форматі `MAJOR.MINOR.PATCH` або `MAJOR.MINOR.PATCH.TWEAK`. За замовчуванням формується з компонентів `PROJECT_VERSION`. Якщо потрібно окремо контролювати числові складові, використовуються змінні `CPACK_PACKAGE_VERSION_MAJOR`, `CPACK_PACKAGE_VERSION_MINOR` та `CPACK_PACKAGE_VERSION_PATCH`.

### `CPACK_PACKAGE_VENDOR`
Рядок із назвою організації, компанії або автора програмного забезпечення (наприклад, `"Acme Corporation"`). Використовується в заголовках RPM (`Vendor:`), полях метаданих WiX та властивостях інсталяторів Windows.

### `CPACK_PACKAGE_CONTACT`
Електронна адреса супровідника або технічної підтримки пакета. Для генератора DEB ця змінна є критично обов'язковою, оскільки вона напряму транслюється в поле `Maintainer:` контрольного файлу Debian. Відсутність цієї змінної при збірці DEB призводить до помилки генерації.

### `CPACK_PACKAGE_DESCRIPTION_SUMMARY`
Короткий однорядковий опис призначення програми. Відображається в заголовках списків пакетів, результатах пошуку `apt search` / `dnf search` та вікнах майстрів інсталяції.

### `CPACK_PACKAGE_DESCRIPTION_FILE`
Абсолютний або відносний шлях до текстового файлу, що містить розгорнутий багаторядковий опис проєкту (наприклад, `README.txt`). Якщо змінна задана, вміст файлу вбудовується в опис пакета.

### `CPACK_PACKAGE_HOMEPAGE_URL`
URL-адреса офіційного вебсайту або репозиторію проєкту. За замовчуванням запозичується з параметра `HOMEPAGE_URL` команди `project()`.

### `CPACK_PACKAGE_FILE_NAME`
Базове ім'я результуючого файлу архіву або пакета без розширення. За замовчуванням CPack формує назву за шаблоном `${CPACK_PACKAGE_NAME}-${CPACK_PACKAGE_VERSION}-${CMAKE_SYSTEM_NAME}` (наприклад, `telemetry-1.4.0-Linux`). При компонентній інсталяції до назви додається суфікс імені компонента.

### `CPACK_PACKAGING_INSTALL_PREFIX`
Абсолютний корінь інсталяційного дерева всередині створюваного пакета. Усі відносні шляхи з правил `install(DESTINATION ...)` розгортаються відносно цього префікса. Для системних пакетів Linux типовим значенням є `/usr`, для ізольованого комерційного софту — `/opt/<продукт>`, а для Windows — стандартний каталог `C:\Program Files\<продукт>`.

```cmake
set(CPACK_PACKAGE_NAME "telemetry")
set(CPACK_PACKAGE_VENDOR "Acme Labs")
set(CPACK_PACKAGE_CONTACT "support@acme.example.com")
set(CPACK_PACKAGE_DESCRIPTION_SUMMARY "High-performance network telemetry agent")
set(CPACK_PACKAGING_INSTALL_PREFIX "/usr")
```

## 2. Керування вибором і поведінкою генераторів

### `CPACK_GENERATOR`
Список імен бінарних генераторів через крапку з комою, які будуть активовані за замовчуванням під час запуску утиліти `cpack` без прапорця `-G`. Можливі значення: `DEB`, `RPM`, `TGZ`, `TXZ`, `ZIP`, `STGZ`, `NSIS`, `WIX`, `DragNDrop`, `productbuild`, `NuGet`.

### `CPACK_SOURCE_GENERATOR`
Список генераторів для створення архівів вихідного коду проєкту при запуску `cpack --config CPackSourceConfig.cmake`. Зазвичай використовують `TGZ` та `ZIP`.

### `CPACK_SOURCE_IGNORE_FILES`
Список регулярних виразів CMake, що визначають файли та папки, які повинні бути виключені зі складу вихідного архіву. Оскільки фільтрація здійснюється зіставленням повного шляху файлу, обов'язково слід екранувати спеціальні символи (крапки, слеші) та враховувати тимчасові файли систем контролю версій (`/\\.git/`), каталоги збірки (`/build/`) та об'єктні файли.

### `CPACK_PROJECT_CONFIG_FILE`
Шлях до додаткового файлу CMake-скрипту, який завантажується утилітою `cpack` безпосередньо в момент виконання пакування. Це дозволяє впроваджувати динамічну логіку, яка залежить від обраного в командному рядку генератора (перевіряючи змінну `CPACK_GENERATOR_SPEC_NAME`).

### `CPACK_VERBATIM_VARIABLES`
Булева змінна (`TRUE` або `FALSE`). Якщо встановлена в `TRUE`, CPack зберігає точні значення змінних у файлі `CPackConfig.cmake` без додаткового екранування, що запобігає спотворенню складних регулярних виразів та багаторядкових shell-скриптів.

## 3. Команди та функції компонентного пакування

Підключення модуля `include(CPackComponent)` після `include(CPack)` активує декларативний API для налаштування логічних компонентів і створення гнучких інсталяторів.

### `cpack_add_component`

Оголошує метадані та правила поведінки для окремого компонента, ім'я якого фігурує у правилах `install(... COMPONENT <ім'я>)`.

```cmake
cpack_add_component(
    <ComponentName>
    [DISPLAY_NAME <name>]
    [DESCRIPTION <text>]
    [HIDDEN]
    [REQUIRED]
    [DISABLED]
    [GROUP <groupName>]
    [DEPENDS <comp1> <comp2> ...]
    [INSTALL_TYPES <type1> <type2> ...]
    [DOWNLOADED]
    [ARCHIVE_FILE <filename>]
)
```

- `DISPLAY_NAME` — текстовий заголовок компонента, який відображається у дереві вибору графічних інсталяторів (NSIS, WiX).
- `DESCRIPTION` — докладний опис функціональності компонента, що виводиться у спливаючих підказках або інформаційних панелях майстра інсталяції.
- `HIDDEN` — прапорець, який робить компонент невидимим у графічному інтерфейсі вибору (компонент встановлюється у фоновому режимі).
- `REQUIRED` — позначає компонент як обов'язковий: користувач не може зняти з нього прапорець вибору під час встановлення.
- `DISABLED` — компонент за замовчуванням є вимкненим у дереві вибору і потребує явної позначки користувачем.
- `GROUP` — прив'язує компонент до певної групи компонентів, створеної командою `cpack_add_component_group`.
- `DEPENDS` — перелік інших компонентів цього ж проєкту, які є обов'язковими для функціонування даного компонента. Якщо користувач обирає цей компонент, інсталятор автоматично обирає всі зазначені залежності.
- `INSTALL_TYPES` — список профілів інсталяції (наприклад, `Full`, `Developer`), до складу яких входить цей компонент.

### `cpack_add_component_group`

Об'єднує декілька логічно пов'язаних компонентів у спільну групу з єдиним заголовком і можливістю масового вибору.

```cmake
cpack_add_component_group(
    <GroupName>
    [DISPLAY_NAME <name>]
    [DESCRIPTION <text>]
    [PARENT_GROUP <parentGroupName>]
    [EXPANDED]
    [BOLD_TITLE]
)
```

- `DISPLAY_NAME` — назва групи компонентів у дереві інсталятора.
- `DESCRIPTION` — опис загального призначення групи.
- `PARENT_GROUP` — ім'я батьківської групи для побудови багаторівневих ієрархій компонентів.
- `EXPANDED` — вказує майстру інсталяції відображати дерево групи у розгорнутому вигляді за замовчуванням.
- `BOLD_TITLE` — виділяє заголовок групи жирним шрифтом у майстрах NSIS.

### `cpack_add_install_type`

Створює іменований профіль інсталяції (наприклад, «Повна інсталяція», «Мінімальна», «Для розробників»), що дозволяє користувачеві швидко обрати заздалегідь визначений набір компонентів у випадаючому списку інсталятора.

```cmake
cpack_add_install_type(
    <TypeName>
    [DISPLAY_NAME <name>]
)
```

## 4. Специфікація змінних генератора DEB (Debian / Ubuntu)

Генератор `DEB` створює нативні бінарні пакети для менеджера `dpkg`. Підтримує як монолітне, так і покомпонентне створення архівів.

### `CPACK_DEB_COMPONENT_INSTALL`
Булева змінна. При значенні `ON` активує генерацію окремого `.deb` файлу для кожного оголошеного компонента інсталяції.

### `CPACK_DEBIAN_PACKAGE_NAME`
Назва пакета у репозиторіях Debian. Може перевизначатися для окремих компонентів через `CPACK_DEBIAN_<COMPONENT>_PACKAGE_NAME`.

### `CPACK_DEBIAN_PACKAGE_ARCHITECTURE`
Цільова архітектура процесора (наприклад, `amd64`, `arm64`, `armhf`, `all`). Якщо змінна не задана, CPack намагається визначити її автоматично через виклик `dpkg --print-architecture`. При крос-компіляції значення необхідно задавати явно.

### `CPACK_DEBIAN_PACKAGE_DEPENDS`
Рядок залежностей у синтаксисі Debian (пакети через кому з можливими обмеженнями версій, наприклад, `"libc6 (>= 2.31), libssl3"`). Для окремого компонента перевизначається через `CPACK_DEBIAN_<COMPONENT>_PACKAGE_DEPENDS`.

### `CPACK_DEBIAN_PACKAGE_SHLIBDEPS`
Булева змінна (`ON` / `OFF`). Якщо увімкнена, CPack автоматично запускає утиліту `dpkg-shlibdeps` над усіма виконуваними файлами та динамічними бібліотеками у staging-дереві, формуючи точний перелік залежностей від системних бібліотек.

### `CPACK_DEBIAN_PACKAGE_SECTION`
Категорія репозиторію, до якої належить пакунок (наприклад, `devel`, `utils`, `net`, `libs`, `admin`). За замовчуванням встановлюється в `devel`.

### `CPACK_DEBIAN_PACKAGE_PRIORITY`
Пріоритет пакета в системі керування пакунками Debian: `optional` (рекомендовано для більшості прикладного ПЗ), `standard`, `important`, `required`.

### `CPACK_DEBIAN_PACKAGE_CONTROL_EXTRA`
Список шляхів до додаткових скриптів супроводу через крапку з комою. Може містити сценарії `preinst`, `postinst`, `prerm`, `postrm`, файл конфігурацій `conffiles` або файл системних тригерів `triggers`.

### `CPACK_DEBIAN_PACKAGE_GENERATE_SHLIBS`
При значенні `ON` CPack автоматично генерує файл `shlibs` для спільних бібліотек, що входять до складу пакета, спрощуючи інтеграцію залежних пакетів.

## 5. Специфікація змінних генератора RPM (Fedora / RHEL / SUSE)

Генератор `RPM` формує пакунки за допомогою системної утиліти `rpmbuild` або внутрішнього рушія CMake.

### `CPACK_RPM_COMPONENT_INSTALL`
Булева змінна. При значенні `ON` вмикає покомпонентне створення окремих `.rpm` файлів для кожного компонента проєкту.

### `CPACK_RPM_PACKAGE_NAME`
Ім'я пакета в базі даних RPM. Може перевизначатися для окремих компонентів через `CPACK_RPM_<COMPONENT>_PACKAGE_NAME`.

### `CPACK_RPM_PACKAGE_RELEASE`
Номер релізу пакета в дистрибутиві (наприклад, `1%{?dist}` або `1`). За замовчуванням дорівнює `1`.

### `CPACK_RPM_PACKAGE_LICENSE`
Рядок із назвою ліцензії (наприклад, `"MIT"`, `"Apache-2.0"`, `"GPL-3.0-or-later"`). Це поле є суворо обов'язковим для генератора RPM.

### `CPACK_RPM_PACKAGE_GROUP`
Група програмного забезпечення згідно з класифікацією дистрибутивів RPM (наприклад, `"Applications/System"`, `"Development/Libraries"`).

### `CPACK_RPM_PACKAGE_REQUIRES`
Список пакетних залежностей (`Requires:`), які повинні бути встановлені в операційній системі для працездатності даного пакета.

### `CPACK_RPM_PACKAGE_PROVIDES`
Список віртуальних імен або можливостей (`Provides:`), які надає даний пакет іншим програмам у системі.

### `CPACK_RPM_PACKAGE_AUTOREQ`
Вмикає (`YES`) або вимикає (`NO`) автоматичне сканування ELF-бінарників на наявність динамічних залежностей `DT_NEEDED` стандартними макросами RPM.

### `CPACK_RPM_PACKAGE_AUTOPROV`
Вмикає (`YES`) або вимикає (`NO`) автоматичне сканування експортованих символів та `soname` динамічних бібліотек.

### `CPACK_RPM_PRE_INSTALL_SCRIPT_FILE` та `CPACK_RPM_POST_INSTALL_SCRIPT_FILE`
Шляхи до shell-сценаріїв, що виконуються перед (`%pre`) та після (`%post`) встановлення файлів пакета.

### `CPACK_RPM_PRE_UNINSTALL_SCRIPT_FILE` та `CPACK_RPM_POST_UNINSTALL_SCRIPT_FILE`
Шляхи до shell-сценаріїв, що виконуються перед (`%preun`) та після (`%postun`) видалення файлів пакета.

### `CPACK_RPM_PACKAGE_RELOCATABLE`
При значенні `ON` додає до специфікації директиву `Prefix: /usr`, роблячи пакет релокабельним за допомогою прапорця `rpm --prefix`.

### `CPACK_RPM_SPEC_MORE_DEFINE`
Рядок довільних директив або макросів, що вставляються безпосередньо в тіло згенерованого `.spec`-файлу.

## 6. Специфікація змінних інсталяторів Windows (NSIS та WIX)

### Генератор NSIS (`.exe`)

- `CPACK_NSIS_DISPLAY_NAME` — ім'я програми, що відображається у системному меню «Встановлення та видалення програм».
- `CPACK_NSIS_PACKAGE_NAME` — назва продукту в заголовках майстра інсталяції.
- `CPACK_NSIS_MUI_ICON` — шлях до файлу `.ico` головної іконки інсталятора.
- `CPACK_NSIS_MUI_UNIICON` — шлях до іконки деінсталятора.
- `CPACK_NSIS_MODIFY_PATH` — при `ON` додає на фінальну сторінку інсталятора прапорець «Додати програму до системної змінної PATH».
- `CPACK_NSIS_EXTRA_INSTALL_COMMANDS` — довільні інструкції мовою NSIS, що виконуються наприкінці встановлення (запис параметрів у системний реєстр, реєстрація служб).
- `CPACK_NSIS_EXTRA_UNINSTALL_COMMANDS` — інструкції NSIS для очищення реєстру та файлів користувача під час деінсталяції.
- `CPACK_NSIS_CREATE_ICONS_EXTRA` — команди NSIS для створення додаткових ярликів на робочому столі чи в меню «Пуск».

### Генератор WIX Toolset (`.msi`)

- `CPACK_WIX_UPGRADE_GUID` — стабільний унікальний UUID продукту, необхідний системі Windows Installer для коректного оновлення старіших версій програми при встановленні нової.
- `CPACK_WIX_PRODUCT_GUID` — унікальний UUID конкретного релізу пакета.
- `CPACK_WIX_PRODUCT_ICON` — шлях до файлу іконки в панелі керування Windows.
- `CPACK_WIX_UI` — ідентифікатор вбудованого діалогового шаблону інтерфейсу WiX (наприклад, `WixUI_InstallDir` або `WixUI_FeatureTree`).
- `CPACK_WIX_EXTENSIONS` — список додаткових бібліотек розширення WiX Toolset через крапку з комою (наприклад, `WixUtilExtension`, `WixFirewallExtension`).

## 7. Специфікація змінних генераторів macOS (DragNDrop та productbuild)

- `CPACK_DMG_VOLUME_NAME` — назва змонтованого дискового тому в системі macOS.
- `CPACK_DMG_BACKGROUND_IMAGE` — шлях до графічного файлу (`.png` або `.tiff`), який встановлюється як фон вікна Finder при відкритті образу `.dmg`.
- `CPACK_DMG_DS_STORE_SETUP_SCRIPT` — шлях до сценарію AppleScript для точного позиціонування іконок програми та папки `/Applications` у вікні змонтованого диска.
- `CPACK_PRODUCTBUILD_IDENTIFIER` — унікальний ідентифікатор бандла у системі Apple (наприклад, `com.company.productname`).
- `CPACK_PKGBUILD_IDENTITY_NAME` — назва сертифіката «Developer ID Installer» у зв'язці ключів macOS для автоматичного підпису інсталяційного пакета `.pkg`.
