# ⚙️ Своє джерело карти: рядок у налаштуваннях або півсотні рядків C++

Тут показано обидва способи під'єднати до наземної станції власний тайловий сервер: спершу без жодного перезбирання, самим лише шаблоном адреси в налаштуваннях, а потім класом — коли шаблона перестає вистачати. Клас коштує близько півсотні рядків у двох нових файлах і два рядки правки в одному чужому. Більша частина роботи — не написати цей клас, а обійти шість місць, де станція мовчки поводиться не так, як здається.

## Умова

Рятувальна служба тримає власний сервер ортофотопланів своєї області. Знімки свіжі, зроблені минулого тижня, і саме тому їх не замінить жоден супутник. Сервер віддає тайли за угодою `z/x/y`:

```text
https://tiles.skylark.example/ortho/{z}/{x}/{y}.jpg
```

Чотири обставини, з яких і виросте весь подальший код:

- доступ за токеном — сервер наш, тож ми можемо навчити його читати той заголовок, який зручний станції;
- знімки існують лише з десятого до дев'ятнадцятого рівня; вище сервер зараз повертає сіру заглушку з кодом `200`;
- тайл — jpeg, у середньому близько сорока кілобайтів, тобто утричі важчий за загальну сталу станції;
- на тому самому сервері лежить ще й схема ділянок, і оператор має вибирати між нею й ортофото просто в списку джерел.

Мета: щоб «SkyOrtho» з'явився в переліку карт поруч із супутником, щоб оцінка обсягу району перед завантаженням не брехала і щоб набір для офлайну качався без помилок.

## Шлях перший: шаблон у налаштуваннях

У списку провайдерів станції наприкінці стоїть об'єкт `CustomURLMapProvider`, і весь він — ось цей метод:

```cpp
QString CustomURLMapProvider::_getURL(int x, int y, int zoom) const
{
    QString url = SettingsManager::instance()->appSettings()
        ->customURL()->rawValue().toString();
    (void) url.replace("{x}", QString::number(x));
    (void) url.replace("{y}", QString::number(y));
    static const QRegularExpression zoomRegExp("\\{(z|zoom)\\}");
    (void) url.replace(zoomRegExp, QString::number(zoom));
    return url;
}
```

Оператор вписує шаблон у налаштуваннях застосунку, вибирає в списку карт джерело `CustomURL` типу `Custom` — і тайли їдуть. Підстановка робиться щоразу заново, тож шаблон можна змінити й побачити результат без перезапуску.

Рядок довільний, отже, у нього влазить і токен — як параметр запиту:

```text
https://tiles.skylark.example/ortho/{z}/{x}/{y}.jpg?key=ce9f4a2b18
```

Саме так виглядає приклад, який станція показує в підказці до цього налаштування: адреса новозеландського сервісу з ключем у хвості. З цього варто починати завжди — якщо через `CustomURL` картинки не з'явилося, то й клас не допоможе, бо проблема тоді в сервері, у мережі або в самому шаблоні.

Тепер про межу. Підстановка трьох чисел — це рівно те, чим `CustomURL` є, і все інше в ньому оголошено порожнім або типовим:

| що потрібно | що дає `CustomURL` |
|---|---|
| два джерела з одного сервера | одне: одне налаштування на весь застосунок |
| правдива оцінка обсягу району | загальна стала 13652 байти на тайл |
| токен окремим заголовком | лише те, що влазить у рядок адреси |
| межі масштабу джерела | немає: станція проситиме аж до 23 |
| розпізнаваний формат картинки | формат оголошено порожнім рядком |
| відомий `Referer` | порожній, заголовок не надсилається |

Окремо варто знати про y. Шаблон підставляє номер рядка таким, яким його порахувала станція, — від верхнього краю вниз, за угодою XYZ. Сервер, що нумерує рядки навпаки, від нижнього краю вгору (угода TMS, а з нею й контейнери на її основі), покладе кожну клітинку не в той рядок: карта вийде дзеркальною згори вниз. Жодною зміною шаблона це не лікується: підстановка вміє лише вставити число, а тут його треба перерахувати —

```text
y_TMS = 2ᶻ − 1 − y
```

Лишається або перевертати рядок на своєму сервері, або писати клас, де цей вираз стоїть просто в `_getURL`. Які взагалі бувають угоди адресації й чим `z/x/y` відрізняється від TMS, WMTS і quadkey — в [адресних схемах тайлових сервісів](book:programming/tile-url-schemes).

## Шлях другий: власний клас

Провайдер у станції — це об'єкт з одним обов'язковим методом. Базовий `MapProvider` тримає все спільне, а нащадок доповідає п'ять сталих у конструкторі й перевизначає те, чим відрізняється:

```cpp
MapProvider(const QString &mapName, const QString &referrer,
            const QString &imageFormat,
            quint32 averageSize = QGC_AVERAGE_TILE_SIZE,
            MapStyle mapStyle = CustomMap);
```

Одна прикрість з'ясовується одразу, і краще знати про неї до початку. Список провайдерів — це закритий статичний член `UrlFactory::_providers`, зібраний під час компіляції; жодного методу «зареєструй ще один» у станції немає. Тому власне джерело, на відміну від ядрового розширення, **не можна додати самою тільки текою власної збірки**: доведеться торкнутися апстримового `QGCMapUrlEngine.cpp`. Зате торкнутися його треба рівно двічі — один `#include` і один рядок у кінці списку, і цей клапоть легко тримати окремою латкою поверх [власної збірки](book:qgroundcontrol/custom-build).

### Заголовок

```cpp
// src/QtLocationPlugin/Providers/SkyOrthoMapProvider.h
#pragma once

#include "MapProvider.h"

/// Ортофотоплани власного сервера: сітка XYZ, jpeg, токен окремим заголовком.
class SkyOrthoMapProvider : public MapProvider
{
public:
    SkyOrthoMapProvider()
        : MapProvider(QStringLiteral("SkyOrtho Aerial"),            // «джерело тип»
                      QStringLiteral("https://tiles.skylark.example"),
                      QStringLiteral("jpg"),
                      41000,                                        // виміряний тайл
                      MapProvider::SatelliteMapDay) {}

    QByteArray getToken() const final;

    QGCTileSet getTileCount(int zoom,
                            double topleftLon, double topleftLat,
                            double bottomRightLon, double bottomRightLat) const final;

private:
    QString _getURL(int x, int y, int zoom) const final;

    static constexpr int kMinZoom = 10;
    static constexpr int kMaxZoom = 19;

    const QString _mapUrl = QStringLiteral(
        "https://tiles.skylark.example/ortho/%1/%2/%3.jpg");
};
```

Кожен аргумент конструктора має наслідок, який видно не тут, а за десять екранів звідси.

Назва `"SkyOrtho Aerial"` розпадеться на два слова: перше стане назвою джерела в списку, решта — назвою типу. Про те, чому в ній рівно один пробіл і чому перше слово одне, — нижче в граблях.

Адреса сайту поїде в заголовок `Referer` кожного запиту. Для чужих служб це спосіб виглядати браузером; для свого сервера — просто чесний підпис, за яким у журналі видно, хто прийшов.

Формат `"jpg"` — це те, чим станція назве байти, якщо не впізнає їх за першими символами. Число `41000` — очікуваний середній тайл; на ньому й тільки на ньому тримається вся арифметика «скільки важить цей район».

Стиль `SatelliteMapDay` не впливає ні на що, крім групування в інтерфейсі: оператор шукає ортофото серед супутникових знімків, а не серед схем.

### Реалізація

```cpp
// src/QtLocationPlugin/Providers/SkyOrthoMapProvider.cpp
#include "SkyOrthoMapProvider.h"

#include "SettingsManager.h"
#include "SkyOrthoSettings.h"

QString SkyOrthoMapProvider::_getURL(int x, int y, int zoom) const
{
    if ((zoom < kMinZoom) || (zoom > kMaxZoom)) {
        return QString();          // порожньо = «не проси»; наслідки — у граблях
    }
    return _mapUrl.arg(zoom).arg(x).arg(y);
}

QByteArray SkyOrthoMapProvider::getToken() const
{
    return SettingsManager::instance()->skyOrthoSettings()
        ->apiKey()->rawValue().toString().toUtf8();
}

QGCTileSet SkyOrthoMapProvider::getTileCount(int zoom,
                                             double topleftLon, double topleftLat,
                                             double bottomRightLon, double bottomRightLat) const
{
    if ((zoom < kMinZoom) || (zoom > kMaxZoom)) {
        return QGCTileSet();       // нуль клітинок, нуль байтів
    }
    return MapProvider::getTileCount(zoom, topleftLon, topleftLat,
                                     bottomRightLon, bottomRightLat);
}
```

`_getURL` — єдиний обов'язковий метод, і в ньому немає нічого, крім складання рядка. Перевірка рівнів на початку робить те, чого в базовому класі немає взагалі: у `MapProvider` немає ані поля мінімального, ані поля максимального рівня, тому обмежити джерело можна лише відмовою складати адресу.

`getToken` виглядає як дрібниця, але має жорстку вимогу до себе: його викликають **на кожен окремий тайл**, у момент складання запиту. Отже, всередині має бути дешеве читання з пам'яті, а не звернення до файлу. Саме тому токен живе не в голому `QSettings`, а у власній групі налаштувань — так само, як токени Esri й Mapbox в апстримі. Як завести таку групу зі своїми полями, показано в [розборі власної групи налаштувань](book:qgroundcontrol/settings-persistence/proj-settings-group.md); там же видно, чому значення переживає перезапуск і де воно лежить на диску.

`getTileCount` повертає нуль поза межами джерела, а всередині меж просто кличе базову реалізацію. Базова рахує номери кутових клітинок і множить їхню кількість на `getAverageSize()` — тобто на те саме число 41000 із конструктора.

### Реєстрація

```cpp
// src/QtLocationPlugin/QGCMapUrlEngine.cpp
#include "SkyOrthoMapProvider.h"
// …
    std::make_shared<OpenAIPMapProvider>(),
    std::make_shared<CustomURLMapProvider>(),
    std::make_shared<CopernicusElevationProvider>(),
    std::make_shared<SkyOrthoMapProvider>()          // ← ТІЛЬКИ в кінець
};
```

Слово «тільки» тут не стилістичне побажання, і чому — перше в граблях.

Далі — звичайне [перезбирання](book:qgroundcontrol/building-qgc) без жодного окремого прапорця. Після нього в переліку карт з'являється джерело `SkyOrtho` з єдиним типом `Aerial`.

Схема ділянок із того самого сервера — це другий такий самий клас із назвою `"SkyOrtho Parcels"` і другий рядок нижче в списку. Тоді джерело в інтерфейсі лишається одне, типів у ньому стає два, а простори ключів у базі — різні, бо номер у кожного об'єкта свій.

## Що станція зробить із цим класом

Коли фреймворк просить клітинку, вона проходить крізь наші три методи в цілком певному порядку — і саме порядок, а не самі методи, породжує більшість несподіванок.

![Шлях однієї клітинки: спершу складання адреси й перевірка на порожнечу, потім база, і аж потім мережа](/reference/qgroundcontrol/map-video/map-engine/img/custom-source-hooks.svg)

*Перевірка адреси стоїть вище за базу: адреса, якої немає, скасовує не тільки мережевий запит, а й читання з диска.*

Складання запиту виглядає так (це апстримовий код, наші методи в ньому позначено):

```cpp
request.setUrl(mapProvider->getTileURL(x, y, zoom));       // → наш _getURL
request.setTransferTimeout(10000);
request.setRawHeader("Accept", "*/*");
request.setHeader(QNetworkRequest::UserAgentHeader, s_userAgent);

const QByteArray referrer = mapProvider->getReferrer().toUtf8();
if (!referrer.isEmpty()) {
    request.setRawHeader("Referer", referrer);             // → наш конструктор
}
const QByteArray token = mapProvider->getToken();
if (!token.isEmpty()) {
    request.setRawHeader("User-Token", token);             // → наш getToken
}
```

І одразу за цим — рядок, довкола якого обертається половина подальшого:

```cpp
if (request.url().isEmpty()) {
    return nullptr;
}
```

Порожня адреса означає, що об'єкт-відповідь не створюється зовсім. А задача на читання з бази живе якраз усередині цього об'єкта, у його `init()`. Тобто база до порожньої адреси не доходить.

## Граблі

### Номер провайдера видається порядком у списку

Ідентифікатором джерела в станції служить не назва, а число. Воно ніде не оголошене — його роздає лічильник у конструкторі базового класу:

```cpp
int MapProvider::_mapIdIndex = 1;
// …
_mapId(_mapIdIndex++)
```

Перший об'єкт списку дістає 1, другий — 2 і так далі. Це саме число потрапляє в ключ тайла на диску:

```cpp
return QString::asprintf("%010d%08d%08d%03d", hash, x, y, z);
```

У типовій настільній збірці список має сорок провайдерів, тож наш стає сорок першим. Клітинка над центром Києва на вісімнадцятому рівні отримає ключ

```text
       провайдер      x         y      z
ключ = "0000000041" "00153296" "00088388" "018"
```

А тепер те саме на планшеті. У складанні під iOS п'ять google-провайдерів вимикаються директивою `QGC_NO_GOOGLE_MAPS`, весь список з'їжджає на п'ять позицій — і наше джерело стає тридцять шостим. Число 36 у настільній збірці належить зовсім іншому провайдерові:

![Той самий клас має різні номери в різних складаннях, і ключ на диску зберігає саме номер](/reference/qgroundcontrol/map-video/map-engine/img/provider-id-drift.svg)

*Ключ кеша пам'ятає позицію джерела в списку на момент запису, а не його назву — тож база, перенесена між складаннями, читається без жодної помилки й видає чужі знімки.*

Звідси три правила, і всі три нудні. Додавати своє джерело **тільки в кінець** списку. Після будь-якої зміни складу списку — свого чи апстримового — вважати стару базу тайлів непридатною й чистити її. Не сподіватися, що кеш переживе перехід на нову версію апстриму: досить, щоб там додали один провайдер перед нашим, і всі раніше збережені знімки почнуть читатися як чужі. Спосіб зробити це безпечним у самому коді існує — виводити число з назви, а не з позиції, — але станція так не робить, і латка на це зачепила б формат уже записаних баз у всіх користувачів світу.

### Назва розбирається за першим пробілом, а тип шукається підрядком

Списки для інтерфейсу будуються з тих самих назв двома функціями. Перша дістає назви джерел, друга — типи всередині вибраного джерела:

```cpp
static const QRegularExpression providerType = QRegularExpression(uR"(^([^\ ]*) (.*)$)"_s);
(void) mapStringList.replaceInStrings(providerType, "\\1");   // джерело: до пробілу
// …
mapStringList = mapStringList.filter(QRegularExpression(provider));
(void) mapStringList.replaceInStrings(providerType, "\\2");   // тип: усе після
```

Два наслідки, обидва неприємні.

Перший: розділяє **перший** пробіл. Назва «Sky Ortho Aerial» дала б джерело «Sky» з типом «Ortho Aerial». А назва без пробілу з виразом не збігається зовсім і лишається цілою в обох списках — так живе апстримовий `OpenAIP`, який показується і як джерело, і як єдиний свій тип. Спіткнутися тут легко навіть апстримові: провайдер OpenStreetMap зветься `"Street Map"`, тому в переліку джерел він осідає під іменем «Street».

Другий, підступніший: тип шукається `filter` за **регулярним виразом**, тобто збігом підрядка десь у назві, а не рівністю. Назвіть своє джерело «Map Ortho» — і, вибравши в списку «Map», оператор побачить у типах усе, де взагалі трапляється це слово: `MapQuest Map`, `Mapbox Street`, `Street Map`. А крапка чи дужка в назві поїде в регулярний вираз службовим символом і зіставиться з чим завгодно.

Правило: перше слово назви — одне, з самих літер і цифр, і воно не має траплятися підрядком у назві жодного іншого провайдера (як і чуже перше слово — у нашій).

### Середній розмір тайла — не косметика, а вся оцінка району

Коли оператор обводить рамкою ділянку, станція показує обсяг завантаження ще до першого запиту. Рахує вона його так:

```cpp
set.tileSize = getAverageSize() * set.tileCount;
```

Тобто кількість клітинок множиться на те число, яке провайдер сам про себе оголосив. Не на виміряне, не на середнє по кешу — на сталу з конструктора. Помилка в ній переноситься в оцінку один в один.

**Приклад: ділянка 3 × 2 км під Києвом, рівні до 19-го включно.**

```text
φ = 50.45°,  cos φ = 0.63673

сторона тайла на z = 19 = 256 · 156543.0339 · cos φ / 2¹⁹ = 48.7 м
клітинок по ширині      = 3000 / 48.7 = 61.6  →  63 (з краями)
клітинок по висоті      = 2000 / 48.7 = 41.1  →  43
на z = 19               = 63 · 43 = 2709
рівні 18, 17, 16, …     ≈ 2709 · (1/4 + 1/16 + …) ≈ 903
разом                   ≈ 3612 клітинок

із загальною сталою:  3612 · 13652 =  49 311 024  ≈  49 МБ
з виміряним тайлом:   3612 · 41000 = 148 092 000  ≈ 148 МБ
```

Оператор побачив «49 МБ», увімкнув телефон роздавачем і поїхав у поле. Приїде втричі більше — і виявиться це посеред завантаження.

Виміряти справжнє середнє нескладно, і робити це треба на робочому рівні й на характерній місцевості: jpeg над однорідною водою чи снігом важить утричі менше, ніж над лісом чи забудовою.

```python
# average_tile.py — виміряти середній тайл свого сервера на робочому рівні
import random, statistics, urllib.request

TEMPLATE = "https://tiles.skylark.example/ortho/{z}/{x}/{y}.jpg"
TOKEN    = "ce9f4a2b18"
Z        = 18
X0, X1   = 153280, 153320      # прямокутник типової ділянки в номерах клітинок
Y0, Y1   = 88370,  88400

sizes = []
for _ in range(100):
    x, y = random.randint(X0, X1), random.randint(Y0, Y1)
    req = urllib.request.Request(TEMPLATE.format(z=Z, x=x, y=y),
                                 headers={"User-Token": TOKEN})
    with urllib.request.urlopen(req) as r:
        if r.status == 200:
            sizes.append(len(r.read()))

print("середнє", round(statistics.mean(sizes)))
print("медіана", round(statistics.median(sizes)))
```

Якщо середнє помітно більше за медіану — оцінку тягне вгору жменя важких клітинок. Брати все одно треба середнє: станція рахує суму, а не типовий випадок.

### Порожня адреса відрізає не тільки мережу

Повертати порожній рядок із `_getURL` — це єдиний спосіб сказати «цього тайла не існує». Працює він добре: об'єкт-відповідь не створюється, тайл не приходить, і карта показує розтягнутого предка з нижчого рівня. Розмиття замість дірки — саме те, чого хочеться на рівнях, де в джерела нічого немає.

Але перевірка порожнечі, як видно зі схеми вище, стоїть **перед** читанням з бази. Тому умова всередині `_getURL` мусить залежати лише від сталих. Ось поширений і привабливий варіант, який ламає все:

```cpp
QString SkyOrthoMapProvider::_getURL(int x, int y, int zoom) const
{
    if (getToken().isEmpty()) {
        return QString();          // ⚠️ так НЕ можна
    }
    // …
}
```

Виглядає обачно: немає токена — немає сенсу питати сервер. Насправді того дня, коли оператор випадково зітре поле з ключем, зникнуть і ті знімки, які були завантажені наперед і чесно лежать на диску. Помилки не буде, у журналі порожньо, карта просто біла. Умова, що залежить від змінного стану — токена, наявності мережі, часу доби, — перетворює порожню адресу з позначки «даних не існує» на вимикач кеша.

Другий бік тієї самої монети — завантажувач районів. Він будує запит так само, а на непридатну адресу реагує ось як:

```cpp
if (!request.url().isValid()) {
    setErrorCount(_errorCount + 1);
    delete tile;
    continue;
}
```

Тобто клітинка мовчки пропускається, а лічильник помилок росте. Саме тому межа рівнів мусить стояти в **обох** місцях. Уявімо, що `getTileCount` ми перевизначити забули, а оператор вибрав рівні до двадцять першого. На ділянці з нашого прикладу він побачить в оцінці ще п'ятдесят чотири тисячі клітинок, яких ніхто ніколи не попросить. Завантаження дійде до кінця — і покаже рівно стільки ж помилок замість того, щоб просто не пропонувати рівнів, де знімків немає.

### Заглушка з кодом 200 оселяється в кеші назавжди

Тайл, що приїхав мережею, потрапляє в базу після однієї-єдиної змістовної перевірки, і та перевірка зашита під конкретне джерело:

```cpp
if (mapProvider->isBingProvider() && (image == _bingNoTileImage)) {
    setError(QGeoTiledMapReply::CommunicationError, tr("Bing Tile Above Zoom Level"));
    return;
}
```

Bing на завеликому рівні віддає код 200 і картинку з написом «зображення недоступне», тому станція тримає її еталонні байти у своїх ресурсах і звіряє кожну відповідь. Для будь-якого іншого провайдера такої гілки немає, і гачка «а це взагалі схоже на тайл?» теж немає. Наша сіра заглушка з кодом 200 пройде як звичайний знімок, ляже в базу під законним ключем і показуватиметься навіть тоді, коли на сервері з'являться справжні знімки цього рівня.

Порядок лікування — від дешевого до дорогого. Найдешевше: **виправити сервер**, бо він наш. Немає знімків — треба відповідати `404`, а не `200` із картинкою; тоді станція отримає помилку, нічого не збереже й покаже предка. Далі йде та сама межа рівнів у `_getURL`: те, чого не питали, не може приїхати заглушкою. Якщо ж сервер чужий і змінити його не можна — лишається [зворотний проксі](book:programming/reverse-proxy) перед ним, який перетворює заглушку на чесний `404`. І тільки в останню чергу — латка в апстримі за зразком гілки для Bing, тобто ще один чужий файл у нашому дифі.

Окремо: помилка сервера, віддана як HTML чи JSON із кодом 200, теж пройде. Формат станція визначає за першими байтами відповіді:

```cpp
if (image.startsWith(pngSignature))  return QStringLiteral("png");
if (image.startsWith(jpegSignature)) return QStringLiteral("jpg");
if (image.startsWith(gifSignature))  return QStringLiteral("gif");
return _imageFormat;
```

Розпізнаються рівно три сигнатури. Усе інше — сторінка помилки, webp, avif, векторний тайл — дістане той рядок, який ми оголосили в конструкторі. Тому формат треба оголошувати чесно: назвати webp форматом `png` означає покласти в базу байти, які потім нікому не вдасться намалювати. І тому ж уся надія на код відповіді: якщо сервер каже 200, станція йому вірить.

### Токен їде в заголовку, якого не існує в природі

Остання пастка — і найчастіша з усіх. Токен, повернений з `getToken`, станція кладе ось так:

```cpp
request.setRawHeader("User-Token", token);
```

Це не `Authorization`, не `X-Api-Key` і взагалі не стандартний заголовок — це власна вигадка станції. Наслідок прямий: якщо сервер очікує на `Authorization: Bearer …`, то `getToken` йому не допоможе ніяк, скільки б правильним не був сам токен.

Виходів два. Свій сервер можна навчити читати саме `User-Token` — це один рядок у налаштуваннях веб-сервера, і саме тому в нашій умові сказано, що сервер наш. Чужий сервер, який вимагає свого заголовка, лікується або токеном у самій адресі всередині `_getURL` — так робить Mapbox, підставляючи `access_token=` у хвіст запиту, — або тим самим зворотним проксі, який додасть потрібний заголовок від себе.

І дрібниця, про яку варто знати заздалегідь: токен не входить у ключ тайла. Ключ складається з номера джерела й трьох чисел клітинки — отже, зміна токена не робить кеш недійсним, і це добре. Але два різні токени, що дають різні знімки (скажімо, пробний доступ зі старими знімками й повний зі свіжими), зіткнуться на тих самих ключах, і в базі виживе те, що приїхало першим. Якщо таке можливе — це не пастка кеша, а привід завести два провайдери з різними назвами: два об'єкти в списку означають два різні номери, а отже, два різні простори ключів. Що станеться з цими ключами далі, коли оператор завантажить район наперед, — тема [офлайн-карт](book:qgroundcontrol/offline-maps).
