# 📋 Довідник інтерфейсу бібліотеки відображення Ено

Прикладний програмувальний інтерфейс бібліотеки `libhenon` розроблений для моделювання, обчислення та цифрового аналізу дискретного відображення Ено у науково-технічних застосунках, системах криптографічного захисту даних та генераторах псевдовипадкових чисел. Інтерфейс забезпечує повний контроль над параметрами нелінійності й дисипативності, реалізує швидку ітерацію орбіт у двовимірному фазовому просторі, надає засоби обчислення дотичного лінійного відображення для оцінки повного спектра показників Ляпунова, а також містить функції аналітичного знаходження нерухомих точок системи та їхньої лінійної стійкості.

Бібліотека поставляється у вигляді двоїстого інтерфейсу: низькорівневого C99-заголовочного файла `henon.h` з гарантією двійкової сумісності (ABI) та нульовими накладними витратами, а також об'єктно-орієнтованої C++20-обгортки `<henon/map.hpp>`, яка використовує сучасні семантики переміщення, опрацювання помилок через семантику `std::expected` та безалокаційні контейнери.

## 1. Загальні припушення та інваріанти інтерфейсу

Бібліотека `libhenon` розроблена із дотриманням суворих вимог до обчислювальної стійкості, детермінованості результатів та безпеки роботи з пам'яттю. Усі обчислювальні рутини є повністю потокобезпечними та не використовують внутрішніх глобальних станів або несинхронізованих статичних буферів. Кожен виклик обчислення орбіти є строго чистим функціональним перетворенням, результат якого залежить виключно від переданих параметрів та початкового стану системи.

При використанні низькорівневого C-інтерфейсу викликач зобов'язаний самостійно виділяти пам'ять під вихідні масиви орбіт та гарантувати, що передані вказівники не є нульовими (`NULL`). Всі функції C-інтерфейсу повертають код стану `henon_status_t`, який повинен обов'язково перевірятися перед подальшим використанням отриманих даних. У разі виникнення арифметичної помилки чи розбіжності траєкторії функція повертає відповідний код помилки, залишаючи вихідний буфер у безпечному стані без витоків пам'яті.

Високорівневий C++20-інтерфейс обгортає низькорівневі C-функції у тип `std::expected<T, Status>`, усуваючи потребу у винятках C++ та забезпечуючи зручне опрацювання помилок на рівні компіляції. Клас `henon::Map` є незмінним (immutable) після створення, що дозволяє безпечно використовувати один екземпляр у декількох паралельних потоках виконання без блокувань та мутексів.

## 2. Структури даних та параметри

Низькорівневий C-інтерфейс та високорівневий C++20-інтерфейс визначають взаємно сумісні типи даних для передачі параметрів та координат фазового простору.

### 2.1 Структура `henon_params_t` та тип `henon::Params`

Параметри системи задають двохпараметричне сімейство відображень Ено. Поле `a` відповідає за нелінійний зсув фазової площини по вертикалі. Фізичний зміст параметра `a` полягає у викривленні квадратичної параболи. При збільшенні `a` від 0 до 1.42 система проходить через каскад біфуркацій подвоєння періоду Фейгенбаума, входячи в область детермінованого хаосу. Значення `a > 1.42` призводить до кризи атрактора, при якій траєкторія залишає область притягання та прямує до мінус нескінченності.

Параметр `b` задає коефіцієнт стискання двовимірного об'єму фазового простору за один крок. При `|b| < 1` система є дисипативною, і початкова площа тане зі швидкістю `|b|^n`. При `b = 0.3` за кожен крок площа зменшується на 70 %. Значення `b = 0` є виродженим, оскільки відображення втрачає двовимірність і перетворюється на одновимірне незворотне логістичне відображення. Значення `|b| >= 1` позбавляє систему атрактора.

### 2.2 Структура `henon_point_t` та тип `henon::Point`

Структура `henon_point_t` представляє точку `(x, y)` у двовимірному фазовому просторі. Поле `x` є головною динамічною змінною системи, яка при перетині Пуанкаре відповідає основній координаті фізичного осцилятора чи зміщенню контуру. Поле `y` являє собою допоміжну змінну затримки, яка виражає стан попереднього кроку `y[n] = b * x[n-1]`. Обчислювальна точність обох полів строго дорівнює 64-бітам (формат `double` стандарту IEEE 754).

### 2.3 Структура `henon_lyapunov_t` та тип `henon::LyapunovResult`

Містить повний спектр показників Ляпунова, обчислений шляхом інтегрування дотичного лінійного відображення. Поле `lambda_1` зберігає старший показник Ляпунова, який для хаотичного режиму є строго додатним (`λ₁ ≈ +0.419`). Поле `lambda_2` зберігає молодший показник Ляпунова, який характеризує швидкість стискання фазового об'єму (`λ₂ ≈ -1.624`). Поле `kaplan_yorke` містить розраховану фрактальну розмірність атрактора `D_KY = 1 + λ₁ / |λ₂| ≈ 1.258`. Поле `converged` інформує про досягнення заданої чисельної точності осереднення.

### 2.4 Структура `henon_fixed_points_t` та тип `henon::FixedPoints`

Зберігає координати двох нерухомих точок `p1` та `p2`, отриманих аналітичним розв'язком квадратного рівняння `a*x² + (1-b)*x - 1 = 0`. Прапорець `is_real` дорівнює `true`, якщо дискримінант рівняння є додатним, що гарантує існування дійсних сідлових точок у фазовій площині.

:::tabs
```c
/* C99: Структури параметрів та точок у henon.h */

typedef struct {
    double a; /* Параметр нелінійності згину фазової площини (за замовчуванням 1.4) */
    double b; /* Параметр дисипативності та стискання площі (за замовчуванням 0.3) */
} henon_params_t;

typedef struct {
    double x; /* Координата x фазового стану */
    double y; /* Координата y фазового стану */
} henon_point_t;

typedef struct {
    double lambda_1;     /* Старший показник Ляпунова */
    double lambda_2;     /* Молодший показник Ляпунова */
    double kaplan_yorke; /* Оцінка фрактальної розмірності D_KY */
    bool converged;      /* Прапорець успішної збіжності */
} henon_lyapunov_t;

typedef struct {
    henon_point_t p1;   /* Первинна нерухома точка (головне сідло) */
    henon_point_t p2;   /* Вторинна нерухома точка (граничне сідло) */
    bool is_real;       /* Прапорець дійсності коренів (true при D > 0) */
} henon_fixed_points_t;

typedef enum {
    HENON_OK = 0,                  /* Успішне завершення операції */
    HENON_ERROR_DIVERGED = 1,      /* Траєкторія розбіглася (|x| > 1e4) */
    HENON_ERROR_INVALID_PARAM = 2, /* Вироджені параметри (b == 0) */
    HENON_ERROR_NULL_POINTER = 3   /* Передано нульовий вказівник */
} henon_status_t;
```

```cpp
namespace henon {

struct Params {
    double a{1.4}; // Параметр нелінійності зсуву
    double b{0.3}; // Параметр дисипації площі
};

struct Point {
    double x{0.0}; // Координата x
    double y{0.0}; // Координата y
};

struct LyapunovResult {
    double lambda_1{0.0};     // Старший показник Ляпунова
    double lambda_2{0.0};     // Молодший показник Ляпунова
    double kaplan_yorke{0.0}; // Фрактальна розмірність
    bool converged{false};    // Прапорець збіжності
};

struct FixedPoints {
    Point p1{};           // Первинна нерухома точка
    Point p2{};           // Вторинна нерухома точка
    bool is_real{false};  // Прапорець дійсності коренів
};

enum class Status {
    Ok = 0,
    Diverged = 1,
    InvalidParam = 2,
    NullPointer = 3
};

} // namespace henon
```

## 3. Інтерфейс підсистеми обчислень

Обидва інтерфейси забезпечують виконання прямого кроку, оберненого кроку, серійної генерації точок орбіти, обчислення спектра Ляпунова та пошуку нерухомих точок.

### 3.1 Функція `henon_step` та метод `Map::step`

Обчислює один крок прямого відображення `(x[n], y[n]) ↦ (x[n+1], y[n+1])`. Функція виконує обчислення за формулою `x[n+1] = 1 - a * x[n]² + y[n]` та `y[n+1] = b * x[n]`. Функція є атомарною, підтримує інлайнінг і не виконує жодних алокацій пам'яті. Вона призначена для використання у високошвидкісних циклах моделювання, де потрібна максимальна продуктивність процесора.

### 3.2 Функція `henon_step_inverse` та метод `Map::inverse_step`

Виконує один крок оберненого відображення, що дозволяє рухатися назад у часі фазового простору. Якщо параметр `b == 0`, обернене відображення є математично невизначеним, і функція повертає код помилки `HENON_ERROR_INVALID_PARAM` (або `std::unexpected(Status::InvalidParam)` у C++).

### 3.3 Функція `henon_iterate_batch` та метод `Map::orbit`

Здійснює серійне моделювання орбіти. Алгоритм спочатку виконує `transient` кроків утримання точки без збереження координат, що дозволяє траєкторії осісти на дивний атрактор від довільного стартового стану. Після цього функція записує `count` послідовних точок у наданий масив. Якщо під час моделювання координата `|x|` перевищує поріг `1e4`, обчислення переривається з кодом `HENON_ERROR_DIVERGED`.

### 3.4 Функція `henon_compute_lyapunov` та метод `Map::lyapunov`

Здійснює обчислення показників Ляпунова за допомогою інтегрування дотичного вектора. Процедура автоматично здійснює нормування вектора розходження на кожному кроці для запобігання чисельному переповненню та накопичує логарифми коефіцієнтів розтягування.

```cpp
// C++20: Клас henon::Map у <henon/map.hpp>

namespace henon {

class Map {
public:
    constexpr Map() noexcept : params_{1.4, 0.3} {}
    constexpr explicit Map(Params params) noexcept : params_(params) {}
    constexpr Map(double a, double b) noexcept : params_{a, b} {}

    [[nodiscard]] constexpr Params params() const noexcept { return params_; }
    constexpr void set_params(Params p) noexcept { params_ = p; }

    [[nodiscard]] constexpr Point step(Point pt) const noexcept {
        return Point{
            .x = 1.0 - params_.a * pt.x * pt.x + pt.y,
            .y = params_.b * pt.x
        };
    }

    [[nodiscard]] std::expected<Point, Status> inverse_step(Point next) const noexcept {
        if (std::abs(params_.b) < 1e-15) {
            return std::unexpected(Status::InvalidParam);
        }
        double x_prev = next.y / params_.b;
        double y_prev = next.x - 1.0 + params_.a * (next.y / params_.b) * (next.y / params_.b);
        return Point{.x = x_prev, .y = y_prev};
    }

    [[nodiscard]] std::expected<std::vector<Point>, Status> 
    orbit(Point start, std::size_t transient, std::size_t count) const {
        std::vector<Point> buf(count);
        henon_point_t c_start{start.x, start.y};
        henon_params_t c_params{params_.a, params_.b};
        henon_status_t st = henon_iterate_batch(c_start, c_params, transient, count, 
                                                reinterpret_cast<henon_point_t*>(buf.data()));
        if (st != HENON_OK) {
            return std::unexpected(static_cast<Status>(st));
        }
        return buf;
    }

    [[nodiscard]] std::expected<LyapunovResult, Status> 
    lyapunov(Point start, std::size_t transient, std::size_t steps) const {
        henon_lyapunov_t c_res{};
        henon_point_t c_start{start.x, start.y};
        henon_params_t c_params{params_.a, params_.b};
        henon_status_t st = henon_compute_lyapunov(c_start, c_params, transient, steps, &c_res);
        if (st != HENON_OK) {
            return std::unexpected(static_cast<Status>(st));
        }
        return LyapunovResult{
            .lambda_1 = c_res.lambda_1,
            .lambda_2 = c_res.lambda_2,
            .kaplan_yorke = c_res.kaplan_yorke,
            .converged = c_res.converged
        };
    }

    [[nodiscard]] FixedPoints fixed_points() const noexcept {
        henon_params_t c_params{params_.a, params_.b};
        henon_fixed_points_t c_fp = henon_find_fixed_points(c_params);
        return FixedPoints{
            .p1 = Point{c_fp.p1.x, c_fp.p1.y},
            .p2 = Point{c_fp.p2.x, c_fp.p2.y},
            .is_real = c_fp.is_real
        };
    }

private:
    Params params_;
};

} // namespace henon
```

## 4. Аналіз межевих режимів та рекомендації щодо використання

При роботі з бібліотекою `libhenon` важливо враховувати математичні обмеження чисельних алгоритмів:
- **Значення параметра нелінійності `a`:** Для класичного атрактора використовують `a = 1.4`. При `a > 1.42` відбувається криза межі атрактора, і траєкторія прямує до мінус нескінченності. Виклики функцій у цьому режимі повертають статус `HENON_ERROR_DIVERGED`.
- **Значення параметра дисипації `b`:** Необхідно стежити, щоб `|b| < 1` та `b ≠ 0`. Значення `b = 0` генерує помилку `HENON_ERROR_INVALID_PARAM`.
- **Вибір кількості кроків транзієнту `transient`:** Рекомендоване значення становить не менше 500–1000 кроків. Це гарантує, що початковий стан, вибраний довільно у фазовій площині, встигне осісти на дивний атрактор до початку запису орбіти.
- **Обчислення Ляпунова `steps`:** Рекомендована кількість ітерацій становить від `10⁵` до `10⁶` кроків для досягнення статистичної точності осереднення логарифмів до третього знака після коми.

## 5. Комплексний приклад використання C та C++ API

Нижче наведено порівняльний приклад використання інтерфейсу бібліотеки `libhenon` мовами C та C++.

:::tabs
```c
/* henon_demo.c — Приклад використання C API henon.h */
#include <stdio.h>
#include <henon.h>

int main(void) {
    henon_params_t params = henon_default_params();
    henon_point_t start = { .x = 0.1, .y = 0.1 };

    /* 1. Розрахунок нерухомих точок */
    henon_fixed_points_t fp = henon_find_fixed_points(params);
    if (fp.is_real) {
        printf("C: Нерухома точка p1 = (%.5f, %.5f)\n", fp.p1.x, fp.p1.y);
    }

    /* 2. Розрахунок показника Ляпунова */
    henon_lyapunov_t lyap;
    if (henon_compute_lyapunov(start, params, 1000, 100000, &lyap) == HENON_OK) {
        printf("C: lambda_1 = %.5f, D_KY = %.5f\n", lyap.lambda_1, lyap.kaplan_yorke);
    }

    return 0;
}
```
```cpp
// henon_demo.cpp — Приклад використання C++20 API <henon/map.hpp>
#include <iostream>
#include <henon/map.hpp>

int main() {
    henon::Map map(1.4, 0.3);

    // 1. Розрахунок нерухомих точок
    auto fp = map.fixed_points();
    if (fp.is_real) {
        std::cout << "C++: Нерухома точка p1 = (" << fp.p1.x << ", " << fp.p1.y << ")\n";
    }

    // 2. Розрахунок показника Ляпунова
    auto lyap_res = map.lyapunov({0.1, 0.1}, 1000, 100000);
    if (lyap_res) {
        std::cout << "C++: lambda_1 = " << lyap_res->lambda_1 
                  << ", D_KY = " << lyap_res->kaplan_yorke << '\n';
    }

    return 0;
}
```
