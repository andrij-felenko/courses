# ⚙️ Моделювання відображення Ено: обчислення орбіт, показників Ляпунова та побудова атрактора

Чисельне моделювання дискретного відображення Ено є фундаментальним інструментом обчислювальної фізики нелінійних явищ, теорії детермінованого хаосу та аналізу складної динаміки. Оскільки відображення Ено задається різницевими рівняннями дискретного часу, воно не потребує наближеного чисельного інтегрування звичайних диференціальних рівнянь (таких як класичні методи Рунге–Кутти четвертого порядку чи методи Ейлера). Це повністю усуває похибки дискретизації часового кроку, проте висуває суворі вимоги щодо вибору числової точності плаваючої крапки, належної фільтрації перехідних процесів та обов'язкового розпізнавання аварійних ситуацій чисельного переповнення.

Програмний комплекс чисельного моделювання відображення Ено розв'язує три головні приклади обчислювальних задач:
1. **Генерація масивів точок орбіти** для візуалізації фазового портрета та фрактальної шаруватої структури дивного атрактора.
2. **Фільтрація перехідного процесу (транзієнту)**, необхідна для вилучення початкових точок, які знаходяться поза атрактором і відбивають тимчасове осідання траєкторії.
3. **Обчислення старшого показника Ляпунова `λ₁`**, яке реалізується шляхом сумісного інтегрування базової траєкторії та дотичного лінійного вектора з процедурою ортогоналізації та нормалізації Ґрама–Шмідта.

## 1. Обчислювальний алгоритм та математична основа

Рівняння відображення Ено описують еволюцію координат у фазовій площині:

```
x[n+1] = 1 - a·x[n]² + y[n]
y[n+1] = b·x[n]
```

Для обчислення найбільшого показника Ляпунова `λ₁` поруч із головною траєкторією `(x[n], y[n])` прораховують нескінченно малий дотичний вектор `w[n] = (dx[n], dy[n])^T`. Його еволюція на кожному кроці визначається множенням на матрицю Якобі `J(x[n], y[n])`:

```
w[n+1] = J(x[n], y[n]) · w[n]
       = [ [ -2·a·x[n],  1 ],
           [  b,         0 ] ] · [ [ dx[n] ], [ dy[n] ] ]
```

Оскільки при наявності хаосу довжина дотичного вектора росте експоненційно `||w[n]|| ≈ ||w[0]|| · e^(λ₁·n)`, безпосереднє множення вже через кілька десятків кроків призводить до арифметичного переповнення типів плаваючої крапки. Щоб запобігти цьому, після кожного кроку обчислюють поточний коефіцієнт розтягування `L[n] = ||w[n+1]||`, нормалізують дотичний вектор `w[n+1] ↦ w[n+1] / L[n]`, а коефіцієнти розтягування накопичують у логарифмічній сумі:

```
λ₁ ≈ (1 / N) · ∑_{n=1}^{N} ln ( ||w[n]|| )
```

Цей метод гарантує числову стійкість обчислення та швидку збіжність до точного значення `λ₁ ≈ 0.419` при `a = 1.4, b = 0.3`.

З обчислювального погляду алгоритм моделювання відображення Ено має ідеальну часову складність `O(N)` та пам'ятневу складність `O(1)` для обчислення показників Ляпунова чи `O(N)` для збереження масиву точок атрактора. Оскільки на кожен крок припадає лише одне множення, одне піднесення до квадрата та два додавання, сучасний процесор виконує понад 100 мільйонів ітерацій за секунду на одному ядрі.

## 2. Реалізація коду

Нижче наведено повноцінну реалізацію чисельного моделювання та обчислення показника Ляпунова мовами C та C++.

```c
/* henon_sim.c — Моделювання відображення Ено та обчислення показників Ляпунова мовою C */
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <stdbool.h>

typedef struct {
    double a;
    double b;
} HenonParams;

typedef struct {
    double x;
    double y;
} Point2D;

/* Один крок відображення Ено */
static inline Point2D henon_step(Point2D pt, HenonParams p) {
    Point2D next;
    next.x = 1.0 - p.a * pt.x * pt.x + pt.y;
    next.y = p.b * pt.x;
    return next;
}

/* Обчислення найбільшого показника Ляпунова */
double compute_lyapunov_c(HenonParams p, Point2D start, size_t transient, size_t steps) {
    Point2D pt = start;

    /* 1. Пропускаємо перехідний процес */
    for (size_t i = 0; i < transient; ++i) {
        pt = henon_step(pt, p);
        if (fabs(pt.x) > 1e6) return -1.0; /* Атрактор розрушився */
    }

    /* 2. Ініціалізуємо дотичний вектор розходження */
    double dx = 1.0;
    double dy = 0.0;
    double log_sum = 0.0;

    for (size_t i = 0; i < steps; ++i) {
        /* Множення на матрицю Якобі J(x,y) */
        double next_dx = -2.0 * p.a * pt.x * dx + dy;
        double next_dy = p.b * dx;

        /* Обчислюємо довжину збурення */
        double norm = sqrt(next_dx * next_dx + next_dy * next_dy);
        if (norm < 1e-12) break;

        log_sum += log(norm);

        /* Нормалізуємо дотичний вектор */
        dx = next_dx / norm;
        dy = next_dy / norm;

        /* Крок базової траєкторії */
        pt = henon_step(pt, p);
    }

    return log_sum / (double)steps;
}

int main(void) {
    HenonParams params = { .a = 1.4, .b = 0.3 };
    Point2D init_state = { .x = 0.1, .y = 0.1 };

    double lyap = compute_lyapunov_c(params, init_state, 1000, 100000);
    printf("Показник Ляпунова (C): lambda_1 = %.5f\n", lyap);

    return 0;
}
```
```cpp
// henon_sim.cpp — Ідіоматична реалізація відображення Ено мовою C++20
#include <iostream>
#include <vector>
#include <cmath>
#include <array>
#include <fstream>
#include <expected>
#include <string>

namespace henon {

struct Params {
    double a{1.4};
    double b{0.3};
};

struct Point {
    double x{0.0};
    double y{0.0};
};

enum class SimError {
    DivergedToInfinity,
    InvalidSteps
};

class Model {
public:
    explicit Model(Params params) : params_(params) {}

    [[nodiscard]] Point step(Point current) const noexcept {
        return Point{
            .x = 1.0 - params_.a * current.x * current.x + current.y,
            .y = params_.b * current.x
        };
    }

    [[nodiscard]] std::expected<std::vector<Point>, SimError> generate_orbit(
        Point start, std::size_t transient, std::size_t count) const {
        
        Point pt = start;
        for (std::size_t i = 0; i < transient; ++i) {
            pt = step(pt);
            if (std::abs(pt.x) > 1e4) {
                return std::unexpected(SimError::DivergedToInfinity);
            }
        }

        std::vector<Point> orbit;
        orbit.reserve(count);
        for (std::size_t i = 0; i < count; ++i) {
            pt = step(pt);
            if (std::abs(pt.x) > 1e4) {
                return std::unexpected(SimError::DivergedToInfinity);
            }
            orbit.push_back(pt);
        }
        return orbit;
    }

    [[nodiscard]] std::expected<double, SimError> compute_lyapunov(
        Point start, std::size_t transient, std::size_t steps) const {
        
        Point pt = start;
        for (std::size_t i = 0; i < transient; ++i) {
            pt = step(pt);
            if (std::abs(pt.x) > 1e4) {
                return std::unexpected(SimError::DivergedToInfinity);
            }
        }

        std::array<double, 2> tangent{1.0, 0.0};
        double log_sum = 0.0;

        for (std::size_t i = 0; i < steps; ++i) {
            double next_dx = -2.0 * params_.a * pt.x * tangent[0] + tangent[1];
            double next_dy = params_.b * tangent[0];

            double norm = std::hypot(next_dx, next_dy);
            if (norm < 1e-12) break;

            log_sum += std::log(norm);
            tangent = {next_dx / norm, next_dy / norm};
            pt = step(pt);
        }

        return log_sum / static_cast<double>(steps);
    }

private:
    Params params_;
};

} // namespace henon

int main() {
    henon::Params params{.a = 1.4, .b = 0.3};
    henon::Model model(params);

    auto result = model.compute_lyapunov({0.1, 0.1}, 1000, 100000);
    if (result) {
        std::cout << "Показник Ляпунова (C++): lambda_1 = " << *result << '\n';
    } else {
        std::cerr << "Помилка обчислення: траєкторія розбіглася\n";
    }

    return 0;
}
```

## 3. Практичні підводні камені та числові пастки

Під час розробки програмного забезпечення моделювання відображення Ено слід звертати увагу на специфічні обчислювальні проблеми:

1. **Критична необхідність подвійної точності (`double`):** Використання 32-бітових чисел з плаваючою крапкою `float` через накопичення похибок заокруглення призводить до хибного зациклення орбіти на коротких штучних періодах вже через `10⁴` кроків. Завжди слід використовувати 64-бітовий тип `double`.
2. **Обов'язковість відсікання перехідного процесу:** Перші 500–1000 кроків ітерації від довільного старту необхідно безвідхідно відкидати, оскільки початкова точка перебуває поза атрактором і демонструє нестаціонарну поведінку.
3. **Криза атрактора та розбіжність:** При `a > 1.42` (наприклад `a = 1.5`) траєкторія після кількох сотень кроків залишає область притягання і прямує до нескінченності. Код повинен обов'язково містити перевірку `abs(x) > 1e4` для запобігання генерації значень `NaN` та `Inf`.
4. **Вибір початкового дотичного вектора:** Напрямок початкового збурення `w[0]` практично не впливає на кінцеве значення `λ₁`, оскільки вже за перші 20–30 кроків матриця Якобі повертає вектор вздовж напрямку найшвидшого розходження (власного вектора найбільшого власного значення).
5. **Векторизація SIMD та кеш-пам'ять:** При моделюванні ансамблів із тисяч орбіт паралельно (наприклад, для побудови басейнів притягання чи біфуркаційних діаграм) дані слід упаковувати у структури масивів (Structure of Arrays, SoA) `double x_arr[]`, `double y_arr[]` замість масивів структур. Це дозволяє компілятору автовекторизувати обчислення за допомогою інструкцій AVX2 / AVX-512, прискорюючи виконання у 4–8 разів.
6. **Оптимізація обчислення логарифмів:** Операція `std::log()` є відносно дорогою на кожній ітерації. Для прискорення розрахунку показника Ляпунова можна накопичувати не логарифми `ln(norm)`, а добуток квадратів норми `norm²`, викликаючи логарифм лише один раз кожні 50–100 кроків (після чого нормувати вектор). Це дає прискорення алгоритму у 2-3 рази без втрати точності.
7. **Паралелізація OpenMP та GPU:** Для обчислення сітки біфуркаційної діаграми при мільйонах значений параметра `a` цикл за значеннями `a` є повністю незалежним (embarrassingly parallel). Його розпаралелюють через директиву `#pragma omp parallel for` у C/C++ або виконують на GPU через CUDA/OpenCL, де кожна нитка обробляє власне значення `a`.

## 4. Вимоги до обробки даних та експорту результатів

При зберіганні результатів чисельного моделювання відображення Ено у текстові файли CSV чи двійкові формати типу HDF5 слід гарантувати збереження повної точності значень. Використання стандартного форматного виводу `printf("%.2f")` обтинає молодші біти координат, через що при повторному зчитуванні згенерованого ряду траєкторія миттєво відхиляється від оригінального обчислення внаслідок хаотичної чутливості до початкових умов.

Для збереження повної точності плаваючої крапки слід використовувати специфікатор виводу `%.17g` у мові C чи `std::setprecision(17)` у C++, що гарантує збереження всіх 53 бітів мантиси стандарту IEEE 754 та забезпечує повну відтворюваність чисельних експериментів.
