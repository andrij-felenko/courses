# 📋 Інтерфейс та довідник розв'язувача рівняння Шредінгера

Цей довідник описує специфікацію публічного програмувального інтерфейсу (API) C/C++ бібліотеки чисельного розв'язання одновимірного стаціонарного рівняння Шредінгера `qs_schrodinger_1d`. Документ визначає структури даних, конфігураційні параметри, типи крайових умов, специфікацію полів результатів, коди повернення, граничні умови, механізми забезпечення обчислювальної стійкості та функціональний контракт для інтеграції розв'язувача у напівпровідникові та квантово-хімічні симулятори.

## Концептуальна архітектура та принципи побудови API

Бібліотека `qs_schrodinger_1d` призначена для швидкого та високоточного розрахунку спектра власних значень енергії `Eₙ` та відповідних ортонормованих хвильових функцій `ψₙ(x)` для заданого користувачем потенціального профілю `V(x)` на одновимірній просторовій сітці. Архітектура бібліотеки спирається на три ключові принципи: модульність, гарантована обчислювальна стійкість та відсутність побічних ефектів при роботі у багатопотокових середовищах.

Модуль надає два типи обчислювальних ядер:
1. **Трьохточкова скінченно-різницева матрична діагоналізація (Matrix Eigen-solver):** забезпечує швидкий та гарантований пошук усіх власних станів шляхом побудови тридіагональної матриці Гамільтоніана та залучення високооптимізованих процедур діагоналізації. Цей метод виступає надійним резервним варіантом при роботі зі складними багатоямними потенціалами.
2. **Алгоритм зшивання Нумерова (Numerov Shooting Solver):** високоточний прицільний пошук конкретного власним станом з підтримкою двонапрямленого зшивання хвильових функцій у точці повороту. Цей метод забезпечує 4-й порядок глобальної точності за кроком сітки.

Для запобігання витокам пам'яті та спрощення інтеграції у високорівневі мови програмування (Python, Julia, Rust, C#) бібліотека дотримується суворого контракту керування ресурсами: розв'язувач створюється явної функцією ініціалізації, а всі виділені масиви результатів звільняються спеціалізованою функцією очищення.

## Детальний опис структур даних та типів

### `qs_boundary_type_t` / `BoundaryType` — Перелік типів крайових умов

Цей перелічувальний тип визначає математичний та фізичний характер крайових умов на лівій (`x_min`) та правій (`x_max`) межах розрахункової області.

Вибір крайових умов безпосередньо впливає на форму обчислювальної матриці Гамільтоніана та на спектральні властивості системи:

- **`QS_BOUNDARY_DIRICHLET` / `BoundaryType::Dirichlet`:** Однорідні умови Дирихле. Задають нульове значення хвильової функції на межах розрахункової області (`ψ(x_bound) = 0`). Вони використовуються для моделювання квантових систем у потенціальних ямах із нескінченно високими стінками, ізольованих наноструктур чи квантових точок, де ймовірність виходу частинки за межі сітки є зневажливо малою.
- **`QS_BOUNDARY_NEUMANN` / `BoundaryType::Neumann`:** Однорідні умови Неймана. Задають нульове значення першої похідної хвильової функції на межах (`dψ/dx |_(x_bound) = 0`). Вони застосовуються для моделювання симетричних хвильових функцій у центрі симетрії або для опису відкритих меж у розрахунках електронного транспорту.
- **`QS_BOUNDARY_ROBIN` / `BoundaryType::Robin`:** Змішані умови Робіна. Визначають лінійну комбінацію значення функції та її першої похідної (`α·ψ + β·dψ/dx = 0`). Вони використовуються для опису напівпрозорих бар'єрів, контактних поверхонь та тунельних зв'язків між наноструктурами.
- **`QS_BOUNDARY_PERIODIC` / `BoundaryType::Periodic`:** Періодичні крайові умови Борна — Кармана. Вимагають тотожної рівності функцій та їхніх перших похідних на протилежних межах розрахункового інтервалу (`ψ(x_min) = ψ(x_max)` та `ψ'(x_min) = ψ'(x_max)`). Вони є базовим інструментом для розрахунку зонної структури у періодичних потенціальних рельєфах кристалічних ґраток та надґраток.

:::tabs
```c
typedef enum {
    QS_BOUNDARY_DIRICHLET = 0, /* ψ(x_bound) = 0 (нескінченні стінки, зв'язані стани) */
    QS_BOUNDARY_NEUMANN   = 1, /* dψ/dx |_(x_bound) = 0 (симетричні стани) */
    QS_BOUNDARY_ROBIN     = 2, /* α·ψ + β·dψ/dx = 0 (імпедансні / контакти) */
    QS_BOUNDARY_PERIODIC  = 3  /* ψ(x_min) = ψ(x_max), ψ'(x_min) = ψ'(x_max) (кристалічні ґратки) */
} qs_boundary_type_t;
```
```cpp
enum class BoundaryType : uint8_t {
    Dirichlet = 0, // ψ(x_bound) = 0 (нескінченні стінки, зв'язані стани)
    Neumann   = 1, // dψ/dx |_(x_bound) = 0 (симетричні стани)
    Robin     = 2, // α·ψ + β·dψ/dx = 0 (імпедансні / контакти)
    Periodic  = 3  // ψ(x_min) = ψ(x_max), ψ'(x_min) = ψ'(x_max) (кристалічні ґратки)
};
```
:::

### `qs_grid_config_t` / `GridConfig` — Конфігурація просторової сітки

Структура конфігурації сітки описує геометрію, просторове розбиття та фізичні константи розрахункової області.

Розмірність розрахункової області задається лівою та правою межами. Параметр кількості вузлів визначає крок просторової сітки `h = (x_max - x_min) / (num_points - 1)`. Фізичні параметри маси частинки та приведеної сталої Планка дозволяють виконувати обчислення як у фізичних одиницях СІ (метри, кілограми, джоулі), так і у атомарних чи безрозмірних системних одиницях.

Кожне поле структури відіграє вирішальну роль у чисельній стійкості:

- `x_min`: Ліва межа розрахункової області. Для зв'язаних станів вона повинна вибиратися достатньо далеко у класично забороненій області, щоб хвильова функція встигла експоненційно згаснути до нуля.
- `x_max`: Права межа розрахункової області. Повинна симетрично заходити у підбар'єрну область.
- `num_points`: Кількість вузлів дискретизації сітки `N`. Збільшення `N` зменшує крок `h`, покращуючи точність Нумерова у 16 разів при кожному подвоєнні `N`.
- `mass`: Ефективна маса частинки `m*`. У напівпровідникових гетероструктурах (GaAs, AlGaAs) ефективна маса електрона може становити від `0.067` до `0.1` від маси вільного електрона `m_e`.
- `hbar`: Приведена стала Планка `ℏ`. При обчисленнях у безрозмірних одиницях встановлюється рівною `1.0`.

:::tabs
```c
typedef struct {
    double x_min;        /* Ліва межа області (м або безрозмірні) */
    double x_max;        /* Права межа області */
    size_t num_points;   /* Кількість вузлів сітки N */
    double mass;         /* Ефективна маса частинки m */
    double hbar;         /* Приведена стала Планка hbar */
} qs_grid_config_t;
```
```cpp
struct GridConfig {
    double x_min{-10.0};
    double x_max{10.0};
    std::size_t num_points{1001};
    double mass{1.0};
    double hbar{1.0};
};
```
:::

| Поле | Тип | Опис | Діапазон / Значення за замовчуванням |
| :--- | :--- | :--- | :--- |
| `x_min` | `double` | Ліва межа розрахункової області (м або безрозмірні одиниці) | `x_min < x_max`, за замовчуванням `-10.0` |
| `x_max` | `double` | Права межа розрахункової області | `x_max > x_min`, за замовчуванням `+10.0` |
| `num_points` | `size_t` | Кількість вузлів сітки `N` (включаючи межі) | `N ≥ 5`, рекомендується `1001–10001` |
| `mass` | `double` | Ефективна маса частинки `m` (кг або відносна `m*`) | `mass > 0`, за замовчуванням `1.0` (маса електрона) |
| `hbar` | `double` | Приведена стала Планка `ℏ` | `hbar > 0`, за замовчуванням `1.0` |

### `qs_solver_params_t` / `SolverParams` — Параметри розв'язувача

Структура параметрів керує точністю, максимальним числом ітерацій та обраним чисельним алгоритмом розв'язувача.

Вона визначає критерій зупинки методу стрільби за відносною похибкою енергії, граничну кількість ітерацій при бісекції, а також кількість власних значень, які необхідно обчислити.

- `method`: Алгоритм обчислення. `QS_METHOD_NUMEROV` забезпечує точність 4-го порядку, а `QS_METHOD_MATRIX` гарантує відсутність пропуску власних станів.
- `tolerance`: Відносна похибка збіжності енергії `|E_new - E_old| / |E_old|`. Типове значення `1e-9` гарантує 9 значущих цифр в енергетичному спектрі.
- `max_iterations`: Поріг зупинки бісекції або методу секучих. Запобігає нескінченним циклам при складних потенціалах.
- `boundary_left`, `boundary_right`: Типи умов на лівій та правій межах.
- `num_eigenvalues`: Запитувана кількість нижчих власних станів `n_states` (наприклад, 5 станів від основного `n=0` до `n=4`).

:::tabs
```c
typedef struct {
    int method;                         /* QS_METHOD_NUMEROV або QS_METHOD_MATRIX */
    double tolerance;                   /* Допустима відносна похибка energy */
    uint32_t max_iterations;            /* Поріг ітерацій стрільби */
    qs_boundary_type_t boundary_left;   /* Умова на лівій межі */
    qs_boundary_type_t boundary_right;  /* Умова на правій межі */
    uint32_t num_eigenvalues;           /* Кількість власних значень */
} qs_solver_params_t;
```
```cpp
struct SolverParams {
    enum class Method { Numerov, Matrix } method{Method::Numerov};
    double tolerance{1e-9};
    std::uint32_t max_iterations{200};
    BoundaryType boundary_left{BoundaryType::Dirichlet};
    BoundaryType boundary_right{BoundaryType::Dirichlet};
    std::uint32_t num_eigenvalues{5};
};
```
:::

| Поле | Тип | Опис | Значення за замовчуванням |
| :--- | :--- | :--- | :--- |
| `method` | `qs_method_t` | Обраний алгоритм (`QS_METHOD_NUMEROV` або `QS_METHOD_MATRIX`) | `QS_METHOD_NUMEROV` |
| `tolerance` | `double` | Відносна похибка збіжності за енергією `ΔE / E` | `1e-9` |
| `max_iterations` | `uint32_t` | Максимальна кількість ітерацій методу стрільби | `200` |
| `boundary_left` | `qs_boundary_type_t` | Умова на лівій межі | `QS_BOUNDARY_DIRICHLET` |
| `boundary_right` | `qs_boundary_type_t` | Умова на правій межі | `QS_BOUNDARY_DIRICHLET` |
| `num_eigenvalues` | `uint32_t` | Кількість власних станів для пошуку (`n_states`) | `5` |

### `qs_eigenstate_t` / `Eigenstate` — Окремий власний стан

Ця структура зберігає всі розраховані фізичні параметри окремого `n`-го власного стану.

Вона містить порядковий номер квантового стану, обчислене значення енергії, оцінену чисельну похибку, кількість знайдених вузлів хвильової функції, а також масиви значень хвильової функції та густини ймовірності вздовж просторової сітки.

Масиви `psi` та `prob_density` автоматично нормуються бібліотекою так, що інтеграл `∫ |ψ(x)|² dx = 1`.

:::tabs
```c
typedef struct {
    uint32_t state_index;    /* Порядковий номер стану n (0 — основний стан) */
    double energy;           /* Власне значення енергії E_n */
    double energy_error;     /* Оцінена чисельна похибка dE */
    uint32_t node_count;     /* Кількість знайдених внутрішніх вузлів (перетинів нуля) */
    double *psi;             /* Вектор значень хвильової функції size = num_points */
    double *prob_density;    /* Вектор густини ймовірності |ψ|^2 size = num_points */
} qs_eigenstate_t;
```
```cpp
struct Eigenstate {
    std::uint32_t state_index{0};
    double energy{0.0};
    double energy_error{0.0};
    std::uint32_t node_count{0};
    std::vector<double> psi;
    std::vector<double> prob_density;
};
```
:::

### `qs_result_t` / `SolverResult` — Підсумковий контейнер результатів

Контейнер результатів об'єднує всі розраховані стани, просторову сітку координат, профіль потенціалу та підсумкову статистику виконання розрахунку.

Після завершення обчислень поле `status_code` містить `QS_SUCCESS` або код конкретної помилки. Поле `compute_time_us` дозволяє оцінювати продуктивність алгоритму у мікросекундах.

:::tabs
```c
typedef struct {
    uint32_t num_found;       /* Фактично знайдена кількість власних станів */
    qs_eigenstate_t *states;  /* Масив власних станів розміром num_found */
    double *x_grid;           /* Масив координат вузлів сітки size = num_points */
    double *potential_grid;   /* Масив значень потенціалу V(x) size = num_points */
    uint64_t compute_time_us; /* Час виконання розрахунку в мікросекундах */
    int status_code;          /* Код завершення (QS_SUCCESS або код помилки) */
} qs_result_t;
```
```cpp
struct SolverResult {
    std::uint32_t num_found{0};
    std::vector<Eigenstate> states;
    std::vector<double> x_grid;
    std::vector<double> potential_grid;
    std::uint64_t compute_time_us{0};
    int status_code{0};
};
```

## Функціональний контракт API

### 1. Ініціалізація та знищення об'єктів

#### `qs_solver_create`
Створює та ініціалізує новий екземпляр розв'язувача на основі переданих конфігурацій сітки та параметрів алгоритму.

:::tabs
```c
qs_solver_t* qs_solver_create(const qs_grid_config_t *grid_cfg,
                              const qs_solver_params_t *params);
```
```cpp
std::unique_ptr<NumerovSolver> create_solver(const GridConfig& grid_cfg,
                                             const SolverParams& params);
```
:::

- **Аргументи:**
  - `grid_cfg`: вказівник на конфігураційну структуру просторової сітки. Повинен бути не-`NULL`.
  - `params`: вказівник на структуру параметрів обчислювального алгоритму. Повинен бути не-`NULL`.
- **Повертає:** вказівник на непрозору структуру `qs_solver_t` або `NULL` при помилці виділення пам'яті чи некоректно заданих інтервалах.

#### `qs_solver_destroy`
Повністю звільняє всі ресурси та оперативну пам'ять, виділену для екземпляра розв'язувача. Після виклику цього методу вказівник `solver` стає недійсним.

:::tabs
```c
void qs_solver_destroy(qs_solver_t *solver);
```
```cpp
// У C++ RAII деструктор std::unique_ptr<NumerovSolver> автоматично звільняє ресурси
```
:::

### 2. Задання потенціального рельєфу

#### `qs_solver_set_potential_func`
Встановлює аналітичну потенціальну функцію `V(x)` через вказівник на функцію зворотного виклику (callback).

:::tabs
```c
typedef double (*qs_potential_fn)(double x, void *user_data);

int qs_solver_set_potential_func(qs_solver_t *solver,
                                 qs_potential_fn potential_fn,
                                 void *user_data);
```
```cpp
void set_potential_func(std::function<double(double)> potential_fn);
```
:::

- **Аргументи:**
  - `solver`: дійсний екземпляр розв'язувача.
  - `potential_fn`: користувацька функція, що обчислює `V(x)` для довільного `x`.
  - `user_data`: довільний вказівник на додатковий контекст даних користувача (може бути `NULL`).

#### `qs_solver_set_potential_array`
Встановлює дискретний потенціальний профіль `V(x)` таблично у вигляді масиву дійсних чисел.

:::tabs
```c
int qs_solver_set_potential_array(qs_solver_t *solver,
                                  const double *v_array,
                                  size_t array_length);
```
```cpp
void set_potential_array(std::span<const double> v_array);
```
:::

- **Аргументи:**
  - `solver`: дійсний екземпляр розв'язувача.
  - `v_array`: масив значень потенціалу у вузлах сітки.
  - `array_length`: довжина масиву, яка мусить строго дорівнювати `num_points`.

### 3. Запуск обчислень

#### `qs_solver_run`
Запускає обчислювальний процес знаходження власних станів та спектра енергії.

:::tabs
```c
int qs_solver_run(qs_solver_t *solver, qs_result_t *out_result);
```
```cpp
std::expected<SolverResult, int> run_solver();
```
:::

- **Аргументи:**
  - `solver`: дійсний екземпляр розв'язувача.
  - `out_result`: вказівник на структуру результату, куди записуються вихідні дані.
- **Повертає:** `QS_SUCCESS` (0) при успішному завершенні або відповідний негативний код помилки (`QS_ERR_*`).

### 4. Звільнення результатів

#### `qs_result_free`
Очищує всі динамічні масиви, виділені всередині структури `qs_result_t`.

:::tabs
```c
void qs_result_free(qs_result_t *result);
```

## Таблиця кодів помилок та статусу (`QS_ERR_*`)

Опис системних кодів помилок, які повертають функції API у разі виникнення позаштатних ситуацій чи нестійкості алгоритму.

| Код | Символьна константа | Фізична / Обчислювальна причина | Спосіб усунення |
| :--- | :--- | :--- | :--- |
| `0` | `QS_SUCCESS` | Успішне виконання обчислення | Не потрібен |
| `-1` | `QS_ERR_INVALID_PARAM` | Передано `NULL` вказівник, `num_points < 5`, або `mass ≤ 0` | Перевірити параметри ініціалізації |
| `-2` | `QS_ERR_MALLOC_FAILED` | Нестача оперативної пам'яті для створення сітки | Зменшити `num_points` або виділити системні ресурси |
| `-3` | `QS_ERR_NO_BOUND_STATES` | У ямі відсутні зв'язані стани для `E < V_max` | Перевірити глибину та ширину потенціалу `V(x)` |
| `-4` | `QS_ERR_SHOOTING_DIVERGED` | Метод стрільби не знайшов корінь за `max_iterations` | Збільшити `max_iterations` або розширити інтервал `[E_low, E_high]` |
| `-5` | `QS_ERR_NODE_MISMATCH` | Число вузлів хвильової функції не відповідає квантовому номеру `n` | Використати зшивання у точці повороту |
| `-6` | `QS_ERR_GRID_TOO_COARSE` | Крок сітки `h` занадто великий для високих станів | Збільшити `num_points` у 2–4 рази |

## Детальний аналіз діагностики помилок

1. **`QS_ERR_SHOOTING_DIVERGED` (Розбіжність методу стрільби):** Виникає, коли випробувальні енергії потрапляють у область дуже швидкого експоненційного зростання хвильової функції під високим бар'єром. Для виправлення слід розширити інтервал пошуку енергії або перейти на метод двонапрямленого зшивання Нумерова.
2. **`QS_ERR_NODE_MISMATCH` (Незбіжність кількості вузлів):** Виникає, коли прицільний вибір енергії збігається до вищого або нижчого стану через пропуск вузлів сіткою. Лікується збільшенням кількості вузлів `num_points` та зменшенням кроку бісекції.
3. **`QS_ERR_NO_BOUND_STATES` (Відсутність зв'язаних станів):** Виникає при спробі знайти стани в потенціалі, де потенціальна яма є занадто мілкою або взагалі відсутня (наприклад, чистий потенціальний бар'єр).

## Багатопотокова безпека та потокобезпечність (Thread Safety)

Екземпляр розв'язувача `qs_solver_t` є повністю потокобезпечним за умови читання. Двоє або більше паралельних робочих потоків (POSIX threads, OpenMP threads, `std::jthread`) можуть одночасно викликати функцію `qs_solver_run` для того самого екземпляра розв'язувача, якщо потенціал `V(x)` не змінюється у часі.

Кожен потік повинен передавати власний локальний екземпляр структури `qs_result_t` для запису результатів. Внутрішній обчислювальний стан розв'язувача не використовує глобальних чи статичних змінних.

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include "qs_schrodinger_1d.h"

int main() {
    // 1. Конфігурація сітки
    qs_grid_config_t grid_cfg = {
        .x_min = -6.0,
        .x_max = 6.0,
        .num_points = 2001,
        .mass = 1.0, // m = 1
        .hbar = 1.0  // hbar = 1
    };

    // 2. Параметри розв'язувача
    qs_solver_params_t params = {
        .method = QS_METHOD_NUMEROV,
        .tolerance = 1e-8,
        .max_iterations = 300,
        .boundary_left = QS_BOUNDARY_DIRICHLET,
        .boundary_right = QS_BOUNDARY_DIRICHLET,
        .num_eigenvalues = 3
    };

    // 3. Створення розв'язувача
    qs_solver_t *solver = qs_solver_create(&grid_cfg, &params);
    if (!solver) {
        std::cerr << "Не вдалося створити розв'язувач!\n";
        return 1;
    }

    // 4. Задання параболічного потенціалу V(x) = 0.5 * x^2
    auto harmonic_potential = [](double x, void *user_data) -> double {
        (void)user_data;
        return 0.5 * x * x;
    };
    qs_solver_set_potential_func(solver, harmonic_potential, nullptr);

    // 5. Запуск обчислень
    qs_result_t result{};
    int status = qs_solver_run(solver, &result);

    if (status == QS_SUCCESS) {
        std::cout << "Розрахунок успішно завершено за " << result.compute_time_us << " мкс.\n";
        std::cout << "Знайдено власних станів: " << result.num_found << "\n\n";

        for (uint32_t i = 0; i < result.num_found; ++i) {
            const auto &st = result.states[i];
            std::cout << "Стан n=" << st.state_index 
                      << " | E = " << st.energy 
                      << " | Вузлів: " << st.node_count 
                      << " | Похибка: " << st.energy_error << "\n";
        }
    } else {
        std::cerr << "Помилка розрахунку! Код: " << status << "\n";
    }

    // 6. Звільнення ресурсів
    qs_result_free(&result);
    qs_solver_destroy(solver);

    return 0;
}
```
