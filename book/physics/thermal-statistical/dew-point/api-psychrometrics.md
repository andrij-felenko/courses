# 📋 Інтерфейс психометричних розрахунків і контролю конденсації

Цей довідник описує специфікацію програмного інтерфейсу (API) психометричного модуля `psychrometrics`, призначеного для вбудовування у мікроконтролерні системи керування кліматом, заходи захисту оптичних приладів та метеорологічні комплекси. Інтерфейс надає функції обчислення тиску насиченої пари, точки роси, точки інею та керування виконавчою автоматикою.

Особливістю даного інтерфейсу є його повна незалежність від операційної системи та динамічного розподілу пам'яті. Модуль розроблено у відповідності до стандартів безаварійного програмного забезпечення (MISRA C / C++ Core Guidelines) для гарантії детермінованого часу виконання в операційних системах реального часу (RTOS).

## 1. Константи, структури даних та коди помилок

Модуль використовує єдиний простір кодів повернення для виявлення аномалій у вимірюваннях давачів. Передані структури даних строго вирівняні по межі 8 байтів для забезпечення ефективного доступу на 32-бітних та 64-бітних архітектурах ARM Cortex-M, RISC-V та x86.

### 1.1 Коди повернення (`psychro_error_t`)

Усі функції обчислення повертають статус виконання типу `psychro_error_t`:

| Перелічення | Значення | Опис |
| :--- | :--- | :--- |
| `PSYCHRO_OK` | `0` | Успішне виконання розрахунку |
| `PSYCHRO_ERR_TEMP_OUT_OF_RANGE` | `-1` | Температура повітря виходить за межі [-50.0 °C, +80.0 °C] |
| `PSYCHRO_ERR_HUMIDITY_OUT_OF_RANGE` | `-2` | Відносна вологість виходить за межі [0.0%, 100.0%] |
| `PSYCHRO_ERR_NULL_POINTER` | `-3` | Передано нульовий вказівник на структуру результату |

### 1.2 Структура результату (`psychro_result_t` / `PsychroResult`)

Структура акумулює розраховані термодинамічні параметри середовища:

:::tabs
```c
typedef struct {
    double air_temp_c;          /* Вхідна температура повітря, °C */
    double rel_humidity_pct;    /* Вхідна відносна вологість, % */
    double dew_point_c;         /* Обчислена температура точки роси, °C */
    double frost_point_c;       /* Обчислена температура точки інею, °C */
    double sat_vapor_press_kpa; /* Тиск насиченої водяної пари, кПа */
    double vapor_press_kpa;     /* Поточний парціальний тиск водяної пари, кПа */
} psychro_result_t;
```
```cpp
namespace physics::thermal {

struct PsychroResult {
    double air_temp_c;          // Вхідна температура повітря, °C
    double rel_humidity_pct;    // Вхідна відносна вологість, %
    double dew_point_c;         // Обчислена температура точки роси, °C
    double frost_point_c;       // Обчислена температура точки інею, °C
    double sat_vapor_press_kpa; // Тиск насиченої водяної пари, кПа
    double vapor_press_kpa;     // Поточний парціальний тиск водяної пари, кПа
};

} // namespace physics::thermal
```
:::

### 1.3 Структура контролера (`anti_cond_controller_t` / `AntiCondensationController`)

Структура зберігає конфігураційні пороги гістерезису та поточний стан актуатора:

:::tabs
```c
typedef struct {
    double temp_margin_on_c;  /* Мінімальний температурний запас для ввімкнення, °C */
    double temp_margin_off_c; /* Максимальний температурний запас для вимкнення, °C */
    bool heater_active;       /* Поточний прапорець стану нагрівача (true = ON) */
} anti_cond_controller_t;
```
```cpp
namespace physics::thermal {

class AntiCondensationController {
public:
    explicit AntiCondensationController(double margin_on_c = 2.0, double margin_off_c = 4.0);
    bool update(double surface_temp_c, double dew_point_c) noexcept;
    [[nodiscard]] bool is_heater_active() const noexcept;
private:
    double margin_on_;
    double margin_off_;
    bool heater_state_;
};

} // namespace physics::thermal
```
:::

## 2. Сигнатури функцій API

Усі функції є строго потокобезпечними (reentrant), оскільки вони не використовують глобального чи статичного стану і працюють виключно з даними, переданими через стекові аргументи та вказівники.

### 2.1 `psychro_calculate` / `Psychrometrics::compute`

Обчислює повний набір психометричних параметрів для заданої температури та вологості.

:::tabs
```c
psychro_error_t psychro_calculate(
    double temp_c,
    double rh_pct,
    psychro_result_t *res
);
```
```cpp
namespace physics::thermal {

class Psychrometrics {
public:
    [[nodiscard]] static std::optional<PsychroResult> compute(
        double temp_c,
        double rh_pct
    ) noexcept;
};

} // namespace physics::thermal
```
:::

- **Параметри:**
  - `temp_c`: Температура довкілля у °C. Допустимий діапазон: `[-50.0, 80.0]`.
  - `rh_pct`: Відносна вологість у %. Допустимий діапазон: `[0.0, 100.0]`.
  - `res`: Вказівник на вихідну структуру `psychro_result_t` (в C++ повертається `std::optional<PsychroResult>`).
- **Повертане значення:** `PSYCHRO_OK` при успіху або відповідний код помилки (`std::nullopt` в C++).
- **Часова складність:** `O(1)` (виконання 1–2 викликів `exp()` та `log()`).
- **Вимоги до пам'яті:** 0 байт динамічної пам'яті (стекова аргументація).

### 2.2 `anti_cond_update` / `AntiCondensationController::update`

Оновлює стан автомату з двома порогами (гістерезис) для уникнення частого перемикання актуатора.

:::tabs
```c
bool anti_cond_update(
    anti_cond_controller_t *ctrl,
    double surface_temp_c,
    double dew_point_c
);
```
```cpp
namespace physics::thermal {

bool AntiCondensationController::update(
    double surface_temp_c,
    double dew_point_c
) noexcept;

} // namespace physics::thermal
```
:::

- **Параметри:**
  - `ctrl`: Вказівник на структуру контролера (в C++ — методи класу `AntiCondensationController`).
  - `surface_temp_c`: Поточна температура захищуваної поверхні, °C.
  - `dew_point_c`: Розрахована температура точки роси, °C.
- **Повертане значення:** `true`, якщо нагрівач/вентилятор повинен бути увімкнений, і `false` у протилежному випадку.
- **Алгоритм прийняття рішень:**
  ```
  ΔT = surface_temp_c - dew_point_c
  Якщо ΔT <= ctrl->temp_margin_on_c   --> ctrl->heater_active = true
  Якщо ΔT >= ctrl->temp_margin_off_c  --> ctrl->heater_active = false
  Інакше                             --> стан не змінюється (гістерезис)
  ```

## 3. Крайові випадки, межі застосування та гарантії надійності

При вбудовуванні модуля в алгоритми реального часу необхідно враховувати наступні крайові умови:

1. **Сухе повітря (`RH -> 0%`):** При вологості нижче `0.001%` математична формула логарифма прямо прямує до мінус нескінченності. Інтерфейс безпечно затискає значення точки роси на нижній фізичній межі `-50.0 °C`, упереджуючи виникнення арифметичних помилок `NaN` чи `-INF`.
2. **Повне насичення (`RH = 100%`):** За умови `100%` вологості `ln(1.0) = 0`, і функція повертає точну рівність `T_d = T_air`.
3. **Від'ємні температури (`T < 0 °C`):** При опусканні температури роси нижче нуля зародкоутворення у повітрі може відбуватися як рідка переохолоджена вода (`T_d`) або як твердий іній (`T_f`). Модуль обчислює обидва значення: `frost_point_c` використовує термодинамічні коефіцієнти для сублімації льоду.
4. **Висотна барометрична корекція:** Для систем, що працюють у розрідженій атмосфері (висота > 2000 м), тиск насичення залишається незмінним від загального тиску, проте парціальний тиск пари `p_v` зменшується пропорційно барометричному тиску `p_atm / p_0`.
5. **Продуктивність та обсяг пам'яті:** Скомпільований бінарний код модуля займає менше 1.5 Кбайт у пам'яті FLASH на архітектурі ARM Cortex-M4 і не потребує оперативної пам'яті SRAM крім 48 байт на стеку під час виклику.
6. **Інтеграція в RTOS та драйвери:** Для інтеграції у FreeRTOS створюється статичний екземпляр структури `anti_cond_controller_t`. Зчитування вхідних даних з давачів SHT3x/SHT4x або BME280 виконується у фоновій задачі `vTaskPsychroPoll()`. Отримані значення температури та вологості передаються в `psychro_calculate()`, а обчислений результат точки роси відправляється через чергу `xQueueSend()` в задачу керування актуаторами.
7. **Відповідальне тестування та калібрування:** При випробуваннях апаратури вимірювальні давачі повинні проходити первинне калібрування за допомогою прецизійних конденсаційних гігрометрів з охолоджуваним дзеркалом (наприклад, Michell Instruments S8000), які володіють прямим зв'язком з національними первинними еталонами вологості NIST/NPL.
8. **Обробка несправностей сенсорної шини:** Якщо цифровий давач вологості сигналізує про помилку контрольної суми CRC чи збій на шині I2C, модуль не використовує застарілі дані, а повертає код `PSYCHRO_ERR_HUMIDITY_OUT_OF_RANGE`. Система керування при цьому може перейти в аварійний захисний режим, утримуючи підігрів увімкненим для гарантованого захисту оптики.

## 4. Інтеграційний протокол та взаємодія з драйверами

При підключенні бібліотеки до промислових систем керування контролер взаємодіє з драйверним рівнем за такою послідовністю:
- **Ініціалізація структури контролера:** Створюється екземпляр `anti_cond_controller_t ctrl` із заданими пороговими значеннями запасу температури (наприклад, `temp_margin_on_c = 2.0`, `temp_margin_off_c = 4.0`).
- **Періодичний цикл опитування:** У головному циклі (або періодичному таймері RTOS) зчитуються показання з цифрового давача середовища та давача температури поверхні.
- **Розрахунок та реакція:** Викликається `psychro_calculate(&temp, &rh, &res)`. Отримане значення `res.dew_point_c` разом із температурою поверхні передається у функцію `anti_cond_update(&ctrl, surface_temp, res.dew_point_c)`. Значення поверненого прапорця переключає силовий транзисторний ключ (MOSFET) або реле плівкового нагрівача.
- **Безпека переривань (ISR Safety):** Оскільки функції не використовують блокуючих примітивів синхронізації (мутексів чи семафорів) та глобального стану, виклик `psychro_calculate()` безпечно проводити безпосередньо у перериваннях апаратного таймера або обробниках dma-буфера I2C без ризику виникнення інверсії пріоритетів чи дедлоків.

Дана триланкова схема гарантує повне розділення бізнес-логіки обчислень від низькорівневого HAL-драйвера периферії, що спрощує портування коду між різними сімействами мікроконтролерів (STM32, ESP32, nRF52, Microchip SAM).
