# ⚙️ Чисельне моделювання теплопередачі на сітці

Диференціальне рівняння теплопровідності у частинних похідних рідко має аналітичний розв'язок для реальних деталі складної геометричної форми, змішаних граничних умов чи матеріалів із залежністю теплопровідності від температури. На практиці інженери та розробники програмного забезпечення використовують чисельні методи, найпростішим і найнаочнішим з яких є **метод скінченних різниць** (Finite Difference Method, FDM).

Нижче розглянуто побудову явної та неявної різницевих схем Ейлера для одновимірного та двовимірного нагріву матеріалу, виведення умови стійкості Куранта–Фрідріхса–Леві (CFL) через аналіз Фон Неймана, метод прогонки (алгоритм Томаса) для неявних схем та робочу програмну реалізацію мовами C та C++.

### 1. Метод скінченних різниць та сіткова дискретизація

Ідея методу скінченних різниць полягає у заміні неперервної просторово-часової області нескінченною множиною дискретних точок — **чисельною сіткою**.

Розглянемо одновимірний простір довжиною `L` та часовий інтервал від `0` до `t_max`. Розділимо відрізок `[0, L]` на `N` однакових шагів довжиною `dx = L / (N - 1)`. Час ділимо на дискретні кроки `dt`. Вузли сітки позначаються індексами `i` (простір, `0 ≤ i < N`) та `n` (час, `n ≥ 0`). Значення температури у вузлі з координатами `x_i = i · dx` у момент часу `t_n = n · dt` позначимо як `T[i][n]`.

![Дискретизація просторово-часової сітки для чисельного розв'язання рівняння теплопровідності](/book/physics/thermal-statistical/heat-transfer/img/fourier-law.svg)
*Дискретна сітка: часова похідна замінюється правою різницею, а друга просторова похідна — центральною різницею по трьох сусідніх вузлах (5-точковий шаблон для 2D).*

Замінимо неперервні частинні похідні в рівнянні `∂T/∂t = α · (∂²T/∂x²)` їхніми скінченно-різницевими апроксимаціями, здобутими з розкладу в ряд Тейлора:

1. **Перша похідна за часом (перший порядок точності `O(dt)`):**
```
∂T / ∂t ≈ ( T[i][n+1] - T[i][n] ) / dt
```

2. **Друга похідна за простором (другий порядок точності `O(dx²)`):**
```
∂²T / ∂x² ≈ ( T[i+1][n] - 2·T[i][n] + T[i-1][n] ) / (dx²)
```

Підставимо ці апроксимації у рівняння теплопровідності:

```
( T[i][n+1] - T[i][n] ) / dt = α · ( T[i+1][n] - 2·T[i][n] + T[i-1][n] ) / (dx²)
```

Виразимо шукане значення температури на новому часовому шарі `T[i][n+1]`:

```
T[i][n+1] = T[i][n] + r · ( T[i+1][n] - 2·T[i][n] + T[i-1][n] )
```

де позначено безрозмірний сітковий параметр дифузії `r`:

```
r = α · dt / (dx²)
```

Ця формулювання визначає **явну різницеву схему Ейлера**. Вона називається явною тому, що значення температури у вузлі `i` на наступному часовому кроці `n+1` обчислюється безпосередньо через вже відомі значення температури у вузлах `i-1`, `i`, `i+1` на поточному кроці `n`.

### 2. Стійкість явної схеми: Аналіз Фон Неймана та критерій CFL

Явна схема Ейлера надзвичайно проста в програмній реалізації, однак вона володіє суворим фізичним та математичним обмеженням на максимальний крок за часом `dt`.

Перегрупуємо доданки для `T[i][n+1]`:

```
T[i][n+1] = (1 - 2·r) · T[i][n] + r · ( T[i+1][n] + T[i-1][n] )
```

З точки зору фізики, температура у вузлі `T[i][n+1]` є середньозваженою комбінацією температур сусідніх вузлів. Якщо коефіцієнт при `T[i][n]` стане від'ємним (`1 - 2·r < 0`), виникне нефізичний ефект: що гарячішим був вузол `i` на поточному кроці, то холоднішим він має стати на наступному. Це спричиняє паразитичні числові осциляції з розгоном амплітуди до нескінченності.

Для математичного доведення застосуємо **аналіз спектральної стійкості Фон Неймана**. Представимо числову помилку на кроці `n` у вигляді просторової гармоніки `T[i][n] = ξ^n · exp(I · k_w · i · dx)`, де `I = √(-1)` — уявна одиниця, `k_w` — вольове число гармоніки, а `ξ` — множник підсилення за один крок за часом.

Підставимо гармоніку в явну різницеву схему:

```
ξ^(n+1) · e^(I·k_w·i·dx) = ξ^n · e^(I·k_w·i·dx) + r · ξ^n · [ e^(I·k_w·(i+1)·dx) - 2·e^(I·k_w·i·dx) + e^(I·k_w·(i-1)·dx) ]
ξ = 1 + r · [ e^(I·k_w·dx) - 2 + e^(-I·k_w·dx) ]    [скорочення на ξ^n · e^(I·k_w·i·dx)]
```

Скориставшись формулою Ейлера `e^(I·θ) + e^(-I·θ) = 2 · cos(θ)` та тригонометричною тотожністю `1 - cos(θ) = 2 · sin²(θ/2)`:

```
ξ = 1 + r · [ 2·cos(k_w·dx) - 2 ]
ξ = 1 - 4·r · sin²( (k_w·dx) / 2 )
```

Умова стійкості чисельної схеми вимагає, щоб абсолютна величина множника підсилення не перевищувала одиницю для всіх можливих хвильових чисел (`|ξ| ≤ 1`):

```
-1 ≤ 1 - 4·r · sin²( (k_w·dx) / 2 ) ≤ 1
```

Найгірший випадок виникає при `sin²(...) = 1`:

```
1 - 4·r ≥ -1
4·r ≤ 2    ⇒    r ≤ 1 / 2
```

Таким чином, умова стійкості Куранта–Фрідріхса–Леві (CFL) для одновимірного рівняння теплопровідності вимагає:

```
α · dt / (dx²) ≤ 1 / 2    ⇒    dt ≤ dx² / (2 · α)
```

Для 2D випадку з однаковими кроками `dx = dy` критерій стійкості стає вдвічі жорсткішим:

```
r_2d = α · dt / (dx²) ≤ 1 / 4    ⇒    dt ≤ dx² / (4 · α)
```

Це означає, що при подвоєнні кількості вузлів сітки (зменшенні `dx` у 2 рази) припустимий часовий крок `dt` доводиться зменшувати у **4 рази**, що різко збільшує час обчислень.

### 3. Неявні схеми та метод прогонки (Thomas Algorithm)

Щоб зняти жорстке обмеження CFL на часовий крок `dt`, використовують **абсолютно стійкі неявні схеми**.

У **неявній схемі Ейлера** друга просторова похідна обчислюється на новому (невідомому) часовому шарі `n+1`:

```
( T[i][n+1] - T[i][n] ) / dt = α · ( T[i+1][n+1] - 2·T[i][n+1] + T[i-1][n+1] ) / (dx²)
- r · T[i-1][n+1] + (1 + 2·r) · T[i][n+1] - r · T[i+1][n+1] = T[i][n]
```

Ця система лінійних алгебраїчних рівнянь має тридіагональну матрицю. Вона вирішується за `O(N)` операцій за допомогою **методу прогонки (алгоритму Томаса)**. Неявна схема є абсолютно стійкою при будь-яких значеннях `dt`, що дозволяє здійснювати великі кроки за часом при симуляції тривалих процесів.

### 4. Програмна реалізація чисельного розв'язувача

Нижче наведено повністю робочий код симулятора 1D прогріву алюмінієвого стрижня довжиною 0.5 м мовами C та C++. Симуляція моделює нагрів стрижня з початкової температури 20 °C при підтриманні лівого кінця при 100 °C, а правого — при 20 °C.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

// Структура конфігурації симулятора
typedef struct {
    double length;      // Довжина стрижня [м]
    int num_points;     // Кількість вузлів сітки
    double alpha;       // Коефіцієнт температуропровідності [м²/с]
    double t_left;      // Гранична температура зліва [°C] (Діріхле)
    double t_right;     // Гранична температура справа [°C] (Діріхле)
    double t_initial;   // Початкова температура всередині [°C]
} thermal_config_t;

// Основна функція розрахунку явної схеми
bool run_thermal_simulation(const thermal_config_t* cfg, double total_time, double dt) {
    if (!cfg || cfg->num_points < 3 || cfg->length <= 0.0) {
        printf("Помилка: Некоректні входні параметри.\n");
        return false;
    }

    double dx = cfg->length / (cfg->num_points - 1);
    double r = cfg->alpha * dt / (dx * dx);

    // Строга перевірка умови стійкості CFL
    if (r > 0.5) {
        printf("Помилка стійкості: r = %.4f перевищує 0.5!\n", r);
        printf("Максимально припустимий dt <= %.6f с\n", 0.5 * dx * dx / cfg->alpha);
        return false;
    }

    // Виділення пам'яті під подвійну буферизацію сітки
    double* u_curr = (double*)malloc(cfg->num_points * sizeof(double));
    double* u_next = (double*)malloc(cfg->num_points * sizeof(double));
    if (!u_curr || !u_next) {
        printf("Помилка виділення оперативної пам'яті.\n");
        free(u_curr);
        free(u_next);
        return false;
    }

    // Ініціалізація початкового стану сітки
    for (int i = 0; i < cfg->num_points; ++i) {
        u_curr[i] = cfg->t_initial;
    }
    u_curr[0] = cfg->t_left;
    u_curr[cfg->num_points - 1] = cfg->t_right;

    int steps = (int)(total_time / dt);
    for (int step = 0; step < steps; ++step) {
        // Фіксація граничних умов 1-го роду
        u_next[0] = cfg->t_left;
        u_next[cfg->num_points - 1] = cfg->t_right;

        // Обчислення внутрішніх вузлів за явною схемою
        for (int i = 1; i < cfg->num_points - 1; ++i) {
            u_next[i] = u_curr[i] + r * (u_curr[i + 1] - 2.0 * u_curr[i] + u_curr[i - 1]);
        }

        // Обмін буферів пам'яті
        for (int i = 0; i < cfg->num_points; ++i) {
            u_curr[i] = u_next[i];
        }
    }

    // Виведення результуючого профілю температури
    printf("--- Результати розрахунку (t = %.1f с, r = %.4f) ---\n", total_time, r);
    for (int i = 0; i < cfg->num_points; i += cfg->num_points / 5) {
        printf("Позиція x = %.3f м : Температура T = %.2f °C\n", i * dx, u_curr[i]);
    }

    free(u_curr);
    free(u_next);
    return true;
}

int main(void) {
    thermal_config_t config = {
        .length = 0.5,
        .num_points = 51,
        .alpha = 9.7e-5,    // Алюміній: α ≈ 9.7e-5 м²/с
        .t_left = 100.0,
        .t_right = 20.0,
        .t_initial = 20.0
    };

    double dt = 0.0005;     // Крок часу підібрано під умову CFL
    double total_time = 10.0;

    if (!run_thermal_simulation(&config, total_time, dt)) {
        return 1;
    }
    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <span>
#include <iomanip>
#include <stdexcept>
#include <string>

struct ThermalConfig {
    double length{0.5};         // Довжина стрижня [м]
    std::size_t num_points{51}; // Кількість вузлів сітки
    double alpha{9.7e-5};       // Температуропровідність [м²/с]
    double t_left{100.0};       // Гранична температура зліва [°C]
    double t_right{20.0};       // Гранична температура справа [°C]
    double t_initial{20.0};     // Початкова температура [°C]
};

class HeatSolver1D {
public:
    explicit HeatSolver1D(ThermalConfig config)
        : config_(config), dx_(config.length / static_cast<double>(config.num_points - 1))
    {
        if (config_.num_points < 3 || config_.length <= 0.0) {
            throw std::invalid_argument("Некоректна геометрія чисельної сітки.");
        }
        grid_.resize(config_.num_points, config_.t_initial);
        grid_.front() = config_.t_left;
        grid_.back() = config_.t_right;
    }

    void step(double dt) {
        const double r = config_.alpha * dt / (dx_ * dx_);
        if (r > 0.5) {
            throw std::runtime_error("Порушення умови стійкості CFL: r = " + std::to_string(r));
        }

        std::vector<double> next_grid = grid_;
        for (std::size_t i = 1; i < grid_.size() - 1; ++i) {
            next_grid[i] = grid_[i] + r * (grid_[i + 1] - 2.0 * grid_[i] + grid_[i - 1]);
        }
        grid_ = std::move(next_grid);
    }

    void simulate(double total_time, double dt) {
        const std::size_t steps = static_cast<std::size_t>(total_time / dt);
        for (std::size_t n = 0; n < steps; ++n) {
            step(dt);
        }
    }

    [[nodiscard]] std::span<const double> grid() const noexcept {
        return grid_;
    }

    [[nodiscard]] double dx() const noexcept {
        return dx_;
    }

private:
    ThermalConfig config_;
    double dx_;
    std::vector<double> grid_;
};

int main() {
    try {
        ThermalConfig cfg{
            .length = 0.5,
            .num_points = 51,
            .alpha = 9.7e-5,
            .t_left = 100.0,
            .t_right = 20.0,
            .t_initial = 20.0
        };

        const double dt = 0.0005;
        const double total_time = 10.0;

        HeatSolver1D solver(cfg);
        solver.simulate(total_time, dt);

        std::cout << "=== Профіль температури (t = " << total_time << " с) ===\n";
        const auto result = solver.grid();
        const double dx = solver.dx();

        for (std::size_t i = 0; i < result.size(); i += result.size() / 5) {
            std::cout << "x = " << std::fixed << std::setprecision(3) << i * dx
                      << " м : T = " << std::setprecision(2) << result[i] << " °C\n";
        }
    } catch (const std::exception& ex) {
        std::cerr << "Помилка розв'язувача: " << ex.what() << '\n';
        return 1;
    }
    return 0;
}
```

### 5. Практичні поради щодо оптимізації та підводні камені

1. **Оптимізація використання кеш-пам'яті**: для 2D і 3D сіток дані слід зберігати в безперервному одновимірному масиві за методом *row-major order* (індексація `index = y * width + x`). Випадковий доступ до пам'яті через масиви вказівників спричиняє численні кеш-промахи (Cache Misses) і сповільнює розрахунок у 5–10 разів.
2. **Векторизація SIMD та OpenMP**: обчислення внутрішніх вузлів на поточному шарі є незалежними для різних `i`. Додавання директиви `#pragma omp parallel for` перед зовнішнім циклом розпаралелює симуляцію на всі ядра процесора без виникнення станів гонитви (Race Conditions).
3. **Граматика фіктивних вузлів (Ghost Nodes)**: при реалізації граничних умов 2-го (потік) або 3-го роду (конвекція) замість прямої зміни обчислювального циклу додають один фіктивний вузол `i = -1` за межею розрахунку. Це зберігає єдину структуру обчислювального шаблону для всіх внутрішніх точок.
