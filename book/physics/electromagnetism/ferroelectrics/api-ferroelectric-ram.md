# 📋 Інтерфейс та архітектура сегнетоелектричної оперативної пам'яті (FeRAM)

Сегнетоелектрична оперативна пам'ять (FeRAM або FRAM, англ. *Ferroelectric Random-Access Memory*) поєднує енергонезалежність флешпам'яті з високою швидкістю та малим енергоспоживанням статічної оперативної пам'яті (SRAM). В основі FeRAM лежить сегнетоелектричний конденсатор, затворний шар якого виготовлений з матеріалу із залишковою поляризацією (PZT або `HfO2`).

Цей документ описує фізичний інтерфейс 1T1C та 2T2C комірок FeRAM, внутрішні часові діаграми операцій руйнівного зчитування й регенерації, апаратний SPI-інтерфейс керування комерційними мікросхемами сегнетоелектричної пам'яті, а також практичні реалізації C/C++ драйверів для вбудованих систем.

## 1. Архітектура та принципи дії комірки 1T1C та 2T2C

### Топологія 1T1C (1 Transistor, 1 Capacitor)

Більшість комерційних мікросхем FeRAM високої щільності використовують топологію 1T1C, яка за будовою нагадує динамічну оперативну пам'ять (DRAM), проте замість параелектричного діелектрика використовується сегнетоелектрик:

```
          [ Bit Line (BL) ]
                 │
                 │
          ┌──────┴──────┐
          │  NMOS (T)   │ ─── [ Word Line (WL) ]
          └──────┬──────┘
                 │ (Вузол SN)
            ┌────┴────┐
            │  C_fe   │ (PZT / HfO2)
            └────┬────┘
                 │
          [ Plate Line (PL) ]
```

### Фізичні стани поляризації

Логічні стани біта кодуються напрямком вектора спонтанної поляризації `P_s` сегнетоелектричного шару конденсатора `C_fe`:

- **Логічна «1»**: вектор поляризації спрямований від верхньої електродної пластини до нижньої (стан `+P_r`).
- **Логічна «0»**: вектор поляризації спрямований від нижньої пластини до верхньої (стан `-P_r`).

Оскільки залишкова поляризація `P_r` зберігається за відсутності зовнішнього поля (`E = 0`), збережені дані не зникають при знеструмленні живлення `V_DD = 0 B`.

### Топологія 2T2C (2 Transistors, 2 Capacitors)

У високонадійних мікросхемах (наприклад, для космічної галузі та авіолуніки) використовується дифперенціальна топологія 2T2C. Кожна комірка має два селекторні транзистори та два сегнетоелектричні конденсатори, які зберігають взаємно інверсні стани («1» і «0»). Зчитування здійснюється диференціально порівнянням напруг на двох суміжних лініях Bit Line (`BL` та `BL_bar`). Це усуває залежність від дрейфу опорної напруги `V_ref` і піднімає ресурс збереження даних при високих температурах.

## 2. Операція зчитування: руйнівний відгук та регенерація

На відміну від звичайної Flash-пам'яті або EEPROM, зчитування інформації з 1T1C FeRAM є руйнівним (destructive read). Для визначення стану диполів до конденсатора прикладається імпульс напруги, який примусово переводить його у стан логічного нуля («0»).

### Покроковий алгоритм та часові затримки (Read Sequence)

1. **Фаза передзаряду (`t_PRE = 10 нс`)**: Лінія даних Bit Line (BL) розряджається до 0 В і відключається від джерела живлення, залишаючись у стані високоімпедансного плаваючого потенціалу.
2. **Активація рядка (`t_WL_on = 15 нс`)**: На лінію вибору Word Line (WL) подається високий рівень напруги `V_DD`, що відкриває селекторний NMOS-транзистор. Вузол SN підключається до лінії BL.
3. **Подача імпульсу на Plate Line (`t_PL_pulse = 25 нс`)**: На пластинчасту лінію Plate Line (PL) подається позитивний імпульс напруги `V_DD`.
4. **Дипольний відгук та інтегрування заряду**:
   - Якщо у комірці зберігався **стан «0»** (`-P_r`), напрямок поляризації збігається з зовнішнім полем. Переполяризація не відбувається; на лінію BL перетікає лише малий заряд лінійної діелектричної ємності `Q_0 = C_linear · V_DD`.
   - Якщо у комірці зберігався **стан «1»** (`+P_r`), зовнішнє поле протилежне поляризації. Вектор диполів стрибком перевертається у стан `-P_r`. На лінію BL перетікає значно більший заряд `Q_1 = Q_0 + 2·P_r·A` (де `A` — площа конденсатора).
5. **Підсилення різниці (Sense Amplification, `t_SENSE = 15 нс`)**: Диференціальний підсилювач зчитування порівнює напругу на лінії BL з еталонним потенціалом `V_ref`:
   - При зчитуванні «0»: `V_BL = Q_0 / (C_BL + C_fe) < V_ref` ⇒ підсилювач видає 0 В.
   - При зчитуванні «1»: `V_BL = Q_1 / (C_BL + C_fe) > V_ref` ⇒ підсилювач видає `V_DD`.
6. **Автоматичний перезапис (Write-Back, `t_WB = 25 нс`)**: Якщо зчитано логічну «1», інформація у конденсаторі виявилася зруйнованою (переведена в «0»). Наприкінці циклу підсилювач зчитування утримує лінію BL на рівні `V_DD`, тоді як PL скидається в 0 В. Поле зворотного напрямку відновлює поляризацію `+P_r` у комірці.

## 4. Апаратний SPI-інтерфейс керування (FM25V02A / MB85RS64V)

Промислові мікросхеми FeRAM випускаються зі стандартними інтерфейсами SPI (Serial Peripheral Interface) або I2C, що дозволяє замінювати ними повільні мікросхеми EEPROM без зміни топології друкованої плати.

### Призначення виводів (Pinout)

```
       ┌───┬───┐
 /CS  1│o  └───│8  VDD (2.0V - 3.6V)
  SO  2│       │7  /HOLD
 /WP  3│       │6  SCK (до 40 МГц)
 VSS  4│       │5  SI
       └───────┘
```

- `/CS` (Chip Select): вибір мікросхеми (активний низький рівень).
- `SCK` (Serial Clock): шина тактування даних.
- `SI` (Serial Data Input): вхідний послідовний потік даних від майстра.
- `SO` (Serial Data Output): вихідний потік даних до майстра.
- `/WP` (Write Protect): апаратний захист від запису регістру статусу.
- `/HOLD` (Hold): тимчасове призупинення SPI-обміну без скидання сесії.

### Набір команд SPI (Instruction Set)

| Команда | Опкод (Hex) | Опис функціоналу | Напрямок даних |
| :--- | :--- | :--- | :--- |
| **WREN** | `0x06` | Увімкнення дозволу запису (Set Write Enable Latch) | Вхідний (1 байт) |
| **WRDI** | `0x04` | Скидання дозволу запису (Reset Write Enable Latch) | Вхідний (1 байт) |
| **RDSR** | `0x05` | Зчитування регістру статусу (Status Register) | Вхід / Вихід |
| **WRSR** | `0x01` | Запис регістру статусу (блокування блоків) | Вхідний (2 байти) |
| **READ** | `0x03` | Зчитування даних за 16-бітною адресою | Вхід (3 байти) + Вихід |
| **WRITE**| `0x02` | Запис даних за 16-бітною адресою (без паузи!) | Вхід (3 байти + N байт)|
| **RDID** | `0x9F` | Зчитування ID виробника та щільності (Device ID)| Вхід (1 байт) + 9 байт |

### Протокол суцільного запису (No-Delay Byte/Page Write)

На відміну від EEPROM, де після відправки байта необхідно витримувати затримку `t_WR = 5 мс` або опитувати статус прапорця `WIP` (Write In Progress), FeRAM здійснює запис безпосередньо на частоті тактування SPI шини (до 40 МГц). Запис байтів відбувається потоково без поділу на сторінки:

```
/CS   ──┐                                                             ┌───
        └─────────────────────────────────────────────────────────────┘
SCK   ────┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  
          └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ 
SI    ───< WREN 0x06 >─── [ /CS pulse ] ───< WRITE 0x02 >─< AddrHi >─< AddrLo >─< Data0 >─< Data1 >...
SO    ───────────────────────────────────────────────────────────────── High-Z
```

## 5. Приклад ідіоматичної програмної реалізації C та C++ драйвера

Нижче наведено робочий драйвер для читання та потокового запису даних у мікросхему FeRAM через послідовний SPI-інтерфейс.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define FRAM_CMD_WREN  0x06
#define FRAM_CMD_WRITE 0x02
#define FRAM_CMD_READ  0x03
#define FRAM_CMD_RDID  0x9F

/* Низькорівневі прототипи HW SPI (реалізуються для конкретного MCU) */
extern void spi_cs_select(bool enable);
extern uint8_t spi_transfer_byte(uint8_t tx_byte);

/* Надання дозволу запису WREN */
void fram_write_enable(void) {
    spi_cs_select(true);
    spi_transfer_byte(FRAM_CMD_WREN);
    spi_cs_select(false);
}

/* Потоковий запис масиву даних у FeRAM без затримок */
bool fram_write_data(uint16_t address, const uint8_t *data, uint16_t length) {
    if (!data || length == 0) return false;

    fram_write_enable();

    spi_cs_select(true);
    spi_transfer_byte(FRAM_CMD_WRITE);
    spi_transfer_byte((uint8_t)(address >> 8));   /* Старіший байт адреси */
    spi_transfer_byte((uint8_t)(address & 0xFF));  /* Молодший байт адреси */

    for (uint16_t i = 0; i < length; i++) {
        spi_transfer_byte(data[i]);
    }

    spi_cs_select(false);
    return true;
}

/* Безперервне зчитування масиву даних з FeRAM */
bool fram_read_data(uint16_t address, uint8_t *buffer, uint16_t length) {
    if (!buffer || length == 0) return false;

    spi_cs_select(true);
    spi_transfer_byte(FRAM_CMD_READ);
    spi_transfer_byte((uint8_t)(address >> 8));
    spi_transfer_byte((uint8_t)(address & 0xFF));

    for (uint16_t i = 0; i < length; i++) {
        buffer[i] = spi_transfer_byte(0xFF); /* Dummy byte */
    }

    spi_cs_select(false);
    return true;
}
```
```cpp
#include <cstdint>
#include <span>
#include <vector>
#include <system_error>

class SpiBusInterface {
public:
    virtual ~SpiBusInterface() = default;
    virtual void select(bool active) = 0;
    virtual uint8_t transfer(uint8_t byte) = 0;
};

class FerroelectricRamDriver {
public:
    explicit FerroelectricRamDriver(SpiBusInterface& bus) : bus_(bus) {}

    enum class Command : uint8_t {
        WREN  = 0x06,
        WRITE = 0x02,
        READ  = 0x03,
        RDID  = 0x9F
    };

    void enable_write() const {
        bus_.select(true);
        bus_.transfer(static_cast<uint8_t>(Command::WREN));
        bus_.select(false);
    }

    void write(uint16_t address, std::span<const uint8_t> data) const {
        if (data.empty()) return;

        enable_write();

        bus_.select(true);
        bus_.transfer(static_cast<uint8_t>(Command::WRITE));
        bus_.transfer(static_cast<uint8_t>(address >> 8));
        bus_.transfer(static_cast<uint8_t>(address & 0xFF));

        for (const uint8_t byte : data) {
            bus_.transfer(byte);
        }
        bus_.select(false);
    }

    [[nodiscard]] std::vector<uint8_t> read(uint16_t address, std::size_t length) const {
        std::vector<uint8_t> buffer(length);
        if (length == 0) return buffer;

        bus_.select(true);
        bus_.transfer(static_cast<uint8_t>(Command::READ));
        bus_.transfer(static_cast<uint8_t>(address >> 8));
        bus_.transfer(static_cast<uint8_t>(address & 0xFF));

        for (auto& byte : buffer) {
            byte = bus_.transfer(0xFF);
        }
        bus_.select(false);
        return buffer;
    }

private:
    SpiBusInterface& bus_;
};
```

## 6. Надійність, захист та інженерні обмеження

1. **Захист від раптового відключення живлення (Power Fail Safety)**: Завдяки тому, що кожен байт записується в FeRAM за час менше `90 нс`, системи реєстрації аварійних подій (black box recorders) встигають скинути весь критичний контекст системи на FeRAM під час згасання живлення на накопичувальному конденсаторі шини `V_DD` (за час порядку `1–5 мс`).
2. **Відсутність зносу сторінок**: У Flash-пам'яті перед записом необхідний повільний процес стирання блоку (sector erase), що обмежує частоту оновлення даних. FeRAM підтримує побайтову перезаписність без попереднього стирання.
3. **Ефект втоми (Fatigue)**: При багаторазовому переполяризуванні (понад `10¹²` циклів) затискання доменних стінок дефектами ґратки (кисневими вакансіями) може зменшувати величину залишкової поляризації `P_r`. Сучасні матеріали з додаванням допантів та переходів на `HfO2` практично усунули цей ефект у робочому діапазоні температур.
4. **Радіаційна та магнітна стійкість**: На відміну від плаваючих затворів Flash-пам'яті, які втрачають заряд під дією іонізуючого випромінювання, іонний зсув у перовськітах стійкий до гамма-випромінювання та важких заряджених частинок. Це робить FeRAM стандартом для космічних апаратів та бортової авіолуніки.
