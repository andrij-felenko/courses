# ⚙️ True RMS у приладі: квадрат → середнє → корінь

> Алгоритмічна вставка про те, як прилад рахує [діюче значення (RMS)](book:physics/rms-value) насправді: чому це лише три дії над відліками сигналу й чому дешевий мультиметр на несинусоїді показує неправду.

### Задача

Мультиметр чи мікроконтролер бачить лише потік **миттєвих відліків** напруги v[n] з АЦП — і має повернути одне число, діюче значення (*RMS*, *root-mean-square*). За означенням це той сталий рівень, що грів би опір так само, як наш змінний сигнал:

```formula
Vrms = √( (1/T)·∫ v(t)² dt )       ← неперервно, за період T
Vrms = √( (1/N)·Σ v[n]² )          ← у прошивці, по N відліках
```

Прилад, який чесно бере цей інтеграл (суму квадратів) **хоч би якої форми був сигнал**, називають **True RMS**. Проблема в тому, що чесність коштує: потрібно перемножити кожен відлік сам на себе. Саме на цьому десятиліттями економили дешеві прилади — і ця економія досі живе в найпростіших мультиметрах, де вона мовчки бреше.

### Ідея

Перш ніж розбирати хитрість, подивімося, як виглядає чесний шлях, — бо він на диво простий. Назва **root-mean-square** — це прямо рецепт, прочитаний **справа наліво**: **square** (квадрат) → **mean** (середнє) → **root** (корінь). Три дії, рівно за формулою.

![Конвеєр True RMS: квадрат, середнє, корінь](/book/physics/electromagnetism/rms-value/img/pipeline.svg)
*Конвеєр True RMS над миттєвими відліками: (1) беремо відлік v[n]; (2) підносимо до квадрата — знак зникає, від'ємні півхвилі гріють нарівні з додатними; (3) усереднюємо квадрат за вікно (це «розсіяна потужність» на одиничному опорі); (4) корінь повертає результат у вольти. Жодного припущення про форму сигналу — тому показ правильний і для синуса, і для меандра, і для гострих піків.*

Чому саме ці три дії — варто відчути, а не вивчити напам'ять. **Квадрат** прибирає знак: потужність ∝ v², і від'ємна півхвиля гріє опір так само, як додатна, тож вони не мають скорочуватись (просте середнє самого v для симетричного сигналу дало б нуль — і збрехало б). **Середнє** квадрата — це і є середня потужність на одиничному опорі. **Корінь** повертає нас із «квадратних вольтів» назад у вольти, щоб число можна було підставляти в P = V²/R замість постійної напруги. Усе разом і є означення RMS, реалізоване буквально.

Звідки ж береться брехня дешевого приладу? Він економить на множенні: бере **середньовипрямне** значення |v| (просто випрямляє сигнал і усереднює модуль — це легко зробити діодним мостом і конденсатором, без жодних обчислень) і множить на сталий коефіцієнт **1.11**. Це **форм-фактор** (*form factor*) — відношення RMS до середньовипрямного, але він дорівнює 1.11 **лише для чистого синуса**. Прилад припускає, що сигнал синусоїдний, і для іншої форми промахується.

![Чому середньовипрямний прилад бреше на несинусоїді](/book/physics/electromagnetism/rms-value/img/form-factor.svg)
*Той самий сигнал міряють True RMS (зелена лінія — правда) і дешевий середньовипрямний прилад (червона — показ). На синусі форм-фактор справді 1.11, похибки немає. На меандрі справжній форм-фактор 1.00, а прилад усе одно множить на 1.11 — і **завищує на 11%**. На гострих піках (фазовий зріз димером, вхідний струм блока живлення) форм-фактор сягає 2.78 і вище — прилад бачить мізерне середнє й **занижує в рази**.*

### Псевдокод

Конвеєр із трьох дій лягає у прошивку майже дослівно: накопичуємо суму квадратів відлік за відліком, а наприкінці вікна беремо корінь із середнього.

:::tabs
```cpp
static uint64_t acc = 0;      // накопичувач суми квадратів (широкий!)
static uint32_t n   = 0;

void on_sample(int32_t v) {           // періодично, з таймера/ISR
    int32_t x = v - offset;           // прибрати зсув АЦП (середину шкали / DC)
    acc += (int64_t)x * x;            // ← єдине множення на відлік
    if (++n == N) {                   // вікно набралось (ціле число періодів!)
        Vrms = sqrtf((float)acc / N);
        acc = 0;  n = 0;              // почати нове вікно
    }
}
```
```py
acc = 0                       # накопичувач суми квадратів
n   = 0

def on_sample(v):                     # періодично, з таймера/ISR
    global acc, n, Vrms
    x    = v - offset                 # прибрати зсув АЦП (середину шкали / DC)
    acc += x * x                      # ← єдине множення на відлік
    n   += 1
    if n == N:                        # вікно набралось (ціле число періодів!)
        Vrms = math.sqrt(acc / N)
        acc = 0;  n = 0               # почати нове вікно
```
:::

Ковзний варіант (щоб не чекати кінця вікна) — експоненційне усереднення квадрата:

:::tabs
```cpp
ms  += alpha * (x * x - ms);  // 0 < alpha << 1: ms пливе за ⟨v²⟩
Vrms = sqrtf(ms);             // читати будь-коли
```
```py
ms  += alpha * (x * x - ms)   # 0 < alpha << 1: ms пливе за ⟨v²⟩
Vrms = math.sqrt(ms)          # читати будь-коли
```
:::

### Складність і пастки на МК

- **Складність — O(1) на відлік:** одне віднімання, одне множення (x·x) і одне додавання; корінь — раз на вікно. Навіть найдешевший МК тягне True RMS у реальному часі; квадратний корінь рахують один раз і не в ISR.
- **Спершу прибрати зсув (DC offset).** АЦП віддає код навколо середини шкали, а біполярний сигнал часто заведений через дільник на VCC/2. Якщо не відняти цю постійну складову, вона **теж піде в квадрат** і завищить RMS. Зсув або вимірюють (середнє самого v), або віднімають відомий рівень.
- **Вікно — ціле число періодів.** Сума по «півтора періоди» дасть **плаваючий** результат від виміру до виміру. Синхронізуйте вікно з періодом сигналу (детектор переходу через нуль) або усереднюйте досить довго, щоб неповний «хвіст» періоду не важив.
- **Переповнення.** v[n]² росте швидко: 12-бітний відлік у квадраті — це вже до 24 біт, а сума по тисячах відліків легко вибиває 32-бітне ціле. Беріть **широкий** накопичувач (32→64 біт) або масштабуйте/нормуйте відліки заздалегідь.
- **Пік-фактор (*crest factor*) і зрізання піків.** Гострі піки несуть більшу частину енергії у вузьких сплесках. Якщо АЦП не встигає за фронтом або діапазон замалий і пік **зрізається**, квадрат «з'їсть» саме найважливіші відліки — True RMS занизить. Тримайте запас по діапазону й частоту дискретизації значно вищою за найвищу значущу [гармоніку](book:physics/sine-wave).
- **Смуга самого АЦП.** Прилад чесний лише в межах своєї смуги: високі гармоніки несинусоїди, що випали за неї, у RMS не потраплять. Дешевий True RMS-мультиметр теж має стелю — десятки кілогерц.
- **Не плутайте з |середнім|.** Якщо бюджет диктує середньовипрямну схему — пам'ятайте, що множник 1.11 правдивий **лише для синуса**; на меандрі, ШІМ, фазовому зрізі чи спотвореному мережевому струмі вона помиляється на десятки відсотків. Напис **True RMS** на приладі — це обіцянка, що всередині працює саме конвеєр «квадрат → середнє → корінь», а не зашитий форм-фактор.
