# ⚙️ Симуляція та рендеринг фігур Ліссажу на віртуальному осцилографі

Ця програмна вставка містить алгоритм чисельної генерації траєкторій Ліссажу, дискретизацію ортогональних гармонік та їхню програмну візуалізацію в режимі X-Y з імітацією післясвічення люмінофора екрана осцилографа.

При симуляції фізичних процесів на цифрових системах або побудові растрових зображень фігур Ліссажу ключовим завданням є точний дискретний розрахунок параметричних координат `(x[i], y[i])` та їх відображення на 2D-сітку пікселів або у буфер кадру з урахуванням ефекту загасання (післясвічення екрана).

---

### 1. Теоретичний підхід до чисельної дискретизації та розрахунку параметричних кривих

Формування замкнених і незамкнених траєкторій Ліссажу в цифрових системах спирається на обчислення параметричних координат точки на площині через задані часові інтервали. Координати точки в дискретні моменти часу `t_k = k · dt` розраховуються за рівняннями:

```
x[k] = A_x · sin(2π · f_x · k · dt + δ)
y[k] = A_y · sin(2π · f_y · k · dt)
```

де `A_x` та `A_y` — масштабні коефіцієнти амплітуди по відповідних осях, `f_x` та `f_y` — частоти генерації сигналів у герцах, `δ` — початковий фазовий зсув каналу X відносно Y, а `dt` — крок дискретизації по часовій осі.

#### Вибір кроку дискретизації та запобігання просторовому аліасінгу:
У класичній теорії обробки сигналів теорема Котельникова-Найквіста вимагає частоту дискретизації `f_s = 1 / dt > 2 · max(f_x, f_y)`. Однак для геометричної побудови 2D-траєкторій цього фундаментального мінімуму абсолютно недостатньо. При частоті дискретизації лише удвічі вищій за частоту сигналу на екрані замість плавної геометричної кривої утвориться хаотичний набір розрізнених точок або кутастий многокутник із зламаними гранями.

Для забезпечення візуальної гладкості та високої точності заповнення замкненої кривої крок дискретизації `dt` вибирається за умовою:

```
dt ≤ 1 / (N_points · max(f_x, f_y))
```

де `N_points` — кількість обчислювальних точок на один повний період найшвидшого з двох коливань. На практиці приймають `N_points ∈ [100, 1000]`.

Якщо співвідношення частот `f_x / f_y = p / q` є раціональним числом, підсумкова крива є замкненою, а загальна кількість точок розрахунку для одного повного періоду `T_total` становить:

```
N_total = N_points · q
```

#### Математичний пайплайн растеризації: світові координати → екранні пікселі:
Перехід від фізичних непреривних координат `(x, y)` у вольтах до дискретних індексів буфера кадру `(px, py)` здійснюється за допомогою лінійного афінного перетворення:

```
px = cx + round( x · K_x )
py = cy − round( y · K_y )
```

де `(cx, cy)` — екранні координати центру осцилографічної сітки (половина ширини й висоти буфера), `K_x` та `K_y` — коефіцієнти масштабування у пікселях на вольт, а знак мінус у виразі для `py` враховує те, що у комп'ютерній графіці вісь Y спрямована зверху вниз.

#### Імітація післясвічення люмінофора та обробка буфера кадру:
В аналогових електронно-променевих трубках люмінофорний шар на внутрішній поверхні скла продовжує світитися ще деякий час після того, як електронний промінь перемістився в іншу точку. Цей фізичний ефект називається післясвіченням екрана (*persistence*).

Для цифрової симуляції цього процесу значення інтенсивності пікселя `I(x, y)` у 2D-масиві буфера кадру оновлюється на кожному кроці за законом експоненційного загасання:

```
I_new(x, y) = I_old(x, y) · exp(−dt / τ) + I_beam
```

де `τ` — стала часу загасання люмінофора, а `I_beam` — внесок яскравості від миттєвого проходження променя через даний піксель.

### 2. Згладжування траєкторій (Anti-Aliasing) та алгоритми з'єднання точок

При побудові графічних інтерфейсів низької роздільної здатності або растрових векторних екранів виникає проблема ступенчастості ліній (*aliasing*). Застосовують два основних класи алгоритмів:

#### 1. З'єднання точок за алгоритмом Брезенхема:
Якщо крок часу `dt` є недостатньо малим, сусідні обчислені точки `P_k(px_k, py_k)` та `P_{k+1}(px_{k+1}, py_{k+1})` можуть розташовуватися на відстані кількох пікселів одна від одної. Малювання лише окремих точок дасть розірвану пунктирну лінію. Алгоритм Брезенхема будує суцільну цілочисельну лінію між `P_k` та `P_{k+1}` без використання обчислень із плаваючою крапкою.

#### 2. Субпіксельне згладжування Сяоліня У (Xiaolin Wu's Algorithm):
Для отримання фотореалістичної якості лінії променя застосовують алгоритм Сяоліня У, який розраховує пропорції прозорості двох сусідніх пікселів залежно від дробової частини координат розрахованої точки. Це створює ефект м'якого розмиття світлової плями електронно-променевої трубки.

### 3. Цифрова фільтрація шуму каналів (DSP-препроцесинг)

На практиці реальні вхідні сигнали осцилографа завжди містять високочастотний шум вимірювальних щупів або електромагнітні наводки. Для отримання чіткої фігури Ліссажу в цифрових осцилографах вхідні масиви `x[k]` та `y[k]` попередньо проходять через цифрові фільтри низьких частот (ФНЧ).

#### Фільтр ковзного середнього (Moving Average Filter):
Найпростішим алгоритмом придушення високочастотних завад є ковзне середнє з вікном довжиною `M`:

```
x_filtered[k] = (1 / M) · ∑_{j=0}^{M-1} x[k - j]
y_filtered[k] = (1 / M) · ∑_{j=0}^{M-1} y[k - j]
```

#### Беквадратний IIR-фільтр другого порядку (Biquad Filter):
Для більш якісного зрізу завад без спотворення фазового зсуву корисного сигналу застосовують рекурсивний решітчастий фільтр:

```
x_out[k] = b0·x[k] + b1·x[k-1] + b2·x[k-2] − a1·x_out[k-1] − a2·x_out[k-2]
```

Коефіцієнти `b0, b1, b2, a1, a2` розраховуються за формулами Баттерворта залежно від бажаної частоти зрізу `f_cutoff`.

### 4. Алгоритм ФАПЧ (Phase-Locked Loop) для автозахоплення фази

У цифрових осцилографах та системах зв'язку для автостабілізації фігур Ліссажу застосовують програмні алгоритми фазової автопідстройки частоти (ФАПЧ / PLL).

Коли частота вхідного сигналу `f_x` невідома або плаває, непорушна фігура Ліссажу починає обертатися. Програмний ФАПЧ постійно підлаштовує частоту опорного генератора `f_y` та фазу `δ` для мінімізації помилки підстроювання `e(t)`:

```
e(t) = x(t) · y_ref(t) − x_quad(t) · y_ref_quad(t)
```

Сигнал помилки `e(t)` проходить через цифровий ПІД-фільтр низьких частот (Loop Filter) та керує числово керованим генератором (NCO / Numerically Controlled Oscillator). Це дозволяє програмі автоматично «захоплювати» та заморожувати геометричну фігуру на екрані при будь-яких дрейфах частоти джерела.

### 5. Архітектурні пастки та крайові випадки цифрової реалізації

При розробці програмного забезпечення для симуляції фігур Ліссажу інженери стикаються з кількома типовими проблемами:

1. **Нагромадження похибки фазового акумулятора (Phase Drift):**
   При тривалому розрахунку кута `θ(t) = 2π · f · t` через постійне додавання дрібного кроку `dθ = 2π · f · dt` змінна типу `double` або `float` втрачає точність через обмеженість розрядності мантиси.
   *Рішення:* Використання нормалізації кута у діапазоні `[0, 2π)` за допомогою функції `fmod(angle, 2*M_PI)` або зберігання фази у вигляді цілочисельного фазового акумулятора (DDS).

2. **Спотворення співвідношення сторін (Aspect Ratio Distortion):**
   Екрани комп'ютерів та консольні термінали мають неквадратні пікселі (у консолі висота символу зазвичай у 2 рази більша за його ширину).
   *Рішення:* Масштабування амплітуд `A_x` та `A_y` з урахуванням геометричного коефіцієнта пропорційності пікселя `k_aspect = H_pixel / W_pixel`.

3. **Просторові прогалини при високій швидкості променя:**
   У ділянках траєкторії, де миттєва швидкість `|v(t)|` є максимальною (наприклад, при проходженні центру еліпса), сусідні дискретні точки `(x[k], y[k])` можуть розташовуватися на відстані кількох пікселів одна від одної. Це утворює пунктирну лінію замість суцільної.
   *Рішення:* Застосування алгоритму Брезенхема для лінійного з'єднання сусідніх точок або адаптивний вибір кроку за часом `dt`, пропорційного зворотному модулю швидкості `1 / |v(t)|`.

### 6. Повна реалізація симулятора на мовах C та C++

Нижче наведено повністю робочий код симуляції генерації фігур Ліссажу. Приклад показано двома мовами у вкладках `:::tabs`:
- У вкладці **C** — класична низькорівнева реалізація з ручним виділенням пам'яті через `malloc`/`free`, роботою з сирими вказівниками та масивами структури.
- У вкладці **C++** — сучасний ідіоматичний C++20 з використанням принципів RAII, концептів стандартної бібліотеки (`std::vector`, `std::span`), безпечного керування пам'яттю без сирих вказівників, типованих математичних констант `<numbers>` та об'єктно-орієнтованого буфера зображення.

```c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <string.h>

#ifndef M_PI
#define M_PI 3.14159265358979323846
#endif

// Структура налаштувань генератора сигналів
typedef struct {
    double amp_x;       // Амплітуда X (вольти / пікселі)
    double amp_y;       // Амплітуда Y (вольти / пікселі)
    double freq_x;      // Частота X (Гц)
    double freq_y;      // Частота Y (Гц)
    double phase_deg;   // Зсув фази (градуси)
} lissajous_config_t;

// Структура точки траєкторії
typedef struct {
    double x;
    double y;
} point2d_t;

// Буфер кадру (ASCII-осцилограф)
typedef struct {
    int width;
    int height;
    char *data;
} framebuffer_t;

// Створення буфера кадру
framebuffer_t* fb_create(int w, int h) {
    framebuffer_t *fb = (framebuffer_t*)malloc(sizeof(framebuffer_t));
    if (!fb) return NULL;
    fb->width = w;
    fb->height = h;
    fb->data = (char*)malloc((size_t)(w * h));
    if (!fb->data) {
        free(fb);
        return NULL;
    }
    memset(fb->data, ' ', (size_t)(w * h));
    return fb;
}

// Очищення буфера
void fb_clear(framebuffer_t *fb) {
    if (fb && fb->data) {
        memset(fb->data, ' ', (size_t)(fb->width * fb->height));
    }
}

// Звільнення пам'яті
void fb_free(framebuffer_t *fb) {
    if (fb) {
        free(fb->data);
        free(fb);
    }
}

// Малювання точки в буфері
void fb_draw_point(framebuffer_t *fb, int px, int py, char ch) {
    if (px >= 0 && px < fb->width && py >= 0 && py < fb->height) {
        fb->data[py * fb->width + px] = ch;
    }
}

// Вивід буфера у консоль
void fb_render_console(const framebuffer_t *fb) {
    for (int y = 0; y < fb->height; ++y) {
        for (int x = 0; x < fb->width; ++x) {
            putchar(fb->data[y * fb->width + x]);
        }
        putchar('\n');
    }
}

// Обчислення дискретної траєкторії Ліссажу
int generate_lissajous_points(const lissajous_config_t *cfg, point2d_t *pts, int max_pts, int num_samples) {
    if (!cfg || !pts || num_samples > max_pts) return -1;

    double phase_rad = cfg->phase_deg * M_PI / 180.0;
    double max_f = (cfg->freq_x > cfg->freq_y) ? cfg->freq_x : cfg->freq_y;
    double dt = 1.0 / (max_f * 100.0); // 100 точок на цикл

    for (int i = 0; i < num_samples; ++i) {
        double t = i * dt;
        pts[i].x = cfg->amp_x * sin(2.0 * M_PI * cfg->freq_x * t + phase_rad);
        pts[i].y = cfg->amp_y * sin(2.0 * M_PI * cfg->freq_y * t);
    }

    return num_samples;
}

int main(void) {
    const int W = 61;
    const int H = 25;
    const int SAMPLES = 600;

    framebuffer_t *fb = fb_create(W, H);
    if (!fb) {
        fprintf(stderr, "Помилка виділення пам'яті!\n");
        return 1;
    }

    point2d_t *points = (point2d_t*)malloc(SAMPLES * sizeof(point2d_t));
    if (!points) {
        fb_free(fb);
        return 1;
    }

    // Налаштування: співвідношення частот 1:2 («вісімка»), фаза 45 градусів
    lissajous_config_t config = {
        .amp_x = (double)(W / 2 - 2),
        .amp_y = (double)(H / 2 - 2),
        .freq_x = 100.0,
        .freq_y = 200.0,
        .phase_deg = 45.0
    };

    int count = generate_lissajous_points(&config, points, SAMPLES, SAMPLES);
    int cx = W / 2;
    int cy = H / 2;

    // Малювання осей
    for (int x = 0; x < W; ++x) fb_draw_point(fb, x, cy, '-');
    for (int y = 0; y < H; ++y) fb_draw_point(fb, cx, y, '|');
    fb_draw_point(fb, cx, cy, '+');

    // Проектування точок траєкторії на екран
    for (int i = 0; i < count; ++i) {
        int px = cx + (int)round(points[i].x);
        int py = cy - (int)round(points[i].y);
        fb_draw_point(fb, px, py, '#');
    }

    printf("=== Віртуальний осцилограф (Режим X-Y): fx:fy = 1:2, phase = 45° ===\n\n");
    fb_render_console(fb);

    free(points);
    fb_free(fb);
    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <numbers>
#include <string>
#include <span>
#include <memory>

// Конфігурація генератора сигналів
struct LissajousConfig {
    double amp_x{1.0};       // Амплітуда X
    double amp_y{1.0};       // Амплітуда Y
    double freq_x{100.0};    // Частота X (Гц)
    double freq_y{100.0};    // Частота Y (Гц)
    double phase_rad{0.0};   // Зсув фази (радіани)
};

// Двовимірна точка
struct Point2D {
    double x{0.0};
    double y{0.0};
};

// RAII-клас віртуального растрового екрана осцилографа
class VirtualOscilloscope {
public:
    VirtualOscilloscope(size_t width, size_t height)
        : width_(width), height_(height), buffer_(width * height, ' ') {}

    void clear() {
        std::fill(buffer_.begin(), buffer_.end(), ' ');
    }

    void draw_point(int px, int py, char symbol = '*') {
        if (px >= 0 && px < static_cast<int>(width_) &&
            py >= 0 && py < static_cast<int>(height_)) {
            buffer_[static_cast<size_t>(py) * width_ + static_cast<size_t>(px)] = symbol;
        }
    }

    void draw_axes() {
        int cx = static_cast<int>(width_ / 2);
        int cy = static_cast<int>(height_ / 2);
        for (size_t x = 0; x < width_; ++x) draw_point(static_cast<int>(x), cy, '-');
        for (size_t y = 0; y < height_; ++y) draw_point(cx, static_cast<int>(y), '|');
        draw_point(cx, cy, '+');
    }

    void render_trajectory(std::span<const Point2D> points) {
        int cx = static_cast<int>(width_ / 2);
        int cy = static_cast<int>(height_ / 2);

        for (const auto& pt : points) {
            int px = cx + static_cast<int>(std::round(pt.x));
            int py = cy - static_cast<int>(std::round(pt.y));
            draw_point(px, py, '#');
        }
    }

    void print() const {
        for (size_t y = 0; y < height_; ++y) {
            for (size_t x = 0; x < width_; ++x) {
                std::cout << buffer_[y * width_ + x];
            }
            std::cout << '\n';
        }
    }

    [[nodiscard]] size_t width() const noexcept { return width_; }
    [[nodiscard]] size_t height() const noexcept { return height_; }

private:
    size_t width_;
    size_t height_;
    std::vector<char> buffer_;
};

// Генератор точок траєкторії Ліссажу
class LissajousGenerator {
public:
    static std::vector<Point2D> generate(const LissajousConfig& cfg, size_t num_samples) {
        std::vector<Point2D> points;
        points.reserve(num_samples);

        double max_f = std::max(cfg.freq_x, cfg.freq_y);
        double dt = 1.0 / (max_f * 100.0); // 100 точок на один період

        for (size_t i = 0; i < num_samples; ++i) {
            double t = static_cast<double>(i) * dt;
            double x = cfg.amp_x * std::sin(2.0 * std::numbers::pi * cfg.freq_x * t + cfg.phase_rad);
            double y = cfg.amp_y * std::sin(2.0 * std::numbers::pi * cfg.freq_y * t);
            points.push_back({x, y});
        }

        return points;
    }
};

int main() {
    constexpr size_t width = 61;
    constexpr size_t height = 25;
    constexpr size_t num_samples = 600;

    VirtualOscilloscope scope(width, height);
    scope.draw_axes();

    LissajousConfig config{
        .amp_x = static_cast<double>(width / 2 - 2),
        .amp_y = static_cast<double>(height / 2 - 2),
        .freq_x = 100.0,
        .freq_y = 200.0,
        .phase_rad = std::numbers::pi / 4.0 // 45 градуси
    };

    std::vector<Point2D> trajectory = LissajousGenerator::generate(config, num_samples);
    scope.render_trajectory(trajectory);

    std::cout << "=== Modern C++ Lissajous Scope (1:2 ratio, pi/4 phase) ===\n\n";
    scope.print();

    return 0;
}
```

### 7. Покроковий порівняльний аналіз C та C++ реалізацій

Порівнюючи наведені варіанти коду, можна виділити кілька ключових відмінностей у парадигмах двох мов:

1. **Автоматичне керування пам'яттю (RAII проти `malloc`/`free`):**
   - У версії на C пам'ять для структури `framebuffer_t` та динамічного масиву точок виділяється у купі за допомогою виклику `malloc()`. Розробник зобов'язаний самостійно контролювати правильність вивільнення ресурсів через `free()`. Якщо виділення пам'яті під `points` зазнає невдачі, вихід із програми вимагає попереднього ручного вивільнення `fb`, інакше виникне витік пам'яті (*memory leak*).
   - У версії на C++ внутрішній буфер каду зберігається у контейнері `std::vector<char>`, що повністю гарантує деструкцію та вивільнення ресурсів при виході об'єкта `VirtualOscilloscope` з області видимості. Жодних викликів `free` чи `delete` не потрібно.

2. **Безкопіювальний доступ до даних та `std::span`:**
   - C++20 вводить концепцію `std::span<const Point2D>` у методі `render_trajectory()`. Це дозволяє передавати послідовний зріз пам'яті без копіювання самого вектора і без ризику передати невалідний вказівник чи невідповідний розмір, що характерно для C-функцій вида `(const point2d_t *pts, int count)`.

3. **Безпека типів та математичні константи:**
   - Замість нетипованого препроцесорного макросу `#define M_PI` C++20 застосовує типовану константу `std::numbers::pi` з модуля `<numbers>`, що усуває можливі конфлікти імен макросів при включенні заголовочних файлів.

4. **Інкапсуляція та цілісність стану:**
   - У C++ стан віртуального осцилографа (внутрішній буфер, розміри) повністю прихований у приватній секції класу `VirtualOscilloscope`. Зовнішній код не може випадково пошкодити розмірність чи вказівник на дані. У C-версії поля структури `framebuffer_t` відкриті для прямих небезпечних модифікацій.

### 8. Генерація аудіосигналів (Стерео WAV) для вектороскопів

Цікавим практичним застосуванням фігур Ліссажу у звукорежисурі та аудіоінженерії є генерація двохканальних стереоаудіофайлів (формат WAV), де лівий канал передає сигнал X, а правий — сигнал Y.

При підключенні виходу звукової карти комп'ютера або смартфона до каналів CH1 та CH2 аналогового осцилографа в режимі X-Y светлова пляма на екрані малює фігуру Ліссажу під дією звукових хвиль.

#### Протокол формування 16-бітного стерео буфера PCM:
Кожен стерео-семпл складається з двох послідовних 16-бітних цілих чисел із знаком (`int16_t`):

```
sample_left  = (int16_t)( 32767.0 * A_x * sin(2π · f_x · t + δ) )
sample_right = (int16_t)( 32767.0 * A_y * sin(2π · f_y · t) )
```

Зміна частот `f_x` та `f_y` у звуковому діапазоні (наприклад, 440 Гц та 880 Гц при частоті дискретизації аудіо `f_s = 44100 Гц`) створює як гармонійні звукові співзвуччя у динаміках, так і стійкі геометричні фігури Ліссажу на екрані осцилографа.

### 9. Векторні графічні дисплеї та архітектура Vector CRT

Окремим класом апаратного забезпечення, що працює на принципах фігур Ліссажу, є **векторні монітори** та осцилографічні індикатори (наприклад, ігрові автомати Atari Asteroids, консоль Vectrex 1982 року, або дисплеї радарів).

#### Принцип роботи векторного променя:
У звичайному растровому дисплеї електронний промінь сканує екран рядок за рядком зверху вниз. У векторному ж дисплеї електроніка відхилення спрямовує промінь строго вздовж відрізків малюнка (як олівець по паперу). Сигнали керування `X(t)` та `Y(t)` формуються двома двоканальними ЦАП високої швидкодії (DAC), а яскравість променя керується третім каналом модуляції `Z(t)` (Blanking).

Це забезпечує нескінченну просторову роздільну здатність без растрових «сходинок», але вимагає від ЦАП та підсилювачів відхилення ширини смуги пропускання у сотні мегагерц.

### 10. Апаратна реалізація генератора фігур Ліссажу на мікроконтролерах

При генерації фігур Ліссажу на реальному апаратному забезпеченні (наприклад, на мікроконтролерах STM32, ESP32 або AVR для керування лазерним проектором чи виводу на реальний осцилограф) використовуються наступні інженерні прийоми:

#### 1. Генерація через двоканальний ЦАП (DAC) з прямою пам'яттю (DMA):
Замість розрахунку синуса у реальному часі у внутрішню пам'ять мікроконтролера завантажуються дві таблиці синусів (Look-Up Table, LUT) на 1024 або 4096 значень:

```
const uint16_t dac_lut_x[1024] = { ... };
const uint16_t dac_lut_y[1024] = { ... };
```

Апаратний модуль DMA (Direct Memory Access) за сигналами від двох таймерів без участі центрального процесора циклічно пересилає дані з таблиць LUT безпосередньо в регістри двоканального цифро-аналогового перетворювача (DAC1 та DAC2). Зміна частот реалізується зміною періоду таймерів перезапуску DMA.

#### 2. Керування гальванометричними дзеркалами (Laser Show Systems):
У лазерних проекторах промінь відхиляється двома електромеханічними дзеркалами (гальванометрами або "гальво"). Оскільки механічна система дзеркала має значна інерцію та резонансні частоти (зазвичай близько 20–30 кГц), електричні сигнали керування `X(t)` та `Y(t)` повинні додатково фільтруватися цифровими ФІЧ-фільтрами для запобігання механічним ударам та спотворенням фігури на екрані.

### 11. Апаратні шейдери GPU (GLSL/HLSL) для реального часу

При візуалізації фігур Ліссажу в інтерактивних тривимірних іграх чи професійному софті для звукозапису (DAW) обчислення мільйонів точок переносять на графічний процесор (GPU).

Векторний шейдер GLSL отримує індекс вершини `gl_VertexID` та обчислює координати прямо в GPU без завантаження шини PCIe:

```glsl
#version 330 core
layout (location = 0) in float t;
uniform float freq_x;
uniform float freq_y;
uniform float phase;

void main() {
    float x = sin(freq_x * t + phase);
    float y = sin(freq_y * t);
    gl_Position = vec4(x, y, 0.0, 1.0);
}
```

Фрагментний шейдер додає імітацію світіння свіжого променя та згасання хвоста траєкторії, створюючи фотореалістичний аналоговий вигляд екрана осцилографа.

### 12. Інтеграція у графічні фреймворки (Qt / ImGui / WebGL)

При створенні віртуальних лабораторних стендів та вимірювальних застосунків модулі рендерингу фігур Ліссажу інтегрують у кросплатформені GUI-фреймворки:

- **Dear ImGui:** рендеринг виконується через додавання точок у списках команд `ImDrawList::AddPolyline()`, що дозволяє малювати тисячі фігур із мінімальними накладними витратами процесора у реальному часі.
- **Qt QCustomPlot / QPainter:** траєкторія будується як `QCPCurve`, де координати виражені не як `y(x)`, а через незалежний часовий параметр `t`.
- **WebGL / HTML5 Canvas:** для веб-симуляторів обчислення виконують у паралельному потоці `WebWorker` та відрисовують у контексті `CanvasRenderingContext2D` або `WebGL2` з підтримкою апаратного прискорення браузера.

### 13. Тестування та верифікація точності симулятора

Для перевірки коректності чисельного алгоритму симуляції фігур Ліссажу проводиться серія юніт-тестів:
1. **Тест фази 90 градусів при 1:1:** перевіряється, що максимальне значення `y` при `x = 0` точно дорівнює амплітуді `A_y`, а відхилення полярного радіуса від кола не перевищує похибки дискретизації `O(dt²)`.
2. **Тест кількості перетинів при 1:2:** підраховується кількість екстремумів по осі Y для підтвердження наявності двох петель у «вісімці».
3. **Тест збереження енергії:** перевіряється, що сума квадратів координат `x[k]² + y[k]²` не виходить за межі амплітудного прямокутника.

### 14. Оптимізація рендерингу для реального часу (DSP/OpenGL)

При побудові графічних інтерфейсів або осцилографів на базі OpenGL/Vulkan/DirectX чи цифрових сигнальних процесорів (DSP) застосовують наступні оптимізації:

- **Використання lookup-таблиць синуса (LUT):** замість виклику важкої функції `std::sin()` у кожному кадрі створюється таблиця `sin_table[4096]`, що прискорює обчислення в 5–10 разів.
- **Векторизація SIMD (AVX2/NEON):** обчислення точок `x[i]` та `y[i]` виконується блоками по 4 або 8 точок паралельно за допомогою векторних інструкцій процесора.
- **Vertex Buffer Objects (VBO):** у шейдерах OpenGL траєкторія завантажується як один масив вершин `GL_LINE_STRIP`, а розрахунок фазового зсуву та обертання виконується прямо на графічному процесорі (GPU) у вершинному шейдері.
