# 📋 Інтерфейс лінійного рушія суперпозиції: струмовий, польовий та сигнальний контур

Цей документ містить повну системну специфікацію програмного бібліотечного рушія `SuperpositionEngine`. Рушій розроблений для високоефективного обчислення лінійних комбінацій просторових векторних і скалярних полів, струмів та напруг у електричних мережах довільної конфігурації, а також часової згортки сигналів на основі імпульсного відгуку (функцій Гріна).

Довідник визначає архітектуру бібліотеки, контракти даних, специфікацію публічних функцій, обмеження складності, гарантії потокобезпечності та таблицю кодів помилок.

---

### Архітектура та принципи проєктування

Бібліотека `SuperpositionEngine` побудована на трьох фундаментальних архітектурних принципах, які гарантують високу обчислювальну продуктивність та детерміновану поведінку у системних застосунках реального часу:

1. **Строгий розподіл за функціональними типами суперпозиції:**
   Кожен тип фізичної суперпозиції (просторові поля, електричні кола, часова згортка, простір станів) виділено в окремий підмодуль API із власним контрактом даних та контролем лінійності. Це запобігає плутанині між скалярним і векторним додаванням та забезпечує незалежність модулів.

2. **Гарантія повної безвинятковості (Exception-Free C/C++ ABI):**
   Усі функції повертають статус виконання через перелічувальний тип `SupStatus`. Усі помилки (некоректні вказівники, сингулярності, насичення) обробляються детерміновано без викидання винятків, що забезпечує повну сумісність із системним кодом, вбудованими системами (embedded) та ОС реального часу (RTOS).

3. **Нульове динамічне виділення пам'яті у циклі обчислень (Zero-Allocation Execution):**
   Функції обчислення полів та згортки працюють із буферами пам'яті, наданими викликаючою стороною. Це повністю усуває накладні витрати на виклики `malloc`/`free` у гарячих циклах симуляції та забезпечує передбачуваний час виконання.

4. **Векторизація та потокобезпечність (SIMD & Thread-Safety):**
   Усі обчислювальні функції є чистими функціями без внутрішнього глобального стану (reentrant). Завдяки відсутності побічних ефектів, внутрішні цикли розпаралелюються за допомогою OpenMP або системних потоків без застосування м'ютексів та блокувань.

### 1. Структури даних та типи (Data Contracts)

#### 1.1. Переліки та константи

Перелік режимів роботи рушія визначає фізичний тип суперпозиції, що застосовується під час обчислень:

```c
typedef enum {
    SUPERPOSITION_MODE_VECTOR_FIELD  = 0x01, /* Векторні та скалярні поля (Кулон/Ньютон) */
    SUPERPOSITION_MODE_CIRCUIT_NODE  = 0x02, /* Електричні кола (Кирхгоф/суперпозиція джерел) */
    SUPERPOSITION_MODE_GREEN_CONV    = 0x04, /* Часова згортка з імпульсним відгуком */
    SUPERPOSITION_MODE_STATE_SPACE   = 0x08  /* Простір станів dx/dt = Ax + Bu */
} SuperpositionMode;
```

Статуси виконання та коди помилок розділені на три категорії: успіх (`SUP_SUCCESS = 0`), фатальні помилки (від'ємні числа) та попередження (додатні числа):

```c
typedef enum {
    SUP_SUCCESS                      =  0,   /* Успішне виконання */
    SUP_ERR_INVALID_POINTER          = -1,   /* Передано NULL вказівник */
    SUP_ERR_INVALID_SIZE             = -2,   /* Розмірність масиву некоректна (N <= 0) */
    SUP_ERR_SINGULARITY_REACHED      = -3,   /* Точка оцінки збігається з точкою джерела (r -> 0) */
    SUP_ERR_OUT_OF_MEMORY            = -4,   /* Недостатньо пам'яті для виділення бувера */
    SUP_WARN_NONLINEAR_SATURATION    =  1    /* Амплітуда вийшла за поріг лінійності */
} SupStatus;
```

#### 1.2. Структури конфігурації та джерел

Структура `FieldSourceSpec` задає фізичні параметри точкового джерела поля у тривимірному просторі:

```c
typedef struct {
    double x, y, z;       /* Координати джерела в метрах */
    double intensity;     /* Інтенсивність джерела (Заряд [Кл], Маса [кг], Сила [Н]) */
    double phase_shift;   /* Початкова фаза в радіанах (для змінного поля) */
} FieldSourceSpec;
```

*Деталізація полів `FieldSourceSpec`:*
- `x, y, z`: декартові координати у міжнародній системі одиниць SI. Повинні бути дійсними скінченними числами (перевірка `isfinite`).
- `intensity`: скалярна величина джерела. Для електростатики це заряд `q` у кулонах, для гравітації — маса `M` у кілограмах, для акустики — амплітуда об'ємного випромінювання.
- `phase_shift`: початковий зсув фази `φ₀`. Використовується для розрахунку фазорного додавання синусоїдальних полів як комплексних амплітуд.

Структура `TargetPointSpec` описує точку у просторі, де здійснюється обчислення сумарного поля:

```c
typedef struct {
    double x, y, z;       /* Координати спостерігача */
} TargetPointSpec;
```

Структура `FieldValueResult` повертає обчислені компоненти поля:

```c
typedef struct {
    double Fx, Fy, Fz;    /* Компоненти результуючого вектора напруженості */
    double potential;     /* Скалярний потенціал */
} FieldValueResult;
```

*Деталізація полів `FieldValueResult`:*
- `Fx, Fy, Fz`: три векторні компоненти сумарного поля, обчислені шляхом строгого геометричного додавання проєкцій.
- `potential`: алгебраїчна скалярна сума потенціалів усіх `N` джерел.

Структура `CircuitNodeSpec` описує електричний вузол схеми для застосування теореми суперпозиції:

```c
typedef struct {
    uint32_t node_id;     /* Ідентифікатор вузла */
    double   conductance; /* Провідність G = 1/R [Сим] */
    double   source_v;    /* Напруга джерела ЕРС [В] */
    double   source_i;    /* Струм джерела струму [А] */
} CircuitNodeSpec;
```

*Деталізація полів `CircuitNodeSpec`:*
- `node_id`: унікальний порядковий номер вузла в лінійній схемі.
- `conductance`: активна провідність вітки `G = 1 / R`. Повинна бути строго додатною величиною.
- `source_v`: ЕРС джерела напруги, підключеного до даного вузла. При вимкненні закорочується.
- `source_i`: струм джерела струму. При вимкненні розривається.

Структура `GreenKernelConfig` містить дискретну імпульсну характеристику `h[n]` для часової згортки:

```c
typedef struct {
    const double *h_kernel;  /* Масив дискретного імпульсного відгуку h[n] */
    size_t        h_length;  /* Кількість відліків імпульсного відгуку */
    double        max_amp;   /* Поріг максимальної амплітуди лінійного режиму */
    double        sample_rate;/* Частота дискретизації [Гц] */
} GreenKernelConfig;
```

### 2. Специфікація публічних функцій (API Signatures)

#### 2.1. Рушій векторної суперпозиції полів

```c
SupStatus SupEngine_CalculateFieldMatrix(
    const FieldSourceSpec *sources,
    size_t num_sources,
    const TargetPointSpec *targets,
    size_t num_targets,
    FieldValueResult *results
);
```

*Детальний опис поведінки та алгоритму:*
Функція здійснює двократно вкладений цикл за всіма джерелами `num_sources` та точками спостереження `num_targets`. Для кожної точки спостереження обчислюється евклідова відстань до джерела `r = √(Δx² + Δy² + Δz²)`. 

Якщо відстань `r` виявляється меншою за критичний поріг регуляризації `10⁻¹²` м, функція перериває розрахунок цієї точки і повертає код помилки `SUP_ERR_SINGULARITY_REACHED` для запобігання діленню на нуль. Векторні проекції обчислюються як `Fx = ∑ intensityᵢ · Δx / r³`.

Преумови виклику:
- Вказівники `sources`, `targets` та `results` не повинні бути `NULL`.
- Кількість джерел `num_sources` та точок `num_targets` має бути більше нуля.

Постумови:
- При поверненні `SUP_SUCCESS` масив `results` гарантовано містить точні сумарні векторні значення поля та потенціалу.

#### 2.2. Теорема суперпозиції в електричних колах

```c
SupStatus SupEngine_SolveCircuitSuperposition(
    const CircuitNodeSpec *nodes,
    size_t num_nodes,
    double *node_volts,
    double *node_currs
);
```

*Детальний опис поведінки та алгоритму:*
Функція реалізує теорему суперпозиції для електричних мереж. Вона послідовно активує кожне джерело ЕРС або струму, вимикаючи решту джерел (джерела напруги замінюються коротким замиканням, джерела струму — розривом). Для кожного стану розраховується матрична система вузлових потенціалів методом Гаусса. Отримані часткові потенціали `node_volts` та часткові струми `node_currs` підсумовуються за принципом суперпозиції.

Преумови виклику:
- Провідність кожного вузла `conductance` має бути строго більшою за нуль.

Постумови:
- Результати містять сумарні напруги та струми. Зверніть увагу: потужність не можна обчислювати як суму часткових потужностей!

#### 2.3. Часова згортка (Неперервна/Дискретна функція Гріна)

```c
SupStatus SupEngine_ProcessGreenConvolution(
    const GreenKernelConfig *config,
    const double *in_signal,
    size_t in_len,
    double *out_signal,
    size_t out_len
);
```

*Детальний опис поведінки та алгоритму:*
Функція обчислює дискретну згортку входного сигналу `in_signal` із масивом імпульсної характеристики `h_kernel`. Згортка моделює дію неперервної суперпозиції відгуків системи у часовій області. Якщо під час сумування у будь-який момент часу модуль вихідного сигналу перевищує поріг `max_amp`, розрахунок завершується, а повертаним значенням стає попередження `SUP_WARN_NONLINEAR_SATURATION`.

### 3. Таблиця обчислювальної складності та обмежень

| Модуль API | Просторова складність (Memory) | Часова складність (Time) | Граничні умови / Помилки |
| :--- | :--- | :--- | :--- |
| **Польовий рушій** (`CalculateFieldMatrix`) | `O(M)` пам'яті для результатів | `O(N · M)` операцій | `r = √(Δx² + Δy² + Δz²) > 10⁻¹²` м; при меншому виникає `SUP_ERR_SINGULARITY_REACHED`. |
| **Коловий рушій** (`SolveCircuitSuperposition`) | `O(N)` пам'яті для вузлів | `O(N²)` для прямих методів | Провідність `G > 0`; вимкнене джерело напруги → коротке замикання; струму → розрив. |
| **Часова згортка** (`ProcessGreenConvolution`) | `O(L_in + L_h)` пам'яті | `O(L_in · L_h)` часова | Якщо `max |y[n]| > max_amp`, повертає `SUP_WARN_NONLINEAR_SATURATION`. |

### 4. Довідник кодів помилок (Error Reference Table)

| Код повернення | Назва символу | Опис причини та рекомендована дія |
| :--- | :--- | :--- |
| **0** | `SUP_SUCCESS` | Виконання пройшло успішно. Результати коректні. |
| **-1** | `SUP_ERR_INVALID_POINTER` | Передано `NULL` в качестве вказівника на масив джерел, точок або результатів. Перевірте виділення пам'яті перед викликом. |
| **-2** | `SUP_ERR_INVALID_SIZE` | Передано нульовий або від'ємний розмір масиву (`num_sources == 0` або `num_targets == 0`). |
| **-3** | `SUP_ERR_SINGULARITY_REACHED` | Точка оцінки лежить надто близько до джерела (`r < 10⁻¹²` м). Задайте мінімальний радіус екранування (smoothing parameter). |
| **-4** | `SUP_ERR_OUT_OF_MEMORY` | Внутрішнє виділення тимчасового буфера завершилося невдачею. Зменшіть розмір блоку обробки. |
| **+1** | `SUP_WARN_NONLINEAR_SATURATION` | Попередження: сумарна амплітуда вийшла за межі лінійного діапазону. Принцип суперпозиції втрачає фізичну точність! |

### 5. Стратегії обробки помилок та відновлення (Error Recovery Protocols)

При виникненні помилок або попереджень під час обчислень розробник повинен дотримуватися детермінованих протоколів відновлення:

#### 5.1. Обробка сингулярності (`SUP_ERR_SINGULARITY_REACHED`)
Коли точка спостереження збігається з координатами джерела поля, фізичний потенціал `1/r` прямує до нескінченності. Рушій не дозволяє обчислення нечисел `NaN` і перериває обробку цієї точки. 

*Рекомендоване відновлення:*
- Застосувати регуляризацію Пламмера або ввести мінімальний зсув `ε = 10⁻⁶` м у параметри джерела.
- Замінити точкове джерело сферичним розподілом заряду радіуса `R`, усередині якого поле лінійно прямує до нуля.

#### 5.2. Обробка нелінійного насичення (`SUP_WARN_NONLINEAR_SATURATION`)
Цей статус є не фатальною помилкою, а фізичним застереженням. Він виникає у часовій згортці, коли амплітуда сумарного сигналу `y[n]` перевищує поріг `max_amp`.

*Рекомендоване відновлення:*
- Зменшити амплітуду вхідного сигналу на вході рушія (застосувати автоматичне регулювання підсилення AGC).
- Перевірити фізичну модель на наявність нелінійних членів (наприклад, насичення сердечника трансформатора або кліпінг транзистора) та вимкнути лінійний рушій суперпозиції.

#### 5.3. Обробка невідповідності розмірів пам'яті (`SUP_ERR_INVALID_SIZE`)
Виникає при передачі масивів із розміром `N ≤ 0` або коли вихідний масив `out_signal` має довжину меншу ніж `in_len + h_len - 1`.

*Рекомендоване відновлення:*
- Завжди виділяти вихідний масив розміром `out_len = in_len + h_len - 1` для повної дискретної згортки.

### 6. Модель системної сумісності та надійності (Safety & Real-Time Performance)

Бібліотека `SuperpositionEngine` задовольняє вимогам промислових стандартів надійності MISRA-C та ISO 26262 для критичних систем:

1. **Гарантований час відгуку (Deterministic Worst-Case Execution Time - WCET):**
   Відсутність динамічних викликів `malloc` під час роботи та відсутність рекурсії гарантує, що час виконання обчислень залежить виключно від розміру вхідних даних `N` та `M`, що робить рушій придатним для циклів керування із частотою до 100 кГц.

2. **Потокобезпечність без блокувань (Lock-Free Thread-Safety):**
   Оскільки функції не пишуть у глобальні чи статичні змінні, кілька потоків обчислень можуть одночасно викликати `SupEngine_CalculateFieldMatrix` для різних ділянок простору без ризику виникнення стану гонитви (race conditions).

3. **Підтримка SIMD-інструкцій:**
   Структури даних `FieldSourceSpec` вирівняні в пам'яті на 32 байти, що дозволяє компіляторам автоматично застосовувати векторні інструкції AVX-2 та NEON для паралельного додавання полів 4 або 8 джерел за один такт процесора.

### 7. Геометричні інваріанти та прискорення великих систем (Fast Multipole Method & GPU)

Коли кількість джерел `N` та точок спостереження `M` сягає мільйонів (наприклад, у симуляції зоряних скупчень або білкових молекул), прямий розрахунок за викликом `SupEngine_CalculateFieldMatrix` зі складністю `O(N · M)` стає неможливим. За принципом суперпозиції дальній потенціал групи точкових зарядів можна з високою точністю замінити потенціалом одного еквівалентного мультиполя у центрі мас цієї групи.

В обчислювальному рушії для таких систем реалізується **швидкий мультипольний метод (Fast Multipole Method - FMM)** та древовидна декомпозиція простору Барнса — Хата:

1. Простір рекурсивно розбивається на квадранти (2D) або октанти (3D-октодерево).
2. Для близьких джерел розрахунок проводиться прямою векторною суперпозицією.
3. Для далеких кластерів джерел суперпозиція обчислюється один раз через сумування дипольних та квадрупольних моментів `Mₗₘ`.

Це знижує складність суперпозиції з `O(N · M)` до `O(N log N)` або `O(N)`, зберігаючи точність на рівні `10⁻⁶`.

При реалізації рушія на графічних прискорювачах (GPU CUDA / OpenCL) структура `FieldSourceSpec` трансформується у соа-масив (Structure of Arrays - SoA). Це гарантує злиття запитів до глобальної відеопам'яті (Coalesced Memory Access) та дозволяє обчислювати суперпозицію мільйона джерел за одиниці мілісекунд завдяки тисячам паралельних потоків у рамках однієї сітки обчислень.

### 8. Квантування, шуми квантування та компенсація помилок Кахана (Kahan Summation)

Коли рушій виконує суперпозицію полів для великої кількості джерел `N > 10⁵`, пряме сумування полів у циклі `results->Fx += E_mag * (dx / r)` у форматі плаваючої коми IEEE 754 `double` або `float` стикається із принциповим чисельним обмеженням — **накопиченням помилки округлення**. 

Якщо до великого вже накопиченого сумарного поля `F_total ~ 10⁶` додається внесок дуже далекого малого заряду `ΔF ~ 10⁻¹⁰`, через обмежену довжину мантиси (53 біти для `double`) малий внесок втрачає свої молодші розряди і взагалі не змінює результат: `10⁶ + 10⁻¹⁰ = 10⁶`.

Для запобігання цій вибірковій втраті інформації в API `SuperpositionEngine` реалізовано алгоритм компенсаційного сумування Кахана (Kahan Summation Algorithm):

```c
/* Алгоритм Кахана для високоточного підсумовування суперпозиції */
typedef struct {
    double sum;        /* Накопичена сума */
    double comp;       /* Компенсація втрачених молодших розрядів */
} KahanAccumulator;

inline void kahan_add(KahanAccumulator *acc, double input) {
    double y = input - acc->comp;
    double t = acc->sum + y;
    acc->comp = (t - acc->sum) - y;
    acc->sum = t;
}
```

Алгоритм Кахана зберігає проміжну компенсаційну змінну `comp`, яка підтримує молодші біти втраченої точності. Це гарантує, що помилка накопичення сумарного поля росте не пропорційно кількості джерел `O(N)`, а залишається обмеженою константою `O(1)`, забезпечуючи високу точність обчислення потенціалів навіть при додаванні мільйона джерел різного масштабу.

6. **Вирівнювання пам'яті для SIMD (Data Alignment):**
   Усі структурні буфери `FieldSourceSpec` та `FieldValueResult` заздалегідь вирівнюються на межу 32 або 64 байтів у пам'яті (за допомогою `alignas(64)` або `posix_memalign`). Це гарантує можливість завантаження векторних регістрів процессора інструкціями `_mm512_load_pd` без накладних витрат на неорієнтований доступ (unaligned memory access). Використання вирівнювання запобігає розщепленню кєш-ліній процесора (cache-line split penalties) при високих частотах викликів.

7. **Планування у системах реального часу (RTOS Scheduling):**
   У операційних системах реального часу з жорсткими часовими рамками (Hard Real-Time RTOS, такими як FreeRTOS або VxWorks) завдання розрахунку суперпозиції призначають високопріоритетному потоку обробки датчиків. Оскільки обчислювач не виконує блокуючих операцій вводу-виводу (I/O) і не задіює системні виклики (syscalls), обчислення є строго детермінованим у часі.

### 9. Рекомендації з інтеграції та використання

Під час використання бібліотеки `SuperpositionEngine` у високонавантажених обчислювальних застосунках (симулятори польоту, обробка гідроакустичних сигналів, розрахунок великих інтегральних схем) дотримуйтеся таких рекомендацій:

1. **Повторне використання буферів:**
   Не виділяйте масиви `FieldValueResult` та `out_signal` на кожному кадрі симуляції. Створюйте їх один раз при ініціалізації системи і передавайте вказівники на готові буфери.

2. **Обробка попереджень насичення:**
   Завжди перевіряйте статус повернення на наявність `SUP_WARN_NONLINEAR_SATURATION`. Якщо цей статус виникає у DSP-рушії, це свідчить про кліпінг або нелінійне спотворення сигналу, що вимагає зменшення коефіцієнта підсилення на вході.

3. **Багатопотокова обробка великих масивів:**
   Для великої кількості точок спостереження `num_targets > 10000` розбивайте масив `targets` на рівні блоки і викликайте `SupEngine_CalculateFieldMatrix` паралельно з кількох робочих потоків.

4. **Кільцеві буфери у потоковому аудіо (Lock-Free Circular Buffers):**
   У звукових рушіях реального часу вхідні відліки `in_signal` надходять безперервними фрагментами (наприклад, по 128 або 256 відліків). Для неперервного обчислення суперпозиції згортки з функцією Гріна використовуйте кільцевий буфер розміром `L_in + L_h`. Кожен новий блок додається до буфера, а старі відліки зсуваються без переподілу пам'яті.

5. **Точність обчислень та нормалізація:**
   Для запобігання втрати значущих цифр при додаванні багатьох малих полів до великих (помилка накопичення плаваючої коми) впорядковуйте джерела у масиві `sources` за зростанням модуля їхньої інтенсивності перед викликом обчислювача.

### 8. Повний приклад використання (Integration Example)

Нижче наведено приклад інтеграції API `SuperpositionEngine` для одночасного розрахунку польової суперпозиції та часової згортки імпульсного відгуку:

```c
#include <stdio.h>
#include <stdlib.h>

/* Імітація заголовка бібліотеки */
#include "superposition_engine.h"

int main(void) {
    /* 1. Налаштування точкових джерел полів */
    FieldSourceSpec sources[2] = {
        { .x = -1.0, .y = 0.0, .z = 0.0, .intensity = 1e-6, .phase_shift = 0.0 },
        { .x =  1.0, .y = 0.0, .z = 0.0, .intensity = 2e-6, .phase_shift = 0.0 }
    };

    TargetPointSpec target = { .x = 0.0, .y = 2.0, .z = 0.0 };
    FieldValueResult result;

    SupStatus status = SupEngine_CalculateFieldMatrix(sources, 2, &target, 1, &result);
    if (status == SUP_SUCCESS) {
        printf("Польова суперпозиція успішна:\n");
        printf("  F_total = (%e, %e, %e) Н/Кл\n", result.Fx, result.Fy, result.Fz);
        printf("  V_total = %e В\n", result.potential);
    }

    /* 2. Налаштування та запуск часової згортки (функція Гріна) */
    double h[3] = { 1.0, 0.5, 0.2 };
    GreenKernelConfig g_config = {
        .h_kernel = h,
        .h_length = 3,
        .max_amp = 5.0,
        .sample_rate = 1000.0
    };

    double signal[4] = { 0.5, 1.0, 1.5, 0.0 };
    double output[6];

    status = SupEngine_ProcessGreenConvolution(&g_config, signal, 4, output, 6);
    if (status == SUP_SUCCESS || status == SUP_WARN_NONLINEAR_SATURATION) {
        printf("Часова суперпозиція (згортка) успішна:\n");
        for (size_t i = 0; i < 6; ++i) {
            printf("  y[%zu] = %.3f\n", i, output[i]);
        }
        if (status == SUP_WARN_NONLINEAR_SATURATION) {
            printf("УВАГА: Виявлено насичення сигналу!\n");
        }
    }

    return 0;
}
```
