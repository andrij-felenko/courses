# 📋 Резонансний біквадратний фільтр (Biquad IIR Filter): API та реалізація на C і C++

У цій довідковій вставці описано програмний інтерфейс (API), алгоритмічну структуру та математичне забезпечення цифрового резонансного фільтра другого порядку (біквадрата, *Biquad IIR Filter*). Фільтр є фундаментальною базовою цеглиною сучасної цифрової обробки сигналів (DSP), аудіоеквалайзерів, програмних радіоприймачів (SDR), медичних приладів, аналізаторів вібрацій та цифровізованих систем автоматичного керування. Наданий API дозволяє селективно підсилювати, відфільтровувати або виділяти вузьку смугу частот поблизу резонансної частоти f₀ із точним контролем добротності Q.

### 1. Принцип побудови та сфери застосування біквадрата

Будь-який лінійний цифровий фільтр із нескінченною імпульсною характеристикою (IIR-фільтр) високого порядку (наприклад, 4-го, 6-го чи 8-го порядку) в теорії можна записати у вигляді єдиного довгого різницевого рівняння. Проте на практиці таке пряме обчислення ніколи не застосовують. Причиною цього є надзвичайно висока чутливість полюсів поліномів високих степенів до найменших похибок округлення коефіцієнтів. Невелика помилка у 16-бітному або навіть 32-бітному представленні числа з плаваючою крапкою зміщує полюс за межі одиничного кола, роблячи фільтр нестійким.

Щоб уникнути цього, будь-яку складну передавальну функцію високого порядку розкладають на множники — каскадне або паралельне з'єднання елементарних фільтрів другого порядку. Окремий цифровий фільтр другого порядку називають **біквадратом** (*Biquad*), оскільки його передавальна функція H(z) являє собою відношення двох квадратичних поліномів. Біквадратний фільтр має достатньо ступенів свободи, щоб сформувати одну пару комплексно-спряжених полюсів і нулів, забезпечуючи формування резонансного піку або провалу на заданій частоті.

У професійному аудіообладнанні біквадрати використовуються у параметричних еквалайзерах для точного коригування акустики приміщень, у цифрових кросоверах для розділення частотних смуг між динаміками, а також у синтезаторах для створення виразного резонансного тембру (*wah-wah effect*).

### 2. Математичні основи та Z-доменний аналіз

Передавальна функція H(z) цифрового біквадрата у Z-області описується виразом:

```
H(z) = (b₀ + b₁·z⁻¹ + b₂·z⁻²) / (a₀ + a₁·z⁻¹ + a₂·z⁻²)
```

Тут змінна z⁻¹ позначає стандартний елементарний оператор затримки дискретного сигналу на один крок дискретизації (один відлік). Коефіцієнти b₀, b₁, b₂ називають коефіцієнтами прямого зв'язку (*feedforward coefficients*), вони визначають положення нулів передавальної функції на комплексній площині. Коефіцієнти a₀, a₁, a₂ називають коефіцієнтами зворотного зв'язку (*feedback coefficients*), вони формують полюси системи.

Для зручності обчислень передавальну функцію завжди нормують, ділячи чисельник і знаменник на a₀. Це робить перший коефіцієнт знаменника рівним одиниці, а різницеве рівняння — готовим до безпосереднього обчислення.

#### Карта нулів та полюсів у комплексній Z-площині

Резонансні властивості фільтра повністю визначаються розташуванням його комплексних полюсів p₁ та p₂ у Z-площині:

```
p₁,₂ = r · e^(±i·θ₀)
```

де:
- θ₀ = 2·π · f₀ / f_s — нормована колова частота резонансу у радіанах на один відлік сигналу;
- r ≈ 1 − π · f₀ / (f_s · Q) — радіальна відстань від початку координат Z-площини до полюса.

Для забезпечення абсолютної чисельної стійкості фільтра обидва полюси повинні суворо перебувати всередині одиничного кола Z-площини (тобто радіус r < 1.0). Що наближеніше радіус r до одиниці, то вищою є добротність Q резонансного піку, але тим тривалішим є перехідний процес згасання власних коливань фільтра. Якщо внаслідок похибок округлення радіус r досягне або перевищить одиницю, фільтр перетворюється на нестійкий генератор незагасаючих коливань.

#### Метод білінійного Z-перетворення

Для проектирования цифрового біквадрата на основі аналогового RLC-прототипу застосовують метод білінійного Z-перетворення (*Bilinear Transform*), який пов'язує аналогову комплексну частоту s з цифровою змінною z через конформне відображення:

```
s = (2 / T) · ( (1 − z⁻¹) / (1 + z⁻¹) )
```

Оскільки білінійне перетворення нелінійно стискає нескінченний інтервал аналогових частот у скінченну зону Найквіста, виникає ефект частотного викривлення (*Frequency Warping*). Для компенсації цього спотворення проводиться попередній перерахунок резонансної частоти (Pre-warping):

```
ω₀ = 2·π · f₀ / f_s
```

За стандартними формулами Бристоу-Джонсона, для резонансного смугового фільтра зі збереженням одиничного підсилення на частоті f₀ коефіцієнти обчислюються як:

```
α = sin(ω₀) / (2 · Q)
b₀ = α
b₁ = 0.0
b₂ = −α
a₀ = 1.0 + α
a₁ = −2.0 · cos(ω₀)
a₂ = 1.0 − α
```

Нормування коефіцієнтів виконується діленням на a₀:
- `b0_norm = b₀ / a₀`
- `b1_norm = b₁ / a₀`
- `b2_norm = b₂ / a₀`
- `a1_norm = a₁ / a₀`
- `a2_norm = a₂ / a₀`

### 3. Вибір канонічної топології: Direct Form I vs Direct Form II Transposed

Існує декілька альтернативних схем реалізації різницевого рівняння у програмному коді, які мають різні вимоги до обсягу пам'яті та чутливість до похибок округлення.

#### Пряма форма I (Direct Form I)

У прямій формі I обчислення виконуються послідовно через пряму комбінацію вхідних та вихідних відліків:

```
y[n] = b0_norm·x[n] + b1_norm·x[n−1] + b2_norm·x[n−2] − a1_norm·y[n−1] − a2_norm·y[n−2]
```

Ця топологія вимагає збереження чотирьох елементів затримки: двох вхідних `x[n-1], x[n-2]` та двох вихідних `y[n-1], y[n-2]`. Її головна перевага — наявність єдиної точки сумування, що дозволяє виконувати розрахунок у 64-бітному накопичувачі акумулятора для запобігання переповненню в сигнальних процесорах з фіксованою крапкою.

#### Транспонована пряма форма II (Direct Form II Transposed)

У транспонованій прямій формі II рівняння переписується через внутрішні змінні стану z1 та z2:

```
y[n] = b0_norm·x[n] + z1[n−1]
z1[n] = b1_norm·x[n] − a1_norm·y[n] + z2[n−1]
z2[n] = b2_norm·x[n] − a2_norm·y[n]
```

Транспонована пряма форма II вимагає лише два елементи пам'яті затримки (`z1` та `z2`). Ця топологія є обчислювальним стандартом для плаваючої точки (IEEE-754 float/double). Оскільки вхідний сигнал додається безпосередньо до внутрішніх станів на кожному кроці, ця форма забезпечує мінімальний рівень фазового шуму та похибок округлення у рекурсивному контурі.

Порівняльна таблиця характеристик двох канонічних форм:

| Характеристика | Direct Form I | Direct Form II Transposed |
| :--- | :--- | :--- |
| **Кількість осередків пам'яті** | 4 (x[n-1], x[n-2], y[n-1], y[n-2]) | 2 (z1, z2) |
| **Оптимальна арифметика** | Фіксована крапка (Fixed-point DSP) | Плаваюча крапка (Float32 / Double) |
| **Чутливість до квантування станів** | Низька (при 64-бітному акумуляторі) | Мінімальна для чисельних похибок |
| **Складаність автовекторизації** | Середня | Висока (зручний SIMD-пайплайн) |

### 4. Специфікація параметрів та контракт API

Програмний інтерфейс реалізує повний цикл управління фільтром: від ініціалізації та валідації параметрів до потокової обробки сигналів.

#### Таблиця параметрів API

| Параметр | Тип | Діапазон | Опис |
| :--- | :--- | :--- | :--- |
| `sample_rate` | `float` / `double` | > 0 Гц | Частота дискретизації сигналу (наприклад, 44100.0 або 48000.0 Гц). |
| `center_freq` | `float` / `double` | 0 < f₀ < sample_rate / 2 | Центральна резонансна частота у Гц (суворо обмежена частотою Найквіста). |
| `Q` | `float` / `double` | > 0.001 (зазвичай 0.5…100.0) | Добротність резонансного піку. Що вище Q, то вужчий пік і більший підсилення. |
| `gain_db` | `float` / `double` | -40.0…+40.0 дБ | Підсилення на резонансій частоті (використовується для Peaking EQ). |
| `type` / `mode` | `enum` | Bandpass, Peaking, Lowpass | Алгоритмічний режим резонансного фільтра. |

#### Правила контракту та валідації:
- **Межа Найквіста**: центральна резонансна частота `center_freq` має бути суворо меншою за половину частоти дискретизації `sample_rate / 2` (на практиці не більше `0.499 * sample_rate`). Наближення до межі Найквіста призводить до спотворення резонансного піку через нелінійність білінійного перетворення.
- **Добротність Q**: коефіцієнт добротності має бути строго додатним чисельним значенням (`Q > 0.001`). Занадто малі значення Q позбавляють фільтр резонансних властивостей, перетворюючи його на широкосмуговий згладжувач.
- **Початковий стан**: функція ініціалізації `biquad_init` обов'язково викликає `biquad_reset`, очищаючи внутрішні стани `z1, z2 = 0`, що запобігає «клацанню» постійної складової при запуску.
- **In-place обробка**: функція `biquad_process_buffer` підтримує збіг вказівників `input` та `output`, що дозволяє фільтрувати аудіомасив без виділення додаткової пам'яті.

```c
#ifndef BIQUAD_FILTER_H
#define BIQUAD_FILTER_H

#include <stddef.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

/* Типи резонансного біквадратного фільтра */
typedef enum {
    BIQUAD_TYPE_BANDPASS = 0,  /* Смуговий резонансний фільтр */
    BIQUAD_TYPE_PEAKING,       /* Резонансний піковий еквалайзер (Peaking EQ) */
    BIQUAD_TYPE_LOWPASS_RES    /* Низькочастотний фільтр з резонансним піком */
} BiquadFilterType;

/* Структура коефіцієнтів та стану біквадратного фільтра */
typedef struct {
    /* Коефіцієнти нормованого різницевого рівняння */
    float b0;
    float b1;
    float b2;
    float a1;
    float a2;

    /* Внутрішній стан (Direct Form II Transposed) */
    float z1;
    float z2;

    /* Збережені конфігураційні параметри */
    float sample_rate;
    float center_freq;
    float Q;
    float gain_db;
    BiquadFilterType type;
} BiquadFilter;

/**
 * @brief Ініціалізувати або переконфігурувати резонансний біквадратний фільтр.
 * @return true при успішній конфігурації, false при невалідних аргументах.
 */
bool biquad_init(BiquadFilter *f, 
                 BiquadFilterType type, 
                 float sample_rate, 
                 float center_freq, 
                 float Q, 
                 float gain_db);

/**
 * @brief Скинути внутрішній стан (очистити історію затримок z1, z2).
 */
void biquad_reset(BiquadFilter *f);

/**
 * @brief Обробити один вхідний відлік сигналу.
 */
static inline float biquad_process_sample(BiquadFilter *f, float in_sample) {
    /* Direct Form II Transposed */
    float out = f->b0 * in_sample + f->z1;
    f->z1 = f->b1 * in_sample - f->a1 * out + f->z2;
    f->z2 = f->b2 * in_sample - f->a2 * out;
    return out;
}

/**
 * @brief Обробити масив відліків у пам'яті (пакетна обробка).
 */
void biquad_process_buffer(BiquadFilter *f, 
                           const float *input, 
                           float *output, 
                           size_t count);

#ifdef __cplusplus
}
#endif

#endif /* BIQUAD_FILTER_H */

/* --- Реалізація функцій C --- */
#include <math.h>

#ifndef M_PI
#define M_PI 3.14159265358979323846
#endif

bool biquad_init(BiquadFilter *f, 
                 BiquadFilterType type, 
                 float sample_rate, 
                 float center_freq, 
                 float Q, 
                 float gain_db) 
{
    if (!f || sample_rate <= 0.0f || center_freq <= 0.0f || Q <= 0.001f) {
        return false;
    }

    if (center_freq >= sample_rate * 0.499f) {
        return false;
    }

    f->sample_rate = sample_rate;
    f->center_freq = center_freq;
    f->Q = Q;
    f->gain_db = gain_db;
    f->type = type;

    double w0 = 2.0 * M_PI * (double)center_freq / (double)sample_rate;
    double alpha = sin(w0) / (2.0 * (double)Q);
    double cos_w0 = cos(w0);
    double A = pow(10.0, (double)gain_db / 40.0);

    double b0_raw = 0.0, b1_raw = 0.0, b2_raw = 0.0;
    double a0_raw = 1.0, a1_raw = 0.0, a2_raw = 0.0;

    switch (type) {
        case BIQUAD_TYPE_BANDPASS:
            b0_raw = alpha;
            b1_raw = 0.0;
            b2_raw = -alpha;
            a0_raw = 1.0 + alpha;
            a1_raw = -2.0 * cos_w0;
            a2_raw = 1.0 - alpha;
            break;

        case BIQUAD_TYPE_PEAKING:
            b0_raw = 1.0 + alpha * A;
            b1_raw = -2.0 * cos_w0;
            b2_raw = 1.0 - alpha * A;
            a0_raw = 1.0 + alpha / A;
            a1_raw = -2.0 * cos_w0;
            a2_raw = 1.0 - alpha / A;
            break;

        case BIQUAD_TYPE_LOWPASS_RES:
            b0_raw = (1.0 - cos_w0) / 2.0;
            b1_raw = 1.0 - cos_w0;
            b2_raw = (1.0 - cos_w0) / 2.0;
            a0_raw = 1.0 + alpha;
            a1_raw = -2.0 * cos_w0;
            a2_raw = 1.0 - alpha;
            break;

        default:
            return false;
    }

    f->b0 = (float)(b0_raw / a0_raw);
    f->b1 = (float)(b1_raw / a0_raw);
    f->b2 = (float)(b2_raw / a0_raw);
    f->a1 = (float)(a1_raw / a0_raw);
    f->a2 = (float)(a2_raw / a0_raw);

    biquad_reset(f);
    return true;
}

void biquad_reset(BiquadFilter *f) {
    if (f) {
        f->z1 = 0.0f;
        f->z2 = 0.0f;
    }
}

void biquad_process_buffer(BiquadFilter *f, 
                           const float *input, 
                           float *output, 
                           size_t count) 
{
    if (!f || !input || !output) return;

    for (size_t i = 0; i < count; ++i) {
        output[i] = biquad_process_sample(f, input[i]);
    }
}
```

#pragma once

#include <cmath>
#include <vector>
#include <span>
#include <expected>
#include <system_error>
#include <numbers>

enum class ResonantBiquadMode {
    Bandpass,
    PeakingEQ,
    ResonantLowpass
};

enum class BiquadError {
    InvalidSampleRate,
    InvalidCenterFrequency,
    InvalidQualityFactor,
    FrequencyAboveNyquist
};

class ResonantBiquadFilter {
public:
    struct Params {
        float sample_rate{44100.0f};
        float center_freq{1000.0f};
        float Q{1.0f};
        float gain_db{0.0f};
        ResonantBiquadMode mode{ResonantBiquadMode::Bandpass};
    };

    constexpr ResonantBiquadFilter() noexcept = default;

    // Конструктор з ініціалізацією параметрів
    static std::expected<ResonantBiquadFilter, BiquadError> create(const Params& p) {
        ResonantBiquadFilter filter;
        auto result = filter.configure(p);
        if (!result) {
            return std::unexpected(result.error());
        }
        return filter;
    }

    // Налаштувати/змінити параметри резонансу під час роботи
    std::expected<void, BiquadError> configure(const Params& p) {
        if (p.sample_rate <= 0.0f) {
            return std::unexpected(BiquadError::InvalidSampleRate);
        }
        if (p.center_freq <= 0.0f) {
            return std::unexpected(BiquadError::InvalidCenterFrequency);
        }
        if (p.Q <= 0.001f) {
            return std::unexpected(BiquadError::InvalidQualityFactor);
        }
        if (p.center_freq >= p.sample_rate * 0.499f) {
            return std::unexpected(BiquadError::FrequencyAboveNyquist);
        }

        params_ = p;

        const double w0 = 2.0 * std::numbers::pi * static_cast<double>(p.center_freq) / static_cast<double>(p.sample_rate);
        const double alpha = std::sin(w0) / (2.0 * static_cast<double>(p.Q));
        const double cos_w0 = std::cos(w0);
        const double A = std::pow(10.0, static_cast<double>(p.gain_db) / 40.0);

        double b0_raw{0.0}, b1_raw{0.0}, b2_raw{0.0};
        double a0_raw{1.0}, a1_raw{0.0}, a2_raw{0.0};

        switch (p.mode) {
            case ResonantBiquadMode::Bandpass:
                b0_raw = alpha;
                b1_raw = 0.0;
                b2_raw = -alpha;
                a0_raw = 1.0 + alpha;
                a1_raw = -2.0 * cos_w0;
                a2_raw = 1.0 - alpha;
                break;

            case ResonantBiquadMode::PeakingEQ:
                b0_raw = 1.0 + alpha * A;
                b1_raw = -2.0 * cos_w0;
                b2_raw = 1.0 - alpha * A;
                a0_raw = 1.0 + alpha / A;
                a1_raw = -2.0 * cos_w0;
                a2_raw = 1.0 - alpha / A;
                break;

            case ResonantBiquadMode::ResonantLowpass:
                b0_raw = (1.0 - cos_w0) / 2.0;
                b1_raw = 1.0 - cos_w0;
                b2_raw = (1.0 - cos_w0) / 2.0;
                a0_raw = 1.0 + alpha;
                a1_raw = -2.0 * cos_w0;
                a2_raw = 1.0 - alpha;
                break;
        }

        b0_ = static_cast<float>(b0_raw / a0_raw);
        b1_ = static_cast<float>(b1_raw / a0_raw);
        b2_ = static_cast<float>(b2_raw / a0_raw);
        a1_ = static_cast<float>(a1_raw / a0_raw);
        a2_ = static_cast<float>(a2_raw / a0_raw);

        return {};
    }

    // Скидання внутрішньої історії фільтра
    void reset() noexcept {
        z1_ = 0.0f;
        z2_ = 0.0f;
    }

    // Обробка одного відліку в реальному часі (Inlined)
    [[nodiscard]] inline float process_sample(float in_sample) noexcept {
        const float out = b0_ * in_sample + z1_;
        z1_ = b1_ * in_sample - a1_ * out + z2_;
        z2_ = b2_ * in_sample - a2_ * out;
        return out;
    }

    // Обробка буфера через std::span
    void process(std::span<const float> input, std::span<float> output) noexcept {
        const size_t count = std::min(input.size(), output.size());
        for (size_t i = 0; i < count; ++i) {
            output[i] = process_sample(input[i]);
        }
    }

    [[nodiscard]] constexpr const Params& params() const noexcept { return params_; }

private:
    Params params_{};
    float b0_{1.0f}, b1_{0.0f}, b2_{0.0f};
    float a1_{0.0f}, a2_{0.0f};
    float z1_{0.0f}, z2_{0.0f};
};
:::

### 6. Покроковий розбір обчислювальної реалізації

Аналіз ключових архітектурних рішень, прийнятих при розробці API:

1. **Безпека типів у C++23**:
   В інтерфейсі C++ застосовано мовну конструкцію `std::expected<ResonantBiquadFilter, BiquadError>`. Це унеможливлює створення об'єкта фільтра з некоректними чисельним значеннями (наприклад, з резонансною частотою за межею Найквіста або від'ємною добротністю). На відміну від винятків (`exceptions`), використання `std::expected` гарантує відсутність додаткових витрат на розгортання стеку у реальному часі.

2. **Використання `std::span` для нульового копіювання**:
   Приймаючи `std::span<const float>` та `std::span<float>`, метод обробки буфера не виділяє динамічну пам'ять у купі (heap). Фільтр працездатний як з динамічними векторами `std::vector<float>`, так і з фіксованими масивами на стеку `std::array<float, N>` або сумісними аудіобуферами операційних систем.

3. **Оптимізація обчислювального ядра**:
   Обробка одного відліку у функції `biquad_process_sample` потребує всього 5 множень та 4 додавання. Послідовна структура обчислень дозволяє компілятору розгортати цикл обробки буфера (loop unrolling) та застосовувати векторні інструкції SIMD (AVX-256 / NEON) для паралельної обробки декількох аудіоканалів.

### 7. Практичні особливості експлуатації та крайові випадки

1. **Захист від денормалізованих чисел (*Denormal numbers*)**. 
   Якщо на вхід фільтра тривалий час не надходить сигнал (пауза в аудіопотоці), значення елементів затримки `z1` та `z2` починають експоненційно згасати. Перетинаючи межу `1.175494e-38f` (найменше нормалізоване число 32-бітного float), процесор потрапляє у режим обробки денормалів. На багатьох процесорах обробка денормалізованих чисел викликає переключення на мікрокод і сповільнює обчислення у **100–1000 разів**, створюючи пікові зависання аудіопотоку.

   Способи усунення проблеми денормалів:
   - Включення апаратних прапорців пропуску денормалів на рівні процесора:
     ```cpp
     #include <xmmintrin.h>
     _mm_setcsr(_mm_getcsr() | 0x8000 | 0x0040); // FTZ та DAZ для x86 SSE
     ```
   - Додавання постійної мікроскопічної смести на вхід фільтра: `in_sample += 1e-18f`.

2. **Усунення цифрового клацання при переналаштуванні (*Zipper Noise*)**. 
   Миттєва зміна коефіцієнтів b₀…a₂ під час обробки сигналу призводить до стрибка станів z1, z2, що сприймається на слух як неприємне клацання. Для плавного переналаштування коефіцієнти фільтра перераховують не миттєво, а інтерполюють за лінійним або експоненційним законом протягом 10–50 мілісекунд.

3. **Обмеження квантування коефіцієнтів у 16-бітних DSP з фіксованою крапкою**.
   При реалізації біквадрата у 16-бітній арифметиці з фіксованою крапкою (наприклад, формат Q1.15) при низьких частотах f₀ « sample_rate коефіцієнт a₁ = −2·cos(ω₀) наближається до значення −2.0. Похибка квантування 16-бітної сітки викликає висунення полюсів за одиничне коло, що призводить до самозбудження фільтра. У таких DSP коефіцієнти зворотного зв'язку обов'язково зберігають у 32-бітному або 48-бітному розрядному сітці.

4. **Запобігання ефекту генерації обмежених циклів (*Limit Cycles*)**.
   У рекурсивних фільтрах із фіксованою крапкою через округлення результатів множення у контурі зворотного зв'язку навіть при нульовому вхідному сигналі можуть виникати стійкі малоамплітудні коливання — так звані граничні цикли (Limit Cycles). Для їхнього придушення у станах затримки застосовують спеціальні типи округлення з диппресією (Magnitude Truncation) або додають елементи випадкового dither-шуму.

5. **Каскадування біквадратних секцій**.
   Для створення резонансних еквалайзерів та складних смугових фільтрів вищого порядку (наприклад, фільтр Баттерворта або Чебишева 8-го порядку) декілька біквадратних структур об'єднують у каскадні ланцюги. Кожен біквадрат обробляє вихідні дані попереднього каскаду, що гарантує обчислювальну стійкість системи у цілому.
