# ⚙️ Суперпозиція в коді: складання, биття, стояча хвиля

Фізика суперпозиції вміщається в один знак «плюс»: у кожній точці простору й у кожну мить часу повне відхилення дорівнює сумі відхилень від кожної хвилі окремо, y = y₁ + y₂. Звучить майже надто просто, щоб із цього виростала ціла наука. Але варто перекласти правило кодом — і виявляється, що й тиша в навушниках із шумозаглушенням, і «ва-ва-ва» розстроєної струни, і чиста нота гітари, і тембр будь-якого інструмента — усе це одна дія над числами: **поелементне додавання двох масивів**. Різниця між явищами живе не в тому, *як* ми додаємо, а лише в тому, *що* саме складаємо. Зберемо кожне з них із нуля — і переконаємось у цьому на власні очі.

### Хвиля — це масив чисел

Щоб хвиля потрапила в програму, її треба **дискретизувати**: замість неперервної кривої зберігати її висоту через рівні проміжки часу — набір **відліків** (англ. *samples*). Частоту відліків fs беруть фіксовану (для звуку — стандартні 44100 на секунду), і тоді n-й відлік відповідає миті t = n/fs. Уся хвиля стає масивом, а формула синусоїди перетворюється на рецепт заповнення цього масиву:

```
y[n] = A · sin(2π · f · n/fs + φ)
```

```python
import numpy as np

fs = 44_100                        # скільки відліків беремо за секунду, Гц

def wave(freq, amp=1.0, phase=0.0, dur=1.0):
    """Масив відліків біжучої синусоїди: y[n] = amp·sin(2π·freq·n/fs + phase)."""
    n = np.arange(int(fs * dur))   # номери відліків: 0, 1, 2, …
    t = n / fs                     # мить кожного відліку, с
    return amp * np.sin(2 * np.pi * freq * t + phase)
```

Тут ховається одне мовчазне припущення, про яке варто пам'ятати одразу: fs мусить бути **більш ніж удвічі** вища за найвищу частоту в сигналі. Інакше швидке коливання, дискретизоване надто рідко, «складеться» на чуже низьке — і код чутиме не той тон, що є. Ця межа й те, як відліки однозначно відновлюють неперервну хвилю, — окрема [теорема про дискретизацію Найквіста–Шеннона](book:math/sampling-theorem). А сам один чистий тон правильно генерують не «в лоб», а накопиченням фази, щоб між викликами не було стрибків і клацань, — про це [синусоїда](book:physics/sine-wave) та [фазовий акумулятор](book:physics/sine-wave/proj-phase-accumulator.md). Нам зараз важливо лише те, що хвиля тепер — це `numpy`-масив, з яким можна робити арифметику.

### Складання відлік за відліком

Ось воно, серце всієї теми. Суперпозиція каже: у кожній точці відхилення додаються. Точка в коді — це відлік з певним номером n. Отже, скласти дві хвилі означає в кожному n узяти відлік з першого масиву, відлік з другого й записати їхню суму:

```
y[n] = y₁[n] + y₂[n]      для кожного n
```

У `numpy` цей цикл ховається за одним символом `+` над масивами; у мові реального часу він стоїть відкрито — саме такий цикл крутить звукова карта на кожному буфері. Ось обидва погляди на ту саму дію:

:::tabs
```python
y1 = wave(220.0, amp=0.5)          # нижчий тон
y2 = wave(330.0, amp=0.3)          # вищий (квінта над ним)
y  = y1 + y2                       # суперпозиція — увесь фокус в одному «+»

# «+» над масивом — це прихований цикл відлік за відліком; ось він явно:
y = np.empty_like(y1)
for n in range(len(y1)):
    y[n] = y1[n] + y2[n]           # точка з першої + точка з другої в тому самому n
```
```c
#include <stdint.h>

/* Змішати дві доріжки в одну — саме це audio-callback робить на КОЖЕН буфер.
   Відлік — int16 у межах [-32768, 32767]. Сума двох може вилізти за край,
   тож накопичуємо ширше (int32) і обрізаємо — інакше буде різкий «клац». */
void mix(const int16_t *a, const int16_t *b, int16_t *out, int n)
{
    for (int i = 0; i < n; i++) {
        int32_t s = (int32_t)a[i] + b[i];   /* сума відлік за відліком */
        if (s >  32767) s =  32767;         /* насичення згори */
        if (s < -32768) s = -32768;         /* і знизу */
        out[i] = (int16_t)s;
    }
}
```
:::

![Три доріжки-стеми: відліки першої хвилі, другої і їхня поелементна сума](/book/physics/oscillations-waves/wave-superposition/img/samples-sum.svg)
*Кожен чорний стовпчик знизу — рівно сума червоного й синього над тим самим номером n. У виділеній колонці велике додатне й велике від'ємне майже погасили одне одного (0.44 + (−0.34) = 0.10): додавання алгебраїчне, гребінь як плюс, западина як мінус. Ніякої «взаємодії» немає — лише арифметика в кожній точці окремо.*

Але в C-версії вже видно першу справжню пастку, і вона глибша, ніж здається. Сума двох повних сигналів легко вилазить за межі шкали. Що робить залізо з відліком, який не влазить? **Обрізає** його до краю — це зветься **кліпінг** (англ. *clipping*):

```
дві доріжки по 0.8 повної шкали, у фазі:
сума  = 0.8 + 0.8 = 1.6      але шкала лише ±1.0
обрізано до 1.0              верхівки зрізано пласко
```

Зрізана верхівка — це вже не синусоїда: пласка «полиця» замість гребеня. А пласка полиця, розкладена на гармоніки, повна різких високих складових — тому кліпінг чутно як брудний, хрипкий «перегруз». І ось у чому краса: **кліпінг — це цифрове відлуння того, як реальна хвиля перекидається на мілині**. Поки все мале, середовище (чи шкала) відповідає пропорційно й додавання ідеальне; жени велике — і пропорційність ламається, лінійна сума поступається спотворенню. Лік простий: дати **запас** (англ. *headroom*) — мікшувати з коефіцієнтами, чия сума не більша за одиницю (наприклад, поділити кожну доріжку навпіл), або тримати ширший тип, як int32 у прикладі.

> 🔧 **Навіщо це.** Це не навчальна вправа, а буквально те, що робить кожен звуковий мікшер, ігровий рушій і DAW: підсумовує доріжки поелементно. Запас гучності — причина, чому майстер-шину рідко тримають упритул до 0 dB. Ширший акумулятор із «сторожовими» бітами — причина, чому апаратний DSP рахує суму в 32 чи 40 бітах, а зрізає лише наприкінці. Один знак «плюс» — і вже треба інженерне рішення.

### Інтерференція в точці: додаємо стрілки, не хвилі

Коли обидві хвилі однієї частоти, зовсім не конче складати всі 44100 відліків, щоб дізнатись амплітуду їхньої суми, — досить додати дві **стрілки-фазори**. Фазор у коді — це комплексне число: його довжина є амплітуда, а кут є фаза. Додавання хвиль однакової частоти зводиться до додавання цих стрілок як векторів, а довжина суми одразу дає амплітуду результату:

```python
import numpy as np

A1, phi1 = 3.0, np.deg2rad(0)      # перша стрілка: довжина 3, кут 0°
A2, phi2 = 4.0, np.deg2rad(90)     # друга: довжина 4, кут 90°
z = A1*np.exp(1j*phi1) + A2*np.exp(1j*phi2)   # додаємо стрілки як вектори
A = abs(z)                                     # довжина суми = амплітуда
# A = 5.0 — і це рівно √(3² + 4² + 2·3·4·cos90°) = √25 = 5
```

Один рядок комплексної арифметики відтворює всю формулу A = √(A₁² + A₂² + 2·A₁·A₂·cos Δφ), бо |z₁ + z₂|² розкривається саме в неї. Звідси й уся гра підсилення й гасіння по простору — [інтерференція хвиль](book:physics/wave-interference): змінюйте лише різницю кутів Δφ, і довжина суми плавно котиться від A₁ + A₂ (стрілки в лад) до |A₁ − A₂| (стрілки назустріч). Жодного масиву — лише дві стрілки.

### Биття: обвідну видно, коли частоти майже рівні

Тепер складімо два тони не однакової, а **близької** частоти — і масив раптом заживе своїм повільним життям. Сума швидко коливається (це чутно як тон), але її розмах поволі дихає — то голосніше, то тихіше. Цю повільну «маску» гучності звуть **обвідною** (англ. *envelope*), і задача — витягти її з масиву числом, а не на око. Тригонометрія підказує, чому обвідна взагалі є: сума двох синусів дорівнює швидкій «несучій» помноженій на повільний косинус, тож розмах котиться саме цим косинусом. У коді ж найнадійніший спосіб дістати обвідну будь-якого сигналу — **аналітичний сигнал** (перетворення Гілберта): його модуль і є обвідна.

```python
import numpy as np
from scipy.signal import hilbert

fs = 44_100
t  = np.arange(int(fs * 1.0)) / fs
f1, f2 = 440.0, 443.0
x = np.sin(2*np.pi*f1*t) + np.sin(2*np.pi*f2*t)   # два майже однакові тони

env       = np.abs(hilbert(x))                    # обвідна = модуль аналітичного сигналу
env_theor = 2*np.abs(np.cos(np.pi*(f1 - f2)*t))   # те саме з тотожності «сума→добуток»
# env ≈ env_theor: повільна крива, що дихає з частотою |f1 − f2|
```

Обидва вирази дають ту саму повільну криву, і її ритм читається без жодного FFT:

**Приклад (розстроєна струна).** Струна дає 443 Гц, камертон — 440 Гц.

```
f_биття = |443 − 440| = 3 Гц      гучність пульсує 3 рази на секунду
T       = 1 / 3 ≈ 0.33 с          один цикл «гучно → тихо → гучно»
```

Тут криється тонкість, на якій легко спіткнутись у коді. Повільний косинус cos(π·(f1−f2)·t) має частоту (f1−f2)/2 — здавалося б, удвічі меншу. Але вухо (і модуль `np.abs`) чують **гучність**, а гучність — це |cos|, а не cos: від'ємна півхвиля обвідної так само гучна, як додатна. Модуль складає два горби на кожен період косинуса, тож пульсацій виходить **удвічі більше** — рівно |f1 − f2| на секунду. Ось чому f_биття = |f1 − f2|, а не половина.

Обвідна через Гілберта майже ідеальна всередині сигналу, але «пливе» на самих краях масиву (перетворення не має що взяти за межами) — перші й останні кілька мілісекунд краще відкинути. А як із цієї обвідної **виміряти** частоту, не знаючи наперед ні f1, ні f2, і навіщо це цифровому тюнеру та радару — окремий інженерний конвеєр у [биттях](book:physics/beats) та їхньому [проєкті-детекторі](book:physics/beats/proj-beat-detect.md).

### Стоячу хвилю можна оживити

Найгарніше видно суперпозицію в русі. Пустимо назустріч **дві однакові хвилі** — так буває, коли хвиля відбивається від стіни й накладається на ту, що ще набігає. Складімо їх у кожній точці — і біжучий візерунок раптом спиняється:

```
y(x, t) = A·sin(kx − ωt) + A·sin(kx + ωt) = 2A·sin(kx)·cos(ωt)
```

Права частина розпадається на дві незалежні: `sin(kx)` каже лише про **місце**, `cos(ωt)` — лише про **час**. Де sin(kx) = 0, там сума нульова в будь-яку мить — це **вузол**, він стоїть нерухомо назавжди. Між вузлами середовище гойдається на повну, лише міняючи розмах за cos(ωt), — це **пучність**. Обчислимо це й переконаймось, що вузли не рухаються, а тоді оживимо картинку в браузері:

:::tabs
```python
import numpy as np

A   = 1.0
lam = 1.0
k   = 2*np.pi/lam                 # хвильове число (2π на довжину хвилі)
f   = 2.0
w   = 2*np.pi*f                   # кутова частота
x   = np.linspace(0, 3*lam, 600)  # три довжини хвилі вздовж струни

def snapshot(t):
    right = A*np.sin(k*x - w*t)   # хвиля, що біжить праворуч
    left  = A*np.sin(k*x + w*t)   # відбита, біжить ліворуч
    return right + left           # сума = 2A·sin(kx)·cos(wt)

# вузли — там, де sin(kx) = 0; сума там нульова В БУДЬ-ЯКУ мить:
nodes = x[np.isclose(np.sin(k*x), 0.0, atol=1e-3)]
# знімки різних t різняться лише множником cos(wt): x-візерунок той самий,
# міняється тільки його розмах — тому вузли стоять, а пучності дихають.
```
```javascript
const cv = document.querySelector('canvas');
const g  = cv.getContext('2d');
const A = 60, k = 2*Math.PI/140, w = 2*Math.PI*0.4;   // піксели, повільно

function draw(t) {
  g.clearRect(0, 0, cv.width, cv.height);
  g.beginPath();
  for (let px = 0; px <= cv.width; px++) {
    const right = A*Math.sin(k*px - w*t);
    const left  = A*Math.sin(k*px + w*t);
    const y = cv.height/2 - (right + left);   // та сама сума двох зустрічних
    px ? g.lineTo(px, y) : g.moveTo(px, y);
  }
  g.stroke();
  requestAnimationFrame(ts => draw(ts / 1000));   // ts у мс → секунди
}
requestAnimationFrame(ts => draw(ts / 1000));
```
:::

Запустивши JS-варіант, побачите живу картину: певні точки на екрані застигли, а між ними струна гойдається вгору-вниз — візерунок «дзвенить» на місці, нікуди не біжучи. Дві пастки, коли переносиш це на реальну струну. По-перше, відбиття від **закріпленого** кінця перевертає хвилю (додає протифазу) — саме тому в стіни завжди утворюється вузол, а не пучність. По-друге, закріплені обидва кінці **квантують** дозволені k: на струні вкладаються лише ті стоячі хвилі, у яких на кінцях вузли, — і саме їхні частоти ви чуєте як ноту з обертонами. Народження цього візерунка, вузли, пучності й дозволені частоти детально розбирає [стояча хвиля](book:physics/standing-wave).

### Будь-який звук — це сума тонів

І тепер найпотужніше. Суперпозиція не спиняється на двох доданках — складати можна скільки завгодно синусів. Візьміть синуси кратних частот, доберіть кожному амплітуду — і зберете **яку завгодно** форму. Найчистіший приклад — квадратна хвиля: це сума лише **непарних** гармонік з амплітудами 1/k:

```
квадрат(t) = (4/π) · [ sin(2πf₀t) + ⅓·sin(2π·3f₀·t) + ⅕·sin(2π·5f₀·t) + … ]
```

```python
import numpy as np

fs = 44_100
t  = np.arange(int(fs * 1.0)) / fs
f0 = 220.0

def square_from_sines(n_harm):
    y = np.zeros_like(t)
    for k in range(1, 2*n_harm, 2):        # тільки непарні: 1, 3, 5, …
        y += np.sin(2*np.pi*k*f0*t) / k    # амплітуда k-ї гармоніки = 1/k
    return (4/np.pi) * y

approx = square_from_sines(8)    # усього 8 непарних гармонік — уже впізнаваний квадрат
```

Це той самий поелементний `+=`, лише повторений багато разів — синтез тембру нічим не відрізняється від складання двох хвиль, крім кількості доданків. Що будь-яку хвилю можна зібрати із синусів, а сигнал розкласти назад на його [частотний спектр](book:physics/frequency-spectrum) — це [ідея Фур'є](book:math/fourier-idea).

![Часткові суми квадратної хвилі для 1, 3, 11 і 63 гармонік; біля стрибка лишається викид ≈9%](/book/physics/oscillations-waves/wave-superposition/img/gibbs.svg)
*Що більше гармонік складаємо, то ближча гладка сума до різкого квадрата — краї дедалі крутіші. Але біля самого стрибка лишається впертий «вушко»-викид приблизно на 9% над рівнем, і він не зникає, скільки гармонік не додай. Це явище Ґіббса.*

А ось найглибша думка всієї теми, виражена кодом. У браузері звук можна синтезувати геть інакше — не рахуючи суму самому, а **дозволивши це зробити системі**. Створіть по осциляторі на кожну гармоніку й з'єднайте всі в один вузол:

```javascript
const ac  = new AudioContext();
const out = ac.createGain();
out.gain.value = 0.2;                 // запас: багато джерел — тихіше кожне
out.connect(ac.destination);

const f0 = 220;
for (let k = 1; k < 32; k += 2) {     // непарні гармоніки квадрата
  const osc = ac.createOscillator();  // чистий синус частоти k·f0
  const g   = ac.createGain();
  osc.frequency.value = k * f0;
  g.gain.value = (4/Math.PI) / k;     // амплітуда 1/k
  osc.connect(g).connect(out);        // усі течуть в ОДИН вузол out
  osc.start();
}
// ніде немає циклу підсумовування: мікшер вузла out ДОДАЄ всі входи сам.
// Це фізична суперпозиція — тільки замість повітря складає аудіограф.
```

Ось у чому суть: **ви ніде не написали суму**. Ви лише під'єднали 16 джерел до однієї точки — і вузол `out` склав їх за вас. Це рівно те, що робить повітря, коли в кімнаті грають 16 інструментів: воно не «обчислює» суму, воно фізично несе накладені збурення, а вже вухо читає результат. Аудіограф тут — модель середовища: складання не в коді, а в самій системі.

Два підводні камені синтезу — обидва фундаментальні. Перший видно на фігурі: **явище Ґіббса** — біля розриву часткова сума завжди вискакує приблизно на 9% над рівнем, і викид не меншає з кількістю гармонік (лише вужчає). Його помітив ще Генрі Вілбрагам 1848 року, а пояснив Джозая Віллард Ґіббс 1899-го, коли Альберт Майкельсон на своєму гармонічному аналізаторі вирішив був, що це похибка машини. Другий камінь — **аліасинг**: будь-яка гармоніка k·f₀ вища за половину частоти відліків «складеться» назад на чужу низьку частоту й забруднить звук, тож синтез треба обмежувати гармоніками нижче fs/2. Ця межа (половина частоти відліків) — та сама [теорема про дискретизацію](book:math/sampling-theorem); її незалежно встановили Найквіст (1928, гранична частота), Володимир Котельников (1933) і Клод Шеннон (1949).

### Складність і пастки

Головна втіха суперпозиції в коді — її дешевизна. Скласти M хвиль по N відліків — це M·N додавань, **лінійно** за обсягом даних і чудово розпаралелюється (SIMD, GPU): додавання незалежних елементів масиву ні на що не чекає. Дорожчає не саме складання, а аналіз — розклад на спектр через FFT коштує O(N·log N).

Пастки ж, зібрані докупи, майже всі про одне — про край, де просте додавання перестає бути простим:

- **Кліпінг і переповнення.** Сума вилазить за шкалу — верхівки зрізає, це чутний бруд і прихована нелінійність. Лік: запас гучності (коефіцієнти з сумою ≤ 1) або ширший акумулятор.
- **Аліасинг.** Складова, вища за fs/2, підміняється низькою. Лік: тримати всі частоти в сумі нижче межі Найквіста.
- **Клацання на стиках.** Обірвати чи ввімкнути хвилю посеред періоду — стрибок, який чутно як «клац». Лік: генерувати через неперервну фазу — [фазовий акумулятор](book:physics/sine-wave/proj-phase-accumulator.md), — а гучність міняти плавно.
- **Краї обвідної.** Гілберт «пливе» на кінцях масиву; крайні відліки обвідної відкидають.
- **Ґіббс.** Скінченна сума синусів вискакує біля розривів; ідеально гострий квадрат недосяжний, лише наближення.

Але за всіма цими деталями стоїть одна проста річ, і заради неї варто було все це писати. **Кожне явище — це поелементне додавання масивів.** Інтерференція, биття, стояча хвиля, тембр будь-якого інструмента — код скрізь той самий `+`; різниться лише те, *що* саме ми в нього подаємо: однакові частоти чи близькі, зустрічні хвилі чи цілий гребінець гармонік. Одне правило — і весь оркестр звуку.
