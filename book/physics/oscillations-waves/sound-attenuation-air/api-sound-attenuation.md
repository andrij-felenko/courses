# 📋 Інтерфейс та специфікація бібліотеки розрахунку поглинання звуку

Модуль розрахунку атмосферного поглинання звуку надає двохавтові програмні та табличні інтерфейси для визначення коефіцієнта загасання акустичних хвиль відповідно до міжнародного стандарту ISO 9613-1:1993. Специфікація описує типи даних, контракти функцій, граничні умови, правила обробки помилок, ABI-сумісність, кешування та табличні еталонні значення.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Вхідні дані (Input)                             │
├────────────────────────┬─────────────────────┬─────────────────────────┤
│ Температура (T)        │ −20.0 .. +50.0 °C   │ Градуси Цельсія         │
│ Тиск (p)               │ 10.0 .. 200.0 кПа   │ Кілопаскалі             │
│ Вологість (h_r)        │ 0.0 .. 100.0 %      │ Відсотки                │
│ Частота (f)            │ 50.0 .. 1000000 Гц  │ Гертці                  │
└────────────────────────┴─────────────────────┴─────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        Вихідні дані (Output)                           │
├────────────────────────┬─────────────────────┬─────────────────────────┤
│ alpha_db_m             │ дБ/м                │ Поглинання на метр      │
│ alpha_db_km            │ дБ/км               │ Поглинання на кілометр  │
│ fr_oxygen_hz           │ Гц                  │ Релаксація кисню        │
│ fr_nitrogen_hz         │ Гц                  │ Релаксація азоту        │
└────────────────────────┴─────────────────────┴─────────────────────────┘
```

## 1. Контракт інтерфейсу даних та системні вимоги

Програмний інтерфейс розроблено для використання як у високонавантажених серверних системах акустичного моделювання, так і у вбудованих мікроконтролерних системах реального часу без операційної системи (bare-metal) та без динамічної пам'яті (no heap allocations).

### 1.1. Одиниці вимірювання та фізичні розмірності

Для запобігання поширеним помилкам узгодження розмірностей бібліотека строго дотримується міжнародної системи СІ та стандартних акустичних одиниць:

- **Температура (`temperature`):** Градуси Цельсія (°C) у базовому API; Кельвіни (K) у внутрішньому обчислювальному ядрі (`T_K = t_C + 273.15`). Перетворення виконується автоматично на рівні вхідних функцій модуля.
- **Атмосферний тиск (`pressure`):** Кілопаскалі (кПа). Стандартний морський тиск становить `101.325 кПа`. Для переведення з мілібарів або гектопаскалів застосовують множник `0.1`.
- **Відносна вологість (`relative_humidity`):** Відсотки (%). Діапазон дійсності: `[0.0, 100.0]`. Значення вище 100% (перенасичена пара) в інженерних розрахунках затискаються до 100%.
- **Акустична частота (`frequency`):** Гертці (Гц). Підтримуються звукові частоти чутного діапазону (20 Гц – 20 кГц) та ультразвукові частоти до 1 МГц.
- **Коефіцієнт загасання (`alpha`):** Децибели на метр (дБ/м) або Децибели на кілометр (дБ/км).
- **Рівень звукового тиску (SPL):** Децибели (дБ) щодо відносного порогового акустичного тиску `p₀ = 20 мкПа`.

Переведення між інженерними одиницями вимірювання здійснюється за стандартними фізичними формулами:
- Для переведення тиску з мілібарів (мбар) або гектопаскалів (гПа) у кілопаскалі (кПа): `p_kpa = p_mbar * 0.1`.
- Для переведення тиску з міліметрів ртутного стовпчика (мм рт. ст., Torr) у кілопаскалі: `p_kpa = p_mmhg * 0.133322`.
- Для переведення коефіцієнта поглинання з Неперів на метр (Непер/м) у децибели на метр (дБ/м): `alpha_db_m = alpha_nep * 8.68589`.

### 1.2. Специфікація структур даних (C / C++ ABI)

Усі вхідні та вихідні структури даних володіють фіксованим вирівнюванням у пам'яті (8 байтів) для забезпечення повної ABI-сумісності з мовами C, C++, Python (ctypes/FFI), Rust та Go.

:::tabs
```c
/**
 * Статуси виконання акустичного розрахунку.
 */
typedef enum {
    ISO9613_SUCCESS               =  0,  /* Успішне обчислення */
    ISO9613_ERR_INVALID_POINTER   = -1,  /* Передано NULL вказівник */
    ISO9613_ERR_FREQ_OUT_OF_RANGE = -2,  /* Частота поза межами [50 Гц..1 МГц] */
    ISO9613_ERR_TEMP_OUT_OF_RANGE = -3,  /* Температура поза межами [-20°C..+50°C] */
    ISO9613_ERR_PRESS_OUT_OF_BOUNDS = -4, /* Тиск поза межами [10 кПа..200 кПа] */
    ISO9613_ERR_HUMIDITY_OUT_OF_RANGE = -5/* Вологість поза межами [0%..100%] */
} iso9613_status_t;

/**
 * Структура входів навколишнього середовища.
 */
typedef struct {
    double temperature_c;     /**< Температура повітря, °C */
    double pressure_kpa;      /**< Атмосферний тиск, кПа */
    double humidity_pct;      /**< Відносна вологість, % */
} iso9613_environment_t;

/**
 * Структура результату поглинання звуку.
 */
typedef struct {
    double alpha_db_m;        /**< Коефіцієнт загасання, дБ/м */
    double alpha_db_km;       /**< Коефіцієнт загасання, дБ/км */
    double fr_oxygen_hz;      /**< Частота релаксації кисню O2, Гц */
    double fr_nitrogen_hz;    /**< Частота релаксації азоту N2, Гц */
    double molar_humidity;    /**< Концентрація водяної пари, % */
    double alpha_classical;   /**< Внесок Стокса-Кірхгофа, дБ/м */
    double alpha_oxygen;      /**< Внесок релаксації кисню, дБ/м */
    double alpha_nitrogen;    /**< Внесок релаксації азоту, дБ/м */
} iso9613_attenuation_result_t;
```

```cpp
namespace acoustic {

enum class Status : int32_t {
    Success = 0,
    InvalidPointer = -1,
    FrequencyOutOfRange = -2,
    TemperatureOutOfRange = -3,
    PressureOutOfBounds = -4,
    HumidityOutOfRange = -5
};

struct Environment {
    double temperature_c{20.0};
    double pressure_kpa{101.325};
    double humidity_pct{50.0};
};

struct AttenuationResult {
    double alpha_db_m{0.0};
    double alpha_db_km{0.0};
    double fr_oxygen_hz{0.0};
    double fr_nitrogen_hz{0.0};
    double molar_humidity{0.0};
    double alpha_classical{0.0};
    double alpha_oxygen{0.0};
    double alpha_nitrogen{0.0};
};

} // namespace acoustic
```

Вирівнювання полів структури `iso9613_environment_t` та `iso9613_attenuation_result_t` відповідає стандартному вирівнюванню `alignof(double) == 8` для 64-бітних архітектур x86_64 та ARM64. Це означає, що при виклику з мов системного програмування не виникає невидимих паддінг-байтів, а масиви структур можна передавати у векторні SIMD-функції без додаткових перепакувань пам'яті.

## 2. Сигнатури функцій API

### 2.1. Точковий розрахунок для однієї частоти

Функція `iso9613_calculate_attenuation` виконує повний розрахунок загасання звукової хвилі для заданих умов навколишнього середовища й частоти. Вона є чистою функцією без побічних ефектів (pure function), не використовує глобальний стан і є повністю потокобезпечною (thread-safe, reentrant).

:::tabs
```c
/**
 * @brief Обчислює атмосферне поглинання для заданої частоти та параметрів середовища.
 * 
 * @param[in]  env  Вказівник на структуру параметрів середовища.
 * @param[in]  frequency_hz  Частота акустичної хвилі у Гц.
 * @param[out] result  Вказівник на структуру для запису результатів.
 * @return iso9613_status_t Статус виконання (ISO9613_SUCCESS у разі успіху).
 */
iso9613_status_t iso9613_calculate_attenuation(
    const iso9613_environment_t *env,
    double frequency_hz,
    iso9613_attenuation_result_t *result
);
```
```cpp
namespace acoustic {

/**
 * @brief C++ ідіоматична обгортка з поверненням std::expected / std::optional.
 */
[[nodiscard]] std::optional<AttenuationResult> calculate_attenuation(
```

:::

Під час виконання точкового розрахунку алгоритм спочатку перевіряє переданий вказівник `env` на `NULL`, після чого здійснює перевірку виходу аргументів за допустимі межі. Якщо частота менша або дорівнює нулю (`frequency_hz <= 0.0`), повертається помилка `ISO9613_ERR_FREQ_OUT_OF_RANGE`. Якщо відносна вологість виходить за діапазон `[0, 100]`, викликом повертається код `ISO9613_ERR_HUMIDITY_OUT_OF_RANGE`.

### 2.2. Векторний розрахунок акустичного спектра

Для підвищення продуктивності при спектральному аналізі (наприклад, обробці 1/3-октавних смуг або спектрів ШПФ) надається векторна функція `iso9613_calculate_spectrum`. Вона розраховує частоти релаксації `f_r,O` та `f_r,N` лише один раз для всього спектра, значно економлячи обчислювальні ресурси процесора.

### 2.3. Розрахунок підсумкового загасання на відстані

Функція `iso9613_calculate_total_spl` поєднує геометричне розходження хвилі та атмосферне поглинання для обчислення підсумкового рівня звукового тиску на заданій відстані.

:::tabs
```c
/**
 * @brief Обчислює підсумковий рівень звукового тиску SPL на відстані r з урахуванням розходження та поглинання.
 * 
 * @param[in] spl_ref_db  Початковий рівень SPL на опорній відстані r_ref, дБ.
 * @param[in] r_ref_m     Опорна відстань від джерела (наприклад, 1.0 м або 10.0 м).
 * @param[in] r_target_m  Цільова відстань від джерела, м.
 * @param[in] alpha_db_m  Коефіцієнт загасання середовища, дБ/м.
 * @return double Підсумковий рівень SPL у дБ на відстані r_target_m.
 */
double iso9613_calculate_total_spl(
    double spl_ref_db,
    double r_ref_m,
    double r_target_m,
    double alpha_db_m
);
```
```cpp
namespace acoustic {

[[nodiscard]] constexpr double calculate_total_spl(
    double spl_ref_db,
    double r_ref_m,
    double r_target_m,
    double alpha_db_m
) noexcept {
    if (r_target_m <= r_ref_m || r_ref_m <= 0.0) {
        return spl_ref_db;
    }
    const double div_loss = 20.0 * std::log10(r_target_m / r_ref_m);
    const double abs_loss = alpha_db_m * (r_target_m - r_ref_m);
    return spl_ref_db - div_loss - abs_loss;
}

} // namespace acoustic
```
:::

Математично розрахунок підсумкового рівня звукового тиску враховує два комбіновані чинники: сферичне геометричне розходження `20 * log10(r_target / r_ref)` та лінійне атмосферне загасання `alpha_db_m * (r_target - r_ref)`. Якщо цільова відстань `r_target_m` менша або дорівнює опорній `r_ref_m`, функція повертає вихідне значення `spl_ref_db` без змін.

## 3. Управління пам'яттю, потокобезпека та точність обчислень

Для забезпечення надійності роботи в реальному часі бібліотека встановлює суворі гарантії щодо виконання та управління ресурсами:

### 3.1. Гарантії нерозподілу пам'яті (No Dynamic Memory Allocation)
Жодна з функцій API не викликає `malloc()`, `free()`, `new` або `delete`. Усі структури даних виділяються клієнтським кодом на стеку або у статичній пам'яті. Це гарантує відсутність фрагментації купи (heap fragmentation) та виключає невизначені затримки виконання (deterministic response time).

### 3.2. Потокобезпека та реентерабельність (Thread Safety & Reentrancy)
Усі функції ядра є реентерабельними й чистими (pure stateless functions). Вони не читають і не модифікують глобальні або статичні змінні середовища, не використовують мутекси чи локальне сховище потоків (TLS). Будь-яка кількість паралельних потоків виконання в багатопотокових обчислювальних ядрах може одночасно викликати обчислювальні функції без будь-якої синхронізації.

### 3.3. Обчислювальна точність (Precision & Double Float)
Усі внутрішні розрахунки проводяться за стандартом IEEE-754 з подвійною точністю (64-бітні числа з плаваючою комою, `double`). Це виключає нагромадження похибок округлення при розрахунку дробових степенів `(T_01 / T)^1.261` та експонент з великими від'ємними аргументами `exp(-3352 / T)`. На системах із 32-бітною плаваючою комою (single precision `float`) відносна похибка не перевищує `0.02%`, що є допустимим для аудіопроцесингу.

## 4. Табличний інтерфейс для вбудованих систем (LUT API)

На системних платформах без блоку обчислень із плаваючою комою (FPU) або на контролерах із суворими часовими лімітами (real-time DSP) прямий розрахунок виразів `pow(x, 1.261)` та `exp()` у кожному акустичному кадрі є неприпустимо дорогим. Для таких застосувань передбачено табличний інтерфейс на основі попередньо згенерованих трьохвимірних таблиць (Lookup Tables, LUT).

### 4.1. Структура сітки інтерполяції

Таблиця зберігається у флеш-пам'яті мікроконтролера (ROM / Flash) і покриває стандартні інженерні умови:
- **Ось температур:** від −20 °C до +50 °C із кроком `5 °C` (15 відліків).
- **Ось вологості:** від 10% до 90% із кроком `10%` (9 відліків).
- **Ось частот:** октавні та третиноктавні частотні центри від 63 Гц до 16 кГц (25 відліків).

Загальний обсяг таблиці становить `15 × 9 × 25 × 2 = 6750` байтів при використанні 16-бітного фіксованого формату `Q8.8`, що вільно вміщується у пам'яті будь-якого мікроконтролера (наприклад, STM32F4 або ESP32).

Механізм трилінійної інтерполяції по трьох осях `(T, h_r, f)` розраховує підсумковий коефіцієнт `α_lut` за вісімкою найближчих опорних вузлів сітки:

```
α_lut = ∑ [i=0..1] ∑ [j=0..1] ∑ [k=0..1] w_ijk * LUT[T_i, h_j, f_k]
```

де вагові коефіцієнти `w_ijk` обчислюються як добутки нормованих відстаней від запитуваної точки до відповідних граней куба сітки.

### 4.2. Сигнатура функції табличної інтерполяції

```cpp
[[nodiscard]] float lut_lookup(float temp_c, float humidity_pct, float freq_hz) noexcept;

} // namespace acoustic
```
:::

Максимальна похибка трилінійної інтерполяції відносно прямого розрахунку ISO 9613-1 не перевищує `0.05 дБ/км`, що є цілком достатнім для моніторингу довкілля та цифрової обробки звуку.

## 5. Межі застосовності та граничні умови

Модель ISO 9613-1 створена на основі фундаментальних вимірювань і має визначений домен придатності. За межами цих діапазонів похибка розрахунку зростає:

| Параметр | Стандартний діапазон ISO 9613-1 | Розширений діапазон API | Поведінка при виході за межі |
| :--- | :--- | :--- | :--- |
| **Температура (`t`)** | −20 °C .. +50 °C | −40 °C .. +70 °C | Повертає `ISO9613_ERR_TEMP_OUT_OF_RANGE` |
| **Тиск (`p`)** | 10.13 кПа .. 202.65 кПа | 10.0 кПа .. 300.0 кПа | Повертає `ISO9613_ERR_PRESS_OUT_OF_BOUNDS` |
| **Вологість (`h_r`)** | 0 % .. 100 % | 0.0 % .. 100.0 % | Затискається до діапазону `[0, 100]` |
| **Частота (`f`)** | 50 Гц .. 100 кГц | 10 Гц .. 1 МГц | На `f > 100 кГц` домінує класичне `α_cl` |

## 7. Інтеграція в багатомовні проектні середовища

C-сумісна динамічна бібліотека (`iso9613.so` / `iso9613.dll`) легко інтегрується в сучасні мови високого рівня через механізми FFI (Foreign Function Interface):

- **Python (ctypes):** Виклик функції `iso9613_calculate_attenuation` здійснюється безпосередньо через обгортку `ctypes.CDLL`. Передача структур виконується через похідний клас `ctypes.Structure` з відносною похибкою `0.0%`.
- **Rust (bindgen):** Автоматична генерація бейдингів за допомогою інструменту `bindgen` створює безпечні unsafe-обгортки над системними C-функціями модуля.
- **C# (.NET P/Invoke):** Застосування атрибута `[DllImport("iso9613.dll")]` із суворим описом полів `[StructLayout(LayoutKind.Sequential)]` дозволяє інтегрувати розрахунок у симуляційні комп'ютерні графічні рушії на базі Unity.

## 8. Стратегія обробки помилок та крайніх випадків

Усі функції розрахунку дотримуються суворих правил безпеки обчислень:
1. **Захист від недійсних вказівників (Null Pointer Safety):** При передачі вказівника `NULL` функція негайно повертає статус `ISO9613_ERR_INVALID_POINTER` без виклику винятків чи сегфолтів.
2. **Захист від ділення на нуль:** Якщо частота `f <= 0`, розрахунок відхиляється зі статусом `ISO9613_ERR_FREQ_OUT_OF_RANGE`.
3. **Обмеження чисельної нестабільності при `h_r → 0`:** При розрахунку сухого повітря волятна концентрація `h` може ставати дуже малою. Формули ISO 9613-1 гарантують чисельну стабільність і не створюють ділення на нуль завдяки наявності аддитивних констант (`0.02` та `0.391`) у чисельнику й знаменнику рівняння кисневої релаксації.
4. **Валідаційний тест модульного тестування (Unit Test Validation):** Під час автоматичного тестування кожна збірка бібліотеки звіряється з еталонними значеннями Таблиць 6.1, 6.2 та 6.3. Відхилення обчислених значень від стандарту на тестовому наборі даних не повинно перевищувати `0.01%`.
