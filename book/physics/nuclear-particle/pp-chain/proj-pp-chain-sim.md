# ⚙️ Чисельне моделювання гілкування та енерговиділення pp-ланцюжка

Чисельне моделювання pp-ланцюжка спирається на розрахунковий алгоритм та програмну систему мовами C та C++, які обчислюють швидкісні коефіцієнти ядерних реакцій, відносні частоти гілкування (pp-I, pp-II, pp-III, pp-IV) та інтегральне енерговиділення зоряного плазмового ядра залежно від температури, густини й хімічного складу.

## Фізико-математична модель та дифрівняння мережі нуклеосинтезу

Усі елементарні реакції у протон-протонному ланцюжку описуються системою зв'язаних диференціальних рівнянь кінетики для концентрацій або мольних часток ізотопів `Y_i = N_i / (ρ · N_A)`, де `N_i` — числове значення концентрації частинок типу `i`, `ρ` — густина плазми, а `N_A` — число Авогадро.

Система диференціальних рівнянь для ключових компонентів `Y_p` (протони), `Y_d` (дейтерій), `Y_3` (гелій-3), `Y_4` (гелій-4), `Y_7` (берилій-7) має вигляд:

```
dY_p / dt = - 2 · R₁₁ · Y_p² + R₃₃ · Y₃² - R₃₄ · Y₃ · Y₄ - R₇₁ · Y₇ · Y_p
dY_d / dt = R₁₁ · Y_p² - R₂₁ · Y_d · Y_p
dY_3 / dt = R₂₁ · Y_d · Y_p - 2 · R₃₃ · Y₃² - R₃₄ · Y₃ · Y₄
dY_4 / dt = R₃₃ · Y₃² + 2 · R₇₁ · Y₇ · Y_p
```

Де швидкісні коефіцієнти реакцій `R_ij = ρ · N_A · ⟨σ·v⟩_ij` є функціями локальної температури плазми `T` та густини `ρ`.

У зоряних умовах дейтерій досягає своєї квазістаціонарної рівноважної концентрації за декілька секунд (`dY_d / dt ≈ 0`), звідки отримуємо:

```
Y_d_eq = (R₁₁ · Y_p) / R₂₁
```

Гелій-3 досягає своєї стаціонарної рівноваги за час близько `10⁵ років`. У стаціонарному стані швидкість утворення `³He` збігається зі швидкістю його знищення в гілках pp-I, pp-II та pp-III:

```
R₂₁ · Y_d · Y_p = 2 · R₃₃ · Y₃² + R₃₄ · Y₃ · Y₄
```

Параметризація температурних залежностей реакційних коефіцієнтів `⟨σ·v⟩` спирається на емпіричні апроксимаційні формули астрофізичної бази даних REACLIB (Joint Institute for Nuclear Astrophysics):

1. **Реакція `p + p → ²H + e⁺ + νₑ` (`R₁₁`)**:
   Описує первинний етап слабої взаємодії. Температурна залежність має вираз:
   ```
   ⟨σ·v⟩₁₁ ∝ T₆⁻²/³ · exp(-33.804 / T₆¹/³)
   ```
   Де `T₆ = T / 10⁶ К` — температура у мільйонах кельвінів.

2. **Реакція `³He + ³He → ⁴He + 2p` (`R₃₃`)**:
   Характеризується високим кулонівським бар'єром для двох ядер із зарядами `Z = 2`:
   ```
   ⟨σ·v⟩₃₃ ∝ T₆⁻²/³ · exp(-122.76 / T₆¹/³)
   ```

3. **Реакція `³He + ⁴He → ⁷Be + γ` (`R₃₄`)**:
   Визначає перехід від гілки pp-I до гілок pp-II та pp-III:
   ```
   ⟨σ·v⟩₃₄ ∝ T₆⁻²/³ · exp(-128.01 / T₆¹/³)
   ```

4. **Реакція електронного захоплення `⁷Be + e⁻ → ⁷Li + νₑ` (`λ₇ₑ`)**:
   Оскільки берилій-7 захоплює вільний електрон плазми, швидкість реакції пропорційна електронній густині `n_e = ρ / (μ_e · m_u)` та обернено пропорційна квадратному кореню з температури через швидкості електронів:
   ```
   λ₇ₑ ∝ ρ / (μ_e · √T₆)
   ```

5. **Реакція протонного захоплення `⁷Be + p → ⁸B + γ` (`R₇₁`)**:
   Описує канал утворення високоенергетичних нейтрино бор-8:
   ```
   ⟨σ·v⟩₇₁ ∝ T₆⁻²/³ · exp(-137.56 / T₆¹/³)
   ```

Відносні частки гілкування обчислюються зі співвідношення швидкостей конкурентних ядерних каналів:

- Відношення швидкості зв'язування `³He` з `⁴He` до саморуйнування `³He + ³He`:
  ```
  γ_34 = (R₃₄ · X₄) / (R₃₃ · X₃)
  ```
  Якщо `γ_34 ≪ 1` (низька температура або мала кількість гелію-4), домінує гілка pp-I. При зростанні `γ_34 > 1` понад `80%` гелію-3 прямує в гілки pp-II та pp-III.

- Відношення швидкості захоплення протона ядром `⁷Be` до електронного захоплення:
  ```
  γ_71 = (R₇₁ · X_p · ρ) / λ₇ₑ
  ```
  При помірних температурах `T < 18 MK` переважає електронне захоплення (`pp-II`), а при високих температурах `T > 20 MK` протонне захоплення починає швидко зростати (`pp-III`).

## Програмна реалізація чисельного солвера

Нижче наведено повну реалізацію алгоритму моделювання мовами C (стандарт C99) та C++ (сучасний стандарт C++20). Програма розраховує частки кожної з чотирьох гілок, середні втрати енергії на нейтрино `⟨Q_ν⟩`, корисне теплове енерговиділення `Q_eff` та питому потужність плазми `ε_pp` (у Вт/кг).

```c
/* C99 Implementation of PP-Chain Branching and Energy Solver */
#include <stdio.h>
#include <math.h>

typedef struct {
    double temp_k;        /* Температура плазми в Кельвінах */
    double density_gcm3;  /* Густина в г/см³ */
    double x_hyd;         /* Масова частка водню X (0..1) */
    double y_hel;         /* Масова частка гелію-4 Y (0..1) */
} StellarCoreConditions;

typedef struct {
    double branch_pp1;    /* Частка гілки pp-I (0..1) */
    double branch_pp2;    /* Частка гілки pp-II (0..1) */
    double branch_pp3;    /* Частка гілки pp-III (0..1) */
    double branch_hep;    /* Частка гілки pp-IV/hep (0..1) */
    double q_eff_mev;     /* Корисна енергія на ядро He-4 (МЕв) */
    double nu_loss_mev;   /* Втрати енергії нейтрино (МЕв) */
    double energy_gen_wkg;/* Питоме енерговиділення (Вт/кг) */
} PPChainResult;

PPChainResult solve_pp_chain(const StellarCoreConditions* cond) {
    PPChainResult res;
    double T6 = cond->temp_k / 1.0e6;
    double rho = cond->density_gcm3;
    double X = cond->x_hyd;
    double Y = cond->y_hel;

    /* Термодинамічні коефіцієнти реакцій (REACLIB parametrizations) */
    double T6_13 = cbrt(T6);
    double T6_23 = T6_13 * T6_13;

    /* 1. Швидкісні параметри r_ij */
    double r11 = 4.0e-15 * (1.0 / T6_23) * exp(-33.804 / T6_13);
    double r33 = 1.2e+04 * (1.0 / T6_23) * exp(-122.76 / T6_13);
    double r34 = 5.6e+05 * (1.0 / T6_23) * exp(-128.01 / T6_13);
    double r71 = 3.1e+05 * (1.0 / T6_23) * exp(-137.56 / T6_13);
    
    /* Електронне захоплення Be-7 */
    double mu_e = 2.0 / (1.0 + X);
    double lambda_7e = 1.34e-9 * (rho / mu_e) * (1.0 / sqrt(T6));

    /* 2. Конкурентні відношення гілкування */
    double ratio_34_33 = (r34 * Y) / (r33 * X + 1.0e-30);
    double f_be = ratio_34_33 / (1.0 + ratio_34_33);
    double f_pp1 = 1.0 - f_be;

    double ratio_71_7e = (r71 * X * rho) / (lambda_7e + 1.0e-30);
    double f_pp3 = f_be * (ratio_71_7e / (1.0 + ratio_71_7e));
    double f_pp2 = f_be - f_pp3;
    double f_hep = 2.0e-7; /* Завжди малий фіксований внесок */

    res.branch_pp1 = f_pp1;
    res.branch_pp2 = f_pp2;
    res.branch_pp3 = f_pp3;
    res.branch_hep = f_hep;

    /* 3. Енергетичні втрати нейтрино для кожної гілки */
    double q_nu = f_pp1 * 0.530 + f_pp2 * 1.127 + f_pp3 * 6.975;
    res.nu_loss_mev = q_nu;
    res.q_eff_mev = 26.731 - q_nu;

    /* 4. Питоме енерговиділення (ε_pp) у Вт/кг */
    double eps = 0.241 * rho * X * X * (1.0 / T6_23) * exp(-33.804 / T6_13);
    res.energy_gen_wkg = eps * 1.0e-4; /* Конвертація в Вт/кг */

    return res;
}

int main(void) {
    StellarCoreConditions sun_center = {
        .temp_k = 15.7e6,
        .density_gcm3 = 150.0,
        .x_hyd = 0.35,
        .y_hel = 0.63
    };

    PPChainResult res = solve_pp_chain(&sun_center);

    printf("=== МОДЕЛЮВАННЯ PP-ЛАНЦЮЖКА У ЦЕНТРІ СОНЦЯ (C99) ===\n");
    printf("Температура: %.2f МК, Густина: %.1f г/см³\n", sun_center.temp_k / 1e6, sun_center.density_gcm3);
    printf("Частка pp-I  гілки: %6.2f%%\n", res.branch_pp1 * 100.0);
    printf("Частка pp-II гілки: %6.2f%%\n", res.branch_pp2 * 100.0);
    printf("Частка pp-III гілки: %6.4f%%\n", res.branch_pp3 * 100.0);
    printf("Нейтринні втрати:   %6.3f МЕв на ядро He-4\n", res.nu_loss_mev);
    printf("Корисне Q_eff:       %6.3f МЕв\n", res.q_eff_mev);
    printf("Питоме виділення:   %.4e Вт/кг\n", res.energy_gen_wkg);

    return 0;
}
```

```cpp
// Modern C++20 Implementation of PP-Chain Branching and Energy Solver
#include <iostream>
#include <cmath>
#include <array>
#include <span>
#include <string_view>
#include <expected>
#include <iomanip>

namespace astro::physics {

struct CoreConditions {
    double temp_k{15.7e6};
    double density_gcm3{150.0};
    double x_hyd{0.35};
    double y_hel{0.63};

    [[nodiscard]] constexpr double t6() const noexcept {
        return temp_k / 1.0e6;
    }
};

struct ChainBranching {
    double pp1{0.0};
    double pp2{0.0};
    double pp3{0.0};
    double hep{0.0};
    double q_eff_mev{0.0};
    double nu_loss_mev{0.0};
    double energy_gen_wkg{0.0};

    void print_summary(std::string_view label) const {
        std::cout << "=== " << label << " ===\n"
                  << std::fixed << std::setprecision(4)
                  << "Частка pp-I:   " << pp1 * 100.0 << " %\n"
                  << "Частка pp-II:  " << pp2 * 100.0 << " %\n"
                  << "Частка pp-III: " << pp3 * 100.0 << " %\n"
                  << "Нейтринні втрати: " << nu_loss_mev << " МЕв\n"
                  << "Корисне Q_eff:    " << q_eff_mev << " МЕв\n"
                  << "Енерговиділення:  " << std::scientific << energy_gen_wkg << " Вт/кг\n";
    }
};

enum class SolverError {
    InvalidTemperature,
    InvalidDensity,
    InvalidComposition
};

class PPChainSolver {
public:
    [[nodiscard]] static std::expected<ChainBranching, SolverError> 
    compute(const CoreConditions& cond) noexcept {
        if (cond.temp_k <= 0.0) return std::unexpected(SolverError::InvalidTemperature);
        if (cond.density_gcm3 <= 0.0) return std::unexpected(SolverError::InvalidDensity);
        if (cond.x_hyd < 0.0 || cond.x_hyd > 1.0) return std::unexpected(SolverError::InvalidComposition);

        ChainBranching res{};
        const double t6 = cond.t6();
        const double rho = cond.density_gcm3;
        const double X = cond.x_hyd;
        const double Y = cond.y_hel;

        const double t6_13 = std::cbrt(t6);
        const double t6_23 = t6_13 * t6_13;

        // Швидкісні коефіцієнти взаємодії
        const double r11 = 4.0e-15 * (1.0 / t6_23) * std::exp(-33.804 / t6_13);
        const double r33 = 1.2e+04 * (1.0 / t6_23) * std::exp(-122.76 / t6_13);
        const double r34 = 5.6e+05 * (1.0 / t6_23) * std::exp(-128.01 / t6_13);
        const double r71 = 3.1e+05 * (1.0 / t6_23) * std::exp(-137.56 / t6_13);

        const double mu_e = 2.0 / (1.0 + X);
        const double lambda_7e = 1.34e-9 * (rho / mu_e) * (1.0 / std::sqrt(t6));

        const double ratio_34_33 = (r34 * Y) / (r33 * X + 1.0e-30);
        const double f_be = ratio_34_33 / (1.0 + ratio_34_33);

        res.pp1 = 1.0 - f_be;
        const double ratio_71_7e = (r71 * X * rho) / (lambda_7e + 1.0e-30);
        res.pp3 = f_be * (ratio_71_7e / (1.0 + ratio_71_7e));
        res.pp2 = f_be - res.pp3;
        res.hep = 2.0e-7;

        res.nu_loss_mev = res.pp1 * 0.530 + res.pp2 * 1.127 + res.pp3 * 6.975;
        res.q_eff_mev = 26.731 - res.nu_loss_mev;

        const double eps = 0.241 * rho * X * X * (1.0 / t6_23) * std::exp(-33.804 / t6_13);
        res.energy_gen_wkg = eps * 1.0e-4;

        return res;
    }
};

} // namespace astro::physics

int main() {
    using namespace astro::physics;

    constexpr CoreConditions sun_core{.temp_k = 15.7e6, .density_gcm3 = 150.0, .x_hyd = 0.35, .y_hel = 0.63};

    if (auto result = PPChainSolver::compute(sun_core); result.has_value()) {
        result->print_summary("РЕЗУЛЬТАТ СИМУЛЯЦІЇ PP-ЛАНЦЮЖКА (C++20)");
    } else {
        std::cerr << "Помилка обчислення параметрів ядра!\n";
    }

    return 0;
}
```

## Детальний порівняльний аналіз архітектури коду

Проведена реалізація демонструє дві фундаментально різні парадигми системного програмування для чисельних методів:

1. **Парадигма C99 (процедурна безпека та низький оверхед)**:
   - Використовує процедурну структуру `StellarCoreConditions` для передачі фізичних параметрів плазми.
   - Передача параметрів здійснюється за вказівниками для запобігання копіюванню даних на стеку.
   - Форматування результатів базується на системній функції `printf`, яка вимагає строгової відповідності специфікаторів формату типів даних (`%.4e`, `%6.2f`).
   - Код може бути зкомпільований будь-яким мінімалістичним компілятором C без залежностей від стандартних бібліотек високого рівня, що робить його ідеальним для високопродуктивних обчислювальних кластерів та високопаралельних GPU-ядер.

2. **Парадигма C++20 (тип-безпечна абстракція та обробка помилок)**:
   - Використовує типізовану обгортку `std::expected<ChainBranching, SolverError>`, що дозволяє явно й безпечно перевіряти вхідні фізичні інваріанти (недопущення від'ємних температур, некоректної масової частки водню) без використання важких винятків `try-catch`.
   - Метод `print_summary` приймає тип `std::string_view`, що виключає динамічне виділення пам'яті під об'єкти `std::string` при передачі текстових міток.
   - Специфікатор `constexpr` дозволяє виконувати розрахунки фізичних параметрів безпосередньо під час компіляції програми, якщо вихідні дані відомі заздалегідь. Це знижує навантаження на процесор у реальному часі під час розрахунку великих астрофізичних сіток зоряної еволюції.

## Фізичний аналіз та крайові випадки симуляції

Аналіз чисельних результатів роботи розробленого солвера виявляє важливі фізичні закономірності реакційної кінетики у зоряних ядрах:

1. **Крайовий випадок низьких температур (`T < 10 MK`)**:
   При температурах нижче `10 МК` швидкість реакції `R₃₄` стає незхновно малою порівняно з `R₃₃`. Частка гілки `pp-I` досягає `99.9%`. Нейтринні втрати прямують до мінімального значення `0.530 МЕв` на ядро гелію-4.

2. **Крайовий випадок високих температур (`T > 20 MK`)**:
   При температурах понад `20 МК` швидкість протонного захоплення `R₇₁` швидко перевищує швидкість електронного захоплення `λ₇ₑ`. Частка борної гілки `pp-III` зростає у десятки разів, а середня енергія унесених нейтрино збільшується до `2–3 МЕв`. Це різко знижує ефективне теплове виділення `Q_eff` у плазмі.

3. **Вплив вигоряння водню в ході зоряної еволюції**:
   Зі зменшенням масової частки водню `X` та накопиченням гелію `Y` співвідношення `γ_34` зростає. Це викликає поступове зміщення горіння від pp-I до pp-II навіть за постійної температури ядра, підвищуючи нейтринне свічення зорі протягом її перебування на головній послідовності.

4. **Чисельна стійкість та жорсткі диференціальні рівняння**:
   У реальних астрофізичних кодах (таких як MESA або FLASH) систему рівнянь нуклеосинтезу розв'язують за допомогою неявних чисельних методів (наприклад, методів Гіра або неявних методів Рунге-Кутти), оскільки часові масштаби різних реакцій відрізняються на 18 порядків — від `10⁻¹⁶ секунди` (розпад берилію-8) до `10⁹ років` (ініціація pp-реакції).
