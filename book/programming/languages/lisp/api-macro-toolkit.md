# 📋 Синтаксичний інтерфейс макросистем: Common Lisp та Scheme

Макроси в сімействі мов Lisp — це спеціальні функції часу трансляції, які приймають на вхід не обчислені значення програми, а самі структури вихідного коду (дерева S-виразів або синтаксичні об'єкти) і повертають трансформований вираз для подальшої компіляції чи виконання.

На відміну від текстових макропроцесорів, макроси Lisp працюють безпосередньо з абстрактним синтаксичним деревом і мають доступ до всієї потужності мови програмування під час розгортання. В історії розвитку Lisp сформувалися дві фундаментальні парадигми побудови макроінтерфейсів:
1. **Невідфільтровані AST-макроси (Common Lisp):** оперують сирими списками cons-пар і покладаються на дисципліну розробника щодо уникнення колізій імен через генерацію унікальних символів.
2. **Гігієнічні макроси за зразками (Scheme):** використовують механізм зіставлення зі зразком і автоматично маркують лексичні контексти ідентифікаторів, роблячи випадкове захоплення змінних неможливим.

Нижче наведено структуровану довідку інтерфейсів, сигнатур, правил трансформації та типових шаблонів використання обох систем.

## 1. Специфікація макросистеми Common Lisp

У Common Lisp макрос створюється спеціальною формою `defmacro`. Коли компілятор зустрічає вираз, першим елементом якого є ім'я макросу, він призупиняє стандартну компіляцію, викликає макрофункцію з синтаксичним списком аргументів і повторно транслює отримане на виході дерево.

### Формальне визначення `defmacro`

```lisp
(defmacro name lambda-list
  [[declaration* | doc-string]]
  form*)
```

- **Параметри (`lambda-list`):** підтримують потужну деструктуризацію списків (*destructuring-bind*). Якщо замість простого імені змінної вказано вкладений шаблон списку на кшталт `(var (key val) &body body)`, макросистема автоматично розбирає вхідний S-вираз на відповідні змінні без необхідності ручного виклику `car` та `cdr`.
- **Спеціальні маркери списку параметрів:**
  - `&optional` — необов'язкові позиційні аргументи з можливістю задання значення за замовчуванням та прапорця присутності;
  - `&rest` або `&body` — зв'язує весь залишок вхідного списку виразів із заданою змінною (маркер `&body` ідентичний `&rest`, але вказує середовищу розробки на необхідність форматування з відступами для блоків коду);
  - `&key` — іменовані аргументи, що передаються у виклику через пари `:ключ значення`;
  - `&whole` — зв'язує весь вихідний вираз виклику макросу (разом із його ім'ям) в єдину змінну до початку деструктуризації.

### Оператори квазіцитування (Quasiquotation)

Побудова нових синтаксичних дерев здійснюється за допомогою системи шаблонізації S-виразів, що керується трьома спеціальними макросами рідера:

```lisp
;; Базовий синтаксис:
`(шаблон ,обчислюваний-елемент ,@список-для-вклейки)
```

1. **Backquote / Quasiquote (зворотний апостроф `` ` ``):** цитує весь наступний вираз як структуру даних, але дозволяє вибірково скасовувати цитування для окремих вкладених піддерев.
2. **Unquote (кома `,`):** тимчасово вмикає режим звичайного обчислення всередині квазіцитати. Вираз після коми обчислюється як звичайний Lisp-код, а його результат підставляється на поточну позицію списку.
3. **Unquote-splicing (кома зі знаком `@` — `,@`):** обчислює наступний вираз (результат якого обов'язково має бути списком) і вклеює всі його елементи безпосередньо в батьківський список, знімаючи зовнішню пару дужок.

### Контракт `gensym` та захист від колізій імен

Під час написання макросів, що вводять проміжні локальні змінні (`let`), виникає ризик колізії з іменами змінних, які користувач передає як аргументи макросу. Для усунення цієї проблеми Common Lisp надає функцію генерації неінтернованих символів:

```lisp
(gensym &optional string-or-number)
```

Функція `gensym` створює новий об'єкт типу `SYMBOL`, який не належить до жодного зареєстрованого пакету (*package*). Такий символ має унікальну адресу в пам'яті і ніколи не збігається за оператором `eq` із жодним символом, введеним у тексті програми.

Правило створення безпечного макросу вимагає, щоб кожна проміжна змінна генерувалася через `gensym`, а кожен аргумент макросу обчислювався строго один раз:

```lisp
(defmacro safe-square (expr)
  (let ((val-sym (gensym "VAL-")))
    `(let ((,val-sym ,expr))
       (* ,val-sym ,val-sym))))
```

### Інспекція та налагодження: `macroexpand-1` та `macroexpand`

Для перевірки коректності трансформації AST-дерев стандартом Common Lisp передбачено дві діагностичні функції:

```lisp
(macroexpand-1 form &optional environment)
(macroexpand form &optional environment)
```

- `macroexpand-1` — виконує рівно один крок макропідстановки для виразу верхнього рівня. Якщо вираз не є викликом макросу, він повертається без змін.
- `macroexpand` — рекурсивно розгортає макрос доти, доки результуючий вираз не перестане бути макроформою.
- Обидві функції повертають два значення через механізм множинних результатів: `(values expanded-form was-expanded-p)`.

## 2. Специфікація гігієнічної макросистеми Scheme

У мові Scheme (стандарти R5RS, R6RS, R7RS) макроси є **гігієнічними за замовчуванням** (*hygienic macros*). Це означає, що компілятор автоматично відстежує лексичні області видимості та автоматично перейменовує всі змінні, згенеровані макросом, унеможливлюючи конфлікти імен без участі програміста.

### Декларативні макроси: `define-syntax` та `syntax-rules`

Основний спосіб створення макросів у Scheme базується на зіставленні зі зразком:

```scheme
(define-syntax name
  (syntax-rules (literal ...)
    ((_ pattern-1) template-1)
    ((_ pattern-2) template-2)
    ...))
```

- **`literals`:** список допоміжних ключових слів (наприклад, `else`, `then`, `->`), які повинні зіставлятися буквально за ідентифікатором, а не сприйматися як змінні зв'язування шаблону.
- **Синтаксичні змінні:** будь-який ідентифікатор у зразку `pattern` (окрім символу підкреслення `_`, який позначає ім'я самого макросу, та оголошених літералів) автоматично зв'язується з відповідним піддеревом вхідного виразу.
- **Еліпсис (`...`):** вказує, що попередній елемент або група елементів зразка може повторюватися нуль або більше разів. У шаблоні `template` еліпсис розгортає відповідну послідовність елементів паралельно:

```scheme
(define-syntax my-cond
  (syntax-rules (else)
    ((_ (else result ...))
     (begin result ...))
    ((_ (test result ...))
     (if test (begin result ...)))
    ((_ (test result ...) rest-clause ...)
     (if test
         (begin result ...)
         (my-cond rest-clause ...)))))
```

### Процедурні гігієнічні макроси: `syntax-case`

Стандарт R6RS запровадив потужнішу систему `syntax-case`, яка поєднує автоматичну лексичну гігієну з можливістю виконання довільного коду мови Scheme під час компіляції:

```scheme
(define-syntax name
  (lambda (stx)
    (syntax-case stx (literals ...)
      ((_ pattern) #'template)
      ((_ pattern-with-guard (guard-expression)) #'template))))
```

- `stx` — синтаксичний об'єкт (*syntax object*), що містить дерево виразу разом із метаданими про його лексичний контекст та номер рядка у вихідному файлі;
- `#'` — префікс створення нового синтаксичного об'єкта (*syntax template*);
- `datum->syntax` та `syntax->datum` — функції мосту, що дозволяють за потреби явно порушувати гігієну, наприклад для створення анафоричних макросів (як-от `aif`, що навмисно впроваджує змінну `it` у контекст виклику).

## 3. Зведена таблиця та порівняльний аналіз

| Характеристика | Common Lisp (`defmacro`) | Scheme (`syntax-rules`) | Scheme (`syntax-case`) |
| :--- | :--- | :--- | :--- |
| **Формат вхідних даних** | Сирі S-вирази (списки cons-пар) | Декларативні шаблони | Синтаксичні об'єкти (`stx`) |
| **Модель гігієни** | Ручна (вимагає виклику `gensym`) | Автоматична лексична | Автоматична з можливістю порушення |
| **Довільні обчислення** | Доступні в повному обсязі | Недоступні (лише шаблони) | Доступні в повному обсязі |
| **Складність діагностики** | Низька (прямий виклик `macroexpand`) | Середня (декларативні правила) | Висока (відстеження синтаксичних міток) |
| **Анафоричні макроси** | Створюються природно | Неможливі за дизайном | Створюються через `datum->syntax` |
| **Підтримка деструктуризації** | Через стандартний lambda-list | Через зіставлення зі зразком | Через зіставлення та валідатори guard |
