# 📋 Довідник специфікаторів обчислень на етапі компіляції

У сучасній мові C++ виділено розгалужену систему специфікаторів, вбудованих трейтів та синтаксичних конструкцій, які керують виконанням коду під час компіляції. Вони визначають, чи зобов'язаний вираз бути обчисленим статично, чи дозволено йому виконуватися динамічно в рантаймі, як ініціалізуються глобальні об'єкти та яким чином відсікаються неактивні гілки шаблонів.

Нижче наведено вичерпний довідник семантики, інваріантів, діагностичних вимог та крайових випадків для кожного з цих інструментів.

### 1. Ключові слова та специфікатори оголошення

| Специфікатор | Стандарт | До чого застосовується | Семантичний контракт та гарантії |
|---|---|---|---|
| `constexpr` (змінна) | C++11 | Об'єкти, статичні поля даних | Значення **мусить бути обчислене під час компіляції**. Змінна неявно отримує кваліфікатор `const`. Обов'язкова пряма ініціалізація константним виразом. Пам'ять розміщується в `.rodata` або значення підставляється інлайном. |
| `constexpr` (функція/метод) | C++11 | Функції, методи класів, конструктори, оператори, лямбди | Функція **може бути виконана під час компіляції**, якщо всі передані аргументи є константними виразами і результат вимагається в константному контексті. Якщо аргументи динамічні — функція транслюється у звичайний машинний код. Функція неявно є `inline`. |
| `consteval` | C++20 | Функції, методи класів, оператори, лямбда-вирази | **Негайна функція (immediate function).** Гарантує виконання **виключно під час компіляції**. Будь-який виклик цієї функції є константним виразом. Спроба виклику з рантайм-аргументами спричиняє жорстку помилку компіляції. Для `consteval`-функцій не генерується адреса точки входу в бінарному коді. |
| `constinit` | C++20 | Змінні зі статичною (`static`) або потоковою (`thread_local`) тривалістю життя | Гарантує, що ініціалізація змінної відбудеться **під час компіляції (статична ініціалізація)**. Захищає програму від невизначеного порядку динамічної ініціалізації між одиницями трансляції (*static initialization order fiasco*). **Не робить змінну константною** — об'єкт мутабельний і може вільно змінюватися в рантаймі. |

#### Механізм взаємодії та відмінностей

Щоб чітко розрізняти призначення цих специфікаторів, розгляньмо їхні інваріанти на прикладах:

```cpp
#include <string_view>
#include <cstdint>

// 1. constexpr змінна: гарантована константа часу збірки, незмінна в рантаймі
constexpr int MAX_PACKET_SIZE = 1500;

// 2. constexpr функція: подвійний режим роботи (compile-time або runtime)
constexpr int compute_buffer(int multiplier) noexcept {
    return MAX_PACKET_SIZE * multiplier;
}

// 3. consteval функція: жорсткий бар'єр, який ніколи не транслюється в рантайм
consteval uint32_t fnv1a_hash(std::string_view str) noexcept {
    uint32_t hash = 2166136261u;
    for (char c : str) {
        hash = (hash ^ static_cast<uint8_t>(c)) * 16777619u;
    }
    return hash;
}

// 4. constinit змінна: ініціалізується компілятором, але може змінюватися в рантаймі
constinit int g_transaction_counter = compute_buffer(2); // Початкове значення 3000

void process_event(int dynamic_multiplier) {
    // Коректно: constexpr функція працює в рантаймі з динамічними даними
    int runtime_buf = compute_buffer(dynamic_multiplier);

    // Коректно: consteval функція викликається зі статичним рядковим літералом
    constexpr uint32_t packet_id = fnv1a_hash("SENSOR_TELEMETRY_V1");

    // Помилка компіляції: consteval не можна викликати з динамічним рядком!
    // std::string dyn_str = "DYNAMIC_KEY";
    // uint32_t bad_id = fnv1a_hash(dyn_str);

    // Коректно: constinit змінну вільно модифікуємо під час виконання
    g_transaction_counter += 1;
}
```

### 2. Керуючі конструкції розгалуження та діагностичні трейти

#### `if constexpr (...)` (C++17)

Конструкція статичного умовного розгалуження в тілі функцій та шаблонів.

- **Умова:** Вираз у круглих дужках зобов'язаний бути контекстуально перетворюваним до типу `bool` константним виразом.
- **Відкинуті гілки (Discarded Statements):** Гілка, умова якої обчислилася в `false`, стає відкинутою. Компілятор не генерує для неї машинний код.
- **Семантичні вимоги до відкинутих гілок:** Код у відкинутій гілці не інстанціюється для поточних шаблонних параметрів. Це означає, що виклики методів, які відсутні у даного типу `T`, не викликають помилки компіляції, якщо вони знаходяться всередині відкинутого блоку:

```cpp
#include <type_traits>
#include <vector>

template <typename T>
auto extract_element(const T& container) {
    if constexpr (std::is_pointer_v<T>) {
        return *container;          // Інстанціюється, лише якщо T — вказівник
    } else if constexpr (requires { container.front(); }) {
        return container.front();   // Інстанціюється для контейнерів із методом front()
    } else {
        return container;           // Інстанціюється для скалярних значень
    }
}
```

#### `std::is_constant_evaluated()` (C++20, заголовок `<type_traits>`)

Функція стандартної бібліотеки, яка повертає булеве значення `true`, якщо поточний виклик виконується всередині константного інтерпретатора компілятора.

**Інваріант та правила використання:**
Функція створена для забезпечення подвійної реалізації алгоритмів: портабельної та повільної для компілятора, і високооптимізованої (з асемблером чи SIMD) для процесора.

> ⚠️ **Головна синтаксична пастка:** Заборонено писати `if constexpr (std::is_constant_evaluated())`!
> Оскільки сама конструкція `if constexpr` вимагає константного контексту для обчислення своєї умови, `std::is_constant_evaluated()` всередині неї **завжди повертає `true`**, навіть якщо вся зовнішня функція викликається у звичайному рантаймі.
> Правильне використання — виключно зі звичайним динамічним оператором `if`:

```cpp
#include <type_traits>

constexpr double power(double base, int exp) {
    if (std::is_constant_evaluated()) {
        // Гілка для компілятора: чистий цикл без системних інтринсиків
        double res = 1.0;
        for (int i = 0; i < exp; ++i) res *= base;
        return res;
    } else {
        // Гілка для рантайму: використання апаратних інструкцій процесора
        return __builtin_pow(base, exp);
    }
}
```

#### `if consteval` / `if !consteval` (C++23)

Вбудована в синтаксис мови конструкція C++23, покликана повністю усунути плутанину навколо `std::is_constant_evaluated()`. Вона явно розділяє блоки коду без необхідності підключення заголовкових файлів:

```cpp
constexpr double smart_sqrt(double x) {
    if consteval {
        // Виконується інтерпретатором компілятора (ряд Тейлора / метод Ньютона)
        return compile_time_newton_sqrt(x);
    } else {
        // Виконується процесором через машинну інструкцію SQRT
        return __builtin_sqrt(x);
    }
}
```

### 4. Типи літералів (Literal Types): формальні вимоги

Щоб тип міг використовуватися як параметр або повертане значення `constexpr`-функції, він повинен належати до категорії **типів літералів (Literal Types)**. Тип є типом літерала, якщо він задовольняє одну з таких умов:

1. **Скалярні типи:**
   - Цілочисельні типи (`char`, `int`, `uint32_t`, `size_t` тощо).
   - Типи з рухомою комою (`float`, `double`, `long double`).
   - Булевий тип `bool`.
   - Переліки `enum` та `enum class`.
   - Вказівники на об'єкти (`T*`), вказівники на функції, `std::nullptr_t`.
   - Вказівники на члени класів (`MemberPtr`).

2. **Посилання:**
   - lvalue-посилання (`T&`) та rvalue-посилання (`T&&`) на типи літералів.

3. **Масиви:**
   - Одновимірні та багатовимірні масиви, елементи яких є типами літералів.

4. **Класи та структури (Class Types), які одночасно відповідають критеріям:**
   - Мають тривіальний деструктор (у C++11–C++17) або деструктор із позначкою `constexpr` (починаючи з C++20).
   - Мають щонайменше один конструктор `constexpr`, який не є конструктором копіювання чи переміщення (або є агрегатним типом).
   - Усі нестатичні поля даних і прямі базові класи є типами літералів.
   - Не мають віртуальних базових класів (`virtual public Base`).

#### Нетипові параметри шаблонів (NTTP) на основі класів

Починаючи зі стандарту C++20, класи, які належать до типів літералів і мають відкриті поля, можуть використовуватися як нетипові параметри шаблонів (англ. *Non-Type Template Parameters, NTTP*). Це дозволяє передавати фіксовані рядки та складні конфігураційні структури безпосередньо у кутові дужки шаблонів:

```cpp
template <size_t N>
struct FixedString {
    char data[N]{};
    constexpr FixedString(const char (&str)[N]) noexcept {
        for (size_t i = 0; i < N; ++i) data[i] = str[i];
    }
};

template <FixedString Str>
void print_compile_time_tag() {
    // Str доступний як константа часу компіляції безпосередньо в типі
}

// Виклик:
// print_compile_time_tag<"SYSTEM_LOG_TAG">();
```

### 5. Заборонені операції в константних виразах (Core Constant Expression Restrictions)

Стандарт C++ суворо перелічує операції, виконання яких у константному контексті призводить до негайної зупинки компілятора та формування діагностичного повідомлення про помилку:

1. **Пряме переприведення типів (`reinterpret_cast`):** Заборонено будь-яке побітове приведення вказівників чи посилань між несумісними типами даних (для побітового копіювання значень слід застосовувати `std::bit_cast`).
2. **Читання неініціалізованих комірок пам'яті:** Спроба прочитати значення змінної, поля структури або елемента масиву до того, як туди було записано конкретні дані.
3. **Вихід за межі масиву (Out of Bounds):** Розіменування вказівника чи використання індексу за межами діапазону `[0, N)`.
4. **Витік динамічної пам'яті (Memory Leak):** Будь-який блок пам'яті, виділений оператором `new` під час виконання константного виразу, зобов'язаний бути вивільнений оператором `delete` до виходу з виразу.
5. **Розіменування недійсних вказівників:** Розіменування `nullptr`, звільненого вказівника або вказівника за межами об'єкта.
6. **Арифметична невизначена поведінка:** Знакове переповнення цілих чисел (наприклад, `INT_MAX + 1`), ділення на нуль або взяття залишку від ділення на нуль.
7. **Доступ до `volatile`-пам'яті:** Будь-яке читання або запис через вказівник або посилання з кваліфікатором `volatile`.
8. **Оператори переходу `goto`:** Заборонено мітки та переходи `goto` всередині `constexpr`-функцій (послаблено в окремих випадках у C++23 для локальних переходів).
9. **Вбудований асемблер:** Інструкції `asm`, `__asm__` або апаратні інтринсики процесора.
10. **Операції вводу/виводу та взаємодія з ОС:** Виклики системних функцій файлової системи, мережевих сокетів, виділення пам'яті рівня операційної системи чи отримання поточного календарного часу.

Ці суворі обмеження гарантують повну детермінованість та ізольованість обчислень: результат трансляції однаковий на будь-якій хост-системі незалежно від стану операційного оточення.
