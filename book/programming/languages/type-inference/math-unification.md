# 🧮 Математика уніфікації Робінсона та підстановки типів

Уніфікація (*unification*, від латинського *unus* — один і *facere* — робити) лежить в основі автоматичного виведення типів. Її мета — знайти спільний знаменник для двох або більше структурних виразів типів. Якщо компілятор бачить, що вихідний тип однієї функції повинен збігатися з вхідним типом іншої, він формулює це як алгебраїчне рівняння між деревами типів і розв'язує його шляхом пошуку підстановки для невідомих змінних.

## 1. Синтаксис термів типів

Розглядається формальна мова термів типів `T`. Множина термів визначається індуктивно над зліченною множиною змінних типів `V = {α, β, γ, ...}` та скінченною множиною констант базових типів `C = {Int, Bool, Float, String, ...}`:

```
T ::= C                  [базовий примітивний тип]
    | α                  [змінна типу, α ∈ V]
    | T₁ → T₂            [функціональний тип / стрілка]
    | T₁ × T₂            [тип пари / добуток]
    | List(T)            [параметризований конструктор типу]
```

Кожен складений терм можна розглядати як дерево: коренем є конструктор (наприклад, оператор `→` або `List`), а дочірніми вузлами — його аргументи.

Множина **вільних змінних типу** для терму `T`, позначена як `vars(T)`, визначається рекурсивно:

```
vars(C)       = ∅
vars(α)       = { α }
vars(T₁ → T₂) = vars(T₁) ∪ vars(T₂)
vars(T₁ × T₂) = vars(T₁) ∪ vars(T₂)
vars(List(T)) = vars(T)
```

Розмір терму `size(T)` визначається як кількість усіх вузлів у його синтаксичному дереві: `size(C) = 1`, `size(α) = 1`, `size(T₁ → T₂) = 1 + size(T₁) + size(T₂)`.

## 2. Підстановки та їхня композиція

**Підстановка** (*substitution*) `σ` — це скінченне відображення з множини змінних типів `V` у множину термів типів `T`:

```
σ = { α₁ ↦ T₁,  α₂ ↦ T₂,  ...,  αₙ ↦ Tₙ }
```

де кожна змінна `αᵢ` є унікальною, і `αᵢ ≠ Tᵢ`. Носієм (*domain*) підстановки називається множина змінних `dom(σ) = { α₁, α₂, ..., αₙ }`.

Застосування підстановки `σ` до терму `T` позначається як `σ(T)` і полягає в одночасній заміні кожної вільної змінної `α ∈ dom(σ)` відповідним термом `σ(α)`:

```
σ(C)       = C
σ(α)       = T,  якщо (α ↦ T) ∈ σ;  інакше α
σ(T₁ → T₂) = σ(T₁) → σ(T₂)
σ(T₁ × T₂) = σ(T₁) × σ(T₂)
```

### Композиція підстановок

Нехай дано дві підстановки `σ₁` та `σ₂`. Їхня **композиція** `σ₂ ∘ σ₁` визначається так, що для будь-якого терму `T` виконується рівність:

```
(σ₂ ∘ σ₁)(T) = σ₂(σ₁(T))
```

Алгебраїчно композиція обчислюється за таким правилом:
1. До кожного терму `Tᵢ` у відображеннях `{ αᵢ ↦ Tᵢ }` підстановки `σ₁` застосовується підстановка `σ₂`, утворюючи пари `αᵢ ↦ σ₂(Tᵢ)`.
2. До результату додаються всі відображення `βⱼ ↦ Uⱼ` з `σ₂`, для яких `βⱼ ∉ dom(σ₁)`.
3. Видаляються тривіальні тотожні пари виду `α ↦ α`.

Розглянемо покрокове обчислення композиції двох підстановок:

```
σ₂ ∘ σ₁
= { α ↦ σ₂(β → Int), γ ↦ σ₂(Bool) } ∪ { β ↦ String, δ ↦ List(Int) }    [застосування σ₂ до значень σ₁]
= { α ↦ String → Int, γ ↦ Bool, β ↦ String, δ ↦ List(Int) }            [розкриття σ₂(β) = String та збереження відображень]
```

Композиція підстановок є строго асоціативною: `(σ₃ ∘ σ₂) ∘ σ₁ = σ₃ ∘ (σ₂ ∘ σ₁)`. Нейтральним елементом виступає порожня підстановка `id = {}`, для якої виконується `id ∘ σ = σ ∘ id = σ`.

## 3. Задача уніфікації та найбільш загальний уніфікатор (MGU)

Пара термів `(T₁, T₂)` називається **уніфіковною**, якщо існує така підстановка `σ`, що:

```
σ(T₁) = σ(T₂)
```

Така підстановка `σ` називається **уніфікатором** для `T₁` та `T₂`.

Уніфікаторів для пари термів може існувати нескінченно багато. Наприклад, для двох вільних змінних `α` та `β` уніфікаторами є `{ α ↦ Int, β ↦ Int }`, `{ α ↦ Bool, β ↦ Bool }`, `{ α ↦ γ, β ↦ γ }`. Проте перші два варіанти передчасно втрачають загальність, накладаючи жорсткі обмеження там, де мова вимагає поліморфізму.

Підстановка `σ` називається **найбільш загальним уніфікатором** (*Most General Unifier*, MGU), якщо:
1. `σ` є уніфікатором для `T₁` та `T₂` (`σ(T₁) = σ(T₂)`).
2. Для будь-якого іншого уніфікатора `σ'` існує така підстановка `θ`, що:

```
σ' = θ ∘ σ
```

Це означає, що MGU не додає жодних довільних припущень і здійснює виключно ті зв'язування змінних, без яких структурна рівність термів неможлива в принципі. Якщо MGU існує, він є математично єдиним з точністю до тривіального перейменування вільних змінних.

## 4. Алгоритм уніфікації Робінсона

Алгоритм Робінсона приймає два терми `T₁` та `T₂` і повертає `MGU(T₁, T₂)` або завершується аварійною зупинкою через структурну несумісність.

Рекурсивні правила зіставлення структури виглядають так:

```
unify(T₁, T₂):
  1. Якщо T₁ ≡ T₂ (ідентичні константи або та сама змінна):
     повернути {}                                      [порожня підстановка]

  2. Якщо T₁ є змінною α:
     повернути bind_var(α, T₂)

  3. Якщо T₂ є змінною α:
     повернути bind_var(α, T₁)

  4. Якщо T₁ = (A₁ → B₁) та T₂ = (A₂ → B₂):
     σ₁ = unify(A₁, A₂)                                [уніфікуємо аргументи]
     σ₂ = unify(σ₁(B₁), σ₁(B₂))                        [уніфікуємо результати з урахуванням σ₁]
     повернути (σ₂ ∘ σ₁)

  5. Якщо T₁ = (A₁ × B₁) та T₂ = (A₂ × B₂):
     σ₁ = unify(A₁, A₂)
     σ₂ = unify(σ₁(B₁), σ₁(B₂))
     повернути (σ₂ ∘ σ₁)

  6. Якщо T₁ = List(A) та T₂ = List(B):
     повернути unify(A, B)

  7. В усіх інших випадках:
     помилка: "Неможливо узгодити типи T₁ та T₂"
```

### Процедура зв'язування змінної та Occurs-Check

Функція `bind_var(α, T)` зв'язує змінну `α` з термом `T`:

```
bind_var(α, T):
  1. Якщо T ≡ α:
     повернути {}                                      [тотожність]

  2. Якщо α ∈ vars(T):                                 [Occurs-Check]
     помилка: "Циклічна залежність: нескінченний тип α = T"

  3. Повернути { α ↦ T }
```

Перевірка входження (*occurs-check*) гарантує, що змінна `α` не міститься всередині терму `T`. Якщо ця умова порушується (наприклад, `α = α → Int`), заміна змінної створює циклічне нескінченне дерево типу `((... → Int) → Int) → Int`. У стандартних системах типізації такі терми заборонені, оскільки вони порушують завершуваність компіляції та надійність логічного виведення.

## 5. Система рівнянь та правила Мартеллі — Монтанарі

На практиці компілятор часто має справу не з однією парою типів, а з цілою системою обмежень-рівнянь: `E = { T₁,₁ = T₁,₂,  T₂,₁ = T₂,₂,  ...,  Tₘ,₁ = Tₘ,₂ }`.

Альберто Мартеллі та Уго Монтанарі (1982) формалізували уніфікацію як систему недетермінованих трансформацій множини рівнянь `E`, що послідовно спрощують систему до канонічної форми розв'язку:

1. **Delete (Видалення тотожностей):**
   `{ T = T } ∪ E  ⇒  E`
2. **Decompose (Декомпозиція конструкторів):**
   `{ f(s₁, ..., sₖ) = f(t₁, ..., tₖ) } ∪ E  ⇒  { s₁ = t₁, ..., sₖ = tₖ } ∪ E`
3. **Clash (Конфлікт конструкторів):**
   `{ f(...) = g(...) } ∪ E` де `f ≠ g`  ⇒  **Помилка розбіжності типів**.
4. **Swap (Орієнтація змінної):**
   `{ T = x } ∪ E` де `T` не є змінною  ⇒  `{ x = T } ∪ E`
5. **Eliminate (Виключення змінної):**
   `{ x = T } ∪ E` де `x ∉ vars(T)` та `x ∈ vars(E)`  ⇒  `{ x = T } ∪ E[x ↦ T]`
6. **Occurs-Check Failure:**
   `{ x = T } ∪ E` де `x ∈ vars(T)` та `x ≠ T`  ⇒  **Помилка циклічності**.

Будь-яка послідовність застосування цих правил гарантовано завершується за скінченну кількість кроків і знаходить MGU або сигналізує про помилку.

## 6. Алгоритмічна оптимізація: від копіювання дерев до Union-Find

Класична наївна реалізація алгоритму Робінсона виконує явне копіювання синтаксичних дерев під час кожного застосування підстановки `σ(T)`. У патологічних випадках це призводить до експоненційного роздування розміру термів:

```
x₁ = Pair(x₀, x₀)
x₂ = Pair(x₁, x₁)
x₃ = Pair(x₂, x₂)
...
```

Для ланцюжка з `n` таких рівнянь терм `xₙ` містить `2ⁿ` листівок `x₀`. Якщо копіювати дерево щоразу, уніфікація вимагатиме експоненційного часу `O(2ⁿ)` та аналогічного обсягу пам'яті.

Щоб досягти лінійної або майже лінійної швидкості в реальних компіляторах, структури даних замінюють на **спрямовані ациклічні графи (DAG)** зі спільними вузлами (*node sharing*) та застосовують алгоритм неперетинних множин **Union-Find** (Жерар Юе, 1976; Патерсон і Вегман, 1978).

У підході Union-Find:
- Кожна змінна типу або конструктор представляється вузлом графа.
- Замість глобального копіювання підстановки зв'язування `α ↦ T` виконується як об'єднання класів еквівалентності (`union(find(α), find(T))`) за час `O(α(n))`, де `α(n)` — обернена функція Акермана (на практиці `α(n) ≤ 4`).
- Перевірка `occurs-check` оптимізується пошуком циклів у зворотному графі залежностей.

Завдяки цьому промислові компілятори розв'язують системи з десятків тисяч рівнянь типів за лічені мілісекунди.

## 7. Покроковий розбір успішного прикладу

Розглянемо уніфікацію двох складених типів:

```
T₁ = (α → Int) → (β × α)
T₂ = (Bool → γ) → (δ × Bool)
```

Необхідно обчислити `unify(T₁, T₂)`.

**Крок 1: Головні конструктори.**
Обидва типи мають форму `L → R`.
- Ліва пара: `L₁ = (α → Int)`, `L₂ = (Bool → γ)`
- Права пара: `R₁ = (β × α)`, `R₂ = (δ × Bool)`

Обчислюємо уніфікацію лівих частин:

```
unify(α → Int, Bool → γ)
= σ₁₁ = unify(α, Bool) = { α ↦ Bool }                 [зв'язування змінної α]
  Застосовуємо σ₁₁: σ₁₁(Int) = Int,  σ₁₁(γ) = γ
  σ₁₂ = unify(Int, γ) = { γ ↦ Int }                   [зв'язування змінної γ]
= σ₁ = σ₁₂ ∘ σ₁₁ = { α ↦ Bool, γ ↦ Int }              [композиція підстановок лівої гілки]
```

**Крок 2: Застосування проміжної підстановки до правих частин.**

```
σ₁(R₁) = σ₁(β × α) = (β × Bool)                        [підстановка α ↦ Bool]
σ₁(R₂) = σ₁(δ × Bool) = (δ × Bool)                     [змінні δ та Bool не змінено]
```

**Крок 3: Уніфікація правих частин.**

```
unify(β × Bool, δ × Bool)
= σ₂₁ = unify(β, δ) = { β ↦ δ }                       [зв'язування змінної β зі змінною δ]
  Застосовуємо σ₂₁: σ₂₁(Bool) = Bool
  σ₂₂ = unify(Bool, Bool) = {}                         [ідентичні константи]
= σ₂ = σ₂₂ ∘ σ₂₁ = { β ↦ δ }                          [підстановка правої гілки]
```

**Крок 4: Фінальна композиція підстановок.**

```
σ = σ₂ ∘ σ₁
= { β ↦ δ } ∘ { α ↦ Bool, γ ↦ Int }                   [композиція підстановок обох гілок]
= { α ↦ Bool, γ ↦ Int, β ↦ δ }                         [підсумковий найбільш загальний уніфікатор MGU]
```

**Підсумкова перевірка узгодженості:**

```
σ(T₁)
= σ((α → Int) → (β × α))                               [вихідний лівий терм]
= (Bool → Int) → (δ × Bool)                            [застосування підстановки σ]

σ(T₂)
= σ((Bool → γ) → (δ × Bool))                           [вихідний правий терм]
= (Bool → Int) → (δ × Bool)                            [застосування підстановки σ]
```

Обидва вирази зведено до єдиної форми `(Bool → Int) → (δ × Bool)`. Змінна `δ` залишилася вільною, що зберігає максимальний можливий ступінь поліморфізму для виразу.

## 8. Покроковий розбір помилки Occurs-Check

Розглянемо випадок, коли уніфікація завершується помилкою через виникнення нескінченного типу:

```
T₁ = α
T₂ = List(α)
```

Спроба обчислити `unify(α, List(α))`:

```
unify(α, List(α))
= bind_var(α, List(α))                                 [виклик процедури зв'язування]
  Перевірка входження: α ∈ vars(List(α))               [перевірка occurs-check]
  vars(List(α)) = { α }                                [змінна α міститься в правому термі]
  Результат: зупинка з помилкою Occurs-Check           [циклічний тип заборонено]
```

Завдяки перевірці входження алгоритм ніколи не потрапляє в нескінченні цикли підстановки під час аналізу синтаксичного дерева програми.
