# 📜 Класифікація Карделлі-Вегнера 1985: як розклали поліморфізм по поличках

На початку 1980-х років теорія мов програмування опинилася у стані термінологічного хаосу. Стрімкий розвиток трьох незалежних шкіл — об'єктно-орієнтованої (Simula 67, Smalltalk-80), функційної (ML, Hope) та модульно-імперативної (CLU, Ada, Algol 68) — призвів до того, що інженери та вчені вживали слово «поліморфізм» для позначення абсолютно несумісних речей. Творці Smalltalk називали поліморфізмом динамічне надсилання повідомлень через таблиці методів; розробники ML мали на увазі систему типів Гіндлі-Мілнера з виведенням типів без анотацій; автори Algol 68 та Ada вважали поліморфізмом перевантаження арифметичних операторів та неявне приведення цілих чисел до дійсних. 

У наукових статтях виникали нескінченні суперечки, оскільки єдиної системи координат не існувало. Потрібна була праця, яка зведе всі ці розрізнені концепції в єдину несуперечливу таксономію. Такою працею стала стаття Луки Карделлі (англ. *Luca Cardelli*) та Пітера Вегнера (англ. *Peter Wegner*) «On Understanding Types, Data Abstraction, and Polymorphism», опублікована в грудні 1985 року в журналі *ACM Computing Surveys*.

## Дві школи до 1985 року: СТРЕЙЧІ ПРОТИ ОБ'ЄКТІВ

Першу спробу навести лад у термінології зробив британський теоретик Крістофер Стрейчі (англ. *Christopher Strachey*) ще у 1967 році в лекційних конспектах «Fundamental Concepts in Programming Languages». Стрейчі помітив фундаментальну різницю між двома механізмами:

1. **Параметричний поліморфізм** (англ. *parametric polymorphism*): коли функція виконує однаковий алгоритм над значеннями будь-якого типу, не спираючись на внутрішню будову цих значень (наприклад, визначення довжини списку).
2. **Спеціальний поліморфізм** (англ. *ad-hoc polymorphism*): коли одне й те саме ім'я позначає кілька абсолютно різних алгоритмів, а вибір конкретного коду залежить від типу аргументів (наприклад, оператор `+`, який для цілих чисел виконує додавання у регістрах, а для рядків — конкатенацію в купі).

Слово *ad-hoc* (лат. «до цього випадку», «спеціально для цієї мети») підкреслювало, що зв'язок між різними реалізаціями є суто умовним: розробник мови або бібліотеки просто приписав одну назву кільком несуміжним функціям.

Однак класифікація Стрейчі створювалася до появи розвинених систем об'єктно-орієнтованого програмування. Коли з'явилися ієрархії спадкування, віртуальні таблиці та підтипи (англ. *subtyping*), виник глухий кут. Якщо функція приймає покажчик на базовий клас `Shape` і викликає віртуальний метод `draw()`, який вид поліморфізму тут діє? З одного боку, код функції `render(Shape* s)` один для всіх фігур (схоже на параметричний). З іншого боку, кожна фігура виконує свій специфічний код малювання (схоже на ad-hoc). Теоретики сперечалися понад десятиліття, доки Карделлі та Вегнер не запропонували матричну модель систем типів.

## ЧОТИРИ ЧВЕРТІ КАРДЕЛЛІ-ВЕГНЕРА

Карделлі (який тоді працював у Bell Labs, а згодом у дослідницькому центрі DEC SRC) та Вегнер (професор Браунівського університету) запропонували дворівневий поділ. На верхньому рівні вони провели чітку межу між **універсальним** (англ. *universal*) та **спеціальним** (*ad-hoc*) поліморфізмом.

Головний критерій поділу полягав у поведінці функції:
- **Універсальний поліморфізм** працює над *необмеженою множиною типів*, зберігаючи спільну логічну структуру обчислення. Типи розглядаються як елементи єдиної алгебраїчної структури.
- **Спеціальний (ad-hoc) поліморфізм** працює лише над *скінченним, фіксованим набором типів*, і для кожного типу поведінка функції може бути докорінно іншою.

Далі автори розділили кожну категорію на дві підкатегорії, сформувавши знамениту «четвірку Карделлі-Вегнера»:

```
Поліморфізм
 ├── Універсальний (Universal)
 │    ├── Параметричний (Parametric)
 │    └── Включення / Підтиповий (Inclusion / Subtyping)
 └── Спеціальний (Ad-hoc)
      ├── Перевантаження (Overloading)
      └── Коерсивний / Приведення (Coercion)
```

### 1. Параметричний поліморфізм (Parametric)

Функція або структура даних явно чи неявно приймає типи як параметри. Тіло функції виконує однаковий алгоритм незалежно від конкретного типу-аргументу. У математичній логіці це відповідає квантору загальності `∀` (для всіх типів).

Приклади: шаблони C++ без спеціалізацій, дженерики Java/C#, параметричні функції в ML та Haskell, універсальні типи в Rust.

### 2. Поліморфізм включення (Inclusion / Subtyping)

Об'єкт належить до багатьох типів одночасно завдяки відношенню включення між типами. Якщо тип `S` є підтипом типу `T` (позначається `S <: T`), то будь-яке значення типу `S` можна безпосередньо передати туди, де очікується `T`. 

Карделлі та Вегнер розрізнили два варіанти моделювання підтипів: структурний (якщо тип має всі необхідні поля/методи — він є підтипом, наприклад у TypeScript або Go) та номінативний (підтип явно декларується спадкуванням, як у C++ чи Java).

### 3. Перевантаження (Overloading)

Один синтаксичний ідентифікатор позначає кілька різних реалізацій функцій. Вибір конкретної реалізації здійснюється компілятором під час трансляції (статичне перевантаження) на основі типів аргументів. Це чистий синтаксичний цукор: компілятор просто підставляє різні внутрішні імена функцій (процес, відомий як *name mangling*). Жодної внутрішньої єдності між перевантаженими функціями мова не вимагає.

### 4. Коерсивний поліморфізм (Coercion)

Операція визначена для аргументів певного цільового типу, але мова дозволяє передавати значення іншого типу, автоматично вставляючи код перетворення (англ. *type coercion*). Наприклад, функція множення дійсних чисел `mult(float, float)` може прийняти ціле число `int`, якщо компілятор неявно перетворить його на `float`. 

Коерсивний поліморфізм створює ілюзію поліморфної операції, хоча сама функція залишається суто мономорфною: замість поліморфізму алгоритму застосовується конверсія даних.

## ОБМЕЖЕНА КВАНТИФІКАЦІЯ: НАРОДЖЕННЯ F<:

Найглибшим теоретичним внеском статті Карделлі-Вегнера стало об'єднання двох гілок універсального поліморфізму: параметричного та підтипового. До 1985 року ці концепції існували в ізоляції: функційні мови спиралися на чистий параметризм системи F (лямбда-числення другого порядку Жана-Іва Жирара та Джона Рейнольдса), а об'єктні мови — на ієрархії підтипів.

Карделлі та Вегнер ввели поняття **обмеженої квантифікації** (англ. *bounded quantification*), створивши формальне числення `F_<:` (читається як «F-sub»).

Ідея полягала в тому, що параметр типу більше не зобов'язаний бути абсолютно довільним: на нього можна накласти обмеження підтипу зверху:

```
∀(T <: Shape). T → Canvas → T
```

Цей вираз означає: «функція працює для будь-якого типу `T`, але лише за умови, що `T` є підтипом `Shape`». Це дозволило одночасно користуватися перевагами обох світів:
- Функція має статичний доступ до інтерфейсу `Shape` (методів `draw()`, `area()`).
- Повертане значення зберігає точний тип `T` на етапі компіляції без втрати інформації про конкретний підтип (на відміну від наївного підтипового поліморфізму, де повертається знеособлений базовий `Shape`).

## ВПЛИВ НА ДИЗАЙН СУЧАСНИХ МОВ

Класифікація 1985 року стала фундаментом, на якому проєктувалися всі наступні системи типів кінця XX та початку XXI століття:

1. **Дженерики в Java та C#**: конструкції на кшталт `<T extends Comparable<T>>` у Java чи `where T : IComparable<T>` у C# є прямим втіленням числення `F_<:` Карделлі-Вегнера.
2. **Трейт-баунди в Rust**: вирази на кшталт `fn process<T: Display + Clone>(item: T)` поєднують параметричний поліморфізм з обмеженнями поведінки без необхідності використання класичного спадкування.
3. **Класи типів у Haskell**: у 1989 році Філіп Водлер та Стівен Блотт запропонували *type classes*, які перетворили ad-hoc перевантаження на суворо типізований параметричний механізм зі словниковою трансляцією (англ. *dictionary passing*).
4. **Концепти в C++20**: після тридцяти років неконтрольованих помилок компіляції шаблонів C++ отримав механізм `concept` (`template<std::floating_point T>`), який формалізує обмеження на параметри шаблонів.

Робота Карделлі та Вегнера залишається найцитованішим орієнтиром у теорії типів. Вона довела, що за розмаїттям синтаксичних конструкцій у різних мовах стоять усього чотири фундаментальні механізми, кожен з яких відповідає на конкретне інженерне питання: як розділити спільний інтерфейс між багатьма конкретними формами даних.
