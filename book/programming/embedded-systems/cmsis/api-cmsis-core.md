# 📋 Довідка контракту CMSIS-Core: інтринсики, NVIC, структури ядра

Тут зібрано ті імена, які CMSIS-Core обіцяє як контракт: якщо ім'я є в цих таблицях, воно збереться на будь-якому Cortex-M і в будь-якому з підтримуваних тулчейнів; якщо його тут немає — це вигадка виробника, і переносність на ньому закінчується. Довідка потрібна саме як межа: у щоденній роботі дорожче коштує не незнання функції, а хибна впевненість, що якесь `HAL_NVIC_…` чи `nrf_…` теж «стандартне».

Усе перелічене — заголовкові файли: `__STATIC_INLINE`-функції, `__STATIC_FORCEINLINE`-обгортки й макроси. Лінкувати нема чого, окремої бібліотеки нема, у прошивку потрапляє рівно та машинна команда, яку ти замовив.

Позначка «не на M0/M0+» у таблицях — не примха, а архітектура: в Armv6-M цих команд і регістрів фізично немає, тож і функції в `core_cm0.h` немає, і код із нею просто не збереться.

## Файли, з яких складається контракт

| Файл | Хто пише | Що дає |
|---|---|---|
| `cmsis_compiler.h` | ARM | обирає файл тулчейна: `cmsis_armclang.h`, `cmsis_clang.h`, `cmsis_gcc.h`, `cmsis_iccarm.h` |
| `cmsis_gcc.h` і рідня | ARM | інтринсики, доступ до спецрегістрів, атрибути `__WEAK`, `__PACKED`, `__ALIGNED(x)`, `__NO_RETURN`, `__USED` |
| `core_cm0.h` … `core_cm85.h` | ARM | структури блоків ядра, функції NVIC, `SysTick_Config()` |
| `cmsis_version.h` | ARM | `__CM_CMSIS_VERSION_MAIN` / `__CM_CMSIS_VERSION_SUB` — версія Core(M) |
| `<device>.h`, напр. `stm32f407xx.h` | виробник | `IRQn_Type`, конфіг-макроси ядра, структури периферії |
| `system_<device>.h` / `.c` | виробник | `SystemInit()`, `SystemCoreClock`, `SystemCoreClockUpdate()` |

Прикладний код майже ніколи не підключає ці файли напряму: один `#include "stm32f4xx.h"` тягне всю вежу. У CMSIS 6 внутрішній розклад перетасували — профільні частини поїхали в підтеки (`m-profile/cmsis_gcc_m.h`, `m-profile/armv7m_mpu.h`), — але імена, які ти пишеш у `#include`, лишилися ті самі.

## Адреси, за якими це живе

Усі блоки ядра лежать за адресами, які задає архітектура, а не виробник. Саме тому цей шар не залежить від чипа: `SCB` на STM32 і `SCB` на nRF — та сама адреса, той самий набір полів.

| Символ | Адреса | Покажчик-макрос і тип |
|---|---|---|
| `SCS_BASE` | `0xE000_E000` | `SCnSCB` → `SCnSCB_Type` (регістри керування поза SCB) |
| `SysTick_BASE` | `0xE000_E010` | `SysTick` → `SysTick_Type` |
| `NVIC_BASE` | `0xE000_E100` | `NVIC` → `NVIC_Type` |
| `SCB_BASE` | `0xE000_ED00` | `SCB` → `SCB_Type` |
| `MPU_BASE` | `0xE000_ED90` | `MPU` → `MPU_Type`, лише при `__MPU_PRESENT == 1` |
| `FPU_BASE` | `0xE000_EF30` | `FPU` → `FPU_Type` |
| `DCB_BASE` | `0xE000_EDF0` | `DCB` → `DCB_Type` (у CMSIS 5 звався `CoreDebug`) |
| `ITM_BASE` | `0xE000_0000` | `ITM` → `ITM_Type` |
| `DWT_BASE` | `0xE000_1000` | `DWT` → `DWT_Type` |
| `TPIU_BASE` | `0xE004_0000` | `TPIU` → `TPIU_Type` |

![Карта простору системного керування: SysTick за 0xE000E010, NVIC за 0xE000E100, SCB за 0xE000ED00, опційні MPU і FPU нижче, поза SCS — ITM, DWT, DCB, TPIU](/book/programming/embedded-systems/cmsis/img/scs-map.svg)
*Ці адреси задає архітектура Armv7-M, а не виробник — тому один і той самий заголовок `core_cm4.h` обслуговує чипи всіх виробників.*

## Інтринсики: одне ім'я — одна команда

**Бар'єри й підказки ядру.** `__DSB()`, `__DMB()`, `__ISB()` — справжні машинні команди, що впорядковують доступи до пам'яті ([бар'єри пам'яті](book:programming/memory-barriers) — команди, які змушують процесор завершити попередні звернення, перш ніж почати наступні). Окремо стоїть `__COMPILER_BARRIER()`: він не породжує жодної команди й лише забороняє компіляторові переставляти доступи через себе.

| Функція | Що робить | Обмеження |
|---|---|---|
| `void __NOP(void)` | одна порожня команда; для вирівнювання коду, **не** для витримок часу | — |
| `void __WFI(void)` | приспати ядро до наступного немаскованого переривання ([режими сну](book:programming/sleep-modes)) | — |
| `void __WFE(void)` | приспати до події; якщо регістр події вже зведено — прокидається одразу | — |
| `void __SEV(void)` | звести регістр події (розбудити те, що чекає на `__WFE`) | — |
| `void __ISB(void)` | скинути конвеєр: наступні команди беруться заново, вже з новим станом | — |
| `void __DSB(void)` | чекати завершення **всіх** попередніх доступів до пам'яті | — |
| `void __DMB(void)` | зафіксувати порядок доступів, не чекаючи їх завершення | — |
| `void __BKPT(uint8_t value)` | зупинити ядро в налагоджувачі; `value` мусить бути константою етапу компіляції | — |

**Перестановка бітів і байтів.** Кожна з цих — одна команда замість циклу.

| Функція | Що робить | Обмеження |
|---|---|---|
| `uint32_t __REV(uint32_t value)` | міняє порядок байтів у слові: `0x12345678` → `0x78563412` | — |
| `uint32_t __REV16(uint32_t value)` | міняє порядок байтів у кожному півслові окремо | — |
| `int16_t __REVSH(int16_t value)` | те саме для 16 біт, із розширенням знака | — |
| `uint32_t __ROR(uint32_t value, uint32_t shift)` | циклічний зсув праворуч, `shift` = 1…31 | — |
| `uint32_t __RBIT(uint32_t value)` | обертає порядок **бітів** у слові | не на M0/M0+ |
| `uint8_t __CLZ(uint32_t value)` | скільки нулів попереду старшої одиниці; для нуля — 32 | — |
| `int32_t __SSAT(int32_t value, uint32_t sat)` | обмежує знакове число розрядністю `sat` = 1…32 | не на M0/M0+ |
| `uint32_t __USAT(int32_t value, uint32_t sat)` | те саме для беззнакового, `sat` = 0…31 | не на M0/M0+ |

**Ексклюзивний доступ.** Пара «завантажити ексклюзивно — записати ексклюзивно» дає атомарну послідовність «прочитати-змінити-записати» без вимикання переривань ([атомарність і гонки](book:programming/atomicity-races) — коли операція або сталася повністю, або не сталася зовсім). Головне тут — повернене значення `__STREX*`: **0 — запис відбувся, 1 — монітор ексклюзивності зірвався**, і цикл треба повторити з початку.

| Функція | Що робить | Обмеження |
|---|---|---|
| `uint8_t __LDREXB(volatile uint8_t *addr)` | ексклюзивне читання байта | не на M0/M0+ |
| `uint16_t __LDREXH(volatile uint16_t *addr)` | ексклюзивне читання півслова | не на M0/M0+ |
| `uint32_t __LDREXW(volatile uint32_t *addr)` | ексклюзивне читання слова | не на M0/M0+ |
| `uint32_t __STREXB(uint8_t v, volatile uint8_t *addr)` | ексклюзивний запис байта; повертає 0 — успіх, 1 — невдача | не на M0/M0+ |
| `uint32_t __STREXH(uint16_t v, volatile uint16_t *addr)` | те саме для півслова | не на M0/M0+ |
| `uint32_t __STREXW(uint32_t v, volatile uint32_t *addr)` | те саме для слова | не на M0/M0+ |
| `void __CLREX(void)` | зняти ексклюзивний захват, нічого не записуючи | не на M0/M0+ |

## Спецрегістри ядра: читання й запис

Спецрегістри (PRIMASK, BASEPRI, CONTROL, стеки) недосяжні звичайним C-кодом — до них треба команду `MRS`/`MSR`. CMSIS дає на кожен пару «прочитати — записати».

| Функція | Що робить | Обмеження |
|---|---|---|
| `void __enable_irq(void)` | `CPSIE i` — скидає PRIMASK, переривання дозволено | — |
| `void __disable_irq(void)` | `CPSID i` — зводить PRIMASK, переривання заборонено | — |
| `uint32_t __get_PRIMASK(void)` / `void __set_PRIMASK(uint32_t)` | прочитати / записати PRIMASK | — |
| `void __enable_fault_irq(void)` / `void __disable_fault_irq(void)` | `CPSIE f` / `CPSID f` — керує FAULTMASK | не на M0/M0+ |
| `uint32_t __get_FAULTMASK(void)` / `void __set_FAULTMASK(uint32_t)` | прочитати / записати FAULTMASK | не на M0/M0+ |
| `uint32_t __get_BASEPRI(void)` / `void __set_BASEPRI(uint32_t)` | поріг пріоритету: глушить усе, що не строго пріоритетніше | не на M0/M0+ |
| `void __set_BASEPRI_MAX(uint32_t)` | те саме, але тільки **підвищує** поріг, ніколи не знижує | не на M0/M0+ |
| `uint32_t __get_IPSR(void)` | номер винятку, що виконується зараз; 0 — режим потоку | — |
| `uint32_t __get_APSR(void)` / `uint32_t __get_xPSR(void)` | прапорці умов / повний регістр стану | — |
| `uint32_t __get_MSP(void)` / `void __set_MSP(uint32_t)` | основний покажчик стека | — |
| `uint32_t __get_PSP(void)` / `void __set_PSP(uint32_t)` | стек процесу — на ньому стоїть [перемикання контексту](book:programming/context-switching) в RTOS | — |
| `uint32_t __get_CONTROL(void)` / `void __set_CONTROL(uint32_t)` | біт 0 — привілей у режимі потоку, біт 1 — який стек активний | — |
| `uint32_t __get_MSPLIM(void)` / `__get_PSPLIM(void)` та пари `__set_…` | апаратна межа стека | лише Armv8-M |
| `uint32_t __get_FPSCR(void)` / `void __set_FPSCR(uint32_t)` | стан дробового блоку ([FPU](book:programming/fpu)) | лише з FPU |

**Пастка перша: `__disable_irq()` вимикає не все.** Він зводить PRIMASK, а PRIMASK не глушить ані NMI, ані HardFault. Тож «переривання вимкнено» ніколи не означає «ядро точно виконає цей шматок до кінця».

**Пастка друга: наївне ввімкнення назад.** `__disable_irq(); …; __enable_irq();` дозволяє переривання навіть тоді, коли на вході в ділянку вони вже були заборонені зовні — і мовчки ламає вкладені [критичні секції](book:programming/critical-sections). Правильна форма зберігає попередній стан:

```c
uint32_t primask = __get_PRIMASK();   /* запам'ятати, як було */
__disable_irq();
/* ... неподільна ділянка ... */
__set_PRIMASK(primask);               /* відновити, а не ввімкнути наосліп */
```

## NVIC: функції керування перериваннями

Аргумент усюди один — `IRQn_Type`, номер лінії з enum виробника ([NVIC у Cortex-M](book:programming/nvic-cortex-m) — апаратний блок, що приймає запити переривань і вирішує, який із них зараз обслужити).

| Функція | Що робить | Повертає / обмеження |
|---|---|---|
| `void NVIC_EnableIRQ(IRQn_Type IRQn)` | дозволити лінію (біт у `ISER`) | — |
| `void NVIC_DisableIRQ(IRQn_Type IRQn)` | заборонити лінію (біт у `ICER`) | — |
| `uint32_t NVIC_GetEnableIRQ(IRQn_Type IRQn)` | чи дозволена лінія | 0 або 1 |
| `void NVIC_SetPendingIRQ(IRQn_Type IRQn)` | звести запит програмно, без апаратної події | — |
| `void NVIC_ClearPendingIRQ(IRQn_Type IRQn)` | зняти запит, що чекає | — |
| `uint32_t NVIC_GetPendingIRQ(IRQn_Type IRQn)` | чи є запит, що чекає | 0 або 1 |
| `uint32_t NVIC_GetActive(IRQn_Type IRQn)` | чи обробник зараз виконується | 0 або 1; не на M0/M0+ |
| `void NVIC_SetPriority(IRQn_Type IRQn, uint32_t priority)` | пріоритет: менше число — вищий пріоритет | — |
| `uint32_t NVIC_GetPriority(IRQn_Type IRQn)` | пріоритет, уже зсунутий назад до логічного рівня | рівень 0…15 при `__NVIC_PRIO_BITS` = 4 |
| `void NVIC_SetPriorityGrouping(uint32_t PriorityGroup)` | ділить біти пріоритету на витіснення й підрівень (`AIRCR[10:8]`) | не на M0/M0+ |
| `uint32_t NVIC_GetPriorityGrouping(void)` | поточний поділ | 0…7; не на M0/M0+ |
| `uint32_t NVIC_EncodePriority(uint32_t group, uint32_t preempt, uint32_t sub)` | зібрати два числа в одне для `NVIC_SetPriority` | готовий логічний пріоритет; не на M0/M0+ |
| `void NVIC_DecodePriority(uint32_t prio, uint32_t group, uint32_t *pPreempt, uint32_t *pSub)` | розібрати назад | через покажчики; не на M0/M0+ |
| `void NVIC_SetVector(IRQn_Type IRQn, uint32_t vector)` | підмінити адресу обробника в таблиці векторів | не на M0 |
| `uint32_t NVIC_GetVector(IRQn_Type IRQn)` | адреса поточного обробника | адреса; не на M0 |
| `void NVIC_SystemReset(void)` | перезавантажити чип через `SYSRESETREQ` | не повертається (`__NO_RETURN`) |

Чого в цьому API немає — так це кодів помилок, і про це варто знати заздалегідь:

- **Від'ємний `IRQn` мовчки ігнорується.** `NVIC_EnableIRQ(SysTick_IRQn)` не зробить нічого й не поскаржиться: системними винятками NVIC не керує, вони вмикаються інакше. Виняток — `NVIC_SetPriority`/`NVIC_GetPriority`: вони від'ємний номер приймають і пишуть у `SCB->SHPR`.
- **Номер понад межу не перевіряється.** Індекс просто вийде за масив `ISER`/`IPR` і зачепить сусідній регістр ядра.
- **`NVIC_SetVector` пише в таблицю, на яку вказує `SCB->VTOR`.** Якщо VTOR досі показує на флеш — запис не пройде. Спершу треба перенести [таблицю векторів](book:programming/vector-table) у RAM і переставити VTOR.
- **`NVIC_SystemReset` не повертається**: усередині — `__DSB()`, запис `SYSRESETREQ` і вічний цикл до фактичного скидання.
- **Імена — макроси-переспрямування.** Реалізації звуться `__NVIC_EnableIRQ` і так далі, а `NVIC_EnableIRQ` — `#define` на них. Це шов для підміни: означивши `CMSIS_NVIC_VIRTUAL` (для векторів — `CMSIS_VECTAB_VIRTUAL`), ти підставляєш власний заголовок, і всі виклики підуть через нього. Так роблять RTOS і TrustZone-прошивки, яким треба перехопити керування перериваннями.
- **`NVIC_USER_IRQ_OFFSET` = 16** — на стільки зсунуто номери ліній відносно позицій у таблиці векторів: перші 16 позицій зайняли системні винятки.

## Пріоритет: що саме потрапляє в регістр

Поле пріоритету в залізі — байт, але виробник реалізує лише кілька його **старших** бітів. Скільки саме — каже макрос `__NVIC_PRIO_BITS` із заголовка пристрою: STM32F4 — 4 (рівні 0…15), nRF52 — 3 (0…7), Cortex-M0/M0+ на кшталт RP2040 — рівно 2 (0…3), більшого архітектура Armv6-M не передбачає взагалі. Молодші біти не реалізовано: що в них не запиши, залізо їх не бачить.

![Байт пріоритету при чотирьох реалізованих бітах: NVIC_SetPriority сама зсуває трійку в старші біти й дає 0x30, а __set_BASEPRI без зсуву кладе трійку в нереалізовані біти й вимикає маскування](/book/programming/embedded-systems/cmsis/img/priority-byte.svg)
*`NVIC_SetPriority` бере логічний рівень і зсуває його сама. `__set_BASEPRI` бере готове значення регістра — тому та сама трійка в цих двох функціях означає геть різне.*

**Куди йде `NVIC_SetPriority(TIM2_IRQn, 3)` на STM32F4:**

```
__NVIC_PRIO_BITS = 4                     (рівні 0…15)
зсув             = 8 − 4 = 4
байт у регістрі  = 3 << 4 = 0x30
регістр          = NVIC->IPR[28]         (TIM2_IRQn = 28)
адреса           = 0xE000_E100 + 0x300 + 28 = 0xE000_E41C
```

**Куди йде від'ємний номер — `NVIC_SetPriority(SysTick_IRQn, 15)`:**

```
SysTick_IRQn = −1
індекс   = (IRQn & 0xF) − 4 = 15 − 4 = 11
регістр  = SCB->SHPR[11]
адреса   = 0xE000_ED00 + 0x18 + 11 = 0xE000_ED23
байт     = 15 << 4 = 0xF0                (найнижчий пріоритет)
```

Поділ на витіснення й підрівень — окрема механіка ([модель пріоритетів](book:programming/interrupt-priorities): витіснення вирішує, хто кого може перебити, підрівень — лише порядок обслуговування рівних). `NVIC_SetPriorityGrouping` ріже байт, `NVIC_EncodePriority` збирає з двох чисел одне:

```
__NVIC_PRIO_BITS = 4,  PriorityGroup = 5
бітів витіснення = min(7 − 5, 4) = 2      → рівні 0…3
бітів підрівня   = (5 − 7) + 4 = 2        → рівні 0…3

NVIC_EncodePriority(5, 2, 1) = (2 << 2) | 1 = 0b1001 = 9
NVIC_SetPriority(TIM2_IRQn, 9) → 9 << 4 = 0x90
```

> 🔧 **Навіщо це.** Зсув — не дрібниця стилю, а місце, де мовчки розходяться дві сусідні функції з тієї самої довідки. `NVIC_SetPriority(irq, 3)` зробить те, що ти думаєш. `__set_BASEPRI(3)` покладе трійку в нереалізовані біти, залізо прочитає нуль — і поріг маскування виявиться вимкненим саме тоді, коли ти думаєш, що затулив критичну ділянку. Тому в BASEPRI пишуть тільки зсунуте: `__set_BASEPRI(3 << (8 − __NVIC_PRIO_BITS))`. Це один із найчастіших способів отримати прошивку, яка «іноді» ламається.

## SysTick_Config: єдина функція з кодом помилки

```c
uint32_t SysTick_Config(uint32_t ticks);
```

Це чи не єдине місце в усій довідці, де функція взагалі повідомляє про невдачу. Вона повертає **0 — таймер заведено, 1 — відмова**, і робить чотири речі поспіль: кладе `ticks − 1` у `LOAD`, ставить SysTick найнижчий пріоритет `(1 << __NVIC_PRIO_BITS) − 1`, обнуляє `VAL` і зводить у `CTRL` біти джерела такту, дозволу переривання й пуску.

Відмова буває рівно одна: лічильник 24-бітний, і більший період у нього не влазить.

```
SysTick_LOAD_RELOAD_Msk = 0x00FF_FFFF = 16 777 215
відмова, якщо ticks − 1 > 16 777 215   →   ticks > 16 777 216

при SystemCoreClock = 168 МГц:
максимальний період = 16 777 216 / 168 000 000 ≈ 0.0999 с ≈ 99.9 мс

SysTick_Config(168000000 / 1000) = SysTick_Config(168000)  →  0   (тік 1 мс)
SysTick_Config(168000000)                                  →  1   (1 с не влазить)
```

Якщо виробник означив `__Vendor_SysTickConfig = 1`, стандартна реалізація вимикається, і `SysTick_Config` мусить дати заголовок пристрою — так роблять чипи, де SysTick тактується не так, як припускає ARM.

## Структури ядра: поля й зміщення

Поля описано кваліфікаторами доступу: `__IM` — тільки читання (`volatile const`), `__OM` — тільки запис, `__IOM` — читання й запис. Старіші форми `__I`, `__O`, `__IO` лишилися для полів периферії у заголовках виробників. Усе це — `volatile`, і не випадково: без нього компілятор має право викинути «зайве» звернення до регістра ([volatile і компілятор](book:programming/volatile-register)).

**`SysTick_Type`** — чотири слова від `0xE000_E010`:

| Поле | Зміщення | Що це |
|---|---|---|
| `CTRL` | `0x00` | пуск, дозвіл переривання, вибір джерела такту, прапорець `COUNTFLAG` |
| `LOAD` | `0x04` | значення перезавантаження, 24 біти |
| `VAL` | `0x08` | поточний лічильник; будь-який запис обнуляє його |
| `CALIB` | `0x0C` | підказка про такт, тільки читання |

**`NVIC_Type`** — масиви по 8 слів, по біту на лінію:

| Поле | Зміщення | Що це |
|---|---|---|
| `ISER[8]` | `0x000` | дозволити лінію (запис 1) |
| `ICER[8]` | `0x080` | заборонити лінію |
| `ISPR[8]` | `0x100` | звести запит |
| `ICPR[8]` | `0x180` | зняти запит |
| `IABR[8]` | `0x200` | які обробники активні, тільки читання |
| `IPR[240]` | `0x300` | по байту пріоритету на лінію |
| `STIR` | `0xE00` | програмний запуск переривання за номером, тільки запис |

**`SCB_Type`** — найважливіші поля від `0xE000_ED00`:

| Поле | Зміщення | Що це |
|---|---|---|
| `CPUID` | `0x00` | хто це ядро: розробник, частина, ревізія |
| `ICSR` | `0x04` | керування PendSV і NMI, номер активного винятку |
| `VTOR` | `0x08` | база таблиці векторів |
| `AIRCR` | `0x0C` | поділ пріоритетів і `SYSRESETREQ`; запис лише з ключем `0x5FA` у старших бітах |
| `SCR` | `0x10` | поведінка сну: `SLEEPONEXIT`, `SLEEPDEEP` |
| `CCR` | `0x14` | пастки на невирівняний доступ і ділення на нуль |
| `SHPR[12]` | `0x18` | пріоритети системних винятків |
| `SHCSR` | `0x24` | дозвіл окремих обробників відмов |
| `CFSR` / `HFSR` | `0x28` / `0x2C` | причина відмови — з цього починається [розбір HardFault](book:programming/hardfault) |
| `MMFAR` / `BFAR` | `0x34` / `0x38` | адреса, на якій стався збій |
| `CPACR` | `0x88` | доступ до співпроцесорів; саме тут вмикають FPU |

Біти всередині регістрів мають імена за єдиним зразком `<БЛОК>_<РЕГІСТР>_<ПОЛЕ>_Pos` (номер молодшого біта) і `_Msk` (маска), наприклад `SysTick_CTRL_TICKINT_Pos` = 1 і `SysTick_CTRL_TICKINT_Msk` = `1 << 1`. Магічних чисел у прикладному коді бути не мусить.

Одна річ ламається при переході з CMSIS 5 на CMSIS 6: поля перейменували — `NVIC->IP` стало `NVIC->IPR`, `SCB->SHP` стало `SCB->SHPR`, і сумісних синонімів не лишили. Код, що звертався до полів напряму замість функцій, доведеться правити; код на `NVIC_SetPriority()` не помітить нічого.

**Де бар'єр обов'язковий.** Після зміни налаштувань, які впливають на вибірку команд або на карту пам'яті, потрібно доробити доступи й скинути конвеєр — інакше наступні команди виконаються ще за старим станом. Так, `ARM_MPU_Enable()` у самому CMSIS обрамлено `__DMB()` перед записом і `__DSB(); __ISB();` після. Те саме правило стосується ввімкнення FPU через `SCB->CPACR` і перестановки `SCB->VTOR`.

## Що зобов'язаний дати виробник

Заголовок пристрою — не вільна творчість: CMSIS перелічує, що в ньому мусить бути й під якими іменами.

**`IRQn_Type`.** Від'ємні номери — системні винятки, фіксовані архітектурою; від нуля починаються лінії конкретного чипа.

| Значення | Ім'я | Що це |
|---|---|---|
| −14 | `NonMaskableInt_IRQn` | немаскований виняток |
| −13 | `HardFault_IRQn` | відмова, яку нікому обробляти |
| −12 | `MemoryManagement_IRQn` | порушення правил MPU |
| −11 | `BusFault_IRQn` | помилка шини |
| −10 | `UsageFault_IRQn` | недозволена команда чи стан |
| −5 | `SVCall_IRQn` | системний виклик `SVC` |
| −4 | `DebugMonitor_IRQn` | монітор налагодження |
| −2 | `PendSV_IRQn` | відкладений системний виклик; на ньому стоїть перемикання задач |
| −1 | `SysTick_IRQn` | системний таймер |
| 0, 1, 2, … | у STM32F4: `WWDG_IRQn` = 0, `PVD_IRQn` = 1, … `TIM2_IRQn` = 28 | лінії периферії цього чипа |

**Конфіг-макроси** — їх треба означити **до** `#include "core_cmX.h"`, бо саме вони вмикають потрібні шматки заголовка:

| Макрос | Що каже |
|---|---|
| `__CM4_REV` (чи `__CM3_REV`, `__CM7_REV`…) | ревізія ядра: `[15:8]` — версія, `[7:0]` — патч |
| `__NVIC_PRIO_BITS` | скільки бітів пріоритету реалізовано |
| `__Vendor_SysTickConfig` | 0 — брати стандартний `SysTick_Config`, 1 — свій |
| `__MPU_PRESENT` | чи є блок захисту пам'яті |
| `__FPU_PRESENT`, `__FPU_DP` | чи є дробовий блок і чи він подвійної точності |
| `__VTOR_PRESENT` | чи можна переставляти таблицю векторів |
| `__DSP_PRESENT` | чи є команди DSP |

**Системний контракт** — три імені, на які спираються стартовий код і будь-яка RTOS:

| Ім'я | Підпис | Коли |
|---|---|---|
| `SystemInit` | `void SystemInit(void)` | викликає `Reset_Handler` ще до `main` ([boot-послідовність](book:programming/mcu-startup-sequence)) |
| `SystemCoreClock` | `uint32_t SystemCoreClock` | поточна частота ядра в герцах |
| `SystemCoreClockUpdate` | `void SystemCoreClockUpdate(void)` | перерахувати `SystemCoreClock` після зміни тактування |

## Мінімальний робочий виклик

Прошивка, яка не чіпає жодного регістра периферії й тому збереться під будь-який Cortex-M із відповідним заголовком пристрою: тік раз на мілісекунду, неподільне читання 64-бітного лічильника, дозвіл лінії переривання, програмний запит на неї та сон між подіями.

```c
#include "stm32f4xx.h"          /* тягне core_cm4.h і cmsis_compiler.h */

static volatile uint64_t ticks_ms;      /* 64 біти — читається двома командами */
static volatile uint32_t pinged;

void SysTick_Handler(void)              /* ім'я з таблиці векторів пристрою */
{
    ticks_ms++;                         /* єдиний, хто пише */
}

void TIM2_IRQHandler(void)              /* запит знімає саме входження у виняток */
{
    pinged++;
}

static uint64_t uptime_ms(void)
{
    uint32_t primask = __get_PRIMASK(); /* як було до нас */
    __disable_irq();
    uint64_t t = ticks_ms;              /* два читання поспіль — без розриву */
    __set_PRIMASK(primask);             /* відновити, а не ввімкнути наосліп */
    return t;
}

int main(void)
{
    SystemCoreClockUpdate();            /* після налаштування тактування */

    if (SysTick_Config(SystemCoreClock / 1000U) != 0U) {
        for (;;) { __BKPT(0); }         /* дільник не вліз у 24 біти */
    }

    NVIC_SetPriority(TIM2_IRQn, 3U);    /* логічний рівень; зсув — усередині */
    NVIC_EnableIRQ(TIM2_IRQn);
    NVIC_SetPendingIRQ(TIM2_IRQn);      /* сам таймер не заведено — будимо лінію програмно */

    for (;;) {
        if (uptime_ms() >= 60000U) {
            NVIC_SystemReset();         /* не повертається */
        }
        __WFI();                        /* спати до наступного переривання */
    }
}
```

Імен виробника тут рівно три: заголовок `stm32f4xx.h` і пара `TIM2_IRQn` / `TIM2_IRQHandler`. Заміни їх — і той самий файл збереться під nRF52 чи RP2040 із будь-яким із чотирьох тулчейнів. Це і є та частина, заради якої контракт узагалі писали.
