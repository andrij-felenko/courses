# ⚙️ Кооперативний super-loop: від трьох if до таблиці задач

**Задача.** Один `loop()` мусить вести кілька незалежних справ із різними ритмами — блимати світлодіодом раз на секунду, опитувати давач п'ять разів на секунду, слати «серцебиття» раз на п'ять секунд — і при цьому **жодного разу не зупинятися** на `delay()`. Коли справ три, рятує проста жменя перевірок `millis()`. Та щойно їх стає десяток, той самий підхід розповзається в плутанину однакових `if`, де легко проґавити рядок або переплутати інтервал. Тут і народжується думка: а що, як описати справи **даними**, а не кодом?

## Ідея: винести «що і як часто» в таблицю

Придивімося до трьох наївних перевірок. Кожна — це насправді одне й те саме твердження, лише з іншими числами та іншою дією:

:::tabs
```cpp
if (now - tLed  >= 1000) { tLed  = now; toggleLed();    }
if (now - tSens >=  200) { tSens = now; readSensor();    }
if (now - tBeat >= 5000) { tBeat = now; sendHeartbeat(); }
```
```python
if now - t_led  >= 1000: t_led  = now; toggle_led()
if now - t_sens >=  200: t_sens = now; read_sensor()
if now - t_beat >= 5000: t_beat = now; send_heartbeat()
```
```js
if (now - tLed  >= 1000) { tLed  = now; toggleLed();    }
if (now - tSens >=  200) { tSens = now; readSensor();    }
if (now - tBeat >= 5000) { tBeat = now; sendHeartbeat(); }
```
```micropython
if now - t_led  >= 1000: t_led  = now; toggle_led()
if now - t_sens >=  200: t_sens = now; read_sensor()
if now - t_beat >= 5000: t_beat = now; send_heartbeat()
```
:::

У кожному рядку повторюється однакова форма «*минув мій інтервал → запам'ятати час → зробити справу*». А коли код повторює одну форму з різними значеннями — це майже завжди натяк, що значення треба зібрати в **таблицю**, а форму лишити **одну**. Винесімо в дані те, що відрізняє справи (період і дія), і напишімо логіку перевірки рівно раз.

Опис однієї справи — це структура з трьох полів: як часто (`period`), коли востаннє спрацювала (`last`) і що робити (`fn` — покажчик на функцію). Масив таких структур і є наш розклад.

:::tabs
```cpp
typedef void (*Job)(void);          // дія — функція без аргументів

typedef struct {
    unsigned long period;           // інтервал, мс
    unsigned long last;             // коли востаннє спрацювала, мс
    Job           fn;               // що виконати
} Task;

Task tasks[] = {
    { 1000, 0, toggleLed    },      // блимати щосекунди
    {  200, 0, readSensor    },     // читати 5 разів/с
    { 5000, 0, sendHeartbeat },     // серцебиття раз на 5 с
};
const int N = sizeof(tasks) / sizeof(tasks[0]);
```
```python
# опис справи: [період (мс), коли востаннє (мс), дія]
tasks = [
    [1000, 0, toggle_led],          # блимати щосекунди
    [ 200, 0, read_sensor],         # читати 5 разів/с
    [5000, 0, send_heartbeat],      # серцебиття раз на 5 с
]
N = len(tasks)
```
```js
// опис справи: { period (мс), last (мс), fn (дія) }
const tasks = [
    { period: 1000, last: 0, fn: toggleLed     },   // блимати щосекунди
    { period:  200, last: 0, fn: readSensor     },  // читати 5 разів/с
    { period: 5000, last: 0, fn: sendHeartbeat  },  // серцебиття раз на 5 с
];
const N = tasks.length;
```
```micropython
# опис справи: [період (мс), коли востаннє (мс), дія]
tasks = [
    [1000, 0, toggle_led],          # блимати щосекунди
    [ 200, 0, read_sensor],         # читати 5 разів/с
    [5000, 0, send_heartbeat],      # серцебиття раз на 5 с
]
N = len(tasks)
```
:::

Тепер `loop()` не знає, **які** саме справи він тягне, — він лише перебирає таблицю й запускає ті, чий час настав:

:::tabs
```cpp
void loop() {
    unsigned long now = millis();
    for (int i = 0; i < N; i++) {
        if (now - tasks[i].last >= tasks[i].period) {
            tasks[i].last += tasks[i].period;   // не = now! (про це нижче)
            tasks[i].fn();
        }
    }
}
```
```python
def loop():
    now = millis()
    for t in tasks:                     # t = [period, last, fn]
        if now - t[1] >= t[0]:
            t[1] += t[0]                 # не = now! (про це нижче)
            t[2]()
```
```js
function loop() {
    const now = millis();
    for (const t of tasks) {
        if (now - t.last >= t.period) {
            t.last += t.period;         // не = now! (про це нижче)
            t.fn();
        }
    }
}
```
```micropython
import time

def loop():
    now = time.ticks_ms()
    for t in tasks:                     # t = [period, last, fn]
        if time.ticks_diff(now, t[1]) >= t[0]:
            t[1] = time.ticks_add(t[1], t[0])   # не = now! (про це нижче)
            t[2]()
```
:::

Один прохід `for` замінив десяток окремих `if`. Додати справу тепер означає **дописати рядок** у таблицю, а не правити логіку циклу. Це і є найпростіший **кооперативний планувальник** (англ. *cooperative scheduler* — «той, що покладається на добру волю»): кожна справа працює, доки сама не завершиться й не поверне керування циклу. Ніхто нікого не перебиває — усе тримається на тому, що кожна дія коротка й чемно віддає чергу далі.

> 🔧 **Навіщо це.** Така таблиця — золота середина між хаосом окремих `if` і повноцінним [RTOS](book:programming/freertos). Поки справ небагато й вони короткі, кооперативний super-loop на `millis()` дає **передбачуваний, легкий для читання** код без жодного байта на стеки задач чи перемикання контексту. Саме тому він живе у безлічі реальних виробів — від побутових дрібниць до промислових контролерів.

## Пастка перша: `last = now` проти `last += period` (дрейф)

У наївному варіанті ми писали `tLed = now`. Здавалося б, дрібниця — але вона потроху **накопичує похибку**. Між тим, як інтервал справді минув, і тим, як цикл до нього дійшов і виконав, завжди є невелика затримка: інші справи теж щось робили. Якщо щоразу класти `last = now`, ця затримка **додається** до кожного періоду, і справа поволі «сповзає» — блимання, замислене щосекунди, насправді йде раз на 1.01 с, потім 1.02 с, і так далі.

```c
// ДРЕЙФ:  last = now           період «росте» на час запізнення
// РІВНО:  last += period       наступний строк рахуємо від попереднього, а не від «зараз»
```

Тому `last += period` краще: наступний строк відмірюється від **попереднього запланованого**, а не від моменту фактичного запуску, — і дрібні запізнення не накопичуються. Середній період лишається точно таким, як задумано. Різниця здається мізерною — частки мілісекунди на оберт, — але вона **систематична**, а не випадкова: похибка завжди одного знаку й тому росте монотонно. За годину безперервної роботи блимання з `last = now` може зсунутися на цілі секунди, тоді як `last += period` тримає його прив'язаним до абсолютної сітки часу від самого старту. Скрізь, де ритм має лишатися рівним надовго — запис у журнал із позначкою часу, музичний темп, опитування давача для подальшого аналізу, — варто рахувати саме від попереднього строку.

Та в цього прийому є власна гостра грань. Якщо справа **проґавила** цілий період (бо інша надовго захопила цикл), то `last += period` за один прохід надолужить лише **один** крок — і наступного оберту `now - last` усе ще буде більшим за період, тож справа спрацює знову, і знову, **навздогін**, поки не нажене графік. Інколи це бажано (не загубити жодного такту), а інколи шкідливо (раптовий «залп» дій). Якщо залпи небажані — після великого відставання розклад **скидають** до теперішнього:

:::tabs
```cpp
if (now - tasks[i].last >= tasks[i].period) {
    tasks[i].last += tasks[i].period;
    if (now - tasks[i].last >= tasks[i].period)   // відстали більш ніж на період?
        tasks[i].last = now;                      // не доганяємо залпом — починаємо з чистого
    tasks[i].fn();
}
```
```python
if now - t[1] >= t[0]:
    t[1] += t[0]
    if now - t[1] >= t[0]:              # відстали більш ніж на період?
        t[1] = now                      # не доганяємо залпом — починаємо з чистого
    t[2]()
```
```js
if (now - t.last >= t.period) {
    t.last += t.period;
    if (now - t.last >= t.period)       // відстали більш ніж на період?
        t.last = now;                   // не доганяємо залпом — починаємо з чистого
    t.fn();
}
```
```micropython
if time.ticks_diff(now, t[1]) >= t[0]:
    t[1] = time.ticks_add(t[1], t[0])
    if time.ticks_diff(now, t[1]) >= t[0]:   # відстали більш ніж на період?
        t[1] = now                           # не доганяємо залпом — починаємо з чистого
    t[2]()
```
:::

Вибір між «надолужити» і «скинути» — це інженерне рішення під конкретну справу, а не дрібниця синтаксису: для лічби імпульсів дорогий кожен такт, а для блимання індикатором залп лише зіпсує вигляд.

## Пастка друга: один довгий крок морозить усіх

Уся модель тримається на чесній угоді: **кожна дія коротка**. Кооперативний цикл нікого не **витісняє** — він лише чемно чекає, доки поточна дія сама завершиться. Тому одна «жадібна» функція рве таймінг **усім**: поки тягнеться вона, дозрілі справи стоять у черзі й чекають.

:::tabs
```cpp
void readSensor() {
    int v = analogRead(PIN);
    delay(50);              // ← ОТРУТА: 50 мс цикл стоїть, LED не блимне, байт загубиться
    publish(v);
}
```
```python
def read_sensor():
    v = analog_read(PIN)
    time.sleep(0.05)        # ← ОТРУТА: 50 мс цикл стоїть, LED не блимне, байт загубиться
    publish(v)
```
```js
function readSensor() {
    const v = analogRead(PIN);
    sleep(50);              // ← ОТРУТА: 50 мс цикл стоїть, LED не блимне, байт загубиться
    publish(v);
}
```
```micropython
def read_sensor():
    v = adc.read()
    time.sleep_ms(50)       # ← ОТРУТА: 50 мс цикл стоїть, LED не блимне, байт загубиться
    publish(v)
```
:::

Той `delay(50)` коштує не лише запізнілого давача — він **заморожує весь цикл** на 50 мс. Якщо ту саму паузу теж переписати на неблокувальний лад (запам'ятати час початку перетворення й забрати результат пізніше, наступними обертами), цикл лишиться чуйним. Загальне правило кооперативної моделі просте: **жодна дія не має права блокувати**; усе, що довше за кілька мікросекунд, розбивають на кроки через ту саму таблицю або через [машину станів](guide:embedded/super-loop-limits).

Окрема, особливо підступна грань довгого кроку — [**сторожовий таймер**](book:programming/watchdog) (*watchdog*). Якщо одна справа законно працює довго (наприклад, форматує флеш чи рахує криптографію), `loop()` може не завершитися вчасно, і watchdog вирішить, що програма зависла, та **перезавантажить** чип. Тоді таку справу або ділять на кроки, або **годують** watchdog усередині неї:

:::tabs
```cpp
for (int block = 0; block < total; block++) {
    erase_flash_block(block);
    esp_task_wdt_reset();    // «я живий, не перезавантажуй» — у межах довгої, але законної роботи
}
```
```micropython
for block in range(total):
    erase_flash_block(block)
    wdt.feed()               # «я живий, не перезавантажуй» — у межах довгої, але законної роботи
```
:::

## Пастка третя: дані, які цикл ділить з ISR

Кооперативний цикл рідко живе сам — поряд з ним працюють [обробники переривань (ISR)](book:programming/isr), що ловлять термінове: натискання кнопки, прихід байта, імпульс від давача. Щойно ISR і цикл **ділять** змінну, виникає [гонка](book:programming/atomicity-races): ISR може змінити дані якраз тоді, коли цикл читає їх посеред оновлення.

Двох заходів вистачає майже завжди. По-перше, спільну змінну позначають [`volatile`](book:programming/volatile) — інакше компілятор, не знаючи про ISR, може закешувати її в регістрі, і цикл **ніколи не побачить** змін. По-друге, багатобайтове значення цикл читає [атомарно](book:programming/atomicity-races) — на коротку мить заборонивши переривання, — щоб не впіймати напівоновлене число (старші байти нові, молодші ще старі).

:::tabs
```cpp
volatile unsigned long pulses = 0;     // лічить ISR, читає loop()

void IRAM_ATTR onPulse() { pulses++; }  // ISR: коротко — лише інкремент

void loop() {
    noInterrupts();
    unsigned long p = pulses;           // знімок цілого 32-бітного значення
    interrupts();
    // далі працюємо з копією p, а не з живою pulses
}
```
```micropython
pulses = 0                              # лічить ISR, читає loop()

def on_pulse(pin):                      # ISR: коротко — лише інкремент
    global pulses
    pulses += 1

def loop():
    state = machine.disable_irq()
    p = pulses                          # знімок цілого значення
    machine.enable_irq(state)
    # далі працюємо з копією p, а не з живою pulses
```
:::

ISR має лишатися **блискавичною**: схопила подію, лишила прапорець чи число — і назад. Уся неквапна обробка того прапорця — уже в кооперативному циклі, як ще одна справа в таблиці. Такий поділ праці зручний ще й тим, що цикл сам вирішує, **коли** взятися за накопичене: ISR може за секунду нарахувати тисячу імпульсів, а справа в таблиці спокійно зведе їх докупи раз на свій період, не захлинаючись. Важлива лише дисципліна знімка: спершу під коротку заборону переривань копіюємо живу змінну в локальну, а тоді працюємо **з копією**, щоб число не змінилося в нас під руками посеред обчислення.

## Що винести з цього

Кооперативний super-loop — це не «код для початківців», а свідомий інженерний вибір з ясними межами. Таблиця задач замість розсипу `if` робить його **охайним і розширюваним**; `last += period` тримає **рівний ритм**; заборона блокувати тримає його **чуйним**; `volatile` плюс атомарне читання роблять **безпечним** стик з перериваннями. Доки справ небагато й вони короткі, цього вистачає надовго. А коли справи починають **залежати одна від одної** чи **чекати** — на зв'язок, на людину, на давач, — і таблиця вже не дає ради, настає час [справжніх задач і витісняючого планувальника](guide:embedded/super-loop-limits).
