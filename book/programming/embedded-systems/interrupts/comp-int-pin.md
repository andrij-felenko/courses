# 🔌 Ніжка INT у периферії: давач сам каже «є дані»

## Що це за деталь

Більшість сучасних цифрових давачів спілкуються з МК по шині (I²C чи SPI). Та багато з них мають ще й окрему ніжку **INT** (*interrupt*, переривання), якою давач **сам** сигналить про подію. Найяскравіші приклади — акселерометр **LIS3DH-класу** та [IMU **MPU6050-класу**](book:electronics/imu): вони майже завжди несуть одну-дві ніжки INT під «дані готові», «помічено рух», «постукування», «буфер FIFO повний». Мають INT і чимало інших — годинники реального часу, АЦП, частина барометрів. (А ось повільні давачі середовища, як-от BME280-класу, INT часто й не мають — їх простіше опитувати; це наочна межа, де переривання не конче потрібне.)

![Опитування проти INT: давач сам гукає, коли є подія](/book/programming/embedded-systems/interrupts/img/int-idea.svg)
*Без INT МК раз у раз питає давача по шині «є дані?» — і марнує час та трафік. З INT давач мовчить, доки не станеться подія, а тоді смикає ніжку — і МК реагує саме тоді, коли треба. Мовчун, якого смикали, стає тим, хто гукає сам.*

Це переломлює саму логіку роботи: замість того щоб [невпинно опитувати](guide:embedded/polling-vs-interrupts) давача, МК дає йому **мовчати, доки не станеться подія**, а тоді той сам підіймає INT — і процесор реагує точно вчасно.

## Розпіновка й підключення

Назовні — лінії шини плюс одна-дві ніжки переривання:

```
VCC, GND    — живлення
SDA, SCL    — шина I²C (або SPI)
INT (INT1)  — вихід переривання: «сталася подія»
INT2        — друга ніжка переривання (під інші події, у деяких давачах)
```

![Підключення INT давача: INT на ніжку-переривання, дані — по шині](/book/programming/embedded-systems/interrupts/img/wiring.svg)
*Лінії шини — як звичайно; ніжку INT ведуть на ту ніжку МК, що налаштована входом-перериванням. Часто INT — відкритий стік, тож потрібна підтяжка. Подію й полярність задають у регістрах давача, а самі дані забирають по шині у відповідь на INT.*

Підключення: лінії шини — як звичайно, а **INT** ведуть на ту ніжку МК, що налаштована **входом-перериванням** (саме та «ніжка з дзвоником», яка перериває роботу процесора). Часто INT — **відкритий стік** ([open-drain](book:electronics/open-drain)), тож йому потрібна **підтяжка** (щоб лінія не [плавала між рівнями](book:electronics/floating-pullups)); типова полярність — активний LOW (подія тягне INT у нуль).

## Перший байт

Робота у три кроки. **Перше:** через регістри давача налаштувати, **яка** подія підіймає INT (готовність даних, поріг, рух) і з якою **полярністю**. **Друге:** повісити [обробник переривання](book:programming/interrupts) на ніжку МК (`attachInterrupt`). **Третє:** коли INT спрацював — у відповідь **прочитати** дані з давача по шині. Класична зв'язка: INT каже «час!», а самі числа МК забирає вже по I²C.

## Типові граблі

- **Полярність і тип.** Переплутали активний рівень (LOW/HIGH) чи фронт — обробник або не спрацює, або сипатиме без кінця. Звіряйте з налаштуванням у давачі.
- **Open-drain без підтяжки.** Якщо INT відкритий стік, без підтяжки лінія [**плаває**](book:electronics/floating-pullups) — переривань не буде або сипатимуться випадкові.
- **«Засвічений» (latched) INT.** Багато давачів **тримають** INT активним, доки ви не **прочитаєте** відповідний регістр (чи самі дані). Не прочитали — INT не відпускає, і нового переривання не буде. Звичка: у відповідь на переривання **скинути** INT читанням.
- **Яка саме ніжка.** У давачів із INT1/INT2 подію треба спрямувати на ту ніжку, яку ви під'єднали.

## Варіації класу

Подія буває різна: **data-ready** (нова порція вимірів), **поріг** (значення вийшло за межу), **рух / постукування** (акселерометри LIS/MPU це вміють), **FIFO** (буфер набрався). Ніжок переривання буває одна чи дві (INT1/INT2), а сам вихід часто **налаштовуваний** — push-pull чи open-drain, активний LOW чи HIGH. Хоч би яка варіація — суть одна: давач перестає бути німим і **сам кличе** процесор, коли є про що казати.
