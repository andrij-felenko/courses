# ⚙️ Матриця кнопок 4×4: сканування рядків, привиди, діоди

> Алгоритмічна вставка про багатокнопковий «модуль»: клавіатура читається малою кількістю ніжок — як прочитати багато клавіш, не витративши вивід на кожну.

## Задача

Шістнадцять кнопок (клавіатура 4×4) «в лоб» — це 16 ніжок, по одній на клавішу. Розкішно й марнотратно: на дрібному МК ніжки на вагу золота. Як прочитати 16 клавіш, не витративши 16 виводів?

## Ідея

Розкладімо кнопки **сіткою** з рядків і стовпців. Кожна клавіша сидить на перетині одного **рядка** й одного **стовпця** і з'єднує їх, коли натиснута. Тоді R рядків і C стовпців дають **R×C** клавіш, а ніжок треба лише **R+C**. Для 4×4: 4 + 4 = **8 ніжок** замість 16.

![Матриця 4×4: 8 ніжок читають 16 клавіш скануванням](/book/programming/embedded-systems/module-model/img/matrix-grid.svg)
*Клавіші сидять на перетинах рядків і стовпців. Скануючи, активуємо один рядок (R1) і читаємо стовпці; натиснута клавіша (R1,C2) з'єднує рядок зі своїм стовпцем, і той озивається. R+C ніжок дають R×C клавіш: 8 → 16.*

Читають матрицю **скануванням**: по черзі «активуємо» один рядок і **читаємо всі стовпці**. Якщо в активному рядку якусь клавішу натиснуто, вона **простягне** активний рядок до свого стовпця — і той стовпець озветься. Пробігли всі рядки — знаємо стан усіх 16 клавіш. Зазвичай стовпці тримають на [**підтяжках**](book:electronics/floating-pullups), а активний рядок **притягують до землі**: натиснута клавіша тоді тягне свій стовпець у LOW.

## Псевдокод

```
scan():
    для кожного рядка r:
        активувати рядок r          # притягнути r до землі, решта — неактивні
        для кожного стовпця c:
            якщо стовпець c у LOW:   # клавіша (r,c) натиснута
                зафіксувати (r, c)
        деактивувати рядок r
```

Сканування роблять **швидко й часто** (десятки разів на секунду), щоб не пропустити натиск; кожну знайдену клавішу ще й [**антидребежать**](book:electronics/contact-debounce), як звичайну кнопку.

## Робочий код

Перекладімо ідею в робочий C для ESP-IDF. Рядки — виходи, стовпці — входи з підтяжкою; активувати рядок означає притягнути його до нуля, решту лишити «відпущеними» (вхід із високим імпедансом), щоб вони не заважали. Стан зчитуємо в бітову маску — по біту на клавішу:

:::tabs
```cpp
#include "driver/gpio.h"

#define ROWS 4
#define COLS 4
static const int row_pin[ROWS] = { 12, 13, 14, 27 };
static const int col_pin[COLS] = { 16, 17, 18, 19 };

void matrix_init(void) {
    for (int c = 0; c < COLS; c++) {
        gpio_set_direction(col_pin[c], GPIO_MODE_INPUT);
        gpio_set_pull_mode(col_pin[c], GPIO_PULLUP_ONLY);  /* спокій = HIGH */
    }
    for (int r = 0; r < ROWS; r++)                          /* рядки поки «відпущені» */
        gpio_set_direction(row_pin[r], GPIO_MODE_INPUT);
}

/* повертає 16 бітів: біт (r*COLS + c) = 1, якщо клавішу натиснуто */
uint16_t matrix_scan(void) {
    uint16_t keys = 0;
    for (int r = 0; r < ROWS; r++) {
        gpio_set_direction(row_pin[r], GPIO_MODE_OUTPUT);   /* активуємо рядок */
        gpio_set_level(row_pin[r], 0);                      /* притягуємо до нуля */
        esp_rom_delay_us(5);                                /* дати лінії осісти */

        for (int c = 0; c < COLS; c++)
            if (gpio_get_level(col_pin[c]) == 0)            /* стовпець упав → натиск */
                keys |= (uint16_t)(1u << (r * COLS + c));

        gpio_set_direction(row_pin[r], GPIO_MODE_INPUT);    /* «відпускаємо» рядок */
    }
    return keys;
}
```
```micropython
from machine import Pin
import time

ROWS = 4
COLS = 4
row_gpio = (12, 13, 14, 27)
col_gpio = (16, 17, 18, 19)

# стовпці — входи з підтяжкою (спокій = HIGH)
cols = [Pin(g, Pin.IN, Pin.PULL_UP) for g in col_gpio]
# рядки поки «відпущені» — просто входи
rows = [Pin(g, Pin.IN) for g in row_gpio]

def matrix_scan():
    # повертає 16 бітів: біт (r*COLS + c) = 1, якщо клавішу натиснуто
    keys = 0
    for r in range(ROWS):
        rows[r].init(Pin.OUT)          # активуємо рядок
        rows[r].value(0)               # притягуємо до нуля
        time.sleep_us(5)               # дати лінії осісти

        for c in range(COLS):
            if cols[c].value() == 0:   # стовпець упав → натиск
                keys |= 1 << (r * COLS + c)

        rows[r].init(Pin.IN)           # «відпускаємо» рядок
    return keys
```
:::

Дрібниця, на якій спотикаються: між «активувати рядок» і «читати стовпці» треба **коротка пауза** (тут `esp_rom_delay_us(5)`). Лінія зі своєю ємністю не падає в нуль миттєво; прочитаєш надто рано — побачиш стару напругу й пропустиш натиск. І ще: неактивні рядки лишаємо саме **входом** (відпущеними), а не виходом у HIGH — інакше натиснута клавіша з'єднає рядок-нуль із рядком-одиницею навпряму, і це коротке замикання через ніжки.

## Пастка: привиди (ghosting)

Поки натиснуто одну-дві клавіші — усе чесно. Але натисніть **три** клавіші, що утворюють «кут» прямокутника, — і з'явиться **фальшива четверта**, якої ніхто не торкався. Це **привид** (*ghosting*): струм «прокрадається» в обхід через три замкнені клавіші й удає натиск у четвертому, порожньому перетині. Сканування чесно бачить активний стовпець — і помиляється.

Простежмо обхідний шлях, бо саме з нього випливають ліки. Активуймо рядок R1 — він тепер у нулі. Натиснуто (R1,C1), (R2,C1) і (R2,C2). Нуль із R1 законно проходить крізь натиснуту (R1,C1) у стовпець C1 — це **справжній** натиск. Але той самий нуль із C1 піднімається крізь натиснуту (R2,C1) у рядок R2, а звідти крізь натиснуту (R2,C2) спадає в стовпець C2. Сканер дивиться на C2, бачить нуль — і впевнено доповідає про натиск (R1,C2), хоч ту клавішу ніхто не торкав. Усе через те, що **звичайна клавіша проводить струм в обидва боки**: вона не розрізняє, де «вхід», а де «вихід», тож нуль гуляє сіткою, куди є замкнений шлях. Поки замкнено менше ніж три клавіші, замкненого кільця не утворюється — обходити нема чим, і привидів немає.

![Привид без діодів і його лікування діодом у кожній клавіші](/book/programming/embedded-systems/module-model/img/matrix-ghost.svg)
*Без діодів три натиснуті клавіші в куті прямокутника породжують фальшиву четверту (привид): струм крадеться в обхід. Діод у кожній клавіші пропускає струм лише в один бік і закриває обхідний шлях — привиди зникають.*

Ліки видно одразу: розірвати обхід так, щоб струм ішов лише «згори вниз» — від рядка до стовпця — і ніколи назад. Це робить **діод** у кожній клавіші. Діод пропускає струм лише **в один бік**, тож той зворотний крок у нашому ланцюжку — підйом нуля зі стовпця C1 назад у рядок R2 — стає **неможливим**: діод на (R2,C1) дивиться «не туди». Кільце розірвано, обхідного шляху більше нема, і сканер бачить лише справжні натиски. З діодами матриця не бреше навіть при будь-якій кількості одночасних натисків (повний *N-key rollover*) — саме тому в ігрових клавіатурах діод стоїть під кожною клавішею. Ціна — той самий діод × кількість клавіш і трохи складніша розводка плати; для побутової клавіатури на 4×4, де рідко тиснуть три кнопки воднораз, діоди часто пропускають свідомо.

> 🔧 **Навіщо це.** Рішення «з діодами чи без» — це чесний компроміс, який треба зробити свідомо, а не за звичкою. Цифрова панель домофона чи меню приладу переживе й без діодів: там одночасних натисків майже не буває. А от ігровий пульт, музична клавіатура чи будь-що, де натискають акордами, без діодів даватиме привидів — і користувач списуватиме це на «глючну» прошивку, хоча причина суто в залізі. Знаючи механізм, ви ставите діоди саме там, де вони справді потрібні, і не платите за них там, де ні.

## Складність і пастки на МК

- **Без діодів — щонайбільше дві.** Надійно розрізнити можна одне-два одночасні натискання; три в куті вже дають привид. Якщо інтерфейс не передбачає акордів, цього досить; треба багато воднораз — ставте діоди й нічого не вгадуйте.
- **Антибрязкіт нікуди не дівся.** Кожна клавіша матриці — це той самий механічний контакт, що [дзвенить](book:electronics/contact-debounce) кількома хибними перемиканнями за мілісекунди. Фільтрувати треба **кожну** клавішу окремо: тримати для кожної свій лічильник стабільних зчитувань і визнавати натиск, лише коли він повторився підряд кілька сканів. Один спільний фільтр на всю матрицю не годиться — клавіші натискають незалежно.
- **Темп сканування.** Тут дві межі з різних боків. Знизу: повний прохід по всіх рядках має вкладатися в десяток мілісекунд, інакше короткий натиск проскочить між сканами. Згори: якщо ганяти сканування в щільному циклі без пауз, воно з'їсть процесор, потрібний на решту. Золота середина — сканувати за таймером, десятки разів на секунду; цього вистачає і пальцю, і антибрязкоту.
- **Напрям ніжок.** Рядки — виходи (активують), стовпці — входи з підтяжками; не переплутайте, інакше «активний» рядок нікого не притягне, і матриця мовчатиме. І пильнуйте сам спосіб активації: активний рядок тягнемо в нуль, а неактивні **відпускаємо** (робимо входом), а не виставляємо в одиницю — інакше натиснута клавіша з'єднає нуль із одиницею навпряму.
- **Коли матриця, а коли розширювач?** Матриця економить ніжки ціною діодів і логіки сканування; [розширювач портів](book:electronics/gpio-expander) — ціною окремого чипа й шини до нього, зате віддає готові незалежні лінії без сканування й привидів. Орієнтир простий: багато клавіш, складених **у сітку** (клавіатура, цифрова панель), — матриця; десяток **розкиданих** входів-виходів по всій платі — розширювач.

## Підсумок

Матриця міняє **ніжки на сканування**: R+C виводів читають R×C клавіш, якщо по черзі активувати рядки й читати стовпці. Платять за це привидами (лікуються діодами) і потребою сканувати й антидребежити. Класичний прийом, що живе в кожній цифровій клавіатурі.
