# 🧮 Математичний аналіз решіток безпеки та метрик поверхонь атак

Проєктування меж довіри часто сприймають як суто інженерну або конфігураційну задачу. Проте стійкість ізоляції, коректність передачі прав і кількісна оцінка зниження ризиків базуються на строгому математичному апараті теорії ґраток (решіток), скінченних автоматів та теорії інформації.

У цій вставці наведено математичну формалізацію моделей цілісності Біби та Кларка-Вілсона, доведення теореми невтручання (Non-Interference), виведення метрики зменшення поверхні атаки за Говардом (Attack Surface Metric) та інформаційно-теоретичну оцінку витоку даних через побічні канали на межі контурів.

## 1. Алгебраїчна структура ґратки рівнів безпеки (Security Lattice)

Формальна модель багатоконтурної безпеки описується повною ґраткою (напіврешіткою):

```
(L, ≤, ∧, ∨, ⊤, ⊥)
```

де:
- `L` — скінченна множина рівнів безпеки або міток цілісності.
- `≤` — бінарне відношення часткового порядку (домінування), яке задовольняє три аксіоми для всіх елементів `a, b, c ∈ L`:
  1. **Рефлексивність:** `a ≤ a`.
  2. **Антисиметричність:** якщо `a ≤ b` та `b ≤ a`, то `a = b`.
  3. **Транзитивність:** якщо `a ≤ b` та `b ≤ c`, то `a ≤ c`.
- `∧` (Meet / Infimum) — операція найбільшої нижньої межі (точна нижня грань двох рівнів).
- `∨` (Join / Supremum) — операція найменшої верхньої межі (точна верхня грань двох рівнів).
- `⊤` (Top / System-High) — найвищий рівень цілісності системи (апаратний корінь довіри).
- `⊥` (Bottom / System-Low) — найнижчий рівень цілісності (відкритий інтернет).

Рівень безпеки `l ∈ L` у загальному випадку визначається як пара `l = (h, C)`, де `h ∈ H` — ієрархічний рівень привілеїв (наприклад, `0 = Guest, 1 = User, 2 = Admin, 3 = Kernel`), а `C ⊆ Compartments` — дискретна множина категорій або контурів безпеки (наприклад, `{Network, Crypto, Storage}`).

Відношення домінування `(h₁, C₁) ≤ (h₂, C₂)` виконується тоді й лише тоді, коли:

```
h₁ ≤ h₂ ∧ C₁ ⊆ C₂
```

### Операції над контурами безпеки

Коли процес, що належить до контуру `l₁`, об'єднує дані з контуром `l₂`, результуючий рівень цілісності та конфіденційності обчислюється через операції ґратки:

```
i(Комбінований_Контур)
= l₁ ∧ l₂              [meet: найнижча спільна цілісність двох джерел]
= (min(h₁, h₂), C₁ ∩ C₂) [покомпонентний перетин рівнів та категорій]
```

Для конфіденційності (модель Белла-ЛаПадули) об'єднання вимагає підняття рівня секретності:

```
c(Комбінований_Контур)
= l₁ ∨ l₂              [join: об'єднання вимог до таємності]
= (max(h₁, h₂), C₁ ∪ C₂) [покомпонентне об'єднання міток доступу]
```

## 2. Формальний аналіз моделі цілісності Біби (Biba Integrity Model)

Нехай `S` — множина суб'єктів (активних сутностей: процесів, потоків), `O` — множина об'єктів (пасивних сутностей: файлів, буферів пам'яті, сокетів), а `i: S ∪ O → L` — функція відображення сутності в рівень цілісності.

Модель Біби гарантує, що жоден високоцілісний стан не може бути спотворений діями низькоцілісного суб'єкта або читанням низькоцілісних даних. Вона задається двома інваріантами переходів станів:

### Аксіома 1: Проста властивість цілісності (Simple Integrity Property / No Read Down)

Суб'єкт `s ∈ S` має право на читання об'єкта `o ∈ O` тоді й лише тоді, коли рівень цілісності об'єкта домінує над рівнем суб'єкта:

```
CanRead(s, o) ⇔ i(o) ≥ i(s)
```

**Доведення захисту від ін'єкції:** Припустимо, що суб'єкт `s` читає об'єкт `o` з рівнем `i(o) < i(s)`. Оскільки стан суб'єкта після читання стає функцією від прочитаних даних `State'(s) = f(State(s), Data(o))`, рівень цілісності суб'єкта деградує: `i(State'(s)) ≤ i(o) < i(s)`. Отже, вимога `i(o) ≥ i(s)` є необхідною і достатньою для збереження рівня довіри `i(s)`.

### Аксіома 2: Зіркова властивість цілісності (Integrity Star-Property / No Write Up)

Суб'єкт `s ∈ S` має право на модифікацію або створення об'єкта `o ∈ O` тоді й лише тоді, коли рівень цілісності суб'єкта домінує над рівнем об'єкта:

```
CanWrite(s, o) ⇔ i(s) ≥ i(o)
```

**Доведення захисту від спотворення:** Якщо суб'єкту з `i(s) < i(o)` дозволити запис в `o`, вміст об'єкта `o` стане залежним від ненадійного коду `s`, що призведе до порушення інваріанта `i(o)`. Отже, запис у контури з вищим рівнем довіри суворо заборонено без проходження через атестований шлюз трансформації.

## 3. Математична формалізація моделі Кларка-Вілсона

Модель Кларка-Вілсона формалізує роботу реальних програмних шлюзів через кортеж:

```
(CDI, UDI, TP, IVP)
```

де:
- `CDI = {c₁, c₂, ..., cₙ}` — множина захищених елементів даних (Constrained Data Items).
- `UDI = {u₁, u₂, ..., uₘ}` — множина недовірених зовнішніх даних (Unconstrained Data Items).
- `TP = {t₁, t₂, ..., tₖ}` — множина процедур трансформації (Transformation Procedures).
- `IVP = {v₁, v₂, ..., vₚ}` — множина процедур верифікації цілісності (Integrity Verification Procedures).

### Інваріанти валідності системи

Стан системи описується функцією конфігурації `σ: CDI → States`. Система перебуває у валідному стані `Valid(σ)`, якщо кожна процедура перевірки повертає істину:

```
Valid(σ) ⇔ ∀ v ∈ IVP, ∀ c ∈ CDI: v(c) = True
```

Кожна процедура трансформації `t ∈ TP` є детермінованим автоматом переходу станів, що задовольняє умову збереження інваріанта:

```
Valid(σ) ∧ (σ' = t(σ, u)) ⇒ Valid(σ')     [інваріант коректності валізатора межі]
```

Якщо для вхідного елемента `u ∈ UDI` умова валідності не може бути гарантована, процедура `t` зобов'язана здійснити перехід у стан відмови `σ' = σ_abort` без мутації `CDI`.

## 4. Кількісна оцінка поверхні атаки (Attack Surface Metric)

Поверхня атаки монолітної системи та системи з розділеними контурами довіри кількісно оцінюється за методикою Майкла Говарда (Michael Howard) та Прадіпа Манохара (Pradeep Manoharan).

Поверхня атаки `AS` системи визначається як сума зважених точок входу:

```
AS = ∑ (w_m · |M|) + ∑ (w_c · |C|) + ∑ (w_d · |D|)
```

де:
- `M` — множина відкритих методів / системних викликів (Methods).
- `C` — множина комунікаційних каналів / відкритих портів / сокетів (Channels).
- `D` — множина небезпечних структур даних / парсерів (Data items).
- `w_m, w_c, w_d` — коефіцієнти вагомості відповідних привілеїв.

### Теорема про декомпозицію простору станів експлойту

Нехай монолітна система має `N` компонентів, кожен із яких володіє простором внутрішніх станів `S_k` та набором доступних привілейованих системних викликів `M_total`.

У монолітній архітектурі будь-яка вразливість у компоненті `j` дає зловмиснику доступ до повного простору дій системи:

```
ReachableExploitStates(Monolith) = ∏ |S_k| · |M_total|
```

Коли система розбивається на `k` ізольованих контурів за допомогою Seccomp-BPF та пісочниць, де кожен контур `k` має доступ лише до звуженого набору викликів `M_k ⊂ M_total` (`|M_k| ≪ |M_total|`), а взаємодія відбувається через шлюз із граматикою `B`:

```
ReachableExploitStates(Decomposed)
= ∑ (|S_k| · |M_k|) + |B|              [сума ізольованих просторів станів плюс пропускна здатність шлюзу]
```

### Покроковий розрахунок зменшення поверхні атаки

Розглянемо поштовий сервер із трьома підсистемами: парсер TIFF (`S₁`), парсер MIME (`S₂`), менеджер доставки листів (`S₃`).
Нехай ядро надає `|M_total| = 350` системних викликів. Припустимо, що кожна підсистема має `|S_k| = 1000` станів.

**1. Монолітний випадок:**
Усі компоненти виконуються під `root` в одному процесі.

```
AS_mono
= (|S₁| + |S₂| + |S₃|) · |M_total|     [усі стани мають доступ до всіх 350 викликів]
= (1000 + 1000 + 1000) · 350          [підстановка значень]
= 3000 · 350                          [множення]
= 1 050 000 одиниць ризику
```

**2. Ізольований випадок із Seccomp та розділенням привілеїв:**
- Парсер TIFF обмежений Seccomp до `|M₁| = 4` викликів (`read`, `write`, `exit`, `sigreturn`).
- Парсер MIME обмежений до `|M₂| = 4` викликів.
- Менеджер доставки листів має `|M₃| = 15` викликів, але ізольований від прямого мережевого трафіку.
- Шлюз IPC має `|B| = 8` строго типізованих операцій.

```
AS_decomposed
= (|S₁| · |M₁|) + (|S₂| · |M₂|) + (|S₃| · |M₃|) + |B|  [декомпозиція за контурами безпеки]
= (1000 · 4) + (1000 · 4) + (1000 · 15) + 8          [підстановка звужених наборів викликів]
= 4000 + 4000 + 15000 + 8                             [обчислення доданків]
= 23 008 одиниць ризику
```

**Коефіцієнт зниження поверхні атаки:**

```
K_reduction
= AS_mono ÷ AS_decomposed              [співвідношення поверхонь атаки]
= 1 050 000 ÷ 23 008                   [підстановка результатів]
≈ 45.63 рази                           [зниження ризику більш ніж на 97.8%]
```

## 5. Інформаційно-теоретична оцінка витоку даних (Shannon Information Flow)

Межа довіри повинна захищати не лише цілісність, але й запобігати несанкціонованому витоку конфіденційної інформації через приховані побічні канали (Covert Channels).

Нехай випадкова величина `X` представляє секретні дані у високонадійному контурі `L_high` з ентропією Шеннона:

```
H(X) = - ∑ P(x) · log₂ P(x)
```

Спостерігач у низьконадійному контурі `L_low` вимірює вихідну послідовність `Y` (наприклад, часові затримки відповідей або споживання пам'яті).
Взаємна інформація `I(X; Y)` визначає обсяг інформації про секрет `X`, який просочився через межу довіри:

```
I(X; Y)
= H(X) - H(X | Y)                      [визначення взаємної інформації через умовну ентропію]
= H(Y) - H(Y | X)                      [еквівалентна симетрична форма Шеннона]
```

### Теорема невтручання Гогена-Мезігера (Goguen-Meseguer Non-Interference)

Система задовольняє властивість **строгого невтручання (Non-Interference)** тоді й лише тоді, коли для будь-якої послідовності дій користувачів високого рівня `Action_high` результат виконання команд користувачами низького рівня `Action_low` є ідентичним:

```
View_low(Action_low) = View_low(Action_high ⋅ Action_low)
```

З погляду теорії інформації це еквівалентно умові абсолютної незалежності:

```
P(Y | X) = P(Y) ⇒ I(X; Y) = 0
```

Якщо шлюз перетину межі забезпечує детермінований час відповіді (константний час виконання операцій валідації незалежно від коректності пароля чи токена) та фіксований розмір вихідних пакетів, витік інформації через межу анулюється: `I(X; Y) = 0` біт/с.

Математичне моделювання доводить, що декомпозиція системи на ізольовані контури довіри, керовані формальними ґратками Біби та шлюзами Кларка-Вілсона, експоненційно скорочує простір досяжних станів зловмисника та мінімізує інформаційний витік через побічні канали.
