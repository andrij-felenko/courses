# 🧮 Матриця доступу та ймовірнісна оцінка конфігураційних помилок

Формальний аналіз систем безпеки спирається на дискретні моделі розмежування доступу: матрицю суб'єктів та об'єктів, критерії безпеки переходів між станами та кількісну оцінку ймовірності витоку повноважень при відхиленні від принципу найменших привілеїв.

## Модель матриці доступу

Формальна модель дискреційного захисту Лампсона (англ. *Lampson access matrix*) та її строге теоретичне узагальнення Гаррісоном, Руззо та Ульманом (модель HRU, 1976 рік) описує стан комп'ютерної системи як трійку дискретних множин:

- `S = {s₁, s₂, ..., sₘ}` — скінченна множина активних суб'єктів (процеси, потоки, користувачі, сервісні облікові записи);
- `O = {o₁, o₂, ..., oₙ}` — скінченна множина пасивних об'єктів (файли, сокети, дескриптори, сегменти пам'яті, системні виклики), причому `S ⊆ O` (кожен суб'єкт може виступати об'єктом дії для іншого суб'єкта);
- `R = {r₁, r₂, ..., rₖ}` — скінченна множина елементарних прав доступу (читання `read`, запис `write`, виконання `execute`, передача дескриптора `bind`, модифікація прав `grant`, створення нового суб'єкта `create`).

Загальний стан системи захисту однозначно визначається матрицею прав `M`, де кожен елемент `M[s, o] ⊆ R` містить підмножину дозволених операцій, які суб'єкт `s ∈ S` може виконати над об'єктом `o ∈ O`.

Повний простір усіх можливих запитів на виконання операцій у системі становить декартовий добуток:

```
Q = S × O × R
|Q| = |S| · |O| · |R| = m · n · k
```

У довільний фіксований момент часу існує множина легітимних операцій `L ⊆ Q`, які об'єктивно необхідні системі для виконання її бізнес-функцій відповідно до принципу найменших привілеїв.

## Коефіцієнт розрідженості системи повноважень

У реальних виробничих середовищах кількість дій, дійсно потрібних конкретному ізольованому процесу, є мізерною часткою від теоретично можливих комбінацій. Введемо коефіцієнт корисної розрідженості простору повноважень `ρ`:

```
ρ = |L| / |Q|
```

Для типового мережевого сервісу на вузлі під керуванням ОС Linux:
- `m = 50` системних користувачів та процесів;
- `n = 2000` ресурсів (файлів конфігурації, таблиць бази даних, мережевих сокетів, системних дескрипторів, ендпоінтів);
- `k = 10` системних операцій.
- Загальна потужність простору запитів: `|Q| = 50 · 2000 · 10 = 1 000 000`.

Якщо процес мережевого парсера реально потребує доступу лише до 5 локальних дескрипторів на читання та запис, його легітимний набір становить `|L| = 10` елементарних операцій. Тоді:

```
ρ = 10 / 1 000 000 = 0.00001 = 10⁻⁵
```

Тобто `99.999%` простору запитів становлять зайві або потенційно небезпечні операції, які повинні бути суворо заблоковані.

## Ймовірнісна модель конфігураційної помилки

Нехай адміністратор або автоматизований конвеєр налаштовує політику доступу. Будь-яке сформульоване правило може містити дефект або пропуск із незалежною ймовірністю `p ∈ (0, 1)`. Розглянемо дві протилежні парадигми побудови політики:

1. **Allow-by-Default (Чорний список / Denylist):** Усі операції з простору `Q` вважаються дозволеними за замовчуванням. Інженер зобов'язаний явно виявити та описати множину заборонених дій `D = Q \ L`.
2. **Deny-by-Default (Білий список / Allowlist):** Усі операції з простору `Q` заборонені за замовчуванням. Інженер зобов'язаний явно описати множину дозволених дій `A = L`.

Помилка полягає у випадковому пропуску правила, некоректному визначенні маски шляху або збої синтаксичного аналізатора.

### Випадок 1: Allow-by-Default

Кількість правил заборони, які потрібно сформувати та підтримувати:

```
|D| = |Q| - |L| = |Q| · (1 - ρ)
```

Якщо одне правило пропущено з імовірністю `p`, відповідна небезпечна операція помилково отримує дозвіл. Математичне сподівання кількості небезпечних операцій, які система дозволить помилково (поверхня витоку прав `E_allow[Leak]`), дорівнює:

```
E_allow[Leak]
= |D| · p                        [визначення математичного сподівання для біномного розподілу]
= |Q| · (1 - ρ) · p              [підстановка розміру множини заборон |D|]
```

Оскільки `ρ ≪ 1` (для нашого прикладу `1 - ρ = 0.99999 ≈ 1`), маємо:

```
E_allow[Leak] ≈ |Q| · p
```

При `|Q| = 1 000 000` та ймовірності людської або програмної помилки `p = 0.01` (1% пропущених патернів у файрволі чи масці шляхів):

```
E_allow[Leak] ≈ 1 000 000 · 0.99999 · 0.01 ≈ 9 999 небезпечних операцій
```

Система помилково відкриває нападнику доступ до майже 10 000 неконтрольованих дій.

### Випадок 2: Deny-by-Default

Кількість правил дозволу, які потрібно сформувати:

```
|A| = |L| = |Q| · ρ
```

Якщо правило пропущено з імовірністю `p`, система за замовчуванням відмовить у легітимній операції (помилка першого роду — хибна відмова, англ. *false denial*).

При цьому кількість випадково дозволених небезпечних операцій за відсутності збігу правил залишається тотожно рівною нулю:

```
E_deny[Leak] = 0                [за відсутності явного дозволу вердикт завжди DENY]
```

Якщо ж інженер припустився помилки й помилково додав надлишкове правило до списку `A` із тією ж імовірністю `p`, кількість помилкових дозволів обмежена розміром самого списку дозволів:

```
E_deny[Leak_err]
= |A| · p                        [помилкове розширення сформульованого правила]
= |Q| · ρ · p                    [підстановка розміру множини дозволів |A|]
```

Порівняємо математичні сподівання ризику витоку повноважень між двома підходами:

```
E_allow[Leak] / E_deny[Leak_err]
= (|Q| · (1 - ρ) · p) / (|Q| · ρ · p)    [відношення величин ризику]
= (1 - ρ) / ρ                            [скорочення однакових множників |Q| та p]
```

При `ρ = 10⁻⁵`:

```
(1 - 10⁻⁵) / 10⁻⁵ = 0.99999 / 0.00001 = 99 999 ≈ 10⁵
```

## Теорема безпеки HRU та транзитивне замикання прав

У класичній праці Гаррісона, Руззо та Ульмана доведено фундаментальну теорему: в загальній моделі дискреційного доступу з динамічним створенням суб'єктів задача перевірки безпеки (чи може право `r` бути передане неавторизованому суб'єкту `s` через ланцюжок дозволених команд) є алгоритмічно нерозв'язною.

Якщо система працює за принципом надлишкової довіри (монолітний `root`), граф передачі повноважень містить ребра від універсального суб'єкта до всіх об'єктів. Будь-яка операція створення процесу чи запису у спільний канал створює транзитивне замикання, через яке право `r` витікає до нападника.

Принцип найменших привілеїв (PoLP) розриває ці ребра в графі станів:
1. Заборона створення нових привілеїв (`PR_SET_NO_NEW_PRIVS`) вилучає перехідні команди `grant` та `setuid` із набору доступних операцій воркера.
2. Звуження множини об'єктів `O` через `chroot` або `unshare` ізолює матрицю воркера `M_w` у замкненому просторі розмірності `m_w ≪ m` та `n_w ≪ n`.

У замкненій монотонній системі без команд розширення прав перевірка безпеки стає лінійною за часом `O(|S| · |O|)`, що усуває теоретичну нерозв'язність і гарантує математичну стійкість ізоляції.

## Висновок моделі

Політика **Deny-by-Default зменшує математичне сподівання площі витоку прав у `(1 - ρ) / ρ` разів** (для типових систем — на 4–6 порядків величини).

При підході Allow-by-Default будь-яка прогалина в знаннях адміністратора або неповнота парсера призводить до відкриття вразливості для нападника. При підході Deny-by-Default прогалина призводить до штатної відмови в доступі, яка негайно виявляється під час тестування функціональності, не створюючи загрози для вузла.
