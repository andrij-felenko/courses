# 🧮 Математичні межі стійкості AES-GCM та ймовірність колізій у конвертах

Конвертне шифрування (англ. *envelope encryption*) вирішує не лише проблему керування доступом та розподілу прав, а й усуває фундаментальне математичне обмеження симетричних автентифікованих шифрів. У режимі AES-GCM (англ. *Galois/Counter Mode*) повторне використання пари «ключ + вектор ініціалізації (IV / Nonce)» призводить до катастрофічної втрати конфіденційності (миттєве розкриття відкритого тексту через порозрядне додавання за модулем 2) та повної компрометації автентичності (обчислення таємного ключа автентифікації GHASH `H`). 

Нижче наведено строгий математичний аналіз імовірності колізій випадкових векторів ініціалізації на основі парадоксу днів народження, виведення меж стандарту NIST SP 800-38D, оцінку переваги зловмисника у підробці автентифікаційного тегу та математичне доведення того, чому генерація унікального ключа DEK на кожен об'єкт зводить імовірність катастрофічного збою до абсолютного нуля.

### Парадокс днів народження для 96-бітного вектора ініціалізації

У режимі AES-GCM стандартний вектор ініціалізації має довжину 96 бітів (12 байтів). Решта 32 біти 128-бітного вхідного блоку шифру AES резервується під монотонний лічильник блоків усередині одного повідомлення (починаючи з лічильника `2` для першого блоку даних і лічильника `1` для обчислення тегу автентифікації).

Нехай для шифрування незалежних об'єктів або записів використовується один фіксований 256-бітний ключ `K`. Для кожного з `q` повідомлень апаратний або програмний генератор випадкових чисел вибирає 96-бітний вектор ініціалізації `IV` із рівномірним розподілом.

Загальний простір усіх можливих значень вектора ініціалізації дорівнює:

```
N = 2⁹⁶ ≈ 7.92281625 · 10²⁸ можливих значень
```

Ймовірність `P_no_coll(q)` того, що серед `q` згенерованих векторів **не виникне жодної колізії** (тобто всі `q` значень `IV` будуть строго унікальними), задається формулою спадного факторіала:

```
P_no_coll(q) = ∏_{i=0}^{q-1} (1 - i / N)
             = 1 · (1 - 1/N) · (1 - 2/N) · ... · (1 - (q - 1)/N)
```

Для малих значень відношення `i / N` (де `i ≪ N`) справедливе наближення першого порядку ряду Тейлора: `1 - x ≈ exp(-x)`. Застосовуючи це наближення до кожного множника добутку:

```
P_no_coll(q)
≈ ∏_{i=0}^{q-1} exp(-i / N)      [наближення 1 - x ≈ e⁻ˣ]
= exp(- ∑_{i=0}^{q-1} i / N)    [добуток експонент дорівнює експоненті суми]
= exp(- (1/N) · ∑_{i=0}^{q-1} i) [винесення константи 1/N за знак суми]
= exp(- (q · (q - 1)) / (2·N))  [сума арифметичної прогресії: q(q-1)/2]
```

Відповідно, ймовірність виникнення **хоча б однієї колізії** векторів ініціалізації `P_coll(q) = 1 - P_no_coll(q)` визначається як:

```
P_coll(q)
= 1 - exp(- (q · (q - 1)) / (2·N))
≈ (q · (q - 1)) / (2·N)          [наближення 1 - e⁻ʸ ≈ y для малих значень y]
≈ q² / (2 · 2⁹⁶)                 [для великих значень q: q - 1 ≈ q]
= q² / 2⁹⁷                       [зведення степенів двійки: 2 · 2⁹⁶ = 2⁹⁷]
```

Отриманий вираз показує, що ймовірність виникнення колізії зростає пропорційно **квадрату** кількості зашифрованих повідомлень `q²`.

### Виведення граничної кількості викликів за стандартом NIST SP 800-38D

Криптографічний стандарт Національного інституту стандартів і технологій США **NIST SP 800-38D (Recommendation for Block Cipher Modes of Operation: GCM)** встановлює суворе нормативне обмеження на надійність автентифікованого шифрування: при використанні випадкових векторів ініціалізації ймовірність колізії `IV` під одним фіксованим ключем не повинна перевищувати значення `2⁻³²` (приблизно `2.328 · 10⁻¹⁰`).

Обчислимо теоретичну межу кількості повідомлень `q_max`, виходячи з цієї нормативної вимоги:

```
P_coll(q) ≤ 2⁻³²
q² / 2⁹⁷ ≤ 2⁻³²                  [підстановка ймовірності колізії]
q² ≤ 2⁹⁷ · 2⁻³²                  [множення обох частин на 2⁹⁷]
q² ≤ 2⁶⁵                         [додавання показників степеня: 97 - 32 = 65]
q ≤ √(2⁶⁵) = 2³²·⁵               [добування квадратного кореня з обох частин]
q ≤ 2³² · √2 ≈ 4 294 967 296 · 1.41421356 ≈ 6.074 · 10⁹ повідомлень
```

Проте стандарт NIST SP 800-38D (Розділ 8, «Керування векторами ініціалізації») для захисту від деградації ентропії генераторів випадкових чисел (RNG) та потенційних атак зловмисника на стан генератора встановлює значно суворіший практичний ліміт безпеки. Під одним статичним симетричним ключем із **випадковими 96-бітними IV** дозволяється зашифрувати не більше ніж:

```
q_NIST_random = 2¹⁹ = 524 288 повідомлень
```

Обчислимо фактичну ймовірність колізії при дотриманні ліміту `q = 2¹⁹`:

```
P_coll(2¹⁹)
≈ (2¹⁹)² / 2⁹⁷
= 2³⁸ / 2⁹⁷                      [властивість степенів: (2ᵃ)ᵇ = 2ᵃᵇ, 19 · 2 = 38]
= 2⁻⁵⁹                           [віднімання показників степеня: 38 - 97 = -59]
≈ 1.7347 · 10⁻¹⁸
```

Ймовірність `2⁻⁵⁹` означає, що шанс зіткнутися з колізією є мізерно малим (один шанс на сотні квінтильйонів операцій). Проте для високонавантаженої системи, яка обробляє тисячі транзакцій на секунду, ліміт у 524 288 повідомлень вичерпується менш ніж за 10 хвилин роботи.

### Межа підробки автентифікаційного тегу GHASH

Автентифікація в режимі GCM виконується за допомогою універсального гешування над скінченним полем Галуа `GF(2¹²⁸)`. Корисні дані та додаткові автентифіковані дані (AAD) розбиваються на 128-бітні блоки й інтерпретуються як коефіцієнти полінома над `GF(2¹²⁸)`, який обчислюється в точці таємного ключа `H = AES_K(0¹²⁸)`.

Нехай супротивник перехоплює `q` шифротекстів, де максимальна довжина кожного шифротексту становить `l` блоків по 16 байтів (тобто довжина корисних даних `L = 16 · l` байтів), і здійснює `v` спроб передати приймачу сфальсифікований шифротекст із підробленим 128-бітним тегом.

Перевага зловмисника (англ. *adversary advantage*) `Adv_GCM` у порушенні автентичності обмежена фундаментальною теоремою Белларе—Брауна—Кемпа:

```
Adv_GCM ≤ ((q + v) · (l + 1)) / 2¹²⁸ + (q + v)² / 2¹²⁹
```

Розглянемо практичний сценарій сховища об'єктів: середній розмір файлу становить 64 КБ (`l = 4096 = 2¹²` блоків), кількість збережених файлів `q = 2¹⁹` повідомлень, а супротивник здійснює `v = 1` спробу підробки:

```
Adv_GCM
≈ ((2¹⁹ + 1) · (2¹² + 1)) / 2¹²⁸
≈ (2¹⁹ · 2¹²) / 2¹²⁸
= 2³¹ / 2¹²⁸                     [додавання показників: 19 + 12 = 31]
= 2⁻⁹⁷                           [віднімання показників: 31 - 128 = -97]
≈ 6.31 · 10⁻³⁰
```

Це доводить, що 128-бітний автентифікаційний тег забезпечує бездоганну стійкість проти підробок, доки не порушено обмеження на максимальну кількість викликів під одним ключем.

### Математичне обґрунтування безпеки конвертного шифрування

Якщо система використовує один глобальний ключ шифрування диска чи бази даних, поріг безпеки у `2¹⁹` (524 тисячі) записів неминуче вимагає складної, регулярної й ресурсомісткої процедури ротації ключа із повним перешифруванням усього масиву даних.

Конвертна архітектура (Envelope Encryption) повністю знімає цю проблему за рахунок зміни ймовірнісної моделі. Замість багаторазового використання одного ключа для множини записів, сервіс KMS для кожного нового об'єкта генерує **новий унікальний ключ DEK**.

Обчислимо ймовірність колізії вектора ініціалізації для кожного окремого об'єкта під його власним ключем DEK:

```
Кількість операцій під конкретним ключем DEK: q = 1
P_coll(1) = 1 - ∏_{i=0}^{0} (1 - i / N) = 1 - (1 - 0/N) = 1 - 1 = 0
```

Оскільки під кожним ключем DEK виконується рівно одне шифрування (`q = 1`), внутрішньоключова колізія вектора ініціалізації є **математично неможливою** (`P_coll = 0`).

Для множини з `M` різних об'єктів система використовує `M` незалежних випадкових ключів `DEK₁, DEK₂, ..., DEK_M`. Навіть якщо генератор випадкових чисел згенерує абсолютно однаковий вектор ініціалізації для двох різних файлів `IV_a = IV_b = IV*`, операція шифрування AES-CTR виконується під різними незалежними ключами:

```
C_a = AES_{DEK_a}(IV*) ⊕ P_a
C_b = AES_{DEK_b}(IV*) ⊕ P_b
```

Оскільки симетричні ключі `DEK_a` та `DEK_b` обираються незалежно з простору `2²⁵⁶`, рівність `DEK_a = DEK_b` виникає з мізерно малою ймовірністю `2⁻²⁵⁶`. За умови різних ключів значення `AES_{DEK_a}(IV*)` та `AES_{DEK_b}(IV*)` є абсолютно незалежними псевдовипадковими послідовностями, і операція порозрядного додавання XOR не розкриває жодної інформації про відкриті тексти `P_a` та `P_b`.

```
Порівняння математичної безпеки архітектур:
┌──────────────────────────────┬────────────────────────┬─────────────────────────┐
│ Схема шифрування             │ Макс. безпечних записів│ Ймовірність колізії IV  │
├──────────────────────────────┼────────────────────────┼─────────────────────────┤
│ Один ключ AES-GCM (random IV)│ 2¹⁹ ≈ 5.24 · 10⁵       │ Зростає як q² / 2⁹⁷     │
│ Конвертне шифрування (DEK)   │ Необмежено (до 2²⁵⁶)   │ Строго 0 на кожен DEK   │
└──────────────────────────────┴────────────────────────┴─────────────────────────┘
```

Таким чином, конвертне шифрування перетворює масштабування сховища до мільярдів об'єктів і петабайтів даних на математично безпечну операцію без ризику колізій гами або деградації автентичності.
