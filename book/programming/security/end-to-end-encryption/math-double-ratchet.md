# 🧮 Математичний апарат X3DH та ентропійні ланцюги Double Ratchet

Безпека протоколів наскрізного шифрування базується на двох фундаментальних математичних конструкціях: скалярному множенні точок на еліптичних кривих у просторі Монтгомері та односторонніх перетвореннях у ланцюгах функцій розгортання ключів на базі псевдовипадкових функцій HMAC.

### 1. Скалярна алгебра еліптичної кривої Curve25519 (X25519)

Асиметричні операції протоколу X3DH та DH-храповика виконуються на кривій Монтгомері Curve25519, заданій над скінченним простим полем `F_p` з модулем `p = 2²⁵⁵ - 19` рівнянням:

```
y² = x³ + 486662·x² + x  (mod 2²⁵⁵ - 19)
```

Базовою точкою є `G` з x-координатою `9`. Порядок базової точки є простим числом `q = 2²⁵² + 27742317777372353535851937790883648493`. Повний порядок групи кривої дорівнює `8·q` (кофактор `h = 8`).

Закритий ключ генерується як випадковий 256-бітний скаляр `k ∈ [0, 2²⁵⁶ - 1]`. Перед виконанням скалярного множення над скаляром виконується обов'язкова операція очищення бітів (англ. *clamping*, RFC 7748):

```
k_clamped[0]  = k[0] & 248          [скидання трьох молодших бітів для обнулення кофактора h = 8]
k_clamped[31] = (k[31] & 127) | 64  [скидання 255-го біта та примусове встановлення 254-го біта]
```

Очищення трьох молодших бітів гарантує, що результат множення будь-якої точки на `k_clamped` завжди належить до великої підгрупи простого порядку `q`, що повністю усуває атаки малого підпростору (англ. *Small Subgroup Confinement Attacks*). Фіксація старших бітів гарантує сталий час виконання скалярного драбинного алгоритму Монтгомері (англ. *Montgomery Ladder*), унеможливлюючи витік бітів закритого ключа через побічні канали вимірювання часу.

Відкритий ключ — точка `K = k · G`. Спільний секрет Діффі — Геллмана між двома парами `(k_A, K_A)` та `(k_B, K_B)` обчислюється як скалярне множення точки на скаляр:

```
SS = X25519(k_A, K_B)
   = k_A · (k_B · G)     [підстановка відкритого ключа K_B = k_B · G]
   = (k_A · k_B) · G     [асоціативність скалярного множення]
   = k_B · (k_A · G)     [комутативність множення скалярів k_A · k_B = k_B · k_A]
   = X25519(k_B, K_A)    [визначення скалярного добутку для K_A = k_A · G]
```

### 2. Формалізація протоколу Extended Triple Diffie-Hellman (X3DH)

X3DH узгоджує початковий майстер-ключ сесії `SK` між Алісою та Бобом за допомогою чотирьох незалежних операцій узгодження ключів на еліптичній кривій.

Вхідні параметри сторін:
- `IK_A = a · G`, `IK_B = b · G` — довгострокові ідентифікаційні ключі (Identity Keys);
- `SPK_B = s_B · G` — підписаний прекей Боба (Signed Prekey), завірений підписом `Sig_B(SPK_B)` за схемою Ed25519 над кривою Edwards25519;
- `OPK_B = o_B · G` — одноразовий прекей Боба (One-Time Prekey);
- `EK_A = e_A · G` — ефемерний ключ Аліси, згенерований виключно для цієї сесії.

Чотири скалярні добутки:

```
DH1 = X25519(a, SPK_B)   = (a · s_B) · G    [Автентифікація Аліси перед Бобом]
DH2 = X25519(e_A, IK_B)  = (e_A · b) · G    [Пряма секретність щодо identity Аліси]
DH3 = X25519(e_A, SPK_B) = (e_A · s_B) · G  [Сесійна пряма секретність]
DH4 = X25519(e_A, OPK_B) = (e_A · o_B) · G  [Одноразова пряма секретність та захист від повтору]
```

Фінальний спільний ключ `SK` обчислюється за допомогою двоетапної функції розгортання HKDF (RFC 5869) на основі криптографічної геш-функції SHA-256:

```
IKM = DH1 || DH2 || DH3 || DH4
PRK = HKDF-Extract(salt = 0³², IKM)
SK  = HKDF-Expand(PRK, info = "WhisperTextProtocolX3DH", L = 32)
```

Якщо одноразові прекеї Боба на сервері вичерпані, `DH4` пропускається, а `IKM = DH1 || DH2 || DH3`. Присутність `DH1` гарантує, що жоден зловмисник без знання закритого ключа `a` не зможе підробити повідомлення від імені Аліси. Присутність `DH2` і `DH3` з ефемерним скаляром `e_A` гарантує, що навіть повне розкриття довгострокових ключів `a` та `b` у майбутньому не дасть змоги розрахувати `SK` із перехопленого архіву трафіку.

### 3. Алгебра симетричного KDF-ланцюга (Symmetric Ratchet)

Симетричний ланцюг забезпечує послідовну односторонню еволюцію ключів шифрування всередині однієї черги відправлення.

Ланцюг складається зі стану ключа ланцюга `CK_i` (32 байти). Кожен крок породжує наступний стан ланцюга `CK_{i+1}` та унікальний 32-байтний ключ повідомлення `MK_i`:

```
MK_i     = HMAC-SHA256(CK_i, 0x01)
CK_{i+1} = HMAC-SHA256(CK_i, 0x02)
```

**Доведення прямої секретності (Forward Secrecy):**
Нехай зловмисник отримав стан `CK_{i+1}` у момент часу `t_{i+1}`. Обчислення попереднього ключа повідомлення `MK_i` або попереднього стану `CK_i` вимагає знаходження прообразу для криптографічної геш-функції SHA-256 у конструкції HMAC:

```
HMAC-SHA256(K, m) = SHA256((K ⊕ opad) || SHA256((K ⊕ ipad) || m))
```

Оскільки SHA-256 моделюється як ідеальний випадковий оракул зі стійкістю до пошуку першого прообразу порядку `2²⁵⁶`, ймовірність знаходження попереднього ключа `CK_i` за `q_hash` запитів до геш-функції обмежена:

```
P(знайти CK_i | CK_{i+1}) ≤ q_hash / 2²⁵⁶
```

Крім того, оскільки HMAC-SHA256 є доведеною псевдовипадковою функцією (PRF), відрізнити послідовність вихідних ключів `MK_0, MK_1, ... MK_n` від справжнього рівномірного випадкового шуму для поліноміального розрізнювача з `q` запитами неможливо з перевагою, більшою ніж:

```
Adv_PRF(D) ≤ q² / 2²⁵⁶
```

Отже, знання будь-якого майбутнього ключа `CK_{i+k}` не дає жодної обчислювальної переваги для розшифрування повідомлень `0...i`, що строго доводить властивість прямої секретності.

### 4. Асиметричний DH-храповик та зцілення ентропії (Post-Compromise Security)

Коли сторона отримує повідомлення з новим відкритим ключем `DH_remote`, відбувається крок асиметричного храповика над кореневим ключем `RK_j`:

```
SS_new   = X25519(dh_priv_local, DH_remote)
PRK      = HKDF-Extract(salt = RK_j, IKM = SS_new)
RK_{j+1} = HKDF-Expand(PRK, info = "WhisperRatchetRoot", L = 32)
CK_recv  = HKDF-Expand(PRK, info = "WhisperRatchetChain", L = 32)
```

Одразу після цього локальна сторона генерує нову ефемерну пару `(dh_priv_new, dh_pub_new)` і повторює крок для свого ланцюга відправлення:

```
SS_send  = X25519(dh_priv_new, DH_remote)
PRK_send = HKDF-Extract(salt = RK_{j+1}, IKM = SS_send)
RK_{j+2} = HKDF-Expand(PRK_send, info = "WhisperRatchetRoot", L = 32)
CK_send  = HKDF-Expand(PRK_send, info = "WhisperRatchetChain", L = 32)
```

**Теорема зцілення після компрометації (Break-in Recovery):**
Припустимо, що в момент `j` зловмисник повністю скомпрометував стан пам'яті клієнта `(RK_j, CK_j, dh_priv_j)`. Противник знає `RK_j` і здатний пасивно читати поточні повідомлення.

На кроці `j+1` чесний користувач генерує новий секрет `dh_priv_new` за допомогою криптографічно стійкого генератора випадкових чисел (CSPRNG) з мінімальною ентропією `H_∞(dh_priv_new) = 256` біт. Оскільки зловмисник не має фізичного доступу до генератора після моменту злому, спільний секрет `SS_send = dh_priv_new · DH_remote` є рівномірно розподіленим випадковим значенням для противника.

Згідно з лемою про залишок ентропії (Leftover Hash Lemma), функція `HKDF-Extract` із невідомим входом високої ентропії видає псевдовипадковий ключ `RK_{j+2}`, статистична відстань якого від ідеального рівномірного розподілу `U₂₅₆` обмежена величиною:

```
Distance(RK_{j+2}, U₂₅₆) ≤ 1/2 · √(2²⁵⁶ / 2^{H_∞(SS)}) = 1/2 · √(2²⁵⁶ / 2²⁵⁶) = 1/2 · 1
```

Оскільки обчислювальна задача Діффі — Геллмана (CDH) на Curve25519 є експоненційно складною для противника без знання `dh_priv_new`, зловмисник не може розрахувати `SS_send`. Після завершення одного повного циклу відповіді («ping-pong» двома новими DH-парами) кореневий ключ `RK` повністю очищається від впливу минулої компрометації, і протокол повертається до стану ідеальної таємності.

### 5. Математична модель спростовності (Deniable Authentication)

На відміну від цифрових підписів RSA/ECDSA, де верифікація спирається на несиметричну операцію `Verify(pk, msg, sig)`, автентифікація в Signal Protocol ґрунтується на симетричному тегу `Tag = MAC(MK, Ciphertext)`.

Оскільки ключ `MK` є детермінованою функцією відкрито узгодженого через X3DH або Double Ratchet секрету `SS`, симулятор `Sim`, що знає закритий ключ одержувача `b`, може згенерувати статистично невідрізненний протокол діалогу:

```
Distribution(RealTranscript) ≡ Distribution(SimulatedTranscript)
```

Неможливість відрізнити справжній мережевий слід від сфабрикованого одержувачем протоколу забезпечує ідеальну криптографічну спростовність авторства перед будь-яким зовнішнім суддею.
