# 📜 Як Outlook Web Access породив XMLHTTP і відкрив епоху AJAX

Наприкінці 1990-х років Всесвітнє павутиння функціонувало як сукупність статичних гіпертекстових сторінок. Кожна дія користувача — перехід за посиланням, сортування таблиці або відправлення вебформи — змушувала браузер розривати поточний контекст, викидати з пам'яті дерево документа й очікувати від сервера нового повного HTML-файлу. На екрані виникав характерний білий спалах, сторінка прокручувалася вгору, а будь-які незбережені дані в полях введення безповоротно зникали.

Для інформаційних порталів така модель була природною, але вона ставала непереборною перешкодою для складних інтерактивних застосунків.

```
Класична модель Web 1.0 (1995–1999):
Дія користувача → Знищення сторінки → Білий екран → Завантаження 100% HTML → Перемалювання
```

## Виклик поштової скриньки OWA (1998)

Головний поштовх до зміни парадигми стався у Редмонді всередині команди Microsoft Exchange Server. У 1998 році інженер Алекс Гопманн (англ. *Alex Hopmann*) разом із групою розробників створював вебклієнт електронної пошти *Outlook Web Access* (OWA) для майбутнього Exchange Server 2000.

Керівництво вимагало, щоб поштовий клієнт у вікні браузера Internet Explorer працював із такою ж швидкістю та плавністю, як і настільна програма Microsoft Outlook:
* перемикання між папками «Вхідні» та «Надіслані» мало відбуватися без перезавантаження вікна;
* список листів мав оновлюватися автоматично під час надходження нової кореспонденції;
* відкриття листа не повинно було збивати позицію прокрутки списку.

Наявні на той час вебтехнології не надавали жодного нативного інтерфейсу для асинхронного мережевого обміну з коду JavaScript. Розробники вдавалися до складних і нестабільних трюків: створювали невидимий елемент `<iframe style="display:none">` або `<frameset>` з нульовою висотою, відправляли форму всередину цього прихованого фрейму і через небезпечні перехресні скрипти переносили отримані дані в основне вікно за допомогою `parent.document`. Ця схема часто зависала, видавала системні звуки клацання браузера під час кожного фонового запиту й засмічувала історію переходів кнопками «Назад» і «Вперед».

```
Трюк із прихованим фреймом (Hidden iframe hack):
[Основне вікно DOM] ──(виклик)──> [<iframe style="display:none">]
        ▲                                      │ (HTTP POST)
        │                                      ▼
[Оновлення таблиці] <──(parent.window)── [Серверна відповідь]
```

## Народження об'єкта XMLHTTP

Алекс Гопманн дійшов висновку, що браузеру потрібен спеціалізований програмний міст між середовищем виконання скриптів і системним мережевим стеком операційної системи.

У грудні 1998 року Гопманн створив компонент, який отримав назву `XMLHTTP`. Оскільки графік релізу Internet Explorer 5.0 уже перебував на стадії заморожування коду (англ. *code freeze*), додати новий інтерфейс безпосередньо у ядро браузера `mshtml.dll` було організаційно неможливо. Гопманн знайшов обхідний шлях: він домовився з сусідньою командою парсера MSXML (Microsoft XML Library) і вмонтував новий мережевий клас у бібліотеку `msxml.dll` як об'єкт автоматизації ActiveX.

У березні 1999 року вийшов Internet Explorer 5.0. У ньому з'явилася можливість ініціалізувати мережевий запит просто з коду сторінки:

```js
// Перший в історії синтаксис фонового запиту (IE 5.0, 1999)
var xhr = new ActiveXObject("MSXML2.XMLHTTP.3.0");
xhr.open("GET", "/api/inbox", true);
xhr.onreadystatechange = function() {
    if (xhr.readyState === 4 && xhr.status === 200) {
        var xmlDoc = xhr.responseXML;
        updateEmailList(xmlDoc);
    }
};
xhr.send(null);
```

Створений об'єкт дозволяв виконувати методи `GET`, `POST` та інші HTTP-запити у фоновому потоці, не блокуючи інтерфейс користувача, та автоматично парсив відповідь у дерево XML DOM або повертав її у вигляді сирого тексту.

## Реверс-інжиніринг та стандарт W3C

Протягом перших років технологія залишалася пропрієтарною особливістю Internet Explorer. Інші браузери не підтримували ActiveX, що стримувало поширення підходу у відкритому вебі.

Ситуація змінилася у 2000–2002 роках, коли інженери проєкту Mozilla (зокрема Девід Гаятт) здійснили реверс-інжиніринг інтерфейсу `XMLHTTP` і створили його відкритий аналог для рушія Gecko. Замість нестабільного ActiveX-виклику вони інтегрували об'єкт безпосередньо в глобальну область видимості `window` під ім'ям `XMLHttpRequest`.

Невдовзі аналогічну нативну реалізацію додали Apple у браузер Safari (2004) та Opera Software (2005).

У 2006 році Консорціум Всесвітнього павутиння (W3C) опублікував першу офіційну специфікацію `XMLHttpRequest Level 1`, остаточно закріпивши загальногалузевий стандарт.

| Браузер | Рік появи | Спосіб створення об'єкта |
| :--- | :--- | :--- |
| **Internet Explorer 5.0** | 1999 | `new ActiveXObject("Microsoft.XMLHTTP")` |
| **Mozilla / Firefox 1.0** | 2002 | `new XMLHttpRequest()` |
| **Apple Safari 1.2** | 2004 | `new XMLHttpRequest()` |
| **Opera 8.0** | 2005 | `new XMLHttpRequest()` |
| **W3C Специфікація** | 2006 | Загальний відкритий стандарт Web API |

## Демонстрація Google та маніфест Джессі Гарретта (2004–2005)

Хоча технічний інструмент існував з 1999 року, більшість веброзробників продовжували сприймати сторінки як статичні документи. Справжній тектонічний зсув свідомості індустрії відбувся у 2004–2005 роках завдяки двом релізам компанії Google:

1. **Gmail (квітень 2004):** вебпошта з миттєвим пошуком, живим перемиканням ланцюжків повідомлень і фоновою синхронізацією чернеток довела, що вебінтерфейс може конкурувати з настільними клієнтами за чутливістю.
2. **Google Maps (лютий 2005):** інтерактивна географічна карта, яку можна було безперервно перетягувати мишею в будь-якому напрямку. Браузер на льоту підвантажував прямокутні графічні тайли розміром 256×256 пікселів через фонові запити `XMLHttpRequest` без жодного миготіння екрана.

```
Конвеєр підвантаження тайлів Google Maps (2005):
Рух миші користувача (Drag & Drop)
  → Обчислення нових географічних координат
  → Паралельні виклики XMLHttpRequest для 4–8 суміжних фрагментів
  → Додавання отриманих <img> у контейнер карти
  → Безперервний плавний скролінг без білих спалахів
```

18 лютого 2005 року Джессі Джеймс Гарретт (англ. *Jesse James Garrett*), співзасновник аналітичної агенції Adaptive Path, опублікував програмне есе під назвою *«Ajax: A New Approach to Web Applications»*.

Гарретт запропонував абревіатуру **AJAX** (*Asynchronous JavaScript and XML*), об'єднавши цим терміном комплекс технологій:
* семантичну розмітку HTML/XHTML та стилі CSS для подання;
* динамічне маніпулювання DOM за допомогою JavaScript;
* обмін структурованими даними (XML або згодом JSON);
* неблоківний мережевий транспорт на базі `XMLHttpRequest`.

Публікація есе Гарретта миттєво легітимізувала технологію в очах корпоративного бізнесу. За лічені місяці з'явилися бібліотеки Prototype.js, Dojo, MooTools, а в серпні 2006 року Джон Резіг представив jQuery, метод `$.ajax()` якого став де-факто головним інтерфейсом веброзробки на наступне десятиліття.

Випадкова інженерна знахідка для поштового сервера перетворила браузер зі статичного переглядача гіпертексту на універсальну платформу для розподілених застосунків.
