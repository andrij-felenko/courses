# 📜 Як криза двостороннього зв'язування породила Virtual DOM

На початку 2010-х років клієнтська веб-розробка опинилася в глухому куті масштабованості. Індустрія масово відмовлялася від неструктурованих сценаріїв jQuery на користь архітектурних каркасів першої хвилі: Backbone.js, Knockout.js, Ember.js та AngularJS (версії 1.x). Ці інструменти пропонували привабливу обіцянку — двостороннє зв'язування даних (*two-way data binding*), де зміни в моделі автоматично відображалися у вузлах DOM, а взаємодія користувача з полями форми миттєво змінювала модель.

Проте на практиці ця модель виявилася крихкою і непередбачуваною.

## Лавина мутацій та криза AngularJS $digest

У класичній моделі двостороннього зв'язування кожен візуальний віджет підписувався на події зміни даних, а модель підписувалася на події інтерфейсу. У складних інтерфейсах (наприклад, у стрічці новин із чатом, коментарями та лічильниками сповіщень) зміна одного прапорця викликала каскадну реакцію:

```
Зміна поля A  →  Оновлення DOM-вузла 1  →  Тригер події 'change'
              →  Оновлення поля B       →  Оновлення DOM-вузла 2
              →  Оновлення поля C       →  Повторне оновлення DOM-вузла 1 (Цикл!)
```

В AngularJS цей процес контролював цикл `$digest`, який повторно проходив по масиву всіх зареєстрованих спостерігачів (*watchers*), доки стан не стабілізувався (*dirty checking*). Якщо за 10 ітерацій модель не досягала спокою (*TTL exceeded*), рушій аварійно викидав виняток.

Коли кількість спостерігачів на сторінці перевищувала 2000 (типова ситуація для великих таблиць чи списків), кожен рух миші або введення символу призводило до затримки в 50–200 мс. Розробники витрачали тижні на тонке налаштування `shouldUpdate`, ручне відписування від подій та оптимізацію селекторів, бо не мали детермінованої відповіді на запитання: «У якому стані перебуває інтерфейс у конкретний момент часу?».

## Ідея Джордана Волка: UI як чиста функція

У 2011 році інженер Facebook Джордан Волк (*Jordan Walke*) почав експериментувати з альтернативним підходом. Надихнувшись функційним програмуванням мовою Standard ML та розширенням XHP для PHP (яке дозволяло писати XML-подібний синтаксис прямо у коді бекенду), Волк створив прототип клієнтської бібліотеки під назвою **FaxJS**.

Головна гіпотеза Волка звучала радикально:
> «Забудьте про мутації окремих вузлів і двосторонні підписки. Уявіть, що при кожній зміні стану застосунок просто викидає старий інтерфейс і перемальовує всю сторінку з нуля, як це робили класичні серверні сайти в 1990-х».

```
UI = f(state)
```

Ця формула знімала весь тягар відстеження проміжних станів: розробник описував лише те, як інтерфейс *має* виглядати для поточного зліпка даних, а не послідовність мутацій `appendChild`, `removeChild` чи `classList.toggle`.

Однак повне перемальовування через `container.innerHTML = render(state)` було неприйнятним:
1. Воно знищувало внутрішній стан елементів введення (скидався фокус клавіатури, виділення тексту, позиція курсора в полі `<input>`);
2. Зупиняло завантаження вбудованого медіа (перезапуск `<video>` та `<iframe>`);
3. Викликало повний параліч графічного конвеєра браузера (масовий *Reflow* та *Repaint* на кожен введений символ).

Щоб зробити ідею функційного перевизначення життєздатною, Волк запропонував проміжний шар абстракції: **Virtual DOM**.

## Народження React і скепсис на JSConf US 2013

У травні 2013 року на конференції JSConf US (Амелія-Айленд, Флорида) Джордан Волк та Том Оккіно (*Tom Occhino*) офіційно представили **React** спільноті відкритого коду в доповіді «JS Apps at Facebook». Згодом, у вересні того ж року на конференції JSConf EU, інженер Facebook Піт Гант (*Pete Hunt*) виступив із доповіддю «React: Rethinking best practices», роз'яснюючи філософію бібліотеки широкій європейській аудиторії.

Перші виступи зустріли хвилю критики та відвертого несприйняття. Індустрія, яка роками вчила принцип «розділення відповідальності» (*Separation of Concerns*) — відокремлення HTML-розмітки, CSS-стилів та JS-поведінки, — побачила синтаксис JSX, що повертав розмітку безпосередньо з тіла JavaScript-функцій.

Другим об'єктом критики була ідея віртуального дерева. Експерти стверджували, що створення тисяч об'єктів JavaScript у пам'яті на кожен користувацький клік викличе колапс збирача сміття (*Garbage Collector*) у рушії V8, а попарне порівняння двох гігантських дерев зробить застосунки повільнішими за наївний jQuery.

Проте за кілька місяців реальні бенчмарки показали зворотне: евристичний алгоритм узгодження React працював за `O(N)` замість теоретичного `O(N^3)`, а виграш від пакетування та мінімізації реальних DOM-операцій багаторазово перекривав накладні витрати на виділення пам'яті в V8.

## Мінімалізм Snabbdom та адаптація у Vue

Успіх React породив цілу екосистему незалежних досліджень алгоритмів узгодження. У 2015 році данський розробник Симон Фрііс Віндум (*Simon Friis Vindum*) опублікував бібліотеку **Snabbdom**. 

Якщо кодова база React на той час уже була тісно переплетена із синтетичною системою подій (*SyntheticEvent*) та класовими компонентами, Snabbdom складався лише з кількох сотень рядків коду. Він зосередився виключно на математиці звіряння та запропонував елегантний **двосторонній алгоритм узгодження (Double-Ended Diffing)** з чотирма покажчиками.

Цей алгоритм став настільки вдалим стандартом, що Еван Ю (*Evan You*) повністю переписав рушій рендерингу **Vue.js 2.0** (2016 рік) на форк Snabbdom. Віртуальне дерево остаточно закріпилося як домінуюча парадигма архітектури вебінтерфейсів.

## Ревізія архітектури: React Fiber та LIS у Vue 3

У 2017 році команда Facebook зіткнулася з новою межею технології. Класичний VDOM-дифінг був синхронним і рекурсивним: якщо дерево налічувало десятки тисяч вузлів, рекурсивний обхід `reconcileChildren` міг зайняти 30–50 мс. Протягом цього часу головний потік браузера залишався заблокованим, викликаючи візуальні зависання (*jank*) та випадання кадрів анімацій (порушення ліміту 16.67 мс для 60 Гц).

Відповіддю став **React Fiber** — повна перебудова рушія, де деревоподібна рекурсія була замінена на однозв'язний список волокон (*fibers*). Це дозволило розбити процес узгодження на дрібні кванти часу (*Time Slicing*), призупиняти обчислення для обробки високопріоритетного введення користувача та відновлювати рендеринг без втрати прогресу.

Паралельно у 2020 році **Vue 3** оновив алгоритм звіряння списків, застосувавши пошук **найдовшої зростаючої підпослідовності (LIS)** за алгоритмом бінарного пошуку з відновленням батьківських посилань. Це дозволило скоротити кількість найдорожчих операцій `Node.insertBefore` до абсолютно мінімального математичного оптимуму.

Virtual DOM пройшов шлях від сміливого експерименту, зустрінутого недовірою, до фундаменту, на якому сьогодні працює переважна більшість інтерфейсів сучасного вебу.
