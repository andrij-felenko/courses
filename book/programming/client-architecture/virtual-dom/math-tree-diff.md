# 🧮 Чому точне мінімальне редагування дерев вимагає O(N³)

Щоб перетворити одне деревоподібне подання інтерфейсу в інше з мінімальною кількістю реальних змін, рушій повинен знайти найкоротшу послідовність елементарних операцій редагування. У комп'ютерних науках ця задача відома як **відстань редагування дерев** (англ. *Tree Edit Distance*, TED).

Нижче наведено формальне математичне виведення того, чому загальне точне розв'язання цієї задачі для впорядкованих маркованих дерев має часову складність `O(N^3)`, і чому бібліотеки інтерфейсу свідомо відмовляються від точного мінімуму на користь евристичного наближення `O(N)`.

## Формальна модель операцій над деревами

Нехай `T` — скінченне впорядковане кореневе дерево, де кожен вузол `v ∈ T` має мітку `label(v)` (назва тегу, набір атрибутів і текстовий вміст). Для вузлів визначено лінійно впорядковані зв'язки «батько — дитина» та порядок серед братніх вузлів зліва направо.

Відстань редагування між двома деревами `T₁` та `T₂` визначається через три елементарні операції над вузлами:

1. **Перейменування (Relabel):** заміна мітки вузла `v` на `v'`. Вартість операції: `γ(v → v') ≥ 0`. Якщо `v = v'`, то `γ = 0`.
2. **Видалення (Delete):** видалення невиділеного вузла `v`. Усі діти вузла `v` стають дітьми його батька `parent(v)`, зберігаючи свій відносний порядок зліва направо серед решти дітей. Вартість: `γ(v → ε)`.
3. **Вставка (Insert):** вставка нового вузла `w` як дитини вузла `u`. Підмножина послідовних дітей вузла `u` стає дочірніми вузлами нового елемента `w`. Вартість: `γ(ε → w)`.

Задача полягає у знаходженні послідовності операцій `S = (op₁, op₂, ..., op_k)`, що трансформує `T₁` у `T₂`, за якої сумарна вартість є мінімальною:

```
TED(T₁, T₂) = min { ∑_{i=1}^k γ(op_i) }
```

## Рівняння динамічного програмування Чжана—Шаші

Найвідомішим класичним алгоритмом точного обчислення TED є алгоритм Као Чжана та Денніса Шаші (*Zhang-Shasha Algorithm*, 1989 рік).

Алгоритм використовує нумерацію вузлів дерева в порядку прямого зворотного обходу (англ. *postorder traversal* зліва направо). Нехай `T[i]` позначає `i`-й вузол у postorder-порядку, а `T[1..i]` — лісовий підграф, утворений першими `i` вузлами.

Для кожного вузла `i` визначимо `l(i)` як індекс найлівішого листового нащадка піддерева з коренем у `i`. Піддерево з коренем `i` записується як `T[l(i)..i]`.

Відстань між двома довільними підлісами `F₁ = T₁[l(i)..i']` та `F₂ = T₂[l(j)..j']` вираховується за рекурентним співвідношенням динамічного програмування:

```
δ(∅, ∅) = 0                                            [базовий випадок порожніх лісів]
δ(F₁, ∅) = δ(T₁[l(i)..i'-1], ∅) + γ(T₁[i'] → ε)         [вартість видалення правого кореня]
δ(∅, F₂) = δ(∅, T₂[l(j)..j'-1]) + γ(ε → T₂[j'])         [вартість вставки правого кореня]
```

Для непорожніх лісів, коли `l(i') = l(i)` та `l(j') = l(j)` (тобто обидва ліси є повноцінними піддеревами `T₁[i]` та `T₂[j]`):

```
δ(F₁, F₂) = min {
  δ(T₁[l(i)..i'-1], F₂) + γ(T₁[i'] → ε),               [варіант 1: видалення вузла i']
  δ(F₁, T₂[l(j)..j'-1]) + γ(ε → T₂[j']),               [варіант 2: вставка вузла j']
  δ(T₁[l(i)..l(i')-1], T₂[l(j)..l(j')-1]) + δ(T₁[l(i')..i'-1], T₂[l(j')..j'-1]) + γ(T₁[i'] → T₂[j'])  [варіант 3: зіставлення піддерев]
}
```

У третьому варіанті матриця розпадається на зіставлення внутрішніх дітей піддерева та заміну мітки кореня.

## Виведення часової складності

Щоб знайти загальну складність, порахуємо кількість викликів динамічного програмування.

Нехай:
- `|T₁| = M`, `|T₂| = N` — кількість вузлів у деревах;
- `leaves(T)` — кількість листків у дереві;
- `depth(T)` — максимальна глибина дерева.

Алгоритм Чжана—Шаші визначає множину так званих **ключових коренів** (англ. *key roots*): вузлів, які або є коренем усього дерева, або мають лівого брата:

```
KR(T) = { k ∈ T | не існує k' ∈ T таких, що k' > k та l(k') = l(k) }
```

Розмір множини ключових коренів обмежений кількістю листків:

```
|KR(T)| ≤ min(depth(T), leaves(T))
```

Для кожної пари ключових коренів `(i, j) ∈ KR(T₁) × KR(T₂)` заповнюється таблиця динамічного програмування розміром `|T₁[l(i)..i]| × |T₂[l(j)..j]|`.

Сумарна кількість операцій `C` дорівнює:

```
C = ∑_{i ∈ KR(T₁)} ∑_{j ∈ KR(T₂)} |T₁[l(i)..i]| · |T₂[l(j)..j]|
```

### Аналіз для граничних форм дерев

Розглянемо поведінку цієї суми для двох крайніх випадків структури дерев однакового розміру `|T₁| = |T₂| = N`:

**1. Вироджене дерево (ланцюг глибини N, де кожен вузол має 1 дитину):**

```
leaves(T) = 1
depth(T) = N
|KR(T)| = 1                                           [лише один ключовий корінь — самий корінь]
C = |T₁| · |T₂|
  = N · N
  = N²                                                [квадратична складність для списків]
```

**2. Повне k-арне дерево або зірка (корінь має N-1 дітей-листків):**

```
leaves(T) = N - 1 ≈ N
depth(T) = 2
|KR(T)| = N                                           [кожен листок є ключовим коренем]
```

Для кожного листка `i` розмір піддерева `|T[l(i)..i]| = 1`. 

Сума набуває вигляду:

```
C = ∑_{i=1}^N ∑_{j=1}^N (1 · 1) + |T₁| · |T₂|         [всі пари листків плюс повний корінь]
```

Для загального випадку збалансованого розгалуженого дерева (де глибина `depth(T) ≈ log N`, а кількість листків `leaves(T) ≈ N/2`):

```
C = ∑_{i ∈ KR(T₁)} |T₁[l(i)..i]| · ∑_{j ∈ KR(T₂)} |T₂[l(j)..j]|
```

Кожен вузол `v ∈ T` входить у піддерева предків, які є ключовими коренями. Кількість таких предків для вузла `v` обмежена `min(depth(T), leaves(T))`. Тому:

```
∑_{i ∈ KR(T)} |T[l(i)..i]| ≤ N · min(depth(T), leaves(T))
```

Перемножуючи дві суми для `T₁` та `T₂`:

```
C ≤ N · min(depth(T₁), leaves(T₁)) · N · min(depth(T₂), leaves(T₂))
```

Для типових дерев розмітки користувацького інтерфейсу, де коефіцієнт розгалуження становить `3–5`, а глибина пропорційна кількості рівнів вкладеності компонентів, `min(depth, leaves) ≈ O(N)`.

Підставляючи граничні значення:

```
C = O(N · N · N)
  = O(N³)                                             [кубічна часова складність]
```

## Чому O(N³) є неприйнятним для UI

Для сторінки середнього розміру з `N = 1000` DOM-вузлами кількість елементарних операцій у таблиці динамічного програмування становить:

```
N³ = 1000³
   = 1 000 000 000                                    [один мільярд операцій порівняння]
```

При швидкості виконання JavaScript у 10⁸ операцій/с точний розрахунок мінімальної редакторської відстані між двома послідовними станами зайняв би близько **10 секунд процесорного часу**. Оскільки потік інтерфейсу має жорсткий ліміт кадру в **16.67 мс** (для частоти оновлення екрана 60 Гц), точний алгоритм заморожував би вікно браузера на сотні кадрів при кожному натисканні кнопки.

## Як евристики Virtual DOM зводять O(N³) до O(N)

Virtual DOM усуває кубічну залежність шляхом введення двох жорстких аксіом, що звужують простір пошуку трансформацій:

### 1. Заборона міжрівневого зіставлення (Level-by-Level Isolation)

Алгоритм узгодження порівнює лише вузли, що знаходяться на **однаковому рівні вкладеності** в обох деревах. Якщо вузол перемістився на інший рівень (наприклад, з `root > div > span` у `root > span`), VDOM не шукає схожість крізь шари: він знищує старий `span` і монтує новий.

Це обмежує пошук ізольованими піддеревами:

```
C_heuristic = ∑_{level=1}^D ∑_{nodes ∈ level} C(node)
            = O(N)                                    [лінійний обхід дерева]
```

### 2. Принцип несумісності типів (Tag Invariance)

Якщо два вузли мають різні типи або теги (`type(A) ≠ type(B)`, наприклад `<div>` замінено на `<section>`), вартість їх зіставлення приймається рівною нескінченності `γ(A → B) = ∞`. Старе піддерево демонтується цілком за час `O(|Subtree_A|)`, а нове монтується за `O(|Subtree_B|)`. Рекурсивне порівняння їхніх нащадків взагалі не виконується.

Завдяки цим двом обмеженням повний обхід двох дерев розміром `N` виконується рівно за один прохід `O(N)` кроків.
