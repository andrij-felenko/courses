# 📋 Специфікація граматики та довідник форматів ISO 8601 і RFC 3339

Стандарт ISO 8601 та його профіль RFC 3339 визначають текстовий контракт для передачі часових величин у мережевих протоколах, базах даних і файлових форматах. Цей довідник містить формальну граматику (ABNF), опис компонентів, таблиці допустимих форм та правила валідації.

## Компоненти та символи-дескриптори

Кожна літера в шаблонах форматів має фіксовану довжину розрядів та семантичне значення:

| Символ | Одиниця вимірювання | Допустимий діапазон | Обов'язкова довжина | Опис |
| :--- | :--- | :--- | :--- | :--- |
| `YYYY` | Рік (Year) | `0000`–`9999` | 4 цифри | Грегоріанський календар (прокінетичний для дат до 1582 року) |
| `±YYYYY` | Розширений рік | `±00000`–`±99999` | 5+ цифр зі знаком | ISO 8601-1:2019 для років поза межами діапазону 0000..9999 |
| `MM` | Місяць (Month) | `01`–`12` | 2 цифри | `01` — січень, `12` — грудень (провідний нуль обов'язковий) |
| `DD` | День місяця (Day) | `01`–`31` | 2 цифри | Залежить від кількості днів у конкретному місяці та високосного року |
| `DDD` | Порядковий день (Ordinal) | `001`–`366` | 3 цифри | День року від 1 січня (`001`) до 31 грудня |
| `Www` | Номер тижня (Week) | `W01`–`W53` | Префікс `W` + 2 цифри | Перший тиждень року містить перший четвер року |
| `D` | День тижня (Weekday) | `1`–`7` | 1 цифра | `1` — понеділок, `7` — неділя |
| `T` | Розділювач часу (Time) | Літера `T` або пробіл | 1 символ | Відокремлює дату від часу доби |
| `hh` | Година (Hour) | `00`–`23` (або `24`) | 2 цифри | 24-годинна шкала; значення `24` допустиме в ISO 8601 для кінця доби |
| `mm` | Хвилина (Minute) | `00`–`59` | 2 цифри | Кількість хвилин поточної години |
| `ss` | Секунда (Second) | `00`–`59` або `60` | 2 цифри | Значення `60` зарезервоване для високосної секунди UTC |
| `.sss` | Дробова частка секунди | `.0`–`.999999999` | 1+ цифр | Крапка або кома (`.`) в ISO 8601; тільки крапка в RFC 3339 |
| `Z` | Позначення UTC (Zulu) | Літера `Z` | 1 символ | Еквівалент числового зміщення `+00:00` |
| `±hh:mm` | Зміщення часового поясу | `-23:59`–`+23:59` | 6 символів | Різниця між локальним часом та шкалою UTC |

## Правила календаря та валідація дат

Коректність календарної дати визначається правилами пролептичного грегоріанського календаря:

1. **Високосний рік (Leap Year):** рік є високосним, якщо він ділиться на 4 без остачі, за винятком тих років, які діляться на 100, але не діляться на 400. Отже, 2000 та 2024 роки — високосні, тоді як 1900 та 2100 роки — звичайні.
2. **Кількість днів у місяці:**
   * Квітень (04), червень (06), вересень (09), листопад (11) містять строго 30 днів.
   * Лютий (02) містить 29 днів у високосному році та 28 днів у звичайному.
   * Решта місяців (01, 03, 05, 07, 08, 10, 12) містять 31 день.
3. **Тижнева система числення (Week Dates):**
   * Тиждень завжди починається з понеділка (день 1) і закінчується неділею (день 7).
   * Перший тиждень року (`W01`) визначається як тиждень, що містить перший четвер року (що еквівалентно наявності 4 січня всередині цього тижня).
   * Через це останні дні грудня можуть належати до першого тижня наступного року (наприклад, `2024-12-30` записується як `2025-W01-1`), а перші дні січня можуть належати до 52-го чи 53-го тижня попереднього року.
4. **Порядкові дати (Ordinal Dates):**
   * Запис `YYYY-DDD` представляє порядковий номер дня від початку року від `001` (1 січня) до `365` (або `366` у високосний рік). Це усуває необхідність обчислення місяців для задач астрономії, геодезії та супутникової навігації.

## Формальна граматика ABNF за RFC 3339

Граматика RFC 3339 у нотації ABNF (Augmented Backus-Naur Form, RFC 5234) визначає суворий інтернет-профіль:

```
date-fullyear   = 4DIGIT
date-month      = 2DIGIT  ; 01-12
date-mday       = 2DIGIT  ; 01-28, 01-29, 01-30, 01-31 за календарем

time-hour       = 2DIGIT  ; 00-23
time-minute     = 2DIGIT  ; 00-59
time-second     = 2DIGIT  ; 00-58, 00-59, 00-60 (високосна секунда)
time-secfrac    = "." 1*DIGIT
time-numoffset  = ("+" / "-") time-hour ":" time-minute
time-offset     = "Z" / time-numoffset

partial-time    = time-hour ":" time-minute ":" time-second [time-secfrac]
full-date       = date-fullyear "-" date-month "-" date-mday
full-time       = partial-time time-offset

date-time       = full-date "T" full-time
```

## Зведені таблиці форматів: ISO 8601 проти RFC 3339

Основна відмінність полягає в тому, що ISO 8601 допускає базовий компактний синтаксис (без дефісів і двокрапок) та різні способи числення дат, тоді як RFC 3339 вимагає єдиного канонічного розширеного подання.

| Тип сутності | Базовий формат (ISO 8601) | Розширений формат (ISO 8601) | Формат за RFC 3339 | Приклад |
| :--- | :--- | :--- | :--- | :--- |
| **Календарна дата** | `YYYYMMDD` | `YYYY-MM-DD` | `YYYY-MM-DD` | `2026-08-20` |
| **Порядкова дата** | `YYYYDDD` | `YYYY-DDD` | *Не підтримується* | `2026-232` |
| **Тижнева дата** | `YYYYWwwD` | `YYYY-Www-D` | *Не підтримується* | `2026-W34-4` |
| **Час у UTC** | `hhmmssZ` | `hh:mm:ssZ` | `hh:mm:ssZ` | `22:30:15Z` |
| **Час зі зміщенням** | `hhmmss±hhmm` | `hh:mm:ss±hh:mm` | `hh:mm:ss±hh:mm` | `22:30:15+03:00` |
| **Дата й час (UTC)** | `YYYYMMDDThhmmssZ` | `YYYY-MM-DDThh:mm:ssZ` | `YYYY-MM-DDThh:mm:ssZ` | `2026-08-20T22:30:15Z` |
| **Дата й час (дріб)** | `YYYYMMDDThhmmss.sssZ` | `YYYY-MM-DDThh:mm:ss.sssZ` | `YYYY-MM-DDThh:mm:ss.sssZ` | `2026-08-20T22:30:15.123Z` |
| **Дата й час (зміщення)**| `YYYYMMDDThhmmss+hhmm`| `YYYY-MM-DDThh:mm:ss+hh:mm` | `YYYY-MM-DDThh:mm:ss+hh:mm` | `2026-08-20T22:30:15+03:00` |
| **З розділювачем-пробілом**| *Не підтримується* | *Не підтримується* | `YYYY-MM-DD hh:mm:ssZ` | `2026-08-20 22:30:15Z` |
| **Невідоме зміщення** | *Не підтримується* | *Не підтримується* | `YYYY-MM-DDThh:mm:ss-00:00` | `2026-08-20T22:30:15-00:00` |

## Відмінності в граничних випадках між специфікаціями

1. **Розділювач дати й часу:**
   * *ISO 8601:* Дозволяє тільки велику літеру `T` (або `T` за домовленістю).
   * *RFC 3339:* Дозволяє велику `T`, малу `t`, або звичайний пробіл ` ` між датою і часом.

2. **Регістр суфікса UTC:**
   * *ISO 8601:* Вимагає велику літеру `Z`.
   * *RFC 3339:* Дозволяє як велику `Z`, так і малу `z`.

3. **Спеціальне значення `-00:00`:**
   * *ISO 8601:* Забороняє знак мінус для нульового зміщення (допускає тільки `+00:00` або `Z`).
   * *RFC 3339:* Прямо резервує `-00:00` для позначення ситуації, коли локальний час відомий, але числове зміщення відносно UTC не встановлено (наприклад, системний годинник налаштовано локально, але інформація про часовий пояс втрачена). Конвертувати такий час у мітку UTC напряму не можна.

4. **Розділювач часток секунди:**
   * *ISO 8601:* Дозволяє крапку `.` або кому `,`.
   * *RFC 3339:* Дозволяє виключно крапку `.`.

5. **Година 24:00:00:**
   * *ISO 8601-1:* Дозволяє значення `24:00:00` як синонім кінця поточної доби (еквівалентно `00:00:00` наступного дня).
   * *RFC 3339:* Суворо обмежує години діапазоном `00`..`23`. Значення `24` заборонене.

6. **Усічені та редуковані дати (Truncated Dates):**
   * *ISO 8601-1:* Дозволяє усічені форми за угодою сторін, наприклад `--08-20` (20 серпня без вказівки року) або `2026-08` (серпень 2026 року без вказівки дня).
   * *RFC 3339:* Категорично забороняє будь-які усічені форми: повна дата `YYYY-MM-DD` та повний час `hh:mm:ss` є неподільними обов'язковими блоками.

## Синтаксис тривалостей (Durations)

Тривалість за ISO 8601 задається рядком, що починається з дескриптора `P` (Period).

Формула загального формату:
```
P [n]Y [n]M [n]D [ T [n]H [n]M [n]S ]
```

* `P` — маркер початку періоду (завжди стоїть першим).
* `nY` — кількість років (`n` — ціле або дробове число).
* `nM` — кількість місяців (якщо стоїть **до** маркера `T`).
* `nD` — кількість днів.
* `T` — маркер початку блоку часу доби.
* `nH` — кількість годин.
* `nM` — кількість хвилин (якщо стоїть **після** маркера `T`).
* `nS` — кількість секунд (може містити дробову частину, наприклад `10.5S`).

### Альтернативний тижневий формат:
```
P [n]W   ; наприклад P4W (рівно 4 календарні тижні, тобто 28 днів)
```

| Рядок тривалості | Значення |
| :--- | :--- |
| `P1Y` | 1 рік |
| `P2M10D` | 2 місяці та 10 днів |
| `PT1H30M` | 1 година 30 хвилин |
| `PT0.5S` | 500 мілісекунд (пів секунди) |
| `P1Y2M10DT2H30M45.5S` | 1 рік, 2 місяці, 10 днів, 2 години, 30 хвилин, 45.5 секунд |
| `P3W` | 3 тижні (21 день) |

## Синтаксис інтервалів часу (Time Intervals)

Інтервал часу складається з двох компонентів, розділених символом скісної риски (`/`):

1. **`<Початок>/<Кінець>`:**
   `2026-08-20T08:00:00Z/2026-08-20T17:00:00Z`
   Визначає фіксований відрізок часу з точними межами.

2. **`<Початок>/<Тривалість>`:**
   `2026-08-20T08:00:00Z/PT9H`
   Подія починається о 08:00 UTC і триває рівно 9 годин (завершується о 17:00 UTC).

3. **`<Тривалість>/<Кінець>`:**
   `PT9H/2026-08-20T17:00:00Z`
   Подія завершується о 17:00 UTC і триває 9 годин (початок був о 08:00 UTC).

4. **Повторювані інтервали (Recurring Intervals): `R[n]/[інтервал]`:**
   * `R5/2026-08-20T08:00:00Z/PT1H` — повторити 5 разів з інтервалом в 1 годину, починаючи від зазначеної миті.
   * `R/PT15M` — нескінченний цикл із періодичністю 15 хвилин (застосовується для таймерів та опитування сервісів).

## Розширення RFC 9557: Ідентифікатори часових поясів IANA

У 2024 році RFC 9557 стандартизував суфікс у квадратних дужках для передачі ідентифікатора зони IANA (tz database):

```
2026-08-20T22:30:00+03:00[Europe/Kyiv]
2026-12-25T10:00:00-05:00[!America/New_York]
```

* `[Europe/Kyiv]` — необов'язкова анотація назви часового поясу. Якщо суфікс суперечить числовому зміщенню, парсер бере числове зміщення як пріоритет для обчислення миті UTC, а назву використовує для відображення в інтерфейсі.
* `[!America/New_York]` — знак оклику `!` означає суворе критичне правило (critical flag). Якщо парсер не знає правил для поясу `America/New_York`, він зобов'язаний відхилити весь рядок як невалідний.
* **Правила вирішення суперечностей:** якщо у майбутній даті числове зміщення вказано як `+02:00`, але за базою даних IANA на той момент діятиме зміщення `+03:00` (наприклад, через перехід на літній час), критичний прапорець `!` змушує систему вважати пріоритетною назву часового поясу, перераховуючи фізичну мить UTC згідно з актуальними правилами.
