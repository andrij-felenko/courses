# 🧮 Парадокс днів народження та розрахунок колізій у просторі 128 бітів

Щоб переконатися у надійності та безпеці використання ідентифікаторів без центрального координатора, інженер має спиратися не на інтуїтивне відчуття «128 бітів — це дуже багато», а на строгий апарат комбінаторики, теорії ймовірностей та асимптотичного аналізу. Цей розрахунок дає точне математичне виведення ймовірності виникнення дублікатів для випадкового UUIDv4 та часово впорядкованого UUIDv7, оцінює похибку наближень, обчислює середній час безвідмовної роботи глобального кластера та пояснює, чому реальні збої стаються не через брак розрядності, а через деградацію ентропії генераторів випадкових чисел.

### 1. Постановка задачі: дискретний парадокс днів народження

Нехай маємо дискретний простір можливих станів ідентифікатора потужністю `N`. Ми послідовно й незалежно генеруємо `n` ідентифікаторів, причому кожен новий вибір має рівномірний розподіл за всіма `N` варіантами (кожен стан вибирається з імовірністю `1/N`). Подія `A` полягає в тому, що всі `n` згенерованих значень виявляться попарно різними (жодної колізії в системі).

Для першого згенерованого значення доступні всі `N` варіантів з `N`. Для другого, щоб уникнути збігу з першим, залишається `N - 1` варіант. Для третього залишається `N - 2` варіанти. Для довільного `k`-го елемента залишається `N - (k - 1)` варіантів. За правилом множення ймовірностей для ланцюга незалежних випробувань дістаємо точну формулу ймовірності відсутності колізій:

```
P(A)
= (N / N) · ((N - 1) / N) · ((N - 2) / N) · … · ((N - (n - 1)) / N)   [правило добутку для незалежних виборів]
= 1 · (1 - 1/N) · (1 - 2/N) · … · (1 - (n - 1)/N)                      [почленне ділення кожного множника на N]
= ∏_{k=0}^{n-1} (1 - k/N)                                              [згортання у формальний символ добутку]
```

Ймовірність появи хоча б одного дубліката в наборі дорівнює ймовірності протилежної події:

```
P(колізії) = 1 - P(A) = 1 - ∏_{k=0}^{n-1} (1 - k/N)
```

### 2. Апроксимація через експоненту та оцінка похибки

Обчислювати точний добуток для великих чисел `n` і `N` складно через обмеження розрядності чисел із плаваючою комою. Скористаємося розкладом функції натурального логарифма `ln(1 - x)` у ряд Тейлора для малих значень аргументу `x = k/N << 1`:

```
ln(1 - x) = -x - x²/2 - x³/3 - … ≈ -x
1 - x ≈ exp(-x)
```

Підставивши експоненційне наближення `1 - k/N ≈ exp(-k/N)` у добуток для `P(A)`, отримуємо ланцюг перетворень:

```
P(A)
≈ ∏_{k=0}^{n-1} exp(-k / N)               [апроксимація Тейлора: 1 - x ≈ exp(-x)]
= exp(- ∑_{k=0}^{n-1} (k / N))           [властивість степеня: добуток експонент є експонентою суми]
= exp(- (1 / N) · ∑_{k=0}^{n-1} k)       [винесення спільного знаменника 1/N за знак суми]
= exp(- (1 / N) · (n · (n - 1) / 2))     [формула суми арифметичної прогресії: n·(n - 1)/2]
≈ exp(- n² / (2·N))                      [наближення для великих n: n·(n - 1) ≈ n²]
```

Залишковий член ряду Тейлора має порядок `O(n³ / N²)`. Оскільки для 128-бітного простору `N ≈ 5.3 × 10³⁶`, при будь-яких практичних значеннях `n < 10¹⁵` відносна похибка апроксимації не перевищує `10⁻²⁰`, що робить експоненційну формулу практично точною.

Таким чином, підсумкова ймовірність виникнення хоча б однієї колізії серед `n` згенерованих ключів виражається формулою:

```
P(колізії) ≈ 1 - exp(- n² / (2·N))
```

Коли ймовірність колізії мала (`n² << 2·N`), застосовуємо наближення першого порядку `1 - exp(-y) ≈ y`:

```
P(колізії) ≈ n² / (2·N)
```

### 3. Кількість ідентифікаторів для досягнення заданого порогу колізій

Виразимо кількість ключів `n`, необхідну для того, щоб імовірність появи хоча б одного дубліката досягла наперед заданого критичного значення `p`:

```
1 - exp(- n² / (2·N)) = p                [початкове рівняння для заданого порогу p]
exp(- n² / (2·N)) = 1 - p                [перенесення доданка]
- n² / (2·N) = ln(1 - p)                 [логарифмування обох частин рівності]
n² = 2·N · ln(1 / (1 - p))               [множення на -2·N з урахуванням ln(1/(1-p)) = -ln(1-p)]
n = √(2·N · ln(1 / (1 - p)))             [добування квадратного кореня]
```

Для класичного парадоксу днів народження з імовірністю колізії 50% (`p = 0.5`):

```
ln(1 / (1 - 0.5)) = ln(2) ≈ 0.693147
n_{50%} = √(2 · ln 2 · N) ≈ 1.1774 · √N
```

### 4. Числовий розрахунок для випадкового UUIDv4

У специфікації UUIDv4 зі 128 бітів 4 біти фіксовані під номер версії (`0100`), а 2 біти — під варіант (`10`). Це залишає рівно `128 - 4 - 2 = 122` біти вільної випадкової ентропії.

Повна потужність простору випадкових станів становить:

```
N = 2¹²² = 5 316 911 983 139 663 491 611 567 624 000 000 000 ≈ 5.317 × 10³⁶
```

Кількість ідентифікаторів для досягнення 50% шансу колізії:

```
n_{50%}
≈ 1.1774 · √(2¹²²)                       [підстановка N = 2¹²² у формулу n_{50%}]
= 1.1774 · 2⁶¹                           [добування кореня з парного степеня: √(2¹²²) = 2⁶¹]
≈ 1.1774 · 2.305843 × 10¹⁸               [обчислення 2⁶¹]
≈ 2.7149 × 10¹⁸                          [підсумкова кількість: понад 2.71 квінтильйона]
```

Оцінимо ймовірність колізії для типових масштабів інформаційних систем:

| Кількість збережених ключів `n` | Формула наближення `n² / (2·N)` | Розрахункова ймовірність `P` | Інженерний еквівалент ризику |
|:---|:---|:---|:---|
| `10⁶` (1 мільйон) | `(10⁶)² / (2 · 5.317 × 10³⁶)` | `≈ 9.40 × 10⁻²⁶` | Неможливо за час існування Всесвіту |
| `10⁹` (1 мільярд) | `(10⁹)² / (2 · 5.317 × 10³⁶)` | `≈ 9.40 × 10⁻²⁰` | Менше шансу виграти в лотерею 3 рази поспіль |
| `10¹²` (1 трильйон) | `(10¹²)² / (2 · 5.317 × 10³⁶)` | `≈ 9.40 × 10⁻¹⁴` | Менше ймовірності збою комірки RAM від космічних променів |
| `10¹⁵` (1 квадрильйон) | `(10¹⁵)² / (2 · 5.317 × 10³⁶)` | `≈ 9.40 × 10⁻⁸` | 1 шанс на 10.6 мільйона |

Якщо розподілений кластер із тисяч серверів генерує один мільярд UUIDv4 щосекунди безперервно протягом 100 років (`n ≈ 3.15 × 10¹⁸`), сумарна ймовірність знайти бодай один дублікат складе приблизно `60%`.

### 5. Розрахунок для UUIDv7 всередині однієї мілісекунди

У стандарті RFC 9562 для UUIDv7 старші 48 бітів відведено під мілісекундний час Unix Epoch. Якщо два ідентифікатори згенеровано в різні мілісекунди, вони гарантовано мають різні старші байти, тобто ймовірність колізії між ними строго дорівнює нулю (`P = 0`).

Колізія можлива виключно тоді, коли два незалежні сервери згенерували ідентифікатори всередині **однієї й тієї самої мілісекунди**. У межах одного часового слота UUIDv7 містить:
- 12 бітів субмілісекундної точності або лічильника (`rand_a`);
- 62 біти криптографічної випадковості (`rand_b`).

Разом це формує `12 + 62 = 74` біти незалежної ентропії на кожен 1-мілісекундний квант часу:

```
N_{slot} = 2⁷⁴ ≈ 1.8889 × 10²²
```

Поріг 50% колізій для генерації всередині однієї мілісекунди становить:

```
n_{slot, 50%} ≈ 1.1774 · √(2⁷⁴) = 1.1774 · 2³⁷ ≈ 1.618 × 10¹¹
```

Якщо глобальний сервіс витримує навантаження у `100 000` операцій на мілісекунду (100 мільйонів запитів на секунду):

```
P(колізії в слоті)
≈ (10⁵)² / (2 · 2⁷⁴)                     [підстановка n = 10⁵ та N = 2⁷⁴]
= 10¹⁰ / (3.77789 × 10²²)                [обчислення знаменника 2 · 2⁷⁴ = 2⁷⁵]
≈ 2.647 × 10⁻¹³                          [ймовірність за одну окрему мілісекунду]
```

Сумарна ймовірність колізії за цілу добу безперервної роботи під таким екстремальним навантаженням (`8.64 × 10⁷` мілісекунд на добу):

```
P_{day} ≈ 8.64 × 10⁷ · 2.647 × 10⁻¹³ ≈ 2.29 × 10⁻⁵
```

Це демонструє, що 74 біти ентропії у поєднанні з 48 бітами часу забезпечують повну безпеку навіть для найбільших розподілених систем планети.

### 6. Моделювання розподіленого кластера як пуассонівського процесу

Нехай система складається з `M` незалежних серверів, де кожен вузол генерує ідентифікатори за законом Пуассона з інтенсивністю `λ` ключів на секунду. Загальна інтенсивність генерації в кластері дорівнює `Λ = M · λ`.

Ймовірність колізії на інтервалі часу `t` описується інтегральною формою:

```
P(колізії за час t) ≈ 1 - exp(- (Λ · t)² / (2 · N))
```

Середній час безперебійної роботи системи до виникнення першої колізії (Mean Time to First Collision, MTTFC):

```
MTTFC ≈ √(π · N / (2 · Λ²)) = (1 / Λ) · √(π · N / 2)
```

Для системи генерації UUIDv4 із сумарною швидкістю `Λ = 1 000 000` ключів/с:

```
MTTFC ≈ (1 / 10⁶) · √(3.14159 · 5.317 × 10³⁶ / 2) ≈ 2.89 × 10¹² секунд ≈ 91 600 років.
```

### 7. Чому колізії насправді стаються у промислових системах

Усі математичні доведення спираються на припущення про ідеальний рівномірний розподіл і повну незалежність генераторів випадкових чисел. У реальному житті практично кожен випадок появи дублікатів UUID спричинений відхиленням від цих припущень:

1. **Деградація джерела ентропії (Entropy Collapse)**: якщо генератор використовує простий лінійний конгруентний генератор `rand()` або неініціалізований стан, ефективна ентропія падає з 122 бітів до 16–32 бітів. Для простору `N = 2³²` колізія очікується вже після генерації `n ≈ 1.1774 · 2¹⁶ ≈ 77 000` ключів.
2. **Клонування стану віртуальних машин (VM Snapshots)**: відновлення віртуальної машини або контейнера зі знімка пам'яті клонує внутрішній стан генератора випадкових чисел. Якщо генератор не переініціалізується після розгалуження, обидва екземпляри видають ідентичні послідовності чисел.
3. **Форк процесів (`fork()`) у Unix**: виклик `fork()` без наступного виклику `exec()` дублює стан псевдовипадкового генератора у дочірньому процесі, призводячи до гарантованої генерації дублікатів між процесами-нащадками.

Математична основа 128-бітного простору забезпечує неперевершений запас надійності, проте системний інженер зобов'язаний гарантувати криптографічну якість та ізоляцію джерел ентропії.
