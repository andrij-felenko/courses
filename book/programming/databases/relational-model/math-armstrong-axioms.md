# 🧮 Аксіоми Армстронга та обчислення замикання функціональних залежностей

У реляційній моделі даних коректність проектування та усунення надлишковості спираються на строгий математичний апарат функціональних залежностей. Цей формалізм дає змогу алгоритмічно визначити, які атрибути однозначно визначають інші, як знайти всі можливі кандидатні ключі таблиці, як побудувати мінімальне канонічне покриття залежностей та чи буде розбиття відношення на частини безвтратним.

## Означення функціональної залежності

Нехай задано схему відношення `R(A₁, A₂, ..., Aₙ)` як скінченну множину атрибутів `U = {A₁, A₂, ..., Aₙ}`, де кожен атрибут `Aᵢ` набуває значень із відповідного домену `dom(Aᵢ)`. Кортеж `t` — це функція, яка зіставляє кожному `Aᵢ ∈ U` значення `t[Aᵢ] ∈ dom(Aᵢ)`.

Нехай `X ⊆ U` та `Y ⊆ U` — підмножини атрибутів. Кажуть, що `Y` **функціонально залежить** від `X` (позначається `X → Y`), якщо для будь-якого допустимого екземпляра відношення `r(R)` і будь-яких двох кортежів `t₁, t₂ ∈ r` виконується умова:

```
t₁[X] = t₂[X]  ⇒  t₁[Y] = t₂[Y]
```

Множина `X` називається **детермінантом** (determinant), а `Y` — **залежною частиною** (dependent).

Якщо `Y ⊆ X`, залежність `X → Y` називають **тривіальною** (вона виконується автоматично для будь-якого відношення за визначенням проекції). Якщо `Y ⊄ X`, залежність є **нетривіальною**.

## Система аксіом Армстронга

У 1974 році Вільям Армстронг (William W. Armstrong) сформулював систему правил виводу для функціональних залежностей. Нехай `F` — задана множина залежностей над множиною атрибутів `U`. Замиканням множини залежностей `F⁺` називають множину всіх функціональних залежностей, які логічно випливають із `F`.

Система аксіом Армстронга складається з трьох базових правил:

### 1. Аксіома рефлексивності (Reflexivity)
Якщо `Y ⊆ X ⊆ U`, то `X → Y`.

**Доведення:**
Нехай `t₁, t₂ ∈ r` і `t₁[X] = t₂[X]`. Оскільки `Y` є підмножиною `X`, кожне значення атрибута `A ∈ Y` є також значенням атрибута з `X`. Отже, якщо всі атрибути з `X` збігаються для двох кортежів, то й їхня підмножина `Y` також обов'язково збігається: `t₁[Y] = t₂[Y]`.

### 2. Аксіома доповнення / нарощування (Augmentation)
Якщо `X → Y` та `Z ⊆ U`, то `XZ → YZ` (де `XZ` означає `X ∪ Z`).

**Доведення:**
Нехай `t₁, t₂ ∈ r` такі, що `t₁[XZ] = t₂[XZ]`. Це означає одночасне виконання двох рівностей: `t₁[X] = t₂[X]` та `t₁[Z] = t₂[Z]`.
За вихідною умовою `X → Y`, з `t₁[X] = t₂[X]` випливає `t₁[Y] = t₂[Y]`.
Поєднуючи рівності для `Y` та `Z`, отримуємо: `t₁[YZ] = t₂[YZ]`. Отже, `XZ → YZ`.

### 3. Аксіома транзитивності (Transitivity)
Якщо `X → Y` та `Y → Z`, то `X → Z`.

**Доведення:**
Нехай `t₁, t₂ ∈ r` такі, що `t₁[X] = t₂[X]`.
Оскільки `X → Y`, звідси маємо `t₁[Y] = t₂[Y]`.
Оскільки `Y → Z`, з `t₁[Y] = t₂[Y]` маємо `t₁[Z] = t₂[Z]`.
Таким чином, з `t₁[X] = t₂[X]` безпосередньо слідує `t₁[Z] = t₂[Z]`, тобто `X → Z`.

## Похідні правила виводу

На основі трьох базових аксіом строго виводяться допоміжні правила, які спрощують практичні аналітичні перетворення:

### Правило декомпозиції (розщеплення правої частини)
Якщо `X → YZ`, то `X → Y` та `X → Z`.

```
X → YZ
= X → YZ              [вихідна умова]
⇒ YZ → Y              [рефлексивність: Y ⊆ YZ]
⇒ X → Y               [транзитивність з X → YZ та YZ → Y]
```

Аналогічно доводиться `X → Z` через рефлексивність `YZ → Z`.

### Правило об'єднання (адитивності)
Якщо `X → Y` та `X → Z`, то `X → YZ`.

```
X → Y
⇒ XX → XY             [нарощування на X: X → XY]
= X → XY              [ідемпотентність об'єднання множин XX = X]
X → Z
⇒ XY → YZ             [нарощування на Y: XY → YZ]
⇒ X → YZ              [транзитивність з X → XY та XY → YZ]
```

### Правило псевдотранзитивності
Якщо `X → Y` та `WY → Z`, то `WX → Z`.

```
X → Y
⇒ WX → WY             [нарощування на W]
WY → Z
⇒ WX → Z              [транзитивність з WX → WY та WY → Z]
```

Система аксіом Армстронга має дві фундаментальні математичні властивості:
- **Коректність (Soundness):** Будь-яка залежність, виведена за допомогою цих аксіом, дійсно виконується в усіх відношеннях, де виконуються вихідні залежності `F`.
- **Повнота (Completeness):** Будь-яка залежність, що логічно слідує з `F`, може бути виведена скінченною послідовністю кроків за цими правилами.

## Алгоритм обчислення замикання множини атрибутів

Безпосереднє генерування всього повного замикання залежностей `F⁺` є обчислювально неефективним, оскільки кількість виведених залежностей може зростати експоненційно від кількості атрибутів `2^{|U|}`. На практиці для перевірки конкретної залежності `X → Y` або пошуку ключів застосовують швидкий поліноміальний алгоритм знаходження **замикання множини атрибутів** `X⁺` відносно множини залежностей `F`.

Замикання `X⁺` — це повна множина атрибутів `A ∈ U`, значення яких однозначно визначаються значеннями атрибутів `X` (тобто `X → A ∈ F⁺`).

### Алгоритм знаходження X⁺:
1. Ініціалізувати результат початковою множиною: `Closure = X`.
2. Повторювати доти, доки множина `Closure` змінюється:
   Для кожної функціональної залежності `W → V` із множини `F`:
   Якщо `W ⊆ Closure`, додати атрибути правої частини: `Closure = Closure ∪ V`.
3. Повернути `Closure` як підсумкове значення `X⁺`.

Часова складність цього алгоритму становить `O(|F| · |U|)` у простій реалізації та `O(|F|)` при використанні бітових масок атрибутів, що робить перевірку будь-якої залежності миттєвою.

### Покроковий приклад обчислення

Розглянемо схему навчального деканату:
`U = {StudentID, StudentEmail, CourseID, CourseTitle, ProfessorID, ProfessorName, Grade}`
Позначимо атрибути їхніми першими літерами: `U = {S, E, C, T, P, N, G}`.

Нехай задано множину функціональних залежностей `F`:
1. `S → E` (номер студента визначає адресу його пошти)
2. `C → T` (код навчального курсу визначає назву дисципліни)
3. `C → P` (курс веде конкретний призначений професор)
4. `P → N` (ідентифікатор професора визначає його повне ім'я)
5. `SC → G` (студент на конкретному курсі отримує фінальну оцінку)

Обчислимо замикання пари атрибутів `X = {S, C}`:

```
Крок 0: Closure = {S, C}

Ітерація 1:
  Перевірка S → E:   {S} ⊆ {S, C}             ⇒ Closure = {S, C, E}
  Перевірка C → T:   {C} ⊆ {S, C, E}          ⇒ Closure = {S, C, E, T}
  Перевірка C → P:   {C} ⊆ {S, C, E, T}       ⇒ Closure = {S, C, E, T, P}
  Перевірка P → N:   {P} ⊆ {S, C, E, T, P}    ⇒ Closure = {S, C, E, T, P, N}
  Перевірка SC → G:  {S, C} ⊆ {S, C, E, T, P, N} ⇒ Closure = {S, C, E, T, P, N, G}

Ітерація 2:
  Жодна залежність не може додати нових атрибутів.
  Кінець обчислення.
```

Результат: `{S, C}⁺ = {S, E, C, T, P, N, G} = U`.
Оскільки замикання `{S, C}⁺` охоплює всю універсальну множину `U`, набір `{S, C}` є **суперключем**. Перевірка підмножин показує: `{S}⁺ = {S, E} ≠ U` та `{C}⁺ = {C, T, P, N} ≠ U`. Отже, жодна власна підмножина не є суперключем, тому `{S, C}` є **мінімальним кандидатним ключем**.

## Канонічне (мінімальне) покриття множини залежностей

Перед виконанням нормалізації набір залежностей `F` спрощують до **канонічного покриття** `F_c`, яке містить мінімальну кількість залежностей без втрати виразної сили (`F_c⁺ = F⁺`).

Канонічне покриття `F_c` повинно задовольняти три умови:
1. Права частина кожної залежності містить рівно один атрибут (`X → A`).
2. У жодній залежності немає сторонніх (надлишкових) атрибутів у лівій частині (якщо `A ∈ X` і `(X \ {A}) → Y` випливає з `F`, то `A` видаляється з детермінанта).
3. У множині немає надлишкових залежностей (видалення будь-якої залежності зменшує замикання `F⁺`).

Алгоритм побудови канонічного покриття дозволяє автоматичним оптимізаторам баз даних скоротити кількість інваріантів, які СУБД зобов'язана перевіряти під час виконання транзакцій.

## Теорема Хіта: Критерій безвтратного з'єднання

Декомпозиція вихідної схеми `R(U)` на дві менші схеми `R₁(U₁)` та `R₂(U₂)` (де `U₁ ∪ U₂ = U`) називається **безвтратною** (lossless-join decomposition), якщо для будь-якого екземпляра відношення `r(R)` природне з'єднання його проекцій відновлює вихідні дані без виникнення хибних рядків-привидів:

```
π[U₁](r) ⋈ π[U₂](r) = r
```

### Формулювання та суть теореми Хіта:
Декомпозиція `(R₁, R₂)` є безвтратною відносно множини функціональних залежностей `F` тоді й лише тоді, коли перетин їхніх атрибутів функціонально визначає всі атрибути хоча б однієї з таблиць:

```
(U₁ ∩ U₂) → U₁   ∈ F⁺
       АБО
(U₁ ∩ U₂) → U₂   ∈ F⁺
```

Це означає, що спільні атрибути `U₁ ∩ U₂` обов'язково повинні утворювати суперключ для схеми `R₁` або для схеми `R₂`. Якщо ця умова порушується, операція `JOIN` неминуче згенерує декартове перемноження рядків із однаковими неключовими значеннями, повністю спотворивши зміст бізнес-інформації.

## Обчислювальна складність задач нормалізації

Теоретичні задачі реляційної алгебри мають чіткі межі обчислювальної складності:
- **Перевірка, чи є задана підмножина атрибутів суперключем:** Поліноміальна складність `O(|F| · |U|)`.
- **Перевірка, чи є задана підмножина кандидатним ключем:** Поліноміальна складність (перевірка суперключа для `X` та перевірка для всіх підмножин `X \ {A}`).
- **Пошук хоча б одного кандидатного ключа:** Поліноміальна складність через жадібне видалення надлишкових атрибутів з `U`.
- **Пошук УСІХ кандидатних ключів або пошук ключа мінімального розміру:** **NP-повна задача** (в загальному випадку вимагає перебору решітки підмножин).
- **Перевірка схеми на відповідність 3NF:** Поліноміальна задача, якщо відомі всі кандидатні ключі.
- **Синтез схеми у 3NF (алгоритм Бернштейна):** Поліноміальний алгоритм, який на основі канонічного покриття `F_c` гарантує збереження залежностей та безвтратність з'єднання за поліноміальний час.
