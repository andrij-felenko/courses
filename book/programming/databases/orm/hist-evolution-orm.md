# 🏛️ Еволюція ORM: від об'єктних СУБД до сучасних Data Mapper

Боротьба між об'єктно-орієнтованим моделюванням у пам'яті програм та реляційним зберіганням даних на диску триває понад чотири десятиліття. Розробники постійно шукали міст між світом вказівників, класів і спадкування та світом таблиць, ключів і реляційної алгебри.

Ця хроніка висвітлює переломні етапи розвитку технологій збереження даних: спробу замінити реляційні СУБД об'єктними базами у 1980-х роках, появу перших паттернів мапінгу від Мартіна Фаулера, злет Hibernate та ActiveRecord, а також сучасний ренесанс типобезпечних SQL-компіляторів.

---

### Епоха об'єктно-орієнтованих СУБД (1980–1990-ті)

У середині 1980-х років, із бурхливим розвитком мов Smalltalk та C++, інженери вважали, що реляційна модель Едгара Кодда застаріла. Виник рух створення чистих об'єктно-орієнтованих баз даних (Object-Oriented Database Management Systems, OODBMS).

Системи на зразок **GemStone (1986)**, **ObjectStore (1990)** та **Versant (1991)** дозволяли зберігати граф об'єктів безпосередньо у пам'яті диска, зберігаючи прямі вказівники на структури. Проте OODBMS зазнали комерційного та технологічного фіаско з таких причин:
1. **Відсутність декларативної мови запитів**: Навігація графом вручну ускладнювала побудову довільних аналітичних звітів та фільтрацій.
2. **Слабка підтримка конкурентності та оптимізації**: Реляційні СУБД (Oracle, IBM DB2, Informix) витратили мільйони доларів на розвиток вартісних оптимізаторів (Cost-Based Optimizers) та протоколів транзакцій (ARIES), що зробило їх значно швидшими та надійнішими.
3. **Прив'язка до мови програмування**: Дані, збережені у форматі C++ або Smalltalk, було неможливо прочитати іншими мовами.

### Стандартизація архітектурних патернів: Мартін Фаулер (2002)

Усвідомивши, що реляційні бази даних домінуватимуть десятиліттями, індустрія зосередилася на створенні проміжного шару відображення.

У 2002 році Мартін Фаулер опублікував фундаментальну працю *Patterns of Enterprise Application Architecture (PoEAA)*, де систематизував ключові патерни:
* **Active Record**: Об'єкт містить як дані одного рядка таблиці, так і методи взаємодії з базою (`save()`, `delete()`).
* **Data Mapper**: Шар, що відокремлює чисті об'єкти пам'яті (Domain Model) від схеми бази даних, унеможливлюючи витік SQL у бізнес-логіку.
* **Unit of Work**: Об'єкт, що відстежує всі модифікації за час сесії та координує запис змін єдиним транзакційним пакетом.
* **Identity Map**: Кеш першого рівня, що забезпечує унікальність інстансу об'єкта в пам'яті для одного первинного ключа.

### Епоха промислових ORM: Hibernate, ActiveRecord та SQLAlchemy (2001–2010)

Початок 2000-х років став золотим віком становлення сучасних ORM-фреймворків:

* **Hibernate (2001)**: Гевін Кінг (Gavin King) розробив Hibernate як протест проти повільної та надскладної специфікації EJB 2.0 Entity Beans у Java. Hibernate запропонував повноцінну реалізацію Data Mapper з підтримкою мови HQL (Hibernate Query Language), кешуванням другого рівня та ледачим завантаженням (Lazy Loading). Пізніше Hibernate ліг в основу офіційного стандарту JPA (Java Persistence API).
* **ActiveRecord у Ruby on Rails (2004)**: Девід Хейнемейєр Ханссон показав силу патерну Active Record, об'єднавши простоту Ruby з магією метапрограмування. Розробники отримали можливість писати `user.orders.where(status: 'paid')` без складних XML-файлів конфігурації.
* **SQLAlchemy (2005)**: Майк Байєр (Mike Bayer) створив для Python потужну модульну систему, яка розділила ORM на дві частини: низькорівневий генератор виразів (SQLAlchemy Core) та високорівневий Data Mapper з підтримкою Unit of Work.

### Хронологічна таблиця еволюції ORM

| Рік | Технологія / Інструмент | Парадигма | Ключовий внесок |
| :--- | :--- | :--- | :--- |
| **1986–1991** | GemStone, ObjectStore | OODBMS | Збереження графів об'єктів без таблиць |
| **2001** | Hibernate (Gavin King) | Data Mapper | HQL, Identity Map, основа для стандарту JPA |
| **2002** | Fowler PoEAA | Архітектурні патерни | Формалізація Active Record, Unit of Work |
| **2004** | Rails ActiveRecord | Active Record | Конвенція над конфігурацією (CoC), авто-мапінг |
| **2005** | SQLAlchemy | Core + Data Mapper | Гнучке поєднання реляційної алгебри та об'єктів |
| **2008** | Entity Framework | Data Mapper | Мова LINQ для строго типізованих SQL-виразів |
| **2019–тепер** | Prisma, Diesel, jOOQ | Type-Safe SQL / Schema-First | Генерація коду за схемою, захист від N+1 на етапі компіляції |

---

### Сучасний ренесанс: Type-Safe Builders та Schema-First підходи

Сучасні системи поступово відмовляються від класичних важких ORM на користь типобезпечних компіляторів запитів (jOOQ у Java, Diesel у Rust, Kysely та Prisma у TypeScript). Замість приховування реляційної моделі під громіздким шаром абстракції, сучасні інструменти дають розробнику повну потужність SQL із контролем типів і перевіркою коректності запитів на етапі компіляції програми.
