# 🧮 Графи серіалізовності та математичні критерії ізоляції

Ізоляція транзакцій гарантує, що результат паралельного виконання множини операцій буде еквівалентний деякому послідовному (*serial*) виконанню, у якому транзакції запускаються одна за одною без жодного перекриття в часі. Цей математичний апарат формалізує розклади транзакцій, визначає поняття конфліктної еквівалентності та доводить фундаментальну теорему про безконтурність графа конфліктів (*Precedence Graph*), що дає алгоритмічний критерій коректності ізоляції складності `O(|V| + |E|)`.

## Формалізація транзакцій та розкладів

Транзакція `T[i]` визначається як скінченна послідовність елементарних операцій читання, запису та термінальних операцій над множиною іменованих елементів даних `D = {X, Y, Z, ...}`:
- `r[i](X)` — транзакція `T[i]` читає елемент даних `X`.
- `w[i](X)` — транзакція `T[i]` записує елемент даних `X`.
- `c[i]` — транзакція `T[i]` успішно фіксується (*Commit*).
- `a[i]` — транзакція `T[i]` скасовується (*Abort*).

**Розклад (або історія виконання) `S`** над множиною транзакцій `T = {T[1], T[2], ..., T[n]}` — це частковий порядок операцій, який:
1. Містить усі операції кожної транзакції `T[i] ∈ T`.
2. Зберігає внутрішній порядок операцій у межах кожної окремої транзакції: якщо в `T[i]` операція `o[i, 1]` передує `o[i, 2]`, то в `S` виконується `o[i, 1] <[S] o[i, 2]`.

**Послідовний розклад (*Serial Schedule*) `S[serial]`** — це розклад, у якому операції різних транзакцій не перемішуються: для будь-яких двох транзакцій `T[i]` та `T[j]` або всі операції `T[i]` передують усім операціям `T[j]`, або навпаки.

## Конфліктна еквівалентність (Conflict Equivalence)

Дві послідовні операції `o[i]` та `o[j]` у розкладі `S` називаються **конфліктними**, якщо одночасно виконуються три умови:
1. Вони належать різним транзакціям: `i ≠ j`.
2. Вони звертаються до одного й того самого елемента даних `X`.
3. Щонайменше одна з них є операцією запису: `w[i](X)` або `w[j](X)`.

Існує три типи конфліктів:
- **Читання–Запис (RW / Anti-dependency)**: `r[i](X) <[S] w[j](X)` — транзакція `T[i]` читає версію до зміни, зробленої `T[j]`.
- **Запис–Читання (WR / True dependency)**: `w[i](X) <[S] r[j](X)` — транзакція `T[j]` читає значення, щойно записане `T[i]`.
- **Запис–Запис (WW / Output dependency)**: `w[i](X) <[S] w[j](X)` — транзакція `T[j]` перетирає запис `T[i]`.

Неконфліктні операції (два читання `r[i](X)` та `r[j](X)` або операції над різними змінними `r[i](X)` та `w[j](Y)`) комутують: їхня перестановка у розкладі не змінює кінцевого стану системи та результатів читань.

Два розклади `S[1]` та `S[2]` над однією множиною транзакцій називаються **конфліктно еквівалентними** (`S[1] ≡[c] S[2]`), якщо:
1. `S[1]` та `S[2]` складаються з однакових операцій.
2. Для кожної пари конфліктних операцій `(o[i], o[j])` їхній відносний порядок у `S[1]` та `S[2]` однаковий.

Розклад `S` називається **конфліктно серіалізовним (*Conflict Serializable, CSR*)**, якщо він конфліктно еквівалентний деякому послідовному розкладу `S[serial]`.

## Граф конфліктів (Precedence Graph)

Для розкладу `S` граф конфліктів (або граф попереднього виконання) — це орієнтований граф `G(S) = (V, E)`, де:
- **Множина вершин `V`**: усі зафіксовані транзакції розкладу `V = {T[1], T[2], ..., T[n]}`.
- **Множина орієнтованих дуг `E`**: дуга `T[i] → T[j]` існує тоді й лише тоді, коли в розкладі `S` існує операція `o[i] ∈ T[i]` та операція `o[j] ∈ T[j]`, які конфліктують, і `o[i] <[S] o[j]`.

Кожна дуга `T[i] → T[j]` означає обов'язкове часове зобов'язання: у будь-якому еквівалентному послідовному розкладі транзакція `T[i]` зобов'язана завершитися до того, як почнеться `T[j]`.

## Теорема конфліктної серіалізовності

**Теорема.** Розклад `S` є конфліктно серіалізовним тоді й лише тоді, коли його граф конфліктів `G(S)` є ациклічним (Directed Acyclic Graph, DAG), тобто не містить орієнтованих контурів.

### Доведення

**Необхідність (⇒):** Нехай розклад `S` є конфліктно серіалізовним, тобто `S ≡[c] S[serial]`.
Припустимо від супротивного, що в графі `G(S)` існує орієнтований контур довжини `k`:
```
T[1] → T[2] → T[3] → ... → T[k] → T[1]
```
З визначення дуги в `G(S)` випливає:
- Дуга `T[1] → T[2]` означає, що існує пара конфліктних операцій, де операція `T[1]` передує операції `T[2]`. Оскільки `S ≡[c] S[serial]`, у послідовному розкладі `S[serial]` транзакція `T[1]` мусить передувати `T[2]` (`T[1] <[serial] T[2]`).
- Аналогічно: `T[2] <[serial] T[3]`, ..., `T[k-1] <[serial] T[k]`.
- За транзитивністю порядку в `S[serial]` маємо: `T[1] <[serial] T[k]`.
- Проте остання дуга контуру `T[k] → T[1]` вимагає: `T[k] <[serial] T[1]`.

Отримуємо суперечність: `T[1] <[serial] T[1]`, що неможливо для строгого лінійного порядку послідовного розкладу. Отже, граф `G(S)` не може містити контурів.

**Достатність (⇐):** Нехай граф конфліктів `G(S)` не містить орієнтованих циклів (є DAG).
За фундаментальною властивістю скінченних DAG, для графа `G(S)` існує щонайменше одне топологічне сортування вершин — лінійний порядок `(T[π(1)], T[π(2)], ..., T[π(n)])`, такий що для будь-якої орієнтованої дуги `T[i] → T[j] ∈ E` вершина `T[i]` передує `T[j]` у сортуванні:
```
π⁻¹(T[i]) < π⁻¹(T[j])
```
Побудуємо послідовний розклад `S[serial]`, виконавши транзакції в порядку цього топологічного сортування:
```
S[serial] = T[π(1)] · T[π(2)] · ... · T[π(n)]
```
Перевіримо довільну пару конфліктних операцій `o[i] ∈ T[i]` та `o[j] ∈ T[j]`:
- Якщо в розкладі `S` операція `o[i] <[S] o[j]`, то за правилом побудови графа в `G(S)` існує дуга `T[i] → T[j]`.
- У топологічному сортуванні `T[i]` розташована раніше за `T[j]`, тому в `S[serial]` усі операції `T[i]` передують усім операціям `T[j]`, зокрема `o[i] <[serial] o[j]`.
- Оскільки взаємний порядок усіх конфліктних пар збігається, `S ≡[c] S[serial]`. Розклад `S` є конфліктно серіалізовним. ■

## Практичний розбір розкладу

Розглянемо паралельний розклад трьох транзакцій `T[1]`, `T[2]`, `T[3]` над змінними `A` та `B`:

```
Час    Транзакція T[1]       Транзакція T[2]       Транзакція T[3]
t1     r[1](A)
t2                           r[2](B)
t3     w[1](A)
t4                                                 r[3](A)
t5                           w[2](B)
t6                                                 w[3](B)
t7     c[1]
t8                           c[2]
t9                                                 c[3]
```

Визначимо всі пари конфліктних операцій між різними транзакціями:
1. `w[1](A)` (при `t3`) та `r[3](A)` (при `t4`):
   Змінна `A`, конфлікт типу WR, порядок `t3 < t4` → породжує дугу **`T[1] → T[3]`**.
2. `w[2](B)` (при `t5`) та `w[3](B)` (при `t6`):
   Змінна `B`, конфлікт типу WW, порядок `t5 < t6` → породжує дугу **`T[2] → T[3]`**.

Побудова графа конфліктів `G = (V, E)`:
```
V = {T[1], T[2], T[3]}
E = { (T[1] → T[3]), (T[2] → T[3]) }
```

Аналіз на ациклічність:
Граф містить лише дві дуги, що сходяться у вершині `T[3]`. Цикли відсутні.
Топологічні сортування графа:
- Варіант 1: `T[1] → T[2] → T[3]`
- Варіант 2: `T[2] → T[1] → T[3]`

Висновок: Розклад є повністю конфліктно серіалізовним. Будь-який із двох знайдених послідовних розкладів дасть точно такий самий кінцевий стан змінних `A` та `B`.

## Поглядова серіалізовність (View Serializability)

Конфліктна серіалізовність (CSR) є достатньою умовою для серіалізовності, але не абсолютно необхідною. Існує ширший клас — **поглядово серіалізовні розклади (*View Serializable, VSR*)**, які допускають циклічні конфлікти, якщо вони нівелюються «сліпими записами» (*Blind Writes*, операціями `w(X)` без попереднього `r(X)`).

Співвідношення класів коректності:
```
Serial ⊂ CSR ⊂ VSR ⊂ Усі можливі розклади
```

Чому всі промислові СУБД базуються виключно на конфліктній серіалізовності (CSR)?
- Перевірка конфліктної серіалізовності полягає у пошуку циклів у графі `G(S)` за допомогою алгоритму Кана або пошуку в глибину (DFS), що виконується за лінійний час:
```
Складність перевірки CSR = O(|V| + |E|)
```
- Перевірка ж належності до класу VSR є **NP-повною задачею** (зводиться до 3-SAT). Обчислювальна перевірка поглядової еквівалентності розкладу з кількома десятками транзакцій потребувала б мільярдів років процесорного часу.
