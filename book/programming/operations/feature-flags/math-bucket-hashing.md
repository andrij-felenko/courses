# 🧮 Математика детермінованого хешування і монотонної розкатки

Під час поступового розгортання функціональності (наприклад, увімкнення нової платіжної форми для 10% аудиторії або A/B-тестування п'яти варіантів рекомендаційного алгоритму) система повинна приймати рішення для кожного вхідного запиту. Зберігання списку активованих користувачів у централізованій базі даних вимагало б додаткового мережевого звернення, блокувань та масштабування сховища на кожен запит.

Математичне розв'язання полягає у **безстановому детермінованому розбитті на бакети** (англ. *stateless deterministic bucketing*). Спеціально сконструйована функція відображає ідентифікатор сутності та ключ прапорця в фіксований числовий простір, гарантуючи однорідність, незалежність, монотонність і швидкість обчислення без жодного рядка стану в базі даних.

## 1. Постановка задачі та формальні аксіоми

Нехай `U` — нескінченна або зліченна множина всіх можливих ідентифікаторів користувачів (рядки довільної довжини: UUID, цілі числа, рядкові логіни), а `F` — простір імен прапорців функцій. Для заданого прапорця `f ∈ F` та цільової частки розкатки `P ∈ [0, 100]` необхідно побудувати предикат включення:

```
E(f, u, P) : F × U × [0, 100] → {0, 1}
```

Предикат повинен строго задовольняти чотири інженерні аксіоми:

1. **Детермінізм (відтворюваність результату):** для фіксованих `f`, `u` та `P` значення `E(f, u, P)` є тотожно рівним у будь-який момент часу на будь-якому вузлі розподіленого кластера, незалежно від мови програмування, порядку запитів чи архітектури процесора.
2. **Однорідність (рівномірний розподіл):** імовірність потрапляння випадково обраного користувача `u` у вибірку розміром `P%` становить рівно `P / 100`:
   ```
   P(E(f, u, P) = 1) = P / 100
   ```
3. **Монотонність розкатки (відсутність миготіння):** якщо частку розкатки збільшують від `P₁` до `P₂` (`P₁ < P₂`), множина активованих користувачів для `P₁` є суворою підмножиною для `P₂`:
   ```
   { u ∈ U | E(f, u, P₁) = 1 } ⊂ { u ∈ U | E(f, u, P₂) = 1 }
   ```
4. **Статистична незалежність прапорців:** включення користувача у вибірку для прапорця `f₁` не корелює з його включенням для будь-якого іншого прапорця `f₂`:
   ```
   P(E(f₁, u, P₁) = 1 ∧ E(f₂, u, P₂) = 1) = (P₁ / 100) · (P₂ / 100)
   ```

## 2. Механіка псевдовипадкового бакетування через MurmurHash3

Для реалізації предиката застосовують некриптографічну хеш-функцію з сильним лавинним ефектом (англ. *avalanche effect*). Класичні поліноміальні хеші (наприклад, алгоритм `hashCode()` у Java, що обчислює суму `s[i] · 31^(n-1-i)`) непридатні для цієї задачі, оскільки на послідовних чи схожих рядках (наприклад, `user_1001`, `user_1002`, `user_1003`) вони створюють регулярні кластери та руйнують рівномірність.

Галузевим стандартом для обчислення бакетів є алгоритм **MurmurHash3 (32-bit x86)**. Він обробляє вхідний потік 4-байтними блоками, застосовуючи комбінацію множення на непарні константи та циклічних бітових зсувів:

```
c₁ = 0xcc9e2d51
c₂ = 0x1b873593

Для кожного 4-байтного блоку k:
k = k · c₁
k = ROTL₁₅(k)
k = k · c₂

h = h ⊕ k
h = ROTL₁₃(h)
h = h · 5 + 0xe6546b64
```

Після обробки всіх блоків виконується фіналізація перемішування бітів (*fmix32*), яка гарантує, що кожен вхідний біт впливає на кожен вихідний біт з імовірністю 50%:

```
h = h ⊕ (h >> 16)
h = h · 0x85ebca6b
h = h ⊕ (h >> 13)
h = h · 0xc2b2ae35
h = h ⊕ (h >> 16)
```

Результатом є беззнакове 32-бітне ціле число `h ∈ [0, 2³² - 1]`.

Далі число нормалізують у цілочисельний бакет у просторі `[0, 99]`:

```
bucket(f, u) = Hash32(f + ":" + u) mod 100
```

Предикат включення формулюється через просте порівняння:

```
E(f, u, P) = [ bucket(f, u) < P ]
```

## 3. Лавинні критерії якості хешування (SAC та BIC)

Математична придатність хеш-функції для динамічного бакетування оцінюється за двома строгими критеріями теорії псевдовипадкових послідовностей:

1. **Суворий лавинний критерій (Strict Avalanche Criterion, SAC):** інверсія будь-якого одного біта у вхідному векторі `x` повинна призводити до зміни кожного біта вихідного хешу `h` з імовірністю рівно `1/2`:
   ```
   P( h_j(x ⊕ e_i) ≠ h_j(x) ) = 0.5    ∀ i, j
   ```
   де `e_i` — одиничний вектор із одиницею в `i`-й позиції.
2. **Критерій незалежності бітів (Bit Independence Criterion, BIC):** для довільної зміни вхідного біта `i` зміни будь-яких двох вихідних бітів `j` та `k` є попарно незалежними випадковими величинами:
   ```
   P( Δh_j = 1 ∧ Δh_k = 1 ) = P( Δh_j = 1 ) · P( Δh_k = 1 ) = 0.25    ∀ j ≠ k
   ```

MurmurHash3 повністю задовольняє SAC та BIC, що запобігає виникненню прихованих гармонік або геометричних скупчень при хешуванні послідовних числових ID користувачів (`1`, `2`, `3`, ...).

## 4. Доведення монотонності розкатки

Вимога монотонності захищає користувацький досвід від явища «миготливої деградації». Якщо клієнт отримав оновлений інтерфейс кошика при 5% розкатки, то при збільшенні частки до 15% він гарантовано повинен залишитися на новому інтерфейсі.

**Теорема про монотонність:** Для будь-яких двох порогів розкатки `P₁` та `P₂` таких, що `0 ≤ P₁ ≤ P₂ ≤ 100`, для довільного користувача `u ∈ U` та прапорця `f ∈ F` виконується імплікація:
```
E(f, u, P₁) = 1  ⇒  E(f, u, P₂) = 1
```

**Формальне доведення:**
```
Крок 1. Припустимо, що предикат для початкового порогу є істинним:
        E(f, u, P₁) = 1

Крок 2. За конструкцією предиката це означає виконання числової нерівності:
        bucket(f, u) < P₁

Крок 3. За умовою теореми виконується співвідношення між порогами:
        P₁ ≤ P₂

Крок 4. Множина цілих чисел зі звичайним відношенням менше «<» є транзитивним простором:
        (a < b) ∧ (b ≤ c) ⇒ a < c

        Підставивши значення, отримуємо:
        bucket(f, u) < P₁ ≤ P₂  ⇒  bucket(f, u) < P₂

Крок 5. Нерівність bucket(f, u) < P₂ за означенням еквівалентна:
        E(f, u, P₂) = 1
```

Теорему доведено. Властивість монотонності гарантує, що множина активованих суб'єктів розширюється концентрично без випадання вже включених користувачів.

## 5. Доведення статистичної незалежності солей

Якщо в системі одночасно працюють два експерименти з ключами `f₁` та `f₂`, їхні вибірки не повинні корелювати між собою. Наприклад, включення користувача в експеримент нової форми реєстрації не повинно збільшувати чи зменшувати ймовірність його потрапляння в експеримент нової пошукової видачі.

Розглянемо дві випадкові величини бакетів для одного користувача `u`:
```
B₁ = bucket(f₁, u) = Hash32(f₁ + ":" + u) mod 100
B₂ = bucket(f₂, u) = Hash32(f₂ + ":" + u) mod 100
```

Оскільки рядок `f₁ + ":" + u` відрізняється від `f₂ + ":" + u` щонайменше префіксом (`f₁ ≠ f₂`), лавинний ефект хеш-функції перетворює бітові послідовності на незалежні псевдовипадкові вектори.

Для дискретних випадкових величин умова незалежності має вигляд:
```
P(B₁ = i ∧ B₂ = j) = P(B₁ = i) · P(B₂ = j) = (1 / 100) · (1 / 100) = 1 / 10 000
```

Для будь-яких двох порогів розкатки `P₁` та `P₂`:
```
P(E(f₁, u, P₁) = 1 ∧ E(f₂, u, P₂) = 1)
= P(B₁ < P₁ ∧ B₂ < P₂)                              [підстановка предиката: E(f,u,P)=1 ⇔ B < P]
= ∑_{i=0}^{P₁-1} ∑_{j=0}^{P₂-1} P(B₁ = i ∧ B₂ = j)   [аксіома адитивності для несумісних подій]
= ∑_{i=0}^{P₁-1} ∑_{j=0}^{P₂-1} (1 / 10 000)         [незалежність солей: P(B₁=i ∧ B₂=j) = 1/10000]
= P₁ · P₂ / 10 000                                   [підсумовування P₁ · P₂ однакових доданків]
= (P₁ / 100) · (P₂ / 100)                            [факторизація в добуток окремих імовірностей]
```

Це доводить, що застосування унікального імені прапорця як солі усуває систематичне зміщення між паралельними експериментами.

## 6. Багатовимірне розбиття: мультиваріантні експерименти

Якщо замість бінарного ввімкнення (`ON/OFF`) проводиться A/B/n-тестування кількох варіантів (наприклад, варіант `A` — 20%, варіант `B` — 30%, контрольна група `Control` — 50%), простір бакетів розбивають на неперетинні напівінтервали.

Нехай задано `K` варіантів `{V₀, V₁, ..., V_{K-1}}` із цілочисельними вагами `{w₀, w₁, ..., w_{K-1}}` такими, що:

```
∑_{i=0}^{K-1} w_i = 100,    де w_i ≥ 0
```

Визначають межі накопичувальної суми (кумулятивні пороги):

```
C_0 = 0
C_j = ∑_{i=0}^{j-1} w_i    для j ∈ {1, 2, ..., K}
```

Користувач `u` відноситься до варіанта `V_j` тоді й тільки тоді, коли його бакет потрапляє у відповідний напівінтервал:

```
AssignVariant(f, u) = V_j  ⇔  C_j ≤ bucket(f, u) < C_{j+1}
```

**Приклад розбиття 100 бакетів:**
* Варіант `Control` (вага 50): бакети `[0, 49]` (50 бакетів);
* Варіант `Alg_A` (вага 25): бакети `[50, 74]` (25 бакетів);
* Варіант `Alg_B` (вага 25): бакети `[75, 99]` (25 бакетів).

Оскільки напівінтервали `[C_j, C_{j+1})` утворюють повне розбиття відрізка `[0, 100)`:
```
⋃_{j=0}^{K-1} [C_j, C_{j+1}) = [0, 100)    і    [C_i, C_{i+1}) ∩ [C_j, C_{j+1}) = ∅ для i ≠ j
```

Кожен користувач однозначно і детерміновано отримує рівно один варіант без перекриттів і дірок.

## 7. Аналіз зміщення залишку (Modulo Bias)

Обчислення залишку від ділення `h mod 100` на 32-бітному просторі потенційно несе мікроскопічну похибку, оскільки `2³²` не є кратним `100`:

```
2³² = 4 294 967 296
4 294 967 296 = 42 949 672 × 100 + 96
```

Це означає, що значення хешу від `0` до `95` мають рівно `42 949 673` прообразів у просторі `[0, 2³² - 1]`, тоді як значення від `96` до `99` мають `42 949 672` прообрази (на один менше).

Обчислимо точну ймовірність потрапляння в бакети обох типів:

```
P(bucket = k) = 42 949 673 / 4 294 967 296 ≈ 0.0100000002328    для k ∈ [0, 95]
P(bucket = k) = 42 949 672 / 4 294 967 296 ≈ 0.0099999999999    для k ∈ [96, 99]
```

Максимальна абсолютна похибка ймовірності:

```
ε_bias = |0.0100000002328 - 0.01| ≈ 2.328 × 10⁻¹⁰
```

Відхилення у дві десятимільярдні частки відсотка неможливо виявити навіть на мільярдних вибірках користувачів. Проте у високонавантажених бібліотеках із суворими вимогами до точності для усунення навіть теоретичного зміщення виконують нормалізацію діленням з рухомою комою подвійної точності (IEEE 754 float64):

```
score(f, u) = (h as Float64) / 4294967296.0
E(f, u, P)  = [ score(f, u) < (P / 100.0) ]
```

Оскільки мантиса `Float64` має 53 біти точності, 32-бітне ціле число `h` перетворюється в дійсне число без жодної втрати розрядів.

## 8. Перевірка рівномірності: критерій згоди Пірсона (Chi-Square Test)

Щоб довести якість хеш-розбиття на практиці, застосовують статистичний критерій згоди Пірсона (χ²-тест).

Нехай `N` користувачів розподілено по `M = 10` бакетах (кожен розміром 10%). Теоретична очікувана кількість спостережень у кожному бакеті становить:

```
E_k = N / M = N / 10
```

Нехай `O_k` — фактична кількість користувачів, які потрапили в `k`-й бакет. Статистика Пірсона обчислюється за формулою:

```
χ² = ∑_{k=0}^{M-1} ( (O_k - E_k)² / E_k )
```

Величина `χ²` має розподіл хі-квадрат із ступенями вільності `df = M - 1 = 9`.

**Числовий розрахунок для вибірки N = 10 000 користувачів:**

| Бакети (частка) | Очікувано (E_k) | Фактично (O_k) | Різниця (O_k - E_k) | (O_k - E_k)² / E_k |
|---|---|---|---|---|
| 0% – 10% | 1 000 | 1 018 | +18 | 0.324 |
| 10% – 20% | 1 000 | 985 | -15 | 0.225 |
| 20% – 30% | 1 000 | 1 012 | +12 | 0.144 |
| 30% – 40% | 1 000 | 994 | -6 | 0.036 |
| 40% – 50% | 1 000 | 1 005 | +5 | 0.025 |
| 50% – 60% | 1 000 | 978 | -22 | 0.484 |
| 60% – 70% | 1 000 | 1 024 | +24 | 0.576 |
| 70% – 80% | 1 000 | 991 | -9 | 0.081 |
| 80% – 90% | 1 000 | 1 008 | +8 | 0.064 |
| 90% – 100% | 1 000 | 985 | -15 | 0.225 |
| **Сума** | **10 000** | **10 000** | **0** | **χ² = 2.184** |

Для 9 ступенів вільності та критичного рівня значущості `α = 0.05` критичне значення розподілу з таблиці становить `χ²_крит = 16.919`.

Оскільки розраховане значення `χ² = 2.184` значно менше за критичне `16.919` (p-value ≈ 0.988), нульова гіпотеза про рівномірність розподілу приймається з високим запасом статистичної достовірності.

## 9. Дисперсія та розрахунок мінімального розміру вибірки

Фактична частка трафіку `p̂ = K / N`, що проходить через нову гілку, коливається навколо заданого відсотка `p = P / 100` через випадковий характер надходження запитів. Кількість користувачів `K` описується біноміальним розподілом:

```
K ~ Binomial(N, p)
E[K] = N · p
Var(K) = N · p · (1 - p)
```

Стандартна похибка вибірки (англ. *Standard Error*):

```
SE(p̂) = √( p · (1 - p) / N )
```

95%-й довірчий інтервал для спостережуваної частки:

```
Довірчий інтервал = p ± 1.96 · √( p · (1 - p) / N )
```

Під час A/B-тестування критичним завданням є визначення **мінімального розміру вибірки (N)** для статистично значущого виявлення мінімального очікуваного ефекту (англ. *Minimum Detectable Effect*, `MDE = δ`).

Для дворівневого Z-тесту з рівнем значущості `α = 0.05` (`Z_{α/2} = 1.96`) та статистичною потужністю `1 - β = 0.80` (`Z_β = 0.84`) мінімальна кількість користувачів у кожній групі розраховується за формулою:

```
N_group = 2 · (Z_{α/2} + Z_β)² · p · (1 - p) / δ²
```

**Практичний розрахунок для базової конверсії p = 5% (p = 0.05) та очікуваного приросту δ = 0.5% (абсолютні 0.005):**

```
N_group
= 2 · (1.96 + 0.84)² · 0.05 · (1 - 0.05) / (0.005)²  [підстановка: Z_{α/2}=1.96, Z_β=0.84, p=0.05, δ=0.005]
= 2 · (2.80)² · 0.0475 / 0.000025                   [додавання квантилей та обчислення p(1-p)]
= 2 · 7.84 · 0.0475 / 0.000025                       [піднесення до квадрата: 2.80² = 7.84]
= 0.7448 / 0.000025                                  [множення в чисельнику: 2 · 7.84 · 0.0475]
= 29 792                                             [ділення: користувачів у кожній групі]
```

Загальний обсяг експерименту вимагає щонайменше `59 584` користувачів. Якщо добовий трафік системи становить 10 000 унікальних користувачів, для надійного підтвердження результатів експеримент повинен тривати не менше 6 днів.

## 10. Зменшення дисперсії за методом CUPED

Коли розмір вибірки обмежений, час проведення A/B-експерименту можна скоротити за допомогою математичної техніки **CUPED** (Controlled-experiment Using Pre-Experiment Data).

Нехай `Y` — цільова метрика користувача під час експерименту (наприклад, сума покупок), а `X` — та сама метрика користувача за період **до** початку експерименту (коваріанта). Нова скоригована метрика `Y_cuped` конструюється як:

```
Y_cuped = Y - θ · (X - E[X])
```

Коефіцієнт `θ` підбирають так, щоб мінімізувати дисперсію `Var(Y_cuped)`:

```
Var(Y_cuped) = Var(Y) + θ² · Var(X) - 2 · θ · Cov(Y, X)
```

Взявши похідну за `θ` та прирівнявши її до нуля:

```
d/dθ Var(Y_cuped) = 2 · θ · Var(X) - 2 · Cov(Y, X) = 0
θ = Cov(Y, X) / Var(X)
```

Підставивши оптимальне значення `θ`, отримуємо мінімальну дисперсію:

```
Var(Y_cuped) = Var(Y) · (1 - ρ²)
```

Тут `ρ = Cov(Y, X) / (σ_Y · σ_X)` — коефіцієнт лінійної кореляції Пірсона між поведінкою користувача до експерименту та під час нього.

Якщо кореляція `ρ = 0.7` (типове значення для повторних покупок або щоденної активності), дисперсія метрики падає на `1 - (0.7)² = 1 - 0.49 = 51%`. Згідно з формулою розрахунку вибірки, зменшення дисперсії вдвічі скорочує необхідну кількість користувачів та тривалість експерименту рівно в **2 рази**.

## 11. Послідовне тестування та запобігання Peeking-проблемі (SPRT)

Класичний фіксований Z-тест вимагає суворого правила: метрики не можна аналізувати до завершення накопичення розрахованої вибірки `N`. Якщо інженер щодня перевіряє p-value («підглядання» або англ. *peeking problem*) і зупиняє експеримент при першому досягненні `p < 0.05`, реальна ймовірність помилки першого роду (хибнопозитивного результату) зростає з 5% до понад 30%.

Для безпечного неперервного моніторингу прапорців застосовують **послідовний критерій відношення ймовірностей Вальда (Sequential Probability Ratio Test, SPRT)**.

Нехай спостереження надходять послідовно: `x₁, x₂, ..., x_n`. На кожному кроці `n` обчислюють логарифмічне відношення правдоподібності:

```
Λ_n = ∑_{i=1}^n ln( f(x_i | H₁) / f(x_i | H₀) )
```

де `H₀` — нульова гіпотеза (відсутність різниці), `H₁` — альтернативна гіпотеза з ефектом `δ`.

Межі зупинки Вальда визначаються через задані ймовірності помилок `α` та `β`:

```
A = ln( (1 - β) / α )      [верхня межа: прийняти H₁ і зупинити тест]
B = ln( β / (1 - α) )      [нижня межа: прийняти H₀ і зупинити тест]
```

Правило ухвалення рішень на кожному запиті:
1. Якщо `Λ_n ≥ A` — нова версія статистично краща; фічу можна безпечно розкочувати на 100% достроково.
2. Якщо `Λ_n ≤ B` — нова версія не дає ефекту або шкідлива; експеримент зупиняють (відкат).
3. Якщо `B < Λ_n < A` — даних недостатньо; збір трафіку продовжується.

SPRT зберігає строгий рівень помилки `α` за будь-якої частоти перевірок і скорочує середній час виявлення сильних дефектів чи переможців у середньому на 30–50% порівняно з тестами фіксованого розміру.
