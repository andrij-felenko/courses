# Від HAKMEM до Hacker's Delight: історія бітових трюків

Сьогодні побітові операції сприймаються як базовий інструментарій будь-якої мови програмування. Проте в перші десятиліття розвитку обчислювальної техніки маніпуляція окремими розрядами була справжнім мистецтвом, народженим із суворих апаратних обмежень. Пам'ять ЕОМ вимірювалася кілобайтами, тактова частота процесорів не перевищувала кількох мегагерців, а дорогі операції множення та ділення могли забирати десятки машинних тактів.

У цих умовах винахідливі інженери та математики почали шукати нетривіальні комбінації логічних та арифметичних інструкцій, які дозволяли виконувати складні обчислення за лічені такти без умовних переходів та циклів.

![Еволюція бітових операцій: від PDP-10 до апаратних інструкцій](/book/programming/computer-architecture/bitwise-operations/img/hakmem-timeline.svg)
*Еволюція бітових маніпуляцій. Шлях від лабораторного звіту лабораторії штучного інтелекту MIT (1972) через супероптимізатори та енциклопедію Генрі Воррена до сучасних кремнієвих інструкцій BMI2 та RISC-V Zbb.*

### 1972: Легендарний звіт HAKMEM у лабораторії штучного інтелекту MIT

29 лютого 1972 року Лабораторія штучного інтелекту Массачусетського технологічного інституту (MIT AI Lab) опублікувала звіт **AI Memo No. 239**, який увійшов в історію під назвою **HAKMEM** (*Hacks Memo*). Його авторами були легендарні дослідники Майкл Білер (Michael Beeler), Ральф Вільям Госпер (R. William Gosper) та Річ Шреппель (Rich Schroeppel).

Дослідження проводилися на комп'ютерах **PDP-6** та **PDP-10** компанії Digital Equipment Corporation (DEC), які працювали під керуванням операційної системи ITS (Incompatible Timesharing System). Ці машини мали незвичну для сучасного програміста архітектуру: машинне слово складалося з **36 бітів**, а в системі команд була присутня багата палітра логічних та умовних інструкцій.

Звіт HAKMEM являв собою неформальну збірку математичних задач, оптимізаційних хаків, геометричних алгоритмів та коротких асемблерних фрагментів. Саме в ньому вперше в історії з'явилися класичні бітові перлини, якими ми користуємося донині:

- **Пункт 169 (Item 169):** формулювання виразу `x & -x` для виділення наймолодшого встановленого біта числа в додатковому коді. Автори помітили, що арифметика доповнення до двійки автоматично інвертує старші біти та створює хвилю переносу, залишаючи недоторканим лише молодший одиничний біт.
- **Пункт 175 (Item 175):** паралельний алгоритм підрахунку одиничних бітів у 36-бітному слові (попередник сучасного паралельного суматора popcount), який згортав сусідні біти за допомогою масок `0b010101...`, `0b00110011...` та множення без жодного циклу.
- **Пункт 173 (Gosper's Hack):** знаменитий алгоритм Вільяма Госпера для генерації наступного за величиною числа з тією самою кількістю одиничних бітів. Алгоритм розв'язував задачу перебору комбінацій без рекурсії за допомогою виразів `x & -x` та зсувів:

:::tabs
```c
#include <stdint.h>

// Генерація наступного числа з тією самою кількістю одиничних бітів (Gosper's Hack)
uint64_t next_combination(uint64_t x) {
    uint64_t smallest = x & -x;             // виділити молодший встановлений біт
    uint64_t ripple = x + smallest;         // викликати перенос через групу одиниць
    uint64_t ones = x ^ ripple;             // знайти змінені біти
    ones = (ones >> 2) / smallest;          // вирівняти молодші одиниці праворуч
    return ripple | ones;
}
```
```cpp
#include <cstdint>

[[nodiscard]] constexpr std::uint64_t next_combination(std::uint64_t x) noexcept {
    const std::uint64_t smallest = x & -x;
    const std::uint64_t ripple = x + smallest;
    const std::uint64_t ones = x ^ ripple;
    return ripple | ((ones >> 2U) / smallest);
}
```
:::

Цей алгоритм Gosper's Hack став основою для швидкого моделювання клітинних автоматів (зокрема, славетної гри «Життя» Джона Конвея, де Вільям Госпер відкрив першу стабільну фабрику планерів — Gosper Glider Gun).

### Шахові бітборди та народження паралельного мислення

Окремим потужним рушієм розвитку бітових алгоритмів стали шахові програми 1970-х років. Шахівниця складається рівно з 64 клітин (8 × 8), що ідеально відповідало розрядності нових суперкомп'ютерів (зокрема, 64-бітних мейнфреймів Cray).

1975 року розробники програми Kaissa (першого чемпіона світу серед шахових програм) та автори американської програми Chess 4.5 (Девід Слейт і Ларрі Аткін) запровадили концепцію **бітбордів** (*bitboards*). Замість зберігання шахівниці як масиву з 64 об'єктів стан фігур кодувався набором 64-бітних цілих чисел: бітборд білих пішаків, бітборд чорних коней, маска атакованих полів.

Усі правила пересування фігур перетворилися на чисті побітові операції:
- Зсув бітборда пішаків на 8 позицій вперед `pawns << 8` генерував усі можливі ходи пішаків за один такт процесора;
- Атаки пішаків вліво та вправо обчислювалися як `(pawns << 7) & ~FILE_H_MASK` та `(pawns << 9) & ~FILE_A_MASK`;
- Виявлення зв'язаних фігур та шахів здійснювалося через побітове І з масками променів.

Бітборди перетворили складний просторовий аналіз гри на надшвидку розрядну логіку, визначивши архітектуру шахових рушіїв на півстоліття вперед.

### 1987: Алексія Массалін та винахід супероптимізатора

У другій половині 1980-х років дослідниця Колумбійського університету **Алексія Массалін** (Alexia Massalin) запропонувала революційну концепцію: замість того, щоб людина вручну шукала оптимальні послідовності інструкцій шляхом інтуїтивних здогадок, нехай комп'ютер знаходить їх автоматично через повний перебір у просторі команд.

1987 року вона опублікувала фундаментальну статтю *«Superoptimizer: A Look at the Smallest Program»* на престижній конференції ASPLOS II. Супероптимізатор Массалін брав коротку функцію (наприклад, обчислення знака числа `signum(x)` або модуля `abs(x)`) і перебирав усі можливі послідовності машинних інструкцій цільового процесора довжиною 1, 2, 3, 4 команди, перевіряючи їхню еквівалентність за допомогою тестових векторів та формальної верифікації.

Результати вразили комп'ютерну спільноту. Супероптимізатор виявив неочевидні алгоритми, до яких люди не могли додуматися роками. Зокрема, він знайшов спосіб обчислення функції знака `signum(x)` (повертає -1 для від'ємних, 0 для нуля і +1 для додатних) усього за три інструкції для процесора Motorola 68000 без жодного умовного переходу `branch`:

```
signum(x):
    add.l  d0, d0       ; зсув знакового біта у прапорець переносу (CF)
    subx.l d1, d1       ; d1 = -CF (-1 якщо x < 0, інакше 0)
    negx.l d0           ; d0 = 1 якщо x > 0, 0 якщо x == 0
    add.l  d1, d0       ; результат: -1, 0 або +1
```

Массалін показала, що в просторі коротких програм ховаються геніальні математичні спрощення, недосяжні для класичних евристичних оптимізаторів. Її ідеї заклали фундамент сучасного синтезу програм, формальної еквівалентності коду та проекту Souper у компіляторі LLVM.

### Легенда тривимірної графіки: швидкий обернений квадратний корінь

На стику бітових маніпуляцій та математики чисел із рухомою комою у 1990-х роках народився ще один шедевр — алгоритм **Fast Inverse Square Root** (`1 / sqrt(x)`), що здобув всесвітню славу після публікації вихідного коду рушія Quake III Arena (1999) Джона Кармака (хоча його витоки сягають досліджень Грега Волша в Arдент Computer та Гарі Тароллі у 3dfx Interactive).

Для розрахунку освітлення та нормалей 3D-моделей потрібна нормалізація векторів, яка впиралася у надзвичайно повільну команду апаратного ділення на корінь `FDIV / FSQRT`. Алгоритм Кармака трактував біти 32-бітного `float` як ціле число `int32_t`, віднімав його від «магічної константи» `0x5f3759df` та робив один зсув вправо:

:::tabs
```c
#include <stdint.h>
#include <string.h>

float fast_inv_sqrt(float number) {
    int32_t i;
    float x2, y;
    x2 = number * 0.5f;
    y  = number;
    memcpy(&i, &y, sizeof(i));                  // безпечне копіювання бітів без strict aliasing
    i  = 0x5f3759df - (i >> 1);                 // магічний бітовий зсув
    memcpy(&y, &i, sizeof(y));
    y  = y * (1.5f - (x2 * y * y));             // 1 ітерація методу Ньютона-Рафсона
    return y;
}
```
```cpp
#include <cstdint>
#include <bit>

[[nodiscard]] constexpr float fast_inv_sqrt(float number) noexcept {
    const float x2 = number * 0.5F;
    std::int32_t i = std::bit_cast<std::int32_t>(number);
    i = 0x5f3759df - (i >> 1U);
    float y = std::bit_cast<float>(i);
    y = y * (1.5F - (x2 * y * y));              // уточнення методом Ньютона
    return y;
}
```
:::

Цей алгоритм спирався на те, що бітова розкладка стандарту IEEE-754 (де порядок логарифмічно кодує степінь двійки) перетворює цілочисловий зсув вправо `i >> 1` на ділення логарифма числа навпіл, тобто на видобування квадратного кореня у логарифмічному просторі.

### 2002: Генрі Воррен та «Hacker's Delight»

Упродовж тридцяти років бітові трюки передавалися як усний фольклор у середовищі системних програмістів, авторів компіляторів, криптографів та розробників графічних рушіїв. Цю ситуацію змінив **Генрі С. Воррен молодший** (Henry S. Warren, Jr.), ветеран компанії IBM, який присвятив понад 40 років дослідженню архітектури ЕОМ та оптимізації компіляторів для систем IBM System/370 та PowerPC.

2002 року видавництво Addison-Wesley опублікувало його монументальну працю **«Hacker's Delight»** (у перекладі — «Радість хакера»). Воррен систематизував розрізнений інженерний досвід, дав суворе алгебраїчне обґрунтування сотням бітових операцій та звів їх у єдину енциклопедію:
- швидкому цілочисловому діленню на сталі через множення на магічні множники (*magic multiplier*) та правий зсув;
- порозрядному підрахунку нулів та одиниць (CLZ, CTZ, POPCOUNT);
- обчисленню бітових перестановок, бітового реверсу та кодів Грея;
- алгоритмам пошуку першого вільного слота в бітових картах пам'яті операційних систем;
- ефективній реалізації циклічних надлишкових кодів (CRC) та контролю парності.

Сам Дональд Кнут (Donald Knuth) високо оцінив працю Воррена, включивши детальний огляд бітових трюків до четвертого тому своєї класичної монографії «The Art of Computer Programming» (том 4A, розділ «Bitwise Tricks & Techniques»).

### 2010–2020-ті: Перехід бітових алгоритмів у кремній

На початку XXI століття природа обчислень зазнала кардинальних змін. Зростання тактових частот процесорів вперлося в тепловий бар'єр, а глибина конвеєрів суперскалярних ядер досягла 20–30 стадій. У цих умовах будь-який умовний перехід, передбачений неправильно блоком Branch Target Buffer, викликав скидання всього конвеєра та втрату десятків тактів.

Потреба в безрозгалужених бітових маніпуляціях стала настільки критичною, що архітектори провідних чипмейкерів вирішили перенести найуспішніші програмні трюки прямо в апаратну логіку процесорів:

1. **Історичний слід POPCNT:** Інструкція підрахунку одиничних бітів (`POPCNT`) довгий час була таємницею військових суперкомп'ютерів (вона була реалізована в Seymour Cray CDC 6600 та Cray-1 для аналізу криптограм Агентства національної безпеки США NSA). 2008 року Intel інтегрувала `POPCNT` у масову архітектуру Nehalem (SSE4.2).
2. **Intel та AMD (2013, архітектури Haswell та Excavator):**
   Впровадження наборів інструкцій **BMI1** та **BMI2** (*Bit Manipulation Instructions*). Інструкція `BLSI` реалізувала трюк HAKMEM `x & -x` за 1 такт, а `BLSR` — трюк `x & (x - 1)`. З'явилися матричні інструкції `PEXT` (*Parallel Extract*) та `PDEP` (*Parallel Deposit*), які дозволяють за 1 такт зібрати або розкидати довільні розсіяні біти за бітовою маскою (що революціонізувало шахові рушії на зразок Stockfish та синтаксичні парсери JSON на кшталт simdjson).
3. **ARM (ARMv8-A / AArch64):**
   Включення інструкцій `CLZ` (*Count Leading Zeros*), `RBIT` (*Reverse Bits*), `BFI` (*Bit Field Insert*), `UBFX` (*Unsigned Bit Field Extract*) як обов'язкової частини базового набору 64-бітної архітектури.
4. **RISC-V (2021, розширення Zbb / Zba / Zbc / Zbs):**
   Офіційна стандартизація групи бітових розширень для відкритої архітектури RISC-V: прямі інструкції встановлення (`bset`), скидання (`bclr`), інверсії (`binv`), витягування (`bext`), логічні операції з інверсією (`andn`, `orn`, `xnor`) та циклічний зсув (`ror`, `rol`).

Таким чином, математичні знахідки, записані ентузіастами MIT 1972 року на перфокартах та роздруківках комп'ютера PDP-10, за півстоліття подолали шлях від лабораторних хаків до кремнієвих вентилів мільярдів сучасних смартфонів, серверів та мікроконтролерів.
