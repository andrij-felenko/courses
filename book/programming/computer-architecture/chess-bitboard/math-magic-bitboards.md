# 🧮 Математичні основи Magic Bitboards та ідеального хешування

У задачах дискретного моделювання на двовимірних ґратках (зокрема на шахівниці `8×8`) обчислення доступних траєкторій для лінійних об'єктів зводиться до задачі поширення променів із зупинкою на першій перешкоді. Прямий обхід променя вздовж векторів напрямку вимагає ітераційного циклу. Метод магічних бітбордів (*Magic Bitboards*) розв'язує цю задачу за сталий час `O(1)` за допомогою безелезійного ідеального хешування скінченної множини розріджених бітових конфігурацій.

---

### Постановка математичної задачі

Нехай клітинки шахівниці пронумеровані індексами `s ∈ {0, 1, ..., 63}`. Стан зайнятості всієї дошки описується 64-бітним двійковим вектором `O ∈ {0, 1}⁶⁴`, де біт `O[i] = 1` позначає наявність довільної фігури (перешкоди) на полі з індексом `i`.

Для заданого вихідного поля `s` та ковзної фігури (тура, слон):
1. Існує фіксована множина клітинок, які лежать на лініях дії фігури (промені на північ, південь, схід, захід для тури або по чотирьох діагоналях для слона);
2. Крайові клітинки дошки не впливають на зупинку променя перед ними (промінь у будь-якому разі закінчується на межі дошки або на самій крайовій клітинці). Тому релевантною маскою перешкод є підмножина внутрішніх клітинок уздовж променів, яка позначається бітовою маскою `M[s]`;
3. Нехай `k = popcount(M[s])` — кількість одиничних розрядів у масці `M[s]`. Для слона `k ∈ [5, 9]`, для тури `k ∈ [10, 12]`.

Конфігурація перешкод (блокерів) для поля `s` визначається побітовим множенням:

```
B = O ∧ M[s]
```

Оскільки маска `M[s]` містить рівно `k` встановлених бітів, вектор `B` може набувати лише одного з `2ᵏ` можливих двійкових станів:

```
|{B}| = 2ᵏ      [де k ≤ 12, тобто від 32 до 4096 унікальних конфігурацій]
```

Задача полягає у побудові відображення `h: {0, 1}⁶⁴ → {0, 1, ..., 2ᵇ - 1}`, де `b ≤ k`, такого, що для будь-яких двох різних конфігурацій перешкод `B₁ ≠ B₂` з різними результатами атак їхні хеш-індекси не перетинаються:

```
Attacks(B₁) ≠ Attacks(B₂)  ⇒  h(B₁) ≠ h(B₂)
```

---

### Хеш-функція через цілочисельне множення та зсув

Хеш-функція методу Magic Bitboards визначається над кільцем лишків за модулем `2⁶⁴`:

```
h(B) = ⌊( (B · C[s]) mod 2⁶⁴ ) / 2⁶⁴⁻ᵇ⌋
```

У машинному представленні ця операція записується як побітове множення 64-бітних беззнакових чисел із подальшим логічним зсувом праворуч:

```
index = (uint64_t)(B * C) >> (64 - b)
```

де:
- `B = O ∧ M[s]` — маска активних блокерів (розріджене 64-бітне число з максимум `k` одиницями);
- `C[s]` — 64-бітна псевдовипадкова константа («магічне число»);
- `b` — бітова розрядність таблиці індексів (`b ≤ k`);
- `64 - b` — величина правого зсуву, яка виділяє `b` найстарших розрядів добутку.

---

### Алгебраїчний механізм перенесення бітів

Щоб зрозуміти, чому звичайне цілочисельне множення здатне перетворити довільні розрізнені біти на неперервний індекс, розкладемо число `B` у суму степенів двійки.

Нехай маска `B` містить одиниці на позиціях `p₁, p₂, ..., pₖ`:

```
B = 2ᵖ¹ + 2ᵖ² + ... + 2ᵖᵏ
```

Тоді множення числа `B` на константу `C` розкладається на лінійну комбінацію зсувів числа `C`:

```
B · C
= (2ᵖ¹ + 2ᵖ² + ... + 2ᵖᵏ) · C       [дистрибутивність множення відносно додавання]
= C · 2ᵖ¹ + C · 2ᵖ² + ... + C · 2ᵖᵏ [множення степеня двійки є лівим зсувом]
= (C ≪ p₁) + (C ≪ p₂) + ... + (C ≪ pₖ)
```

Аналогічно, якщо розглядати дію числа `B` як оператора над розрядами константи `C = ∑ cⱼ · 2ʲ`, кожен встановлений біт `pᵢ` у блокері копіює та зміщує біти константи `C` на `pᵢ` позицій ліворуч.

Якщо константа `C` має одиничні біти на таких позиціях `qᵢ`, що для кожної пари `(pᵢ, qᵢ)` сума `pᵢ + qᵢ` потрапляє в діапазон старших розрядів `[64 - b, 63]`:

```
64 - b ≤ pᵢ + qᵢ ≤ 63
```

то біт `pᵢ` вихідної маски `B` буде скопійований у старшу зону добутку. Оскільки додавання кількох зсунутих копій утворює арифметичні переноси, при правильному підборі константи `C` ці переноси не спотворюють взаємну однозначність комбінацій у старших `b` розрядах.

### Оцінка розміру таблиць та колізій

Кількість можливих 64-бітних констант становить `2⁶⁴ ≈ 1.844 · 10¹⁹`. Простір пошуку занадто великий для повного перебору, проте частка вдалих «магічних» констант є достатньо високою, що дозволяє знаходити їх методом Монте-Карло за кілька мілісекунд.

Необхідні властивості ефективної магічної константи `C`:
1. **Низька щільність одиниць (Low Bit Density):** Константа `C` повинна містити відносно невелику кількість одиничних бітів (зазвичай `popcount(C) ∈ [6, 9]`). Занадто велика кількість одиниць породжує надлишкові каскади арифметичних переносів, які викликають колізії у старших розрядах;
2. **Конструктивний критерій відсутності колізій:** Для фіксованого поля `s` константа `C` є валідною тоді й лише тоді, коли функція `h(B)` є ін'єктивною на підмножині суттєво різних конфігурацій:

```
∀ Bᵢ, Bⱼ ⊂ M[s] : Attacks(Bᵢ) ≠ Attacks(Bⱼ) ⇒ h(Bᵢ) ≠ h(Bⱼ)
```

Зверніть увагу на конструктивну оптимізацію: дві різні конфігурації блокерів `B₁` та `B₂` можуть породжувати абсолютно ідентичну маску атак. Наприклад, якщо на лінії дії тури стоїть блокер на полі `d5`, то наявність або відсутність другого блокера далі за ним на полі `d6` не змінює маску досяжних клітинок тури (поле `d6` все одно закрите). Тому хеш-функція `h` не зобов'язана бути строго ін'єктивною щодо всіх конфігурацій `B`, а лише щодо класів еквівалентності результуючих атак. Це дозволяє зменшити розрядність індексу `b` на 1–2 біти порівняно з теоретичним максимумом `k`, заощаджуючи пам'ять таблиць у 2–4 рази.

#### Зведення обсягів таблиць для 64 клітинок

Для слонів максимальна кількість релевантних бітів `k` становить від 5 (у кутах) до 9 (у центрі дошки). Сумарний обсяг пам'яті для всіх 64 слонів:

```
Size(Bishops)
= ∑ 2ᵇ[s] · 8 байтів      [де s = 0 .. 63]
= 1428 · 8 байтів
= 11424 байти ≈ 11.16 КБ  [повністю поміщається в L1D-кеш процесора]
```

Для тур `k` становить від 10 до 12. Сумарний обсяг пам'яті для всіх 64 тур:

```
Size(Rooks)
= ∑ 2ᵇ[s] · 8 байтів      [де s = 0 .. 63]
= 102400 · 8 байтів
= 819200 байтів = 800 КБ  [поміщається в L2/L3-кеш процесора]
```

### Алгоритм конструктивного пошуку магічних констант

Пошук магічного числа для поля `s` виконується один раз під час ініціалізації рушія за алгоритмом:

```
Алгоритм знаходження магічного числа C[s]:
1. Згенерувати маску релевантних полів M[s] та підрахувати k = popcount(M[s]).
2. Згенерувати всі 2ᵏ можливих комбінацій перешкод B[0 .. 2ᵏ - 1].
3. Для кожної комбінації B[i] обчислити еталонну маску атак ReferenceAttacks[i]
   класичним покроковим трасуванням променів.
4. У циклі випадкового пошуку:
   a. Згенерувати випадкове 64-бітне число C з низькою щільністю одиниць
      через побітове множення 3 незалежних псевдовипадкових чисел:
      C = rand64() & rand64() & rand64();
   b. Створити порожню тестову таблицю TestTable розміром 2ᵇ елементів (заповнити нулями);
   c. Для кожного i від 0 до 2ᵏ - 1:
      - Обчислити індекс idx = (B[i] * C) >> (64 - b);
      - Якщо TestTable[idx] == 0:
           TestTable[idx] = ReferenceAttacks[i];
        Інакше якщо TestTable[idx] != ReferenceAttacks[i]:
           Колізія знайдена! Перервати перевірку та перейти до кроку 4a (нова спроба);
   d. Якщо всі 2ᵏ конфігурацій пройшли перевірку без колізій — число C знайдено!
```

Ймовірність випадкового знаходження валідної константи `C` для слона становить близько `1 / 50`, а для тури — близько `1 / 5000`. Оскільки кожна перевірка константи виконується за кілька тисяч тактів процесора, повна генерація всіх магічних констант для всіх 64 полів дошки займає менше 15 мілісекунд під час старту програми.
