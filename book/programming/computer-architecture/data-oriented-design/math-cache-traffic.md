# 🧮 Кількісна модель трафіку пам'яті та утилізації кеш-ліній

Пропускна здатність шини між процесором та оперативною пам'яттю (англ. *memory bandwidth*) є фізично обмеженим ресурсом обчислювальної системи. Коли обчислювальне ядро виконує трансформацію масивів даних, реальна продуктивність визначається не теоретичною піковою частотою АЛП (арифметико-логічного пристрою), а обсягом корисних байтів, переданих через ієрархію кешів за одиницю часу.

Кількісна модель дає змогу точно розрахувати коефіцієнт засмічення кешу (англ. *cache pollution*), надлишковий трафік шини та втрати енергії внаслідок неоптимального розташування полів у пам'яті.

---

### Параметри апаратної моделі

Розглянемо сучасну архітектуру x86-64 або ARM64 з типовою організацією кеш-пам'яті:

- `L = 64` — розмір однієї кеш-лінії в байтах (стандарт для більшості мікропроцесорів);
- `N` — загальна кількість оброблюваних елементів (сутностей);
- `S_obj` — повний розмір структури сутності в пам'яті (у байтах);
- `S_act` — сумарний розмір полів, які реально зчитуються та модифікуються в конкретному обчислювальному циклі (`S_act ≤ S_obj`);
- `W_bus` — ширина шини пам'яті (типово 64 біти = 8 байтів на канал);
- `T_clk` — період тактового сигналу процесора.

Контролер пам'яті фізично не здатний прочитати з DRAM одиничний байт або окреме 4-байтне число: мінімальною неподільною одиницею передачі між DRAM, кешем L3, L2 та L1 завжди є повна кеш-лінія розміром `L` байтів.

---

### Модель 1: Об'єктна ієрархія (Pointer Soup та масив покажчиків)

У класичній об'єктно-орієнтованій моделі програма зберігає масив покажчиків `Entity* entities[N]`, де кожен екземпляр виділяється окремим викликом у динамічній пам'яті (купі).

#### 1. Трафік масиву покажчиків
Для доступу до кожного об'єкта процесор спочатку зчитує 64-бітний покажчик (8 байтів):

```
B_ptr = N · 8      [трафік на вибірку адрес]
```

Оскільки покажчики розміщені суміжно, вони утилізують кеш-лінії повністю. Кількість ліній для покажчиків:

```
C_ptr = ceil(N · 8 / L) = ceil(N / 8)
```

#### 2. Трафік тіл об'єктів
Оскільки кожен об'єкт виділений у купі незалежно, відстань у віртуальній пам'яті між двома сусідніми покажчиками `entities[i]` та `entities[i+1]` значно перевищує розмір кеш-лінії `L`:

```
|Addr(entities[i+1]) - Addr(entities[i])| >> L
```

Це означає, що доступ до кожного `i`-го об'єкта викликає завантаження нової, незалежної кеш-лінії з DRAM. Навіть якщо об'єкт `S_obj` займає менше ніж `L` (наприклад, 48 байтів), контролер пам'яті змушений завантажити всі 64 байти. Якщо ж об'єкт має розмір `S_obj > L` (наприклад, 96 байтів) і не вирівняний по межі 64 байтів, він перетинає межу двох ліній, спричиняючи зчитування двох кеш-ліній:

```
C_obj = ceil(S_obj / L)      [кеш-ліній на один об'єкт]
```

Сумарний обсяг переданих байтів з оперативної пам'яті для об'єктного підходу:

```
B_OOP = B_ptr + N · ceil(S_obj / L) · L
```

Підставимо значення для `S_obj = 96` байтів, `S_act = 24` байти (позиція `x, y, z` та швидкість `vx, vy, vz` по 4 байти float) та `L = 64` байти:

```
ceil(96 / 64) = 2      [дві лінії на об'єкт]
B_OOP = N · 8 + N · 2 · 64
= N · (8 + 128)
= 136 · N [байтів]
```

### Модель 2: Data-Oriented Design (Лінійний потік Structure of Arrays)

У Data-Oriented підході компоненти рознесені на окремі неперервні лінійні масиви. Цикл фізики оперує виключно суміжними масивами `Position` та `Velocity`.

Масив покажчиків відсутній: індексація здійснюється прямою арифметикою за індексом `i`. Холодні поля (ім'я, інвентар, візуальні сітки) розташовані в інших областях пам'яті і взагалі не торкаються шини під час виконання фізичного циклу.

Сумарний обсяг байтів, необхідний для обробки `N` елементів:

```
B_DOD = N · S_act
```

Кількість кеш-ліній, що зчитуються з пам'яті:

```
C_DOD = ceil(N · S_act / L)
```

Для того ж набору даних (`S_act = 24` байти):

```
B_DOD = N · 24 [байтів]
```

### Коефіцієнт корисної утилізації кеш-пам'яті (Payload Efficiency)

Визначимо коефіцієнт корисної утилізації трафіку `η` як відношення розміру корисних обчислених даних до сумарного обсягу байтів, прокачаних через системну шину:

```
η = (N · S_act) / B_total
```

Порівняємо ефективність двох підходів:

```
η_OOP = (N · 24) / (N · 136)
= 24 / 136
≈ 0.1764          [17.6% корисного навантаження]
```

```
η_DOD = (N · 24) / (N · 24)
= 1.0000          [100.0% корисного навантаження]
```

У класичному об'єктному коді **82.4% усієї пропускної здатності шини пам'яті витрачається на транспортування непотрібного сміття** (холодних полів, невикористаних таблиць віртуальних методів, заголовків алокатора купи та невирівняних залишків кеш-ліній).

---

### Коефіцієнт прискорення за пропускною здатністю (Bandwidth Speedup Factor)

Коефіцієнт теоретичного виграшу за обсягом трафіку шини визначається співвідношенням:

```
K_BW = B_OOP / B_DOD
= (8 + ceil(S_obj / L) · L) / S_act
```

Для нашого прикладу:

```
K_BW = 136 / 24 ≈ 5.67
```

Лише внаслідок усунення непотрібних байтів із шини пам'яті система отримує скорочення навантаження на підсистему DRAM у **5.67 раза**.

### Вплив на затримки сторінок DRAM (Row Buffer Hit vs Miss)

Крім кількості байтів, колосальне значення має режим роботи контролера пам'яті DRAM. Пам'ять DDR4/DDR5 організована у вигляді банків, де доступ відбувається через буфер рядка (англ. *Row Buffer* розміром 1–2 КБ).

1. **При лінійному доступі (DOD):**
   Сусідні елементи потрапляють в один і той самий відкритий рядок DRAM (англ. *Row Buffer Hit* / *Page Hit*).
   Затримка доступу:

   ```
   T_hit = t_CL      [лише затримка вибірки стовпця: ~14 нс]
   ```

2. **При хаотичному доступі за покажчиками (OOP):**
   Кожен наступний об'єкт потрапляє у випадковий рядок іншого банку або вимагає закриття поточного рядка (англ. *Row Buffer Conflict* / *Page Miss*).
   Контролер змушений виконати повний цикл перезарядки та активації:

   ```
   T_miss = t_RP + t_RCD + t_CL      [перезарядка + активація + вибірка: ~45–60 нс]
   ```

Сумарна затримка вибірки даних для `N` елементів при відсутності апаратного прискорення:

```
T_total_OOP = N · T_miss = N · 50 нс
T_total_DOD = (N · S_act / L) · (T_hit / N_line) + T_burst
```

Завдяки неперервності апаратний блок випереджального читання процесора (англ. *hardware stream prefetcher*) автоматично виявляє лінійний крок `stride = L` і завантажує наступні кеш-лінії в L2/L1 ще до того, як інструкція звернеться до них. У результаті для DOD час затримки пам'яті повністю маскується виконанням обчислень, зводячи ефективну затримку до нуля тактів простою конвеєра.
