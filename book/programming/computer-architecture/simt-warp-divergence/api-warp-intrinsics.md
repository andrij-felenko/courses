# 📋 Варпові інтринсики CUDA: інтерфейс синхронізації та обміну даними між доріжками

Варпові інтринсики (англ. *warp-level intrinsics*) надають прямий низькорівневий інтерфейс до внутрішніх апаратних комунікаційних мереж мультипроцесора GPU. Вони дозволяють 32 потокам у межах одного варпу синхронізувати виконання, опитувати маски предикатів та обмінюватися даними безпосередньо через регістровий файл, повністю оминаючи спільну та глобальну пам'ять.

Усі ці функції виконуються за 1–2 такти апаратного конвеєра, що робить їх на порядок продуктивнішими за звернення до спільної пам'яті (`LDS`/`STS`) та бар'єри рівня блоку `__syncthreads()`.

### Апаратний механізм передачі даних через регістровий кросбар

На відміну від звичайної передачі даних через спільну пам'ять (яка вимагає запису в масив SRAM, бар'єра синхронізації та зчитування через конвеєр LSU з ризиком банківських конфліктів), варпові інтринсики сімейства shuffle реалізовані безпосередньо в обчислювальному конвеєрі мультипроцесора.

Кожна апаратна секція SM містить внутрішній комутатор (англ. *operand crossbar network*), який сполучає виходи регістрового файлу 32 фізичних доріжок. Коли планувальник варпів видає машинну інструкцію `SHFL.SYNC`, апаратна частина вибирає операнд із регістру доріжки-джерела `srcLane` і комутує його безпосередньо на вхід АЛП або в цільовий регістр приймача за один такт. Це повністю унеможливлює виникнення банківських конфліктів та зменшує затримку обміну до мінімуму.

### Інтерфейс синхронізації та маскування

Починаючи з архітектури Nvidia Volta (Compute Capability 7.0+) та платформи CUDA 9, модель виконання була переведена на незалежне планування потоків (ITS). У зв'язку з цим усі варпові інтринсики вимагають першим обов'язковим аргументом явну 32-бітну бітову маску `mask` (англ. *member mask*).

Маска визначає підмножину потоків варпу, які обов'язково беруть участь у цій операції:
* Якщо біт `1 << laneId` встановлено в `1`, потік із цим номером зобов'язаний дійти до виклику цієї інструкції.
* Якщо потік вказаний у масці, але через умовне розгалуження не досягає виклику інтринсика, апаратна частина фіксує непередбачувану поведінку або зависання (англ. *hang* / *deadlock*).
* Функція `__activemask()` повертає бітову маску всіх потоків варпу, які є фізично активними в поточний момент виклику. Проте її слід використовувати з обережністю: вона відображає лише миттєвий стан планувальника, а не логічний інваріант програми.

```
Специфікація базових функцій синхронізації:

1. void __syncwarp(unsigned int mask = 0xFFFFFFFF);
   Призначення: Апаратний бар'єр збіжності варпу.
   Поведінка:   Призупиняє виконання викликаючого потоку доти, доки всі активні потоки,
                зазначені в `mask`, не досягнуть цієї інструкції.
   Асемблер PTX: bar.warp.sync mask;

2. unsigned int __activemask();
   Призначення: Повертає 32-бітну маску фізично активних доріжок варпу.
```

### Інтерфейс колективного голосування (Warp Vote Functions)

Функції голосування оцінюють цілочисловий предикат `predicate` (де `0` — хибність, будь-яке ненульове число — істина) для кожного потоку, вказаного в `mask`, та повертають зведену бітову або булеву відповідь.

Голосування є базовим будівельним блоком для усунення дивергенції варпів: варп може за 1 такт перевірити, чи всі потоки йдуть одним шляхом (`__all_sync`), чи є хоча б один активний елемент (`__any_sync`), або отримати точний перелік активних потоків (`__ballot_sync`).

```
Таблиця операцій голосування:

┌────────────────────────────────────────┬───────────────────────────────────────────┐
│ Сигнатура функції                      │ Результат та апаратна поведінка           │
├────────────────────────────────────────┼───────────────────────────────────────────┤
│ unsigned int __ballot_sync(            │ Повертає 32-бітне число, де n-й біт       │
│     unsigned int mask,                 │ дорівнює 1, якщо потік n надав істинний   │
│     int predicate);                    │ предикат, і 0 в іншому разі.              │
│                                        │ PTX: vote.sync.ballot.b32                 │
├────────────────────────────────────────┼───────────────────────────────────────────┤
│ int __all_sync(                        │ Повертає ненульове число (1), якщо ВСІ    │
│     unsigned int mask,                 │ активні потоки з маски надали істинний    │
│     int predicate);                    │ предикат. PTX: vote.sync.all.pred         │
├────────────────────────────────────────┼───────────────────────────────────────────┤
│ int __any_sync(                        │ Повертає ненульове число (1), якщо ХОЧА Б │
│     unsigned int mask,                 │ ОДИН потік з маски надав істинний         │
│     int predicate);                    │ предикат. PTX: vote.sync.any.pred         │
└────────────────────────────────────────┴───────────────────────────────────────────┘
```

Поєднання `__ballot_sync` зі швидкою апаратною інструкцією підрахунку одиничних бітів `__popc` дозволяє обчислювати ранг потоку (його порядковий номер серед усіх активних потоків варпу) за один такт без звернення до лічильників у пам'яті:

```
unsigned int ballot = __ballot_sync(0xFFFFFFFF, condition);
unsigned int rank = __popc(ballot & ((1u << laneId) - 1));
```

### Інтерфейс перетасовки регістрів (Warp Shuffle Functions)

Функції сімейства `__shfl_*` (англ. *shuffle*) забезпечують пряму передачу значень регістрів між фізичними доріжками варпу через внутрішній комутатор кросбара мультипроцесора.

Шаблонний параметр `T` підтримує фундаментальні типи `int`, `unsigned int`, `long`, `unsigned long`, `long long`, `unsigned long long`, `float`, `double` та половинну точність `half`.

Параметр `width` задає логічний розмір підварпу (має бути степенем двійки: 2, 4, 8, 16 або 32 за замовчуванням). Якщо `width < 32`, варп розбивається на незалежні сегменти фіксованого розміру, і всі операції перетасовки замикаються всередині відповідного підварпу. Це дозволяє ефективно реалізовувати 2D-фільтри зображень та блокові редукції невеликого розміру:

```
Специфікація функцій перетасовки:

1. T __shfl_sync(unsigned int mask, T var, int srcLane, int width = 32);
   Широкомовне зчитування: повертає значення `var` з доріжки з номером `srcLane`.
   Якщо всі потоки викликають з `srcLane = 0`, потік 0 транслює своє значення всім.
   PTX: shfl.sync.idx.b32

2. T __shfl_down_sync(unsigned int mask, T var, unsigned int delta, int width = 32);
   Зсув вниз: потік `i` отримує значення `var` від потоку `i + delta`.
   Якщо `i + delta >= width`, потік `i` зберігає своє власне значення `var`.
   Базовий примітив для побудови паралельних деревних редукцій.
   PTX: shfl.sync.down.b32

3. T __shfl_up_sync(unsigned int mask, T var, unsigned int delta, int width = 32);
   Зсув вгору: потік `i` отримує значення `var` від потоку `i - delta`.
   Якщо `i - delta < 0`, потік `i` зберігає власне значення `var`.
   Базовий примітив для префіксного сумування (англ. *inclusive/exclusive scan*).
   PTX: shfl.sync.up.b32

4. T __shfl_xor_sync(unsigned int mask, T var, int laneMask, int width = 32);
   Метеликовий обмін (Butterfly exchange): потік `i` обмінюється значенням
   із потоком `i ^ laneMask`. Використовується в алгоритмах швидкого перетворення
   Фур'є (FFT) та бітонічного сортування.
   PTX: shfl.sync.bfly.b32
```

### Інтерфейс порівняння та зіставлення значень (Match Functions)

Починаючи з архітектури Volta (Compute Capability 7.0+), графічні процесори підтримують апаратні інструкції зіставлення значень між потоками варпу. Це дозволяє за 1 такт згрупувати потоки, які обробляють однакові ключі (наприклад, при побудові гістограм або сортуванні за значенням):

```
Специфікація функцій зіставлення:

1. unsigned int __match_any_sync(unsigned int mask, T value);
   Повертає бітову маску всіх потоків у `mask`, у яких змінна `value` має
   точно таке саме значення, як і в поточного викликаючого потоку.
   PTX: match.any.sync.b32

2. unsigned int __match_all_sync(unsigned int mask, T value, int *pred);
   Повертає маску `mask`, якщо ВСІ потоки в `mask` мають однакове значення `value`,
   і записує `*pred = 1`. Якщо хоча б одне значення відрізняється, повертає `0`
   і записує `*pred = 0`.
   PTX: match.all.sync.b32
```

### Практичний приклад: паралельна варпова редукція та префіксний скан

Редукція 32 чисел у межах варпу за допомогою `__shfl_down_sync` виконується за `log₂(32) = 5` кроків без використання спільної пам'яті та без блокових синхронізацій:

:::tabs
```c
// warp_primitives.c (C API / CUDA C)
#include <cuda_runtime.h>

// Швидка редукція суми всередині варпу
__device__ inline float warp_reduce_sum(float val)
{
    unsigned int mask = 0xFFFFFFFF; // Усі 32 потоки активні

    // Деревна редукція: 16 -> 8 -> 4 -> 2 -> 1
    val += __shfl_down_sync(mask, val, 16);
    val += __shfl_down_sync(mask, val, 8);
    val += __shfl_down_sync(mask, val, 4);
    val += __shfl_down_sync(mask, val, 2);
    val += __shfl_down_sync(mask, val, 1);

    // Потік 0 містить фінальну суму всіх 32 потоків
    return val;
}

// Префіксне сумування (Inclusive Scan) всередині варпу
__device__ inline float warp_prefix_scan(float val)
{
    unsigned int mask = 0xFFFFFFFF;

    for (int offset = 1; offset < 32; offset <<= 1) {
        float temp = __shfl_up_sync(mask, val, offset);
        if ((threadIdx.x & 31) >= offset) {
            val += temp;
        }
    }
    return val;
}
```
```cpp
// warp_primitives.hpp (Modern CUDA C++ / Type-safe Templates)
#pragma once
#include <cuda_runtime.h>
#include <concepts>
#include <type_traits>

namespace gpu {

// Концепт арифметичного типу, що підтримується апаратним shuffle
template <typename T>
concept Shuffleable = std::is_arithmetic_v<T> && (sizeof(T) == 4 || sizeof(T) == 8);

// Універсальна типобезпечна редукція варпу
template <Shuffleable T, typename BinaryOp>
__device__ inline T warp_reduce(T val, BinaryOp op, unsigned int mask = 0xFFFFFFFF) noexcept
{
    #pragma unroll
    for (int offset = 16; offset > 0; offset >>= 1) {
        T other = __shfl_down_sync(mask, val, offset);
        val = op(val, other);
    }
    return val;
}

// Спеціалізація суми для довільного числового типу
template <Shuffleable T>
__device__ inline T warp_sum(T val, unsigned int mask = 0xFFFFFFFF) noexcept
{
    return warp_reduce(val, [](T a, T b) { return a + b; }, mask);
}

// Спеціалізація максимуму
template <Shuffleable T>
__device__ inline T warp_max(T val, unsigned int mask = 0xFFFFFFFF) noexcept
{
    return warp_reduce(val, [](T a, T b) { return (a > b) ? a : b; }, mask);
}

} // namespace gpu
```

### Бар'єри пам'яті проти бар'єрів виконання

Критично важливо розрізняти призначення інструкції `__syncwarp()` та бар'єрів пам'яті:
1. **`__syncwarp(mask)` є бар'єром виконання (Execution Barrier):** він гарантує, що всі потоки з маски дійшли до цієї інструкції в коді. Проте він **не** є бар'єром пам'яті (Memory Fence) для глобальної пам'яті або кешів інших SM.
2. **Взаємодія з пам'яттю:** якщо потік 0 записав дані у спільну або глобальну пам'ять, а потік 1 намагається їх прочитати, для гарантії видимості запису на нових архітектурах слід використовувати явні операції пам'яті з семантикою `cuda::memory_order_release` / `acquire` або бар'єр блоку `__syncthreads()`.

### Типові помилки та апаратні пастки

1. **Використання неактуальної маски збіжності:** передача повної маски `0xFFFFFFFF` у коді, який виконується всередині розгалуження `if (threadIdx.x < 16)`, призведе до зависання на архітектурах Volta+, оскільки потоки 16–31 ніколи не дійдуть до точки виклику інтринсика.
2. **Невідповідність типів у `__shfl_sync`:** передача складних структур даних або об'єктів розміром понад 8 байтів напряму викличе помилку компіляції; такі типи слід розбивати на 32-бітні або 64-бітні скалярні поля.
3. **Хибне очікування результату на всіх доріжках:** після виконання `__shfl_down_sync` редукований результат знаходиться виключно на нульовій доріжці варпу. Якщо результат потрібен усім 32 потокам, після редукції викликають широкомовлення `val = __shfl_sync(mask, val, 0)`.
4. **Неправильний розрахунок маски підварпу:** при роботі з `width = 16` маска виклику для другої половини варпу (потоки 16..31) має містити одиниці у старших 16 бітах (`0xFFFF0000`), а не `0x0000FFFF`.
