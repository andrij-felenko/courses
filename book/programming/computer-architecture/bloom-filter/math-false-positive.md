# 🧮 Математичне виведення ймовірності та оцінки ентропії фільтра Блума

Фільтр Блума спирається на точний імовірнісний апарат, що пов'язує чотири фундаментальні змінні:
- `m` — довжина бітового масиву в розрядах (бітах);
- `n` — кількість елементів, доданих до множини;
- `k` — кількість незалежних геш-функцій;
- `p` — імовірність хибнопозитивного спрацьовування (*False Positive rate*).

Головна мета математичного моделювання — розрахувати оптимальну кількість геш-функцій `k`, яка мінімізує `p` при заданих обмеженнях на пам'ять `m` та розмір множини `n`, а також визначити необхідну питому кількість бітів `m / n` для досягнення цільової точності.

### 1. Покрокове виведення ймовірності хибнопозитивного спрацьовування

Припустимо, що всі `k` геш-функцій є ідеально рівномірними та незалежними випадковими оракулами. Це означає, що кожна геш-функція відображає довільний вхідний ключ у будь-який із `m` бітів масиву з однаковою ймовірністю `1 / m`.

#### Крок 1: Ймовірність збереження нульового біта одним гешем
Коли геш-функція обчислює індекс для ключа, ймовірність того, що конкретний (фіксований) біт масиву **не буде обраний**, дорівнює:

```
P₀(1 геш) = 1 - 1/m
```

#### Крок 2: Ймовірність збереження нуля після додавання одного елемента
Для додавання одного ключа обчислюються значення всіх `k` незалежних геш-функцій. Ймовірність того, що конкретний біт не буде обраний **жодною** з цих `k` функцій, становить:

```
P₀(1 елемент) = (1 - 1/m)ᵏ
```

#### Крок 3: Стан біта після додавання n елементів
Коли у фільтр послідовно записано `n` різних ключів, сумарно виконується `k · n` незалежних спроб вибору бітів. Ймовірність того, що певний біт залишиться нулем (жодного разу не буде обраний), дорівнює:

```
P(біт = 0) = (1 - 1/m)ᵏⁿ
```

Для аналізу великих масивів (`m ≫ 1`) скористаємося стандартною границею експоненційної функції:

```
lim_{m → ∞} (1 - 1/m)ᵐ = 1/e = e⁻¹
```

Перетворимо вираз для ймовірності нульового стану:

```
P(біт = 0)
= (1 - 1/m)ᵏⁿ                       [початкова ймовірність]
= ((1 - 1/m)ᵐ)^(k · n / m)          [розподіл степенів]
≈ (e⁻¹)^(k · n / m)                 [граничний перехід при великому m]
= e^(-k · n / m)                    [зведення до спільного показника]
```

#### Крок 4: Ймовірність того, що біт дорівнює одиниці
Ймовірність того, що випадково обраний розряд масиву перебуває у встановленому стані (дорівнює 1):

```
P(біт = 1) = 1 - P(біт = 0) ≈ 1 - e^(-k · n / m)
```

#### Крок 5: Умова хибнопозитивного спрацьовування
Хибнопозитивне спрацьовування виникає для стороннього ключа `y` (якого ніколи не записували у фільтр), якщо всі `k` його геш-індексів випадково вкажуть на біти, які вже містять одиницю.

Оскільки геш-функції незалежні, сумарна ймовірність `p` дорівнює добутку ймовірностей потрапляння в одиницю для кожного з `k` випробувань:

```
p = (P(біт = 1))ᵏ ≈ (1 - e^(-k · n / m))ᵏ
```

### 2. Знаходження оптимальної кількості геш-функцій k

Для заданого обсягу пам'яті `m` та кількості елементів `n` існує єдине оптимальне значення `k`, за якого ймовірність помилки `p` є мінімальною. Якщо обрати `k` занадто малим, кожен ключ встановлюватиме мало бітів, і для хибного збігу сторонньому ключу знадобиться перевірити мало позицій. Якщо ж обрати `k` занадто великим, бітовий масив швидко перенасититься одиницями, і майже кожен біт дорівнюватиме 1.

Мінімізуємо функцію `p(k)` аналітично. Оскільки натуральний логарифм є монотонно зростаючою функцією, мінімум `p(k)` збігається з мінімумом `ln(p)`:

```
ln(p) = ln((1 - e^(-k · n / m))ᵏ) = k · ln(1 - e^(-k · n / m))
```

Введемо заміну змінної для спрощення диференціювання:

```
x = e^(-k · n / m)
```

Тоді:

```
k = - (m / n) · ln(x)
```

Підставимо `k` у формулу для `ln(p)`:

```
ln(p)
= (- (m / n) · ln(x)) · ln(1 - x)   [підстановка k через x]
= - (m / n) · (ln(x) · ln(1 - x))   [винесення константи]
```

Щоб мінімізувати `ln(p)`, необхідно максимізувати функцію:

```
f(x) = ln(x) · ln(1 - x)
```

Обчислимо похідну `f'(x)` за правилом диференціювання добутку:

```
f'(x)
= (ln(x))' · ln(1 - x) + ln(x) · (ln(1 - x))'   [правило добутку]
= (1/x) · ln(1 - x) + ln(x) · (-1 / (1 - x))   [похідні логарифмів]
= ln(1 - x) / x - ln(x) / (1 - x)              [спрощення дробів]
```

Прирівняємо похідну до нуля для знаходження точки екстремуму:

```
ln(1 - x) / x - ln(x) / (1 - x) = 0
ln(1 - x) / x = ln(x) / (1 - x)
(1 - x) · ln(1 - x) = x · ln(x)
```

Рівняння `(1 - x) · ln(1 - x) = x · ln(x)` має єдиний симетричний розв'язок на інтервалі `(0, 1)`:

```
x = 1/2 = 0.5
```

Повернемося до початкової змінної `k`:

```
e^(-k · n / m) = 1/2
-k · n / m = ln(1/2) = -ln(2)
k · n / m = ln(2)
```

Звідси отримуємо точну аналітичну формулу оптимальної кількості геш-функцій:

```
k_opt = (m / n) · ln(2) ≈ 0.693147 · (m / n)
```

#### Наслідок: щільність заповнення бітового масиву
Підставивши `k_opt` у формулу ймовірності одиничного стану біта, отримуємо:

```
P(біт = 1) = 1 - e^(-k_opt · n / m) = 1 - e^(-ln(2)) = 1 - 1/2 = 0.5
```

Фільтр Блума досягає максимальної інформаційної ефективності та мінімального рівня помилок саме тоді, коли **рівно половина бітів масиву дорівнює одиниці, а інша половина — нулю**.

### 3. Розрахунок необхідної пам'яті m на елемент

Підставимо оптимальне значення `k_opt` у вираз для ймовірності хибного спрацьовування:

```
p_opt
= (1 - e^(-k_opt · n / m))^(k_opt)   [формула ймовірності при k_opt]
= (1 - 1/2)^(k_opt)                  [оскільки P(біт=1) = 1/2]
= (1/2)^(k_opt)                      [спрощення основи]
= 2^(-k_opt)                         [запис через степінь двійки]
```

Прологарифмуємо обидві частини за основою 2:

```
log₂(p_opt) = -k_opt = - (m / n) · ln(2)
```

Звідси виразимо питомі витрати пам'яті на один елемент `m / n`:

```
m / n
= - log₂(p_opt) / ln(2)             [ділення на ln(2)]
= - (ln(p_opt) / ln(2)) / ln(2)     [перехід до натурального логарифма]
= - ln(p_opt) / (ln(2))²            [зведення знаменника]
```

Обчислимо числову константу знаменника:

```
(ln(2))² ≈ (0.693147)² ≈ 0.480453
1 / (ln(2))² ≈ 1 / 0.480453 ≈ 2.0813689
1 / ln(2) = log₂(e) ≈ 1.442695
```

Отже:

```
m / n = -1.442695 · log₂(p_opt)
```

### 4. Теоретико-інформаційна оцінка та межа Шеннона

Порівняємо ефективність фільтра Блума з абсолютною інформаційною межею стиснення множин за Шенноном.

Нехай ми хочемо представляти підмножину розміру `n` з універсуму `U`, що дозволяє перевірку належності з імовірністю хибного спрацьовування `p`. Згідно з теорією інформації, мінімальна кількість бітів, необхідна для розрізнення запитів з точністю `p`, дорівнює:

```
(m / n)_Shannon = log₂(1 / p) = -log₂(p)
```

Для фільтра Блума ми отримали:

```
(m / n)_Bloom = (1 / ln(2)) · log₂(1 / p) ≈ 1.4427 · log₂(1 / p)
```

Коефіцієнт надлишковості становить:

```
(m / n)_Bloom / (m / n)_Shannon = 1 / ln(2) ≈ 1.442695   [надлишковість 44.3%]
```

Звідки береться ця 44% втрата?
Вона зумовлена тим, що фільтр Блума використовує повністю незалежні біти без стиснення. Хоча при `k_opt` половина бітів є одиницями (що максимізує ентропію окремого біта до 1 біта), зв'язки між геш-позиціями різних елементів створюють колізії, які не використовують ентропію структури на 100%.

### 5. Оптимізація Кірша-Мітценмахера: генерація k гешів із двох

У практичних архітектурах обчислення `k` незалежних геш-функцій (наприклад, 7 чи 14 разів для кожного ключа) створює надмірне навантаження на конвеєр CPU. 2006 року Адам Кірш (*Adam Kirsch*) та Майкл Мітценмахер (*Michael Mitzenmacher*) довели фундаментальну теорему гешування:

**Теорема (Less Hashing, Same Performance):**
Маючи лише **дві** незалежні 64-розрядні геш-функції `h₁(x)` та `h₂(x)`, можна згенерувати довільну кількість `k` псевдонезалежних індексів за лінійною формулою:

```
g_i(x) = (h₁(x) + i · h₂(x)) mod m,    де i = 0, 1, 2, ..., k - 1
```

Асимптотична ймовірність хибнопозитивного спрацьовування для такого методу повністю збігається з класичним фільтром Блума на `k` повністю незалежних гешах:

```
lim_{m, n → ∞} P_Kirsch(False Positive) = (1 - e^(-k · n / m))ᵏ
```

Це математичне спрощення зменшує кількість обчислень із `k` геш-раундів до всього 2 геш-викликів (наприклад, єдиний виклик `MurmurHash3_x64_128`, що повертає два 64-бітних значення `h₁` та `h₂`), після чого всі `k` адрес розраховуються за допомогою однієї інструкції множення з додаванням (FMA/LEA) за 1 такт CPU.
