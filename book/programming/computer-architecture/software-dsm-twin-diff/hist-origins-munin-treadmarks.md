# 📜 Історія появи протоколів множинних записувачів: від IVY до Munin і TreadMarks

Ідея створити враження єдиної спільної пам'яті над мережею незалежних комп'ютерів виникла в середині 1980-х років, коли ціна багатопроцесорних суперкомп'ютерів зі спільною шиною (як-от Sequent Symmetry чи SGI Origin) вимірювалася сотнями тисяч доларів, тоді як звичайні робочі станції з процесорами Motorola 68020 та Intel 80386 масово дешевшали. Проте перша ж спроба об'єднати дешеві машини у спільний адресний простір виявила фундаментальний дефект апаратної гранулярності, який паралізував паралельні програми.

## Початок епохи: система IVY Кая Лі (1986)

У 1986 році в Єльському університеті (Yale University, США) аспірант Кай Лі (Kai Li) під керівництвом професора Пола Худака (Paul Hudak) захистив докторську дисертацію та опублікував епохальну статтю «Memory Coherence in Shared Virtual Memory Systems». Лі створив першу в світі працюючу систему розподіленої спільної пам'яті — **IVY** (Integrated Shared Virtual Memory for the Apollo Ring Network).

Архітектура IVY була прямолінійною: вона перенесла класичний протокол апаратного кешування з інвалідацією на сторінки операційної системи. Кожна сторінка пам'яті розміром 1 КБ або 4 КБ мала рівно одного власника (Single-Writer). Якщо вузол читав сторінку, він отримував копію `Read-Only`. Щойно будь-який вузол намагався записати хоча б один байт, протокол відбирав сторінку в усіх інших вузлів, переводив їхні локальні копії в стан `Invalid` (`PROT_NONE`) і призначав новий виключний статус записувача.

IVY працювала бездоганно на суворо розділених даних, але на реальних алгоритмах розбиття матриць або ітераційної лінійної алгебри продуктивність різко деградувала. Якщо два потоки записували в сусідні змінні, розташовані в межах однієї сторінки (хибне спільне використання), сторінка безперервно літала кільцевою мережею Apollo Token Ring, витрачаючи мілісекунди на кожен запис. Програмістам доводилося власноруч вирівнювати кожну структуру даних за межами 4096 байтів, штучно роздуваючи витрати оперативної пам'яті.

## Прорив у Rice University: Джон Картер та система Munin (1991)

Наприкінці 1980-х років дослідницька група Університету Райса (Rice University, Х'юстон, штат Техас) під керівництвом професора Віллі Званепула (Willy Zwaenepoel) та Джона Картера (John B. Carter) розпочала пошук кардинально іншого підходу.

Картер дійшов ключового висновку: **корінь проблеми полягає не в розмірі сторінки, а в аксіомі одного записувача**. Якщо дозволити кільком вузлам одночасно писати в одну й ту саму сторінку, сторінковий пінг-понг зникне. Але як потім об'єднати результати їхньої роботи, не переписуючи машинний код програм?

Саме в Райсі в 1991 році на симпозіумі ACM SOSP була представлена система **Munin**. У ній Картер та Званепул вперше реалізували революційний механізм **Twin-and-Diff**:
1. При першому записі в сторінку обробник сигналу непомітно створює її точний двійник (Twin).
2. Потік виконує нативні команди процесора без жодного програмного уповільнення.
3. У точці синхронізації сторінка покомпонентно порівнюється з двійником, а обчислений журнал відмінностей (Diff) розсилається іншим вузлам.

Для теоретичного обґрунтування множинного запису команда Munin спиралася на концепцію узгодженості за звільненням (Release Consistency), яку роком раніше (1990) сформулювали дослідники Стенфордського університету на чолі з Курошем Гарачорлу (Kourosh Gharachorloo) та Джоном Хеннессі (John L. Hennessy).

Munin довів, що програмна DSM може досягати 80–90% продуктивності апаратних багатопроцесорних систем на широкому класі наукових обчислень.

## Вершина програмної DSM: Пітер Келехер та система TreadMarks (1994)

Незважаючи на успіх Munin, вона використовувала модель «жадібного» звільнення (Eager Release Consistency): у момент відпускання замка всі створені Diff негайно розсилалися всім вузлам кластера широкомовними повідомленнями. На повільних мережах Ethernet 10 Мбіт/с це призводило до сплесків трафіку (Broadcast Storms).

У 1994–1996 роках Пітер Келехер (Peter Keleher), Алан Кокс (Alan L. Cox) та Віллі Званепул у тому ж Університеті Райса створили систему **TreadMarks**, яка стала канонічним зразком програмної розподіленої пам'яті.

TreadMarks поєднала механізм Twin-and-Diff з винайденою Келехером моделлю **лінивої узгодженості** (Lazy Release Consistency, LRC). Замість негайної розсилки Diff у мережу, система передавала між вузлами лише легковагі векторні часові мітки (Vector Timestamps). Пакети Diff надсилалися виключно за запитом (On-Demand), коли віддалений вузол дійсно звертався до зміненої сторінки.

TreadMarks стала першою комерційно успішною програмною системою DSM. Вона постачалася як бібліотека користувацького простору для систем SunOS, IRIX, AIX та Linux, не вимагаючи жодних модифікацій ядра ОС чи спеціальних компіляторів.

## Спадщина та трансформація ідей

Наприкінці 1990-х та на початку 2000-х років розвиток стандарту MPI (Message Passing Interface) для суперкомп'ютерів та перехід до кластерних архітектур на базі акторів і мікросервісів дещо зменшив інтерес до класичної прозорої DSM для загального програмування.

Проте механізм Twin-and-Diff не зник — він перетворився на фундаментальний інструмент сучасного системного програмування. Сьогодні принципи створення тіньових знімків сторінок пам'яті та передачі компактних дельт змін є базою для:
- алгоритмів безперервної міграції віртуальних машин у гіпервізорах KVM, Xen та VMware ESXi;
- систем знімків пам'яті (Memory Checkpointing) для відновлення після збоїв у розподілених сховищах;
- протоколів оптимістичної реплікації у розподілених базах даних (Delta-State CRDT).
