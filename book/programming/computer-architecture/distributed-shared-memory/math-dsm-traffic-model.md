# 🧮 Модель мережевого трафіку та накладних витрат у протоколах DSM

Цей розрахунок дає формальну математичну модель обсягу мережного трафіку, кількості службових повідомлень, затримок синхронізації та меж паралельного прискорення для різних протоколів і моделей узгодженості розподіленої спільної пам'яті.

## 1. Формалізація параметрів розподіленої системи

Розглянемо паралельну обчислювальну систему, що складається з `N` однорідних обчислювальних вузлів, з'єднаних мережею передачі даних. Кожен вузол має власну локальну оперативну пам'ять і бере участь у підтримці спільного віртуального адресного простору.

Введемо базові параметри системи:
- `N` — кількість обчислювальних вузлів у кластері;
- `P` — розмір сторінки віртуальної пам'яті в байтах (стандартний розмір сторінки в архітектурах x86-64 та ARMv8 становить `P = 4096` байтів);
- `S` — загальна кількість послідовних інтервалів синхронізації або фаз обчислень;
- `W` — середня кількість операцій запису, які виконує один вузол у межах однієї критичної секції або інтервалу обчислень;
- `k` — сумарний розмір фактично змінених байтів у межах однієї сторінки за один інтервал синхронізації (`1 ≤ k ≤ P`);
- `H` — розмір службових заголовків мережного пакета (сума заголовків канального рівня Ethernet, мережного рівня IP та транспортного рівня UDP/TCP або RoCE; типово `H = 48`–`64` байти);
- `L` — базова мережна затримка передачі пакета туди й назад (RTT, англ. *Round-Trip Time*), що включає затримку комутатора, трансиверів та обробки мережною картою;
- `B` — ефективна пропускна здатність мережного каналу зв'язку в байтах за секунду.

Крім того, для програмних систем сторінкового захисту визначимо операційні витрати ядра операційної системи:
- `T_fault` — час виникнення апаратного виключення Page Fault та доставки сигналу `SIGSEGV` у простір користувача (типово 1.5–3.5 мікросекунди);
- `T_mprotect` — час виконання системного виклику `mprotect()` для зміни бітів таблиці сторінок і скидання записів TLB (типово 0.8–2.0 мікросекунди).

## 2. Аналітичні моделі комунікаційної складності

### А. Послідовна узгодженість (Sequential Consistency, SC)

У моделі послідовної узгодженості кожен окремий запис у пам'ять є точкою глобальної синхронізації. Якщо вузол не має виключних прав запису на сторінку (стан `RO` або `INV`), виконання команди запису блокується до завершення протоколу інвалідації.

У найгіршому, але типовому для хибного спільного використання випадку, коли `N` вузлів почергово пишуть у різні змінні однієї сторінки:
- На кожен із `W` записів вузол надсилає 1 запит на право власності;
- Отримує повну копію сторінки розміром `P` байтів від попереднього власника;
- Розсилає `N - 1` повідомлень про знеправлення (Invalidation) усім іншим вузлам;
- Отримує `N - 1` підтверджень (Acks).

```
Кількість мережних повідомлень на один інтервал:
M_sc = W · (1 + 1 + 2 · (N - 1))
     = W · (2 + 2 · N - 2)
     = 2 · W · N

Сумарний мережний об'єм передачі даних на один інтервал (байтів):
V_sc = W · ((P + H) + (N - 1) · H + (N - 1) · H + H)
     = W · (P + H + 2 · (N - 1) · H + H)
     = W · (P + 2 · N · H)

Сумарний час простою процесора (Stall Time) на один інтервал:
T_stall_sc = W · (T_fault + T_mprotect + L + (P + 2 · N · H) / B)
```

Масштабованість моделі SC має порядок `O(W · N)` за кількістю повідомлень та `O(W · P)` за обсягом трафіку. Оскільки розмір сторінки `P = 4096` є фіксованим і великим множником, навіть при зміні всього одного 32-бітного числа (`k = 4`) система змушена передавати понад 4 кілобайти на кожен запис.

### Б. Жадібна узгодженість за звільненням (Eager Release Consistency, ERC)

У моделі ERC локальні операції запису всередині критичної секції виконуються без виходу в мережу. Під час виклику операції `Release()` вузол агрегує всі накопичені модифікації.

Якщо використовується протокол Twin-and-Diff:
- Вузол обчислює різницю розміром `k` байтів;
- Розсилає пакети з журналом Diff усім `N - 1` вузлам кластера, які тримають копію сторінки;
- Отримує `N - 1` підтверджень про успішне оновлення перед тим, як відпустити замок.

```
Кількість мережних повідомлень на один інтервал:
M_erc = 2 · (N - 1)

Сумарний мережний об'єм передачі даних на один інтервал (байтів):
V_erc = (N - 1) · (k + H) + (N - 1) · H
      = (N - 1) · (k + 2 · H)

Сумарний час простою процесора (Stall Time) на один інтервал:
T_stall_erc = T_diff + L + ((N - 1) · (k + 2 · H)) / B
```
де `T_diff` — час процесорного порівняння сторінки з її двійником (побайтове або 64-бітне сканування, типово 0.5–1.2 мікросекунди).

Складність ERC за повідомленнями масштабується як `O(N)`, а за обсягом трафіку — як `O(N · k)`. Це усуває залежність від кількості записів `W` та розміру сторінки `P`, але зберігає лінійне зростання трафіку зі збільшенням кількості серверів `N`.

### В. Лінива узгодженість за звільненням (Lazy Release Consistency, LRC)

У моделі LRC операція `Release()` є суто локальною: векторний годинник інкрементується, але мережні пакети не надсилаються.

Синхронізація відбувається в момент, коли інший вузол виконує `Acquire()`:
- Новий власник надсилає 1 прямий запит попередньому власникові замка разом зі своїм векторним таймстемпом `V_dest`;
- Попередній власник визначає за відношенням часткового порядку Лампорта, які інтервали відсутні в одержувача;
- Надсилає 1 пакет-відповідь, що містить вектор годинника та лише необхідні фрагменти Diff розміром `k` байтів.

```
Кількість мережних повідомлень на один інтервал:
M_lrc = 2    [1 запит на блокування + 1 відповідь із даними]

Сумарний мережний об'єм передачі даних на один інтервал (байтів):
V_lrc = (H + 8 · N) + (k + H + 8 · N)
      = k + 2 · H + 16 · N

Сумарний час простою процесора (Stall Time) на один інтервал:
T_stall_lrc = T_diff + T_merge + L + (k + 2 · H + 16 · N) / B
```
де `T_merge` — час накладання різниці на віддалену сторінку (типово 0.2–0.5 мікросекунди).

Складність LRC за кількістю повідомлень становить константу `O(1)` відносно розміру кластера `N`, а обсяг передачі масштабується суто пропорційно розміру реальних змін `O(k)`.

## 3. Кількісний порівняльний аналіз: чотири тестові сценарії

Розглянемо чотири характерні класи паралельних навантажень на кластері з такими характеристиками:
- Кількість вузлів: `N = 16`
- Розмір сторінки: `P = 4096` байтів
- Заголовок пакета: `H = 48` байтів
- Затримка мережі (Ethernet): `L = 40` мкс (40 000 нс)
- Пропускна здатність: `B = 100` Мбіт/с = `12.5` байтів/мкс
- Час обробника помилки та системного виклику: `T_fault + T_mprotect = 3.5` мкс

---

### Сценарій 1: Спільний атомарний лічильник (Висока конкуренція)
Кожен із 16 вузлів виконує `W = 500` інкрементів лічильника `uint64_t` (`k = 8` байтів) у межах однієї сторінки.

**1. Послідовна узгодженість (SC):**
```
Повідомлень:
M_sc = 2 · W · N
     = 2 · 500 · 16
     = 16 000 повідомлень

Обсяг трафіку:
V_sc = W · (P + 2 · N · H)
     = 500 · (4096 + 2 · 16 · 48)
     = 500 · (4096 + 1536)
     = 500 · 5632
     = 2 816 000 байтів  [≈ 2.68 МБ]

Час простою:
T_stall_sc = W · (3.5 мкс + 40 мкс + 5632 / 12.5)
           = 500 · (43.5 + 450.56) мкс
           = 500 · 494.06 мкс
           ≈ 247.03 мілісекунди
```

**2. Lazy Release Consistency (LRC):**
```
Повідомлень:
M_lrc = 2 повідомлення

Обсяг трафіку:
V_lrc = k + 2 · H + 16 · N
      = 8 + 2 · 48 + 16 · 16
      = 8 + 96 + 256
      = 360 байтів

Час простою:
T_stall_lrc = 1.0 мкс + 0.3 мкс + 40 мкс + 360 / 12.5
            = 41.3 мкс + 28.8 мкс
            ≈ 70.1 мікросекунд (0.0701 мс)
```

**Результат порівняння для Сценарію 1:**
- Зменшення трафіку: `2 816 000 / 360 ≈ 7822.2` разів;
- Скорочення часу блокування: `247 030 / 70.1 ≈ 3524` рази.

---

### Сценарій 2: Двовимірна сітка 2D Stencil (Ітерація Якобі / Лапласа)
Кожен вузол обробляє свою просторову смугу матриці. На кожній ітерації оновлюються внутрішні комірки, а на межах розділу передаються граничні рядки розміром `k = 128` байтів у сторінці 4096 байтів. Кількість локальних записів на смугу `W = 2048`.

**1. Послідовна узгодженість (SC):**
```
Обсяг трафіку на межі смуги:
V_sc = W · (P + 2 · N · H)
     = 2048 · (4096 + 1536)
     = 2048 · 5632
     = 11 534 336 байтів  [≈ 11.0 МБ]

Час простою:
T_stall_sc = 2048 · 494.06 мкс
           ≈ 1011.83 мілісекунд (1.01 секунди на ітерацію!)
```

**2. Lazy Release Consistency (LRC):**
```
Обсяг трафіку на межі смуги:
V_lrc = k + 2 · H + 16 · N
      = 128 + 96 + 256
      = 480 байтів

Час простою:
T_stall_lrc = 1.2 мкс + 0.4 мкс + 40 мкс + 480 / 12.5
            = 41.6 мкс + 38.4 мкс
            ≈ 80.0 мікросекунд (0.00008 секунди)
```

**Результат порівняння для Сценарію 2:**
- Зменшення трафіку: `11 534 336 / 480 ≈ 24 029.8` разів;
- Прискорення ітерації: `1 011 830 / 80.0 ≈ 12 647.8` разів.

---

### Сценарій 3: Конвеєр «Виробник — Споживач» (Streaming Buffer)
Вузол-виробник записує порцію даних `k = 1024` байти (`W = 256` записів по 32 біти), після чого передає семафор споживачеві.

**1. Послідовна узгодженість (SC):**
```
V_sc = 256 · 5632 = 1 441 792 байти  [≈ 1.37 МБ]
T_stall_sc = 256 · 494.06 мкс ≈ 126.48 мілісекунд
```

**2. Eager Release Consistency (ERC):**
```
V_erc = (N - 1) · (k + 2 · H)
      = 15 · (1024 + 96)
      = 15 · 1120
      = 16 800 байтів  [розсилка всім 15 вузлам]

T_stall_erc = 1.0 мкс + 40 мкс + 16 800 / 12.5
            = 41.0 мкс + 1344 мкс
            ≈ 1385.0 мікросекунд (1.385 мс)
```

**3. Lazy Release Consistency (LRC):**
```
V_lrc = 1024 + 96 + 256 = 1376 байтів  [лише прямий запит від споживача]
T_stall_lrc = 1.0 мкс + 0.4 мкс + 40 мкс + 1376 / 12.5
            = 41.4 мкс + 110.08 мкс
            ≈ 151.48 мікросекунд (0.151 мс)
```

---

### Сценарій 4: Апаратний RDMA та CXL проти програмної DSM
Для оцінки сучасної апаратної реінкарнації DSM порівняємо затримку обслуговування промаху читання 64-байтової кеш-лінії через різні технології:

```
1. Software DSM (TCP/IP + SIGSEGV + mprotect):
   T_soft = T_fault + T_mprotect + L_tcp + P / B_eth
          = 2.5 мкс + 1.5 мкс + 40 мкс + 4096 / 12.5 байтів/мкс
          = 4.0 мкс + 40 мкс + 327.68 мкс
          ≈ 371.68 мікросекунд (371 680 нс)

2. RDMA Read (RoCEv2 100GbE / InfiniBand, апаратний DMA в обхід ЦП):
   T_rdma = L_rdma + 64 / B_rdma
          = 1.5 мкс + 64 / 12 500 байтів/мкс
          = 1.5 мкс + 0.00512 мкс
          ≈ 1.505 мікросекунд (1505 нс)

3. CXL.mem (PCIe 5.0 x16, прямий FLIT-доступ контролера пам'яті):
   T_cxl = L_cxl_controller + L_pcie_fabric + T_dram_pool
         = 40 нс + 80 нс + 80 нс
         ≈ 200 наносекунд (0.2 мкс)
```

Співвідношення швидкості доступу:
- RDMA швидший за Software DSM у: `371 680 / 1505 ≈ 246.9` разів;
- CXL швидший за Software DSM у: `371 680 / 200 ≈ 1858.4` разів.

## 4. Закон Амдала та межі паралельного прискорення в DSM

З урахуванням накладних витрат розподіленої пам'яті класичний закон Амдала модифікується додаванням часу комунікацій та синхронізації:

```
S(N) = T_seq / (T_seq · (1 - f) + (T_seq · f) / N + S_sync · T_stall(N))
```
де:
- `T_seq` — загальний час послідовного виконання програми на одному вузлі;
- `f` — частка коду, що піддається ідеальному розпаралелюванню (`0 < f < 1`);
- `S_sync` — сумарна кількість точок синхронізації в алгоритмі;
- `T_stall(N)` — час простою на одну точку синхронізації як функція від кількості вузлів `N`.

Для моделі послідовної узгодженості `T_stall_sc(N) = O(N)`. При зростанні `N` доданок `S_sync · T_stall(N)` починає лінійно зростати. Продиференціювавши знаменник за `N`, отримаємо критичну точку зламу масштабування `N_crit`:

```
d/dN [(T_seq · f) / N + S_sync · C_sc · N] = 0
-(T_seq · f) / N² + S_sync · C_sc = 0
N_crit = √((T_seq · f) / (S_sync · C_sc))
```

При перевищенні `N > N_crit` загальний час виконання програми починає **зростати**, а паралельне прискорення `S(N)` падає нижче одиниці (додавання нових серверів лише сповільнює обчислення).

Для моделі Lazy Release Consistency `T_stall_lrc(N) = O(1)`. Залежність від `N` у накладних витратах майже відсутня, що усуває точку передчасного зламу й дозволяє системі масштабуватися до значно більших кластерів.

## 5. Алгебраїчні властивості векторних годинників та відношення Лампорта

Формальна коректність протоколу Lazy Release Consistency спирається на структуру частково впорядкованої множини подій `(E, ≺)`, де `≺` — відношення причинного передування Лампорта (*happens-before*).

Подія `a` передує події `b` (`a ≺ b`) тоді й лише тоді, коли виконується одна з трьох аксіом:
1. Події `a` та `b` відбулися на одному вузлі, і `a` передувала `b` у порядку програми (Program Order).
2. Подія `a` є викликом `Release(lock)` на вузлі `i`, а подія `b` — відповідним наступним викликом `Acquire(lock)` на вузлі `j`.
3. Існує проміжна подія `c` така, що `a ≺ c` та `c ≺ b` (Транзитивність).

Кожен інтервал `I_i^k` (інтервал номер `k` на вузлі `i`) однозначно ідентифікується парою `(i, k)`. Стан знань вузла описується векторним годинником:

```
V_i = [v_i[1], v_i[2], ..., v_i[N]]
```
де `v_i[j]` — номер найбільшого інтервалу вузла `j`, про який відомо вузлу `i`.

### Правила алгебраїчного оновлення векторного таймстемпу:

1. **Початок нового локального інтервалу на вузлі `i`:**
```
v_i[i] ← v_i[i] + 1
```

2. **Передача синхронізаційного повідомлення від вузла `i` до вузла `j`:**
```
v_j[m] ← max(v_j[m], v_msg[m])  для всіх m ∈ {1, 2, ..., N}
```

### Теорема про необхідну та достатню множину різниць (Diffs)

Нехай вузол `j` виконує `Acquire` після того, як вузол `i` виконав `Release`. Множина інтервалів `Δ(i → j)`, модифікації яких необхідно передати вузлу `j`, строго визначається різницею векторів:

```
Δ(i → j) = { I_m^k | v_j[m] < k ≤ v_i[m], де m ∈ {1, 2, ..., N} }
```

Якщо для певного вузла `m` значення `v_j[m] ≥ v_i[m]`, це є строгим математичним доказом того, що вузол `j` уже володіє всіма змінами, зробленими вузлом `m`, які були відомі вузлу `i`. Тому жоден байт цих сторінок не передається повторно, що мінімізує обсяг трафіку до абсолютного інформаційного оптимуму.

## 6. Критерій стійкості до затримок (Latency Tolerance Bound)

Для досягнення ефективного паралелізму в будь-якій системі DSM час корисних обчислень між точками синхронізації `T_comp` повинен суттєво перевищувати накладні витрати синхронізації та передачі пам'яті `T_stall`.

Введемо коефіцієнт обчислювальної щільності `η` (Compute-to-Communication Ratio):

```
η = T_comp / T_stall
```

Умова ефективного прискорення паралельної програми (ефективність `E(N) = S(N) / N ≥ 0.75`):

```
η_min = T_comp / T_stall ≥ 3 · (N - 1)
```

Для програмного DSM із затримкою `T_stall ≈ 60` мкс мінімальний інтервал між синхронізаціями на 16 вузлах становить:
```
T_comp_min ≥ 3 · 15 · 60 мкс = 2700 мкс = 2.7 мілісекунди.
```

Для апаратної пам'яті CXL із затримкою `T_stall ≈ 0.2` мкс:
```
T_comp_min ≥ 3 · 15 · 0.2 мкс = 9.0 мікросекунд.
```

Це математично доводить, чому перехід від програмного DSM до апаратних пулів пам'яті CXL дозволяє ефективно розпаралелювати дрібногранулярні алгоритми, які раніше були неможливими для розподілених систем.

## 7. Порівняльний аналіз: DSM проти колективних операцій MPI

Щоб зрозуміти, чому високопродуктивні обчислення (HPC) розділилися між парадигмами розподіленої пам'яті (DSM/PGAS) та передачі повідомлень (MPI), зіставимо комунікаційну складність DSM із класичними колективними операціями стандарту MPI:

### А. Розсилка даних (MPI_Bcast) через біноміальне дерево
Коли один вузол транслює блок даних розміром `M` байтів усім `N` вузлам кластера, бібліотека MPI будує логічне біноміальне дерево зв'язку з висотою `⌈log₂ N⌉`.

Час виконання операції `MPI_Bcast`:
```
T_bcast = ⌈log₂ N⌉ · L + (N - 1) / N · (M / B)
```
Для `N = 16` вузлів, затримки `L = 40` мкс та розміру сторінки `M = 4096` байтів:
```
T_bcast = 4 · 40 мкс + (15 / 16) · (4096 / 12.5) мкс
        = 160 мкс + 307.2 мкс
        ≈ 467.2 мікросекунди.
```

### Б. Кільцеве зведення (Ring-AllReduce)
У сучасних системах розподіленого навчання нейромереж (Data Parallelism у PyTorch / DeepSpeed) синхронізація градієнтів між вузлами виконується за алгоритмом Ring-AllReduce. Дані розміром `M` байтів розбиваються на `N` сегментів, і вузли передають їх кільцем у два етапи (Scatter-Reduce та Allgather).

Час виконання операції Ring-AllReduce:
```
T_allreduce = 2 · (N - 1) · L + 2 · (N - 1) / N · (M / B)
```
Для `N = 16`, `L = 40` мкс та розміру тензора `M = 1` МБ (`1 048 576` байтів):
```
T_allreduce = 2 · 15 · 40 мкс + 2 · (15 / 16) · (1 048 576 / 12.5) мкс
            = 1200 мкс + 157 286.4 мкс
            ≈ 158.48 мілісекунди.
```

### В. Вплив мережевої топології на розсилку оновлень

Ефективність передачі сторінок та журналів Diff суттєво залежить від фізичної топології комутаторів кластера:

1. **Ієрархічне дерево (Fat-Tree Topology):**
   У багаторівневих мережах комутаторів (Spine-Leaf) затримка передачі між двома серверами всередині однієї стійки (Top-of-Rack switch) становить `L_local ≈ 10` мкс, тоді як передача через кореневий комутатор (Spine switch) між різними стійками зростає до `L_cross ≈ 45` мкс.
   Для протоколу Eager Release Consistency на Fat-Tree топології сумарний час розсилки визначається найповільнішою міжстійковою ланкою:
   ```
   T_erc_fattree = L_cross + ((N - 1) · (k + 2 · H)) / B
   ```

2. **Багатовимірний тор (3D Torus):**
   У суперкомп'ютерних архітектурах (як-от IBM Blue Gene) вузли з'єднані тривимірною сіткою з прямими лініями зв'язку. Середня кількість хопів (проміжних комутаторів) між двома довільними вузлами масштабується як `D_avg = 3/4 · ∛N`.
   Затримка передачі пакета:
   ```
   L_torus = D_avg · L_hop = (3/4 · ∛N) · L_hop
   ```
   Для Lazy Release Consistency передача Diff виконується за схемою Point-to-Point, тому середній час очікування замка на 3D Torus становить `T_stall_lrc = (3/4 · ∛N) · L_hop + (k + 2·H) / B`, що забезпечує стійку суб-лінійну залежність від кількості вузлів.

### Г. Облік пам'яті під службові метадані (Memory Footprint)

Окрім мережного трафіку, кожна модель узгодженості накладає витрати на оперативну пам'ять для збереження службових структур:
- **У послідовній узгодженості (SC):** Облік обмежується бітовою маскою співвласників `Copiyset` на домашньому вузлі (розмір `N` бітів на кожну 4-кілобайтну сторінку). Для пулу пам'яті 1 ГБ (`262 144` сторінки) і `N = 16` маска займає лише `512` КБ RAM.
- **У Lazy Release Consistency (LRC):** Кожен вузол зберігає векторний годинник розміром `N · 8` байтів, таблицю інтервалів та чергу згенерованих журналів Diff для сторінок, які ще не були синхронізовані з усіма вузлами. Для тисячі активних інтервалів службова пам'ять становить від 2 до 8 МБ на вузол, що становить менше 1% від сучасного обсягу оперативної пам'яті серверів.

### Висновок з аналізу MPI проти DSM:
- **Для регулярних щільних структур (матриці, тензори ваг):** MPI забезпечує близьку до 100% утилізацію фізичної смуги пропускання мережі завдяки монолітній потоковій передачі мегабайтних буферів в обхід сторінкових помилок.
- **Для нерегулярних розріджених структур (графи, просторові дерева, хеш-таблиці):** Модель DSM на базі Lazy Release Consistency та Twin-and-Diff є набагато ефективнішою, оскільки передає лише поодинокі змінені байти (`k ≪ P`) за запитом, позбавляючи програміста необхідності вручну серіалізувати динамічні покажчики.
