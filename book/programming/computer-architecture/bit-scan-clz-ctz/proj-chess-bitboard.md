# ⚙️ Реалізація бітбордів та бітових черг у шахових рушіях і планувальниках

Швидкий пошук одиничних бітів є наріжним інструментом побудови високопродуктивних структур даних у системному програмуванні, телекомунікаціях та рушіях настільних ігор. Традиційний об'єктно-орієнтований підхід, де стан системи зберігається у вигляді масивів структур, покажчиків або динамічних списків, вимагає послідовного обходу пам'яті за допомогою циклів. Такий обхід створює часті промахи кеш-пам'яті першого рівня (L1 Data Cache Misses) та породжує численні непередбачувані умовні розгалуження, які блокують суперскалярний конвеєр процесора.

Заміна масивів об'єктів на 64-бітні бітові маски (бітборди) дозволяє перенести всю логіку фільтрації, перетину множин та пошуку елементів безпосередньо в регістри загального призначення. Процесор маніпулює станом усієї системи паралельно за допомогою побітових інструкцій АЛП, а виділення конкретних елементів зводиться до апаратного підрахунку кінцевих нулів (CTZ) за константний час O(1).

Нижче детально розглянуто три практичні архітектурні реалізації: генератор ходів для стрибкових та лінійних шахових фігур, модуль диспетчеризації задач у планувальнику операційної системи та бенчмарк оцінки продуктивності.

### 1. Шахові бітборди: математика дошки та генерація ходів коня

У сучасних шахових програмах (таких як Stockfish чи Leela Chess Zero) стандартна шахівниця розміром `8×8` представляється у вигляді одного 64-бітного беззнакового цілого числа `uint64_t`. Кожен біт регістра однозначно відповідає одній із 64 клітинок шахівниці:
- Біт 0 відповідає полю `a1` (лівий нижній кут);
- Біт 7 відповідає полю `h1` (правий нижній кут);
- Біт 56 відповідає полю `a8` (лівий верхній кут);
- Біт 63 відповідає полю `h8` (правий верхній кут).

Якщо сторона має на дошці, наприклад, двох коней на полях `b1` (індекс 1) та `g1` (індекс 6), бітборд коней містить значення `(1ULL << 1) | (1ULL << 6) = 0x0000000000000042`.

#### Перевага над матричним представленням 8×8

Традиційний шаховий рушій 1970-х років зберігав дошку як двовимірний масив `char board[8][8]`. Щоб згенерувати всі можливі ходи для коней, програма мала:
1. Пройти у подвійному циклі крізь усі 64 клітинки матриці;
2. На кожній клітинці виконати перевірку, чи стоїть там кінь потрібного кольору;
3. Для кожного знайденого коня перевірити 8 можливих геометричних зміщень `(±1, ±2)` та `(±2, ±1)`, щоразу перевіряючи вихід за межі дошки.

Такий підхід генерує сотні розгалужень `if`, на яких конвеєр сучасного процесора постійно зазнає штрафів за хибне передбачення переходів (*branch misprediction penalty*, 15–20 тактів за кожен промах).

Бітборд вирішує задачу принципово інакше:
1. Таблиця можливих ударів коня для кожної з 64 клітинок обчислюється один раз під час запуску програми й зберігається у вигляді статичного масиву `uint64_t knight_attack_table[64]`;
2. Усі коні вилучаються з бітборда по черзі за допомогою операції підрахунку кінцевих нулів (CTZ), яка миттєво повертає індекс наступного поля з конем;
3. Маска ходів коня фільтрується однією побітовою операцією `attacks & ~friendly_pieces` (виключаючи клітинки, зайняті власними фігурами);
4. Опрацьований кінь видаляється з бітборда виразом `bb = bb & (bb - 1)` (скидання наймолодшого встановленого біта за один такт АЛП).

Кількість ітерацій циклу дорівнює точній кількості коней на дошці (зазвичай 1–2), повністю усуваючи необхідність сканування 64 клітинок.

:::tabs
```c
#include <stdint.h>
#include <stdio.h>

/* Таблиця попередньо обчислених масок атак коня для кожної з 64 клітинок */
static uint64_t knight_attack_table[64];

/* Ініціалізація масок атак коня під час старту програми */
void init_knight_attacks(void) {
    /* Можливі зміщення ходу коня по горизонталі (dx) та вертикалі (dy) */
    static const int dx[8] = {-2, -2, -1, -1,  1,  1,  2,  2};
    static const int dy[8] = {-1,  1, -2,  2, -2,  2, -1,  1};

    for (int sq = 0; sq < 64; ++sq) {
        int x = sq % 8;
        int y = sq / 8;
        uint64_t mask = 0;

        for (int i = 0; i < 8; ++i) {
            int nx = x + dx[i];
            int ny = y + dy[i];
            /* Перевіряємо, чи новий координати залишаються в межах шахівниці 8x8 */
            if (nx >= 0 && nx < 8 && ny >= 0 && ny < 8) {
                mask |= (1ULL << (ny * 8 + nx));
            }
        }
        knight_attack_table[sq] = mask;
    }
}

/* Генерація та розпакування ходів для всіх коней на дошці */
void generate_all_knight_moves(uint64_t knights_bb, uint64_t friendly_pieces) {
    /* Цикл виконується рівно стільки разів, скільки коней є на дошці */
    while (knights_bb != 0) {
        /* 1. Апаратний CTZ повертає індекс поля фігури за 1 такт */
        int from_sq = __builtin_ctzll(knights_bb);

        /* 2. Отримуємо атаку коня та виключаємо поля, зайняті своїми фігурами */
        uint64_t attacks = knight_attack_table[from_sq] & ~friendly_pieces;

        /* 3. Розпаковуємо всі доступні ходи для поточного коня */
        while (attacks != 0) {
            int to_sq = __builtin_ctzll(attacks);
            printf("Хід коня: поле %d -> поле %d\n", from_sq, to_sq);
            /* Скидаємо молодший біт знайденого ходу */
            attacks &= (attacks - 1);
        }

        /* 4. Видаляємо опрацьованого коня з бітборда */
        knights_bb &= (knights_bb - 1);
    }
}
```
```cpp
#include <cstdint>
#include <iostream>
#include <array>
#include <bit>

class ChessBoard {
public:
    ChessBoard() {
        init_knight_attacks();
    }

    // Генерація та виведення всіх легальних цільових клітинок для коней
    void generate_all_knight_moves(std::uint64_t knights_bb, std::uint64_t friendly_pieces) const noexcept {
        while (knights_bb != 0) {
            // Безпечне отримання молодшого біта за 1 такт процесора
            const int from_sq = std::countr_zero(knights_bb);
            std::uint64_t attacks = knight_attacks_[from_sq] & ~friendly_pieces;

            while (attacks != 0) {
                const int to_sq = std::countr_zero(attacks);
                std::cout << "Хід коня: поле " << from_sq << " -> поле " << to_sq << '\n';
                attacks &= (attacks - 1); // Очищення обробленого біта ходу
            }

            knights_bb &= (knights_bb - 1); // Очищення біта коня
        }
    }

private:
    std::array<std::uint64_t, 64> knight_attacks_{};

    void init_knight_attacks() noexcept {
        constexpr std::array<int, 8> dx{-2, -2, -1, -1, 1, 1, 2, 2};
        constexpr std::array<int, 8> dy{-1, 1, -2, 2, -2, 2, -1, 1};

        for (int sq = 0; sq < 64; ++sq) {
            const int x = sq % 8;
            const int y = sq / 8;
            std::uint64_t mask = 0;

            for (std::size_t i = 0; i < 8; ++i) {
                const int nx = x + dx[i];
                const int ny = y + dy[i];
                if (nx >= 0 && nx < 8 && ny >= 0 && ny < 8) {
                    mask |= (1ULL << (ny * 8 + nx));
                }
            }
            knight_attacks_[sq] = mask;
        }
    }
};
```

### 2. Лінійні фігури та пошук перешкод променів (Ray Attacks)

Для далекобійних фігур (тура, слон, ферзь) атаки поширюються у 8 напрямках (вгору, вниз, вліво, вправо та 4 діагоналі) до першої фігури-перешкоди на шляху (*blocker*).

Визначення першої перешкоди вздовж променя виконується без покрокового перебору клітинок:
- **Для позитивних променів (напрямок зростання індексів бітів):** маска зайнятих клітинок накладається на промінь `blockers = occupied & ray_mask`. Перша перешкода знаходиться за допомогою `CTZ(blockers)`;
- **Для негативних променів (напрямок спадання індексів бітів):** перша перешкода знаходиться за допомогою інструкції підрахунку провідних нулів `CLZ(blockers)`.

Такий алгоритм (відомий як класичний бітовий променевий трасувальник, *Ray Attack Generator*) усуває цикли сканування по прямих лініях і обчислює повну маску атак тури або слона всього за 4 побітові операції.

### 3. Модуль вибору пріоритетів у планувальнику задач ОС

В операційних системах реального часу та ядрах загального призначення (наприклад, класичному планувальнику O(1) ядра Linux, розробленому Інго Молнаром, Ingo Molnar) черги готових до виконання потоків діляться за рівнями статичного та динамічного пріоритету.

У ядрі Linux визначено 140 рівнів пріоритету (від 0 до 99 — пріоритети реального часу RT FIFO/RR, від 100 до 139 — звичайні користувацькі задачі з різними значеннями `nice`). Для кожного рівня пріоритету виділено окремий двозв'язний список задач `struct list_head queue[140]`.

#### Проблема пошуку найважливішої задачі

Коли процесор завершує квант часу поточної задачі або потік блокується на операції вводу-виводу, планувальник ядра повинен миттєво знайти непорожню чергу з найвищим пріоритетом (найменшим числовим індексом).

Якщо реалізувати цей пошук звичайним циклом `for (int p = 0; p < 140; ++p)`, ядро буде змушене послідовно читати заголовки списків із пам'яті. У гіршому випадку, коли в системі працює лише одна низькопріоритетна фонова задача з пріоритетом 139, процесор виконає 140 перевірок пам'яті та 140 ітерацій циклу. Якщо в системі запущено тисячі потоків, час планування залежатиме від конфігурації черг, що є неприпустимим для систем реального часу.

#### Рішення на базі бітової карти (Priority Bitmap)

Планувальник ядра зберігає компактний масив із 64-бітних слів `unsigned long bitmap[3]`, де кожен біт від 0 до 139 є дзеркальним прапорцем відповідної черги:
- Біт `k = 1`, якщо в черзі `queue[k]` є хоча б одна готова задача;
- Біт `k = 0`, якщо черга `queue[k]` порожня.

Коли задача створюється або прокидається від події, ядро додає її до списку `queue[k]` і встановлює біт `k` у карті пріоритетів атомарною операцією `set_bit`. Коли остання задача залишає чергу, біт `k` скидається операцією `clear_bit`.

Пошук найвищого пріоритету зводиться до пошуку першого одиничного біта в масиві з трьох слів за допомогою функції `sched_find_first_bit`:

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define MAX_PRIORITIES 140
#define WORDS_COUNT ((MAX_PRIORITIES + 63) / 64)

typedef struct {
    uint64_t words[WORDS_COUNT];
} PriorityBitmap;

/* Встановлення прапорця наявності задачі у відповідній черзі */
static inline void priority_bitmap_set(PriorityBitmap *bm, int prio) {
    if (prio >= 0 && prio < MAX_PRIORITIES) {
        bm->words[prio / 64] |= (1ULL << (prio % 64));
    }
}

/* Скидання прапорця, коли всі задачі черги завершилися */
static inline void priority_bitmap_clear(PriorityBitmap *bm, int prio) {
    if (prio >= 0 && prio < MAX_PRIORITIES) {
        bm->words[prio / 64] &= ~(1ULL << (prio % 64));
    }
}

/* Пошук черги з найвищим пріоритетом за сталий час O(1) */
static inline int sched_find_first_bit(const PriorityBitmap *bm) {
    for (int i = 0; i < WORDS_COUNT; ++i) {
        uint64_t w = bm->words[i];
        if (w != 0) {
            /* CTZ знаходить індекс молодшої одиниці за 1 такт АЛП */
            return i * 64 + __builtin_ctzll(w);
        }
    }
    return -1; /* У системі немає готових задач */
}
```
```cpp
#include <cstdint>
#include <array>
#include <optional>
#include <bit>

class PrioritySchedulerBitmap {
public:
    static constexpr std::size_t MaxPriorities = 140;
    static constexpr std::size_t WordsCount = (MaxPriorities + 63) / 64;

    // Встановлення активного пріоритету
    constexpr void set(std::size_t prio) noexcept {
        if (prio < MaxPriorities) {
            words_[prio / 64] |= (1ULL << (prio % 64));
        }
    }

    // Скидання активного пріоритету
    constexpr void reset(std::size_t prio) noexcept {
        if (prio < MaxPriorities) {
            words_[prio / 64] &= ~(1ULL << (prio % 64));
        }
    }

    // Пошук найвищого пріоритету за O(1) за допомогою C++20 std::countr_zero
    [[nodiscard]] constexpr std::optional<std::size_t> find_highest_priority() const noexcept {
        for (std::size_t i = 0; i < WordsCount; ++i) {
            if (const std::uint64_t w = words_[i]; w != 0) {
                return i * 64 + static_cast<std::size_t>(std::countr_zero(w));
            }
        }
        return std::nullopt; // Активних задач не знайдено
    }

private:
    std::array<std::uint64_t, WordsCount> words_{};
};
```

У такій структурі ядро перевіряє щонайбільше три 64-бітні регістри. Пошук триває менше однієї наносекунди (3–5 тактів процесора) незалежно від того, скільки мільйонів процесів запущено в операційній системі.
