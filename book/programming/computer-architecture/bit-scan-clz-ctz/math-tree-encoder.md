# 🧮 Логіка та виведення схем пріоритетного шифрування і компресорних дерев

Обчислення кількості провідних нулів (Count Leading Zeros, CLZ) та підрахунок загальної кількості одиничних бітів (Population Count, Popcount) у сучасних мікропроцесорах виконуються за сталий час O(1). На рівні кремнієвого кристала цей результат досягається за допомогою комбінаційних схем двох фундаментальних типів: ієрархічних пріоритетних шифраторів (Priority Encoders) та паралельних компресорних дерев Воллеса (Wallace Trees).

Нижче наведено строге математичне виведення булевих функцій пріоритетного кодування, синтез багаторівневого 64-бітного дерева, покроковий матричний розрахунок ярусів дерева Воллеса та алгебраїчний доказ роботи паралельного алгоритму SWAR.

---

### 1. Булева алгебра 4-бітного та 8-бітного пріоритетного шифратора

Розглянемо вхідний вектор із 4 бітів `D = (D₃, D₂, D₁, D₀)`, де індекс позначає розрядність: `D₃` — старший розряд (MSB), а `D₀` — молодший розряд (LSB). Завдання пріоритетного шифратора полягає у визначенні 2-бітного двійкового коду `Y = (Y₁, Y₀)` позиції найстаршого біта, рівного одиниці, а також сигнального прапорця валідності `V` (наявності хоча б однієї одиниці):

```
V = D₃ ∨ D₂ ∨ D₁ ∨ D₀          [прапорець валідності: вихід 1, якщо слово ненульове]
Z = ¬V                          [прапорець нуля: вихід 1, якщо всі біти слова нульові]
```

Для синтезу виходів `Y₁` та `Y₀` записуємо таблицю істинності з урахуванням абсолютного пріоритету старших розрядів над молодшими:

```
D₃ = 1: результат Y = 11₂ (позиція 3), молодші біти D₂, D₁, D₀ ігноруються.
D₃ = 0, D₂ = 1: результат Y = 10₂ (позиція 2), біти D₁, D₀ ігноруються.
D₃ = 0, D₂ = 0, D₁ = 1: результат Y = 01₂ (позиція 1), біт D₀ ігнорується.
D₃ = 0, D₂ = 0, D₁ = 0, D₀ = 1: результат Y = 00₂ (позиція 0).
```

Виводимо мінімізовані канонічні рівняння для старшого розряду індексу `Y₁`:

```
Y₁ = D₃ ∨ (¬D₃ ∧ D₂)
   = (D₃ ∨ ¬D₃) ∧ (D₃ ∨ D₂)    [дистрибутивність диз'юнкції відносно кон'юнкції]
   = 1 ∧ (D₃ ∨ D₂)             [закон виключеного третього: D₃ ∨ ¬D₃ = 1]
   = D₃ ∨ D₂                   [нейтральний елемент кон'юнкції: 1 ∧ A = A]
```

Виводимо мінімізоване рівняння для молодшого розряду індексу `Y₀`:

```
Y₀ = D₃ ∨ (¬D₃ ∧ ¬D₂ ∧ D₁)
   = (D₃ ∨ ¬D₃) ∧ (D₃ ∨ (¬D₂ ∧ D₁))  [дистрибутивність диз'юнкції]
   = 1 ∧ (D₃ ∨ (¬D₂ ∧ D₁)            [закон виключеного третього]
   = D₃ ∨ (¬D₂ ∧ D₁)                  [спрощення нейтрального елемента]
```

#### Розширення до 8-бітного шифратора

Для 8-бітного входу `D[7:0]` вихідний індекс має 3 біти `Y = (Y₂, Y₁, Y₀)`. Застосовуючи аналогічну мінімізацію булевих функцій, отримуємо аналітичні рівняння:

```
Y₂ = D₇ ∨ D₆ ∨ D₅ ∨ D₄                         [старший біт: одиниця у верхній четвірці розрядів]
Y₁ = D₇ ∨ D₆ ∨ (¬D₅ ∧ ¬D₄ ∧ (D₃ ∨ D₂))         [середній біт: вибір старшої пари у відповідній четвірці]
Y₀ = D₇ ∨ (¬D₆ ∧ D₅) ∨ (¬D₆ ∧ ¬D₄ ∧ D₃) ∨ (¬D₆ ∧ ¬D₄ ∧ ¬D₂ ∧ D₁)  [молодший біт: непарна позиція]
```

Отримані булеві вирази демонструють важливу властивість: вихід `Y₂` формується затримкою всього одного логічного вентиля `OR`, а виходи `Y₁` та `Y₀` вимагають не більше 2–3 вентильних переходів.

### 2. Проблема масштабування та ієрархічне дерево 64-бітного шифратора

Пряма спроба побудувати 64-бітний шифратор за однорівневою схемою стикається з фізичним обмеженням мікроелектроніки — коефіцієнтом розгалуження за входом (*fan-in*). Для формування молодшого розряду знадобився б логічний вентиль `AND` на 63 входи:

```
Y₀ = D₆₃ ∨ (¬D₆₃ ∧ ¬D₆₂ ∧ D₆₁) ∨ ... ∨ (¬D₆₃ ∧ ¬D₆₂ ∧ ... ∧ ¬D₂ ∧ D₁)
```

Вентиль із великою кількістю входів має велетенську паразитну ємність p-n переходів, що призводить до падіння крутизни фронтів сигналу та різкого зростання затримки (пропорційно квадрату кількості входів).

Для подолання цього обмеження застосовують деревоподібну модульну декомпозицію. Розбиваємо 64-бітний вектор `D[63:0]` на `K = 4` паралельні блоки по `B = 16` бітів кожен:
- `Block₃` обробляє біти `D[63..48]`;
- `Block₂` обробляє біти `D[47..32]`;
- `Block₁` обробляє біти `D[31..16]`;
- `Block₀` обробляє біти `D[15..0]`.

Кожен 16-бітний блок побудовано з чотирьох 4-бітних шифраторів за аналогічною ієрархічною схемою. Блок формує:
1. 4-бітний локальний вектор індексу `y[i] = (y[i]₃, y[i]₂, y[i]₁, y[i]₀)` у межах свого 16-бітного вікна;
2. Прапорець нульового блока `Z[i] = ¬(D[16i+15] ∨ D[16i+14] ∨ ... ∨ D[16i])`.

На верхньому рівні ієрархії чотири сигнали `Z[3], Z[2], Z[1], Z[0]` надходять на окремий 4-бітний блок вибору активної групи (Group Priority Encoder). Сигнали активності блоків формуються за пріоритетним правилом:

```
Active₃ = ¬Z[3]                                   [активний блок 3: є одиниця в діапазоні 63..48]
Active₂ = Z[3] ∧ ¬Z[2]                            [активний блок 2: блок 3 нульовий, але блок 2 містить одиницю]
Active₁ = Z[3] ∧ Z[2] ∧ ¬Z[1]                     [активний блок 1: блоки 3 і 2 нульові, блок 1 містить одиницю]
Active₀ = Z[3] ∧ Z[2] ∧ Z[1] ∧ ¬Z[0]              [активний блок 0: блоки 3, 2, 1 нульові, блок 0 містить одиницю]
```

Старші розряди 6-бітного індексу `Y[5:4]` визначаються виключно номером активного 16-бітного блоку:

```
Y₅ = Active₃ ∨ Active₂                           [одиниця розташована у верхній половині 64-бітного слова]
Y₄ = Active₃ ∨ Active₁                           [одиниця розташована в непарному 16-бітному блоці]
```

Молодші чотири розряди `Y[3:0]` вибираються із локальних індексів `y[3]..y[0]` за допомогою чотириканального мультиплексора:

```
Y[3:0] = (Active₃ ∧ y[3]) ∨ (Active₂ ∧ y[2]) ∨ (Active₁ ∧ y[1]) ∨ (Active₀ ∧ y[0])
```

Кількість провідних нулів (CLZ) отримується інверсією або відніманням знайденої позиції старшого біта від розрядності слова:

```
CLZ(D) = 63 - Y(D)             [де Y(D) — 6-бітне число від 0 до 63]
```

Оцінимо сумарну затримку такого дерева. Для слова розрядністю `W` кількість ієрархічних рівнів дорівнює `log₂(W)`. Кожен рівень додає затримку одного каскаду логічних елементів (NOR для визначення нуля блоку + MUX для вибору результату). Для 64-бітного операнда глибина логіки становить рівно 6 вентильних переходів:

```
Затримка = ⌈log₂(64)⌉ · τ_gate = 6 · τ_gate
```

Для сучасних напівпровідникових техпроцесів (TSMC N5/N3, Intel 4) затримка перемикання базового інвертора `τ_gate` становить близько 30–50 пікосекунд (`0.03–0.05` нс). Отже, вся схема 64-бітного пріоритетного шифратора спрацьовує приблизно за 0.25–0.30 нс, що дозволяє виконувати інструкції `LZCNT`, `TZCNT` та `CLZ` за один такт конвеєра на тактових частотах понад 5.0 ГГц.

### 3. Компресорне дерево Воллеса (Wallace Tree) для операції POPCNT

Операція підрахунку одиниць (Population Count) принципово відрізняється від пошуку першого біта: вона не може відкинути молодші біти після знаходження першої одиниці. Необхідно скласти 64 однорозрядні числа, кожне з яких має вагу `2⁰ = 1`.

Традиційний суматор із послідовним переносом (Ripple-Carry Adder) витрачає час, пропорційний кількості бітів O(N), оскільки сигнал переносу повинен послідовно пройти крізь усі 64 розряди.

Австралійський комп'ютерний інженер Кріс Воллес (Chris Wallace) у 1964 році запропонував структуру швидкісного множника на базі дерев суматорів зі збереженням переносу (Carry-Save Adders, CSA), яка сьогодні є основою апаратного блоку `POPCNT`.

Один компресор 3:2 (повний однорозрядний двійковий суматор) приймає на вхід три біти однакової ваги `2ᵏ` (`A, B, C`) і формує два вихідні сигнали:
- Біт суми `S` тієї ж ваги `2ᵏ`;
- Біт переносу `C_out` подвоєної ваги `2ᵏ⁺¹`.

Булеві рівняння компресора 3:2 мають вигляд:

```
S = A ⊕ B ⊕ C                 [порозрядна сума за модулем 2]
C_out = (A ∧ B) ∨ (B ∧ C) ∨ (A ∧ C)  [сигнал мажоритарної функції / переносу]
```

Головна перевага Carry-Save суматора полягає в тому, що вихід переносу `C_out` не розповсюджується горизонтально сусіднім коміркам. Він просто передається на наступний ярус дерева у стовпчик вищої вагової категорії. Завдяки цьому всі суматори одного ярусу працюють абсолютно незалежно та паралельно.

#### Поярусна матриця ваг компресії 64 входів

Простежимо точний розподіл кількості бітів за вагами `2⁰..2⁶` на кожному ярусі дерева Воллеса:

```
Ярус 0 (вхід):     64 біти ваги 2⁰.
Ярус 1 (21 CSA):   21 біт (вага 2⁰) + 1 прямий біт + 21 біт переносу (вага 2¹) = 22 біти (2⁰), 21 біт (2¹).
Ярус 2 (14 CSA):   7 бітів (вага 2⁰) + 1 прямий біт, 7 бітів (вага 2¹) + 7 бітів (вага 2²) = 8 бітів (2⁰), 14 бітів (2¹), 7 бітів (2²).
Ярус 3 (9 CSA):    3 біти (2⁰), 6 бітів (2¹), 6 бітів (2²), 5 бітів (2³).
Ярус 4 (6 CSA):    2 біти (2⁰), 3 біти (2¹), 4 біти (2²), 3 біти (2³), 2 біти (2⁴).
Ярус 5 (4 CSA):    1 біт (2⁰), 2 біти (2¹), 2 біти (2²), 2 біти (2³), 1 біт (2⁴), 1 біт (2⁵).
Ярус 6:            Формування двох 7-бітних векторів: Суми S[6:0] та Переносу C[6:0].
```

Кількість рівнів дерева компресії зменшується за геометричною прогресією з коефіцієнтом `3/2 = 1.5`:

```
Кількість ярусів = ⌈log₁.₅(64 / 2)⌉ = 6 рівнів компресії
```

На виході шостого ярусу утворюються лише два 7-бітні двійкові вектори: вектор сум `S` та вектор переносів `C`. Вони подаються на вхід швидкого паралельного суматора з передбаченням переносу (Carry-Lookahead Adder, CLA), який за 2–3 вентильні затримки обчислює остаточну 7-бітну суму в діапазоні від `0` до `64`.

Сумарна затримка компресорного дерева Воллеса разом із фінальним суматором складає близько 8–9 вентильних затримок, що дозволяє виконувати інструкцію `POPCNT` за 1–2 такти процесора з темпом видачі (*throughput*) в один такт.

### 4. Алгебраїчне виведення програмного алгоритму SWAR Popcount

Коли апаратна інструкція `POPCNT` відсутня (наприклад, у старих процесорах або мікроконтролерах), для підрахунку одиниць застосовують паралельний алгоритм SWAR (*SIMD Within A Register*).

Розглянемо математичне виведення класичного алгоритму:

:::tabs
```c
#include <stdint.h>

uint32_t swar_popcount64(uint64_t x) {
    x = x - ((x >> 1) & 0x5555555555555555ULL);
    x = (x & 0x3333333333333333ULL) + ((x >> 2) & 0x3333333333333333ULL);
    x = (x + (x >> 4)) & 0x0F0F0F0F0F0F0F0FULL;
    return (uint32_t)((x * 0x0101010101010101ULL) >> 56);
}
```
```cpp
#include <cstdint>

[[nodiscard]] constexpr std::uint32_t swar_popcount64(std::uint64_t x) noexcept {
    x = x - ((x >> 1) & 0x5555555555555555ULL);
    x = (x & 0x3333333333333333ULL) + ((x >> 2) & 0x3333333333333333ULL);
    x = (x + (x >> 4)) & 0x0F0F0F0F0F0F0F0FULL;
    return static_cast<std::uint32_t>((x * 0x0101010101010101ULL) >> 56);
}
```
:::

#### Доказ кроку 1: Попарне додавання бітів

Розглянемо довільну пару сусідніх бітів `(b₁, b₀)`. Числове значення цієї 2-бітної комбінації дорівнює:

```
V = 2 · b₁ + b₀
```

Кількість одиниць у цій парі дорівнює сумі `b₁ + b₀`. Зауважимо алгебраїчну тотожність:

```
Сума = b₁ + b₀ = (2 · b₁ + b₀) - b₁ = V - ⌊V / 2⌋
```

Зсув числа праворуч на 1 біт `x >> 1` із маскою `0x5555...` (`0101 0101...₂`) виділяє значення `b₁` для кожної пари. Віднімання `x - ((x >> 1) & 0x5555...)` одночасно перетворює кожну 2-бітну пару на число від `0` до `2` (`00₂`, `01₂`, `10₂`), що дорівнює кількості одиниць у цій парі.

#### Доказ кроку 2 та 3: Об'єднання 4-бітних та 8-бітних блоків

На другому кроці маска `0x3333...` (`0011 0011...₂`) виділяє 2-бітні суми пар і додає їх зі зсунутими сумами, утворюючи 4-бітні підсумки (значення від `0` до `4` у кожному 4-бітному ніблі).

На третьому кроці сума `(x + (x >> 4)) & 0x0F0F...` додає сусідні 4-бітні підсумки, формуючи 8-бітні значення від `0` до `8` у кожному байті слова. Оскільки максимальне значення `8` поміщається в 4 біти, додавання не викликає міжбайтового переповнення.

#### Доказ кроку 4: Паралельне накопичення через множення

Множення 64-бітного числа на мультиплікативну константу `M = 0x0101010101010101ULL` еквівалентне додаванню всіх восьми байтів числа зі зсувами:

```
x · M = (B₇·2⁵⁶ + B₆·2⁴⁸ + ... + B₀) · (1 + 2⁸ + 2¹⁶ + ... + 2⁵⁶)
```

Найстарший байт результату (розряди 63..56) містить точну суму всіх восьми байтових полів:

```
Старший байт = B₇ + B₆ + B₅ + B₄ + B₃ + B₂ + B₁ + B₀
```

Фінальний зсув `>> 56` витягує старший байт, повертаючи точну кількість одиничних бітів у 64-бітному слові всього за 12 арифметичних операцій без жодного розгалуження.
