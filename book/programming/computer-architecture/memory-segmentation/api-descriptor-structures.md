# 📋 Структури дескрипторів сегментів, селекторів та шлюзів IA-32 і x86-64

Повний довідник двійкових форматів, структур пам'яті, системних регістрів та машинних угод сегментації архітектури x86 (IA-32 та x86-64).

### 1. Формат селектора сегмента (Segment Selector)

Селектор сегмента — це 16-бітний числовий ідентифікатор, який завантажується в сегментні регістри (CS, DS, SS, ES, FS, GS) для вибору запису в глобальній (GDT) або локальній (LDT) таблиці дескрипторів.

```
 15                                  3   2   1   0
+--------------------------------------+---+-------+
|                Index                 | T |  RPL  |
|               (13 бітів)             | I |(2 біти|
+--------------------------------------+---+-------+
```

Поле **Index** (біти 15..3) містить порядковий номер дескриптора в обраній таблиці від 0 до 8191. Оскільки розмір кожного дескриптора в пам'яті становить рівно 8 байтів, процесор апаратно зсуває це поле на 3 біти ліворуч (множить на 8) для обчислення точного байтового зсуву дескриптора відносно базової адреси таблиці.

Поле **TI** (*Table Indicator*, біт 2) вказує на цільову таблицю дескрипторів. Значення `0` вибирає глобальну таблицю GDT (*Global Descriptor Table*), спільну для всієї системи. Значення `1` вибирає локальну таблицю LDT (*Local Descriptor Table*), яка належить поточному процесу та адресується через системний регістр `LDTR`.

Поле **RPL** (*Requested Privilege Level*, біти 1..0) визначає запитаний рівень привілеїв (від 0 для найбільш привілейованого ядра ОС до 3 для непривілейованих прикладних програм). Це значення використовується процесором під час перевірок захисту при завантаженні селектора в сегментний регістр.

> ⚠️ **Нульовий селектор (*Null Selector*):** селектор зі значенням `Index = 0` та `TI = 0` (числові значення `0x0000`–`0x0003`) вказує на нульовий запис GDT. Архітектура IA-32 дозволяє завантажувати нульовий селектор у регістри даних (DS, ES, FS, GS) для позначення невикористовуваного сегмента, проте будь-яка спроба адресації пам'яті через такий регістр негайно викликає апаратний виняток загального захисту `#GP(0)`. Завантаження нульового селектора в регістри CS або SS заборонено на рівні інструкцій і одразу викликає `#GP(0)`.

### 2. Регістри таблиць дескрипторів (GDTR, IDTR, LDTR)

Для збереження розташування таблиць дескрипторів у фізичній або лінійній пам'яті процесор містить спеціалізовані внутрішні регістри керування:

- **Регістр GDTR (*Global Descriptor Table Register*):**
  У 32-бітному режимі IA-32 регістр містить 48-бітний псевдодескриптор:
  - `Limit` (біти 15..0): розмір таблиці в байтах мінус 1. Максимальне значення `0xFFFF` відповідає таблиці розміром 65 536 байтів (рівно 8192 дескриптори по 8 байтів кожен).
  - `Base Address` (біти 47..16): 32-бітна лінійна адреса початку масиву GDT у пам'яті.
  У 64-бітному режимі x86-64 розмір структури зростає до 80 бітів: 16 бітів межі та 64 біти повної канонічної базової адреси.
  Завантаження регістра виконується виключно в кільці 0 інструкцією `lgdt [mem]`, а читання доступне на будь-якому рівні через `sgdt [mem]`.

- **Регістр IDTR (*Interrupt Descriptor Table Register*):**
  Зберігає розташування таблиці дескрипторів переривань (IDT). Має ідентичний до GDTR двійковий формат (48 бітів у 32-біт та 80 бітів у 64-біт). Завантажується інструкцією `lidt`, читається через `sidt`.

- **Регістр LDTR (*Local Descriptor Table Register*):**
  На відміну від GDTR, цей регістр є звичайним 16-бітним селектором, який повинен вказувати на системний дескриптор типу LDT усередині таблиці GDT. Завантажується інструкцією `lldt reg16/mem16`. Під час завантаження процесор зчитує 8-байтовий дескриптор LDT із GDT та автоматично кешує його базу й межу в прихованій частині LDTR.

### 3. Структура 8-байтового дескриптора сегмента (IA-32)

Дескриптор сегмента займає 8 байтів (64 біти) і має складну розбиту структуру, зумовлену еволюцією від 24-бітної адресації процесора 80286 до 32-бітної в 80386:

```
 31             24 23 22 21 20 19      16 15 14 13 12 11        8 7              0
+-----------------+--+--+--+--+----------+--+-----+--+----------+-----------------+
|   Base [31:24]  |G |D/|L |A |  Limit   |P | DPL |S |   Type   |   Base [23:16]  |
|                 |  |B |  |V | [19:16]  |  |     |  |          |                 |
+-----------------+--+--+--+--+----------+--+-----+--+----------+-----------------+
|           Base Address [15:0]          |          Segment Limit [15:0]           |
+----------------------------------------+-----------------------------------------+
```

Розподіл полів дескриптора за байтами:
- **Байти 0..1 (біти 15..0):** `Limit [15:0]` — молодші 16 бітів межі сегмента.
- **Байти 2..3 (біти 31..16):** `Base [15:0]` — молодші 16 бітів базової лінійної адреси.
- **Байт 4 (біти 7..0):** `Base [23:16]` — середні 8 бітів базової адреси.
- **Байт 5 (біти 3..0):** `Type` — тип сегмента та атрибути доступу.
- **Байт 5 (біт 4):** `S` (*Descriptor Type*) — тип дескриптора: `1` для сегментів коду та даних, `0` для системних дескрипторів (TSS, LDT, шлюзи).
- **Байт 5 (біти 6..5):** `DPL` (*Descriptor Privilege Level*) — рівень привілеїв дескриптора (0..3).
- **Байт 5 (біт 7):** `P` (*Segment Present*) — ознака присутності сегмента в пам'яті (`1` — присутній, `0` — вивантажений на диск, звернення викликає виняток `#NP`).
- **Байт 6 (біти 3..0):** `Limit [19:16]` — старші 4 біти межі (разом утворюють 20-бітну межу).
- **Байт 6 (біт 4):** `AVL` (*Available for System*) — вільний біт для потреб операційної системи.
- **Байт 6 (біт 5):** `L` (*Long Mode*) — у 64-бітному режимі позначає 64-бітний код (`1` — режим 64 біти, `0` — режим 32-бітної сумісності). Для сегментів даних цей біт повинен бути встановлений у 0.
- **Байт 6 (біт 6):** `D/B` (*Default operation size / Big stack pointer*):
  - Для сегментів коду (`D`): `1` означає використання 32-бітних адрес та операндів за замовчуванням; `0` означає 16-бітні операнди (сумісність із 80286/8086).
  - Для звичайних сегментів даних та стека (`B`): `1` вказує на 32-бітний регістр вказівника стека ESP, `0` — на 16-бітний SP.
  - Для сегментів, що ростуть униз (*Expand-Down*): `1` встановлює верхню межу діапазону в 4 ГБ (`0xFFFFFFFF`), `0` — у 64 КБ (`0xFFFF`).
- **Байт 6 (біт 7):** `G` (*Granularity*) — біт гранулярності:
  - Якщо `G = 0`, значення поля Limit інтерпретується в байтах (розмір сегмента від 1 байта до 1 МБ).
  - Якщо `G = 1`, значення поля Limit множиться на 4096 (розмір 4 КБ сторінки). Процесор апаратно доповнює 20-бітну межу дванадцятьма одиницями праворуч: максимальна межа `0xFFFFF` перетворюється на `0xFFFFFFFF` (4 Гігабайти).
- **Байт 7 (біти 7..0):** `Base [31:24]` — старші 8 бітів базової лінійної адреси сегмента.

### 4. Детальне кодування поля Type для сегментів коду та даних (S = 1)

Поле `Type` (4 біти) визначає характер операцій, дозволених процесором над пам'яттю сегмента.

#### Сегменти даних (Type[3] = 0):
Біти поля інтерпретуються як `0 | E | W | A`:
- **E** (*Expand-Down*, біт 2): `0` — звичайний сегмент (зсув від 0 до Limit); `1` — сегмент росте вниз (стек, дозволені адреси строго від Limit+1 до максимальної межі 64 КБ або 4 ГБ).
- **W** (*Writable*, біт 1): `0` — сегмент лише для читання (спроба запису викликає `#GP`); `1` — читання та запис дозволені.
- **A** (*Accessed*, біт 0): встановлюється процесором в `1` під час першого звернення до сегмента (корисно для статистики ОС).

| Біти Type | Шістнадцяткове | Назва сегмента даних | Поведінка та обмеження |
| :--- | :--- | :--- | :--- |
| `0000` | `0x0` | Read-Only | Дозволено лише читання; запис заборонено. |
| `0001` | `0x1` | Read-Only, Accessed | Лише читання; біт A встановлено. |
| `0010` | `0x2` | Read/Write | Дозволено читання та модифікацію даних. |
| `0011` | `0x3` | Read/Write, Accessed | Читання та запис; біт A встановлено. |
| `0100` | `0x4` | Expand-Down Read-Only | Стек росте вниз; лише читання. |
| `0101` | `0x5` | Expand-Down Read-Only, Accessed | Стек росте вниз; лише читання з фіксацією. |
| `0110` | `0x6` | Expand-Down Read/Write | Стек росте вниз; читання та запис (стандартний сегмент стека SS). |
| `0111` | `0x7` | Expand-Down Read/Write, Accessed | Стек росте вниз; читання та запис із фіксацією. |

#### Сегменти коду (Type[3] = 1):
Біти поля інтерпретуються як `1 | C | R | A`:
- **C** (*Conforming*, біт 2): `0` — непідпорядкований код (виконання дозволено лише тоді, коли CPL дорівнює DPL); `1` — підпорядкований код (може викликатися з менш привілейованих кілець без зміни CPL).
- **R** (*Readable*, біт 1): `0` — сегмент лише для виконання (спроба читання констант інструкцією `mov` викликає `#GP`); `1` — виконання та читання дозволені.
- **A** (*Accessed*, біт 0): встановлюється процесором в `1` при вибірці інструкцій із сегмента.

| Біти Type | Шістнадцяткове | Назва сегмента коду | Поведінка та обмеження |
| :--- | :--- | :--- | :--- |
| `1000` | `0x8` | Execute-Only | Тільки виконання інструкцій; читання даних заборонено. |
| `1001` | `0x9` | Execute-Only, Accessed | Тільки виконання з фіксацією звернення. |
| `1010` | `0xA` | Execute/Read | Стандартний сегмент коду: виконання та читання констант. |
| `1011` | `0xB` | Execute/Read, Accessed | Виконання та читання з фіксацією звернення. |
| `1100` | `0xC` | Conforming, Execute-Only | Підпорядкований код лише для виконання. |
| `1101` | `0xD` | Conforming, Execute-Only, Accessed | Підпорядкований код лише для виконання, з фіксацією. |
| `1110` | `0xE` | Conforming, Execute/Read | Підпорядкований код: виконання та читання на рівні викликача. |
| `1111` | `0xF` | Conforming, Execute/Read, Accessed | Підпорядкований код для виконання та читання, з фіксацією. |

### 5. Системні дескриптори та шлюзи (S = 0)

Коли біт `S` встановлено в `0`, дескриптор описує системну керуючу структуру ядра.

У 32-бітному режимі IA-32 системні дескриптори мають 8 байтів:
- `0x2`: **LDT Descriptor** — вказує на масив локальної таблиці дескрипторів процесу.
- `0x9`: **32-bit TSS (Available)** — вільний сегмент стану завдання.
- `0xB`: **32-bit TSS (Busy)** — зайнятий сегмент стану завдання (запобігає рекурсивному перемиканню).
- `0x4`: **32-bit Call Gate** — шлюз міжрівневого виклику підпрограм.
- `0x5`: **Task Gate** — шлюз апаратного перемикання завдань через TSS.
- `0xE`: **32-bit Interrupt Gate** — шлюз переривання в IDT (при вході автоматично скидає прапорець переривань `EFLAGS.IF = 0`).
- `0xF`: **32-bit Trap Gate** — шлюз винятків та пасток в IDT (залишає `EFLAGS.IF` незмінним).

#### Структура 32-бітного шлюзу виклику (Call Gate Descriptor):
```
 31                               16 15 14 13 12 11     8 7   5 4         0
+-----------------------------------+--+-----+--+--------+-----+-----------+
|          Target Offset [31:16]    |P | DPL |0 |  0100  | 000 |Param Count|
+-----------------------------------+--+-----+--+--------+-----+-----------+
|       Target Code Selector [15:0] |         Target Offset [15:0]          |
+-----------------------------------+---------------------------------------+
```

Поле **Param Count** (біти 4..0 другого слова) вказує процесору кількість 32-бітних слів параметрів, які апаратний блок переходу повинен автоматично скопіювати зі стека викликача (Ring 3) на новий стек ядра (Ring 0) під час переходу через шлюз.

#### Розширення системних дескрипторів у x86-64:
У 64-бітному режимі всі системні дескриптори подвоюють свій розмір до 16 байтів (128 бітів). Байти 8..11 містять старшу частину 64-бітної адреси `Base/Offset [63:32]`, а байти 12..15 зарезервовані процесором і повинні бути обнулені.

### 6. Сегмент стану завдання (Task State Segment, TSS) та бітова карта портів I/O

- **32-бітний TSS (розмір 104 байти):**
  Містить повні копії регістрів EAX, ECX, EDX, EBX, ESP, EBP, ESI, EDI, EIP, EFLAGS, CR3, селекторів сегментів CS, DS, SS, ES, FS, GS, LDTR, а також поля `ESP0:SS0`, `ESP1:SS1`, `ESP2:SS2` (вершини стеків для кілець привілеїв 0, 1, 2) та 16-бітне поле зсуву до бітової карти дозволів портів вводу/виводу (*I/O Permission Bit Map*).
  Апаратне перемикання завдань у 32-бітному режимі завантажувало новий стан процесора інструкцією `ltr selector` або стрибком `jmp FarTssSelector`.

- **Бітова карта дозволів вводу/виводу (*I/O Permission Bit Map*):**
  Розташована в кінці структури TSS. Кожен біт карти відповідає одному з 65 536 портів вводу/виводу процесора (`in`/`out`). Значення `0` дозволяє доступ з кільця 3 без виклику винятку; значення `1` генерує `#GP(0)`. Карта повинна обов'язково завершуватися фінальним байтом `0xFF`, аби процесор мав змогу безпечно перевірити дозволи для 16-бітних та 32-бітних операцій введення/виведення, які перетинають межу байтів.

- **64-бітний TSS (розмір 104 байти):**
  У 64-бітному режимі апаратне перемикання завдань повністю скасовано на користь швидкого програмного перемикання контексту. TSS зберігається виключно заради таких критичних механізмів:
  1. `RSP0`, `RSP1`, `RSP2` — 64-бітні покажчики стеків для переходу в кільця 0..2 при виникненні системних викликів та переривань;
  2. `IST1`..`IST7` (*Interrupt Stack Table*) — сім 64-бітних покажчиків на виділені стеки обробки критичних винятків ядра (зокрема `#DF` *Double Fault*, `#NMI`, `#MC` *Machine Check*), що гарантує працездатність обробника навіть при повному переповненні основного стека ядра;
  3. 16-бітний зсув до бітової карти дозволів вводу/виводу (I/O Map Base). Регістр завантажується інструкцією `ltr`.

### 7. Специфічні регістри моделі (MSR) для FS/GS у 64-бітному режимі

В архітектурі AMD64/Intel 64 лінійні базові адреси для сегментів FS та GS налаштовуються через 64-бітні регістри керування MSR (*Model-Specific Registers*):

| Символьна назва MSR | Шістнадцятковий номер | Рівень доступу | Функціональне призначення |
| :--- | :--- | :--- | :--- |
| `IA32_FS_BASE` | `0xC0000100` | Ring 0 (або Ring 3 при `CR4.FSGSBASE=1`) | 64-бітна лінійна базова адреса сегмента `FS`. Використовується системними бібліотеками (glibc, musl) для адресації локальної пам'яті потоку (TLS). |
| `IA32_GS_BASE` | `0xC0000101` | Ring 0 (або Ring 3 при `CR4.FSGSBASE=1`) | Поточна 64-бітна базова адреса сегмента `GS`. |
| `IA32_KERNEL_GS_BASE` | `0xC0000102` | Ring 0 | Тіньовий базовий регістр ядра для `GS`. Інструкція `swapgs` атомарно міняє значення `IA32_GS_BASE` та `IA32_KERNEL_GS_BASE` місцями при вході та виході з ядра. |

Інструкції прямого читання та запису бази сегментів `rdfsbase`, `wrfsbase`, `rdgsbase`, `wrgsbase` виконуються за 1 такт і доступні в просторі користувача, якщо операційна система встановила біт 16 регістра керування `CR4.FSGSBASE = 1`.

### 8. Апаратна послідовність верифікації дескриптора при завантаженні селектора

Коли процесор виконує інструкцію завантаження сегментного регістра (наприклад, `mov ds, ax` або міжсегментний перехід `ljmp 0x08:target`), мікрокод ядра виконує суворий багатокроковий алгоритм апаратної верифікації:

1. **Перевірка нульового селектора:** Якщо селектор має `Index = 0` та `TI = 0`, процесор дозволяє завантаження в DS, ES, FS, GS, але очищає біт валідності в тіньовому кеші. Завантаження в CS або SS негайно викликає `#GP(0)`.
2. **Перевірка межі таблиці дескрипторів:** Процесор перевіряє умову `(Index * 8 + 7) <= GDTR.Limit` (або `LDTR.Limit`). Якщо дескриптор виходить за межі виділеної пам'яті таблиці, генерується збій `#GP(selector)`.
3. **Перевірка типу дескриптора:** Для регістра CS дескриптор повинен бути сегментом коду (`S=1`, `Type[3]=1`). Для SS це має бути сегмент даних із дозволом на запис (`S=1`, `Type[3]=0`, `Writable=1`). Спроба завантажити сегмент коду в SS або сегмент даних лише для читання генерує `#GP(selector)`.
4. **Перевірка привілеїв доступу:**
   - Для сегментів даних (DS, ES, FS, GS): перевіряється формула `max(CPL, RPL) <= DPL`.
   - Для стека (SS): вимагається сувора рівність `CPL == RPL == DPL`. Невідповідність викликає `#GP(selector)`.
   - Для коду (CS): для непідпорядкованих сегментів вимагається `CPL == DPL` та `RPL <= DPL`.
5. **Перевірка присутності в пам'яті:** Процесор перевіряє біт `Present` (байт 5, біт 7). Якщо `P = 0`, генерація винятку відрізняється: для регістра SS генерується `#SS(selector)` (*Stack Fault*), а для решти регістрів — `#NP(selector)` (*Segment Not Present*). Під час виклику обробника винятку процесор автоматично кладе на стек ядра числовий код помилки (*Error Code*), молодші 16 бітів якого містять селектор, що спричинив збій, біт `TI`, а також біт `EXT` (вказує, чи виняток викликано зовнішньою подією апаратного переривання).
6. **Заповнення тіньового кешу та фіксація доступу:** Процесор декодує базову адресу, межу та атрибути в прихований тіньовий регістр, встановлює біт `Accessed` (`Type[0] = 1`) у вихідній таблиці GDT/LDT у пам'яті (виконуючи атомарний запис) і завершує виконання інструкції.

#include <stdint.h>
#include <stdbool.h>

#pragma pack(push, 1)

/* 16-бітний селектор сегмента */
typedef union {
    uint16_t raw;
    struct {
        uint16_t rpl   : 2;  /* Запитаний рівень привілеїв (0..3) */
        uint16_t ti    : 1;  /* 0 = GDT, 1 = LDT */
        uint16_t index : 13; /* Номер запису в таблиці дескрипторів */
    };
} segment_selector_t;

/* 8-байтовий дескриптор сегмента IA-32 */
typedef struct {
    uint16_t limit_low;       /* Межа [15:0] */
    uint16_t base_low;        /* База [15:0] */
    uint8_t  base_mid;        /* База [23:16] */
    uint8_t  type        : 4; /* Тип сегмента та права доступу */
    uint8_t  s           : 1; /* 1 = Код/Дані, 0 = Системний дескриптор */
    uint8_t  dpl         : 2; /* Рівень привілеїв дескриптора (0..3) */
    uint8_t  present     : 1; /* 1 = Сегмент присутній у пам'яті */
    uint8_t  limit_high  : 4; /* Межа [19:16] */
    uint8_t  avl         : 1; /* Вільний біт для використання ОС */
    uint8_t  long_mode   : 1; /* 1 = 64-бітний код (x86-64 Long Mode) */
    uint8_t  db_size     : 1; /* 1 = 32-бітні операнди/стек, 0 = 16-бітні */
    uint8_t  granularity : 1; /* 1 = Межа в блоках по 4 КБ, 0 = у байтах */
    uint8_t  base_high;       /* База [31:24] */
} segment_descriptor_t;

/* 16-байтовий системний дескриптор x86-64 (LDT, TSS, Call Gate) */
typedef struct {
    uint16_t limit_low;
    uint16_t base_low;
    uint8_t  base_mid_low;
    uint8_t  type        : 4;
    uint8_t  s           : 1;
    uint8_t  dpl         : 2;
    uint8_t  present     : 1;
    uint8_t  limit_high  : 4;
    uint8_t  avl         : 1;
    uint8_t  reserved0   : 2;
    uint8_t  granularity : 1;
    uint8_t  base_mid_high;
    uint32_t base_high;       /* Базова адреса [63:32] */
    uint32_t reserved1;       /* Має містити нуль */
} system_descriptor64_t;

/* 48-бітний псевдодескриптор GDTR / IDTR для 32-бітного режиму */
typedef struct {
    uint16_t limit;           /* Розмір таблиці в байтах - 1 */
    uint32_t base_address;    /* Лінійна адреса початку масиву GDT */
} gdtr32_t;

/* 80-бітний псевдодескриптор GDTR / IDTR для 64-бітного режиму */
typedef struct {
    uint16_t limit;
    uint64_t base_address;
} gdtr64_t;

#pragma pack(pop)

/* Складання 32-бітної бази з розрізнених полів дескриптора */
static inline uint32_t descriptor_decode_base32(const segment_descriptor_t *d) {
    return ((uint32_t)d->base_high << 24) |
           ((uint32_t)d->base_mid  << 16) |
           ((uint32_t)d->base_low);
}

/* Обчислення реальної межі сегмента в байтах */
static inline uint32_t descriptor_decode_limit_bytes(const segment_descriptor_t *d) {
    uint32_t raw_limit = ((uint32_t)d->limit_high << 16) | (uint32_t)d->limit_low;
    if (d->granularity) {
        return (raw_limit << 12) | 0xFFF; /* Масштабування на 4096 байтів */
    }
    return raw_limit;
}

/* Завантаження регістра GDTR у 64-бітному режимі */
static inline void load_gdtr64(const gdtr64_t *gdtr) {
    __asm__ volatile("lgdt %0" : : "m"(*gdtr) : "memory");
}

#include <cstdint>
#include <bit>
#include <span>
#include <array>

#pragma pack(push, 1)

/* Типізований селектор сегмента x86 у стандарті C++20 */
struct SegmentSelector {
    uint16_t raw{0};

    [[nodiscard]] constexpr uint8_t rpl() const noexcept {
        return static_cast<uint8_t>(raw & 0x03);
    }

    [[nodiscard]] constexpr bool is_ldt() const noexcept {
        return (raw & 0x04) != 0;
    }

    [[nodiscard]] constexpr uint16_t index() const noexcept {
        return raw >> 3;
    }

    static constexpr SegmentSelector from_parts(uint16_t idx, bool ldt, uint8_t priv_level) noexcept {
        return SegmentSelector{
            static_cast<uint16_t>((idx << 3) | (ldt ? 0x04 : 0x00) | (priv_level & 0x03))
        };
    }
};

/* Дескриптор сегмента IA-32 */
struct SegmentDescriptor {
    uint16_t limit_low{0};
    uint16_t base_low{0};
    uint8_t  base_mid{0};
    uint8_t  type : 4 {0};
    uint8_t  s : 1 {1};
    uint8_t  dpl : 2 {0};
    uint8_t  present : 1 {1};
    uint8_t  limit_high : 4 {0};
    uint8_t  avl : 1 {0};
    uint8_t  long_mode : 1 {0};
    uint8_t  db_size : 1 {1};
    uint8_t  granularity : 1 {1};
    uint8_t  base_high{0};

    [[nodiscard]] constexpr uint32_t base() const noexcept {
        return (static_cast<uint32_t>(base_high) << 24) |
               (static_cast<uint32_t>(base_mid)  << 16) |
               (static_cast<uint32_t>(base_low));
    }

    [[nodiscard]] constexpr uint32_t limit_in_bytes() const noexcept {
        const uint32_t lim = (static_cast<uint32_t>(limit_high) << 16) | limit_low;
        return granularity ? ((lim << 12) | 0xFFF) : lim;
    }

    /* Фабрика плоского сегмента (Flat Model 4 GB) */
    static constexpr SegmentDescriptor make_flat(uint8_t seg_type, uint8_t priv_dpl, bool code_64) noexcept {
        SegmentDescriptor desc{};
        desc.base_low = 0;
        desc.base_mid = 0;
        desc.base_high = 0;
        desc.limit_low = 0xFFFF;
        desc.limit_high = 0x0F;
        desc.type = seg_type;
        desc.s = 1;
        desc.dpl = priv_dpl;
        desc.present = 1;
        desc.granularity = 1; /* Множення на 4 КБ -> 4 ГБ */
        desc.db_size = code_64 ? 0 : 1;
        desc.long_mode = code_64 ? 1 : 0;
        return desc;
    }
};

/* 80-бітний псевдодескриптор GDTR у 64-бітному режимі */
struct alignas(2) Gdtr64 {
    uint16_t limit{0};
    uint64_t base_address{0};

    explicit constexpr Gdtr64(std::span<const SegmentDescriptor> gdt_view) noexcept
        : limit(static_cast<uint16_t>(gdt_view.size_bytes() - 1)),
          base_address(reinterpret_cast<uint64_t>(gdt_view.data())) {}

    void install() const noexcept {
        asm volatile("lgdt %0" : : "m"(*this) : "memory");
    }
};

#pragma pack(pop)
