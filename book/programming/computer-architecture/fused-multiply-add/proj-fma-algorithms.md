# ⚙️ Алгоритми високої точності та швидкодії на базі FMA

Апаратна інструкція FMA (*Fused Multiply-Add*, `a × b + c`) є одним із найважливіших інструментів у сучасному чисельному аналізі, комп'ютерній графіці, фізичному моделюванні та системному програмуванні. Вона докорінно змінює підходи до розробки математичного програмного забезпечення, надаючи інженерові дві фундаментальні переваги:

1. **Математична точність і відстеження похибок.** Завдяки виконанню множення без проміжного зрізання розрядів FMA дозволяє за одну-єдину машинну інструкцію видобувати точну похибку округлення операції множення. Це перетворює громіздкі алгоритми корекції похибок на короткі, ефективні ланцюжки команд.
2. **Апаратна продуктивність і пропускна здатність.** Поєднуючи дві базові операції в єдиний конвеєрний цикл, FMA подвоює теоретичну кількість операцій із плаваючою комою за такт (*FLOPS*), проте вимагає від програміста глибокого розуміння мікроархітектури процесора для подолання затримок конвеєра та правильного насичення регістрового файлу.

Нижче наведено детальний розбір ключових алгоритмів: відстеження похибок через Fast2Mult, точного обчислення дискримінанта квадратного рівняння за Вільямом Кехеном, компенсованої схеми Горнера для многочленів, точного скалярного добутку Огіти-Румпа-Оїші (Dot2), надійного геометричного векторного добутку, чергування операцій у метелику ШПФ (FFT Butterfly), векторизованого ядра AVX2 / FMA3 з ручним розгортанням конвеєра, а також керування поведінкою компілятора та системними прапорцями FPU.

### 1. Точне розкладання добутку: алгоритм Fast2Mult

В обчислювальній математиці високої точності (зокрема в бібліотеках розширеної точності *double-double*, що забезпечують 106 бітів мантиси за допомогою пари стандартних чисел `double`) базовою операцією є точне розкладання добутку двох чисел:

```
a × b = x + y
```

де `x = round(a × b)` — стандартне машинне число, округлене до найближчого значення за правилами IEEE 754, а `y` — залишок округлення, який точно дорівнює математичній різниці `(a × b) − x`.

#### Порівняння: класичний алгоритм Деккера проти FMA

До появи апаратної підтримки FMA знаходження залишкового члена `y` було надзвичайно повільною процедурою. Алгоритм Теодоруса Деккера (*Theodorus Dekker*, 1971) вимагав штучного розщеплення кожного 53-бітного числа на дві 26-бітні частини за допомогою спеціальної константи `C = 2²⁷ + 1 = 134217729.0`. Загалом алгоритм Деккера вимагав **17 операцій із плаваючою комою** (чотири множення і тринадцять додавань/віднімань) для кожного обчислення похибки добутку двох чисел!

За наявності апаратної інструкції FMA алгоритм Деккера спрощується до двох коротких операцій (алгоритм Fast2Mult):

```
x = a * b
y = fma(a, b, -x)
```

#### Математичне доведення точності Fast2Mult

Чому вираз `fma(a, b, -x)` повертає абсолютно точний залишок без виникнення нової похибки?
- Нехай числа `a` та `b` належать формату IEEE 754 binary64 (53 біти мантиси).
- Точний математичний добуток `a × b` має мантису довжиною не більше ніж `53 + 53 = 106` бітів.
- Число `x = round(a × b)` містить старші 53 біти цього добутку.
- Різниця `(a × b) − x` складається виключно з молодших 53 бітів незрізаного добутку.
- Оскільки всередині апаратного блоку FMA добуток `a × b` формується на 106-бітному акумуляторі, а віднімання `x` відбувається до фінального нормалізування та округлення, результат різниці містить не більше 53 значущих бітів. Він ідеально вкладається в стандартний формат `double` без повторного округлення.

Це скорочення з 17 інструкцій до 2 забезпечує прискорення програмної емуляції розширеної точності майже на порядок, що робить моделювання фізичних систем на порядки швидшим без використання сторонніх повільних бібліотек довільної точності.

### 2. Точний розрахунок дискримінантів: алгоритм Вільяма Кехена

Класична формула дискримінанта квадратного рівняння `D = b² - 4ac` є хрестоматійним прикладом **катастрофічного скасування** (*catastrophic cancellation*) в обчисленнях плаваючої коми. Коли добуток `b²` майже дорівнює за величиною `4ac`, їхня різниця втрачає майже всі значущі розряди мантиси.

Розглянемо числовий приклад із точними коефіцієнтами:

```
a = 1.0
b = 3344556600.0
c = 2796523490714705.0
```

Точне аналітичне значення дискримінанта:

```
D = b² - 4ac
  = (3344556600)² - 4 × 1 × 2796523490714705
  = 11186093962858820000 - 11186093962858820000
  = 0
```

У стандартній арифметиці типу `double` (IEEE 754 float64) мантиса має 53 біти (приблизно 15–17 десяткових цифр). Значення `b² = 11186093962858820000` вимагає 67 двійкових розрядів для точного запису. Під час звичайного множення `p = b * b` молодші 14 бітів відтинаються. Аналогічно округлюється другий добуток `q = 4.0 * a * c`.

У результаті наївне обчислення `(b * b) - (4.0 * a * c)` повертає значення `1.0` (або навіть від'ємне число залежно від режиму округлення процесора). Комп'ютерна програма робить хибний висновок, що квадратне рівняння має два різні дійсні корені або не має дійсних коренів взагалі, тоді як насправді дискримінант строго дорівнює нулю і корінь рівно один.

#### Механізм компенсації Кехена

Професор Вільям Кехен (*William Kahan*) запропонував алгоритм, який використовує інструкцію FMA для відстеження похибок обох множень:

1. Обчислюємо округлений перший добуток: `p = b * b`.
2. За допомогою Fast2Mult знаходимо точний втрачений хвіст першого множення: `dp = fma(b, b, -p)`.
3. Обчислюємо другий добуток: `q = 4.0 * a * c`.
4. Знаходимо точний втрачений хвіст другого множення: `dq = fma(4.0 * a, c, -q)`.
5. Обчислюємо різницю старших частин `p - q` та додаємо різницю молодших хвостів `dp - dq`:

```
D = (p - q) + (dp - dq)
```

Якщо старші частини `p` і `q` повністю збігаються (катастрофічне скасування старших бітів), різниця `p - q` дає нуль, а точний результат формується залишками `dp - dq`.

#### Реалізація алгоритму Кехена

:::tabs
```c
#include <stdio.h>
#include <math.h>

// Обчислення дискримінанта b^2 - 4ac за алгоритмом Кехена з FMA
double discriminant_kahan(double a, double b, double c) {
    double p = b * b;
    double dp = fma(b, b, -p);       // Точна похибка першого множення

    double q = 4.0 * a * c;
    double dq = fma(4.0 * a, c, -q); // Точна похибка другого множення

    double d = (p - q) + (dp - dq);  // Компенсована різниця
    return d;
}

int main(void) {
    double a = 1.0;
    double b = 3344556600.0;
    double c = 2796523490714705.0;

    double naive = (b * b) - (4.0 * a * c);
    double exact = discriminant_kahan(a, b, c);

    printf("Наївне b*b - 4ac: %.10e\n", naive);
    printf("Алгоритм Кехена:  %.10e\n", exact);
    return 0;
}
```
```cpp
#include <iostream>
#include <cmath>
#include <iomanip>

// Обчислення дискримінанта b^2 - 4ac за алгоритмом Кехена з FMA
[[nodiscard]] constexpr double discriminant_kahan(double a, double b, double c) noexcept {
    const double p = b * b;
    const double dp = std::fma(b, b, -p);       // Точна похибка першого множення

    const double q = 4.0 * a * c;
    const double dq = std::fma(4.0 * a, c, -q); // Точна похибка другого множення

    return (p - q) + (dp - dq);
}

int main() {
    constexpr double a = 1.0;
    constexpr double b = 3344556600.0;
    constexpr double c = 2796523490714705.0;

    const double naive = (b * b) - (4.0 * a * c);
    const double exact = discriminant_kahan(a, b, c);

    std::cout << std::scientific << std::setprecision(10);
    std::cout << "Наївне b*b - 4ac: " << naive << '\n';
    std::cout << "Алгоритм Кехена:  " << exact << '\n';
    return 0;
}
```

### 3. Компенсована схема Горнера для обчислення многочленів

Обчислення значення многочлена `P(x) = aₙxⁿ + aₙ₋₁xⁿ⁻¹ + ... + a₁x + a₀` у заданій точці `x` за класичною схемою Горнера полягає в послідовному згортанні виразу з найстаршого коефіцієнта до вільного члена:

```
P(x) = (...((aₙ × x + aₙ₋₁) × x + aₙ₋₂) × x + ...) × x + a₀
```

У наївній схемі кожен крок циклу містить два незалежні джерела похибок: множення на `x` та додавання коефіцієнта `aᵢ`. На многочленах високих степенів або біля кратних коренів похибка накопичується за степеневим законом.

Просте використання `fma(acc, x, a[i])` скорочує кількість кроків округлення рівно вдвічі, що суттєво покращує результат. Проте дослідники Стефані Грайо (*Stef Graillat*), Філіп Ланглуа (*Philippe Langlois*) та Ніколас Лауз (*Nicolas Louvet*) пішли далі й розробили **компенсовану схему Горнера** (*Compensated Horner Scheme*).

#### Принцип роботи компенсованої схеми

На кожній ітерації `i` алгоритм виконує крок Горнера, паралельно видобуваючи обидва залишки:
1. Похибка множення `pi = fma(s, x, -p)`, де `p = s * x`.
2. Похибка додавання `sigma`, яка видобувається за допомогою класичного алгоритму точного додавання 2Sum (Кнута-Деккера).

Сума `pi + sigma` є абсолютно точною похибкою одного кроку Горнера. Усі ці елементарні похибки паралельно накопичуються в додатковий корекційний многочлен `P_err(x)`. Наприкінці обчислення значення `P_err(x)` додається до основного результату `s`.

Це забезпечує точність результату, еквівалентну виконанню всієї схеми Горнера у форматі з подвоєною довжиною мантиси (106 бітів), без потреби підключати сторонні бібліотеки довгої арифметики.

#### Реалізація схеми Горнера

:::tabs
```c
#include <stdio.h>
#include <math.h>
#include <stddef.h>

// Базова схема Горнера через FMA
double horner_fma(const double *coeffs, size_t degree, double x) {
    double res = coeffs[degree];
    for (size_t i = degree; i > 0; --i) {
        res = fma(res, x, coeffs[i - 1]);
    }
    return res;
}

// Компенсована схема Горнера з повним відстеженням похибок
double horner_compensated(const double *coeffs, size_t degree, double x) {
    double s = coeffs[degree];
    double c = 0.0; // Акумулятор компенсованої похибки

    for (size_t i = degree; i > 0; --i) {
        double a = coeffs[i - 1];
        double p = s * x;
        double pi = fma(s, x, -p);   // Точна похибка множення
        double s_next = p + a;
        
        // Алгоритм 2Sum для точного відстеження похибки додавання
        double v = s_next - p;
        double sigma = (p - (s_next - v)) + (a - v);

        s = s_next;
        c = fma(c, x, pi + sigma);
    }
    return s + c;
}

int main(void) {
    // Тестовий многочлен P(x) = (x - 1)^4 = x^4 - 4x^3 + 6x^2 - 4x + 1 біля x = 1.000001
    double poly[] = {1.0, -4.0, 6.0, -4.0, 1.0};
    double x = 1.000001;

    double fma_val = horner_fma(poly, 4, x);
    double comp_val = horner_compensated(poly, 4, x);

    printf("FMA Горнер:           %.16e\n", fma_val);
    printf("Компенсований Горнер:  %.16e\n", comp_val);
    return 0;
}
```
```cpp
#include <iostream>
#include <cmath>
#include <iomanip>
#include <vector>
#include <span>

// Базова схема Горнера через FMA
[[nodiscard]] double horner_fma(std::span<const double> coeffs, double x) noexcept {
    if (coeffs.empty()) return 0.0;
    double res = coeffs.back();
    for (size_t i = coeffs.size() - 1; i > 0; --i) {
        res = std::fma(res, x, coeffs[i - 1]);
    }
    return res;
}

// Компенсована схема Горнера з повним відстеженням похибок
[[nodiscard]] double horner_compensated(std::span<const double> coeffs, double x) noexcept {
    if (coeffs.empty()) return 0.0;
    double s = coeffs.back();
    double c = 0.0;

    for (size_t i = coeffs.size() - 1; i > 0; --i) {
        const double a = coeffs[i - 1];
        const double p = s * x;
        const double pi = std::fma(s, x, -p);
        const double s_next = p + a;
        
        const double v = s_next - p;
        const double sigma = (p - (s_next - v)) + (a - v);

        s = s_next;
        c = std::fma(c, x, pi + sigma);
    }
    return s + c;
}

int main() {
    // Тестовий многочлен P(x) = (x - 1)^4 = x^4 - 4x^3 + 6x^2 - 4x + 1 біля x = 1.000001
    const std::vector<double> poly = {1.0, -4.0, 6.0, -4.0, 1.0};
    constexpr double x = 1.000001;

    const double fma_val = horner_fma(poly, x);
    const double comp_val = horner_compensated(poly, x);

    std::cout << std::scientific << std::setprecision(16);
    std::cout << "FMA Горнер:           " << fma_val << '\n';
    std::cout << "Компенсований Горнер:  " << comp_val << '\n';
    return 0;
}
```

### 4. Точний скалярний добуток: алгоритм Огіти-Румпа-Оїші (Dot2)

Під час обчислення скалярного добутку довгих векторів великої розмірності `∑(xᵢ × yᵢ)` класична компенсація Кехана фіксує лише похибки додавання, ігноруючи похибки множення пар `xᵢ × yᵢ`.

Такеші Огіта (*Takeshi Ogita*), Зігфрід Румп (*Siegfried Rump*) та Шін'їчі Оїші (*Shin'ichi Oishi*) у 2005 році запропонували алгоритм **Dot2** (відомий як *Accurate Dot Product*). Він використовує інструкцію FMA для одночасного точного відстеження як похибок додавання, так і похибок множення кожного елемента вектора.

#### Механізм роботи алгоритму Dot2

На кожній ітерації для пари `xᵢ, yᵢ` обчислюється машинний добуток `p = xᵢ * yᵢ` та його точний залишок `pi = fma(xᵢ, yᵢ, -p)`. Потім добуток `p` додається до основного акумулятора `s` за алгоритмом 2Sum, що продукує похибку додавання `sigma`. Обидві похибки `pi` та `sigma` підсумовуються у вторинний акумулятор похибок `c`.

Наприкінці виконується фінальне додавання основного накопичувача та суми похибок: `res = s + c`. Алгоритм Dot2 гарантує отримання результату з точністю, еквівалентною подвійній точності `double-double`, за умови, що вектор не спричиняє екстремального переповнення експоненти.

#### Реалізація алгоритму Dot2

:::tabs
```c
#include <stdio.h>
#include <math.h>
#include <stddef.h>

// Точний скалярний добуток Dot2 (Ogita-Rump-Oishi)
double dot_product_dot2(const double *x, const double *y, size_t n) {
    if (n == 0) return 0.0;

    double p = x[0] * y[0];
    double s = p;
    double c = fma(x[0], y[0], -p); // Початкова похибка множення

    for (size_t i = 1; i < n; ++i) {
        double pi_prod = x[i] * y[i];
        double pi_err  = fma(x[i], y[i], -pi_prod); // Похибка множення i-го члена

        // 2Sum для додавання добутку pi_prod до суми s
        double s_next = s + pi_prod;
        double v = s_next - s;
        double sigma = (s - (s_next - v)) + (pi_prod - v); // Похибка додавання

        s = s_next;
        c = (c + pi_err) + sigma; // Накопичення похибок
    }

    return s + c;
}

int main(void) {
    // Вектори з майже повною взаємною компенсацією
    double x[] = {1e10, 1.0, -1e10, 1e-10};
    double y[] = {1e10, 1.0,  1e10, 1e-10};

    double naive = 0.0;
    for (size_t i = 0; i < 4; ++i) naive += x[i] * y[i];

    double accurate = dot_product_dot2(x, y, 4);

    printf("Наївний скалярний добуток: %.16e\n", naive);
    printf("Алгоритм Dot2 (FMA):       %.16e\n", accurate);
    return 0;
}
```
```cpp
#include <iostream>
#include <cmath>
#include <iomanip>
#include <vector>
#include <span>

// Точний скалярний добуток Dot2 (Ogita-Rump-Oishi)
[[nodiscard]] double dot_product_dot2(std::span<const double> x, std::span<const double> y) noexcept {
    const size_t n = std::min(x.size(), y.size());
    if (n == 0) return 0.0;

    double p = x[0] * y[0];
    double s = p;
    double c = std::fma(x[0], y[0], -p);

    for (size_t i = 1; i < n; ++i) {
        const double pi_prod = x[i] * y[i];
        const double pi_err  = std::fma(x[i], y[i], -pi_prod);

        const double s_next = s + pi_prod;
        const double v = s_next - s;
        const double sigma = (s - (s_next - v)) + (pi_prod - v);

        s = s_next;
        c = (c + pi_err) + sigma;
    }

    return s + c;
}

int main() {
    const std::vector<double> x = {1e10, 1.0, -1e10, 1e-10};
    const std::vector<double> y = {1e10, 1.0,  1e10, 1e-10};

    double naive = 0.0;
    for (size_t i = 0; i < x.size(); ++i) naive += x[i] * y[i];

    const double accurate = dot_product_dot2(x, y);

    std::cout << "Алгоритм Dot2 (FMA):       " << accurate << '\n';
    return 0;
```

### 5. Точні детермінанти 2×2 та стійкий векторний добуток у 3D

У комп'ютерній геометрії, фізичних рушіях комп'ютерних ігор та CAD-системах найважливішою операцією є обчислення визначника матриці другого порядку:

```
det = a × d − b × c
```

Цей вираз лежить в основі перевірки орієнтації трьох точок на площині (чи лежить точка ліворуч, праворуч або строго на лінії), визначення перетину відрізків та обчислення компонентів тривимірного векторного добутку `u × v`.

Коли вектори майже колінеарні (наприклад, кут між ними близький до 0 або 180 градусів), добутки `a × d` та `b × c` мають майже однакові значення. Наївне віднімання `a*d - b*c` страждає від катастрофічного скасування розрядів: знак результату може спотворитися, що призводить до збою топології полігональних сіток (утворення дірок, самоперетинів або нескінченних циклів у триангуляції Делоне).

#### Алгоритм Кехена для визначників 2×2

Вільям Кехен довів, що застосування FMA дозволяє обчислити `a × d − b × c` зі збереженням знаку та абсолютної точності:

```
w = b * c
det = fma(a, d, -w) + fma(-b, c, w)
```

Перший виклик `fma(a, d, -w)` обчислює `(a × d) − round(b × c)`. Другий виклик `fma(-b, c, w)` точно компенсує похибку округлення числа `w = round(b × c)`. Сума цих двох доданків гарантує, що знак визначника обчислено математично безпомилково, навіть коли вектори відрізняються лише на частку наймолодшого біта.

#### Реалізація стійкого векторного добутку

:::tabs
```c
#include <stdio.h>
#include <math.h>

typedef struct {
    double x, y, z;
} Vec3;

// Точний розрахунок 2x2 детермінанта: a*d - b*c
double det2x2_kahan(double a, double b, double c, double d) {
    double w = b * c;
    double e = fma(-b, c, w); // Похибка множення b*c
    double f = fma(a, d, -w); // Точна різниця a*d - w
    return f + e;
}

// Стійкий векторний добуток u x v у 3D
Vec3 cross_product_exact(Vec3 u, Vec3 v) {
    Vec3 r;
    r.x = det2x2_kahan(u.y, u.z, v.y, v.z);
    r.y = det2x2_kahan(u.z, u.x, v.z, v.x);
    r.z = det2x2_kahan(u.x, u.y, v.x, v.y);
    return r;
}

int main(void) {
    Vec3 u = {1.0, 1.0000000001, 1.0};
    Vec3 v = {1.0, 1.0000000002, 1.0};

    Vec3 res = cross_product_exact(u, v);
    printf("Стійкий векторний добуток: (%.10e, %.10e, %.10e)\n", res.x, res.y, res.z);
    return 0;
}
```

### 6. Комплексне множення в ШПФ: інструкції VFMADDSUB та VFMSUBADD

У швидкому перетворенні Фур'є (ШПФ / FFT) базовою обчислювальною операцією є комплексний «метелик» (*butterfly*), який вимагає множення двох комплексних чисел із наступним додаванням:

```
(u_re + i·u_im) × (w_re + i·w_im) + (v_re + i·v_im)
```

Розкриваючи дійсну та уявну частини:

```
res_re = (u_re × w_re) − (u_im × w_im) + v_re
res_im = (u_re × w_im) + (u_im × w_re) + v_im
```

Дійсна частина вимагає віднімання другого добутку, тоді як уявна частина вимагає додавання. При звичайній векторизації програмістові доводилося або розбивати масив на окремі дійсні та уявні вектори, або застосовувати маски інверсії знаків.

Для вирішення цієї проблеми система команд x86 FMA3 ввела спеціальні черговані векторні інструкції:
- `VFMADDSUB213PS` / `VFMADDSUB231PS` — виконує віднімання на парних позиціях вектора (індекси 0, 2, 4...) та додавання на непарних (індекси 1, 3, 5...).
- `VFMSUBADD213PS` / `VFMSUBADD231PS` — дзеркальна інструкція, яка виконує додавання на парних і віднімання на непарних позиціях.

Ці інструкції дозволяють обробляти комплексні числа у природній переплетеній розкладці (*interleaved format*, де пари дійсна/уявна частина лежать поруч у пам'яті: `re0, im0, re1, im1...`) без жодних накладних витрат на перестановку елементів вектора, що прискорює обчислення цифрової обробки сигналів майже вдвічі.

### 7. Векторизований скалярний добуток (AVX2 / FMA3) та пастка латентності

При написанні низькорівневих обчислювальних ядер для лінійної алгебри (GEMM, згорткові шари нейромереж, цифрова обробка сигналів) програмісти часто припускаються класичної мікроархітектурної помилки. Вони задіюють найновіші векторні інструкції FMA, проте організовують цикл із єдиним вектором-акумулятором.

#### Схемотехнічна природа пастки латентності

Розглянемо мікроархітектурні характеристики векторного блоку FPU у процесорах сучасної архітектури x86-64 (наприклад, Intel Skylake, Golden Cove або AMD Zen 3 / Zen 4):

1. **Апаратна затримка інструкції (latency):** 4 такти (у деяких архітектурах — 5 тактів). Це означає, що від моменту надходження команди `_mm256_fmadd_ps` до порту виконання до моменту запису результату у векторний регістр минає 4 повні такти тактового генератора.
2. **Пропускна здатність блоків (throughput):** 2 інструкції FMA за один такт. Процесор має два паралельні конвеєри плаваючої коми (наприклад, Port 0 та Port 1 у процесорах Intel), кожен з яких здатний приймати нову 256-бітну інструкцію `VFMADD` щотакту.

Якщо цикл скалярного добутку написаний наївно:

```
__m256 acc = _mm256_setzero_ps();
for (size_t i = 0; i < n; i += 8) {
    __m256 va = _mm256_loadu_ps(&a[i]);
    __m256 vb = _mm256_loadu_ps(&b[i]);
    acc = _mm256_fmadd_ps(va, vb, acc); // ПАСТКА: залежність за даними RAW!
}
```

виникає жорстка залежність за даними типу *Read-After-Write* (RAW). Кожна наступна інструкція `_mm256_fmadd_ps` вимагає значення `acc`, обчислене на попередній ітерації. Позачерговий планувальник інструкцій процесора (*Out-of-Order Scheduler*) не може відправити нову команду FMA на конвеєр, доки попередня не пройде всі 4 стадії виконання.

У результаті процесор виконує лише одну інструкцію FMA кожні 4 такти замість потенційних двох інструкцій за один такт. Реальна швидкість обчислень становить лише **12.5% від пікової апаратної потужності кристала**.

#### Подолання затримки: розгортання на множинні акумулятори

Єдиний спосіб досягти 100% завантаження конвеєрів FPU — застосувати **розгортання циклу (*loop unrolling*) з кількома незалежними регістрами-акумуляторами**.

Оскільки затримка становить 4 такти, а конвеєрів два, для повного заповнення черги необхідно одночасно утримувати в конвеєрах щонайменше `4 × 2 = 8` незалежних операцій. Використання 4 або 8 векторних регістрів (`acc0`, `acc1`, `acc2`, `acc3`, ...) розриває ланцюжок залежностей RAW. Планувальник процесора безперервно завантажує обидва порти виконання на кожному такті без найменших затримок.

Крім того, для роботи з великими масивами даних, що не вміщуються в кеш L1/L2, критично забезпечити вирівнювання пам'яті за межею 32 або 64 байтів. Це запобігає розщепленню кеш-ліній (*cache-line splits*), коли векторний запит перетинає межу двох ліній кешу, викликаючи подвійне зчитування з пам'яті.

#### Повний робочий код високопродуктивного скалярного добутку

:::tabs
```c
#include <immintrin.h>
#include <stddef.h>
#include <stdio.h>
#include <stdlib.h>

// Скалярний добуток з 4 незалежними акумуляторами на базі AVX2 + FMA3
float dot_product_fma_avx2(const float *a, const float *b, size_t n) {
    __m256 acc0 = _mm256_setzero_ps();
    __m256 acc1 = _mm256_setzero_ps();
    __m256 acc2 = _mm256_setzero_ps();
    __m256 acc3 = _mm256_setzero_ps();

    size_t i = 0;
    // Обробка по 32 елементи за ітерацію (4 вектори по 8 елементів float)
    for (; i + 31 < n; i += 32) {
        __m256 va0 = _mm256_loadu_ps(a + i);
        __m256 vb0 = _mm256_loadu_ps(b + i);
        acc0 = _mm256_fmadd_ps(va0, vb0, acc0);

        __m256 va1 = _mm256_loadu_ps(a + i + 8);
        __m256 vb1 = _mm256_loadu_ps(b + i + 8);
        acc1 = _mm256_fmadd_ps(va1, vb1, acc1);

        __m256 va2 = _mm256_loadu_ps(a + i + 16);
        __m256 vb2 = _mm256_loadu_ps(b + i + 16);
        acc2 = _mm256_fmadd_ps(va2, vb2, acc2);

        __m256 va3 = _mm256_loadu_ps(a + i + 24);
        __m256 vb3 = _mm256_loadu_ps(b + i + 24);
        acc3 = _mm256_fmadd_ps(va3, vb3, acc3);
    }

    // Редукція 4 акумуляторів в один 256-бітний вектор
    __m256 sum256 = _mm256_add_ps(_mm256_add_ps(acc0, acc1),
                                  _mm256_add_ps(acc2, acc3));

    // Горизонтальне додавання 8 елементів вектора
    __m128 lo = _mm256_castps256_ps128(sum256);
    __m128 hi = _mm256_extractf128_ps(sum256, 1);
    __m128 sum128 = _mm_add_ps(lo, hi);
    sum128 = _mm_hadd_ps(sum128, sum128);
    sum128 = _mm_hadd_ps(sum128, sum128);

    float total = _mm_cvtss_f32(sum128);

    // Дообробка хвостових елементів масиву
    for (; i < n; ++i) {
        total += a[i] * b[i];
    }
    return total;
}

int main(void) {
    const size_t N = 1024;
    float *a = (float *)malloc(N * sizeof(float));
    float *b = (float *)malloc(N * sizeof(float));

    for (size_t i = 0; i < N; ++i) {
        a[i] = 1.0f;
        b[i] = 2.0f;
    }

    float res = dot_product_fma_avx2(a, b, N);
    printf("Скалярний добуток: %.2f (очікувано: %.2f)\n", res, (float)N * 2.0f);

    free(a);
    free(b);
    return 0;
}
```

### 8. Керування FMA в компіляторах та системні прапорці FPU

При компіляції коду поведінка FMA регулюється спеціальними стандартами та прапорцями компілятора:

1. **Стандартна директива `#pragma STDC FP_CONTRACT` (C99 / C++):**
   - За замовчуванням стандарт вимагає режим `ON` або `DEFAULT`, де злиття множення та додавання дозволяється лише в межах одного синтаксичного виразу мови (наприклад, `double r = a * b + c;`).
   - Якщо вираз розбито на дві окремі змінні (`double tmp = a * b; double r = tmp + c;`), стандарт забороняє компілятору автоматично утворювати інструкцію FMA без явного дозволу.
2. **Прапорці оптимізації GCC та Clang:**
   - `-ffp-contract=off` — повна заборона генерації інструкцій FMA. Компілятор завжди генерує роздільні інструкції `VMULPS` та `VADDPS`. Використовується, коли потрібна 100% бітова відтворюваність чисельних результатів на застарілих процесорах без FMA.
   - `-ffp-contract=on` — дозволяє злиття лише в межах одного виразу (відповідає стандарту C99).
   - `-ffp-contract=fast` — дозволяє агресивне злиття множень і додавань через межі операторів і проміжних змінних у межах усієї функції. За увімкненого прапорця `-O3` цей режим часто вмикається автоматично.
3. **Обробка ненормалізованих чисел (Denormals) та режим FTZ/DAZ:**
   - Якщо проміжний добуток `a × b` у звичайному обчисленні потрапляє у діапазон ненормалізованих чисел (менше `2⁻¹⁰²²` для `double`), математичний співпроцесор без увімкнених прапорців *Flush-To-Zero* (FTZ) та *Denormals-Are-Zero* (DAZ) впадає в мікропрограмне переривання (*microcode assist*), уповільнюючи обчислення у 100–1000 разів.
   - Апаратний блок FMA завдяки внутрішньому 106-бітному акумулятору не породжує проміжного антипереповнення: якщо фінальна сума `a × b + c` повертається у нормальний діапазон чисел, усе обчислення проходить на повній швидкості без виклику мікрокоду.
