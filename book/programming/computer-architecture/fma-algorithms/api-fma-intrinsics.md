# 📋 Довідник FMA-інструкцій, інтрінсіків та прагм компілятора

Цей довідник містить систематичний опис стандартних інтерфейсів мов C/C++, низькорівневих апаратних інтрінсіків (*intrinsics*) для мікропроцесорних архітектур x86-64 (AVX2, AVX-512), ARM (Neon, SVE), RISC-V, WebAssembly SIMD, графічних процесорів (CUDA/PTX), а також прагм і прапорців компіляторів для керування суміщеним множенням-додаванням (*Fused Multiply-Add*, скорочено **FMA**).

---

### 1. Математичні варіанти операції FMA

Апаратні блоки FPU підтримують чотири базові комбінації знаків для операндів `a`, `b` та `c` з виконанням одного фінального округлення:

| Позначення | Математичний вираз | Назва операції | Особливість поведінки |
|:---|:---|:---|:---|
| `FMADD` | `round(a × b + c)` | Fused Multiply-Add | Стандартне множення з додаванням |
| `FMSUB` | `round(a × b − c)` | Fused Multiply-Subtract | Віднімання третього операнда від незрізаного добутку |
| `FNMADD` | `round(−(a × b) + c)` | Fused Negated Multiply-Add | Зміна знака добутку перед додаванням |
| `FNMSUB` | `round(−(a × b) − c)` | Fused Negated Multiply-Subtract | Зміна знака добутку перед відніманням |

### 2. Специфікація IEEE 754: спеціальні значення та винятки

Стандарт IEEE 754 суворо регламентує поведінку операції FMA для всіх граничних комбінацій значень:

1. **Множення нуля на нескінченність:** якщо `a = ±0`, а `b = ±∞` (або навпаки), проміжний добуток є невизначеністю. Операція генерує апаратний виняток *Invalid Operation* (`FE_INVALID`) і повертає тихе не-число `NaN` (*Quiet NaN*), навіть якщо третій операнд `c` є скінченним числом.
2. **Скасування нескінченностей:** якщо `a × b = +∞`, а `c = −∞`, або навпаки `a × b = −∞` та `c = +∞`, операція виконує віднімання нескінченностей однакового знака, що генерує `FE_INVALID` і повертає `NaN`.
3. **Робота з не-числами (NaN):** якщо будь-який із трьох операндів є сигнальним не-числом (`sNaN`), генерується виняток `FE_INVALID`, і повертається `qNaN`. Якщо операнд є тихим `qNaN`, він передається на вихід без генерації винятку (за умови, що інші операнди не утворюють `0 × ∞`).
4. **Знаковий нуль:** якщо точний математичний результат дорівнює нулю, знак результату визначається поточним режимом округлення. При округленні до найближчого парного `+0.0 + (-0.0)` повертає `+0.0`, крім випадку `(-0.0) + (-0.0) = -0.0`.

### 3. Стандартна бібліотека C (C99/C11/C23) та C++ (C++11/C++20/C++23)

Стандарт C99 ввів сімейство функцій `fma()` у заголовний файл `<math.h>`, а стандарт C++11 включив їх у простір імен `std::` у заголовному файлі `<cmath>`.

:::tabs
```c
#include <math.h>

/* Базові скалярні інтерфейси C99/C11/C23 */
double      fma (double x, double y, double z);
float       fmaf(float x, float y, float z);
long double fmal(long double x, long double y, long double z);
```
```cpp
#include <cmath>

/* Базові скалярні інтерфейси C++11/C++20/C++23 у просторі std:: */
namespace std {
    double      fma(double x, double y, double z);
    float       fma(float x, float y, float z);
    long double fma(long double x, long double y, long double z);

    float       fmaf(float x, float y, float z);
    long double fmal(long double x, long double y, long double z);
}
```
:::

#### Макроси наявності апаратної підтримки

Стандарт визначає макроси, які дозволяють під час компіляції дізнатися, чи виконується `fma()` за одну апаратну інструкцію, чи емулюється програмно:

- `FP_FAST_FMA`: визначено як `1`, якщо `fma(double, double, double)` виконується апаратно не повільніше за окремі множення та додавання.
- `FP_FAST_FMAF`: апаратна підтримка для типу `float`.
- `FP_FAST_FMAL`: апаратна підтримка для типу `long double`.

Якщо макрос не визначено, виклик `fma()` може призвести до запуску повільної програмної емуляції IEEE 754 через довгу арифметику, що знижує швидкість у десятки разів.

### 4. Архітектура x86-64: AVX2 та AVX-512 FMA3

Заголовний файл: `<immintrin.h>`.
Прапорець компілятора: `-mfma -mavx2` або `-mavx512f`.

#### Номенклатура x86 ISA: форми 132, 213 та 231

В інструкціях x86-64 операція FMA є триоперандною (результат записується в перший зазначений регістр). Щоб уникнути зайвих інструкцій копіювання регістрів `vmovapd`, архітектура надає три форми кодування залежно від того, який операнд перезаписується:

1. **`VFMADD132PD dst, src2, src3`**: `dst = (dst × src3) + src2` (перезаписується перший множник).
2. **`VFMADD213PD dst, src2, src3`**: `dst = (src2 × dst) + src3` (перезаписується другий множник).
3. **`VFMADD231PD dst, src2, src3`**: `dst = (src2 × src3) + dst` (перезаписується доданок акумулятора — найчастіша форма у циклах акумуляції).

Компілятор обирає відповідну асемблерну форму автоматично при використанні C-інтрінсіків.

#### 1. Скалярні операції над одним числом (Scalar FMA)

Працюють над молодшим елементом векторного регістра, зберігаючи старші елементи без змін:

| Інтрінсік | Формат | Опис |
|:---|:---|:---|
| `_mm_fmadd_sd(__m128d a, __m128d b, __m128d c)` | 64-біт `double` | `c[0] = round(a[0] × b[0] + c[0])` |
| `_mm_fmadd_ss(__m128 a, __m128 b, __m128 c)` | 32-біт `float` | `c[0] = round(a[0] × b[0] + c[0])` |
| `_mm_fmsub_sd(__m128d a, __m128d b, __m128d c)` | 64-біт `double` | `c[0] = round(a[0] × b[0] − c[0])` |
| `_mm_fnmadd_sd(__m128d a, __m128d b, __m128d c)` | 64-біт `double` | `c[0] = round(−(a[0] × b[0]) + c[0])` |

#### 2. Векторні 256-бітні операції AVX2 (4 × double або 8 × float)

| Інтрінсік | Тип | Опис операції над усіма елементами вектора |
|:---|:---|:---|
| `_mm256_fmadd_pd(__m256d a, __m256d b, __m256d c)` | 4 × `double` | `res[i] = round(a[i] × b[i] + c[i])` |
| `_mm256_fmadd_ps(__m256 a, __m256 b, __m256 c)` | 8 × `float` | `res[i] = round(a[i] × b[i] + c[i])` |
| `_mm256_fmsub_pd(__m256d a, __m256d b, __m256d c)` | 4 × `double` | `res[i] = round(a[i] × b[i] − c[i])` |
| `_mm256_fnmadd_pd(__m256d a, __m256d b, __m256d c)` | 4 × `double` | `res[i] = round(−(a[i] × b[i]) + c[i])` |
| `_mm256_fnmsub_pd(__m256d a, __m256d b, __m256d c)` | 4 × `double` | `res[i] = round(−(a[i] × b[i]) − c[i])` |
| `_mm256_fmaddsub_pd(__m256d a, __m256d b, __m256d c)` | 4 × `double` | Чергування: парні віднімають `-`, непарні додають `+` |
| `_mm256_fmsubadd_pd(__m256d a, __m256d b, __m256d c)` | 4 × `double` | Чергування: парні додають `+`, непарні віднімають `-` |

#### 3. Векторні 512-бітні операції AVX-512 (8 × double або 16 × float)

| Інтрінсік | Тип | Опис |
|:---|:---|:---|
| `_mm512_fmadd_pd(__m512d a, __m512d b, __m512d c)` | 8 × `double` | `res[i] = round(a[i] × b[i] + c[i])` |
| `_mm512_fmadd_round_pd(a, b, c, rounding)` | 8 × `double` | FMA з явним перевизначенням режиму округлення |

Параметр `rounding` для `_mm512_fmadd_round_pd` може набувати значень:
- `_MM_FROUND_TO_NEAREST_INT | _MM_FROUND_NO_EXC` — до найближчого парного.
- `_MM_FROUND_TO_NEG_INF | _MM_FROUND_NO_EXC` — до мінус нескінченності.
- `_MM_FROUND_TO_POS_INF | _MM_FROUND_NO_EXC` — до плюс нескінченності.
- `_MM_FROUND_TO_ZERO | _MM_FROUND_NO_EXC` — до нуля (зрізання).

### 5. Векторні інтрінсіки ARM (Neon та SVE)

Заголовний файл: `<arm_neon.h>` або `<arm_sve.h>`.
Прапорець компілятора: `-march=armv8-a` або `-march=armv8-a+sve`.

#### 1. ARM Neon (128-бітні вектори)

| Інтрінсік Neon | Тип | Формула |
|:---|:---|:---|
| `vfma_f32(float32x2_t a, b, c)` | 2 × `float` | `a + (b × c)` |
| `vfmaq_f32(float32x4_t a, b, c)` | 4 × `float` | `a + (b × c)` |
| `vfmaq_f64(float64x2_t a, b, c)` | 2 × `double` | `a + (b × c)` |
| `vfmsq_f64(float64x2_t a, b, c)` | 2 × `double` | `a − (b × c)` |

*Увага до порядку аргументів у Neon:* перший аргумент `a` є акумулятором, до якого додається добуток `b × c`: `vfmaq_f64(acc, x, y) = acc + x * y`.

#### 2. ARM SVE / SVE2 (Вектори змінної довжини)

| Інтрінсік SVE | Опис |
|:---|:---|
| `svmla_f64_m(svbool_t pg, svfloat64_t a, b, c)` | Масковане додавання добутку: `pg[i] ? a[i] + b[i]*c[i] : a[i]` |
| `svmad_f64_m(svbool_t pg, svfloat64_t a, b, c)` | Маскований деструктивний FMA: `pg[i] ? a[i]*b[i] + c[i] : a[i]` |

### 6. Інструкції FMA в архітектурі RISC-V

У стандартному наборі розширень RISC-V "F" (Single-Precision) та "D" (Double-Precision) інструкції FMA є чотириоперандними формату R4-type:

```
fmadd.d  rd, rs1, rs2, rs3, rm   # rd = round(rs1 × rs2 + rs3)
fmsub.d  rd, rs1, rs2, rs3, rm   # rd = round(rs1 × rs2 − rs3)
fnmsub.d rd, rs1, rs2, rs3, rm   # rd = round(−(rs1 × rs2) + rs3)
fnmadd.d rd, rs1, rs2, rs3, rm   # rd = round(−(rs1 × rs2) − rs3)
```

Поле `rm` дозволяє явно вказати динамічний режим округлення для конкретної інструкції:
- `rne`: Round to Nearest, ties to Even (до найближчого парного).
- `rtz`: Round towards Zero (до нуля).
- `rdn`: Round Down (до `-∞`).
- `rup`: Round Up (до `+∞`).
- `rmm`: Round to Nearest, ties to Max Magnitude.
- `dyn`: Використовувати режим із системного контрольного регістра `fcsr`.

### 7. WebAssembly SIMD128 та Relaxed SIMD

У стандарті WebAssembly інструкції FMA з'явилися в розширенні *Relaxed SIMD*, призначеному для досягнення нативної швидкості на x86 та ARM:

```wat
;; WebAssembly Relaxed SIMD FMA інструкції
f32x4.relaxed_fma     ;; (a * b) + c для 4x float32
f32x4.relaxed_fnms    ;; -(a * b) + c
f64x2.relaxed_fma     ;; (a * b) + c для 2x float64
f64x2.relaxed_fnms    ;; -(a * b) + c
```

У середовищі C/C++ (Emscripten) ці інструкції доступні через заголовний файл `<wasm_simd128.h>` як `wasm_f64x2_relaxed_fma(a, b, c)`.

### 8. Графічні процесори: CUDA та PTX FMA

У середовищі NVIDIA CUDA та мові проміжного представлення PTX операції FMA підтримуються як на рівні C++-функцій середовища виконання, так і через низькорівневі інструкції пристрою:

:::tabs
```c
#include <cuda_runtime.h>

/* CUDA C інтерфейси скалярного FMA */
__device__ double cuda_fma_example(double a, double b, double c) {
    /* __fma_rn гарантує компіляцію в fma.rn.f64 */
    return __fma_rn(a, b, c);
}
```
```cpp
#include <cuda_runtime.h>

/* CUDA C++ інтерфейси скалярного FMA з контролем округлення */
__device__ double cuda_fma_example(double a, double b, double c) noexcept {
    /* __fma_rn: округлення до найближчого парного */
    /* __fma_rz: округлення до нуля */
    return __fma_rn(a, b, c);
}
```
:::

Асемблер PTX містить пряму інструкцію:
```
fma.rn.f64 d, a, b, c;   // d = round_nearest_even(a * b + c)
fma.rz.f64 d, a, b, c;   // d = round_towards_zero(a * b + c)
```

### 9. Прагми стандарту та прапорці оптимізації компіляторів

:::tabs
```c
/* Керування згортанням виразів у C */
#pragma STDC FP_CONTRACT ON
#pragma STDC FP_CONTRACT OFF
#pragma STDC FP_CONTRACT DEFAULT
```
```cpp
/* Керування згортанням виразів у C++ */
#pragma STDC FP_CONTRACT ON
#pragma STDC FP_CONTRACT OFF
#pragma STDC FP_CONTRACT DEFAULT
```
:::

- `ON`: дозволяє компілятору згортати вирази вигляду `x * y + z` в одну апаратну інструкцію FMA, ігноруючи проміжне округлення IEEE 754.
- `OFF`: забороняє автоматичне об'єднання. Компілятор зобов'язаний згенерувати окреме множення з округленням і окреме додавання. Необхідно вмикати в алгоритмах, де проміжне округлення є частиною математичної моделі.

#### 1. Прапорці компіляторів GCC та Clang

| Прапорець | Режим згортання | Поведінка |
|:---|:---|:---|
| `-ffp-contract=off` | Вимкнено | Жоден вираз не згортається автоматично (тільки явні виклики `fma()`) |
| `-ffp-contract=on` | За стандартом | Згортання дозволено лише в межах одного виразу мови C/C++ |
| `-ffp-contract=fast` | Агресивний | Дозволено згортання через межі операторів і проміжних змінних |

#### 2. Прапорці компілятора MSVC

| Прапорець | Режим плаваючої коми | Поведінка FMA |
|:---|:---|:---|
| `/fp:precise` | Точний (типовий) | Дотримується меж виразів, генерація FMA дозволена |
| `/fp:strict` | Строгий | Забороняє генерацію FMA для виразів `a*b + c`, суворо вимагає окремих операцій |
| `/fp:fast` | Швидкий | Максимально агресивне авто-згортання та перевпорядкування |

#### Небезпека неконтрольованого автоматичного згортання (Auto-Fusion)

Якщо прапорець `-ffp-contract=fast` увімкнено глобально, компілятор може автоматично замінити вираз `x = a * b; y = a * b - x;` на інструкцію FMA, що призведе до `y = 0.0` замість обчислення коректного залишку в алгоритмах розщеплення (наприклад, у класичному розщепленні Деккера).

Для надійного написання алгоритмів підвищеної точності рекомендується:
1. Завжди викликати апаратний FMA явно через `std::fma()` або векторні інтрінсіки `_mm256_fmadd_pd`.
2. Компілювати чутливі чисельні модулі з прапорцем `-ffp-contract=on` або `#pragma STDC FP_CONTRACT DEFAULT`.
