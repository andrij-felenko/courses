# 🧮 Денотаційна семантика FRP: алгебра поведінок і топологічний детермінізм

Математична строгість функціонального реактивного програмування ґрунтується на **денотаційній семантиці** (англ. *denotational semantics*). На відміну від операційної семантики, яка описує, *які інструкції процесора* треба виконати крок за кроком, денотаційна семантика ставить у відповідність кожній синтаксичній конструкції абстрактний математичний об'єкт — функцію, множину або алгебраїчну структуру.

Це дає змогу виводити властивості програми за допомогою алгебраїчних перетворень (*equational reasoning*), доводити коректність композиції та гарантувати відсутність часових аномалій ще до запуску коду.

## Модель часу: континуум і дискретність

У класичній моделі Конала Елліотта та Пола Гудака час моделюється як неперервна множина дійсних чисел `Time = R` (або `R₊` для часу від запуску програми `t ≥ 0`), на якій визначено лінійний строгий порядок `<` та операцію додавання.

Головними типами даних є **Поведінка** (`Behavior`) та **Подія** (`Event`):

```
Time = R,  де t ∈ [0, ∞)

Behavior a = Time → a

Event a = [(t, a)] = { (tᵢ, vᵢ) | tᵢ ∈ Time, vᵢ ∈ a, t₀ < t₁ < t₂ < ... }
```

### Властивості поведінки B(t)

Поведінка `B : Time → a` є повною функцією часу: для будь-якого моменту `t ∈ Time` значення `B(t)` строго визначене. Якщо `a = Real`, поведінка моделює фізичну величину (швидкість, координату, температуру). Якщо `a = Color`, поведінка моделює оптичну зміну світла.

На множині поведінок природно виникають структури **функтора** (*Functor*), **аплікативного функтора** (*Applicative Functor*) та **монади** (*Monad*).

## Функторна та аплікативна алгебра поведінок

### 1. Функторна структура (fmap / map)

Для довільної чистої функції `f : a → b` підняття функції над поведінкою визначається точковим застосуванням у кожен момент часу:

```
fmap : (a → b) → Behavior a → Behavior b

Денотація:
(fmap f B)(t) = f (B(t))
```

Закони функтора виконуються автоматично в силу законів функціональної композиції:

```
fmap id B
= \t → id (B(t))        [за означенням fmap]
= \t → B(t)             [властивість id: id x = x]
= B                     [екстенсійність функцій]

fmap (g ∘ f) B
= \t → (g ∘ f) (B(t))   [за означенням fmap]
= \t → g (f (B(t)))     [за означенням композиції]
= \t → g ((fmap f B)(t))
= fmap g (fmap f B)     [закон композиції функтора доведено]
```

### 2. Аплікативна структура (pure та <*>)

Аплікативний функтор дає змогу об'єднувати кілька незалежних поведінок без потреби переходити до мутабельного стану.

Оператор `pure` підіймає константу в стаціонарну поведінку, значення якої не залежить від часу:

```
pure : a → Behavior a
(pure c)(t) = c
```

Оператор аплікації `<*>` бере поведінку-функцію і застосовує її до поведінки-значення в однаковий момент часу `t`:

```
(<*>) : Behavior (a → b) → Behavior a → Behavior b
(B_f <*> B_x)(t) = (B_f(t)) (B_x(t))
```

Для аплікативних поведінок строго доводяться чотири класичні аплікативні закони:

**Закон тотожності (Identity):**
```
pure id <*> v
= (\t → id) <*> v        [підстановка означення pure: pure c = \t → c]
= \t → (id) (v(t))       [застосування точкової аплікації (<*>)]
= \t → v(t)              [властивість функції id: id x = x]
= v                      [екстенсійність функцій]
```

**Закон гомоморфізму (Homomorphism):**
```
pure f <*> pure x
= (\t → f) <*> (\t → x)  [означення pure для функції та аргументу]
= \t → f x               [точкова аплікація константних функцій]
= pure (f x)             [згортання за означенням pure]
```

**Закон перестановки (Interchange):**
```
u <*> pure y
= \t → (u(t)) y          [застосування точкової аплікації до pure y]
= \t → (\f → f y) (u(t)) [секціювання аргументу y: f y = (\f → f y) f]
= pure (\f → f y) <*> u  [згортання лівої частини через pure та (<*>)]
```

**Закон композиції (Composition):**
```
pure (∘) <*> u <*> v <*> w
= \t → ((u(t)) ∘ (v(t))) (w(t)) [послідовне розкриття точкової аплікації]
= \t → (u(t)) ((v(t)) (w(t)))   [розкриття функціональної композиції (∘)]
= u <*> (v <*> w)               [згортання вкладеної аплікації]
```


Завдяки цьому будь-яку n-арну функцію `g : a₁ → a₂ → ... → aₙ → r` можна підняти над n поведінками:

```
liftN g B₁ B₂ ... Bₙ = pure g <*> B₁ <*> B₂ <*> ... <*> Bₙ
```

Денотація піднятої функції відповідає одночасному зрізу всіх входів:

```
(lift2 (+) B₁ B₂)(t) = B₁(t) + B₂(t)
```

### 3. Монадична структура та сплющення (join)

Поведінка є монадою, де операція `join` розплющує поведінку, яка повертає іншу поведінку:

```
join : Behavior (Behavior a) → Behavior a
(join BB)(t) = (BB(t))(t)
```

Денотація показує, що в момент `t` спочатку обирається активна поведінка `BB(t)`, і вона негайно опитується в той самий момент `t`. Це дозволяє моделювати динамічні системи, де структура зв'язків змінюється в часі.

## Алгебра дискретних подій (Event Algebra)

Дискретна подія `Event a` моделюється як послідовність пар «час-значення»:

```
E = [(t₀, v₀), (t₁, v₁), (t₂, v₂), ...]
```

### 1. Фільтрація подій (filterE)

Оператор `filterE` залишає лише ті спалахи, для яких предикат `p : a → Bool` повертає істину:

```
filterE : (a → Bool) → Event a → Event a

Денотація:
filterE p [(tᵢ, vᵢ)] = [(tᵢ, vᵢ) | p(vᵢ) == True]
```

### 2. Злиття подій (mergeE)

Оператор `mergeE` об'єднує два дискретні потоки подій, упорядковуючи їх за часом появи:

```
mergeE : Event a → Event a → Event a

Денотація:
mergeE [(tᵢ, uᵢ)] [(sⱼ, wⱼ)] = sort_by_time ([(tᵢ, uᵢ)] ∪ [(sⱼ, wⱼ)])
```

Якщо дві події трапляються в один і той самий момент `tᵢ = sⱼ`, семантика класичного FRP детерміновано обирає значення лівого потоку або застосовує комбінатор напівгрупи `(<>)` для їх склеювання.

### 3. Накопичення стану (accumB / foldp)

Міст між дискретними подіями та неперервною поведінкою забезпечує оператор накопичення `accumB` (в Elm відомий як `foldp` — *fold from the past*):

```
accumB : a → Event (a → a) → Behavior a
```

Нехай початкове значення дорівнює `a₀`, а потік подій-трансформацій має вигляд `E = [(t₁, f₁), (t₂, f₂), ...]`. Тоді денотація `accumB` визначається як кусочно-стала функція:

```
(accumB a₀ E)(t) =
  a₀,                           якщо t < t₁
  f₁(a₀),                       якщо t₁ ≤ t < t₂
  f₂(f₁(a₀)),                   якщо t₂ ≤ t < t₃
  (fₖ ∘ ... ∘ f₁)(a₀),          якщо tₖ ≤ t < tₖ₊₁
```

Це перетворює дискретні поштовхи на тривалий стан системи, визначений у будь-який момент часу.

### 4. Зріз поведінки (snapshot / sampleOn)

Зворотне перетворення — від неперервної поведінки до дискретного потоку — виконує оператор `snapshot`:

```
snapshot : Event b → Behavior a → Event (b, a)

Денотація:
snapshot [(tᵢ, vᵢ)] B = [(tᵢ, (vᵢ, B(tᵢ)))]
```

У момент настання кожної дискретної події `tᵢ` береться миттєве значення поведінки `B(tᵢ)`, утворюючи новий потік пар.

## Безперервні оператори: диференціювання та інтегрування

Оскільки `Time = R`, на числових поведінках `Behavior Real` природно визначаються операції диференціювання та інтегрування за неперервним часом.

### 1. Неперервне інтегрування (integral)

Нехай `B : Time → Real` — інтегровна за Ріманом функція. Оператор `integral` визначається як первісна від моменту старту симуляції `t = 0` до поточного моменту `t`:

```
integral : Behavior Real → Behavior Real

Денотація:
(integral B)(t) = ∫₀ᵗ B(τ) dτ
```

Якщо швидкість тіла задана поведінкою `v(t) = v₀ + a · t`, то положення тіла `s(t)` описується безпосередньо через композицію комбінаторів:

```
s = s₀ + integral v
```

Значення `s(t)` в аналітичній денотації дорівнює:

```
s(t) = s₀ + ∫₀ᵗ (v₀ + a · τ) dτ = s₀ + v₀ · t + (a · t²) / 2
```

### 2. Диференціювання (derivative)

Оператор диференціювання визначається через границю відношення приросту:

```
derivative : Behavior Real → Behavior Real

Денотація:
(derivative B)(t) = lim_{h → 0} (B(t) - B(t - h)) / h = B'(t)
```

В аналітичних моделях диференціювання зберігає точну форму похідної. У чисельних рушіях диференціювання наближається скінченними різницями першого або другого порядку, проте на рівні мови FRP інженер оперує чистим поняттям похідної.

## Модель перемикання та динамічних графів

Для зміни топології реакцій у відповідь на події застосовується оператор вищого порядку `switcher` (або `switch`):

```
switcher : Behavior a → Event (Behavior a) → Behavior a
```

Нехай `B₀` — початкова поведінка, а `E = [(t₁, B₁), (t₂, B₂), ...]` — потік подій, кожна з яких приносить нову поведінку. Денотація `switcher` визначається як шматочково-визначена функція:

```
(switcher B₀ E)(t) =
  B₀(t),        якщо t < t₁
  B₁(t),        якщо t₁ ≤ t < t₂
  Bᵢ(t),        якщо tᵢ ≤ t < tᵢ₊₁
```

Це гарантує, що перехід між різними режимами системи є детермінованим і неперервним праворуч у точках перемикання `tᵢ`.

## Топологічний детермінізм і доведення відсутності глітчів

У дискретних та гібридних реалізаціях FRP реактивна система представляється орієнтованим ациклічним графом обчислень `G = (V, E)`.

- Вершини `V` — реактивні змінні: джерела (`Sources`), похідні обчислення (`Derived/Computations`), кінцеві ефекти (`Sinks`).
- Ребра `E ⊆ V × V` — спрямовані залежності: орієнтоване ребро `(u, v) ∈ E` означає, що вузол `v` читає значення вузла `u` (тобто `u` є входом для `v`).

### Означення глітча (Glitch)

Нехай у момент транзакції `T_k` змінюється джерело `S ∈ V`. Кожен вузол `u ∈ V` має послідовність станів `u⁽⁰⁾, u⁽¹⁾, ..., u⁽ᵏ⁾`.

**Глітч** — це ситуація, коли вузол `v` обчислює своє значення на кроці `k` за формулою `v⁽ᵏ⁾ = f(u₁⁽ᵃ⁾, u₂⁽ᵇ⁾, ..., uₘ⁽ᵐ⁾)`, де індекси кроків входів не узгоджені (існують `i, j` такі, що `a ≠ b`). Тобто вузол `v` бачить частину входів оновленими до транзакції `k`, а частину — застарілими з кроку `k-1`.

### Теорема про топологічну коректність (Glitch Freedom)

**Теорема:** Якщо граф залежностей `G = (V, E)` є ациклічним, і всі похідні вузли обчислюються у порядку **топологічного сортування** `topo(V)`, то для будь-якої транзакції `k` поява глітчів неможлива: кожен вузол `v` обчислюється строго один раз і використовує входи виключно з транзакції `k`.

### Доведення

1. Оскільки граф `G` є орієнтованим ациклічним (DAG), для кожної вершини `v ∈ V` коректно визначено топологічний ранг (глибину) `rank(v)`:
   ```
   rank(v) = 0,                                 якщо pred(v) = ∅ (джерело)
   rank(v) = 1 + max { rank(u) | u ∈ pred(v) }, якщо pred(v) ≠ ∅
   ```
   де `pred(v) = { u ∈ V | (u, v) ∈ E }` — множина прямих предків вузла `v`.

2. За означенням рангу, для будь-якого ребра `(u, v) ∈ E` виконується строга нерівність:
   ```
   rank(u) < rank(v)
   ```

3. Проведемо індукцію за значенням `rank(v) = r`:

   - **База індукції (`r = 0`):** Вузли рангу 0 є джерелами. На кроці транзакції `k` нове значення джерела `S⁽ᵏ⁾` встановлюється безпосередньо. Глітчів немає.

   - **Індукційний перехід (`r > 0`):** Припустимо, що всі вузли `u` з `rank(u) < r` вже обчислені і мають узгоджені значення стану `u⁽ᵏ⁾` для поточної транзакції `k`.

   - Розглянемо довільний вузол `v` з `rank(v) = r`. Усі його прямі предки `u ∈ pred(v)` за властивістю (2) мають `rank(u) ≤ r - 1 < r`.

   - Отже, за припущенням індукції, на момент черги обчислення вузла `v` кожен предок `u ∈ pred(v)` уже завершив своє оновлення і має значення `u⁽ᵏ⁾`.

   - Значення вузла `v` обчислюється як `v⁽ᵏ⁾ = f({ u⁽ᵏ⁾ | u ∈ pred(v) })`. Оскільки всі аргументи належать одній і тій самій транзакції `k`, несумісності станів не виникає.

   - Вузол `v` отримує значення `v⁽ᵏ⁾` і не потребує повторного обчислення в рамках поточної транзакції.

4. За принципом математичної індукції, властивість узгодженості виконується для всіх вершин графа `V`. Транзакція завершується за час `O(|V| + |E|)` без проміжних некоректних станів.

### Динамічні залежності та перерахунок рангів

Якщо вираз містить умовні оператори `v = if cond then a else b`, множина предків `pred(v)` змінюється динамічно під час виконання.

Коли значення умови `cond` змінюється, система виконує локальне динамічне перевпорядкування графа:

```
Якщо cond = True:   pred(v) = {cond, a},  rank(v) = 1 + max(rank(cond), rank(a))
Якщо cond = False:  pred(v) = {cond, b},  rank(v) = 1 + max(rank(cond), rank(b))
```

Якщо новий ранг `rank'(v)` збільшується, система рекурсивно оновлює ранги всіх нащадків `succ(v)` перед виконанням фази обчислення, що зберігає інваріант `rank(u) < rank(w)` для всіх активних ребер `(u, w)` і гарантує збереження властивості Glitch Freedom навіть при динамічній зміні топології.

## Причинність (Causality) та зворотні зв'язки у стрілковому FRP

У моделюванні фізичних систем і симуляторах виникає потреба створювати зворотні зв'язки (*feedback loops*), наприклад, коли сила тертя залежить від поточної швидкості, а прискорення визначає зміну швидкості: `v = integral (F(v) / m)`.

Без суворих математичних обмежень такий циклічний вираз веде до миттєвого парадоксу (ділення на нуль або нескінченної рекурсії). Для формалізації коректності використовується теорія **причинності** (англ. *causality*).

### 1. Означення причинної функції сигналу

Функція перетворення сигналів `sf : Signal a → Signal b` називається **причинною** (*causal*), якщо значення виходу в будь-який момент часу `t` залежить виключно від значень входу в моменти `τ ≤ t`:

```
∀ s₁, s₂ ∈ Signal a, ∀ t ∈ Time:
(∀ τ ≤ t: s₁(τ) = s₂(τ))  ⇒  ((sf s₁)(t) = (sf s₂)(t))
```

Це математично гарантує, що система не «зазирає в майбутнє».

### 2. Строга причинність та розв'язання циклів

Функція сигналу `sf` називається **строго причинною** (*strictly causal* або *decoupled*), якщо значення виходу в момент `t` залежить лише від вхідних значень у строго минулі моменти `τ < t`:

```
∀ s₁, s₂ ∈ Signal a, ∀ t ∈ Time:
(∀ τ < t: s₁(τ) = s₂(τ))  ⇒  ((sf s₁)(t) = (sf s₂)(t))
```

Оператор неперервного інтегрування `integral` є строго причинним: значення інтеграла `∫₀ᵗ x(τ) dτ` у точці `t` не залежить від миттєвого одиничного значення `x(t)` у тій самій ізольованій точці, оскільки інтеграл за точковою множиною нульової міри дорівнює нулю.

### 3. Теорема про нерухому точку для циклів зі зворотним зв'язком

Комбінатор циклу `loop` у стрілковому FRP визначається як:

```
loop : SF (a, c) (b, c) → SF a b
```

**Теорема:** Якщо функція `sf : SF (a, c) (b, c)` є строго причинною по відношенню до внутрішнього сигналу зворотного зв'язку `c`, то рівняння нерухомої точки:

```
(b(t), c(t)) = sf(a(t), c(t))
```

має єдиний детермінований розв'язок на будь-якому часовому інтервалі `[0, T]`.

Це випливає з теореми Банаха про нерухому точку: строго причинний оператор є стискаючим відображенням (*contraction mapping*) у метричному просторі неперервних функцій часу з експоненційно зваженою метрикою Беллаша (*Bielawski/Biasi metric*). Це гарантує стабільність чисельного інтегрування та відсутність нескінченних циклів обчислення.

## Тристанова модель Push-Pull та інваріанти продуктивності

Для досягнення мінімальної кількості обчислень у сучасних реактивних графах використовується **тристанова модель прапорців** (*Three-state Push-Pull*):

Кожен вузол графа `v ∈ V` перебуває в одному з трьох станів:
1. `CLEAN` (чистий): значення вузла актуальне і відповідає поточній транзакції.
2. `DIRTY` (брудний): значення прямого предка змінилося, цей вузол обов'язково потребує перерахунку.
3. `CHECK_DIRTY` (потребує перевірки): один із непрямих предків змінився, проте безпосередні батьки можуть після перерахунку не змінити свого значення (наприклад, функція `memoized` або `equals`).

### Алгоритм двоетапного оновлення

**Фаза 1 (Push Downstream):**
Коли змінюється джерело `S`:
- Джерело переходить у стан `DIRTY`.
- Для всіх прямих нащадків `v ∈ succ(S)` встановлюється прапорець `DIRTY`.
- Для всіх подальших нащадків у підграфі `succ*(v)` рекурсивно встановлюється прапорець `CHECK_DIRTY`.
- **Складність фази 1:** `O(|E_subgraph|)` операцій виставлення бітових прапорців, жодна користувацька функція не викликається.

**Фаза 2 (Pull / Read Upstream):**
Коли споживач запитує значення вузла `v`:
- Якщо стан `v == CLEAN`, негайно повертається кешоване значення `value(v)`.
- Якщо стан `v == CHECK_DIRTY`:
  - Вузол рекурсивно опитує предків `u ∈ pred(v)`.
  - Якщо жоден предок не змінив фактичного значення після власного оновлення, стан `v` перемикається в `CLEAN` без виклику формули `v`.
- Якщо стан `v == DIRTY` (або предок змінив значення):
  - Викликається функція обчислення `v = f({ u })`.
  - Якщо нове значення відрізняється від попереднього (`new_val ≠ old_val`), оновлюється кеш і стан переходить у `CLEAN`.
  - Якщо нове значення збігається (`new_val == old_val`), нащадки у стані `CHECK_DIRTY` не будуть перераховуватися (*change propagation pruning*).

### Доведення мінімальності обчислень

**Твердження:** Тристанова модель гарантує, що жоден вузол графа не обчислюється, якщо його вхідні дані фактично не змінилися, а кожен змінений вузол обчислюється строго один раз за транзакцію.

Справді, завдяки відкладенню обчислення (pull) та попередній розмітці (push), вузли, виходи яких не зчитуються ефектами або користувачем, залишаються у стані `DIRTY` і взагалі не витрачають такти процесора (*lazy evaluation of unused branches*). 

Це поєднує математичну строгість денотаційної семантики з асимптотичною оптимальністю `O(|V_active_changed| + |E_active|)` реального виконання.

## Повний приклад: моделювання гармонічного осцилятора

Для демонстрації сили денотаційної семантики розглянемо математичну модель гармонічного осцилятора (пружинного маятника) без тертя:

Диференціальне рівняння другого порядку:
```
x''(t) + ω² · x(t) = 0,   при початкових умовах x(0) = x₀,  v(0) = 0
```

У класичному FRP рівняння записується прямою декларативною композицією взаємозалежних поведінок:

```
a = pure (-ω²) <*> x
v = integral a
x = pure x₀ + integral v
```

Аналітичний розв'язок у денотаційній семантиці отримується миттєво:

```
x(t)
= x₀ + ∫₀ᵗ v(τ) dτ                         [підстановка денотації x = x₀ + integral v]
= x₀ + ∫₀ᵗ (∫₀ᵘ (-ω² · x(s)) ds) du        [підстановка денотації швидкості v = integral a]
= x₀ · cos(ω · t)                          [розв'язок лінійного інтегрального рівняння Вольтерра]
```


Якщо до системи додається подія зіткнення `bounce : Event ()`, яка миттєво інвертує швидкість `v ↦ -v`, модель використовує комбінатор `switcher`:

```
v_final = switcher v (fmap (\_ → pure (-1) <*> v) bounce)
```

Математична денотація гарантує, що траєкторія руху є кусочно-гладкою функцією, де в точках зіткнення зберігається закон збереження повної механічної енергії:

```
E(t) = (m · v(t)²)/2 + (k · x(t)²)/2 = const
```

На відміну від дискретних ігрових циклів із накопиченням чисельного дрейфу енергії, денотаційний опис усуває похибки апроксимації на рівні архітектури специфікації.

### Оцінка похибки дискретизації (Sampling Error Bound)

Коли неперервна денотація `B(t)` транслюється у дискретні кадри з кроком дискретизації `Δt`, локальна похибка обчислення значень за методом Ейлера обмежена величиною порядку `O(Δt)`:

```
|x_чисельне(t) - x_аналітичне(t)| ≤ C · Δt · max_{τ ∈ [0, t]} |x''(τ)|
```

Використання вищих порядків апроксимації (наприклад, методу Рунге-Кутти 4-го порядку `O(Δt⁴)`) всередині рушія FRP залишається внутрішньою деталлю виконання: користувацький код ніколи не прив'язується до конкретного чисельного методу чи частоти кадрів монітора, зберігаючи повну математичну інваріантність специфікації.
