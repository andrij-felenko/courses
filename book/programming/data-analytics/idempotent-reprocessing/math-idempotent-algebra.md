# 🧮 Алгебраїчні структури ідемпотентної обробки: напівґратки та комутативні моноїди

У розподілених системах та конвеєрах обробки великих даних гарантія повторюваності результатів спирається на абстрактну алгебру. Коли конвеєр перераховує історію подій, він неминуче стикається з трьома аномаліями розподіленого середовища:

1. **Дублювання повідомлень**: внаслідок повторних спроб (*retries*) мережі, перезапуску брокера або рестарту воркерів та сама подія надходить двічі або більше разів.
2. **Порушення порядку**: запізнілі події надходять не за хронологією часу створення (*event time*), а у довільному порядку часу прибуття (*arrival time*).
3. **Паралельне розбиття**: історія нарізається на незалежні чанки (*chunks*) або партиції, які обчислюються паралельно на різних вузлах кластера і потім зливаються в один результат.

Щоб кінцевий аналітичний стан був стійким до цих трьох факторів, операція злиття даних зобов'язана належати до строго визначеного класу алгебраїчних структур.

---

### Фундаментальні властивості бінарних операцій над даними

Нехай `S` — множина можливих станів агрегату (наприклад, стан метрик користувача або набір замовлень), а `·` — бінарна операція об'єднання двох станів `· : S × S → S`.

#### 1. Асоціативність (Associativity)
Для будь-яких елементів `a, b, c ∈ S`:
```
(a · b) · c = a · (b · c)
```
*Фізичний зміст*: асоціативність дозволяє довільно групувати обчислення. Ми можемо порахувати агрегат потижнево, а потім злити тижні разом, або порахувати окремо на десяти вузлах Spark і об'єднати результати. Порядок розстановки дужок не впливає на відповідь. Множина з асоціативною операцією утворює **напівгрупу** (англ. *semigroup*). Якщо існує нейтральний елемент `e` такий, що `a · e = a`, структура стає **моноїдом** (англ. *monoid*).

#### 2. Комутативність (Commutativity)
Для будь-яких елементів `a, b ∈ S`:
```
a · b = b · a
```
*Фізичний зміст*: комутативність усуває залежність від часу надходження подій. Якщо платіж #101 прийшов пізніше за платіж #102 через затримку в черзі Kafka, результат їх злиття залишається незмінним. Разом з асоціативністю комутативність утворює **комутативний моноїд** (абелів моноїд).

#### 3. Ідемпотентність (Idempotency)
Для будь-якого елемента `a ∈ S`:
```
a · a = a
```
*Фізичний зміст*: повторне застосування вже врахованого стану або події не змінює акумулятор. Якщо задача збоює і перезапускається з попереднього зміщення, повторно прочитані записи розчиняються в поточному стані без подвоєння показників.

### Верхня напівґратка (Join-Semilattice) як основа безконфліктного злиття

Алгебраїчна структура, яка одночасно є **асоціативною, комутативною та ідемпотентною**, називається **верхньою напівґраткою** (англ. *join-semilattice*) і позначається як `(S, ∨)`, де операція `∨` зветься злиттям або верхньою гранню (англ. *join* / *least upper bound*).

Напівґратка природним чином задає на множині `S` відношення часткового порядку `≤`:
```
a ≤ b  ⇔  a ∨ b = b
```
Це означає, що злиття двох станів завжди рухає систему вперед у просторі знань: результат `a ∨ b` містить у собі всю інформацію стану `a` і всю інформацію стану `b`.

```
                    a ∨ b (Найменша верхня грань)
                   /     \
                  /       \
                 a         b
                  \       /
                   \     /
                    a ∧ b (Нижня грань)
```

#### Покрокове доведення стійкості перерахунку над напівґраткою

Нехай `E = {e₁, e₂, ..., eₙ}` — скінченна множина незмінних первинних подій за певний інтервал часу. Нехай `E_replayed` — мультимножина подій, яка утворилася під час збійного бекфілу, де деякі події продубльовані, а загальний порядок задано довільною перестановкою `π`:

```
E_replayed = [ e₂, e₁, e₂, e₃, e₁, e₂, ..., eₙ ]
```

Обчислимо результат агрегації `R` через послідовне застосування оператора злиття `∨`:

```
R = e₂ ∨ e₁ ∨ e₂ ∨ e₃ ∨ e₁ ∨ e₂ ∨ ... ∨ eₙ
  = e₁ ∨ e₁ ∨ e₂ ∨ e₂ ∨ e₂ ∨ e₃ ∨ ... ∨ eₙ   [комутативність: перегрупування однакових елементів]
  = (e₁ ∨ e₁) ∨ (e₂ ∨ (e₂ ∨ e₂)) ∨ e₃ ∨ ...   [асоціативність: виділення блоків дублів]
  = e₁ ∨ e₂ ∨ e₃ ∨ ... ∨ eₙ                   [ідемпотентність: e ∨ e = e]
  = ⋁_{e ∈ E} e                               [канонічний згорнутий стан множини E]
```

**Висновок**: для будь-якої структури, що утворює верхню напівґратку, результат обчислення над довільним потоком з дублями та перестановками **тотожно дорівнює** результату однократного обчислення над чистою множиною фактів.

### Класифікація аналітичних функцій за алгебраїчним типом

Не всі стандартні SQL-агрегати є ідемпотентними від природи. Саме нерозуміння алгебраїчного типу операції є головною причиною збоїв під час перерахунку звітів.

| Операція SQL | Алгебраїчна структура | Ідемпотентність (`a · a = a`) | Поведінка при наївному перерахунку |
| :--- | :--- | :--- | :--- |
| `MAX(x)`, `MIN(x)` | Верхня/нижня напівґратка | **Так** (`max(5, 5) = 5`) | Безпечно: повтор не спотворює результат |
| `COUNT(DISTINCT x)` | Напівґратка над множинами (`∪`) | **Так** (`{1,2} ∪ {2} = {1,2}`) | Безпечно: дублі ключів розчиняються |
| `BIT_OR(x)`, `BIT_AND(x)` | Булева напівґратка | **Так** (`0b1100 \| 0b1100 = 0b1100`) | Безпечно |
| `SUM(x)` | Комутативний моноїд `(ℝ, +)` | **Ні** (`10 + 10 = 20 ≠ 10`) | **Катастрофа**: подвоєння суми при повторі |
| `COUNT(x)` | Комутативний моноїд `(ℕ₀, +)` | **Ні** (`1 + 1 = 2 ≠ 1`) | **Катастрофа**: подвоєння кількості рядків |
| `AVG(x)` | Неасоціативна конструкція (`∑/n`) | **Ні** | **Катастрофа**: зміщення середнього значення |

### Техніки перетворення неідемпотентних операцій в ідемпотентні

Якщо бізнес-задача вимагає підрахунку неідемпотентних показників (`SUM`, `COUNT`, `AVG`), інженер має три математичні шляхи перетворення конвеєра в ідемпотентний.

#### 1. Модель доданих дельт з дедуплікаційним фільтром (Set Monoid Tracking)
Замість простого додавання сирих чисел до скалярного поля акумулятора зберігається множина пар `(event_id, value)`:
```
Стан = M ⊆ (UUID × ℝ)
Злиття(M₁, M₂) = M₁ ∪ M₂
```
Оскільки операція об'єднання множин `∪` є ідемпотентною напівґраткою (`M ∪ M = M`), підсумкова сума обчислюється як детермінована функція-проекція над накопиченою множиною:
```
SUM(M) = ∑_{(id, v) ∈ M} v
```
При повторному читанні події з уже наявним `event_id` вона потрапляє в множину без створення дубліката: `{ (e₁, 100), (e₂, 50) } ∪ { (e₁, 100) } = { (e₁, 100), (e₂, 50) }`.

#### 2. Ймовірнісні структури даних (HyperLogLog та Roaring Bitmaps)
Для обчислення кількості унікальних відвідувачів (*Cardinality Estimation*) над мільярдами подій замість точних множин використовують регістри **HyperLogLog (HLL)**.

Стан HLL — це фіксований вектор `M` із `m` байтових регістрів: `M = [r₀, r₁, ..., r_{m-1}]`.
Операція злиття двох HLL-ескізів `HLL_A` та `HLL_B` визначається поелементним максимумом:
```
Merge(HLL_A, HLL_B)[i] = max(HLL_A[i], HLL_B[i])  для всіх i ∈ [0, m-1]
```
Оскільки функція `max` є верхньою напівґраткою, об'єднання ескізів `HLL` є строго асоціативним, комутативним та ідемпотентним. Перерахунок історії за допомогою HLL дозволяє довільно комбінувати денні та місячні агрегати без ризику дублювання унікальних користувачів:
```
HLL_місяць = HLL_день_1 ∨ HLL_день_2 ∨ ... ∨ HLL_день_30
```

#### 3. Монотонні часові вектори та версіонування LWW (Last-Write-Wins)
Для операцій мутації рядків стан кожного поля моделюється парою `(Значення, Версія)` або `(Значення, Timestamp)` з частковим порядком за часом:
```
(v₁, t₁) ∨ (v₂, t₂) = (v₂, t₂)  якщо t₂ > t₁
(v₁, t₁) ∨ (v₂, t₂) = (v₁, t₁)  якщо t₁ > t₂
(v₁, t₁) ∨ (v₂, t₁) = (max(v₁, v₂), t₁)  якщо t₁ = t₂ (детермінований розрив нічиєї)
```
Це перетворює мутацію рядків у напівґратку: будь-який старий або дублюючий пакет подій із меншим чи рівним таймстемпом автоматично відкидається оператором `∨`.

#### 4. Обчислення середнього через комутативну пару (Sum-Count Pair)
Оскільки середнє `AVG` саме по собі не є ні асоціативним, ні ідемпотентним (`avg(avg(a, b), c) ≠ avg(a, b, c)`), у проміжних агрегатах зберігають вектор `(S, N)`, де `S = ∑ x_i`, а `N = count(x_i)` над множиною унікальних ключів `K`:
```
Стан = ( ∑_{k ∈ K} value(k), |K| )
Злиття((S₁, K₁), (S₂, K₂)) = ( ∑_{k ∈ K₁ ∪ K₂} value(k), |K₁ ∪ K₂| )
Фінальний AVG = S / N
```

Математична строгість напівґраток гарантує: якщо шар зберігання або алгоритм агрегації спирається на напівґратку, конвеєр перерахунку не потребує складних евристик чи ручного контролю — узгодженість досягається автоматично в силу законів алгебри.
