# 🧮 Статистичні межі виявлення дрейфу даних і розрахунок вибірки для SLO

У високонавантажених потокових системах через шлюз завантаження проходять сотні тисяч або мільйони подій на секунду (`10⁶` req/s). Повна верифікація складних бізнес-інваріантів (наприклад, перевірка унікальності первинного ключа по розподіленій базі, перевірка зовнішніх ключів або обчислення статистичного розподілу числових полів) для 100% рядків у реальному часі створює неприйнятне навантаження на обчислювальні ресурси та різко збільшує затримку обробки (англ. *latency penalty*).

Тому контроль виконання угоди про рівень обслуговування (англ. *Service Level Objective*, SLO) часто базується на **вибірковому аудиті** (англ. *sampled verification*). Виникає строге математичне завдання: який мінімальний розмір випадкової вибірки `n` необхідно перевірити, щоб гарантувати з довірчою ймовірністю `1 - α`, що реальна частка бракованих даних у потоці не перевищує граничний поріг `p₀ + ε`.

## Ймовірнісна модель помилки валідації

Нехай потік даних генерує послідовність записів `X₁, X₂, ..., Xₙ`. Для кожного запису введемо індикаторну випадкову величину помилки `Yᵢ`:

```
Yᵢ = 1,  якщо запис Xᵢ порушує інваріант контракту
Yᵢ = 0,  якщо запис Xᵢ повністю валідний
```

Випадкові величини `Yᵢ` є незалежними та однаково розподіленими за законом Бернуллі з невідомою справжньою ймовірністю дефекту `p = E[Yᵢ]`.

Вибіркова оцінка частки дефектів `p̂` для вибірки розміром `n` обчислюється як середнє арифметичне індикаторних величин:

```
p̂ = (1 / n) · ∑_{i=1}^{n} Yᵢ
```

SLO контракту стверджує, що допустима частка браку в стабільному стані не перевищує норму: `p ≤ p₀` (наприклад, `p₀ = 0.0001`, тобто 99.99% чистоти потоку).

Якщо внаслідок збою продюсера справжня частка дефектів зросла до `p = p₀ + ε` (де `ε > 0` — величина семантичного дрейфу), вибірковий аудит повинен виявити це порушення, обмеживши ймовірність помилки другого роду (пропуску дефекту, коли `p̂ ≤ p₀`) заданою величиною `α` (наприклад, `α = 0.01` або 99% надійності виявлення).

## Виведення мінімального розміру вибірки за нерівністю Гефдінга

Оскільки кожна величина `Yᵢ` обмежена відрізком `[0, 1]`, застосуємо експоненційну нерівність концентрації Гефдінга (англ. *Hoeffding's inequality*) для суми незалежних обмежених випадкових величин:

```
P(p̂ - p ≤ -ε) ≤ exp(-2 · n · ε²)
```

Підставимо умову, що справжній рівень помилок `p = p₀ + ε`, тоді подія `p̂ ≤ p₀` відповідає відхиленню оцінки ліворуч від її математичного сподівання на величину не менше ніж `ε`:

```
P(p̂ ≤ p₀ | p = p₀ + ε)
= P(p̂ - (p₀ + ε) ≤ -ε)       [підстановка: p = p₀ + ε]
≤ exp(-2 · n · ε²)            [нерівність Гефдінга для величин на [0, 1]]
```

Ми вимагаємо, щоб імовірність пропуску бракованого потоку не перевищувала допустимий поріг `α`:

```
exp(-2 · n · ε²) ≤ α
-2 · n · ε² ≤ ln(α)           [логарифмування обох частин нерівності]
2 · n · ε² ≥ ln(1 / α)        [множення на -1 зі зміною знаку нерівності]
n ≥ ln(1 / α) / (2 · ε²)      [ділення на додатний множник 2 · ε²]
```

Ця формула задає абсолютну непараметричну межу: вона гарантує необхідну точність незалежно від форми розподілу, спираючись виключно на факт обмеженості величини `Yᵢ`.

## Асимптотично точніші межі за нерівністю Чернова для рідкісних помилок

Коли базова норма дефектів є дуже малою величиною (наприклад, `p₀ = 10⁻⁴`), абсолютна нерівність Гефдінга дає дещо завищену оцінку вибірки, оскільки вона розглядає найгірший випадок дисперсії при `p = 0.5`.

Для рідкісних подій точніший результат дає мультиплікативна нерівність Чернова (англ. *multiplicative Chernoff bound*). Нехай `μ = E[∑ Yᵢ] = n · p`. Тоді ймовірність суттєвого недооцінювання помилок при відносному дрейфі `δ = ε / p` обмежується як:

```
P(p̂ ≤ (1 - δ) · p) ≤ exp(-μ · δ² / 2) = exp(-n · p · δ² / 2)
```

Виражаючи необхідний обсяг вибірки `n` для досягнення ймовірності помилки `α`:

```
exp(-n · p · δ² / 2) ≤ α
n · p · δ² / 2 ≥ ln(1 / α)
n ≥ 2 · ln(1 / α) / (p · δ²) = 2 · ln(1 / α) · p / ε²
```

Порівнюючи з межею Гефдінга `n_H = ln(1 / α) / (2 · ε²)`, відношення обсягів вибірок становить:

```
n_Chernoff / n_Hoeffding = 4 · p
```

Коли ймовірність браку `p = 0.002` (0.2%), оцінка Чернова показує, що для контролю відносного дрейфу достатньо значно меншої вибірки, ніж передбачає найконсервативніша межа Гефдінга.

## Послідовний аналіз Вальда (SPRT) для потокового моніторингу

У реальних конвеєрах шлюз обробляє події безперервно, тому фіксований розмір вибірки `n` можна замінити на **послідовний критерій відношення ймовірностей Вальда** (англ. *Sequential Probability Ratio Test*, SPRT).

SPRT перевіряє нульову гіпотезу `H₀: p = p₀` (потік відповідає нормі SLO) проти альтернативної гіпотези `H₁: p = p₁ = p₀ + ε` (потік містить неприпустимий брак).

Після спостереження `m` записів шлюз обчислює логарифмічне відношення правдоподібності `S_m`:

```
S_m = ∑_{i=1}^{m} z_i

де z_i = ln( (p₁ / p₀) · Yᵢ + ((1 - p₁) / (1 - p₀)) · (1 - Yᵢ) )
```

Правило ухвалення рішень Вальда базується на двох порогах:
- Нижня межа: `B = β / (1 - α)`
- Верхня межа: `A = (1 - β) / α`

де `α` — ймовірність хибної тривоги (відхилення чистого потоку), а `β` — ймовірність пропуску браку.

Алгоритм динамічного шлюзу на кожному кроці `m` виконує одне з трьох рішень:
1. Якщо `S_m ≥ ln(A)` — зупинити аудит, **відхилити нульову гіпотезу H₀** та негайно згенерувати аварійний алерт про порушення SLO продюсером.
2. Якщо `S_m ≤ ln(B)` — зупинити аудит, **прийняти нульову гіпотезу H₀** (потік визнано валідним) і скинути накопичений логарифм `S_m` до нуля для наступного інтервалу моніторингу.
3. Якщо `ln(B) < S_m < ln(A)` — даних недостатньо, продовжити накопичення вибірки для наступного повідомлення `m + 1`.

Середня кількість спостережень (ASN, Average Sample Number) при використанні SPRT є в середньому у 2–3 рази меншою порівняно з фіксованим тестом Гефдінга, що дозволяє виявляти масові аварії продюсера за лічені секунди.

## Довірчий інтервал Вільсона для оцінки якості дискретних батчів

Коли перевірка якості виконується над скінченними мікробатчами даних (наприклад, щогодинні вивантаження розміром `N = 10 000` рядків), стандартне наближення нормальним розподілом (інтервал Вальда) дає некоректні результати: при нульовій кількості помилок `k = 0` воно видає нульову ширину інтервалу `[0, 0]`, що є оманливим.

Для строгих гарантій SLO контрактів застосовується **інтервал оцінки Вільсона** (англ. *Wilson score interval*), який враховує асиметрію біноміального розподілу на краях. Верхня межа частки дефектів `p_upper` із квантилем нормального розподілу `z = 2.576` (для надійності 99%) обчислюється як:

```
p_upper = ( k + z² / 2 + z · √( (k · (N - k) / N) + z² / 4 ) ) / ( N + z² )
```

Якщо в батчі з `N = 10 000` записів виявлено `k = 2` бракованих рядки (`p̂ = 0.0002`), верхня довірча межа становить:

```
k + z² / 2 = 2 + (2.576)² / 2 = 2 + 3.318 = 5.318
z · √( (2 · 9998 / 10000) + 1.659 ) = 2.576 · √( 1.9996 + 1.659 ) = 2.576 · 1.9128 ≈ 4.927
N + z² = 10000 + 6.636 = 10006.636

p_upper = (5.318 + 4.927) / 10006.636 = 10.245 / 10006.636 ≈ 0.001024  (0.102%)
```

Якщо контракт вимагав гарантії `p ≤ 0.001`, шлюз автоматично фіксує ризик порушення SLO (оскільки `p_upper > 0.001`), навіть попри те, що точкова вибіркова оцінка `p̂ = 0.02%` виглядала формально допустимою. Це запобігає прихованій деградації якості даних на ранніх етапах.

## Розрахунковий приклад розміру аудиторської вибірки

Припустимо, контракт гарантує SLO якості: допустима частка дефектів `p₀ ≤ 0.001` (0.1%). Необхідно надійно виявити дрейф якості розміром `ε = 0.002` (частка помилок зросла до 0.3%) із надійністю `99%` (`α = 0.01`).

Обчислимо мінімальний обсяг вибірки `n` за формулою Гефдінга:

```
ln(1 / 0.01) = ln(100) ≈ 4.60517
2 · ε² = 2 · (0.002)² = 2 · 0.000004 = 0.000008

n ≥ 4.60517 / 0.000008
n ≥ 575 646.25 ≈ 575 647 записів
```

Якщо загальний потік подій становить `10⁷` записів на добу, для забезпечення 99% надійності виявлення дрейфу шлюзу достатньо провести глибоку валідацію приблизно `5.76 · 10⁵` випадково вибраних подій (лише 5.76% від загального обсягу потоку).

Це знижує навантаження на обчислювальні вузли валідації на 94.24%, гарантуючи суворе математичне дотримання умов data-контракту без затримок у доставці аналітичних даних.
