# МК як USB-host: читаємо флешки й клавіатури

Найзвичніша роль мікроконтролера в USB — бути **пристроєм** (device): встромив у ПК, плата відповідає на запити, живиться з лінії VBUS. Але той самий апаратний блок USB-OTG у ESP32-S2/S3 уміє й зворотне — стати **хостом** (host, від англ. *host* «господар, той, хто приймає гостей»): сам подавати живлення, сам виявляти підключені пристрої й опитувати їхні [кінцеві точки](book:programming/usb-endpoints). Цей текст — про те, що насправді означає така зміна ролі, чого вона коштує й коли по неї варто тягнутися.

Корисно тримати в голові головну несиметрію шини: у USB завжди є одна сторона, що командує, і одна чи кілька, що лише відповідають. Командує саме host — він задає темп, роздає адреси, ініціює кожну передачу. Тому слово «господар» тут буквальне: пристрій без дозволу host не скаже ані біта.

## Що означає бути хостом

Уся робота, яку в парі з пристроєм бере на себе ПК, лягає тепер на сам ESP32. Перелік обов'язків господаря короткий на словах, але великий у коді:

- **дати живлення** — підняти VBUS 5 В на порт і тримати його, доки триває сесія;
- **помітити підключення** — дочекатися, доки приєднаний пристрій підтягне D+ (Full Speed) або D− (Low Speed) до робочого рівня через свій резистор;
- **скинути й [пройти енумерацію](book:programming/usb-enumeration)** — видати сигнал reset, призначити пристрою адресу, вичитати дескриптори, вибрати конфігурацію;
- **відкрити кінцеві точки** й тримати **розклад передач** — слати кадр SOF (Start of Frame) кожну мілісекунду й опитувати їх за своїм планом;
- **керувати живленням і помилками** — стежити за струмом, гасити VBUS при перевантаженні, обробляти від'єднання.

Жодного з цих кроків у device-стеку немає: пристрій лише реагує. Саме тому host-стек у кілька разів більший і ненажерливіший до пам'яті, ніж device-стек. На практиці це й відчувається як головна ціна ролі: складність USB живе саме у [хості](book:programming/usb-overview), і взявши цю роль, ти береш складність на себе.

![Зліва ПК — host, чип — device (просто); справа чип — host, флешка й клавіатура — device (складніше). Стрілки команд завжди йдуть від host.](/book/programming/peripherals/usb-host/img/roles-swapped.svg)

*Той самий апаратний блок працює в обох напрямках; міняється не залізо, а хто кому віддає команди й хто дає живлення.*

## OTG: один роз'єм — дві ролі

Те, що один і той самий роз'єм уміє бути то пристроєм, то господарем, забезпечує розширення стандарту **USB OTG** (On-The-Go, англ. «на ходу» — тобто без участі ПК, прямо в полі). Роль визначається не програмою, а **статичним рівнем на контакті ще до першого біта даних**.

У класичному micro-USB це п'ятий контакт **ID**. Якщо ID плаває (не підключений) — контролер лишається пристроєм. Якщо ID замкнутий на землю — а так зроблено лише в OTG-кабелі з боку штекера micro-A — контролер стає хостом і, за специфікацією OTG, **зобов'язаний подати VBUS**. На сучасному USB-C ту саму роль грають резистори CC, але ідея незмінна: апаратний сигнал каже контролеру, хто головний, перш ніж піде будь-який обмін.

![Контакт ID, замкнутий на землю в OTG-кабелі, перемикає контролер у роль host іще до даних; плаваючий ID лишає його пристроєм.](/book/programming/peripherals/usb-host/img/otg-id-pin.svg)

*Роль задає залізо, а не прошивка: статичний рівень на ID (чи резистори CC на USB-C) вирішує все до енумерації.*

> 🔌 **Який кабель і звідки взяти 5 В** — практичний бік host-режиму: чим micro-A відрізняється від micro-B, які перехідники потрібні, три способи дістати VBUS і типові граблі. Деталі — у вставці [«OTG-кабель і host-модулі»](book:programming/usb-host/comp-otg.md).

## Що в сімействі ESP32 реально вміє host

Тут варто бути відвертим, бо плутанина коштує згаяного вечора. Host-режим тягнуть **лише ESP32-S2 і ESP32-S3** — лише вони мають нативний USB-OTG. Класичний ESP32 (без суфікса) [USB-контролера не має взагалі](book:programming/esp32-usb) — назовні в нього виходить тільки UART через окремий міст. ESP32-C3 і C6 мають блок USB-Serial-JTAG, але той уміє лише фіксовану роль пристрою (CDC+JTAG), і хостом стати не може. Отже, щойно проєкт потребує читати USB-периферію з мікроконтролера, вибір чипа звужується до S2 або S3 — це перше, що варто перевірити, перш ніж планувати решту.

## Найчастіші ролі хоста на МК

Два сценарії покривають майже всі практичні випадки, коли взагалі варто вмикати host.

**Читати USB-флешку (клас MSC).** Оновлення прошивки чи конфігурації з флешки без програматора; збір логів на знімний носій, який потім просто виймають і несуть до ПК. ESP32-S3 у ролі господаря монтує [файлову систему](book:programming/flash-filesystems) FAT на флешці й читає та пише файли так само, як із SD-картки.

**Приймати USB-клавіатуру (клас HID).** Ввід даних чи команд стандартною клавіатурою, без власної фізичної матриці кнопок. Промисловий або медичний прилад зі звичайною USB-клавіатурою на вході — типовий випадок: дешево, звично оператору, нічого не треба паяти.

Поряд з ними host-режим відкриває й сканери штрих-кодів, аудіопристрої, модеми — але саме флешка й клавіатура трапляються найчастіше, тож на них і варто міряти, чи потрібен вам host узагалі.

![МК-host у центрі: ліворуч флешка класу MSC (логи й оновлення), праворуч клавіатура класу HID (ввід без матриці кнопок); обом потрібне VBUS 5 В.](/book/programming/peripherals/usb-host/img/host-use-cases.svg)

*Дві найчастіші причини зробити МК хостом — знімний носій і клавіатура; обидві вимагають подати на порт зовнішні 5 В.*

## Живлення тепер на тобі

У ролі пристрою живлення приходить дарма: VBUS дає ПК. У ролі господаря все навпаки — **подавати VBUS 5 В мусить сам ESP32**. А чип живиться від 3.3 В і власного boost-перетворювача на шину не має. Тому для host-режиму потрібне [зовнішнє джерело 5 В і електронний ключ](book:programming/usb-power) (наприклад, P-канальний MOSFET або спеціальна мікросхема USB-switch), яким мікроконтролер вмикає й вимикає VBUS на порт. Без цього встромлена флешка просто не отримає живлення — і з боку стека все виглядатиме справно, хоч пристрій мертвий.

Саме звідси й береться правило: «голий» DevKit без зовнішніх доповнень не потягне host для периферії, що живиться від шини. Або беруть плату з ключем VBUS на борту, або додають зовнішні 5 В, або вмикають живлений хаб — інакше господар є, а годувати гостей нічим.

> 🔧 **Навіщо це.** Host-режим відкриває широкий клас задач — флешки, клавіатури, сканери, аудіо, модеми, — але платиться більшою пам'яттю й кодом проти device-стека і вимагає зовнішніх 5 В для VBUS. Для більшості проєктів на ESP32 оптимальна роль — пристрій; хост обирають свідомо, коли він справді потрібен і коли під рукою S2 або S3. Перевірити це **до** розведення плати дешевше, ніж після.

## Worked-приклад: host опитує клавіатуру

Ілюстративний кістяк на базі ESP-IDF USB Host Library. Видно головне: коли спрацьовує callback підключення, господар **уже** провів усю енумерацію сам — нам лишається почепити клас-драйвер і читати звіти.

```c
#include "usb/usb_host.h"
#include "usb/hid_host.h"

/* Callback при підключенні нового пристрою */
static void device_connected_cb(usb_device_handle_t dev_hdl,
                                 const usb_config_desc_t *config_desc)
{
    /* host-стек уже провів енумерацію: адресу призначено,
       дескриптори прочитано, конфігурацію встановлено */
    hid_host_device_handle_t hid_dev;
    hid_host_install_device(dev_hdl, &hid_dev);
}

/* Callback при отриманні HID-звіту (interrupt-IN) */
static void hid_report_cb(hid_host_device_handle_t hid_dev,
                          const hid_report_t *report)
{
    if (report->usage == HID_USAGE_KEYBOARD) {
        uint8_t keycode = report->keyboard.keycode[0];
        if (keycode != 0) {
            /* keycode — код клавіші зі стандарту HID Usage Tables */
            printf("Key pressed: 0x%02X\n", keycode);
        }
    }
}

void app_main(void)
{
    /* 1. Підняти USB Host */
    usb_host_config_t host_config = { .intr_flags = ESP_INTR_FLAG_LEVEL1 };
    usb_host_install(&host_config);

    /* 2. Встановити клас-драйвер HID */
    hid_host_config_t hid_config = {
        .create_background_task = true,
        .task_priority = 5,
        .stack_size    = 4096,
        .callback      = hid_report_cb,
    };
    hid_host_install(&hid_config);

    /* 3. Головний цикл: крутимо події USB Host Library */
    while (1) {
        uint32_t event_flags;
        usb_host_lib_handle_events(portMAX_DELAY, &event_flags);
        if (event_flags & USB_HOST_LIB_EVENT_FLAGS_NO_CLIENTS) {
            usb_host_device_free_all();
        }
    }
}
```

Зверни увагу: код не торкається VBUS. Мається на увазі, що 5 В уже подано — ключ живлення підняли окремим GPIO **перед** `usb_host_install`. Якщо цього не зробити, callback підключення просто ніколи не спрацює, бо живити гостя нічим.
