# 🧮 Згортка навиворіт: математика ітератора

Коли ти пишеш `list.forEach(f)` чи `reduce`, ти — з погляду математики — виконав **згортку**: зібрав усю колекцію в одне значення однією операцією, і кермом усередині крутила сама колекція. Зовнішній ітератор із `hasNext()`/`next()` — це **та сама згортка, вивернута навиворіт**: кермо повернуто клієнтові, а «решта обходу», яка у згортці мовчки жила на стеку викликів, витягнута назовні в явний, збережний стан. Тут ми зробимо цю двоїстість точною — покажемо, що передати функцію в колекцію математично тотожно згорнути її згортком, — і з'ясуємо, що саме робить обхід коректним.

## Згортка: згортання структури до значення

Список — це одна з двох форм: або він порожній, або це голова, приклеєна до хвоста. Запишімо цей устрій двома конструкторами: `[]` (порожній, *nil*) і `(:)` (приклеїти голову до хвоста, *cons*). Тоді `[3, 1, 4]` насправді є `3 : (1 : (4 : []))`. Ця рекурсивна форма — увесь секрет: щоб означити будь-що над списком, досить сказати дві речі — на що перетворюється `[]` і на що перетворюється `x : хвіст`, якщо хвіст ти вже обробив. Означувати значення над формою за випадками її конструкторів, спираючись на вже оброблену меншу частину, — це [структурна рекурсія](book:algorithms/recursion): рекурсія, чий базовий випадок і крок точно повторюють базу й крок самого типу даних.

Згортка (англ. *fold*, *reduce*) пакує рівно цей прийом у один оператор. Даєш їй дві речі: початкове значення `z` (на що обертається `[]`) і поєднувач `f` (на що обертається `x : хвіст`, коли вже маєш `x` і згорнутий хвіст). Означення — дослівний відбиток двох конструкторів:

```
fold(f, z, [])        = z
fold(f, z, x : хвіст) = f(x, fold(f, z, хвіст))
```

Інтуїція — **заміна конструкторів**. Згортка просто переписує список, підставивши `f` замість кожного `(:)` і `z` замість `[]`:

```
    3 : ( 1 : ( 4 : [] ))        ← список
    3 f ( 1 f ( 4 f  z  ))       ← (:) ↦ f,  [] ↦ z
  = f(3, f(1, f(4, z)))
```

Обчислюєш зсередини — від `z` — назовні, і вся структура сходиться в одне значення. Функція `f` тут — звичайне [значення, яке передають в аргумент](book:programming/first-class-functions) і викликають усередині згортки; саме тому одним оператором `fold` виражають цілий клас обходів, лише міняючи пару `(f, z)`.

**Приклад: сума як згортка.** Візьмімо `f = (+)`, `z = 0` над `[3, 1, 4]`:

```
fold(+, 0, [3,1,4]) = f(3, f(1, f(4, 0)))
                    = 3 + (1 + (4 + 0))
                    = 3 + (1 + 4)
                    = 3 + 5
                    = 8
```

Поміняй пару — і той самий механізм дає інше. `f = (x, n) ↦ n + 1`, `z = 0` рахує довжину. `f = (x, a) ↦ [g(x), …a]`, `z = []` дає `map`. Сума, довжина, `map`, `filter`, розворот, ба навіть звичайне копіювання списку — усе це один оператор з різними `(f, z)`.

![Список 3 : 1 : 4 : [] угорі; посередині — заміна конструкторів (двокрапку на f, порожній список на z); унизу вкладений вираз f(3, f(1, f(4, z))), що згортається зсередини назовні в одне число 8. Праворуч підпис: катаморфізм — згортає структуру ВНИЗ до значення.](/book/programming/design-patterns/iterator/img/iterator-fold-collapse.svg)
*Згортка переписує список, підставляючи поєднувач замість «приклеїти» і початкове значення замість «порожньо», а тоді сходить усе в одну величину.*

> 🔧 **Навіщо це.** Згортка — це єдина форма, що стоїть за кожним «торкнутися кожного елемента рівно раз і зібрати результат». Коли бачиш цикл, що біжить колекцією й накопичує, — сума, добуток, найбільше, конкатенація рядків, побудова нового списку, — ти бачиш згортку в конкретному вбранні. Зрозумівши її одну, розумієш увесь клас.

Категорійне ім'я цієї згортки — **катаморфізм** (гр. *katá* — «вниз» + *morphḗ* — «форма»): згортка сходить структуру *вниз* до одного значення. Категорійне трактування згорток як катаморфізмів увів клясичний допис «Functional Programming with Bananas, Lenses, Envelopes and Barbed Wire» (Erik Meijer, Maarten Fokkinga, Ross Paterson, 1991), а загальне категорійне означення згодом уточнив Grant Malcolm; згортка узагальнюється на будь-який алгебричний тип даних, не лише список (доказовий статус — усталений, рецензована праця). Сам оператор старший: згортання масиву операцією було вже в APL як редукція `/` (Kenneth Iverson, «A Programming Language», 1962: `+/x` дає суму `x`), а ліві й праві згортки досліджував Christopher Strachey близько 1961 року (статус — добре задокументований).

Є ще одна річ, без якої двоїстість нижче була б випадковим спостереженням, а не рівністю. Згортка — не просто *якийсь* розв'язок рекурсії `h([]) = z`, `h(x : хвіст) = f(x, h(хвіст))`; вона **єдиний** такий `h`. Це **універсальна властивість згортки**, яку Graham Hutton у праці «A Tutorial on the Universality and Expressiveness of Fold» (Journal of Functional Programming, 1999) перетворив на принцип означення й доведення: будь-яка функція, задана цим взірцем рекурсії, *є* згорткою, і рівності про неї доводяться без індукції. Для нас це означає одне: «пройти колекцію й накопичити» має канонічну форму — згортку, — і все, що чесно відвідує кожен елемент рівно раз, є її окремим випадком.

## Внутрішня ітерація — це і є згортка

`forEach` на вигляд не схожий на `reduce`: перший нічого не повертає, другий повертає значення. Та `forEach` — теж згортка, тільки над порожнім значенням: `z = ⟨нічого⟩`, `f = (x, _) ↦ ⟨зроби ефект над x, тоді нічого⟩`. `reduce`, `map`, `filter` — згортки за самою побудовою. Спільна риса важливіша за відмінності: **рекурсію крутить колекція**, ти лише подаєш `f` (і `z`). Цикл вбудований у `fold`; керування живе всередині колекції. Це і є внутрішня ітерація — пасивна з боку клієнта.

```python
def fold_right(f, z, xs):
    acc = z
    for x in reversed(xs):            # згортаємо з правого кінця (z) назовні
        acc = f(x, acc)
    return acc

total  = fold_right(lambda x, a: x + a,     0,  [3, 1, 4])   # 8
length = fold_right(lambda x, a: a + 1,     0,  [3, 1, 4])   # 3
mapped = fold_right(lambda x, a: [x * x] + a, [], [3, 1, 4]) # [9, 1, 16]
```

У мові, збудованій навколо цього, згортка — просто вбудований примітив: у Haskell вона зветься `foldr :: (a -> b -> b) -> b -> [a] -> b`, і `sum`, `length`, `map` там — три однорядкові її застосування.

Коли `f` асоціативна, а `z` — її нейтральний елемент, порядок згортання перестає впливати на **результат**: `f(f(a, b), c) = f(a, f(b, c))` і `f(z, a) = f(a, z) = a`. Пара «асоціативна операція з нейтральним елементом» — це [моноїд](book:math/monoid), а згортка над моноїдом є гомоморфізмом, який вільно перебивати дужками й ділити між потоками (паралельний `reduce`). Саме тому сума розпаралелюється, а віднімання — ні: `+` з `0` утворює моноїд, а `−` асоціативності не має.

## Виворіт: інверсія керування

Тепер хочемо дзеркало. Клієнт тягне по одному елементу через `next()`, сам вирішує, коли спинитися, веде два обходи в ногу. Перешкода структурна: рекурсія згортки збігає до кінця одним подихом — вона ніде не завмирає на `k`-му елементі, щоб віддати тобі кермо. Щоб дістати обхід на витягування, згортку треба **заморозити посеред рекурсії** й уміти відновити з того самого місця.

У цього вивороту є ім'я — **інверсія керування** (*inversion of control*). Термін увели Ralph E. Johnson і Brian Foote у праці «Designing Reusable Classes» (Journal of Object-Oriented Programming, 1988) — «голлівудський принцип»: не телефонуй нам, ми зателефонуємо тобі. Саме перетворення циклу-що-штовхає на процедуру-яку-тягнуть ще старше: Michael Jackson називав його *program inversion* у методі Jackson Structured Programming ще в 1970-х (статус — добре задокументований). У згортці колекція кличе твій `f` — керує вона; у зовнішньому ітераторі ти кличеш його `next()` — керуєш ти. Той самий обхід, кермо в іншій парі рук.

Та назвати виворіт — ще не зробити його. Щоб призупинити рекурсію, треба вловити «що лишилося зробити» як щось, що кладеться в змінну. Об'єкт, який пам'ятає своє місце між викликами, — це [машина станів](book:programming/state-machine): скінченний набір станів і переходів між ними. Лишається знайти, що це за стани.

## Defunctionalization: «решту обходу» роблять явними даними

Заморозьмо `f(3, f(1, f(4, z)))` на першому кроці. Ти віддаєш `3`, а лишається `f(1, f(4, z))` — відкладене обчислення з діркою там, куди піде внесок трійки: `f(3, ▢)`. Ця дірка — **продовження** (континуація), «решта обходу». Щоб зберегти її між викликами `next()`, функцієподібний залишок треба обернути на **дані**.

Це і є **defunctionalization** Рейнольдса. Прийом описав John C. Reynolds у праці «Definitional Interpreters for Higher-Order Programming Languages» (1972; статус — фундаментальний, усталений). Спостереження таке: у програмі лише *скінченно багато* форм функцій; познач кожну конструктором даних, а «виклич функцію» заміни на «збережи мітку з її захопленими значеннями, а згодом розберися з нею в єдиному `apply`, що диспетчеризує за міткою». Вища-порядкова функція обертається на явний стан плюс одну функцію кроку.

Прикладімо до обходу. «Решту обходу» списку будь-якої миті описує одна-єдина річ: який хвіст ще не спожито. Тож defunctionalization згортає весь стан в один **курсор** — вказівник на непройдений суфікс. `next()` читає голову й пересуває курсор на хвіст:

```python
class ListIterator:
    def __init__(self, head):
        self.cur = head              # стан = решта обходу, згорнута в ОДИН вказівник

    def has_next(self):
        return self.cur is not None

    def next(self):
        node = self.cur
        self.cur = node.next         # δ: крок до наступного стану
        return node.value
```

Для списку відкладене обчислення — рівний ланцюжок, тож вистачає одного вказівника. А ось де defunctionalization по-справжньому заробляє — це дерево. Симетричний обхід (*in-order*) двійкового дерева рекурсує ліворуч, відвідує вузол, рекурсує праворуч:

```
inorder(t, z) = якщо t порожнє: z
                інакше: inorder(t.right,
                                f(t.value,
                                  inorder(t.left, z)))
```

У мить, коли ми віддаємо вузол, «решта» — це: доробити праве піддерево цього вузла, а тоді ще не пройдені праві піддерева всіх предків, по порядку. Це вже не один вказівник — це **стек** відкладених вузлів. І цей стек — не що інше, як власний стек викликів рекурсії, зроблений явним. Знефункціоналізувати симетричну згортку означає витягти прихований стек викликів мови у звичайний список, який ти тримаєш у полі:

```python
class InOrderIterator:
    def __init__(self, root):
        self.stack = []
        self._descend(root)          # стан = стек напівпройдених вузлів

    def _descend(self, node):
        while node is not None:      # завантажуємо лівий хребет
            self.stack.append(node)
            node = node.left

    def has_next(self):
        return len(self.stack) > 0

    def next(self):
        node = self.stack.pop()      # δ: наступний найлівіший вузол
        self._descend(node.right)    # праве піддерево стає новою «рештою»
        return node.value
```

Версія з генератором і `yield` пише цей стек за тебе: компілятор застосовує defunctionalization до обходу сам, заморожуючи кадр виклику як відновний об'єкт. Обчислення, застигле посеред кроку й здатне ожити з того самого місця, — це [корутина](book:cpp-standards/coroutines); генератор — це згортка, поставлена на паузу.

Праворуч «зовнішній ітератор»: той самий вираз заморожено на f(3, ▢), де дірка ▢ збережена як явний стан q; клієнт тягне next() і дістає 3, стан переходить у наступну дірку — керує клієнт, «решту» згорнуто в дані.](img/iterator-defunc.svg)
*Інверсія керування плюс defunctionalization: те саме відкладене обчислення, що у згортці живе на стеку викликів, стає збережним станом ітератора — дірку континуації обертають на дані.*

## Три інваріанти коректного обходу

Тепер можна точно сказати, що таке «коректний». Хай колекція тримає мультимножину елементів `E` (мультимножину — бо дублікати рахуються). Обхід породжує послідовність `e₀, e₁, …`. Три властивості:

**1. Кожен елемент — рівно раз.** Породжена послідовність є перестановкою `E`: як мультимножини `{e₀, e₁, …} = E`. Дві поломки дзеркальні. *Пропуск* — якийсь елемент так і не з'явився (послідовність не накриває всього `E`). *Подвійне відвідування* — елемент з'явився частіше за свою кратність. Формально відображення «позиція ↦ елемент» має бути бієкцією між `{0, …, n−1}` і `E`-з-кратностями. Саме це руйнує пастка недійсного ітератора: зміна колекції посеред обходу перекроює граф станів так, що подальший шлях курсора вже не є бієкцією на недоторкані елементи — щось проскочить або повториться.

**2. Скінченність (термінація).** На скінченній колекції обхід спиняється. Мовою автомата: з `q₀` немає нескінченного ланцюга `q₀ → q₁ → q₂ → …` — кожен шлях доходить до фінального стану. Чистий спосіб це гарантувати — пред'явити міру `μ(q) ∈ ℕ`, що *строго* спадає з кожним кроком: `μ(q′) < μ(q)`. Для спискового курсора `μ` — довжина непройденого суфікса; для дерева `μ` — кількість ще не відданих вузлів. Строго спадна послідовність натуральних чисел не може тривати вічно (це фундованість `ℕ`) — отже, обхід завершується. Це той самий доказ через фундовану рекурсію, що робить скінченною структурну рекурсію над скінченним типом. Два чесні застереження. По-перше, нескінченний ітератор (усі числа Фібоначчі) *навмисне* не має фінального стану — термінувати не його робота; замість цього завершуватися має кожен *крок* (продуктивність), а зупинку накладає клієнт. По-друге, зіпсутий ітератор, що забув зменшити `μ` (курсор, який не рушає), крутиться вічно — пропущене спадання й є той баг.

**3. Означений порядок.** `next()` детермінований: той самий стан колекції ⇒ той самий наступний елемент. Порядок — це повний лад, який фіксує обхід: право-ліва `foldr` проти ліво-правої `foldl`, або прямий/симетричний/зворотний обхід дерева. Для множини чи геш-таблиці природного ладу немає — контракт слабший, але не порожній: порядок *не означений наперед*, проте мусить бути *якимось одним фіксованим* на час одного обходу, бо сам інваріант «рівно раз» спирається на стабільне перелічення. Геш-таблиця, що перегешувалася посеред ітерації, втратила б і порядок, і бієкцію — тому мови це й забороняють.

Ці три — не оздоба: саме вони дають клієнтові право довіряти, що `for x in c` торкнеться кожного елемента раз, спиниться й зробить це в повторюваному порядку.

## Ітератор ≡ автомат обходу

Складімо частини — і зовнішній ітератор виявляється **детермінованим автоматом**: машиною, чиї стани — це «решта обходу», обернена defunctionalization на дані, а переходи видають елементи. Означмо її:

```
Q          — множина станів обходу (defunctionalized «решта»)
q₀ ∈ Q     — початковий стан (від колекції)
Fin ⊆ Q    — фінальні стани (обхід скінчено)
δ : (Q \ Fin) → E × Q   — крок: із нефінального q видати елемент і перейти далі
```

Тоді два методи ітератора — це буквально:

```
hasNext()  ≡  q ∉ Fin
next()     ≡  хай δ(q) = (e, q′);   стан ← q′;   повернути e
```

Прогнати машину від `q₀`, доки вона не впаде у `Fin`, — означає видати `e₀, e₁, …, e₍ₙ₋₁₎`, і цей вихідний потік точно збігається з порядком обходу згортки. Це машина в дусі Мілі: вихід — на переходах. І тут двоїстість замикається в тотожність: згорни поєднувач `f` над вихідним потоком автомата — і відновиш `fold(f, z, колекція)`:

```
fold(f, z, c)  =  прогнати(iterator(c))  згорнуте з (f, z)
```

Тобто внутрішня ітерація = (зовнішній автомат) + (цикл, що згортає його вихід), а зовнішній ітератор = defunctionalize(fold). Кожне механічно виводиться з іншого. Оце й є точний сенс, у якому «віддати функцію колекції» і «тягти елементи по одному» — одна математика під двома обличчями.

![Ланцюг станів автомата обходу: q₀ переходом next()→3 йде в q₁, далі →1 в q₂, далі →4 у фінальний стан q₃ (подвійне коло, hasNext()=false). Під кожним станом — його зміст для списку: суфікси [3,1,4] → [1,4] → [4] → []. *Зовнішній ітератор як детермінований автомат: hasNext() питає, чи стан фінальний, а next() застосовує перехід δ — видає елемент і зсуває стан; вихідний потік машини дослівно є порядком згортки.*

Одне слово честі про «скінченний». Для скінченної колекції множина досяжних станів скінченна: список із `n` елементів має рівно `n + 1` стан (`n + 1` суфіксів), тож це справді скінченний автомат. Для лінивого чи нескінченного джерела множина досяжних станів необмежена (кожен крок Фібоначчі вигадує свіжий стан), тож `δ` лишається детермінованою функцією переходу, але над зліченно-нескінченним простором станів — автомат у широкому сенсі, не скінченний. Машина стану обходу скінченна рівно тоді, коли скінченне те, що вона обходить.

## Одна згортка, побачена з обох кінців

Отже, увесь механізм ітератора стоїть на одній рівності. Внутрішня ітерація — це катаморфізм: колекція згортає твій `f` над своїми елементами, а цикл захований у її власній рекурсії. Зовнішній ітератор — той самий катаморфізм із інвертованим керуванням (ти тягнеш, а не тебе кличуть) і континуацією, яку defunctionalization обернула на дані (відкладена рекурсія — чи то один вказівник на хвіст, чи цілий стек предків — стає явним станом, який можна заморозити й відновити). Коректність — це три властивості отриманої функції переходу: її вихід є бієкцією на елементи (кожен рівно раз), її міра кроку фундована на скінченному вході (обхід термінує), а `δ` є функцією (порядок означений). Генератори лише дають компіляторові зробити defunctionalization за тебе; баг недійсного ітератора — це просто зміна, що зламала бієкцію; паралельний `reduce` — це окремий випадок, де `f` утворює моноїд і порядок перестає важити для відповіді. Одна згортка, побачена з обох кінців.
