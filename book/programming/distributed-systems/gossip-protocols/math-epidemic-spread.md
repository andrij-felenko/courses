# 🧮 Математика епідемічної збіжності та детектування збоїв

Епідемічні протоколи поширення інформації спираються на класичну теорію стохастичних процесів та динаміку популяційних інфекцій. Щоб гарантувати надійність розподіленої системи, інженер має точно оцінювати три величини: кількість раундів до повного охоплення всіх вузлів, обсяг надлишкового мережевого трафіку та ймовірність хибного виявлення збою в нестабільній мережі.

---

## 1. Динаміка поширення: модель «сприйнятливі — інфіковані» (SI)

Розглянемо кластер із `N` однорідних вузлів. У кожен дискретний часовий раунд `t` (`t = 0, 1, 2, ...`) кожен вузол перебуває в одному з двох станів:
- `S_t` — кількість сприйнятливих вузлів (англ. *Susceptible*), які ще не отримали оновлення;
- `I_t` — кількість інфікованих вузлів (англ. *Infected*), які вже зберегли оновлення та транслюють його.

Для системи виконується закон збереження популяції:

```
S_t + I_t = N      [постійний розмір кластера]
```

На початку процесу (`t = 0`) лише один вузол генерує оновлення: `I_0 = 1`, `S_0 = N - 1`. У кожному раунді кожен інфікований вузол обирає `k` випадкових партнерів (коефіцієнт розмноження / fanout) рівномірно з усієї множини `N`.

---

## 2. Механізм Push: вибуховий старт і повільний фініш

У моделі Push інфіковані вузли активно надсилають оновлення випадково обраним сусідам.

Обчислимо ймовірність того, що конкретний сприйнятливий вузол `u` **не буде обраний** жодним із `I_t` інфікованих вузлів протягом раунду:

```
P(вузол u не обраний вузлом v)
= 1 - k / (N - 1)      [вибір k випадкових партнерів із N-1 можливих]
≈ 1 - k / N            [припущення для великих кластерів N >> 1]
```

Оскільки вибір партнерів кожним із `I_t` інфікованих вузлів є незалежною подією, ймовірність того, що вузол `u` уникне контакту з усіма інфікованими вузлами:

```
P(u лишився сприйнятливим)
= (1 - k / N)^(I_t)      [добуток незалежних імовірностей]
≈ e^(-k · I_t / N)       [використано границю (1 - x/N)^M ≈ e^(-x M / N)]
```

Математичне сподівання кількості сприйнятливих вузлів у наступному раунді `S_{t+1}`:

```
S_{t+1}
= S_t · (1 - k / N)^(I_t)      [перемноження на поточну кількість сприйнятливих]
≈ S_t · e^(-k · I_t / N)       [експоненційне наближення]
```

### Аналіз двох фаз протоколу Push

**Рання фаза (`I_t << N`, `S_t ≈ N`):**
Коли інфікованих вузлів мало, імовірність перетину їхніх виборів близька до нуля. Кожен інфікований вузол успішно заражає `k` нових вузлів:

```
I_{t+1}
= I_t + k · I_t      [кожен вузол заражає k нових сусідів]
= I_t · (1 + k)      [експоненційне розширення]
```

Звідси кількість інфікованих вузлів зростає як геометрична прогресія `I_t = (1 + k)^t`. Кількість раундів для досягнення 50% кластера становить:

```
t_half
= log_(1 + k)(N / 2)      [розв'язання рівняння (1+k)^t = N/2]
= O(log N)                [логарифмічна швидкість]
```

**Пізня фаза (`I_t ≈ N`, `S_t << N`):**
Коли майже всі вузли вже мають оновлення, інфіковані вузли марно надсилають повідомлення іншим інфікованим вузлам. Кількість сприйнятливих вузлів зменшується лише в постійне число разів за раунд:

```
S_{t+1}
≈ S_t · e^(-k)      [оскільки I_t / N ≈ 1]
```

Щоб досягти останнього сприйнятливого вузла (`S_t = 1`), протокол Push змушений генерувати сумарно `O(N · log N)` зайвих повідомлень, зазнаючи сильної деградації ефективності на фініші.

## 3. Механізм Pull: квадратичний фініш

У моделі Pull сприйнятливі вузли самі періодично опитують `k` випадкових сусідів, запитуючи їхній дайджест стану.

Вузол `u` залишиться сприйнятливим у раунді `t+1` тоді й лише тоді, коли всі `k` опитаних ним партнерів також виявляться сприйнятливими:

```
P(обраний партнер є сприйнятливим)
= S_t / N      [частка неінфікованих вузлів у системі]
```

Ймовірність того, що всі `k` випадково обраних партнерів є сприйнятливими:

```
P(усі k партнерів сприйнятливі)
= (S_t / N)^k      [добуток імовірностей k незалежних виборів]
```

Тоді кількість сприйнятливих вузлів у наступному раунді дорівнює:

```
S_{t+1}
= S_t · (S_t / N)^k      [множимо поточну кількість на ймовірність невдачі]
= (S_t)^(k + 1) / N^k    [квадратичне/степеневе придушення залишку]
```

Введемо частку сприйнятливих вузлів `s_t = S_t / N`. Рівняння набуває елегантного вигляду:

```
s_{t+1}
= (S_t / N)^(k + 1)      [ділимо обидві частини на N]
= (s_t)^(k + 1)          [суперекспоненційне згасання частки неінфікованих]
```

### Приклад обчислення пізньої фази для `k = 2`

Нехай у системі лишився 1% неінфікованих вузлів (`s_t = 0.01`):

```
s_{t+1}
= (0.01)^(2 + 1)      [застосування формули s_{t+1} = s_t^3]
= (10^(-2))^3         [піднесення до степеня]
= 10^(-6)             [один вузол на мільйон!]
```

Один додатковий раунд Pull знищує залишок неінфікованих вузлів із частки `10^(-2)` до `10^(-6)`.

## 4. Оптимум: комбінований протокол Push-Pull

Поєднання двох підходів забезпечує математично бездоганну конвергенцію:
1. **Фаза 1 (від `1` до `N/2` вузлів):** домінує Push, розганяючи поширення експоненційно за `O(log N)` раундів.
2. **Фаза 2 (від `N/2` до `N` вузлів):** домінує Pull, ліквідуючи залишок за `O(log(log N))` раундів.

Сумарний час повної синхронізації кластера:

```
T_total
= O(log N) + O(log(log N))      [сума двох фаз]
= O(log N)                      [асимптотична оцінка]
```

При цьому кожен вузол у кожному раунді генерує рівно `k` повідомлень, що гарантує суворе обмеження локального трафіку `O(k)`.

## 5. Модель SIR: правила зупинки пліток (Rumor Mongering)

Щоб запобігти нескінченному циркулюванню застарілих пліток у мережі, класичний алгоритм Демерса вводить третій стан — **Removed** (вузол видалено / вилікувано). Отримуємо класичну трифазну модель SIR:
- `S` (Susceptible): ще не чув новину;
- `I` (Infective): знає новину й активно її поширює;
- `R` (Removed): знає новину, але припинив поширення.

Вузол переходить зі стану `I` у стан `R` за правилом зворотного зв'язку (Feedback Counter). Коли інфікований вузол контактує з сусідом, який **вже володіє цією пліткою**, він із фіксованою ймовірністю `1 / b` (де `b` — поріг повторів, зазвичай `b = 2` або `3`) вирішує, що чутка втратила актуальність, і переходить у стан `R`.

Частка залишкових неінфікованих вузлів `s_inf` після повного згасання плітки задовольняє трансцендентне рівняння:

```
s_inf
= e^(-(k + 1) · (1 - s_inf))      [граничний стан епідемічного процесу]
```

Для `k = 3` частка вузлів, що не отримали новину до моменту зупинки плітки, становить менше ніж `0.001` (менше ніж 0.1% кластера).

## 6. Стійкість до втрати пакетів та поріг надійності

У реальних мережах частина UDP-пакетів губиться з імовірністю `p`. Ефективний коефіцієнт розмноження стає рівним:

```
k_eff
= k · (1 - p)      [математичне сподівання кількості доставлених повідомлень]
```

Для збереження гарантії поширення з імовірністю помилки, що не перевищує `ε`, мінімальний fanout `k` повинен задовольняти нерівність:

```
k
≥ (ln N - ln ε) / (1 - p)      [поріг надійності при втратах у мережі]
```

Наприклад, для кластера з `N = 10 000` вузлів при втратах у мережі `p = 20%` (`0.2`) та допустимій імовірності збою `ε = 10^(-6)`:

```
k
≥ (ln(10000) - ln(10^(-6))) / (1 - 0.2)      [підстановка параметрів N=10000, ε=10^(-6), p=0.2]
= (9.21 + 13.81) / 0.8                      [обчислення логарифмів ln(10000) та ln(10^(-6))]
= 23.02 / 0.8                               [додавання в чисельнику]
≈ 28.8                                      [ділення на коефіцієнт надійності каналу]
```

Збільшення fanout до `k ≈ 29` гарантує повне поширення оновлення навіть за умов втрати кожного п'ятого пакета.

## 7. Детектор збоїв Phi Accrual: математична модель

Замість бінарного рішення («живий / мертвий») адаптивний детектор Phi Accrual вимірює рівень підозри `phi` (`φ`) на основі ковзного вікна інтервалів між надходженнями пульсу (heartbeat).

Нехай у ковзному вікні розміру `W` зафіксовано часові інтервали між пакетами `Δt_1, Δt_2, ..., Δt_W`.

1. Обчислюємо вибіркове середнє `μ` та вибіркову дисперсію `σ^2`:

```
μ = (1 / W) · ∑ Δt_i                 [математичне сподівання інтервалу]

σ² = (1 / W) · ∑ (Δt_i - μ)²         [дисперсія інтервалу надходження]
```

2. Припускаючи нормальний розподіл затримок, імовірність `P_later(t)` того, що черговий пульс запізниться на час `t` (де `t = t_now - t_last`), обчислюється через функцію розподілу:

```
P_later(t)
= 1 - F(t)                                      [хвіст розподілу ймовірностей]
= (1 / 2) · erfc((t - μ) / (σ · √2))            [додаткова функція помилок Гаусса]
```

3. Рівень підозри `φ` визначається як логарифмічна шкала:

```
φ = -log10(P_later(t))      [шкала небезпеки]
```

### Фізичний зміст шкали `φ`:

```
+-----------+-----------------------+---------------------------------------+
| Значення φ| Ймовірність помилки    | Типова інтерпретація в кластері       |
+-----------+-----------------------+---------------------------------------+
| φ = 1     | P = 10^(-1) = 0.1     | 10% шанс хибної тривоги (норма)       |
| φ = 3     | P = 10^(-3) = 0.001   | Короткочасний мережевий сплеск        |
| φ = 8     | P = 10^(-8)           | Cassandra: переведення в стан підозри |
| φ = 12    | P = 10^(-12)          | Повний failover та виключення з кільця|
+-----------+-----------------------+---------------------------------------+
```

Логарифмічна природа `φ` дозволяє системі плавно адаптуватися до джитера (коливань затримок) у мережі: якщо мережа нестабільна (`σ` велике), поріг спрацьовування автоматично розсувається в часі без потреби ручного переналаштування таймаутів.
