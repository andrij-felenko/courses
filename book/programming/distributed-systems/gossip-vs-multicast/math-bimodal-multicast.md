# 🧮 Ймовірнісна надійність: комбінація IP Multicast та Gossip у Bimodal Multicast

Намагання побудувати абсолютно надійну доставку повідомлень (Reliable Multicast) суто на мережевому рівні L3 стикається з фундаментальним математичним бар'єром: експоненційним зростанням навантаження на відправника під час збоїв. Протокол Bimodal Multicast (розроблений Кеном Бірманом) розв'язує цю суперечність, розділяючи передачу на дві фази: оптимістичну апаратну розсилку та епідемічне довиправлення втрат.

Нижче наведено строгий математичний аналіз колапсу негативних підтверджень (NAK implosion), динаміки епідемічної збіжності та доведення бімодальності фінального стану системи.

---

## 1. Математична модель NAK-колапсу в класичному Multicast

Розглянемо систему з одного джерела `S` та `N` незалежних одержувачів `R₁, R₂, ..., R_N`. Джерело транслює потік пакетів з інтенсивністю `λ` (пакетів на секунду).

Нехай імовірність втрати окремого пакета на мережевому інтерфейсі або проміжному маршрутизаторі довільного одержувача дорівнює `p` (де `0 < p < 1`). Одержувачі виявляють втрату за розривом у послідовних номерах пакетів (Sequence Numbers) і негайно надсилають джерелу запит на повторне передавання — пакет `NAK` (Negative Acknowledgment).

### Математичне сподівання кількості NAK на один втрачений пакет

Випадкова величина `X`, що позначає кількість одержувачів, які втратили даний пакет, має біноміальний розподіл `X ~ Bin(N, p)`:

```
P(X = m) = (N! / (m! · (N - m)!)) · pᵐ · (1 - p)ᴺ⁻ᵐ

E[X]
= ∑_{m=0}^{N} m · P(X = m)     [означення математичного сподівання]
= N · p                       [властивість біноміального розподілу]

Var(X)
= N · p · (1 - p)             [дисперсія біноміального розподілу]
```

Якщо втрата відбувається на магістральному комутаторі (спільній ланці дерева розсилки), пакет втрачають одразу всі `M` одержувачів у піддереві за цим комутатором.

### Інтенсивність вхідного потоку NAK на джерело

При інтенсивності мовлення `λ` середня кількість запитів `NAK`, які надходять до мережевого буфера джерела за одиницю часу `R_nak`, становить:

```
R_nak
= λ · E[X]                    [добуток інтенсивності потоку на середню кількість відмов]
= λ · N · p                   [підстановка середнього біноміального розподілу]
```

### Умова переповнення черги та відмови джерела

Нехай мережевий стек джерела здатен обробляти та відправляти повторні пакети з максимальною продуктивністю `μ` пакетів/с, а системний буфер сокета вміщує `B` запитів. Черга NAK зростає зі швидкістю `Δ = R_nak - μ`.

```
λ · N · p > μ                 [умова нестабільності черги за теорією масового обслуговування]

T_overflow
= B / (R_nak - μ)             [час до повного вичерпання буфера сокета]
= B / (λ · N · p - μ)         [підстановка виразу для R_nak]
```

**Числовий приклад розрахунку колапсу:**
Нехай кластер налічує `N = 10 000` серверів, інтенсивність трансляції `λ = 1000` пакетів/с (наприклад, біржовий біржовий потік котирувань), імовірність втрати дейтаграми `p = 0.01` (1%), розмір буфера сокета `B = 65 536` пакетів, а швидкість опрацювання переривань ядром ОС `μ = 20 000` пакетів/с:

```
R_nak
= 1000 · 10 000 · 0.01        [обчислення вхідного потоку запитів]
= 100 000 пакетів/с           [інтенсивність вдесятеро перевищує пропускну здатність μ]

T_overflow
= 65 536 / (100 000 - 20 000) [розрахунок часу колапсу]
= 65 536 / 80 000
≈ 0.819 секунди               [буфер переповнюється менш ніж за 1 секунду]
```

Після переповнення буфера ядро операційної системи починає мовчки відкидати як нові `NAK`, так і вхідні керуючі пакети. Відправник входить у метастабільний колапс (NAK Storm), повністю припиняючи трансляцію свіжих даних.

## 2. Модель Bimodal Multicast: двофазна збіжність

Bimodal Multicast усуває NAK-колапс шляхом заборони надсилання запитів на відновлення первинному відправнику. Процес розділяється на дві фази:

```
Фаза 1 (Оптимістична): Джерело надсилає пакет через звичайний IP Multicast (UDP).
                       Більшість вузлів (1 - p) отримують його миттєво.
Фаза 2 (Gossip Anti-Entropy): Вузли періодично обмінюються історією отриманих
                              номерів (дайджестами) з k випадковими сусідами.
```

### Динаміка відновлення через Pull-Gossip

Позначимо через `y[t]` частку вузлів кластера, які **не мають** пакета після раунду пліток `t`. Відповідно, частка поінформованих вузлів становить `x[t] = 1 - y[t]`.

У фазі 1 пакет розсилається через апаратний Multicast. Початкова частка непоінформованих вузлів дорівнює ймовірності втрати:
```
y[0] = p                      [початкова частка вузлів, що втратили пакет у фазі 1]
x[0] = 1 - p                  [початкова частка успішно отриманих вузлів]
```

У кожному раунді анти-ентропії кожен непоінформований вузол обирає `k` випадкових партнерів у кластері та запитує їхній дайджест (Pull-запит). Якщо хоча б один із `k` обраних партнерів уже має пакет, непоінформований вузол дізнається про нього і завантажує відсутній пакет.

Вузол **залишиться непоінформованим** у раунді `t + 1` тоді й лише тоді, коли **всі `k`** обраних ним партнерів також були непоінформованими в раунді `t`:

```
P(обраний партнер не має пакета)
= y[t]                        [частка непоінформованих у популяції]

P(усі k партнерів не мають пакета)
= (y[t])ᵏ                     [добуток імовірностей для незалежного вибору]

y[t + 1]
= y[t] · (y[t])ᵏ              [частка тих, хто не мав, помножена на ймовірність невдачі вибору]
= (y[t])^{k + 1}              [рекурентна формула згасання дефіциту інформації]
```

Розгорнемо рекурентне співвідношення для `r` раундів епідемічного обміну:

```
y[1] = (y[0])^{k + 1}         [стан після 1-го раунду]
y[2] = (y[1])^{k + 1} = (y[0])^{(k + 1)²} [стан після 2-го раунду]
...
y[r]
= (y[0])^{(k + 1)ʳ}           [загальна формула частки непоінформованих після r раундів]
= p^{(k + 1)ʳ}                [підстановка початкової ймовірності втрати p]
```

### Числовий розрахунок епідемічного затухання втрат

Нехай `N = 100 000` серверів, початкова втрата в апаратній мережі `p = 0.05` (5%), а коефіцієнт розгалуження пліток `k = 3` (кожен вузол опитує лише 3 випадкові сервери за раунд):

```
y[0] = 0.05                   [5000 серверів не отримали пакет через multicast]

y[1]
= 0.05^{(3 + 1)¹}             [обчислення після 1-го раунду gossip]
= 0.05⁴
= 0.00000625                  [частка непоінформованих становить 0.000625%]

Очікувана кількість непоінформованих вузлів E[U₁] після 1-го раунду:
E[U₁]
= N · y[1]
= 100 000 · 0.00000625
= 0.625 вузла                 [у середньому менше 1 сервера на весь 100-тисячний кластер]

y[2]
= 0.05^{(3 + 1)²}             [обчислення після 2-го раунду gossip]
= 0.05¹⁶
≈ 1.526 · 10⁻²¹

Очікувана кількість непоінформованих вузлів E[U₂] після 2-го раунду:
E[U₂]
= 100 000 · 1.526 · 10⁻²¹
≈ 1.526 · 10⁻¹⁶ вузла         [імовірність існування хоча б одного втраченого пакета практично нульова]
```

Два короткі раунди пліток із навантаженням лише 3 UDP-пакети на сервер гарантують повну збіжність даних по всьому кластеру.

## 3. Теорема про бімодальний розподіл доставки

Термін «Bimodal» походить від форми розподілу ймовірностей кінцевої кількості одержувачів, які збережуть пакет.

Нехай `Z` — випадкова величина, що позначає частку вузлів кластера, які успішно зафіксували повідомлення після завершення протоколу (`0 ≤ Z ≤ 1`).

```
Функція густини ймовірності f(z) має два дельта-подібні піки (моди):

f(z) ≈ (1 - P_fail) · δ(z - 1) + P_fail · δ(z - 0)
```

```
Густина ймовірності f(z)
      ▲
      │
 1.0 ─┤              Пік 1: Доставка майже ВСІМ (z ≈ 1)
      │              Імовірність: 1 - ε (наприклад, 0.999999)
      │                                     │
      │                                     │ █
      │                                     │ █
 0.0 ─┼───█─────────────────────────────────┴─█───► z (частка одержувачів)
      │   █                                  1.0
      │   Пік 2: Джерело впало на старті (z ≈ 0)
      │   Імовірність: ε (рідкісний крах джерела)
```

### Доведення відсутності проміжних станів (розщеплення)

У класичних ненадійних протоколах розподіл `Z` розмазаний: частина вузлів отримала 70% повідомлень, частина 40%, що створює неконсистентний стан системи. Доведемо, що в Bimodal Multicast імовірність опинитися в проміжному діапазоні `ε < Z < 1 - ε` прямує до нуля.

Нехай джерело надіслало повідомлення хоча б `C` вузлам (де `C ≥ k + 1`), перш ніж зазнало фатального краху.

Імовірність того, що епідемічний процес згасне і не охопить решту популяції, еквівалентна класичній задачі про вимирання гіллястого процесу Гальтона-Ватсона:

```
P_extinct
= ∑_{j=0}^{\infty} P(процес вироджується | j активних носіїв)

Для k ≥ 2 та початкової кількості інфікованих x[0] · N > log N:
P(Z < 1 - ε)
≤ exp(-c · k · x[0] · N)      [експоненційна оцінка Чорнова для випадкових графів]
```

Оскільки `N` велике (тисячі вузлів), експоненційний вираз стає нескінченно малим:

```
lim_{N → ∞} P(ε < Z < 1 - ε) = 0 [проміжні стани математично неможливі]
```

## 4. Розрахунок вікна зберігання в буфері (Buffer Retention Window)

Оскільки джерело не отримує індивідуальних підтверджень `ACK` від кожного з `N` вузлів, виникає питання: скільки часу `T_retain` кожен вузол повинен зберігати отримані пакети в кільцевому буфері для задоволення запитів сусідів, перш ніж їх можна безпечно видалити (Reclamation).

Нехай `r_max` — максимальна кількість раундів пліток, необхідна для збіжності з імовірністю `1 - 10⁻⁹`, а `T_round` — тривалість одного раунду анти-ентропії (наприклад, 100 мс).

```
y[r_max] ≤ 10⁻⁹               [критерій повної збіжності для кластера]
p^{(k + 1)^{r_max}} ≤ 10⁻⁹    [підстановка формули епідемічного затухання]

(k + 1)^{r_max} · ln(p) ≤ ln(10⁻⁹) [логарифмування нерівності]

(k + 1)^{r_max}
≥ ln(10⁻⁹) / ln(p)            [враховуємо, що ln(p) < 0, тому знак нерівності змінюється]

r_max
= ⌈ ln(ln(10⁻⁹) / ln(p)) / ln(k + 1) ⌉ [мінімальна кількість раундів]
```

Для `p = 0.05` та `k = 3`:

```
ln(10⁻⁹) ≈ -20.723
ln(0.05) ≈ -2.996
-20.723 / -2.996 ≈ 6.917

r_max
= ⌈ ln(6.917) / ln(4) ⌉
= ⌈ 1.934 / 1.386 ⌉
= ⌈ 1.395 ⌉
= 2 раунди                    [теоретично достатньо лише двох раундів]
```

Враховуючи можливі затримки в мережі (Network Jitter) та варіацію RTT, інженерний запас коефіцієнта безпеки `S_f` приймається рівним `3`:

```
T_retain
= S_f · r_max · T_round       [гарантований час утримання пакета в пам'яті]
= 3 · 2 · 100 мс
= 600 мс                      [пакет зберігається в пам'яті щонайменше 0.6 секунди]
```

Якщо інтенсивність потоку становить `λ = 10 000` пакетів/с із середнім розміром дейтаграми `S_pkt = 512` байтів, мінімальний розмір кільцевого буфера в пам'яті хоста дорівнює:

```
Buffer_size
= λ · T_retain · S_pkt        [обсяг оперативної пам'яті для буфера ретрансляції]
= 10 000 · 0.6 с · 512 байтів
= 3 072 000 байтів ≈ 2.93 МБ  [надзвичайно малий обсяг для сучасних серверів]
```

## 5. Модель корельованих пачкових втрат (Гілберта-Елліотта)

У реальних мережах пакети губляться не незалежно, а пачками (Bursts) через тимчасове переповнення черг комутаторів. Модель Гілберта-Елліотта описує поведінку каналу двостадійним марковським ланцюгом:
- Стан `G` (Good / Добрий): імовірність втрати дейтаграми `p_G ≈ 0`.
- Стан `B` (Bad / Поганий): імовірність втрати дейтаграми `p_B ≈ 1`.

```
        1 - α                   1 - β
       ┌──────┐                ┌──────┐
       │      ▼                │      ▼
     ┌──────────┐    α       ┌──────────┐
     │ Стан G   ├───────────►│ Стан B   │
     │ (Втрати  │            │ (Втрати  │
     │  p_G≈0)  │◄───────────┤  p_B≈1)  │
     └──────────┘    β       └──────────┘
```

Стаціонарна ймовірність перебування каналу в стані `B` (середній рівень втрат `p_avg`) та середня довжина пачки втрачених пакетів `L_burst` обчислюються як:

```
p_avg
= α / (α + β)                 [стаціонарна ймовірність стану збою B]

L_burst
= 1 / β                       [середня кількість послідовно втрачених пакетів]
```

У разі класичного Multicast пачкова втрата `L_burst` послідовних пакетів викликає одночасні NAK-запити на весь діапазон послідовностей, посилюючи шторм у `L_burst` разів.

У Bimodal Multicast вузол передає у дайджесті компактний бітовий масив або діапазон `[Seq_start, Seq_end]`. Незалежно від довжини пачки `L_burst`, розмір керуючого повідомлення дайджесту залишається фіксованим `O(1)`, що забезпечує повну стійкість до корельованих мережевих сплесків.

## 6. Інженерний висновок

Bimodal Multicast перетворює непередбачувану ненадійну мережу UDP на детерміновану бінарну поведінку:
1. Якщо джерело встигло передати пакет хоча б невеликій групі вузлів, пакет **гарантовано** отримають абсолютно всі здорові вузли кластера (`Z ≈ 1`).
2. Якщо джерело впало до початку передачі або на перших мікросекундах, повідомлення не отримає ніхто (`Z ≈ 0`).
3. Стан «половина кластера побачила конфігурацію, а половина ні» повністю виключається без використання важких синхронних двофазних комітів (2PC) або лідерних блокувань.
