# 🧮 Математичні засади алгоритму Maglev: перестановки, взаємна простота та межі стійкості

Математична основа алгоритму Maglev спирається на теорію чисел, модульну арифметику та комбінаторику перестановок. Головне математичне завдання алгоритму полягає в тому, щоб без централізованого стану відобразити довільну множину мережевих потоків на `N` серверів-обробників так, щоб навантаження розподілялося строго рівномірно, а вибуття або додавання сервера спричиняло мінімально можливе зміщення потоків.

---

### 1. Теорема про генерацію повної перестановки через взаємну простоту

Нехай `M` — фіксований розмір таблиці пошуку (*Lookup Table*), що є простим числом (англ. *prime number*). Для кожного сервера `i` (де `0 ≤ i < N`) обчислюються два цілих числа:
1. Початковий зсув: `offset[i] = hash1(name[i]) mod M`
2. Крок генератора: `skip[i] = (hash2(name[i]) mod (M - 1)) + 1`

За побудовою величина кроку строго обмежена діапазоном:

```
1 ≤ skip[i] ≤ M - 1
```

Послідовність кандидатів для сервера `i` задається лінійним конгруентним рівнянням:

```
P[i][j] = (offset[i] + j · skip[i]) mod M,    де j ∈ {0, 1, 2, ..., M - 1}
```

**Теорема.** Якщо `M` — просте число, а `1 ≤ skip[i] < M`, то послідовність `P[i][j]` для `j = 0, 1, ..., M - 1` є строгою бієкцією множини `{0, 1, ..., M - 1}` на саму себе (тобто повною перестановкою без повторень).

**Доведення від супротивного.**
Припустимо, що в послідовності існують два різних індекси `j₁` та `j₂` такі, що `0 ≤ j₁ < j₂ < M`, для яких значення комірок збігаються:

```
P[i][j₁] ≡ P[i][j₂] (mod M)
```

Розпишемо конгруенцію за означенням:

```
(offset[i] + j₁ · skip[i]) ≡ (offset[i] + j₂ · skip[i]) (mod M)
(j₁ · skip[i]) ≡ (j₂ · skip[i]) (mod M)                     [віднімання offset[i] від обох частин]
(j₂ - j₁) · skip[i] ≡ 0 (mod M)                             [перенесення доданків]
```

Це означає, що добуток `(j₂ - j₁) · skip[i]` ділиться націло на `M` (тобто `M | (j₂ - j₁) · skip[i]`).

За лемою Евкліда (грец. *Εὐκλείδης*): якщо просте число `M` ділить добуток двох цілих чисел `a · b`, то воно зобов'язане ділити хоча б одне з них:

```
M | (j₂ - j₁)    або    M | skip[i]
```

Розглянемо обидва випадки:
1. Оскільки `1 ≤ skip[i] ≤ M - 1`, число `skip[i]` не може ділитися націло на `M`, бо воно строго менше за `M` і строго більше за нуль: `M ∤ skip[i]`.
2. Оскільки `0 ≤ j₁ < j₂ ≤ M - 1`, різниця лежить у межах `1 ≤ j₂ - j₁ ≤ M - 1`. Отже, різниця `(j₂ - j₁)` також строго менша за `M` і не може ділитися на `M`: `M ∤ (j₂ - j₁)`.

Отримали суперечність: добуток ділиться на `M`, але жоден зі співмножників не ділиться на `M`. Отже, припущення про існування повторюваних елементів хибне. Усі `M` значень `P[i][j]` для `j ∈ {0, ..., M - 1}` є попарно різними. Оскільки потужність множини дорівнює `M`, ця послідовність містить кожне число з діапазону `[0, M - 1]` рівно один раз.

### 2. Рівномірність розподілу комірок у таблиці пошуку

Нехай `N` — кількість активних серверів, а `M` — розмір таблиці. При побудові таблиці за алгоритмом циклічного раундового вибору (англ. *Round-Robin*) сервери по черзі займають перший вільний слот зі своєї послідовності перестановок.

Позначимо через `S[i]` кількість слотів у таблиці, призначених серверу `i`.

**Лема про максимальне відхилення частки.** У незваженому режимі різниця між кількістю слотів, отриманих будь-якими двома серверами, не перевищує одиниці:

```
|S[a] - S[b]| ≤ 1    для будь-яких a, b ∈ {0, 1, ..., N - 1}
```

**Доведення.**
Процес заповнення таблиці складається з послідовних раундів. У кожному раунді кожен сервер робить рівно одну успішну спробу зайняти вільну комірку:
- Нехай `R = ⌊M / N⌋` — кількість повних раундів, які пройшли всі сервери.
- За `R` повних раундів кожен сервер гарантовано отримав рівно `R` комірок.
- Кількість комірок, що залишилися незаповненими після `R` повних раундів:

```
K = M - R · N = M mod N,    де 0 ≤ K < N
```

- Останній, неповний раунд завершується після того, як перші `K` серверів займуть по одній додатковій комірці.
- Таким чином:
  - Перші `K` серверів отримують `S[i] = R + 1 = ⌈M / N⌉` комірок.
  - Решта `(N - K)` серверів отримують `S[i] = R = ⌊M / N⌋` комірок.

Різниця між максимальною та мінімальною кількістю комірок:

```
⌈M / N⌉ - ⌊M / N⌋ ≤ 1
```

Відносна частка навантаження сервера `i` становить:

```
L[i] = S[i] / M
```

Підставивши значення `S[i]`:

```
⌊M / N⌋ / M ≤ L[i] ≤ ⌈M / N⌉ / M
(M/N - 1) / M ≤ L[i] ≤ (M/N + 1) / M
1/N - 1/M ≤ L[i] ≤ 1/N + 1/M
```

Абсолютна похибка відхилення від ідеального балансу `1/N`:

```
|L[i] - 1/N| ≤ 1/M
```

При стандартному розмірі таблиці `M = 65537` похибка становить:

```
1 / 65537 ≈ 0.00001525 (0.0015%)
```

Це доводить, що Maglev забезпечує практично ідеальний рівномірний розподіл навантаження між усіма доступними вузлами.

### 3. Межа стійкості до збурень при зміні складу пулу

Головна вимога до консистентного хешування — мінімізація частки ключів, які змінюють свого власника при зміні кількості робочих вузлів.

Нехай у системі працювало `N` серверів. Розглянемо два випадки: вихід вузла з ладу та додавання нового вузла.

#### Випадок А. Відмова одного сервера (`N → N - 1`)

Нехай сервер `k` вибуває з пулу. Усі його комірки `S[k]` стають вакантними й підлягають перерозподілу між рештою `(N - 1)` серверів.

Частка комірок, що належали вибулому серверу:

```
D = S[k] / M ≈ 1/N
```

Комірки, які раніше належали іншим `(N - 1)` серверам, залишаються закріпленими за ними або заповнюються на більш ранніх кроках їхніх перестановок. Завдяки детермінізму перестановок жоден непорушений сервер не витісняється зі слотів, які він уже займав раніше:

```
Частка збережених з'єднань = 1 - 1/N = (N - 1) / N
Частка перерозподілених з'єднань = 1/N
```

Це теоретично досяжний мінімум для будь-якої системи консистентного розподілу без централізованого координатора.

#### Випадок Б. Додавання нового сервера (`N → N + 1`)

Коли додається новий `(N + 1)`-й сервер, він бере участь у загальному раундовому змаганні за слоти. На кожному раунді він забирає собі одну комірку, витісняючи сервер, який займав її з найменшим пріоритетом у попередній конфігурації.

Кількість комірок, яку отримує новий сервер:

```
S[новий] ≈ M / (N + 1)
```

Ці комірки рівномірно відбираються у всіх `N` попередніх серверів. Частка зміщених з'єднань становить:

```
Частка збурення = S[новий] / M ≈ 1 / (N + 1)
```

Частка сесій, які залишаються на своїх попередніх серверах:

```
1 - 1 / (N + 1) = N / (N + 1)
```

### 4. Чому розмір таблиці `M` зобов'язаний бути простим числом

Якщо розмір таблиці `M` є складеним числом (наприклад, степенем двійки `M = 2¹⁶ = 65536`), алгоритм зазнає фатального збою через розпад на циклічні підгрупи.

Нехай `M` — парне число, а `skip[i]` виявилося парним числом. Тоді їхній найбільший спільний дільник:

```
d = НСД(skip[i], M) ≥ 2
```

Довжина циклічної підгрупи, яку генерує крок `skip[i]` у кільці лишків `ℤ / Mℤ`, становить:

```
L = M / d ≤ M / 2
```

Послідовність `P[i][j] = (offset[i] + j · skip[i]) mod M` зможе відвідати максимум `M / d` комірок. Решта `M - (M/d)` комірок таблиці ніколи не будуть досягнуті сервером `i`, скільки б ітерацій `j` він не виконав.

Якщо всі інші сервери вже зайняли ці `M / d` комірок, алгоритм заповнення потрапляє в **нескінченний цикл**: сервер `i` постійно генерує кандидати, які вже зайняті, але математично не здатний згенерувати індекси вільних комірок.

```
M = 65537 (просте число Ферма, 2¹⁶ + 1):
  Для будь-якого skip ∈ [1, 65536]:
  НСД(skip, 65537) = 1    [бо 65537 не має дільників, крім 1 і себе]
  Довжина циклу = 65537  [гарантоване повне покриття таблиці]
```

Вибір числа `M = 65537` забезпечує три ключові інженерні властивості:
1. **Математична коректність:** гарантія завершення алгоритму заповнення за скінченну кількість кроків `O(M)`.
2. **Низька колізійність:** велике значення `M` мінімізує похибку дискретизації ваг до `0.0015%`.
3. **Кеш-локальність процесора:** таблиця з 65537 елементів типу `uint32_t` займає `262 148` байтів (≈ 256 КБ), що ідеально вміщується в апаратний кеш L2 сучасних процесорів (1–2 МБ на ядро).
