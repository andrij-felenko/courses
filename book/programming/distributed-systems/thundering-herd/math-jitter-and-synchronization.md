# 🧮 Математика фазової синхронізації та аналіз алгоритмів джитеру

Математичний аналіз явища гримучої отари дає строге пояснення того, чому незалежні розподілені процеси мимовільно синхронізують свої періоди повторів, і чому введення випадкового шуму (джитеру) є єдиним математично доведеним засобом розсіювання когерентних хвиль навантаження.

## Модель фазового колапсу та резонанс повторів

Розглянемо систему з `N` незалежних клієнтів, які звертаються до централізованого сервісу з максимальною пропускною здатністю `C` (кількість запитів на секунду). Час обробки одного запиту дорівнює `s`, отже максимальна одночасна місткість системи становить:

```
K = C · s      [максимальна кількість паралельних запитів у черзі]
```

Припустимо, що в початковий момент `t = 0` сервіс зазнає короткочасного збою тривалістю `τ`, через що всі `N` клієнтів одночасно фіксують помилку (код HTTP 503 або обрив TCP-з'єднання). 

Кожен клієнт запускає локальний детермінований алгоритм експоненційного затримання без додавання випадкового шуму. Час очікування перед `k`-ю спробою визначається функцією:

```
t[k] = min(M, b · 2ᵏ)      [де b — базовий інтервал, M — максимальна стеля]
```

Оскільки годинники клієнтських пристроїв синхронізовані через протокол NTP з точністю до кількох мілісекунд, розкид моментів запуску таймерів між усіма клієнтами обмежений вузьким часовим вікном `Δt` (величина джитеру мережевої затримки RTT, зазвичай `Δt ≤ 50 мс = 0.05 с`).

### Інтенсивність пікового навантаження

У мить настання `t = t[1]` усі `N` клієнтів одночасно надсилають повторний запит. Миттєва інтенсивність вхідного потоку запитів `λ_peak` у межах вікна `Δt` становить:

```
λ_peak = N / Δt
```

Якщо `N = 1 000 000` клієнтів, а розкид `Δt = 0.05 с`, пікова швидкість надходження запитів дорівнює:

```
λ_peak
= 1 000 000 / 0.05
= 20 000 000 запитів/с      [перевищення норми у 400 разів при C = 50 000 RPS]
```

Кількість запитів `N_overload`, які гарантовано будуть відкинуті вхідною чергою або призведуть до таймауту за час `Δt`, дорівнює:

```
N_overload
= N - (C · Δt)
= 1 000 000 - (50 000 · 0.05)
= 1 000 000 - 2 500
= 997 500 запитів      [99.75% усіх клієнтів знову отримують відмову]
```

Оскільки 99.75% клієнтів одночасно зазнають повторної невдачі в межах того самого інтервалу `Δt`, вони одночасно переходять до наступної спроби `k = 2`. Відбувається фазове замикання: клієнти формують незгасаючу когерентну хвилю (поїзд імпульсів), яка повторюється в моменти `t[2] = b · 2²`, `t[3] = b · 2³` тощо.

## Динаміка фазової синхронізації та параметр порядку Курамото

Явище спонтанної синхронізації в розподілених повторних циклах є дискретним аналогом моделі зв'язаних фазових осциляторів Курамото. У цій моделі кожен клієнт розглядається як осцилятор із власною фазою `θ[i](t) ∈ [0, 2π]`.

Коли клієнт очікує завершення таймера, його фаза еволюціонує за законом:

```
dθ[i] / dt = ω[i]      [де ω[i] = 2π / t_sleep[i] — власна кутова частота]
```

У момент досягнення фази `θ[i] = 2π` клієнт надсилає запит до сервера. Якщо сервер відповідає успішно, клієнт залишає цикл повторів. Проте якщо сервер перевантажений і повертає помилку або таймаут, фаза клієнта примусово скидається в нуль:

```
θ[i](t+) = 0      [скидання фази при отриманні помилки від перевантаженого сервера]
```

Це скидання діє як сильне глобальне поле зв'язку (англ. *mean-field coupling*): перевантажений сервер миттєво зводить фази всіх невдалих запитів до єдиної точки. Ступінь колективної синхронізації системи кількісно вимірюється за допомогою комплексного параметра порядку Курамото `r(t)`:

```
r(t) · e^(i·ψ(t)) = (1 / N) · ∑ e^(i·θ[j](t))
```

Тут модуль `r(t) ∈ [0, 1]` визначає рівень когерентності системи:
- `r(t) ≈ 0` — стан повної десинхронізації (фази розподілені рівномірно по колу, запити надходять як стаціонарний пуассонівський потік, навантаження на сервер рівне й передбачуване);
- `r(t) → 1` — стан повної фазової когерентності (усі клієнти мають однакову фазу, утворюючи монолітну хвилю гримучої отари).

Без застосування джитеру кожна хвиля відмов примусово збільшує значення `r(t)` до одиниці, перетворюючи систему на резонансний контур із нульовою корисною пропускною здатністю.

## Колапс закону Літтла під час імпульсного навантаження

У стаціонарному режимі функціонування розподілених черг середня кількість запитів у системі `L` визначається класичним законом Літтла:

```
L = λ · W      [де λ — інтенсивність потоку, W — середній час перебування в системі]
```

Під час накочування гримучої отари припущення про стаціонарність потоку грубо порушується. У системі виникає імпульс із тривалістю `Δt ≪ W`. Замість стаціонарного розподілу черга сокетів та пулів потоків описується нестаціонарним накопиченням:

```
L(t) = L(0) + ∫ (λ_in(u) - μ_out(u)) du
```

Оскільки максимальна швидкість обробки сервером обмежена фізичною межею `μ_out(u) ≤ C`, а вхідний потік становить `λ_in = N / Δt ≫ C`, довжина черги `L(t)` зростає практично миттєво:

```
L(Δt) ≈ N - C · Δt
```

Середній час очікування в такій переповненій черзі для запиту, що стоїть на позиції `x`, дорівнює `W(x) = x / C`. Для останнього запиту в черзі час очікування становить:

```
W_max
= N / C
= 1 000 000 / 50 000
= 20.0 секунд      [при типовому клієнтському таймауті D = 3.0 с]
```

Оскільки час очікування `W_max = 20 с` перевищує клієнтський таймаут `D = 3 с`, усі клієнти, які чекають у хвості черги, розривають TCP-з'єднання до того, як сервер добереться до обробки їхніх пакетів. Сервер витрачає обчислювальні ресурси на вибірку застарілих запитів з черги, результат яких уже нікому не потрібен, що доводить корисну пропускну здатність (англ. *goodput*) до абсолютного нуля.

## Статистичний аналіз стратегій додавання джитеру

Для руйнування фазової узгодженості та розсіювання імпульсу `N` у широкий часовий інтервал застосовують псевдовипадкові величини. Дослідимо три класичні математичні моделі джитеру.

Нехай `U(a, b)` — неперервний рівномірний розподіл на інтервалі `[a, b]`, а `T_max[k] = min(M, b · 2ᵏ)` — детермінована експоненційна верхня межа для `k`-го кроку.

### 1. Повний джитер (Full Jitter)

Інтервал очікування обирається випадково з усього доступного діапазону від 0 до `T_max[k]`:

```
t_full[k] = U(0, T_max[k])
```

Математичне сподівання часу затримки `E[t_full]` та дисперсія `Var(t_full)` обчислюються за властивостями рівномірного розподілу:

```
E[t_full[k]]
= (0 + T_max[k]) / 2
= T_max[k] / 2      [середній час очікування скорочується вдвічі]

Var(t_full[k])
= (T_max[k] - 0)² / 12
= (T_max[k])² / 12  [максимальна дисперсія серед стаціонарних схем]
```

Оскільки ширина вікна розсіювання становить `W = T_max[k]`, середня пікова щільність навантаження `λ_full` спадає обернено пропорційно до зростання `k`:

```
λ_full[k] = N / T_max[k]
```

При `T_max = 20 с` і `N = 1 000 000`:

```
λ_full
= 1 000 000 / 20
= 50 000 запитів/с      [повне входження у ліміт пропускної здатності C]
```

### 2. Рівний джитер (Equal Jitter)

Для гарантування того, що клієнт не виконає спробу занадто рано (збереження гарантованого мінімального часу затримки), половина інтервалу фіксується, а випадковий шум додається до другої половини:

```
half[k] = T_max[k] / 2
t_equal[k] = half[k] + U(0, half[k])
```

Обчислення числових характеристик:

```
E[t_equal[k]]
= half[k] + (half[k] / 2)
= 3/4 · T_max[k]      [вище середнє очікування, ніж у Full Jitter]

Var(t_equal[k])
= (half[k])² / 12
= (T_max[k] / 2)² / 12
= (T_max[k])² / 48    [дисперсія у 4 рази менша за Full Jitter]
```

Менша дисперсія призводить до того, що навантаження розсіюється у вікно `W = T_max[k] / 2`, подвоюючи пікову амплітуду порівняно з Full Jitter: `λ_equal = 2 · N / T_max[k]`.

### 3. Декорельований джитер (Decorrelated Jitter)

У перших двох алгоритмах поточне значення затримки жорстко залежить від номера кроку `k`, прив'язаного до початкового моменту аварії `t = 0`. Декорельований джитер розриває цей зв'язок, обчислюючи кожну наступну затримку як випадкову функцію від **попереднього фактичного значення** `t[k-1]`:

```
t_decorr[0] = base
t_decorr[k] = min(M, U(base, 3 · t_decorr[k-1]))
```

Умовне математичне сподівання для кроку `k` за умови попереднього значення `t[k-1]` (поки не досягнуто стелі `M`):

```
E[t_decorr[k] | t_decorr[k-1]]
= (base + 3 · t_decorr[k-1]) / 2
= 0.5 · base + 1.5 · t_decorr[k-1]
```

Оскільки коефіцієнт при `t_decorr[k-1]` дорівнює `1.5 > 1`, ряд математичних сподівань демонструє стійке геометричне зростання, еквівалентне експоненційному відступанню зі знаменником `1.5`:

```
E[t_decorr[k]] ≈ base · (1.5)ᵏ      [за умови base << M]
```

Головна математична перевага декорельованого джитеру полягає в динамічній десинхронізації: навіть якщо група клієнтів мала однаковий номер спроби `k`, через мультиплікативний розкид `[base, 3 · t[k-1]]` їхні наступні інтервали затримки стають некорельованими між собою, повністю унеможливлюючи утворення вторинних гармонік у довготривалих збоях.

## Зведена таблиця порівняння математичних моделей

| Параметр | Без джитеру (No Jitter) | Повний (Full Jitter) | Рівний (Equal Jitter) | Декорельований (Decorrelated) |
| :--- | :--- | :--- | :--- | :--- |
| **Формула `t[k]`** | `T_max[k]` | `U(0, T_max[k])` | `T_max/2 + U(0, T_max/2)` | `min(M, U(b, 3·t[k-1]))` |
| **Сподівання `E[t]`** | `T_max[k]` | `0.5 · T_max[k]` | `0.75 · T_max[k]` | `≈ b · (1.5)ᵏ` |
| **Дисперсія `Var(t)`** | `≈ 0` (лише RTT) | `(T_max)² / 12` | `(T_max)² / 48` | Зростає експоненційно |
| **Ширина вікна `W`** | `Δt ≈ 50 мс` | `T_max[k]` | `0.5 · T_max[k]` | Неперервно розмита |
| **Піковий сплеск** | `N / Δt` (Катастрофа) | `N / T_max` (Мінімальний) | `2N / T_max` (Помірний) | `N / W_eff` (Мінімальний) |
| **Стійкість до резонансу**| Нульова | Висока | Середня | Абсолютна |

Математичний висновок однозначний: для повного придушення гримучої отари та запобігання резонансним перевантаженням у розподілених системах оптимальним вибором є **Decorrelated Jitter** (для клієнтських протоколів перепідключення) та **Full Jitter** (для повторів ідемпотентних RPC-викликів).
