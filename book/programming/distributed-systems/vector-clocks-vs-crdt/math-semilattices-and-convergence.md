# 🧮 Математика збіжності: напівґратки, монотонність та сильна кінцева узгодженість

Математичний фундамент безконфліктних типів даних (CRDT) ґрунтується на абстрактній алгебрі та теорії порядку: він доводить, що система реплік гарантовано сходиться до єдиного стану без централізованого координатора тоді й лише тоді, коли простір станів утворює обмежену об'єднавчу напівґратку, а мутації є монотонними.

---

### 1. Частковий порядок та об'єднавча напівґратка

Нехай `S` — множина можливих станів репліки.

Відношення часткового порядку `⊑` на множині `S` є бінарним відношенням, яке задовольняє три фундаментальні аксіоми для довільних елементів `x, y, z ∈ S`:

1. **Рефлексивність:** кожен елемент порівнянний із самим собою:
```
x ⊑ x
```
2. **Антисиметричність:** два елементи не можуть одночасно передувати один одному без тотожної рівності:
```
(x ⊑ y  ∧  y ⊑ x)  ⇒  x = y
```
3. **Транзитивність:** відношення порядку зберігається через проміжні ланки:
```
(x ⊑ y  ∧  y ⊑ z)  ⇒  x ⊑ z
```

Пара `(S, ⊑)` називається частково впорядкованою множиною (Partially Ordered Set, poset).

#### Точна верхня межа (Least Upper Bound, LUB)

Для будь-якої пари елементів `x, y ∈ S` елемент `m ∈ S` називається **точною верхньою межею** (позначається як `m = x ⊔ y` або join), якщо виконуються дві необхідні та достатні умови:

1. `m` є верхньою межею для обох елементів:
```
x ⊑ m  та  y ⊑ m
```
2. `m` є найменшою серед усіх можливих верхніх меж:
```
∀ z ∈ S: (x ⊑ z  ∧  y ⊑ z)  ⇒  m ⊑ z
```

#### Алгебраїчне означення напівґратки

Множина `S` з бінарною операцією `⊔: S × S → S` утворює **об'єднавчу напівґратку** (Join-Semilattice) `(S, ⊔)`, якщо для всіх `x, y, z ∈ S` виконуються алгебраїчні закони:

```
(x ⊔ y) ⊔ z = x ⊔ (y ⊔ z)      [Асоціативність]
x ⊔ y = y ⊔ x                  [Комутативність]
x ⊔ x = x                      [Ідемпотентність]
```

Зв'язок між алгебраїчною операцією `⊔` та порядком `⊑` є взаємно однозначним і задається канонічним еквівалентом:

```
x ⊑ y  ⇔  x ⊔ y = y
```

Якщо напівґратка має найменший елемент `⊥ ∈ S` такий, що `∀ x ∈ S: ⊥ ⊑ x` (тобто `⊥ ⊔ x = x`), вона називається **обмеженою знизу напівґраткою** (Bounded Join-Semilattice). Елемент `⊥` представляє початковий (порожній) стан репліки до отримання будь-яких мутацій.

### 2. Формальна модель State-based CRDT (CvRDT)

Реплікований об'єкт на базі стану задається алгебраїчним кортежем із шести компонентів:

```
CvRDT = (S, ⊥, ⊑, ⊔, u, q)
```

де:
* `(S, ⊔, ⊥)` — обмежена знизу об'єднавча напівґратка можливих станів;
* `u: S × Op → S` — функція локальної мутації (Update), що переводить стан `s` під дією операції `op` у новий стан `s' = u(s, op)`;
* `merge: S × S → S` — функція злиття віддаленого стану, що тотожно дорівнює точній верхній межі: `merge(s_1, s_2) = s_1 ⊔ s_2`;
* `q: S → V` — функція читання (Query), що обчислює результуюче значення прикладного типу `V` зі стану `s`.

#### Інваріант монотонного зростання

Для забезпечення гарантованої збіжності будь-яка локальна мутація `u` мусить бути строго монотонною відносно часткового порядку `⊑`:

```
∀ s ∈ S, ∀ op ∈ Op:  s ⊑ u(s, op)
```

З визначення точної верхньої межі автоматично випливає монотонність операції злиття для обох реплік, що беруть участь в обміні:

```
s_local ⊑ (s_local ⊔ s_remote)
s_remote ⊑ (s_local ⊔ s_remote)
```

Це означає, що стан кожного вузла в часі незворотно рухається виключно вгору вздовж часткового порядку напівґратки.

### 3. Доведення теореми сильної кінцевої узгодженості (SEC)

**Означення SEC (Strong Eventual Consistency):**
Розподілена система гарантує сильну кінцеву узгодженість, якщо для будь-яких двох реплік `i` та `j`, які застосували однаковий мультинабір оновлень `U = {op_1, op_2, ..., op_n}`, їхні стани є строго рівними: `s_i = s_j`.

#### Доведення:

Нехай на вузлі `A` виконано скінченну послідовність оновлень, що перевела його через проміжні стани:
```
s_A = ⊥ ⊔ Δ_A1 ⊔ Δ_A2 ⊔ ... ⊔ Δ_Ak
```
де `Δ_Am` — інкрементальні дельти або стани, згенеровані локальними мутаціями на вузлі `A`.

Аналогічно на вузлі `B` отримано стани `Δ_B1, Δ_B2, ..., Δ_Bm`.

Після завершення взаємного обміну репліками через ненадійну мережу стан вузла `A` є результатом послідовних злиттів у порядку прибуття повідомлень `π_A`:

```
s_final(A) = ⊥ ⊔ X_1 ⊔ X_2 ⊔ ... ⊔ X_N      [де X_k ∈ {Δ_A, Δ_B}, порядок π_A]
```

Стан вузла `B` є результатом злиття тих самих елементів у довільному іншому порядку `π_B`:

```
s_final(B) = ⊥ ⊔ Y_1 ⊔ Y_2 ⊔ ... ⊔ Y_N      [де Y_k ∈ {Δ_A, Δ_B}, порядок π_B]
```

Оскільки мультинабори отриманих операндів збігаються `{X_1, ..., X_N} = {Y_1, ..., Y_N} = U`, застосуємо алгебраїчні аксіоми оператора `⊔`:

```
s_final(A)
= ⊥ ⊔ X_1 ⊔ X_2 ⊔ ... ⊔ X_N
= ⊥ ⊔ (⨆_{x ∈ U} x)                          [Асоціативність: довільне розставлення дужок]
= ⊥ ⊔ (⨆_{y ∈ U} y)                          [Комутативність: інваріантність до перестановки операндів]
= ⊥ ⊔ Y_1 ⊔ Y_2 ⊔ ... ⊔ Y_N                  [Ідемпотентність: усунення повторних дублікатів x ⊔ x = x]
= s_final(B)
```

Оскільки кінцевий вираз залежить виключно від множини `U`, а не від послідовності застосування операндів, стан обох вузлів тотожно рівний: `s_final(A) = s_final(B)`. Теорему доведено.

### 4. Алгебра Дельта-мутацій (Delta-State CRDTs)

У класичній моделі CvRDT передача повного стану `s ∈ S` створює надмірне навантаження на мережу. Delta-CRDT оптимізує передачу за рахунок виділення мінімального диференціального стану `d ∈ S`.

Нехай функція мутації генерує дельту: `u^Δ: S × Op → S`, таку що новий стан обчислюється локальним злиттям:
```
s_{t+1} = s_t ⊔ u^Δ(s_t, op)
```

Вузол надсилає мережею лише згенеровану дельту `d = u^Δ(s_t, op)`. Віддалений вузол зі станом `s_remote` застосовує отриману дельту через стандартний оператор напівґратки:
```
s'_remote = s_remote ⊔ d
```

#### Доведення коректності дельта-злиття:

Нехай вузол `A` згенерував дві послідовні дельти `d_1` та `d_2`. Покажемо, що пряме злиття дельт між собою перед передачею на віддалений вузол є строго еквівалентним їхньому послідовному застосуванню:

```
(s_remote ⊔ d_1) ⊔ d_2
= s_remote ⊔ (d_1 ⊔ d_2)                     [Асоціативність оператора ⊔]
= s_remote ⊔ d_merged                        [де d_merged = d_1 ⊔ d_2]
```

Це дозволяє мережевим буферам об'єднувати декілька проміжних дельт в один компактний пакет `d_merged` без ризику спотворення підсумкового стану репліки.

### 5. Алгебраїчний аналіз фундаментальних структур CRDT

#### 1. Лічильник PN-Counter (Positive-Negative Counter)

Нехай у системі бере участь `K` вузлів з ідентифікаторами `1..K`. Стан лічильника складається з двох векторів додавання `P ∈ ℕ^K` та віднімання `N ∈ ℕ^K`:

```
S = ℕ^K × ℕ^K,    ⊥ = ([0, ..., 0], [0, ..., 0])
```

Частковий порядок задається покомпонентним порівнянням обох векторів:
```
(P_1, N_1) ⊑ (P_2, N_2)  ⇔  (∀ i ∈ 1..K: P_1[i] ≤ P_2[i]  ∧  N_1[i] ≤ N_2[i])
```

Оператор злиття `⊔`:
```
(P_1, N_1) ⊔ (P_2, N_2) = (P_merged, N_merged)
де:
P_merged[i] = max(P_1[i], P_2[i])
N_merged[i] = max(N_1[i], N_2[i])
```

Функція обчислення видимого значення:
```
value(P, N) = ∑_{i=1}^K P[i] - ∑_{i=1}^K N[i]
```

Оскільки функція `max(a, b)` на множині цілих чисел є асоціативною, комутативною та ідемпотентною, прямий добуток напівґраток `(ℕ^K, max) × (ℕ^K, max)` строго гарантує детерміновану збіжність лічильника.

#### 2. Множина Observed-Remove Set (OR-Set)

Простір станів OR-Set моделюється за допомогою додавання унікальних причинних тегів (Dots) до кожного факту додавання елемента:

```
Tag = NodeID × Counter
S = 𝒫(E × Tag) × 𝒫(Tag)
```
де `E` — множина значень елементів, `𝒫(X)` — булеан (множина всіх підмножин `X`).

Стан представляється парою `(A, R)`:
* `A ⊆ E × Tag` — множина доданих елементів з унікальними тегами;
* `R ⊆ Tag` — множина видалених тегів (Tombstones).

Частковий порядок — відношення включення підмножин:
```
(A_1, R_1) ⊑ (A_2, R_2)  ⇔  (A_1 ⊆ A_2  ∧  R_1 ⊆ R_2)
```

Операція злиття — теоретико-множинне об'єднання:
```
(A_1, R_1) ⊔ (A_2, R_2) = (A_1 ∪ A_2,  R_1 ∪ R_2)
```

Поточний видимий вміст множини:
```
read(A, R) = { e ∈ E | ∃ t ∈ Tag: (e, t) ∈ A  ∧  t ∉ R }
```

**Доведення розв'язання конфлікту конкурентного додавання і видалення:**

Нехай елемент `e` існував із тегом `t_1`, тобто `(e, t_1) ∈ A`.
Вузол 1 виконує `remove(e)`: він спостерігає лише тег `t_1` і додає його до `R`: `R_1 = {t_1}`.
Конкурентно Вузол 2 виконує `add(e)`: він генерує новий унікальний тег `t_2` (оскільки лічильник або UUID є свіжим): `A_2 = A ∪ {(e, t_2)}`.

Обчислюємо злиття станів:
```
A_merged = A_1 ∪ A_2 = A ∪ {(e, t_1), (e, t_2)}
R_merged = R_1 ∪ R_2 = {t_1}
```

Обчислюємо результуючу множину:
```
read(A_merged, R_merged)
= { e | ∃ t: (e, t) ∈ A_merged ∧ t ∉ R_merged }
= { e }                                      [оскільки для t_2: (e, t_2) ∈ A_merged і t_2 ∉ {t_1}]
```

Новий факт додавання `(e, t_2)` вижив, тому що операція видалення на Вузлі 1 не могла спостерегти ще не створений тег `t_2`. Це строго підтверджує семантику Add-Wins без жодної потреби в глобальному синхронному блокуванні.

### 6. Теорема про неможливість монотонного обмеження балансу

Покажемо строге математичне обмеження CRDT: неможливість підтримки інваріанту `Value ≥ 0` без зовнішньої координації.

Нехай стан описується PN-Counter `s = (P, N)` з початковим значенням `P = [100, 0], N = [0, 0]`, що відповідає балансу `100`.

Нехай Вузол 1 виконує локальну операцію списання `80`:
```
s_1 = ([100, 0], [80, 0]),    value(s_1) = 20 ≥ 0  [дозволено локально]
```
Одночасно Вузол 2 виконує локальну операцію списання `70`:
```
s_2 = ([100, 0], [0, 70]),    value(s_2) = 30 ≥ 0  [дозволено локально]
```

Обидва вузли перебувають у коректному стані відносно локального інваріанту. Обчислимо точну верхню межу злиття:
```
s_merged = s_1 ⊔ s_2 = ([100, 0], [80, 70])
value(s_merged) = 100 - (80 + 70) = -50 < 0
```

Підмножина станів `S_{valid} = { (P, N) | ∑ P[i] - ∑ N[i] ≥ 0 }` не є замкненою відносно оператора `⊔`. Отже, побудова обмеженого від'ємними значеннями лічильника на базі чистої напівґратки неможлива без застосування двофазного консенсусу або протоколів резервування (Escrow-токенів).
