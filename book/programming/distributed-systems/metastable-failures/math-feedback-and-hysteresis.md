# 🧮 Математична модель підсилення навантаження, біфуркацій та гістерезису

Математичний апарат теорії динамічних систем і нелінійного аналізу дозволяє формалізувати поведінку розподіленої системи під час перевантаження, точно обчислити точки фазового переходу та визначити межі зон стійкості.

## 1. Параметри базової моделі обслуговування

Розглянемо розподілену обчислювальну систему (сервіс, пул серверів або базу даних) як систему масового обслуговування з нелінійним зворотним зв'язком.

Введемо базові змінні системи:
* `L` — інтенсивність зовнішнього вхідного потоку запитів (Offered Load), вимірюється у запитах на секунду (RPS);
* `C` — гранична пропускна спроможність системи (System Capacity), вимірюється в одиницях обчислювальної роботи на секунду;
* `W_0` — номінальний обсяг обчислювальної роботи, необхідний для обробки одного успішного запиту в ізоляції;
* `q(t)` — поточний стан завантаженості системи в момент часу `t` (наприклад, довжина черги завдань `N_queue` або середній час очікування в черзі `T_wait`);
* `T_timeout` — жорсткий клієнтський таймаут очікування відповіді;
* `A(q)` — безрозмірний коефіцієнт підсилення роботи (Work Amplification Factor), що показує, у скільки разів збільшується сукупна внутрішня робота системи на один вхідний запит за рівня завантаженості `q`.

Сукупна інтенсивність внутрішньої роботи, що генерується в системі під впливом вхідного потоку `L`, визначається функцією:

```
W_internal(L, q) = L · W_0 · A(q)
```

У стані спокою та низького навантаження (`q ≈ 0`) жодних додаткових повторів чи вимивання кешу немає, тому `A(0) = 1`. За цих умов внутрішня робота дорівнює номінальній: `W_internal = L · W_0`.

## 2. Функція підсилення навантаження при клієнтських повторах

Розглянемо механізм підсилення роботи, спричинений повторними спробами клієнтів (Retries) за спливанням таймауту.

Нехай кожен клієнт у разі неотримання відповіді протягом `T_timeout` надсилає повторний запит з фіксованою ймовірністю або робить до `R_max` повторних спроб.

Час перебування запиту в системі `T_resp(q)` складається з часу очікування в черзі `W_q(q)` та чистого часу виконання `T_exec`:

```
T_resp(q) = W_q(q) + T_exec
```

Ймовірність того, що клієнт розірве з'єднання за таймаутом і здійснить повторну спробу, моделюється гладкою сигмоїдною функцією активації (або функцією Фермі-Дірака):

```
P_retry(q) = 1 / (1 + exp(-k · (T_resp(q) - T_timeout)))
```

де:
* `k > 0` — коефіцієнт крутизни переходу, що відображає дисперсію клієнтських таймаутів;
* якщо `T_resp(q) << T_timeout`, то `exp(...) >> 1` і `P_retry ≈ 0`;
* якщо `T_resp(q) >> T_timeout`, то `exp(...) → 0` і `P_retry ≈ 1`.

Якщо клієнт генерує `r` повторних спроб на кожен прострочений запит, сукупний коефіцієнт підсилення навантаження стає функцією стану `q`:

```
A(q) = 1 + r · P_retry(q)
```

За максимальної деградації (`P_retry = 1`) коефіцієнт підсилення сягає граничного значення:

```
A_max = 1 + r
```

Якщо клієнти роблять у середньому 2 повторні спроби, то `r = 2`, а `A_max = 3`. Це означає, що при колапсі черги внутрішнє навантаження на сервери зростає втричі за незмінного зовнішнього трафіку `L`.

## 3. Динамічне рівняння стану системи

Зміна стану черги `q(t)` у часі описується диференціальним рівнянням балансу між надходженням роботи та її виконанням:

```
dq/dt = W_internal(L, q) - C
dq/dt = L · W_0 · A(q) - C
```

Для спрощення без обмеження загальності нормуємо одиниці роботи так, щоб `W_0 = 1`. Тоді рівняння динаміки набуває канонічного вигляду:

```
dq/dt = L · A(q) - C
```

Стаціонарні стани рівноваги системи `q*` визначаються умовою незмінності черги у часі:

```
dq/dt = 0   [умова стаціонарності]
L · A(q*) - C = 0
L · A(q*) = C
```

Рівновага можлива лише в тих точках `q*`, де згенерована внутрішня робота `L · A(q*)` точно дорівнює пропускній спроможності системи `C`.

## 4. Аналіз стійкості точок рівноваги (Лінеаризація за Ляпуновим)

Щоб з'ясувати, чи є точка рівноваги `q*` стійкою до збурень, виконаємо лінеаризацію динамічного рівняння в околі `q*`.

Нехай `δq(t) = q(t) - q*` — мале відхилення від точки рівноваги. Розкладаючи функцію в ряд Тейлора до першого порядку малості, отримуємо:

```
d(δq)/dt = d/dq [L · A(q) - C]_(q=q*) · δq
d(δq)/dt = L · A'(q*) · δq
```

Критерій стійкості за Ляпуновим:
* **Стійкий вузол (асистентне притягання):** якщо `L · A'(q*) < 0` (похідна від'ємна), будь-яке збурення `δq` згасає експоненційно з часом (`δq(t) = δq(0) · exp(λ·t)` де `λ < 0`).
* **Нестійка сідлова точка (бар'єр відштовхування):** якщо `L · A'(q*) > 0`, будь-яке мікроскопічне збурення лавиноподібно наростає.

Оскільки в реальних системах функція черги та затримок є суворо зростаючою (`W_q'(q) > 0` і `A'(q) ≥ 0`), стійкість системи на практиці визначається обмеженням зверху: на насиченій ділянці `A(q)` виходить на плато `A_max`, де `A'(q) → 0`, а фізична черга обмежується місткістю буфера пам'яті `q_max`.

## 5. Виведення біфуркації сідло-вузол та критичних точок

Розглянемо графічний розв'язок рівняння рівноваги `L · A(q) = C`.

Залежно від величини зовнішнього потоку `L` можливі три топологічні режими:

```
                           Графік рівноваги L · A(q) проти C

  Робота ^
         │                                    A_max · L (верхня гілка)
         │                                ┌─────────────────────────
         │                               /
    C    ├──────────────────────────────/─────────────────────────── [Лінія ємності C]
         │                             /
         │                            /
         │     ──────────────────────┘  1 · L (нижня гілка)
         │
         └──────────────────────────────────────────────────────────> q
```

### Режим 1: Низьке навантаження (`L < C / A_max`)

Якщо зовнішній потік настільки малий, що навіть за максимального коефіцієнта підсилення `A_max` внутрішня робота не перевищує ємності:

```
L · A_max < C
L < C / A_max
```

Рівняння має рівно **один стабільний розв'язок** `q_low* ≈ 0`. Навіть якщо систему штучно вивести на максимальне завантаження, вона самостійно очистить черги і повернеться в робочий стан.

Це визначає **поріг безумовного відновлення (Recovery Threshold)**:

```
L_rec = C / A_max
```

### Режим 2: Проміжне навантаження (Зона бістабільності та гістерезису: `L_rec < L < L_crit`)

Коли зовнішній потік перебуває в діапазоні:

```
C / A_max < L < C
```

Крива `L · A(q)` перетинає горизонтальну пряму `C` у трьох точках:

```
1. q_1* (Нижній стан): q_1* ≈ 0       -> Стійкий робочий стан (Healthy)
2. q_2* (Середній стан): q_2* = q_crit -> Нестійкий розділовий бар'єр (Unstable threshold)
3. q_3* (Верхній стан): q_3* = q_max   -> Стійкий стан відмови (Metastable Failure)
```

Система є **бістабільною**. Її фінальний стан цілком залежить від передісторії (початкового значення `q(0)`):
* Якщо `q(0) < q_2*`, траєкторія прямує до нормального стану `q_1*` (Goodput = 100%).
* Якщо під впливом тимчасового тригера `q(0)` перевищує поріг `q_2*`, система неминуче скочується в точку колапсу `q_3*` (Goodput ≈ 0%).

### Режим 3: Критичне навантаження та зрив (`L ≥ L_crit = C`)

Коли зовнішній потік досягає номінальної місткості `C`:

```
L_crit = C
```

Нижня точка рівноваги `q_1*` зливається з нестійкою точкою `q_2*` і зникає через **біфуркацію сідло-вузол (Saddle-Node Bifurcation)**. 

У системі залишається єдиний глобальний атрактор — стан повної відмови `q_3*`. Відбувається катастрофічний зрив на верхню гілку метастабільності.

## 6. Покроковий розрахунок петлі гістерезису

Розглянемо числовий приклад реальної мікросервісної системи:

**Вхідні параметри:**
* Пропускна здатність кластера: `C = 10 000` RPS;
* Штатне вхідне навантаження: `L_nominal = 7 000` RPS;
* Максимальна кількість повторів: `r = 3` спроби на збійний запит;
* Граничний коефіцієнт підсилення: `A_max = 1 + 3 = 4.0`.

**Розрахунок точок переходу:**

Крок 1: Розрахунок критичного навантаження зриву:
```
L_crit = C
= 10000 RPS                      [номінальна місткість кластера]
```

Крок 2: Розрахунок порогу відновлення системи з колапсу:
```
L_rec = C / A_max
= 10000 / 4.0                    [ділення на коефіцієнт підсилення]
= 2500 RPS
```

Крок 3: Порівняння штатного навантаження з порогом відновлення:
```
L_nominal = 7000 RPS
L_rec = 2500 RPS
7000 > 2500                      [L_nominal перевищує L_rec у 2.8 раза]
```

**Математичний висновок:**

Після того, як зовнішній сплеск перевів кластер через точку `L_crit = 10 000` RPS у метастабільний стан, повернення вхідного трафіку до штатного рівня `L_nominal = 7 000` RPS **не здатне відновити систему**. 

Оскільки `7 000 > 2 500`, внутрішнє навантаження за умов колапсу становить:

```
W_internal = L_nominal · A_max
= 7000 · 4.0                     [множення на коефіцієнт 4]
= 28000 RPS                      [у 2.8 раза більше за фізичну ємність 10000]
```

Кластер залишатиметься намертво заблокованим на 100% завантаженні CPU та 0% корисного Goodput. Єдиний математично коректний спосіб повернути систему на робочу гілку — тимчасово зрізати вхідний потік нижче порогу `L_rec = 2 500` RPS (на 75% від номіналу) до повного спорожнення черг, після чого плавно нарощувати трафік.
