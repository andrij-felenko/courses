# 🧮 Математика max-min справедливості, віртуального часу та DRF

Розподіл обмеженого ресурсу між конкурентними потоками вимагає строгого математичного апарату. Просте ділення загальної місткості на кількість клієнтів (`C / N`) виявляється неефективним, оскільки реальні користувачі мають нерівномірні запити: невикористаний залишок ресурсу «малих» клієнтів блокується, тоді як «великі» клієнти відчувають штучний дефіцит.

Математична теорія справедливого розподілу розв'язує цю суперечність за допомогою трьох концепцій: критерію макс-мін рівності, механіки віртуального часу та домінантної частки багатовимірних ресурсів.

## 1. Макс-мін справедливість (Max-Min Fairness)

Нехай у системі є неподільний ресурс із загальною скалярною місткістю `C > 0` (наприклад, сумарна пропускна здатність 100 Мбіт/с або ліміт обробки 10 000 RPS).

За ресурс змагаються `n` незалежних джерел. Кожне джерело `i` (`1 ≤ i ≤ n`) характеризується вектором вимог `d = (d₁, d₂, ..., dₙ)`, де `dᵢ ≥ 0` — бажана швидкість споживання ресурсу.

Необхідно знайти вектор фактичного виділення ресурсу `x = (x₁, x₂, ..., xₙ)`, який задовольняє такі аксіоми:

1. **Реалістичність виділення:** жодне джерело не отримує більше, ніж вимагає:
```
0 ≤ xᵢ ≤ dᵢ   для всіх i ∈ {1, 2, ..., n}
```

2. **Обмеження місткості:** сума виділених часток не перевищує доступну ємність системи:
```
∑ xᵢ ≤ C   (де сума береться за всіма i від 1 до n)
```

3. **Критерій Парето-ефективності (збереження роботи):** якщо `∑ dᵢ > C`, то весь ресурс вичерпується повністю:
```
∑ xᵢ = C
```

**Формальне означення Max-Min:** вектор виділення `x` називається макс-мін справедливим, якщо для збільшення частки будь-якого учасника `i` неминуче доведеться зменшити частку іншого учасника `j`, виділення якого вже менше або дорівнює виділенню `i`:

```
x є max-min справедливим ⇔ 
∀ i, ∀ x' (допустимого): x'ᵢ > xᵢ ⇒ ∃ j: xⱼ ≤ xᵢ ∧ x'ⱼ < xⱼ
```

### Алгоритм прогресивного насичення (Water-filling)

У безперервному просторі вектор `x` обчислюється процедурою водного наповнення:

1. Усі джерела одночасно отримують приріст ресурсу з однаковою швидкістю.
2. Якщо виділена частка досягає бажаного рівня джерела (`xᵢ = dᵢ`), це джерело вважається задоволеним, його частка фіксується, і воно більше не претендує на додатковий ресурс.
3. Залишок місткості продовжує рівномірно ділитися між активними незадоволеними джерелами.
4. Процес зупиняється, коли весь ресурс `C` вичерпано або всі вимоги задоволено.

Математично це виражається через єдиний скалярний поріг відсікання `f` (fair share), який задовольняє рівняння:

```
∑ min(dᵢ, f) = C
```

Тоді виділення кожному клієнту становить:

```
xᵢ = min(dᵢ, f)
```

**Покроковий приклад розрахунку:**

Нехай місткість `C = 100`, а вектор вимог чотирьох клієнтів становить `d = (10, 20, 50, 80)`. Сумарна вимога `∑ dᵢ = 160 > 100`.

*Крок 1:* Припускаємо, що всі 4 джерела обмежені спільним порогом `f`:
```
min(10, f) + min(20, f) + min(50, f) + min(80, f) = 100
```
Якщо `f ≥ 10`, перший клієнт насичується на рівні `x₁ = 10`. Залишок ресурсу `C₁ = 100 - 10 = 90` ділиться між трьома джерелами.

*Крок 2:* Середній залишок на 3 джерела: `90 / 3 = 30`. Але другий клієнт просить лише `d₂ = 20 < 30`. Отже, другий клієнт повністю насичується: `x₂ = 20`.

*Крок 3:* Залишок ресурсу `C₂ = 90 - 20 = 70` ділиться порівну між двома останніми ненасиченими клієнтами (3 і 4):
```
f = 70 / 2 = 35
```
Оскільки `d₃ = 50 > 35` та `d₄ = 80 > 35`, обидва клієнти зупиняються на порозі `f = 35`:
```
x₃ = 35
x₄ = 35
```

Підсумковий вектор виділення: `x = (10, 20, 35, 35)`. Перевірка балансу: `10 + 20 + 35 + 35 = 100`. Малі клієнти отримали 100% бажаного, а важкі порівну розділили весь залишок.

## 2. Зважена макс-мін справедливість (Weighted Max-Min)

Коли клієнти мають різні вагові коефіцієнти `w = (w₁, w₂, ..., wₙ)` (наприклад, відповідно до оплачених тарифів), рівномірне наповнення замінюється пропорційним приростом:

```
xᵢ = min(dᵢ, wᵢ · f)
```

де скалярний множник `f` шукається з балансового рівняння:

```
∑ min(dᵢ, wᵢ · f) = C
```

Якщо два ненасичені клієнти мають ваги `w₁ = 1` та `w₂ = 3`, то при будь-якому дефіциті другий клієнт гарантовано отримує ресурс утричі швидше за першого.

## 3. Generalized Processor Sharing (GPS) та віртуальний час у WFQ

В ідеальній моделі GPS потік даних розглядається як неперервна рідина. Нехай `B(t) ⊆ {1, ..., n}` — множина черг, які мають дані для передачі в момент часу `t` (активні черги).

Швидкість обслуговування черги `i ∈ B(t)` в момент `t` визначається формулою:

```
rᵢ(t) = C · (wᵢ / ∑_{j ∈ B(t)} wⱼ)
```

Оскільки реальні мережеві та RPC-пакети неподільні, планувальник Weighted Fair Queuing (WFQ) емулює GPS за допомогою концепції **віртуального часу `V(t)`**.

Віртуальний час відображає прогрес передачі одного умовного біта в еталонній системі GPS. Його динаміка опиняється диференціальним рівнянням:

```
d V(t) / dt = 1 / ∑_{j ∈ B(t)} wⱼ
```

Коли активних черг багато, знаменник великий, і віртуальний час рухається повільно; коли активна лише одна черга з вагою 1, `d V(t) / dt = 1`, і віртуальний час збігається з фізичним.

Для кожного пакета `k` черги `i`, який має довжину `Lᵢᵏ` (у байтах або одиницях складності) і надійшов у фізичний момент `aᵢᵏ`, обчислюються дві мітки:

```
Sᵢᵏ = max(V(aᵢᵏ), Fᵢ^{k-1})       [віртуальний час початку передачі]
Fᵢᵏ = Sᵢᵏ + Lᵢᵏ / wᵢ             [віртуальний час завершення передачі]
```

де:
* `Sᵢᵏ` (Virtual Start Time) — момент, коли пакет почав би обслуговуватися в моделі GPS (або одразу після прибуття, або після завершення попереднього пакета своєї черги).
* `Fᵢᵏ` (Virtual Finish Time) — момент завершення передачі пакета в GPS.

**Правило вибору WFQ:** у будь-який момент звільнення каналу планувальник вибирає пакет із мінімальним значенням `Fᵢᵏ` серед усіх доступних черг.

Теорема Пареха — Галлагера гарантує, що затримка завершення будь-якого пакета в дискретному WFQ відхиляється від ідеального часу в неперервному GPS не більше ніж на час передачі одного максимального пакета:

```
T_WFQ(p) - T_GPS(p) ≤ L_max / C
```

## 4. Математична коректність Deficit Round Robin (DRR)

Алгоритм DRR усуває необхідність підтримки сортування за віртуальним часом зі складністю `O(log N)`, замінюючи його покроковим балансом дефіциту `DeficitCounterᵢ` (`DCᵢ`) та квантом `Quantumᵢ = wᵢ · Q_base`.

### Теорема про обмеженість дефіциту

Для будь-якої черги `i` значення `DCᵢ` у будь-який момент часу обмежене зверху:

```
0 ≤ DCᵢ < L_max + Quantumᵢ
```

*Доведення:* 
1. Черга передає пакети доти, доки розмір пакета `L ≤ DCᵢ`. 
2. Як тільки `L > DCᵢ`, обслуговування черги негайно припиняється, а залишок `DCᵢ` переноситься на наступний раунд. 
3. Оскільки найбільший можливий пакет, який не зміг відправитися, має розмір `L < L_max`, залишок дефіциту в кінці раунду строго менший за `L_max`. 
4. На початку нового раунду до дефіциту додається рівно `Quantumᵢ`. Отже, максимальне значення `DCᵢ` перед початком вибірки становить менше ніж `L_max + Quantumᵢ`.

### Доведення складності O(1) на пакет

Нехай черга `i` має `k` пакетів із розмірами `L₁, L₂, ..., Lₖ`.

Якщо планувальник відвідує чергу і не може відправити жодного пакета (бо `L₁ > DCᵢ`), він виконує рівно `O(1)` операцій (одне додавання та одне порівняння) і переходить далі.

Якщо черга відправляє `m` пакетів за один раунд, вона витрачає `m` операцій вибірки, однак сумарний переданий обсяг даних становить не менше ніж `Quantumᵢ - L_max`. Амортизована кількість перевірок на один відправлений пакет становить:

```
T_amortized = O(1 + L_max / Quantumᵢ) = O(1)   [за умови Quantumᵢ ≥ L_max]
```

## 5. Багатовимірна справедливість: Dominant Resource Fairness (DRF)

У хмарних системах запит споживає вектор ресурсів `R = ⟨CPU, RAM, IOPS, Net⟩`.

Нехай загальна місткість кластера описується вектором `C = ⟨C₁, C₂, ..., Cₘ⟩`, де `m` — кількість типів ресурсів.

Користувач `i` подає однотипні завдання, кожне з яких вимагає вектор ресурсів `rᵢ = ⟨r_{i,1}, r_{i,2}, ..., r_{i,m}⟩`.

Якщо користувачу `i` виділено `kᵢ` завдань, його сумарне споживання ресурсу `j` дорівнює `U_{i,j} = kᵢ · r_{i,j}`.

**Домінантна частка (Dominant Share):** для користувача `i` домінантним називається ресурс, частка якого від загальної місткості кластера є максимальною серед усіх ресурсів:

```
sᵢ = max_{1 ≤ j ≤ m} ( (kᵢ · r_{i,j}) / Cⱼ )
```

**Оптимізаційна задача DRF:** розподілити кількості завдань `k = (k₁, k₂, ..., kₙ)` так, щоб максимізувати мінімальну домінантну частку за принципом Max-Min:

```
max min_{1 ≤ i ≤ n} (sᵢ)
при обмеженнях:
∑_{i=1}^n kᵢ · r_{i,j} ≤ Cⱼ   для всіх ресурсів j ∈ {1, ..., m}
```

### Числовий приклад розрахунку DRF

Нехай кластер має загальну місткість:
```
C = ⟨ 18 CPU, 36 GB RAM ⟩
```

Два клієнти запускають завдання з такими профілями споживання:
* **Клієнт A:** вимагає `r_A = ⟨ 2 CPU, 1 GB RAM ⟩` на одне завдання.
* **Клієнт B:** вимагає `r_B = ⟨ 1 CPU, 4 GB RAM ⟩` на одне завдання.

*Крок 1: Визначення домінантного ресурсу для кожного клієнта:*
* Для клієнта A:
  - Частка CPU = `2 / 18 = 1/9`
  - Частка RAM = `1 / 36`
  - Домінантний ресурс A: **CPU** (бо `1/9 > 1/36`). Домінантна частка одного завдання: `s_A(1) = 2/18 = 1/9`.

* Для клієнта B:
  - Частка CPU = `1 / 18`
  - Частка RAM = `4 / 36 = 1/9`
  - Домінантний ресурс B: **RAM** (бо `4/36 > 1/18`). Домінантна частка одного завдання: `s_B(1) = 4/36 = 1/9`.

*Крок 2: Зрівнювання сумарних домінантних часток:*
Нехай клієнт A отримує `x` завдань, а клієнт B отримує `y` завдань. Принцип DRF вимагає рівності домінантних часток:
```
s_A(x) = s_B(y)
x · (2 / 18) = y · (4 / 36)
2x / 18 = 4y / 36
x / 9 = y / 9
x = y
```

*Крок 3: Розв'язання системи обмежень місткості кластера:*
```
2x + 1y ≤ 18   [обмеження за CPU]
1x + 4y ≤ 36   [обмеження за RAM]
```

Оскільки `x = y`:
```
2x + x = 3x ≤ 18  ⇒  x ≤ 6
1x + 4x = 5x ≤ 36  ⇒  x ≤ 7.2
```
Критичним обмеженням є процесор: `x = 6`, `y = 6`.

*Підсумок розподілу:*
* Клієнт A отримує 6 завдань: `6 · ⟨2 CPU, 1 GB⟩ = ⟨12 CPU, 6 GB RAM⟩`.
* Клієнт B отримує 6 завдань: `6 · ⟨1 CPU, 4 GB⟩ = ⟨6 CPU, 24 GB RAM⟩`.
* Сумарне споживання кластера: `⟨12 + 6, 6 + 24⟩ = ⟨18 CPU, 30 GB RAM⟩`.

CPU утилізовано на 100% (`18 / 18`), RAM утилізовано на 83.3% (`30 / 36`). Обидва клієнти мають абсолютно рівну домінантну частку `s_A = s_B = 12 / 18 = 24 / 36 = 2/3 (66.7%)`. Жоден клієнт не може звинуватити іншого в несправедливій монополізації кластера.
