# 🧮 Математичне моделювання збіжності Push, Pull та Push-Pull

Цей математичний аналіз виводить суворі динамічні рівняння поширення інформації в епідемічних протоколах, доводить фундаментальну асиметрію швидкості збіжності стратегій Push і Pull та обґрунтовує мінімальну межу кількості повідомлень `O(N · log log N)` для гібридного протоколу Push-Pull.

Тут представлено ймовірнісну модель системи на базі ланцюгів Маркова, розрахунок математичного сподівання швидкості зараження для кожної фази, аналіз точки перемикання між режимами та виведення фінальних оцінок затримок збіжності.

---

## 1. Формальна модель системи та початкові умови

Розглядається синхронна розподілена система з `N` однорідних вузлів, об'єднаних у топологію повного зв'язку (*Complete Graph*). Процес поширення дискретизовано на дискретні раунди `t = 0, 1, 2, ...`.
У кожному раунді кожен активний вузол обирає `k` випадкових партнерів із рівномірним розподілом з усієї множини `N - 1` інших серверів. Параметр `k` позначає коефіцієнт розгалуження (*fanout*).

Позначимо випадкові величини стану системи в раунді `t`:
- `I_t` — кількість інфікованих вузлів (тих, що отримали нове оновлення).
- `S_t = N - I_t` — кількість сприйнятливих або неінфікованих вузлів.
- `p_t = I_t / N` — частка інфікованих вузлів у кластері (`0 ≤ p_t ≤ 1`).
- `s_t = S_t / N = 1 - p_t` — частка неінфікованих вузлів.

У початковий момент часу `t = 0` оновлення з'являється на одному вузлі:
```
p₀ = 1 / N
s₀ = 1 - 1 / N
```

## 2. Динаміка чистого Push-протоколу

У чистому Push-протоколі передачу оновлення ініціюють виключно ті вузли, які вже перебувають в інфікованому стані. Кожен із `I_t = N · p_t` інфікованих серверів обирає `k` випадкових вузлів і надсилає їм повідомлення з повними даними.

### Ймовірнісний вивід переходу станів

Розглянемо довільний неінфікований вузол `u`.
Ймовірність того, що конкретний інфікований вузол `v` НЕ обере вузол `u` в одному з `k` своїх незалежних виборів:

```
P(v не обрав u)
= 1 - k / (N - 1)                      [вибір без повернення серед N-1 сусідів]
≈ 1 - k / N                            [наближення для великих N >> k]
```

Оскільки всі `N · p_t` інфікованих вузлів роблять свій вибір незалежно, сумарна кількість спроб вибору по всьому кластеру становить `k · N · p_t`.
Ймовірність того, що вузол `u` не буде обраний жодним з інфікованих вузлів і залишиться неінфікованим у наступному раунді `t + 1`:

```
s_{t+1}
= s_t · (1 - 1 / N)^{k · N · p_t}       [добуток імовірностей незалежних виборів]
≈ s_t · e^{-k · p_t}                    [граничний перехід (1 - 1/N)^N → e⁻¹ при N → ∞]
```

Частка інфікованих вузлів у наступному раунді виражається як:

```
p_{t+1}
= 1 - s_{t+1}                           [означення частки інфікованих]
= 1 - (1 - p_t) · e^{-k · p_t}          [підстановка s_t = 1 - p_t]
```

### Рання фаза Push: експоненційний вибух

На початку епідемії частка інфікованих вузлів є дуже малою величиною (`p_t << 1`).
Розкладемо експоненту в ряд Тейлора: `e^{-x} = 1 - x + x²/2 - ... ≈ 1 - x`:

```
p_{t+1}
≈ 1 - (1 - p_t) · (1 - k · p_t)         [лінеаризація експоненти e^{-k·p_t} ≈ 1 - k·p_t]
= 1 - (1 - k · p_t - p_t + k · p_t²)    [розкриття дужок]
= (k + 1) · p_t - k · p_t²              [спрощення виразу]
≈ (k + 1) · p_t                         [нехтування членом другого порядку k·p_t² << p_t]
```

Кількість інфікованих вузлів на початковому етапі зростає за експоненційним законом:

```
p_t ≈ p₀ · (k + 1)^t = (1 / N) · (k + 1)^t
```

Кількість раундів, необхідна для зараження половини кластера (`p_t = 0.5`):

```
t_{half}
= ln(N / 2) / ln(k + 1)                 [логарифмування рівняння (k+1)^t = N/2]
= O(log N)                              [асимптотична оцінка тривалості]
```

### Пізня фаза Push: проблема колекціонера купонів

Коли майже весь кластер інфікований (`p_t ≈ 1`, `s_t << 1`), динаміка різко деградує:

```
s_{t+1}
≈ s_t · e^{-k · 1}                      [підстановка p_t ≈ 1 у рекурентне співвідношення]
= s_t · e^{-k}                          [лінійне геометричне згасання залишку]
```

Цей процес повністю еквівалентний класичній задачі теорії ймовірностей про колекціонера купонів (*Coupon Collector's Problem*). Коли колекціонер уже зібрав 95% унікальних купонів, придбання кожного нового купона з високою ймовірністю дублює вже наявні.

Щоб зменшити кількість неінфікованих вузлів від початкового залишку `S_t = N · s_t = N · ε` до нуля (`S_t < 1`), залишок неінфікованих повинен стати строго меншим за `1 / N`:

```
s_t · (e^{-k})^m < 1 / N                [умова повного зникнення неінфікованих]
m · k > ln(N · s_t)                     [логарифмування нерівності]
m > ln(N · s_t) / k                     [оцінка кількості фінішних раундів]
```

Сумарна кількість повідомлень, що генеруються в кластері протягом усіх раундів чистого Push-протоколу:

```
M_{push}
= ∑_{t=0}^{T} k · N · p_t               [кожен інфікований вузол надсилає k пакетів]
= O(k · N · log N)                      [інфіковані вузли марно бомбардують один одного]
```

## 3. Динаміка чистого Pull-протоколу

У чистому Pull-протоколі неінфіковані вузли періодично опитують `k` випадкових сусідів, запитуючи їхній поточний стан.

### Ймовірнісний вивід переходу станів

Вузол `u` залишається неінфікованим у раунді `t + 1` тоді й тільки тоді, коли одночасно виконуються дві умови:
1. Вузол `u` був неінфікованим у раунді `t` (ймовірність `s_t`).
2. Усі `k` обраних ним випадкових сусідів також виявилися неінфікованими.

Оскільки частка неінфікованих вузлів у кластері становить `s_t`, імовірність того, що випадково обраний партнер не має оновлення, дорівнює `s_t`.
Для `k` незалежно обраних партнерів отримуємо:

```
s_{t+1}
= s_t · (s_t)^k                         [усі k опитаних партнерів також неінфіковані]
= s_t^{k+1}                             [зведення степенів: супер-експоненційне згасання]
```

### Рання фаза Pull: параліч холодного запалювання

У початковому раунді `t = 0`, коли інфіковано лише один вузол (`s₀ = 1 - 1 / N`):

```
s₁
= (1 - 1 / N)^{k + 1}                   [підстановка s₀ у формулу Pull]
≈ 1 - (k + 1) / N                       [розклад за біномом Ньютона]
```

Ймовірність для конкретного неінфікованого вузла натрапити на єдиний інфікований вузол становить лише `k / N`.
Очікувана кількість раундів, необхідна лише для того, щоб хоча б один вузол успішно підтягнув оновлення, масштабується як `O(N / k)`. Без попереднього підштовхування чистий Pull демонструє неприпустимо велику затримку старту, оскільки кластер марно витрачає тисячі порожніх запитів `GetState()`.

### Пізня фаза Pull: квадратична лавина

Коли частка інфікованих вузлів перевищує половину (`p_t > 0.5`, отже `s_t < 0.5`), швидкість збіжності стає надзвичайно високою.
Розглянемо випадок `k = 1`:

```
s_{t+1} = s_t²                          [квадратичне згасання неінфікованого залишку]
```

Простежимо еволюцію залишку неінфікованих вузлів, починаючи з `s_t = 0.1` (10% неінфікованих у кластері на 10 000 серверів):

```
Крок 0: s_t     = 10⁻¹ = 0.1            [1000 неінфікованих із 10 000]
Крок 1: s_{t+1} = (10⁻¹)² = 10⁻² = 0.01  [100 неінфікованих]
Крок 2: s_{t+2} = (10⁻²)² = 10⁻⁴ = 0.0001 [1 неінфікований]
Крок 3: s_{t+3} = (10⁻⁴)² = 10⁻⁸         [0 неінфікованих — 100% узгодженість!]
```

Залишок неінфікованих вузлів спадає як подвійна експонента:

```
s_t = (s₀)^{(k + 1)^t}                  [загальний розв'язок рекурентного рівняння]
```

Кількість раундів у фінальній фазі для досягнення `s_t < 1 / N`:

```
(k + 1)^t > ln N                        [логарифмування подвійної експоненти]
t_{late} = ln(ln N) / ln(k + 1) = O(log log N) [надшвидкий фініш]
```

## 4. Динаміка гібридного Push-Pull та теорема Карпа

У комбінованому протоколі Push-Pull у кожному раунді інформація передається в обох напрямках.
Вузол `u` залишається неінфікованим у раунді `t + 1` тоді й тільки тоді, коли:
1. Він сам не обрав жодного інфікованого вузла під час Pull-запиту (ймовірність `s_t^k`).
2. Жоден інфікований вузол не обрав його під час Push-передачі (ймовірність `(1 - 1/N)^{k N p_t} ≈ e^{-k p_t}`).

### Загальне рекурентне рівняння Push-Pull

```
s_{t+1}
= s_t · (s_t)^k · e^{-k · p_t}          [поєднання невдачі Pull та уникнення Push]
= s_t^{k + 1} · e^{-k · (1 - s_t)}      [підстановка p_t = 1 - s_t]
```

### Точка перемикання між домінуванням Push та Pull

Швидкість приросту частки інфікованих вузлів `Δp = p_{t+1} - p_t` для обох механізмів:
- Для Push: `Δp_{push} ≈ (1 - p_t) · (1 - e^{-k·p_t})`.
- Для Pull: `Δp_{pull} = (1 - p_t) · (1 - (1 - p_t)^k)`.

При малих значеннях `p_t` величина `Δp_{push} >> Δp_{pull}`.
При переході через точку рівноваги `p* ≈ 1 - 1 / (k + 1)` (для `k = 1` це точка `p* = 0.5`) механізм Pull стає ефективнішим за Push у темпах зараження залишку.

### Покроковий аналіз трьох фаз поширення (Теорема Карпа, 2000)

Повний процес поширення Push-Pull розбивається на три чіткі фази:

```
+-------------------------------------------------------------------------------+
| Фаза 1: Експоненційний розгін через Push (від p₀ = 1/N до p_t = 1 / log N)    |
|   • Кількість раундів: t₁ = log_{k+1} N - O(log log N)                        |
|   • Основний рушій: Push-повідомлення від інфікованих                         |
+-------------------------------------------------------------------------------+
                                       │
                                       ▼
+-------------------------------------------------------------------------------+
| Фаза 2: Проміжне перемикання (від p_t = 1 / log N до s_t = 1 / log N)         |
|   • Кількість раундів: t₂ = O(1)                                              |
|   • Основний рушій: Симетричний внесок обох механізмів                        |
+-------------------------------------------------------------------------------+
                                       │
                                       ▼
+-------------------------------------------------------------------------------+
| Фаза 3: Квадратичне схлопування через Pull (від s_t = 1 / log N до s_t = 0)   |
|   • Кількість раундів: t₃ = (ln ln N) / ln(k + 1) + O(1)                      |
|   • Основний рушій: Pull-запити від залишку неінфікованих                     |
+-------------------------------------------------------------------------------+
```

Сумарна тривалість повної збіжності:

```
T_{total}
= t₁ + t₂ + t₃                          [сума тривалості трьох послідовних фаз]
= log_{k+1} N + (ln ln N) / ln(k + 1) + O(1) [підстановка оцінок тривалості кожної фази]
```

Для `k = 1` при розрахунку Карпа коефіцієнт бази логарифма становить `log₃ N`:

```
T_{push-pull} = log₃ N + O(log log N)   [теоретична межа Карпа]
```

### Порівняльна таблиця складності

```
+------------------+--------------------------+------------------------------+
| Стратегія        | Кількість раундів (Час)  | Сумарна кількість повідомлень |
+------------------+--------------------------+------------------------------+
| Чистий Push      | O(log N)                 | O(N · log N)                 |
| Чистий Pull      | O(N) або O(log N)*       | O(N · log N)                 |
| Гібрид Push-Pull | log₃ N + O(log log N)   | O(N · log log N)             |
+------------------+--------------------------+------------------------------+
* За умови попереднього штучного запалювання.
```

Гібридний протокол Push-Pull досягає теоретично мінімального обсягу мережевого трафіку `O(N · log log N)` завдяки тому, що Push припиняє бути активним драйвером у той самий момент, коли Pull входить у фазу квадратичної збіжності.
