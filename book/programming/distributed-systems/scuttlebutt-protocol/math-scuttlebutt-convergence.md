# 🧮 Математика узгодження Scuttlebutt: складність дайджесту, трафік та час збіжності

Протокол Scuttlebutt розв'язує задачу синхронізації розподіленого стану, мінімізуючи два критичні параметри: обсяг службового мережевого трафіку під час кожного раунду обміну та кількість раундів, необхідних для досягнення повної збіжності кластера.

Нижче наведено формальний математичний аналіз складності представлення стану, ймовірнісної динаміки поширення оновлень та строгого доведення інваріанта безпеки при фрагментації пакетів.

---

## 1. Складність дайджесту стану: Scuttlebutt проти класичних схем

Нехай у розподіленій системі функціонує `N` вузлів. Кожен вузол є джерелом `K` іменованих атрибутів (ключів). Розмір ідентифікатора вузла позначається як `S_node` байтів, ідентифікатора ключа — як `S_key` байтів, а значення лічильника версії — як `S_ver` байтів.

### Класичний векторний дайджест (Key-Level Version Vectors)

У традиційній схемі кожен атрибут кожного вузла має свій власний незалежний номер версії. Дайджест стану, який вузол надсилає у фазі `SYN`, містить повний перелік трійок `(Вузол, Ключ, Версія)`:

```
Size_classic = N · K · (S_node + S_key + S_ver)
```

### Дайджест Scuttlebutt (Monotonic Per-Node Version)

У Scuttlebutt всі ключі вузла отримують мітку з єдиного монотонного лічильника версій цього вузла. Тому для повного опису знань про вузол достатньо передати єдине максимальне число версії `max_ver`. Дайджест складається лише з пар `(Вузол, Версія)`:

```
Size_scuttlebutt = N · (S_node + S_ver)
```

### Порівняльний розрахунок для кластера з 1000 вузлів

Припустимо типові параметри промислового середовища:
- Кількість серверів `N = 1000`;
- Кількість атрибутів на кожному сервері `K = 50`;
- `S_node = 16` байтів (UUID або IPv6 + порт);
- `S_key = 4` байти (ідентифікатор enum або хеш);
- `S_ver = 8` байтів (64-бітне ціле число).

**Обчислення розміру класичного дайджесту:**
```
Size_classic
= 1000 · 50 · (16 + 4 + 8)        [підстановка параметрів N, K, S_node, S_key, S_ver]
= 50000 · 28                      [додавання розмірів полів у дужках]
= 1400000 байтів                  [множення: 1.4 МБ]
= 1367.2 КБ                       [переведення в кілобайти: 1400000 / 1024]
```

**Обчислення розміру дайджесту Scuttlebutt:**
```
Size_scuttlebutt
= 1000 · (16 + 8)                 [підстановка параметрів N, S_node, S_ver]
= 1000 · 24                       [додавання розмірів полів у дужках]
= 24000 байтів                    [множення: 24 КБ]
= 23.44 КБ                        [переведення в кілобайти: 24000 / 1024]
```

**Коефіцієнт стиснення дайджесту:**
```
Ratio
= Size_classic / Size_scuttlebutt [формула відношення обсягів]
= 1400000 / 24000                 [підстановка обчислених байтів]
= 58.33                           [результат: зменшення навантаження у ~58 разів]
```

При зростанні кількості метрик `K` до 200 на вузол класичний дайджест досягає `5.6 МБ`, тоді як дайджест Scuttlebutt залишається незмінним — `24 КБ`, оскільки його асимптотична складність становить строго `O(N)` і повністю позбавлена залежності від `K`.

## 2. Динаміка збіжності трифазного Push-Pull обміну

Scuttlebutt поєднує передачу нових даних за ініціативою партнера (Push) та підтягування відсутніх оновлень (Pull) в єдиному трифазному раунді `SYN-ACK-ACK2`.

Нехай у кластері з `N` вузлів у момент часу `t = 0` на одному вузлі з'являється мутація стану.
- `I_t` — кількість інфікованих вузлів (тих, хто вже отримав оновлення) у раунді `t`;
- `S_t = N - I_t` — кількість сприйнятливих вузлів (тих, хто ще не знає оновлення);
- `p_t = I_t / N` — частка інфікованих вузлів;
- `s_t = S_t / N = 1 - p_t` — частка неінфікованих вузлів.

У кожному раунді кожен вузол обирає випадкового партнера з рівномірним розподілом `1 / N`.

### Рання фаза (Експоненційне зростання)

Коли `p_t` близьке до 0 (`s_t ≈ 1`), домінує механізм Push: кожен інфікований вузол контактує з випадковим вузлом, який із високою ймовірністю є неінфікованим. Крім того, неінфіковані вузли самі ініціюють контакти з інфікованими (Pull).

Кількість неінфікованих вузлів у наступному раунді визначається ймовірністю того, що неінфікований вузол `u`:
1. Не обрав інфікований вузол сам (ймовірність `1 - p_t`);
2. Не був обраний жодним із `I_t` інфікованих вузлів (ймовірність `(1 - 1/N)^{I_t} ≈ e^{-p_t}`).

```
s_{t+1}
= s_t · (1 - p_t) · (1 - 1/N)^{I_t}     [ймовірність уникнути вибору з обох сторін]
= s_t · (1 - p_t) · e^{-p_t}            [граничний перехід при великих N: (1 - 1/N)^{I_t} ≈ e^{-p_t}]
≈ s_t · (1 - p_t) · (1 - p_t)           [розклад у ряд Тейлора для малих p_t: e^{-p_t} ≈ 1 - p_t]
= s_t · (1 - p_t)²                      [зведення подібних членів]
```

Звідси приріст частки інфікованих вузлів подвоюється на кожному кроці:
```
p_{t+1} ≈ 2 · p_t                       [експоненційне подвоєння інфікованих вузлів]
```

Кількість раундів до досягнення середини кластера (`p_t = 0.5`):
```
T_early ≈ log₂(N) - 1                   [раундів для покриття половини кластера]
```

### Фінішна фаза (Квадратично-експоненційне згасання неінфікованих)

Коли частка інфікованих перевищує 90% (`p_t ≈ 1`, `s_t << 1`), чистий Push застрягає в проблемі колекціонера купонів. Проте в Scuttlebutt діє зворотна гілка Pull: кожен неінфікований вузол обов'язково контактує з кимось. Ймовірність потрапити на інфікованого становить `p_t = 1 - s_t ≈ 1`.

Аналіз частки неінфікованих вузлів `s_t` у фіналі:
```
s_{t+1}
= s_t · (1 - p_t) · e^{-p_t}            [точне рівняння спадання залишку]
= s_t · s_t · e^{-1}                    [підстановка p_t ≈ 1 та 1 - p_t = s_t]
= (1 / e) · s_t²                        [квадратична залежність наступного стану від попереднього]
```

Квадратична залежність `s_{t+1} ∝ s_t²` означає, що кількість неінфікованих вузлів спадає супер-експоненційно (як подвійна експонента):

```
s_0 = 0.1 (10% неінфіковано)
s_1 ≈ 0.368 · (0.1)² = 0.00368 (0.37% неінфіковано)
s_2 ≈ 0.368 · (0.00368)² = 0.00000498 (0.0005% неінфіковано — повне закриття)
```

Кількість раундів у фінальній фазі:
```
T_late ≈ log₂(log₂(N))                  [надшвидкий фінішний хвіст завдяки Push-Pull]
```

### Сумарний час повної збіжності

Повний час розповсюдження оновлення до 100% вузлів кластера:
```
T_total
= T_early + T_late                      [сума тривалості обох фаз]
= log₂(N) + log₂(log₂(N)) + O(1)        [асимптотична оцінка загальної кількості раундів]
```

Для кластера з `N = 10 000` вузлів при періоді пліток `T_gossip = 1` секунда:
```
T_total
= log₂(10000) + log₂(log₂(10000))       [підстановка N = 10000]
≈ 13.29 + log₂(13.29)                   [обчислення першого логарифма: 2¹³·²⁹ ≈ 10000]
≈ 13.29 + 3.73                          [обчислення подвійного логарифма]
≈ 17 раундів (17 секунд)                [загальний час для 100% узгодженості 10 000 серверів]
```

## 3. Теорема про неперервний префікс версій (Monotonic Prefix Invariance)

При передачі оновлень через мережу розмір повідомлення обмежений параметром `MTU` (Maximum Transmission Unit). Якщо між вузлом `A` та `B` накопичилося `M` оновлень сумарним розміром `Bytes > MTU`, пакет змушений передати лише підмножину з `m < M` дельт.

### Формулювання проблеми дірок у версіях

Якщо дельти передаються у випадковому порядку, одержувач `A` може отримати оновлення з версіями `{11, 15, 18}`, пропустивши `{12, 13, 14, 16, 17}`.
Якщо `A` оновить відому йому максимальну версію до `18`, у наступному раунді `A` запитає версії `v > 18`. Версії `12..17` будуть назавжди втрачені для `A`, що спричинить перманентне розходження стану (*silent state corruption*).

### Теорема про безпечне оновлення версії

> **Теорема (Scuttlebutt Prefix Invariance):**
> Якщо для будь-якого вузла-джерела `X` множина переданих дельт `Δ(X)` впорядкована строго за монотонним зростанням версій:
> `v₁ < v₂ < v₃ < ... < v_m`, де `v₁ = v_current(X) + 1`,
> і кожен наступний елемент задовольняє умову `v_{i+1} = v_i + 1` (відсутність розривів у генераторі),
> то для будь-якого відсікання за розміром `m ≥ 1` оновлений стан одержувача володіє повним неперервним префіксом усіх мутацій `X` до версії `v_m` включно.

### Доведення за математичною індукцією

**База індукції:**
Нехай локальна версія вузла `X` на одержувачі дорівнює `V_0`.
Перша дельта в пакеті має версію `v₁ = V_0 + 1`.
Отримувач застосовує `v₁`. Його локальний стан містить усі версії до `v₁` без жодного пропуску. Версія стає `V_1 = v₁ = V_0 + 1`. Твердження істинне.

**Індукційний перехід:**
Припустимо, що після застосування `k` дельт (`k < m`) стан одержувача містить усі версії від `1` до `v_k` неперервно.
Наступна дельта в пакеті має версію `v_{k+1}`.
За умовою впорядкування генератора `v_{k+1} = v_k + 1`.
Після застосування цієї дельти одержувач отримує значення для версії `v_k + 1`.
Усі версії від `1` до `v_{k+1}` присутні в локальному стані. Нова максимальна версія стає `V_{k+1} = v_{k+1}`.

**Висновок:**
Якщо пакет обривається на довільному елементі `m` через ліміт MTU, максимальна версія, зафіксована одержувачем, дорівнює `v_m`.
У наступному раунді пліток одержувач надішле дайджест із запитом `v > v_m`.
Першим елементом наступного пакета стане `v_{m+1} = v_m + 1`.
Жодна проміжна дельта не втрачається і не перестрибується. Інваріант збережено.
