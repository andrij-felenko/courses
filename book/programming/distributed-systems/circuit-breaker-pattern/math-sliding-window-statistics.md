# 🧮 Статистика ковзного вікна та ймовірнісні оцінки збоїв у запобіжниках

Математичний апарат запобіжника розв'язує фундаментальну задачу статистичної перевірки гіпотез у режимі реального часу: на основі обмеженої вибірки останніх `N` спостережень або часового інтервалу `T` необхідно оцінити невідому ймовірність збою віддаленого сервісу `p` та ухвалити бінарне рішення про розривання ланцюга.

## Математична модель кількісного ковзного вікна (Count-Based Window)

Розглянемо послідовність викликів до віддаленого сервісу як послідовність випадкових величин `X₁, X₂, ..., X_m`, де кожен виклик `X_i ∈ {0, 1}` є випробуванням Бернуллі:

```
X_i = 1,  якщо виклик завершився збоєм (помилка 5xx, таймаут або аномальна затримка)
X_i = 0,  якщо виклик виконано успішно
```

Кількісне ковзне вікно фіксованого розміру `N` зберігає останні `N` результатів викликів у кільцевому буфері. Вибіркова частка помилок `R_N` на кроці `m` визначається як середнє арифметичне елементів поточного вікна:

```
R_N(m) = (1 / N) · ∑_{j=0}^{N-1} X_{m-j}
```

Нехай `S_N(m) = ∑_{j=0}^{N-1} X_{m-j}` — абсолютна кількість зафіксованих помилок у вікні. Тоді відсоток помилок виражається формулою:

```
R_N(m)
= S_N(m) / N                       [означення вибіркової частки]
= (S_N(m-1) + X_m - X_{m-N}) / N   [рекурентне оновлення при зсуві буфера]
```

Рекурентне співвідношення показує, що для підтримки точної суми помилок `S_N` немає потреби щоразу підсумовувати весь масив із `N` елементів: достатньо додати новий результат `X_m` та відняти найстаріший результат `X_{m-N}`, витіснений із вікна, що забезпечує часову складність `O(1)` на кожен виклик.

## Дисперсія оцінки та похибка вибірки: чому необхідний `minimumNumberOfCalls`

Якщо справжня ймовірність відмови сервісу дорівнює `p`, то випадкова величина `S_N` має біноміальний розподіл `S_N ~ Binomial(N, p)` із математичним сподіванням `E[S_N] = N · p` та дисперсією `Var(S_N) = N · p · (1 - p)`.

Дисперсія вибіркової частки `R_N` дорівнює:

```
Var(R_N)
= Var(S_N / N)                     [винесення константи 1/N з-під дисперсії]
= (1 / N²) · Var(S_N)              [властивість дисперсії Var(a·Y) = a²·Var(Y)]
= (1 / N²) · N · p · (1 - p)       [підстановка дисперсії біноміального розподілу]
= (p · (1 - p)) / N                [скорочення на N]
```

Стандартна похибка оцінки `σ(R_N)` дорівнює квадратному кореню з дисперсії:

```
σ(R_N) = √((p · (1 - p)) / N)
```

Звідси безпосередньо випливає закон згасання похибки: точність оцінки зростає пропорційно `1 / √N`. 

Розглянемо практичний приклад: поріг спрацьовування запобіжника встановлено на рівні `θ = 0.50` (50% помилок). Припустимо, що сервіс працює стабільно, і його фоновий рівень помилок становить лише `p = 0.05` (5%).

Обчислимо ймовірність помилкового розмикання ланцюга (False Positive) при різному розмірі вибірки `N`, якщо випадково станеться сплеск помилок:

### Випадок 1: Мала вибірка без захисного порогу (`N = 4`)

Якщо в системі надійшло лише 4 запити, і 2 з них випадково завершилися таймаутом (наприклад, через короткочасну втрату одного TCP-пакета), вибіркова частка складе `R₄ = 2 / 4 = 0.50`.

Ймовірність отримати 2 або більше збоїв із 4 викликів при `p = 0.05` обчислюється за біноміальним законом:

```
P(S₄ ≥ 2)
= P(S₄ = 2) + P(S₄ = 3) + P(S₄ = 4)
= C(4, 2) · p² · (1-p)² + C(4, 3) · p³ · (1-p) + C(4, 4) · p⁴
= 6 · (0.05)² · (0.95)² + 4 · (0.05)³ · (0.95) + 1 · (0.05)⁴
= 6 · 0.0025 · 0.9025 + 4 · 0.000125 · 0.95 + 0.00000625
= 0.0135375 + 0.000475 + 0.00000625
≈ 0.014018  [тобто 1.40% ймовірність хибного розмикання]
```

При 1.4% ймовірності хибного спрацьовування на кожні 4 виклики система з високою інтенсивністю трафіку буде постійно безпричинно переходити у стан `OPEN`.

### Випадок 2: Захисний поріг `minimumNumberOfCalls = 50`

Якщо встановлено мінімальний обсяг вибірки `N = 50`, розмикання вимагає щонайменше `S₅₀ ≥ 25` помилок при `θ = 0.50`.

Застосуємо нерівність Чернова для верхньої межі хвоста біноміального розподілу при `k ≥ N · p`:

```
P(S_N ≥ k) ≤ exp(-N · D_KL((k/N) || p))
```

де `D_KL(q || p) = q · ln(q/p) + (1-q) · ln((1-q)/(1-p))` — відстань Кульбака — Лейблера між розподілами Бернуллі з параметрами `q = 0.50` та `p = 0.05`:

```
D_KL(0.50 || 0.05)
= 0.50 · ln(0.50 / 0.05) + 0.50 · ln(0.50 / 0.95)   [підстановка q = 0.50 та p = 0.05]
= 0.50 · ln(10) + 0.50 · ln(0.5263)                  [обчислення часток під логарифмами]
= 0.50 · 2.302585 + 0.50 · (-0.64185)                [обчислення натуральних логарифмів]
= 1.15129 - 0.32092                                  [множення на вагу 0.50]
= 0.83037                                            [кінцева сума компонентів дивергенції]
```

Підставимо отримане значення у нерівність Чернова для `N = 50`:

```
P(S₅₀ ≥ 25)
≤ exp(-50 · 0.83037)                                 [підстановка показника N · D_KL]
= exp(-41.5185)                                      [обчислення експоненти]
≈ 9.3 · 10⁻¹⁹                                        [верхня межа ймовірності хибного спрацювання]
```

Ймовірність хибного спрацьовування становить менше `10⁻¹⁸`, що практично виключає можливість безпідставного розмикання ланцюга за умови стабільної роботи залежності.

## Модель часового ковзного вікна (Time-Based Window) з круговими бакетами

Часове ковзне вікно аналізує події за фіксований інтервал часу `T` (наприклад, останні 10 секунд). Для уникнення збереження мільйонів окремих міток часу інтервал `T` дискретизується на `K` рівних часових кошиків (бакетів) тривалістю `Δt = T / K` кожен.

Нехай кожен бакет `b_k` (де `k ∈ {0, 1, ..., K-1}`) містить вектор двох атомарних лічильників: `(c_total(k), c_failed(k))`.

Поточний індекс активного бакета `k_cur` у кільцевому масиві визначається системним часом `t_now` (у мілісекундах) за формулою:

```
k_cur = ⌊(t_now / Δt)⌋ mod K
```

Сумарна статистика за все вікно `T` обчислюється як сума по всіх валідних бакетах, чий вік не перевищує `T`:

```
C_total = ∑_{k=0}^{K-1} c_total(k) · I(t_now - t_bucket(k) < T)
C_failed = ∑_{k=0}^{K-1} c_failed(k) · I(t_now - t_bucket(k) < T)
```

де `I(·)` — індикаторна функція валідності часового зрізу.

Вибіркова частка відмов у часовому вікні становить:

```
R_T(t) = C_failed / C_total,  за умови C_total ≥ minimumNumberOfCalls
```

Дискретизація вносить часову похибку реакції (Latency of Detection) не більше ніж `Δt`. При `T = 10 с` та `K = 10` (бакети по `Δt = 1 с`) максимальне запізнення витіснення застарілої помилки з вікна складає рівно 1 секунду, що є оптимальним компромісом між точністю та накладними витратами на синхронізацію пам'яті.

## Ймовірнісна динаміка стану HALF-OPEN: пробний пакет запитів

У стані `HALF-OPEN` запобіжник пропускає фіксовану квоту пробних запитів `n_probe` (наприклад, `n_probe = 10`). Перехід назад у стан `CLOSED` відбувається, якщо частка помилок серед пробних запитів не перевищує поріг `θ_half` (або якщо всі `n_probe` запитів виконано без жодної помилки).

Нехай справжня ймовірність відмови деградованого сервісу під час відновлення становить `p_true`.

Ймовірність того, що запобіжник успішно виявить збереження збою і повернеться в стан `OPEN` при випробуванні `n_probe` викликів за умови правила «хоча б одна помилка повертає в OPEN», визначається формулою:

```
P(Open | p_true)
= 1 - P(усі n_probe запитів успішні)                 [перехід до протилежної події]
= 1 - (1 - p_true)^(n_probe)                         [добуток ймовірностей незалежних успіхів]
```

Проаналізуємо чутливість детектора відновлення:

```
P(Open | p_true = 0.50, n_probe = 10)
= 1 - (1 - 0.50)¹⁰                                   [підстановка p_true = 0.50]
= 1 - (0.50)¹⁰                                       [обчислення ймовірності успішного випробування]
= 1 - 0.000976                                       [піднесення до 10-го степеня]
= 0.999024                                           [99.90% ймовірність повернення в OPEN]
```

```
P(Open | p_true = 0.20, n_probe = 10)
= 1 - (1 - 0.20)¹⁰                                   [підстановка p_true = 0.20]
= 1 - (0.80)¹⁰                                       [обчислення ймовірності успіху 0.80]
= 1 - 0.107374                                       [піднесення 0.80 до 10-го степеня]
= 0.892626                                           [89.26% ймовірність виявлення деградації]
```

```
P(Open | p_true = 0.05, n_probe = 10)
= 1 - (1 - 0.05)¹⁰                                   [підстановка p_true = 0.05]
= 1 - (0.95)¹⁰                                       [обчислення ймовірності успіху 0.95]
= 1 - 0.598737                                       [піднесення 0.95 до 10-го степеня]
= 0.401263                                           [40.13% ймовірність блокування при шумі]
```

Звідси видно, що при малій кількості пробних викликів `n_probe = 10` важка аварія (`p_true ≥ 0.50`) відсікається практично гарантовано (99.9%), тоді як приховані мікрозбої (`p_true = 0.05`) можуть випадково пройти перевірку. Для підвищення надійності при високонавантажених інтерфейсах `n_probe` збільшують до `20–50`, або використовують процентний поріг збоїв замість умови одиничного збою.

## Експоненційне згладжування (EWMA) як альтернатива ковзному вікну

Замість збереження дискретної історії у кільцевому масиві альтернативним математичним підходом до оцінки відмов є експоненційно зважене ковзне середнє (Exponentially Weighted Moving Average, EWMA).

Нехай `S_k` — оцінка частки збоїв на кроці `k`, а `x_k ∈ {0, 1}` — результат останнього виклику. Оновлення здійснюється за формулою:

```
S_k = α · x_k + (1 - α) · S_{k-1}
```

де `α ∈ (0, 1]` — фактор згладжування (вага останнього вимірювання).

Розгорнемо рекурентний вираз у явний ряд:

```
S_k
= α · x_k + (1 - α) · (α · x_{k-1} + (1 - α) · S_{k-2})                          [розкриття S_{k-1}]
= α · x_k + α · (1 - α) · x_{k-1} + α · (1 - α)² · x_{k-2} + ... + (1 - α)^k · S₀  [ітераційне розгортання до початкового стану]
= α · ∑_{j=0}^{k-1} (1 - α)^j · x_{k-j} + (1 - α)^k · S₀                        [згортання суми випробувань у степеневий ряд]
```

Вага спостереження, що відбулося `j` кроків тому, спадає за експоненційним законом `w(j) = α · (1 - α)^j`.

Ефективний розмір вибірки (Half-life період) для EWMA дорівнює:

```
N_eff ≈ 1 / α
```

При `α = 0.02` ефективне вікно складає `N_eff ≈ 50` викликів. Головною перевагою EWMA є використання всього 8 байтів пам'яті (одне число з плаваючою крапкою `double`) без виділення масивів та буферів, проте EWMA має триваліший «хвіст пам'яті» при різкому відновленні сервісу порівняно з жорстким прямокутним ковзним вікном.
