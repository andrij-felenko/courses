# 🧮 Математика черг, часу перебування та колапсу корисної пропускної здатності

Математичний аналіз систем масового обслуговування дає змогу точно описати фізику виникнення черг, розрахувати нелінійний стрибок затримок при наближенні до точки насичення та строго довести неминучість колапсу корисної пропускної здатності (Goodput) за відсутності механізмів скидання навантаження. Ця вставка містить формальні виведення часових характеристик черги за законами Літтла та Кінгмана, побудову функції корисної продуктивності та розрахунок оптимального порогу відсікання надлишкового трафіку.

## 1. Базова модель M/M/1 та закон Літтла

Розглянемо сервер як одноканальну систему масового обслуговування `M/M/1` з пуассонівським вхідним потоком запитів з інтенсивністю `λ` (запитів/с) та експоненційним часом обслуговування із середньою інтенсивністю `μ` (запитів/с).

Коефіцієнт завантаження (інтенсивність використання) системи позначається як `ρ`:

```
ρ = λ / μ
```

У стаціонарному стані обов'язковою умовою існування системи є `ρ < 1` (інакше черга зростає до нескінченності).

Ймовірність того, що в системі перебуває рівно `n` запитів (включаючи той, що обслуговується), задається розподілом:

```
P_n = (1 - ρ) · ρⁿ
```

Середня кількість запитів у системі `L` обчислюється як математичне сподівання:

```
L = ∑_{n=0}^{∞} n · P_n
= (1 - ρ) · ∑_{n=0}^{∞} n · ρⁿ
= (1 - ρ) · (ρ / (1 - ρ)²)     [сума ряду: ∑ n·ρⁿ = ρ / (1-ρ)²]
= ρ / (1 - ρ)                  [скорочення на (1 - ρ)]
```

За **законом Літтла (Little's Law)** середня кількість вимог у системі `L` прямо пропорційна інтенсивності вхідного потоку `λ` та середньому часу перебування запиту в системі `W` (Sojourn Time = час у черзі + час обробки):

```
L = λ · W
```

Звідси середній повний час перебування запиту в системі `W`:

```
W = L / λ
= (ρ / (1 - ρ)) / λ            [підстановка L = ρ / (1 - ρ)]
= (λ / μ) / (λ · (1 - λ / μ))  [підстановка ρ = λ / μ]
= 1 / (μ · (1 - λ / μ))        [скорочення на λ]
= 1 / (μ - λ)                  [розкриття дужок у знаменнику]
```

Середній час безпосереднього очікування в черзі `W_q` (Queue Waiting Time) дорівнює повному часу `W` мінус середній час обслуговування `1/μ`:

```
W_q = W - 1/μ
= (1 / (μ - λ)) - (1 / μ)      [підстановка W = 1 / (μ - λ)]
= (μ - (μ - λ)) / (μ · (μ - λ)) [зведення до спільного знаменника]
= λ / (μ · (μ - λ))            [спрощення чисельника: μ - μ + λ = λ]
= (λ / μ) / (μ · (1 - λ / μ))  [ділення чисельника і знаменника на μ]
= ρ / (μ · (1 - ρ))            [підстановка ρ = λ / μ]
```

### Граничний аналіз поведінки затримки

Дослідимо поведінку часу очікування `W_q` при наближенні завантаження `ρ` до 1:

```
lim_{ρ → 1⁻} W_q = lim_{ρ → 1⁻} [ρ / (μ · (1 - ρ))] = +∞
```

Графік залежності затримки від завантаження має характерний вигляд хокейної ключки (Hockey-Stick Curve): при `ρ = 0.5` час очікування становить `1/μ`, при `ρ = 0.9` він зростає до `9/μ` (у 9 разів), а при `ρ = 0.99` сягає `99/μ` (майже у 100 разів більше за базовий час обробки).

## 2. Апроксимація Кінгмана для реальних систем G/G/1

У реальних розподілених системах час надходження та час обробки запитів не підкоряються простому експоненційному закону через патерни спалахів трафіку (Burstiness), конкуренцію за пам'ять та важкі хвости затримок (Long Tails).

Для довільних розподілів інтервалів надходження та часу виконання (система `G/G/1`) застосовується **формула Кінгмана (Kingman's Formula)**, яка враховує коефіцієнти варіації:

* `c_a = σ_a / E[A]` — коефіцієнт варіації інтервалів надходження (де `σ_a` — стандартне відхилення, `E[A]` — середній інтервал `1/λ`).
* `c_s = σ_s / E[S]` — коефіцієнт варіації часу обслуговування (де `σ_s` — стандартне відхилення, `E[S]` — середній час `1/μ = τ_s`).

Апроксимація Кінгмана для середнього часу очікування в черзі `W_q`:

```
W_q ≈ (ρ / (1 - ρ)) · ((c_a² + c_s²) / 2) · τ_s
```

Ця формула виділяє три незалежні фактори впливу на чергу:
1. **Фактор завантаження `ρ / (1 - ρ)`:** визначає нелінійне вибухове зростання затримки при насиченні.
2. **Фактор варіативності `(c_a² + c_s²) / 2`:** показує, що навіть при помірному завантаженні (`ρ = 0.7`) висока дисперсія (наприклад, `c_a = 3`, `c_s = 2`, що типово для мікросервісів з важкими запитами) збільшує затримку черги в `(9 + 4) / 2 = 6.5` раза порівняно з ідеальним пуассонівським процесом (`c_a = c_s = 1`).
3. **Фактор масштабу часу `τ_s`:** базовий час виконання однієї транзакції.

## 3. Модель колапсу корисної пропускної здатності (Goodput)

Нехай кожен клієнт встановлює фіксований таймаут очікування відповіді `T_out`. Якщо повний час перебування запиту в системі `S` (час у черзі `T_wait` + час виконання `T_exec`) перевищує `T_out`, відповідь вважається застарілою, а клієнтський сокет розривається.

Для системи `M/M/1` функція густини ймовірності повного часу перебування `S` має експоненційний вигляд:

```
f_S(t) = (μ - λ) · e^(-(μ - λ) · t),   для t ≥ 0
```

Ймовірність того, що запит буде оброблено і доставлено в межах таймауту `T_out`:

```
P(S ≤ T_out) = ∫_{0}^{T_out} f_S(t) dt
= ∫_{0}^{T_out} (μ - λ) · e^(-(μ - λ) · t) dt
= [ -e^(-(μ - λ) · t) ]_{0}^{T_out}            [первісна показникової функції]
= 1 - e^(-(μ - λ) · T_out)                     [підстановка меж інтегрування]
```

Функція корисної пропускної здатності `Goodput(λ)` визначається як добуток інтенсивності вхідного потоку на ймовірність успішного вчасного виконання:

```
Goodput(λ) = λ · P(S ≤ T_out)
= λ · (1 - e^(-(μ - λ) · T_out))
```

### Дослідження поведінки Goodput за перевантаження

Розглянемо поведінку функції `Goodput(λ)` у трьох режимах:

#### Режим 1: Низьке навантаження (`λ ≪ μ`)
Коли `λ` мале, різниця `μ - λ ≈ μ`. Якщо таймаут `T_out` значно більший за середній час обробки (`T_out ≫ 1/μ`), то `e^(-μ · T_out) ≈ 0`, отже:
```
Goodput(λ) ≈ λ · (1 - 0) = λ
```
Корисна продуктивність лінійно зростає зі збільшенням вхідного трафіку.

#### Режим 2: Наближення до насичення (`λ → μ⁻`)
Розкладемо експоненту в ряд Тейлора при малих значеннях `(μ - λ) · T_out`:
```
e^(-(μ - λ) · T_out) ≈ 1 - (μ - λ) · T_out
```
Підставимо це наближення у функцію `Goodput(λ)`:

```
Goodput(λ) ≈ λ · (1 - (1 - (μ - λ) · T_out))
= λ · (μ - λ) · T_out          [розкриття дужок]
```

Знайдемо границю `Goodput(λ)` при наближенні вхідного потоку до максимальної місткості `μ`:

```
lim_{λ → μ⁻} Goodput(λ) = lim_{λ → μ⁻} [λ · (μ - λ) · T_out] = μ · 0 · T_out = 0
```

Це строге математичне доведення феномену **колапсу перевантаження**: намагання черги обслужити весь трафік при `λ → μ` призводить до того, що час очікування в черзі прямує до нескінченності, 100% запитів перевищують таймаут `T_out`, а корисна пропускна здатність падає до абсолютного нуля.

## 4. Числовий розрахунок навантаження та колапсу

Розглянемо високопродуктивний сервер із такими параметрами:
* Продуктивність воркерів: `μ = 1000` запитів на секунду (середній час виконання `τ_s = 1` мс).
* Клієнтський таймаут: `T_out = 50` мс (у 50 разів більше за час чистої обробки).

Розрахуємо середній час очікування в черзі `W_q`, ймовірність вчасної відповіді `P(S ≤ 50 мс)` та корисний `Goodput` для різних значень вхідного навантаження `λ`:

```
Приклад 1: λ = 800 req/s (Завантаження ρ = 0.80)
W_q = 0.80 / (1000 · (1 - 0.80)) = 0.80 / 200 = 0.004 с = 4.0 мс
μ - λ = 1000 - 800 = 200
P(S ≤ 0.050 с) = 1 - e^(-200 · 0.050) = 1 - e^(-10) = 1 - 0.000045 = 99.995%
Goodput = 800 · 0.99995 = 799.96 req/s

Приклад 2: λ = 980 req/s (Завантаження ρ = 0.98)
W_q = 0.98 / (1000 · (1 - 0.98)) = 0.98 / 20 = 0.049 с = 49.0 мс
μ - λ = 1000 - 980 = 20
P(S ≤ 0.050 с) = 1 - e^(-20 · 0.050) = 1 - e^(-1) = 1 - 0.3678 = 63.2%
Goodput = 980 · 0.632 = 619.36 req/s   [втрата 37% корисного трафіку!]

Приклад 3: λ = 998 req/s (Завантаження ρ = 0.998)
W_q = 0.998 / (1000 · (1 - 0.998)) = 0.998 / 2 = 0.499 с = 499.0 мс
μ - λ = 1000 - 998 = 2
P(S ≤ 0.050 с) = 1 - e^(-2 · 0.050) = 1 - e^(-0.1) = 1 - 0.9048 = 9.52%
Goodput = 998 · 0.0952 = 95.0 req/s    [колапс: пропускна здатність впала в 10 разів!]
```

## 5. Розрахунок оптимального порогу скидання навантаження

Щоб максимізувати `Goodput(λ)`, необхідно обмежити інтенсивність трафіку, що допускається до черги, значенням `λ*` (Admission Rate), скидаючи весь надлишок `λ - λ*`.

Знайдемо точку максимуму функції `Goodput(λ) = λ · (1 - e^(-(μ - λ) · T_out))`. Візьмемо похідну по `λ` та прирівняємо її до нуля:

```
d/dλ [ Goodput(λ) ]
= (1 - e^(-(μ - λ) · T_out)) + λ · d/dλ [ 1 - e^(-(μ - λ) · T_out) ]  [правило добутку]
= 1 - e^(-(μ - λ) · T_out) - λ · T_out · e^(-(μ - λ) · T_out)        [похідна складеної функції]
= 1 - (1 + λ · T_out) · e^(-(μ - λ) · T_out)                         [факторизація]
```

Прирівнюємо похідну до нуля для пошуку екстремуму:

```
1 - (1 + λ · T_out) · e^(-(μ - λ) · T_out) = 0
e^((μ - λ) · T_out) = 1 + λ · T_out                                   [перенесення та взяття оберненої експоненти]
```

Для практичних інженерних систем, де `μ · T_out ≫ 1` (клієнтський таймаут у десятки разів перевищує час виконання одного запиту), розв'язок цього рівняння апроксимується формулою:

```
λ* = μ · (1 - δ)
де δ ≈ ln(μ · T_out) / (μ · T_out)
```

Для нашого числового прикладу (`μ = 1000`, `T_out = 0.050` с, `μ · T_out = 50`):
```
δ ≈ ln(50) / 50 = 3.912 / 50 ≈ 0.0782
λ* = 1000 · (1 - 0.0782) = 921.8 req/s
```

Якщо вхідне навантаження становить `λ_in = 5000` req/s, шеддер повинен пропустити `λ* = 922` req/s і миттєво відхилити `λ_shed = 5000 - 922 = 4078` req/s.

При цьому для пропущених `922` запитів:
```
μ - λ* = 1000 - 922 = 78
P(S ≤ 0.050 с) = 1 - e^(-78 · 0.050) = 1 - e^(-3.9) = 1 - 0.0202 = 97.98%
Стабільний Goodput = 922 · 0.9798 = 903.4 req/s
```

Замість падіння корисної продуктивності до нуля під час сплеску 5 000 req/s, алгоритм скидання навантаження стабільно підтримує корисний вихід на рівні **903 успішних запитів на секунду**, що становить понад 90% від теоретичного максимуму апаратної місткості системи.
