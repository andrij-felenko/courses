# 🧮 Математичне моделювання ампліфікації хвоста затримок у віялових RPC-запитах

Коли координатор розподіленої системи розбиває один клієнтський запит на `N` паралельних підзапитів до незалежних вузлів або шардів (патерн *Scatter-Gather*), загальний час очікування визначається не середньою тривалістю відповіді, а поведінкою найповільнішого учасника групи. Математичний аналіз цієї поведінки розкриває фундаментальну закономірність: навіть якщо кожен окремий мікросервіс працює з надійністю 99%, для агрегованого запиту показник затримки 99-го перцентиля експоненційно деградує і стає типовою подією для більшості користувачів.

Цей математичний аналіз формалізує ймовірнісні закономірності ампліфікації затримок, досліджує поведінку вибіркового максимуму для різних класів розподілів і доводить високу ефективність техніки спекулятивного геджування.

## Модель розподілу затримок одиночного вузла

Нехай тривалість обробки запиту одним ізольованим сервісом є невід'ємною неперервною випадковою величиною `X` із функцією накопиченого розподілу (Cumulative Distribution Function, CDF) `F(t)` та функцією густини ймовірності `f(t)`:

```
F(t) = P(X ≤ t)
```

Ймовірність того, що випадкова затримка `X` перевищить заданий часовий поріг `t`, визначається функцією надійності (Survival Function, або complementary CDF) `S(t)`:

```
S(t) = P(X > t) = 1 − F(t)
```

Визначимо квантиль затримки `t_p` як часовий поріг, вище якого знаходиться частка `p` найповільніших відповідей (хвіст розподілу). За означенням квантиля:

```
F(t_p) = 1 − p
S(t_p) = p
```

Для 99-го перцентиля затримки (p99) маємо `p = 0.01`, тобто `F(t₀.₀₁) = 0.99`. Це означає, що рівно 1% запитів до окремого вузла виконується довше за час `t₀.₀₁`. Відповідно, для 95-го перцентиля (p95) маємо `p = 0.05`, а для медіани (p50) — `p = 0.50`.

## Агрегація у віялі: розподіл максимуму вибірки

При паралельному виконанні віяла з `N` запитів координатор може завершити агрегацію та повернути відповідь клієнту лише тоді, коли надійдуть відповіді від **усіх** `N` вузлів. Позначимо випадкові величини затримок окремих вузлів як `T₁, T₂, ..., T_N`.

Загальний час очікування агрегованого запиту `T_agg` дорівнює максимуму з усіх індивідуальних затримок:

```
T_agg = max(T₁, T₂, ..., T_N)
```

Припустимо спочатку, що затримки `T₁, ..., T_N` є взаємно незалежними однаково розподіленими (i.i.d.) випадковими величинами зі спільною функцією розподілу `F(t)`. Зазначимо, що в реальних мережах дата-центрів затримки можуть мати додаткову позитивну кореляцію через спільні комутатори стійок або перевантаження каналів, що лише посилює деградацію хвоста. Припущення про незалежність дає оптимістичну нижню оцінку деградації системи.

Подія `T_agg ≤ t` настає тоді й лише тоді, коли кожен окремий запит вклався у час `t`:

```
P(T_agg ≤ t)
= P(max(T₁, ..., T_N) ≤ t)         [за означенням максимуму]
= P(T₁ ≤ t ∧ T₂ ≤ t ∧ ... ∧ T_N ≤ t) [одночасне виконання всіх подій]
= P(T₁ ≤ t) · P(T₂ ≤ t) · ... · P(T_N ≤ t) [незалежність випадкових величин]
= [F(t)]ᴺ                         [однаковість розподілу F(t)]
```

Звідси отримуємо функцію розподілу агрегованої затримки:

```
F_agg(t) = [F(t)]ᴺ
```

Відповідно, ймовірність того, що клієнт зазнає перевищення порогової затримки `t` (функція надійності агрегату), становить:

```
S_agg(t)
= P(T_agg > t)
= 1 − F_agg(t)                    [властивість доповнення]
= 1 − [F(t)]ᴺ                     [підстановка розподілу максимуму]
= 1 − [1 − S(t)]ᴺ                 [вираження через функцію надійності]
```

## Ймовірність зіткнення з хвостовою затримкою p99

Підставимо у виведену формулу квантиль 99-го перцентиля одиночного вузла `t₀.₀₁`, для якого `S(t₀.₀₁) = p = 0.01`:

```
P(T_agg > t₀.₀₁) = 1 − (1 − p)ᴺ = 1 − (0.99)ᴺ
```

Обчислимо точні значення ймовірності потрапляння в хвостову затримку для різних ступенів віяла `N`:

```
N = 1:   P = 1 − (0.99)¹   = 1 − 0.9900 = 0.0100  (1.0%)
N = 5:   P = 1 − (0.99)⁵   = 1 − 0.9510 = 0.0490  (4.9%)
N = 10:  P = 1 − (0.99)¹⁰  = 1 − 0.9044 = 0.0956  (9.56%)
N = 25:  P = 1 − (0.99)²⁵  = 1 − 0.7778 = 0.2222  (22.22%)
N = 50:  P = 1 − (0.99)⁵⁰  = 1 − 0.6050 = 0.3950  (39.50%)
N = 100: P = 1 − (0.99)¹⁰⁰ = 1 − 0.3660 = 0.6340  (63.40%)
N = 200: P = 1 − (0.99)²⁰⁰ = 1 − 0.1340 = 0.8660  (86.60%)
N = 500: P = 1 − (0.99)⁵⁰⁰ = 1 − 0.0066 = 0.9934  (99.34%)
```

При малих значеннях `p` та помірних `N` (де `N · p ≪ 1`) застосуємо розклад функції у біноміальний ряд Тейлора в околі точки `p = 0`:

```
(1 − p)ᴺ = 1 − N·p + (N·(N − 1) ÷ 2)·p² − ...
1 − (1 − p)ᴺ ≈ N·p                [лінійне наближення першого порядку]
```

Це математично доводить, що при масштабуванні паралельного розпитування ймовірність потрапляння в хвостову деградацію на початковому етапі зростає **лінійно пропорційно до кількості вузлів `N`**. Якщо ступінь віяла подвоюється, ризик деградації запиту також подвоюється, а при досягненні `N = 100` понад 63% усіх клієнтських запитів гарантовано відчувають на собі затримку найгіршого перцентиля.

## Математичне сподівання затримки для експоненційного розподілу

Щоб зрозуміти, як зміщується середній час очікування `E[T_agg]` залежно від `N`, розглянемо випадок, коли тривалість обробки запиту вузлом має експоненційний розподіл з параметром інтенсивності `λ` (середній час відповіді одного вузла `E[X] = 1 / λ`):

```
F(t) = 1 − e^(−λ·t),   t ≥ 0
```

Математичне сподівання максимуму невід'ємної випадкової величини обчислюється через інтегрування функції надійності:

```
E[T_agg]
= ∫₀^∞ P(T_agg > t) dt             [інтегральне представлення сподівання]
= ∫₀^∞ (1 − [1 − e^(−λ·t)]ᴺ) dt   [підстановка експоненційного CDF]
```

Зробимо заміну змінної інтегрування `u = 1 − e^(−λ·t)`, звідки `e^(−λ·t) = 1 − u`, а диференціал `du = λ·e^(−λ·t) dt = λ·(1 − u) dt`, тобто `dt = du / (λ·(1 − u))`:

```
E[T_agg]
= (1 ÷ λ) · ∫₀¹ ((1 − uᴺ) ÷ (1 − u)) du [заміна змінної інтегрування]
= (1 ÷ λ) · ∫₀¹ (1 + u + u² + ... + uᴺ⁻¹) du [сума геометричної прогресії]
= (1 ÷ λ) · [u + u²÷2 + u³÷3 + ... + uᴺ÷N]₀¹ [первісна полінома]
= (1 ÷ λ) · ∑_{k=1}^N (1 ÷ k)      [підстановка меж інтегрування 0 та 1]
= (1 ÷ λ) · H_N                   [означення гармонічного числа H_N]
```

Використовуючи асимптотичний розклад гармонічного числа `H_N` для великих `N` через сталу Ейлера–Маскероні `γ ≈ 0.57721`:

```
H_N = ln(N) + γ + O(1 ÷ N)
E[T_agg] ≈ (ln(N) + 0.5772) ÷ λ
```

Математичне сподівання агрегованої затримки зростає логарифмічно з ростом `N`. Проте реальні системи мають не експоненційний, а важкохвостий (Heavy-Tailed / Lognormal / Pareto) або бімодальний розподіл затримок (через паузи збирання сміття Garbage Collection, скидання брудних сторінок кешу на диск fsync, мережеві колізії TCP retransmission). 

У бімодальному розподілі з імовірністю `1 - p` запит потрапляє у швидкий режим (10–15 мс), а з імовірністю `p` — у повільний режим (300–500 мс). Оскільки при `N = 100` ймовірність отримати хоча б одну повільну відповідь сягає 63.4%, медіана агрегованого розподілу стрибкоподібно переміщується з 15 мс безпосередньо в зону 300–500 мс.

## Математичний ефект спекулятивного геджування (Hedged Requests)

Стратегія спекулятивного геджування (*Speculative Hedging*) модифікує процес: координатор відправляє запит на перший вузол, і якщо відповідь не надходить протягом фіксованого часу геджування `t_h` (зазвичай обирається на рівні 95-го перцентиля `t₀.₀₅`), дублюючий запит надсилається на незалежну репліку того самого сервісу.

Нехай затримки первинного запиту `X₁` та геджованого запиту `X₂` є незалежними. Підсумковий час очікування відповіді від цього сегмента становить:

```
T_hedged = min(X₁, t_h + X₂)
```

Обчислимо ймовірність того, що затримка геджованого вузла перевищить квантиль `t_p` (де `t_p > t_h`):

```
P(T_hedged > t_p)
= P(X₁ > t_p ∧ t_h + X₂ > t_p)    [обидва виклики затрималися]
= P(X₁ > t_p) · P(X₂ > t_p − t_h) [незалежність первинного і дублюючого викликів]
```

Оскільки `t_p − t_h > 0`, і якщо розподіл затримок репліки подібний, маємо `P(X₂ > t_p − t_h) ≈ p`. Звідси результуюча ймовірність деградації окремої пари стає квадратичною:

```
p_eff = P(T_hedged > t_p) ≈ p · p = p²
```

Для 99-го перцентиля одиночного вузла (`p = 0.01`):

```
p_eff = 0.01 · 0.01 = 0.0001 (0.01%)
```

Тепер обчислимо загальну ймовірність деградації віялового запиту з `N = 100` паралельними гілками при застосуванні геджування:

```
P(T_agg_hedged > t₀.₀₁)
= 1 − (1 − p_eff)ᴺ
= 1 − (1 − 0.0001)¹⁰⁰             [підстановка квадратичної ймовірності]
= 1 − (0.9999)¹⁰⁰
= 1 − 0.990049
= 0.009951 ≈ 0.995%
```

Математичні висновки:
1. Без геджування при `N = 100` ймовірність потрапляння в p99 становила **63.40%**.
2. Зі спекулятивним геджуванням при `N = 100` ймовірність становить лише **0.995%** (зменшення ризику зриву SLA у 63.7 раза).
3. При цьому додаткове навантаження на систему складає лише `P(X₁ > t_h) = 1 − 0.95 = 5%` додаткових запитів, оскільки дублюючий виклик генерується лише для 5% найповільніших операцій. Це робить геджування найефективнішим інструментом захисту хвостових затримок у великих кластерах.
