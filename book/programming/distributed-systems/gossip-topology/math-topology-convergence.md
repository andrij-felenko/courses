# 🧮 Математичний аналіз збіжності пліток на топологіях: спектральний аналіз, експандери та затримки між ДЦ

Епідемічне поширення інформації у розподіленій системі моделюється як марковський випадковий процес на орієнтованому або неорієнтованому графі зв'язків `G = (V, E)`, де `V` — множина серверів (`|V| = N`), а `E` — дозволені канали прямого зв'язку. Швидкість збіжності та обсяг трафіку фундаментально залежать від топологічної структури матриці суміжності графа `G`.

---

## 1. Повний граф (Full Mesh): аналітичне виведення швидкості збіжності

У повнозв'язному графі кожен вузол може безпосередньо обрати будь-якого іншого учасника з рівномірною ймовірністю:

```
P(вибору вузла j вузлом i) = 1 / (N - 1)    [для будь-яких i ≠ j]
```

Нехай у раунді `t` частка інфікованих вузлів становить `i_t`, а частка неінфікованих — `s_t = 1 - i_t`. Кожен інфікований вузол у раунді `t` обирає `k` випадкових партнерів (коефіцієнт розгалуження *fanout*).

Імовірність того, що конкретний неінфікований вузол `u` **не буде обраний** жодним із `k` викликів конкретного інфікованого вузла `v`, дорівнює:

```
P(не отримати від v) = 1 - k / (N - 1)
```

Оскільки в раунді `t` активні `N · i_t` інфікованих вузлів, які обирають партнерів незалежно, сумарна ймовірність для вузла `u` залишитися неінфікованим у раунді `t + 1` становить:

```
s_{t+1} = s_t · (1 - k / (N - 1))^(N · i_t)
```

Застосовуючи стандартну границю другої чудової границі `(1 - x / N)^N ≈ e^(-x)` при `N → ∞`, отримуємо детерміністичне різницеве рівняння епідемії:

```
s_{t+1} = s_t · e^(-k · i_t)
        = s_t · e^(-k · (1 - s_t))    [оскільки i_t = 1 - s_t]
```

### Фази поширення та загальна кількість раундів

Процес поширення складається з трьох послідовних математичних фаз:

1. **Фаза експоненційного розгону (`s_t ≈ 1`):**
   Кількість інфікованих вузлів зростає геометрично як `(1 + k)^t`. Тривалість фази до досягнення 50% кластера становить:
   ```
   T_start = ln(N / 2) / ln(1 + k)
   ```

2. **Фаза насичення (`s_t < 0.1`):**
   Майже всі вузли інфіковані. Частка неінфікованих згасає експоненційно за законом `s_{t+1} ≈ s_t · e^(-k)`.

3. **Фаза збору останніх вузлів (*Coupon Collector's Problem*):**
   Коли в кластері залишається мала кількість неінфікованих серверів (наприклад, останні кілька вузлів), випадкові дейтаграми інфікованих машин часто потрапляють у вже оновлені вузли. Для зараження останнього неінфікованого сервера необхідно:
   ```
   T_finish = (1 / k) · ln(N)
   ```

Сумарна кількість раундів `T_mesh` для досягнення 100% узгодженості в повному графі:

```
T_mesh = (1 / ln(1 + k)) · ln(N) + (1 / k) · ln(N) + O(1)
       = O(log N)
```

## 2. Графи-експандери та спектральний розрив (Spectral Gap)

Коли повний огляд неможливий через обмеження пам'яті, вузли утворюють `d`-регулярний оверлейний граф, де кожен вузол знає лише `d` сусідів (`d = O(log N)` або `d = const`).

Нехай `A` — матриця суміжності графа `G` розміру `N × N`, де `A_{ij} = 1`, якщо між `i` та `j` є зв'язок. Нормована матриця ймовірностей переходу випадкового блукання дорівнює:

```
P = (1 / d) · A
```

Матриця `P` має дійсні власні значення, упорядковані за спаданням:

```
1 = λ₁ > λ₂ ≥ λ₃ ≥ ... ≥ λ_N ≥ -1
```

Різниця між першим і другим власними значеннями називається **спектральним розривом** (*Spectral Gap*):

```
γ = 1 - λ₂
```

Спектральний розрив визначає швидкість змішування марковського ланцюга: чим більший розрив `γ`, тим швидше інформація поширюється графом і тим швидше розподіл ймовірностей наближається до стаціонарного рівномірного стану.

### Константа Чеєгера та нерівність Алона-Мілмана

Для будь-якої підмножини вузлів `S ⊂ V` розміром `|S| ≤ N / 2` визначимо кількість ребер, що перетинають межу між `S` та рештою графа `V \ S`, як `|∂S| = e(S, V \ S)`.

**Константа Чеєгера** (коефіцієнт ізопериметричного розширення) визначається як мінімальне відношення кількості ребер межі до розміру підмножини:

```
h(G) = min_{S: 0 < |S| ≤ N/2} ( |∂S| / |S| )
```

Зв'язок між геометрією графа (константою Чеєгера) та спектром матриці переходу встановлює дискретна **нерівність Чеєгера (теорема Алона-Мілмана)**:

```
γ / 2 ≤ h(G) ≤ √(2 · γ)
```

```
[Виведення часу змішування (Mixing Time)]:
Нехай p_t — вектор розподілу ймовірностей знаходження повідомлення на кроці t.
Відстань за повною варіацією до рівномірного розподілу π = (1/N, ..., 1/N):

|| p_t - π ||_TV ≤ (1/2) · √N · (λ₂)^t
                 = (1/2) · √N · (1 - γ)^t
                 ≤ (1/2) · √N · e^(-γ · t)    [оскільки 1 - x ≤ e^(-x)]

Прирівнюючи похибку до ε = 1/N:
(1/2) · √N · e^(-γ · t) = 1/N
e^(-γ · t) = 2 / (N^(1.5))
-γ · t = -1.5 · ln(N) + ln(2)
t = (1.5 / γ) · ln(N) - (ln 2) / γ

T_mix = O( (1 / γ) · log N )
```

### Лема про перемішування в експандерах (Expander Mixing Lemma)

Для будь-яких двох підмножин вершин `S, T ⊆ V` у `d`-регулярному графі кількість ребер між ними `e(S, T)` відхиляється від очікуваного середнього значення не більше ніж на спектральний штраф:

```
| e(S, T) - (d / N) · |S| · |T| | ≤ λ₂ · √( |S| · |T| · (1 - |S| / N) · (1 - |T| / N) )
```

Ця лема гарантує, що у випадковому графі-експандері ребра розподілені майже рівномірно між усіма підмножинами вершин, що унеможливлює виникнення ізольованих вузьких кластерів, у яких могли б застрягти плітки.

### Графи Рамануджана: оптимальні оверлеї

За теоремою Алона-Бопани, для будь-якого `d`-регулярного графа друге власне значення обмежене знизу:

```
λ₂ ≥ (2 · √(d - 1) / d) - o(1)
```

Графи, що досягають цієї теоретичної межі (`λ₂ ≤ 2 · √(d - 1) / d`), називаються **графами Рамануджана**. У таких графах спектральний розрив є максимальним:

```
γ_opt = 1 - (2 · √(d - 1) / d) ≈ 1 - 2 / √d
```

Для графа Рамануджана навіть за степеня вершини `d = 8` спектральний розрив становить `γ ≈ 1 - 2/√8 = 0.293`. Це гарантує, що випадковий gossip-протокол на оверлеї з 8 сусідами поширює інформацію за `O(log N)` раундів, аналогічно повному графу, але зі строго постійним споживанням пам'яті `O(1)` на кожному сервері.

## 3. Математична оптимізація ієрархічної двошарової топології (Multi-DC)

Розглянемо систему з `N` вузлів, розподілених між `M` однаковими дата-центрами. Кожен дата-центр містить `n = N / M` вузлів.

Параметри фізичної мережі:
- Локальна мережа (LAN): затримка `RTT_lan = 0.1 мс`, вартість передачі байта `c_lan = 0`.
- Глобальна мережа (WAN): затримка `RTT_wan = 80 мс`, вартість передачі байта `c_wan > 0`.

Вузол обирає партнера за правилом зваженої ймовірності:
- З імовірністю `1 - p_remote` партнер обирається рівномірно з локального ДЦ (`n - 1` кандидатів).
- З імовірністю `p_remote` партнер обирається рівномірно з віддалених ДЦ (`N - n` кандидатів).

```
P(локальний партнер) = (1 - p_remote) / (n - 1)
P(віддалений партнер) = p_remote / (N - n)
```

### Обсяг трафіку WAN за один раунд

Кількість міжрегіональних дейтаграм `W`, що генеруються всім кластером за один раунд пліток тривалістю `T_round` секунд із fanout `k`:

```
W = N · k · p_remote    [дейтаграм / раунд]
```

Трафік WAN на секунду:

```
R_wan = (N · k · p_remote · S_msg) / T_round    [байтів / с]
```
де `S_msg` — середній розмір UDP-пакета пліток (зазвичай 1200 байтів).

### Загальний час збіжності між дата-центрами

Час поширення оновлення складається з двох компонентів:
1. Час локального насичення дата-центру-ініціатора:
   ```
   T_local = (1 / ln(1 + k · (1 - p_remote))) · ln(n) · T_round
   ```
2. Час очікування першого успішного міжрегіонального пробиття тунелю:
   Ймовірність того, що хоча б один із `n` локальних інфікованих вузлів відправить дейтаграму у віддалений дата-центр за один раунд, дорівнює:
   ```
   P_bridge = 1 - (1 - p_remote / (M - 1))^(n · k)
   ```
   Середня кількість раундів очікування переходу інфекції через WAN:
   ```
   E[Rounds_wan] = 1 / P_bridge ≈ (M - 1) / (n · k · p_remote)    [при малих p_remote]
   ```

Сумарний фізичний час повної глобальної конвергенції `T_global`:

```
T_global = T_local + (E[Rounds_wan] · T_round) + RTT_wan + T_remote_local
         ≈ (2 / ln(1 + k)) · ln(n) · T_round + ( (M - 1) / (n · k · p_remote) ) · T_round + RTT_wan
```

### Формулювання задачі оптимізації

Інженерна мета полягає в мінімізації сумарної функції вартості `Cost(p_remote)`, що враховує як фінансові витрати на трафік WAN, так і штраф за затримку несинхронізованого стану:

```
Cost(p_remote) = c_wan · R_wan + c_time · T_global
               = c_wan · ( (N · k · S_msg) / T_round ) · p_remote
                 + c_time · ( ( (M - 1) · T_round ) / (n · k) ) · (1 / p_remote) + Const
```

Диференціюючи `Cost(p_remote)` за `p_remote` і прирівнюючи похідну до нуля:

```
d(Cost) / d(p_remote) = c_wan · ( (N · k · S_msg) / T_round )
                       - c_time · ( ( (M - 1) · T_round ) / (n · k) ) · (1 / p_remote²) = 0
```

Розв'язуючи відносно `p_remote`:

```
p_remote² = (c_time / c_wan) · ( ( (M - 1) · T_round² ) / (N · n · k² · S_msg) )
```

Оскільки `N = n · M`:

```
p_remote^* = (T_round / (n · k)) · √( (c_time / c_wan) · ( (M - 1) / (M · S_msg) ) )
           = O( 1 / (n · k) )
```

Цей результат дає строгий математичний закон проектування: **міжрегіональна ймовірність `p_remote` повинна зменшуватися обернено пропорційно розміру локального дата-центру `n`**.

Якщо локальний кластер збільшується в 10 разів (наприклад, з 100 до 1000 серверів), ймовірність вибору зовнішнього вузла необхідно знизити в 10 разів (з `0.1` до `0.01`). Це зберігає сумарний потік транзитного трафіку WAN на постійному рівні, запобігаючи перевантаженню каналів зв'язку.
