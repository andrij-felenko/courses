# 🧮 Математика закону Літтла та збіжності алгоритму Vegas

Математична модель адаптивного контролю конкурентності поєднує фундаментальну теорію стаціонарних черг (закон Літтла) та теорію дискретного керування зі зворотним зв'язком за затримкою (алгоритм TCP Vegas та градієнтні методи).

## 1. Закон Літтла та оптимальна точка роботи

Розгляньмо обчислювальну систему (сервіс) як стаціонарну систему масового обслуговування.
Позначимо ключові змінні:
- `λ` — середня швидкість надходження та завершення запитів (пропускна здатність або throughput, вимірюється в запитах за секунду);
- `W` — повний середній час перебування запиту в системі (затримка або Round-Trip Time `RTT`, вимірюється в секундах);
- `L` — середня кількість запитів, які одночасно перебувають у системі в процесі обробки або очікування (паралелізм або *in-flight requests*).

**Теорема Літтла (Little's Law, 1961):**
Для будь-якої ергодичної стаціонарної системи без втрат виконується строге співвідношення:

```
L = λ · W
```

Повний час перебування `W` складається з двох компонентів:
1. `W_p` (чистий час обробки або *processing time* без урахування очікування);
2. `W_q` (час очікування в черзі або *queueing delay*).

```
W = W_p + W_q
```

Коли система недовантажена, черга порожня (`W_q = 0`). Тоді час відповіді дорівнює мінімально можливій фізичній затримці системи:

```
W = W_p = RTT_min
```

Нехай максимальна пропускна здатність сервісу (фізична межа обробки за 100% завантаження ресурсів процесора чи пам'яті) становить `μ = λ_max`.
Тоді **оптимальна кількість одночасних запитів** `L_opt` (так звана точка зламу або *Knee*), за якої ресурси використовуються на 100%, але черга ще не утворюється (`W_q = 0`), обчислюється як:

```
L_opt = λ_max · RTT_min
```

Якщо вхідний паралелізм `L` перевищує `L_opt`, швидкість завершення `λ` не може перевищити фізичну межу `λ_max`. Згідно із законом Літтла, надлишковий паралелізм неминуче трансформується у зростання затримки очікування `W_q`:

```
L
= λ_max · (RTT_min + W_q)           [підстановка W = RTT_min + W_q у закон Літтла]
= λ_max · RTT_min + λ_max · W_q     [розкриття дужок]
= L_opt + λ_max · W_q               [підстановка L_opt = λ_max · RTT_min]

W_q
= (L - L_opt) / λ_max               [вираження часу затримки в черзі]
```

Звідси видно закономірність: будь-яке збільшення ліміту `L` понад `L_opt` призводить до строго лінійного зростання затримки в черзі без жодного приросту корисної пропускної здатності.

## 2. Оцінка розміру черги в алгоритмі Vegas

Алгоритм Vegas використовує вимірювання затримки для оцінки поточної кількості запитів, що осіли в черзі очікування `Queue(t)`.

Нехай у момент часу `t`:
- `Limit(t)` — поточний встановлений ліміт паралелізму;
- `RTT_min` — мінімальна зафіксована затримка системи без навантаження;
- `RTT_sample(t)` — поточна виміряна середня затримка запитів.

Очікувана пропускна здатність системи за відсутності черг:

```
λ_expected(t) = Limit(t) / RTT_min
```

Фактична виміряна пропускна здатність системи:

```
λ_actual(t) = Limit(t) / RTT_sample(t)
```

Різниця між очікуваною та фактичною швидкістю показує, яка частка пропускної здатності втрачається через простоювання в черзі. Множачи цю різницю на час обігу `RTT_min`, отримуємо оцінку кількості запитів у черзі `Queue(t)`:

```
Queue(t)
= (λ_expected(t) - λ_actual(t)) · RTT_min                     [визначення черги через різницю швидкостей]
= (Limit(t) / RTT_min - Limit(t) / RTT_sample(t)) · RTT_min   [підстановка очікуваної та фактичної швидкостей]
= Limit(t) · (RTT_min / RTT_min - RTT_min / RTT_sample(t))    [внесення множника RTT_min у дужки]
= Limit(t) · (1 - RTT_min / RTT_sample(t))                    [скорочення RTT_min / RTT_min = 1]
```

Отриманий вираз є базовим рівнянням черги Vegas:

```
Queue(t) = Limit(t) · (1 - RTT_min / RTT_sample(t))
```

Введемо коефіцієнт градієнта затримки `g(t)`:

```
g(t) = RTT_min / RTT_sample(t)
```

Тоді розмір черги записується як:

```
Queue(t) = Limit(t) · (1 - g(t))
```

- Якщо `RTT_sample(t) ≈ RTT_min`, то `g(t) ≈ 1`, а `Queue(t) ≈ 0` (черга відсутня, система має вільний запас ємності);
- Якщо `RTT_sample(t) > RTT_min`, то `g(t) < 1`, а `Queue(t) > 0` (у системі накопичується черга).

## 3. Стохастичний шум та оцінювачі затримки

У реальних розподілених системах затримка окремого запиту `RTT_i` є випадковою величиною:

```
RTT_i = RTT_base + η_i + q_i
```
де `RTT_base` — детермінований час обробки та мережевого транзиту, `η_i ≥ 0` — випадковий шум виконання (паузи збирача сміття, перемикання контексту, конкуренція за кеш процесора), а `q_i ≥ 0` — затримка очікування в черзі.

Щоб шум `η_i` не призводив до помилкового стискання ліміту, алгоритм використовує два окремі фільтри:

### Мінімум базової затримки
Мінімальна затримка вибирається як інфімум вибірки у ковзному часовому вікні тривалістю `T_base` (зазвичай 5–10 хвилин):

```
RTT_min(t) = min { RTT_i | t_i ∈ [t - T_base, t] }
```
Оскільки для випадкового шуму виконується `P(η_i > 0) > 0`, зі зростанням розміру вибірки `N` мінімум збігається до фізичної межі за ймовірністю:

```
lim_{N → ∞} P( |min(RTT_i) - RTT_base| < ε ) = 1
```

### Поточна затримка вікна
Для обчислення `RTT_sample(t)` використовують або середнє значення в короткому вікні спостереження (наприклад, останні `K = 100` запитів або вікно тривалістю 500 мс), або перцентиль `P_90`.

При використанні експоненційного згладжування середнього (EMA):

```
RTT_smoothed(k)
= (1 - γ) · RTT_smoothed(k - 1) + γ · RTT_sample(k)    [експоненційне оновлення з вагою γ ∈ (0, 1)]
```

## 4. Дискретне правило оновлення та збіжність

Класичне дискретне правило Vegas використовує два пороги `α` та `β` (де `0 < α < β`):

```
Limit(t + 1) =
  Limit(t) + 1,        якщо Queue(t) < α  (канал недовантажений)
  Limit(t) - 1,        якщо Queue(t) > β  (черга перевищила поріг)
  Limit(t),            якщо α ≤ Queue(t) ≤ β (стан рівноваги)
```

У сучасних реалізаціях (Gradient2 в Envoy та Netflix) застосовується неперервна мультиплікативна форма оновлення з коефіцієнтом запасу (headroom) `h` та експоненційним згладжуванням `σ ∈ (0, 1]`:

```
Limit_target(t) = Limit(t) · g(t) + h
Limit(t + 1) = (1 - σ) · Limit(t) + σ · Limit_target(t)
```

## 5. Дослідження стійкості точки спокою за Ляпуновим

Розгляньмо стійкість градієнтного регулятора за методом першого наближення Ляпунова.

Нехай система перебуває в стаціонарному стані перевантаження, де час обробки залежить від паралелізму за законом черги `RTT_sample(L) = RTT_min + k · (L - L_opt)` для `L > L_opt` (де `k = 1 / λ_max`).
Запишімо різницеве рівняння динаміки ліміту навколо точки рівноваги `L*`:

```
F(L) = (1 - σ) · L + σ · (L · (RTT_min / RTT_sample(L)) + h)
```

У точці рівноваги `L*` виконується рівність `F(L*) = L*`, звідки:

```
L* · (1 - RTT_min / RTT_sample(L*))
= h                                                   [умова стаціонарності F(L*) = L*]

Queue(L*)
= h                                                   [підстановка визначення черги Queue = L · (1 - g)]
```

Тобто система стабілізується в точці, де постійний розмір черги строго дорівнює параметру запасу `h`.

Обчислимо похідну функції переходу `dF/dL` у точці `L*`:

```
dF/dL = (1 - σ) + σ · d/dL [ L · RTT_min / (RTT_min + k · (L - L_opt)) + h ]
```

Застосуємо правило диференціювання частки:

```
d/dL [ L / (RTT_min + k · (L - L_opt)) ]
= ( (RTT_min + k · (L - L_opt)) - L · k ) / (RTT_sample)^2    [похідна частки u/v за формулою (u'v - uv')/v^2]
= ( RTT_min - k · L_opt ) / (RTT_sample)^2                    [скорочення подібних k·L - L·k = 0]
```

Оскільки `L_opt = λ_max · RTT_min` та `k = 1 / λ_max`, маємо:

```
k · L_opt
= (1 / λ_max) · (λ_max · RTT_min)                             [підстановка k та L_opt]
= RTT_min                                                     [скорочення λ_max]

RTT_min - k · L_opt
= RTT_min - RTT_min                                           [підстановка k·L_opt = RTT_min]
= 0                                                           [тотожний нуль]
```

Отже, похідна виразу в точці рівноваги дорівнює нулю:

```
dF/dL |_{L = L*}
= (1 - σ) + σ · 0                                             [підстановка нульової похідної]
= 1 - σ                                                       [спрощення виразу]
```

Умова асимптотичної стійкості різницевого рівняння `|dF/dL| < 1` зводиться до:

```
|1 - σ| < 1
-1 < 1 - σ < 1
0 < σ < 2
```

Оскільки коефіцієнт згладжування зазвичай обирається в діапазоні `σ ∈ [0.1, 0.5]`, умова стійкості виконується з великим запасом. Це гарантує швидку монотонну збіжність ліміту до оптимальної точки без коливань і зривів.

## 6. Покроковий числовий приклад збіжності

**Вихідні параметри системи:**
- Базовий час відповіді: `RTT_min = 20 мс = 0.020 с`;
- Максимальна ємність бекенду: `λ_max = 5000 RPS`;
- Оптимальний паралелізм: `L_opt = 5000 · 0.020 = 100 запитів`;
- Параметри алгоритму: запас `h = 10`, коефіцієнт згладжування `σ = 0.2`.

**Сценарій перевантаження:**
Вхідний трафік різко зріс, і початковий ліміт становив `Limit(0) = 180`.
Через накопичення черги виміряний час відповіді досяг `RTT_sample = 36 мс = 0.036 с`.

Обчислимо перерахунок ліміту на першій ітерації:

**Крок 1: Обчислення градієнта та розміру черги**
```
g(0)
= RTT_min / RTT_sample                                        [формула градієнта затримки]
= 0.020 / 0.036                                               [підстановка виміряних значень у секундах]
≈ 0.5556                                                      [ділення чисел з округленням]

Queue(0)
= Limit(0) · (1 - g(0))                                       [формула оцінки черги Vegas]
= 180 · (1 - 0.5556)                                          [підстановка Limit(0) = 180 та g(0)]
= 180 · 0.4444                                                [віднімання в дужках]
≈ 80 запитів                                                  [множення чисел]
```

**Крок 2: Обчислення цільового та оновленого ліміту**
```
Limit_target(0)
= Limit(0) · g(0) + h                                         [формула цільового ліміту з запасом]
= 180 · 0.5556 + 10                                           [підстановка значень Limit(0), g(0) та h]
= 100.0 + 10                                                  [множення 180 · 0.5556 = 100.0]
= 110.0                                                       [додавання запасу h]

Limit(1)
= (1 - σ) · Limit(0) + σ · Limit_target(0)                    [формула експоненційного згладжування]
= (1 - 0.2) · 180 + 0.2 · 110.0                               [підстановка σ = 0.2, Limit(0) та Limit_target]
= 0.8 · 180 + 22.0                                            [спрощення доданків]
= 144.0 + 22.0                                                [множення 0.8 · 180 = 144.0]
= 166.0                                                       [підсумковий ліміт першої ітерації]
```

За першу ітерацію ліміт знизився зі 180 до 166. За 5–7 наступних ітерацій (при вікні 500 мс це менше 3.5 секунди) значення ліміту плавно зійдеться до точки спокою `L* = L_opt + h = 100 + 10 = 110`, черга зменшиться з 80 до запланованих 10 запитів, а час відповіді стабілізується на рівні `RTT ≈ 22 мс`.
