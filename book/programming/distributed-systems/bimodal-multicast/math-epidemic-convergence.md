# 🧮 Математика бімодальності: виведення епідемічної збіжності та згасання дефіциту

Математичний фундамент Bimodal Multicast базується на поєднанні класичної теорії масового обслуговування, епідемічних процесів на випадкових графах та марковських ланцюгів. Мета цього математичного аналізу — строго довести, чому традиційне квитування колапсує при масштабуванні кластера, як швидко згасає дефіцит інформації під час раундів пліток і чому фінальний стан системи має строго бімодальну форму.

---

## 1. Математична модель NAK-колапсу в традиційному Multicast

Розглянемо розподілену систему, що складається з одного вузла-джерела `S` та `N` незалежних вузлів-одержувачів `R₁, R₂, ..., R_N`. Джерело генерує та транслює потік дейтаграм з інтенсивністю `λ` повідомлень на секунду.

У фізичному мережевому середовищі дейтаграми втрачаються через переповнення черг комутаторів, колізії та помилки контрольних сум. Нехай імовірність втрати окремого пакета на мережевому шляху до довільного одержувача дорівнює `p` (де `0 < p < 1`). У детермінованих протоколах групової надійності одержувачі відстежують неперервність послідовності номерів `SeqNum`. Виявивши пропуск у послідовності, одержувач генерує негативне підтвердження `NAK` (Negative Acknowledgment) і надсилає його безпосередньо первинному джерелу.

### Розподіл кількості NAK на один втрачений пакет
Випадкова величина `X`, яка позначає кількість одержувачів, що втратили конкретний надісланий пакет, підпорядковується біноміальному закону розподілу `X ~ Bin(N, p)`:

```
P(X = m) = (N! / (m! · (N - m)!)) · pᵐ · (1 - p)ᴺ⁻ᵐ

E[X]
= ∑_{m=0}^{N} m · P(X = m)     [означення математичного сподівання дискретної величини]
= N · p                       [математичне сподівання біноміального розподілу]

Var(X)
= N · p · (1 - p)             [дисперсія біноміального розподілу]
```

Якщо втрата стається на спільній магістральній ланці дерева розсилки (наприклад, на вихідному порту комутатора стійки ToR), пакет одночасно втрачають усі `M` вузлів піддерева, створюючи детермінований сплеск із `M` негативних квитанцій.

### Інтенсивність вхідного потоку NAK на джерело
При середній частоті мовлення `λ` середня кількість запитів `NAK`, які надходять до мережевого інтерфейсу джерела за одиницю часу `R_nak`, дорівнює добутку інтенсивності потоку на середню кількість відмов на один пакет:

```
R_nak
= λ · E[X]                    [інтенсивність вхідного потоку запитів за формулою Літтла]
= λ · N · p                   [підстановка середнього значення біноміального розподілу]
```

### Умова нестабільності черги та час до колапсу
Нехай ядро операційної системи джерела здатне обробляти та відправляти повторні пакети з максимальною продуктивністю `μ` пакетів/с, а системний буфер сокета вміщує максимум `B` запитів. Черга запитів до джерела поводиться як система масового обслуговування типу `M/M/1/B`.

Якщо вхідний потік запитів перевищує пропускну здатність обробки, черга зростає лінійно зі швидкістю `Δ = R_nak - μ`:

```
λ · N · p > μ                 [умова необмеженого зростання черги та переповнення буфера]

T_overflow
= B / (R_nak - μ)             [час до повного вичерпання системного буфера сокета]
= B / (λ · N · p - μ)         [підстановка аналітичного виразу для R_nak]
```

**Числовий розрахунок колапсу джерела:**
Розглянемо кластер на `N = 10 000` серверів. Джерело транслює біржовий потік котирувань з інтенсивністю `λ = 1000` пакетів/с. Імовірність втрати дейтаграми на мережевій карті становить `p = 0.01` (1%). Розмір системного буфера сокета `B = 65 536` пакетів, а максимальна швидкість опрацювання переривань ядром `μ = 20 000` пакетів/с:

```
R_nak
= 1000 · 10 000 · 0.01        [обчислення вхідного потоку запитів на ретрансляцію]
= 100 000 пакетів/с           [інтенсивність у 5 разів перевищує продуктивність μ]

T_overflow
= 65 536 / (100 000 - 20 000) [розрахунок часу переповнення черги]
= 65 536 / 80 000
≈ 0.819 секунди               [буфер переповнюється менш ніж за 1 секунду]
```

Коли буфер переповнюється, ядро скидає нові `NAK`. Інші вузли не отримують відповіді, фіксують таймаут і повторно генерують `NAK`. Система входить у стан незворотної метастабільної відмови (NAK Storm), повністю припиняючи трансляцію нових корисних даних.

## 2. Динаміка епідемічного відновлення (Pull-Gossip)

Bimodal Multicast усуває NAK-колапс шляхом заборони надсилання запитів первинному джерелу. Відновлення виконується через децентралізований епідемічний обмін дайджестами між випадковими вузлами.

Нехай `y[t]` — частка вузлів кластера, які **не мають** конкретного повідомлення після завершення раунду пліток `t` (де `0 ≤ y[t] ≤ 1`). Відповідно, частка поінформованих вузлів становить `x[t] = 1 - y[t]`.

### Початковий стан після Фази 1
Оскільки у фазі 1 пакет транслюється через оптимістичний IP Multicast або Unicast-дерево з імовірністю мережевої втрати `p`:

```
y[0] = p                      [початкова частка вузлів, що не отримали пакет у фазі 1]
x[0] = 1 - p                  [початкова частка успішно поінформованих вузлів]
```

### Рекурентне рівняння згасання дефіциту інформації
У кожному раунді анти-ентропії кожен непоінформований вузол обирає `k` випадкових партнерів у кластері та запитує їхні дайджести стану (Pull-запит). Якщо хоча б один із `k` обраних партнерів уже володіє пакетом, непоінформований вузол виявляє дефіцит і завантажує відсутні дані.

Вузол залишається непоінформованим у раунді `t + 1` тоді й лише тоді, коли **всі `k`** випадково обраних ним партнерів також були непоінформованими в раунді `t`:

```
P(обраний партнер не має пакета)
= y[t]                        [частка непоінформованих вузлів у популяції]

P(усі k партнерів не мають пакета)
= (y[t])ᵏ                     [добуток імовірностей для незалежного вибору k пірів]

y[t + 1]
= y[t] · (y[t])ᵏ              [частка тих, хто не мав, помножена на ймовірність невдачі вибору]
= (y[t])^{k + 1}              [рекурентна формула надшвидкого затухання дефіциту]
```

Розгорнемо рекурентне співвідношення для `r` послідовних раундів пліток:

```
y[1] = (y[0])^{k + 1}         [частка непоінформованих після 1-го раунду]
y[2] = (y[1])^{k + 1} = (y[0])^{(k + 1)²} [частка непоінформованих після 2-го раунду]
...
y[r]
= (y[0])^{(k + 1)ʳ}           [загальна формула частки дефіциту після r раундів]
= p^{(k + 1)ʳ}                [підстановка початкової ймовірності втрати p]
```

Зверніть увагу на степінь `(k + 1)ʳ`: згасання частки втрачених пакетів відбувається не просто експоненційно, а **суперекспоненційно** (подвійна експонента).

### Числовий розрахунок епідемічної збіжності
Розглянемо великий кластер на `N = 100 000` серверів. Нехай початковий рівень втрат в апаратній мережі під час оптимістичної розсилки становить `p = 0.05` (5%), а коефіцієнт розгалуження пліток `k = 3` (кожен сервер опитує лише 3 випадкові сусіди за раунд):

```
y[0] = 0.05                   [5000 серверів не отримали дейтаграму у фазі 1]

y[1]
= 0.05^{(3 + 1)¹}             [обчислення частки втрат після 1-го раунду gossip]
= 0.05⁴
= 0.00000625                  [частка непоінформованих становить 0.000625%]

Очікувана кількість непоінформованих вузлів E[U₁] після 1-го раунду:
E[U₁]
= N · y[1]                    [множення розміру кластера на частку втрат]
= 100 000 · 0.00000625
= 0.625 вузла                 [у середньому менше 1 сервера на весь 100-тисячний кластер]

y[2]
= 0.05^{(3 + 1)²}             [обчислення частки втрат після 2-го раунду gossip]
= 0.05¹⁶
≈ 1.526 · 10⁻²¹

Очікувана кількість непоінформованих вузлів E[U₂] після 2-го раунду:
E[U₂]
= 100 000 · 1.526 · 10⁻²¹     [очікувана кількість втрачених копій у кластері]
≈ 1.526 · 10⁻¹⁶ вузла         [імовірність існування хоча б одного втраченого пакета практично нульова]
```

Лише два короткі раунди пліток із навантаженням 3 UDP-дейтаграми на сервер зводять кількість втрачених повідомлень практично до абсолютного нуля по всьому кластеру.

## 3. Теорема про бімодальний розподіл доставки

Нехай `Z` — випадкова величина, що позначає частку вузлів кластера, які успішно зберегли повідомлення після завершення роботи протоколу (`0 ≤ Z ≤ 1`).

Функція густини ймовірності `f(z)` має два дельта-подібні піки (моди):

```
f(z) ≈ (1 - P_fail) · δ(z - 1) + P_fail · δ(z - 0)
```

де `δ(x)` — дельта-функція Дірака, а `P_fail` — імовірність того, що джерело зазнало фатального краху в перші мікросекунди передачі, не встигнувши заразити достатню кількість пірів.

### Доведення відсутності проміжних станів (розщеплення)
У класичних ненадійних протоколах розподіл `Z` є розмитим: частина вузлів отримує 40% повідомлень, частина — 70%, що створює непередбачувані стани розбіжності. Доведемо, що в Bimodal Multicast імовірність опинитися в проміжному діапазоні `P(ε < Z < 1 - ε)` прямує до нуля при зростанні розміру кластера `N`.

Нехай джерело встигло надіслати повідомлення хоча б `C` вузлам (де `C ≥ k + 1`), перш ніж вийшло з ладу. Процес поширення пліток на ранньому етапі моделюється гіллястим процесом Гальтона-Ватсона, де кожен інфікований вузол породжує в середньому `μ_g = k · (1 - y)` нових носіїв інформації.

Оскільки на старті `y ≈ 1`, маємо `μ_g ≈ k ≥ 2 > 1`. За фундаментальною теоремою про гіллясті процеси, якщо математичне сподівання кількості нащадків `μ_g > 1`, процес є надкритичним: імовірність виродження після подолання порогу `C` є строго меншою за одиницю і спадає експоненційно з ростом `C`.

На пізньому етапі епідемії зв'язність графа передачі оцінюється через границю Чернова та властивості експандера випадкових регулярних графів. Для будь-якого фіксованого `ε > 0`:

```
P(Z < 1 - ε | C ≥ k + 1)
≤ exp(-c · k · x[0] · N)      [експоненційна оцінка Чернова для випадкових графів]

lim_{N → ∞} P(ε < Z < 1 - ε) = 0 [проміжні стани математично неможливі при великому N]
```

Це доводить, що система є строго бінарною: або повідомлення отримають майже всі вузли (`Z ≈ 1`), або повідомлення не отримає ніхто (`Z ≈ 0`).

## 4. Розрахунок вікна зберігання в буфері (Buffer Retention Window)

Оскільки в pbcast відсутні глобальні підтвердження від кожного одержувача, виникає питання: скільки часу `T_retain` кожен вузол повинен утримувати отримані пакети в пам'яті, перш ніж їх можна безпечно видалити без ризику відмовити сусідам у ретрансляції.

Нехай `r_max` — мінімальна кількість раундів анти-ентропії, необхідна для досягнення залишкового дефіциту `y[r_max] ≤ 10⁻⁹`:

```
y[r_max] ≤ 10⁻⁹               [критерій повної надійності для промислових систем]
p^{(k + 1)^{r_max}} ≤ 10⁻⁹    [підстановка формули суперекспоненційного затухання]

(k + 1)^{r_max} · ln(p) ≤ ln(10⁻⁹) [логарифмування лівої та правої частини нерівності]

(k + 1)^{r_max}
≥ ln(10⁻⁹) / ln(p)            [враховуємо, що ln(p) < 0, тому знак нерівності змінюється на протилежний]

r_max
= ⌈ ln(ln(10⁻⁹) / ln(p)) / ln(k + 1) ⌉ [аналітичний вираз для кількості раундів]
```

Підставимо інженерні параметри `p = 0.05` та `k = 3`:

```
ln(10⁻⁹) ≈ -20.7233
ln(0.05) ≈ -2.9957
-20.7233 / -2.9957 ≈ 6.9177

r_max
= ⌈ ln(6.9177) / ln(4) ⌉       [підстановка логарифма бази розгалуження]
= ⌈ 1.9341 / 1.3863 ⌉
= ⌈ 1.3951 ⌉
= 2 раунди                    [теоретично достатньо лише двох раундів пліток]
```

Для компенсації мережевого джитеру, затримок у чергах планувальника ОС та варіації RTT вводиться коефіцієнт безпеки `S_f = 3`. Тоді гарантований час утримання пакета в пам'яті:

```
T_retain
= S_f · r_max · T_round       [час життя пакета в кільцевому буфері]
= 3 · 2 · 100 мс
= 600 мс                      [пакет зберігається в пам'яті рівно 0.6 секунди]
```

Якщо інтенсивність вхідного потоку становить `λ = 10 000` пакетів/с із середнім розміром дейтаграми `S_pkt = 512` байтів, мінімальний обсяг оперативної пам'яті для кільцевого буфера на кожному сервері:

```
Buffer_RAM
= λ · T_retain · S_pkt        [обчислення обсягу пам'яті для буфера ретрансляції]
= 10 000 · 0.6 с · 512 байтів
= 3 072 000 байтів ≈ 2.93 МБ  [надзвичайно компактний буфер для високошвидкісного потоку]
```

## 5. Модель корельованих пачкових втрат Гілберта-Елліотта

У реальних комутаторах втрати дейтаграм відбуваються не ізольовано, а пачками через раптове переповнення черг буферів портів. Двостадійний марковський ланцюг Гілберта-Елліотта моделює стан мережевого каналу:
- Стан `G` (Good / Справний): імовірність втрати пакета `p_G ≈ 0`.
- Стан `B` (Bad / Збійний): імовірність втрати пакета `p_B ≈ 1`.

Ймовірність переходу зі стану `G` у стан `B` позначається як `α`, а зворотний перехід з `B` у `G` — як `β`.

```
Стаціонарна ймовірність перебування каналу в стані збою p_avg:
p_avg
= α / (α + β)                 [стаціонарна ймовірність марковського ланцюга]

Середня тривалість пачки втрачених пакетів L_burst:
L_burst
= 1 / β                       [математичне сподівання довжини перебування в стані B]
```

У разі класичного детермінованого Multicast пачкова втрата довжиною `L_burst` пакетів спричиняє генерацію `L_burst` окремих NAK-запитів від кожного постраждалого вузла, багаторазово посилюючи NAK-шторм.

У Bimodal Multicast кожен вузол передає інформацію про свій стан у вигляді бітової маски або компактного діапазону `[LowWatermark, HighWatermark]`. Незалежно від довжини пачки втрат `L_burst`, розмір повідомлення дайджесту залишається константним `O(1)`, що забезпечує абсолютну стійкість протоколу до корельованих сплесків мережевих втрат.
