# 🧮 Математика Phi Accrual детектора збоїв

У розподілених системах класичний підхід до виявлення відмов спирається на фіксований бінарний таймаут: якщо вузол не надіслав сигнал пульсу (heartbeat) протягом `T` секунд, його оголошують мертвим. У реальних публічних хмарах та глобальних мережах (WAN) мережева затримка піддається значним нелінійним флуктуаціям через сплески трафіку, повторні передачі TCP, зміни маршрутизації BGP та паузи збирача сміття (GC). Фіксований таймаут або призводить до неприпустимо довгих затримок виявлення реальної аварії (якщо обрати консервативний поріг `T = 30` секунд), або генерує лавину хибних підозр під час короткочасних мережевих сплесків (якщо обрати агресивний поріг `T = 2` секунди).

Строге математичне виведення та ймовірнісна модель адаптивного детектора збоїв **Phi Accrual Failure Detector** (запропонованого Наото Хаясібарою, Ксав'є Дефаго та колегами у 2004 році) описують базовий механізм оцінки доступності в Apache Cassandra та Akka Cluster.

---

## 1. Ймовірнісна модель надходження сигналів пульсу

Нехай процес `p` періодично надсилає повідомлення пульсу процесу `q`. Через випадкові затримки в операційній системі, буферах сокетів та комутаторах мережі інтервали між моментами прибуття послідовних повідомлень є неперервною випадковою величиною `X`.

Детектор на вузлі-спостерігачі `q` зберігає ковзне вікно з останніх `W` спостережуваних інтервалів прибуття:

```
Δt = [Δt₁, Δt₂, ..., Δt_W]
```

Зазвичай розмір вікна встановлюється в діапазоні `W = 250..1000` вибірок. На основі цих даних алгоритм динамічно розраховує поточне вибіркове середнє `μ` та вибіркову дисперсію `σ²`:

```
μ = (1 / W) · ∑_{i=1}^{W} Δt[i]
```

```
σ² = (1 / (W - 1)) · ∑_{i=1}^{W} (Δt[i] - μ)²
```

Стандартне відхилення `σ = √(σ²)` відображає поточний рівень джиттеру (мережевого тремтіння затримок) у кластері.

Припускається, що інтервали між прибуттями підпорядковуються нормальному (гаусовому) розподілу з густиною ймовірності `f(t)`:

```
f(t) = (1 / (σ · √(2π))) · e^(-(t - μ)² / (2σ²))
```

Хоча в мережах із високим рівнем втрат пакетів хвости затримок можуть мати експоненційний характер або асиметрію, гаусова апроксимація у ковзному вікні забезпечує чудовий компроміс між швидкістю адаптації до зміни умов та мінімальними обчислювальними витратами процесора на кожному кроці обробки подій.

## 2. Обчислення ймовірності запізнення та метрики Phi

Нехай `t_last` — мітка часу отримання останнього повідомлення пульсу від вузла `p`, а `t_now` — поточний локальний час на вузлі-спостерігачі `q`. Час, що минув з моменту останнього контакту, дорівнює:

```
t_diff = t_now - t_last
```

Ймовірність `P_later(t_diff)` того, що чергове повідомлення пульсу затримається на час, більший або рівний `t_diff` (за умови, що віддалений вузол насправді живий і працює у звичному статистичному режимі), визначається як інтеграл від правого хвоста функції густини розподілу:

```
P_later(t_diff) = ∫_{t_diff}^{∞} f(t) dt = 1 - F(t_diff)
```

де `F(t)` — інтегральна функція розподілу (Cumulative Distribution Function, CDF) нормального закону:

```
F(t_diff) = (1 / 2) · (1 + erf((t_diff - μ) / (σ · √2)))
```

Тут `erf(z)` — стандартна функція помилок Гауса. Звідси ймовірність запізнення набуває вигляду:

```
P_later(t_diff) = (1 / 2) · (1 - erf((t_diff - μ) / (σ · √2))) = (1 / 2) · erfc((t_diff - μ) / (σ · √2))
```

де `erfc(z) = 1 - erf(z)` — додаткова функція помилок.

Значення рівня підозри `Φ` (грецька літера «фі») визначається як логарифмічна шкала правдоподібності відмови:

```
Φ = -log₁₀(P_later(t_diff))
```

## 3. Покрокове перетворення формули підозри

Розглянемо аналітичне перетворення виразу для `Φ` залежно від величини затримки відносно математичного сподівання.

```
P_later(t_diff)
= 1 - F(t_diff)                                     [означення ймовірності хвоста розподілу]
= 1 - (1/2)·(1 + erf((t_diff - μ) / (σ·√2)))         [підстановка CDF нормального закону]
= 1/2 - (1/2)·erf((t_diff - μ) / (σ·√2))             [розкриття дужок та зведення подібних]
= (1/2) · (1 - erf((t_diff - μ) / (σ·√2)))           [винесення спільного множника 1/2]
= (1/2) · erfc((t_diff - μ) / (σ·√2))                [застосування тотожності 1 - erf(z) = erfc(z)]
```

Підставляючи отриману ймовірність у формулу логарифмічної підозри `Φ`:

```
Φ
= -log₁₀(P_later(t_diff))                            [означення метрики підозри за Хаясібарою]
= -log₁₀((1/2) · erfc((t_diff - μ) / (σ·√2)))        [підстановка знайденої ймовірності хвоста]
= -(log₁₀(1/2) + log₁₀(erfc((t_diff - μ) / (σ·√2)))) [застосування властивості логарифма добутку]
= log₁₀(2) - log₁₀(erfc((t_diff - μ) / (σ·√2)))      [спрощення від'ємного доданка -log₁₀(1/2) = log₁₀(2)]
```

### Чисельна стійкість обчислення

Під час практичної імплементації алгоритму на мовах програмування виникає проблема чисельного зникнення порядку (underflow): коли час очікування `t_diff` суттєво перевищує середнє значення `μ` (наприклад, на `5σ` або `6σ`), ймовірність `P_later` падає нижче `10⁻¹⁵`. Якщо обчислювати її наївно як `1.0 - cdf(t_diff)`, округлення чисел із плаваючою комою подвійної точності (IEEE 754 `double`) повертає `1.0 - 1.0 = 0.0`, що призводить до обчислення `-log₁₀(0.0) = +Infinity`.

Для запобігання втраті точності бібліотеки використовують безпосереднє наближення логарифма додаткової функції помилок `log(erfc(z))` через асимптотичний розклад у ряд або спеціалізовані апроксимації Чебишова, що гарантує плавне монотонне зростання `Φ` без нескінченних стрибків.

## 4. Фізичний зміст та шкала рівнів підозри

Метрика `Φ` вимірює степінь неправдоподібності того, що вузол усе ще живий. Зв'язок між числовим значенням `Φ`, ймовірністю запізнення та середньою частотою помилкових спрацьовувань визначається логарифмічною шкалою.

При значенні `Φ = 1` ймовірність випадкового запізнення становить 10%, що призводить до помилкової підозри приблизно кожні 10 секунд при щосекундному пульсі. Такий рівень є занадто агресивним для прийняття рішень про відключення.

При значенні `Φ = 2` ймовірність становить 1%, що дає одну помилку кожні 100 секунд (приблизно 1.6 хвилини).

При значенні `Φ = 4` ймовірність падає до 0.01%, тобто одна помилкова підозра виникає раз на 2.7 години.

При значенні `Φ = 6` ймовірність становить 0.0001%, що відповідає одній помилці раз на 11.5 днів безперервної роботи.

При значенні `Φ = 8` ймовірність становить одну стомільйонну (`10⁻⁸`), що відповідає одній помилці раз на 3.17 року. Саме це значення обрано як стандартний поріг за замовчуванням у Cassandra.

При значенні `Φ = 12` ймовірність становить `10⁻¹²`, що практично гарантує відсутність хибних спрацьовувань (одна помилка на десятки тисяч років) навіть в умовах нестабільного міжрегіонального зв'язку в хмарах.

## 5. Компроміс між часом виявлення та частотою помилок

Формальний зв'язок між частотою хибних спрацьовувань `λ_M` (кількість помилок детектора за одиницю часу) та часом виявлення аварії `T_D` виражається через обране порогове значення `Φ_th`:

```
λ_M ≈ (1 / μ) · 10^(-Φ_th)
```

```
T_D ≈ μ + σ · √2 · erf_inv(1 - 2 · 10^(-Φ_th))
```

де `erf_inv` — обернена функція помилок Гауса.

Зі зростанням `Φ_th` частота помилок `λ_M` спадає експоненційно, тоді як час виявлення `T_D` зростає сублінійно відносно середнього значення `μ` та стандартного відхилення `σ`.

Головна перевага ймовірнісного підходу полягає в динамічній самоадаптації: якщо в дата-центрі раптово зростає мережеве навантаження і стандартне відхилення затримок `σ` подвоюється, детектор автоматично розширює допустимий часовий інтервал очікування без будь-якої зміни конфігурації. Щойно навантаження спадає і дисперсія зменшується, часове вікно автоматично звужується, відновлюючи блискавичну реакцію на реальні збої серверів.
