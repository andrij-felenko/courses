# 🧮 Математична модель fan-out, динаміка буферів і ймовірність втрат у Pub/Sub

У системі публікації-підписки (Pub/Sub) одне вхідне повідомлення від видавця розмножується брокером на `M` незалежних підписників. Якщо видавець генерує події з інтенсивністю `λ` повідомлень за секунду, а підписники обробляють їх із різними швидкостями `μ₁`, `μ₂`, ..., `μ_M`, у системі виникає гетерогенна мережа черг. 

Ця модель формалізує баланс смуги пропускання мережі, швидкість наповнення буферів повільних споживачів, середній час очікування в черзі та точну ймовірність відкидання повідомлень за скінченного розміру пам'яті.

## 1. Множення смуги пропускання (Fan-Out Bandwidth Model)

Нехай видавець відправляє в тему повідомлення із середнім розміром `S` байтів з інтенсивністю `λ_in` повідомлень на секунду.

Вхідна швидкість передачі даних до брокера:

```
BW_in = λ_in · S       [вхідний потік байтів від видавця]
```

Якщо на тему підписано `M` активних підписників, брокер зобов'язаний здублювати кожне повідомлення `M` разів (або передати копію кожному сесійному сокету).

Вихідна швидкість передачі даних із брокера дорівнює:

```
BW_out = ∑_{i=1}^{M} λ_in · S
= M · λ_in · S         [множення трафіку: fan-out коефіцієнт M]
```

Коефіцієнт мультиплікації мережевого навантаження дорівнює:

```
K_fanout = BW_out / BW_in
= (M · λ_in · S) / (λ_in · S)     [підстановка виразів для BW_out та BW_in]
= M                               [смуга пропускання брокера масштабується лінійно від M]
```

Якщо фізичний мережевий інтерфейс брокера має граничну пропускну здатність `C` байт/с, максимальна частота публікації `λ_max`, яку здатна витримати система без утворення мережевої черги на рівні сокетів, обмежена величиною:

```
λ_max = C / (M · S)    [максимальна частота вхідних подій]
```

## 2. Динаміка черги повільного споживача

Розглянемо окремого підписника `i`, який має локальний буфер місткістю `K` повідомлень. Нехай вхідний потік повідомлень від брокера надходить зі швидкістю `λ(t)`, а споживач обробляє повідомлення зі швидкістю `μ_i(t)`.

Рівняння балансу довжини черги `Q_i(t)` у неперервному часі має вигляд:

```
dQ_i(t) / dt = λ(t) - μ_i(t),   за умови 0 < Q_i(t) < K
```

Розглянемо випадок стаціонарного перевантаження, коли швидкість надходження перевищує продуктивність споживача: `λ > μ_i`.

Час `T_overflow`, через який буфер місткістю `K` повідомлень буде вичерпано, визначається інтегруванням:

```
Q_i(T_overflow) - Q_i(0) = ∫₀^{T_overflow} (λ - μ_i) dt
K - 0 = (λ - μ_i) · T_overflow
T_overflow = K / (λ - μ_i)        [час до повного переповнення буфера]
```

**Числовий приклад:**
Нехай видавець транслює `λ = 10 000` msg/s, а повільний підписник через блокування в базі даних обробляє лише `μ_i = 200` msg/s. Розмір виділеного буфера `K = 50 000` повідомлень.

```
T_overflow = 50000 / (10000 - 200)
= 50000 / 9800                    [різниця швидкостей 10000 - 200]
≈ 5.102 секунди                   [через 5.1 с пам'ять буфера вичерпано]
```

Після моменту `t = T_overflow` будь-яка спроба записати повідомлення в буфер спричинить або скидання з'єднання (Drop), або блокування брокера (Backpressure).

## 3. Застосування закону Літтла до черги підписника

Закон Літтла (Little's Law) встановлює фундаментальний зв'язок між середньою кількістю повідомлень у системі `L`, ефективною швидкістю надходження `λ` та середнім часом перебування повідомлення в черзі `W`:

```
L = λ · W              [закон Літтла: середня довжина = інтенсивність · затримка]
```

Звідси середня затримка доставки повідомлення (latency) від моменту публікації до початку обробки споживачем становить:

```
W = L / λ              [середній час очікування в черзі]
```

Якщо буфер заповнений на `L = K` повідомлень при пропускній здатності споживача `μ`:

```
W_max = K / μ          [максимальне старіння повідомлення в черзі]
```

Якщо повідомлення має обмежений час життя (TTL, *Time-To-Live*), повідомлення стає неактуальним і марнує ресурси споживача, якщо:

```
W_max > TTL
K / μ > TTL
K > μ · TTL            [критична межа розміру буфера]
```

Буфер, розмір якого перевищує `μ · TTL`, є шкідливим: він накопичує завідомо застарілі дані, які споживач усе одно відкине після вичитування.

## 4. Марковська модель M/M/1/K: розрахунок імовірності втрат (Drop Probability)

Щоб оцінити роботу підписника в умовах стохастичного трафіку, змоделюємо чергу підписки як систему масового обслуговування типу `M/M/1/K`:
- Потік подій підпорядковується закону Пуассона з параметром `λ`.
- Час обробки розподілений експоненційно з параметром `μ`.
- Ємність черги разом із повідомленням на обробці обмежена числом `K`.
- Коефіцієнт завантаження системи: `ρ = λ / μ`.

### Виведення стаціонарних імовірностей станів

Нехай `P_n` — імовірність того, що в буфері підписника перебуває рівно `n` повідомлень (`0 ≤ n ≤ K`).

Запишемо рівняння глобального балансу для ланцюга Маркова:

```
λ · P₀ = μ · P₁                   [баланс для стану n = 0]
(λ + μ) · P_n = λ · P_{n-1} + μ · P_{n+1},  для 1 ≤ n ≤ K - 1
μ · P_K = λ · P_{K-1}             [баланс для стану n = K]
```

Виразимо `P_n` через `P₀` послідовною підстановкою:

```
P₁ = (λ / μ) · P₀ = ρ · P₀
P₂ = (λ / μ) · P₁ = ρ² · P₀
P_n = ρⁿ · P₀                     [вираз для n-го стану, 0 ≤ n ≤ K]
```

Застосуємо умову нормування імовірностей (сума всіх станів дорівнює 1):

```
∑_{n=0}^{K} P_n = 1
P₀ · ∑_{n=0}^{K} ρⁿ = 1           [сума геометричної прогресії]
```

Сума скінченної геометричної прогресії для `ρ ≠ 1`:

```
∑_{n=0}^{K} ρⁿ = (1 - ρ^{K+1}) / (1 - ρ)
```

Підставляємо суму в умову нормування та знаходимо `P₀`:

```
P₀ · (1 - ρ^{K+1}) / (1 - ρ) = 1
P₀ = (1 - ρ) / (1 - ρ^{K+1})      [імовірність порожнього буфера]
```

### Виведення ймовірності відкидання (Drop Probability)

Повідомлення відкидається (Drop) тоді й лише тоді, коли воно надходить у момент, коли буфер повністю заповнений, тобто система перебуває в стані `n = K`.

Отже, імовірність втрати повідомлення `P_drop` дорівнює `P_K`:

```
P_drop = P_K
= ρ^K · P₀                        [підстановка P_K = ρ^K · P₀]
= ρ^K · (1 - ρ) / (1 - ρ^{K+1})   [підстановка виразу для P₀]
= ((1 - ρ) · ρ^K) / (1 - ρ^{K+1}) [точна формула ймовірності втрат M/M/1/K]
```

Для випадку `ρ = 1` (інтенсивність надходження дорівнює швидкості обробки):

```
P_drop = 1 / (K + 1)              [імовірність втрат при критичному навантаженні]
```

## 5. Середня довжина черги та час очікування в буфері

Середня кількість повідомлень у системі `L` (у буфері та на обробці) обчислюється як математичне сподівання кількості зайнятих слотів:

```
L = ∑_{n=0}^{K} n · P_n
= P₀ · ∑_{n=0}^{K} n · ρⁿ         [підстановка виразу P_n = P₀ · ρⁿ]
```

Використовуючи формулу суми похідної геометричної прогресії:

```
∑_{n=0}^{K} n · ρⁿ = ρ · d/dρ [ (1 - ρ^{K+1}) / (1 - ρ) ]
= (ρ · (1 - (K + 1)·ρ^K + K·ρ^{K+1})) / (1 - ρ)²
```

Підставляючи вираз для `P₀`, отримуємо середню кількість повідомлень у системі `L`:

```
L = (ρ / (1 - ρ)) - ((K + 1) · ρ^{K+1}) / (1 - ρ^{K+1}) [середня довжина черги]
```

Оскільки частина вхідних повідомлень відкидається при заповненому буфері, **ефективна швидкість надходження** `λ_eff`, яка фактично потрапляє в буфер, дорівнює:

```
λ_eff = λ · (1 - P_drop)          [ефективний вхідний потік]
```

Застосовуючи закон Літтла до ефективного потоку, знаходимо **середній час перебування повідомлення в системі** `W`:

```
W = L / λ_eff
= L / (λ · (1 - P_drop))          [середній наскрізний час доставки]
```

Середня кількість повідомлень, які очікують виключно в черзі без урахування повідомлення на виконанні `L_q`:

```
L_q = L - (1 - P₀)                [віднімання зайнятості каналу обслуговування]
```

Середній час очікування безпосередньо в черзі до початку вичитування `W_q`:

```
W_q = L_q / λ_eff                 [середня затримка в буфері брокера]
```

## 6. Граничний аналіз: стійкість проти деградації

Проаналізуємо поведінку `P_drop` за різних значень коефіцієнта навантаження `ρ`:

### Сценарій 1: Стабільна підсистема (`ρ < 1`, тобто `λ < μ`)

Коли споживач у середньому швидший за вхідний потік, чисельник спадає експоненційно зі зростанням `K`:

```
lim_{K → ∞} P_drop
= lim_{K → ∞} ((1 - ρ) · ρ^K) / (1 - ρ^{K+1}) [підстановка формули P_drop]
= (1 - ρ) · 0 / (1 - 0)                       [оскільки ρ < 1, границя ρ^K при K → ∞ дорівнює 0]
= 0                                           [втрати зникають при зростанні буфера]
```

### Сценарій 2: Перевантажена підсистема (`ρ > 1`, тобто `λ > μ`)

Коли споживач хронічно відстає від видавця, перетворимо вираз, розділивши чисельник і знаменник на `ρ^{K+1}`:

```
P_drop = ((1 - ρ) · ρ^K) / (1 - ρ^{K+1})
= ((1 - ρ) / ρ) / (ρ^{-(K+1)} - 1)    [ділення чисельника і знаменника на ρ^{K+1}]
= (1 - 1/ρ) / (1 - ρ^{-(K+1)})        [спрощення: зміна знаків у чисельнику і знаменнику]
```

При зростанні `K → ∞` величина `ρ^{-(K+1)} → 0`, оскільки `ρ > 1`:

```
lim_{K → ∞} P_drop = 1 - 1/ρ
= 1 - μ / λ                       [підстановка ρ = λ / μ]
= (λ - μ) / λ                     [приведення до спільного знаменника]
```

**Фундаментальний висновок:**
Якщо споживач повільніший за видавця (`λ > μ`), **жоден скінченний розмір буфера `K` не здатен зупинити втрату даних**. Буфер лише відтерміновує момент настання аварії на час `T_overflow`, після чого рівно частка `(λ - μ) / λ` усіх подій буде відкинута брокером.

## 7. Розрахунок мінімального буфера для гарантування надійності (SLA)

Якщо система працює в допустимому діапазоні `ρ < 1`, але схильна до короткочасних сплесків трафіку, інженер повинен розрахувати розмір буфера `K`, який гарантує рівень втрат, менший за допустимий поріг `ε` (наприклад, `ε = 10⁻⁵` для SLA 99.999%):

```
P_drop ≤ ε
((1 - ρ) · ρ^K) / (1 - ρ^{K+1}) ≤ ε
```

Оскільки `ρ^{K+1} ≪ 1` для великих `K`, наближено маємо:

```
(1 - ρ) · ρ^K ≤ ε                 [наближення для малого ε]
ρ^K ≤ ε / (1 - ρ)
ln(ρ^K) ≤ ln(ε / (1 - ρ))
K · ln(ρ) ≤ ln(ε / (1 - ρ))
```

Оскільки `ρ < 1`, величина `ln(ρ)` є від'ємною, тому при діленні знак нерівності змінюється на протилежний:

```
K ≥ ln(ε / (1 - ρ)) / ln(ρ)       [формула розрахунку буфера під SLA]
```

**Практичний розрахунок:**
Нехай `λ = 800` msg/s, `μ = 1000` msg/s (`ρ = 0.8`), допустима частка втрат `ε = 10⁻⁴` (0.01%):

```
1 - ρ = 1 - 0.8 = 0.2
ε / (1 - ρ) = 0.0001 / 0.2 = 0.0005
ln(0.0005) ≈ -7.6009
ln(0.8) ≈ -0.2231
K ≥ (-7.6009) / (-0.2231)
K ≥ 34.07
```

**Висновок:** буфер місткістю всього у **35 повідомлень** достатній, щоб при завантаженні 80% гарантувати збереження 99.99% повідомлень в умовах випадкових пуассонівських сплесків надходження.

## 8. Оптимальний розподіл пам'яті брокера між кількома підписниками

Нехай брокер обслуговує `M` гетерогенних підписників з інтенсивностями надходження `λ_i`, швидкостями обробки `μ_i` та допустимими ймовірностями втрат `ε_i`. Загальний бюджет оперативної пам'яті брокера обмежений величиною `B` байтів, а розмір повідомлення становить `S` байтів.

Задача оптимізації формулюється як мінімізація сумарного ризику втрат за умови обмеження пам'яті:

```
Мінімізувати: ∑_{i=1}^{M} P_{drop, i}(K_i)
За умови: ∑_{i=1}^{M} K_i · S ≤ B
та K_i ≥ ln(ε_i / (1 - ρ_i)) / ln(ρ_i)   для всіх i = 1..M
```

Розв'язок методом множників Лагранжа показує, що розмір буфера `K_i` повинен виділятися пропорційно чутливості споживача до навантаження `1 / (1 - ρ_i)`: споживачам із високим коефіцієнтом утилізації `ρ_i → 1` необхідно виділяти експоненційно більшу частку пам'яті, ніж клієнтам із запасом продуктивності.
