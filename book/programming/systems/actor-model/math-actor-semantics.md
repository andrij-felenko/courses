# 🧮 Формальна операційна семантика моделі акторів

Математичний опис конкурентних систем тривалий час опирався строгій формалізації через недетермінізм та відсутність єдиного фізичного годинника. У моделі акторів стан обчислювальної системи описується не вектором значень спільних комірок пам'яті, а динамічною конфігурацією з ізольованих сутностей і повідомлень, що перебувають у процесі транзиту. Формальна операційна семантика, розроблена Карлом Г'юїттом, Генрі Бейкером та Ґулом Аґою, визначає систему як простір переходів між дискретними конфігураціями.

### 1. Простори та структури конфігурації

Нехай задано такі базові множини:
- `Адреси` (`Addresses`, або `PID`) — зліченна множина унікальних адрес акторів `a, b, c ∈ Addresses`.
- `Значення` (`Values`) — множина допустимих корисних даних.
- `Повідомлення` (`Messages`) — скінченні кортежі вигляду `⟨target, payload⟩`, де `target ∈ Addresses`, а `payload ∈ Values`.
- `Поведінки` (`Behaviors`) — множина функціональних відображень, що визначають реакцію актора на повідомлення.

Конфігурація системи `C` в довільний дискретний момент часу задається впорядкованою парою:

```
C = ⟨A, M⟩
```

де:
- `A: Addresses ⇀ Behaviors` — скінченне часткове відображення з множини адрес акторів у їхні поточні локальні поведінки.
- `M ∈ ℳ(Messages)` — мультимножина повідомлень, які вже відправлені, але ще не вилучені з поштових скриньок відповідними адресатами.

Мультимножина `M` моделює асинхронне середовище передачі: повідомлення не зникають, але порядок їхнього прибуття не фіксований жорстко глобальним часом.

### 2. Функція переходу поведінки та одиничний крок

Кожна поведінка `β ∈ Behaviors` є функцією, яка приймає вхідне повідомлення `m` і повертає трійку результатів згідно з трьома аксіомами Г'юїтта:

```
β(m) = ⟨β_next, M_out, A_new⟩
```

де:
- `β_next ∈ Behaviors` — нова поведінка (новий локальний стан), що замінює поточну поведінку для наступного вхідного повідомлення цього ж актора.
- `M_out ⊂ Messages` — скінченна множина нових повідомлень, породжених актором під час обробки `m`.
- `A_new ⊂ (Addresses × Behaviors)` — скінченна множина новостворених акторів із їхніми початковими адресами та поведінками.

Відношення переходу між глобальними конфігураціями `⟨A, M⟩ → ⟨A', M'⟩` відбувається шляхом споживання одного повідомлення `m = ⟨a, v⟩ ∈ M` актором за адресою `a ∈ dom(A)` з поточною поведінкою `β = A(a)`.

Оновлення множини акторів `A'` та мультимножини повідомлень `M'` розгортається поетапно за правилами теорії множин:

```
A' = (A \ {a ↦ β}) ∪ {a ↦ β_next} ∪ A_new    [оновлення стану та реєстрація нових акторів]
M' = (M \ {m}) ∪ M_out                         [вилучення спожитого m та додавання породжених M_out]
```

Таким чином, один крок системи локалізований: змінюється стан рівно одного актора `a`, видаляється рівно одне повідомлення `m`, а глобальний простір збагачується новими повідомленнями `M_out` та новими адресами `A_new`.

### 3. Структурні правила переходу (SOS)

Для строгої формалізації обчислень у стилі структурної операційної семантики Плоткіна (SOS) кожна з трьох базових операцій розглядається через локальне відношення редукції актора `⟨β, m⟩ ↪ ⟨β', M_out, A_new⟩`:

1. **Правило надсилання повідомлень (Send):**
   Якщо поточна поведінка `β` актора `a` під час виконання генерує повідомлення `⟨b, v⟩`, це повідомлення додається до мультимножини `M`:
```
m = ⟨a, v_in⟩ ∈ M,  A(a) = β,  β(m) = ⟨β', {⟨b, v_out⟩}, ∅⟩
───────────────────────────────────────────────────────────── [SEND]
⟨A, M⟩ → ⟨(A \ {a ↦ β}) ∪ {a ↦ β'}, (M \ {m}) ∪ {⟨b, v_out⟩}⟩
```

2. **Правило породження нового актора (Spawn):**
   Якщо поведінка `β` ініціює створення нового актора з поведінкою `β_child`, вибирається свіжа адреса `c ∉ dom(A)`:
```
m = ⟨a, v_in⟩ ∈ M,  A(a) = β,  β(m) = ⟨β', ∅, {⟨c, β_child⟩}⟩,  c ∉ dom(A)
──────────────────────────────────────────────────────────────────────────── [SPAWN]
⟨A, M⟩ → ⟨(A \ {a ↦ β}) ∪ {a ↦ β', c ↦ β_child}, M \ {m}⟩
```

3. **Правило зміни поведінки (Become):**
   Актор атомарно змінює свою функцію обробки для всіх наступних повідомлень без блокування інших вузлів системи:
```
m = ⟨a, v_in⟩ ∈ M,  A(a) = β,  β(m) = ⟨β_new, ∅, ∅⟩
──────────────────────────────────────────────────── [BECOME]
⟨A, M⟩ → ⟨(A \ {a ↦ β}) ∪ {a ↦ β_new}, M \ {m}⟩
```

### 4. Частковий порядок подій і причинність (Causal Ordering)

У системі акторів не існує глобального абсолютного часу. Замість нього справедливий частковий порядок причинно-наслідкових зв'язків (відношення `≺`), введений Леслі Лампортом:

1. **Локальний порядок актора:** Для будь-якого фіксованого актора `a` послідовність обробки ним повідомлень `m_1, m_2, m_3, ...` утворює строгий лінійний (повний) порядок:
```
e(a, m_1) ≺ e(a, m_2) ≺ e(a, m_3) ...
```
2. **Причинність передачі повідомлення:** Якщо подія `e_send` відправляє повідомлення `m`, а подія `e_recv` є моментом споживання цього повідомлення адресатом, то:
```
e_send ≺ e_recv
```
3. **Транзитивність:** Якщо `e_1 ≺ e_2` та `e_2 ≺ e_3`, то `e_1 ≺ e_3`.

Події `e_x` та `e_y`, між якими немає прямого чи транзитивного причинного ланцюжка (`e_x ⊀ e_y` і `e_y ⊀ e_x`), є строго конкурентними (*concurrent*). Це означає, що відношення переходу `→` може виконувати їх у довільному порядку без впливу на коректність інваріантів кожного окремого актора.

### 5. Справедливість планування (Fairness) та властивості живості

Рантайм моделі акторів задовольняє умові **слабкої справедливості доставки** (*message delivery fairness*): якщо повідомлення `m = ⟨a, v⟩` перебуває в мультимножині `M`, а актор `a` не завершив своє існування, то подія обробки `m` обов'язково настане через скінченну кількість кроків редукції конфігурації.

Формально це виключає нескінченне голодування (*starvation*):

```
∀ m ∈ M : (∃ k ∈ ℕ : C_0 → C_1 → ... → C_k ∧ m ∉ M_k)
```

Це математично гарантує властивість живості (*liveness*): якщо актор надіслав коректний запит, адресат з гарантованою справедливістю черги рано чи пізно його опрацює.

### 6. Необмежений недетермінізм (Unbounded Non-Determinism)

Фундаментальна математична відмінність моделі акторів від моделі CSP (Communicating Sequential Processes) Тоні Гоара та охоронюваних команд Едсгера Дейкстри полягає в типі недетермінізму.

У класичних моделях Дейкстри недетермінізм є **обмеженим** (*bounded non-determinism*): на кожному кроці вибір здійснюється серед скінченної кількості гілок. Як наслідок, якщо програма гарантовано завершується, множина її можливих кінцевих станів завжди скінченна.

У моделі акторів час доставки повідомлення каналом зв'язку є скінченним, але не обмеженим жодною наперед заданою константою `K`. Розгляньмо класичну задачу про конкурентний лічильник:
- Актор-клієнт надсилає лічильнику повідомлення `stop`.
- Одночасно актор-генератор надсилає нескінченний потік повідомлень `inc`.
- Лічильник збільшує значення на кожне `inc`, доки не отримає `stop`.

Обчислення фінального значення лічильника `N` після надходження `stop`:

```
N = k, де k ∈ {0, 1, 2, 3, 4, ...}
```

Оскільки повідомлення `stop` може прийти після довільної скінченної кількості повідомлень `inc`, множина можливих значень результату `N` є зліченно нескінченною (`ℕ₀`). Це властивість **необмеженого недетермінізму** (*unbounded non-determinism*). Вона доводить, що модель акторів строго потужніша за класичні автомати з обмеженим вибором і здатна моделювати відкриті розподілені системи без припущення про глобальну синхронізацію.

### 7. Математична відсутність дедлоків у чистій асинхронній моделі

Класичний стан взаємного блокування (дедлок за Кофманом) вимагає одночасного виконання чотирьох умов:
1. Взаємне виключення (Mutual Exclusion);
2. Утримання та очікування (Hold and Wait);
3. Відсутність витіснення (No Preemption);
4. Кругове очікування (Circular Wait).

У чистому асинхронному протоколі моделі акторів (патерн *tell* / `send`) умова 2 «утримання та очікування» не виконується математично. Оскільки операція `send(target, payload)` є миттєвою та неблокувальною, відправник ніколи не блокує свій потік виконання в очікуванні ресурсу або відповіді. Будь-який граф викликів між акторами є орієнтованим мультиграфом асинхронних подій без циклів блокування потоків виконання. Дедлок може виникнути лише при штучному порушенні базових аксіом — наприклад, при синхронному блокуванні на `ask` з нескінченним таймаутом у взаємно залежних акторах.
