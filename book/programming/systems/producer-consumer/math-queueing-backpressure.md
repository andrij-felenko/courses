# 🧮 Математика буферизації: закон Літтла, марковські черги M/M/1/K та ймовірність переповнення

Коли інженер проєктує буфер між виробником і споживачем, перше запитання завжди стосується розміру: скільки пам'яті виділити під чергу? Якщо виділити занадто мало комірок, навіть короткий сплеск вхідного потоку призведе до переповнення, втрати пакетів або блокування виробника. Якщо виділити занадто багато — система витрачатиме гігабайти оперативної пам'яті, а дані стоятимуть у черзі секундами, породжуючи руйнівні затримки (феномен *Bufferbloat*).

Теорія масового обслуговування дає точний математичний апарат, що пов'язує інтенсивність генерації задач, швидкість їх обробки, розмір буфера, середній час затримки та ймовірність втрати даних.

### Закон Літтла: фундаментальне співвідношення систем очікування

У 1961 році американський математик Джон Літтл (John D.C. Little) строгим математичним методом довів теорему, яка пов'язує три головні параметри будь-якої стаціонарної системи обслуговування, незалежно від розподілу ймовірностей вхідного потоку та дисципліни черги.

**Формулювання закону Літтла:**
Середня кількість задач у системі `L` дорівнює добутку середньої інтенсивності вхідного потоку `λ` на середній час перебування задачі в системі `W`:

```
L = λ · W
```

де:
- `L` — середня кількість елементів у черзі (або в черзі разом з обробником);
- `λ` — середня швидкість надходження нових елементів (кількість задач за одиницю часу, наприклад, пакетів/секунду);
- `W` — середній повний час перебування одного елемента в системі (затримка, латентність від моменту додавання до завершення обробки).

**Практичне застосування:**
Припустимо, що виробник генерує відеокадри зі швидкістю `λ = 1000` кадрів/секунду, а середня допустима затримка перебування кадру в буфері до початку аналізу становить `W = 15` мілісекунд (`0.015` с).

Розрахунок середньої заповненості буфера:

```
L = λ · W
  = 1000 · 0.015     [підстановка значень: 1000 кадрів/с на 0.015 с]
  = 15 кадрів        [результат: середній робочий обсяг буфера]
```

Закон Літтла показує жорстку пропорційність: якщо ми збільшимо буфер у 10 разів, щоб згладжувати більші сплески, при заповненій черзі середня затримка `W = L / λ` неминуче зросте в ті самі 10 разів.

### Марковська модель черги M/M/1: необмежений буфер

Для детального аналізу динаміки системи розглядають класичну марковську чергу `M/M/1`:
- Перша літера `M` (*Markovian / Memoryless*): пуассонівський потік вхідних задач з інтенсивністю `λ` (експоненційний розподіл інтервалів між надходженнями);
- Друга літера `M`: експоненційний розподіл часу обслуговування задач споживачем із середньою інтенсивністю `μ` (де `1/μ` — середній час обробки одного елемента);
- `1`: один обслуговуючий потік (один споживач).

Ключовим параметром системи є **коефіцієнт завантаження** (інтенсивність трафіку) `ρ`:

```
ρ = λ / μ
```

У стаціонарному стані для існування рівноваги необхідно, щоб `ρ < 1` (швидкість споживання `μ` строго перевищує швидкість надходження `λ`). Якщо `ρ ≥ 1`, довжина черги прямує до нескінченності.

Ймовірність того, що в системі перебуває рівно `n` елементів (`p_n`), визначається геометричним розподілом:

```
p_0 = 1 - ρ           [ймовірність того, що буфер повністю порожній]
p_n = (1 - ρ) · ρⁿ    [ймовірність наявності рівно n елементів у черзі]
```

Середня кількість елементів у черзі `L` та середній час очікування `W` для необмеженого буфера виводяться через суму нескінченного геометричного ряду:

```
L = ∑_{n=0}^∞ n · p_n
  = (1 - ρ) · ∑_{n=0}^∞ n · ρⁿ
  = (1 - ρ) · (ρ / (1 - ρ)²)   [диференціювання ряду геом. прогресії]
  = ρ / (1 - ρ)                [середня кількість елементів у системі]
```

```
W = L / λ
  = (ρ / (1 - ρ)) / λ          [застосування закону Літтла]
  = (λ / μ) / (λ · (1 - λ/μ))  [підстановка ρ = λ/μ]
  = 1 / (μ - λ)                [середній повний час очікування та обробки]
```

Звідси видно нелінійний стрибок затримки: коли завантаження `ρ` наближається до `1.0` (наприклад, `ρ = 0.95`), знаменник `1 - ρ = 0.05` прямує до нуля, а затримка та довжина черги вибухоподібно зростають у 20 разів.

### Модель M/M/1/K: обмежений буфер та ймовірність втрати даних

У реальних комп'ютерних системах пам'ять завжди обмежена. Розглянемо систему `M/M/1/K`, де максимальна місткість системи становить `K` елементів (1 елемент обробляється споживачем, а `K - 1` елементів очікують у буфері).

Якщо в момент надходження нового повідомлення в системі вже знаходиться `K` елементів, буфер вважається повністю переповненим. Залежно від обраної політики система або відкидає новий пакет (*Drop*), або примусово зупиняє (блокує) потік-виробник (*Backpressure*).

**Розподіл ймовірностей станів:**
Оскільки кількість станів скінченна (`0, 1, 2, ..., K`), сума всіх ймовірностей дорівнює одиниці: `∑_{n=0}^K p_n = 1`.

```
p_0 + p_0·ρ + p_0·ρ² + ... + p_0·ρᴷ = 1
p_0 · (1 - ρᴷ⁺¹) / (1 - ρ) = 1       [формула скінченної геометричної прогресії]
p_0 = (1 - ρ) / (1 - ρᴷ⁺¹)           [ймовірність порожнього стану при ρ ≠ 1]
```

Ймовірність перебування системи в довільному стані `k` (`0 ≤ k ≤ K`):

```
p_k = p_0 · ρᵏ
    = ((1 - ρ) · ρᵏ) / (1 - ρᴷ⁺¹)    [розподіл станів для обмеженого буфера]
```

Якщо `ρ = 1` (швидкість генерації точно дорівнює швидкості обробки), розподіл стає строго рівномірним:

```
p_k = 1 / (K + 1)                    [для всіх k від 0 до K при ρ = 1]
```

### Ймовірність переповнення буфера (Loss Probability)

Ймовірність втрати даних або блокування виробника `P_loss` — це ймовірність того, що новоприбулий елемент застане систему в стані `K` (буфер заповнений на 100%):

```
P_loss = p_K
       = ((1 - ρ) · ρᴷ) / (1 - ρᴷ⁺¹)
```

**Ефективна пропускна здатність системи (Throughput):**
Частина вхідного потоку втрачається через відкидання або блокування, тому реальна пропускна здатність `λ_eff` становить:

```
λ_eff = λ · (1 - P_loss)
```

### Практичний розрахунок розміру буфера

**Постановка задачі:**
Мережевий сервер приймає пакети телеметрії із середньою інтенсивністю `λ = 800` пакетів/с. Робочий потік-споживач здатний десеріалізувати та записувати в базу даних `μ = 1000` пакетів/с.
Необхідно розрахувати мінімальну місткість буфера `K`, щоб частка втрачених пакетів не перевищувала `0.1%` (`P_loss ≤ 0.001`).

**Крок 1. Обчислення коефіцієнта завантаження `ρ`:**

```
ρ = λ / μ            [формула завантаження: відношення інтенсивностей]
  = 800 / 1000       [підстановка значень: 800 та 1000 пакетів/с]
  = 0.8              [коефіцієнт навантаження черги]
```

**Крок 2. Складання рівняння для `P_loss`:**

```
P_loss = ((1 - ρ) · ρᴷ) / (1 - ρᴷ⁺¹) ≤ 0.001
```

Оскільки при `ρ < 1` та достатньо великому `K` знаменник `1 - ρᴷ⁺¹ ≈ 1`, отримуємо зручне аналітичне наближення:

```
(1 - ρ) · ρᴷ ≤ 0.001       [аналітичне наближення для P_loss]
(1 - 0.8) · 0.8ᴷ ≤ 0.001   [підстановка коефіцієнта ρ = 0.8]
0.2 · 0.8ᴷ ≤ 0.001         [спрощення: 1 - 0.8 = 0.2]
0.8ᴷ ≤ 0.001 / 0.2         [ділення обох частин на 0.2]
0.8ᴷ ≤ 0.005               [кінцевий степеневий вираз]
```

**Крок 3. Логарифмування обох частин нерівності:**

```
ln(0.8ᴷ) ≤ ln(0.005)       [взяття натурального логарифма]
K · ln(0.8) ≤ ln(0.005)    [винесення степеня K: ln(a^b) = b·ln(a)]
K ≥ ln(0.005) / ln(0.8)    [ділення на від'ємне число ln(0.8) змінює знак]
K ≥ (-5.2983) / (-0.2231)  [обчислення значень натуральних логарифмів]
K ≥ 23.75                  [числове значення порогу місткості]
```

**Висновок:**
Буфер місткістю `K = 24` елементи гарантує, що при навантаженні `80%` менше одного пакета з 1000 буде відкинуто через переповнення черги.

### Проблема Bufferbloat: плата за надлишковий буфер

Якщо інженер вирішить перестрахуватися і встановить буфер не на 24 елементи, а на 10 000 елементів, система отримає катастрофічний побічний ефект.

У моменти пікового сплеску навантаження (коли `λ` тимчасово перевищує `μ`), буфер на 10 000 елементів заповниться повністю. Розрахуємо час затримки чергового пакета за законом Літтла:

```
W = K / μ
  = 10000 / 1000     [10 000 пакетів у черзі при обробці 1000 пакетів/с]
  = 10 секунд        [затримка в черзі]
```

Затримка в 10 секунд для інтерактивного додатка чи мережевого сокета рівнозначна повній відмові системи (таймаут клієнта, розрив TCP-сесії). Клієнт вирішить, що пакет втрачено, надішле повторний дублікат, що ще більше посилить перевантаження буфера.

Математика показує, що правильне проєктування буфера — це завжди пошук строгого компромісу між імовірністю втрати даних `P_loss` та максимально допустимим часом очікування `W`.
