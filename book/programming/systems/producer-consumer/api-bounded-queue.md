# 📋 Специфікація інтерфейсу блокуючої черги та операцій синхронізації

Потокобезпечна обмежена черга (*Thread-Safe Bounded Blocking Queue*) є базовим програмним контрактом взаємодії між виробниками та споживачами. Вона інкапсулює циклічний буфер у спільній пам'яті, примітиви синхронізації та протокол безаварійного завершення роботи (*Graceful Shutdown*).

Цей довідник визначає публічний програмний інтерфейс (API), перед- та післяумови методів, гарантії виняткобезпеки, семантику бар'єрів пам'яті та системні таблиці відповідності для POSIX Threads і стандарту C++.

---

### Загальний контракт черги (Class Invariants)

Для будь-якої коректної реалізації `BoundedQueue<T>` у будь-який момент часу `t` гарантовано виконуються такі інваріанти:

1. **Інваріант місткості:** Кількість збережених елементів `count` завжди перебуває в межах `0 ≤ count ≤ capacity`. Спроба перевищити `capacity` або опуститися нижче нуля блокується на рівні синхронізації.
2. **Інваріант FIFO (First-In, First-Out):** Для будь-якої пари елементів `A` та `B`, доданих одним потоком-виробником у чергу, де `A` додано раніше за `B`, потік-споживач гарантовано вилучить `A` раніше за `B`.
3. **Інваріант блокування споживача:** Метод `pop()` ніколи не повертає значення з порожньої черги (`count == 0`), доки черга відкрита. Потік-споживач гарантовано переводиться в режим очікування без активного спалювання процесорних тактів.
4. **Інваріант блокування виробника:** Метод `push()` ніколи не перезаписує існуючі дані в заповненій черзі (`count == capacity`). Потік-виробник блокується до моменту звільнення хоча б однієї комірки споживачем.
5. **Інваріант закриття (Shutdown Invariant):** Після виклику `close()` операція `push()` гарантовано відхиляється, а операція `pop()` дозволяє вичитати всі залишкові елементи черги до стану `count == 0`, після чого повертає ознаку зупинки.

### Таблиця операцій синхронізованої черги

| Метод | Тип блокування | Дія при порожній черзі | Дія при повній черзі | Поведінка після `close()` |
| :--- | :--- | :--- | :--- | :--- |
| `push(item)` | Блокуючий | Додає елемент негайно | Засинає на `cv_not_full` | Повертає `false` або відхиляє запис |
| `try_push(item)` | Неблокуючий | Додає елемент | Повертає `false` негайно | Повертає `false` негайно |
| `push_for(item, t)` | З таймаутом | Додає елемент | Чекає до `t` мс на `cv_not_full` | Повертає `false` негайно |
| `pop()` | Блокуючий | Засинає на `cv_not_empty` | Вилучає елемент негайно | Повертає `nullopt` коли черга порожня |
| `try_pop()` | Неблокуючий | Повертає `nullopt` | Вилучає елемент | Повертає `nullopt` |
| `pop_for(t)` | З таймаутом | Чекає до `t` мс на `cv_not_empty` | Вилучає елемент | Повертає `nullopt` |
| `close()` | Неблокуючий | Переводить чергу в стан зупинки та будить усі сплячі потоки через `notify_all()` | — | Повторний виклик безпечний (ідемпотентний) |
| `size()` | Захищений | Повертає поточну кількість елементів | — | Повертає залишок елементів |
| `capacity()` | Константний | Повертає максимальну місткість буфера | — | Значення не змінюється |
| `is_closed()` | Неблокуючий | Повертає статус прапорця завершення | — | Повертає `true` |
| `is_empty()` | Захищений | Повертає `true`, якщо `size() == 0` | — | Дозволяє перевірити вичерпання |
| `is_full()` | Захищений | Повертає `true`, якщо `size() == capacity` | — | Дозволяє оцінити заповнення |

### Детальна специфікація методів

#### 1. `push(const T& item)` / `push(T&& item)`

```cpp
bool push(T item);
```

- **Призначення:** Додавання нового елемента в кінець черги з блокуванням при її повному заповненні.
- **Параметри:** `item` — значення або rvalue-посилання на об'єкт типу `T`.
- **Повертане значення:** `true` — елемент успішно додано в буфер; `false` — черга закрита (`is_closed() == true`), новий запис відхилено.
- **Передумови:** Тип `T` підтримує конструктор переміщення або копіювання, що не порушує інваріантів ресурсу.
- **Післяумови:** Кількість елементів `count` збільшується на 1, викликається сповіщення `cv_not_empty.notify_one()`.
- **Гарантія винятків:** Строга гарантія виняткобезпеки (Strong Exception Safety). Якщо конструктор переміщення типу `T` кидає виняток, внутрішній стан черги (індекси та лічильник) залишається повністю незмінним.
- **Бар'єри пам'яті:** Звільнення замка м'ютекса (Release sequence) гарантує повну видимість створеного об'єкта в оперативній пам'яті для будь-якого потоку-споживача, що захопить цей замок.

#### 2. `try_push(T item)`

```cpp
bool try_push(T item);
```

- **Призначення:** Спроба миттєвого додавання елемента без переходу в стан блокування потоку.
- **Повертане значення:** `true` — елемент успішно поміщено в буфер; `false` — черга повністю заповнена або закрита.
- **Часова складність:** `O(1)` без виклику системних функцій планувальника очікування.
- **Застосування:** Обробники подій реального часу, де затримка потоку є неприпустимою (наприклад, переривання або колбеки мережевого рушія).

#### 3. `push_for(T item, std::chrono::milliseconds timeout)`

```cpp
bool push_for(T item, std::chrono::milliseconds timeout);
```

- **Призначення:** Додавання елемента з обмеженим часом очікування звільнення місця в буфері.
- **Повертане значення:** `true` — елемент додано до завершення ліміту часу; `false` — час очікування вичерпано або чергу закрито.
- **Обробка таймауту:** Якщо за час `timeout` споживачі не вилучили жодного елемента, потік виходить зі стану сну, відпускає замок і повертає `false`, не модифікуючи буфер.

#### 4. `pop()`

```cpp
std::optional<T> pop();
```

- **Призначення:** Вилучення елемента з голови черги з блокуванням до моменту появи даних.
- **Повертане значення:** `std::optional<T>` з переміщеним об'єктом при успіху, або `std::nullopt`, якщо черга закрита і повністю вичерпана (`count == 0`).
- **Передумови:** Поточний потік має право блокуватися (не викликається з обробника апаратних переривань чи неблокувального циклу подій).
- **Післяумови:** Кількість елементів `count` зменшується на 1, викликається сповіщення `cv_not_full.notify_one()`.
- **Гарантія винятків:** Строга гарантія при вилученні та переміщенні об'єкта зі слота буфера.

#### 5. `try_pop()`

```cpp
std::optional<T> try_pop();
```

- **Призначення:** Миттєва перевірка наявності даних та їх вилучення без переходу в стан сну.
- **Повертане значення:** `std::optional<T>` з вилученим об'єктом, або `std::nullopt`, якщо черга на момент перевірки порожня.
- **Застосування:** Диспетчери задач, опитування кількох черг пріоритетів (*polling*), балансування навантаження між воркерами.

#### 6. `pop_for(std::chrono::milliseconds timeout)`

```cpp
std::optional<T> pop_for(std::chrono::milliseconds timeout);
```

- **Призначення:** Вилучення елемента з обмеженим часом очікування наявності даних.
- **Повертане значення:** `std::optional<T>` з даними, або `std::nullopt`, якщо за вказаний інтервал черга не отримала нових повідомлень.

#### 7. `close()`

```cpp
void close() noexcept;
```

- **Призначення:** Атомарне переведення черги в режим завершення роботи та пробудження всіх заблокованих потоків.
- **Післяумови:** Прапорець `is_closed` стає `true`. Викликаються широкомовні сигнали `cv_not_empty.notify_all()` та `cv_not_full.notify_all()`.
- **Властивість:** Метод є повністю ідемпотентним (повторні виклики безпечні) та маркований як `noexcept`.

### Системні примітиви: POSIX vs C++ Standard Library

| Механізм синхронізації | Реалізація POSIX Threads (C) | Стандартна бібліотека C++ (C++11/20) |
| :--- | :--- | :--- |
| **Взаємне виключення** | `pthread_mutex_t` + `pthread_mutex_lock()` / `unlock()` | `std::mutex` + `std::unique_lock<std::mutex>` (RAII) |
| **Очікування умови** | `pthread_cond_t` + `pthread_cond_wait()` | `std::condition_variable::wait(lock, predicate)` |
| **Очікування з таймаутом**| `pthread_cond_timedwait()` | `std::condition_variable::wait_for(lock, timeout, pred)`|
| **Сигналізація одному** | `pthread_cond_signal(&cond)` | `std::condition_variable::notify_one()` |
| **Широкомовний сигнал** | `pthread_cond_broadcast(&cond)` | `std::condition_variable::notify_all()` |
| **Лічильні семафори** | `sem_t` + `sem_wait()` / `sem_post()` (`<semaphore.h>`) | `std::counting_semaphore<N>` (`<semaphore>`, C++20) |
| **Неблокувальні атоміки**| `atomic_size_t` (`<stdatomic.h>`) | `std::atomic<size_t>` (`<atomic>`) |
| **Бар'єри пам'яті** | `atomic_thread_fence()` | `std::atomic_thread_fence(std::memory_order_...)` |

### Семантика моделі пам'яті та міжпотокова синхронізація

Для забезпечення коректності передачі даних між потоками без явних блокувань (lock-free) API спирається на стандартну модель пам'яті C++11 / C11:

1. **Відношення Синхронізації (Synchronizes-With Relationship):**
   Операція запису в атомарну змінну з прапорцем `std::memory_order_release` у потоці-виробнику синхронізується з операцією читання тієї самої змінної з прапорцем `std::memory_order_acquire` у потоці-споживачі.
2. **Гарантія Видимості (Visibility Guarantee):**
   Усі записи в неатомарні поля об'єкта, виконані до операції `release`, гарантовано стають видимими для потоку, що виконав `acquire`, усуваючи необхідність додаткових інструкцій очищення кешу.
3. **Усунення перевпорядкування компілятора:**
   Бар'єри пам'яті діють як апаратні та компіляторні межі, які забороняють оптимізатору переносити інструкції читання тіла пакета вище перевірки індексу готовності слота.

### Обробка винятків та безпека пам'яті

При роботі з довільними типами даних `T` черга забезпечує такі гарантії:

1. **Гарантія відсутності витоків (No-Leak Guarantee):**
   Якщо під час виконання `push(item)` конструктор переміщення елемента кидає виняток, пам'ять внутрішнього буфера не пошкоджується, а м'ютекс гарантовано звільняється через механізм RAII (`std::unique_lock`).
2. **Знищення залишкових об'єктів у деструкторі:**
   Під час виклику деструктора `~BoundedQueue()` черга автоматично викликає деструктори для всіх елементів, які залишилися невичитаними в діапазоні між `head` та `tail`.
3. **Заборона гонок на деструкторі:**
   Виклик деструктора черги, коли інші потоки все ще заблоковані у викликах `push()` або `pop()`, є невизначеною поведінкою (Undefined Behavior). Саме тому деструктор черги спочатку ініціює виклик `close()`, сповіщаючи всі залежні потоки про необхідність завершення операцій.

### Коди станів та обробка помилок

Для мов і бібліотек із явними кодами помилок (наприклад, C або низькорівневі драйвери вбудованих систем) визначається стандартизований перелік статусів черги:

```
enum class QueueStatus {
    Success = 0,    // Операцію додавання або вилучення виконано успішно
    Empty   = 1,    // Черга порожня (для неблокувального try_pop)
    Full    = 2,    // Черга переповнена (для неблокувального try_push)
    Closed  = 3,    // Черга закрита для запису або повністю вичерпана
    Timeout = 4     // Вичерпано встановлений ліміт часу очікування
};
```

Цей контракт гарантує повну сумісність між різними реалізаціями буферів (від блокуючих м'ютексних черг до lock-free кільцевих буферів).
