# 📋 Специфікація та контракти комбінаторів: Promise API

Програмний інтерфейс об'єкта `Promise` визначає контракти створення, зв'язування та конкурентної композиції асинхронних задач. Специфікація стандартизована стандартом ECMAScript (розділ 27.2) та гарантує сувору й детерміновану поведінку черги мікрозадач середовища виконання.

Розуміння точних контрактів кожного комбінатора дозволяє уникнути типових виробничих дефектів: зависання процесів через порожні масиви у перегонах задач, прихованих витоків пам'яті через підвішені з'єднання при достроковому відхиленні та втрати діагностичної інформації при групових збоях.

## Стани та фундаментальний життєвий цикл

Об'єкт `Promise` перебуває рівно в одному з трьох взаємовиключних станів:

| Стан | Опис | Доступні переходи | Гарантія незмінності |
| :--- | :--- | :--- | :--- |
| **`pending`** (очікування) | Початковий стан. Результат або помилка ще не визначені. | `→ fulfilled`<br>`→ rejected` | Може підписувати нові реакції в чергу. |
| **`fulfilled`** (виконано) | Операція завершилася успішно із зафіксованим значенням `value`. | Немає (кінцевий) | Значення незмінне; повторні виклики resolve/reject ігноруються. |
| **`rejected`** (відхилено) | Операція завершилася з помилкою із зафіксованою причиною `reason`. | Немає (кінцевий) | Причина незмінна; помилка транслюється в ланцюг обробників. |

Стани `fulfilled` та `rejected` разом називають **завершеними** (англ. *settled*).

Коли проміс переходить у стан завершення, він атомарно фіксує свій результат. Усі зареєстровані функції зворотного виклику (підписники) поміщаються в чергу мікрозадач і гарантовано виконуються у порядку їхньої реєстрації.

## Специфікація конкурентних комбінаторів

Стандарт надає чотири статичні методи для одночасного запуску множини асинхронних операцій з різними правилами агрегації результату.

```ts
type PromiseState<T> =
  | { status: "fulfilled"; value: T }
  | { status: "rejected"; reason: unknown };
```

### 1. `Promise.all<T>(iterable: Iterable<Promise<T> | T>): Promise<T[]>`
- **Контракт поведінки**: чекає на успішне завершення **всіх** вхідних промісів (стратегія *All-or-Nothing*).
- **Умова успіху**: виконується тоді, коли всі елементи колекції перейшли у стан `fulfilled`. Повертає масив значень у порядку, що строго відповідає вихідним позиціям елементів в ітераторі, незалежно від того, яка операція закінчилася раніше.
- **Умова відхилення**: негайно відхиляється (**short-circuit**) у момент збою **першого ж** проміса. Причиною відхилення вихідного проміса стає помилка `reason` цього першого невдалого елемента.
- **Побічний ефект і витік ресурсів**: якщо один із промісів упав, решта операцій у колекції **не скасовуються автоматично**. Вони продовжують виконуватися у фоні циклу подій, навантажуючи мережу та процесор, хоча їхній підсумковий результат буде проігнорований.
- **Крайовий випадок (порожній вхід)**: виклик `Promise.all([])` повертає вже вирішений проміс `Promise.resolve([])` синхронно.

### 2. `Promise.allSettled<T>(iterable: Iterable<Promise<T> | T>): Promise<PromiseState<T>[]>`
- **Контракт поведінки**: чекає на завершення **всіх** вхідних промісів без винятку, незалежно від того, чи завершилися вони успіхом, чи збоєм.
- **Умова успіху**: завжди завершується успішно, повертаючи масив об'єктів-дескрипторів стану. Для кожного елемента повертається об'єкт виду `{ status: "fulfilled", value: T }` у разі успіху або `{ status: "rejected", reason: unknown }` у разі збою.
- **Умова відхилення**: ніколи не відхиляється через помилки вхідних задач (відхилення можливе лише за умови збою самого ітератора або переповнення пам'яті).
- **Сфера застосування**: операції очищення ресурсів, фонове логування, надсилання пакетних повідомлень, де збій одного запиту не повинен переривати обробку інших.
- **Крайовий випадок (порожній вхід)**: повертає вирішений проміс із порожнім масивом `[]`.

### 3. `Promise.race<T>(iterable: Iterable<Promise<T> | T>): Promise<T>`
- **Контракт поведінки**: переймає стан того проміса, який завершився **першим** у часі (стратегія *First-to-Settle*).
- **Поведінка**: якщо найшвидший проміс завершився успіхом, вихідний проміс переходить у `fulfilled` з його значенням. Якщо найшвидший проміс завершився помилкою, вихідний проміс негайно переходить у `rejected` з цією помилкою.
- **Критична пастка (порожній вхід)**: виклик `Promise.race([])` створює проміс, який **назавжди зависає у стані `pending`**. Оскільки жоден елемент не може завершитися першим, цей проміс ніколи не викличе обробники, що може призвести до непомітного зависання всієї корутини викликача.
- **Сфера застосування**: встановлення часових обмежень (тайм-аутів) для мережевих операцій шляхом змагання цільового проміса з промісом таймера.

### 4. `Promise.any<T>(iterable: Iterable<Promise<T> | T>): Promise<T>`
- **Контракт поведінки**: шукає **перший успішний** результат серед переданих задач, ігноруючи поодинокі збої.
- **Умова успіху**: переходить у стан `fulfilled`, щойно бодай один вхідний проміс успішно завершився зі значенням.
- **Умова відхилення**: переходить у стан `rejected` лише тоді, коли **всі** вхідні проміси зазнали збою. Причиною відхилення стає стандартний об'єкт винятку `AggregateError`, поле `errors` якого містить масив усіх отриманих помилок у вихідному порядку задач.
- **Крайовий випадок (порожній вхід)**: виклик `Promise.any([])` негайно відхиляється з порожнім `AggregateError: All promises were rejected`.
- **Сфера застосування**: звернення до надлишкових дзеркал серверів або резервних баз даних (перша успішна відповідь використовується, а збої окремих вузлів ігноруються).

## Зведена порівняльна таблиця

| Метод | Стратегія завершення | Поведінка при першій помилці | Що повертає при успіху | Порожній вхід `[]` |
| :--- | :--- | :--- | :--- | :--- |
| **`Promise.all`** | Усі мають бути успішними | Негайний зрив (*fail-fast*) | Масив значень `[v1, v2, ...]` | `Promise.resolve([])` |
| **`Promise.allSettled`** | Чекає на всіх без винятку | Не зривається, збирає помилку | Масив дескрипторів стану | `Promise.resolve([])` |
| **`Promise.race`** | Перший завершений (успіх або збій) | Зривається, якщо перший — збій | Значення найшвидшого | Зависає в `pending` |
| **`Promise.any`** | Перший успішний | Ігнорує, доки є інші кандидати | Значення найпершого успішного | `reject(AggregateError)` |

## Допоміжні конструктори та фабрики

Сучасний стандарт надає додаткові фабричні методи для спрощення роботи з обіцянками:

- **`Promise.resolve(val)`**: повертає вирішений проміс. Якщо аргумент сам є Thenable/Promise, виконує його розпакування; якщо звичайне значення — загортає його в успішний стан.
- **`Promise.reject(reason)`**: повертає відхилений проміс із переданою причиною збою. На відміну від `resolve`, ніколи не розпаковує вкладені проміси.
- **`Promise.withResolvers<T>()`** (стандарт ECMAScript 2024): розв'язує давню проблему витягування керуючих функцій `resolve` та `reject` за межі конструктора. Повертає об'єкт кортежу `{ promise, resolve, reject }`, що спрощує інтеграцію зі старими подієвими API.

## Контракт кооперативного скасування (AbortController)

Оскільки стандартний проміс може мати довільну кількість незалежних підписників, прямий метод скасування `.cancel()` у ньому відсутній (один споживач не повинен ламати обчислення для іншого). Стандартним механізмом переривання є патерн **кооперативного скасування** на базі `AbortController`:

```ts
interface AbortSignal {
  readonly aborted: boolean;
  readonly reason: unknown;
  addEventListener(type: "abort", listener: (ev: Event) => void): void;
  removeEventListener(type: "abort", listener: (ev: Event) => void): void;
  throwIfAborted(): void;
}

interface AbortController {
  readonly signal: AbortSignal;
  abort(reason?: unknown): void;
}
```

### Правила побудови скасовуваної функції:
1. Функція приймає параметр `{ signal }: { signal?: AbortSignal }`.
2. Перед початком роботи викликається `signal?.throwIfAborted()`, щоб відхилити операцію, якщо сигнал уже був активований раніше.
3. Внутрішня асинхронна процедура реєструє слухача події `abort`, який зобов'язаний закрити мережеві сокети або файлові дескриптори.
4. Після завершення операції слухач події обов'язково видаляється через `removeEventListener`, щоб запобігти витоку пам'яті через замикання контролера.
5. У разі скасування проміс відхиляється стандартною помилкою `signal.reason` (за замовчуванням `DOMException("This operation was aborted", "AbortError")`).

## Гарантії черги мікрозадач (Microtask Queue)

1. **Асинхронність реакцій**: обробники, зареєстровані через `.then()`, `.catch()`, `.finally()`, **ніколи** не виконуються синхронно у поточному кадрі виклику, навіть якщо проміс уже давно перебуває у стані `fulfilled`. Вони завжди ставляться в чергу мікрозадач (Microtask / Job Queue).
2. **Пріоритет вичерпання**: цикл подій зобов'язаний повністю спустошити всю чергу мікрозадач (включно з мікрозадачами, породженими під час виконання інших мікрозадач) перед тим, як перейти до наступної макрозадачі (таймери `setTimeout`, операції вводу-виводу I/O, рендеринг кадру браузера).
3. **Діагностика неперехоплених помилок**: якщо проміс перейшов у стан `rejected`, і до моменту повного вичерпання поточної черги мікрозадач на нього не було встановлено жодного обробника відхилення, рушій генерує глобальну подію `unhandledrejection`. Це дозволяє централізовано фіксувати приховані збої та запобігати мовчанню помилок у фонових асинхронних процесах.
