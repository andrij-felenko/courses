# ⚙️ Стек Трайбера: реалізація LIFO-структури без блокувань

Стек Трайбера (англ. *Treiber stack*) — це класична конкурентна структура даних із дисципліною доступу LIFO (Last-In, First-Out), у якій операції додавання (`push`) та вилучення (`pop`) елементів реалізовані без використання системних м'ютексів або спінлоків. Усі операції синхронізуються через єдиний атомарний покажчик на вершину стека за допомогою неподільної інструкції Compare-And-Swap (CAS).

Алгоритм забезпечує властивість **Lock-Free**: якщо кілька потоків одночасно намагаються виконати операції над стеком, щонайменше один потік завжди гарантовано завершує свою дію за скінченну кількість кроків, незалежно від стану, затримок або витіснення інших потоків.

### Архітектура та принцип роботи алгоритму

Стек формується як однозв'язний список динамічно виділених вузлів. Кожен вузол містить корисне навантаження та покажчик `next` на попередній елемент. Єдиною спільною точкою доступу для всіх потоків є атомарна змінна `head`, яка вказує на поточну вершину стека (або містить `nullptr`, якщо стек порожній).

```
Вершина стека (head)
       │
       ▼
 ┌───────────┐      ┌───────────┐      ┌───────────┐
 │  Node C   │ ───► │  Node B   │ ───► │  Node A   │ ───► nullptr
 └───────────┘      └───────────┘      └───────────┘
```

1. **Покрокова механіка операції Push (Додавання):**
   - **Фаза 1 (Локальна підготовка):** Потік виділяє новий вузол у приватній пам'яті (`new_node = malloc(...)`) та ініціалізує його корисні дані. На цьому етапі вузол невидимий для інших ядер процесора, тому ніякої синхронізації не потрібно.
   - **Фаза 2 (Зчитування вершини):** Потік завантажує поточне значення `head` у локальну змінну `old_head`.
   - **Фаза 3 (Зв'язування):** Потік спрямовує внутрішній покажчик `new_node->next` на `old_head`.
   - **Фаза 4 (Атомарна публікація через CAS):** Потік намагається замінити `head` на `new_node` за умови, що `head` досі дорівнює `old_head`. Якщо інше ядро не втрутилося, CAS успішно змінює вершину. Якщо інше ядро встигло вставити свій вузол першим, `head` вже не дорівнює `old_head`: CAS повертає `false`, автоматично оновлює `old_head` новим значенням вершини, і потік повторює прив'язку `new_node->next = old_head` на наступній ітерації.

2. **Покрокова механіка операції Pop (Вилучення):**
   - **Фаза 1 (Читання вершини):** Потік зчитує `head` у локальну змінну `old_head`. Якщо `old_head == nullptr`, стек порожній, і операція негайно повертає ознаку відсутності даних.
   - **Фаза 2 (Підготовка нової вершини):** Потік зчитує покажчик `next_node = old_head->next`.
   - **Фаза 3 (Атомарне перемикання вершини):** Потік намагається змінити `head` з `old_head` на `next_node` за допомогою CAS. У разі успіху вузол вважається вилученим зі стека, і його дані повертаються викликачу. У разі невдачі (якщо інший потік встиг виконати `push` або `pop` раніше) потік повторює цикл зі свіжим значенням `head`.

### Реалізація алгоритму мовами C та C++

```c
#include <stdatomic.h>
#include <stdbool.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node* next;
} Node;

typedef struct {
    _Atomic(Node*) head;
} TreiberStack;

void stack_init(TreiberStack* stack) {
    atomic_init(&stack->head, NULL);
}

void stack_push(TreiberStack* stack, int value) {
    Node* new_node = (Node*)malloc(sizeof(Node));
    new_node->value = value;

    // Зчитуємо поточну вершину без накладання важких бар'єрів
    Node* old_head = atomic_load_explicit(&stack->head, memory_order_relaxed);

    // Оптимістичний цикл публікації
    do {
        new_node->next = old_head;
        // memory_order_release гарантує, що запис new_node->value та new_node->next
        // стане видимим для інших ядер до того, як оновиться покажчик head.
    } while (!atomic_compare_exchange_weak_explicit(
        &stack->head,
        &old_head,
        new_node,
        memory_order_release,
        memory_order_relaxed));
}

bool stack_pop(TreiberStack* stack, int* result) {
    // memory_order_acquire гарантує коректне отримання полів вузла
    Node* old_head = atomic_load_explicit(&stack->head, memory_order_acquire);

    while (old_head != NULL) {
        Node* next_node = old_head->next;

        if (atomic_compare_exchange_weak_explicit(
                &stack->head,
                &old_head,
                next_node,
                memory_order_acquire,
                memory_order_relaxed)) {
            *result = old_head->value;
            // УВАГА: прямий free(old_head) у конкурентному коді без системи безпечного
            // відкладеного звільнення (SMR) породжує проблему Use-After-Free та ABA.
            free(old_head);
            return true;
        }
    }
    return false; // Стек порожній
}
```
```cpp
#include <atomic>
#include <memory>
#include <optional>

template <typename T>
class TreiberStack {
public:
    TreiberStack() : head_(nullptr) {}

    ~TreiberStack() {
        // Послідовне очищення залишків стека при знищенні об'єкта
        Node* current = head_.load(std::memory_order_relaxed);
        while (current != nullptr) {
            Node* next = current->next;
            delete current;
            current = next;
        }
    }

    // Заборона копіювання для уникнення порушення цілісності покажчиків
    TreiberStack(const TreiberStack&) = delete;
    TreiberStack& operator=(const TreiberStack&) = delete;

    void push(T value) {
        auto* new_node = new Node(std::move(value));
        Node* old_head = head_.load(std::memory_order_relaxed);

        // Цикл оптимістичної спроби: прив'язуємо next і публікуємо через release
        while (!head_.compare_exchange_weak(
            old_head,
            new_node,
            std::memory_order_release,
            std::memory_order_relaxed)) {
            new_node->next = old_head;
        }
    }

    std::optional<T> pop() {
        Node* old_head = head_.load(std::memory_order_acquire);

        while (old_head != nullptr) {
            Node* next_node = old_head->next;

            if (head_.compare_exchange_weak(
                    old_head,
                    next_node,
                    std::memory_order_acquire,
                    std::memory_order_relaxed)) {
                T result = std::move(old_head->value);
                // У промислових lock-free структурах фізичне видалення вузла передається
                // підсистемі безпечного відкладеного звільнення пам'яті (Hazard Pointers / EBR).
                delete old_head;
                return result;
            }
        }
        return std::nullopt;
    }

private:
    struct Node {
        T value;
        Node* next{nullptr};
        explicit Node(T val) : value(std::move(val)) {}
    };

    std::atomic<Node*> head_;
};
```

### Пастки реалізації та тонкощі пам'яті

1. **Чому застосовується саме `compare_exchange_weak`?**
   На процесорах із розділеними інструкціями завантаження з резервуванням та умовного запису (ARM `LDREX`/`STREX`, RISC-V `lr`/`sc`) слабкий CAS може повертати хибний збій (spurious failure) через випадкові зовнішні події або перемикання контексту. Оскільки в алгоритмі Трайбера CAS у будь-якому разі обгорнутий у цикл `while`, використання `weak` дозволяє компілятору згенерувати пряму пару інструкцій без зайвих перевірок та внутрішніх переходів, що помітно знижує накладні витрати на конвеєрі.

2. **Моделі пам'яті: точний вибір Acquire і Release:**
   - **У функції Push:** Обов'язково використовується `memory_order_release`. Цей бар'єр гарантує, що ініціалізація даних `new_node->value` та зв'язування покажчика `new_node->next` будуть зафіксовані в когерентній пам'яті до того, як адреса `new_node` потрапить у глобальну змінну `head`. Без цього інше ядро могло б прочитати нову вершину і розіменувати `next`, коли пам'ять за покажчиком ще не встигла оновитися через спекулятивне перевпорядкування записів процесором.
   - **У функції Pop:** Використовується `memory_order_acquire`. Це гарантує, що наступні операції читання вмісту вузла `old_head->next` та `old_head->value` не будуть виконані спекулятивно до того, як потоку вдасться успішно зафіксувати володіння вершиною.

3. **Проблема ABA та безпечне звільнення пам'яті (SMR):**
   У наведеному навчальному прикладі виклик `free(old_head)` чи `delete old_head` виконується безпосередньо після успіху CAS. У реальному багатопотоковому коді це створює критичну вразливість:
   - Якщо потік 1 зупинився між рядками читання `old_head` та читанням `old_head->next`, а потік 2 тим часом видалив цей вузол і викликав `free`, потік 1 спробує розіменувати вже звільнену пам'ять (Use-After-Free).
   - Якщо алокатор повторно виділить ту саму адресу пам'яті під новий вузол, виникне класична аномалія ABA: CAS потоку 1 помилково вирішить, що стек не змінювався, і встановить вершину на пошкоджений покажчик.

### Розв'язання проблеми ABA через версіонування (Tagged Pointers)

Якщо в системі немає збирача сміття, найпростішим апаратним захистом від аномалії ABA є використання **тегованих покажчиків** (англ. *tagged pointers*) або подвійного CAS (Double-Word CAS, `cmpxchg16b` на x86-64 або `LDXP`/`STXP` на ARM64).

Замість одного 64-бітного покажчика вершина стека зберігається як 128-бітна структура з двох полів:
```
┌──────────────────────────────────────┬──────────────────────────────────────┐
│       Покажчик на вузол (ptr, 64 біти)│     Лічильник змін (tag, 64 біти)    │
└──────────────────────────────────────┴──────────────────────────────────────┘
```

Щоразу, коли потік виконує операцію `push` або `pop`, він не лише оновлює покажчик на вузол, але й монотонно збільшує числовий тег генерації (`tag + 1`).

Якщо потік 1 зчитав вершину `{ptr: 0x1000, tag: 42}` і був витіснений планувальником, а інші потоки встигли видалити вузол `0x1000`, звільнити його і знову виділити ту саму адресу під новий елемент, стан вершини набуде вигляду `{ptr: 0x1000, tag: 45}`.

Коли потік 1 прокинеться і спробує виконати 128-бітний CAS, операція порівняє обидва поля одночасно. Оскільки очікуваний тег `42` не збігається з актуальним тегом `45`, CAS надійно відхилить зміну, повністю унеможливлюючи пошкодження структури даних.
