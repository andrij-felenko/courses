# 📋 Атомарні примітиви CAS: контракт апаратури та компілятора

Примітив Compare-And-Swap (CAS, порівняння з обміном) — це фундаментальна неподільна інструкція мікропроцесора, на якій ґрунтується переважна більшість неблокувальних структур даних. Її призначення полягає в умовному оновленні значення в пам'яті: нове значення записується лише в тому разі, якщо поточний вміст комірки точно збігається з очікуваним зразком. Якщо ж інше процесорне ядро встигло змінити комірку раніше, операція відхиляє запис і повертає актуальне значення з пам'яті.

У сучасних стандартах C11 (заголовний файл `<stdatomic.h>`) та C++11/C++20 (заголовний файл `<atomic>`) операція CAS представлена двома основними функціями: слабкою (`compare_exchange_weak`) та сильною (`compare_exchange_strong`).

### Сигнатури інтерфейсів у C та C++

:::tabs
```c
#include <stdatomic.h>
#include <stdbool.h>

// Сильний варіант: успіх або гарантована невідповідність значення
bool atomic_compare_exchange_strong(
    volatile _Atomic(T)* object,
    T* expected,
    T desired
);

// Слабкий варіант: дозволяє хибні збої для оптимізації циклів
bool atomic_compare_exchange_weak(
    volatile _Atomic(T)* object,
    T* expected,
    T desired
);

// Варіанти з явним зазначенням моделей пам'яті для успіху та невдачі
bool atomic_compare_exchange_strong_explicit(
    volatile _Atomic(T)* object,
    T* expected,
    T desired,
    memory_order success_order,
    memory_order failure_order
);

bool atomic_compare_exchange_weak_explicit(
    volatile _Atomic(T)* object,
    T* expected,
    T desired,
    memory_order success_order,
    memory_order failure_order
);
```
```cpp
#include <atomic>

template <typename T>
class atomic {
public:
    // Сильний варіант CAS
    bool compare_exchange_strong(
        T& expected,
        T desired,
        std::memory_order success_order,
        std::memory_order failure_order
    ) noexcept;

    bool compare_exchange_strong(
        T& expected,
        T desired,
        std::memory_order order = std::memory_order_seq_cst
    ) noexcept;

    // Слабкий варіант CAS
    bool compare_exchange_weak(
        T& expected,
        T desired,
        std::memory_order success_order,
        std::memory_order failure_order
    ) noexcept;

    bool compare_exchange_weak(
        T& expected,
        T desired,
        std::memory_order order = std::memory_order_seq_cst
    ) noexcept;
};
```

### Поведінковий контракт та семантика параметрів

Принциповою особливістю сигнатури CAS є передача аргументу `expected` за вказівником (у мові C) або за неконстантною посиланням (у мові C++). Це зроблено для усунення зайвих операцій читання з пам'яті:

1. **Цільовий об'єкт (`object` або `this`):** Вказує на спільну атомарну комірку пам'яті. Звернення до неї завжди відбувається неподільно на рівні шини або кеш-контролера.
2. **Очікуване значення (`expected`):** Потік передає значення, яке він раніше прочитав зі спільної комірки. Якщо значення в пам'яті дорівнює `*expected`, виконується запис `desired`. Якщо ж значення в пам'яті відрізняється, апаратний блок CAS автоматично перезаписує змінну `*expected` фактичним значенням, що наразі перебуває в пам'яті. Завдяки цьому програмісту не потрібно робити окремий виклик `load` перед наступною ітерацією циклу.
3. **Бажане значення (`desired`):** Значення, яке потік намагається записати у разі збігу.
4. **Результат виконання (булевий прапорець):**
   - Повернення `true` гарантує, що значення в пам'яті збіглося, запис `desired` виконано неподільно, а всі побічні ефекти пам'яті впорядковані відповідно до моделі `success_order`.
   - Повернення `false` означає, що запис **не відбувся**. При цьому `expected` оновлюється поточним вмістом пам'яті, а операція впорядковується згідно з моделлю `failure_order`.

### Обмеження моделей пам'яті для успіху та невдачі

Стандарт C та C++ вимагає чіткого розмежування бар'єрів пам'яті для гілки успіху та гілки невдачі. Неправильний вибір моделей є поширеною причиною помилок компіляції або тонких порушень когерентності:

- **Заборона моделей запису для невдачі:** У разі повернення `false` процесор не змінює спільну пам'ять, а лише зчитує її. Тому для `failure_order` категорично заборонено використовувати семантику звільнення — `memory_order_release` або `memory_order_acq_rel`. Компілятор відхилить такий виклик під час перевірки типів. Дозволеними є виключно моделі читання: `memory_order_relaxed`, `memory_order_consume`, `memory_order_acquire` або `memory_order_seq_cst`.
- **Правило монотонності сили бар'єрів:** Модель невдачі `failure_order` не може бути суворішою (сильнішою) за модель успіху `success_order`. Наприклад, заборонено призначати успіху `memory_order_relaxed`, а невдачі — `memory_order_acquire`.
- **Типові робочі комбінації:**
  - `success = memory_order_release`, `failure = memory_order_relaxed`: класичний вибір для операцій типу `push`, де потік публікує сформовані дані у разі успіху, а в разі невдачі лише перезавантажує покажчик без накладання бар'єрів.
  - `success = memory_order_acq_rel`, `failure = memory_order_acquire`: стандартний вибір для операцій типу `pop`, де успіх вимагає і отримання актуального стану вузла (`acquire`), і безпечного оновлення вершини (`release`), а невдача вимагає коректного прочитання нової вершини (`acquire`).

### Різниця між Weak та Strong: апаратне підґрунтя

Головна відмінність між `compare_exchange_weak` та `compare_exchange_strong` криється у ставленні до так званих **хибних збоїв** (англ. *spurious failure*).

Хибний збій — це ситуація, за якої значення в пам'яті реально дорівнювало `*expected`, але операція CAS все одно повернула `false` і не виконала запис. Причиною такого явища є особливості мікроархітектури різних сімейств процесорів:

1. **Архітектури Load-Linked / Store-Conditional (ARM, RISC-V, MIPS, PowerPC):**
   На цих процесорах немає єдиної монолітної інструкції CAS. Натомість операція розбивається на дві фази:
   - Інструкція `LDREX` (або `lr.w` у RISC-V) завантажує значення і встановлює внутрішній апаратний монітор ексклюзивного доступу (Exclusive Monitor) для даної кеш-лінії.
   - Інструкція `STREX` (або `sc.w` у RISC-V) намагається записати нове значення. Вона завершується успіхом лише в тому разі, якщо монітор ексклюзивності не був скинутий.
   Якщо між завантаженням і збереженням відбулося апаратне переривання, перемикання контексту операційної системи або сусіднє ядро надіслало запит когерентності до того самого блока пам'яті, монітор скидається. В результаті `STREX` повертає помилку, навіть якщо саме число в пам'яті не змінилося.
   - У `compare_exchange_weak` компілятор транслює виклик у пряму пару `LDREX`/`STREX` без додаткових перевірок.
   - У `compare_exchange_strong` компілятор генерує навколо `STREX` внутрішній короткий цикл повтору: якщо сталася втрата монітора, код перечитує комірку і повторює спробу, повертаючи `false` лише тоді, коли значення в пам'яті дійсно змінилося.

2. **Архітектура x86 / x86-64:**
   Процесори сімейства x86 підтримують монолітну апаратну інструкцію `LOCK CMPXCHG`. Ця інструкція на рівні апаратного контролера кеша захоплює кеш-лінію в стан Modified/Exclusive на час виконання і ніколи не зазнає хибних збоїв. Тому на x86 слабкий `weak` і сильний `strong` варіанти генерують абсолютно однаковий машинний код.

### Практичне правило вибору між Weak та Strong

- **Обирайте `compare_exchange_weak`, якщо CAS виконується всередині циклу `while` або `do-while`:**
  Оскільки в разі конфлікту цикл все одно піде на наступне коло, випадковий хибний збій на архітектурі ARM ніяк не порушить логіку програми, але дозволить уникнути накладних витрат на внутрішні мікроцикли та перевірки всередині сильного CAS.
- **Обирайте `compare_exchange_strong`, якщо CAS викликається один раз без циклу:**
  Якщо програма після невдачі не повторює спробу, а ухвалює альтернативне логічне рішення (наприклад, повертає помилку або переходить до іншої гілки алгоритму), хибний збій неприпустимий, і використання `strong` є обов'язковим.

### Пастка байтів вирівнювання (Padding Bytes)

При використанні атомарних структур користувача (`std::atomic<MyStruct>`) апаратний CAS зазвичай порівнює байти пам'яті побітово (як функція `memcmp`). Якщо структура містить невикористані байти вирівнювання (англ. *padding bytes*), значення цих байтів може бути невизначеним.

У такому випадку два екземпляри структури з абсолютно однаковими значеннями полів матимуть різні значення в байтах вирівнювання. Операція CAS зазнаватиме постійних невдач, оскільки побітове порівняння не сходитиметься. Для запобігання цій пастці структури, призначені для використання в CAS, необхідно попередньо ініціалізувати за допомогою `std::memset` або проектувати без проміжків у вирівнюванні полів.
