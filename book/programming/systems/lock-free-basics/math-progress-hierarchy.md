# 🧮 Ієрархія поступу: формальні моделі та консенсусні числа

У теорії паралельних систем математичні властивості алгоритмів без блокувань спираються на строгу класифікацію гарантій поступу (англ. *progress conditions*), закладену в роботах Моріса Герліхі та Ніра Шавіта. Ця класифікація формально визначає, яку поведінку демонструє обчислювальна система, коли окремі потоки раптово сповільнюються, витісняються планувальником операційної системи або аварійно завершують виконання.

### Формальні означення рівнів поступу

Нехай обчислювальна система складається з фіксованої або змінної множини `N` паралельних потоків `T = {t₁, t₂, ..., tₙ}`, що одночасно виконують скінченну послідовність атомарних інструкцій над спільною структурою даних.

Кожна операція над структурою (наприклад, додавання елемента або його вилучення) складається з послідовності кроків, де крок — це виконання однієї машинної інструкції доступу до пам'яті.

```
Класифікація гарантій неблокувального поступу:

┌─────────────────────────────────────────────────────────────┐
│ 1. Obstruction-Free (Без перешкод)                          │
│    Гарантія: Окремий потік tᵢ завершує дію за скінченний    │
│    час, якщо всі інші потоки tⱼ (j ≠ i) призупинено.        │
└─────────────────────────────────────────────────────────────┘
                              ▲
                              │ посилення гарантії
┌─────────────────────────────────────────────────────────────┐
│ 2. Lock-Free (Без блокувань)                                │
│    Гарантія: Уся система гарантовано завершує щонайменше    │
│    одну операцію за скінченну кількість сумарних кроків K.  │
│    (Окремі потоки можуть зазнавати голодування).            │
└─────────────────────────────────────────────────────────────┘
                              ▲
                              │ посилення гарантії
┌─────────────────────────────────────────────────────────────┐
│ 3. Wait-Free (Без очікування)                               │
│    Гарантія: КОЖЕН потік tᵢ гарантовано завершує свою дію   │
│    за обмежену зверху кількість кроків B(N), незалежно від  │
│    дій, затримок та швидкості решти потоків.                │
└─────────────────────────────────────────────────────────────┘
```

1. **Obstruction-Free (Відсутність перешкод):**
   Це найслабша з неблокувальних гарантій. Вона вимагає, щоб будь-який потік `tᵢ`, отримавши монопольний доступ до процесорного часу на певний інтервал `Δt` (тобто якщо всі конкуруючі потоки тимчасово зупинені або витіснені планувальником), гарантовано завершив свою операцію за скінченну кількість власних кроків.
   - *Вразливість:* Якщо два або більше потоків виконуються одночасно і змінюють спільні ресурси у протифазі, вони можуть нескінченно заважати один одному. Такий стан називається «живим замком» (англ. *livelock*). Алгоритм не блокується операційною системою, але й корисного поступу не відбувається.

2. **Lock-Free (Системний поступ без блокувань):**
   Алгоритм називається Lock-Free, якщо в будь-який момент часу виконання нескінченної кількості кроків системою гарантує успішне завершення нескінченної кількості операцій.
   - *Математичний зміст:* Якщо `N` потоків одночасно змагаються за оновлення структури через інструкцію Compare-And-Swap (CAS), рівно один потік гарантовано виграє конкуренцію і фіксує свій результат, тоді як решта `N - 1` потоків зазнають невдачі і переходять на наступну ітерацію. Окремий невдалий потік теоретично може голодувати (англ. *starvation*), постійно програючи конкурентам, але вся система як єдине ціле ніколи не зупиняється. Загибель або зависання будь-яких `N - 1` потоків не здатні зупинити останній потік, що залишився.

3. **Wait-Free (Індивідуальний поступ без голодування):**
   Найсильніша неблокувальна гарантія. Алгоритм є Wait-Free, якщо існує детермінована функція межі `B(N)`, така що кожен окремий потік `tᵢ` гарантовано завершує свою операцію максимум за `B(N)` власних кроків, незалежно від поведінки, швидкості чи зупинки решти потоків у системі.
   - *Population-Oblivious Wait-Free:* межа `B` є абсолютною константою `O(1)` і не залежить від кількості потоків `N` (приклад: кільцевий буфер SPSC, де потік виконує фіксовану кількість читань та записів).
   - *Bounded Wait-Free:* межа залежить від розміру популяції потоків `B = O(N)` (приклад: черги з кооперативною допомогою, де активний потік спочатку допомагає завершити дію іншим зареєстрованим потокам, обмежуючи максимальну затримку кількістю учасників).

### Теорема про консенсусні числа (Ієрархія Герліхі, 1991)

Для строгого вимірювання сили синхронізаційних примітивів Моріс Герліхі сформулював задачу консенсусу для `N` паралельних процесів.

**Формалізація задачі консенсусу:**
Нехай кожен із `N` потоків починає роботу з власним приватним вхідним значенням `vᵢ ∈ {0, 1}`. Потоки спілкуються через спільні об'єкти пам'яті і повинні ухвалити спільне рішення `v*`:
1. **Узгодженість (Agreement):** Усі потоки, що завершили протокол, отримують однакове значення `v*`.
2. **Валідність (Validity):** Рішення `v*` зобов'язане належати множині запропонованих початкових значень (`v* ∈ {v₁, ..., vₙ}`).
3. **Завершуваність (Wait-Freedom):** Кожен коректний потік ухвалює рішення за скінченну кількість власних кроків.

**Означення консенсусного числа:** Консенсусним числом атомарного примітиву `P` (позначається `CN(P)`) називається максимальна кількість потоків `N`, для яких за допомогою примітиву `P` та звичайних комірок атомарного читання/запису (Read/Write) можна побудувати протокол консенсусу, що задовольняє вимогу Wait-Freedom. Якщо примітив може розв'язати задачу для довільного числа потоків, його консенсусне число дорівнює нескінченності (`CN(P) = ∞`).

```
Доведення CN(Read/Write) = 1 (Неможливість консенсусу для двох потоків):

1. Припустимо, що існує wait-free протокол для N = 2 на базі атомарних регістрів Read/Write.
2. Простір станів протоколу містить бівалентні стани (стани, з яких залежно від планувальника 
   можливий вихід як у значення 0, так і в значення 1).
3. Оскільки протокол wait-free і завершується за скінченну кількість кроків, дерево станів містить 
   критичний бівалентний стан S, з якого будь-який наступний крок потоку t₀ переводить систему 
   в 0-валентний стан, а крок потоку t₁ — в 1-валентний стан.
4. Нехай наступна дія потоку t₀ — це дія a₀ над коміркою M, а дія потоку t₁ — це a₁ над коміркою M':
   - Випадок A: M ≠ M' (звернення до різних комірок). Виконання послідовності a₀a₁ переводить 
     систему в стан S₀₁, а послідовність a₁a₀ — у стан S₁₀. Але стани S₀₁ та S₁₀ є повністю 
     ідентичними для обох потоків, оскільки дії над різними адресами комутують. Виникає суперечність.
   - Випадок B: M = M', і обидві дії є записами (Write). Дія a₁ повністю затирає результат a₀, 
     роблячи крок t₀ невидимим для наступних спостерігачів, що унеможливлює узгодження.
   - Випадок C: M = M', одна дія — Read, інша — Write. Потік, що виконує читання, не змінює стан 
     комірки для сусіда.
5. Суперечність доводить, що CN(Atomic Read/Write) = 1. Без сильніших примітивів неможливо 
   синхронізувати навіть два ядра без блокувань.
```

```
Доведення CN(Compare-And-Swap) = ∞ (Універсальність CAS):

1. Спільна пам'ять містить змінну C, ініціалізовану спеціальним нейтральним значенням EMPTY.
2. Алгоритм консенсусу для довільного числа N потоків:
   Кожен потік tᵢ виконує:
     CAS(&C, expected = EMPTY, desired = vᵢ)
3. Оскільки апаратний CAS виконується неподільно, рівно один перший потік успішно замінить EMPTY на своє vᵢ.
4. Усі інші потоки отримають відмову (false) і прочитають із C значення переможця.
5. Усі потоки гарантовано отримують однакове значення за O(1) кроків.
6. Висновок: CN(CAS) = ∞. За допомогою CAS можна побудувати wait-free версію будь-якої структури даних.
```

### Імовірнісна модель навантаження на цикл CAS

Розглянемо аналітичну модель поведінки `N` конкуруючих ядер, які одночасно намагаються модифікувати спільну вершину неблокувального стека за допомогою класичного оптимістичного циклу.

Нехай кожен потік виконує локальні обчислення тривалістю `τ_local` та генерує запити на оновлення вершини. Тривалість апаратної транзакції інструкції CAS на спільній шині процесора дорівнює `τ_cas`.

Якщо `N` потоків одночасно надсилають запити на виконання CAS до однієї кеш-лінії, апаратний арбітр шини або протокол когерентності (MESI) випадковим чином задовольняє запит рівно одного ядра, надаючи йому ексклюзивний статус Exclusive/Modified.

```
Ймовірність успіху для окремого потоку з однієї спроби:
P_success = 1 / N

Розподіл кількості спроб k до першого успіху підпорядковується геометричному розподілу:
P(k = m) = (1 - P_success)ᵐ⁻¹ · P_success = (1 - 1/N)ᵐ⁻¹ · (1/N)

Математичне сподівання кількості ітерацій E[k] для одного потоку:
E[k] = 1 / P_success = N

Сумарна кількість конфліктних звернень до шини на одну корисну операцію:
Total_Bus_Attempts = N · E[k] = N²
```

Ця квадратична залежність `O(N²)` пояснює, чому за великої кількості ядер (від 16 до 64) прості цикли CAS зазнають різкої деградації продуктивності. Кожна невдала спроба CAS супроводжується інвалідацією рядка кеша в L1/L2-кешах усіх інших ядер, породжуючи шторм транзакцій на між'ядерній магістралі (англ. *cacheline bouncing*).

Для стабілізації алгоритмів за високої конкуренції в математичну модель вводять адаптивну паузу (Backoff), яка перетворює детерміноване зіткнення на розріджений пуассонівський потік запитів:

```
T_pause(attempt) = T_base · 2ᵐⁱⁿ⁽ᵃᵗᵗᵉᵐᵖᵗ' ᵃᵗᵗᵉᵐᵖᵗ_ᵐᵃˣ⁾ · Uniform(0, 1)
```

Застосування експоненційної рандомізованої паузи знижує середню інтенсивність конфліктів на шині до лінійного рівня `O(N)`, повертаючи системі стабільну пропускну здатність.
