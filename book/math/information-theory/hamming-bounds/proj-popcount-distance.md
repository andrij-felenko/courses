# ⚙️ Відстань і вага через XOR і popcount

Уся арифметика [відстані Геммінга](topic:math/hamming-bounds) зводиться до двох дій: накласти XOR на два слова й порахувати в результаті одиниці. Перша — одна машинна команда. Друга, **підрахунок одиниць** (*population count*, скорочено popcount), на вигляд дрібниця, але саме від неї залежить, чи рахуватиме прошивка відстані за такт, чи буде топтатися в циклі по бітах. Різниця між цими двома варіантами — десятки разів за швидкістю на тому самому ядрі, тож попри простоту задачі спосіб її розв'язати має значення. Розберімо, як це писати в C правильно: від наївного циклу до апаратної команди, яку процесор виконує за один-два такти.

## Задача

У прошивці постійно треба те саме: знайти **вагу** слова `w(x)` (скільки в ньому одиниць) і **відстань** між двома словами `d(a, b)` (у скількох розрядах вони різні). Відстань через вагу виражається миттєво — `d(a, b) = w(a ⊕ b)`, бо XOR запалює одиниці точно там, де біти не збігаються. Тож уся робота — у швидкому й коректному popcount; відстань стає одним рядком поверх нього, і окремо її писати не треба.

Де це треба насправді: декодер шукає **найближче** кодове слово, а «найближче» — це найменша вага різниці; перевірка [синдрому](topic:communications/hamming-code) лічить, скільки контрольних рівнянь порушено; діагностика лінії рахує, скільки бітів псується за одиницю часу (це й є частота бітових помилок). Усюди в основі — порахувати одиниці, і часто на гарячому шляху, де кожне прийняте слово проганяється крізь цей підрахунок по багато разів на секунду. Тому варто один раз розібратися, як це робити швидко, і далі скрізь спиратися на готову функцію.

## Ідея: відстань = вага XOR

Найпряміший popcount — пройти всі біти й додати молодший:

:::tabs
```c
// Наївний підрахунок: дивимося кожен біт по черзі.
int popcount_naive(uint32_t x) {
    int n = 0;
    while (x) {
        n += x & 1u;     // додати молодший біт
        x >>= 1;          // зсунути наступний на його місце
    }
    return n;
}
```
```cpp
// Наївний підрахунок: дивимося кожен біт по черзі.
int popcount_naive(uint32_t x) {
    int n = 0;
    while (x) {
        n += x & 1u;     // додати молодший біт
        x >>= 1;          // зсунути наступний на його місце
    }
    return n;
}
```
```python
def popcount_naive(x: int) -> int:
    """Наївний підрахунок: дивимося кожен біт по черзі."""
    n = 0
    while x:
        n += x & 1        # додати молодший біт
        x >>= 1           # зсунути наступний на його місце
    return n
```
:::

Він правильний, але робить стільки кроків, скільки в слові розрядів — 32 ітерації навіть для майже нульового числа. Краще зробити стільки кроків, скільки **одиниць**, а не скільки бітів. Це дає класичний **трюк Кернігана**: вираз `x & (x − 1)` гасить найнижчу встановлену одиницю, лишаючи решту слова незмінним. Скільки разів устигнемо так зробити, доки слово не обнулиться, — стільки в ньому й було одиниць.

:::tabs
```c
// Трюк Кернігана: кожен прохід циклу прибирає рівно одну одиницю.
int popcount_kernighan(uint32_t x) {
    int n = 0;
    while (x) {
        x &= x - 1;       // згасити найнижчу встановлену одиницю
        n++;
    }
    return n;
}
```
```cpp
// Трюк Кернігана: кожен прохід циклу прибирає рівно одну одиницю.
int popcount_kernighan(uint32_t x) {
    int n = 0;
    while (x) {
        x &= x - 1;       // згасити найнижчу встановлену одиницю
        n++;
    }
    return n;
}
```
```python
def popcount_kernighan(x: int) -> int:
    """Трюк Кернігана: кожен прохід циклу прибирає рівно одну одиницю."""
    n = 0
    while x:
        x &= x - 1        # згасити найнижчу встановлену одиницю
        n += 1
    return n
```
:::

Чому `x & (x − 1)` стирає саме найнижчу одиницю? Віднімання одиниці перевертає найнижчий встановлений біт на 0, а всі нулі під ним — на 1; AND із початковим словом лишає старші біти як були, а цю групу обнуляє. На розрідженому слові (одна-дві одиниці) це блискавично: для слова з трьома одиницями — рівно три проходи замість тридцяти двох.

А тепер відстань — просто вага XOR, тож вона коштує рівно один popcount:

:::tabs
```c
// Відстань Геммінга між двома словами.
int hamming_distance(uint32_t a, uint32_t b) {
    return popcount_kernighan(a ^ b);   // d(a,b) = w(a ⊕ b)
}
```
```cpp
// Відстань Геммінга між двома словами.
int hamming_distance(uint32_t a, uint32_t b) {
    return popcount_kernighan(a ^ b);   // d(a,b) = w(a ⊕ b)
}
```
```python
def hamming_distance(a: int, b: int) -> int:
    """Відстань Геммінга між двома словами."""
    return popcount_kernighan(a ^ b)    # d(a,b) = w(a ⊕ b)
```
:::

Щоб трюк перестав бути магією, прокрутімо його на одному байті `x = 0b01011000` (три одиниці). Кожен рядок — один прохід циклу `x &= x − 1`:

```
крок 0:  x = 0101 1000              (три одиниці)
крок 1:  x − 1 = 0101 0111
         x & (x−1) = 0101 0000      ← згасла найнижча одиниця, n = 1
крок 2:  x − 1 = 0100 1111
         x & (x−1) = 0100 0000      ← згасла наступна,        n = 2
крок 3:  x − 1 = 0011 1111
         x & (x−1) = 0000 0000      ← згасла остання,         n = 3
         x == 0  → стоп,  popcount = 3
```

Три одиниці — три проходи, і жодного дарма витраченого кроку на нулях. Саме тому Кернігана варто тримати напохваті там, де апаратної команди нема, а слова здебільшого розріджені.

## Апаратний popcount

Майже всі сучасні ядра вміють рахувати одиниці **однією командою**. На x86 це `POPCNT`, на ARM — `CNT` (через сусідній регістр), на RISC-V — розширення `Zbb`. Компілятор сам підставить її, якщо попросити вбудовану функцію замість циклу:

:::tabs
```c
// GCC/Clang: одна машинна команда, якщо ядро її має.
int popcount_builtin(uint32_t x) {
    return __builtin_popcount(x);        // для 64-біт — __builtin_popcountll
}
```
```cpp
#include <bit>       // C++20: переносно, без прив'язки до компілятора
// std::popcount сам обере машинну команду, якщо ядро її має.
int popcount_builtin(uint32_t x) {
    return std::popcount(x);             // працює для будь-якої ширини uint
}
```
```python
def popcount_builtin(x: int) -> int:
    # Python 3.10+: одна вбудована операція над цілим.
    return x.bit_count()                 # до 3.10 — bin(x).count("1")
```
:::

Якщо апаратної команди в ядра нема (дрібні 8/16-бітні МК), компілятор тихо підставить швидку таблично-зсувну реалізацію — все одно зазвичай не гірше за ручний цикл. У C++20 те саме дає стандартний `std::popcount` із заголовка `<bit>` — переносно, без прив'язки до компілятора.

> 🔧 **Навіщо це.** Декодер на кожне прийняте слово рахує відстань до кодових слів — це гарячий шлях. На голому циклі по 32 біти він з'їсть час, якого в керуванні на кілька кілогерц може й не бути; на `__builtin_popcount` той самий підрахунок — пара тактів. Тому в прошивці відстань і вагу рахуйте через вбудований popcount, а ручний цикл лишайте тільки туди, де команди апаратно нема й де швидкість некритична.

Коли команди нема, а швидкість усе ж потрібна, посередині лежить давній прийом — **таблиця на байт**. Заздалегідь рахуємо ваги всіх 256 байтів у масив, а тоді вагу слова складаємо з ваг його байтів: чотири звернення до таблиці замість тридцяти двох перевірок біта.

:::tabs
```c
static uint8_t bits_in_byte[256];               // заповнити одноразово на старті
void popcount_table_init(void) {
    for (int i = 0; i < 256; i++)
        bits_in_byte[i] = popcount_kernighan((uint32_t)i);
}
int popcount_table(uint32_t x) {
    return bits_in_byte[x & 0xFF] + bits_in_byte[(x >> 8) & 0xFF]
         + bits_in_byte[(x >> 16) & 0xFF] + bits_in_byte[(x >> 24) & 0xFF];
}
```
```cpp
#include <array>
static std::array<uint8_t, 256> bits_in_byte;   // заповнити одноразово на старті
void popcount_table_init() {
    for (int i = 0; i < 256; i++)
        bits_in_byte[i] = popcount_kernighan(static_cast<uint32_t>(i));
}
int popcount_table(uint32_t x) {
    return bits_in_byte[x & 0xFF] + bits_in_byte[(x >> 8) & 0xFF]
         + bits_in_byte[(x >> 16) & 0xFF] + bits_in_byte[(x >> 24) & 0xFF];
}
```
:::

Плата за швидкість — 256 байтів пам'яті під таблицю; на МК із тісною RAM це варто зважити, та на флеші таблиця цілком може лежати константою. Це класичний обмін «пам'ять за час»: коли підрахунок справді гарячий, а апаратної команди катма, таблиця дає рівну, передбачувану швидкість без циклу.

## Мінімальна відстань коду перебором

Коли код малий (десятки-сотні слів) і заданий просто списком, його [мінімальну відстань](topic:math/hamming-bounds) знаходять прямо за означенням — найменша відстань по всіх парах різних слів:

:::tabs
```c
// d_min малого коду: перебір усіх пар. Слова — у масиві code[0..n-1].
int min_distance(const uint32_t *code, int n) {
    int best = INT_MAX;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++) {      // кожну пару — один раз
            int d = hamming_distance(code[i], code[j]);
            if (d < best) best = d;
        }
    return best;                                 // n < 2 → лишиться INT_MAX
}
```
```cpp
#include <span>
#include <limits>
// d_min малого коду: перебір усіх пар. Слова — у code.
int min_distance(std::span<const uint32_t> code) {
    int best = std::numeric_limits<int>::max();
    for (size_t i = 0; i < code.size(); i++)
        for (size_t j = i + 1; j < code.size(); j++) {  // кожну пару — один раз
            int d = hamming_distance(code[i], code[j]);
            if (d < best) best = d;
        }
    return best;                                 // менш ніж 2 слова → лишиться max
}
```
```python
from itertools import combinations

def min_distance(code: list[int]) -> int:
    """d_min малого коду: перебір усіх пар."""
    # менш ніж 2 слова → нескінченність (немає жодної пари)
    return min((hamming_distance(a, b)          # кожну пару — один раз
                for a, b in combinations(code, 2)),
               default=float("inf"))
```
:::

Пар тут n·(n−1)/2 — для сотні слів це п'ять тисяч дешевих порівнянь, мить навіть на скромному МК. Перебір росте квадратично, тож для кодів у тисячі й більше слів він уже завеликий — там d_min беруть із побудови коду, а не міряють; але для маленьких таблиць, які зустрічаються в прошивці найчастіше, прямий перебір простий і цілком швидкий. Маючи `d_min`, одразу читаємо силу коду тими ж двома формулами: виявлення до `d_min − 1`, виправлення до `(d_min − 1) / 2` (цілочисловий поділ у C і є потрібна нижня заокруглина ⌊·⌋).

:::tabs
```c
int can_detect(int d_min)  { return d_min - 1; }        // скільки помилок гарантовано видно
int can_correct(int d_min) { return (d_min - 1) / 2; }  // ⌊(d_min−1)/2⌋ — цілочислове ділення
```
```cpp
int can_detect(int d_min)  { return d_min - 1; }        // скільки помилок гарантовано видно
int can_correct(int d_min) { return (d_min - 1) / 2; }  // ⌊(d_min−1)/2⌋ — цілочислове ділення
```
```python
def can_detect(d_min: int) -> int:  return d_min - 1        # скільки помилок гарантовано видно
def can_correct(d_min: int) -> int: return (d_min - 1) // 2  # ⌊(d_min−1)/2⌋ — цілочислове ділення
```
:::

## Декодування за найближчим словом

Та сама відстань і виконує власне відновлення даних. Прийнявши (можливо, зіпсоване) слово, [декодер за найближчим сусідом](topic:math/hamming-bounds) оголошує переданим те кодове слово, до якого відстань найменша. Для малого коду це знову прямий перебір — порахувати відстань до кожного слова й узяти мінімум:

:::tabs
```c
// Повертає індекс найближчого кодового слова; *out_d — його відстань.
int decode_nearest(const uint32_t *code, int n, uint32_t got, int *out_d) {
    int best_i = 0, best_d = INT_MAX;
    for (int i = 0; i < n; i++) {
        int d = hamming_distance(got, code[i]);
        if (d < best_d) { best_d = d; best_i = i; }   // ближчий — запам'ятати
    }
    if (out_d) *out_d = best_d;
    return best_i;
}
```
```cpp
#include <span>
#include <limits>
// Повертає {індекс найближчого слова, його відстань}.
std::pair<int, int> decode_nearest(std::span<const uint32_t> code, uint32_t got) {
    int best_i = 0, best_d = std::numeric_limits<int>::max();
    for (size_t i = 0; i < code.size(); i++) {
        int d = hamming_distance(got, code[i]);
        if (d < best_d) { best_d = d; best_i = i; }   // ближчий — запам'ятати
    }
    return {best_i, best_d};
}
```
```python
def decode_nearest(code: list[int], got: int) -> tuple[int, int]:
    """Повертає (індекс найближчого слова, його відстань)."""
    best_i, best_d = 0, float("inf")
    for i, word in enumerate(code):
        d = hamming_distance(got, word)
        if d < best_d:                                # ближчий — запам'ятати
            best_d, best_i = d, i
    return best_i, best_d
```
:::

Поки помилок не більше за `can_correct(d_min)`, прийняте слово гарантовано лежить ближче до свого джерела, ніж до будь-якого іншого центру, тож `best_i` укаже саме передане слово. А відстань `best_d` корисна й сама собою: якщо вона перевищує `can_correct`, виправляти небезпечно — слово зайшло в «нічию землю» між кулями, і чесніше повернути «виявлено помилку, але не виправлено», ніж навмання приписати найближчий центр. Так одна функція дає і виправлення в межах радіуса, і чесний сигнал відмови за ним.

Цей перебірний декодер свідомо простий — він не використовує жодної структури коду, лише відстані, тож працює для будь-якого коду, заданого списком слів. Справжні коди (той самий [код Геммінга](topic:communications/hamming-code)) декодують куди дешевше — через синдром, без перебору всіх слів; але саме перебірна версія найясніше показує, що декодування — це буквально пошук найближчого за відстанню Геммінга центру, а вся хитрість справжніх кодів лише в тому, щоб знайти його, не обходячи весь список.

## Пастки

**Ширина типу.** `__builtin_popcount` бере `unsigned int`; для 64-бітних слів потрібен `__builtin_popcountll`, інакше старша половина просто загубиться без жодного попередження. Звіряйте суфікс із шириною аргументу.

**Знакові зсуви.** Наївний popcount на `int` зі знаком — пастка: для від'ємного числа `x >>= 1` тягне зверху одиниці (арифметичний зсув), і цикл або зациклиться, або дасть дурницю. Рахуйте одиниці **тільки на беззнакових** типах (`uint32_t`, `unsigned`).

**Різна довжина слів.** Відстань означена лише для слів **однакової** довжини. Якщо порівнюєте поля різної ширини, спершу зведіть їх до спільного типу й вирівняйте значущі біти — XOR коротшого з довшим мовчки порахує «зайві» старші розряди як різні.

**`d_min` від одного слова.** Перебір пар на коді з одного слова не виконає жодної ітерації й поверне `INT_MAX` — стережіть випадок `n < 2` окремо, бо інакше «нескінченна» відстань протече далі в розрахунок виявлення й виправлення.
