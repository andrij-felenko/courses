# 📋 Довідник операцій та алгебраїчних структур префіксних сум

Цей довідник містить повну специфікацію операцій, алгебраїчних вимог, системних параметрів та алгоритмічних характеристик складності для всіх варіантів префіксних сум і різницевих операторів. Він слугує інженерним керівництвом для вибору оптимальної структури даних під конкретні вимоги до швидкодії, пам'яті та типів алгебраїчних операцій (від абелевих груп до довільних моноїдів).

У матеріалі подано розгорнутий аналіз 8 структур даних, параметричні специфікації викликів, вимоги до алгебраїчної оберненості, аналіз крайових умов, інваріанти падінгу та критерії вибору між статичними префіксними масивами, різницевими масивами, деревами Фенвіка та деревами відрізків.

### 2. Детальний розбір специфікацій та сигнатур інтерфейсів

#### 2.1. 1D Префіксний масив статичного підсумовування (`PrefixSum1D`)

Структура `PrefixSum1D` призначена для виконання довільної кількості запитів суми елементів на закритому відрізку `[l, r]` незмінного послідовного масиву за константний час `O(1)`.

- **Призначення та область застосування**: Використовується в задачах з накопичувальними обчисленнями, де вихідний масив створюється один раз і надалі не змінюється, але піддається багатьом мільйонам запитів підсумовування на довільних діапазонах (сценарій `Read-Heavy`).
- **Контракт вхідних параметрів ініціалізації**:
  - `data`: Безперервний вказівник або абстракція `std::span` на вихідний масив елементів `A[0..N-1]`. Елементи можуть бути цілими числами будь-якого знака.
  - `N`: Кількість елементів у вихідному масиві (значення типу `size_t`).
- **Внутрішній стан та виділення пам'яті**:
  - Створюється масив префіксних сум `P` розміром суворо `N + 1` елементів.
  - Тип елементів масиву `P` — `int64_t` для запобігання знаковому переповненню.
- **Математичний інваріант падінгу**:
  - `P[0] = 0` (фіктивний нульовий елемент на початку).
  - `P[i] = P[i-1] + A[i-1]` для всіх `1 ≤ i ≤ N`.
- **Контракт запиту суми**:
  - Сигнатура виклику: `query(size_t l, size_t r)`.
  - Вхідні індекси відповідають 0-based індексації вихідного масиву (включно).
  - Алгебраїчна формула виконання за один крок: `Result = P[r + 1] - P[l]`.
- **Обробка крайових умов та помилок**:
  - Якщо `l > r` або `r ≥ N`, інтерфейс генерує виняток `std::out_of_range` (в C++) або повертає значення `0` із встановленням прапорця помилки (в C).
  - Порожній вихідний масив (`N = 0`) створює внутрішній вектор із 1 елемента (`P[0] = 0`), а будь-який запит викликає помилку меж.

#### 2.2. 1D Різницевий масив масового оновлення (`DifferenceArray1D`)

Структура `DifferenceArray1D` призначена для накопичення масових групових додавань значення `val` на відрізках `[l, r]` за константний час `O(1)` на операцію з подальшим одноразовим відновленням масиву.

- **Призначення та область застосування**: Застосовується в обчислювальних сценаріях `Write-Heavy, Final-Read`, де над масивом спочатку виконується величезна серія оновлень на відрізках, і лише наприкінці обчислень потрібно зчитати підсумкові значення елементів.
- **Контракт вхідних параметрів ініціалізації**:
  - `N`: Довжина вихідного масиву (тип `size_t`).
  - `init_data` (опціонально): Початковий масив елементів для побудови початкових різниць `D[i] = A[i] - A[i-1]`.
- **Внутрішній стан**:
  - Масив різниць `D` розміром `N + 1` у типі `int64_t`. Додатковий `+1` елемент необхідний для безпечної модифікації правої межі `D[r + 1]`.
- **Контракт операції оновлення**:
  - Сигнатура виклику: `add_range(size_t l, size_t r, int64_t val)`.
  - Алгебраїчні операції за `O(1)`:
    - `D[l] = D[l] + val` (додавання значення на лівій межі).
    - `D[r + 1] = D[r + 1] - val` (скасування дії значення за правою межею).
- **Контракт відновлення підсумкового масиву**:
  - Сигнатура виклику: `build()`.
  - Повертає новий масив `A'` розміром `N`, побудований за один прохід `O(N)` префіксним підсумовуванням: `A'[i] = ∑_{k=0}^i D[k]`.
- **Помилки та граничні умови**:
  - Спроба оновлення за межами `r ≥ N` блокується перевіркою границь.
  - Послідовні виклики `add_range` є асоціативними та комутативними між собою.

#### 2.3. 2D Префіксний масив прямокутних сіток (`PrefixSum2D`)

Структура `PrefixSum2D` виражає двовимірне накопичувальне підсумовування на матрицях розміром `R × C`.

- **Призначення**: Швидке знаходження суми значень у довільній прямокутній підматриці від `(r1, c1)` до `(r2, c2)` включно за `O(1)` часу.
- **Контракт вхідних параметрів ініціалізації**:
  - `grid`: Двовимірна матриця цілих чисел розміром `R × C`.
- **Внутрішній стан та геометричний падінг**:
  - Матриця префіксних сум `P` розміром `(R + 1) × (C + 1)` у типі `int64_t`.
  - Фіктивні нульові рядки та стовпчики: `P[0][c] = 0` для всіх `0 ≤ c ≤ C` та `P[r][0] = 0` для всіх `0 ≤ r ≤ R`.
- **Інваріант побудови за принципом включень-виключень**:
  - `P[r + 1][c + 1] = A[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]`.
- **Контракт запиту прямокутної суми**:
  - Сигнатура виклику: `query(r1, c1, r2, c2)`.
  - Формула виконання: `Result = P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]`.
- **Помилки та граничні умови**:
  - Перевіряються умови `0 ≤ r1 ≤ r2 < R` та `0 ≤ c1 ≤ c2 < C`.

#### 2.4. 3D Префіксний паралелепіпед (`PrefixSum3D`)

Структура `PrefixSum3D` забезпечує накопичувальне підсумовування у тривимірних воксельних сітках розміром `X × Y × Z`.

- **Призначення**: Знаходження суми значень у довільному тривимірному паралелепіпеді від `(x1, y1, z1)` до `(x2, y2, z2)` за `O(1)` часу.
- **Внутрішній стан**:
  - Тривимірний масив `P` розміром `(X + 1) × (Y + 1) × (Z + 1)`.
- **Інваріант побудови**:
  - `P[x+1][y+1][z+1] = A[x][y][z] + P[x][y+1][z+1] + P[x+1][y][z+1] + P[x+1][y+1][z] - P[x][y][z+1] - P[x][y+1][z] - P[x+1][y][z] + P[x][y][z]`.
- **Формула виконання запиту**:
  - Включає лінійну комбінацію 8 вершин об'єму зі змінними знаками відповідно до парності вимірності перетинів.

### 3. Алгебраїчні обмеження та межі застосовності

#### 3.1. Необхідність оберненого оператора (Invertibility Requirement)

Префіксні суми та різницеві масиви вимагають, щоб бінарна операція `⊕` утворювала **абелеву групу** `(G, ⊕)`. Це означає обов'язкову наявність оберненого елемента `a⁻¹`, такого що `a ⊕ a⁻¹ = e` (де `e` — нейтральний елемент групи).

- **Дозволені алгебраїчні операції**:
  - Додавання цілих та дійсних чисел `(ℝ, +)` (обернена операція: віднімання `-`).
  - Побітовий XOR `(Bitset, ⊕)` (обернена операція: сам XOR, оскільки `x ⊕ x = 0`).
  - Модульне додавання `(ℤ/mℤ, +)` (обернена операція: `-a mod m`).
  - Множення у полі ненульових чисел `(ℝ \ {0}, ·)` (префіксні добутки; обернена операція: ділення `/`).

- **Заборонені операції (де префіксні суми НЕ працюють)**:
  - Операція мінімуму `min(a, b)` або максимуму `max(a, b)` (задачі Range Minimum Query, RMQ). Операція `min` не має оберненого елемента: знаючи, що `min(a, b) = 3` та `a = 5`, неможливо математично визначити початкове значення `b`. Для задач RMQ використовують Sparse Table або Segment Tree.
  - Найбільший спільний дільник `gcd(a, b)`. Операція `gcd` є асоціативною та комутативною (утворює півгрупу), але не має оберненого оператора.
  - Множення матриць загального вигляду (через відсутність комутативності та необоротність вироджених матриць).

#### 3.2. Докладне порівняння алгебраїчних структур

| Алгебраїчна операція | Вимога оберненості | Застосовність префіксних сум | Альтернативна структура даних |
|---|---|---|---|
| **Додавання (+)** | Присутня (`-x`) | Так (Префіксна сума) | Array / Vector |
| **Множення (·)** | Присутня (`1/x`, якщо `x ≠ 0`) | Так (Префіксний добуток) | Array (з обробкою нулів) |
| **Побітовий XOR (⊕)** | Присутня (`x`) | Так (Префіксний XOR) | Array / Vector |
| **Мінімум / Максимум** | Відсутня | **Ні** | Sparse Table / Segment Tree |
| **НСД (GCD)** | Відсутня | **Ні** | Sparse Table / Segment Tree |
| **Об'єднання множин (∪)**| Відсутня | **Ні** | Disjoint Set Union (DSU) |

### 4. Динамічні альтернативи: Дерево Фенвіка та Дерево відрізків

Коли вихідний масив піддається і оновленням елементів, і запитам підсумовування у довільному перемішаному порядку, статичні префіксні масиви стають неефективними (коротке оновлення елемента вимагає `O(N)` часу на перебудову префіксів). 

У цьому розділі систематизовано характеристики двох головних динамічних альтернатив.

#### 4.1. Дерево Фенвіка (Binary Indexed Tree, BIT)

- **Алгебраїчна вимога**: Абелева група `(G, +)` (потрібен обернений оператор віднімання).
- **Часова складність**:
  - Точкове оновлення елемента `update(idx, val)`: `O(log N)`.
  - Запит префіксної суми `query(idx)`: `O(log N)`.
  - Запит суми на відрізку `query_range(l, r)`: `O(log N)` як `query(r) - query(l - 1)`.
- **Пам'ять**: `N + 1` елементів (абсолютно однакова з префіксним масивом).
- **Особливості реалізації**: Використовує бітовий трюк `i & (-i)` для знаходження довжини інтервалу відповідальності вузла. Має найнижчий коефіцієнт накладної витрати пам'яті та ідеально вкладається у кеш-лінії.

#### 4.2. Дерево відрізків (Segment Tree)

- **Алгебраїчна вимога**: Моноїд `(M, ·)` (потрібна лише асоціативність та наявність нейтрального елемента; обернений елемент **не потрібен**).
- **Часова складність**:
  - Точкове або групове оновлення (з ледачим проштовхуванням *Lazy Propagation*): `O(log N)`.
  - Запит на довільному відрізку `query(l, r)`: `O(log N)`.
- **Пам'ять**: `4N` елементів (у 4 рази більше за вихідний масив).
- **Особливості застосування**: Універсальна структура даних, яка підтримує суми, мінімуми, максимуми, НСД, побітові операції та масові оновлення на відрізках.

### 5. Межеві випадки, інваріанти та безпека типів

При програмній реалізації префіксних систем необхідно дотримуватися суворих інваріантів для запобігання фатальним помилкам виконання:

#### 5.1. Помилки переповнення типів (Integer Overflow Boundaries)

1. **8-бітні та 16-бітні масиви**: При підсумовуванні масиву елементів `int8_t` сума переповнюється вже після 256 елементів. Префіксний масив мусить мати тип `int32_t` або `int64_t`.
2. **32-бітні масиви `int32_t`**: Максимальне значення `INT32_MAX = 2 147 483 647`. Якщо вихідні елементи дорівнюють `10^6`, префіксна сума переповниться вже після 2148 елементів. Для будь-яких 32-бітних даних префіксний масив зобов'язаний використовувати 64-бітний тип `int64_t`.
3. **64-бітні масиви `int64_t`**: При підсумовуванні понад `10^12` великих 64-бітних чисел префіксна сума може вийти за межі `INT64_MAX ≈ 9.22 · 10^18`. У таких задачах застосовують модульну арифметику `mod M` або типи довільної точності (BigInt / `__int128`).

#### 5.2. Помилки індексації та границь (Off-by-One Guardrails)

- **Падінг розміру `N + 1`**: Розмір масиву префіксних сум `P` повинен дорівнювати суворо `N + 1`. Спроба зекономити пам'ять і створити `P` розміром `N` призводить до обов'язкового розгалуження `if (l == 0)` при кожному запиті, що знижує швидкість виконання через непередбачувані переходи процесора (*branch mispredictions*).
- **Визначення порожнього відрізка**: Якщо запит передає `l > r`, виклик має вважатися некоректним та повертати 0 або генерувати виняток. Відрізок `l == r` є коректним і повертає значення одного елемента `A[l]`.

### 6. Гарантії винятків та безпека обробки помилок (Exception Safety)

При використанні префіксних структур у сучасних об'єктно-орієнтованих мовах (зокрема C++) важливе значення мають гарантії винятків при виділенні ресурсів та обробці некоректних аргументів:

#### 6.1. Строга гарантія винятків (Strong Exception Guarantee)

Конструктор структури `PrefixSum1D` або `PrefixSum2D` забезпечує строгу гарантію винятків (*Strong Exception Safety Guarantee*). Якщо під час виділення динамічної пам'яті під префіксний масив виникає виняток браків пам'яті `std::bad_alloc`, об'єкт залишається у незмінному початковому стані, а вже виділена пам'ять повністю звільняється без витоків ресурсів.

#### 6.2. Гарантія відсутності винятків (Noexcept Guarantee)

Константні методи запиту сум, такі як `query(l, r)` або `query(r1, c1, r2, c2)`, які не виконують виділення пам'яті й не використовують динамчних алокацій, можуть позначатися специфікатором `noexcept` у випадках, коли перевірка границь здійснюється за допомогою стверджень `assert` або обробляється поверненням статусних кодів помилок. Це дозволяє компілятору оптимізувати виклики функцій і генерувати ефективніший машинний код без створення таблиць розгортання стеку.

### 7. Специфікація 4D префіксних сум та гіперкубічних сіток

У високовимірному фізичному моделюванні, квантовій хромодинаміці та обробці часово-просторових даних (3D відеопотоки плюс вісь часу `t`) застосовуються чотиривимірні префіксні суми `P[x][y][z][t]`.

- **Формула підсумовування гіперкуба**: Сума елементів у 4D гіперкубі від `(x1, y1, z1, t1)` до `(x2, y2, z2, t2)` обчислюється через лінійну комбінацію 16 вершин чотиривимірного об'єму:
  `Sum = ∑_{k=0}^{15} (-1)^{popcount(k)} · P[v_k]`.
- **Вимоги до об'єму пам'яті**: Чотиривимірний префіксний масив розміром `N × N × N × N` вимагає `(N + 1)⁴ · 8` байт пам'яті. Для `N = 100` об'єм пам'яті становить близько 800 мегабайт, що вимагає ретельного вирівнювання сторінок пам'яті.

### 8. Багатопотоковість та гарантії потокобезпеки (Thread Safety Guarantees)

У конкурентних багаторівневих системах використання префіксних сум підкоряється стандартній моделі `Multiple Readers, Single Writer`:

- **Паралельне читання (Concurrent Reads)**: Оскільки після завершення ініціалізації масив префіксних сум `P` є суворо незмінним (*immutable*), довільна кількість паралельних потоків виконання може одночасно викликати метод `query(l, r)` без використання жодних блокувальних примітивів синхронізації (`std::mutex` не потрібен). Це гарантує максимальну масштабованість на багатиядерних системах без взаємного блокування потоків (*lock-free read*).
- **Конкурентна перебудова (Concurrent Rebuild)**: Якщо префіксний масив перезаписується в одному потоці під час того, як інші потоки виконують запити читання, виникає стан гонки за даними (*Data Race*). Для динамічного оновлення необхідно використовувати блокування зчитувачів-записувачів (`std::shared_mutex`), де читачі беруть `shared_lock`, а записувач — `unique_lock`.

#### 9.1. Використання великих сторінок пам'яті (Huge Pages / Large Pages)

При обробці масивів префіксних сум, обсяг яких перевищує десятки гігабайт (наприклад, у задачах біоінформатики або аналізу великих графів), стандартний розмір сторінки пам'яті в 4 кілобайти призводить до високої накладної витрати на перекладання адресної пам'яті буфера TLB (*Translation Lookaside Buffer*). Використання великих сторінок розміром 2 мегабайти або 1 гігабайт (`MAP_HUGETLB` у системному виклику `mmap` на Linux або `MEM_LARGE_PAGES` на Windows) зменшує кількість записів у буфері TLB у 512 разів. Це ліквідує затримки на прохід по таблицях сторінок і прискорює довільний доступ до префіксних сум у 1.5–2 рази.

#### 9.2. Нульове копіювання через абстракцію std::span

При проєктуванні C++ API сучасним стандартом є повна відмова від передачі сирих вказівників `const T*` разом із окремою довжиною `size_t len`. Замість цього використовується неволодіюча абстракція `std::span<const T>`, яка об'єднує вказівник на перший елемент і розмір масиву у єдиний легкий об'єкт. Це гарантує сувору безпеку типів, повністю унеможливлює передачу некоректного розміру та дозволяє передавати як вхідні дані будь-які суцільні контейнери — `std::vector`, `std::array`, `std::initializer_list` або сирі C-масиви — без жодного копіювання даних у пам'яті (*Zero-Copy Interface*). Завдяки цьому продуктивність обчислень залишається на найвищому рівні сирих вказівників, а надійність коду повністю відповідає вимогам стандарту C++20. Крім того, `std::span` дозволяє прозоро створювати зрізи масиву (*subspans*) за `O(1)` без виділення нової пам'яті.
