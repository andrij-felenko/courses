# ⚙️ Алгоритми та реалізація префіксних сум мовами C та C++

Практичне втілення ідеї префіксних сум вимагає уважного ставлення до індексації, виділення пам'яті, запобігання цілочисельному переповненню та дотримання ідіом мови програмування. На відміну від теоретичного формулювання, де індексація часто починається з 1, у реальних програмах вибір між 0-based індексацією з виділенням фіктивного додаткового елемента `P[0] = 0` (так званого `padding`) або прямою модифікацією масиву визначає швидкість роботи та відсутність помилок «зміщення на одиницю» (*off-by-one errors*). 

У цьому матеріалі подано вичерпні, автономні та ідіоматичні реалізації чотирьох ключових алгоритмічних шаблонів на C та C++: 1D префіксних сум, 1D різницевого масиву для групових оновлень, 2D префіксних сум для прямокутних матриць та шукача відрізків із кратною сумою за модулем. Крім того, розглянуто тему SIMD-векторизації, алгоритм Хілліса — Стіла для багатопотокового обчислення, динамічні дерева Фенвіка та детальні покрокові трасування виконання.

### 1. 1D Префіксні суми та накопичувальні запити на відрізках

#### 1.1. Архітектурні принципи та вибір типів даних

Основна задача 1D префіксного масиву — перетворити накопичувальне додавання на відрізках із лінійного обходу `O(N)` на миттєву арифметичну дію `O(1)`. Для цього на етапі ініціалізації виділяється додаткова пам'ять під масив `P` розміром `N + 1`, де `P[0] = 0`. Додавання фіктивного нуля на початку усуває необхідність перевіряти умову `l == 0` під час кожного запиту: сума на відрізку `[l, r]` завжди обчислюється за єдиною формулою `P[r + 1] - P[l]`.

Важливим технічним нюансом є захист від цілочисельного переповнення. Якщо вихідний масив містить великі 32-бітні цілі числа `int32_t`, сума вже кількох тисяч елементів може вийти за межі `2^31 - 1`. Тому масив префіксних сум обов'язково виділяється у 64-бітному типі `int64_t`.

З точки зору процесорного виконання, обчислення префіксних сум є послідовним алгоритмом, де кожна наступна ітерація залежить від результату попередньої (`P[i] = P[i-1] + A[i]`). Ця послідовна залежність за даними (*loop-carried data dependency*) обмежує пряму векторну паралельність на рівні одного ядра процесора (SIMD), але забезпечує ідеальну локальність кешу L1, оскільки пам'ять зчитується суцільним потоком.

#### 1.2. Векторизація SIMD та паралельний алгоритм Хілліса — Стіла

На сучасних процесорних архітектурах із підтримкою інструкцій AVX2 та AVX-512 послідовну залежність даних можна частково подолати за допомогою каскадного зміщення векторних регістрів. Векторний алгоритм Хілліса — Стіла (*Hillis-Steele Parallel Prefix Scan*) виконує обчислення префіксів за `O(log N)` паралельних кроків.

На першому кроці кожен елемент додається зі своїм сусідом на відстані 1, на другому кроці — з сусідом на відстані 2, на `k`-му кроці — з сусідом на відстані `2^(k-1)`. У векторних регістрах AVX2 це реалізується через комбінацію інструкцій `_mm256_add_epi32` та зсувів `_mm256_bslli_si256`. Хоча загальна кількість арифметичних операцій зростає до `O(N · log N)`, на високопаралельних GPU та SIMD-блоках це дає прискорення у 4–8 разів порівняно з послідовним циклом.

#### 1.4. Стратегії виділення пам'яті та мінімізація системних викликів

При роботі з префіксними масивами великого обсягу (від десятків мільйонів елементів) суттєвий вплив на продуктивність має спосіб виділення оперативної пам'яті. Використання функції `calloc` у мові C або конструктора `std::vector(size, 0)` у C++ призводить до примусового обнулення всього масиву. На операційних системах Linux та Windows це викликає системні покрокові помилки сторінок (*page faults*), оскільки ядро фізично виділяє нульові сторінки оперативної пам'яті під час запису.

Якщо масив префіксних сум одразу ж повністю перезаписується у циклі (`P[i + 1] = P[i] + A[i]`), виділення пам'яті через `malloc` у C або за допомогою незаповненої резервації пам'яті в C++ без попереднього нульового заповнення дає змогу уникнути подвійного проходу по оперативній пам'яті. Для критичних до затримок систем використовують арена-алокатори (*Arena Allocators*) або попередньо виділені буфери пам'яті `mmap` із прапорцем `MAP_POPULATE`. Крім того, на великих обсягах даних понад сотні мегабайт програмна підкачка пам'яті (*Software Prefetching*) за допомогою інструкцій `_mm_prefetch` дозволяє приховати аппаратні затримки звернення до основної системної DRAM-пам'яті, завчасно завантажуючи наступні блоки елементів масиву у швидкі кеш-лінії L1/L2 за 64–128 ітерацій до безпосереднього початку їхньої обробки арифметичним ядром.

#### 1.5. Порівняння реалізацій мовами C та C++

Нижче наведено порівняльну реалізацію мовами C та C++. У версії для C застосовано сувору перевірку вхідних вказівників, ручне виділення пам'яті через `malloc` та явне звільнення ресурсів. У версії для C++ використано сучасні ідіоми: RAII-контейнер `std::vector`, абстракцію `std::span` (C++20) для неволодіючого доступу до послідовностей та генерацію винятків `std::out_of_range` при виході за межі.

:::tabs
```c
/* Реалізація мовою C: класична структура з ручним керуванням пам'яттю */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    int64_t* pref;
    size_t size;
} PrefixSum1D;

/* Побудова префіксного масиву з виділенням N + 1 елементів */
bool prefix_sum_1d_init(PrefixSum1D* ps, const int32_t* arr, size_t n) {
    if (!ps || (!arr && n > 0)) return false;
    
    ps->pref = (int64_t*)malloc((n + 1) * sizeof(int64_t));
    if (!ps->pref) {
        ps->size = 0;
        return false;
    }
    
    ps->size = n;
    ps->pref[0] = 0;
    for (size_t i = 0; i < n; ++i) {
        ps->pref[i + 1] = ps->pref[i] + (int64_t)arr[i];
    }
    return true;
}

/* Запит суми на відрізку [l, r] в 0-вказаній індексації (включно) */
int64_t prefix_sum_1d_query(const PrefixSum1D* ps, size_t l, size_t r) {
    if (!ps || !ps->pref || l > r || r >= ps->size) {
        return 0; /* Обробка межевих помилок */
    }
    return ps->pref[r + 1] - ps->pref[l];
}

/* Звільнення пам'яті */
void prefix_sum_1d_free(PrefixSum1D* ps) {
    if (ps && ps->pref) {
        free(ps->pref);
        ps->pref = NULL;
        ps->size = 0;
    }
}
```
```cpp
// Реалізація мовою C++: RAII-обгортка з std::vector та std::span
#include <vector>
#include <span>
#include <cstdint>
#include <stdexcept>

class PrefixSum1D {
private:
    std::vector<int64_t> pref_;

public:
    // Конструктор приймає будь-який безперервний контейнер через std::span
    explicit PrefixSum1D(std::span<const int32_t> data) 
        : pref_(data.size() + 1, 0) {
        for (size_t i = 0; i < data.size(); ++i) {
            pref_[i + 1] = pref_[i] + static_cast<int64_t>(data[i]);
        }
    }

    // Повертає суму на відрізку [l, r] включно в 0-індексації за O(1)
    [[nodiscard]] int64_t query(size_t l, size_t r) const {
        if (l > r || r >= pref_.size() - 1) {
            throw std::out_of_range("Некоректні межі відрізка в PrefixSum1D::query");
        }
        return pref_[r + 1] - pref_[l];
    }

    [[nodiscard]] size_t size() const noexcept {
        return pref_.empty() ? 0 : pref_.size() - 1;
    }
};
```
:::

Просторова складність цієї структури становить `O(N)` додаткової пам'яті, а часова складність побудови — `O(N)`. Після побудови кожен запит виконується за `O(1)` операцій без жодного розгалуження, що робить префіксний масив ідеальним для сценаріїв `Read-Heavy` (багато запитів читання на незмінному масиві).

### 2. 1D Різницевий масив для групових оновлень на відрізках

#### 2.1. Концепція ланичного модифікування та відновлення

Коли виникає протилежна задача — виконувати численні оновлення на відрізках `[l, r]`, додаючи значення `val` до кожного елемента, наивний підхід вимагає `O(N)` кроків на кожну операцію. Різницевий масив (*Difference Array*) дозволяє знизити складність оновлення до `O(1)`.

Ідея полягає в тому, що замість прямої модифікації елементів ми модифікуємо лише дві межі в масиві різниць `D[i] = A[i] - A[i-1]`:
1. На лівій межі `l` додаємо значення: `D[l] += val`. Це означає, що при подальшому префіксному підсумовуванні значення `val` додасться до всіх елементів, починаючи з `l`.
2. На елементі після правої межі `r + 1` віднімаємо значення: `D[r + 1] -= val`. Це скасовує дію `val` для всіх елементів за межами відрізка.

Після виконання всіх `Q` оновлень підсумковий масив відновлюється за один прохід префіксного підсумовування `A'[i] = ∑_{k=0}^i D[k]` за `O(N)` часу.

#### 2.2. Альтернатива для динамічних оновлень: Дерево Фенвіка та Дерево відрізків

Якщо оновлення на відрізках та запити сум чергуються в довільному порядку (динамічний сценарій `Read-Write-Interleaved`), статичний різницевий масив стає неефективним, оскільки кожне відновлення вимагає `O(N)` часу. У таких викликах використовують дерево Фенвіка (*Binary Indexed Tree*, BIT) або дерево відрізків (*Segment Tree*), які дозволяють виконувати і точкові оновлення, і префіксні запити за `O(log N)` часу, використовуючи бітову операцію виділення наймолодшого встановленого біта `i & (-i)`. 

Дерево Фенвіка використовує стільки ж пам'яті, скільки й вихідний масив `O(N)`, і має надзвичайно низький коефіцієнт константи часу завдяки простій бітовій арифметиці. Однак для пакетних оновлень (*Batch Updates*), де мільйони модифікацій відбуваються до початку будь-яких запитів читання, статичний різницевий масив залишається беззаперечним лідером за швидкістю, перевищуючи дерево Фенвіка у 5–10 разів за рахунок суцільного векторного обходу пам'яті.

#### 2.3. Вирівнювання пам'яті та вирівняні типи даних (alignas)

Для досягнення максимальної продуктивності на процесорах архітектури x86_64 та ARM64 масиви префіксних сум рекомендується вирівнювати по межі кеш-лінії (зазвичай 64 байти). У сучасному C++20 це досягається за допомогою специфікатора `alignas(64)` або спеціалізованих алокаторів `std::aligned_alloc`. Вирівняний доступ дозволяє векторним інструкціям AVX2 та AVX-512 зчитувати 256-бітні та 512-бітні регістри за один такт шини пам'яті без штрафів за перетин меж кеш-ліній (*cache line split penalty*).

#### 2.4. Програмна реалізація та Fluent API

У версії C++ показано патерн *Fluent API* (ланцюговий виклик методів `add_range`), де кожна операція оновлення повертає посилання на поточний об'єкт `*this`.

:::tabs
```c
/* Реалізація мовою C: оператор різниць та накопичувальне відновлення */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    int64_t* diff;
    size_t size;
} DifferenceArray1D;

bool diff_array_init(DifferenceArray1D* da, const int32_t* init_arr, size_t n) {
    if (!da || n == 0) return false;
    
    /* Додаємо 1 додатковий елемент для безпечного виконання diff[r + 1] -= val */
    da->diff = (int64_t*)calloc(n + 1, sizeof(int64_t));
    if (!da->diff) return false;
    
    da->size = n;
    if (init_arr) {
        da->diff[0] = init_arr[0];
        for (size_t i = 1; i < n; ++i) {
            da->diff[i] = (int64_t)init_arr[i] - (int64_t)init_arr[i - 1];
        }
    }
    return true;
}

/* Додавання значення val на відрізку [l, r] за O(1) */
void diff_array_add_range(DifferenceArray1D* da, size_t l, size_t r, int64_t val) {
    if (!da || !da->diff || l > r || r >= da->size) return;
    
    da->diff[l] += val;
    da->diff[r + 1] -= val;
}

/* Відновлення вихідного масиву префіксними сумами за O(N) */
bool diff_array_build(const DifferenceArray1D* da, int64_t* result_out, size_t out_size) {
    if (!da || !da->diff || !result_out || out_size < da->size) return false;
    
    int64_t current_sum = 0;
    for (size_t i = 0; i < da->size; ++i) {
        current_sum += da->diff[i];
        result_out[i] = current_sum;
    }
    return true;
}

void diff_array_free(DifferenceArray1D* da) {
    if (da && da->diff) {
        free(da->diff);
        da->diff = NULL;
        da->size = 0;
    }
}
```
```cpp
// Реалізація мовою C++: клас із підтримкою ланцюгових викликів (Fluent API)
#include <vector>
#include <span>
#include <cstdint>
#include <stdexcept>

class DifferenceArray1D {
private:
    std::vector<int64_t> diff_;
    size_t size_;

public:
    explicit DifferenceArray1D(size_t size) 
        : diff_(size + 1, 0), size_(size) {}

    explicit DifferenceArray1D(std::span<const int32_t> init_data) 
        : diff_(init_data.size() + 1, 0), size_(init_data.size()) {
        if (!init_data.empty()) {
            diff_[0] = init_data[0];
            for (size_t i = 1; i < init_data.size(); ++i) {
                diff_[i] = static_cast<int64_t>(init_data[i]) - init_data[i - 1];
            }
        }
    }

    // Додавання на відрізку [l, r] за O(1)
    DifferenceArray1D& add_range(size_t l, size_t r, int64_t val) {
        if (l > r || r >= size_) {
            throw std::out_of_range("Некоректний відрізок у DifferenceArray1D::add_range");
        }
        diff_[l] += val;
        diff_[r + 1] -= val;
        return *this;
    }

    // Відновлення підсумкового масиву префіксними сумами за O(N)
    [[nodiscard]] std::vector<int64_t> build() const {
        std::vector<int64_t> result(size_);
        int64_t current = 0;
        for (size_t i = 0; i < size_; ++i) {
            current += diff_[i];
            result[i] = current;
        }
        return result;
    }
};
```

Різницевий масив демонструє найвищу ефективність у сценаріях `Write-Heavy, Final-Read`: коли спочатку накопичуються мільйони оновлень на відрізках, і лише наприкінці потрібно зчитати підсумковий стан.

### 3. 2D Префіксні суми для прямокутних матриць

#### 3.1. Плоске розміщення у пам'яті та кеш-оптимізація

Розширення префіксних сум на двовимірний простір керується принципом включень-виключень. Двовимірний префіксний масив `P[r][c]` зберігає суму елементів у прямокутнику від `(0, 0)` до `(r-1, c-1)`.

При обчисленні префіксної матриці використовується рекурентна формула:
`P[r + 1][c + 1] = A[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]`.
Віднімання `P[r][c]` необхідно тому, що верхній прямокутник `P[r][c + 1]` та лівий прямокутник `P[r + 1][c]` обидва включають спільну кутову область `P[r][c]`.

При виконанні запиту суми для прямокутника з верхнім лівим кутом `(r1, c1)` та нижнім правим кутом `(r2, c2)` застосовується формула:
`Sum = P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]`.

У реалізації мовою C для забезпечення найкращої локальності кешу процесора двовимірна матриця зберігається у суцільному одновимірному буфері `Row-Major Order`, де елемент `(r, c)` розміщено за індексом `r * stride_cols + c`. Таке плоске розгортання запобігає фрагментації пам'яті, що виникає при використанні масивів вказівників `int**`, і дозволяє процесорові ефективно завантажувати дані у кеш-лінії L1/L2. У версії на C++ показано реалізацію через вектор векторів.

#### 3.2. Двовимірна реалізація на C та C++

:::tabs
```c
/* Реалізація мовою C: плоский масив 1D для двовимірної сітки (Row-Major Ordering) */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    int64_t* pref;
    size_t rows;
    size_t cols;
} PrefixSum2D;

static inline size_t idx2d(size_t r, size_t c, size_t stride_cols) {
    return r * stride_cols + c;
}

bool prefix_sum_2d_init(PrefixSum2D* ps, const int32_t* matrix, size_t rows, size_t cols) {
    if (!ps || !matrix || rows == 0 || cols == 0) return false;
    
    size_t p_cols = cols + 1;
    size_t p_rows = rows + 1;
    
    ps->pref = (int64_t*)calloc(p_rows * p_cols, sizeof(int64_t));
    if (!ps->pref) return false;
    
    ps->rows = rows;
    ps->cols = cols;
    
    for (size_t r = 0; r < rows; ++r) {
        for (size_t c = 0; c < cols; ++c) {
            int64_t val = (int64_t)matrix[r * cols + c];
            int64_t top = ps->pref[idx2d(r, c + 1, p_cols)];
            int64_t left = ps->pref[idx2d(r + 1, c, p_cols)];
            int64_t top_left = ps->pref[idx2d(r, c, p_cols)];
            
            ps->pref[idx2d(r + 1, c + 1, p_cols)] = val + top + left - top_left;
        }
    }
    return true;
}

int64_t prefix_sum_2d_query(const PrefixSum2D* ps, size_t r1, size_t c1, size_t r2, size_t c2) {
    if (!ps || !ps->pref || r1 > r2 || c1 > c2 || r2 >= ps->rows || c2 >= ps->cols) {
        return 0;
    }
    size_t p_cols = ps->cols + 1;
    
    int64_t total    = ps->pref[idx2d(r2 + 1, c2 + 1, p_cols)];
    int64_t top      = ps->pref[idx2d(r1, c2 + 1, p_cols)];
    int64_t left     = ps->pref[idx2d(r2 + 1, c1, p_cols)];
    int64_t top_left = ps->pref[idx2d(r1, c1, p_cols)];
    
    return total - top - left + top_left;
}

void prefix_sum_2d_free(PrefixSum2D* ps) {
    if (ps && ps->pref) {
        free(ps->pref);
        ps->pref = NULL;
        ps->rows = ps->cols = 0;
    }
}
```

```cpp
// Реалізація мовою C++: матричний клас із підтримкою двовимірних векторів
#include <vector>
#include <cstdint>
#include <stdexcept>

class PrefixSum2D {
private:
    std::vector<std::vector<int64_t>> pref_;
    size_t rows_;
    size_t cols_;

public:
    explicit PrefixSum2D(const std::vector<std::vector<int32_t>>& grid) {
        if (grid.empty() || grid[0].empty()) {
            rows_ = cols_ = 0;
            return;
        }
        rows_ = grid.size();
        cols_ = grid[0].size();
        
        pref_.assign(rows_ + 1, std::vector<int64_t>(cols_ + 1, 0));
        
        for (size_t r = 0; r < rows_; ++r) {
            for (size_t c = 0; c < cols_; ++c) {
                pref_[r + 1][c + 1] = static_cast<int64_t>(grid[r][c])
                                    + pref_[r][c + 1]
                                    + pref_[r + 1][c]
                                    - pref_[r][c];
            }
        }
    }

    [[nodiscard]] int64_t query(size_t r1, size_t c1, size_t r2, size_t c2) const {
        if (r1 > r2 || c1 > c2 || r2 >= rows_ || c2 >= cols_) {
            throw std::out_of_range("Некоректна прямокутна область у PrefixSum2D::query");
        }
        return pref_[r2 + 1][c2 + 1] 
             - pref_[r1][c2 + 1] 
             - pref_[r2 + 1][c1] 
             + pref_[r1][c1];
    }
};
```

### 4. Шукач підмасиву із кратністю суми за модулем m (Пошук за O(N))

#### 4.1. Нормалізація від'ємних остач та таблиці першого входження

У теоретичній частині було доведено, що в масиві з `N` елементів завжди існує підмасив, сума якого ділиться на `N`. Програмування цієї задачі вимагає збереження першого індексу появі кожного залишку префіксної суми.

Якщо префіксні суми `P_j` та `P_i` дають однаковий залишок за модулем `m` (`P_j ≡ P_i (mod m)`), то сума підмасиву від `i` до `j - 1` ділиться на `m` без остачі: `(P_j - P_i) % m == 0`.

Важливим практичним моментом є коректне зведення від'ємних чисел за модулем. В обчислювальних мовах C та C++ оператор `%` реалізує не алгебраїчний залишок, а математичну остачу від ділення, яка для від'ємного діленого дає від'ємний результат (наприклад, `-7 % 5 == -2`). Для переведення залишку в математичний діапазон `[0, m - 1]` застосовується формула: `rem = (val % m + m) % m`.

Нижче наведено алгоритм пошуку першого кратного підмасиву за один прохід `O(N)`.

#### 4.2. Алгоритмічна реалізація пошуку кратних підмасивів

```c
/* Реалізація мовою C: пошук відрізка з кратністю за модулем m */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    size_t start_idx;
    size_t end_idx;
    bool found;
} SubarrayResult;

SubarrayResult find_subarray_divisible_by_m(const int32_t* arr, size_t n, int32_t m) {
    SubarrayResult res = {0, 0, false};
    if (!arr || n == 0 || m <= 0) return res;

    /* Динамічний масив для збереження індексів першої появи остач mod m */
    int64_t* first_seen = (int64_t*)malloc((size_t)m * sizeof(int64_t));
    if (!first_seen) return res;

    for (int32_t i = 0; i < m; ++i) {
        first_seen[i] = -1; /* -1 означає, що остача ще не зустрічалася */
    }
    first_seen[0] = 0; /* P_0 = 0 має індекс 0 */

    int64_t current_prefix = 0;
    for (size_t j = 0; j < n; ++j) {
        current_prefix += arr[j];
        
        /* Коректне зведення від'ємних остач у діапазон [0, m-1] */
        int32_t rem = (int32_t)(current_prefix % m);
        if (rem < 0) rem += m;

        if (first_seen[rem] != -1) {
            res.start_idx = (size_t)first_seen[rem];
            res.end_idx = j;
            res.found = true;
            free(first_seen);
            return res;
        } else {
            first_seen[rem] = (int64_t)(j + 1);
        }
    }

    free(first_seen);
    return res;
}
```

```cpp
// Реалізація мовою C++: використання std::unordered_map для довільних модулів
#include <vector>
#include <span>
#include <cstdint>
#include <unordered_map>
#include <optional>

struct SubarrayRange {
    size_t start_idx;
    size_t end_idx;
};

std::optional<SubarrayRange> find_subarray_divisible_by_m(std::span<const int32_t> arr, int64_t m) {
    if (arr.empty() || m <= 0) return std::nullopt;

    // Зберігаємо перше входження кожної остачі: rem -> index
    std::unordered_map<int64_t, size_t> first_seen;
    first_seen[0] = 0; // P_0 = 0

    int64_t current_prefix = 0;
    for (size_t j = 0; j < arr.size(); ++j) {
        current_prefix += arr[j];
        
        int64_t rem = current_prefix % m;
        if (rem < 0) rem += m; // Нормалізація від'ємних остач

        if (auto it = first_seen.find(rem); it != first_seen.end()) {
            return SubarrayRange{ .start_idx = it->second, .end_idx = j };
        }
        first_seen.emplace(rem, j + 1);
    }

    return std::nullopt;
}
```

### 5. 3D Префіксні суми та багатовимірний гіперкуб

У тривимірному просторі (наприклад, при обробці воксельних сіток у томографії, 3D графіці або моделюванні фізичних полів) префіксний паралелепіпед `P[x][y][z]` зберігає суму всіх вокселів від `(0, 0, 0)` до `(x-1, y-1, z-1)`.

Побудова здійснюється за тривимірним принципом включень-виключень:
`P[x+1][y+1][z+1] = A[x][y][z] + P[x][y+1][z+1] + P[x+1][y][z+1] + P[x+1][y+1][z] - P[x][y][z+1] - P[x][y+1][z] - P[x+1][y][z] + P[x][y][z]`.

Запит суми вокселів у паралелепіпеді від `(x1, y1, z1)` до `(x2, y2, z2)` вимагає комбінації 8 об'ємів вершини:
`Sum = P[x2+1][y2+1][z2+1] - P[x1][y2+1][z2+1] - P[x2+1][y1][z2+1] - P[x2+1][y2+1][z1] + P[x1][y1][z2+1] + P[x1][y2+1][z1] + P[x2+1][y1][z1] - P[x1][y1][z1]`.

Збереження 3D префіксного масиву у суцільному одновимірному буфері `1D` виконується через крок стрибків (*strides*):
`idx3d(x, y, z) = x * (dimY * dimZ) + y * dimZ + z`.
Це забезпечує послідовне зчитування пам'яті уздовж осі Z, що максимально прискорює кешування при векторних запитах.

### 6. Паралельні обчислення префіксних сум на GPU (CUDA / GPGPU)

На графічних процесорах (GPU) обчислення префіксних сум відоме під назвою `Parallel Prefix Scan` і виступає фундаментальним примітивом для алгоритмів подекадного сортування (*Radix Sort*), побудови дерев BVH у трасуванні променів та стиснення скіп-списків.

Алгоритм Блеллока (*Blelloch Parallel Scan*) виконує обчислення за два проходи по бінарному дереву обчислень:
1. **Прямий хід (Up-Sweep / Reduce)**: Дерево обчислює суми піддерев від листя до кореня. За `log N` кроків у корені формується загальна сума масиву.
2. **Зворотний хід (Down-Sweep)**: Значення з кореня розповсюджуються вниз до листя, будуючи ексклюзивні префіксні суми.

На відміну від алгоритму Хілліса — Стіла, алгоритм Блеллока є **робоче-оптимальним** (*Work-Efficient*): він виконує `O(N)` загальних операцій додавання, що робить його ідеальним для тисяч паралельних потоків у блоках CUDA із використанням швидкої розділюваної пам'яті (*Shared Memory*).

### 7. Покрокове трасування та аналіз пасток обробки

#### 7.1. Трасування виконання пошуку за модулем m = 5

Проілюструємо покрокову роботу алгоритму `find_subarray_divisible_by_m` на прикладі масиву `arr = [4, 2, 7, 3, 5, 1]` при `m = 5`.

1. **Ініціалізація**: Створюємо таблицю `first_seen` розміром 5. Заповнюємо значеннями `-1`. Записуємо `first_seen[0] = 0` (початкова порожня сума).
2. **Ітерація `j = 0` (`arr[0] = 4`)**:
   - `current_prefix = 0 + 4 = 4`
   - `rem = 4 % 5 = 4`
   - `first_seen[4]` дорівнює `-1` -> Записуємо `first_seen[4] = 1`.
3. **Ітерація `j = 1` (`arr[1] = 2`)**:
   - `current_prefix = 4 + 2 = 6`
   - `rem = 6 % 5 = 1`
   - `first_seen[1]` дорівнює `-1` -> Записуємо `first_seen[1] = 2`.
4. **Ітерація `j = 2` (`arr[2] = 7`)**:
   - `current_prefix = 6 + 7 = 13`
   - `rem = 13 % 5 = 3`
   - `first_seen[3]` дорівнює `-1` -> Записуємо `first_seen[3] = 3`.
5. **Ітерація `j = 3` (`arr[3] = 3`)**:
   - `current_prefix = 13 + 3 = 16`
   - `rem = 16 % 5 = 1`
   - `first_seen[1]` вже дорівнює `2` (значення не `-1`). **Знайдено колізію залишків!**
   - Шуканий підмасив починається з індексу `start_idx = first_seen[1] = 2` і закінчується на `end_idx = 3`.
   - В 0-індексації це елементи `arr[2..3] = [7, 3]`. Сума: `7 + 3 = 10 ≡ 0 (mod 5)`.

Алгоритм завершується успішно за 4 кроки, знайшовши підмасив із сумою, кратною 5.

#### 7.2. Пастки реалізації та рекомендації для виробничого коду

При впровадженні префіксних сум у реальні системи слід зважати на кілька типових розробницьких пасток:

1. **Неузгодженість індексації в інтерфейсах API.** У деяких бібліотеках запити сум приймають напіввідкриті інтервали `[l, r)`, а в інших — закриті відрізки `[l, r]`. У поданих реалізаціях застосовано суворо закриті інтервали `[l, r]`, що вимагає виразу `P[r + 1] - P[l]`. Зміна інтерфейсу на напіввідкритий `[l, r)` спрощує формулу до `P[r] - P[l]`.
2. **Переповнення при 2D підсумовуванні.** У двовимірній формулі `P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]` проміжна сума доданків може тимчасово перевищувати межі цілочисельного типу, навіть якщо фінальний результат вміщується у діапазон. Використання 64-бітних типів `int64_t` є обов'язковим для уникнення залишків від знакового переповнення.
3. **Модифікація вихідного масиву під час роботи.** Статичний префіксний масив стає невалідним при будь-якій зміні вихідних даних. Якщо дані змінюються в процесі виконання програми, слід переходити до дерев Фенвіка або дерева відрізків (*Segment Tree*).

### Порівняльний підсумок ефективності та вибір алгоритму

Нижче наведено зведений порівняльний аналіз п'яти реалізованих паттернів за складністю та сферою застосування:

| Алгоритмічний паттерн | Час побудови | Час запиту | Додаткова пам'ять | Основний сценарій використання |
|---|---|---|---|---|
| **1D Prefix Sum** | `O(N)` | `O(1)` | `O(N)` | `Read-Heavy`: багаторазові суми на статичних відрізках |
| **1D Difference Array** | `O(1)` на додавання | `O(N)` відновлення | `O(N)` | `Write-Heavy`: масові групові додавання на відрізках |
| **2D Prefix Sum** | `O(R · C)` | `O(1)` | `O(R · C)` | Комп'ютерний зір, прямокутні фільтри та інтегральні карти |
| **3D Prefix Sum** | `O(X · Y · Z)` | `O(1)` | `O(X · Y · Z)` | Томографія, 3D графіка та воксельні поля |

Завдяки цим шаблонам інженер отримує повний інструментарій для роботи з сумами на послідовностях і сітках будь-якої вимірності.
