# Генератор досконалих чисел (C++)

У цьому практичному проєкті ми реалізуємо скрипт мовою C++17, який застосовує теорему Евкліда — Ейлера для ефективного пошуку парних досконалих чисел. Замість того, щоб наївно перевіряти кожне натуральне число (що є надзвичайно повільним і обчислювально затратним процесом через необхідність факторизації), ми будемо генерувати прості числа Мерсенна та безпосередньо конструювати досконалі числа за доведеною формулою Евкліда.

## Постановка задачі

Мета нашого скрипта — знайти всі досконалі числа, що генеруються простими числами Мерсенна 2ᵖ − 1 для p ≤ 31. Для підтвердження правильності результату ми маємо не лише згенерувати число за формулою N = 2ᵖ⁻¹(2ᵖ − 1), але й незалежно перевірити його, обчисливши суму всіх його дільників за допомогою окремої функції та переконавшись, що σ(N) = 2N. Це слугує емпіричною верифікацією теореми Евкліда — Ейлера.

## Архітектурна логіка

Архітектура програми розбита на п'ять чітких логічних компонентів, кожен з яких відповідає за свою частину процесу:
1. **Конфігурація**: Глобальні налаштування, що визначають межі пошуку (наприклад, максимальне значення показника степеня p).
2. **Типи даних**: Використання 64-бітних цілих чисел без знаку (`unsigned long long`), оскільки досконалі числа дуже швидко зростають і виходять за межі звичайного 32-бітного `int`. Третє досконале число вже дорівнює 496, а п'яте — 33550336.
3. **Обчислювальні примітиви**: Функції для перевірки простоти числа та обчислення суми всіх дільників σ(n).
4. **Ядро генерації**: Основний цикл, який перебирає показники p, перевіряє їх на простоту, обчислює потенційне просте Мерсенна і перевіряє його простоту. Якщо воно просте, формується досконале число.
5. **Ввід-вивід (CLI)**: Виведення результатів та незалежна верифікація з форматованим звітом.

## Розбір коду

Нижче наведено повний вихідний код програми.

```cpp
#include <iostream>
#include <vector>
#include <cmath>

// 1. Конфігурація та параметри
struct Config {
    int max_p = 31; // Максимальний показник степеня p для перевірки
};

// 2. Стан та базові типи
using ull = unsigned long long;

struct PerfectNumberRecord {
    int p;
    ull mersenne_prime;
    ull perfect_number;
};

// 3. Логіка: Перевірка на простоту та функція сигма
bool is_prime(ull n) {
    if (n < 2) return false;
    if (n == 2 || n == 3) return true;
    if (n % 2 == 0 || n % 3 == 0) return false;
    for (ull i = 5; i * i <= n; i += 6) {
        if (n % i == 0 || n % (i + 2) == 0) {
            return false;
        }
    }
    return true;
}

ull sigma_sum(ull n) {
    ull sum = 0;
    for (ull i = 1; i <= std::sqrt(n); ++i) {
        if (n % i == 0) {
            sum += i;
            if (i != 1 && i * i != n) {
                sum += n / i;
            }
        }
    }
    return sum + n; // Додаємо саме число
}

// 4. Обчислювальне ядро
std::vector<PerfectNumberRecord> generate_perfect_numbers(const Config& cfg) {
    std::vector<PerfectNumberRecord> results;
    
    // Перевіряємо лише прості p, оскільки 2^p - 1 може бути простим лише для простого p
    for (int p = 2; p <= cfg.max_p; ++p) {
        if (!is_prime(p)) continue;
        
        ull mersenne = (1ULL << p) - 1; // 2^p - 1
        
        if (is_prime(mersenne)) {
            ull perfect = (1ULL << (p - 1)) * mersenne; // 2^{p-1} * (2^p - 1)
            results.push_back({p, mersenne, perfect});
        }
    }
    
    return results;
}

// 5. Ввід-вивід та точка входу
int main() {
    Config cfg;
    std::cout << "Генерація досконалих чисел за теоремою Евкліда-Ейлера...\n";
    std::cout << "Перевірка до p = " << cfg.max_p << "\n\n";
    
    auto records = generate_perfect_numbers(cfg);
    
    for (const auto& rec : records) {
        std::cout << "p = " << rec.p << "\n";
        std::cout << "Просте Мерсенна 2^p - 1: " << rec.mersenne_prime << "\n";
        std::cout << "Досконале число N: " << rec.perfect_number << "\n";
        
        // Верифікація через сигма-функцію
        ull sum_divs = sigma_sum(rec.perfect_number);
        std::cout << "Перевірка: σ(N) = " << sum_divs << " (очікується " << 2 * rec.perfect_number << ")\n";
        if (sum_divs == 2 * rec.perfect_number) {
            std::cout << "Успіх: Число підтверджено як досконале.\n";
        } else {
            std::cout << "Помилка: Число не є досконалим!\n";
        }
        std::cout << "----------------------------------------\n";
    }
    
    return 0;
}
```

### Покроковий розбір

Функція `is_prime` використовує класичний алгоритм перевірки дільників до √n з оптимізацією кроку (пропускаючи числа, кратні 2 та 3). Вона дозволяє швидко переконатися, чи є показник p простим, і чи є отримане число 2ᵖ − 1 простим Мерсенна.

Функція `sigma_sum` безпосередньо симулює означення функції суми дільників σ(n). Вона також працює за час O(√n), обережно додаючи обидва дільники `i` та `n / i` за один крок циклу, уникаючи подвійного додавання у випадку, коли `i * i == n`. Наприкінці вона додає саме число `n`. Ця функція є найбільш обчислювально затратною в нашому скрипті.

У функції `generate_perfect_numbers` ми робимо важливу математичну оптимізацію: замість перевірки всіх підряд p, ми перевіряємо лише ті p, які вже є простими. Це спирається на відому теорему: якщо 2ᵖ − 1 є простим, то й показник p зобов'язаний бути простим (але не навпаки). Це суттєво зменшує кількість ітерацій. Операція зсуву бітів `1ULL << p` швидко і ефективно обчислює 2ᵖ.

## Аналіз складності (I/O Complexity)

Часова складність генерації:
Для кожного p до `max_p` алгоритм перевіряє простоту p за O(√p), а потім, якщо p просте, перевіряє простоту 2ᵖ − 1 за O(√(2ᵖ)) = O(2^(p/2)). Загальна складність генерації домінується експоненційною перевіркою простоти числа Мерсенна і становить O(2^(max_p / 2)). У нашому випадку для p ≤ 31 це близько 2¹⁵ ≈ 32000 ітерацій, що виконується миттєво. Проте для значно більших p цей наївний тест простоти стане занадто повільним, і для чисел Мерсенна знадобиться спеціалізований тест Люка-Лемера, який працює за O(p²) операцій множення довгих чисел.

Часова складність верифікації:
Для кожного згенерованого досконалого числа N ≈ 2²ᵖ, обчислення суми дільників у функції `sigma_sum` займає O(√N) = O(2ᵖ) операцій. Це цілком ефективно для перших 7-8 досконалих чисел, що поміщаються у 64-бітний тип, але було б неможливо застосувати для верифікації гігантських досконалих чисел без використання теореми Евкліда-Ейлера, яка зводить обчислення σ(N) до мультиплікативних властивостей.

Просторова складність складає O(K), де K — кількість знайдених досконалих чисел, оскільки ми зберігаємо лише результати у векторі для подальшого виводу. Таким чином, програма вкрай економна щодо пам'яті.
