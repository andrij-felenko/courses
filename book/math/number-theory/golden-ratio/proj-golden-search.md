# ⚙️ Пошук золотого перетину: одновимірна оптимізація в коді

Метод золотого перетину (*Golden Section Search*) — це класичний та надзвичайно надійний алгоритм знаходження локального екстремуму (мінімуму або максимуму) одновимірної унімодальної функції на заданому відрізку `[a, b]` без використання похідних. Його головна практична перевага полягає у винятковій ефективності використання обчислень: на кожному кроці інтервал локалізації звужується в один і той самий фіксований коефіцієнт `1/φ ≈ 0.618034`, але завдяки унікальній геометрії золотого перетину одна з двох нових внутрішніх точок збігається з уже обчисленою точкою з попереднього кроку. Це дозволяє послідовно зменшувати інтервал пошуку, виконуючи лише **одне нове обчислення цільової функції за ітерацію**. Практична реалізація алгоритму ґрунтується на збереженні стану обчислених точок у пам'яті: під час кожної ітерації оновлюються лише координати й значення в одній новопроведеній точці, тоді як друга точка разом із готовим значенням цільової функції перевикористовується з попереднього кроку без додаткових обчислювальних витрат.

Аналіз стійкости та амортизованої вартості процедури підтверджує, що коефіцієнт `1/φ` дає теоретично мінімальну кількість оцінок цільової функції серед усіх аперіодичних алгоритмів одновимірної оптимізації без використання похідних.

## Ідея та геометричний фокус збереження обчислень

Нехай цільова функція `f(x)` є суворо унімодальною на відрізку `[a, b]`, тобто має на ньому єдиний локальний мінімум і не має інших локальних екстремумів чи плато. Для звуження інтервалу потрібно обрати две внутрішні випробувальні точки `x₁` та `x₂` такі, що `a < x₁ < x₂ < b`.

Обчисливши значення функції `f(x₁)` та `f(x₂)`, ми порівнюємо їх між собою і робимо один із двох логічних висновків:
- Якщо `f(x₁) < f(x₂)`, то шуканий мінімум не може лежати в правій частині `(x₂, b]`. Новим інтервалом локалізації стає відрізок `[a, x₂]`.
- Якщо `f(x₁) ≥ f(x₂)`, то шуканий мінімум не може лежати в лівій частині `[a, x₁)`. Новим інтервалом локалізації стає відрізок `[x₁, b]`.

Щоб довжина інтервалу зменшувалася з однаковим коефіцієнтом `K` незалежно від того, яка саме гілка умови виявиться виграшною, точки `x₁` та `x₂` мусять бути розташовані строго симетрично відносно кінців вихідного інтервалу:

```
x₁ = b − K · (b − a)
x₂ = a + K · (b − a)
```

Головний фокус алгоритму полягає у виборі коефіцієнта `K`. Припустимо, що на черговому кроці ми обрали новий інтервал `[a, x₂]` довжиною `L' = K · (b − a)`. Ми бажаємо, щоб точка `x₁`, яка вже лежить усередині цього нового інтервалу `[a, x₂]`, виявилася точно новою правою внутрішньою точкою для `[a, x₂]`.

Це означає, що відношення відстаней має задовольняти рівняння:

```
(x₂ − x₁) / (x₂ − a)  =  (x₁ − a) / (x₂ − a)
```

Записавши ці відстані через коефіцієнт `K`, ми отримуємо квадратне рівняння для частки збереження довжини:

```
1 − K = K²     ⟹     K² + K − 1 = 0
```

Єдиним додатним дійсним коренем цього рівняння є коефіцієнт, обернений до золотого перетину:

```
K = (√5 − 1) / 2 = 1 / φ ≈ 0.6180339887...
```

Завдяки цьому геометричному вибору на кожному кроці алгоритм повторно використовує вже обчислене значення функції в точці `x₁` або `x₂`, зменшуючи довжину інтервалу в `φ ≈ 1.618034` раза за ціною всього **одного** нового виклику `f(x)`.

## Формальне математичне доведення збереження точки

Доведемо строгим алгебраїчним розрахунком, що при переході від інтервалу `[a, b]` до нового інтервалу `[a, x₂]` стара ліва точка `x₁` виявляється новою правою точкою `x₂'`.

Вихідні точки на відрізку `[a, b]`:

```
x₁ = b − (1/φ)(b − a)
x₂ = a + (1/φ)(b − a)
```

Нехай `f(x₁) < f(x₂)`. Зменшуємо інтервал: новими межами стають `a' = a`, `b' = x₂ = a + (1/φ)(b − a)`.
Довжина нового інтервалу становить `L' = b' − a' = (1/φ)(b − a)`.

Обчислимо нову праву внутрішню точку `x₂'` для інтервалу `[a', b']`:

```
x₂' = a' + (1/φ)(b' − a') = a + (1/φ) · [ (1/φ)(b − a) ] = a + (1/φ²)(b − a)
```

Згадаємо фундаментальну тотожність `1/φ² = 1 − 1/φ`. Підставити її у вираз для `x₂'`:

```
x₂' = a + (1 − 1/φ)(b − a) = a + (b − a) − (1/φ)(b − a) = b − (1/φ)(b − a) = x₁
```

Тотожність `x₂' = x₁` доведено строго. Це означає, що точка `x₁` уже зафіксована у пам'яті комп'ютера, її значення `f(x₁)` вже обчислено, і його не потрібно повторно обчислювати на новій ітерації!

Аналогічно, при виборі гілки `f(x₁) ≥ f(x₂)` новим інтервалом стає `[x₁, b]`, а стара точка `x₂` точно збігається з новою лівою точкою `x₁'`.

## Покроковий алгоритм та числове простеження

Розглянемо алгоритм кроковим способом:

1. **Ініціалізація:** Приймаємо початковий інтервал `[a, b]` та задану точність зупинки `eps > 0`.
2. Обчислити початкові внутрішні точки:
   ```
   inv_phi = (√5 - 1) / 2 ≈ 0.6180339887
   x₁ = b - inv_phi * (b - a)
   x₂ = a + inv_phi * (b - a)
   ```
3. Обчислюємо значення функції в обох початкових точках: `f₁ = f(x₁)`, `f₂ = f(x₂)`.
4. **Основний цикл звуження:** Доки довжина інтервалу перевищує поріг `|b - a| > eps`:
   - Якщо `f₁ < f₂`:
     - Права межа переміщується: `b = x₂`.
     - Права внутрішня точка стає новою лівою: `x₂ = x₁`, `f₂ = f₁`.
     - Обчислюємо лише одну нову ліву точку: `x₁ = b - inv_phi * (b - a)` та `f₁ = f(x₁)`.
   - Інакше (`f₁ ≥ f₂`):
     - Ліва межа переміщується: `a = x₁`.
     - Ліва внутрішня точка стає новою правою: `x₁ = x₂`, `f₁ = f₂`.
     - Обчислюємо лише одну нову праву точку: `x₂ = a + inv_phi * (b - a)` та `f₂ = f(x₂)`.
5. **Завершення:** Повертаємо центр підсумкового інтервалу `(a + b) / 2` як оцінку точки мінімуму.

Простежимо роботу алгоритму чисельно на прикладі функції `f(x) = (x − 3)² + 2` на початковому інтервалі `[a, b] = [0, 10]`. Справжній мінімум знаходиться у точці `x* = 3.0` зі значенням `f(x*) = 2.0`.

Початкові точки:
- `inv_phi = 0.618034`
- `x₁ = 10 − 0.618034 · 10 = 3.819660`, `f(x₁) = (3.819660 − 3)² + 2 = 2.671828`
- `x₂ = 0 + 0.618034 · 10 = 6.180340`, `f(x₂) = (6.180340 − 3)² + 2 = 12.112486`

За `N` ітерацій початковий інтервал довжиною `L₀` звужується до величини `L_N = L₀ · (1/φ)ᴺ`. Кількість ітерацій, необхідних для досягнення бажаної точності `eps`, обчислюється аналітично:

```
N = ⌈ log(eps / L₀) / log(1/φ) ⌉  ≈  ⌈ 2.078 · ln(L₀ / eps) ⌉
```

Для прикладу, щоб зменшити інтервал довжиною `L₀ = 10` до точності `eps = 1e-8`, алгоритму потрібно лише `N = ⌈ 2.078 · ln(10 / 1e-8) ⌉ = 43` ітерацій, що вимагає всього 44 обчислень цільової функції.

## Порівняльний аналіз із суміжними методами оптимізації

Щоб зрозуміти нішу методу золотого перетину, порівняємо його з трьома альтернативними підходами до одновимірної оптимізації:

### 1. Метод дихотомії (послідовного ділення навпіл)
У звичайному методі дихотомії на кожному кроці обирають дві точки біля серединного значення: `x₁ = m − δ`, `x₂ = m + δ`. Інтервал звужується вдвічі (`K = 0.5`), але алгоритм вимагає **двох нових обчислень функції за крок**.

Для зменшення інтервалу в `10⁶` разів:
- Дихотомія вимагає `N ≈ log₂(10⁶) ≈ 20` кроків, що означає `20 × 2 = 40` обчислень функції.
- Золотий перетин вимагає `N ≈ log_φ(10⁶) ≈ 29` кроків, що означає `29 + 1 = 30` обчислень функції.

Метод золотого перетину вимагає на **25–30% менше викликів цільової функції**, що робить його істотно швидшим на важких обчислювальних функціях.

### 2. Метод Брента (Brent's Method)
Метод Брента поєднує метод золотого перетину із параболічною інтерполяцією (обратною квадратичною інтерполяцією). Якщо функція є гладкою (двічі диференційовною), параболічна інтерполяція будує через 3 точки параболу й стрибає в її мінімум із суперлінійною швидкістю збіжності `O(1.324)`. Якщо ж параболічна інтерполяція дає точки за межами інтервалу або збігається надто повільно, метод Брента автоматично повертається до надійного кроку золотого перетину. Метод Брента вважається золотим стандартом у бібліотеках `SciPy` (`scipy.optimize.minimize_scalar`) та `Boost.Math`.

### 3. Метод Ньютона–Рафсона
Якщо функція має легкообчислювані першу та другу похідні `f'(x)` та `f''(x)`, метод Ньютона шукає нуль першої похідної за формулою `xₙ₊₁ = xₙ − f'(xₙ)/f''(xₙ)` із квадратичною швидкістю `O(N²)`. Проте якщо похідні недоступні, обчислюються з шумними похибками або функція має злами (недиференційовна у точці мінімуму), метод Ньютона розвалюється. Метод золотого перетину не вимагає існування похідних взагалі — йому потрібна лише неперервна унімодальність.

## Застосування як підпрограми лінійного пошуку (Line Search)

У багатовимірній оптимізації (наприклад, у методі Пауелла, покоординатного спуску або методі сопряжених градієнтів) на кожній макро-ітерації виникає задача знаходження мінімуму векторної функції `F(x₁, x₂, ..., xₙ)` уздовж заданого напрямку `d ∈ ℝⁿ`.

Цю задачу зводять до одновимірної мінімізації цільової функції одного скалярного параметра `α`:

```
g(α) = F(x₀ + α · d)
```

Для знаходження оптимального кроку `α*` алгоритми багатовимірного спуску викликають метод золотого перетину як надійну й стійку внутрішню підпрограму (*line search subroutine*). Оскільки обчислення векторної функції `F` може бути надзвичайно дорогим, мінімізація кількості викликів `F` за рахунок збереження точок золотого перетину дає прямий приріст швидкості усієї системи багатовимірного аналізу.

У задачах машинного навчання алгоритм використовується для одновимірного оптимізаційного підбору коефіцієнтів L1/L2 регуляризації (*hyperparameter tuning*). Оскільки обчислення втрат моделі (*loss function*) на великих датасетах є високовартісним, збереження точки на кожній ітерації дає прямий приріст продуктивності фази навчального тренування.

Також у робототехніці та автопілотах золотий перетин застосовується для одномірного вирівнювання траєкторії руху рульового приводного механізму у режимі реального часу.

Окрім цього, у фізичному моделюванні та обчислювальній біофізиці метод використовують для швидкої мінімізації конформаційної енергії молекулярних зв'язків уздовж кутів обертання (*torsion angles*).

## Масштабування та паралелізація на графичних прискорювачах (GPU)

На масивно паралельних архітектурах (GPU CUDA / OpenCL) метод золотого перетину демонструє виняткову ефективність завдяки відсутності розходження обчислювальних потоків (*warp divergence*):
- Кожен обчислювальний потік виконує оптимізацію власного параметричного каналу незалежно.
- Кількість ітерацій `N` є однаковою для всіх потоків варпу при фіксованій точності `eps`.
- Пам'ять для збереження проміжних значень `f(x₁)` та `f(x₂)` потребує лише 2 регістри на потік, що повністю виключає звернення до повільної локальної або глобальної пам'яті.

Кожен векторний процесор (SIMD-ядро) може одночасно обробляти до 1024 незалежних одномірних оптимізаційних задач без виникнення спин-блокувань.

## Оптимізація шаблонів C++20 та концепт std::invocable

У сучасному стандарті C++20 функціональний аргумент цільової функції доцільно обмежувати концептом `std::invocable`:

:::tabs
```c
/* У мові C тип функції передається через стандартний вказівник */
typedef double (*c_target_func_t)(double);
```
```cpp
#include <concepts>

namespace math::optimization {

template <typename Func>
requires std::invocable<Func, double> && 
         std::same_as<std::invoke_result_t<Func, double>, double>
SearchResult golden_section_search_concept(
    Func&& func, double a, double b, double eps = 1e-7);

} // namespace math::optimization
```
:::

Це дозволяє під час компіляції перевіряти сумісність типи й повністю усувати overhead віртуальних викликів через вказівник.

## Профіль використання оперативної пам'яті

Алгоритм має нульовий розмір динамічної пам'яті `O(1)` додаткової просторової складності (*space complexity*). Усі робочі змінні `a, b, x1, x2, f1, f2` розміщуються виключно в процесорних регістрах або стековому кадрі функції. Відсутність операцій виділення пам'яті (`malloc` або `new`) гарантує детермінований час виконання без паузи на збір сміття, що є критично важливим для систем реального часу (*real-time systems*).

Усі вхідні дані та проміжні обчислення не виходять за межі L1-кешу процесора, що виключає тривалі затримки доступу до системної пам'яті (RAM).

Алгоритм пошуку золотого перетину успішно застосовується в аналізі сигналів, адаптивній фільтрації, машинному навчанні для гіперпараметричної настройки та задач розрахунку фазових рівноваг у термодинаміці.

## Чисельний аналіз межі точності у плаваючій точці

У стандартній 64-бітній арифметиці IEEE 754 (`double`) машинний епсилон становить `ε_mach ≈ 2.22 × 10⁻¹⁶`. Розкладемо цільову функцію `f(x)` у ряд Тейлора біля точки мінімуму `x*`:

```
f(x*) + (1/2) f''(x*) (x − x*)²
```

Точність порівняння значень `f(x₁)` та `f(x₂)` обмежена тим моментом, коли квадратична різниця `(1/2) f''(x*) (x − x*)²` стає меншою за чисельний шум `ε_mach · |f(x*)|`. Звідси випливає фундаментальна межа локалізації мінімуму за довжиною інтервалу:

```
(b − a)_min ≈ √ε_mach · │x*│  ≈  10⁻⁸ · │x*│
```

Спроба встановити поріг зупинки `eps < 1e-8` при використанні типів `double` призводить до чисельного скасування (*cancellation error*), випадкових коливань гілок `f1 < f2` та нескінченного зациклення.

## Варіація: Пошук Фібоначчі (Fibonacci Search)

Якщо кількість ітерацій `N` фіксована заздалегідь, замість константи `1/φ` можна використовувати точні відношення чисел Фібоначчі:

```
K☿ = F_{N-k} / F_{N-k+1}
```

Алгоритм Фібоначчі є математично оптимальним дискретним алгоритмом: для фіксованого `N` він дає найменший можливий інтервал локалізації серед усіх методів порівняння значень функції.

Розглянемо реалізацію алгоритму пошуку Фібоначчі мовами C та C++ у порівняльних вкладках:

:::tabs
```c
#include <stdio.h>

/* Обчислює n-е число Фібоначчі */
static unsigned long fibonacci(int n) {
    unsigned long a = 0, b = 1;
    for (int i = 0; i < n; ++i) {
        unsigned long c = a + b;
        a = b;
        b = c;
    }
    return a;
}

double fibonacci_search(double (*func)(double), double a, double b, int n) {
    double x1 = a + (double)fibonacci(n - 2) / fibonacci(n) * (b - a);
    double x2 = a + (double)fibonacci(n - 1) / fibonacci(n) * (b - a);
    double f1 = func(x1);
    double f2 = func(x2);

    for (int k = n; k > 2; --k) {
        if (f1 < f2) {
            b = x2;
            x2 = x1;
            f2 = f1;
            x1 = a + (double)fibonacci(k - 3) / fibonacci(k - 1) * (b - a);
            f1 = func(x1);
        } else {
            a = x1;
            x1 = x2;
            f1 = f2;
            x2 = a + (double)fibonacci(k - 2) / fibonacci(k - 1) * (b - a);
            f2 = func(x2);
        }
    }
    return (a + b) / 2.0;
}
```
```cpp
#include <vector>
#include <functional>
#include <cmath>

namespace math::optimization {

double fibonacci_search(
    const std::function<double(double)>& func,
    double a,
    double b,
    std::size_t n)
{
    std::vector<unsigned long long> F(n + 1);
    F[0] = 0; F[1] = 1;
    for (std::size_t i = 2; i <= n; ++i) F[i] = F[i - 1] + F[i - 2];

    double x1 = a + static_cast<double>(F[n - 2]) / F[n] * (b - a);
    double x2 = a + static_cast<double>(F[n - 1]) / F[n] * (b - a);
    double f1 = func(x1);
    double f2 = func(x2);

    for (std::size_t k = n; k > 2; --k) {
        if (f1 < f2) {
            b = x2;
            x2 = x1;
            f2 = f1;
            x1 = a + static_cast<double>(F[k - 3]) / F[k - 1] * (b - a);
            f1 = func(x1);
        } else {
            a = x1;
            x1 = x2;
            f1 = f2;
            x2 = a + static_cast<double>(F[k - 2]) / F[k - 1] * (b - a);
            f2 = func(x2);
        }
    }
    return (a + b) / 2.0;
}

} // namespace math::optimization
```

## Адаптація для пошуку максимуму

Щоб перетворити алгоритм пошуку мінімуму на пошук **максимуму** унімодальної функції `f(x)`, достатньо змінити знаки в умовах порівняння функцій:
- Якщо `f₁ > f₂`, локальний максимум лежить на інтервалі `[a, x₂]`. Права межа переміщується `b = x₂`.
- Якщо `f₁ ≤ f₂`, локальний максимум лежить на інтервалі `[x₁, b]`. Ліва межа переміщується `a = x₁`.

Альтернативно можна зауважити, що максимум функції `f(x)` відповідає мінімуму функції `g(x) = −f(x)`, що дозволяє використовувати код мінімізації без жодних змін.

## Захист від шуму та поведінка на негладких функціях

У практичних обчисленнях цільова функція `f(x)` часто обчислюється з чисельним шумом (наприклад, через округлення у виразах з плаваючою точкою або дискретизацію сітки симуляції):

```
f_obs(x) = f(x) + ε_noise(x)
```

Градієнтні методи (градієнтний спуск, метод Ньютона, BFGS) на шумних функціях зазнають катастрофічного розвалу: чисельне диференціювання `f'(x) ≈ (f(x+h) - f(x))/h` множить похибок на `1/h`, через що обчислені градієнти стають хаотичними векторами.

Натомість метод золотого перетину порівнює тільки значущі макро-значення функції `f(x₁)` та `f(x₂)` на відрізках макроскопічної довжини. Доки амплітуда шуму `|ε_noise|` значно менша за різницю макро-значень `|f(x₁) - f(x₂)|`, метод золотого перетину зберігає сувору монотонію звуження інтервалу і надійно знаходить околицю мінімуму.

Також метод чудово працює на недиференційовних функціях із гострими зламами (наприклад, `f(x) = |x - 3| + |2x - 5|`), де похідна не існує в точці мінімуму.

## Ніша в мікроконтролерах та вбудованих системах

У мікроконтролерах без апаратного дільника (наприклад, 8-бітових процесорах серії AVR, PIC або м'яких ядрах FPGA) виконання floating-point ділення `(b - a) / 2.0` забирає сотні тактів процесора.

Метод золотого перетину дозволяє уникнути ділення в циклі: коефіцієнт `INV_PHI ≈ 0.6180339887` обчислюється на етапі компіляції або подається як фіксована константа. Оновлення координат `x₁` та `x₂` вимагає лише однієї операції множення та віднімання.

:::tabs
```c
double x1 = b - (b - a) * INV_PHI;
```
```cpp
double x1 = b - (b - a) * inv_phi;
```
:::

У виразах з фіксованою точкою (*fixed-point arithmetic*) константу `INV_PHI` подають у форматі Q31 або Q16:

:::tabs
```c
int32_t inv_phi_q31 = 1327172048; // floor(0.6180339887 * 2^31)
int32_t x1 = b - (int32_t)(((int64_t)(b - a) * inv_phi_q31) >> 31);
```
```cpp
constexpr int32_t inv_phi_q31 = 1327172048; // floor(0.6180339887 * 2^31)
int32_t x1 = b - static_cast<int32_t>((static_cast<int64_t>(b - a) * inv_phi_q31) >> 31);
```
:::

Це дозволяє оптимізувати обчислювальний цикл до кількох базових процесорних інструкцій.

## Реалізація мовами C та C++

Нижче наведено ідіоматичні реалізації оптимізації методом золотого перетину мовами C та C++.

:::tabs
```c
#include <stdio.h>
#include <math.h>

/* Константа inv_phi = (sqrt(5) - 1) / 2 */
#define INV_PHI 0.61803398874989484820

typedef double (*target_func_t)(double);

/*
 * Знаходить мінімум унімодальної функції func на інтервалі [a, b] з точністю eps.
 * Повертає абсцису знайденого мінімуму.
 */
double golden_section_search(target_func_t func, double a, double b, double eps, int *eval_count) {
    double x1 = b - INV_PHI * (b - a);
    double x2 = a + INV_PHI * (b - a);
    double f1 = func(x1);
    double f2 = func(x2);
    
    int evals = 2;

    while (fabs(b - a) > eps) {
        if (f1 < f2) {
            b = x2;
            x2 = x1;
            f2 = f1;
            x1 = b - INV_PHI * (b - a);
            f1 = func(x1);
        } else {
            a = x1;
            x1 = x2;
            f1 = f2;
            x2 = a + INV_PHI * (b - a);
            f2 = func(x2);
        }
        evals++;
    }

    if (eval_count) {
        *eval_count = evals;
    }

    return (a + b) / 2.0;
}

/* Приклад: f(x) = (x - 3)^2 + 2, мінімум у x = 3.0 */
static double sample_function(double x) {
    return (x - 3.0) * (x - 3.0) + 2.0;
}

int main(void) {
    double a = 0.0, b = 10.0, eps = 1e-7;
    int evals = 0;
    
    double min_x = golden_section_search(sample_function, a, b, eps, &evals);
    
    printf("C Result: min_x = %.8f, f(min_x) = %.8f (evals = %d)\n", 
           min_x, sample_function(min_x), evals);
    
    return 0;
}
```

```cpp
struct SearchResult {
    double min_x;

    std::size_t eval_count;

 * Обчислює мінімум унімодальної функції func на інтервалі [a, b].
 * Використовує std::function для гнучкої передачі лямбда-виразів та функторів.

    const std::function<double(double)>& func,
    double a,
    double b,
    double eps = 1e-7) 
{
    double x1 = b - inv_phi * (b - a);
    double x2 = a + inv_phi * (b - a);
    double f1 = func(x1);
    double f2 = func(x2);
    
    std::size_t evals = 2;

    while (std::abs(b - a) > eps) {
        if (f1 < f2) {
            b = x2;
            x2 = x1;
            f2 = f1;
            x1 = b - inv_phi * (b - a);

            a = x1;
            x1 = x2;
            f1 = f2;
            x2 = a + inv_phi * (b - a);
            f2 = func(x2);
        }
        ++evals;
    }

    double best_x = (a + b) / 2.0;
    return SearchResult{best_x, func(best_x), evals};
}
```

## Практичні застереження, крайові випадки та вибір точності

При використанні методу в реальних обчислювальних проектах слід враховувати такі технічні деталі:

1. **Вимога суворої унімодальності:** Метод ґрунтується на припущенні, що функція має єдиний мінімум на `[a, b]`. Якщо функція має декілька локальних мінімумів (мультимодальна), алгоритм зійдеться до одного з локальних ярів залежно від початкового інтервалу, не гарантуючи знаходження глобального мінімуму. Для мультимодальних функцій рекомендується спочатку провести сіткове сканування (Grid Search), визначити унімодальний відрізок, а потім передати його методу золотого перетину.
2. **Відносна точність та захист від зациклення:** У наведеному коді умова зупинки задається як `|b - a| > eps`. Якщо значення `x` дуже великі за модулем (наприклад, `x ≈ 1e12`), абсолютна різниця `b - a` не зможе опуститися нижче машинного епсилона для чисел типу `double` (`DBL_EPSILON ≈ 2.22e-16`). Рекомендовано застосовувати комбіновану умову зупинки:
   ```cpp
   while (std::abs(b - a) > eps * (std::abs(x1) + std::abs(x2)) + 1e-15)
   ```
3. **Обчислювальна вартість функції:** Метод золотого перетину випереджає всі інші методи градієнтного типу в ситуаціях, коли обчислення `f(x)` вимагає виконання важкої чисельної симуляції (наприклад, розв'язання системи диференційних рівнянь, скінченно-елементний аналіз балки або прогон тривимірної гідродинамічної сітки). У таких задачах кожне збережене обчислення цільової функції прямо заощаджує хвилини або години процесорного часу.

У результаті метод виступає золотим стандартом базової одновимірної оптимізації без похідних у багатьох інженерних та фізичних обчисленнях.
