# ⚙️ Символ Якобі за O(log): робочий код

Закон взаємності — це не лише теорема, а готовий алгоритм: він згортає питання «чи є a квадратом за модулем n» у короткий цикл, що працює за час [алгоритму Евкліда](book:math/gcd-euclidean) і ні разу не розкладає n на прості. Саме здатність рахувати символ **без розкладу** й робить його вартим програмування — розклад великого числа сам по собі важкий, а тут він просто не потрібен.

## Що саме рахуємо і чому не «в лоб»

Символ Лежандра (a|p) можна дістати критерієм Ейлера — піднести a до степеня (p−1)/2 за модулем p і глянути, вийшло +1 чи −1. Спосіб чесний, але має дві вади. По-перше, він тримається на тому, що модуль простий: для складеного n величина a^((n−1)/2) уже не зобов'язана дорівнювати символу, а щоб порахувати (a|n) через його означення — добуток символів за простими дільниками — довелося б спершу n **розкласти**, чого ми й уникаємо. По-друге, навіть для простого модуля піднесення до степеня — це десятки [модульних множень](book:math/modular-exponentiation), і кожне перемножує два великі числа.

Мета інша: рахувати (a|n) для **будь-якого** непарного n, швидко й без розкладу. Ключ дає закон взаємності разом із двома доповненнями — вони дозволяють крок за кроком зменшувати числа так само, як їх зменшує пошук найбільшого спільного дільника.

## Ідея: три дії по колу

Символ Якобі (a|n) визначений для непарного n і перемножується так само, як розкладається число: (ab|n) = (a|n)·(b|n). Ця мультиплікативність разом із законом взаємності дають три дії, що по черзі стискають пару (a, n).

**Звести верх.** Символ (a|n) залежить лише від a за модулем n, тож першим ділом беремо a mod n. Приємний наслідок: знак a зникає сам собою — від'ємне a тим самим ділінням зводиться в діапазон [0, n), і жодного окремого правила для (−1|n) писати не треба.

**Винести двійки.** Тепер зчищаємо з a всі множники 2. Кожна двійка дає внесок (2|n) = ±1, і його знак вирішує остача n за модулем 8:

```
(2|n) = +1,  якщо n ≡ 1 або 7 (mod 8)
(2|n) = −1,  якщо n ≡ 3 або 5 (mod 8)
```

Після цього a непарне.

**Перевернути пару.** Два непарні числа можна поміняти місцями за законом взаємності: (a|n) стає (n|a). Знак при цьому міняється рівно в одному разі — коли **обидва** мають вигляд 4k + 3; інакше лишається як був:

```
(a|n) = −(n|a),  якщо a ≡ 3 і n ≡ 3 (mod 4)
(a|n) = +(n|a),  інакше
```

Після перевороту знову зводимо верх (n mod a) — і коло замикається.

Числа тануть, як в алгоритмі Евкліда, бо кожен переворот міняє більше на менше, а зведення за модулем ще й обрізає його. Коли верх стає нулем, низ дорівнює найбільшому спільному дільнику вихідних a і n: якщо це 1 — вони взаємно прості, і накопичений знак і є відповідь; якщо більше — числа мали спільний дільник, і символ дорівнює 0.

Варто спинитися на тому, чого тут **немає**. Немає розкладу на прості — переворот працює з будь-яким непарним низом, простим чи складеним, бо символ Якобі зберігає і взаємність, і обидва доповнення. І немає жодного множення двох великих чисел — лише ділення з остачею та зсуви. Це робить редукцію і швидшою за критерій Ейлера, і безпечнішою щодо переповнення: доки n влазить у цілий тип, проміжні числа теж, бо вони тільки меншають.

## Робочий код

Три дії лягають у цикл майже дослівно. Код число-теоретичний і бітовий, тож природна мова для нього — C: остача за модулем 8 і 4 — це `& 7` і `& 3`, парність — молодший біт, ділення навпіл — зсув.

```c
#include <stdint.h>

/* Символ Якобі (a | n) для непарного n ≥ 1.
   Повертає +1, −1 або 0 (останнє — коли a і n мають спільний дільник).
   Для простого n це заразом символ Лежандра. */
int jacobi(int64_t a, int64_t n)
{
    /* (a|n) залежить лише від a mod n — зводимо в [0, n),
       і знак від'ємного a враховується цим самим кроком. */
    a %= n;
    if (a < 0) a += n;

    int sign = 1;                      /* накопичений знак ±1 */
    while (a != 0) {
        /* 1) винести всі двійки: кожна дає (2|n) за n mod 8 */
        while ((a & 1) == 0) {
            a >>= 1;
            int r = n & 7;             /* n mod 8 */
            if (r == 3 || r == 5)
                sign = -sign;
        }
        /* 2) переворот (a|n) → (n|a); знак міняється,
              лише коли обидва ≡ 3 (mod 4) */
        int64_t t = a; a = n; n = t;
        if ((a & 3) == 3 && (n & 3) == 3)
            sign = -sign;
        /* 3) звести верх за модулем низу — крок Евкліда */
        a %= n;
    }
    return (n == 1) ? sign : 0;        /* n тепер = gcd(a₀, n₀) */
}
```

Двійки виносить внутрішній цикл. Позаяк n усередині нього незмінне, знак перемикається рівно стільки разів, скільки двійок, — а це і є (2|n) у відповідному степені: парне число двійок повертає +1, непарне лишає (2|n). Переворот міняє a і n місцями одним обміном; умову «обидва ≡ 3 (mod 4)» перевіряють уже після обміну, і це нічого не псує, бо вона симетрична. Ось перевірка на кількох числах:

```c
#include <stdio.h>

int main(void)
{
    printf("(30|53) = %d\n", jacobi(30, 53));  /* -1: 30 — нелишок */
    printf("( 3|11) = %d\n", jacobi(3, 11));   /* +1: 3 = 5² mod 11 */
    printf("( 2|15) = %d\n", jacobi(2, 15));   /* +1, АЛЕ 2 не квадрат! */
    printf("( 6|15) = %d\n", jacobi(6, 15));   /*  0: gcd(6,15)=3 */
    return 0;
}
```

Виведе:

```
(30|53) = -1
( 3|11) = +1
( 2|15) = +1
( 6|15) = 0
```

Простежмо перший рядок, щоб побачити три дії в роботі. **(30|53):** зводити нема чого, бо 30 < 53; виносимо одну двійку — 30 = 2·15, а 53 ≡ 5 (mod 8), тож знак стає −1, і лишається (15|53). Переворот: 15 має вигляд 4k+3, але 53 ≡ 1 (mod 4), тож знак не рухається і (15|53) = (53|15); зводимо 53 mod 15 = 8, маємо (8|15). Далі 8 = 2³, а 15 ≡ 7 (mod 8), отже кожна двійка дає +1 — знак стоїть, лишається (1|15). Ще переворот і зведення — верх падає в нуль, низ дорівнює 1, коло стало, а накопичений знак так і лишився −1. Отже, (30|53) = −1: рівняння x² ≡ 30 (mod 53) розв'язку не має. Той самий шлях робить і рука, і машина; різниця лише в тому, що код не мусить вгадувати, коли спинитися, — цикл сам доходить до нуля.

## Складність

Кроків тут стільки ж, скільки в алгоритмі Евкліда для тих самих чисел, — приблизно пропорційно log n; винесення двійок за весь прогін додає ще log n зсувів. У переліку бітових операцій це виходить O((log n)²) — рівно ціна одного НСД. Порівняймо з критерієм Ейлера: той теж робить близько log n кроків, але кожен крок — модульне множення двох log n-бітних чисел, тобто загалом O((log n)³), та ще й лише для простого модуля. Редукція взаємністю виграє множник log n і при цьому взагалі не питає, чи n просте.

> 🔧 **Навіщо це.** Саме цю редукцію викликає [тест простоти Соловея–Штрассена](book:algorithms/solovay-strassen): щоб перевірити кандидата n, він бере випадкове a і порівнює a^((n−1)/2) mod n із символом (a|n), порахованим переворотами. Для простого n дві величини завжди збігаються — це критерій Ейлера; якщо ж вони розійшлися, n напевно складене. Права частина цієї перевірки й є наш `jacobi`.

## Пастки

Далі — місця, де легко дістати тихо хибну відповідь: функція нічого не «падає», просто повертає не той знак.

**Головна: +1 за складеним модулем не означає квадрат.** Для простого p символ (a|p) = +1 однозначно каже «a — квадрат». Для складеного n це вже не так. Символ Якобі — добуток символів за простими дільниками, а добуток двох мінусів дає плюс. Тож число, що є **нелишком за кожним** простим дільником, отримає символ +1, хоч квадратом не є.

Найменший приклад — n = 15 = 3·5 і a = 2. Двійка не квадрат ні за модулем 3, ні за модулем 5, тож (2|3) = (2|5) = −1, а їхній добуток (2|15) = +1 — саме те, що надрукувала програма. І все ж серед квадратів за модулем 15, а це 1, 4, 6, 9, 10, двійки немає.

![Оборотні лишки за модулем 15, розкладені за поведінкою окремо за модулем 3 і за модулем 5; символ Якобі як добуток двох знаків, де діагональ дає +1, а антидіагональ −1](/book/math/number-theory/quadratic-residue/img/jacobi-trap.svg)
*Усі оборотні лишки за модулем 15, розсортовані за тим, лишок вони чи нелишок окремо за модулем 3 і за модулем 5. Символ Якобі — добуток двох знаків, тож +1 дає ціла діагональ, де знаки однакові: і «лишок·лишок», і «нелишок·нелишок». Та справжні квадрати лише в лівій верхній клітині — {1, 4}; клітина {2, 8} носить точнісінько той самий +1, не бувши квадратом. Ось чому за складеним модулем довіряти можна тільки знаку −1.*

Практичний висновок різкий: за складеним модулем **вирішальний лише −1**. Символ −1 чесно доводить, що число — нелишок (бодай за одним простим дільником воно нелишок). А +1 не гарантує нічого: розрізнити справжні квадрати серед чисел із символом +1, не знаючи розкладу n, вважають важкою задачею — і саме на цьому розриві тримається криптографія лишків. Для простого модуля пастки немає: там Якобі збігається з Лежандром, і +1 таки означає квадрат.

**Модуль має бути непарним і додатним.** Усе виведення (2|n) за модулем 8 і переворот за модулем 4 припускають непарний n. Для парного чи від'ємного низу потрібне ширше означення — **символ Кронекера**, що окремими правилами означує ще й (a|2) та (a|−1). Наведений код мовчки припускає непарний n ≥ 1; коли треба довільний, беруть готову реалізацію — у бібліотеці GMP це `mpz_jacobi` та ширший `mpz_kronecker`, і та сама редукція працює там уже на числах довільної довжини.

**Знак.** Уся правильність тримається на двох умовах — множині {3, 5} для остачі за модулем 8 і вимозі «обидва ≡ 3» за модулем 4. Переставити 8 на 4, написати «або» замість «і» чи сплутати {3, 5} з {1, 7} — і функція й далі повертатиме ±1, лише часом не той. Тому єдина надійна перевірка — прогнати її на відомих значеннях: (30|53) = −1, будь-який квадрат дає +1, спільний дільник дає 0.

**Нуль.** Коли цикл спиняється, низ дорівнює найбільшому спільному дільнику вихідних чисел. Якщо він не 1 — числа не взаємно прості, і символ за означенням 0; тому останній рядок повертає 0, а не накопичений знак. Перевіряти gcd наперед не треба — редукція знаходить його по дорозі.
