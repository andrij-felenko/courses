# ⚙️ Добування квадратного кореня за модулем

Тест на квадратичність каже лише «так» або «ні» — існує x із x² ≡ a (mod p) чи ні; самого x він не показує. Ось робочий код, що дістає цей корінь: миттєво, коли p ≡ 3 (mod 4), і алгоритмом Тонеллі — Шенкса — за будь-яким непарним простим p.

Над звичайними числами корінь беруть, звужуючись до нього: √2 затиснуте між 1.41 і 1.42, тоді між 1.414 і 1.415, і кожен крок відрізає половину відрізка. За простим модулем такого відрізка немає — лишки не вишикувані в ряд, звужувати нема куди. Тому корінь тут не наближають, а **обчислюють** — прямим піднесенням до правильно дібраного степеня.

### Легкий випадок: p ≡ 3 (mod 4)

Здогад напрошується сам: якщо всі дії — це степені a, то й корінь пошукаймо серед степенів a. Уся хитрість — дібрати показник.

Відправна точка — те, що a вже майже дорівнює своєму степеню. Помножмо a на одиницю, але записану хитро: для лишка a справджується a^((p−1)/2) ≡ 1 (це критерій Ейлера — власне означення того, що a лишок). Тоді

```
a = a · 1 = a · a^((p−1)/2) = a^((p+1)/2)
```

Отже, a — це a у степені (p+1)/2. А тепер погляньмо: якщо цей показник **парний**, його можна поділити навпіл і дістати корінь безкоштовно. Нехай x = a^((p+1)/4); тоді

```
x² = a^((p+1)/2) = a
```

— рівно те, що треба. Лишається умова: показник (p+1)/4 має бути цілим, тобто p + 1 має ділитися на 4, тобто **p ≡ 3 (mod 4)**. За таким простим корінь дається однією формулою й одним піднесенням до степеня, без жодного циклу.

![Дві дороги до кореня залежно від остачі p за модулем 4: ліворуч одна формула x = a^((p+1)/4), праворуч — коли показник не цілий — алгоритм Тонеллі — Шенкса](/book/math/number-theory/quadratic-residue/img/sqrt-branches.svg)
*Коли p ≡ 3 (mod 4), корінь — це a^((p+1)/4), бо a^((p+1)/2) розкладається на a^((p−1)/2)·a = 1·a = a. Коли ж p ≡ 1 (mod 4), показник (p+1)/4 уже не цілий, і півшляху зробити не можна — тоді працює Тонеллі — Шенкс.*

### Чому трюк ламається за p ≡ 1 (mod 4)

Коли p ≡ 1 (mod 4), число (p+1)/4 не ціле — поділити показник навпіл одним махом не вдається. За цим стоїть глибша причина, і побачити її найлегше через будову групи лишків.

Ненульові лишки за простим p утворюють [циклічну групу](book:math/group-theory) порядку p − 1: кожен елемент у степені p − 1 дає одиницю ([мала теорема Ферма](book:math/fermat-little-theorem)). Узяти квадратний корінь — це половинити показник. Розкладімо порядок групи на непарну частину й степінь двійки:

```
p − 1 = Q · 2ˢ,   Q непарне
```

На **непарній** частині половинити легко: 2 оборотне за модулем Q, тож поділ показника навпіл там завжди означений — саме тому легка формула й спрацьовує, коли вся «парність» вичерпується єдиною двійкою (S = 1, тобто p ≡ 3 mod 4). Уся притичина сидить у **2-степеневій частині** — вкладених підгрупах порядків 2, 4, …, 2ˢ, — де половинити показник заважає парність. Тонеллі — Шенкс якраз і проводить корінь крізь цю вежу двійок.

### Ідея Тонеллі — Шенкса

Алгоритм тримається на двох величинах. Перша — чорновий корінь, друга — похибка, що показує, наскільки чорновик хибний.

```
R = a^((Q+1)/2)     чорновий корінь
t = a^Q             похибка
```

Їх дібрано так, що між ними весь час стоїть простий зв'язок. Підставмо:

```
R² = a^(Q+1) = a · a^Q = a · t
```

Ось **інваріант**, що не зламається до кінця: **R² ≡ a · t (mod p)**. Якби вдалося догнати t до одиниці, не порушивши цієї рівності, то R² стало б рівно a — і R виявився б шуканим коренем. Уся робота зводиться до одного: **згасити t до 1**.

Чому це взагалі можливо? Похибка t не гуляє де завгодно — вона замкнена в 2-степеневій вежі. Бо a лишок, тож a^((p−1)/2) = 1, а отже

```
t^(2^(S−1)) = a^(Q · 2^(S−1)) = a^((p−1)/2) = 1
```

Порядок t ділить 2^(S−1) — це якийсь степінь двійки 2ᵏ, не більший. Інакше кажучи, t сидить на одній зі сходинок вежі, і збити його вниз можна, домноживши на дібраний елемент тієї ж вежі.

Такий елемент дає **затравка** — будь-який квадратичний нелишок z. Покладімо c = z^Q. На відміну від t, цей c має порядок рівно 2ˢ — повний розмах вежі, бо c^(2^(S−1)) = z^((p−1)/2) = −1 ≠ 1 (нелишок дає −1). Саме c постачає «важіль» потрібної висоти, щоб гасити верхній біт порядку t.

**Один крок.** Знайдімо порядок t: найменше i, для якого t^(2ⁱ) = 1; тоді порядок дорівнює 2ⁱ. Візьмімо b = c^(2^(S−i−1)) — його квадрат b² має порядок теж рівно 2ⁱ, той самий, що й у t. Чому домноження t на b² збиває порядок? У циклічній 2-групі єдиний елемент порядку 2 — це −1, тож і t^(2^(i−1)) = −1, і (b²)^(2^(i−1)) = −1; перемноживши,

```
(t · b²)^(2^(i−1)) = (−1) · (−1) = 1
```

Новий порядок t уже ділить 2^(i−1) — **щонайменше вдвічі менший**. Щоб інваріант устояв, домножмо і чорновик: (R·b)² = R²·b² = a·t·b² = a·(t·b²) — тобто R·b лишається коренем нового, меншого t. Оновивши c ← b², повторюємо. Порядок t падає щокроку принаймні вдвічі, тож не більш як за S кроків доходить до 1 — і тоді R² = a.

![Тонеллі — Шенкс як сходи вниз: порядок похибки t (степінь двійки) щокроку меншає удвічі — 4, потім 2, потім 1 — а чорновий корінь R накопичує домноження, аж поки t = 1 і R² = a](/book/math/number-theory/quadratic-residue/img/sqrt-cascade.svg)
*Наскрізний приклад a = 5, p = 41. Похибка t сходить вежею двійок 9 → 40 → 1, а корінь R росте 2 → 35 → 28. Праворуч на кожній сходинці видно незламний інваріант R² ≡ a·t. Дійшовши до t = 1, дістаємо x = 28 (другий корінь — це −28 ≡ 13).*

### Наскрізний приклад

**Знайти x із x² ≡ 5 (mod 41).**

```
p − 1 = 40 = 5 · 2³        →  Q = 5,  S = 3
нелишок-затравка z = 3     →  c = 3⁵ ≡ 38
t = 5⁵ ≡ 9                 R = 5³ ≡ 2      (перевірка: R² = 4 = 5·9 = a·t) ✓

крок 1:  порядок t = 4     (9² ≡ 40 ≡ −1,  40² ≡ 1)
         i = 2,  b = c^(2^(3−2−1)) = 38^1 = 38
         t ← t·b² = 9·9 ≡ 40      R ← R·b = 2·38 ≡ 35     c ← b² ≡ 9
         (перевірка: R² = 35² ≡ 36 = 5·40 = a·t) ✓

крок 2:  порядок t = 2     (40 ≡ −1,  40² ≡ 1)
         i = 1,  b = c^(2^(2−1−1)) = 9^1 = 9
         t ← t·b² = 40·40 ≡ 1     R ← R·b = 35·9 ≡ 28

t = 1    →  x = R = 28
```

Перевірка: 28² = 784 = 19·41 + 5 ≡ 5. Другий корінь — 41 − 28 = 13, і 13² = 169 = 4·41 + 5 ≡ 5. Обидва на місці.

### Робочий код

Обидві версії — той самий алгоритм. Різниця лише в тому, що на C++ доводиться самому берегтися від переповнення (добуток двох лишків сягає ~p², аж до 2¹²⁶ для 63-бітного p), а Python рахує у довгій арифметиці й ховає цей клопіт — тому там код читається як сам псевдокод, хоча ціна операцій та сама.

:::tabs
```cpp
#include <cstdint>
#include <optional>

using u64 = uint64_t;

// (a · b) mod m без переповнення: множимо в 128 бітах (p < 2⁶³)
static u64 mulmod(u64 a, u64 b, u64 m) {
    return (unsigned __int128)a * b % m;
}
// a^e mod m — швидке піднесення подвоєнням показника
static u64 powmod(u64 a, u64 e, u64 m) {
    u64 r = 1; a %= m;
    while (e) {
        if (e & 1) r = mulmod(r, a, m);
        a = mulmod(a, a, m);
        e >>= 1;
    }
    return r;
}

// Корінь x із x² ≡ a (mod p), p — непарне просте.
// Повертає один корінь (другий — це p − x); nullopt, якщо a — нелишок.
std::optional<u64> modular_sqrt(u64 a, u64 p) {
    a %= p;
    if (a == 0) return u64{0};                  // єдиний корінь — сам нуль
    if (powmod(a, (p - 1) / 2, p) != 1)         // критерій Ейлера: чи a лишок
        return std::nullopt;
    if (p % 4 == 3)                             // легкий випадок — одна формула
        return powmod(a, (p + 1) / 4, p);

    // p − 1 = Q · 2^S, Q непарне
    u64 Q = p - 1; int S = 0;
    while ((Q & 1) == 0) { Q >>= 1; ++S; }

    // затравка: будь-який квадратичний нелишок z (у нього z^((p−1)/2) ≡ −1)
    u64 z = 2;
    while (powmod(z, (p - 1) / 2, p) != p - 1) ++z;

    int M = S;
    u64 c = powmod(z, Q, p);                    // порядок рівно 2^S
    u64 t = powmod(a, Q, p);                    // похибка, порядок ділить 2^(S−1)
    u64 R = powmod(a, (Q + 1) / 2, p);          // чорновий корінь, R² ≡ a·t

    while (t != 1) {
        // найменше i з t^(2^i) ≡ 1 — степінь двійки в порядку t
        int i = 0;
        for (u64 s = t; s != 1; s = mulmod(s, s, p)) ++i;
        // b = c^(2^(M−i−1)); b² згасить верхній біт порядку t
        u64 b = c;
        for (int j = 0; j < M - i - 1; ++j) b = mulmod(b, b, p);
        M = i;
        c = mulmod(b, b, p);
        t = mulmod(t, c, p);                    // порядок t падає щонайменше вдвічі
        R = mulmod(R, b, p);                    // інваріант R² ≡ a·t уцілів
    }
    return R;
}
```
```py
def modular_sqrt(a: int, p: int) -> int | None:
    """Корінь x із x² ≡ a (mod p) для непарного простого p; None, якщо a — нелишок."""
    a %= p
    if a == 0:
        return 0                              # єдиний корінь — сам нуль
    if pow(a, (p - 1) // 2, p) != 1:          # критерій Ейлера: чи a лишок
        return None
    if p % 4 == 3:                            # легкий випадок — одна формула
        return pow(a, (p + 1) // 4, p)

    # p − 1 = Q · 2^S, Q непарне
    Q, S = p - 1, 0
    while Q % 2 == 0:
        Q //= 2; S += 1

    z = 2                                     # затравка: будь-який нелишок
    while pow(z, (p - 1) // 2, p) != p - 1:
        z += 1

    M, c = S, pow(z, Q, p)                    # c має порядок рівно 2^S
    t, R = pow(a, Q, p), pow(a, (Q + 1) // 2, p)   # похибка t і чорновик R (R² ≡ a·t)

    while t != 1:
        i, s = 0, t                           # порядок t = 2^i
        while s != 1:
            s = s * s % p; i += 1
        b = pow(c, 1 << (M - i - 1), p)        # b² згасить верхній біт порядку t
        M, c = i, b * b % p
        t, R = t * c % p, R * b % p            # t меншає вдвічі, R тримає інваріант
    return R
```

> 🔧 **Навіщо це.** Стиснений відкритий ключ на еліптичній кривій зберігає лише координату x — щоб відновити y, кожна перевірка підпису бере y = √(x³ + ax + b) за модулем p, тобто **щоразу викликає рівно цей алгоритм**. Так само модульний корінь — серце схеми підпису Рабіна й декодування в кодах, що спираються на скінченні поля. Це не навчальна вправа, а гаряча операція, яку мільярди разів на день виконують клієнти TLS.

### Складність і пастки

Уся вага — у піднесеннях до степеня. Підготовка робить кілька викликів powmod, кожен по O(log p) множень; цикл крутиться щонайбільше S ≤ log₂p разів, а всередині пошук порядку й побудова b дають разом O(S²) = O(log²p) множень. Отже, весь алгоритм коштує **як жменя піднесень до степеня** — той самий порядок, що й одне обчислення a^((p+1)/4). У легкому випадку p ≡ 3 (mod 4) це буквально одне піднесення.

Пастки, кожна з яких псує наївну реалізацію:

- **Затравка-нелишок обов'язкова.** Алгоритмові потрібен z із символом −1; його шукають перебором z = 2, 3, … Половина лишків — нелишки, тож у середньому вистачає ~2 спроб. Швидкої формули для найменшого нелишка немає (його розмір обмежують лише оцінками), але перебір тривіально дешевий; можна брати z і навмання.
- **Спершу перевір, що a справді лишок.** Це не косметика. Якщо подати нелишок, порядок t дорівнюватиме повному 2ˢ, пошук дасть i = M, і показник (M − i − 1) стане від'ємним — зсув 1 << (−1) це невизначена поведінка на C++ і нескінченний цикл на Python. Критерій Ейлера на початку перетворює тиху катастрофу на чесне «кореня немає».
- **Нуль окремо.** a ≡ 0 має єдиний корінь — сам нуль; групова машинерія припускає a оборотним, тож цей випадок відсікають до неї.
- **Переповнення.** На C++ добуток двох лишків не влазить у 64 біти — потрібне множення в 128 бітах (`unsigned __int128`) або окремий mulmod; Python бере довгі числа сам, і саме тому його версія оманливо коротша.
- **Корінь не один.** Функція повертає один x; другий — це p − x. За **складеним** модулем коренів стає більше (чотири для n = p·q): тоді n розкладають, беруть корінь за кожним простим і склеюють [китайською теоремою про залишки](book:math/chinese-remainder-theorem), а за степенями простого — піднімають методом Гензеля. Робоча конячка всюди та сама — [швидке піднесення до степеня](book:math/modular-exponentiation).

Алгоритм носить два імені, бо його відкривали двічі: метод обчислення такого кореня дав італійський математик Альберто Тонеллі 1891 року, а зручну сучасну форму, якою користуються сьогодні, — американець Деніел Шенкс 1973 року. Це усталена, незаперечна історія — обидва внески документовані й розрізнені за роллю: постановка й практичний алгоритм.
