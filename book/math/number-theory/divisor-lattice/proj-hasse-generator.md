# ⚙️ Генерація діаграми Хассе для дільників

### Постановка задачі (Problem Statement)
У теорії чисел та дискретній математиці часто виникає потреба візуалізувати структуру дільників певного натурального числа n. Ця структура утворює частково впорядковану множину, яку можна зобразити за допомогою спеціального графа — діаграми Хассе. 
Діаграма Хассе — це орієнтований граф, у якому вершини відповідають елементам множини (у нашому випадку — дільникам числа n), а ребра показують відношення безпосереднього підпорядкування. Для решітки дільників це означає, що число u з'єднується ребром із числом v тоді й тільки тоді, коли u ділить v, і між ними немає жодного іншого дільника k, такого що u ділить k, а k ділить v. 
Математично це еквівалентно тому, що частка v / u є простим числом. Наша мета — розробити ефективний програмний інструмент, який автоматично генерує такий граф для будь-якого заданого числа n та виводить його у форматі DOT, що дозволить легко побудувати візуалізацію за допомогою інструментів на зразок Graphviz.

### Архітектурна логіка алгоритму (Architectural Logic)
Щоб розв'язати поставлену задачу найефективніше, ми уникаємо складних графових алгоритмів, таких як транзитивне скорочення повного графа подільності, що вимагало б кубічного часу. Натомість ми спираємося на фундаментальну властивість решітки дільників: наявність ребра між u та v прямо залежить від простоти їхньої частки.

Алгоритм будується за таким конвеєром обробки:
1. Знаходження всіх дільників: спочатку ми збираємо всі дільники числа n. Це робиться за один прохід до квадратного кореня з n. Отриманий список обов'язково сортується за зростанням.
2. Фільтрація пар для ребер: ми розглядаємо всі можливі пари дільників (u, v), де u < v. Замість того, щоб шукати проміжні дільники, ми просто перевіряємо дві умови: чи ділиться v на u без остачі, та чи є частка v / u простим числом. Якщо обидві умови виконуються, пара (u, v) утворює ребро.
3. Генерація виводу: зібрані ребра перетворюються на текстовий опис графа мовою DOT, що дозволяє миттєво отримати візуалізацію.

Такий підхід забезпечує модульність, легкість тестування та високу швидкість роботи навіть для великих значень n з великою кількістю дільників.

### Покроковий розбір коду (Step-by-Step Code Breakdown)

Нижче наведено алгоритм мовою C++17, який приймає число n і генерує список ребер для діаграми Хассе. Код розбитий на 5 логічних компонентів для ясності.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <utility>

// Компонент 1: Перевірка на простоту
// Використовується для визначення, чи є частка двох дільників простим числом.
bool is_prime(int n) {
    if (n < 2) return false;
    if (n == 2 || n == 3) return true;
    if (n % 2 == 0 || n % 3 == 0) return false;
    for (int i = 5; i * i <= n; i += 6) {
        if (n % i == 0 || n % (i + 2) == 0)
            return false;
    }
    return true;
}

// Компонент 2: Знаходження всіх дільників
// Шукаємо дільники за O(√n) і сортуємо їх за зростанням.
std::vector<int> get_divisors(int n) {
    std::vector<int> divs;
    for (int i = 1; i * i <= n; ++i) {
        if (n % i == 0) {
            divs.push_back(i);
            if (i * i != n) {
                divs.push_back(n / i);
            }
        }
    }
    std::sort(divs.begin(), divs.end());
    return divs;
}

// Компонент 3: Генерація ребер діаграми Хассе
// Для кожної пари дільників a і b (де a < b) перевіряємо, 
// чи ділить a число b, і чи є їхня частка b/a простим числом.
std::vector<std::pair<int, int>> generate_hasse_edges(const std::vector<int>& divs) {
    std::vector<std::pair<int, int>> edges;
    for (size_t i = 0; i < divs.size(); ++i) {
        for (size_t j = i + 1; j < divs.size(); ++j) {
            int a = divs[i];
            int b = divs[j];
            if (b % a == 0 && is_prime(b / a)) {
                edges.push_back({a, b});
            }
        }
    }
    return edges;
}

// Компонент 4: Вивід графа (ребер)
// Друкує результат у форматі, зручному для побудови графів (наприклад, Graphviz).
void print_graph(int n, const std::vector<std::pair<int, int>>& edges) {
    std::cout << "digraph D_" << n << " {\n";
    std::cout << "  rankdir=BT;\n"; // Знизу вгору
    for (const auto& edge : edges) {
        std::cout << "  " << edge.first << " -> " << edge.second << ";\n";
    }
    std::cout << "}\n";
}

// Компонент 5: Головна функція
int main() {
    int n = 36; // Можна змінити на будь-яке інше число
    std::cout << "// Генерація решітки дільників для n = " << n << "\n";
    
    std::vector<int> divisors = get_divisors(n);
    std::vector<std::pair<int, int>> hasse_edges = generate_hasse_edges(divisors);
    
    print_graph(n, hasse_edges);
    
    return 0;
}
```

Давайте розберемо кожен компонент детальніше:

**Компонент 1: Перевірка на простоту.** Функція `is_prime` реалізує оптимізований алгоритм перевірки числа на простоту. Спочатку відкидаються числа, менші за 2, потім окремо перевіряються 2 та 3. Далі відсіюються всі числа, кратні 2 або 3. Основний цикл перевіряє дільники форми 6k-1 та 6k+1 аж до квадратного кореня з перевіряємого числа. Це стандартна оптимізація, що значно прискорює роботу порівняно з перевіркою всіх непарних чисел.

**Компонент 2: Знаходження всіх дільників.** Функція `get_divisors` проходить у циклі від 1 до квадратного кореня з n. Якщо i є дільником, ми додаємо як i, так і парний йому дільник n / i (за умови, що вони не рівні, щоб уникнути дублювання для точних квадратів). Наприкінці вектор сортується, оскільки алгоритм генерації ребер очікує, що дільники йдуть за зростанням.

**Компонент 3: Генерація ребер діаграми Хассе.** Функція `generate_hasse_edges` містить подвійний цикл. Зовнішній цикл бере менший дільник a, а внутрішній — більший дільник b. Ми застосовуємо нашу математичну умову: b % a == 0 перевіряє подільність, а `is_prime(b / a)` гарантує відсутність проміжних дільників. Знайдені пари додаються до списку ребер.

**Компонент 4: Вивід графа.** Функція `print_graph` формує вивід у синтаксисі DOT. Директива `rankdir=BT` вказує рушію рендерингу (наприклад, dot з пакета Graphviz), що граф слід малювати знизу вгору (Bottom-Top), що є стандартним для діаграм Хассе.

**Компонент 5: Головна функція.** Тут ми об'єднуємо всі компоненти. Задаємо початкове значення n, отримуємо дільники, генеруємо ребра і друкуємо результат. Змінюючи константу n, ми можемо одразу генерувати діаграму для будь-якого іншого числа.

### Аналіз складності вводу-виводу та обчислень (I/O & Complexity Analysis)

Аналіз складності цього алгоритму є багатоаспектним, оскільки він залежить від кількості дільників числа n (позначимо цю кількість як d).

**Часова складність:**
1. Знаходження дільників: цикл працює до квадратного кореня з n, тобто виконує O(√n) ітерацій. Сортування дільників займає O(d log d) часу.
2. Генерація ребер: подвійний цикл по дільниках виконує близько d² / 2 ітерацій. У найгіршому випадку всередині циклу викликається перевірка на простоту `is_prime(b / a)`, яка працює за O(√(b / a)). Максимальне значення b / a не перевищує n, тому перевірка займає в гіршому випадку O(√n). Таким чином, загальна складність цього етапу становить O(d² √n). Проте на практиці більшість пар не проходять тест b % a == 0, і функція `is_prime` викликається значно рідше.
3. Вивід графа: операції вводу-виводу (I/O) виконуються пропорційно кількості знайдених ребер, яка становить O(d²), але на практиці ближче до O(d log d). Запис у стандартний потік виводу `std::cout` є відносно повільною операцією, тому для дуже великих n рекомендується перенаправляти вивід у файл.

**Просторова складність:**
Алгоритм потребує пам'яті для зберігання списку дільників та списку ребер. Список дільників вимагає O(d) пам'яті. Кількість ребер у діаграмі Хассе також оцінюється як O(d log d) у гіршому випадку (коли n — добуток багатьох різних простих). Таким чином, загальна просторова складність становить O(d log d). Враховуючи, що кількість дільників d навіть для чисел у межах стандартного 32-бітного цілого (до 2 мільярдів) не перевищує 1344, алгоритм споживає мізерну кількість оперативної пам'яті (лічені кілобайти) і є надзвичайно ефективним.

Цей скрипт працює дуже ефективно. Замість того, щоб перевіряти транзитивне замикання всього графа (що вимагало б кубічної складності), ми використовуємо математичну властивість решітки дільників: ребро в діаграмі Хассе між a та b існує тоді й тільки тоді, коли ми множимо a на одне просте число, щоб отримати b. Це дозволяє звести задачу до простої перевірки частки b/a на простоту, що робить алгоритм швидким та елегантним.

### Компіляція та генерація зображень (Compilation and Rendering)

Для використання цього інструменту достатньо мати встановлений компілятор C++ (наприклад, GCC або Clang) та інструмент для візуалізації графів Graphviz. 

Команда для компіляції та запуску генератора може виглядати наступним чином:
```bash
g++ -std=c++17 -O3 hasse.cpp -o hasse
./hasse > hasse_output.dot
```
Прапорець `-O3` активує максимальні оптимізації, що є доречним при роботі з дуже великими числами, коли кількість дільників максимальна. Перенаправлення потоку виводу `>` дозволяє легко зберегти згенерований DOT-код у файл `hasse_output.dot`.

Після цього можна створити графічний файл (наприклад, у форматі PNG) за допомогою Graphviz:
```bash
dot -Tpng hasse_output.dot -o hasse.png
```
Отримане зображення `hasse.png` буде містити красиву та зрозумілу решітку дільників числа n, у якій усі зв'язки спрямовані знизу вгору, як і передбачає класична конвенція малювання діаграм Хассе.
