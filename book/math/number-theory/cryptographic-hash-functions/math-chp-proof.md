# 🧮 Доведення стійкості хеш-функції Чаума — ван Гейста — Пфітцманна

Ця математична вставка містить строге доведення безпеки доказово стійкої хеш-функції Чаума — ван Гейста — Пфітцманна (CHP), математичний аналіз групових структур, гомоморфні властивості та детальний розбір обчислень на конкретному числовому прикладі.

## Алгебраїчний фундамент і безпечні прості числа

Хеш-функція Чаума — ван Гейста — Пфітцманна (*Chaum-van Heijst-Pfitzmann*, 1991) є алгебраїчною конструкцією, стійкість якої заснована на складності обчислення дискретного логарифма у скінченній циклічній групі.

Для побудови функції обирають такі математичні об'єкти:

1. **Безпечне просте число** `p` (англ. *safe prime*), яке має вигляд:
```
p = 2·q + 1
```
де `q` — також просте число (просте число Софі Жермен). Наприклад, при `q = 11` отримуємо безпечне просте `p = 23`.

2. **Мультиплікативна група** `ℤ_p* = {1, 2, ..., p-1}` порядку `p - 1 = 2q`. Оскільки порядок групи дорівнює `2q`, за теоремою Лагранжа будь-який елемент цієї групи має порядок `1`, `2`, `q` або `2q`. Елементи, що мають порядок `q`, утворюють циклічну підгрупу `G ⊂ ℤ_p*` простого порядку `q`.

Вибір саме простого порядку підгрупи `q` має принципове значення для стійкості проти криптоаналітичного алгоритму Погліґа — Геллмана (*Pohlig-Hellman Algorithm*). Якби порядок групи `p - 1` складався лише з малих простих множників (так звані гладкі числа, *smooth numbers*), то задачу дискретного логарифма можна було б розкласти за китайською теоремою про остачі на серію легких задач у малих підгрупах. Вимога `p = 2q + 1` гарантує наявність велетенського простого множника `q`, що повністю блокує алгоритм Погліґа — Геллмана.

### Квадратичні лишки та структура підгрупи G

Оскільки `p - 1 = 2q`, підгрупа `G` утворена квадратичними лишками за модулем `p` (**Quadratic Residues**, `QR_p`):

```
G = QR_p = { x² mod p | x ∈ ℤ_p* }
```

За критерієм Ейлера число `y ∈ ℤ_p*` є квадратичним лишком за модулем `p` тоді й лише тоді, коли:

```
y^{(p-1)/2} ≡ y^q ≡ 1 (mod p)
```

Оскільки порядок `q` є простим числом, кожен елемент `g ∈ G` (окрім нейтрального елемента `1`) є генератором підгрупи `G`. Це означає, що послідовність степенів `{g¹, g², ..., g^q mod p}` вичерпує абсолютно всі `q` елементів підгрупи `G`.

3. **Два генератори підгрупи** `g` та `h` групи `G`, обидва порядку `q`. Вони вибираються випадковим чином так, щоб ніхто не знав дискретного логарифма `a`, який пов'язує їх у `G`:
```
h ≡ gᵃ (mod p),   де  a = log_g h ∈ ℤ_q
```

Для запобігання закладкам (*backdoors*) генератори обирають за допомогою детермінованого псевдовипадкового генератора на основі концепції "Nothing-Up-My-Sleeve" (NUMS). Наприклад, `g` береться як найменший квадратний лишок у `ℤ_p*`, а `h = SHA256(g) mod p` (якщо числовий результат належить `G`). Це дає загальновизнане доведення того, що творець системи не підібрав `g` та `h` з відомим секретним степенем `a`.

Значення `(p, q, g, h)` є публічними системними параметрами.

Вхідне повідомлення розбивається на блоки пар цілих чисел `(x₁, x₂)`, де кожне значення лежить у межах від `0` до `q - 1`, тобто `(x₁, x₂) ∈ ℤ_q × ℤ_q`.

Загальна кількість можливих вхідних блоків пар дорівнює `|ℤ_q × ℤ_q| = q²`.

Функція хешування `CHP: ℤ_q × ℤ_q → G` визначається як модульний добуток піднесень до степеня:

```
CHP(x₁, x₂) = (g^{x₁} · h^{x₂}) mod p
```

Оскільки вихід `CHP(x₁, x₂)` є елементом підгрупи `G` порядку `q`, функція стискає простір входів розміру `q²` до простору виходів розміру `q`.

## Теорема про редукцію безпеки до дискретного логарифма

**Теорема.** Якщо існує ймовірнісний алгоритм `A`, який за поліноміальний час знаходить колізію хеш-функції CHP (тобто дві різні пари `(x₁, x₂) ≠ (y₁, y₂)` такі, що `CHP(x₁, x₂) = CHP(y₁, y₂)`), то існує ймовірнісний алгоритм `B`, який за поліноміальний час обчислює дискретний логарифм `a = log_g h (mod q)`.

### Строге доведення теореми

Нехай алгоритм `A` знайшов колізію `(x₁, x₂) ≠ (y₁, y₂)`. За означенням хеш-функції CHP це означає рівність остач за модулем `p`:

```
g^{x₁} · h^{x₂} ≡ g^{y₁} · h^{y₂} (mod p)
```

Використавши алгебраїчний зв'язок `h ≡ gᵃ (mod p)`, підставимо `gᵃ` замість `h`:

```
g^{x₁} · (gᵃ)^{x₂} ≡ g^{y₁} · (gᵃ)^{y₂} (mod p)
g^{x₁ + a·x₂} ≡ g^{y₁ + a·y₂} (mod p)             [властивість степенів: gᵘ · gᵛ = gᵘ⁺ᵛ]
```

Оскільки елемент `g` має порядок `q` у групі `G`, рівність двох степенів `gᵘ ≡ gᵛ (mod p)` має місце тоді й лише тоді, коли їхні показники є порівнянними за модулем `q` (`u ≡ v (mod q)`):

```
x₁ + a·x₂ ≡ y₁ + a·y₂ (mod q)                   [теорема про порядок генератора q]
x₁ - y₁ ≡ a·y₂ - a·x₂ (mod q)                   [алгебраїчне перенесення доданків]
x₁ - y₁ ≡ a · (y₂ - x₂) (mod q)                 [винесення a за дужки]
```

Розглянемо значення різниці `Δx₂ = y₂ - x₂ (mod q)` у кільці residual classes `ℤ_q`:

**Випадок 1: `y₂ ≢ x₂ (mod q)`**

Оскільки `q` є простим числом, а значення `Δx₂ = y₂ - x₂` не дорівнює нулю за модулем `q`, число `Δx₂` є взаємно простим із `q` (`gcd(Δx₂, q) = 1`).

За розширеним алгоритмом Евкліда у полі `ℤ_q` існує єдиний мультиплікативний обернений елемент `(y₂ - x₂)⁻¹ (mod q)`.

Помножимо обидві частини порівняння на `(y₂ - x₂)⁻¹ (mod q)`:

```
a ≡ (x₁ - y₁) · (y₂ - x₂)⁻¹ (mod q)
```

Тобто ми точно обчислили секретний дискретний логарифм `a = log_g h (mod q)`.

**Випадок 2: `y₂ ≡ x₂ (mod q)`**

Якщо `y₂ - x₂ ≡ 0 (mod q)`, то оскільки за умовою `x₂, y₂ ∈ {0, 1, ..., q-1}`, єдиною можливістю є повна рівність `y₂ = x₂`.

Підставимо `y₂ = x₂` у порівняння:

```
x₁ - y₁ ≡ a · 0 ≡ 0 (mod q)
x₁ ≡ y₁ (mod q)
```

Оскільки `x₁, y₁ ∈ {0, 1, ..., q-1}`, це означає `x₁ = y₁`.

Таким чином, у Випадку 2 ми отримуємо `(x₁, x₂) = (y₁, y₂)`, що прямо суперечить умові, що колізійна пара є **різною**!

Отже, Випадок 2 є математично неможливим для будь-якої справжньої колізії. Будь-яка колізія обов'язково задовольняє умову Випадку 1, що дозволяє негайно відновити дискретний логарифм `a`.

**Висновок доведення:** Обчислювальна складність пошуку колізій у CHP строго дорівнює складності розв'язання задачі дискретного логарифма в підгрупі `G`. ∎

## Алгебраїчний гомоморфізм та зв'язок із зобов'язаннями Педерсена

Хеш-функція CHP володіє фундаментальною алгебраїчною властивістю — **мультиплікативним гомоморфізмом**.

Для двох вхідних пар `X = (x₁, x₂)` та `Y = (y₁, y₂)` розглянемо покомпонентну суму `X + Y = (x₁ + y₁ mod q, x₂ + y₂ mod q)`:

```
CHP(x₁ + y₁ mod q,  x₂ + y₂ mod q)
= g^{(x₁ + y₁) mod q} · h^{(x₂ + y₂) mod q} mod p      [означення хеш-функції CHP]
= (g^{x₁} · g^{y₁}) · (h^{x₂} · h^{y₂}) mod p            [властивість показника степеня: gᵃ⁺ᵇ = gᵃ · gᵇ]
= (g^{x₁} · h^{x₂}) · (g^{y₁} · h^{y₂}) mod p            [перестановність множників у ℤ_p*]
= (CHP(x₁, x₂) · CHP(y₁, y₂)) mod p                    [згортання за означенням CHP]
```

Ця гомоморфна властивість робить CHP основою для **схем зобов'язання Педерсена** (*Pedersen Commitment Scheme*).

У зобов'язанні Педерсена число `x₁` є корисним повідомленням, а `x₂` — випадковим маскувальним значенням (англ. *blinding factor*). Значення `C = g^{x₁} · h^{x₂} mod p` є безумовно прихованим (*information-theoretically hiding*), оскільки для кожного можливого `x₁` існує єдиний маскувальний елемент `x₂`, що дає те саме значення `C`. З іншого боку, через стійкість CHP до колізій ця схема є обчислювально зв'язуючою (*computationally binding*).

## Алгоритми розв'язання дискретного логарифма

Для правильного вибору розмірів системних параметрів `p` та `q` необхідно проаналізувати найефективніші алгоритми розв'язання задачі дискретного логарифма у скінченних полях:

### 1. Алгоритм крок немовляти — крок гіганта (Baby-Step Giant-Step, BSGS)

Алгоритм Деніела Шенкса (*Daniel Shanks*) знаходить логарифм `a = log_g h (mod q)` за час `O(√q)` та вимагає `O(√q)` пам'яті:
1. Покладемо `m = ⌈√q⌉`.
2. Обчислимо й збережемо у хеш-таблиці значення `g^j mod p` для всіх `j = 0...m-1` (кроки немовляти).
3. Обчислимо `γ = g^{-m} mod p`.
4. Декретно обчислюємо `h · γ^i mod p` для `i = 0...m-1` (кроки гіганта) і шукаємо збіг у хеш-таблиці. При збігу `g^j ≡ h · g^{-im}`, звідки `a = i·m + j mod q`.

### 2. Алгоритм Полларда ρ (Pollard's Rho Algorithm)

Алгоритм Джона Полларда дозволяє знайти дискретний логарифм за той самий час `O(√q)`, проте вимагає лише `O(1)` пам'яті. Він будує псевдовипадкову послідовність елементів `x_{k+1} = f(x_k)`, де `x_k = g^{u_k} · h^{v_k} mod p`, та знаходить цикл за допомогою алгоритму Флойда (алгоритм "черепахи й зайця"). З рівності `g^{u_A} · h^{v_A} ≡ g^{u_B} · h^{v_B} (mod p)` знаходять логарифм `a = (u_A - u_B) · (v_B - v_A)⁻¹ mod q`.

### 3. Алгоритм загального чисельного решета (GNFS / Index Calculus)

Для мультиплікативної групи `ℤ_p*` найшвидшим детермінованим алгоритмом є метод Index Calculus та його сучасне узагальнення — загальне чисельне решето (GNFS). Його складність є субекспоненційною:

```
L_p[1/3, c] = exp((c + o(1)) · (ln p)¹/³ · (ln ln p)²/³)
```

Саме через існування GNFS для полів `ℤ_p*` просте число `p` повинно мати довжину не менше 2048 бітів, тоді як порядок підгрупи `q` береться 256 бітів для захисту від алгоритму Полларда.

## Векторне розширення CHP для обробки довгих блоків (Vector CHP)

Початкова схема CHP стискає два блоки `(x₁, x₂)` в одне значення. Для обробки вектора з `k` блоків `(x₁, x₂, ..., x_k) ∈ (ℤ_q)^k` обирають `k` незалежних генераторів `g₁, g₂, ..., g_k ∈ G`.

Векторна хеш-функція обчислюється як модульний добуток:

```
Vector-CHP(x₁, x₂, ..., x_k) = (g₁^{x₁} · g₂^{x₂} · ... · g_k^{x_k}) mod p
```

**Теорема про векторне зведення:** Пошук колізії для `Vector-CHP` за поліноміальний час дозволяє обчислити дискретний логарифм `log_{g_i} g_j (mod q)` бодай для однієї пари генераторів `(g_i, g_j)`.

Доведення повністю аналогічне скалярному випадку: з порівняння `∏ g_i^{x_i} ≡ ∏ g_i^{y_i} (mod p)` виражається показник для будь-якої пари, де `x_j ≢ y_j (mod q)`.

## Модифікація CHP на еліптичних кривих (EC-CHP)

Для підвищення обчислювальної ефективності CHP можна перенести з мультиплікативної групи `ℤ_p*` у групу точок еліптичної кривої `E(𝔽_q)`.

Нехай `P` та `Q` — дві точки простого порядку `r` на еліптичній кривій `E(𝔽_q)` такі, що `Q = k · P`, де `k` — невідомий скаляр (дискретний логарифм на еліптичній кривій).

Для вхідних блоків `(m₁, m₂) ∈ ℤ_r × ℤ_r` еліптична хеш-функція обчислюється через скалярне множення точок:

```
EC-CHP(m₁, m₂) = m₁ · P + m₂ · Q
```

Колізія `m₁ · P + m₂ · Q = m₁' · P + m₂' · Q` дає рівність `(m₁ - m₁') · P = (m₂' - m₂) · Q = (m₂' - m₂) · k · P`, звідки мгновенно вираховується секретний скаляр `k = (m₁ - m₁') · (m₂' - m₂)⁻¹ mod r`.

Перевага EC-CHP полягає у тому, що через відсутність алгоритмів типу index calculus для еліптичних кривих, 128-бітовий рівень безпеки досягається вже при 256-бітовому розмірі поля `q`, що значно прискорює обчислення.

## Детальний числовий приклад обчислень у `ℤ₂₃*`

Проілюструємо математику CHP на числовому прикладі малого розміру.

### 1. Генерація параметрів системи

Оберемо прості числа:
```
q = 11                              [просте число Софі Жермен]
p = 2·11 + 1 = 23                   [безпечне просте число]
```

Група `ℤ₂₃* = {1, 2, ..., 22}` має порядок 22. 

Знайдемо підгрупу `G` порядку `q = 11`. Елемент `g = 2` у `ℤ₂₃*` має порядок 11:

```
2¹  = 2
2²  = 4
2³  = 8
2⁴  = 16
2⁵  = 32 ≡ 9 (mod 23)
2⁶  = 18 (mod 23)
2⁷  = 13 (mod 23)
2⁸  = 3 (mod 23)
2⁹  = 6 (mod 23)
2¹⁰ = 12 (mod 23)
2¹¹ = 24 ≡ 1 (mod 23)                [порядок елемента 2 дорівнює 11]
```

Підгрупа `G = {1, 2, 3, 4, 6, 8, 9, 12, 13, 16, 18}` містить ровно 11 елементів.

Оберемо другий генератор `h = 3 ∈ G`. З вищенаведеної таблиці степенів бачимо, що:
```
h = 3 = 2⁸ mod 23
```
Отже, секретний дискретний логарифм `a = log₂ 3 (mod 11)` дорівнює **`a = 8`**.

### 2. Обчислення хеш-значень для трьох різних пар

**Пара 1:** `(x₁, x₂) = (4, 7)`
```
CHP(4, 7) = (g⁴ · h⁷) mod 23
g⁴ = 2⁴ = 16 (mod 23)
h⁷ = 3⁷ = 2187 ≡ 2 (mod 23)           [бо 2187 = 95·23 + 2]
CHP(4, 7) = (16 · 2) mod 23 = 32 mod 23 = 9
```

**Пара 2:** `(x₁, x₂) = (9, 6)`
```
CHP(9, 6) = (g⁹ · h⁶) mod 23
g⁹ = 2⁹ = 512 ≡ 6 (mod 23)            [бо 512 = 22·23 + 6]
h⁶ = 3⁶ = 729 ≡ 16 (mod 23)           [бо 729 = 31·23 + 16]
CHP(9, 6) = (6 · 16) mod 23 = 96 mod 23 = 4
```

**Пара 3 (Крайовий випадок з нульовим компонентом):** `(x₁, x₂) = (0, 5)`
```
CHP(0, 5) = (g⁰ · h⁵) mod 23
g⁰ = 1 (mod 23)
h⁵ = 3⁵ = 243 ≡ 13 (mod 23)           [бо 243 = 10·23 + 13]
CHP(0, 5) = (1 · 13) mod 23 = 13
```

### 3. Демонстрація відновлення логарифма з штучної колізії

Припустимо, що у нашому малому полі знайдено колізійну пару `(x₁, x₂) = (2, 5)` та `(y₁, y₂) = (10, 4)`.

Перевіримо, що обидві пари дають однаковий хеш за модулем 23:

```
CHP(2, 5) = (2² · 3⁵) mod 23
2² = 4
3⁵ = 243 ≡ 13 (mod 23)                [бо 243 = 10·23 + 13]
CHP(2, 5) = (4 · 13) mod 23 = 52 mod 23 = 6

CHP(10, 4) = (2¹⁰ · 3⁴) mod 23
2¹⁰ = 1024 ≡ 12 (mod 23)              [бо 1024 = 44·23 + 12]
3⁴ = 81 ≡ 12 (mod 23)                 [бо 81 = 3·23 + 12]
CHP(10, 4) = (12 · 12) mod 23 = 144 mod 23 = 6
```

Обидві пари дали однакову остачу `6 (mod 23)`, тобто ми маємо колізію `CHP(2, 5) = CHP(10, 4)`.

Застосуємо нашу доведену формулу для відновлення секретного логарифма `a`:

```
x₁ = 2,  x₂ = 5
y₁ = 10, y₂ = 4

Δx₁ = x₁ - y₁ = 2 - 10 = -8 ≡ 3 (mod 11)
Δx₂ = y₂ - x₂ = 4 - 5 = -1 ≡ 10 (mod 11)

Знайдемо обернений елемент до Δx₂ = 10 за модулем 11:
10⁻¹ ≡ 10 (mod 11)                    [бо 10·10 = 100 = 9·11 + 1 ≡ 1 (mod 11)]

Обчислимо a:
a ≡ Δx₁ · (Δx₂)⁻¹ (mod 11)
a ≡ 3 · 10 (mod 11) = 30 mod 11 = 8 (mod 11)
```

Ми точнісінько відновили секретний дискретний логарифм `a = 8`!

Цей приклад наочно показує: жоден алгоритм не може створювати колізії у CHP, не вміючи розв'язувати задачу дискретного логарифмування.
