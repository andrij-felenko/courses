# ⚙️ Генератор Піфагорових трійок на C++

Ця реалізація демонструє алгоритмічне застосування методу хорди для прямої генерації всіх примітивних Піфагорових трійок, гарантуючи, що ми не пропускаємо жодного розв'язку і не робимо зайвих обчислень. Метод генерування через раціональні параметри кардинально кращий за будь-який перебір. 

### Постановка задачі та математична база

Класичний наївний підхід до пошуку Піфагорових трійок (a² + b² = c²) полягає у вкладених циклах, які перебирають усі можливі значення катетів a та b, після чого перевіряють, чи є сума їхніх квадратів ідеальним повним квадратом. Такий підхід має квадратичну складність O(N²) і виконує величезну кількість марної роботи, оскільки абсолютна більшість пар не утворює Піфагорову трійку. Крім того, такий алгоритм генерує багато похідних трійок (наприклад, 6, 8, 10), які є просто масштабованими копіями примітивної трійки (3, 4, 5).

Метод хорди дає нам точні аналітичні формули генерації: a = m² - n², b = 2mn, c = m² + n². Замість того, щоб перебирати самі сторони трикутника, ми будемо перебирати твірні параметри m та n. Щоб гарантовано отримувати лише примітивні трійки (де числа a, b, c взаємно прості в сукупності), параметри m та n повинні задовольняти три жорсткі інваріанти:
1. m більше за n, і обидва строго додатні.
2. m та n є взаємно простими (їхній найбільший спільний дільник НСД дорівнює 1).
3. m та n мають різну парність (одне з них обов'язково парне, а інше непарне).

### Архітектурна логіка

Архітектура нашого рішення базується на єдиній функції генератора, яка приймає ліміт за довжиною гіпотенузи. Ми використовуємо вкладені цикли для параметрів m та n. Оскільки гіпотенуза дорівнює c = m² + n², зовнішній цикл для m може зупинитися, щойно m² перевищить заданий ліміт c. Це надзвичайно звужує простір пошуку. 

Ми використовуємо стандартну бібліотеку `<numeric>`, яка у стандарті C++17 містить оптимізовану вбудовану функцію `std::gcd` для обчислення найбільшого спільного дільника за алгоритмом Евкліда. Це звільняє нас від необхідності писати власну рекурсію.

### Розбір коду по кроках

Уважно розглянемо саму реалізацію мовою C++17.

```cpp
#include <iostream>
#include <numeric>
#include <vector>

// Структура для зберігання знайденої Піфагорової трійки
struct PythagoreanTriple {
    long long a;
    long long b;
    long long c;
};

// Головна функція генерації трійок з обмеженням на гіпотенузу
std::vector<PythagoreanTriple> generatePrimitiveTriples(long long max_c) {
    std::vector<PythagoreanTriple> triples;
    
    // Зовнішній цикл: перебираємо m. 
    // Оскільки c = m^2 + n^2, верхня межа для m - це квадратний корінь з max_c.
    for (long long m = 2; m * m <= max_c; ++m) {
        
        // Внутрішній цикл: перебираємо n від 1 до m-1 (інваріант m > n > 0)
        for (long long n = 1; n < m; ++n) {
            
            // Інваріант парності: m та n повинні мати різну парність.
            // Якщо остачі від ділення на 2 однакові, пропускаємо ітерацію.
            if ((m % 2) == (n % 2)) {
                continue;
            }
            
            // Інваріант взаємної простоти: найбільший спільний дільник має бути 1.
            if (std::gcd(m, n) != 1) {
                continue;
            }
            
            // Обчислення сторін a, b, c за параметричними формулами методу хорди
            long long a = m * m - n * n;
            long long b = 2 * m * n;
            long long c = m * m + n * n;
            
            // Запобіжник: хоча m*m <= max_c, сума m^2 + n^2 може вийти за межу.
            if (c > max_c) {
                break; // Оскільки n зростає, наступні c теж будуть більшими, тому break.
            }
            
            // Усі перевірки пройдено, додаємо нову примітивну трійку до результату
            triples.push_back({a, b, c});
        }
    }
    return triples;
}

int main() {
    // Встановлюємо межу гіпотенузи
    long long max_hypotenuse = 100;
    
    // Викликаємо алгоритм генерації
    auto triples = generatePrimitiveTriples(max_hypotenuse);
    
    // Виводимо всі знайдені примітивні трійки на екран
    std::cout << "Примітивні Піфагорові трійки з гіпотенузою до " << max_hypotenuse << ":\n";
    for (const auto& t : triples) {
        std::cout << "(" << t.a << ", " << t.b << ", " << t.c << ")\n";
    }
    
    return 0;
}
```

### Аналіз складності I/O та висновки

Алгоритмічна складність нашого рішення є надзвичайно ефективною порівняно з наївними методами. Кількість ітерацій зовнішнього циклу становить приблизно квадратний корінь із `max_c`. Внутрішній цикл виконується `m` разів. Загальна кількість пар `(m, n)` пропорційна інтегралу від функції x, що дає площу трикутника, отже, асимптотична складність генерації становить O(max_c). 

Більше того, складність обчислення `std::gcd` є логарифмічною, O(log(min(m, n))), але завдяки відсіканню за парністю, ми викликаємо її значно рідше. Відповідно, просторова складність становить O(K), де K — кількість знайдених примітивних трійок (яка зростає приблизно лінійно відносно максимальної гіпотенузи). Завдяки використанню алгебраїчної параметризації ми перетворили неконтрольований перебір O(N²) на швидкий, лінійний алгоритм, який дає виключно цільові результати без жодних похибок чи дублікатів. Цей алгоритм є стандартним патерном у прикладному програмуванні та криптографії, де потрібна генерація еліптичних точок.
