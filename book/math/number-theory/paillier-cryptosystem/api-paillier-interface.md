# 📋 Специфікація інтерфейсу та контракт криптографічного API Пайє

Даний документ визначає формальний специфікований контракт криптографічного інтерфейсу програмного забезпечення (API) для криптосистеми Пайє. Опис охоплює детальний опис структур даних, бінарні формати серіалізації, типи ключів, перед- і пост-умови операцій, контракти обробки помилок та специфікації безпеки.

Специфікація розроблена для забезпечення повної сумісності та взаємозамінності криптографічних модулів мовами C, C++ та Python у розподілених високонавантажених системах.

## Апаратна та програмна поверхня підключення

Криптосистема Пайє на програмному рівні представляє собою набір незмінних (Immutable) даних та чистих функцій (Pure Functions), які виконують обчислення у кільцях залишків `ℤ_n` та `ℤ_{n²}*`.

На відміну від симетричних блочних шифрів (таких як AES-GCM), криптосистема Пайє не зберігає внутрішнього стану сесії (State-Less API). Кожна операція шифрування, розшифрування чи гомоморфної комбінації є повністю самодостатньою та приймає всі необхідні параметри через відповідні структури ключів.

На апаратному рівні криптографічний модуль взаємодіє з системним джерелом ентропії (Hardware True Random Number Generator або OS CSPRNG) для генерації маскувального шуму `r` при кожному виклику функції шифрування.

## Структури даних та параметри криптографічних ключів

Криптосистема Пайє використовує дві базові структури даних для представлення ключів та зашифрованих контейнерів.

### 1. Відкритий ключ (PaillierPublicKey)

Структура `PaillierPublicKey` містить усі параметри, необхідні для шифрування відкритих текстів та проведення гомоморфних обчислень на сторонніх недовірених серверах.

Ця структура є повністю публічною і може вільно поширюватися мережею, передаватися в хмарні сервіси чи публікуватися в реєстрі відкритих ключів.

Детальний опис полів структури `PaillierPublicKey`:

- `n`: Основний RSA-модуль `n = p · q`, який виступає базовим діапазоном для відкритих повідомлень `m ∈ [0, n − 1]`. Займає `k` біт у пам'яті (наприклад, 2048 або 4096 біт).
- `n_sq`: Попередньо обчислений квадрат модуля `n² = n · n`, який є модулем для всіх зашифрованих чисел `c ∈ ℤ_{n²}*`. Займає `2k` біт у пам'яті. Попереднє обчислення `n²` при ініціалізації усуває потребу повторного множення великих чисел при кожній гомоморфній операції.
- `g`: Генератор аддитивної підгрупи залишків. У канонічній схемі фіксується як `g = 1 + n mod n²`, що скасовує важкі операції модульного піднесення до степеня під час шифрування.
- `bits`: Ціле число, яке вказує точну бітову довжину модуля `n` (наприклад, 2048, 3072 або 4096). Використовується для швидких перевірок межевих умов при розподілі пам'яті.

**Контракт ідепотентності та незмінності:**
- Об'єкт `PaillierPublicKey` є повністю потокобезпечним (Thread-Safe) і може одночасно використовуватися довільною кількістю робочих потоків без застосування м'ютексів чи блокувань.
- Після завершення процедури ініціалізації всі поля структури стають доступними лише для читання (Read-Only).

### 2. Приватний ключ (PaillierPrivateKey)

Структура `PaillierPrivateKey` містить секретні математичні константи, необхідні для розшифрування шифротекстів та підписання доведень з нульовим розголошенням.

Детальний опис полів структури `PaillierPrivateKey`:

- `pub`: Вкладений екземпляр публічного ключа `PaillierPublicKey`, який забезпечує доступ до параметрів `n` та `n²` під час розшифрування.
- `p`: Перше секретне просте число бітової довжини `k / 2`. Повинно зберігатися в суворій таємниці.
- `q`: Друге секретне просте число бітової довжини `k / 2`. Повинно зберігатися в суворій таємниці.
- `lam`: Показник Кармайкла `λ = нск(p − 1, q − 1)`, який є секретним універсальним показником нейтралізації маскувального шуму `r^n`.
- `mu`: Попередньо обчислений приватний коефіцієнт `μ = (L(g^λ mod n²))⁻¹ mod n`, який у спрощеній канонічній схемі дорівнює `λ⁻¹ mod n`.
- `hp`, `hq`: Попередньо обчислені коефіцієнти прискорення дешифрування за китайською теоремою про лишки (CRT), які дозволяють виконувати розшифрування за модулями `p²` та `q²`.

**Контракт безпеки пам'яті:**
- Екземпляр `PaillierPrivateKey` повинен зберігатися виключно в заблокованій оперативній пам'яті (`mlock`), яка захищена від вивантаження на диск у файл підкачки (Swap).
- Деструктор об'єкта `PaillierPrivateKey` у C++ зобов'язаний виконувати гарантоване очищення пам'яті `OPENSSL_cleanse()`, яке не оптимізується компілятором.

## Формат бінарної серіалізації (ASN.1 DER, PEM та JSON)

Для забезпечення взаємодії між різними мовами програмування та мережевими протоколами специфікація визначає канонічні бінарні та текстові формати серіалізації.

### 1. Серіалізація публічного ключа в ASN.1 DER та PEM

Публічний ключ серіалізується відповідно до загальноприйнятого стандарту ASN.1 (Abstract Syntax Notation One) з використанням правил канонічного кодування DER (Distinguished Encoding Rules).

Для збереження на диску DER-структура кодується в текстовий формат PEM (Privacy-Enhanced Mail) з додаванням стандартних заголовків:

```
-----BEGIN PAILLIER PUBLIC KEY-----
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAu...
-----END PAILLIER PUBLIC KEY-----
```

Структура документа містить ідентифікатор алгоритму (OID), бітову довжину модуля та великі цілі числа `n` і `g`, заковані у форматі Big-Endian з можливим додаванням нульового старшого байта для збереження додатного знака числа.

### 2. Серіалізація зашифрованих даних у JSON

Для REST API та мікросервісної архітектури шифротексти та супутні доведення з нульовим розголошенням пакуються у текстові JSON-контейнери. Великі цілі числа кодуються як шестнадцятерічні рядки з префіксом `0x` або у форматі Base64URL.

JSON-структура включає версію протоколу, криптографічний відбиток публічного ключа (Key Fingerprint), точну довжину шифротексту в байтах та вкладений блок ZKP-доведення Range Proof.

## Сигнатури та детальний аналіз функцій API

Розглянемо специфікацію та контракти програмного інтерфейсу C/C++ бібліотеки.

### 1. Генерація пар ключів (paillier_keygen)

Функція `paillier_keygen` відповідає за створення нової пари ключів заданої криптографічної стійкості.

Під час виконання функція виконує такі кроки:
- Перевіряє, що запитана бітова довжина `bits` є не меншою за 2048 і кратною 128.
- Викликає системний генератор ентропії для вибору випадкових кандидатів `p` та `q`.
- Проводить серію з 40 ітерацій тесту простоти Міллера — Рабіна для кожного числа.
- Обчислює добуток `n = p · q` та перевіряє, що `p` та `q` мають однакову бітову довжину і не є занадто близькими одне до одного.
- Обчислює приватні параметри `λ` та `μ`.

При успішному завершенні функція виділяє пам'ять під обидві структури і повертає код `PAILLIER_SUCCESS`.

### 2. Зашумлене шифрування відкритого тексту (paillier_encrypt)

Функція `paillier_encrypt` приймає відкрите повідомлення `m` та публічний ключ `pub`.

Покроковий контракт виконання:
- Перевіряє перед-умову: значення `m` має строго задовольняти нерівність `0 ≤ m < n`. Якщо `m` перевищує `n`, повертається код помилки `PAILLIER_ERR_MSG_OUT_OF_BOUNDS`.
- Звертається до CSPRNG для вибору випадкового елемента `r ∈ [1, n − 1]`.
- Перевіряє умову взаємної простоти `нсд(r, n) = 1`. Якщо обране `r` ділить `n`, обирається нове значення `r`.
- Обчислиє зашумлений шифротекст `c = (1 + m·n) · r^n mod n²`.
- Записує результат у вихідний об'єкт `ciphertext` і повертає `PAILLIER_SUCCESS`.

### 3. Детерміноване розшифрування (paillier_decrypt)

Функція `paillier_decrypt` відновлює вихідне повідомлення `m` за допомогою приватного ключа `priv`.

Покроковий контракт виконання:
- Перевіряє перед-умову: шифротекст `ciphertext` має строго лежати в інтервалі `(0, n²)`.
- Якщо в приватному ключі наявні CRT-коефіцієнти `hp` та `hq`, функція виконує прискорене дешифрування за китайською теоремою про лишки за модулями `p²` та `q²`.
- У протилежному випадку виконується піднесення до степеня `u = c^λ mod n²`, обчислюється `L(u) = (u − 1) / n` та проводиться множення на `μ mod n`.
- Якщо відновлене значення `m` перевищує `n / 2`, виконується декодування від'ємного числа у доповняльному коді.
- Повертає `PAILLIER_SUCCESS`.

### 4. Гомоморфне додавання зашифрованих даних (paillier_homomorphic_add)

Функція `paillier_homomorphic_add` виконує підсумування двох відкритих текстів шляхом множення їхніх шифротекстів на недовіреній стороні.

Покроковий контракт виконання:
- Перевіряє перед-умови: обидва шифротексти `c₁` та `c₂` мають бути меншими за `n²`.
- Обчислює модульний добуток `c_out = (c₁ · c₂) mod n²`.
- Операція не вимагає знання приватного ключа і не змінює рівень криптографічного зашумлення.
- Повертає `PAILLIER_SUCCESS`.

### 5. Гомоморфне скалярне множення (paillier_homomorphic_mul_scalar)

Функція `paillier_homomorphic_mul_scalar` реалізує множення зашифрованого повідомлення на відкриту цілу константу `k`.

Покроковий контракт виконання:
- Перевіряє перед-умови: `c < n²`.
- Якщо скаляр `k` є від'ємним (`k < 0`), функція спочатку обчислює модульний інверс шифротексту `c_inv = c⁻¹ mod n²`, після чого підносить `c_inv` до додатного степеня `|k| mod n²`.
- Записує підсумковий шифротекст `c_out = c^k mod n²`.
- Повертає `PAILLIER_SUCCESS`.

### 6. Експорт та імпорт ключів (paillier_key_export / paillier_key_import)

Функції експорту та імпорту забезпечують збереження та відновлення ключів з зашифрованих бінарних або PEM буферів.

Покроковий контракт виконання:
- При експорті приватного ключа функція вимагає введення парольної фрази (Passphrase) для симетричного зашифрування алгоритмом AES-256-GCM.
- При імпорті виконується валідація математичних тотожностей `n = p · q` та `g^λ mod n² ≡ 1 + λ·n (mod n²)`. Якщо ключовий файл пошкоджено або підроблено, повертається код `PAILLIER_ERR_KEY_CORRUPTED`.

## Обробка виняткових ситуацій та граничні умови

Модуль передбачає сувору обробку помилок на кожному етапі обчислень.

Розглянемо основні граничні випадки:

1. **Переповнення модуля при гомоморфному додаванні:** Якщо сума відкритих повідомлень `m₁ + m₂` перевищує `n`, результат за модулем `n` циклічно обнуляється (wrap-around). Програма повинна контролювати максимальну кількість доданків `N_max`, щоб не допустити переповнення.
2. **Спроба розшифрувати некоректне число:** Якщо на вхід `paillier_decrypt` подано число `c`, яке є кратним `p` або `q` (тобто `нсд(c, n²) != 1`), функція негайно зупиняє обчислення і повертає код `PAILLIER_ERR_CIPHERTEXT_INVALID`. Це запобігає атак на витік факторів модуля через дешифрувальний оракул.
3. **Збій системного джерела ентропії:** Якщо виклик системної функції отримання випадкових байтів повертає помилку, шифрування переривається з кодом `PAILLIER_ERR_CSPRNG_FAILED`. Використання нестійких або детермінованих псевдовипадкових генераторів категорично заборонено.

## Потокобезпечність та паралелізм (Thread-Safety & Concurrency)

Розглянемо вимоги до поведінки API в багатопотокових середовищах:

- **Паралельне шифрування (Concurrent Encryption):** Багатопотокові виклики `paillier_encrypt` з одним і тим самим об'єктом `PaillierPublicKey` є абсолютно безпечними і не вимагають зовнішньої синхронізації, оскільки кожен потік використовує власний локальний CSPRNG-контекст.
- **Паралельне розшифрування (Concurrent Decryption):** Функція `paillier_decrypt` може викликатися паралельно з кількох потоків, якщо вони не модифікують об'єкт `PaillierPrivateKey`. Тимчасові обчислювальні буфери Монтгомері allocated локально в кожному потоці.
- **Пули потоків та асинхронні обчислення:** У високопродуктивних C++20 серверах операції гомоморфного додавання масивів `paillier_homomorphic_add` автоматично розпаралелюються між ядрами CPU за допомогою OpenMP або C++ Execution Policies (`std::execution::par`).

## Градація рівнів криптографічної стійкості (NIST / BSI)

Специфікація API визначає суворі параметри бітової довжини модуля `n` відповідно до рекомендацій NIST SP 800-57 та Німецького федерального офісу з безпеки інформації (BSI):

- **Рівень 112 біт (Legacy, n = 2048 біт, n² = 4096 біт):** Мінімально припустимий розмір ключа для сумісності зі старими системами. Дозволено для використання до 2030 року.
- **Рівень 128 біт (Standard, n = 3072 біт, n² = 6144 біт):** Базовий стандарт для всіх нових промислових розробок. Забезпечує довгостроковий захист від факторизації.
- **Рівень 192 біт (High, n = 7680 біт, n² = 15360 біт):** Підвищений рівень безпеки для критично важливих фінансових та медичних систем.
- **Рівень 256 біт (TopSec, n = 15360 біт, n² = 30720 біт):** Найвищий рівень захисту державних та військових секретів.

## Інтеграційні вимоги та сумісність мовних обгорток

Для забезпечення сумісності C/C++ ядра з мовами вищого рівня (Python, Go, Rust, Java) специфікація передбачає:

1. **C-Compatible ABI:** Усі функції експортуються з заголовком `extern "C"`, що усуває манглювання імен і дозволяє прямо імпортувати бібліотеку через `ctypes` / `cffi` у Python або `cgo` у Go.
2. **Нульове копіювання буферів (Zero-Copy Transfer):** Передача великих масивів шифротекстів виконується через вказівники на вирівняні в пам'яті буфери `uint8_t*` з вказанням довжини в байтах.
3. **Обробка винятків у обгортках:** Мовні обгортки (Python wrapper) транслюють від'ємні коди помилок у відповідні винятки мови вищого рівня (`ValueError`, `MemoryError`, `CryptoError`).

Дана специфікація становить повний технічний контракт для промислової розробки та аудитів криптографічних модулів Пайє.


## Аудит безпеки та контракти журналювання (Security Audit & Telemetry)

Для підтримки промислової відповідності вимогам ISO/IEC 27001 та SOC2 криптографічний модуль надає стандартизований контракт журналювання аудійованих подій:

- **Реєстрація криптографічних відбитків (Key Fingerprinting):** Кожна операція розшифрування чи генерації ключів фіксує в системному журналі лише Хеш-відбиток SHA-256 від публічного ключа `pub_key`. Жодні елементи приватного ключа `λ`, `p`, `q` чи проміжні значення `u = c^λ mod n²` ніколи не потрапляють у лог-файли.
- **Журналювання помилок дешифрування:** Спроби дешифрування неструктурованих шифротекстів фіксуються в журналі аудиту безпеки з позначкою `SECURITY_ALERT_INVALID_CIPHERTEXT`. Це дозволяє SIEM-системам виявляти спроби атак за допомогою підроблених зашифрованих пакетів у режимі реального часу.
- **Гарантії вирівнювання пам'яті (Memory Alignment Guarantees):** Для прискорення обчислень на сучасних SIMD-процесорах структури ключів та буфери `BigInt` вирівнюються на межу 64 байтів (`alignas(64)`), що відповідає розміру кєш-лінії сучасних процесорів x86_64 та ARM64.

## Завершальний підсумок контракту API

Сформований API-контракт забезпечує вичерпну специфікацію для розробки безпечних, високонавантажених та сумісних модулів криптосистеми Пайє. Суворі перед- і пост-умови операцій, прозора обробка помилок та підтримка стандартів NIST і ASN.1 гарантують високу надійність підсистеми у складі складових розподілених продуктів.

Додатково інтерфейс гарантує повну зворотну сумісність із протоколами передачі зашифрованих даних попередніх версій, забезпечуючи плавну міграцію ключової інфраструктури без зупинки працюючих сервісів.
