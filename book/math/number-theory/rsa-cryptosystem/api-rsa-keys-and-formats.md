# 📋 Специфікація форматів ключів, ASN.1 та інструментарій OpenSSL

Криптосистема RSA спирається на набір чітко визначених математичних параметрів та міжнародних стандартів (RFC 8017 / PKCS #1 v2.2), які регулюють структуру ключів, їх двійкове кодування у форматі ASN.1 DER, текстове представлення PEM та інтерфейси командного рядка для керування ними у розробці та адмініструванні систем.

---

## 1. Математична специфікація параметрів ключів

Пара ключів RSA містить два типи об'єктів: відкритий ключ (Public Key), призначений для вільного поширення, та приватний ключ (Private Key), який мусить зберігатися у суворій конфіденційності.

### Кортеж відкритого ключа (Public Key)

Відкритий ключ описується впорядкованою парою двох натуральних чисел:

```
K_pub = (N, e)
```

| Параметр | Позначення | Специфікація та вимоги |
| :--- | :--- | :--- |
| **Модуль (Modulus)** | `N` | Добуток двох великих простих чисел `N = p · q`. Стандартна бітова довжина: 2048, 3072 або 4096 біт. |
| **Відкритий показник (Public Exponent)** | `e` | Ціле число, взаємно просте з `ϕ(N)` (`НСД(e, ϕ(N)) = 1`). Стандартне значення: `65537` (`2¹⁶ + 1`). |

### Кортеж приватного ключа (Private Key)

Повний приватний ключ для забезпечення швидкого розшифрування за допомогою Китайської теореми про лишки (CRT) містить кортеж з 8 математичних величин:

```
K_priv = (N, e, d, p, q, d_p, d_q, q_{inv})
```

| Параметр | Позначення | Математична формула / Опис |
| :--- | :--- | :--- |
| **Модуль** | `N` | `N = p · q` |
| **Відкритий показник** | `e` | `НСД(e, (p-1)(q-1)) = 1` |
| **Приватний показник** | `d` | `d ≡ e⁻¹ (mod ϕ(N))` |
| **Перше просте число** | `p` | Старший простий множник модуля `N` |
| **Друге просте число** | `q` | Молодший простий множник модуля `N` |
| **Експонента p (CRT)** | `d_p` | `d_p = d mod (p − 1)` |
| **Експонента q (CRT)** | `d_q` | `d_q = d mod (q − 1)` |
| **Коефіцієнт CRT** | `q_{inv}` | `q_{inv} = q⁻¹ mod p` |

## 2. Принципи кодування ASN.1 та правила DER

Для передачі та зберігання ключів у файлових системах та мережевих протоколах математичні параметри упаковуються у формалізовану мову опису структур даних **ASN.1** (Abstract Syntax Notation One).

ASN.1 визначає абстрактну типів даних (числа, рядки, послідовності), які потім кодуються у двійковий вигляд за допомогою конкретних правил. Для криптографічних застосувань використовуються канонічні правила кодування **DER** (Distinguished Encoding Rules), які гарантують єдиний канонічний байтовий вигляд для будь-якого об'єкта.

Кожен елемент у форматі DER будується за принципом **TLV** (Tag-Length-Value):
- **Tag (Тег, 1 байт):** Визначає тип даних. Наприклад, `0x02` означає `INTEGER`, `0x30` — `SEQUENCE` (послідовність), `0x03` — `BIT STRING`.
- **Length (Довжина, 1–5 байт):** Задає розмір даних у байтах. Для довжин до 127 байт використовується 1 байт; для більших довжин перший байт вказує кількість наступних байтів довжини (наприклад, `0x82 0x01 0x00` вказує на 256 байт).
- **Value (Значення):** Самі двійкові дані.

### Особливість кодування цілих чисел INTEGER в DER

Усі цілі числа `INTEGER` у форматах DER кодуються як числа зі знаком у доповняльному коді (Two's Complement). Якщо найстарший біт першого байта числа дорівнює 1 (тоді значення починається з `0x80`..`0xFF`), синтаксичний аналізатор витлумачить число як від'ємне.

Оскільки всі елементи RSA (модуль `N`, показник `d` тощо) є додатними натуральними числами, кодувальник зобов'язаний додавати нульовий префіксний байт `0x00` перед будь-яким числом, у якого найстарший біт першого значущого байта дорівнює одиниці. Наприклад, 2048-бітний модуль `N` часто займає в DER не 256, а **257 байтів** за рахунок провідного `0x00`.

## 3. Специфікація структур PKCS #1 (RFC 8017)

Історично першим і найпростішим є стандарт PKCS #1, який описує ключі RSA безпосередньо як списки цілих чисел `INTEGER` у єдиній послідовності `SEQUENCE`.

### Приватний ключ: RSAPrivateKey

Формат `RSAPrivateKey` визначає повний кортеж приватного ключа разом із заздалегідь обчисленими компонентами для прискорення за допомогою Китайської теореми про лишки:

```asn1
RSAPrivateKey ::= SEQUENCE {
    version           Version,         -- 0 для двох множників (two-prime)
    modulus           INTEGER,         -- N
    publicExponent    INTEGER,         -- e
    privateExponent   INTEGER,         -- d
    prime1            INTEGER,         -- p
    prime2            INTEGER,         -- q
    exponent1         INTEGER,         -- d mod (p-1)
    exponent2         INTEGER,         -- d mod (q-1)
    coefficient       INTEGER,         -- (inverse of q) mod p
    otherPrimeInfos   OtherPrimeInfos OPTIONAL -- Використовується якщо >2 простих
}

Version ::= INTEGER { two-prime(0), multi(1) }
```

### Відкритий ключ: RSAPublicKey

Відкритий ключ у форматі PKCS #1 містить лише модуль та відкриту експоненту:

```asn1
RSAPublicKey ::= SEQUENCE {
    modulus           INTEGER,         -- N
    publicExponent    INTEGER          -- e
}
```

## 4. Універсальні структури X.509 та PKCS #8

У сучасних програмних комплексах використання голих структур PKCS #1 викликає незручності, оскільки аналізатор файлів не може автоматично визначити, для якого саме криптографічного алгоритму призначений ключ (RSA, ECC, Ed25519 чи DSA). Для вирішення цієї проблеми розроблено універсальні обгортки.

Універсальні структури додають цифровий ідентифікатор алгоритму **OID** (Object Identifier). Для алгоритму `rsaEncryption` стандартний OID дорівнює `1.2.840.113549.1.1.1`.

### Відкритий ключ X.509 (SubjectPublicKeyInfo — RFC 5280)

Структура `SubjectPublicKeyInfo` є стандартом для збереження відкритого ключа у сертифікатах X.509 та мережевому протоколі TLS:

```asn1
SubjectPublicKeyInfo ::= SEQUENCE {
    algorithm         AlgorithmIdentifier,
    subjectPublicKey  BIT STRING
}

AlgorithmIdentifier ::= SEQUENCE {
    algorithm         OBJECT IDENTIFIER, -- 1.2.840.113549.1.1.1 (rsaEncryption)
    parameters        ANY DEFINED BY algorithm OPTIONAL -- NULL для RSA
}
```

Вміст поля `subjectPublicKey` є двійковим кодом `RSAPublicKey` стандарту PKCS #1, загорнутим у бітовий рядок.

### Приватний ключ PKCS #8 (PrivateKeyInfo — RFC 5208 / RFC 5958)

Універсальний приватний ключ стандарту PKCS #8 огортає будь-який приватний ключ алгоритмів асиметричної криптографії:

```asn1
PrivateKeyInfo ::= SEQUENCE {
    version           Version,         -- 0 (v1) або 1 (v2)
    privateKeyAlgorithm AlgorithmIdentifier,
    privateKey        OCTET STRING,    -- Двійкове кодування RSAPrivateKey
    attributes        [0] IMPLICIT Attributes OPTIONAL
}
```

## 5. Заголовки текстових форматів PEM

Формат **PEM** (Privacy-Enhanced Mail) являє собою текстове кодування двійкових ASN.1 DER структур у форматі Base64 із додаванням захисних текстових заголовків (Armor headers). Текстове кодування дозволяє передавати ключі електронною поштою, вставляти їх у текстові конфігураційні файли або середовища CI/CD без ризику пошкодження двійкових байтів при форматуванні.

```
   Контекст ключа                 Формат PEM Заголовок / Закінчення
┌───────────────────────────┬─────────────────────────────────────────────────────────────┐
│ PKCS #1 Приватний ключ    │ -----BEGIN RSA PRIVATE KEY-----                             │
│                           │ -----END RSA PRIVATE KEY-----                               │
├───────────────────────────┼─────────────────────────────────────────────────────────────┤
│ PKCS #1 Відкритий ключ    │ -----BEGIN RSA PUBLIC KEY-----                              │
│                           │ -----END RSA PUBLIC KEY-----                                │
├───────────────────────────┼─────────────────────────────────────────────────────────────┤
│ PKCS #8 Приватний ключ    │ -----BEGIN PRIVATE KEY-----                                 │
│ (Загальний/Сучасний)      │ -----END PRIVATE KEY-----                                   │
├───────────────────────────┼─────────────────────────────────────────────────────────────┤
│ PKCS #8 Зашифрований      │ -----BEGIN ENCRYPTED PRIVATE KEY-----                       │
│ Приватний ключ            │ -----END ENCRYPTED PRIVATE KEY-----                         │
├───────────────────────────┼─────────────────────────────────────────────────────────────┤
│ X.509 Відкритий ключ      │ -----BEGIN PUBLIC KEY-----                                  │
│ (Загальний/Сучасний)      │ -----END PUBLIC KEY-----                                    │
└───────────────────────────┴─────────────────────────────────────────────────────────────┘
```

## 6. Практичний інструментарій OpenSSL CLI

Для генерації, інспектування, конвертації та тестування ключів RSA у консольному середовищі використовується утиліта OpenSSL.

### 1. Генерація пари ключів

Генерація приватного ключа RSA довжиною 3072 біти у сучасному форматі PKCS #8:

```bash
# Генерація приватного ключа (без пароля)
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out private_key.pem

# Генерація приватного ключа, захищеного паролем (AES-256)
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 \
    -aes256 -pass pass:SuperSecretPass123 -out encrypted_private_key.pem
```

### 2. Екстракція відкритого ключа

Витяг відкритого ключа у форматі X.509 `SubjectPublicKeyInfo` з приватного:

```bash
openssl pkey -in private_key.pem -pubout -out public_key.pem
```

### 3. Дамп та перевірка математичних параметрів

Перегляд усіх 8 математичних компонентів приватного ключа у числовому вигляді:

```bash
openssl pkey -in private_key.pem -text -noout
```

Приклад виводу OpenSSL:

```text
RSA Private-Key: (3072 bit, 2 primes)
modulus:
    00:c3:91:f4:88:...
publicExponent: 65537 (0x10001)
privateExponent:
    47:19:a2:b1:cd:...
prime1:
    00:f5:aa:12:bc:...
prime2:
    00:cb:88:45:ef:...
exponent1:
    3b:41:c8:71:09:...
exponent2:
    12:89:dd:ee:56:...
coefficient:
    78:99:ab:cd:ef:...
```

### 4. Конвертація між форматами PKCS #1 та PKCS #8

```bash
# Перетворення приватного ключа PKCS #8 (BEGIN PRIVATE KEY) у PKCS #1 (BEGIN RSA PRIVATE KEY)
openssl rsa -in private_key.pem -traditional -out private_pkcs1.pem

# Перетворення назад у сучасний PKCS #8
openssl pkey -in private_pkcs1.pem -out private_pkcs8.pem
```

### 5. Зашифрування та розшифрування файлу через OpenSSL CLI

Для відкритих файлів використовується комбінація шифрування з доповненням OAEP:

```bash
# Зашифрування файлу secret.txt за допомогою відкритого ключа
openssl pkeyutl -encrypt -in secret.txt -pubin -inkey public_key.pem \
    -pkeyopt rsa_padding_mode:oaep -pkeyopt rsa_oaep_md:sha256 -out encrypted.bin

# Розшифрування файлу за допомогою приватного ключа
openssl pkeyutl -decrypt -in encrypted.bin -inkey private_key.pem \
    -pkeyopt rsa_padding_mode:oaep -pkeyopt rsa_oaep_md:sha256 -out decrypted.txt
```

## 7. Обмеження та стандарти безпеки

- **Мінімальна довжина модуля `N`:** Стандарт NIST SP 800-57 рекомендує мінімальний розмір ключа RSA у **2048 біт** для поточного використання. Для довгострокового захисту даних (після 2030 року) обов'язковим є розмір **3072 біти** або **4096 біт**.
- **Значення `e`:** Показник `e = 65537` (`0x10001`) є стандартом de facto, оскільки містить лише дві одиниці в двійковому записі (`10000000000000001₂`), що вимагає всього 16 квадратів і 1 множення при зашифруванні, при цьому повністю протистоїть атакам типу Вінера та Копперсміта.
- **Парсинг в C/C++:** При написанні парсерів DER-структур слід перевіряти переповнення буфера та валідувати значення довжини перед копіюванням байтів у розрядні масиви big-integer бібліотек.
