# 🔍 Тест простоти Ферма: сказати «складене», не знайшовши жодного дільника

Мала теорема Ферма, прочитана як заперечення, дає найдешевший спосіб спитати величезне число «ти просте?» і в разі «ні» **довести** це одним піднесенням до степеня — ані на що число не розкладаючи; саме цей тест щосекунди підбирає прості для ключів RSA.

<preknowlist>
- [Модульна арифметика](topic:math/modular-arithmetic) — запис a ≡ b (mod n) означає «однакова остача при діленні на n»; додавати, множити й підносити до степеня можна прямо на остачах, не виходячи за межі 0 … n−1.
- [НСД і взаємна простота](topic:math/gcd-euclidean) — коли найбільший спільний дільник двох чисел дорівнює 1, вони не мають спільного простого множника; такі числа звуть взаємно простими.
</preknowlist>

## Задача, якої не бере розклад

Генератор ключів RSA щоразу мусить знайти пару великих простих чисел — на кілька сотень десяткових цифр кожне. Стійкість шифру тримається саме на тому, що розкласти їхній добуток на множники не здатен ніхто: ні за роки, ні за століття машинного часу. Але тоді постає незручне питання: як переконатися, що знайдений кандидат n **сам** простий, коли навіть його розклад нам не до снаги?

Найпростіший шлях — перебирати дільники до √n — тут не годиться. Для стоцифрового n це близько 10⁵⁰ проб; навіть мільярд проб на секунду розтягнув би перевірку на 10⁴¹ секунд, а Всесвіту заледве 10¹⁷. Потрібен тест, що виносить вирок **не розкладаючи** — і теорема Ферма дає рівно такий, бо говорить про просте число щось, що можна перевірити самим лише піднесенням до степеня, ні разу не спитавши про дільники.

## Ідея: перетворити теорему на заперечення

Теорема стверджує: якщо p просте, то для кожного a, взаємно простого з p,

```
aᵖ⁻¹ ≡ 1 (mod p)
```

Оберни це твердження. Якщо для якогось конкретного a раптом виявилося, що

```
aⁿ⁻¹ ≢ 1 (mod n),
```

то n **напевно не просте** — інакше рівність мусила б виконатися. Таку основу a називають **свідком** складеності: вона доводить, що n складене, і доводить, ні на що n не розклавши. Ми дізнаємося факт про будову n, не побачивши жодного його множника. Оце й найдивовижніше в тесті: він викриває складеність, лишаючи розклад цілком невідомим.

Зворотний бік не такий певний. Якщо aⁿ⁻¹ ≡ 1, це ще **не** доводить простоти n: рівність, яку зобов'язане давати кожне просте, іноді дає й складене число. Тому одна вдала перевірка нічого не гарантує, а основу, що промовчала перед складеним n, звуть **брехуном**. Ліки прості: беремо не одну основу, а кілька різних. Перший-ліпший свідок остаточно вбиває кандидата; а що більше основ підряд промовчали, то менше шансів, що всі вони брехуни. Тест **односторонній**: «складене» — це вирок, «імовірно просте» — лише зростаюча підозра на простоту.

## Двигун: піднесення до степеня, що не роздуває чисел

Уся робота тесту — обчислити aⁿ⁻¹ mod n. Але показник n−1 для стоцифрового n сам має сотню цифр; помножити a на себе n−2 рази так само неможливо, як і перебрати дільники. Рятує **піднесення до степеня квадратами** (square-and-multiply): показник читають по бітах, і замість n−1 множень вистачає приблизно log₂n — для стоцифрового n це якихось 330 множень замість 10¹⁰⁰.

Ідея в тому, що aⁿ⁻¹ можна скласти зі «сходинок-квадратів» a, a², a⁴, a⁸, … — кожна наступна є квадратом попередньої, тож коштує одне множення, — а потім перемножити лише ті сходинки, які стоять під одиничними бітами показника. І головне: після **кожного** множення результат одразу зводять за модулем n, тож числа ніколи не виростають більші за n². Докладніше про сам механізм і його оцінку — у [швидкому піднесенні до степеня за модулем](topic:math/modular-exponentiation); тут воно нам — готовий двигун.

## Робочий код

Спершу сам двигун — цикл square-and-multiply, щоб було видно, з чого він зроблений:

```python
def modpow(base, exp, mod):
    result = 1
    base %= mod
    while exp > 0:
        if exp & 1:                     # молодший біт показника = 1?
            result = result * base % mod    # ...домножити поточну сходинку
        base = base * base % mod        # наступна сходинка — квадрат
        exp >>= 1                       # зсув до наступного біта
    return result
```

У самому Python цей цикл писати не конче: вбудований `pow(a, e, m)` робить рівно те саме, тільки в C і з цілими довільної точності «під капотом». Тому ідіоматичний тест Ферма — це кілька рядків, де вся важка робота сидить у `pow`. У C такого дарунку немає, і та сама функція оголює шар, що його Python ховає, — тож порівняймо дві мови поруч:

:::tabs
```python
import random

def is_probable_prime(n, k=20):
    if n < 4:
        return n in (2, 3)              # 2 і 3 прості; 0 та 1 — ні
    if n % 2 == 0:
        return False                    # усе парне, крім 2, складене
    for _ in range(k):
        a = random.randrange(2, n - 1)  # основа у діапазоні 2 … n−2
        if pow(a, n - 1, n) != 1:       # знайшовся свідок
            return False                # n НАПЕВНО складене
    return True                         # усі k основ промовчали → імовірно просте
```
```c
#include <stdint.h>
#include <stdbool.h>

// a·b mod m без переповнення: добуток двох майже-64-бітних чисел не влазить
// у 64 біти, тож множимо у 128-бітному проміжку й лише тоді беремо остачу.
static uint64_t mulmod(uint64_t a, uint64_t b, uint64_t m) {
    return (uint64_t)((unsigned __int128)a * b % m);
}

static uint64_t powmod(uint64_t base, uint64_t exp, uint64_t m) {
    uint64_t result = 1;
    base %= m;
    while (exp > 0) {
        if (exp & 1) result = mulmod(result, base, m);  // домножити сходинку
        base = mulmod(base, base, m);                   // наступний квадрат
        exp >>= 1;
    }
    return result;
}

bool is_probable_prime(uint64_t n, const uint64_t *bases, int k) {
    if (n < 4)      return n == 2 || n == 3;
    if (n % 2 == 0) return false;
    for (int i = 0; i < k; i++) {
        uint64_t a = bases[i] % n;
        if (a < 2) continue;                 // основи 0 та 1 нічого не кажуть
        if (powmod(a, n - 1, n) != 1)        // свідок складеності
            return false;                    // n напевно складене
    }
    return true;                             // імовірно просте
}
```
:::

Той самий алгоритм, але C робить видимим те, про що Python мовчить. У рядку `base = base * base % mod` обидва множники менші за n, проте їхній добуток — ні: для n близького до 2⁶⁴ квадрат сягає майже 2¹²⁸ і у звичайний 64-бітний тип не влазить, тихо «перевертаючись» через нуль. Таке мовчазне переповнення отруїть результат, і тест почне брехати навіть на правильній математиці. Python цього не помічає — його цілі ростуть скільки треба; а в C доводиться на **кожне** множення за модулем брати ширший, 128-бітний проміжок (`unsigned __int128`), де добуток гарантовано вміщається. Там, де 128-бітних цілих немає, той самий захист будують «подвійним множенням» — розкладають один множник на біти й накопичують добуток додаванням за модулем, бо сума двох чисел, менших за m, переповнення вже не викликає (аби лишень m < 2⁶³):

```c
// портативна заміна mulmod через додавання (вимагає m < 2⁶³)
static uint64_t mulmod(uint64_t a, uint64_t b, uint64_t m) {
    uint64_t r = 0;
    a %= m;
    while (b > 0) {
        if (b & 1) r = (r + a) % m;   // додати поточну сходинку
        a = (a + a) % m;              // подвоїти
        b >>= 1;
    }
    return r;
}
```

Одне коротке трасування — на найменшому підступному числі. Візьмімо n = 341:

```
2³⁴⁰ mod 341 = 1     → основа 2 промовчала: 341 «прикинулося» простим
3³⁴⁰ mod 341 = 56    → основа 3 — свідок: 341 напевно складене
```

Перша основа збрехала, друга викрила. І справді, 341 = 11·31 — але код цього не «побачив»: він лише двічі підніс до степеня, жодного разу не поділивши.

## Складність — і чому вона того варта

Один прохід тесту — це k основ, на кожну ≈ log₂n множень за модулем; разом близько k·log₂n модульних множень. Для стоцифрового n і k = 20 це кілька тисяч множень довгих чисел — частка секунди. Порівняй із «чесним» шляхом: найкращі відомі алгоритми розкладу працюють суб-експоненційний час і для стоцифрового n лишаються далеко за межею досяжного. Тест Ферма дешевший за розклад не на відсотки, а на астрономічні порядки — саме тому в кожному генераторі простих стоїть він, а не факторизація.

> 🔧 **Навіщо це.** Тут теорема XVII століття лежить у гарячому циклі коду XXI-го: щоб згенерувати один RSA-ключ, машина перебирає сотні непарних кандидатів, і кожного відсіює або пропускає дешевою пробою на степінь. Без односторонності («складене» — певний вирок, і його вистачає, щоб викинути кандидата) генерація ключів була б неможлива: розкласти стоцифрового кандидата, аби відкинути, — та сама нездоланна задача, на непіддатливості якої й стоїть сам шифр.

## Пастки: брехуни, псевдопрості й числа Кармайкла

Односторонність має ціну: складене число іноді проходить. Складене n, що дає aⁿ⁻¹ ≡ 1 для конкретної основи a, називають **псевдопростим Ферма** до основи a. Найменше псевдопросте до основи 2 — це 341 = 11·31, з яким ми щойно мали справу: 2³⁴⁰ ≡ 1 (mod 341), і основа 2 сама по собі тут брехун. Та досить додати основу 3 — і 341 викрито. Здавалося б, кілька випадкових основ рятують справу завжди.

Не завжди. Існують складені числа, які дають одиницю для **кожної** основи, взаємно простої з ними: жоден коректний свідок серед взаємно простих основ до них не пробивається. Це **[числа Кармайкла](topic:math/carmichael-function)**; найменше з них — 561 = 3·11·17. Причину видно з показника, на якому одиниця настає для складеного модуля. Для 561 найменший спільний показник усіх взаємно простих остач — це функція Кармайкла λ(561) = lcm(3−1, 11−1, 17−1) = lcm(2, 10, 16) = 80. А 80 **ділить** n−1 = 560 (бо 560 = 80·7). Тому для будь-якої основи a, взаємно простої з 561,

```
a⁵⁶⁰ = (a⁸⁰)⁷ ≡ 1⁷ = 1 (mod 561),
```

хоча 561 складене. Конгруенція Ферма для таких чисел сліпа: єдина основа, що їх «ловить», — та, яка випадково ділить n спільно з ним (для 561 таких близько 43% усіх основ). Але то вже не заслуга тесту, а звичайне натрапляння на множник; для великого числа Кармайкла з великими простими дільниками ймовірність натрапити мізерна, і воно пройде тест наскрізь. А чисел Кармайкла нескінченно багато, і серед них є як завгодно великі.

*Ліворуч від кожної клітинки — основа a, усередині — доля aⁿ⁻¹ mod n. У 341 є зелені свідки, тож кілька основ його викривають. У 561 зелених немає взагалі: усі взаємно прості основи брешуть, і конгруенція Ферма безсила — лишаються тільки сірі «випадкові» влучення в дільник, яких у великих чисел Кармайкла практично не буває.*

## Звідси — до Міллера — Рабіна

Діру видно точно: критерій aⁿ⁻¹ ≡ 1 надто грубий — він дивиться лише на **кінець** ланцюжка квадратів. Підсилення, відоме як [тест Міллера — Рабіна](topic:algorithms/miller-rabin), додає другий погляд — на **проміжні** квадрати. По дорозі до aⁿ⁻¹ алгоритм стежить, чи не з'явиться «нетривіальний корінь із одиниці»: таке число x, що x² ≡ 1, але саме x ≢ ±1 (mod n). За простим модулем таких коренів не буває — рівняння x² ≡ 1 має рівно два розв'язки, +1 і −1; тож щойно між квадратами вигулькнув третій корінь одиниці, n **напевно** складене. Числа Кармайкла, на відміну від простих, такі корені **мають** — і саме на цьому попадаються, хай як їх крутили.

Виграш не косметичний, а доказовий: для **будь-якого** складеного n щонайменше ¾ основ є свідками (це доведено — і, на відміну від проби Ферма, тут уже немає чисел, що обманювали б геть усі основи заразом). Тож k незалежних основ лишають шанс на помилку не більший за 4⁻ᵏ, і двадцять основ роблять його меншим за один на 10¹². Тест Ферма лишається найдешевшим зондом у простоту — одне піднесення до степеня; його єдина сліпа пляма, числа Кармайкла, і є те, що його спадкоємець навчився бачити.
