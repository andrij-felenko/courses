# 📋 Інтерфейс та контракт Дерева Відрізків для арифметичних обчислень

Цей довідник визначає точний програмний та математичний контракт інтерфейсу Дерева Відрізків (Segment Tree) для використання у чисельних алгоритмах, комп'ютерній алгебрі та високопродуктивних обчислювальних системах. Документ регламентує структури даних, сигнатури функцій, вхідні та вихідні інваріанти, асимптотичні оцінки складності пам'яті та часу, а також правила обробки виняткових ситуацій для двох мов програмування — C та C++.

Дерево відрізків виступає в ролі універсального адаптера між послідовним масивом даних та логарифмічним обчислювальним двигуном. Для гарантії коректності інтерфейс декларує чіткі інваріанти збереження станів, поведінку при граничних умовах (порожні інтервали, вихід за межі масиву, цілочисельне переповнення) та правила ресурсної гігієни пам'яті.

## 1. Специфікація типів даних та структур

Для забезпечення максимальної переносності та точності обчислень використовуються стандартизовані цілочисельні типи з фіксованою шириною бітів (`uint64_t`, `int64_t`, `size_t`).

:::tabs
```c
typedef struct {
    uint64_t *tree;   /* Плоский масив агрегованих вузлів розміром 4N */
    size_t n;         /* Кількість елементів у початковій послідовності */
} SegTreeGCD;
```
```cpp
template <typename T = int64_t, typename CombineOp = std::plus<T>>
class SegmentTreeLazy {
private:
    size_t n_;
    std::vector<T> sum_;
    std::vector<T> lazy_;
    CombineOp op_;
    T identity_;
public:
    explicit SegmentTreeLazy(std::span<const T> init_data, T identity = T(0), CombineOp op = CombineOp());
    ~SegmentTreeLazy() = default;
};
```
:::

**Формальні інваріанти структури:**
1. **Інваріант пам'яті:** Вказівник `tree` завжди вказує на виділений блок пам'яті розміром `4 * n * sizeof(uint64_t)`. Будь-яке пряме звільнення `free(tree)` без виклику спеціалізованого деструктора `segtree_gcd_free` є порушенням контракту.
2. **Інваріант кореня:** Елемент `tree[1]` містить значення моноїдної агрегації на всьому інтервалі `[0, n - 1]`.
3. **Інваріант бінарного розбиття:** Для будь-якого внутрішнього вузла за індексом `v`, який відповідає інтервалу `[tl, tr]` (де `tl < tr`), його лівий син знаходиться за індексом `2v` і покриває `[tl, tm]`, а правий син — за індексом `2v + 1` і покриває `[tm + 1, tr]`, де `tm = tl + (tr - tl) / 2`.
4. **Інваріант листя:** Листові вузли розташовані на глибині `⌈log₂ n⌉` та відповідають початковим елементам масиву за відповідними індексами.

## 2. Публічний контракт методів та функцій

### 2.1. Ініціалізація та побудова (Initialization & Build)

:::tabs
```c
SegTreeGCD* segtree_gcd_create(const uint64_t *arr, size_t n);
```
```cpp
template <typename T, typename CombineOp>
SegmentTreeLazy<T, CombineOp>::SegmentTreeLazy(std::span<const T> init_data, T identity, CombineOp op);
```
:::

- **Призначення:** Створює новий екземпляр дерева відрізків та ініціалізує агреговані значення на масиві.
- **Прекондиції (C):** `arr != NULL`, `n > 0`. Виклик із `n = 0` повертає `NULL`.
- **Прекондиції (C++):** `init_data` може бути порожнім спаном. `identity` є нейтральним елементом для `op`.
- **Посткондиції:** Повертає збудоване дерево розміром `4N`. У разі браку пам'яті C-функція повертає `NULL`, а C++ конструктор викидає `std::bad_alloc`.
- **Складність:**
  - Часова складність: `O(N)`.
  - Просторова складність: `O(N)` додаткових комірок пам'яті.

---

### 2.2. Інтервальний запит (Range Query)

:::tabs
```c
uint64_t segtree_gcd_query(const SegTreeGCD *st, size_t l, size_t r);
```
```cpp
template <typename T, typename CombineOp>
[[nodiscard]] T SegmentTreeLazy<T, CombineOp>::query(size_t l, size_t r) const noexcept;
```
:::

- **Призначення:** Обчислює агреговане значення бінарної операції на відрізку `[l, r]`.
- **Параметри:**
  - `st` — вказівник на створене дерево.
  - `l` — ліва межа запиту (inclusive, 0-indexed).
  - `r` — права межа запиту (inclusive, 0-indexed).
- **Поведінка при некоректних аргументах:**
  - Якщо `st == NULL`, повернути `0`.
  - Якщо `l >= st->n` або `r >= st->n`, повернути `0`.
  - Якщо `l > r`, повернути `0` (нейтральний елемент моноїда `gcd`).
- **Складність:**
  - Часова складність: `O(log N)`.
  - Просторова складність: `O(log N)` на фрейми рекурсивного стека.

---

### 2.3. Точкове оновлення (Point Update)

:::tabs
```c
void segtree_gcd_update(SegTreeGCD *st, size_t idx, uint64_t new_val);
```
```cpp
template <typename T, typename CombineOp>
void SegmentTreeLazy<T, CombineOp>::update_point(size_t idx, const T& new_val);
```
:::

- **Призначення:** Замінює значення елемента за індексом `idx` на `new_val` і перераховує всі агрегати в батьківських вузлах.
- **Параметри:**
  - `st` — вказівник на дерево.
  - `idx` — індекс елемента для модифікації (`0 <= idx < st->n`).
  - `new_val` — нове значення.
- **Посткондиції:** Значення `a[idx]` замінюється на `new_val`, і всі батьківські вузли оновлюють свої агрегати за `O(log N)`.
- **Складність:**
  - Часова складність: `O(log N)`.
  - Просторова складність: `O(log N)` стек.

---

### 2.4. Групове оновлення з відкладеною пропогацією (Range Update)

:::tabs
```c
void segtree_lazy_update_range(SegTreeLazy *st, size_t l, size_t r, int64_t addend);
```
```cpp
template <typename T, typename CombineOp>
void SegmentTreeLazy<T, CombineOp>::update_range(size_t l, size_t r, const T& addend);
```
:::

- **Призначення:** Додає значення `addend` до всіх елементів підмасиву `[l, r]`.
- **Параметри:**
  - `l`, `r` — межі відрізка (inclusive).
  - `addend` — значення для додавання до всіх елементів відрізка `[l, r]`.
- **Посткондиції:** Значення у вузлах оновлюються негайно на покривальних рівнях, а дочірні піддерева отримують прапорці `lazy`.
- **Складність:**
  - Часова складність: `O(log N)`.
  - Просторова складність: `O(log N)`.

## 3. Таблиця алгебраїчних моноїдів та граничних інваріантів

Нижче наведено параметризацію для найпоширеніших числово-теоретичних операцій, які передаються в дерево відрізків:

| Операція | Тип даних `T` | Опис операції `op(a, b)` | Нейтральний елемент `identity` | Оновлення `f(x, len, val)` |
| :--- | :--- | :--- | :--- | :--- |
| **Сума на відрізку** | `int64_t` | `a + b` | `0` | `x + len · val` |
| **Мінімум (RMQ)** | `int64_t` | `min(a, b)` | `INT64_MAX` | `x + val` |
| **Максимум (RMQ)** | `int64_t` | `max(a, b)` | `INT64_MIN` | `x + val` |
| **НСД (Range GCD)** | `uint64_t` | `gcd(a, b)` | `0` | `val` (заміна) |
| **НСК (Range LCM)** | `uint64_t` | `lcm(a, b)` | `1` | `val` (заміна) |
| **Матричний добуток** | `Matrix2x2` | `A × B mod m` | `IdentityMatrix` | `A × val` |

## 4. Специфікація пам'яті та часова складність

| Операція | Часова складність (Best/Worst) | Просторова складність (Auxiliary) | Необхідна пам'ять на масив `N` |
| :--- | :--- | :--- | :--- |
| `Побудова (Build)` | `O(N)` | `O(N)` | `4 · N · sizeof(T)` |
| `Point Update` | `O(log N)` | `O(log N)` стек | `0` додатково |
| `Range Query` | `O(log N)` | `O(log N)` стек | `0` додатково |
| `Range Update (Lazy)` | `O(log N)` | `O(log N)` стек | `4 · N · sizeof(LazyT)` |
| `Очищення (Free)` | `O(1)` | `O(1)` | Звільнення `4N` |

## 5. Граничні випадки, помилки та інваріанти безпеки

### 5.1. Захист від цілочисельного переповнення (Integer Overflow)

При обчисленні суми на відрізку `sum = sum + len · addend` для великих масивів (`N = 10⁶`) добуток `len · addend` може виходити за межі 32-бітних типів `int32_t`. Інтерфейс вимагає використання `int64_t` або `uint64_t` для всіх акумуляторів та lazy-прапорців.

У задачах модулярної арифметики множення двох 64-бітних чисел перед впадуванням за модулем `(a · b) mod m` вимагає використання 128-бітного проміжного типу `__int128_t` для запобігання відсіканню старших розрядів.

### 5.2. Обробка некоректного ділення на нуль у GCD/LCM

Операція `gcd(a, 0)` за виведеним алгебраїчним інваріантом повертає `a`. Проте стандартне мовне ділення по модулю `a % 0` призводить до апаратного винятку CPU (`SIGFPE`). Внутрішня реалізація `gcd_op` має явно обробляти випадок `b == 0`.

Для найменшого спільного кратного `lcm(a, b) = (a · b) / gcd(a, b)` випадок `a = 0` або `b = 0` повинен повертати `0`, уникаючи множення та ділення на нульові величини.

### 5.3. Колізії відкладених прапорців при комбінованих оновленнях

Якщо дерево підтримує одночасно операції «додати `v`» та «присвоїти `v`», прапорець `lazy` повинен містити комплексний тег або пару `(set_val, add_val)`. 

Правила комбінації прапорців при проштовхуванні:
1. При встановленні нового значення присвоєння `set_val = new_v`, прапорець додавання `add_val` скидається в 0.
2. При додаванні нового значення `add_v`, якщо встановлено прапорець присвоєння `set_val`, модифікується безпосередньо `set_val += add_v`, а `add_val` залишається 0.
3. Порядок обробки в функції `push` повинен суворо віддавати пріоритет прапорцю присвоєння перед прапорцем додавання.

### 5.4. Потокобезпека та багатопотокове середовище (Thread Safety)

Класичне дерево відрізків із точковими оновленнями та неперсистентною структурою не є потокобезпечним при одночасному зчитуванні та записі різними потоками виконання без зовнішньої синхронізації.

Правила паралельного доступу:
- **Паралельне зчитування (Read-Only Concurrent Queries):** Операції `query` на статичному або немодифіковуваному дереві відрізків є повністю потокобезпечними й можуть виконуватися довільною кількістю потоків без блокувань (Lock-Free Read).
- **Паралельна модифікація (Concurrent Updates):** Якщо один потік викликає `update` або `update_range`, інші потоки не повинні виконувати читання або запис без взяття взаємного виключення (М'ютекса / Read-Write Lock) над екземпляром дерева.
