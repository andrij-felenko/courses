Сервер аналітики обробляє масив із мільйона цілих чисел. Система постійно отримує два типи сповіщень: точкові модифікації (зміна значення в одній комірці масиву) та інтервальні запити (обчислення найбільшого спільного дільника або суми на довільному проміжку `[l, r]`). Якщо зберегти дані у звичайному плоскому масиві, точкова заміна виконується миттєво за один крок `O(1)`, але обчислення НСД на відрізку довжиною `N` вимагає повного проходу по всіх елементах за `O(N)` операцій. При тисячі запитів на секунду система вичерпує процесорний час і падає. Якщо ж підтримувати таблицю префіксних сум чи дільників, обчислення на відрізку прискорюється до `O(1)`, проте кожна точкова заміна перетворюється на важкий перезапис усього масиву за `O(N)`. Спроба збалансувати цей конфлікт між модифікацією та агрегацією наводить на ідею деревоподібного розбиття простору.

## Проблема асиметрії інтервальних обчислень

Конфлікт між швидкістю зчитування та швидкістю запису у динамічних числових послідовностях має фундаментальну алгебраїчну природу. У стаціонарних системах, де масив не змінюється після побудови, проблема агрегації розв'язується накопичувальними масивами. 

Для обчислення суми елементів на відрізку `[l, r]` будується префіксний масив `P[i] = a[0] + a[1] + ... + a[i]`, після чого результат будь-якого запиту витягується за єдине віднімання `P[r] - P[l - 1]` за константний час `O(1)`. Проте найменша зміна значення `a[k]` каскадно руйнує всі наступні префіксні суми `P[k], P[k+1], ..., P[N-1]`, змушуючи оновлювати `N - k` комірок пам'яті.

Асиметрія між двома граничними підходами виражається таблицею складностей:

```
Звичайний масив:        Оновлення O(1)   | Запит O(N)
Префіксні суми:         Оновлення O(N)   | Запит O(1)
```

Для багатьох числово-теоретичних операцій — таких як найбільший спільний дільник `gcd`, найменше спільне кратне `lcm`, мінімум чи максимум — ситуація ще складніша. На відміну від додавання, операції `gcd` та `min` не мають алгебраїчно оберненої дії. Побачивши значення `gcd(a[0], ..., a[r])`, неможливо «відняти» з нього значення `a[0]`, щоб отримати `gcd(a[1], ..., a[r])`. Префіксні структури для таких операцій взагалі не дозволяють віднімати префікси, звужуючи можливості стаціонарного аналізу.

Необхідна структура даних має розбити масив на таку мережу перекривних підінтервалів, щоб при зміні одного елемента оновлювалася лише мала (логарифмічна) кількість блоків, і водночас будь-який довільний відрізок `[l, r]` можна було зібрати з невеликої кількості готових агрегованих блоків.

## Ієрархічна декомпозиція та бінарне дерево відрізків

Дерево відрізків (англ. *Segment Tree*) розв'язує цю задачу шляхом систематичного бінарного поділу початкового інтервалу `[0, N - 1]`. Корінь дерева відповідає всьому масиву `[0, N - 1]`. Якщо інтервал містить більше ніж один елемент (`L < R`), він ділиться посередині в точці `M = ⌊(L + R) / 2⌋` на два дочірні вузли:
- **Лівий син:** відповідає підмасиву `[L, M]`.
- **Правий син:** відповідає підмасиву `[M + 1, R]`.

Рекурсивний поділ продовжується доти, доки інтервал не скоротиться до одного елемента `[i, i]`. Вузли такого типу утворюють листя дерева відрізків і зберігають безпосередні значення елементів початкового масиву `a[i]`.

![Ієрархічна структура дерева відрізків для масиву з N = 8 елементів](/book/math/number-theory/segment-tree/img/fig-segment-tree-structure.svg)
*Ієрархічне розбиття інтервалу [0, 7] на бінарне дерево та його лінійне представлення в пам'яті.*

Оскільки кожен внутрішній вузол ділить свій відрізок навпіл, висота отриманого дерева не перевищує `⌈log₂ N⌉ + 1`. Це означає, що шлях від кореня до будь-якого листка містить логарифмічну кількість кроків.

### Компактне розміщення в плоскому масиві

Ідеально збалансоване бінарне дерево відрізків не вимагає динамічного виділення пам'яті через вказівники та вузли зі вказівниками на дітей. Замість цього дерево упаковується в один суцільний плоский масив `tree[]` за схемою `1`-індексації, аналогічною до двійкової купи (Binary Heap):

- Кореневий вузол `[0, N - 1]` зберігається за індексом `v = 1`.
- Для вузла за індексом `v`:
  - **Лівий син** знаходиться за індексом `2v`.
  - **Правий син** знаходиться за індексом `2v + 1`.
  - **Батьківський вузол** знаходиться за індексом `⌊v / 2⌋`.

Оскільки `N` не обов'язково є точним степенем двійки, максимальний індекс вузла у найгіршому випадку не перевищує `4N`. Виділення масиву розміром `4N` комірок гарантує захист від переповнення буфера для будь-яких послідовностей довжиною `N`.

Математично це пояснюється тим, що найближчий степінь двійки `2^k ≥ N` задовольняє умову `2^k < 2N`. Повне бінарне дерево для масиву розміром `2^k` містить `2 · 2^k - 1 < 4N` вузлів. Отже, верхня межа пам'яті складає строго `4N` комірок.

Приклад розміщення вузлів для масиву з `N = 4` елементів `[24, 36, 60, 48]`:
- `tree[1]` містить агрегат `[0, 3] = gcd(12, 12) = 12`.
- `tree[2]` містить агрегат `[0, 1] = gcd(24, 36) = 12`.
- `tree[3]` містить агрегат `[2, 3] = gcd(60, 48) = 12`.
- `tree[4]` містить листок `[0, 0] = 24`.
- `tree[5]` містить листок `[1, 1] = 36`.
- `tree[6]` містить листок `[2, 2] = 60`.
- `tree[7]` містить листок `[3, 3] = 48`.

Масив `tree` має розмір `4 · 4 = 16` комірок, із яких активними є перші 7, а решта зарезервована під вирівнювання рівнів.

## Алгебраїчна суть: Робота з довільними моноїдами

Поширеною помилкою є сприйняття дерева відрізків лише як структури для обчислення суми або мінімуму. У дійсності дерево відрізків є абстрактним обчислювачем для довільної алгебраїчної системи типу **моноїд**.

Моноїд `(S, ⊗, e)` — це множина `S` з бінарною операцією `⊗`, яка задовольняє дві аксіоми:
1. **Асоціативність:** `(a ⊗ b) ⊗ c = a ⊗ (b ⊗ c)`.
2. **Нейтральний елемент `e`:** `a ⊗ e = e ⊗ a = a`.

Асоціативність операції гарантує, що порядок об'єднання піддерев не змінює кінцевого результату. Оскільки `(a[0] ⊗ a[1]) ⊗ (a[2] ⊗ a[3]) = ((a[0] ⊗ a[1]) ⊗ a[2]) ⊗ a[3]`, значення у внутрішньому вузлі дерева `val[v] = val[2v] ⊗ val[2v+1]` точно дорівнює результату послідовного застосування операції `⊗` до всіх елементів цього відрізка.

Про те, як саме асоціативність забезпечує інваріанти обчислень у скінченних полях, кільцях лишків та алгебрі ендоморфізмів, детально розписано в окремому математичному аналізі: [🧮 Алгебраїчна структура дерева відрізків: моноїди, асоціативність та інтервальна комбінаторика](book:math/number-theory/segment-tree/math-segment-tree-monoids.md).

Такий підхід дозволяє використовувати єдиний алгоритм дерева відрізків для кардинально різних числових задач:
- **Range Sum Query:** `(ℤ, +, 0)` — обчислення суми елементів.
- **Range GCD Query:** `(ℕ₀, gcd, 0)` — обчислення найбільшого спільного дільника.
- **Range LCM Query:** `(ℕ, lcm, 1)` — обчислення найменшого спільного кратного.
- **Матричні рекурентності:** `(Mat₂(ℤ_m), ×, I)` — обчислення членів послідовностей Фібоначчі чи Люка на динамічному проміжку.
- **Модулярний добуток:** `(ℤ_m, ×_m, 1)` — підтримка добутку у скінченному полі за модулем `m`.

> 🔧 **Навіщо це.** У комп'ютерній алгебрі та криптографії часто потрібно обчислювати добуток послідовності елементів у скінченному полі `GF(p)` або кільці `ℤ_m` із можливістю заміни окремого коефіцієнта. Використання моноїда `(ℤ_m, ×_m, 1)` у дереві відрізків дозволяє за `O(log N)` перераховувати модулярний добуток усієї послідовності після будь-якого точкового оновлення.

## Механіка виконання інтервального запиту (Range Query)

При надходженні запиту `query(l, r)` необхідно обчислити агреговане значення операції `⊗` на відрізку `[l, r]`. Алгоритм починає спуск із кореневого вузла `v = 1`, який відповідає інтервалу `[tl, tr] = [0, N - 1]`.

На кожному кроці рекурсивної функції `query(v, tl, tr, l, r)` можливі три взаємовиключні геометричні випадки відносно поточного інтервалу вузла `[tl, tr]` та інтервалу запиту `[l, r]`:

1. **Повне неспівпадання (`[tl, tr] ∩ [l, r] = ∅`):** Інтервал вузла повністю лежить поза межами запиту. Функція негайно припиняє спуск у дану гілку й повертає нейтральний елемент моноїда `e`.
2. **Повне покриття (`[tl, tr] ⊆ [l, r]`):** Інтервал вузла повністю міститься всередині запиту. Функція повертає попередньо обчислене значення `tree[v]` без подальшого спуску до дітей.
3. **Частковий перетин:** Інтервал вузла лише частково перетинається із запитом. Функція розбиває запит на дві частини, викликає рекурсивний спуск для лівого `2v` та правого `2v + 1` синів, і повертає комбінацію їхніх відповідей: `res_left ⊗ res_right`.

### Доведення логарифмічної складності запиту

На перший погляд здається, що частковий перетин може спричинить масове розгалуження рекурсії по всьому дереву. Проте на кожному рівні дерева висоти `H = ⌈log₂ N⌉` може існувати **не більше двох вузлів**, чиї інтервали частково перетинаються із запитом `[l, r]`. 

Один із цих вузлів містить ліву межу запиту `l`, а інший — праву межу `r`. Усі вузли, що лежать строго між ними на тому ж рівні, виявляються повністю покритими запитом і зупиняють рекурсію.

Оскільки кожен із двох часткових вузлів породжує не більше двох викликів до своїх дітей, на кожному рівні дерева відвідується максимум 4 вузли. Сумарна кількість відвіданих вузлів за весь час виконання запиту обмежується величиною:
```
N_visited ≤ 4 · ⌈log₂ N⌉ = O(log N)
```

Таким чином, замість послідовного перебору `(r - l + 1)` елементів масиву, алгоритм об'єднує результати не більше ніж `4 log₂ N` готових вузлів дерева.

## Механіка точкового оновлення (Point Update)

Коли елемент масиву за індексом `idx` змінює своє значення на `new_val`, необхідно оновити всі вузли дерева відрізків, інтервали яких містять цей індекс.

Алгоритм `update(v, tl, tr, idx, new_val)` виконується за схемою «згори вдолу з наступним підйомом»:

1. Якщо `tl == tr`, то поточний вузол є листком, який відповідає елементу `idx`. Значення вузла модифікується: `tree[v] = new_val`.
2. Якщо `tl < tr`, обчислюється середина `tm = ⌊(tl + tr) / 2⌋`:
   - Якщо `idx ≤ tm`, рекурсивний виклик спрямовується в лівого сина `2v`.
   - Якщо `idx > tm`, рекурсивний виклик спрямовується в правого сина `2v + 1`.
3. Після повернення з рекурсивного виклику дочірнього вузла, поточний вузол перераховує своє значення на основі оновлених даних своїх дітей:
```
tree[v] = tree[2v] ⊗ tree[2v + 1]
```

Оскільки на кожному рівні дерева обирається лише один напрямок руху (ліворуч або праворуч), рекурсивний спуск від кореня до листка відвідує точно `⌈log₂ N⌉ + 1` вузлів. Підйом назад і перерахунок значень виконується за той самий логарифмічний час. Отже, складові операції точкового оновлення становлять `O(log N)`.

## Групові оновлення та відкладена пропогація (Lazy Propagation)

Прямолінійне застосування точкових оновлень для модифікації діапазону елементів є неефективним. Якщо потрібно додати число `val` до всіх елементів у підмасиву `[l, r]`, то виклик `(r - l + 1)` точкових оновлень вимагатиме `O(N log N)` операцій. Це повільніше за звичайний послідовний прохід по масиву.

Для збереження логарифмічної складності `O(log N)` при групових оновленнях застосовується техніка **відкладеної пропогації** (англ. *Lazy Propagation*).

Основна ідея полягає в «ледачому» виконанні дій: якщо оновлення діапазону `[l, r]` повністю покриває інтервал поточного вузла `[tl, tr]`, то оновлення застосовується безпосередньо до поточного вузла, а в сам вузол записується відкладений прапорець (`lazy tag`). Подальший спуск у дочірні піддерева припиняється.

![Принцип відкладеної пропогації (Lazy Propagation)](/book/math/number-theory/segment-tree/img/fig-lazy-propagation.svg)
*Передача відкладених прапорців оновлення (lazy tags) вниз по дереву при влучанні запиту.*

### Механізм проштовхування (Push Down)

Відкладений прапорець `lazy[v]` означає, що вузол `v` уже врахував нові зміни, але його дочірні піддерева `2v` та `2v + 1` все ще містять застарілі дані.

При наступних зверненнях до дерева (під час виконання нових запитів чи оновлень), перед тим як спуститися у дочірні вузли, викликається процедура **проштовхування** `push(v, tl, tr)`:

1. Якщо `lazy[v] ≠ 0` і вузол не є листком (`tl < tr`):
   - Передати значення `lazy[v]` до відкладених прапорців дочірніх вузлів: `lazy[2v] += lazy[v]` та `lazy[2v+1] += lazy[v]`.
   - Перерахувати агреговані значення дочірніх вузлів з урахуванням довжини їхніх інтервалів.
   - Скинути відкладений прапорець поточного вузла: `lazy[v] = 0`.

Завдяки процедурі `push` інваріант коректності даних підтримується на всіх відвіданих рівнях дерева, а загальна складність групового оновлення залишається логарифмічною `O(log N)`.

## Нерекурсивне (Bottom-Up) Дерево відрізків

Для високонавантажених обчислювальних систем у реальному часі накладні витрати на виклики функцій у рекурсивному дереві відрізків можуть створювати помітні процесорні затримки. Нерекурсивне (Bottom-Up) дерево відрізків розміщує листки початкового масиву у другій половині плоского масиву за індексами `N + i` (де `0 ≤ i < N`).

Внутрішні вузли будуються заповненням від індексу `N - 1` до `1` за формулою:
```
tree[i] = tree[2i] ⊗ tree[2i + 1]
```

### Запит на нерекурсивному дереві

При надходженні запиту `query(l, r)` межі переводяться в індекси листків: `l += N` та `r += N`. Обхід виконується в циклі за допомогою побітових операцій:

```
acc_left = e
acc_right = e
поки l <= r:
    якщо l є правим сином (l mod 2 == 1):
        acc_left = acc_left ⊗ tree[l]
        l = l + 1
    якщо r є лівим сином (r mod 2 == 0):
        acc_right = tree[r] ⊗ acc_right
        r = r - 1
    l = l / 2
    r = r / 2
повернути acc_left ⊗ acc_right
```

Нерекурсивне дерево виконується ітеративно без жодного виклику стека, забезпечуючи максимальну швидкість процесорного виконання та кеш-локальність. Проте воно вимагає комутативності операції або строгой роздільності лівого та правого акумуляторів, і складніше піддається Lazy Propagation.

## Динамічне (Неявне) та Персистентне Дерево відрізків

У практичних числово-теоретичних задачах виникають дві особливі ситуації, які вимагають розширення класичної концепції дерева відрізків:
1. **Величезний координатний простір:** Масив визначається на діапазоні ключів від `0` до `10¹⁸` (або `2⁶⁴ - 1`), але реальна кількість активних елементів `K` не перевищує `10⁵`.
2. **Версійність та збереження історії:** Необхідно мати доступ до стану дерева відрізків після кожної з минулих `Q` модифікацій.

### Динамічне (Неявне) Дерево відрізків

Створення `4N` вузлів для `N = 10¹⁸` неможливе з огляду на обмеження оперативної пам'яті. У **динамічному дереві відрізків** вузли не створюються заздалегідь. 

Початково існує лише один кореневий вузол, який відповідає всьому діапазону `[0, 10¹⁸]`. Вказівники на лівого та правого сина `left_child` та `right_child` початково дорівнюють `NULL`.

Коли операція оновлення `update(idx, val)` спускається по дереву, нові дочірні вузли створюються «за вимогою» (on demand) тільки вздовж пути спуску. Відсутній син вважається таким, що містить порожнє значення (нейтральний елемент моноїда `e`).

Пам'ять для динамічного дерева оцінюється величиною:
```
Memory = O(K · log N)
```
де `K` — кількість виконаних точкових оновлень, `N` — розмір координатного простору. Це дозволяє виконувати інтервальні запити на віртуальних масивах розмірністю `2⁶⁴` елементів.

### Персистентне Дерево відрізків

**Персистентність** означає здатність зберегти всі попередні версії структури даних при її модифікації. 

Замість того щоб змінювати значення у наявних вузлах при точковому оновленні `update(idx, val)`, алгоритм створює **нові копії** вузлів уздовж шляху спуску від кореня до листка:

1. Створюється новий корінь для версії `t`.
2. Спускаючись до листка `idx`, створюється новий вузол на кожному рівні.
3. Вказувач на гілку, яка **не зазнала змін**, перенаправляється на відповідного сина з попередньої версії `t - 1` (структурний шеринг пам'яті).

Оскільки висота дерева дорівнює `⌈log₂ N⌉`, кожне оновлення додає точно `⌈log₂ N⌉ + 1` нових вузлів. 

Загальні витрати пам'яті для збереження історії `Q` оновлень складають:
```
Memory_persistent = O(N + Q · log N)
```

Персистентні дерева відрізків є основними інструментами в задачах пошуку порядку на відрізку (k-та порядкова статистика на довільному підмасиві за допомогою персистентного дерева Частот / Борів), версійних базах даних та функційному програмуванні.

## Історичний та концептуальний розвиток

Першу концепцію дерева відрізків розробляв американський науковець Джон Бентлі у 1977 році для розв'язання обчислювальних задач геометрії, зокрема проблеми міри Клі (обчислення площі об'єднання прямокутників). 

Згодом дослідники комп'ютерної алгебри узагальнили геометричні відрізки до дискретних масивів та абстрактних моноїдних систем. Паралельно у 1994 році Пітер Фенвік запропонував Binary Indexed Tree (Дерево Фенвіка), яке працювало швидше за рахунок бітових інваріантів, але вимагало обов'язкової обратності алгебраїчної операції (групової структури). Дерево відрізків залишилося єдиною універсальною ієрархічною структурою для необротних бінарних операцій (`gcd`, `min`, `max`).

Повний історичний нарис із деталями наукових дискусій та еволюцією алгоритмів винесено в окремий матеріал: [📜 Історія розвитку точкових та інтервальних запитів у комп'ютерній алгебрі](book:math/number-theory/segment-tree/hist-segment-tree.md).

## Числово-теоретичні та арифметичні застосування

Завдяки моноїдній природі дерево відрізків активно застосовується в заплутаних числових та алгебраїчних алгоритмах.

### 1. Динамічний інтервальний НСД (Dynamic Range GCD)

У теорії чисел часто виникає задача підтримки найбільшого спільного дільника на підмасивах із можливістю заміни поодиноких елементів. Оскільки `gcd(a, b)` є асоціативною операцією з нейтральним елементом `0`, дерево відрізків дозволяє шукати `gcd(a[l], a[l+1], ..., a[r])` за `O(log N · log(max_val))` операцій, де другий логарифм відповідає алгоритму Евкліда.

### 2. Динамічне розкладання на прості множники та канонічні суми

Для обчислення кількості дільників або значення функції Ейлера `φ(n)` на відрізку масиву `∏ a[i]` у вузлах дерева відрізків можна зберігати вектори ступенів простих множників. 

Завдяки асоціативності додавання векторів ступенів у приватному кільці, інтервальний добуток легко перераховується без прямого множення надвеликих чисел, запобігаючи цілочисельному переповненню.

### 3. Обчислення лінійних рекурентностей на динамічних інтервалах

Розглянемо систему, де коефіцієнти лінійної рекурентності `Fₖ = c₁ Fₖ₋₁ + c₂ Fₖ₋₂` змінюються в часі. Перехід від стану `(Fₖ₋₁, Fₖ₋₂)` до `(Fₖ, Fₖ₋₁)` кодується матрицею переходу `2 × 2`:

```
M_i = [ c1  c2 ]
      [  1   0 ]
```

Оскільки множення матриць є асоціативним, дерево відрізків із моноїдом `(Mat₂(ℤ_m), ×, I)` дозволяє обчислити результат застосування ланцюжка з `K` різних матриць переходу `M_l × M_{l+1} × ... × M_r` за `O(log K)` матричних множень. Це забезпечує швидке обчислення динамічних систем у криптографії та чисельних методах.

## Порівняльний аналіз інтервальних структур

Щоб свідомо обрати дерево відрізків серед інших структур даних, порівняємо його з основними альтернативами:

| Структура даних | Складність запиту | Складність оновлення | Витрати пам'яті | Вимоги до операції |
| :--- | :--- | :--- | :--- | :--- |
| **Плоский масив** | `O(N)` | `O(1)` | `N` | Без обмежень |
| **Префіксні суми** | `O(1)` | `O(N)` | `N` | Обратність (Група) |
| **Дерево Фенвіка (BIT)** | `O(log N)` | `O(log N)` | `N` | Обратність / Комутативність |
| **Sparse Table** | `O(1)` | `O(N log N)` (перебудова) | `N log N` | Ідемпотентність (`a ⊗ a = a`) |
| **Дерево відрізків** | `O(log N)` | `O(log N)` | `4N` | Асоціативність (Моноїд) |

Дерево відрізків є єдиною структурою, яка поєднує логарифмічний час оновлення та запиту для довільних некомутативних та необротних моноїдних операцій.

## Межі застосування та чесні інваріанти

Дерево відрізків не є панацеєю й має чітко окреслені межі застосування:

1. **Неасоціативні операції:** Якщо операція `⊗` не є асоціативною, об'єднання результатів піддерев є математично некоректним. Для таких операцій побудова дерева відрізків неможлива.
2. **Відсутність дистрибутивності для Lazy Propagation:** Якщо оновлення `f` та операція запиту `⊗` не задовольняють умову дистрибутивності `f(a ⊗ b) = f(a) ⊗ f(b)`, відкладена пропогація не зможе перераховувати значення вузлів без повного проходу по всіх листках піддерева.
3. **Обмеження пам'яті в багатовимірних задачах:** Багатовимірні дерева відрізків (2D / 3D Segment Trees) вимагають `O(4ᵈ · Nᵈ)` пам'яті, що робить їх занадто важкими при `d ≥ 3` порівняно з K-d деревами чи R-деревами.

Усі обчислення, що виходять за ці межі, потребують використання спеціалізованих динамічних структур даних або наближених евристичних алгоритмів.
