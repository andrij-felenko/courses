# ⚙️ Реалізація арифметики точок еліптичної кривої над скінченним полем

Повний робочий код реалізації точкової арифметики (додавання, подвоєння та скалярне множення алгоритмом Double-and-Add) на еліптичній кривій над скінченним полем `𝔽ₚ` з обробкою нейтрального елемента, розбором проективних координат, представленням великих чисел BigInt, стисненням точок та захистом від атак по побічних каналах.

Реалізація точкової арифметики на еліптичних кривих над скінченними полями вимагає акуратної обробки двох фундаментальних моментів: обчислень у кільці залишків (зокрема знаходження оберненого елемента за допомогою Розширеного алгоритму Евкліда) та коректного обходу крайових випадків з нейтральним елементом — точкою на нескінченності `O`.

---

## 1. Архітектурні виклики та крайові випадки

На відміну від неперервної аналітичної геометрії над полем дійсних чисел `ℝ`, арифметика над скінченним полем `𝔽ₚ` оперує цілими числами у діапазоні `[0, p-1]`. Будь-яке віднімання чи множення може утворювати від'ємні значення чи числа, що перевищують `p`, тому кожна проміжна операція вимагає нормування за модулем `p`.

Для побудови коректного модуля додавання точок необхідно обробляти 5 алгоритмічних режимів:

1. **Додавання з нейтральним елементом (`P + O = P` або `O + Q = Q`):**
   Точка на нескінченності `O` виступає нулем групи. Якщо один із доданків є точкою `O`, функція миттєво повертає другий доданок без обчислення нахилів.

2. **Додавання протилежних точок (`P + (-P) = O`):**
   Якщо координати точок задовольняють `x₁ ≡ x₂ (mod p)` та `y₁ + y₂ ≡ 0 (mod p)` (при `y₁ ≠ 0`), пряма через `P` та `Q` є строго вертикальною. Вона перетинає криву у третій точці `O`. Функція повертає прапорець нескінченності `is_infinity = true`.

3. **Подвоєння точки (`P = Q` при `y₁ ≠ 0`):**
   Коли точки збігаються, січна пряма перетворюється на дотичну. Нахил дотичної `λ` обчислюється через похідну `λ = (3·x₁² + a) · (2·y₁)⁻¹ mod p`.

4. **Подвоєння точки з нулевою ординатою (`P = Q` при `y₁ ≡ 0 mod p`):**
   У точках перетину кривої з віссю абсцис дотична пряма є вертикальною. Подвоєння такої точки дає нейтральний елемент `2·P = O`.

5. **Загальний випадок додавання нерівних точок (`x₁ ≠ x₂`):**
   Нахил січної прямої обчислюється за класичною формулою `λ = (y₂ - y₁) · (x₂ - x₁)⁻¹ mod p`.

Чому не можна використовувати банальні декартові координати `(0, 0)` як маркер нуля `O`? Оскільки для багатьох еліптичних кривих (наприклад `y² = x³ + 0·x + 0` або `y² = x³ + a·x + 0`) точка `(0, 0)` лежить на самій кривій і є валідною точкою 2-кручення, спроба позначити нуль як `(0, 0)` призводить до логічної плутанини. Саме тому структура точок повинна містити явний булевий прапорець `is_infinity` або тип `std::optional` у C++.

## 2. Математичні засади арифметики залишків та алгоритм Евкліда

Найбільш обчислювально витратною операцією у початковій афінній арифметиці є знаходження оберненого елемента `den⁻¹ mod p`.

### Розширений алгоритм Евкліда (Extended Euclidean Algorithm)

Для знаходження числа `x = b⁻¹ mod p` розв'язується лінійне діофантове рівняння:

```
b·x + p·y = gcd(b, p) = 1
```

Переходячи за модулем `p`, маємо `b·x ≡ 1 (mod p)`, звідки `x` є шуканим оберненим елементом.

Розглянемо числовий приклад обчислення `12⁻¹ mod 97`:
1. `97 = 8 · 12 + 1` (остача 1)
2. Перегрупуємо: `1 = 97 - 8 · 12`
3. Берючи модуль 97: `-8 · 12 ≡ 1 (mod 97)`
4. Нормуємо від'ємний залишок: `x = -8 + 97 = 89`

Перевірка: `12 · 89 = 1068 = 11 · 97 + 1 ≡ 1 (mod 97)`. Алгоритм знайшов обернений елемент всього за один крок ділення! У загальному випадку складність алгоритму Евкліда становить `O(log² p)` операцій.

### Застосування Малої теореми Ферма

Альтернативним способом знаходження оберненого елемента для простого модуля `p` є використання Малої теореми Ферма (`bᵖ⁻¹ ≡ 1 mod p`):

```
b⁻¹ ≡ bᵖ⁻² (mod p)
```

Обчислення `bᵖ⁻² mod p` виконується методом двійкового піднесення до степеня за час `O(log p)`. Головна перевага цього підходу — можливість виконання обчислень у **сталий час (Constant-Time)**, що запобігає витокам приватного ключа через аналіз часу виконання.

## 3. Детальний кроковий розбір алгоритму Double-and-Add

Для розуміння роботи алгоритму скалярного множення `k·P` розглянемо покрокове виконання для скаляра `k = 5` (двійкове представлення `101₂`) та базової точки `P = (3, 6)` над полем `𝔽₉₇`:

- **Початковий стан:** `result = O`, `addend = P = (3, 6)`.
- **Крок 1 (молодший біт b₀ = 1):**
  - Біт `k & 1` дорівнює 1 ⇒ `result = result + addend = O + P = P = (3, 6)`.
  - Подвоюємо доданок для наступного кроку: `addend = 2·P = (80, 10)`.
  - Зсуваємо скаляр: `k = 5 >> 1 = 2` (`10₂`).
- **Крок 2 (середній біт b₁ = 0):**
  - Біт `k & 1` дорівнює 0 ⇒ `result` залишається без змін `(3, 6)`.
  - Подвоюємо доданок: `addend = 2·(2·P) = 4·P = (80, 87)`.
  - Зсуваємо скаляр: `k = 2 >> 1 = 1` (`1₂`).
- **Крок 3 (старший біт b₂ = 1):**
  - Біт `k & 1` дорівнює 1 ⇒ `result = result + addend = P + 4·P = 5·P = (3, 91)`.
  - Подвоюємо доданок: `addend = 2·(4·P) = 8·P`.
  - Зсуваємо скаляр: `k = 1 >> 1 = 0`.
- **Фінал:** Цикл завершено, повертаємо `5·P = (3, 91)`.

Загалом для `b`-бітного скаляра виконано `b` операцій подвоєння та `W(k)` операцій додавання (де `W(k)` — вага Геммінга скаляра).

## 4. Від афінних точок до координат Якобі: оптимізація продуктивності

У наведеній нижче базовій реалізації точки представлено в **афінних координатах** `(x, y)`. На кожному кроці додавання чи подвоєння обчислення нахилу `λ` вимагає знаходження оберненого елемента `den⁻¹ mod p` за допомогою Розширеного алгоритму Евкліда.

Часова складність знаходження оберненого елемента становить `O(log² p)` арифметичних операцій, що у 30–50 разів повільніше за одне звичайне множення у полі. При виконанні скалярного множення `k·P` для 256-бітного ключа `k` наївне знаходження обернених елементів стає головним пляшковим горлом продуктивності.

Для прискорення криптографічних бібліотек (таких як OpenSSL, BoringSSL або libsecp256k1) точки переводять у **проективні координати Якобі** `(X : Y : Z)`, де зв'язок з афінними координатами задається співвідношеннями:

```
x = X / Z²,   y = Y / Z³
```

У координатах Якобі рівняння Вейєрштрасса набуває вигляду:

```
Y² = X³ + a·X·Z⁴ + b·Z⁶
```

Головна перевага координат Якобі полягає у тому, що додавання та подвоєння точок виконуються **виключно через операції додавання, віднімання та множення** у полі `𝔽ₚ` без жодного ділення та знаходження обернених елементів! 

Для додавання двох точок у координатах Якобі потрібно всього 12 множень у полі (`12M`), а знаходження єдиного оберненого елемента `Z⁻¹ mod p` виконується лише один раз — під час зворотного переведення підсумкової точки у афінні координати `(x, y)` наприкінці скалярного множення.

## 5. Проективні координати Гомогенного вигляду проти координат Якобі

У класичній алгебраїчній геометрії проективні координати вводять **гомогенним чином**: `(X : Y : Z)`, де `x = X/Z` та `y = Y/Z`. 

При цьому кубічне рівняння набуває однорідного вигляду `Y²·Z = X³ + a·X·Z² + b·Z³`.

Порівняємо арифметичну складність операцій над точками у трьох різних системах координат (де `I` — обчислення оберненого елемента, `M` — множення у полі, `S` — піднесення до квадрата):

1. **Афінні координати `(x, y)`:**
   - Додавання точок: `1I + 2M + 1S`
   - Подвоєння точки: `1I + 2M + 2S`
   - *Плюси:* Мінімальний обсяг пам'яті (2 елементи полів).
   - *Мінуси:* Дороге ділення `1I` на кожному кроці.

2. **Гомогенні проективні координати `(X : Y : Z)`:**
   - Додавання точок: `12M + 2S`
   - Подвоєння точки: `7M + 5S`
   - *Плюси:* Відсутність ділень `I = 0`.
   - *Мінуси:* Повільніше подвоєння точок у порівнянні з Якобі.

3. **Координати Якобі `(X : Y : Z)` (де `x = X/Z²`, `y = Y/Z³`):**
   - Додавання точок: `12M + 4S`
   - Подвоєння точки: `4M + 6S` (а при `a = -3` швидкість стає `3M + 5S`!).
   - *Плюси:* Найшвидше у світі подвоєння точок, що і зробило систему Якобі світовим стандартом у криптографії (криві secp256k1, NIST P-256).

## 6. Віконні методи прискорення скалярного множення (wNAF)

Окрім вибору систем координат, вагомим резервом прискорення програмних реалізацій еліптичної криптографії є віконні алгоритми скалярного множення.

### Метод ковзного вікна (Sliding Window Method)

Замість обробки скаляра по одному біту за раз, алгоритм розбиває скаляр `k` на блоки (вікна) шириною `w` біт (наприклад `w = 4`). Заздалегідь обчислюється таблиця з 16 точок `{O, 1·P, 2·P, ..., 15·P}`. На кожній ітерації алгоритм виконує `w` операцій подвоєння підряд і лише 1 операцію додавання попередньо обчисленої точки з таблиці. Це зменшує кількість точкових додавань у `w` разів!

### Представлення скаляра у формі wNAF (Width-w Non-Adjacent Form)

Оскільки на еліптичній кривій обчислення від'ємної точки `-P = (x, -y)` є абсолютно безкоштовною операцією (потрібно лише змінити знак ординати `y ↦ p - y`), скаляр `k` можна подати у трійковій формі із цифрами `{-1, 0, 1}`:

```
k = ∑ c_i · 2ⁱ,   c_i ∈ {-1, 0, 1}
```

У формі **wNAF** довільний скаляр `k` перетворюється на канонічний вираз, у якому з кожних `w` послідовних цифр максимум одна є ненульовою. Це гарантує, що середня щільність ненульових цифр зменшується з `1/2` до `1 / (w + 1)`. 

Для 256-бітного скаляра використання `wNAF` при `w = 5` скорочує кількість точкових додавань з 128 до всього 42, забезпечуючи прискорення обчислення цифрових підписів ECDSA на 35–40%!

## 7. Схема стиснення точок (Point Compression)

У мережевих протоколах (TLS, SSH, Bitcoin) передача повної точки `(x, y)` вимагає 64 байти (для 256-бітних полів). Проте, оскільки ордината `y` обчислюється з рівняння `y² ≡ x³ + a·x + b (mod p)`, для відновлення `y` достатньо знати абсцису `x` та парність ординати `y mod 2`!

- **Стиснута точка (Compressed Point):** Записується як `1 байт префікса (0x02 якщо y парне, 0x03 якщо y непарне) + 32 байти x`. Розмір зменшується з 65 до 33 байтів!
- **Декомпресія (Point Decompression):**
  1. Обчислити `z = x³ + a·x + b mod p`.
  2. Обчислити квадратний корінь `y = √z mod p` за допомогою Символу Лежандра та алгоритму Тонеллі–Шенкса (або піднесенням до степеня `z^{(p+1)/4} mod p` для простих чисел `p ≡ 3 mod 4`).
  3. Якщо `y mod 2` не збігається з префіксом, обрати від'ємний корінь `y' = p - y`.

## 8. Представлення великих чисел BigInt та редукція Монтгомері

У реальних криптографічних системах (наприклад secp256k1 чи Curve25519) просте число `p` та координати `x, y` мають довжину 256 біт. Оскільки стандартні регістри процесора мають розмір 64 біти (`uint64_t`), кожне таке число зберігається як масив із 4 слів (limbs):

:::tabs
@tab C
```c
typedef struct {
    uint64_t limbs[4]; // 4 * 64 = 256 біт
} bigint256;
```

@tab C++
```cpp
struct bigint256 {
    std::array<uint64_t, 4> limbs{}; // 4 * 64 = 256 біт
};
```
:::

Множення двох 256-бітних чисел утворює 512-бітний результат. Для швидкого обчислення залишку від ділення 512-бітного результату на `p` замість звичайного повільного ділення використовують **Редукцію Монтгомері (Montgomery Reduction)**.

Переходячи у простір Монтгомері `a_mont = (a · R) mod p` (де `R = 2²⁵⁶`), операція множення `MontgomeryReduction(A_mont · B_mont)` виконується за допомогою лише декількох операцій множення та зсувів 64-бітних регістрів без жодного ділення 512-бітних чисел.

Крім того, для спеціальних простих чисел (таких як просте число Псевдо-Мерсенна `p = 2²⁵⁵ - 19` у Curve25519) обчислення залишку виконується за 1-2 операції додавання завдяки тотожності `2²⁵⁵ ≡ 19 (mod p)`.

## 9. Алгоритми скалярного множення та захист від атак по побічних каналах

Найпростіший спосіб обчислення скалярного добутку `R = k·P` — двійковий алгоритм **Double-and-Add** (аналог піднесення до степеня Square-and-Multiply). Алгоритм сканує біти скаляра `k` від молодшого до старшого (або від старшого до молодшого):
- На кожному кроці поточне значення подвоюється: `P_temp = 2·P_temp`.
- Якщо поточний біт скаляра `k` дорівнює 1, виконується додаткове додавання: `R = R + P_temp`.

Загальна кількість подвоєнь для `b`-бітного скаляра завжди дорівнює `b`, а кількість додавань у середньому дорівнює `b / 2` (вага Геммінга скаляра).

### Проблема витоку інформації через побічні канали (Side-Channel Attacks)

У нативній реалізації `if (k & 1)` виконання додаткової операції `point_add` залежить від значення конкретного біта приватного ключа `k`. Зловмисник, вимірюючи час виконання операції (Timing Attack) або енергоспоживання процесора (Simple Power Analysis, SPA), може чітко розрізнити кроки, де виконувалося лише подвоєння, від кроків, де виконувалося і подвоєння, і додавання. Це дозволяє повністю відновити всі біти приватного ключа `k`.

Для захисту від атак у реальних системах використовують:
1. **Драбину Монтгомері (Montgomery Ladder):** Алгоритм, у якому на кожному ітераційному кроці **завжди** виконується і одне подвоєння, і одне додавання, незалежно від значення біта `k`.
2. **Множення у сталий час (Constant-Time Execution):** Відсутність умовних розгалужень `if/else`, що залежать від таємних даних, та використання масок у бітових операціях.

Умовний обмін точок `CSWAP(bit, P, Q)` реалізують без умовного розгалуження через побітові операції:

:::tabs
@tab C
```c
void cswap(uint64_t bit, Point* P, Point* Q) {
    uint64_t mask = -bit; // 0x0000... якщо bit=0, 0xFFFF... якщо bit=1
    uint64_t delta_x = mask & (P->x ^ Q->x);
    P->x ^= delta_x;
    Q->x ^= delta_x;
    
    uint64_t delta_y = mask & (P->y ^ Q->y);
    P->y ^= delta_y;
    Q->y ^= delta_y;
}
```

@tab C++
```cpp
void cswap(uint64_t bit, Point& P, Point& Q) noexcept {
    const uint64_t mask = -bit; // 0x0000... якщо bit=0, 0xFFFF... якщо bit=1
    const uint64_t delta_x = mask & (P.x ^ Q.x);
    P.x ^= delta_x;
    Q.x ^= delta_x;
    
    const uint64_t delta_y = mask & (P.y ^ Q.y);
    P.y ^= delta_y;
    Q.y ^= delta_y;
}
```
:::

Розглянемо ключові компоненти та особливості наведених системних рішень мовами C, C++ та Python.

### С-реалізація:
- **Тип даних `Point`:** Зберігає координати `x`, `y` типу `int64_t` та булевий прапорець `is_infinity`. Це дозволяє уникнути виділення динамічної пам'яті у купі (`malloc`), що гарантує високу швидкість обчислень та відсутність витоків пам'яті.
- **Функція `mod_pos`:** Обчисливає мажорантний залишок `a % p`. Оскільки у стандарті C99 оператор `%` для від'ємних ділених повертає від'ємну остачу (наприклад `-5 % 97 = -5`), функція коригує це значення додаванням `+ p`, повертаючи коректне число з діапазону `[0, p-1]`.
- **Функція `mod_inverse`:** Реалізує Розширений алгоритм Евкліда з використанням двох інваріантних пар `(r, newr)` та `(t, newt)`. Алгоритм виконується до обнулення `newr` і повертає `t mod p`. Якщо підсумковий `gcd(b, p) > 1`, функція повертає `-1` як індикатор відсутності оберненого елемента.

### C++-реалізація:
- **Модель точок через `std::optional`:** Точка описується як `std::optional<std::pair<int64_t, int64_t>>`. Відсутність значення (`std::nullopt`) природно моделює точку на нескінченності `O`, що виключає необхідність використання спеціальних прапорців чи умовних указівників.
- **Інкапсуляція кривої `EllipticCurve`:** Параметри кривої `a`, `b`, `p` передаються у конструктор і зберігаються у приватних полями класу, а методи `double_point`, `add` та `scalar_multiply` є константними мебер-функціями (`[[nodiscard]]`), що запобігає випадковому викривленню стану кривої.
- **Обробка винятків:** У випадку спроби обчислення оберненого елемента для неіснуючого значення метод `mod_inverse` ґенерить виняток `std::invalid_argument`.

### Python-реалізація:
- **Вбудована арифметика нескінченної точності:** Python автоматично підтримує довгу арифметику, що дозволяє легко тестувати обчислення для великих простих чисел (наприклад 256-бітних простих чисел) без підключення сторонніх бібліотек BigInt.
- **Функція `pow(val, -1, p)`:** Починаючи з Python 3.8, стандартна функція `pow` підтримує від'ємний показник степеня `-1` для швидкого обчислення оберненого елемента за модулем `p` на рівні C-коду інтерпретатора.

## 11. Вихідний код реалізації

Нижче наведено три ідіоматичні реалізації точкової арифметики над полем `𝔽ₚ` мовами C, C++ та Python. 

Усі три програми вирішують одну й ту саму контрольну задачу на тестовій кривій `y² = x³ + 2·x + 3 (mod 97)` для базової точки `P = (3, 6)` і повертають точний однаковий результат:
- `P = (3, 6)`
- `2·P = (80, 10)`
- `3·P = (80, 87)`
- `5·P = (3, 91)`

```c
#include <stdio.h>
#include <stdbool.h>
#include <stdint.h>

// Точка на еліптичній кривій y^2 = x^3 + a*x + b (mod p)
typedef struct {
    int64_t x;
    int64_t y;
    bool is_infinity; // true відповідає точці на нескінченності O
} Point;

// Корректне обчислення a mod p з гарантією додатності результату [0, p-1]
static int64_t mod_pos(int64_t a, int64_t p) {
    int64_t r = a % p;
    return r < 0 ? r + p : r;
}

// Розширений алгоритм Евкліда для знаходження b^-1 mod p
static int64_t mod_inverse(int64_t b, int64_t p) {
    int64_t t = 0, newt = 1;
    int64_t r = p, newr = mod_pos(b, p);

    while (newr != 0) {
        int64_t quotient = r / newr;
        int64_t temp_t = t - quotient * newt;
        t = newt;
        newt = temp_t;

        int64_t temp_r = r - quotient * newr;
        r = newr;
        newr = temp_r;
    }

    if (r > 1) return -1; // Элемент не має оберненого
    return mod_pos(t, p);
}

// Перевірка рівності двох точок
bool point_equals(Point p1, Point p2) {
    if (p1.is_infinity && p2.is_infinity) return true;
    if (p1.is_infinity || p2.is_infinity) return false;
    return p1.x == p2.x && p1.y == p2.y;
}

// Подвоєння точки: R = 2*P mod p
Point point_double(Point p1, int64_t a, int64_t p) {
    if (p1.is_infinity || p1.y == 0) {
        return (Point){0, 0, true};
    }

    // lambda = (3*x1^2 + a) * (2*y1)^-1 mod p
    int64_t num = mod_pos(3 * p1.x * p1.x + a, p);
    int64_t den = mod_pos(2 * p1.y, p);
    int64_t den_inv = mod_inverse(den, p);

    if (den_inv == -1) return (Point){0, 0, true};

    int64_t lambda = mod_pos(num * den_inv, p);

    // x3 = lambda^2 - 2*x1 mod p
    int64_t x3 = mod_pos(lambda * lambda - 2 * p1.x, p);
    // y3 = lambda*(x1 - x3) - y1 mod p
    int64_t y3 = mod_pos(lambda * (p1.x - x3) - p1.y, p);

    return (Point){x3, y3, false};
}

// Додавання двох точок: R = P + Q mod p
Point point_add(Point p1, Point p2, int64_t a, int64_t p) {
    if (p1.is_infinity) return p2;
    if (p2.is_infinity) return p1;

    // Якщо x1 == x2
    if (p1.x == p2.x) {
        if (mod_pos(p1.y + p2.y, p) == 0) {
            return (Point){0, 0, true}; // P + (-P) = O
        }
        return point_double(p1, a, p);
    }

    // lambda = (y2 - y1) * (x2 - x1)^-1 mod p
    int64_t num = mod_pos(p2.y - p1.y, p);
    int64_t den = mod_pos(p2.x - p1.x, p);
    int64_t den_inv = mod_inverse(den, p);

    if (den_inv == -1) return (Point){0, 0, true};

    int64_t lambda = mod_pos(num * den_inv, p);

    // x3 = lambda^2 - x1 - x2 mod p
    int64_t x3 = mod_pos(lambda * lambda - p1.x - p2.x, p);
    // y3 = lambda*(x1 - x3) - y1 mod p
    int64_t y3 = mod_pos(lambda * (p1.x - x3) - p1.y, p);

    return (Point){x3, y3, false};
}

// Скалярне множення R = k * P методом Double-and-Add (двійкова драбина)
Point scalar_multiply(int64_t k, Point p1, int64_t a, int64_t p) {
    Point result = {0, 0, true}; // O
    Point addend = p1;

    while (k > 0) {
        if (k & 1) {
            result = point_add(result, addend, a, p);
        }
        addend = point_double(addend, a, p);
        k >>= 1;
    }
    return result;
}

int main(void) {
    // Параметри кривої y^2 = x^3 + 2*x + 3 (mod 97)
    int64_t a = 2, b = 3, p = 97;

    // Базова точка P = (3, 6)
    Point P = {3, 6, false};

    printf("Початкова точка P: (%lld, %lld)\n", P.x, P.y);

    Point P2 = point_double(P, a, p);
    printf("2*P: (%lld, %lld)\n", P2.x, P2.y);

    Point P3 = point_add(P2, P, a, p);
    printf("3*P (додавання P2 + P): (%lld, %lld)\n", P3.x, P3.y);

    Point P5 = scalar_multiply(5, P, a, p);
    printf("5*P (скалярне множення): (%lld, %lld)\n", P5.x, P5.y);

    return 0;
}
```

```cpp
#include <iostream>
#include <optional>
#include <stdexcept>
#include <cstdint>

// Клас моделювання скінченного поля F_p та точкової арифметики
class EllipticCurve {
public:
    struct Point {
        std::optional<std::pair<int64_t, int64_t>> coord; // nullopt відповідає точці O

        [[nodiscard]] bool is_infinity() const noexcept {
            return !coord.has_value();
        }
    };

private:
    int64_t a_;
    int64_t b_;
    int64_t p_;

    [[nodiscard]] static int64_t mod_pos(int64_t val, int64_t p) noexcept {
        int64_t r = val % p;
        return r < 0 ? r + p : r;
    }

    [[nodiscard]] static int64_t mod_inverse(int64_t b, int64_t p) {
        int64_t t = 0, newt = 1;
        int64_t r = p, newr = mod_pos(b, p);

        while (newr != 0) {
            int64_t quotient = r / newr;
            int64_t temp_t = t - quotient * newt;
            t = newt;
            newt = temp_t;

            int64_t temp_r = r - quotient * newr;
            r = newr;
            newr = temp_r;
        }

        if (r > 1) {
            throw std::invalid_argument("Елемент не має оберненого за модулем");
        }
        return mod_pos(t, p);
    }

public:
    EllipticCurve(int64_t a, int64_t b, int64_t p) : a_(a), b_(b), p_(p) {}

    [[nodiscard]] Point double_point(const Point& P) const {
        if (P.is_infinity() || P.coord->second == 0) {
            return Point{std::nullopt};
        }

        const auto [x1, y1] = *P.coord;
        const int64_t num = mod_pos(3 * x1 * x1 + a_, p_);
        const int64_t den = mod_pos(2 * y1, p_);
        const int64_t lambda = mod_pos(num * mod_inverse(den, p_), p_);

        const int64_t x3 = mod_pos(lambda * lambda - 2 * x1, p_);
        const int64_t y3 = mod_pos(lambda * (x1 - x3) - y1, p_);

        return Point{std::make_pair(x3, y3)};
    }

    [[nodiscard]] Point add(const Point& P, const Point& Q) const {
        if (P.is_infinity()) return Q;
        if (Q.is_infinity()) return P;

        const auto [x1, y1] = *P.coord;
        const auto [x2, y2] = *Q.coord;

        if (x1 == x2) {
            if (mod_pos(y1 + y2, p_) == 0) {
                return Point{std::nullopt};
            }
            return double_point(P);
        }

        const int64_t num = mod_pos(y2 - y1, p_);
        const int64_t den = mod_pos(x2 - x1, p_);
        const int64_t lambda = mod_pos(num * mod_inverse(den, p_), p_);

        const int64_t x3 = mod_pos(lambda * lambda - x1 - x2, p_);
        const int64_t y3 = mod_pos(lambda * (x1 - x3) - y1, p_);

        return Point{std::make_pair(x3, y3)};
    }

    [[nodiscard]] Point scalar_multiply(int64_t k, const Point& P) const {
        Point result{std::nullopt};
        Point addend = P;

        while (k > 0) {
            if (k & 1) {
                result = add(result, addend);
            }
            addend = double_point(addend);
            k >>= 1;
        }
        return result;
    }
};

int main() {
    // Крива y^2 = x^3 + 2*x + 3 (mod 97)
    EllipticCurve curve(2, 3, 97);
    EllipticCurve::Point P{std::make_pair(3, 6)};

    std::cout << "Початкова точка P: (" << P.coord->first << ", " << P.coord->second << ")\n";

    auto P2 = curve.double_point(P);
    std::cout << "2*P: (" << P2.coord->first << ", " << P2.coord->second << ")\n";

    auto P3 = curve.add(P2, P);
    std::cout << "3*P: (" << P3.coord->first << ", " << P3.coord->second << ")\n";

    auto P5 = curve.scalar_multiply(5, P);
    std::cout << "5*P (через Double-and-Add): (" << P5.coord->first << ", " << P5.coord->second << ")\n";

    return 0;
}
```

```python
from typing import Optional, Tuple

class Point:
    def __init__(self, coord: Optional[Tuple[int, int]] = None):
        self.coord = coord  # None відповідає точці O (нескінченність)

    @property
    def is_infinity(self) -> bool:
        return self.coord is None

    def __repr__(self) -> str:
        if self.is_infinity:
            return "Point(O)"
        return f"Point({self.coord[0]}, {self.coord[1]})"


class EllipticCurve:
    def __init__(self, a: int, b: int, p: int):
        self.a = a
        self.b = b
        self.p = p

    def _mod_inverse(self, val: int) -> int:
        # Вбудований розширений алгоритм Евкліда в Python 3.8+
        return pow(val, -1, self.p)

    def double_point(self, P: Point) -> Point:
        if P.is_infinity or P.coord[1] == 0:
            return Point(None)

        x1, y1 = P.coord
        num = (3 * x1**2 + self.a) % self.p
        den = (2 * y1) % self.p
        lambda_val = (num * self._mod_inverse(den)) % self.p

        x3 = (lambda_val**2 - 2 * x1) % self.p
        y3 = (lambda_val * (x1 - x3) - y1) % self.p

        return Point((x3, y3))

    def add(self, P: Point, Q: Point) -> Point:
        if P.is_infinity:
            return Q
        if Q.is_infinity:
            return P

        x1, y1 = P.coord
        x2, y2 = Q.coord

        if x1 == x2:
            if (y1 + y2) % self.p == 0:
                return Point(None)
            return self.double_point(P)

        num = (y2 - y1) % self.p
        den = (x2 - x1) % self.p
        lambda_val = (num * self._mod_inverse(den)) % self.p

        x3 = (lambda_val**2 - x1 - x2) % self.p
        y3 = (lambda_val * (x1 - x3) - y1) % self.p

        return Point((x3, y3))

    def scalar_multiply(self, k: int, P: Point) -> Point:
        result = Point(None)
        addend = P

        while k > 0:
            if k & 1:
                result = self.add(result, addend)
            addend = self.double_point(addend)
            k >>= 1

        return result


if __name__ == "__main__":

    P = Point((3, 6))

    P2 = curve.double_point(P)
    print(f"2*P: {P2}")

    print(f"3*P: {P3}")
    P5 = curve.scalar_multiply(5, P)
    print(f"5*P (Double-and-Add): {P5}")
```

## 12. Тестові вектори та автоматизоване верифікаційне тестування

Для гарантії надійності промислового коду реалізації точкової арифметики розробники використовують стандартизовані тестові вектори (NIST CAVP / Wycheproof). 

Верифікаційне тестування охоплює 4 обов'язкові сценарії:
1. **Перевірка фундаментальних алгебраїчних тотожностей:** `1·P = P`, `0·P = O`, `P + (-P) = O`, `(k + 1)·P = k·P + P`.
2. **Тестування крайніх бітових масок:** Перевірка скалярів вигляду `k = 0`, `k = 1`, `k = n - 1` (де `n` — порядок базової точки), а також скалярів з усіма одиничними бітами `k = 2²⁵⁶ - 1`.
3. **Генерація випадкових атак (Fuzzing):** Подача некоректно сформованих байтових послідовностей на вхід функції декомпресії точок `point_decompression` для перевірки відсутності аварійного завершення (паніки або падіння сегментації).

## 13. Валідація точок та захист від атак на некоректні криві (Invalid Curve Attacks)

Під час прийому публічного ключа або точки `Q` від зовнішнього користувача або мережевого сокета криптографічний модуль зобов'язаний виконувати 3 перевірки валідності перед виконанням операцій точкової арифметики:

1. **Належність полю 𝔽ₚ:** Перевірити, що координати `x` та `y` є цілими числами в інтервалі `[0, p-1]`.
2. **Перевірка рівняння кривої:** Підставити `(x, y)` у рівняння `y² ≡ x³ + a·x + b (mod p)`. Якщо рівність не справджується, точка не належить кривій.
3. **Перевірка порядку підгрупи:** Переконатися, що точка `Q` належить підгрупі великого простого порядку `n` (обчислити `n·Q == O`).

Нехтування цими перевірками дозволяє зловмиснику передати точку `Q'`, яка належить іншій (нестійкій) кривій з малим порядком групи, що дає можливість швидко обчислити приватний ключ `k` за допомогою Китайської теореми про залишки. Описаний набір інженерних вимог забезпечує повну точність та захищеність програмних систем еліптичної криптографії.
