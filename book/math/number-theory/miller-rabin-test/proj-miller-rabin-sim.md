# ⚙️ Тест Міллера-Рабіна: детермінована перевірка для uint64_t

## Навіщо ми це пишемо?
Стандартні методи перевірки на простоту (перебір дільників) працюють занадто довго для 64-бітних цілих чисел, адже вимагають до 4 мільярдів ітерацій у гіршому випадку. Тест Міллера-Рабіна дозволяє перевірити таке число за частки мікросекунди. Використовуючи заздалегідь відомий математичний набір із семи баз, ми перетворюємо ймовірнісний алгоритм на абсолютно точний (детермінований) для будь-якого значення, що вміщується у `uint64_t`.

## Алгоритмічна ідея
Тест Міллера-Рабіна базується на малій теоремі Ферма та властивостях нетривіальних квадратних коренів з одиниці за простим модулем. Ми подаємо парне число `n - 1` у вигляді `d * 2^s`, де `d` — непарне число. Потім для кожної обраної бази `a` перевіряємо, чи виконується хоча б одна з двох умов: або `a^d mod n == 1`, або послідовне піднесення результату до квадрата `s - 1` разів дає `n - 1`. Якщо число просте, це гарантовано виконується. Для складеного числа хоча б одна база з нашого ретельно відібраного набору гарантовано виявить складеність (стане «свідком»). Математики довели, що для перевірки всіх 64-бітних чисел достатньо перевірити лише сім специфічних баз. Важливий нюанс — безпечне множення 64-бітних чисел по модулю без переповнення, для чого використовується проміжний тип `__int128`.

## Реалізація на C++17

```cpp
#include <iostream>
#include <vector>
#include <cstdint>

// Безпечне модульне піднесення до степеня (base^exp % mod)
uint64_t power_mod(uint64_t base, uint64_t exp, uint64_t mod) {
    uint64_t res = 1;
    base %= mod;
    while (exp > 0) {
        if (exp % 2 == 1) {
            // Використовуємо __int128 для уникнення переповнення при множенні
            res = static_cast<uint64_t>((static_cast<__int128>(res) * base) % mod);
        }
        base = static_cast<uint64_t>((static_cast<__int128>(base) * base) % mod);
        exp /= 2;
    }
    return res;
}

// Детермінований тест Міллера-Рабіна для uint64_t
bool is_prime(uint64_t n) {
    if (n < 2) return false;
    if (n == 2 || n == 3) return true;
    if (n % 2 == 0) return false;

    // Представляємо n - 1 як d * 2^s
    uint64_t d = n - 1;
    int s = 0;
    while (d % 2 == 0) {
        d /= 2;
        s++;
    }

    // Детерміновані бази, достатні для будь-якого uint64_t
    std::vector<uint64_t> bases = {2, 325, 9375, 28178, 450775, 9780504, 1795265022};

    for (uint64_t a : bases) {
        // Якщо база кратна числу n, ігноруємо її
        if (a % n == 0) continue;

        uint64_t x = power_mod(a, d, n);
        if (x == 1 || x == n - 1) continue;

        bool composite = true;
        for (int r = 1; r < s; r++) {
            x = static_cast<uint64_t>((static_cast<__int128>(x) * x) % n);
            if (x == n - 1) {
                composite = false;
                break;
            }
        }
        
        // Якщо жодна умова не виконалася, число гарантовано складене
        if (composite) return false;
    }
    return true;
}

int main() {
    std::vector<uint64_t> test_nums = {97, 1000000007, 4294967291, 18446744073709551557ULL};
    for (uint64_t n : test_nums) {
        std::cout << n << " is " << (is_prime(n) ? "prime" : "composite") << "\n";
    }
    return 0;
}
```

## Ключові фрагменти та інваріанти
1. **Безпечне множення (`__int128`)**: Під час піднесення бази до квадрата чи множення на проміжний результат ми можемо отримати число, що наближається до максимального `(2^64)^2`. Це неминуче спричинить переповнення в 64-бітному типі `uint64_t` та зіпсує залишок від ділення. Розширення проміжних результатів до 128-бітного цілого типу вирішує цю проблему без використання повільної довгої арифметики. Цей тип вбудований у GCC та Clang.
2. **Виокремлення непарної частини (`d * 2^s`)**: Цей крок гарантує, що ми завжди починаємо тест із непарного показника `d`, а потім послідовно підносимо результат до квадрата рівно `s` разів. Головний інваріант цього фрагмента полягає в тому, що наприкінці циклу ми неявно обчислюємо значення `a^(n-1) mod n`.
3. **Відсів дільників (`a % n == 0`)**: Якщо число `n` ділить базу, ми не можемо використовувати її для перевірки простоти, оскільки обчислення дадуть нуль. У такому випадку цю базу алгоритм безпечно ігнорує — це не впливає на точність перевірки.
4. **Обробка крайових випадків**: Усі числа, що менші за 2, автоматично позначаються як складені. Числа 2 та 3 повертають `true`. Парні числа більші за 2 миттєво відкидаються, що дозволяє значно прискорити обробку великих випадкових наборів даних, не переходячи до важкого циклу.

## I/O та алгоритмічна складність
Вхідними даними є єдине беззнакове 64-бітне ціле число. Функція повертає булеве значення: `true`, якщо число гарантовано просте, та `false`, якщо воно гарантовано складене. 
Алгоритм виконується за час, пропорційний `O(k * log n)`, де `k` — кількість баз (тут `k = 7`), а `n` — значення нашого числа. Завдяки класичній оптимізації через швидке піднесення до степеня, кількість операцій модульного множення становить щонайбільше близько 64 для кожної бази. Отже, загалом для перевірки будь-якого `uint64_t` потрібно не більше 450-500 модульних множень. Це забезпечує екстремальну швидкодію (сотні наносекунд на одне число) у порівнянні з класичним повним перебором дільників. Споживання пам'яті складає лише `O(1)` для збереження фіксованого масиву семи баз.
