# Проєкт: Калькулятор мультиплікативного порядку на C++17

Швидке знаходження мультиплікативного порядку для гігантських чисел — це задача, яка вимагає алгоритмічної кмітливості. Уявіть, що ви працюєте з модулем m, який становить мільярди, або навіть сотні цифр. Якщо ми спробуємо обчислити порядок наївно — тобто просто послідовно підносити базу до степенів a¹, a², a³... і перевіряти, коли ж нарешті вийде 1, — наш комп'ютер зависне на роки. Часова складність такого "сліпого" підходу є лінійною O(m), що абсолютно неприйнятно для криптографії, де використовуються числа розміром 2048 і більше біт.

Ефективний, інженерний підхід полягає у тому, щоб не перевіряти всі числа підряд, а використати фундаментальну властивість мультиплікативного порядку: він обов'язково є точним дільником функції Ейлера φ(m). Таким чином, замість O(m) операцій ми маємо справу лише з дільниками числа φ(m), що радикально зменшує простір пошуку. 

Нижче наведено повноцінний, професійний проєкт на C++17, який реалізує цей розумний алгоритм. Код розбитий на 5 чітко відокремлених логічних компонентів, кожен з яких відповідає за свою частину математичної архітектури.

## Постановка задачі

Основна мета даного проєкту — створити високоефективну програму для розрахунку мультиплікативного порядку заданого цілого числа a за заданим модулем m. Мультиплікативний порядок, який математично позначається як ordₘ(a), визначається як найменше додатне ціле число k, для якого виконується конгруенція aᵏ ≡ 1 (mod m).

Важливо пам'ятати про дві ключові вимоги. По-перше, мультиплікативний порядок існує тоді і тільки тоді, коли числа a та m є взаємно простими. Це означає, що їхній найбільший спільний дільник (НСД) має дорівнювати одиниці. Якщо це не так, програма повинна коректно це розпізнати і повідомити про відсутність порядку. По-друге, алгоритм має працювати з достатньо великими числами, які можуть перевищувати стандартні обмеження 32-бітних цілих типів, тому необхідно обережно працювати з типами даних, запобігаючи переповненню розрядної сітки під час проміжних обчислень (зокрема, при множенні).

Наївно реалізована перевірка кожного показника степеня по порядку призводить до складності O(m), що означає виконання m кроків. Якщо m досягає значення 10⁹, обчислення займуть значний час. Отже, нам потрібен оптимізований підхід, який спирається на глибоку математичну закономірність, що пов'язує мультиплікативний порядок з функцією Ейлера φ(m).

## Архітектурна логіка

Архітектура цього калькулятора побудована на теоремі Лагранжа для скінченних груп, яка в контексті модульної арифметики стверджує, що мультиплікативний порядок числа завжди є точним дільником функції Ейлера φ(m). Це геніальне спостереження дозволяє різко звузити область пошуку. Замість того, щоб шукати k серед усіх чисел від 1 до m, нам достатньо перебрати виключно дільники числа φ(m).

Для втілення цієї математичної логіки в код, архітектуру поділено на кілька чітких, ізольованих етапів обробки даних:
1. **Етап валідації:** Перевірка чисел a та m на взаємну простоту за допомогою алгоритму Евкліда. Якщо НСД(a, m) ≠ 1, виконання відразу припиняється з нульовим результатом.
2. **Етап аналізу модуля:** Обчислення функції Ейлера φ(m), яка визначає кількість чисел, взаємно простих з модулем.
3. **Етап генерації простору пошуку:** Знаходження всіх можливих дільників обчисленого значення φ(m). Це наші кандидати на мультиплікативний порядок.
4. **Етап фільтрації (Оркестрація):** Перевірка знайдених дільників у порядку зростання. Кожен дільник d підставляється у формулу aᵈ mod m. Оскільки ми шукаємо найменше число, що дає 1, то перший же дільник, який задовольнить цю умову, і буде нашим шуканим мультиплікативним порядком.

Для гарантування відсутності переповнення під час модульного піднесення до степеня, архітектура також передбачає використання спеціалізованих 128-бітних типів даних при множенні двох 64-бітних цілих чисел, а також алгоритм швидкого піднесення до степеня двійковим розкладом.

## Програмний код C++17

```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <algorithm> // для std::sort

// 1. Швидке модульне піднесення до степеня (a^b mod m) за O(log b)
// Використання __uint128_t запобігає переповненню під час множення двох 64-бітних чисел.
uint64_t power_mod(uint64_t base, uint64_t exp, uint64_t mod) {
    uint64_t res = 1;
    base = base % mod;
    while (exp > 0) {
        // Якщо поточний біт експоненти одиничний, множимо результат на поточну базу
        if (exp % 2 == 1) {
            res = (uint64_t)(((__uint128_t)res * base) % mod); 
        }
        // Підносимо базу в квадрат для наступного кроку
        base = (uint64_t)(((__uint128_t)base * base) % mod);
        exp /= 2; // Зсуваємо експоненту вправо
    }
    return res;
}

// 2. Обчислення найбільшого спільного дільника (НСД) класичним алгоритмом Евкліда
uint64_t gcd(uint64_t a, uint64_t b) {
    while (b) {
        a %= b;
        std::swap(a, b);
    }
    return a;
}

// 3. Обчислення функції Ейлера φ(n) за допомогою простої факторизації
// Використовує формулу: φ(n) = n * (1 - 1/p1) * (1 - 1/p2) ...
uint64_t euler_totient(uint64_t n) {
    uint64_t result = n;
    for (uint64_t i = 2; i * i <= n; i++) {
        // Якщо i є простим дільником n
        if (n % i == 0) {
            // Видаляємо всі входження цього дільника
            while (n % i == 0) {
                n /= i;
            }
            // Застосовуємо частину формули Ейлера
            result -= result / i;
        }
    }
    // Якщо після всього залишився простий множник, більший за sqrt(початкового n)
    if (n > 1) {
        result -= result / n;
    }
    return result;
}

// 4. Ефективний пошук усіх дільників числа (для числа φ(m))
std::vector<uint64_t> get_divisors(uint64_t n) {
    std::vector<uint64_t> divs;
    for (uint64_t i = 1; i * i <= n; i++) {
        if (n % i == 0) {
            divs.push_back(i); // Додаємо дільник i
            if (i * i != n) {
                divs.push_back(n / i); // Одразу додаємо симетричний дільник n/i
            }
        }
    }
    // Сортуємо масив, щоб перевіряти від найменшого дільника
    std::sort(divs.begin(), divs.end());
    return divs;
}

// 5. Головна оркеструюча функція пошуку порядку
uint64_t multiplicative_order(uint64_t a, uint64_t m) {
    // Якщо числа не взаємно прості, порядку не існує (мультиплікативна група не охоплює a)
    if (gcd(a, m) != 1) return 0; 
    
    // Крок А: знаходимо φ(m)
    uint64_t phi = euler_totient(m);
    
    // Крок Б: знаходимо всі можливі кандидати на порядок (дільники φ(m))
    std::vector<uint64_t> divs = get_divisors(phi);
    
    // Крок В: перевіряємо кандидати по зростанню
    for (uint64_t d : divs) {
        // Якщо a^d ≡ 1 (mod m), то d і є мультиплікативним порядком
        if (power_mod(a, d, m) == 1) {
            return d; 
        }
    }
    // За Теоремою Ейлера, цикл має закритися максимум на φ(m)
    return phi;
}

// Демонстрація роботи калькулятора
int main() {
    // Тестуємо для m = 13, a = 3 (Порядок = 3)
    uint64_t a = 3;
    uint64_t m = 13;
    
    uint64_t order = multiplicative_order(a, m);
    if (order == 0) {
        std::cout << "Порядок не існує, числа " << a << " та " << m << " не взаємно прості.\n";
    } else {
        std::cout << "Мультиплікативний порядок ord_" << m << "(" << a << ") = " << order << "\n";
    }
    
    // Тестуємо для великого складеного числа
    uint64_t a_big = 7;
    uint64_t m_big = 1000000007; // Відоме велике просте число
    std::cout << "Мультиплікативний порядок ord_" << m_big << "(" << a_big << ") = " 
              << multiplicative_order(a_big, m_big) << "\n";
              
    return 0;
}
```

## Построчний розбір

Для повного розуміння механіки калькулятора, розглянемо кожну складову частину окремо.

**Функція `power_mod`:** Це критично важливий будівельний блок. Замість того, щоб множити базу саму на себе exp разів, алгоритм використовує метод "exponentiation by squaring" (піднесення до степеня двійковим розкладом). У циклі `while (exp > 0)`, ми перевіряємо останній біт експоненти (`exp % 2 == 1`). Якщо він одиничний, поточна `base` множиться на накопичений `res`. Після цього база обов'язково зводиться в квадрат, а експонента ділиться на 2 (побітовий зсув вправо). Рядок з приведенням до типу `__uint128_t` рятує від прихованої помилки: множення двох чисел типу `uint64_t` (до 10¹⁹) може дати результат до 10³⁸, що миттєво переповнить стандартний 64-бітний регістр. Розширення типу до 128 біт гарантує, що результат множення збережеться в цілісності до застосування операції `modulo` (`% mod`).

**Функція `gcd`:** Класичний та безвідмовний алгоритм Евкліда. У циклі `while (b)` змінній `a` присвоюється остача від ділення `a` на `b`, після чого їхні значення обмінюються місцями `std::swap(a, b)`. Процес триває, доки `b` не стане рівним нулю. Це працює гарантовано швидко, за логарифмічний час.

**Функція `euler_totient`:** Обчислює значення φ(n). Цикл іде лише до квадратного кореня з `n` (`i * i <= n`). Якщо `i` ділить `n` без остачі, це означає, що ми знайшли простий множник. Вкладений цикл `while` послідовно ділить `n` на `i`, повністю "видаляючи" цей множник з числа. Далі застосовується математична формула Ейлера: від поточного `result` віднімається його ж значення, поділене на `i` (`result -= result / i`). Це еквівалентно множенню на `(1 - 1/i)`. Якщо після закінчення циклу залишкове значення `n` більше одиниці, це означає, що число мало один простий множник, більший за свій корінь. Його також враховують в окремому блоці `if (n > 1)`.

**Функція `get_divisors`:** Збирає всі дільники числа `n`. Знову ж таки, цикл доходить лише до квадратного кореня. Якщо знайдено дільник `i`, він додається у вектор `divs.push_back(i)`. Одразу після цього розраховується і додається парний, симетричний йому дільник `n / i`, якщо він не дорівнює самому `i` (щоб уникнути дублювання, коли `n` є точним квадратом). Наприкінці вектор сортується за допомогою `std::sort`, що гарантує, що ми будемо тестувати кандидати від найменшого до найбільшого.

**Головна функція `multiplicative_order`:** Вона оркеструє весь процес. Починається з перевірки `gcd(a, m) != 1`. Якщо перевірка пройдена, викликається `euler_totient(m)` для отримання φ(m), потім `get_divisors(phi)` для отримання відсортованого списку кандидатів. Останній етап — проходження циклом `for` по кожному дільнику `d`. Перший дільник, який при підстановці в `power_mod(a, d, m)` дає результат 1, негайно повертається функцією.

## I/O складність (Аналіз складності)

Щоб оцінити продуктивність цього алгоритму, варто розглянути часову та просторову складність кожного окремого етапу та їхню сукупну вагу.

**Часова складність:**
1. Знаходження НСД через алгоритм Евкліда вимагає O(log(min(a, m))) операцій. Це надзвичайно швидко і практично не впливає на загальний час роботи.
2. Обчислення функції Ейлера φ(m) виконує факторизацію шляхом пробного ділення до квадратного кореня з модуля. Відповідно, її найгірший час становить O(√m).
3. Пошук дільників для числа φ(m) також працює до квадратного кореня, тобто вимагає O(√(φ(m))) операцій. Оскільки φ(m) ≤ m, це не перевищує O(√m). Додаткове сортування масиву вимагає O(D log D) операцій, де D — кількість дільників числа φ(m). Кількість дільників D зростає дуже повільно, значно повільніше за логарифм.
4. Фінальний етап тестування кандидатів. Ми здійснюємо модульне піднесення до степеня для кожного дільника, що вимагає O(log d) операцій для кожного кандидата d. Сумарно це займає O(D · log(φ(m))).

Отже, домінуючим фактором у часовій складності є обчислення функції Ейлера та знаходження дільників. Загальна асимптотична часова складність алгоритму жорстко обмежена величиною **O(√m)**. Порівняно з наївним підходом зі складністю O(m), це колосальний прорив. Якщо m = 10¹², наївний алгоритм виконав би трильйон операцій, а наш алгоритм виконає лише близько мільйона, що сучасний процесор зробить за мілісекунду.

**Просторова складність (I/O Complexity):**
Алгоритм використовує дуже мало пам'яті. Єдиною структурою даних, яка динамічно масштабується, є вектор дільників `divs`. Максимальна кількість дільників числа N у межах 64-бітних цілих чисел (до 10¹⁹) ніколи не перевищує 103680 (це максимальне значення для числа з багатьма малими простими множниками). Відповідно, вектор `divs` займе щонайбільше близько 800 кілобайт оперативної пам'яті. Всі інші операції відбуваються на місці за допомогою змінних на стеку. Тому просторова складність оцінюється як **O(D)**, де D — кількість дільників φ(m). У найгіршому випадку вона є дуже малою, що робить алгоритм ідеальним для вбудованих систем (embedded systems) із жорстко обмеженою пам'яттю, підкреслюючи його високу інженерну елегантність.
