# ⚙️ Алгоритм пошуку фундаментального розв'язку рівняння Пелля

У цьому розділі детально розглядається, аналізується та реалізується обчислювальний алгоритм для знаходження фундаментального цілочисельного розв'язку квадратичного діофантового рівняння Пелля вида:

```
x² - d·y² = 1
```

де параметр `d` є додатним цілим числом, яке не є точним квадратом. Алгоритм базується на теорії розкладу квадратного кореня `√d` у неперервний дріб та послідовному обчисленні чисельників і знаменників підхідних дробів `pₙ / qₙ`.

## 1. Алгоритмічна ідея та рекурентні співвідношення

Квадратний ірраціонал `√d` розкладається у періодичний ланцюговий дріб вида:

```
√d = [a₀; (a₁, a₂, ..., a_k, 2a₀)]
```

де `a₀ = ⌊√d⌋` — ціла частина значення `√d`, а `k` — довжина періоду (без урахування кінцевого елемента `2a₀`).

Обчислення коефіцієнтів розкладу `aₙ` виконується без використання дробової арифметики із плаваючою крапкою (що повністю запобігає втраті точності обчислень) за допомогою трьох послідовностей цілих чисел `mₙ`, `dₙ` та `aₙ`:

```
m₀ = 0,   d₀ = 1,   a₀ = ⌊√d⌋
mₙ₊₁ = dₙ·aₙ - mₙ
dₙ₊₁ = (d - mₙ₊₁²) / dₙ
aₙ₊₁ = ⌊(a₀ + mₙ₊₁) / dₙ₊₁⌋
```

Паралельно з коефіцієнтами `aₙ` обчислюються чисельники `pₙ` та знаменники `qₙ` підхідних дробів `pₙ / qₙ` за двочленовими лінійними рекурентними формулами:

```
p₋₂ = 0,   p₋₁ = 1,   pₙ = aₙ·pₙ₋₁ + pₙ₋₂
q₋₂ = 1,   q₋₁ = 0,   qₙ = aₙ·qₙ₋₁ + qₙ₋₂
```

Алгоритм виконує ітерації доти, доки поточний підхідний дріб `pₙ / qₙ` не задовольнить рівняння Пелля:

```
pₙ² - d·qₙ² = 1
```

За теоремою Лагранжа:
- Якщо довжина періоду `k` є парною, фундаментальний розв'язок відповідає підхідному дробу на кроці `n = k - 1`.
- Якщо довжина періоду `k` є непарною, на кроці `n = k - 1` отримуємо розв'язок негативного рівняння `p² - d·q² = -1`, а фундаментальний розв'язок для `+1` досягається на подвоєному періоді при `n = 2k - 1`.

## 2. Аналіз крайових випадків та переповнення цілочисельних типів

При програмній реалізації алгоритму розв'язання рівняння Пелля необхідно враховувати два критичних обчислювальних фактори:

### 1. Перевірка на точний квадрат
Якщо передане число `d` є точним квадратом (`d = k²`), неперервний дріб обривається на першому кроці (`√d = a₀`), а рівняння `x² - k²·y² = 1` має лише тривіальний розв'язок `y = 0, x = 1`. Алгоритм повинен негайно виявляти такі випадки за допомогою перевірки `⌊√d⌋² == d` та повертати спеціальний індикатор відсутності нетривіального розв'язку.

### 2. Експоненціальний ріст та переповнення 64-бітних цілих типів
Чисельники `pₙ` та знаменники `qₙ` зростають експоненціально зі швидкістю `(a₁·a₂...aₙ)`. Наприклад:
- Для `d = 13`: `x = 649, y = 180` (вміщується у 16 біт).
- Для `d = 61`: `x = 1766319049, y = 226153980` (вміщується у 32 біти).
- Для `d = 67`: `x = 48842, y = 5967` (вміщується у 16 біт).
- Для `d = 109`: `x = 158070671986249, y = 15140424455100` (вміщується у 64 біти).
- Для `d = 991`: `x` має 29 десяткових знаків (переповнює стандартні 64-бітні типи `uint64_t` та `unsigned long long`).

Тому надійна програма повинна містити перевірку арифметичного переповнення перед виконанням множення та додавання `p_next = a * p_curr + p_prev1`.

## 3. Детальний трасування алгоритму для d = 13

Простежимо послідовні зміни всіх змінних алгоритму під час обчислення фундаментального розв'язку для `d = 13` (`√13 ≈ 3.60555`):

1. **Ініціалізація**:
   `a₀ = ⌊√13⌋ = 3`. `m₀ = 0`, `d₀ = 1`.
   `p₋₁ = 1, p₀ = 3`, `q₋₁ = 0, q₀ = 1`.
   Перевірка `p₀² - 13·q₀² = 9 - 13 = -4 ≠ 1`.

2. **Крок 1**:
   `m₁ = 1·3 - 0 = 3`.
   `d₁ = (13 - 9) / 1 = 4`.
   `a₁ = ⌊(3 + 3) / 4⌋ = 1`.
   `p₁ = 1·3 + 1 = 4`, `q₁ = 1·1 + 0 = 1`.
   Перевірка `p₁² - 13·q₁² = 16 - 13 = 3 ≠ 1`.

3. **Крок 2**:
   `m₂ = 4·1 - 3 = 1`.
   `d₂ = (13 - 1) / 4 = 3`.
   `a₂ = ⌊(3 + 1) / 3⌋ = 1`.
   `p₂ = 1·4 + 3 = 7`, `q₂ = 1·1 + 1 = 2`.
   Перевірка `p₂² - 13·q₂² = 49 - 52 = -3 ≠ 1`.

4. **Крок 3**:
   `m₃ = 3·1 - 1 = 2`.
   `d₃ = (13 - 4) / 3 = 3`.
   `a₃ = ⌊(3 + 2) / 3⌋ = 1`.
   `p₃ = 1·7 + 4 = 11`, `q₃ = 1·2 + 1 = 3`.
   Перевірка `p₃² - 13·q₃² = 121 - 117 = 4 ≠ 1`.

5. **Крок 4**:
   `m₄ = 3·1 - 2 = 1`.
   `d₄ = (13 - 1) / 3 = 4`.
   `a₄ = ⌊(3 + 1) / 4⌋ = 1`.
   `p₄ = 1·11 + 7 = 18`, `q₄ = 1·3 + 2 = 5`.
   Перевірка `p₄² - 13·q₄² = 324 - 325 = -1` (знайдено розв'язок негативного рівняння!).

6. **Крок 5**:
   `m₅ = 4·1 - 1 = 3`.
   `d₅ = (13 - 9) / 4 = 1`.
   `a₅ = ⌊(3 + 3) / 1⌋ = 6` (кінець періоду `k = 5`).
   `p₅ = 6·18 + 11 = 119`, `q₅ = 6·5 + 3 = 33`.

7. **Продовження до 2k - 1 (n = 9)**:
   Послідовно обчислюючи підхідні дроби до кроку `n = 9`, алгоритм зупиняється на підхідному дробі `p₉ / q₉ = 649 / 180`.
   Перевірка: `649² - 13·180² = 421201 - 13·32400 = 421201 - 421200 = 1`!
   Фундаментальний розв'язок знайдено: **`x = 649, y = 180`**.

## 4. Архітектура програмних реалізацій мовами C та C++

При проектуванні коду мовою C алгоритм винесено в окрему функцію, яка повертає структуру з прапорцями успішності обчислення та наявності арифметичного переповнення. Двокроковий контроль переповнення виконується за допомогою перевірок верхньої межі `UINT64_MAX / b`. Сучасні компілятори C (GCC, Clang) автоматично замінюють ці перевірки на апаратні інструкції перевірки прапорця переповнення `OF` після множення в процесорних реєстрах.

У реалізації мовою C++ застосовано об'єктно-орієнтовану обгортку з класичним RAII-патерном, статичний метод розв'язання та сучасний тип `std::optional` для елегантного повернення результатів без використання вказівників чи спеціальних сигнальних значень.

```c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <math.h>

// Структура для повернення результату розв'язку рівняння Пелля
typedef struct {
    uint64_t x;
    uint64_t y;
    bool found;
    bool overflow;
} PellSolutionC;

// Функція безпечного множення з перевіркою 64-бітного переповнення
static inline bool check_mul_overflow_u64(uint64_t a, uint64_t b, uint64_t *res) {
    if (a == 0 || b == 0) {
        *res = 0;
        return false;
    }
    if (a > UINT64_MAX / b) {
        return true; // Переповнення
    }
    *res = a * b;
    return false;
}

// Пошук фундаментального розв'язку x^2 - d*y^2 = 1 мовою C
PellSolutionC solve_pell_c(uint64_t d) {
    PellSolutionC sol = {0, 0, false, false};

    uint64_t a0 = (uint64_t)sqrt((double)d);
    if (a0 * a0 == d) {
        // d є точним квадратом — нетривіальних розв'язків не існує
        return sol;
    }

    uint64_t m = 0;
    uint64_t d_val = 1;
    uint64_t a = a0;

    uint64_t p_prev1 = 1;
    uint64_t p_curr = a0;

    uint64_t q_prev1 = 0;
    uint64_t q_curr = 1;

    while (true) {
        // Перевірка, чи є поточний підхідний дріб розв'язком: p^2 - d*q^2 == 1
        uint64_t p2, dq2, q2;
        bool ov1 = check_mul_overflow_u64(p_curr, p_curr, &p2);
        bool ov2 = check_mul_overflow_u64(q_curr, q_curr, &q2);
        bool ov3 = check_mul_overflow_u64(d, q2, &dq2);

        if (!ov1 && !ov2 && !ov3 && (p2 == 1 + dq2)) {
            sol.x = p_curr;
            sol.y = q_curr;
            sol.found = true;
            return sol;
        }

        // Обчислення наступних коефіцієнтів ланцюгового дробу
        m = d_val * a - m;
        d_val = (d - m * m) / d_val;
        a = (a0 + m) / d_val;

        // Перевірка переповнення при обчисленні p_next = a * p_curr + p_prev1
        uint64_t a_p, a_q;
        if (check_mul_overflow_u64(a, p_curr, &a_p) || check_mul_overflow_u64(a, q_curr, &a_q)) {
            sol.overflow = true;
            return sol;
        }

        if (UINT64_MAX - a_p < p_prev1 || UINT64_MAX - a_q < q_prev1) {
            sol.overflow = true;
            return sol;
        }

        uint64_t p_next = a_p + p_prev1;
        uint64_t q_next = a_q + q_prev1;

        p_prev1 = p_curr;
        p_curr = p_next;

        q_prev1 = q_curr;
        q_curr = q_next;
    }
}

int main(void) {
    uint64_t test_d[] = {2, 3, 5, 7, 13, 61, 67, 109};
    size_t count = sizeof(test_d) / sizeof(test_d[0]);

    for (size_t i = 0; i < count; ++i) {
        uint64_t d = test_d[i];
        PellSolutionC res = solve_pell_c(d);
        if (res.found) {
            printf("d = %3llu: x = %16llu, y = %16llu\n",
                   (unsigned long long)d,
                   (unsigned long long)res.x,
                   (unsigned long long)res.y);
        } else if (res.overflow) {
            printf("d = %3llu: розв'язок перевищує 64-бітне ціле (переповнення)\n",
                   (unsigned long long)d);
        } else {
            printf("d = %3llu: розв'язок відсутній (d є точним квадратом)\n",
                   (unsigned long long)d);
        }
    }
    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <optional>
#include <cmath>
#include <cstdint>
#include <limits>

struct PellSolution {
    std::uint64_t x;
    std::uint64_t y;
};

// Клас розв'язувача рівняння Пелля мовою C++ (RAII, безпечна арифметика, std::optional)
class PellSolver {
public:
    static std::optional<PellSolution> solve(std::uint64_t d) {
        const std::uint64_t a0 = static_cast<std::uint64_t>(std::sqrt(d));
        if (a0 * a0 == d) {
            return std::nullopt; // Параметр d є точним квадратом
        }

        std::uint64_t m = 0;
        std::uint64_t d_val = 1;
        std::uint64_t a = a0;

        std::uint64_t p_prev1 = 1;
        std::uint64_t p_curr = a0;

        std::uint64_t q_prev1 = 0;
        std::uint64_t q_curr = 1;

        while (true) {
            // Безпечна перевірка умови p^2 - d*q^2 == 1
            if (p_curr <= std::numeric_limits<std::uint64_t>::max() / p_curr &&
                q_curr <= std::numeric_limits<std::uint64_t>::max() / q_curr) {
                
                const std::uint64_t p2 = p_curr * p_curr;
                const std::uint64_t q2 = q_curr * q_curr;
                if (q2 <= (std::numeric_limits<std::uint64_t>::max() - 1) / d) {
                    if (p2 == 1 + d * q2) {
                        return PellSolution{p_curr, q_curr};
                    }
                }
            }

            // Обчислення наступного кроку неперервного дробу
            m = d_val * a - m;
            d_val = (d - m * m) / d_val;
            a = (a0 + m) / d_val;

            // Безпечна перевірка переповнення перед множенням та додаванням
            if (a > 0 && (p_curr > (std::numeric_limits<std::uint64_t>::max() - p_prev1) / a ||
                          q_curr > (std::numeric_limits<std::uint64_t>::max() - q_prev1) / a)) {
                return std::nullopt; // Переповнення типу uint64_t (потрібен BigInt)
            }

            const std::uint64_t p_next = a * p_curr + p_prev1;
            const std::uint64_t q_next = a * q_curr + q_prev1;

            p_prev1 = p_curr;
            p_curr = p_next;

            q_prev1 = q_curr;
            q_curr = q_next;
        }
    }
};

int main() {
    const std::vector<std::uint64_t> test_cases = {2, 3, 5, 7, 13, 61, 67, 109};

    for (std::uint64_t d : test_cases) {
        if (auto sol = PellSolver::solve(d)) {
            std::cout << "d = " << d << ": x = " << sol->x << ", y = " << sol->y << '\n';
        } else {
            std::cout << "d = " << d << ": розв'язок перевищує 64 біти або d є квадратом\n";
        }
    }

    return 0;
}
```

## 5. Порівняльний аналіз та альтернативні підходи

У практичному програмуванні існують два основних підходи до розв'язання рівняння Пелля: класичний метод неперервних дробів (реалізований вище) та індійський метод Чукравала.

### 1. Метод неперервних дробів
- **Переваги**: Легко реалізується через лінійні рекурентності, вимагає лише арифметики цілих чисел, володіє передбачуваною кількістю ітерацій.
- **Недоліки**: При великих непарних періодах `k` алгоритм повинен пройти два повних періоди (`2k` кроків) до досягнення розв'язку з `+1`.

### 2. Метод Чукравала
- **Переваги**: Може швидко перескочити через довгі періоди неперервного дробу завдяки оптимізованій мінімізації `|m² - d|`, а також дозволяє одразу отримати розв'язок піднесенням допоміжної трійки до квадрата при досягненні `k = -1, ±2, ±4`.
- **Недоліки**: Вимагає додаткового алгоритму для пошуку оптимального `m` за модулем `|k|` на кожному кроці циклу.

## 6. Оцінка складності та розширення до довгої арифметики

1. **Часова складність**: Кількість ітерацій циклу дорівнює довжині періоду `k` (або `2k`) розкладу `√d` у неперервний дріб. За теоремою Левенгайма та Шанкса, довжина періоду `k` обмежена величиною `O(√d · log d)`. На кожному кроці циклу виконуєтьсяведеначена кількість арифметичних операцій `O(1)`. Отже, часова складність обчислення становить `O(√d · log d)`.
2. **Просторова складність**: Алгоритм вимагає `O(1)` додаткової пам'яті, оскільки на кожному кроці зберігаються лише коефіцієнти двох останніх підхідних дробів (`p_curr`, `p_prev1`, `q_curr`, `q_prev1`).
3. **Інтеграція довгої арифметики (BigInt)**: Для значень `d > 1000` розв'язки швидко виходять за межі 64-бітних реєстрів процесора. У C++ для обчислення таких значень типи `std::uint64_t` легко замінюються на класи `boost::multiprecision::cpp_int` або `mpz_t` з бібліотеки GNU MP (GMP). Довга арифметика дозволяє обчислювати розв'язки з тисячами десяткових знаків без втрати точності. При цьому алгоритмічна структура циклу, математичні формули переходів та логіка перевірки залишків залишаються повністю незмінними.
