# 📋 Інтерфейс та специфікація операцій дерева Фенвіка

Ця вставка містить точну технічну специфікацію структурних контрактів, часової та просторової складності, граничних умов, інваріантів та внутрішньої організації реалізації дерева Фенвіка (Binary Indexed Tree / BIT). Подано порівняльну матрицю з альтернативними структурами даних для інтервальних запитів, інженерні рекомендації з вибору алгоритму, аналіз кеш-локальності та детальний розбір поведінки системи в крайових режимах.

### 1. Контракт інтерфейсу та специфікація фундаментальних операцій

Дерево Фенвіка інкапсулює масив цілих або дробових чисел `A` довжиною `N` та надає логарифмічний доступ до накопичувальних сум та оновлень. Усі операції гарантують строго визначену часову та просторову складність. Нижче наведено розширену специфікацію основних методів структури даних та їхніх математичних гарантій.

#### Детальна специфікація методів та їхніх параметрів

- **Конструктор порожнього виділення `Fenwick(N)`:**
  Створює порожнє дерево Фенвіка ємністю `N` елементів. Виділяє пам'ять під внутрішній масив `T[0..N]` і заповнює його нейтральними елементами `0`.
  - *Часова складність:* `O(N)` для заповнення нулями.
  - *Просторова складність:* `O(N)` у суцільному блоці пам'яті.
  - *Передумови:* Розмір `N` повинен бути додатним цілим числом `N > 0`.При `N = 0` конструктор генерує виняток `std::invalid_argument`.

- **Конструктор лінійної побудови `Fenwick(A)`:**
  Приймає готовий вектор або масив `A` довжиною `N` і будує дерево за один лінійний прохід, проштовхуючи накопичені суми до безпосередніх батьківських вузлів `T[i + LSB(i)] += T[i]`.
  - *Часова складність:* `O(N)` (на відміну від послідовного виклику `add()`, який займає `O(N log N)`).
  - *Просторова складність:* `O(N)`.
  - *Передумови:* Вхідний масив `A` не повинен бути порожнім.

- **Точкове оновлення `add(idx, val)`:**
  Додає арифметичне значення `val` до елемента вихідного масиву `A[idx]`. Всередині методу відбувається перехід від 0-індексації користувача до внутрішньої 1-індексації `i = idx + 1` та підйом по батьківських вузлах `i += i & (-i)`.
  - *Часова складність:* `O(log N)` у найгіршому та середньому випадках. Кількість ітерацій циклу не перевищує `⌊log_2 N⌋ + 1`.
  - *Просторова складність:* `O(1)` додаткової пам'яті.
  - *Передумови:* Індекс повинен знаходитися у діапазоні `0 ≤ idx < N`. При порушенні меж генерується виняток `std::out_of_range`.

- **Обчислення префіксної суми `query_prefix(idx)`:**
  Повертає накопичувальну суму елементів `A[0] + A[1] + ... + A[idx]`. Внутрішній обхід спускається по ортогональних двійкових півінтервалах `i -= i & (-i)`.
  - *Часова складність:* `O(log N)`. Кількість доданок дорівнює вазі Геммінга `popcount(idx + 1)`.
  - *Просторова складність:* `O(1)`.
  - *Передумови:* `0 ≤ idx < N`.

- **Запит суми на відрізку `query_range(left, right)`:**
  Обчислює суму елементів `A[left] + A[left+1] + ... + A[right]` як різницю двох префіксних сум `query_prefix(right) - query_prefix(left - 1)`.
  - *Часова складність:* `O(log N)`. Виконується строго дві процедури префіксного обходу.
  - *Просторова складність:* `O(1)`.
  - *Передумови:* `0 ≤ left ≤ right < N`. Якщо `left == 0`, замість віднімання одразу повертається `query_prefix(right)`.

- **Двійковий підйом за сумою `lower_bound(target_sum)`:**
  Знаходить найменший 0-based індекс `idx`, для якого `query_prefix(idx) ≥ target_sum`.Використовує метод двійкового проходу по степенях двійки від `max_pow ≤ N` до `1`.
  - *Часова складність:* `O(log N)`.
  - *Просторова складність:* `O(1)`.
  - *Передумови:* Усі елементи вихідного масиву мають бути неот'ємними `A[k] ≥ 0`, що забезпечує монотонне зростання префіксних сум.

### 2. Внутрішня організація та інваріанти структури

Внутрішній стан дерева Фенвіка підтримується за допомогою трьох фундаментальних інваріантів, які забезпечують коректність виконання всіх алгоритмічних операцій.

#### Інваріант покриття вузла `T[i]`

Для кожного індексу `i ∈ [1, N]` у внутрішній 1-індексованій системі числення значення комірки `T[i]` строго відповідає сумі елементів первинного масиву `A`:

```
T[i] = ∑_{k = i - (i & -i) + 1}^i A[k]
```

Цей інваріант гарантує, що кожен вузол `T[i]` відповідає за півінтервал довжиною `LSB(i) = i & (-i)`, який закінчується в позиції `i`. При виконані оновлення `add(idx, val)` інваріант відновлюється для всіх покриваючих вузлів вищих рівнів за логарифмічний час.

#### Невід'ємність та монотонність (для двійкового підйому)

Операція `lower_bound(target_sum)` спирається на інваріант монотонного зростання префіксних сум. Якщо вихідний масив містить від'ємні елементи, послідовність префіксів перестає бути монотонною, і прямий двійковий підйом може повернути хибний індекс.

Формально умовою застосування двійкового підйому є:

```
∀ k ∈ [1, N-1]:  A[k] ≥ 0  ⇒  query_prefix(k - 1) ≤ query_prefix(k)
```

Якщо масив містить від'ємні значення, для пошуку елемента необхідно використовувати подвійний бінарний пошук поверху префіксних запитів, що збільшує складність до `O(log^2 N)`.

#### Пам'ятковий профіль та аналіз кеш-локальності

Дерево Фенвіка володіє унікальними показниками ефективності використання оперативної пам'яті комп'ютера:

- **Фізичний розмір масиву:** Для зберігання `N` елементів виділяється строго `(N + 1) · sizeof(T)` байтів пам'яті. Усі дані розміщуються в єдиному суцільному блоці (контигуальний вектор).
- **Відсутність оверхеду вказівників:** На відміну від дерев відрізків чи бінарних дерев пошуку, дерево Фенвіка не витрачає жодного байта на збереження вказівників `left`, `right`, `parent` або додаткових колірних міток балансування. Накладні витрати пам'яті дорівнюють нулю (`0%`).
- **Локальність кешу (Cache Locality):** Оскільки елементи розміщені послідовно у пам'яті, при обході префіксних сум процесорний кеш L1/L2 завантажує суміжні комірки лініями кешу (Cache Lines по 64 байти). Це зводить кількість промахів кешу до абсолютного мінімуму, що забезпечує у 2–4 рази вищу реальну швидкодію порівняно з деревами відрізків.

### 3. Порівняльна матриця та критерії вибору структур даних

Для обґрунтованого вибору структури даних під конкретне інженерне завдання нижче наведено порівняльний аналіз п'яти алгоритмічних підходів обробки інтервальних сум.

| Структура даних | Побудова | Точкове оновлення | Запит префіксу / відрізка | Інтервальне оновлення (Range Update) | Пам'ятковий оверхед | Складність реалізації |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Плоский масив** | `O(1)` | `O(1)` | `O(N)` | `O(N)` | `0` (вже в пам'яті) | Тривіальна |
| **Префіксний масив** | `O(N)` | `O(N)` | `O(1)` | `O(N)` | `+N` | Тривіальна |
| **Різницевий масив** | `O(N)` | `O(N)` | `O(N)` | `O(1)` (для точкового запиту) | `+N` | Проста |
| **Дерево Фенвіка (BIT)** | `O(N)` | `O(log N)` | `O(log N)` | `O(log N)` (двохмасивне) | `+N` | Винятково проста (3–5 рядків) |
| **Дерево відрізків (Segment Tree)** | `O(N)` | `O(log N)` | `O(log N)` | `O(log N)` (Lazy Propagation) | `+4N` | Середня / Складна |
| **Декартове дерево (Treap / Splay)** | `O(N log N)` | `O(log N)` | `O(log N)` | `O(log N)` (з розщепленням) | `+6N` (вказівники + пріоритети) | Дуже складна |

#### Інженерні правила прийняття рішень

1. **Обирайте Дерево Фенвіка, якщо:**
   - Алгебраїчна операція утворює абелеву групу (існує обернена операція: додавання/віднімання, XOR, множення за модулем).
   - Задача вимагає масового оброблення мільйонів елементів у реальному часі з обмеженим обсягом пам'яті.
   - Потрібна проста, компактна реалізація без складних багів та динамічного виділення пам'яті.

2. **Відмовляйтеся від Дерева Фенвіка на користь Дерева Відрізків, якщо:**
   - Операція є незворотною напівгруповою (пошук мінімуму `min`, максимуму `max`, найбільшого спільного дільника `GCD`).
   - Потрібно виконувати складні інтервальні присвоєння `A[l..r] = v` з лінивим проштовхуванням (Lazy Propagation).
   - Необхідно підтримувати персистентність (збереження попередніх версій структури даних).

### 4. Граничні випадки, винятки та протокол обробки помилок

При практичній експлуатації дерева Фенвіка у високонавантажених сервісах необхідно суворо обробляти чотири критичні крайові ситуації:

#### 1. Нульовий індекс у 1-індексованій арифметиці

Якщо до внутрішньої процедури обходу передати 1-індекс `i = 0`, операція `i & (-i)` поверне `0`. В результаті виклики `i += 0` або `i -= 0` призводять до нескінченного циклу (Infinite Loop) та зависання потоку виконання.
- *Протокол захисту:* Зовнішні класи-обгортки виконують виклики лише для 0-індексованих аргументів `0 ≤ idx < N` та транслюють їх у `i = idx + 1`. Внутрішній цикл сумування містить строгу умову зупинки `i > 0`.

#### 2. Переповнення цілочисельного типу (Integer Overflow)

При підсумовуванні великої кількості елементів (`N = 10^6`, значення `A[i] = 10^9`) префіксна сума виходить за межі діапазону 32-бітного знакового цілого числа `2^31 - 1 ≈ 2.14 · 10^9`.
- *Протокол захисту:* Усі сумувальні змінні та елементи масиву `T` повинні мати тип `long long` у C/C++, `int64_t` у POSIX або `std::int64_t`.

#### 3. Вихід за межі масиву (Out of Bounds)

При виконанні точкового оновлення `add(idx, val)` індекс `i` піднімається догори `i += LSB(i)`. Перевірка умови `i ≤ N` є строго обов'язковою на кожній ітерації циклу для запобігання пошкодженню пам'яті (buffer overflow).

#### 4. Некоректні межі інтервальних запитів

При виконанні виклику `query_range(left, right)` з параметрами `left > right` або `right ≥ N` система може повернути хибний результат чи згенерувати виняток.
- *Протокол захисту:* Метод перевіряє гарантію `0 ≤ left ≤ right < N` і при виявленні некоректного інтервалу викидає виняток `std::out_of_range`.
