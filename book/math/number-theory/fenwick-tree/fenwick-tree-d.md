Уявіть високонавантажений аналітичний рушій торговельного майданчика, потоковий обробник фінансових транзакцій або серверну платформу мережевої гри з 100 000 активних гравців, яка обробляє понад 500 000 подій щосекунди. Система повинна в режимі реального часу виконувати дві принципово протилежні за своєю обчислювальною природою операції: по-перше, постійно оновлювати поточні бали чи рейтинги окремих користувачів при виконанні дій (наприклад, додавати бали за виконані транзакції), і по-друге, миттєво відповідати на аналітичні запити — яка сумарна кількість балів набрана всіма гравцями з 1200-го по 45 000-й рейтинг у таблиці лідерів.

Якщо для збереження даних використовувати звичайний плоский масив елементів, то кожен новий запит підсумовування вимагатиме послідовного лінійного обходу `O(N)`. При довжині масиву `N = 100 000` один запит вимагає до 100 000 послідовних операцій додавання. При навантаженні у 500 000 аналітичних запитів на секунду обчислювальному ядру процесора доведеться виконувати до `5 · 10¹⁰` арифметичних операцій щосекунди. Пам'ять та процесорні ядра миттєво застрягнуть у безкінечних обходах масиву, а система втратить здатність реагувати на нові події.

Якщо ж спробувати оптимізувати обчислення за допомогою статичного масиву префіксних сум, то запит суми на довільному відрізку буде виконуватися за один такт процесора `O(1)` шляхом віднімання двох накопичених сум. Проте виникне обчислювальна катастрофа на операції оновлення даних: будь-яка зміна балів одного гравця вимагатиме додавання різниці до всіх наступних елементів префіксного масиву. Оновлення елемента вироджується в лінійну модифікацію `O(N)`, і при високій частоті змінення даних система знову застрягне у постійних перебудовах префіксного масиву.

Виникає фундаментальний конфлікт складнійстей:
1. **Статичний масив:** оновлення `O(1)`, запит суми `O(N)`.
2. **Префіксний масив:** запит суми `O(1)`, оновлення `O(N)`.

Щоб зламати цю бачу обчислювальної складності, потрібна структура даних, яка здатна виконувати **і точкове оновлення, і інтервальний запит суми за логарифмічний час `O(log N)`**, не витрачаючи при цьому додаткової пам'яті на вказівники, динамічні вузли чи складну деревну графіку.

Такою структурою даних є **дерево Фенвіка** (або двійкове індексоване дерево, Binary Indexed Tree / BIT). Вона розбиває масив на ортогональну систему двоічних півінтервалів, дозволяючи оновлювати дані та обчислювати префіксні суми за `O(log N)` кроків із нульовим пам'ятковим оверхедом та максимальною швидкодією у кеші процесора.

### Механіка побітового покриття та структура дерева

Головна ідея дерева Фенвіка полягає в тому, щоб зберігати часткові суми елементів у суцільному масиві `T[1..N]` тієї ж довжини, що й вихідний масив `A[1..N]`. На відміну від явних дерев відрізків, де створюються окремі динамічні вузли з вказівниками на лівого й правого сина (`left`, `right`), дерево Фенвіка не використовує жодного вказівника чи мітки балансування. Ієрархія зв'язків між вузлами повністю закладена у двійковому записі індексів елементів.

#### Чому використовується 1-індексація

Дерево Фенвіка фундаментально спирається на двійкові розряди позицій. Оскільки індекс `0` у двійковій системі містить лише нулі (`0000_2`), для нього неможливо виділити наймолодший одиничний біт. Тому математична модель дерева Фенвіка строго вимагає **1-індексації** елементів (`1 ≤ i ≤ N`). Індекс `0` зарезервований як фіктивний нульовий префікс, що відповідає порожній сумі порожнього підмножини.

#### Інтервали покриття вузлів

Кожен елемент масиву дерева `T[i]` відповідає за підсумовування елементів вихідного масиву `A` на лівовідкритому півінтервалі `(i - LSB(i), i]`:

```
T[i] = A[i - LSB(i) + 1] + A[i - LSB(i) + 2] + ... + A[i]
```

Довжина цього інтервалу строго дорівнює величині **LSB (Least Significant Bit)** — наймолодшому встановленому біту в двійковому записі числа `i`.

Простежимо, які саме інтервали покривають вузли для масиву з `N = 8` елементів:

- `i = 1 (0001_2)`: LSB = 1. Вузол `T[1]` покриває півінтервал `(0, 1]`, тобто містить лише `A[1]`.
- `i = 2 (0010_2)`: LSB = 2. Вузол `T[2]` покриває півінтервал `(0, 2]`, тобто містить суму `A[1] + A[2]`.
- `i = 3 (0011_2)`: LSB = 1. Вузол `T[3]` покриває півінтервал `(2, 3]`, тобто містить лише `A[3]`.
- `i = 4 (0100_2)`: LSB = 4. Вузол `T[4]` покриває півінтервал `(0, 4]`, тобто містить суму `A[1] + A[2] + A[3] + A[4]`.
- `i = 5 (0101_2)`: LSB = 1. Вузол `T[5]` покриває півінтервал `(4, 5]`, тобто містить лише `A[5]`.
- `i = 6 (0110_2)`: LSB = 2. Вузол `T[6]` покриває півінтервал `(4, 6]`, тобто містить суму `A[5] + A[6]`.
- `i = 7 (0111_2)`: LSB = 1. Вузол `T[7]` покриває півінтервал `(6, 7]`, тобто містить лише `A[7]`.
- `i = 8 (1000_2)`: LSB = 8. Вузол `T[8]` покриває півінтервал `(0, 8]`, тобто містить суму всіх 8 елементів.

![Ієрархія покриття інтервалів у дереві Фенвіка](/book/math/number-theory/fenwick-tree/img/tree-structure.svg)
*Ієрархічна структура покриття півінтервалів у дереві Фенвіка для N = 8. Довжина інтервалу кожного вузла T[i] дорівнює LSB(i).*

#### Алгебра виділення наймолодшого біта i & (-i)

Найдивовижнішим елементом дерева Фенвіка є те, як саме обчислюється величина `LSB(i)`. У комп'ютерній арифметиці із використанням доповняльного коду (Two's Complement) від'ємне число `-i` отримують інвертуванням усіх бітів `~i` з додаванням арифметичної одиниці: `-i = (~i) + 1`.

Якщо виконати побітову операцію logical AND між числом `i` та його запереченням `-i`, всі старші біти скорочуються, а в результаті залишається єдиний біт — наймолодша одиниця числа `i`.

```
i & (-i) = LSB(i) = 2^r
```

Проілюструємо це на числовому прикладі для індексу `i = 12`:

```
i        = 12  =  0000 1100_2
~i             =  1111 0011_2
-i       = ~i+1 = 1111 0100_2

i & (-i)       =  0000 0100_2  =  4
```

Для числа `12` виділений біт дорівнює `4`. Це означає, що вузол `T[12]` покриває інтервал довжиною 4 елементи: від `A[9]` до `A[12]`.

![Алгебра побітового виділення LSB: i & (-i)](/book/math/number-theory/fenwick-tree/img/lsb-decomposition.svg)
*Механіка побітового виділення LSB за допомогою доповняльного коду -i = (~i) + 1. Операція i & (-i) виділяє наймолодший 1-біт за один такт ALU.*

Детальний математичний доказ тотожності `LSB(i)` та властивості ортогональних розкладів наведено у вставці [🧮 Математичний апарат дерева Фенвіка](book:math/fenwick-tree/math-fenwick-algebra.md).

### Запити накопичувальної суми та точкове оновлення

Завдяки структурі покриття півінтервалів, як обчислення префіксної суми, так і точкове оновлення елемента зводяться до обходу коротких ланцюжків індексів у масиві.

#### Обчислення префіксної суми

Щоб знайти префіксну суму `Pref(i) = A[1] + A[2] + ... + A[i]`, необхідно розкласти інтервал `(0, i]` у суму покриваючих півінтервалів.

Алгоритм обчислення префіксної суми:
1. Ініціалізувати змінну-накопичувач `sum = 0`.
2. Поки `i > 0`:
   - Додати до суми значення поточного вузла: `sum += T[i]`.
   - Перейти до лівого сусіднього інтервалу, віднявши наймолодший біт: `i = i - (i & -i)`.
3. Повернути `sum`.

Простежимо обчислення префіксної суми `Pref(7)` для масиву `A = [3, 1, 4, 1, 5, 9, 2, 6]` довжиною `N = 8`:
- Крок 1: `i = 7 (0111_2)`. `LSB(7) = 1`. Додаємо `T[7] = 2` (інтервал `(6, 7]`). Зсув: `i = 7 - 1 = 6`.
- Крок 2: `i = 6 (0110_2)`. `LSB(6) = 2`. Додаємо `T[6] = 14` (інтервал `(4, 6]`). Зсув: `i = 6 - 2 = 4`.
- Крок 3: `i = 4 (0100_2)`. `LSB(4) = 4`. Додаємо `T[4] = 9` (інтервал `(0, 4]`). Зсув: `i = 4 - 4 = 0`.
- Крок 4: `i = 0`. Зупинка!

Підсумкова сума: `Pref(7) = T[7] + T[6] + T[4] = 2 + 14 + 9 = 25`. 
Перевірка прямим додаванням дає той самий результат: `3 + 1 + 4 + 1 + 5 + 9 + 2 = 25`. Ми обчислили суму 7 елементів всього за 3 кроки! Загальна кількість ітерацій дорівнює кількості одиничних бітів у двійковому записі числа `i`, що не перевищує `⌊log_2 N⌋ + 1`.

Щоб знайти суму елементів на довільному відрізку `A[l..r]`, використовується різниця двох префіксних сум:

```
Sum(l..r) = Pref(r) − Pref(l − 1)
```

Наприклад, сума на відрізку `A[3..7]` обчислюється як `Pref(7) - Pref(2) = 25 - 4 = 21`. Перевірка: `4 + 1 + 5 + 9 + 2 = 21`.

#### Точкове оновлення елемента

При зміні значення елемента `A[idx]` на величину `val` (операція `A[idx] += val`) необхідно оновити значення всіх вузлів `T[j]`, інтервали покриття яких містять позицію `idx`.

Алгоритм точкового оновлення:
1. Почати з індексу `i = idx`.
2. Поки `i ≤ N`:
   - Збільшити значення вузла: `T[i] += val`.
   - Перейти до батьківського вузла вищого рівня, додавши наймолодший біт: `i = i + (i & -i)`.

Простежимо оновлення елемента `A[3]` на величину `+v` для `N = 8`:
- Крок 1: `i = 3 (0011_2)`. `LSB(3) = 1`. Оновлюємо `T[3] += v`. Зсув: `i = 3 + 1 = 4`.
- Крок 2: `i = 4 (0100_2)`. `LSB(4) = 4`. Оновлюємо `T[4] += v`. Зсув: `i = 4 + 4 = 8`.
- Крок 3: `i = 8 (1000_2)`. `LSB(8) = 8`. Оновлюємо `T[8] += v`. Зсув: `i = 8 + 8 = 16 > N`.
- Крок 4: `i = 16 > 8`. Зупинка!

Оновлення елемента `A[3]` модифікувало лише 3 вузли дерева: `T[3]`, `T[4]` та `T[8]`.

![Двонаправлений обхід дерева Фенвіка: Запит vs Оновлення](/book/math/number-theory/fenwick-tree/img/update-query-paths.svg)
*Порівняння шляхів обходу дерева Фенвіка. Запит префіксної суми віднімає LSB(i) для зсуву вліво; точкове оновлення додає LSB(i) для підйому до батьківських вузлів.*

Історичний контекст створення цієї структури Пітером Фенвіком у 1994 році для задач арифметичного кодування висвітлено у вставці [📜 Історія винайдення дерева Фенвіка](book:math/fenwick-tree/hist-fenwick-origin.md).

### Побудова дерева за лінійний час O(N)

Найпростіший спосіб побудувати дерево Фенвіка з готового масиву `A` довжиною `N` — це створити порожнє дерево й виконати `N` послідовних викликів процедури `add()`. Оскільки кожен виклик займає `O(log N)`, сумарний час побудови складе `O(N log N)`.

Проте існує елегантний алгоритм побудови дерева Фенвіка за строго **лінійний час `O(N)`**.

Ідея полягає в тому, що на самому початку ми копіюємо масив `A` у масив `T[1..N]`. Після цього проходимо індексами від `i = 1` до `N`. Кожен вузол `T[i]` вже містить суму елементів свого власного покриття. Щоб передати цю суму вище по ієрархії, достатньо додати значення `T[i]` до його безпосереднього батьківського вузла `parent = i + (i & -i)`:

```
якщо i + LSB(i) ≤ N:
    T[i + LSB(i)] += T[i]
```

Оскільки кожен вузол передає свою накопичену суму батькові рівно один раз під час лінійного проходу, всі вищі вузли рекурсивно отримають правильні суми за `N` ітерацій.

Простежимо лінійну побудову для масиву `A = [3, 1, 4, 1, 5, 9, 2, 6]`:
- `i = 1`: `T[1] = 3`. `parent = 1 + 1 = 2`. `T[2] += 3` (`T[2]` стає `1 + 3 = 4`).
- `i = 2`: `T[2] = 4`. `parent = 2 + 2 = 4`. `T[4] += 4` (`T[4]` стає `1 + 4 = 5`).
- `i = 3`: `T[3] = 4`. `parent = 3 + 1 = 4`. `T[4] += 4` (`T[4]` стає `5 + 4 = 9`).
- `i = 4`: `T[4] = 9`. `parent = 4 + 4 = 8`. `T[8] += 9` (`T[8]` стає `6 + 9 = 15`).
- `i = 5`: `T[5] = 5`. `parent = 5 + 1 = 6`. `T[6] += 5` (`T[6]` стає `9 + 5 = 14`).
- `i = 6`: `T[6] = 14`. `parent = 6 + 2 = 8`. `T[8] += 14` (`T[8]` стає `15 + 14 = 29`).
- `i = 7`: `T[7] = 2`. `parent = 7 + 1 = 8`. `T[8] += 2` (`T[8]` стає `29 + 2 = 31`).
- `i = 8`: `T[8] = 31`. `parent = 8 + 8 = 16 > 8`. Без дій.

Результат побудови повністю збігається з точним інваріантом дерева Фенвіка за `N = 8` кроків.

### Двоїстість та розширення: інтервальні операції та 2D структури

Завдяки лінійності оператора сумування, дерево Фенвіка можна застосовувати не лише для точкових оновлень, а й для операцій на цілих відрізках.

#### Інтервальне оновлення та точковий запит (Range Update, Point Query)

Якщо задача вимагає додавати значення `v` до всіх елементів на відрізку `A[l..r] += v`, а запитувати лише значення окремого елемента `A[i]`, можна використати концепцію **різницевого масиву** (Difference Array) `D[i] = A[i] − A[i-1]`.

Тоді сам елемент `A[i]` дорівнює префіксній сумі різницевого масиву: `A[i] = D[1] + D[2] + ... + D[i]`.

Оновлення відрізка `A[l..r] += v` змінює лише два елементи в масиві `D`:
- `D[l] += v`
- `D[r + 1] -= v`

Зберігаючи різницевий масив `D` у дереві Фенвіка, ми виконуємо інтервальне оновлення за дві точкові операції `O(log N)`, а точковий запит `A[i]` — за один префіксний запит `O(log N)`.

#### Інтервальне оновлення та інтервальний запит (Range Update, Range Query)

Найвищим ступенем двоїстості є підтримка і оновлень відрізка `A[l..r] += v`, і запитів суми відрізка `Sum(l..r)` за логарифмічний час `O(log N)`.

Математичне розгортання подвійної суми різницевого масиву дає наступну формулу для префіксної суми `Pref(p)`:

```
Pref(p) = (p + 1) · ∑_{j=1}^p D[j]  −  ∑_{j=1}^p (j − 1) · D[j]
```

Для підтримки цієї формули використовуються **два паралельні дерева Фенвіка**:
1. Дерево `T1` зберігає значення `D[j]`.
2. Дерево `T2` зберігає зважені значення `(j − 1) · D[j]`.

![Двохмасивна структура для оновлення та запиту відрізка](/book/math/number-theory/fenwick-tree/img/range-update-dual.svg)
*Архітектура двохмасивного дерева Фенвіка для інтервальних оновлень та інтервальних запитів. Дерево T1 зберігає різницевий масив, а T2 — зважені компенсації.*

#### Двовимірне дерево Фенвіка (2D Fenwick Tree)

Для роботи з матрицями `A[1..N][1..M]` дерево Фенвіка розширюється на два виміри. Вузол `T[i][j]` зберігає суму елементів у прямокутнику розміром `LSB(i) × LSB(j)`.

Точкове оновлення та прямокутний запит виконуються за допомогою двох вкладених циклів по індексах `i` та `j` за час `O(log N · log M)`. Для обчислення суми в довільному прямокутнику `(r1, c1)..(r2, c2)` застосовується принцип включень-виключень:

```
Sum2D = Pref2D(r2, c2) − Pref2D(r1-1, c2) − Pref2D(r2, c1-1) + Pref2D(r1-1, c1-1)
```

Повний вихідний код реалізацій 1D, 2D та двохмасивних структур мовами C та C++ подано у вставці [⚙️ Реалізація дерева Фенвіка](book:math/fenwick-tree/proj-fenwick-implementation.md).

### Пошук елемента за накопиченою сумою: двійковий підйом

Якщо всі елементи масиву `A` є невід'ємними (`A[i] ≥ 0`), префіксні суми формують монотонно зростаючу послідовність. У цьому випадку часто виникає задача: знайти найменший індекс `idx`, для якого префіксна сума досягає або перевищує задане значення `S` (`Pref(idx) ≥ S`). Таку операцію називають знаходженням `k`-го елемента або `lower_bound`.

Наивний бінарний пошук по індексах від `1` до `N` робить `log N` кроків, на кожному з яких викликає `query_prefix()`, що дає загальну складність `O(log² N)`.

Проте, використовуючи двійкову структуру самого дерева Фенвіка, цю задачу можна розв'язати за один прохід за **`O(log N)`** за допомогою алгоритму **двійкового підйому (Binary Lifting)**.

Алгоритм випробовує кроки степенями двійки `len = max_pow, ..., 1`:
```cpp
std::size_t idx = 0;
T current_sum = 0;

for (std::size_t len = max_pow; len > 0; len >>= 1) {
    if (idx + len <= N && current_sum + T[idx + len] < target_sum) {
        idx += len;
        current_sum += T[idx];
    }
}
return idx + 1; // 1-based індекс шуканого елемента
```

Оскільки кожна комірка `T[idx + len]` вже містить суму блоку довжиною `len`, ми перевіряємо можливість стрибка за один такт без додаткових префіксних запитів.

### Порівняльний аналіз та інженерна специфікація

Щоб зрозуміти місце дерева Фенвіка в арсеналі розробника, порівняємо його з альтернативними структурами даних для інтервальних запитів:

| Властивість / Структура | Дерево Фенвіка (BIT) | Дерево відрізків (Segment Tree) | Плоский префіксний масив |
| :--- | :--- | :--- | :--- |
| **Час побудови** | `O(N)` | `O(N)` | `O(N)` |
| **Точкове оновлення** | `O(log N)` | `O(log N)` | `O(N)` |
| **Запит на відрізку** | `O(log N)` | `O(log N)` | `O(1)` |
| **Пам'ятковий оверхед** | **`0%`** (`N` елементів) | `+300%` (`4N` елементів) | `0%` (`N` елементів) |
| **Вказівниковий оверхед** | **Ні (0 вказівників)** | Опціонально (динамічні вузли) | Ні |
| **Кеш-локальність** | **Максимальна (L1/L2 vector)** | Низька / Середня | Максимальна |
| **Обмеження операцій** | Потрібна обернена операція (група) | Будь-яка асоціативна (напівгрупа: min/max) | Потрібна обернена операція |

> 🔧 **Навіщо це.** Дерево Фенвіка — це головний вибір для високонавантажених обчислювальних систем, де важлива кожна наносекунда та кожен кілобайт пам'яті. У високочастотному трейдингу (HFT) воно обчислює ковзний обсяг торговців; у рушіях баз даних підтримує лічильники частот для опису семантики запитів; у розробці ігор керує таблицями лідерів та розподілом ресурсів у реальному часі.

Повну специфікацію API, параметри складності та детальний розбір граничних режимів наведено у вставці [📋 Інтерфейс та специфікація операцій дерева Фенвіка](book:math/fenwick-tree/api-fenwick-interface.md).
