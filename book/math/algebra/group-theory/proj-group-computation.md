# ⚙️ Група як програма: побудувати скінченну групу й перевірити Лагранжа

Теорема Лагранжа стверджує, що порядок підгрупи ділить порядок групи; тут ми не приймаємо це на віру, а змушуємо машину побудувати живу групу з кількох твірних, порахувати порядок кожного елемента, розкласти групу на суміжні класи й на власні очі перевірити рівність |G| = [G : H] · |H|. Виходить пів сотні рядків — і найцікавіше в них те, що **рушій не знає, з якою саме групою має справу**: той самий код замикає симетрії трикутника й оборотні лишки за модулем 7, бо нічого, крім операції, від елементів не потребує.

Саме це й перевіряє програму на чесність. Якщо теорія каже, що глибокий факт випливає з чотирьох аксіом і ні з чого більше, то й код, який спирається лише на операцію, зобов'язаний спрацювати всюди, де ці аксіоми виконано. Напишемо його раз — і запустимо на двох зовсім різних групах, не змінивши жодного рядка ядра.

### Головна ідея: писати про «скелет», а не про приклад

Абстракція групи окупається тим, що доведене про групу взагалі спрацьовує в кожному конкретному випадку. У коді ця думка стає буквальною вимогою: функції, що рахують порядок, замикання чи суміжні класи, **не мають заглядати всередину елемента**. Вони приймають операцію `op` окремим аргументом і викликають лише її. Тоді елементом може бути перестановка, ціле число, матриця — рушію байдуже.

Щоб це стало можливим, від елемента потрібно рівно дві речі: його можна порівнювати на рівність і класти в множину. Усе інше — множення, обернення, порядок — рушій добуде сам з операції. З цієї скупої вимоги й почнімо, бо саме тут ховається перша й найпідступніша пастка.

### Елемент мусить бути порівнюваним і хешованим

Ми складатимемо елементи в множини: групу як множину, суміжний клас як множину, набір уже знайдених елементів. А множина працює тоді й лише тоді, коли елемент **хешований** і два однакові елементи мають буквально однакове представлення. Це не технічна дрібниця — це те саме «канонічне представлення», без якого порівняння елементів бреше.

Візьмімо симетрії трикутника. Кожну зручно записати як **перестановку** — куди йде кожна з трьох вершин. Занумеруймо вершини 0, 1, 2 і представмо симетрію кортежем образів: на позиції `i` стоїть номер, у який переходить вершина `i`. Тотожність — це `(0, 1, 2)`, поворот `0→1→2→0` — це `(1, 2, 0)`.

Чому саме **кортеж** (незмінний), а не список? Список у множину не покласти — він не хешований; ба гірше, порівнювати структуру, яку можна тихо змінити на місці, — джерело помилок, що не відтворюються. Кортеж хешований, незмінний, і два рівні кортежі рівні буквально. Це і є канонічна форма для перестановки: жодних двох різних записів того самого елемента.

```python
def pmul(g, h):                 # g після h:  (g·h)[i] = g[h[i]]
    return tuple(g[h[i]] for i in range(len(g)))

def pinv(g):                    # обернена перестановка
    inv = [0] * len(g)
    for i, gi in enumerate(g):
        inv[gi] = i
    return tuple(inv)

e3 = (0, 1, 2)                  # тотожність
r  = (1, 2, 0)                  # поворот  0→1→2→0
s1 = (0, 2, 1)                  # відбиття, що лишає вершину 0 на місці
```

Один рядок в `pmul` вимагає обережності — **домовленість про порядок**. Ми кладемо `g·h` як «спершу h, потім g», тобто `(g·h)(i) = g(h(i))`, як у композиції функцій справа наліво. Домовленість вільна, але, обравши, її треба тримати скрізь: перевернете її подумки в одному місці — і обернені елементи та суміжні класи почнуть тихо виходити неправильними, а програма ні на що не поскаржиться, бо синтаксично все чинне.

> 🔧 **Навіщо це.** Хибне представлення отруює все, що стоїть далі. Якби ми взяли елементом матрицю повороту з дробовими числами, рівність `A == B` залежала б від похибки округлення, і два «однакові» повороти опинилися б у множині як різні — розмір групи роздувся б, а Лагранж «не зійшовся» б не через математику, а через представлення. Тому елемент завжди беруть у точній, канонічній, хешованій формі: перестановку — кортежем цілих, лишок — цілим, і ніяк інакше.

### Побудувати всю групу з твірних

Групу рідко задають повним списком — зазвичай дають кілька **твірних** і кажуть: бери їх, перемножуй як завгодно, а групою буде все, що з цього вийде. Формально група, породжена набором S, — це найменша множина, що містить S і замкнена щодо операції. Обчислити її можна прямо за означенням: множимо все, що вже маємо, на все, що маємо; кожен новий добуток кидаємо назад у скарбничку; повторюємо, доки множення перестане давати щось нове. Щойно перестало — множина замкнена, а замкнена множина з оберненими та нейтральним і є група.

![Побудова групи з двох твірних: множимо всі пари, нові добутки додаємо, аж поки множення не перестане виводити за межі — тоді множина замкнена](/book/math/algebra/group-theory/img/group-closure.svg)
*Замикання за операцією. З двох твірних r та s₁ добутки поступово дають r², s₂, s₃ та e — і на шостому елементі множення вже нікуди не веде: група D₃ побудована, |G| = 6.*

```python
def closure(gens, op):
    """Замкнути твірні за операцією op — уся породжена група."""
    G = set(gens)
    frontier = list(gens)          # елементи, ще не перемножені з усіма
    while frontier:
        fresh = []
        for a in list(G):
            for b in frontier:
                for x in (op(a, b), op(b, a)):
                    if x not in G:
                        G.add(x)
                        fresh.append(x)
        frontier = fresh
    return G
```

Множина `G` служить двом цілям одразу: це і відповідь, і журнал уже баченого — перевірка `x not in G` не дає кружляти по тих самих елементах вічно. Ось як із двох твірних виростає D₃:

```
>>> D3 = closure([r, s1], pmul)
>>> len(D3)
6
```

Шість — рівно шість симетрій трикутника, здобутих із двох рухів: повороту й одного відбиття. Ту саму техніку так само добре застосуєш до будь-якої скінченної групи; поки група невелика, наївне замикання просто працює.

### Порядок елемента й циклічна підгрупа — без жодної формули

Порядок елемента g — це найменше m > 0, для якого gᵐ = e. Означення само підказує алгоритм: множ g на себе й лічи кроки, доки не впадеш у нейтральний. У скінченній групі це станеться неодмінно.

```python
def order(g, op, e):
    x, m = g, 1
    while x != e:
        x = op(x, g)
        m += 1
    return m

def cyclic(g, op, e):              # ⟨g⟩ — усі степені g
    sub, x = {e}, g
    while x != e:
        sub.add(x)
        x = op(x, g)
    return sub
```

Тут ховається маленька, але промовиста перлина. Обернений елемент можна знайти **самою лише операцією**, без жодної спеціальної формули: у скінченній групі g⁻¹ = g^(m−1), де m — порядок g, адже g · g^(m−1) = gᵐ = e. Рушій, який уміє тільки множити, уміє й обертати:

```python
def inverse(g, op, e):
    prev, x = e, g
    while x != e:
        prev, x = x, op(x, g)      # prev завжди на крок позаду x
    return prev                    # останній степінь перед e — це g⁻¹
```

Це не трюк заради ефекту, а сам дух абстракції: обернення — не окрема здатність елемента, а наслідок скінченності й операції. Порахуймо порядки всіх шести елементів D₃:

```
>>> sorted(order(g, pmul, e3) for g in D3)
[1, 2, 2, 2, 3, 3]
```

Тотожність має порядок 1, три відбиття — по 2, два повороти — по 3. І жоден порядок не дорівнює 4 чи 5 — усі вони дільники шістки. Це поки що лише спостереження; за мить Лагранж перетворить його на закон.

### Ліві суміжні класи й пастка дедуплікації

Лівий суміжний клас — це підгрупа H, зсунута елементом g: gH = {g·h : h ∈ H}. Щоб розкласти групу, напрошується прямий хід: узяти gH для **кожного** g групи. Але тоді той самий клас вигулькне багато разів — стільки, скільки в ньому елементів, бо будь-який його мешканець породжує рівно той самий зсув. Отже класи треба **здедуплювати**, і тут криється друга пастка: порівнювати їх треба **як множини за належністю**, а не за представником.

Спокуса — позначити клас його представником g і рахувати різні g. Хибно: `s₁H` і `s₂H` — це та сама множина відбиттів, дарма що представники різні. Правильний ключ — сам склад класу. У Python його дає `frozenset` (незмінна, хешована множина), яку можна класти у множину вже бачених класів:

```python
def left_cosets(G, H, op):
    seen, cosets = set(), []
    for g in sorted(G):
        c = frozenset(op(g, h) for h in H)   # клас як МНОЖИНА, не як представник
        if c not in seen:
            seen.add(c)
            cosets.append(c)
    return cosets
```

Розкладімо D₃ за підгрупою поворотів H = ⟨r⟩ = {e, r, r²}:

```
>>> H = closure([r], pmul)
>>> for c in left_cosets(D3, H, pmul):
...     print(sorted(c))
[(0, 1, 2), (1, 2, 0), (2, 0, 1)]      # e, r, r²   — повороти (це сама H)
[(0, 2, 1), (1, 0, 2), (2, 1, 0)]      # s₁, s₃, s₂ — відбиття
```

Два класи, по три елементи, разом усі шість, без перекриття. Зсув поворотної підгрупи одним відбиттям дав усі три відбиття — і на цьому група вичерпана. Одна засторога живе прямо в назві функції: `left_cosets` вважає, що H **насправді підгрупа**. Дайте їй довільну підмножину — і «класи» почнуть перекриватися, а їхня кількість збрешеться. Тому H ми не вигадуємо руками, а будуємо тим самим `closure` з якихось твірних — тоді підгрупність гарантована за побудовою.

### Перевірка Лагранжа

Тепер уся теорема — це один рядок арифметики: число класів, помножене на розмір кожного, має дати розмір групи.

```python
def lagrange(G, H, op):
    idx = len(left_cosets(G, H, op))       # [G : H] — індекс
    return idx, len(G) == idx * len(H) and len(G) % len(H) == 0
```

```
>>> lagrange(D3, H, pmul)                  # H = ⟨r⟩, |H| = 3
(2, True)                                  # [G:H]=2,  6 = 2·3  ✓
>>> K = closure([s1], pmul)                # K = ⟨s₁⟩, |K| = 2
>>> lagrange(D3, K, pmul)
(3, True)                                  # [G:H]=3,  6 = 3·2  ✓
```

Обидві підгрупи ділять групу — і трійка, і двійка — та ще й дають різні індекси. А порядок 4 не з'явився серед підгруп не тому, що ми погано шукали, а тому, що 4 не ділить 6: структура групи наперед забороняє такий розмір.

### Та сама машина — зовсім інша група

Настав час обіцяної перевірки на чесність. Замінімо елемент і операцію — беремо [оборотні лишки за модулем 7](book:math/modular-arithmetic), тобто (Z₇\*, ·): числа {1, …, 6} з множенням за модулем 7. Елемент тепер звичайне ціле, операція — множення по колу. **Ядро — `closure`, `order`, `left_cosets`, `lagrange` — не міняємо ні на символ.**

```python
def mul7(a, b):
    return (a * b) % 7

Z7 = closure([3], mul7)        # 3 породжує всю групу (його степені пробігають усе)
```

```
>>> len(Z7)
6
>>> sorted(order(g, mul7, 1) for g in Z7)
[1, 2, 3, 3, 6, 6]
>>> H7 = closure([2], mul7)    # ⟨2⟩ = {1, 2, 4}
>>> lagrange(Z7, H7, mul7)
(2, True)                      # 6 = 2·3  ✓
```

Той самий рушій, ніякий не переписаний, знову склав Лагранжа — вже над числами, а не над трикутником. І погляньте на порядки: усі до одного ділять 6. Це не збіг, а [мала теорема Ферма](book:math/fermat-little-theorem) у нас перед очима: порядок кожного елемента ділить |G| = 6, тому g⁶ = 1 для будь-якого ненульового лишку за модулем 7. Те, що століттями доводили окремими арифметичними хитрощами, наш код здобув як звичайний наслідок розкладу на суміжні класи. Для складеного модуля та сама програма над (Zₙ\*, ·) дає [теорему Ейлера](book:math/euler-totient) — досить підставити іншу операцію за модулем.

```python
>>> all(len(Z7) % order(g, mul7, 1) == 0 for g in Z7)
True                           # кожен порядок ділить |G| — це і є Ферма
```

### Складність і на що зважати

Наївне замикання коштує приблизно **O(|G|² · k)** операцій для k твірних: кожен новий елемент множиться з усіма попередніми, а перевірка належності до множини — стала. Порядок елемента — щонайбільше |G| множень. Перелік суміжних класів — O(|G| · |H|) на побудову зсувів плюс дедуплікація. Для навчальних груп на десятки-сотні елементів це миттєво; для груп із мільярдами елементів наївний перебір нездійсненний, і справжня [обчислювальна теорія груп](book:math/computational-group-theory) працює інакше — через ланцюжки стабілізаторів (алгоритм Шраєра–Симса) та інші хитрощі, що ніколи не матеріалізують усю групу.

Пастки ж, які насправді псують такий код, майже всі про представлення, а не про математику:

- **Канонічність і хешованість елемента.** Кортеж, а не список; ціле, а не число з рухомою комою. Два рівні елементи мусять мати буквально рівне представлення — інакше множина рахує їх за різні.
- **Домовленість про порядок множення.** «Спершу h, потім g» чи навпаки — оберіть і тримайте скрізь; мовчазна неузгодженість ламає обернені та класи, не викликавши жодної помилки.
- **Дедуплікація класів за належністю.** Ключ — склад класу (`frozenset`), а не представник; інакше той самий клас порахується кілька разів.
- **H має бути підгрупою.** Будуйте її замиканням твірних, а не збирайте руками — інакше «суміжні класи» перекриються й індекс збреше.
- **Ліві проти правих класів.** Обидва розбиття дають той самий індекс (і той самий добуток за Лагранжем), але самі блоки збігаються лише коли підгрупа [нормальна](book:math/normal-subgroup); для перевірки Лагранжа байдуже, для тонших побудов — ні.

### Повна програма

Нижче — усе разом, у двох мовах. Python читається як сама математика — множини, кортежі, генератори лягають на поняття один-в-один, тому він тут головний. C++ виражає ту саму абстракцію інакше: рушій параметризовано **шаблоном** за типом елемента й операцією, а роль множин грає `std::set`; це показує, що незалежність від природи елемента — не риса мови, а властивість самого алгоритму.

:::tabs
```python
# Побудова скінченної групи й перевірка теореми Лагранжа.
# Рушій нічого не знає про природу елементів — лише про операцію op.

def closure(gens, op):
    """Замкнути твірні за операцією: уся породжена група."""
    G = set(gens)
    frontier = list(gens)
    while frontier:
        fresh = []
        for a in list(G):
            for b in frontier:
                for x in (op(a, b), op(b, a)):
                    if x not in G:
                        G.add(x)
                        fresh.append(x)
        frontier = fresh
    return G

def order(g, op, e):
    """Порядок елемента: найменше m>0 з gᵐ = e."""
    x, m = g, 1
    while x != e:
        x = op(x, g)
        m += 1
    return m

def left_cosets(G, H, op):
    """Ліві суміжні класи gH, здедупльовані як множини."""
    seen, cosets = set(), []
    for g in sorted(G):
        c = frozenset(op(g, h) for h in H)
        if c not in seen:
            seen.add(c)
            cosets.append(c)
    return cosets

def lagrange(G, H, op):
    idx = len(left_cosets(G, H, op))
    return idx, len(G) == idx * len(H) and len(G) % len(H) == 0

# група 1: симетрії трикутника D₃, елемент = перестановка (кортеж образів)
def pmul(g, h):                         # g після h: (g·h)[i] = g[h[i]]
    return tuple(g[h[i]] for i in range(len(g)))
```

```cpp
// Побудова скінченної групи й перевірка Лагранжа.
// Рушій параметризовано шаблоном: тип елемента T + операція Op.
#include <iostream>
#include <vector>
#include <set>

template <class T, class Op>
std::set<T> closure(std::vector<T> gens, Op op) {
    std::set<T> G(gens.begin(), gens.end());
    std::vector<T> frontier = gens;
    while (!frontier.empty()) {
        std::vector<T> fresh;
        std::vector<T> snap(G.begin(), G.end());       // копія: G зростатиме
        for (const T& a : snap)
            for (const T& b : frontier)
                for (const T& x : { op(a, b), op(b, a) })
                    if (G.insert(x).second) fresh.push_back(x);
        frontier = std::move(fresh);
    }
    return G;
}

template <class T, class Op>
int order(T g, Op op, const T& e) {
    T x = g; int m = 1;
    while (x != e) { x = op(x, g); ++m; }
    return m;
}

template <class T, class Op>
std::vector<std::set<T>> left_cosets(const std::set<T>& G,
                                     const std::set<T>& H, Op op) {
    std::set<std::set<T>> seen;
    std::vector<std::set<T>> out;
    for (const T& g : G) {
        std::set<T> c;
        for (const T& h : H) c.insert(op(g, h));         // клас як множина
        if (seen.insert(c).second) out.push_back(c);
    }
    return out;
}

using Perm = std::vector<int>;
Perm pmul(const Perm& g, const Perm& h) {                // g після h
    Perm p(g.size());
    for (int i = 0; i < (int)g.size(); ++i) p[i] = g[h[i]];
    return p;
}

int main() {
    // група 1: D₃ як перестановки
    Perm e3{0,1,2}, r{1,2,0}, s1{0,2,1};
    auto D3 = closure<Perm>({r, s1}, pmul);
    auto H  = closure<Perm>({r}, pmul);
    auto cs = left_cosets(D3, H, pmul);
    std::cout << "D3: |G|=" << D3.size() << "  |H|=" << H.size()
              << "  [G:H]=" << cs.size()
              << "  Lagrange=" << (D3.size() == cs.size() * H.size()) << "\n";

    // група 2: Z₇* — той самий рушій, інша операція
    auto mul7 = [](int a, int b) { return (a * b) % 7; };
    auto Z7 = closure<int>({3}, mul7);
    auto H7 = closure<int>({2}, mul7);
    auto cz = left_cosets(Z7, H7, mul7);
    std::cout << "Z7*: |G|=" << Z7.size() << "  |H|=" << H7.size()
              << "  [G:H]=" << cz.size()
              << "  Lagrange=" << (Z7.size() == cz.size() * H7.size()) << "\n";
}
```
