У 1982 році асиметрична криптографія стояла на порозі масштабного переділу. Поряд із щойно створеним шифром RSA головним претендентом на світовий стандарт шифрування вважалася рюкзачна криптосистема Ральфа Меркля та Мартіна Геллмана. Вона спиралася на NP-повну задачу про суму підмножин, працювала у сотні разів швидше за модульне піднесення до степеня і вважалася практично неприступною. Проте за кілька місяців система Меркля — Геллмана була вщент розбита, а за нею впали майже всі запропоновані модифікації рюкзачних шифрів. 

У той самий час у комп'ютерній алгебрі вирішувалася інша застаріла проблема: як розкласти многочлен із цілими коефіцієнтами на незвідні множники за поліноміальний час, не потонувши у комбінаторному вибуху перебору мільярдів можливих дільників.

Обидві ці фундаментальні задачі були розв'язані за допомогою одного математичного інструменту, створеного нідерландськими математиками Ар'єном Ленстрою, Хендріком Ленстрою та угорським ученим Ласло Ловасом — **LLL-алгоритму редукції базису ґраток**.

Детальніше про драматичні обставини появи алгоритму та крах рюкзачних шифрів розказано в нарисі: [історію відкриття LLL та падіння рюкзачних шифрів](book:math/algebra/lll-algorithm/hist-lenstra-lovasz.md).

### Прикладна мотивація: комбінаторний бар'єр та криптоаналіз

Щоб усвідомити масштаб інженерного прориву, який здійснив LLL-алгоритм, розглянемо дві ключові прикладні задачі, які десятиліттями вважалися практично нездоланними через комбінаторний вибух.

Перша задача — це **факторизація многочленів над полем раціональних чисел `ℚ[x]` або кільцем цілих чисел `ℤ[x]`**. У системах комп'ютерної алгебри розклад многочлена на незвідні множники є базовою операцією. Класичний метод Леопольда Кронекера (1882) вимагав обчислення значень многочлена у фіксованих точках, факторизації цих цілих чисел і побудови інтерполяційних многочленів для всіх комбінацій дільників, що призводило до астрономічної експоненційної складності.

У 1967 році Елвін Берлекамп розробив швидкий поліноміальний алгоритм факторизації многочленів над скінченними полями `GF(p)`. У 1969 році Ганс Цассенгауз запропонував поєднати метод Берлекампа з лемою Гензеля:
1. Замінити коефіцієнти многочлена `f(x) ∈ ℤ[x]` їхніми лишками за модулем невеликого простого числа `p`.
2. Швидко розкласти многочлен над полем `GF(p)` на незвідні множники `h_1(x), ..., h_r(x) mod p`.
3. Підняти ці дільники за допомогою леми Гензеля до великого модуля `p^k`, де степінь `k` обирається так, щоб модуль `p^k` перевищував теоретичну межу Міньотта для коефіцієнтів можливих дійсних дільників у `ℤ[x]`.
4. Перебрати всі можливі підмножини піднятих модульних дільників, щоб перевірити, чи є їхній добуток справжнім дільником вихідного многочлена в кільці `ℤ[x]`.

Саме на четвертому кроці схема Цассенгауза зазнавала краху. Для так званих многочленів Свіннертона — Дайєра многочлен степеня `d` є незвідним над `ℤ[x]`, але розпадається на `d` лінійних множників за будь-яким простим модулем `p`. Кількість можливих комбінацій для перевірки дорівнює `2^d`. Уже при степені `d = 60` число комбінацій перевищує `10¹⁸`, що робило алгоритм Цассенгауза непридатним для складних поліномів.

Друга задача — це **криптоаналіз рюкзачних криптосистем**. У схемі Меркля — Геллмана відправник шифрує двійкове повідомлення `x = (x_1, ..., x_n) ∈ {0, 1}ⁿ`, обчислюючи суму відкритих ваг `S = ∑ x_i a_i`. Атакуючий повинен відновити вектор `x` за відомими відкритими числами `a_1, ..., a_n` та сумою `S`. Це класична задача Subset Sum (про суму підмножин). Для випадкового набору чисел прямий пошук вимагає перевірки `2^n` варіантів.

LLL-алгоритм показав, що обидві ці задачі зводяться до пошуку аномально короткого вектора у спеціально сконструйованій багатовимірній дискретній структурі — ґратці. Відмовившись від спроб знайти абсолютно найкоротший вектор і погодившись на його поліноміальне наближення, автори отримали перший детермінований алгоритм, який розв'язує ці задачі за гарантований поліноміальний час.

### Що таке ґратка: геометрія дискретного простору

Щоб зрозуміти принцип редукції, необхідно перейти від неперервного векторного простору до його дискретної підмножини.

Нехай дано евклідовий векторний простір `ℝᵐ` зі стандартним скалярним добутком `⟨u, v⟩ = ∑_{j=1}^m u_j v_j` та довжиною (нормою) вектора `‖v‖ = √⟨v, v⟩`. Візьмемо впорядкований набір із `n` лінійно незалежних векторів `b_1, b_2, ..., b_n ∈ ℝᵐ` (`n ≤ m`).

**Ґраткою** (lattice) `Λ`, породженою базисом `B = (b_1, ..., b_n)`, називається дискретна адитивна підгрупа простору `ℝᵐ`, яка складається з усіх можливих лінійних комбінацій цих векторів із **виключно цілими** коефіцієнтами:

```
Λ = ℒ(b_1, ..., b_n) = { ∑_{i=1}^n z_i b_i : z_i ∈ ℤ }
```

Число `n` називають **рангом** або розмірністю ґратки (`rank(Λ) = n`), а число `m` — розмірністю навколишнього простору. Якщо розмірності збігаються (`n = m`), ґратка називається повноранговою.

Дискретність означає, що навколо кожного вузла ґратки існує куля деякого додатного радіуса `r > 0`, яка не містить жодних інших точок ґратки.

Ключова геометрична властивість полягає в тому, що **одна й та сама ґратка може бути породжена нескінченною кількістю різних базисів**. Якщо ми візьмемо матрицю `B`, стовпцями якої є координати векторів `b_1, ..., b_n`, то будь-який інший базис `B'` тієї ж ґратки отримується множенням на унімодулярну цілочисельну матрицю `U ∈ GL_n(ℤ)`:

```
B' = B · U,   де det(U) = ±1 та U_{i,j} ∈ ℤ
```

Фундаментальною областю (напіввідкритим паралелепіпедом) базису `B` є множина точок простору:

```
𝒫(B) = { ∑_{i=1}^n t_i b_i : 0 ≤ t_i < 1, t_i ∈ ℝ }
```

Об'єм цієї фундаментальної області є геометричним інваріантом ґратки, який не залежить від вибору конкретного базису. Він називається **детермінантом** або визначником ґратки `det(Λ)`:

```
det(Λ) = √det(Bᵀ · B)
```

Якщо розмірності збігаються (`n = m`), то визначник дорівнює абсолютному значенню визначника матриці: `det(Λ) = |det(B)|`. Якщо ми замінимо базис `B` на інший базис `B' = B · U`, об'єм фундаментальної області збережеться:

```
det(B'ᵀ · B') = det(Uᵀ Bᵀ B U) = det(U)² · det(Bᵀ B) = det(Bᵀ B)
```

![Порівняння «поганого» та «редукованого» базисів](/book/math/algebra/lll-algorithm/img/lll-lattice-basis.svg)
*Геометрія ґратки: зліва — витягнутий невигідний базис з гострим кутом; справа — LLL-редукований короткий майже ортогональний базис.*

#### Клітини Вороного та послідовні мінімуми Мінковського
Простір `ℝᵐ` можна розбити на однакові багатогранники, кожен з яких містить точки, найближчі до конкретного вузла ґратки. Така область навколо початку координат називається **клітиною Вороного** (Voronoi cell):

```
𝒱(0) = { x ∈ span(Λ) : ‖x‖ ≤ ‖x - v‖  для всіх v ∈ Λ }
```

Об'єм клітини Вороного завжди точно дорівнює детермінанту ґратки: `vol(𝒱(0)) = det(Λ)`.

Щоб охарактеризувати щільність та геометрію ґратки, Герман Мінковський ввів поняття **послідовних мінімумів** (successive minima) `λ_1, λ_2, ..., λ_n`. 

Для кожного `i ∈ {1, ..., n}` `i`-й мінімум `λ_i(Λ)` визначається як радіус найменшої кулі з центром у початку координат, яка містить щонайменше `i` лінійно незалежних векторів ґратки:

```
λ_i(Λ) = inf { r > 0 : dim(span(Λ ∩ B(0, r))) ≥ i }
```

Зокрема, `λ_1(Λ)` є довжиною найкоротшого ненульового вектора у ґратці:

```
λ_1(Λ) = min_{v ∈ Λ \ {0}} ‖v‖
```

Знаменита **друга теорема Мінковського** пов'язує добуток усіх послідовних мінімумів із детермінантом ґратки:

```
(∏_{i=1}^n λ_i(Λ)) ≤ (2^n / V_n) · det(Λ)
```

де `V_n = π^{n/2} / Γ(n/2 + 1)` — евклідовий об'єм одиничної `n`-вимірної кулі.

#### Дуальна ґратка
Для кожної ґратки `Λ ⊂ ℝᵐ` визначається її **дуальна ґратка** `Λ*`:

```
Λ* = { y ∈ span(Λ) : ⟨y, x⟩ ∈ ℤ  для всіх x ∈ Λ }
```

Якщо `B` — матриця базису повнорангової ґратки `Λ`, то базис дуальної ґратки задається матрицею `D = (B⁻¹)ᵀ`. Визначники прямої та дуальної ґраток пов'язані простим співвідношенням `det(Λ*) = 1 / det(Λ)`. Властивості дуальної ґратки відіграють фундаментальну роль у дуальних атаках на сучасні постквантові шифри.

#### «Поганий» проти «хорошого» базису: у чому полягає редукція
Хоча всі еквівалентні базиси породжують однакову множину вузлів, їхня обчислювальна зручність кардинально різниться:
- **«Поганий» (нередукований) базис:** вектори мають велетенську довжину, розташовані під дуже гострими кутами один до одного і є майже колінеарними. У такому базисі координати точок мають величезні значення, а спроба знайти найближчий вузол вимагає повного експоненційного перебору.
- **«Хороший» (редукований) базис:** вектори є максимально короткими, а кути між ними близькі до `90°` (прямого кута). У такому базисі геометрична структура ґратки стає наочною.

Головними обчислювальними задачами геометрії ґраток є:
1. **SVP (Shortest Vector Problem):** знайти ненульовий вектор `v ∈ Λ \ {0}`, що досягає першого мінімуму `‖v‖ = λ_1(Λ)`.
2. **CVP (Closest Vector Problem):** для довільної точки простору `t ∈ ℝᵐ` знайти найближчий до неї вузол ґратки `v ∈ Λ`, що мінімізує відстань `‖t - v‖`.

Обидві задачі в точній постановці є NP-важкими при великих розмірностях `n`. **Редукція базису ґратки** — це процес алгоритмічного перетворення довільного «поганого» базису на еквівалентний «хороший» базис із короткими та майже ортогональними векторами.

### Історичний попередник: двовимірна редукція Гаусса — Лагранжа

Перш ніж розглядати багатовимірний випадок, корисно поглянути на те, як задача редукції розв'язується на площині (`n = 2`).

На початку XIX століття Карл Фрідріх Гаусс та Жозеф-Луї Лагранж розробили алгоритм для редукції бінарних квадратичних форм, який геометрично є точним розв'язком задачі SVP для двовимірних ґраток.

Нехай дано два базисні вектори `b_1, b_2 ∈ ℝ²`. Алгоритм Гаусса повторює два прості кроки:
1. **Розмірне редукування:** віднімаємо від вектора `b_2` проекцію на `b_1`, округлену до найближчого цілого:
   ```
   b_2 ← b_2 - ⌊⟨b_1, b_2⟩ / ‖b_1‖²⌉ · b_1
   ```
2. **Перевірка довжин:** якщо новий вектор `b_2` виявився коротшим за `b_1` (`‖b_2‖ < ‖b_1‖`), міняємо їх місцями `b_1 ↔ b_2` і повертаємося до кроку 1. Інакше алгоритм зупиняється.

Цей процес є прямим геометричним еквівалентом алгоритму Евкліда знаходження найбільшого спільного дільника чисел. Коли алгоритм Гаусса зупиняється, вектор `b_1` гарантовано є абсолютно найкоротшим вектором ґратки (`‖b_1‖ = λ_1(Λ)`), а кут між векторами `b_1` та `b_2` лежить у межах від `60°` до `120°`.

Проте пряма спроба узагальнити алгоритм Гаусса на розмірності `n ≥ 3` зазнавала невдачі: кількість можливих комбінацій сусідніх векторів зростає експоненційно, і вибір правильного порядку перестановок стає комбінаторним тупиком. Геніальна ідея Ловаса полягала в тому, щоб контролювати вектори не за їхніми абсолютними довжинами, а за довжинами їхніх **ортогональних проєкцій Грама — Шмідта** на двовимірні підпростори.

### Ортогоналізація Грама — Шмідта та цілочисельний бар'єр

Класичним інструментом лінійної алгебри для побудови ортогонального базису у векторному просторі є процес ортогоналізації Грама — Шмідта (Gram-Schmidt Orthogonalization, GSO).

Для базису `(b_1, ..., b_n)` ортогональні вектори `b_1*, ..., b_n*` та проєкційні коефіцієнти `μ_{i,j}` обчислюють за рекурентними формулами:

```
b_1* = b_1
b_i* = b_i - ∑_{j=1}^{i-1} μ_{i,j} b_j*   для i = 2, 3, ..., n
```

де скалярний коефіцієнт `μ_{i,j}` задає довжину проєкції вектора `b_i` на напрямок `b_j*`:

```
μ_{i,j} = ⟨b_i, b_j*⟩ / ‖b_j*‖²           для 1 ≤ j < i ≤ n
```

Вектори `b_i*` є попарно ортогональними (`⟨b_i*, b_j*⟩ = 0` при `i ≠ j`), а детермінант ґратки виражається як добуток їхніх довжин:

```
det(Λ) = ∏_{i=1}^n ‖b_i*‖
```

Зв'язок між матрицею вихідного базису `B` та ортогоналізованого базису `B*` описується формулою:

```
B = B* · Mᵀ
```

де `M = (μ_{i,j})` — нижньотрикутна унітрикутна матриця з одиницями на головній діагоналі (`μ_{i,i} = 1` та `μ_{i,j} = 0` для `j > i`).

Геометрично вектор `b_i*` є проєкцією вихідного вектора `b_i` на ортогональне доповнення до підпростору, натягнутого на перші `i-1` векторів:

```
b_i* = π_i(b_i),   де π_i: ℝᵐ → (span(b_1, ..., b_{i-1}))^⊥
```

#### Цілочисельний бар'єр ортогоналізації
У випадку ґраток постає фундаментальна перепона — **цілочисельний бар'єр**. Оскільки коефіцієнти `μ_{i,j}` у загальному випадку є раціональними дробами, вектори `b_i*` **не належать самій ґратці `Λ`** (за винятком першого вектора `b_1* = b_1`). Ми не можемо просто замінити базис `b_i` на вектори `b_i*`, оскільки їхні цілочисельні комбінації не покриють вузли вихідної ґратки.

Задача LLL полягає у знаходженні справжнього цілочисельного базису `(b_1, ..., b_n)`, який за своїми геометричними властивостями максимально наближається до ідеального ортогонального базису `(b_1*, ..., b_n*)`.

Повні алгебраїчні доведення та матричні виведення процесу ортогоналізації подано у розділі: [математичну теорію Грама — Шмідта та редукції](book:math/algebra/lll-algorithm/math-gram-schmidt-reduction.md).

### Критерії LLL-редукованого базису

Нехай зафіксовано параметр фактора якості `δ ∈ (1/4, 1]`. Зазвичай обирають `δ = 3/4` (значення з оригінальної статті 1982 року) або `δ = 0.99`.

Базис `(b_1, b_2, ..., b_n)` називається **`δ`-LLL-редукованим**, якщо він одночасно задовольняє дві умови:

#### 1. Умова розмірного редукування (Size Reduction)
Для всіх пар індексів `1 ≤ j < i ≤ n` коефіцієнти Грама — Шмідта за модулем не перевищують половини:

```
|μ_{i,j}| ≤ 1/2
```

Ця умова гарантує, що вектор `b_i` не має надлишкової складової вздовж напрямків попередніх векторів `b_j`. Якщо для деякої пари індексів виявилося, що `|μ_{i,j}| > 1/2`, вектор `b_i` можна скоротити, віднявши цілочисельне кратне:

```
b_i ← b_i - ⌊μ_{i,j}⌉ · b_j
```

де `⌊x⌉` позначає найближче ціле число до `x`. Після такого віднімання новий коефіцієнт `μ_{i,j}` гарантовано потрапляє у проміжок `[-1/2, 1/2]`.

#### 2. Умова Ловаса (Lovász Condition)
Для всіх сусідніх пар векторів з індексами `k ∈ {2, 3, ..., n}` виконується нерівність:

```
δ · ‖b_{k-1}*‖² ≤ ‖b_k* + μ_{k,k-1} b_{k-1}*‖² = ‖b_k*‖² + μ_{k,k-1}² ‖b_{k-1}*‖²
```

Переносячи другий доданок ліворуч, отримуємо стандартний критерій Ловаса:

```
‖b_k*‖² ≥ (δ - μ_{k,k-1}²) · ‖b_{k-1}*‖²
```

![Геометрія розмірного редукування та умови Ловаса](/book/math/algebra/lll-algorithm/img/lll-gram-schmidt-step.svg)
*Геометрія розмірного редукування (зліва) та умови Ловаса (справа): зсув вздовж дискретної прямої та критерій обміну векторів.*

#### Геометричний зміст умови Ловаса
Якщо спроєктувати вектори `b_{k-1}` та `b_k` на ортогональне доповнення підпростору `span(b_1, ..., b_{k-2})`, ми отримаємо двовимірну площину `P_k`. На цій площині вектори мають ортогональні координати `(‖b_{k-1}*‖, 0)` та `(μ_{k,k-1} ‖b_{k-1}*‖, ‖b_k*‖)`.

Умова Ловаса вимагає, щоб проєкція вектора `b_k` не була суттєво коротшою за проєкцію вектора `b_{k-1}`. Якщо ця умова порушується, це означає, що вектори стоять у «неправильному» порядку: вектор `b_k` містить коротшу складову і повинен передувати вектору `b_{k-1}`. У такому разі алгоритм міняє їх місцями.

Для стандартного значення `δ = 3/4` та за умови виконання розмірного редукування (`|μ_{k,k-1}| ≤ 1/2`) маємо:

```
δ - μ_{k,k-1}² ≥ 3/4 - 1/4 = 1/2
```

Отже, довжини ортогональних компонент задовольняють співвідношення:

```
‖b_k*‖² ≥ (1/2) · ‖b_{k-1}*‖²
```

Це означає, що довжини ортогональних векторів уздовж базису не можуть різко спадати.

#### Роль параметра `δ`
Вибір параметра `δ` визначає баланс між швидкістю роботи та якістю редукції:
- Якщо `δ ≤ 1/4`, умова Ловаса виконується автоматично для будь-яких векторів після розмірного редукування, тому алгоритм не виконає жодного обміну і поверне нередукований базис.
- При `δ = 3/4` константа росту становить `α = 1 / (3/4 - 1/4) = 2`, що забезпечує швидку збіжність і стабільність.
- При `δ = 0.99` константа росту дорівнює `α ≈ 1.35`, що дає значно коротші вектори ціною збільшення кількості ітерацій приблизно на 30–40%.
- При `δ = 1.0` алгоритм формально втрачає строгу гарантію поліноміального часу у найгіршому теоретичному випадку.

### Механізм LLL-алгоритму: покроковий конвеєр

Алгоритм підтримує поточний базис `(b_1, ..., b_n)` та показчик поточного індексу `k`, який ініціалізується значенням `k = 2`.

![Блок-схема LLL-алгоритму](/book/math/algebra/lll-algorithm/img/lll-flowchart.svg)
*Повна блок-схема конвеєра LLL-алгоритму: розмірна редукція, перевірка умови Ловаса, перестановка та перехід індексу.*

Алгоритм виконує такі кроки в циклі:

```
1. [Ініціалізація]
   Обчислити вектори b*₁, ..., b*ₙ та коефіцієнти μ_{i,j} за Грамом — Шмідтом.
   Встановити індекс k = 2.

2. [Розмірне редукування сусідньої пари]
   Виконати bₖ ← bₖ - ⌊μ_{k, k-1}⌉ · b_{k-1}.
   Оновити коефіцієнти μ_{k, j} для j < k.

3. [Перевірка умови Ловаса]
   Якщо ‖b*ₖ‖² < (δ - μ_{k, k-1}²) · ‖b*_{k-1}‖²:
     а) [Обмін]: поміняти місцями вектори bₖ ↔ b_{k-1}.
     б) [Оновлення GSO]: перерахувати вектори b*_{k-1}, b*ₖ та коефіцієнти μ.
     в) [Крок назад]: встановити k = max(k - 1, 2).
     г) Перейти до кроку 2.

4. [Повне розмірне редукування та просування вперед]
   Для кожного j від k-2 спадаючи до 1:
     Виконати bₖ ← bₖ - ⌊μ_{k, j}⌉ · bⱼ.
     Оновити коефіцієнти μ_{k, l} для l < j.
   Встановити k = k + 1.

5. [Завершення]
   Якщо k ≤ n, перейти до кроку 2.
   Якщо k = n + 1, алгоритм успішно завершено. Базис є LLL-редукованим.
```

Чому після обміну `b_k ↔ b_{k-1}` достатньо зробити крок назад лише на один індекс `k ← max(k - 1, 2)`? Оскільки обмін зачіпає виключно підґратку `span(b_1, ..., b_k)`, усі попередні вектори `b_1, ..., b_{k-2}` вже взаємно редуковані між собою. Єдине, що могло порушитися — це умова Ловаса між новим вектором на позиції `k-1` та його попередником `b_{k-2}`.

### Повний числовий приклад покрокового виконання

Розглянемо роботу LLL-алгоритму на конкретному числовому прикладі тривимірної ґратки в просторі `ℝ³`.

Нехай дано початковий базис із сильно скошеними векторами:

```
b₁ = (1, -1, 3)
b₂ = (1,  0, 5)
b₃ = (1,  2, 6)
```

Параметр Ловаса оберемо стандартним: `δ = 3/4 = 0.75`.

#### Крок 1. Початкова ортогоналізація Грама — Шмідта
Обчислимо норму першого вектора:

```
b₁* = b₁ = (1, -1, 3)
‖b₁*‖² = 1² + (-1)² + 3² = 1 + 1 + 9 = 11
```

Для другого вектора:

```
μ_{2,1} = ⟨b₂, b₁*⟩ / ‖b₁*‖² = (1·1 + 0·(-1) + 5·3) / 11 = (1 + 0 + 15) / 11 = 16 / 11 ≈ 1.4545
b₂* = b₂ - μ_{2,1} b₁* = (1, 0, 5) - (16/11) · (1, -1, 3) = (-5/11, 16/11, 7/11)
‖b₂*‖² = (-5/11)² + (16/11)² + (7/11)² = (25 + 256 + 49) / 121 = 330 / 121 = 30 / 11 ≈ 2.7273
```

Для третього вектора:

```
μ_{3,1} = ⟨b₃, b₁*⟩ / ‖b₁*‖² = (1·1 + 2·(-1) + 6·3) / 11 = (1 - 2 + 18) / 11 = 17 / 11 ≈ 1.5455
μ_{3,2} = ⟨b₃, b₂*⟩ / ‖b₂*‖² = (1·(-5/11) + 2·(16/11) + 6·(7/11)) / (30/11) = (-5 + 32 + 42) / 30 = 69 / 30 = 23 / 10 = 2.3
b₃* = b₃ - μ_{3,1} b₁* - μ_{3,2} b₂* = (1/10, 1/10, -1/10)
‖b₃*‖² = (1/10)² + (1/10)² + (-1/10)² = 3 / 100 = 0.03
```

#### Крок 2. Ітерація `k = 2`
Розмірне редукування для пари `(2, 1)`:
Коефіцієнт `μ_{2,1} = 16/11 ≈ 1.4545`. Найближче ціле число `q = ⌊1.4545⌉ = 1`.
Оновлюємо вектор `b₂`:

```
b₂ ← b₂ - 1 · b₁ = (1, 0, 5) - (1, -1, 3) = (0, 1, 2)
```

Новий коефіцієнт стає: `μ_{2,1} = 16/11 - 1 = 5/11 ≈ 0.4545 ≤ 0.5`. Умова розмірної редукції виконана.

Перевіримо умову Ловаса для `k = 2`:

```
‖b₂*‖² = 30 / 11 ≈ 2.7273
(δ - μ_{2,1}²) · ‖b₁*‖² = (0.75 - (5/11)²) · 11 = (3/4 - 25/121) · 11 = (263 / 484) · 11 = 263 / 44 ≈ 5.9773
```

Порівнюємо:

```
2.7273 < 5.9773   [Умова Ловаса ПОРУШЕНА!]
```

Оскільки `‖b₂*‖²` значно менший за допустиму межу, вектори `b₁` та `b₂` стоять у невигідному порядку.
**Виконуємо обмін `b₁ ↔ b₂`**:

```
Новий b₁ = (0, 1, 2)
Новий b₂ = (1, -1, 3)
```

Перераховуємо Грама — Шмідта для перших двох векторів:

```
b₁* = (0, 1, 2),   ‖b₁*‖² = 0² + 1² + 2² = 5
μ_{2,1} = ⟨b₂, b₁*⟩ / ‖b₁*‖² = (1·0 + (-1)·1 + 3·2) / 5 = 5 / 5 = 1.0
b₂* = (1, -1, 3) - 1.0 · (0, 1, 2) = (1, -2, 1),   ‖b₂*‖² = 1² + (-2)² + 1² = 6
```

Розмірне редукування після обміну: `q = ⌊1.0⌉ = 1`.
Оновлюємо `b₂ ← b₂ - 1 · b₁ = (1, -1, 3) - (0, 1, 2) = (1, -2, 1)`.
Тепер `μ_{2,1} = 0.0`.

Перевіряємо умову Ловаса: `‖b₂*‖² = 6 ≥ (0.75 - 0) · 5 = 3.75`. Умова виконана!
Переходимо до `k = 3`.

#### Крок 3. Ітерація `k = 3`
Вектор `b₃ = (1, 2, 6)`.
Обчислюємо коефіцієнти відносно оновленого базису:
`μ_{3,2} = ⟨b₃, b₂*⟩ / ‖b₂*‖² = (1·1 + 2·(-2) + 6·1) / 6 = (1 - 4 + 6) / 6 = 3 / 6 = 0.5`.
`μ_{3,1} = ⟨b₃, b₁*⟩ / ‖b₁*‖² = (1·0 + 2·1 + 6·2) / 5 = 14 / 5 = 2.8`.

Виконуємо розмірне редукування:
- Для `j = 2`: `μ_{3,2} = 0.5 ≤ 0.5` (зсув не потрібен).
- Для `j = 1`: `q = ⌊2.8⌉ = 3`. Оновлюємо `b₃ ← b₃ - 3 · b₁ = (1, 2, 6) - 3·(0, 1, 2) = (1, -1, 0)`.
Тепер `μ_{3,1} = 2.8 - 3 = -0.2`.

Перевіряємо умову Ловаса для `k = 3`:

```
b₃* = (1/10, 1/10, -1/10),   ‖b₃*‖² = 0.03
(δ - μ_{3,2}²) · ‖b₂*‖² = (0.75 - 0.25) · 6 = 0.5 · 6 = 3.0
```

Оскільки `0.03 < 3.0`, умова Ловаса порушена.
**Виконуємо обмін `b₂ ↔ b₃`**, повертаємо індекс на `k = 2` і продовжуємо ітерації.

#### Результат редукції
Після завершення всіх обмінів та розмірних редукцій алгоритм повертає LLL-редукований базис:

```
v₁ = (0,  1, 2),   ‖v₁‖ = √5 ≈ 2.236
v₂ = (1, -1, 0),   ‖v₂‖ = √2 ≈ 1.414
v₃ = (1,  0, 1),   ‖v₃‖ = √2 ≈ 1.414
```

Початкові вектори мали довжини `√11 ≈ 3.32`, `√26 ≈ 5.10`, `√41 ≈ 6.40`. Редукований базис складається з надзвичайно коротких векторів із довжинами `√2, √2, √5`, кути між якими близькі до ортогональних.

### Теоретичні гарантії та математичні доведення

LLL-алгоритм надає строгі математичні гарантії на якість редукованого базису та час свого виконання. Розглянемо детальні виведення цих оцінок.

#### Лема про експоненційне зростання ортогональних проєкцій
Нехай `(b_1, ..., b_n)` — `δ`-LLL-редукований базис з параметром `δ = 3/4`. Тоді для будь-яких індексів `1 ≤ j < i ≤ n` виконується нерівність:

```
‖b_j*‖² ≤ 2^{i - j} · ‖b_i*‖²
```

*Доведення:* З умови Ловаса для сусідньої пари маємо:

```
‖b_i*‖² ≥ (3/4 - μ_{i, i-1}²) · ‖b_{i-1}*‖² ≥ (3/4 - 1/4) · ‖b_{i-1}*‖² = (1/2) · ‖b_{i-1}*‖²
```

Звідси `‖b_{i-1}*‖² ≤ 2 · ‖b_i*‖²`. Застосовуючи цю нерівність послідовно `i - j` разів для індексів від `i` вниз до `j`, отримуємо потрібну оцінку.

#### Теорема 1. Верхня оцінка на довжину першого вектора
Перший вектор `b_1` редукованого базису задовольняє нерівність відносно детермінанта ґратки:

```
‖b_1‖ ≤ 2^{(n - 1) / 4} · (det Λ)^{1 / n}
```

*Доведення:* Оскільки `b_1 = b_1*`, за лемою маємо `‖b_1‖² ≤ 2^{i-1} ‖b_i*‖²` для кожного `i = 1, 2, ..., n`. Перемножимо ці `n` нерівностей:

```
‖b_1‖^{2n} = ∏_{i=1}^n ‖b_1‖²                           [добуток n однакових множників]
           ≤ ∏_{i=1}^n (2^{i-1} · ‖b_i*‖²)              [підстановка нерівності з леми]
           = 2^{∑_{i=1}^n (i - 1)} · ∏_{i=1}^n ‖b_i*‖²  [відокремлення степенів двійки]
           = 2^{n(n - 1) / 2} · (det Λ)²                [сума прогресії та означення det Λ]
```

Вилучаючи корінь степеня `2n` з обох частин, отримуємо:

```
‖b_1‖ ≤ 2^{(n - 1) / 4} · (det Λ)^{1 / n}
```

#### Теорема 2. Апроксимація найкоротшого вектора (SVP)
Перший вектор `b_1` редукованого базису задовольняє нерівність відносно першого мінімуму Мінковського:

```
‖b_1‖ ≤ 2^{(n - 1) / 2} · λ_1(Λ)
```

*Доведення:* Нехай `v = ∑_{i=1}^n z_i b_i ∈ Λ \ {0}` — довільний ненульовий вектор ґратки. Нехай `m` — найбільший індекс, для якого `z_m ≠ 0`. Спроєктуємо вектор `v` на ортогональне доповнення `span(b_1, ..., b_{m-1})^⊥`:

```
π_m(v) = z_m · π_m(b_m) = z_m · b_m*
```

Оскільки ортогональна проєкція не може збільшувати довжину вектора (`‖v‖ ≥ ‖π_m(v)‖`), а `z_m` є ненульовим цілим числом (`|z_m| ≥ 1`), маємо:

```
‖v‖² ≥ ‖π_m(v)‖² = z_m² · ‖b_m*‖² ≥ ‖b_m*‖²
```

Використовуючи лему для `j = 1` та `i = m`:

```
‖b_1‖² = ‖b_1*‖² ≤ 2^{m - 1} · ‖b_m*‖² ≤ 2^{n - 1} · ‖v‖²
```

Вилучаючи квадратний корінь: `‖b_1‖ ≤ 2^{(n - 1) / 2} · ‖v‖`. Оскільки це справедливо для будь-якого ненульового вектора `v ∈ Λ`, оберемо як `v` найкоротший вектор `λ_1(Λ)` і отримаємо шукану оцінку `‖b_1‖ ≤ 2^{(n - 1) / 2} · λ_1(Λ)`.

#### Теорема 3. Обмеження дефекту ортогональності (Нерівність Адамара)
Вектори редукованого базису задовольняють співвідношення:

```
∏_{i=1}^n ‖b_i‖ ≤ 2^{n(n - 1) / 4} · det(Λ)
```

*Доведення:* Оскільки `‖b_i‖² = ‖b_i* + ∑_{j=1}^{i-1} μ_{i,j} b_j*‖² = ‖b_i*‖² + ∑_{j=1}^{i-1} μ_{i,j}² ‖b_j*‖²`, за умовою розмірного редукування `|μ_{i,j}| ≤ 1/2` та лемою про ортогональні проєкції отримуємо `‖b_i‖² ≤ 2^{i-1} ‖b_i*‖²`. Перемноження за всіма `i` дає потрібний результат.

#### Теорема 4. Потенційна функція та поліноміальна збіжність
Автори ввели монотонно спадну **потенційну функцію** `D`:

```
D = ∏_{i=1}^{n-1} d_i = ∏_{i=1}^{n-1} (det Λ_i)² = ∏_{i=1}^{n-1} (∏_{j=1}^i ‖b_j*‖²)
```

де `d_i` — квадрат детермінанта підґратки `Λ_i = ℒ(b_1, ..., b_i)`.

- Операція розмірного редукування не змінює ортогональних векторів `b_i*`, отже, залишає величини `d_i` та потенціал `D` незмінними.
- Під час операції обміну `b_{k-1} ↔ b_k` змінюється лише підґратка `Λ_{k-1}` (усі інші підґратки `Λ_i` при `i ≠ k-1` зберігають свій простір, а отже й визначник `d_i`).
- Новий визначник `d_{k-1}^{new}` дорівнює `(det Λ_{k-2})² · ‖(b_{k-1}*)_{new}‖² = d_{k-2} · ‖b_k* + μ_{k,k-1} b_{k-1}*‖² < δ · d_{k-2} · ‖b_{k-1}*‖² = δ · d_{k-1}^{old}`.

При `δ = 3/4` кожен обмін зменшує потенціал `D` щонайменше у `4/3` раза:

```
D_{new} ≤ (3/4) · D_{old}
```

Для цілочисельної ґратки величина `D` є натуральним числом (`D ≥ 1`). Оскільки початкове значення обмежене `D_0 ≤ B^{n(n-1)}`, де `B = max ‖b_i‖`, загальна кількість операцій обміну не перевищує `N_{swaps} ≤ O(n² · log B)`. Загальна бітова складність алгоритму становить `O(n⁵ · m · log³ B)`, що доводить його поліноміальність.

### Чисельна стабільність та плаваюча кома: алгоритм `L²`

Класичний опис LLL-алгоритму вимагає роботи з точними раціональними числами для `μ_{i,j}` та `‖b_i*‖²`. Проте чисельник і знаменник цих дробів можуть досягати розміру `O(n · log B)` бітів. Для великих розмірностей (`n ≥ 100`) постійне скорочення довгих чисел через НСД робить алгоритм надзвичайно повільним.

Спроба замінити точні дроби стандартними числами типу `double` (53 біти мантиси) натикається на катастрофічну втрату точності (catastrophic cancellation): накопичені похибки заокруглення призводять до того, що умова Ловаса починає циклічно хибити, і алгоритм зависає у нескінченному переставлянні сусідніх рядків.

У 2005–2009 роках французькі дослідники Фон Нгуєн та Дам'єн Стеле розробили алгоритм **`L²` (Floating-Point LLL)**. Вони ввели механізм динамічного контролю за похибками:
1. Алгоритм відстежує верхню межу похибки округлення для кожного `μ_{i,j}`.
2. Якщо похибка наближається до небезпечного порогу `|μ_{i,j} - 1/2| < ε`, точність мантиси автоматично подвоюється (від 53 бітів до 106, 212 або більше за допомогою бібліотек типу MPFR).
3. Вони довели, що для успішної редукції достатньо підтримувати точність мантиси порядку `O(n)` бітів.

Це зменшило бітову складність до `O(n³ · (n + log B) · log B)`, прискоривши редукцію ґраток у десятки разів. Алгоритм `L²` реалізований як базовий рушій у сучасній бібліотеці `fplll`.

### Розв'язання задачі CVP: алгоритми Бабаї

Окрім пошуку найкоротшого вектора (SVP), редукований базис дозволяє ефективно розв'язувати задачу знаходження найближчого вузла (Closest Vector Problem, CVP). У 1986 році Ласло Бабаї запропонував два елегантні алгоритми на базі LLL.

#### 1. Алгоритм простого округлення (Babai's Round-Off)
Нехай дано цільову точку `t ∈ ℝᵐ`.
1. Виразимо `t` як дійсну лінійну комбінацію векторів LLL-редукованого базису: `t = ∑_{i=1}^n c_i b_i`, де `c_i ∈ ℝ`.
2. Округлимо кожен коефіцієнт до найближчого цілого: `z_i = ⌊c_i⌉`.
3. Повернемо вузол ґратки `v = ∑_{i=1}^n z_i b_i ∈ Λ`.

#### 2. Алгоритм найближчої площини (Babai's Nearest Plane)
Цей алгоритм працює послідовно від останнього вектора до першого, проєктуючи точку `t` на ортогональні підпростори:
1. Встановлюємо `t_n = t`.
2. Для `i` від `n` спадаючи до `1`:
   - Знаходимо дійсний коефіцієнт `c_i = ⟨t_i, b_i*⟩ / ‖b_i*‖²`.
   - Округлюємо `z_i = ⌊c_i⌉`.
   - Зсуваємо точку: `t_{i-1} = t_i - (c_i - z_i) b_i* - z_i (b_i - b_i*)`.
3. Повертаємо вектор `v = ∑_{i=1}^n z_i b_i`.

Алгоритм найближчої площини гарантує, що відстань від точки `t` до знайденого вузла `v` задовольняє нерівність:

```
‖t - v‖ ≤ 2^{n / 2} · dist(t, Λ)
```

де `dist(t, Λ)` — точна мінімальна відстань від `t` до ґратки.

### Ієрархія редукції: від LLL до BKZ та меж алгоритму

Хоча фактор наближення `2^{(n-1)/2}` є поліноміальним за часом, його абсолютне значення експоненційно зростає з розмірністю. Для `n = 100` фактор становить `2⁴⁹.⁵ ≈ 7.8 · 10¹⁴`, а для `n = 500` — астрономічні `2²⁴⁹.⁵`.

У криптографії та практичних обчисленнях застосовують ієрархію алгоритмів редукції:

```
[Швидкі, слабка якість]                               [Повільні, точний розв'язок]
LLL (δ = 0.75)  ───►  LLL (δ = 0.99)  ───►  BKZ-20  ───►  BKZ-60  ───►  Точний SVP
Час: O(n⁵)            Час: O(n⁵)           Час: 2^{O(20)}  Час: 2^{O(60)}    Час: 2^{O(n)}
Якість: δ₀ ≈ 1.0219   Якість: δ₀ ≈ 1.0185  Якість: 1.0128  Якість: 1.0065   Якість: 1.0000
```

Алгоритм **BKZ (Block Korkine-Zolotarev)**, розроблений Клаусом Шнорром, узагальнює LLL: замість пар сусідніх векторів він розглядає ковзні блоки розміру `β` (`2 ≤ β ≤ n`). Усередині кожного блоку запускається точний SVP-пошук (методом перебору або решіткового решета — lattice sieving), а зв'язок між блоками забезпечується стандартним LLL.

При цьому LLL залишається незамінним фундаментом: він використовується як обов'язковий етап попередньої обробки перед запуском BKZ, скорочуючи час роботи в тисячі разів.

### Практичні застосування в інженерії та криптографії

LLL-алгоритм став універсальним інструментом на стику чистої математики, криптографії та комп'ютерних наук.

![Криптоаналіз рюкзака](/book/math/algebra/lll-algorithm/img/lll-crypto-knapsack.svg)
*Криптоаналіз рюкзака через LLL: зведення задачі Subset Sum до пошуку найкоротшого вектора у спеціальній ґратці.*

#### 1. Факторизація многочленів над `ℚ[x]`
Історично перше призначення LLL. Многочлен `f(x) ∈ ℤ[x]` розкладають за простим модулем `p`, піднімають дільники до високого степеня `p^k` через лему Гензеля і будують ґратку коефіцієнтів многочленів, що діляться на модульний фактор `h(x) mod p^k`. 

Завдяки межі Міньотта справжній незвідний дільник `g(x) ∈ ℤ[x]` має малі коефіцієнти і є найкоротшим ненульовим вектором у цій ґратці. LLL знаходить цей многочлен за поліноміальний час, повністю усуваючи потребу в комбінаторному переборі системи Цассенгауза.

#### 2. Злам рюкзачних криптосистем (Subset Sum)
Задача знаходження двійкового повідомлення `x_i ∈ {0, 1}` із рівняння `∑ x_i a_i = S` зводиться до пошуку вектора `(2x_1 - 1, ..., 2x_n - 1, 0)` у ґратці розмірності `(n+1)`. Для будь-яких рюкзаків із низькою щільністю (`d < 0.9408`) LLL знаходить точний розв'язок за частки секунди.

Покрокову програмну реалізацію цієї атаки на C та C++ розібрано у практикумі: [практикум з реалізації LLL та зламу рюкзака](book:math/algebra/lll-algorithm/proj-lattice-reduction.md).

#### 3. Атака Копперсміта на криптосистему RSA
Дон Копперсміт застосував LLL для знаходження малих коренів рівняння `f(x) ≡ 0 mod N`. Метод базується на лемі Хаугрейва — Ґрехема: якщо для многочлена `h(x)` виконується нерівність `‖h(x · X)‖ < N^m / √d`, то будь-який модульний корінь `|x_0| < X` є строгим дійсним коренем `h(x_0) = 0` над `ℤ`. Це дозволяє зламати RSA з малим експонентом `e = 3`, відновити ключ при витоку бітів або факторизувати складені модулі з відомою структурою (атака ROCA).

#### 4. Знаходження цілочисельних лінійних залежностей
Якщо дано набір дійсних чисел `(α_1, ..., α_n)`, LLL знаходить ненульовий набір цілих чисел `m_i ∈ ℤ` таких, що `∑ m_i α_i ≈ 0`. Це дозволяє знаходити мінімальні многочлени для чисельно заданих алгебраїчних чисел та відкривати нові математичні тотожності (аналог алгоритму PSLQ).

#### 5. Одночасне діофантове наближення
За теоремою Діріхле, для будь-яких чисел `α_1, ..., α_n` та обмеження `Q > 1` існує спільний знаменник `q ≤ Q` такий, що `|q α_i - p_i| ≤ Q^{-1/n}`. LLL знаходить такий знаменник за поліноміальний час, зводячи задачу до редукції ґратки розмірності `n+1`.

#### 6. Цілочисельне лінійне програмування (ILP)
Хендрік Ленстра довів, що для будь-якої фіксованої розмірності `d` задачу цілочисельного лінійного програмування можна розв'язати за поліноміальний час за допомогою LLL-редукції простору обмежень (знаходження «тонкого напрямку» багатогранника).

#### 7. Постквантова криптографія (Kyber, Dilithium, NTRU)
У сучасній постквантовій криптографії задачі на ґратках (LWE, Short Integer Solution) є головним фундаментом стійкості проти квантових комп'ютерів. Стійкість стандартів NIST ML-KEM та ML-DSA оцінюється на основі складності редукції ґраток за допомогою LLL та його блочного узагальнення BKZ.

#### 8. Просторово-часове кодування та MIMO-декодування (5G/6G)
У сучасних бездротових мережах з багатьма передавальними та приймальними антенами (MIMO) задача розділення накладених сигналів від різних передавачів зводиться до задачі CVP у ґратці сигналів. Застосування швидкої LLL-редукції канальної матриці безпосередньо у сигнальних процесорах базових станцій дозволяє алгоритмам округлення Бабаї досягати пропускної здатності, близької до теоретичної межі Шеннона, в реальному часі.
