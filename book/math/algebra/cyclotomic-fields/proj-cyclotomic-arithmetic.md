# ⚙️ Арифметика в кругових кільцях і решіткова криптографія

Практична цінність кругової алгебри в сучасних обчисленнях зосереджена в галузі постквантової криптографії та надшвидкої цифрової обробки сигналів. Нові світові стандарти шифрування з відкритим ключем та електронного цифрового підпису (зокрема алгоритми CRYSTALS-Kyber / ML-KEM та CRYSTALS-Dilithium / ML-DSA, офіційно затверджені Національним інститутом стандартів і технологій США NIST) відмовилися від традиційної модульної арифметики великих цілих чисел RSA та алгебри еліптичних кривих. Їхньою математичною основою стала арифметика в поліноміальних фактор-кільцях над круговими полями.

Тут розібрано, як елементи кругового кільця `ℤ[ζₙ]` представляються у пам'яті комп'ютера, як круговий многочлен `Φₙ(x)` забезпечує згортку коефіцієнтів без виходу за межі фіксованого степеня, чому випадок степеня двійки `n = 2·N` породжує негациклічну згортку `xᴺ ≡ −1`, як влаштоване теоретико-числове перетворення Фур'є (NTT) зі схемами Кулі — Тьюкі та Джентльмена — Сенде, як працюють швидкі редуктори Монтгомері та Барретта, як семплюється малий шум із центрованого біноміального розподілу (CBD), як аналізується ймовірність помилки дешифрування, як досягти векторизації через SIMD-інструкції AVX2 / Neon, та як реалізувати швидку й захищену від атак по сторонніх каналах арифметику кругового фактор-кільця `ℤ_q[x] / (xᴺ + 1)` мовами C та C++.

### Чому постквантовий світ обрав кругові кільця

Класична криптографія з відкритим ключем (RSA, протокол Діффі — Геллмана, еліптичні криві ECDSA / Ed25519) тримається на двох числових задачах: факторизації великих складених чисел та обчисленні дискретного логарифма. Алгоритм Пітера Шора, запущений на масштабованому квантовому комп'ютері, розв'язує обидві ці задачі за поліноміальний час, що повністю руйнує безпеку сучасного інтернету.

Найперспективнішим захистом від квантових обчислень виявилася криптографія на евклідових решітках (англ. *lattice-based cryptography*). У її базовому варіанті — задачі навчання з помилками (LWE, Learning With Errors) — секретом є звичайний вектор `s ∈ ℤ_qᴺ`, а відкритим ключем — випадкова матриця `A ∈ ℤ_q^(M × N)` разом із вектором шуму `e`:

```
b = A · s + e      (mod q)
```

Хоча стандартний LWE є криптографічно стійким, він має катастрофічний інженерний недолік: матриця `A` містить сотні тисяч чисел. Розмір відкритого ключа досягає десятків і сотень кілобайтів, а множення матриці на вектор вимагає часу `O(N²)` або `O(M·N)`. Передавати такі ключі через протокол TLS у кожному веб-з'єднанні надто дорого для мережевої інфраструктури.

Вихід запропонувала кругова алгебра: замінити загальний простір `ℤ_qᴺ` на **кругове поліноміальне кільце** `R_q = ℤ_q[x] / (Φₘ(x))`. У кільцевому варіанті задачі (Ring-LWE / Module-LWE) замість прямокутної матриці `A` використовують один-єдиний многочлен `a(x) ∈ R_q`:

```
b(x) = a(x) · s(x) + e(x)      [у кільці ℤ_q[x] / (Φₘ(x))]
```

Цей перехід має фундаментальні наслідки:
1. **Стиснення ключів у `N` разів:** поліном `a(x)` ступеня `N − 1` повністю замінює квадратну матрицю розміру `N × N`. Розмір відкритого ключа падає з сотень кілобайтів до 1–2 кілобайтів.
2. **Прискорення множення з `O(N²)` до `O(N log N)`:** дискретна кругова згортка за допомогою теоретико-числового перетворення (NTT) виконується за лінійний за логарифмом час, дозволяючи процесору шифрувати й розшифровувати повідомлення за мікросекунди.
3. **Збереження математичної стійкості:** задача знаходження найкоротшого вектора в ідеальних решітках кругових полів (Shortest Vector Problem на ідеалах) залишається експоненційно складною як для класичних, так і для квантових алгоритмів.

### Поліноміальне представлення кругових чисел

Кільце цілих кругового поля `ℚ(ζₙ)` збігається з кільцем многочленів від одного генератора:

```
ℤ[ζₙ] = { a₀ + a₁·ζₙ + a₂·ζₙ² + ... + a[d−1]·ζₙ^(d−1)  |  a[j] ∈ ℤ }
де d = deg(Φₙ) = φ(n)
```

Будь-який елемент цього кільця зберігається у пам'яті як масив або вектор довжини `d = φ(n)`, складений із цілочисельних коефіцієнтів `(a₀, a₁, ..., a[d−1])`.

Додавання двох таких елементів є звичайним поелементним додаванням відповідних векторів:

```
(a + b)[j] = a[j] + b[j]      [для всіх 0 ≤ j < d]
```

Множення є складнішим і складається з двох послідовних кроків:
1. **Звичайне поліноміальне множення (згортка):** обчислюється добуток двох многочленів `c(x) = a(x) · b(x)`. Якщо вихідні многочлени мали ступінь `< d`, їхній добуток матиме ступінь `< 2·d − 1`:
```
c[k] = ∑[i + j = k] a[i] · b[j]      [для 0 ≤ k < 2·d − 1]
```
2. **Кругова редукція:** оскільки генератор задовольняє рівняння `Φₙ(ζₙ) = 0`, отриманий многочлен `c(x)` ділять з остачею на круговий многочлен `Φₙ(x)`:
```
c(x) = q(x) · Φₙ(x) + r(x)      [де deg(r) < deg(Φₙ) = d]
```

Остача `r(x)` і є шуканим добутком у круговому кільці `ℤ[ζₙ]`.

### Негациклічна згортка: випадок n = 2·N (степінь двійки)

Найважливішим для комп'ютерної інженерії є випадок, коли порядок кореня `n` є степенем двійки: `n = 2·N`, де `N = 2ᵏ⁻¹` (наприклад, `n = 512`, `N = 256 = 2⁸`).

Для такого індексу круговий многочлен має максимально простий двочленний вигляд:

```
Φ[2N](x) = xᴺ + 1      [ступінь d = N = φ(2N)]
```

Рівність `Φ[2N](x) = 0` означає фундаментальне алгебраїчне правило заміни:

```
xᴺ ≡ −1
```

Будь-який вищий степінь змінної редукується зі зміною знака:

```
x^(N + k) = xᴺ · xᵏ ≡ −xᵏ      [для будь-якого 0 ≤ k < N]
```

Завдяки цьому ділення многочлена `c(x) = c₀ + c₁·x + ... + c[2N−2]·x^(2N−2)` на `xᴺ + 1` не потребує тривалого ділення в стовпчик. Воно зводиться до миттєвого віднімання старшої половини коефіцієнтів від молодшої:

```
r[k] = c[k] − c[k + N]      [для всіх 0 ≤ k < N]
```

Така операція називається **негациклічною згорткою** (англ. *negacyclic convolution*). Вона виконується за лінійний час `O(N)` після обчислення звичайного добутку коефіцієнтів і не створює жодних дробових числових значень.

Множення двох елементів у фактор-кільці `ℤ_q[x] / (xᴺ + 1)` відповідає дії лінійного оператора множення на негациркулянтну матрицю:

```
[ r₀     ]   [  a₀   −a_{N-1}  −a_{N-2}  ...  −a₁  ]   [ b₀     ]
[ r₁     ]   [  a₁     a₀      −a_{N-1}  ...  −a₂  ]   [ b₁     ]
[ r₂     ] = [  a₂     a₁        a₀      ...  −a₃  ] · [ b₂     ]   (mod q)
[ ...    ]   [ ...    ...       ...      ...  ...  ]   [ ...    ]
[ r_{N-1}]   [ a_{N-1} a_{N-2}  a_{N-3}  ...   a₀  ]   [ b_{N-1}]
```

Зверніть увагу на структуру матриці: кожен наступний стовпчик отримується з попереднього циклічним зсувом униз, а елемент, що випадає з нижнього рядка і переходить у верхній, змінює знак на протилежний. Це геометричне втілення правила `xᴺ ≡ −1`.

### Порівняння з нестепеневими круговими кільцями

Чому інженери криптографії майже завжди обирають саме `Φ₂ₙ(x) = xᴺ + 1`, а не довільний круговий многочлен `Φₚ(x)` для простого числа `p`?

Розгляньмо для порівняння просте число `p = 5`. Відповідний круговий многочлен дорівнює:

```
Φ₅(x) = x⁴ + x³ + x² + x + 1
```

Правило редукції тут вимагає заміни:

```
x⁴ ≡ −x³ − x² − x − 1
```

Якщо при перемноженні двох многочленів степеня 3 виникає член `x⁶`, його редукція є багатоступеневою:
```
x⁶ = x² · x⁴ ≡ x² · (−x³ − x² − x − 1) = −x⁵ − x⁴ − x³ − x²
   = −x · x⁴ − x⁴ − x³ − x²
   ≡ −x · (−x³ − x² − x − 1) − (−x³ − x² − x − 1) − x³ − x²
   = (x⁴ + x³ + x² + x) + (x³ + x² + x + 1) − x³ − x²
   ≡ (−x³ − x² − x − 1) + x³ + x² + 2·x + 1 = x
```

Кожен вищий степінь породжує розсип кількох доданків із різними коефіцієнтами. Це вимагає значно більше операцій додавання та множення.

Ба більше, ступінь `deg(Φₚ) = p − 1` для простого `p > 2` завжди є парним числом, але **ніколи не є степенем двійки** (крім випадків простих чисел Ферма `p = 2^(2^k) + 1`). Це унеможливлює використання стандартного, високоефективного двійкового алгоритму ШПФ Кулі — Тьюкі без громіздких доповнень нулями чи алгоритму Блюстайна.

Саме тому кільця `ℤ_q[x] / (xᴺ + 1)` зі степенем двійки `N = 2ᵏ` стали стандартом де-факто: вони забезпечують ідеальну простоту редукції та максимальну швидкість обчислень.

### Теоретико-числове перетворення (NTT) у круговому кільці

Пряме обчислення негациклічної згортки через вкладені цикли вимагає `N²` множень. Щоб прискорити цю операцію до `O(N log N)`, застосовують теоретико-числове перетворення (NTT, Number Theoretic Transform) — аналог швидкого перетворення Фур'є (ШПФ) над скінченним полем `ℤ_q`.

**Алгебраїчна умова існування NTT:**
У скінченному полі `ℤ_q` повинен існувати примітивний корінь `2N`-го степеня з одиниці `ω ∈ ℤ_q` такий, що:

```
ω^(2N) ≡ 1 (mod q)   і   ωᴺ ≡ −1 (mod q)
```

За теоремою про циклічність мультиплікативної групи скінченного поля `(ℤ_q)*` такий елемент існує тоді й тільки тоді, коли модуль `q` задовольняє умову:

```
q ≡ 1 (mod 2N)
```

Саме тому в алгоритмі Kyber обрано `N = 256` та просте число `q = 3329`: число `2N = 512`, а `3329 = 13 · 256 + 1 = 6 · 512 + 257`, тобто в розширенні `ℤ_q` многочлен `x²⁵⁶ + 1` повністю розпадається на лінійні множники або квадратичні блоки.

У полі `ℤ_q` многочлен `xᴺ + 1` розкладається на `N` лінійних множників:

```
xᴺ + 1 = (x − ω¹) · (x − ω³) · (x − ω⁵) · ... · (x − ω^(2N−1))
```

За китайською теоремою про залишки (CRT) для многочленів, кругове фактор-кільце розпадається на прямий добуток одновимірних полів:

```
ℤ_q[x] / (xᴺ + 1) ≅ ℤ_q × ℤ_q × ... × ℤ_q      (N копій поля ℤ_q)
```

Пряме перетворення NTT обчислює значення многочлена `a(x)` у непарних степенях кореня `ω`:

```
â[k] = a(ω^(2k + 1)) = ∑[j=0..N−1] a[j] · ω^((2k + 1)·j)      [для 0 ≤ k < N]
```

У цій формі множення двох кругових многочленів стає **поточковим множенням векторів** довжини `N`:

```
ĉ[k] = â[k] · b̂[k] (mod q)      [для всіх 0 ≤ k < N]
```

Після цього обернене перетворення NTT повертає коефіцієнти результуючого многочлена:

```
c(x) = NTT⁻¹( ĉ )
```

### «Метелики» Кулі — Тьюкі та Джентльмена — Сенде

Обчислення NTT виконується за допомогою каскаду операцій над парами коефіцієнтів, які називають «метеликами» (англ. *butterfly operations*).

1. **Метелик Кулі — Тьюкі (CT Butterfly):**
Використовується в прямому перетворенні NTT. Приймає коефіцієнти `u` та `v` у часовій області й поворотний множник `ζ`:
```
u' = u + ζ · v      (mod q)
v' = u − ζ · v      (mod q)
```

2. **Метелик Джентльмена — Сенде (GS Butterfly):**
Використовується в оберненому перетворенні INTT. Множення на поворотний множник виконується після віднімання:
```
u' = u + v          (mod q)
v' = (u − v) · ζ    (mod q)
```

Комбінація прямого CT-перетворення з інверсним бітовим порядком коефіцієнтів та зворотного GS-перетворення дозволяє повністю **уникнути операцій бітової перестановки (bit-reversal permutation)** у пам'яті. Коефіцієнти природно перегруповуються в правильний порядок під час зворотного проходу, що заощаджує до 20% процесорного часу.

### Швидка модульна арифметика: редуктори Монтгомері та Барретта

Усередині NTT та негациклічної згортки найповільнішою операцією процесора є ділення на модуль `q` (інструкція `DIV` або `IDIV` вимагає від 15 до 40 тактів процесора і часто виконується з непостійним часом). Для усунення операції ділення використовують модульні редуктори.

**1. Редукція Барретта (Barrett Reduction):**
Ідея полягає в заміні ділення на `q` множенням на попередньо обчислену константу `μ = floor(2ᵏ / q)` зі зсувом вправо на `k` бітів:

```
q̂ = (a · μ) >> k
r = a − q̂ · q
if (r ≥ q) r −= q
```

Це зводить обчислення остачі до одного 64-бітного множення, одного бітового зсуву та одного віднімання.

**2. Редукція Монтгомері (Montgomery Reduction):**
Числа представляють у формі Монтгомері `ã = a · R mod q`, де `R = 2¹⁶` або `R = 2³²` — ступінь двійки, взаємно простий із `q`.

Функція `REDC(T)` обчислює `T · R⁻¹ mod q` без жодного ділення:
```
m = (T mod R) · q' mod R      [де q' = −q⁻¹ mod R]
t = (T + m · q) / R           [число T + m·q точно ділиться на R, тому ділення є зсувом >>]
if (t ≥ q) t −= q
return t
```

Усі проміжні коефіцієнти поліномів під час обчислення NTT тримають у формі Монтгомері, виконуючи швидке приведення за 1–2 такти процесора.

### Генерація шуму та центрований біноміальний розподіл (CBD)

У криптосистемах Ring-LWE безпека ґрунтується на тому, що секретний вектор `s(x)` та вектор помилки `e(x)` не є рівномірно випадковими в `ℤ_q`, а вибираються з «малими» коефіцієнтами. Якщо шум буде нульовим, систему лінійних рівнянь легко розв'язати методом Гаусса; якщо ж шум буде завеликим, правильне повідомлення неможливо буде розшифрувати.

Для генерації шуму використовують **центрований біноміальний розподіл** `CBD_η` (англ. *Centered Binomial Distribution*).

Кожен коефіцієнт `e[i]` формується з `2·η` випадкових бітів `(a₁, ..., a[η])` та `(b₁, ..., b[η])`, отриманих із криптографічної геш-функції SHAKE-256:

```
e[i] = ∑[j=1..η] a[j] − ∑[j=1..η] b[j]
```

Значення `e[i]` лежить у строго обмеженому симетричному діапазоні `[−η, +η]` з математичним сподіванням 0.
- У Kyber-512 параметр `η = 3`, тому коефіцієнти шуму набувають значень від −3 до +3.
- У Kyber-768 параметр `η = 2`, коефіцієнти від −2 до +2.

Такий розподіл ідеально моделює дискретний гауссівський розподіл, але генерується в константному часі за допомогою простих побітових операцій без повільних обчислень дійсних чисел із плаваючою комою.

### Ймовірність помилки дешифрування та геометрія шумів

Під час розшифрування повідомлення в протоколі Kyber обчислюється різниця:

```
v − sᵀ · u = (m · ⌊q/2⌉ + e' + sᵀ · e'') − sᵀ · (A · r + e)
           = m · ⌊q/2⌉ + (e' + sᵀ · e'' − sᵀ · e)
           = m · ⌊q/2⌉ + e_total
```

Щоб правильно відновити біт повідомлення `m ∈ {0, 1}`, загальний шум `e_total` за абсолютною величиною не повинен перевищувати поріг `q / 4 ≈ 832`. Завдяки тому, що коефіцієнти шумів і секретів обмежені константою `η ≤ 3`, а розмірність `N = 256`, імовірність виходу шуму за поріг становить менше ніж `2⁻¹⁴⁰`, що гарантує безпомилкову роботу системи протягом усього життєвого циклу.

### Векторизація SIMD та сучасні процесорні архітектури

Реальна продуктивність кругової арифметики на серверах і мобільних пристроях досягається через паралелізм рівня інструкцій (SIMD — Single Instruction, Multiple Data):

1. **Упаковка коефіцієнтів у 256-бітні регістри AVX2 (`__m256i`):**
Оскільки модуль `q = 3329` уміщується у 16-бітне знакове ціле (`int16_t`), один векторний регістр `ymm` вміщує рівно 16 коефіцієнтів многочлена. Увесь масив із 256 коефіцієнтів кругового полінома займає лише 16 векторних регістрів процесора.

2. **Паралельні метелики:**
Інструкції `_mm256_add_epi16`, `_mm256_sub_epi16` та помножувачі `_mm256_mullo_epi16` / `_mm256_mulhi_epi16` виконують одразу 16 операцій метелика за один машинний такт.

3. **Підсумок продуктивності:**
Завдяки круговій структурі `x²⁵⁶ + 1` одне ядро сучасного процесора x86-64 або ARM Cortex-A78 здатне виконувати понад 150 000 повних операцій шифрування Kyber на секунду, що на два порядки перевищує швидкість класичного RSA-2048.

### Модульні рівні безпеки в стандартах NIST

У стандарті FIPS 203 (ML-KEM / Kyber) кругове кільце `R_q = ℤ₃₃₂₉[x] / (x²⁵⁶ + 1)` є єдиним і незмінним будівельним блоком для всіх трьох категорій безпеки. Рівень криптографічної стійкості масштабується не збільшенням розмірності кільця, а зміною розміру матриці модулів (Module-LWE):

- **ML-KEM-512 (Рівень безпеки NIST 1, еквівалент AES-128):** використовує матрицю розміром `2 × 2` над кільцем `R_q` (разом 512 коефіцієнтів).
- **ML-KEM-768 (Рівень безпеки NIST 3, еквівалент AES-192):** використовує матрицю розміром `3 × 3` над кільцем `R_q` (разом 768 коефіцієнтів). Рекомендований дефолтний вибір для більшості застосунків.
- **ML-KEM-1024 (Рівень безпеки NIST 5, еквівалент AES-256):** використовує матрицю розміром `4 × 4` над кільцем `R_q` (разом 1024 коефіцієнти).

Усі три рівні безпеки використовують однаковий базовий код арифметики поліномів у кільці `R_q`, що значно спрощує верифікацію програмного забезпечення та створення апаратних прискорювачів.

### Реалізація арифметики кругових кілець на C та C++

Наведемо повну, працездатну реалізацію арифметики в круговому кільці `ℤ_q[x] / (xᴺ + 1)`. Для наочності розрахунків оберемо розмірність `N = 8` та модуль `q = 97` (просте число, що задовольняє умову `q ≡ 1 mod 2N`, оскільки `97 = 6 · 16 + 1`). Реалізація містить додавання, віднімання, пряме негациклічне множення, скалярне множення та приведення коефіцієнтів за модулем.

```c
#include <stdint.h>
#include <stdbool.h>
#include <stdio.h>
#include <string.h>

#define RING_N 8
#define RING_Q 97

/* Структура полінома в круговому кільці Z_q[x] / (x^N + 1) */
typedef struct {
    int32_t coeffs[RING_N];
} CycloPoly;

/* Канонічне приведення за модулем q до діапазону [0, q - 1] */
static inline int32_t mod_q(int32_t val) {
    int32_t r = val % RING_Q;
    if (r < 0) {
        r += RING_Q;
    }
    return r;
}

/* Ініціалізація полінома нулями */
void poly_init_zero(CycloPoly *p) {
    for (size_t i = 0; i < RING_N; ++i) {
        p->coeffs[i] = 0;
    }
}

/* Додавання двох поліномів: out = (a + b) mod q */
void poly_add(CycloPoly *out, const CycloPoly *a, const CycloPoly *b) {
    for (size_t i = 0; i < RING_N; ++i) {
        out->coeffs[i] = mod_q(a->coeffs[i] + b->coeffs[i]);
    }
}

/* Віднімання двох поліномів: out = (a - b) mod q */
void poly_sub(CycloPoly *out, const CycloPoly *a, const CycloPoly *b) {
    for (size_t i = 0; i < RING_N; ++i) {
        out->coeffs[i] = mod_q(a->coeffs[i] - b->coeffs[i]);
    }
}

/* Множення полінома на скаляр: out = (a * scalar) mod q */
void poly_scalar_mul(CycloPoly *out, const CycloPoly *a, int32_t scalar) {
    int32_t s = mod_q(scalar);
    for (size_t i = 0; i < RING_N; ++i) {
        out->coeffs[i] = mod_q(a->coeffs[i] * s);
    }
}

/* Кругове множення за модулем Phi_{2N}(x) = x^N + 1: out = (a * b) mod (x^N + 1, q) */
void poly_mul_cyclotomic(CycloPoly *out, const CycloPoly *a, const CycloPoly *b) {
    int64_t prod[2 * RING_N];
    for (size_t i = 0; i < 2 * RING_N; ++i) {
        prod[i] = 0;
    }

    /* 1. Звичайне множення поліномів (згортка) */
    for (size_t i = 0; i < RING_N; ++i) {
        for (size_t j = 0; j < RING_N; ++j) {
            prod[i + j] += (int64_t)a->coeffs[i] * (int64_t)b->coeffs[j];
        }
    }

    /* 2. Негациклічна редукція x^N = -1 та приведення mod q */
    for (size_t i = 0; i < RING_N; ++i) {
        int64_t low = prod[i];
        int64_t high = prod[i + RING_N];
        int32_t reduced = (int32_t)((low - high) % RING_Q);
        out->coeffs[i] = mod_q(reduced);
    }
}

/* Друк полінома */
void poly_print(const char *label, const CycloPoly *p) {
    printf("%s: [", label);
    for (size_t i = 0; i < RING_N; ++i) {
        printf("%d%s", p->coeffs[i], (i + 1 < RING_N) ? ", " : "");
    }
    printf("]\n");
}

int main(void) {
    CycloPoly a, b, sum, prod;
    poly_init_zero(&a);
    poly_init_zero(&b);

    /* a(x) = 3 + 2x + x^7 */
    a.coeffs[0] = 3;
    a.coeffs[1] = 2;
    a.coeffs[7] = 1;

    /* b(x) = 5 + 4x^2 + 2x^7 */
    b.coeffs[0] = 5;
    b.coeffs[2] = 4;
    b.coeffs[7] = 2;

    poly_add(&sum, &a, &b);
    poly_mul_cyclotomic(&prod, &a, &b);

    printf("=== Арифметика в круговому кільці Z_%d[x] / (x^%d + 1) ===\n", RING_Q, RING_N);
    poly_print("a(x)", &a);
    poly_print("b(x)", &b);
    poly_print("a(x) + b(x)", &sum);
    poly_print("a(x) * b(x) mod (x^8 + 1)", &prod);

    return 0;
}
```

```cpp
#include <iostream>
#include <array>
#include <vector>
#include <span>
#include <cstdint>
#include <string_view>

template <size_t N, int32_t Q>
class CycloPoly {
public:
    static constexpr size_t Dimension = N;
    static constexpr int32_t Modulus = Q;

    std::array<int32_t, N> coeffs{};

    constexpr CycloPoly() = default;

    constexpr CycloPoly(std::initializer_list<int32_t> list) {
        size_t idx = 0;
        for (auto val : list) {
            if (idx >= N) break;
            coeffs[idx++] = normalize(val);
        }
    }

    static constexpr int32_t normalize(int32_t val) noexcept {
        int32_t r = val % Q;
        return (r < 0) ? (r + Q) : r;
    }

    CycloPoly operator+(const CycloPoly& other) const noexcept {
        CycloPoly res;
        for (size_t i = 0; i < N; ++i) {
            res.coeffs[i] = normalize(coeffs[i] + other.coeffs[i]);
        }
        return res;
    }

    CycloPoly operator-(const CycloPoly& other) const noexcept {
        CycloPoly res;
        for (size_t i = 0; i < N; ++i) {
            res.coeffs[i] = normalize(coeffs[i] - other.coeffs[i]);
        }
        return res;
    }

    CycloPoly operator*(int32_t scalar) const noexcept {
        CycloPoly res;
        int32_t s = normalize(scalar);
        for (size_t i = 0; i < N; ++i) {
            res.coeffs[i] = normalize(coeffs[i] * s);
        }
        return res;
    }

    /* Негациклічне множення за модулем x^N + 1 та Q */
    CycloPoly operator*(const CycloPoly& other) const noexcept {
        std::array<int64_t, 2 * N> prod{};

        /* 1. Згортка коефіцієнтів */
        for (size_t i = 0; i < N; ++i) {
            for (size_t j = 0; j < N; ++j) {
                prod[i + j] += static_cast<int64_t>(coeffs[i]) * static_cast<int64_t>(other.coeffs[j]);
            }
        }

        /* 2. Негациклічна редукція: x^(N + k) = -x^k */
        CycloPoly res;
        for (size_t i = 0; i < N; ++i) {
            int64_t diff = prod[i] - prod[i + N];
            res.coeffs[i] = normalize(static_cast<int32_t>(diff % Q));
        }
        return res;
    }

    void print(std::string_view label) const {
        std::cout << label << ": [";
        for (size_t i = 0; i < N; ++i) {
            std::cout << coeffs[i] << (i + 1 < N ? ", " : "");
        }
        std::cout << "]\n";
    }
};

int main() {
    using Ring8 = CycloPoly<8, 97>;

    Ring8 a{3, 2, 0, 0, 0, 0, 0, 1}; // a(x) = 3 + 2x + x^7
    Ring8 b{5, 0, 4, 0, 0, 0, 0, 2}; // b(x) = 5 + 4x^2 + 2x^7

    auto sum = a + b;
    auto prod = a * b;

    std::cout << "=== C++ Арифметика в круговому кільці Z_97[x] / (x^8 + 1) ===\n";
    a.print("a(x)");
    b.print("b(x)");
    sum.print("a(x) + b(x)");
    prod.print("a(x) * b(x) mod (x^8 + 1)");

    return 0;
}
```

### Покроковий розбір обчислення добутку

Простежмо вручну, чому множення двох конкретних членів дає саме такий результат.

Нехай `a(x) = x⁷` та `b(x) = 2·x⁷` у кільці `ℤ₉₇[x] / (x⁸ + 1)`.

1. Звичайний алгебраїчний добуток:
```
c(x) = a(x) · b(x) = 1·x⁷ · 2·x⁷ = 2·x¹⁴
```

2. Розклад степеня за модулем кругового многочлена `x⁸ + 1`:
```
x¹⁴ = x⁸ · x⁶
    ≡ (−1) · x⁶      [оскільки x⁸ ≡ −1]
    = −x⁶
```

3. Множення на коефіцієнт та приведення за модулем `q = 97`:
```
2·x¹⁴ ≡ 2·(−x⁶) = −2·x⁶
−2 ≡ 97 − 2 = 95 (mod 97)
отже: x⁷ · 2·x⁷ ≡ 95·x⁶
```

Старший степінь `x¹⁴` без жодного ділення в стовпчик перетворився на член шостого степеня `95·x⁶` зі зміною знака.

### Інженерні пастки та захист від атак

Під час реалізації кругової арифметики на практиці виникають чотири критичні проблеми безпеки та продуктивності:

1. **Проміжне переповнення цілих чисел:**
Під час множення многочленів кожен коефіцієнт `prod[k]` є сумою до `N` добутків вигляду `a[i] · b[j]`. Якщо коефіцієнти лежать у межах `[0, q − 1]`, максимальне значення суми становить приблизно `N · q²`.
- Для `N = 256` та `q = 3329` (Kyber): `256 · 3329² ≈ 2.83 · 10⁹`.
- Це значення перевищує максимальне додатне значення стандартного 32-бітного знакового цілого (`2³¹ − 1 ≈ 2.14 · 10⁹`).
- **Рішення:** акумулювання добутків виконується виключно у 64-бітних змінних (`int64_t` / `uint64_t`) або за допомогою швидкого модульного редуктора Монтгомері / Барретта після кожної операції.

2. **Вразливість до атак за часом виконання (Side-Channel Timing Attacks):**
Звичайна операція взяття остачі від ділення `val % q` або умовний перехід `if (r < 0) r += q` на багатьох процесорах виконується за змінну кількість тактів залежно від значення операндів. Якщо час виконання залежить від коефіцієнтів таємного ключа, зловмисник може відновити ключ через аналіз часу відповіді сервера.
- **Рішення:** усі криптографічні операції кругової редукції пишуться в константному часі (англ. *constant-time*), з використанням безрозгалуженої бітової магії (наприклад, додавання модуля через маску знакового біта: `val -= q; val += (val >> 31) & q;`).

3. **Коректне приведення від'ємних чисел:**
Оператор `%` у мовах C та C++ обчислює усічене ділення, де остача для від'ємного числа залишається від'ємною (`-5 % 97 = -5`). У математиці кільця лишків `ℤ_q` значення мусить лежати в діапазоні `[0, q − 1]`. Завжди потрібна нормалізація `r = (val % q + q) % q` або безрозгалужений еквівалент.

4. **Кеш-атаки на таблиці синусів/косинусів (Twiddle Factors):**
Під час обчислення NTT коефіцієнти степенів `ω` зберігають у попередньо обчислених масивах. Якщо доступ до таблиці виконується за індексами, що залежать від секретних даних, процесорний кеш видає різний час доступу. Використання лінійного сканування пам'яті або векторних інструкцій AVX-512 / ARM Neon усуває цей канал витоку.
