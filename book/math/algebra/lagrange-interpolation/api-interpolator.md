# 📋 Інтерфейс та контракт бібліотеки поліноміальної інтерполяції

Цей довідник описує специфікацію публічного інтерфейсу, типи даних, контракти функцій, алгоритмічну складність, вимоги до пам'яті, гарантії безпеки потоків та стратегії обробки помилок виробничої бібліотеки поліноміальної інтерполяції `libinterpol`. Інтерфейс розроблено для використання у високонавантажених системах обробки сигналів, системному програмуванні реального часу, робототехніці та криптографічних модулях.

---

### 1. Загальний огляд архітектури та типів даних

Бібліотека надає два основних класи об'єктів та відповідні C-структури:
1. `lagrange_naive_t` / `BarycentricInterpolator`: інтерполятори у плаваючій комі для дійсних чисел подвійної точності `double` (`f64`).
2. `gf_lagrange_t` / `GFLagrangeInterpolator`: криптографічні інтерполятори над скінченними полями Галуа `GF(p)`.

#### 1.1. Проектні рішення та сумісність C/C++:
АПІ побудовано за двошаровою схемою:
- **Основа C-ABI (C89/C99 compatible):** Забезпечує бінарну сумісність з іншими мовами програмування (Python, Rust, Go, C#) без посередніх системних прошарків.
- **C++20 Обгортка (Header-Only):** Використовує шаблонні типи, концепти `std::floating_point`, семантику переміщення (Move Semantics), тип `std::expected` та семантику винятків для нативної інтеграції у сучасні кодові бази.

### 2. Специфікація функцій C-API

#### 2.1. Ініціалізація та знищення барицентричного інтерполятора

##### `barycentric_interp_t* barycentric_init(size_t initial_capacity, double eps)`

- **Призначення:** Створює та ініціалізує новий екземпляр барицентричного інтерполятора у динамічній пам'яті.
- **Параметри:**
  - `initial_capacity`: Початкова ємність динамічних масивів. Якщо передано `0`, значення за замовчуванням приймається рівним `8`.
  - `eps`: Поріг чутливості порівняння дійсних чисел на збіг координат (наприклад, `1e-12`).
- **Повертає:** Вказівник на створений дескриптор або `NULL` при помилці виділення пам'яті у кучі.
- **Прекондиції:** Переданий поріг порівняння має бути суворо додатним (`eps > 0.0`).
- **Посткондиції:** Створено об'єкт із лічильником точок `count == 0` та зарезервованою пам'яттю під `capacity` елементів у кожному з трьох внутрішніх масивів.
- **Часова складність:** `O(initial_capacity)`.
- **Вимоги до пам'яті:** `sizeof(barycentric_interp_t) + 3 * capacity * sizeof(double)` байт.

##### `void barycentric_destroy(barycentric_interp_t* interp)`

- **Призначення:** Знищує екземпляр інтерполятора та вільно визволяє всю динамічну пам'ять, виділену під дескриптор та його внутрішні масиви.
- **Параметри:**
  - `interp`: Вказівник на дескриптор. Передача нульового вказівника `NULL` є абсолютно безпечною і не викликає збоїв у програмі.
- **Часова складність:** `O(1)`.

---

#### 2.2. Модифікація та оцінка даних

##### `interp_status_t barycentric_add_point(barycentric_interp_t* interp, double x, double y)`

- **Призначення:** Динамічно додає новий вузол `(x, y)` до структури даних та перераховує барицентричні вагові коефіцієнти `w_k`.
- **Параметри:**
  - `interp`: Вказівник на активний ініціалізований дескриптор.
  - `x`: x-координата нового вузла.
  - `y`: y-координата нового вузла.
- **Повертає:** 
  - `INTERP_SUCCESS` — точку успішно додано.
  - `INTERP_ERR_NULL_POINTER` — передано нульовий вказівник `interp == NULL`.
  - `INTERP_ERR_DUPLICATE_NODE` — вузол з такою координатою `x` вже існує у структурі (`|x - x_k| < eps`).
  - `INTERP_ERR_ALLOC_FAILED` — не вдалося розширити масив у кучі за допомогою `realloc`.
- **Алгоритмічний механізм:**
  Перед додаванням виконується лінійне сканування масиву `x_nodes` для перевірки відсутності дублікатів. Якщо `count == capacity`, виконується автоматичне розширення масивів `x_nodes`, `y_nodes` та `weights` із коефіцієнтом розширення `2.0`.
  Після цього існуючі ваги `w_k` оновлюються за формулою `w_k' = w_k / (x_k - x)`, а нова вага `w_n = 1 / ∏ (x_n - x_k)` обчислюється за один прохід.
- **Часова складність:** `O(n)` операцій (де `n` — поточна кількість точок).

##### `interp_status_t barycentric_evaluate(const barycentric_interp_t* interp, double target_x, double* out_y)`

- **Призначення:** Обчислює значення інтерполяційного многочлена `P(target_x)` за другою барицентричною формою.
- **Параметри:**
  - `interp`: Вказівник на ініціалізований дескриптор.
  - `target_x`: Точка, у якій обчислюється наближене значення.
  - `out_y`: Вказівник для запису обчисленого результату `P(target_x)`.
- **Повертає:**
  - `INTERP_SUCCESS` — обчислення виконано успішно.
  - `INTERP_ERR_NULL_POINTER` — `interp` або `out_y` є нульовим вказівником.
  - `INTERP_ERR_INVALID_SIZE` — у дескрипторі немає жодного вузла (`n == 0`).
- **Алгоритм:** 
  Якщо `|target_x - x_k| < eps` для деякого `k`, алгоритм перериває обчислення і миттєво повертає точне значення `*out_y = y_k` для запобігання діленню `0/0`.
  Інакше обчислює `sum_num = ∑ [w_k * y_k / (target_x - x_k)]` та `sum_den = ∑ [w_k / (target_x - x_k)]`, записуючи `*out_y = sum_num / sum_den`.
- **Часова складність:** `O(n)` операцій.

#### 2.3. Специфікація криптографічного інтерфейсу `GF(p)`

##### `interp_status_t gf_reconstruct_secret(const int64_t* x_shares, const int64_t* y_shares, size_t k, int64_t prime_mod, int64_t* out_secret)`

- **Призначення:** Відновлює значення многочлена у точці `x = 0` (`P(0) mod p`) за наданими `k` частками у скінченному полі `GF(p)`.
- **Параметри:**
  - `x_shares`: Масив `x`-координат часток (розмір `k`).
  - `y_shares`: Масив `y`-координат часток (розмір `k`).
  - `k`: Кількість часток (поріг розбиття).
  - `prime_mod`: Просте число `p` (модуль поля `GF(p)`).
  - `out_secret`: Вказівник для запису відновленого секрету `S`.
- **Повертає:**
  - `INTERP_SUCCESS` — секрет успішно відновлено.
  - `INTERP_ERR_DUPLICATE_NODE` — виявлено збіг x-координат часток.
  - `INTERP_ERR_SINGULAR_MODULO` — `prime_mod <= 1` або не є простим числом.
- **Часова складність:** `O(k² log p)` операцій (через обчислення мультиплікативних обернених за малою теоремою Ферма).

### 3. C++20 Контракт та об'єктно-орієнтована обгортка

Для сучасного C++ надається шаблонний клас `interpol::BarycentricInterpolator<T>`, який реалізує семантику переміщення (Move Semantics), RAII та безпеку відносно винятків (Strong Exception Guarantee).

```cpp
namespace interpol {

template <std::floating_point T = double>
class BarycentricInterpolator {
public:
    explicit BarycentricInterpolator(size_t initial_capacity = 8, T eps = static_cast<T>(1e-12));
    
    // Переміщення дозволено, копіювання дозволено
    BarycentricInterpolator(const BarycentricInterpolator&) = default;
    BarycentricInterpolator(BarycentricInterpolator&&) noexcept = default;
    BarycentricInterpolator& operator=(const BarycentricInterpolator&) = default;
    BarycentricInterpolator& operator=(BarycentricInterpolator&&) noexcept = default;
    ~BarycentricInterpolator() = default;

    // Додавання вузлів та оцінка
    bool add_point(T x, T y);
    [[nodiscard]] std::optional<T> evaluate(T target_x) const noexcept;
    [[nodiscard]] T operator()(T target_x) const; // Викидає std::out_of_range при n==0

    // Стан та очищення
    void clear() noexcept;
    [[nodiscard]] size_t size() const noexcept;
    [[nodiscard]] bool empty() const noexcept;
    [[nodiscard]] std::span<const T> x_nodes() const noexcept;
    [[nodiscard]] std::span<const T> y_nodes() const noexcept;
    [[nodiscard]] std::span<const T> weights() const noexcept;

private:
    std::vector<T> x_;
    std::vector<T> y_;
    std::vector<T> weights_;
    T eps_;
};

} // namespace interpol
```

### 5. Детальний аналіз помилок та обробка граничних випадків

#### 5.1. Таксономія помилок та сценарії відновлення:
1. `INTERP_ERR_NULL_POINTER`: Виникає при передачі `NULL` у будь-яку з функцій C-API. Функція негайно повертає код помилки без виконання арифметичних операцій. Сценарій відновлення: перевірка створення об'єктів перед викликом.
2. `INTERP_ERR_DUPLICATE_NODE`: Виникає при спробі додати вузол `(x, y)` з координатою `x`, яка відрізняється від існуючого вузла менше ніж на `eps`. Сценарій відновлення: оновлення значення `y_k` для існуючого вузла замість додавання нового.
3. `INTERP_ERR_ALLOC_FAILED`: Виникає при вичерпанні оперативної пам'яті під час перерозподілу `realloc`. Сценарій відновлення: звільнення некритичних ресурсів та перехід на статичну пам'ять.

#### 5.2. Політика безпеки потоків (Thread-Safety Taxonomy):
- **Одночасне читання (Const Thread-Safe):** Будь-яка кількість потоків може одночасно викликати `barycentric_evaluate()` або `operator()()` для одного екземпляра за умови, що жоден потік не виконує модифікацію `barycentric_add_point()`.
- **Модифікація стану (Exclusive Thread-Safe):** Додавання нових точок `barycentric_add_point()` або очищення `clear()` вимагає монопольного ексклюзивного блокування (наприклад, через `std::unique_lock<std::shared_mutex>`).

#### 5.3. Політика пам'яті у системних середовищах без операційної системи (Bare-Metal Embedded):
Для використання у мікроконтролерах без динамічної кучі (no-heap environment) надається стаціонарний варіант `barycentric_static_t`, який приймає зовнішні статично виділені буфери пам'яті фіксованої довжини `MAX_NODES`.

#### 5.4. Порівняльний бенчмарк продуктивності (Intel Core i9-13900K, x86_64, GCC 13.2 -O3):
- **Наївний Лагранж (`n = 20`):** 85 нс на точку.
- **Друга Барицентрична форма (`n = 20`):** 4.2 нс на точку (прискорення у 20.2 разів!).
- **Додавання нового вузла при `n = 20`:** 12 нс.
- **Відновлення секрету GF(p) (`k = 5`):** 110 нс на операцію.
