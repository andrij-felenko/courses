# ⚙️ Мова, яку можна виконати

На папері мова — множина слів, а операції над мовами (об'єднання, переріз, склейка, зірка) — рядки означень. Спокуса очевидна: а чи можна тримати мову як живий об'єкт у програмі, будувати з неї склейки й зірки та питати «чи це слово в ній?» — і щоб усе це справді рахувалося?

Заковика в тому, що мова майже завжди нескінченна. `a*` — це `ε, a, aa, aaa, …` без кінця; списком її в пам'ять не покладеш. Тож перш ніж писати хоч рядок, треба відповісти на просте на позір питання: **що значить «тримати в програмі» нескінченну множину?**

Чесних відповідей рівно дві, і вони поводяться разюче по-різному.

Перша — тримати не саму множину, а **спосіб перевірити належність**: функцію, яка на будь-яке слово каже «так» або «ні». Множини як такої ніде немає, є лише її межа, обведена контуром. Це **предикат**.

Друга — тримати **спосіб видавати слова** по одному: лінивий перелік, який на вимогу народжує наступне слово мови. Сама нескінченність нікого не лякає, бо ми ніколи не просимо весь список одразу — лише «дай іще одне». Це **генератор** (лінивий перелік — [ітератор](book:programming/iterator), що віддає значення на вимогу, а не одразу масив).

Одна й та сама мова, дві ручки, за які її можна вхопити. Далі — обидві в коді, обидві з повним набором операцій, і головне — чому вони не рівносильні: одна ручка вирішує належність завжди, друга у загальному випадку не вирішує ніколи.

*Мова `a*` та дві ручки до неї. Предикат бере ОДНЕ слово й дає повну відповідь — і «так», і «ні». Генератор бере нуль слів і видає ВСІ по черзі, але прямого «ні» про конкретне слово не каже — лише «ось наступне». Уся дальша різниця в складності виростає саме з цієї несиметрії.*

## Дві ручки: предикат і генератор

Почнемо з чотирьох найпростіших мов, бо саме на них видно пастку, через яку спіткнувся не один розбірник, — різницю між **порожньою мовою ∅** (у ній немає жодного слова) і **мовою {ε}** (у ній рівно одне слово — порожнє). Обидва подання мусять розрізняти їх з першого рядка.

:::tabs
```py
from itertools import count, product

# ── Подання «предикат»: мова — функція «слово → чи належить» ──────────────
empty_p = lambda w: False            # ∅  — не містить нічого
eps_p   = lambda w: w == ""          # {ε} — містить лише порожнє слово
def word_p(s):   return lambda w: w == s              # {s}
def sigma_p(al): return lambda w: all(c in al for c in w)   # Σ*

# ── Подання «генератор»: мова — джерело свіжого лінивого потоку слів ──────
empty_g = lambda: iter(())           # ∅  — порожній потік, жодного слова
eps_g   = lambda: iter([""])         # {ε} — потік рівно з одного слова: ε
def word_g(s):   return lambda: iter([s])             # {s}
def sigma_g(al):                                      # Σ* у шортлекс-порядку
    def gen():
        for n in count(0):                            # довжина 0, 1, 2, …
            for t in product(al, repeat=n):
                yield "".join(t)                      # n = 0 дає рівно одне: ε
    return gen
```
```ts
// ── Подання «предикат»: мова — функція «слово → чи належить» ──────────────
type Pred = (w: string) => boolean;
const emptyP:   Pred = _ => false;             // ∅  — не містить нічого
const epsP:     Pred = w => w === "";          // {ε} — лише порожнє слово
const wordP  = (s: string): Pred => w => w === s;                 // {s}
const sigmaP = (al: string): Pred => w => [...w].every(c => al.includes(c));  // Σ*

// ── Подання «генератор»: мова — джерело свіжого лінивого потоку слів ──────
type Lang = () => Generator<string>;
const emptyG: Lang = function* () {};              // ∅  — нічого не видає
const epsG:   Lang = function* () { yield ""; };   // {ε} — рівно одне слово: ε
const wordG = (s: string): Lang => function* () { yield s; };     // {s}
function* sigmaG(al: string): Generator<string> {                 // Σ* шортлекс
  for (let n = 0; ; n++)
    for (let i = 0; i < al.length ** n; i++) {     // слова довжини n — числа 0…kⁿ−1
      let w = "", r = i;
      for (let p = 0; p < n; p++) { w = al[r % al.length] + w; r = (r / al.length) | 0; }
      yield w;
    }
}
```
:::

Погляньте на два рядки для ∅ і {ε} у кожному поданні. Предикат ∅ на будь-яке слово каже `False` — навіть на порожнє: `empty_p("")` це `False`. Предикат {ε} на порожнє слово каже `True`: `eps_p("")` це `True`. Генератор ∅ не видає нічого — `list(empty_g())` це `[]`; генератор {ε} видає одне слово — `list(eps_g())` це `[""]`. Різниця між «мова порожня» і «мова містить порожнє слово» тут не філософська: у першому випадку не приймається нічого, у другому приймається порожній вхід. Плутанина цих двох — класична причина розбірника, який мовчки їсть порожній файл, хоча не мав би.

Далі всю алгебру пишемо на Python: над множинами й генераторами його синтаксис лягає найщільніше, а те, що ідея не залежить від мови, вже видно з двох вкладок вище.

## Предикатна алгебра: усе спиняється

Предикатне подання успадковує операції множин майже дослівно, бо `∈` для нього — це виклик функції.

```py
union_p  = lambda A, B: lambda w: A(w) or  B(w)     # A ∪ B — бодай в одній
inter_p  = lambda A, B: lambda w: A(w) and B(w)     # A ∩ B — в обох
compl_p  = lambda A:    lambda w: not A(w)          # доповнення в Σ*
```

Дві операції, властиві саме мовам, трохи цікавіші, бо працюють зі структурою слова.

**Склейка** `A · B` містить слово `w`, якщо його можна розрізати на префікс `u` та суфікс `v` так, що `u ∈ A` і `v ∈ B`. Розрізів рівно `|w| + 1` — по одному на кожну точку зламу, включно з крайніми. Скінченно багато, тож перевірка гарантовано доходить до кінця:

```py
def cat_p(A, B):                                    # A · B
    return lambda w: any(A(w[:i]) and B(w[i:]) for i in range(len(w) + 1))
```

**Зірка Кліні** `A*` — слово `w` розкладається на нуль чи більше шматків, кожен з яких лежить у `A`. І ось тут ховається перша справжня пастка. Наївний код пробує перший шматок будь-якої довжини — від порожнього до всього слова:

```py
def star_p_bad(A):                                  # ⚠️ з дефектом
    def contains(w):
        if w == "":
            return True
        # i починається з 0 → перший шматок може бути ПОРОЖНІЙ
        return any(A(w[:i]) and contains(w[i:]) for i in range(0, len(w) + 1))
    return contains
```

Візьміть `i = 0`. Тоді перший шматок — це `w[:0]`, тобто порожнє слово, а решта — `w[0:]`, тобто **все `w` цілком**. Якщо `ε ∈ A`, то `A("")` істинне, і код рекурсивно питає `contains(w)` — те саме слово, з якого почав. Нескінченний спуск, стек переповнюється. Це **пастка ε в зірці**: порожній шматок нічого від слова не відкушує, тож розбір нікуди не рухається.

Ліки прості й повчальні: перший шматок мусить бути **непорожнім**. Тоді решта завжди коротша за `w`, і рекурсія неминуче доходить до дна. А те, що `ε` завжди належить `A*` (це склейка нуля шматків), обробляємо окремою умовою — вона не залежить від того, чи `ε ∈ A` взагалі:

```py
def star_p(A):                                      # A*
    def contains(w):
        if w == "":
            return True                             # ε ∈ A* завжди
        # i ≥ 1 → перший шматок непорожній → решта КОРОТША → спуск скінченний
        return any(A(w[:i]) and contains(w[i:]) for i in range(1, len(w) + 1))
    return contains
```

Ця дрібна зміна — `range(1, …)` замість `range(0, …)` плюс окрема база — і є вся різниця між кодом, що спиняється, і кодом, що зациклюється. Перевірмо на ній другу класичну пастку, **∅ проти {ε}** у зірці:

```py
star_p(empty_p)("")    # True   — ∅* МІСТИТЬ ε
star_p(empty_p)("a")   # False  — і більше нічого
star_p(eps_p)("")      # True   — {ε}* теж лише {ε}
```

Результат `∅* = {ε}` збиває з пантелику: порожня мова, з якої нема чого брати, у зірці породжує рівно одне слово. Причина — та сама окрема база: зірка завжди містить склейку нуля шматків, а нуль шматків з будь-чого дає `ε`. Наївний код, що почав би від `A¹` і забув про `A⁰`, дав би тут `∅` — і це помилка, яку регулярні рушії відловлюють у себе ще на етапі тестів.

Головне про це подання — не окремі функції, а їхня спільна риса: **кожна з них на будь-якому слові за скінченний час дає відповідь**. `cat_p` перебирає скінченно багато розрізів; `star_p` спускається по щоразу коротших словах. Ланцюжок з `union_p`, `cat_p`, `star_p` над скінченними базовими мовами — це функція, яка завжди спиняється й завжди каже правду. Такий предикат зветься **розв'язувачем**, а мова, для якої він існує, — **розв'язною**. Тримайте цю думку: предикатне подання дає розв'язувача майже задарма.

## Генераторна алгебра: тут ховається цикл

Генераторне подання починається так само легко — і несподівано впирається в стіну.

Об'єднання й переріз двох **упорядкованих** потоків — це класичне злиття, знайоме з сортування. Обидва наші потоки йдуть у шортлекс-порядку (коротші раніше, рівні за довжиною — за абеткою), тож їх можна зливати, зберігаючи цей порядок, і жодного разу не тримаючи в пам'яті більш ніж по одному слову з кожного:

```py
import heapq
KEY = lambda w: (len(w), w)          # шортлекс-ключ: спершу довжина, тоді абетка

def union_g(A, B):                    # A ∪ B — злиття з викиданням дублів
    def gen():
        prev = object()               # свідомо не рівний жодному рядку
        for w in heapq.merge(A(), B(), key=KEY):   # два впорядкованих у один
            if w != prev:             # дублі в злитті стоять поруч
                prev = w
                yield w
    return gen

def inter_g(A, B):                    # A ∩ B — слова, що є в обох
    def gen():
        a, b = A(), B()
        x, y = next(a, None), next(b, None)
        while x is not None and y is not None:
            if x == y:
                yield x
                x, y = next(a, None), next(b, None)
            elif KEY(x) < KEY(y):     # x «менший» — підтягуємо x
                x = next(a, None)
            else:
                y = next(b, None)
    return gen
```

Обидва працюють навіть над нескінченними потоками — над `sigma_g("ab")` включно — і пам'яті беруть стало, бо дивляться лише на голову кожного потоку. Досі генератор нічим не гірший за предикат.

А тепер склейка — і катастрофа. Найочевидніший код виглядає бездоганно:

```py
def cat_g_naive(A, B):               # ⚠️ виглядає правильно, а не працює
    def gen():
        for u in A():                # кожне слово першої мови…
            for v in B():            # …і за ним кожне слово другої
                yield u + v
    return gen
```

Прочитайте цикли пильно. Якщо `B` нескінченна, то внутрішній `for v in B()` **не завершиться ніколи**. Зовнішній цикл назавжди застрягне на першому `u`, видаючи `u+v₀, u+v₁, u+v₂, …` — до другого слова `A` черга не дійде до кінця часів. Мова `A·B` вийде обрізаною до `{u₀}·B`, а решта склейок просто загубиться. І навіть коли обидві мови скінченні, порядок псується: `cat_g_naive` видасть `u₀v₀, u₀v₁, …, u₀v_останнє, u₁v₀` — а це вже не шортлекс, бо `u₀v_довге` довше за `u₁v₀`, але виходить раніше. **Ось де ховається нескінченний цикл** — не в зірці, а в найбуденнішому подвійному переборі.

Приборкати його можна лише одним чином — **межею на довжину**. Слово `A·B` завдовжки `n` склеєне з `u` та `v`, де `|u| + |v| = n`, тож `|u| ≤ n` і `|v| ≤ n`. Отже, щоб отримати всі результати завдовжки до `n`, досить префіксів з `A` завдовжки до `n` і суфіксів з `B` завдовжки до `n` — а таких скінченно багато. Ключ до всього — функція, що чесно спиняється:

```py
def upto(L, n):
    """Усі слова мови L завдовжки ≤ n — скінченний список у шортлекс-порядку.
    Спиняється ЛИШЕ на шортлекс-потоці: перше ж слово, довше за n, означає,
    що довших уже не буде, — і читати далі нема сенсу."""
    out = []
    for w in L():
        if len(w) > n:
            break                    # ← ось ця межа й робить нескінченне скінченним
        out.append(w)
    return out
```

`upto` — це та сама межа довжини, яку просив здоровий глузд, тільки виражена як стоп-правило. На нескінченному `sigma_g("ab")` вона не зависає: щойно потік переходить до слів довжини `n+1`, `break` обриває читання. І зверніть увагу на застереження в докрядку — воно ще спрацює. Тепер склейка й зірка стають скінченними обчисленнями:

```py
def cat_upto(A, B, n):               # (A · B), обмежена довжиною ≤ n
    Bs = upto(B, n)
    res = {u + v for u in upto(A, n) for v in Bs if len(u) + len(v) <= n}
    return sorted(res, key=KEY)

def star_upto(A, n):                 # A*, обмежена довжиною ≤ n
    pieces = [u for u in upto(A, n) if u != ""]   # ε-шматки викидаємо: інакше цикл
    reached = {""}                                # ε ∈ A* завжди
    frontier = {""}
    while frontier:                               # ширимося, доки додається нове
        nxt = set()
        for w in frontier:
            for u in pieces:
                x = w + u
                if len(x) <= n and x not in reached:
                    reached.add(x)
                    nxt.add(x)
        frontier = nxt
    return sorted(reached, key=KEY)
```

У `star_upto` варто спинитися на рядку `pieces = [u for u in … if u != ""]`. Ми викидаємо `ε` зі списку шматків — і це та сама пастка ε в зірці, що й у предикаті, тільки в іншому вбранні. Якби `ε` лишилося серед шматків, то `w + ε = w` додавало б слово до самого себе без кінця, і фронтир ніколи б не спорожнів. А `ε` у результаті все одно є — його кладе початкове `reached = {""}`. Ось ці операції в дії:

```py
A = union_g(word_g("a"), word_g("ab"))    # A = { a, ab }
B = union_g(word_g("b"), word_g("ba"))    # B = { b, ba }

cat_upto(A, B, 4)          # ['ab', 'aba', 'abb', 'abba']   — усі чотири склейки
star_upto(word_g("ab"), 5) # ['', 'ab', 'abab']  — (ab)* до довжини 5
star_upto(empty_g, 5)      # ['']  — знову ∅* = {ε}, а не ∅
```

Та сама межа `n` пронизує все: обчисліть будь-який вираз над мовами на одному й тому самому `n` — і дістанете правду «настільки, наскільки вистачає довжини `n`». Це не костур, а чесне визнання: у нескінченного об'єкта не можна попросити «усе», можна лише «усе до цієї межі».

## Дві задачі різної складності

Тепер зведемо обидва подання віч-на-віч і побачимо, що вони відповідають на різні питання — і що ці питання не однакової складності.

Предикатне подання прямо відповідає на **належність**: `L(w)` це `True` або `False`, і — якщо `L` зібрана з наших операцій над скінченними мовами — відповідь приходить завжди. Це розв'язувач, мова розв'язна, крапка.

Генераторне подання прямо відповідає на інше питання — **перелік**: «дай наступне слово мови». Щоб через нього перевірити належність, доводиться сидіти біля потоку й чекати, чи не випливе `w`:

```py
def member(L, w):
    """Вирішує w ∈ L, читаючи потік. Спиняється правильно, ПОКИ потік шортлекс."""
    for x in L():
        if x == w:
            return True              # трапилось — належить
        if len(x) > len(w):
            return False             # потік пішов у довші слова — w тут уже не буде
    return False                     # потік вичерпався, w не трапилось
```

Це працює — `member(sigma_g("ab"), "bab")` дасть `True`, а `member(sigma_g("ab"), "bac")` дасть `False` і не зависне, — але подивіться пильно, **завдяки чому**. Рятує рядок `if len(x) > len(w)`. Потік іде так, що довжина не спадає; щойно він переступив довжину `w`, ми певні, що `w` попереду вже не буде, і кажемо «ні». Стоп-правило працює **тільки тому, що порядок шортлекс** — той самий порядок, що дозволив `upto` спинятися. Приберіть його — і код обернеться на пастку:

```py
def member_semi(L, w):
    for x in L():                    # без стоп-правила за довжиною
        if x == w:
            return True
    return False                     # для нескінченного L і чужого w сюди НЕ дійти
```

На нескінченній мові, слова якої виходять у довільному порядку, `member_semi` для слова з мови колись відповість `True` — а для слова не з мови крутитиметься вічно, ніколи не сказавши `False`. Це вже не розв'язувач, а **напіврозв'язувач**: «так» він доведе, «ні» — ніколи. Мову, для якої існує лише таке, звуть **напіврозв'язною** (у теорії обчислюваності — *перелічною*, англ. *recursively enumerable*: її слова можна виписати переліком, хай і в якомусь дивному порядку).

І ось питання на мільйон: чому не можна просто **завжди** переставити слова в шортлекс-порядок, як у наших генераторах, і тим перетворити будь-який напіврозв'язувач на розв'язувач? Адже якби вдавалося, задача переліку й задача належності злилися б в одну.

Відповідь — тверде «ні», і вона не про брак кмітливості, а про межу можливого. Тут працює точний критерій, який 1944 року сформулював американський логік Еміл Пост (родом з Августова, тоді Конгресова Польща в складі Російської імперії, з польсько-єврейської родини — не росіянин): **мова розв'язна тоді й лише тоді, коли перелічити можна і її саму, і її доповнення** (усі слова, яких у ній нема). Причина проста: якби ми вміли перелічувати те й те, то, ведучи два переліки паралельно, дочекалися б `w` в одному з них — і сказали б чи то «так», чи то «ні» за скінченний час.

А тепер удар. Існують мови — і серед них [мова програм, що спиняються](book:algorithms/halting-problem), — у яких саму мову перелічити можна (запускай усі програми потроху й виписуй ті, що спинилися), а її **доповнення перелічити не можна в принципі**: не існує способу систематично виписати всі програми, що не спиняються, бо для кожної довелося б наперед знати, що вона й справді не спиниться. За критерієм Поста така мова напіврозв'язна, але не розв'язна. Стоп-правила для неї немає не тому, що ми його не знайшли, а тому, що його там немає.

![Дві стрічки перелічування одного слова: угорі шортлекс — довжина не спадає, тож за межею довжини |w| можна впевнено сказати «ні»; унизу довільний порядок — стоп-правила немає, чуже слово змушує чекати вічно](/book/math/logic-foundations/formal-language/img/membership-vs-listing.svg)
*Шукаємо, чи належить мові слово `w`. Угорі потік шортлекс: дійшовши до слів, довших за `w`, ми ЗНАЄМО, що `w` попереду не буде, — червона межа дає право сказати «ні». Належність розв'язна. Унизу той самий вміст у довільному порядку: `w` може випірнути будь-де попереду, тож поки воно не випірнуло, «ні» сказати не можна. Належність лише напіврозв'язна — і для деяких мов упорядкувати потік за довжиною неможливо навіть у принципі.*

Ось де по-справжньому розходяться дві ручки. **Перелічити мову** можна завжди, коли є генератор, — це слабша, напіврозв'язна задача. **Вирішити належність** — сильніша: вона під силу предикатові, що спиняється, або генераторові, але лише **впорядкованому за довжиною**. Наші `union_g`, `inter_g`, `cat_upto`, `star_upto` тримають шортлекс-порядок навмисне — саме він і є тим, що робить перелік придатним для рішень. Загубіть порядок — і залишиться сама тільки здатність виписувати, без здатності відмовляти.

## Пастки наостанок

Три місця, де цей код найлегше зіпсувати, варто мати перед очима разом.

**Нескінченна склейка.** Подвійний цикл `for u in A(): for v in B()` виглядає як пряме прочитання означення `A·B = { u·v }`, а насправді застрягає на першому `u`, тільки-но `B` нескінченна, і псує порядок навіть на скінченних мовах. Єдиний надійний лік — вести склейку за зростанням довжини результату (`cat_upto`), бо лише довжина дає скінченну межу перебору.

**ε в зірці.** І в предикаті (`range(0, …)`), і в генераторі (`ε` серед шматків) порожній шматок нічого від слова не відкушує, тож розбір або рекурсія кружляють на місці. Лік один: шматки в зірці мусять бути непорожні, а належність `ε` до `A*` забезпечувати окремо — вона істинна завжди, незалежно від самої `A`.

**∅ проти {ε}.** Порожня мова не містить нічого; мова `{ε}` містить одне порожнє слово. Звідси `L · ∅ = ∅` (немає з чим склеювати), але `L · {ε} = L` (дописуємо порожнє — нічого не міняється), і найпідступніше — `∅* = {ε}`, а не `∅`, бо зірка завжди містить склейку нуля шматків. Код, що плутає ці дві мови, дає розбірник, який або відкидає порожній вхід, який мав приймати, або приймає порожній, який мав відкидати, — і обидві помилки виявляються далеко від місця, де їх посіяли.

Спільний висновок за всіма трьома пастками той самий, що й за всім кодом: нескінченне тримається в програмі лише доти, доки ми не просимо його цілком. Предикат ніколи не питає про всю множину — лише про одне слово. Генератор ніколи не видає всю множину — лише наступне слово. А щойно нам треба скінченна відповідь про нескінченний об'єкт — межа довжини або впорядкованість за довжиною виявляються не зручністю, а єдиним, що взагалі дозволяє обчисленню спинитися.
