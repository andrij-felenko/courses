# ⚙️ Одне додавання, три несхожі машини — і всі кажуть «п'ять»

Теза стверджує дивовижне: чотири означення «обчислюваного», придумані незалежно й геть різними інструментами, окреслюють **один і той самий** клас функцій. Прочитати це легко, кивнути — теж. А от **відчути** — інша річ. Найкоротший шлях до цього відчуття — не доводити теорему (це зробили Кліні й Тюринг рівностями формалізмів), а взяти одну-єдину скромну функцію й порахувати її трьома по-справжньому чужими одна одній машинами. Якщо всі три на кожному вході видадуть те саме число — ти на власних пальцях намацав той збіг, що його теза підносить у принцип.

Функцію візьмемо найпростішу, яку не соромно рахувати вручну, — **додавання**. Наскрізний приклад — 2 + 3 = 5, але перевіримо цілу низку входів. Правило гри одне, і воно суворе: **жодного шахрайства**. Кожна модель робить свою роботу сама. Ніякого «взяти готовий `+` мови-господаря» — інакше ми порахували б додавання Пайтоном, а не λ-численням чи машиною Тюринга. У кожній моделі число «п'ять» мусить **народитися з її власних цеглинок**.

Ось три світи, які ми зіштовхнемо на тій самій задачі:

- **λ-числення** — світ без чисел і без машин, самі функції; «порахувати» означає «спрощувати вираз, доки він спрощується».
- **загальнорекурсивні функції** — число будується з нуля й «додати одиницю», а додавання — з примітивної рекурсії.
- **машина Тюринга** — стрічка з унарним записом, голівка й скінченна таблиця переходів δ.

Три дороги, що й на вигляд не мають нічого спільного. Пройдімо кожну до кінця.

## Дорога перша: λ-числення, де немає чисел

Почнімо з найдивнішого світу. Тут знадобиться сам його апарат. [У λ-численні немає ні чисел, ні типів — лише змінні, функції одного аргументу (запис `λx. тіло`) та застосування функції до аргумента; єдина дія обчислення — β-редукція: у тілі функції підставити аргумент замість зв'язаної змінної.](book:math/lambda-calculus) Усе інше — числа, умови, рекурсія — доводиться **закодувати** цими трьома цеглинками.

Число тут — це **дія повторення**. Число `n` — це функція, яка бере якусь дію `f` і точку `x` і застосовує `f` рівно `n` разів: `n = λf.λx. f(f(…(f x)…))`. Нуль не застосовує `f` жодного разу (`λf.λx. x`), двійка — двічі, трійка — тричі. Це **числа Черча**. А додавання? Додати `a` і `b` — повторити дію спершу стільки разів, скільки каже `a`, а тоді ще стільки, скільки каже `b`:

```
add = λa.λb.λf.λx.  a f (b f x)
```

Прочитаймо праву частину: спершу `b f x` застосовує `f` до `x` рівно `b` разів, тоді зовнішнє `a f (…)` навішує зверху ще `a` застосувань `f`. Разом — `a + b` застосувань. Уся арифметика тут — у тому, скільки разів навісилася одна й та сама `f`.

Щоб довести собі, що це справді обчислення, а не фокус, ми **не** покладемося на λ мови-господаря (це б перекинуло редукцію на неї). Натомість збудуємо власний **редуктор**: терм як дерево (змінна / абстракція / застосування) і функцію, що знаходить редекс і виконує β-крок сама. Ось повний, робочий редуктор — і у Пайтоні (його `lambda` тут лише синтаксис, справжню роботу робить наш код), і в Гаскелі, мові, що сама виросла з λ-числення:

```python
from itertools import count

# терм: змінна, абстракція (λ), застосування
class Var:
    def __init__(s, name): s.name = name
class Lam:
    def __init__(s, param, body): s.param, s.body = param, body
class App:
    def __init__(s, fn, arg): s.fn, s.arg = fn, arg

def free(t):                       # вільні (незв'язані) змінні терма
    if isinstance(t, Var): return {t.name}
    if isinstance(t, Lam): return free(t.body) - {t.param}
    return free(t.fn) | free(t.arg)

_n = count()
def fresh(base): return f"{base}#{next(_n)}"

def subst(t, x, s):                # t[x := s], без захоплення змінних
    if isinstance(t, Var):
        return s if t.name == x else t
    if isinstance(t, App):
        return App(subst(t.fn, x, s), subst(t.arg, x, s))
    if t.param == x:               # x перекрито цією λ — далі не чіпаємо
        return t
    if t.param in free(s):         # підстановка спіймала б вільну змінну —
        p = fresh(t.param)         # перейменовуємо зв'язану, щоб не захопити
        body = subst(t.body, t.param, Var(p))
        return Lam(p, subst(body, x, s))
    return Lam(t.param, subst(t.body, x, s))

def step(t):                       # один крок нормального порядку (лівий-зовнішній)
    if isinstance(t, App):
        if isinstance(t.fn, Lam):                   # ось він, зовнішній редекс
            return subst(t.fn.body, t.fn.param, t.arg)
        f = step(t.fn)
        if f is not None: return App(f, t.arg)
        a = step(t.arg)
        if a is not None: return App(t.fn, a)
        return None
    if isinstance(t, Lam):
        b = step(t.body)
        return Lam(t.param, b) if b is not None else None
    return None                                     # Var — нема куди редукувати

def normalize(t, limit=100_000):
    for _ in range(limit):
        nt = step(t)
        if nt is None: return t                     # нормальна форма
        t = nt
    raise RuntimeError("нормальної форми не видно — можливо, її й немає")

# число Черча n = λf.λx. f (f (… x …))  — рівно n застосувань f
def church(n):
    body = Var("x")
    for _ in range(n): body = App(Var("f"), body)
    return Lam("f", Lam("x", body))

add = Lam("a", Lam("b", Lam("f", Lam("x",
        App(App(Var("a"), Var("f")),
            App(App(Var("b"), Var("f")), Var("x")))))))

def to_int(t):                     # нормалізуй і полічи застосування f
    t = normalize(t)
    f, inner = t.param, t.body
    x, cur, n = inner.param, inner.body, 0
    while isinstance(cur, App) and cur.fn.name == f:
        n, cur = n + 1, cur.arg
    return n

print(to_int(App(App(add, church(2)), church(3))))   # 5
```
```haskell
data Term = Var String | Lam String Term | App Term Term

free :: Term -> [String]                     -- вільні (незв'язані) змінні
free (Var x)   = [x]
free (Lam x b) = filter (/= x) (free b)
free (App f a) = free f ++ free a

fresh :: String -> [String] -> String        -- перша назва, вільна від used
fresh y used = head [c | c <- iterate (++ "'") y, c `notElem` used]

subst :: Term -> String -> Term -> Term       -- t[x := s], без захоплення
subst (Var y)   x s = if y == x then s else Var y
subst (App f a) x s = App (subst f x s) (subst a x s)
subst (Lam y b) x s
  | y == x          = Lam y b                             -- x перекрито цією λ
  | y `elem` free s = let y' = fresh y (free s ++ free b) -- уникаємо захоплення
                      in  Lam y' (subst (subst b y (Var y')) x s)
  | otherwise       = Lam y (subst b x s)

step :: Term -> Maybe Term                    -- крок нормального порядку
step (App (Lam x b) a) = Just (subst b x a)   -- зовнішній редекс
step (App f a)         = case step f of
                           Just f' -> Just (App f' a)
                           Nothing -> fmap (App f) (step a)
step (Lam x b)         = fmap (Lam x) (step b)
step (Var _)           = Nothing              -- нема куди редукувати

normalize :: Term -> Term
normalize t = maybe t normalize (step t)

church :: Int -> Term                         -- λf.λx. f (f … x)
church n = Lam "f" (Lam "x" (go n))
  where go 0 = Var "x"
        go k = App (Var "f") (go (k - 1))

add :: Term                                   -- λa.λb.λf.λx. a f (b f x)
add = Lam "a" (Lam "b" (Lam "f" (Lam "x"
        (App (App (Var "a") (Var "f"))
             (App (App (Var "b") (Var "f")) (Var "x"))))))

toInt :: Term -> Int                          -- нормалізуй і полічи f
toInt t = case normalize t of
            Lam f (Lam x body) -> go f x body
            _                  -> error "не число Черча"
  where go f x (App (Var g) r) | g == f = 1 + go f x r
        go _ x (Var y)         | y == x = 0
        go _ _ _                        = error "не число Черча"

main :: IO ()
main = print (toInt (App (App add (church 2)) (church 3)))   -- 5
```

Запусти будь-яку з версій — на екрані `5`. Ми ніде не написали `2 + 3`; ми лише **спростили вираз** `add «2» «3»`, і в нормальній формі виявилося рівно п'ять навішених `f`. Ось хід спрощення у головних віхах, від виразу до відповіді:

```
add «2» «3»
  → λf.λx. «2» f («3» f x)          підставили a := «2», b := «3»
  → λf.λx. f (f («3» f x))          «2» f = «двічі застосувати f»
  → λf.λx. f (f (f (f (f x))))      «3» f x = «тричі f поверх x»
  = «5»                             п'ять f — це число Черча 5
```

Тут ховається перша тонка деталь, яку варто помітити. Ці три віхи наш редуктор дробить на дрібніші β-кроки — і рахує їх. Скільки ж β-кроків забирає це додавання? Відповідь **однакова для будь-яких m і n: рівно шість**. Додати 2 і 3 — шість кроків; додати 500 і 500 — теж шість. Спокуса сказати «додавання в λ-численні коштує сталого часу» — і це була б **пастка**. Число β-кроків стале, бо число Черча несе свою величину як **структуру** (готове дерево з `n` вкладених застосувань), а не як обчислення, яке треба виконати. Але підстановка на кожному кроці **копіює** підтерм, а розмір цих підтермів росте з `m + n`. Тобто справжня робота (розмір термів, пам'ять, час копіювання) все одно масштабується — просто лічильник β-кроків цього не бачить. Стала кількість кроків над термами, що ростуть, — не те саме, що сталий обсяг роботи.

> 🔧 **Навіщо це.** Редуктор, який ми щойно написали, — це λ-числення, що біжить **на машині фон Неймана** (звичайному комп'ютері з Пайтоном чи Гаскелем). Іншими словами, ми **симулювали одну модель обчислення всередині іншої**. Теза гарантує, що така симуляція завжди можлива в обидва боки: будь-яку з чотирьох моделей можна відтворити будь-якою іншою. Саме цим щодня живуть інтерпретатори, віртуальні машини й транспілери — вони перекладають між рівносильними моделями, і те, що переклад завжди існує, — не щастя інженерів, а прямий наслідок того самого збігу, який ми зараз мацаємо руками.

## Дорога друга: числа з нуля й «наступного»

Тепер геть інший світ — жодних термів і жодного спрощення, самі числа й функції над ними. [Загальнорекурсивні функції будуються з трьох базових — нуль-функції, наступника (S: n ↦ n+1) і проєкцій (вибрати i-й аргумент) — трьома способами складати нове зі старого: композицією, примітивною рекурсією та мінімізацією μ (необмеженим пошуком).](book:math/general-recursive-functions) Клас, який виходить, і є точно обчислювані функції.

Домовмось про чесність відразу. Натуральні числа й **дві** речі ми беремо за примітив: нуль і наступник `S(x) = x+1`. Наступник — атом, «додати одну паличку». Заборонено інше — писати `a + b` напряму. **Додавання ми мусимо вивести** з наступника. І виводиться воно чистою примітивною рекурсією, без жодного μ:

```
add(a, 0)    = a                 база:  додати нуль — нічого не змінити
add(a, S b)  = S(add(a, b))      крок:  додати на одиницю більше — на одиницю більший результат
```

Ця пара рядків і є вся ідея: щоб додати `b`, застосуй наступника `b` разів. Тепер запишімо це не як звичайну функцію, а через **самі формальні цеглинки** — щоб було видно, що жодної схованої арифметики немає, лише нуль, наступник, проєкції та схеми складання:

```python
# базові функції
def Z(*_):  return 0                  # нуль-функція: за будь-яких аргументів 0
def S(x):   return x + 1              # наступник — єдиний атом арифметики
def Proj(i):                          # проєкція: i-й з аргументів
    return lambda *a: a[i]

# способи будувати нові функції з наявних
def Comp(f, gs):                      # композиція:  f(g₁(…), …, gₖ(…))
    return lambda *a: f(*(g(*a) for g in gs))

def PrimRec(f, g):                    # примітивна рекурсія по останньому аргументу
    def h(*a):
        *xs, y = a
        if y == 0: return f(*xs)                   # h(xs, 0)   = f(xs)
        return g(*xs, y - 1, h(*xs, y - 1))        # h(xs, y+1) = g(xs, y, h(xs, y))
    return h

def Mu(f):                            # μ: найменше y, за якого f(…, y) = 0
    def m(*a):
        y = 0
        while f(*a, y) != 0: y += 1   # може не спинитися ніколи
        return y
    return m

# add(a, 0) = a ;  add(a, S b) = S(add(a, b))
add = PrimRec(Proj(0), Comp(S, [Proj(2)]))

print(add(2, 3))   # 5
```

Розберімо той єдиний насичений рядок `add = PrimRec(Proj(0), Comp(S, [Proj(2)]))`. У базі, коли другий аргумент нуль, віддаємо перший — це `f = Proj(0)` (візьми аргумент з індексом 0, тобто `a`). У кроці рекурсії `PrimRec` викликає `g` з трьома значеннями: `(xs, y, h(xs, y))` — тут це `(a, b−1, add(a, b−1))`. Нам треба взяти останнє з них, попередній результат `add(a, b−1)`, і навісити наступника: `S(add(a, b−1))`. «Взяти третій аргумент» — це `Proj(2)`, «навісити S» — `Comp(S, [Proj(2)])`. Уся арифметика додавання зведена до вибору потрібного значення й одного `S`. Запусти — `5`.

Тут причаїлася найглибша пастка цієї моделі, і вона багато чого пояснює про саму тезу. Додавання лягло в **чисту примітивну рекурсію** — жодного `Mu` ми не вжили. Спокусливо подумати, що примітивної рекурсії досить для всього. Це не так. Кожна примітивно-рекурсивна функція **тотальна** — завжди спиняється й дає відповідь (рекурсія зменшує лічильник до нуля, вічно крутитися нема як). Але серед обчислюваних є тотальні функції, до яких примітивна рекурсія **не дотягується**: класична **функція Аккермана** обчислювана й завжди спиняється, проте росте швидше за будь-яку примітивно-рекурсивну — а отже, сама примітивно-рекурсивною не є. Щоб клас накрив **усе** обчислюване, потрібен `Mu` — необмежений пошук `μy. f(…, y) = 0`. І саме `Mu` вперше впускає у світ можливість **не спинитися**: цикл `while` може не знайти нуля ніколи.

Це не дрібна технічна деталь, а сама суть. [Рівно та сила, що зрівнює загальнорекурсивні функції з машиною Тюринга — необмежений пошук μ, — приносить і ту саму ваду: часткові функції, що на деяких входах крутяться вічно. Немає й не може бути способу заздалегідь відсіяти «зациклиться / не зациклиться» — це і є проблема зупинки.](book:algorithms/halting-problem) Додавання щасливо цього уникає, бо `μ` йому не потрібен; але щойно модель дозволяє собі повну силу — вона неминуче дозволяє собі й вічний цикл. Повнота й ризик незупинки — дві сторони однієї монети.

## Дорога третя: голівка, що повзе стрічкою

Третій світ найпростіший на вигляд і найтупіший у роботі — і саме тому найпереконливіший як образ «механічного». [Машина Тюринга — це нескінченна стрічка з клітинок, голівка над однією клітинкою, скінченний набір станів і функція переходів δ, що за парою (стан, символ під голівкою) диктує трійку (що записати, куди зсунути голівку, у який стан перейти).](book:math/turing-machine) Жодного розуму — самий перегляд таблиці.

Число закодуємо **унарно**: `n` — це `n` одиниць поспіль. Вхід «додати m і n» запишемо як `1ᵐ 0 1ⁿ` — блок одиниць, роздільник-нуль, ще блок одиниць. Наприклад, 2 + 3 — це `11 0 111`, тобто стрічка `110111`. Результат має лишити на стрічці `m + n` одиниць.

Ідея алгоритму до смішного проста, і в ній є маленька хитрість. Якщо просто **замінити роздільник `0` на `1`**, два блоки зіллються в один суцільний — але одиниць стане `m + n + 1`, на одну забагато (нуль перетворився на зайву паличку). Тому наприкінці треба **стерти одну** одиницю з правого краю. Ось і весь план: біжи праворуч до нуля, зроби з нього одиницю, добіжи до кінця, зітри останню. Уся δ вміщується у п'ять рядків:

| стан | читає | пише | рух | новий стан | що робить |
|------|:----:|:----:|:---:|:----:|-----------|
| q0 | 1 | 1 | → | q0 | біжимо по першому блоку одиниць |
| q0 | 0 | 1 | → | q1 | роздільник 0 → 1, входимо в другий блок |
| q1 | 1 | 1 | → | q1 | біжимо по злитому блоку |
| q1 | _ | _ | ← | q2 | дійшли порожньої клітинки — крок назад |
| q2 | 1 | _ | стоп | qH | стираємо одну зайву 1 і спиняємось |

Тепер — короткий інтерпретатор, що просто ганяє цю таблицю над стрічкою (стрічку тримаємо як словник «індекс → символ», тож вона росте в обидва боки без меж):

```python
BLANK = "_"
# δ: (стан, символ) → (новий стан, що записати, куди рухатись: -1, 0, +1)
delta = {
    ("q0", "1"): ("q0", "1", +1),
    ("q0", "0"): ("q1", "1", +1),
    ("q1", "1"): ("q1", "1", +1),
    ("q1", "_"): ("q2", "_", -1),
    ("q2", "1"): ("qH", "_",  0),
}

def run(word):
    tape = dict(enumerate(word))
    head, state, steps = 0, "q0", 0
    while state != "qH":                     # qH — стан-зупинка
        sym = tape.get(head, BLANK)
        state, write, move = delta[(state, sym)]
        tape[head] = write
        head += move
        steps += 1
    return sum(1 for v in tape.values() if v == "1"), steps

def tm_add(m, n):
    ones, steps = run("1" * m + "0" + "1" * n)
    return ones                              # кількість одиниць = сума

print(tm_add(2, 3))   # 5
```

Простежмо, як машина додає 2 + 3 на стрічці `110111`. Голівка стартує ліворуч у стані `q0`:

![Дев'ять послідовних станів машини Тюринга при додаванні 2 + 3: голівка біжить праворуч по стрічці «110111», перетворює роздільник-нуль на одиницю (стрічка стає «111111»), добігає краю, вертається на крок і стирає одну зайву одиницю, лишаючи «11111» — п'ять одиниць](/book/math/logic-foundations/church-turing-thesis/img/tm-trace.svg)
*Стрічка крок за кроком. У `q0` голівка проходить перші дві одиниці й натрапляє на роздільник — переписує його на `1` і переходить у `q1` (тепер шість одиниць поспіль, на одну забагато). У `q1` добігає до порожньої клітинки, вертається на крок у `q2` і стирає останню одиницю. Лишається п'ять одиниць — це й є 2 + 3. Вісім кроків на суму п'ять; узагалі кроків лінійно від `m + n`.*

Знову ніде не написано «2 + 3»: машина лише **переписувала символи** за таблицею, а сума вигулькнула сама — як кількість одиниць, що лишилися.

І тут своя пастка, навіть дві. Перша — **ціна унарного запису**. Число `n` займає `n` клітинок, а не `log n`, як у двійковому; додавання коштує `m + n + 3` кроки — лінійно від **значення** чисел, тобто експоненційно від довжини їхнього двійкового запису. Двійкове кодування було б у рази компактніше — але тоді δ мусила б уміти переноси, і таблиця роздулася б утричі. Ми свідомо обрали унарний запис заради крихітної п'ятирядкової δ: плата за прості правила лягла на довжину стрічки. Це наскрізний закон машин Тюринга — простоту правил купуєш витратами стрічки й кроків, і навпаки.

Друга пастка тонша й важливіша. Наш словник-стрічка росте **без меж** — і це не недбалість, а джерело всієї сили машини. Обмеж стрічку фіксованою довжиною — і машина Тюринга миттю вироджується у **скінченний автомат**, строго слабший: він не порахує навіть, чи збалансовані дужки в достатньо довгому рядку. Уся різниця між «просто автомат» і «повна за Тюрингом машина» — саме в необмеженості стрічки. Реальне залізо завжди скінченне, тож машина Тюринга — ідеалізація, що припускає стільки паперу, скільки колись знадобиться. Без цього припущення збіг, який ми доводимо, розсипався б.

## Три дороги, одна точка

Кожна модель порахувала додавання по-своєму, зі своїх цеглинок. Лишилося головне — **зіштовхнути їх на тих самих входах** і побачити, чи справді вони завжди згодні. Зберімо всі три `add` в один файл (перейменувавши, щоб не плутати: `add_l` для λ, `add_rec`, `add_tm`) і зажадаймо рівності:

```python
def check(m, n):
    lam = to_int(App(App(add_l, church(m)), church(n)))   # λ-числення
    rec = add_rec(m, n)                                    # рекурсія
    tur = tm_add(m, n)                                     # стрічка
    assert lam == rec == tur == m + n, (m, n, lam, rec, tur)
    return lam

for m, n in [(2, 3), (0, 0), (4, 1), (5, 5), (7, 6)]:
    print(f"{m} + {n} = {check(m, n)}")
```

`assert` жодного разу не спрацьовує — три несхожі світи дають те саме число на кожному вході:

| вхід | λ-числення | загальнорекурсивна | машина Тюринга |
|:----:|:----------:|:------------------:|:--------------:|
| 2 + 3 | **5** (6 β-кроків) | **5** | **5** (8 кроків стрічки) |
| 0 + 0 | **0** (6 β) | **0** | **0** (3) |
| 4 + 1 | **5** (6 β) | **5** | **5** (8) |
| 5 + 5 | **10** (6 β) | **10** | **10** (13) |
| 7 + 6 | **13** (6 β) | **13** | **13** (16) |

Зверни увагу на **колонки витрат** — вони геть різні. λ-числення дає стале число β-кроків, але над термами, що ростуть; машина Тюринга — лінійне число кроків від суми. Дороги різняться і виглядом, і ціною роботи. А **колонка результату — та сама**, до останнього числа.

![Одна функція 2 + 3, порахована трьома моделями: ліворуч λ-числення спрощує вираз до п'яти застосувань f, посередині загальнорекурсивна функція розкручує рекурсію S(S(S(2))), праворуч машина Тюринга переписує стрічку — і всі три сходяться в число п'ять](/book/math/logic-foundations/church-turing-thesis/img/three-roads.svg)
*Три несхожі світи — функції, рекурсія, стрічка — і той самий результат на кожному вході. Ліва колонка спрощує вираз, середня розкручує рекурсію, права переписує символи; способи не мають між собою нічого спільного, а число внизу одне. Це і є той збіг, що його теза підносить у принцип: усі означують один клас функцій.*

Що ми, власне, побачили? Не доведення — доведення дали рівності Кліні й аналіз Тюринга, і воно стосується **всіх** обчислюваних функцій, а не однієї. Ми побачили **свідчення, яке можна відчути руками**: три означення «обчислюваного», що народилися з різних інтуїцій і не мають спільної форми, на конкретній функції завжди згодні. Помнож це відчуття на те, що так само згодні вони **на кожній** обчислюваній функції, — і стане ясно, чому чотири незалежні спроби впіймати «механічно обчислюване» виявилися описом однієї й тієї самої речі з різних боків. Саме цей збіг теза й підносить у принцип.

## Що варто винести

Три моделі, три способи рахувати те саме — і три різні пастки, які насправді про одне:

- **λ-числення** просить пильнувати **порядок редукції**. Нормальний порядок (лівий-зовнішній, який ми й узяли) завершується щоразу, коли нормальна форма існує, — це гарантує теорема Черча–Россера. Аплікативний (спершу порахувати аргумент) може зациклитися там, де нормальний спокійно дійшов би відповіді: класичний `(λx.λy.x) I Ω`, де `Ω = (λz. z z)(λz. z z)` редукується сама в себе довіку, — нормальний порядок за два кроки викидає непотрібну `Ω` й повертає `I`, аплікативний кинеться рахувати `Ω` і не спиниться. І окремо — **захоплення змінної**: наївна підстановка `x := y` у `λy. x` дала б `λy. y`, підступно зв'язавши чужий вільний `y`; правильно перейменувати зв'язану змінну на свіжу — `λy'. y`. Цікаво, що в самому `add «2» «3»` захоплення так і не спрацьовує (числа Черча замкнені, вільних змінних нема), проте редуктор без цієї перевірки все одно зламаний: досить одного відкритого терма, щоб він збрехав.

- **Загальнорекурсивні функції** нагадують, що **примітивної рекурсії замало**. Додавання в ній живе безпечно, але сама лише примітивна рекурсія дає тільки тотальні функції й не накриває всього обчислюваного (свідок — функція Аккермана). Повноту приносить `μ` — необмежений пошук; він же вперше й дозволяє незупинку. Сила й ризик вічного циклу нероздільні.

- **Машина Тюринга** нагадує про **ціну кодування й необмеженість стрічки**. Унарний запис купує п'ятирядкову δ ціною лінійної (від значення) довжини й кількості кроків. А головне — сила машини вся тримається на тому, що стрічці дозволено рости без меж: обмеж її — і залишиться слабший скінченний автомат.

Три світи, три різні способи спіткнутися — і той самий результат унизу. Порахувати одну функцію трьома чужими одна одній моделями й побачити, що всі три згодні, — це і є теза Черча–Тюринга, яку намацали пальцями, а не прийняли на слово.
