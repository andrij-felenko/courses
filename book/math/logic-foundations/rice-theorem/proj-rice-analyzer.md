# Симуляція статичного аналізатора на C++17

Теорема Райса може здаватися дещо абстрактною через концепції "Машин Тюрінга" та "нерозв'язності". Щоб побачити, як ця математична стіна виглядає на практиці, ми напишемо простий C++17 скрипт. Він симулює спробу створити ідеальний статичний аналізатор, який має визначити, чи виконається певна нетривіальна умова (наприклад, досягнення певної гілки коду). Ми побачимо, чому будь-який такий аналізатор приречений на помилку або зависання.

Цей навчальний проєкт складається з п'яти ключових компонентів:
1. Визначення семантичної властивості.
2. Цільові функції для аналізу (успішні та проблемні).
3. Симуляція наївного статичного аналізатора.
4. Програмна реалізація зведення (генерація хитрої функції-обгортки).
5. Тестовий драйвер (Runtime).

### 1. Визначення семантичної властивості
Наша нетривіальна властивість: "Чи поверне ця функція число 42 для входу 0?". Це суто семантична властивість, оскільки вона залежить від логіки виконання, а не від того, як написаний код.

### 2. Цільові функції
Створимо кілька тестових функцій, щоб перевірити наш аналізатор.
```cpp
#include <iostream>
#include <functional>
#include <string>

// Функція, яка ОЧЕВИДНО має властивість P
int function_has_P(int x) {
    return 42;
}

// Функція, яка ОЧЕВИДНО не має властивості P
int function_not_P(int x) {
    return x + 1;
}

// Функція з прихованою семантикою (Гіпотеза Коллатца)
// Чи зупиниться вона? Якщо зупиниться, поверне 42. Якщо ні - зависне.
int function_collatz_like(int x) {
    int n = x > 0 ? x : 27; // Використовуємо 27 як число з довгою траєкторією
    while (n > 1) {
        if (n % 2 == 0) n = n / 2;
        else n = 3 * n + 1;
    }
    return 42;
}
```

### 3. Наївний статичний аналізатор
Ми створюємо аналізатор, який приймає функцію та намагається передбачити її поведінку. Оскільки це C++, ми не можемо легко аналізувати вихідний код у рантаймі, тому наш аналізатор спробує зробити єдине можливе (і неправильне) рішення: виконати функцію.

```cpp
// Наш "аналізатор", який намагається перевірити властивість P.
// Він приречений на провал через теорему Райса / проблему зупинки.
bool static_analyzer(const std::function<int(int)>& func) {
    std::cout << "[Аналізатор] Спроба виконати аналіз...\n";
    // Єдиний спосіб дізнатися, що функція зробить - це запустити її.
    // Але якщо функція містить нескінченний цикл, наш аналізатор ЗАВИСНЕ!
    int result = func(0);
    return result == 42;
}
```
Як бачимо, щоб дізнатися семантику, аналізатор змушений симулювати програму. Але якщо програма зациклюється, аналізатор також зациклюється. Він не може за скінченний час дати відповідь.

### 4. Програмна реалізація зведення
Покажемо концепцію зведення в коді. Ми маємо "підозрілу" функцію `suspect_func`, і хочемо дізнатися, чи зупиниться вона. Ми обгортаємо її в нову функцію, створюючи екземпляр для нашого аналізатора.

```cpp
// Функція, яка зациклюється (імітує незупинку)
void infinite_loop() {
    while (true) {} 
}

// Генератор обгортки (мапове зведення)
// Він бере функцію `suspect` і перетворює її на нову функцію `wrapper`.
std::function<int(int)> create_rice_wrapper(const std::function<void()>& suspect) {
    return [suspect](int y) -> int {
        // Крок 1: запустити підозрілу функцію
        suspect(); 
        
        // Крок 2: якщо вона завершилась, завжди повертаємо 42
        return 42;
    };
}
```

### 5. Тестовий драйвер (Runtime)
Тепер зберемо все разом у `main`. Ми покажемо, як аналізатор легко справляється з тривіальними випадками, але повністю ламається на функції-обгортці, якщо підозріла функція зависає.

```cpp
int main() {
    std::cout << "--- Демонстрація Теореми Райса ---\n\n";

    std::cout << "Тест 1: Проста функція (очікуємо Так)\n";
    bool res1 = static_analyzer(function_has_P);
    std::cout << "Результат: " << (res1 ? "Має властивість" : "Не має") << "\n\n";

    std::cout << "Тест 2: Функція-обгортка, яка зупиниться\n";
    auto wrapper_halts = create_rice_wrapper([](){ /* нічого не робить, миттєво зупиняється */ });
    bool res2 = static_analyzer(wrapper_halts);
    std::cout << "Результат: " << (res2 ? "Має властивість" : "Не має") << "\n\n";

    std::cout << "Тест 3: Функція-обгортка, яка НЕ зупиниться\n";
    auto wrapper_loops = create_rice_wrapper([](){ infinite_loop(); });
    
    std::cout << "Запускаємо аналізатор для Тесту 3... (Увага: програма зависне назавжди!)\n";
    // Наступний рядок ніколи не завершить виконання
    // bool res3 = static_analyzer(wrapper_loops);
    // std::cout << "Результат: " << (res3 ? "Має властивість" : "Не має") << "\n";
    
    std::cout << "[ПЕРЕРВАНО] Як бачите, аналізатор не може дати відповідь.\n";
    std::cout << "Він не розв'язав задачу за скінченний час. Теорема Райса в дії.\n";

    return 0;
}
```

Цей простий скрипт наочно демонструє ключову ідею Теореми Райса: будь-який спроба дізнатися щось точне про поведінку програми неминуче вимагає її виконання. І якщо ця програма містить приховані нескінченні цикли або складну логіку, що залежить від зовнішніх чинників (Проблема зупинки), наш аналізатор приречений або дати неточну відповідь, обірвавши аналіз за тайм-аутом, або зависнути назавжди разом із цільовою програмою. Саме тому досконалий статичний аналізатор написати неможливо.
