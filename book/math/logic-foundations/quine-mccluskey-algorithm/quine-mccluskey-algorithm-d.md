- [Мінімізація логічних функцій](book:math/logic-minimization) — що таке імплікант, простий імплікант, істотний імплікант та дволанкова оптимізація.
- [Карти Карно](book:math/karnaugh-maps) — графічний пошук склейок та чому візуальний метод зупиняється на 4–6 змінних.
</preknowlist>

[Карта Карно](book:math/karnaugh-maps) чудово мінімізує логіку на площині, але її сила тримається виключно на людському зорі. До чотирьох змінних шістнадцять клітин утворюють звичну двовимірну сітку, де сусіди за один біт лежать поруч. Для п'яти змінних доводиться подумки тримати два шари 4×4 у тривимірному просторі. Для шести змінних карта перетворюється на матрицю з чотирьох карт 4×4 (шістнадцять тривимірних перевірок сусідства), а для восьми змінних знадобилося б двісті п'ятдесят шість окремих таблиць. Геометрична інтуїція людини вичерпується: око не здатне бачити діагональні склейки крізь чотиривимірні гіперкуби. Комп'ютер натомість зору не має — йому потрібен суворий, табличний, суто алгебраїчний алгоритм (від імені середньовічного математика аль-Хорезмі, лат. *Algorithmi*), який виконує мінімізацію над числовими бітовими наборами для будь-якої кількості змінних без побудови просторових фігур.

Саме таку процедуру 1952 року започаткував американський логік і філософ Віллард Квайн (англ. *Willard Van Orman Quine*), а 1956 року інженер Едвард Мак-Класкі (англ. *Edward J. McCluskey*) із Массачусетського технологічного інституту довів її до табличного алгоритму, розробленого для автоматичного обчислення на цифрових машинах. Як розвивалася ця концепція від філософських семінарів у Гарварді до лабораторій Bell Labs, висвітлює історичний нарис [Квайн, Мак-Класкі й народження мінімізації](book:math/karnaugh-map/hist-quine-mccluskey.md).

Метод Квайна–Мак-Класкі (англ. *Quine–McCluskey algorithm*, або *метод простих імплікантів*) гарантує знаходження **абсолютно точного мінімуму** диз'юнктивної нормальної форми (ДНФ) логічної функції. Увесь процес чітко розпадається на дві послідовні фази:
1. **Фаза 1:** повне систематичне знаходження **всіх** простих імплікантів функції шляхом каскадного склеювання двійкових векторів.
2. **Фаза 2:** вибір **найменшої** підмножини знайдених простих імплікантів, яка повністю накриває всі одиничні значення функції, за допомогою матриці покриття та правил редукції.

![Двоетапна структура методу Квайна–Мак-Класкі](/book/math/logic-foundations/quine-mccluskey-algorithm/img/qm-pipeline.svg)
*Двоетапна архітектура методу: від двійкових мінтермів через вагу Геммінга до повного переліку простих імплікантів (Фаза 1), а звідти через матрицю покриття до мінімальної ДНФ (Фаза 2).*

### Двійковий гіперкуб і відстань Геммінга

Будь-яка логічна функція `n` змінних однозначно визначається множиною своїх одиничних наборів — **мінтермів**. Кожен мінтерм є вершиною `n`-вимірного двійкового гіперкуба `{0, 1}ⁿ` і записується послідовністю з `n` бітів. Наприклад, для чотирьох змінних `(A, B, C, D)` мінтерм `m5` відповідає двійковому числу `5 = 0101₂`, тобто добутку `Ā·B·C̄·D`.

Фундаментом усієї мінімізації є булева тотожність склеювання (винесення спільного консенсусу, лат. *consensus* — згода, спільність):

```
X·y + X·ȳ
= X·(y + ȳ)    [дистрибутивність: винесення спільного множника X]
= X·1          [доповнення: y + ȳ = 1]
= X            [нейтральний елемент: X·1 = X]
```

Два доданки склеюються в один тоді й лише тоді, коли їхні двійкові вектори збігаються в усіх позиціях, окрім **рівно однієї**. Кількість позицій, у яких різняться два двійкові вектори однакової довжини, називають **відстанню Геммінга** (англ. *Hamming distance*) `d_H(u, v)`. На двійковому рівні вона дорівнює кількості одиниць у результаті побітового виключного АБО (`XOR`):

```
d_H(u, v) = popcount(u ⊕ v)
```

Якщо `d_H(u, v) = 1`, то вектори `u` та `v` різняться рівно одним бітом. Їхнє склеювання породжує інтервал гіперкуба (1-куб, або грань), у якому змінна, що відрізнялася, випадає, а на її місці записують прочерк `-` (символ «байдуже»):

```
m0 (0000 = Ā·B̄·C̄·D̄)  і  m1 (0001 = Ā·B̄·C̄·D)
= 000- (Ā·B̄·C̄)
```

Кожен такий прочерк означає, що терм охоплює дві сусідні вершини гіперкуба ціною вилучення однієї літери з кон'юнкції. Подальше склеювання двох 1-кубів із однаковим розташуванням прочерків (`000-` та `001-`) породжує 2-куб із двома прочерками (`00--` = `Ā·B̄`), що накриває чотири вершини двома літерами.

### Фаза 1: Каскадне склеювання за вагою Геммінга

Якби ми порівнювали кожен мінтерм із кожним серед `N` одиниць функції, це вимагало б `N·(N - 1) / 2` попарних перевірок на першому кроці, а на наступних кроках кількість порівнянь зростала б лавиноподібно.

Геніальна оптимізація Едварда Мак-Класкі полягає у використанні **ваги Геммінга** (англ. *Hamming weight*, або `popcount`) — кількості одиничних бітів у двійковому записі числа `w(u)`.

> **Властивість ваги Геммінга:** якщо два двійкові вектори `u` та `v` різняться рівно в одному біті (`d_H(u, v) = 1`), то кількість одиниць у них **обов'язково різниться рівно на одиницю**:
> 
> ```
> |w(u) - w(v)| = 1
> ```

Якщо вектори мають однакову кількість одиниць (`w(u) = w(v)`), вони можуть різнитися щонайменше у двох бітах (один біт замінено з 0 на 1, інший — з 1 на 0). Якщо різниця кількості одиниць становить два або більше, відстань Геммінга не менша за два.

Звідси випливає фундаментальне спрощення:
1. Усі початкові мінтерми розподіляють за класами (групами) `G₀, G₁, G₂, …, Gₙ`, де індекс групи `k` дорівнює кількості одиниць у векторі.
2. Порівняння проводять **виключно між сусідніми групами** `Gₖ` та `Gₖ₊₁`. Порівнювати терми всередині однієї групи або через групу (наприклад, `G₀` із `G₂`) математично беззмістовно — відстань Геммінга між ними гарантовано більша за 1.

![Покрокове склеювання за групами ваги Геммінга](/book/math/logic-foundations/quine-mccluskey-algorithm/img/group-merging.svg)
*Розбиття мінтермів за вагою Геммінга (кількістю одиниць) та попарне склеювання між суміжними групами. Терми, що не склеїлися на жодному етапі (позначено ★), утворюють повний набір простих імплікантів.*

#### Алгоритм склеювання по кроках:

1. **Раунд 0 (0-куби, мінтерми):**
   - Розподілити всі мінтерми за групами `G₀, …, Gₙ` відповідно до їхнього `popcount`.
2. **Формування наступного раунду (1-куби з одним прочерком):**
   - Для кожного елемента групи `Gₖ` перевірити кожен елемент групи `Gₖ₊₁`.
   - Якщо вони різняться рівно в одному біті, записати новий терм із прочерком `-` на місці цього біта до відповідної групи наступного списку.
   - Обидва вихідні терми позначаються прапорцем «використано» (`✓`).
3. **Ітерація для вищих кубів (2-куби, 4-куби тощо):**
   - Два терми вищого порядку можуть склеїтися тоді й лише тоді, коли:
     * їхні прочерки розташовані в **абсолютно однакових позиціях**;
     * за незмінними бітами вони різняться **рівно в одній позиції**.
   - Наприклад, `(0, 1)` із кодом `000-` та `(8, 9)` із кодом `100-` мають прочерк у молодшому біті й різняться лише старшим бітом → склеюються у 2-куб `(0, 1, 8, 9)` із кодом `-00-` (`B̄·C̄`).
   - Усі об'єднані терми знову отримують позначку `✓`.
   - При утворенні однакових кубів різними шляхами дублікати вилучаються.
4. **Збір простих імплікантів:**
   - Процес зупиняється, коли в новому раунді не вдається утворити жодної нової склейки.
   - Усі терми з усіх раундів (0-го, 1-го, 2-го тощо), які **не отримали жодної позначки `✓`**, є **простими імплікантами** (лат. *implicare* — вплітати; англ. *prime implicants*, PI). Їх більше неможливо розширити, і саме вони є максимальними блоками для побудови схеми.

### Врахування невизначених станів (Don't-Care)

У багатьох реальних цифрових пристроях певні вхідні двійкові комбінації є фізично неможливими або їхній вихід не має значення для системи (наприклад, коди 1010–1111 у двійково-десяткових лічильниках 8421 BCD). Такі комбінації позначають як **невизначені стани** (англ. *don't-care conditions*, `d`).

Метод Квайна–Мак-Класкі враховує невизначені стани з бездоганною строгістю:
- **На Фазі 1:** мінтерми `d` заносять до початкових груп `Gₖ` на рівних правах із обов'язковими мінтермами `F`. Вони беруть повноцінну участь у склеюванні, дозволяючи утворювати ширші куби (4-куби, 8-куби) та зменшувати кількість літер у простих імплікантах.
- **На Фазі 2:** мінтерми `d` **вилучають із заголовків стовпців** таблиці покриття. Оскільки система не зобов'язана видавати одиницю на наборах `d`, покривати їх не потрібно. Вони лише допомогли простим імплікантам стати ширшими й дешевшими.

### Фаза 2: Таблиця покриття простих імплікантів

Отримавши повний перелік простих імплікантів, ми стикаємося з другою задачею: їх зазвичай значно більше, ніж потрібно для представлення функції. Необхідно відібрати мінімальну за ціною підмножину імплікантів, сума яких накриє всі обов'язкові мінтерми функції.

Для цього будують **таблицю покриття** (англ. *prime implicant chart*):
- **Рядки** відповідають знайденим простим імплікантам `P₁, P₂, …`.
- **Стовпці** відповідають обов'язковим одиничним мінтермам функції `m₁, m₂, …`.
- На перетині рядка `Pᵢ` та стовпця `mⱼ` ставлять позначку `✕`, якщо імплікант `Pᵢ` накриває мінтерм `mⱼ` (тобто бітовий шаблон `Pᵢ` узгоджується з двійковим кодом `mⱼ`).

![Таблиця покриття: виявлення істотних імплікантів та редукція](/book/math/logic-foundations/quine-mccluskey-algorithm/img/pi-chart-reduction.svg)
*Таблиця покриття: стовпці з єдиним знаком «✕» виявляють істотні прості імпліканти (зелені рядки). Після їхнього вилучення решта розв'язується правилами домінування рядків.*

#### Крок 2.1: Виділення істотних простих імплікантів (EPI)

Перший крок розв'язання таблиці є безальтернативним:
1. Переглядають усі стовпці таблиці.
2. Якщо стовпець містить **рівно одну** позначку `✕`, простий імплікант у відповідному рядку є **істотним** (англ. *essential prime implicant*, EPI).
3. **Чому це неминуче:** цей мінтерм не здатний накрити жоден інший простий імплікант. Якщо ми не включимо цей імплікант у вираз, відповідний мінтерм залишиться нулем, і функція буде реалізована неправильно.
4. Усі знайдені EPI обов'язково додають до фінальної суми.
5. Після обрання EPI викреслюють його рядок, а також **усі стовпці**, які він накриває (навіть ті, що мали багато інших позначок).

Якщо після викреслення всіх EPI всі стовпці виявилися закритими, мінімізація завершена — знайдено точний мінімум.

### Правила редукції таблиці: домінування

Коли після вилучення істотних імплікантів у таблиці ще залишаються непокриті стовпці, таблицю спрощують за допомогою двох правил алгебраїчного **домінування**:

```
Домінування рядків:     Рядок A накриває підмножину стовпців рядка B (C_A ⊆ C_B)
                        → Рядок A слабший, його можна викреслити (A вилучається)

Домінування стовпців:   Стовпець j накривається підмножиною рядків стовпця k (R_j ⊆ R_k)
                        → Покриття жорсткішого j автоматично покриє вільніший k
                        → Стовпець k можна викреслити (k вилучається)
```

#### 1. Домінування рядків (Row Dominance)
Нехай маємо два рядки `P_a` та `P_b` з однаковою кількістю літер. Якщо множина стовпців, які накриває `P_b`, повністю містить у собі множину стовпців, які накриває `P_a` (тобто `P_b` накриває все те саме, що й `P_a`, плюс іще якісь стовпці):
- Рядок `P_a` називають **домінованим** (слабшим).
- Будь-який розв'язок, що містить `P_a`, можна без втрати покриття покращити або зробити рівноцінним, замінивши `P_a` на `P_b`.
- Рядок `P_a` **вилучають із таблиці**.

#### 2. Домінування стовпців (Column Dominance)
Нехай маємо два стовпці `C_j` та `C_k`. Якщо стовпець `C_k` має позначки `✕` в усіх тих рядках, де має позначки `C_j`, та ще й у деяких додаткових рядках:
- Стовпець `C_k` називають **домінуючим** над `C_j` (його легше накрити).
- Стовпець `C_j` є більш жорстким: будь-який імплікант, обраний для накриття `C_j`, **автоматично накриє і `C_k`**.
- Окремо піклуватися про стовпець `C_k` більше немає потреби — **стовпець `C_k` вилучають із таблиці**.

> ⚠️ **Увага на дзеркальність:** у правилі рядків вилучають **менший** (домінований) рядок, бо шукають найефективніший імплікант. У правилі стовпців вилучають **більший** (домінуючий) стовпець, бо задоволення жорсткішої вимоги автоматично задовольняє м'якшу!

Редукцію повторюють циклічно: домінування рядків → домінування стовпців → пошук нових EPI (оскільки після скорочень у деяких стовпцях могла залишитися єдина позначка).

### Циклічне ядро та метод Патріка

У складних функціях після застосування всіх можливих правил домінування таблиця може зменшитися, але не спорожніти. Виникає ситуація, коли:
- у кожному стовпці залишилося щонайменше дві позначки `✕` (немає EPI);
- жоден рядок не містить у собі інший;
- жоден стовпець не містить у собі інший.

Таку нерозкладну матрицю називають **циклічним ядром** (англ. *cyclic core*).

![Циклічна таблиця покриття та розв'язання за методом Патріка](/book/math/logic-foundations/quine-mccluskey-algorithm/img/cyclic-core-petrick.svg)
*Циклічне ядро, у якому жоден стовпець не має єдиного імпліканта, та його точне алгебраїчне розкриття за методом Патріка у суму альтернативних мінімальних покриттів.*

Для точного розв'язання циклічного ядра застосовують два еквівалентні підходи:

1. **[Метод Патріка](book:math/logic-foundations/quine-mccluskey-algorithm/math-petrick-method.md)**: кожному простому імпліканту зіставляють булеву змінну `Pᵢ`. Для кожного стовпця записують суму `(P_{a} + P_{b} + …) = 1`, а загальну вимогу покриття формулюють як кон'юнкцію всіх умов `∏ (P_{a} + P_{b}) = 1`. Розкриваючи дужки за дистрибутивним законом і застосовуючи закон поглинання булевої алгебри `X + X·Y = X`, отримують диз'юнктивну нормальну форму `P = P₁·P₃·P₅ + P₂·P₄·P₆ + …`. Кожен кон'юнктивний доданок є валідним покриттям, серед яких обирають доданок із мінімальною кількістю термів та літер.
2. **Метод гілок і меж (правило розщеплення Квайна):** обирають опорний імплікант `Pᵢ` і рекурсивно розглядають дві гілки:
   - Гілка «взяти `Pᵢ`»: додаємо `Pᵢ` до розв'язку і спрощуємо таблицю.
   - Гілка «відкинути `Pᵢ`»: викреслюємо рядок `Pᵢ` і шукаємо розв'язок серед решти.

### Наскрізний покроковий приклад

Розглянемо повну мінімізацію 4-змінної функції `F(A,B,C,D)`:

```
F(A,B,C,D) = Σ m(0, 1, 2, 5, 6, 7, 8, 9, 10, 14)
```

Початковий наївний запис складався б із 10 доданків по 4 літери (40 входів вентилів).

#### Фаза 1: Склеювання за групами ваги Геммінга

**Крок 1: Розподіл за кількістю одиниць:**

```
Група      Мінтерм    Двійковий код    Позначка
───────────────────────────────────────────────
G₀ (w=0)   m0         0000             ✓
───────────────────────────────────────────────
G₁ (w=1)   m1         0001             ✓
           m2         0010             ✓
           m8         1000             ✓
───────────────────────────────────────────────
G₂ (w=2)   m5         0101             ✓
           m6         0110             ✓
           m9         1001             ✓
           m10        1010             ✓
───────────────────────────────────────────────
G₃ (w=3)   m7         0111             ✓
           m14        1110             ✓
```

**Крок 2: Порівняння сусідніх груп (утворення 1-кубів):**

```
Пари G₀ × G₁:
(0, 1)   000-   ✓
(0, 2)   00-0   ✓
(0, 8)   -000   ✓

Пари G₁ × G₂:
(1, 5)   0-01   ★ (не склеюється у 2-куб → простий імплікант Ā·C̄·D)
(1, 9)   -001   ✓
(2, 6)   0-10   ✓
(2, 10)  -010   ✓
(8, 9)   100-   ✓
(8, 10)  10-0   ✓

Пари G₂ × G₃:
(5, 7)   01-1   ★ (не склеюється у 2-куб → простий імплікант Ā·B·D)
(6, 7)   011-   ★ (не склеюється у 2-куб → простий імплікант Ā·B·C)
(6, 14)  -110   ✓
(10, 14) 1-10   ✓
```

**Крок 3: Склеювання 1-кубів у 2-куби (терми з двома прочерками):**
- `(0, 1)` `000-` і `(8, 9)` `100-` → `(0, 1, 8, 9)` з кодом `-00-` (`B̄·C̄`) ★
- `(0, 8)` `-000` і `(1, 9)` `-001` → той самий куб `(0, 1, 8, 9)` `-00-` (дублікат)
- `(0, 2)` `00-0` і `(8, 10)` `10-0` → `(0, 2, 8, 10)` з кодом `-0-0` (`B̄·D̄`) ★
- `(0, 8)` `-000` і `(2, 10)` `-010` → той самий куб `(0, 2, 8, 10)` `-0-0` (дублікат)
- `(2, 6)` `0-10` і `(10, 14)` `1-10` → `(2, 6, 10, 14)` з кодом `--10` (`C·D̄`) ★
- `(2, 10)` `-010` і `(6, 14)` `-110` → той самий куб `(2, 6, 10, 14)` `--10` (дублікат)

Усі терми 2-го раунду більше не склеюються.

**Зібрані прості імпліканти (PI):**
- `P1`: `-00-` = `B̄·C̄` (покриває 0, 1, 8, 9; 2 літери)
- `P2`: `-0-0` = `B̄·D̄` (покриває 0, 2, 8, 10; 2 літери)
- `P3`: `--10` = `C·D̄` (покриває 2, 6, 10, 14; 2 літери)
- `P4`: `0-01` = `Ā·C̄·D` (покриває 1, 5; 3 літери)
- `P5`: `01-1` = `Ā·B·D` (покриває 5, 7; 3 літери)
- `P6`: `011-` = `Ā·B·C` (покриває 6, 7; 3 літери)

#### Фаза 2: Таблиця покриття та розв'язання

Складаємо матрицю розміру 6 рядків на 10 стовпців:

```
Імплікант     0    1    2    5    6    7    8    9    10   14
────────────────────────────────────────────────────────────
P1 (B̄·C̄)      ✕    ✕                        ✕    ✕
P2 (B̄·D̄)      ✕         ✕                   ✕         ✕
P3 (C·D̄)                ✕         ✕                   ✕    ✕
P4 (Ā·C̄·D)         ✕         ✕
P5 (Ā·B·D)                   ✕         ✕
P6 (Ā·B·C)                        ✕    ✕
```

**Крок 1: Пошук стовпців з єдиним «✕»:**
- Стовпець `m9` містить позначку лише в рядку **P1** → **P1 є істотним (EPI)**!
- Стовпець `m14` містить позначку лише в рядку **P3** → **P3 є істотним (EPI)**!

Беремо `P1` і `P3` до мінімальної форми.
- `P1` накриває стовпці: `0, 1, 8, 9`.
- `P3` накриває стовпці: `2, 6, 10, 14`.

Викреслюємо ці стовпці. Непокритими залишилися лише два мінтерми: `{5, 7}`.

**Крок 2: Домінування рядків для залишку:**
Подивимося на рядки, що можуть накрити `{5, 7}`:
- `P2`: накриває `{0, 2, 8, 10}` — жодного з `{5, 7}` → відкидаємо.
- `P4`: накриває `{1, 5}` → серед залишку накриває лише `{5}`.
- `P5`: накриває `{5, 7}` → серед залишку накриває **обидва** `{5, 7}`!
- `P6`: накриває `{6, 7}` → серед залишку накриває лише `{7}`.

Рядок `P5` строго домінує над `P4` та `P6`, оскільки самостійно закриває всю решту стовпців при тій самій ціні (3 літери). Обираємо `P5`.

**Остаточна мінімальна форма:**

```
F(A,B,C,D) = B̄·C̄ + C·D̄ + Ā·B·D
```

Замість початкових 10 доданків і 40 входів вентилів ми отримали **3 доданки і 7 входів** — майже у шість разів дешевша та швидша схема. Повний робочий код для автоматичного розрахунку цієї та довільних інших функцій наведено у практичній вставці [Реалізація алгоритму Квайна–Мак-Класкі](book:math/logic-foundations/quine-mccluskey-algorithm/proj-qm-solver.md).

### Асимптотична складність і межі застосування

Незважаючи на математичну елегантність, метод Квайна–Мак-Класкі має жорстку алгоритмічну межу.

1. **Кількість простих імплікантів:**
   У гіршому випадку кількість простих імплікантів логічної функції росте експоненційно. Теоретична верхня межа (доведена Чандрою та Марковським, 1978) оцінюється як:
   
   ```
   N_PI = O(3ⁿ / n)    або    O(3ⁿ / √n)
   ```
   
   Для `n = 4` це щонайбільше десятки імплікантів. Але вже для `n = 16` функція може мати понад `100 000` простих імплікантів, а для `n = 32` їхня кількість перевищує мільярди.
2. **NP-важкість другої фази:**
   Задача точного вибору мінімального покриття на Фазі 2 є прямим екземпляром класичної задачі [покриття множини](book:algorithms/set-cover) (англ. *Set Cover*), яка належить до класу **NP-важких**.

Саме тому метод Квайна–Мак-Класкі слугує **еталоном абсолютно точної мінімізації** для невеликих та середніх блоків (до 10–15 змінних). Для проєктування великих інтегральних схем із сотнями входів сучасні САПР (EDA) використовують евристичні мінімізатори на зразок **ESPRESSO** (розроблені в Каліфорнійському університеті в Берклі), які не будують повного каталогу імплікантів, а циклічно розширюють і зменшують куби, знаходячи квазіоптимальний розв'язок за поліноміальний час.

> 🔧 **Навіщо це.** Метод Квайна–Мак-Класкі є фундаментом логічного синтезу цифрових мікросхем. Він використовується:
> - У компіляторах мов опису апаратури (Verilog, VHDL) для оптимізації комбінаційних блоків перед укладанням у таблиці перекодування (LUT, Look-Up Tables) у [ПЛІС (FPGA)](book:electronics/programmable-logic).
> - Для автоматичного проєктування графів переходів і виходів керуючих автоматів Мура й Мілі.
> - При компресії та апаратній оптимізації правил міжмережевих екранів (firewalls), списків контролю доступу (ACL) та таблиць маршрутизації мережевих пакетів за масками IP-адрес.
