# ⚙️ SAT-розв'язувач DPLL (DPLL SAT Solver)

Алгоритм Девіса-Патнема-Логемана-Лавленда (DPLL) вирішує задачу здійсненності булевих формул (SAT) у кон'юнктивній нормальній формі (CNF) через одиничну поширеність та відсікання гілок пошуку.

## Постановка інженерної задачі та інтуїція рішення
Задача здійсненності булевих формул (SAT) полягає у визначенні, чи існує набір значень логічних змінних, за якого формула набуває значення "Істина". Формула зазвичай подається у кон'юнктивній нормальній формі (CNF) — як кон'юнкція (І) диз'юнкцій (АБО) літералів. Наївний підхід за допомогою таблиць істинності вимагає O(2^N) часу і є непридатним для реальних задач із тисячами змінних.

Алгоритм DPLL вирішує цю проблему за допомогою розумного перебору з поверненням (backtracking). Інтуїція полягає в тому, щоб на кожному кроці приймати рішення щодо значення однієї змінної (наприклад, x = True), спрощувати формулу на основі цього рішення, і рекурсивно перевіряти здійсненність. Щоб оптимізувати процес, DPLL використовує два ключові правила: поширення одиничних диз'юнкцій (Unit Propagation) та виключення чистих літералів (Pure Literal Elimination).

## Логічна архітектура та алгоритм
Формулу в CNF можна зобразити як набір (вектор) клозів (диз'юнкцій), де кожен клоз — це вектор цілих чисел. Додатне число `i` означає змінну `X_i`, від'ємне `-i` — заперечення змінної `NOT X_i`.
Алгоритм DPLL працює так:
1. **Базові випадки:** Якщо набір клозів порожній, формула здійсненна (True). Якщо набір містить порожній клоз, формула нездійсненна (False) у поточній гілці.
2. **Unit Propagation (Поширення одиниць):** Якщо існує клоз лише з одним літералом (одиничний клоз), ця змінна повинна набути значення, що робить цей літерал істинним. Ми призначаємо це значення, видаляємо всі клози, що містять цей літерал, і видаляємо протилежний літерал з усіх інших клозів.
3. **Pure Literal (Чистий літерал):** Якщо змінна зустрічається лише з однією полярністю (завжди додатна або завжди від'ємна) у всій формулі, ми призначаємо їй значення, що робить цей літерал істинним, і видаляємо всі клози з ним.
4. **Branching (Галуження):** Якщо правила вище не застосовні, обираємо будь-яку нерозподілену змінну, припускаємо спочатку, що вона True, і рекурсивно викликаємо DPLL. Якщо це призводить до конфлікту, ми повертаємося (backtrack) і припускаємо, що вона False.

## Повний робочий код на C++

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <set>

// Представлення CNF формули
// Літерали: 1 для X1, -1 для NOT X1
using Clause = std::vector<int>;
using Formula = std::vector<Clause>;

// Функція для пошуку одиничного клозу
int findUnitClause(const Formula& formula) {
    for (const auto& clause : formula) {
        if (clause.size() == 1) {
            return clause[0];
        }
    }
    return 0; // 0 означає, що одиничних клозів не знайдено
}

// Функція для застосування поширення одиниць або спрощення після вибору
Formula simplify(Formula formula, int literal) {
    Formula newFormula;
    for (const auto& clause : formula) {
        // Якщо клоз містить літерал, він стає True, тому весь клоз видаляється (задоволений)
        if (std::find(clause.begin(), clause.end(), literal) != clause.end()) {
            continue;
        }
        
        // Якщо клоз містить протилежний літерал, цей літерал стає False і видаляється з клозу
        Clause newClause;
        for (int l : clause) {
            if (l != -literal) {
                newClause.push_back(l);
            }
        }
        newFormula.push_back(newClause);
    }
    return newFormula;
}

// Головна рекурсивна функція DPLL
bool dpll(Formula formula) {
    // 1. Базові випадки
    if (formula.empty()) return true; // Всі клози задоволені
    for (const auto& clause : formula) {
        if (clause.empty()) return false; // Конфлікт: знайдено порожній клоз
    }

    // 2. Unit Propagation (Поширення одиничних клозів)
    int unitLiteral = findUnitClause(formula);
    while (unitLiteral != 0) {
        formula = simplify(formula, unitLiteral);
        if (formula.empty()) return true;
        for (const auto& clause : formula) {
            if (clause.empty()) return false;
        }
        unitLiteral = findUnitClause(formula);
    }

    // 3. Branching (Вибір нерозподіленої змінної)
    // Обираємо перший літерал з першого клозу
    if (formula.empty()) return true; // Перевірка безпеки
    int splitLiteral = formula.front().front();

    // Спроба призначити змінній True
    if (dpll(simplify(formula, splitLiteral))) {
        return true;
    }

    // Backtrack: Спроба призначити змінній False
    return dpll(simplify(formula, -splitLiteral));
}

int main() {
    // Формула: (X1 OR NOT X2) AND (NOT X1 OR X2) AND (X1 OR X2) AND (NOT X1 OR NOT X2)
    // Це класичний приклад нездійсненної формули (XNOR AND XOR).
    Formula cnf = {
        {1, -2},
        {-1, 2},
        {1, 2},
        {-1, -2}
    };

    bool isSatisfiable = dpll(cnf);
    std::cout << "Formula is " << (isSatisfiable ? "SATISFIABLE" : "UNSATISFIABLE") << std::endl;
    
    return 0;
}
```

## Построчний аналіз, пам'ять та керування ресурсами
У цій реалізації `Formula` передається по значенню у функцію `simplify` та `dpll`. Це призводить до копіювання векторів на кожному рекурсивному виклику. Для навчальної демонстрації це робить код надзвичайно читабельним та імутабельним. Однак у промислових (production) SAT-сольверах (таких як MiniSat або CaDiCaL) таке копіювання є недопустимим через величезні накладні витрати пам'яті O(C * L), де C - кількість клозів, L - середня довжина. Натомість там використовують індексовані масиви, алгоритм "Two-Watched Literals" та in-place модифікації стану зі стеком відкату.

Критичний момент `std::find(clause.begin(), clause.end(), literal)` у функції `simplify` відповідає за перевірку, чи задовольняє поточний вибір даний клоз. Якщо так, `continue;` гарантує, що весь клоз відкидається (не потрапляє у `newFormula`). Запобіжник `if (clause.empty()) return false;` реагує на порушення інваріанту: якщо всі літерали в клозі стали хибними (відкинутими), клоз неможливо задовольнити, тому гілка визнається тупиковою.

## Вхідні та вихідні дані і оцінка складності (I/O)
Приклад виконання для `(X1 OR NOT X2) AND (NOT X1 OR X2) AND (X1 OR X2) AND (NOT X1 OR NOT X2)`:
```text
Formula is UNSATISFIABLE
```
**Оцінка складності:**
- **Часова складність:** У найгіршому випадку O(2^N * M), де N — кількість змінних, M — загальна довжина формули. Проте завдяки евристикам та Unit Propagation практичний час на багатьох екземплярах значно кращий (суб-експоненційний або поліноміальний для певних класів задач).
- **Просторова складність:** O(N * M) через копіювання `Formula` на кожному рівні рекурсії стеку (який може мати глибину до N). Це O(N^2 * C) загалом. In-place версії зводять пам'ять до строгого O(M).
