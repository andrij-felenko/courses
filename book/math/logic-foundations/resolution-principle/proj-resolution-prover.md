# ⚙️ Резолюційний прувер (Resolution Prover)

Метод резолюцій Робінсона доводить теореми від супротивного через парне поєднання диз'юнктів та виведення порожнього кляуза $\square$.

## Постановка інженерної задачі та інтуїція рішення
Метод резолюцій використовується для доведення теорем "від супротивного" (refutation proof). Якщо ми хочемо довести, що база знань (Knowledge Base, KB) імплікує теорему `T`, ми повинні показати, що об'єднання `KB` та заперечення `¬T` є логічно суперечливим (нездійсненним).

Всі формули повинні бути попередньо зведені до кон'юнктивної нормальної форми (CNF) — набору диз'юнкцій (клозів). Інтуїція правила резолюції дуже проста: якщо у нас є факти `(A ∨ B)` та `(¬B ∨ C)`, ми можемо зробити висновок, що має виконуватися `(A ∨ C)`, оскільки `B` не може бути істинним і хибним одночасно. Цей новий факт називається резольвентою. Алгоритм полягає в ітеративному застосуванні цього правила до наявної бази клозів, поки ми не отримаємо "порожній клоз" (абсолютну суперечність).

## Логічна архітектура та алгоритм генерації резольвент
1. База знань зберігається як множина клозів (щоб уникати дублювання).
2. Ми створюємо два вкладені цикли, що ітерують по всім можливим парам існуючих клозів `Ci` та `Cj`.
3. Для кожної пари перевіряємо, чи існує комплементарна пара літералів (наприклад, змінна `X` в `Ci` і `¬X` в `Cj`).
4. Якщо така пара існує, ми застосовуємо правило резолюції: видаляємо ці два літерли і об'єднуємо решту літерлів в новий клоз (резольвенту).
5. Якщо отримана резольвента є порожньою (тобто ми зробили резолюцію `X` і `¬X`), це означає пряме протиріччя. Доведення успішне.
6. Якщо ні, додаємо нову резольвенту до бази. Якщо після всіх можливих об'єднань база не поповнилася новими клозами (сатурація), то доведення неможливе.

## Повний робочий код на C++

```cpp
#include <iostream>
#include <vector>
#include <set>
#include <algorithm>

// Літерали представлені цілими числами (додатні = X, від'ємні = ¬X)
// Клоз є впорядкованою множиною літерлів для швидкого порівняння та уникнення дублікатів (наприклад X v X -> X)
using Clause = std::set<int>;

// База знань
using ClauseSet = std::set<Clause>;

// Функція для виконання резолюції між двома клозами
// Повертає вектор можливих резольвент (їх може бути декілька, якщо є кілька комплементарних пар)
std::vector<Clause> resolve(const Clause& c1, const Clause& c2) {
    std::vector<Clause> resolvents;

    for (int l1 : c1) {
        // Шукаємо комплементарний літерал у c2
        if (c2.find(-l1) != c2.end()) {
            Clause res;
            // Копіюємо всі елементи з c1, окрім l1
            for (int x : c1) if (x != l1) res.insert(x);
            // Копіюємо всі елементи з c2, окрім -l1
            for (int x : c2) if (x != -l1) res.insert(x);
            
            resolvents.push_back(res);
        }
    }
    return resolvents;
}

// Головний цикл резолюційного прувера
bool resolutionProver(ClauseSet kb) {
    ClauseSet newClauses;

    while (true) {
        int pairsChecked = 0;
        newClauses.clear();

        // Ітеруємо по всіх парах клозів (O(N^2) на кожній ітерації)
        for (auto it1 = kb.begin(); it1 != kb.end(); ++it1) {
            auto it2 = it1; ++it2; // Починаємо з наступного, щоб не дублювати пари і не резольвувати з собою
            for (; it2 != kb.end(); ++it2) {
                std::vector<Clause> resolvents = resolve(*it1, *it2);
                
                for (const Clause& res : resolvents) {
                    // Якщо отримали порожній клоз - знайдено протиріччя
                    if (res.empty()) {
                        return true; 
                    }
                    newClauses.insert(res);
                }
                pairsChecked++;
            }
        }

        // Перевіряємо, чи отримали ми хоча б один НОВИЙ клоз
        bool hasNew = false;
        for (const Clause& c : newClauses) {
            if (kb.find(c) == kb.end()) {
                kb.insert(c);
                hasNew = true;
            }
        }

        // Якщо нових клозів немає (сатурація бази знань), протиріччя не знайдено
        if (!hasNew) {
            return false; 
        }
    }
}

int main() {
    // Задача: маємо правила (¬A ∨ B), (¬B ∨ C), і факт (A).
    // Хочемо довести теорему (C).
    // Доведення від супротивного: додаємо заперечення теореми, тобто (¬C), до бази.
    ClauseSet kb = {
        {-1, 2},  // ¬A ∨ B
        {-2, 3},  // ¬B ∨ C
        {1},      // A
        {-3}      // ¬C (Заперечення теореми)
    };

    if (resolutionProver(kb)) {
        std::cout << "Theorem PROVED by contradiction.\n";
    } else {
        std::cout << "Theorem CANNOT be proved.\n";
    }

    return 0;
}
```

## Построчний аналіз, пам'ять та керування ресурсами
Реалізація клозу як `std::set<int>` автоматично обробляє проблему дуплікації літерлів (ідемпотентність `A ∨ A ≡ A`) та сортування. Це забезпечує безпечне та коректне порівняння клозів, коли ми перевіряємо їх наявність в базі: `kb.find(c) == kb.end()`. 

Найбільша небезпека методу резолюцій — це комбінаторний вибух розміру бази знань `kb`. У циклі ми генеруємо всі можливі резольвенти між існуючими клозами. Для бази з N клозів, ми робимо `O(N^2)` перевірок. Але якщо ми додаємо нові клози, N збільшується експоненційно (за умови довгого виведення). Інваріант перевірки `hasNew` гарантує зупинку: алгоритм припиняється, як тільки об'єм простору клозів вичерпано (сатурація).

Крайовий випадок — порожній клоз (результат резолюції `X` та `¬X`). У нашому коді це перевіряється через `if (res.empty()) return true;`. Це і є точкою виходу при успішному доведенні.

## Вхідні та вихідні дані і оцінка складності (I/O)
Приклад виконання для бази: `{¬A ∨ B, ¬B ∨ C, A, ¬C}`:
```text
Theorem PROVED by contradiction.
```
Розгортання:
- Резолюція `{-1, 2}` та `{1}` дає `{2}` (B).
- Резолюція `{-2, 3}` та `{-3}` дає `{-2}` (¬B).
- Резолюція `{2}` та `{-2}` дає `{}` (Порожній клоз, протиріччя!).

**Оцінка складності:**
- **Часова складність:** У найгіршому випадку метод резолюцій потребує експоненційного часу `O(2^N)` (або навіть гірше, через комбінаторне накопичення клозів). Проте для рогових клозів (Horn clauses, наприклад у мові Prolog) існує лінійний алгоритм.
- **Просторова складність:** `O(3^N)` у найгіршому випадку, де N - кількість унікальних змінних, оскільки база `kb` може розростатися і зберігати величезну кількість згенерованих нових клозів, кожен з яких займає власну пам'ять у купі (через `std::set`).
