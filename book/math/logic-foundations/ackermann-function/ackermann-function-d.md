# Функція Аккермана

> **Навіщо це:** Функція Аккермана — це ключовий концептуальний прорив у розумінні меж комп'ютерних обчислень. Вона демонструє, що існують алгоритми, які є математично правильними і гарантовано завершуються, але їхня складність настільки велика, що виходить за межі будь-яких звичайних циклів (примітивної рекурсії). Вивчення цієї функції допомагає програмістам усвідомити різницю між теоретичною обчислюваністю та практичною здійсненністю, а також глибше зрозуміти природу рекурсії, яка використовується у повсякденній розробці програмного забезпечення.

Уявіть, що вам доручили написати програму, яка завжди зупиняється. Якщо ви використовуєте лише цикли, де кількість ітерацій відома ще до початку циклу (наприклад, цикл `for i in 1 to N`), ви можете бути впевнені, що ваша програма ніколи не зависне у нескінченному циклі. Тривалий час математики вважали, що будь-яку функцію, яку в принципі можна обчислити за допомогою алгоритму, можна реалізувати виключно за допомогою таких передбачуваних циклів. Цей клас алгоритмів називається **примітивно рекурсивними функціями**.

Але чи справді це межа? Чи існує алгоритм, який однозначно завершує свою роботу, дає точний результат, але який принципово неможливо записати за допомогою заздалегідь обмежених циклів? Відповідь на це запитання у 1928 році дав німецький математик Вільгельм Аккерман, представивши функцію, яка носить його ім'я.

Функція Аккермана — це математичний монстр. Вона визначається надзвичайно простими правилами, але результати, які вона генерує, зростають з такою шаленою швидкістю, що уява відмовляється їх осягнути. Це не просто академічний курйоз; ця функція провела чітку межу в теорії обчислюваності, довівши, що існують обчислювані функції, які виходять далеко за рамки примітивної рекурсії.

## Анатомія функції Аккермана

Сучасна версія функції Аккермана (часто звана функцією Аккермана-Петера) — це функція A(m, n), яка приймає два невід'ємні цілі числа (m та n) і повертає одне невід'ємне ціле число. Її визначення складається всього з трьох простих правил.

Ось ці правила:

1. Якщо m = 0, то результат дорівнює n + 1.
2. Якщо m > 0, але n = 0, ми викликаємо функцію знову, зменшивши m на одиницю, а замість n підставляємо 1: A(m - 1, 1).
3. Якщо і m > 0, і n > 0, ми робимо найбільш закручений крок. Ми викликаємо функцію, зменшивши m на одиницю, а як другий аргумент передаємо результат *ще одного* виклику функції Аккермана: A(m - 1, A(m, n - 1)).

Давайте подивимося на це у вигляді псевдокоду, щоб зробити правила більш наочними для програміста:

Формально, це записується як система рівностей:

A(0, n) = n + 1
A(m, 0) = A(m - 1, 1), якщо m > 0
A(m, n) = A(m - 1, A(m, n - 1)), якщо m > 0 і n > 0

На перший погляд, ці правила виглядають безневинно. Тут немає жодних складних математичних операцій, лише перевірка на нуль, додавання одиниці та віднімання одиниці. Як щось настільки просте може генерувати проблеми космічного масштабу? Секрет криється у третьому правилі — вкладеній рекурсії. Функція не просто посилається на саму себе; вона посилається на саму себе, щоб обчислити аргумент для іншого посилання. Це створює каскад розгортань, який росте як лавина.

## Розгортання базових випадків

Щоб зрозуміти, як працює ця лавина, давайте спробуємо обчислити функцію Аккермана для найменших можливих значень m. Ми будемо фіксувати m і дивитися, що відбувається, коли ми змінюємо n.

### Рівень нуль: m = 0

Це найпростіший випадок. Застосовується перше правило.
A(0, n) = n + 1.

Отже, коли m = 0, функція просто виконує операцію інкременту (додавання одиниці). 
A(0, 0) = 1
A(0, 1) = 2
A(0, 5) = 6.

### Рівень один: m = 1

Тепер зафіксуємо m = 1 і подивимося на A(1, n). Як це обчислюється?
Почнемо з n = 0:
A(1, 0) за другим правилом перетворюється на A(0, 1).
А з попереднього рівня ми знаємо, що A(0, 1) = 2.

Тепер n = 1:
A(1, 1) за третім правилом перетворюється на A(0, A(1, 0)).
Ми щойно обчислили, що A(1, 0) = 2. Отже, це стає A(0, 2).
А A(0, 2) = 2 + 1 = 3.

Тепер n = 2:
A(1, 2) = A(0, A(1, 1)) = A(0, 3) = 4.

Якщо ви уважно придивитеся, ви побачите шаблон: A(1, n) завжди повертає n + 2. Функція Аккермана для m = 1 фактично еквівалентна операції додавання двійки до числа. Додавання — це просто багаторазовий інкремент, і ми бачимо, як функція будує наступну математичну операцію з попередньої.

### Рівень два: m = 2

Переходимо до m = 2.
Для n = 0:
A(2, 0) = A(1, 1). Ми знаємо, що A(1, n) = n + 2, тому A(1, 1) = 1 + 2 = 3.

Для n = 1:
A(2, 1) = A(1, A(2, 0)) = A(1, 3) = 3 + 2 = 5.

Для n = 2:
A(2, 2) = A(1, A(2, 1)) = A(1, 5) = 5 + 2 = 7.

Для n = 3:
A(2, 3) = A(1, A(2, 2)) = A(1, 7) = 7 + 2 = 9.

Шаблон знову очевидний. Значення послідовності A(2, n) утворюють ряд: 3, 5, 7, 9... Це арифметична прогресія. Формула для A(2, n) дорівнює 2 * n + 3. Отже, рівень m = 2 відповідає операції множення! Знову ж таки, вкладена рекурсія третього правила перетворила операцію попереднього рівня (додавання) на операцію наступного рівня (множення).

Щоб візуалізувати процес розгортання вкладеної рекурсії, погляньте на рисунок нижче, який демонструє дерево обчислень для A(2, 1).

### Рівень три: m = 3

Що ж буде при m = 3? Якщо m = 0 було інкрементом, m = 1 — додаванням, m = 2 — множенням, то ми можемо очікувати, що m = 3 буде багаторазовим множенням, тобто піднесенням до степеня. Перевіримо це.

Для n = 0:
A(3, 0) = A(2, 1). Ми знаємо, що A(2, n) = 2 * n + 3, отже A(2, 1) = 5.

Для n = 1:
A(3, 1) = A(2, A(3, 0)) = A(2, 5) = 2 * 5 + 3 = 13.

Для n = 2:
A(3, 2) = A(2, A(3, 1)) = A(2, 13) = 2 * 13 + 3 = 29.

Для n = 3:
A(3, 3) = A(2, A(3, 2)) = A(2, 29) = 2 * 29 + 3 = 61.

Послідовність виглядає так: 5, 13, 29, 61. Якщо додати до кожного числа 3, ми отримаємо 8, 16, 32, 64. Це ж просто степені двійки!
Отже, A(3, n) + 3 = 2^(n + 3).
Або A(3, n) = 2^(n + 3) - 3.

Дійсно, рівень m = 3 відповідає піднесенню числа 2 до степеня, що зростає. Ми вийшли на рівень експоненціального зростання. Хоча формула вже виглядає грізно (наприклад, A(3, 10) = 2^13 - 3 = 8189), це все ще числа, які ми можемо легко обчислити на калькуляторі і зрозуміти. Справжній жах починається на наступному рівні.

### Рівень чотири: m = 4

Ми підійшли до межі того, що можна легко записати звичайними математичними символами.
A(4, 0) = A(3, 1) = 13. Це не страшно.
Але що таке A(4, 1)?
A(4, 1) = A(3, A(4, 0)) = A(3, 13).
Підставимо це у формулу для третього рівня:
A(3, 13) = 2^(13 + 3) - 3 = 2^16 - 3 = 65536 - 3 = 65533.

Гаразд, 65533 — це велике число, але воно поміщається навіть у 16-бітний регістр процесора. Здається, ми все ще контролюємо ситуацію. Спробуємо A(4, 2).

A(4, 2) = A(3, A(4, 1)) = A(3, 65533).
Знову використовуємо формулу третього рівня:
A(3, 65533) = 2^(65533 + 3) - 3 = 2^65536 - 3.

Зупиніться на мить і усвідомте це число. Два в степені шістдесят п'ять тисяч п'ятсот тридцять шість. Це число має 19729 десяткових цифр! Якби ви спробували роздрукувати його стандартним шрифтом, воно б зайняло кілька десятків сторінок формату А4, повністю списаних цифрами. Це значення обчислюється, коли вхідні параметри функції дорівнюють всього лише 4 і 2!

А що таке A(4, 3)?
A(4, 3) = A(3, A(4, 2)) = 2^(A(4, 2) + 3) - 3 = 2^(2^65536) - 3.

Це число настільки велике, що для нього немає жодного фізичного змісту. Кількість атомів у видимому Всесвіті оцінюється приблизно як 10^80. Це ніщо порівняно з A(4, 3). Якщо ви спробуєте записати це число у десятковій системі числення, вам не вистачить атомів у Всесвіті, навіть щоб просто записати всі його нулі. Математично, операція багаторазового піднесення до степеня називається "тетрацією". Рівень m = 4 відповідає тетрації числа 2.

## Чому це ламає примітивну рекурсію?

Тепер ми можемо відповісти на головне питання: чому функція Аккермана не є примітивно рекурсивною?

Примітивна рекурсія базується на циклах з фіксованою кількістю ітерацій. Будь-яка програма, написана виключно за допомогою таких циклів (без умов нескінченних переходів типу `while (true)`), може бути перетворена на математичний вираз. Математично доведено, що кожна примітивно рекурсивна функція має свою межу зростання. Якою б складною не була така програма, завжди можна знайти фіксований рівень m (додавання, множення, піднесення до степеня, тетрація тощо), такий, що для достатньо великих аргументів функція Аккермана A(m, n) зростатиме швидше.

Секрет функції Аккермана полягає в тому, що параметр m не є фіксованим; він є вхідним аргументом. Функція здатна "стрибати" по ієрархії арифметичних операцій. Якщо ви дасте їй примітивно рекурсивну функцію, яка використовує множення, функція Аккермана увімкне експоненту (m=3) і обжене її. Якщо ви дасте їй функцію з експонентою, Аккерман увімкне тетрацію (m=4) і обжене і її.

Функція Аккермана — це ніби універсальний генератор гіпероперацій. Вона розгортається у все нові і нові рівні обчислень під час виконання. Саме ця здатність динамічно змінювати "потужність" операції (через вкладену рекурсію у третьому правилі) робить її недосяжною для плоских, статичних циклів примітивної рекурсії.

## Практичні наслідки для програмування

Незважаючи на свій суто теоретичний генезис, функція Аккермана має реальні наслідки для інженерії програмного забезпечення.

По-перше, вона ідеально підходить для стрес-тестування компіляторів та середовищ виконання. Оскільки алгоритм генерує гігантське дерево викликів навіть для найменших вхідних даних (наприклад, для A(3, 4) глибина рекурсії та кількість викликів приголомшливі), спроба виконати цю функцію — це найкращий спосіб перевірити, як система управляє стеком викликів. Більшість мов програмування дуже швидко викинуть помилку `StackOverflowError` або `RecursionError`. Оптимізація компілятора, така як оптимізація хвостової рекурсії (tail call optimization), не може повністю врятувати ситуацію, оскільки вкладений виклик `A(m, n - 1)` не є хвостовим.

По-друге, функція Аккермана яскраво демонструє небезпеку прихованої складності у рекурсивному коді. Код з трьох рядків, який виглядає тривіально, може приховувати алгоритм, який буквально неможливо обчислити на жодному існуючому комп'ютері через брак пам'яті та часу. Це слугує застереженням для програмістів: аналізувати потрібно не лише розмір коду, але й графу його розгортання в часі.

Нарешті, обернена функція Аккермана — це функція, яка визначає, скільки разів потрібно застосувати функцію Аккермана до числа 1, щоб досягти або перевищити задане число N. Оскільки пряма функція зростає незбагненно швидко, обернена функція зростає неймовірно повільно. Для будь-якого числа, з яким може зіткнутися людство (навіть числа, більшого за кількість атомів у Всесвіті), обернена функція Аккермана не перевищуватиме значення 5. Ця обернена функція з'являється в оцінці складності деяких реальних алгоритмів, наприклад, алгоритму Крускала для пошуку мінімального кістякового дерева з використанням структури даних "система неперетинних множин" (Disjoint-Set). У цьому контексті повільне зростання оберненої функції Аккермана гарантує, що алгоритм працює практично з лінійним часом.

Отже, хоча ви навряд чи коли-небудь напишете функцію Аккермана у своєму робочому проєкті для бізнес-логіки, розуміння її природи розширює ваше бачення того, що взагалі можуть і чого не можуть робити комп'ютерні програми. Це міст між філософією математики та суворою реальністю комп'ютерної пам'яті.
