# C++17: Мемоїзація функції Аккермана

Функція Аккермана сумнозвісна не лише своїм швидким зростанням результатів, але й колосальною кількістю рекурсивних викликів, необхідних для обчислення навіть порівняно невеликих значень. Наприклад, щоб обчислити A(3, 4) (результат всього лише 125), алгоритм виконує десятки тисяч викликів самого себе. Якщо спробувати обчислити A(4, 1), стандартна рекурсія просто вичерпає стек викликів (stack overflow) або буде працювати довше, ніж існує Всесвіт.

Проте, багато з цих рекурсивних викликів є надлишковими. Алгоритм знову і знову обчислює A(m, n) для тих самих значень параметрів. Тут на допомогу приходить мемоїзація — техніка оптимізації, яка зберігає результати дорогих викликів функцій і повертає кешований результат, коли з'являються ті самі вхідні дані.

У цьому проєкті ми реалізуємо функцію Аккермана на мові C++17, використовуючи `std::map` або `std::unordered_map` для кешування проміжних результатів. Це дозволить нам обчислити значно більші значення за прийнятний час.

## Код реалізації

```cpp
#include <iostream>
#include <map>
#include <utility>

// Використовуємо 64-бітні беззнакові цілі числа для уникнення швидкого переповнення
using uint64 = unsigned long long;

// Тип для ключа кешу (пара m та n)
using CacheKey = std::pair<uint64, uint64>;

// Глобальний кеш для зберігання вже обчислених значень A(m, n)
std::map<CacheKey, uint64> memo_cache;

uint64 ackermann(uint64 m, uint64 n) {
    // Базовий випадок: m = 0
    if (m == 0) {
        return n + 1;
    }

    // Створюємо ключ для поточних аргументів
    CacheKey key = {m, n};

    // Перевіряємо, чи результат вже є в кеші
    if (memo_cache.find(key) != memo_cache.end()) {
        return memo_cache[key];
    }

    uint64 result;
    
    // Рекурсивні випадки
    if (n == 0) {
        result = ackermann(m - 1, 1);
    } else {
        result = ackermann(m - 1, ackermann(m, n - 1));
    }

    // Зберігаємо результат у кеші перед поверненням
    memo_cache[key] = result;
    
    return result;
}

int main() {
    std::cout << "Обчислення функції Аккермана з мемоїзацією\n";
    std::cout << "-------------------------------------------\n";

    // Обчислимо кілька значень
    for (uint64 m = 0; m <= 3; ++m) {
        for (uint64 n = 0; n <= 4; ++n) {
            std::cout << "A(" << m << ", " << n << ") = " << ackermann(m, n) << "\n";
        }
    }

    // Спробуємо обчислити більше значення (A(4, 0))
    // Увага: A(4, 1) = 65533 вже потребує глибокої рекурсії, 
    // але завдяки мемоїзації та збільшенню розміру стека ОС це можливо обчислити.
    // A(4, 2) має 19729 десяткових цифр і не поміститься у uint64.
    
    std::cout << "\nРозширене обчислення:\n";
    std::cout << "A(4, 0) = " << ackermann(4, 0) << "\n";
    
    // Статистика кешу
    std::cout << "\nКількість елементів у кеші: " << memo_cache.size() << "\n";

    return 0;
}
```

## Як це працює

1. **Типи даних**: Ми визначаємо `uint64` як `unsigned long long`, щоб мати змогу працювати з числами до 18 квінтильйонів. Втім, функція Аккермана перевершує цю межу настільки швидко, що навіть 64 біти рятують ненадовго.
2. **Ключ кешу**: Для ідентифікації унікального виклику ми використовуємо `std::pair<uint64, uint64>`, що містить аргументи `m` та `n`.
3. **Кеш**: Стандартний контейнер `std::map` зберігає результати. Кожного разу, коли викликається `ackermann(m, n)`, ми перевіряємо наявність ключа в `map`. Якщо значення вже обчислене, миттєво повертаємо його (O(log N) для `map`, де N — розмір кешу).
4. **Обчислення та збереження**: Якщо результату в кеші немає, ми виконуємо стандартну рекурсивну логіку, але перед `return` обов'язково записуємо знайдений `result` у `memo_cache[key]`.

Завдяки мемоїзації, кількість рекурсивних викликів для A(3, 4) скорочується з десятків тисяч до кількох сотень унікальних пар (m, n). Це драматично підвищує ефективність виконання, хоча й вимагає додаткової оперативної пам'яті для зберігання словника (кешу). Такий підхід є класичним прикладом просторово-часового компромісу (space-time tradeoff) в алгоритміці.
