# ⚙️ Мінімізація логіки методом Квайна–Мак-Класкі

Карта Карно — інструмент для **ока**: вона кладе сусідів за один біт поряд, і людина бачить групи. Та щойно змінних більше п'яти-шести, сітку оком уже не охопити. Тоді ту саму ідею «склеювати сусідів, що різняться одним бітом» виконують **машинно**. Поняття простого імпліканта ввів логік Віллард Квайн (англ. *Willard V. Quine*) 1952 року, а інженер Едвард Мак-Класкі (англ. *Edward J. McCluskey*) 1956-го перетворив його на покроковий табличний алгоритм (стаття «Minimization of Boolean Functions», Bell System Technical Journal — знов та сама лабораторія, що дала й карту, й код Грея). Метод Квайна–Мак-Класкі дає **той самий** мінімальний результат, що й карта, але систематично, для будь-якого числа входів і без зорового сприйняття — отже, його легко запрограмувати.

## Задача

На вході — список **мінтермів**: номери рядків таблиці істинності, де функція дорівнює 1 (плюс, за бажання, список «байдуже»-комбінацій). На виході — коротка сума добутків, що накриває всі одиниці й жодного нуля. Працюватимемо з тією самою функцією, яку мінімізує карта в основній статті:

```
F(A,B,C,D) = Σ m(0, 2, 6, 8, 10, 14)
очікуваний результат: F = C·D̄ + B̄·D̄   (дві групи по чотири)
```

## Ідея у два кроки

Алгоритм має дві чіткі фази, і їх корисно тримати окремо в голові.

**Крок 1 — знайти прості імпліканти (склеювання).** Кожен мінтерм запишемо як набір бітів. Два набори, що різняться **рівно одним** бітом, склеюються в один доданок, де цей біт замінено прочерком `-` (він означає «змінна випала»). Скажімо, `0010` і `0110` різняться другим бітом → склеюються в `0-10`. Далі склеюємо вже самі склейки за тим самим правилом (`0-10` з `1-10` → `--10`), доки є що склеювати. Усе, що **більше не склеюється**, — це **простий імплікант** (англ. *prime implicant*): максимально велика група, яку вже нікуди розширити. Це машинний відповідник «тягни групу якомога більшою» з карти.

**Крок 2 — вибрати мінімальне покриття.** Простих імплікантів зазвичай більше, ніж треба. Будуємо таблицю «імплікант × мінтерм» і шукаємо найменший набір імплікантів, що накриває всі мінтерми. Спершу беремо **істотні** імпліканти — ті, що єдині накривають якийсь мінтерм (їх не уникнути), а тоді добираємо решту жадібно — щоразу той, що накриває найбільше ще не покритих одиниць.

## Як склеюються набори бітів

Зручне подання кожного доданка — пара чисел: `bits` (значення сталих бітів) і `mask` (де стоять прочерки). Біт «байдуже» позначаємо одиницею в `mask`. Тоді два доданки склеюються, якщо їхні `mask` однакові, а `bits` різняться **рівно одним** бітом — і той біт переходить у нову маску:

```c
// різниця двох наборів — рівно один біт?
static int one_bit_apart(unsigned a, unsigned b) {
    unsigned diff = a ^ b;
    return diff && (diff & (diff - 1)) == 0;   // степінь двійки → один біт
}
```

Вираз `diff & (diff - 1)` обнуляє наймолодший установлений біт; якщо результат нуль, а сам `diff` ненульовий, то у `diff` був рівно один біт — класичний прийом для перевірки «лишилася одна одиниця».

## Робочий код

Повна реалізація для функцій до 16 змінних. Доданок — структура `Imp` з полями `bits`, `mask` і прапорцем «уже склеєний» (такий уже не є простим імплікантом). Код навмисно тримається простих масивів, без динамічної пам'яті, щоб його легко було покласти в офлайн-утиліту чи навіть прошивку.

```c
#include <stdio.h>
#include <string.h>

#define NVARS 4
#define MAXTERMS 256

typedef struct {
    unsigned bits;   // значення сталих бітів
    unsigned mask;   // 1 там, де прочерк «-» (змінна випала)
    int      used;   // 1, якщо доданок поглинувся в більшу склейку
} Imp;

static int one_bit_apart(unsigned a, unsigned b) {
    unsigned diff = a ^ b;
    return diff && (diff & (diff - 1)) == 0;
}

// чи накриває імплікант мінтерм m? (поза прочерками біти мають збігтися)
static int covers(Imp imp, unsigned m) {
    return ((m ^ imp.bits) & ~imp.mask) == 0;
}

// КРОК 1: усі прості імпліканти. Повертає їх кількість у prime[].
static int prime_implicants(const unsigned *minterms, int n, Imp *prime) {
    Imp cur[MAXTERMS], nxt[MAXTERMS];
    int ncur = 0, nprime = 0;

    for (int i = 0; i < n; i++) {        // початковий шар — самі мінтерми
        cur[ncur].bits = minterms[i];
        cur[ncur].mask = 0;
        cur[ncur].used = 0;
        ncur++;
    }

    while (ncur > 0) {
        int nnxt = 0;
        for (int i = 0; i < ncur; i++)
            for (int j = i + 1; j < ncur; j++)
                if (cur[i].mask == cur[j].mask &&
                    one_bit_apart(cur[i].bits, cur[j].bits)) {
                    unsigned d = cur[i].bits ^ cur[j].bits;
                    Imp merged = { cur[i].bits & ~d, cur[i].mask | d, 0 };
                    cur[i].used = cur[j].used = 1;     // обидва поглинулися
                    // не додавати дублікат у наступний шар
                    int dup = 0;
                    for (int k = 0; k < nnxt; k++)
                        if (nxt[k].bits == merged.bits && nxt[k].mask == merged.mask)
                            { dup = 1; break; }
                    if (!dup) nxt[nnxt++] = merged;
                }
        for (int i = 0; i < ncur; i++)               // що не склеїлося — простий імплікант
            if (!cur[i].used) prime[nprime++] = cur[i];
        memcpy(cur, nxt, nnxt * sizeof(Imp));
        ncur = nnxt;
    }
    return nprime;
}

// друк доданка як C·D̄ … (старший біт = A)
static void print_imp(Imp imp) {
    const char *names = "ABCD";
    int any = 0;
    for (int b = NVARS - 1; b >= 0; b--) {
        unsigned bit = 1u << b;
        if (imp.mask & bit) continue;                // прочерк — змінна випала
        printf("%c%s", names[NVARS - 1 - b], (imp.bits & bit) ? "" : "'");
        any = 1;
    }
    if (!any) printf("1");
}

int main(void) {
    unsigned minterms[] = { 0, 2, 6, 8, 10, 14 };
    int n = sizeof(minterms) / sizeof(minterms[0]);

    Imp prime[MAXTERMS];
    int np = prime_implicants(minterms, n, prime);

    // КРОК 2: жадібне покриття (для невеликих задач дає мінімум)
    int covered[MAXTERMS] = { 0 };
    int remaining = n;
    printf("F = ");
    int first = 1;
    while (remaining > 0) {
        int best = -1, best_cnt = 0;                 // імплікант, що накриває найбільше нового
        for (int p = 0; p < np; p++) {
            int cnt = 0;
            for (int i = 0; i < n; i++)
                if (!covered[i] && covers(prime[p], minterms[i])) cnt++;
            if (cnt > best_cnt) { best_cnt = cnt; best = p; }
        }
        if (best < 0) break;
        for (int i = 0; i < n; i++)
            if (!covered[i] && covers(prime[best], minterms[i]))
                { covered[i] = 1; remaining--; }
        if (!first) printf(" + ");
        print_imp(prime[best]);
        first = 0;
    }
    printf("\n");
    return 0;
}
```

Прогін друкує:

```
F = B'D' + CD'
```

— той самий результат, що дала карта Карно (штрих `'` тут заміняє риску над літерою). `B'D'` — це `B̄·D̄` (чотири кути карти), `CD'` — це `C·D̄` (стовпець). Порядок доданків залежить лише від того, у якому порядку алгоритм перебрав прості імпліканти; функція та сама, що `C·D̄ + B̄·D̄`.

## Пастки

- **Дублікати в наступному шарі.** Один і той самий більший доданок народжується з кількох різних пар (як `--10` з обох діагоналей). Без перевірки на дублікат масив шару роздувається експоненційно. У коді цю перевірку зроблено явно — не прибирайте її.
- **«Байдуже» включають у склейки, але не в покриття.** X-комбінації беруть участь у кроці 1 (хай збільшують групи), але на кроці 2 їх **не треба накривати** — інакше алгоритм даремно витратить імпліканти на рядки, до яких нікому немає діла. У наведеному коді списку «байдуже» немає; щоб додати — занесіть їх у `minterms` для кроку 1, але виключіть із циклу `remaining`.
- **Жадібний вибір — не завжди абсолютний мінімум.** Для малих задач (і всіх, що раніше робила карта) жадібне покриття дає оптимум. Для великих і «незручних» функцій буває потрібен точніший вибір (метод Петрика чи перебір) — але це вже інша, важча задача, і саме тому промислові синтезатори користуються складнішими евристиками, а не голим Квайном–Мак-Класкі.
- **Розрядність.** `unsigned` тут вистачає на 32 змінні з запасом, та `MAXTERMS` росте швидко — для багатьох входів масиви фіксованого розміру треба замінити на динамічні або зовсім інший алгоритм.

## Де це справді стоїть

Самостійно писати мінімізатор сьогодні майже не доводиться: цю роботу вже робить кожен синтезатор [ПЛІС](book:electronics/combinational-circuits) і будь-яка САПР цифрових схем — варто описати логіку рівнянням чи мовою опису апаратури, і вираз згорнеться сам. Та принцип лишається тим самим, що в карти Карно й у наведеному коді: знайти всі максимальні склейки, тоді накрити ними кожну одиницю якомога меншим числом груп. Знаючи це зсередини, ви читаєте звіт синтезатора (скільки комірок, який критичний шлях) не як магію, а як результат зрозумілого вам кроку — і розумієте, чому інколи варто переписати рівняння, щоб інструменту було що склеювати. Сам метод Квайна–Мак-Класкі при цьому показує і свою межу: число простих імплікантів у найгіршому разі росте експоненційно, тож промислові пакети давно перейшли на хитріші евристики (як-от ESPRESSO), але та сама дволанкова ідея — «імпліканти, потім покриття» — лишається в їхній основі.
