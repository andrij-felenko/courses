# 🧮 Математичні моделі та цільові функції адаптивного бітрейту

Мета алгоритму адаптивного бітрейту (ABR) на стороні клієнта полягає у виборі такої дискретної якості кожного наступного сегмента відео, яка максимізує сукупне задоволення глядача протягом усього сеансу перегляду. Для формалізації цієї інженерної задачі використовують поняття якості користувацького досвіду (англ. *Quality of Experience*, QoE), динамічні рівняння еволюції відеобуфера, фільтрацію випадкових процесів швидкості, оптимізацію за Ляпуновим, предиктивне керування (Model Predictive Control) та аналіз взаємодії кількох клієнтів у спільному вузькому каналі.

### 1. Формалізація задачі та цільова функція QoE

Відеопотік розбито на послідовність із `N` сегментів фіксованої тривалості `Δt` секунд (типово `Δt ∈ [2, 6]` с). На сервері доступний дискретний набір профілів кодування (бітрейт-драбина, Bitrate Ladder):

```
R = { R₁, R₂, ..., R_M },   де R₁ < R₂ < ... < R_M
```

Кожен профіль `R_m` задає номінальний бітрейт кодування в бітах за секунду. Обсяг `k`-го сегмента для обраного профілю `R[k]` визначається інтегралом потоку:

```
S(R[k]) = R[k] · Δt  [біт]
```

#### Складові користувацького сприйняття

Задоволення користувача формується трьома фізичними факторами, які перебувають у постійному антагонізмі:

1. **Корисність візуальної якості `q(R[k])`:** Чим вищий бітрейт, тим вища роздільна здатність і тим менше помітні артефакти квантування. За психофізичним законом Вебера–Фехнера суб'єктивне відчуття людини зростає пропорційно логарифму інтенсивності стимулу. Збільшення бітрейту від 500 кбіт/с до 1.5 Мбіт/с приносить різке покращення сприйняття (зникає сильне розмиття), тоді як підвищення від 15 Мбіт/с до 25 Мбіт/с у форматі 4K дає майже невідчутний приріст якості при колосальному навантаженні на канал. Цю спадну граничну корисність моделюють логарифмічною функцією відносно мінімального базового профілю:

```
q(R[k]) = ln(R[k] / R₁)   [безрозмірна корисність якості]
```

У комерційних системах замість логарифма часто застосовують об'єктивні метрики якості відео (наприклад, VMAF або SSIM), нормовані на інтервал `[0, 100]`.

2. **Штраф за зупинку відтворення (Rebuffering Stall):** Якщо час завантаження сегмента `t_dl[k]` перевищує наявний запас часу у відеобуфері `B[k]`, відтворення зупиняється на тривалість `T_stall[k]`. Пауза посеред перегляду викликає найвищий рівень роздратування глядача:

```
t_dl[k] = S(R[k]) / C[k]                 [час завантаження чанка, с]
T_stall[k] = max(0, t_dl[k] - B[k])      [тривалість паузи, с]
```

де `C[k]` — середня корисна пропускна здатність каналу зв'язку під час передачі `k`-го сегмента.

3. **Штраф за коливання якості (Quality Flapping):** Часті та різкі стрибки роздільної здатності між сусідніми сегментами викликають зоровий дискомфорт. Око фіксує перепад чіткості як дратівливе мерехтіння:

```
Δq[k] = |q(R[k]) - q(R[k-1])|            [величина перемикання якості]
```

#### Загальна цільова функція QoE

Сукупний користувацький досвід за сеанс із `N` сегментів формалізується як зважена функція корисностей і штрафних відрахувань:

```
QoE = ∑_{k=1}^{N} q(R[k])  −  λ · ∑_{k=1}^{N} T_stall[k]  −  μ · ∑_{k=1}^{N-1} |q(R[k+1]) - q(R[k])|
```

де:
- `λ` — ваговий коефіцієнт штрафу за паузу (емпірично встановлюється в діапазоні `λ ∈ [50, 100]`, що означає: одна секунда зависання повністю нівелює ефект від 50–100 секунд перегляду відео найвищої чіткості);
- `μ` — ваговий коефіцієнт штрафу за нестабільність якості (`μ ∈ [0.5, 2.0]`).

Завдання клієнтського рушія ABR — максимізувати `QoE` за умов, коли майбутня пропускна здатність каналу `C[k+1], C[k+2], ...` є непередбачуваним випадковим процесом із раптовими спадами та джитером.

### 2. Динаміка відеобуфера

Відеобуфер клієнта функціонує як резервуар накопичення часу відтворення. Позначимо рівень буфера на момент початку завантаження `k`-го сегмента через `B[k]` (у секундах). 

Під час завантаження чергового сегмента тривалістю `t_dl[k] = S(R[k]) / C[k]` апаратний декодер споживає дані з буфера зі швидкістю одна секунда відео за одну секунду фізичного часу. Після повного прийому чанка буфер миттєво поповнюється на його медійну тривалість `Δt`:

```
B[k+1] = max(0, B[k] - S(R[k]) / C[k]) + Δt
```

Якщо швидкість каналу вища за бітрейт сегмента (`C[k] > R[k]`), то `t_dl[k] < Δt`, і запас буфера зростає зі швидкістю `Δt - t_dl[k]`. Якщо ж мережа просідає нижче бітрейту (`C[k] < R[k]`), час завантаження перевищує тривалість сегмента, і буфер безперервно виснажується.

### 3. Оцінка швидкості каналу: гармонійне середнє проти арифметичного

Алгоритми ABR на базі оцінки пропускної здатності вимірюють час завантаження попередніх `W` сегментів. Проте пряме арифметичне усереднення спостережуваних швидкостей `T_i = S_i / t_dl[i]` є некоректним і призводить до систематичного завищення оцінки.

Нехай завантажено `W` сегментів однакового розміру `S`. Їхні часи завантаження склали `t_1, t_2, ..., t_W`. Загальний переданий обсяг дорівнює `W · S`, а сукупний витрачений час — `∑ t_i`. Реальна середня швидкість каналу на цьому інтервалі дорівнює:

```
C_real = (W · S) / (∑_{i=1}^{W} t_i)
```

Підставимо зв'язок часу зі швидкістю `t_i = S / T_i`:

```
C_real = (W · S) / (∑_{i=1}^{W} (S / T_i)) = W / (∑_{i=1}^{W} (1 / T_i))
```

Це вираз **гармонійного середнього** (англ. *Harmonic Mean*). За класичною нерівністю Коші між середніми для будь-яких додатних нерівних значень:

```
T_harmonic ≤ T_geometric ≤ T_arithmetic
```

#### Чому арифметичне середнє ламає відеопотік

Якщо один сегмент завантажився через раптовий сплеск мережі надзвичайно швидко (наприклад, 20 Мбіт/с через короткочасний кеш CDN), а три наступні повзли по 2 Мбіт/с, арифметичне середнє дасть:

```
T_arithmetic = (20 + 2 + 2 + 2) / 4 = 6.5 Мбіт/с
```

Якщо плеєр повірить цій цифрі й замовить профіль 6 Мбіт/с, буфер миттєво спорожніє, оскільки реальна стабільна швидкість каналу становить лише 2 Мбіт/с. Натомість гармонійне середнє строго вираховує фізичну швидкість передачі байтів:

```
T_harmonic = 4 / (1/20 + 1/2 + 1/2 + 1/2) = 4 / (0.05 + 1.5) = 4 / 1.55 ≈ 2.58 Мбіт/с
```

Гармонійне середнє природним чином стійке до викидів у бік завищення і дає адекватну оцінку стійкої смуги пропускання. Для згладжування залишків джитера застосовують експоненційне вирівнювання (EWMA):

```
Ĉ[k] = α · T_harmonic[k] + (1 - α) · Ĉ[k-1],   де α ∈ [0.8, 0.9]
```

### 4. Фаза запуску (Startup / Ramp-Up Phase)

На початку перегляду буфер порожній (`B[0] = 0`). Плеєр стоїть перед дилемою: якнайшвидше розпочати відтворення першого кадру (мінімізувати Time-to-First-Frame) і водночас швидко наростити якість до максимальної смуги каналу без виклику паузи.

Стандартна стаціонарна логіка BBA не працює на старті, оскільки при `B = 0` вона застрягла б на мінімальному профілі `R₁` на довгий час. Тому фаза запуску виділяється в окремий кінцевий автомат:

1. **Перший сегмент (Probe Chunk):** Завжди замовляється з мінімальним бітрейтом `R₁`. Це мінімізує час відгуку, дозволяючи декодеру показати початкову заставку за 100–300 мс.
2. **Експоненційне подвоєння (Exponential Ramp-Up):** На кожному кроці запуску плеєр вимірює реальну швидкість завантаження `T[k]`. Якщо `T[k] ≥ 2 · R[k]` і буфер зростає (`B[k+1] > B[k]`), бітрейт наступного чанка підвищується одразу на кілька щаблів угору до найвищого профілю, що задовольняє умову:

```
R[k+1] = max { R_m ∈ R | R_m ≤ γ_startup · T[k] }
```

де `γ_startup ≈ 0.75` — консервативний запас смуги на старті.

3. **Критерій переходу в стаціонарний режим:** Фаза запуску припиняється, і керування передається основному алгоритму (BBA або BOLA), щойно виконується одна з двох умов:
   - Буфер накопичив безпечний рівень: `B[k] ≥ r + c / 2`.
   - Швидкість зростання буфера припинилася або виникло перше зниження якості (`R[k+1] < R[k]`).

### 5. Математична модель алгоритму BBA (Buffer-Based Adaptation)

Алгоритм BBA (Huang et al., ACM SIGCOMM 2014) базується на висновку, що в умовах пульсуючого трафіку TCP спроби вгадати швидкість каналу створюють паразитні коливання. BBA переносить керування в простір заповненості буфера `B`.

#### Геометрія буферного простору

Буферний діапазон `[0, B_max]` розбивається на три зони:

1. **Резервуар `[0, r]` (Reservoir):** Зона критично низького запасу часу. За будь-яких умов обирається мінімальний профіль `R₁` для запобігання паузі.
2. **Подушка `[r, r + c]` (Cushion):** Робоча зона динамічної адаптації. Бітрейт зростає зі збільшенням буфера.
3. **Зона насичення `[r + c, B_max]` (Upper Reservoir):** Зона максимального запасу часу. Завжди обирається максимальний доступний профіль `R_M`.

#### Неперервна функція відображення `f(B)`

Функція `f(B)` відображає поточний запас часу `B` у неперервний цільовий бітрейт. У межах подушки залежність є лінійною:

```
        ⎧ R₁,                                         якщо B ≤ r
f(B) =  ⎨ R₁ + (B - r) / c · (R_M - R₁),              якщо r < B < r + c
        ⎩ R_M,                                        якщо B ≥ r + c
```

#### Вибір дискретного профілю та гістерезис

Оскільки кодек надає лише дискретний набір `R = {R₁, ..., R_M}`, правило вибору шукає найбільший бітрейт, що лежить під кривою `f(B)`:

```
R_selected = max { R_m ∈ R | R_m ≤ f(B) }
```

Щоб виключити постійне перемикання між сусідніми профілями `R_m` та `R_{m+1}` при незначних коливаннях буфера, вводиться смуга гістерезису шириною `δ`:
- Підвищення якості `R_m → R_{m+1}` дозволяється лише за умови: `f(B) ≥ R_{m+1} + δ`.
- Зниження якості `R_{m+1} → R_m` активується, коли: `f(B) < R_{m+1} - δ`.

### 6. Оптимізація за Ляпуновим: алгоритм BOLA

Алгоритм **BOLA** (Spiteri et al., IEEE/ACM Trans. Netw. 2020) формулює керування бітрейтом як строгу задачу максимізації корисності при обмеженні черги за теорією стохастичної оптимізації Ляпунова.

#### Функція дрейфу Ляпунова

Для черги відеобуфера `B[k]` із цільовим рівнем `B_target` вводиться квадратична функція Ляпунова:

```
L(B[k]) = ½ · (B[k] - B_target)²
```

Дрейф функції Ляпунова за один крок завантаження визначається як:

```
ΔL[k] = E[ L(B[k+1]) - L(B[k]) | B[k] ]
```

#### Мінімізація суми «дрейф плюс штраф» (Drift-plus-Penalty)

Згідно з методом Ляпунова, для одночасної стабілізації буфера та максимізації якості відео мінімізують функціонал:

```
Мінімізувати:   ΔL[k] − V · E[ q(R[k]) | B[k] ]
```

де `V > 0` — параметр ваги керування, що задає баланс між максимізацією роздільної здатності та надійністю утримання буфера.

Розгорнувши різницю `L(B[k+1]) - L(B[k])` через наближення `B[k+1] - B[k] ≈ Δt - S(R[k]) / C[k]`, автори BOLA довели, що розв'язок задачі оптимізації для кожного сегмента `k` зводиться до пошуку профілю `R_m`, який максимізує вираз:

```
R[k] = argmax_{R_m ∈ R}  ( V · q(R_m) + B[k] ) / S(R_m)
```

де `S(R_m) = R_m · Δt` — розмір сегмента в бітах.

#### Фізичний зміст критерію BOLA

Критерій ділить зважену суму візуальної корисності `V · q(R_m)` та наявного буфера `B[k]` на «ціну» у байтах `S(R_m)`:
- При малому буфері `B[k] ≈ 0` дріб визначається величиною `V · q(R_m) / S(R_m)`. Оскільки `q(R)` зростає логарифмічно, а `S(R)` — лінійно, вигіднішими стають малі профілі (низький бітрейт `R₁`).
- Коли буфер `B[k]` стає великим, доданок `B[k]` починає домінувати над чисельником. Вираз наближається до `B[k] / S(R_m)`, що стимулює вибір високих профілів для стабілізації черги від переповнення.
- Головна перевага BOLA: алгоритм є асимптотично оптимальним і взагалі не вимагає вимірювання швидкості каналу `C[k]`.

### 7. Предиктивне керування: RobustMPC

Алгоритм **MPC** (Model Predictive Control, Yin et al., ACM SIGCOMM 2015) оптимізує траєкторію вибору бітрейтів на ковзному горизонті глибиною `K` сегментів (типово `K = 5`).

На кроці `k` за поточного буфера `B[k]` алгоритм розв'язує задачу оптимізації над усіма комбінаціями `{R[k], ..., R[k+K-1]} ∈ R^K`:

```
max_{R[k]...R[k+K-1]}  ∑_{j=k}^{k+K-1} q(R[j])  −  λ · ∑_{j=k}^{k+K-1} T_stall[j]  −  μ · ∑_{j=k}^{k+K-1} |q(R[j]) - q(R[j-1])|
```

за динамічних обмежень переходу:
```
t_dl[j] = (R[j] · Δt) / Ĉ_worst[j]
B[j+1] = max(0, B[j] - t_dl[j]) + Δt
T_stall[j] = max(0, t_dl[j] - B[j])
```

Для захисту від похибок прогнозу швидкості `Ĉ[j]` у RobustMPC використовують нижню межу довірчого інтервалу:

```
Ĉ_worst[j] = Ĉ[j] / (1 + 2 · σ_rel)
```

де `σ_rel` — відносне стандартне відхилення похибки екстраполяції за останніми завантаженими чанками. Отримавши оптимальний вектор із `K` кроків, плеєр застосовує лише перший елемент `R[k]`, після чого на наступному сегменті зміщує вікно на один крок уперед.

### 8. Навчання з підкріпленням: модель MDP в алгоритмі Pensieve

Сучасний напрям розвитку ABR-алгоритмів базується на глибокому навчанні з підкріпленням (англ. *Deep Reinforcement Learning*, DRL), яскравим представником якого є система **Pensieve** (Mao et al., ACM SIGCOMM 2017). Замість жорстких евристичних правил нейромережа навчається керувати бітрейтом через пряму оптимізацію марковського процесу вирішування (англ. *Markov Decision Process*, MDP).

#### Простір станів системи (State Space)

На момент завершення завантаження сегмента `k` агент спостерігає вектор стану `s[k]`, який містить повну передісторію останніх спостережень:

```
s[k] = ( s_bitrate[k], s_throughput[k], s_download_time[k], s_next_sizes[k], B[k], rem_chunks )
```

де:
- `s_bitrate[k] = (R[k-w+1], ..., R[k])` — вектор останніх `w` обраних бітрейтів;
- `s_throughput[k] = (T[k-w+1], ..., T[k])` — спостережувані швидкості за останні `w` сегментів;
- `s_download_time[k] = (t_dl[k-w+1], ..., t_dl[k])` — тривалості завантаження останніх `w` чанків;
- `s_next_sizes[k] = (S₁(R₁), S₁(R₂), ..., S₁(R_M))` — точні розміри наступного сегмента для кожного з `M` профілів (відомі з маніфесту або індексу);
- `B[k]` — поточний запас часу у відеобуфері;
- `rem_chunks` — залишок сегментів до завершення відео.

#### Простір дій та функція винагороди (Reward Function)

Простір дій `a[k] ∈ {1, 2, ..., M}` відповідає вибору одного з `M` профілів бітрейту `R_{a[k]}` для наступного сегмента.

Функція винагороди `r[k]` за один крок безпосередньо збігається з миттєвим приростом метрики QoE:

```
r[k] = q(R[k]) − λ · T_stall[k] − μ · |q(R[k]) − q(R[k-1])|
```

Мета навчання полягає в знаходженні параметрів нейромережі `θ` (політики `π_θ(a | s)`), яка максимізує очікувану дисконтовану винагороду за всю сесію перегляду:

```
J(θ) = E_{π_θ} [ ∑_{k=1}^{N} γ^k · r[k] ]
```

де `γ ∈ (0, 1]` — фактор дисконтування майбутніх подій. 

Навчання проводиться за допомогою алгоритму Actor-Critic (A3C): критична мережа оцінює функцію цінності стану `V(s)`, а акторна мережа оновлює ваги політики за градієнтом:

```
∇_θ J(θ) = E [ ∇_θ ln π_θ(a[k] | s[k]) · ( r[k] + γ · V(s[k+1]) − V(s[k]) ) ]
```

Перевага підходу на базі DRL полягає в тому, що нейромережа здатна виявляти тонкі кореляції між VBR-коливаннями розмірів сегментів, історією джитера та динамікою буфера, досягаючи вищої середньої якості без ручного підбору ваг `r` та `c`.

### 9. Взаємодія кількох клієнтів у вузькому каналі (Fairness and Instability)

Коли кілька ABR-плеєрів ділять спільне пляшкове горло маршрутизатора (Bottleneck Buffer), виникає феномен **ON-OFF конкуренції**:

1. Плеєр із повним буфером припиняє запити (фаза OFF). 
2. Звільнену смугу захоплює другий плеєр, чий буфер ще не заповнений. Його TCP-з'єднання розганяє вікно перевантаження (cwnd), оцінюючи всю смугу каналу як власну.
3. Другий плеєр хибно підвищує бітрейт до максимуму.
4. Коли перший плеєр повертається у фазу ON, сумарний потік перевищує ємність маршрутизатора: виникає скидання пакетів, TCP в обох потоках різко скидає швидкість, і обидва плеєри одночасно падають на мінімальний бітрейт.

Для оцінки справедливості розподілу ресурсів між `P` клієнтами застосовують **індекс справедливості Джейна** (Jain's Fairness Index):

```
J(R₁, R₂, ..., R_P) = ( ∑_{i=1}^{P} R_i )²  /  ( P · ∑_{i=1}^{P} R_i² )
```

Значення `J = 1.0` відповідає абсолютно рівному розподілу смуги між користувачами, тоді як `J → 1/P` вказує на монополізацію каналу одним потоком. Алгоритми BBA та BOLA значно пом'якшують цей ефект, оскільки не намагаються агресивно наповнювати канал у періоди короткочасних пауз сусідніх клієнтів.

### 9. Покроковий розрахунок: числовий приклад поведінки ABR

Розглянемо практичний числовий приклад реакції систем на раптовий спад пропускної здатності.

**Вхідні параметри системи:**
- Тривалість сегмента: `Δt = 4.0` с.
- Бітрейт-драбина: `R = { 0.8, 1.6, 3.2, 6.0 }` Мбіт/с.
- Розміри сегментів:
  `S(0.8) = 3.2` Мбіт, `S(1.6) = 6.4` Мбіт, `S(3.2) = 12.8` Мбіт, `S(6.0) = 24.0` Мбіт.
- Параметри BBA: `r = 8.0` с, `c = 16.0` с (`r + c = 24.0` с).
- Початковий стан: буфер `B = 18.0` с, завантажується сегмент `R = 6.0` Мбіт/с.
- **Мережева подія:** Пропускна здатність каналу раптово падає з 10.0 Мбіт/с до **1.2 Мбіт/с**.

```
═══════════════════════════════════════════════════════════════════════════════
КРОК 1: Завантаження поточного сегмента R = 6.0 Мбіт/с на швидкості C = 1.2 Мбіт/с
═══════════════════════════════════════════════════════════════════════════════
Час завантаження:
t_dl = S(6.0) / C = 24.0 Мбіт / 1.2 Мбіт/с = 20.0 с

Зміна буфера:
B_new = max(0, B_old - t_dl) + Δt
      = max(0, 18.0 - 20.0) + 4.0
      = 0 + 4.0 = 4.0 с  (буфер вичерпався, виникла пауза T_stall = 20.0 - 18.0 = 2.0 с)

═══════════════════════════════════════════════════════════════════════════════
КРОК 2: Вибір наступного сегмента при залишку буфера B = 4.0 с
═══════════════════════════════════════════════════════════════════════════════

1. Алгоритм на базі швидкості (Throughput-based):
   Виміряна швидкість за попередній чанк: T = 24.0 / 20.0 = 1.2 Мбіт/с.
   Коефіцієнт безпеки: γ = 0.85 → C_safe = 1.2 · 0.85 = 1.02 Мбіт/с.
   Вибір: максимальний профіль під C_safe → R = 0.8 Мбіт/с.
   Час завантаження: t_dl = 3.2 / 1.2 = 2.67 с.
   Буфер після завантаження: B = 4.0 - 2.67 + 4.0 = 5.33 с (без пауз).

2. Алгоритм BBA:
   Поточний буфер: B = 4.0 с.
   Перевірка зони: B = 4.0 с < r = 8.0 с (стан Резервуара).
   f(B) = R_min = 0.8 Мбіт/с.
   Вибір: R = 0.8 Мбіт/с.
   Буфер відновлюється до 5.33 с.

3. Алгоритм BOLA (при V = 10, q(R) = ln(R/0.8) + 1):
   q(0.8) = 1.0, q(1.6) = 1.693, q(3.2) = 2.386, q(6.0) = 3.015.
   Обчислення оцінки для кожного профілю при B = 4.0:
   - R = 0.8: Score = (10 · 1.0 + 4.0) / 3.2 = 14.0 / 3.2 = 4.375
   - R = 1.6: Score = (10 · 1.693 + 4.0) / 6.4 = 20.93 / 6.4 = 3.270
   - R = 3.2: Score = (10 · 2.386 + 4.0) / 12.8 = 27.86 / 12.8 = 2.176
   - R = 6.0: Score = (10 · 3.015 + 4.0) / 24.0 = 34.15 / 24.0 = 1.423
   Максимум досягається при R = 0.8 Мбіт/с (Score = 4.375).
   Вибір: R = 0.8 Мбіт/с.
```

Усі три математичні моделі за критичного рівня буфера своєчасно скидають бітрейт на мінімальний щабель `R = 0.8` Мбіт/с, що дозволяє поповнювати буфер швидше за швидкість його вичерпання і виводить відеоплеєр із зони ризику зависань.
