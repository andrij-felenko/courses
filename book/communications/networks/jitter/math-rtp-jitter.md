# 🧮 Математика оцінювання джитеру: від різниці інтервалів до фільтра RFC 3550

Оцінювання варіації мережевої затримки спирається на дискретну статистичну фільтрацію, яка дозволяє обчислити стан каналу в умовах нестабільності без використання дорогих протоколів абсолютної синхронізації часу. Математичний апарат джитеру розв'язує задачу виокремлення стохастичного шуму черг із детермінованого потоку передавання пакетів.

---

### 1. Формальне означення затримки одностороннього передавання (OWD)

Нехай передавач надсилає послідовність пакетів у дискретні моменти часу `S_k` (Sender Timestamp), а приймач фіксує їхнє надходження у моменти `R_k` (Receiver Timestamp) за власним локальним таймером.

Одностороння затримка передавання `k`-го пакета через мережу дорівнює різниці:

```
T_transit_k = R_k - S_k
```

Якщо годинники передавача та приймача не синхронізовані через PTP (IEEE 1588) чи GPS, між ними існує невідомий часовий зсув `Δ_clock` та дрейф частоти `δ_drift`:

```
R_k = S_k + T_transit_k + Δ_clock + δ_drift · S_k
```

На коротких проміжках часу (секунди чи хвилини) дрейфом кварцового резонатора `δ_drift ≈ 10⁻⁵` (близько 1 секунди за добу) можна знехтувати. Тоді виміряний локальний час прибуття описується спрощеною моделлю:

```
R_k = S_k + T_transit_k + Δ_clock
```

### 2. Відносний інтервальний джитер (RFC 3393 та RFC 3550)

Для двох сусідніх пакетів `i` та `j` (де `j = i + 1`) різниця часу між прибуттям та надсиланням визначає зміну часу перебування в мережі (Inter-arrival Jitter):

```
D(i, j) = (R_j - R_i) - (S_j - S_i)
```

Розкриємо цей вираз через фізичні компоненти затримки:

```
D(i, j)
= (R_j - R_i) - (S_j - S_i)
= (R_j - S_j) - (R_i - S_i)                                [перегрупування доданків]
= (S_j + T_transit_j + Δ_clock - S_j) - (S_i + T_transit_i + Δ_clock - S_i)
= (T_transit_j + Δ_clock) - (T_transit_i + Δ_clock)        [взаємне скорочення S_j та S_i]
= T_transit_j - T_transit_i                                [взаємне скорочення Δ_clock]
```

Головна математична властивість відносного джитеру: **абсолютний часовий зсув годинників `Δ_clock` повністю скорочується**. Приймач отримує точну різницю часу польоту двох пакетів, використовуючи лише власні монотонні годинники та мітки часу в заголовках пакетів.

Значення `D(i, j)` може бути як додатним, так і від'ємним:
- `D(i, j) > 0` — затримка збільшилася (пакет `j` зустрів чергу або обхідний маршрут);
- `D(i, j) < 0` — затримка зменшилася (пакет `j` наздогнав пакет `i`, компресія пакетів);
- `D(i, j) = 0` — затримка абсолютно незмінна (ідеальний ізохронний канал).

### 3. Рекурсивний згладжувальний фільтр RFC 3550

Миттєве абсолютне значення `|D(i-1, i)|` містить значний високочастотний стохастичний шум через поодинокі сплески черг у комутаторах. Стандарт RTP (RFC 3550) застосовує рекурсивний експоненційний фільтр (Exponential Weighted Moving Average — EWMA) першого порядку:

```
J_i = J_{i-1} + (|D(i-1, i)| - J_{i-1}) / 16
```

Перепишемо це рівняння в класичному вигляді дискретного авторегресійного фільтра з ваговим коефіцієнтом `α = 1/16`:

```
J_i
= J_{i-1} + α · (|D(i-1, i)| - J_{i-1})      [підстановка коефіцієнта α = 1/16]
= (1 - α) · J_{i-1} + α · |D(i-1, i)|        [групування доданків при J_{i-1}]
= (15/16) · J_{i-1} + (1/16) · |D(i-1, i)|  [підстановка дробового значення α = 1/16]
```

#### Математичні властивості фільтра:
1. **Цілочисельна оптимізація:** Ділення на `16` еквівалентне арифметичному правому зсуву на 4 біти (`>> 4`), що дозволяє обчислювати джитер на мікроконтролерах і сигнальних процесорах (DSP) без блоку апаратної плаваючої коми.
2. **Ефективна постійна часу (Time Constant):** Кількість вибірок `N_eff`, за яку попередня оцінка згасає в `e ≈ 2.718` разів:
   ```
   (1 - α)^{N_eff} ≈ e⁻¹
   N_eff ≈ 1 / α = 16 пакетів
   ```
3. **Фізичний час реакції:** Для типового голосового потоку VoIP з інтервалом кадрів `T_packet = 20` мс ефективне вікно згладжування становить:
   ```
   τ = N_eff · T_packet = 16 · 20 мс = 320 мс
   ```
   Фільтр фільтрує дрібні коливання на рівні кількох пакетів, але встигає зреагувати на зміну режиму мережі за третину секунди.

### 4. Дискретний частотний аналіз фільтра в Z-просторі

Для дослідження частотної вибірковості фільтра RFC 3550 застосуємо Z-перетворення до різницевого рівняння.

Нехай вхідним сигналом є послідовність миттєвих абсолютних різниць `x[n] = |D(n-1, n)|`, а вихідним — згладжена оцінка джитеру `y[n] = J_n`. Тоді:

```
y[n] = (1 - α) · y[n-1] + α · x[n]
```

Застосувавши властивість запізнення Z-перетворення `Z{y[n-1]} = z⁻¹ · Y(z)`:

```
Y(z) = (1 - α) · z⁻¹ · Y(z) + α · X(z)
Y(z) · (1 - (1 - α) · z⁻¹) = α · X(z)
```

Звідси передавальна функція дискретної системи `H(z)` дорівнює:

```
H(z) = Y(z) / X(z) = α / (1 - (1 - α) · z⁻¹)
```

Полюс системи знаходиться в точці `z_p = 1 - α = 15/16 = 0.9375`. Оскільки `|z_p| < 1`, фільтр є строго стійким (Bounded-Input Bounded-Output Stable).

#### Амплітудно-частотна характеристика (АЧХ)
Підставимо `z = e^{j ω T_p}`, де `ω` — кругова частота, а `T_p` — інтервал між пакетами:

```
|H(e^{j ω T_p})|² = α² / ((1 - (1 - α) cos(ω T_p))² + ((1 - α) sin(ω T_p))²)
```

Частота зрізу за рівнем `-3 дБ` (де потужність сигналу падає вдвічі, `|H|² = 0.5`) визначається формулою:

```
ω_c · T_p = arccos(1 - α² / (2 · (1 - α)))
```

Для `α = 1/16 = 0.0625`:

```
1 - α² / (2 · (1 - α)) = 1 - 0.00390625 / 1.875 = 0.997917
ω_c · T_p = arccos(0.997917) ≈ 0.06456 рад/семпл
```

При частоті генерації пакетів `f_packet = 1 / T_p = 50` Гц (один пакет кожні 20 мс) частота зрізу фільтра становить:

```
f_c = (ω_c · T_p · f_packet) / (2 · π) = (0.06456 · 50) / 6.28318 ≈ 0.514 Гц
```

Це означає, що фільтр RFC 3550 пропускає лише повільні зміни мережевих черг із періодом понад `1 / 0.514 ≈ 1.95` секунди, повністю пригнічуючи високочастотні пульсації від поодиноких перешкод.

### 5. Покроковий числовий приклад розрахунку

Розглянемо голосовий потік G.711 із частотою дискретизації `f_s = 8000` Гц (8 кГц). Кожен пакет містить `20` мс аудіо, що відповідає `160` відлікам часової мітки:

```
ΔS = 8000 Гц · 0.020 с = 160 квантів
```

Початковий стан фільтра: `J_0 = 0`.

| Пакет `k` | Час відправлення `S_k` (кванти) | Локальний час `R_k` (кванти) | Затримка `R_k - S_k` | Різниця `D(k-1, k)` | `|D|` | Оцінка джитеру `J_k` (кванти) | `J_k` у мілісекундах (`/ 8`) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | 0 | 800 | 800 | — | — | 0.00 | 0.000 мс |
| **2** | 160 | 976 | 816 | (816 - 800) = +16 | 16 | 0 + (16 - 0)/16 = **1.00** | 0.125 мс |
| **3** | 320 | 1296 | 976 | (976 - 816) = +160 | 160 | 1.00 + (160 - 1)/16 = **10.94** | 1.367 мс |
| **4** | 480 | 1440 | 960 | (960 - 976) = -16 | 16 | 10.94 + (16 - 10.94)/16 = **11.25** | 1.406 мс |
| **5** | 640 | 1600 | 960 | (960 - 960) = 0 | 0 | 11.25 + (0 - 11.25)/16 = **10.55** | 1.319 мс |

#### Пояснення перетворень:
- На пакеті 3 сталася затримка в буфері комутатора на `160` квантів (`20` мс).
- Миттєвий джитер підскочив до `|D| = 160`.
- Оцінка фільтра `J_3` плавно піднялася з `1.00` до `10.94` квантів (`1.367` мс), запобігаючи хибним панічним розширенням буфера.
- На пакеті 5 затримка стабілізувалася (`D = 0`), і фільтр почав експоненційне спадання: `11.25 → 10.55`.

### 6. Стохастичний розподіл затримок та важкі хвости (Heavy Tails)

У класичній теорії телекомунікацій затримка черги часто моделюється пуассонівським процесом (модель M/M/1), де час перебування в системі має експоненційний розподіл:

```
P(T_queue > t) = e^{-(μ - λ) t}
```

Проте реальний Інтернет-трафік має самоподібну пачкову природу (Self-similar traffic), породжену агрегацією TCP-потоків із розподілом розмірів файлів за законом Парето. Хвіст функції розподілу затримки є важким (Heavy-tailed):

```
P(T_queue > t) ~ t^{-γ},  де 1 < γ < 2
```

Це означає, що припущення про нормальний (гауссівський) розподіл затримок катастрофічно занижує ймовірність великих сплесків джитеру.

```
Ймовірність сплеску           Гауссівська модель           Реальна мережа (Парето)
─────────────────────────────────────────────────────────────────────────────────
Відхилення > 3σ               0.27 %                       ~ 2.5–5.0 %
Відхилення > 6σ               10⁻⁹ % (неможливо)           ~ 0.1–0.5 % (щохвилини!)
─────────────────────────────────────────────────────────────────────────────────
```

Якщо розмір буфера відтворення розраховувати за спрощеною формулою `E[D] + 3σ`, розрахованою на гауссівський розподіл, користувач отримає від 2% до 5% втрачених через запізнення пакетів замість очікуваних 0.27%.

### 7. Непараметрична оцінка квантилів: алгоритм P-Square

Щоб адаптивний буфер гарантував роботу без втрат (наприклад, доставка 99.9% пакетів до дедлайну), необхідно відстежувати 99.9-й процентиль `p = 0.999` розподілу затримки в реальному часі.

Зберігання історії з 10 000 останніх пакетів та їхнє постійне сортування вимагає забагато оперативної пам'яті та процесорного часу. Алгоритм Jain-Chlamtac (алгоритм P-Square) вирішує цю задачу за допомогою 5 маркерів без збереження самого масиву даних:

1. Маркери `q_1, q_2, q_3, q_4, q_5` відстежують мінімум, `p/2`-квантиль, `p`-квантиль, `(1+p)/2`-квантиль та максимум.
2. Для кожного нового виміряного значення затримки `T_k` позиції маркерів зміщуються за кусочно-параболічною інтерполяцією:
   ```
   q_i' = q_i + d_i / (n_{i+1} - n_{i-1}) · ((n_i - n_{i-1} + d_i) · (q_{i+1} - q_i) / (n_{i+1} - n_i) + (n_{i+1} - n_i - d_i) · (q_i - q_{i-1}) / (n_i - n_{i-1}))
   ```
3. Значення центрального маркера `q_3` служить точною асимптотичною оцінкою шуканого квантиля, дозволяючи виставляти глибину буфера відтворення `D_target = q_3` з мінімальними накладними витратами.

### 8. Компенсація дрейфу годинників (Clock Skew) через лінійну регресію

Якщо кварцовий резонатор передавача поспішає відносно приймача на відносну величину `δ_drift`, затримка `T_transit_k` містить монотонний лінійний тренд:

```
R_k - S_k = T_base + δ_drift · k · T_p + T_queue_k
```

При позитивному дрейфі `δ_drift > 0` розрахована затримка штучно росте щосекунди. Адаптивний буфер сприймає це як зростання джитеру і починає безпідставно роздувати чергу пам'яті.

Щоб відокремити апаратний дрейф від мережевого джитеру, застосовують алгоритм Паксона (Paxson's Convex Hull Algorithm):
1. Будується нижня опукла оболонка графіка `(S_k, R_k)`.
2. Точки мінімумів відповідають пакетам, що пройшли мережу за абсолютно порожніх черг (`T_queue ≈ 0`).
3. Нахил прямої, що з'єднує ці мінімуми, точно дорівнює коефіцієнту дрейфу:
   ```
   δ_drift = (R_{min2} - R_{min1}) / (S_{min2} - S_{min1}) - 1
   ```
4. Локальний час приймача програмно коригується: `R_corrected_k = R_k - δ_drift · S_k`, повністю усуваючи накопичення похибки джитеру.

### 9. Метрики RFC 5481: PPDV проти MAPDV

RFC 5481 визначає два класи метрик варіації затримки залежно від інженерної мети аналізу:

```
                                  Метрики PDV (RFC 5481)
                                            │
                    ┌───────────────────────┴───────────────────────┐
                    ▼                                               ▼
         PPDV (Packet-to-Packet)                          MAPDV / 1-Point PDV
      Різниця сусідніх пакетів:                        Відхилення від мінімуму:
      |T_transit_i - T_transit_{i-1}|                  T_transit_i - T_min
                    │                                               │
                    ▼                                               ▼
      Оцінка короткочасного шуму                   Розрахунок необхідної глибини
      для фільтра RTP (RFC 3550)                   буфера відтворення (Jitter Buffer)
```

1. **Packet-to-Packet Delay Variation (PPDV):**
   ```
   PPDV_i = |T_transit_i - T_transit_{i-1}|
   ```
   Показує динаміку міжсусідніх коливань. Не залежить від мінімальної базової затримки мережі.

2. **Mean Absolute Packet Delay Variation (MAPDV) та абсолютна PDV:**
   ```
   PDV_abs_i = T_transit_i - min_{k}(T_transit_k)
   ```
   Вимірює накопичене відхилення пакета від найкращого можливого часу проходження лінії (`T_min`). Саме ця метрика є фундаментальною для розрахунку глибини буфера відтворення: розмір буфера `B` має покривати 99.9-й процентиль величини `PDV_abs`, щоб мінімізувати ймовірність буферного виснаження.
