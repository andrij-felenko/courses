# ⚙️ Алгоритм та калькулятор VLSM-планування адресного простору

При проєктуванні мережевої інфраструктури сучасного підприємства інженери щодня розв'язують складну комбінаторну оптимізаційну задачу. Організація отримує у своє розпорядження певний агрегований діапазон адрес — наприклад, корпоративний префікс `10.100.0.0/18`, що містить рівно `2¹⁴ = 16 384` IP-адреси. Всередині цієї інфраструктури необхідно розмістити десятки різнорідних підсистем із принципово різними вимогами до місткості:

- центральний серверний кластер (Server Farm) на 500 віртуальних машин;
- департамент розробки та інженерії на 220 робочих станцій;
- відділ продажу та маркетингу на 120 співробітників;
- загальнодоступну бездротову мережу (Guest Wi-Fi) на 1000 клієнтських пристроїв;
- технологічні магістральні канали зв'язку між маршрутизаторами ядра (Point-to-Point лінки) ємністю рівно по 2 хости кожен.

Якщо намагатися розрахувати такий план вручну на аркуші паперу чи в електронній таблиці, людина майже неминуче припускається критичних помилок: накладання адресних інтервалів, порушення обов'язкового вирівнювання меж блоків за степенями двійки або створення катастрофічної зовнішньої фрагментації, за якої тисячі вільних адрес виявляються розбитими на крихітні непридатні шматки.

Автоматизований алгоритм VLSM-планування повністю виключає людський фактор, гарантує безвідходне пакування префіксів у дереві адрес та автоматично формує повні набори конфігураційних параметрів для кожного інтерфейсу.

---

### Алгоритмічна модель жадібного VLSM-пакування

Математична основа алгоритму спирається на теорему про оптимальне двійкове розбиття простору: якщо всі запити на виділення ресурсів попередньо впорядковані за монотонним спаданням необхідного розміру блоку, послідовне жадібне розміщення адрес за найменшою доступною кратною межею гарантує нульову зовнішню фрагментацію.

Алгоритмічний процес розбивається на шість чітко визначених кроків:

#### 1. Перетворення вхідних даних у числовий формат

IPv4-адреса та маска парсяться з текстового десятково-крапкового представлення (наприклад, `"10.100.0.0/18"`) у беззнакове 32-бітне ціле число `uint32_t` у прямому порядку байтів процесора (Host Byte Order). Це дозволяє виконувати всі подальші обчислення за допомогою швидких апаратних регістрових операцій зсуву та логічного маскування без накладних витрат на роботу з рядками.

Мережевий порядок байтів (Network Byte Order, або Big-Endian) є стандартом для передачі пакетів лініями зв'язку, де старший байт передається першим. Проте всередині процесорних регістрів архітектури x86-64 чи ARM64 адреса завантажується як цілісне 32-бітне число. Це дозволяє виконувати перевірку меж та арифметику зміщення покажчика за допомогою однієї машинної інструкції додавання `ADD` замість розпакування на чотири окремі байти.

#### 2. Обчислення бітової ємності та довжини маски

Для кожного підрозділу із запитом на `R` корисних хостів визначається розмір хостової частини `h`:
- якщо активовано стандарт RFC 3021 для міжмаршрутизаторних каналів точка-точка і запит становить рівно `R = 2` хости, виділяється маска `/31` (`h = 1`), що дає блок рівно на 2 адреси без резервування адрес мережі та широкомовлення;
- для всіх стандартних підмереж до числа хостів додаються 2 обов'язкові службові адреси (мережевий ідентифікатор із нулями в полі хоста та широкомовна адреса з одиницями в полі хоста): `Needed = R + 2`. Потім значення округлюється вгору до найближчого степеня двійки:

```
h = ⌈log₂(R + 2)⌫
```

Довжина префікса підмережі обчислюється як `n = 32 − h`, а повний розмір блоку становить `S = 2ʰ`. 32-бітна маска підмережі формується бітовим зсувом: `Mask = ~0U << (32 − n)`.

#### 3. Сортування масиву запитів за спаданням розміру

Масив структур підмереж сортується за спаданням величини виділеного блоку `S` (що еквівалентно сортуванню за зростанням довжини префікса `n`). Це ключовий інваріант: спочатку розміщуються найбільші блоки (наприклад, `/22`), а наприкінці — найменші (наприклад, `/31`).

Якщо відсортувати запити у зворотному порядку (від дрібних до великих), алгоритм зазнає краху: після виділення підмережі розміром 4 адреси наступний блок розміром 1024 адреси вимагатиме вирівнювання за адресою, кратною 1024. У результаті алгоритм буде змушений пропустити 1020 адрес, утворивши «мертву зону» (зовнішню фрагментацію), у яку неможливо вкласти жодну іншу велику підмережу.

#### 4. Побітове вирівнювання меж та виділення підмереж

Алгоритм підтримує числовий покажчик поточної вільної адреси `current_ip`, який спочатку встановлюється на початок базового пулу `pool_start`. Для кожного наступного блоку розміром `S`:
- виконується операція бітового вирівнювання адреси початку на найближчу межу, кратну `S`:

```
current_ip = (current_ip + S − 1) ∧ ¬(S − 1)
```

- перевіряється умова переповнення: адреса кінця блоку `current_ip + S − 1` не повинна перевищувати верхню межу виділеного пулу `pool_end`;
- мережева адреса підмережі фіксується як `Net_IP = current_ip`;
- перший корисний хост призначається як `Net_IP + 1` (або `Net_IP` для `/31`);
- останній корисний хост призначається як `Net_IP + S − 2` (або `Net_IP + 1` для `/31`);
- широкомовна адреса призначається як `Net_IP + S − 1` (для `/31` широкомовлення відсутнє);
- покажчик поточної адреси зміщується на розмір виділеного блоку: `current_ip = current_ip + S`.

#### 5. Визначення залишку адресного простору

Після виділення всіх підмереж інтервал між фінальним значенням `current_ip` та `pool_end` являє собою суцільний нерозподілений резерв, який згодом можна розділити на нові підмережі без зміни адрес раніше налаштованих підрозділів.

### Реалізація калькулятора мовами C та C++

Нижче наведено повні та автономні реалізації алгоритму двома мовами: на чистому стандартному C (C99/C11) з прямим маніпулюванням бітовими масками та на сучасному ідіоматичному C++ (C++20) з використанням типізованих обгорток, виняткобезпечності через `std::expected` та сучасних алгоритмів `<ranges>`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

/* Структура запиту на виділення підмережі */
typedef struct {
    char name[64];
    uint32_t required_hosts;
    bool is_p2p_31;
    uint32_t allocated_size;
    uint8_t prefix_len;
    uint32_t net_ip;
    uint32_t mask;
    uint32_t first_host;
    uint32_t last_host;
    uint32_t broadcast_ip;
} Subnet;

/* Перетворення рядка IPv4 у 32-бітне число в host byte order */
bool parse_ipv4(const char *str, uint32_t *out_ip) {
    unsigned int b3, b2, b1, b0;
    if (sscanf(str, "%u.%u.%u.%u", &b3, &b2, &b1, &b0) != 4) return false;
    if (b3 > 255 || b2 > 255 || b1 > 255 || b0 > 255) return false;
    *out_ip = ((uint32_t)b3 << 24) | ((uint32_t)b2 << 16) | ((uint32_t)b1 << 8) | (uint32_t)b0;
    return true;
}

/* Форматування 32-бітного числа в рядок IPv4 */
void format_ipv4(uint32_t ip, char *buf, size_t len) {
    snprintf(buf, len, "%u.%u.%u.%u",
             (ip >> 24) & 0xFF, (ip >> 16) & 0xFF,
             (ip >> 8) & 0xFF, ip & 0xFF);
}

/* Обчислення найменшого степеня двійки 2^h >= val */
uint8_t compute_host_bits(uint32_t val) {
    uint8_t bits = 0;
    uint32_t size = 1;
    while (size < val && bits < 32) {
        size <<= 1;
        bits++;
    }
    return bits;
}

/* Компаратор для сортування за спаданням виділеного розміру */
int compare_subnets_desc(const void *a, const void *b) {
    const Subnet *sa = (const Subnet *)a;
    const Subnet *sb = (const Subnet *)b;
    if (sa->allocated_size < sb->allocated_size) return 1;
    if (sa->allocated_size > sb->allocated_size) return -1;
    return 0;
}

/* Головна функція планування VLSM */
bool plan_vlsm(uint32_t root_ip, uint8_t root_prefix, Subnet *subnets, size_t count) {
    uint32_t root_size = (root_prefix == 0) ? 0xFFFFFFFF : (1U << (32 - root_prefix));
    uint32_t pool_start = root_ip & ~((root_prefix == 32) ? 0 : (root_size - 1));
    uint32_t pool_end = pool_start + root_size - 1;

    /* Крок 1: Обчислення розміру та маски для кожного запиту */
    for (size_t i = 0; i < count; i++) {
        if (subnets[i].is_p2p_31 && subnets[i].required_hosts == 2) {
            subnets[i].prefix_len = 31;
            subnets[i].allocated_size = 2;
        } else {
            uint32_t needed = subnets[i].required_hosts + 2; /* + мережа і broadcast */
            uint8_t h = compute_host_bits(needed);
            subnets[i].prefix_len = 32 - h;
            subnets[i].allocated_size = 1U << h;
        }
        subnets[i].mask = (subnets[i].prefix_len == 0) ? 0 : (~0U << (32 - subnets[i].prefix_len));
    }

    /* Крок 2: Сортування за спаданням розміру */
    qsort(subnets, count, sizeof(Subnet), compare_subnets_desc);

    /* Крок 3: Жадібне виділення адрес */
    uint32_t current_ip = pool_start;
    for (size_t i = 0; i < count; i++) {
        uint32_t sz = subnets[i].allocated_size;
        /* Вирівнювання адреси за межею блоку */
        current_ip = (current_ip + sz - 1) & ~(sz - 1);

        /* Перевірка виходу за межі пулу */
        if (current_ip > pool_end || (current_ip + sz - 1) > pool_end) {
            fprintf(stderr, "Помилка: пул вичерпано на підмережі '%s'!\n", subnets[i].name);
            return false;
        }

        subnets[i].net_ip = current_ip;
        if (subnets[i].prefix_len == 31) {
            subnets[i].first_host = current_ip;
            subnets[i].last_host = current_ip + 1;
            subnets[i].broadcast_ip = 0; /* Broadcast відсутній у /31 */
        } else {
            subnets[i].first_host = current_ip + 1;
            subnets[i].last_host = current_ip + sz - 2;
            subnets[i].broadcast_ip = current_ip + sz - 1;
        }

        current_ip += sz;
    }
    return true;
}

int main(void) {
    uint32_t root_ip;
    if (!parse_ipv4("10.100.0.0", &root_ip)) return 1;
    uint8_t root_prefix = 18;

    Subnet list[] = {
        { .name = "Server Farm",     .required_hosts = 500,  .is_p2p_31 = false },
        { .name = "Engineering Dept",.required_hosts = 220,  .is_p2p_31 = false },
        { .name = "Sales Dept",      .required_hosts = 120,  .is_p2p_31 = false },
        { .name = "Guest Wi-Fi",     .required_hosts = 1000, .is_p2p_31 = false },
        { .name = "Core Link A-B",   .required_hosts = 2,    .is_p2p_31 = true  },
        { .name = "Core Link B-C",   .required_hosts = 2,    .is_p2p_31 = true  }
    };
    size_t count = sizeof(list) / sizeof(list[0]);

    if (!plan_vlsm(root_ip, root_prefix, list, count)) return 1;

    printf("Результати планування VLSM для пулу 10.100.0.0/18:\n");
    printf("%-18s %-6s %-16s %-16s %-33s %-16s\n",
           "Підмережа", "Префікс", "Мережа", "Маска", "Діапазон хостів", "Broadcast");
    printf("----------------------------------------------------------------------------------------------------------------\n");

    char net_str[16], mask_str[16], first_str[16], last_str[16], brd_str[16], range_str[36];
    for (size_t i = 0; i < count; i++) {
        format_ipv4(list[i].net_ip, net_str, sizeof(net_str));
        format_ipv4(list[i].mask, mask_str, sizeof(mask_str));
        format_ipv4(list[i].first_host, first_str, sizeof(first_str));
        format_ipv4(list[i].last_host, last_str, sizeof(last_str));
        snprintf(range_str, sizeof(range_str), "%s - %s", first_str, last_str);

        if (list[i].prefix_len == 31) {
            snprintf(brd_str, sizeof(brd_str), "N/A (RFC 3021)");
        } else {
            format_ipv4(list[i].broadcast_ip, brd_str, sizeof(brd_str));
        }

        printf("%-18s /%-5u %-16s %-16s %-33s %-16s\n",
               list[i].name, list[i].prefix_len, net_str, mask_str, range_str, brd_str);
    }
    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <string_view>
#include <algorithm>
#include <sstream>
#include <iomanip>
#include <cstdint>
#include <bit>
#include <expected>

struct IPv4Address {
    uint32_t val{0};

    constexpr IPv4Address() = default;
    constexpr explicit IPv4Address(uint32_t v) : val(v) {}

    static std::expected<IPv4Address, std::string> from_string(std::string_view str) {
        unsigned int b3, b2, b1, b0;
        char dot1, dot2, dot3;
        std::istringstream iss{std::string(str)};
        if (!(iss >> b3 >> dot1 >> b2 >> dot2 >> b1 >> dot3 >> b0) ||
            dot1 != '.' || dot2 != '.' || dot3 != '.' ||
            b3 > 255 || b2 > 255 || b1 > 255 || b0 > 255) {
            return std::unexpected("Некоректний формат IP-адреси");
        }
        uint32_t num = (static_cast<uint32_t>(b3) << 24) |
                       (static_cast<uint32_t>(b2) << 16) |
                       (static_cast<uint32_t>(b1) << 8)  |
                       static_cast<uint32_t>(b0);
        return IPv4Address(num);
    }

    [[nodiscard]] std::string to_string() const {
        std::ostringstream oss;
        oss << ((val >> 24) & 0xFF) << '.'
            << ((val >> 16) & 0xFF) << '.'
            << ((val >> 8)  & 0xFF) << '.'
            << (val & 0xFF);
        return oss.str();
    }
};

struct SubnetRequest {
    std::string name;
    uint32_t required_hosts{0};
    bool is_p2p_31{false};
};

struct AllocatedSubnet {
    std::string name;
    uint8_t prefix_len{0};
    uint32_t allocated_size{0};
    IPv4Address network;
    IPv4Address mask;
    IPv4Address first_host;
    IPv4Address last_host;
    IPv4Address broadcast;
    bool is_rfc3021{false};
};

class VLSMPlanner {
public:
    static std::expected<std::vector<AllocatedSubnet>, std::string>
    calculate(IPv4Address root_ip, uint8_t root_prefix, std::vector<SubnetRequest> requests) {
        if (root_prefix > 32) {
            return std::unexpected("Довжина префікса не може перевищувати 32");
        }

        uint32_t root_size = (root_prefix == 0) ? 0xFFFFFFFF : (1U << (32 - root_prefix));
        uint32_t pool_start = root_ip.val & ~((root_prefix == 32) ? 0 : (root_size - 1));
        uint64_t pool_end = static_cast<uint64_t>(pool_start) + root_size - 1;

        struct SizingItem {
            SubnetRequest req;
            uint8_t prefix;
            uint32_t size;
        };

        std::vector<SizingItem> items;
        items.reserve(requests.size());

        for (const auto &r : requests) {
            if (r.is_p2p_31 && r.required_hosts == 2) {
                items.push_back({r, 31, 2});
            } else {
                uint32_t needed = r.required_hosts + 2;
                // std::bit_width обчислює мінімальну кількість бітів для представлення числа
                uint8_t h = (needed <= 1) ? 1 : static_cast<uint8_t>(std::bit_width(needed - 1));
                uint8_t p = 32 - h;
                items.push_back({r, p, 1U << h});
            }
        }

        // Сортування за спаданням розміру блоку
        std::ranges::sort(items, [](const SizingItem &a, const SizingItem &b) {
            return a.size > b.size;
        });

        std::vector<AllocatedSubnet> result;
        result.reserve(items.size());

        uint64_t current_ip = pool_start;

        for (const auto &item : items) {
            uint64_t sz = item.size;
            // Вирівнювання адреси за межею блоку степеня двійки
            current_ip = (current_ip + sz - 1) & ~(sz - 1);

            if (current_ip + sz - 1 > pool_end) {
                return std::unexpected("Адресний пул вичерпано для підмережі: " + item.req.name);
            }

            uint32_t net_val = static_cast<uint32_t>(current_ip);
            uint32_t mask_val = (item.prefix == 0) ? 0 : (~0U << (32 - item.prefix));

            AllocatedSubnet sub;
            sub.name = item.req.name;
            sub.prefix_len = item.prefix;
            sub.allocated_size = item.size;
            sub.network = IPv4Address(net_val);
            sub.mask = IPv4Address(mask_val);

            if (item.prefix == 31) {
                sub.is_rfc3021 = true;
                sub.first_host = IPv4Address(net_val);
                sub.last_host = IPv4Address(net_val + 1);
                sub.broadcast = IPv4Address(0);
            } else {
                sub.is_rfc3021 = false;
                sub.first_host = IPv4Address(net_val + 1);
                sub.last_host = IPv4Address(net_val + item.size - 2);
                sub.broadcast = IPv4Address(net_val + item.size - 1);
            }

            result.push_back(sub);
            current_ip += sz;
        }

        return result;
    }
};

int main() {
    auto root_ip = IPv4Address::from_string("10.100.0.0");
    if (!root_ip) {
        std::cerr << root_ip.error() << std::endl;
        return 1;
    }

    std::vector<SubnetRequest> requests = {
        { "Server Farm",      500,  false },
        { "Engineering Dept", 220,  false },
        { "Sales Dept",       120,  false },
        { "Guest Wi-Fi",      1000, false },
        { "Core Link A-B",    2,    true  },
        { "Core Link B-C",    2,    true  }
    };

    auto plan = VLSMPlanner::calculate(*root_ip, 18, std::move(requests));
    if (!plan) {
        std::cerr << "Помилка планування: " << plan.error() << std::endl;
        return 1;
    }

    std::cout << "Результати планування VLSM для пулу 10.100.0.0/18 (C++20):\n";
    std::cout << std::left << std::setw(18) << "Підмережа"
              << std::setw(8)  << "Префікс"
              << std::setw(16) << "Мережа"
              << std::setw(16) << "Маска"
              << std::setw(33) << "Діапазон хостів"
              << std::setw(16) << "Broadcast" << "\n";
    std::cout << std::string(107, '-') << "\n";

    for (const auto &sub : *plan) {
        std::string range = sub.first_host.to_string() + " - " + sub.last_host.to_string();
        std::string brd = sub.is_rfc3021 ? "N/A (RFC 3021)" : sub.broadcast.to_string();

        std::cout << std::left << std::setw(18) << sub.name
                  << "/" << std::setw(7) << static_cast<int>(sub.prefix_len)
                  << std::setw(16) << sub.network.to_string()
                  << std::setw(16) << sub.mask.to_string()
                  << std::setw(33) << range
                  << std::setw(16) << brd << "\n";
    }
    return 0;
}
```

### Аналіз бітових операцій на рівні процесора

Розглянемо детально внутрішню механіку ключових обчислювальних виразів, які виконуються в ядрі алгоритму:

#### 1. Безрозгалужене вирівнювання на степінь двійки

Вираз вирівнювання адреси в C та C++ має вигляд:

```
current_ip = (current_ip + sz - 1) & ~(sz - 1);
```

Оскільки розмір блоку `sz` завжди є степенем двійки (`sz = 2ʰ`), його двійковий запис містить єдину одиницю у позиції `h` та нулі в усіх молодших розрядах.
Відповідно, вираз `sz - 1` формує бітову маску, у якій усі молодші `h` розрядів дорівнюють одиниці `1`, а старші розряди — нулю `0`.

Операція `current_ip + sz - 1` виконує додавання з надлишком: якщо `current_ip` вже була кратна `sz`, додавання `sz - 1` не перетинає наступну межу кратності. Якщо ж `current_ip` мала ненульовий залишок, додавання проштовхує старші розряди до наступного кратного значення.

Побітове інвертування `~(sz - 1)` формує маску з нулями в молодших `h` розрядах. Порозрядне множення `&` гарантовано обнуляє молодші `h` бітів, завершуючи округлення вгору до найближчого кратного степеня двійки. Сучасні компілятори транслюють цей вираз у дві процесорні інструкції: `LEA` (Load Effective Address) та `AND`, повністю уникаючи умовних переходів (Branchless Execution).

#### 2. Апаратне піднесення до степеня двійки та підрахунок нулів

У версії C++ функція `std::bit_width(needed - 1)` повертає точну кількість двійкових розрядів, необхідних для представлення числа. На сучасних процесорах сімейства x86-64 вона компілюється в апаратну інструкцію `LZCNT` (Leading Zero Count) або комбінацію `BSR` (Bit Scan Reverse) та `XOR`:

```
bit_width(x) = 32 - lzcnt(x)
```

Це гарантує, що визначення маски для будь-якої довільної кількості хостів виконується за 1 такт центрального процесора без виклику важких бібліотечних функцій обчислення логарифмів з плаваючою комою (`log2`).

### Покроковий числовий трейс виконання алгоритму

Розглянемо детальну динаміку зміни покажчиків пам'яті під час виконання програми для вихідного пулу `10.100.0.0/18`.

Базовий пул охоплює числовий діапазон від `10.100.0.0` до `10.100.63.255` (разом 16 384 адреси).

```
Початковий стан покажчика: current_ip = 10.100.0.0 (число 174 325 760)
Верхня межа пулу:          pool_end   = 10.100.63.255 (число 174 342 143)
```

#### Крок 1. Підмережа «Guest Wi-Fi» (потреба 1000 хостів)

- Необхідно адрес: `1000 + 2 = 1002`.
- Найближчий степінь двійки: `2¹⁰ = 1024` (`h = 10`, префікс `32 − 10 = /22`).
- Маска: `255.255.252.0`.
- Вирівнювання: `10.100.0.0` вже кратна 1024.
- Виділений діапазон:
  - Мережева адреса: `10.100.0.0/22`
  - Перший хост: `10.100.0.1`
  - Останній хост: `10.100.3.254`
  - Широкомовна адреса: `10.100.3.255`
- Нове значення покажчика: `current_ip = 10.100.0.0 + 1024 = 10.100.4.0`.

#### Крок 2. Підмережа «Server Farm» (потреба 500 хостів)

- Необхідно адрес: `500 + 2 = 502`.
- Найближчий степінь двійки: `2⁹ = 512` (`h = 9`, префікс `32 − 9 = /23`).
- Маска: `255.255.254.0`.
- Вирівнювання: адреса `10.100.4.0` (число 174 326 784) ділиться націло на 512.
- Виділений діапазон:
  - Мережева адреса: `10.100.4.0/23`
  - Перший хост: `10.100.4.1`
  - Останній хост: `10.100.5.254`
  - Широкомовна адреса: `10.100.5.255`
- Нове значення покажчика: `current_ip = 10.100.4.0 + 512 = 10.100.6.0`.

#### Крок 3. Підмережа «Engineering Dept» (потреба 220 хостів)

- Необхідно адрес: `220 + 2 = 222`.
- Найближчий степінь двійки: `2⁸ = 256` (`h = 8`, префікс `32 − 8 = /24`).
- Маска: `255.255.255.0`.
- Вирівнювання: адреса `10.100.6.0` ділиться націло на 256.
- Виділений діапазон:
  - Мережева адреса: `10.100.6.0/24`
  - Перший хост: `10.100.6.1`
  - Останній хост: `10.100.6.254`
  - Широкомовна адреса: `10.100.6.255`
- Нове значення покажчика: `current_ip = 10.100.6.0 + 256 = 10.100.7.0`.

#### Крок 4. Підмережа «Sales Dept» (потреба 120 хостів)

- Необхідно адрес: `120 + 2 = 122`.
- Найближчий степінь двійки: `2⁷ = 128` (`h = 7`, префікс `32 − 7 = /25`).
- Маска: `255.255.255.128`.
- Вирівнювання: адреса `10.100.7.0` ділиться націло на 128.
- Виділений діапазон:
  - Мережева адреса: `10.100.7.0/25`
  - Перший хост: `10.100.7.1`
  - Останній хост: `10.100.7.126`
  - Широкомовна адреса: `10.100.7.127`
- Нове значення покажчика: `current_ip = 10.100.7.0 + 128 = 10.100.7.128`.

#### Крок 5. Магістральний лінк «Core Link A-B» (2 хости, RFC 3021)

- Прапорець `is_p2p_31 = true`, виділяється рівно 2 адреси (префікс `/31`).
- Маска: `255.255.255.254`.
- Вирівнювання: адреса `10.100.7.128` парна (ділиться на 2).
- Виділений діапазон:
  - Мережева адреса: `10.100.7.128/31`
  - Хост Router A: `10.100.7.128`
  - Хост Router B: `10.100.7.129`
  - Широкомовна адреса: відсутня (N/A).
- Нове значення покажчика: `current_ip = 10.100.7.128 + 2 = 10.100.7.130`.

#### Крок 6. Магістральний лінк «Core Link B-C» (2 хости, RFC 3021)

- Префікс `/31`, розмір 2 адреси, маска `255.255.255.254`.
- Вирівнювання: адреса `10.100.7.130` парна.
- Виділений діапазон:
  - Мережева адреса: `10.100.7.130/31`
  - Хост Router B: `10.100.7.130`
  - Хост Router C: `10.100.7.131`
  - Широкомовна адреса: відсутня (N/A).
- Нове значення покажчика: `current_ip = 10.100.7.130 + 2 = 10.100.7.132`.

#### Підсумок використання простору

Усі шість підрозділів зайняли діапазон від `10.100.0.0` до `10.100.7.131` — сумарно 1 924 адреси. Нерозподілений залишок становить `16 384 − 1 924 = 14 460` адрес (від `10.100.7.132` до `10.100.63.255`), причому він не має внутрішніх «дірок» і може бути виділений під нові великі підмережі (наприклад, ще кілька блоків `/22` чи `/20`).

### Порівняння ефективності: VLSM проти класичного FLSM

Для демонстрації переваг VLSM порівняємо отриманий результат із застарілим методом маскування фіксованої довжини (Fixed Length Subnet Masking, FLSM).

За моделлю FLSM інженер мусить обрати єдину довжину маски для всіх підрозділів, орієнтуючись на найбільшу потребу (Guest Wi-Fi на 1000 хостів).
Найменший блок для 1000 хостів — це `/22` (1024 адреси).

Якщо застосувати фіксовану маску `/22` для всіх 6 підмереж:

```
Загальна потреба FLSM = 6 підмереж × 1024 адреси = 6144 адреси
Загальна потреба VLSM = 1024 + 512 + 256 + 128 + 2 + 2 = 1924 адреси
Економія простору     = 6144 − 1924 = 4220 адрес (68.7% економії)
```

Особливо помітна різниця на каналах точка-точка: замість витрачання 1024 адрес на 2 маршрутизатори за методом FLSM, стандарт RFC 3021 використовує рівно 2 адреси, скорочуючи витрати ресурсів на 99.8%.

Утилізація виділеного адресного простору розраховується як відношення суми фізично потрібних хостів до загального обсягу задіяних адрес:

```
Утилізація VLSM = (1000 + 500 + 220 + 120 + 2 + 2) / 1924 = 1844 / 1924 ≈ 95.8%
Утилізація FLSM = 1844 / 6144 ≈ 30.0%
```

Завдяки VLSM корисна утилізація виділених блоків зростає більше ніж утричі, запобігаючи передчасному вичерпанню корпоративних пулів.

### Системна інтеграція та конфігурація операційних систем

Результати роботи алгоритму транслюються безпосередньо в конфігураційні файли мережевих стеків або застосовуються в реальному часі через інтерфейси операційних систем.

#### Інтеграція з ядром Linux через Netlink

У Linux конфігурація мережевого інтерфейсу виконується через підсистему Netlink (`rtnetlink`). Коли утиліта `iproute2` викликає команду призначення адреси:

```bash
ip addr add 10.100.0.1/22 dev eth0.10
ip addr add 10.100.7.128/31 dev eth1
```

ядро формує системне повідомлення `RTM_NEWADDR` і додає запис у внутрішню таблицю маршрутизації FIB.

Для звичайної підмережі `/22` ядро автоматично реєструє три типи маршрутів:
1. **Локальний маршрут хоста (`RTN_LOCAL`):** `10.100.0.1/32` для обробки пакетів, адресованих власне цьому хосту.
2. **Маршрут підмережі (`RTN_UNICAST`):** `10.100.0.0/22` зі статусом `proto kernel, scope link` для прямої відправки ARP-запитів до сусідів у межах канального рівня.
3. **Широкомовні маршрути (`RTN_BROADCAST`):** для мережевої адреси `10.100.0.0/32` та спрямованого широкомовлення `10.100.3.255/32`.

Для каналу `/31` за стандартом RFC 3021 ядро Linux створює лише записи `RTN_LOCAL` для власної адреси та `RTN_UNICAST` на суміжну адресу сусіда. Широкомовні маршрути не реєструються взагалі, що повністю виключає генерацію фонового широкомовного трафіку.

#### Апаратні таблиці комутації TCAM

Сучасні високопродуктивні комутатори L3 (на чипсетах Broadcom Trident/Tomahawk або Marvell Prestera) реалізують апаратне пересилання пакетів через спеціалізовану пам'ять TCAM (Ternary Content Addressable Memory). Кожен запис у TCAM складається зі значення ключа (Value) та бітової маски (Mask), дозволяючи знайти маршрут за один такт синхросигналу незалежно від розміру таблиці.

Коли підмережі виділено через VLSM з обов'язковим двійковим вирівнюванням, кожен префікс займає рівно один рядок TCAM. Якщо ж інженер спробує сконфігурувати довільний, не вирівняний за степенем двійки діапазон адрес, чип комутатора буде змушений розбити такий інтервал на декілька двійкових підпрефіксів. Це призводить до надлишкового заповнення TCAM та апаратного переповнення таблиць комутації FIB (Forwarding Information Base).

### Алгоритм перевірки колізій та інтеграція в системи IPAM

Сучасні платформи керування адресним простором (IP Address Management, IPAM — NetBox, phpIPAM, Nautobot) використовують алгоритм перевірки колізій перед внесенням будь-яких змін у глобальний реєстр.

Для двох довільних підмереж `(IP₁, Mask₁)` та `(IP₂, Mask₂)` умова перетину перевіряється комбінованим маскуванням:

```
Overlap = ( (IP₁ ∧ Mask₁ ∧ Mask₂) == (IP₂ ∧ Mask₁ ∧ Mask₂) )
```

Якщо ця рівність справджується, підмережі мають спільний адресний простір, причому підмережа з довшою маскою є підмножиною підмережі з коротшою маскою.

Платформи автоматизації (NetDevOps) генерують із розрахованих структур файли конфігурації для серверів автоматичної видачі адрес DHCP (ISC Kea, dnsmasq) та файли зворотних зон DNS (`in-addr.arpa`). Наприклад, для підмережі `10.100.4.0/23` автоматично генерується пул видачі хостів від `10.100.4.10` до `10.100.5.250`, шлюз за замовчуванням `10.100.4.1` та статичні записи для серверів керування.

### Інженерні пастки та захист від помилок розширення

У практичній експлуатації мереж виділяють дві головні помилки довгострокового планування:

1. **Пастка відсутності коефіцієнта зростання (Growth Factor Padding):**
   Якщо у відділі на момент запуску налічується 115 комп'ютерів і йому виділяють підмережу `/25` (126 хостів), запас місткості становить лише 11 робочих місць. Коли штат розширюється до 130 осіб, інженер не може розширити поточний префікс до `/24`, оскільки наступні адреси вже призначено іншому відділу. Доводиться або призначати вторинну підмережу (Secondary IP) на шлюзі, що ускладнює керування політиками безпеки, або повністю мігрувати відділ на новий VLAN із масовою зміною статичних IP-адрес обладнання. Професійний стандарт планування вимагає закладати щонайменше 30–50% запасу зростання (резервування 1 додаткового біта маски).
2. **Пастка змішування ролей в одному префіксі:**
   Не можна розміщувати в одній підмережі клієнтські ПК, принтери, сервери та інтерфейси керування обладнанням. Крім ризиків безпеки, це блокує агрегацію маршрутів у списках доступу (ACL) та політиках міжмережевих екранів (Firewall). Правильне проєктування передбачає окремі ієрархічні піддерева для кожної функціональної категорії.
