# 📜 Еволюція безпеки Wi-Fi: від краху WEP до створення WPA і 802.11i

Коли у 1997 році робоча група IEEE 802.11 ухвалила перший стандарт бездротових локальних мереж, інженери зіткнулися з фундаментальним викликом: як забезпечити в радіоефірі той самий рівень конфіденційності, що й у звичайному мідному кабелі крученої пари. У дротовій мережі Ethernet зловмисник змушений мати фізичний доступ до розетки або комутатора. У бездротовій мережі кожен радіокадр поширюється у вільному просторі, перетинаючи стіни кабінетів, вікна та паркани. Будь-який радіоприймач на тій самій частоті безперешкодно фіксує кожен переданий біт. Відповіддю комітету став протокол WEP (Wired Equivalent Privacy, у перекладі з англійської — «конфіденційність, еквівалентна дротовій мережі»). Проте закладені в нього криптографічні компроміси перетворили WEP на один із найгучніших провалів в історії інформаційної безпеки, що змусило індустрію терміново створити тимчасовий стандарт WPA та розробити повноцінну архітектуру IEEE 802.11i.

---

### 1. Архітектурні компроміси 1990-х і вибір шифру RC4

Наприкінці 1990-х років обчислювальні ресурси мережевого обладнання були вкрай обмеженими. Перші бездротові адаптери (наприклад, легендарні картки Lucent Orinoco та Cisco Aironet стандарту 802.11b на швидкостях 1–11 Мбіт/с) оснащувалися дешевими 8-бітними або 16-бітними мікроконтролерами з мінімальним енергоспоживанням. Апаратна реалізація симетричних блокових шифрів на кшталт DES чи щойно розробленого Rijndael вимагала надто великої площі кремнієвого кристала й суттєво здорожчувала кінцевий пристрій.

З цієї причини автори стандарту 802.11 обрали потоковий симетричний шифр **RC4** (Rivest Cipher 4), розроблений Роном Рівестом (Ron Rivest) у 1987 році для компанії RSA Security. RC4 мав виняткові переваги для вбудованих систем:
- Надзвичайна простота програмної реалізації (увесь алгоритм генерації псевдовипадкової послідовності складається з кількох рядків коду).
- Висока швидкодія навіть на слабких процесорах без спеціалізованих апаратних прискорювачів.
- Робота у формі генератора псевдовипадкової гами (keystream): шифрування зводилося до порозрядної операції додавання за модулем 2 (`XOR`, `⊕`) між байтами відкритого тексту та байтами згенерованої гами.

Шифр RC4 використовує внутрішній стан у вигляді таблиці підстановок `S` розміром 256 байтів (перестановка чисел від 0 до 255) та два 8-бітні індекси `i` та `j`. Алгоритм ініціалізації ключа (Key Scheduling Algorithm, KSA) наповнює та перемішує масив `S` на основі секретного ключа:

```
// Ініціалізація масиву підстановок S
для i від 0 до 255:
    S[i] = i

j = 0
для i від 0 до 255:
    j = (j + S[i] + Key[i mod key_length]) mod 256
    поміняти_місцями(S[i], S[j])
```

Після виконання KSA запускається генератор псевдовипадкових слів (Pseudo-Random Generation Algorithm, PRGA), який видає по одному байту псевдовипадкової гами `z` для кожного байта повідомлення:

```
i = (i + 1) mod 256
j = (j + S[i]) mod 256
поміняти_місцями(S[i], S[j])
z = S[(S[i] + S[j]) mod 256]
Шифротекст[k] = Відкритий_текст[k] ⊕ z
```

Головне правило безпеки будь-якого потокового шифру є абсолютним: **криптографічну гаму ніколи не можна використовувати повторно з двома різними повідомленнями**. Якщо два відкриті тексти `P₁` та `P₂` зашифровані на одній гамі `Z` (`C₁ = P₁ ⊕ Z`, `C₂ = P₂ ⊕ Z`), зловмисник, просто додавши два перехоплені шифротексти, миттєво знищує ключ:
```
C₁ ⊕ C₂ = (P₁ ⊕ Z) ⊕ (P₂ ⊕ Z) = P₁ ⊕ P₂
```
Маючи результат `P₁ ⊕ P₂` та знаючи структуру мережевих заголовків (наприклад, фіксовані байти SNAP-заголовка `0xAA 0xAA 0x03` або поля IP-пакета), відновлення обох відкритих повідомлень стає тривіальною задачею лінгвістичного чи статистичного аналізу.

Щоб запобігти повторному використанню гами з фіксованим спільним паролем мережі (статичним ключем довжиною 40 або 104 біти), розробники WEP додали до кожного кадру відкритий 24-бітний **вектор ініціалізації** (Initialization Vector, IV). Повний сеансовий ключ для алгоритму KSA формувався простим склеюванням: `Key = IV || Shared_Secret_Key` (довжиною 64 або 128 біт відповідно).

### 2. Анатомія катастрофи: парадокс днів народження та атака FMS

Конструкція WEP містила три фатальні вразливості, які перетворили його захист на фікцію.

#### Вразливість 1: Катастрофічно малий простір IV (24 біти)
Розмірність у 24 біти надає лише `2²⁴ = 16 777 216` унікальних значень вектора ініціалізації. У завантаженій мережі стандарту 802.11b, де точка доступу передає близько 1000 кадрів на секунду, повний перебір усіх можливих IV вичерпується менш ніж за 4.6 години. 

Більше того, через парадокс днів народження (Birthday Paradox) перша колізія (повторне використання однакового IV двома пакетами) з імовірністю понад 50% настає вже після передачі приблизно `√(2²⁴) ≈ 4096` пакетів, тобто через 4–5 секунд роботи мережі. Оскільки більшість дешевих мережевих карток скидали лічильник IV у нуль під час кожного перезавантаження або ініціалізували його передбачуваним лінійним інкрементом, перехоплювач накопичував гігабайти колізій гами за лічені хвилини.

#### Вразливість 2: Слабкість алгоритму KSA та атака FMS (2001)
У серпні 2001 року криптографи Скотт Флурер (Scott Fluhrer), Іцик Мантін (Itsik Mantin) та Аді Шамір (Adi Shamir) опублікували фундаментальну статтю «Weaknesses in the Key Scheduling Algorithm of RC4». Вони довели, що початковий стан таблиці перестановки `S` після виконання KSA містить сильний статистичний витік інформації про перші байти секретного ключа, якщо вектор ініціалізації має спеціальний вигляд.

Оскільки перші три байти ключа RC4 у WEP складаються з відкритого IV (`IV[0], IV[1], IV[2]`), а байт секретного ключа `K[B]` є четвертим і наступними елементами, перехоплювач фільтрує в ефірі так звані **слабкі вектори ініціалізації** (weak IVs) виду:
```
IV = (B + 3, 255, V)
```
де `B` — індекс байта секретного пароля, який атакуючий намагається відновити, а `V` — довільне число.

За такої структури IV перший згенерований байт гами `z₁` з імовірністю близько 5% (1 з 20) прямо дорівнює:
```
z₁ = (S[1] + j₂) mod 256
```
Оскільки перший байт відкритого тексту кадру 802.11 майже завжди відомий наперед (це байт `0xAA` заголовка IEEE 802.2 SNAP), атакуючий обчислює перший байт гами безпосередньо з шифротексту: `z₁ = C₁ ⊕ 0xAA`. Накопичивши кілька сотень слабких IV для фіксованого значення `B`, зловмисник будує гістограму кандидатів. Правильне значення байта `K[B]` утворює чіткий статистичний пік над рівномірним шумом. Відновивши байт `K[0]`, атака послідовно переходить до відновлення `K[1]`, `K[2]` і так далі. Для повного зламу 104-бітного ключа WEP за допомогою FMS було достатньо зібрати від 1 до 5 мільйонів пакетів.

У 2004 році хакер під псевдонімом KoreK опублікував набір практичних оптимізацій, що знизили вимогу до 200 000 пакетів, а у 2007 році Андрій Пишкін (Andrei Pyshkin), Ерік Тевс (Erik Tews) та Ральф-Філіп Вайнманн (Ralf-Philipp Weinmann) представили метод **PTW**, який аналізував не лише перші, а й подальші байти гами, скоротивши час зламу WEP до 40 000 перехоплених пакетів (менше 60 секунд за умов активної генерації трафіку).

#### Вразливість 3: Лінійність контрольної суми CRC-32 (ICV)
Для перевірки цілісності кадру WEP використовував 32-бітний код перевірки цілісності (Integrity Check Value, ICV), обчислений алгоритмом CRC-32. Функція CRC-32 є строго лінійною відносно операції `XOR`:
```
CRC(A ⊕ B) = CRC(A) ⊕ CRC(B)
```
Це дозволило реалізувати атаку модифікації повідомлень (Bit-flipping attack). Зловмисник, бажаючи змінити біти у відкритому тексті на маску `ΔP`, просто обчислював `ΔCRC = CRC(ΔP)` і модифікував шифротекст:
```
C' = C ⊕ (ΔP || ΔCRC)
```
Приймач успішно розшифровував змінений кадр, перевіряв ICV і вважав його повністю легітимним. Це дозволяло інжектувати власні кадри в мережу, викликати відповіді точки доступу та штучно розганяти швидкість генерації нових IV (атака ARP-ін'єкції).

### 3. Тимчасовий порятунок: протокол WPA та алгоритм TKIP

Повний крах WEP поставив бездротову індустрію на межу кризи: корпоративні користувачі почали масово відключати Wi-Fi через неможливість гарантувати безпеку даних. Розробка нового стандарту IEEE 802.11i на основі криптостійкого блокового шифру AES тривала надто повільно, а головне — вимагала заміни апаратного парку клієнтських адаптерів і точок доступу.

Щоб врятувати мільйони вже розгорнутих пристроїв, консорціум Wi-Fi Alliance у квітні 2003 року представив проміжний стандарт **WPA** (Wi-Fi Protected Access). Його фундаментальною вимогою була **100% програмна сумісність** з наявними апаратними чипами WEP: шифрування мусило базуватися на тому самому апаратному блоці RC4, але з повною ліквідацією механізмів, які робили можливими атаки FMS та повторне використання ключів.

Основним криптографічним рушієм WPA став протокол **TKIP** (Temporal Key Integrity Protocol, у перекладі з англійської — «протокол тимчасової цілісності ключів»). TKIP вніс чотири ключові вдосконалення:

```
+-----------------------------------------------------------------------------------+
|                            АРХІТЕКТУРНІ СКЛАДОВІ TKIP                             |
|                                                                                   |
|  1. Розширення простору векторів ініціалізації:                                   |
|     24-бітний IV WEP ──► 48-бітний лічильник TSC (TKIP Sequence Counter)          |
|     Час повторення за 1000 кадр/с: зростання з 4.6 годин до 8900 років!           |
|                                                                                   |
|  2. Двофазне перемішування ключів (Per-Packet Key Mixing):                         |
|     Фаза 1 (раз на 65536 кадрів): TTAK = Mix1(TK, TA, TSC_high)                   |
|     Фаза 2 (для кожного кадру):   WEP_Seed = Mix2(TK, TTAK, TSC_low)              |
|     Усуває зв'язок між відкритим IV та сеансовим ключем (блок атаки FMS).         |
|                                                                                   |
|  3. Криптографічний код цілісності Michael MIC (64 біти):                         |
|     Заміна лінійного CRC-32 на повноцінний криптографічний хеш корисного          |
|     навантаження (MSDU) з власними 64-бітними ключами автентифікації.             |
|                                                                                   |
|  4. Механізм самозахисту (Countermeasures):                                       |
|     У разі виявлення двох помилок Michael MIC за 60 секунд:                       |
|     • Точка доступу негайно розриває всі з'єднання.                              |
|     • Блокує радіоканал на 60 секунд (запобігає підбору хешу).                   |
|     • Ініціює повну зміну сеансових ключів (Rekeying).                            |
+-----------------------------------------------------------------------------------+
```

#### Двофазне перемішування ключів (Key Mixing)
Замість тривіального склеювання `IV || Key`, алгоритм TKIP розділив 48-бітний лічильник TSC на старші 32 біти (`TSC_high`) та молодші 16 бітів (`TSC_low`).
- **Фаза 1** виконується лише раз на `2¹⁶ = 65 536` пакетів. Вона змішує 128-бітний часовий ключ `TK`, MAC-адресу передавача (`TA`) та `TSC_high` за допомогою серії підстановок у S-блоках, формуючи проміжний 80-бітний ключ `TTAK` (TKIP Phase 1 Intermediate Key). Цю ресурсомістку операцію процесор точки доступу міг виконувати без затримок у фоні.
- **Фаза 2** виконується для кожного окремого кадру. Вона швидко комбінує `TTAK`, сеансовий `TK` та 16 бітів `TSC_low`, генеруючи унікальний 128-бітний сеансовий ключ для шифратора RC4.

Таке розділення повністю унеможливило атаку FMS, оскільки байти відкритого IV більше не потрапляли в KSA RC4 у незмінному вигляді.

#### Код цілісності Michael MIC та захисні контрзаходи
Оскільки слабкі процесори 2003 року не могли розраховувати складні імітовставки на кшталт HMAC-SHA1 для кожного пакета без падіння пропускної здатності каналу, криптограф Нільс Фергюсон (Niels Ferguson) спроєктував спеціальний 64-бітний алгоритм **Michael**.

Michael був розрахований на екстремально швидке виконання (прості зсуви та додавання `XOR`), але мав невисоку теоретичну стійкість: криптографічна міцність становила лише близько 29 бітів. Зловмисник міг підібрати правильний код цілісності в середньому за `2²⁹ ≈ 5.3 · 10⁸` спроб підробки пакетів.

Щоб компенсувати математичну слабкість алгоритму, Фергюсон заклав жорсткий протокольний механізм протидії (MIC Failure Countermeasures). Якщо приймач фіксував два некоректні значення Michael MIC протягом 60 секунд, система робила висновок про активну атаку. Точка доступу миттєво відключала всіх клієнтів, припиняла передачу кадрів рівно на 60 секунд і примусово генерувала новий майстер-ключ. Це знизило ймовірність успішного підбору Michael MIC до абсолютно нікчемних значень (на підбір за такої швидкості знадобилися б роки), однак відкрило можливість для атак на відмову в обслуговуванні (DoS): нападник міг навмисно надсилати два пошкоджені кадри щохвилини, паралізуючи роботу всієї мережі.

### 4. Ратифікація IEEE 802.11i (2004) та поява WPA2

TKIP виконав своє історичне завдання: він дав індустрії перепочинок і захистив користувачів від швидкого зламу наявної інфраструктури. Проте всім було зрозуміло, що RC4 та Michael — це інженерні милиці, які вичерпали свій ресурс.

24 червня 2004 року комітет IEEE офіційно ратифікував стандарт **IEEE 802.11i-2004** (відомий як WPA2 / Robust Security Network, RSN). Головними рішеннями нового стандарту стали:
1. **Повна відмова від застарілих шифрів:** Потоковий шифр RC4 та алгоритм Michael були офіційно визнані небезпечними і заборонені в новому обладнанні (а у 2015 році стандартом IEEE 802.11-2016 TKIP був остаточно вилучений зі специфікацій).
2. **Апаратна інтеграція AES:** Стандарт зафіксував обов'язкове використання протоколу **CCMP** (Counter Mode with Cipher Block Chaining Message Authentication Code Protocol) на базі симетричного блокового шифру **AES-128** (Advanced Encryption Standard).
3. **Розділення конфіденційності та автентифікації:** CCMP використовує режим CTR для шифрування даних та режим CBC-MAC для створення 64/128-бітного коду цілісності, що зробило структуру повністю стійкою до всіх відомих видів математичного та статистичного аналізу.
4. **Стандартизація чотириетапного рукостискання (4-Way Handshake):** Створення криптографічно надійного протоколу взаємної автентифікації клієнта та точки доступу з динамічним розгортанням сеансових ключів PTK та GTK.

Перехід від WEP до 802.11i став найважливішим еволюційним стрибком у розвитку бездротових комунікацій: Wi-Fi перетворився з дірявого експериментального радіоефіру на надійне корпоративне середовище, здатне захищати банківські транзакції та конфіденційні державні дані.
