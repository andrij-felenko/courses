# ⚙️ Слухати перед передачею: CSMA/CA у коді

Wi-Fi сидить на фіксованому каналі й уживається із сусідами однією простою звичкою: **спершу слухає, і лише потім говорить**. Метод зветься **CSMA/CA** (англ. *Carrier Sense Multiple Access with Collision Avoidance* — «множинний доступ із прослуховуванням несучої та униканням зіткнень»). Назва довга, та ідея вкладається в один рух: перш ніж випустити пакет, перевір, чи в ефірі тихо. Розберімо, як це справді працює — і чому наївна перевірка «вільно → передаю» не рятує, а часом навіть шкодить.

## Задача

Маємо багато передавачів на одній частоті й один-єдиний ефір. Якщо двоє заговорять водночас, їхні сигнали накладуться, і приймач не зрозуміє жодного — це **зіткнення** (англ. *collision*). Обидва пакети гинуть, обидва доведеться слати наново. Завдання: звести зіткнення до мінімуму, **не маючи жодного диригента** — ніхто не роздає, кому коли говорити. Кожен пристрій вирішує сам, спираючись лише на те, що чує в ефірі.

Окрема складність радіо, якої немає на дроті: передавач **не чує власного зіткнення**. Поки антена випромінює, потужний свій сигнал глушить усе інше — пристрій фізично не може водночас і голосно говорити, і слухати слабкий чужий голос. На дроті можна було б ловити зіткнення прямо під час передачі (так працює провідний CSMA/CD — *Collision Detection*). У повітрі це неможливо, тому радіо й робить ставку не на *виявлення* зіткнень, а на їх **уникання** заздалегідь. Звідси й буква **CA** замість **CD**.

## Ідея

Наївний підхід — «канал вільний → передаю негайно» — має очевидну діру. Уяви, що канал зайнятий і його чекають **двоє**. Щойно поточний передавач замовкне, обидва побачать тишу **тієї самої миті** й заговорять разом — гарантоване зіткнення. Що більше пристроїв чекає, то надійніше вони зіткнуться.

Рятує **випадкова пауза перед передачею**. Побачивши вільний канал, пристрій не кидається говорити, а відлічує випадковий **відступ** (англ. *backoff*) — скільки додаткових тихих проміжків перечекати. Двоє охочих майже напевно витягнуть різні числа; менше виграє перегони й почне передачу, більший побачить, що канал знову зайнятий, і **зупинить свій лічильник**, доерахувавши решту вже після наступної тиші. Випадковість розводить претендентів у часі — у цьому все ядро методу.

Якщо пакет усе ж зіткнувся (передавач здогадається про це з того, що не прийшло підтвердження), він не повторює з тим самим розмахом, а **подвоює діапазон випадкової паузи** — так званий двійковий експоненційний відступ. Що більше зіткнень поспіль, то ширший діапазон і то менший шанс знову влучити в той самий момент, що й сусід. Коли ж ефір вільний, діапазон повертається до малого мінімуму, щоб не марнувати час на порожнє очікування.

Чому саме подвоєння, а не стала пауза? Бо мінятися мусить не середня затримка одного пристрою, а **щільність претендентів у часі**. Поки в ефірі двоє, тісний діапазон їх легко розводить — вибрати різні числа з шістнадцяти неважко. Та коли разом прокидаються двадцять пристроїв, тих самих шістнадцяти варіантів на всіх замало: декілька неодмінно витягнуть однакове число й зіткнуться. Кожне зіткнення вдвічі розсуває діапазон, і простір варіантів росте, доки не дожене кількість претендентів. Система сама намацує потрібну «ширину лотереї» під поточне навантаження — без жодного диригента, що знав би, скільки пристроїв в ефірі.

Проста прикидка показує масштаб. Якщо діапазон — 16 значень, а охочих говорити двоє, шанс обом витягнути одне число лише 1/16 ≈ 6 %; решта 94 % разів хтось виграє перегони чисто. Та якщо охочих десять, ймовірність, що *жодні* двоє не збіглися, падає десь до чверті — тобто здебільшого хтось таки зіткнеться, діапазон розсунеться, і вже на ширшому наборі повтор пройде спокійніше.

У звичайній прошивці всю цю механіку не пишуть руками: радіо на чипі (той-таки Wi-Fi-контролер ESP32) виконує DIFS, відступ і повтори **усередині**, а назовні віддає просту відповідь — пакет надіслано чи ні. Та коли в людному ефірі виклик `send()` раптом починає затинатися й часом повертати помилку, корисно знати, що під ним крутиться саме ця лотерея відступів: пристрій не «висить», а чесно перечікує зайнятий канал. Розуміння механізму прямо підказує ліки — розвести передачі в часі, скоротити пакети або піти на вільніший канал, — замість марних спроб «прискорити» те, що впирається не в код, а в загальну тісноту смуги.

## Робочий код

Ось логіка CSMA/CA, зведена до прошивкового скелета. Дрібниці часу (DIFS, тривалість слота) тут — узагальнені; конкретні значення задає стандарт радіо, але структура саме така:

```c
#define SLOT_US     9      // тривалість одного "слота" тиші, мкс
#define DIFS_US     34     // канал має бути вільним стільки перед стартом
#define CW_MIN      15     // початковий діапазон відступу (слотів)
#define CW_MAX      1023   // стеля діапазону

// апаратне: чи зайнятий ефір просто зараз
extern bool channel_busy(void);

// чекати, доки канал не буде вільним суцільно gap_us мікросекунд
static void wait_idle_for(uint32_t gap_us) {
    for (;;) {
        while (channel_busy()) { /* зайнято — чекаємо звільнення */ }
        uint32_t t0 = micros();
        while (!channel_busy()) {
            if (micros() - t0 >= gap_us) return;   // витримали всю тишу
        }
        // хтось заговорив посеред паузи — починаємо відлік тиші наново
    }
}

// одна спроба надіслати кадр; повертає true, якщо прийшов ACK
bool csma_send(const uint8_t *frame, size_t len) {
    uint32_t cw = CW_MIN;

    for (int attempt = 0; attempt < 7; attempt++) {
        wait_idle_for(DIFS_US);                 // 1. канал вільний DIFS?

        // 2. випадковий відступ у слотах із поточного діапазону
        int backoff = rand() % (cw + 1);
        while (backoff > 0) {
            if (channel_busy()) {               //   хтось зайняв ефір —
                wait_idle_for(DIFS_US);         //   заморозити лічильник,
                continue;                       //   доерахувати після тиші
            }
            delay_us(SLOT_US);
            backoff--;                          //   тихий слот — крок вниз
        }

        radio_transmit(frame, len);             // 3. лічильник 0 → передаємо
        if (wait_for_ack())                     // 4. дочекалися ACK?
            return true;                        //    доставлено

        cw = (cw * 2 + 1);                       // 5. зіткнення: подвоїти діапазон
        if (cw > CW_MAX) cw = CW_MAX;
    }
    return false;                               // здалися після кількох спроб
}
```

Читається це як проста історія: дочекайся суцільної тиші завдовжки DIFS, відлічи випадкову кількість тихих слотів (заморожуючи лічильник щоразу, коли ефір знову зайнято), передай, дочекайся підтвердження. Немає ACK — вважай, що зіткнувся, розсунь діапазон удвічі й спробуй знову.

## Пастки

**Прихований вузол.** Найпідступніша вада CSMA/CA: пристрій чує не весь ефір, а лише те, що дістає до **його** антени. Уяви трьох: A і C по краях, B посередині. A і C **не чують одне одного** (задалеко), зате обидва добре чують B. Коли A передає до B, для C ефір здається вільним — і C сміливо передає, глушачи пакет A прямо на приймачі. Жодне прослуховування цього не лове, бо C фізично не чує A. Це класична **проблема прихованого вузла** (англ. *hidden node*).

Лікують її коротким рукостисканням перед великим пакетом: передавач шле крихітний запит **RTS** (*Request To Send* — «прошу дозволу передавати»), приймач відповідає **CTS** (*Clear To Send* — «можна передавати»). CTS чують **усі** довкола приймача — зокрема й прихований C, — і мовчать домовлений час. Платня — зайвий обмін на кожен пакет, тож RTS/CTS вмикають лише для довгих кадрів, які надто дорого пересилати.

**Чесність проти швидкості.** Випадковий відступ робить доступ приблизно справедливим, але саме *приблизно*: комусь щастить із числами частіше. А коли в ефірі багато активних пристроїв, левову частку часу з'їдають уже не самі пакети, а паузи й зіткнення — корисна пропускна здатність обвалюється задовго до «теоретичної» межі каналу. Це та сама тіснота 2.4 ГГц, лише видна зсередини протоколу: канал начебто широкий, а реальна швидкість у людному ефірі — частка від обіцяної.

**Ціна слухання для батарейки.** Для пристрою на акумуляторі слухати ефір — не безкоштовно: приймач мусить бути ввімкнений увесь час очікування й відступу, а це струм. Тому маленькі давачі рідко тримають CSMA/CA постійно — вони здебільшого сплять, прокидаються рідкими сплесками, швидко вистрілюють пакет і знову гаснуть. Що довша тиснява в ефірі змушує слухати, то більше енергії згоряє ні на що — і це окремий, дуже практичний аргумент проти переповнених каналів.

**Не плутати «вільно зараз» із «вільно весь пакет».** Перевірка перед стартом каже лише, що ефір тихий **цієї миті**. Доки довгий пакет летить, поряд цілком може прокинутися хтось, хто щойно вийшов із власного відступу, — і зіпсувати кінець кадру. Саме тому довгі передачі ризикованіші за короткі, і саме тому втрату ловлять **підтвердженням** (ACK) уже після факту, а не самим лише прослуховуванням до старту.

**Не плутати з арбітражем на дроті.** На спільній шині на кшталт I²C чи CAN зіткнення розв'язує не випадкова пауза, а [детермінований арбітраж за рівнями сигналу](book:communications/clock-stretch-arbitration): хто «сильніший», той і виграє, без жодної лотереї. У радіо такий фокус неможливий — звідси й уся ставка на випадковість і повтори. Один спосіб «чемності» не переноситься на інше середовище наосліп.
