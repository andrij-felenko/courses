# 🧮 Розрахунок Slot Time, затримки RTT та мінімального розміру кадру Ethernet

Цей математичний вивід показує, як закони електродинаміки та поширення хвиль у хвилеводах і мідних лініях передачі диктують точний аналітичний зв'язок між бітовою швидкістю передачі, фізичною довжиною колізійного домену та мінімально допустимим розміром кадру в протоколах випадкового доступу CSMA/CD. Розрахунок розкриває фундаментальну причину появи стандарту 64 байтів (512 біт-часів) у мережах Ethernet, а також математичні обмеження швидкості та масштабування напівдуплексних середовищ.

---

## 1. Електродинаміка лінії передачі та швидкість поширення сигналу

Коаксіальний кабель та вита пара являють собою лінії передачі з розподіленими параметрами: погонною індуктивністю `L_m` (Гн/м) та погонною ємністю `C_m` (Ф/м).

Хвильовий (характерний) опір лінії `Z_0` та фазова швидкість поширення електромагнітної хвилі `v` визначаються рівняннями телеграфістів:

```
Z_0 = √(L_m / C_m)

v = 1 / √(L_m · C_m) = c / √(ε_r · μ_r)
```

де:
- `c = 299 792 458 м/с ≈ 3.0 · 10⁸ м/с` — швидкість світла у вакуумі;
- `μ_r ≈ 1.0` — відносна магнітна проникність немагнітних діелектриків (поліетилену, тефлону);
- `ε_r` — відносна діелектрична проникність ізолятора кабелю;
- `VF = 1 / √ε_r` — коефіцієнт уповільнення хвилі (англ. *Velocity Factor*).

Для стандартних кабелів локальних мереж фізичні параметри мають такі значення:

```
1. 10BASE5 (товстий коаксіал RG-8/U, спінений поліетилен Foam PE):
   ε_r ≈ 1.69
   VF  = 1 / √1.69 = 1 / 1.30 ≈ 0.77
   v   = 0.77 · 3.0 · 10⁸ м/с = 2.31 · 10⁸ м/с = 231 м/мкс

2. 10BASE2 (тонкий коаксіал RG-58A/U, суцільний поліетилен Solid PE):
   ε_r ≈ 2.25
   VF  = 1 / √2.25 = 1 / 1.50 ≈ 0.667
   v   = 0.667 · 3.0 · 10⁸ м/с = 2.00 · 10⁸ м/с = 200 м/мкс

3. 10BASE-T / 100BASE-TX (вита пара категорії 5 UTP, діелектрик FEP/HDPE):
   ε_r ≈ 2.1 – 2.3
   VF  ≈ 0.65 – 0.68
   v   ≈ 195 – 204 м/мкс
```

Питома часова затримка поширення сигналу на один метр довжини кабелю `τ_m` обчислюється як обернена швидкість:

```
τ_m = 1 / v = √(ε_r) / c

Для 10BASE5:  τ_m = 1 / (231 м/мкс) ≈ 4.33 нс/м
Для 10BASE2:  τ_m = 1 / (200 м/мкс) = 5.00 нс/м
Для UTP Cat5: τ_m = 1 / (198 м/мкс) ≈ 5.05 нс/м
```

## 2. Часова геометрія колізійного вікна (Worst-Case RTT)

Розглянемо дві граничні станції `A` та `B`, під'єднані до спільного фізичного сегмента довжиною `L`. Односторонній час проходження хвилі між ними дорівнює:

```
τ = L · τ_m
```

Аналізуємо найгірший випадок (найдовший час до виявлення конфлікту):
1. У момент часу `t = 0` станція `A` починає передачу кадру. Електромагнітна хвиля рухається по провіднику зі швидкістю `v`.
2. Сигнал досягає станції `B` у момент `t = τ`.
3. Нехай станція `B` вирішує передати власний пакет за нескінченно малий інтервал часу `ε` до приходу сигналу від `A`, тобто в момент `t = τ − ε` (де `ε → 0`).
4. Оскільки хвиля від `A` ще не досягла приймача станції `B`, функція Carrier Sense станції `B` фіксує тишу (лінія вільна), і `B` випромінює свій сигнал.
5. У точці розташування станції `B` сигнали накладаються у момент `t = τ`. Напруга або форма імпульсів спотворюється.
6. Станція `B` негайно фіксує колізію, обриває передачу даних і надсилає в лінію глушильний сигнал (Jam sequence).
7. Хвиля спотвореного сигналу та сигнал Jam повинні пройти весь зворотний шлях від `B` до `A`, що потребує ще одного інтервалу `τ`.
8. Станція `A` реєструє колізію лише в момент:

```
t_detect = (τ − ε) + τ = 2τ − ε ≈ 2τ
```

Інтервал `2τ` становить затримку подвійного обороту (англ. *Round-Trip Time*, RTT).

```
        t=0                                         t=τ-ε
Станція A [Передача кадру] -----------------------> Станція B [Слухає: тихо -> TX]
          \                                         /
           \                                       / Колізія о t=τ!
            \                                     /  B надсилає Jam
             \                                   /
              <----------------------------------
        t=2τ  A виявляє колізію!
```

### Фундаментальна умова коректності CSMA/CD

Щоб мережевий контролер станції `A` міг розпізнати, що колізія сталася саме з **його** поточним кадром, передача цього кадру повинна тривати довше, ніж час приходу зворотного фронту колізії разом із сигналом Jam та часом реакції схемотехніки:

```
T_frame ≥ 2τ_max + T_jam + T_transceiver
```

Якщо розмір кадру виявиться меншим за цей поріг (`T_frame < 2τ`), станція `A` завершить передачу, очистить апаратний буфер FIFO та вважатиме кадр успішно надісланим. Водночас отримувач відкине спотворений пакет через помилку CRC. Втрата даних на канальному рівні залишиться непоміченою, а відновлення зв'язку ляже на високорівневі таймаути транспортного рівня (наприклад, TCP), що сповільнить обмін на секунди.

## 3. Бюджет затримок для топології 10BASE5 (Правило 5-4-3)

Стандарт IEEE 802.3 встановлює граничну фізичну топологію напівдуплексного коаксіального домену за правилом **5-4-3**:
- Не більше **5 сегментів** коаксіального кабелю по 500 м кожен (загальна довжина коаксіалу `L_coax = 2500 м`);
- Не більше **4 повторювачів (репітерів)** між будь-якою парою станцій;
- Не більше **3 змішаних сегментів** із підключеними станціями (інші 2 сегменти — виключно міжкабельні перемички між репітерами);
- До **2 спускних кабелів AUI** (між картою та трансивером на кабелі) довжиною до 50 м кожен (сумарна довжина `L_aui = 100 м`).

Виведемо сумарний час подвійного обороту (RTT):

```
1. Затримка в коаксіальному кабелі (туди й назад):
   T_coax = 2 × (L_coax × τ_m_coax)
          = 2 × (2500 м × 4.33 нс/м)
          = 2 × 10 825 нс = 21.650 мкс

2. Затримка в кабелях AUI (туди й назад):
   T_aui  = 2 × (L_aui × τ_m_aui)
          = 2 × (100 м × 5.05 нс/м)
          = 2 × 505 нс = 1.010 мкс

3. Затримка обробки в 4 репітерах (регенерація форми, фазовий ретаймінг FIFO):
   Кожен репітер додає близько 1.6 мкс затримки в обидва боки:
   T_rep  = 4 × 1.600 мкс = 6.400 мкс

4. Затримка трансиверів MAU / DTE (аналоговий компаратор колізії, драйвер лінії):
   T_mau  = 3.200 мкс

5. Час випромінювання сигналу глушіння Jam (32 біти на 10 Мбіт/с):
   T_jam  = 32 біти × 100 нс/біт = 3.200 мкс

6. Запас на втрату бітів преамбули (Preamble Shrinkage), фазовий джиттер і температуру:
   T_margin = 5.700 мкс
────────────────────────────────────────────────────────────────────────
Повний розрахунковий критичний інтервал:
   T_crit = 21.650 + 1.010 + 6.400 + 3.200 + 3.200 + 5.700 = 41.160 мкс
```

Комітет IEEE 802.3 обрав із запасом еталонний квант часу — **Slot Time** (`T_slot`):

```
T_slot = 512 біт-часів = 512 × (1 / 10⁷ с) = 51.2 мкс
```

Оскільки `51.2 мкс > 41.16 мкс`, забезпечується безумовна гарантія: будь-яка колізія в межах максимально дозволеної конфігурації буде зафіксована до завершення передачі перших 512 бітів кадру.

## 4. Виведення мінімального розміру кадру

Мінімальна довжина кадру `L_min` безпосередньо випливає з тривалості часового слота `T_slot` та бітової швидкості передавача `R`:

```
L_min = T_slot × R

Для 10 Мбіт/с:
L_min = 51.2 × 10⁻⁶ с × 10⁷ біт/с = 512 бітів

L_min_bytes = 512 / 8 = 64 байти
```

Ці 64 байти включають усі поля кадру канального рівня від MAC-адреси отримувача до контрольної суми FCS (без урахування 8 байтів фізичної преамбули та SFD):

```
+---------------+---------------+-----------+-------------------+-------+
|  MAC Dst (6)  |  MAC Src (6)  | Type (2)  |   Payload (46)    |FCS (4)| = 64 байти
+---------------+---------------+-----------+-------------------+-------+
```

Якщо користувацькі дані (Payload) містять менше 46 байтів (наприклад, TCP ACK довжиною 40 байтів або порожній кадр ARP), канальний рівень MAC зобов'язаний доповнити поле корисного навантаження байтами заповнення (Padding) до мінімального розміру 46 байтів, гарантуючи сумарну довжину 64 байти.

Будь-який отриманий кадр довжиною менше 64 байтів називається **runt frame** і апаратно відкидається як залишок колізійного зіткнення.

## 5. Міжкадровий інтервал (IFG) та теоретична межа продуктивності (FPS)

Після завершення передачі кадру або глушильного сигналу Jam передавач зобов'язаний витримати обов'язкову паузу тиші — **Interframe Gap (IFG)**, або **Interpacket Gap (IPG)**.

У стандарті IEEE 802.3 тривалість IFG зафіксована на рівні **96 біт-часів**:
- На швидкості 10 Мбіт/с: `T_ifg = 96 × 100 нс = 9.6 мкс` (еквівалент 12 байтів);
- На швидкості 100 Мбіт/с: `T_ifg = 96 × 10 нс = 0.96 мкс`;
- На швидкості 1 Гбіт/с: `T_ifg = 96 × 1 нс = 96 нс`.

Фізичне призначення IFG полягає в наданні приймальним вузлам достатнього часу для:
1. Відновлення фазового автопідстроювання частоти (PLL) у мікросхемі PHY-трансивера;
2. Очищення внутрішніх буферів FIFO канального контролера;
3. Згасання паразитних електричних перехідних процесів і відбиттів у мідному кабелі.

### Розрахунок максимальної частоти кадрів (Frames Per Second — FPS)

Загальні накладні витрати на передачу одного кадру складаються з фізичної преамбули та роздільника кадру SFD (8 байтів), самого кадру (`L_frame` байтів) та міжкадрового інтервалу IFG (12 байтів):

```
L_total = 8 (Preamble + SFD) + L_frame + 12 (IFG) = L_frame + 20 байтів
```

Частота кадрів `FPS` при 100% завантаженні каналу без колізій на швидкості `R = 10 Мбіт/с` обчислюється як:

```
FPS = R / (L_total × 8)

1. Для мінімальних кадрів (L_frame = 64 байти):
   L_total = 64 + 20 = 84 байти = 672 біти
   FPS_min = 10 000 000 / 672 ≈ 14 880.95 кадрів/с

   Корисна швидкість передачі даних (Payload = 46 байтів):
   Throughput_min = 14 880.95 × (46 × 8) ≈ 5 476 190 біт/с ≈ 5.48 Мбіт/с
   (Ефективність каналу = 54.8%)

2. Для максимальних стандартних кадрів (L_frame = 1518 байтів):
   L_total = 1518 + 20 = 1538 байтів = 12 304 біти
   FPS_max = 10 000 000 / 12 304 ≈ 812.74 кадрів/с

   Корисна швидкість передачі даних (Payload = 1500 байтів):
   Throughput_max = 812.74 × (1500 × 8) ≈ 9 752 930 біт/с ≈ 9.75 Мбіт/с
   (Ефективність каналу = 97.5%)
```

## 6. Масштабування CSMA/CD при переході до Fast та Gigabit Ethernet

Співвідношення між бітовою швидкістю `R`, мінімальним кадром `L_min` та максимальною відстанню між вузлами `D_max` виражається формулою:

```
D_max ≤ (L_min / R) · (v / 2)
```

Звідси очевидно, що при фіксованому розмірі кадру `L_min = 512 бітів` збільшення бітової швидкості `R` прямо пропорційно скорочує максимальну довжину кабельної мережі.

### Fast Ethernet (100BASE-TX, 100 Мбіт/с)

При зростанні швидкості в 10 разів (`R = 100 Мбіт/с = 10⁸ біт/с`), тривалість одного біта скоротилася до `T_bit = 10 нс`.
Часовий слот зберіг значення 512 біт-часів, проте в абсолютному часі він зменшився вдесятеро:

```
T_slot = 512 × 10 нс = 5.12 мкс
```

Максимальний радіус домену колізій скоротився пропорційно:

```
D_max ≈ 5.12 мкс × (200 м/мкс / 2) ≈ 512 м  (теоретично)
```

З урахуванням затримок подвійного проходження через комутаційні повторювачі (Class I / Class II Fast Ethernet Hubs) та кабель Cat5, практичний діаметр колізійного домену 100BASE-TX обмежили відстанню **205 метрів** (максимум два сегменти по 100 метрів через один репітер класу II).

### Gigabit Ethernet (1000BASE-T, 1000 Мбіт/с) і крах напівдуплексу

При переході на швидкість 1000 Мбіт/с (`R = 10⁹ біт/с`, `T_bit = 1 нс`) збереження слота 512 бітів дало б часовий інтервал:

```
T_slot = 512 × 1 нс = 512 нс = 0.512 мкс
```

Максимальна фізична відстань між станціями за такого слота становила б:

```
D_max ≈ 0.512 мкс × (200 м/мкс / 2) ≈ 51.2 м
```

З урахуванням внутрішніх затримок трансиверів DSP PHY Gigabit Ethernet реальний радіус мережі не перевищував би **15–20 метрів**, що унеможливлювало прокладання стандартних 100-метрових ліній у будівлях.

Щоб зберегти напівдуплексний режим у стандарті IEEE 802.3z, інженери пішли на два компроміси:
1. **Carrier Extension (розширення несучої):** часовий слот штучно збільшили у 8 разів — до **4096 біт-часів** (`512 байтів` = `4.096 мкс`), що дозволило зберегти 100-метрову довжину кабелю. Якщо кадр коротший за 512 байтів, передавач після закінчення кадру продовжував утримувати лінію спеціальними символами розширення (Extension symbols).
2. **Frame Bursting (пакетне передавання):** дозволяло станції після успішного захоплення каналу передавати кілька коротких кадрів поспіль без повторного змагання за слот, заповнюючи проміжки між ними символами IFG.

Ціною Carrier Extension стало катастрофічне падіння ефективності каналу на дрібних пакетах (наприклад, 64-байтних TCP ACK):

```
Ефективність = Розмір_кадру / Розмір_слота = 64 байти / 512 байтів = 12.5%
```

Майже 87.5% пропускної здатності гігабітного каналу спалювалося на передачу порожніх символів розширення. Це стало фінальним інженерним доказом того, що механізм CSMA/CD вичерпав свій фізичний ресурс. Повнодуплексна комутація витіснила напівдуплексний CSMA/CD назавжди.

## 7. Аналітична модель пропускної здатності CSMA/CD

Ефективність використання спільного каналу в CSMA/CD залежить від безрозмірного параметра `a`, який визначає відношення часу поширення сигналу `τ` до тривалості передачі кадру `T_frame`:

```
a = τ / T_frame = (L / v) / (L_frame / R)
```

Чим менший параметр `a`, тим меншу частку часу займає вразливе вікно поширення і тим вища теоретична пропускна здатність каналу.

Згідно з класичною моделлю Тобагі та Клейнрока (Tobagi & Kleinrock), максимальна пропускна здатність (Channel Utilization) `U_max` для 1-persistent CSMA/CD при оптимальному навантаженні описується наближенням:

```
U_max ≈ 1 / (1 + 5 · a)
```

Порівняємо ефективність каналу для різних розмірів кадрів на швидкості 10 Мбіт/с при затримці `τ = 25 мкс` (`L ≈ 2500 м`):

```
1. Мінімальний кадр (64 байти = 512 бітів):
   T_frame = 512 × 100 нс = 51.2 мкс
   a       = 25 мкс / 51.2 мкс ≈ 0.488
   U_max   ≈ 1 / (1 + 5 · 0.488) = 1 / 3.44 ≈ 0.29  (29% корисної ємності)

2. Максимальний стандартний кадр (1518 байтів = 12 144 біти):
   T_frame = 12 144 × 100 нс = 1.2144 мс = 1214.4 мкс
   a       = 25 мкс / 1214.4 мкс ≈ 0.0206
   U_max   ≈ 1 / (1 + 5 · 0.0206) = 1 / 1.103 ≈ 0.906 (90.6% корисної ємності)
```

Цей розрахунок демонструє, чому передача великих кадрів у спільній шині Ethernet була критично вигіднішою: довгий кадр амортизує накладні витрати на арбітраж колізійного вікна `2τ`.

## 8. Ймовірнісний розбір Truncated Binary Exponential Backoff (BEB)

Після виявлення колізії станція обирає випадкове число слотів `r` з дискретного рівномірного розподілу:

```
r ∈ {0, 1, 2, ..., W_k − 1}

де W_k = 2^k,  k = min(n, 10),  n — номер поточної спроби (1 ≤ n ≤ 16)
```

Математичне сподівання часу затримки на `n`-й спробі становить:

```
E[T_backoff(n)] = E[r] · T_slot
                = ((W_k − 1) / 2) · T_slot
                = ((2^(min(n, 10)) − 1) / 2) · 51.2 мкс
```

Дисперсія випадкової затримки:

```
Var[r] = (W_k² − 1) / 12 = (4^k − 1) / 12

Var[T_backoff(n)] = ((4^(min(n, 10)) − 1) / 12) · (51.2 мкс)²
```

### Ймовірність колізії при змаганні N станцій

Нехай `N` станцій одночасно претендують на доступ до каналу і мають однаковий розмір вікна `W`. Кожна станція обирає слот `s ∈ [0, W − 1]` з імовірністю `p = 1 / W`.

Ймовірність того, що в конкретному слоті відбудеться успішна передача (рівно одна станція обрала цей слот), становить:

```
P_success = C(N, 1) · p¹ · (1 − p)^(N − 1)
          = N · (1 / W) · (1 − 1 / W)^(N − 1)
```

Ймовірність колізії в слоті (дві або більше станцій обрали один і той самий слот за умови, що слот не порожній):

```
P_idle      = (1 − 1 / W)^N
P_collision = 1 − P_idle − P_success
            = 1 − (1 − 1 / W)^N − (N / W) · (1 − 1 / W)^(N − 1)
```

При високій щільності станцій `N` і малому вікні `W` (наприклад, `N = 10`, `W = 2` після першої колізії):

```
P_idle      = (1 − 1/2)¹⁰ = (0.5)¹⁰ ≈ 0.00098
P_success   = 10 · (1/2) · (1/2)⁹ = 10 · (0.5)¹⁰ ≈ 0.00977
P_collision = 1 − 0.00098 − 0.00977 = 0.98925 (98.9% ймовірність повторної колізії!)
```

Саме тому показник `k` повинен швидко зростати: при `W = 16` (`k = 4`):

```
P_success = 10 · (1/16) · (15/16)⁹ ≈ 0.625 · 0.559 ≈ 0.349 (34.9% успіху)
```

Алгоритм BEB діє як динамічний стохастичний стабілізатор: він збільшує вікно `W` пропорційно навантаженню доти, доки `W` не зрівняється з порядком кількості активних станцій `N`, виводячи систему на оптимальну ймовірність успішного вибору слота `~ 1/e ≈ 36.8%`.

### Марковський процес станів станції

Процес повторних передач станції моделюється дискретним ланцюгом Маркова зі станами `S_0, S_1, ..., S_{16}`, де стан `S_n` відповідає `n`-й спробі передачі. Ймовірність успішного переходу зі стану `S_n` у початковий стан `S_0` (скидання лічильника після успіху) дорівнює `1 − p_c(n)`, де `p_c(n)` — ймовірність колізії на `n`-му кроці.

Середня кількість спроб до успішного відправлення кадру `E[N_attempts]` обчислюється як сума ряду:

```
E[N_attempts] = 1 + ∑_{n=1}^{15} ∏_{i=1}^{n} p_c(i)
```

При помірному навантаженні (`p_c ≈ 0.1`) `E[N_attempts] ≈ 1 + 0.1 + 0.01 ≈ 1.11` спроби на кадр, що забезпечує мінімальні затримки доставки. Під критичним навантаженням (`p_c > 0.7`) значення `E[N_attempts]` стрімко наближається до 16, викликаючи лавиноподібне зростання затримок та скидання пакетів у стані `S_{16}`.

## 9. Математика пізніх колізій (Late Collisions) та невідповідності дуплексу

Пізня колізія (англ. *Late Collision*) — це аварійний стан, за якого колізійне зіткнення детектується мережевою картою **після** відправки перших 512 бітів (64 байтів) кадру:

```
t_detect > T_slot = 51.2 мкс  (або > 64 передані байти)
```

У логіці IEEE 802.3 канальний рівень MAC розглядає перші 64 байти як транзакцію арбітражу слота. Якщо перші 64 байти вийшли в дріт без колізії, MAC вважає, що канал надійно захоплено, скидає лічильник колізій `n = 0` і передає решту байтів кадру в потоковому режимі.

Якщо на 65-му або 500-му байті виникає пізня колізія, поведінка MAC відрізняється від звичайної:
1. MAC **НЕ** здійснює автоматичного відкату за алгоритмом BEB і **НЕ** перевідправляє кадр;
2. MAC негайно припиняє передачу, викидає пошкоджений залишок і встановлює апаратний прапорець помилки `Late Collision` у дескрипторі DMA;
3. Кадр безповоротно втрачається на рівні L2.

Математично пізня колізія виникає у двох випадках:
- Фізична довжина кабелю перевищує критичну: `2τ_cable > T_slot` (наприклад, довжина сегмента 10BASE2 становить 400 м замість 185 м);
- **Duplex Mismatch (невідповідність дуплексу):** станція `X` налаштована на Full-Duplex (передає будь-коли без перевірки Carrier Sense), а станція `Y` — на Half-Duplex (використовує CSMA/CD). Коли станція `Y` надсилає довгий кадр (1500 байтів), станція `X` посеред прийому починає власну передачу в будь-який момент `t_x ∈ [0, T_frame]`. Якщо `t_x > 51.2 мкс`, станція `Y` фіксує незворотну пізню колізію з імовірністю:

```
P_late = (T_frame − T_slot) / T_frame = (1518 − 64) / 1518 ≈ 95.8%
```

Майже 96% зіткнень при невідповідності дуплексу класифікуються як пізні колізії, викликаючи масове непомітне для L2 скидання пакетів і падіння швидкості TCP до лічених кілобітів на секунду.
