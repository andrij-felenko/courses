# 🧮 Виведення формули Поллачека–Хінчина та вплив варіації розміру пакетів

Математичне виведення середньої затримки в системі масового обслуговування `M/G/1` через залишковий час передачі, що доводить фундаментальну залежність черги від дисперсії довжини пакетів і пояснює, чому суміш дрібних службових та великих корисних пакетів створює значно більші затримки, ніж передбачає проста експоненційна модель.

### Постановка задачі для системи M/G/1

У класичній моделі комутатора або маршрутизатора пакети надходять на вхідний мережевий інтерфейс у випадкові моменти часу, утворюючи Пуассонівський потік з інтенсивністю `λ` (пакетів за секунду). Це означає, що інтервали часу між послідовними надходженнями пакетів є незалежними випадковими величинами, розподіленими за експоненційним законом із середнім значенням `1 / λ`.

Вихідний інтерфейс має фіксовану бітову швидкість `C` (біт/с). Час передачі пакета `S` (тривалість обслуговування, від англ. *service time*) безпосередньо пропорційний його довжині в байтах `L_p`:

```
S = (L_p · 8) / C
```

На відміну від спрощеної моделі `M/M/1`, де розмір пакета вважається експоненційно розподіленим, у реальній мережі розмір пакета має довільний загальний розподіл (позначається літерою `G` — *General*). Ми характеризуємо тривалість обслуговування `S` двома статистичними моментами:

1. Математичним сподіванням (середнім часом передачі одного пакета):

```
E[S] = 1 / μ
```

де `μ` — середня інтенсивність обслуговування (пакетів за секунду).

2. Дисперсією тривалості передачі:

```
Var(S) = σ² = E[S²] - (E[S])²
```

Коефіцієнт завантаження каналу зв'язку (частка часу, протягом якого передавач зайнятий) визначається відношенням:

```
ρ = λ · E[S] = λ / μ
```

Для існування стаціонарного режиму черги (щоб довжина черги не зростала необмежено до нескінченності) вимагається виконання умови `ρ < 1`.

### Доведення закону Літтла через інтеграли траєкторій

Перш ніж аналізувати формулу Поллачека–Хінчина, доведемо закон Літтла `L = λ · W`, на який спирається вся подальша алгебра черг.

Розглянемо систему масового обслуговування на інтервалі часу `[0, T]`. Нехай:
- `A(t)` — кількість пакетів, що надійшли в систему до моменту `t`;
- `D(t)` — кількість пакетів, що повністю обслуговані й покинули систему до моменту `t`;
- `N(t) = A(t) - D(t)` — кількість пакетів, що перебувають у системі в момент часу `t`.

Сумарний час, проведений усіма пакетами в системі за час `T`, являє собою інтеграл від ступінчастої функції кількості пакетів `N(t)`:

```
Area(T) = ∫ N(t) dt      [інтеграл від 0 до T]
```

З іншого боку, якщо `W_i` — це час перебування `i`-го пакета в системі, то для всіх `M(T)` пакетів, що завершили обслуговування за час `T`, та сама площа під графіком дорівнює сумі індивідуальних часів затримки:

```
Area(T) = ∑ W_i          [сума для i від 1 до M(T)]
```

Прирівнюючи обидва вирази та ділячи їх на загальний час спостереження `T`:

```
(1 / T) · ∫ N(t) dt = (M(T) / T) · (1 / M(T)) · ∑ W_i
```

При переході до границі `T → ∞`:
1. Ліва частина `(1 / T) · ∫ N(t) dt` за ергодичною теоремою збігається до часового середнього кількості пакетів у системі `L`.
2. Відношення `M(T) / T` збігається до середньої інтенсивності надходження пакетів `λ`.
3. Вибіркове середнє `(1 / M(T)) · ∑ W_i` збігається до середнього часу перебування пакета в системі `W`.

Отримуємо строге співвідношення:

```
L = λ · W
```

Аналогічно, якщо інтегрувати лише кількість пакетів, що очікують у черзі буфера `N_q(t)`, площа під графіком дорівнює сумі часів очікування `∑ W_{q,i}`, що дає закон Літтла для черги:

```
L_q = λ · W_q
```

### Парадокс інспекції та залишковий час передачі

Коли новий пакет прибуває у випадковий момент часу `t`, він застає передавач у зайнятому стані з імовірністю `ρ`. Якщо лінія зайнята, новому пакету необхідно зачекати завершення передачі поточного кадру. Цей залишок часу називається **залишковим часом обслуговування `R`** (*residual service time*).

Тут виникає відомий у теорії ймовірностей **парадокс інспекції** (парадокс часу очікування): випадковий момент надходження пакета з більшою ймовірністю потрапляє всередину тривалого інтервалу передачі (великого кадру на 1500 байтів), ніж усередину короткого інтервалу (малого ACK на 64 байти).

Нехай `f_S(t)` — функція густини розподілу тривалості передачі пакета. Імовірність того, що точка прибуття потрапить у пакет тривалістю `t`, пропорційна не просто частоті появи таких пакетів `f_S(t)`, а їхній сумарній тривалості `t · f_S(t)`.

Густина ймовірності тривалості інтервалу, в який потрапив спостерігач:

```
f_hit(t) = [ t · f_S(t) ] / E[S]
```

Оскільки точка прибуття випадково (рівномірно) ділить цей інтервал навпіл, умовне математичне сподівання залишку часу за умови, що тривалість поточного кадру дорівнює `t`, становить `t / 2`.

Інтегруючи за всіма можливими тривалостями пакетів `t`, отримуємо безумовне математичне сподівання залишкового часу `E[R]`:

```
E[R] = ∫ (t / 2) · f_hit(t) dt
     = ∫ (t / 2) · [ t · f_S(t) / E[S] ] dt
     = [ 1 / (2 · E[S]) ] · ∫ t² · f_S(t) dt
     = E[S²] / (2 · E[S])
```

Оскільки ймовірність того, що лінія взагалі зайнята в момент надходження, дорівнює `ρ = λ · E[S]`, середній залишковий час у будь-який довільний момент (з урахуванням імовірності застати лінію вільною, коли `R = 0`) становить:

```
E[R_total] = ρ · E[R] = (λ · E[S]) · [ E[S²] / (2 · E[S]) ] = (1 / 2) · λ · E[S²]
```

Це строге виведення підтверджує результат геометричного підрахунку через площу трикутників.

### Компоненти часу очікування нового пакета

Розглянемо довільний пакет, який надходить до буфера маршрутизатора в довільний момент часу `t`. Нехай `W_q` — випадкова величина часу очікування цього пакета в черзі до початку його безпосередньої передачі на фізичну лінію.

Час очікування `W_q` складається з двох незалежних частин:
1. Залишковий час обслуговування `R`, якщо лінія зайнята;
2. Сумарний час передачі всіх `N_q` пакетів, що вже стоять у черзі перед новим пакетом: `N_q · E[S]`.

Беручи математичне сподівання від обох частин:

```
E[W_q] = E[R_total] + E[N_q] · E[S]
```

Застосовуючи закон Літтла `E[N_q] = λ · E[W_q]`:

```
E[W_q] = E[R_total] + λ · E[W_q] · E[S]
E[W_q] = E[R_total] + ρ · E[W_q]
```

Переносячи члени:

```
E[W_q] · (1 - ρ) = E[R_total]
E[W_q] = E[R_total] / (1 - ρ)
```

Підставляючи `E[R_total] = (1 / 2) · λ · E[S²]`:

```
E[W_q] = (λ · E[S²]) / (2 · (1 - ρ))
```

Оскільки за означенням дисперсії `E[S²] = (E[S])² + Var(S) = (1 / μ)² + σ²`:

```
E[W_q] = (λ · [ (1 / μ)² + σ² ]) / (2 · (1 - ρ))
```

Це і є класична **формула Поллачека–Хінчина** для середнього часу очікування в черзі системи `M/G/1`.

### Перетворення через коефіцієнт варіації C_v

Щоб виразити формулу через безрозмірний коефіцієнт варіації розміру пакетів, уведемо параметр `C_v` (коефіцієнт варіації випадкової величини `S`):

```
C_v = σ / E[S] = σ · μ
σ² = C_v² / μ²
```

Підставляючи `σ² = C_v² / μ²` у формулу:

```
E[W_q] = (λ · [ 1/μ² + C_v²/μ² ]) / (2 · (1 - ρ))
       = (λ / μ²) · (1 + C_v²) / (2 · (1 - ρ))
       = (λ / μ) · (1 / μ) · (1 + C_v²) / (2 · (1 - ρ))
       = (ρ / (1 - ρ)) · [ (1 + C_v²) / 2 ] · (1 / μ)
```

Застосовуючи закон Літтла `L_q = λ · E[W_q]`, знаходимо середню кількість пакетів, що очікують у черзі буфера:

```
L_q = (ρ² / (1 - ρ)) · [ (1 + C_v²) / 2 ]
```

Повний середній час перебування пакета у вузлі зв'язку `W` (час очікування в черзі плюс час передачі на лінії) дорівнює:

```
W = E[W_q] + E[S] = E[W_q] + (1 / μ)
```

А повна середня кількість пакетів у вузлі (в буфері та на передавачі) за законом Літтла `L = λ · W`:

```
L = L_q + ρ = ρ + (ρ² / (1 - ρ)) · [ (1 + C_v²) / 2 ]
```

### Перетворення Лапласа–Стілтьєса для розподілу затримки

Формула Поллачека–Хінчина визначає не лише перше математичне сподівання `E[W_q]`, а й повне перетворення Лапласа–Стілтьєса функції розподілу часу очікування `W_q^*(s) = E[e^(-s · W_q)]`:

```
W_q^*(s) = [ (1 - ρ) · s ] / [ s - λ + λ · S^*(s) ]
```

де `S^*(s) = E[e^(-s · S)]` — перетворення Лапласа–Стілтьєса розподілу тривалості передачі пакета.

Диференціюючи `W_q^*(s)` за `s` у точці `s = 0`, можна отримати будь-який момент часу очікування. Зокрема, другий момент часу очікування в черзі дорівнює:

```
E[W_q²] = 2 · (E[W_q])² + [ λ · E[S³] ] / [ 3 · (1 - ρ) ]
```

Цей вираз показує, що дисперсія часу затримки `Var(W_q) = E[W_q²] - (E[W_q])²` залежить уже від **третього моменту** довжини пакетів `E[S³]`. Для важкохвостих розподілів розміру пакетів (де третій момент може бути гігантським), дисперсія затримки (джиттер) зростає набагато швидше, ніж саме середнє значення затримки.

### Тривалість періоду зайнятості сервера (Busy Period)

Важливою характеристикою роботи мережевого інтерфейсу є випадкова тривалість **періоду зайнятості `B`** (*busy period*) — інтервалу часу від моменту надходження пакета в порожній буфер до моменту, коли передавач повністю передасть усі накопичені пакети й знову спорожніє.

За рівнянням Кендалла–Такача для системи `M/G/1` середнє значення та дисперсія періоду зайнятості мають вигляд:

```
E[B] = E[S] / (1 - ρ) = 1 / [ μ · (1 - ρ) ]
Var(B) = [ σ² + ρ · (E[S])² ] / (1 - ρ)³
```

Зверніть увагу на знаменник дисперсії: `(1 - ρ)³`. Це означає, що коли коефіцієнт завантаження каналу наближається до 1 (`ρ → 1`), період безперервної зайнятості буфера стає надзвичайно варіативним. Замість регулярних коротких пачок виникають рідкісні, але гігантські інтервали безперервної роботи тривалістю в секунди, протягом яких буфер залишається постійно заповненим.

### Модель з періодами сну передавача (Server Vacations / Green Ethernet)

У сучасних енергоефективних комутаторах стандарту IEEE 802.3az (Energy-Efficient Ethernet) передавач вимикає живлення підсилювачів, коли черга порожня, переходячи в режим сну на випадковий час `V` (тривалість відпустки сервера, *vacation time*).

Якщо за час сну надходять нові пакети, передавачу потрібен час на прокидання. За теоремою декомпозиції Фохама для черг із відпустками `M/G/1 with vacations`, середній час очікування пакета складається зі стандартного часу очікування M/G/1 та залишкового часу сну передавача:

```
W_q(vacation) = W_q(M/G/1) + E[V²] / (2 · E[V])
```

Це доводить, що заходи з енергозбереження фізичного рівня каналу (EEE) додають детермінований зсув затримки `E[V²] / (2 · E[V])`, який необхідно враховувати в розрахунках буферів для критичних промислових мереж (TSN / Profinet).

### Важкохвості розподіли (Парето) та самоподібний трафік

У реальних глобальних мережах трафік часто виявляє властивість **самоподібності** (*self-similarity*) та важких хвостів (heavy-tailed distributions). Якщо розміри переданих файлів підпорядковуються розподілу Парето з функцією виживання `P(S > t) = (k / t)^α`, де показник форми лежить у діапазоні `1 < α < 2`:

- Математичне сподівання `E[S]` є скінченним;
- Проте другий момент `E[S²] = ∞` і дисперсія `σ² = ∞`.

Підставляючи нескінченний другий момент у формулу Поллачека–Хінчина, отримуємо фундаментальний висновок:

```
E[W_q] = (λ · ∞) / (2 · (1 - ρ)) = ∞
```

Це означає, що за наявності важкохвостого трафіку навіть при помірному середньому завантаженні (наприклад, `ρ = 0.5`) черга в буфері не стабілізується навколо фіксованого середнього значення. Збільшення розміру буфера в таких умовах не зменшує втрати пакетів, а лише безмежно збільшує затримку. Це є математичним доказом того, чому традиційний Tail Drop принципово не здатен стабілізувати інтернет-трафік без активного регулювання (AQM).

### Порівняльний аналіз пріоритетних черг (Формула Кобхема)

Якщо на інтерфейсі реалізовано пріоритетне планування без витіснення (Non-preemptive Priority Queuing) для `P` класів трафіку (де клас 1 має найвищий пріоритет, а клас `P` — найнижчий), середня затримка для `k`-го класу за формулою Кобхема становить:

```
W_{q,k} = E[R_total] / [ (1 - σ_{k-1}) · (1 - σ_k) ]
```

де `σ_k = ∑ ρ_i` (сума завантажень для класів від 1 до `k`, причому `σ_0 = 0`).

Для високопріоритетного трафіку (`k = 1`):

```
W_{q,1} = E[R_total] / (1 - ρ_1)
```

Високопріоритетні пакети (голос, керування) відчувають затримку лише від свого класу `ρ_1` та залишкового часу поточного низькопріоритетного пакета `E[R_total]`, але не стоять позаду черги завантаження файлів.

### Порівняльний аналіз розподілів пакетного трафіку

Множник `(1 + C_v²) / 2` у формулі Поллачека–Хінчина є коефіцієнтом масштабування черги відносно дисперсії довжин пакетів. Порівняємо п'ять характерних класів розподілів мережевих потоків:

```
1. Детермінований час передачі (M/D/1, фіксований розмір пакетів):
   σ² = 0  ⇒  C_v = 0
   Множник = (1 + 0) / 2 = 0.50
   W_q(M/D/1) = 0.50 · (ρ / (1 - ρ)) · (1 / μ)
   L_q(M/D/1) = 0.50 · (ρ² / (1 - ρ))

2. Розподіл Ерланга порядку k = 2 (E₂ / середня варіативність):
   σ² = 1 / (2 · μ²)  ⇒  C_v = 1 / √2 ≈ 0.707
   Множник = (1 + 0.5) / 2 = 0.75
   W_q(M/E₂/1) = 0.75 · (ρ / (1 - ρ)) · (1 / μ)
   L_q(M/E₂/1) = 0.75 · (ρ² / (1 - ρ))

3. Експоненційний розмір пакетів (M/M/1):
   σ = E[S] = 1/μ  ⇒  C_v = 1.00
   Множник = (1 + 1) / 2 = 1.00
   W_q(M/M/1) = 1.00 · (ρ / (1 - ρ)) · (1 / μ)
   L_q(M/M/1) = 1.00 · (ρ² / (1 - ρ))

4. Бімодальний реальний Інтернет-трафік (суміш 64-байтних ACK та 1500-байтних MTU):
   C_v ≈ 1.80  ⇒  C_v² = 3.24
   Множник = (1 + 3.24) / 2 = 2.12
   W_q(M/G/1) = 2.12 · (ρ / (1 - ρ)) · (1 / μ)
   L_q(M/G/1) = 2.12 · (ρ² / (1 - ρ))

5. Важкохвостий пачковий трафік (розподіл Парето / самоподібний веб-трафік):
   C_v = 2.50  ⇒  C_v² = 6.25
   Множник = (1 + 6.25) / 2 = 3.625
   W_q(M/G/1) = 3.625 · (ρ / (1 - ρ)) · (1 / μ)
   L_q(M/G/1) = 3.625 · (ρ² / (1 - ρ))
```

### Персентилі затримки та небезпека важких хвостів

Математичне сподівання `E[W_q]` дає лише середню затримку, але для чутливих додатків (голосовий зв'язок VoIP, відеоконференції, тактильне керування дронами) критичними є **персентилі затримки** — 95-й та 99-й персентилі (хвости розподілу).

Для експоненційного часу обслуговування (система `M/M/1`) функція розподілу часу очікування в черзі має вигляд:

```
P(W_q ≤ t) = 1 - ρ · e^(-μ · (1 - ρ) · t)
```

Звідси `p`-й персентиль часу очікування `t_p` (час, який не перевищується з імовірністю `p`):

```
t_p = [ ln(ρ / (1 - p)) ] / [ μ · (1 - ρ) ]
```

Для каналу із середнім часом передачі `1/μ = 6` мкс та завантаженням `ρ = 0.85`:
- Середній час у черзі: `E[W_q] = 34` мкс.
- 95-й персентиль (`p = 0.95`): `t_{0.95} = [ ln(0.85 / 0.05) ] / [ (1/6) · 0.15 ] = ln(17) / 0.025 ≈ 2.833 / 0.025 = 113.3` мкс (у 3.3 раза більше за середнє!).
- 99-й персентиль (`p = 0.99`): `t_{0.99} = [ ln(0.85 / 0.01) ] / [ (1/6) · 0.15 ] = ln(85) / 0.025 ≈ 4.443 / 0.025 = 177.7` мкс (у 5.2 раза більше за середнє!).

Для систем `M/G/1` із важкохвостими розподілами розміру пакетів (де `C_v > 1`) хвіст затримки спадає не експоненційно, а степенево. Це означає, що 99-й персентиль затримки в реальних мережах може перевищувати середнє значення у 10–20 разів, що призводить до раптових джиттер-стрибків (*latency spikes*), якщо черги не контролюються алгоритмами активного керування (AQM).

### Мультиплексування кількох незалежних потоків

Розглянемо практичний випадок, коли на один вихідний порт маршрутизатора надходять `N` незалежних Пуассонівських потоків із власними інтенсивностями `λ_i` та характеристиками розміру пакетів `(E[S_i], E[S_i²])`.

Сумарний вхідний потік також є Пуассонівським із сумарною інтенсивністю:

```
λ_total = ∑ λ_i
```

Перший та другий моменти тривалості обслуговування сумарного змішаного потоку обчислюються як зважені середні за частками інтенсивностей `α_i = λ_i / λ_total`:

```
E[S_total] = ∑ [ (λ_i / λ_total) · E[S_i] ]
E[S_total²] = ∑ [ (λ_i / λ_total) · E[S_i²] ]
```

Підсумковий коефіцієнт завантаження:

```
ρ_total = λ_total · E[S_total] = ∑ ρ_i
```

Підставляючи ці значення у формулу Поллачека–Хінчина, отримуємо середній час очікування для будь-якого пакета в об'єднаній черзі:

```
W_q = [ ∑ (λ_i · E[S_i²]) ] / [ 2 · (1 - ρ_total) ]
```

Цей результат підкреслює важливу властивість черг FIFO: **один потік із великими пакетами та високою дисперсією погіршує час очікування для всіх інших потоків**, які мультиплексуються в ту саму чергу, навіть якщо їхні власні пакети є дрібними та регулярними. Це є головною математичною мотивацією переходу від спільних черг FIFO до роздільних черг у Fair Queuing (FQ-CoDel / CAKE).

### Розрахунок числового прикладу для гігабітного каналу

Розглянемо вихідний інтерфейс комутатора зі швидкістю каналу `C = 1` Гбіт/с (`10⁹` біт/с), на який надходить трафік із середнім розміром пакета `L_avg = 750` байтів (`6000` бітів) при коефіцієнті завантаження лінії `ρ = 0.85` (інтенсивність `λ = 141 667` пакетів/с).

Середній час передачі одного пакета:

```
1 / μ = 6000 / 10⁹ = 6.0 мкс
```

Обчислимо середній час очікування пакета в буфері для трьох різних варіантів розподілу довжини:

```
Базовий множник завантаження:
ρ / (1 - ρ) = 0.85 / (1 - 0.85) = 0.85 / 0.15 ≈ 5.667

1. Для M/D/1 (усі пакети рівно по 750 байтів):
   W_q = 5.667 · 0.5 · 6.0 мкс = 17.0 мкс
   L_q = 141 667 · 17.0 · 10⁻⁶ ≈ 2.41 пакета

2. Для M/M/1 (експоненційний розподіл довжин):
   W_q = 5.667 · 1.0 · 6.0 мкс = 34.0 мкс
   L_q = 141 667 · 34.0 · 10⁻⁶ ≈ 4.82 пакета

3. Для реального Інтернет-трафіку (C_v = 1.8):
   W_q = 5.667 · 2.12 · 6.0 мкс = 72.1 мкс
   L_q = 141 667 · 72.1 · 10⁻⁶ ≈ 10.21 пакета
```

Цей числовий розрахунок наочно демонструє, що ігнорування дисперсії розміру пакетів у мережевому плануванні призводить до недооцінки затримки в буферах у понад два рази.
