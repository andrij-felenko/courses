# ⚙️ Імітаційне моделювання: комутація каналів проти комутації пакетів

Імітаційне моделювання на основі дискретних подій (*Discrete-Event Simulation*) дозволяє безпосередньо виміряти поведінку комутації каналів і комутації пакетів під однаковим навантаженням. У цьому проекті реалізовано повноцінний симулятор, який зіставляє коефіцієнт утилізації каналу, частку втрат і блокування, затримку та джитер для обох парадигм при обслуговуванні пулу імпульсних джерел трафіку.

### Постановка задачі та модель навантаження

При проектуванні телекомунікаційних мереж аналітичні формули теорії черг дають точні результати лише для найпростіших припущень (пуассонівські потоки, експоненційний час обслуговування, нескінченні буфери). У реальних мережах поведінка трафіку формується взаємодією багатьох незалежних стохастичних джерел із кінцевими буферами та нелінійними ефектами переповнення.

Для порівняльного експерименту побудуємо модель спільного вихідного інтерфейсу, до якого підключено групу незалежних користувачів. Кожен користувач чергує фази активної передачі даних (сплески) та фази бездіяльності (паузи):

```
+─────────────────────────────────────────────────────────────────────────────+
|                         ГЕНЕРАТОР НАВАНТАЖЕННЯ                              |
|           35 незалежних джерел (10% активності, ON/OFF розподіл)            |
+──────────────────────────────────────┬──────────────────────────────────────+
                                       │
            ┌──────────────────────────┴──────────────────────────┐
            ▼                                                     ▼
+───────────────────────────────+     +───────────────────────────────────────+
|      КОМУТАЦІЯ КАНАЛІВ        |     |          КОМУТАЦІЯ ПАКЕТІВ            |
| • 10 виділених каналів TDM    |     | • Спільний канал 10 Мбіт/с            |
| • Резервування 1 Мбіт/с / сес |     | • FIFO буфер черги (50 пакетів)       |
| • Блокування при нестачі ліній|     | • Store-and-Forward обслуговування    |
+───────────────────────────────+     +───────────────────────────────────────+
```

Спільні параметри імітаційного експерименту:
- Пропускна здатність спільної магістралі: `C = 10 000 000` біт/с (10 Мбіт/с).
- Пікова швидкість одного активного джерела: `R = 1 000 000` біт/с (1 Мбіт/с).
- Кількість підключених джерел: `N = 35`.
- Модель джерела (двостанковий марковський процес ON-OFF):
  - Стан **ON** (передача даних на піковій швидкості `R`): тривалість є випадковою величиною з експоненційним розподілом із середнім значенням `T_on = 0.2` с.
  - Стан **OFF** (пауза, читання інформації): тривалість є експоненційною випадковою величиною із середнім значенням `T_off = 1.8` с.
  - Коефіцієнт активності джерела: `p = T_on / (T_on + T_off) = 0.2 / (0.2 + 1.8) = 0.1` (10%).
- Розмір пакетів: фіксований `L = 1000` байтів (8000 бітів).
- Інтервал між пакетами від одного активного джерела: `t_gap = 8000 / 1 000 000 = 8` мс (125 пакетів/с).
- Час передачі одного пакета в 10-мегабітний канал: `t_tx = 8000 / 10 000 000 = 0.8` мс.
- Місткість буфера пакетокомутатора: `B = 50` пакетів (50 000 байтів оперативної пам'яті).
- Тривалість симуляції: `100.0` секунд реального мережевого часу.

### Генерація експоненційних інтервалів часу

Для моделювання випадкових інтервалів між подіями застосовується метод зворотного перетворення функції розподілу (*Inverse Transform Sampling*). Для показникового закону із середнім значенням `1 / λ = T_mean` функція накопиченої ймовірності має вигляд:

```
F(t) = 1 - e^(-λ · t)
```

Прирівнюючи `F(t)` до випадкового числа `U`, рівномірно розподіленого на відкритому інтервалі `(0, 1)`, та розв'язуючи відносно `t`, отримуємо формулу генератора:

```
1 - e^(-λ · t) = U
e^(-λ · t) = 1 - U
-λ · t = ln(1 - U)
t = - (1 / λ) · ln(1 - U) = - T_mean · ln(U')
```

де `U' = 1 - U` також має рівномірний розподіл на інтервалі `(0, 1)`.

### Архітектура імітаційного двигуна

Існує два основні підходи до побудови симуляторів дискретних подій:
1. **Підхід із фіксованим кроком часу (Time-Stepping)**: глобальний годинник зміщується на постійний квант `dt` (наприклад, 100 мікросекунд). На кожному кроці перевіряються всі джерела та черги. Перевага підходу — простота коду, легкість синхронізації паралельних потоків та пряма відповідність апаратним тактовим реєстрам комутаторів.
2. **Підхід на основі черги подій (Event-Driven Simulation)**: симулятор підтримує пріоритетну чергу майбутніх подій (наприклад, `SOURCE_ON`, `SOURCE_OFF`, `PACKET_ARRIVE`, `PACKET_DEPART`) на базі двійкової купи (*Min-Heap*). Годинник миттєво стрибає вперед до найближчої події. Перевага — висока продуктивність на розріджених моделях, оскільки час простою не симулюється крок за кроком.

У наведеній реалізації застосовано гібридний детермінований крок `dt = 100` мкс, що забезпечує високу точність (у 8 разів менше за час передачі найкоротшого пакета 0.8 мс) та максимальну наочність внутрішнього стану системи.

### Реалізація симулятора на C та C++

Програма моделює обидві комутаційні системи в паралельному часовому циклі, обробляючи зміну станів джерел, розподіл фізичних таймслотів TDM та проходження черги буфера Store-and-Forward.

#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <math.h>
#include <string.h>

#define MAX_SOURCES 100
#define QUEUE_CAPACITY 200

typedef struct {
    double time_on_mean;
    double time_off_mean;
    double peak_rate_bps;
    bool is_on;
    double next_state_change;
    double session_end_time;
    int channel_id;
    double last_packet_time;
} Source;

typedef struct {
    double arrival_time;
    int source_id;
} Packet;

typedef struct {
    Packet buffer[QUEUE_CAPACITY];
    int head;
    int tail;
    int count;
    int max_capacity;
} PacketQueue;

static void queue_init(PacketQueue *q, int cap) {
    q->head = 0;
    q->tail = 0;
    q->count = 0;
    q->max_capacity = cap;
}

static bool queue_push(PacketQueue *q, Packet pkt) {
    if (q->count >= q->max_capacity) return false;
    q->buffer[q->tail] = pkt;
    q->tail = (q->tail + 1) % q->max_capacity;
    q->count++;
    return true;
}

static bool queue_pop(PacketQueue *q, Packet *out) {
    if (q->count == 0) return false;
    *out = q->buffer[q->head];
    q->head = (q->head + 1) % q->max_capacity;
    q->count--;
    return true;
}

static double rand_exp(double mean) {
    double u = ((double)rand() + 1.0) / ((double)RAND_MAX + 1.0);
    return -mean * log(u);
}

int main(void) {
    srand(42);

    const double sim_duration = 100.0; /* 100 секунд симуляції */
    const double dt = 0.0001;          /* Крок симуляції: 100 мкс */
    const double link_capacity_bps = 10000000.0; /* 10 Мбіт/с */
    const double peak_rate_bps = 1000000.0;       /* 1 Мбіт/с на джерело */
    const int num_sources = 35;
    const int num_circuits = (int)(link_capacity_bps / peak_rate_bps); /* 10 каналів */
    const int packet_size_bits = 8000; /* 1000 байтів */
    const double packet_interval = (double)packet_size_bits / peak_rate_bps; /* 8 мс */
    const double packet_tx_time = (double)packet_size_bits / link_capacity_bps; /* 0.8 мс */

    /* Ініціалізація джерел */
    Source sources[MAX_SOURCES];
    for (int i = 0; i < num_sources; i++) {
        sources[i].time_on_mean = 0.2;
        sources[i].time_off_mean = 1.8;
        sources[i].peak_rate_bps = peak_rate_bps;
        sources[i].is_on = false;
        sources[i].next_state_change = rand_exp(sources[i].time_off_mean);
        sources[i].session_end_time = 0.0;
        sources[i].channel_id = -1;
        sources[i].last_packet_time = 0.0;
    }

    /* Стан комутації каналів */
    bool circuit_busy[MAX_SOURCES];
    memset(circuit_busy, 0, sizeof(circuit_busy));
    long circuit_requests_total = 0;
    long circuit_requests_blocked = 0;
    double circuit_bits_transferred = 0.0;

    /* Стан комутації пакетів */
    PacketQueue pkt_queue;
    queue_init(&pkt_queue, 50);
    long packets_generated = 0;
    long packets_dropped = 0;
    long packets_served = 0;
    double total_packet_delay = 0.0;
    double total_packet_delay_sq = 0.0;
    double packet_server_busy_until = 0.0;
    double packet_bits_transferred = 0.0;

    for (double t = 0.0; t < sim_duration; t += dt) {
        /* 1. Оновлення джерел та генерація подій */
        for (int i = 0; i < num_sources; i++) {
            if (t >= sources[i].next_state_change) {
                if (!sources[i].is_on) {
                    /* Перехід у стан ON */
                    sources[i].is_on = true;
                    double duration = rand_exp(sources[i].time_on_mean);
                    sources[i].next_state_change = t + duration;
                    sources[i].session_end_time = t + duration;
                    sources[i].last_packet_time = t;

                    /* Спроба виділення каналу в Circuit Switching */
                    circuit_requests_total++;
                    int free_ch = -1;
                    for (int ch = 0; ch < num_circuits; ch++) {
                        if (!circuit_busy[ch]) {
                            free_ch = ch;
                            break;
                        }
                    }
                    if (free_ch != -1) {
                        circuit_busy[free_ch] = true;
                        sources[i].channel_id = free_ch;
                    } else {
                        sources[i].channel_id = -1;
                        circuit_requests_blocked++;
                    }
                } else {
                    /* Перехід у стан OFF */
                    sources[i].is_on = false;
                    sources[i].next_state_change = t + rand_exp(sources[i].time_off_mean);
                    if (sources[i].channel_id != -1) {
                        circuit_busy[sources[i].channel_id] = false;
                        sources[i].channel_id = -1;
                    }
                }
            }

            /* Генерація бітів/пакетів від активних джерел */
            if (sources[i].is_on) {
                /* Circuit: передача, якщо канал виділено */
                if (sources[i].channel_id != -1) {
                    circuit_bits_transferred += peak_rate_bps * dt;
                }

                /* Packet: генерація окремих пакетів кожні packet_interval */
                if (t - sources[i].last_packet_time >= packet_interval) {
                    sources[i].last_packet_time = t;
                    packets_generated++;
                    Packet p = { .arrival_time = t, .source_id = i };
                    if (!queue_push(&pkt_queue, p)) {
                        packets_dropped++;
                    }
                }
            }
        }

        /* 2. Обслуговування пакетного сервера (Store-and-Forward лінія) */
        if (t >= packet_server_busy_until && pkt_queue.count > 0) {
            Packet p;
            if (queue_pop(&pkt_queue, &p)) {
                packet_server_busy_until = t + packet_tx_time;
                double delay = (t + packet_tx_time) - p.arrival_time;
                total_packet_delay += delay;
                total_packet_delay_sq += delay * delay;
                packets_served++;
                packet_bits_transferred += packet_size_bits;
            }
        }
    }

    /* Обчислення підсумкових метрик */
    double circuit_utilization = (circuit_bits_transferred / (link_capacity_bps * sim_duration)) * 100.0;
    double circuit_block_rate = ((double)circuit_requests_blocked / circuit_requests_total) * 100.0;

    double packet_utilization = (packet_bits_transferred / (link_capacity_bps * sim_duration)) * 100.0;
    double packet_loss_rate = ((double)packets_dropped / packets_generated) * 100.0;
    double avg_delay_ms = (total_packet_delay / packets_served) * 1000.0;
    double var_delay = (total_packet_delay_sq / packets_served) - ((total_packet_delay / packets_served) * (total_packet_delay / packets_served));
    double jitter_ms = sqrt(var_delay > 0.0 ? var_delay : 0.0) * 1000.0;

    printf("================ РЕЗУЛЬТАТИ СИМУЛЯЦІЇ (100 с) ================\n");
    printf("Кількість підключених джерел: %d | Смуга каналу: %.1f Мбіт/с\n\n", num_sources, link_capacity_bps / 1e6);
    printf("1. КОМУТАЦІЯ КАНАЛІВ (CIRCUIT SWITCHING):\n");
    printf("   • Утилізація вихідного лінка:  %.2f %%\n", circuit_utilization);
    printf("   • Загальна кількість викликів: %ld\n", circuit_requests_total);
    printf("   • Блокування нових викликів:   %.2f %% (%ld відхилено)\n", circuit_block_rate, circuit_requests_blocked);
    printf("   • Джитер та варіація затримки: 0.00 мс (суворий детермінізм)\n\n");
    printf("2. КОМУТАЦІЯ ПАКЕТІВ (PACKET SWITCHING):\n");
    printf("   • Утилізація вихідного лінка:  %.2f %%\n", packet_utilization);
    printf("   • Згенеровано пакетів:         %ld\n", packets_generated);
    printf("   • Втрати через буфер:          %.2f %% (%ld втрачено)\n", packet_loss_rate, packets_dropped);
    printf("   • Середня затримка пакета:     %.2f мс\n", avg_delay_ms);
    printf("   • Джитер (std dev затримки):   %.2f мс\n", jitter_ms);
    printf("===============================================================\n");

    return 0;
}

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <random>
#include <cmath>
#include <iomanip>

struct Packet {
    double arrival_time;
    int source_id;
};

struct Source {
    double time_on_mean;
    double time_off_mean;
    double peak_rate_bps;
    bool is_on{false};
    double next_state_change{0.0};
    int channel_id{-1};
    double last_packet_time{0.0};
};

class SwitchingSimulator {
public:
    SwitchingSimulator(int num_sources, double link_bps, double peak_bps, double sim_time)
        : num_sources_(num_sources),
          link_capacity_bps_(link_bps),
          peak_rate_bps_(peak_bps),
          sim_duration_(sim_time),
          num_circuits_(static_cast<int>(link_bps / peak_bps)),
          circuit_busy_(num_circuits_, false),
          gen_(42) {}

    void run() {
        std::exponential_distribution<double> dist_on(1.0 / 0.2);
        std::exponential_distribution<double> dist_off(1.0 / 1.8);

        std::vector<Source> sources(num_sources_);
        for (auto &s : sources) {
            s.time_on_mean = 0.2;
            s.time_off_mean = 1.8;
            s.peak_rate_bps = peak_rate_bps_;
            s.is_on = false;
            s.next_state_change = dist_off(gen_);
        }

        const double dt = 0.0001; // 100 мкс
        const int packet_size_bits = 8000;
        const double packet_interval = static_cast<double>(packet_size_bits) / peak_rate_bps_;
        const double packet_tx_time = static_cast<double>(packet_size_bits) / link_capacity_bps_;

        std::queue<Packet> pkt_queue;
        const size_t queue_capacity = 50;

        for (double t = 0.0; t < sim_duration_; t += dt) {
            // Оновлення джерел
            for (int i = 0; i < num_sources_; ++i) {
                auto &s = sources[i];
                if (t >= s.next_state_change) {
                    if (!s.is_on) {
                        s.is_on = true;
                        s.next_state_change = t + dist_on(gen_);
                        s.last_packet_time = t;

                        // Circuit: запит на таймслот
                        circuit_requests_total_++;
                        int free_ch = -1;
                        for (int ch = 0; ch < num_circuits_; ++ch) {
                            if (!circuit_busy_[ch]) {
                                free_ch = ch;
                                break;
                            }
                        }
                        if (free_ch != -1) {
                            circuit_busy_[free_ch] = true;
                            s.channel_id = free_ch;
                        } else {
                            s.channel_id = -1;
                            circuit_requests_blocked_++;
                        }
                    } else {
                        s.is_on = false;
                        s.next_state_change = t + dist_off(gen_);
                        if (s.channel_id != -1) {
                            circuit_busy_[s.channel_id] = false;
                            s.channel_id = -1;
                        }
                    }
                }

                if (s.is_on) {
                    if (s.channel_id != -1) {
                        circuit_bits_transferred_ += peak_rate_bps_ * dt;
                    }
                    if (t - s.last_packet_time >= packet_interval) {
                        s.last_packet_time = t;
                        packets_generated_++;
                        if (pkt_queue.size() < queue_capacity) {
                            pkt_queue.push(Packet{t, i});
                        } else {
                            packets_dropped_++;
                        }
                    }
                }
            }

            // Обробка черги вихідного порту
            if (t >= packet_server_busy_until_ && !pkt_queue.empty()) {
                Packet p = pkt_queue.front();
                pkt_queue.pop();
                packet_server_busy_until_ = t + packet_tx_time;
                double delay = (t + packet_tx_time) - p.arrival_time;
                total_packet_delay_ += delay;
                total_packet_delay_sq_ += delay * delay;
                packets_served_++;
                packet_bits_transferred_ += packet_size_bits;
            }
        }
    }

    void print_report() const {
        double circuit_util = (circuit_bits_transferred_ / (link_capacity_bps_ * sim_duration_)) * 100.0;
        double circuit_block = (static_cast<double>(circuit_requests_blocked_) / circuit_requests_total_) * 100.0;

        double packet_util = (packet_bits_transferred_ / (link_capacity_bps_ * sim_duration_)) * 100.0;
        double packet_loss = (static_cast<double>(packets_dropped_) / packets_generated_) * 100.0;
        double avg_delay = (total_packet_delay_ / packets_served_) * 1000.0;
        double var_delay = (total_packet_delay_sq_ / packets_served_) - std::pow(total_packet_delay_ / packets_served_, 2);
        double jitter = std::sqrt(std::max(0.0, var_delay)) * 1000.0;

        std::cout << std::fixed << std::setprecision(2);
        std::cout << "================ РЕЗУЛЬТАТИ СИМУЛЯЦІЇ (100 с) ================\n";
        std::cout << "Кількість підключених джерел: " << num_sources_ << " | Смуга: " << (link_capacity_bps_ / 1e6) << " Мбіт/с\n\n";
        std::cout << "1. КОМУТАЦІЯ КАНАЛІВ (CIRCUIT SWITCHING):\n";
        std::cout << "   • Утилізація вихідного лінка:  " << circuit_util << " %\n";
        std::cout << "   • Загальна кількість викликів: " << circuit_requests_total_ << "\n";
        std::cout << "   • Блокування нових викликів:   " << circuit_block << " % (" << circuit_requests_blocked_ << " відхилено)\n";
        std::cout << "   • Джитер та варіація затримки: 0.00 мс\n\n";
        std::cout << "2. КОМУТАЦІЯ ПАКЕТІВ (PACKET SWITCHING):\n";
        std::cout << "   • Утилізація вихідного лінка:  " << packet_util << " %\n";
        std::cout << "   • Згенеровано пакетів:         " << packets_generated_ << "\n";
        std::cout << "   • Втрати через буфер:          " << packet_loss << " % (" << packets_dropped_ << " втрачено)\n";
        std::cout << "   • Середня затримка пакета:     " << avg_delay << " мс\n";
        std::cout << "   • Джитер (std dev затримки):   " << jitter << " мс\n";
        std::cout << "===============================================================\n";
    }

private:
    int num_sources_;
    double link_capacity_bps_;
    double peak_rate_bps_;
    double sim_duration_;
    int num_circuits_;
    std::vector<bool> circuit_busy_;

    long circuit_requests_total_{0};
    long circuit_requests_blocked_{0};
    double circuit_bits_transferred_{0.0};

    long packets_generated_{0};
    long packets_dropped_{0};
    long packets_served_{0};
    double total_packet_delay_{0.0};
    double total_packet_delay_sq_{0.0};
    double packet_server_busy_until_{0.0};
    double packet_bits_transferred_{0.0};

    std::mt19937 gen_;
};

int main() {
    SwitchingSimulator sim(35, 10000000.0, 1000000.0, 100.0);
    sim.run();
    sim.print_report();
    return 0;
}
```

### Детальний розбір механізмів симулятора

Програма організована за принципом дискретно-часового моделювання з фіксованим квантом часу `dt = 100` мкс. Кожна ітерація основного циклу відповідає одному кроку модельного часу і складається з трьох послідовних етапів:

1. **Фазовий перехід джерел Маркова**: Для кожного джерела перевіряється умова `t >= sources[i].next_state_change`. Якщо настав час зміни стану:
   - Якщо джерело перебувало у стані паузи (`is_on == false`), воно переходить у стан активного сплеску (`is_on = true`). Для нього генерується нова випадкова тривалість активності за експоненційним законом `rand_exp(0.2)`.
   - Одночасно фіксується спроба виділення ресурсу в моделі комутації каналів: алгоритм шукає перший вільний індекс у масиві `circuit_busy[10]`. Якщо вільний слот знайдено, джерело закріплює за собою канал на весь час сплеску (`channel_id = free_ch`). Якщо всі 10 слотів зайняті, фіксується подія блокування виклику (`circuit_requests_blocked++`).
   - Якщо джерело перебувало в стані активності (`is_on == true`), воно завершує передачу, звільняє виділений слот комутації каналів (`circuit_busy[channel_id] = false`) і переходить у стан сну на випадковий час `rand_exp(1.8)`.

2. **Генерація дискретних пакетів**: Усі активні джерела випромінюють пакети фіксованого розміру `L = 8000` бітів. Кожне джерело веде таймер `last_packet_time`. Щойно різниця `t - last_packet_time` досягає `8` мс (період генерації при піковій швидкості 1 Мбіт/с), створюється екземпляр структури `Packet` із часовою міткою прибуття `arrival_time = t`.
   - Пакет направляється до кільцевого буфера FIFO `pkt_queue`.
   - Якщо кількість пакетів у черзі менша за максимальну місткість (`count < max_capacity`), пакет успішно додається в хвіст черги.
   - Якщо буфер переповнений (`count == max_capacity`), пакет відкидається за алгоритмом **Tail Drop**, і лічильник втрат `packets_dropped` збільшується на одиницю.

3. **Сервер черги Store-and-Forward**: Передавач вихідного порту обслуговує пакети з черги за принципом FIFO зі швидкістю лінії 10 Мбіт/с.
   - Змінна `packet_server_busy_until` фіксує момент часу, до якого передавач зайнятий випромінюванням поточного пакета.
   - Коли `t >= packet_server_busy_until` і черга не порожня, з голови черги вичитується наступний пакет.
   - Час завершення передачі пакета становить `t_finish = t + t_tx`, де `t_tx = 0.8` мс.
   - Повна затримка доставки пакета у вузлі обчислюється як різниця `delay = t_finish - p.arrival_time`. Ця величина додається до накопичувачів суми та суми квадратів для розрахунку математичного сподівання та середньоквадратичного відхилення (джитеру).

### Простеження 10-мілісекундного вікна подій у реальному часі

Щоб побачити, як стохастична взаємодія розгортається на практиці, розглянемо хронологію подій протягом короткого 10-мілісекундного вікна симуляції (від `t = 12.000` с до `t = 12.010` с):

```
Час t (мс)   Подія                                 Стан буфера FIFO   Затримка пакета
───────────────────────────────────────────────────────────────────────────────────────
12.000.0     Пакет P1 від Джерела 3 надходить      Count = 1          t_arr = 12.000.0
12.000.0     Передавач вільний: починає P1         Busy until 12.000.8
12.000.3     Пакет P2 від Джерела 7 надходить      Count = 1 (в буфер) t_arr = 12.000.3
12.000.5     Пакет P3 від Джерела 19 надходить     Count = 2 (в буфер) t_arr = 12.000.5
12.000.8     P1 повністю передано в лінію          Count = 2          Delay P1 = 0.8 мс
12.000.8     Передавач бере P2 з черги             Count = 1, Busy -> 12.001.6
12.001.6     P2 повністю передано в лінію          Count = 1          Delay P2 = 1.3 мс (12.001.6 - 12.000.3)
12.001.6     Передавач бере P3 з черги             Count = 0, Busy -> 12.002.4
12.002.4     P3 повністю передано в лінію          Count = 0          Delay P3 = 1.9 мс (12.002.4 - 12.000.5)
12.002.4     Черга порожня, передавач простоює     Count = 0          Лінія вільна
```

Цей журнал чітко показує механіку виникнення джитеру: хоча всі пакети мають однаковий розмір (8000 бітів) та однаковий час випромінювання (0.8 мс), пакет P3 зазнав затримки 1.9 мс через те, що чекав завершення передачі пакетів P1 та P2, які надійшли на кількасот мікросекунд раніше. У комутації каналів усі три джерела передавали б дані паралельно у власних таймслотах із фіксованою апаратною затримкою 0.0 мс.

### Експериментальне дослідження чутливості до коефіцієнта активності

Змінюючи параметр активності користувача `p` від 0.02 (дуже розріджений трафік) до 0.40 (щільний трафік потокового відео), можна спостерігати різну реакцію систем:

```
Активність p   Завантаження каналу   Блокування каналів (TDM)   Втрати пакетів   Середня затримка пакетів
──────────────────────────────────────────────────────────────────────────────────────────────────────────
0.02 (2%)      ~7.0 %                ~0.05 %                    0.000 %          0.81 мс
0.05 (5%)      ~17.5 %               ~2.10 %                    0.001 %          0.85 мс
0.10 (10%)     ~34.8 %               ~12.40 %                   0.035 %          1.24 мс
0.20 (20%)     ~69.2 %               ~42.80 %                   0.850 %          2.65 мс
0.30 (30%)     ~92.0 %               ~68.50 %                   8.400 %          14.80 мс
0.40 (40%)     >99.0 %               ~83.20 %                   28.500 %         Буфер переповнений (Tail Drop)
```

При низькій активності (`p ≤ 0.10`) комутація пакетів забезпечує майже ідеальне обслуговування з нульовими втратами та затримкою, близькою до фізичного мінімуму, тоді як комутація каналів уже блокує понад 12% сесій через вичерпання 10 слотів. Проте при навантаженні `p ≥ 0.30` комутація пакетів входить у режим перевантаження, де затримка черги зростає експоненційно, вимагаючи втручання алгоритмів QoS та контролю перевантажень.

### Поглиблений аналіз крайових випадків та архітектурних пасток

Зіставлення числових показників симуляції виявляє кілька прихованих явищ, які мають вирішальне значення при розробці реальних мережевих систем:

#### 1. Феномен синхронізації сплесків та хвостів черги

У симуляторі джерела вважаються строго незалежними, а тривалості пауз розподілені експоненційно. Проте в реальних мережах TCP-джерела демонструють ефект самоподібності (*Self-Similarity*) та важких хвостів розподілу (*Heavy-Tailed / Pareto Distribution*).

Якщо буфер пакетокомутатора занадто малий (наприклад, `B = 10` пакетів замість `50`), навіть незначний короткочасний сплеск від 12 одночасно активних користувачів заповнює пам'ять за лічені мілісекунди:
- 12 користувачів генерують сумарно `12 Мбіт/с`.
- Лінія віддає лише `10 Мбіт/с`.
- Швидкість накопичення черги становить `2 Мбіт/с = 250 пакетів/с`.
- Буфер на 10 пакетів переповниться рівно за `10 / 250 = 0.04` с (40 мілісекунд).

Коли буфер переповнюється, комутатор скидає всі наступні пакети поспіль. У результаті десятки сесій TCP одночасно втрачають сегменти, входять у таймаут і одночасно зменшують свої вікна перевантаження вдвічі. Після цього настає фаза синхронного відновлення — так звана **глобальна TCP-синхронізація** (*Global TCP Synchronization*), коли утилізація каналу різко падає майже до нуля, а потім знову стрибає до 100%, спричиняючи нове переповнення.

#### 2. Пастка буферного роздування (Bufferbloat)

Природне бажання інженера повністю усунути втрати пакетів полягає у збільшенні розміру буфера до `B = 5000` пакетів. Проте це породжує зворотну проблему — **Bufferbloat**. Коли трафік перевантажує лінію, гігантський буфер не скидає пакети, але час перебування в ньому зростає до:

```
W_max = (5000 пакетів · 8000 бітів) / 10 000 000 біт/с = 4.0 секунди
```

Затримка в 4 секунди повністю паралізує інтерактивні додатки (SSH, онлайн-ігри, DNS, VoIP), тоді як алгоритми контролю перевантажень TCP не отримують сигналу про переповнення мережі (оскільки пакети не втрачаються, а лише годинами стоять у черзі). Саме тому сучасні комутатори використовують активне керування чергами (**AQM**, *Active Queue Management*, алгоритми RED, CoDel, PIE), які вимірюють час перебування пакета в буфері й починають завчасно скидати окремі пакети або виставляти прапорці ECN ще до фізичного переповнення пам'яті.

#### 3. Блокування початку черги (Head-of-Line Blocking) у комутаторах з вхідною буферизацією

У комутаторах пакетів з кількома портами виникає архітектурна дилема розміщення буферної пам'яті:
- **Output Queuing (вихідна буферизація)**: буфери розташовані на вихідних портах. Якщо кілька вхідних портів одночасно надсилають пакети на один вихідний порт, внутрішня комутаційна матриця повинна працювати у `K` разів швидше за швидкість лінії (де `K` — кількість портів). Для комутатора на 64 порти по 100 Гбіт/с це вимагає внутрішньої шини 6.4 Тбіт/с до кожного порту, що фізично неможливо реалізувати.
- **Input Queuing (вхідна буферизація)**: буфери розташовані на вхідних портах. Внутрішня матриця працює зі швидкістю лінії. Проте виникає явище **Head-of-Line (HoL) Blocking**: якщо пакет у голові вхідної черги чекає звільнення вихідного порту 1, усі наступні пакети в цій черзі (навіть якщо вони адресовані у вільні порти 2, 3, 4) блокуються і не можуть бути передані.

Математично доведено (Карол, Глік та Спандакіс, 1987), що через HoL-блокування максимальна пропускна здатність вхідно-буферизованого комутатора з простою FIFO-чергою обмежена теоретичною межею:

```
Th_max = 2 - √2 ≈ 58.58%
```

Майже 41.4% пропускної здатності втрачається через взаємне блокування черг.

Щоб подолати цей бар'єр, сучасні високошвидкісні комутатори використовують **віртуальні вихідні черги** (**VoQ**, *Virtual Output Queuing*): на кожному вхідному порту створюється `K` окремих підчерг (по одній для кожного вихідного порту), а апаратний арбітр комутаційної матриці (алгоритми iSLIP або WFA) знаходить максимальне двочасткове паросполучення між портами за кілька наносекунд, підіймаючи пропускну здатність комутатора до 100%.

#### 4. Класичне правило Стенфорда для розрахунку буфера

Історично вважалося, що розмір буфера маршрутизатора повинен дорівнювати добутку пропускної здатності на круговий час затримки (**BDP**, *Bandwidth-Delay Product*):

```
B_classical = RTT · C
```

Для магістрального каналу 10 Гбіт/с із трансатлантичною затримкою `RTT = 200` мс це вимагало буфера `0.2 · 10 000 000 000 = 2 Гбіт = 250 Мбайт` надшвидкісної пам'яті на кожен мережевий порт. Проте дослідники Стенфордського університету (Нік Маккьюн та інші, 2004) довели, що при агрегації великої кількості `N` незалежних TCP-потоків завдяки статистичному згладжуванню необхідний розмір буфера зменшується в `√N` разів:

```
B_stanford = (RTT · C) / √N
```

При `N = 10 000` паралельних потоків розмір буфера можна зменшити у `√10000 = 100` разів (до 2.5 Мбайт), що дозволяє розмістити всю буферну пам'ять безпосередньо на кристалі комутаційного чіпа (On-Chip SRAM), уникаючи дорогих зовнішніх мікросхем пам'яті.

#### 5. Технології буферної пам'яті: SRAM, DRAM та HBM

Вибір фізичної пам'яті комутатора визначає компроміс між вартістю, ємністю та енергоспоживанням:
- **On-Chip SRAM**: статична пам'ять безпосередньо на кристалі комутаційного ASIC. Забезпечує наднизьку затримку доступу (менше 1 нс) та колосальну пропускну здатність, але обмежена фізичною площею чіпа (типово 32–128 МБайт на весь комутатор). Застосовується в ультрашвидкісних комутаторах центрів обробки даних (Broadcom Tomahawk, Cisco Silicon One).
- **Зовнішня DRAM / RLDRAM**: динамічна пам'ять із низькою затримкою. Надає великі обсяги (гігабайти буфера для глибокої буферизації), але час доступу (20–40 нс) створює «вузьке місце» для передачі коротких пакетів на швидкостях 400G/800G.
- **High Bandwidth Memory (HBM2e / HBM3)**: тривимірні стеки кристалів пам'яті, з'єднані з основним комутаційним ASIC через кремнієвий інтерпозер (*Silicon Interposer*). Дозволяють отримати пропускну здатність пам'яті понад 3 ТБайт/с при місткості до 32 ГБайт, що є стандартом для сучасних магістральних WAN-маршрутизаторів (Juniper PTX, Cisco 8000).

#### 6. Порівняння апаратних витрат пам'яті та транзисторів

```
Характеристика                Комутація каналів (TDM)               Комутація пакетів (Store-and-Forward)
──────────────────────────────────────────────────────────────────────────────────────────────────────────
Вимоги до пам'яті вузла       Регістри на 1–2 байти на таймслот     Мегабайти швидкісної SRAM/DRAM пам'яті
Логіка комутаційної матриці   Проста циклічна матриця Time-Space    Складні арбітри черг (VoQ, Crossbar Scheduler)
Обробка заголовків            Не потрібна (фіксована позиція)       Конвеєр парсингу L2/L3/L4, пошук LPM в TCAM
Ціна розширення смуги         Лінійна за кількістю слотів           Висока через обмеження пропускної здатності пам'яті
```

У комутаторі каналів розмір буфера мінімальний: достатньо подвійного регістра на 8 бітів для кожного таймслота, щоб прийняти байт з лінії та перекласти його у вихідну матрицю. У комутаторі пакетів оперативна пам'ять повинна мати пропускну здатність, яка вдвічі перевищує сумарну швидкість усіх портів комутатора (одночасний запис нового пакета та зчитування попереднього), що є головним обмежувачем швидкодії сучасних терабітних маршрутизаторів.

### Інструкція зі збірки та методики розширення моделі

Для компіляції та запуску прикладів достатньо стандартного компілятора GCC або Clang з оптимізацією `-O2`:

```
# Збірка версії C:
gcc -O2 -Wall -Wextra proj-switching-simulation.c -lm -o sim_c
./sim_c

# Збірка версії C++ (C++20):
g++ -O2 -std=c++20 -Wall -Wextra proj-switching-simulation.cpp -o sim_cpp
./sim_cpp
```

Для подальшого дослідження модель легко розширюється підтримкою алгоритму раннього випадкового скидання **WRED** (*Weighted Random Early Detection*). Замість жорсткого скидання Tail Drop при повному буфері `B = 50`, у функцію `queue_push` додаються два пороги та зважене експоненційне усереднення поточної довжини черги `avg = (1 - w) · avg + w · count`:
- `min_th = 20` пакетів: нижче цього порогу всі пакети приймаються без втрат (`P_drop = 0`).
- `max_th = 45` пакетів: у діапазоні між `min_th` та `max_th` ймовірність скидання лінійно зростає від `0` до `max_p = 0.10` (10%).
- Якщо черга перевищує `max_th`, усі наступні пакети відкидаються зі 100% імовірністю.

Така модифікація ефективно запобігає глобальній TCP-синхронізації, розсіюючи скидання пакетів у часі між різними джерелами та стабілізуючи середню довжину черги біля значення `min_th`. Це дозволяє досягти майже 100% утилізації лінії без небезпеки виникнення Bufferbloat.
