# 🧮 Математика статистичного мультиплексування проти моделі Ерланга

Математичне обґрунтування переваги комутації пакетів над комутацією каналів спирається на теорію ймовірностей, теорію масового обслуговування та апарат великих відхилень. Цей розділ містить строгий аналітичний розрахунок місткості мережі для обох парадигм, виведення формул блокування викликів Ерланга B, затримки Ерланга C та моделі Енгсета для скінченної кількості абонентів, біноміальний аналіз статистичного мультиплексування пачкових джерел, формальне виведення меж Чернова за допомогою твірних функцій моментів, практичну теорію ефективної смуги пропускання Келлі для багатокласового трафіку та модель Норроса для самоподібного фрактального трафіку.

### 1. Модель комутації каналів: марковський процес та формула Ерланга B

У класичній мережі комутації каналів (TDM/PSTN) магістральна лінія містить фіксовану кількість паралельних обслуговуючих каналів (таймслотів) `m`. Якщо новий виклик надходить у момент, коли всі `m` каналів зайняті розмовами інших абонентів, система відхиляє виклик (абонент чує короткі гудки «зайнято»). Такий режим описується моделлю `M/M/m/m` за нотацією Кендалла (система без черги, з відмовами/втратами).

Розглянемо систему як неперервний у часі марковський процес загибелі та розмноження з дискретним простором станів `S = {0, 1, 2, ..., m}`, де стан `k` позначає кількість одночасно зайнятих каналів у даний момент часу.

Нехай:
- `λ` — середня інтенсивність надходження нових викликів (викликів за секунду), що утворює пуассонівський потік (інтервали між викликами розподілені експоненційно з параметром `λ`);
- `1 / μ` — середня тривалість однієї розмови (секунд), де час обслуговування розподілений експоненційно з параметром `μ`;
- `A = λ / μ` — безрозмірне телефонне навантаження в **ерлангах** (*Erlangs*).

Один ерланг відповідає безперервному 100% завантаженню одного фізичного каналу протягом періоду спостереження (наприклад, одна неперервна розмова тривалістю 60 хвилин за 1 годину створює навантаження 1 Ерл).

#### Рівняння балансу ймовірностей станів

У стаціонарному стані для кожного перерізу між сусідніми станами `k - 1` та `k` сумарний потік імовірності переходу праворуч (надходження виклику з інтенсивністю `λ`) дорівнює потоку ймовірності переходу ліворуч (завершення будь-якої з `k` активних розмов із сумарною інтенсивністю `k · μ`):

```
Стан 0 <-> 1:   λ · P(0) = 1 · μ · P(1)
Стан 1 <-> 2:   λ · P(1) = 2 · μ · P(2)
Стан 2 <-> 3:   λ · P(2) = 3 · μ · P(3)
...
Стан k-1 <-> k: λ · P(k - 1) = k · μ · P(k)
```

Виразимо ймовірність довільного стану `P(k)` рекурентно через ймовірність нульового стану `P(0)`:

```
P(1) = (λ / μ) · P(0) = A · P(0)
P(2) = (λ / (2 · μ)) · P(1) = (A / 2) · A · P(0) = (A² / 2!) · P(0)
P(3) = (λ / (3 · μ)) · P(2) = (A / 3) · (A² / 2!) · P(0) = (A³ / 3!) · P(0)
...
P(k) = (A^k / k!) · P(0),   для 0 ≤ k ≤ m
```

Оскільки система скінченна і обов'язково перебуває в одному зі станів від `0` до `m`, застосовуємо фундаментальну умову нормування ймовірностей `∑_{j=0}^m P(j) = 1`:

```
P(0) · ∑_{j=0}^m (A^j / j!) = 1
=> P(0) = 1 / (∑_{j=0}^m (A^j / j!))
```

Підставляючи отримане значення `P(0)` у загальний вираз для `P(k)`, маємо стаціонарний розподіл Ерланга:

```
P(k) = (A^k / k!) / (∑_{j=0}^m (A^j / j!))
```

Ймовірність блокування нового виклику `P_block` (ймовірність того, що всі `m` каналів зайняті і новий виклик втрачається) відповідає стану `k = m`. Цей вираз називається **першою формулою Ерланга** або **формулою Ерланга B** (Agner Krarup Erlang, 1917):

```
B(m, A) = (A^m / m!) / (∑_{j=0}^m (A^j / j!))
```

#### Рекурентне обчислення формули Ерланга B

Пряме обчислення факторіала `m!` та степеня `A^m` на комп'ютері призводить до переповнення розрядної сітки чисел із рухомою комою при `m > 150`. Для стійких обчислень застосовують рекурентне співвідношення, яке виводиться діленням чисельника й знаменника на факторіал попереднього кроку:

```
B(0, A) = 1

B(k, A) = (A · B(k - 1, A)) / (k + A · B(k - 1, A)),   k = 1, 2, ..., m
```

**Приклад розрахунку магістралі E1 (m = 30 голосових каналів):**

Магістральний цифровий потік E1 містить `m = 30` каналів по 64 кбіт/с. Допустима оператором норма блокування становить `P_block ≤ 0.01` (не більше 1% втрачених викликів у годину найбільшого навантаження).

Розв'яжемо рівняння `B(30, A) = 0.01` за допомогою рекурентної формули:

```
B(30, A) = 0.01
=> A ≈ 20.33 Ерл
```

Це означає, що 30 виділених каналів TDM здатні стабільно обслуговувати сумарне навантаження лише у 20.33 Ерланга. Решта 32.2% пропускної здатності фізичного кабелю постійно резервується як запас на випадкові статистичні сплески, щоб не перевищити поріг блокування.

### 2. Системи з очікуванням: формула Ерланга C

Якщо комутатор каналів має буфер очікування (модель `M/M/m/∞` — система з очікуванням, типова для кол-центрів), виклики, які застали всі `m` каналів зайнятими, не скидаються, а стають у нескінченну чергу.

Ймовірність того, що новий виклик буде змушений чекати в черзі (всі `m` каналів зайняті), визначається **формулою Ерланга C**:

```
C(m, A) = ( (A^m / m!) · (m / (m - A)) ) / ( ∑_{k=0}^{m-1} (A^k / k!) + (A^m / m!) · (m / (m - A)) )
```

Зв'язок між формулами Ерланга B та C виражається компактним співвідношенням:

```
C(m, A) = (m · B(m, A)) / (m - A · (1 - B(m, A)))
```

Середній час очікування виклику в черзі до початку з'єднання становить:

```
W_q = C(m, A) / (m · μ - λ)
```

### 3. Модель Енгсета: скінченна кількість абонентів

Припущення пуассонівського потоку у формулі Ерланга B справедливе лише тоді, коли загальна кількість потенційних абонентів `S` прямує до нескінченності (`S >> m`). Якщо кількість користувачів скінченна і співрозмірна з кількістю каналів (наприклад, `S = 50` офісних телефонів підключено до корпоративної АТС з `m = 10` зовнішніми лініями), надходження викликів перестає бути стаціонарним: кожен зайнятий користувач тимчасово вибуває з генерації нових викликів.

У цьому випадку застосовується **формула Енгсета** (*Engset formula*, 1918):

```
E(m, S, α) = ( C(S - 1, m) · α^m ) / ( ∑_{k=0}^m C(S - 1, k) · α^k )
```

де:
- `S` — загальна кількість абонентів у мережі;
- `α = γ / μ` — питоме навантаження, яке генерує один вільний користувач (де `γ` — інтенсивність викликів від одного не зайнятого абонента).

Формула Енгсета дає меншу ймовірність блокування, ніж формула Ерланга B для того самого середнього навантаження, оскільки зайнятість каналів автоматично знижує швидкість надходження нових заявок.

### 4. Модель комутації пакетів: біноміальний розподіл активності

Комп'ютерний трафік має імпульсну природу: користувач генерує дані лише невелику частку часу, а решту часу лінія простоює (читання веб-сторінки, паузи між транзакціями).

Сформулюємо базову стохастичну модель:
1. У системі є `N` незалежних користувачів.
2. Кожен користувач активний лише частку часу `p` (`0 < p < 1`, коефіцієнт активності).
3. У стані активності користувач передає дані з постійною піковою швидкістю `R` біт/с.
4. У стані паузи (частка часу `1 - p`) швидкість дорівнює 0 біт/с.
5. Пропускна здатність вихідної лінії комутатора дорівнює `C` біт/с.

Кількість одночасно активних користувачів, яку лінія здатна обслужити на максимальній піковій швидкості без затримки в черзі:

```
M = C / R
```

- **При комутації каналів**: мережа здатна підключити щонайбільше `N_circuit = M` користувачів. Підключення `M + 1`-го користувача неможливе.
- **При комутації пакетів**: мережа дозволяє підключити `N >> M` користувачів. Тимчасове перевантаження виникає лише тоді, коли кількість одночасно активних користувачів `k` випадково перевищує значення `M`.

Оскільки джерела діють незалежно одне від одного, кількість одночасно активних користувачів `X` у довільний момент часу підпорядковується **біноміальному розподілу** `X ~ Binomial(N, p)`:

```
P(X = k) = C(N, k) · p^k · (1 - p)^(N - k)
```

де `C(N, k) = N! / (k! · (N - k)!)` — біноміальний коефіцієнт.

Ймовірність перевантаження вихідного інтерфейсу `P_overload` (ймовірність того, що сумарна миттєва швидкість перевищить ємність лінії `C`):

```
P_overload = P(X > M) = ∑_{k=M+1}^N C(N, k) · p^k · (1 - p)^(N - k)
```

### 5. Числовий розрахунок виграшу статистичного мультиплексування

Розглянемо практичну інженерну задачу:
- Швидкість вихідної лінії: `C = 10` Мбіт/с.
- Пікова швидкість джерела: `R = 1` Мбіт/с.
- Місткість лінії без перевантаження: `M = C / R = 10 / 1 = 10`.
- Коефіцієнт активності користувача: `p = 0.1` (10% часу активності, типово для веб-серфінгу).

#### Варіант А: Комутація каналів
Комутатор жорстко ділить канал на 10 таймслотів по 1 Мбіт/с.
- Максимальна кількість абонентів: `N = 10`.
- Будь-яка спроба підключити 11-го користувача блокується зі 100% імовірністю.

#### Варіант Б: Комутація пакетів при N = 35 користувачах
Підключимо до лінії `N = 35` користувачів (у 3.5 раза більше, ніж дозволяє комутація каналів).

Обчислимо ймовірність того, що одночасно активними виявляться 11 або більше користувачів:

```
P(X > 10) = 1 - P(X ≤ 10)
P(X ≤ 10) = ∑_{k=0}^{10} C(35, k) · 0.1^k · 0.9^(35 - k)
```

Почленний розрахунок біноміального розподілу:

```
P(X = 0)  = C(35, 0)  · (0.1)⁰  · (0.9)³⁵  ≈ 0.02503
P(X = 1)  = C(35, 1)  · (0.1)¹  · (0.9)³⁴  ≈ 0.09734
P(X = 2)  = C(35, 2)  · (0.1)²  · (0.9)³³  ≈ 0.18387
P(X = 3)  = C(35, 3)  · (0.1)³  · (0.9)³²  ≈ 0.22473
P(X = 4)  = C(35, 4)  · (0.1)⁴  · (0.9)³¹  ≈ 0.19976
P(X = 5)  = C(35, 5)  · (0.1)⁵  · (0.9)³⁰  ≈ 0.13761
P(X = 6)  = C(35, 6)  · (0.1)⁶  · (0.9)²⁹  ≈ 0.07645
P(X = 7)  = C(35, 7)  · (0.1)⁷  · (0.9)²⁸  ≈ 0.03519
P(X = 8)  = C(35, 8)  · (0.1)⁸  · (0.9)²⁷  ≈ 0.01369
P(X = 9)  = C(35, 9)  · (0.1)⁹  · (0.9)²⁶  ≈ 0.00456
P(X = 10) = C(35, 10) · (0.1)¹⁰ · (0.9)²⁵ ≈ 0.00132

Сума P(X ≤ 10) = 0.99958
```

Звідси ймовірність перевантаження каналу:

```
P(X > 10) = 1 - 0.99958 = 0.00042 ≈ 0.042%
```

**Висновок**: при підключенні 35 користувачів імовірність того, що сумарне навантаження перевищить пропускну здатність лінії 10 Мбіт/с, становить лише **0.042%** (близько 4.2 секунди на кожні 10 000 секунд роботи). Короткочасний сплеск легко згладжується буфером комутатора розміром у кілька десятків кілобайтів.

**Коефіцієнт виграшу статистичного мультиплексування** (*Statistical Multiplexing Gain*):

```
G = N_packet / N_circuit = 35 / 10 = 3.5
```

### 6. Асимптотичні оцінки: нормальне наближення та межа Чернова

Для магістральних каналів з тисячами користувачів (`N >> 100`) пряме обчислення факторіалів стає обчислювально важким. Для аналізу застосовують інтегральну теорему Муавра–Лапласа та нерівність Чернова.

#### Апроксимація нормальним розподілом (Муавр–Лаплас)

Математичне сподівання `μ_X` та дисперсія `σ_X²` кількості активних джерел:

```
μ_X = E[X] = N · p
σ_X² = Var(X) = N · p · (1 - p)
```

За центральною граничною теоремою, при великих `N` випадкова величина `X` наближається до нормального розподілу `N(μ_X, σ_X²)`. Ймовірність перевантаження з урахуванням поправки на неперервність записується через стандартну `Q`-функцію:

```
P(X > M) ≈ Q((M + 0.5 - N · p) / √(N · p · (1 - p)))
```

де `Q(z) = (1 / √(2 · π)) · ∫_z^∞ e^(-t² / 2) dt`.

**Розрахунок для магістралі N = 100 користувачів при C = 20 Мбіт/с (M = 20, p = 0.1):**

```
μ_X = 100 · 0.1 = 10
σ_X = √(100 · 0.1 · 0.9) = √9 = 3

z = (20 + 0.5 - 10) / 3 = 10.5 / 3 = 3.5

P(X > 20) ≈ Q(3.5) ≈ 0.0002326 (близько 0.023%)
```

Комутація каналів дозволила б підключити лише 20 абонентів. Комутація пакетів підключає 100 абонентів з імовірністю перевантаження `2.3 · 10⁻⁴`. Виграш мультиплексування становить `G = 100 / 20 = 5.0×`.

#### Строге виведення межі Чернова через твірну функцію моментів

Для отримання верхньої оцінки хвоста розподілу без симетричного припущення нормального закону скористаємося нерівністю Маркова для довільного `s > 0`:

```
P(X ≥ M) = P(e^(s · X) ≥ e^(s · M)) ≤ E[e^(s · X)] / e^(s · M)
```

Твірна функція моментів для біноміальної випадкової величини `X = ∑_{i=1}^N Y_i`, де `Y_i` — незалежні величини Бернуллі `P(Y_i = 1) = p`:

```
E[e^(s · Y_i)] = (1 - p) · e⁰ + p · e^s = 1 - p + p · e^s
E[e^(s · X)] = ∏_{i=1}^N E[e^(s · Y_i)] = (1 - p + p · e^s)^N
```

Підставляючи у нерівність Маркова:

```
P(X ≥ M) ≤ exp(-s · M) · (1 - p + p · e^s)^N
P(X ≥ M) ≤ exp( - [ s · M - N · ln(1 - p + p · e^s) ] )
```

Щоб отримати найточнішу (найнижчу) верхню межу, мінімізуємо показник експоненти за параметром `s > 0`. Диференціюємо функцію `g(s) = s · M - N · ln(1 - p + p · e^s)` та прирівнюємо до нуля:

```
g'(s) = M - (N · p · e^s) / (1 - p + p · e^s) = 0
M · (1 - p + p · e^s) = N · p · e^s
M · (1 - p) = (N - M) · p · e^s
e^(s*) = (M / (N - M)) · ((1 - p) / p)
```

Позначимо частку активних користувачів від загальної кількості як `a = M / N`. Тоді:

```
e^(s*) = (a / (1 - a)) · ((1 - p) / p)
s* = ln( (a / (1 - a)) · ((1 - p) / p) )
```

Підставляючи `s*` назад у вираз для `P(X ≥ M)`, отримуємо формулу великих відхилень Чернова:

```
P(X ≥ M) ≤ exp(-N · D(a || p))
```

де `D(a || p)` — дивергенція Кульбака–Лейблера (відносна ентропія) між розподілами Бернуллі з параметрами `a` та `p`:

```
D(a || p) = a · ln(a / p) + (1 - a) · ln((1 - a) / (1 - p))
```

Ця формула строго доводить: **ймовірність перевантаження комутатора спадає експоненційно зі зростанням масштабу системи `N`** за умови фіксованої частки надлишковості `a > p`.

### 7. Теорія ефективної смуги пропускання для неоднорідного трафіку

У реальних мережах джерела трафіку неоднорідні: відеопотоки мають пік 15 Мбіт/с з `p = 0.35`, веб-трафік — 2 Мбіт/с з `p = 0.05`, а телеметрія IoT — 20 кбіт/с з `p = 0.01`.

Теорія **ефективної смуги пропускання** (*Effective Bandwidth Theory*, запропонована Френком Келлі) призначає кожному типу джерела `j` число `α_j(θ)`, що лежить суворо між його середньою та піковою швидкістю:

```
R_average,j ≤ α_j(θ) ≤ R_peak,j
```

Для марковського ON-OFF джерела ефективна смуга при параметрі простору станів `θ` (який визначається допустимою ймовірністю переповнення буфера `P_loss ≤ e^(-θ · B)`) обчислюється аналітично:

```
α(θ) = (1 / θ) · ln(1 - p + p · e^(θ · R_peak))
```

Умова безаварійної роботи мережі для `K` різних класів трафіку (де клас `j` налічує `N_j` джерел) набуває лінійного вигляду:

```
∑_{j=1}^K N_j · α_j(θ) ≤ C
```

**Числовий приклад багатокласового мультиплексування:**

Магістральний лінк: `C = 100` Мбіт/с.
- Клас 1 (Відео): `R_peak = 15` Мбіт/с, `p = 0.35`. Ефективна смуга `α_1 ≈ 7.8` Мбіт/с.
- Клас 2 (Web): `R_peak = 2` Мбіт/с, `p = 0.05`. Ефективна смуга `α_2 ≈ 0.35` Мбіт/с.
- Клас 3 (IoT): `R_peak = 0.02` Мбіт/с, `p = 0.01`. Ефективна смуга `α_3 ≈ 0.001` Мбіт/с.

Якщо мережа повинна обслуговувати 8 потоків відео (`8 · 7.8 = 62.4` Мбіт/с), залишок смуги `100 - 62.4 = 37.6` Мбіт/с дозволяє одночасно підключити:

```
N_web = 37.6 / 0.35 ≈ 107 веб-користувачів
```

При комутації каналів 8 потоків відео вимагали б `8 · 15 = 120` Мбіт/с (перевантаження вже на стадії відео), і жодного веб-користувача підключити не вдалося б.

### 8. Наближення важкого навантаження (Heavy-Traffic) та формула Кінгмана

Коли утилізація лінії `ρ` наближається до 1, звичайна марковська модель перестає адекватно описувати поведінку буфера, якщо розподіли інтервалів надходження та розмірів пакетів мають довільний вигляд (модель `G/G/1`).

У цьому випадку середній час очікування в черзі пакетокомутатора обчислюється за **формулою Кінгмана** (*Kingman's formula*):

```
W_q ≈ (ρ / (1 - ρ)) · ((c_a² + c_s²) / 2) · (1 / μ)
```

де:
- `c_a = σ_a / E[a]` — коефіцієнт варіації інтервалів надходження пакетів;
- `c_s = σ_s / E[s]` — коефіцієнт варіації часу обслуговування (розміру пакетів).

Формула Кінгмана показує важливий практичний висновок: затримка зростає не лише через навантаження `ρ`, але й прямо пропорційно дисперсії розмірів пакетів. Якщо мережа передає суміш крихітних 64-байтних ACK-пакетів та гігантських 9000-байтних Jumbo-кадрів (`c_s² >> 1`), затримка черги зростає у кілька разів порівняно з передачею стандартизованих пакетів фіксованої довжини (як це реалізовано в комірках ATM).

### 9. Фрактальний трафік та модель Норроса

У реальних мережах агрегація тисяч незалежних джерел не приводить до пуассонівського згладжування, якщо окремі джерела мають важкі хвости розподілу тривалості сесій (розподіл Парето). Такий трафік стає самоподібним (*Self-Similar*) і моделюється дробовим броунівським рухом (**FBM**, *Fractional Brownian Motion*).

Згідно з **формулою Норроса** (*Norros formula*, 1994), ймовірність того, що довжина черги в буфері перевищить рівень `B`, спадає не експоненційно (як у моделях Маркова `e^(-θ · B)`), а за напівекспоненційним законом Вейбулла:

```
P(Q > B) ≈ exp( - ( (C - m_tr)^(2 · H) ) / ( 2 · a · m_tr · (H^H · (1 - H)^(1 - H))² ) · B^(2 · (1 - H)) )
```

де:
- `H` — параметр Херста (`0.5 < H < 1.0`, де `H = 0.5` відповідає звичайному випадковому блуканню без пам'яті, а `H ≈ 0.8–0.9` типовий для Інтернет-магістралей);
- `m_tr` — середня швидкість надходження трафіку;
- `a` — коефіцієнт дисперсії.

Оскільки показник степеня `2 · (1 - H) < 1` при `H > 0.5`, хвіст черги спадає набагато повільніше за класичну експоненту. Це означає, що збільшення розміру буфера `B` дає значно менший захист від переповнення, ніж передбачали марковські моделі, і єдиним надійним засобом стабілізації мережі є підтримка проектного коефіцієнта завантаження `ρ ≤ 0.65–0.70`.
