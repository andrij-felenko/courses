# 🧮 Розрахунок часового бюджету рядка та піксельного такту OSD

Точність позиціонування символів телеметрії на аналоговому екрані залежить від суворого дотримання часових інтервалів відеорядка. Розглянемо виведення розрахункових формул для обчислення частоти піксельного такту, часового бюджету, вертикальної роздільності та допусків фазового джитеру для аналогових відеостандартів PAL та NTSC.

### Математичний вивід часового бюджету рядка PAL

Частота кадрової розгортки визначається фізичними характеристиками передавальної камери та приймального монітора. Загальний період одного відеорядка обчислюється як обернена величина від добутку кількості рядків у повній кадровій сітці `N_{lines}` на частоту змінення кадрів `F_{frame}`.

Для аналогового відеостандарту PAL повний кадр містить `625` рядків при частоті передачі `25` кадрів за секунду. Тоді загальний тривалісний період одного рядка `T_{line}` дорівнює:

```
T_line = 1 / (N_lines · F_frame)      [період рядка через частоту кадрів]
       = 1 / (625 · 25 Гц)            [підстановка параметрів PAL 625 рядків 25 Гц]
       = 1 / 15625 Гц = 64.0 мкс       [підсумкова тривалість рядка]
```

Знайдений часовий інтервал `64.0 мкс` ділиться на чотири послідовні часові фази:

```
T_line = t_hsync + t_back_porch + t_active + t_front_porch

Де:
t_hsync       = 4.7 мкс  [рядковий синхроімпульс спаду напруги]
t_back_porch  = 5.8 мкс  [задня площадка гасіння зі спалахом кольору 4.43 МГц]
t_active      = 52.0 мкс [активна зона відеосигналу камери]
t_front_porch = 1.5 мкс  [передня площадка гасіння]

Перевірка геометричної суми:
T_line = 4.7 + 5.8 + 52.0 + 1.5 = 64.0 мкс
```

### Структура черезрядкової розгортки та кадровий бюджет

В аналоговому відео використовується черезрядкова розгортка (*Interlacing*). Повний кадр PAL з `625` рядків розбивається на два послідовних півкадри (поля):
- **Непарне поле (Field 1):** містить `312.5` рядків (рядки з `1` по `312`);
- **Парне поле (Field 2):** містить `312.5` рядків (рядки з `313` по `625`).

Період одного півкадру `T_{field}` становить:

```
T_field = T_frame / 2                  [тривалість півкадру через кадрову частоту]
        = (1 / 25 Гц) / 2 = 20.0 мс    [підстановка частоти 25 Гц]
```

Із `312.5` рядків кожного поля лише `288` рядків є активними та видимими на екрані. Решта `24.5` рядків припадають на вертикальне кадрове гасіння (*Vertical Blanking Interval*, VBI), під час якого передаються зрівнювальні імпульси та кадровий синхроімпульс `VSYNC` тривалістю `160 мкс` (5 повних рядків).

Таким чином, повна активна вертикальна роздільність кадру PAL становить:

```
N_active_lines = 288 рядків/поле × 2 поля = 576 активних рядків
```

### Порівняльний розрахунок для стандарту NTSC

Для американського та японського відеостандарту NTSC сітка кадру містить `525` рядків, а кадрова частота становить `29.97` кадрів за секунду (точніше `30 / 1.001 Гц`). Період одного рядка NTSC обчислюється так:

```
T_line = 1 / (525 · 29.97003 Гц)      [підстановка параметрів NTSC 525 рядків 29.97 Гц]
       = 1 / 15734.26 Гц ≈ 63.555 мкс  [підсумкова тривалість рядка NTSC]

Часовий розклад компонентів рядка NTSC:
t_hsync       = 4.70 мкс  [рядковий імпульс]
t_back_porch  = 4.70 мкс  [колірний спалах 3.58 МГц]
t_active      = 52.60 мкс [активна зона відеосигналу]
t_front_porch = 1.55 мкс  [передня площадка]

Сума інтервалів:
T_line = 4.70 + 4.70 + 52.60 + 1.55 = 63.55 мкс
```

Активна вертикальна роздільність кадру NTSC містить `240` активних рядків на поле, що дає у сумі `480` активних рядків на кадр при тривалості поля `16.68 мс`.

### Обчислення частоти піксельного такту (Pixel Clock Rate)

Дисплейна сітка монохромного OSD у мікросхемі MAX7456 містить `N_{col} = 30` колонок символів завширшки `W_{char} = 12` пікселів кожна, плюс бічні захисні поля. Загальна кількість графічних точок уздовж активної частини рядка становить `N_{pix} = 360` пікселів.

Для рівномірного розміщення цих пікселів протягом активної зони `t_{active} = 52.0 мкс` частота піксельного генератора `f_{pix}` обчислюється за формулою:

```
f_pix = N_pix / t_active               [формула піксельної частоти]
      = 360 / (52.0 · 10⁻⁶ с)          [підстановка 360 пікселів на 52 мкс]
      = 6 923 076 Гц ≈ 6.92 МГц         [підсумкова піксельна частота]
```

Тривалість одного графічного пікселя `t_{pix}` при частоті `6.92 МГц` становить:

```
t_pix = 1 / f_pix                      [обернена частота]
      = 1 / 6.92 МГц ≈ 144.44 нс       [тривалість пікселя]
```

У мікросхемі MAX7456 використовується подвоєна частота `6.92 МГц × 2 = 13.84 МГц` для забезпечення оверсемплінгу та формування чорної обводки завширшки півпікселя (`72.2 нс`).

### Математичний допуск на джитер горизонтальної синхронізації (Jitter Tolerance)

Якщо фазовий джитер (тремтіння) моменту виявлення синхроімпульсу `HSYNC` аналоговим сепаратором дорівнює `Δt_{jitter}`, це спричиняє горизонтальне виляння символів OSD по екрану. Щоб це тремтіння не перевищувало половини ширини одного пікселя `t_{pix} / 2`, накладається умова на часову стабільність сепаратора:

```
t_pix = 1 / 6.92 МГц ≈ 144.44 нс

Δt_jitter ≤ t_pix / 2                  [умова відсутності тремтіння]
          ≤ 144.44 нс / 2
          ≤ 72.22 нс
```

При перевищенні фазового джитеру за поріг `72.22 нс` вертикальні краї літер почнуть дрижати по горизонталі, створюючи ефект «розмитого» або «кудлатого» шрифту.

### Математична чутливість порогу компаратора до постійного зсуву напруги

Аналоговий сепаратор порівнює відеосигнал із порогом `V_{th} = 0.15 В`. Якщо вхідна напруга відео камери має зсув постійної складової `ΔV_{dc}` через відсутність схеми `DC Clamp`, це призводить до помилки моменту виявлення `HSYNC`.

Час наростання фронту синхроімпульсу від `0.3 В` до `0.0 В` становить `t_{fall} = 250 нс`. Крутизна фронту `S_sync` обчислюється як:

```
S_sync = ΔV / t_fall                   [похідна напруги за часом]
       = (0.3 В - 0.0 В) / 250 нс      [розмах напруги за час спаду]
       = 0.3 В / 250 нс = 1.2 мВ/нс    [крутизна фронту]
```

Тоді помилка затримки синхронізації `Δt_{sync}` від зсуву напруги `ΔV_{dc}` становить:

```
Δt_sync = ΔV_dc / S_sync               [перетворення напруги у час]
        = ΔV_dc / 1.2 мВ/нс
```

Якщо постійна складова зсунеться всього на `50 мВ` (`0.05 В`), помилка затримки дорівнюватиме:

```
Δt_sync = 50 мВ / (1.2 мВ/нс) ≈ 41.67 нс  [часовий зсув розгортки]
```

Помилка у `41.67 нс` становить понад `28%` від ширини пікселя (`144.4 нс`), викликаючи горизонтальний зсув тексту при зміні яскравості кадру.

### Вплив стабільності внутрішнього генератора PLL та температурного дрейфу

Джерелом піксельного такту у мікроконтролерах слугує система фазового автопідстроювання частоти (PLL). Якщо використовувати внутрішній RC-генератор (HSI) замість зовнішнього кварцового резонатора (HSE), температурний дрейф частоти може досягати `1%`.

Розрахуємо горизонтальний зсув зображення при дрейфі частоти на `1%`:

```
Δt_drift = t_active · 0.01             [абсолютна часова похибка]
         = 52.0 мкс · 0.01 = 520 нс

Зсув у пікселях:
N_shift = Δt_drift / t_pix             [зсув сітки у пікселях]
        = 520 нс / 144.44 нс ≈ 3.6 пікселя
```

Зсув на `3.6` пікселя призводить до плавання всієї графічної сітки OSD по горизонталі при нагріванні польотного контролера. Тому для OSD-систем застосування зовнішнього кварцового резонатора з термостабільністю кращою за `20 ppm` є суворо обов'язковим.

### Вимоги до смуги пропускання та часу наростання вихідного підсилювача

Для передачі прямокутних імпульсів OSD-пікселів тривалістю `t_{pix} = 144.44 нс` без розмивання межі час наростання фронту `t_{rise}` повинен становити не більше `10%` від тривалості пікселя:

```
t_rise ≤ 0.10 · t_pix                  [умова прямокутності фронту]
       = 0.10 · 144.44 нс = 14.44 нс ≈ 14.5 нс
```

Необхідна смуга пропускання аналогового вихідного підсилювача `BW` за рівнем `-3 дБ` обчислюється через стандартне співвідношення для однополюсних RC-кіл:

```
BW = 0.35 / t_rise                     [зв'язок смуги підсилювача та часу наростання]
   = 0.35 / (14.44 · 10⁻⁹ с)           [підстановка фронту 14.44 нс]
   = 24 238 227 Гц ≈ 24.2 МГц          [підсумкова смуга пропускання]
```

Звідси випливає схемотехнічна вимога: вихідний операційний підсилювач відеоключа мусить мати смугу підсилення не менше ніж `24.2 МГц` та швидкість наростання напруги `SR > 300 В/мкс`.

> 🔧 **Навіщо це.** Якщо вихідний операційний підсилювач має вузьку смугу (наприклад, стандартні `5 МГц`), фронт перемикання пікселя `14.5 нс` затягнеться до `70 нс`. У результаті білі символи OSD втратять контрастність і розпливуться по зображенню камери сірими плямами.
