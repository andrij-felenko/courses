# 📋 Карта регістрів та SPI-інтерфейс OSD-контролера MAX7456 / AT7456E

Мікросхема MAX7456 (та її енергоефективний аналог AT7456E) є монохромним генератором On-Screen Display із вбудованим аналоговим сепаратором синхросигналу та відеоключами. Керування пристроєм здійснюється через послідовний синхронний інтерфейс SPI (Mode 0: CPOL=0, CPHA=0) з максимальною тактовою частотою шини до `10 МГц`.

Кожна командна транзакція по шині SPI складається з байта адреси та байта даних. Старший біт байта адреси `A7` визначає напрямок передачі: запис у регістр виконується при `A7 = 0` (дійсні адреси `0x00..0x6F`), а читання — при `A7 = 1` (адреси `0x80..0xEF`). Сигнал вибору мікросхеми `CS` (*Chip Select*) встановлюється в низький рівень на весь час транзакції.

### Опис командних регістрів OSD-контролера

Контролер містить 16 доступних для читання й запису конфігураційних регістрів, які визначають режими роботи відеотракту, зсув екранної сітки, параметри дисплейної пам'яті та стан вхідного відеосигналу.

| Адреса (Write) | Назва регістру | Призначення та бітові прапори |
| :--- | :--- | :--- |
| `0x00` | **VM0** (*Video Mode 0*) | Режим відео: `bit 6`: PAL=1 / NTSC=0, `bit 3`: OSD Enable, `bit 1`: Sync Select (Auto/Internal/External), `bit 0`: Soft Reset |
| `0x01` | **VM1** (*Video Mode 1*) | Налаштування яскравості: рівні чорного (`bits 6:4`) та білого (`bits 3:2`) |
| `0x02` | **HOS** (*Horizontal Offset*) | Зсув OSD-сітки по горизонталі у пікселях (`0..63`) |
| `0x03` | **VOS** (*Vertical Offset*) | Зсув OSD-сітки по вертикалі у рядках (`0..31`) |
| `0x04` | **DMM** (*Display Memory Mode*) | Режим пам'яті дисплея: `bit 6`: 16-bit Auto-Inc, `bit 4`: Clear Display Memory, `bit 2`: Invert Pixel Color |
| `0x05` | **DMAH** (*Display Memory Addr High*) | Старший біт адреси символу у дисплейному SRAM (`bit 0`) |
| `0x06` | **DMAL** (*Display Memory Addr Low*) | Молодший байт адреси символу дисплея (`0..255`) |
| `0x07` | **DMDI** (*Display Memory Data In*) | Байт даних для запису коду символу чи атрибута |
| `0x08` | **CMM** (*Character Memory Mode*) | Режим NVM шрифтів: `0xA0` = запис 64-байтного блоку шрифту |
| `0x0A` | **STAT** (*Status Register, Read Only*) | Стан синхронізації: `bit 5`: Loss of Sync, `bit 2`: NVM Busy, `bit 0`: PAL/NTSC Detected |

### Детальний аналіз функцій основних регістрів

#### Регістр режимів відеокодування VM0 (`0x00`)

Регістр `VM0` визначає базову конфігурацію аналогового відеопроцесора. Біт `bit 6 (PAL/NTSC)` обирає формат кадрової розгортки: значення `1` перемикає чип у стандарт PAL (`625` рядків, `30×18` символів ОЗП), а `0` — у NTSC (`525` рядків, `30×16` символів).

Біт `bit 3 (OSD Enable)` є головним вмикачем графіка: при `1` аналоговий відеоключ починає підставляти пікселі у відеопотік камери; при `0` ключ переходить у прозорий режим і пропускає відеосигнал камери без змін. 

Біти `bits 2:1 (Sync Select)` регулюють режим синхронізації:
- Поєднання `00` обирає автоматичний режим (*Auto Sync*), за якого чип синхронізується від камери, а при зникненні відеосигналу самостійно переключається на внутрішній аварійний генератор.
- Поєднання `10` примусово включає внутрішній генератор (режим Stand-alone OSD без камери).
- Поєднання `11` примусово вимагає зовнішнього синхросигналу від камери.

Запис одиниці в `bit 0 (Soft Reset)` виконує програмне скидання чипа, повертаючи всі конфігураційні регістри в стан за замовчуванням.

#### Регістр зсуву та вирівнювання сітки HOS (`0x02`) та VOS (`0x03`)

Регістри `HOS` та `VOS` дозволяють зсувати усю екранну матрицю OSD по горизонталі та вертикалі для ідеального центрування графіки на екранах конкретних окулярів чи моніторів. Регістр `HOS` регулює затримку від спаду `HSYNC` з кроком у півпікселя (від `0` до `63` відліків), а `VOS` — вертикальний зсув з кроком в один відеорядок (від `0` до `31` рядків).

#### Статусний регістр стану аналогового каналу STAT (`0x0A`)

Регістр `STAT` доступний лише для читання по SPI-адресі `0x8A`. Він дозволяє мікроконтролеру відстежувати поточний стан відеосигналу та процесів прошивки:

- `bit 5 (Loss of Sync)`: Прапорець встановлюється в `1`, якщо вхідний аналоговий сепаратор не виявляє імпульсів рядкової синхронізації понад `128 мкс` (сигнал камери втрачено або кабель обірвано).
- `bit 2 (NVM Busy)`: Прапорець встановлюється в `1` під час запису блоків шрифтів у внутрішню енергонезалежну пам'ять EEPROM. Під час дії цього прапорця будь-яка спроба запису по SPI ігнорується.
- `bit 0 (PAL/NTSC Detect)`: Апаратний детектор відеостандарту: `1` свідчить про виявлення сигналу PAL на вході, `0` — сигналу NTSC.

### Пам'ять дисплея SRAM та структура атрибутів символів

Пам'ять дисплея (Display Memory) містить static RAM обсягом 540 осередків для режиму PAL (сітка `30` колонок на `18` рядків) або 480 осередків для NTSC (`30` колонок на `16` рядків). Кожен осередок кодується двома послідовними байтами у пам'яті:

1. **Байт коду символу (Character Code Byte):** Містить індекс знака у шрифтовій таблиці від `0` до `255`.
2. **Байт атрибутів (Attribute Byte):** Визначає індивідуальне відображення символу:
   - `bit 5 (Blink)`: Увімкнення миготіння символу з частотою `1 Гц`.
   - `bit 4 (Invert)`: Інверсія кольорів (білий шрифт стає чорним, а контур — білим).
   - `bit 3 (Local Background Control)`: Включення чорного контуру навколо символу.
   - `bit 2 (Transparent)`: Прозорий фон навколо знака.

```
Послідовність автоінкрементного запису рядка символів у пам'ять Display RAM:

[CS Low] ──► WriteReg(DMM, 0x40) ──► WriteReg(DMAH, 0x00) ──► WriteReg(DMAL, StartAddr)
                                                                       │
┌──────────────────────────────────────────────────────────────────────┘
▼
WriteReg(DMDI, Char_0) ──► WriteReg(DMDI, Char_1) ──► ... ──► WriteReg(DMDI, Char_N) ──► [CS High]
```

### Програмування енергонезалежної пам'яті шрифтів (NVM EEPROM)

Мікросхема містить енергонезалежну пам'ять EEPROM, у якій зберігаються растрові матриці 256 користувацьких символів. Кожен символ складається з прямокутної матриці `12` пікселів завширшки на `18` пікселів заввишки (усього `216` пікселів).

Кожен піксель у пам'яті шрифту кодується `2` бітами:
- `00`: Прозорий піксель (пропускає відео камери);
- `01`: Чорний піксель (напруга `0.3 В`);
- `10`: Білий піксель (напруга `1.0 В`).

Таким чином, один символ вимагає `216 × 2 = 432` біти, які пакуються у `54` байти пам'яті (доповнюються до `64` байтів службовим вирівнюванням). 

Схема запису нового символу в EEPROM вимагає такої послідовності дій:
1. Записати код символу (`0..255`), який замінюється, у регістр `CMAH` (`0x09`).
2. Послідовно записати 64 байти растрової маски через регістри `CMAH`, `CMAL` та `CMDI`.
3. Записати команду `0xA0` у регістр `CMM` (`0x08`) для запуску внутрішнього циклу програмування EEPROM.
4. Очікувати падіння прапорця `STAT[2] (NVM Busy)` у `0` протягом приблизно `12 мс`.

> 🔧 **Навіщо це.** Завдяки автоінкрементному режиму пам'яті (`DMM = 0x40`) мікроконтролер польотного контролера може оновлювати весь екран OSD (540 символів) за одну безперервну SPI-транзакцію тривалістю менше ніж `1.5 мс`. Це дозволяє перемальовувати штучний горизонт зі частотою `50 Гц` без завантаження процесора.
