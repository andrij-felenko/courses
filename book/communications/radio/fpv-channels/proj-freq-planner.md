# ⚙️ Планувальник частот та оптимізатор IMD-free розподілу для FPV

Організація спільних польотів кількох безпілотних авіаційних комплексів на частоті 5.8 ГГц вимагає точного математичного узгодження частотної сітки. Випадковий вибір вільних каналів з екранного меню або використання стандартних кроків смуг Band A/B/E/F неминуче призводить до раптової втрати відеозв'язку. Причина полягає в інтермодуляції 3-го порядку (IMD3): коли два близькі дрони перебувають у повітрі або на старті, їхнє сумарне випромінювання породжує в нелінійних каскадах приймачів комбінаційні частоти, які за амплітудою значно перевищують слабкий корисний сигнал далекого третього пілота.

Нижче наведено повний інженерний розбір задачі аналізу довільного частотного плану, математичні критерії виявлення колізій, алгоритм комбінаторного пошуку безконфліктного розподілу каналів (IMD-Free Channel Planner) мовами C та C++, протоколи інтеграції з польотними контролерами, особливості роботи сучасних приймачів із синхронним відновленням кадрів, методику польового контролю спектра за допомогою SDR-аналізаторів, стендове вимірювання IP3 та аналіз апаратних крайових випадків.

---

## Постановка задачі та критерії конфліктності

Нехай задано множину з `N` частот передавачів `F = {f₁, f₂, ..., f_N}` (у МГц), які планується використовувати одночасно на одному льотному майданчику.

Для забезпечення безперебійного прийому відеоінформації алгоритм перевіряє три рівні електромагнітної сумісності (EMC):

### 1. Прямий збіг частот (Co-Channel Collision)

```
|f_i − f_j| = 0  (для будь-яких i ≠ j)
```

Два передавачі налаштовані на ту саму несучу частоту. У широкосмуговій частотній модуляції (WFM) спрацьовує ефект захоплення FM: приймач декодує лише той сигнал, амплітуда якого на вході детектора більша щонайменше на 1.5–3.0 дБ. Якщо дрони маневрують, потужніший сигнал миттєво глушить слабший, викликаючи повний зрив кадрової синхронізації та «сніг» на екрані другого пілота.

### 2. Конфлікт сусідніх каналів (Adjacent Channel Interference, ACI)

```
|f_i − f_j| < Δf_guard_adj
```

Ширина смуги аналогового композитного відеосигналу CVBS стандарту PAL або NTSC разом із піднесною звуку (6.0–6.5 МГц) за правилом Карсона становить `B_RF = 2·(Δf_peak + f_max) ≈ 17–22 МГц`. На рівні згасання −20 дБ спектральні «спідниці» передавача займають смугу близько 20–25 МГц. 

Якщо відстань між сусідніми каналами `|f_i − f_j|` менша за захисний інтервал `Δf_guard_adj = 25–30 МГц`, бічні пелюстки потужнішого передавача частково потрапляють у смугу пропускання фільтра проміжної частоти (IF) сусіднього приймача. Це проявляється як плаваючі горизонтальні чорні смуги, вибивання кольору або фоновий гул у звуковому каналі.

### 3. Двотонова інтермодуляція 3-го порядку (Two-Tone IMD3)

```
|(2·f_i − f_j) − f_k| < Δf_guard_imd  (для будь-яких i ≠ j та k ∉ {i, j})
```

Кубічна нелінійність вхідного малошумного підсилювача (LNA) та змішувача приймача формує паразитні продукти на частотах `2·f_i − f_j` та `2·f_j − f_i`. Якщо обчислена комбінаційна частота потрапляє у захисний інтервал `Δf_guard_imd` (зазвичай 10–15 МГц) відносно частоти третього пілота `f_k`, приймач пілота `k` виявляється заблокованим, навіть якщо передавачі `i` та `j` розташовані за сотні мегагерців від його номінальної частоти.

### 4. Тритонова інтермодуляція 3-го порядку (Triple-Beat IMD3)

```
|(f_i + f_j − f_k) − f_m| < Δf_guard_imd  (для всіх різних індексів i, j, k, m)
```

При одночасному польоті чотирьох і більше дронів нелінійне перемножування трьох незалежних коливань генерує потрійні продукти інтермодуляції. Математично їхня амплітуда вдвічі вища (+6 дБ за потужністю) за двотонові продукти, що створює високу щільність паразитних піків у робочому діапазоні 5.8 ГГц.

## Математична структура алгоритму пошуку

Алгоритм оптимізації розв'язує задачу знаходження підмножини розміру `N` із пулу `M = 48` доступних каналів (Bands A, B, E, F, R, L), яка задовольняє наступну оптимізаційну функцію мети:

```
Знайти: F* ⊂ ALL_CHANNELS, |F*| = N
Максимізувати: min_{i ≠ j} |f_i − f_j|
За обмежень:
  1. direct_conflicts(F*) = 0
  2. adjacent_conflicts(F*) = 0  (при порозі min_adj_mhz)
  3. imd3_two_tone_conflicts(F*) = 0  (при порозі imd_guard_mhz)
  4. imd3_three_tone_conflicts(F*) = 0 (при порозі imd_guard_mhz)
```

Повний перебір вимагає перевірки кількості комбінацій `C(M, N) = M! / (N! · (M − N)!)`. Для `N = 4` кількість варіантів становить `C(48, 4) = 194 580`, для `N = 6` — `C(48, 6) = 12 271 512`, а для `N = 8` — `C(48, 8) = 377 348 994`.

Для забезпечення миттєвої роботи на мікроконтролерах польотних стеків та наземних станцій застосовано алгоритм пошуку з відсіканням гілок (Branch-and-Bound / Backtracking):
- Канали вхідного пулу сортуються за зростанням частоти;
- Під час додавання кожного нового кандидата `f_new` до поточного набору довжиною `k < N` одразу перевіряються обмеження на мінімальний сусідній інтервал `|f_new − f_last| ≥ min_adj_mhz` та всі часткові комбінації IMD3 з уже обраними каналами;
- Якщо хоча б одне обмеження порушено, вся подальша гілка дерева рекурсії відсікається без заглиблення. Це скорочує кількість ітерацій на 3–4 порядки.

typedef struct {
    int pilot_count;
    int freqs[MAX_PILOTS];
    char labels[MAX_PILOTS][32];
} FrequencyPlan;

typedef struct {
    int direct_conflicts;
    int adjacent_conflicts;
    int imd3_two_tone_conflicts;
    int imd3_three_tone_conflicts;
    int min_spacing_mhz;
} ConflictReport;

/* Перевірка набору частот на наявність колізій */
ConflictReport analyze_plan(const FrequencyPlan *plan, int min_adj_mhz, int imd_guard_mhz, bool verbose) {
    ConflictReport report = {0, 0, 0, 0, 9999};
    int n = plan->pilot_count;

    /* 1. Перевірка сусідніх та прямих каналів */
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            int diff = abs(plan->freqs[i] - plan->freqs[j]);
            if (diff < report.min_spacing_mhz) {
                report.min_spacing_mhz = diff;
            }
            if (diff == 0) {
                report.direct_conflicts++;
                if (verbose) {
                    printf("  [КОЛІЗІЯ] Прямий збіг: %s та %s (%d МГц)\n",
                           plan->labels[i], plan->labels[j], plan->freqs[i]);
                }
            } else if (diff < min_adj_mhz) {
                report.adjacent_conflicts++;
                if (verbose) {
                    printf("  [УВАГА] Недостатній інтервал: %s та %s (Δf = %d МГц < %d МГц)\n",
                           plan->labels[i], plan->labels[j], diff, min_adj_mhz);
                }
            }
        }
    }

    /* 2. Перевірка двотонового IMD3: 2*f1 - f2 */
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            if (i == j) continue;
            int f_imd = 2 * plan->freqs[i] - plan->freqs[j];
            for (int k = 0; k < n; ++k) {
                if (k == i || k == j) continue;
                int diff = abs(f_imd - plan->freqs[k]);
                if (diff < imd_guard_mhz) {
                    report.imd3_two_tone_conflicts++;
                    if (verbose) {
                        printf("  [IMD3 2-Tone] 2·%s − %s = %d МГц б'є в %s (%d МГц), похибка %d МГц\n",
                               plan->labels[i], plan->labels[j], f_imd,
                               plan->labels[k], plan->freqs[k], diff);
                    }
                }
            }
        }
    }

    /* 3. Перевірка тритонового IMD3: f1 + f2 - f3 */
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            for (int k = 0; k < n; ++k) {
                if (k == i || k == j) continue;
                int f_triple = plan->freqs[i] + plan->freqs[j] - plan->freqs[k];
                for (int m = 0; m < n; ++m) {
                    if (m == i || m == j || m == k) continue;
                    int diff = abs(f_triple - plan->freqs[m]);
                    if (diff < imd_guard_mhz) {
                        report.imd3_three_tone_conflicts++;
                        if (verbose) {
                            printf("  [IMD3 3-Tone] %s + %s − %s = %d МГц б'є в %s (%d МГц), похибка %d МГц\n",
                                   plan->labels[i], plan->labels[j], plan->labels[k],
                                   f_triple, plan->labels[m], plan->freqs[m], diff);
                        }
                    }
                }
            }
        }
    }

    return report;
}

}};

struct ConflictSummary {
    int co_channel_count = 0;
    int adjacent_count = 0;
    int imd3_2tone_count = 0;
    int imd3_3tone_count = 0;
    int min_spacing_mhz = 9999;

    [[nodiscard]] bool is_clean() const noexcept {
        return co_channel_count == 0 && adjacent_count == 0 &&
               imd3_2tone_count == 0 && imd3_3tone_count == 0;
    }
};

class FrequencyPlanner {
public:
    static ConflictSummary evaluate(std::span<const FpvChannel> plan,
                                    int min_adjacent_mhz = 25,
                                    int imd_guard_mhz = 10,
                                    bool verbose = true) {
        ConflictSummary summary;
        const size_t n = plan.size();

        /* 1. Аналіз попарного рознесення */
        for (size_t i = 0; i < n; ++i) {
            for (size_t j = i + 1; j < n; ++j) {
                const int diff = std::abs(plan[i].freq_mhz - plan[j].freq_mhz);
                summary.min_spacing_mhz = std::min(summary.min_spacing_mhz, diff);

                if (diff == 0) {
                    summary.co_channel_count++;
                    if (verbose) {
                        std::cout << "  [КОЛІЗІЯ] Прямий збіг: " << plan[i].format()
                                  << " та " << plan[j].format() << "\n";
                    }
                } else if (diff < min_adjacent_mhz) {
                    summary.adjacent_count++;
                    if (verbose) {
                        std::cout << "  [УВАГА] Недостатній інтервал: " << plan[i].format()
                                  << " та " << plan[j].format() << " (Δf = " << diff << " МГц)\n";
                    }
                }
            }
        }

        /* 2. Аналіз 2-тонового IMD3 */
        for (size_t i = 0; i < n; ++i) {
            for (size_t j = 0; j < n; ++j) {
                if (i == j) continue;
                const int f_imd = 2 * plan[i].freq_mhz - plan[j].freq_mhz;
                for (size_t k = 0; k < n; ++k) {
                    if (k == i || k == j) continue;
                    const int diff = std::abs(f_imd - plan[k].freq_mhz);
                    if (diff < imd_guard_mhz) {
                        summary.imd3_2tone_count++;
                        if (verbose) {
                            std::cout << "  [IMD3 2-Tone] 2·" << plan[i].format() << " − "
                                      << plan[j].format() << " = " << f_imd << " МГц б'є в "
                                      << plan[k].format() << " (похибка " << diff << " МГц)\n";
                        }
                    }
                }
            }
        }

        /* 3. Аналіз 3-тонового IMD3 */
        for (size_t i = 0; i < n; ++i) {
            for (size_t j = i + 1; j < n; ++j) {
                for (size_t k = 0; k < n; ++k) {
                    if (k == i || k == j) continue;
                    const int f_triple = plan[i].freq_mhz + plan[j].freq_mhz - plan[k].freq_mhz;
                    for (size_t m = 0; m < n; ++m) {
                        if (m == i || m == j || m == k) continue;
                        const int diff = std::abs(f_triple - plan[m].freq_mhz);
                        if (diff < imd_guard_mhz) {
                            summary.imd3_3tone_count++;
                            if (verbose) {
                                std::cout << "  [IMD3 3-Tone] " << plan[i].format() << " + "
                                          << plan[j].format() << " − " << plan[k].format()
                                          << " = " << f_triple << " МГц б'є в "
                                          << plan[m].format() << " (похибка " << diff << " МГц)\n";
                            }
                        }
                    }
                }
            }
        }

        return summary;
    }

    /* Пошук оптимального безконфліктного набору для N пілотів */
    static std::optional<std::vector<FpvChannel>> find_best_allocation(
            std::span<const FpvChannel> pool,
            size_t target_pilots,
            int min_adjacent_mhz = 30,
            int imd_guard_mhz = 12) {
        
        std::vector<FpvChannel> current;
        std::vector<FpvChannel> best_result;
        int best_spacing = 0;

        auto backtrack = [&](auto& self, size_t start_idx) -> void {
            if (current.size() == target_pilots) {
                auto report = evaluate(current, min_adjacent_mhz, imd_guard_mhz, false);
                if (report.is_clean() && report.min_spacing_mhz > best_spacing) {
                    best_spacing = report.min_spacing_mhz;
                    best_result = current;
                }
                return;
            }

            for (size_t i = start_idx; i < pool.size(); ++i) {
                current.push_back(pool[i]);
                self(self, i + 1);
                current.pop_back();
            }
        };

        backtrack(backtrack, 0);

        if (!best_result.empty()) {
            return best_result;
        }
        return std::nullopt;
    }
};

## Інтеграція з польотними контролерами та протоколами керування

Розрахований безконфліктний частотний план необхідно оперативно передати на борт кожного БПЛА без ручного перемикання DIP-перемикачів чи навігації через OSD перед стартом.

### 1. Автоматизація через протокол MSP (MultiWii Serial Protocol v2)

### 2. Синхронізація через ExpressLRS (ELRS VTX Backpack)

У сучасних системах радіокерування ExpressLRS передавальний модуль пульта (TX) та відеоокуляри пілота (VRX) містять допоміжні бездротові чипи ESP8285 (Backpack), об'єднані по протоколу ESP-NOW на частоті 2.4 ГГц.

При виборі польотної моделі на пульті:
- Пульт надсилає на борт команду зміни каналу VTX через службові пакети CRSF (Crossfire Protocol, `CRSF_FRAMETYPE_COMMAND` із підтипом `CRSF_COMMAND_SUBCMD_VTX`);
- Одночасно передавальний модуль через радіоканал Backpack транслює частоту на приймальний модуль окулярів пілота (VRX);
- Приймач окулярів миттєво переналаштовує свій гетеродин на призначену частоту, гарантуючи, що пілот і дрон завжди перебувають на одному каналі без ризику випадкового включення на чужу частоту.

## Особливості приймачів із синхронним відновленням кадрів

У традиційних аналогових приймачах (наприклад, класичному модулі RX5808) вихідний відеотракт містить простий апаратний комутатор Diversity, який раз на кілька кадрів порівнює напругу RSSI (індикатор рівня сигналу) двох антен і перемикає вихід на антену з сильнішим сигналом. У момент перемикання утворюється видимий стрибок кадру або чорна смуга.

Сучасні цифрово-обробні аналогові приймачі (ImmersionRC RapidFIRE, TBS Fusion, Skyzone SteadyView) працюють за принципом **піксельного та рядкового зшивання (Video Fusion / Sync Re-lock)**:

1. **Синхронізація розгортки:** два незалежні приймальні тракти оцифровують композитний сигнал CVBS за допомогою високошвидкісних АЦП;
2. **Відновлення імпульсів синхронізації:** внутрішній процесор обробки сигналів (DSP) аналізує горизонтальні синхроімпульси рядків (15.625 кГц для PAL) та кадровий гасильний імпульс;
3. **Реконструкція кадру:** якщо на одній із антен сигнал спотворюється через багатопроменеве інтерференційне завмирання або короткочасний сплеск IMD3, процесор не перемикає екран повністю, а замінює пошкоджені фрагменти рядка неушкодженими пікселями з іншого приймального тракту.

**Вплив IMD3 на Fusion-приймачі:** хоча алгоритми реконструкції ефективно усувають короткочасні випадання сигналу через рух антени, вони виявляються безсилими проти постійних інтермодуляційних завад. Постійний продукт IMD3 порушує фазове автопідлаштування генератора рядкової розгортки DSP-процесора, викликаючи повне «заморожування» або штучне спотворення геометрії кадру.

## Польовий моніторинг ефіру за допомогою SDR-аналізаторів

Перед початком групових польотів або бойового чергування розрахований частотний план підлягає обов'язковій перевірці в реальному часі за допомогою портативних програмно-визначених радіоприймачів (SDR, від англ. *Software-Defined Radio*) або компактних аналізаторів спектра (tinySA Ultra, HackRF One, RF Explorer 6G Combo).

Методика польового тестування включає наступні кроки:

1. **Оцінка фонового шуму (Noise Floor Survey):**
   Аналізатор спектра налаштовується на діапазон 5600–6000 МГц із роздільною здатністю RBW = 100 кГц. Фіксується рівень фонових шумів від базових станцій мобільного зв'язку, систем Wi-Fi 5 ГГц (канали 149–165) та радарів. Канали з шумовою полицею вище −85 дБм виключаються з пулу планувальника.

2. **Почергове ввімкнення передавачів (Step-by-Step Bring-up):**
   Дрони вмикаються по одному на мінімальній потужності (25 мВт). Для кожного VTX спектроаналізатор фіксує точну центральну частоту (перевірка дрейфу кварцового генератора, який у дешевих передавачах може досягати ±3–5 МГц) та ширину спектральної смуги.

3. **Стрес-тест на інтермодуляцію (IMD Stress Test):**
   Два дрони з увімкненими передавачами розташовують на відстані 2 метрів від приймальної антени аналізатора. На водоспаді (Waterfall) спектра спостерігають появу бічних спектральних спалахів на частотах `2·f₁ − f₂` та `2·f₂ − f₁`. Якщо рівень паразитного піку перевищує −70 дБм на розрахованій частоті третього дрона, коригують частотний розподіл або змінюють просторову орієнтацію антен.

## Стендове вимірювання IP3 приймачів та ретрансляційна топологія

Для точного інженерного аудиту приймальних модулів у лабораторних умовах застосовують метод двох генераторів (Two-Tone Generator Test):
1. Два високочастотні генератори сигналів налаштовують на частоти `f₁ = 5740 МГц` та `f₂ = 5777 МГц` (рознесення `Δf = 37 МГц`, аналогічно до Raceband);
2. Сигнали об'єднуються резистивним або спрямованим дільником потужності (Power Combiner) із високою міжпортовою ізоляцією (> 25 дБ), щоб виключити паразитну інтермодуляцію всередині самих генераторів;
3. Об'єднаний сигнал через прецизійний ступінчастий атенюатор подається на ВЧ-вхід тестованого приймача;
4. За допомогою вимірювача потужності або спектроаналізатора, підключеного до виходу першого змішувача тракту, фіксують зростання амплітуди основного тону та паразитного продукту `2·f₁ − f₂ = 5703 МГц`. Точка перетину графіків на логарифмічній площині дає точне експериментальне значення `IIP3` конкретного екземпляра приймача.

### Топологія ретрансляторів (Ground-Air-Air Repeaters)

При використанні наземних або повітряних ретрансляторів, де на одній щоглі чи борту одночасно встановлено приймач 5.8 ГГц (Downlink із дрона) та передавач 5.8 ГГц (Re-broadcast на командний пункт):
- Мінімальне просторове рознесення антен ретранслятора повинно складати не менше **1.5–2.0 метрів по вертикалі** (вертикальне рознесення забезпечує на 15–20 дБ вище згасання, ніж горизонтальне, завдяки нулям діаграми спрямованості колінеарних антен уздовж осі);
- Використовують ортогональну поляризацію: прийом на антену RHCP, ретрансляція — на антену LHCP або лінійної вертикальної поляризації;
- Частотний розрив між вхідним і вихідним каналом ретранслятора має становити **не менше 150–200 МГц** (наприклад, прийом на каналі R1 5658 МГц, передача — на каналі R8 5917 МГц або смузі Band L).

## Інженерний аналіз результатів та типові пастки

Результати виконання алгоритму наочно демонструють фундаментальні обмеження радіоефіру:

1. **Небезпека рівномірних сіток із кроком 20 МГц (Band F / Band A):**
   При спробі одночасного польоту 4 пілотів на каналах F1 (5740), F2 (5760), F3 (5780) та F4 (5800) виникає цілий каскад взаємних накладень:
   - `2·F2 − F1 = 5780 МГц` — точний збіг із каналом F3;
   - `2·F3 − F2 = 5800 МГц` — точний збіг із каналом F4;
   - `2·F3 − F4 = 5760 МГц` — зворотний удар у канал F2;
   - Тритонові комбінації `F1 + F4 − F2 = 5780 МГц` вчетверо перевищують за рівнем потужності двотонові продукти.
   У такій конфігурації стабільний політ неможливий: як тільки дрони зближуються в повітрі, канали F3 та F4 повністю зникають.

2. **Оптимальна конфігурація для 4 пілотів (R1, R2, R4, R7):**
   Використання каналів Raceband 1 (5658 МГц), 2 (5695 МГц), 4 (5769 МГц) та 7 (5880 МГц) формує нерівномірні інтервали:
   - `R2 − R1 = 37 МГц`;
   - `R4 − R2 = 74 МГц`;
   - `R7 − R4 = 111 МГц`.
   Усі міжчастотні різниці є кратними, але взаємно унікальними (`37 ≠ 74 ≠ 111`). У результаті жодна комбінація 2-тонового або 3-тонового IMD3 не потрапляє у робочі смуги активних пілотів, забезпечуючи максимальну дальність і чистоту відео для всіх чотирьох учасників.

3. **Проблема 6 і більше пілотів (Межа діапазону 5.8 ГГц):**
   Пошук за алгоритмом Голомба показує, що розмістити 6 або більше аналогових каналів зі смугою 20 МГц у межах стандартного діапазону 5650–5950 МГц з абсолютною відсутністю IMD3 математично неможливо через брак ширини спектра (потрібна смуга понад 450 МГц).
   Для безпечної організації польотів 6–8 пілотів частотний поділ обов'язково комбінують із просторовою поляризаційною селекцією:
   - Непарні канали (R1, R3, R5, R7) оснащують антенами правої кругової поляризації (RHCP);
   - Парні канали (R2, R4, R6, R8) оснащують антенами лівої кругової поляризації (LHCP).
   Це створює додаткові 18–25 дБ крос-поляризаційної розв'язки, що придушує продуктові биття на вході приймача нижче рівня теплового шуму.

4. **Апаратні пастки потужності та теплового режиму:**
   - **Асиметрія потужностей (Near-Far Problem):** якщо один пілот увімкне передавач на потужність 1 Вт (+30 дБм), а інший — на 25 мВт (+14 дБм), різниця рівнів сигналів на старті перевищить динамічний діапазон вхідного LNA приймача, викликаючи повну десенсибілізацію слабшого каналу незалежно від обраної частоти. Усі пілоти групи повинні літати на однаковій мінімально достатній потужності (25–200 мВт).
   - **Випромінювання в режимі PitMode:** увімкнення дрона на піт-стопі без активації PitMode призводить до короткочасного викиду повної потужності під час калібрування PLL синтезатора, що миттєво збиває відео пілота, який перебуває у повітрі на цій або сусідній частоті.
   - **Просторова відстань між базовими станціями:** відеоокуляри та наземні ретранслятори пілотів повинні бути фізично рознесені на відстань не менше 2–3 метрів один від одного. Гетеродини сусідніх приймальних модулів RX5808 мають паразитне випромінювання через власні приймальні антени на частоті `f_LO = f_RF − 480 МГц` (або `f_RF + 480 МГц`). При близькому розташуванні антен це випромінювання створює додатковий шумовий фон для сусідніх приймачів.
   - **Деградація осьового коефіцієнта (Axial Ratio) на кутах:** антени кругової поляризації типу Cloverleaf або Pagoda мають ідеальну кругову поляризацію (AR < 1.2) лише в межах головного променя ±45°. При польоті під великими кутами до горизонту кругова поляризація вироджується в еліптичну, внаслідок чого ефективність придушення багатопроменевих відбить падає з 20 дБ до 3–6 дБ.
