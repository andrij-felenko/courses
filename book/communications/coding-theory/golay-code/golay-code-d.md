# Коди Голея

<preknowlist>
- [Відстань Геммінга](book:communications/hamming-distance) — скільки позицій різнять два слова; мінімальна відстань коду вирішує, скільки помилок він виправляє.
- [Лінійні блокові коди](book:communications/linear-block-codes) — k бітів даних доповнюють надлишком до n-бітового слова; звідки береться запис [n, k, d].
- [Досконалі коди](book:communications/perfect-codes) — код, що ділить увесь простір слів на однакові кулі без зазору й без перекриття; межа пакування куль.
- [Біт парності](book:communications/parity-bit) — одна перевірка, що робить число одиниць у слові парним.
</preknowlist>

Кожен дріт радіоканалу, мідний дріт чи оптичне волокно піддається фізичному шуму: теплові коливання електронів, зовнішні електромагнітні завади та спалахи сонячної активності періодично спотворюють сигнальні рівні й перевертають передані біти з нуля в одиницю або навпаки. Якщо передавати повідомлення «як є», будь-яка поодинока завада викривить результат на приймачі. Щоб приймач міг самостійно виявити й полагодити зіпсоване повідомлення без повторного запиту по каналу, до корисних даних домішують перевірний надлишок.

Проте виправлення помилок завжди коштує ресурсів: передача додаткових перевірних бітів вимагає часу, енергії передавача та звужує корисну смугу пропускання. Виникає межове інженерне питання: яким є найкоротший за довжиною двійковий блок, здатний гарантовано виявити й полагодити будь-які три спотворені біти, не витрачаючи при цьому жодного зайвого біта надлишку?

Відповідь диктується геометрією простору двійкових послідовностей. Якщо повідомлення пакується у двійковий блок довжиною `n` бітів, усього існує `2ⁿ` можливих двійкових слів. Коли приймач дістає з дискретного каналу зв'язку слово `r`, воно може відрізнятися від відправленого кодового слова `c` кількома перевернутими позиціями. Кількість цих відмінностей називають [відстанню Геммінга](book:communications/hamming-distance). Якщо код покликаний виправляти до трьох помилок включно, навколо кожного дозволеного кодового слова утворюється подумкова «куля» радіуса 3, яка містить у собі всі можливі варіанти спотворень даного слова.

Щоб декодування було однозначним, кулі різних кодових слів не повинні перекриватися між собою. Якщо якесь спотворене слово потрапить у зони дії двох різних куль, приймач за критерієм максимуму правдоподібності не матиме жодної підстави обрати, до котрого з двох можливих повідомлень його округлювати. Отже, загальна кількість двійкових слів, які займають усі ці кулі, не може перевищувати повного об'єму двійкового простору `2ⁿ`.

## Геометрична межа пакування куль Геммінга

Обчислимо точний об'єм однієї кулі радіуса 3 у `n`-вимірному двійковому просторі. Позначимо через `C(n, k)` кількість сполучень із `n` елементів по `k`. Усі двійкові слова, що віддалені від обраного кодового слова не далі ніж на 3 кроки, складаються з чотирьох послідовних шарів:

```
саме кодове слово (0 помилок):         C(n, 0) = 1
слова з 1 перевернутим бітом:         C(n, 1) = n
слова з 2 перевернутими бітами:       C(n, 2) = n · (n - 1) / 2
слова з 3 перевернутими бітами:       C(n, 3) = n · (n - 1) · (n - 2) / 6
```

Сума цих чотирьох величин визначає загальну кількість слів, які потрапляють усередину кулі радіуса 3: `V(n, 3) = C(n, 0) + C(n, 1) + C(n, 2) + C(n, 3)`. Якщо код передає `k` бітів корисної інформації, він містить `2ᵏ` різних дозволених кодових слів. Кожне з них оточене власною кулею об'єму `V(n, 3)`. Оскільки кулі різних кодових слів не перекриваються, їх сумарний об'єм суворо обмежений загальною кількістю векторів у просторі:

```
2ᵏ · V(n, 3) ≤ 2ⁿ      [нерівність пакування Геммінга]
```

У переважній більшості кодових систем ця нерівність є суворою: між кулями неминуче залишаються «порожні» двійкові вектори, які не потрапляють до кулі жодного кодового слова. Це означає марнування потенціалу коду: перевірні біти витрачено, а деякі варіанти прийнятих слів виявляються «нічийними». Якщо ж сумарний об'єм усіх куль дорівнює точно `2ⁿ`, код називають [досконалим](book:communications/perfect-codes). У досконалому коді немає жодного зазору чи шпарини: кожен можливий двійковий вектор довжини `n` належить кулі одного-єдиного кодового слова.

Підставимо у формулу об'єму значення довжини блока `n = 23`:

```
C(23, 0) = 1                              [центральне кодове слово]
C(23, 1) = 23                             [перший шар: 1 помилка]
C(23, 2) = (23 · 22) / 2 = 253            [другий шар: 2 помилки]
C(23, 3) = (23 · 22 · 21) / 6 = 1771      [третій шар: 3 помилки]

Загальний об'єм кулі V(23, 3) = 1 + 23 + 253 + 1771 = 2048 = 2¹¹
```

Об'єм кулі радіуса 3 навколо 23-бітового слова виявився точним степенем двійки: `2¹¹ = 2048`. Якщо обрати кількість інформаційних бітів `k = 12`, то кількість кодових слів дорівнює `2¹² = 4096`. Підрахуємо загальну кількість охоплених векторів:

```
2¹² куль × 2¹¹ слів у кулі = 2²³ = 8 388 608 слів
```

Добуток точнісінько дорівнює `2²³` — повному об'єму 23-вимірного двійкового простору. Арифметика збігається без жодного залишку чи зазору. Це і є двійковий **код Голея [23, 12, 7]**: [лінійний блоковий код](book:communications/linear-block-codes) довжини `n = 23`, що несе `k = 12` бітів даних, має 11 перевірних бітів та мінімальну відстань Геммінга `d = 7`.

Мінімальна відстань `d = 7` гарантує виправлення трьох помилок, бо за загальною формулою `t = ⌊(d - 1) / 2⌋` отримуємо `t = ⌊6 / 2⌋ = 3`. Два будь-яких кодових слова віддалені одне від одного щонайменше на 7 бітів. Якщо канал переверне 3 біти в одному з них, зсув від оригінального центра становитиме 3 кроки, а до найближчого чужого кодового слова залишиться щонайменше `7 - 3 = 4` кроки. Приймач безпомилково відновить вихідні дані.

![Стільниковий візерунок: код Голея ділить увесь простір слів на однакові осередки без зазору й без перекриття](/book/communications/coding-theory/golay-code/img/perfect-packing.svg)
*Досконале укладання, схематично (справжній простір слів — 23-вимірний). Кожен осередок — одне кодове слово (крапка в центрі) разом з усіма 2047 словами, у які його могли б перетворити не більш як три помилки. Осередки не перекриваються — інакше приймач не знав би, що лагодити, — і не лишають зазору: 4096 осередків по 2048 слів дають рівно 2²³, весь простір.*

Математичне збігання для `V(23, 3) = 2¹¹` є унікальним комбінаторним феноменом. Глибокі дослідження теорії алгебраїчного кодування (теорема Ллойда та результат Зінов'єва–Левенштейна) довели, що крім тривіальних кодів (із 1 кодовим словом або повторенням непарної довжини) та класичних кодів Геммінга, у двійковому світі існує **лише один нетривіальний досконалий код, здатний виправляти понад одну помилку** — двійковий код Голея `[23, 12, 7]`.

## Трійковий родич [11, 6, 5] та відкриття Якобсталя

Окрім двійкового коду, у сімействі Голея існує ще один винятковий об'єкт — **трійковий код Голея [11, 6, 5]**, визначений над полем із трьох елементів `GF(3) = {0, 1, 2}`. Цей код пакує 6 інформаційних трійкових символів у блок довжиною 11 символів, має мінімальну відстань `d = 5` і виправляє будь-які 2 трійкові помилки (`t = ⌊(5-1)/2⌋ = 2`).

Обчислимо об'єм кулі радіуса 2 у 11-вимірному трійковому просторі. Оскільки кожен спотворений символ має 2 можливі варіанти помилки, формулу шар за шаром модифікують множниками `2ⁱ`:

```
C(11, 0) · 2⁰ = 1                                 [кодове слово]
C(11, 1) · 2¹ = 11 · 2 = 22                       [1 помилка: 22 вектори]
C(11, 2) · 2² = 55 · 4 = 220                      [2 помилки: 220 векторів]

Об'єм кулі V₃(11, 2) = 1 + 22 + 220 = 243 = 3⁵
```

Підрахуємо загальну кількість охоплених трійкових векторів для `k = 6` інформаційних символів:

```
3⁶ куль × 3⁵ слів у кулі = 3¹¹ = 177 147 слів
```

Сума збігається точно з `3¹¹` — повному об'єму 11-вимірного трійкового простору. Трійковий код Голея `[11, 6, 5]` є другим нетривіальним досконалим кодом у природі.

Цікаво, що трійковий код був опублікований у журналі спортивних ставок фінським ентузіастом Югані Віртакалліо у 1947 році — за півтора року до публікації Марселя Голея. Детальніше про [історію відкриття Голея та Якобсталя](book:communications/perfect-codes/hist-golay-codes.md) розкрито в історичній вставці.

## Розширений код [24, 12, 8] — космічний стандарт "Вояджерів"

У практичній інженерії непарна довжина блока 23 біти створює незручності для обробки на мікроконтролерах і процесорах, де робота з пам'яттю вирівнюється по межах байтів та 16/32-бітних слів. Щоб полагодити цю несиметрію, до кожного 23-бітового кодового слова додають один додатковий загальний [біт парності](book:communications/parity-bit). У результаті утворюється **розширений двійковий код Голея [24, 12, 8]**.

Додатковий біт парності обчислюється так, щоб загальна кількість одиниць у кожному 24-бітовому кодовому слові стала парною. Додавання одного біта збільшує довжину блока з 23 до 24, залишаючи кількість інформаційних бітів рівною `k = 12`. Проте мінімальна відстань підскакує з 7 до 8 (`d = 8`).

Збільшення мінімальної відстані до парного значення `d = 8` надає коду нову критично важливу якість. Згідно з теорією кодування, код із мінімальною відстанню `d` здатний одночасно виправляти `t` помилок та виявляти `e` помилок за дотримання вимоги:

```
t + e < d      та      t ≤ e
```

Для `d = 8` можна встановити режим `t = 3` та `e = 4`. Це означає, що розширений код Голея `[24, 12, 8]` і далі виправляє будь-які 3 перевернуті біти в блоці, але якщо канал спотворить **рівно 4 біти**, декодер не схибить і не округлить вектор до чужого слова, а чесно виявить факт аварії й підніме прапорець «помилка невиправна, блок зіпсовано».

З енергетичного погляду завадостійке кодування забезпечує так званий **енергетичний виграш кодування** (coding gain). У двійковому симетричному каналі без пам'яті (BSC, Binary Symmetric Channel) ймовірність помилки на біт без кодування згасає повільно при падінні відношення сигналу до шуму `E_b / N_0`. Застосування коду Голея `[24, 12, 8]` дає виграш кодування близько 3 дБ на рівні ймовірності помилки `10⁻⁵`. Це означає, що для досягнення тієї самої надійності зв'язку передавач може випромінювати вдвічі меншу потужність.

З інженерного погляду код `[24, 12, 8]` має ідеальну пропорційність: 12 бітів даних і 12 перевірних бітів. Половина кодового блока повністю захищає іншу половину. Крім того, 24 біти зручно упаковуються у три 8-бітних байти або один 32-бітний регістр процесора.

![Три коди Голея: двійковий [23,12,7], розширений [24,12,8] і трійковий [11,6,5] — параметри, що кожен виправляє і які з них досконалі](/book/communications/coding-theory/golay-code/img/golay-family.svg)
*Родина Голея. Двійковий [23, 12, 7] і трійковий [11, 6, 5] — досконалі: їхні кулі укладають простір без залишку (2¹²·2¹¹ = 2²³ і 3⁶·3⁵ = 3¹¹). Розширений [24, 12, 8] сам уже не досконалий, зате рівно збалансований — половина даних, половина захисту — і саме він захищав знімки «Вояджерів».*

Саме розширений код Голея `[24, 12, 8]` забезпечив успіх легендарної космічної місії NASA з дослідження далеких планет-гігантів апаратами «Вояджер-1» та «Вояджер-2» (Voyager 1 & 2). Під час прольоту поблизу Юпітера (1979) та Сатурна (1980–1981) бортові телевізійні камери знімали кольорові панорами атмосфер та супутників. Передавач апарата мав потужність усього 20 Вт, і на відстані понад мільярд кілометрів радіосигнал приходив на земні антени системи Deep Space Network надзвичайно слабким.

Без кодування відношення сигналу до шуму давало високий рівень помилок, що вкривало б фотографії цифровими плямами. Щоб цього уникнути, кожні 12 бітів графічних даних (пакет із двох 6-бітних відтінків сірого) кодувалися 24-бітним блоком Голея. Декодери на Землі виправляли до 3 помилок у кожному блоці, відновивши чисту картинку планет.

Пізніше, перед підльотом до Урана (1986) та Нептуна (1989), бортові комп'ютери «Вояджерів» перепрограмували з Землі на потужніший каскадний код із [кодом Рід–Соломона](book:communications/reed-solomon). Проте перші кольорові портрети Юпітера й Сатурна людство побачило саме завдяки коду Голея. Сьогодні код `[24, 12, 8]` прописано у стандарті військового короткохвильового радіозв'язку (MIL-STD-188-141) для швидкого встановлення автоматичного з'єднання (ALE, Automatic Link Establishment).

> 🔧 **Навіщо це.** Досконалість коду — це не математична естетика, а жорстка економіка фізичних ресурсів. У дальньому космосі чи в автономних датчиках кожен переданий біт коштує міліджоулів батареї. Досконалий код гарантує, що жоден біт надлишку не витрачається даремно: досягається гранично можливий рівень захисту від завад на вкладені перевірні біти.

## Систематична матриця та алгебраїчний механізм

Будучи лінійним блоковим кодом, код Голея формується шляхом множення 12-бітного вектора інформаційних даних `m` на твірну матрицю `G` розміром 12×24 над полем `GF(2)` (арифметика за модулем 2, де додавання виконується як `XOR`, а множення — як `AND`).

У систематичній формі твірна матриця `G` містить одиничний блок `I₁₂` ліворуч та квадратний перевірний блок `B` розміром 12×12 праворуч:

```
G = [ I₁₂ | B₁₂×₁₂ ]
```

Множення 12-бітного вектора повідомлення `m` на таку матрицю створює 24-бітне кодове слово `c`:

```
c = m · G = m · [ I₁₂ | B ] = [ m | m · B ]
```

Перші 12 бітів кодового слова дослівно повторюють вхідні дані `m`, а наступні 12 бітів утворюють перевірний відбиток `m · B`.

![Розкладка кодового слова: 24 біти в одному uint32, де ліва половина — самі дані, а права — перевірна згортка m·B](/book/communications/coding-theory/golay-code/img/codeword-layout.svg)
*Розкладка слова. Ліва половина — самі дані (систематичний код: якщо помилок не було, повідомлення читається прямо, без декодування). Права — згортка m·B, дванадцять перевірних бітів. Ключова умовність — де тут біт 0: кодер і декодер мусять розуміти її однаково.*

Уся комбінаторна сила коду Голея прихована у будові 12×12 матриці `B`. Вона володіє трьома винятковими алгебраїчними властивостями:

1. **Симетричність:** `B = Bᵀ`. Матриця `B` збігається зі своєю транспонованою копиєю. Рядок `i` матриці `B` тотожний її стовпцю `i`.
2. **Ортогональність над GF(2):** `B · Bᵀ = B² = I₁₂`. Квадрат матриці `B` за модулем 2 дорівнює одиничній матриці `I₁₂`.
3. **Самодуальність та двійчаста парність:** розширений код Голея `[24, 12, 8]` є **самодуальним кодом** (`C = C⊥`), тобто дорівнює своєму ортогональному доповненню. Вага кожного кодового слова ділиться на 4 (є кратною 4: 0, 8, 12, 16 або 24).

![Твірна матриця G систематичного розширеного коду Голея [24, 12, 8] із симетричним перевірним блоком B розміром 12×12](/book/communications/coding-theory/golay-code/img/generator-matrix.svg)
*Будова твірної матриці G = [I₁₂ | B]. Одиничний блок I₁₂ відповідає за пряму передачу 12 бітів даних. Блок B₁₂×₁₂ — симетрична матриця, побудована за допомогою циркулянта квадратичних лишків за модулем 23. Кожен рядок B містить непарну кількість одиниць, що забезпечує парність ваги всіх слів коду.*

Явний вигляд матриці `B` будується на основі теорії чисел. Верхньо-лівий блок розміром 11×11 є циклічною матрицею (циркулянтом), перший рядок якої формується множиною **квадратичних лишків** за модулем 23:

```
Квадратичні лишки mod 23:  1²≡1, 2²≡4, 3²≡9, 4²≡16, 5²≡2, 6²≡13, 7²≡3, 8²≡18, 9²≡12, 10²≡8  (mod 23)
```

Масив із 11 квадратичних лишків `{1, 2, 3, 4, 6, 8, 9, 12, 13, 16, 18}` визначає позиції одиниць у першому рядку 11×11 блоку. Кожен наступний рядок утворюється циклічним зсувом попереднього праворуч, а 12-й рядок та 12-й стовпець заповнюються суцільними одиницями (крім кутової нульки).

Окрім матричного множення, циклічність коду Голея `[23, 12, 7]` дозволяє реалізувати кодування в апаратурі за допомогою **просувного регістра зі зворотним зв'язком** (LFSR, Linear Feedback Shift Register). Поліном-породжувач коду має вигляд `g(x) = x¹¹ + x¹⁰ + x⁶ + x⁵ + x⁴ + x² + 1`. Це дільник многочлена `x²³ - 1` над полем `GF(2)`. Завдяки цьому апаратний кодер може обчислювати 11 перевірних бітів послідовно за 12 тактів просування бітів даних через LFSR-схему на 11 регістрів без збереження матриці в пам'яті.

Детальне [математичне виведення побудови коду Голея](book:communications/golay-code/math-golay-construction.md) через алгебраїчні поля Галуа `GF(2²³)` та геометрію ікосаедра наведено в окремій вставці.

**Числовий приклад кодування повідомлення:**

Простежимо процес кодування на конкретних бітах. Нехай вхідне 12-бітне повідомлення дорівнює `m = 0xB46` (у двійковому записі `1011 0100 0110₂`). Одиничні біти стоять у позиціях 1, 2, 6, 8, 9, 11.

```
m               = 0xB46                         [12 бітів корисних даних]
m · B           = B[1] ⊕ B[2] ⊕ B[6] ⊕ B[8] ⊕ B[9] ⊕ B[11]
                = 0xD1D ⊕ 0xE8E ⊕ 0xF68 ⊕ 0x9DA ⊕ 0x8ED ⊕ 0x7FF
                = 0xA33                         [12 бітів перевірки]
кодове слово c  = [ даних(12) | перевірки(12) ]
                = 0xB46 | (0xA33 << 12)
                = 0xA33B46                     [24-бітне підсумкове слово]
```

Низькі 12 бітів `0xB46` — це самі дані, а високі 12 бітів `0xA33` — обчислений перевірний відбиток. Саме таке 24-бітне слово `0xA33B46` випромінюється у фізичний канал.

![Квадратичні лишки за модулем 23 утворюють круговий поліном для побудови циклічного коду Голея](/book/communications/coding-theory/golay-code/img/qr23-circle.svg)
*Алгебраїчне коріння: 11 квадратичних лишків за модулем 23 утворюють множник ділення x²³ - 1 над GF(2). Ця дуальність між теорією чисел і геометрією коду забезпечує мінімальну відстань 7.*

## Апаратний алгоритм декодування за синдромом

Класичне декодування блокового коду зводиться до обчислення вектора синдрому `s` та пошуку за ним найбільш ймовірного патерну помилки `e`. Прийнятий із зашумленого каналу 24-бітний вектор `r` розбивається на дві 12-бітні половини: `x` (прийняті дані) та `y` (прийнята перевірка).

Синдром `s` є відхиленням між фактично отриманою перевіркою `y` та перевіркою, перерахованою з отриманих даних `B · x`:

```
s = B · x ⊕ y      [вектор синдрому]
```

Через лінійність коду синдром залежить **виключно від вектора помилок `e = [u | v]`**, де `u` — 12-бітний вектор помилок у даних, а `v` — 12-бітний вектор помилок у перевірній частині:

```
s = B · (m ⊕ u) ⊕ (m · B ⊕ v)      [синдром прийнятого слова r = c ⊕ e]
  = (B · m ⊕ m · B) ⊕ (B · u ⊕ v)  [розкриття дужок і дистрибутивність]
  = 0 ⊕ (B · u ⊕ v)                [симетрія B: B·m = m·B, тому B·m ⊕ m·B = 0]
  = B · u ⊕ v                          [нейтральність нульового вектора по XOR]
```

Якщо дані не спотворені (`u = 0, v = 0`), синдром дорівнює нулю `s = 0`. Ненульовий синдром виступає унікальним цифровим підписом помилки.

Оскільки код Голея `[24, 12, 8]` виправляє до 3 помилок, загальна вага вектора помилки не перевищує 3: `вага(u) + вага(v) ≤ 3`. У загальному випадку синдромне декодування вимагало б таблиці на `2¹² = 4096` записів (близько 12 КБ пам'яті). Проте властивість `B² = I` дозволяє виконати декодування за допомогою **каскадного алгоритму з 4 перевірок** усього за 24 байти пам'яті констант.

Помножимо синдром `s` на матрицю `B` ще раз, щоб сформувати другий (дзеркальний) синдром `s₂`:

```
s₂ = B · s = B · (B · u ⊕ v) = B² · u ⊕ B · v = u ⊕ B · v      [оскільки B² = I]
```

Пара синдромів `s = B · u ⊕ v` та `s₂ = u ⊕ B · v` дозволяє миттєво знайти локалізацію помилок за чотирма гілками:

1. **Гілка 1 (усі ≤3 помилки сидять у перевірці, `u = 0`):**
   Тоді `s = v`, і `вага(s) ≤ 3`. Вектор помилки: `e = [ 0 | s ]`.
2. **Гілка 2 (1 помилка в даних, ≤2 у перевірці, `вага(u) = 1`):**
   Вектор `u` є `i`-м одиничним вектором `eᵢ`, а `B · u` дорівнює `i`-му рядку `Bᵢ`. Пробуємо всі `i ∈ [0..11]`: якщо `вага(s ⊕ Bᵢ) ≤ 2`, то вектор помилки дорівнює `e = [ eᵢ | s ⊕ Bᵢ ]`.
3. **Гілка 3 (усі ≤3 помилки сидять у даних, `v = 0`):**
   У другому синдромі `s₂ = u`, і `вага(s₂) ≤ 3`. Вектор помилки: `e = [ s₂ | 0 ]`.
4. **Гілка 4 (1 помилка в перевірці, ≤2 у даних, `вага(v) = 1`):**
   Аналогічно до другої гілки над синдромом `s₂`: якщо для якогось `i ∈ [0..11]` виконується `вага(s₂ ⊕ Bᵢ) ≤ 2`, то вектор помилки дорівнює `e = [ s₂ ⊕ Bᵢ | eᵢ ]`.

Якщо не спрацювала жодна з чотирьох гілок, в блоці виникло 4 або більше помилок. Декодер перериває роботу й відмовляється від виправлення.

**Числовий приклад виправлення трьох помилок:**

Нехай при передачі переданого кодового слова `c = 0xA33B46` канал спотворив біти у позиціях 2 (у даних), 14 і 21 (у перевірці). Приймач дістає зіпсоване слово `r = 0x837B42`.

```
прийняте слово r  = 0x837B42                  [x = 0xB42, y = 0x837]
перший синдром s  = B · 0xB42 ⊕ 0x837 = 0xC8A [вага(s) = 5, гілка 1 не підходить]

перевірка гілки 2 (перебір рядків B):
  для i = 2: s ⊕ B[2] = 0xC8A ⊕ 0xE8E = 0x204  [вага(0x204) = 2 ≤ 2 — спрацювало!]

знайдена помилка e = [ 1<<2 | 0x204 << 12 ] = 0x204004
відновлене слово  = r ⊕ e = 0x837B42 ⊕ 0x204004 = 0xA33B46  [точний оригінал!]
декодовані дані   = 0xA33B46 & 0xFFF = 0xB46
```

Лише кілька XOR-операцій та оцінка ваги бітів дозволили точно відновити вихідне повідомлення без будь-яких громіздких таблиць.

**Числовий приклад виявлення чотирьох помилок:**

Нехай канал перевернув 4 біти в позиціях 1, 5, 17 і 22. На приймач приходить вектор `r`. Початковий синдром `s` має вагу 8. Перевірка 12 рядків у гілці 2 не дає ваги `≤ 2`. Обчислення другого синдрому `s₂ = B · s` дає результат вагою 7 (гілка 3 не підходить), і гілка 4 також не дає ваги `≤ 2`. Алгоритм стікає до кінця каскаду й повертає відмову. Декодер не створив хибного декодування, а виявив непереборну аварію.

![Каскад декодування: порахувати синдром, перевірити його вагу й ваги s після XOR з рядками B, за потреби взяти другий синдром s₂ = B·s; чотири гілки дають виправлення, інакше — чесна відмова](/book/communications/coding-theory/golay-code/img/decode-flow.svg)
*Декодер як водоспад із чотирьох перевірок. Кожна «так»-гілка одразу дає патерн помилки; усі «ні» стікають донизу. Другий синдром s₂ = B·s існує лише завдяки B² = I — саме заради цього ми й брали симетричну B. Останнє «ні» — це не збій, а результат: чотири помилки виявлено.*

Алгоритм виконує лише кілька XOR-операцій та швидких підрахунків бітів (`popcount`). Готовий [практичний кодек Голея](book:communications/golay-code/proj-golay-codec.md) із розбором оптимізацій під інструкції `POPCNT` наведено в практичному проектному файлі.

## Фундаментальні зв'язки з вищою математикою

Код Голея вирізняється серед усіх комбінаторних об'єктів тим, що він стоїть на перетині кількох глибоких галузей чистої математики: теорії графів, теорії решіток та теорії скінченних груп.

![Багато шляхів приводять до одного й того самого єдиного коду Голея](/book/communications/coding-theory/golay-code/img/many-roads.svg)
*Багато шляхів до однієї вершини: розширений код Голея [24, 12, 8] можна побудувати через квадратичні лишки, геометрію додекаедра, системи Штейнера S(5,8,24) або спорадичні групи Матьє M₂₄.*

Серед цих математичних мостів найвідомішими є:

- **Ґратка Ліча (Leech Lattice `Λ₂₄`):** Найщільніше відоме укладання однаковісіньких куль у 24-вимірному евклідовому просторі побудоване безпосередньо з векторів розширеного коду Голея `[24, 12, 8]`. Вектори коду слугують координатами центрів 24-вимірних сфер.
- **Групи Матьє (`M₂₄`, `M₂₃`, `M₂₂`):** Група автоморфізмів (симетрій) розширеного коду Голея є спорадичною простою групою Матьє `M₂₄` порядку 244 823 040. Це одна з найвидатніших математичних груп у класифікації скінченних простих груп.
- **Система Штейнера `S(5, 8, 24)`:** Множина з 759 кодових слів ваги 8 (званих октадами) у коді `[24, 12, 8]` утворює точну комбінаторну систему Штейнера, де будь-які 5 елементів із 24 містяться у винятково єдиній октаді.

Те, що започатковувалося як прикладне інженерне завдання зі стиснення надлишку для радіозв'язку, виявилося фундаментальною константою багатовимірної геометрії. Коди Голея демонструють нерозривний зв'язок між прикладною теорією кодування та найглибшими симетріями математичного всесвіту.
