# Циклічні коди

<preknowlist>
- [Лінійні блокові коди](book:communications/linear-block-codes) — кодове слово з n бітів, запис [n, k] і головна властивість: XOR двох кодових слів — знову кодове слово.
- [Скінченні поля (Галуа)](book:math/finite-fields) — GF(2): коефіцієнти-біти, де й додавання, і віднімання — це XOR (1⊕1 = 0), без переносів.
- [Кільця многочленів](book:math/polynomial-rings) — многочлени додають, множать і ділять з остачею; що означає «один многочлен ділить інший націло».
</preknowlist>

Коли довжина блоку `n` у лінійному коді зростає від кількох бітів до тисяч — як у пам'яті ECC, шинах даних чи мережевих кадрах, — матрична модель кодування починає опиратися залізобудуванню. Твірна матриця `G` розміру `k × n` і перевірна матриця `H` розміру `(n - k) × n` вимагають зберігати мільйони елементів і виконувати векторно-матричне множення на кожному блоці даних. Це коштує тисяч обчислювальних вентилів або сотень тактів процесора. Щоб спростити залізо, коду дають одну додаткову геометричну симетрію: вимагають, щоб циклічний зсув будь-якого кодового слова знову ставав дозволеним кодовим словом. Ця єдина вимога перетворює масивні матриці на один короткий многочлен, а кодер і декодер — на жменьку тригерів зсувного регістра.

### Геометрія та алгебра циклічного зсуву

Код `C` називають **циклічним** (гр. *kýklos* — коло), якщо він є лінійним блоковим кодом `[n, k]` над полем [GF(2)](book:math/finite-fields), і для кожного кодового слова `c = (c₀, c₁, …, cₙ₋₁) ∈ C` його правий циклічний зсув `T(c)` також належить `C`:

```
T(c) = (cₙ₋₁, c₀, c₁, c₂, …, cₙ₋₂) ∈ C
```

Оскільки зсунуте слово `T(c)` само є кодовим словом, його можна зсунути ще раз, діставши `T²(c) ∈ C`, і так далі. За індукцією всі `n` циклічних зсувів `T⁰(c), T¹(c), …, Tⁿ⁻¹(c)` лишаються в межах коду `C`. На `n`-му кроці цикл замикається: `Tⁿ(c) = c`.

Розгляньмо цей ефект на канонічному `[7, 4]`-коді [Геммінга](book:communications/hamming-code). Візьмімо кодове слово `0001011` і виконаємо всі його сім циклічних зсувів:

```
T⁰:  0 0 0 1 0 1 1
T¹:  1 0 0 0 1 0 1
T²:  1 1 0 0 0 1 0
T³:  0 1 1 0 0 0 1
T⁴:  1 0 1 1 0 0 0
T⁵:  0 1 0 1 1 0 0
T⁶:  0 0 1 0 1 1 0
```

Кожен із цих семи рядків є допустимим кодовим словом `[7, 4]`-коду Геммінга. Усі 16 кодових слів цього коду розпадаються на кілька таких замкнених циклічних орбіт (включно з тривіальною орбітою з одного нульового слова `0000000`).

![Слово 0001011 та всі сім його циклічних зсувів. Компактний блок 1011 просто їде по колу — і кожне з семи положень лишається дозволеним кодовим словом. Ця замкненість щодо повороту й означає «циклічний».](/book/communications/coding-theory/cyclic-codes/img/wheel.svg)
*Слово `0001011` та всі сім його циклічних зсувів. Компактний блок `1011` просто їде по колу — і кожне з семи положень лишається дозволеним кодовим словом. Ця замкненість щодо повороту й означає «циклічний».*

Ця замкненість здається простим комбінаторним трюком, але вона набуває алгебраїчної сили, коли вектор бітів записують як многочлен.

### Многочленний запис слів: від вектора до алгебраїчного кільця

Поставимо у відповідність кодовому вектору `c = (c₀, c₁, …, cₙ₋₁)` многочлен `c(x)`, де біти `cᵢ` слугують коефіцієнтами при степенях `xⁱ`:

```
c(x) = c₀ + c₁·x + c₂·x² + … + cₙ₋₁·xⁿ⁻¹
```

Коефіцієнти належать полю [GF(2)](book:math/finite-fields), де додавання й віднімання еквівалентні операції XOR (`1 ⊕ 1 = 0`, `-1 = +1`).

Множення многочлена `c(x)` на `x` підвищує степінь кожного члена на одиницю:

```
x·c(x) = c₀·x + c₁·x² + c₂·x³ + … + cₙ₋₂·xⁿ⁻¹ + cₙ₋₁·xⁿ
```

Старший член `cₙ₋₁·xⁿ` має степінь `n`, який виходить за межі слів довжини `n`. Щоб повернути його на місце вільного члена `x⁰ = 1`, підпорядкуємо арифметику правилові `xⁿ = 1`, тобто виконуватимемо ділення з остачею за модулем `xⁿ - 1`.

Оскільки `xⁿ ≡ 1 (mod xⁿ - 1)`, маємо:

```
x·c(x) mod (xⁿ - 1)
= (c₀·x + c₁·x² + … + cₙ₋₂·xⁿ⁻¹ + cₙ₋₁·xⁿ) mod (xⁿ - 1)   [розкриття дужок x·c(x)]
= c₀·x + c₁·x² + … + cₙ₋₂·xⁿ⁻¹ + cₙ₋₁·1                   [зведення за модулем: xⁿ ≡ 1]
= cₙ₋₁ + c₀·x + c₁·x² + … + cₙ₋₂·xⁿ⁻¹                     [впорядкування степенів]
```

Отриманий многочлен має коефіцієнти `(cₙ₋₁, c₀, c₁, …, cₙ₋₂)` — це точно многочлен правого циклічного зсуву `T(c)`!

![Верхній рядок — слово 0001011 з підписаними степенями x⁶…x⁰ і його многочлен x³+x+1; стрілка «× x, за модулем x⁷−1»; нижній рядок — зсунуте слово 0010110 з поверненим по колу старшим бітом і многочленом x⁴+x²+x](/book/communications/coding-theory/cyclic-codes/img/shift-as-x.svg)
*Біти — коефіцієнти многочлена. Множення на x піднімає кожен степінь на одиницю (зсув), а старший член повертається у вільний за правилом x⁷ = 1 (звідси «за модулем x⁷ − 1»). Циклічний зсув `0001011 → 0010110` — це рівно множення x³+x+1 на x.*

Алгебраїчним середовищем для слів циклічного коду є фактор-кільце многочленів:

```
R = GF(2)[x] / (xⁿ - 1)
```

Операція одного циклічного зсуву в цьому кільці зводиться до звичайного множення на `x`.

### Циклічний код як ідеал у кільці R

Поняття [ідеалу](book:math/ideal) в алгебрі описує підмножину кільця, яка замкнена щодо додавання елементів і поглинає множення на довільний елемент цього кільця.

Доведімо, що будь-який циклічний код `C` є ідеал у кільці `R`:

1. **Замкненість щодо додавання:** Код `C` є лінійним, тому для будь-яких `a(x), b(x) ∈ C` їхня сума `a(x) + b(x)` належить `C`.
2. **Замкненість щодо множення на x:** Це безпосереднє визначення циклічного коду: якщо `c(x) ∈ C`, то `x·c(x) mod (xⁿ - 1) ∈ C`.
3. **Поглинання множення на будь-який многочлен:** Послідовне множення на `x` показує, що `x²·c(x), x³·c(x), …, xⁱ·c(x)` також лежать у `C`. Візьмімо довільний многочлен `a(x) = a₀ + a₁·x + … + aₙ₋₁·xⁿ⁻¹ ∈ R`. Його добуток на `c(x)` розкладається в суму:

```
a(x)·c(x) mod (xⁿ - 1)
= a₀·c(x) + a₁·(x·c(x)) + a₂·(x²·c(x)) + … + aₙ₋₁·(xⁿ⁻¹·c(x))
```

Кожен доданок у правій частині є циклічним зсувом `c(x)` (помноженим на скаляр `0` або `1`), тобто елементом `C`. Оскільки `C` замкнений щодо додавання, уся сума `a(x)·c(x) mod (xⁿ - 1)` належить `C`.

Отже, циклічні коди довжини `n` — це точно ідеали фактор-кільця `GF(2)[x] / (xⁿ - 1)`. Усі алгебраїчні властивості коду випливають із цієї еквівалентності. Повний математичний вивід структури ідеалів наведено у вставці [алгебра твірного многочлена](book:communications/cyclic-codes/math-generator-polynomial.md).

### Твірний многочлен g(x) та його властивості

Оскільки `GF(2)[x]` є кільцем головних ідеалів, кожен ідеал у `R` породжується одним елементом. 

У циклічному коді `C` існує єдиний ненульовий многочлен найменшого степеня. Його називають **твірним многочленом** (англ. *generator polynomial*) і позначають `g(x)`.

Твірний многочлен має три фундаментальні властивості:

1. **Унікальність:** У коді `C` існує лише один ненульовий многочлен мінімального степеня. Якби існував другий многочлен `g'(x)` того ж степеня, їхня сума `g(x) + g'(x)` мала б менший степінь (бо старші коефіцієнти `1 ⊕ 1 = 0` знищилися б), що суперечить мінімальності степеня `g(x)`.
2. **Породження кодових слів:** Многочлен `c(x) ∈ R` є кодовим словом тоді й лише тоді, коли він ділиться на `g(x)` націло в `GF(2)[x]`:

```
c(x) = m(x)·g(x),     де deg m(x) < n - deg g
```

3. **Ділення xⁿ - 1:** Твірний многочлен `g(x)` завжди ділить `xⁿ - 1` націло в `GF(2)[x]`:

```
(xⁿ - 1) = q(x)·g(x)
```

Доведення цієї третьої властивості є вирішальним. Поділімо `xⁿ - 1` на `g(x)` із остачею:

```
xⁿ - 1 = q(x)·g(x) + r(x),     де r(x) = 0 або deg r < deg g
```

Перейдімо до фактор-кільця `R`, звівши вираз за модулем `xⁿ - 1`:

```
0 ≡ q(x)·g(x) + r(x)  (mod xⁿ - 1)
r(x) ≡ -q(x)·g(x) ≡ q(x)·g(x)  (mod xⁿ - 1)
```

Оскільки `q(x)·g(x)` є добутком елемента кільця на твірний многочлен, він є кодовим словом `C`. Отже, остача `r(x)` також мусить бути кодовим словом. Але `deg r < deg g`. Єдиним кодовим словом зі степенем, меншим за степінь твірного многочлена `g(x)`, є нульовий многочлен `r(x) = 0`. Отже, `xⁿ - 1` ділиться на `g(x)` без остачі.

![Розклад x⁷−1 над GF(2) на три множники (x+1), (x³+x+1), (x³+x²+1); середній множник обведено як обраний g(x); стрілка веде до підсумку: g(x)=x³+x+1 дає [7,4]-код Геммінга з трьома перевірними бітами](/book/communications/coding-theory/cyclic-codes/img/generator.svg)
*Щоб дістати циклічний код довжини 7, розкладають x⁷−1 і беруть за твірний многочлен добуток частини множників. Вибір g(x) = x³+x+1 (степінь 3 → три перевірні біти) дає саме [7, 4]-код Геммінга — той, чиє слово крутилося на колесі вище.*

Звідси випливає конструктивний метод побудови циклічних кодів: щоб створити циклічний код довжини `n`, розкладають многочлен `xⁿ - 1` на незвідні множники над `GF(2)` і беруть за `g(x)` добуток будь-якої підмножини цих множників.

Для `n = 7` розклад над `GF(2)` має вигляд:

```
x⁷ - 1 = (x + 1)·(x³ + x + 1)·(x³ + x² + 1)
```

Оскільки `x⁷ - 1` розкладається на 3 незвідні множники, існує `2³ = 8` різних виборів `g(x)`, які задають 8 різних циклічних кодів довжини 7:

```
Множники g(x)             g(x)                     [n, k, d]    Назва коду
─────────────────────────────────────────────────────────────────────────────
1                         1                        [7, 7, 1]    Увесь простір
(x + 1)                   x + 1                    [7, 6, 2]    Перевірка парності
(x³ + x + 1)              x³ + x + 1               [7, 4, 3]    Геммінга [7,4]
(x³ + x² + 1)             x³ + x² + 1              [7, 4, 3]    Геммінга (дуальний)
(x + 1)(x³ + x + 1)       x⁴ + x³ + x² + 1         [7, 3, 4]    Симплексний
(x + 1)(x³ + x² + 1)      x⁴ + x² + x + 1          [7, 3, 4]    Симплексний (дзеркальний)
(x³ + x + 1)(x³ + x² + 1) x⁶ + x⁵ + x⁴ + x³ + x² + x + 1  [7, 1, 7]  Повторення
(x⁷ - 1)                  x⁷ - 1 ≡ 0               [7, 0, —]    Нульовий код
```

### Матрична структура та перевірний многочлен h(x)

Степінь твірного многочлена визначить кількість перевірних бітів коду:

```
deg g(x) = n - k
```

Розмірність коду `k` дорівнює кількості інформаційних бітів. Базис коду як лінійного простору утворюють `k` послідовних зсувів твірного многочлена:

```
g(x),  x·g(x),  x²·g(x),  …,  xᵏ⁻¹·g(x)
```

Ці `k` многочленів мають різні степені від `n - k` до `n - 1`, тому вони є лінійно незалежними. Виклавши їх як рядки матриці розміром `k × n`, отримуємо твірну матрицю `G` циклічного коду:

![Твірна матриця [7,4]-коду: чотири рядки — це g=1101 і його зсуви xg, x²g, x³g, кожен на біт правіше; провідні одиниці утворюють сходинку по діагоналі, а блок g завширшки deg g+1=4 уміщається в семи стовпцях рівно k=4 рази](/book/communications/coding-theory/cyclic-codes/img/staircase-basis.svg)
*k = 4 зсуви g(x) = x³+x+1 (біти 1101) складають твірну матрицю [7, 4]-коду. Блок g завширшки deg g + 1 = 4 з'їжджає вниз-вправо і вміщається в n = 7 стовпцях рівно k = n − deg g = 4 рази — стільки незалежних рядків, стільки й розмірність; перевірних бітів лишається n − k = deg g = 3.*

Оскільки `g(x)` ділить `xⁿ - 1`, частка від ділення позначається `h(x)` і називається **перевірним многочленом** (англ. *parity-check polynomial*):

```
h(x) = (xⁿ - 1) / g(x),     де deg h = k
```

Перевірний многочлен `h(x)` задає критерій належності слова кодові: многочлен `c(x)` ступеня, меншого за `n`, є кодовим словом тоді й лише тоді, коли:

```
c(x)·h(x) ≡ 0  (mod xⁿ - 1)
```

Якщо `c(x) = m(x)·g(x)`, то `c(x)·h(x) = m(x)·g(x)·h(x) = m(x)·(xⁿ - 1) ≡ 0 (mod xⁿ - 1)`.

Отже, `g(x)` будує кодові слова шляхом множення, а `h(x)` перевіряє їх шляхом обнулення за модулем `xⁿ - 1`.

### Систематичне кодування: алгебра та алгоритм

При несистематичному кодуванні кодове слово будують як ззвичайний добуток інформаційного многочлена `m(x) = m₀ + m₁·x + … + mₖ₋₁·xᵏ⁻¹` на твірний `g(x)`:

```
c(x) = m(x)·g(x)
```

При цьому вихідні інформаційні біти змішуються з перевірними. У практичних системах зв'язку необхідне **систематичне кодування**: інформаційні біти мають передаватися у первинному вигляді в старших `k` позиціях слова, а перевірні біти — розміщуватися у молодших `n - k` позиціях.

Алгоритм систематичного кодування виконується у три кроки:

1. **Зсув інформаційного блоку:** Помножити `m(x)` на `xⁿ⁻ᵏ`. Це зсуває інформаційні біти у старші розряди `xⁿ⁻ᵏ, xⁿ⁻ᵏ⁺¹, …, xⁿ⁻¹`:

```
xⁿ⁻ᵏ·m(x) = m₀·xⁿ⁻ᵏ + m₁·xⁿ⁻ᵏ⁺¹ + … + mₖ₋₁·xⁿ⁻¹
```

2. **Обчислення остачі:** Поділити `xⁿ⁻ᵏ·m(x)` на `g(x)` із остачею в `GF(2)[x]`:

```
xⁿ⁻ᵏ·m(x) = q(x)·g(x) + r(x),     де deg r < n - k
```

3. **Формування кодового слова:** Додати остачу `r(x)` до зсунутого інформаційного многочлена:

```
c(x) = xⁿ⁻ᵏ·m(x) + r(x)
```

Оскільки в `GF(2)` додавання та віднімання тотожні (`+ = -`), маємо:

```
c(x) = q(x)·g(x) + r(x) + r(x) = q(x)·g(x)
```

Слово `c(x)` ділиться на `g(x)` без остачі, отже є допустимим кодовим словом. При цьому старші `k` коефіцієнтів `c(x)` збігаються з `m(x)`, а молодші `n - k` коефіцієнтів утворюють перевірочний блок `r(x)`.

#### Числовий приклад кодування

Закодуємо 4 інформаційні біти `m = 1010` (`m(x) = x³ + x`) у `[7, 4]`-код Геммінга з твірним многочленом `g(x) = x³ + x + 1` (`1011` у двійковому записі):

1. **Зсув даних:** `n - k = 7 - 4 = 3`.

```
x³·m(x) = x³·(x³ + x) = x⁶ + x⁴   →  бітовий рядок 1010000
```

2. **Ділення на g(x) у стовпчик над GF(2):**

```
  x⁶ + x⁴          │ x³ + x + 1
⊕ (x⁶ + x⁴ + x³)   ├────────────
───────────────    │ x³ + 1   (частка q(x))
        x³         │
      ⊕ (x³ + x + 1)
      ─────────────
            x + 1  (остача r(x))
```

Остача `r(x) = x + 1`, що відповідає бітам `011`.

3. **Результат:**

```
c(x) = x⁶ + x⁴ + x + 1   →  бітовий рядок 1010 011
```

Перші 4 біти `1010` — це вихідне повідомлення `m`, а 3 молодші біти `011` — це перевірочна остача `r`.

### Апаратна реалізація: ділення многочленів за допомогою LFSR

Головна практична перевага циклічних кодів полягає у тому, що ділення многочленів над `GF(2)` не вимагає арифметичного процесора чи складних логічних схем. Воно реалізується послідовним **зсувним регістром із лінійним зворотним зв'язком (LFSR)**.

Регістр для ділення на `g(x) = g₀ + g₁·x + … + gᵣ·xʳ` (де `r = n - k`, `gᵣ = 1`, `g₀ = 1`) складається з `r` тригерів `b₀, b₁, …, bᵣ₋₁`. Елементи XOR розташовуються перед тими тригерами `bᵢ`, для яких коефіцієнт `gᵢ = 1`.

![Схема LFSR-кодера для g=x³+x+1: три тригери b0 b1 b2, зсув зліва направо, зворотний зв'язок від b2 через XOR із даними, відводи XOR перед b0 і b1 (де g0=g1=1), без відводу перед b2 (g2=0)](/book/communications/coding-theory/cyclic-codes/img/lfsr-encoder.svg)
*Ділення на g(x) як залізо: три тригери остачі, відводи XOR там, де в g стоять одиниці (g₀=g₁=1), і жодного відводу там, де нуль (g₂=0). Один такт — один біт даних. Після K тактів у регістрі лежить та сама остача, що її poly_rem рахує над цілим словом.*

Процес кодування на залізі відбувається за `k` тактів:

1. Тригери регістра обнуляються `(b₀ = b₁ = … = bᵣ₋₁ = 0)`.
2. Інформаційні біти `mₖ₋₁, mₖ₋₂, …, m₀` подаються на вхід по одному біту за такт, починаючи зі старшого.
3. На кожному такті біт зворотного зв'язку обчислюється як `fb = in ⊕ bᵣ₋₁`. Вміст регістра зсувається вправо, а значення `fb` додається через XOR у ті позиції, де коефіцієнти `gᵢ = 1`.
4. Після `k` тактів у тригерах регістра автоматично залишається остача `r(x)`. Вона висувається вслід за інформаційними бітами у канал зв'язку.

Ця схема вимагає лише `n - k` тригерів і кількох вентилів XOR. Вона працює на частоті тактування лінії передачі. Саме тому циклічні коди виявлення помилок — [CRC](book:communications/crc) — вбудовані у первинний кремній мережевих адаптерів Ethernet, контролерів шин CAN, USB та SATA.

### Синдромне декодування та алгоритм пастки для помилки

При передачі через зашумлений канал зв'язку до кодового слова `c(x)` додається вектор помилок `e(x)`:

```
v(x) = c(x) + e(x)
```

Приймач обчислює **синдром** `s(x)` як остачу від ділення прийнятого слова `v(x)` на твірний многочлен `g(x)`:

```
s(x) = v(x) mod g(x) = (c(x) + e(x)) mod g(x) = e(x) mod g(x)
```

Якщо `s(x) = 0`, приймач вважає, що помилок немає (або виникла невиявлена помилка, кратна `g(x)`). Якщо `s(x) ≠ 0`, синдром містить повну інформацію про конфігурацію помилки `e(x)`.

#### Декодування методом пастки для помилки (Error-Trapping)

Для виправлення поодиноких помилок або кратних завад малої довжини (пакетів помилок) використовують декодер Меггітта — алгоритм **пастки для помилки** (*error-trapping*).

Він спирається на властивість циклічного зсуву синдрому: якщо зсунути прийняте слово `v(x)` на 1 біт вліво по колу, новий синдром дорівнюватиме `x·s(x) mod g(x)`.

Якщо одиночна помилка `e(x) = xⁱ` при обертанні слова потрапляє у молодші `n - k` розрядів (зону перевірних бітів), її степінь `i` стає меншим за `deg g = n - k`. У цей момент остача від ділення `xⁱ` на `g(x)` дорівнює самій помилці `xⁱ`, а вага Геммінга синдрому (кількість одиничних бітів) стає рівною 1:

```
weight(s(x)) ≤ 1
```

Алгоритм виправлення однієї помилки:

1. Обчислити початковий синдром `s(x) = v(x) mod g(x)`. Якщо `s(x) = 0`, слово коректне.
2. Якщо `weight(s(x)) ≤ 1`, помилка знаходиться у молодших розрядах і дорівнює самому синдрому `s(x)`. Виправити її: `v'(x) = v(x) ⊕ s(x)`.
3. Якщо `weight(s(x)) > 1`, циклічно зсунути слово `v(x)` на 1 біт вліво, а синдром оновити за правилом `s(x) := x·s(x) mod g(x)`.
4. Повторювати зсуви доти, доки вага синдрому не впаде до `≤ 1` (пастка закрилася).
5. Виправити слово в зсунутому положенні `v'(x) = v(x) ⊕ s(x)` і повернути його циклічним зсувом вправо на таку ж кількість кроків.

![Таблиця чотирьох обертів error-trapping: слово 1000011→0000111→0001110→0011100, синдром 110→111→101→001, вага 2→3→2→1; на четвертому оберті синдром замикається у перевірних розрядах і вага падає до 1](/book/communications/coding-theory/cyclic-codes/img/error-trap.svg)
*Синдром крутиться разом зі словом: `110 → 111 → 101 → 001`, вага `2 → 3 → 2 → 1`. На четвертому оберті помилковий біт заходить у перевірні розряди, вага падає до одиниці — синдром `001` і є той самий біт. XOR його у слово, докрутити назад на три оберти — і відновлено `1010011`.*

Повний робочий вихідний код кодера, обчислювача синдрому та декодера пастки для помилок наведено у вставці [кодек циклічного коду](book:communications/cyclic-codes/proj-cyclic-codec.md).

### Історія відкриття та розвиток роду циклічних кодів

Теорію циклічних кодів заснував американський математик Юджин Пренж (Eugene Prange) у 1957 році, працюючи у Дослідницькому центрі ВПС США в Кембриджі (AFCRC). У зведеній праці «Cyclic Error-Correcting Codes in Two Symbols» Пренж першим зсунув фокус теорії кодування з комбінаторного пошуку матриць на кільця многочленів і довів, що циклічні коди тотожні ідеалам у фактор-кільці `GF(2)[x] / (xⁿ - 1)`.

Детальний опис того, як Пренж перетворив теорію кодування на розділ алгебри, наведено у вставці [як зсув перетворив коди на алгебру](book:communications/cyclic-codes/hist-prange.md).

![Горизонтальний таймлайн 1948–1960: Шеннон, Геммінг, тоді 1957 як «злам», де коди з комбінаторики стають алгеброю, і далі Окенгем, Бозе–Рей-Чоудхурі та Рід–Соломон](/book/communications/coding-theory/cyclic-codes/img/hist-timeline.svg)
*За три роки — з 1957-го по 1960-й — виправлення помилок стало алгеброю. 1957-й тут злам: ліворуч від нього коди — вдалі здогади комбінаторики, праворуч — ідеали в кільці многочленів, а з них уже течуть цілі родини BCH і Рід–Соломона.*

Алгебраїчний підхід Пренжа породив ціле дерево фундаментальних класів кодів:

1. **CRC (Cyclic Redundancy Check, 1961):** Застосування циклічних кодів для надшвидкого виявлення помилок у мережевих протоколах та системах збереження даних (Peterson, Brown).
2. **Коди BCH (Bose, Ray-Chaudhuri, 1960; Hocquenghem, 1959):** Широкий клас циклічних кодів, у яких твірний многочлен `g(x)` будують як добуток незвідних многочленів із заданими коренями у розширених полях Галуа `GF(2ᵐ)`. Це дозволяє конструювати коди з гарантованою мінімальною відстанню `d ≥ 2t + 1` для виправлення `t` довільних помилок.
3. **Коди Рід — Соломона (Reed, Solomon, 1960):** Недвійкові циклічні коди над полем `GF(2ᵐ)`, де символами є не окремі біти, а байти або машинні слова. Вони ефективні проти пакетних збоїв і використовуються в оптичних дисках (CD/DVD/Blu-ray), QR-кодах, супутниковому зв'язку та космічних апаратах Deep Space Network.
4. **Коди Фара (Fire Codes):** Спеціалізовані циклічні коди для виправлення довгих пакетних помилок у магнітних дисках та стрічкових накопичувачах.

![Дерево наслідків: корінь — «код = ідеал, заданий дільником g(x)»; три гілки — CRC (виявляти), BCH (замовити відстань через корені), Рід–Соломон (символи в GF(2ᵐ))](/book/communications/coding-theory/cyclic-codes/img/hist-lineage.svg)
*Один алгебраїчний ключ — «код = ідеал, заданий дільником g(x)» — відчинив одразу три робочі родини: CRC, що лише виявляє збій; BCH, якому відстань замовляють через корені; і Рід–Соломон, що працює з цілими символами. Жодну не знайшли навмання — усі три спроєктували з тієї самої алгебри.*

> 🔧 **Навіщо це.** Циклічна симетрія вирішує головну проблему практичного кодування — складність апаратної реалізації. Введення вимоги замкненості щодо циклічного зсуву зводить усе лінійне кодування до ділення на один многочлен `g(x)`. Це дозволяє кодувати й обчислювати синдроми на апаратному рівні за допомогою декількох тригерів зсувного регістра LFSR без залучення обчислювальних ядер процесора. Майже кожен код, що захищає високошвидкісні шини (PCIe, USB, SATA), мережеві кадри (Ethernet, Wi-Fi) чи енергонезалежну пам'ять (NAND Flash), належить до родини циклічних кодів саме завдяки мінімальній ціні заліза та можливості алгебраїчного синтезу під задану стійкість.
