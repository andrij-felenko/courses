# 🧮 Математика згорткового коду: D-перетворення, G(D) і вільна відстань

<preknowlist>
- [Скінченні поля (поля Галуа)](book:math/galois-field) — GF(2) — це два елементи, 0 і 1, де додавання є XOR, а множення — логічним «І». У полі немає дільників нуля: добуток ненульових множників ненульовий. Це фундамент усієї арифметики нижче.
- [Кільця многочленів](book:math/polynomial-rings) — многочлени над полем додаються, множаться й діляться зі стачею; є степінь, подільність, найбільший спільний дільник (НСД) і поле дробів, де дозволене ділення. Саме тут живуть генератори коду.
- [Згортка](book:math/convolution) — сума виду Σᵢ aᵢ·b₍ₙ₋ᵢ₎: кожен елемент одного ряду множиться на зсунуту копію іншого, і все складається. Добуток двох многочленів — це згортка їхніх коефіцієнтів.
- [Лінійні блокові коди](book:communications/linear-block-codes) — кодування як добуток на породжувальну матрицю v = u·G, і ключова властивість лінійності: сума двох кодових слів знову кодове слово, тому мінімальна відстань коду дорівнює мінімальній **вазі** ненульового слова.
- [Відстань Геммінга](book:communications/hamming-distance) — кількість позицій, у яких різняться два слова; вага слова — кількість одиниць у ньому. На ній тримається і виправлення, і міра сили коду.
- [Z-перетворення](book:math/z-transform) — спосіб замінити послідовність одним рядом за степенями оператора затримки; тут той самий прийом, лише оператор звуть D, а не z⁻¹.
</preknowlist>

Кодер згорткового коду виглядає як жменя дротів: зсувний регістр і кілька суматорів XOR. Але за цією схемою стоїть точний алгебраїчний механізм, і щойно його побачити, все інше — вибір генераторів, сила коду, небезпека катастрофи — перестає бути набором рецептів і стає однією операцією. Ця операція — множення многочленів над полем із двох елементів. Розберімо її від самого низу, бо саме звідти видно, чому код зветься згортковим і що насправді робить приймач.

## Потік як многочлен: оператор затримки D

Бітовий потік — це послідовність u₀, u₁, u₂, u₃, … : біт u₀ надійшов першим, u₁ наступним і так далі. Причепімо до кожного біта позначку, що запам'ятовує його момент: біт, який прийшов на такті k, дістає мітку Dᵏ. Тоді весь потік згортається в один формальний ряд:

```
u(D) = u₀ + u₁D + u₂D² + u₃D³ + …
```

Тут D — не число, яке кудись підставляють. Це маркер «на один такт пізніше». Помножити на D означає посунути весь потік на такт уперед у часі:

```
D · u(D) = u₀D + u₁D² + u₂D³ + …   (той самий потік, затриманий на один такт)
```

Тобто D — буквально оператор затримки. Це той самий прийом, що й [Z-перетворення](book:math/z-transform) у обробці сигналів: там оператор пишуть як z⁻¹, у теорії кодування його звуть D («delay», затримка) і лишають додатні степені. Об'єкт формальний — ми ніколи не підставляємо в D якесь значення, ми лише стежимо за коефіцієнтами. Навіщо це? Бо марудна часова бухгалтерія «який вхідний біт впливає на який вихідний» тепер згортається у звичайне множення.

## Кодер — це множення многочленів, тобто згортка

Візьмімо робочий приклад — код (7, 5) зі швидкістю 1/2, у якого два суматори знімають такі відводи:

```
v1 = uₖ ⊕ u₍ₖ₋₁₎ ⊕ u₍ₖ₋₂₎
v2 = uₖ ⊕ u₍ₖ₋₂₎
```

Придивімося до v1 на такті k: це фіксована сума поточного входу й двох затриманих копій. Мовою D «вхід, затриманий на один такт» — це D·u(D), «на два» — це D²·u(D). Отже, весь вихідний потік v1 стає:

```
v1(D) = u(D) + D·u(D) + D²·u(D) = u(D) · (1 + D + D²)
v2(D) = u(D) +          D²·u(D) = u(D) · (1 + D²)
```

Візерунок відводів обернувся на многочлен. **Породжувальні многочлени** (generator polynomials): g₁(D) = 1 + D + D², g₂(D) = 1 + D². Кодування — це буквально

```
vⱼ(D) = u(D) · gⱼ(D)
```

множення в кільці [GF(2)[D]](book:math/polynomial-rings) — многочленів, чиї коефіцієнти живуть у [GF(2)](book:math/galois-field) (додати = XOR, помножити = «І»).

І ось обіцянка, зашита в назві коду. Помножмо два многочлени й погляньмо на коефіцієнт при Dⁿ у добутку:

```
[коефіцієнт при Dⁿ]  =  Σᵢ  uᵢ · g₍ₙ₋ᵢ₎    (сума за модулем 2)
```

Ця сума — кожен вхідний біт помножений на зсунуту й обернену копію генератора, і все складено — і є [згорткою](book:math/convolution) двох послідовностей. Тому «згортковий код» — не метафора: вихід є згорткою вхідного потоку з коротким незмінним ядром g. Зсувний регістр — це просто залізо, що рахує згортку по одному відводу за такт.

**Приклад — той самий, що кодер робить руками.** Закодуймо 1 0 1 1 0 0. У многочлені лишаються тільки одиниці: u(D) = 1 + D² + D³. Множимо на g₁ довгим стовпчиком, де кожен зайнятий біт u породжує зсунуту копію g₁, а стовпці складаються за модулем 2:

```
          D⁰ D¹ D² D³ D⁴ D⁵
u:         1  0  1  1            (= 1 + D² + D³)
g₁:        1  1  1               (= 1 + D + D²)

g₁ · D⁰:   1  1  1               (бо u₀ = 1)
g₁ · D²:         1  1  1         (бо u₂ = 1)
g₁ · D³:            1  1  1      (бо u₃ = 1)
───────────────────────────  ⊕  (за модулем 2)
v₁:        1  1  0  0  0  1      (= 1 + D + D⁵)
```

![Множення многочленів v₁ = u·g₁ як згортка: колонки — степені D⁰…D⁵, три рядки — копії генератора g₁, зсунуті на набрані степені входу u = 1 + D² + D³; складання стовпців за модулем 2 дає v₁ = 1 1 0 0 0 1](/book/communications/coding-theory/convolutional-codes/img/polymul.svg)
*Кожен рядок — копія g₁, посунута на позицію одиниці входу; XOR по стовпцях — це і є згортка. Коефіцієнт при Dⁿ збирає всі пари, чиї степені дають n.*

Другий суматор рахується так само: v₂(D) = (1 + D² + D³)(1 + D²) = 1 + D³ + D⁴ + D⁵ = 1 0 0 1 1 1. Переплетімо два потоки — і дістанемо 11 10 00 01 01 11, той самий потік, що регістр видавав біт за бітом. Інакше й бути не могло: множення й зсувний регістр — це одна операція, побачена з двох боків.

**Три обличчя генератора.** Один і той самий об'єкт можна записати трьома способами, і всі три — те саме:

```
многочлен      вектор відводів      вісімково
1 + D + D²  ↔     (1, 1, 1)     ↔    111₂ = 7₈   =  g₁
1 +     D²  ↔     (1, 0, 1)     ↔    101₂ = 5₈   =  g₂
```

Домовленість читання проста: найновіший відвід (коефіцієнт при D⁰) — старший біт вісімкового запису. Тому короткий запис «(7, 5)» і є парою многочленів, лише стиснутою в два числа. Вибрати генератори — це вибрати два многочлени; уся сила чи слабкість коду вже сховані в цьому виборі.

## Породжувальна матриця G(D) і швидкість

Складімо генератори в матрицю. Для нашого коду швидкості 1/2:

```
G(D) = [ 1+D+D²   1+D² ]      (розмір 1×2)
```

і весь кодер — один добуток матриць:

```
v(D) = u(D) · G(D),   де  v(D) = [ v₁(D)  v₂(D) ]
```

Загальний випадок швидкості k/n: k вхідних потоків, n вихідних, G(D) — матриця k×n над GF(2)[D], u(D) — рядок довжини k, v(D) — рядок довжини n. **Швидкість** R = k/n — стільки бітів даних припадає на кодований біт. **Пам'ять** m — найвищий степінь многочлена в матриці; **довжина обмеження** K = m + 1; станів автомата 2ᵐ (для швидкості 1/n).

Порівняймо з блоковим кодом. У [лінійному блоковому коді](book:communications/linear-block-codes) G — стала матриця над GF(2), і v = u·G — звичайний добуток вектора на матрицю в полі. Тут єдина зміна в тому, що елементи стали многочленами від D — тобто поле GF(2) замінене кільцем GF(2)[D]. Скелет лінійної алгебри той самий, лише один вимір — час — згорнуто в оператор D. Усе, що ви знаєте про породжувальні матриці, переноситься сюди слово в слово.

Іноді елементи роблять раціональними: G(D) = [ 1, (1+D²)/(1+D+D²) ] — систематичний рекурсивний кодер (RSC), робочий блок усередині турбоконструкцій. Ділення тут живе в полі дробів GF(2)(D). Це поле нам знадобиться вже за хвилину — саме воно ховає найпідступнішу пастку згорткових кодів.

## Вільна відстань: чому вона грає роль мінімальної відстані

Сила блокового коду вимірюється мінімальною відстанню Геммінга d_min між кодовими словами. Для згорткового коду її пряма родичка — **вільна відстань** (free distance, d_free): найменша вага Геммінга серед усіх ненульових кодових слів; рівнозначно — найменша відстань між двома різними шляхами ґратки, що розходяться й пізніше знову сходяться.

Чому раптом вага, а не відстань? Бо код лінійний. v(D) = u(D)·G(D) лінійне за u, тож XOR двох кодових слів сам є кодовим словом (словом XOR-а їхніх входів). Отже, множина всіх попарних відстаней збігається з множиною ваг ненульових кодових слів, а відстань до найближчого сусіда — це вага найлегшого ненульового слова. Той самий факт, що й для блокового коду, дослівно (див. [відстань Геммінга](book:communications/hamming-distance) й лінійність у [блокових кодах](book:communications/linear-block-codes)) — тому d_free і посідає місце d_min.

Отже, d_free — це найменша вага виходу серед усіх входів, що виводять кодер із нульового стану й повертають назад у нуль. Така вилазка «розійшовся й зійшовся» зветься **помилковою подією** (error event): найкоротший спосіб для двох легальних шляхів розбігтися й знову злитися. Якщо канал псує менше ніж половину d_free уздовж кожної події, найближчий легальний шлях лишається справжнім, і декодер відновлює переданe — він виправляє до ⌊(d_free − 1)/2⌋ помилок на подію. Наш код (7, 5) має d_free = 5.

## Спектр відстаней і показник експоненти помилки

d_free — це заголовок; повну історію розповідає **спектр відстаней**: скільки помилкових подій кожної ваги існує. Запишімо його твірною функцією — **передавальною функцією** коду:

```
T(D) = Σ  a_d · Dᵈ       (сума за d ≥ d_free)
```

де a_d — кількість різних помилкових подій вихідної ваги d. Це ваговий перелічувач (weight enumerator), і він механічно випадає зі схеми станів. Розщепімо нульовий стан на «старт» і «фініш», підпишімо кожне ребро як D у степені ваги його виходу й спитаймо про сумарний «коефіцієнт передачі» всіх шляхів від старту до фінішу (правило Мейсона — розв'язання рівнянь потоку в графі). Для (7, 5) алгебра замикається в короткий дріб:

```
T(D) = D⁵ / (1 − 2D) = D⁵ + 2D⁶ + 4D⁷ + 8D⁸ + …
```

Читаємо спектр: рівно одна подія ваги 5 (це і є d_free, і вона єдина), дві ваги 6, чотири ваги 7, і далі подвоюється без кінця: a_d = 2^(d−5).

![Спектр відстаней коду (7,5): стовпчики висотою a_d для ваг d = 5, 6, 7, 8 показують 1, 2, 4, 8 шляхів; перший стовпчик (d = 5) — це d_free і єдиний шлях мінімальної ваги, далі число подвоюється, що відповідає T(D) = D⁵/(1−2D)](/book/communications/coding-theory/convolutional-codes/img/distspec.svg)
*Один шлях ваги 5 задає експоненту помилки; далі кількість шляхів росте як 2^(d−5). Спектр — це вся сила коду, згорнута в один ряд.*

Навіщо нам увесь ряд, а не сама п'ятірка? Бо ряд передбачає рівень помилок. Два шляхи на вихідній відстані d плутаються каналом із **попарною ймовірністю** P₂(d), що падає експоненційно з d: у двійковому симетричному каналі P₂(d) ≈ [2·√(p(1−p))]ᵈ, у гаусовому каналі з м'яким рішенням P₂(d) ≈ Q(√(2d·R·Eb/N0)) ~ e^(−d·R·Eb/N0). Об'єднавча межа (union bound) складає всі способи помилитися:

```
P(помилкова подія)  ≤  Σ  a_d · P₂(d)      (сума за d ≥ d_free)
```

Оскільки P₂(d) обвалюється експоненційно, найменший степінь панує: доданок d = d_free забиває решту. Тому

```
P ≈ a_{d_free} · P₂(d_free)
```

Показник експоненти ймовірності помилки — нахил «водоспаду» на графіку, той самий кодовий виграш — визначено вільною відстанню d_free. Множник попереду задає a_{d_free} (а точніше — спектр, зважений вагою входу). Ось у якому сенсі d_free є показником експоненти помилки згорткового коду: це буквально число в показнику. Подвоїти довжину обмеження — купити більшу d_free й тим крутіший спад; той самий важіль тягне код далекого космосу (171, 133), у якого d_free = 10. А стеля, до якої всі ці криві прагнуть, — [межа Шеннона](book:communications/bandwidth-capacity).

> 🔧 **Навіщо це.** Спектр перетворює питання «який код сильніший?» зі справи смаку на арифметику. Два кандидати-пари генераторів однакової K порівнюють за (d_free, a_{d_free}): більша d_free виграє експоненту; за рівної d_free виграє менша a_{d_free}. Саме таку таблицю обчислив Джеймс Оденвалдер (Odenwalder, 1970-ті) — не вгадуванням, а перебором многочленів у пошуках пари з максимальною d_free для кожної K. Коли ви читаєте «генератори 171, 133₈» у стандарті CCSDS для далекого космосу, ви читаєте переможця того перебору для K = 7 — і саме він захищав телеметрію «Вояджерів» та «Галілео». *(Історичний статус: авторство оптимізації за Оденвалдером і закріплення в CCSDS підтверджені; конкретні d_free беруться з опублікованих таблиць.)*

## Пастка: катастрофічні кодери

Тепер небезпека, про яку попереджає алгебра й якої не видно у схемі. Кодер зветься **катастрофічним** (catastrophic), якщо якийсь вхід нескінченної ваги дає вихід скінченної ваги. Звучить безневинно, поки не перевернути: якщо скінченна різниця виходів може відповідати нескінченній різниці входів, то скінченне число помилок каналу здатне зіштовхнути декодер на хибний шлях, що різниться від правди в нескінченній кількості вхідних бітів. Коротка завада на вході — і нескінченний потік сміття на виході. Декодер не оговтується ніколи.

Класичний приклад — його наводить кожен підручник — g₁ = 1 + D, g₂ = 1 + D². Подаймо вхід u(D) = 1/(1+D) = 1 + D + D² + D³ + … — суцільні одиниці, нескінченна вага. Виходи:

```
v₁ = u · g₁ = [1/(1+D)] · (1+D)  = 1
v₂ = u · g₂ = [1/(1+D)] · (1+D²) = 1 + D     (бо 1+D² = (1+D)² над GF(2))
```

Скінченні. Нескінченно важкий вхід випарувався у вихід ваги 3.

*У схемі станів винуватець — червоний самовиток при стані 11: вхід 1, вихід 00. Крути його безкінечно — вага входу росте, вага виходу стоїть. Ось звідки нескінченний вхід зі скінченним виходом.*

Чому 1/(1+D) взагалі має сенс? Ми вийшли з многочленів у поле дробів GF(2)(D) — формальні степеневі ряди, де ділення дозволене. 1/(1+D) — це чесний розв'язок рівняння (1+D)·x = 1, і він нескінченний рівно тому, що 1+D не є одночленом.

Це веде просто до критерію (Джеймс Мессі та Майкл Сейн, 1968, «Inverses of linear sequential circuits», IEEE Trans. Computers): кодер **не** катастрофічний тоді й лише тоді, коли найбільший спільний дільник його генераторів — чистий степінь D:

```
НСД(g₁, g₂, …, gₙ) = Dˡ      (зазвичай просто 1)
```

Тепер «ЧОМУ» прозоре. Хай НСД дорівнює якомусь c(D) з ненульовим вільним членом і степенем ≥ 1 — запишімо gⱼ = c·hⱼ. Візьмімо вхід u = 1/c(D). Це нескінченний ряд (бо c — не одночлен), а проте кожен вихід vⱼ = u·gⱼ = hⱼ — голий многочлен, скінченний. Нескінченне всередину, скінченне назовні: точнісінько катастрофа. Єдиний безпечний спільний множник — c = Dˡ, бо 1/Dˡ = D⁻ˡ є простим зсувом у часі, все ще скінченним на символ. Ось чому в критерії стоїть «степінь D», а не «дорівнює 1»: спільна затримка нешкідлива, шкідливий лише спільний множник із ненульовим вільним членом, як 1+D, що замикає нескінченний зворотний зв'язок.

Перевірмо наш робочий код. НСД(1+D+D², 1+D²)? Перший многочлен незвідний над GF(2) — у нього немає кореня в цьому полі (значення в 0 і в 1 обидва дорівнюють 1), а степінь 2; водночас 1+D² = (1+D)². Спільного немає нічого: НСД = 1. Код (7, 5) безпечний. А катастрофічна пара (1+D, 1+D²) ділить спільний множник 1+D — і той самий 1+D є зворотним зв'язком, що дає ряду 1/(1+D) розбігтися. НСД тут не бухгалтерія, а точний відбиток того самого витка нульової ваги зі схеми станів: код катастрофічний тоді й лише тоді, коли в його схемі є цикл (окрім нульового самовитка) з ненульовим входом і нульовою вагою виходу.

## Де це працює

Три практичні висновки випливають з однієї думки — кодер є множенням на G(D):

- **Проєктування = вибір многочленів.** Вісімкові таблиці (як Оденвалдерові для K приблизно до 14) подають для кожної довжини обмеження взаємно просту пару генераторів із найбільшою d_free. Вибрати код — це прочитати рядок таблиці.
- **Передбачення, а не надія.** Передавальна функція перетворює схему станів на спектр {a_d}, а об'єднавча межа перетворює спектр на криву помилок, чий нахил задає d_free. Коди порівнюють на папері, ще не торкнувшись декодера.
- **Безпека.** Одна перевірка НСД відкидає катастрофічну халепу — код, що на стенді виглядає бездоганно, а тоді ніколи не оговтається від єдиного завмирання каналу.

Зсувний регістр — це привітне обличчя; GF(2)[D] — механізм за ним. Усе, що код уміє й чого боїться, — його швидкість, його сила, його єдина фатальна вада — записано в цих двох коротких многочленах.
