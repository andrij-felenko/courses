# 🧮 Алгебра скінченних полів у GHASH, Poly1305 та криптоаналіз Nonce Reuse

Автентифіковане шифрування базується на суворій алгебраїчній структурі скінченних полів: двійкового поля Галуа `GF(2^128)` у режимі AES-GCM та поля простих чисел `GF(2^130 - 5)` в алгоритмі Poly1305. Розуміння цієї математичної основи розкриває, чому автентифікація може виконуватися паралельно з шифруванням, як працює швидка редукція поліномів без ділення в стовпчик і чому одноразове повторення Nonce перетворює стійкий шифр на елементарну систему алгебраїчних рівнянь, що повністю компрометує автентифікаційний ключ.

---

### 1. Арифметика поля Галуа GF(2¹²⁸) у режимі GCM

Поле Галуа `GF(2^128)` (двійкове поле характеристики 2) складається з `2^128` елементів. На відміну від звичайної модульної арифметики над цілими числами, кожен 128-бітний блок даних розглядається як поліном степеня менше 128 над полем `GF(2)` з бінарними коефіцієнтами `{0, 1}`:

```
A(x) = a₁₂₇·x¹²⁷ + a₁₂₆·x¹²⁶ + ... + a₁·x + a₀,   де aᵢ ∈ {0, 1}
```

#### Додавання та віднімання в полі характеристики 2
Операція додавання двох многочленів у полі характеристики 2 зводиться до додавання відповідних коефіцієнтів за модулем 2. Оскільки в полі `GF(2)` діє правило `1 + 1 = 0` та `0 + 1 = 1`, додавання поліномів повністю еквівалентне порозрядному виключному АБО (XOR) і виконується без жодних міжрозрядних переносів:

```
C(x) = A(x) ⊕ B(x) = ∑_{i=0}^{127} (aᵢ ⊕ bᵢ)·xⁱ
```

Властивість характеристики 2 веде до важливого алгебраїчного наслідку: віднімання повністю тотожне додаванню, оскільки `-1 ≡ +1 (mod 2)`. Отже:

```
A(x) − B(x) = A(x) ⊕ B(x)
```

Будь-який елемент є власним протилежним елементом за додаванням: `A(x) ⊕ A(x) = 0`.

#### Безпереносне множення та метод Карацуби
Множення двох елементів `A(x)` та `B(x)` у полі `GF(2^128)` складається з двох кроків:
1. Безпереносне множення многочленів (Carry-less Multiplication), що дає проміжний многочлен `C'(x)` степеня до `254`:
   ```
   C'(x) = A(x) · B(x) = ∑_{k=0}^{254} c'_k · x^k,   де c'_k = ⨁_{i+j=k} (a_i · b_j)
   ```
2. Модульна редукція `C(x) = C'(x) mod f(x)` за незвідним многочленом поля `f(x)`.

Для оптимізації програмного множення без спеціальних інструкцій застосовують поліноміальний варіант алгоритму Карацуби. Розбивши 128-бітні поліноми на 64-бітні половини `A = A_1 · x^64 ⊕ A_0` та `B = B_1 · x^64 ⊕ B_0`, добуток обчислюють лише через три 64-бітні безпереносні множення замість чотирьох:

```
C'(x)
= (A_1 · x⁶⁴ ⊕ A_0) · (B_1 · x⁶⁴ ⊕ B_0)                                                    [розклад на 64-бітні половини]
= A_1 · B_1 · x¹²⁸ ⊕ ((A_1 ⊕ A_0) · (B_1 ⊕ B_0) ⊕ A_1 · B_1 ⊕ A_0 · B_0) · x⁶⁴ ⊕ A_0 · B_0 [формула Карацуби з 3 множеннями]
```

#### Незвідний многочлен та швидка редукція
Стандарт NIST SP 800-38D фіксує канонічний незвідний многочлен для режиму GCM:

```
f(x) = x¹²⁸ + x⁷ + x² + x + 1
```

Вибір саме цього многочлена забезпечує надшвидку модульну редукцію. Оскільки `f(x) = 0` у полі `GF(2^128)`, старший степінь `x^128` тотожно замінюється сумою молодших членів:

```
x¹²⁸ mod f(x)
= x⁷ + x² + x + 1      [перенесення старшого степеня через тотожність x¹²⁸ ≡ x⁷ + x² + x + 1 (mod f(x))]
```

У двійковому поданні многочлен `x⁷ + x² + x + 1` відповідає 128-бітній константі `R = 0xE1000000000000000000000000000000` (з урахуванням дзеркального порядку бітів у GCM, де старший коефіцієнт полінома відображається у молодший біт байта).

#### Покрокове множення на x (зсувний регістр зі зворотним зв'язком)
Якщо елемент `V` помножити на `x`, це відповідає логічному зсуву бітів вправо на 1 позицію. Якщо молодший біт `V` до зсуву дорівнював 1 (тобто при множенні на `x` утворився член `x^128`), до результату додається константа редукції `R`:

```
V · x = (V >> 1) ⊕ ( (V & 1) ? R : 0 )
```

Будь-яке довільне множення `A · B` у полі `GF(2^128)` можна обчислити за 128 таких тактів «зсув-і-XOR» (класична схема LFSR), або за один машинний такт за допомогою апаратної векторної інструкції `PCLMULQDQ` (на архітектурі x86) чи `PMULL` (на архітектурі ARM).

### 2. Функція GHASH як схема Горнера

Автентифікація в режимі GCM покладається на функцію універсального гешування `GHASH`. Її задача — згорнути довільний масив асоційованих даних `AAD` та шифротексту `Ciphertext` у єдиний 128-бітний дайджест за допомогою секретного хеш-ключа Галуа `H = AES_K(0^128)`.

Нехай вхідні дані доповнено нулями до кратності 16 байтам і розбито на послідовність 128-бітних блоків `X_1, X_2, ..., X_m`, де:
- блоки `X_1, ..., X_u` — це асоційовані дані `AAD`;
- блоки `X_{u+1}, ..., X_{m-1}` — це блоки шифротексту `Ciphertext`;
- фінальний блок `X_m` — це конкатенація 64-бітних довжин: `len(AAD)_64 || len(Ciphertext)_64`.

Обчислення `GHASH` виконується за рекурентною схемою Горнера:

```
Y₀ = 0¹²⁸
Y₁ = (Y₀ ⊕ X₁) · H = X₁ · H
Y₂ = (Y₁ ⊕ X₂) · H = (X₁ · H ⊕ X₂) · H = X₁ · H² ⊕ X₂ · H
Y₃ = (Y₂ ⊕ X₃) · H = X₁ · H³ ⊕ X₂ · H² ⊕ X₃ · H
...
Y_m = X₁ · Hᵐ ⊕ X₂ · Hᵐ⁻¹ ⊕ ... ⊕ X_{m-1} · H² ⊕ X_m · H
```

Завдяки дистрибутивності множення над додаванням у полі `GF(2^128)`, значення `GHASH(H, X)` є поліномом від змінної `H`, де коефіцієнтами виступають вхідні блоки даних:

```
GHASH(H, X₁, ..., X_m) = ∑_{i=1}^{m} Xᵢ · H^{m - i + 1}
```

Фінальний тег автентичності `Tag` утворюється шляхом маскування значення `GHASH` результатом шифрування нульового лічильника:

```
Tag = GHASH(H, X₁, ..., X_m) ⊕ AES_K(Y₀),   де Y₀ = Nonce || 0³¹1
```

### 3. Арифметика Poly1305 над полем простих чисел GF(2¹³⁰ − 5)

На відміну від GCM, алгоритм Poly1305 Деніела Бернштейна використовує модульну арифметику над полем лишків за великим простим числом псевдо-Мерсеннівської форми:

```
p = 2¹³⁰ − 5
```

#### Чому обрано саме просте число 2¹³⁰ − 5
Число `2^130 - 5` є найближчим простим числом, що перевищує `2^128` (розмір стандартного 16-байтового блоку даних). Форма `2^130 - 5` забезпечує надзвичайно швидку модульну редукцію без виконання операції цілочисельного ділення.

Оскільки `2^130 ≡ 5 (mod p)`, будь-яке проміжне 260-бітне число `Z`, отримане в результаті множення двох 130-бітних значень, можна розбити на старшу частину `Z_hi = Z >> 130` та молодшу частину `Z_lo = Z & (2^130 - 1)`:

```
Z mod (2¹³⁰ − 5)
= (Z_hi · 2¹³⁰ + Z_lo) mod (2¹³⁰ − 5)   [розкладання числа за основою 2¹³⁰]
= (Z_hi · 5 + Z_lo) mod (2¹³⁰ − 5)      [заміна степеня 2¹³⁰ еквівалентним залишком 5]
```

Замість виконання важкого 260-бітного ділення процесор виконує одне коротке множення старших бітів на 5 і додає молодші біти.

#### Затискання ключа r (Clamping)
Ключ автентифікації `r` (16 байтів / 128 бітів) генерується потоковим шифром ChaCha20 і підлягає обов'язковому бітовому маскуванню (clamping):

```
r[3], r[7], r[11], r[15] &= 0x0f   [очищення 4 старших бітів кожного 4-го байта]
r[4], r[8], r[12]         &= 0xfc   [очищення 2 молодших бітів кожного 4-го байта]
```

**Математичний сенс затискання:**
1. **Запобігання переповненню розрядів:** маскування гарантує, що значення `r` суворо менше ніж `2^124`. Це дозволяє реалізаціям Poly1305 розбивати 130-бітні числа на п'ять 26-бітних або три 44-бітних кінцівок (limbs) і виконувати множення з накопиченням у 64-бітних регістрах процесора без виникнення проміжних переповнень до моменту фінальної редукції.
2. **Константний час виконання:** структура затиснутого ключа унеможливлює виникнення довгих ланцюжків переносів між регістрами, що гарантує відсутність умовних переходів у машинному коді та захищає від витоків інформації через сторонні часові канали.

#### Поліноміальне обчислення автентифікатора
Вхідне повідомлення розбивається на 16-байтові блоки `c_1, c_2, ..., c_k`. До кожного блоку дописується байт `0x01` на 17-ту позицію (що відповідає додаванню константи `2^128`), перетворюючи кожен блок на число `n_i` у діапазоні `[1, 2^129]`:

```
Acc₀ = 0
Acc₁ = ( (Acc₀ + n₁) · r ) mod (2¹³⁰ − 5)
Acc₂ = ( (Acc₁ + n₂) · r ) mod (2¹³⁰ − 5)
...
Acc_k = ( ... ( (n₁·r + n₂)·r + n₃)·r ... + n_k) · r mod (2¹³⁰ − 5)
```

Фінальний 128-бітний тег отримується додаванням секретної 128-бітної константи `s` (наступні 16 байтів, згенеровані ChaCha20 з нульового блоку) за звичайним модулем `2^128`:

```
Tag = (Acc_k + s) mod 2¹²⁸
```

### 4. Алгебраїчний криптоаналіз Nonce Reuse у GCM (Атака Джукса)

У 2006 році французький криптограф Антуан Джукс (фр. *Antoine Joux*) опублікував атаку, яка довела, що повторне використання `Nonce` у режимі GCM призводить до повного краху системи автентичності.

Нехай під одним і тим самим ключем `K` та однаковим `Nonce` відправлено два різні повідомлення з шифротекстами `C_1` та `C_2` однакової довжини `m` блоків.

Оскільки `Nonce` однаковий, значення початкового лічильника `Y_0 = Nonce || 0x00000001` є ідентичним в обох сесіях. Отже, зашифрована маска тегу `Mask = AES_K(Y_0)` повністю збігається:

```
Tag₁ = GHASH(H, X₁) ⊕ AES_K(Y₀)
Tag₂ = GHASH(H, X₂) ⊕ AES_K(Y₀)
```

#### Крок 1. Скорочення маски тегу
Додамо обидва рівняння в полі `GF(2^128)` (порозрядний XOR):

```
ΔTag
= Tag₁ ⊕ Tag₂                                          [позначення різниці тегів]
= (GHASH(H, X₁) ⊕ AES_K(Y₀)) ⊕ (GHASH(H, X₂) ⊕ AES_K(Y₀)) [підстановка виразів тегів]
= GHASH(H, X₁) ⊕ GHASH(H, X₂) ⊕ (AES_K(Y₀) ⊕ AES_K(Y₀))   [комутативність додавання в полі]
= GHASH(H, X₁) ⊕ GHASH(H, X₂) ⊕ 0                      [тотожність V ⊕ V = 0 у характеристиці 2]
= GHASH(H, X₁) ⊕ GHASH(H, X₂)                         [нейтральний елемент 0]
```

Секретне значення `AES_K(Y_0)` повністю знищилося без знання ключа AES!

#### Крок 2. Формування поліноміального рівняння від H
Розпишемо вираз різниці через блоки повідомлень:

```
Tag₁ ⊕ Tag₂ = ∑_{i=1}^{m} X_{1,i} · H^{m - i + 1} ⊕ ∑_{i=1}^{m} X_{2,i} · H^{m - i + 1}
```

Об'єднаємо доданки однакових степенів `H`:

```
P(H) = (X_{1,1} ⊕ X_{2,1})·Hᵐ ⊕ (X_{1,2} ⊕ X_{2,2})·Hᵐ⁻¹ ⊕ ... ⊕ (X_{1,m} ⊕ X_{2,m})·H ⊕ (Tag₁ ⊕ Tag₂) = 0
```

Ми отримали поліноміальне рівняння `P(H) = 0` степеня `m` над скінченним полем `GF(2^128)`, де:
- коефіцієнти `(X_{1,i} ⊕ X_{2,i})` та `(Tag_1 ⊕ Tag_2)` повністю відомі атакуючому з перехопленого відкритого трафіку;
- єдиною невідомою величиною є секретний хеш-ключ Галуа `H`.

#### Крок 3. Знаходження коренів многочлена в GF(2¹²⁸)
За основною теоремою алгебри для скінченних полів, ненульовий многочлен степеня `m` над полем `GF(2^128)` має **не більше ніж `m` коренів**.

Для повідомлення довжиною в 1 Кілобайт степінь многочлена становить `m ≈ 64`. Знаходження коренів многочлена `P(H)` у полі `GF(2^128)` виконується за алгоритмом Берлекампа або через обчислення найбільшого спільного дільника з тестовим поліномом `gcd(P(x), x^(2^k) - x)` за лічені мілісекунди на звичайному процесорі.

У результаті атакуючий отримує множину кандидатів на ключ `{H_1, H_2, ..., H_d}` (де `d <= m`). Якщо перехоплено третє повідомлення з тим самим `Nonce` або атакуючий може надіслати тестовий пакет на сервер, справжній ключ `H` визначається однозначно.

#### Крок 4. Повна компрометація автентичності (Universal Forgery)
Знаючи справжній ключ `H`, атакуючий миттєво обчислює секретну маску лічильника `AES_K(Y_0)`:

```
AES_K(Y₀) = Tag₁ ⊕ GHASH(H, X₁)
```

Маючи на руках пару `(H, AES_K(Y_0))`, атакуючий отримує абсолютну можливість створення підроблених повідомлень (Universal Forgery):
1. Створити довільний фальшивий заголовок `AAD_{fake}`.
2. Створити довільний фальшивий шифротекст `C_{fake}`.
3. Обчислити валідний автентифікаційний тег:
   ```
   Tag_{fake} = GHASH(H, AAD_{fake}, C_{fake}, len_{fake}) ⊕ AES_K(Y₀)
   ```

Одержувач прийме фальсифіковане повідомлення як повністю легітимне. Тим самим одне повторення `Nonce` у GCM не просто розкриває різницю відкритого тексту, а **повністю знищує захист автентичності для всіх наступних повідомлень під цим ключем**.

### 5. Покроковий числовий приклад атаки на двоблокове повідомлення

Розгляньмо спрощений числовий приклад розкриття ключа `H` для двох повідомлень довжиною по 16 байтів (1 блок шифротексту, `AAD` порожній).

Нехай передано:
- Повідомлення 1: шифротекст `C_1`, довжина `L_1 = 128`, отримано `Tag_1`.
- Повідомлення 2: шифротекст `C_2`, довжина `L_2 = 128`, отримано `Tag_2`.

Блоки для `GHASH`:
- `X_{1,1} = C_1`, `X_{1,2} = L_1`
- `X_{2,1} = C_2`, `X_{2,2} = L_2`

Теги виражаються як:
```
Tag_1 = C_1 · H² ⊕ L_1 · H ⊕ AES_K(Y_0)
Tag_2 = C_2 · H² ⊕ L_2 · H ⊕ AES_K(Y_0)
```

Додаємо обидва рівняння (XOR):
```
Tag_1 ⊕ Tag_2 = (C_1 ⊕ C_2) · H² ⊕ (L_1 ⊕ L_2) · H
```

Оскільки довжини повідомлень однакові (`L_1 = L_2`), член `L_1 ⊕ L_2 = 0` повністю зникає:

```
(C_1 ⊕ C_2) · H² = Tag_1 ⊕ Tag_2
```

Знаходимо `H^2` шляхом множення на обернений елемент у полі `GF(2^128)`:

```
H² = (Tag_1 ⊕ Tag_2) · (C_1 ⊕ C_2)⁻¹
```

Оскільки в полі характеристики 2 операція взяття квадратного кореня `√V = V^{2^{127}}` є однозначною автоморфізмом Фробеніуса, атакуючий знаходить справжній ключ `H` рівно за **одне піднесення до степеня `2^127`**:

```
H = ( (Tag_1 ⊕ Tag_2) · (C_1 ⊕ C_2)⁻¹ )^{2¹²⁷}
```

Ключ `H` відновлено миттєво і детерміновано без перебору кандидатів. Це наочно доводить, чому математична конструкція GHASH не прощає жодної колізії Nonce.
