# 🧮 Математичний апарат GHASH та Poly1305: арифметика скінченних полів і відновлення ключа H

Цей розділ розкриває алгебраїчну структуру універсального гешування в інтегрованих схемах автентифікованого шифрування (AEAD). Без розуміння арифметики двійкових полів Галуа `GF(2¹²⁸)` та простих полів `GF(2¹³⁰ - 5)` неможливо осягнути ні причини колосальної швидкодії алгоритмів GHASH та Poly1305 на сучасному обладнанні, ні механізм повного криптографічного колапсу схеми при повторному використанні одноразового вектора ініціалізації (Nonce).

Тут наведено виведення правил додавання і множення многочленів, схем редукції, безпереносного множення, схему Горнера для паралельної обробки блоків, межі ймовірності підробки тегу за парадоксом днів народження, алгебраїчне відновлення ключа при повторі Nonce для GCM та Poly1305, а також математику стійких до повтору векторів конструкцій SIV.

## 1. Арифметика поля Галуа `GF(2¹²⁸)` у схемі GHASH

Скінченне поле `GF(2¹²⁸)` (двійкове розширене поле степеня 128 над базовим полем `GF(2)`) містить рівно `2¹²⁸` елементів. Кожен елемент поля представляється як двійковий многочлен степеня менше 128 з коефіцієнтами з поля `GF(2) = {0, 1}`:

```
A(x) = a₁₂₇·x¹²⁷ + a₁₂₆·x¹²⁶ + ... + a₁·x + a₀,   де aᵢ ∈ {0, 1}
```

Такий многочлен однозначно кодується 128-бітним двійковим вектором `(a₁₂₇, a₁₂₆, ..., a₀)` або послідовністю з 16 байтів.

### Операція додавання в `GF(2¹²⁸)`

Додавання двох многочленів `A(x)` та `B(x)` у полі характеристики 2 виконується покоефіцієнтно за модулем 2, що на апаратному та програмному рівнях є звичайною порозрядною операцією виключного «АБО» (XOR, `⊕`):

```
C(x) = A(x) + B(x)
     = ∑ (aᵢ ⊕ bᵢ) · xⁱ   [покоординатне додавання за модулем 2]
```

Оскільки в `GF(2)` виконується `1 ⊕ 1 = 0`, операції додавання та віднімання в цьому полі є абсолютно тотожними:

```
A(x) + B(x) = A(x) ⊕ B(x) = A(x) - B(x)
```

### Операція множення та незвідний поліном

Множення двох елементів `A(x)` та `B(x)` складається з двох послідовних кроків:
1. Алгебраїчне безпереносне множення многочленів над `GF(2)`, у результаті якого утворюється проміжний поліном степеня до `127 + 127 = 254`.
2. Редукція (взяття залишку від ділення) проміжного многочлена за незвідним (первісним) поліномом `f(x)` степеня 128.

У специфікації NIST SP 800-38D для алгоритму GCM як базовий стандарт обрано незвідний многочлен:

```
f(x) = x¹²⁸ + x⁷ + x² + x + 1
```

Оскільки `f(x) ≡ 0 (mod f(x))`, старший степінь `x¹²⁸` виражається через молодші члени:

```
x¹²⁸ ≡ x⁷ + x² + x + 1   (mod f(x))
```

### Дзеркальне представлення та двійкова редукція (Reflected Representation)

У стандарті NIST SP 800-38D застосовано відображення бітів за принципом Little-Endian на рівні байтів: старший степінь многочлена `x⁰` відповідає крайньому лівому (найстаршому) біту байта 0, а степінь `x¹²⁷` — наймолодшому біту байта 15.

Через таке відображення порядок бітів є інверсним відносно класичної математичної форми запису многочленів. При зсуві вправо ми множимо поліном на `x`. Коли наймолодший біт 15-го байта виходить за межі 128 бітів, ми повинні додати дзеркальний образ незвідного многочлена `f(x)`.

Незвідний многочлен `x¹²⁸ + x⁷ + x² + x + 1` у дзеркальному записі перетворюється на 128-бітну константу `R`:
* Коефіцієнт при `x⁰` = 1 (біт 0)
* Коефіцієнт при `x¹` = 1 (біт 1)
* Коефіцієнт при `x²` = 1 (біт 2)
* Коефіцієнт при `x⁷` = 1 (біт 7)
* Решта 120 бітів = 0.

У шістнадцятковому форматі константа редукції `R` має вигляд:

```
R = 11100001₂ || 0¹²⁰ = 0xE1000000000000000000000000000000
```

Алгоритм побітового множення двох 128-бітних блоків `X · Y` у `GF(2¹²⁸)`:

```
V = X
Z = 0¹²⁸
Для i від 0 до 127:
    Якщо біт i числа Y дорівнює 1:
        Z = Z ⊕ V
    Якщо молодший біт V дорівнює 0:
        V = V >> 1
    Інакше:
        V = (V >> 1) ⊕ R
Результат: Z = X · Y у GF(2¹²⁸)
```

### Апаратне безпереносне множення (PCLMULQDQ) та метод Карацуби

На сучасних процесорах архітектури x86-64 та ARMv8 операція побітового множення замінюється апаратною інструкцією безпереносного множення (`PCLMULQDQ` в Intel/AMD або `PMULL/PMULL2` в ARM NEON). Ця інструкція перемножує два 64-бітних двійкових поліноми за 1–3 такти процесора, повертаючи 128-бітний безпереносний добуток.

Для множення двох повних 128-бітних блоків `A = (A₁ · 2⁶⁴ + A₀)` та `B = (B₁ · 2⁶⁴ + B₀)` застосовують алгоритм Карацуби над `GF(2)`:

```
M₀ = PCLMUL(A₀, B₀)
M₁ = PCLMUL(A₁, B₁)
M_mid = PCLMUL(A₀ ⊕ A₁, B₀ ⊕ B₁)
M_cross = M_mid ⊕ M₀ ⊕ M₁
Добуток P = M₁ · x¹²⁸ ⊕ M_cross · x⁶⁴ ⊕ M₀   [256-бітний многочлен]
```

Отриманий 256-бітний многочлен редукується за незвідним поліномом `f(x)` за допомогою ще двох швидких операцій `PCLMULQDQ` з попередньо обчисленою константою редукції, що дає сумарну швидкість обчислення GHASH на рівні менше 0.4 такту на байт.

## 2. Схема Горнера та ланцюг обчислення GHASH

Функція GHASH приймає секретний 128-бітний хеш-підключ `H` (отриманий як шифрування нульового блоку `H = AES_K(0¹²⁸)`) та довільну послідовність 128-бітних блоків даних `X = (X₁, X₂, ..., X_m)`.

### Рекурентне обчислення

Обчислення згортки блоків за схемою Горнера задається рекурентним співвідношенням:

```
Y₀ = 0¹²⁸
Y₁ = (Y₀ ⊕ X₁) · H = X₁ · H
Y₂ = (Y₁ ⊕ X₂) · H = (X₁ · H ⊕ X₂) · H = X₁ · H² ⊕ X₂ · H
...
Y_m = (Y_{m-1} ⊕ X_m) · H = ∑ Xᵢ · H^{m - i + 1}   де сума береться за ⊕
```

Розгорнута аналітична формула значення `GHASH_H(X₁, ..., X_m)` являє собою обчислення значення многочлена від невідомої `H`:

```
GHASH_H(X₁, ..., X_m) = X₁·H^m ⊕ X₂·H^{m-1} ⊕ ... ⊕ X_{m-1}·H² ⊕ X_m·H
```

### Форматування вхідного потоку блоків у GCM

Нехай маємо асоційовані дані `A` довжиною `len(A)` бітів та шифротекст `C` довжиною `len(C)` бітів.
1. Послідовність `A` вирівнюється нульовими бітами до найближчого кратного 128 бітам розміру, утворюючи `u` блоків: `A₁, A₂, ..., A_u`.
2. Послідовність `C` вирівнюється нульовими бітами до кратного 128 бітам розміру, утворюючи `v` блоків: `C₁, C₂, ..., C_v`.
3. Формується фінальний 128-бітний блок довжин `L`, який складається з 64-бітного беззнакового цілого `len(A)` та 64-бітного беззнакового цілого `len(C)` у форматі Big-Endian:

```
L = [ len(A) ]₆₄ || [ len(C) ]₆₄
```

Повний вхідний вектор для функції GHASH складається з `m = u + v + 1` блоків:

```
X = (A₁, ..., A_u, C₁, ..., C_v, L)
```

Фінальний автентифікаційний тег `T` отримується накладанням одноразової шифрованої маски `S₀ = AES_K(J₀)` на результат полінома:

```
T = GHASH_H(A, C) ⊕ AES_K(J₀)
```

де `J₀` — початковий лічильник, що формується з 96-бітного Nonce `N` як `J₀ = N || 0³¹ || 1`.

## 3. Поліноміальний автентифікатор Poly1305 у полі `GF(2¹³⁰ - 5)`

На відміну від GCM, який оперує в двійковому полі характеристики 2, алгоритм **Poly1305** (розроблений Даніелем Бернштейном) працює в простому полі за модулем псевдочисла Мерсенна:

```
p = 2¹³⁰ - 5
```

Число `2¹³⁰ - 5` є простим. Вибір саме цього модуля обумовлений винятковою простотою і швидкістю виконання операції взяття залишку:

```
2¹³⁰ ≡ 5 (mod p)
```

Будь-яке проміжне 260-бітне число `Z = Z_hi · 2¹³⁰ + Z_lo` редукується до 130 бітів за один крок без важкого ділення:

```
Z mod p = (Z_hi · 5 + Z_lo) mod (2¹³⁰ - 5)
```

### Представлення кінцівок (Limbs) та уникнення переповнень

Для швидкого програмного обчислення на 64-бітних процесорах 130-бітне число розбивають на три 64-бітні регістри («кінцівки» або limbs) з основою `2⁴⁴`:

```
A = A₀ + A₁ · 2⁴⁴ + A₂ · 2⁸⁸   де A₀, A₁ < 2⁴⁴, A₂ < 2⁴²
```

При множенні на `r = (r₀, r₁, r₂)` перехресні добутки акумулюються у 128-бітних регістрах:

```
D₀ = A₀ · r₀ + (A₁ · r₂ + A₂ · r₁) · 5 · 2⁴⁴ / 2⁴⁴ ...
```

Коефіцієнт `5` виникає саме через те, що частини, що перевищують `2¹³⁰`, домножуються на 5 згідно з рівністю `2¹³⁰ ≡ 5 (mod p)`.

Для 32-бітних процесорів (ARM Cortex-M, MIPS) число розбивають на п'ять 32-бітних регістрів з основою `2²⁶`:

```
A = A₀ + A₁ · 2²⁶ + A₂ · 2⁵² + A₃ · 2⁷⁸ + A₄ · 2¹⁰⁴
```

У цьому випадку добуток будь-яких двох частин `A_i · r_j` не перевищує `2²⁶ · 2²⁶ = 2⁵²`, що чудово вміщується в стандартне 64-бітне беззнакове множення без переповнення та без необхідності поблокового ділення.

### Клемпування ключа (Key Clamping)

Poly1305 вимагає 256-бітного одноразового ключа `(r, s)`, де `r` — 128-бітний коефіцієнт полінома, а `s` — 128-бітна одноразова маска. Для гарантування стійкості та запобігання переповненню розрядів при 64-бітних операціях над вектором `r` виконується операція «клемпування» (очищення фіксованих бітів):

```
r[3], r[7], r[11], r[15] &= 0x0F   [очищення 4 старших бітів кожного 4-го байта]
r[4], r[8], r[12]        &= 0xFC   [очищення 2 молодших бітів кожного 4-го байта]
```

Це обмежує `r` до спеціальної підмножини, де певні бітові позиції гарантовано дорівнюють нулю, що усуває слабкі ключі та запобігає поширенню переносів між регістрами під час безперервного додавання без потреби у фінальній редукції після кожного доданка.

### Схема обчислення Poly1305

Вхідне повідомлення розбивається на 16-байтові блоки `B₁, B₂, ..., B_k`. До кожного блоку праворуч дописується байт `0x01` (що еквівалентно додаванню `2¹²⁸`), утворюючи 129-бітне ціле число. Це усуває неоднозначність нульових хвостів.

Акумулятор `Acc` обчислюється за схемою Горнера:

```
Acc₀ = 0
Acc₁ = ((Acc₀ + B₁ + 2¹²⁸) · r) mod (2¹³⁰ - 5)
Acc₂ = ((Acc₁ + B₂ + 2¹²⁸) · r) mod (2¹³⁰ - 5)
...
Acc_k = ((Acc_{k-1} + B_k + 2¹²⁸) · r) mod (2¹³⁰ - 5)
```

Фінальний тег автентичності `Tag` формується додаванням 128-бітної маски `s` за модулем `2¹²⁸`:

```
Tag = (Acc_k + s) mod 2¹²⁸
```

## 4. Межі безпеки та ймовірність випадкової підробки тегу

Універсальне поліноміальне гешування гарантує інформаційно-теоретичну межу стійкості до підробки повідомлення за умови, що ключ `(H, S₀)` або `(r, s)` використовується строго один раз.

Нехай зловмисник намагається підробити повідомлення довжиною `m` блоків. Різниця між автентифікаційними поліномами для двох різних повідомлень є ненульовим многочленом степеня не вище `m`. За основною теоремою алгебри такий многочлен над полем `GF(2¹²⁸)` або `GF(2¹³⁰ - 5)` має не більше ніж `m` коренів.

Ймовірність `P_forge` того, що випадково обраний фальшивий тег виявиться валідним для модифікованого пакету розміром `m` блоків, строго обмежена зверху:

```
P_forge ≤ m / 2¹²⁸   (для AES-GCM)
P_forge ≤ m / (2¹³⁰ - 5)   (для Poly1305)
```

Для стандартного мережевого кадру довжиною 1500 байтів (`m ≈ 100`) ймовірність успішної підробки становить менше `100 / 2¹²⁸ ≈ 2⁻¹²¹`, що робить підбір тегу абсолютно нездійсненним на практиці.

## 5. Алгебраїчне відновлення ключа H при повторі Nonce у GCM

Припустимо, відправник зашифрував два різних повідомлення `M₁ = (A₁, P₁)` та `M₂ = (A₂, P₂)` з використанням одного й того самого секретного ключа `K` та **однакового вектора ініціалізації Nonce `N`**.

У результаті зловмисник перехоплює в каналі зв'язку пари шифротекстів і тегів:
* Пакет 1: `C₁`, `T₁ = GHASH_H(A₁, C₁) ⊕ AES_K(J₀)`
* Пакет 2: `C₂`, `T₂ = GHASH_H(A₂, C₂) ⊕ AES_K(J₀)`

Оскільки Nonce `N` однаковий, значення початкового лічильника `J₀ = N || 0³¹ || 1` також ідентичне в обох випадках. Відповідно, невідома 128-бітна маска тегу `S₀ = AES_K(J₀)` є повністю однаковою для обох пакетів.

### Крок 1. Знищення маски тегу

Виконаємо операцію XOR між двома перехопленими тегами `T₁` та `T₂`:

```
T₁ ⊕ T₂
= (GHASH_H(A₁, C₁) ⊕ S₀) ⊕ (GHASH_H(A₂, C₂) ⊕ S₀)   [підстановка формул тегів]
= GHASH_H(A₁, C₁) ⊕ GHASH_H(A₂, C₂) ⊕ (S₀ ⊕ S₀)     [комутативність XOR]
= GHASH_H(A₁, C₁) ⊕ GHASH_H(A₂, C₂) ⊕ 0             [властивість: X ⊕ X = 0]
= GHASH_H(A₁, C₁) ⊕ GHASH_H(A₂, C₂)                 [маска S₀ повністю скоротилася]
```

### Крок 2. Формування алгебраїчного полінома від H

Нехай вектор блоків першого повідомлення має вигляд `(X₁, X₂, ..., X_m)`, а другого — `(W₁, W₂, ..., W_k)`.
Без втрати загальності припустимо, що довжина блоків однакова `m = k` (якщо ні, коротший вектор просто доповнюється нульовими старшими коефіцієнтами).

Розпишемо різницю GHASH через поліноми:

```
GHASH_H(X) ⊕ GHASH_H(W)
= (X₁·H^m ⊕ ... ⊕ X_m·H) ⊕ (W₁·H^m ⊕ ... ⊕ W_m·H)           [розгортання значень многочленів]
= (X₁ ⊕ W₁)·H^m ⊕ (X₂ ⊕ W₂)·H^{m-1} ⊕ ... ⊕ (X_m ⊕ W_m)·H    [групування доданків при однакових степенях H]
```

Позначимо різницю коефіцієнтів як `Δ_i = X_i ⊕ W_i`, а різницю тегів як `Δ_T = T₁ ⊕ T₂`.
Отримуємо поліноміальне рівняння степеня `m` відносно єдиної невідомої величини `H`:

```
P(H) = Δ₁·H^m ⊕ Δ₂·H^{m-1} ⊕ ... ⊕ Δ_m·H ⊕ Δ_T = 0   у полі GF(2¹²⁸)
```

Усі коефіцієнти `Δ₁, Δ₂, ..., Δ_m` та вільний член `Δ_T` є **повністю відомими величинами**, оскільки вони складаються виключно з перехоплених з каналу відкритих заголовків AAD, шифротекстів, довжин пакетів та тегів.

### Крок 3. Числовий приклад розв'язання для 2-блокового пакета

Розглянемо спрощений випадок повідомлення з одного блоку AAD `A₁` та одного блоку шифротексту `C₁`. Разом із блоком довжини `L₁` маємо `m = 3` блоки: `(A₁, C₁, L₁)`.
Для другого повідомлення маємо блоки `(A₂, C₂, L₂)`.

Рівняння набуває вигляду кубічного полінома:

```
(A₁ ⊕ A₂)·H³ ⊕ (C₁ ⊕ C₂)·H² ⊕ (L₁ ⊕ L₂)·H ⊕ (T₁ ⊕ T₂) = 0
```

Якщо обидва пакети мали однакову довжину, то `L₁ = L₂`, і лінійний член зануляється: `L₁ ⊕ L₂ = 0`. Рівняння спрощується до полінома:

```
Δ_A · H³ ⊕ Δ_C · H² ⊕ Δ_T = 0
```

У полі характеристики 2 факторизація многочлена методом розкладання на незвідні множники виконується за лічені мілісекунди.

### Крок 4. Знаходження коренів полінома над `GF(2¹²⁸)`

Многочлен `P(H)` має степінь `m`, де `m` зазвичай дорівнює кількості 128-бітних блоків у пакеті (наприклад, для стандартного кадру Ethernet розміром 1500 байтів `m ≈ 100`).

У скінченному полі `GF(2¹²⁸)` корені полінома знаходяться за поліноміальний час за допомогою класичного **алгоритму Кантора — Цассенгауза** (Cantor–Zassenhaus) або **алгоритму Берлекампа** (Berlekamp trace algorithm):
1. Обчислюється `d(H) = НСД(P(H), H^{2^{128}} - H)`. Це виділяє добуток усіх лінійних множників `(H - α)`, де `α` — корінь у `GF(2¹²⁸)`.
2. Застосовується оператор сліду `Tr(z) = z + z² + z⁴ + ... + z^{2^{127}}` для розщеплення полінома на множники менших степенів.

Кількість коренів полінома `P(H)` не перевищує його степеня `m` (тобто не більше ~100 кандидатів). Якщо зловмисник перехопить третій пакет `M₃`, зашифрований з тим самим Nonce `N`, обчислення спільного дільника `НСД(P₁(H), P₂(H))` однозначно звужує множину коренів до **рівно одного справжнього значення `H`**.

### Крок 5. Відновлення маски тегу та довільна універсальна підробка

Маючи обчислене значення хеш-підключа `H`, зловмисник миттєво обчислює маску `S₀`:

```
S₀ = T₁ ⊕ GHASH_H(A₁, C₁)
```

Тепер зловмисник володіє повним контролем над каналом:
1. Для будь-якого фальшивого відкритого тексту `P_forge` та метаданих `A_forge` формується шифротекст за допомогою перехопленої гами шифру: `C_forge = P_forge ⊕ (C₁ ⊕ P₁)`.
2. Обчислюється легітимний автентифікаційний тег:
   ```
   T_forge = GHASH_H(A_forge, C_forge) ⊕ S₀
   ```
3. Отримувач перевіряє `T_forge`, отримує нульову різницю і приймає сфальсифікований пакет `(A_forge, C_forge, T_forge)` як повністю автентичний.

Знання підключа `H = AES_K(0¹²⁸)` є глобальним для всієї сесії під ключем `K`. Навіть якщо для інших пакетів генератор відправника використає новий Nonce `N_k`, але зловмисник зможе вгадати або отримати хоча б один відкритий байт, знання `H` дозволяє здійснювати підробки тегів для всієї подальшої комунікації.

## 6. Компрометація ключа Poly1305 при повторі одноразової пари `(r, s)`

Аналогічна катастрофа трапляється в схемі ChaCha20-Poly1305, якщо пара ключів `(r, s)` використовується для автентифікації більше ніж одного повідомлення.

Нехай два повідомлення мають значення акумулятора `Acc₁` та `Acc₂`, а їхні теги рівні:

```
Tag₁ = (Acc₁ + s) mod 2¹²⁸
Tag₂ = (Acc₂ + s) mod 2¹²⁸
```

Віднімаючи одне рівняння від іншого за модулем `2¹²⁸`, отримуємо:

```
Tag₁ - Tag₂ ≡ Acc₁ - Acc₂ (mod 2¹²⁸)
```

Оскільки акумулятори є поліномами від невідомої `r` над полем `GF(2¹³⁰ - 5)`:

```
Acc₁ - Acc₂ = (B₁,₁ - B₂,₁)·r^k + ... + (B₁,k - B₂,k)·r
```

Маємо рівняння відносно єдиного невідомого числа `r` над полем `GF(2¹³⁰ - 5)`:

```
P(r) = (Tag₁ - Tag₂ + k · 2¹²⁸) mod (2¹³⁰ - 5)
```

Для коротких повідомлень (довжиною в один блок `B₁` та `B₂`) рівняння стає лінійним:

```
(B₁ - B₂) · r ≡ Tag₁ - Tag₂ (mod 2¹²⁸)
```

Зловмисник обчислює обернений елемент `(B₁ - B₂)⁻¹` у полі `GF(2¹³⁰ - 5)` за допомогою розширеного алгоритму Евкліда та безпосередньо знаходить секретний ключ `r`. Після цього відновлюється маска `s = (Tag₁ - Acc₁) mod 2¹²⁸`, що повністю відкриває можливість необмеженої генерації фальшивих підписів.

## 7. Математична нейтралізація атаки в режимі AES-GCM-SIV (RFC 8452)

Щоб захиститися від повтору векторів ініціалізації в ненадійних середовищах (наприклад, у віртуальних машинах, що повертаються до попереднього знімка пам'яті / с snapshot), криптографи розробили синтетичний режим **AES-GCM-SIV** (RFC 8452).

В основі SIV лежить детерміноване обчислення синтетичного вектора `IV` безпосередньо з відкритого тексту повідомлення `P` та асоційованих даних `A`:

```
S = POLYVAL_H(A, P) ⊕ N
IV_synth = AES_K1(S)   [синтетичний вектор ініціалізації]
C = AES_CTR_K2(IV_synth, P)
Tag = IV_synth
```

Функція `POLYVAL` є Little-Endian варіантом GHASH у полі `GF(2¹²⁸)` з незвідним поліномом `x¹²⁸ + x¹²⁷ + x¹²⁶ + x¹²¹ + 1`.

Якщо Nonce `N` повторюється для двох різних відкритих текстів `P₁ ≠ P₂`, значення `S₁ ≠ S₂` будуть різними. Як наслідок, шифрування AES видасть повністю непов'язані псевдовипадкові вектори `IV_synth,1 ≠ IV_synth,2`. Гами шифрування та маски тегів для двох повідомлень залишаються некорельованими, що повністю запобігає як атаці Two-Time Pad, так і скороченню масок у поліноміальному рівнянні GHASH.
