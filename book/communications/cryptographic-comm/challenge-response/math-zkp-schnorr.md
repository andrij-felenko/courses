# 🧮 Протокол Шнора та ідентифікація Гію-Кіскатера: доведення знання без витоку бітів

Коли дві сторони виконують класичну процедуру виклику-відповіді на основі цифрового підпису, перевіряльник отримує повідомлення, яке математично засвідчує авторство. Проте підпис є передаваною структурою: перевіряльник може зберегти його і показати третій стороні як незаперечний доказ того, що підписант брав участь у сесії. Доведення з нульовим розголошенням (*Zero-Knowledge Proofs, ZKP*) розв'язують іншу задачу: довести перевіряльнику тут і зараз факт володіння секретним ключем так, щоб перевіряльник переконався на 100%, але при цьому не отримав жодного біта інформації про секрет і не зміг довести третій стороні абсолютно нічого. Математичним еталоном таких систем є трикроковий протокол ідентифікації Шнора (*Schnorr identification protocol*) та схема Гію-Кіскатера (*Guillou-Quisquater*).

## Алгебраїчна група Шнора та задача дискретного логарифма

Протокол Шнора розгортається у мультиплікативній підгрупі простого порядку, де обчислення дискретного логарифма є обчислювально нездійсненним завданням.

Параметри системи генеруються таким чином:
1. Обирають велике просте число `p` довжиною 2048 або 3072 біти.
2. Обирають просте число `q` довжиною 256 бітів таке, що `q` є дільником числа `p - 1` (тобто `p - 1 ≡ 0 (mod q)`).
3. Знаходять генератор `g` підгрупи `Gq` порядку `q` у мультиплікативній групі `Zp*`. Для цього беруть довільний елемент `h ∈ Zp*` і обчислюють `g = h^((p - 1) / q) mod p` (за умови `g ≠ 1`).
4. Порядок елемента `g` дорівнює `q`, тобто `g^q ≡ 1 (mod p)`.

Секретний ключ доводжувача (*Prover, Alice*) — це випадкове число:

```
x ∈ Zq* = {1, 2, ..., q - 1}
```

Відкритий ключ, відомий перевіряльнику (*Verifier, Bob*) та всім учасникам мережі, обчислюється як піднесення генератора до степеня секрету:

```
Y = g^x mod p
```

Стійкість протоколу спирається на складність задачі дискретного логарифма (DLP): знаючи публічні параметри `(p, q, g)` та відкритий ключ `Y`, знайти `x` за поліноміальний час на класичному комп'ютері неможливо.

## Три кроки інтерактивного сигма-протоколу

Протокол Шнора належить до класу сигма-протоколів (Σ-protocols) через свою трифазну структуру зв'язку: Зобов'язання → Виклик → Відповідь (*Commitment → Challenge → Response*).

### Крок 1: Зобов'язання (Commitment)
Доводжувач генерує одноразове випадкове число `v` (ефемерний секрет), рівномірно розподілене в кільці `Zq`:

```
v ∈ Zq*
```

Доводжувач обчислює значення зобов'язання `R` і відсилає його перевіряльнику:

```
R = g^v mod p
```

Значення `R` маскує ефемерне число `v` в групі `Gq`. Перевіряльник, отримавши `R`, не може відновити `v` через складність дискретного логарифма.

### Крок 2: Виклик (Challenge)
Отримавши `R`, перевіряльник обирає випадковий виклик `c` із множини бітових рядків довжини `t` (де `2^t ≤ q`, зазвичай `t = 128` або `t = 256` бітів):

```
c ∈ {0, 1, ..., 2^t - 1}
```

Перевіряльник надсилає число `c` доводжувачу. Непередбачуваність `c` є критичною: доводжувач не повинен мати змоги передбачити `c` до того, як зафіксує значення `R`.

### Крок 3: Відповідь (Response)
Доводжувач обчислює лінійну комбінацію ефемерного та довготривалого секретів за модулем `q`:

```
s = (v + c · x) mod q
```

Доводжувач надсилає число `s` перевіряльнику.

### Крок 4: Верифікація (Verification)
Перевіряльник перевіряє, що `R ≠ 0` та `R ∈ Gq`, після чого обчислює обидві частини рівняння в групі `Zp*`:

```
ліва частина   = g^s mod p
права частина  = (R · Y^c) mod p
```

Якщо `g^s ≡ R · Y^c (mod p)`, перевіряльник приймає доведення (*Accept*), інакше відхиляє (*Reject*).

## Математичне доведення повноти (Completeness)

Властивість повноти гарантує: якщо доводжувач чесно знає секрет `x` і дотримується кроків протоколу, перевіряльник завжди прийме доведення.

Розгорнемо ліву частину перевірочної рівності, підставивши вираз для `s`:

```
g^s mod p
= g^(v + c·x mod q) mod p
= g^(v + c·x) mod p             [оскільки порядок g дорівнює q: g^q ≡ 1 mod p]
= (g^v · g^(c·x)) mod p         [властивість степеня: g^(a+b) = g^a · g^b]
= (g^v · (g^x)^c) mod p         [властивість степеня: g^(c·x) = (g^x)^c]
= (R · Y^c) mod p               [за означенням: R = g^v mod p та Y = g^x mod p]
```

Обидві частини тотожно збігаються. Повнота доведена строго для будь-якого коректного виконання.

## Спеціальна обґрунтованість (Special Soundness) та екстрактор знань

Властивість обґрунтованості (*Soundness*) стверджує: ошуканець (*Cheater*), який не знає секрету `x`, не може переконати перевіряльника за винятком мізерної ймовірності випадкового вгадування.

Сигма-протокол володіє властивістю **спеціальної обґрунтованості**: маючи два успішні протокольні транскрипти з однаковим зобов'язанням `R`, але різними викликами `c1 ≠ c2`, можна за поліноміальний час повністю вилучити секрет `x`.

Нехай існують дві трійки прийнятих значень:

```
Транскрипт 1: (R, c1, s1),  де  g^s1 ≡ R · Y^c1 (mod p)
Транскрипт 2: (R, c2, s2),  де  g^s2 ≡ R · Y^c2 (mod p)
```

Поділимо першу рівність на другу в полі лишків по модулю `p`:

```
g^s1 / g^s2 ≡ (R · Y^c1) / (R · Y^c2) (mod p)
g^(s1 - s2) ≡ Y^(c1 - c2) (mod p)
```

Оскільки `Y = g^x mod p`, підставимо його у праву частину:

```
g^(s1 - s2) ≡ (g^x)^(c1 - c2) (mod p)
g^(s1 - s2) ≡ g^(x · (c1 - c2)) (mod p)
```

Перейдемо до показників степенів за модулем порядку групи `q`:

```
s1 - s2 ≡ x · (c1 - c2) (mod q)
```

Оскільки `c1 ≠ c2` і `q` — просте число, різниця `c1 - c2` є взаємно простою з `q`, отже існує мультиплікативний обернений елемент `(c1 - c2)⁻¹ mod q`. Помножимо обидві частини на цей обернений елемент:

```
x = ((s1 - s2) · (c1 - c2)⁻¹) mod q
```

Цей результат доводить існування поліноміального **екстрактора знання** (*Knowledge Extractor*): якщо доводжувач здатний відповісти на два різні виклики для одного й того самого `R`, він гарантовано володіє `x`. Якщо ж ошуканець не знає `x`, він може підготувати коректну відповідь `s` щонайбільше для одного конкретного виклику `c`. Ймовірність успіху ошуканця в одному раунді становить рівно:

```
P(успіху) = 1 / 2^t
```

При `t = 128` бітів ця ймовірність дорівнює `2⁻¹²⁸ ≈ 2.9 · 10⁻³⁹`, що робить фальсифікацію абсолютно неможливою.

## Доведення нульового розголошення (HVZK) та симулятор

Найтонша властивість протоколу — нульове розголошення щодо чесного перевіряльника (*Honest-Verifier Zero-Knowledge, HVZK*). Необхідно довести, що транскрипт сесії `(R, c, s)` не містить жодної інформації про секрет `x`.

Формальне визначення Zero-Knowledge за Голдвассером, Мікалі та Ракоффом (1985) вимагає існування імовірнісного поліноміального алгоритму — **симулятора** (*Simulator*), який, знаючи лише відкритий ключ `Y` (і не маючи доступу до секрету `x`), здатний згенерувати трійку значень `(R', c', s')`, чий імовірнісний розподіл є строго ідентичним до розподілу реальних сесій між Алісою та Бобом.

### Алгоритм симулятора Sim(Y)
1. Симулятор обирає випадковий виклик `c' ∈ {0, 1, ..., 2^t - 1}`.
2. Симулятор обирає випадкову відповідь `s' ∈ Zq*`.
3. Симулятор штучно конструює зобов'язання `R'`, розгортаючи перевірочну формулу назад:

```
R' = (g^s' · Y^(-c')) mod p
```

Перевіримо, чи задовольняє трійка `(R', c', s')` рівняння перевірки:

```
R' · Y^c'
= (g^s' · Y^(-c')) · Y^c' mod p     [підстановка R' за формулою симулятора]
= g^s' · Y^(-c' + c') mod p         [властивість степеня: Y^a · Y^b = Y^(a+b)]
= g^s' · Y^0 mod p                  [арифметика показників: -c' + c' = 0]
= g^s' mod p                        [нейтральний елемент групи: Y^0 = 1]
```

Рівність виконується абсолютно.

### Аналіз імовірнісних розподілів
Порівняємо розподіл реальних та змодельованих змінних:
- У реальному протоколі: `v` обирається рівномірно з `Zq`, тому `R = g^v mod p` розподілене рівномірно в `Gq`. Виклик `c` обирається незалежно і рівномірно з `{0, ..., 2^t - 1}`. Відповідь `s = v + c·x mod q` є рівномірно розподіленою в `Zq`, оскільки випадкове `v` діє як одноразовий блокнот (*One-Time Pad*), що маскує `c·x`.
- У симуляції: `c'` обирається рівномірно з `{0, ..., 2^t - 1}`, `s'` обирається рівномірно з `Zq`, а `R'` однозначно визначається парою `(s', c')`.

Спільні ймовірнісні розподіли випадкових трійок `(R, c, s)` у реальному протоколі та `(R', c', s')` у симуляторі є **строго ідентичними**:

```
Dist(Реальний транскрипт) ≡ Dist(Симульований транскрипт)
```

Звідси випливає фундаментальний висновок: оскільки будь-який сторонній спостерігач або сам Боб міг би згенерувати такий транскрипт самостійно на своєму комп'ютері без участі Аліси, отриманий у результаті сесії запис `(R, c, s)` несе **рівно 0 бітів корисної інформації** про секретний ключ `x`.

## Межі чесного перевіряльника та перехід до повного ZK

Властивість HVZK гарантує нульове розголошення лише за умови, що перевіряльник обирає виклик `c` чесно і випадково. Якщо перевіряльник є зловмисним (*Malicious Verifier*), він може генерувати виклики не випадково, а адаптивно залежно від отриманого `R` (наприклад, обирати `c = H(R, state)` або вживати зміщені бітові структури), намагаючись вилучити біти секрету `x` через серію повторних взаємодій.

Щоб перетворити протокол зі слабкого HVZK на повний інтерактивний Zero-Knowledge, стійкий до будь-якого зловмисного перевіряльника, застосовують протокол зобов'язання для виклику (*Commitment on Challenge*):
1. Аліса надсилає зобов'язання `R`.
2. Боб обирає виклик `c` і спочатку надсилає лише його криптографічне зобов'язання `Commit(c, r_bob) = H(c || r_bob)`.
3. Аліса фіксує отримання зобов'язання.
4. Боб розкриває пару `(c, r_bob)`.
5. Аліса перевіряє, що `H(c || r_bob)` збігається з раніше надісланим зобов'язанням, і лише після цього обчислює й повертає відповідь `s`.

Така попередня фіксація позбавляє Боба можливості адаптивно вибирати `c` після спостереження за `R`, що відновлює строгу властивість нульового розголошення проти будь-якого супротивника.

## Оптимізація верифікації: трюк Штрауса-Шаміра

На етапі верифікації перевіряльник повинен обчислити вираз `R · Y^c mod p`. Якщо обчислювати `Y^c` окремим піднесенням до степеня (що вимагає в середньому `1.5 · t` операцій множення за методом подвоєння та додавання), а потім множити на `R`, це створює помітне обчислювальне навантаження.

Алгоритм Штрауса (*Straus-Shamir multi-exponentiation*) дозволяє обчислити добуток степенів `g^a · Y^b` паралельно за один прохід за бітами показників:
1. Заздалегідь обчислюють таблицю добутків основ для комбінацій бітів: `g^0 · Y^0 = 1`, `g^1 · Y^0 = g`, `g^0 · Y^1 = Y`, `g^1 · Y^1 = g · Y`.
2. Сканують біти показників `a` та `b` від старшого до молодшого.
3. На кожному кроці виконують одне спільне піднесення акумулятора до квадрата та одне множення на попередньо обрахований елемент таблиці відповідно до пари поточних бітів `(a_i, b_i)`.

Така оптимізація скорочує час верифікації добутку на 35–40%, наближаючи вартість перевірки до вартості одного звичайного піднесення до степеня.

## Доведення рівності дискретних логарифмів (Протокол Chaum-Pedersen / DLEQ)

Прямим узагальненням сигма-протоколу Шнора є протокол доведення рівності двох дискретних логарифмів у різних базах без розкриття самого логарифма (DLEQ — *Discrete Logarithm Equality*).

Задача: довести, що для публічних точок `Y1 = g1^x mod p` та `Y2 = g2^x mod p` доводжувач знає одне й те саме значення `x` відносно різних генераторів `g1` та `g2`.

### Кроки протоколу DLEQ:
1. **Зобов'язання (Prover):**
   Доводжувач генерує єдине ефемерне число `v ∈ Zq*` та обчислює пару зобов'язань:
   ```
   R1 = g1^v mod p
   R2 = g2^v mod p
   ```
   Надсилає пару `(R1, R2)` перевіряльнику.
2. **Виклик (Verifier):**
   Перевіряльник надсилає випадковий виклик `c ∈ {0, ..., 2^t - 1}`.
3. **Відповідь (Prover):**
   Доводжувач обчислює лінійну відповідь:
   ```
   s = (v + c · x) mod q
   ```
   Надсилає `s` перевіряльнику.
4. **Верифікація (Verifier):**
   Перевіряльник перевіряє одночасне виконання двох рівностей:
   ```
   g1^s ≟ R1 · Y1^c (mod p)
   g2^s ≟ R2 · Y2^c (mod p)
   ```

Якщо обидві перевірки проходять, це математично гарантує, що дискретний логарифм `Y1` за основою `g1` дорівнює дискретному логарифму `Y2` за основою `g2`. Ця конструкція є основою конфіденційних транзакцій, криптографічних мікшерів та сліпих підписів.

## Числовий приклад роботи протоколу Шнора

Розглянемо числовий розрахунок на іграшкових параметрах невеликого розміру, щоб простежити кожен арифметичний крок.

**Параметри системи:**
- Просте число `p = 467`.
- Просте число `q = 233` (дільник `p - 1 = 466 = 2 · 233`).
- Генератор: знайдемо елемент порядку `q`. Візьмемо `h = 2`:
  `g = 2^2 mod 467 = 4`. Перевірка порядку: `4^233 ≡ 1 (mod 467)`.
- Секретний ключ Аліси: `x = 89 ∈ Z233*`.
- Відкритий ключ Аліси:
  `Y = g^x mod p = 4^89 mod 467 = 345`.

**Крок 1: Зобов'язання (Alice)**
- Аліса генерує випадкове `v = 53 ∈ Z233*`.
- Обчислює зобов'язання `R = 4^53 mod 467 = 293`.
- Відправляє `R = 293` Бобу.

**Крок 2: Виклик (Bob)**
- Боб генерує випадковий виклик `c = 15`.
- Відправляє `c = 15` Алісі.

**Крок 3: Відповідь (Alice)**
- Аліса рахує: `s = (v + c · x) mod q = (53 + 15 · 89) mod 233`.
- `15 · 89 = 1335`.
- `53 + 1335 = 1388`.
- `1388 mod 233 = 223` (оскільки `1388 = 5 · 233 + 223`).
- Аліса відправляє `s = 223` Бобу.

**Крок 4: Перевірка (Bob)**
- Боб обчислює ліву частину:
  `ліва = g^s mod p = 4^223 mod 467 = 196`.
- Боб обчислює праву частину:
  `Y^c mod p = 345^15 mod 467 = 247`.
  `права = (R · Y^c) mod p = (293 · 247) mod 467 = 72371 mod 467 = 196`.
- `196 ≡ 196 (mod 467)` — перевірка успішна!

## Варіант на еліптичних кривих (EC-Schnorr)

У сучасних криптосистемах (Ed25519, Secp256k1 у Bitcoin) мультиплікативну групу чисел за модулем `p` замінюють групою точок на еліптичній кривій `E(Fp)`. Замість піднесення до степеня використовують множення точки на скаляр:

- Публічні параметри: базова точка `G` простого порядку `l`.
- Секретний ключ: скаляр `x ∈ Zl*`.
- Відкритий ключ: точка `Y = x · G`.
- Зобов'язання: випадковий скаляр `v ∈ Zl*`, точка `R = v · G`.
- Виклик: скаляр `c ∈ Zl`.
- Відповідь: `s = (v + c · x) mod l`.
- Перевірка: `s · G ≟ R + c · Y`.

Доведення повноти на еліптичній кривій:

```
s · G
= (v + c · x) · G                   [підстановка скаляра відповіді s]
= v · G + (c · x) · G               [дистрибутивність множення точки на скаляр]
= R + c · (x · G)                   [заміна R = v · G та асоціативність]
= R + c · Y                         [підстановка відкритого ключа Y = x · G]
```

Перехід до еліптичних кривих скорочує розмір зобов'язання `R` з 256 байтів до 32 байтів і прискорює обчислення в десятки разів при тому самому рівні стійкості.

## Евристика Фіата-Шаміра: перетворення в цифровий підпис

Інтерактивний діалог із трьох повідомлень незручний для асинхронних протоколів (електронна пошта, підпис файлів, транзакції блокчейну). У 1986 році Амос Фіат (*Amos Fiat*) та Аді Шамір (*Adi Shamir*) запропонували евристику, яка замінює інтерактивного перевіряльника криптографічною геш-функцією, що моделюється як випадковий оракул (*Random Oracle*).

Замість очікування числа `c` від Боба, Аліса обчислює виклик самостійно як геш від зобов'язання `R` та підписуваного повідомлення `M`:

```
c = H(R || M)
```

Алгоритм неінтерактивного доведення (цифрового підпису Шнора):
1. Генерація: `v ∈ Zq*`, `R = g^v mod p`.
2. Виклик: `c = H(R || M) mod q`.
3. Відповідь: `s = (v + c · x) mod q`.
4. Підпис — це пара `(R, s)` або компактніше `(c, s)`.

Верифікатор відновлює `R' = (g^s · Y^(-c)) mod p` і перевіряє рівність:

```
c ≟ H(R' || M)
```

Евристика Фіата-Шаміра зберігає спеціальну обґрунтованість у моделі випадкового оракула (*Random Oracle Model*), перетворюючи протокол ідентифікації на один із найефективніших алгоритмів цифрового підпису у криптографії (покладений в основу стандартів Ed25519 та BIP-340 у мережі Bitcoin).

## Схема ідентифікації Гію-Кіскатера (Guillou-Quisquater)

Якщо протокол Шнора спирається на групу дискретного логарифма, то схема Луї Гію та Жан-Жака Кіскатера (1988) будується над складним складеним модулем RSA, де порядки груп невідомі учасникам.

### Параметри системи та ключі
1. Модуль RSA: `n = p · q`, де `p` і `q` — великі секретні прості числа.
2. Публічна експонента: просте число `e ≥ 3` (наприклад, `e = 65537` або спеціальне 16-бітне число).
3. Секретний ключ клієнта: число `s ∈ Zn*`.
4. Публічний ключ клієнта `v ∈ Zn*` пов'язаний із секретом співвідношенням оберненого кореня:

```
v · s^e ≡ 1 (mod n)    або    v = (s⁻¹)^e mod n
```

Стійкість схеми спирається на складність знаходження коренів степеня `e` за модулем `n` (задача RSA).

### Протокол обміну
1. **Commitment (Зобов'язання):**
   Доводжувач обирає випадкове число `r ∈ Zn*`, обчислює `T` і відсилає його:
   ```
   T = r^e mod n
   ```
2. **Challenge (Виклик):**
   Перевіряльник надсилає випадкове число `d` у діапазоні:
   ```
   d ∈ {0, 1, ..., e - 1}
   ```
3. **Response (Відповідь):**
   Доводжувач обчислює мультиплікативну відповідь:
   ```
   t = (r · s^d) mod n
   ```
4. **Verification (Перевірка):**
   Перевіряльник перевіряє виконання рівності:
   ```
   t^e · v^d ≟ T (mod n)
   ```

### Доведення повноти схеми Гію-Кіскатера
Підставимо вираз для `t` у перевірочне рівняння:

```
t^e · v^d mod n
= (r · s^d)^e · v^d mod n
= (r^e · (s^d)^e) · v^d mod n
= r^e · (s^e)^d · v^d mod n
= r^e · (s^e · v)^d mod n
= r^e · (1)^d mod n             [оскільки за побудовою s^e · v ≡ 1 mod n]
= r^e mod n
= T mod n                       [за означенням T = r^e mod n]
```

Рівність виконується.

### Екстрактор знань у схемі Гію-Кіскатера
Нехай ошуканець зумів дати дві коректні відповіді `t1` та `t2` на різні виклики `d1 > d2` для одного зобов'язання `T`:

```
t1^e · v^d1 ≡ T (mod n)
t2^e · v^d2 ≡ T (mod n)
```

Поділимо одне рівняння на інше:

```
(t1 / t2)^e ≡ v^(d2 - d1) (mod n)
```

Позначимо `Δd = d1 - d2`. Оскільки `0 < Δd < e`, а `e` — просте число, то `НСД(Δd, e) = 1`. За тотожністю Безу існують цілі числа `u` та `w` такі, що:

```
u · Δd + w · e = 1
```

Обчислимо значення `s' = v^(-w) · (t1 / t2)^(-u) mod n`. Піднесемо `s'` до степеня `e`:

```
(s')^e ≡ v^(-w · e) · (t1 / t2)^(-u · e)
       ≡ v^(-w · e) · (v^(-Δd))^(-u)
       ≡ v^(-w · e + u · Δd)
       ≡ v^(-(w · e + u · Δd))
       ≡ v^(-1) (mod n)
```

Отримали `(s')^e · v ≡ 1 (mod n)`, тобто екстрактор відновив секретний корінь `s = s' mod n`.

## Порівняння математичних параметрів схем ZKP

Схеми Шнора та Гію-Кіскатера демонструють різні інженерні компроміси між розміром ключів, обчислювальною складністю та структурою довіри:

| Властивість | Протокол Шнора (DLP / Еліптичні криві) | Схема Гію-Кіскатера (RSA / Факторизація) |
| :--- | :--- | :--- |
| **Математична основа** | Дискретний логарифм у підгрупі простого порядку | Добування кореня степеня `e` за модулем `n` |
| **Довірене налаштування** | Не потрібне (лише вибір кривої або групи `p, q, g`) | Потрібне (генерація модуля `n = p·q` без витоку `p, q`) |
| **Розмір зобов'язання** | 32 байти (на Ed25519) / 256 байтів (Zp) | 256–384 байти (довжина модуля `n`) |
| **Операції доводжувача** | 1 піднесення до степеня + 1 множення в полі | 1 піднесення до степеня + 1 множення по модулю `n` |
| **Операції верифікатора** | 2 піднесення до степеня (або multi-exponentiation) | 2 короткі піднесення до степеня (якщо `e, d` малі) |
| **Сфера впровадження** | FIDO2, EdDSA, Schnorr Signatures, блокчейн-ZKP | Смарт-картки ISO/IEC 9798-5, чипи PayTV |

Обидві схеми надають математично строгий апарат для доведення знання секрету: перевіряльник отримує абсолютну впевненість у легітимності контрагента, але залишається з нулем бітів секрету в руках.
