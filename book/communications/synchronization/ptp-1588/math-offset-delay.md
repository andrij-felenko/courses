# 🧮 Розрахунок зміщення та затримки у протоколі PTP

Цей математичний апарат дає строге алгебраїчне виведення формул обчислення зміщення годинника (*Offset from Master*) та середньої затримки поширення (*Mean Path Delay*), доводить чутливість протоколу до фізичної асиметрії каналу зв'язку, формулює методи фільтрації пакетного джитеру (*Packet Delay Variation*), моделює стохастичний фільтр Калмана для оцінки стану генератора та описує дискретну модель пропорційно-інтегрального сервоприводу.

---

## 1. Базова геометрія часового простору та мітки часу

Розглянемо два незалежні просторово розділені вузли: головний генератор часу (*Master*) та підпорядкований годинник (*Slave*). Кожен годинник описується власною монотонно зростаючою функцією локального часу від неперервного фізичного (ідеального) часу `t`:

```
T_m(t) = (1 + γ_m)·t + θ_m
T_s(t) = (1 + γ_s)·t + θ_s
```

де `γ_m, γ_s` — відносні похибки частоти генераторів (дробовий дрейф частоти, *fractional frequency drift*, безрозмірна величина порядку `10⁻⁶` для звичайних кварців або `10⁻⁹` для термостатованих генераторів OCXO), а `θ_m, θ_s` — початкові фазові зсуви в секундах.

Різниця показів годинника Slave відносно Master у довільний момент `t` визначається як часове зміщення (*offset*) `θ(t)`:

```
θ(t) = T_s(t) - T_m(t) = (γ_s - γ_m)·t + (θ_s - θ_m)
```

Швидкість зміни зміщення в часі визначається відносною різницею частот:

```
dθ(t)/dt = γ_s - γ_m = Δγ
```

За час одного раунду обміну пакетами `Δt` (типово від 8 до 128 мілісекунд при темпі обміну від 8 до 128 пакетів на секунду) максимальний дрейф фази через нестабільність частоти становить:

```
|Δγ · Δt| ≤ 10⁻⁵ · 0.128 с ≈ 1.28 мкс   (для неякісного кварцу)
|Δγ · Δt| ≤ 10⁻⁸ · 0.128 с ≈ 1.28 нс    (для якісного TCXO/OCXO)
```

При використанні апаратного таймстемпінгу в межах одного циклу вимірювання зміщення `θ` вважається квазістаціонарною величиною.

## 2. Механізм End-to-End (Delay Request-Response)

Обмін у схемі E2E фіксує чотири фізичні мітки часу:
1. `t1` — момент відправлення кадру `Sync` за шкалою Master: `t1 = T_m(t_tx1)`.
2. `t2` — момент прийому кадру `Sync` за шкалою Slave: `t2 = T_s(t_rx1)`.
3. `t3` — момент відправлення кадру `Delay_Req` за шкалою Slave: `t3 = T_s(t_tx2)`.
4. `t4` — момент прийому кадру `Delay_Req` за шкалою Master: `t4 = T_m(t_rx2)`.

Нехай `d_ms` — час поширення сигналу від Master до Slave (прямий напрямок), а `d_sm` — час поширення від Slave до Master (зворотний напрямок). Тоді зв'язок між мітками записується системою двох фундаментальних лінійних рівнянь:

```
t2 = t1 + d_ms + θ
t4 = t3 + d_sm - θ
```

Перепишемо різниці виміряних інтервалів:

```
Δt_forward = t2 - t1 = d_ms + θ
Δt_reverse = t4 - t3 = d_sm - θ
```

Маємо систему з двох рівнянь із трьома невідомими (`θ`, `d_ms`, `d_sm`). Система недовизначена. Стандарт IEEE 1588 робить базове припущення про симетрію затримки поширення сигналу в прямому та зворотному напрямках:

```
d_ms = d_sm = d
```

де `d` — середня затримка лінії (*Mean Path Delay*).

Підставляючи умову симетрії в систему рівнянь:

```
t2 - t1 = d + θ
t4 - t3 = d - θ
```

Додамо обидва рівняння для знаходження затримки `d`:

```
(t2 - t1) + (t4 - t3)
= (d + θ) + (d - θ)         [підстановка системи]
= 2·d                       [скорочення зміщення θ]
```

Звідси отримуємо формулу середньої затримки:

```
MeanPathDelay = ((t2 - t1) + (t4 - t3)) / 2
```

Віднімемо друге рівняння від першого для знаходження зміщення `θ`:

```
(t2 - t1) - (t4 - t3)
= (d + θ) - (d - θ)         [підстановка системи]
= d + θ - d + θ             [розкриття дужок]
= 2·θ                       [скорочення затримки d]
```

Звідси отримуємо формулу розрахунку зміщення підпорядкованого годинника:

```
Offset = ((t2 - t1) - (t4 - t3)) / 2
```

Зауважимо, що зміщення можна також записати через уже обчислену затримку `MeanPathDelay`:

```
Offset = (t2 - t1) - MeanPathDelay
```

## 3. Вплив та доведення похибки асиметрії каналу

У реальних мережах умова `d_ms = d_sm` порушується через різницю довжин волокон у дуплексних оптичних лініях, несиметричні затримки в трансиверах PHY (різні латентності серіалізатора/десеріалізатора SerDes для TX та RX) або використання черг із різним завантаженням.

Визначимо повну затримку в прямому та зворотному напрямках через середню затримку `d` та величину асиметрії `Δ_asym`:

```
d_ms = d + Δ_asym / 2
d_sm = d - Δ_asym / 2
```

де `Δ_asym = d_ms - d_sm`.

Підставимо ці вирази у формулу розрахунку зміщення, яку обчислює вузол Slave (вважаючи канал симетричним):

```
Offset_calc
= ((t2 - t1) - (t4 - t3)) / 2                       [базова формула зміщення]
= ((d_ms + θ) - (d_sm - θ)) / 2                     [підстановка виразів для t2-t1 та t4-t3]
= ((d + Δ_asym / 2 + θ) - (d - Δ_asym / 2 - θ)) / 2 [підстановка d_ms та d_sm через асиметрію]
= (d + Δ_asym / 2 + θ - d + Δ_asym / 2 + θ) / 2     [розкриття дужок у чисельнику]
= (2·θ + Δ_asym) / 2                                [зведення подібних: скорочення затримок d]
= θ + Δ_asym / 2                                    [почленне ділення на 2]
```

Похибка оцінки зміщення часу `ε_offset` дорівнює:

```
ε_offset = Offset_calc - θ = Δ_asym / 2 = (d_ms - d_sm) / 2
```

> **Теорема про похибку асиметрії:**
> Будь-яка неврахована фізична асиметрія часу поширення `Δ_asym` між прямим і зворотним напрямками транслюється в систематичну незсувну похибку годинника, рівну рівно половині цієї асиметрії: `ε = Δ_asym / 2`.

Розглянемо фізичні джерела асиметрії:

1. **Різниця довжин оптичного волокна або витої пари.** При швидкості світла в серцевині кварцового волокна `v = c / n_g ≈ 3·10⁸ / 1.4682 ≈ 2.043·10⁸` м/с затримка становить приблизно `4.89` наносекунди на кожен метр кабелю. Якщо оптичний патчкорд передавання довший за патчкорд прийому на `2.0` метри:
```
Δ_asym = 2.0 м · 4.89 нс/м = 9.78 нс
ε_offset = 9.78 / 2 = 4.89 нс
```

2. **Різниця довжин хвиль у WDM-системах (хроматична дисперсія).** При одноволоконній передачі за технологією BiDi прямий сигнал іде на довжині хвилі `λ_1 = 1310` нм, а зворотний — на `λ_2 = 1490` нм. Через залежність показника заломлення кварцу `n(λ)` від довжини хвилі (рівняння Селлмейєра) групові швидкості відрізняються. На трасі довжиною `L = 20` км різниця затримок сягає десятків наносекунд:
```
Δt_disp = L · D · Δλ ≈ 20 км · 17 пс/(нм·км) · 180 нм ≈ 61.2 нс
ε_offset ≈ 30.6 нс
```

Для компенсації відомої статичної асиметрії стандарт IEEE 1588 вводить параметр `delayAsymmetry`:
```
Offset_corrected = Offset_calc - delayAsymmetry
```

## 4. Механізм Peer Delay (P2P)

У топологіях із прозорими комутаторами Peer-to-Peer затримка кожного фізичного кабельного сегмента між двома сусідніми портами вимірюється автономно за допомогою повідомлень `Pdelay_Req`, `Pdelay_Resp` та `Pdelay_Resp_Follow_Up`.

Позначимо мітки часу між портом-ініціатором `A` та портом-відповідачем `B`:
- `t1` — відправлення `Pdelay_Req` портом `A` за його локальним часом `T_A`.
- `t2` — отримання `Pdelay_Req` портом `B` за його локальним часом `T_B`.
- `t3` — відправлення `Pdelay_Resp` портом `B` за його локальним часом `T_B`.
- `t4` — отримання `Pdelay_Resp` портом `A` за його локальним часом `T_A`.

Нехай `d_link` — затримка кабелю між `A` та `B`, а `θ_BA` — зсув фази годинника `B` відносно `A` (`θ_BA = T_B - T_A`). Тоді:

```
t2 = t1 + d_link + θ_BA
t4 = t3 + d_link - θ_BA
```

Різниця часу перебування запиту в лінії туди й назад на вузлі `A`:

```
Δt_total = t4 - t1 = 2·d_link + (t3 - t2)
```

де `(t3 - t2)` — час обробки та підготовки відповіді портом `B` (виміряний повністю внутрішнім лічильником вузла `B`).

Звідси затримка одиничного кабельного сегмента `PeerMeanPathDelay`:

```
PeerMeanPathDelay = ((t4 - t1) - (t3 - t2)) / 2
```

Зауважте фундаментальну перевагу: у формулу входять тільки внутрішні різниці `(t4 - t1)` (на годиннику `A`) та `(t3 - t2)` (на годиннику `B`). Зсув `θ_BA` повністю випадає з рівняння.

Якщо частота генератора `B` відрізняється від частоти `A` на коефіцієнт відносного дрейфу `R_ratio = f_B / f_A`, інтервал `(t3 - t2)` у шкалі годинника `A` триває `(t3 - t2) · (f_A / f_B)`. Тоді скоригована затримка лінії:

```
PeerMeanPathDelay = ((t4 - t1) - (t3 - t2) · (1 / NeighborRateRatio)) / 2
```

де `NeighborRateRatio = f_B / f_A` визначається порівнянням послідовних інтервалів прийому регулярних повідомлень `Pdelay_Resp`:

```
NeighborRateRatio = (t2[k] - t2[k-1]) / (t1[k] - t1[k-1])
```

## 5. Арифметика поля корекції (Correction Field)

У повідомленнях PTP поле `correctionField` займає 64 біти і зберігає накопичену затримку у форматі дробових наносекунд із фіксованою комою (*scaled nanoseconds*):
- Старші 48 бітів — ціла частина в наносекундах.
- Молодші 16 бітів — дробова частина (одиниця молодшого розряду LSB дорівнює `2⁻¹⁶` нс ≈ `15.2585` фемтосекунд).

Формула переведення дійсного значення часу в наносекундах `t_ns` у 64-бітне ціле `CF_raw`:

```
CF_raw = round(t_ns · 2¹⁶) = round(t_ns · 65536)
```

Зворотне переведення 64-бітного значення в дійсне число наносекунд:

```
t_ns = CF_raw / 65536.0
```

Коли повідомлення `Sync` проходить крізь ланцюг із `N` прозорих комутаторів (Transparent Clocks), кожен комутатор `k` додає до поля свій час перебування пакета (*Residence Time*) `T_residence,k = t_egress,k - t_ingress,k`, а у випадку P2P — також затримку вхідного лінка `PeerMeanPathDelay,k`:

```
CF_total = CF_initial + ∑ [k=1..N] (T_residence,k + PeerMeanPathDelay,k)
```

При отриманні повідомлення `Sync` підпорядкований вузол коригує формулу зміщення:

```
Offset = (t2 - t1) - MeanPathDelay - (CF_sync + CF_followup + CF_delayresp)
```

### Накопичення похибки в каскаді прозорих комутаторів

Кожен комутатор вимірює час перебування з власною дисперсією шуму таймстемпінгу `σ_TC,k²`. За умови незалежності шумів вимірювання на різних комутаторах сумарна дисперсія похибки поля корекції на підпорядкованому вузлі зростає лінійно з кількістю транзитних вузлів:

```
Var(CF_total) = ∑ [k=1..N] σ_TC,k² = N · σ_TC²
σ_total = σ_TC · √N
```

Якщо один апаратний TC має похибку `σ_TC = 2` нс, то після проходження каскаду з `N = 16` комутаторів середньоквадратичне відхилення складе:
```
σ_total = 2 · √16 = 2 · 4 = 8 нс
```

Це доводить, що навіть у великих мережах на базі Transparent Clock похибка зростає сублінійно як корінь із кількості хопів, на відміну від звичайних комутаторів, де джитер зростає непропорційно швидко через затори в чергах.

## 6. Фільтрація пакетного джитеру (Packet Delay Variation)

У ненавантажених мережах розподіл затримки пакетів описується вузьким гаусовим шумом. Однак при наявності фонового трафіку черги комутаторів формують асиметричний розподіл із «довгим важким хвостом» (розподіл Вейбулла або експоненційний зсув).

Нехай `d_min` — фізична мінімальна затримка прямого кабельного тракту (без черг), а `Q_ms(t) ≥ 0` — випадкова затримка перебування в чергах:

```
d_ms(t) = d_min + Q_ms(t)
```

### Алгоритм фільтрації «вдалих пакетів» (Lucky Packet Filter)

Оскільки `Q_ms(t) ≥ 0`, мінімальне спостережуване значення `(t2 - t1)` у ковзному вікні з `W` відліків найближче до істинної апаратної затримки лінії:

```
d_est = min [i ∈ (k-W+1 .. k)] (t2[i] - t1[i])
```

Ймовірність того, що хоча б один пакет із вибірки розміром `W` пройде мережу без затримки в черзі з ймовірністю вільного каналу `p_0`:

```
P_lucky = 1 - (1 - p_0)^W
```

Якщо `p_0 = 0.05` (5 % пакетів пролітають без очікування), при вікні `W = 60` пакетів:

```
P_lucky = 1 - (1 - 0.05)⁶⁰ = 1 - (0.95)⁶⁰ ≈ 1 - 0.046 = 0.954 (95.4 %)
```

Використання екстремальної квантильної фільтрації (наприклад, нижнього 5-го процентиля) дозволяє знизити оціночний джитер зміщення в 10–50 разів без апаратної підтримки комутаторів.

## 7. Модель простору станів та фільтр Калмана для PTP

Оптимальна оцінка фази та частоти годинника в умовах гаусового та дробового шуму здійснюється за допомогою лінійного фільтра Калмана.

Сформулюємо вектор стану системи `x[k]` розмірності 2×1:

```
x[k] = [ θ[k]   ]   (зміщення фази в секундах)
       [ Δγ[k]  ]   (дробове відхилення частоти)
```

Динаміка системи між кроками вимірювань `Δt` описується матричним рівнянням стану:

```
x[k] = F · x[k-1] + w[k-1]
```

де матриця переходу стану `F`:

```
F = [ 1   Δt ]
    [ 0    1 ]
```

Вектор шуму процесу `w[k]` має коваріаційну матрицю `Q`, визначену білим шумом фази `q_θ` та шумом випадкового блукання частоти `q_γ` кварцового генератора:

```
Q = [ q_θ·Δt + q_γ·Δt³/3    q_γ·Δt²/2 ]
    [ q_γ·Δt²/2             q_γ·Δt    ]
```

Рівняння вимірювання пов'язує спостережувану різницю міток `z[k] = Offset_meas[k]` зі станом системи:

```
z[k] = H · x[k] + v[k]
```

де матриця спостереження `H = [ 1   0 ]`, а `v[k]` — шум мережевого вимірювання з дисперсією `R = σ_meas²`.

### Рекурсивні кроки фільтрації

1. **Етап прогнозу (Time Update):**
```
x̂⁻[k] = F · x̂[k-1]
P⁻[k] = F · P[k-1] · Fᵀ + Q
```

2. **Обчислення коефіцієнта підсилення Калмана (Kalman Gain):**
```
K[k] = P⁻[k] · Hᵀ · (H · P⁻[k] · Hᵀ + R)⁻¹
```

3. **Етап корекції (Measurement Update):**
```
ỹ[k] = z[k] - H · x̂⁻[k]         [нев'язка вимірювання]
x̂[k] = x̂⁻[k] + K[k] · ỹ[k]       [оновлення вектора стану]
P[k] = (I - K[k] · H) · P⁻[k]    [оновлення коваріації похибки]
```

Фільтр Калмана одночасно видає оптимальну оцінку як поточного фазового зміщення `θ̂[k]`, так і точного дрейфу частоти кварцу `Δγ̂[k]`. Це дозволяє утримувати час під час тимчасової втрати пакетів (*Holdover mode*) шляхом екстраполяції накопиченої оцінки частоти.

## 8. Цифровий PI-сервопривід годинника (Clock Servo Model)

Отримані з мережі значення зміщення `θ_meas[k]` містять залишковий шум квантування та мережевий джитер. Подавати їх напряму на лічильник часу не можна, оскільки це створить стрибки фази та порушить монотонність плину часу.

Керування частотою апаратного генератора здійснюється за допомогою пропорційно-інтегрального (PI) цифрового фільтра-регулятора.

Позначимо:
- `e[k] = θ_meas[k]` — виміряна похибка фази (зміщення) на кроці `k`.
- `Δt[k]` — інтервал часу між послідовними корекціями (період оновлення).
- `y[k]` — керівний вплив на частоту генератора в частинах на мільярд (ppb — *parts per billion*, `10⁻⁹`).
- `I[k]` — інтегральний стан накопиченої похибки частоти.

Рівняння дискретного PI-контролера записуються як:

```
I[k] = I[k-1] + K_i · e[k] · Δt[k]
y[k] = K_p · e[k] + I[k]
```

де `K_p` — коефіцієнт пропорційного підсилення (розмірність `1/с`), а `K_i` — коефіцієнт інтегрального підсилення (розмірність `1/с²`).

### Дискретна передатна функція замкненої системи

Нехай внутрішній стан фази годинника описується інтегруванням частотного зсуву:

```
θ[k+1] = θ[k] + (y_drift - y[k]) · Δt[k]
```

Застосуємо Z-перетворення. Помилка замкненого контуру:

```
E(z) = (z - 1)² / ((z - 1)² + K_p·Δt·(z - 1) + K_i·Δt²) · N(z)
```

де `N(z)` — спектральна густина шуму вимірювань міток.

Система є стабільною тоді й лише тоді, коли всі корені характеристичного полінома лежать строго всередині одиничного кола на комплексній площині:

```
|z_1,2| < 1
```

Критичні умови на коефіцієнти для кроку `Δt`:

```
0 < K_i · Δt² < K_p · Δt < 2
```

Типові значення для PTP-стеків із частотою оновлення 16 Гц (`Δt = 0.0625` с):
- `K_p ≈ 0.7`
- `K_i ≈ 0.3`

Це забезпечує коефіцієнт демпфування `ζ ≈ 0.707` (критичне згасання коливань без тривалого перерегулювання) та частоту зрізу низькочастотного фільтра, яка надійно пригнічує пакетний джитер коммутаторів.

## 9. Оцінка стабільності частоти: дисперсія Аллана

У дескрипторі якості годинника `ClockQuality` протокол PTP використовує параметр `offsetScaledLogVariance`. Він базується на дисперсії Аллана (*Allan Variance*, `σ_y²(τ)`), яка вимірює нестабільність частоти генератора на часовому інтервалі вибірки `τ`:

```
σ_y²(τ) = (1 / (2·(M - 1))) · ∑ [n=1..M-1] (ȳ_{n+1} - ȳ_n)²
```

де `ȳ_n` — середнє значення дробового відхилення частоти за `n`-й інтервал тривалістю `τ`.

Переведення дисперсії Аллана в стандартизоване 16-бітне логарифмічне поле PTP:

```
offsetScaledLogVariance = round(256 · log₂(σ_y²(τ_PTP) · 2¹⁶))
```

де базовий інтервал спостереження `τ_PTP = 1` с (для профілю за замовчуванням). Це дозволяє алгоритму BMCA автоматично обирати як Grandmaster той годинник, який має найменший власний фазовий шум та температурний дрейф.

## 10. Метрики стабільності ITU-T: MTIE та TDEV

Для телекомунікаційних профілів (G.8275.1 / G.8275.2) стандарт вимагає відповідності маскам максимальної часової похибки MTIE (*Maximum Time Interval Error*) та часової девіації TDEV (*Time Deviation*).

1. **MTIE:** пікове розгойдування фази на вікні спостереження `S`:
```
MTIE(S) = max [t_0 ≤ t ≤ T - S] ( max [t ≤ u ≤ t + S] x(u) - min [t ≤ u ≤ t + S] x(u) )
```
де `x(t)` — функція часової похибки (Time Error, TE). Для класу точності Class C телеком-профілю MTIE не повинна перевищувати `30` наносекунд на інтервалах до `1000` секунд.

2. **TDEV:** оцінка спектрального складу фазового шуму:
```
TDEV(S) = √ ( (1 / (6·n²·(N - 3·n + 1))) · ∑ [j=1..N-3n+1] ( ∑ [i=j..j+n-1] (x_{i+2n} - 2·x_{i+n} + x_i) )² )
```
де `S = n · τ_0`. TDEV дозволяє розрізнити білий шум фази, флікер-шум фази та випадкове блукання частоти.

## 11. Математична модель дрейфу в режимі утримання (Holdover)

Коли зв'язок із Grandmaster втрачається, підпорядкований годинник переходить у режим утримання (*Holdover*). Похибка часу накопичується під впливом початкової похибки фази `θ_0`, залишкової неточності оцінки частоти `Δγ_0`, лінійного старіння кварцу (*aging rate*) `D = dγ/dt` та температурного коефіцієнта частоти:

```
θ_holdover(t) = θ_0 + Δγ_0 · t + (1/2) · D · t² + ∫ [0..t] Δγ_temp(T(τ)) dτ
```

1. **Короткі інтервали (до 100 с):** домінує лінійний член швидкості розбіжності `Δγ_0 · t`. Для OCXO з `Δγ_0 = 10⁻¹⁰` (0.1 ppb) розбіжність за 100 секунд складе:
```
θ(100 с) ≈ 10⁻¹⁰ · 100 с = 10 нс
```

2. **Тривалі інтервали (години та доби):** починає переважати квадратичний член старіння `(1/2) · D · t²`. Для генератора зі швидкістю старіння `D = 10⁻¹¹` на добу (`≈ 1.16·10⁻¹⁶` с⁻¹), через `t = 86400` с (1 доба):
```
θ_aging(1 доба) = (1/2) · 1.16·10⁻¹⁶ · (86400)² ≈ (1/2) · 1.16·10⁻¹⁶ · 7.465·10⁹ ≈ 433 нс
```

Звідси випливає максимальний допустимий час утримання `t_max` до виходу за межі бюджету похибки `θ_max`:

```
t_max ≈ ( -Δγ_0 + √(Δγ_0² + 2·D·θ_max) ) / D
```

## 12. Повний числовий приклад розрахунку

Нехай у мережі з апаратними мітками зафіксовано такі значення:
- `t1 = 1700000000.100000000` с (Master TX Sync)
- `t2 = 1700000000.100054230` с (Slave RX Sync)
- `t3 = 1700000000.120000000` с (Slave TX Delay_Req)
- `t4 = 1700000000.119946170` с (Master RX Delay_Req)
- `CF = 0.000000200` с (накопичений час у комутаторах = 200 нс)

### Крок 1. Обчислення різниць інтервалів

```
t2 - t1
= 100054230 нс - 100000000 нс   [підстановка числових міток t2 та t1]
= 54230 нс                      [обчислення різниці прямих міток]

t4 - t3
= 119946170 нс - 120000000 нс   [підстановка числових міток t4 та t3]
= -53830 нс                     [обчислення різниці зворотних міток]
```

### Крок 2. Обчислення середньої затримки лінії

```
MeanPathDelay_raw
= ((t2 - t1) + (t4 - t3)) / 2    [базова формула середньої затримки]
= (54230 + (-53830)) / 2        [підстановка обчислених різниць]
= 400 / 2                       [додавання інтервалів]
= 200 нс                        [ділення навпіл]
```

Віднімемо корекцію комутаторів `CF = 200` нс:

```
MeanPathDelay_net = 200 - 200 = 0 нс (затримка чистих кабелів)
```

### Крок 3. Обчислення зміщення годинника

```
Offset
= ((t2 - t1) - (t4 - t3) - CF) / 2 [формула зміщення з корекцією]
= (54230 - (-53830) - 200) / 2     [підстановка значень та поля CF]
= (108060 - 200) / 2               [віднімання від'ємної величини]
= 107860 / 2                       [віднімання затримки комутаторів]
= 53930 нс                         [результуюче зміщення Slave відносно Master]
```

Годинник Slave випереджає Master на `53.930` мікросекунди. Сервопривід застосує від'ємну поправку частоти та плавно підтягне фазу Slave до еталону.
