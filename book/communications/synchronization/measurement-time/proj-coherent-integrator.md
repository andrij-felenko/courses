# ⚙️ Двоетапний когерентно-некогерентний інтегратор та дискримінатор затримки

Програмна реалізація алгоритмів цифрової просторово-часової обробки сигналів для вимірювання затримки приходу (Time of Arrival, TOA) та різниці затримок приходу (Time Difference of Arrival, TDOA) вимагає суворого узгодження часу когерентного та некогерентного накопичення в умовах динамічного доплерівського зсуву та низького відношення сигнал/шум. Якщо час вимірювання налаштовано невірно, пристрій або втратить корисний сигнал через обертання фази, або потоне у тепловому шумі.

У радіонавігаційних приймачах (GNSS), пасивних комплексах радіотехнічного моніторингу та радіолокаційних станціях із фазованими антенними решітками ядро цифрової обробки вирішує фундаментальну дилему: як накопичити достатню енергію слабкого радіосигналу (наприклад, на 20 дБ нижче рівня теплових шумів), не допустивши при цьому його деструктивного фазового самознищення через залишковий доплерівський зсув або маніпуляцію інформаційних бітів.

Нижче наведено робочий алгоритмічний модуль для вбудованих цифрових сигнальних процесорів (DSP) та програмно-конфігурованого радіо (SDR), що виконує повний цикл обробки: фазове зняття доплерівської несучої (Doppler Wipe-off) через числовий генератор (NCO), паралельне триканальне кореляційне децимаційне накопичення (Early, Prompt, Late) на когерентному вікні `T_coh`, блокове некогерентне підсумовування енергії за `M` епох до досягнення повного часу вимірювання `T_meas`, та формування керувального сигналу похибки стеження за затримкою (Delay-Locked Loop, DLL).

## 1. Архітектура та послідовність цифрової обробки

Вхідний потік комплексних відліків `I[k] + j·Q[k]` надходить від аналогово-цифрового перетворювача (АЦП) квадратурного демодулятора з частотою дискретизації `f_s`. Обробка виконується у п'ять послідовних етапів:

1. **Компенсація доплерівського зсуву (Carrier Wipe-Off):** Кожен вхідний відлік множиться на комплексне спряжене значення опорної фази `e^{-j·φ[k]}`, згенерованої фазовим акумулятором числового генератора (NCO) за оцінкою поточної частоти Доплера `f_d`.
2. **Кореляція з опорним кодом (Early, Prompt, Late):** Фазокомпенсований сигнал паралельно множиться на три копії опорної псевдовипадкової послідовності (PRN):
   - **Prompt (P):** точна поточна оцінка затримки сигналу.
   - **Early (E):** випереджальна копія, зміщена на `-Δ/2` чипу (типово `Δ = 0.5` чипу).
   - **Late (L):** запізніла копія, зміщена на `+Δ/2` чипу.
3. **Когерентне інтегрування (Coherent Accumulation):** Протягом `N_coh = f_s · T_coh` відліків виконується векторне підсумовування комплексних добутків окремо для трьох каналів `E, P, L`. Наприкінці кожного когерентного інтервалу формуються три комплексні числа `S_E, S_P, S_L`.
4. **Некогерентне накопичення енергії (Non-Coherent Summation):** Якщо сумарний час вимірювання `T_meas` вимагає об'єднання `M` когерентних блоків (`T_meas = M · T_coh`), обчислюються квадрати модулів `|S_E|²`, `|S_P|²`, `|S_L|²`, які накопичуються в енергетичних акумуляторах.
5. **Нормований дискримінатор затримки (Normalized Early-Minus-Late):** Обчислюється безрозмірна оцінка неузгодженості кодової затримки `e_τ`, що подається на цифровий петльовий фільтр:

```
e_τ = [ (|S_E|² - |S_L|²) ] ÷ [ (|S_E|² + |S_L|²) ]
```

#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <stdint.h>
#include <math.h>

#ifndef M_PI
#define M_PI 3.14159265358979323846
#endif

/* Комплексний відлік базової смуги (I/Q) */
typedef struct {
    float i;
    float q;
} iq_sample_t;

/* Стан кореляційного інтегратора */
typedef struct {
    uint32_t fs_hz;            /* Частота дискретизації, Гц */
    uint32_t n_coh;            /* Кількість відліків в одному когерентному вікні T_coh */
    uint32_t m_blocks;         /* Кількість некогерентних блоків у T_meas */
    
    /* Параметри доплерівського NCO */
    float doppler_hz;          /* Поточна оцінка доплерівської частоти */
    float nco_phase_rad;       /* Поточна фаза генератора NCO [0, 2pi) */
    float phase_step_rad;      /* Крок фази за один відлік */
    
    /* Проміжні когерентні акумулятори */
    float acc_coh_e_i;
    float acc_coh_e_q;
    float acc_coh_p_i;
    float acc_coh_p_q;
    float acc_coh_l_i;
    float acc_coh_l_q;
    uint32_t coh_counter;
    
    /* Некогерентні накопичувачі енергії за T_meas */
    float power_early;
    float power_prompt;
    float power_late;
    uint32_t block_counter;
    
    /* Результати останнього повного вимірювання */
    float last_discriminator_err;
    float estimated_snr_db;
    bool measurement_ready;
} correlator_integrator_t;

/* Ініціалізація структури корелятора */
void correlator_init(correlator_integrator_t *self, uint32_t fs_hz, 
                     float t_coh_sec, uint32_t m_blocks, float initial_doppler_hz) {
    self->fs_hz = fs_hz;
    self->n_coh = (uint32_t)(fs_hz * t_coh_sec + 0.5f);
    if (self->n_coh < 1) self->n_coh = 1;
    self->m_blocks = (m_blocks > 0) ? m_blocks : 1;
    
    self->doppler_hz = initial_doppler_hz;
    self->nco_phase_rad = 0.0f;
    self->phase_step_rad = (float)(2.0 * M_PI * initial_doppler_hz / fs_hz);
    
    self->acc_coh_e_i = 0.0f; self->acc_coh_e_q = 0.0f;
    self->acc_coh_p_i = 0.0f; self->acc_coh_p_q = 0.0f;
    self->acc_coh_l_i = 0.0f; self->acc_coh_l_q = 0.0f;
    self->coh_counter = 0;
    
    self->power_early = 0.0f;
    self->power_prompt = 0.0f;
    self->power_late = 0.0f;
    self->block_counter = 0;
    
    self->last_discriminator_err = 0.0f;
    self->estimated_snr_db = 0.0f;
    self->measurement_ready = false;
}

/* Оновлення поточної частоти Доплера для NCO */
void correlator_set_doppler(correlator_integrator_t *self, float doppler_hz) {
    self->doppler_hz = doppler_hz;
    self->phase_step_rad = (float)(2.0 * M_PI * doppler_hz / self->fs_hz);
}

/* Обробка одного відліку вхідного сигналу та значень трьох кодових копій */
bool correlator_process_sample(correlator_integrator_t *self, iq_sample_t raw,
                               float code_early, float code_prompt, float code_late) {
    self->measurement_ready = false;
    
    /* 1. Фазове зняття Доплера через NCO: r_bb = raw * exp(-j * phi) */
    float cos_phi = cosf(self->nco_phase_rad);
    float sin_phi = sinf(self->nco_phase_rad);
    
    float rot_i = raw.i * cos_phi + raw.q * sin_phi;
    float rot_q = raw.q * cos_phi - raw.i * sin_phi;
    
    /* Оновлення фази NCO на один крок */
    self->nco_phase_rad += self->phase_step_rad;
    if (self->nco_phase_rad >= (float)(2.0 * M_PI)) {
        self->nco_phase_rad -= (float)(2.0 * M_PI);
    } else if (self->nco_phase_rad < 0.0f) {
        self->nco_phase_rad += (float)(2.0 * M_PI);
    }
    
    /* 2. Когерентне накопичення для трьох плечей */
    self->acc_coh_e_i += rot_i * code_early;
    self->acc_coh_e_q += rot_q * code_early;
    
    self->acc_coh_p_i += rot_i * code_prompt;
    self->acc_coh_p_q += rot_q * code_prompt;
    
    self->acc_coh_l_i += rot_i * code_late;
    self->acc_coh_l_q += rot_q * code_late;
    
    self->coh_counter++;
    
    /* 3. Завершення когерентного вікна T_coh */
    if (self->coh_counter >= self->n_coh) {
        /* Обчислення потужностей трьох плечей за когерентний блок */
        float blk_pwr_e = self->acc_coh_e_i * self->acc_coh_e_i + 
                          self->acc_coh_e_q * self->acc_coh_e_q;
        float blk_pwr_p = self->acc_coh_p_i * self->acc_coh_p_i + 
                          self->acc_coh_p_q * self->acc_coh_p_q;
        float blk_pwr_l = self->acc_coh_l_i * self->acc_coh_l_i + 
                          self->acc_coh_l_q * self->acc_coh_l_q;
        
        /* Додавання до некогерентних акумуляторів */
        self->power_early  += blk_pwr_e;
        self->power_prompt += blk_pwr_p;
        self->power_late   += blk_pwr_l;
        
        /* Скидання когерентних акумуляторів */
        self->acc_coh_e_i = 0.0f; self->acc_coh_e_q = 0.0f;
        self->acc_coh_p_i = 0.0f; self->acc_coh_p_q = 0.0f;
        self->acc_coh_l_i = 0.0f; self->acc_coh_l_q = 0.0f;
        self->coh_counter = 0;
        self->block_counter++;
        
        /* 4. Завершення повного інтервалу вимірювання T_meas = M * T_coh */
        if (self->block_counter >= self->m_blocks) {
            float sum_el = self->power_early + self->power_late;
            if (sum_el > 1e-12f) {
                /* Нормований дискримінатор похибки затримки NEMLP */
                self->last_discriminator_err = (self->power_early - self->power_late) / sum_el;
            } else {
                self->last_discriminator_err = 0.0f;
            }
            
            /* Оцінка вихідного відношення сигнал/шум */
            float noise_floor = 0.5f * (self->power_early + self->power_late);
            if (noise_floor > 1e-12f && self->power_prompt > noise_floor) {
                float snr_lin = (self->power_prompt - noise_floor) / noise_floor;
                self->estimated_snr_db = 10.0f * log10f(snr_lin);
            } else {
                self->estimated_snr_db = -30.0f;
            }
            
            /* Скидання некогерентних акумуляторів для наступного T_meas */
            self->power_early = 0.0f;
            self->power_prompt = 0.0f;
            self->power_late = 0.0f;
            self->block_counter = 0;
            self->measurement_ready = true;
        }
    }
    
    return self->measurement_ready;
}

#include <iostream>
#include <vector>
#include <complex>
#include <cmath>
#include <numbers>
#include <span>
#include <optional>

struct MeasurementResult {
    float discriminator_error{0.0f}; /* Безрозмірна похибка затримки (-1..+1) */
    float prompt_power{0.0f};        /* Накопичена енергія центрального піку */
    float estimated_snr_db{0.0f};    /* Оцінка вихідного відношення сигнал/шум */
};

class CoherentIntegrator {
public:
    CoherentIntegrator(uint32_t sample_rate_hz, float t_coh_sec, 
                       uint32_t num_blocks, float initial_doppler_hz = 0.0f)
        : sample_rate_hz_(sample_rate_hz),
          n_coh_(std::max(1u, static_cast<uint32_t>(sample_rate_hz * t_coh_sec + 0.5f))),
          m_blocks_(std::max(1u, num_blocks)) {
        set_doppler(initial_doppler_hz);
    }

    void set_doppler(float doppler_hz) noexcept {
        doppler_hz_ = doppler_hz;
        phase_step_rad_ = static_cast<float>(2.0 * std::numbers::pi * doppler_hz_ / sample_rate_hz_);
    }

    /* Потокова обробка масиву відліків */
    std::optional<MeasurementResult> process_sample(
        std::complex<float> raw_sample,
        float code_early,
        float code_prompt,
        float code_late) noexcept {
        
        /* 1. Фазова компенсація несучої: rot = raw * exp(-j * phi) */
        float cos_phi = std::cos(nco_phase_rad_);
        float sin_phi = std::sin(nco_phase_rad_);
        std::complex<float> nco_rot{cos_phi, -sin_phi};
        std::complex<float> bb_sample = raw_sample * nco_rot;

        /* Оновлення фази NCO */
        nco_phase_rad_ += phase_step_rad_;
        if (nco_phase_rad_ >= 2.0f * std::numbers::pi_v<float>) {
            nco_phase_rad_ -= 2.0f * std::numbers::pi_v<float>;
        } else if (nco_phase_rad_ < 0.0f) {
            nco_phase_rad_ += 2.0f * std::numbers::pi_v<float>;
        }

        /* 2. Когерентне накопичення */
        acc_coh_e_ += bb_sample * code_early;
        acc_coh_p_ += bb_sample * code_prompt;
        acc_coh_l_ += bb_sample * code_late;
        coh_counter_++;

        /* 3. Перевірка завершення когерентного вікна T_coh */
        if (coh_counter_ >= n_coh_) {
            power_early_  += std::norm(acc_coh_e_);
            power_prompt_ += std::norm(acc_coh_p_);
            power_late_   += std::norm(acc_coh_l_);

            acc_coh_e_ = {0.0f, 0.0f};
            acc_coh_p_ = {0.0f, 0.0f};
            acc_coh_l_ = {0.0f, 0.0f};
            coh_counter_ = 0;
            block_counter_++;

            /* 4. Перевірка завершення повного вікна T_meas */
            if (block_counter_ >= m_blocks_) {
                MeasurementResult res{};
                float sum_el = power_early_ + power_late_;
                
                if (sum_el > 1e-12f) {
                    res.discriminator_error = (power_early_ - power_late_) / sum_el;
                }
                res.prompt_power = power_prompt_;

                float noise_floor = 0.5f * sum_el;
                if (noise_floor > 1e-12f && power_prompt_ > noise_floor) {
                    float snr_lin = (power_prompt_ - noise_floor) / noise_floor;
                    res.estimated_snr_db = 10.0f * std::log10(snr_lin);
                } else {
                    res.estimated_snr_db = -30.0f;
                }

                /* Скидання некогерентних акумуляторів */
                power_early_ = 0.0f;
                power_prompt_ = 0.0f;
                power_late_ = 0.0f;
                block_counter_ = 0;

                return res;
            }
        }
        return std::nullopt;
    }

    [[nodiscard]] uint32_t total_measurement_samples() const noexcept {
        return n_coh_ * m_blocks_;
    }

private:
    uint32_t sample_rate_hz_;
    uint32_t n_coh_;
    uint32_t m_blocks_;

    float doppler_hz_{0.0f};
    float nco_phase_rad_{0.0f};
    float phase_step_rad_{0.0f};

    std::complex<float> acc_coh_e_{0.0f, 0.0f};
    std::complex<float> acc_coh_p_{0.0f, 0.0f};
    std::complex<float> acc_coh_l_{0.0f, 0.0f};
    uint32_t coh_counter_{0};

    float power_early_{0.0f};
    float power_prompt_{0.0f};
    float power_late_{0.0f};
    uint32_t block_counter_{0};
};

## 3. Математика S-кривої дискримінатора та петлі DLL

Дискримінатор Early-Minus-Late формує залежність вихідного сигналу похибки `e_τ` від істинного зсуву затримки коду `ε = τ_rx - τ_est`. Ця характеристика називається **S-кривою дискримінатора** (S-Curve).

Для псевдовипадкової кодової послідовності з трикутною автокореляційною функцією `R(ε) = max(0, 1 - |ε|/T_chip)` та відстанню між плечима `Δ = 0.5` чипу, вихідні потужності плечей мають вигляд:

```
P_E(ε) = |R(ε + Δ/2)|² = |R(ε + 0.25)|²
P_L(ε) = |R(ε - Δ/2)|² = |R(ε - 0.25)|²
```

Нормований дискримінатор потужності Early-Minus-Late (NEMLP) обчислює різницю, поділену на суму:

```
e_τ(ε) = [ P_E(ε) - P_L(ε) ] / [ P_E(ε) + P_L(ε) ]
```

У лінійній зоні дискримінатора (при малих похибках `|ε| < 0.25` чипу) функція `e_τ(ε)` є строго пропорційною часовій похибці:

```
e_τ(ε) ≈ K_d · (ε / T_chip)
```

де `K_d` — крутизна дискримінатора (коефіцієнт дискримінаційної характеристики). Завдяки нормуванню на повну потужність `(P_E + P_L)` вихідна похибка стає повністю незалежною від коливань амплітуди вхідного сигналу та коефіцієнта підсилення тракту АРП (автоматичного регулювання підсилення).

Петльовий фільтр 2-го порядку (PI-регулятор) використовує сигнал похибки `e_τ` для корекції кодового NCO:

```
v_{code}[n] = v_{code}[n-1] + C₁ · e_τ[n] + C₂ · (e_τ[n] - e_τ[n-1])
```

Коефіцієнти фільтра `C₁, C₂` розраховуються за еквівалентною шумовою смугою петлі `B_L` та коефіцієнтом демпфування `ζ = 0.707`:

```
ω_n = (8 · ζ · B_L) / (4 · ζ² + 1)
C₁ = 2 · ζ · ω_n · T_meas
C₂ = ω_n² · T_meas²
```

Це математичне замикання петлі демонструє, як час вимірювання `T_meas` безпосередньо впливає на динамічну смугу фільтра: що довший інтервал `T_meas`, то меншою має бути смуга `B_L`, і то повільніше петля реагуватиме на різкі маневри приймача.

## 4. Оптимізація обчислень для DSP та SIMD (AVX2 / ARM NEON)

У широкосмугових системах (наприклад, супутниковий зв'язок зі смугою 20–100 МГц або 5G PRS) корелятор повинен обробляти від 50 до 200 мільйонів комплексних відліків на секунду для кожного супутникового або базового каналу. Поточкове скалярне обчислення `cosf/sinf` для кожного відліку створює неприпустиме навантаження на центральний процесор.

Для досягнення реального масштабу часу застосовують три архітектурні оптимізації:

1. **Табличний або поліноміальний NCO (Direct Digital Synthesis, DDS):** Замість виклику тригонометричних функцій фазовий кут розбивається на індекс таблиці синусів/косинусів фіксованого розміру (наприклад, 1024 або 4096 елементів) та лінійну інтерполяцію залишку:
   ```
   uint32_t idx = (phase_accumulator >> 20) & 0x0FFF;
   cos_val = cos_lut[idx];
   sin_val = sin_lut[idx];
   ```
2. **Векторизація SIMD (Single Instruction, Multiple Data):** Використовуючи інструкції AVX2 (x86) або NEON (ARM), когерентний корелятор завантажує одночасно 8 або 16 комплексних відліків `I/Q` і виконує паралельне множення на вектор кодових чипів за одну інструкцію `FMA` (Fused Multiply-Add):
   ```
   __m256 v_raw_i = _mm256_loadu_ps(&raw_i[k]);
   __m256 v_code  = _mm256_loadu_ps(&code_prompt[k]);
   v_acc_p_i = _mm256_fmadd_ps(v_raw_i, v_code, v_acc_p_i);
   ```
3. **Децимація відліків коду через поліфазну фільтрацію:** Кодові копії Early, Prompt, Late генеруються не на повній частоті АЦП, а формуються через поліфазний банк фільтрів дробової затримки (Farrow Filter), що скорочує витрати пам'яті таблиць кодів у десятки разів.

## 5. Калібрування та температурна компенсація групової затримки апаратного тракту

У високоточних вимірювачах часу (наприклад, станціях диференційного зв'язку RTK та базових станціях TDOA) внутрішня групова затримка аналогового тракту приймача `τ_{hw}` зазнає температурного дрейфу через нагрівання фільтрів проміжної частоти (ПЧ), малошумних підсилювачів (LNA) та кабельних ліній. Типовий коефіцієнт температурного дрейфу керамічного або ПАХ-фільтра становить від `0.1` до `0.5 нс/°C`, що при добових коливаннях температури на 20 °C генерує систематичну похибку дальності від 60 сантиметрів до 3 метрів.

Для компенсації апаратного дрейфу в структуру інтегратора вбудовують канал внутрішнього самокалібрування:
1. **Інжекція калібрувального імпульсу:** На антенний вхід через спрямований відгалужувач періодично подається короткий еталонний тестовий імпульс із відомою міткою часу.
2. **Вимірювання повної петльової затримки:** Кореляційний модуль вимірює момент появи сигналу на виході АЦП і записує апаратне зміщення `τ_{calib}` у калібрувальний регістр.
3. **Температурна апроксимація:** Приймач будує поліноміальну модель корекції групової затримки за показами вбудованого термодавача, віднімаючи зміщення з кожного результату вимірювання псевдодальності.

## 6. Покроковий розбір чисельного тесту та збіжності петлі DLL

Розглянемо чисельний приклад роботи реалізованого інтегратора при супроводі навігаційного сигналу GPS L1 C/A (`f_s = 4.092 МГц`, смуга коду `1.023 МГц`, один чип `T_{chip} ≈ 977.5 нс`).

Початкові умови експерименту:
- Тривалість когерентного вікна: `T_{coh} = 1 мс` (`N_{coh} = 4092` відліки).
- Кількість некогерентних блоків: `M = 20` (`T_{meas} = 20 мс`).
- Початкова похибка кодової затримки: `ε₀ = +0.2 чипу` (`+195.5 нс`, сигнал випереджає опорний генератор).
- Вхідний SNR у смузі приймача: `-20 дБ`.

Динаміка роботи інтегратора за 4 послідовні вимірювальні епохи (кожна тривалістю 20 мс):
1. **Епоха 1 (t = 20 мс):** Оскільки сигнал випереджає опорний код, випереджальне плече Early захоплює більшу частину енергії автокореляційного піка: `P_E = 1420`, `P_L = 580`. Дискримінатор обчислює похибку `e_τ = (1420 - 580) / (1420 + 580) = +0.420`. Петльовий фільтр генерує корекцію кодової швидкості `-41.0 Гц`, сповільнюючи генератор коду.
2. **Епоха 2 (t = 40 мс):** Похибка затримки зменшується до `+0.09 чипу`. Накопичені потужності: `P_E = 1180`, `P_L = 820`. Вихід дискримінатора: `e_τ = +0.180`. Петльовий фільтр коригує частоту на `-17.5 Гц`.
3. **Епоха 3 (t = 60 мс):** Похибка затримки зменшується до `+0.02 чипу`. Потужності плечей майже вирівнюються: `P_E = 1030`, `P_L = 970`. Дискримінатор видає залишковий шум `e_τ = +0.030`.
4. **Епоха 4 (t = 80 мс):** Петля переходить у режим стаціонарного супроводу (Locked State). Потужності Early та Late симетричні (`P_E ≈ P_L`), центральне плече Prompt накопичує максимальну енергію піка `P_P = 3850`, що дає стабільну оцінку вихідного відношення сигнал/шум `SNR_{est} ≈ +14.2 дБ`.

Цей чисельний простежувальний розбір демонструє стійку збіжність двоступеневого алгоритму накопичення та утримання синхронізації навіть в умовах глибокого перевищення теплового шуму над корисним сигналом на вході приймача.

## 7. Багатоканальне розпаралелювання кореляторів для 3D-TDOA та супутникової навігації

У багатопозиційних системах TDOA та мультисистемних GNSS-приймачах (GPS, Galileo, BeiDou) процесор обробки сигналів паралельно відстежує від 12 до 64 незалежних супутникових або базових сигналів. Кожен канал має власний доплерівський зсув `f_{d,i}`, власну псевдодальність `τ_i` та індивідуальну кодову послідовність PRN.

Організація обчислювального конвеєра спирається на три базові інженерні принципи:
- **Кільцевий буфер прямого доступу до пам'яті (DMA Ring Buffer):** АЦП безперервно записує сирі відліки `I/Q` у подвійний буфер (Ping-Pong Buffer). Поки ядро DMA наповнює буфер B, процесорні потоки одночасно зчитують буфер A без блокувань шини.
- **Прив'язка потоків до процесорних ядер (Thread Pinning):** Канали відстеження групуються за ядрами процесора (наприклад, по 4 канали на одне ядро CPU), що усуває перемикання контексту ОС та мінімізує промахи кеш-пам'яті першого рівня (L1 Data Cache).
- **Спільна тактова мітка когерентності (Coherent Epoch Snap):** Момент завершення інтервалу вимірювання `T_meas` синхронізується для всіх каналів за апаратним секундним PPS-імпульсом або єдиним лічильником тактів АЦП, що гарантує сувору просторово-часову узгодженість формуваних псевдодальностей.

## 8. Адаптація когерентного вікна за показниками детектора замкненої петлі

У реальних умовах експлуатації динаміка руху приймача та рівень перешкод безперервно змінюються. Фіксоване когерентне вікно `T_coh` є компромісом, який програє в екстремальних режимах:
- Під час пошуку та захоплення сигналу залишкова частотна похибка велика (`Δf > 100 Гц`), тому когерентне вікно має бути коротким (`T_coh = 1 мс`), щоб уникнути sinc-загасання.
- Після замикання петлі стеження за частотою несучої (FLL) та фазою (PLL) частотна неузгодженість спадає до часток герца (`Δf < 1 Гц`). Це дозволяє автоматично збільшити `T_coh` до 10 або 20 мс, отримавши додатковий когерентний виграш `+13 дБ` без квадратичних втрат.

Адаптивний контролер інтегратора безперервно аналізує вихід детектора фазового зриву (Phase Lock Detector, PLD): якщо індикатор фазової когерентності перевищує поріг `PLD > 0.85`, довжина когерентного вікна `T_coh` ступінчасто збільшується. У разі різкого динамічного маневру або появи інтерференційної завади контролер миттєво повертається до короткого `T_coh = 1 мс`, запобігаючи повному зриву стеження.

## 9. Інтеграція в архітектури програмного радіо (GNU Radio, GNSS-SDR)

У сучасних відкритих стеках обробки SDR-сигналів алгоритм когерентно-некогерентного інтегрування інкапсулюється у потоковий блок обробки. Вхідні пакети даних маркуються апаратними мітками часу стандарту VITA-49 або UHD Timestamp, прив'язаними до фронту PPS-імпульсу опорного генератора.

Під час обробки сигналів TDOA від кількох географічно рознесених SDR-приймачів центральний серверний вузол синхронізує потоки відліків за їхніми числовими мітками та запускає паралельні когерентні інтегратори на спільних часових вікнах `[t_k, t_k + T_meas]`. Формування взаємної функції кореляції через швидке перетворення Фур'є (FFT-based Cross-Correlator) на кожному часовому інтервалі дає змогу виділяти наносекундні затримки сигналу на тлі несинхронних промислових завад і багатопроменевих відбиттів.

Для безперервної передачі даних між високошвидкісним DSP-потоком корелятора (що працює на частоті АЦП десятки мегагерців) та навігаційним процесором розрахунку просторових координат (PVT Solver, що виконує матричні операції методом найменших квадратів на частоті 10–100 Гц) застосовують безблокувальні кільцеві черги (Lock-Free SPSC Ring Buffer). Це запобігає затримкам синхронізації м'ютексів та гарантує детермінований час передачі сформованих часових оцінок без втрати відліків.

Окремий потік диспетчеризації здійснює динамічний моніторинг глибини буферів: якщо спостерігається затримка передачі по мережі Ethernet між SDR-вузлами, алгоритм коригує межі вікна вимірювання `T_meas`, запобігаючи спустошенню або переповненню черги обробки. Завдяки цьому досягається мілісекундна повторюваність оцінок навіть при нестабільному навантаженні операційної системи.

## 10. Інженерні підводні камені та граничні ефекти

Під час практичного використання та налагодження когерентно-некогерентних інтеграторів у радіоприймачах необхідно враховувати чотири фундаментальні обмеження:

### 1. Зсув фази за залишку частотної похибки (Sinc Loss)
Якщо оцінка доплерівської частоти `f_d` має похибку `Δf`, фаза вектора корисного сигналу за час `T_coh` повертається на кут `Δφ = 2π · Δf · T_coh`. Когерентне підсумовування вектора, що обертається, призводить до амплітудних втрат за законом функції sinc:

```
Loss(Δf, T_coh) = | sinc(π · Δf · T_coh) | = | sin(π · Δf · T_coh) / (π · Δf · T_coh) |
```

Якщо добуток `Δf · T_coh = 0.5`, втрати потужності складають `-3.92 дБ`. Якщо ж `Δf · T_coh = 1.0`, інтеграл сигналу на періоді обертання стає рівним нулю: корисний сигнал повністю знищується власним фазовим обертанням! Звідси випливає фундаментальне правило проектування: **крок частотної сітки під час паралельного пошуку сигналу не повинен перевищувати `1 / (2 · T_coh)`**.

### 2. Перетинання меж навігаційних бітів (Bit Boundary Phase Inversion)
У сигналах BPSK із передачею навігаційних даних (наприклад, GPS L1 C/A з бітами 50 біт/с тривалістю 20 мс) кожен біт змінює знак огинальної сигналу на `180°`. Якщо когерентне вікно `T_coh = 20 мс` випадково накладається на момент перемикання біта (10 мс одного біта і 10 мс протилежного), дві половини когерентного інтеграла мають протилежні знаки і взаємно знищуються (`acc_coh ≈ 0`).

Для уникнення цього явища застосовують два підходи:
- Спочатку проводять початковий пошук із коротким когерентним вікном `T_coh = 1 мс` та великою кількістю некогерентних блоків `M = 20...100`.
- Після захоплення синхронізують межі когерентних блоків із фронтами бітів навігаційного повідомлення через гістограмний детектор перепадів знака (Bit Sync Detector).

### 3. Динамічний діапазон та переповнення акумуляторів
При реалізації на цілочисельних процесорах із фіксованою комою (Fixed-Point DSP) 16-бітних вхідних відліків `I/Q` когерентний акумулятор на `N_coh = 20 000` відліків вимагає запасу розрядності `log2(20000) ≈ 15 біт`. Якщо акумулятор має лише 16 або 32 біти, виникає ризик переповнення (Overflow Wrap-around), що призводить до катастрофічних шумів. У наведеній реалізації застосовано 32-бітні числа з рухомою комою (`float`), що забезпечує динамічний діапазон понад 150 дБ без загрози переповнення.

### 4. Вплив некогерентних втрат квадратування на чутливість
Збільшення часу вимірювання за рахунок некогерентного накопичення `M` блоків при підпороговому сигналі (`SNR_in ≪ 1`) супроводжується втратами квадратування `L_sq ≈ 1 / (2 · SNR_block)`. Це означає, що енергетичний виграш зростає як `√M`, а не лінійно `M`. Тому для виявлення надслабких сигналів (наприклад, у закритих приміщеннях при рівні `-160 дБм`) інженери завжди намагаються збільшити `T_coh` до максимально можливої межі, дозволеної стабільністю опорного генератора та часом когерентності каналу `T_c`.
