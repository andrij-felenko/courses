# 📋 Регістровий інтерфейс FIFO сучасних цифрових сенсорів

Регістровий інтерфейс апаратного буфера FIFO (*First-In, First-Out*, англ. «першим прийшов — першим пішов») визначає прямий бітовий контракт між мікроконтролером і вбудованим контролером пам'яті сенсора. Хоча фізичний принцип кільцевого буфера залишається спільним для всієї цифрової мікроелектроніки, конкретні регістрові карти, правила кодування прапорців стану, механізми синхронізації та формати пакування вибірок суттєво різняться залежно від виробника.

Нижче наведено вичерпну структурну специфікацію регістрових карт, бітових масок, систем тегування та протоколів керування для п'яти провідних індустріальних родин мікросхем: STMicroelectronics LSM6DSO, TDK InvenSense ICM-42688-P, Bosch Sensortec BMA400, класичного InvenSense MPU-6050 та радіотрансиверів Nordic Semiconductor nRF24L01+ і Texas Instruments CC1101.

### 1. STMicroelectronics LSM6DSO / LSM6DSL

У сенсорах сімейства LSM6DSO апаратний буфер FIFO має обсяг 3 КБ (3072 байти), що еквівалентно 512 слотам пакетів по 7 байтів кожен (плюс службова ділянка пам'яті). Буфер здатний одночасно зберігати вибірки первинного тривісного акселерометра, первинного тривісного гіроскопа, допоміжних сенсорів зовнішньої шини Sensor Hub (магнітометр, барометр), температурного сенсора, вбудованого апаратного крокоміра та 32-бітного лічильника системного часу.

#### 1.1. Блок конфігураційних регістрів (FIFO_CTRL1 – FIFO_CTRL4)

Керування режимами функціонування, порогами переривань та розподілом пропускної здатності здійснюється через блок конфігурації `FIFO_CTRL1` – `FIFO_CTRL4` (адреси `0x07` – `0x0A`).

| Адреса | Назва регістра | Біти 7:4 | Біти 3:0 | Функціональне призначення |
| :--- | :--- | :--- | :--- | :--- |
| `0x07` | `FIFO_CTRL1` | `WTM[7:0]` | `WTM[7:0]` | Молодші 8 бітів порогу вотермарка (*Watermark Threshold*). Задає рівень спрацьовування переривання в одиницях 7-байтових пакетних слотів. Діапазон значень: `0` – `512`. |
| `0x08` | `FIFO_CTRL2` | `STOP_ON_WTM`<br>`FIFO_COMPR_RT_EN`<br>`ODR_CHG_EN`<br>`UNCOPTR_RATE` | `WTM[10:8]` | Старші 3 біти порогу вотермарка. Біт 7 (`STOP_ON_WTM`) вмикає примусову зупинку запису при досягненні порогу вотермарка. Біт 6 вмикає стиснення даних у реальному часі. |
| `0x09` | `FIFO_CTRL3` | `BDR_GY[3:0]` | `BDR_XL[3:0]` | Частота пакетного збереження (*Batch Data Rate*) для гіроскопа (`GY`) та акселерометра (`XL`). Дозволяє децимувати потік запису відносно частоти АЦП. |
| `0x0A` | `FIFO_CTRL4` | `DEC_TS_BATCH[1:0]`<br>`ODR_T_BATCH[1:0]` | `FIFO_MODE[2:0]` | Децимація міток часу (*Timestamp*), частота пакування температурних вибірок та вибір базового апаратного режиму буфера. |

Поле `FIFO_MODE[2:0]` у регістрі `FIFO_CTRL4` (біти 2:0) задає логіку поведінки апаратних вказівників пам'яті:

- `0b000` — **Bypass Mode (Режим обходу):** Буфер FIFO вимкнено та скинуто. Вказівники обнулено. Виміри надходять виключно у вихідні регістри `OUTX_L_A`..`OUTZ_H_G`.
- `0b001` — **FIFO Mode (Режим Stop-on-Full):** Запис ведеться від початку буфера до повного заповнення 3 КБ. Після заповнення запис нових вибірок повністю блокується, зберігаючи записану серію.
- `0b011` — **Continuous-to-FIFO Mode (Неперервний до тригера):** Буфер працює в кільцевому режимі до появи апаратного тригера (наприклад, детектора вільного падіння), після чого перемикається в режим FIFO Mode і зупиняється після заповнення залишку пам'яті.
- `0b100` — **Bypass-to-Continuous Mode (Обхід до тригера):** До виникнення апаратної події буфер вимкнено; після спрацьовування тригера автоматично вмикається неперервний кільцевий запис.
- `0b110` — **Continuous Mode (Потоковий кільцевий режим):** Неперервний запис. При заповненні 100% обсягу пам'яті найновіші вибірки перезаписують найстаріші дані. У пам'яті завжди зберігається найсвіжіше часове вікно вимірів.
- `0b111` — **Bypass-to-FIFO Mode:** Буфер вимкнено до появи апаратної події, після чого виконується однократний запис вибірок до заповнення місткості SRAM.

Поля вибору швидкості збереження `BDR_XL[3:0]` та `BDR_GY[3:0]` у регістрі `FIFO_CTRL3` забезпечують незалежну децимацію каналів:

- `0b0000` — Датчик не записується у FIFO (канал відключено від конвеєра буферизації).
- `0b0001` — 12.5 Гц; `0b0010` — 26 Гц; `0b0011` — 52 Гц; `0b0100` — 104 Гц.
- `0b0101` — 208 Гц; `0b0110` — 416 Гц; `0b0111` — 833 Гц.
- `0b1000` — 1.66 кГц; `0b1001` — 3.33 кГц; `0b1010` — 6.66 кГц.

#### 1.2. Регістри стану та діагностики (FIFO_STATUS1, FIFO_STATUS2)

Моніторинг стану черги та прапорців переривань здійснюється за допомогою пари регістрів читання `FIFO_STATUS1` (`0x3A`) та `FIFO_STATUS2` (`0x3B`):

- `DIFF[10:0]` (11-бітний лічильник): Показує точну кількість незчитаних 7-байтових слотів, доступних у пам'яті. Молодші 8 бітів зчитуються з `FIFO_STATUS1`, а старші 3 біти — з поля `DIFF[10:8]` регістра `FIFO_STATUS2`.
- `FIFO_WTM_IA` (біт 7 `FIFO_STATUS2`): Апаратний прапорець активності вотермарка. Набуває значення `1`, коли `DIFF[10:0] >= WTM[10:0]`.
- `FIFO_OVR_IA` (біт 6 `FIFO_STATUS2`): Прапорець події переповнення (*FIFO Overrun*). Встановлюється в `1`, якщо нова вибірка надійшла в момент відсутності вільних слотів (у режимі Continuous сигналізує про втрату найстарішого елемента потоку).
- `FIFO_FULL_IA` (біт 5 `FIFO_STATUS2`): Прапорець 100% заповнення доступної пам'яті буфера.
- `COUNTER_B_RESET` (біт 4 `FIFO_STATUS2`): Сигналізує про завершення скидання внутрішніх вказівників пам'яті.

#### 1.3. Специфікація 7-байтового тегованого кадру (FIFO_DATA_OUT)

Зчитування накопичених даних здійснюється виключно через 7-байтове вихідне вікно, що починається з адреси `FIFO_DATA_OUT_TAG` (`0x78`) та продовжується регістрами `0x79` – `0x7E`.

Кожен слот містить рівно **7 байтів**:
- **Байт 0 (`0x78`): `FIFO_TAG`** — Старші 5 бітів `TAG[4:0]` (біти 7:3) кодують тип підключеного сенсора; молодші 2 біти `CNT[1:0]` (біти 2:1) утворюють лічильник парності кадру.
- **Байти 1–2 (`0x79`–`0x7A`): `DATA_X`** — молодший та старший байти осі X (або молодше 16-бітне слово службового блоку).
- **Байти 3–4 (`0x7B`–`0x7C`): `DATA_Y`** — молодший та старший байти осі Y.
- **Байти 5–6 (`0x7D`–`0x7E`): `DATA_Z`** — молодший та старший байти осі Z.

| Код `TAG[4:0]` | Ідентифікатор джерела | Формат корисного навантаження (6 байтів) |
| :--- | :--- | :--- |
| `0x01` (`0b00001`) | Гіроскоп (`GYRO_NC`) | Три 16-бітні осі `Gyr_X`, `Gyr_Y`, `Gyr_Z` у форматі int16_t (доповняльний код, Little-Endian). |
| `0x02` (`0b00010`) | Акселерометр (`ACC_NC`) | Три 16-бітні осі `Acc_X`, `Acc_Y`, `Acc_Z` у форматі int16_t (Little-Endian). |
| `0x03` (`0b00011`) | Температура кристала | `Temp[15:0]`, байти 3–6 заповнені фіксованим нульовим патерном. |
| `0x04` (`0b00100`) | Мітка часу (*Timestamp*) | 32-бітне беззнакове значення системного таймера (крок 25 мкс) плюс 16 бітів контрольної інформації. |
| `0x05` (`0b00101`) | Зміна конфігурації / помилка | Службовий інформаційний блок зі станом поточних ODR. |
| `0x0E` (`0b01110`) | Sensor Hub: Датчик 0 | Три осі зовнішнього цифрового сенсора (наприклад, магнітометра). |
| `0x12` (`0b10010`) | Апаратний крокомір | Кількість кроків та прапорці виявлення активності/ходьби. |

#### 1.4. Апаратний механізм компресії даних (FIFO Compression Engine)

У сенсорах LSM6DSO передбачено апаратний блок компресії в реальному часі, що активується бітом `FIFO_COMPR_RT_EN` у регістрі `FIFO_CTRL2`. Алгоритм базується на обчисленні різниць другого порядку між послідовними вибірками (дельта-дельта кодування). Якщо амплітуда прискорення чи кутової швидкості змінюється плавно, відхилення займають значно менше бітів, ніж повні 16-бітні відліки. Сенсор автоматично пакує такі різниці у змінні 8-бітні та 4-бітні контейнери, дозволяючи зберегти у фіксованому буфері 3 КБ до 9 КБ еквівалентних сирих даних без найменшої втрати математичної точності.

#### 1.5. Регістри керування допоміжною шиною Sensor Hub

Для налаштування автоматичного збору даних із зовнішніх сенсорів використовуються конфігураційні регістри `MASTER_CONFIG` (`0x14`) та описники каналів `SLV0_ADD` (`0x15`), `SLV0_SUBADD` (`0x16`), `SLV0_CONFIG` (`0x17`). Вони вказують 7-бітну адресу зовнішнього I2C-чипа, номер початкового регістра вимірів та кількість байтів для читання (від 1 до 6). Сенсор самостійно вичитує ці байти через допоміжні лінії AUX_SCL/AUX_SDA і пакує їх у FIFO з тегами `0x0E` – `0x11`.

### 2. TDK InvenSense ICM-42688-P

У прецизійному 6-осьовому MEMS IMU ICM-42688-P розмір апаратного буфера складає 2048 байтів (2 КБ). Сенсор вирізняється підтримкою розширеного 20-бітного формату високої роздільної здатності та конфігурованою структурою кадру зі змінним набором полів.

#### 2.1. Конфігураційна карта регістрів

| Адреса | Назва регістра | Бітові поля | Опис та правила конфігурації |
| :--- | :--- | :--- | :--- |
| `0x16` | `FIFO_CONFIG` | `7:6` : `FIFO_MODE[1:0]` | `00` — Bypass Mode (вимкнено); `01` — Stream-to-FIFO Mode (Continuous); `10` — Stop-on-Full (FIFO Mode). |
| `0x5F` | `FIFO_CONFIG1` | `4` : `FIFO_RESUME_DBG`<br>`3` : `FIFO_WM_INT_WAKE`<br>`2` : `FIFO_TEMP_EN`<br>`1` : `FIFO_GYRO_EN`<br>`0` : `FIFO_ACCEL_EN` | Біти індивідуального дозволу збереження джерел даних. Встановлення біта в `1` підключає відповідний канал до черги буферизації. Біт 3 дозволяє пробудження мікроконтролера по WTM з режимів глибокого сну. |
| `0x60` | `FIFO_CONFIG2` | `7:0` : `FIFO_WM[7:0]` | Молодші 8 бітів порогу вотермарка, вираженого в абсолютній кількості байтів. |
| `0x61` | `FIFO_CONFIG3` | `3:0` : `FIFO_WM[11:8]` | Старші 4 біти порогу вотермарка (повний діапазон: `0` – `2048` байтів). |
| `0x2E` | `FIFO_COUNTH` | `7:0` : `FIFO_CNT[15:8]` | Старший байт лічильника доступних незчитаних байтів у буфері. |
| `0x2F` | `FIFO_COUNTL` | `7:0` : `FIFO_CNT[7:0]` | Молодший байт лічильника доступних незчитаних байтів у буфері. |
| `0x30` | `FIFO_DATA` | `7:0` : `FIFO_R_DATA` | Єдине вікно пакетного зчитування даних буфера (Burst Read Port). |

#### 2.2. Пакетна організація та структура байта FIFO Header

Сенсор ICM-42688-P формує пакети відповідно до конфігурації біта `FIFO_HOLD_LAST_DATA_EN` та розрядності каналів. Кожен пакет відкривається обов'язковим однобайтним заголовком `FIFO Header`.

**Бітова структура байта FIFO Header:**
- `Bit 7 (HEADER_MSG)`: Встановлюється в `1`, якщо пакет містить повідомлення про зміну ODR або скидання конфігурації.
- `Bit 6 (HEADER_ACCEL)`: Сигналізує про наявність у поточному кадрі валідних даних акселерометра (`1` = присутні, `0` = відсутні).
- `Bit 5 (HEADER_GYRO)`: Сигналізує про наявність у поточному кадрі валідних даних гіроскопа (`1` = присутні).
- `Bit 4 (HEADER_20BIT)`: Ознака 20-бітного розширеного кадру (довжина кадру становить 20 байтів замість стандартних 16).
- `Bit 3:2 (HEADER_FSYNC)`: Стан апаратного зовнішнього входу синхронізації FSYNC на момент дискретизації.
- `Bit 1:0 (HEADER_ODR_MATCH)`: Прапорці збігу фази дискретизації між акселерометром та гіроскопом.

**Анатомія стандартного 16-байтового пакета (Packet 1):**
```
Байт 0      : FIFO Header
Байти 1..2  : Accel X [15:8], Accel X [7:0] (int16_t, Big-Endian)
Байти 3..4  : Accel Y [15:8], Accel Y [7:0]
Байти 5..6  : Accel Z [15:8], Accel Z [7:0]
Байти 7..8  : Gyro X [15:8], Gyro X [7:0] (int16_t, Big-Endian)
Байти 9..10 : Gyro Y [15:8], Gyro Y [7:0]
Байти 11..12: Gyro Z [15:8], Gyro Z [7:0]
Байт 13     : Temperature [7:0] (знаковий 8-бітний відлік)
Байти 14..15: Timestamp [15:0] (16-бітний лічильник часу)
```

### 3. Bosch Sensortec BMA400

Ультранизькоспоживаючий акселерометр BMA400 містить апаратний буфер FIFO ємністю 1024 байти (1 КБ) із підтримкою покадрового маркування змін конфігурації, контролю цілісності та автоматичного вирівнювання за заголовками.

#### 3.1. Регістри керування та розміру черги

| Адреса | Регістр | Опис функціоналу |
| :--- | :--- | :--- |
| `0x24` | `FIFO_LENGTH_0` | Молодший байт поточної кількості байтів у буфері (`FIFO_BYTE_COUNTER[7:0]`). |
| `0x25` | `FIFO_LENGTH_1` | Старші 3 біти лічильника (`FIFO_BYTE_COUNTER[10:8]`) та біт збереження цілісності. |
| `0x26` | `FIFO_DATA` | Порт послідовного вичитування даних буфера FIFO. |
| `0x27` | `FIFO_CONFIG_0` | Біти 7:5 (`fifo_z_en`, `fifo_y_en`, `fifo_x_en`) — вибірковий дозвіл осей;<br>Біти 3:2 (`fifo_stop_on_full`) — блокування при заповненні;<br>Біт 1 (`fifo_auto_flush`) — автоматичне очищення буфера при зміні ODR або фільтра. |
| `0x28` | `FIFO_CONFIG_1` | Вибір формату збереження: 12-бітний стандартний або 8-бітний скорочений режим; джерело фільтра (Acc Filter 1 / LP Filter). |
| `0x29` | `FIFO_CONFIG_2` | Конфігурація додавання даних апаратного крокоміра та подій активності. |
| `0x2A` | `FIFO_WTM_0` | Поріг спрацьовування вотермарка (крок 1 байт, діапазон `0` – `1024`). |

#### 3.2. Типи кадрів у байтовому потоці BMA400

Потік вибірок BMA400 формується з динамічних кадрів, кожен з яких відкривається однобайтним заголовком `Frame Header`:

1. **Кадр вимірів акселерометра (`Header = 0b10001000`..`0b10001111`):** Заголовок вказує набір активних осей у кадрі. Залежно від увімкнених осей та розрядності (12 чи 8 біт), за заголовком слідують від 1 до 6 байтів вимірів.
2. **Кадр керування (`Control Frame, Header = 0x80`):** Генерується автоматично, якщо під час збору даних хост змінив налаштування смуги пропускання чи діапазону прискорення. Наступний байт містить точний код причини зміни.
3. **Кадр часу (*Time Frame, Header = 0x89*):** Містить 3 байти лічильника реального часу сенсора.
4. **Кадр порожнечі (*Overread Frame, Header = 0x00*):** Повертається хосту, якщо той продовжує зчитувати регістр `FIFO_DATA` після вичерпання всіх валідних накопичених байтів.

### 4. Класичний сенсор InvenSense MPU-6050 (Нетегований потік)

Для розуміння еволюції інтерфейсів важливо знати класичну структуру регістрів сенсорів MPU-6000 / MPU-6050, де обсяг буфера складав 1024 байти (1 КБ):

| Адреса | Регістр | Опис |
| :--- | :--- | :--- |
| `0x23` | `FIFO_EN` | Біт 7: `TEMP_FIFO_EN`, Біти 6:4: `XG_FIFO_EN`, `YG_FIFO_EN`, `ZG_FIFO_EN`, Біт 3: `ACCEL_FIFO_EN`, Біти 2:0: `SLV2_FIFO_EN`, `SLV1_FIFO_EN`, `SLV0_FIFO_EN` (зовнішні I2C сенсори). |
| `0x6A` | `USER_CTRL` | Біт 6: `FIFO_EN` (глобальне ввімкнення апаратного блоку FIFO), Біт 2: `FIFO_RESET` (скидання вказівників пам'яті). |
| `0x72` | `FIFO_COUNTH` | Старші 8 бітів лічильника байтів (макс. 1024). |
| `0x73` | `FIFO_COUNTL` | Молодші 8 бітів лічильника байтів. |
| `0x74` | `FIFO_R_W` | Порт читання/запису FIFO (автоінкремент покажчика читання). |

У цій архітектурі кадри записувалися безперервно без жодного байта тегу чи заголовка. Порядок байтів був жорстко зафіксований бітами регістра `FIFO_EN`.

### 5. Радіотрансивери: Nordic nRF24L01+ та TI CC1101

У бездротових трансиверах архітектура буфера організована як **два повністю роздільні апаратні тракти**: черга передавача (TX FIFO) та черга приймача (RX FIFO).

#### 5.1. Nordic Semiconductor nRF24L01+

Буфери організовано у вигляді трьох рівнів по 32 байти кожен:

| Біт | Назва поля `FIFO_STATUS` (`0x17`) | Фізичний зміст |
| :--- | :--- | :--- |
| `6` | `TX_REUSE` | Режим повторного надсилання останнього переданого кадру без повторного завантаження в пам'ять. |
| `5` | `TX_FULL` | `1` — буфер передавача TX FIFO заповнений на 100% (усі 3 рівні зайняті). Запис нових даних блокується. |
| `4` | `TX_EMPTY` | `1` — буфер передавача TX FIFO повністю порожній. Передавач переходить у стан очікування (Standby-II). |
| `1` | `RX_FULL` | `1` — буфер приймача RX FIFO заповнений на 100% (усі 3 рівні зайняті). Нові вхідні радіопакети скидаються апаратно без генерації підтвердження ACK. |
| `0` | `RX_EMPTY` | `1` — буфер приймача RX FIFO порожній (немає прийнятих пакетів). |

Команди доступу до буферів nRF24L01+:
- `R_RX_PAYLOAD` (`0x61`): Вичитати прийнятий пакет із вершини RX FIFO (1–32 байти).
- `W_TX_PAYLOAD` (`0xA0`): Записати пакет у чергу TX FIFO для відправки в ефір.
- `FLUSH_TX` (`0xE1`): Апаратно очистити весь буфер TX FIFO.
- `FLUSH_RX` (`0xE2`): Апаратно очистити весь буфер RX FIFO.

#### 5.2. Texas Instruments CC1101

У трансивері CC1101 ємність TX FIFO та RX FIFO складає по 64 байти кожен:

- **Адреса доступу:** Регістр `0x3F` (одиночний доступ) або `0xBF` (Burst доступ із повнодуплексним читанням/записом).
- **Регістр статусу `RXBYTES` (`0x3B | 0xC0`):** Біти 6:0 повертають кількість байтів у RX FIFO; біт 7 сигналізує про переповнення `RXFIFO_OVERFLOW`.
- **Регістр статусу `TXBYTES` (`0x3A | 0xC0`):** Біти 6:0 повертають кількість вільних байтів у TX FIFO; біт 7 сигналізує про вичерпання `TXFIFO_UNDERFLOW`.
- **Команди стробування:** `SFTX` (`0x3B`) — очищення TX FIFO; `SFRX` (`0x34`) — очищення RX FIFO.
- **Програмований поріг вотермарка:** Регістр `FIFOTHR` (`0x03`) дозволяє налаштовувати поріг переривання лінії GDO0/GDO2 від 4 до 60 байтів із кроком 4 байти.

### 6. Послідовності ініціалізації та конфігурації регістрів

Для типового сценарію налаштування 6-осьового IMU (на прикладі ST LSM6DSO) драйвер виконує чітку послідовність записів:

1. **Скидання та перехід у Bypass Mode:**
   - Запис `0x00` у регістр `FIFO_CTRL4` (`0x0A`) — гарантує обнулення лічильників та вказівників.
2. **Конфігурація порогу вотермарка:**
   - Запис молодших 8 бітів `WTM = 64` (значення `0x40`) у `FIFO_CTRL1` (`0x07`).
   - Запис `0x00` у `FIFO_CTRL2` (`0x08`) — старші біти вотермарка та вимкнення зупинки.
3. **Налаштування темпу збереження (BDR):**
   - Запис `0x11` у `FIFO_CTRL3` (`0x09`) — встановлює частоту пакетного збереження 12.5 Гц для гіроскопа та акселерометра (або `0x88` для 1.66 кГц).
4. **Маршрутизація переривання на фізичну ніжку:**
   - Запис `0x08` у регістр `INT1_CTRL` (`0x0D`) — комутує сигнал `FIFO_TH` (вотермарк) на зовнішній вивід INT1.
5. **Активація неперервного режиму:**
   - Запис `0x06` у регістр `FIFO_CTRL4` (`0x0A`) — перемикає сенсор у `Continuous Mode` (потоковий кільцевий буфер).

### 8. Скінченний автомат обробки станів черги та відновлення синхронізації

Для надійної роботи вбудованого драйвера рекомендується реалізовувати скінченний автомат стану буфера (*State Machine*), що керується апаратними прапорцями регістрів статусу:

1. **Стан НАКОПИЧЕННЯ (Accumulation):**
   - Умова: `0 < FIFO_COUNT < WTM_THRESHOLD`, прапорець `FIFO_WTM_IA = 0`.
   - Дія: Хост-контролер перебуває в режимі глибокого сну. Сенсор накопичує вибірки у SRAM.
2. **Стан ВИЧИТУВАННЯ (Watermark Readout):**
   - Умова: `FIFO_WTM_IA = 1` або спрацьовування лінії `INT`.
   - Дія: Пробудження ядра, активація неблокуючої транзакції SPI DMA на вичитку `WTM_THRESHOLD` слотів даних, деактивація лінії переривання.
3. **Стан АВАРІЙНОГО ПЕРЕПОВНЕННЯ (Overrun Recovery):**
   - Умова: Прапорець `FIFO_OVR_IA = 1` (або `RX_FULL = 1`).
   - Дія: Фіксація лічильника втрачених вибірок для діагностики, примусове вичитування залишків даних, виконання послідовності скидання вказівників (перемикання `Bypass -> Continuous`) та реініціалізація вотермарка.
4. **Стан ДЕСИНХРОНІЗАЦІЇ (Desynchronization Recovery):**
   - Умова: Отримання невалідного коду `TAG` або розрив структури заголовка.
   - Дія: Негайне апаратне скидання буфера для запобігання фазовому зміщенню вимірювальних осей у подальших обчисленнях фільтра орієнтації.
