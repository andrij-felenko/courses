# 🧮 Математичний аналіз пропускної здатності, накладних витрат та енергоефективності шини I3C

Кількісне порівняння характеристик інтерфейсу MIPI I3C з класичними шинами I2C та SPI вимагає математичного моделювання часового бюджету транзакцій, питомих накладних витрат протоколу, затримок перезаряджання розподіленої ємності магістралі та динамічного і статичного енергоспоживання фізичного рівня.

---

### 1. Аналітична модель часового бюджету транзакції

Загальний час виконання транзакції пакетного зчитування `N` байтів корисних даних з цільового пристрою на шині I3C у базовому режимі SDR (*Single Data Rate*) складається з трьох послідовних часових інтервалів:

```
T_total = T_header_OD + T_data_PP + T_stop_OD
```

1. **Фаза заголовка відкритого стоку (*Open-Drain Header*):** включає сигнал старту (*START*), 7-бітну динамічну адресу цілі, біт напрямку `RnW` та такт підтвердження `ACK/NACK`. Оскільки арбітраж виконується на відкритому стоці, ця фаза тактується на зниженій частоті `f_OD = 4.0` МГц (тривалість такту `t_OD = 250` нс):

```
T_header_OD
= 1 · t_start + 7 · t_OD + 1 · t_OD + 1 · t_OD   [тривалість: 1 старт-біт + 7 бітів адреси + 1 RnW + 1 ACK]
= t_start + 9 · t_OD                            [групування: 9 тактових періодів відкритого стоку]
= 250 + 9 · 250                                 [підстановка: t_start = 250 нс, t_OD = 250 нс]
= 2500 нс = 2.50 мкс                            [розрахунок: загальна тривалість заголовка адреси]
```

2. **Фаза даних у двотактному режимі (*Push-Pull Data*):** кожен байт даних супроводжується дев'ятим перехідним бітом парності (*T-bit*). Фаза виконується на повній тактовій частоті `f_PP = 12.5` МГц (тривалість такту `t_PP = 80` нс):

```
T_data_PP
= N · (8 + 1) · t_PP                            [тривалість: N байтів по 8 бітів даних + 1 T-біт]
= N · 9 · 80 нс                                 [підстановка: період такту t_PP = 80 нс]
= N · 720 нс = N · 0.72 мкс                     [розрахунок: час передачі N байтів даних]
```

3. **Фаза завершення (*STOP Condition*):** формування переходу сигналу зупинки у режимі відкритого стоку:

```
T_stop_OD
= 2 · t_OD                                      [тривалість: підготовка лінії + формування переходу STOP]
= 2 · 250                                       [підстановка: t_OD = 250 нс]
= 500 нс = 0.50 мкс                             [розрахунок: час завершення транзакції]
```

Підсумковий час зчитування `N` байтів виражається лінійною функцією:

```
T_I3C(N)
= T_header_OD + T_data_PP + T_stop_OD           [структура: сума трьох часових фаз транзакції]
= 2.50 мкс + (N · 0.72) мкс + 0.50 мкс          [підстановка розрахованих компонентів]
= 3.00 + 0.72 · N                               [спрощення: лінійна часова залежність у мікросекундах]
```

Для порівняння, на шині I2C у режимі Fast-Mode (частота такту `f_I2C = 400` кГц, тривалість такту `t_I2C = 2.5` мкс) аналогічна транзакція зчитування з попереднім записом адреси регістра вимагає двох фаз адресації та формування повторного старту (*Repeated START*):

```
T_I2C_400k(N)
= (1 + 9 + 9 + 1 + 9 + 9 · N + 1) · t_I2C       [структура: Start + Addr(W) + Reg + Sr + Addr(R) + N Data + Stop]
= (29 + 9 · N) · 2.5 мкс                        [підстановка: період такту t_I2C = 2.5 мкс]
= 72.5 + 22.5 · N                               [спрощення: лінійна часова залежність у мікросекундах]
```

### 2. Порівняльний розрахунок для 6-осьового інерційного давача (IMU)

Розглянемо практичну інженерну задачу: безперервне опитування 6-осьового модуля IMU (3 осі акселерометра + 3 осі гіроскопа, сумарно `N = 12` байтів вихідних регістрів вимірів) з частотою дискретизації `F_sample = 1` кГц (період вибірки `T_period = 1000` мкс).

#### Час зайнятості шини (*Bus Occupancy Time*):

* **I2C Standard-Mode (100 кГц, `t_I2C = 10.0` мкс):**
```
T_I2C_100k
= (29 + 9 · 12) · 10.0 мкс                      [підстановка: N = 12 байтів, t_I2C = 10 мкс]
= (29 + 108) · 10.0 мкс                         [арифметика: множення 9 · 12 = 108 тактів даних]
= 137 · 10.0 = 1370.0 мкс                       [розрахунок: повний час транзакції перевищує період 1000 мкс]
```
*Коефіцієнт завантаження шини:* `1370 мкс / 1000 мкс = 137%` — шина перевантажена, неперервне опитування на цій швидкості фізично неможливе.

* **I2C Fast-Mode (400 кГц, `t_I2C = 2.5` мкс):**
```
T_I2C_400k
= 72.5 + 22.5 · 12                              [підстановка: формула транзакції при N = 12]
= 72.5 + 270.0                                  [арифметика: 22.5 · 12 = 270.0 мкс]
= 342.5 мкс                                     [розрахунок: час зайнятості шини]
```
*Коефіцієнт завантаження шини:* `342.5 мкс / 1000 мкс = 34.25%`.

* **I2C Fast-Mode Plus (1 МГц, `t_bit = 1.0` мкс):**
```
T_I2C_1M
= (29 + 9 · 12) · 1.0 мкс                       [підстановка: N = 12 байтів, t_bit = 1.0 мкс]
= 137.0 мкс                                     [розрахунок: час транзакції]
```
*Коефіцієнт завантаження шини:* `137.0 мкс / 1000 мкс = 13.70%`.

* **I3C SDR (12.5 МГц):**
```
T_I3C_SDR
= 3.00 + 0.72 · 12                              [підстановка: формула I3C SDR при N = 12]
= 3.00 + 8.64                                   [арифметика: 0.72 · 12 = 8.64 мкс]
= 11.64 мкс                                     [розрахунок: сумарний час транзакції]
```
*Коефіцієнт завантаження шини:* `11.64 мкс / 1000 мкс = 1.164%`.

* **I3C HDR-DDR (25 Мбіт/с, подвійна швидкість на обох фронтах SCL):**
```
T_I3C_HDR
= 2.50 + (12 · 9 / 2) · 0.08 + 0.50             [підстановка: 54 такти DDR по 80 нс = 4.32 мкс]
= 2.50 + 4.32 + 0.50                            [додавання: фаза заголовка + дані HDR + стоп]
= 7.32 мкс                                      [розрахунок: сумарний час транзакції HDR-DDR]
```
*Коефіцієнт завантаження шини:* `7.32 мкс / 1000 мкс = 0.732%`.

Шина I3C у базовому режимі SDR скорочує час зайнятості каналу зв'язку у **29.4 раза** порівняно з I2C 400 кГц, вивільняючи 98.8% часового бюджету процесора для виконання алгоритмів стабілізації або переходу в стан глибокого сну.

### 3. Протокольна ефективність (*Protocol Efficiency*)

Протокольна ефективність `η` визначається як відношення часу передачі суто корисних інформаційних бітів до повного часу утримання шини:

```
η = (8 · N · t_bit_ideal) / T_total(N)
```

де `t_bit_ideal = 1 / f_nominal`.

Для пакета довжиною `N = 16` байтів:

1. **I2C 400 кГц:**
```
T_data_useful = 16 · 8 · 2.5 мкс = 320.0 мкс   [корисний час: 128 інформаційних бітів]
T_total_i2c   = 72.5 + 22.5 · 16 = 432.5 мкс   [повний час: заголовок адреси + дані + ACK]
η_I2C         = 320.0 / 432.5 = 73.99%          [ефективність: частка корисного часу]
```

2. **I3C SDR 12.5 МГц:**
```
T_data_useful = 16 · 8 · 0.08 мкс = 10.24 мкс  [корисний час: 128 бітів на швидкості 12.5 МГц]
T_total_i3c   = 3.00 + 0.72 · 16  = 14.52 мкс  [повний час: заголовок OD + дані PP + Stop]
η_I3C         = 10.24 / 14.52 = 70.52%          [ефективність: накладні витрати заголовка відкритого стоку]
```

Зі збільшенням розміру пакета до `N = 128` байтів фіксована вартість заголовка нівелюється:

```
T_total_128   = 3.00 + 0.72 · 128 = 95.16 мкс  [повний час транзакції для 128 байтів]
T_useful_128  = 128 · 8 · 0.08 мкс = 81.92 мкс [корисний час передачі даних]
η_I3C_128     = 81.92 / 95.16 = 86.09%          [ефективність: прагне до теоретичної межі 8/9 = 88.89%]
```

### 4. Фізична модель перезаряджання ємності лінії: RC-ланцюг проти Push-Pull

Фізична різниця між відкритим стоком та двотактним виходом описується диференціальним рівнянням перехідного процесу заряджання вузлової ємності:

```
C_bus · (dV(t) / dt) + (V(t) - V_DD) / R_pullup = 0
```

Розв'язок цього рівняння для напруги наростання `V(t)` від нуля до порогу логічної одиниці `V_IH = 0.7 · V_DD`:

```
V(t) = V_DD · (1 - e^(-t / (R_pullup · C_bus)))
```

Час наростання фронту від 10% (`0.1 · V_DD`) до 90% (`0.9 · V_DD`) визначається постійною часу `τ = R_pullup · C_bus`:

```
t_rise_OD
= ln(0.9 / 0.1) · R_pullup · C_bus              [логарифмічна різниця меж інтегрування]
= ln(9) · R_pullup · C_bus                      [спрощення: ln(9) ≈ 2.1972]
≈ 2.2 · R_pullup · C_bus                        [інженерна формула часу наростання відкритого стоку]
```

Розрахуємо час наростання для трьох типових конфігурацій ємності плати при `R_pullup = 2.2` кОм:

* При `C_bus = 25` пФ: `t_rise = 2.2 · 2200 · 25 · 10⁻¹² = 121.0` нс.
* При `C_bus = 50` пФ: `t_rise = 2.2 · 2200 · 50 · 10⁻¹² = 242.0` нс.
* При `C_bus = 100` пФ: `t_rise = 2.2 · 2200 · 100 · 10⁻¹² = 484.0` нс.

Для тактової частоти 12.5 МГц напівперіод сигналу становить лише `t_half = 40` нс. Очевидно, що пасивний відкритий стік з часом наростання від 121 до 484 нс не здатен функціонувати на такій частоті.

У двотактному каскаді Push-Pull верхній P-канальний транзистор відкривається в лінійній/насиченій області, забезпечуючи вихідний струм заряду `I_drive ≈ 4..8` мА. Час наростання визначається швидкістю інтегрування струму:

```
t_rise_PP
= C_bus · ΔV / I_drive                          [інтегрування постійного струму перезаряджання ємності]
= 50 · 10⁻¹² · 1.8 / (6 · 10⁻³)                 [підстановка: C = 50 пФ, V = 1.8 В, I = 6 мА]
= 90 · 10⁻¹² / (6 · 10⁻³)                       [ділення чисельника на знаменник]
= 15.0 · 10⁻⁹ с = 15.0 нс                       [розрахунок: крутий симетричний фронт сигналу]
```

Час 15.0 нс повністю вкладається в часове вікно напівперіоду 40 нс, залишаючи 25 нс запасу для стабільного зчитування даних приймачем.

### 5. Енергетична модель фізичного рівня: статичні та динамічні втрати

Енергія `E_trans`, що витрачається на передачу одного пакета даних, визначається сумою динамічних втрат на перезаряджання паразитної ємності ліній `C_bus` та статичних втрат струму через підтягувальні резистори `R_pullup`.

```
E_trans = E_dynamic + E_static
```

#### Статичні втрати на шині I2C (відкритий стік)

Коли лінія SDA або SCL утримується вихідним транзистором у низькому стані логічного нуля, через підтягувальний резистор `R_pullup` безперервно протікає струм:

```
I_static = V_DD / R_pullup
P_static = (V_DD)² / R_pullup
```

Для стандартних параметрів шини I2C (`V_DD = 3.3` В, `R_pullup = 2.2` кОм):
```
I_static = 3.3 / 2200 = 1.50 мА
P_static = (3.3)² / 2200 = 4.95 мВт
```

Якщо припустити статистично рівноймовірний розподіл нулів та одиниць (коефіцієнт заповнення низького рівня `D_low ≈ 0.5` на SDA та `0.5` на SCL), статична енергія за час транзакції `T_I2C = 342.5` мкс складає:

```
E_static_I2C
= P_static · T_I2C · (D_low_SDA + D_low_SCL)    [інтегрування статичної потужності за час транзакції]
= 4.95 мВт · 342.5 мкс · (0.5 + 0.5)            [підстановка: P = 4.95 мВт, T = 342.5 мкс, сумарний коефіцієнт = 1]
= 4.95 · 10⁻³ · 342.5 · 10⁻⁶                    [переведення величин у систему СІ]
= 1.695 мкДж                                    [розрахунок: статична енергія, розсіяна у тепло на резисторі]
```

#### Динамічні втрати на шині I3C (двотактний Push-Pull)

У двотактному режимі Push-Pull резистори підтяжки відімкнені внутрішніми ключами, а рівні утримуються схемою *High-Keeper* зі струмом витоку менше 5 мкА. Статичні втрати практично дорівнюють нулю (`P_static ≈ 0`).

Динамічна енергія визначається кількістю циклів перезаряджання паразитної ємності шини `C_bus` (типово `C_bus = 25` пФ):

```
E_dynamic = N_switches · C_bus · (V_DD)²
```

Для шини I3C з напругою живлення `V_DD = 1.8` В при передачі 12 байтів (`12 · 9 = 108` тактових перемикань SCL та близько 54 перемикань SDA):

```
E_dynamic_I3C
= (108 + 54) · C_bus · (V_DD)²                  [сума перемикань ліній: 108 SCL + 54 SDA = 162 перемикання]
= 162 · 25 · 10⁻¹² · (1.8)²                     [підстановка: C = 25 пФ, V = 1.8 В]
= 162 · 25 · 10⁻¹² · 3.24                       [обчислення квадрата напруги: 1.8² = 3.24 В²]
= 13.12 · 10⁻⁹ Дж = 0.0131 мкДж                 [розрахунок: сумарна динамічна енергія перезаряду ємності]
```

#### Порівняння питомої енергії на зчитування виміру

```
E_I2C(12 bytes) ≈ 1.70 мкДж
E_I3C(12 bytes) ≈ 0.013 мкДж
```

За рахунок швидкого завершення передачі (11.6 мкс замість 342.5 мкс), зниження напруги живлення до 1.8 В та усунення резистивного витоку струму шина I3C споживає у **130 разів менше електричної енергії** на одну операцію зчитування, ніж класичний інтерфейс I2C.

### 6. Розрахунок часу автономної роботи мобільного пристрою

Оцінимо виграш у тривалості роботи наручного смарт-годинника від стандартного акумулятора ємністю `E_bat = 300` мА·год (`1.11` Вт·год `= 3996` Дж при номінальній напрузі `3.7` В).

Припустимо, що система безперервно опитує 6-осьовий IMU на частоті `1` кГц (`1000` опитувань/с `= 86.4 · 10⁶` транзакцій на добу):

1. **Добові витрати енергії на інтерфейс I2C 400 кГц:**
```
E_day_I2C = 86.4 · 10⁶ · 1.695 · 10⁻⁶ Дж = 146.45 Дж/добу
Частка від ємності батареї: 146.45 / 3996 = 3.66% ємності на добу лише на нагрів підтяжки
```

2. **Добові витрати енергії на інтерфейс I3C SDR 12.5 МГц:**
```
E_day_I3C = 86.4 · 10⁶ · 0.0131 · 10⁻⁶ Дж = 1.13 Дж/добу
Частка від ємності батареї: 1.13 / 3996 = 0.028% ємності на добу
```

Шина I3C практично повністю усуває енергетичні накладні витрати шинного інтерфейсу, зберігаючи до 3.6% заряду акумулятора щодня.

### 7. Затримка обслуговування переривань (Interrupt Latency)

Порівняємо математичну затримку реакції системи на подію давача:

* **Періодичне опитування (Polling) через I2C:**
```
Середня затримка:  T_latency = T_period / 2 = 1000 / 2 = 500 мкс
Максимальна:       T_latency_max = 1000 мкс
```

* **Асинхронний вивід GPIO INT + шина I2C:**
```
T_latency_GPIO
= t_irq_cpu + T_I2C_read_status + T_I2C_read_data [структура: переривання процесора + читання статусу + читання даних]
= 2.0 мкс + 72.5 мкс + 342.5 мкс                 [підстановка: вхід у переривання + 2 транзакції I2C]
= 417.0 мкс                                      [розрахунок: загальна затримка реакції системи]
```

* **Внутрішньосмугове переривання I3C IBI:**
```
T_latency_IBI
= t_bus_arb + t_MDB_payload                      [структура: арбітраж адреси на шині + читання байта MDB]
= 2.50 мкс + (1 · 9 · 0.08) мкс                  [підстановка: заголовок OD 2.5 мкс + 1 байт PP 0.72 мкс]
= 2.50 + 0.72                                    [додавання фаз арбітражу та корисної інформації]
= 3.22 мкс                                       [розрахунок: миттєва доставка причини переривання]
```

Механізм IBI знижує латентність реакції системи на критичні апаратні події (наприклад, детектування вільного падіння чи зіткнення дрона) з сотень мікросекунд до **3.22 мікросекунди**, доставляючи байт причини переривання MDB безпосередньо у першому ж циклі арбітражу.
