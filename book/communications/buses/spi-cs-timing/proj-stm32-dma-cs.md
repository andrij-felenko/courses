# ⚙️ Керування CS у зв'язці з DMA та апаратним SPI

Під час передачі великих масивів даних (кадрів графічних дисплеїв, сторінок Flash-пам'яті чи потокових вибірок швидкісних АЦП) розробники вбудованих систем намагаються максимально розвантажити центральний процесор за допомогою прямого доступу до пам'яті (DMA). Проте спроба довірити керування лінією вибору кристала CS апаратному виводу NSS або наївне перемикання GPIO всередині обробника переривання DMA Transfer Complete призводить до систематичного обриву останнього байта транзакції. Причина полягає в асинхронній природі конвеєра передавача: контролер DMA сигналізує про завершення своєї задачі в момент, коли останній байт переміщено з оперативної пам'яті в буфер передавача SPI, тоді як апаратний зсувний регістр SPI ще тільки починає виштовхувати біти в лінію.

Нижче детально розібрано апаратну архітектуру конвеєра SPI + DMA на прикладі мікроконтролерів сімейства STM32, наведено діаграму станів надійного автомата керування лінією CS, проаналізовано взаємодію з операційними системами реального часу (FreeRTOS), представлено архітектуру асинхронного неблокуючого драйвера, розібрано протокол аварійного відновлення шини та наведено повноцінний промисловий код мовами C (STM32 Low-Layer API) та C++ (сучасна RAII-обгортка з нульовими накладними витратами).

### Архітектура конвеєра передавача та механізм часової пастки

Щоб зрозуміти, чому сигнал CS не можна знімати безпосередньо по завершенню передачі DMA, розглянемо фізичний конвеєр проходження даних усередині периферійного модуля SPI:

```
[ Оперативна пам'ять SRAM ]
            │
            ▼ (Шина DMA)
[ Вхідний буфер даних / FIFO: SPI_DR / SPI_TXDR ] ◄── Прапорець TXE = 1 (Буфер вільний)
            │
            ▼ (Внутрішній паралельний перенос)
[ Апаратний зсувний регістр: Shift Register ]     ◄── Прапорець BSY = 1 (Шина передає біти)
            │
            ▼ (Послідовний зсув за тактами SCLK)
[ Вихідний вивід MOSI ] ─────────────────────────► Лінія передачі даних
```

Конвеєр складається з двох послідовних ступенів:
1. **Буфер передавача (`TXDR` / `DR` або FIFO)**: проміжний регістр, у який контролер DMA або процесорне ядро записує чергове слово даних. Коли цей буфер спорожнюється (дані скопійовано у зсувний регістр), апаратний блок SPI негайно виставляє статусний прапорець `TXE = 1` (*Transmit Data Register Empty*), сигналізуючи DMA про готовність прийняти наступний байт.
2. **Апаратний зсувний регістр (*Shift Register*)**: паралельно-послідовний регістр, який безпосередньо підключений до лінії MOSI і тактується генератором SCLK. Поки в цьому регістрі зсувається хоча б один біт, апаратний блок утримує статусний прапорець `BSY = 1` (*Busy*).

#### Розвиток помилки при передачі блоку з N байт:

1. Контролер DMA передає перші `N - 1` байт без затримок: як тільки `TXE = 1`, DMA миттєво завантажує наступний байт у чергу.
2. Коли DMA завантажує останній `N`-й байт у регістр `TXDR`, його внутрішній лічильник передач досягає нуля.
3. Контролер DMA вважає свою місію повністю виконаною: він формує апаратне переривання `DMA_IT_TC` (*Transfer Complete*) та викликає користувацький колбек `HAL_SPI_TxCpltCallback()` (або переводить потік у неактивний стан).
4. **У цей самий момент `N`-й байт ще навіть не почав передаватися по фізичній шині!** Він лише чекає, поки зсувний регістр завершить передачу `(N - 1)`-го байта, після чого почнеться виштовхування 8 біт останнього байта (що займає 8 періодів такту `T[SCK]`).
5. Якщо програмний код піднімає лінію CS усередині обробника переривання DMA, лінія CS переходить у неактивний високий стан, коли останній байт тільки почав виходити на лінію MOSI (передано 1–2 біти).
6. Ведений пристрій бачить підйом CS, аварійно відключає лінію MISO, скидає свій внутрішній зсувний регістр і відхиляє весь пакет через помилку неповного кадру (*framing error*).

### Регістрова карта та бітові поля керування

Для безпосереднього контролю конвеєра SPI та DMA на рівні апаратних регістрів мікроконтролера STM32 використовуються такі бітові поля:

* **Регістр конфігурації `SPI_CR1`**:
  * Біт `SPE` (*SPI Enable*): вмикає внутрішній тактовий генератор та вихідні буфери.
  * Біти `BR[2:0]` (*Baud Rate Control*): задають коефіцієнт ділення системної частоти шини APB (від ділення на 2 до ділення на 256).
  * Біти `CPOL` та `CPHA`: задають режим полярності та фази тактування.
  * Біт `SSM` (*Software Slave Management*): повинен бути встановлений в `1` для відключення апаратного виводу NSS і переходу на програмне керування через GPIO.
  * Біт `SSI` (*Internal Slave Select*): при `SSM = 1` утримується в `1`, щоб апаратний модуль вважав себе ведучим і не переходив у помилку `MODF` (*Mode Fault*).
* **Регістр конфігурації `SPI_CR2`**:
  * Біт `TXDMAEN` (*Tx Buffer DMA Enable*): дозволяє формувати запити DMA при появі прапорця `TXE = 1`.
  * Біт `RXDMAEN` (*Rx Buffer DMA Enable*): дозволяє запити DMA на прийом даних при `RXNE = 1`.
* **Регістр статусу `SPI_SR`**:
  * Прапорець `TXE` (біт 1): встановлюється в `1`, коли вхідний буфер вільний для запису.
  * Прапорець `BSY` (біт 7): активний (`1`), коли зсувний регістр передає біти або коли буфер `TXDR` не порожній. Скидається в `0` лише після повернення SCLK у рівень спокою.
* **Регістр конфігурації потоку `DMA_SxCR`**:
  * Біт `EN` (*Stream Enable*): увімкнення та вимкнення потоку DMA.
  * Біт `TCIE` (*Transfer Complete Interrupt Enable*): генерація переривання після передачі останнього слова.
  * Біти `DIR[1:0]`: вибір напрямку (для передачі встановлюється в `01` — з пам'яті в периферію, *Memory-to-Peripheral*).
  * Біт `MINC`: автоматичний інкремент покажчика пам'яті після кожного переданого байта.

### Часова діаграма фаз передачі з DMA

Для гарантованого збереження цілісності даних процес передачі розбивається на шість послідовних часових фаз:

```
Фаза 1: Активація CS ────────► GPIO CS = 0
Фаза 2: Витримка t_CSS ──────► Пауза t_CSS (інструкції NOP або апаратне випередження)
Фаза 3: Передача через DMA ──► Запуск DMA, вивантаження пам'яті в SPI_TXDR
Фаза 4: Очікування DMA TC ───► DMA спустошив масив RAM (DMA_IT_TC = 1)
Фаза 5: Очікування BSY = 0 ──► Очікування фізичного зсуву останнього біта (BSY = 0) + витримка t_CSH
Фаза 6: Деактивація CS ──────► GPIO CS = 1 + витримка паузи t_CS_HIGH перед новим пакетом
```

### Взаємодія з операційними системами реального часу (FreeRTOS)

У багатозадачних системах під керуванням FreeRTOS або Zephyr виникає критичний ризик **витіснення задачі** (*Task Preemption*) в інтервалі між активацією CS та стартом DMA, або між завершенням DMA та підйомом CS:

1. **Ризик пріоритетної інверсії**:
   Якщо задача з низьким пріоритетом опустила лінію CS, але була витіснена високопріоритетною задачею обробки звуку чи мережевого стека, лінія CS залишатиметься активною протягом кількох мілісекунд. Для Flash-пам'яті це безпечно, проте в деяких сенсорах тривале утримання CS активним без тактування SCLK сприймається як таймаут інтерфейсу і переводить сенсор у режим апаратного перезавантаження.
2. **Захист критичною секцією або семафором**:
   Доступ до шини SPI повинен захищатися м'ютексом із протоколом успадкування пріоритетів (*Priority Inheritance*).
3. **Асинхронне сповіщення задачі через Task Notifications**:
   Замість блокуючого очікування прапорця `BSY` у коді задачі обробник переривання DMA (або кінцевий обробник SPI TX) надсилає пряме сповіщення задачі `xTaskNotifyFromISR()`, пробуджуючи потік лише після повного звільнення фізичної лінії.

### Асинхронний неблокуючий драйвер на базі переривань

Для високонавантажених систем блокування процесорного ядра в циклі очікування прапорця `BSY` є неприпустимим марнуванням обчислювальних ресурсів. Якщо транзакція передає 1024 байти на швидкості 1 Мбіт/с, процесор витратив би понад 8 мілісекунд у порожньому циклі `while (BSY)`.

Асинхронний підхід вирішує цю проблему за допомогою двоетапного ланцюжка переривань:
1. **Перший етап (DMA TC)**: Контролер DMA передає масив даних і формує переривання `DMA_IT_TC`. В обробнику переривання DMA потік вимикається, а замість блокуючого очікування вмикається переривання самого модуля SPI по завершенню передачі `SPI_IT_TXE` або `SPI_IT_RXNE`.
2. **Другий етап (SPI ISR / Timer)**: Коли зсувний регістр повністю завершує тактування і прапорець `BSY` скидається в `0`, обробник переривання піднімає вивід GPIO CS, формує міжкадрову паузу `t[CS_HIGH]` та надсилає асинхронне сповіщення `vTaskNotifyGiveFromISR()` керуючій задачі операційної системи.

Така архітектура дозволяє центральному процесору виконувати інші корисні задачі протягом усього часу передачі даних по шині SPI.

### Реалізація промислового драйвера на C (STM32 Low-Layer) та C++

У наведених нижче прикладах реалізовано драйвер керування лінією CS для мікроконтролера STM32F4/G4/H7. У вкладці C використано низькорівневу бібліотеку STM32 LL, що забезпечує мінімальні накладні витрати на рівні окремих регістрових операцій. У вкладці C++ представлено об'єктно-орієнтований клас `SpiDmaSession`, який реалізує ідіому RAII (*Resource Acquisition Is Initialization*), інкапсулює роботу з буферами `std::span` та автоматично гарантує коректне закриття транзакції у деструкторі.

:::tabs
```c
#include "stm32f4xx_ll_spi.h"
#include "stm32f4xx_ll_dma.h"
#include "stm32f4xx_ll_gpio.h"
#include "stm32f4xx_ll_bus.h"
#include <stdint.h>
#include <stdbool.h>

/* Конфігурація порту та виводу лінії CS */
#define SPI_CS_PORT GPIOA
#define SPI_CS_PIN  LL_GPIO_PIN_4

/* Функція захисної мікропаузи для витримки t_CSS та t_CSH */
static inline void spi_guard_delay(void) {
    __NOP(); __NOP(); __NOP(); __NOP();
    __NOP(); __NOP(); __NOP(); __NOP();
}

/* Ініціалізація виводу CS у режимі швидкісного двотактного виходу */
void spi_cs_init(void) {
    LL_AHB1_GRP1_EnableClock(LL_AHB1_GRP1_PERIPH_GPIOA);
    
    LL_GPIO_SetPinMode(SPI_CS_PORT, SPI_CS_PIN, LL_GPIO_MODE_OUTPUT);
    LL_GPIO_SetPinOutputType(SPI_CS_PORT, SPI_CS_PIN, LL_GPIO_OUTPUT_PUSHPULL);
    LL_GPIO_SetPinSpeed(SPI_CS_PORT, SPI_CS_PIN, LL_GPIO_SPEED_FREQ_VERY_HIGH);
    LL_GPIO_SetPinPull(SPI_CS_PORT, SPI_CS_PIN, LL_GPIO_PULL_UP);
    
    /* За замовчуванням лінія CS деактивована (високий рівень) */
    LL_GPIO_SetOutputPin(SPI_CS_PORT, SPI_CS_PIN);
}

/* Активація вибору кристала з гарантованою витримкою t_CSS */
void spi_cs_assert(void) {
    LL_GPIO_ResetOutputPin(SPI_CS_PORT, SPI_CS_PIN);
    spi_guard_delay(); /* Гарантуємо t_CSS перед першим тактом SCLK */
}

/* Безпечна деактивація CS з повною перевіркою зсувного регістра */
void spi_cs_deassert(SPI_TypeDef *SPIx) {
    /* 1. Очікуємо повного спорожнення вхідного буфера даних */
    while (!LL_SPI_IsActiveFlag_TXE(SPIx)) {
        /* Чекаємо готовності буфера TXDR */
    }

    /* 2. КРИТИЧНИЙ ЕТАП: чекаємо завершення фізичного тактування в лінії */
    while (LL_SPI_IsActiveFlag_BSY(SPIx)) {
        /* Прапорець BSY активний, поки зсувний регістр жене біти в MOSI */
    }

    /* 3. Витримуємо час утримання t_CSH після останнього спаду SCLK */
    spi_guard_delay();

    /* 4. Переводимо лінію CS у високий стан */
    LL_GPIO_SetOutputPin(SPI_CS_PORT, SPI_CS_PIN);
    
    /* 5. Витримуємо час неактивності t_CS_HIGH перед наступною операцією */
    spi_guard_delay();
}

/* Блокуюча функція передачі блоку пам'яті через DMA з контролем CS */
bool spi_dma_transmit_sync(SPI_TypeDef *SPIx, DMA_TypeDef *DMAx, uint32_t Stream,
                           const uint8_t *tx_buffer, uint32_t length) {
    if (tx_buffer == NULL || length == 0) {
        return false;
    }

    /* Крок 1: Опускаємо CS */
    spi_cs_assert();

    /* Крок 2: Налаштовуємо параметри DMA */
    LL_DMA_DisableStream(DMAx, Stream);
    LL_DMA_SetMemoryAddress(DMAx, Stream, (uint32_t)tx_buffer);
    LL_DMA_SetDataLength(DMAx, Stream, length);
    LL_DMA_ClearFlag_TC4(DMAx);
    LL_DMA_ClearFlag_TE4(DMAx);

    /* Крок 3: Запускаємо передачу */
    LL_SPI_EnableDMAReq_TX(SPIx);
    LL_DMA_EnableStream(DMAx, Stream);
    LL_SPI_Enable(SPIx);

    /* Крок 4: Очікуємо вивантаження пам'яті контролером DMA */
    while (!LL_DMA_IsActiveFlag_TC4(DMAx)) {
        if (LL_DMA_IsActiveFlag_TE4(DMAx)) {
            /* Обробка апаратної помилки шини DMA */
            LL_DMA_DisableStream(DMAx, Stream);
            LL_SPI_DisableDMAReq_TX(SPIx);
            spi_cs_deassert(SPIx);
            return false;
        }
    }

    /* Крок 5: Зупиняємо запити DMA */
    LL_DMA_DisableStream(DMAx, Stream);
    LL_SPI_DisableDMAReq_TX(SPIx);

    /* Крок 6: Безпечно знімаємо CS після звільнення зсувного регістра */
    spi_cs_deassert(SPIx);
    return true;
}
```

```cpp
#include <cstdint>
#include <span>
#include <concepts>
#include "stm32f4xx_ll_spi.h"
#include "stm32f4xx_ll_dma.h"
#include "stm32f4xx_ll_gpio.h"

// Концепт для апаратної конфігурації лінії CS
struct GpioPin {
    GPIO_TypeDef* port;
    uint32_t pin;
};

// RAII-клас керування транзакцією SPI з прецизійним контролем таймінгу CS
class SpiDmaSession {
public:
    // Конструктор: захоплює лінію CS та витримує інтервал t_CSS
    explicit SpiDmaSession(SPI_TypeDef* spi, GpioPin cs) noexcept
        : spi_(spi), cs_(cs), active_(true) {
        LL_GPIO_ResetOutputPin(cs_.port, cs_.pin);
        guard_delay(); // Забезпечуємо t_CSS перед першим тактовим імпульсом
    }

    // Заборона копіювання для запобігання подвійному підйому CS
    SpiDmaSession(const SpiDmaSession&) = delete;
    SpiDmaSession& operator=(const SpiDmaSession&) = delete;

    // Підтримка семантики переміщення
    SpiDmaSession(SpiDmaSession&& other) noexcept
        : spi_(other.spi_), cs_(other.cs_), active_(other.active_) {
        other.active_ = false;
    }

    SpiDmaSession& operator=(SpiDmaSession&& other) noexcept {
        if (this != &other) {
            if (active_) {
                finalize();
            }
            spi_ = other.spi_;
            cs_ = other.cs_;
            active_ = other.active_;
            other.active_ = false;
        }
        return *this;
    }

    // Передача блоку даних із використанням std::span
    [[nodiscard]] bool transmit(DMA_TypeDef* dma, uint32_t stream,
                                std::span<const uint8_t> data) noexcept {
        if (!active_ || data.empty()) {
            return false;
        }

        LL_DMA_DisableStream(dma, stream);
        LL_DMA_SetMemoryAddress(dma, stream, reinterpret_cast<uint32_t>(data.data()));
        LL_DMA_SetDataLength(dma, stream, static_cast<uint32_t>(data.size()));
        LL_DMA_ClearFlag_TC4(dma);
        LL_DMA_ClearFlag_TE4(dma);

        LL_SPI_EnableDMAReq_TX(spi_);
        LL_DMA_EnableStream(dma, stream);
        LL_SPI_Enable(spi_);

        // Очікування спустошення пам'яті контролером DMA
        while (!LL_DMA_IsActiveFlag_TC4(dma)) {
            if (LL_DMA_IsActiveFlag_TE4(dma)) {
                LL_DMA_DisableStream(dma, stream);
                LL_SPI_DisableDMAReq_TX(spi_);
                return false;
            }
        }

        LL_DMA_DisableStream(dma, stream);
        LL_SPI_DisableDMAReq_TX(spi_);
        return true;
    }

    // Деструктор: автоматично та безпечно деактивує CS при виході з області видимості
    ~SpiDmaSession() noexcept {
        if (active_) {
            finalize();
        }
    }

private:
    void finalize() noexcept {
        // 1. Очікуємо звільнення буфера даних
        while (!LL_SPI_IsActiveFlag_TXE(spi_)) {
        }

        // 2. Очікуємо закінчення фізичного тактування SCLK у зсувному регістрі
        while (LL_SPI_IsActiveFlag_BSY(spi_)) {
        }

        // 3. Витримуємо t_CSH
        guard_delay();

        // 4. Піднімаємо CS
        LL_GPIO_SetOutputPin(cs_.port, cs_.pin);

        // 5. Витримуємо паузу відновлення t_CS_HIGH
        guard_delay();
        active_ = false;
    }

    static void guard_delay() noexcept {
        __NOP(); __NOP(); __NOP(); __NOP();
        __NOP(); __NOP(); __NOP(); __NOP();
    }

    SPI_TypeDef* spi_{nullptr};
    GpioPin cs_{nullptr, 0};
    bool active_{false};
};
```
:::

### Вплив порогів DMA FIFO та пакетних передач (Burst Transfers)

У мікроконтролерах із просунутими контролерами DMA (STM32F4/F7/H7) кожен потік містить апаратний 4-слівний буфер FIFO (`DMA_SxFCR`):
* **Конфігурація порогів FIFO**: Якщо встановлено поріг заповнення FIFO `1/2` або `3/4`, контролер DMA ініціює пакетні перенесення по шині AHB (*Burst Transfers* по 4 або 8 слів).
* **Пастка залишку в FIFO**: Коли залишок даних у масиві RAM менший за поріг спрацьовування FIFO, контролер автоматично переходить у прямий режим (*Direct Mode*) для вивантаження останніх неповних байтів. Якщо на цьому етапі виникає затримка арбітражу системної шини через активність процесорного ядра, генерація прапорця `DMA_IT_TC` затримується на кілька десятків тактів ядра, штучно збільшуючи інтервал утримання CS після завершення передачі.
* **Запобігання затримкам**: Для критичних до латентності транзакцій малого обсягу (менше 16 байтів) рекомендується вимикати режим FIFO DMA (`DMA_SxFCR_DMDIS = 0`), використовуючи пряму передачу без проміжної буферизації.

### Мультиплексування кількох ведених пристроїв та дескрипторні черги

У складних вбудованих системах до однієї апаратної шини SPI підключають кілька різних ведених пристроїв (наприклад, Flash-пам'ять, 6-осьовий IMU та OLED-дисплей). Оскільки кожен ведений пристрій має власні часові обмеження `t[CSS]`, `t[CSH]` та `t[CS_HIGH]`, універсальний драйвер повинен параметризувати ці затримки:

1. **Структура дескриптора транзакції (*Transaction Descriptor*)**:
   Кожен запит на передачу містить покажчик на буфер даних, довжину, посилання на відповідний вивід GPIO CS, цільову полярність/фазу такту (CPOL/CPHA), робочу частоту шини, а також індивідуальні значення затримок `guard_setup_cycles` та `guard_hold_cycles`.
2. **Черга транзакцій FreeRTOS (*Transaction Queue*)**:
   Задачі надсилають дескриптори в загальну чергу `xQueueHandle`. Окрема задача-диспетчер послідовно витягує дескриптори, динамічно переналаштовує регістри блоку SPI під параметри конкретного веденого, активує відповідний GPIO CS, запускає потік DMA та контролює дотримання інтервалу відновлення `t[CS_HIGH]` перед переходом до наступного веденого в черзі.
3. **Запобігання конфліктам на спільній шині**:
   Завдяки централізованій черзі та автоматичному контролю затримок виключається ситуація, коли CS другого пристрою опускається раніше, ніж вихід MISO першого пристрою встиг повністю перейти у високоомний стан Hi-Z (`t[CHZ]`).

### Когерентність кешу даних (D-Cache) та модуль захисту пам'яті (MPU)

У високопродуктивних ядрах ARM Cortex-M7 (мікроконтролери серій STM32F7 та STM32H7) процесорний кеш даних L1 D-Cache працює за алгоритмом зворотного запису (*Write-Back*):
* **Проблема неактуальних даних**: Якщо масив передачі формується процесором у кешованій області SRAM, оновлені байти можуть залишатися в рядках кешу і не бути скинутими в фізичну пам'ять RAM на момент старту DMA. В результаті контролер DMA вичитає застарілі дані.
* **Очищення кешу перед передачею**: Перед опусканням CS та запуском DMA програма зобов'язана виконати операцію `SCB_CleanDCache_by_Addr((uint32_t*)tx_buffer, length)`.
* **Інвалідація кешу після прийому**: Для операцій читання після підйому CS перед обробкою прийнятих даних ядро повинно викликати `SCB_InvalidateDCache_by_Addr((uint32_t*)rx_buffer, length)`, щоб гарантувати зчитування свіжих байтів із RAM, а не застарілих значень із кешу.

### Протокол аварійного відновлення шини (Bus Error Recovery)

Якщо під час передачі блоку через DMA виникає апаратний збій шини (наприклад, переривання по прапорцю помилки передачі `TEIF` або помилка переповнення буфера `OVR`), драйвер зобов'язаний коректно завершити сесію без зависання периферії:

1. **Аварійна зупинка DMA**: Викликається `LL_DMA_DisableStream()`, щоб заблокувати подальші спроби невалідних транзакцій по внутрішній шині AHB/APB.
2. **Скидання запитів DMA периферії**: Вимикається біт `TXDMAEN` у регістрі `SPI_CR2`.
3. **Очищення вхідних буферів**: Читанням регістра даних `SPI_DR` та статусу `SPI_SR` скидаються можливі помилки переповнення `OVR` (*Overrun Error*).
4. **Примусовий підйом CS**: Лінія CS повертається у стан високого логічного рівня (`1`), перериваючи транзакцію на боці веденого.
5. **Витримка захисної міжкадрової паузи**: Виконується пауза тривалістю не менше `t[CS_HIGH_write] ≥ 100–200 нс` для повного скидання внутрішнього автомата станів веденого пристрою перед наступною спробою повторної передачі.

### Апаратні особливості та кремнієві помилки (Errata Sheet)

Під час реалізації алгоритму опитування прапорця `BSY` у різних сімействах мікроконтролерів слід враховувати задокументовані виробником апаратні нюанси:

#### 1. Тимчасовий скид BSY між байтами (STM32F1 / STM32F4 Errata)
У деяких ревізіях кремнію прапорець `BSY` може короткочасно (на 1 такт внутрішньої шини APB) скидатися в `0` між передачею сусідніх байтів, коли буфер даних спорожнів, а наступний байт завантажується зі зсувом у 1 такт.
Щоб уникнути помилкового виходу з циклу очікування, перевірку завжди слід будувати комплексно:

:::tabs
```c
/* Комплексна перевірка: буфер TXE повинен бути вільним І шина BSY повинна стати неактивною */
while (!LL_SPI_IsActiveFlag_TXE(SPIx) || LL_SPI_IsActiveFlag_BSY(SPIx)) {
    /* Очікування повного завершення передачі всіх байтів */
}
```
```cpp
// Комплексна перевірка: буфер TXE повинен бути вільним І шина BSY повинна стати неактивною
while (!LL_SPI_IsActiveFlag_TXE(spi_) || LL_SPI_IsActiveFlag_BSY(spi_)) {
    // Очікування повного завершення передачі всіх байтів
}
```
:::

#### 2. Робота в циклічному режимі DMA (Circular Mode)
Якщо DMA налаштовано на безперервне оновлення буфера (наприклад, циклічна передача кадру на дисплей через SPI), лінія CS не повинна підніматися між кадрами взагалі, або повинна короткочасно стробуватися по перериванню `DMA_IT_TC` виключно за умови синхронізації з кадровим імпульсом TE (*Tearing Effect*).

#### 3. Асиметричний подвійний буфер (DMA Double-Buffer Mode)
При використанні подвійної буферизації пам'яті перемикання цільового масиву відбувається без зупинки генератора SCLK. У такому режимі сигнал CS залишається постійно активним на весь час роботи потоку, забезпечуючи максимальну пропускну здатність без накладних витрат на інтервали відновлення.

### Налаштування логічного аналізатора для пошуку прихованих помилок CS

Для апаратної діагностики часових збоїв лінії CS за допомогою логічного аналізатора (Saleae Logic, DSLogic або Sigrok/PulseView) налаштовують такі умови захоплення:

1. **Частота дискретизації (*Sample Rate*)**:
   Частота дискретизації аналізатора повинна перевищувати максимальну частоту такту SCLK щонайменше у 4–8 разів. Для шини SPI 25 МГц потрібен аналізатор із частотою захоплення не менше 100–200 Мвиб/с.
2. **Складний тригер із кваліфікацією тривалості імпульсу (*Pulse Width Trigger*)**:
   Щоб виявити передчасний обрив CS або паразитні глітчі тривалістю менше 10 нс, тригер налаштовують на канал CS в умові: `Negative Pulse Width < T[frame_expected]`. Це дозволяє автоматично зупиняти запис саме в момент, коли апаратний блок передчасно підняв CS посеред транзакції.
3. **Маркери вимірювання затримок**:
   У програмі аналізу встановлюють два часових маркери: перший — на спадний перепад CS, другий — на перший фронт SCLK. Якщо різниця `T2 - T1` менша за паспортне значення `t[CSS]`, драйвер вимагає вставки додаткових затримок у програмному коді.
