# 🧮 Розрахунок накладних витрат і часового бюджету шин I2C та SPI

Оптимізація обміну з цифровими давачами вимагає точного математичного балансу між частотою оновлення вибірок (ODR, *Output Data Rate*), тривалістю серіалізації на фізичному рівні інтерфейсу та накладними витратами протоколу. Коли мікроконтролер опитує багатоосьовий інерціальний модуль (акселерометр, гіроскоп або барометр), пропускна здатність послідовної шини стає головним системним обмеженням.

Математичний аналіз часового бюджету дозволяє кількісно порівняти побайтовий та пакетний доступ, вивести аналітичну залежність корисної ефективності від довжини пакета та розрахувати теоретичну стелю частоти опитування для шин [I2C](topic:communications/i2c-bus) і [SPI](topic:communications/spi-bus).

---

### Аналітична часова модель протоколу I2C

У протоколі I2C кожна передача байта супроводжується дев'ятим тактовим імпульсом для підтвердження (ACK або NACK), а межі транзакцій визначаються апаратними станами [START, REPEATED START і STOP](topic:communications/start-stop-ack).

Нехай `T_clk` — період тактового сигналу SCL, що визначається базовою частотою шини `f_scl`:

```
T_clk = 1 / f_scl
```

Для стандартних швидкостей I2C маємо:
- Standard Mode (100 кГц): `T_clk = 10 мкс`;
- Fast Mode (400 кГц): `T_clk = 2.5 мкс`;
- Fast Mode Plus (1 МГц): `T_clk = 1.0 мкс`.

Тривалість формування умов START, REPEATED START (Sr) і STOP на шині регламентується специфікацією I2C. Для спрощення дискретного розрахунку в тактах шини кожен стан START і STOP еквівалентний мінімум одному періоду тактової частоти `T_clk` (з урахуванням часу утримання шини `t_HD;STA` та часу встановлення `t_SU;STO`).

#### 1. Одиночне побайтове зчитування (Single-Byte Read)

Щоб прочитати один байт із заданого внутрішнього регістра давача, ведучий виконує комбіновану транзакцію: фазу запису адреси регістра та фазу зчитування даних.

Структура транзакції складається з таких обов'язкових полів:
1. Стан START: `1 · T_clk`;
2. Байт адреси пристрою з бітом запису (Slave Addr + W) + ACK: `9 · T_clk`;
3. Байт адреси цільового регістра (Register Address) + ACK: `9 · T_clk`;
4. Стан REPEATED START (Sr): `1 · T_clk`;
5. Байт адреси пристрою з бітом читання (Slave Addr + R) + ACK: `9 · T_clk`;
6. Байт даних від давача (Data Byte) + NACK від ведучого: `9 · T_clk`;
7. Стан STOP: `1 · T_clk`.

Загальний час зчитування одного байта `T_single_1` становить:

```
T_single_1
= (1 + 9 + 9 + 1 + 9 + 9 + 1) · T_clk       [підсумовування всіх фаз транзакції]
= 39 · T_clk                                 [загальна тривалість одиночного читання]
```

Якщо ведучому необхідно зчитати блок із `N` послідовних регістрів (наприклад, 6 байтів вимірів для 3-осьового акселерометра) за допомогою `N` окремих одиночних транзакцій, загальний час на шині дорівнює:

```
T_single(N)
= N · T_single_1                            [сума N незалежних транзакцій]
= N · 39 · T_clk                            [множення часу однієї транзакції на кількість байтів]
```

Для вимірювального пакета з `N = 6` байтів на шині I2C:

```
T_single(6)
= 6 · 39 · T_clk                            [підстановка N = 6]
= 234 · T_clk                               [сумарна кількість тактів]
```

За частоти `f_scl = 400 кГц` (`T_clk = 2.5 мкс`):

```
T_single(6)
= 234 · 2.5 мкс                             [підстановка тривалості такту Fast Mode]
= 585.0 мкс                                 [чистий час на шині без урахування програмних пауз]
```

#### 2. Пакетне зчитування (Burst Read)

У режимі пакетного читання фаза адресації виконується лише один раз на початку. Після отримання стартового номера регістра внутрішній апаратний лічильник давача автоматично інкрементує покажчик адреси після кожного підтвердженого байта.

Структура єдиної Burst-транзакції для `N` байтів містить:
1. Стан START: `1 · T_clk`;
2. Байт адреси пристрою (Slave Addr + W) + ACK: `9 · T_clk`;
3. Початкова адреса регістра (Start Reg Address) + ACK: `9 · T_clk`;
4. Стан REPEATED START (Sr): `1 · T_clk`;
5. Байт адреси пристрою (Slave Addr + R) + ACK: `9 · T_clk`;
6. `N` байтів даних: перші `N - 1` байтів супроводжуються ACK від ведучого, останній `N`-й байт — NACK: `N · 9 · T_clk`;
7. Стан STOP: `1 · T_clk`.

Загальний час пакетного зчитування `T_burst(N)` описується рівнянням:

```
T_burst(N)
= (1 + 9 + 9 + 1 + 9 + 1) · T_clk + 9 · N · T_clk   [виділення постійного префікса і потоку даних]
= (30 + 9 · N) · T_clk                               [підсумкова формула часу пакетної транзакції]
```

Для блока вимірів `N = 6` байтів:

```
T_burst(6)
= (30 + 9 · 6) · T_clk                      [підстановка N = 6]
= (30 + 54) · T_clk                         [обчислення тривалості корисної фази]
= 84 · T_clk                                [сумарна кількість тактів I2C]
```

За частоти `f_scl = 400 кГц` (`T_clk = 2.5 мкс`):

```
T_burst(6)
= 84 · 2.5 мкс                              [підстановка періоду такту]
= 210.0 мкс                                 [час пакетного зчитування на шині]
```

Порівняння показує абсолютний виграш у часі передачі:

```
ΔT = T_single(6) - T_burst(6)
= 585.0 мкс - 210.0 мкс                      [різниця тривалості на фізичному рівні]
= 375.0 мкс                                 [чисте скорочення часу зайнятості шини]
```

Коефіцієнт прискорення обміну `K_speedup` на шині I2C становить:

```
K_speedup(N)
= T_single(N) / T_burst(N)
= (39 · N) / (30 + 9 · N)                   [відношення тривалостей побайтового і пакетного режимів]
```

Для різних розмірів пакетів отримуємо:
- Для `N = 6` байтів (акселерометр XYZ): `K_speedup = (39 · 6) / (30 + 54) = 234 / 84 ≈ 2.785` (прискорення у 2.79 раза);
- Для `N = 12` байтів (акселерометр + гіроскоп): `K_speedup = (39 · 12) / (30 + 108) = 468 / 138 ≈ 3.391` (прискорення у 3.39 раза);
- Для `N = 14` байтів (акселерометр + гіроскоп + температура): `K_speedup = (39 · 14) / (30 + 126) = 546 / 156 = 3.500` (прискорення рівно у 3.50 раза).

### Вплив розтягування такту (Clock Stretching)

Деякі цифрові мікросхеми (зокрема барометри, датчики вологості та старіші контролери з програмним стеком I2C) утримують лінію SCL на низькому рівні після отримання адреси або байта даних для завершення внутрішнього аналого-цифрового перетворення або вибірки з енергонезалежної пам'яті.

Нехай `t_stretch` — додатковий сумарний час розтягування такту слейвом протягом транзакції:

```
T_total_i2c = T_burst(N) + t_stretch
```

Якщо слейв додає паузу розтягування перед кожним байтом вибірки `t_byte_wait`:

```
t_stretch = N · t_byte_wait
```

За наявності `t_byte_wait = 15 мкс` на кожен байт для `N = 6` на частоті 400 кГц:

```
t_stretch = 6 · 15 мкс = 90 мкс
T_total_i2c = 210 мкс + 90 мкс = 300 мкс
```

Це знижує результуючу пропускну здатність шини, але все одно перевершує побайтове зчитування (яке при аналогічному розтягуванні займало б `585 + 90 = 675 мкс`).

### Коефіцієнт корисної дії шини (Payload Efficiency)

Корисна ефективність шини `η` визначається як відношення часу передачі корисних інформаційних бітів даних до повного часу зайнятості фізичної лінії зв'язку.

У кожному байті корисними є 8 бітів інформації вимірів. Загальна кількість переданих інформаційних бітів дорівнює `8 · N`. Кожен біт за ідеальних умов займає тривалість одного такту `T_clk`.

Формула коефіцієнта корисної дії `η`:

```
η = (8 · N · T_clk) / T_total
```

#### Ефективність побайтового зчитування I2C

Для одиночних транзакцій корисна дія не залежить від кількості байтів, оскільки кожна одиниця даних несе фіксований службовий оверхед:

```
η_single
= (8 · T_clk) / (39 · T_clk)                [відношення 8 бітів даних до 39 тактів транзакції]
= 8 / 39
≈ 0.2051                                    [20.51% корисної пропускної здатності]
```

Майже 79.5% часу шини витрачається на адресацію, старти, стопи та біти підтвердження.

#### Ефективність пакетного зчитування I2C

Для Burst-режиму коефіцієнт корисної дії є зростаючою функцією від розміру блока `N`:

```
η_burst(N)
= (8 · N) / (30 + 9 · N)                    [підстановка T_burst у формулу ефективності]
```

Знайдемо асимптотичну межу ефективності при нескінченно великому пакеті (`N → ∞`):

```
lim_{N → ∞} η_burst(N)
= lim_{N → ∞} (8 · N) / (30 + 9 · N)        [граничний перехід при зростанні довжини пакета]
= 8 / 9
≈ 0.8889                                    [теоретична межа 88.89% для шини I2C]
```

Верхня межа 88.89% обумовлена обов'язковим бітом ACK/NACK (9-й такт) на кожен переданий байт.

Розрахуємо значення ефективності для типових сценаріїв зчитування давачів:

```
η_burst(1)  = (8 · 1) / (30 + 9)   = 8 / 39   ≈ 20.51%
η_burst(2)  = (8 · 2) / (30 + 18)  = 16 / 48  ≈ 33.33%
η_burst(6)  = (8 · 6) / (30 + 54)  = 48 / 84  ≈ 57.14%
η_burst(12) = (8 · 12) / (30 + 108) = 96 / 138 ≈ 69.57%
η_burst(14) = (8 · 14) / (30 + 126) = 112 / 156 ≈ 71.79%
η_burst(32) = (8 · 32) / (30 + 288) = 256 / 318 ≈ 80.50%
η_burst(64) = (8 · 64) / (30 + 576) = 512 / 606 ≈ 84.49%
```

Перехід від одиночного опитування 14 регістрів до одного Burst-пакета піднімає корисне використання шини з 20.51% до 71.79% — зростання ефективності у 3.5 раза.

### Аналітична часова модель протоколу SPI

Шина SPI є повнодуплексним інтерфейсом без протокольних бітів підтвердження ACK/NACK. Межі транзакцій задаються апаратним сигналом вибору кристала Chip Select (`CS`).

Нехай `T_sck` — період тактового сигналу шини SPI:

```
T_sck = 1 / f_sck
```

Типові частоти SPI для сучасних цифрових давачів становлять від 1 МГц до 20 МГц:
- `f_sck = 1 МГц`: `T_sck = 1000 нс`;
- `f_sck = 10 МГц`: `T_sck = 100 нс`;
- `f_sck = 20 МГц`: `T_sck = 50 нс`.

Часовий бюджет транзакції SPI включає такі складові:
1. `t_lead` (час випередження): інтервал від спаду `CS` (активація слейва) до першого тактового фронту SCK;
2. `T_data`: час передачі байтів команди, адреси та даних по лініях MOSI/MISO;
3. `t_lag` (час утримання): інтервал від останнього тактового фронту SCK до наростання `CS`;
4. `t_high` (час деактивації CS між транзакціями): мінімальна пауза високого рівня `CS`, необхідна для скидання внутрішнього автомата слейва.

Згідно з даташитами сучасних MEMS-давачів (наприклад, ST LSM6DSO або Bosch BMI270):
- `t_lead ≥ 50 нс`;
- `t_lag ≥ 50 нс`;
- `t_high ≥ 100 нс`.

Сумарні накладні витрати на перемикання лінії вибору кристала позначимо як `T_cs_overhead`:

```
T_cs_overhead = t_lead + t_lag + t_high
```

Для типових значень:

```
T_cs_overhead
= 50 нс + 50 нс + 100 нс                    [підстановка параметрів CS]
= 200 нс                                    [накладний час перемикання кристала]
```

#### 1. Одиночне зчитування по байтах у SPI

Для зчитування одного байта ведучий опускає `CS`, передає 1 байт адреси/команди (8 тактів), зчитує 1 байт даних (8 тактів) і піднімає `CS`.

Тривалість одиночної транзакції `T_single_spi_1`:

```
T_single_spi_1
= T_cs_overhead + (8 + 8) · T_sck           [час перемикання CS + 16 тактів передачі]
= T_cs_overhead + 16 · T_sck
```

Для зчитування `N` байтів через `N` окремих транзакцій:

```
T_single_spi(N)
= N · (T_cs_overhead + 16 · T_sck)          [сумарний час N послідовних транзакцій]
```

Обчислимо час для `N = 14` байтів при частоті `f_sck = 10 МГц` (`T_sck = 100 нс`, `T_cs_overhead = 200 нс`):

```
T_single_spi_1
= 200 нс + 16 · 100 нс                      [час однієї транзакції]
= 200 нс + 1600 нс
= 1.80 мкс

T_single_spi(14)
= 14 · 1.80 мкс                             [множення на 14 транзакцій]
= 25.20 мкс                                 [загальний час без урахування затримок програмного коду]
```

#### 2. Пакетне зчитування в SPI (Burst Read)

У режимі пакетного читання `CS` утримується на низькому рівні протягом усього масиву. Ведучий передає лише 1 початковий байт команди з адресою, після чого тактує шину для отримання `N` байтів даних:

```
T_burst_spi(N)
= T_cs_overhead + 8 · (1 + N) · T_sck       [один байт адреси + N байтів вимірів]
```

Для деяких давачів (наприклад, Bosch BMI270 у режимі SPI) після байта адреси перед даними слейву потрібен 1 фіктивний байт-заглушка (Dummy Byte, 8 тактів) для вибірки з внутрішньої пам'яті:

```
T_burst_spi_dummy(N)
= T_cs_overhead + 8 · (1 + 1 + N) · T_sck   [адреса + dummy-байт + N байтів вимірів]
= T_cs_overhead + 8 · (2 + N) · T_sck
```

Розрахуємо тривалість стандартного Burst-зчитування для `N = 14` байтів при `f_sck = 10 МГц`:

```
T_burst_spi(14)
= 200 нс + 8 · (1 + 14) · 100 нс            [підстановка параметрів]
= 200 нс + 8 · 15 · 100 нс
= 200 нс + 12000 нс
= 12.20 мкс                                 [тривалість пакетної передачі]
```

Коефіцієнт прискорення на шині SPI:

```
K_speedup_spi(14)
= T_single_spi(14) / T_burst_spi(14)
= 25.20 мкс / 12.20 мкс                     [відношення тривалостей]
≈ 2.066                                     [прискорення у 2.07 раза на фізичному рівні]
```

#### Ефективність передачі по шині SPI

Корисна ефективність шини SPI при `N` байтах вимірів:

```
η_spi(N)
= (8 · N · T_sck) / T_burst_spi(N)                              [відношення корисних бітів до загального часу]
= (8 · N · T_sck) / (T_cs_overhead + 8 · (1 + N) · T_sck)       [підстановка аналітичної формули T_burst_spi]
```

За частоти `f_sck = 10 МГц` (`T_sck = 100 нс`, `T_cs_overhead = 200 нс = 2 · T_sck`):

```
η_spi(N)
= (8 · N · T_sck) / (2 · T_sck + 8 · T_sck + 8 · N · T_sck)    [підстановка T_cs_overhead = 2 · T_sck]
= (8 · N) / (10 + 8 · N)                                       [скорочення на спільний множник T_sck]
```

Обчислимо значення для різних розмірів блоків:
- Для `N = 1` байт: `η_spi(1) = 8 / 18 ≈ 44.44%`;
- Для `N = 6` байтів: `η_spi(6) = 48 / 58 ≈ 82.76%`;
- Для `N = 14` байтів: `η_spi(14) = 112 / 122 ≈ 91.80%`;
- Для `N = 64` байти: `η_spi(64) = 512 / 522 ≈ 98.08%`.

У шині SPI завдяки відсутності 9-го біта ACK асимптотична межа ефективності прямує до 100%:

```
lim_{N → ∞} η_spi(N) = 1.000 (100%)
```

### Конкуренція на спільній шині (Multi-Sensor Bus Contention)

У реальних вбудованих системах до однієї шини часто підключаються кілька різних давачів: IMU (14 байтів при ODR = 1 кГц), магнітометр (6 байтів при ODR = 100 Гц) та барометр (6 байтів при ODR = 50 Гц).

Сумарне завантаження шини `U_bus` розраховується як суперпозиція часових витрат усіх пристроїв за одну секунду:

```
U_bus = Σ (ODR_i · T_burst_i)
```

Обчислимо завантаження для шини I2C Fast Mode (400 кГц, `T_clk = 2.5 мкс`):
1. **IMU (LSM6DSO)**: `N = 14` байтів, `ODR = 1000 Гц`.
   `T_imu = (30 + 9 · 14) · 2.5 мкс = 156 · 2.5 мкс = 390.0 мкс`.
   Час за 1 с: `1000 · 390.0 мкс = 390.0 мс` (39.00% завантаження шини).
2. **Магнітометр (LIS3MDL)**: `N = 6` байтів, `ODR = 100 Гц`.
   `T_mag = (30 + 9 · 6) · 2.5 мкс = 84 · 2.5 мкс = 210.0 мкс`.
   Час за 1 с: `100 · 210.0 мкс = 21.0 мс` (2.10% завантаження шини).
3. **Барометр (BMP388)**: `N = 6` байтів, `ODR = 50 Гц`.
   `T_baro = (30 + 9 · 6) · 2.5 мкс = 210.0 мкс`.
   Час за 1 с: `50 · 210.0 мкс = 10.5 мс` (1.05% завантаження шини).

Сумарне навантаження шини I2C:

```
U_bus_i2c
= 39.00% + 2.10% + 1.05%                    [підсумовування внеску трьох давачів]
= 42.15%                                    [загальна зайнятість шини I2C]
```

Якщо ж спробувати опитувати ті самі давачі побайтово:
- `T_imu_single = 14 · 39 · 2.5 мкс = 1365.0 мкс` -> `136.5%`;
- `T_mag_single = 6 · 39 · 2.5 мкс = 585.0 мкс` -> `5.85%`;
- `T_baro_single = 6 · 39 · 2.5 мкс = 585.0 мкс` -> `2.93%`.
- Сума: `145.28%` -> **шина колапсує**, виникають пропуски кадрів, переповнення черг і збої навігаційного фільтра.

Пакетне зчитування повертає завантаження шини в безпечну зону (42.15%), забезпечуючи запас пропускної здатності для транзакцій запису калібрувальних коефіцієнтів та обробки колізій.

### Асинхронний дрейф тактових генераторів та джиттер вибірки

Внутрішні тактові генератори цифрових MEMS-давачів реалізуються у вигляді інтегрованих RC-осциляторів. На відміну від кварцових резонаторів мікроконтролера, точність таких RC-генераторів варіюється в межах `±1.5% ... ±2.0%` залежно від температури кристала та напруги живлення.

Нехай номінальний період вибірки давача становить `T_nom = 1.0 мс` (1000 Гц), а похибка внутрішнього генератора дорівнює `δ = ±2.0%`. Фактичний інтервал між послідовними імпульсами лінії готовності `DRDY` змінюється в діапазоні:

```
T_drdy_min = T_nom · (1 - 0.02) = 980.0 мкс
T_drdy_max = T_nom · (1 + 0.02) = 1020.0 мкс
```

Якщо мікроконтролер опитує давач не за апаратним сигналом `DRDY`, а за власним періодичним таймером із періодом `T_timer = 1000.0 мкс`:
1. У випадку `T_drdy < T_timer` (давач поспішає на 20 мкс кожного періоду): за 50 періодів давач згенерує на одну вибірку більше. Без пакетного вичитування з буфера FIFO один кадр буде безповоротно перезаписаний або виникне подвійне зчитування застарілих даних.
2. У випадку `T_drdy > T_timer` (давач відстає): мікроконтролер виконає читання до завершення інтегрування сигналу аналоговим трактом, отримавши попереднє значення або частково оновлений результат.

Математична умова відсутності колізій при роботі з сигналом `DRDY`:

```
T_burst_transfer + T_irq_latency < T_drdy_min
```

Для I2C Fast Mode (`T_burst = 390 мкс`) та максимальної затримки переривання `T_irq_latency = 15 мкс`:

```
390 мкс + 15 мкс = 405 мкс < 980 мкс
```

Запас часового вікна до наступного такту становить `575 мкс` (58.7% запасу надійності), що гарантує 100% захист від розсинхронізації навіть за екстремальних температурних градієнтів кристала.

### Гранична частота дискретизації давача (ODR Ceiling)

Частота оновлення вибірок `ODR` (*Output Data Rate*) обмежена періодом опитування `T_sample`, який повинен бути строго більшим за сумарний час передачі даних по шині `T_bus`, час програмної обробки мікроконтролером `T_cpu` та захисний часовий запас `T_margin`:

```
T_sample ≥ T_bus + T_cpu + T_margin
```

Гранична теоретична частота опитування `ODR_max`:

```
ODR_max = 1 / (T_bus + T_cpu + T_margin)
```

Якщо використовується прямий доступ до пам'яті (DMA), процесорний час серіалізації зводиться до нуля (`T_cpu_transfer = 0`), а обмін обмежується виключно фізичною тривалістю передачі на шині:

```
ODR_bus_limit = 1 / T_bus
```

### Розрахунок енергетичної вигоди пакетного доступу

Зниження часу активності шини безпосередньо впливає на споживання енергії автономними пристроями з батарейним живленням.

Нехай:
- `I_active` — динамічний струм споживання мікроконтролера та приймача під час активної передачі по шині (наприклад, 12.0 мА при роботі драйверів I2C/SPI);
- `I_sleep` — струм мікроконтролера в режимі глибокого сну (Deep Sleep / Stop Mode), наприклад, 15.0 мкА (`0.015 мА`);
- `V_dd` — напруга живлення системи (3.3 В);
- `f_odr` — частота опитування давача (наприклад, `100 Гц`, період `T_p = 10 мс = 10000 мкс`).

Середній струм споживання підсистеми збору даних `I_avg`:

```
I_avg = (T_bus / T_p) · I_active + (1 - T_bus / T_p) · I_sleep
```

Порівняємо побайтовий та пакетний режими на I2C 400 кГц для `N = 14` байтів:
- Побайтово: `T_bus = 1365.0 мкс`;
- Пакетом: `T_bus = 390.0 мкс`.

#### Середній струм при побайтовому читанні:

```
I_avg_single
= (1365.0 / 10000) · 12.0 мА + (1 - 1365.0 / 10000) · 0.015 мА     [підстановка параметрів активності]
= 0.1365 · 12.0 мА + 0.8635 · 0.015 мА                             [обчислення часток активності та сну]
= 1.638 мА + 0.013 мА                                             [зважений струм фаз]
= 1.651 мА                                                        [середньозважений струм споживання]
```

#### Середній струм при пакетному читанні:

```
I_avg_burst
= (390.0 / 10000) · 12.0 мА + (1 - 390.0 / 10000) · 0.015 мА      [підстановка параметрів пакетного читання]
= 0.0390 · 12.0 мА + 0.9610 · 0.015 мА                             [обчислення часток для 3.9% активності]
= 0.468 мА + 0.014 мА                                             [зважений струм фаз]
= 0.482 мА                                                        [середньозважений струм у режимі Burst]
```

#### Коефіцієнт енергетичної оптимізації `K_power`:

```
K_power
= I_avg_single / I_avg_burst                                      [відношення середніх струмів]
= 1.651 мА / 0.482 мА                                             [підстановка розрахованих значень]
≈ 3.425                                                           [кратність зниження енергоспоживання]
```

Застосування Burst Read на частоті 100 Гц зменшує енергоспоживання цифрового вузла збору вимірів у 3.42 раза, дозволяючи продовжити час автономної роботи батареї на одному заряді у понад три рази.
