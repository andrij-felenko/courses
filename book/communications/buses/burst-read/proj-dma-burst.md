# ⚙️ Пакетне зчитування вимірів з IMU через DMA

Опитування високошвидкісних цифрових інерціальних модулів (IMU) на частотах від 1 кГц до 6.6 кГц у системах стабілізації дронів, робототехніці та навігації створює критичне навантаження на процесорне ядро мікроконтролера. Якщо зчитувати кожен байт через програмні цикли очікування (*polling*) або обробляти переривання на кожен прийнятий байт шини [SPI](book:communications/spi-bus) чи [I2C](book:communications/i2c-bus), центральний процесор витрачає від 30% до 50% власної тактової потужності виключно на обслуговування перемикання контексту переривань і порожнє очікування готовності регістрів.

Прямий доступ до пам'яті (DMA, *Direct Memory Access*) дозволяє повністю апаратизувати процес зчитування. Процесор ініціалізує конфігурацію каналу один раз, після чого апаратний контролер DMA самостійно забирає байт за байтом із приймального буфера інтерфейсу SPI/I2C і записує їх у масив оперативної пам'яті (SRAM) за лічені мікросекунди без жодного такту затримки процесорного ядра.

---

### Архітектура конвеєра збору даних

Апаратний конвеєр збору вимірів об'єднує зовнішній давач (наприклад, 6-осьовий IMU STMicroelectronics LSM6DSO або Bosch BMI270), апаратний блок шинного інтерфейсу, контролер DMA та подвійний кільцевий буфер у системній пам'яті.

Послідовність роботи конвеєра:
1. **Генерація вибірки давачем**: аналого-цифровий перетворювач IMU завершує інтегрування 3 осей акселерометра, 3 осей гіроскопа та датчика температури. Результат фіксується у внутрішніх вихідних регістрах.
2. **Апаратний строб готовності**: давач піднімає зовнішню лінію переривання `DRDY` (Data Ready), підключену до виводу GPIO мікроконтролера.
3. **Запуск транзакції**: зовнішнє переривання або таймер активує апаратну передачу кадру. Ведучий SPI виставляє низький рівень на лінії вибору кристала `CS` і передає початковий байт адреси з бітом читання та прапорцем автоінкременту (наприклад, `0x80 | 0x20` або `0xC0 | 0x28`).
4. **Апаратне перекачування DMA**: контролер DMA тактує шину (для SPI) або вичитує приймальний регістр `RXFIFO` і автоматично розміщує 14 байтів у пам'яті SRAM. Приймальний канал DMA налаштовується з фіксованою адресою периферії (`PINC = 0`) та автоінкрементом адреси пам'яті (`MINC = 1`).
5. **Сигнал завершення (Transfer Complete)**: після отримання останнього байта лічильник `NDTR` досягає нуля. DMA генерує єдине переривання `TC_ISR`, піднімає лінію `CS` і передає готовий покажчик на кадр у задачу навігаційного фільтра або алгоритму орієнтації (AHRS).
6. **Обробка в режимі подвійної буферизації (Ping-Pong Buffering)**: поки алгоритм орієнтації читає дані з буфера A, наступний запуск DMA заповнює паралельний буфер B. Це виключає стан гонитви (*race condition*) та блокування пам'яті.

---

### Апаратна конфігурація регістрів контролера DMA

Для розуміння того, як контролер DMA виконує транзакцію без втручання процесора, розглянемо конфігурацію його внутрішніх регістрів на рівні апаратного ядра ARM Cortex-M:

1. **Регістр адреси периферії (`DMA_SxPAR`)**: сюди записується фізична адреса регістра даних інтерфейсу SPI (`&(SPI1->DR)` або `&(SPI1->RXDR)`).
2. **Регістр адреси пам'яті (`DMA_SxM0AR`)**: вказує на початок цільового масиву в оперативній пам'яті SRAM, куди записуватимуться прийняті байти.
3. **Регістр лічильника елементів (`DMA_SxNDTR`)**: завантажується кількістю байтів у пакеті (`NDTR = 15`). При кожному перенесенні байта внутрішній апаратний віднімач зменшує це число на одиницю. Коли лічильник досягає нуля, транзакція автоматично завершується.
4. **Регістр управління потоком (`DMA_SxCR`)**:
   - `DIR[1:0] = 00`: напрямок передачі "Периферія в пам'ять" (*Peripheral-to-Memory*);
   - `MINC = 1`: дозволити автоінкремент адреси в пам'яті після кожного байта;
   - `PINC = 0`: заборонити інкремент адреси периферії (адреса регістра SPI фіксована);
   - `PSIZE[1:0] = 00` та `MSIZE[1:0] = 00`: 8-бітний розмір порції даних (Byte);
   - `PL[1:0] = 11`: найвищий пріоритет каналу (*Very High Priority*);
   - `TCIE = 1`: дозволити генерацію переривання після завершення передачі повного блоку.

### Реалізація на мікроконтролерах STM32 (SPI + DMA)

У мікроконтролерах родини STM32 (Cortex-M4/M7) периферійний модуль SPI поєднується з контролером DMA (наприклад, DMA1/DMA2 або BDMA/GPDMA). Для повнодуплексного зчитування через SPI необхідно налаштувати два потоки DMA: потік передачі TX (який шле масив тактових заглушок або стартову адресу) і потік прийому RX (який забирає байти вимірів з регістра `SPI_DR` або `SPI_RXDR`).

#### Структура кадру вимірів IMU

Типовий кадр 6-осьового давача LSM6DSO складається з 14 байтів:
- `0x20`: статус готовності (`STATUS_REG`);
- `0x22..0x27`: кутова швидкість осі X, Y, Z (3 × 16-бітні слова);
- `0x28..0x2D`: лінійне прискорення осі X, Y, Z (3 × 16-бітні слова);
- `0x30..0x31`: температура кристала (16-бітне слово).

extern SPI_HandleTypeDef IMU_SPI_HANDLE;

static uint8_t g_spi_tx_buf[IMU_FRAME_SIZE] __attribute__((aligned(4)));
static uint8_t g_spi_rx_buf[2][IMU_FRAME_SIZE] __attribute__((aligned(4)));

    uint8_t rx_idx = g_active_rx_buf_idx;
    HAL_SPI_TransmitReceive_DMA(&IMU_SPI_HANDLE, g_spi_tx_buf, g_spi_rx_buf[rx_idx], IMU_FRAME_SIZE);

void HAL_SPI_TxRxCpltCallback(SPI_HandleTypeDef *hspi) {
    if (hspi->Instance == SPI1) {
        HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_SET);
        g_active_rx_buf_idx ^= 1;
        __DMB(); /* Апаратний бар'єр пам'яті для синхронізації ядер */
        g_imu_data_ready_flag = true;
    }
}

    static constexpr uint8_t kBurstCmd = 0x80 | 0x20;

        HAL_GPIO_WritePin(cs_port_, cs_pin_, GPIO_PIN_SET);
        active_buf_idx_.store(active_buf_idx_.load(std::memory_order_relaxed) ^ 1, std::memory_order_release);
        has_new_data_.store(true, std::memory_order_release);

private:
    SPI_HandleTypeDef& spi_;
    GPIO_TypeDef*      cs_port_;
    uint16_t           cs_pin_;
    alignas(4) std::array<uint8_t, kFrameSize> tx_buf_{};
    alignas(4) std::array<std::array<uint8_t, kFrameSize>, 2> rx_double_buf_{};
    std::atomic<uint8_t> active_buf_idx_{0};
    std::atomic<bool>    has_new_data_{false};
};

} // namespace sensor

### Управління кеш-пам'яттю (Cache Coherency на Cortex-M7)

На високопродуктивних мікроконтролерах із кешем даних (Cortex-M7: STM32F7, STM32H7) контролер DMA пише дані безпосередньо в оперативну пам'ять AXI SRAM, оминаючи L1 D-Cache процесора. Якщо процесор спробує прочитати змінні з буфера без попередньої інвалідації кешу, він отримає застарілі значення з кеш-ліній.

Правила роботи з DMA і кешем:
1. **Вирівнювання буфера**: розмір буфера та його адреса мають бути вирівняні за розміром рядка кешу (32 байти для Cortex-M7): `__attribute__((aligned(32)))`.
2. **Інвалідація перед читанням**: перед розпакуванням кадру процесор повинен викликати інструкцію інвалідації рядків пам'яті: `SCB_InvalidateDCache_by_Addr((uint32_t*)&g_spi_rx_buf[ready_idx][0], 32);`.
3. **Очищення перед передачею TX**: якщо буфер передачі модифікується процесором, перед стартом DMA викликається скидання кешу в пам'ять: `SCB_CleanDCache_by_Addr((uint32_t*)&g_spi_tx_buf[0], 32);`.
4. **Використання MPU**: альтернативний надійний підхід — налаштування апаратного захисту пам'яті MPU, що оголошує секцію пам'яті DMA-буферів як некашовану (*Device/Non-cacheable SRAM*).

class EspImuDma {

    static constexpr size_t kTotalBytes   = 1 + kPayloadBytes;

    EspImuDma(spi_host_device_t host, int cs_pin, int drdy_pin)

    ~EspImuDma() {
        if (spi_dev_) {
            spi_bus_remove_device(spi_dev_);
        }
        if (tx_buf_) heap_caps_free(tx_buf_);
        if (rx_buf_) heap_caps_free(rx_buf_);

        devcfg.clock_speed_hz = 10 * 1000 * 1000;
        devcfg.mode = 3;

        rx_buf_ = static_cast<uint8_t*>(heap_caps_malloc(kTotalBytes, MALLOC_CAP_DMA));

        trans_.rx_buffer = rx_buf_;

        return queue_ != nullptr;

        if (spi_device_polling_transmit(spi_dev_, &trans_) != ESP_OK) {
            return false;

        return true;

    int                  drdy_pin_;

    uint8_t*             rx_buf_{nullptr};
    spi_transaction_t    trans_{};

### Неперервний кільцевий режим (Circular DMA з HT/TC перериваннями)

У задачах безперервного високочастотного моніторингу вібрацій або сейсморозвідки (де давач працює в режимі FIFO потоку на частотах понад 4 кГц) постійний перезапуск каналу DMA створює зайвий оверхед на запис у регістри `DMA_SxCR` та `DMA_SxNDTR`.

Для таких сценаріїв застосовується кільцевий режим DMA (*Circular Mode*, біт `CIRC = 1` у `DMA_SxCR`):
1. **Виділення подвійного буфера**: в пам'яті створюється масив подвійної довжини `2 · FRAME_SIZE`.
2. **Half-Transfer Interrupt (HT)**: коли DMA заповнює рівно першу половину буфера (Buffer A), контролер генерує переривання `HT_ISR`. Процесор починає обробку вибірок з Buffer A, поки DMA автономно продовжує запис у другу половину (Buffer B).
3. **Transfer-Complete Interrupt (TC)**: коли DMA заповнює Buffer B, генерується переривання `TC_ISR`, лічильник `NDTR` автоматично перезавантажується початковим значенням без участі процесора, а DMA переходить на початок Buffer A.

Це усуває навіть мінімальну ймовірність втрати вибірки (*gap-free streaming*), забезпечуючи абсолютно рівномірний темп зчитування.

### Апаратне тригерування DMA від системного таймера

У системах із фіксованим кроком дискретизації для фільтра Калмана замість обробки зовнішнього переривання `DRDY` можна використовувати прямий апаратний запуск DMA від внутрішнього таймера мікроконтролера (наприклад, `TIM3_TRGO`).

Схема підключення без залучення ядра:
- **Таймер `TIM3`**: генерує імпульс переповнення `TRGO` з частотою рівно 1000.00 Гц;
- **DMA Request Multiplexer (DMAMUX)**: перенаправляє подію `TIM3_TRGO` як запит на запуск передачі SPI TX DMA;
- **Потік SPI TX DMA**: надсилає масив із байтом адреси та 14 нулями на шину SPI;
- **Потік SPI RX DMA**: підхоплює прийняті байти й складає їх у SRAM;
- **Ядро процесора**: не прокидається на старт передачі і не бере участі в тактуванні. Процесор отримує єдине переривання лише тоді, коли всі 14 байтів уже лежать у пам'яті.

### Атомарне часове маркування вибірок (Hardware Timestamping)

Для точного інтегрування кутової швидкості та прискорення у безінерціальних системах навігації (INS) критично знати точний момент часу `t_k`, коли сталася вибірка.

Якщо фіксувати час у функції програмної обробки, непередбачувані затримки диспетчера FreeRTOS або переривань інших драйверів створюють джиттер до кількох мілісекунд.

Правильний підхід полягає в апаратному захопленні таймера:
1. Лінія `DRDY` від давача підключається не лише до входу переривання, а й до каналу захоплення таймера (*Input Capture Channel*, наприклад, `TIM2_CH1`).
2. При наростанні фронту `DRDY` 32-бітний апаратний лічильник таймера `TIM2->CCR1` миттєво фіксує поточне значення тактового часу з дискретністю в 1 такт процесора (наприклад, 1/168 МГц = 5.95 нс).
3. У структурі вимірів поле мітки часу заповнюється значенням з регістра захоплення:

:::tabs

@tab C (Мітка часу)

    uint32_t timestamp_ticks; /* Апаратна мітка захоплення TIM2_CCR1 */
    float    accel[3];

### Простеження та діагностика за допомогою логічного аналізатора

При налагодженні апаратного Burst-зчитування на шині SPI обов'язково контролюються такі критичні часові інтервали за допомогою цифрового логічного аналізатора або осцилографа:

```
          ┌────────────────────────────────────────────────────────┐
   CS: ───┘                                                        └──────────
               │                                                │
               ├─ t_lead                                        ├─ t_lag
               ▼                                                ▼
  SCK: ───────────П_П_П_П_П_П_П_П───П_П_П_П_П_П_П_П───...───────────П_П_П_П_П_П_П_П────
  MOSI: ──────────<  0x80 | 0x20  >───<    0x00     >───...───────────<    0x00     >────
  MISO: ──────────<  Don't Care   >───<   STATUS    >───...───────────<   TEMP_H    >────
```

Перевірочні критерії на діаграмі:
1. **Пауза `t_lead`**: спад `CS` повинен випереджати перший наростаючий фронт `SCK` мінімум на 50 нс. Якщо фронт `SCK` починається одночасно зі спадом `CS`, перший біт адреси буде інтерпретований слейвом як помилковий.
2. **Безперервність тактування**: між послідовними байтами даних всередині пакета не повинно бути програмних пауз. Контролер DMA забезпечує безперервний потік тактових імпульсів з міжбайтовою паузою 0 нс.
3. **Пауза `t_lag`**: наростання `CS` має відбуватися строго після завершення останнього (8-го) тактового імпульсу останнього байта. Якщо `CS` підніметься завчасно, останній байт вимірів буде обірваний і згенерує помилку `CRC` або спотворить старший байт температури.

### Апаратні буфери FIFO давача та вичитування за порогом заповнення (FIFO Watermark)

У багатьох сценаріях збору даних процесору недоцільно прокидатися на кожну окрему вибірку вимірів (наприклад, 1000 разів на секунду). Більшість сучасних 6-осьових IMU містять вбудований апаратний буфер FIFO глибиною від 512 байтів до 3 кілобайтів (наприклад, 3 КБ у LSM6DSO або 2 КБ у Bosch BMI270).

Режими роботи FIFO:
1. **Bypass Mode (Обхід)**: FIFO вимкнено, вихідні регістри оновлюються в реальному часі за частотою ODR.
2. **FIFO Mode (Накопичення до заповнення)**: давач записує вибірки, поки буфер не заповниться, після чого зупиняє запис.
3. **Continuous / Stream Mode (Кільцевий буфер FIFO)**: найновіші вибірки перезаписують найстаріші при переповненні.

Використання порога заповнення (Watermark / Threshold):
- У регістрі `FIFO_CTRL1 / FIFO_CTRL2` налаштовується поріг переривання, наприклад, `WTM = 32` кадри (по 14 байтів = 448 байтів).
- Давач накопичує 32 вибірки автономно, не турбуючи мікроконтролер.
- При досягненні порога на виводі `INT1` генерується строб `FIFO_TH`.
- Контролер DMA за один неперервний Burst-доступ вичитує весь блок 448 байтів із єдиного регістра виходу `FIFO_DATA_OUT_L` (адреса регістра не змінюється, а вичитування автоматично виштовхує наступне слово зі стека FIFO давача).
- Кількість пробуджень ядра CPU скорочується в 32 рази (з 1000 Гц до 31.25 Гц), а загальний час сну мікроконтролера зростає до 98.5%.

### Інтеграція в операційні системи реального часу (FreeRTOS Zero-Copy Pipeline)

У багатозадачних системах під керуванням FreeRTOS або Zephyr передача сирих байтів вимірів між перериванням DMA та обчислювальними задачами вимагає архітектури з нульовим копіюванням (*Zero-Copy*):

1. **Пряме сповіщення задачі (`vTaskNotifyGiveFromISR`)**: замість важких черг FreeRTOS, які копіюють пам'ять побайтово, переривання DMA `TC_ISR` використовує пряме сповіщення задачі (*Direct Task Notification*). Затримка пробудження задачі AHRS скорочується з 12 мкс до 1.8 мкс.
2. **Кільцевий пуфер покажчиків**: пам'ять виділяється у вигляді масиву статичних структур. DMA заповнює структуру `frames[idx]`, а переривання передає в чергу лише покажчик `&frames[idx]`.
3. **М'ютекси без блокувань**: захист від одночасного доступу реалізується за допомогою атомарних покажчиків `std::atomic<const Frame*>` або подвійної буферизації з бар'єрами пам'яті.

### Фізичний рівень і цілісність сигналів (Signal Integrity на високих швидкостях)

При роботі шини SPI на частотах від 10 МГц до 20 МГц фізичні параметри друкованої плати істотно впливають на надійність пакетного читання:

1. **Демпферні резистори (Series Damping Resistors)**: послідовно в лінії `SCK`, `MOSI` та `CS` біля виводів мікроконтролера встановлюються резистори номіналом `22 Ом ... 33 Ом`. Вони узгоджують вихідний опір драйвера мікроконтролера з хвильовим опором доріжки (зазвичай `50 Ом`), запобігаючи дзвінким викидам напруги (*ringing*) та хибним спрацьовуванням тактових фронтів.
2. **Швидкість наростання виводів GPIO (Slew Rate)**: у регістрах конфігурації мікроконтролера (`GPIOx_OSPEEDR`) швидкість виводів SPI встановлюється на значення `Medium Speed` або `High Speed`, але не `Very High Speed` без крайньої потреби. Надмірно крутий фронт (< 1 нс) створює високочастотне електромагнітне випромінювання та перехресні завади (*crosstalk*) на аналоговий тракт чутливого гіроскопа.
3. **Блокувальні конденсатори**: по лініях живлення `VDD` та `VDDIO` безпосередньо біля корпусу IMU встановлюються керамічні конденсатори ємністю 100 нФ (типорозмір 0402) та танталовий/керамічний конденсатор 10 мкФ для фільтрації імпульсних просідань живлення під час одночасного перемикання вихідних буферів інтерфейсу.

### Діагностика та усунення крайових випадків у DMA

При експлуатації апаратного зчитування виникають специфічні помилки, які неможливо виявити звичайним покроковим відлагодженням:

#### 1. Помилка переповнення буфера (Overrun Error, OVR)
Якщо центральний процесор затримує підтвердження або блокується пріоритетнішим перериванням, наступний імпульс `DRDY` може прийти до завершення попередньої передачі DMA. Модуль SPI встановлює прапорець `OVR` у регістрі `SPI_SR` і припиняє прийом нових байтів.
*Лікування*: обробник помилок DMA зобов'язаний вичитати `SPI_DR`, перевірити прапорець `OVR`, скинути його читанням послідовності `SR -> DR` та перезапустити лічильник `NDTR`.

#### 2. Зависання лінії Chip Select при аварійному скиданні
Якщо мікроконтролер перезавантажується посеред транзакції SPI, коли лінія `CS` перебуває в низькому рівні, давач залишається у стані очікування тактових імпульсів.
*Лікування*: у функції апаратної ініціалізації драйвера перед стартом SPI необхідно виконати ручне скидання: примусово виставити високий рівень на виводі `CS`, згенерувати 16 порожніх тактів на лінії SCK і за потреби надіслати команду програмного скидання давача (`CTRL3_C.SW_RESET = 1`).

#### 3. Апаратне вирівнювання та колізії пам'яті (Bus Error)
Шина DMA вимагає, щоб адреса буфера відповідала обраній розрядності передачі (для 32-бітних слів адреса має бути кратною 4). Невирівняний покажчик призводить до генерації винятку `HardFault` або апаратного зависання потоку DMA (`TEIF` — Transfer Error Interrupt Flag). Завжди використовуйте специфікатор `alignas(4)` або `__attribute__((aligned(4)))` для масивів DMA.

### Апаратний арбітраж шинної матриці та вузькі місця пам'яті (Bus Matrix Arbitration)

У сучасних 32-бітних мікроконтролерах контролер DMA взаємодіє з оперативною пам'яттю через багатошарову шинну матрицю (*Multi-Layer AHB Bus Matrix*). Розуміння топології шин дозволяє уникнути апаратних конфліктів доступу між ядром процесора та потоками DMA.

Основні елементи шинної структури:
1. **Майстри шини (Bus Masters)**: ядро процесора (інструкційна шина I-Bus, шина даних D-Bus, системна шина S-Bus), контролер загального DMA (DMA1/DMA2) та периферійні контролери Ethernet або USB OTG.
2. **Слейви шини (Bus Slaves)**: внутрішня пам'ять Flash, внутрішня пам'ять SRAM (розділена на кілька фізичних банків SRAM1, SRAM2, CCM / DTCM), та міст до периферійних шин APB1/APB2.
3. **Алгоритм арбітражу**: коли ядро процесора та потік DMA одночасно звертаються до одного й того самого банку пам'яті SRAM1, арбітр матриці вирішує конфлікт за правилом циклічного пріоритету (*Round-Robin*) або фіксованого пріоритету. При цьому один із майстрів отримує апаратну затримку в 1 такт (*wait-state*).

Інженерна рекомендація для нульових затримок:
- Розміщуйте буфери DMA в окремому банку пам'яті (наприклад, у пам'яті SRAM2 або AXI SRAM), тоді як ядро процесора виконує обчислення фільтра Калмана над даними у внутрішній надшвидкій пам'яті щільного зв'язку (DTCM / CCM SRAM). У цьому випадку потоки шини ніколи не перетинаються, а продуктивність обчислень досягає теоретичного максимуму.

### Апаратна затримка переривань NVIC та конвеєр збереження контексту

При виклику обробника `TC_ISR` контролер переривань ARM Cortex-M (NVIC, *Nested Vectored Interrupt Controller*) виконує апаратну послідовність дій:

1. **Збереження регістрів у стек (*Stacking*)**: контролер автоматично зберігає у стек 8 базових регістрів процесора (`R0-R3`, `R12`, `LR`, `PC`, `xPSR`). Для процесорів із блоком плаваючої коми (FPU) за наявності активного FPU-контексту зберігаються додатково 16 регістрів `S0-S15` та `FPSCR` (разом 26 слів = 104 байти). Апаратний час стекування становить рівно 12 тактів ядра (або 26 тактів з FPU).
2. **Вибірка вектора (*Vector Fetch*)**: одночасно зі стекуванням контролер NVIC зчитує адресу точки входу функції з таблиці векторів переривань.
3. **Оптимізація Tail-Chaining**: якщо під час виконання обробника DMA виникає наступне за пріоритетом переривання (наприклад, таймер), ядро не витрачає час на відновлення та повторне збереження стека: воно миттєво перемикається на наступний обробник за 6 тактів.
4. **Оптимізація Late-Arrival**: якщо під час початкового стекування низькопріоритетного переривання надходить вищий за пріоритетом запит, NVIC змінює вектор виклику на більш пріоритетний, не перезапускаючи процес збереження контексту.

### Математика декодування вибірок: від Q-формату до одиниць SI

Сирі значення, вичитані з вихідних регістрів IMU через DMA, представлені у форматі доповняльного коду (*Two's Complement signed 16-bit integers*). Для використання в навігаційних рівняннях ці цілі числа необхідно перетворити на фізичні величини міжнародної системи одиниць (SI):

1. **Лінійне прискорення**:
   Нехай виміряне значення осі становить `raw_accel_z`. За обраного діапазону вимірювання `±4 g` роздільна здатність становить `0.122 мг / LSB` (де `1 g = 9.80665 м/с²`):
   ```
   a_z [м/с²] = raw_accel_z · 0.000122 · 9.80665
   ```
2. **Кутова швидкість**:
   За обраного діапазону `±2000 dps` (*degrees per second*) коефіцієнт масштабування становить `70 мдпс / LSB`:
   ```
   ω_z [рад/с] = raw_gyro_z · 0.070 · (π / 180.0)
   ```
3. **Температура кристала**:
   Більшість MEMS-давачів мають термодатчик із крутизною характеристики `256 LSB / °C` та зміщенням при 25 °C:
   ```
   T [°C] = 25.0 + (raw_temp / 256.0)
   ```

### Особливості пакетного зчитування I2C через DMA (Генерація NACK та STOP)

На відміну від шини SPI, де ведучий повністю контролює тактування через лінію SCK і завершує транзакцію підняттям Chip Select, на шині I2C протокол вимагає чіткої апаратної послідовності прийому останнього байта:
1. Перед останнім байтом ведучий зобов'язаний сформувати біт NACK (негативне підтвердження), щоб повідомити слейву про завершення читання.
2. Одразу після NACK ведучий повинен згенерувати стан STOP на шині.

У контролерах STM32 керування NACK у режимі DMA реалізується апаратно:
- **Для блоків із 1 байта**: перед увімкненням DMA встановлюється біт `POS = 1` та `ACK = 0` у регістрі `I2C_CR1`.
- **Для блоків `N ≥ 2` байтів**: у регістрі `I2C_CR2` встановлюється біт `LAST = 1` (Next DMA transfer is the last transfer). Апаратний блок I2C автоматично генерує NACK на `N`-му байті та відправляє умову STOP без програмного втручання процесора.

### Маршрутизація запитів через DMAMUX у новітніх мікроконтролерах

У класичних контролерах STM32F4/F1 прив'язка периферійного модуля до потоку DMA була жорстко зафіксована апаратною таблицею (наприклад, `SPI1_RX` міг обслуговуватися лише `DMA2_Stream0_Channel3` або `DMA2_Stream2_Channel3`).

У сучасних родинах (STM32G4, STM32H7, STM32U5) впроваджено апаратний мультиплексор запитів **DMAMUX**:
1. **Гнучка комутація**: будь-який периферійний модуль може бути зкомутований із будь-яким каналом DMA.
2. **Генератор подій синхронізації (Synchronization Trigger)**: DMAMUX дозволяє затримувати виконання передачі DMA до настання зовнішньої події (наприклад, фронту на виводі `EXTI_Line` або сигналу таймера `TIMx_TRGO`).
3. **Режим генератора запитів (Request Generator)**: дозволяє перетворювати одиничний імпульс стробу `DRDY` на серію апаратних запитів DMA без проміжного коду обробника переривань.

### Апаратні пакети DMA в пам'яті (DMA Burst Transfers: INCR4, INCR8, INCR16)

Для зменшення навантаження на системну шину AHB контролери DMA підтримують режим пакетного доступу до самої оперативної пам'яті (*Memory Burst*):
- Замість одиночних звернень до пам'яті (по 1 байту на кожен такт шини) внутрішній апаратний FIFO буфер контролера DMA накопичує 4, 8 або 16 байтів.
- Після заповнення FIFO контролер DMA захоплює шину AHB і виконує нерозривний пакетний запис (*Burst Transaction: INCR4 або INCR8*) у пам'ять SRAM за один пакетний цикл шини.
- Це скорочує кількість циклів арбітражу шинної матриці у 4–8 разів, практично повністю усуваючи вплив фонового обміну давачами на швидкість виконання математичних обчислень ядра процесора.

### Апаратна конфігурація MPU для регіонів буферів DMA (Non-Cacheable SRAM)

На мікроконтролерах ARM Cortex-M7 (таких як STM32F746, STM32H743) найбезпечнішим і найефективнішим способом уникнення проблем із когерентністю кешу L1 є пряме налаштування модуля захисту пам'яті (MPU, *Memory Protection Unit*).

Замість постійного виклику повільних інструкцій програмної інвалідації кешу `SCB_InvalidateDCache_by_Addr()` перед кожним кадром вимірів, розробник виділяє окремий діапазон адрес пам'яті (наприклад, банк пам'яті AXI SRAM або окремий сегмент SRAM4 розміром 32 кілобайти) та призначає йому апаратні атрибути некашованої пам'яті:

1. **Базова адреса регіону**: `MPU_RBAR` вказує на початок сегмента буферів DMA (наприклад, `0x24000000`).
2. **Розмір регіону (`MPU_RASR.SIZE`)**: налаштовується на ступінь двійки (32 КБ: `SIZE = 0x0E`).
3. **Тип пам'яті та кешування**:
   - `TEX[2:0] = 001`, `C = 0`, `B = 0`: пам'ять типу *Normal Memory, Non-Cacheable, Non-Shareable*;
   - Або `TEX[2:0] = 000`, `C = 0`, `B = 1`: пам'ять типу *Device Memory, Shareable*.
4. **Політика доступу**: `AP[2:0] = 011` (повний доступ на читання та запис для привілейованого та користувацького режимів).

При такій конфігурації процесорне ядро читає дані з буфера DMA безпосередньо з фізичних комірок SRAM через системну шину AXI без проміжного кешування в L1 D-Cache. Це повністю усуває ймовірність читання застарілих даних, знижує навантаження на кеш-контролер і скорочує час обробки переривання на 12–18 тактів на кожну вибірку.

### Ієрархія пріоритетів переривань NVIC: групування та витіснення

У системі керування безпілотником одночасно працюють десятки джерел переривань: таймери ШІМ моторів, радіокерування, інтерфейс давача IMU, модуль супутникової навігації GNSS та протокол телеметрії.

Правильне налаштування контролера переривань NVIC вимагає суворого структурування пріоритетів:

1. **Групування пріоритетів (`NVIC_PriorityGroup_4`)**:
   Усі 4 біти регістру пріоритету виділяються під пріоритет витіснення (*Preemption Priority*), а підпріоритет (*Subpriority*) вимикається (`0..15` рівнів витіснення).
2. **Розподіл рівнів пріоритетів у системі стабілізації**:
   - **Пріоритет 0 (Найвищий)**: Аварійне відключення живлення та захист моторів (OCP / Watchdog);
   - **Пріоритет 1**: Апаратне переривання захоплення таймера та строб `DRDY` від IMU;
   - **Пріоритет 2**: Переривання завершення передачі `DMA_SPI_TC_ISR`;
   - **Пріоритет 5**: Опитування повільних давачів (барометр, магнітометр, термометр);
   - **Пріоритет 6**: Обробка пакетів зв'язку (UART / CAN-шина телеметрії);
   - **Пріоритет 15 (Найнижчий)**: Системні виклики операційної системи RTOS (PendSV, SysTick).

Такий розподіл гарантує, що жодне переривання від повільних інтерфейсів (CAN або UART) не зможе затримати або витіснити критичний обробник `DMA_TC_ISR` інерціального модуля, забезпечуючи нульовий фазовий джиттер навігаційного контуру.

### Фазові співвідношення шини SPI: вибір режиму CPOL та CPHA

Універсальний синхронний послідовний інтерфейс SPI підтримує 4 режими тактування, які визначаються комбінацією двох бітів:
- **Полярність тактового сигналу (CPOL, *Clock Polarity*)**: стан лінії SCK у режимі очікування (`0` — низький рівень, `1` — високий рівень);
- **Фаза тактового сигналу (CPHA, *Clock Phase*)**: за яким фронтом фіксуються дані (`0` — за першим фронтом такту, `1` — за другим фронтом такту).

Більшість інерціальних давачів (ST LSM6DSO, Bosch BMI270, InvenSense ICM-42688) підтримують два сумісні режими: **Mode 0 (CPOL=0, CPHA=0)** та **Mode 3 (CPOL=1, CPHA=1)**.

Чому для високошвидкісного DMA обирають саме Mode 3:
1. У режимі Mode 3 лінія тактування SCK перебуває у високому рівні, коли транзакція неактивна (`CS = High`).
2. При спаді лінії `CS` напруга на лінії SCK уже стабільна, що запобігає появі хибного стартового такту через паразитну ємнісну наводку між лініями `CS` та `SCK`.
3. Перший біт адреси виставляється ведучим на лінії MOSI миттєво після опускання `CS` і стабільно фіксується першим спадним фронтом SCK, забезпечуючи максимальний запас за часом встановлення (*Setup Time: `t_su > 5 нс`*) та часом утримання (*Hold Time: `t_h > 5 нс`*).

### Низькорівневе пряме керування через регістри (STM32 LL vs HAL)

У високонавантажених системах керування БПЛА стандартна бібліотека `HAL_SPI_TransmitReceive_DMA()` створює відчутний оверхед: функція виконує десятки перевірок вказівників, блокування м'ютексів та оновлення статусних прапорців стану дескриптора, що забирає до 4.2 мкс (близько 350 тактів на частоті 84 МГц).

Прямий запис в апаратні регістри (*Low-Layer / Direct Register Access*) скорочує час активації передачі до 15 тактів процесора (близько 180 нс):

1. **Регістр `SPI1->CR2`**: біти `RXDMAEN = 1` та `TXDMAEN = 1` дозволяють генерацію апаратних запитів DMA при появі даних у приймальному буфері або звільненні буфера передачі.
2. **Регістр `DMA2_Stream0->CR`**:
   - Вимкнення потоку: `DMA2_Stream0->CR &= ~DMA_SxCR_EN`;
   - Очікування апаратного скидання біта `EN`;
   - Очищення статусних прапорців у `DMA2->LIFCR`: скидання бітів завершення передачі `CTCIF0`, половинної передачі `CHTIF0` та помилок `CTEIF0`, `CDMEIF0`, `CFEIF0`;
   - Завантаження лічильника: `DMA2_Stream0->NDTR = FRAME_SIZE`;
   - Увімкнення потоку: `DMA2_Stream0->CR |= DMA_SxCR_EN`.
3. **Пряме опускання лінії Chip Select**: маніпуляція регістром атомарного встановлення/скидання бітів GPIO `GPIOA->BSRR = GPIO_BSRR_BR_4` (1 такт шини AHB).

### Апаратна корекція некоаксіальності та калібрування на FPU Cortex-M

Отримані через DMA сирі вибірки містять систематичні похибки: зміщення нуля (*Zero-Rate Offset / Bias*), масштабний коефіцієнт (*Scale Factor*) та взаємний перекіс осей чутливості (*Cross-Axis Non-Orthogonality*).

Математична модель калібрування виражається матричним рівнянням:

```
v_calibrated = M_scale · (v_raw - v_bias)
```

де `v_raw` — 3-вимірний вектор сирих вимірів, `v_bias` — вектор адитивного зміщення, `M_scale` — симетрична матриця масштабування та некоаксіальності розміром 3x3.

На мікроконтролерах із блоком обчислень із плаваючою комою (FPU Single Precision на ARM Cortex-M4/M7) це перетворення реалізується апаратними інструкціями злитого множення-додавання `VFMA.F32` (*Fused Multiply-Accumulate*):
- Інструкція `VFMA.F32 Sd, Sn, Sm` виконує операцію `Sd = Sd + (Sn · Sm)` за 1 такт тактової частоти без проміжного округлення.
- Калібрування повного 3-осьового вектора прискорення займає рівно 9 інструкцій `VFMA` (9 тактів = 53.5 нс на частоті 168 МГц).

Завдяки цьому повна обробка вибірки після переривання DMA виконується швидше, ніж апаратний час вибірки чергового байта на шині SPI.

### Автоматичне відновлення шини при апаратних збоях (Bus Recovery FSM)

У польотних умовах сильні вібрації або електромагнітні імпульси можуть спричинити апаратне скидання зв'язку. Надійний драйвер містить кінцевий автомат діагностики та відновлення:

1. **Таймаут очікування переривання DMA (Watchdog Timeout)**:
   Якщо переривання `TC_ISR` не настає протягом подвійного розрахункового часу транзакції (наприклад, 50 мкс замість 15 мкс), таймер безпеки фіксує аварію каналу.
2. **Апаратний ресет шинного контролера**:
   - Примусове вимкнення потоку DMA (`DMA_SxCR.EN = 0`);
   - Вимкнення та повторне увімкнення периферійного модуля SPI через скидання біта `SPE = 0 -> SPE = 1`;
   - Підняття лінії `CS` у високий рівень.
3. **Програмне скидання давача (Software Reset)**:
   Якщо повторна спроба зчитування завершується помилкою, драйвер надсилає в давач команду програмного ресету (запис `0x01` у регістр `CTRL3_C.SW_RESET`) та повторює повний цикл ініціалізації регістрової карти.

### Аналіз латентності перемикання контексту в FreeRTOS (`portYIELD_FROM_ISR`)

При використанні операційної системи реального часу (FreeRTOS) передача події від апаратного переривання DMA до задачі обчислення орієнтації (AHRS Task) вимагає мінімізації часу перемикання контексту.

Механізм роботи виклику `portYIELD_FROM_ISR`:
1. **Прапорець `xHigherPriorityTaskWoken`**: коли функція `xTaskNotifyGiveFromISR()` або `xQueueSendFromISR()` розблоковує задачу обробки вимірів, планувальник перевіряє її пріоритет. Якщо пріоритет розблокованої задачі вищий за пріоритет перерваної фонової задачі, прапорець встановлюється у значення `pdTRUE`.
2. **Програмне переривання PendSV**: макрос `portYIELD_FROM_ISR(xHigherPriorityTaskWoken)` встановлює біт `PENDSVSET` у регістрі `ICSR` (Interrupt Control and State Register) процесора Cortex-M.
3. **Відкладене перемикання контексту**: оскільки переривання `PendSV` має найнижчий апаратний пріоритет (пріоритет 15), процесор спочатку завершує обробник `DMA_TC_ISR`, відновлює базові регістри, і лише після цього миттєво викликає `PendSV_Handler`.
4. **Збереження стека задачі**: обробник `PendSV` зберігає програмні регістри `R4-R11` у стек поточної задачі, перемикає покажчик стека процесора `PSP` на вершину стека задачі AHRS і передає їй керування за 3.8 мкс (близько 320 тактів ядра на частоті 84 МГц).

### Апаратне профілювання затримок через DWT та трасування ITM

Для вимірювання реальної швидкодії конвеєра DMA без використання повільних функцій виводу `printf` (які спотворюють часові інтервали на мілісекунди) використовується вбудований апаратний блок трасування ARM Cortex-M **DWT** (*Data Watchpoint and Trace*):

1. **Активація 32-бітного лічильника циклів**:
   ```c
   CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
   DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
   ```
2. **Фіксація точок вимірювання**:
   - Момент запуску транзакції: `uint32_t t_start = DWT->CYCCNT;`
   - Момент входу в переривання `DMA_TC_ISR`: `uint32_t t_isr = DWT->CYCCNT;`
   - Момент пробудження задачі в RTOS: `uint32_t t_task = DWT->CYCCNT;`
3. **Розрахунок апаратних затримок**:
   - Час передачі кадру шиною SPI (15 байтів при 10 МГц): `(t_isr - t_start) / F_CPU = 12.2 мкс`;
   - Час диспетчеризації переривання та пробудження RTOS: `(t_task - t_isr) / F_CPU = 3.8 мкс`.
4. **Вивід діагностики через лінію SWO (ITM Trace)**:
   Апаратний модуль ITM дозволяє виводити контрольні маркери через один вивід `SWO` на частоті до 2 МГц без жодного такту затримки виконання інструкцій ядра процесора.

### Електромагнітна сумісність (EMC) та правила розведення друкованої плати для SPI DMA

Високошвидкісні сигнали шини SPI (тактові імпульси 10–20 МГц із часом наростання фронту `t_r < 2 нс`) створюють інтенсивні електромагнітні завади на сусідні аналогові доріжки давачів.

Основні правила проектування топології плати (*PCB Layout Guidelines*):
1. **Суцільний полігон заземлення (Continuous Ground Plane)**: сигнальні доріжки `SCK`, `MOSI`, `MISO` та `CS` повинні проходити строго над суцільним шаром землі (GND Plane) на сусідньому шарі багатошарової плати. Будь-які вирізи або розриви в полігоні землі під лінією SPI змушують зворотний струм високої частоти обходити перешкоду, утворюючи антенний контур великої площі.
2. **Контрольований хвильовий опір**: ширина сигнальних доріжок розраховується під стандартний хвильовий опір `Z_0 = 50 Ом`.
3. **Послідовні демпферні резистори**: безпосередньо біля вихідних виводів мікроконтролера (на відстані не більше 5 мм) у розрив ліній `SCK`, `MOSI` та `CS` встановлюються резистори номіналом `22 Ом ... 33 Ом`. Вони усувають явище імпедансного неузгодження та гасять дзвінкі викиди напруги на фронтах сигналу.
4. **Екранування ліній (Ground Guard Traces)**: лінія тактування `SCK` відокремлюється від ліній даних та аналогових ланцюгів захисними доріжками заземлення з перехідними отворами (Vias Stitching) через кожні 5–10 мм.

### Порівняння продуктивності: Polling проти DMA

Експериментальне вимірювання завантаження процесора Cortex-M4 (STM32F401, 84 МГц) при частоті оновлення IMU 1000 Гц (розмір кадру 14 байтів):

| Метод зчитування | Час блокування ядра CPU на 1 транзакцію | Завантаження ядра CPU при 1 кГц | Джиттер моменту зчитування |
| :--- | :--- | :--- | :--- |
| **Побайтове опитування (Single I2C)** | 1365.0 мкс | **100% (переповнення шини)** | ±120.0 мкс |
| **Пакетне опитування (Burst SPI Polling)** | 12.2 мкс | **1.22%** | ±5.4 мкс |
| **Пакетне переривання (Burst SPI Interrupt)** | 4.8 мкс (ISR overhead) | **0.48%** | ±1.2 мкс |

Апаратний конвеєр з прямим доступом до пам'яті вивільняє центральний процесор для математично інтенсивних операцій: інтегрування кватерніонів, матричних перетворень та прогнозування розширеного фільтра Калмана (EKF).
