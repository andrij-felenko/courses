# 🧮 Математика бітового інтервалу CAN

Щоб десяток контролерів на спільній шині могли одночасно брати участь у побітовому арбітражі й коректно розпізнавати біти на швидкості до 1 Мбіт/с без спільної тактової лінії, кожен вузол мусить розгортати один логічний біт у серію дискретних мікрокроків — квантів часу. Цей математичний апарат визначає, де саме всередині біта вимірюється напруга шини, скільки наносекунд відводиться на фізичний біг електричного сигналу кабелем туди й назад, і як апаратний фазовий коректор компенсує температурний дрейф локальних кварцових резонаторів.

Без точного розрахунку бітового інтервалу шина CAN або втратить здатність до арбітражу (коли вузли на протилежних кінцях кабелю не встигатимуть бачити чужі домінантні біти), або накопичуватиме помилки стафінгу через розбіжність внутрішніх годинників мікроконтролерів.

```
       |<─────────────────────── Номінальний час біта (t_bit) ──────────────────────>|
       |                                                                              |
┌──────┴──────────┬──────────────────────────┬──────────────────────────┬─────────────┴──────────┐
│    Sync_Seg     │         Prop_Seg         │       Phase_Seg1         │       Phase_Seg2       │
│  (завжди 1 TQ)  │ (компенсація затримок)   │ (буфер фази до вибірки)  │ (буфер після вибірки)  │
└─────────────────┴──────────────────────────┴──────────────────────────┴────────────────────────┘
                                                                        ▲
                                                                  Sample Point
                                                                (Точка вибірки)
```

### Кванти часу та поділ бітового інтервалу

Час передачі одного біта `t_bit` (який визначає бітову швидкість `Bitrate = 1 / t_bit`) в апаратному контролері CAN розбивається на ціле число неподільних відрізків — квантів часу (*Time Quanta*, скорочено `TQ` або `t_q`). Тривалість одного кванта `t_q` формується апаратним дільником частоти (*Baud Rate Prescaler*, `BRP`) від базової системної частоти модуля CAN `f_can`:

```
t_q = BRP / f_can
```

Сумарна кількість квантів усередині одного біта `N_total` за стандартом ISO 11898-1 лежить у межах від 8 до 25 `TQ` для класичного CAN 2.0 (у сучасних контролерах CAN FD — до 80 або 128 `TQ` для номінальної фази арбітражу). Номінальний час біта складається з чотирьох послідовних неперекривних сегментів:

```
N_total = Sync_Seg + Prop_Seg + Phase_Seg1 + Phase_Seg2
```

Кожен із чотирьох сегментів виконує строго визначену фізичну та алгоритмічну функцію:

1. **Сегмент синхронізації (`Sync_Seg` — *Synchronization Segment*)**:
   Має фіксовану тривалість рівно в 1 `TQ`. На цьому інтервалі очікується перепад напруги з рецесивного стану в домінантний (спадний фронт), за яким приймач узгоджує свій лічильник фази біта з передавачем.

2. **Сегмент затримки поширення (`Prop_Seg` — *Propagation Segment*)**:
   Призначений для фізичної компенсації затримки проходження сигналу по шині та через трансивери. Під час арбітражу та в слоті підтвердження ACK сигнал від одного вузла мусить дійти до найвіддаленішого вузла мережі, пройти через його вхідні кола компаратора, і повернутися назад до передавача до моменту, коли передавач здійснить вимірювання напруги. Тривалість `Prop_Seg` програмується в діапазоні від 1 до 8 `TQ`.

3. **Фазовий буфер 1 (`Phase_Seg1` — *Phase Buffer Segment 1*)**:
   Буферний інтервал перед точкою вибірки, призначений для поглинання фазових запізнень фронтів через дрейф генераторів або ємнісне затягування фронтів у довгій лінії. За потреби апаратно подовжується алгоритмом ресинхронізації. Діапазон: від 1 до 8 `TQ`.

4. **Фазовий буфер 2 (`Phase_Seg2` — *Phase Buffer Segment 2*)**:
   Буферний інтервал після точки вибірки. Якщо фронт синхронізації приходить із випередженням (раніше, ніж закінчився попередній біт), апаратна логіка скорочує `Phase_Seg2`, щоб наступний біт почався раніше. Діапазон: від 2 до 8 `TQ` (мусить бути не меншим за затримку внутрішньої обробки сигналу в контролері).

### Точка вибірки (Sample Point) та режими фільтрації вибірок

Точка вибірки (*Sample Point*, `SP`) — це точний момент часу всередині бітового інтервалу, у який логіка контролера фіксує та оцифровує рівень напруги шини. Усе, що відбувається на лінії до цієї точки, вважається перехідним процесом; усе, що після — підготовкою до наступного біта.

Положення точки вибірки виражається у відсотках від початку біта:

```
SP = (Sync_Seg + Prop_Seg + Phase_Seg1) / N_total · 100%
```

Міжнародна організація CiA (*CAN in Automation*) та стандарт ISO 11898 встановлюють рекомендовані значення точки вибірки:
- Для швидкостей до 500 кбіт/с: `SP ≈ 87.5%` (дозволяє максимізувати час на `Prop_Seg` для роботи на довгих кабелях);
- Для швидкості 1 Мбіт/с: `SP = 75%..80%` (забезпечує симетричніший запас під час високих частот);
- Для фази даних CAN FD (2..8 Мбіт/с): `SP = 70%..75%`.

Більшість апаратних контролерів підтримують два режими вибірки напруги в точці `Sample Point`:
1. **Режим 1 вибірки (1-Sample Mode):** рівень шини фіксується одноразово в точний момент `SP`. Забезпечує максимальну швидкодію та мінімальну фазову невизначеність на швидкостях 500 кбіт/с і 1 Мбіт/с.
2. **Режим 3 вибірок (3-Sample / Majority Voting Mode):** контролер виконує три послідовні заміри напруги з інтервалом в `1 TQ` (у моменти `SP - 2 TQ`, `SP - 1 TQ` та `SP`) і визначає підсумковий біт правилом мажоритарного голосування (2 з 3). Цей режим підвищує стійкість до високочастотних імпульсних завад на низьких швидкостях (до 125 кбіт/с), але вимагає, щоб `Phase_Seg1` був не меншим за `2 TQ`.

### Математичний розрахунок Propagation Segment для заданої довжини кабелю

Критична умова працездатності шини CAN полягає в тому, що час затримки поширення сигналу по замкненому колу туди й назад (*Round-Trip Time*, `t_round_trip`) не повинен перевищувати сумарну тривалість `Sync_Seg + Prop_Seg`.

Повний час затримки сигналу по колу складається з трьох доданків:

```
t_round_trip = 2 · (t_bus + t_tx + t_rx)
```

Де:
- `t_bus` — час польоту електромагнітної хвилі кабелем на максимальну довжину `L`. Швидкість поширення сигналу в крученій парі з ізоляцією зі спіненого поліетилену або тефлону становить близько `v ≈ 0.2 м/нс` (що відповідає затримці `tau_cable ≈ 5 нс/м`):
  ```
  t_bus = L · tau_cable = L · 5 нс/м
  ```
- `t_tx` — апаратна затримка передавача CAN-трансивера (від цифрового входу TXD до встановлення диференційної напруги на виводах CANH/CANL). Для типових мікросхем (наприклад, TJA1051, MCP2562 або SN65HVD230) `t_tx ≈ 60..100 нс`.
- `t_rx` — затримка приймача CAN-трансивера (від напруги на шині до появи логічного рівня на виході RXD мікроконтролера), зазвичай `t_rx ≈ 60..100 нс`.

Затримка внутрішньої логіки та фільтрації мікроконтролера зазвичай становить `t_mcu ≈ 20..40 нс`.

Отже, мінімально необхідна тривалість `Prop_Seg` у квантах часу визначається як:

```
Prop_Seg ≥ ceil( (2 · (L · tau_cable + t_tx + t_rx) + t_mcu) / t_q )
```

Якщо це число виходить більшим за максимальний розмір регістру `Prop_Seg` (8 `TQ`), необхідно або зменшувати тривалість кванта `t_q` (збільшувати загальну кількість квантів у біті `N_total`), або знижувати бітову швидкість шини.

### Вплив топології: відгалуження (Stub Lines) та ємнісне затягування

У реальних інженерних системах шина CAN рідко є ідеальною прямою лінією. До магістрального кабелю підключаються відгалуження (*stubs*) до окремих блоків керування. Кожне відгалуження створює неузгоджену ємність та відбиття сигналу, що спотворює форму хвилі:

1. **Максимальна довжина відгалуження:** за стандартом ISO 11898 довжина одного відгалуження не повинна перевищувати `L_stub ≤ 0.3 м` на швидкості 1 Мбіт/с (та до `L_stub ≤ 1 м` на швидкості 500 кбіт/с). Сумарна довжина всіх відгалужень мережі не повинна перевищувати 5 метрів.
2. **Ємнісна затримка фронту:** паразитна ємність трансиверів (зазвичай `10..20 пФ` на вузол) та захисних TVS-діодів додається до погонної ємності кабелю (`≈ 40..70 пФ/м`). Це затягує перехід лінії з домінантного стану в рецесивний, вимагаючи додаткового запасу часу в сегменті `Phase_Seg1`.

### Механізм фазової підстройки: SJW та пересинхронізація

Локальні тактові генератори різних вузлів на шині мають температурний та виробничий розкид частоти `Delta_f / f`. Як наслідок, спадний фронт між бітами приходить не строго на межі `Sync_Seg`, а зі зміщенням у часі `e` (фазова похибка).

CAN використовує два механізми синхронізації:

1. **Жорстка синхронізація (Hard Synchronization)**:
   Відбувається виключно на спадному фронті біта **Start of Frame (SOF)**, коли шина перебувала в стані спокою (*Bus Idle*). Контролер миттєво обнуляє свій внутрішній лічильник квантів, примусово виставляючи поточний момент як закінчення `Sync_Seg`. Усі вузли розпочинають відлік першого біта синхронно.

2. **Ресинхронізація на льоту (Resynchronization)**:
   Здійснюється на кожному наступному спадному фронті (переході з рецесивного стану в домінантний) усередині кадру. Якщо перепад потрапляє поза межі `Sync_Seg`, обчислюється фазова похибка `e`:
   - Якщо фронт запізнюється (`e > 0`, фронт потрапив у `Prop_Seg` або `Phase_Seg1`), сегмент `Phase_Seg1` тимчасово подовжується на величину `min(e, SJW)`.
   - Якщо фронт випереджає (`e < 0`, фронт потрапив у `Phase_Seg2`), сегмент `Phase_Seg2` тимчасово скорочується на величину `min(|e|, SJW)`.

Параметр **SJW (*Synchronization Jump Width*)** задає верхню межу (від 1 до 4 `TQ`), на яку дозволено одноразово змінювати тривалість фазових буферів. Занадто малий `SJW` не встигатиме виправляти накопичений дрейф кварцу між рідкісними фронтами, а занадто великий — зробить систему вразливою до високочастотного шуму на фронтах.

### Математичний критерій допустимого дрейфу тактових генераторів

Для надійної роботи мережі без виникнення хибних помилок стафінгу розкид тактових частот кварцових резонаторів двох довільних вузлів `Delta_f` відносно номінальної частоти `f_nom` повинен строго задовольняти двом нерівностям стандарту ISO 11898-1:

**Умова 1 (Здатність до повної ресинхронізації за один крок SJW):**
Максимальна фазова похибка, накопичена між двома послідовними фронтами синхронізації (у найгіршому випадку це 10 бітів через правило 5 однакових бітів підряд), не повинна перевищувати величину стрибка `SJW`:

```
Delta_f / f_nom ≤ SJW / (2 · 10 · N_total)
```

**Умова 2 (Запас фазових буферів до моменту вибірки):**
Фазовий зсув за час передачі 13 бітів (максимальний інтервал між двома бітами ресинхронізації з урахуванням дестафінгу та кінця кадру) не повинен виходити за межі буферів `Phase_Seg1` та `Phase_Seg2`:

```
Delta_f / f_nom ≤ min(Phase_Seg1, Phase_Seg2) / (2 · (13 · N_total - Phase_Seg2))
```

Якщо обидві умови виконуються, мережа гарантовано функціонує без збоїв навіть при максимальній різниці температур між блоками керування (наприклад, гарячим моторним відсіком при +105 °C та холодним салоном при -40 °C). Застосування внутрішніх дешевих RC-генераторів мікроконтролерів (які мають нестабільність 1..2%) у шині CAN категорично заборонено: для CAN 2.0 потрібні кварцові або керамічні резонатори з точністю краще ніж 0.5%, а для CAN FD — кварцові резонатори з точністю краще ніж 0.15% (1500 ppm).

### Повний числовий приклад проектування бітового інтервалу для класичного CAN

**Вихідні вимоги інженерного розрахунку:**
- Бітова швидкість шини: `Bitrate = 500 кбіт/с` (час біта `t_bit = 2000 нс`);
- Тактова частота модуля CAN мікроконтролера: `f_can = 80 МГц` (базовий період тактування `T_sys = 12.5 нс`);
- Довжина кабельної траси: `L = 40 м` (кручена пара, `tau_cable = 5 нс/м`);
- Сумарна затримка трансивера (TX + RX): `t_trx = 150 нс`;
- Додатковий запас на внутрішню затримку мікроконтролера: `t_mcu = 30 нс`;
- Цільове положення точки вибірки: `SP_target = 80%`.

**Покроковий математичний розрахунок:**

**Крок 1. Вибір дільника частоти та сумарної кількості квантів.**
Для частоти 80 МГц оберемо дільник `BRP = 8`:

```
t_q
= BRP / f_can                     [формула тривалості кванта]
= 8 / (80 · 10⁶)
= 100 нс                          [тривалість 1 TQ]

N_total
= t_bit / t_q                     [загальна кількість квантів на біт]
= 2000 нс / 100 нс
= 20 TQ                           [стандартне значення для класичного CAN 2.0]
```

**Крок 2. Фіксація сегмента синхронізації.**

```
Sync_Seg
= 1 TQ                            [за стандартом ISO 11898-1 завжди рівно 1]
= 100 нс
```

**Крок 3. Розрахунок сегмента затримки поширення (`Prop_Seg`).**
Обчислимо сумарну фізичну затримку по колу:

```
t_prop
= 2 · (L · tau_cable + t_trx) + t_mcu   [двостороння затримка в кабелі й чіпах]
= 2 · (40 · 5 + 150) + 30
= 2 · (200 + 150) + 30
= 2 · 350 + 30
= 730 нс                                [час обходу сигналу]

Prop_Seg_calc
= ceil(t_prop / t_q)                    [переведення в ціле число квантів вгору]
= ceil(730 / 100)
= 8 TQ                                  [Prop_Seg = 8 TQ = 800 нс, забезпечує запас 70 нс]
```

**Крок 4. Розподіл фазових буферів за цільовою точкою вибірки.**
Для `SP = 80%` точка вибірки мусить припадати на квант:

```
Sample_Point_TQ
= N_total · SP                          [положення точки вибірки в квантах]
= 20 · 0.80
= 16 TQ                                 [вибірка на 16-му кванті біта]

Phase_Seg1
= Sample_Point_TQ - Sync_Seg - Prop_Seg [визначення першого буфера]
= 16 - 1 - 8
= 7 TQ                                  [Phase_Seg1 = 7 TQ]

Phase_Seg2
= N_total - (Sync_Seg + Prop_Seg + Phase_Seg1) [решта квантів на другий буфер]
= 20 - (1 + 8 + 7)
= 4 TQ                                  [Phase_Seg2 = 4 TQ]
```

**Крок 5. Вибір Synchronization Jump Width (`SJW`).**
За стандартом `SJW` не повинен перевищувати `min(Phase_Seg1, 4)`:

```
SJW
= min(Phase_Seg1, 4)                    [максимально допустимий стрибок]
= min(7, 4)
= 4 TQ                                  [SJW = 4 TQ = 400 нс компенсації на крок]
```

**Перевірка фактичної точки вибірки:**

```
SP_actual
= (1 + 8 + 7) / 20 · 100%               [фактичне співвідношення]
= 16 / 20 · 100%
= 80.0%                                 [ідеальний збіг із цільовим значенням]
```

### Розрахунок фази даних CAN FD та компенсація затримки передавача (TDC)

У стандарті CAN FD фаза даних передається на підвищеній швидкості (наприклад, 2 Мбіт/с або 5 Мбіт/с). На швидкості 5 Мбіт/с тривалість усього біта становить лише `t_bit_data = 200 нс`.

При такій тривалості біта виникає фундаментальна фізична проблема: власна затримка передавача та приймача CAN-трансивера `t_tx + t_rx ≈ 150 нс` становить 75% від усього часу біта! Якщо передавач намагатиметься читати шину в звичайній точці вибірки для перевірки Bit Error, він бачитиме свій попередній біт, що призведе до хибного спрацьовування детектора помилок.

Для розв'язання цієї проблеми контролери CAN FD реалізують механізм **компенсації затримки передавача (TDC — *Transmitter Delay Compensation*)**:

```
                       |<──────── Час передачі біта даних (200 нс) ────────>|
TXD контролера: ───────┌───────────────────────────┐────────────────────────────
                       │        Біт N (TX)         │        Біт N+1 (TX)        
                       └───────────────────────────┘────────────────────────────
                                   │
                                   ▼ Затримка трансивера (t_tx + t_rx ≈ 150 нс)
RXD контролера: ───────────────────────────┌───────────────────────────┐────────
                                           │        Біт N (RX)         │        
                                           └───────────────────────────┘────────
                                                         ▲
                                             Secondary Sample Point (SSP)
                                             SSP = Measured_Delay + TDCO
```

Контролер автоматично вимірює реальну затримку петлі трансивера `t_loop = t_tx + t_rx` на спадному фронті біта FDF/BRS і формує **вторинну точку вибірки (SSP — *Secondary Sample Point*)**:

```
SSP_offset = Measured_Delay + TDCO
```

Де `TDCO` (*Transmitter Delay Compensation Offset*) — зміщення, що задається програмістом і відповідає положенню точки вибірки всередині затриманого біта (зазвичай 70%..75%).

**Розрахунок бітових параметрів для фази даних 2 Мбіт/с при f_can = 80 МГц:**
- `Bitrate_data = 2 Мбіт/с` (`t_bit_data = 500 нс`);
- Обираємо `BRP_data = 1` (`t_q = 12.5 нс`);
- Загальна кількість квантів: `N_total_data = 500 / 12.5 = 40 TQ`;
- `Sync_Seg = 1 TQ`;
- `Prop_Seg_data = 0 TQ` (у фазі даних арбітраж відсутній, затримка кабелю не вимагає компенсації між різними вузлами);
- Для точки вибірки `SP = 75%`:
  ```
  Sample_Point_TQ = 40 · 0.75 = 30 TQ
  Phase_Seg1_data = 30 - 1 - 0 = 29 TQ
  Phase_Seg2_data = 40 - 30 = 10 TQ
  SJW_data = min(Phase_Seg2_data, 8) = 8 TQ
  ```

### Відображення параметрів у регістри популярних мікроконтролерів

Отримані математичні величини заносяться у відповідні конфігураційні бітові поля регістрів апаратних периферійних модулів. Слід звертати увагу, що апаратні лічильники більшості мікросхем зберігають значення зі зміщенням на одиницю (тобто значення `1 TQ` записується в регістр як двійковий нуль `0x00`).

1. **Регістр `CAN_BTR` мікроконтролерів STM32 (периферія bxCAN):**
   - Поле `BRP[9:0]`: записується `BRP - 1` (для `BRP = 8` записується `7`);
   - Поле `TS1[3:0]`: об'єднує `Prop_Seg + Phase_Seg1 - 1` (для `8 + 7 = 15 TQ` записується `14` або `0x0E`);
   - Поле `TS2[2:0]`: кодує `Phase_Seg2 - 1` (для `Phase_Seg2 = 4 TQ` записується `3` або `0x03`);
   - Поле `SJW[1:0]`: кодує `SJW - 1` (для `SJW = 4 TQ` записується `3` або `0x03`).

2. **Регістри `FDCAN_NBTP` та `FDCAN_DBTP` контролерів STM32 G4/H7 (FDCAN):**
   - `NBRP[8:0] = BRP - 1`;
   - `NTSEG1[7:0] = Prop_Seg + Phase_Seg1 - 1`;
   - `NTSEG2[6:0] = Phase_Seg2 - 1`;
   - `NSJW[6:0] = SJW - 1`;
   - У регістрі даних `FDCAN_DBTP`: аналогічні поля `DBRP`, `DTSEG1`, `DTSEG2`, `DSJW` для фази даних.

3. **Автономний CAN-контролер Microchip MCP2515 (регістри CNF1, CNF2, CNF3):**
   - `CNF1`: біти `BRP[5:0] = BRP - 1`, біти `SJW[1:0] = SJW - 1`;
   - `CNF2`: біт `BTLMODE = 1` (дозволяє індивідуальне налаштування Phase_Seg2), `SAM` (кількість вибірок: 0 для 1 вибірки, 1 для 3 вибірок), біти `PRSEG[2:0] = Prop_Seg - 1`, біти `PHSEG1[2:0] = Phase_Seg1 - 1`;
   - `CNF3`: біти `PHSEG2[2:0] = Phase_Seg2 - 1`, біт `SOF` (вивід сигналу SOF на пін CLKOUT).

Грамотно розрахована конфігурація бітових таймінгів забезпечує стабільний обмін даними навіть при екстремальних довжинах кабельних ліній, надійно захищаючи систему від помилкової генерації аварійних прапорців.
