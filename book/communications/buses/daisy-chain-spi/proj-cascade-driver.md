# ⚙️ Практичний драйвер каскадної шини SPI з повнодуплексною діагностикою

Каскадне з'єднання мікросхем на шині SPI вимагає від драйвера мікроконтролера суворого дотримання протокольної дисципліни: зворотного порядку пакування слів у передавальний буфер, гарантованої часової витримки активного стану лінії вибору кристала (CS) та регулярної діагностики цілісності кільця за допомогою тестових сигнатур. У практичних вбудованих системах керування релейними блоками, світлодіодними драйверами та багатоканальними вимірювальними вузлами помилка в організації буферів або ігнорування часових параметрів засувки призводить до хаотичного мерехтіння виходів, спотворення даних та неможливості виявлення фізичного обриву шлейфа. Нижче наведено детальний аналіз архітектури, повну програмну реалізацію мовами C та сучасного C++, а також інженерні рекомендації щодо інтеграції драйвера з апаратними блоками прямого доступу до пам'яті (DMA).

---

### Архітектура та організація буферів драйвера

Головна відмінність каскадного драйвера від звичайного драйвера SPI полягає в способі адресації кінцевих вузлів. Оскільки каскад працює як єдиний розподілений зсувний регістр за принципом FIFO (First-In, First-Out), слово даних, яке мікроконтролер виштовхує в лінію MOSI найпершим, після `N` циклів зсуву опиняється в найвіддаленішій мікросхемі `IC_N`. Відповідно, слово для першої мікросхеми `IC_1`, розташованої найближче до процесора, має передаватися в лінію останнім.

Якщо прикладний код почне формувати апаратний буфер передачі напряму, це призведе до плутанини з індексами та ускладнить роботу системної логіки. Тому драйвер реалізує дворівневу модель пам'яті з подвійною буферизацією:

```
Прикладний рівень (Логічний масив):
  [ Вузол 0 (IC_1) ]  [ Вузол 1 (IC_2) ]  ...  [ Вузол N-1 (IC_N) ]
         │                   │                        │
         │ (Дзеркальне перевпорядкування драйвером)    │
         ▼                   ▼                        ▼
Апаратний буфер передачі (TX DMA Buffer):
  [ Байт 0..1 (IC_N) ]  [ Байт 2..3 (IC_N-1) ]  ...  [ Байт 2N-2..2N-1 (IC_1) ]
```

1. **Логічний тіньовий буфер (Logical Shadow Array):** Зберігає поточний стан каналів у природній послідовності (індекс `0` відповідає першій мікросхемі `IC_1`, індекс `N-1` — останній мікросхемі `IC_N`). Прикладні задачі записують нові значення виходів або зчитують результати вимірювань виключно через логічні індекси.
2. **Апаратний буфер передачі (Hardware TX Buffer):** Лінійний масив байтів, у який драйвер копіює дані з логічного буфера у зворотному порядку безпосередньо перед стартом передачі. Цей буфер вирівнюється в пам'яті під вимоги апаратного контролера DMA.
3. **Апаратний буфер прийому (Hardware RX Buffer):** Приймає сирий потік байтів, що повертається з виходу SDO останньої мікросхеми каскаду по лінії MISO. Після завершення передачі драйвер розпаковує його у зворотному порядку в логічний буфер прийому.

### Математика реверсування та порядок байтів (Endianness)

Під час побайтового пакування 16-бітних або 24-бітних слів у передавальний буфер виникає необхідність узгодження порядку передачі старшого біта (MSB-first) та порядку слів:
- Для каскаду з `N` мікросхем слово з логічним індексом `k` (де `k = 0 .. N - 1`) має займати позицію `(N - 1 - k)` у послідовності переданих слів.
- Усередині кожного 16-бітного слова старший байт (`MSB = word >> 8`) записується за адресою `offset = 2 · (N - 1 - k)`, а молодший байт (`LSB = word & 0xFF`) — за адресою `offset + 1`.
- Це гарантує, що апаратний SPI-модуль мікроконтролера, транслюючи байти у стандартному режимі MSB-First, спочатку виштовхне старший біт найвіддаленішого слова `IC_N`, а в кінці — молодший біт найближчого слова `IC_1`.

### Реалізація драйвера каскаду

Нижче наведено модульний драйвер, що містить повний цикл обслуговування транзакції: ініціалізацію, оновлення тіньових регістрів, апаратний обмін та функцію повнодуплексної самодіагностики з локалізацією пошкодженої мікросхеми.

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

#define DAISY_MAX_DEVICES   16
#define DAISY_WORD_SIZE     2   /* 16-бітні слова даних для кожного чипа */

typedef enum {
    DAISY_OK = 0,
    DAISY_ERR_INVALID_PARAM,
    DAISY_ERR_BUS_BUSY,
    DAISY_ERR_LOOPBACK_FAULT,
    DAISY_ERR_TIMEOUT
} daisy_status_t;

/* Структура конфігурації та стану каскаду */
typedef struct {
    uint8_t num_devices;                    /* Кількість мікросхем у каскаді */
    uint16_t shadow_tx[DAISY_MAX_DEVICES];  /* Логічний вихідний буфер */
    uint16_t shadow_rx[DAISY_MAX_DEVICES];  /* Логічний буфер зчитаних даних */
    uint8_t raw_tx[DAISY_MAX_DEVICES * 2];  /* Сирий буфер передачі (реверсний) */
    uint8_t raw_rx[DAISY_MAX_DEVICES * 2];  /* Сирий буфер прийому */
} daisy_cascade_t;

/* Прототипи функцій апаратно-залежного рівня (HAL) */
extern void hal_spi_cs_low(void);
extern void hal_spi_cs_high(void);
extern void hal_spi_delay_ns(uint32_t ns);
extern bool hal_spi_transfer_blocking(const uint8_t *tx, uint8_t *rx, size_t len);

/* Ініціалізація структури драйвера */
daisy_status_t daisy_init(daisy_cascade_t *dev, uint8_t num_devices) {
    if (!dev || num_devices == 0 || num_devices > DAISY_MAX_DEVICES) {
        return DAISY_ERR_INVALID_PARAM;
    }
    dev->num_devices = num_devices;
    memset(dev->shadow_tx, 0, sizeof(dev->shadow_tx));
    memset(dev->shadow_rx, 0, sizeof(dev->shadow_rx));
    hal_spi_cs_high();
    return DAISY_OK;
}

/* Оновлення логічного стану конкретного чипа в тіньовому буфері */
daisy_status_t daisy_set_device_value(daisy_cascade_t *dev, uint8_t index, uint16_t value) {
    if (!dev || index >= dev->num_devices) {
        return DAISY_ERR_INVALID_PARAM;
    }
    dev->shadow_tx[index] = value;
    return DAISY_OK;
}

/* Зчитування отриманого телеметричного значення конкретного чипа */
daisy_status_t daisy_get_device_feedback(const daisy_cascade_t *dev, uint8_t index, uint16_t *value) {
    if (!dev || !value || index >= dev->num_devices) {
        return DAISY_ERR_INVALID_PARAM;
    }
    *value = dev->shadow_rx[index];
    return DAISY_OK;
}

/* Повний синхронний обмін кадру каскаду */
daisy_status_t daisy_sync_transaction(daisy_cascade_t *dev) {
    if (!dev) return DAISY_ERR_INVALID_PARAM;

    const size_t total_bytes = dev->num_devices * DAISY_WORD_SIZE;

    /* Пакування слів у передавальний буфер у зворотному порядку (IC_N першим) */
    for (uint8_t i = 0; i < dev->num_devices; ++i) {
        uint8_t rev_idx = (dev->num_devices - 1) - i;
        uint16_t word = dev->shadow_tx[rev_idx];
        dev->raw_tx[i * 2 + 0] = (uint8_t)(word >> 8);    /* Старший байт (MSB) */
        dev->raw_tx[i * 2 + 1] = (uint8_t)(word & 0xFF);   /* Молодший байт (LSB) */
    }

    /* Початок кадру: переведення лінії CS у низький активний рівень */
    hal_spi_cs_low();
    hal_spi_delay_ns(50); /* Час випередження CS до першого фронту такту (t_setup_CS) */

    /* Повнодуплексна передача даних через апаратний SPI */
    bool ok = hal_spi_transfer_blocking(dev->raw_tx, dev->raw_rx, total_bytes);
    if (!ok) {
        hal_spi_cs_high();
        return DAISY_ERR_BUS_BUSY;
    }

    /* Завершення кадру: фіксація даних у вихідних засувках (Latch) */
    hal_spi_delay_ns(50); /* Час утримання CS після останнього фронту такту (t_hold_CS) */
    hal_spi_cs_high();
    hal_spi_delay_ns(100); /* Мінімальна тривалість імпульсу засувки (t_pulse_CS_high) */

    /* Розпакування прийнятих даних із черги MISO у логічний буфер */
    for (uint8_t i = 0; i < dev->num_devices; ++i) {
        uint8_t rev_idx = (dev->num_devices - 1) - i;
        uint16_t high_byte = dev->raw_rx[i * 2 + 0];
        uint16_t low_byte  = dev->raw_rx[i * 2 + 1];
        dev->shadow_rx[rev_idx] = (uint16_t)((high_byte << 8) | low_byte);
    }

    return DAISY_OK;
}

/* Комплексна діагностика цілісності кільця за допомогою тестової сигнатури */
daisy_status_t daisy_run_loopback_test(daisy_cascade_t *dev, uint8_t *first_faulty_index) {
    if (!dev || !first_faulty_index) return DAISY_ERR_INVALID_PARAM;

    const uint16_t test_magic = 0xA55A;

    /* Зберігаємо поточний робочий стан виходів */
    uint16_t saved_tx[DAISY_MAX_DEVICES];
    memcpy(saved_tx, dev->shadow_tx, sizeof(saved_tx));

    /* Заповнюємо каскад унікальними тестовими мітками */
    for (uint8_t i = 0; i < dev->num_devices; ++i) {
        dev->shadow_tx[i] = (uint16_t)(test_magic + i);
    }

    /* Перша транзакція: завантажуємо тестові сигнатури в зсувні регістри */
    daisy_status_t st = daisy_sync_transaction(dev);
    if (st != DAISY_OK) return st;

    /* Друга транзакція: виштовхуємо сигнатури на лінію MISO контролера */
    st = daisy_sync_transaction(dev);
    if (st != DAISY_OK) return st;

    /* Перевірка відповідності повернутих сигнатур очікуваним значенням */
    for (uint8_t i = 0; i < dev->num_devices; ++i) {
        uint16_t expected = (uint16_t)(test_magic + i);
        if (dev->shadow_rx[i] != expected) {
            *first_faulty_index = i;
            /* Відновлюємо робочий стан перед виходом */
            memcpy(dev->shadow_tx, saved_tx, sizeof(saved_tx));
            daisy_sync_transaction(dev);
            return DAISY_ERR_LOOPBACK_FAULT;
        }
    }

    /* Відновлюємо робочий стан */
    memcpy(dev->shadow_tx, saved_tx, sizeof(saved_tx));
    daisy_sync_transaction(dev);
    return DAISY_OK;
}

```cpp
#include <cstdint>
#include <cstddef>
#include <array>
#include <span>
#include <expected>
#include <algorithm>

/* Перелік статусів помилок драйвера */
enum class DaisyError {
    InvalidParameter,
    BusBusy,
    LoopbackFault,
    HardwareTimeout
};

/* Апаратний інтерфейс низького рівня (HAL Concept / Interface) */
class ISpiHal {
public:
    virtual ~ISpiHal() = default;
    virtual void setCs(bool active) = 0;
    virtual void delayNs(std::uint32_t ns) = 0;
    virtual bool transfer(std::span<const std::uint8_t> tx, std::span<std::uint8_t> rx) = 0;
};

/* Шаблонний драйвер каскаду з фіксованою кількістю пристроїв */
template <std::size_t NumDevices, typename WordType = std::uint16_t>
class DaisyChainDriver {
    static_assert(NumDevices > 0 && NumDevices <= 32, "Кількість пристроїв має бути від 1 до 32");
    static_assert(sizeof(WordType) == 2, "Підтримуються 16-бітні слова даних");

public:
    static constexpr std::size_t ByteCount = NumDevices * sizeof(WordType);

    explicit DaisyChainDriver(ISpiHal& hal) : m_hal(hal) {
        m_shadowTx.fill(0);
        m_shadowRx.fill(0);
        m_hal.setCs(false);
    }

    /* Встановлення значення виходу конкретної мікросхеми в тіньовому буфері */
    void setDeviceValue(std::size_t index, WordType value) noexcept {
        if (index < NumDevices) {
            m_shadowTx[index] = value;
        }
    }

    /* Зчитування останнього отриманого стану конкретної мікросхеми */
    [[nodiscard]] WordType getDeviceFeedback(std::size_t index) const noexcept {
        return (index < NumDevices) ? m_shadowRx[index] : WordType{0};
    }

    /* Виконання синхронного обміну кадру крізь увесь каскад */
    std::expected<void, DaisyError> syncTransaction() noexcept {
        // Формування реверсного апаратного буфера передачі (IC_N передається першим)
        for (std::size_t i = 0; i < NumDevices; ++i) {
            std::size_t revIdx = (NumDevices - 1) - i;
            WordType word = m_shadowTx[revIdx];
            m_rawTx[i * 2 + 0] = static_cast<std::uint8_t>(word >> 8);
            m_rawTx[i * 2 + 1] = static_cast<std::uint8_t>(word & 0xFF);
        }

        // Апаратний фреймінг: активуємо лінію CS (Active Low)
        m_hal.setCs(true);
        m_hal.delayNs(50); // t_setup(CS)

        bool ok = m_hal.transfer(std::span<const std::uint8_t>(m_rawTx),
                                 std::span<std::uint8_t>(m_rawRx));
        if (!ok) {
            m_hal.setCs(false);
            return std::unexpected(DaisyError::BusBusy);
        }

        // Завершення кадру: фіксація даних вихідними засувками мікросхем (Latch)
        m_hal.delayNs(50); // t_hold(CS)
        m_hal.setCs(false);
        m_hal.delayNs(100); // t_pulse(CS_High)

        // Розпакування зчитаних слів зворотного потоку
        for (std::size_t i = 0; i < NumDevices; ++i) {
            std::size_t revIdx = (NumDevices - 1) - i;
            auto hi = static_cast<WordType>(m_rawRx[i * 2 + 0]);
            auto lo = static_cast<WordType>(m_rawRx[i * 2 + 1]);
            m_shadowRx[revIdx] = static_cast<WordType>((hi << 8) | lo);
        }

        return {};
    }

    /* Комплексна перевірка цілісності ланцюга та локалізація обриву */
    std::expected<void, std::size_t> runDiagnosticLoopback() noexcept {
        constexpr WordType MagicBase = 0x5AA5;
        auto savedTx = m_shadowTx;

        // Завантаження унікального сигнатурного шаблону в каскад
        for (std::size_t i = 0; i < NumDevices; ++i) {
            m_shadowTx[i] = static_cast<WordType>(MagicBase + i);
        }

        // Дві транзакції: запис та наступне виштовхування даних у MISO
        if (!syncTransaction()) return std::unexpected(0);
        if (!syncTransaction()) return std::unexpected(0);

        // Перевірка повернення сигнатур
        for (std::size_t i = 0; i < NumDevices; ++i) {
            auto expected = static_cast<WordType>(MagicBase + i);
            if (m_shadowRx[i] != expected) {
                m_shadowTx = savedTx;
                syncTransaction();
                return std::unexpected(i); // Повертаємо індекс першого збійного чіпа
            }
        }

        m_shadowTx = savedTx;
        syncTransaction();
        return {};
    }

private:
    ISpiHal& m_hal;
    std::array<WordType, NumDevices> m_shadowTx{};
    std::array<WordType, NumDevices> m_shadowRx{};
    std::array<std::uint8_t, ByteCount> m_rawTx{};
    std::array<std::uint8_t, ByteCount> m_rawRx{};
};

### Конфігурація апаратних регістрів SPI мікроконтролера

Для коректної роботи з каскадом апаратний SPI-периферійний блок мікроконтролера (наприклад, STM32 чи NXP Kinetis) потребує специфічного налаштування:

1. **Програмне керування лінією CS (Software Slave Management, SSM):**
   У регістрах керування `SPI_CR1` біти `SSM = 1` та `SSI = 1` налаштовуються так, щоб апаратний контролер SPI не намагався автоматично смикати лінією NSS після кожного переданого байта. Якщо лінія CS підніметься у високий рівень посеред 24-байтового кадру, мікросхеми зафіксують проміжні незавершені дані у вихідних засувках, що викликає збій. Лінія CS повинна залишатися під повним програмним контролем драйвера або керуватися таймером.
2. **Вибір тактової фази та полярності:**
   Для більшості класичних зсувних регістрів (74HC595, TLC5940) встановлюється режим SPI Mode 0 (`CPOL = 0, CPHA = 0`). Це означає, що тактова лінія у стані спокою перебуває в нулі, а біти фіксуються за наростаючим фронтом такту.
3. **Розмір блоку даних (Data Frame Format):**
   Якщо мікроконтролер підтримує апаратний 16-бітний режим передачі (наприклад, біт `DFF = 1` або поле `DS[3:0] = 1111`), його активація дозволяє скоротити навантаження на процесор удвічі під час роботи з 16-бітними драйверами реле або ЦАП.

### Покроковий розбір критичних часових інтервалів

Під час роботи з каскадними драйверами необхідно контролювати чотири фундаментальні затримки інтерфейсу:

1. **Час випередження вибору кристала (`t_setup(CS)`):** Інтервал між падінням CS у нуль та першим активним фронтом такту SCLK. Якщо розпочати тактування занадто швидко, внутрішній дешифратор мікросхеми не встигне підготувати перший тригер, і стартовий біт буде втрачено.
2. **Час утримання після тактування (`t_hold(CS)`):** Інтервал між останнім фронтом SCLK та підняттям CS у високий рівень. Запобігає передчасному спрацьовуванню вихідної засувки до завершення запису останнього біта в зсувний регістр.
3. **Мінімальна тривалість імпульсу засувки (`t_w(CS_HIGH)`):** Час, протягом якого CS має залишатися у високому рівні перед початком наступної транзакції. Упродовж цього часу внутрішній формувач імпульсу замикає стан зсувного регістра у вихідних тригерах або запускає цикл перетворення вбудованого АЦП/ЦАП.
4. **Час затримки вихідних даних (`t_co` / `t_valid`):** Затримка появи валідного біта на виході SDO кожної мікросхеми після спадного фронту такту. У довгих ланцюгах ця затримка обмежує граничну швидкість опитування шини.

### Інтеграція з DMA та оптимізація високонавантажених каскадів

У системах керування світлодіодними відеоекранами або високошвидкісними багатоканальними збирачами даних процесор не може витрачати такти ядра на побайтовий обмін у блокуючому режимі. Для таких задач драйвер перемикають на роботу з прямим доступом до пам'яті (DMA):

1. **Подвійна буферизація DMA (Ping-Pong Buffering):** Контролер DMA налаштовується на роботу з двома апаратними буферами (`Buffer_A` та `Buffer_B`). Поки контролер передає `Buffer_A` по шині SPI, процесор розраховує новий кадр анімації або математичну фільтрацію у `Buffer_B`. Після завершення передачі буфери міняються місцями без жодної затримки в трансляції.
2. **Апаратна генерація імпульсу Latch через таймер:** У мікроконтролерах STM32 або ESP32 лінію CS/Latch часто прив'язують до виходу апаратного таймера або блоку гнучкого керування пам'яттю (FMC/FSMC). Таймер генерує імпульс фіксації автоматично після підрахунку рівно `N · K` тактів передавача, усуваючи необхідність програмного смикання ніжками GPIO в обробнику переривань.
3. **Керування кеш-пам'яттю (D-Cache Coherency):** На високопродуктивних ядрах ARM Cortex-M7 (наприклад, STM32H7 чи NXP i.MX RT) апаратні буфери DMA мають розміщуватися у некешованій пам'яті (`D1 Non-Cacheable SRAM`) або вимагають обов'язкового виклику інструкцій очищення та інвалідації кешу (`SCB_CleanDCache_by_Addr`, `SCB_InvalidateDCache_by_Addr`) перед початком і після завершення кожної транзакції. Ігнорування когерентності кешу призводить до того, що DMA передає застарілі дані з оперативної пам'яті, ігноруючи оновлення, зроблені процесором у кеші.

### Робота під керуванням операційних систем реального часу (RTOS)

Під час інтеграції драйвера каскаду в середовище FreeRTOS або Zephyr OS необхідно вирішити дві задачі багатопоточності:

1. **Захист від стану гонитви (Thread Safety):**
   Якщо різні системні задачі мають право керувати окремими виходами каскаду (наприклад, задача керування живленням вмикає реле на чипі `IC_1`, а задача аварійної сигналізації блимає світлодіодом на чипі `IC_4`), запис у тіньовий буфер `m_shadowTx` та запуск передачі захищаються бінарним семафором або м'ютексом (`std::mutex` або `osMutexWait`).
2. **Асинхронне блокування задачі під час DMA-обміну:**
   Замість активного очікування завершення передачі функція `syncTransaction()` викликає блокуюче очікування прямого сповіщення задачі (Direct-to-Task Notification у FreeRTOS). Обробник переривання DMA (DMA Transfer Complete ISR) піднімає лінію CS та надсилає сповіщення задачі, повертаючи її в стан готовності без марнування процесорного часу.

### Налагодження та діагностика за допомогою осцилографа

Під час перевірки каскаду на фізичному стенді підключають 4 канали цифрового осцилографа:
- Канал 1: Тактова лінія SCLK.
- Канал 2: Лінія даних MOSI (вхід першого чипа).
- Канал 3: Лінія даних MISO (вихід останнього чипа).
- Канал 4: Лінія вибору/засувки CS.

```
CH1 (SCLK):  ___/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_________
CH2 (MOSI):  ---< D_N >---< D_N-1 >---< D_1 >-----------
CH3 (MISO):  ---< Q_N >---< Q_N-1 >---< Q_1 >-----------
CH4 (CS):    ‾‾‾\______________________________/‾‾‾‾‾‾‾‾
                                               ▲
                                          Імпульс Latch
```

**Що перевіряти на осцилограмі:**
1. **Форма тактового сигналу:** Наявність дзвінка або завалу фронтів свідчить про надмірну паразитну ємність (необхідні буфери-повторювачі або демпферні резистори 33 Ом).
2. **Запас за часом встановлення (Setup Margin):** Рівень даних на вході SDI наступного чипа повинен стабілізуватися щонайменше за 15–20 нс до приходу активного фронту SCLK.
3. **Полярність стробу засувки:** Наростаючий фронт CS повинен з'являтися суворо після завершення останнього тактового імпульсу SCLK, витримуючи час `t_hold(CS) ≥ 25` нс.

### Низькорівневе налаштування потоків DMA (STM32 CMSIS)

Для досягнення максимальної швидкодії без завантаження процесорного ядра налаштування контролера DMA (на прикладі STM32 DMA2 Stream 3 для SPI1_TX та DMA2 Stream 0 для SPI1_RX) виконується за такими етапами:

1. **Конфігурація каналу прийому (RX DMA Stream):**
   - Регістр адреси периферії `DMA2_Stream0->PAR` встановлюється на адресу регістра даних SPI `(uint32_t)&(SPI1->DR)`.
   - Регістр адреси пам'яті `DMA2_Stream0->M0AR` вказує на масив `dev->raw_rx`.
   - Кількість елементів `DMA2_Stream0->NDTR` встановлюється рівною `total_bytes`.
   - Регістр керування `DMA2_Stream0->CR` налаштовується з бітами: `MINC = 1` (інкремент пам'яті), `DIR = 00` (напрямок «периферія-пам'ять»), `TCIE = 1` (дозвіл переривання після повного прийому кадру).

2. **Конфігурація каналу передачі (TX DMA Stream):**
   - Регістр адреси периферії `DMA2_Stream3->PAR` встановлюється на `(uint32_t)&(SPI1->DR)`.
   - Регістр адреси пам'яті `DMA2_Stream3->M0AR` вказує на масив `dev->raw_tx`.
   - Кількість передач `DMA2_Stream3->NDTR` дорівнює `total_bytes`.
   - Регістр керування `DMA2_Stream3->CR`: `MINC = 1`, `DIR = 01` (напрямок «пам'ять-периферія»).

3. **Запуск транзакції:**
   - Драйвер опускає лінію CS у низький рівень.
   - Активує запити DMA в блоці SPI (`SPI1->CR2 |= SPI_CR2_RXDMAEN | SPI_CR2_TXDMAEN`).
   - Вмикає потоки DMA: спочатку потік RX (`DMA2_Stream0->CR |= DMA_SxCR_EN`), потім потік TX (`DMA2_Stream3->CR |= DMA_SxCR_EN`).
   - Увімкнення потоку TX ініціює миттєву генерацію тактових імпульсів SCLK та виштовхування першого байта в лінію MOSI.

4. **Обробник переривання Transfer Complete (DMA2_Stream0_IRQHandler):**
   - Фіксує прапорець завершення транзакції `TCIF0`.
   - Вимикає запити DMA в регістрі `SPI1->CR2`.
   - Піднімає лінію CS у високий логічний рівень, генеруючи апаратний імпульс засувки (Latch).
   - Сповіщає прикладну задачу про готовність оновлених телеметричних даних.

### Прикладний сценарій: життєвий цикл роботи системи автоматики

У типовому промисловому контролері шасі автоматики на базі каскаду з 8 мікросхем TPIC6C595 робочий цикл драйвера виглядає наступним чином:

+-------------------------------------------------------------------+

|    - Скидання тіньових буферів у 0 (усі навантаження вимкнені)    |
|    - Виклик daisy_run_loopback_test(): перевірка цілісності шини   |
|    - Якщо виявлено обрив: блокування старту, тривога LED Alarm    |
+-------------------------------------------------------------------+
                                 │
                                 ▼
+-------------------------------------------------------------------+
| 2. РОБОЧИЙ ЦИКЛ КЕРУВАННЯ (ТАЙМЕР 100 Гц)                         |
|    - Прикладний алгоритм оновлює стани каналів у shadow_tx        |
|    - Запуск транзакції через DMA: daisy_sync_transaction()        |
|    - Зчитування зворотного діагностичного стану з shadow_rx       |
|    - Перевірка струмових прапорців захисту від перевантаження     |

+-------------------------------------------------------------------+
```

Така організація гарантує не лише швидке й детерміноване керування виконавчими механізмами, але й повний контроль фізичного стану кожного міліметра друкованої плати та кабельних з'єднань у реальному часі.

### Стан ліній при скиданні мікроконтролера та вибір підтягувальних резисторів

Під час запуску системи, перепрошивки або апаратного скидання (Reset) мікроконтролера його виводи GPIO перебувають у високоімпедансному стані (Hi-Z / Input Floating). Щоб запобігти аварійному вмиканню силових навантажень до повної ініціалізації драйвера:

1. **Підтяжка лінії CS/Latch до живлення (Pull-Up):**
   На платі встановлюють зовнішній підтягувальний резистор 4.7–10 кОм між лінією CS та шиною живлення 3.3 В. Це гарантує, що лінія CS за замовчуванням перебуває у неактивному високому рівні, запобігаючи випадковій фіксації шумів у вихідних засувках.
2. **Підтяжка тактової лінії SCLK до землі (Pull-Down):**
   Резистор 10 кОм на землю утримує лінію SCLK у нульовому стані режиму Mode 0, усуваючи паразитні імпульси від наводок сусідніх силових кіл.
3. **Керування лінією дозволу виходів (Output Enable, OE):**
   Більшість мікросхем каскаду (74HC595, TLC5940, TPIC6C595) мають вхід `OE` з активним нулем. Встановлення зовнішнього підтягувального резистора 10 кОм до V_DD на виводі `OE` утримує всі фізичні силові транзистори у вимкненому стані доти, доки мікроконтролер не завершить завантаження першого валідного кадру та явно не опустить `OE` в нуль програмним шляхом.

### Стратегії обробки помилок та аварійне відновлення

Коли функція самодіагностики `runDiagnosticLoopback()` виявляє невідповідність повернутих сигнатур, драйвер виконує алгоритм аварійного захисту обладнання:

1. **Локалізація точки відмови:** Перший індекс `i`, на якому очікувана сигнатура не збіглася з реальною, точно вказує на відмову лінії між мікросхемами `IC_i` та `IC_{i+1}`.
2. **Переведення виходів у безпечний стан:** Якщо мікросхеми мають вивід дозволу виходів (Output Enable, OE), контролер негайно виставляє пасивний рівень на цій лінії, вимикаючи всі силові ключі, щоб запобігти короткому замиканню або аварійному вмиканню навантаження.
3. **Реєстрація системної події:** Драйвер генерує аварійне повідомлення в журнал подій (Syslog / Flash Log) із зазначенням номера збійного каналу для ремонтної бригади.
4. **Спроба відновлення зв'язку:** Якщо дефект викликаний короткочасним просіданням живлення або перешкодою, драйвер виконує цикл перезавантаження шини: формує серію з 128 холостих тактів при високому рівні CS, скидає внутрішні кінцеві автомати мікросхем та повторює самодіагностику.

### Динамічне енергоспоживання та тепловий баланс шини

При безперервному оновленні каскаду на високих тактових частотах (наприклад, у світлодіодних екранах із частотою оновлення понад 100 Гц при тактовій частоті 10 МГц) необхідно враховувати динамічний струм перезаряду ємності ліній:

```
I_dyn = C_total · V_DD · f_sclk
```

Для каскаду з 24 мікросхем із сумарною ємністю тактової лінії `C_total = 200 пФ` при напрузі живлення `V_DD = 3.3 В` та тактовій частоті `f_sclk = 10 МГц`:
```
I_dyn = 200 · 10⁻¹² Ф · 3.3 В · 10 · 10⁶ Гц = 6.6 мА
```

Цей динамічний струм споживається виключно вихідним каскадом виводу SCLK мікроконтролера. Якщо тактова лінія живить десятки чипів, вихідний буфер процесора може відчутно нагріватися, а крутизна фронтів — деградувати. Для зняття теплового навантаження з кристала мікроконтролера в промислових дизайнах на виході SCLK завжди встановлюють зовнішній потужний логічний буфер серії 74LVC1G125 або 74AHC244 із допустимим вихідним струмом до 24–32 мА.
