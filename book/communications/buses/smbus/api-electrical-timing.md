# Специфікація електричних рівнів, таймінгів та сигналів SMBus

Цей довідник містить повні таблиці електричних порогів постійного струму (DC), динамічних часових параметрів (AC), інваріантів скидання шини, сигнальних інтерфейсів `SMBALERT#`, формату адреси сповіщення хоста ARA, протоколу динамічного призначення адрес ARP, кінцевого автомата інтерфейсу, кодів апаратних помилок та специфікації контрольної суми пакета PEC для системної шини SMBus версій 1.1, 2.0, 3.0 та 3.2. Довідник призначений для проєктувальників апаратних вузлів, розробників драйверів операційних систем та системного мікрокоду (BIOS/UEFI, ACPI, OpenBMC).

### 1. Електричні параметри постійного струму (DC Characteristics)

На відміну від стандарту I2C, де порогові напруги логічних рівнів жорстко залежать від поточної напруги шини живлення `V_DD`, специфікація SMBus 2.0/3.0 фіксує абсолютні значення логічних порогів, сумісні з рівнями TTL та CMOS. Це усуває проблему несумісності цифрових доменів 3.3 В та 5.0 В на спільній материнській платі.

| Параметр | Позначення | SMBus 2.0 (Стандарт) | SMBus 3.0 (Low-Voltage) | Одиниці | Умови тестування |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Напруга живлення шини** | `V_DD` | 3.0 – 5.5 | 1.35 – 3.3 | В | Діапазон живлення підтяжок |
| **Вхідна напруга логічного 0** | `V_IL` | ≤ 0.8 | ≤ 0.35 · V_DD | В | Максимальний поріг визнання 0 |
| **Вхідна напруга логічної 1** | `V_IH` | ≥ 2.1 | ≥ 0.65 · V_DD | В | Мінімальний поріг визнання 1 |
| **Вихідна напруга логічного 0** | `V_OL` | ≤ 0.4 | ≤ 0.4 | В | При втіканні струму `I_OL` |
| **Струм утримання нуля (Low Power)** | `I_OL:LP` | ≥ 350 | ≥ 350 | мкА | Клас низького енергоспоживання |
| **Струм утримання нуля (High Power)** | `I_OL:HP` | ≥ 4.0 | ≥ 4.0 | мА | Клас підвищеної навантаженості |
| **Струм витоку виводів (Hi-Z)** | `I_LI` | ≤ 5.0 | ≤ 5.0 | мкА | При `0.1 · V_DD ≤ V_PIN ≤ 0.9 · V_DD` |
| **Вхідна ємність виводу** | `C_IN` | ≤ 10 | ≤ 10 | пФ | Ємність на контактах SCL/SDA |

#### Запас завадостійкості та узгодження рівнів

Фіксація порогів логічних рівнів забезпечує чітко визначений статичний запас завадостійкості (*Noise Margin*):
* **Запас завадостійкості низького рівня:** `V_NML = V_IL - V_OL = 0.8 В - 0.4 В = 0.4 В`. Це означає, що імпульсна завада амплітудою до 400 мВ на лінії, утримуваній у нулі, не призведе до помилкового перемикання вхідних тригерів Шмітта.
* **Запас завадостійкості високого рівня:** `V_NMH = V_OH - V_IH = V_DD - 2.1 В`. Для шини з живленням 3.3 В цей запас становить `3.3 В - 2.1 В = 1.2 В`, а для 5-вольтової шини — `5.0 В - 2.1 В = 2.9 В`.

У версії SMBus 3.0 для роботи з сучасними енергоефективними мікропроцесорами (домени живлення 1.8 В, 1.35 В та 1.2 В) запроваджено масштабовані пороги `V_IL ≤ 0.35 · V_DD` та `V_IH ≥ 0.65 · V_DD`. При цьому для напруги `V_DD = 1.8 В` максимальний рівень нуля становить `0.63 В`, а мінімальний рівень одиниці — `1.17 В`.

#### Класи навантаження за вихідним струмом

Специфікація SMBus чітко розмежовує пристрої за здатністю втікання струму (*Current Sink Capability*):
1. **Клас низької потужності (Low-Power Class):** Пристрої цього класу гарантують втікання струму не менше `I_OL = 350 мкА` при напрузі на відкритому стоці не вище `0.4 В`. Ця категорія розроблена спеціально для інтелектуальних акумуляторних батарей (BMS), годинників реального часу (RTC) та малопотужних термодавачів, які живляться від автономних джерел. Низький робочий струм дозволяє мінімізувати паразитичний розряд батареї у черговому режимі.
2. **Клас високої потужності (High-Power Class):** Пристрої цього класу підтримують струм втікання до `I_OL = 4.0 мА`. Вони застосовуються в системних чипсетах материнських плат, серверних контролерах базової плати BMC та комутаторах живлення. Завдяки струму 4 мА такі контролери здатні швидко розряджати ємність довгих шин backplane-плат (до 400 пФ) із низькоомними підтяжками, забезпечуючи круті спадні фронти імпульсів.

#### Розрахунок номіналів резисторів підтяжки `R_P`

Правильний вибір опору резисторів підтяжки `R_P` визначається компромісом між максимально допустимим струмом через вихідні транзистори та граничним часом наростання сигналу через паразитну ємність шини `C_BUS`.

1. **Мінімальний опір `R_P(min)`** гарантує, що при відкритому стані транзистора струм, який протікає через нього від джерела `V_DD`, не перевищить граничний струм `I_OL`, а вихідна напруга залишиться нижчою за `V_OL = 0.4 В`:
```
R_P(min) = (V_DD - V_OL) / I_OL
```
* Для лінії з напругою `V_DD = 3.3 В` та пристроїв класу низької потужності (`I_OL = 350 мкА`):
```
R_P(min) = (3.3 - 0.4) / 0.00035 = 8285 Ом ≈ 8.2 кОм
```
* Для лінії з напругою `V_DD = 3.3 В` та пристроїв класу високої потужності (`I_OL = 4.0 мА`):
```
R_P(min) = (3.3 - 0.4) / 0.004 = 725 Ом ≈ 750 Ом
```

2. **Максимальний опір `R_P(max)`** обмежується максимально допустимим часом наростання фронту `t_R` від рівня 10% до 90% амплітуди:
```
t_R = ln( (V_DD - 0.1 · V_DD) / (V_DD - 0.9 · V_DD) ) · R_P · C_BUS
t_R = ln(0.9 / 0.1) · R_P · C_BUS ≈ 2.1972 · R_P · C_BUS
```
Для стандарту SMBus пороги вимірювання фронту визначено між `V_IL = 0.8 В` та `V_IH = 2.1 В`. Для лінії 3.3 В це дає коефіцієнт інтегрування `0.8473`:
```
R_P(max) = t_R / (0.8473 · C_BUS)
```
Якщо загальна ємність друкованих провідників, роз'ємів та входів мікросхем становить `C_BUS = 150 пФ`, то для забезпечення часу наростання `t_R ≤ 1000 нс` (режим 100 кГц) максимальний опір дорівнює:
```
R_P(max) = (1000 · 10⁻⁹) / (0.8473 · 150 · 10⁻¹²) ≈ 7868 Ом ≈ 7.5 кОм
```
Таким чином, для 3.3-вольтової шини стандартного класу оптимальним номіналом є резистор **`4.7 кОм – 6.8 кОм`**.

### 2. Динамічні часові параметри (AC Timing Characteristics)

Усі пристрої на шині SMBus зобов'язані дотримуватися часових обмежень для запобігання втраті синхронізації, фазовому тремтінню та зависанню ліній.

| Параметр | Позначення | SMBus 1.0/2.0 (100 кГц) | SMBus 3.0 (400 кГц) | SMBus 3.0 (1 МГц) | Одиниці |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Робоча тактова частота** | `f_SMB` | 10 – 100 | 10 – 400 | 10 – 1000 | кГц |
| **Тайм-аут зависання лінії в 0** | `t_TIMEOUT` | 25 – 35 | 25 – 35 | 25 – 35 | мс |
| **Тривалість низького стану SCL** | `t_LOW` | 4.7 – 35000 | 1.3 – 35000 | 0.5 – 35000 | мкс |
| **Тривалість високого стану SCL** | `t_HIGH` | 4.0 – 50 | 0.6 – 50 | 0.26 – 50 | мкс |
| **Тайм-аут виявлення шини в IDLE** | `t_HIGH:MAX` | ≤ 50 | ≤ 50 | ≤ 50 | мкс |
| **Розтягнення веденим на пакет** | `t_LOW:SEXT` | ≤ 25 | ≤ 25 | ≤ 10 | мс |
| **Розтягнення ведучим на байт** | `t_LOW:MEXT` | ≤ 10 | ≤ 10 | ≤ 10 | мс |
| **Час наростання сигналів** | `t_R` | ≤ 1000 | ≤ 300 | ≤ 120 | нс |
| **Час спадання сигналів** | `t_F` | ≤ 300 | ≤ 300 | ≤ 120 | нс |
| **Час утримання сигналу СТАРТ** | `t_HD:STA` | ≥ 4.0 | ≥ 0.6 | ≥ 0.26 | мкс |
| **Час встановлення повторного СТАРТ** | `t_SU:STA` | ≥ 4.7 | ≥ 0.6 | ≥ 0.26 | мкс |
| **Час встановлення сигналу СТОП** | `t_SU:STO` | ≥ 4.0 | ≥ 0.6 | ≥ 0.26 | мкс |
| **Час встановлення даних** | `t_SU:DAT` | ≥ 250 | ≥ 100 | ≥ 50 | нс |
| **Час утримання даних** | `t_HD:DAT` | ≥ 300 | ≥ 300 | ≥ 0 | нс |
| **Вільний стан шини між транзакціями** | `t_BUF` | ≥ 4.7 | ≥ 1.3 | ≥ 0.5 | мкс |

#### Детальний аналіз критичних динамічних інваріантів

1. **Таймаут аварійного відновлення `t_TIMEOUT` (25–35 мс):** Якщо будь-який пристрій утримує лінію SCL або SDA у стані нуля довше ніж 35 мс, вбудований таймер апаратного вузла шини формує внутрішнє переривання скидання. Кінцевий автомат повертається в початковий стан IDLE, а вихідні N-канальні транзистори вимикаються. Це унеможливлює зависання всієї материнської плати через збій одного чипа.
2. **Максимальний час високого рівня `t_HIGH:MAX` (50 мкс):** Якщо лінія SCL залишається у високому стані понад 50 мкс без генерації сигналу СТОП, пристрої вважають поточну транзакцію незавершеною та переводять шину в стан очікування нового сигналу СТАРТ. Це запобігає блокуванню ведених вузлів, якщо ведучий раптово припинив тактування посеред транзакції.
3. **Кумулятивне обмеження розтягування веденим `t_LOW:SEXT` (25 мс):** Встановлює жорсткий ліміт на суму всіх пауз низького рівня SCL, які ведений має право згенерувати під час передачі одного кадру (від СТАРТ до СТОП). Це захищає хост від ситуацій, коли ведений розтягує такт на 20 мс на кожному байті блоку з 32 байтів, блокуючи процесор на сотні мілісекунд.
4. **Кумулятивне обмеження розтягування ведучим `t_LOW:MEXT` (10 мс):** Обмежує максимальний час, на який ведучий контролер може призупинити тактування між сусідніми байтами транзакції (наприклад, під час очікування готовності системного DMA чи обробника переривання ОС).

### 3. Сигнал SMBALERT# та адреса сповіщення хоста ARA

Лінія **`SMBALERT#`** — це додаткова однопровідна магістраль асинхронних переривань з активним низьким рівнем і відкритим стоком, яка об'єднує всі ведені пристрої на платі.

#### Специфікація транзакції Alert Response Address (ARA)

Коли лінія `SMBALERT#` падає до рівня логічного нуля, хост-контролер ініціює спеціальну транзакцію зчитування за зарезервованою 7-бітною адресою сповіщення:
* **7-бітна адреса ARA:** `0001 100b` (`0x0C`);
* **8-бітний адресний байт на шині (з бітом Read = 1):** `0001 1001b` (`0x19`);
* **Формат транзакції:** `[START] → [0x19 (ARA + Rd)] → [ACK від ведених] → [7-бітний адресний байт веденого-переможця] → [NACK від хоста] → [STOP]`.

```
Хост:   [START] [ 0 0 0 1 1 0 0 | Rd=1 ]        [ACK]                   [NACK] [STOP]
Ведені:                                   [ACK]       [ D7 D6 D5 D4 D3 D2 D1 D0 ]
                                                       └───── Адреса веденого ─────┘
```

#### Зарезервовані системні адреси SMBus

Специфікація SMBus закріплює спеціальні 7-бітні адреси, які не можуть призначатися звичайним периферійним чипам:

| 7-бітна адреса | Шістнадцятковий код | Призначення |
| :--- | :--- | :--- |
| `0000 000b` | `0x00` | General Call (Загальний виклик I2C) |
| `0000 001b` | `0x01` | CBus Compatibility (Сумісність із шиною CBus) |
| `0000 010b` | `0x02` | Reserved for different bus formats |
| `0000 011b` | `0x03` | Reserved for future use |
| `0001 000b` | `0x08` | SMBus Host (Адреса ведучого пристрою для Host Notify) |
| `0001 001b` | `0x09` | Smart Battery Charger (Контролер зарядного пристрою) |
| `0001 010b` | `0x0A` | Smart Battery Selector (Селектор акумуляторів) |
| `0001 011b` | `0x0B` | Smart Battery System (Інтелектуальна акумуляторна батарея) |
| `0001 100b` | `0x0C` | SMBus Alert Response Address (ARA) |
| `0101 000b` | `0x28` | Access.bus default address |
| `1100 001b` | `0x61` | SMBus Device Default Address (ARP-ініціалізація) |
| `1111 0xxb` | `0x78 – 0x7B` | 10-bit slave addressing prefix |

### 4. Протокол динамічного виділення адрес ARP (Address Resolution Protocol)

У версії SMBus 2.0 стандартизовано механізм динамічного призначення адрес **ARP** (*Address Resolution Protocol*). Він усуває конфлікти адрес однакових мікросхем на одній шині (наприклад, кількох однотипних термодавачів чи планок пам'яті).

#### Структура унікального ідентифікатора UDID (128 біт)

Кожен ARP-сумісний пристрій містить унікальний 128-бітний ідентифікатор **UDID** (*Unique Device Identifier*), який формується з таких полів:
1. **Device Capabilities (16 біт):** Описує підтримувані швидкості шини, тип адресації та вимоги до PEC.
2. **Version / Revision (16 біт):** Версія специфікації UDID та ревізія кремнієвого кристала виробника.
3. **Vendor ID (16 біт):** 16-бітний ідентифікатор виробника, зареєстрований організацією PCI-SIG.
4. **Device ID (16 біт):** Код моделі мікросхеми, визначений виробником.
5. **Interface (16 біт):** Тип протокольного інтерфейсу пристрою (IPMI, SBS, PMBus).
6. **Subsystem Vendor ID (16 біт):** Ідентифікатор постачальника підсистеми.
7. **Subsystem Device ID (16 біт):** Код підсистеми.
8. **Vendor-Specific ID (32 біти):** Унікальний серійний номер конкретного екземпляра мікросхеми.

#### Команди протоколу ARP

Взаємодія виконується зарезервованою адресою за замовчуванням `0x61` (*SMBus Device Default Address*):
* **Prepare to ARP:** Готує всі неналаштовані пристрої до процесу перерахунку.
* **Reset Device:** Скидає поточні призначені адреси пристроїв у стан за замовчуванням.
* **Get UDID (General / Directed):** Зчитує 128-бітний ідентифікатор пристрою. Усі неконфігуровані вузли одночасно беруть участь в арбітражі на лінії SDA; пристрій із меншим числовим значенням UDID виграє арбітраж і першим передає свій повний ідентифікатор.
* **Assign Address:** Хост призначає веденому-переможцю постійну 7-бітну робочу адресу. Після цього пристрій виходить із процесу виявлення і звільняє шину для конфігурації наступних вузлів.

### 5. Контрольна сума пакета PEC (Packet Error Checking)

Контрольна сума **PEC** обчислюється за стандартом циклічного надлишкового коду **CRC-8** над усіма байтами повідомлення, починаючи від найпершого адресного байта після сигналу СТАРТ.

#### Математична специфікація алгоритму CRC-8-SMBus

```
Поліном-генератор: C(x) = x⁸ + x² + x + 1
Шістнадцяткове представлення: 0x07 (нормальне) / 0x83 (реверсне)
Початкове значення регістра: 0x00
Пряме чи реверсне подання:   Пряме (MSB передається першим)
Фінальний XOR:               0x00 (без інверсії)
```

#### Охоплення байтів транзакцій контрольною сумою PEC

1. **Write Byte з PEC:**
   `CRC8( [Slave_Addr + Wr] + [Command_Code] + [Data_Byte] )`
2. **Write Word з PEC:**
   `CRC8( [Slave_Addr + Wr] + [Command_Code] + [Data_Low] + [Data_High] )`
3. **Read Word з PEC (з урахуванням Repeated START):**
   `CRC8( [Slave_Addr + Wr] + [Command_Code] + [Slave_Addr + Rd] + [Data_Low] + [Data_High] )`
4. **Block Read з PEC:**
   `CRC8( [Slave_Addr + Wr] + [Command_Code] + [Slave_Addr + Rd] + [Byte_Count = N] + [Data_1] + ... + [Data_N] )`

При виявленні невідповідності байта PEC під час транзакції запису ведений зобов'язаний виставити сигнал **NACK** на такті передачі PEC і не записувати прийняті дані у внутрішні регістри. При читанні хост-контролер перевіряє PEC локально: у разі неспівпадіння драйвер відкидає дані та генерує код помилки введення-виведення (наприклад, `-EBADMSG` або `-EIO` у ядрі Linux).

### 6. Кінцевий автомат станів інтерфейсу (SMBus Interface State Machine)

Кожен апаратний контролер або інтегрований у мікроконтролер вузол SMBus реалізує детермінований кінцевий автомат (*Finite State Machine*, FSM). Логіка станів визначає реакцію пристрою на зовнішні сигнальні події та забезпечує безумовне відновлення працездатності:

1. **Стан `IDLE` (Шина вільна):** Обидві сигнальні лінії SCL та SDA перебувають у стані високої напруги `V_DD` довше ніж час `t_BUF`. Вхідні компаратори відстежують спадний перепад напруги на лінії SDA при високому рівні SCL (сигнал СТАРТ).
2. **Стан `START_DETECTED` (Виявлено старт):** Апаратний лічильник бітів скидається в 0. Запускається таймер контролю таймауту низького стану `t_TIMEOUT`.
3. **Стан `ADDR_RX` (Прийом адреси):** Протягом наступних 8 тактів SCL вхідний зсувний регістр приймає 7 бітів адреси та 1 біт напрямку `R/W`.
4. **Стан `ADDR_DECODE` (Декодування адреси):** Логіка порівнює прийняті 7 бітів із власною адресою пристрою, адресою General Call (`0x00`) та адресою ARA (`0x0C`). Якщо адресу розпізнано — чип виставляє рівень логічного нуля на такті ACK (9-й такт SCL). Якщо адреса чужа — чип повертається в режим очікування сигналу СТОП без генерації ACK.
5. **Стан `COMMAND_RX` (Прийом коду команди):** Для операцій запису та складеного читання ведений приймає 8-бітний код регістру. Запускається акумулятор контрольної суми CRC-8.
6. **Стан `DATA_TRANSFER` (Передача / Прийом даних):** Виконується побайтовий обмін із контролем ліміту розтягування такту `t_LOW:SEXT`. Кожен прийнятий або надісланий байт подається на вхід поліноміального ділення CRC.
7. **Стан `PEC_CHECK` (Перевірка контрольної суми):** Якщо сесія конфігурована з підтримкою PEC, після останнього байта даних хост передає, а ведений звіряє 8-бітний залишок CRC. При неспівпадінні виставляється біт помилки у внутрішньому регістрі статусу, а оновлення цільових регістрів блокується.
8. **Стан `TIMEOUT_RECOVERY` (Аварійне скидання за таймаутом):** Якщо таймер тривалості низького рівня SCL або SDA перевищує 35 мс, кінцевий автомат примусово перериває будь-яку поточну транзакцію, закриває вихідні польові транзистори у високоімпедансний стан Hi-Z та скидає покажчики буферів у стан за замовчуванням.

### 7. Коди помилок та статуси апаратних контролерів SMBus

Апаратні контролери шини SMBus (наприклад, інтегровані в південні мости чипсетів Intel серій ICH/PCH чи AMD FCH) фіксують стан виконання транзакцій у спеціалізованому регістрі статусу хоста `SMBHSTSTS`:

* **`INTR` (All Done / Interrupt Status):** Транзакція завершилася успішно, всі байти передано, отримано всі очікувані сигнали ACK.
* **`DEV_ERR` (Device Error):** Ведений пристрій виставив сигнал NACK на фазі передачі адреси або даних. Свідчить про відсутність пристрою за вказаною адресою або його неготовність прийняти команду.
* **`BUS_ERR` (Bus Collision / Transaction Collision):** Виявлено несанкціонований сигнал СТАРТ або СТОП посеред передачі байта даних, або втрачено арбітраж у багатомайстровій конфігурації.
* **`FAILED` (Hardware Timeout / Bus Hang):** Спрацював апаратний таймер таймауту `t_TIMEOUT` через утримання лінії SCL чи SDA в нулі довше 35 мс. Контролер автоматично переводить виводи в Hi-Z.
* **`SMBALERT_STS` (SMBALERT Signal Asserted):** Зафіксовано спадний перепад напруги на виводі `SMBALERT#`. Сигналізує системному ПЗ про необхідність виконання процедури ARA.

### 8. Рекомендації щодо проєктування друкованих плат та захисту ліній (PCB Layout & Protection)

Для забезпечення надійної роботи шини SMBus в умовах промислових завад рекомендується дотримуватися таких апаратних правил:
1. **Хвильовий опір та довжина відгалужень:** Хвильовий опір поодиноких провідників SCL/SDA рекомендується підтримувати на рівні `Z_0 = 50–60 Ом`. Довжина відгалужень (*stubs*) від магістралі до виводів мікросхем не повинна перевищувати 10 см для запобігання відбиттям сигналів у швидкісних режимах 400 кГц та 1 МГц.
2. **Захист від статичної електрики (ESD Protection):** На лініях, які виходять на зовнішні роз'єми (наприклад, роз'єм підключення знімного акумулятора ноутбука), обов'язково встановлюються супресори TVS з ультранизькою паразитними ємністю (`C_TVS < 5 пФ`), щоб не спотворювати час наростання фронтів `t_R`.
3. **Демпферні резистори:** Послідовно з виводами SCL та SDA поруч із мікросхемами рекомендується встановлювати резистори номіналом `R_S = 22–33 Ом`. Вони обмежують піковий струм розряду паразитної ємності та гасять дзвін (*ringing*) на спадних фронтах імпульсів.
