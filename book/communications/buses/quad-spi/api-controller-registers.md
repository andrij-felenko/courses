# 📋 Регістрова архітектура контролерів Quad-SPI

Неможливо забезпечити надійну роботу зовнішньої Flash-пам'яті безпосередньо з адресного простору процесора або реалізувати швидкісне оновлення прошивки без розуміння низькорівневого інтерфейсу апаратного контролера Quad-SPI. Цей довідник визначає регістрову структуру, призначення бітових полів, конечні автомати транзакцій та конфігураційні матриці периферійних модулів QSPI (на прикладі архітектур STMicroelectronics QUADSPI та NXP FlexSPI), які керують 4-лінійною шиною, апаратним опитуванням статусу та трансляцією адреси в режимі прямого виконання коду (Execute-in-Place, XIP).

---

### Організація регістрового простору контролера

Апаратний контролер QSPI у мікроконтролері є інтелектуальним мостом між внутрішньою системною шиною (AHB або AXI) та зовнішніми сигнальними лініями `CS#`, `CLK`, `IO0`, `IO1`, `IO2`, `IO3`. Контролер містить власний конфігурований тактовий генератор, буфери FIFO, апаратний лічильник байтів і цифровий скінченний автомат (Finite State Machine, FSM), який формує часові діаграми згідно з протоколом конкретної мікросхеми пам'яті.

Базова адреса периферійного модуля QSPI прив'язана до внутрішньої шини периферії (наприклад, `0xA0001000` у STM32F7/H7 або `0x400DA000` у сімействі i.MX RT).

```
                        Карта регістрів контролера QSPI (STM32)
   Зсув   │ Регістр       │ Опис
  ────────┼───────────────┼───────────────────────────────────────────────────────
   0x00   │ QUADSPI_CR    │ Регістр керування: тактування, переривання, режими FSM
   0x04   │ QUADSPI_DCR   │ Конфігурація пристрою: розмір Flash, затримки CS
   0x08   │ QUADSPI_SR    │ Регістр статусу: прапорці стану, заповнення FIFO, зайнятість
   0x0C   │ QUADSPI_FCR   │ Регістр очищення прапорців статусу
   0x10   │ QUADSPI_DLR   │ Регістр довжини даних (кількість байтів у транзакції)
   0x14   │ QUADSPI_CCR   │ Конфігурація зв'язку: параметри 5 фаз транзакції
   0x18   │ QUADSPI_AR    │ Регістр адреси Flash-пам'яті
   0x1C   │ QUADSPI_ABR   │ Регістр службових байтів (Alternate / Mode Bits)
   0x20   │ QUADSPI_DR    │ Регістр даних (доступ до приймально-передавального FIFO)
   0x24   │ QUADSPI_PSMKR │ Маска для режиму автоматичного опитування статусу
   0x28   │ QUADSPI_PSMAR │ Очікуване значення для збігу статусу (Match Value)
   0x2C   │ QUADSPI_PIR   │ Інтервал опитування (період між повторними запитами)
   0x30   │ QUADSPI_LPTR  │ Таймер переходу в енергоощадний стан (CS High Timeout)
```

### Детальний опис бітових полів регістрів

#### 1. QUADSPI_CR (Control Register) — Зсув `0x00`

Регістр `QUADSPI_CR` визначає глобальні параметри функціонування контролера: тактовий поділ, рівні спрацьовування FIFO, активацію DMA та переривань.

```
 31         24 23 22 21 20 19 18 17 16 15 14 13 12  8  7  6  5  4  3  2  1  0
┌─────────────┬──┬──┬──┬──┬──┬──┬──┬──┬──────────────┬──┬──┬──┬──┬──┬──┬──┬──┐
│  PRESCALER  │PM│AP│TO│SM│FT│TC│TE│- │    FTHRES    │- │- │- │SS│TC│DM│AB│EN│
└─────────────┴──┴──┴──┴──┴──┴──┴──┴──┴──────────────┴──┴──┴──┴──┴──┴──┴──┴──┘
```

* **`EN` (біт 0)** — *Enable*: `1` — увімкнення периферійного модуля; `0` — вимкнення та скидання внутрішніх лічильників. Вимикати модуль дозволено лише тоді, коли прапорець `BUSY` у регістрі статусу дорівнює нулю, інакше поточний обмін обривається в довільному стані шини.
* **`ABORT` (біт 1)** — *Abort request*: програмне переривання поточної транзакції. Запис `1` змушує контролер негайно підняти `CS#`, дочекатися завершення поточного такту `CLK` та встановити прапорець завершення передачі `TCF`.
* **`DMAEN` (біт 2)** — *DMA Enable*: активація запитів прямого доступу до пам'яті (DMA Request) під час досягнення порогу заповнення FIFO.
* **`TCEN` (біт 3)** — *Timeout Counter Enable*: увімкнення таймера `LPTR` для автоматичного відпускання шини (підняття `CS#` у логічну одиницю) у режимі Memory-Mapped, якщо до Flash тривалий час немає звернень процесора.
* **`SSHIFT` (біт 4)** — *Sample Shift*: затримка вибірки даних на пів такту. На частотах понад 80 МГц затримка поширення сигналу по друкованій платі `t[PD]` зсуває валідні дані щодо фронту такту; `SSHIFT = 1` переносить зчитування вхідних ліній на наступний спадний фронт, запобігаючи спотворенню бітів.
* **`FTHRES` (біти 12:8)** — *FIFO Threshold*: визначає кількість вільних або зайнятих слів у FIFO (від 0 до 31), яка генерує прапорець `FTF` та запит DMA/переривання. Значення `3` означає генерацію події при наявності 4 байтів.
* **`TEIE`, `TCIE`, `FTIE`, `SMIE`, `TOIE` (біти 16, 17, 18, 19, 20)** — *Interrupt Enables*: дозволи переривань за помилкою передачі (Transfer Error), завершенням передачі (Transfer Complete), досягненням порогу FIFO, збігом статусу (Status Match) та тайм-аутом.
* **`APMS` (біт 22)** — *Automatic Polling Mode Stop*: поведінка контролера при успішному збігу статусу. `0` — продовжувати опитування без зупинки; `1` — автоматично зупинити операцію, підняти `CS#` та деактивувати кінцевий автомат.
* **`PMM` (біт 23)** — *Polling Match Mode*: логіка перевірки маски. `0` — логічне «І» (усі замасковані біти мають збігтися); `1` — логічне «АБО» (достатньо збігу хоча б одного біта з маскованих).
* **`PRESCALER` (біти 31:24)** — *Clock Prescaler*: дільник частоти вхідного тактового сигналу шини AHB/AXI:
  ```
  f[SCK] = f[AHB] ÷ (PRESCALER + 1)
  ```
  При вхідній частоті 200 МГц значення `PRESCALER = 1` формує частоту шини QSPI 100 МГц; `PRESCALER = 0` виводить максимальну частоту 200 МГц.

#### 2. QUADSPI_DCR (Device Configuration Register) — Зсув `0x04`

Регістр `QUADSPI_DCR` описує фізичні властивості підключеної мікросхеми пам'яті.

* **`CKMODE` (біт 0)** — *Clock Mode*: стан тактової лінії `CLK` при неактивному `CS#`. `0` — режим Mode 0 (CLK у низькому стані, CPOL = 0); `1` — режим Mode 3 (CLK у високому стані, CPOL = 1). Більшість мікросхем SPI/QSPI Flash підтримують обидва режими.
* **`CSHT` (біти 10:8)** — *Chip Select High Time*: мінімальна кількість тактів (від 1 до 8), протягом яких лінія `CS#` залишається у високому рівні між двома послідовними транзакціями (параметр `t[CS_HIGH]` у даташиті Flash, зазвичай 10–50 нс). Недотримання цієї паузи призводить до збою внутрішнього дешифратора Flash.
* **`FSIZE` (біти 20:16)** — *Flash Memory Size*: показник степеня обсягу пам'яті у байтах за формулою:
  ```
  Ємність = 2^(FSIZE + 1) байтів
  ```
  * Для мікросхеми 128 Мбіт (16 МБайт = `2^24` байтів): `FSIZE = 24 - 1 = 23` (`0x17`).
  * Для мікросхеми 256 Мбіт (32 МБайт = `2^25` байтів): `FSIZE = 25 - 1 = 24` (`0x18`).
  * Для мікросхеми 512 Мбіт (64 МБайт = `2^26` байтів): `FSIZE = 26 - 1 = 25` (`0x19`).
  У режимі Memory-Mapped звернення процесора поза межі діапазону, заданого `FSIZE`, генерують апаратну помилку шини (Bus Fault).

#### 3. QUADSPI_SR (Status Register) — Зсув `0x08`

Регістр статусу відображає поточний стан кінцевого автомата, прапорці помилок та рівень наповнення буфера FIFO.

* **`TEF` (біт 0)** — *Transfer Error Flag*: встановлюється апаратно при некоректній спробі запису в заблоковані регістри під час активної передачі або при помилці адресації в режимі Memory-Mapped.
* **`TCF` (біт 1)** — *Transfer Complete Flag*: фіксує успішне завершення передачі всієї кількості байтів, заданої в регістрі `QUADSPI_DLR`.
* **`FTF` (біт 2)** — *FIFO Threshold Flag*: встановлюється, коли кількість байтів у FIFO досягає або перевищує значення `FTHRES` (у режимі читання) або коли у FIFO з'являється достатньо місця для запису (у режимі запису).
* **`SMF` (біт 3)** — *Status Match Flag*: сигналізує про успішний збіг значення опитуваного регістра пам'яті із заданим шаблоном у режимі `Automatic Status-Polling`.
* **`TOF` (біт 4)** — *Timeout Flag*: сигналізує про спрацьовування таймера очікування `LPTR`.
* **`BUSY` (біт 5)** — *Busy Flag*: активний логічний стан `1` вказує, що на фізичній шині відбувається передача або лінія `CS#` утримується в активному низькому рівні.
* **`FLEVEL` (біти 13:8)** — *FIFO Level*: поточна кількість доступних байтів у 32-бітному буфері FIFO (від 0 до 32).

---

#### 4. QUADSPI_CCR (Communication Configuration Register) — Зсув `0x14`

Центральний регістр конфігурації зв'язку, який визначає формат кадру протоколу для кожної операції.

```
 31 30 29 28 27 26 25 24 23 22    18 17 16 15 14 13 12 11 10  9  8  7        0
┌──┬──┬──┬──┬─────┬─────┬──┬────────┬─────┬─────┬─────┬─────┬─────┬───────────┐
│DD│- │- │SI│FMODE│DMODE│- │  DCYC  │ABSIZ│ABMOD│ADSIZ│ADMOD│IMODE│INSTRUCTION│
└──┴──┴──┴──┴─────┴─────┴──┴────────┴─────┴─────┴─────┴─────┴─────┴───────────┘
```

* **`INSTRUCTION` (біти 7:0)** — 8-бітний код операції (опкод), який видається у фазі команди (наприклад, `0xEB` для Fast Read Quad I/O або `0x32` для Quad Page Program).
* **`IMODE` (біти 9:8)** — *Instruction Mode*: кількість ліній для передачі опкоду:
  * `00` — Фаза інструкції відсутня (пропуск команди у режимі Continuous Read);
  * `01` — Передача по 1 лінії (`IO0`);
  * `10` — Передача по 2 лініях (`IO0..IO1`);
  * `11` — Передача по 4 лініях (`IO0..IO3` у режимі QPI).
* **`ADMODE` (біти 11:10)** — *Address Mode*: конфігурація ліній фази адреси (`00` — немає, `01` — 1 лінія, `10` — 2 лінії, `11` — 4 лінії).
* **`ADSIZE` (біти 13:12)** — *Address Size*: розрядність адреси (`00` — 8 біт, `01` — 16 біт, `10` — 24 біти / 3 байти, `11` — 32 біти / 4 байти).
* **`ABMODE` (біти 15:14)** — *Alternate Bytes Mode*: режим передачі службових байтів режиму (`00` — немає, `01` — 1 лінія, `10` — 2 лінії, `11` — 4 лінії).
* **`ABSIZE` (біти 17:16)** — *Alternate Bytes Size*: довжина поля Alternate Bytes (`00` — 8 біт / 1 байт, `01` — 16 біт, `10` — 24 біти, `11` — 32 біти).
* **`DCYC` (біти 22:18)** — *Dummy Cycles Count*: кількість холостих тактів (від 0 до 31), протягом яких лінії перебувають у Hi-Z для компенсації часу вибірки матриці Flash (`t[ACC]`).
* **`DMODE` (біти 25:24)** — *Data Mode*: режим передачі корисних даних (`00` — фаза даних відсутня, `01` — 1 лінія, `10` — 2 лінії, `11` — 4 лінії).
* **`FMODE` (біти 27:26)** — *Functional Mode*: вибір функціонального режиму роботи контролера:
  * `00` — **Indirect Write**: запис даних у Flash через FIFO або DMA;
  * `01` — **Indirect Read**: зчитування даних із Flash через FIFO або DMA;
  * `10` — **Automatic Status-Polling**: періодичне опитування регістра статусу Flash до виконання умови збігу;
  * `11` — **Memory-Mapped**: відображення пам'яті в системний адресний простір для виконання коду XIP.
* **`SIOO` (біт 28)** — *Send Instruction Only Once*: надсилати байт інструкції лише в першій транзакції. У режимі Memory-Mapped активація цього біта забезпечує апаратний перехід у режим безперервного читання (0-4-4).
* **`DDRM` (біт 31)** — *Double Data Rate Mode*: активація передачі даних по обох фронтах тактового сигналу (Dual Edge Sampling).

#### 5. Допоміжні регістри передачі, таймінгу та DMA

* **`QUADSPI_DLR` (Data Length Register, Зсув `0x10`)**: визначає кількість байтів даних для передачі в непрямих режимах. Значення поля розраховується як `DLR = N - 1`, де `N` — необхідна кількість байтів (наприклад, для зчитування 3 байтів JEDEC ID у регістр записується `2`).
* **`QUADSPI_AR` (Address Register, Зсув `0x18`)**: містить 32-бітну адресу комірки пам'яті для операцій у непрямому режимі (Indirect Mode). Запис у цей регістр автоматично запускає виконання транзакції кінцевим автоматом.
* **`QUADSPI_ABR` (Alternate Bytes Register, Зсув `0x1C`)**: містить шаблон службових бітів (Mode Bits), які видаються безпосередньо після фази адреси. Значення `0xA5` активує режим безперервного читання XIP.
* **`QUADSPI_DR` (Data Register, Зсув `0x20`)**: вікно доступу до буфера FIFO. Запис у регістр поміщає дані у передавальний чергу, а зчитування витягує прийняті байти. Підтримує 8-, 16- та 32-бітний доступ із автоматичним пакуванням/розпакуванням слів.
* **`QUADSPI_PSMKR` / `QUADSPI_PSMAR` (Polling Status Mask/Match Registers, Зсув `0x24` / `0x28`)**: визначають бітову маску та очікуваний шаблон для апаратного опитування регістрів Flash. Під час роботи контролер обчислює вираз `(Status_Byte & PSMKR) == (PSMAR & PSMKR)`. Якщо результат істинний, фіксується подія `SMF`.
* **`QUADSPI_PIR` (Polling Interval Register, Зсув `0x2C`)**: задає кількість періодів тактового сигналу `CLK`, які контролер вичікує між двома послідовними спробами зчитування статусу пам'яті. Це запобігає монополізації шини Flash постійними опитуваннями.
* **`QUADSPI_LPTR` (Low-Power Timeout Register, Зсув `0x30`)**: лічильник тактів неактивності у режимі Memory-Mapped. Якщо протягом заданої кількості тактів ядро процесора не звертається до Flash, контролер автоматично піднімає сигнал `CS#`, дозволяючи мікросхемі пам'яті перейти в стан зниженого енергоспоживання (Standby Current < 10–25 мкА).

### Апаратний буфер FIFO та взаємодія з контролером DMA

Контролер QSPI містить 32-байтний двонаправлений буфер FIFO, організований як черга FIFO глибиною 8 слів (кожне слово шириною 32 біти). Буфер розв'язує за часом повільну серійну передачу на зовнішній шині та швидкісні пакетні транзакції системної шини AHB/AXI.

#### Механізм пакування та розпакування слів
Контролер автоматично адаптує розрядність системного доступу:
* При 32-бітному записі у `QUADSPI_DR` слово розбивається на 4 окремі байти, які послідовно подаються на 4-бітний зсувний регістр (Shift Engine);
* При 8-бітному доступі записується один байт, а решта байтів слова залишаються незмінними;
* У фазі зчитування кожні два послідовні нібли з ліній `IO0..IO3` збираються в байт, а 4 байти формують повне 32-бітне слово, доступне для зчитування процесором або контролером DMA.

#### Арбітраж запитів DMA
При активації біта `DMAEN` у регістрі `QUADSPI_CR` контролер формує апаратний сигнал запиту до шини DMA (наприклад, MDMA або DMA1/DMA2 у STM32H7):
1. **У режимі читання (Indirect Read)**: сигнал DMA Request виставляється щоразу, коли кількість зчитаних слів у FIFO перевищує поріг `FTHRES`. DMA-контролер виконує пакетну передачу (Burst Transfer на 4 або 8 слів) без участі ядра процесора.
2. **У режимі запису (Indirect Write)**: сигнал DMA Request виставляється, коли у FIFO звільняється кількість слів, задана порогом `FTHRES`, що забезпечує безперервне надходження даних під час програмування сторінки.

### Порівняльна архітектура: Таблиця пошуку інструкцій NXP FlexSPI (LUT)

На відміну від підходу STMicroelectronics, де параметри кожної фази жорстко розкодовуються бітовими полями регістра `CCR`, контролер **NXP FlexSPI** (мікроконтролери i.MX RT1050/1060/1170) використовує табличну архітектуру **Look-Up Table (LUT)**.

Простір LUT складається з 64 регістрів, розбитих на 16 послідовностей по 4 інструкції. Кожен запис LUT містить пару: `[Код_інструкції (6 біт) | Кількість_ліній (2 біти) | Операнд (8 біт)]`.

```
                  Формат команди LUT контролера FlexSPI (NXP)
 15          10  9  8  7                   0
┌──────────────┬─────┬──────────────────────┐
│  INSTR_CODE  │ NUM │       OPERAND        │
│  (Опкод FSM) │_PADS│ (Значення або байти) │
└──────────────┴─────┴──────────────────────┘
```

#### Базові команди автомата FlexSPI:
1. `CMD_SDR (0x01)` — видати опкод із поля `OPERAND` (наприклад, `0xEB`);
2. `ADDR_SDR (0x02)` — видати адресу розрядністю `OPERAND` бітів (наприклад, 24 або 32);
3. `MODE8_SDR (0x05)` — передати 8-бітний службовий байт режиму Performance Enhance (`0xA5`);
4. `DUMMY_SDR (0x03)` — виконати `OPERAND` холостих тактів у стані Hi-Z;
5. `READ_SDR (0x04)` — зчитати потік байтів заданої довжини;
6. `WRITE_SDR (0x08)` — передати потік байтів для запису;
7. `STOP (0x00)` — підняти `CS#` та завершити послідовність.

**Приклад заповнення послідовності Fast Read Quad I/O (1-4-4) у FlexSPI LUT:**

:::tabs
```c
/* Конфігурація LUT FlexSPI (C) */
FLEXSPI->LUT[0] = FLEXSPI_LUT_SEQ(CMD_SDR,   FLEXSPI_1PAD, 0xEB, ADDR_SDR,  FLEXSPI_4PAD, 0x18); // 24-біт адреса
FLEXSPI->LUT[1] = FLEXSPI_LUT_SEQ(MODE8_SDR, FLEXSPI_4PAD, 0xA5, DUMMY_SDR, FLEXSPI_4PAD, 0x04); // 4 dummy-такти
FLEXSPI->LUT[2] = FLEXSPI_LUT_SEQ(READ_SDR,  FLEXSPI_4PAD, 0x04, STOP,       FLEXSPI_1PAD, 0x00);
```
```cpp
/* Конфігурація LUT FlexSPI (C++20 constexpr) */
constexpr auto lut_quad_read = std::to_array<uint32_t>({
    FLEXSPI_LUT_SEQ(CMD_SDR,   FLEXSPI_1PAD, 0xEB, ADDR_SDR,  FLEXSPI_4PAD, 0x18),
    FLEXSPI_LUT_SEQ(MODE8_SDR, FLEXSPI_4PAD, 0xA5, DUMMY_SDR, FLEXSPI_4PAD, 0x04),
    FLEXSPI_LUT_SEQ(READ_SDR,  FLEXSPI_4PAD, 0x04, STOP,       FLEXSPI_1PAD, 0x00)
});
std::copy(lut_quad_read.begin(), lut_quad_read.end(), std::span{FLEXSPI->LUT}.begin());
```
:::

Табличний підхід FlexSPI забезпечує значно вищу гнучкість, дозволяючи будувати довільні послідовності для пам'яті HyperFlash, Octal-SPI та нестандартних ASIC без перепроєктування логіки процесора.

### Апаратний кінцевий автомат: фази та обробка помилок

Під час запуску операції внутрішній FSM контролера QSPI послідовно проходить такі стани:

```
 [IDLE] ──(Старт)──► [CS_LOW] ──► [INSTRUCTION] ──► [ADDRESS] ──► [ALT_BYTES]
                                                                        │
 [IDLE] ◄──(CS_HIGH)── [DESELECT] ◄── [DATA] ◄── [DUMMY_WAIT] ◄────────┘
```

1. **`IDLE`**: Лінія `CS#` утримується на рівні VDD, лінії даних у стані Hi-Z або підтягнуті.
2. **`CS_LOW`**: Спад сигналу `CS#`. Контролер витримує затримку встановлення `t[CSS]` (зазвичай ≥ 5 нс) перед першим тактовим фронтом.
3. **`INSTRUCTION`**: Якщо `IMODE != 00`, на лінію `IO0` (або `IO0..IO3`) видаються 8 бітів опкоду.
4. **`ADDRESS`**: Якщо `ADMODE != 00`, лічильник видає адресу з регістра `QUADSPI_AR` або системної шини.
5. **`ALT_BYTES`**: Видача службових бітів режиму з регістра `QUADSPI_ABR`.
6. **`DUMMY_WAIT`**: Лінії переводяться у вхідний стан (Hi-Z), генератор видає задану в `DCYC` кількість імпульсів `CLK`.
7. **`DATA`**: Прийом (зчитування в FIFO) або передача байтів з інкрементом лічильника `DLR`.
8. **`DESELECT`**: Підняття `CS#` та витримка паузи `CSHT` перед можливістю початку наступного циклу.

#### Діагностика апаратних помилок
* **`TEF` (Transfer Error Flag)**: фіксується у разі некоректної адресації за межі `FSIZE` у режимі Memory-Mapped або спроби запису в заблокований регістр під час активного біта `BUSY`.
* **`TOF` (Timeout Flag)**: спрацьовує, якщо в режимі автоматичного опитування (`Automatic Polling`) пам'ять не повернула очікуваний статус протягом відліку лічильника `LPTR`.
