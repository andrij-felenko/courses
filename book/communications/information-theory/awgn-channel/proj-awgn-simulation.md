# ⚙️ Симуляція каналу AWGN: виміряти BER і звірити з теорією

**Задача.** Уся модель каналу вміщається в один рядок — `r = s + n`, прийняте дорівнює переданому плюс гаусів шум. Але з одного рядка не видно найважливішого: **скільки бітів насправді зламається**. Тож напишімо програму, що грає цей канал мільйони разів, лічить частку перекинутих бітів (BER, bit error rate) і показує, що ця виміряна частка лягає **точно** на теоретичну криву `Q(√(2·Eb/N₀))` уздовж усього діапазону відношення сигнал/шум.

Природне заперечення: навіщо симуляція, якщо формула вже є? Бо формула є **рівно для одного** чистого випадку — незакодованих BPSK чи QPSK у голому AWGN. Щойно ти додаси завадостійкий код, фільтр, неточну синхронізацію чи реальне сузір'я з десятків точок — закрита формула вмирає, і Монте-Карло-симуляція стає єдиним інструментом, що каже правду. Тому інструмент **калібрують** об той єдиний випадок, де відповідь відома наперед: якщо твоя симуляція відтворює `Q` до третьої цифри — їй можна вірити й там, де теорія скінчилася. Уся вправа — зібрати канал, прогнати по діапазону Eb/N₀, полічити помилки.

**Ідея.** Вимірювальний цикл в одне речення: набрати випадкові біти, відобразити їх у символи, з цільового Eb/N₀ порахувати силу шуму σ, додати гаусів шум, вирішити кожен символ як **найближчу точку сузір'я**, полічити, скільки бітів не збіглося. `BER = помилки / біти`. Це прилад на законі великих чисел: зіграй той самий випадковий канал багато разів — і виміряна частка збіжиться до справжньої ймовірності помилки. Усе складне ховається в одному числі — σ, — і правильно дістати його з Eb/N₀ є саме те місце, де більшість саморобних симуляторів тихо брешуть.

> 🔧 **Навіщо це.** Майже кожен серйозний проєкт лінії зв'язку закінчується графіком «BER проти Eb/N₀»: саме на ньому видно, чи вистачить запасу, скільки дасть кодування, де межа модуляції. Аналітично цей графік можна намалювати для жменьки хрестоматійних випадків; для решти — реальних систем із кодами, фільтрами й недосконалостями — його **вимірюють симуляцією**. Хто вміє зібрати чесний AWGN-симулятор і звірити його з теорією там, де вона є, той має робочий стенд для всього іншого. Хто ні — той малює криві, яким не можна довіряти.

Мова тут — **Python з numpy**: увесь код зводиться до дій над великими масивами (згенерувати мільйон відліків шуму, порівняти два масиви, порахувати незбіги), а це рівно те, для чого векторний numpy створений і де він іде зі швидкістю C. Псевдокоду не буде — усе нижче запускається як є.

## Крок 1. Найтонше місце — σ із Eb/N₀

Перш ніж писати цикл, розберімо єдину формулу, у якій криється весь ризик помилитися: як із заданого Eb/N₀ дістати стандартне відхилення шуму σ. Пройдімо ланцюжок від означень, а не завчаймо результат.

**Eb/N₀** — це енергія на **біт**, поділена на спектральну щільність шуму. Задають його майже завжди в децибелах, тож перший крок — з дБ у рази:

```
Eb/N₀ (рази) = 10^(Eb/N₀_дБ / 10)
```

Далі — тонкість, через яку QPSK у чужих симуляторах виходить на 3 дБ кращим, ніж має бути. Шум додається до **символів**, а не до бітів, тож нам потрібна енергія на **символ**, Es. Один символ несе `k` бітів (k = 1 для BPSK, k = 2 для QPSK), і енергії просто складаються:

```
Es = k · Eb        ⇒        Es/N₀ = k · (Eb/N₀)
```

Тепер нормуймо сузір'я так, щоб середня енергія символу дорівнювала одиниці, `Es = 1` (це найзручніший масштаб — усі точки лежать на одиничній відстані від нуля). Тоді щільність шуму N₀ дістається одним діленням:

```
N₀ = Es / (Es/N₀) = 1 / (k · Eb/N₀)
```

І останній, найпідступніший крок. У повній моделі шум **комплексний** — у нього дві незалежні складові, синфазна I та квадратурна Q. Повна потужність комплексного шуму `E[|n|²] = N₀` ділиться між ними порівну, тож на **кожну** складову припадає половина:

```
σ² = N₀ / 2        (дисперсія на кожну складову I та Q окремо)
σ  = √(N₀ / 2)
```

Ось воно, ключове число. Складімо все в один короткий помічник — він буде спільним серцем і BPSK-, і QPSK-каналу, і саме він кодує правило «σ на складову» рівно один раз:

```python
import numpy as np
from math import erfc, sqrt

def q(x):
    """Q(x): імовірність, що стандартна гаусова величина перевищить x.
    Це просто хвіст нормального розподілу: Q(x) = ½·erfc(x/√2)."""
    return 0.5 * erfc(x / sqrt(2.0))

def noise_sigma(EbN0_dB, bits_per_symbol):
    """σ на КОЖНУ складову (I та Q) для символів одиничної енергії Es=1."""
    EbN0 = 10 ** (EbN0_dB / 10.0)          # з дБ у рази
    EsN0 = bits_per_symbol * EbN0          # Es = k·Eb  →  Es/N₀ = k·(Eb/N₀)
    N0 = 1.0 / EsN0                        # Es=1  →  N₀ = 1/(Es/N₀)
    return sqrt(N0 / 2.0)                  # σ² = N₀/2 на складову
```

Щоб це не висіло догмою, перевірмо його об аналітику для BPSK. Символи там — `+1` і `−1` на дійсній осі; приймач вирішує за знаком. Помилка стається, коли шум перекине точку через нуль: для переданого `+1` це `n < −1`. Для BPSK `k = 1`, тож `σ = √(N₀/2) = √(1/(2·Eb/N₀))`, і ймовірність помилки —

```
P(помилка) = P(n < −1) = Q(1/σ) = Q(√(2·Eb/N₀))
```

рівно хрестоматійна крива BER для BPSK. Наш помічник дає точно її. Те, що [нормальний розподіл](book:math/normal-distribution) обриває на своєму хвості цей самий інтеграл `Q`, — і є містком між «σ шуму» та «часткою збитих бітів».

## Крок 2. Канал BPSK у десяток рядків

Маючи σ, увесь BPSK-канал — це кілька дій над масивами. Згенерувати біти, відобразити їх у ±1, додати гаусів шум потрібної сили, вирішити за знаком, полічити незбіги:

```python
def ber_bpsk(EbN0_dB, n_bits, rng):
    bits = rng.integers(0, 2, n_bits)              # 0/1 рівноймовірно
    tx = 1.0 - 2.0 * bits                          # 0→+1, 1→−1 (символи на осі I, Es=1)
    sigma = noise_sigma(EbN0_dB, bits_per_symbol=1)
    rx = tx + sigma * rng.standard_normal(n_bits)  # дійсний шум: рішення лише по осі I
    bits_hat = (rx < 0).astype(int)                # найближчий символ = знак напруги
    return np.count_nonzero(bits_hat != bits) / n_bits
```

Кілька тонкощів, які легко проґавити. По-перше, `tx = 1 - 2*bits` — це не хитрість, а найкоротший спосіб відобразити `{0,1} → {+1,−1}`; уся операція йде над цілим масивом одразу, без жодного циклу Python. По-друге, шум тут **дійсний**, хоч у Кроці 1 ми говорили про комплексний. Це навмисно: BPSK читає лише вісь I, а квадратурну складову шуму приймач однаково викидає, — тож генерувати її для BPSK марно. Але `σ` береться той самий, `√(N₀/2)` **на складову**, — і це критично: якби ми з переляку взяли для дійсного шуму повну потужність N₀, шуму стало б удвічі більше, і крива поїхала б на 3 дБ. По-третє, `rx < 0` повертає булів масив, а `count_nonzero` над `bits_hat != bits` лічить незбіги теж однією векторною дією.

Символи `±1` — це найпростіше сузір'я на [площині I/Q](book:communications/fsk-psk), де BPSK кладе дві точки на дійсну вісь, а QPSK — чотири по кутах. Рішення «найближчий символ» для двох точок на осі вироджується в перевірку знаку, і саме тому BPSK такий стійкий: між точками ціла одиниця, а половину шуму (квадратурну) приймач просто не бачить.

## Крок 3. Прогін по діапазону — і таблиця, що лягає на теорію

Одна точка BER — ще не доказ. Прогонимо канал по всьому діапазону Eb/N₀ й поряд із виміром друкуймо теорію. Тут же вилазить перша практична пастка — **скільки відліків брати**. При високому SNR помилки рідшають лавиноподібно, тож кількість відліків треба **підбирати під очікувану частку**, щоб на кожній точці набралося хоч зо сотня помилок:

```python
rng = np.random.default_rng(2025)

print(" Eb/N0 |   теорія   |    BPSK    |  відліків")
print("-------+------------+------------+-----------")
for EbN0_dB in range(0, 10):
    theory = q(sqrt(2 * 10 ** (EbN0_dB / 10.0)))       # Q(√(2·Eb/N₀))
    n = int(min(3e7, max(2e5, 100 / theory)))          # ~100 помилок на точку
    ber = ber_bpsk(EbN0_dB, n, rng)
    print(" %4d  | %.3e | %.3e | %9d" % (EbN0_dB, theory, ber, n))
```

## Крок 4. QPSK — той самий шум, удвічі більше бітів, та сама крива

Тепер найкрасивіше. QPSK кладе **чотири** символи по кутах квадрата, `(±1 ± j)/√2`, і несе **два** біти на символ замість одного. Здавалося б, удвічі щільніша передача має коштувати надійності. Порахуймо — і побачмо диво.

```python
def ber_qpsk(EbN0_dB, n_bits, rng):
    n_bits -= n_bits % 2                       # парне число: 2 біти на символ
    bits = rng.integers(0, 2, n_bits)
    b_i, b_q = bits[0::2], bits[1::2]          # код Грея: один біт на вісь I, другий на Q
    tx = ((1 - 2*b_i) + 1j*(1 - 2*b_q)) / sqrt(2.0)     # 4 точки (±1±j)/√2, Es=1
    sigma = noise_sigma(EbN0_dB, bits_per_symbol=2)
    noise = sigma * (rng.standard_normal(len(tx)) + 1j*rng.standard_normal(len(tx)))
    rx = tx + noise                            # КОМПЛЕКСНИЙ шум: σ окремо в I та в Q
    b_i_hat = (rx.real < 0).astype(int)        # найближчий символ = знак по кожній осі
    b_q_hat = (rx.imag < 0).astype(int)
    bits_hat = np.empty(n_bits, dtype=int)
    bits_hat[0::2], bits_hat[1::2] = b_i_hat, b_q_hat
    return np.count_nonzero(bits_hat != bits) / n_bits
```

Тут комплексний шум уже **обов'язковий**: обидві осі несуть біт, тож на кожну треба свою незалежну гаусову складову, обидві з тим самим `σ = √(N₀/2)`. Ділення на `√2` теж не косметика — воно тримає енергію символу рівно одиничною (`|(±1±j)/√2|² = 1`), щоб бухгалтерія Eb/N₀ не з'їхала.

Найтонше — чому рішення «найближчий символ» тут звелося до **двох окремих перевірок знаку**, по осі I та по осі Q. Бо квадратне сузір'я QPSK — це просто добуток двох незалежних BPSK: одна вісь нічого не знає про іншу, шумові складові незалежні, і пошук найближчої з чотирьох точок точно розпадається на «який знак у I» та «який знак у Q». QPSK — це буквально два BPSK, що їдуть на одній несучій у квадратурі.

А тепер розплата за здогад. У помічнику `noise_sigma` для QPSK стоїть `k = 2`, тож `N₀ = 1/(2·Eb/N₀)` — шуму вдвічі **менше** на ту саму щільність, бо енергія розподілена на два біти. Проженемо обидві модуляції поряд (той самий цикл, лише додавши `ber_qpsk`):

```
 Eb/N0 |   теорія   |    BPSK    |    QPSK
-------+------------+------------+------------
    0  | 7.865e-02  | 7.914e-02  | 7.884e-02
    3  | 2.288e-02  | 2.268e-02  | 2.321e-02
    6  | 2.388e-03  | 2.375e-03  | 2.520e-03
    9  | 3.363e-05  | 2.959e-05  | 3.834e-05
```

QPSK лягає на **ту саму** криву, що й BPSK. Удвічі більше даних за той самий Eb/N₀ і **та сама** надійність біта — ось чому QPSK усюди, від Wi-Fi до супутника: за ту саму ціну помилки він везе вдвічі більше. Причина проста, коли розкладено: QPSK — два незалежні BPSK-канали в I та Q, кожен зі своєю половиною символьної енергії; уся математика зводиться до того самого `Q(√(2·Eb/N₀))`.

Червоні хрестики внизу — пастка фіксованого N: при 9–10 дБ жодної помилки на 10⁴ відліків, і точка провалюється в нуль. Уся надійність каналу — це те, як круто ця крива падає з ростом Eb/N₀.*

Ця крута спадна крива — і є [крива надійності BER проти SNR](book:communications/ber-snr-curve) у чистому вигляді: кожен зайвий децибел відношення сигнал/шум збиває частку помилок у рази, і симуляція міряє цей обмін напряму, без жодної формули.

## Крок 5. Рідкісні помилки: скільки відліків насправді треба

Повернімося до правої колонки таблиці — вона ховає найпідступнішу пастку всіх BER-симуляцій. При 10 дБ теоретичний BER ≈ 3.9·10⁻⁶: один збитий біт на чверть мільйона. Якщо прогнати наївні фіксовані 10⁴ відліків, очікуване число помилок — `10⁴ · 3.9·10⁻⁶ ≈ 0.04`. Тобто **найчастіше нуль**. Симулятор бадьоро повідомить `BER = 0`, ти зрадієш «ідеальному каналу» — і намалюєш порожнечу (на логарифмічній осі нуль не лягає ніде). Це не працює канал ідеально; це ти не набрав жодної помилки.

Ліки — рахувати не фіксовану кількість відліків, а **до потрібного числа помилок**. Статистична похибка виміру BER падає як `1/√(число_помилок)`: сотня помилок дає близько 10 % розкиду, тисяча — близько 3 %. Тож правильний цикл ллє відліки порціями, поки не набереться, скажімо, сотня помилок (а щоб не зависнути назавжди при неможливо низькому BER — зі стелею на загальне число бітів). Порційність заразом тримає пам'ять обмеженою: за раз у пам'яті лише один шматок, а не всі двадцять шість мільйонів відліків:

```python
def ber_bpsk_until(EbN0_dB, rng, target_errors=100,
                   chunk=200_000, max_bits=200_000_000):
    sigma = sqrt(1.0 / (2 * 10 ** (EbN0_dB / 10.0)))   # BPSK: σ² = N₀/2 = 1/(2·Eb/N₀)
    n_err = n_tot = 0
    while n_err < target_errors and n_tot < max_bits:
        bits = rng.integers(0, 2, chunk)
        rx = (1.0 - 2.0*bits) + sigma*rng.standard_normal(chunk)
        n_err += int(np.count_nonzero((rx < 0) != bits))
        n_tot += chunk
    return n_err / n_tot, n_err, n_tot
```

Запуск на кількох точках показує, як лавиноподібно росте потрібний обсяг:

```
 6 дБ: BER=2.26·10⁻³ (теорія 2.39·10⁻³) |  452 помилки на    200 000 бітів
 8 дБ: BER=1.85·10⁻⁴ (теорія 1.91·10⁻⁴) |  111 помилок на    600 000 бітів
10 дБ: BER=3.82·10⁻⁶ (теорія 3.87·10⁻⁶) |  100 помилок на 26 200 000 бітів
```

Ось де ховається справжня ціна симуляції: спуститися на криві всього на 4 дБ (з 6 до 10) — і кількість відліків, щоб побачити ту саму сотню помилок, зросла в **сто тридцять разів**. Правило кишенькове й непорушне: `N ≈ 100 / BER_очікуваний`. Хочеш чесно намалювати хвіст кривої аж до 10⁻⁸ — приготуйся ганяти мільярди відліків або чекати; саме тут інженери переходять на хитріші методи (importance sampling), але для навчального діапазону простого Монте-Карло цілком досить.

## Складність і пастки

Уся симуляція — сотня рядків, і три з них здатні тихо збрехати так, що крива виглядатиме правдоподібно, а буде зсунута на цілі децибели. Розберімо їх по черзі, бо кожна — класика.

**Дисперсія шуму з Eb/N₀: не переплутай Es/N₀ з Eb/N₀.** Це пастка номер один. Шум додається до символів, тож у формулу входить енергія **символу**, `Es = k·Eb`. Забудеш множник `k` для QPSK — візьмеш N₀ удвічі більшим, ніж слід, і крива QPSK поїде на 3 дБ (10·log₁₀2). Певна ознака хвороби: криві BPSK і QPSK, які **не збігаються**, — а вони зобов'язані злитися в одну. Тому завжди веди розрахунок через `Es/N₀ = k·(Eb/N₀)`, а не навпростець.

**Комплексний шум: σ на кожну складову, не на весь вектор.** Повна потужність комплексного шуму `E[|n|²] = N₀` розкладається на дві незалежні складові по `N₀/2` кожна, тож стандартне відхилення однієї складової — `√(N₀/2)`, а не `√N₀`. Візьмеш `√N₀` на складову — подвоїш повну потужність шуму, і крива поїде на 3 дБ у песимізм. Дзеркальна помилка теж поширена: додати до **комплексного** сузір'я лише дійсний шум — тоді квадратурний біт QPSK узагалі лишиться без шуму, і надійність вийде фальшиво завищеною. Правило: скільки осей несуть біт, стільки незалежних гаусових складових по `√(N₀/2)` і додавай.

**Достатньо відліків, щоб побачити рідкісні помилки.** При високому SNR помилки астрономічно рідкісні, і фіксована жменька відліків дасть нуль помилок — а `BER = 0` це не «ідеально», це «нічого не виміряно». Рахуй **до** набору хоча б сотні помилок (похибка ~`1/√(n_помилок)`), лий відліки порціями заради обмеженої пам'яті, і тримай у голові `N ≈ 100/BER`. Саме через це «нуль помилок» новачок радісно приймає за досконалість, тоді як він просто недобрав статистики.

Поза цією трійцею є ще дві дрібніші, але не менш реальні.

**Q проти erfc.** У numpy немає Q-функції; її беруть через доповнювальну функцію помилок: `Q(x) = ½·erfc(x/√2)`. Загубиш дільник `√2` — і вся теоретична крива з'їде, а вимір із нею вже не збіжиться (і ти марно винитимеш симулятор). `erfc` бери зі стандартного `math` (для скалярних точок теорії) або зі `scipy.special` (для масивів).

**Символьна помилка — не бітова, і код Грея не випадковий.** Лічи **біти**, не символи. Один символ QPSK несе два біти; при кодуванні Грея сусідні по сузір'ю символи різняться рівно одним бітом, тож найімовірніша помилка (стрибок через межу до сусіда) псує лише **один** біт із двох — і саме тому BER виходить чистим `Q(√(2·Eb/N₀))`. Відобразиш біти в символи без Грея — і та сама фізична помилка почне псувати по два біти нарівні, крива відірветься від теорії, а винен буде не канал, а розкладка бітів.

Спільний висновок усіх п'яти пасток той самий: у чесній BER-симуляції кожна невидима — вона не валить програму з помилкою, а мовчки зсуває криву на кілька децибелів або підмінює недобір статистики «ідеальним каналом». Тому калібрування об аналітику там, де вона є, — незакодовані BPSK і QPSK у голому AWGN — не формальність, а єдиний спосіб упевнитися, що стенд не бреше, **перш** ніж довіряти йому там, де формули вже немає.
