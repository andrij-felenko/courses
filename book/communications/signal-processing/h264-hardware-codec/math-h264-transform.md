# 🧮 Вивід цілочисельного перетворення 4x4 H.264

Математичне обґрунтування показує вивід 4x4 цілочисельного перетворення стандарту H.264 з класичного дискретного косинусного перетворення (ДКТ-II), а також механізм повного вилучення дійснозначної арифметики з апаратного обчислювального конвеєра.

## Постановка математичної задачі та обмеження класичного ДКТ

У попередніх стандартах стиснення відео (MPEG-2, MPEG-4 Part 2, H.263) для усунення просторової кореляції пікселів використовувалося ортогональне дискретне косинусне перетворення ДКТ розміром 8x8. Для блоку просторових відліків `X` двовимірне перетворення обчислювалося через добуток матриць:

```
Y_dct = A · X · Aᵀ
```

Де `A` — ортогональна матриця 1D ДКТ розміром 4x4 або 8x8, елементи якої визначаються дійсними значеннями косинусів дробових кутів. Для матриці розміром 4x4 елементи масиву `A` дорівнюють:

```
A = [   a      a      a      a   ]
    [   b      c     -c     -b   ]
    [   a     -a     -a      a   ]
    [   c     -b      b     -c   ]

де дійсні коефіцієнти визначаються через тригонометричні функції:
a = cos(π/8) / 2 ≈ 0.461937928
b = cos(π/8) / √2 ≈ 0.653281482
c = cos(3π/8) / √2 ≈ 0.270598050
```

Застосування плаваючої крапки у класичному ДКТ створює три фундаментальні проблеми при обробці в апаратурі:

1. **Площа кристала та споживання:** апаратні блоки множення чисел із плаваючою крапкою (FPU) або фіксованою комою високої розрядності вимагають сотень тисяч транзисторів і споживають значну енергію.
2. **Проблема розходження результатів (Mismatch Issue):** оскільки стандарт IEEE 754 допускає мікроскопічні відмінності у процедурах округлення результатів множення на процесорах різних архітектур (x86, ARM, DSP), відновлений декомпресований кадр на кодері та декодері відрізнявся на частки значення пікселя. При тривалому Inter-кодуванні ланцюжка з сотень P-кадрів ця похибка накопичувалася, викликаючи розмиття та дрижання зображення.
3. **Обчислювальний затор:** матричне множення `A · X · Aᵀ` для дійснозначних елементів вимагає 64 множень та 56 додавань на кожні 16 пікселів.

Для розв'язання цих проблем розробники H.264 створили 4x4 цілочисельне перетворення (Integer Transform), яке повністю виконується в цілочисельній арифметиці 16-бітових регістрів без похибки округлення та без жодного множника.

## Математична факторизація матриці перетворення

Ідея розкладання полягає у тому, щоб винести дійсні множники із матриці перетворення у окрему діагональну матрицю масштабування.

Звернемо увагу на відношення коефіцієнтів другої та четвертої рядків матриці `A`: `c / b = cos(3π/8) / cos(π/8) = tan(π/8) ≈ 0.414213562`. Наблизимо це значення раціональним дробом `0.5` (або `1 / 2`).

Для збереження ортогональності помножимо перший та третій рядки матриці на `a`, а другий та четвертий рядки — на `b / 2`. Тоді вихідну матрицю `A` можна точно виразити як добуток діагональної масштабувальної матриці `D` та цілочисельної ядра-матриці `C`:

```
A = D · C

де цілочисельна матриця ядра C дорівнює:
C = [   1      1      1      1   ]
    [   2      1     -1     -2   ]
    [   1     -1     -1      1   ]
    [   1     -2      2     -1   ]

а дійсна діагональна матриця масштабування D дорівнює:
D = diag(a, b/2, a, b/2)
```

## Повна факторизація двовимірного перетворення

Підставивши факторизоване розкладання `A = D · C` у формулу двовимірного перетворення `Y_dct`, отримуємо:

```
Y_dct = (D · C) · X · (D · C)ᵀ
      = D · (C · X · Cᵀ) · Dᵀ
```

Оскільки матриця `D` є діагональною, її транспонована форма збігається з нею (`Dᵀ = D`). Позначивши точне цілочисельне ядро перетворення як `Y = C · X · Cᵀ`, отримуємо підсумкове рівняння двовимірного спектра:

```
Y_dct = (C · X · Cᵀ) ⊗ E
```

Символ `⊗` означає поелементне множення Адамара (Hadamard product), а матриця масштабування коефіцієнтів `E` є зовнішнім добутком векторів діагоналі:

```
E = [ a²     a·b/2   a²     a·b/2 ]
    [ a·b/2  b²/4    a·b/2  b²/4  ]
    [ a²     a·b/2   a²     a·b/2 ]
    [ a·b/2  b²/4    a·b/2  b²/4  ]
```

Оскільки `a = 1/2` та `b = √(2/5) ≈ 0.632455`, значення елементів матриці `E` задаються трьома константами:
- Для кутових елементів `(0,0), (0,2), (2,0), (2,2)`: `a² = 0.25`.
- Для центральних елементів `(1,1), (1,3), (3,1), (3,3)`: `b² / 4 = 0.1`.
- Для решти елементів: `a · b / 2 = √(2/5) / 4 ≈ 0.158113883`.

## Об'єднання масштабування з квантуванням (Quantization Scaling)

Фундаментальне досягнення стандарту H.264 полягає у тому, що поелементне множення на дійсну матрицю `E` не виконується окремим обчислювальним блоком. Його повністю об'єднано з наступною стадією конвеєра — квантуванням коефіцієнтів.

Пряме квантування коефіцієнта `Y_dct[i][j]` під час ділення на крок квантування `Qstep` визначається формулою:

```
Z[i][j] = round( Y_dct[i][j] / Qstep )
        = round( (Y[i][j] · E[i][j]) / Qstep )
        = round( Y[i][j] · (E[i][j] / Qstep) )
```

Апаратний кодер завчасно обчислює цілочисельну таблицю мультиплікаторів `MF[QP][i][j]`, де `QP` (Quantization Parameter) — параметр квантування від 0 до 51:

```
MF[QP][i][j] = floor( (2^qbits) · E[i][j] / Qstep(QP) )
```

Де параметр бітового зсуву дорівнює `qbits = 15 + floor(QP / 6)`.

Завдяки цьому ділення на `Qstep` та множення на `E[i][j]` замінюється однією цілочисельною операцією: множенням на табличну константу `MF` та зсувом бітів праворуч на `qbits` позицій:

```
Z[i][j] = ( Y[i][j] · MF[QP % 6][pos] + f ) >> qbits
```

Де `f` — константа округлення (`f = 2^qbits / 3` для Intra-блоків або `2^qbits / 6` для Inter-блоків).

Таблиця `MF` містить всього 6 рядків (оскільки значення `Qstep` подвоюється кожні 6 кроків `QP`), а индекс позиції `pos` приймає одне з 3 значень залежно від розташування коефіцієнта в матриці 4x4.

## Обчислення ядра C · X · Cᵀ на додавачах («Метелик»)

Обчислення двовимірного ядра `Y = C · X · Cᵀ` виконується за 2 проходи 1D-перетворення: спочатку над 4 стовпчиками матриці `X`, потім над 4 рядками отриманого проміжного масиву.

Для 1D-вектора вхідних відліків `x = [x0, x1, x2, x3]` обчислення виразу `y = C · x` розгортається у покрокові прості операції:

```
a0 = x0 + x3      [сумний коефіцієнт крайніх відліків]
a1 = x1 + x2      [сумний коефіцієнт середніх відліків]
a2 = x1 - x2      [різницевий коефіцієнт середніх відліків]
a3 = x0 - x3      [різницевий коефіцієнт крайніх відліків]

y0 = a0 + a1             [постійна складова DC]
y1 = (a3 << 1) + a2      [зсув біта вліво замість множення на 2]
y2 = a0 - a1             [середня частота AC]
y3 = a2 - (a3 << 1)      [висока частота AC]
```

Один прохід 1D-перетворення вимагає всього 8 додавань/віднімань та 2 зсувів бітів. Повний двовимірний прохід над блоком 4x4 вимагає 64 додавань та 16 бітових зсувів. Жодного апаратного множника не використовується.

## Додаткове перетворення Hadamard 2x2 для Chroma DC

Для подальшого стиснення постійної складової (DC-коефіцієнтів) у блоках колірності 4:2:0, чотири DC-коефіцієнти кожного з блоків Cb та Cr збираються у матрицю 2x2 `X_dc` і піддаються додатковому перетворенню Адамара (Hadamard Transform 2x2):

```
Y_dc = H2 · X_dc · H2

де матриця Адамара 2x2 дорівнює:
H2 = [  1   1  ]
     [  1  -1  ]
```

Розгортання перетворення 2x2 у скалярні операції:

```
dc0 = X_dc[0][0] + X_dc[0][1] + X_dc[1][0] + X_dc[1][1]
dc1 = X_dc[0][0] - X_dc[0][1] + X_dc[1][0] - X_dc[1][1]
dc2 = X_dc[0][0] + X_dc[0][1] - X_dc[1][0] - X_dc[1][1]
dc3 = X_dc[0][0] - X_dc[0][1] - X_dc[1][0] + X_dc[1][1]
```

Це перетворення ще більше концентрує енергію колірності у єдиному коефіцієнті `dc0`, підвищуючи ефективність стиснення колірних площин додатково на 5–8%.

## Обернене цілочисельне перетворення у декодері

Апаратний декодер H.264 виконує відновлення просторових відліків `X'` у зворотному порядку:

1. **Обернене квантування (De-quantization):**
   ```
   W[i][j] = ( Z[i][j] · V[QP % 6][pos] ) << floor(QP / 6)
   ```
   де `V` — таблиця коефіцієнтів оберненого масштабування.

2. **Обернене цілочисельне перетворення 4x4 (Inverse Integer Transform):**
   ```
   X' = Cᵢ · W · Cᵢᵀ

   де обернена матриця Cᵢ дорівнює:
   Cᵢ = [  1    1    1    1/2 ]
        [  1   1/2  -1    -1  ]
        [  1  -1/2  -1     1  ]
        [  1   -1    1   -1/2 ]
   ```

Для уникнення ділення на 2 у регістрах декодера коефіцієнти 1/2 реалізуються бітовим зсувом праворуч (`x >> 1`), а підсумковий відновлений масив зсувається на 6 бітів праворуч із додаванням константи округлення. Оскільки обчислення є математично точними, декомпресоване зображення на будь-якому апаратному декодері збігається біт-у-біт із кадровою відновленою матрицею енкодера.
