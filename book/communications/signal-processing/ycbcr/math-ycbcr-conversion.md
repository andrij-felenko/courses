# 🧮 Математичний апарат: матричні перетворення RGB ↔ YCbCr та квантування

Ця вставка містить детальний математичний вивід перетворень між гама-корегованим колірним простором `R'G'B'` та цифровою колірнорізничною моделлю `YCbCr`. У тексті наведено покрокові системи лінійних матричних рівнянь, виведення коефіцієнтів для міжнародних стандартів ITU-R BT.601, BT.709 та BT.2020, доказ мінімізації міжканальної надлишковості через аналіз головних компонентів, а також математичний апарат квантування динамічного діапазону для 8-бітних, 10-бітних та 12-бітних цифрових систем.

### 1. Порядок виконання нелінійних перетворень та гама-корекція

Математичне розділення сигналу на яскравість та колірність у практичній відеоінженерії проводиться не над лінійними фізичними інтенсивностями світлового потоку `RGB`, а над нелінійними гама-корегованими сигналами `R'`, `G'`, `B'`. Потреба в нелінійному перетворенні зумовлена нелінійною чутливістю зорової системи людини до інтенсивності світла: людське око значно чутливіше до малих змін у тінях, ніж у яскраво освітлених ділянках. Описовий закон психофізики Вебера-Фехнера стверджує, що суб'єктивна інтенсивність відчуття пропорційна логарифму фізичного стимулу.

Для наближення цифрового відліку до логарифмічного сприйняття ока застосовується нелінійне гама-стискання:

```
R' = R^(1/γ)      [закон степеневої гами: γ ≈ 2.2 для sRGB та BT.709]
G' = G^(1/γ)      [перетворення лінійної інтенсивності у нелінійний сигнал]
B' = B^(1/γ)      [формування гама-корегованого сигналу синього кольору]
```

Оскільки порядок математичних операцій (матричне множення та розрахунок степенного показника) не є комутативним, сформований із нелінійних сигналів компонент `Y'` називається **відеосигналом яркості (*Luma*)**, на відміну від лінійної фізичної яркості **`Y` (*Luminance*)**.

Якби яскравість обчислювалася з лінійних сигналів `RGB`, а гама-корекція виконувалася після цього, цифровий відеокодек видавав би важкі колірні спотворення на контрастних межах — так зване порушення принципу постійності яркості (*Non-Constancy of Luma*). У такій помилковій схемі високі просторові частоти кольору перетікали б у яскравісний канал, викликаючи темні ореоли та колірний аліасинг довкола чітких контурів об'єктів.

### 2. Спектральний аналіз надлишковості та перетворення Карунена-Лоева

Математичним обґрунтуванням переходу від `RGB` до `YCbCr` є оптимізаційне перетворення Карунена-Лоева (KLT, *Karhunen-Loève Transform*) або аналіз головних компонентів (PCA, *Principal Component Analysis*).

Якщо обчислити коваріаційну матрицю тривимірного коефіцієнтного масиву `RGB` для набору природних зображень, її власні вектори показують наступні просторові напрямки:
- **Перший власний вектор (головна компонента):** орієнтований уздовж головної діагоналі куба `(1, 1, 1)` і акумулює від 80% до 90% загальної дисперсії (енергії) колірного сигналу. Саме цей вектор описує ахроматичну яскравість кадру.
- **Другий та третій власні вектори:** лежать у перпендикулярній ортогональній площині і відповідають за колірнорізничні відхилення у червоно-зеленому та синьо-жовтому спектрах, описуючи лише 10–20% залишкової дисперсії.

Матриця YCbCr являє собою фіксовану ортогональну апроксимацію перетворення Карунена-Лоева, яка усуває позадіагональні кореляційні члени коваріаційної матриці. Це дозволяє обробляти яскравість та колірність як математично незалежні випадкові величини.

### 3. Алгебраїчна форма рівняння яркості та вагові коефіцієнти

Сигнал яркості `Y'` формується як зважена лінійна комбінація трьох нелінійних компонентів:

```
Y' = Kr·R' + Kg·G' + Kb·B'      [зважена сума нелінійних компонентів R'G'B']
```

Для збереження енергетичного балансу при відтворенні ахроматичного білого кольору `(1, 1, 1)` коефіцієнти підпорядковані моновалентній умові нормування:

```
Kr + Kg + Kb = 1      [умова нормування яркості для білого кольору]
Kg = 1 - Kr - Kb      [вираження зеленого коефіцієнта через червоний і синій]
```

Числові значення коефіцієнтів `Kr` та `Kb` визначаються координатним положенням вершин базових кольорів (*primaries*) на колірній діаграмі CIE 1931 відповідного відеостандарту:

#### Стандарт ITU-R BT.601 (SDTV, аналогові ЕПТ-дисплеї)
Базові люмінофори ЕПТ-телевізорів 1950-х років задають наступні вагові коефіцієнти:
- `Kr = 0.2990`
- `Kg = 0.5870`
- `Kb = 0.1140`
- `Y' = 0.2990·R' + 0.5870·G' + 0.1140·B'`

Математичне значення зеленого коефіцієнта `0.5870` означає, що понад 58% інформації про яскравість кадру формується саме зеленим каналом. Це пояснює, чому у матрицях Баєра цифрових фотосенсорів кількість зелених пікселів є вдвічі більшою, ніж червоних чи синіх.

#### Стандарт ITU-R BT.709 (HDTV, монітори sRGB)
Сучасні світлодіодні та рідкокристалічні дисплеї мають зміщені базисні координати первинних кольорів:
- `Kr = 0.2126`
- `Kg = 0.7152`
- `Kb = 0.0722`
- `Y' = 0.2126·R' + 0.7152·G' + 0.0722·B'`

У цьому стандарті частка зеленого кольору зросла до 71.52%, оскільки сучасні люмінофори та світлофільтри HD-моніторів випромінюють більш насичений зелений спектр.

#### Стандарт ITU-R BT.2020 (UHDTV, 4K/8K, розширене колірне охоплення)
Для новітніх лазерних та квантово-точкових дисплеїв із надширокою колірною гамою:
- `Kr = 0.2627`
- `Kg = 0.6780`
- `Kb = 0.0593`
- `Y' = 0.2627·R' + 0.6780·G' + 0.0593·B'`

### 4. Нормалізація колірнорізничних сигналів Pb та Pr

Колірнорізничні сигнали виражають відхилення червоного та синього відтінків від загального рівня яркості кадру:

```
B' - Y' = B' - (Kr·R' + Kg·G' + Kb·B')   [підстановка виразу яркості Y']
        = (1 - Kb)·B' - Kr·R' - Kg·G'    [розкриття дужок та групування за B']

R' - Y' = R' - (Kr·R' + Kg·G' + Kb·B')   [підстановка виразу яркості Y']
        = (1 - Kr)·R' - Kg·G' - Kb·B'    [розкриття дужок та групування за R']
```

Оскільки вихідні гама-сигнали `R'`, `G'`, `B'` обмежені одиничним інтервалом `[0, 1]`, їхні різниці мають несиметричні межі:
- Сигнал `B' - Y'` варіюється у діапазоні від `-(1 - Kb)` (на чистому жовтому кольорі `(1, 1, 0)`) до `+(1 - Kb)` (на чистому синьому кольорі `(0, 0, 1)`).
- Сигнал `R' - Y'` варіюється у діапазоні від `-(1 - Kr)` (на чистому блакитному кольорі `(0, 1, 1)`) до `+(1 - Kr)` (на чистому червоному кольорі `(1, 0, 0)`).

Для приведення обох компонентів до єдиного симетричного масштабу `[-0.5, +0.5]` вводяться нормувальні дільники `2·(1 - Kb)` та `2·(1 - Kr)`:

```
Pb = (B' - Y') / (2·(1 - Kb))    [нормалізація сигналу синьої колірності]
Pr = (R' - Y') / (2·(1 - Kr))    [нормалізація сигналу червоної колірності]
```

Для стандарту BT.601 нормувальні дільники дорівнюють `1.772` та `1.402`:

```
Pb = (B' - Y') / 1.772 = -0.168736·R' - 0.331264·G' + 0.500000·B' [колірність Pb BT.601]
Pr = (R' - Y') / 1.402 = 0.500000·R' - 0.418688·G' - 0.081312·B'  [колірність Pr BT.601]
```

### 5. Дискретизація та квантування: 8-бітний, 10-бітний та 12-бітний динамічний діапазон

Для представлення аналогових компонентів у вигляді беззнакових цілих чисел комп'ютерної пам'яті застосовується амплітудне масштабування та афінний зсув нуля.

#### Варіант A: Full Range (0..255, JPEG / ПК-відео)

У повномасштабному 8-бітному режимі сигнал яркості використовує весь простір `0..255`, а колірні сигнали отримують афінний зсув `+128`:

```
Y  = clamp(round(255·Y'), 0, 255)        [масштабування яркості на повний 8-бітний діапазон]
Cb = clamp(round(255·Pb + 128), 0, 255)  [масштабування Pb та зсув нуля на рівень 128]
Cr = clamp(round(255·Pr + 128), 0, 255)  [масштабування Pr та зсув нуля на рівень 128]
```

Пряма матриця BT.601 Full Range у чисельному вигляді:

```
Y  =  0.299000·R + 0.587000·G + 0.114000·B       [пряме обчислення Y Full Range]
Cb = -0.168736·R - 0.331264·G + 0.500000·B + 128 [пряме обчислення Cb Full Range]
Cr =  0.500000·R - 0.418688·G - 0.081312·B + 128 [пряме обчислення Cr Full Range]
```

#### Варіант B: Limited / Studio Range для різної бітової глибини

У студійних відеостандартах робочий діапазон обмежується для резервування полів `Footroom` (нижня межа) та `Headroom` (верхня межа).

1. **8-бітне Studio Range (BT.601 / BT.709):**
   - Яскравість `Y`: корисний діапазон 220 рівнів (`16..235`).
   - Колірність `Cb/Cr`: корисний діапазон 224 рівні (`16..240`), центр у `128`.
   ```
   Y  = round(219·Y' + 16)      [масштабування на 219 рівнів зі зміщенням +16]
   Cb = round(224·Pb + 128)     [масштабування на 224 рівні зі зміщенням +128]
   Cr = round(224·Pr + 128)     [масштабування на 224 рівні зі зміщенням +128]
   ```

2. **10-бітне Studio Range (BT.2020 / HDR10):**
   Загальний діапазон 10-бітного числа становить 1024 рівні (`0..1023`).
   - Яскравість `Y`: корисний діапазон 876 рівнів (`64..940`).
   - Колірність `Cb/Cr`: корисний діапазон 896 рівнів (`64..960`), центр у `512`.
   ```
   Y  = round(876·Y' + 64)      [10-бітна яскравість зі зміщенням +64]
   Cb = round(896·Pb + 512)     [10-бітна колірність зі зміщенням +512]
   Cr = round(896·Pr + 512)     [10-бітна колірність зі зміщенням +512]
   ```
   Перехід до 10-бітного кодування збільшує кількість градацій яркості у 4 рази, усуваючи артефакти колірних смуг (*color banding*) на плавному градієнті неба у HDR-відео.

3. **12-бітне Studio Range (Dolby Vision / Master Footage):**
   Загальний діапазон 12-бітного числа становить 4096 рівнів (`0..4095`).
   - Яскравість `Y`: корисний діапазон 3504 рівні (`256..3760`).
   - Колірність `Cb/Cr`: корисний діапазон 3584 рівні (`256..3840`), центр у `2048`.

### 6. Виведення оберненої матриці (YCbCr → RGB)

Відтворення вихідних нелінійних компонентів `R'`, `G'`, `B'` здійснюється шляхом обернення системи лінійних матричних рівнянь.

Вираження компонентів через `Y'`, `Pb` та `Pr`:
```
R' = Y' + (1 - Kr)·2·Pr                        [вираження червоного з формули Pr]
B' = Y' + (1 - Kb)·2·Pb                        [вираження синього з формули Pb]
G' = (Y' - Kr·R' - Kb·B') / Kg                  [вираження зеленого з формули Luma Y']
```

Підставивши вирази для `R'` та `B'` у рівняння для `G'`, отримуємо:

```
G' = Y' - (Kr·(1 - Kr)·2·Pr + Kb·(1 - Kb)·2·Pb) / Kg [групування та підстановка R' і B']
```

#### Зворотні формули BT.601 Full Range (0..255):

```
R = Y + 1.402000·(Cr - 128)                       [відновлення R Full Range]
G = Y - 0.344136·(Cb - 128) - 0.714136·(Cr - 128) [відновлення G Full Range]
B = Y + 1.772000·(Cb - 128)                       [відновлення B Full Range]
```

#### Зворотні формули BT.709 Full Range (0..255):

```
R = Y + 1.574800·(Cr - 128)                       [відновлення R BT.709 Full]
G = Y - 0.187324·(Cb - 128) - 0.468124·(Cr - 128) [відновлення G BT.709 Full]
B = Y + 1.855600·(Cb - 128)                       [відновлення B BT.709 Full]
```

#### Зворотні формули BT.709 Limited Range (16..235):

```
R = 1.164384·(Y - 16) + 1.792741·(Cr - 128)                       [відновлення R BT.709 Limited]
G = 1.164384·(Y - 16) - 0.213249·(Cb - 128) - 0.532909·(Cr - 128) [відновлення G BT.709 Limited]
B = 1.164384·(Y - 16) + 2.112402·(Cb - 128)                       [відновлення B BT.709 Limited]
```

### 7. Геометрія простору та проблема виходу за межі колірного охоплення (Out-of-Gamut)

Геометрична форма колірного простору YCbCr у трьох вимірах являє собою похилий паралелепіпед. У той же час 8-бітний простір пам'яті комп'ютера описується ортогональним прямокутним кубом `[0..255] × [0..255] × [0..255]`.

Оскільки похилий паралелепіпед YCbCr вписаний у прямокутний куб RGB лише зальтно, у цифровому просторі існують комбінації відліків `(Y, Cb, Cr)`, які не відповідають жодному дійсному колірному тону в фізичному просторі `RGB`.

Наприклад, якщо взяти комбінацію `Y = 255` (максимальна яскравість) та `Cr = 255` (максимальна червона колірність):
```
R = 255 + 1.402·(255 - 128) = 255 + 1.402·127 = 433  [обчислення R без обмеження]
```

Отримане значення `R = 433` суттєво перевищує максимальну межу 8-бітного числа (255). При зворотному перетворенні такі виходи за межі колірного охоплення обов'язково піддаються операції жорсткого затискання (*clamping*):

```
R_final = min(max(round(R), 0), 255)  [затискання значення R в діапазон 0..255]
G_final = min(max(round(G), 0), 255)  [затискання значення G в діапазон 0..255]
B_final = min(max(round(B), 0), 255)  [затискання значення B в діапазон 0..255]
```

У професійному відеомонтажі вихід компонентів за межі охоплення виявляється за допомогою контрольних приладів — осцилографів колірних векторів (*vectorscopes*). Якщо значення сигналів `Cb` або `Cr` виходять за граничні межі сітки векторскопа, зображення вважається непридатним для трансляції і піддається процедурі тональної корекції (*gamut mapping*).
