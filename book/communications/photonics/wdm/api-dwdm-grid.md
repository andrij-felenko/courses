# 📋 Специфікація спектральної сітки ITU-T та DOM-моніторингу

Цей довідник містить таблиці частотних каналів ITU-T G.694.1 (DWDM 100 ГГц / 50 ГГц), спектральну сітку CWDM (ITU-T G.694.2) та карту реєстрів цифрового оптичного моніторингу (DOM / DDMI за специфікаціями SFF-8472 / SFF-8636).

### 1. Принципи побудови спектральних сіток та таблиця каналів DWDM

Стандартизація оптичних частот є необхідною умовою для забезпечення сумісності обладнання різних виробників у єдиному волоконно-оптичному тракті. Спектральна сітка щільного спектрального ущільнення DWDM за рекомендацією ITU-T G.694.1 побудована на частотній основі, де кожен канал має чітко закріплену абсолютну частоту в герцах.

Опорною точкою всієї сітки DWDM обрано частоту `193.10 ТГц` (що відповідає довжині хвилі у вакуумі `1552.52 нм`), яка є центральною частотою каналу C31 у традиційному C-діапазоні (*Conventional Band*). Вибір C-діапазону зумовлений двома фундаментальними фізичними факторами: по-перше, саме на довжині хвилі `1550 нм` кварцове скло має абсолютний мінімум оптичного загасання (`~0.18–0.22 дБ/км`); по-друге, цей спектральний проміжок строго збігається зі смугою підсилення оптичних підсилювачів на волокні, легованому іонами ербію (EDFA).

Частотна сітка ділиться на канали з регулярним кроком. У сітці `100 ГГц` (крок `0.1 ТГц`) канали позначаються номерами з кроком `100 ГГц` від опорної точки. У сітці `50 ГГц` (крок `0.05 ТГц`) між основними каналами додаються додаткові інтервальні канали. У новіших системах з кроком `25 ГГц` або `12.5 ГГц` щільність упаковки зростає відповідно вдвічі та вчотири рази.

При виборі обладнання DWDM інженери враховують температуру середовища та температурний коефіцієнт лазерного діода. Оскільки спектральна відстань між каналами `100 ГГц` складає всього близько `0.8 нм`, напівпровідникові лазери передавачів вимагають суворого контролю температури за допомогою побудованих у корпус лазера термоелектричних охолоджувачів TEC (*Thermoelectric Cooler*). Лазерний локер (*wavelength locker*) вимірює довжину хвилі випромінювання за допомогою відгалужуваного пасивного етілону Фабрі-Перо та підтримує центральну частоту лазера з відхиленням не більше `±1.5 ГГц` (`±0.012 нм`) від номіналу ITU-T.

### 2. Спектральна сітка грубого ущільнення CWDM (ITU-T G.694.2)

На відміну від DWDM, спектральна сітка грубого ущільнення CWDM за рекомендацією ITU-T G.694.2 стандартизована в одиницях довжини хвилі (нанометрах). Це зумовлено тим, що CWDM розроблялася для недорогих міських мереж, де застосовуються неохолоджувані лазерні діоди DFB.

Діапазон довжин хвиль CWDM охоплює весь доступний спектр кварцового одномодового волокна від `1271 нм` до `1611 нм` із постійним кроком **20 нм**. Всього сітка містить 18 довжин хвиль, які розподілені по п'яти оптичних діапазонах:
- **O-band (Original Band, 1271–1331 нм)**: діапазон біля точки нульової хроматичної дисперсії стандартного волокна G.652. Тут загасання становить `~0.35 дБ/км`, що робить його зручним для компактних міських зв'язків.
- **E-band (Extended Band, 1351–1451 нм)**: діапазон розширених хвиль. У застарілих волокнах тут спостерігався високий водневий пік поглинання іонами `OH⁻` (загасання до `2–3 дБ/км`). Сучасні волокна стандарту G.652.D (*Low Water Peak*) позбавлені цього піку, що дозволяє повноцінно використовувати всі 18 каналів CWDM.
- **S-band (Short-Wavelength Band, 1471–1511 нм)**: короткохвильовий діапазон з помірним загасанням `~0.23 дБ/км`.
- **C-band (Conventional Band, 1531–1551 нм)**: діапазон найвищої прозорості скла (`~0.19–0.20 дБ/км`).
- **L-band (Long-Wavelength Band, 1571–1611 нм)**: довгохвильовий діапазон з загасанням `~0.21–0.23 дБ/км`.

Пропускна смуга канального фільтра становить `13 нм` (від `-6.5 нм` до `+6.5 нм` від центральної довжини хвилі). Решта `7 нм` слугує захистним інтервалом (*guard band*) між сусідніми каналами для запобігання міжканальним перехресним завадам.

### 3. Карта реєстрів цифрового моніторингу DOM (SFF-8472, I2C адреса 0xA2)

Оптичні транспондери та трансивери WDM у форматах SFP+, XFP, QSFP28 та QSFP-DD надають повну цифрову діагностику параметрів у реальному часі через функцію DOM (*Digital Optical Monitoring*) або DDMI (*Digital Diagnostic Monitoring Interface*).

Доступ до параметрів моніторингу здійснюється через послідовну шину I2C. Вся пам'ять трансивера розділена на дві сторінки:
- **Сторінка I2C за адресою 0xA0**: містить статичну інформацію EEPROM (назва виробника, партійний номер, серійний номер, довжина хвилі лазера, тип кодування та швидкість).
- **Сторінка I2C за адресою 0xA2**: містить динамічні значення цифрового аналого-цифрового перетворювача (АЦП), де оновлюються поточні виміряні значення п'яти ключових параметрів трансивера.

Нижче наведено карту реєстрів сторінки `0xA2` (байтове зміщення від `96` до `105` у верхній оперативній пам'яті):

| Байтові адреси | Поле діагностики | Формат даних АЦП | Роздільна здатність (масштаб) | Формула перерахунку |
| :--- | :--- | :--- | :--- | :--- |
| **96–97** | Температура модуля | 16-біт Знакове MSB/LSB | 1 / 256 °C | `T (°C) = Raw / 256.0` |
| **98–99** | Напруга живлення Vcc | 16-біт Беззнакове MSB/LSB | 100 мкВ (0.0001 В) | `Vcc (В) = Raw / 10000.0` |
| **100–101** | Струм зміщення лазера | 16-біт Беззнакове MSB/LSB | 2 мкА (0.002 мА) | `I_bias (мА) = Raw · 0.002` |
| **102–103** | Вихідна потужність Tx | 16-біт Беззнакове MSB/LSB | 0.1 мкВт (0.0001 мВт) | `P_tx (дБм) = 10·log₁₀(Raw · 0.0001)` |
| **104–105** | Вхідна потужність Rx | 16-біт Беззнакове MSB/LSB | 0.1 мкВт (0.0001 мВт) | `P_rx (дБм) = 10·log₁₀(Raw · 0.0001)` |

#### Аналіз фізичного змісту параметрів DOM

Кожен з п'яти параметрів моніторингу дає системному інженеру або автоматизованій системі управління мережею (NMS) важливу інформацію про стан оптичного каналу:
1. **Температура модуля (`Temp`)**: вимірюється всередині корпусу трансивера. Підвищення температури вище `+70 °C` свідчить про проблеми з охолодженням шафі або вихід з ладу внутрішнього термоелектричного охолоджувача TEC.
2. **Напруга живлення (`Vcc`)**: нормальне значення становить `3.3 В` (`±5%`). Падіння напруги нижче `3.13 В` вказує на перевантаження внутрішнього джерела живлення плати.
3. **Струм зміщення лазера (`Tx Bias`)**: вимірює струм накачки напівпровідникового лазерного діода. З плином часу внаслідок деградації кристал лазера вимагає більшого струму для підтримання тієї самої вихідної оптичної потужності. Поступове зростання струму `Tx Bias` на `20–30%` протягом місяців є головною ознакою близького виходу лазера з ладу.
4. **Вихідна потужність передавача (`Tx Power`)**: оптична потужність, яка випромінюється у волокно. Для WDM-трансиверів номінальне значення зазвичай лежить у межах від `-1.0 дБм` до `+4.0 дБм`.
5. **Вхідна потужність приймача (`Rx Power`)**: оптична потужність, що приходить від віддаленого вузла. Раптове падіння `Rx Power` на `3–5 дБ` вказує на погіршення стану оптичного з'єднувача, деградацію заварки волокна або появу мікровигинів кабелю в магістралі.

#### Реєстри аварійних порогів (Alarm & Warning Thresholds, адреси 0–39)

Для запобігання раптовим аваріям трансивер містить у прошивці байтові значення заводських порогів тривог. При виході параметра за межі порогу Warning модуль виставляє прапор попередження, а при виході за поріг Alarm — виставляє прапор аварії та може автоматично вимкнути лазер передавача для захисту обладнання:

```text
Адреси 00–01: Temp High Alarm   (наприклад, +75 °C)
Адреси 02–03: Temp Low Alarm    (наприклад, -5 °C)
Адреси 04–05: Temp High Warning (наприклад, +70 °C)
Адреси 06–07: Temp Low Warning  (наприклад, 0 °C)

Адреси 24–25: Tx Power High Alarm   (+5.0 дБм)
Адреси 26–27: Tx Power Low Alarm    (-4.0 дБм)
Адреси 32–33: Rx Power High Alarm   (-3.0 дБм)
Адреси 34–35: Rx Power Low Alarm    (-22.0 дБм)
```

#### Приклад декодування сирих даних DOM (C та C++):

:::tabs
```c
#include <math.h>

typedef struct {
    double temp_c;
    double vcc_volts;
    double tx_bias_ma;
    double tx_power_dbm;
    double rx_power_dbm;
} dom_data_t;

dom_data_t decode_sff8472_dom(const unsigned char *a2_page_bytes) {
    dom_data_t dom;
    
    /* Температура: 16-біт signed integer */
    short raw_temp = (short)((a2_page_bytes[96] << 8) | a2_page_bytes[97]);
    dom.temp_c = (double)raw_temp / 256.0;

    /* Напруга Vcc: 16-біт unsigned integer */
    unsigned short raw_vcc = (unsigned short)((a2_page_bytes[98] << 8) | a2_page_bytes[99]);
    dom.vcc_volts = (double)raw_vcc / 10000.0;

    /* Струм накачки: 16-біт unsigned integer */
    unsigned short raw_bias = (unsigned short)((a2_page_bytes[100] << 8) | a2_page_bytes[101]);
    dom.tx_bias_ma = (double)raw_bias * 0.002;

    /* Потужність Tx у мкВт -> переведення в дБм */
    unsigned short raw_tx = (unsigned short)((a2_page_bytes[102] << 8) | a2_page_bytes[103]);
    double tx_mw = (double)raw_tx * 0.0001;
    dom.tx_power_dbm = (tx_mw > 0.0) ? 10.0 * log10(tx_mw) : -40.0;

    /* Потужність Rx у мкВт -> переведення в дБм */
    unsigned short raw_rx = (unsigned short)((a2_page_bytes[104] << 8) | a2_page_bytes[105]);
    double rx_mw = (double)raw_rx * 0.0001;
    dom.rx_power_dbm = (rx_mw > 0.0) ? 10.0 * log10(rx_mw) : -40.0;

    return dom;
}
```
```cpp
#include <cmath>
#include <cstdint>
#include <span>

struct DomData {
    double temp_c;
    double vcc_volts;
    double tx_bias_ma;
    double tx_power_dbm;
    double rx_power_dbm;

    static DomData parseSff8472(std::span<const uint8_t> a2_page) {
        if (a2_page.size() < 106) {
            return {};
        }

        const auto read_u16 = [&](size_t offset) -> uint16_t {
            return static_cast<uint16_t>((a2_page[offset] << 8) | a2_page[offset + 1]);
        };

        const auto read_i16 = [&](size_t offset) -> int16_t {
            return static_cast<int16_t>((a2_page[offset] << 8) | a2_page[offset + 1]);
        };

        const double tx_mw = static_cast<double>(read_u16(102)) * 0.0001;
        const double rx_mw = static_cast<double>(read_u16(104)) * 0.0001;

        return DomData{
            .temp_c = static_cast<double>(read_i16(96)) / 256.0,
            .vcc_volts = static_cast<double>(read_u16(98)) / 10000.0,
            .tx_bias_ma = static_cast<double>(read_u16(100)) * 0.002,
            .tx_power_dbm = (tx_mw > 0.0) ? 10.0 * std::log10(tx_mw) : -40.0,
            .rx_power_dbm = (rx_mw > 0.0) ? 10.0 * std::log10(rx_mw) : -40.0
        };
    }
};
```

Застосування регулярного цифрового моніторингу DOM дозволяє операторам оптичних магістралей автоматизовано виявляти деградацію лінії до появи реальних втрат пакетів даних та завчасно замінювати трансивери під час планового технічного обслуговування.
