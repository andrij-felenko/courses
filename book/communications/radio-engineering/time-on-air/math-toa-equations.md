# 🧮 Математичне виведення формул часу в ефірі

Математичний розрахунок часу в ефірі (англ. *Time-on-Air*, ToA) описує точну часову тривалість випромінювання радіокадра трансивером. Оскільки радіокадр складається з двох основних частин — преамбули (необхідної для захоплення частоти й синхронізації приймача) та корисного навантаження (що містить заголовок, дані користувача й контрольне сумування), загальний час в ефірі є сумою їхніх тривалостей.

Для чирпових систем модуляції (LoRa) і класичних частотних систем (FSK) математичні моделі суттєво відрізняються через різний спосіб упаковки бітів у радіочастотні символи.

---

### 1. Фундаментальні часові параметри модуляції LoRa

У модуляції з розширенням спектра чирпами (CSS) базовою одиницею часу є тривалість одного символа `T_s`. Символ являє собою один повний чирп, що проходить усю ширину смуги частот `BW`.

Швидкість зміни частоти чирпа задається шириною смуги `BW` (в Герцах), а кількість дискретних частотних станів усередині одного чирпа визначається коефіцієнтом розширення `SF` (англ. *Spreading Factor*). Один символ несе рівно `SF` бітів інформації й складається з `2ⁿ` (де `n = SF`) відліків частоти.

Тривалість одного символа обчислюється як:

```
T_s = 2ˢᶠ / BW
```

де:
* `SF` — коефіцієнт розширення (ціле число від 7 до 12);
* `BW` — ширина смуги частот у Герцах (наприклад, 125000 Гц, 250000 Гц або 500000 Гц).

Фізичний зміст цього рівняння простий: при зростанні `SF` на одиницю кількість часових відліків чирпа подвоюється, тож символ їде вдвічі довше.

Наприклад, при `SF = 7` та `BW = 125000` Гц тривалість символа становить:

```
T_s = 2⁷ / 125000 = 128 / 125000 = 0.001024 с = 1.024 мс
```

При переході до `SF = 12` при тій самій смузі тривалість символа зростає в `2⁵ = 32` рази:

```
T_s = 2¹² / 125000 = 4096 / 125000 = 0.032768 с = 32.768 мс
```

### 2. Тривалість преамбули (T_preamble)

Преамбула складається з послідовності неодвозначних базових чирпів, за якими слідують 4.25 символа синхронізації кадра (два символи виявлення кадра та 2.25 символа зворотного чирпа для точного захоплення часу й частоти).

Якщо кількість запрограмованих символів преамбули дорівнює `N_preamble`, то загальна кількість символів преамбули становить `N_preamble + 4.25`.

Тривалість преамбули обчислюється за формулою:

```
T_preamble = (N_preamble + 4.25) · T_s
```

За замовчуванням у більшості протоколів на базі LoRa (зокрема LoRaWAN) приймається `N_preamble = 8`. У цьому випадку загальна кількість символів преамбули дорівнює `8 + 4.25 = 12.25`.

Наприклад, при `SF7` і `BW 125` кГц тривалість преамбули дорівнює `12.25 · 1.024 мс = 12.544 мс`.

### 3. Повне математичне виведення кількості символів корисного навантаження (N_payload)

Корисне навантаження кадра передається у вигляді набору символів. Точна кількість символів `N_payload` залежить від розміру даних `PL` (у байтах), наявності явного заголовка (Explicit Header), наявності контрольної суми кадра (CRC), коефіцієнта кодування (Coding Rate, `CR`) та режиму оптимізації низької швидкості (Low Data Rate Optimization, `DE`).

Загальна формула для визначення кількості символів корисного навантаження має вигляд:

```
N_payload = 8 + max( ceil( (8·PL - 4·SF + 28 + 16·CRC - 20·IH) / (4·(SF - 2·DE)) ) · (CR + 4), 0 )
```

Розберемо кожен член цієї формули з фізичного й математичного погляду:

1. **`8·PL`** — загальна кількість бітів даних користувача (байтовий розмір `PL`, помножений на 8).
2. **`- 4·SF`** — віднімання бітів, які поміщаються в перші два заголовкові символи кадра (заголовкова частина з'їдає частину ємності перших символів).
3. **`+ 28`** — додаткові біти службової інформації явного заголовка (включають 8 бітів довжини кадра, 3 біти `CR`, 1 біт CRC прапорця та 5 бітів заголовкового CRC, плюс 11 бітів падингу).
4. **`+ 16·CRC`** — якщо контрольна сума кадра увімкнена (`CRC = 1`), додається 16 бітів (2 байти CRC-16). Якщо `CRC = 0`, додається 0 бітів.
5. **`- 20·IH`** — якщо використовується неявний заголовок (Implicit Header mode, `IH = 1`), прихований заголовок заощаджує 20 бітів. При появному заголовку `IH = 0`.
6. **`SF - 2·DE`** — чиста кількість корисних бітів на один символ без урахування завадостійкого кодування. Якщо увімкнено оптимізацію низької швидкості даних (`DE = 1`), два молодші біти кожного символа відкидаються для стійкості проти частотного дрейфу, тому ємність символа зменшується до `SF - 2`. Оптимізація `DE = 1` є обов'язковою, коли тривалість символа `T_s > 16` мс (типово для `SF = 11` та `SF = 12` на смузі 125 кГц).
7. **`4·(SF - 2·DE)`** — дільник, що визначає інформаційну ємність блоку до накладання завадостійкого кодування.
8. **`ceil(...)`** — округлення вгору до найближчого цілого числа (дрібний блок символів заповнюється повністю, бо завадостійкий код обробляє дані цілими ніблами/блоками).
9. **`CR + 4`** — множник завадостійкого кодування. При `CR = 1` (код 4/5) кожен 4-бітний блок кодується 5 бітами (множник 5). При `CR = 4` (код 4/8) кожен 4-бітний блок кодується 8 бітами (множник 8).
10. **`+ 8`** — базові 8 символів корисного навантаження, які передаються завжди для розміщення заголовкової частини кадра.

Тривалість передачі корисного навантаження обчислюється як:

```
T_payload = N_payload · T_s
```

Загальний час у ефірі складається з двох частин:

```
ToA = T_preamble + T_payload
```

### 4. Розрахунок часу в ефірі для модуляції FSK / GFSK

На відміну від LoRa, у класичній частотній маніпуляції (FSK) швидкість передачі бітів є постійною величиною `R_b` (бітрейт у бітах за секунду).

Кадр FSK складається з:
1. Преамбули розміром `N_pre_bytes` байтів;
2. Синхрослова (Sync Word) розміром `N_sync_bytes` байтів;
3. Заголовка довжини (Length Byte) розміром `N_hdr_bytes` байтів (зазвичай 1 байт);
4. Корисних даних розміром `PL` байтів;
5. Контрольної суми `N_crc_bytes` байтів (зазвичай 2 байти CRC-16).

Загальна кількість бітів у кадрі FSK становить:

```
N_bits_total = 8 · (N_pre_bytes + N_sync_bytes + N_hdr_bytes + PL + N_crc_bytes)
```

Загальний час в ефірі кадра FSK розраховується за прямою формулою:

```
ToA_FSK = N_bits_total / R_b
```

Якщо швидкість становить 50 кбіт/с (`50000` біт/с), а кадр містить 29 байтів (232 біти), маємо:

```
ToA_FSK = 232 / 50000 = 0.00464 с = 4.64 мс
```

### 5. Математична модель обов'язкового часу мовчання (Off-Time)

Згідно з регламентами ETSI EN 300 220, якщо пристрій передає кадр тривалістю `ToA` в смузі з дозволеним робочим циклом `DC` (вираженим у частках від одиниці, де 1% відповідає `DC = 0.01`), він зобов'язаний витримати паузу мовчання `T_off` перед наступною передачею.

З визначення робочого циклу маємо пропорцію відношення часу мовчання до загального періоду:

```
DC = ToA / (ToA + T_off)
```

Покрокове алгебраїчне виведення рівняння паузи мовчання:

```
DC · (ToA + T_off) = ToA              [помножили обидві частини на (ToA + T_off)]
DC · ToA + DC · T_off = ToA          [розкрили дужки]
DC · T_off = ToA - DC · ToA          [перенесли доданок DC·ToA у праву частину]
DC · T_off = ToA · (1 - DC)          [винесли ToA за дужки]
T_off = ToA · (1 - DC) / DC          [поділили на DC]
T_off = ToA · (1/DC - 1)             [розділили дріб у дужках]
```

При робочому циклі `1%` (`DC = 0.01`):

```
T_off = ToA · (1 / 0.01 - 1) = ToA · (100 - 1) = 99 · ToA
```

Це означає, що тривалість паузи мовчання рівно в 99 разів перевищує тривалість передачі пакета.

### 6. Покрокові числові приклади обчислення

#### Приклад 1: Коротка посилка LoRa (SF7, BW = 125 кГц, 20 байт даних)

Параметри: `SF = 7`, `BW = 125000` Гц, `PL = 20` байт, `CR = 1` (код 4/5), `N_preamble = 8`, `CRC = 1` (увімкнено), `IH = 0` (явний заголовок), `DE = 0` (вимкнено).

1. Обчислюємо тривалість символа:
```
T_s = 2⁷ / 125000 = 128 / 125000 = 1.024 мс
```

2. Обчислюємо тривалість преамбули:
```
T_preamble = (8 + 4.25) · 1.024 мс = 12.25 · 1.024 мс = 12.544 мс
```

3. Обчислюємо кількість символів корисного навантаження `N_payload`:
```
чисельник = 8·20 - 4·7 + 28 + 16·1 - 20·0
          = 160 - 28 + 28 + 16 - 0
          = 176 бітів

дільник   = 4 · (7 - 2·0) = 4 · 7 = 28 бітів

блоків    = ceil(176 / 28) = ceil(6.2857) = 7

N_payload = 8 + 7 · (1 + 4) = 8 + 7 · 5 = 8 + 35 = 43 символи
```

4. Обчислюємо тривалість корисного навантаження та загальний ToA:
```
T_payload = 43 · 1.024 мс = 44.032 мс
ToA = 12.544 мс + 44.032 мс = 56.576 мс
```

5. Необхідна пауза мовчання при Duty Cycle 1%:
```
T_off = 99 · 56.576 мс = 5601.024 мс ≈ 5.601 секунди
```

---

#### Приклад 2: Далека посилка LoRa (SF12, BW = 125 кГц, 20 байт даних)

Параметри: ті самі `PL = 20` байт, `CR = 1`, `N_preamble = 8`, `CRC = 1`, але `SF = 12`. Оскільки `T_s > 16` мс, обов'язково встановлюємо `DE = 1`.

1. Обчислюємо тривалість символа:
```
T_s = 2¹² / 125000 = 4096 / 125000 = 32.768 мс
```

2. Обчислюємо тривалість преамбули:
```
T_preamble = 12.25 · 32.768 мс = 401.408 мс
```

3. Обчислюємо кількість символів корисного навантаження `N_payload`:
```
чисельник = 8·20 - 4·12 + 28 + 16·1 - 20·0
          = 160 - 48 + 28 + 16
          = 156 бітів

дільник   = 4 · (12 - 2·1) = 4 · 10 = 40 бітів

блоків    = ceil(156 / 40) = ceil(3.9) = 4

N_payload = 8 + 4 · (1 + 4) = 8 + 4 · 5 = 8 + 20 = 28 символів
```

4. Обчислюємо тривалість корисного навантаження та загальний ToA:
```
T_payload = 28 · 32.768 мс = 917.504 мс
ToA = 401.408 мс + 917.504 мс = 1318.912 мс ≈ 1.319 секунди
```

5. Необхідна пауза мовчання при Duty Cycle 1%:
```
T_off = 99 · 1.318912 с = 130.572 секунди ≈ 2.17 хвилини
```

---

#### Приклад 3: Та сама посилка 20 байт у модуляції FSK (50 кбіт/с)

Параметри: `R_b = 50000` біт/с, `PL = 20` байт, преамбула 4 байти, Sync Word 2 байти, заголовок 1 байт, CRC 2 байти.

1. Загальний обсяг кадра в байтах і бітах:
```
N_bytes_total = 4 + 2 + 1 + 20 + 2 = 29 байтів
N_bits_total  = 29 · 8 = 232 біти
```

2. Час у ефірі:
```
ToA_FSK = 232 / 50000 = 0.00464 секунди = 4.64 мс
```

Порівняльний підсумок обчислень унаочнює фізичну ціну дальності: передача тих самих 20 байтів у LoRa SF12 вимагає в 284 рази більше часу в ефірі, ніж у FSK 50 кбіт/с, що прямо визначає енергетичні витрати батареї та пропускну спроможність радіоканалу.
