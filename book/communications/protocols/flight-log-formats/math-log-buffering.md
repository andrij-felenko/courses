# 🧮 Математичний аналіз черг буферизації та оцінка ризику переповнення під час затримок SD-карт

Ця математична вставка містить строгий аналіз теорії масового обслуговування та детермінований розрахунок динаміки заповнення кільцевого буфера оперативної пам'яті (RAM) польотного контролера при високочастотному логуванні даних. Розглянуто задачу запобігання втратам пакетів (англ. *dropouts*) в умовах неперіодичних сплесків затримок запису (англ. *latency spikes*) накопичувачів Flash/MicroSD, спричинених внутрішніми процесами збирання сміття та стирання блоків NAND-пам'яті.

---

## 1. Постановка задачі та фізична модель джерела і накопичувача

У польотному контролері безпілотного апарата підсистема логування є класичною системою обслуговування з накопичувачем. Потоки реального часу генерують неперервний бінарний потік повідомлень із сумарною інтенсивністю `R_in` (байтів/с), який записується в кільцевий буфер оперативної пам'яті місткістю `B` байтів. Фоновий потік вивантажує накопичені байти на MicroSD-карту через контролер інтерфейсу SDMMC або SPI.

```
Потоки реального часу                Кільцевий буфер SRAM           SD-карта / Flash
(IMU, EKF, PID, GPS)                  (Місткість B байтів)          (Інтерфейс SDIO)
       |                                      |                            |
       |  Вхідний потік R_in (байтів/с)        |   Вихідний потік R_out     |
       +------------------------------------->|--------------------------->|
                                              |   (Періодичні зупинки     |
                                              |    T_stall до 250 мс!)     |
```

Хоча середня пропускна здатність інтерфейсу SDMMC `R_out` у десятки разів перевищує вхідний потік `R_in` (`R_out >> R_in`), фізика роботи NAND-флеш пам'яті створює критичну нелінійність:
* Запис у комірки NAND-флеш здійснюється сторінками розміром 4–16 КБ, але перезапис можливий лише після попереднього електричного **стирання цілого блоку** (англ. *Erase Block*) розміром 1–4 МБ.
* Коли внутрішній пул стертих блоків у контролері карти вичерпується, контролер карти MicroSD призупиняє прийом даних по шині на час операції `Block Erase` та внутрішнього збирання сміття (англ. *Garbage Collection*, GC).
* У цей інтервал, що триває `T_stall` (від 50 до 250 мс), швидкість обслуговування накопичувача миттєво падає до нуля: `R_out(t) = 0`.

Якщо кільцевий буфер SRAM не має достатнього обсягу для поглинання всіх байтів, що надійшли за час `T_stall`, буфер переповнюється, і система втрачає польотні кадри (`dropouts`).

## 2. Детермінована модель найгіршого випадку (Worst-Case Bounding)

Розглянемо детерміновану динаміку накопичення черги в буфері при виникненні поодинокого сплеску затримки тривалістю `T_stall`.

### 2.1. Виведення мінімально необхідного обсягу буфера

Нехай `R_in` — максимальна сумарна швидкість генерації бінарних логів усіма підсистемами автопілота:

```
R_in = ∑ (f_i · S_i)
```
де:
* `f_i` — частота публікації `i`-го топіка (Гц),
* `S_i` — розмір кадру `i`-го топіка разом із транспортним заголовком (байти).

Під час блокування шини накопичувача на інтервалі `t ∈ [0, T_stall]` обсяг даних у буфері `Q(t)` лінійно зростає:

```
Q(t)
= Q(0) + ∫₀ᵗ R_in(τ) dτ      [інтегрування вхідного потоку при R_out = 0]
= Q(0) + R_in · t            [при постійній швидкості R_in]
```

Припускаючи, що перед початком сплеску затримки буфер був майже порожнім (`Q(0) ≈ 0`), максимальний піковий обсяг черги `Q_peak` досягається в момент завершення блокування `t = T_stall`:

```
Q_peak
= R_in · T_stall             [базовий обсяг накопичених даних]
```

Для врахування аперіодичних стохастичних сплесків (одночасний запис текстових журналів, дамп таблиці параметрів під час зміни режиму польоту) додається запас `ΔB_burst`:

```
B_min
= R_in · T_stall + ΔB_burst  [абсолютний детермінований поріг переповнення]
```

Якщо фактична місткість буфера `B` задовольняє умову `B ≥ B_min`, втрата жодного байта під час спайку затримки є неможливою.

---

### 2.2. Розрахунок часу повного спорожнення буфера (Drain Time)

Після завершення операції стирання блоку контролер MicroSD відновлює запис із максимальною швидкістю інтерфейсу `R_out` (для 4-бітної шини SDIO на частоті 50 МГц реальна швидкість запису становить `R_out ≈ 10..15 МБ/с`).

На фазі відновлення `t > T_stall` динаміка черги описується диференціальним рівнянням:

```
dQ(t)/dt
= R_in - R_out               [швидкість зміни черги при активному скиданні]
```

Оскільки `R_out > R_in`, похідна є від'ємною, і черга спадає до нуля за час `T_drain`:

```
Q_peak - (R_out - R_in) · T_drain = 0

T_drain
= Q_peak ÷ (R_out - R_in)    [виведення часу спорожнення буфера]
= (R_in · T_stall) ÷ (R_out - R_in)
```

Відношення часу скидання до часу блокування називається **коефіцієнтом відновлення буфера** `K_rec`:

```
K_rec
= T_drain ÷ T_stall                  [означення коефіцієнта відновлення]
= R_in ÷ (R_out - R_in)              [підстановка T_drain через Q_peak та R_out]
= 1 ÷ ( (R_out / R_in) - 1 )         [ділення чисельника і знаменника на R_in]
```

Оскільки для вбудованих автопілотів `R_out / R_in ≈ 50..100`, коефіцієнт `K_rec ≈ 0.01..0.02`. Це означає, що буфер, заповнений за 200 мс затримки, повністю спорожнюється контролером DMA всього за 2–4 мілісекунди після відновлення працездатності шини.

## 3. Стохастична модель масового обслуговування (Queueing Model M/G/1)

Хоча датчики генерують вибірки з фіксованою періодичністю, об'єднання багатьох незалежних потоків (переривання від трьох IMU, барометра, магнітометра, EKF, планувальника завдань RTOS) формує стохастичний вхідний потік, який у теорії масового обслуговування моделюється пуассонівським процесом із параметром `λ` (пакетів/с).

### 3.1. Застосування формули Поллачека-Хінчина

Час обслуговування пакета накопичувачем `S` є випадковою величиною з математичним сподіванням `E[S] = 1/μ` та дисперсією `Var(S) = σ_S²`. Наявність рідкісних, але довгих пауз `T_stall` створює велику дисперсію `σ_S²`.

Коефіцієнт завантаження системи:
```
ρ = λ · E[S] = λ / μ         [коефіцієнт утилізації черги, 0 < ρ < 1]
```

За формулою Поллачека-Хінчина середня кількість пакетів у черзі `E[L]` становить:

```
E[L]
= ρ + ( λ² · σ_S² + ρ² ) ÷ ( 2 · (1 - ρ) )   [середня довжина черги]
```

Якщо час обслуговування був би строго детермінованим (`σ_S² = 0`, модель M/D/1), довжина черги дорівнювала б:

```
E[L]_{M/D/1}
= ρ + ρ² ÷ ( 2 · (1 - ρ) )
```

Проте через високу дисперсію `σ_S²`, викликану сплесками затримки MicroSD, другий доданок різко зростає. Це математично доводить, що навіть при низькому середньому завантаженні системи (`ρ ≈ 0.05..0.1`) черга в окремі моменти часу може досягати значних розмірів виключно через варіативність часу відповіді карти.

---

### 3.2. Оцінка ймовірності переповнення скінченного буфера

Для буфера скінченної місткості на `K` повідомлень імовірність переповнення `P_overflow` (ймовірність втрати пакета при надходженні) в асимптотичному наближенні теорії великих відхилень експоненційно залежить від розміру буфера:

```
P_overflow
≈ C · exp( - θ · K )         [асимптотична оцінка ймовірності переповнення]
```
де `θ > 0` — характеристичний корінь рівняння генератриси моментів черги. Звідси випливає, що збільшення розміру кільцевого буфера вдвічі знижує ймовірність випадання кадрів на кілька порядків.

---

### 3.3. Авторегресійна модель динамічних сплесків трафіку (AR(1) Burst Dynamics)

Під час виконання різких просторових маневрів (максимальний розгін, вихід із пікірування) вібраційний спектр рами розширюється. Алгоритми автопілота активують додаткові діагностичні топіки відстеження гармонік (Tracked Gyro Harmonic Peaks) та логують стан внутрішніх інтеграторів ПІД-регулятора на підвищеній частоті.

Цей процес описується авторегресійною моделлю першого порядку AR(1):
```
R_in(t) = R_base + α · (R_in(t - 1) - R_base) + ε(t)
```
де:
* `R_base` — номінальний трафік спокійного польоту (200 КБ/с),
* `α ∈ (0, 1)` — коефіцієнт кореляції маневру (`α ≈ 0.85`),
* `ε(t)` — випадковий сплеск генерації діагностичних логів.

Враховуючи авторегресійну кореляцію, дисперсія сумарного обсягу накопичених за час затримки даних зростає у `1 / (1 - α)²` разів, що математично підтверджує необхідність інженерного коефіцієнта запасу `k_safe ≥ 1.5` при розрахунку розміру буфера в оперативній пам'яті.

## 4. Математична модель вибіркового скидання пріоритетів (Selective Drop Model)

Коли виникає екстремальний сплеск затримки (`T_stall > 500 мс`, спричинений глибоким циклом ремапінгу бед-блоків дешевої карти пам'яті), повного обсягу буфера SRAM може не вистачити навіть при місткості 64 КБ. У такій ситуації підсистема логування застосовує алгоритм багатопріоритетного скидання черг.

Усі логовані потоки розділяються на три класи пріоритетів:
1. **Клас P₁ (Критичний стан):** Повідомлення параметрів `PARM`, кути орієнтації `ATT`, стан навігаційного фільтра `EKF`, текстові журнали помилок `MSG`/`LOG`. Швидкість потоку: `R_1 ≈ 25 КБ/с`.
2. **Клас P₂ (Керування та приводи):** Виходи регуляторів `CTUN`, сигнали моторів `RCOU`, вхідні канали пілота `RCIN`. Швидкість потоку: `R_2 ≈ 35 КБ/с`.
3. **Клас P₃ (Високочастотні сирі вибірки):** Сирі вибірки тривісних гіроскопів та акселерометрів на частотах 1000–2000 Гц (`IMU`, `sensor_combined`). Швидкість потоку: `R_3 ≈ 145 КБ/с`.

Сумарний потік:
```
R_in = R_1 + R_2 + R_3 = 25 + 35 + 145 = 205 КБ/с
```

Коли рівень заповнення кільцевого буфера перевищує поріг скидання `Q_thresh = 0.75 · B`, логер вмикає селективне фільтрування:
* Трафік класу P₃ негайно припиняє записуватися в буфер (`R_3 → 0`).
* Ефективний вхідний потік падає до:
  ```
  R_degraded = R_1 + R_2 = 25 + 35 = 60 КБ/с   [падіння навантаження на 71%]
  ```
* Якщо буфер продовжує заповнюватися і досягає порогу `Q_crit = 0.90 · B`, скидається також клас P₂, зменшуючи потік до мінімальних `R_1 = 25 КБ/с`.

Максимальний час затримки `T_max_survive`, який система здатна витримати без втрати критичних даних навігації:

```
T_max_survive
= (B - Q_thresh) ÷ R_1       [час виживання на критичному потоці P1]
= (65536 - 49152) ÷ 25600
= 16384 ÷ 25600 ≈ 0.640 с = 640 мс
```

Селективне скидання високочастотних сирих вибірок дозволяє збільшити час автономного утримання критичної телеметрії у буфері більш ніж утричі (з 200 мс до 640 мс).

## 5. Порівняння ефективності: подвійна буферизація проти кільцевого буфера

В архітектурі вбудованих систем розглядають два підходи до організації проміжного накопичувача:
1. **Подвійна буферизація (Double Buffering / Ping-Pong Buffers):** Виділення двох окремих масивів фіксованого розміру `S_block` (зазвичай 4096 байтів). Поки один буфер наповнюється, другий вивантажується через DMA на SD-карту.
2. **Циклічний кільцевий буфер (Lockless Circular Ring Buffer):** Єдиний суцільний масив пам'яті з атомарними покажчиками `Head` та `Tail`.

### Математичне зіставлення ефективності використання пам'яті
У схемі Ping-Pong максимальний розмір одиничної затримки, яку здатна поглинути система, обмежений обсягом одного блоку:
```
T_max_pingpong = S_block ÷ R_in
```
Для блоку `S_block = 4096 байтів` та швидкості `R_in = 200 КБ/с`:
```
T_max_pingpong = 4096 ÷ 204800 = 0.020 с = 20 мс
```
Якщо сплеск затримки триває 150 мс, схема Ping-Pong гарантовано переповниться, оскільки другий буфер буде заблокований триваючим записом.

Натомість кільцевий буфер місткістю 64 КБ дозволяє безперервно акумулювати потік протягом усіх 200 мс затримки, забезпечуючи коефіцієнт використання виділеної оперативної пам'яті `η = 100%` проти `η ≤ 50%` у подвійній буферизації.

## 6. Параметричний аналіз чутливості розміру буфера

Для оптимізації розподілу SRAM у мікроконтролерах із суворими обмеженнями пам'яті корисно проаналізувати частинні похідні функції необхідного розміру буфера:

```
B(R_in, T_stall) = k_safe · R_in · T_stall
```

Чутливість до тривалості затримки карти:
```
∂B / ∂T_stall = k_safe · R_in
```
При `R_in = 200 КБ/с` та `k_safe = 1.5` кожні додаткові 10 мс паузи SD-карти вимагають рівно 3.0 КБ додаткової оперативної пам'яті.

Чутливість до вхідного бінарного бітрейту:
```
∂B / ∂R_in = k_safe · T_stall
```
При `T_stall = 200 мс` кожні додаткові 10 КБ/с вхідного потоку датчиків (наприклад, підключення ще одного IMU на 200 Гц) вимагають 3.0 КБ приросту буфера SRAM.

Вплив тактової частоти інтерфейсу:
* При використанні шини SPI на частоті 20 МГц теоретична швидкість становить `R_out ≈ 2.5 МБ/с`, а час спорожнення `T_drain ≈ 17.5 мс`.
* При переході на 4-бітний інтерфейс SDMMC на частоті 50 МГц швидкість зростає до `R_out ≈ 12.5 МБ/с`, скорочуючи час скидання до 3.4 мс.

### 7.2. Розрахунок параметрів буфера під сплеск затримки 200 мс

За результатами апаратних вимірювань типова MicroSD-карта класу SanDisk Extreme UHS-I при записі блоків піддається паузам тривалістю `T_stall = 200 мс = 0.20 с`.

1. **Розрахунок базового накопичення за час паузи:**
   ```
   Q_peak
   = R_in · T_stall
   = 208320 · 0.20
   = 41 664 байти ≈ 40.69 КБ
   ```

2. **Врахування коефіцієнта запасу на стохастичні сплески (`k_safe = 1.5`):**
   ```
   B_required
   = k_safe · Q_peak
   = 1.5 · 41664
   = 62 496 байтів ≈ 61.03 КБ
   ```

3. **Округлення до ступеня двійки для оптимізації кільцевого буфера:**
   Для ефективного обчислення операції взяття залишку `index = head & (B - 1)` на рівні однієї апаратної інструкції процесора розмір буфера обирається як найближчий степінь двійки:
   ```
   B_alloc = 65 536 байтів = 64 КБ (2¹⁶ байтів)
   ```

4. **Розрахунок часу відновлення буфера `T_drain`:**
   Швидкість запису інтерфейсу 4-bit SDMMC (DMA) при тактовій частоті 50 МГц становить `R_out = 12.5 МБ/с = 12.5 × 10⁶ байтів/с`:
   ```
   T_drain
   = Q_peak ÷ (R_out - R_in)            [формула часу розвантаження]
   = 41664 ÷ (12500000 - 208320)        [підстановка числових значень]
   = 41664 ÷ 12291680                   [обчислення різниці знаменника]
   ≈ 0.00339 с ≈ 3.39 мс                [кінцевий час спорожнення в мілісекундах]
   ```

## 8. Динамічна адаптація порогів скидання та апаратне регулювання DMA

В сучасних польотних контролерах високого класу застосовують алгоритми динамічної адаптації порогів зливання черги. Замість статичного очікування наповнення буфера до розміру кластера FATFS (4096 байтів), контролер моніторить швидкість росту покажчиків:
* **Адаптивний поріг DMA Watermark:** Якщо похідна заповнення черги `dQ/dt` перевищує базовий рівень `R_in` у 2–3 рази (наприклад, під час інтенсивного виконання фігур вищого пілотажу, коли одночасно активуються логи швидких кутових прискорень), поріг запуску DMA автоматично зменшується з 4096 байтів до 512 байтів.
* **Мінімізація латентності:** Це дозволяє утилізувати шину SDMMC дрібними, але частими порціями ще до того, як рівень черги наблизиться до критичної межі `Q_thresh`.
* **Розподіл шинної матриці (AXI Bus Matrix):** Використання виділеного контролера BDMA або MDMA на кристалі STM32H7 дозволяє передавати блоки пам'яті між SRAM та периферією SDMMC паралельно, не створюючи колізій на головній шині ядра AXI, що гарантує стабільний час виконання циклів ПІД-стабілізації навіть при піковому зливанні даних.
* **Запобігання перериванню польоту:** Завдяки комбінації апаратного DMA, кільцевої адресації через бітову маску `head & (B - 1)` та адаптивного порогу водяного знака ймовірність втрати критичних даних польоту на надійних носіях класу A2 прямує до нуля (`P_drop < 10⁻⁸`).

## 9. Інженерні висновки та правила проектування

1. **Мінімальний поріг безпеки пам'яті:** Для надійного логування високочастотного потоку 200 КБ/с без втрати даних виділений розмір кільцевого буфера SRAM повинен становити **не менше 64 КБ**.
2. **Асиметрія часу заповнення та спустошення:** Час накопичення критичного обсягу (200 мс) у 60 разів перевищує час його апаратного скидання каналом DMA (3.4 мс). Це гарантує швидке повернення системи до стійкого базового стану після проходження сплеску затримки.
3. **Вибір класу носія:** Використання промислових карт MicroSD із підтримкою режиму pSLC (pseudo-Single-Level Cell) або класу Application Performance Class A2 знижує максимальну затримку `T_stall` з 200 мс до 20–30 мс, що дозволяє зменшити необхідний розмір буфера в оперативній пам'яті до 16 КБ.
