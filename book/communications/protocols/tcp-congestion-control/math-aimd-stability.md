# 🧮 Аналіз стійкості AIMD та модель продуктивності Матіса

Контроль заторів у протоколі TCP спирається на математично доведені моделі збіжності та стійкості. Головним алгоритмом лінійного регулювання є **аддитивне збільшення та мультиплікативне зменшення** (англ. *Additive Increase Multiplicative Decrease*, AIMD). Цей документ розбирає формальний векторний доказ стійкості AIMD за моделлю Чіу-Джейна, доводить непридатність альтернативних комбінацій (AIAD, MIMD, MIAD), а також покроково виводить аналітичну формулу Матіса та узагальнену модель Падьє, які пов'язують ймовірність втрати пакетів із максимально досяжною швидкістю передачі даних.

## Модель Чіу-Джейна: векторний простір двох потоків

У 1989 році Дхамака Чіу (Dah-Ming Chiu) та Радж Джейн (Raj Jain) запропонували математичний апарат для аналізу розподілу спільного ресурсу каналу між `n` незалежними потоками.

Розглянемо спрощену систему з двох потоків даних із швидкостями `x₁` та `x₂`, які ділять один вузький канал із сумарною пропускною здатністю `C`. Стан системи в кожен момент часу визначається точкою `(x₁, x₂)` на двовимірній фазовій площині.

Система має дві фундаментальні межі:

1. **Лінія ефективності (єдності ресурсу):**
   ```
   x₁ + x₂ = C
   ```
   Якщо `x₁ + x₂ < C`, канал недовантажений і мережевий ресурс марнується. Якщо `x₁ + x₂ > C`, у мережі виникає затор, буфери маршрутизаторів переповнюються і починаються втрати пакетів.

2. **Лінія справедливості (рівного розподілу):**
   ```
   x₁ = x₂
   ```
   Усі точки на цій лінії відповідають ідеально рівному розподілу пропускної здатності між обома користувачами, незалежно від того, коли кожен із них відкрив з'єднання.

Перетин цих двох ліній визначає єдину **оптимальну точку** `(C/2, C/2)`, у якій ресурс каналу використовується на 100%, а обидва потоки отримують однакову частку.

```
x₂ (Швидкість Потоку 2)
  ▲
  │     Лінія справедливості (x₁ = x₂)
  │    /
  │   /   Оптимум (C/2, C/2)
  │  /   ●
  │ /   / \
  │/   /   \  Лінія ємності (x₁ + x₂ = C)
  ┼───┼─────\─────────► x₁ (Швидкість Потоку 1)
 O    C/2    C
```

## Доказ збіжності чотирьох комбінацій розширення/скорочення

Нехай на кожному кроці регулювання (через інтервал часу RTT) потоки змінюють свої швидкості за загальною лінійною формулою:

```
[при відсутності втрат]    xᵢ(t + 1) = a + b · xᵢ(t),   де a ≥ 0, b ≥ 1
[при виявленні втрати]     xᵢ(t + 1) = c + d · xᵢ(t),   де c ≥ 0, 0 ≤ d < 1
```

Для кількісної оцінки справедливості розподілу ресурсів використовується **Індекс справедливості Джейна** (Jain's Fairness Index):

```
F(x₁, x₂) = (x₁ + x₂)² / (2 · (x₁² + x₂²))
```

Властивості індексу справедливості `F`:
- Якщо `x₁ = x₂`, то `F = (2x₁)² / (2 · 2x₁²) = 4x₁² / 4x₁² = 1.0` (ідеально рівний розподіл).
- Якщо один потік займає весь канал (`x₁ = C`, `x₂ = 0`), то `F = C² / (2 · C²) = 0.5` (максимальна несправедливість).
- Для `n` потоків формула узагальнюється як `F(x₁, ..., xₙ) = (∑ xᵢ)² / (n · ∑ xᵢ²)`.

Розглянемо чотири можливі комбінації лінійного регулювання на фазовій площині:

### 1. Аддитивне збільшення / Аддитивне зменшення (AIAD)

Правила: при успіху `xᵢ → xᵢ + α`, при втраті `xᵢ → xᵢ - β` (де `α > 0, β > 0`).

Розглянемо зміну стану системи під час кроку збільшення:
```
(x₁ + α, x₂ + α)
```
Вектор зміни `(α, α)` спрямований під кутом 45° до осей координат. Відношення швидкостей двох потоків змінюється з `x₂ / x₁` на `(x₂ + α) / (x₁ + α)`. Якщо початково `x₂ > x₁`, то дріб `(x₂ + α)/(x₁ + α)` стає ближчим до 1, ніж `x₂/x₁`. Справедливість при збільшенні трохи зростає.

Проте при настанні затору правила AIAD вимагають відняти однакову величину `β`:
```
(x₁ - β, x₂ - β)
```
Вектор зменшення `(-β, -β)` спрямований строго в протилежний бік під кутом 225° (паралельно вектору збільшення). В результаті за повний цикл «зростання + зменшення» система здійснює нескінченні паралельні осциляції вздовж однієї прямої лінії. Відстань до лінії справедливості `x₁ = x₂` **взагалі не зменшується**. Механізм AIAD є непридатним, оскільки він не збігається до рівності.

### 2. Мультиплікативне збільшення / Мультиплікативне зменшення (MIMD)

Правила: при успіху `xᵢ → γ · xᵢ` (де `γ > 1`), при втраті `xᵢ → d · xᵢ` (де `0 < d < 1`).

Обчислимо відношення швидкостей після кроку збільшення:
```
(γ · x₂) / (γ · x₁) = x₂ / x₁
```
Аналогічно при зменшенні:
```
(d · x₂) / (d · x₁) = x₂ / x₁
```
Співвідношення швидкостей **не змінюється взагалі ніколи**. Вектор руху завжди спрямований уздовж прямої лінії, що з'єднує початок координат `(0,0)` із поточним станом точки `(x₁, x₂)`. Якщо один потік стартував раніше й отримав швидкість 100 кбіт/с, а другий відкрився пізніше зі швидкістю 10 кбіт/с, то при MIMD перший потік завжди споживатиме у 10 разів більше за другий. Індекс справедливості залишається постійним (`F = const`). Протокол з MIMD є принципово несправедливим до нових з'єднань.

### 3. Мультиплікативне збільшення / Аддитивне зменшення (MIAD)

Правила: при успіху `xᵢ → γ · xᵢ`, при втраті `xᵢ → xᵢ - β`.

При крокі зменшення відношення швидкостей стає:
```
(x₂ - β) / (x₁ - β)
```
Якщо `x₂ > x₁`, це значення є **більшим** за початкове `x₂/x₁`. Це означає, що потік із меншою швидкістю `x₁` втрачає набагато більшу відносну частку свого ресурсу, ніж великий потік `x₂`. При кожній втраті малий потік наближається до нуля, тоді як великий захоплює все більше каналу. Механізм MIAD є **дивергентним та нестійким**: він знищує малі потоки й призводить к монополізації мережі.

### 4. Аддитивне збільшення / Мультиплікативне зменшення (AIMD)

Правила: при успіху `xᵢ → xᵢ + α`, при втраті `xᵢ → d · xᵢ` (у класичному TCP Reno: `α = 1 MSS`, `d = 0.5`).

Математичний доказ збіжності AIMD:

Обчислимо евклідову відстань `D` від довільної точки `(x₁, x₂)` до лінії справедливості `x₁ - x₂ = 0`:

```
D = |x₁ - x₂| / √2
```

1. **Аналіз кроку аддитивного збільшення (xᵢ → xᵢ + α):**
   ```
   D_new = |(x₁ + α) - (x₂ + α)| / √2 = |x₁ - x₂| / √2 = D
   ```
   Абсолютна відстань `D` до лінії справедливості залишається незмінною. Проте сумарна швидкість `S = x₁ + x₂` зростає на `2α`.
   Відносна помилка справедливості визначається як `E = D / S`. Оскільки чисельник `D` константний, а знаменник `S` зростає, відносна помилка `E` **зменшується**:
   ```
   E_new = D / (S + 2α) < E
   ```

2. **Аналіз кроку мультиплікативного скорочення (xᵢ → d · xᵢ):**
   ```
   D_new = |d · x₁ - d · x₂| / √2 = d · (|x₁ - x₂| / √2) = d · D
   ```
   Оскільки параметр скорочення `d = 0.5 < 1`, абсолютна відстань `D` **прямо зменшується вдвічі** за один крок скорочення!

Сумарний ефект циклу AIMD: розширення зберігає абсолютний розрив, зменшуючи відносний, а скорочення масштабує абсолютний розрив до нуля. У результаті траєкторія стану системи утворює стискальний зациклений трикутник, який геометрично збігається до точної точки оптимуму `(C/2, C/2)`. Це доводить, що AIMD є єдиною стійкою та справедливою лінійною стратегією.

## Формула Матіса: математична межа пропускної здатності TCP

У 1997 році Метт Матіс (Matt Mathis), Джеффрі Семке (Jeffrey Semke) та Джамшид Махдаві (Jamshid Mahdavi) вивели аналітичну модель продуктивності TCP у режимі уникання заторів (AIMD) при випадкових втратах пакетів із ймовірністю `p`.

### Покрокове виведення формули

Розглянемо один стаціонарний цикл пилкоподібної динаміки вікна `cwnd` між двома послідовними втратами пакетів.

Нехай `W` — максимальний розмір вікна заторів (у сегментах MSS) безпосередньо перед втратою пакета.

```
1. Значення вікна після мультиплікативного скорочення (AIMD: d = 0.5):
   W_min = W / 2

2. Тривалість одного циклу пилки (у інтервалах RTT):
   Оскільки у кожному RTT вікно зростає на 1 MSS (a = 1):
   N_RTT = W - W_min = W - W/2 = W / 2

3. Середнє значення вікна за цикл:
   W_avg = (W + W_min) / 2 = (W + W/2) / 2 = (3/4) · W

4. Загальна кількість пакетів Y, переданих за один цикл пилки:
   Y дорівнює площі під графіком вікна (площа трапеції):
   Y = N_RTT · W_avg
   
   Замінимо N_RTT та W_avg їхніми виразами через W:
   Y = (W / 2) · ((3/4) · W)
   Y = (3/8) · W²

5. Зв'язок із ймовірністю втрат p:
   За визначенням, якщо на один цикл з Y пакетів припадає 1 втрачений пакет, то ймовірність втрати p дорівнює:
   p = 1 / Y = 1 / ((3/8) · W²) = 8 / (3 · W²)

   Звідси виразиємо пикове вікно W через ймовірність p:
   W² = 8 / (3 · p)
   W = √(8 / (3 · p)) = √(8/3) · (1 / √p) ≈ 1.633 / √p

6. Підставимо W у вираз для середнього вікна W_avg:
   W_avg = (3/4) · W = (3/4) · √(8 / (3 · p))
   W_avg = √(9/16 · 8/3 · 1/p) = √(72 / 48 · 1/p) = √(1.5 / p) ≈ 1.225 / √p

7. Обчислення середньої швидкості передачі даних (BW — Bandwidth):
   Пропускна здатність дорівнює обсягу байтів, переданих за один RTT:
   BW = (W_avg · MSS) / RTT

   Підставляємо виражене W_avg:
   BW = (MSS / RTT) · (1.225 / √p)
```

Отже, підсумкова **Формула Матіса** має вигляд:

```
BW ≤ (MSS / RTT) · (C / √p)
```

де `C = √(1.5) ≈ 1.225` (для класичного TCP Reno з `α = 1` та `d = 0.5`).

## Узагальнена модель Падьє (Padhye Model)

Модель Матіса припускає, що всі втрати виявляються через 3 dupACK (Fast Retransmit) без спрацьовування тайм-аутів RTO. У 1998 році Джітендра Падьє (Jitendra Padhye), Вішал Фіройю (Vishal Firoiu), Джим Куроуз (Jim Kurose) та Дон Товслі (Don Towsley) розробили повну математичну модель, яка враховує можливість тайм-аутів RTO при серійних втратах пакетів (англ. *burst loss*).

Формула Падьє виражає продуктивність TCP як:

```
BW = min( W_max, 1 / ( RTT · √(2p / 3) + RTO · 3 · √(3p / 8) · p · (1 + 32p²) ) )
```

Коли ймовірність втрат `p` дуже мала (`p → 0`), член із `RTO` наближається до нуля, і формула Падьє зводиться до классичної формули Матіса. Проте при високих втратах (`p > 0.05`) значення тайм-ауту RTO починає домінувати, що призводить до падіння продуктивності за законом `1/p` замість `1/√p`.

## Практичний розбір трьох числових сценаріїв

### Сценарій A: Локальна мережа з малими затримками (LAN)
- Параметри: `MSS = 1460 байтів`, `RTT = 1 мс` (0.001 с), ймовірність втрати `p = 0.0001` (0.01%).
- Обчислення:
  ```
  1 / √p = 1 / √0.0001 = 1 / 0.01 = 100
  W_avg = 1.225 · 100 = 122.5 сегментів
  BW = (122.5 · 1460 байтів) / 0.001 с = 178 850 000 байтів/с
  BW_mbps = (178 850 000 · 8) / 1 000 000 = 1430.8 Mbit/s (≈ 1.43 Gbit/s)
  ```
- Висновок: У локальній мережі з малою затримкою AIMD без проблем утилізує гігабітний канал.

### Сценарій B: Трансатлантичний оптичний канал (High RTT)
- Параметри: `MSS = 1460 байтів`, `RTT = 100 мс` (0.1 с), ймовірність втрати `p = 0.0001` (0.01%).
- Обчислення:
  ```
  1 / √p = 100
  W_avg = 122.5 сегментів
  BW = (122.5 · 1460 байтів) / 0.1 с = 1 788 500 байтів/с
  BW_mbps = (1 788 500 · 8) / 1 000 000 = 14.3 Mbit/s
  ```
- Висновок: Збільшення RTT у 100 разів при тому самому рівні втрат пропорційно знижує швидкість TCP Reno у 100 разів — до 14.3 Мбіт/с.

### Сценарій C: Бездротова мережа з радіовтратами (Wi-Fi / 4G)
- Параметри: `MSS = 1460 байтів`, `RTT = 40 мс` (0.04 с), ймовірність втрати `p = 0.04` (4% шумові втрати в ефірі).
- Обчислення:
  ```
  1 / √p = 1 / √0.04 = 1 / 0.2 = 5
  W_avg = 1.225 · 5 = 6.125 сегментів
  BW = (6.125 · 1460 байтів) / 0.04 с = 223 562 байтів/с
  BW_mbps = (223 562 · 8) / 1 000 000 = 1.78 Mbit/s
  ```
- Висновок: Шум у радіоефірі (4% втрат) сприймається алгоритмом Reno як затор у маршрутизаторах, що штучно обвалює швидкість до 1.78 Мбіт/с, навіть якщо канал абсолютно порожній. Це пояснює необхідність переходу на алгоритми BBR та CUBIC у сучасних мобільних мережах.
