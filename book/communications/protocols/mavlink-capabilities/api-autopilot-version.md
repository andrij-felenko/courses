# 📋 Специфікація повідомлення AUTOPILOT_VERSION та бітова маска можливостей MAVLink

Під час встановлення телеметрійного з'єднання між наземною станцією керування (англ. *Ground Control Station*, GCS) та бортовою системою керування безпілотним апаратом виникає потреба точно встановити, які саме версії протоколу, формати команд та функціональні розширення підтримує польотний контролер. Замість вгадування чи передачі фіксованих параметрів у протоколі MAVLink застосовують механізм динамічного узгодження (англ. *capability negotiation*). Центральним елементом цього механізму є повідомлення `AUTOPILOT_VERSION` з ідентифікатором `#148`, яке передає вичерпний опис апаратної плати, версій прошивки, операційної системи реального часу та 64-бітну маску функціональних прапорців `MAV_PROTOCOL_CAPABILITY`.

Нижче наведено вичерпну специфікацію бінарного формату повідомлення `AUTOPILOT_VERSION`, правила розміщення полів у пам'яті, детальну розшифровку кожного біта можливостей, алгоритми розпакування семантичних версій прошивки, аналіз сумісності між версіями MAVLink v1 та v2, а також готові реалізації серіалізації й розбору мовами C та C++.

---

### Двійкова структура корисного навантаження AUTOPILOT_VERSION (#148)

Повідомлення `AUTOPILOT_VERSION` належить до базового діалекту `common.xml` і має номер `ID 148`. У стандарті MAVLink v2 повне корисне навантаження повідомлення має фіксований базовий розмір 78 байтів.

Згідно з правилами кадрування MAVLink, усі поля всередині бінарного згустку впорядковано за спаданням розміру типів даних. Це запобігає появі неконтрольованого апаратного вирівнювання (англ. *padding*) на 32-бітних та 64-бітних мікроконтролерах. Спершу розміщуються 64-бітні поля (`uint64_t`), потім 32-бітні числа (`uint32_t`), далі 16-бітні значення (`uint16_t`) і наприкінці — масиви однобайтних символів та чисел (`uint8_t`).

| Зсув (байти) | Поле структури | Тип даних MAVLink | Позначення в C/C++ | Призначення та діапазон значень |
| :--- | :--- | :--- | :--- | :--- |
| `0..7` | `capabilities` | `uint64_t` | `uint64_t` | 64-бітна маска бітових прапорців `MAV_PROTOCOL_CAPABILITY` |
| `8..15` | `uid` | `uint64_t` | `uint64_t` | Застарілий 64-бітний унікальний ідентифікатор CPU або плати |
| `16..19` | `flight_sw_version` | `uint32_t` | `uint32_t` | Версія прошивки автопілота у бінарному форматі SemVer |
| `20..23` | `middleware_sw_version` | `uint32_t` | `uint32_t` | Версія проміжного програмного забезпечення (MAVLink/uORB) |
| `24..27` | `os_sw_version` | `uint32_t` | `uint32_t` | Версія операційної системи реального часу (RTOS, наприклад NuttX) |
| `28..31` | `board_version` | `uint32_t` | `uint32_t` | Апаратна ревізія та номер друкованої плати автопілота |
| `32..39` | `flight_custom_version` | `uint8_t[8]` | `uint8_t[8]` | Хеш коміту Git або вендорний рядок збірки польотної прошивки |
| `40..47` | `middleware_custom_version` | `uint8_t[8]` | `uint8_t[8]` | Хеш коміту Git або вендорний рядок для шару middleware |
| `48..55` | `os_custom_version` | `uint8_t[8]` | `uint8_t[8]` | Хеш коміту Git або ідентифікатор збірки операційної системи |
| `56..57` | `vendor_id` | `uint16_t` | `uint16_t` | Ідентифікатор виробника обладнання (USB/Dronecode Vendor ID) |
| `58..59` | `product_id` | `uint16_t` | `uint16_t` | Ідентифікатор конкретної моделі плати (USB/Dronecode Product ID) |
| `60..77` | `uid2` | `uint8_t[18]` | `uint8_t[18]` | Розширений 128-бітний унікальний серійний номер чіпа процесора |

Важливою особливістю версії протоколу MAVLink v2 є механізм усікання нульових байтів наприкінці корисного навантаження (англ. *zero-byte payload truncation*). Якщо кінцеві байти масиву `uid2` містять суцільні нулі (наприклад, коли мікроконтролер надає 12-байтний серійний номер, а решта 6 байтів залишаються нульовими), передавач відтинає їх перед обчисленням контрольної суми CRC. Довжина кадру `LEN` у заголовку зменшується, що заощаджує пропускну здатність каналу зв'язку. Приймач автоматично доповнює відсутні кінцеві байти нулями перед розбором структури.

### Історія полів розширення та відмінності між MAVLink v1 і v2

Повідомлення `AUTOPILOT_VERSION` є класичним прикладом еволюції схеми даних MAVLink з використанням механізму розширень (тег `<extensions>` у схемі XML).

У початковій версії MAVLink v1 це повідомлення містило лише перші 60 байтів — від поля `capabilities` до `os_custom_version`. Поля `vendor_id`, `product_id` та `uid2` були додані пізніше у блоці розширень. Завдяки системі екстра-байт контрольної суми `CRC_EXTRA` та правилам зворотної сумісності старі парсери MAVLink v1, отримавши повний 78-байтний кадр, відкидають кінцеві 18 байтів без помилки десеріалізації, а нові парсери, отримавши урізаний 60-байтний пакет від старого автопілота, автоматично ініціалізують поля `vendor_id`, `product_id` та `uid2` нулями.

Це означає, що наземна станція повинна бути готовою до того, що на старіших прошивках значення `uid2` може бути повністю порожнім. У такій ситуації програмне забезпечення GCS повинно перемикатися на використання застарілого 64-бітного поля `uid` або генерувати тимчасовий сесійний псевдо-ідентифікатор на основі номера системи `SYSID`.

### Механізм запиту: MAV_CMD_REQUEST_MESSAGE (#512)

Повідомлення `AUTOPILOT_VERSION` не транслюється у циклічному потоці телеметрії постійно, оскільки його зміст залишається незмінним протягом усієї сесії роботи автопілота. Натомість наземна станція ініціює запит відразу після виявлення першого сигналу `HEARTBEAT` від нового бортового вузла.

Запит виконується за допомогою універсальної команди `MAV_CMD_REQUEST_MESSAGE` (числовий код `#512`), яка пакується в повідомлення `COMMAND_LONG` (`ID 76`) або `COMMAND_INT` (`ID 75`). Раніше для цієї мети існувала окрема команда `MAV_CMD_AUTOPILOT_VERSION_REQUEST` (`#183`), проте у сучасному стандарті MAVLink вона оголошена застарілою (англ. *deprecated*) на користь єдиного стандартизованого інтерфейсу запиту будь-яких повідомлень.

Параметри команди `COMMAND_LONG` для запиту версії налаштовуються наступним чином:

* `target_system` — ідентифікатор цільового апарата (зазвичай `1`);
* `target_component` — ідентифікатор компонента (зазвичай `MAV_COMP_ID_AUTOPILOT1` = `1`);
* `command` — константа `MAV_CMD_REQUEST_MESSAGE` (`512`);
* `confirmation` — лічильник спроб відправки (починається з `0`);
* `param1` — числовий ідентифікатор запитуваного повідомлення: `148.0f` для `AUTOPILOT_VERSION`;
* `param2` .. `param6` — `0.0f` (не використовуються для цього повідомлення);
* `param7` — прапорець маршрутизації відповіді: `0.0f` для стандартної широкомовної відповіді або `1.0f` для адресної відповіді безпосередньо станції, що надіслала запит.

У відповідь автопілот надсилає один екземпляр повідомлення `AUTOPILOT_VERSION (#148)`, після чого надсилає підтвердження команди `COMMAND_ACK (#77)` із результатом `MAV_RESULT_ACCEPTED` (`0`). Якщо автопілот з якоїсь причини зайнятий або не підтримує запитувану версію, він повертає відповідний код помилки в `COMMAND_ACK` (`MAV_RESULT_FAILED` або `MAV_RESULT_UNSUPPORTED`).

У разі відсутності відповіді протягом тайм-ауту (зазвичай 1000 мс) наземна станція здійснює до трьох повторних спроб надсилання запиту із нарощуванням поля `confirmation` (0, 1, 2). Якщо відповіді немає після вичерпання ліміту спроб, станція вважає лінк обмеженим і переходить у режим сумісності з базовими протоколами (Float Mission, Float Params).

### Детальна розшифровка маски можливостей MAV_PROTOCOL_CAPABILITY

Поле `capabilities` є 64-бітним бітовим масивом (`uint64_t`), де кожен окремий біт відповідає прапорцю переліку `MAV_PROTOCOL_CAPABILITY`. Нижче наведено детальний технічний зміст кожного встановленого біта.

```
63                                                          16 15        0
+-------------------------------------------------------------+----------+
|                 Зарезервовані майбутні біти                 | Прапорці |
+-------------------------------------------------------------+----------+
                                                                ▲        ▲
                                                     FLIGHT_INFO│        │MISSION_FLOAT
                                                              (Bit 15)  (Bit 0)
```

#### Бит 0 (0x0000000000000001): MAV_PROTOCOL_CAPABILITY_MISSION_FLOAT
Вказує на підтримку базового протоколу місій, де географічні координати шляхових точок передаються числами з рухомою комою одинарної точності (`float32`) у повідомленнях `MISSION_ITEM` (`#39`). Через обмеження мантиси `float32` (24 біти) точність позиціонування на широті екватора обмежена приблизно 1.1 метра. Якщо активний лише цей біт, станція зобов'язана використовувати застарілий формат шляхових точок.

#### Бит 1 (0x0000000000000002): MAV_PROTOCOL_CAPABILITY_PARAM_FLOAT
Сигналізує про підтримку класичного протоколу конфігурації параметрів, у якому всі значення незалежно від їхнього логічного типу (цілі числа, бітові маски, булеві прапорці) упаковуються у 32-бітне поле `float param_value` повідомлень `PARAM_VALUE` (`#22`) та `PARAM_SET` (`#23`). Цей режим вимагає побайтового копіювання бітів для цілочисельних параметрів, щоб уникнути їхньої модифікації під час нормалізації чисел з рухомою комою.

#### Бит 2 (0x0000000000000004): MAV_PROTOCOL_CAPABILITY_MISSION_INT
Підтримка цілочисельного протоколу місій через повідомлення `MISSION_ITEM_INT` (`#73`). Широта й довгота передаються 32-бітними цілими числами зі знаком (`int32_t`), масштабованими коефіцієнтом `1e7` (одиниці вимірювання — десятки мікроградусів). Це забезпечує просторову роздільну здатність близько 1.1 сантиметра на поверхні Землі, повністю усуваючи накопичення похибок заокруглення під час тривалих автономних місій.

#### Бит 3 (0x0000000000000008): MAV_PROTOCOL_CAPABILITY_COMMAND_INT
Вказує на готовність автопілота приймати команди керування та просторового позиціонування у форматі `COMMAND_INT` (`#75`), де параметри просторових координат також кодуються як масштабовані цілі числа `int32_t` (`x`, `y` помножені на `1e7`), а висота `z` передається у міліметрах або абсолютних метрах.

#### Бит 4 (0x0000000000000010): MAV_PROTOCOL_CAPABILITY_PARAM_UNION
Підтримка розширеного протоколу параметрів `PARAM_EXT_VALUE` (`#322`) та `PARAM_EXT_SET` (`#323`). Значення параметра передається як 128-бітний сирий масив байтів (`char param_value[128]`) у поєднанні з полем типу `param_type` (`MAV_PARAM_EXT_TYPE`). Це дозволяє безпечно передавати 64-бітні цілі числа, рядкові константи та складні структури без спотворення бітів під час перетворення у float.

#### Бит 5 (0x0000000000000020): MAV_PROTOCOL_CAPABILITY_FTP
Підтримка високошвидкісного протоколу передачі файлів MAVLink FTP (повідомлення `FILE_TRANSFER_PROTOCOL`, `#110`). Наземна станція використовує цей прапорець для перемикання з повільного поодинокого вичитування параметрів на пакетне завантаження стиснених файлів конфігурації та польотних журналів через пакетний канал передачі даних.

#### Бит 6 (0x0000000000000040): MAV_PROTOCOL_CAPABILITY_SET_ATTITUDE_TARGET
Автопілот підтримує пряме керування орієнтацією та рівнем тяги через повідомлення `SET_ATTITUDE_TARGET` (`#82`). Використовується зовнішніми бортовими комп'ютерами (англ. *companion computers*) для передачі бажаного кватерніона орієнтації та кутових швидкостей у режимах зовнішнього керування (Offboard / Guided).

#### Бит 7 (0x0000000000000080): MAV_PROTOCOL_CAPABILITY_SET_POSITION_TARGET_LOCAL_NED
Підтримка керування положенням, швидкістю та прискоренням безпілотника у локальній системі координат NED (North-East-Down) через повідомлення `SET_POSITION_TARGET_LOCAL_NED` (`#84`).

#### Бит 8 (0x0000000000000100): MAV_PROTOCOL_CAPABILITY_SET_POSITION_TARGET_GLOBAL_INT
Підтримка потокового керування цільовою точкою в глобальній системі координат WGS-84 через повідомлення `SET_POSITION_TARGET_GLOBAL_INT` (`#86`). Координати задаються у вигляді цілих чисел, масштабованих на `1e7`.

#### Бит 9 (0x0000000000000200): MAV_PROTOCOL_CAPABILITY_TERRAIN
Підтримка протоколу обміну даними про висоту рельєфу (повідомлення `TERRAIN_REQUEST`, `TERRAIN_DATA`, `TERRAIN_REPORT`). Дозволяє автопілоту запитувати карти висот із накопичувача наземної станції під час польоту на надмалих висотах з огинанням місцевості.

#### Бит 10 (0x0000000000000400): MAV_PROTOCOL_CAPABILITY_RESERVED2
Історично зарезервований біт, який у сучасних прошивках позначає наявність апаратно-програмного модуля аварійного припинення польоту (англ. *Flight Termination System*, FTS).

#### Бит 11 (0x0000000000000800): MAV_PROTOCOL_CAPABILITY_COMPASS_CALIBRATION
Підтримка алгоритму бортового калібрування магнітометра (англ. *onboard compass calibration*). Замість пересилання сирих вимірювань магнітометра на наземну станцію для обчислення сферичного наближення, автопілот самостійно виконує розрахунки матриці корекції жестів на борту та повертає статус калібрування у реальному часі.

#### Бит 12 (0x0000000000001000): MAV_PROTOCOL_CAPABILITY_MAVLINK2
Критично важливий прапорець, що підтверджує повну підтримку кадрування MAVLink версії 2.0 (стартовий байт `0xFD`, розширений діапазон ідентифікаторів повідомлень до 24 бітів, нульове стискання корисного навантаження та криптографічний підпис пакетів). Отримавши цей біт, станція повністю перемикає лінк у режим v2.

#### Бит 13 (0x0000000000002000): MAV_PROTOCOL_CAPABILITY_MISSION_FENCE
Підтримка завантаження, перевірки та активації віртуальних просторових бар'єрів (англ. *Geo-fence*) за допомогою стандартних повідомлень протоколу місій (`MAV_CMD_NAV_FENCE_*`).

#### Бит 14 (0x0000000000004000): MAV_PROTOCOL_CAPABILITY_MISSION_RALLY
Підтримка точок аварійної посадки (англ. *Rally Points*), куди безпілотник прямує при спрацьовуванні захисних механізмів відмови зв'язку або розряду батареї.

#### Бит 15 (0x0000000000008000): MAV_PROTOCOL_CAPABILITY_FLIGHT_INFORMATION
Підтримка формування спеціального інформаційного повідомлення `FLIGHT_INFORMATION` (`#264`), яке транслює загальний час нальоту апарата (англ. *flight time*), час з моменту останнього зведення двигунів (англ. *arming time*) та унікальний ідентифікатор польотної сесії.

### Семантичне версіонування у полі flight_sw_version

Поле `flight_sw_version` упаковує номер версії прошивки згідно з концепцією семантичного версіонування (англ. *Semantic Versioning*, SemVer) у єдине 32-бітне ціле без знаку. Структура бітових полів розподіляється наступним чином:

* **Байт 3 (біти 31..24):** Головний номер версії (Major). Збільшується при внесенні несумісних змін у логіку роботи або інтерфейси керування.
* **Байт 2 (біти 23..16):** Додатковий номер версії (Minor). Збільшується при додаванні нової функціональності зі збереженням зворотної сумісності.
* **Байт 1 (біти 15..8):** Номер виправлення (Patch). Збільшується при виправленні помилок без зміни поведінки системи.
* **Байт 0 (біти 7..0):** Тип релізу (Release Type), закодований переліком `FIRMWARE_VERSION_TYPE`.

```
31              24 23              16 15               8 7                 0
+-----------------+-----------------+-----------------+-----------------+
|   Major (v1)    |   Minor (.14)   |   Patch (.0)    | Type (192 = RC) |
+-----------------+-----------------+-----------------+-----------------+
```

Значення байта типу релізу визначаються наступними константами стандарту MAVLink:

* `0` (`0x00`) — `FIRMWARE_VERSION_TYPE_DEV`: збірка з гілки розробки;
* `64` (`0x40`) — `FIRMWARE_VERSION_TYPE_ALPHA`: альфа-версія для внутрішнього тестування;
* `128` (`0x80`) — `FIRMWARE_VERSION_TYPE_BETA`: бета-версія для публічних тестів;
* `192` (`0xC0`) — `FIRMWARE_VERSION_TYPE_RC`: кандидат на фінальний реліз;
* `255` (`0xFF`) — `FIRMWARE_VERSION_TYPE_OFFICIAL`: стабільний офіційний реліз.

Для прикладу, якщо польотний контролер передає значення `flight_sw_version = 0x010E00C0`:
* Байт 3 = `0x01` = `1` (Major);
* Байт 2 = `0x0E` = `14` (Minor);
* Байт 1 = `0x00` = `0` (Patch);
* Байт 0 = `0xC0` = `192` (`FIRMWARE_VERSION_TYPE_RC`).
Рядкове представлення версії: `v1.14.0-rc`.

Аналогічна логіка кодування використовується для полів `middleware_sw_version` та `os_sw_version`. Це дає змогу GCS визначити не лише версію польотного алгоритму, а й версію ядра операційної системи NuttX, що є вирішальним фактором під час діагностики системних збоїв чи планування оновлення завантажувача.

### Ідентифікація заліза: vendor_id, product_id та uid2

Для точного розпізнавання апаратного вузла без прив'язки до типу польотного контролера використовуються поля `vendor_id` та `product_id`. Вони відповідають офіційним реєстраційним ідентифікаторам USB Vendor/Product ID або кодам організації Dronecode Foundation (наприклад, `0x26AC` для плат серії Pixhawk/Cube).

Поле `uid2` містить 18 байтів апаратного серійного номера процесора:
* Перший байт `uid2[0]` вказує формат або фактичну довжину унікального ідентифікатора (зазвичай `12` для 96-бітних серійних номерів STM32 або `16` для 128-бітних UUID);
* Наступні байти містять зчитані з регістрів мікроконтролера значення унікального кремнієвого ідентифікатора (наприклад, зчитування регістрів `UID` за адресою `0x1FFF7A10` на мікроконтролерах STM32F7/H7 або криптографічних eFuse на ESP32). Це гарантує захист від клонування телеметрійних сесій та забезпечує однозначну прив'язку сертифікатів безпеки до конкретного фізичного борту.

Завдяки наявності `uid2` наземна станція може вести наскрізну базу даних апаратів (англ. *vehicle registry*), автоматично прив'язуючи калібрувальні профілі сенсорів, польотні журнали та логи телеметрії до фізичного процесора незалежно від того, як часто користувач перепрошиває або скидає параметри контролера.

```c
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

// Бітова маска можливостей MAVLink
#define CAP_MISSION_FLOAT  (1ULL << 0)
#define CAP_PARAM_FLOAT    (1ULL << 1)
#define CAP_MISSION_INT    (1ULL << 2)
#define CAP_COMMAND_INT    (1ULL << 3)
#define CAP_PARAM_UNION    (1ULL << 4)
#define CAP_FTP            (1ULL << 5)
#define CAP_MAVLINK2       (1ULL << 12)

typedef struct {
    uint64_t capabilities;
    uint64_t uid;
    uint32_t flight_sw_version;
    uint32_t middleware_sw_version;
    uint32_t os_sw_version;
    uint32_t board_version;
    uint8_t  flight_custom_version[8];
    uint8_t  middleware_custom_version[8];
    uint8_t  os_custom_version[8];
    uint16_t vendor_id;
    uint16_t product_id;
    uint8_t  uid2[18];
} autopilot_version_payload_t;

// Перевірка готовності апарата до швидкісного обміну
bool is_high_speed_capable(const autopilot_version_payload_t* msg) {
    uint64_t mask = CAP_MISSION_INT | CAP_FTP | CAP_MAVLINK2;
    return (msg->capabilities & mask) == mask;
}

// Формування 32-бітного числа SemVer
uint32_t pack_semver(uint8_t major, uint8_t minor, uint8_t patch, uint8_t type) {
    return ((uint32_t)major << 24) |
           ((uint32_t)minor << 16) |
           ((uint32_t)patch << 8)  |
           ((uint32_t)type);
}
```

```cpp
#include <cstdint>
#include <string>
#include <string_view>
#include <array>
#include <format>
#include <span>

enum class ReleaseType : uint8_t {
    Dev      = 0,
    Alpha    = 64,
    Beta     = 128,
    Rc       = 192,
    Official = 255
};

class AutopilotVersionDecoder {
public:
    struct VersionInfo {
        uint8_t major{0};
        uint8_t minor{0};
        uint8_t patch{0};
        ReleaseType type{ReleaseType::Dev};

        [[nodiscard]] std::string to_string() const {
            std::string_view suffix;
            switch (type) {
                case ReleaseType::Dev:      suffix = "-dev"; break;
                case ReleaseType::Alpha:    suffix = "-alpha"; break;
                case ReleaseType::Beta:     suffix = "-beta"; break;
                case ReleaseType::Rc:       suffix = "-rc"; break;
                case ReleaseType::Official: suffix = ""; break;
            }
            return std::format("v{}.{}.{}{}", major, minor, patch, suffix);
        }
    };

    [[nodiscard]] static VersionInfo decode_version(uint32_t raw) noexcept {
        return {
            .major = static_cast<uint8_t>((raw >> 24) & 0xFF),
            .minor = static_cast<uint8_t>((raw >> 16) & 0xFF),
            .patch = static_cast<uint8_t>((raw >> 8) & 0xFF),
            .type  = static_cast<ReleaseType>(raw & 0xFF)
        };
    }

    [[nodiscard]] static std::string format_git_hash(std::span<const uint8_t, 8> custom_ver) {
        std::string hash_str;
        hash_str.reserve(16);
        for (uint8_t b : custom_ver) {
            hash_str += std::format("{:02x}", b);
        }
        return hash_str;
    }

    [[nodiscard]] static std::string format_uid2(std::span<const uint8_t, 18> uid_bytes) {
        std::string out;
        out.reserve(36);
        for (size_t i = 0; i < uid_bytes.size(); ++i) {
            out += std::format("{:02X}", uid_bytes[i]);
            if (i + 1 < uid_bytes.size() && (i == 3 || i == 5 || i == 7 || i == 9)) {
                out += '-';
            }
        }
        return out;
    }
};
```
