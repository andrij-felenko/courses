# 🧮 Математичне обґрунтування меж розміру вікна та ймовірнісної пропускної здатності ARQ

У протоколах передачі даних зі ковзним вікном розмір заголовка кадру суворо обмежений: під номер послідовності виділяється фіксована кількість бітів `k`, що породжує скінченний кільцевий простір номерів `M = 2^k`. Якщо розмір вікна передавача `W_s` або вікна приймача `W_r` вибрати без урахування розміру цього кільця, у разі масової втрати службових підтверджень протокол потрапляє в стан математичної неоднозначності (англ. *sequence number ambiguity*), за якого приймач не здатен відрізнити повторну передачу старого кадру від первинної передачі абсолютно нового блоку даних.

Ця математична вставка містить строгі доведення граничних теорем про допустимі розміри вікон для алгоритмів Go-Back-N та Selective Repeat на кільці лишків `ℤ_(2^k)`, повне ймовірнісне виведення коефіцієнтів використання каналу `U` та середньої затримки доставки `E[D]`, аналіз двостороннього каналу з втратами підтверджень, марковську модель пакетних завад Гілберта-Елліотта, а також аналітичне виведення оптимальної довжини кадру `L*`.

---

## 1. Алгебраїчна структура кільцевого простору номерів

Нехай під номер послідовності кадру виділено `k` бітів. Множина доступних номерів утворює скінченне кільце лишків за модулем `M = 2^k`:

```
ℤ_M = {0, 1, 2, ..., 2^k - 1}
```

Усі операції інкременту та обчислення зміщення номерів виконуються за модулем `M`:

```
Seq_next = (Seq_current + 1) mod M
```

### Метрика відносної відстані на кільці

Оскільки простір замкнений у коло, звичайне відношення лінійного порядку `<` на множині цілих чисел втрачає зміст: для `M = 8` номер `0` є як прямим наступником `7` (`0 = (7 + 1) mod 8`), так і попередником `1`.

Для коректного визначення того, чи потрапляє отриманий номер кадру `x` усередину вікна `[Base, Base + W - 1]`, вводиться функція **орієнтованої відстані за годинниковою стрілкою**:

```
dist(Base, x) = (x - Base + M) mod M
```

Ця функція відображає кільцевий інтервал на лінійну множину `{0, 1, ..., M - 1}`. Кадр `x` вважається таким, що належить активному вікну розміру `W`, тоді й тільки тоді, коли:

```
dist(Base, x) < W
```

## 2. Теорема про максимальний розмір вікна в протоколі Go-Back-N (GBN)

У протоколі Go-Back-N приймач не має буфера для зберігання невпорядкованих пакетів (`W_r = 1`) і в кожен момент часу очікує рівно один конкретний номер `R_next`. Передавач підтримує вікно розміру `W_s`.

### Формулювання теореми

> **Теорема 1 (Межа вікна GBN):** Для протоколу Go-Back-N на кільці послідовних номерів `M = 2^k` коректне функціонування без ризику помилкового прийому дублікатів можливе тоді й лише тоді, коли:
> ```
> W_s ≤ 2^k - 1 = M - 1
> ```

### Доведення (від супротного)

Нехай `W_s = M = 2^k`. Покажемо, що існує реальний сценарій втрати службових повідомлень у каналі, за якого приймач прийме спотворені дані без генерації помилки CRC.

1. **Крок 1 (Початковий стан):**
   * Передавач має базу `S_base = 0` і транслює повне вікно кадрів із номерами `0, 1, 2, ..., M - 1`.
   * Приймач перебуває в стані очікування `R_next = 0`.

2. **Крок 2 (Успішний прийом на RX):**
   * Усі `M` кадрів успішно досягають приймача без бітових помилок.
   * Приймач послідовно приймає кадри `0, 1, ..., M - 1`, передає їх прикладному процесу і для кожного генерує підтвердження `ACK 0, ACK 1, ..., ACK (M - 1)`.
   * Нове значення очікуваного номера на приймачі становить:
   ```
   R_next = (M - 1 + 1) mod M = M mod M = 0
   ```

3. **Крок 3 (Катастрофічна втрата зворотного каналу):**
   * Усі `M` пакетів `ACK` губляться у зворотному каналі через сплеск завад.
   * Передавач не отримує жодного підтвердження.

4. **Крок 4 (Спрацьовування таймауту на TX):**
   * На передавачі спливає таймер очікування для найстарішого кадру `S_base = 0`.
   * За алгоритмом GBN передавач зобов'язаний повторити передачу всього непідтвердженого вікна, починаючи з `S_base`.
   * Передавач повторно випромінює в канал старий кадр `0` (копію вже прийнятих даних).

5. **Крок 5 (Колізія сприйняття на RX):**
   * Приймач отримує цей повторний кадр із позначкою `Seq = 0`.
   * Приймач порівнює `Seq` зі своїм поточним очікуваним станом `R_next`. Оскільки `R_next = 0`, приймач робить помилковий висновок: *«Прибув абсолютно новий кадр 0 із наступного циклу нумерації»*.
   * Приймач записує дублікат старих даних у вихідний потік застосунку.

Дані незворотно спотворені дублюванням. Отже, рівність `W_s = M` є неприпустимою.

Якщо ж `W_s ≤ M - 1`, то після успішного прийому вікна приймач зміщується в стан `R_next = W_s mod M`. Старий непідтверджений кадр має номер `0`. Оскільки `0 ≠ W_s mod M` (бо `1 ≤ W_s < M`), повторний кадр `0` не збігається з `R_next`, успішно розпізнається як запізнілий дублікат і відкидається приймачем. Теорему доведено. `■`

## 3. Теорема про розміри вікон у протоколі Selective Repeat (SR)

У протоколі Selective Repeat приймач володіє внутрішнім буфером розміру `W_r > 1`, що дозволяє приймати та тимчасово зберігати невпорядковані кадри з діапазону `[R_base, R_base + W_r - 1]`. Передавач має вікно `W_s`.

### Формулювання теореми

> **Теорема 2 (Межа вікон Selective Repeat):** Для протоколу Selective Repeat на кільці послідовних номерів `M = 2^k` однозначне розпізнавання дублікатів гарантується тоді й лише тоді, коли сума розмірів вікон передавача та приймача не перевищує потужності простору номерів:
> ```
> W_s + W_r ≤ 2^k = M
> ```
> У класичному симетричному випадку (`W_s = W_r = W`):
> ```
> W ≤ 2^(k - 1) = M / 2
> ```

### Доведення (геометрично-алгебраїчне на кільці)

Проаналізуймо граничні просторові зміщення вікна передавача та вікна приймача на кільці `ℤ_M`.

Нехай у початковий момент часу `t_0` обидва вікна мають спільну точку відліку:
* Вікно передавача: `TX_win = [0, W_s - 1]`
* Вікно приймача: `RX_win = [0, W_r - 1]`

1. **Крок 1 (Максимальний вихід RX уперед):**
   * Передавач надсилає всі кадри від `0` до `W_s - 1`.
   * Приймач без помилок отримує всі ці кадри, надсилає відповідні індивідуальні `ACK` і зсуває своє вікно на максимально можливу дистанцію `W_s` позицій уперед.
   * Нове вікно приймача охоплює діапазон:
   ```
   RX_win = [W_s, W_s + W_r - 1] mod M
   ```

2. **Крок 2 (Максимальне відставання TX через втрату ACK):**
   * Нехай усі `W_s` надісланих `ACK` губляться в каналі зв'язку.
   * Вікно передавача не зрушується взагалі й залишається на місці:
   ```
   TX_win = [0, W_s - 1] mod M
   ```

3. **Крок 3 (Умова виникнення колізії):**
   * Після спливання таймауту передавач повторює передачу кадру з номером `0`.
   * Кадр `0` досягає приймача. Приймач перевіряє, чи потрапляє номер `0` у його активне вікно `RX_win = [W_s, W_s + W_r - 1] mod M`.
   * Якщо `0 ∈ RX_win`, приймач сприйме старий дублікат як новий кадр із наступного кола.
   * Щоб номер `0` гарантовано не належав множині `[W_s, W_s + W_r - 1] mod M`, верхня границя вікна приймача без взяття за модулем не повинна дійти до `M`:
   ```
   W_s + W_r - 1 < M
   ```
   Оскільки всі величини цілочисельні:
   ```
   W_s + W_r ≤ M = 2^k
   ```

Якщо `W_s + W_r > 2^k`, то верхня межа зсунутого вікна приймача перекриває початок старого вікна передавача (`0 mod M`), спричиняючи непомітне пошкодження потоку даних. Для стандартного випадку рівних буферів `W_s = W_r = W` маємо:

```
2 · W ≤ 2^k  ⇒  W ≤ 2^(k - 1)
```

Теорему доведено. `■`

## 4. Виведення коефіцієнта використання каналу U та пропускної здатності

Оцінимо математичне сподівання часу передачі кадру та коефіцієнт використання каналу `U` для різних протоколів ARQ.

Введемо базові фізичні параметри:
* `L` — довжина кадру даних (біт).
* `R` — бітова швидкість каналу (біт/с).
* `T_tx = L / R` — час передачі (випромінювання) кадру.
* `T_prop` — одностороння затримка поширення сигналу в середовищі.
* `a = T_prop / T_tx` — нормалізована затримка поширення.
* `RTT ≈ T_tx + 2 · T_prop = T_tx · (1 + 2a)` — час повного кругового обігу.
* `p` — імовірність того, що окремо взятий кадр буде втрачено або пошкоджено (Frame Error Rate, FER). Помилки вважаються статистично незалежними за схемою випробувань Бернуллі.

Коефіцієнт використання каналу `U` визначається як відношення часу передачі корисних бітів до загального часу зайнятості каналу:

```
U = T_tx / (E[T_total] · (1 - p))
```

### 4.1. Stop-and-Wait ARQ

У протоколі Stop-and-Wait на кожну спробу передачі витрачається повний цикл `T_cycle = T_tx + 2 · T_prop = T_tx · (1 + 2a)`.

Кількість спроб передачі `K` до першого успіху є геометрично розподіленою випадковою величиною з параметром успіху `(1 - p)`:

```
P(K = i) = (1 - p) · p^(i - 1),   i = 1, 2, 3, ...
```

Математичне сподівання кількості спроб `E[K]`:

```
E[K] = ∑ [i=1..∞] i · (1 - p) · p^(i - 1)
= (1 - p) · d/dp ( ∑ [i=0..∞] p^i )   [похідна степеневого ряду]
= (1 - p) · d/dp ( 1 / (1 - p) )      [сума нескінченної геометричної прогресії]
= (1 - p) · ( 1 / (1 - p)² )          [диференціювання]
= 1 / (1 - p)                         [скорочення]
```

Середній сумарний час, необхідний для успішної доставки одного кадру:

```
E[T_SW] = E[K] · T_cycle = (T_tx · (1 + 2a)) / (1 - p)
```

Коефіцієнт використання каналу:

```
U_SW = T_tx / E[T_SW] = (1 - p) / (1 + 2a)
```

При великих затримках (`a >> 1`), навіть якщо канал ідеальний (`p = 0`), маємо `U_SW ≈ 1 / (2a) → 0`.

---

### 4.2. Go-Back-N ARQ

У Go-Back-N передавач веде неперервну передачу. Розглянемо випадок, коли розмір вікна достатній для повного заповнення каналу: `W_s ≥ 1 + 2a`.

1. Якщо кадр передано успішно (з імовірністю `1 - p`), на нього витрачається рівно `1` інтервал `T_tx`.
2. Якщо кадр пошкоджено (з імовірністю `p`), передавач витрачає `1` інтервал на невдалу передачу і після спливання таймауту зобов'язаний повторно передати не лише цей кадр, а й усі `W_s - 1` наступних кадрів, які приймач відкинув. Отже, кожна невдала спроба коштує `W_s` інтервалів передачі.

Математичне сподівання загальної кількості витрачених інтервалів передачі `N_tx` для доставки одного успішного кадру:

```
E[N_tx] = 1 · (1 - p) + (1 + W_s + E[N_tx] - 1) · p   [початкове ймовірнісне рівняння]
= 1 - p + p + W_s · p + p · (E[N_tx] - 1)            [розкриття дужок]
= 1 + W_s · p + p · E[N_tx] - p                      [скорочення 1 - p + p = 1]
= 1 + (W_s - 1) · p + p · E[N_tx]                    [групування членів при p]
```

Розв'яжемо рівняння відносно `E[N_tx]`:

```
E[N_tx] - p · E[N_tx] = 1 + (W_s - 1) · p   [перенесення p·E[N_tx] ліворуч]
E[N_tx] · (1 - p) = 1 + (W_s - 1) · p       [винесення E[N_tx] за дужки]
E[N_tx] = (1 + (W_s - 1) · p) / (1 - p)     [ділення обох частин на (1 - p)]
```

Коефіцієнт використання каналу `U_GBN` (при `W_s ≥ 1 + 2a`):

```
U_GBN = 1 / E[N_tx] = (1 - p) / (1 + (W_s - 1) · p)   [обернена величина до E[N_tx]]
```

Якщо ж вікно вибрано замалим (`W_s < 1 + 2a`), передавач простоює час `(1 + 2a - W_s) · T_tx` в очікуванні підтверджень, і формулу модифікують:

```
U_GBN = (W_s · (1 - p)) / ((1 + 2a) · (1 + (W_s - 1) · p))   [для W_s < 1 + 2a]
```

### 4.3. Selective Repeat ARQ

У протоколі Selective Repeat приймач буферизує всі правильно прийняті кадри незалежно від їхнього порядку. Повторна передача здійснюється суто для тих блоків, які були реально пошкоджені.

Втрата одного кадру жодним чином не знецінює передачу інших `W_s - 1` пакетів вікна. Кожен кадр вимагає в середньому `1 / (1 - p)` спроб передачі, кожна з яких займає рівно `1` інтервал `T_tx` (за умови, що розмір вікна `W_s ≥ 1 + 2a` усуває простої).

Математичне сподівання витрат на один кадр:

```
E[N_SR] = 1 / (1 - p)
```

Коефіцієнт використання каналу для Selective Repeat:

```
U_SR = 1 / E[N_SR] = 1 - p   [для W_s ≥ 1 + 2a]
```

Для малого розміру вікна (`W_s < 1 + 2a`):

```
U_SR = (W_s · (1 - p)) / (1 + 2a)   [для W_s < 1 + 2a]
```

## 5. Двостороння модель втрат та надійність зворотного каналу

У реальних мережах втрати відбуваються як у прямому каналі передачі даних (з імовірністю `p_f`), так і у зворотному каналі підтверджень (з імовірністю `p_r`).

Кадр вважається успішно закритим на передавачі, якщо він дійшов до приймача без помилок **і** зворотний пакет `ACK` дійшов до передавача. Імовірність успішного циклу `P_succ`:

```
P_succ = (1 - p_f) · (1 - p_r)
```

Сумарна ефективна ймовірність невдачі транзакції `p_eff`:

```
p_eff = 1 - P_succ = 1 - (1 - p_f) · (1 - p_r) = p_f + p_r - p_f · p_r
```

У протоколі Go-Back-N кумулятивна природа підтверджень пом'якшує вплив `p_r`: втрата окремого `ACK i` не шкодить з'єднанню, якщо будь-який наступний `ACK j` (`j > i`) успішно доходить до передавача до спливання таймауту. У протоколі Selective Repeat втрата індивідуального `ACK i` завжди призводить до вибіркового повтору кадру `i`, що робить SR більш залежним від надійності зворотного трафіку, якщо не використовується кумулятивне поле SACK.

## 6. Модель пакетних завад Гілберта-Елліотта

Реальні бездротові канали піддаються завмиранням сигналу (fading), через що бітові помилки виникають не поодиноко, а тривалими пачками (англ. *burst errors*). Для математичного моделювання таких середовищ застосовується двозв'язна марковська модель Гілберта-Елліотта:

```
           1 - α                     1 - β
          ┌──────┐                  ┌──────┐
          │      ▼                  │      ▼
      +--------------+          +--------------+
      |  Стан Good   |──── α ──►|   Стан Bad   |
      |   (P_e ≈ 0)  |◄─── β ───|  (P_e ≈ 0.5) |
      +--------------+          +--------------+
```

1. **Стан Good (G):** низький рівень шуму, імовірність помилки `P_e(G) ≈ 0`.
2. **Стан Bad (B):** глибоке завмирання, імовірність помилки `P_e(B) ≈ 0.5`.
3. Ймовірності переходів: `α = P(G → B)` (ймовірність входження в заваду) та `β = P(B → G)` (ймовірність виходу із завади).

Стаціонарні ймовірності перебування каналу в станах `G` та `B`:

```
π_G = β / (α + β),      π_B = α / (α + β)
```

Середня тривалість перебування в стані завади становить `1 / β` кадрів. Якщо тривалість завади `1 / β` перевищує розмір вікна `W_s`, як Go-Back-N, так і Selective Repeat змушені зупиняти передачу й чекати виходу каналу зі стану завмирання. Проте після повернення в стан `G` Selective Repeat миттєво досилає лише пошкоджені кадри, тоді як GBN витрачає `W_s` пакетів на повне перезавантаження конвеєра.

## 7. Розрахунок середньої затримки доставки кадру E[D] (Mean Delivery Delay)

Окрім коефіцієнта використання каналу `U`, критичною метрикою якості зв'язку є середня затримка доставки `E[D]` — математичне сподівання часу від моменту готовності кадру на передавачі до моменту його успішної видачі прикладному процесу на приймачі.

### Затримка Stop-and-Wait

Кожна невдала спроба затримує доставку на час повного таймауту `T_out ≈ RTT = T_tx + 2 · T_prop`. Останній успішний кадр досягає приймача за час `T_tx + T_prop`:

```
E[D_SW] = T_tx + T_prop + (E[K] - 1) · T_out
= T_tx + T_prop + (p / (1 - p)) · (T_tx + 2 · T_prop)
```

### Затримка Go-Back-N

У Go-Back-N при успішній першій спробі кадр доставляється за час `T_tx + T_prop`. Якщо кадр втрачено, передавач дізнається про це після спливання таймауту `T_out`, після чого повторно передає кадр. Середня затримка доставки для черги без накопичення:

```
E[D_GBN] = T_tx + T_prop + (p / (1 - p)) · T_out
```

### Затримка Selective Repeat та джитер буфера перевпорядкування

У Selective Repeat втрачений кадр повторюється індивідуально, тому його затримка доставки також збільшується на `(p / (1 - p)) · T_out`. Проте всі наступні кадри `k+1, k+2, ...`, які надійшли успішно, змушені **очікувати в буфері приймача** (англ. *reordering delay*) доти, доки втрачений кадр `k` не буде відновлено, щоб зберегти строгий порядок потоку даних для прикладного рівня.

Математичне сподівання додаткового часу затримки невпорядкованого кадру в буфері SR при одночасній втраті попередника становить приблизно `RTT`, що вносить варіацію затримки (джитер) у вихідний потік.

## 8. Оптимізація довжини кадру L* при випадкових бітових помилках

Нехай фізичний канал зв'язку характеризується коефіцієнтом бітових помилок `BER` (англ. *Bit Error Rate*). При довжині кадру `L` бітів (де `H` бітів — службовий заголовок і контрольна сума CRC, а `(L - H)` — корисні дані), імовірність того, що весь кадр дійде без жодної бітової помилки, дорівнює:

```
1 - p = (1 - BER)^L ≈ e^(-BER · L)   [наближення при BER << 1]
```

Ефективна пропускна здатність передачі корисних даних `S(L)` становить:

```
S(L) = R · U_SR(p) · ((L - H) / L)          [визначення корисної швидкості]
= R · (1 - p) · ((L - H) / L)               [підстановка U_SR = 1 - p для повного вікна]
= R · e^(-BER · L) · (1 - H / L)            [наближення 1 - p ≈ e^(-BER · L) та спрощення частки]
```

Щоб знайти оптимальний розмір кадру `L*`, продиференціюємо функцію `S(L)` за змінною `L` і прирівняємо похідну до нуля:

```
d/dL [ e^(-BER · L) · (1 - H · L⁻¹) ] = 0                       [умова максимуму функції S(L)]
-BER · e^(-BER · L) · (1 - H / L) + e^(-BER · L) · (H / L²) = 0 [диференціювання за правилом добутку]
-BER · (1 - H / L) + H / L² = 0                                 [скорочення на експоненту e^(-BER · L)]
-BER + BER · H / L + H / L² = 0                                 [розкриття дужок]
BER · L² - BER · H · L - H = 0                                  [множення обох частин на L²]
```

Оскільки `BER · H << 1`, нехтуючи лінійним членом, отримуємо точну асимптотичну формулу оптимального розміру кадру:

```
L* ≈ √( H / BER )
```

Наприклад, якщо службовий заголовок із CRC становить `H = 64` біти (8 байтів), а канал має якість `BER = 10⁻⁵`, оптимальний розмір кадру дорівнює:

```
L* = √( 64 / 10⁻⁵ ) = √( 6.4 · 10⁶ ) ≈ 2530 бітів (близько 316 байтів).
```

Якщо обрати кадр довжиною `1500` байтів (`12 000` бітів), імовірність втрати зросте до `p = 1 - e^(-0.12) ≈ 11.3%`, що спричинить постійні повтори. Якщо ж обрати кадр усього `64` байти, оверхед заголовків знизить корисну швидкість удвічі. Формула `L* = √(H / BER)` визначає строгий інженерний оптимум для будь-якого ARQ-протоколу.
