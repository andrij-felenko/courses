# 📋 Специфікація повідомлень та бітових масок уставок MAVLink

Цей довідник містить повну структуру бінарних пакетів, бітових масок, систем координат та числових констант, необхідних для програмної реалізації високочастотного керування безпілотними апаратами через MAVLink у режимах Offboard (PX4) та Guided (ArduPilot). Без точного дотримання цих бітових масок, систем координат та часових вимог автопілот відхиляє команди керування або переходить у стан аварійної зупинки.

---

### Архітектура передачі уставок руху

У протоколі MAVLink взаємодія між зовнішнім керуючим обчислювачем (бортовим комп'ютером або наземною станцією) та автопілотом базується на регулярному надсиланні цільових векторів стану. На відміну від разових команд керування місією (`COMMAND_LONG`), повідомлення уставок руху проектуються для високочастотної циклічної трансляції (від 10 до 50 Гц). Вони мають фіксовану бінарну довжину, не потребують підтвердження `COMMAND_ACK` на кожен надісланий пакет (що перевантажило б канал зв'язку) і містять спеціалізовані бітові маски, які вказують автопілоту, які саме фізичні величини слід брати до уваги в поточному циклі регулювання.

### Повідомлення SET_POSITION_TARGET_LOCAL_NED (#84)

Повідомлення призначене для передачі метричних уставок положення, швидкості, прискорення та кута рискання в локальній декартовій системі координат. Воно є основним інструментом для взаємодії з системами локальної навігації, такими як оптичний потік, візуально-інерційна одометрія (VIO) або лідарний SLAM.

* **ID повідомлення:** `84`
* **Назва структури C:** `mavlink_set_position_target_local_ned_t`
* **Порядок байтів у корисній структурі:** 53 байти (MAVLink v1 / v2 без розширень)
* **Призначення:** пряма ін'єкція цільових координат і динамічних векторів у локальному тривимірному метричному просторі

| Поле | Тип | Зсув (байти) | Одиниці | Опис |
| :--- | :--- | :--- | :--- | :--- |
| `time_boot_ms` | `uint32_t` | 0 | мс | Час з моменту завантаження польотного контролера (0 = автопілот бере поточний системний час) |
| `x` | `float` | 4 | м | Цільова координата X у вибраній системі координат (Північ або Вперед) |
| `y` | `float` | 8 | м | Цільова координата Y у вибраній системі координат (Схід або Праворуч) |
| `z` | `float` | 12 | м | Цільова координата Z у вибраній системі координат (Вниз: від'ємне значення = висота) |
| `vx` | `float` | 16 | м/с | Цільова лінійна швидкість уздовж осі X |
| `vy` | `float` | 20 | м/с | Цільова лінійна швидкість уздовж осі Y |
| `vz` | `float` | 24 | м/с | Цільова лінійна швидкість уздовж осі Z (позитивне значення = зниження) |
| `afx` | `float` | 28 | м/с² або Н | Лінійне прискорення або вектор сили вздовж осі X (залежить від біта `force_set`) |
| `afy` | `float` | 32 | м/с² або Н | Лінійне прискорення або вектор сили вздовж осі Y (залежить від біта `force_set`) |
| `afz` | `float` | 36 | м/с² або Н | Лінійне прискорення або вектор сили вздовж осі Z (залежить від біта `force_set`) |
| `yaw` | `float` | 40 | рад | Цільовий кут рискання (0 = Північ у NED, діапазон `[-π, +π]` або `[0, 2π]`) |
| `yaw_rate` | `float` | 44 | рад/с | Цільова кутова швидкість обертання навколо вертикальної осі Z |
| `type_mask` | `uint16_t` | 48 | бітова маска | 16-бітна маска ігнорування полів (1 = ігнорувати, 0 = обробляти) |
| `target_system` | `uint8_t` | 50 | ID | Системний ID цільового апарата (зазвичай 1) |
| `target_component` | `uint8_t` | 51 | ID | ID цільового компонента (1 = `MAV_COMP_ID_AUTOPILOT1`) |
| `coordinate_frame` | `uint8_t` | 52 | enum | Базова система координат (`MAV_FRAME`) |

### Бітова маска POSITION_TARGET_TYPEMASK

Поле `type_mask` повідомлень #84 та #86 використовує **інверсну семантику**: біт зі значенням `1` наказує автопілоту **ігнорувати** відповідне поле вхідного повідомлення, а біт зі значенням `0` вмикає його обробку регулятором. Така схема була закладена в архітектуру MAVLink для забезпечення зворотної сумісності: якщо зовнішня програма надсилає структуру, повністю заповнену нулями (`0x0000`), автопілот намагатиметься обробляти всі доступні поля (позицію, швидкість, прискорення та рискання).

```
Бітова розкладка type_mask (16-бітне ціле число без знаку):
  Біт 0  (0x0001) : POSITION_TARGET_TYPEMASK_X_IGNORE
  Біт 1  (0x0002) : POSITION_TARGET_TYPEMASK_Y_IGNORE
  Біт 2  (0x0004) : POSITION_TARGET_TYPEMASK_Z_IGNORE
  Біт 3  (0x0008) : POSITION_TARGET_TYPEMASK_VX_IGNORE
  Біт 4  (0x0010) : POSITION_TARGET_TYPEMASK_VY_IGNORE
  Біт 5  (0x0020) : POSITION_TARGET_TYPEMASK_VZ_IGNORE
  Біт 6  (0x0040) : POSITION_TARGET_TYPEMASK_AX_IGNORE
  Біт 7  (0x0080) : POSITION_TARGET_TYPEMASK_AY_IGNORE
  Біт 8  (0x0100) : POSITION_TARGET_TYPEMASK_AZ_IGNORE
  Біт 9  (0x0200) : POSITION_TARGET_TYPEMASK_FORCE_SET (1 = afx/afy/afz є силою в Ньютонах)
  Біт 10 (0x0400) : POSITION_TARGET_TYPEMASK_YAW_IGNORE
  Біт 11 (0x0800) : POSITION_TARGET_TYPEMASK_YAW_RATE_IGNORE
  Біти 12..15     : Зарезервовано (мусять бути встановлені в 0)
```

#### Детальний аналіз та конфігурації типових режимів

1. **Режим утримання та стеження за позицією (Position Only):**
   Використовується, коли бортовий комп'ютер задає виключно цільову просторову точку `(x, y, z)` та бажаний кут курсу `yaw`. У цьому випадку внутрішні регулятори швидкості та прискорення польотного контролера генерують власні профілі руху.
   * Значення бітової маски: `0b0000 1101 1111 1000` (`0x0DF8`, десяткове 3576).
   * Ігноруються: `vx`, `vy`, `vz`, `afx`, `afy`, `afz`, `yaw_rate`.

2. **Режим прямого керування вектором швидкості (Velocity Control):**
   Застосовується під час польоту за оптичним потоком, керування від джойстика або динамічного наведення на рухомий об'єкт за даними відеокамери. Позиція апарата не фіксується: автопілот підтримує задану швидкість руху.
   * Значення бітової маски: `0b0000 1101 1100 0111` (`0x0DC7`, десяткове 3527).
   * Ігноруються: `x`, `y`, `z`, `afx`, `afy`, `afz`, `yaw_rate`.

3. **Режим швидкості з кутовою швидкістю рискання (Velocity + Yaw Rate):**
   Оптимальний для безперервного маневрування та повороту навколо вертикальної осі без фіксації абсолютного азимуту.
   * Значення бітової маски: `0b0000 0101 1100 0111` (`0x05C7`, десяткове 1479).
   * Ігноруються: `x`, `y`, `z`, `afx`, `afy`, `afz`, `yaw`.

4. **Позиційне керування з прямим зв'язком за швидкістю (Pos + Vel Feedforward):**
   Стандартний режим для плавного руху по заздалегідь згенерованих траєкторіях. Бортовий комп'ютер передає поточну цільову точку траєкторії `(x, y, z)` та аналітичну швидкість руху вздовж кривої `(vx, vy, vz)`. Це усуває фазове запізнення інтегрального контуру позиції.
   * Значення бітової маски: `0b0000 1101 1100 0000` (`0x0DC0`, десяткове 3520).
   * Ігноруються: `afx`, `afy`, `afz`, `yaw_rate`.

5. **Повний динамічний стан (Full State: Pos + Vel + Acc + Yaw):**
   Забезпечує максимальну точність слідування за сплайновими траєкторіями вищих порядків (мінімального ривка). Автопілот отримує повний набір кінематичних змінних.
   * Значення бітової маски: `0b0000 1000 0000 0000` (`0x0800`, десяткове 2048).
   * Ігнорується: `yaw_rate`.

6. **Повний стан із кутовою швидкістю (Full State: Pos + Vel + Acc + YawRate):**
   Використовується для швидкісних зйомок та проходження трас гоночними дронами, де кут повороту камери має безперервно змінюватися з фіксованою кутовою швидкістю.
   * Значення бітової маски: `0b0000 0100 0000 0000` (`0x0400`, десяткове 1024).
   * Ігнорується: `yaw`.

7. **Керування вектором сили та прискорення (Acceleration / Thrust Vector):**
   Дозволяє зовнішньому обчислювачу безпосередньо задавати вектор сили або лінійного прискорення в просторі, оминаючи геометричні регулятори положення та швидкості.
   * Значення бітової маски: `0b0000 1100 0011 1111` (`0x0C3F`, десяткове 3135).
   * Ігноруються: `x`, `y`, `z`, `vx`, `vy`, `vz`, `yaw_rate`.

### Повідомлення SET_POSITION_TARGET_GLOBAL_INT (#86)

Застосовується для передачі глобальних географічних координат у форматі цілих чисел високої точності (градуси · 10⁷) разом із метричними швидкостями та прискореннями. На відміну від стандартних чисел з плаваючою комою одинарної точності (`float`), які на рівні екватора мають дискретність лише близько 1–2 метрів, 32-бітні цілі числа забезпечують субсантиметрову просторову роздільну здатність приблизно 1.1 см.

* **ID повідомлення:** `86`
* **Назва структури C:** `mavlink_set_position_target_global_int_t`
* **Розмір структури:** 53 байти

| Поле | Тип | Зсув | Одиниці | Опис |
| :--- | :--- | :--- | :--- | :--- |
| `time_boot_ms` | `uint32_t` | 0 | мс | Час завантаження контролера |
| `lat_int` | `int32_t` | 4 | град · 10⁷ | Географічна широта WGS84 (наприклад, `504501000` = `50.4501000°`) |
| `lon_int` | `int32_t` | 8 | град · 10⁷ | Географічна довгота WGS84 (наприклад, `305234000` = `30.5234000°`) |
| `alt` | `float` | 12 | м | Висота (абсолютна MSL або відносна над точкою старту залежно від фрейму) |
| `vx` | `float` | 16 | м/с | Швидкість на Північ (Positive North) |
| `vy` | `float` | 20 | м/с | Швидкість на Схід (Positive East) |
| `vz` | `float` | 24 | м/с | Швидкість Вниз (Positive Down) |
| `afx` | `float` | 28 | м/с² | Прискорення на Північ |
| `afy` | `float` | 32 | м/с² | Прискорення на Схід |
| `afz` | `float` | 36 | м/с² | Прискорення Вниз |
| `yaw` | `float` | 40 | рад | Цільовий азимут курсу відносно географічної півночі |
| `yaw_rate` | `float` | 44 | рад/с | Швидкість зміни азимуту |
| `type_mask` | `uint16_t` | 48 | бітова маска | 16-бітна маска ігнорування каналів (ідентична до повідомлення #84) |
| `target_system` | `uint8_t` | 50 | ID | ID апарата |
| `target_component` | `uint8_t` | 51 | ID | ID компонента (1) |
| `coordinate_frame` | `uint8_t` | 52 | enum | `MAV_FRAME_GLOBAL_INT` (5) або `MAV_FRAME_GLOBAL_RELATIVE_ALT_INT` (6) |

### Повідомлення SET_ATTITUDE_TARGET (#82)

Використовується для безпосереднього керування орієнтацією корпусу (через одиничний кватерніон або кутові швидкості) та нормованою колективною тягою. Це дає змогу зовнішньому комп'ютеру оминати позиційні регулятори автопілота для виконання високодинамічних маневрів, акробатичних перевертань або роботи з нейромережевими контролерами прямого керування.

* **ID повідомлення:** `82`
* **Назва структури C:** `mavlink_set_attitude_target_t`
* **Розмір структури:** 39 байтів

| Поле | Тип | Зсув | Одиниці | Опис |
| :--- | :--- | :--- | :--- | :--- |
| `time_boot_ms` | `uint32_t` | 0 | мс | Час завантаження контролера |
| `q` | `float[4]` | 4 | одиничний | Орієнтація у формі кватерніона `[w, x, y, z]` (впорядкування `q[0]=w`, `q[1]=x`, `q[2]=y`, `q[3]=z`) |
| `body_roll_rate` | `float` | 20 | рад/с | Кутова швидкість крену навколо поздовжньої осі X тіла |
| `body_pitch_rate` | `float` | 24 | рад/с | Кутова швидкість тангажу навколо поперечної осі Y тіла |
| `body_yaw_rate` | `float` | 28 | рад/с | Кутова швидкість рискання навколо вертикальної осі Z тіла |
| `thrust` | `float` | 32 | `[0.0 .. 1.0]` | Нормована колективна тяга (`0.0` = вимкнено, `1.0` = 100% максимальної тяги) |
| `target_system` | `uint8_t` | 36 | ID | ID апарата |
| `target_component` | `uint8_t` | 37 | ID | ID компонента |
| `type_mask` | `uint8_t` | 38 | бітова маска | 8-бітна маска ігнорування каналів орієнтації та кутових швидкостей |

#### Бітова маска ATTITUDE_TARGET_TYPEMASK (8 біт)

```
  Біт 0 (0x01) : ATTITUDE_TARGET_TYPEMASK_BODY_ROLL_RATE_IGNORE
  Біт 1 (0x02) : ATTITUDE_TARGET_TYPEMASK_BODY_PITCH_RATE_IGNORE
  Біт 2 (0x04) : ATTITUDE_TARGET_TYPEMASK_BODY_YAW_RATE_IGNORE
  Біт 6 (0x40) : ATTITUDE_TARGET_TYPEMASK_THRUST_BODY_SET (1 = тяга інтерпретується як вектор 3D)
  Біт 7 (0x80) : ATTITUDE_TARGET_TYPEMASK_ATTITUDE_IGNORE (1 = ігнорувати кватерніон q)
```

* **Керування кутовим положенням + тягою (Attitude + Thrust):**
  Встановлюється `type_mask = 0b0000 0111` (`0x07`). Автопілот стабілізує кути орієнтації за наданим кватерніоном `q`, підтримує колективну тягу `thrust`, а внутрішній регулятор швидкості обертання генерує необхідні моменти самостійно.
* **Керування кутовими швидкостями (Body Rate Control + Thrust):**
  Встановлюється `type_mask = 0b1000 0000` (`0x80`). Автопілот повністю ігнорує кватерніон `q` і відпрацьовує безпосередньо кутові швидкості `body_roll_rate`, `body_pitch_rate`, `body_yaw_rate` за допомогою високочастотного внутрішнього PID-регулятора кутових швидкостей (частота оновлення до 1 кГц).

### Перелік систем координат MAV_FRAME

Система координат задає базис, відносно якого розраховуються числові значення полів у повідомленні уставки.

| Значення | Назва константи | Базис та орієнтація осей | Застосування |
| :--- | :--- | :--- | :--- |
| `1` | `MAV_FRAME_LOCAL_NED` | X — Північ, Y — Схід, Z — Вниз. Початок координат прив'язаний до точки старту або локального орієнтира EKF. | Стандарт для локальної автономної навігації мультироторів. |
| `7` | `MAV_FRAME_LOCAL_OFFSET_NED` | Локальний базис NED зі зміщенням відносно поточної позиції апарата в момент прийому пакета. | Ступінчасті переміщення на фіксовану відстань (наприклад, «зміститися на 2 метри на північ»). |
| `8` | `MAV_FRAME_BODY_NED` | X — поздовжньо вперед за носом апарата, Y — праворуч, Z — вниз. Базис повертається разом із курсом, але залишається горизонтальним. | Політ вперед/назад відносно напрямку погляду дрона без урахування крену та тангажу. |
| `9` | `MAV_FRAME_BODY_OFFSET_NED` | Зміщення вздовж осей тіла апарата відносно його поточного положення. | Команди обходу локальних перешкод за даними передніх далекомірів або ультразвукових сенсорів. |
| `12` | `MAV_FRAME_BODY_FRD` | Тіловий базис Forward-Right-Down: жорстко зафіксований на конструкції дрона і обертається за всіма трьома осями (крен, тангаж, курс). | Керування вектором тяги та прискорення безпосередньо в системі координат планера. |
| `5` | `MAV_FRAME_GLOBAL_INT` | Широта і довгота WGS84, абсолютна висота над рівнем моря (MSL). | Глобальна маршрутна навігація та супутникове позиціонування. |
| `6` | `MAV_FRAME_GLOBAL_RELATIVE_ALT_INT` | Широта і довгота WGS84, відносна висота над точкою домашнього старту (Home Altitude). | Найпоширеніший режим для виконання місій над рівною місцевістю. |

### Валідація числових полів та фізичні інваріанти

Перед формуванням та відправкою будь-якого кадру уставки керуюча програма зобов'язана виконувати строгу перевірку вхідних даних на відповідність математичним та фізичним інваріантам:

1. **Перевірка на нечислові значення (NaN / Inf):**
   Попадання значень `NaN` (Not a Number) або `±Inf` у поля координат, швидкостей чи кутів спричиняє внутрішній збій фільтра Калмана (EKF2) або аварійне скидання регуляторів. Програма повинна відкидати невалідне значення й переходити на утримання попереднього стану.
2. **Нормалізація кватерніона орієнтації:**
   У повідомленні `SET_ATTITUDE_TARGET` кватерніон `q` обов'язково повинен бути одиничним:
   ```
   ||q|| = √(w² + x² + y² + z²) = 1.0 ± 0.001
   ```
   Якщо довжина вектора відхиляється від одиниці через похибки округлення, автопілот PX4 може згенерувати некоректну матрицю поворотів і викликати аварійний перекид апарата.
3. **Обмеження діапазону курсу (Yaw Wrapping):**
   Кут рискання `yaw` повинен бути згорнутий у канонічний інтервал `[-π, +π]` або `[0, 2π]`. Передача значень поза цими межами (наприклад, `yaw = 15.7` рад) змусить внутрішній кутовий регулятор здійснювати непотрібні повні оберти навколо осі.
4. **Обмеження значень тяги:**
   Поле `thrust` повинно бути обмежене діапазоном `[0.0, 1.0]`. Значення вище 1.0 обрізаються контролером, а від'ємні значення в стандартних конфігураціях інтерпретуються як нульова тяга (або викликають реверс моторів у спеціалізованих 3D-прошивках).

### Телеметричний зворотний зв'язок та оцінка помилки стеження

Для замкненого контролю якості виконання траєкторії бортовий комп'ютер повинен одночасно приймати зворотний потік телеметрії від польотного контролера. Основними повідомленнями для моніторингу є:

* **`LOCAL_POSITION_NED` (#32):** транслює фактичну оцінку просторового стану `(x, y, z)` та лінійних швидкостей `(vx, vy, vz)` від фільтра EKF2 на частоті 30–50 Гц.
* **`POSITION_TARGET_LOCAL_NED` (#85):** телеметричне ехо-повідомлення, яке автопілот транслює назад у мережу. Воно містить поточну уставку, яку регулятори польотного контролера безпосередньо відпрацьовують у цей мілісекундний квант часу (з урахуванням внутрішніх обмежень швидкості та прискорення).

Обчислення просторової помилки слідування за траєкторією здійснюється за формулою Евклідової відстані:
```
e_pos = √((x_ref - x_actual)² + (y_ref - y_actual)² + (z_ref - z_actual)²)
```
Якщо помилка `e_pos` перевищує допустимий динамічний коридор (наприклад, понад 1.5 метра під час сильного пориву вітру), планувальник на комп'ютері-компаньйоні повинен тимчасово призупинити прогрес траєкторії за часом, щоб дрон міг стабілізуватися в поточній зоні.

---

### Синхронізація часу між комп'ютером і польотним контролером

Для точного узгодження часових міток `time_boot_ms` у високодинамічних польотах використовується протокол синхронізації часу MAVLink на базі повідомлення `TIMESYNC` (#111).

Бортовий комп'ютер періодично (наприклад, із частотою 1 Гц) надсилає повідомлення `TIMESYNC` із нульовим полем `tc1` та власним системним часом у наносекундах у полі `ts1`. Польотний контролер заповнює поле `tc1` власним внутрішнім таймером і повертає пакет назад.

На основі часу відправки `t1`, часу прийому контролером `t2` та часу повернення `t3` бортовий комп'ютер розраховує:

```
Час проходження сигналу в обидва боки (RTT):
RTT = (t3 - t1) - час обробки на контролері

Зсув годинника (Clock Offset):
Offset = t2 - (t1 + RTT / 2)
```

Згладжене значення `Offset` дає змогу комп'ютеру-компаньйону точно транслювати системні часові мітки Linux у мілісекунди `time_boot_ms` польотного контролера, компенсуючи затримки транспортування даних по шині UART.

---

### Специфікація обрізання нульових байтів у MAVLink v2

У протоколі MAVLink v2 впроваджено оптимізацію пропускної здатності каналу — **обрізання кінцевих нульових байтів** (*zero-byte truncation*). Якщо останні байти структури корисного навантаження дорівнюють нулю, серіалізатор відсікає їх і зменшує поле довжини `len` у заголовку кадру.

Для повідомлення `SET_POSITION_TARGET_LOCAL_NED` (номінальний розмір 53 байти) останніми полями є:
* `target_system` (зсув 50, 1 байт)
* `target_component` (зсув 51, 1 байт)
* `coordinate_frame` (зсув 52, 1 байт)

Якщо `coordinate_frame` дорівнює нулю або останні поля не заповнені, кадр MAVLink v2 може мати довжину лише 50–52 байти в каналі зв'язку. Приймач автопілота автоматично доповнює відсутні кінцеві байти нулями перед передачею в обробник uORB. Розробники низькорівневих парсерів повинні враховувати це правило і не вважати пакет битим, якщо його довжина менша за `sizeof(mavlink_set_position_target_local_ned_t)`.

### Підпис пакетів та безпека (MAVLink v2 Packet Signing)

У критичних безпілотних комплексах потік уставок може бути захищений криптографічним підписом MAVLink v2 (прапорець `MAVLINK_IFLAG_SIGNED = 0x01` у байті несумісності `incompat_flags`).

Підпис додає до кінця кадру 13-байтний хвіст (*Signature Trailer*):
* 1 байт: `link_id` (ідентифікатор логічного каналу)
* 6 байтів: `timestamp` (монотонний лічильник часу в мікросекундах для захисту від атак повторного відтворення — *replay attacks*)
* 6 байтів: перші 48 біт геш-коду SHA-256 від усього кадру та секретного симетричного ключа

Під час трансляції потоку уставок із частотою 50 Гц криптографічний підпис вимагає додаткових обчислювальних ресурсів мікроконтролера STM32 (обчислення SHA-256 50 разів на секунду) та збільшує розмір кожного кадру на 13 байтів (650 байт/с додаткового навантаження на порт UART). Тому на ізольованих прямих лініях між бортовим комп'ютером і польотним контролером підпис часто вимикають, залишаючи його обов'язковим лише для зовнішніх радіоканалів телеметрії.

### Налаштування низькорівневого порту UART у Linux (termios)

Для стабільної трансляції потоку уставок на швидкостях 921600 бод без накопичення затримок у буферах ядра Linux дескриптор послідовного порту повинен бути налаштований у неблокуючому «сирому» режимі (*raw mode*) через інтерфейс `termios`:

```
c_cflag: CS8 | CREAD | CLOCAL
c_iflag: 0 (вимкнено програмний контроль потоку XON/XOFF)
c_oflag: 0 (вимкнено пост-обробку виводу)
c_lflag: 0 (вимкнено канонічний режим та ехо)
c_cc[VMIN]  = 0  (не чекати заповнення буфера)
c_cc[VTIME] = 0  (нульовий таймаут очікування)
```

Це гарантує, що кожен сформований кадр MAVLink миттєво відправляється в апаратний буфер FIFO контролера UART, а затримка передачі не перевищує 50–100 мікросекунд.

### Команди активації режимів польоту

Перехід у режим зовнішнього керування виконується через повідомлення `COMMAND_LONG` з командою `MAV_CMD_DO_SET_MODE` (#176).

```
MAV_CMD_DO_SET_MODE (#176)
  param1 : Базовий режим (MAV_MODE_FLAG) -> MAV_MODE_FLAG_CUSTOM_MODE_ENABLED (1)
  param2 : Головний кастомний режим автопілота (Main Mode)
  param3 : Додатковий кастомний підрежим (Sub Mode)
```

#### Специфіка PX4 Autopilot

У PX4 режим Offboard кодується встановленням `param2 = PX4_CUSTOM_MAIN_MODE_OFFBOARD` (числове значення `6`), а `param3 = 0`. Автопілот вимагає попереднього потоку уставок зі швидкістю щонайменше 2 Гц протягом як мінімум 500 мс перед відправкою команди `MAV_CMD_DO_SET_MODE`. Якщо потік відсутній або частота нижча за 2 Гц, команда відхиляється з кодом `MAV_RESULT_DENIED`.

#### Специфіка ArduPilot (ArduCopter)

В ArduPilot режим зовнішніх уставок називається `GUIDED`. Його активація здійснюється встановленням `param2 = COPTER_MODE_GUIDED` (числове значення `4`). Альтернативний метод — надсилання спеціалізованої команди `MAV_CMD_NAV_GUIDED_ENABLE` (#92) з `param1 = 1`. Якщо потік уставок переривається в режимі Guided, ArduPilot не скидає режим автоматично, а зависає в поточній точці, очікуючи нових команд або втручання пілота.

#include <stdint.h>
#include <stdbool.h>
#include <string.h>
#include <math.h>

// Перевірка числових параметрів уставки на коректність
bool validate_setpoint(float x, float y, float z, float vx, float vy, float vz, float yaw) {
    if (isnan(x) || isnan(y) || isnan(z) || isnan(vx) || isnan(vy) || isnan(vz) || isnan(yaw)) {
        return false;
    }
    if (isinf(x) || isinf(y) || isinf(z) || isinf(vx) || isinf(vy) || isinf(vz) || isinf(yaw)) {
        return false;
    }
    // Ліміт швидкості для безпеки (наприклад, не більше 15 м/с)
    float speed_sq = vx * vx + vy * vy + vz * vz;
    if (speed_sq > 225.0f) {
        return false;
    }
    return true;
}

// Формування кадру SET_POSITION_TARGET_LOCAL_NED з прямим зв'язком швидкості
int send_offboard_position_target(int serial_fd, uint8_t sys_id, uint8_t comp_id,
                                  float x, float y, float z,
                                  float vx, float vy, float vz,
                                  float yaw_rad) {
    if (!validate_setpoint(x, y, z, vx, vy, vz, yaw_rad)) {
        return -1;
    }

    mavlink_set_position_target_local_ned_t setpoint;
    memset(&setpoint, 0, sizeof(setpoint));

    // 0 = автопілот використовує власний поточний час прийому пакета
    setpoint.time_boot_ms = 0;
    setpoint.target_system = 1;
    setpoint.target_component = MAV_COMP_ID_AUTOPILOT1;
    setpoint.coordinate_frame = MAV_FRAME_LOCAL_NED;

    // Маска: Pos + Vel + Yaw активні, прискорення та yaw_rate ігноруються (0x0DC0)
    setpoint.type_mask = POSITION_TARGET_TYPEMASK_AX_IGNORE |
                         POSITION_TARGET_TYPEMASK_AY_IGNORE |
                         POSITION_TARGET_TYPEMASK_AZ_IGNORE |
                         POSITION_TARGET_TYPEMASK_YAW_RATE_IGNORE;

    // У системі NED вісь Z спрямована вниз, тому висота +5м задається як z = -5.0f
    setpoint.x = x;
    setpoint.y = y;
    setpoint.z = z;
    setpoint.vx = vx;
    setpoint.vy = vy;
    setpoint.vz = vz;
    setpoint.yaw = yaw_rad;

    mavlink_message_t msg;
    mavlink_msg_set_position_target_local_ned_encode(sys_id, comp_id, &msg, &setpoint);

    uint8_t buffer[MAVLINK_MAX_PACKET_LEN];
    uint16_t len = mavlink_msg_to_send_buffer(buffer, &msg);

    ssize_t written = write(serial_fd, buffer, len);
    return (written == (ssize_t)len) ? 0 : -1;
}

// Розрахунок Евклідової помилки слідування за позицією
float compute_tracking_error(float target_x, float target_y, float target_z,
                             const mavlink_local_position_ned_t *actual_pos) {
    float dx = target_x - actual_pos->x;
    float dy = target_y - actual_pos->y;
    float dz = target_z - actual_pos->z;
    return sqrtf(dx * dx + dy * dy + dz * dz);
}

#include <cstdint>
#include <cmath>
#include <array>
#include <span>
#include <optional>
#include <mavlink.h>

namespace drone_control {

enum class Frame : uint8_t {
    LocalNed       = MAV_FRAME_LOCAL_NED,
    LocalOffsetNed = MAV_FRAME_LOCAL_OFFSET_NED,
    BodyNed        = MAV_FRAME_BODY_NED,
    BodyOffsetNed  = MAV_FRAME_BODY_OFFSET_NED,
    BodyFrd        = MAV_FRAME_BODY_FRD
};

struct SetpointCommand {
    float x{0.0f}, y{0.0f}, z{0.0f};
    float vx{0.0f}, vy{0.0f}, vz{0.0f};
    float afx{0.0f}, afy{0.0f}, afz{0.0f};
    float yaw{0.0f};
    float yaw_rate{0.0f};
    uint16_t type_mask{0x0DC0}; // За замовчуванням Pos + Vel + Yaw активні
    Frame frame{Frame::LocalNed};

    [[nodiscard]] bool is_valid() const noexcept {
        if (std::isnan(x) || std::isnan(y) || std::isnan(z) ||
            std::isnan(vx) || std::isnan(vy) || std::isnan(vz) ||
            std::isnan(yaw)) {
            return false;
        }
        if (std::isinf(x) || std::isinf(y) || std::isinf(z) ||
            std::isinf(vx) || std::isinf(vy) || std::isinf(vz) ||
            std::isinf(yaw)) {
            return false;
        }
        const float speed_sq = vx * vx + vy * vy + vz * vz;
        return speed_sq <= 400.0f; // Максимум 20 м/с
    }
};

class SetpointEncoder {
public:
    explicit SetpointEncoder(uint8_t source_sys = 255, uint8_t source_comp = MAV_COMP_ID_ONBOARD_COMPUTER) noexcept
        : sys_id_{source_sys}, comp_id_{source_comp} {}

    // Серіалізує уставку в наданий буфер span; повертає зріз записаних байтів
    [[nodiscard]] std::span<const uint8_t> encode(
        const SetpointCommand& cmd,
        std::span<uint8_t> output_buffer,
        uint8_t target_sys = 1,
        uint8_t target_comp = MAV_COMP_ID_AUTOPILOT1) const noexcept
    {
        if (!cmd.is_valid() || output_buffer.size() < MAVLINK_MAX_PACKET_LEN) {
            return {};
        }

        mavlink_set_position_target_local_ned_t raw{};
        raw.time_boot_ms = 0;
        raw.target_system = target_sys;
        raw.target_component = target_comp;
        raw.coordinate_frame = static_cast<uint8_t>(cmd.frame);
        raw.type_mask = cmd.type_mask;

        raw.x = cmd.x;
        raw.y = cmd.y;
        raw.z = cmd.z;
        raw.vx = cmd.vx;
        raw.vy = cmd.vy;
        raw.vz = cmd.vz;
        raw.afx = cmd.afx;
        raw.afy = cmd.afy;
        raw.afz = cmd.afz;
        raw.yaw = cmd.yaw;
        raw.yaw_rate = cmd.yaw_rate;

        mavlink_message_t msg{};
        mavlink_msg_set_position_target_local_ned_encode(sys_id_, comp_id_, &msg, &raw);

        const uint16_t written = mavlink_msg_to_send_buffer(output_buffer.data(), &msg);
        return output_buffer.subspan(0, written);
    }

    // Оцінка Евклідової помилки між цільовою уставкою та фактичною телеметрією
    [[nodiscard]] static float compute_error(
        const SetpointCommand& target,
        const mavlink_local_position_ned_t& telemetry) noexcept
    {
        const float dx = target.x - telemetry.x;
        const float dy = target.y - telemetry.y;
        const float dz = target.z - telemetry.z;
        return std::sqrt(dx * dx + dy * dy + dz * dz);
    }

private:
    uint8_t sys_id_{255};
    uint8_t comp_id_{MAV_COMP_ID_ONBOARD_COMPUTER};
};

} // namespace drone_control
