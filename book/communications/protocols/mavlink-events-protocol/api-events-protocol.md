# 📋 Специфікація протоколу подій MAVLink та форматів libevents

Двійковий протокол подій MAVLink (**Events Protocol**) забезпечує структуровану, компактну та гарантовану доставку діагностичних повідомлень, системних попереджень, аварійних сповіщень та статусів між бортовим автопілотом (PX4, ArduPilot) та наземними станціями керування (QGroundControl, MAVSDK). Ця специфікація містить повний технічний опис двійкових кадрів MAVLink v2, структури 32-бітного ідентифікатора події `event_id`, правил бітового кодування рівнів серйозності, форматів типізованих двійкових аргументів, а також повну схему JSON-метаданих компонента.

---

### Двійкові повідомлення MAVLink протоколу подій

Протокол подій базується на трьох спеціалізованих повідомленнях MAVLink v2: трансляції події `EVENT` (#410), періодичного стану послідовності `CURRENT_EVENT_SEQUENCE` (#411) та запиту відновлення втрачених подій `REQUEST_EVENT` (#412 / `MAV_CMD_REQUEST_MESSAGE`).

#### 1. EVENT (ID 410) — Трансляція події

Повідомлення `EVENT` генерується бортовим вузлом (польотним контролером, супутнім комп'ютером, підвісом камери) при виникненні будь-якої значущої системної події. Кадр містить числовий ідентифікатор події, часову мітку, порядковий номер у черзі, бітове поле рівнів серйозності та сирий буфер двійкових аргументів.

| Зсув (байти) | Поле | Тип | Опис та правила заповнення |
| :--- | :--- | :--- | :--- |
| `0..3` | `id` | `uint32_t` | 32-бітний унікальний ідентифікатор події (`event_id`), обчислений як хеш простору імен та назви події. |
| `4..7` | `event_time_boot_ms` | `uint32_t` | Час виникнення події в мілісекундах від моменту старту процесора польотного контролера (Boot Time). |
| `8..9` | `sequence` | `uint16_t` | Монотонно зростаючий порядковий номер події для цього компонента (`0..65535`). |
| `10` | `destination_component` | `uint8_t` | Ідентифікатор цільового компонента (`0` — широкомовне повідомлення для всіх станцій і вузлів мережі). |
| `11` | `destination_system` | `uint8_t` | Ідентифікатор цільової системи (`0` — широкомовне повідомлення для всіх безпілотних апаратів). |
| `12` | `log_levels` | `uint8_t` | Бітове поле рівнів серйозності: старші 4 біти — внутрішній лог, молодші 4 біти — зовнішній лог. |
| `13..52` | `arguments` | `uint8_t[40]` | Буфер серіалізованих двійкових аргументів події (формат little-endian, без вирівнювання). |

Загальний максимальний розмір корисного навантаження повідомлення `EVENT` становить 53 байти. Завдяки механізму обрізання нульових байтів у хвості кадру MAVLink v2 (Zero-Byte Truncation), якщо подія не містить аргументів або містить лише короткий 1-байтовий аргумент, невикористані нульові байти масиву `arguments` не передаються в радіоефір, що скорочує розмір корисних даних до 14 байтів.

**Оголошення структур повідомлення у C та C++:**

:::tabs
```c
#include <stdint.h>

// Оголошення структури кадру EVENT (MAVLink v2 ID 410)
#pragma pack(push, 1)
typedef struct {
    uint32_t id;                    // 32-бітний ідентифікатор події
    uint32_t event_time_boot_ms;    // Часова мітка від старту (мс)
    uint16_t sequence;              // Порядковий номер у черзі
    uint8_t  destination_component; // Цільовий вузол (0 = broadcast)
    uint8_t  destination_system;    // Цільова система (0 = broadcast)
    uint8_t  log_levels;            // Бітова маска рівнів важливості
    uint8_t  arguments[40];         // Двійковий буфер аргументів
} mavlink_event_t;
#pragma pack(pop)
```
```cpp
#include <cstdint>
#include <array>

// Ідіоматична типізована структура кадру EVENT
struct alignas(1) MavlinkEventMessage {
    uint32_t              id{0};
    uint32_t              eventTimeBootMs{0};
    uint16_t              sequence{0};
    uint8_t               destinationComponent{0};
    uint8_t               destinationSystem{0};
    uint8_t               logLevels{0};
    std::array<uint8_t, 40> arguments{};
};
```

#### 2. CURRENT_EVENT_SEQUENCE (ID 411) — Періодичний стан послідовності

Повідомлення `CURRENT_EVENT_SEQUENCE` транслюється автопілотом періодично (зазвичай із базовою частотою 1 Гц) або негайно після відправлення чергової пачки нових подій. Воно слугує системним пульсом підсистеми сповіщень і дозволяє наземній станції оперативно виявити пропуск подій навіть у разі повної втрати відповідних кадрів `EVENT`.

| Зсув (байти) | Поле | Тип | Опис та призначення |
| :--- | :--- | :--- | :--- |
| `0..1` | `sequence` | `uint16_t` | Останній виданий порядковий номер події цим компонентом на момент надсилання кадру. |
| `2` | `flags` | `uint8_t` | Бітова маска службових прапорців стану черги подій (`MAV_EVENT_CURRENT_SEQUENCE_FLAGS`). |

**Бітові прапорці поля `flags`:**
* `0x01` (`MAV_EVENT_CURRENT_SEQUENCE_FLAGS_RESET`): Порядковий номер подій було скинуто (відбулося перезавантаження процесора польотного контролера або переініціалізація підсистеми журналювання). Станція зобов'язана очистити чергу очікування ARQ.
* `0x02` (`MAV_EVENT_CURRENT_SEQUENCE_FLAGS_OVERFLOW`): Кільцевий буфер подій автопілота в RAM переповнився через тривалий розрив радіозв'язку; найстаріші події було перетерто новими без можливості відновлення.

:::tabs
```c
#include <stdint.h>

#pragma pack(push, 1)
typedef struct {
    uint16_t sequence; // Останній виданий номер події
    uint8_t  flags;    // Прапорці стану черги (RESET, OVERFLOW)
} mavlink_current_event_sequence_t;
#pragma pack(pop)
```
```cpp
#include <cstdint>

struct alignas(1) MavlinkCurrentEventSequenceMessage {
    uint16_t sequence{0};
    uint8_t  flags{0};
};
```

#### 3. REQUEST_EVENT (ID 412 / MAV_CMD_REQUEST_MESSAGE) — Запит відновлення

Коли наземна станція фіксує розрив у послідовності отриманих номерів `sequence`, вона надсилає запит на вибіркову повторну передачу відсутніх кадрів. Запит формується як команда `MAV_CMD_REQUEST_MESSAGE` (номер команди 512) або спеціалізоване повідомлення `REQUEST_EVENT`:

| Поле структури | Тип | Значення | Опис |
| :--- | :--- | :--- | :--- |
| `param1` (`message_id`) | `float` | `410.0f` | Ідентифікатор запитуваного повідомлення MAVLink (`MAVLINK_MSG_ID_EVENT`). |
| `param2` (`first_sequence`) | `float` | `uint16_t` | Порядковий номер першої втраченої події в діапазоні прогалини. |
| `param3` (`count`) | `float` | `uint8_t` | Кількість послідовних подій для повторного відправлення (від 1 до 32). |
| `target_system` | `uint8_t` | `1` | Ідентифікатор цільового апарата (`sysid`). |
| `target_component` | `uint8_t` | `1` | Ідентифікатор цільового вузла (`compid`, наприклад `MAV_COMP_ID_AUTOPILOT1`). |

### Ідентифікатори компонентів MAVLink у системі подій

Кожен апаратний модуль у безпілотному комплексі має власний унікальний `Component ID`, що дозволяє спрямовувати сповіщення від конкретних підсистем без перетину просторів імен:

| Ідентифікатор компонента | Числовий код | Опис та призначення підсистеми |
| :--- | :--- | :--- |
| `MAV_COMP_ID_AUTOPILOT1` | 1 | Головний польотний контролер (PX4 / ArduPilot). Генерує події навігації, EKF, режимів польоту та датчиків. |
| `MAV_COMP_ID_USER1` | 25 | Супутній бортовий комп'ютер (Companion Computer на базі NVIDIA Jetson чи Raspberry Pi). |
| `MAV_COMP_ID_TELEMETRY_RADIO` | 68 | Бортовий телеметрійний радіомодем. Генерує події рівня сигналу RSSI та переповнення буфера. |
| `MAV_COMP_ID_CAMERA` | 100 | Головна цифрова оптична або тепловізійна камера. Сповіщення про запис відео та помилки SD-карти. |
| `MAV_COMP_ID_GIMBAL` | 154 | Стабілізований 3-осьовий підвіс корисного навантаження. Події калібрування моторів та досягнення лімітів кутів. |

### Структура 32-бітного ідентифікатора `event_id`

Кожна подія ідентифікується 32-бітним числом `uint32_t event_id`. Воно генерується автоматично під час збирання прошивки шляхом обчислення 32-бітного поліноміального хешу CRC32 від канонічного рядка формату `<namespace>:<event_name>`:

```
Приклад генерації ідентифікатора:
Простір імен (Namespace): "sensors"
Символьна назва події:    "compass_cal_failed"
Вхідний рядок хешування:  "sensors:compass_cal_failed"
Хеш-функція:              CRC32 (поліном 0xEDB88320)
Результат event_id:       0x8A12B4C0 (десяткове 2 316 482 752)
```

#### Стандартні простори імен (Namespaces)
* `default` — загальносистемні повідомлення автопілота (армування, перемикання режимів, стан батареї).
* `sensors` — діагностика, помилки калібрування та збої інерційних датчиків, магнітометрів, барометрів і GNSS.
* `failsafe` — аварійні стани системи захисту (втрата радіозв'язку RC, геозона, критичний розряд).
* `commander` — високорівневий автомат станів навігації та виконання автономних місій.
* `payload` — підвіси корисного навантаження, цифрові оптичні та тепловізійні камери, сервоприводи скиду.

### Бітове кодування поля `log_levels` та рівні серйозності

Поле `log_levels` займає рівно 1 байт (8 бітів) і об'єднує два незалежні 4-бітні рівні важливості:

```
Бітове розміщення поля log_levels (1 байт):
┌───────────┬───────────┬───────────┬───────────┬───────────┬───────────┬───────────┬───────────┐
│   Біт 7   │   Біт 6   │   Біт 5   │   Біт 4   │   Біт 3   │   Біт 2   │   Біт 1   │   Біт 0   │
├───────────┴───────────┴───────────┴───────────┼───────────┴───────────┴───────────┴───────────┤
│         Внутрішній рівень логування           │          Зовнішній рівень серйозності         │
│          (Internal Log Level, 0..7)           │           (External Severity, 0..7)           │
└───────────────────────────────────────────────┴───────────────────────────────────────────────┘
```

**Операції пакування та вилучення рівнів серйозності:**

:::tabs
```c
#include <stdint.h>

// Пакування внутрішнього та зовнішнього рівнів у 1 байт log_levels
uint8_t pack_log_levels(uint8_t internal_level, uint8_t external_severity) {
    return (uint8_t)(((internal_level & 0x0F) << 4) | (external_severity & 0x0F));
}

// Вилучення внутрішнього рівня (для запису на SD-карту)
uint8_t get_internal_log_level(uint8_t log_levels) {
    return (uint8_t)((log_levels >> 4) & 0x0F);
}

// Вилучення зовнішнього рівня серйозності (для відображення на GCS)
uint8_t get_external_severity(uint8_t log_levels) {
    return (uint8_t)(log_levels & 0x0F);
}
```
```cpp
#include <cstdint>

// Типобезпечні обгортки для роботи з log_levels (C++20)
constexpr uint8_t packLogLevels(uint8_t internalLevel, uint8_t externalSeverity) noexcept {
    return static_cast<uint8_t>(((internalLevel & 0x0F) << 4) | (externalSeverity & 0x0F));
}

constexpr uint8_t getInternalLogLevel(uint8_t logLevels) noexcept {
    return static_cast<uint8_t>((logLevels >> 4) & 0x0F);
}

constexpr uint8_t getExternalSeverity(uint8_t logLevels) noexcept {
    return static_cast<uint8_t>(logLevels & 0x0F);
}
```
:::

#### Рівні серйозності `MAV_SEVERITY` (Syslog RFC 5424)

| Код | Назва переліку | Опис та типове системне застосування |
| :--- | :--- | :--- |
| `0` | `MAV_SEVERITY_EMERGENCY` | Система повністю непридатна до польоту. Відстріл рятувального парашута, повне знеструмлення. |
| `1` | `MAV_SEVERITY_ALERT` | Вимагає негайних дій оператора. Критичний розряд батареї, термінова аварійна посадка. |
| `2` | `MAV_SEVERITY_CRITICAL` | Критична відмова сенсора чи каналу зв'язку. Втрата первинного GPS, перехід на резервний одометр. |
| `3` | `MAV_SEVERITY_ERROR` | Помилка функціонування. Збій перевірки перед стартом (Pre-Arm check), відхилення неприпустимої команди. |
| `4` | `MAV_SEVERITY_WARNING` | Попередження. Наближення до межі геозони, висока вітрова завада, підвищена температура процесора. |
| `5` | `MAV_SEVERITY_NOTICE` | Нормальна, але значуща подія. Зміна польотного режиму (Hold -> Mission), початок виконання місії. |
| `6` | `MAV_SEVERITY_INFO` | Інформаційне повідомлення. Успішне армування, досягнення проміжної точки навігації, калібрування OK. |
| `7` | `MAV_SEVERITY_DEBUG` | Налагоджувальні дані. Технічні переходи внутрішніх автоматів станів, діагностика шин I2C/SPI. |

### Формат та типізація двійкових аргументів (`arguments[40]`)

Масив `arguments` містить сирі значення аргументів події, розташовані послідовно у порядку, визначеному JSON-схемою. Усі багатобайтові типи даних кодуються у форматі little-endian без проміжних байтів вирівнювання пам'яті (Packed struct).

#### Специфікація підтримуваних типів даних libevents

| Тип у схемі | Розмір (B) | Діапазон значень / Опис | Типове застосування |
| :--- | :--- | :--- | :--- |
| `uint8_t` | 1 | `0 .. 255` | Номери екземплярів сенсорів, бітові маски прапорців. |
| `int8_t` | 1 | `-128 .. 127` | Температурні поправки, відносні кроки потужності. |
| `uint16_t` | 2 | `0 .. 65 535` | Напруга в мілівольтах, частота обертання двигунів (RPM). |
| `int16_t` | 2 | `-32 768 .. 32 767` | Кутові відхилення у сотих частках градуса (`0.01°`). |
| `uint32_t` | 4 | `0 .. 4 294 967 295` | Системні часові інтервали в мікросекундах, бітові маски. |
| `int32_t` | 4 | `-2.14·10⁹ .. 2.14·10⁹` | Координати WGS84 (широта / довгота) у форматі `1e-7` градуса. |
| `uint64_t` | 8 | `0 .. 1.84·10¹⁹` | 64-бітні апаратні UUID мікросхем, мікросекундні мітки часу. |
| `int64_t` | 8 | `-9.22·10¹⁸ .. 9.22·10¹⁸` | Абсолютні мітки глобального часу UNIX епохи. |
| `float` | 4 | IEEE 754 одинарна точність | Лінійна швидкість (м/с), тиск (Па), струм (А), температура (°C). |

#### Стандартні фізичні одиниці вимірювання (`unit`)
* Довжина та відстань: `m` (метри), `cm` (сантиметри), `mm` (міліметри).
* Швидкість та прискорення: `m/s` (метри за секунду), `m/s^2` (метри на секунду в квадраті).
* Кутові величини: `deg` (градуси), `deg/s` (градуси за секунду), `rad` (радіани), `rad/s` (радіани за секунду).
* Електричні величини: `V` (вольти), `mV` (мілівольти), `A` (ампери), `mAh` (міліампер-години).
* Температура та тиск: `degC` (градуси Цельсія), `Pa` (паскалі), `hPa` (гектопаскалі).
* Час: `s` (секунди), `ms` (мілісекунди), `us` (мікросекунди).
* Відносні величини: `%` (відсотки), `ratio` (безрозмірна частка `0.0..1.0`).

### Схема метаданих JSON (Component Information Protocol)

Метадані поширюються у вигляді стисненого архіву `events.json.xz`, що розміщується у Flash/microSD автопілота чи на хмарному сервері оновлень. Структура файлу підпорядковується стандартизованій схемі libevents:

```json
{
  "version": 1,
  "scope": "px4",
  "components": {
    "1": {
      "namespace": "default",
      "event_groups": {
        "sensors": {
          "events": {
            "2316482752": {
              "name": "compass_cal_failed",
              "type": "calibration",
              "message": "Збій калібрування компаса №{1} (відхилення: {2:.1f}°)",
              "description": "Перевірка консистентності магнітного поля завершилася помилкою. Виміряний вектор відхиляється від очікуваної геомагнітної моделі WMM для поточних координат.",
              "action": "Переконайтеся, що апарат знаходиться на відстані не менше 15 метрів від автомобілів, залізобетону та силових ліній електропередач. Повторіть калібрування.",
              "arguments": [
                {
                  "name": "sensor_id",
                  "type": "uint8_t",
                  "description": "Номер екземпляра несправного компаса"
                },
                {
                  "name": "deviation_deg",
                  "type": "float",
                  "unit": "deg",
                  "decimal_places": 1,
                  "description": "Виміряний кут магнітного відхилення"
                }
              ]
            }
          }
        },
        "failsafe": {
          "events": {
            "1327145217": {
              "name": "battery_critical_landing",
```

### Процедура завантаження та перевірки метаданих

Наземна станція керування виконує ініціалізацію та синхронізацію метаданих за протоколом **Component Information Protocol**:

1. **Запит дескриптора метаданих:** Станція надсилає повідомлення `COMP_METADATA_REQUEST` (команда #397) до компонента автопілота.
2. **Отримання дескриптора `COMPONENT_INFORMATION_BASIC` (#396):** Автопілот повертає кадр, що містить:
   * URI розміщення файлу (наприклад, `mftp://events.json.xz` або посилання на HTTPS веб-сервер релізу прошивки).
   * 32-бітний хеш CRC32 вмісту файлу метаданих.
3. **Звірка з локальним сховищем:** Станція порівнює отриманий CRC32 із контрольними сумами вже збережених локальних файлів:
   * **CRC32 збігається:** файл метаданих миттєво підтягується з локального диска комп'ютера оператора за 5–10 мілісекунд, радіообмін не виконується.
   * **CRC32 не збігається або файл відсутній:** станція запускає фонове завантаження архіву `events.json.xz` через протокол MAVLink FTP або через підключення до мережі Інтернет.
4. **Розпакування та побудова індексу:** Після завантаження станція розпаковує потік XZ, парсить JSON-структуру та створює в оперативній пам'яті швидкісну хеш-таблицю, індексовану за числовим ключем `event_id`. Це гарантує пошук шаблону та підстановку аргументів під час прийому подій у польоті за константний час `O(1)`.
