# 📋 Специфікація полів кадру LIN та розрахунок PID і Checksum

Ця довідкова специфікація містить повний аналіз бітових структур кадру LIN, математичні виведення та матриці розрахунку паритету PID, алгоритми обчислення контрольних сум (Classic та Enhanced), карту ідентифікаторів `0x00 .. 0x3F`, а також специфікацію часових параметрів і електричних рівнів згідно зі стандартами LIN 2.2A та ISO 17987 (частини 2, 3 та 4).

---

## 1. Побайтовий аналіз та таймінги полів кадру

Кадр протоколу LIN являє собою послідовну транзакцію, яка ініціюється Master-вузлом і завершується відповіддю (Response) адресованого вузла. Усі байти передаються в асинхронному форматі UART: 1 стартовий біт (домінантний `LOW`), 8 бітів даних (передаються молодшим бітом uперед — LSB first), відсутність біта паритету у структурі UART та 1 стоповий біт (рецесивний `HIGH`).

### Деталізація полів кадру

1. **Break Field (Поле перерви):**
   - **Призначення:** Початок нового кадру LIN, скидання скінченних автоматів усіх Slave-вузлів.
   - **Тривалість:** Щонайменше 13 домінантних бітових інтервалів (`13 × T_bit`) для Master-передавача; приймачі виявляють Break за тривалістю не менше 11 бітових інтервалів `LOW`.
   - **Механізм фіксації:** Стандартний периферійний модуль UART приймача фіксує відсутність стопового біта у призначений момент і генерує апаратний прапорець помилки кадрування (Framing Error, `FE`).

2. **Break Delimiter (Розділювач перерви):**
   - **Призначення:** Відновлення рецесивного шинного рівня перед стартовим бітом поля Sync.
   - **Тривалість:** Щонайменше 1 рецесивний бітовий інтервал (`1 × T_bit`), максимальна тривалість обмежена специфікацією тайм-ауту заголовка.

3. **Sync Byte (Байт синхронізації):**
   - **Значення:** Завжди фіксоване двійкове значення `0x55` (`01010101b`).
   - **Призначення:** Надання 5 спадних фронтів для вимірювання тривалості біта `T_bit` та автокалібрування внутрішніх RC-генераторів Slave-вузлів.

4. **Protected Identifier (PID, Захищений ідентифікатор):**
   - **Структура:** 6 бітів ідентифікатора (`ID0 .. ID5`) та 2 біти паритету (`P0`, `P1`).
   - **Призначення:** Визначення змісту кадру, адресація джерела відповідей та завдання довжини корисного навантаження.

5. **Response Space (Інтервал відповіді):**
   - **Призначення:** Часовий зазор між закінченням стопового біта PID та стартовим бітом першого байта даних. Дозволяє мікроконтролеру переключити напрямок лінії (якщо Master запитує дані від Slave) або обробити переривання.

6. **Data Bytes (Байти даних):**
   - **Обсяг:** Від 1 до 8 байтів даних.
   - **Порядок передачі:** Байт `Data 0` передається першим, байт `Data N-1` — останнім.

7. **Checksum (Контрольна сума):**
   - **Обсяг:** 1 байт.
   - **Призначення:** Верифікація цілісності кадру прийому (Classic Checksum для LIN 1.x / діагностики, Enhanced Checksum для LIN 2.x / ISO 17987).

## 2. Математика та матриця розрахунку Protected Identifier (PID)

Захищений ідентифікатор складається з 8 бітів. Молодші 6 бітів передають числовий ідентифікатор `ID` у діапазоні від `0` до `63` (`0x00 .. 0x3F`). Два старших біти `P0` та `P1` доповнюють ідентифікатор контрольною інформацією для виявлення помилок прийому.

### Структура байта PID

```
Розряд байта:  Bit 7   Bit 6   Bit 5   Bit 4   Bit 3   Bit 2   Bit 1   Bit 0
Значення:        P1      P0     ID5     ID4     ID3     ID2     ID1     ID0
```

### Формули обчислення паритету

Паритетні біти обчислюються за допомогою комбінаторних операцій XOR (сумування за модулем 2) та NOT (побітове заперечення):

- **Формула парного паритету P0:**
  `P0 = ID0 ⊕ ID1 ⊕ ID2 ⊕ ID4`

- **Формула непарного паритету P1:**
  `P1 = ¬(ID1 ⊕ ID3 ⊕ ID4 ⊕ ID5)`

### Матрична форма рівнянь паритету

Математично обчислення вектор-стовпчика паритету `[P0, P1]^T` над вектором ідентифікатора `[ID0, ID1, ID2, ID3, ID4, ID5]^T` можна записати через двовимірну порождаючу матрицю над полем Галуа `GF(2)`:

```
P0 = 1·ID0 ⊕ 1·ID1 ⊕ 1·ID2 ⊕ 0·ID3 ⊕ 1·ID4 ⊕ 0·ID5
P1 = 1 ⊕ (0·ID0 ⊕ 1·ID1 ⊕ 0·ID2 ⊕ 1·ID3 ⊕ 1·ID4 ⊕ 1·ID5)
```

Властивості коду паритету PID:
1. Забезпечує **гарантоване виявлення будь-якої 1-бітової помилки** у полі ідентифікатора.
2. Забезпечує **гарантоване виявлення будь-яких 2-бітових помилок** (подвійних спотворень).
3. Якщо приймач виявляє помилку паритету PID, кадр негайно відкидається без надсилання відповіді, що запобігає асинхронним накладанням сигналів на шині.

## 3. Математика та алгоритми контрольної суми (Checksum)

Стандарт LIN використовує специфічний 8-бітний суматор із циклічним переносом старшого розряду (Modulo-255 arithmetic / Carry-Add Addition) та підсумковим інвертуванням бітів (Bitwise Complement).

### Опис математичного алгоритму сумування

Звичайна арифметика 8-бітних суматорів при переповненні відкидає 9-й біт переносу (Carry bit). У суматорі LIN (Modulo-255) цей біт переносу не відкидається, а додається назад до молодшого розряду суми:

```
Початкове значення: Sum = 0

Для кожного байта X з послідовності сумування:
    Sum = Sum + X
    Якщо Sum > 255 (виник перенос):
        Sum = (Sum & 0xFF) + 1

Оточна контрольна сума = (~Sum) & 0xFF
```

Якщо обчислена таким чином контрольна сума додається до переданої послідовності байтів і над нею проганяється той самий алгоритм, підсумковий результат сумування в приймачі має дорівнювати `0xFF` (255).

### Відмінності Classic та Enhanced Checksum

1. **Classic Checksum (Класична контрольна сума):**
   - **Послідовність сумування:** Включає тільки байти даних `Data[0] .. Data[N-1]`.
   - **Застосування:** Стандарт LIN 1.x, а також обов'язково для діагностичних кадрів з PID `0x3C` та `0x3D` у LIN 2.x / ISO 17987.

2. **Enhanced Checksum (Покращена контрольна сума):**
   - **Послідовність сумування:** Починається з байта `PID`, за яким слідують байти даних `Data[0] .. Data[N-1]`.
   - **Застосування:** Стандарт LIN 2.0, LIN 2.1, LIN 2.2A та ISO 17987 для усіх звичайних сигнальних кадрів (PID `0x00 .. 0x3B`).

## 4. Карта розподілу ідентифікаторів кадрів (ID Map)

Шестибітне поле ідентифікатора розбито на чотири функціональні діапазони:

| Діапазон ID (Hex) | Діапазон ID (Dec) | Тип кадру LIN | Функціональне призначення та специфіка |
| :--- | :--- | :--- | :--- |
| `0x00 .. 0x1F` | `0 .. 31` | Signal Frames (1..8 B) | Кадри телеметрії та команд (типово 2, 4 або 8 байт). Enhanced Checksum. |
| `0x20 .. 0x2F` | `32 .. 47` | Signal Frames (2..8 B) | Сигнальні кадри середньої довжини. Enhanced Checksum. |
| `0x30 .. 0x3B` | `48 .. 59` | Signal Frames (8 B) | Довгі сигнальні кадри (завжди 8 байт даних). Enhanced Checksum. |
| `0x3C` | `60` | Master Request (8 B) | Діагностичний запит Master до Slave. Завжди 8 байт, Classic Checksum. |
| `0x3D` | `61` | Slave Response (8 B) | Діагностична відповідь Slave до Master. Завжди 8 байт, Classic Checksum. |
| `0x3E` | `62` | User Defined | Розширення користувача (тестове обладнання). |
| `0x3F` | `63` | Reserved | Зарезервовано стандартами ISO 17987 для майбутніх розширень. |

## 5. Специфікація часових параметрів та електричних рівнів

Специфікація ISO 17987-4 встановлює чіткі межі електричних параметрів та таймінгів для забезпечення інтерлінеарної сумісності трансиверів різних виробників (NXP, Microchip, Texas Instruments, STMicroelectronics).

### Допустимі межі напруг шини

- **Напруга живлення бортової мережі (`VBAT`):** Номінально 12.0 V, робочий діапазон від 7.0 V до 18.0 V.
- **Поріг приймача для рецесивного стану (`V_BUS_REC`):** Понад 60 % від `VBAT` (приймається як логічна 1).
- **Поріг приймача для домінантного стану (`V_BUS_DOM`):** Менше 40 % від `VBAT` (приймається як логічний 0).
- **Зона невизначеності (Гістерезис):** Між 40 % та 60 % від `VBAT` для захисту від шумів.

### Бюджет часових допусків (Timing Budget)

- **Максимальний час каду (`T_Frame_Max`):**
  Обчислюється за формулою: `T_Frame_Max = 1.4 × T_Frame_Nominal`.
  Кожен кадр, тривалість якого перевищує `T_Frame_Max`, скасовується приймачем за тайм-аутом.
- **Стробування біта в UART:**
  Приймач здійснює вибірку сигналу (Bit Sampling) на рівні **50 % .. 75 %** від обчисленої тривалості біта `T_bit`.

Завдяки суворому дотриманню цих параметрів шина LIN зберігає повну працездатність при перепадах напруги живлення під час запуску ДВЗ (cranking) та в умовах сильного температурного дрейфу.
