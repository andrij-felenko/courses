# 🧮 Інтервальний аналіз Марзулло та оцінка похибок NTP

Мережева синхронізація часу відбувається в умовах неповноти інформації. Клієнт не може виміряти точний час віддаленого сервера напряму: він отримує лише набір дискретних міток часу, спотворених мережевими затримками черг у маршрутизаторах, дрейфом кварцових резонаторів та можливими апаратними збоями окремих вузлів. Щоб гарантувати точність системного часу, математичний апарат NTP замінює точкову оцінку часу **довірчим інтервалом** (англ. *confidence interval*) і застосовує інтервальну алгебру Кейта Марзулло (англ. *Keith Marzullo*) для відсікання збійних серверів.

### Формальна інтервальна алгебра

В інтервальній математиці Рамона Мура (англ. *Ramon Moore*) невизначена величина задається замкненим числовим відрізком `X = [x_l, x_r]`, де `x_l ≤ x_r`. Для інтервалів визначено базові алгебраїчні операції:

1. **Середина інтервалу (Midpoint):**
   ```
   mid(X) = (x_l + x_r) / 2
   ```
2. **Радіус (напівширина) інтервалу (Radius):**
   ```
   rad(X) = (x_r − x_l) / 2
   ```
3. **Сума Мінковського:**
   ```
   [a, b] + [c, d] = [a + c, b + d]
   ```
4. **Множення на додатний скаляр:**
   ```
   k · [a, b] = [k · a, k · b]    (для k ≥ 0)
   ```
5. **Перетин інтервалів:**
   ```
   [a, b] ∩ [c, d] = [max(a, c), min(b, d)]    (якщо max(a, c) ≤ min(b, d), інакше ∅)
   ```

У моделі NTP часовий відлік від кожного сервера `i` представляється інтервалом `I[i] = [θ[i] − Λ[i], θ[i] + Λ[i]]`, де центром є виміряне зміщення `mid(I[i]) = θ[i]`, а радіусом — синхронізаційна відстань `rad(I[i]) = Λ[i]`.

### Математична модель довірчого інтервалу

Кожен віддалений сервер `i` надає клієнту виміряне зміщення годинника `θ[i]` та кругову затримку `δ[i]`. Оскільки затримка поширення пакета не може бути від'ємною, істинне значення зміщення `θ_true` гарантовано лежить у замкненому числовому інтервалі:

```
I[i] = [θ[i] − Λ[i], θ[i] + Λ[i]]
```

Тут величина `Λ[i]` (грецька велика літера лямбда) називається **радіусом синхронізації** або **синхронізаційною відстанню** (англ. *synchronization distance*, або *root distance*). Вона визначає максимальну теоретичну похибку вимірювання й складається з двох компонентів: половини кругової затримки та сумарної дисперсії похибки:

```
Λ[i] = E[i] + δ[i] / 2
```

де:
* `δ[i]` — повна затримка поширення сигналу від клієнта через усі проміжні вузли до первинного еталона Stratum 0 (англ. *root delay*);
* `E[i]` — сумарна дисперсія еталона (англ. *root dispersion*), яка накопичує похибки квантування таймерів, джиттер мережі та максимальний можливий дрейф кварцового генератора за час, що минув від останнього оновлення.

### Рекурентне накопичення кореневої затримки та дисперсії

Під час передачі часу крізь ієрархію шарів Stratum похибки накопичуються рекурентно. Якщо сервер `S` синхронізується від джерела `P`, його власні параметри `Δ[S]` (коренева затримка) та `E[S]` (коренева дисперсія) обчислюються за формулами:

```
Δ[S] = Δ[P] + δ[S,P]
E[S] = E[P] + ε[S,P] + φ · (t − t_last)
```

де:
* `δ[S,P]` — виміряна кругова затримка між вузлом `S` та сервером `P`;
* `ε[S,P]` — виміряна дисперсія вибірки на проміжку між `S` та `P`;
* `φ` — константа максимального дрейфу локального кварцового резонатора (у специфікації RFC 5905 прийнято `φ = 15 · 10⁻⁶`, тобто 15 ppm або 15 мікросекунд на секунду);
* `t − t_last` — час, що минув з моменту останнього отримання мітки від джерела `P`.

Член `φ · (t − t_last)` відображає фундаментальну фізичну властивість: якщо сервер тимчасово втратив зв'язок зі своїм джерелом, довіра до його поточного часу не зникає миттєво, а лінійно розширює довірчий інтервал зі швидкістю 15 мікросекунд за секунду.

### Похибка асиметрії маршрутів

Головне припущення класичного чотириточкового алгоритму NTP полягає в симетрії мережевих затримок: час руху пакета-запиту від клієнта до сервера `d_req` вважається рівним часу руху пакета-відповіді від сервера до клієнта `d_resp`.

Розгляньмо фізичні рівняння руху пакетів. Нехай `T1` та `T4` — моменти відправки та прийому на клієнті, а `T2` та `T3` — моменти прийому та відправки на сервері за їхніми локальними шкалами. Зв'язок між шкалами задається істинним зміщенням `θ_true = t_server − t_client`.

```
T2 = T1 + θ_true + d_req             [час прибуття запиту на сервер]
T4 = T3 − θ_true + d_resp            [час прибуття відповіді на клієнт]
```

Віднявши друге рівняння від першого, отримуємо систему зв'язку виміряного зміщення `θ_meas` та істинного зміщення `θ_true`:

```
θ_meas
= ((T2 − T1) + (T3 − T4)) / 2        [стандартна формула NTP]
= ((θ_true + d_req) + (θ_true − d_resp)) / 2   [підстановка фізичних часів]
= θ_true + (d_req − d_resp) / 2      [виділення похибки асиметрії]
```

Звідси похибка вимірювання зміщення `Δθ = θ_meas − θ_true` дорівнює половині різниці затримок прямого та зворотного шляхів:

```
Δθ = (d_req − d_resp) / 2
```

Оскільки повна кругова затримка `δ = d_req + d_resp`, а затримки в кожному напрямку не можуть бути меншими за нуль (`d_req ≥ 0`, `d_resp ≥ 0`), різниця `|d_req − d_resp|` не перевищує повної затримки `δ`:

```
|Δθ| ≤ δ / 2
```

Це доводить фундаментальну теорему точності NTP: **похибка оцінки часу через невідому асиметрію мережі принципово обмежена половиною виміряної кругової затримки `δ / 2`**. Жоден статистичний чи програмний алгоритм обробки міток не здатний подолати цю межу без зовнішніх незалежних каналів калібрування затримки.

### Математичне обґрунтування фільтра мінімальної затримки

У системі масового обслуговування пакетних маршрутизаторів (модель `M/M/1`) повна затримка датаграми складається з константи фізичного поширення `d_min = d_prop + d_trans` та випадкової складової очікування в черзі `W`:

```
d = d_min + W
```

Випадкова величина очікування `W` описується експоненційним законом розподілу ймовірностей із параметром інтенсивності `α = μ − λ` (де `μ` — пропускна здатність інтерфейсу, `λ` — інтенсивність вхідного потоку пакетів).

Якщо клієнт збирає вибірку з `k = 8` незалежних пакетів `W₁, W₂, ..., W₈`, то мінімум вибірки `W_min = min(W₁, ..., W₈)` також є експоненційною випадковою величиною, але з сумарним параметром `k · α`:

```
E[W_min] = 1 / (k · α)
Var[W_min] = 1 / (k² · α²)
```

Це означає, що при виборі найменшої затримки серед 8 послідовних вимірювань математичне сподівання похибки черги зменшується у 8 разів, а її дисперсія спадає у **64 рази**. Таким чином, фільтр відбору мінімальної кругової затримки (англ. *Clock Filter Algorithm*) математично відсікає стохастичний шум комутаторів без необхідності складних інтегральних обчислень.

### Чому середнє арифметичне та медіана зазнають краху

Розгляньмо класичну візантійську задачу розподіленого консенсусу (англ. *Byzantine agreement*). Нехай у системі є `n = 5` серверів часу, з яких `f = 2` є збійними (наприклад, через апаратний збій резонатора або зловмисну атаку підміни).

Нехай три коректні сервери повідомляють істинний час із невеликою похибкою `θ₁ = 0.001` с, `θ₂ = 0.002` с, `θ₃ = 0.001` с, а два збійні сервери передають фальшивий час `θ₄ = 100.0` с та `θ₅ = 100.0` с.

1. **Середнє арифметичне (Mean):**
   ```
   θ_mean = (0.001 + 0.002 + 0.001 + 100.0 + 100.0) / 5 = 40.0008 с
   ```
   Похибка становить 40 секунд. Середнє арифметичне має нульову стійкість до викидів (англ. *breakdown point = 0*): єдиний скомпрометований вузол може змістити системний час на довільну величину.

2. **Медіана (Median):**
   Впорядкований ряд вибірок: `[0.001, 0.001, 0.002, 100.0, 100.0]`. Медіана дорівнює `0.002` с (успішно).
   Але якщо збійні сервери підступно заявлять значення `θ₄ = 0.050` с та `θ₅ = 0.060` с, впорядкований ряд набуде вигляду: `[0.001, 0.001, 0.002, 0.050, 0.060]`. Медіана обере `0.002` с. Проте якщо один із коректних серверів тимчасово запізниться з відповіддю, ряд стане `[0.001, 0.002, 0.050, 0.060]`, і медіана візьме значення `(0.002 + 0.050)/2 = 0.026` с, прийнявши сторону збійних вузлів.

Алгоритм Марзулло натомість оперує інтервалами й гарантує коректність, якщо кількість джерел задовольняє умову більшості: `n ≥ 2f + 1`.

### Алгоритм перетину інтервалів Марзулло

Кейт Марзулло розробив алгоритм знаходження мінімального інтервалу, який гарантовано містить істинний час, за умови, що з загальної кількості `n` джерел не більше `f` є збійними.

#### Покроковий розбір алгоритму Марзулло:

1. **Побудова списку кінцевих точок:** для кожного з `n` серверів формується інтервал `[L[i], R[i]] = [θ[i] − Λ[i], θ[i] + Λ[i]]`. Кожен інтервал розпадається на дві окремі точки:
   * ліва межа `L[i]` з типом `-1` (початок інтервалу);
   * права межа `R[i]` з типом `+1` (кінець інтервалу).

2. **Впорядкування точок:** усі `2n` точок об'єднуються в єдиний масив і сортуються за зростанням координати часу. Якщо ліва межа одного інтервалу збігається з правою межею іншого, ліва межа (`-1`) ставиться першою, щоб зберегти замкненість перетину.

3. **Сканування прямою (Sweep-line):** алгоритм проходить по впорядкованому списку точок зліва направо, підтримуючи лічильник активних інтервалів `c`:
   * зустрівши ліву межу `(L, -1)`: лічильник збільшується `c = c + 1`;
   * зустрівши праву межу `(R, +1)`: лічильник зменшується `c = c − 1`.

4. **Пошук інтервалу максимальної когерентності:** фіксуються всі відрізки між сусідніми точками, де кількість накладених інтервалів задовольняє умову більшості:
   ```
   c ≥ n − f
   ```
   Найменший відрізок `[L_best, R_best]`, що накриває область, де перетинаються щонайменше `m = n − f` джерел, є результуючим інтервалом Марзулло.

5. **Відсікання збійних серверів:** будь-який сервер `k`, чий вихідний інтервал `[L[k], R[k]]` взагалі не перетинає результуючий інтервал `[L_best, R_best]`, маркується як *falseticker* і повністю виключається з подальших розрахунків.

### Числовий приклад трасування алгоритму Марзулло

Розгляньмо практичний приклад роботи алгоритму для `n = 5` серверів, серед яких щонайбільше `f = 2` можуть бути збійними (необхідна більшість `m = n − f = 3` джерела).

Нехай отримано такі вимірювання зміщення та радіусів синхронізації:
* Сервер 1 (Truechimer): `θ₁ = -10 мс`, `Λ₁ = 20 мс` → інтервал `[-30, +10]` мс
* Сервер 2 (Truechimer): `θ₂ = +5 мс`, `Λ₂ = 20 мс` → інтервал `[-15, +25]` мс
* Сервер 3 (Truechimer): `θ₃ = +15 мс`, `Λ₃ = 20 мс` → інтервал `[-5, +35]` мс
* Сервер 4 (Falseticker 1 — дрейф антени): `θ₄ = +68 мс`, `Λ₄ = 20 мс` → інтервал `[+48, +88]` мс
* Сервер 5 (Falseticker 2 — збійний кристал): `θ₅ = -70 мс`, `Λ₅ = 15 мс` → інтервал `[-85, -55]` мс

Формуємо масив із 10 кінцевих точок і сортуємо їх за часом:

| Точка | Значення (мс) | Тип точки | Зміна лічильника | Лічильник `c` | Стан умови `c ≥ 3` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `L₅` | -85 | Початок (-1) | `+1` | `1` | Ні |
| `R₅` | -55 | Кінець (+1) | `-1` | `0` | Ні |
| `L₁` | -30 | Початок (-1) | `+1` | `1` | Ні |
| `L₂` | -15 | Початок (-1) | `+1` | `2` | Ні |
| `L₃` | -5 | Початок (-1) | `+1` | **`3`** | **Так (початок перетину: -5 мс)** |
| `R₁` | +10 | Кінець (+1) | `-1` | `2` | **Так (кінець перетину: +10 мс)** |
| `R₂` | +25 | Кінець (+1) | `-1` | `1` | Ні |
| `R₃` | +35 | Кінець (+1) | `-1` | `0` | Ні |
| `L₄` | +48 | Початок (-1) | `+1` | `1` | Ні |
| `R₄` | +88 | Кінець (+1) | `-1` | `0` | Ні |

У результаті сканування алгоритм визначає єдиний неперервний інтервал максимального перетину більшості: `[-5 мс .. +10 мс]`.

Перевірка перетину з вихідними інтервалами серверів:
* Сервер 1: `[-30, +10] ∩ [-5, +10] = [-5, +10]` (перетинається — Truechimer);
* Сервер 2: `[-15, +25] ∩ [-5, +10] = [-5, +10]` (перетинається — Truechimer);
* Сервер 3: `[-5, +35] ∩ [-5, +10] = [-5, +10]` (перетинається — Truechimer);
* Сервер 4: `[+48, +88] ∩ [-5, +10] = ∅` (порожня множина — **Falseticker, відкинуто**);
* Сервер 5: `[-85, -55] ∩ [-5, +10] = ∅` (порожня множина — **Falseticker, відкинуто**).

Алгоритм успішно відкинув обидва збійні джерела, навіть якби вони мали мінімальну кругову затримку.

### Модифікація Девіда Міллса (NTP Intersection Algorithm)

Оригінальний алгоритм Марзулло володіє властивістю, небажаною для фізичного годинника: якщо одне з коректних джерел має дуже малу затримку (і відповідно дуже вузький інтервал), результуючий перетин може стати надто малим або навіть не містити центрів `θ[i]` інших коректних серверів.

Девід Міллс модифікував алгоритм для NTP:
* якщо під час початкового пошуку з параметром `f` перетин виявляється порожнім, лічильник збійних серверів інкрементується `f = f + 1`, і пошук повторюється;
* ліва межа результуючого інтервалу не може бути більшою за найменше центральне значення `θ[i]` серверів-кандидатів, а права межа — меншою за найбільше центральне значення `θ[i]`.

Це гарантує, що підсумковий довірчий проміжок містить центри вимірювань усіх узгоджених джерел, уникаючи штучного звуження через статистичні флуктуації джиттеру окремого вузла.

### Обчислювальна складність алгоритму

Асимптотична складність алгоритму перетину Марзулло визначається етапом сортування `2n` кінцевих точок інтервалів:

```
O(n · log n)
```

де `n` — кількість опитуваних серверів. Оскільки в практичних конфігураціях NTP кількість пірів становить від 3 до 10 джерел, алгоритм виконується за мікросекунди без створення помітного навантаження на процесор.

### Алгоритм кластеризації та зваженого об'єднання

Після того, як алгоритм перетину відібрав множину узгоджених серверів-кандидатів (англ. *survivors*), NTP запускає **алгоритм кластеризації** (англ. *Clustering Algorithm*):

1. Для кожного кандидата `i` будується матриця взаємного статистичного розкиду (джиттеру) `d[i, j] = |θ[i] − θ[j]|`.
2. Обчислюється сумарний зважений джиттер кандидата `ψ[i]`:
   ```
   ψ[i] = √ ( (1 / (m − 1)) · ∑ (θ[i] − θ[j])² )    [для всіх j ≠ i]
   ```
3. Кандидат із найбільшим джиттером послідовно вилучається з вибірки, доки розмір пулу не зменшиться до заданого порогу або поки максимальний джиттер не стане меншим за кореневу дисперсію.

Для решти відібраних джерел (зазвичай 3–5 серверів) виконується **алгоритм об'єднання** (англ. *Combining Algorithm*). Фінальне значення зміщення `θ_final` формується як зважене середнє:

```
w[i] = 1 / Λ[i]                      [вага обернено пропорційна відстані]
θ_final = (∑ w[i] · θ[i]) / (∑ w[i]) [зважена оцінка для PLL/FLL]
```

### Динаміка та стійкість контуру автопідстроювання (PLL/FLL)

Передане значення зміщення `θ_final` обробляється контуром зворотного зв'язку другого порядку в просторі перетворень Лапласа. Передавальна функція замкненого контуру має вигляд:

```
H(s) = (2 · ζ · ω_n · s + ω_n²) / (s² + 2 · ζ · ω_n · s + ω_n²)
```

де:
* `ω_n` — власна резонансна частота контуру (англ. *natural frequency*), обернено пропорційна постійній часу `time_constant` та інтервалу опитування `Poll`;
* `ζ` (дзета) — коефіцієнт демпфування (англ. *damping factor*).

Для виключення автоколивань і резонансних перерегулювань у ядрі NTP обрано критичне демпфування Баттерворта: `ζ = 1 / √2 ≈ 0.707`. Це забезпечує запас стійкості за фазою понад 45 градусів та швидке експоненційне згасання помилки без затяжних коливань навколо нульового зміщення.

### Статистика Аллана та модель шумів генератора

Чому для дисципліни системного годинника потрібні одночасно контури фази (PLL) та частоти (FLL)? Відповідь дає **дисперсія Аллана** (англ. *Allan variance*, `σ_y²(τ)`), яка характеризує стабільність тактових генераторів залежно від інтервалу усереднення `τ`:

```
σ_y²(τ) = (1 / (2 · (N − 1))) · ∑ (y[k+1] − y[k])²
```

де `y[k]` — відносне відхилення частоти на k-му інтервалі вимірювання тривалістю `τ`.

* На малих інтервалах часу (`τ < 100 с`) у вимірюваннях домінує білий фазовий шум мережевих затримок і квантування таймера (англ. *white phase noise*). На цих масштабах оптимальним є контур фазового автопідстроювання (PLL), який фільтрує фазові коливання за низькочастотним законом другого порядку.
* На великих інтервалах часу (`τ > 1000 с`) домінує фліккер-шум і випадкове блукання частоти кварцового кристала під впливом коливань температури (англ. *random walk frequency noise*). Тут контур PLL втрачає ефективність, і керування перехоплює контур частотного автопідстроювання (FLL), який безпосередньо коригує першу похідну фази — частоту генератора.

Точка перетину двох шумів називається **інтервалом перемикання Аллана** (англ. *Allan intercept*, `τ_0`). Гібридний алгоритм Міллса динамічно зважує внески фазового та частотного контурів залежно від співвідношення поточного інтервалу опитування `Poll` та константи `τ_0`, досягаючи мінімальної дисперсії Аллана на всіх часових масштабах. Це забезпечує як швидке придушення короткострокового джиттеру мережевих черг, так і надійну компенсацію багатодобового теплового дрейфу локального кварцового кристала.
