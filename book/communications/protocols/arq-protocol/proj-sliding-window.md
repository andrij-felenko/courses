# ⚙️ Симулятор ковзного вікна: Go-Back-N та Selective Repeat у C та C++

У реальних вбудованих системах, радіомодемах, промислових контролерах і користувацьких протоколах передачі даних поверх сирого UART, RS-485 або ненадійних сокетів UDP реалізація надійного зв'язку за допомогою механізму ковзного вікна є базовою інженерною задачею.

Головна складність полягає в тому, що мережевий стек працює асинхронно та подійно: апаратні таймери відраховують таймаути у фоні, пакети надходять із непередбачуваними мережевими затримками або переплутаним порядком, контрольні суми можуть не збігатися через імпульсні завади в ефірі, а обсяг оперативної пам'яті під буфери на мікроконтролері суворо обмежений. Найменша помилка в арифметиці покажчиків кільцевого буфера або запізніле скидання таймера призводить до мертвого зависання протоколу (англ. *deadlock*) або прихованого дублювання байтів у пам'яті застосунку.

Нижче наведено детальну архітектуру, математичний аналіз граничних станів, алгоритми таймерів та повнофункціональну робочу реалізацію дискретного подійно-орієнтованого симулятора протоколів **Go-Back-N** та **Selective Repeat**.

---

### Архітектура протоколу та структура кадру

Кадр канального або транспортного рівня має бути самодостатньою одиницею передачі: він повинен містити достатньо інформації для маршрутизації, розпізнавання типу операції, контролю послідовності та перевірки цілісності даних.

Формат кадру в нашому симуляторі спроєктовано з урахуванням мінімізації накладних витрат:

```
+---------------+---------------+---------------+---------------+-------------------+---------------+
| Тип (1 байт)  | Seq (1 байт)  | Ack (1 байт)  | Len (1 байт)  | Payload (0..64 B) | CRC16 (2 B)   |
+---------------+---------------+---------------+---------------+-------------------+---------------+
```

1. **Тип повідомлення (`Type`, 1 байт):**
   * `0x01` (`FRAME_DATA`) — інформаційний кадр, що несе корисні дані користувача.
   * `0x02` (`FRAME_ACK`) — службове підтвердження успішного прийому даних.
   * `0x03` (`FRAME_NACK`) — заперечне підтвердження / явний запит повторної передачі пропущеного номера.
2. **Номер послідовності (`Seq`, 1 байт):** порядковий номер кадру даних у кільцевому просторі лишків `0 .. M - 1` (де `M = 2^k`). У службових пакетах `ACK` це поле зарезервовано або використовується для додаткової діагностики.
3. **Номер підтвердження (`Ack`, 1 байт):**
   * У протоколі **Go-Back-N** поле `Ack` містить кумулятивний номер: воно вказує номер *наступного очікуваного* кадру. Наприклад, `Ack = 3` означає: «усі кадри до номера 2 включно прийнято успішно; я чекаю на кадр 3».
   * У протоколі **Selective Repeat** поле `Ack` несе вибірковий номер конкретного успішно прийнятого кадру.
4. **Довжина корисного навантаження (`Len`, 1 байт):** кількість дійсних байтів у масиві `Payload` (від `0` до `64` байтів).
5. **Корисне навантаження (`Payload`, до 64 байтів):** потік байтів користувацького застосунку.
6. **Контрольна сума (`CRC16-CCITT`, 2 байти):** поліноміальний код перевірки цілісності, який обчислюється над усіма попередніми полями кадру. Якщо розрахована сума не збігається зі значенням у кадрі, пакет вважається спотвореним завадою і відкидається на фізичному рівні без генерації будь-яких відповідей.

### Модульна арифметика номерів послідовності

Оскільки номер послідовності `Seq` кодується скінченною кількістю бітів `k` (наприклад, для наочності візьмемо `k = 3` біти, що дає простір номерів `M = 2³ = 8` зі значеннями `0, 1, 2, 3, 4, 5, 6, 7`), лічильник номерів циклічно скидається в нуль після досягнення `7`.

У такій системі класичні оператори порівняння мов C та C++ (`<`, `>`, `<=`, `>=`) стають небезпечними й хибними. Наприклад, якщо база вікна `Base = 6`, а розмір вікна `W = 4`, то вікно охоплює номери `[6, 7, 0, 1]`. Кадр із номером `Seq = 0` є абсолютно коректним і лежить усередині вікна, проте наївна перевірка `Seq >= Base` поверне `false` (`0 >= 6` — брехня).

Щоб коректно визначити, чи належить довільний номер `seq` поточному вікну `[base .. base + win - 1]`, обчислюють **модульну відстань уперед** від бази до шуканого номера:

```
dist = (seq - base + M) % M
```

Кадр вважається належним до вікна тоді й лише тоді, коли ця відстань строго менша за розмір вікна:

```
dist < win
```

Ця формула інваріантна до циклічного переходу через нуль і надійно працює для будь-яких значень `base`, `seq` та `win`.

### Стан та життєвий цикл передавача й приймача

Поведінка вузлів протоколу описується скінченними автоматами:

#### Передавач (Sender)
* Зберігає покажчик нижньої межі вікна `send_base` (найстаріший надісланий, але ще не підтверджений кадр) та покажчик `next_seq` (номер, який буде присвоєно наступному новому кадру).
* Дозволяє відправляти нові дані лише доти, доки різниця `(next_seq - send_base + M) % M < W`. Якщо вікно заповнене, передавач блокує вхідні запити від застосунку.
* **У Go-Back-N:** керує **одним спільним таймером** для найстарішого непідтвердженого кадру (`send_base`). При отриманні `ACK` база зсувається вперед: `send_base = ack`. Якщо у вікні ще лишаються непідтверджені кадри, таймер перезапускається; якщо всі кадри підтверджено, таймер зупиняється. При вичерпанні таймауту передавач повертається назад і відправляє повторно всю пачку від `send_base` до `next_seq - 1`.
* **У Selective Repeat:** підтримує **окремий таймер для кожного слота вікна**. При вичерпанні таймауту повторно надсилається виключно той кадр, чий індивідуальний таймер обнулився.

#### Приймач (Receiver)
* **У Go-Back-N:** зберігає єдиний лічильник `expected_seq`. Якщо приходить кадр із номером `seq == expected_seq`, він приймається, віддається застосунку, а лічильник збільшується: `expected_seq = (expected_seq + 1) % M`. Будь-який інший кадр (позачерговий або дублікат) негайно відкидається, а у відповідь повторно надсилається старий `ACK`.
* **У Selective Repeat:** має приймальний буфер розміром `W_R` та покажчик `rcv_base`. Будь-який правильний кадр із вікна `[rcv_base .. rcv_base + W_R - 1]` зберігається у відповідній комірці буфера й індивідуально підтверджується. Якщо заповнюється комірка на позиції `rcv_base`, приймач перевіряє ланцюжок наступних комірок: усі послідовні накопичені кадри виймаються з буфера й передаються застосунку, а `rcv_base` зсувається вправо до першої дірки.

### Реалізація протоколів у C та C++

У наведених нижче вкладках представлено повний код реалізації протоколів:

```c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>
#include <stdlib.h>

#define MAX_PAYLOAD  64
#define SEQ_SPACE    8   /* Простір номерів M = 8 (номери від 0 до 7) */
#define WIN_SIZE_GBN 4   /* Розмір вікна GBN: W <= M - 1 */
#define WIN_SIZE_SR  4   /* Розмір вікна SR: W <= M / 2 */
#define RTO_TICKS    5   /* Таймаут повторної передачі в тактах */

typedef enum {
    FRAME_DATA = 1,
    FRAME_ACK  = 2,
    FRAME_NACK = 3
} FrameType;

typedef struct {
    uint8_t   type;
    uint8_t   seq;
    uint8_t   ack;
    uint8_t   len;
    uint8_t   payload[MAX_PAYLOAD];
    uint16_t  crc;
} Frame;

/* Обчислення контрольної суми CRC16-CCITT над полями кадру */
static uint16_t calc_crc16(const Frame *f) {
    uint16_t crc = 0xFFFF;
    const uint8_t *data = (const uint8_t *)f;
    size_t len = sizeof(Frame) - sizeof(uint16_t);
    for (size_t i = 0; i < len; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (int b = 0; b < 8; ++b) {
            if (crc & 0x8000) crc = (crc << 1) ^ 0x1021;
            else crc <<= 1;
        }
    }
    return crc;
}

/* Модульна перевірка: чи потрапляє номер seq у вікно [base .. base + win - 1] */
static bool is_in_window(uint8_t seq, uint8_t base, uint8_t win) {
    uint8_t dist = (uint8_t)((seq - base + SEQ_SPACE) % SEQ_SPACE);
    return dist < win;
}

/* ── Стан передавача Go-Back-N ── */
typedef struct {
    uint8_t send_base;
    uint8_t next_seq;
    Frame   buffer[SEQ_SPACE];
    int     timer_ticks;
    bool    timer_running;
} GbnSender;

/* ── Стан приймача Go-Back-N ── */
typedef struct {
    uint8_t expected_seq;
} GbnReceiver;

void gbn_sender_init(GbnSender *s) {
    s->send_base = 0;
    s->next_seq = 0;
    s->timer_ticks = 0;
    s->timer_running = false;
}

void gbn_receiver_init(GbnReceiver *r) {
    r->expected_seq = 0;
}

/* Відправлення нового кадру даних через Go-Back-N */
bool gbn_sender_send(GbnSender *s, const uint8_t *data, uint8_t len, Frame *out_frame) {
    if (!is_in_window(s->next_seq, s->send_base, WIN_SIZE_GBN)) {
        return false; /* Вікно заповнене, передачу заблоковано */
    }

    Frame *f = &s->buffer[s->next_seq];
    f->type = FRAME_DATA;
    f->seq = s->next_seq;
    f->ack = 0;
    f->len = len;
    memcpy(f->payload, data, len);
    f->crc = calc_crc16(f);

    *out_frame = *f;
    s->next_seq = (s->next_seq + 1) % SEQ_SPACE;

    if (!s->timer_running) {
        s->timer_running = true;
        s->timer_ticks = RTO_TICKS;
    }
    return true;
}

/* Обробка отриманого кадру на приймачі Go-Back-N */
bool gbn_receiver_on_frame(GbnReceiver *r, const Frame *in, Frame *out_ack) {
    if (calc_crc16(in) != in->crc) {
        return false; /* Спотворений кадр відкидаємо без відповіді */
    }

    if (in->type == FRAME_DATA && in->seq == r->expected_seq) {
        /* Кадр надійшов у суворій послідовності */
        r->expected_seq = (r->expected_seq + 1) % SEQ_SPACE;

        out_ack->type = FRAME_ACK;
        out_ack->seq = 0;
        out_ack->ack = r->expected_seq; /* Кумулятивне підтвердження: чекаємо наступний */
        out_ack->len = 0;
        out_ack->crc = calc_crc16(out_ack);
        return true;
    }

    /* Позачерговий або дубльований кадр відкидаємо, повторюємо останній дійсний ACK */
    out_ack->type = FRAME_ACK;
    out_ack->seq = 0;
    out_ack->ack = r->expected_seq;
    out_ack->len = 0;
    out_ack->crc = calc_crc16(out_ack);
    return true;
}

/* Обробка отриманого підтвердження на передавачі Go-Back-N */
void gbn_sender_on_ack(GbnSender *s, const Frame *ack) {
    if (calc_crc16(ack) != ack->crc || ack->type != FRAME_ACK) return;

    /* Перевіряємо, чи просуває отриманий ack базу вікна вперед */
    if (is_in_window(ack->ack, s->send_base, WIN_SIZE_GBN + 1)) {
        s->send_base = ack->ack;
        if (s->send_base == s->next_seq) {
            s->timer_running = false; /* Усі відправлені кадри підтверджено */
        } else {
            s->timer_ticks = RTO_TICKS; /* Перезапуск таймера для наступного непідтвердженого */
        }
    }
}

/* Обробка такту таймера на передавачі Go-Back-N */
int gbn_sender_tick(GbnSender *s, Frame retransmit_queue[]) {
    if (!s->timer_running) return 0;

    s->timer_ticks--;
    if (s->timer_ticks > 0) return 0;

    /* Спрацював таймаут RTO -> Go Back N: повторюємо ВСІ неподтверджені кадри */
    s->timer_ticks = RTO_TICKS;
    int count = 0;
    uint8_t curr = s->send_base;
    while (curr != s->next_seq) {
        retransmit_queue[count++] = s->buffer[curr];
        curr = (curr + 1) % SEQ_SPACE;
    }
    return count;
}
```

```cpp
#include <iostream>
#include <vector>
#include <array>
#include <optional>
#include <cstdint>
#include <cstring>
#include <memory>
#include <algorithm>

namespace arq {

constexpr size_t MAX_PAYLOAD   = 64;
constexpr uint8_t SEQ_SPACE    = 8;  // M = 8
constexpr uint8_t WIN_SIZE_SR  = 4;  // W <= M / 2
constexpr int     RTO_TICKS    = 5;

enum class FrameType : uint8_t {
    Data = 1,
    Ack  = 2,
    Nack = 3
};

struct Frame {
    FrameType type{FrameType::Data};
    uint8_t   seq{0};
    uint8_t   ack{0};
    uint8_t   len{0};
    std::array<uint8_t, MAX_PAYLOAD> payload{};
    uint16_t  crc{0};

    [[nodiscard]] uint16_t compute_crc() const noexcept {
        uint16_t res = 0xFFFF;
        const auto* raw = reinterpret_cast<const uint8_t*>(this);
        const size_t sz = sizeof(Frame) - sizeof(uint16_t);
        for (size_t i = 0; i < sz; ++i) {
            res ^= static_cast<uint16_t>(raw[i]) << 8;
            for (int b = 0; b < 8; ++b) {
                if (res & 0x8000) res = (res << 1) ^ 0x1021;
                else res <<= 1;
            }
        }
        return res;
    }

    [[nodiscard]] bool is_valid() const noexcept {
        return compute_crc() == crc;
    }
};

[[nodiscard]] inline bool in_window(uint8_t seq, uint8_t base, uint8_t win) noexcept {
    const uint8_t dist = (seq - base + SEQ_SPACE) % SEQ_SPACE;
    return dist < win;
}

// ── Передавач Selective Repeat (окремий таймер на кожен кадр) ──
class SelectiveRepeatSender {
public:
    struct Slot {
        Frame frame;
        bool  acked{false};
        int   timer{0};
        bool  active{false};
    };

    SelectiveRepeatSender() = default;

    std::optional<Frame> send(const std::vector<uint8_t>& data) {
        if (!in_window(next_seq_, send_base_, WIN_SIZE_SR)) {
            return std::nullopt; // Вікно переповнено
        }

        Slot& slot = slots_[next_seq_];
        slot.frame.type = FrameType::Data;
        slot.frame.seq = next_seq_;
        slot.frame.ack = 0;
        slot.frame.len = static_cast<uint8_t>(std::min(data.size(), MAX_PAYLOAD));
        std::copy_n(data.begin(), slot.frame.len, slot.frame.payload.begin());
        slot.frame.crc = slot.frame.compute_crc();

        slot.acked = false;
        slot.timer = RTO_TICKS;
        slot.active = true;

        Frame out = slot.frame;
        next_seq_ = (next_seq_ + 1) % SEQ_SPACE;
        return out;
    }

    void on_ack(const Frame& ack) {
        if (!ack.is_valid() || ack.type != FrameType::Ack) return;

        const uint8_t acked_seq = ack.ack;
        if (in_window(acked_seq, send_base_, WIN_SIZE_SR)) {
            slots_[acked_seq].acked = true;
            slots_[acked_seq].active = false;

            // Зсув вікна передавача вправо, якщо підтверджено базовий слот
            while (slots_[send_base_].acked && send_base_ != next_seq_) {
                slots_[send_base_].acked = false;
                send_base_ = (send_base_ + 1) % SEQ_SPACE;
            }
        }
    }

    std::vector<Frame> tick() {
        std::vector<Frame> retransmissions;
        for (uint8_t i = 0; i < SEQ_SPACE; ++i) {
            if (slots_[i].active && !slots_[i].acked) {
                if (--slots_[i].timer <= 0) {
                    // Таймаут ЛИШЕ для цього конкретного кадру
                    slots_[i].timer = RTO_TICKS;
                    retransmissions.push_back(slots_[i].frame);
                }
            }
        }
        return retransmissions;
    }

    [[nodiscard]] uint8_t base() const noexcept { return send_base_; }

private:
    uint8_t send_base_{0};
    uint8_t next_seq_{0};
    std::array<Slot, SEQ_SPACE> slots_{};
};

// ── Приймач Selective Repeat (буфер out-of-order пакетів) ──
class SelectiveRepeatReceiver {
public:
    struct Slot {
        Frame frame;
        bool  received{false};
    };

    SelectiveRepeatReceiver() = default;

    std::optional<Frame> on_frame(const Frame& in, std::vector<std::vector<uint8_t>>& delivered) {
        if (!in.is_valid() || in.type != FrameType::Data) return std::nullopt;

        const uint8_t seq = in.seq;
        Frame ack;
        ack.type = FrameType::Ack;
        ack.seq = 0;
        ack.ack = seq; // Індивідуальне підтвердження саме цього кадру
        ack.len = 0;
        ack.crc = ack.compute_crc();

        if (in_window(seq, rcv_base_, WIN_SIZE_SR)) {
            slots_[seq].frame = in;
            slots_[seq].received = true;

            // Перевіряємо, чи можна видати накопичені кадри застосунку
            while (slots_[rcv_base_].received) {
                const auto& f = slots_[rcv_base_].frame;
                std::vector<uint8_t> payload(f.payload.begin(), f.payload.begin() + f.len);
                delivered.push_back(std::move(payload));

                slots_[rcv_base_].received = false;
                rcv_base_ = (rcv_base_ + 1) % SEQ_SPACE; // Зсув вікна прийому
            }
        }
        return ack;
    }

    [[nodiscard]] uint8_t base() const noexcept { return rcv_base_; }

private:
    uint8_t rcv_base_{0};
    std::array<Slot, SEQ_SPACE> slots_{};
};

} // namespace arq
```

### Тестовий стенд: емуляція каналу з втратами

Нижче наведено код головної програми, яка імітує реальний канал зв'язку зі штучним внесенням втрати пакета (кадр #2 втрачається в дорозі).

Стенд демонструє фундаментальну різницю між двома протоколами:
1. У **Go-Back-N** приймач викидає наступний успішний кадр #3, змушуючи передавач після таймауту заново пересилати і кадр #2, і кадр #3.
2. У **Selective Repeat** приймач зберігає кадр #3 у своєму внутрішньому буфері й надсилає підтвердження `ACK 3`. Передавач після таймауту надсилає **лише пропущений кадр #2**. Щойно кадр #2 прибуває, приймач миттєво віддає застосунку одразу обидва повідомлення (#2 та #3) і зсуває вікно вперед.

```c
/* Сценарій емуляції ненадійного каналу та роботи Go-Back-N у C */
int main(void) {
    GbnSender tx;
    GbnReceiver rx;
    gbn_sender_init(&tx);
    gbn_receiver_init(&rx);

    printf("========================================\n");
    printf("  Симуляція протоколу Go-Back-N (C)\n");
    printf("========================================\n");
    uint8_t msg[] = "PAYLOAD_BLOCK";

    /* Крок 1. Передавач відправляє пачку з 4 кадрів (номери 0, 1, 2, 3) */
    Frame f[4];
    for (int i = 0; i < 4; ++i) {
        if (gbn_sender_send(&tx, msg, sizeof(msg), &f[i])) {
            printf("[TX] Відправлено Кадр #%d (SendBase=%d, NextSeq=%d)\n",
                   f[i].seq, tx.send_base, tx.next_seq);
        }
    }

    /* Крок 2. Кадри 0 та 1 успішно доходять до приймача */
    Frame ack;
    for (int i = 0; i < 2; ++i) {
        if (gbn_receiver_on_frame(&rx, &f[i], &ack)) {
            printf("[RX] Отримано Кадр #%d -> Відповідь: Кумулятивний ACK %d\n",
                   f[i].seq, ack.ack);
            gbn_sender_on_ack(&tx, &ack);
            printf("[TX] Отримано ACK %d -> SendBase зміщено на %d\n", ack.ack, tx.send_base);
        }
    }

    /* Крок 3. Кадр 2 губиться в каналі зв'язку через заваду */
    printf("\n>>> [КАНАЛ] ✗ Кадр #2 СПОТВОРЕНО / ВТРАЧЕНО! <<<\n\n");

    /* Крок 4. Кадр 3 надходить до приймача */
    if (gbn_receiver_on_frame(&rx, &f[3], &ack)) {
        printf("[RX] Отримано Кадр #3 поза чергою (очікувався #2) -> ВІДКИДАЄМО!\n");
        printf("[RX] Повтор попереднього ACK %d\n", ack.ack);
        gbn_sender_on_ack(&tx, &ack);
    }

    /* Крок 5. Передавач чекає таймауту для неподтвердженого кадру #2 */
    printf("\n[TX] Очікування таймауту RTO для Кадру #2...\n");
    Frame retrans[SEQ_SPACE];
    int count = 0;
    for (int t = 0; t < RTO_TICKS; ++t) {
        count = gbn_sender_tick(&tx, retrans);
        if (count > 0) break;
    }

    /* Крок 6. Спрацював таймаут: передавач повторює ВСЮ пачку від кадру #2 */
    printf("[TX] Спрацював RTO! Відкат назад на N: повтор %d кадрів:\n", count);
    for (int i = 0; i < count; ++i) {
        printf("     -> Повторна передача кадру #%d\n", retrans[i].seq);
    }

    return 0;
}
```

```cpp
int main() {
    using namespace arq;
    SelectiveRepeatSender tx;
    SelectiveRepeatReceiver rx;

    std::cout << "========================================\n";
    std::cout << "  Симуляція Selective Repeat (C++)\n";
    std::cout << "========================================\n";

    std::vector<uint8_t> payload = {'T', 'E', 'L', 'E', 'M', 'E', 'T', 'R', 'Y'};

    // Крок 1. Відправляємо пачку кадрів 0, 1, 2, 3
    std::vector<Frame> in_flight;
    for (int i = 0; i < 4; ++i) {
        if (auto f = tx.send(payload)) {
            std::cout << "[TX] Відправлено Кадр #" << static_cast<int>(f->seq)
                      << " (TX Base = " << static_cast<int>(tx.base()) << ")\n";
            in_flight.push_back(*f);
        }
    }

    std::vector<std::vector<uint8_t>> delivered;

    // Крок 2. Кадри 0 та 1 благополучно доходять
    for (int i = 0; i < 2; ++i) {
        if (auto ack = rx.on_frame(in_flight[i], delivered)) {
            std::cout << "[RX] Прийнято #" << static_cast<int>(in_flight[i].seq)
                      << " -> Шлемо вибірковий ACK " << static_cast<int>(ack->ack) << "\n";
            tx.on_ack(*ack);
        }
    }

    // Крок 3. Кадр 2 губиться в каналі
    std::cout << "\n>>> [КАНАЛ] ✗ Кадр #2 ВТРАЧЕНО В ЕФІРІ! <<<\n\n";

    // Крок 4. Кадр 3 прибуває до приймача: він зберігається в буфері!
    if (auto ack = rx.on_frame(in_flight[3], delivered)) {
        std::cout << "[RX] Отримано Кадр #3 поза чергою -> ЗБЕРЕЖЕНО В БУФЕРІ!\n";
        std::cout << "[RX] Відправлено вибірковий ACK " << static_cast<int>(ack->ack) << "\n";
        tx.on_ack(*ack);
    }

    // Крок 5. На передавачі вичерпується таймаут для кадру #2
    std::cout << "\n[TX] Очікування таймауту для Кадру #2...\n";
    std::vector<Frame> retrans;
    for (int t = 0; t < RTO_TICKS; ++t) {
        retrans = tx.tick();
        if (!retrans.empty()) break;
    }

    // Крок 6. Передавач повторює ЛИШЕ кадр #2 (не чіпаючи #3!)
    std::cout << "[TX] Спрацював RTO! Точковий повтор " << retrans.size() << " кадру(ів):\n";
    for (const auto& rf : retrans) {
        std::cout << "     -> Повтор виключно втраченого кадру #" 
                  << static_cast<int>(rf.seq) << "\n";
    }

    // Крок 7. Повторений кадр #2 прибуває: приймач склеює буфер і видає обидва повідомлення!
    if (auto ack = rx.on_frame(retrans[0], delivered)) {
        std::cout << "\n[RX] Отримано пропущений Кадр #2! Буфер розблоковано!\n";
        std::cout << "[RX] Застосунку доставлено повідомлень: " << delivered.size() 
                  << " (номери #0, #1, #2, #3 по порядку)\n";
        tx.on_ack(*ack);
    }

    std::cout << "\n[Підсумок] Поточний стан: TX Base = " << static_cast<int>(tx.base())
              << ", RX Base = " << static_cast<int>(rx.base()) << "\n";

    return 0;
}
```

### Керування чергою таймерів: масив проти годинникового колеса (Timer Wheel)

У наведеному навчальному прикладі передавач Selective Repeat виконує лінійний прохід масивом слотів під час кожного такту таймера (`tick()`). Для малого вікна `W = 4` чи `W = 8` на мікроконтролері це займає кілька десятків тактів процесора.

Однак у високонавантажених системах, де розмір вікна сягає сотень або тисяч пакетів (як у ядрах операційних систем Linux чи FreeBSD), лінійний перебір масиву складності `O(W)` під час кожного системного переривання таймера є неприпустимим марнотратством процесорного часу.

Для досягнення константної складності `O(1)` при керуванні таймерами використовують структуру даних **ієрархічне годинникове колесо** (англ. *Hashed and Hierarchical Timing Wheel*, запропоноване Джорджем Варгезе та Ентоні Лауком у 1987 році):

1. Пам'ять організується у вигляді кільцевого масиву списків (кошиків, англ. *buckets*), де кожен кошик відповідає майбутньому кванту часу.
2. Коли кадр передається в лінію в момент часу `T_now` з таймаутом `RTO`, дескриптор кадру прив'язується до кошика за індексом `(T_now + RTO) % WHEEL_SIZE`. Операція взяття на таймер виконується за строго `O(1)` тактів.
3. Під час чергового переривання системного таймера стрілка колеса зсувається на одну позицію `current_tick = (current_tick + 1) % WHEEL_SIZE`, і ядро обробляє виключно той зв'язний список касет, чий час сплив саме в цей квант часу. Решта тисяч активних таймерів навіть не перевіряються.
4. При отриманні підтвердження `ACK` дескриптор кадру миттєво видаляється зі свого двозв'язного списку за час `O(1)`.

### Адаптивний розрахунок RTO в цілочисельній арифметиці

У реальних бездротових та пакетних мережах час кругового обігу `RTT` постійно коливається через зміну радіоумов та довжини черг на проміжних вузлах. Фіксований таймаут `RTO` використовувати не можна.

Для вбудованих мікроконтролерів без апаратного блоку обчислень із плаваючою комою (FPU), таких як ARM Cortex-M0/M3, класичні формули Вана Джейкобсона (RFC 6298) реалізують у **фіксованій точці** (цілочисельне масштабування з коефіцієнтами `8` та `4`):

```
/* Цілочисельна реалізація алгоритму Джейкобсона / Карелса */
typedef struct {
    int32_t srtt_scaled;   /* SRTT * 8 */
    int32_t rttvar_scaled; /* RTTVAR * 4 */
    int32_t rto_ms;        /* Розрахований таймаут у мілісекундах */
} RtoEstimator;

void rto_init(RtoEstimator *e) {
    e->srtt_scaled = 0;
    e->rttvar_scaled = 0;
    e->rto_ms = 1000; /* Початковий таймаут за замовчуванням 1000 мс */
}

void rto_update(RtoEstimator *e, int32_t rtt_sample_ms) {
    if (e->srtt_scaled == 0) {
        /* Перший вимір RTT */
        e->srtt_scaled = rtt_sample_ms << 3;   /* srtt = rtt_sample */
        e->rttvar_scaled = rtt_sample_ms << 1; /* rttvar = rtt_sample / 2 */
    } else {
        /* delta = rtt_sample - SRTT */
        int32_t delta = rtt_sample_ms - (e->srtt_scaled >> 3);
        
        /* SRTT = SRTT + delta / 8 */
        e->srtt_scaled += delta;
        
        if (delta < 0) delta = -delta;
        
        /* delta_var = |delta| - RTTVAR */
        int32_t delta_var = delta - (e->rttvar_scaled >> 2);
        
        /* RTTVAR = RTTVAR + delta_var / 4 */
        e->rttvar_scaled += delta_var;
    }

    /* RTO = SRTT + 4 * RTTVAR */
    e->rto_ms = (e->srtt_scaled >> 3) + e->rttvar_scaled;

    /* Обмеження знизу та зверху */
    if (e->rto_ms < 200)   e->rto_ms = 200;   /* Мінімальний поріг 200 мс */
    if (e->rto_ms > 60000) e->rto_ms = 60000; /* Максимальний поріг 60 с */
}
```

#### Правило Карна-Партріджа
Критично важливим правилом при оновленні `RTO` є **заборона вимірювання `RTT` для повторно надісланих кадрів** (англ. *Karn's Algorithm*). Якщо передавач надіслав кадр, не дочекався `ACK`, надіслав його вдруге, а за мить отримав `ACK`, він принципово не може знати, на яку саме спробу надійшла відповідь — на першу (яка просто затрималася в мережі) чи на другу. Використання такої вибірки спотворить статистику згладжування `SRTT`.

Тому при виникненні таймауту діє правило:
1. Вибірка `RTT` для цього кадру ігнорується.
2. Поточне значення `RTO` подвоюється (**експоненційний відступ**, англ. *exponential backoff*): `RTO = 2 · RTO`.

### Прискорення повтору: NACK та швидкий повтор (Fast Retransmit)

Очікування вичерпання таймауту `RTO` — це завжди затримка й простій каналу. Щоб скоротити час реакції на втрату кадру, сучасні протоколи використовують активну сигналізацію:

1. **Явний сигнал NACK (Negative Acknowledgment):** Щойно приймач Selective Repeat отримує кадр із номером `#5`, коли найстарішим очікуваним є `#2`, він фіксує пропуск і миттєво відправляє службовий кадр `NACK 2`. Передавач, не чекаючи спливання таймера `RTO`, негайно виконує позачергову повторну передачу кадру `#2`.
2. **Правило трьох дубльованих ACK (Fast Retransmit у TCP):** Якщо приймач підтримує лише кумулятивні підтвердження (як у Go-Back-N), прихід кожного позачергового кадру (#3, #4, #5) викликає повторну генерацію старого `ACK 1`. Отримання передавачем трьох однакових `ACK` поспіль є статистично достовірним свідченням того, що наступний кадр (#2) утрачено, і передавач запускає швидкий повтор кадру `#2` без очікування таймауту.

### Інтеграція протоколу в архітектуру реального часу (FreeRTOS / DMA)

При перенесенні наведеного алгоритму на реальний мікроконтролер (наприклад, STM32 з апаратним інтерфейсом RS-485) типова архітектура драйвера будується за трирівневою схемою:

1. **Рівень переривань та DMA:** Периферія UART за допомогою кільцевого буфера DMA накопичує прийняті байти. Після виявлення кінця кадру (за таймаутом лінії `IDLE Line Detection` або за спеціальним байтом-маркером кінця пакета `SLIP/COBS`) переривання перевіряє `CRC16` і передає готовий `Frame` у чергу FreeRTOS.
2. **Задача протокольного автомата (Protocol Worker Task):** Окрема задача операційної системи блокується на очікуванні подій із черги (`xQueueReceive`). Подіями є або надходження нового кадру від DMA, або сигнал періодичного таймера (наприклад, `10 мс` через `vTaskDelayUntil`). Задача викликає методи `on_frame()`, `on_ack()` або `tick()` і формує чергу вихідних пакетів.
3. **Керування протитиском застосунку:** Якщо внутрішній буфер передавача `buffer[]` заповнений (вікно закрито), функція `send()` блокує викликаючий потік застосунку на семафорі або повертає код помилки `ERR_WOULDBLOCK`, запобігаючи неконтрольованому витоку пам'яті.

### Взаємодія з керуванням потоком (Flow Control)

У практичних системах механізм ARQ рідко існує у вакуумі: він тісно переплітається з механізмом керування потоком (англ. *flow control*). Якщо швидкий передавач заливає повільний приймач даними швидше, ніж центральний процесор приймача встигає їх обробляти, буфер приймача неминуче переповниться, навіть якщо радіоканал є абсолютно бездоганним і вільним від завад.

Щоб запобігти переповненню пам'яті, у заголовок підтвердження додають поле **оголошення вікна** (англ. *Window Advertisement*):

```
+---------------+---------------+---------------+-------------------+---------------+
| Тип (1 байт)  | Seq (1 байт)  | Ack (1 байт)  | WinSize (1 байт)  | CRC16 (2 B)   |
+---------------+---------------+---------------+-------------------+---------------+
```

Поле `WinSize` показує, скільки вільних слотів наразі залишилося в оперативній пам'яті приймача. Передавач динамічно обмежує розмір свого вікна передавання:

```
Effective_Window = min(Configured_W, Advertised_WinSize)
```

Якщо споживчий процес на приймачі тимчасово завис (наприклад, виконує повільний запис у Flash-пам'ять або розрахунок криптографічного підпису), приймач надсилає `WinSize = 0` (так зване **нульове вікно**, англ. *Zero Window*). Отримавши такий сигнал, передавач негайно зупиняє передачу нових даних, але запускає періодичний таймер зондування (англ. *Zero Window Probe*). Кожні кілька секунд передавач надсилає короткий 1-байтовий зонд, змушуючи приймач відповісти актуальним значенням `WinSize`, доки пам'ять не звільниться.

#### Запобігання синдрому дурного вікна (Silly Window Syndrome)
Якщо застосунок на приймачі вичитує дані малими порціями (по 1 байту), наївний приймач щоразу оголошуватиме відкриття вікна на 1 байт (`WinSize = 1`). Передавач негайно відправлятиме 1 корисний байт у повнорозмірному кадрі з 6 байтами заголовка та CRC. Ефективність каналу впаде до критично низьких значень через надмірні накладні витрати заголовків.

Для боротьби з цим явищем застосовують алгоритм Кларка: приймач **не оголошує** збільшення вікна доти, доки в буфері не звільниться місце принаймні для одного повнорозмірного кадру максимального розміру (англ. *Maximum Segment Size*, MSS) або доки не звільниться половина всього приймального буфера.

### Суміщення підтверджень із даними (Piggybacking) та відкладений ACK

У симетричних двосторонніх каналах (де обидва вузли безперервно обмінюються даними, наприклад, у режимі повнодуплексного UART або сокетного зв'язку) передавати окремий службовий кадр `ACK` на кожен прийнятий кадр даних неефективно: це витрачає пропускну здатність лінії та час перемикання трансиверів.

Застосовують техніку **попутного підтвердження** (англ. *piggybacking* — «їзда на чужій спині»):

1. Коли вузол `B` приймає кадр від вузла `A`, він не відправляє окремий пакет `ACK` негайно.
2. Якщо у вузла `B` уже є підготовлений власний кадр даних для вузла `A`, він записує номер підтвердження в поле `Ack` свого вихідного кадру даних і транслює обидві сутності одночасно в одному пакеті.
3. Якщо у вузла `B` немає власних даних для передачі, запускається короткий **таймер відкладеного підтвердження** (англ. *Delayed ACK Timer*, типово 10–50 мс). Якщо протягом цього часу застосунок формує відповідь, `ACK` «сідає на спину» вихідного кадру. Якщо таймер спливає, а нових даних немає, генерується звичайний окремий короткий службовий `ACK`.

### Безпека та стійкість до атак на вичерпання ресурсів

При розробці мережевих протоколів для вбудованих пристроїв та серверів архітектор повинен враховувати ризики зловмисного маніпулювання пакетами ARQ:

1. **Атака виснаження пам'яті (Memory Exhaustion / Out-of-Order Flooding):** Зловмисник надсилає шкідливі кадри з випадковими розрізненими номерами послідовності `Seq`, що лежать у межах вікна `W_R`, але навмисно не надсилає найперший очікуваний кадр `rcv_base`. Якщо розмір вікна `W_R` занадто великий, приймач виділить пам'ять під тисячі буферизованих фрагментів, що призведе до вичерпання пулу пам'яті (Panic / OOM). Захистом є жорстке статичне обмеження максимального розміру приймального буфера та скидання сесії при виявленні аномальної кількості дірок.
2. **Атака оптимістичного підтвердження (Optimistic ACK Attack):** Зловмисний приймач надсилає підтвердження `ACK` на кадри, які він ще навіть не отримав (передбачаючи майбутні номери `Seq`). Це змушує передавача неконтрольовано нарощувати швидкість передачі та випорожняти свій буфер повтору. Захистом є додавання випадкових одноразових міток (англ. *nonces*) у кожен кадр даних, які приймач зобов'язаний повернути всередині службового `ACK`.
