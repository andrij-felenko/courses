# 🧮 Математичний аналіз ефективності та пропускної здатності протоколів ARQ

Протоколи автоматичного запиту повторної передачі (англ. *Automatic Repeat reQuest*, ARQ) перетворюють фізично ненадійний канал із шумами й втратами на надійне логічне з'єднання. Однак за надійність доводиться платити часом очікування підтверджень, простоєм передавача та повторним пересиланням спотворених блоків.

Кількісною мірою цієї плати є **коефіцієнт використання каналу** (англ. *channel utilization*, `U`) — частка загального часу роботи каналу, протягом якої лінія передає виключно корисні, неповторювані дані. Знаючи коефіцієнт `U`, можна обчислити реальну пропускну здатність каналу `S` (у бітах на секунду) за базової фізичної швидкості лінії `R`:

```
S = U · R
```

Нижче наведено строге математичне виведення коефіцієнта `U` для трьох класичних схем ARQ: Stop-and-Wait, Go-Back-N та Selective Repeat — спершу для ідеального каналу без завад, а потім для реального середовища з імовірністю втрати пакета `p`. Крім того, наведено алгебраїчні доведення фундаментальних обмежень на розмір вікна в кільцевому просторі номерів послідовності та аналіз поведінки протоколів у каналах із пакетними помилками Гільберта-Елліотта.

---

### Базові часові параметри та нормалізована затримка

Процес передачі одного кадру довжиною `L` біт через канал із фізичною бітовою швидкістю `R` біт/с та відстанню між вузлами `d` метрів описується такими параметрами:

1. **Час передачі кадру даних (`T_frame` або `T_f`):** час, необхідний передавачу для випромінювання всіх `L` бітів кадру в лінію:
```
T_frame = L / R
```

2. **Час поширення сигналу в середовищі (`T_prop` або `T_p`):** час проходження електромагнітної хвилі крізь кабель або простір зі швидкістю `v` (типово `v ≈ 2·10⁸` м/с у міді та оптоволокні, `v ≈ 3·10⁸` м/с у вакуумі):
```
T_prop = d / v
```

3. **Час передачі підтвердження (`T_ack`):** тривалість випромінювання службового пакета `ACK` довжиною `L_ack` біт:
```
T_ack = L_ack / R
```
Оскільки службовий пакет `ACK` зазвичай дуже короткий (`L_ack << L`), часто приймають `T_ack ≈ 0`.

4. **Час апаратної обробки на приймачі (`T_proc`):** час перевірки контрольної суми CRC та генерації відповіді (типово мікросекунди, `T_proc ≈ 0`).

5. **Повний час кругового обігу (`RTT`, Round-Trip Time):**
```
RTT = 2 · T_prop + T_proc + T_ack
```

6. **Нормалізована затримка поширення (`a`):** безрозмірний параметр зв'язку, який виражає затримку поширення в одиницях тривалості передачі одного кадру:
```
a = T_prop / T_frame = (d / v) / (L / R) = (d · R) / (v · L)
```

Добуток `R · T_prop` (або `R · RTT`) називають **добутком ємності на затримку** (англ. *Bandwidth-Delay Product*, BDP). Він показує, скільки бітів одночасно перебуває «в польоті» всередині фізичної лінії. Якщо `a << 1`, лінія коротка, а кадри довгі; якщо `a >> 1`, лінія являє собою довгу трубу, де одночасно може летіти багато окремих кадрів.

### 1. Stop-and-Wait ARQ

У протоколі Stop-and-Wait передавач надсилає один кадр, після чого повністю зупиняє передачу й чекає на надходження підтвердження `ACK`.

#### Ідеальний канал без помилок (p = 0)

Загальний час одного повного циклу передачі `T_cycle` складається з часу передачі кадру, подвійного часу поширення та часу передачі ACK:

```
T_cycle = T_frame + 2 · T_prop + T_proc + T_ack
```

Нехтуючи малими величинами `T_proc` та `T_ack`, маємо:

```
T_cycle = T_frame + 2 · T_prop
```

Коефіцієнт використання каналу `U` є відношенням корисного часу передачі `T_frame` до загального часу циклу `T_cycle`:

```
U_SW0 = T_frame / T_cycle
      = T_frame / (T_frame + 2 · T_prop)      [підстановка T_cycle]
      = 1 / (1 + 2 · (T_prop / T_frame))      [ділення чисельника і знаменника на T_frame]
      = 1 / (1 + 2 · a)                       [заміна a = T_prop / T_frame]
```

Якщо `a` велике (наприклад, супутниковий канал, де `a = 50`), коефіцієнт використання становить `1 / (1 + 100) ≈ 0.0099` (менше 1%).

#### Канал із випадковими втратами пакетів (p > 0)

Нехай `p` — імовірність того, що кадр даних або відповідний йому `ACK` буде пошкоджено завадою чи втрачено в мережі.

Кожна невдала спроба передачі завершується спрацьовуванням таймера повторної передачі (англ. *Retransmission Timeout*, `T_out`). Оптимально налаштований таймер задовольняє умову:

```
T_out ≈ T_cycle = T_frame + 2 · T_prop
```

Кількість спроб передачі `N`, необхідних для першої успішної доставки кадру та отримання `ACK`, є дискретною випадковою величиною, що має геометричний розподіл:

```
P(N = k) = (1 - p) · p^(k - 1),   де k = 1, 2, 3, ...
```

Математичне сподівання кількості спроб `E[N]` дорівнює:

```
E[N] = ∑ (k · (1 - p) · p^(k - 1))             [сума від k = 1 до нескінченності]
     = (1 - p) · ∑ (k · p^(k - 1))             [винесення спільного множника (1 - p)]
     = (1 - p) · (1 / (1 - p)²)                [похідна суми нескінченного геометричного ряду]
     = 1 / (1 - p)                             [скорочення дробу]
```

Загальний середній час, витрачений на успішну доставку одного кадру, дорівнює:

```
T_total = E[N] · T_cycle = T_cycle / (1 - p)
```

Коефіцієнт використання каналу `U_SW` при наявності втрат:

```
U_SW = T_frame / T_total
     = T_frame / (T_cycle / (1 - p))          [підстановка T_total]
     = (1 - p) · (T_frame / T_cycle)          [винесення множника (1 - p)]
     = (1 - p) / (1 + 2 · a)                  [підстановка формули для ідеального каналу]
```

### 2. Go-Back-N ARQ

У протоколі Go-Back-N передавач може безперервно транслювати до `W` кадрів поспіль (розмір вікна передавання), не очікуючи на підтвердження кожного з них. Приймач приймає кадри суворо по порядку; будь-який кадр, що надійшов із порушенням нумерації, негайно відкидається.

#### Ідеальний канал без помилок (p = 0)

Час, за який передавач може відправити ціле вікно з `W` кадрів, становить `W · T_frame`. Перший `ACK` від першого кадру повернеться до передавача через час `T_frame + 2 · T_prop`.

Можливі два випадки залежно від розміру вікна `W`:

1. **Вікно повністю покриває час очікування (`W ≥ 1 + 2a`):**
   Поки передавач випромінює `W`-й кадр, підтвердження на перший кадр уже прибуває. Передавач безперервно зсуває вікно вперед і ніколи не зупиняє передачу. Лінія завантажена на 100%:
```
U_GBN0 = 1,   якщо W ≥ 1 + 2 · a
```

2. **Вікно менше за затримку кругового обігу (`W < 1 + 2a`):**
   Передавач відправляє `W` кадрів за час `W · T_frame`, після чого вимушено зупиняється й чекає на `ACK` першого кадру, який прийде лише через `T_frame + 2 · T_prop`. Тоді:
```
U_GBN0 = (W · T_frame) / (T_frame + 2 · T_prop)
       = W / (1 + 2 · a),   якщо W < 1 + 2 · a
```

Об'єднаний вираз для ідеального каналу:

```
U_GBN0 = min(1, W / (1 + 2 · a))
```

#### Канал із випадковими втратами пакетів (p > 0)

Якщо кадр втрачається, приймач відкидає всі наступні `W - 1` кадрів, які передавач уже встиг відправити слідом у межах відкритого вікна. Коли на передавачі спрацьовує таймаут, він змушений повернутися назад на `W` позицій і повторно передати не лише втрачений кадр, а й усю наступну пачку з `W - 1` кадрів.

Порахуємо математичне сподівання кількості переданих кадрів `E[M]`, необхідних для того, щоб один кадр був успішно прийнятий приймачем:

* Якщо кадр доходить із першої спроби (ймовірність `1 - p`), витрачається рівно `1` передача.
* Якщо перша спроба невдала (ймовірність `p`), передавач витрачає `1` передачу на сам кадр плюс `W` передач на повторне відправлення пачки після таймауту.

Загальне число спроб формується сумою:

```
E[M] = 1 · (1 - p) + (1 + W) · p · (1 - p) + (1 + 2 · W) · p² · (1 - p) + ...
     = (1 - p) · ∑ ((1 + k · W) · p^k)       [сума від k = 0 до нескінченності]
     = (1 - p) · [ ∑ (p^k) + W · ∑ (k · p^k) ]
     = (1 - p) · [ (1 / (1 - p)) + W · (p / (1 - p)²) ]
     = 1 + (W · p) / (1 - p)
     = (1 - p + W · p) / (1 - p)
```

Оскільки на одну корисну доставку в середньому витрачається `E[M]` передач слотів тривалістю `T_frame`:

1. Якщо `W ≥ 1 + 2a`:
```
U_GBN = 1 / E[M]
      = (1 - p) / (1 - p + W · p)             [підстановка E[M]]
      = (1 - p) / (1 + (W - 1) · p)           [спрощення знаменника]
```

2. Якщо `W < 1 + 2a`:
```
U_GBN = (W / (1 + 2 · a)) · (1 / E[M])
      = (W · (1 - p)) / ((1 + 2 · a) · (1 - p + W · p))
```

Звідси видно, що при збільшенні ймовірності помилки `p` коефіцієнт `U_GBN` стрімко деградує пропорційно `W · p`, оскільки кожен збій знищує ціле вікно кадрів.

### 3. Selective Repeat ARQ

У протоколі Selective Repeat приймач має власний буфер пам'яті розміром `W_R = W`. Коли один кадр губиться, приймач не відкидає наступні правильні кадри, а зберігає їх у буфері й підтверджує вибірковими `ACK`.

Передавач після таймауту повторно надсилає **виключно той єдиний кадр**, який було втрачено.

#### Ідеальний канал без помилок (p = 0)

Для ідеального каналу поведінка Selective Repeat повністю збігається з Go-Back-N:

```
U_SR0 = min(1, W / (1 + 2 · a))
```

#### Канал із випадковими втратами пакетів (p > 0)

Оскільки приймач зберігає всі правильно прийняті кадри, успіх чи невдача передачі будь-якого кадру ніяк не впливає на інші кадри у вікні. Кожен кадр передається незалежно доти, доки не буде успішно підтверджений.

Середня кількість передач, необхідна для доставки одного конкретного кадру, підпорядковується стандартному геометричному розподілу:

```
E[N] = 1 / (1 - p)
```

Жоден успішний кадр не передається повторно. Тому ефективність знижується суто через повтор втрачених кадрів:

1. Якщо `W ≥ 1 + 2a`:
```
U_SR = 1 / E[N] = 1 - p
```

2. Якщо `W < 1 + 2a`:
```
U_SR = (W / (1 + 2 · a)) · (1 - p)
```

**Ключовий висновок:** Ефективність Selective Repeat за достатнього розміру вікна (`W ≥ 1 + 2a`) взагалі не залежить від затримки каналу `a` і лінійно залежить від імовірності помилки: `U_SR = 1 - p`. Це абсолютний теоретичний максимум для будь-якого протоколу повторного відправлення з лінійним кодом виявлення помилок.

### 4. Алгебраїчні обмеження на розмір вікна та циклічну нумерацію

Усі протоколи зі ковзним вікном виділяють фіксовану кількість `k` бітів у заголовку кадру під номер послідовності. Це означає, що номери належать скінченному кільцю лишків `Z_M = {0, 1, 2, ..., M - 1}`, де `M = 2^k`.

Розмір вікна не може бути довільним: якщо вікно завелике, приймач не зможе розрізнити новий кадр наступного циклу нумерації від повторної передачі старого кадру попереднього циклу при втраті підтверджень.

#### Доведення для Go-Back-N: W_S ≤ M - 1

Нехай передавач використовує вікно розміру `W_S`, а приймач очікує рівно один кадр (`W_R = 1`).

Припустимо, передавач відправив кадри з номерами від `0` до `W_S - 1`. Усі кадри успішно дійшли до приймача, і приймач надіслав `ACK` на кожен із них. Поточне очікування приймача змістилося на номер:

```
Next_Expected = W_S (mod M)
```

Тепер розгляньмо найгірший випадок у каналі: **усі `W_S` підтверджень `ACK` втрачено в дорозі**.

Передавач не отримує жодного `ACK`, у нього спливає таймаут для кадру `0`, і він повторно надсилає кадр із номером `0`.

Приймач бачить надходження кадру з номером `0`. Він має однозначно зрозуміти, чи це старий кадр `0` (повтор, який треба відкинути), чи це новий кадр `0` (який передавач міг би відправити, якби отримав усі `ACK` і зсунув вікно вперед).

Новий кадр `0` міг би з'явитися лише тоді, коли `Next_Expected = 0 (mod M)`. Щоб приймач гарантовано знав, що кадр `0` — це старий дублікат, поточний очікуваний номер `Next_Expected` не повинен дорівнювати `0`:

```
W_S mod M ≠ 0
```

Оскільки передавач повинен мати змогу відправити принаймні один кадр (`W_S ≥ 1`), максимально можливий цілий розмір вікна задовольняє рівність:

```
W_S ≤ M - 1 = 2^k - 1
```

Якщо встановити `W_S = 2^k`, то `W_S mod M = 0`. Тоді при втраті всіх `ACK` передавач повторить старий кадр `0`, а приймач (який уже чекає кадр `0` наступного кола) сприйме його як абсолютно нові дані, спричинивши тихе дублювання інформації в застосунку.

#### Доведення для Selective Repeat: W_S + W_R ≤ M (типово W_S = W_R ≤ 2^(k - 1))

У Selective Repeat буфер мають обидві сторони: передавач має вікно `W_S`, приймач має вікно `W_R`.

Нехай у початковий момент вікно приймача охоплює діапазон номерів:

```
Win_RX_start = [0, 1, 2, ..., W_R - 1]
```

Передавач транслює кадри `0, 1, ..., W_S - 1`. Приймач успішно приймає всі ці кадри, буферизує їх, віддає застосунку та зсуває своє вікно вправо на `W_S` позицій. Нове вікно приймача охоплює діапазон:

```
Win_RX_new = [W_S, W_S + 1, ..., W_S + W_R - 1] (mod M)
```

Знову розгляньмо найгірший випадок: **усі `ACK` на кадри від `0` до `W_S - 1` загублено**.

Передавач не змістив своє вікно й після таймауту надсилає повтор кадру `0`.

Кадр `0` належить старому вікну передавача: `Win_TX = [0, 1, ..., W_S - 1]`. Щоб приймач не сплутав старий кадр `0` з новим допустимим кадром, номер `0` (і взагалі будь-який номер зі старого вікна `Win_TX`) не повинен потрапляти в нове вікно приймача `Win_RX_new`.

Математично це означає, що старе вікно передавача й нове вікно приймача не повинні перетинатися в кільці `Z_M`:

```
Win_TX ∩ Win_RX_new = ∅ (mod M)
```

Сумарна довжина обох неперетинних інтервалів у кільці довжиною `M` не може перевищувати сам розмір кільця `M`:

```
|Win_TX| + |Win_RX_new| ≤ M
W_S + W_R ≤ M = 2^k
```

Якщо для симетрії та рівномірності потоку обирають однаковий розмір вікна для відправника та одержувача (`W_S = W_R = W`), отримуємо канонічну нерівність:

```
2 · W ≤ 2^k
W ≤ 2^(k - 1)
```

Для 3-бітової нумерації (`k = 3`, `M = 8`):
* Для Go-Back-N максимальний розмір вікна `W_S = 8 - 1 = 7`.
* Для Selective Repeat максимальний розмір вікна `W_S = W_R = 8 / 2 = 4`.

### 5. Поведінка ARQ у каналах із пакетними помилками (Модель Гільберта-Елліотта)

У реальних бездротових каналах зв'язку (LTE, Wi-Fi, супутниковий радіозв'язок) помилки рідко виникають як незалежні події Бернуллі. Завмирання сигналу (англ. *fading*) та імпульсні перешкоди призводять до виникнення **пакетних помилок** (англ. *burst errors*), коли втрачаються кілька послідовних кадрів поспіль.

Для моделювання такого середовища використовують двозв'язний дискретний марковський ланцюг Гільберта-Елліотта з двома станами:
1. **Стан G (Good / Гарний):** канал чистий, імовірність втрати пакета `p_G ≈ 0`.
2. **Стан B (Bad / Поганий):** канал у глибокому завмиранні, імовірність втрати `p_B ≈ 1`.

Ймовірності переходів між станами позначають як `P(G → B) = α` та `P(B → G) = β`. Середня тривалість перебування каналу в поганому стані дорівнює `T_burst = 1 / β` кадрів.

Стаціонарна ймовірність того, що канал перебуває у поганому стані:

```
P_B = α / (α + β)
```

#### Вплив пакетних помилок на Go-Back-N проти Selective Repeat

* **Для Go-Back-N:** Пакетна втрата довжиною `K` кадрів (де `K < W`) призводить до скидання того самого одного вікна `W`. Якщо помилки групуються разом, Go-Back-N страждає **менше**, ніж при незалежних випадкових помилках із тією самою середньою частотою. Дві втрати, що сталися всередині однієї пачки розміром `W`, викликають лише один спільний повтор вікна замість двох окремих.
* **Для Selective Repeat:** При виникненні тривалого сплеску помилок (`K ≥ W`) буфер приймача повністю заповнюється кадрами, які надійшли після сплеску. Приймач припиняє прийом нових даних через вичерпання вікна `W_R`, виникає блокування початку черги (англ. *Head-of-Line Blocking*), і затримка доставки зростає доти, доки не буде відновлено найперший втрачений кадр пачки.

---

### Порівняння трьох протоколів: аналітична зведена таблиця

| Характеристика | Stop-and-Wait | Go-Back-N | Selective Repeat |
| :--- | :--- | :--- | :--- |
| **Ефективність `U` (без втрат, `p = 0`)** | `1 / (1 + 2a)` | `min(1, W / (1 + 2a))` | `min(1, W / (1 + 2a))` |
| **Ефективність `U` (при `W ≥ 1 + 2a, p > 0`)** | `(1 - p) / (1 + 2a)` | `(1 - p) / (1 + (W - 1) · p)` | `1 - p` |
| **Розмір вікна передавача `W_S` (для `k` біт)** | `1` | `≤ 2^k - 1` | `≤ 2^(k - 1)` |
| **Розмір вікна приймача `W_R`** | `1` | `1` (без буфера) | `W_S` (буфер обов'язковий) |
| **Чутливість до затримки `a` при `W ≥ 1 + 2a`** | Критична (`~ 1/a`) | Середня (залежить від `W · p`) | Відсутня (не залежить від `a`) |
| **Складність реалізації логіки** | Мінімальна | Низька (1 таймер) | Висока (черги, таймери на кадр) |

### Практичні розрахункові задачі

Розгляньмо три типові інженерні сценарії, які ілюструють поведінку протоколів у реальних телекомунікаційних мережах.

#### Задача 1. Трансатлантична оптоволоконна лінія зв'язку

**Вхідні дані:**
* Пропускна здатність каналу: `R = 10` Гбіт/с (`10¹⁰` біт/с).
* Затримка в один бік: `T_prop = 35` мс (`0.035` с), звідси `RTT = 70` мс.
* Розмір кадру: `L = 1500` байт (`12 000` біт).
* Імовірність спотворення пакета: `p = 0.001` (`0.1%`).

**Крок 1. Розрахунок часу передачі кадру та параметра a:**
```
T_frame = 12 000 / 10¹⁰ = 1.2 · 10⁻⁶ с = 1.2 мкс
a = T_prop / T_frame = 0.035 / (1.2 · 10⁻⁶) = 29 166.67
1 + 2 · a = 1 + 2 · 29 166.67 ≈ 58 334
```

**Крок 2. Розрахунок Stop-and-Wait:**
```
U_SW = (1 - 0.001) / 58 334 = 0.999 / 58 334 ≈ 0.00001712  (0.0017%)
S_SW = U_SW · 10 Гбіт/с ≈ 171.2 кбіт/с
```
*Висновок:* Stop-and-Wait утилізує менше двох десятитисячних відсотка гігабітного оптоволокна, перетворюючи 10-гігабітну магістраль на повільний модем 1990-х років.

**Крок 3. Розрахунок Go-Back-N та Selective Repeat (при вікні W = 60 000 кадрів, що покриває RTT):**
```
U_GBN = (1 - 0.001) / (1 + (60 000 - 1) · 0.001)   [підстановка W = 60 000, p = 0.001]
      = 0.999 / (1 + 59.999)                       [обчислення знаменника]
      = 0.999 / 60.999                             [спрощення дробу]
      ≈ 0.01638                                    [коефіцієнт утилізації 1.64%]

S_GBN = 0.01638 · 10 Гбіт/с = 163.8 Мбіт/с

U_SR = 1 - p = 1 - 0.001 = 0.999                   [ефективність Selective Repeat 99.9%]
S_SR = 0.999 · 10 Гбіт/с = 9.99 Гбіт/с
```
*Висновок:* При ймовірності втрати лише 0.1% протокол Go-Back-N втрачає понад 98% пропускної здатності, оскільки кожна одинична втрата змушує передавач пересилати 60 000 кадрів повторно. Лише Selective Repeat забезпечує роботу лінії на повній швидкості 9.99 Гбіт/с.

#### Задача 2. Геостаціонарний супутниковий канал зв'язку

**Вхідні дані:**
* Пропускна здатність: `R = 20` Мбіт/с (`2 · 10⁷` біт/с).
* Затримка в один бік: `T_prop = 270` мс (`0.27` с), `RTT = 540` мс.
* Розмір кадру: `L = 4000` байт (`32 000` біт).
* Імовірність спотворення пакета через атмосферні опади: `p = 0.02` (`2%`).

**Крок 1. Розрахунок базових параметрів:**
```
T_frame = 32 000 / (2 · 10⁷) = 1.6 · 10⁻³ с = 1.6 мс
a = 0.270 / 0.0016 = 168.75
1 + 2 · a = 1 + 2 · 168.75 = 338.5
```
Оптимальний розмір вікна `W_opt = 339` кадрів (близько 1.35 МБ пам'яті).

**Крок 2. Порівняння пропускної здатності:**
```
S_SW = ((1 - 0.02) / 338.5) · 20 Мбіт/с
     = (0.98 / 338.5) · 20 Мбіт/с                  [підстановка p = 0.02]
     ≈ 57.9 кбіт/с                                 [утилізація 0.29%]

S_GBN = (0.98 / (1 + (339 - 1) · 0.02)) · 20 Мбіт/с
      = (0.98 / (1 + 6.76)) · 20 Мбіт/с            [обчислення знаменника]
      = (0.98 / 7.76) · 20 Мбіт/с                  [спрощення дробу]
      ≈ 2.526 Мбіт/с                               [утилізація 12.6%]

S_SR = (1 - 0.02) · 20 Мбіт/с = 0.98 · 20 Мбіт/с = 19.60 Мбіт/с
```

#### Задача 3. Бездротовий промисловий зв'язок Sub-GHz (IoT)

**Вхідні дані:**
* Швидкість трансивера: `R = 100` кбіт/с (`10⁵` біт/с).
* Відстань між датчиками: `d = 300` м (`T_prop ≈ 1` мкс).
* Розмір пакета телеметрії: `L = 64` байти (`512` біт).
* Апаратний час обробки та перемикання RX/TX на мікроконтролері: `T_proc = 2` мс.
* Час передачі короткого ACK (8 байт): `T_ack = 64 / 100 000 = 0.64` мс.
* Рівень радіозавад у цеху: `p = 0.05` (`5%`).

**Крок 1. Розрахунок часу циклу:**
```
T_frame = 512 / 100 000 = 5.12 мс
T_cycle = T_frame + 2 · T_prop + T_proc + T_ack
        = 5.12 + 0.002 + 2.0 + 0.64                [підсумовування компонентів]
        = 7.762 мс                                 [загальний час циклу]
```

**Крок 2. Ефективність Stop-and-Wait:**
```
U_SW = (1 - p) · (T_frame / T_cycle)
     = (1 - 0.05) · (5.12 / 7.762)                 [підстановка значень]
     = 0.95 · 0.6596                               [проміжне множення]
     ≈ 0.6266                                      [коефіцієнт використання 62.7%]
S_SW = 0.6266 · 100 кбіт/с = 62.66 кбіт/с
```

*Висновок:* У локальних радіомережах малої дальності, де час поширення хвилі мізерний, а обсяг оперативної пам'яті мікроконтролера обмежений кілобайтами, Stop-and-Wait забезпечує понад 60% корисної утилізації каналу без витрат пам'яті на складні черги ковзного вікна.
