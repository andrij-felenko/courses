# Специфікація повідомлень та типів даних протоколу параметрів

Ця довідкова специфікація містить вичерпний технічний опис двійкових структур даних, розкладки мережевих кадрів, числових типів, автоматів станів, структур C/C++ та контрактів взаємодії для класичного та розширеного протоколів параметрів MAVLink (Parameter Protocol та Parameter Protocol Ext). Вона слугує інженерним стандартом для розробників вбудованого програмного забезпечення автопілотів (ArduPilot, PX4), наземних станцій керування (QGroundControl, Mission Planner) та бортових супутніх систем (MAVROS, MAVSDK).

### Типи даних класичного протоколу (MAV_PARAM_TYPE)

У класичному протоколі MAVLink тип кожної конфігураційної змінної визначається однобайтним числовим значенням із переліку `MAV_PARAM_TYPE`. Незалежно від заявленого типу даних, корисне значення в повідомленнях `PARAM_VALUE` та `PARAM_SET` завжди передається через уніфікований чотирибайтний контейнер `param_value` (у формальній XML-схемі повідомлень має базовий двійковий тип `float`).

Якщо параметр зберігає ціле число або бітову маску, двійкові байти значення записуються в пам'ять поля `param_value` без будь-яких математичних обчислень — шляхом побітового відображення (bit-cast). Для типів меншої розрядності, ніж 32 біти, корисні байти розміщуються у молодших розрядах чотирибайтового контейнера, а старші байти заповнюються нулями (для знакових типів виконується коректне знакове розширення до 32 бітів).

| Числовий код | Назва типу в переліку | Розмірність у пам'яті | Опис двійкового формату та правило упакування |
| :--- | :--- | :--- | :--- |
| `1` | `MAV_PARAM_TYPE_UINT8` | 1 байт (8 бітів) | Беззнакове 8-бітне ціле число (діапазон 0..255). Займає молодший байт контейнера `param_value`, байти 1..3 містять нулі. |
| `2` | `MAV_PARAM_TYPE_INT8` | 1 байт (8 бітів) | Знакове 8-бітне ціле число (діапазон −128..127). Виконується знакове розширення до 32 бітів перед копіюванням у контейнер. |
| `3` | `MAV_PARAM_TYPE_UINT16` | 2 байти (16 бітів) | Беззнакове 16-бітне ціле число (діапазон 0..65535). Порядок байтів little-endian, байти 2..3 містять нулі. |
| `4` | `MAV_PARAM_TYPE_INT16` | 2 байти (16 бітів) | Знакове 16-бітне ціле число (діапазон −32768..32767). Знакове розширення до 32 бітів у форматі доповняльного коду. |
| `5` | `MAV_PARAM_TYPE_UINT32` | 4 байти (32 біти) | Беззнакове 32-бітне ціле число або бітова маска конфігурації (0..4294967295). Побітове відображення 1:1. |
| `6` | `MAV_PARAM_TYPE_INT32` | 4 байти (32 біти) | Знакове 32-бітне ціле число (−2147483648..2147483647). Побітове відображення 1:1. |
| `7` | `MAV_PARAM_TYPE_UINT64` | 8 байтів (64 біти) | Зарезервовано. **Не підтримується** класичним протоколом через жорсткий 4-байтний ліміт поля `param_value`. |
| `8` | `MAV_PARAM_TYPE_INT64` | 8 байтів (64 біти) | Зарезервовано. **Не підтримується** класичним протоколом через жорсткий 4-байтний ліміт поля `param_value`. |
| `9` | `MAV_PARAM_TYPE_REAL32` | 4 байти (32 біти) | Число з рухомою комою одинарної точності за стандартом IEEE 754. Передається в поле `param_value` напряму. |
| `10` | `MAV_PARAM_TYPE_REAL64` | 8 байтів (64 біти) | Зарезервовано. **Не підтримується** класичним протоколом через ліміт 4 байти. |

### Структури повідомлень класичного протоколу

Нижче наведено двійкову розкладку корисного навантаження (payload) для чотирьох базових повідомлень класичного протоколу параметрів. Усі багатобайтні числові поля передаються у порядку від молодшого до старшого байта (little-endian). Загальне вирівнювання полів усередині кадру формується генератором коду MAVLink за спаданням розміру типів для запобігання неявному паддингу процесора.

#### 1. PARAM_REQUEST_LIST (Message ID: 21, 0x15)

Повідомлення надсилається наземною станцією керування або бортовим комп'ютером для ініціалізації вичитування повної таблиці параметрів цільового автопілота чи підсистеми.

```
Структура PARAM_REQUEST_LIST (Розмір корисного навантаження: 2 байти)
┌────────────────────────┬────────────────────────┐
│ target_system (uint8)  │ target_component(uint8)│
│ Байт 0                 │ Байт 1                 │
└────────────────────────┴────────────────────────┘
```

* **`target_system`** (тип `uint8_t`, зміщення 0, розмір 1 байт) — числовий ідентифікатор цільового апарата (System ID). Типове значення для одного дрона — `1`. Значення `0` розцінюється як широкомовне звернення до всіх доступних систем на шині зв'язку.
* **`target_component`** (тип `uint8_t`, зміщення 1, розмір 1 байт) — ідентифікатор цільового вузла всередині системи (Component ID). Типове значення для головного автопілота — `MAV_COMP_ID_AUTOPILOT1` (`1`). Якщо запит адресовано камері, підвісу або системі супутникової навігації, вказується відповідний `Component ID` (наприклад, `MAV_COMP_ID_CAMERA` = `100` або `MAV_COMP_ID_GIMBAL` = `154`).

#### 2. PARAM_REQUEST_READ (Message ID: 20, 0x14)

Повідомлення використовується для точкового вичитування конкретного параметра: або за його порядковим номером (індексом у внутрішній таблиці), або за текстовим іменем (символьною назвою).

```
Структура PARAM_REQUEST_READ (Розмір корисного навантаження: 20 байтів)
┌─────────────────────────┬────────────────────────┬────────────────────────┐
│ param_index (int16)     │ target_system (uint8)  │ target_component(uint8)│
│ Байти 0..1 (little-end) │ Байт 2                 │ Байт 3                 │
├─────────────────────────┴────────────────────────┴────────────────────────┤
│ param_id (масив char[16])                                                 │
│ Байти 4..19 (ASCII-символи, без обов'язкового кінцевого нуля)             │
└───────────────────────────────────────────────────────────────────────────┘
```

* **`param_index`** (тип `int16_t`, зміщення 0, розмір 2 байти) — порядковий номер параметра в пам'яті (діапазон `0..param_count-1`).
  * **Режим запиту за індексом:** поле `param_index` містить число від `0` до `N-1`. Поле `param_id` заповнюється нульовими байтами або містить порожній рядок (`param_id[0] = '\0'`). Автопілот ігнорує поле `param_id` і повертає параметр за вказаним числовим зміщенням.
  * **Режим запиту за назвою:** поле `param_index` встановлюється у значення `-1`. Поле `param_id` містить точну назву параметра в кодуванні ASCII. Автопілот виконує пошук у своїй таблиці символьних імен.
* **`target_system`** (тип `uint8_t`, зміщення 2, розмір 1 байт) — адреса цільової системи.
* **`target_component`** (тип `uint8_t`, зміщення 3, розмір 1 байт) — адреса цільового компонента.
* **`param_id`** (тип `char[16]`, зміщення 4, розмір 16 байтів) — символьний ідентифікатор параметра. Якщо довжина рядка менша 16 символів, рядок обов'язково завершується нульовим байтом `\0`. Якщо довжина рядка становить рівно 16 символів, нульовий термінатор у масиві відсутній.

#### 3. PARAM_VALUE (Message ID: 22, 0x16)

Головне інформаційне повідомлення протоколу. Транслюється автопілотом у відповідь на `PARAM_REQUEST_LIST` та `PARAM_REQUEST_READ`, а також після будь-якої зміни конфігурації через `PARAM_SET` чи внутрішню системну подію.

```
Структура PARAM_VALUE (Розмір корисного навантаження: 25 байтів)
┌───────────────────────────────────────────────────────────────────────────┐
│ param_value (float, 4 байти, зміщення 0..3) — значення або bit-cast       │
├────────────────────────────────────────┬──────────────────────────────────┤
│ param_count (uint16, 2 байти, зм. 4..5)│ param_index (uint16, 2 B, 6..7)  │
├────────────────────────────────────────┴──────────────────────────────────┤
│ param_id (char[16], 16 байтів, зміщення 8..23)                            │
├───────────────────────────────────────────────────────────────────────────┤
│ param_type (uint8, 1 байт, зміщення 24) — значення з переліку MAV_PARAM   │
└───────────────────────────────────────────────────────────────────────────┘
```

* **`param_value`** (тип `float`, зміщення 0, розмір 4 байти) — контейнер збереженого значення. Інтерпретується залежно від поля `param_type`.
* **`param_count`** (тип `uint16_t`, зміщення 4, розмір 2 байти) — загальна кількість доступних параметрів у системі.
* **`param_index`** (тип `uint16_t`, зміщення 6, розмір 2 байти) — числовий індекс поточного параметра (починається з `0`). Якщо повідомлення надсилається автопілотом спонтанно (внаслідок зміни конфігурації з пульта або внутрішнього скрипту) поза контекстом вичитування списку, автопілот має право передати у цьому полі значення `65535` (`UINT16_MAX`), позначаючи, що індекс не визначено.
* **`param_id`** (тип `char[16]`, зміщення 8, розмір 16 байтів) — текстова назва параметра.
* **`param_type`** (тип `uint8_t`, зміщення 24, розмір 1 байт) — числовий тип конфігураційної змінної з переліку `MAV_PARAM_TYPE`.

#### 4. PARAM_SET (Message ID: 23, 0x17)

Повідомлення надсилається клієнтом для запису нового значення конфігураційної змінної в оперативну пам'ять автопілота.

```
Структура PARAM_SET (Розмір корисного навантаження: 23 байти)
┌───────────────────────────────────────────────────────────────────────────┐
│ param_value (float, 4 байти, зміщення 0..3) — нове значення / bit-cast    │
├────────────────────────┬────────────────────────┬─────────────────────────┤
│ target_system (uint8)  │ target_component(uint8)│ param_type (uint8)      │
│ Байт 4                 │ Байт 5                 │ Байт 22                 │
├────────────────────────┴────────────────────────┴─────────────────────────┤
│ param_id (char[16], 16 байтів, зміщення 6..21)                            │
└───────────────────────────────────────────────────────────────────────────┘
```

* **`param_value`** (тип `float`, зміщення 0, розмір 4 байти) — нове значення конфігураційної змінної, запаковане шляхом побітового копіювання відповідно до зазначеного типу.
* **`target_system`** (тип `uint8_t`, зміщення 4, розмір 1 байт) — System ID цільового апарата.
* **`target_component`** (тип `uint8_t`, зміщення 5, розмір 1 байт) — Component ID цільового модуля.
* **`param_id`** (тип `char[16]`, зміщення 6, розмір 16 байтів) — символьний ідентифікатор змінної, яку необхідно модифікувати.
* **`param_type`** (тип `uint8_t`, зміщення 22, розмір 1 байт) — тип даних параметра із переліку `MAV_PARAM_TYPE`. Автопілот зобов'язаний перевірити збіг переданого типу з внутрішнім типом змінної; у разі невідповідності транзакція відхиляється.

### Структури C та C++ для роботи з параметрами

Для безпечної роботи з полями повідомлень у вбудованому та системному коді застосовуються строго типізовані об'єднання (union) та контейнери.

:::tabs
```c
#include <stdint.h>
#include <string.h>
#include <stdbool.h>

// Уніфікований двійковий контейнер для пакування значень у 4 байти
typedef union {
    float    f32;
    uint32_t u32;
    int32_t  i32;
    uint16_t u16;
    int16_t  i16;
    uint8_t  u8;
    int8_t   i8;
    uint8_t  raw_bytes[4];
} mav_param_union_t;

// Безпечне читання param_id у буфер розміром 17 байтів
void extract_param_id(const char wire_id[16], char out_buf[17]) {
    memcpy(out_buf, wire_id, 16);
    out_buf[16] = '\0';
}

// Запис значення цілого числа в контейнер PARAM_SET / PARAM_VALUE
float pack_uint32_value(uint32_t val) {
    mav_param_union_t u;
    u.u32 = val;
    return u.f32;
}

// Вилучення 32-бітного цілого числа без втрати мантиси
uint32_t unpack_uint32_value(float wire_float) {
    mav_param_union_t u;
    u.f32 = wire_float;
    return u.u32;
}
```
```cpp
#include <cstdint>
#include <cstring>
#include <string>
#include <string_view>
#include <array>
#include <variant>
#include <bit>

// Типобезпечне представлення значення параметра в C++20
using ParamValueVariant = std::variant<
    uint8_t, int8_t, uint16_t, int16_t, uint32_t, int32_t, float
>;

// Безпечне перетворення сирого масиву param_id у string_view
std::string_view extract_param_id_view(const std::array<char, 16>& wire_id) noexcept {
    const size_t len = strnlen(wire_id.data(), 16);
    return std::string_view(wire_id.data(), len);
}

// Упаковка варіанта у 32-бітний float-контейнер через bit_cast
float pack_param_variant(const ParamValueVariant& val) noexcept {
    return std::visit([](auto&& arg) -> float {
        using T = std::decay_t<decltype(arg)>;
        if constexpr (std::is_same_v<T, float>) {
            return arg;
        } else if constexpr (sizeof(T) == 4) {
            return std::bit_cast<float>(arg);
        } else if constexpr (sizeof(T) < 4) {
            uint32_t container = 0;
            if constexpr (std::is_signed_v<T>) {
                const auto extended = static_cast<int32_t>(arg);
                container = std::bit_cast<uint32_t>(extended);
            } else {
                container = static_cast<uint32_t>(arg);
            }
            return std::bit_cast<float>(container);
        } else {
            return 0.0f;
        }
    }, val);
}
```

### Розширений протокол параметрів (Parameter Protocol Ext)

Розширений протокол параметрів усуває апаратні обмеження класичної схеми: підтримує 64-бітні цілі числа, дійсні числа подвійної точності (double), довільні двійкові масиви до 128 байтів та додає обов'язкове явне квитування транзакцій запису через повідомлення `PARAM_EXT_ACK`.

#### Типи даних розширеного протоколу (MAV_PARAM_EXT_TYPE)

| Числовий код | Назва типу в переліку | Розмірність | Опис двійкового формату |
| :--- | :--- | :--- | :--- |
| `1` | `MAV_PARAM_EXT_TYPE_UINT8` | 1 байт | Беззнакове 8-бітне ціле число. |
| `2` | `MAV_PARAM_EXT_TYPE_INT8` | 1 байт | Знакове 8-бітне ціле число. |
| `3` | `MAV_PARAM_EXT_TYPE_UINT16` | 2 байти | Беззнакове 16-бітне ціле число (little-endian). |
| `4` | `MAV_PARAM_EXT_TYPE_INT16` | 2 байти | Знакове 16-бітне ціле число (little-endian). |
| `5` | `MAV_PARAM_EXT_TYPE_UINT32` | 4 байти | Беззнакове 32-бітне ціле число (little-endian). |
| `6` | `MAV_PARAM_EXT_TYPE_INT32` | 4 байти | Знакове 32-бітне ціле число (little-endian). |
| `7` | `MAV_PARAM_EXT_TYPE_UINT64` | 8 байтів | Беззнакове 64-бітне ціле число (little-endian). |
| `8` | `MAV_PARAM_EXT_TYPE_INT64` | 8 байтів | Знакове 64-бітне ціле число (little-endian). |
| `9` | `MAV_PARAM_EXT_TYPE_REAL32` | 4 байти | Дійсне число одинарної точності IEEE 754 (float). |
| `10` | `MAV_PARAM_EXT_TYPE_REAL64` | 8 байтів | Дійсне число подвійної точності IEEE 754 (double). |
| `11` | `MAV_PARAM_EXT_TYPE_CUSTOM` | до 128 байтів | Довільний двійковий буфер (ключі шифрування, рядкові конфігурації, сертифікати). |

#### Специфікація повідомлень розширеного протоколу

1. **PARAM_EXT_REQUEST_LIST (Message ID: 321, 0x141, Payload: 2 байти)**
   * `target_system` (`uint8_t`, зміщення 0, 1 байт);
   * `target_component` (`uint8_t`, зміщення 1, 1 байт).

2. **PARAM_EXT_REQUEST_READ (Message ID: 320, 0x140, Payload: 20 байтів)**
   * `param_index` (`int16_t`, зміщення 0, 2 байти) — порядковий номер параметра або `-1` при читанні за назвою;
   * `target_system` (`uint8_t`, зміщення 2, 1 байт);
   * `target_component` (`uint8_t`, зміщення 3, 1 байт);
   * `param_id` (`char[16]`, зміщення 4, 16 байтів) — текстова назва параметра.

3. **PARAM_EXT_VALUE (Message ID: 322, 0x142, Payload: 149 байтів)**
   * `param_count` (`uint16_t`, зміщення 0, 2 байти) — загальна кількість доступних параметрів;
   * `param_index` (`uint16_t`, зміщення 2, 2 байти) — порядковий індекс поточного параметра;
   * `param_id` (`char[16]`, зміщення 4, 16 байтів) — символьний ідентифікатор;
   * `param_value` (`char[128]`, зміщення 20, 128 байтів) — корисне двійкове навантаження;
   * `param_type` (`uint8_t`, зміщення 148, 1 байт) — тип із переліку `MAV_PARAM_EXT_TYPE`.

4. **PARAM_EXT_SET (Message ID: 323, 0x143, Payload: 147 байтів)**
   * `target_system` (`uint8_t`, зміщення 0, 1 байт);
   * `target_component` (`uint8_t`, зміщення 1, 1 байт);
   * `param_id` (`char[16]`, зміщення 2, 16 байтів) — назва параметра;
   * `param_value` (`char[128]`, зміщення 18, 128 байтів) — нове двійкове значення;
   * `param_type` (`uint8_t`, зміщення 146, 1 байт) — тип із переліку `MAV_PARAM_EXT_TYPE`.

5. **PARAM_EXT_ACK (Message ID: 324, 0x144, Payload: 146 байтів)**
   Повідомлення обов'язково транслюється автопілотом у відповідь на отримання кадру `PARAM_EXT_SET`.
   * `param_id` (`char[16]`, зміщення 0, 16 байтів) — ідентифікатор параметра;
   * `param_value` (`char[128]`, зміщення 16, 128 байтів) — фактичне підтверджене значення в пам'яті автопілота після валідації та застосування меж;
   * `param_type` (`uint8_t`, зміщення 144, 1 байт) — тип параметра;
   * `param_result` (`uint8_t`, зміщення 145, 1 байт) — результат обробки транзакції з переліку `PARAM_ACK`.

#### Перелік статусів квитування (PARAM_ACK)

| Числовий код | Константа переліку | Опис результату операції запису |
| :--- | :--- | :--- |
| `0` | `PARAM_ACK_ACCEPTED` | Зміну прийнято. Значення успішно перевірено та збережено в робочій конфігурації. |
| `1` | `PARAM_ACK_VALUE_UNSUPPORTED` | Запропоноване значення неприпустиме (виходить за межі min/max або порушує залежності конфігурації). |
| `2` | `PARAM_ACK_FAILED` | Помилка виконання операції (наприклад, спроба запису калібрувальних параметрів під час активного польоту чи збій флеш-пам'яті). |
| `3` | `PARAM_ACK_IN_PROGRESS` | Операція триває в асинхронному режимі (наприклад, триває перезапис енергонезалежного сектора EEPROM/Flash). |

### Ідентифікатори компонентів та маршрутизація

Параметри MAVLink можуть належати не лише центральному автопілоту, а й іншим автономним підсистемам апарата. Під час відправлення повідомлень `PARAM_REQUEST_LIST`, `PARAM_REQUEST_READ` та `PARAM_SET` поле `target_component` визначає адресата:

* **`MAV_COMP_ID_AUTOPILOT1` (1):** Основний польотний контролер (ArduPilot / PX4). Зберігає коефіцієнти навігації, калібрування сенсорів, режими керування.
* **`MAV_COMP_ID_CAMERA` (100) та `MAV_COMP_ID_CAMERA2` (101):** Бортові корисні навантаження фото/відеозйомки (витримка, ISO, режим запису, фокус).
* **`MAV_COMP_ID_GIMBAL` (154):** Стабілізований трьохосьовий підвіс камери (коефіцієнти стабілізації, кутові швидкості, нейтральні положення).
* **`MAV_COMP_ID_ONBOARD_COMPUTER` (191):** Бортовий супутній комп'ютер (Companion Computer). Зберігає налаштування алгоритмів комп'ютерного зору (VIO, SLAM) та мережевих інтерфейсів.
* **`MAV_COMP_ID_OBSTACLE_AVOIDANCE` (196):** Лідари та радари системи запобігання зіткненням.

Кожен компонент веде власну незалежну таблицю параметрів із нумерацією `param_index` від `0` до власного `param_count-1`. Клієнтський додаток зобов'язаний створювати окремі екземпляри автомата синхронізації для кожного унікального `Component ID`.

### Обрізання кінцевих нулів (Zero-Trimming) у MAVLink v2

У протоколі MAVLink v2 впроваджено оптимізацію пропускної здатності — обрізання кінцевих нулів (**Zero-Trimming**). Якщо корисне навантаження повідомлення містить байти `0x00` наприкінці буфера, вони відтинаються перед відправленням у фізичний канал, а поле `len` у заголовку кадру зменшується відповідно до довжини залишкових значущих даних.

Для повідомлення `PARAM_VALUE` це створює специфічний крайовий випадок. Поле `param_type` розташоване за зміщенням 24 (останній байт корисного навантаження). Якщо `param_type` дорівнює ненульовому значенню (наприклад, `9` для `REAL32`), байти поля `param_id` (зміщення 8..23), навіть якщо вони містять нулі, не обрізаються, оскільки за ними йде значущий байт `param_type`.

Однак у розширеному повідомленні `PARAM_EXT_VALUE` масив `param_value[128]` розташований за зміщенням 20..147, а `param_type` — за зміщенням 148. Якщо клієнт надсилає короткий 8-бітний параметр `UINT8`, значення якого `0`, а `param_type` також нульовий, весь хвіст кадру може бути обрізаний. Приймач MAVLink v2 зобов'язаний перед парсингом виділити повний буфер максимального розміру повідомлення, ініціалізувати його нулями `memset(buf, 0, sizeof(msg))`, і скопіювати отримані байти `memcpy(buf, wire_payload, rx_len)`.

### Контроль цілісності конфігурації: Param Hash / CRC

Для скорочення часу підключення наземна станція може не завантажувати 2000+ параметрів щоразу через радіолінію, а використати локальний кеш параметрів, якщо автопілот підтвердить незмінність своєї таблиці через контрольний хеш (Param Hash / CRC).

1. **Розрахунок Param Hash:** Автопілот сортує всі конфігураційні змінні за алфавітом імені `param_id`. Далі послідовно обчислюється контрольна сума (CRC32 або FNV-1a) над двійковим потоком пар `(param_id, param_value)`.
2. **Перевірка хешу в GCS:** Під час першого контакту станція зчитує прапорець `MAV_PROTOCOL_CAPABILITY_PARAM_UNION` з кадру `AUTOPILOT_VERSION` або отримує хеш метаданих за протоколом Component Information Protocol.
3. **Валідація кешу:** Якщо отриманий хеш збігається з хешем попередньої сесії, станція миттєво ініціалізує дерево налаштувань із локального диску, заощаджуючи до 30 секунд часу передпольотної підготовки.

### Збереження конфігурації в енергонезалежній пам'яті (Flash/EEPROM)

Зміна параметра через `PARAM_SET` модифікує значення змінної в оперативній пам'яті автопілота (RAM). Залежно від архітектури прошивки, збереження в постійну пам'ять (Flash або EEPROM) відбувається за двома сценаріями:

1. **Автоматичне відкладене збереження (ArduPilot / PX4 за замовчуванням):** автопілот планує фоновий запис секторів пам'яті через 1–3 секунди після останньої модифікації.
2. **Явне збереження через команду `MAV_CMD_PREFLIGHT_STORAGE` (Message ID: 246):** клієнт надсилає повідомлення `COMMAND_LONG` із зазначенням параметрів операції.

```
Параметри команди MAV_CMD_PREFLIGHT_STORAGE:
  param1: Дія над пам'яттю
          0 = Читання параметрів із Flash/EEPROM в оперативну пам'ять (перезавантаження конфігурації)
          1 = Запис поточної конфігурації з RAM у Flash/EEPROM (збереження)
          2 = Скидання конфігурації до заводських налаштувань за замовчуванням
  param2: Область пам'яті (0 = Параметри, 1 = Польотні місії)
  param3..param7: 0 (не використовуються)
```

Автопілот підтверджує результат операції збереження повідомленням `COMMAND_ACK`. У разі успішного запису повертається статус `MAV_RESULT_ACCEPTED` (0). Якщо запис заблоковано (наприклад, апарат перебуває в режимі `ARMED`), повертається статус `MAV_RESULT_DENIED` (2).

### Специфікація метаданих параметрів (Component Information Protocol)

Для відображення параметрів людинозрозумілим способом наземні станції використовують метадані, отримані за протоколом Component Information Protocol у форматі стисненого JSON/XML файлу. Метадані не передаються в кожному двійковому повідомленні `PARAM_VALUE`, а кешуються окремо.

```json
{
  "version": 1,
  "parameters": [
    {
      "name": "MPC_XY_VEL_MAX",
      "type": "Float",
      "default": 12.0,
      "min": 0.5,
      "max": 20.0,
      "decimalPlaces": 1,
      "units": "m/s",
      "shortDesc": "Maximum horizontal velocity in mission and position control",
      "longDesc": "Limits the maximum horizontal ground speed commanded by position controller.",
      "rebootRequired": false
    },
    {
      "name": "SYS_AUTOSTART",
      "type": "Int32",
      "default": 0,
      "min": 0,
      "max": 50000,
      "shortDesc": "Airframe configuration ID",
      "rebootRequired": true
    }
  ]
}
```

* **`name`** (рядок): точний збіг із полем `param_id` (до 16 символів).
* **`type`** (рядок): тип даних (`Uint8`, `Int8`, `Uint16`, `Int16`, `Uint32`, `Int32`, `Float`).
* **`default`** (число): заводське значення за замовчуванням для функції скидання налаштувань.
* **`min` / `max`** (числа): апаратні та програмні межі валідації.
* **`units`** (рядок): фізичні одиниці вимірювання (`m/s`, `rad/s`, `deg`, `mAh`, `V`, `us`).
* **`bitmask`** (словник): бітові назви для параметрів-масок (наприклад, прапорці сенсорів або режимів аварійного захисту).
* **`rebootRequired`** (булеве): вказує, чи вимагає зміна параметра повного перезавантаження системи для набуття чинності.

### Часові константи та мережеві контракти

1. **Міжпакетна затримка автопілота (`Autopilot Burst Pacing`):** 5–15 мс між сусідніми кадрами `PARAM_VALUE`. Необхідна для запобігання переповненню передавального буфера апаратного UART та черги радіомодема.
2. **Тайм-аут початку вичитування списку (`List Response Timeout`):** 1000 мс після надсилання `PARAM_REQUEST_LIST`.
3. **Тайм-аут переривання пакетного потоку (`Stream Silence Timeout`):** 500 мс після надходження останнього кадру під час отримання списку.
4. **Тайм-аут точкового запиту індексу (`Index Read Timeout`):** 800 мс на кожну транзакцію `PARAM_REQUEST_READ`.
5. **Максимальна кількість повторів для одного індексу (`Max Index Retries`):** 5 спроб перед визнанням помилки синхронізації.
6. **Тайм-аут квитування операції запису (`Set Ack Timeout`):** 1000 мс після відправлення кадру `PARAM_SET`.
7. **Максимальна кількість спроб запису (`Max Set Retries`):** 3 повторні спроби передачі `PARAM_SET` при відсутності відповіді `PARAM_VALUE`.
