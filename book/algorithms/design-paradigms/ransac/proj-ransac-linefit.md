# ⚙️ Проєкт: підгоняч прямої, що не боїться викидів

<preknowlist>
- [Найменші квадрати](book:math/least-squares) — спосіб провести модель крізь дані так, щоб сума квадратів відхилень була найменшою; наприкінці ми уточнюємо ним переможну пряму, але вже по самих згодних точках.
- [Імовірність як міра непевності](book:math/probability-basics) — шанс події та як перемножуються шанси незалежних спроб; на цьому тримається міркування «скільки випадкових вибірок узяти».
</preknowlist>

Чотири кроки RANSAC вкладаються в чотири рядки, і саме тому підгоняч прямої здається вправою на пів години. Він і пишеться за пів години. Далі починається цікаве: пряма виходить трохи не та, на крутих даних метод чомусь мовчки програє, а на двох однакових точках програма або падає, або тихо бреше — і жодної з цих бід не видно з опису алгоритму.

Тут ми зберемо підгоняч цілком і проженемо його на конкретних числах, друкуючи згоду кожної спроби. Усе, що нижче, — справжній вивід справжнього коду на тих самих дванадцяти точках; жодне число не вигадане. Дорогою з'ясується, що найнебезпечніша вибірка — та, у якій **обидві точки чесні**.

## Що на столі

Дванадцять точок. Дев'ять лягли вздовж прямої `y = 0.5·x + 1` із дрібним шумом, три підкинуто збоку.

```
чесні (індекси 0–8):
  (0, 1.05)  (1, 1.42)  (2, 2.10)  (3, 2.42)  (4, 3.08)
  (5, 3.44)  (6, 4.13)  (7, 4.39)  (8, 5.06)

викиди (індекси 9–11):
  (2, 5.60)  (5, 0.40)  (7, 1.20)
```

Перш ніж писати код, гляньмо на дані чесно — інакше поріг згоди доведеться вгадувати. Перпендикулярні відстані чесних точок від істинної прямої:

```
0.045  0.072  0.089  0.072  0.072  0.054  0.116  0.098  0.054

макс = 0.116        ско (σ) = 0.078
```

А викиди відстоять на `3.22`, `2.77` і `2.95` — у 36–41 раз далі за типове відхилення чесної точки. Розрив велетенський, і саме він дає нам простір для порога: будь-яке `t` між `0.12` і `2.7` розділить ці дві купи. Візьмемо `t = 0.25` — це приблизно `3.2·σ`, тобто «чесна точка майже напевно всередині, викид не має шансу».

На виході потрібні **дві** речі, і друга важить не менше за першу: сама пряма — і список точок, які за неї проголосували. Без другого списку немає чим уточнювати, а без уточнення пряма лишиться такою, якою її задали дві випадкові точки.

## Пряма, яка не ділиться на нуль

Перше рішення визначає долю всієї програми. Пряму можна записати як `y = k·x + b` — звично зі школи й катастрофічно для нас. Вертикальна пряма має `k = ∞`; а відстань, яку дає такий запис, — це відстань **по вертикалі**, не найкоротша. Обидві біди ми зараз побачимо в живому прогоні, тож візьмімо запис, у якого їх немає:

```
a·x + b·y + c = 0        за умови  a² + b² = 1
```

Пара `(a, b)` — це одиничний вектор **нормалі** до прямої, а `c` — зсув. Умова `a² + b² = 1` перетворює вираз `|a·x + b·y + c|` рівно на **найкоротшу відстань** від точки `(x, y)` до прямої. Вертикаль тут — звичайнісінький випадок `b = 0`, без жодних нескінченностей.

Тепер проведімо таку пряму крізь дві точки `p` і `q`. Напрямок уздовж прямої — це `(Δx, Δy) = (q.x − p.x, q.y − p.y)`, отже нормаль до неї — повернутий на прямий кут вектор `(Δy, −Δx)`:

```
a = q.y − p.y                    (це Δy)
b = p.x − q.x                    (це −Δx)
n = √(a² + b²) = √(Δy² + Δx²)
```

Придивіться до `n`. Це не якийсь службовий дільник — це рівно **відстань між p і q**. Довжина нормалі до нормування збігається з довжиною відрізка, на якому ми будуємо пряму. Дрібничка, яка виявиться подарунком: величина, потрібна для нормування, і величина, за якою ми судитимемо про якість вибірки, — одне й те саме число, обчислене один раз. Назвімо його **базою вибірки**.

Поділивши `a` і `b` на `n`, дістаємо нормовані коефіцієнти, а `c` знаходимо з умови, що точка `p` лежить на прямій: `c = −(a·p.x + b·p.y)`.

## Повний код

Чотири функції: побудувати пряму по двох точках, полічити згоду, зібрати згодних, уточнити. І цикл, що їх складає.

Дві дрібниці в коді варті окремого погляду. По-перше, у циклі ми згоду лише **лічимо**, а список згодних матеріалізуємо один-єдиний раз — для переможця: інакше кожна вдала спроба дарма виділяла б пам'ять під масив, який за мить викинуть. По-друге, другий індекс беремо з діапазону на одиницю коротшого й посуваємо на один, якщо він наздогнав перший, — так `j` рівномірно пробігає всі значення, крім `i`, без циклу відкидання й без ризику зациклитися.

```python
import math
import random


def line_through(p, q, min_base):
    """Пряма a·x + b·y + c = 0 крізь дві точки, нормована: a² + b² = 1.
    Повертає None, якщо вибірка вироджена (точки надто близько)."""
    a = q[1] - p[1]                       # Δy
    b = p[0] - q[0]                       # −Δx
    n = math.hypot(a, b)                  # = відстань між p і q, тобто база вибірки
    if n < min_base:
        return None                       # ділити на це не можна — та й не варто
    a, b = a / n, b / n
    return a, b, -(a * p[0] + b * p[1])


def count_inliers(model, pts, t):
    """Скільки точок лежать до моделі ближче за поріг t."""
    a, b, c = model
    return sum(1 for x, y in pts if abs(a * x + b * y + c) <= t)


def collect_inliers(model, pts, t):
    a, b, c = model
    return [(x, y) for x, y in pts if abs(a * x + b * y + c) <= t]


def refine(pts):
    """Тотальні найменші квадрати: пряма крізь центроїд уздовж головної осі хмари.
    Мінімізує суму квадратів ПЕРПЕНДИКУЛЯРНИХ відхилень — ту саму міру, якою
    міряла згода. Вертикальних прямих не боїться."""
    m = len(pts)
    xm = sum(x for x, _ in pts) / m
    ym = sum(y for _, y in pts) / m
    sxx = sum((x - xm) ** 2 for x, _ in pts)
    syy = sum((y - ym) ** 2 for _, y in pts)
    sxy = sum((x - xm) * (y - ym) for x, y in pts)
    th = 0.5 * math.atan2(2 * sxy, sxx - syy)   # напрямок головної осі
    a, b = -math.sin(th), math.cos(th)          # нормаль до неї — вже одинична
    return a, b, -(a * xm + b * ym)


def ransac_line(pts, t, k, min_base, rng):
    """Повертає (уточнена модель, згодні точки) або (None, [])."""
    m = len(pts)
    if m < 2:
        return None, []
    best, best_count = None, 0
    for _ in range(k):
        i = rng.randrange(m)                    # 1. мінімальна вибірка — 2 точки
        j = rng.randrange(m - 1)
        if j >= i:
            j += 1                              # рівномірно серед усіх, крім i
        model = line_through(pts[i], pts[j], min_base)   # 2. модель по вибірці
        if model is None:
            continue                            # вироджена вибірка — спроба намарне
        cnt = count_inliers(model, pts, t)      # 3. згода: у циклі тільки лічимо
        if cnt > best_count:                    # 4. новий рекорд
            best, best_count = model, cnt
    if best is None:
        return None, []
    inliers = collect_inliers(best, pts, t)     # список — один раз, для переможця
    return refine(inliers), inliers             # уточнення ТІЛЬКИ по згодних
```
```cpp
#include <cmath>
#include <optional>
#include <random>
#include <vector>

struct Pt { double x, y; };
struct Line { double a, b, c; };        // a·x + b·y + c = 0, причому a² + b² = 1

// Пряма крізь дві точки. nullopt — вибірка вироджена.
std::optional<Line> line_through(Pt p, Pt q, double min_base) {
    double a = q.y - p.y;               // Δy
    double b = p.x - q.x;               // −Δx
    const double n = std::hypot(a, b);  // = відстань між p і q, тобто база вибірки
    if (n < min_base) return std::nullopt;
    a /= n; b /= n;
    return Line{a, b, -(a * p.x + b * p.y)};
}

int count_inliers(const Line& L, const std::vector<Pt>& pts, double t) {
    int n = 0;
    for (const Pt& p : pts)
        if (std::fabs(L.a * p.x + L.b * p.y + L.c) <= t) ++n;
    return n;
}

std::vector<Pt> collect_inliers(const Line& L, const std::vector<Pt>& pts, double t) {
    std::vector<Pt> in;
    for (const Pt& p : pts)
        if (std::fabs(L.a * p.x + L.b * p.y + L.c) <= t) in.push_back(p);
    return in;
}

// Тотальні найменші квадрати: пряма крізь центроїд уздовж головної осі хмари.
// Мінімізує суму квадратів ПЕРПЕНДИКУЛЯРНИХ відхилень — ту саму міру, якою
// міряла згода. Вертикальних прямих не боїться.
Line refine(const std::vector<Pt>& pts) {
    const double m = static_cast<double>(pts.size());
    double xm = 0.0, ym = 0.0;
    for (const Pt& p : pts) { xm += p.x; ym += p.y; }
    xm /= m; ym /= m;
    double sxx = 0.0, syy = 0.0, sxy = 0.0;
    for (const Pt& p : pts) {
        const double dx = p.x - xm, dy = p.y - ym;
        sxx += dx * dx; syy += dy * dy; sxy += dx * dy;
    }
    const double th = 0.5 * std::atan2(2.0 * sxy, sxx - syy);  // головна вісь
    const double a = -std::sin(th), b = std::cos(th);          // нормаль, одинична
    return Line{a, b, -(a * xm + b * ym)};
}

// Повертає згодні точки; уточнену модель кладе в out.
std::vector<Pt> ransac_line(const std::vector<Pt>& pts, double t, int k,
                            double min_base, std::mt19937& rng, Line& out) {
    const int m = static_cast<int>(pts.size());
    if (m < 2) return {};
    std::uniform_int_distribution<int> pick_i(0, m - 1), pick_j(0, m - 2);
    std::optional<Line> best;
    int best_count = 0;
    for (int it = 0; it < k; ++it) {
        const int i = pick_i(rng);                  // 1. мінімальна вибірка
        int j = pick_j(rng);
        if (j >= i) ++j;                            // рівномірно серед усіх, крім i
        const auto model = line_through(pts[i], pts[j], min_base);   // 2. модель
        if (!model) continue;                       // вироджена — спроба намарне
        const int cnt = count_inliers(*model, pts, t);   // 3. згода: тільки лічимо
        if (cnt > best_count) {                     // 4. новий рекорд
            best = model; best_count = cnt;
        }
    }
    if (!best) return {};
    std::vector<Pt> in = collect_inliers(*best, pts, t);   // список — один раз
    out = refine(in);                                      // уточнення по згодних
    return in;
}
```
:::

Функція `refine` заслуговує на пояснення, бо в ній заховано менше магії, ніж здається. Пряма, що мінімізує суму квадратів перпендикулярних відхилень, обов'язково проходить крізь **центроїд** хмари — а її напрямок збігається з головною віссю розкиду. Для двох вимірів цю вісь дає закритий вираз через другі моменти: `θ = ½·atan2(2·Sxy, Sxx − Syy)`. Жодних матричних бібліотек, п'ять рядків арифметики. Нормаль до осі — це `(−sin θ, cos θ)`, і вона вже одинична, тож нормувати нічого не треба.

## Прогін: що каже кожна спроба

Частка чесних точок `w = 9/12 = 0.75`, модель потребує `n = 2` точок. Формула `k = log(1−p)/log(1−wⁿ)` під певність `p = 0.99` дає `k = 5.57`, тобто **6 спроб**. Візьмімо з запасом дванадцять і надрукуймо кожну. У прогоні ми знаємо правду наперед — точки 9–11 підкинуті нами, — тож друкуємо ще й тип вибірки та нахил; на справжніх даних цих колонок, звісно, не буває.

   3   0, 2    чч    2.26    +0.525      8

Читаймо. **Усі чотири брудні вибірки** (спроби 2, 5, 6, 12) набрали рівно `2`. Не «мало» — рівно два, і це не збіг: модель завжди містить власну вибірку, бо від своїх двох точок вона відстоїть на нуль. Двійка — це підлога, нижче впасти нікуди. Брудна вибірка не переконала **жодної сторонньої точки**. Перевірка всіх 30 брудних пар цього набору дає ту саму відповідь: максимум `2`, у середньому `2.00`. Розрив між чистою вибіркою й брудною тут не поступовий, а прірва: 9 проти 2.

Спроба 5 — окрема радість. Вона взяла точки `(5, 3.44)` і `(5, 0.40)` — з **однаковим x**. Пряма крізь них вертикальна, і наш запис приймає це не змигнувши: `a = −1`, `b = 0`, `c = 5`, тобто `−x + 5 = 0`. Відстань рахується як завжди. Запис `y = k·x + b` тут просто вмер би: у стовпчику `нахил` не дарма стоїть `+inf` — це друкує вимірювальна обгортка, а не сам алгоритм, якому нахил байдужий.

А тепер найцікавіше. Гляньте на спроби 4 і 11. **Обидві чисті** — жодного викиду. Спроба 4 набрала `9`, спроба 11 — `6`. Три чесні точки не впізнали правильної за формою прямої, проведеної по двох їхніх же чесних сусідах.

## Чому чиста вибірка ще не означає добру модель

Різниця між спробами 4 і 11 — в одній колонці. База `7.89` проти `2.21`.

Механіка проста, як важіль. Дві точки з шумом `σ` кожна, база `L`. Пряма крізь них хитається на кут приблизно

```
Δθ ≈ σ·√2 / L
```

бо шум обох кінців зсуває їх незалежно, а важіль, що перетворює зсув на кут, — це база. Тепер візьмімо точку, що лежить на відстані `R` уздовж прямої від вибірки: її знесе на `R·Δθ`. Якщо цей знос перевищить `t`, точка випаде зі згоди — хоч вона й чесна, і пряма чесна.

Порахуймо для наших чисел. Шум `σ = 0.078`, поріг `t = 0.25`, а за `R` візьмімо пів розмаху хмари, `≈ 4.5` — типову відстань від вибірки до її дальніх точок (вибірці з краю хмари важіль дістанеться ще довший, і знос буде більший). Величина `Δθ` тут — теж типова: конкретній парі щастить більше або менше, тож це прикидка порядку, а не пророцтво.

```
L = 1.0  →  Δθ ≈ 0.110 рад = 6.3°  →  знос на R=4.5 ≈ 0.494    ≫ t  — випаде
L = 2.21 →  Δθ ≈ 0.050 рад = 2.9°  →  знос ≈ 0.224             ≈ t  — на межі
L = 3.29 →  Δθ ≈ 0.033 рад = 1.9°  →  знос ≈ 0.150             < t  — втримається
L = 7.89 →  Δθ ≈ 0.014 рад = 0.8°  →  знос ≈ 0.063             ≪ t  — з запасом
```

А ось що показує перебір **усіх 36 чистих пар** цього набору — не оцінка, а замір:

```
база 0…2:   8 пар,  згода в середньому 2.50   (мін 2, макс 4)
база 2…4:  13 пар,  згода в середньому 8.00   (мін 6, макс 9)
база 4…6:   9 пар,  згода в середньому 9.00   (мін 9, макс 9)
база 6…9:   6 пар,  згода в середньому 9.00   (мін 9, макс 9)
```

Прикидка й замір збігаються по всіх чотирьох поличках: там, де формула обіцяє знос більший за поріг, згода провалюється; там, де знос менший, — згода повна. **Лише 20 із 36 чистих пар (56%) дають повну згоду 9.** Чистота вибірки — умова необхідна, але геть не достатня.

Праворуч вибірка з двох чесних точок на протилежних кінцях хмари: база 7.89, пряма лягла точно, згода 9](/book/algorithms/design-paradigms/ransac/img/sample-baseline.svg)
*Обидві вибірки — з двох чесних точок; жодного викиду ні там, ні там. Уся різниця в тому, як далеко взяті точки одна від одної: коротка база робить із дрібного шуму помітний кут, і далекі чесні точки випадають зі смуги.*

> 🔧 **Навіщо це.** База — це та величина, якої немає в описі алгоритму, зате вона керує його якістю. Саме вона пояснює, чому формула числа спроб обіцяє більше, ніж дає: формула лічить шанс ухопити **чисту** вибірку, а нам потрібна **чиста й розтягнута**. І вона ж підказує, куди дивитися, коли RANSAC на щільній купці точок раптом перестає працювати: якщо вся хмара вміщається в п'ятачок, довгої бази взяти нізвідки, кожна пряма хитається, і згода перестає відрізняти правильну модель від випадкової.

## Чому переможця треба уточнити

Переможець прогону — спроба 4, побудована рівно по двох точках: `(8, 5.06)` і `(1, 1.42)`. Вона зібрала всі дев'ять чесних. Здавалося б, готово. Але гляньмо, що це за пряма:

```
сира (по 2 точках):   y = 0.5200·x + 0.9000
істина:               y = 0.5000·x + 1.0000
```

Похибка нахилу `0.02`, вільного члена `0.10`. Звідки вона? Звідти ж, звідки й узялася: пряма проходить **рівно** крізь дві точки, а обидві зсунуті шумом. Увесь шум цих двох точок сидить у відповіді на повну силу — решта дев'яти вимірів, які ми маємо, у побудові не брали участі **жодним чином**. Згода відповіла на питання «хто чесний», але саму пряму ніхто не усереднював.

Ось для чого існує останній рядок. Тепер, коли викиди відсіяно, по дев'яти чесних точках можна чесно застосувати [найменші квадрати](book:math/least-squares) — і шум усередниться:

```
уточнена (TLS по 9 згодних):   y = 0.5009·x + 1.0062
максимальне |d| по чесних:     0.1420  →  0.1098
```

Похибка нахилу впала з `0.0200` до `0.0009`, вільного члена — з `0.1000` до `0.0062`. Двадцятиразовий виграш за один прохід по масиву.

І тут-таки — пастка, у яку легко впасти саме на цьому місці. Двадцятиразовий виграш **не є** типовим: це один прогін, і йому просто пощастило. Прогнавши те саме на 4000 різних реалізацій шуму, дістаємо чесну відповідь:

```
                ско похибки нахилу    ско похибки віл. члена
сира (2 точки)       0.02290                0.10920
TLS по 9 згодних     0.01119                0.05290
виграш                 2.05×                  2.06×
```

Приблизно вдвічі — ось скільки насправді дає уточнення на дев'яти точках. Теорія обіцяє `√(M/n) = √(9/2) ≈ 2.12`: замість двох вимірів працює дев'ять, а шум усереднення спадає як корінь із їх числа. Замір `2.05` ліг трохи нижче обіцянки, і це теж зрозуміло: переможна вибірка не випадкова, її вже відібрала згода за довгою базою, тож сира пряма стартує краще за середню пару.

Виграш росте з числом згодних, хоч і повільніше за корінь — з тієї самої причини:

```
 9 чесних →  2.0×        90 чесних →  4.0×
30 чесних →  2.8×       270 чесних →  6.3×
```

На реальних даних із сотнями точок це вже не дрібниця. Ціна — один прохід наприкінці.

## Скільки це коштує

Порахуймо роботу циклу. Вибірка двох індексів — `O(1)`. Побудова прямої — `O(1)`: кілька множень і один `hypot`. Згода — `O(N)`, бо треба торкнутися кожної точки. Отже одна спроба коштує `O(N)`, а весь цикл:

```
O(k·N)
```

Тепер головне, і воно ховається в тому, чого у формулі **немає**. Число спроб `k` залежить від частки чесних `w` і розміру вибірки `n` — і не залежить від `N` узагалі. Скільки б точок ви не сипнули в підгоняч, шанс ухопити чисту пару лишається тим самим. Тобто `k` — стала, а RANSAC — **лінійний за числом точок**.

Порівняймо з чесним перебором. Пар із `N` точок — `N·(N−1)/2`, і кожній треба порахувати згоду за `O(N)`, разом `O(N³)`. Для тисячі точок:

```
перебір усіх пар:  ~500 000 пар × 1000 точок  ≈ 5·10⁸ перевірок відстані
RANSAC (w = 0.5):        17 спроб × 1000      ≈ 1.7·10⁴ перевірок

різниця — приблизно в 30 000 разів
```

Пам'ять: у циклі — `O(1)`, бо ми лише лічимо. Список згодних завдовжки `O(M)` виникає один раз наприкінці. Якби ми, як напрошується, збирали список щоразу, кожна рекордна спроба виділяла б масив — і на великих даних алокатор коштував би більше за саму арифметику.

До речі, про арифметику: у внутрішньому циклі немає ані кореня, ані ділення — лише два множення, два додавання, модуль і порівняння. Три ділення на `n` трапляються **раз на спробу**, а не раз на точку, бо ми нормуємо коефіцієнти одразу після побудови. Внутрішній цикл до того ж не має залежностей між ітераціями — він чудово векторизується й ріжеться на потоки.

## Дві ручки на практиці

### Поріг t

Поріг береться зі **шуму чесних точок**, не з викидів і не зі стелі. Якщо чесне відхилення розподілене нормально з відхиленням `σ`, то смуга `±t` вміщає передбачувану частку:

```
t = 1.00·σ  →  68.3%        t = 2.50·σ  →  98.8%
t = 1.96·σ  →  95.0%        t = 3.00·σ  →  99.7%
```

Звідси й усталена в машинному зорі домовленість `t = 1.96·σ` (її частіше пишуть як `t² = 3.84·σ²`) — це 95-й відсоток для відстані з однією віссю свободи, як у точки до прямої. Наші `t = 0.25` при `σ = 0.078` дають `3.2·σ`: свідомо щедро, бо викиди відстоять аж на 36 σ і місця для маневру — море. Звідки береться зв'язок `t` із `σ` й чому там саме така кількість ступенів вільності — у [математиці числа ітерацій](book:algorithms/ransac/math-iterations.md).

А що робити, коли `σ` невідоме? Два проходи. Перший — зі щедрим порогом, аби зібрати приблизну хмару чесних; далі оцінити розкид їхніх відхилень стійко до решток сміття — через медіану абсолютних відхилень, `σ̂ ≈ 1.4826·MAD` ([стійкі оцінки](book:math/median-robust-stats)); другий прохід — уже з `t = 2·σ̂`.

Найкорисніше ж думати про `t` не через частку чесних, а через **контраст**. RANSAC не потребує великої згоди — він потребує великого **розриву** між згодою правильної моделі й згодою випадкової. У нашому наборі розрив 9 проти 2, і саме тому все працює. Замалий поріг — правильна модель збирає, скажімо, 4 голоси замість 9, а якась крива випадково 3; аргмаксимум починає плавати. Завеликий поріг — усі моделі збирають майже всі точки, згода стає рівною, і переможцем виявляється просто той, хто трапився першим. Звідси готова діагностика: **якщо згода щоразу близька до `N` — поріг завеликий**, і ви обираєте модель навмання, самі того не бачачи.

### Число спроб k

Формула дає ось такі числа для прямої (`n = 2`) під певність `p = 0.99`:

```
w = 0.9  →  k =   3        w = 0.4  →  k =  27
w = 0.8  →  k =   5        w = 0.3  →  k =  49
w = 0.7  →  k =   7        w = 0.2  →  k = 113
w = 0.6  →  k =  11        w = 0.1  →  k = 459
w = 0.5  →  k =  17
```

Тепер перевірмо формулу на нашому наборі. `w = 0.75` дає `k = 6`. Проженімо 2000 разів по шість спроб і полічімо дві різні речі:

```
хоч раз ухопили чисту вибірку:   99.2%      (формула обіцяла 99% — точно)
згода дійшла до 9:               88.1%
```

Формула виконала обіцянку **бездоганно** — і цього не вистачило. Розрив у 11 відсоткових пунктів — це рівно те, про що йшлося вище: `k = 6` гарантує чисту вибірку, а чиста вибірка лише в 56% випадків має досить довгу базу. **Формула лічить шанс ухопити чисту вибірку, а не шанс дістати добру модель.**

Практичний висновок звідси один: беріть `k` із запасом у два-три рази. Він дешевий — цикл лінійний, зайві спроби коштують копійки:

```
k =  3  →  66%        k =  8  →  94.5%
k =  6  →  88%        k = 12  →  98.6%
```

Подвоївши `k` з 6 до 12, ми піднялися з 88% до 98.6%. Скупість тут карається неправильною відповіддю, щедрість — часткою мілісекунди. Асиметрія очевидна.

Дрібниця для малих наборів: `wⁿ` мовчки припускає вибір **з поверненням**, тобто що друга точка може виявитися першою. Насправді ми беремо дві різні, і шанс чистої пари — `(9/12)·(8/11) = 0.5455` замість `0.75² = 0.5625`. Формула трохи оптимістична: `k = 5.84` проти `5.57`. Обидва округлюються до 6, тож тут це байдуже — але на десятку точок різниця вже виднілася б. Як переоцінювати `w` на льоту й скорочувати `k` просто під час роботи — там-таки, у [математиці числа ітерацій](book:algorithms/ransac/math-iterations.md).

## Пастки

**Пряма як `y = k·x + b`.** Вертикаль тут дає ділення на нуль — це видно одразу й лагодиться швидко. Гірша біда тиха: поріг на `|y − k·x − b|` міряє відхилення **по вертикалі**, а вертикальна відстань більша за найкоротшу в `√(1+k²)` разів. Тобто той самий `t` вирізає смугу, чия справжня напівширина — `t/√(1+k²)`, і вона тим вужча, чим крутіша пряма:

```
k = 0.5  →  смуга 0.894·t          k = 5   →  смуга 0.196·t
k = 1.0  →  смуга 0.707·t          k = 10  →  смуга 0.099·t
```

Наслідок отруйний: круті прямі систематично **недобирають голосів** і програють голосування пологим — навіть неправильним. На наших дев'яти відхиленнях полога пряма (`k = 0.5`) пропускає всі 9 точок, а крута (`k = 5`) — одну. Ніхто нікуди не падає й не свариться: метод упевнено вертає не ту пряму.

![Дві панелі. Ліворуч полога пряма з нахилом 0.5: смуга, яку лишає поріг по вертикалі, майже збігається з чесною перпендикулярною смугою, і всі 9 точок проходять. Праворуч крута пряма з нахилом 5: чесна смуга та сама, але поріг по вертикалі лишає від неї вузеньку смужку вп'ятеро тоншу, і крізь неї проходить лише 1 точка з 9](/book/algorithms/design-paradigms/ransac/img/vertical-vs-perp.svg)
*Той самий поріг, той самий шум, різний нахил. Зелена штрихова смуга — чесні `±t` по перпендикуляру; червона — те, що від неї лишає поріг на `|y − k·x − b|`. На пологій прямій вони майже збігаються, на крутій червона стискається вп'ятеро — і чесні точки масово випадають зі згоди.*

**Вироджена вибірка.** Перевірка `if p == q` ловить лише точне збігання й пропускає головне: виродження — не подія, а **спектр**. Пара на відстані `10⁻⁶` формально різна, а пряма крізь неї — чистий шум. Тому охороняти треба базу, а не рівність. Коштує це нуль: `n` уже обчислено для нормування.

Що буває без охорони — залежить від мови, і по-різному підступно. Python на точних дублікатах кидає `ZeroDivisionError` і падає голосно. C++ на звичайному IEEE-754 залізі тихо дасть `NaN` — а далі `std::fabs(NaN) <= t` хибне для **будь-якої** точки, тож така модель набирає нуль голосів і мовчки програє. Падіння краще: воно принаймні помітне. До речі, звідси й дрібне правило — `best_count` треба починати з нуля, а не з `−1`: інакше NaN-модель із нульовою згодою виграє перший-таки раунд і залишиться в переможцях, якщо всі інші вибірки теж вироджені.

**Охорона бази не пришвидшує — і це вимірюється.** Напрошується думка: відкидаймо короткі бази, і згода поліпшиться. Замір каже інше. Частка прогонів, що дійшли до згоди 9, на 3000 зерен:

```
k     без охорони    з охороною база ≥ 2.0    з охороною + перетяг
 3       66.3%              66.3%                    72.6%
 6       88.0%              88.0%                    92.2%
12       98.6%              98.6%                    99.3%
```

Другий стовпчик збігається з першим **до десятої частки відсотка**. Причина проста, щойно її побачиш: коротка база й так набирає 2–4 голоси й ніколи не стає рекордом. Згода вже сама її відкидає — охорона тільки повторює вирок, який і без неї виносять. Виграш з'являється лише в третьому стовпчику, де вироджена вибірка **не з'їдає спроби**, а тягнеться нова (зі стелею на число перетягів, інакше хмара з однакових точок закрутить цикл навіки). Та й той виграш скромний, і піднявши `k` з 6 до 8, ви купите більше. Висновок: охорона бази — це запобіжник **числовий**, а не спосіб поліпшити якість. Ставте її заради `NaN`, не заради згоди.

**Уточнення не тією мірою.** Згода міряла перпендикулярні відстані — отже й уточнювати треба тим самим, інакше метод сам собі суперечить. Звичайні найменші квадрати мінімізують **вертикальні** відхилення й тягнуть за собою всі біди запису `y = k·x + b`, включно з вибухом на вертикалі. На наших даних різниця мізерна (сума квадратів перпендикулярних відхилень `0.053557` у TLS проти `0.053567` у звичайних НК) — бо нахил пологий, `0.5`. На крутих даних вона перестає бути мізерною, а на вертикальних звичайні НК просто не існують. TLS не дорожчий: ті самі п'ять рядків.

**Виродження ховається й в уточненні.** Якщо згодні точки лягли ізотропною купкою — `Sxx = Syy`, `Sxy = 0`, — то `atan2(0, 0)` поверне `0`, і `refine` видасть горизонтальну пряму. Не помилка: у круглої хмари **немає** головної осі, будь-який напрямок однаково поганий. Але прийняти таку відповідь за виміряну — помилка.

**`rand() % m` у C++.** Класика, що переживе нас усіх. По-перше, зсув: якщо `RAND_MAX + 1` не ділиться на `m` націло, менші індекси випадають частіше. По-друге, і це вбивчіше: `RAND_MAX` стандарт гарантує лише `≥ 32767`, і в MSVC він рівно такий. Тобто `rand() % m` для масиву на сто тисяч точок **ніколи не вибере точку з номером понад 32767** — дві третини даних просто не існують для алгоритму, і жодного попередження. `std::mt19937` разом із `std::uniform_int_distribution` знімають обидві біди.

**Один прогін нічого не доводить.** Метод випадковий: та сама програма на тих самих даних дає різні відповіді. Зерно генератора треба задавати явно — інакше тест, що вчора проходив, сьогодні впаде, і ви шукатимете помилку там, де її немає. І пам'ятайте, чого нас навчило уточнення: один прогін показав виграш у 21 раз, ансамбль із 4000 — у 2.05. Судити стохастичний метод за однією реалізацією — найдешевший спосіб обманути себе. Перевіряти краще стійкі величини — розмір згоди, частку успіхів на багатьох зернах, — а не точні коефіцієнти.

**Викиди зі структурою.** Найглибше припущення методу зазвичай не промовляють уголос: даних одна модель, а решта — безладне сміття. Хай-но викиди самі складуться в модель — скажімо, на знімку не одна пряма, а дві, — і RANSAC чесно знайде **ту, у якої точок більше**, з повною певністю й великою згодою. Він не помилиться: він відповість на питання, яке ви поставили, а ви хотіли поставити інше. Коли моделей на сцені кілька, шукати треба інакше — наприклад, [перетворенням Хафа](book:algorithms/hough-transform), яке дає голосувати всім точкам за всі моделі одразу й показує кілька піків замість одного переможця.

## Що лишається в руках

Підгоняч зібрано: чотири функції, один цикл, жодної залежності. Але вартий він не рядків, а того, що показав прогін. Брудна вибірка не набирає нічого понад власні дві точки — розрив між нею й чистою не поступовий, а прірва, і саме на ньому тримається весь метод. Чиста вибірка ще не є доброю: коротка база перетворює дрібний шум на помітний кут, і три з дев'яти чесних точок відмовляються впізнавати власну пряму. Формула числа спроб не бреше — вона просто відповідає на вужче питання, ніж те, яке нас цікавить, тому `k` беруть у два-три рази більшим за її пораду. Переможець — не відповідь, а лише список чесних: сама пряма проходить крізь дві зашумлені точки й уточнення чекає обов'язково. А охорона бази, яку так хочеться додати заради якості, якості не додає зовсім — згода й без неї виносить той самий вирок; ставлять її, щоб не ділити на нуль.
