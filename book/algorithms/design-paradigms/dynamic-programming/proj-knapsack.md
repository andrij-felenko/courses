# 🎒 Задача про рюкзак: NP-важка, а піддається таблиці

Рюкзак витримує лише `W` кілограмів, речей більше, ніж улізе, і кожна має свою вагу й цінність — які взяти, щоб винести якнайдорожче? Ця задача знаменита подвійно: у загальному випадку вона **NP-важка** (швидкого розв'язку не відомо), а проте акуратна двовимірна таблиця розв'язує її за час, цілком по кишені для практичних розмірів. Розберімо, як саме, і де захована пастка.

## Умова, і чому перебір не годиться

Дано `n` речей; річ `i` має **цілу** вагу `wᵢ` і цінність `vᵢ`. Рюкзак витримує сумарну вагу `W`. Треба вибрати підмножину речей, чия вага не перевищує `W`, а сумарна цінність — найбільша можлива. Назва «0/1» про те, що кожну річ беруть **цілою або не беруть зовсім**: половини немає, другого примірника немає. Саме ця незламна цілість, як з'ясується наприкінці, і робить задачу важкою.

Найпростіший задум — перебрати всі підмножини. Але їх `2ⁿ`: для тридцяти речей це вже понад мільярд, для сотні — більше, ніж атомів у видимому Всесвіті. Перебір відпадає.

Наступна спокуса — **жадібність**: складати речі за «вигідністю», цінністю на кілограм, доки влазять. Спокуса оманлива. Візьмімо чотири речі й рюкзак на `W = 7`:

```
річ   вага   цінність   цінність/кг
 A      1        1          1.00
 B      3        4          1.33
 C      4        5          1.25
 D      5        7          1.40
```

Жадібний хапає найвигіднішу `D` (1.40 за кілограм) — лишається 2 кг, і туди вже не влазить ні `B`, ні `C`, тулиться хіба `A`. Разом `D + A`: цінність **8**. А оптимум — `B + C`: вага рівно `3 + 4 = 7`, цінність **9**. Жадібний, погнавшись за найкращим кілограмом, застряг із незручним залишком. Отже треба зважити **всі** варіанти, не платячи за це експонентою, — і це вже робота для динамічного програмування.

## Стан: що доводиться пам'ятати

Усе починається з питання: який **найменший** опис підзадачі, щоб відповідь від нього повністю залежала? Тут діють дві сили. Перша — рішення ухвалюють **річ за річчю**: для кожної окремо кажуть «беру» чи «ні». Друга — рішення не незалежні, вони змагаються за спільний ресурс: узяв важку річ — лишилося менше місця для решти. Тож стан мусить тримати рівно дві речі: **докуди дійшли в списку речей** і **скільки місткості лишилось**.

Позначмо `dp[i][w]` — найбільша цінність, яку можна набрати, **дозволивши собі лише перші `i` речей** за **місткості `w`**. Тепер погляньмо на `i`-ту річ. Рішення про неї бінарне:

- **не брати** — тоді все набране з перших `i−1` речей у ту саму місткість: `dp[i−1][w]`;
- **узяти** (можливо лише коли вона влазить, `wᵢ ≤ w`) — тоді дістаємо цінність `vᵢ`, місткості лишається `w − wᵢ`, а решту добираємо з перших `i−1` речей: `dp[i−1][w − wᵢ] + vᵢ`.

Наперед не знаємо, який вибір кращий, тож пробуємо обидва й лишаємо більший:

```
dp[i][w] = max( dp[i−1][w],  dp[i−1][w − wᵢ] + vᵢ )      якщо wᵢ ≤ w
dp[i][w] = dp[i−1][w]                                     якщо wᵢ > w
dp[0][w] = 0        нуль речей — нуль цінності, хоч яка місткість
```

Верхній рядок — **рекурентність**: відповідь виражена через відповіді для меншої кількості речей. Чому готове `dp[i−1][…]` можна брати не боячись, що воно «не найкраще»? Бо оптимум цілого складається з оптимумів частин — це принцип оптимальності, на якому стоїть уся парадигма динамічного програмування: якби хвіст розв'язку (добір із перших `i−1` речей) не був найкращим для своєї місткості, ми підмінили б його кращим і поліпшили ціле. Відповідь на всю задачу сидить у кутку таблиці — `dp[n][W]`.

![Двовимірна таблиця dp[i][w] для речей A(1,1), B(3,4), C(4,5), D(5,7) і місткості 7; заповнені значення по рядках, виділено слід відновлення від dp[4][7]=9 назад до бази, стрілки «взяти» по діагоналі та «пропустити» вгору, і трасування набору {B, C}](/book/algorithms/design-paradigms/dynamic-programming/img/knapsack-table.svg)
*Таблиця рюкзака. Кожна клітина `dp[i][w]` — максимум із двох: клітини **прямо над нею** (нову річ не взяли) і клітини **на рядок вище, на `wᵢ` лівіше, плюс `vᵢ`** (узяли). Відповідь `dp[4][7] = 9` у правому нижньому куті. Зелений слід відновлює сам набір: від відповіді назад, діагональ — «взяти», вертикаль угору — «пропустити»; виходить `{B, C}` вагою 7 і цінністю 9.*

## Робочий код: заповнюємо таблицю

Каркас прямо перекладається у два вкладені цикли — по речах і по місткості. Річ `i` (від 1) має вагу `wt[i−1]` і цінність `val[i−1]`, бо масиви нумеруються з нуля:

:::tabs
```cpp
#include <vector>
#include <algorithm>
using std::vector;

// Будує таблицю dp[i][w] і повертає її цілком.
// wt[k], val[k] — вага й цінність k-ї речі (k від 0); cap — місткість W.
vector<vector<int>> knap_table(const vector<int>& wt,
                               const vector<int>& val, int cap) {
    int n = (int)wt.size();
    vector<vector<int>> dp(n + 1, vector<int>(cap + 1, 0));   // рядок 0 — самі нулі
    for (int i = 1; i <= n; ++i)
        for (int w = 0; w <= cap; ++w) {
            dp[i][w] = dp[i - 1][w];                          // не брати i-ту річ
            if (wt[i - 1] <= w) {                             // якщо влазить —
                int take = dp[i - 1][w - wt[i - 1]] + val[i - 1];
                if (take > dp[i][w]) dp[i][w] = take;         // …спробувати взяти
            }
        }
    return dp;                                                // відповідь — dp[n][cap]
}
```
```py
def knap_table(wt, val, cap):
    n = len(wt)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]      # рядок 0 — самі нулі
    for i in range(1, n + 1):
        for w in range(cap + 1):
            dp[i][w] = dp[i - 1][w]                    # не брати i-ту річ
            if wt[i - 1] <= w:                         # якщо влазить —
                take = dp[i - 1][w - wt[i - 1]] + val[i - 1]
                dp[i][w] = max(dp[i][w], take)         # …спробувати взяти
    return dp                                          # відповідь — dp[n][cap]
```
:::

Простежмо роботу руками.

**Умова.** Речі `A(1, 1)`, `B(3, 4)`, `C(4, 5)`, `D(5, 7)`, місткість `W = 7`. Заповнюємо рядок за рядком, додаючи по одній речі:

```
        w:  0   1   2   3   4   5   6   7
 i=0 (—)    0   0   0   0   0   0   0   0
 i=1 +A     0   1   1   1   1   1   1   1
 i=2 +B     0   1   1   4   5   5   5   5
 i=3 +C     0   1   1   4   5   6   6   9
 i=4 +D     0   1   1   4   5   7   8   9
```

Наприклад, клітина `dp[3][7]`: не взяти `C` — це `dp[2][7] = 5`; узяти `C` — це `dp[2][7 − 4] + 5 = dp[2][3] + 5 = 4 + 5 = 9`. Більше — дев'ять, тож `C` варто взяти. Відповідь усієї задачі — у кутку: `dp[4][7] = 9`.

## Відновлення самого набору

Таблиця сказала «дев'ять», але не сказала, **які** речі. Проте це відновлюється зі самої таблиці, без жодного додаткового запису під час заповнення. Ідемо від `dp[n][W]` назад і в кожному рядку питаємо одне: чи змінилося значення, коли з'явилася `i`-та річ?

- якщо `dp[i][w] == dp[i−1][w]` — річ `i` **не брали** (вона нічого не додала); переходимо на рядок вище, місткість не чіпаємо;
- якщо `dp[i][w] ≠ dp[i−1][w]` — річ `i` **узяли**; записуємо її, зменшуємо місткість на `wᵢ` і йдемо вище.

:::tabs
```cpp
vector<int> knap_items(const vector<vector<int>>& dp,
                       const vector<int>& wt, int cap) {
    int n = (int)wt.size(), w = cap;
    vector<int> taken;
    for (int i = n; i >= 1; --i)
        if (dp[i][w] != dp[i - 1][w]) {   // значення змінилося → річ i узято
            taken.push_back(i - 1);       // її індекс (від 0)
            w -= wt[i - 1];               // звільняємо зайняте нею місце
        }
    return taken;
}
```
```py
def knap_items(dp, wt, cap):
    n, w = len(wt), cap
    taken = []
    for i in range(n, 0, -1):
        if dp[i][w] != dp[i - 1][w]:      # значення змінилося → річ i узято
            taken.append(i - 1)           # її індекс (від 0)
            w -= wt[i - 1]                # звільняємо зайняте нею місце
    return taken
```
:::

На нашій таблиці зворотний хід дає: `dp[4][7]=9` дорівнює `dp[3][7]` — `D` пропустили; `dp[3][7]=9` більше за `dp[2][7]=5` — `C` узяли, місткість `7−4=3`; `dp[2][3]=4` більше за `dp[1][3]=1` — `B` узяли, місткість `3−3=0`; `dp[1][0]=dp[0][0]` — `A` пропустили. Набір — `{B, C}`, вага 7, цінність 9. Той самий, який жадібний проґавив.

## Ощадна пам'ять: один рядок замість таблиці

Придивімося до рекурентності: `dp[i][·]` читає **лише попередній рядок** `dp[i−1][·]`. Уся давніша частина таблиці більше не потрібна. Отже цілу сітку `(n+1)×(W+1)` можна замінити **одним рядком** `dp[w]` завдовжки `W+1`, який переписують на місці, додаючи речі по одній.

Але тут криється найпідступніша пастка рюкзака, і вся вона — у **порядку**, в якому оновлювати `w`. Оновлення `dp[w] = max(dp[w], dp[w − wᵢ] + vᵢ)` читає клітину `dp[w − wᵢ]`, що **лівіше**. Ця клітина мусить іще містити значення з **попередньої** речі — інакше ми додамо `vᵢ` до варіанта, у якому річ `i` уже присутня, тобто **візьмемо ту саму річ двічі**.

Тому місткість перебирають **у зворотному порядку**, від `W` до `wᵢ`. Тоді, коли ми змінюємо `dp[w]`, клітину `dp[w − wᵢ]` (лівіше) цього проходу ще не торкалися — вона стара, з попередньої речі, як і треба.

![Один рядок dp[w] при додаванні речі B: угорі перебір назад (w=7..3) читає стару dp[3]=1 і дає dp[6]=5, річ узято раз; унизу перебір уперед (w=3..7) читає вже оновлену dp[3]=4 і дає хибне dp[6]=8, річ узято двічі](/book/algorithms/design-paradigms/dynamic-programming/img/knapsack-direction.svg)
*Чому назад. Додаємо річ `B` (3 кг) до одного рядка. **Назад** (`w = 7…3`): коли рахуємо `dp[6]`, клітина `dp[3]` іще стара (з попередньої речі), тож `dp[6] = 1 + 4 = 5` — річ `B` узято раз. **Вперед** (`w = 3…7`): доки дійдемо до `dp[6]`, клітину `dp[3]` уже змінила ця сама річ, тож `dp[6] = 4 + 4 = 8` — річ `B` порахована двічі. Напрям циклу — рівно та риска, що відділяє «0/1» від безмежного рюкзака.*

Якби перебирали **вперед**, від малих `w` до великих, то `dp[w − wᵢ]` уже було б оновлене цією ж річчю — і кожну річ можна було б класти скільки завгодно разів. Це не помилка, а **інша задача** — рюкзак із необмеженою кількістю копій кожної речі; напрям циклу і є та єдина риска, що відділяє «0/1» від «безмежного».

:::tabs
```cpp
int knap_value(const vector<int>& wt, const vector<int>& val, int cap) {
    vector<int> dp(cap + 1, 0);                      // єдиний рядок
    for (size_t i = 0; i < wt.size(); ++i)
        for (int w = cap; w >= wt[i]; --w)           // w — СТРОГО назад
            dp[w] = std::max(dp[w], dp[w - wt[i]] + val[i]);
    return dp[cap];
}
```
```py
def knap_value(wt, val, cap):
    dp = [0] * (cap + 1)                             # єдиний рядок
    for i in range(len(wt)):
        for w in range(cap, wt[i] - 1, -1):          # w — СТРОГО назад
            dp[w] = max(dp[w], dp[w - wt[i]] + val[i])
    return dp[cap]
```
:::

За цю ощадність доводиться платити: один рядок дає оптимальну **цінність**, але вже не тримає історії, з якої ми відновлювали набір. Хочеш і речі, і пам'ять `O(W)` — доводиться запам'ятовувати вибір інакше (наприклад, бітову маску «взято» на кожну місткість) або застосувати поділ навпіл у стилі Гіршберга. Найчастіше, якщо набір таки потрібен, просто лишають повну таблицю — пам'ять `O(n·W)` того варта.

## Скільки коштує і що таке «псевдополіном»

Час читається просто з коду: два вкладені цикли — по речах (`n`) і по місткості (`W`) — зі сталою роботою всередині. Отже

```
час:     O(n · W)
пам'ять:  O(n · W)  на повну таблицю  →  O(W)  на один рядок
```

`O(n·W)` виглядає як поліном — і тут ховається славетна тонкість. Складність вимірюють від **довжини входу в бітах**. Число `W` займає на вході лише близько `log₂W` бітів; сама його величина — це `2` у степені кількості цих бітів. Тому `O(n·W)` — це `O(n · 2^log₂W)`, тобто **експонента від довжини запису** `W`. Якщо місткість — звичайне 64-бітове число, скажімо `W ≈ 10⁹`, то рядок таблиці має мільярд клітин навіть для трьох речей. Такий час — поліном від **величини** чисел, але не від їхнього **запису** — називають **псевдополіноміальним**.

Це не дрібниця означень, а сама природа задачі. Рюкзак — [NP-важка задача](topic:algorithms/np-completeness): її розв'язувальна версія («чи є набір вагою не більш ніж `W` і цінністю хоча б `V`?») входить у список Карпа з 21 NP-повної задачі 1972 року. Поліноміального від довжини входу алгоритму для неї не відомо, і поки не доведено `P = NP`, не буде. Псевдополіноміальне ДП цьому не суперечить: рюкзак належить до **слабко** NP-важких — тих, у яких експонента ховається лише у **величині** чисел (термін «псевдополіном» і поділ на слабку та сильну важкість увели Ґері й Джонсон 1979 року). Для **сильно** NP-важких задач навіть такого ДП не існує, якщо `P ≠ NP`.

Звідси й дві жорсткі вимоги. По-перше, **ваги мусять бути цілі**: таблицю індексують цілою місткістю, і клітини `dp[w]` для дробового `w` просто немає. Раціональні ваги рятують домноженням на спільний знаменник — але це роздуває `W`, а з ним і час. Ірраціональні вибивають ґрунт з-під табличного підходу зовсім.

І останній штрих, що замикає розмову про жадібність із початку. Якщо **прибрати цілість** — дозволити брати частину речі, — задача стає **неперервним** (дробовим) рюкзаком, і для нього [жадібний алгоритм](topic:algorithms/greedy-algorithms) уже оптимальний: бери речі за спаданням цінності на кілограм, останню — скільки влізе. `O(n log n)`, і жодних таблиць. Уся важкість 0/1-рюкзака сидить саме в тій незламній цілості, через яку не можна «долити» рівно стільки, скільки лишилось місця.

## Типові пастки

- **Напрям циклу в ощадній версії.** Місткість — тільки назад (`w` від `W` до `wᵢ`). Вперед — і це вже безмежний рюкзак: кожну річ порахує багато разів. Ця однорядкова помилка — найпоширеніша.
- **Річ, що не влазить.** Гілку «взяти» беруть лише при `wᵢ ≤ w`; без цієї перевірки індекс `w − wᵢ` піде у від'ємне, і програма впаде або прочитає сміття.
- **Переповнення.** Сума цінностей може вилізти за межу 32-бітного `int`; для великих входів тримайте цінності у 64-бітному цілому.
- **Втрата набору при `O(W)`.** Один рядок дає лише число. Потрібні самі речі — лишайте повну таблицю або окремо записуйте вибір.
- **Нецілі ваги.** Таблиця їх не терпить; масштабуйте до цілих (пам'ятаючи, що це збільшує `W`) або шукайте інший метод.
- **Плутанина «0/1» з «безмежним» і «обмеженим».** Це три різні задачі, а в табличному коді їх розрізняє дрібниця — напрям циклу й те, з якого рядка читати. Спершу назвіть, скільки копій кожної речі дозволено, а тоді пишіть цикл.
