# 📋 Інтерфейси зв'язаних списків у системних та стандартних бібліотеках

Зв'язані списки реалізовано практично в усіх системних бібліотеках, операційних системах та стандартах сучасних мов програмування. Однак підходи до їхнього проектування кардинально відрізняються залежно від рівня абстракції: від інтрузивних списків у ядрі Linux без виділення пам'яті до класів стандартної бібліотеки шаблонів C++ STL (`std::list` та `std::forward_list`). У цьому довіднику розібрано контракти інтерфейсів, асимптотичні гарантії, правила інвалідації ітераторів та інженерні тонкощі використання списків на системному й прикладному рівнях.

## 1. Інтрузивні списки ядра Linux (`struct list_head`)

У системному програмуванні та ядрах операційних систем традиційне виділення пам'яті під вузол-обгортку (`malloc(sizeof(Node))`) є неприпустимим. Викликати аллокатор купи на кожну мережеву пакетну обгортку або дескриптор процесу означало б катастрофічне падіння швидкості, загрозу фрагментації та ризик фатального збою при браків пам'яті (Out-of-Memory, OOM).

Ядро Linux використовує елегантну концепцію **інтрузивного списку** (Intrusive List). На відміну від стандартних списків, де вузол містить вказівник на об'єкт даних, **структура даних містить у собі вузол списка**.

### Анатомія та розміщення `struct list_head` у системній пам'яті

Структура `struct list_head` визначена у заголовку `<linux/types.h>` як двохзв'язаний вузол без даних:

:::tabs
```c
/* Оголошення системної структури вузла в ядрі Linux */
struct list_head {
    struct list_head *next, *prev;
};
```
```cpp
// Концептуальне відображення інтрузивного вузла в C++
struct list_head {
    list_head* next{nullptr};
    list_head* prev{nullptr};
};
```
:::

Ця структура розміщується безпосередньо всередині цільового об'єкта. Наприклад, у дескрипторі процесу `struct task_struct` або дескрипторі сокета `struct sock` може жити одразу кілька полів типу `struct list_head`. Це дозволяє одному й тому самому об'єкту одночасно перебувати в кількох незалежних списках (наприклад, у списку всіх процесів системи та в черзі очікування конкретного таймера чи файлового дескриптора) без жодного додаткового виділення пам'яті!

### Повний макросний контракт системного API ядра (`<linux/list.h>`)

Ядро Linux надає багатий набір функцій та inline-макросів для роботи з інтрузивними списками:

1. **`LIST_HEAD(name)`**: Макрос статичного оголошення та ініціалізації головного стоитлового вузла `name`. Зациклює вказівники `next` та `prev` на сам вузол `name`.
2. **`INIT_LIST_HEAD(struct list_head *list)`**: Динамічна ініціалізація вже виділеного заголовочного вузла списку у рантаймі.
3. **`list_add(struct list_head *new, struct list_head *head)`**: Додає вузол `new` одразу після вартового `head`. Використовується для реалізації стейка (LIFO), де нові елементи потрапляють на початок.
4. **`list_add_tail(struct list_head *new, struct list_head *head)`**: Додає вузол `new` перед вартовим `head` (тобто в кінець списка). Використовується для реалізації черги (FIFO).
5. **`list_del(struct list_head *entry)`**: Видаляє вузол `entry` зі списка, зводячи вказівники його попередника та наступника напряму один на одного. Полям `next` і `prev` вилученого вузла присвоюються спеціальні отруєні адреси `LIST_POISON1` та `LIST_POISON2` для швидкого виявлення помилок Use-After-Free.
6. **`list_replace(struct list_head *old, struct list_head *new)`**: Заміщує старий вузол `old` на новий `new` у списку без порушення зв'язків.
7. **`list_move(struct list_head *list, struct list_head *head)`**: Видаляє вузол із поточного списка і додає його на початок нового списка `head`.
8. **`list_splice(const struct list_head *list, struct list_head *head)`**: Об'єднує два списки за `O(1)`, під'єднуючи весь вміст списка `list` у позицію після `head`.
9. **`list_empty(const struct list_head *head)`**: Повертає істину, якщо `head->next == head`.
10. **`list_entry(ptr, type, member)`**: Головний розрахунковий макрос. Повертає вказівник на батьківську структуру типу `type`, в яку вбудовано поле `member` за адресою `ptr`.
11. **`list_for_each_entry(pos, head, member)`**: Макрос безпечного обходу списка у циклі `for`.

### Математичний розрахунок зміщення у макросі `container_of`

Обчислення адреси батьківської структури за адресою внутрішнього поля виконується за допомогою макросу `container_of`, який базується на вбудованому операторі компілятора `offsetof`:

:::tabs
```c
/* Визначення макросу container_of у системних заголовках Linux */
#define container_of(ptr, type, member) ({                      \
    const typeof( ((type *)0)->member ) *__mptr = (ptr);    \
    (type *)( (char *)__mptr - offsetof(type,member) );})
```
```cpp
// Реалізація container_of у C++20 за допомогою reinterpret_cast та offsetof
template <typename Parent, typename Member>
Parent* container_of(Member* ptr, std::size_t offset) noexcept {
    return reinterpret_cast<Parent*>(reinterpret_cast<char*>(ptr) - offset);
}
```
:::

Метрика зміщення обчислюється так: компілятор беручи уявний вказівник `0` (NULL) типу `type*`, знаходить фізичний офсет поля `member` у байтах. Потім із реальної адреси `ptr` віднімається це зміщення `offsetof`. У результаті процесор отримує точну початкову адресу батьківського об'єкта в оперативній пам'яті за `0` додаткових інструкцій у рантаймі!

## 2. Інтерфейси C++ STL: `std::list` та `std::forward_list`

Стандартна бібліотека C++ надає два класичних контейнери для роботи зі зв'язаними списками:
- **`std::list<T>`**: Повнофункціональний двохзв'язаний список (Doubly Linked List).
- **`std::forward_list<T>`**: Мінімалістичний однозв'язаний список (Singly Linked List), оптимізований для економії пам'яті.

### Порівняльний аналіз функціональних контрактів

| Операція / Властивість | `std::vector<T>` | `std::forward_list<T>` | `std::list<T>` |
| :--- | :--- | :--- | :--- |
| **Структура в пам'яті** | Суцільний масив | Однозв'язаний список | Двохзв'язаний список |
| **Категорія ітераторів** | RandomAccessIterator | ForwardIterator | BidirectionalIterator |
| **Накладні витрати на елемент** | `0` байтів | `1` вказівник (`8` байтів) | `2` вказівники (`16` байтів) |
| **Вставка на початок `push_front`** | `O(N)` (зсув даних) | `O(1)` | `O(1)` |
| **Видалення з початку `pop_front`** | `O(N)` (зсув даних) | `O(1)` | `O(1)` |
| **Вставка в кінець `push_back`** | `O(1)` амортизовано | Відсутня | `O(1)` |
| **Довільний доступ `operator[]`** | `O(1)` | Відсутній | Відсутній |
| **Вставка в позицію `insert`** | `O(N)` (зсув даних) | `O(1)` (`insert_after`) | `O(1)` |
| **Видалення з позиції `erase`** | `O(N)` (зсув даних) | `O(1)` (`erase_after`) | `O(1)` |
| **Сплайсинг (переміщення вузлів)** | `O(N)` | `O(1)` / `O(N)` | `O(1)` |
| **Метод визначення розміру `size()`** | `O(1)` | Відсутній (лише `empty()`) | `O(1)` (з стандарту C++11) |

### Чому в `std::forward_list` немає методу `size()` та `push_back()`?

Дизайн `std::forward_list` підпорядкований суворому принципу C++: «Ти не платиш за те, чим не користуєшся» (Zero-Cost Abstraction). 
- Збереження вказівника на останній елемент (`tail`) або лічильника розміру додало б 8–16 байтів до кожного об'єкта `std::forward_list`, що позбавило б його переваги над `std::list` у графах та хеш-таблицях з відкритим зв'язуванням (Chaining у `std::unordered_map`).
- Збереження лише одного вказівника `head` дозволяє `std::forward_list` мати абсолютно однаковий розмір із сирим покажчиком мови C (`sizeof(std::forward_list<T>) == sizeof(void*)`).

### Еволюція стандарту C++11 та операція `splice`

У стандарті C++98 метод `std::list::size()` міг виконуватися за лінійний час `O(N)`. Це було свідомим рішенням розробників, щоб операція `splice(iterator pos, list& other)` — яка переміщує всі вузли з одного списка в інший перенаправленням покажчиків — працювала за миттєвий час `O(1)` без підрахунку кількості перенесених елементів.

Однак починаючи з C++11 стандарт суворо зобов'язав метод `std::list::size()` повертати значення за константний час `O(1)`. У результаті реалізації бібліотек (`libstdc++`, `libc++`) змушені зберігати лічильник розміру у заголовочному вузлі. Це зробило операцію `splice()` для повного списка за константний час `O(1)`, але переміщення довільного діапазону `splice(pos, other, first, last)` тепер вимагає обходу `O(dist(first, last))` для коригування лічильників розміру обох списків.

## 3. Гарантії інвалідації ітераторів та винятків

Спискові контейнери C++ забезпечують унікальні гарантії стійкості ітераторів та безпеки при винятках (Exception Safety):

### Правила інвалідації ітераторів та посилань

```
+-----------------------------------------------------------------------------------+
| Операція над контейнером | Вплив на ітератори та посилання у std::list / forward_list |
+-----------------------------------------------------------------------------------+
| push_back() / push_front()| Усі наявні ітератори та посилання залишаються ДІЙСНИМИ|
| insert() / emplace()     | Усі наявні ітератори та посилання залишаються ДІЙСНИМИ|
| erase(it) / pop_front()  | Інвалідується ВИКЛЮЧНО ітератор it видаленого елемента |
| splice()                 | Усі ітератори залишаються ДІЙСНИМИ (змінюють власника)|
| clear()                  | Інвалідуються УСІ ітератори та посилання             |
+-----------------------------------------------------------------------------------+
```

При виконанні `std::list::splice()` ітератори, що вказували на переміщені елементи, залишаються повністю робочими. Вони продовжують посилатися на ті самі елементи, але тепер при інкременті `++it` переходять по нових сусідах всередині нового списка-отримувача!

### Строга гарантія безпеки винятків (Strong Exception Guarantee)

Методи `push_back()`, `push_front()`, `emplace_back()` та `insert()` у `std::list` забезпечують строгу гарантію безпеки винятків: якщо під час створення нового вузла або копіювання/переміщення елемента `T` виникає виняток (Exception), стан списка залишається абсолютно незмінним. Ніяких частково доданих вузлів чи витоків пам'яті не відбувається.

## 4. Оптимізація пам'яті за допомогою Polymorphic Allocators (C++17 PMR)

Головний недолік `std::list` у промислових системах — це фрагментація купи через постійні виклики глобального аллокатора `malloc`/`free` на кожен вузол. У C++17 введено стандартний модуль **PMR (Polymorphic Memory Resource)** у заголовку `<memory_resource>`.

Завдяки `std::pmr::list<T>` розробник може підключити арений аллокатор пам'яті (`std::pmr::monotonic_buffer_resource` або `std::pmr::unsynchronized_pool_resource`). У цьому випадку всі вузли списка виділяються з одного заздалегідь підготовленого суцільного буфера в оперативній пам'яті. Це повністю усуває системні виклики виділення пам'яті та значно покращує кеш-локальність вузлів списка!

## 5. Приклади використання мовами C та C++

:::tabs
```c
/* kernel_list_example.c — Демонстрація інтрузивного списка Linux Kernel */
#include <stdio.h>
#include <stdlib.h>
#include <stddef.h>

/* Проста емуляція макросів ядра Linux */
struct list_head {
    struct list_head *next, *prev;
};

#define INIT_LIST_HEAD(ptr) do { \
    (ptr)->next = (ptr); (ptr)->prev = (ptr); \
} while (0)

#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

#define list_entry(ptr, type, member) \
    container_of(ptr, type, member)

#define list_for_each(pos, head) \
    for (pos = (head)->next; pos != (head); pos = pos->next)

/* Прикладна структура процесу, що містить інтрузивний list_head */
typedef struct {
    int pid;
    char name[32];
    struct list_head list_node; /* Вбудований вузол */
} ProcessTask;

static inline void list_add_tail(struct list_head *new_node, struct list_head *head) {
    struct list_head *prev_node = head->prev;
    new_node->next = head;
    new_node->prev = prev_node;
    prev_node->next = new_node;
    head->prev = new_node;
}

int main(void) {
    struct list_head process_list;
    INIT_LIST_HEAD(&process_list);

    /* Створюємо два процеси без додаткового allocation під вузли списка */
    ProcessTask p1 = {.pid = 101, .name = "systemd"};
    ProcessTask p2 = {.pid = 502, .name = "nginx"};

    list_add_tail(&p1.list_node, &process_list);
    list_add_tail(&p2.list_node, &process_list);

    /* Обхід списка за допомогою container_of */
    struct list_head *curr;
    list_for_each(curr, &process_list) {
        ProcessTask *task = list_entry(curr, ProcessTask, list_node);
        printf("Процес PID: %d, Назва: %s\n", task->pid, task->name);
    }

    return 0;
}
```
```cpp
// stl_list_example.cpp — Демонстрація ефективного використання std::list та splice
#include <iostream>
#include <list>
#include <string>
#include <algorithm>

int main() {
    std::list<std::string> main_queue = {"Task1", "Task2", "Task5"};
    std::list<std::string> priority_queue = {"UrgentTaskA", "UrgentTaskB"};

    // Знайдемо позицію перед Task5
    auto it = std::find(main_queue.begin(), main_queue.end(), "Task5");

    // splice() переміщує вузли з priority_queue у main_queue за O(1) без копіювання рядків!
    if (it != main_queue.end()) {
        main_queue.splice(it, priority_queue);
    }

    std::cout << "Головна черга після сплайсингу:\n";
    for (const auto& task : main_queue) {
        std::cout << " - " << task << "\n";
    }

    std::cout << "Розмір пріоритетної черги: " << priority_queue.size() << " (порожня)\n";

    return 0;
}
```
