# 🧮 Математичний аналіз та доведення швидкодії Quickselect

Ця вставка містить суворий математичний аналіз алгоритму Quickselect: виведення середнього лінійного часу виконання `O(n)`, аналіз ймовірностей вибору опорного елемента, розрахунок найгіршого випадку та повне індуктивне доведення детермінованої межі `O(n)` для алгоритму Median-of-Medians (BFPRT).

## 1. Формальна постановка задачі порядкових статистик

Розглянемо формальне математичне визначення задачі вибору порядкових статистик. Нехай задано масив `A`, який складається з `n` унікальних елементів, взятих із множини, на якій визначено відношення лінійного порядку. Елемент `x` з масиву `A` називається `k`-ю порядковою статистикою (англ. *k-th order statistic*), де порядковий номер `k` належить діапазону від `1` до `n`, якщо після впорядкування масиву `A` за зростанням цей елемент опиняється рівно на позиції з індексом `k - 1` у 0-індексованій нумерації масивів.

Задача вибору (англ. *selection problem*) полягає у знаходженні цього елемента `x` без необхідності повністю сортувати решту `n - 1` елементів масиву. Найпростіший спосіб розв'язання задачі вимагає повного сортування масиву за час `O(n log n)`, після чого елемент зчитується за індексом `k - 1` за час `O(1)`. Метою алгоритму Quickselect є зменшення загальної часової складності до суворо лінійної межі `O(n)`.

Оцінка часової складності алгоритму здійснюється за кількістю елементарних попарних порівнянь елементів, позначуваною як випадкова величина `C(n)`. Операції перестановки елементів та інкременту індексних лічильників вважаються математично пропорційними кількості порівнянь і враховуються у сукупній константі алгоритму. Знаходження порядкових статистик має принципове значення для побудови квантилей, медіанних фільтрів та аналізу розподілів у статистичному аналізі даних.

## 2. Найгірший випадок складності (Worst-case Analysis)

Проаналізуємо сценарій найгіршого випадку виконання Quickselect. Найгірший випадок виникає тоді, коли на кожному кроці процедури розбиття (англ. *partitioning*) обраний опорний елемент (англ. *pivot*) виявляється екстремальним значенням — тобто мінімальним або максимальним елементом у поточному діапазоні масиву.

Така ситуація систематично виникає, якщо вхідний масив уже відсортований у прямому чи зворотному порядку, а реалізація алгоритму послідовно вибирає як pivot крайній елемент діапазону (перший або останній). У цьому разі на кожному кроці розбиття масив розміром `m` ділиться на два вкрай неспівмірні підмасиви: один підмасив порожній (містить 0 елементів), а другий містить `m - 1` елементів.

Для розбиття підмасиву розміром `m` алгоритм змушений порівняти обраний pivot із кожним з решти `m - 1` елементів. Відповідно, рекурентне співвідношення для кількості порівнянь у найгіршому випадку `T_worst(n)` набуває наступного вигляду:

```
T_worst(n) = T_worst(n - 1) + (n - 1)
           = T_worst(n - 2) + (n - 2) + (n - 1)    [розгортання рекуренсії]
           = ∑ (i)  від i = 1 до n - 1              [сума арифметичної прогресії]
           = (n - 1)·n / 2                          [за формулою Гаусса]
           = (n² - n) / 2                           [розкриття дужок]
           = O(n²)                                  [квадратична асимптотична межа]
```

Отриманий вираз підтверджує, що сума порівнянь утворює класичну арифметичну прогресію. Перший крок виконує `n - 1` порівнянь, другий крок — `n - 2` порівнянь, і так далі аж до останнього порівняння єдиного елемента. Загальна кількість порівнянь дорівнює точній половині квадрата кількості елементів `(n² - n) / 2`. Таким чином, асимптотична складність найгіршого випадку Quickselect становить `O(n²)`. Це означає, що при відсутності заходів із захисту (таких як рандомізація або інтроспективна перевірка глибини рекурсії) алгоритм втрачає свою перевагу над звичайним сортуванням.

Крім того, виклики рекурсії в найгіршому випадку створюють стек глибиною `n`, що призводить до лінійних витрат додаткової пам'яті `O(n)` і загрожує переповненням стеку викликів під час обробки великих масивів даних у реальних комп'ютерних системах.

## 3. Математичний вивід середнього часу виконання (Average-case Analysis)

Розглянемо тепер середній випадок виконання алгоритму Quickselect. Сформулюємо математичне припущення про рівноймовірність: приймемо, що вхідний масив складається з `n` елементів у випадковому порядку, а вибір опорного елемента на кожному кроці здійснюється рівномірно і незалежно серед усіх доступних індексів.

При рівномірному виборі півота з підмасиву розміром `n`, ранг обраного півота `i` (де ранг `i` означає, що елемент займає `i`-е місце у відсортованому порядку, `1 ≤ i ≤ n`) приймає будь-яке значення від `1` до `n` з однаковою ймовірністю `P(i) = 1/n`.

Після виконання розбиття навколо півота з рангом `i` масив розділяється на два підмасиви:
- Лівий підмасив містить `i - 1` елементів, які менші або рівні за pivot.
- Правий підмасив містить `n - i` елементів, які більші або рівні за pivot.

На відміну від алгоритму Quicksort, який змушений рекурсивно обробляти обидві зони (витрачаючи `T(i - 1) + T(n - i)` операцій), Quickselect робить рекурсивний крок лише в один із двох підмасивів — залежно від того, де розташований індекс шуканої `k`-ї порядкової статистики.

Щоб отримати сувору верхню межу для математичного сподівання кількості порівнянь `E[C(n)]`, приймемо найгірший можливий сценарій рекурсивного вибору: припустимо, що шуканий елемент завжди опиняється в більшій за розміром частині масиву. Тоді верхня межа математичного сподівання кількості порівнянь `C(n)` задовольняє рекурентну нерівність:

```
C(n) ≤ (n - 1) + (1/n) · ∑ C(max(i - 1, n - i))   при сумуванні i від 1 до n
```

Проаналізуємо структуру внутрішньої суми у цій нерівності. Коли індекс `i` змінюється від `1` до `n`, значення виразу `max(i - 1, n - i)` набуває цілочисельних значень від `⌈n/2⌉` до `n - 1`. Оскільки вираз є симетричним відносно центра масиву, кожне таке значення зустрічається у сумі рівно два рази (для лівої та правої половин масиву). Це дозволяє спростити підсумовування та записати нерівність у більш зручній формі:

```
C(n) ≤ n + (2/n) · ∑ C(j)   при сумуванні j від ⌈n/2⌉ до n - 1
```

Для доведення того, що дана рекурентність має лінійний розв'язок `C(n) = O(n)`, застосуємо метод математичної індукції за розміром масиву `n`. Формулюємо індуктивну гіпотезу: припустимо, що існує така додатна константа `c > 0`, що для всіх масивів розміром `j < n` виконується оцінка `C(j) ≤ c · j`.

Підставимо індуктивне припущення у верхню межу рекурентної суми:

```
C(n) ≤ n + (2/n) · ∑ (c · j)                       [за індуктивним припущенням]
     = n + (2c/n) · ( (n - 1)·n / 2 - (n/2 - 1)·(n/2) / 2 ) [обчислення суми j]
     = n + (2c/n) · ( n²/2 - n/2 - n²/8 + n/4 )   [спрощення квадратних членів]
     = n + (2c/n) · ( 3n²/8 - n/4 )                [зведення подібних доданків]
     = n + 3c·n / 4 - c / 2                       [множення на 2c/n]
     = (3c/4 + 1)·n - c/2                         [винесення n за дужки]
```

Проаналізуємо отриманий алгебраїчний вираз `(3c/4 + 1)·n - c/2`. Для завершення індуктивного кроку нам необхідно довести, що цей вираз не перевищує `c · n` для всіх `n ≥ 1`.

Складаємо та розв'язуємо нерівність відносно константи `c`:

```
(3c/4 + 1)·n - c/2 ≤ c·n
(3c/4 + 1)·n ≤ c·n
3c/4 + 1 ≤ c                        [поділ на n > 0]
1 ≤ c - 3c/4                        [перенесення членів з c]
1 ≤ c/4                             [зведення 1 - 3/4 = 1/4]
c ≥ 4                               [множення обох частин на 4]
```

Результат розв'язання є фундаментальним: нерівність виконується для будь-якого `c ≥ 4`. Обираючи `c = 4`, ми отримуємо строге індуктивне доведення:

```
C(n) ≤ 4n = O(n)                    [строга верхня межа середнього часу]
```

Математичний висновок доводить, що середня кількість порівнянь у Quickselect за будь-якого розкладу даних та незалежно від конкретного значення індексу `k` не перевищує `4n`. Це дає суворо лінійну часову складність `O(n)`.

Детальніший аналіз Седжвіка дозволяє уточнити математичне сподівання кількості порівнянь `E[C(n, k)]` залежно від відносного положення шуканої порядкової статистики `k` у масиві:

```
E[C(n, k)] = 2·( n + k·ln(n/k) + (n - k + 1)·ln(n / (n - k + 1)) )
```

З цієї точної формули випливають важливі практичні характеристики складності:
- **Пошук екстремумів (`k = 1` або `k = n`):** вирази під логарифмами прямують до нульових значень, і кількість порівнянь прямує до `2n`. Це відповідає знаходженню мінімуму чи максимуму за два проходи.
- **Пошук медіани (`k = n/2`):** значення `ln(2)` дорівнює приблизно 0.693, що дає точну оцінку `2n + 2n·ln(2) ≈ 3.38 n` порівнянь.
- **Пошук квантилей (`k = n/4` або `k = 3n/4`):** середня кількість порівнянь становить приблизно `3.1 n`.

Таким чином, для найважчого випадку — знаходження медіани — пересічний Quickselect виконує в середньому лише `3.38 n` порівнянь, тоді як найшвидший алгоритм сортування Quicksort витрачає `2 n ln(n) ≈ 1.38 n log2(n)` порівнянь, що при `n = 10⁶` дає близько `27.6 n` порівнянь (у 8 разів більше за Quickselect).

## 4. Геометричний розподіл спроб та ймовірнісний аналіз

Щоб зрозуміти глибоку інтуїцію лінійності Quickselect, розглянемо ймовірнісну модель зрізання масиву через геометричний розподіл випадкових величин.

Сформулюємо визначення «хорошого» опорного елемента. Назвемо pivot «хорошим» (англ. *good pivot*), якщо він потрапляє у центральний міжквартильний діапазон масиву — тобто між 25-м та 75-м перцентилями відсортованого порядку (індекси від `n/4` до `3n/4`).

При абсолютно випадковому виборі елемента з масиву розміром `n`, ймовірність `p` того, що обраний pivot є «хорошим», обчислюється як відношення довжини центрального інтервалу до загальної довжини масиву:

```
p = (3n/4 - n/4) / n = (n/2) / n = 1/2
```

Це означає, що рівно кожен другий випадковий вибір півота є «хорошим». Головна властивість «хорошого» півота полягає в тому, що після розбиття масиву розмір найбільшої залишкової частини гарантовано зменшується щонайменше до `3/4` від початкового розміру `n`.

Оскільки кожна спроба вибору півота є незалежним випробуванням за схемою Бернуллі з ймовірністю успіху `p = 1/2`, кількість спроб `X` до отримання першого «хорошого» півота є випадковою величиною з геометричним розподілом `X ~ Geom(1/2)`.

Обчислимо математичне сподівання кількості випробувань `E[X]`:

```
E[X] = 1 / p = 1 / (1/2) = 2
```

Це означає, що в середньому алгоритм робить лише 2 випадкові спроби розбиття, щоб гарантовано скоротити розмір робочої області масиву щонайменше на 25%.

Розглянемо суму розмірів підмасивів на послідовних «хороших» кроках розбиття. Ця сума утворює спадну геометричну прогресію зі знаменником `q = 3/4`:

```
S_sum = n + (3/4)·n + (3/4)²·n + (3/4)³·n + ...
      = n · ∑ (3/4)ⁱ   при i від 0 до ∞    [сума нескінченної прогресії]
      = n · ( 1 / (1 - 3/4) )              [за формулою b1 / (1 - q)]
      = n · ( 1 / (1/4) )                  [обчислення 1 - 3/4 = 1/4]
      = 4n                                 [результат]
```

Отриманий геометричний аналіз надає просте і беззаперечне пояснення лінійності Quickselect: сума розмірів усіх оброблюваних підмасивів обмежена знаменником нескінченної прогресії і ніколи не перевищує `4n`. Практична швидкість алгоритму береться саме з цієї геометрії спадання обсягу даних.

## 5. Математичне доведення алгоритму Median-of-Medians (BFPRT)

Проаналізуємо детермінований алгоритм BFPRT (Median-of-Medians), який гарантує складність `O(n)` навіть у найгіршому випадку за рахунок спеціального вибору півота.

Опишемо математичну процедуру вибору півота в BFPRT:
1. Вхідний масив із `n` елементів ділиться на `⌈n/5⌉` груп по 5 елементів у кожній (остання група може містити менше 5 елементів).
2. У кожній 5-елементній групі знаходиться медіана. Оскільки розмір групи дорівнює 5, медіана знаходиться за допомогою не більше ніж 6 порівнянь. Сукупна кількість порівнянь на цьому кроці не перевищує `6 · (n/5) = 1.2 n`.
3. З отриманих `n/5` медіан рекурсивно викликається алгоритм BFPRT для знаходження їхньої спільної медіани, позначуваної як `M` (медіана медіан). Час цього кроку дорівнює `T(n/5)`.
4. Знайдена медіана медіан `M` використовується як опорний елемент для стандартного розбиття всього масиву.

Оцінимо кількість елементів масиву, які гарантовано менші або більші за обраний pivot `M`.

Оскільки `M` є медіаною `n/5` елементів, щонайменше половина з цих медіан (тобто `(1/2)·(n/5) = n/10` груп) є меншими або рівними `M`. Розглянемо кожну таку 5-елементну групу: у ній сам елемент медіани та два елементи, що менші за неї, гарантовано не перевищують `M`. Отже, кожна така група дає щонайменше 3 елементи, які менші або рівні `M`.

Враховуючи можливі неповні групи та крайні елементи, загальна кількість елементів `N_less`, які гарантовано не перевищують `M`, задовольняє нерівність:

```
N_less ≥ 3 · ( (1/2)·(n/5) - 2 ) = 3n/10 - 6
```

З міркувань симетрії, щонайменше така сама кількість елементів `3n/10 - 6` є строго більшою або рівною `M`.

Відповідно, у найгіршому випадку розмір підмасиву `N_next`, який залишається для рекурсивного кроку Quickselect після розбиття навколо `M`, не перевищує:

```
N_next ≤ n - (3n/10 - 6) = 7n/10 + 6
```

Тепер ми можемо вивести повне рекурентне співвідношення для часової складності алгоритму BFPRT `T(n)` у найгіршому випадку:

```
T(n) ≤ T(n/5) + T(7n/10 + 6) + d · n
```

де член `T(n/5)` відповідає рекурсивному знаходженню медіани медіан, член `T(7n/10 + 6)` відповідає рекурсивному кроку у більшу з двох половин, а `d · n` є константними витратами на знаходження медіан у 5-ках та процедуру розбиття (при `d ≈ 1.5`).

Доведемо за допомогою методу математичної індукції, що `T(n) ≤ c · n` для деякої константи `c > 0`.

Сформулюємо індуктивну гіпотезу: припустимо, що `T(k) ≤ c · k` для всіх `k < n`. Підставимо гіпотезу в рекурентність:

```
T(n) ≤ c · (n/5) + c · (7n/10 + 6) + d · n         [за індуктивним припущенням]
     = (c/5 + 7c/10 + d) · n + 6c                  [зведення подібних доданків при n]
     = (9c/10 + d) · n + 6c                        [обчислення 2c/10 + 7c/10 = 9c/10]
```

Проаналізуємо коефіцієнт при `n` у виразі `(9c/10 + d) · n + 6c`. Для виконання індуктивного кроку `T(n) ≤ c · n` нам необхідно забезпечити:

```
(9c/10 + d) · n + 6c ≤ c · n
c·n - 9c·n/10 ≥ d·n + 6c
(c/10) · n ≥ d·n + 6c                              [зведення c - 9c/10 = c/10]
```

Для досить великих значеннях `n` (зокрема, при `n ≥ 120`) член `6c` стає не більшим за `(c/10)·n / 2`:

```
(c/10) · n / 2 ≥ 6c  =>  c · n / 20 ≥ 6c  =>  n ≥ 120
```

Тоді для покриття решти `d · n` достатньо вимагати:

```
(c/10) · n / 2 ≥ d · n  =>  c / 20 ≥ d  =>  c ≥ 20 d
```

Принципово важливим математичним фактом є те, що сума коефіцієнтів рекурсивних викликів `1/5 + 7/10 = 9/10` є строго меншою за `1`. Згідно з класичною теоремою Акра-Баззі для лінійних рекурентностей, це гарантує, що розв'язок рекурентного рівняння є строго лінійним:

```
T(n) = O(n)                                        [строгий детермінований лінійний час]
```

Чому саме 5? Чому розбиття на групи по 3 елементи не дає лінійного часу?

Якщо розбити масив на групи по 3 елементи, то кількість медіан дорівнюватиме `n/3`. Кількість елементів, більших за медіану медіан, становитиме приблизно `2 · (n/6) = n/3`. Залишковий підмасив матиме розмір `n - n/3 = 2n/3`. Рекурентне рівняння для груп по 3 елементи набуде вигляду:

```
T_groups3(n) = T(n/3) + T(2n/3) + d · n
```

Сума коефіцієнтів у даному випадку дорівнює `1/3 + 2/3 = 1`. За теоремою про розгортання рекурентності, сума з коефіцієнтом `1` дає розв'язок `T(n) = O(n log n)`.

Отже, саме розмір групи 5 є мінімальним непарним числом, яке забезпечує суму коефіцієнтів `1/5 + 7/10 = 9/10 < 1` та гарантує детермінований лінійний час `O(n)`. Математична витонченість цього вибору полягає в тому, що 5 — найменше число, що дає суму коефіцієнтів нижчу за одиницю.

## 6. Зведена математична таблиця характеристик

Ніжченаведена таблиця підсумовує математичні характеристики варіантів Quickselect:

| Варіант алгоритму | Середній час E[T(n)] | Найгірший час T_worst(n) | Пам'ять за стеком (Stack Space) | Константа перед n у порівняннях |
|---|---|---|---|---|
| Класичний Quickselect (перший pivot) | `O(n)` (3.38 n) | `O(n²)` | `O(n)` (рекурсія) або `O(1)` (цикл) | ≈ 3.38 (медіана) |
| Рандомізований Quickselect | `O(n)` (3.38 n) | `O(n²)` (ймовірність → 0) | `O(log n)` або `O(1)` | ≈ 3.38 |
| Quickselect + Median-of-3 | `O(n)` (2.75 n) | `O(n²)` | `O(log n)` або `O(1)` | ≈ 2.75 |
| BFPRT (Median-of-Medians) | `O(n)` (16 n) | `O(n)` | `O(log n)` | ≈ 16 – 20 |
| Introselect (гібрид) | `O(n)` (2.75 n) | `O(n)` | `O(log n)` | ≈ 2.75 |

Математичні властивості показують, чому саме Introselect є оптимальним вибором для практичної інженерії: він забезпечує малу константу `2.75 n` на типових даних та гарантує суворе `O(n)` у найгіршому випадку.
