# 🧮 Математичний аналіз Quicksort: від рекурентності до середнього часу

Аналіз швидкодії алгоритму швидкого сортування (Quicksort) є одного з найвідоміших здобутків у галузі аналізу алгоритмів та теорії ймовірностей. На відміну від сортування злиттям (Mergesort), де розміри підзадач на кожному кроці строго дорівнюють `n / 2`, у Quicksort розміри лівої та правої частин залежать від випадкового значення виправдано обраного опорного елемента (pivot).

Цей документ містить математично точне виведення очікуваної кількості порівнянь елементів `E[T(n)]` у припущенні рівноймовірності всіх `n!` можливих перестановок вхідного масиву з `n` різних елементів, розрахунок дисперсії, а також аналіз нижніх меж складності сортування порівняннями.

## 1. Формулювання рекурентного рівняння

Нехай випадкова величина `T(n)` позначає кількість порівнянь ключів, необхідних для сортування масиву з `n` різних елементів.

У процедурі розбиття (як Ломуто, так і Гоара) обраний опорний елемент порівнюється з кожним із решти `n - 1` елементів підмасиву. Отже, вартість фази розбиття масиву розміром `n` становить рівно `n - 1` порівнянь ключів.

Після розбиття опорний елемент займає рангову позицію `k ∈ {1, 2, ..., n}`. Це означає, що лівий підмасив отримує `k - 1` елементів, а правий підмасив отримує `n - k` елементів.

Оскільки всі `n!` перестановок вхідних даних вважаються однаково ймовірними, ранг опорного елемента `k` може набути будь-якого значення від `1` до `n` з однаковою ймовірністю, яка дорівнює `1 / n`.

Записуємо математичне сподівання часу виконання `E[T(n)]` (для стислості позначимо його як `Tₙ = E[T(n)]`):

```
Tₙ = (n − 1) + (1 / n) · ∑ [Tₖ₋₁ + Tₙ₋▖]    [для k від 1 до n]
```

Придивимося до двох сум усередині виразу. Сума `∑ Tₖ₋₁` при `k` від 1 до `n` послідовно додає елементи `T₀, T₁, T₂, ..., Tₙ₋₁`. Друга сума `∑ Tₙ₋▖` при `k` від 1 до `n` додає ті самі елементи у зворотному порядку: `Tₙ₋₁, Tₙ₋₂, ..., T₀`. З огляду на комутативність додавання, обидві суми є тотожно рівними.

Це дозволяє спростити вираз і переписати рекурентне співвідношення у вигляді:

```
Tₙ = (n − 1) + (2 / n) · ∑ Tₖ               [для k від 0 до n − 1]
```

Базові граничні умови для малих масивів визначаються очевидно: порожній масив та масив із одного елемента вже впорядковані й не вимагають жодного порівняння, тобто:

```
T₀ = 0
T₁ = 0
```

## 2. Алгебраїчний розв'язок методом телескопування

Щоб позбутися знака підсумовування `∑ Tₖ`, застосуємо метод алгебраїчного телескопування. На першому кроці помножимо обидві частини співвідношення на `n`:

```
n · Tₙ = n · (n − 1) + 2 · ∑ Tₖ              [для k від 0 до n − 1; множення на n]
```

Запишемо тотожне рівняння для масиву розміром `n - 1`:

```
(n − 1) · Tₙ₋₁ = (n − 1) · (n − 2) + 2 · ∑ Tₖ  [для k від 0 до n − 2; запис для n - 1]
```

Віднімемо друге рівняння від першого. Зауважимо, що сума `2 · ∑ Tₖ` у першому рівнянні містить ті самі доданки, що й у другому, за винятком єдиного останнього додатка `2 · Tₙ₋₁`:

```
n · Tₙ − (n − 1) · Tₙ₋₁ 
= n·(n − 1) − (n − 1)·(n − 2) + 2 · Tₙ₋₁   [віднімання двох рівнянь]
= 2·(n − 1) + 2 · Tₙ₋₁                    [спрощення: n(n-1) - (n-1)(n-2) = 2(n-1)]
```

Перенесемо член `(n - 1) · Tₙ₋₁` у праву частину рівняння та згрупуємо коефіцієнти біля `Tₙ₋₁`:

```
n · Tₙ = (n + 1) · Tₙ₋₁ + 2·(n − 1)         [додано (n-1)Tₙ₋₁ до обох частин]
```

Щоб звести коефіцієнти при `Tₙ` та `Tₙ₋₁` до зручної канонічної форми, поділимо обидві частини отриманого рівняння на добуток `n · (n + 1)`:

```
Tₙ / (n + 1) = Tₙ₋₁ / n + 2·(n − 1) / (n · (n + 1))  [ділення на n(n+1)]
```

Розкладемо раціональний дріб `2 · (n - 1) / (n · (n + 1))` на суму найпростіших дробів:

```
2·(n − 1) / (n · (n + 1)) = 4 / (n + 1) − 2 / n       [розклад на прості доданки]
```

Позначимо нормовану змінну `Sₙ = Tₙ / (n + 1)`. Отримуємо просте телескопічне співвідношення:

```
Sₙ = Sₙ₋₁ + 4 / (n + 1) − 2 / n                      [заміна змінної Sₙ]
```

Розгортаємо телескопічну суму від `k = 2` до `n`:

```
Sₙ = S₁ + 4 · ∑ (1 / (k + 1)) − 2 · ∑ (1 / k)        [телескопічне сумування]
```

Зважаючи на те, що `S₁ = T₁ / 2 = 0`, розписуємо обидві суми через гармонічні числа `Hₙ = ∑ (1 / j)` для `j = 1..n`:

```
Sₙ = 2 · Hₙ + 4 / (n + 1) − 4                         [вираження через Hₙ]
```

Помножимо `Sₙ` назад на `(n + 1)`, щоб отримати остаточну точну формулу математичного сподівання кількості порівнянь:

```
Tₙ = 2·(n + 1)·Hₙ − 4·n                               [повернення від Sₙ до Tₙ]
```

## 3. Асимптотичний розклад та обчислення константи 1.386

Для великих `n` гармонічне число `Hₙ` виражається через натуральний логарифм за допомогою формули Ейлера — Маклорена:

```
Hₙ = ln n + γ + 1 / (2n) − 1 / (12n²) + O(1/n⁴)     [асимптотика гармонічного числа]
```

де `γ ≈ 0.5772156649` — стала Ейлера — Маскероні.

Підставимо асимптотичний розклад `Hₙ` у формулу для `Tₙ`:

```
Tₙ 
= 2 · (n + 1) · (ln n + γ + 1/(2n)) − 4 · n           [підстановка Hₙ]
= 2 · n · ln n + 2 · n · γ + 2 · ln n + 2 · γ + 1 − 4 · n + O(1/n)  [раскрытие дужок]
= 2 · n · ln n + (2·γ − 4) · n + 2 · ln n + (2·γ + 1) + O(1/n)       [групування за ступенями n]
```

Обчислимо константу при `n`: `2 · γ - 4 = 2 · (0.57721566) - 4 ≈ -2.845568`.

Отримуємо асимптотичну формулу в натуральних логарифмах:

```
Tₙ = 2 · n · ln n − 2.845568 · n + 2 · ln n + 2.1544   [підстановка числових констант]
```

Перейдемо від натурального логарифма `ln n` до двійкового логарифма `log₂ n`, скориставшись математичною тотожністю `ln n = (ln 2) · log₂ n`:

```
2 · ln n = 2 · (ln 2) · log₂ n = 2 · (0.69314718) · log₂ n ≈ 1.38629436 · log₂ n
```

Таким чином, підсумкове математичне сподівання кількості порівнянь алгоритму Quicksort у середньому випадку становить:

```
E[T(n)] = 1.386294 · n · log₂ n − 2.845568 · n         [остаточна формула в log₂ n]
```

## 4. Порівняння з теоретичною нижньою межею сортування

У теорії складності алгоритмів доведено теорему про нижню межу сортування порівняннями: будь-який детермінований чи ймовірнісний алгоритм, який сортує `n` елементів шляхом їхніх парних порівнянь, у найгіршому випадку мусить виконати щонайменше `⌈log₂ (n!)⌉` порівнянь.

За формулою Стірлінга розгортаємо логарифм факторіала:

```
log₂ (n!) 
= n · log₂ n − (log₂ e) · n + (1/2) · log₂ (2πn) + O(1/n)  [формула Стірлінга]
= n · log₂ n − 1.442695 · n + 0.5 · log₂ (2πn)              [підстановка log₂ e]
```

Порівняємо середня кількість порівнянь Quicksort з абсолютним теоретичним мінімумом:

```
E[T(n)] / log₂ (n!) = (1.386294 · n · log₂ n) / (1.000000 · n · log₂ n) = 2 · ln 2 ≈ 1.386294
```

Це дивовижний математичний результат: **Quicksort у середньому виконує лише на 38.63% більше порівнянь, ніж абсолютний теоретичний мінімум**, можливий для будь-якого сортування порівняннями.

## 5. Дисперсія часу виконання та концентрація маси

Середнє значення `E[T(n)] = O(n log n)` само по собі не гарантує практичної стабільності, якщо дисперсія випадкової величини є занадто великою. Якщо відхилення від середнього були б суттєвими, алгоритм часто сповільнювався б на реальних даних.

Детальний аналіз дисперсії кількості порівнянь Quicksort, виконаний Робертом Седжвіком та Дональдом Кнутом, дав точну асимптотичну формулу для `Var[T(n)]`:

```
Var[T(n)] = (7 − 2 · π² / 3) · n² − 2 · (n + 1) · H♁ + O(n)  [формула дисперсії Седжвіка]
```

Обчислимо числову константу при `n²`:

```
7 − 2 · π² / 3 = 7 − 2 · (9.8696044) / 3 = 7 − 6.579736 ≈ 0.4202636
```

Отже, дисперсія дорівнює:

```
Var[T(n)] = 0.420264 · n²                              [асимптотична дисперсія]
```

Середньоквадратичне відхилення `σ(n) = √(Var[T(n)])` зростає лінійно зі зростанням `n`:

```
σ(n) = √(0.420264) · n ≈ 0.648277 · n                 [середньоквадратичне відхилення]
```

Порівняємо середньоквадратичне відхилення `σ(n)` з очікуваним значенням `E[T(n)]`:

```
σ(n) / E[T(n)] = (0.648 · n) / (1.386 · n · log₂ n) ≈ 0.467 / log₂ n
```

Оскільки відношення `σ(n) / E[T(n)]` прямує до нуля при `n → ∞`, за нерівністю Чебишова ймовірність відхилення реального часу виконання Quicksort від математичного сподівання більш ніж на декілька відсотків прагне до нуля. Це доводить, що випадковий час Quicksort дуже щільно концентрується навколо значення `1.386 n log₂ n`.

## 6. Кількість обмінів елементів (Swaps)

Окрім порівнянь ключів, суттєвим фактором швидкодії є кількість обмінів (swaps) осередків пам'яті.

1. **Схема Ломуто:** Елемент міняється місцями щоразу, коли він не перевищує pivot. Очікувана кількість обмінів становить:

```
E[Swaps_Lomuto(n)] = (1 / 2) · n · ln n + O(n) ≈ 0.3465 · n · log₂ n  [обміни Ломуто]
```

2. **Схема Гоара:** Елементи міняються місцями лише тоді, коли лівий вказівник знайшов елемент `> pivot`, а правий — елемент `< pivot`. Очікувана кількість обмінів становить:

```
E[Swaps_Hoare(n)] = (1 / 6) · n · ln n + O(n) ≈ 0.1155 · n · log₂ n   [обміни Гоара]
```

Отже, математичний аналіз підтверджує, що схема Гоара робить у **3 рази менше обмінів пам'яті**, ніж схема Ломуто, що робить її значно вигіднішою для великих об'єктів у пам'яті.

## 7. Складність 3-way partition на дублікатах

Якщо вхідний масив містить лише `k` унікальних ключів із частотами `p₁, p₂, ..., pₖ` (де `∑ pᵢ = 1`), тристороннє розбиття (3-way partition) Седжвіка — Дейкстри вилучає всі однакові елементи `= pivot` з дальшої рекурсії за один прохід.

Математичне сподівання кількості порівнянь у цьому випадку обмежене ентропією Шеннона розподілу ключів:

```
E[T(n, k)] = O(n · H(p₁, p₂, ..., pₖ)) = O(n · ∑ [pᵢ · log₂ (1 / pᵢ)])  [ентропійна межа]
```

У найгіршому для 3-way випадку, коли всі `k` ключів зустрічаються однаково часто (`pᵢ = 1 / k`), це дає `O(n log k)`. Якщо ж усі елементи масиву однакові (`k = 1`), ентропія дорівнює 0, і алгоритм завершує роботу за один прохід за **`O(n)`** порівнянь.
