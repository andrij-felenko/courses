# 🧮 Математичний аналіз Timsort: ентропія серій, межі злиття та інваріанти

Оцінка алгоритму сортування в академічній літературі часто зводиться до єдиного виразу найгіршого випадку `O(N log N)`. Проте для адаптивного сортування така характеристика приховує найважливіше: точну кількість операцій порівняння як функцію від внутрішньої ентропії вхідних даних, строгі межі глибини рекурсивного стека, математичний доказ інваріантів злиття, збереження інваріанта стабільності та точку беззбитковості між лінійним скануванням і експоненційним пошуком. Ця вставка містить строгий математичний розрахунок і виведення ключових механік Timsort: вибору базової довжини серії `minrun`, складності бінарного розширення коротких серій, обмеження висоти стека через числа Фібоначчі, доведення дефекту та коректності 4-елементного інваріанта стека, досягнення інформаційно-теоретичної ентропійної межі Макілроя, доведення стабільності операцій, обмеження динамічної пам'яті та розрахунку ефективності режиму галопу.

## Алгебра вибору minrun: збалансованість дерева злиття

Основна мета вибору константи `minrun` полягає в тому, щоб загальна кількість серій `k = ⌈N / minrun⌉` була або точно степенем двійки `2^m`, або знаходилася трохи нижче степеня двійки (наприклад, `2^m - 1` чи `2^m - 2`). 

Якщо `k` є точним степенем двійки, дерево попарного злиття серій стає ідеально збалансованим бінарним деревом: на кожному рівні зливаються блоки однакового або близького розміру. Якщо ж `k` трохи перевищує степінь двійки (наприклад, `k = 2^m + 1`), то на останньому кроці алгоритму доведеться зливати величезний накопичений блок розміром майже `N` із крихітним залишковим блоком розміром `minrun`, що призводить до зайвих копіювань пам'яті та руйнування симетрії обчислень.

Для масивів розміром `N < 64` встановлюється `minrun = N` (сортування повністю зводиться до сортування вставками без фази злиття). Для `N ≥ 64` алгоритм вибирає число в замкненому діапазоні `[32, 64]` за наступним бітовим правилом:

```
minrun(N):
  r = 0
  поки N >= 64:
    r = r | (N & 1)     [акумуляція молодших бітів]
    N = N >> 1          [побітовий зсув вправо]
  повернути N + r
```

### Доведення меж значення minrun

Доведемо, що результуюче значення завжди лежить у межах `32 ≤ minrun ≤ 64`:

1. Цикл зсуву завершується в той момент, коли поточне значення `N` задовольняє умову `N < 64`. Оскільки на попередньому кроці виконувалося `N ≥ 64`, після останнього ділення на 2 число потрапляє в діапазон `32 ≤ N ≤ 63`.
2. Змінна `r` є бітовим прапорцем: `r = 1`, якщо хоча б один зі зміщених молодших бітів був одиницею, і `r = 0`, якщо всі відкинуті біти були нулями.
3. Якщо `N = 63` і `r = 1`, підсумкове значення дорівнює `63 + 1 = 64`.
4. Якщо `N = 32` і `r = 0`, підсумкове значення дорівнює `32 + 0 = 32`.
5. Отже, для будь-якого вхідного розміру `N` значення `minrun` строго належить відрізку `[32, 64]`.

При такому виборі кількість серій `k = N / minrun` з високою точністю дорівнює степеню двійки, оскільки відкидання молодших бітів залишає рівно 6 найстарших значущих бітів числа `N`.

## Складність подовження серій сортуванням бінарними вставками

Якщо виявлена природна серія має довжину `L < minrun`, алгоритм примусово подовжує її до розміру `min(minrun, N - start)` шляхом поглинання наступних елементів вхідного масиву за допомогою сортування бінарними вставками (Binary Insertion Sort).

Нехай поточна відсортована частина має довжину `i` (де `L ≤ i < minrun`). Для вставки чергового елемента алгоритм виконує двійковий пошук точки вставки серед `i` вже впорядкованих елементів, після чого здійснює блоковий зсув відрізка пам'яті.

### Розрахунок кількості порівнянь

Двійковий пошук у масиві довжиною `i` вимагає точно `⌈log₂(i + 1)⌉` операцій порівняння. Загальна кількість порівнянь `C_ins` для подовження серії від довжини `L` до `minrun` виражається сумою:

```
C_ins = ∑_{i=L}^{minrun - 1} ⌈log₂(i + 1)⌉
```

Для типового діапазону `32 ≤ minrun ≤ 64` логарифм `⌈log₂(i + 1)⌉` набуває значень 5 або 6. У найгіршому випадку, коли природна серія складалася лише з одного елемента (`L = 1`), а `minrun = 64`, кількість порівнянь обмежена:

```
C_ins <= 63 · 6 = 378 порівнянь
```

### Розрахунок кількості зсувів пам'яті

У середньому при випадковому розподілі ключів новий елемент вставляється в середину відсортованого відрізка, що вимагає зсуву `i / 2` елементів. Загальна кількість переміщень елементів виводиться за формулою:

```
M_ins
= ∑_{i=L}^{minrun - 1} (i / 2)                      [середнє зміщення для одного елемента]
= (1 / 2) · ∑_{i=L}^{minrun - 1} i                  [винесення константи 1/2 за знак суми]
= (1 / 4) · (minrun · (minrun - 1) - L · (L - 1))   [формула суми арифметичної прогресії]
```

Для `minrun = 64` та `L = 1` середня кількість зсувів складає приблизно `(64 · 63) / 4 = 1008` операцій копіювання слів. Оскільки ці операції виконуються над невеликим неперервним блоком пам'яті обсягом менше 512 байтів, увесь відрізок гарантовано вміщується в кеш L1 процесора, а копіювання здійснюється високоефективними векторними інструкціями процесора (`memmove`). Це пояснює, чому для малих масивів сортування бінарними вставками перевершує за реальною швидкістю будь-які рекурсивні алгоритми злиття чи швидкого розбиття.

## Інваріанти стека та межа висоти через числа Фібоначчі

Для збереження просторової локальності та контролю пам'яті дескриптори виділених серій зберігаються у стеку. Нехай довжини верхніх серій на стеку позначаються від верхівки до глибини як `A = len(stack[top])`, `B = len(stack[top-1])`, `C = len(stack[top-2])`, `D = len(stack[top-3])`.

Для забезпечення логарифмічної висоти стека підтримуються інваріанти злиття:

```
1. len(C) > len(B) + len(A)
2. len(B) > len(A)
```

### Теорема про зростання довжин серій

Доведемо, що за умови дотримання цих інваріантів довжини серій на стеку зростають щонайменше зі швидкістю чисел Фібоначчі.

Нехай `S` — кількість активних серій на стеку, а `R_i` — довжина серії на глибині `i` від верхівки (де `R_0 = A`, `R_1 = B`, `R_2 = C`, ..., `R_{S-1}` — основа стека).

Базові випадки визначаються мінімальною довжиною серії після фази бінарних вставок:

```
R_0 >= minrun
R_1 > R_0 >= minrun
```

Для будь-якого індексу `i ≥ 2` з першого інваріанта випливає нерівність:

```
R_i > R_{i-1} + R_{i-2}
```

Розглянемо класичну послідовність чисел Фібоначчі `F_0 = 0, F_1 = 1, F_2 = 1, F_3 = 2, F_4 = 3, F_5 = 5, ...`, де `F_{n} = F_{n-1} + F_{n-2}`.

Застосуємо метод математичної індукції:
- База індукції: `R_0 ≥ minrun = minrun · F_2`, `R_1 ≥ minrun = minrun · F_2`.
- Для `R_2`: `R_2 > R_1 + R_0 ≥ minrun + minrun = 2 · minrun = minrun · F_3`.
- Припущення індукції: нехай для всіх `j < i` виконується нерівність `R_j ≥ minrun · F_{j+1}`.
- Крок індукції для глибини `i`:

```
R_i > R_{i-1} + R_{i-2}
    >= minrun · F_i + minrun · F_{i-1}    [за припущенням індукції]
    = minrun · (F_i + F_{i-1})             [винесення minrun за дужки]
    = minrun · F_{i+1}                     [за рекурентним означенням Фібоначчі]
```

Таким чином, для будь-якого елемента стека з індексом `i` довжина серії обмежена знизу масштабованим числом Фібоначчі:

```
R_i >= minrun · F_{i+1}
```

### Верхня межа глибини стека

Загальний розмір масиву `N`, що містить усі серії, які одночасно знаходяться на стеку, дорівнює сумі їхніх довжин:

```
N = ∑_{i=0}^{S-1} R_i
  >= minrun · ∑_{i=0}^{S-1} F_{i+1}
  = minrun · (F_{S+2} - 1)                [тотожність суми ряду Фібоначчі]
```

З формули Біне відомо, що `F_n = (φⁿ - ψⁿ) / √5`, де `φ = (1 + √5) / 2 ≈ 1.6180339887` — золотий перетин, а `ψ = (1 - √5) / 2 ≈ -0.6180339887`.

Отже, для кількості серій `S`:

```
N >= minrun · (φ^{S+2} / √5 - 1)
```

Логарифмуючи нерівність за основою золотого перетину `φ`:

```
S <= log_φ(N / minrun) + log_φ(√5) - 2
S <= 1.4404 · log₂(N / minrun) + 0.67
```

Для масиву з максимальним 32-бітним індексом `N = 2^31 - 1 ≈ 2.14 × 10^9` при `minrun = 32`:

```
S <= 1.4404 · log₂(2^31 / 32) + 0.67
   = 1.4404 · 26 + 0.67
   ≈ 38.1
```

Для 64-бітного простору адрес `N = 2^64 - 1`:

```
S <= 1.4404 · log₂(2^64 / 32) + 0.67
   = 1.4404 · 59 + 0.67
   ≈ 85.6
```

Отже, стек розміром у **40 елементів** математично гарантує непереповнення для будь-якого 32-бітного масиву, а стек розміром у **85 елементів** повністю забезпечує 64-бітну архітектуру.

## Математичний розбір контрприкладу де Хау та 4-елементний інваріант

У 2015 році формальна верифікація за допомогою системи KeY довела, що перевірки лише трьох верхніх серій `A, B, C` недостатньо для гарантування інваріанта глибини.

Розглянемо рекурентну послідовність довжин серій, яка обходить класичну перевірку Пітерса:

```
R_0 = 120
R_1 = 80
R_2 = 25
R_3 = 20
```

Перевірка трьох верхніх елементів `(A=20, B=25, C=80)` показує:
- `len(C) > len(B) + len(A)` тобто `80 > 25 + 20 = 45` (виконано).
- `len(B) > len(A)` тобто `25 > 20` (виконано).

Алгоритм не запускає злиття, вважаючи стек збалансованим. Проте розгляд четвірки серій `(A=20, B=25, C=80, D=120)` виявляє приховану проблему: якщо на наступному кроці надходить нова серія, порушення інваріанта між `D` та `(C + B)` не призводить до злиття на потрібній глибині, накопичуючи надлишкові дескриптори.

Щоб усунути цю вразливість, сучасний стандарт Timsort містить розширене правило:

```
1. len(D) > len(C) + len(B)    [якщо на стеку є щонайменше 4 елементи]
2. len(C) > len(B) + len(A)    [якщо на стеку є щонайменше 3 елементи]
3. len(B) > len(A)             [якщо на стеку є щонайменше 2 елементи]
```

Це математично гарантує монотонне зростання суми довжин сусідніх серій на будь-якій глибині стека і виключає можливість виходу за межі виділеного буфера дескрипторів.

## Досягнення ентропійної межі Макілроя

Теоретична складність сортування порівняннями для масиву випадкових даних обмежена знизу інформаційною ентропією `⌈log₂(N!)⌉ ≈ N log₂ N - 1.4427 N`. Якщо масив розбитий на `k` природних впорядкованих серій довжинами `L_1, L_2, ..., L_k`, де `∑_{i=1}^k L_i = N`, простір можливих перестановок звужується.

Кількість перестановок `M`, які зберігають внутрішній порядок кожної з `k` серій, визначається поліноміальним коефіцієнтом:

```
M = N! / (L_1! · L_2! · ... · L_k!)
```

Застосуємо наближення Стірлінга `ln(n!) = n ln n - n + O(ln n)` до двійкового логарифма кількості перестановок:

```
log₂(M)
= log₂(N!) - ∑_{i=1}^k log₂(L_i!)                          [властивість логарифма частки]
= (N log₂ N - N) - ∑_{i=1}^k (L_i log₂ L_i - L_i) + O(k log N) [наближення Стірлінга]
= N log₂ N - ∑_{i=1}^k L_i log₂ L_i                        [скорочення доданків N = ∑ L_i]
```

Позначимо частку масиву, яку займає `i`-та серія, як `p_i = L_i / N`. Виразимо логарифм через частки `p_i`:

```
log₂(M)
= N log₂ N - ∑_{i=1}^k (p_i · N) · log₂(p_i · N)           [підстановка L_i = p_i · N]
= N log₂ N - N · ∑_{i=1}^k p_i · (log₂ N + log₂ p_i)       [розклад логарифма добутку]
= N log₂ N - N log₂ N · (∑_{i=1}^k p_i) - N · ∑_{i=1}^k p_i log₂ p_i [розкриття дужок]
= N log₂ N - N log₂ N · 1 - N · ∑_{i=1}^k p_i log₂ p_i    [сума часток ∑ p_i = 1]
= N · ( - ∑_{i=1}^k p_i log₂ p_i )                         [винесення множника N]
= N · H(p_1, p_2, ..., p_k)                                [означення ентропії Шеннона]
```

де `H(p_1, ..., p_k) = - ∑_{i=1}^k p_i log₂ p_i` — інформаційна ентропія розподілу довжин серій.

Завдяки збалансованому підтриманню інваріантів злиття на стеку Timsort досягає оптимальної складності за кількістю порівнянь:

```
C_total = O(N + N · H)
```

Це доводить, що Timsort є інформаційно-оптимальним адаптивним алгоритмом сортування.

## Математичне доведення збереження стійкості (Stability Proof)

Стійкість алгоритму сортування означає, що для будь-якої пари елементів `x_p` та `x_q` із ключами `key(x_p) == key(x_q)`, якщо `p < q` у вихідному масиві, то після впорядкування їхні підсумкові індекси `p'` та `q'` задовольняють умову `p' < q'`.

Доведемо, що кожен етап Timsort строго зберігає інваріант відносного порядку:

1. **Інверсія спадних серій:** Природна спадна серія визначається строгою нерівністю `x_k > x_{k+1}`. Якщо зустрічаються два елементи з однаковими ключами `x_k == x_{k+1}`, спадна серія негайно переривається. Таким чином, однакові елементи ніколи не потрапляють у спадний відрізок і ніколи не міняються місцями під час інверсії.
2. **Бінарні вставки:** При подовженні серії двійковий пошук знаходить найправішу можливу позицію вставки через пошук першого елемента, що строго більший за `key(x)`. У результаті новий елемент поміщається **після** всіх уже наявних елементів із таким самим ключем, зберігаючи часовий порядок надходження.
3. **Злиття `merge_lo`:** При виборі між `A[i]` та `B[j]` за умови рівності ключів `A[i] == B[j]` алгоритм завжди віддає пріоритет елементу `A[i]` з лівої серії, записуючи його першим.
4. **Злиття `merge_hi`:** При правосторонньому злитті за умови `A[i] == B[j]` алгоритм обирає елемент `B[j]` з правої серії та розміщує його в праву (старшу) позицію підсумкового відрізка. Елемент `A[i]` залишається ліворуч від `B[j]`.

Отже, жодна операція Timsort не порушує відносного взаємного розташування еквівалентних ключів, що доводить абсолютну стабільність алгоритму.

## Обмеження тимчасової пам'яті при злитті

Класичне сортування злиттям вимагає виділення допоміжного масиву повного розміру `N`. Timsort оптимізує використання оперативної пам'яті, зливаючи лише дві суміжні серії `A` та `B` за один крок і копіюючи в тимчасовий буфер виключно **меншу** з двох серій:

- Якщо `len(A) ≤ len(B)`, процедура `merge_lo` копіює серію `A` у тимчасовий буфер обсягом `len(A)`. Злиття відбувається зліва направо прямо в пам'ять `A` та `B`.
- Якщо `len(B) < len(A)`, процедура `merge_hi` копіює серію `B` у тимчасовий буфер обсягом `len(B)`. Злиття відбувається справа наліво.

### Теорема про максимальний обсяг буфера

Доведемо, що максимальний розмір виділеного динамічного буфера ніколи не перевищує `N / 2`.

Нехай виконується злиття двох суміжних серій `A` та `B`, сумарна довжина яких `len(A) + len(B) ≤ N`.
Обсяг пам'яті буфера `V_buf` становить:

```
V_buf = min(len(A), len(B))
```

Оскільки для будь-яких двох додатних чисел `min(a, b) ≤ (a + b) / 2`, маємо:

```
V_buf <= (len(A) + len(B)) / 2 <= N / 2
```

Крім того, попередній двійковий пошук меж звужує реальні робочі діапазони серій:
- Початкові елементи `A`, які менші за перший елемент `B`, вже стоять на своїх фінальних місцях і не копіюються в буфер.
- Фінальні елементи `B`, які більші за останній елемент `A`, вже стоять на своїх фінальних місцях і не беруть участі у злитті.

Це суттєво зменшує фактичний обсяг виділеної та переміщуваної пам'яті на практиці до значень, значно менших за теоретичну межу `N / 2`.

## Математична оптимізація режиму галопу

Під час злиття двох серій `A` та `B` стандартний покроковий алгоритм порівнює поточні головні елементи `A[i]` та `B[j]`. Якщо один масив виграє підряд `MIN_GALLOP` разів (за замовчуванням 7), Timsort перемикається в режим галопу (Galloping Mode).

Нехай елемент `x = A[i]` має бути вставлений у відсортований масив `B[j .. j+m]`, причому правильна позиція знаходиться на відстані `m` від поточного вказівника.

### Порівняння вартості пошуку

1. **Лінійний пошук (Linear Scan):**
   - Послідовно порівнює `x` з `B[j], B[j+1], ..., B[j+m]`.
   - Кількість порівнянь: `C_lin = m`.

2. **Експоненційний стрибковий пошук (Gallop):**
   - Перевіряє зміщення `2^0 - 1, 2^1 - 1, 2^2 - 1, ..., 2^p - 1`, доки не знайдеться таке `p`, що `B[j + 2^p - 1] ≥ x` або досягнуто кінець серії.
   - Кількість кроків для локалізації інтервалу: `p = ⌊log₂(m)⌋ + 1`.
   - Інтервал пошуку звужується до відрізка довжиною `2^p - 2^{p-1} = 2^{p-1} ≤ m`.
   - Двійковий пошук усередині цього інтервалу вимагає: `C_bin = ⌈log₂(2^{p-1})⌉ = p - 1`.
   - Загальна кількість порівнянь галопу:

```
C_gal = p + (p - 1) = 2p - 1 = 2 · ⌊log₂(m)⌋ + 1
```

### Точка беззбитковості (Break-even point)

Знайдемо критичне значення довжини стрибка `m`, починаючи з якого галоп стає вигіднішим за покрокове лінійне порівняння:

```
C_gal < C_lin
2 · log₂(m) + 1 < m
```

Розрахуємо значення для невеликих `m`:
- `m = 1`: `C_lin = 1`, `C_gal = 2 · 0 + 1 = 1` (паритет).
- `m = 3`: `C_lin = 3`, `C_gal = 2 · 1 + 1 = 3` (паритет).
- `m = 6`: `C_lin = 6`, `C_gal = 2 · 2 + 1 = 5` (`C_gal < C_lin`).
- `m = 7`: `C_lin = 7`, `C_gal = 2 · 2 + 1 = 5` (економія 2 порівняння).
- `m = 100`: `C_lin = 100`, `C_gal = 2 · 6 + 1 = 13` (економія у 7.7 раза).

Таким чином, поріг `MIN_GALLOP = 7` є строго математично обґрунтованим: він гарантує, що перехід у режим галопу відбувається лише тоді, коли математичне сподівання довжини однорідного блоку `m` перевищує точку гарантованої переваги експоненційного пошуку над лінійним.

### Адаптивне динамічне регулювання порогу

Щоб уникнути штрафу на випадкових даних, де довгі однакові серії чергуються зі збігами, Timsort адаптує поріг `min_gallop`:
- Якщо режим галопу успішно знайшов блок довжиною понад 7 елементів, поріг зменшується на одиницю: `min_gallop = max(1, min_gallop - 1)`. Це полегшує повторний вхід у галоп на сильно структурованих даних.
- Якщо режим галопу дав короткий блок і перервався, поріг збільшується на одиницю: `min_gallop = min_gallop + 1`. Це діє як від'ємний зворотний зв'язок, захищаючи алгоритм від зайвих накладних витрат на випадкових послідовностях.

## Порівняння з моделлю потужності вузлів (Powersort)

Для подолання евристичної природи інваріантів стека сучасні дослідження (зокрема праця Вільда та Мунро 2018 року) формалізували задачу злиття серій через концепцію майже оптимальних двійкових дерев пошуку.

У моделі Powersort кожна межа між сусідніми серіями `R_i` та `R_{i+1}` отримує математичну характеристику — «потужність вузла» (node power) `P(i)`. Нехай серія `R_i` займає відрізок від індексу `s_1` до `e_1`, а серія `R_{i+1}` — від `s_2` до `e_2` у нормалізованому інтервалі `[0, 1]`. Середні точки цих серій позначаються як `mid_1 = (s_1 + e_1) / (2N)` та `mid_2 = (s_2 + e_2) / (2N)`.

Потужність межі `P(i)` визначається як індекс найстаршого біта, у якому двійкові представлення дійсних чисел `mid_1` та `mid_2` вперше різняться:

```
P(i) = min { j in N : floor(mid_1 * 2^j) != floor(mid_2 * 2^j) }
```

Алгоритм підтримує стек, де потужності меж строго спадають. Коли нова межа має потужність, вищу або рівну за попередню, запускається злиття. На відміну від інваріантів Timsort, які оцінюють лише суми розмірів кількох сусідніх серій, підхід Powersort заздалегідь визначає глобально оптимальне дерево злиття, що зменшує загальну кількість порівнянь на частково впорядкованих даних ще на 1–2% і повністю усуває потребу в складних інваріантах глибини стека.
