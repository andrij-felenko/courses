# 📋 Специфікація інтерфейсу та системний контракт Відрізкового Дерева

Цей документ визначає формальний програмний контракт, сигнатури функцій, типів даних, асимптотичні оцінки складності та гарантії надійності для абстракції відрізкового дерева (англ. *Segment Tree*). Специфікація охоплює як класичні точкові модифікації, так і інтервальні оновлення з відкладеною пропогацією (англ. *lazy propagation*), а також розширені динамічні та персистентні моделі.

Призначення контракту — надати точні правила інтеграції структури даних у системні рушії баз даних, геоінформаційні комплекси (GIS), компілятори та високонавантажені серверні додатки.

## 1. Контракти типів даних та параметри ініціалізації

Відрізкове дерево функціонує над абстрактним алгебраїчним моноїдом `(S, ⊕, e)`. Для забезпечення коректності обчислень системний контракт вимагає формального визначення носія множини `S`, оператора об'єднання `⊕` та нейтрального елемента `e`.

### 1.1. Структури даних у мовах C та C++

У мові C відрізкове дерево подається у вигляді екземпляра структури `segment_tree_t` або `lazy_seg_tree_t`, де ресурси пам'яті виділяються динамічно в кучі. У C++ застосовується шаблонний клас `SegmentTree<T, CombineOp>`.

:::tabs
```c
typedef struct {
    long long* tree;    /* Динамічний масив вузлів дерева розмірності 4N */
    size_t n;           /* Кількість елементів у вичатковому масиві */
} segment_tree_t;

typedef struct {
    long long* tree;    /* Динамічний масив агрегованих значень (4N) */
    long long* lazy;    /* Динамічний масив відкладених поміток (4N) */
    size_t n;           /* Кількість елементів у вичатковому масиві */
} lazy_seg_tree_t;
```
```cpp
template <typename T, typename CombineOp = std::plus<T>>
class SegmentTree {
private:
    std::size_t n_;
    T identity_;
    CombineOp op_;
    std::vector<T> tree_;
};

template <typename T, typename CombineOp = std::plus<T>, typename LazyOp = std::plus<T>>
class LazySegmentTree {
private:
    std::size_t n_;
    std::vector<T> tree_;
    std::vector<T> lazy_;
};
```
:::

**Вимоги до пам'яті та вирівнювання:**
- Масив `tree` має бути виділений для `4 * N` елементів типу `long long`.
- Для відкладеної пропогації масив `lazy` має бути виділений для `4 * N` елементів і проініціалізований нульовими потичками (`calloc`).
- Пойнтери `tree` та `lazy` повинні бути вирівняні в пам'яті щонайменше за межею `alignof(max_align_t)` (8 або 16 байт) для виключення неузгоджених читань. У високонавантажених SIMD-обчисленнях застосовують вирівнювання за межею 64 байти (кеш-лінія x86_64).

### 1.2. Шаблонний клас у мові C++

У мові C++20 відрізкове дерево реалізується як шаблонний клас `SegmentTree<T, CombineOp>`, де тип `T` задовольняє вимогам концепту `std::movable` та `std::copyable`.

:::tabs
```c
/* Контракт сумісності типів С */
typedef long long element_t;
typedef element_t (*combine_fn)(element_t, element_t);
```
```cpp
template <typename T, typename CombineOp = std::plus<T>>
class SegmentTree;

template <typename T, typename CombineOp = std::plus<T>, typename LazyOp = std::plus<T>>
class LazySegmentTree;
```
:::

**Параметри шаблону:**
- `T`: тип даних, що зберігаються у вузлах дерева (наприклад, `long long`, `double`, `std::size_t` або користувацька структура).
- `CombineOp`: бінарний функтор або лямбда-вираз `(const T&, const T&) -> T`, який реалізує асоціативну операцію моноїда `⊕`.
- `LazyOp`: функтор застосування модифікатора `(const T&, const T&, std::size_t) -> T`.

### 1.3. Порівняльний контракт дизайн-патернів у C та C++

У системній інженерії вибір між інтерфейсом мови C та шаблонним класом C++ визначається вимогами до абстракції та продуктивності:

1. **C API (Низькорівневий контракт):** гарантує сумісність з ABI компілятора (C ABI Stability), відсутність накладних витрат на RTTI та винятки, можливість виклику з інших мов програмування (Python FFI, Rust FFI, Go cgo). Управління ресурсами здійснюється явно парними викликами `segtree_create` та `segtree_destroy`.
2. **C++ API (Об'єктно-орієнтований контракт):** гарантує автоматичне управління ресурсами через деструктори (RAII), сувору перевірку типів під час компіляції (Compile-Time Type Safety) та повну підставку методів (Inlining), що усуває накладні витрати на виклики функцій за вказівниками.

## 2. Специфікація функцій класичного відрізкового дерева

Класичне відрізкове дерево підтримує побудову за час `O(N)`, точкову модифікацію елемента за час `O(log N)` та інтервальний запит агрегата за час `O(log N)`.

### 2.1. Створення та ініціалізація (`segtree_create` / `SegmentTree::SegmentTree`)

:::tabs
```c
segment_tree_t* segtree_create(const long long* arr, size_t n);
```
```cpp
explicit SegmentTree(std::span<const T> data, T identity = T{}, CombineOp op = CombineOp{});
```
:::

- **Опис:** будує ієрархічне відрізкове дерево над вхідним масивом `arr` або срізом `data`.
- **Вхідні параметри:**
  - `arr` / `data`: вказівник на вхідний масив елементів. Не повинен бути `NULL` (у C).
  - `n`: розмірність вхідного масиву (`n > 0`).
  - `identity`: нейтральний елемент моноїда `e`.
- **Передумови (Preconditions):** вхідний масив містить `n` дійсно ініціалізованих елементів. Операція `CombineOp` задовольняє аксіомі асоціативності.
- **Постдумови (Postconditions):** виділено пам'ять під `4 * n` вузлів. Кожен вузол `v` містить результат застосування операції `⊕` до відповідного піддіапазону. Корінь з індексом `0` містить агрегат всього масиву `[0, n-1]`.
- **Часова складність:** `O(N)` лінійний час побудови.
- **Просторова складність:** `O(N)` виділення пам'яті під `4N` елементів.

### 2.2. Точкове оновлення (`segtree_update_point` / `SegmentTree::update_point`)

:::tabs
```c
void segtree_update_point(segment_tree_t* st, size_t v, size_t tl, size_t tr, size_t pos, long long new_val);
```
```cpp
void update_point(std::size_t index, const T& value);
```
:::

- **Опис:** замінює значення елемента за індексом `pos` / `index` на нове значення `new_val` / `value` та оновлює всі підінтервальні агрегати на шляху від листка до кореня.
- **Вхідні параметри:**
  - `st` / `this`: дійсний екземпляр відрізкового дерева.
  - `pos` / `index`: 0-орієнтований індекс елемента в початковому масиві (`0 <= pos < n`).
  - `new_val` / `value`: нове значення елемента.
- **Передумови:** `st != NULL`, `0 <= pos < st->n`.
- **Постдумови:** значення в листку з індексом `pos` дорівнює `new_val`. Усі внутрішні вузли на шляху від кореня до листка `pos` перераховані за формулою `Tree[v] = Tree[Left] ⊕ Tree[Right]`. Решта вузлів дерева залишаються незмінними.
- **Часова складність:** `O(log N)` глибина рекурсії строго обмежена висотою дерева `⌈log₂ N⌉`.
- **Просторова складність:** `O(log N)` глибина стека рекурсивних викликів.

### 2.3. Інтервальний запит (`segtree_query_range` / `SegmentTree::query_range`)

:::tabs
```c
long long segtree_query_range(const segment_tree_t* st, size_t v, size_t tl, size_t tr, size_t l, size_t r);
```
```cpp
[[nodiscard]] T query_range(std::size_t left, std::size_t right) const;
```
:::

- **Опис:** обчислює результат застосування бінарної операції `⊕` до всіх елементів масиву у закритому інтервалі `[l, r]` / `[left, right]`.
- **Вхідні параметри:**
  - `l` / `left`: ліва межа інтервалу запиту (0-індексація).
  - `r` / `right`: права межа інтервалу запиту (0-індексація).
- **Передумови:** `0 <= l <= r < n`. Якщо передано `l > r`, функція повертає нейтральний елемент `e` / `0`.
- **Постдумови:** повертає обчислене значення `A[l] ⊕ A[l+1] ⊕ ... ⊕ A[r]`. Вичаткова структура дерева не видозмінюється (const-операція).
- **Часова складність:** `O(log N)` за теоремою про канонічну декомпозицію інтервалу відвідується не більше `4 ⌈log₂ N⌉` вузлів.
- **Просторова складність:** `O(log N)` використання стека викликів.

## 3. Специфікація відкладеної пропогації (Lazy Propagation)

Інтерфейс відкладеної пропогації розширює класичне дерево можливістю виконання групових інтервальних оновлень `[L, R]` за логарифмічний час.

### 3.1. Інтервальне оновлення (`lazy_segtree_update_range` / `LazySegmentTree::update_range`)

:::tabs
```c
void lazy_segtree_update_range(lazy_seg_tree_t* st, size_t v, size_t tl, size_t tr, size_t l, size_t r, long long add_val);
```
```cpp
void update_range(std::size_t left, std::size_t right, long long add_value);
```
:::

- **Опис:** додає значення `add_val` / `add_value` до кожного елемента масиву на відрізку `[l, r]`.
- **Вхідні параметри:**
  - `l`, `r`: межі інтервалу модифікації `[l, r]`.
  - `add_val` / `add_value`: величина модифікації.
- **Передумови:** `0 <= l <= r < n`.
- **Постдумови:** найвищі канонічні вузли, що повністю покриваються `[l, r]`, отримують пометку в масиві `lazy`. Значення їх `tree`-вузлів модифікуються з урахуванням довжини інтервалу. Нижні дочірні піддерева не відвідуються негайно.
- **Часова складність:** `O(log N)`.
- **Просторова складність:** `O(log N)`.

### 3.2. Допоміжна функція проштовхування (`push_down`)

:::tabs
```c
static void push_down(lazy_seg_tree_t* st, size_t v, size_t tl, size_t tr);
```
```cpp
void push_down(std::size_t v, std::size_t tl, std::size_t tr);
```
:::

- **Опис:** проштовхує відкладену пометку з вузла `v` до дочірніх вузлів `2*v + 1` та `2*v + 2`.
- **Інваріант виконання:** викликається обов'язково на початку обходу вузла `v` перед тим, як рекурсія звертається до його дочірніх вузлів. Після виконання `push_down` пометка `lazy[v]` дорівнює 0.
- **Часова складність:** `O(1)` константний час.

## 4. Контракт типів для комбінаторного алгоритму Кадане

Для задач знаходження максимальної суми на підвідрізку (Maximum Subarray Sum) вузол містить структуру з 4 полів:

:::tabs
```c
typedef struct {
    long long sum;   /* Загальна сума елементів */
    long long pref;  /* Максимальна сума на префіксі */
    long long suff;  /* Максимальна сума на суфіксі */
    long long ans;   /* Максимальна сума на підвідрізку */
} kadane_node_t;

kadane_node_t combine_kadane(kadane_node_t left, kadane_node_t right) {
    kadane_node_t res;
    res.sum = left.sum + right.sum;
    res.pref = (left.pref > left.sum + right.pref) ? left.pref : left.sum + right.pref;
    res.suff = (right.suff > right.sum + left.suff) ? right.suff : right.sum + left.suff;
    
    long long m1 = (left.ans > right.ans) ? left.ans : right.ans;
    long long m2 = left.suff + right.pref;
    res.ans = (m1 > m2) ? m1 : m2;
    return res;
}
```
```cpp
struct KadaneNode {
    long long sum{0};
    long long pref{0};
    long long suff{0};
    long long ans{0};
};

struct KadaneCombine {
    KadaneNode operator()(const KadaneNode& left, const KadaneNode& right) const noexcept {
        KadaneNode res;
        res.sum = left.sum + right.sum;
        res.pref = std::max(left.pref, left.sum + right.pref);
        res.suff = std::max(right.suff, right.sum + left.suff);
        res.ans = std::max({left.ans, right.ans, left.suff + right.pref});
        return res;
    }
};
```
:::

- **Нейтральний елемент:** `sum = 0, pref = -INF, suff = -INF, ans = -INF`.
- **Вимоги до асоціативності:** доведено, що функція `combine_kadane` виконується строго асоціативно.

## 5. Контракт потокобезпечності та багатопотокового доступу (Thread Safety)

В умовах багатопотокового виконання в системних середовищах (multi-threading) екземпляри відрізкового дерева повинні задовольняти наступним контрактам:

1. **Паралельне читання (Concurrent Readers):** Довільна кількість потоків може одночасно викликати метод `query_range` для одного й того ж екземпляра `SegmentTree` без додаткового заборювання або синхронізації (Thread-Safe for concurrent reads).
2. **Конфлікт модифікації (Write Contention):** Якщо хоча б один потік здійснює точкове `update_point` або інтервальне оновлення `update_range`, усі інші потоки повинні бути заблоковані за допомогою механізмів синхронізації (м'ютекс `std::shared_mutex` або блокування читання-запису `reader-writer lock`).
3. **Межі пам'яті (Memory Barriers):** При передачі екземпляра `SegmentTree` між потоками виділена пам'ять повинна узгоджуватися через бар'єри пам'яті (пам'ять аквізиції/релізу `std::memory_order_release` / `std::memory_order_acquire`).

## 6. Специфікація бінарної серіалізації та збереження на диск

Для збереження стану відрізкового дерева в дискових базах даних або передачі мережею визначається бінарний контракт серіалізації:

1. **Заголовок файлу (Header):**
   - `magic` (4 байти): `0x53454754` ("SEGT").
   - `version` (2 байти): `0x0001`.
   - `flags` (2 байти): прапори типів (`0x01` = Lazy Tree, `0x02` = Monoid Type).
   - `element_count` (8 байт): значення `N`.
   - `node_count` (8 байт): значення `4N`.
2. **Тіло дампу (Payload):**
   - Послідовний бінарний масив вузлів `tree[0..4N-1]`.
   - Послідовний бінарний масив поміток `lazy[0..4N-1]` (якщо встановлено прапор `Lazy Tree`).

Даний контракт гарантує сумісність між різними версіями програмного забезпечення та платформеними архітектурами (Little-Endian / Big-Endian).

## 8. Специфікація розширених контрактів (Dynamic & Persistent)

Для спеціалізованих застосувань (розріджені великі інтервали або версіонування) діють додаткові розширені контракти:

### 8.1. Неявне (Динамічне) відрізкове дерево (Sparse / Dynamic Segment Tree)
- Застосовується коли координати елементів лежать у великому діапазоні `[0, 10⁹]`, але кількість реально доданих елементів `Q` є відносно малою (`Q << 10⁹`).
- Вузли створюються динамічно лише при першому зверненні (on-demand allocation).
- **Контракт пам'яті:** кожна точкова модифікація створює не більше ніж `⌈log₂ N⌉` нових вузлів. Загальні витрати пам'яті оцінюються як `O(Q log N)`.

### 8.2. Персистентне відрізкове дерево (Persistent Segment Tree)
- Забезпечує збереження історії всіх версій масиву після кожної модифікації.
- Метод створення нових версій — копіювання шляху (path copying). Стара версія масиву залишається доступною за її кореневим пойнтером `root_version_k`.
- **Контракт незмінності (Immutability Contract):** жоден вузол вже існуючої версії `k` не може бути підданий модифікації. Будь-яка зміна генерує новий корінь і нові вузли вздовж зміненої гілки.

## 9. Граничні режими, виняткові ситуації та гарантії надійності

Специфікація встановлює наступні правила поведінки структури даних у граничних та виняткових умовах:

### 9.1. Вихід за межі масиву (Out-of-Bounds Handling)
- У реалізації мовою C при передачі некоректних індексів (`l > r` або `pos >= n`) функція `segtree_query_range` повертає нейтральний елемент `0` без генерації помилок сегментації (Segmentation Fault).
- У реалізації мовою C++ методи перевіряють межі й викидають стандартне виключення `std::out_of_range`.

### 9.2. Порожній вхідний масив (`N = 0`)
- Конструктор C++ або функція `segtree_create` при `n = 0` не виділяють динамічну пам'ять і повертають порожній стан (`NULL` у C або `tree_.empty()` у C++).

### 9.3. Гарантії безпеки винятків у C++ (Exception Safety)
- **Strong Exception Guarantee (Сильна гарантія):** якщо під час побудови `SegmentTree` виділення пам'яті під `std::vector` викликає `std::bad_alloc` або оператор `CombineOp` викидає виняток, конструктор гарантує відсутність витоків пам'яті (Memory Leaks). Стани об'єктів повністю відновлюються.
- **Nothrow Guarantee:** метод `size()` та деструктор об'єкта мають специфікатор `noexcept` і гарантовано не викидають винятків.

Дана специфікація є вичерпним контрактом для проектування та промислового застосування відрізкового дерева.
