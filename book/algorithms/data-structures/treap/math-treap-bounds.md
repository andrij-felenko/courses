# 🧮 Математичні основи декартового дерева: єдиність, глибина та зв'язок із Quicksort

Математична привабливість декартового дерева полягає в тому, що складна динамічна поведінка деревоподібної структури зводиться до елементарної теорії ймовірностей та комбінаторики перестановок. Замість відстеження нерівностей висот у піддеревах випадкові пріоритети перетворюють глибину будь-якого вузла на суму незалежних індикаторних випадкових величин, зв'язуючи середню продуктивність структури з гармонічним рядом та класичним аналізом швидкого сортування [Quicksort](topic:algorithms/quicksort).

## 1. Теорема про єдиність декартового дерева (бієкція Вюйємена)

Розглянемо скінченну множину з `n` парних елементів `S = {(k₁, p₁), (k₂, p₂), ..., (kₙ, pₙ)}`, де всі ключі `kᵢ` є попарно різними (`kᵢ ≠ kⱼ` при `i ≠ j`), а всі пріоритети `pᵢ` також є попарно різними (`pᵢ ≠ pⱼ` при `i ≠ j`).

Вважатимемо, що інваріант купи вимагає максимального пріоритету в корені (*max-heap*).

> **Теорема (про єдиність).** Для будь-якої множини `S` із попарно різними ключами та попарно різними пріоритетами існує рівно одне двійкове дерево, яке одночасно задовольняє:
> 1. **Інваріант BST за ключами:** для кожного вузла `v` усі ключі в його лівому піддереві строго менші за `k(v)`, а всі ключі в правому піддереві — строго більші за `k(v)`.
> 2. **Інваріант купи за пріоритетами:** для кожного вузла `v` (відмінного від кореня) його пріоритет `p(v)` строго менший за пріоритет його батька `p(parent(v))`.

### Доведення за математичною індукцією

Доведемо теорему індукцією за кількістю елементів `n = |S|`.

**База індукції (`n = 0` та `n = 1`):**
- Для порожньої множини `S = ∅` існує єдине порожнє дерево (`NULL`).
- Для одноелементної множини `S = {(k₁, p₁)}` існує єдине дерево, що складається з одного кореневого вузла без нащадків. Обидва інваріанти виконуються тривіально.

**Індукційний перехід (`n > 1`):**
Припустимо, що твердження теореми є справедливим для всіх множин розміром `< n`.

1. **Визначення кореня:** За інваріантом купи пріоритет кореневого вузла повинен бути строго більшим за пріоритет будь-якого іншого вузла в дереві. Оскільки всі `pᵢ` у множині `S` попарно різні, існує **єдиний** елемент `r = (k_r, p_r) ∈ S`, такий що:
```
p_r = max { pᵢ | (kᵢ, pᵢ) ∈ S }
```
Отже, вузол `r` однозначно зобов'язаний бути коренем дерева. Будь-який інший вибір кореня негайно порушить інваріант купи.

2. **Розбиття піддерев:** За інваріантом двійкового дерева пошуку всі елементи з ключами, меншими за `k_r`, мусять розташовуватися у лівому піддереві `L`, а всі елементи з ключами, більшими за `k_r` — у правому піддереві `R`. Оскільки всі ключі попарно різні, множина `S \ {r}` однозначно розпадається на два неперетинні класи:
```
S_L = { (kᵢ, pᵢ) ∈ S | kᵢ < k_r }
S_R = { (kᵢ, pᵢ) ∈ S | kᵢ > k_r }
```
3. **Застосування індукційного припущення:**
Оскільки `|S_L| < n` та `|S_R| < n`, за індукційним припущенням існує рівно одне дерево `T_L`, побудоване з множини `S_L`, та рівно одне дерево `T_R`, побудоване з множини `S_R`.

Корінь `r` із лівим нащадком `T_L` та правим нащадком `T_R` формує шукане дерево. Оскільки вибір кореня `r` та розбиття на `S_L` і `S_R` були єдино можливими на кожному кроці, результуюче декартове дерево є єдиним. Теорему доведено.

## 2. Ізоморфізм із рандомізованим Quicksort

Нехай ключі `k₁, k₂, ..., kₙ` впорядковані за зростанням: `k₁ < k₂ < ... < kₙ`.

У рандомізованому алгоритмі [Quicksort](topic:algorithms/quicksort) на першому кроці випадково і рівноймовірно обирається опорний елемент (*pivot*) `k_pivot` з імовірністю `1/n`. Цей опорний елемент ділить масив на два підмасиви: елементи ліворуч від нього та елементи праворуч від нього. Далі алгоритм рекурсивно повторює цю процедуру для кожної частини.

Якщо зобразити історію рекурсивних викликів Quicksort у вигляді дерева (де опорний елемент стає коренем, а результати рекурсії для лівої та правої частин — його піддеревами), ми отримаємо дерево пошуку.

У рандомізованому декартовому дереві пріоритети `p₁, p₂, ..., pₙ` генеруються незалежно як випадкові дійсні числа з рівномірного розподілу на відрізку `[0, 1)`.

Оскільки пріоритети незалежні та однаково розподілені, кожен із `n` елементів має абсолютно однакову ймовірність мати максимальний пріоритет:
```
P(pᵢ = max {p₁, ..., pₙ}) = 1/n
```
Елемент із максимальним пріоритетом стає коренем Treap і розбиває решту елементів на піддерева з меншими та більшими ключами. Оскільки цей вибір математично еквівалентний рівноймовірному вибору опорного елемента у Quicksort, **ймовірнісний розподіл форм декартового дерева повністю збігається з розподілом дерев викликів рандомізованого Quicksort**.

## 3. Точний розрахунок математичного сподівання глибини вузла

Знайдемо очікувану глибину вузла `x_i` у дереві Treap із `n` вузлами. 

Нехай ключі впорядковані: `x₁ < x₂ < ... < xₙ`.
Визначимо **глибину** вузла `depth(x_i)` як кількість ребер на шляху від кореня до `x_i`. Глибина кореня дорівнює 0.

Кількість предків вузла `x_i` (включаючи його самого) дорівнює `depth(x_i) + 1`. Введемо індикаторну випадкову величину `A_{i, j}`:
```
A_{i, j} = 1, якщо вузол x_j є предком вузла x_i у дереві
A_{i, j} = 0, в іншому випадку
```
Тоді глибину вузла `x_i` можна виразити через суму індикаторів:
```
depth(x_i) = ( ∑_{j=1}^n A_{i, j} ) - 1
```
За лінійністю математичного сподівання:
```
E[depth(x_i)] = ∑_{j=1, j ≠ i}^n E[A_{i, j}] = ∑_{j=1, j ≠ i}^n P(x_j є предком x_i)
```

### Коли вузол `x_j` є предком `x_i`?

Розглянемо підмножину вузлів, розташованих між `x_i` та `x_j` включно за порядком ключів:
- Якщо `j < i`, цей відрізок містить вузли `{x_j, x_{j+1}, ..., x_i}`.
- Якщо `j > i`, цей відрізок містить вузли `{x_i, x_{i+1}, ..., x_j}`.

Кількість вузлів на цьому відрізку дорівнює `|i - j| + 1`.

За властивістю декартового дерева вузол `x_j` стає предком вузла `x_i` тоді й лише тоді, коли серед усіх `|i - j| + 1` вузлів цього діапазону саме вузол `x_j` має **найбільший пріоритет**. Якщо максимальний пріоритет належав би будь-якому проміжному вузлу `x_k` (де `j < k < i` або `i < k < j`), то вузол `x_k` став би спільним предком і розділив би `x_i` та `x_j` по різних піддеревах (один пішов би ліворуч, інший праворуч), після чого `x_j` вже ніколи не зміг би стати предком `x_i`.

Оскільки всі пріоритети згенеровані незалежно, кожен із `|i - j| + 1` вузлів має рівні шанси мати максимальний пріоритет на цьому відрізку. Звідси:
```
P(x_j є предком x_i) = 1 / (|i - j| + 1)
```

### Обчислення суми через гармонічні числа

Підставимо отриману ймовірність у формулу математичного сподівання глибини:
```
E[depth(x_i)] = ∑_{j=1}^{i-1} 1/(i - j + 1)  +  ∑_{j=i+1}^n 1/(j - i + 1)
```
Зробимо заміну індексів підсумовування:
- Для лівої суми нехай `k = i - j + 1`. Коли `j` змінюється від `i - 1` до `1`, змінна `k` змінюється від `2` до `i`.
- Для правої суми нехай `k = j - i + 1`. Коли `j` змінюється від `i + 1` до `n`, змінна `k` змінюється від `2` до `n - i + 1`.

Отримуємо:
```
E[depth(x_i)]
= ∑_{k=2}^i (1/k) + ∑_{k=2}^{n - i + 1} (1/k)      [розбиття на ліву та праву частини]
= (H_i - 1) + (H_{n - i + 1} - 1)                  [через гармонічні числа H_m = ∑_{k=1}^m 1/k]
= H_i + H_{n - i + 1} - 2                          [зведення подібних доданків]
```

Гармонічне число `H_m` апроксимується натуральним логарифмом через сталу Ейлера — Маскероні `γ ≈ 0.5772156`:
```
H_m = ln m + γ + O(1/m)
```
Підставляючи апроксимацію, маємо:
```
E[depth(x_i)]
= ln(i) + ln(n - i + 1) + 2γ - 2 + O(1/i + 1/(n - i + 1))
```
Для найгіршого випадку (вузли на краях масиву або в центрі) значення виразу строго обмежується:
```
ln(i) + ln(n - i + 1) ≤ 2 · ln(n / 2) = 2 · ln n - 2 · ln 2
```
Отже, для довільного вузла `x_i`:
```
E[depth(x_i)] ≤ 2 · ln n + 2γ - 2 - 2 · ln 2 ≈ 2 · ln n - 2.23
```
Переходячи до двійкового логарифма:
```
2 · ln n = 2 · (ln 2) · log₂ n ≈ 1.38629 · log₂ n
```
Таким чином, математичне сподівання глибини будь-якого вузла в декартовому дереві становить менше ніж `1.39 · log₂ n`, що лише на 39% перевищує теоретичний мінімум для ідеально збалансованого повного двійкового дерева (`log₂ n`).

## 4. Середня глибина вузлів по всьому дереву

Знайдемо середнє значення математичного сподівання глибини, усереднене по всіх `n` вузлах дерева:
```
E_avg(n) = (1/n) · ∑_{i=1}^n E[depth(x_i)] = (1/n) · ∑_{i=1}^n (H_i + H_{n - i + 1} - 2)
```
Оскільки `∑_{i=1}^n H_{n - i + 1} = ∑_{i=1}^n H_i`, вираз спрощується:
```
E_avg(n) = (2/n) · ∑_{i=1}^n H_i - 2
```
Використовуючи відому комбінаторну тотожність `∑_{i=1}^n H_i = (n + 1) · H_n - n`:
```
E_avg(n)
= (2/n) · ((n + 1) · H_n - n) - 2                  [підстановка тотожності суми]
= 2 · (1 + 1/n) · H_n - 2 - 2                      [розкриття дужок]
= 2 · H_n + (2 · H_n)/n - 4                        [групування доданків]
= 2 · ln n + 2γ - 4 + O((ln n)/n)                  [підстановка H_n = ln n + γ]
≈ 2 · ln n - 2.84557                               [числове обчислення для γ = 0.5772156]
```
У двійковому логарифмі:
```
E_avg(n) ≈ 1.386 · log₂ n - 2.846
```

## 5. Дисперсія глибини вузла

Окрім математичного сподівання, важливо знати, наскільки сильно випадкова глибина може відхилятися від свого середнього значення. Дисперсія глибини вузла `x_i` обчислюється через коваріації індикаторних величин `A_{i, j}` та `A_{i, k}`:
```
Var(depth(x_i)) = ∑_{j ≠ i} Var(A_{i, j}) + 2 · ∑_{j < k, j ≠ i, k ≠ i} Cov(A_{i, j}, A_{i, k})
```
Аналіз залежностей між трійками вузлів показує, що коваріація між індикаторами предків є від'ємною або близькою до нуля, що приводить до точної оцінки дисперсії:
```
Var(depth(x_i)) = (H_i + H_{n - i + 1}) - (H_i^{(2)} + H_{n - i + 1}^{(2)})
```
де `H_m^{(2)} = ∑_{k=1}^m (1/k²)` — узагальнене гармонічне число 2-го порядку. Оскільки при `m → ∞` сума `H_m^{(2)} → π²/6 ≈ 1.6449`, дисперсія глибини є логарифмічною:
```
Var(depth(x_i)) ≈ 2 · ln n - π²/3 ≈ 2 · ln n - 3.2898
```
Низька дисперсія (того ж порядку, що й середнє `O(log n)`) доводить високу стабільність структури: випадкові відхилення глибини вузлів від середнього є вкрай малими, а стандартне відхилення зростає лише як `√(2 · ln n)`.

## 6. Гранична оцінка максимальної висоти дерева

Хоча середня глибина вузла становить `≈ 1.386 · log₂ n`, максимальна висота дерева `h(n) = max_{1 ≤ i ≤ n} depth(x_i)` є супремумом по всіх гілках.

Згідно з класичною теоремою Люка Девроя (фр. *Luc Devroye*, 1986 рік) про висоту випадкових двійкових дерев пошуку, випадкова величина `h(n) / ln n` збігається за ймовірністю до єдиного дійсного розв'язку рівняння:
```
c · ln(2 · e / c) = 1   при c ≥ 2
```
Числовий розв'язок цього рівняння дає сталу Девроя:
```
c_max ≈ 4.31107
```
Переходячи до двійкового логарифма:
```
c_max · ln n = c_max · (ln 2) · log₂ n ≈ 4.31107 · 0.693147 · log₂ n ≈ 2.9882 · log₂ n
```
Застосування експоненціальної нерівності Чернова показує, що ймовірність того, що висота Treap перевищить значення `α · c_max · ln n` при `α > 1`, спадає швидше ніж `O(1/n²)`:
```
P(h(n) > 4.312 · ln n) ≤ 1 / n²
```
Це гарантує, що у будь-якій реальній системі Treap практично ніколи не перевищує висоту `3 · log₂ n`, унеможливлюючи виродження за будь-яких практичних обсягів пам'яті (для `n = 10⁶` максимальна висота не перевищує 60 рівнів).

## 7. Очікувана кількість обертань під час вставки

Під час додавання нового елемента за алгоритмом Арагона й Зайделя новий вузол спочатку розміщується на позиції листка відповідно до інваріанта BST, після чого піднімається вгору за допомогою правих і лівих обертань (*rotations*) доти, доки його випадковий пріоритет не задовольнить інваріант купи.

Позначимо кількість виконаних обертань як `R`. Кожне праве обертання піднімає вузол замість лівого сина свого батька, а ліве обертання — замість правого сина.

> **Теорема (Арагон і Зайдель, 1989).** Під час вставки нового елемента в Treap розміру `n` математичне сподівання загальної кількості обертань є строго меншим за константу:
> ```
> E[R] < 2
> ```

### Доведення

Нехай у дерево вставляється новий елемент `x`. Після повної побудови дерева довжина лівого хребта піддерева `x` (кількість вузлів на шляху `x -> x.left -> x.left.right -> ...`) відповідає кількості правих обертань, а довжина правого хребта — кількості лівих обертань.

Імовірність того, що вузол `x_j` опиниться на лівому хребті вузла `x`, вимагає, щоб серед усіх вузлів між `x_j` та `x` саме `x` мав максимальний пріоритет, а `x_j` — другий за величиною пріоритет.
Сума цих імовірностей по всіх можливих вузлах `x_j < x`:
```
E[R_right] = ∑_{k=2}^{rank(x)} 1 / (k · (k - 1)) = ∑_{k=2}^{rank(x)} (1/(k-1) - 1/k) = 1 - 1/rank(x) < 1
```
Аналогічно для лівих обертань:
```
E[R_left] = ∑_{k=2}^{n - rank(x) + 1} 1 / (k · (k - 1)) = 1 - 1/(n - rank(x) + 1) < 1
```
Додаючи обидві величини:
```
E[R] = E[R_right] + E[R_left] = (1 - 1/rank(x)) + (1 - 1/(n - rank(x) + 1)) < 2
```
Це фундаментальний результат: середня кількість структурних змін покажчиків у пам'яті під час вставки не залежить від розміру дерева `n` і в середньому не перевищує двох поворотів.

## 8. Швидке злиття двох дерев (Union) за O(m · log(n/m))

Окрім простого `merge(L, R)`, де всі ключі `L` менші за ключі `R`, декартові дерева підтримують повноцінне об'єднання двох довільних дерев `T₁` (розміру `n`) та `T₂` (розміру `m`, де `m ≤ n`) з пересічними діапазонами ключів.

Алгоритм `union(T₁, T₂)` працює наступним чином:
1. Якщо `T₁ == NULL`, результат `T₂`; якщо `T₂ == NULL`, результат `T₁`.
2. Обираємо корінь із більшим пріоритетом (нехай це корінь `T₁` з ключем `k₁ = T₁.key`).
3. Розрізаємо друге дерево за цим ключем: `split(T₂, k₁, L₂, R₂)`.
4. Рекурсивно об'єднуємо ліві та праві частини:
```
T₁.left  = union(T₁.left, L₂)
T₁.right = union(T₁.right, R₂)
```
5. Повертаємо `T₁`.

### Аналіз складності алгоритму Union

Кожен крок розрізання `split` витрачає час, пропорційний глибині у дереві `T₂`. Якщо менше дерево має розмір `m`, а більше — розмір `n`, розбиття меншого дерева на `m` фрагментів за ключами більшого дерева формує рекурентне співвідношення, розв'язок якого дає:
```
E[Time(union)] = O(m · log(n / m + 1))
```
При `m = 1` ми отримуємо стандартну логарифмічну вставку `O(log n)`. При `m ≈ n` об'єднання двох дерев однакового розміру виконується за строго лінійний час `O(n)`. Це теоретично оптимальна межа для злиття неперетинних множин на основі порівнянь.

## 9. Покроковий числовий приклад для n = 5

Розглянемо практичний розрахунок математичного сподівання глибини кожного з 5 елементів (`x₁ < x₂ < x₃ < x₄ < x₅`):

1. **Для вузла `x₁` (перший елемент):**
```
E[depth(x₁)] = H₁ + H₅ - 2 = 1 + (1 + 1/2 + 1/3 + 1/4 + 1/5) - 2 = 2.283 - 1 = 1.283
```
2. **Для вузла `x₂`:**
```
E[depth(x₂)] = H₂ + H₄ - 2 = (1 + 1/2) + (1 + 1/2 + 1/3 + 1/4) - 2 = 1.5 + 2.083 - 2 = 1.583
```
3. **Для вузла `x₃` (центральний елемент):**
```
E[depth(x₃)] = H₃ + H₃ - 2 = 2 · (1 + 1/2 + 1/3) - 2 = 2 · 1.833 - 2 = 1.667
```
4. **Для вузлів `x₄` та `x₅`:** за симетрією `E[depth(x₄)] = 1.583`, `E[depth(x₅)] = 1.283`.

Середня очікувана глибина по всьому дереву з 5 елементів становить:
```
E_avg(5) = (1.283 + 1.583 + 1.667 + 1.583 + 1.283) / 5 = 7.40 / 5 = 1.48
```
Для порівняння, ідеальна глибина у повному двійковому дереві з 5 вузлів дорівнює `(0 + 1 + 1 + 2 + 2) / 5 = 1.20`.

## 10. Лінійна побудова декартового дерева за O(n) через монотонний стек

Якщо всі пари `(kᵢ, pᵢ)` вже заздалегідь впорядковані за зростанням ключів `k₁ < k₂ < ... < kₙ`, декартове дерево можна побудувати за детермінований лінійний час `O(n)` без застосування рандомізованих вставок.

Цей алгоритм, запропонований Жаном Вюйєменом у 1980 році, використовує монотонний стек для підтримки **правого хребта** дерева (*right spine*):

1. Ініціалізуємо порожній стек вузлів.
2. Для кожного наступного елемента `(kᵢ, pᵢ)` послідовно:
   - Виштовхуємо зі стека всі вузли `u`, чий пріоритет `p(u) < pᵢ` (для max-heap).
   - Останній виштовхнутий вузол стає **лівим сином** нового вузла `(kᵢ, pᵢ)` (оскільки його ключ менший за `kᵢ`, а його пріоритет менший за `pᵢ`).
   - Якщо в стеку ще залишився вузол `top`, новий вузол `(kᵢ, pᵢ)` стає **правим сином** вузла `top`.
   - Заштовхуємо новий вузол `(kᵢ, pᵢ)` у стек.
3. Коренем побудованого дерева є найглибший (перший) елемент, що залишився на дні стека.

### Амортизаційний аналіз

Кожен із `n` вузлів додається в стек рівно один раз. Кожен вузол може бути виштовхнутий зі стека не більше одного разу за весь час роботи алгоритму. Отже, сумарна кількість операцій зі стеком строго дорівнює:
```
Total_Operations ≤ 2 · n = O(n)
```
Це дозволяє перетворити будь-який числовий масив розміру `n` на декартове дерево для розв'язання задачі RMQ за строго лінійний час `O(n)`.
