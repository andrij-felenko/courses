# 🧮 Математика кільця: ймовірності, віртуальні вузли та доведення рівномірності

Консистентне хешування — це не просто зручна геометрична метафора з колом і годинниковою стрілкою. За цим алгоритмом стоїть строгий математичний апарат теорії ймовірностей, порядку статистик та центральної граничної теореми. 

Головна мета математичного обґрунтування — довести дві ключові властивості:
1. **Рівномірність навантаження:** як мінімізувати дисперсію кількості ключів між фізичними серверами.
2. **Мінімальність ребалансування:** чому при зміні конфігурації кластера переміщується саме `1 / N` частка даних, що є теоретичним нижнім порогом.

У цьому файлі розібрано ймовірнісну модель кільця, математичну природу віртуальних вузлів (vnodes) та формальне доведення теореми про ребалансування без використання LaTeX.

## Геометрична модель та хеш-простір

Нехай хеш-функція `h(k)` відображає довільний ключ `k` у 32-бітне ціле беззнакове число:

```
h: Key → [0, 2³² - 1]
```

Позначимо розмір хеш-простору як `M = 2³²` (приблизно 4.29 × 10⁹ можливих значень). Замикаємо цей інтервал у коло `S¹`, де число `0` збігається з точкою `M - 1`. Для зручності математичного аналізу нормуємо довжину кола до одиниці, перейшовши до неперервного інтервалу `[0, 1)`.

Припустимо, що хеш-функція `h` є **ідеально рівномірною**: для будь-якого ключа `k` значення `h(k)` є незалежною випадковою величиною, рівномірно розподіленою на інтервалі `[0, 1)`.

## Розподіл дуг без віртуальних вузлів: проблема великої дисперсії

Нехай у кластері є `N` фізичних серверів. Ми розміщуємо їх на кільці за допомогою тієї ж хеш-функції, обчислюючи `h(Server_i)` для кожного `i = 1, 2, ..., N`. 

Розташуємо отримані точки на колі у порядку зростання їхніх координат:

```
0 ≤ x₁ < x₂ < ... < x_N < 1
```

Кожен сервер `S_i` відповідає за дугу кільця між своїм попередником `x_{i-1}` та власною точкою `x_i` за годинниковою стрілкою. Позначимо довжину цієї дуги як `L_i = x_i - x_{i-1}` (для першого сервера `L₁ = x₁ + (1 - x_N)`).

З міркувань симетрії математичне сподівання довжини дуги будь-якого сервера є однаковим:

```
E[L_i] = 1 / N
```

Якщо на кільце кинуто `K` ключів, то очікувана кількість ключів на одному сервері дорівнює `K · E[L_i] = K / N`. 

Проте математичного сподівання недостатньо для гарантії стабільності системи! Ключовим параметром є **дисперсія** довжини дуги `Var(L_i)`. 

З теорії випадкових точок на колі (порядкові статистики рівномірного розподілу) відомо, що довжина окремого інтервалу `L_i` між двома сусідніми випадковими точками підпорядковується бета-розподілу `Beta(1, N - 1)`. Для великих `N` цей розподіл добре апроксимується експоненціальним розподілом із щільністю:

```
f(l) = N · e^(-N · l),   при l ≥ 0
```

Дисперсія довжини дуги для експоненціального розподілу дорівнює:

```
Var(L_i) ≈ 1 / N²
```

Це означає, що розкид розмірів дуг надзвичайно великий! Найбільш тривожним результатом є математичне сподівання **найбільшої дуги** на колі `L_max = max(L₁, L₂, ..., L_N)`:

```
E[L_max] ≈ (ln N + 1) / N
```

### Практичний висновок для `N` фізичних вузлів
Максимальна дуга на колі в середньому в `ln N` разів більша за середню дугу `1 / N`!

Наприклад, при `N = 100` серверах значення `ln(100) ≈ 4.6`. Це означає, що найбільш завантажений сервер отримає у **4.6–5 разів більше ключів**, ніж середнє значення `K / N` (тобто нестиме 500% нормативного навантаження), тоді як найменш завантажений сервер отримає менше 10% від норми. Такий кричущий дисбаланс робить чисте консистентне хешування без додаткових модифікацій непридатним для реальних високонавантажених систем.

## Математична теорія віртуальних вузлів (Vnodes)

Для приборкання дисперсії автори консистентного хешування ввели концепцію **віртуальних вузлів (vnodes)**. 

Замість того, щоб розміщувати кожен фізичний сервер на кільці лише один раз, ми створюємо для кожного фізичного сервера `S_i` масив із `V` різних віртуальних міток:

```
vnode_(i, j) = hash(Server_i + ":" + j),   для j = 1, 2, ..., V
```

Усі `N · V` віртуальних точок кидаються на те саме числове кільце. Загальна кількість точок на колі стає рівною `M = N · V`.

Тепер коло розбивається на `M` дрібних інтервалів середньої довжини `1 / M = 1 / (N · V)`. Фізичний сервер `S_i` володіє тими інтервалами, які передують його `V` віртуальним точкам.

Позначимо загальну частку кільця, яку контролює фізичний сервер `S_i`, як суму довжин його `V` випадково розкиданих дуг:

```
W_i = l_(i, 1) + l_(i, 2) + ... + l_(i, V)
```

Оскільки `V` віртуальних вузлів сервера `S_i` розміщені у різних випадкових місцях кола, довжини дуг `l_(i, j)` можна вважати приблизно незалежними випадковими величинами з математичним сподіванням `E[l] = 1 / (N · V)` та дисперсією `Var(l) ≈ 1 / (N · V)²`.

За **Центральною Граничною Теоремою (ЦГТ)**, сума `V` незалежних випадкових величин при зростанні `V` асимптотично прямує до **нормального (гаусового) розподілу**:

```
W_i  ~  N( μ, σ² )
```

Де параметри розподілу становлять:
- Математичне сподівання: `μ = E[W_i] = V · (1 / (N · V)) = 1 / N`
- Дисперсія суми: `σ² = Var(W_i) = V · Var(l) = V · (1 / (N² · V²)) = 1 / (N² · V)`
- Стандартне відхилення: `σ = 1 / (N · sqrt(V))`

Обчислимо **відносне стандартне відхилення** (коефіцієнт варіації `CV = σ / μ`), який показує відсоток відхилення навантаження сервера від ідеального середнього `1 / N`:

```
CV = σ / μ = (1 / (N · sqrt(V))) / (1 / N) = 1 / sqrt(V)
```

Це фундаментальний результат! Відносний розкид навантаження **взагалі не залежить від кількості серверів `N`**, а визначається виключно кількості віртуальних вузлів `V` на один сервер:

| Кількість vnodes (`V`) | Коефіцієнт варіації (`CV = 1/√V`) | Максимальний відхил (`±3σ`) |
| :--- | :--- | :--- |
| `V = 10` | `1/√10 ≈ 31.6%` | `±95%` (неприйнятно) |
| `V = 100` | `1/√100 = 10.0%` | `±30%` (добре) |
| `V = 256` | `1/√256 = 6.25%` | `±18.7%` (відмінно) |
| `V = 1000` | `1/√1000 ≈ 3.16%` | `±9.5%` (ідеально) |

Збільшуючи `V` до 100–250 віртуальних вузлів на сервер, ми стискаємо відхилення навантаження від середнього до контрольованих 5–10%, забезпечуючи майже ідеальну рівномірність.

## Врахування гетерогенності обладнання (Weighted Vnodes)

У реальних дата-центрах сервери часто мають різну апаратну потужність. Наприклад, новий сервер `S_A` має 64 ядра та 256 ГБ ОЗП, а старий сервер `S_B` — лише 16 ядер та 64 ГБ ОЗП.

Математика віртуальних вузлів природно розв'язує цю задачу через призначення вагових коефіцієнтів `w_i`. Кількість віртуальних вузлів для сервера `S_i` роблять пропорційною його вазі:

```
V_i = w_i · V_base
```

Загальна кількість vnodes на кільці стає `M = Σ V_i`. Тоді математичне сподівання частки кільця для сервера `S_i` дорівнює:

```
E[W_i] = V_i / M = w_i / (Σ w_k)
```

Потужний сервер `S_A` з вагою `w_A = 4` отримає у 4 рази більше віртуальних точок на колі, ніж `S_B` з вагою `w_B = 1`, і відповідно збере в 4 рази більше ключів даних.

## Доведення теореми про мінімальне ребалансування

**Теорема (Про мінімальне переміщення ключів):**
*При додаванні нового фізичного сервера в кластер із `N` серверів до нового `(N + 1)`-го сервера, математичне сподівання частки ключів, що змінюють своє місцеположення, становить точно `1/(N + 1)`. При цьому жоден ключ не мігрує між існуючими `N` старими серверами.*

### Доведення:
1. Розглянемо кільце з `N` фізичними серверами, на якому розміщено `K` ключів.
2. Додамо новий сервер `S_{N+1}` із `V` віртуальними вузлами. На кільце кидається `V` нових точок.
3. Кожна нова точка `vnode_(N+1, j)` влучає в якусь існуючу дугу кільця й «відрізає» від неї частину території за годинниковою стрілкою.
4. Сумарна частка кільця, яку покриває новий сервер `S_{N+1}`, дорівнює його частці `W_{N+1}`. Як доведено вище, математичне сподівання цієї частки становить:

```
E[W_{N+1}] = 1 / (N + 1)
```

5. Оскільки ключі розподілені по колу рівномірно з густиною `K`, очікувана кількість ключів, що потрапляють у території нового сервера `S_{N+1}`, дорівнює:

```
E[K_moved] = K · E[W_{N+1}] = K / (N + 1)
```

6. Усі ці `K / (N + 1)` ключів раніше належали старим серверам і тепер переходять виключно до `S_{N+1}`.
7. Жодний інший сектор кільця, який не належить `S_{N+1}`, не зазнав змін. Отже, між існуючими `N` серверами не перемістився жоден ключ.

**Висновок:** При зміні розміру кластера з `N` до `N + 1` переміщується лише `1 / (N + 1)` частка даних. Це є математично доведеним теоретичним мінімумом для будь-якого алгоритму розподілу ключів.
