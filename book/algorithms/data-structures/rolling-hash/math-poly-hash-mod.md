# 🧮 Математика поліноміального хешування, колізії та вибір параметрів

Поліноміальне хешування є одним із найпотужніших алгебраїчних методів у дискретній математиці та алгоритмах над рядками. Воно проектує довільну послідовність символів `s = (s₀, s₁, ..., sₖ₋₁)` у скалярне числове значення у кільці залишків за модулем простого числа `P`.

У цій вставці розглянуто суворі математичні підвалини поліноміального хешу, алгебраїчне обґрунтування `O(1)` оновлення ковзного вікна, оцінку ймовірності колізій за лемою Шварца-Зіппеля та оптимізації модулярної арифметики.

---

## 1. Поліноміальне представлення та схема Горнера

Нехай алфавіт `Σ` відображається у множину невід'ємних цілих чисел. Рядок `s` довжиною `k` розглядається як послідовність коефіцієнтів полінома `P(x)` від однієї змінної `x`:

P(x) = s₀ · xᵏ⁻¹ + s₁ · xᵏ⁻² + s₂ · xᵏ⁻³ + ... + sₖ₋₂ · x¹ + sₖ₋₁ · x⁰

Хеш-значення обчислюється як значення цього полінома у точці `x = B` за модулем простого числа `P`:

H(s) = P(B) mod P = ( ∑_{j=0}^{k-1} s_j · B^{k-1-j} ) mod P

### Обчислення за схемою Горнера
Для прямого обчислення `H(s)` за `O(k)` операцій без піднесення `B` до степеня застосовується канонічна схема Горнера (Horner's rule):

H₀ = 0
Hⱼ = (Hⱼ₋₁ · B + sⱼ₋₁) mod P,   для j = 1, 2, ..., k

Тоді підсумковий хеш дорівнює `Hₖ`. Схема Горнера вимагає лише `k` множень та `k` додавань за модулем `P`, гарантуючи високу обчислювальну ефективність при первинній ініціалізації вікна.

## 2. Строгий алгебраїчний вивід рекурентного оновлення

Розглянемо два послідовні вікна довжиною `k`:
- Перше вікно `W₁ = (s₀, s₁, ..., sₖ₋₁)`;
- Друге вікно `W₂ = (s₁, s₂, ..., sₖ)`.

Випишемо їхні поліноміальні значення:

H(W₁) = ( s₀ · Bᵏ⁻¹ + s₁ · Bᵏ⁻² + s₂ · Bᵏ⁻³ + ... + sₖ₋₁ · B⁰ ) mod P

H(W₂) = ( s₁ · Bᵏ⁻¹ + s₂ · Bᵏ⁻² + s₃ · Bᵏ⁻³ + ... + sₖ · B⁰ ) mod P

Розглянемо вираз `(H(W₁) - s₀ · Bᵏ⁻¹) mod P`:

H(W₁) - s₀ · Bᵏ⁻¹ ≡ s₁ · Bᵏ⁻² + s₂ · Bᵏ⁻³ + ... + sₖ₋₁ · B⁰ (mod P)

Помножимо обидві частини порівняння на основу `B`:

(H(W₁) - s₀ · Bᵏ⁻¹) · B ≡ s₁ · Bᵏ⁻¹ + s₂ · Bᵏ⁻² + ... + sₖ₋₁ · B¹ (mod P)

Зауважимо, що правий боку відрізняється від `H(W₂)` лише відсутністю останнього доданку `sₖ · B⁰`. Додавши `sₖ`, отримуємо підсумкову тотожність:

H(W₂) ≡ ( (H(W₁) - s₀ · Bᵏ⁻¹) · B + sₖ ) (mod P)

Отже, для переходу від `H(W₁)` до `H(W₂)` достатньо:
1. Відняти `s₀ · E mod P`, де `E = Bᵏ⁻¹ mod P`;
2. Додати `P`, щоб усунути можливий від'ємний результат: `H' = (H(W₁) - s₀ · E mod P + P) mod P`;
3. Помножити на `B` та додати `sₖ`: `H(W₂) = (H' · B + sₖ) mod P`.

Усі три кроки виконуються за сталий час `O(1)`, оскільки коефіцієнт `E = Bᵏ⁻¹ mod P` є константою для фіксованої довжини вікна `k` і зберігається в пам'яті.

## 3. Аналіз колізій та лема Шварца-Зіппеля

Колізія виникає тоді, коли два різних рядки `s != t` однакової довжини `k` мають однакове хеш-значення: `H(s) ≡ H(t) (mod P)`.

Це означає, що:

( ∑_{j=0}^{k-1} s_j · B^{k-1-j} ) ≡ ( ∑_{j=0}^{k-1} t_j · B^{k-1-j} ) (mod P)

Перенесемо всі доданки в один бік:

∑_{j=0}^{k-1} (s_j - t_j) · B^{k-1-j} ≡ 0 (mod P)

Позначимо `d_j = s_j - t_j`. Оскільки `s != t`, принаймні один коефіцієнт `d_j != 0`. Розглянемо поліном:

Q(x) = d₀ · xᵏ⁻¹ + d₁ · xᵏ⁻² + ... + dₖ₋₁ (mod P)

Виникнення колізії еквівалентне тому, що обрана основа `B` є коренем полінома `Q(x)` у скінченному полі `F_P = Z / P Z`.

Згідно з основною теоремою алгебри для скінченних полів, ненульовий поліном `Q(x)` степеня `N_deg <= k - 1` над полем `F_P` може мати **щонайбільше `k - 1` різних коренів**.

Якщо основа `B` обирається рівномірно й випадково з множини `F_P \ {0}` (тобто з `P - 1` можливих значень), то за лемою Шварца-Зіппеля (Schwartz-Zippel Lemma) ймовірність того, що випадкове `B` виявиться коренем `Q(x)`, обмежується співвідношенням:

P(collision) = P(Q(B) ≡ 0 mod P) <= (k - 1) / (P - 1) ≈ k / P

### Практичний наслідок
Якщо `k = 10⁴` (довжина вікна 10 000 символів), а модуль `P = 10⁹ + 7`, ймовірність колізії для двох конкретних фіксованих рядків не перевищує:

P(collision) <= 10⁴ / 10⁹ = 10⁻⁵ = 0.001%

Якщо ж ми порівнюємо `N = 10⁶` різних вікон у тексті, загальна кількість пар порівнянь становить `O(N²)`. За парадоксом днів народження (Birthday Paradox), для уникнення колізій серед `N` вікон модуль `P` повинен задовольняти умову `P >> N²`.

## 4. Змагальний аналіз та випадкова основа (Anti-Hash Test)

Якщо основа `B` та модуль `P` є заздалегідь відомими константами, зловмисник може легко згенерувати спеціальні рядки, які викликають колізію (так звані Anti-Hash тести).

Класичним прикладом є побудова послідовності Туе-Морса (Thue-Morse sequence). Нехай `S₀ = "a"`, `S₁ = "ab"`, `S₂ = "abba"`, де кожне наступне слово будується як інверсія попереднього (`S_{n+1} = S_n + inv(S_n)`).

Для будь-якої фіксованої поліноміальної хеш-функції можна підібрати довжину послідовності Туе-Морса, для якої `H(S_n) ≡ H(inv(S_n)) (mod P)`. При попаданні таких даних у розгалужені хеш-структури алгоритм Рабіна-Карпа вироджується у квадратичний час `O(N · M)` через постійні хибні спрацьовування.

### Захист через рандомізацію
Для захисту від цілеспрямованих атак основою `B` обирають **випадкове число**, згенероване під час запуску програми:

B = random_range(256, P - 1)

Оскільки зловмисник не знає значення `B`, яке буде обрано під час виконання, ймовірність побудувати колізійні рядки повертається до теоретичного мінімуму `O(k / P)`.

## 5. Подвійне хешування та Китайська теорема про залишки

Щоб досягти криптографічного рівня надійності без використання важких криптографічних функцій, застосовують подвійне хешування.

Нехай обчислюються два незалежні хеші:
- `H₁(s)` за основою `B₁` та модулем `P₁`;
- `H₂(s)` за основою `B₂` та модулем `P₂`.

Пара `(H₁(s), H₂(s))` утворює елемент прямого добутку кілець `Z / P₁ Z × Z / P₂ Z`.

Якщо `P₁` та `P₂` є взаємно простими числами (gcd(P₁, P₂) = 1), за Китайською теоремою про залишки (Chinese Remainder Theorem, CRT) цей прямий добуток ізоморфний кільцю `Z / (P₁ · P₂) Z`.

У результаті сукупна ймовірність колізії для двох підрядків довжиною `k` становить:

P(collision_double) <= (k / P₁) · (k / P₂) = k² / (P₁ · P₂)

При `P₁ ≈ 10⁹ + 7` та `P₂ ≈ 10⁹ + 9` добуток `P₁ · P₂ ≈ 10¹⁸`.
Для вікна довжиною `k = 1000` ймовірність колізії становить:

P(collision_double) <= 10⁶ / 10¹⁸ = 10⁻¹₂

Це робить систему повністю стійкою до колізій у будь-яких практичних застосуваннях.

## 6. Оптимізація обчислень за допомогою чисел Мерсенна

Найбільш затратною арифметичною операцією при обчисленні ковзного хешу на ЦП є операція взяття залишку від ділення `% P`, оскільки команда цілочисельного ділення (`DIV`/`IDIV` в архітектурі x86_64) виконується за 15–40 тактів процесора.

Щоб прискорити обчислення, як модуль `P` обирають **просте число Мерсенна** (Mersenne prime) виду `P = 2^q - 1`. Найвідомішим прикладом є `P = 2³¹ - 1 = 2147483647` (число Мерсенна M₃₁).

Для будь-якого числа `X` залишок від ділення на `2^q - 1` обчислюється за формулою:

X mod (2^q - 1) = (X & (2^q - 1)) + (X >> q)

Якщо отримана сума перевищує `2^q - 1`, операцію повторюють ще один раз.

Завдяки цьому повільна операція ділення `% P` замінюється на дві надшвидкі бітові операції: побітове І `&` та логічний зсув праворуч `>>`, які виконуються за **1 такт процесора**. Це забезпечує 3–5-кратне прискорення обчислення ковзного хешу у високопродуктивних системах CDC та дедуплікації.
