# 🧮 Математичний апарат некриптографічних хеш-функцій

Якість некриптографічної хеш-функції визначається її здатністю трансформувати вхідний простір ключів K у вихідний простір хеш-значень H розмірністю `2ⁿ` (де `n = 32` або `n = 64`) таким чином, щоб отриманий розподіл не відрізнявся від випадкового оракула (Random Oracle).

На відміну від криптографії, де вимагається обчислювальна складність знаходження оберненого образу (Preimage Resistance), у некриптографічному хешуванні математичними критеріями якості є **строгий критерій лавини (SAC)**, **критерій незалежності бітів (BIC)**, **відсутність диференціальних колізій** та **рівномірність згортання в діапазон бакетів**.

## Строгий критерій лавини (Strict Avalanche Criterion, SAC)

Функція `h: {0,1}ᵏ → {0,1}ⁿ` задовольняє строгий критерій лавини (запропонований Вебстером і Таваресом у 1985 році), якщо при зміні будь-якого одного біта вхідного вектора `X` кожен біт вихідного вектора `Y = h(X)` змінює своє значення на протилежне з ймовірністю p = 0.5.

Формально, нехай `eᵢ` — вхідний вектор, у якому лише `i`-й біт дорівнює 1 (одиничний бітовий зсув), а `⊕` позначє операцію `XOR`. Тоді вектор різниці виходів:

```
ΔY = h(X) ⊕ h(X ⊕ eᵢ)
```

Матриця лавинності А розміром `k × n` містить елементи `A[i][j]`, де:

```
A[i][j] = P( ΔY[j] = 1 )
```

Ідеальний хеш має матрицю, де кожна комірка `A[i][j] = 0.5`. Якщо для якихось `i` та `j` ймовірність відхиляється від 0.5 (наприклад, `A[i][j] = 0` або `A[i][j] = 1`), це свідчить про наявність шлейфу закономірності (незмішаного біта), що створює масиви колізій при структурованому вводі.

### Критерій незалежності бітів (Bit Independence Criterion, BIC)

Критерій BIC вимагає, щоб для будь-якого фіксованого інвертованого вхідного біта `i` пара вихідних бітів `j` та `l` (де `j ≠ l`) змінювалася **незалежно**. Якщо біти `j` та `l` завжди інвертуються одночасно (`ΔY[j] = ΔY[l]`), вихідний простір вироджується, і ефективна розмірність хешу зменшується з `2ⁿ` до `2ⁿ⁻¹`.

## Математика нелінійних бітових міксерів (fmix)

Щоб досягти SAC та BIC без криптографічних кругових підстановок (S-Box), застосовують каскад мультиплікативно-зсувних трансформацій. Розглянемо канонічний 64-бітний фіналізатор MurmurHash3 `fmix64`:

```
h = h ⊕ (h >> 33)        [Крок 1: зсув-XOR змішує старші біти з молодшими]
h = h × C₁               [Крок 2: множення на C₁ = 0xff51afd7565a1a5d]
h = h ⊕ (h >> 33)        [Крок 3: повторний зсув-XOR]
h = h × C₂               [Крок 4: множення на C₂ = 0xc4ceb9fe1a85ec53]
h = h ⊕ (h >> 33)        [Крок 5: фінальне розсіювання]
```

Виведення лавинного ефекту через множення спирається на **поширення переносів (carry propagation)**. При множенні 64-бітного числа `X` на константу `C` кожен біт `X[i]` зсувається на `i` позицій ліворуч і додається до результату. Якщо константа `C` має високу бітову щільність (тобто приблизно половина її бітів дорівнює 1), кожен біт `X[i]` спричиняє ланцюг переносів, який змінює значення багатьох бітів вище позиції `i`.

Операція `h ⊕ (h >> 33)` передає зміни зі старших бітів у молодші біти (оскільки зсув вправо переміщує біти 33..63 на позиції 0..30). Поєднання множення (зсув вліво з переносом) та зсуву-XOR вправо дає повний двосторонній дифузійний зв'язок (full bit diffusion).

## Перевірка якісного розподілу: Тест Хі-квадрат (χ²)

Для перевірки рівномірності розподілу хеш-значень по `m` бакетах хеш-таблиці використовують статистичний тест Хі-квадрат Пірсона.

Нехай всього маємо `N` вхідних ключів, які розкидаються по `m` бакетах. Очікувана кількість ключів у кожному бакеті за рівномірного розподілу дорівнює:

```
E = N / m
```

Якщо `Oᵢ` — фактична спостережувана кількість ключів у `i`-му бакеті, статистика Хі-квадрат обчислюється як:

```
χ² = ∑ᵢ₌₀ᵐ⁻¹ (Oᵢ - E)² / E
```

Згідно зі статистичною теорією, для якісного хешу значення `χ²` має лежати в межах інтервалу довіри для розподілу Хі-квадрат з `k = m - 1` ступенями свободи:

```
k - 2·√(2k) ≤ χ² ≤ k + 2·√(2k)
```

Якщо обчислене значення `χ²` виходить далеко за верхню межу, хеш-функція створює кластеризацію (скупчення колізій). Якщо `χ²` значно менше за нижню межу, розподіл є «занадто рівномірним» (надмірно детермінованим), що зазвичай свідчить про наявність бітових кореляцій.

## Імовірність колізій та парадокс днів народження

Простір 64-бітного хешу містить `2⁶⁴ ≈ 1.84 × 10¹⁹` можливих значень. Відповідно до парадоксу днів народження, імовірність `P` виникнення хоча б однієї колізії при збереженні `N` випадкових ключів у 64-бітному просторі оцінюється формулою:

```
P(N) ≈ 1 - exp(-N² / (2 · 2⁶⁴))
```

Розклавши експоненту в ряд Тейлора для малих значеннях `P`:

```
P(N) ≈ N² / (2⁶⁵)
```

Отже, щоб отримати імовірність колізії `P = 50%` у 64-бітному хеш-просторі, потрібно згенерувати приблизно:

```
N ≈ √(2⁶⁴ · 2 · ln 2) ≈ 5.08 × 10⁹ ключів (5 мільярдів)
```

Для 32-бітного хеш-простору поріг 50% колізій настає всього лише при `N ≈ 77 000` ключів. Саме тому 32-бітні некриптографічні хеші не підходять для великих масивів даних або географічно розподілених сховищ без додаткового механізму розв'язання колізій.

## Згортання хешу в діапазон: Модуль проти Lemire Reduction

Отримавши 64-бітне значення хешу `h`, його необхідно згорнути в діапазон `[0, m - 1]` розміру хеш-таблиці.

### 1. Звичайний модуль `h mod m`
Класичний спосіб `h % m` вимагає виконання інструкції цілочисельного ділення (`IDIV` / `DIV` на x86), яка є однією з найповільніших операцій ЦПУ (забирає 20–40 тактів).

### 2. Маска `h & (m - 1)` (для m = 2ᵏ)
Якщо розмір таблиці є ступенем двійки, остача від ділення замінюється миттєвою побітовою маскою за 1 такт. Але цей підхід повністю ігнорує старші біти хешу, використовуючи лише `k` молодших бітів. Якщо хеш-функція має слабке змішування у молодших бітах, хеш-таблиця миттєво вироджується.

### 3. Швидке згортання Леміра (Lemire Fast Reduction)
Даніель Лемір (Daniel Lemire) у 2016 році запропонував математичний підхід згортання без ділення для довільного `m`, який використовує старші біти 128-бітного добутку.

Нехай `h` — 64-бітне беззнакове ціле число (`0 ≤ h < 2⁶⁴`). Ми хочемо відобразити його на `0 ≤ x < m`.

Розглянемо дріб `(h / 2⁶⁴) ∈ [0, 1)`. Його помноження на `m` дає дійсне число у діапазоні `[0, m)`. Ціла частина цього числа дорівнює:

```
x = ⌊ (h · m) / 2⁶⁴ ⌋
```

У 64-бітній арифметиці ділення на `2⁶⁴` — це просто взяття старших 64 бітів 128-бітного добутку `h · m`:

```
uint64_t reduce(uint64_t h, uint64_t m) {
    return (uint64_t)((( __uint128_t )h * m) >> 64);
}
```

Ця операція виконується за **1 такт CPU** (інструкцією `MULX` або `MUL` на x86-64), використовує **всі біти хешу** (включаючи старші) та усуває апаратне ділення, прискорюючи доступ до хеш-таблиці в 2–3 рази.
