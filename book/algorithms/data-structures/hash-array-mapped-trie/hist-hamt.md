# 📜 Історія виникнення HAMT та ідеальних хеш-дерев

Історія розвитку асоціативних структур даних — це тривала еволюція пошуку компромісу між часовою складністю доступу, ефективністю використання оперативної пам'яті, локальністю даних у кеші процесора та можливістю зберігати попередні стани системи (персистентністю).

## 1. Контекст 1990-х років: криза класичних структур

До кінця 1990-х років у системному програмуванні та теорії алгоритмів панували два основні класи асоціативних контейнерів:

1. **Збалансовані двійкові дерева пошуку (AVL, Red-Black Tree):**
   Запропоновані Г. Адельсон-Вельським, Є. Ландісом (1962) та Р. Баєром (1972), ці структури гарантували логарифмічний час пошуку `O(log₂ N)`. Вони легко піддавалися персистентному копіюванню шляху (Path Copying), оскільки при оновленні вузла потрібно було створити копії лише `log₂ N` батьківських елементів. Проте їхня локальність у кеші CPU була незадовільною: кожен вузол зберігав лише один ключ і два вказівники (`left`, `right`), що призводило до інтенсивної фрагментації оперативної пам'яті та постійних промахів кешу першого й другого рівнів (L1/L2 Cache Misses).

2. **Геш-таблиці з прямим доступом (Open Addressing, Chaining):**
   Класичні геш-таблиці, описані Д. Кнутом та Г. Луном, забезпечували амортизований час доступу `O(1)`. Проте вони вимагали суцільного контигуального масиву в пам'яті. Коли розмір масиву вичерпувався, виникала потреба у повній регешації (Rehash) усіх елементів у новий масив удвічі більшого розміру. У системах реального часу це спричиняло непередбачувані затримки. Крім того, геш-таблиці були абсолютно непридатними для функційного програмування: щоб зберегти попередній стан таблиці при додаванні одного ключа, доводилося копіювати весь масив розміром `N`, що вимагало `O(N)` часу та пам'яті.

3. **Префіксні дерева (Trie / Radix Tree):**
   Запропоновані Е. Фредкіним (1960) та Д. Моррісоном (PATRICIA, 1968), префіксні дерева використовували біти ключа для ієрархічної навігації. Для прискорення обходу розробники збільшували фактор розгалуження (Branching Factor) з `B = 2` до `B = 16` або `B = 32`. Проте це призводило до катастрофічної перевитрати пам'яті: кожен внутрішній вузол повинен був містити фіксований масив із 16 або 32 вказівників. У розріджених деревах понад 80–90% цих комірок залишалися порожніми (`NULL`), марно витрачаючи оперативну пам'ять на 64-бітних архітектурах.

## 2. Відкриття Філа Багвелла: «Ideal Hash Trees» (2000)

У 2000 році швейцарський інженер і дослідник Філ Багвелл (Phil Bagwell), працюючи у Швейцарському федеральному інституті технологій Лозанни (EPFL), опублікував фундаментальну працю під назвою *«Ideal Hash Trees»*.

Багвелл поставив собі за мету створити «ідеальну» структуру даних, яка б поєднувала найкращі риси геш-таблиць та префіксних дерев:
- Амортизований час доступу `O(1)`, як у геш-таблиці;
- Відсутність необхідності регешації всього масиву при зростанні;
- Мінімальне споживання пам'яті без порожніх `NULL`-вказівників;
- Ефективну підтримку структурного суміщення (Structural Sharing) для персистентності.

Ключовим осяянням Багвелла стало поєднання розгалуженого геш-дерева (Hash Trie) із **побітовим маскуванням та апаратною інструкцією підрахунку одиничних бітів (`popcount`)**.

Замість того щоб виділяти для кожного внутрішнього вузла статичний масив із 32 вказівників, Багвелл запропонував зберігати:
1. **32-бітне ціле число (`bitmap`)**, у якому кожен біт відповідає наявності або відсутності дитини для відповідного 5-бітного фрагмента гешу (`0..31`).
2. **Динамічний компактний масив вказівників**, розмір якого точно дорівнює кількості встановлених одиничних бітів у масці `popcount(bitmap)`.

Завдяки формулі `index = popcount(bitmap & ((1 << chunk) - 1))` вдалося досягти миттєвого обчислення фізичної адреси дитини в компактному масиві за 1 такт процесора, повністю усунувши витрати пам'яті на порожні вказівники.

Структуру було названо **Hash Array Mapped Trie (HAMT)**.

## 3. Революція у функційному програмуванні: Clojure та Scala

Тривалий час розробка Багвелла залишалася теоретичним досягненням académico-спільноти. Справжній технологічний вибух стався у 2007 році, коли американський розробник Річ Гікі (Rich Hickey) створив мову програмування Clojure на платформі JVM.

Основою філософії Clojure була незмінність даних (Immutability) та відсутність побічних ефектів при паралельному виконанні. Для реалізації незмінних мап (`PersistentHashMap`) та множин (`PersistentHashSet`) Гікі використав modified 32-way Persistent HAMT.

Гікі виявив важливу практичну закономірність: при факторі розгалуження `B = 32` глибина дерева для мільйона елементів дорівнює лише `⌈log₃₂ 10⁶⌉ = 4` рівні, а для мільярда елементів — лише `6` рівнів. Оскільки глибина дерева фактично обмежена константою (для 32-бітного гешу максимум 7 рівнів), персистентний пошук і вставка за `O(log₃₂ N)` на практиці працюють із тією ж швидкістю, що й `O(1)` у звичайній геш-таблиці, але забезпечують абсолютну побітоку безпеку в багатопотоковому середовищі.

У 2009 році Філ Багвелл приєднався до лабораторії розробки мови Scala під керівництвом Мартіна Одерські в EPFL. Разом із Тіарком Ромпфом (Tiark Rompf) Багвелл переробив стандартну бібліотеку колекцій Scala 2.8, зробивши `scala.collection.immutable.HashMap` основою для незмінних даних у мові Scala.

## 4. Подальший розвиток: Ctrie та поширення в екосистемі

У 2011–2012 роках Олександр Прокопець (Aleksandar Prokopec) разом із Філом Багвеллом та Мартіном Одерські опублікували працю про **Ctrie (Concurrent Trie)** — мутабельну високоефективну багатопотокову версію HAMT. Завдяки використанню атомарних інструкцій `Compare-And-Swap` (CAS) та концепції генераційних вузлів (Generation Nodes), Ctrie дозволила виконувати паралельні операції вставки, видалення та створення знімків стану (Snapshots) за час `O(1)` без використання жодного м'ютекса чи блокування.

Сьогодні HAMT та її модифікації є фундаментальним стандартом у багатьох сучасних мовах програмування та екосистемах:
- **Haskell:** стандартний пакет `unordered-containers` (автор Йоган Тібелл) використовує HAMT для реалізації `Data.HashMap.Strict`, що забезпечує значно вищу продуктивність порівняно з давніми двійковими деревами `Data.Map`.
- **Rust:** бібліотека `im` (та `im-rc`) надає персистентні геш-мапи на основі HAMT для системного програмування з гарантією безпеки пам'яті.
- **JavaScript / V8:** бібліотека `Immutable.js` від Facebook, а також внутрішні структури оптимізації контекстів у рушіях JavaScript спираються на бітово-маповані префіксні дерева для швидкого порівняння станів у компонентах React.
- **Блокчейн-платформи:** структура Merkle Patricia Trie (вживана в Ethereum) є прямою модифікацією ідей HAMT та PATRICIA trees для швидкого формування криптографічних доказів стану мережі.

Внесок Філа Багвелла (який передчасно пішов із життя у 2012 році) залишається одним із найважливіших досягнень у галузі практичних структур даних XXI століття.
