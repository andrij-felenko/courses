# 📋 Інтерфейс та інваріанти таблиці хешування зозулею

Специфікація інтерфейсу модуля хешування зозулею (Cuckoo Hash Map) визначає контракт взаємодії, типи даних, коди повернення, інваріанти цілісності та гарантії часової складності для систем реального часу та високонавантажених мережевих сервісів.

Модуль надає програмний інтерфейс двома мовами: чистою мовою C (стандарт C99/C11) з явним контролем розподілу пам'яті та кодами помилок, а також ідіоматичною мовою C++ (стандарт C++17/C++20) з підтримкою узагальнених типів, концептів, розумних покажчиків і семантики переміщення.

## Типи даних та конфігурація

Конфігурація таблиці визначається набором статичних та динамічних параметрів, які контролюють поведінку структури під час наближення до критичного коефіцієнта заповнення:

| Параметр | Тип | Типове значення | Призначення |
| :--- | :--- | :--- | :--- |
| `initial_capacity` | `size_t` | `16` | Початкова кількість кошиків у кожній із двох підтаблиць `T₁` та `T₂` |
| `max_load_factor` | `float` | `0.45` (для `b=1`), `0.90` (для `b=4`) | Коефіцієнт заповнення, при перевищенні якого ініціюється розширення |
| `max_displacements` | `size_t` | `2 · capacity` | Максимальна глибина ланцюжка витіснень перед скиданням у схованку |
| `stash_capacity` | `size_t` | `4` | Кількість слотів у резервному буфері схованки |

:::tabs
```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

/* Коди результатів виконання операцій */
typedef enum {
    CUCKOO_OK               =  0,  /* Операція завершилася успішно */
    CUCKOO_ERR_NOT_FOUND    = -1,  /* Ключ не знайдено в жодній таблиці чи схованці */
    CUCKOO_ERR_KEY_EXISTS   = -2,  /* Ключ уже присутній у таблиці */
    CUCKOO_ERR_NO_MEMORY    = -3,  /* Збій виділення динамічної пам'яті */
    CUCKOO_ERR_REHASH_FAIL  = -4,  /* Не вдалося перехешувати таблицю після вичерпання спроб */
    CUCKOO_WARN_STASH_USED  =  1   /* Елемент збережено в аварійній схованці */
} CuckooStatus;

/* Статистика внутрішнього стану таблиці */
typedef struct {
    size_t total_elements;        /* Загальна кількість збережених пар */
    size_t table_capacity;         /* Сумарна місткість основних таблиць T1 + T2 */
    size_t stash_count;            /* Поточна кількість елементів у схованці */
    size_t rehash_count;           /* Кількість виконаних перехешувань за час життя */
    double load_factor;            /* Поточний коефіцієнт заповнення (elements / capacity) */
} CuckooStats;

/* Непрозора структура хеш-таблиці */
typedef struct CuckooMap CuckooMap;
```

#include <cstdint>

    std::size_t rehash_count{0};
    double load_factor{0.0};
};

## Специфікація функцій (C та C++ API)

### 1. `cuckoo_map_create`
Ініціалізує нову таблицю зозулі із заданою початковою місткістю.

:::tabs
```c
CuckooMap *cuckoo_map_create(size_t initial_capacity);
```
```cpp
// Конструктор CuckooMap<Key, Value>
explicit CuckooMap(std::size_t initial_capacity = 16);
```
:::
- **Призначення:** Створює новий екземпляр таблиці та виділяє пам'ять під дві підтаблиці `T₁` і `T₂` однакового розміру.
- **Параметри:** `initial_capacity` — бажана кількість слотів у кожній таблиці (якщо передано менше 8, автоматично встановлюється значення 8; для ефективності бітових масок рекомендується передавати степені двійки).
- **Повертає:** Покажчик на виділену структуру `CuckooMap` або `NULL` у разі вичерпання доступної пам'яті. У C++ повертає створений екземпляр об'єкта або генерує виняток `std::bad_alloc`.
- **Часова складність:** `O(m)`, де `m` — початкова місткість.
- **Передмова:** Немає.
- **Післямова:** Виділяється блок пам'яті для двох масивів `T₁` та `T₂` місткістю `m` кожен, усі слоти ініціалізуються як порожні (`occupied = false`), схованка `stash` обнуляється, генеруються незалежні псевдовипадкові зерна `seed1` та `seed2`.

### 2. `cuckoo_map_destroy`
Повністю звільняє всі динамічні ресурси, зайняті таблицею.

:::tabs
```c
void cuckoo_map_destroy(CuckooMap *map);
```
```cpp
// Автоматичне звільнення ресурсів за принципом RAII
~CuckooMap() = default;
```
:::
- **Призначення:** Звільняє пам'ять масивів `t1`, `t2` та самої структури `CuckooMap`.
- **Параметри:** `map` — покажчик на екземпляр таблиці. Допускається безпечна передача покажчика `NULL` (у цьому випадку функція не виконує жодних дій).
- **Часова складність:** `O(1)`.
- **Передмова:** Покажчик `map` отримано через виклик `cuckoo_map_create`.
- **Післямова:** Уся пам'ять звільняється, покажчик стає недійсним.

### 3. `cuckoo_map_find`
Здійснює детермінований пошук значення за 64-бітним ключем.

:::tabs
```c
CuckooStatus cuckoo_map_find(const CuckooMap *map, uint64_t key, uint64_t *out_value);
```
```cpp
[[nodiscard]] std::optional<Value> find(const Key &key) const;
[[nodiscard]] bool contains(const Key &key) const noexcept;
```
:::
- **Призначення:** Перевіряє наявність ключа у структурі та зчитує асоційоване значення.
- **Параметри:**
  - `map` — покажчик на ініціалізовану таблицю.
  - `key` — 64-бітний ключ для пошуку.
  - `out_value` — покажчик для запису знайденого значення (може бути `NULL`, якщо користувача цікавить лише факт наявності ключа).
- **Повертає:**
  - `CUCKOO_OK` — якщо ключ знайдено в `T₁`, `T₂` або у схованці.
  - `CUCKOO_ERR_NOT_FOUND` — якщо ключ відсутній у всіх можливих слотах.
- **Часова складність:** Строго `O(1)` у найгіршому разі (щонайбільше 2 звернення до пам'яті в основних таблицях плюс перевірка 4 слотів схованки).

### 4. `cuckoo_map_insert`
Вставляє нову пару «ключ — значення» або оновлює наявну.

:::tabs
```c
CuckooStatus cuckoo_map_insert(CuckooMap *map, uint64_t key, uint64_t value);
```
```cpp
CuckooStatus insert(const Key &key, const Value &value);
CuckooStatus insert_or_assign(const Key &key, const Value &value);
```
:::
- **Призначення:** Додає новий елемент із динамічним витісненням за потреби або перезаписує значення наявного ключа.
- **Параметри:**
  - `map` — покажчик на таблицю.
  - `key` — цілочисельний ключ.
  - `value` — асоційоване значення.
- **Повертає:**
  - `CUCKOO_OK` — елемент успішно розміщено в `T₁` або `T₂`.
  - `CUCKOO_WARN_STASH_USED` — елемент розміщено в аварійній схованці через вичерпання ліміту кроків витіснення.
  - `CUCKOO_ERR_NO_MEMORY` — не вдалося виділити пам'ять під час автоматичного перехешування.
- **Часова складність:** `O(1)` амортизовано, `O(n)` у найгіршому разі рідкісного перехешування.

### 5. `cuckoo_map_erase`
Видаляє ключ і звільняє зайнятий ним слот.

:::tabs
```c
CuckooStatus cuckoo_map_erase(CuckooMap *map, uint64_t key);
```
```cpp
bool erase(const Key &key);
void clear() noexcept;
```
:::
- **Призначення:** Видаляє вказаний ключ без необхідності встановлення фіктивних надгробків.
- **Параметри:**
  - `map` — покажчик на таблицю.
  - `key` — ключ для видалення.
- **Повертає:**
  - `CUCKOO_OK` — ключ успішно знайдено й видалено.
  - `CUCKOO_ERR_NOT_FOUND` — ключа не існувало в таблиці.
- **Часова складність:** Строго `O(1)` у найгіршому разі.

### 6. `cuckoo_map_get_stats`
Повертає актуальні діагностичні показники стану структури даних.

:::tabs
```c
void cuckoo_map_get_stats(const CuckooMap *map, CuckooStats *out_stats);
```
```cpp
[[nodiscard]] CuckooStats stats() const noexcept;
```
:::
- **Призначення:** Надає доступ до статистики заповненості, місткості, кількості перехешувань та використання схованки.
- **Параметри:**
  - `map` — покажчик на таблицю.
  - `out_stats` — покажчик на структуру `CuckooStats` для запису метрик.

## Специфікація об'єктно-орієнтованого C++ API

Клас-шаблон `CuckooMap<Key, Value, Hash1, Hash2>` інкапсулює поведінку таблиці з безпечною системою типів:

```cpp
template <
    typename Key,
    typename Value,
    typename Hash1 = DefaultHash1<Key>,
    typename Hash2 = DefaultHash2<Key>
>
class CuckooMap {
public:
    using key_type = Key;
    using mapped_type = Value;
    using value_type = std::pair<const Key, Value>;
    using size_type = std::size_t;

    explicit CuckooMap(size_type initial_capacity = 16);
    ~CuckooMap() = default;

    CuckooMap(const CuckooMap &other);
    CuckooMap(CuckooMap &&other) noexcept;
    CuckooMap &operator=(const CuckooMap &other);
    CuckooMap &operator=(CuckooMap &&other) noexcept;

    [[nodiscard]] std::optional<Value> find(const Key &key) const;
    [[nodiscard]] bool contains(const Key &key) const noexcept;

    CuckooStatus insert(const Key &key, const Value &value);
    CuckooStatus insert_or_assign(const Key &key, const Value &value);

    bool erase(const Key &key);
    void clear() noexcept;

    [[nodiscard]] size_type size() const noexcept;
    [[nodiscard]] size_type capacity() const noexcept;
    [[nodiscard]] bool empty() const noexcept;
    [[nodiscard]] CuckooStats stats() const noexcept;
};
```

## Інваріанти структури даних

Для забезпечення строгої математичної коректності та безпеки виконання операцій реалізація підтримує такі фундаментальні інваріанти:

1. **Інваріант локалізації ключа:**
   Кожен збережений ключ `x ∈ S` обов'язково перебуває рівно в одній із трьох чітко визначених позицій:
   ```
   x ∈ T₁[h₁(x)]  ∨  x ∈ T₂[h₂(x)]  ∨  x ∈ Stash    [інваріант розміщення ключа]
   ```
   Жоден елемент за жодних обставин не може опинитися за іншим індексом.

2. **Інваріант унікальності:**
   Жоден ключ не може одночасно дублюватися у двох різних слотах (наприклад, одночасно в `T₁[h₁(x)]` та `T₂[h₂(x)]`). Попередня перевірка наявності ключа перед кожною вставкою гарантує повну відсутність клонів.

3. **Інваріант місткості комірки:**
   Кожен слот `T₁[i]` та `T₂[j]` містить щонайбільше один активний запис (`occupied == true`).

4. **Інваріант безпеки витіснення:**
   Під час ланцюжка витіснень елемент `y`, що звільняє комірку в `T₁`, негайно переміщується у свій альтернативний законний слот `T₂[h₂(y)]`. У будь-який момент часу кожен активний елемент знаходиться або у валідному слоті таблиці, або в локальній змінній потоку виконання, що запобігає втраті даних.

## Гарантії часової складності та конкурентність

| Операція | Найкращий час | Середній час | Найгірший час | Звернень до пам'яті |
| :--- | :--- | :--- | :--- | :--- |
| `Find` | `O(1)` (1 такт) | `O(1)` (1.2 звернення) | `O(1)` (2 слоти + stash) | `2 + STASH_CAPACITY` |
| `Erase` | `O(1)` (1 такт) | `O(1)` (1.2 звернення) | `O(1)` (2 слоти + stash) | `2 + STASH_CAPACITY` |
| `Insert` (без витіснень) | `O(1)` (1 такт) | `O(1)` (1.3 витіснення) | `O(1)` | `2` |
| `Insert` (з витісненням) | `O(1)` (2 такти) | `O(1)` (стало) | `O(max_steps)` | `2 · max_steps` |
| `Rehash` | `O(n)` | `O(n)` | `O(n)` | `2n` |

## Рекомендації щодо безпечної багатопотоковості

У середовищах із багатьма потоками виконання хешування зозулею надає унікальні можливості для асиметричної оптимізації читання та запису:
- **Безблокувальне читання (Lock-Free Reads):** Оскільки операція `Find` перевіряє лише два фіксовані слоти, потоки-читачі можуть виконувати пошук без захоплення м'ютексів. Для цього запис полів `key` та `value` здійснюється з використанням атомарних операцій `std::atomic` із бар'єром пам'яті `memory_order_release`, а читач зчитує їх через `memory_order_acquire`.
- **Сегментоване блокування запису (Striped Locks):** Для операцій `Insert` та `Erase` застосовують масив незалежних м'ютексів (наприклад, 64 або 256 м'ютексів на таблицю). Кожен кошик прив'язується до свого м'ютекса за маскою індексу. Під час витіснення потік блокує лише задіяні комірки, що дозволяє виконувати паралельні вставки в різні частини таблиці без взаємного блокування.
- **Вирівнювання по межах кеш-рядків (Cache Line Alignment):** Щоб уникнути ефекту фальшивого спільного використання пам'яті (false sharing) між різними процесорними ядрами, блоки кошиків та м'ютекси вирівнюють за межею 64 байтів за допомогою специфікатора `alignas(64)`.
