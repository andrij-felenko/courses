# 📋 Інтерфейсна специфікація та контракт сортування вставками

Ця довідкова вставка містить вичерпну специфікацію програмних інтерфейсів (API), сигнатур функцій, контрактів виконання, передумов, післяумов, гарантій винятків та обробки граничних станів для сімейства алгоритмів сортування вставками у мовах C та C++.

## 1. Загальний огляд інтерфейсної поверхні

Сортування вставками надає функції для трьох різних парадигм організації даних:
1. **Універсальний поліморфний інтерфейс у стилі POSIX `qsort` (C89/C99/C11):** робота з нетипізованими вказівниками `void*` та функціями зворотного виклику для порівняння.
2. **Типобезпечні шаблонні функції на діапазонах та ітераторах (C++17/C++20):** інтеграція зі стандартною бібліотекою, концептами `std::ranges` та проєкціями (projections).
3. **Спеціалізовані мікроінтерфейси для систем реального часу та ядер операційних систем:** нульова залежність від стандартної бібліотеки, гарантії відсутності динамічної алокації пам'яті.

## 2. Специфікація API для мови C (ISO C99/C11)

### Поліморфний інтерфейс для довільних типів даних

:::tabs
```c
#include <stddef.h>

/**
 * @brief Сортує масив довільних об'єктів методом прямих вставок.
 * 
 * @param base   Вказівник на перший елемент масиву.
 * @param nel    Кількість елементів у масиві.
 * @param width  Розмір одного елемента в байтах (sizeof(T)).
 * @param compar Вказівник на функцію порівняння двох елементів.
 * 
 * @return void
 */
void insertion_sort_generic(
    void *base,
    size_t nel,
    size_t width,
    int (*compar)(const void *, const void *)
);
```
```cpp
#include <cstddef>
#include <concepts>

// C++ сумісне оголошення функції з C-лінкуванням
extern "C" {
    void insertion_sort_generic(
        void *base,
        std::size_t nel,
        std::size_t width,
        int (*compar)(const void *, const void *)
    );
}
```
:::

#### Контракт виконання функції `insertion_sort_generic`

* **Передумови (Preconditions):**
  - Якщо `nel > 0`, покажчик `base` мусить бути валідним і вказувати на неперервний блок доступної пам'яті розміром щонайменше `nel * width` байтів.
  - Покажчик `compar` не повинен бути `NULL`.
  - Функція `compar(a, b)` повинна реалізовувати строгий слабкий порядок: повертати від'ємне число, якщо `*a < *b`; `0`, якщо `*a` еквівалентно `*b`; додатне число, якщо `*a > *b`.
  - Пам'ять елементів не повинна перекриватися з іншими неконтрольованими об'єктами.
* **Післяумови (Postconditions):**
  - Масив за адресою `base` містить ті самі `nel` елементів, перевпорядкованих таким чином, що для всіх `0 <= i < j < nel` виконується `compar(base + i*width, base + j*width) <= 0`.
  - Зберігається стійкість сортування: якщо `compar(a, b) == 0`, їхній взаємний порядок у масиві залишається незмінним.
* **Граничні стани:**
  - Якщо `base == NULL` або `nel <= 1` або `width == 0`, функція негайно повертає керування без модифікації пам'яті (no-op).

### Типобезпечний мономорфний макрогенератор (C99)

Для усунення накладних витрат на виклик функції через вказівник у гарячому циклі в мові C використовується генерація спеціалізованих інлайн-функцій:

:::tabs
```c
#include <stddef.h>

#define DEFINE_INSERTION_SORT(NAME, TYPE, LESS_THAN)                         \
static inline void insertion_sort_##NAME(TYPE *arr, size_t n) {              \
    if (arr == NULL || n <= 1) return;                                       \
    for (size_t i = 1; i < n; ++i) {                                          \
        TYPE key = arr[i];                                                    \
        size_t j = i;                                                         \
        while (j > 0 && LESS_THAN(key, arr[j - 1])) {                         \
            arr[j] = arr[j - 1];                                              \
            --j;                                                              \
        }                                                                     \
        arr[j] = key;                                                         \
    }                                                                         \
}
```
```cpp
#include <span>
#include <functional>

// Еквівалентний шаблон C++ без використання макросів препроцесора
template <typename T, auto LessThan = std::less<T>{}>
void static_insertion_sort(std::span<T> data) {
    if (data.size() <= 1) return;
    for (std::size_t i = 1; i < data.size(); ++i) {
        T key = std::move(data[i]);
        std::size_t j = i;
        while (j > 0 && LessThan(key, data[j - 1])) {
            data[j] = std::move(data[j - 1]);
            --j;
        }
        data[j] = std::move(key);
    }
}
```
:::

## 3. Специфікація API для мови C++ (C++20 Ranges & Concepts)

У сучасному C++ сортування вставками проектується у повній відповідності до вимог бібліотеки концептів `std::ranges`.

### Сигнатури концептуальних інтерфейсів

:::tabs
```cpp
#include <iterator>
#include <ranges>
#include <functional>

namespace algo {

    /**
     * @brief Класичне сортування вставками для діапазону ітераторів.
     * Вимагає щонайменше двонаправлених ітераторів (bidirectional_iterator).
     */
    template <
        std::bidirectional_iterator I,
        std::sentinel_for<I> S,
        typename Comp = std::ranges::less,
        typename Proj = std::identity
    >
    requires std::sortable<I, Comp, Proj>
    constexpr I insertion_sort(
        I first,
        S last,
        Comp comp = {},
        Proj proj = {}
    );

    /**
     * @brief Двійкове сортування вставками.
     * Вимагає ітераторів довільного доступу (random_access_iterator) для бінарного пошуку.
     */
    template <
        std::random_access_iterator I,
        std::sentinel_for<I> S,
        typename Comp = std::ranges::less,
        typename Proj = std::identity
    >
    requires std::sortable<I, Comp, Proj>
    constexpr I binary_insertion_sort(
        I first,
        S last,
        Comp comp = {},
        Proj proj = {}
    );

    /**
     * @brief Перевантаження для безпосередньої роботи з об'єктами Range (вектори, масиви, span).
     */
    template <
        std::ranges::bidirectional_range R,
        typename Comp = std::ranges::less,
        typename Proj = std::identity
    >
    requires std::sortable<std::ranges::iterator_t<R>, Comp, Proj>
    constexpr std::ranges::borrowed_iterator_t<R> insertion_sort(
        R&& r,
        Comp comp = {},
        Proj proj = {}
    );

} // namespace algo
```
```c
/* У чистому C концептуальні перевантаження не підтримуються.
   Натомість використовуються чіткі роздільні імена функцій. */
#include <stddef.h>

void insertion_sort_bidirectional(void *base, size_t n, size_t sz, int (*cmp)(const void*, const void*));
void binary_insertion_sort_random_access(int *arr, size_t n);
```
:::

#### Специфікація вимог до типів (Type Constraints)

* **`std::bidirectional_iterator<I>`:** Ітератор повинен підтримувати операції інкременту `++it` та декременту `--it`. Для лінійного сортування вставками операція прямого доступу за індексом `it[n]` не є обов'язковою, що дозволяє сортувати двобічно зв'язані списки `std::list`.
* **`std::random_access_iterator<I>`:** Для `binary_insertion_sort` необхідна константна складність `O(1)` для обчислення середини інтервалу `it + (last - first) / 2` та різниці ітераторів `last - first`.
* **`std::indirect_strict_weak_order<Comp, std::projected<I, Proj>>`:** Предикат `comp` разом із проєкцією `proj` зобов'язаний задавати відношення строгого слабкого порядку над елементами, що розіменовуються ітератором `I`.

## 4. Реентрабельний інтерфейс із користувацьким контекстом (C11 Annex K та GNU C)

У реальних системних застосунках (драйвери, сервери баз даних, графічні рушії) функція порівняння часто потребує доступу до додаткового контексту — наприклад, покажчика на таблицю символів, поточної локалі або структури конфігурації. Класичний інтерфейс `qsort` не дозволяє передавати такий контекст без використання небезпечних глобальних змінних.

Для вирішення цієї проблеми специфікація сортування вставками визначає два стандартизовані реентрабельні інтерфейси:

:::tabs
```c
#include <stddef.h>

/* Реентрабельне сортування у стилі GNU (context першим аргументом компаратора) */
void insertion_sort_r(
    void *base,
    size_t nel,
    size_t width,
    int (*compar)(const void *, const void *, void *),
    void *arg
);

/* Безпечний інтерфейс за стандартом C11 Annex K (context останнім аргументом) */
int insertion_sort_s(
    void *base,
    size_t nel,
    size_t width,
    int (*compar)(const void *, const void *, void *),
    void *context
);
```
```cpp
#include <cstddef>
#include <functional>

// У C++ контекст природно інкапсулюється через лямбда-захоплення (Closures)
template <typename T, typename Context, typename CompareWithContext>
void insertion_sort_context(std::span<T> data, Context& ctx, CompareWithContext comp) {
    if (data.size() <= 1) return;
    for (std::size_t i = 1; i < data.size(); ++i) {
        T key = std::move(data[i]);
        std::size_t j = i;
        while (j > 0 && comp(key, data[j - 1], ctx)) {
            data[j] = std::move(data[j - 1]);
            --j;
        }
        data[j] = std::move(key);
    }
}
```
:::

#### Семантика та повертані значення `insertion_sort_s`
- Якщо `base == NULL`, `width == 0` або `compar == NULL`, функція `insertion_sort_s` не виконує сортування, викликає зареєстрований обробник порушення обмежень (Runtime Constraint Handler) і повертає ненульовий код помилки `EINVAL`.
- При успішному впорядкуванні масиву функція повертає `0`.

## 5. Формальні контракти за методологією Design by Contract

Для формальної верифікації програмного забезпечення наведемо повну специфікацію контрактів для функції сортування вставками у термінах передмов, післямов та інваріантів:

### 1. Передумови (Requires Clause)
- **`Valid_Range(first, last)`:** Діапазон `[first, last)` є дійсним і доступним для читання та запису.
- **`Strict_Weak_Order(comp, proj)`:** Предикат `comp` разом із проєкцією `proj` задає строгий слабкий порядок. Для будь-яких елементів `x, y, z` виконуються аксіоми:
  - `comp(x, x) == false` (іррефлексивність);
  - `comp(x, y) == true ⇒ comp(y, x) == false` (асиметричність);
  - `comp(x, y) && comp(y, z) ⇒ comp(x, z)` (транзитивність).
- **`Memory_Exclusivity`:** Пам'ять переданого діапазону не перекривається з іншими змінними, що можуть асинхронно змінюватися іншими потоками виконання під час сортування.

### 2. Післяумови (Ensures Clause)
- **`Is_Sorted(first, last, comp, proj)`:** Для кожної пари ітераторів `it1` та `it2`, де `first <= it1 < it2 < last`, предикат `comp(proj(*it2), proj(*it1))` дорівнює `false`.
- **`Is_Permutation(original_range, final_range)`:** Результуючий діапазон містить мультимножину елементів, яка є точною перестановкою початкової мультимножини елементів. Жоден елемент не втрачено і не додано.
- **`Stability_Preserved`:** Для будь-якої пари елементів `a` та `b`, де `a` передував `b` у вихідному масиві, якщо `!comp(proj(a), proj(b)) && !comp(proj(b), proj(a))` (еквівалентні ключі), то `a` гарантовано передує `b` у результуючому масиві (за винятком алгоритмів з явним префіксом `sentinel_`).

### 3. Інваріант стану (Loop Invariant)
- **`Prefix_Sorted(i)`:** На початку кожної ітерації зовнішнього циклу для індексу `i` підмасив `[first, first + i)` є повністю впорядкованим і містить перестановку початкових елементів із цього діапазону.

## 6. Внутрішні інтерфейси у стандартних бібліотеках C++ (libstdc++, libc++, MSVC)

Щоб побачити, як сортування вставками інтегрується в реальні інженерні системи, проаналізуємо внутрішні (непублічні) інтерфейси популярних стандартних бібліотек C++:

### 1. GNU libstdc++ (GCC)
У заголовковому файлі `bits/stl_algo.h` бібліотека libstdc++ визначає три взаємопов'язані функції:
- `__insertion_sort(_RandomAccessIterator __first, _RandomAccessIterator __last, _Compare __comp)`: класичне сортування вставками з повною перевіркою меж для малих діапазонів.
- `__unguarded_linear_insert(_RandomAccessIterator __last, _Value __val, _Compare __comp)`: внутрішня функція зсуву, яка передбачає наявність вартового елемента зліва і не перевіряє вихід за ліву межу.
- `__unguarded_insertion_sort(_RandomAccessIterator __first, _RandomAccessIterator __last, _Compare __comp)`: швидкісний варіант сортування вставками, який викликається на фінальному етапі `std::sort` після того, як Quicksort розбив масив на частково впорядковані блоки.

### 2. LLVM libc++ (Clang)
У файлі `algorithm` бібліотека libc++ використовує оптимізовану функцію `__insertion_sort_incomplete`, яка обмежує максимальну кількість кроків зсуву для запобігання квадратичному виродженню під час обробки специфічних анти-quicksort послідовностей.

### 3. Microsoft MSVC STL
У файлі `<algorithm>` бібліотека MSVC реалізує функцію `_Insertion_sort_unchecked`, яка відключає перевірки безпеки ітераторів (Checked Iterators) у релізних збірках для досягнення максимальної швидкості на конвеєрі процесора.

## 7. Статична діагностика та типові помилки компіляції

При некоректному використанні шаблонів сортування вставками система статичної типізації C++ генерує діагностичні повідомлення. Розглянемо типові сценарії:

### Помилка 1: Спроба сортування діапазону лише з прямими ітераторами
Якщо передати в `insertion_sort` однозв'язний список `std::forward_list`:
```cpp
std::forward_list<int> fl = {3, 1, 4};
algo::insertion_sort(fl.begin(), fl.end()); // Помилка компіляції!
```
*Діагностика:* Компілятор повідомляє про порушення вимоги концепту `std::bidirectional_iterator`. Лінійне сортування вставками масиву вимагає оператора декременту `--it` для руху від поточної позиції назад до початку префікса. Для однозв'язних списків необхідно використовувати спеціалізовану функцію `sort_linked_list`.

### Помилка 2: Несумісність типів у користувацькій проєкції
Якщо передати проєкцію, яка повертає тип, що не підтримує порівняння через переданий компаратор:
```cpp
struct User { std::string name; int id; };
std::vector<User> users;
// Помилка: comp очікує int, а проєкція повертає string!
algo::insertion_sort(users, std::less<int>{}, &User::name);
```
*Діагностика:* Концепт `std::indirect_strict_weak_order` фіксує невідповідність типів між результатом виклику `std::invoke(proj, *it)` та аргументами компаратора на етапі перевірки обмежень шаблону (Concept Constraint Satisfaction).

## 8. Гарантії безпеки щодо винятків (Exception Safety)

Поведінка C++ шаблонів при виникненні виняткових ситуацій під час роботи компаратора чи конструкторів переміщення/копіювання регламентується такими гарантіями:

1. **Гарантія відсутності винятків (Nothrow Guarantee):**
   - Якщо операції переміщення типу `T` (`std::is_nothrow_move_constructible_v<T>` та `std::is_nothrow_move_assignable_v<T>`) та виклик `comp` позначені як `noexcept`, функція `insertion_sort` має специфікатор `noexcept` і гарантовано не генерує винятків.
2. **Базова гарантія винятків (Basic Exception Guarantee):**
   - Якщо компаратор `comp` або копіювання об'єкта генерує виняток, у масиві не виникає витоків пам'яті (memory leaks) та подвійного звільнення ресурсів (double free). Усі об'єкти залишаються у валідному, хоча й невизначеному стані.
3. **Вимога до проєкцій:**
   - Функція проєкції `proj` не повинна модифікувати переданий елемент (має бути константною та ідемпотентною).

## 10. Вимоги для вбудованих систем (Bare-metal & Embedded API)

У низькорівневих системах реального часу (RTOS, прошивки мікроконтролерів ARM Cortex-M, архітектури без операційної системи) до інтерфейсів сортування висуваються жорсткі вимоги щодо передбачуваності використання ресурсів:

### 1. Гарантія нульової динамічної пам'яті (Zero Heap Allocation)
- Функції сортування вставками гарантують, що під час їх виконання **не здійснюється жодного виклику** `malloc`, `calloc`, `realloc`, `free` або операторів `new`/`delete`.
- Це дозволяє викликати функції всередині обробників переривань (ISR, Interrupt Service Routines), де використання розподілювачів динамічної пам'яті строго заборонене через небезпеку взаємних блокувань (Deadlocks) та недетермінований час виконання.

### 2. Строго обмежений розмір стекового кадру (Stack Frame Bounds)
- Максимальний обсяг пам'яті, що виділяється на стеку потоку для виконання `insertion_sort`, обмежений константою:
```
Stack_Size = sizeof(T) + 3 · sizeof(size_t) + C_alignment
```
- Наприклад, для 32-бітного мікроконтролера STM32 при сортуванні 32-бітних цілих чисел (`int32_t`) весь стековий кадр функції займає не більше `24 байтів`, що унеможливлює переповнення стеку (Stack Overflow) навіть у середовищах із загальним розміром стеку задачі в 512 байтів.

## 11. Специфікація інтерфейсу для часткових діапазонів (Subrange API)

Для використання сортування вставками як базового будівельного блоку у складних структурах даних (наприклад, сортування окремих бакетів у Hash Table, листя в B-деревах або підмасивів у Quicksort) визначено спеціалізований інтерфейс роботи з піддіапазонами:

:::tabs
```c
#include <stddef.h>

/**
 * @brief Сортує підмасив у межах більшого масиву [left, right] включно.
 * 
 * @param arr   Вказівник на початок базового масиву.
 * @param left  Індекс першого елемента підмасиву.
 * @param right Індекс останнього елемента підмасиву (включно).
 */
void insertion_sort_subrange(int *arr, size_t left, size_t right);
```
```cpp
#include <span>
#include <functional>

template <typename T, typename Compare = std::less<T>>
void insertion_sort_subrange(std::span<T> data, std::size_t left, std::size_t right, Compare comp = Compare{}) {
    if (left >= right || right >= data.size()) {
        return;
    }
    insertion_sort(data.subspan(left, right - left + 1), comp);
}
```
:::

#### Контракт виконання `insertion_sort_subrange`
- **Передумова:** `left <= right && right < total_size`.
- **Післяумова:** Елементи з індексами `[0...left-1]` та `[right+1...total_size-1]` залишаються незмінними. Підмасив `[left...right]` стає повністю відсортованим.

## 13. Специфікація потокового інкрементального інтерфейсу (Online & Streaming API)

Сортування вставками є за своєю суттю **онлайн-алгоритмом** (Online Algorithm): воно здатне впорядковувати потік даних у міру їх надходження без необхідності мати весь масив у пам'яті наперед.

Для систем обробки потокових подій (ринкові котирування, телеметрія сенсорів, планувальники пакетів) визначається інтерфейс інкрементальної вставки:

:::tabs
```c
#include <stddef.h>
#include <stdbool.h>

typedef struct {
    int *data;
    size_t size;
    size_t capacity;
} SortedStreamBuffer;

/**
 * @brief Вставляє новий елемент у вже відсортований буфер зі збереженням порядку.
 * 
 * @param buf Вказівник на дескриптор буфера.
 * @param val Значення, що додається.
 * @return true при успішній вставці, false якщо буфер заповнений.
 */
bool stream_buffer_insert(SortedStreamBuffer *buf, int val) {
    if (buf == NULL || buf->data == NULL || buf->size >= buf->capacity) {
        return false;
    }

    size_t j = buf->size;
    while (j > 0 && buf->data[j - 1] > val) {
        buf->data[j] = buf->data[j - 1];
        --j;
    }

    buf->data[j] = val;
    buf->size++;
    return true;
}
```
```cpp
#include <vector>
#include <algorithm>
#include <concepts>

template <typename T, typename Compare = std::less<T>>
class SortedStreamBufferCpp {
public:
    explicit SortedStreamBufferCpp(std::size_t max_capacity, Compare comp = Compare{})
        : capacity_(max_capacity), comp_(comp) {
        data_.reserve(max_capacity);
    }

    bool insert(T val) {
        if (data_.size() >= capacity_) {
            return false;
        }

        // Бінарний пошук точки вставки у відсортованому векторі
        auto pos = std::upper_bound(data_.begin(), data_.end(), val, comp_);
        data_.insert(pos, std::move(val));
        return true;
    }

    [[nodiscard]] std::span<const T> view() const noexcept {
        return data_;
    }

private:
    std::vector<T> data_;
    std::size_t capacity_;
    Compare comp_;
};
```
:::

#### Контракт потокового інтерфейсу
- **Складність операції:** Пошук позиції та зсув виконуються за час `O(K)`, де `K` — поточна кількість елементів у буфері.
- **Інваріант:** Після кожного успішного виклику `insert` буфер залишається строго відсортованим.

## 14. Специфікація для простору ядра операційної системи (Kernel Space API)

У коді ядра Linux (`linux/lib/`) та драйверах пристроїв рекурсивні виклики та неконтрольований ріст стека є неприпустимими через жорстке обмеження стеку ядра (типово 8 або 16 КБ на процес у x86-64).

### Специфікація ядра (Kernel Contract)
- **`NO_RECURSION`:** Алгоритм сортування вставками виконується виключно за допомогою ітеративних циклів `for`/`while`, гарантуючи глибину стеку `O(1)`.
- **`ATOMIC_EXECUTION`:** Функція може безпечно викликатися в контексті атомних операцій та обробників переривань верхньої половини (Hard IRQ) при утриманні спінлоків (`spin_lock_irqsave`), оскільки вона не викликає функцій, що можуть заснути (Non-sleeping context).
- **`MEMORY_BARRIERS`:** При сортуванні масивів керуючих дескрипторів апаратних кілець DMA запис ключів у комірки супроводжується відповідними бар'єрами пам'яті (`smp_wmb()`) для гарантії узгодженості кешів когерентності шини PCIe.

Для функцій із підтримкою обробки помилок стандартизовано такі коди повернення (відповідно до заголовка `<errno.h>`):

| Код помилки | Числове значення | Причина виникнення |
| :--- | :--- | :--- |
| **`0 (SUCCESS)`** | `0` | Масив успішно впорядковано за контрактом. |
| **`EINVAL`** | `22` | Некоректні аргументи: `base == NULL` при `nel > 0`, `compar == NULL` або `width == 0`. |

## 16. Гарантії бінарної сумісності (ABI Stability & Linkage)

При включенні функцій сортування вставками до складу динамічних бібліотек (`.so` в Linux, `.dll` у Windows, `.dylib` у macOS) необхідно враховувати правила двійкової сумісності (Application Binary Interface):

1. **Експорт C-символів (C Linkage):** Функції C API (`insertion_sort_generic`, `insertion_sort_r`, `insertion_sort_s`) експортуються з немодифікованими іменами (`extern "C"`), що забезпечує пряму сумісність із будь-якими іншими мовами програмування через механізм FFI (Foreign Function Interface) у Rust, Python (`ctypes`), Go (`cgo`), Java (`JNI/JNA`) та C#.
2. **Контроль видимості символів (Symbol Visibility):** Для запобігання конфліктам імен у великих монолітних додатках допоміжні функції повинні позначатися атрибутом прихованої видимості `__attribute__((visibility("hidden")))` у GCC/Clang або оголошуватися як `static inline`.
3. **Робота з поліморфними алокаторами (C++17 PMR):** Оскільки сортування вставками виконується на місці (in-place) без виділення динамічної пам'яті, шаблонні інтерфейси є повністю прозорими для контейнерів із поліморфними ресурсами пам'яті `std::pmr::vector` та користувацькими алокаторами, не спричиняючи жодного скидання алокацій чи порушення арени пам'яті.

## 17. Граничні умови та обробка некоректного використання (Misuse Prevention)

### 1. Робота з порожніми масивами та одиничними елементами
Будь-яка реалізація сортування вставками зобов'язана коректно обробляти розміри `N = 0` та `N = 1` як тривіально відсортовані послідовності. Жодних розіменувань вказівників чи звернень до компаратора для таких діапазонів не виконується.

### 2. Спеціальні числові значення IEEE 754 (NaN)
Якщо масив чисел із плаваючою комою (`float`, `double`) містить значення `NaN` (Not-a-Number), стандартний оператор `<` повертає `false` для будь-яких порівнянь за участю `NaN` (наприклад, `NaN < x` є `false`, і `x < NaN` є `false`). Це порушує транзитивність незрівнянності:
- **Наслідок:** елементи `NaN` перестають пересуватися і можуть «застрягати» в довільних позиціях масиву, розриваючи впорядкованість інших чисел.
- **Вимога до API:** Для чисел з плаваючою комою у виробничих системах слід використовувати спеціалізовані предикати повного порядку (такі як `std::strong_order` у C++20 або `totalOrder` у IEEE 754-2008), які розміщують `-NaN` на початку, а `+NaN` у кінці масиву.

### 3. Збереження стійкості при користувацькому компараторі
Для збереження стійкості сортування вставками внутрішній цикл повинен перевіряти умову `comp(key, arr[j - 1])`, а не `!comp(arr[j - 1], key)` чи `arr[j - 1] >= key`. Якщо елементи мають однакові ключі, вираз `comp(key, arr[j - 1])` повертає `false`, цикл негайно зупиняється, і новий елемент сідає строго праворуч від раніше вставленого дубліката.
