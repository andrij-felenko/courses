# 🧮 Математичне доведення коректності інтервального дерева

Ця вставка містить формальні математичні означення, інваріанти доповненого бінарного дерева пошуку (Augmented Binary Search Tree), доведення основної теореми пошуку перетину, математичне обґрунтування збереження інваріантів при поворотах та вилученні, а також доведення складності процедури пошуку всіх перетинів.

---

## 1. Формальне означення інтервалів та відношення перетину

Нехай `R` позначує множину дійсних чисел. Замкненим одновимірним інтервалом `i` називається впорядкована пара дійсних чисел `[l[i], r[i]]`, де `l[i]` відповідає лівій (нижній) межі, а `r[i]` — правій (верхній) межі, причому виконується фундаментальна умова некоректності від'ємної довжини:

```
l[i] ≤ r[i]
```

Довжина інтервалу визначається як неотриємна величина `len(i) = r[i] - l[i] ≥ 0`. Випадок `l[i] = r[i]` відповідає виродженому точковому інтервалу.

Для двох інтервалів `i = [l[i], r[i]]` та `j = [l[j], r[j]]` відношення перетину `Overlap(i, j)` визначається як логічна предикатна функція:

```
Overlap(i, j) = (l[i] ≤ r[j]) ∧ (r[i] ≥ l[j])
```

Два інтервали **не перетинаються** (`¬Overlap(i, j)`), якщо і тільки якщо один із них розташований строго ліворуч від іншого на числовій прямій:

```
¬Overlap(i, j) = (r[i] < l[j]) ∨ (r[j] < l[i])
```

На множині інтервалів вводиться строго відношення лінійного порядку `≺` за лівою межею `l[i]` (і за правою межею `r[i]` у випадку рівності лівих меж):

```
i ≺ j  ⇔  (l[i] < l[j]) ∨ (l[i] = l[j] ∧ r[i] < r[j])
```

## 2. Структура та інваріанти доповненого дерева

Нехай `T` — балансоване бінарне дерево пошуку (наприклад, червоно-чорне дерево), у вузлах якого зберігається множина з `n` інтервалів. Кожен вузол `x` дерева `T` містить:
1. Інтервальний об'єкт `int[x] = [l[x], r[x]]`.
2. Ключ бінарного дерева пошуку, яким слугує ліва межа `l[x]`.
3. Дочірні вказівники `left[x]` та `right[x]`, а також вказівник на батьківську вершину `p[x]`.
4. Атрибут аугментації `max[x]`, який за означенням дорівнює точній верхній межі (супремуму) правих кінців серед усіх інтервалів, збережених у піддереві з коренем у `x`:

```
max[x] = max { r[y] | y ∈ Subtree(x) }
```

### Рекурсивне означення та локальний інваріант `max`

Для довільного вузла `x` атрибут `max[x]` виражається через атрибути його прямих дочірніх вузлів за допомогою локальної рекурентної формули:

```
max[x] = max( r[x], max[left[x]], max[right[x]] )
```

де за домовленістю для фіктивного листового вузла `NIL` покладається значення `max[NIL] = -∞`.

Оскільки значення `max[x]` залежить виключно від власного інтервалу `r[x]` та значень `max` двох прямих дітей `left[x]` і `right[x]`, підтримання цього інваріанта при вставці, вилученні або поворотах дерева виконується за час `O(1)` для кожного зміненого вузла.

## 3. Збереження інваріанта max при поворотах та вилученні вузла

Під час відновлення балансу червоно-чорного чи AVL-дерева виконуються базові операції поворотів (`Left-Rotate` та `Right-Rotate`). Доведемо, що атрибут `max` коректно перераховується за локальний час `O(1)`.

### Теорема про перерахунок при лівому повороті `Left-Rotate(X)`

Розглянемо вузол `X` із правим сином `Y`. Ліве піддерево `X` позначимо через `α`, ліве піддерево `Y` — через `β`, а праве піддерево `Y` — через `γ`.

До повороту:
- `Subtree(X)` містить `X`, `Y`, `α`, `β`, `γ`.
- `Subtree(Y)` містить `Y`, `β`, `γ`.

Після виконання `Left-Rotate(X)` вузол `Y` стає батьком `X`:
- Нове піддерево `X'` містить `X`, `α`, `β`.
- Нове піддерево `Y'` містить `Y`, `X'`, `γ`.

**Формули оновлення:**
1. Спочатку обчислюється нове значення для нижнього вузла `X`:
   ```
   max[X] = max( r[X], max[α], max[β] )
   ```
2. Потім обчислюється нове значення для верхнього вузла `Y`:
   ```
   max[Y] = max( r[Y], max[X], max[γ] )
   ```

*Доведення коректності:*
Множина вузлів у новому піддереві `Subtree(X')` є точною об'єднаною множиною `{X} ∪ Subtree(α) ∪ Subtree(β)`. Отже, максимальне значення правого кінця в цьому піддереві дорівнює `max(r[X], max[α], max[β])`. Аналогічно, нове піддерево `Subtree(Y')` охоплює всі елементи початкового піддерева `Subtree(X)`, тому його нове значення `max[Y]` дорівнює максимум між `r[Y]`, `max[γ]` та вже оновленим `max[X]`. Інші вузли дерева свого складу не змінили, тому їхні атрибути `max` залишаються незмінними. ∎

### Математичне обґрунтування перерахунку при вилученні вузла (Delete)

При видаленні вузла `Z`, який має двох дітей, він замінюється своїм наступником `Y` (найменшим елементом правого піддерева `Subtree(right[Z])`).

1. Вузол `Y` переміщується на позицію `Z`.
2. Батьківські зв'язки та колір `Y` оновлюються за правилами BST/Red-Black Tree.
3. Шлях від колишнього батька `Y` до кореня дерева містить вузли, у піддеревах яких відбулася зміна складу елементів.
4. Для кожного вузла `P` вздовж цього шляху знизу вгору виконується повторний розрахунок:
   ```
   max[P] = max( r[P], max[left[P]], max[right[P]] )
   ```

Оскільки довжина шляху від вилученої вершини до кореня не перевищує висоту дерева `h = O(log n)`, повне оновлення інваріанта `max` після вилучення вимагає точно `O(log n)` операцій. ∎

## 4. Теорема про коректність алгоритму пошуку перетину

Алгоритм `Interval_Search(T, i)` приймає корінь дерева `T` та шуканий інтервал запиту `i = [l[i], r[i]]`. Процедура виконує обхід дерева від кореня до листків за таким алгоритмом:

```
x = root[T]
while x ≠ NIL and not Overlap(int[x], i):
    if left[x] ≠ NIL and max[left[x]] ≥ l[i]:
        x = left[x]
    else:
        x = right[x]
return x
```

### Формулювання теореми

**Теорема.** *Для довільного інтервалу запиту `i` процедура `Interval_Search(T, i)` повертає вузол `x`, що перетинає `i` (тобто `Overlap(int[x], i) = true`), або повертає `NIL`, якщо у дереві `T` не існує жодного інтервалу, що перетинає `i`.*

## 5. Детальне формальне доведення теореми

Для доведення теореми необхідно розглянути два взаємодоповнюючі твердження:

1. **Частина A (Коректність знайденого елемента):** Якщо алгоритм зупиняється на вузлі `x ≠ NIL`, то повернутий елемент є коректним (значено збіг).
2. **Частина B (Безпечність вибору напрямку):** Якщо алгоритм повертає `NIL` або повертає елемент із лівого/правого піддерева, то пропущені піддерева не містили шуканого перетину (або збіг гарантовано існує в обраному напрямку).

### Доведення Частини A

Умова виходу з циклу `while` вимагає зупинки при `x = NIL` або при виконанні умови `Overlap(int[x], i) == true`. Отже, якщо повертається `x ≠ NIL`, умова перетину виконується за конструюванням алгоритму.

### Доведення Частини B (Ключовий інваріант вибору гілки)

Розглянемо довільний вузол `x` на шляху пошуку, для якого `int[x]` не перетинає `i`. Оцінимо два можливі випадки прийняття рішення алгоритмом:

#### Випадок 1: Алгоритм повертає ліворуч (`left[x] ≠ NIL` та `max[left[x]] ≥ l[i]`)

Потрібно довести: якщо в усьому піддереві `Subtree(x)` існує принаймні один інтервал, що перетинає `i`, то принаймні один такий інтервал **обов'язково існує у лівому піддереві** `Subtree(left[x])`.

*Доведення:*
За означенням `max[left[x]]`, у лівому піддереві `Subtree(left[x])` існує деякий вузол `y` такий, що його права межа дорівнює максимумів лівого піддерева:

```
r[y] = max[left[x]]
```

З умови переходу ліворуч маємо:

```
r[y] = max[left[x]] ≥ l[i]      [Рівняння 1]
```

Оскільки дерево `T` впорядковане за лівими межами `l` (властивість бінарного дерева пошуку), а вузол `y` належить лівому піддереву `Subtree(left[x])`, його ліва межа не перевищує ліву межу поточного вузла `x`:

```
l[y] ≤ l[x]                      [Рівняння 2]
```

Оскільки поточний вузол `x` не перетинає `i`, аналізуємо відношення між `l[x]` та `r[i]`. Якби `l[x] > r[i]`, то з `l[y] ≤ l[x]` випливало б:

```
l[y] ≤ l[x] ≤ r[i]   ⇒   l[y] ≤ r[i]
```

Поєднуючи це з `r[y] ≥ l[i]` (з Рівняння 1), отримуємо:

```
(l[y] ≤ r[i]) ∧ (r[y] ≥ l[i])   ⇒   Overlap(int[y], i) = true
```

Отже, вузол `y` з лівого піддерева гарантовано перетинає `i`. Рішення піти ліворуч є математично безпечним та коректним.

#### Випадок 2: Алгоритм повертає праворуч (`left[x] = NIL` або `max[left[x]] < l[i]`)

Потрібно довести: у лівому піддереві `Subtree(left[x])` **не існує жодного інтервалу**, який би перетинав `i`.

*Доведення:*
Якщо `left[x] = NIL`, ліве піддерево порожнє, і твердження тривіально вірне.

Якщо `left[x] ≠ NIL`, то з умови переходу праворуч маємо:

```
max[left[x]] < l[i]
```

За означенням `max`, для будь-якого вузла `z ∈ Subtree(left[x])` його права межа обмежена зверху:

```
r[z] ≤ max[left[x]] < l[i]   ⇒   r[z] < l[i]
```

Але якщо `r[z] < l[i]`, то за означенням відношення перетину `Overlap(int[z], i) = false`. Тобто жоден інтервал у лівому піддереві не може досягти лівої межі запиту `l[i]`. Отже, пошук у лівому піддереві є безперспективним, і алгоритм зобов'язаний перейти у праве піддерево `right[x]`.

Теорему доведено повністю. ∎

## 6. Математична теорія центрованого інтервального дерева Едельсбруннера

На відміну від аугментованого BST, центроване інтервальне дерево спирається на рекурсивний поділ простору.

### Медіанне розбиття та розміщення інтервалів

Нехай `S` — множина з `n` інтервалів. З множини всіх кінцевих точок `U = { l[i], r[i] | i ∈ S }` обирається медіанна точка `x_mid`.

Усі інтервали `i ∈ S` класифікуються на три диз'юнктні множини:
1. `S_L = { i ∈ S | r[i] < x_mid }` — інтервали строго ліворуч.
2. `S_R = { i ∈ S | l[i] > x_mid }` — інтервали строго праворуч.
3. `S_M = { i ∈ S | l[i] ≤ x_mid ≤ r[i] }` — інтервали, що перетинають медіану.

Вузол дерева зберігає число `x_mid` та два впорядковані списки для множини `S_M`:
- Список `A_L`, відсортований за зростанням лівих меж `l[i]`.
- Список `A_R`, відсортований за спаданням правих меж `r[i]`.

### Теорема про складність обходу центрованого дерева

**Теорема.** *Для запиту точки `q` або інтервалу `Q = [q_l, q_r]` обхід центрованого дерева знаходить усі `k` перетинів за час `O(k + log n)`.*

*Доведення:*
1. На кожному рівні дерева запит порівнюється з `x_mid`.
2. Якщо `q < x_mid`, ми скануємо список `A_L` від найменшої лівої межі. Сканування зупиняється на першому елементі з `l[i] > q`. Усі відвідані елементи списку до зупинки є збігами.
3. Якщо `q > x_mid`, аналогічно сканується список `A_R` від найбільшої правої межі до першого елемента з `r[i] < q`.
4. Загальна кількість безуспішних перевірок на всьому шляху рекурсії від кореня до листків не перевищує висоти дерева `O(log n)`, а кількість успішних перевірок дорівнює `k`.
5. Отже, загальна складність є `O(k + log n)`. ∎

## 7. Алгоритм та математична складність пошуку всіх перетинів

Для знаходження всіх `k` інтервалів, які перетинають запит `i`, застосовується рекурсивна процедура `Interval_Search_All(x, i, result)`:

```
procedure Interval_Search_All(x, i, result):
    if x == NIL:
        return
    
    # 1. Перевірка перетину у поточному вузлі
    if Overlap(int[x], i):
        result.append(int[x])
        
    # 2. Рекурсивний похід у ліве піддерево
    if left[x] ≠ NIL and max[left[x]] ≥ l[i]:
        Interval_Search_All(left[x], i, result)
        
    # 3. Рекурсивний похід у праве піддерево
    if right[x] ≠ NIL and l[x] ≤ r[i] and max[right[x]] ≥ l[i]:
        Interval_Search_All(right[x], i, result)
```

### Теорема про складність вибірки всіх перетинів

**Теорема.** *Процедура `Interval_Search_All` знаходить усі `k` перетинів за час `O(k · log n)` у найгіршому випадку на аугментованому BST.*

*Доведення складності:*
Для аугментованого BST кожен відвіданий вузол є або елементом шуканої відповіді (що дає `k` збігів), або належить до шляху довжиною не більше `h = O(log n)` від кореня до одного з відвіданих листків. Оскільки кількість таких шляхів обмежена `O(k)`, загальна кількість відвіданих вузлів не перевищує `O(k · log n)`. ∎

## 8. Покроковий числовий приклад розрахунку інваріантів та пошуку

Розглянемо множину з 6 інтервалів:
`A = [15, 20]`, `B = [10, 30]`, `C = [17, 19]`, `D = [5, 20]`, `E = [12, 15]`, `F = [30, 40]`.

Побудуємо бінарне дерево пошуку з ключем `l`:
- Корінь `A [15, 20]`
- Лівий син `A` — `B [10, 30]`
- Правий син `A` — `F [30, 40]`
- Лівий син `B` — `D [5, 20]`
- Правий син `B` — `E [12, 15]`
- Лівий син `F` — `C [17, 19]`

Обчислимо атрибут `max` знизу вгору:

```
max[D] = r[D] = 20                                 [листок]
max[E] = r[E] = 15                                 [листок]
max[C] = r[C] = 19                                 [листок]

max[B] = max(r[B], max[D], max[E])
       = max(30, 20, 15) = 30                      [піддерево B]

max[F] = max(r[F], max[C], max[NIL])
       = max(40, 19, -∞) = 40                      [піддерево F]

max[A] = max(r[A], max[B], max[F])
       = max(20, 30, 40) = 40                      [корінь A]
```

### Трасування запиту `Q = [21, 23]` (`l[Q] = 21`, `r[Q] = 23`)

1. **Крок 1: Вузол A [15, 20]**
   - Перевірка перетину: `Overlap([15,20], [21,23])`: `(15 ≤ 23) ∧ (20 ≥ 21)` — `TRUE ∧ FALSE` → Ні.
   - Перевірка лівого сина `B`: `max[B] = 30`.
   - Порівняння: `max[B] (30) ≥ l[Q] (21)` → `TRUE`.
   - **Рішення:** Перейти у ліве піддерево до вузла `B`.

2. **Крок 2: Вузол B [10, 30]**
   - Перевірка перетину: `Overlap([10,30], [21,23])`: `(10 ≤ 23) ∧ (30 ≥ 21)` — `TRUE ∧ TRUE` → ЗНАЙДЕНО!
   - **Результат:** Алгоритм повертає вузол `B [10, 30]`.

## 9. Порівняльний аналіз математичних властивостей геометричних дерев

| Структура даних | Час побудови | Час пошуку 1 перетину | Час пошуку всіх `k` перетинів | Пам'ять | Обмеження домену |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Доповнене BST (CLRS)** | `O(n log n)` | `O(log n)` | `O(k log n)` | `O(n)` | Неперервний (динамічний) |
| **Центроване дерево** | `O(n log n)` | `O(log n)` | `O(k + log n)` | `O(n)` | Неперервний (стативний / напівдинамічний) |
| **Відрізкове дерево** | `O(n log n)` | N/A (Point Enclosure) | `O(k + log n)` | `O(n log n)` | Фіксований / дискретний |
| **R-дерево (1D)** | `O(n log n)` | `O(log n)` (avg) | `O(k + log n)` (avg) | `O(n)` | Неперервний (багатовимірний) |

## 10. Доведення суворої межі висоти червоно-чорного інтервального дерева

Оскільки доповнене інтервальне дерево конструюється на основі червоно-чорного дерева, збереження його колірних інваріантів гарантує логарифмічне обмеження висоти.

### Теорема про висоту

**Теорема.** *Червоно-чорне інтервальне дерево з `n` внутрішніми вузлами має висоту `h`, яка задовольняє нерівність:*

```
h ≤ 2 · log₂ (n + 1)
```

*Доведення:*
1. Нехай `bh(x)` позначує чорну висоту вузла `x` (кількість чорних вузлів на шляху від `x` до листового `NIL`, не включаючи сам `x`).
2. За допомогою індукції за висотою піддерева можна довести, що піддерево з коренем у `x` містить принаймні `2^(bh(x)) - 1` внутрішніх вузлів.
   - Для бази індукції (`h = 0`, вузол `NIL`): `bh(NIL) = 0`, кількість внутрішніх вузлів `2⁰ - 1 = 0`, що вірно.
   - Для кроку індукції: якщо вузол `x` має висоту `h > 0`, кожен з його дітей має чорну висоту `bh(x)` (якщо дитина червона) або `bh(x) - 1` (якщо дитина чорна). Оскільки червоний вузол не може мати червоного сина, принаймні половина вузлів на будь-якому шляху є чорними: `bh(x) ≥ h / 2`.
3. Тоді загальна кількість внутрішніх вузлів `n` задовольняє нерівність:
   ```
   n ≥ 2^(bh(root)) - 1 ≥ 2^(h / 2) - 1
   ```
4. Додаючи 1 до обох частин та беручи двоковий логарифм, отримуємо:
   ```
   n + 1 ≥ 2^(h / 2)   ⇒   log₂ (n + 1) ≥ h / 2   ⇒   h ≤ 2 · log₂ (n + 1)
   ```
Таким чином, максимальна глибина обходу при пошуку перетину в аугментованому червоно-чорному дереві строго обмежена величиною `O(log n)`. ∎

## 11. Математичне розширення: Запит повного включення (Interval Enclosure)

Поряд із запитом перетину `Overlap(int[x], i)`, у деяких практичних задачах (наприклад, перевірка потрапляння інтервалу всередину контейнера) вимагається розв'язати задачу **включення**: `Enclosed(int[x], i)`, що означає `l[i] ≤ l[x]` та `r[x] ≤ r[i]` (інтервал `int[x]` повністю лежить усередині запиту `i`).

Для виконання запитів включення атрибут `max` доповнюється дуальним атрибутом `min_low[x]`, який зберігає мінімальне значення лівої межі у піддереві:

```
min_low[x] = min { l[y] | y ∈ Subtree(x) }
```

Відсікання гілок виконується за подвійним інваріантом:
- Якщо `min_low[left[x]] > r[i]`, то у лівому піддереві не існує інтервалів, що починаються до закінчення запиту.
- Якщо `max[left[x]] < l[i]`, у лівому піддереві не існує інтервалів, що закінчуються після початку запиту.

Це гарантує логарифмічний пошук за `O(log n)` часу і для розширених просторових відношень.

## 13. Математичний аналіз масової побудови (Bulk-Loading)

Якщо множина з `n` інтервалів відома заздалегідь (статистичний або стаційний випадок), побудова інтервального дерева через `n` послідовних вставок вимагає `O(n log n)` часу.

Однак за допомогою процедури масової побудови (Bulk-Loading) можна побудувати ідеально збалансоване інтервальне дерево мінімальної висоти:
1. Вхідна множина інтервалів сортується за лівою межею `l[i]` за час `O(n log n)`.
2. Рекурсивна функція `Build_Tree(sorted_intervals, start, end)` обирає медіанний елемент `mid = (start + end) / 2` як корінь піддерева.
3. Рекурсивно будуються ліве `Build_Tree(..., start, mid - 1)` та праве `Build_Tree(..., mid + 1, end)` піддерева.
4. Значення `max` поточного вузла обчислюється на зворотному шляху рекурсії за `O(1)` за рекурентною формулою:
   ```
   max[mid] = max( r[mid], max[left_child], max[right_child] )
   ```

### Теорема про складність масової побудови

**Теорема.** *Рекурсивне конструювання деревного каркаса з відсортованого масиву задовольняє рекурентне співвідношення `T(n) = 2 · T(n / 2) + O(1)` і виконується за час `O(n)`.*

*Доведення:*
За Основними теоремами про рекуренції (Master Theorem), для `a = 2`, `b = 2`, `f(n) = O(1) = O(n⁰)` випадок 1 дає `n^(log₂ 2) = n¹ = n`. Отже, складність рекурсивної побудови становить `O(n)`. Загальний час разом із сортуванням дорівнює `O(n log n)`. При цьому висота отриманого дерева є мінімально можливою: `h = ⌈log₂ (n + 1)⌉`. ∎

## 14. Підсумковий висновок

Математична строгість доповненого інтервального дерева базується на двох стовпах:
1. Збереженні порядку бінарного дерева пошуку за лівою межею `l[x]`.
2. Однозначному рекурсивному оновленні супремуму правих меж `max[x]`.

Поєднання цих двох властивостей перетворює однопрохідний пошук від кореня до листка на математично доведену процедуру знаходження перетинів із гарантованою логарифмічною складністю `O(log n)`.
