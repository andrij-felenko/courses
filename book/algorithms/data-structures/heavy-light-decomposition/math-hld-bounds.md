# 🧮 Математичне доведення логарифмічної межі ланцюгів та складності HLD

Ефективність Heavy-Light декомпозиції ґрунтується на суворому комбінаторному факті: довільне кореневе дерево з `N` вершин розбивається на систему ланцюгів так, що будь-який простий шлях між двома довільними вершинами перетинає не більше ніж логарифмічну кількість неперервних важких сегментів та легких ребер. Нижче наведено формальне математичне визначення компонентів HLD, доведення ключових лем про єдиність важкої дитини, стиснення розмірів піддерев, теорему про неперервність DFS-лінеаризації, властивості моноїдного агрегування, аналіз потенціалів амортизації, а також строгі виведення часової та просторової складності алгоритмічних операцій.

## Формальні означення та структура дерева

Нехай задано орієнтоване кореневе дерево `T = (V, E, r)`, де `V` — скінченна множина з `|V| = N` вершин, `E ⊂ V × V` — множина орієнтованих ребер (від батьківського вузла до дочірнього), а `r ∈ V` — виділена вершина, що є коренем дерева.

Для кожної вершини `v ∈ V` визначимо:
1. **Піддерево `T[v]`:** множина всіх вершин `w ∈ V`, для яких простий орієнтований шлях від кореня `r` до `w` містить вершину `v`.
2. **Розмір піддерева `sz(v)`:** потужність множини вершин піддерева:
```
sz(v) = |T[v]| = 1 + ∑_{c ∈ children(v)} sz(c)    [рекурентна сума за всіма прямими нащадками]
```
де `children(v) = {c ∈ V | (v, c) ∈ E}` — множина безпосередніх дітей вершини `v`. Для будь-якого листка `sz(v) = 1`, а для кореня дерева `sz(r) = N`.

3. **Батьківський вузол `p(v)`:** для кожної не кореневої вершини `v ≠ r` існує єдина вершина `p(v) ∈ V` така, що `(p(v), v) ∈ E`.

### Класифікація ребер: Важкі та легкі

Для кожного ребра `(u, v) ∈ E`, де `u = p(v)`, класифікація визначається співвідношенням розміру піддерева `sz(v)` та розміру піддерева батька `sz(u)`:

* Ребро `(u, v)` називається **важким (heavy)**, якщо розмір піддерева нащадка строго перевищує половину розміру піддерева батька: `sz(v) > sz(u) / 2`.
  В алгоритмічній практиці, щоб забезпечити наявність важкого нащадка у кожного внутрішнього вузла, важким призначають ребро до сина з максимальним розміром піддерева: `v = argmax_{c ∈ children(u)} sz(c)` (при рівності максимумів обирається довільний один кандидат).
* Ребро `(u, v)` називається **легким (light)**, якщо воно не є важким.

## Лема 1. Єдиність важкого нащадка за пороговим критерієм

**Твердження:** Будь-яка вершина `u ∈ V` може мати щонайбільше одного дочірнього вузла `v ∈ children(u)`, для якого виконується строга нерівність `sz(v) > sz(u) / 2`.

**Доведення (від супротивного):**
Припустимо супротивне: нехай вершина `u` має щонайменше двох різних дочірніх вузлів `v₁` та `v₂` (`v₁ ≠ v₂`), таких що:
```
sz(v₁) > sz(u) / 2    [припущення для першої дитини]
sz(v₂) > sz(u) / 2    [припущення для другої дитини]
```

Запишемо точний розмір піддерева вершини `u` через суму розмірів піддерев усіх її дітей та виконаємо ланцюг оцінок:

```
sz(u) = 1 + sz(v₁) + sz(v₂) + ∑_{c ∈ children(u) \ {v₁, v₂}} sz(c)   [означення розміру піддерева]
      ≥ 1 + sz(v₁) + sz(v₂)                                          [невід'ємність розмірів піддерев решти нащадків]
      > 1 + sz(u)/2 + sz(u)/2                                        [підстановка припущень sz(v₁) > sz(u)/2 та sz(v₂) > sz(u)/2]
      = 1 + sz(u)                                                    [зведення подібних доданків]
      > sz(u)                                                        [строга нерівність 1 + sz(u) > sz(u) для будь-якого дійсного числа]
```

Отримали строгу суперечність: `sz(u) > sz(u)`. Отже, наше припущення хибне.

**Висновок:** Вершина `u` не може мати більше одного важкого нащадка. Внаслідок цього множина важких ребер розпадається на взаємно неперетинні шляхи (важкі ланцюги), які не розгалужуються. Кожна вершина дерева належить рівно одному максимальному важкому ланцюгу (ланцюг може складатись і з однієї ізольованої вершини).

## Лема 2. Стиснення розміру піддерева вздовж легких ребер

**Твердження:** Якщо ребро `(u, v) ∈ E` є легким ребром (тобто `v` — легка дитина вершини `u`), то розмір піддерева `sz(v)` становить не більше половини розміру піддерева батька `sz(u)`:
```
sz(v) ≤ sz(u) / 2     [верхня межа для легкої дитини за означенням]
sz(v) ≤ ⌊sz(u) / 2⌋    [оскільки розміри піддерев є цілими додатними числами]
```

**Доведення:**
За класичним означенням, ребро є легким тоді й лише тоді, коли `sz(v) ≤ sz(u) / 2`.
Якщо ж застосовується жадібне означення важкого ребра як максимуму `sz(c)` серед усіх `c ∈ children(u)`, припустимо супротивне: нехай для легкої дитини `v` виконується `sz(v) > sz(u) / 2`.

За Лемою 1 жоден інший нащадок `c ≠ v` не може мати `sz(c) > sz(u) / 2`. Отже, для всіх `c ∈ children(u) \ {v}` виконується:
```
sz(c) ≤ sz(u) - 1 - sz(v)     [віднімання розміру поточної вершини та сина v]
      < sz(u) - 1 - sz(u)/2   [підстановка строгої нерівності sz(v) > sz(u)/2]
      = sz(u)/2 - 1           [алгебраїчне спрощення різниці]
      < sz(v)                 [оскільки sz(v) > sz(u)/2]
```
Це означає, що `sz(v)` є строго найбільшим серед усіх дітей вершини `u`. Тоді за жадібним правилом ребро `(u, v)` зобов'язане бути обраним як важке, що суперечить умові, що воно є легким.

Таким чином, у будь-якій коректній реалізації HLD перехід через легке ребро зменшує розмір піддерева щонайменше вдвічі:
```
sz(v) ≤ ⌊sz(u) / 2⌋    [гарантоване ділення розміру піддерева навпіл]
```

## Теорема 1. Логарифмічна межа кількості легких ребер на шляху від кореня

**Твердження:** На будь-якому простому орієнтованому шляху `P(r, v)` від кореня `r` до довільної вершини `v ∈ V` кількість легких ребер `m` не перевищує `⌊log₂ N⌋`.

**Доведення:**
Нехай `P(r, v) = (w₀ = r, w₁, w₂, ..., wₖ = v)` — простий шлях від кореня `r` до вершини `v` довжиною `k`.
Нехай у цій послідовності ребер рівно `m` ребер є легкими. Позначимо індекси цих легких переходів як `i₁, i₂, ..., iₘ`, де `0 ≤ i₁ < i₂ < ... < iₘ < k`.

Для кожного легкого ребра `(w_{iⱼ}, w_{iⱼ + 1})` за Лемою 2 маємо:
```
sz(w_{iⱼ + 1}) ≤ sz(w_{iⱼ}) / 2    [властивість стиснення піддерева легкої дитини]
```

Оскільки для будь-якого кроку вздовж шляху розмір піддерева монотонно спадає (`sz(w_{a + 1}) < sz(w_{a})` для будь-яких ребер), можемо скласти ланцюг нерівностей від кореня до вершини `v`:

```
sz(r) = N                                                           [корінь охоплює все дерево]
sz(w_{i₁ + 1}) ≤ sz(w_{i₁}) / 2 ≤ sz(r) / 2 = N / 2                 [перший легкий перехід]
sz(w_{i₂ + 1}) ≤ sz(w_{i₂}) / 2 ≤ sz(w_{i₁ + 1}) / 2 ≤ N / 2²       [другий легкий перехід]
sz(w_{iⱼ + 1}) ≤ N / 2ʲ                                             [j-й легкий перехід за індукцією]
sz(w_{iₘ + 1}) ≤ N / 2ᵐ                                             [після проходження всіх m легких ребер]
```

Оскільки вершина `v` знаходиться на підшляху після останнього легкого переходу `w_{iₘ + 1}`, маємо `1 ≤ sz(v) ≤ sz(w_{iₘ + 1})`. Об'єднаємо нерівності:

```
1 ≤ N / 2ᵐ                                                          [нижня межа розміру непорожнього піддерева]
2ᵐ ≤ N                                                              [множення нерівності на 2ᵐ]
m ≤ log₂(N)                                                         [логарифмування обох частин за основою 2]
m ≤ ⌊log₂ N⌋                                                        [оскільки m — ціла кількість ребер]
```

**Висновок:** На шляху від кореня до будь-якої вершини зустрічається не більше `⌊log₂ N⌋` легких ребер.

## Теорема 2. Логарифмічна межа важких ланцюгів на довільному шляху

**Твердження:** Будь-який простий шлях між двома довільними вершинами `u, v ∈ V` перетинає не більше ніж `2 · ⌊log₂ N⌋ + 1 = O(log N)` неперервних сегментів важких ланцюгів.

**Доведення:**
1. Розглянемо спочатку вертикальний шлях від кореня `r` до вершини `u`.
   Будь-який крок уздовж шляху або продовжує рух усередині поточного важкого ланцюга (важке ребро), або переходить у новий важкий ланцюг через легке ребро.
   Кількість переходів між різними важкими ланцюгами на шляху `P(r, u)` рівна кількості легких ребер `m ≤ ⌊log₂ N⌋`.
   Враховуючи початковий важкий ланцюг, що містить корінь `r`, загальна кількість важких сегментів на шляху `P(r, u)` обмежена величиною:
```
Chains(r, u) ≤ 1 + ⌊log₂ N⌋    [початковий ланцюг плюс кількість легких переходів]
```

2. Розглянемо довільний шлях між вершинами `u` та `v`. Нехай `w = LCA(u, v)` — їхній найменший спільний предок.
   Простий шлях `P(u, v)` однозначно розкладається на два спрямовані вгору вертикальні шляхи: від `u` до `w` та від `v` до `w`:
```
P(u, v) = P(u, w) ∪ P(w, v)    [розкладання шляху через найменшого спільного предка]
```

Шлях `P(u, w)` є підмножиною шляху від кореня `P(r, u)`, тому він містить не більше `⌊log₂ N⌋` легких ребер і не більше `1 + ⌊log₂ N⌋` важких ланцюгів.
Аналогічно, шлях `P(w, v)` є підмножиною шляху `P(r, v)` і містить не більше `⌊log₂ N⌋` легких ребер та не більше `1 + ⌊log₂ N⌋` важких ланцюгів.

Важкий ланцюг, що містить найменшого спільного предка `w = LCA(u, v)`, є спільним для обох гілок і враховується один раз. Сумарна кількість неперервних сегментів важких ланцюгів на шляху `P(u, v)` становить:

```
Chains(u, v) ≤ Chains(u, w) + Chains(v, w) - 1     [сума ланцюгів на двох вертикальних шляхах за вирахуванням спільного предка]
             ≤ (1 + ⌊log₂ N⌋) + (1 + ⌊log₂ N⌋) - 1  [підстановка верхніх меж для вертикальних шляхів]
             = 2 · ⌊log₂ N⌋ + 1                    [арифметичне спрощення виразу]
             = O(log N)                            [асимптотична оцінка при зростанні N]
```

**Висновок:** Довільний шлях між двома вершинами розбивається максимум на `O(log N)` неперервних числових відрізків у лінеаризованому масиві дерева.

## Теорема 3. Теорема про неперервність DFS-лінеаризації

**Твердження:** Нехай функція `pos : V → {0, 1, ..., N - 1}` призначає порядковий номер кожній вершині під час обходу в глибину, де важкий нащадок `heavy[u]` відвідується строго першим серед усіх дітей вершини `u`. Тоді:
1. Для будь-якого максимального важкого ланцюга `C = (c₀, c₁, ..., cₖ)`, де `c_{i+1} = heavy[cᵢ]`, множина позицій утворює неперервний інтервал:
```
pos(cᵢ) = pos(c₀) + i,   ∀ i ∈ {0, 1, ..., k}    [строга неперервність індексів важкого ланцюга]
```
2. Для будь-якої вершини `v ∈ V` множина позицій усіх вершин її піддерева `T[v]` утворює неперервний інтервал довжиною `sz(v)`:
```
{pos(w) | w ∈ T[v]} = [pos(v), pos(v) + sz(v) - 1]    [неперервність піддерева в DFS-порядку]
```

**Доведення:**
1. Нехай обхід DFS входить у вершину `u` і призначає їй позицію `pos[u] = t`. Наступним кроком DFS безпосередньо викликається для важкої дитини `heavy[u]`, не відвідуючи жодних інших вершин чи бічних піддерев. Отже, важкий нащадок отримує позицію `pos[heavy[u]] = t + 1`. За математичною індукцією вздовж усього важкого ланцюга кожна наступна вершина отримує позицію на одиницю більшу за позицію батька, що доводить пункт 1.
2. Властивість неперервності піддерева є фундаментальним інваріантом пошуку в глибину: алгоритм відвідує корінь піддерева `v`, рекурсивно обходить усі вершини `T[v]`, призначаючи їм послідовні лічильники, і лише після повного завершення `T[v]` переходить до братніх піддерев. Оскільки загальна кількість вершин у піддереві дорівнює `sz(v)`, діапазон призначених індексів точно дорівнює `[pos[v], pos[v] + sz(v) - 1]`.

## Алгебраїчні властивості моноїдного агрегування на шляхах

Для того щоб дерево відрізків коректно обчислювало запити на шляху між `u` та `v`, значення у вершинах повинні належати алгебраїчній структурі — **моноїду** `(M, ⊕, e)`:
1. **Замкненість:** для будь-яких `a, b ∈ M` результат `a ⊕ b ∈ M`.
2. **Асоціативність:** для будь-яких `a, b, c ∈ M` виконується `(a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)`.
3. **Нейтральний елемент:** існує такий `e ∈ M`, що `a ⊕ e = e ⊕ a = a`.

### Комутативні та некомутативні операції

Якщо операція `⊕` є **комутативною** (`a ⊕ b = b ⊕ a`, наприклад сума, мінімум, максимум, бітове XOR), порядок об'єднання інтервалів уздовж шляху не має значення. Алгоритм просто накопичує результат у довільній послідовності:
```
Total = SegQuery(L₁, R₁) ⊕ SegQuery(L₂, R₂) ⊕ ... ⊕ SegQuery(Lₖ, Rₖ)    [комутативне об'єднання]
```

Якщо операція є **некомутативною** (множення матриць `A · B ≠ B · A`, конкатенація рядків, композиція функцій), напрямок обходу шляху є критичним. Шлях від `u` до `v` складається з підйому від `u` до `w = LCA(u, v)` та спуску від `w` до `v`:
```
Result(u → v) = LeftChain(u → w) ⊕ RightChain(w → v)    [строгий порядок орієнтованого шляху]
```
Під час підйому від `u` до `w` інтервали зчитуються знизу вгору, тому значення кожного відрізка додаються до лівого агрегату `LeftChain` у прямому порядку. Під час підйому від `v` до `w` інтервали також зчитуються знизу вгору, проте на результуючому шляху рух здійснюється згори вниз. Тому значення з правої гілки накопичуються в окремому акумуляторі `RightChain` у зворотній послідовності, після чого обидва агрегати об'єднуються: `Total = LeftChain ⊕ RightChain`.

## Математичне відображення ребер на вершини (Edge-to-Vertex Mapping)

Якщо ваги або дані задані не на вершинах, а на ребрах графа `E`, застосовується бієктивне відображення ребер на підмножину вершин `V \ {r}`.

Кожне ребро `e = (u, v) ∈ E`, де `u = p(v)`, однозначно ідентифікується своєю глибшою кінцевою вершиною `v`. Оскільки кожна вершина, крім кореня `r`, має рівно одного батька, це відображення:
```
f : E → V \ {r},   f((p(v), v)) = v    [бієкція між множиною ребер та некореневими вершинами]
```
є строгою бієкцією (`|E| = N - 1 = |V \ {r}|`).

При виконанні запиту на шляху між вершинами `u` та `v` найменший спільний предок `w = LCA(u, v)` є найвищою точкою шляху. Ребро, що веде у вершину `w` від її батька `p(w)`, **не належить** шляху між `u` та `v`.
Тому при досягненні спільного ланцюга, коли обидві змінні знаходяться у вершинах `w` та `k` (`pos[w] ≤ pos[k]`), інтервальний запит модифікується з включенням зміщення:
```
Range_Edge(w, k) = [pos[w] + 1, pos[k]]    [виключення ребра над спільним предком w]
```
Якщо `w = k` (тобто шлях складався з однієї вершини), інтервал `[pos[w] + 1, pos[w]]` стає порожнім і запит повертає нейтральний елемент `e`.

## Амортизаційний аналіз та оптимізація важких шляхів

Розглянемо випадок, коли над кожним важким ланцюгом довжини `L` будується збалансована інтервальна структура даних (дерево відрізків). Нехай дерево розбите на `k` важких ланцюгів з довжинами `L₁, L₂, ..., Lₖ`, де `∑_{i=1}^k Lᵢ = N`.

Якщо б запит обробляв кожен ланцюг за `O(log Lᵢ)`, то сумарний час запиту на шляху `P` оцінюється сумою:
```
T(P) = ∑_{i ∈ Chains(P)} O(log Lᵢ)    [сума логарифмів довжин ланцюгів на шляху]
```

Застосуємо нерівність Єнсена для увігнутої функції логарифма `f(x) = log₂(x)`:

```
(1 / |Chains(P)|) · ∑_{i ∈ Chains(P)} log₂(Lᵢ) ≤ log₂((1 / |Chains(P)|) · ∑_{i ∈ Chains(P)} Lᵢ)    [нерівність Єнсена для логарифма]
                                               ≤ log₂(N / |Chains(P)|)                              [оскільки сума довжин ланцюгів не перевищує N]
```

Помноживши обидві частини на кількість ланцюгів `|Chains(P)| ≤ 2 · log₂ N + 1`, отримуємо точну верхню оцінку сумарної вартості:

```
∑_{i ∈ Chains(P)} log₂(Lᵢ) ≤ |Chains(P)| · log₂(N / |Chains(P)|)    [верхня межа суми логарифмів довжин]
                           ≤ (2 · log₂ N + 1) · log₂(N)             [найгірший випадок при одиничних ланцюгах]
                           = O(log² N)                              [асимптотична межа складності]
```

Цей аналіз доводить, що навіть у найнесприятливіших конфігураціях довжин ланцюгів сума витрат на запити у деревах відрізків не може перевищити `O(log² N)`.

## Теорема 4. Асимптотична складність операцій HLD

Поєднавши декомпозицію шляхів з одновимірною інтервальною структурою даних (деревом відрізків), отримуємо строгі теоретичні гарантії часу та пам'яті для всіх операцій.

### 1. Просторова складність (Space Complexity)
Для представлення графа та структур HLD зберігаються масиви розміром `N`: `parent`, `depth`, `sz`, `heavy`, `head`, `pos`.
Дерево відрізків над лінеаризованим масивом розміру `N` потребує масиву довжиною `4N`.
Загальний обсяг пам'яті становить:
```
S(N) = O(N) + O(4N) = O(N)    [лінійна пам'ять від кількості вершин]
```

### 2. Час попередньої обробки (Preprocessing Time)
1. **Перший прохід DFS (`dfs1`):** відвідує кожне ребро дерева рівно двічі, обчислюючи глибини `depth`, розміри `sz` та важких дітей `heavy`. Складність: `O(N)`.
2. **Другий прохід DFS (`dfs2`):** нумерує вершини у лінеаризованому порядку `pos` та встановлює голови ланцюгів `head`. Складність: `O(N)`.
3. **Побудова дерева відрізків (Build):** ініціалізація `4N` вузлів дерева відрізків виконується за лінійний час:
```
T_build(N) = ∑_{i=0}^{⌈log₂ N⌉} 2ⁱ · O(1) = O(N)    [сума геометричної прогресії вузлів дерева відрізків]
```
Сумарний час попередньої обробки становить:
```
T_prep(N) = O(N) + O(N) + O(N) = O(N)    [лінійний час ініціалізації всіх підсистем]
```

### 3. Запит та оновлення на шляху (Path Query / Path Update)
За Теоремою 2 шлях між `u` та `v` розбивається на `k ≤ 2 · ⌊log₂ N⌋ + 1` неперервних інтервалів `[L_i, R_i]`.
Для кожного інтервалу виконується запит або оновлення у дереві відрізків висоти `H = ⌈log₂ N⌉`. Запит у дереві відрізків відвідує не більше `4 · ⌈log₂ N⌉` вузлів, що вимагає часу `O(log N)`.

Загальний час запиту чи модифікації на шляху становить:
```
T_path(N) = k · T_seg(N)                           [добуток кількості ланцюгів на час запиту в дереві відрізків]
          = (2 · ⌊log₂ N⌋ + 1) · O(log N)          [підстановка максимальної кількості інтервалів k]
          = O(log² N)                              [асимптотичний добуток двох логарифмічних функцій]
```

### 4. Запит та оновлення на піддереві (Subtree Query / Subtree Update)
Завдяки властивості DFS-нумерації все піддерево вершини `v` займає єдиний неперервний інтервал `[pos[v], pos[v] + sz(v) - 1]` у лінеаризованому масиві.
Операція на піддереві вимагає рівно одного звернення до дерева відрізків:
```
T_subtree(N) = 1 · T_seg(N) = O(log N)    [одне звернення до інтервальної структури]
```

### 5. Обчислення LCA (Lowest Common Ancestor)
Пошук LCA через HLD виконує підйом вершини з глибшою головою ланцюга `head`: `u = parent[head[u]]`. Кожен такий крок перетинає одне легке ребро.
За Теоремою 1 кількість підйомів не перевищує `2 · ⌊log₂ N⌋`. Кожен підйом виконується за константний час `O(1)` без звернення до дерева відрізків.
Отже, складність знаходження LCA становить:
```
T_LCA(N) = O(log N)    [логарифмічна кількість стрибків між головами ланцюгів]
```

| Операція | Часова складність HLD | Наївний обхід дерева | Двійкові підйоми (Binary Lifting) |
| :--- | :--- | :--- | :--- |
| **Побудова структури** | `O(N)` | `O(N)` | `O(N log N)` |
| **Використання пам'яті** | `O(N)` | `O(N)` | `O(N log N)` |
| **Запит на шляху (Path Query)** | `O(log² N)` | `O(N)` | `O(log N)` (лише статичний) |
| **Оновлення на шляху (Path Update)** | `O(log² N)` | `O(N)` | `O(N)` (не підтримує інтервали) |
| **Запит на піддереві (Subtree Query)** | `O(log N)` | `O(N)` | `O(N)` |
| **Оновлення на піддереві (Subtree Update)** | `O(log N)` | `O(N)` | `O(N)` |
| **Пошук найменшого спільного предка (LCA)**| `O(log N)` | `O(N)` | `O(log N)` |

## Аналітичний розбір крайових топологій дерев

Розглянемо поведінку HLD на крайніх топологіях дерев:

1. **Лінійний ланцюг (Бамбук, `N` вершин):**
   Усі ребра від кореня до листка задовольняють `sz(v) = sz(p) - 1 > sz(p) / 2` (для всіх `sz(p) ≥ 3`). Все дерево стає **одним важким ланцюгом** довжини `N`. Кількість легких ребер дорівнює нулю. Будь-який запит на шляху між двома вершинами перетворюється на рівно **один** інтервальний запит у дереві відрізків, що виконується за час `O(log N)`.
2. **Зіркоподібний граф (Зірка, корінь і `N - 1` листків):**
   Усі нащадки кореня мають розмір `sz(c) = 1`. Рівно один нащадок обирається важким за жадібним правилом, решта `N - 2` нащадків з'єднані легкими ребрами. Проте глибина дерева дорівнює 1. Будь-який шлях між листками складається максимум з 2 ребер і розбивається щонайбільше на 2 запити до дерева відрізків. Час роботи: `O(log N)`.
3. **Повне збалансоване двійкове дерево (`N` вершин, глибина `log₂ N`):**
   Для кожного вузла ліва і права дитини мають приблизно однаковий розмір піддерева `≈ sz(u) / 2`. Одне з ребер стає важким, інше легким. Будь-який шлях містить максимум `log₂ N` легких ребер, досягаючи теоретичної верхньої межі `O(log² N)` для запитів на шляху.

Математична строгість та гарантії `O(log² N)` роблять Heavy-Light декомпозицію однією з найнадійніших структур даних у дискретній математиці та комп'ютерній інженерії.
