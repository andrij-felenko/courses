# 🧮 Дерево рішень та логарифмічний поріг складності

Математична краса двійкового пошуку полягає не лише в його високій швидкості, а й у тому, що він є **теоретично оптимальним** алгоритмом для пошуку елемента у впорядкованому масиві за допомогою порівнянь.

У цій уставці ми розглянемо строге математичне обґрунтування часової складності двійкового пошуку через модель дерева рішень, інформаційну ентропію Шеннона та розв'язання рекурентних співвідношень.

## Модель дерева рішень (Decision Tree Model)

Будь-який алгоритм пошуку, який базується на попарному порівнянні елементів (`<`, `=`, `>`), можна представити у вигляді двового чи тріового **дерева рішень**.

Розглянемо масив із N елементів `A[0...N-1]`. Ми шукаємо елемент `target`. 

У кожному внутрішньому вузлі дерева рішень алгоритм здійснює порівняння `target` із деяким елементом масиву `A[i]`. Залежно від результату порівняння, виконання алгоритму відгалужується:
- Якщо `target < A[i]`, алгоритм переходить у ліве піддерево.
- Якщо `target > A[i]`, алгоритм переходить у праве піддерево.
- Якщо `target == A[i]`, пошук успішно зупиняється (знайдено індекс `i`).

Листки дерева рішень відповідають усім можливим остаточним висновкам алгоритму. Скільки всього унікальних результатів може дати пошук?

1. Елемент знайдено на одній із N позицій: індекс 0, індекс 1, ..., індекс N-1 (всього N можливих результатів).
2. Елемент відсутній у масиві (1 додатковий результат).

Отже, будь-яке дерево рішень для пошуку серед N елементів повинно мати як мінімум **L = N + 1 листових вузлів**.

### Нижня межа складності порівняльного пошуку

Кількість порівнянь у найгіршому випадку відповідає **висоті H** дерева рішень (довжині найдовшого шляху від кореня до листка).

З теорії графів відомо, що двійкове дерево висоти H із бінарними або потрійними розгалуженнями може мати на висоті H не більше ніж 2ᴴ листових вузлів:

```
L ≤ 2ᴴ
```

Оскільки наше дерево рішень повинно містити щонайменше N + 1 листків, отримуємо фундаментальну нерівність:

```
2ᴴ ≥ N + 1
```

Прологарифмуємо обидві частини нерівності за основою 2:

```
H ≥ log₂ (N + 1)
```

Оскільки кількість порівнянь H має бути цілим числом, то мінімальна можлива висота дерева рішень у найгіршому випадку становить:

```
H_min = ⌈log₂ (N + 1)⌉
```

Це означає, що **жоден** алгоритм пошуку, який базується лише на порівняннях елементів, не може працювати швидше ніж за **Ω(log N)** порівнянь у найгіршому випадку. 

Оскільки двійковий пошук досягає саме цієї межі (`⌈log₂ (N + 1)⌉` порівнянь), він є **асимптотично оптимальним** (англ. *asymptotically optimal*) алгоритмом порівняльного пошуку.

## Інформаційно-теоретичний поріг (Ентропія Шеннона)

До цієї ж нижньої межі можна дійти з точки зору теорії інформації Клода Шеннона.

До початку пошуку у нас є N + 1 можливих станів системи (елемент на позиції 0, 1, ..., N-1 або відсутній). Якщо припустити, що всі позиції рівноймовірні, початкова а невизначеність (ентропія) системи становить:

```
I = log₂ (N + 1) біт
```

Кожне попарне порівняння `target` з елементом масиву `A[mid]` розділяє поточний діапазон можливих станів приблизно навпіл. Результат порівняння («менше» чи «більше або дорівнює») дає нам рівно **1 біт інформації**.

Щоб повністю усунути невизначеність і зменшити ентропію системи від `log₂ (N + 1)` біт до 0 біт (коли точна позиція стане відомою на 100%), ми мусимо отримати не менше ніж `log₂ (N + 1)` біт інформації.

Оскільки кожна операція порівняння дає максимум 1 біт інформації, мінімально необхідна кількість порівнянь становить:

```
k ≥ ⌈log₂ (N + 1)⌉
```

Двійковий пошук є ідеальним з точки зору теорії інформації, тому що на кожному кроці він обирає медіанний елемент `mid`, витискаючи з кожного порівняння максимально можливий 1 біт інформації.

## Розв'язання рекурентного співвідношення (Master Theorem)

Часову складність двійкового пошуку можна також строго довести через рекурентні рівняння.

Нехай `T(N)` — кількість операцій, необхідна для двійкового пошуку в масиві розміру N. 

На кожному кроці алгоритм виконує 1 порівняння (костантний час `O(1)`) і рекурсивно (або ітеративно) зводить задачу до одного підмасиву удвічі меншого розміру `N / 2`.

Отримуємо рекурентне співвідношення:

```
T(N) = T(N / 2) + c,   де c > 0 — константа (час порівняння та обчислення mid)
T(1) = O(1)
```

Розгорнемо цю рекурентність методом підстановки:

```
T(N) = T(N / 2) + c
     = (T(N / 4) + c) + c = T(N / 4) + 2c
     = (T(N / 8) + c) + 2c = T(N / 8) + 3c
     ...
     = T(N / 2ᵏ) + k · c
```

Процес розгортання зупиняється, коли розмір підмасиву скорочується до 1, тобто `N / 2ᵏ = 1`, що означає `2ᵏ = N` або `k = log₂ N`.

Підставивши `k = log₂ N` у формулу, отримуємо:

```
T(N) = T(1) + c · log₂ N = O(1) + c · log₂ N = O(log N)
```

### Застосування Основної теореми (Master Theorem)

Для загального рівняння вигляду `T(N) = a · T(N / b) + f(N)` у нашому випадку маємо:
- `a = 1` (розв'язуємо лише 1 підзадачу)
- `b = 2` (розмір підзадачі зменшується вдвічі)
- `f(N) = O(1) = O(N⁰)` (додаткова робота на кожному кроці є константною)

Обчислимо критичний показник: `N^(log_b a) = N^(log₂ 1) = N⁰ = 1`.

Оскільки `f(N) = Θ(N^(log_b a)) = Θ(1)`, це відповідає **Другому випадку Основної теореми про рекурентності**. 

Згідно з другим випадком:

```
T(N) = Θ(N^(log_b a) · log N) = Θ(1 · log N) = Θ(log N)
```

Таким чином, асимптотична складність двійкового пошуку математично строго доведена трьома незалежними шляхами: через дерево рішень, теорію інформації Шеннона та Основну теорему про рекурентності.
