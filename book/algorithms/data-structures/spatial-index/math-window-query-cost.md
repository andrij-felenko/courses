# 🧮 Скільки вузлів прочитає віконний запит

У R*-дерева три критерії якості розщеплення — площа, периметр і перекриття, — і збоку вони скидаються на набір інженерних здогадів. Насправді перші два випадають окремими доданками з однієї-єдиної формули: ймовірності того, що випадково поставлене вікно запиту зачепить дану коробку. Третій береться з наступного кроку тієї самої викладки. Виведімо формулу й прочитаймо кожен доданок.

### Коли вікно зачіпає коробку

Світ — квадрат зі стороною 1. Вікно запиту має розміри qw × qh, а стоїть де завгодно: його лівий нижній кут (a, b) рівномірно розкиданий по світу. Коробка — прямокутник R зі сторонами вздовж осей, що займає проміжок [x₁, x₂] по горизонталі й [y₁, y₂] по вертикалі; позначмо w = x₂ − x₁, h = y₂ − y₁.

Уся потрібна далі геометрія — одне спостереження: два прямокутники зі сторонами вздовж осей перетинаються тоді й лише тоді, коли перетинаються їхні проєкції на кожну вісь **окремо**. Запишімо це по горизонталі.

```
a ≤ x₂          ліве ребро вікна не правіше за праве ребро коробки
a + qw ≥ x₁     праве ребро вікна не лівіше за ліве ребро коробки

⟹   x₁ − qw ≤ a ≤ x₂
```

Допустимі a утворюють проміжок довжини x₂ − (x₁ − qw) = w + qw. По вертикалі така сама пара нерівностей дає h + qh. Координати a і b незалежні, тому множина допустимих положень кута — прямокутник площею (w + qw)(h + qh). Для рівномірно розкиданої точки ймовірність влучити в множину дорівнює її площі, поділеній на площу світу ([імовірність як міра](book:math/probability-basics)), а світ у нас одиничний.

```
P(вікно зачепить коробку R) = (w + qw)·(h + qh)
```

Роздутий прямокутник має ім'я: це [сума Мінковського](book:math/minkowski-sum) коробки з відбитим вікном. Суть переходу варта того, щоб її назвати вголос: питання «чи перетнуться дві фігури» ми замінили на «чи впаде одна точка в одну фігуру» — рухому фігуру стиснули в її кут, а нерухому натомість роздули на розміри рухомої.

Одне застереження про чесність моделі. Біля краю світу кут вікна пробігає не весь квадрат, а [0, 1−qw] × [0, 1−qh], тож частина рамки звисає назовні й справжня ймовірність трохи менша. Модель вартості цим нехтує: коробки й вікна на кілька порядків менші за світ. Формально це рівносильно тому, щоб замкнути світ у тор.

![Ліворуч — рамка допустимих положень кута вікна, поділена на чотири шматки: велика зелена коробка R розміром w на h, вузька синя смуга завширшки qw збоку від неї, синя смуга заввишки qh знизу й маленький червоний прямокутник qw на qh у куті; над рамкою окремо намальовано саме вікно запиту з позначеним кутом. Праворуч — розкриття добутку (w + qw)(h + qh) у чотири доданки й три підписи: площа коробки лишається навіть при точковому запиті, мішані доданки за квадратного вікна дають півпериметр, а площа вікна від коробки не залежить узагалі](img/minkowski.svg)
*Чотири доданки формули — це буквально чотири шматки роздутої рамки. Кожен по-своєму залежить від того, що індекс здатен змінити.*

### Чотири доданки

```
(w + qw)·(h + qh) = w·h + h·qw + w·qh + qw·qh
```

**w·h** — площа коробки. Єдиний доданок, що виживає при qw = qh = 0: точковий запит зачіпає коробку рівно з імовірністю її площі.

**h·qw + w·qh** — мішані доданки, лінійні за розмірами коробки. За квадратного вікна qw = qh = q вони згортаються в q·(w + h), тобто в половину периметра, помножену на сторону вікна.

**qw·qh** — площа вікна. Від коробки не залежить взагалі: цей доданок платить кожен вузол дерева просто за факт свого існування.

Хто з трьох головує — вирішує співвідношення розмірів вікна й коробки.

**Коробка 0.03 × 0.03, квадратне вікно зі стороною q:**

```
q        w·h        q·(w+h)      q²          разом       частки
0.001    0.000900   0.000060     0.000001    0.000961    94% / 6% / 0.1%
0.03     0.000900   0.001800     0.000900    0.003600    25% / 50% / 25%
0.3      0.000900   0.018000     0.090000    0.108900    0.8% / 17% / 83%
```

Малий запит бачить лише площу, великий — лише себе самого. Рівно посередині, коли вікно завбільшки з коробку, доданки стоять як 1 : 2 : 1 — це просто квадрат суми, і саме там периметр важить максимум із можливого, аж половину вартості.

### Від однієї коробки до всього дерева

Далі працює [лінійність сподівання](book:math/mean-variance): сподівання суми дорівнює сумі сподівань, і байдуже, залежні доданки чи ні. Нехай X — число вузлів, які запит змушений прочитати; це сума одиниць-індикаторів «вузол зачеплено». Отже,

```
E[прочитаних вузлів] = Σᵢ (wᵢ + q)·(hᵢ + q)
                     = Σᵢ wᵢ·hᵢ  +  q·Σᵢ (wᵢ + hᵢ)  +  q²·n

                     = сумарна площа
                     + (q/2) · сумарний периметр
                     + q² · кількість вузлів
```

Три доданки — три важелі, і вони ж є переліком критеріїв R*-дерева. Сумарну площу коробок мінімізує ще класичне R-дерево — і при виборі гілки для спуску, і при розщепленні. Сумарний периметр додало R*-дерево. Кількість вузлів n залежить від заповнення, тому третій його важіль — не залишати вузли напівпорожніми.

Периметр тут не є перевдягненою площею. За фіксованої площі S = w·h периметр 2(w + h) найменший, коли коробка квадратна: з нерівності між середнім арифметичним і геометричним w + h ≥ 2√(wh) = 2√S, і рівність лише при w = h. Тобто «менший периметр» означає «квадратніші коробки» — вимога, якої з вимоги «менша площа» не видобути.

```
коробка 0.001 × 0.900:  площа 0.0009,  периметр 1.802
коробка 0.030 × 0.030:  площа 0.0009,  периметр 0.120
```

Однакова площа, периметри різняться в п'ятнадцять разів — а разом з ними й вартість усіх запитів, більших за точку.

**Листковий рівень індексу над мільйоном об'єктів:**

```
n = 20 000 листків, кожен — квадратик зі стороною g = 1/√20000 = 0.00707

Σ площ      = 1        (листки покривають світ і майже не налазять)
Σ (w + h)   = 20000 · 0.01414 = 282.8

E(q) = 1 + 282.8·q + 20000·q²

q = 0.001 → 1 +  0.28 +   0.02 =   1.30
q = 0.010 → 1 +  2.83 +   2.00 =   5.83
q = 0.100 → 1 + 28.28 + 200.00 = 229.28
```

Одиниця в кожному рядку — підлога: точковий запит читає рівно один листок, і менше не буває. Решта — те, що коштує ширина вікна.

> 🔧 **Навіщо це.** Три величини — сумарна площа коробок, сумарний півпериметр і число вузлів — можна просто зміряти на живому індексі, обійшовши його один раз. Порівнявши три доданки для типової в цій системі сторони запиту, одразу видно, чи є сенс у перебудові: якщо головує q²·n, форма коробок ні до чого й допоможе тільки щільніше заповнення вузлів; якщо головує периметр, перебудова за критеріями R*-дерева окупиться.

### Скільки коштує перекриття

Перекриття у формулі вище не з'явилося — і не могло. Сума ймовірностей нічого не знає про те, чи зачеплені коробки належать одному батькові й чи спуск у них дублює роботу. Перекриття — це про **спільні** влучання, тобто про другий момент.

Візьмімо коробки одного рівня й порахуймо не саме X, а число **пар** зачеплених коробок: для кожного положення вікна це C(X, 2) = X(X−1)/2. Кожна пара (i, j) додає одиницю рівно тоді, коли кут вікна впав і в роздуту Rᵢ, і в роздуту Rⱼ — тобто в перетин двох рамок. Позначмо роздуту коробку через R⊕:

```
E[ X·(X−1)/2 ] = Σ_{i<j} площа( Rᵢ⊕ ∩ Rⱼ⊕ )
```

Для точкового запиту (qw = qh = 0) роздування зникає й лишається чиста сума площ попарних перетинів:

```
E[ X·(X−1)/2 ] = Σ_{i<j} площа( Rᵢ ∩ Rⱼ )
```

Зв'язати це з «зайвими спусками» просто. Корисним є щонайбільше один спуск, тож зайвих — X − 1, коли X ≥ 1, і нуль, коли X = 0. Для цілого X завжди max(X−1, 0) ≤ X(X−1)/2, причому рівність за X ≤ 2. Отже сума площ попарних перетинів — верхня оцінка очікуваного числа марних спусків, і оцінка точна доти, доки коробки не налазять по три відразу, що для пристойного дерева і є звичайним станом.

Тепер найцікавіше — що робить з цим доданком ненульове вікно. Роздування розсовує коробки назустріч одна одній, тому перетин рамок буває непорожнім і тоді, коли самі коробки не перетинаються.

**Дві коробки 0.03 × 0.03, розсунуті по горизонталі на проміжок g = 0.01, вирівняні по вертикалі:**

```
рамки перекриваються по x на (q − g), доки q > g
по y вони перекриваються на всю висоту (w + q)

q = 0     → 0                            коробки не перетинаються, платити нема за що
q = 0.02  → (0.02 − 0.01)·(0.03 + 0.02) = 0.00050
q = 0.10  → (0.10 − 0.01)·(0.03 + 0.10) = 0.01170
```

Звідси видно межу критерію «мінімізуй перекриття»: він є наближенням для малого вікна. Насправді штрафується не лише накладання коробок, а й їхня **близькість** — дві коробки, розведені на менше, ніж сторона типового запиту, оплачуються так само, як накладені.

### Смуга проти вікна

Тепер порахуймо строго те, чим міряють програш упорядкування за однією координатою. N точок рівномірно й незалежно розсипано в одиничному кубі d вимірів; запит — кубик зі стороною s. Кожна точка потрапляє в нього з імовірністю, що дорівнює об'єму кубика, тож за тією ж лінійністю сподівання відповідь містить у середньому s^d·N точок.

Індекс, який уміє обмежити лише k координат із d, відбирає всі точки, що влучили в «плиту»: обмежену по k осях і на всю довжину світу по решті.

```
E[кандидатів] = s^k · N
E[відповіді]  = s^d · N

відношення    = s^(k−d) = (1/s)^(d−k)
```

Кожна нерозв'язана вісь множить марну роботу на 1/s — незалежно від того, скільки їх усього. Упорядкування за однією координатою на площині — це k = 1, d = 2: смуга дає s·N кандидатів проти s²·N у відповіді, тобто в 1/s разів більше зайвого. У d вимірах індекс, що не дорізав одну-єдину вісь, дає s^(d−1)·N проти s^d·N — знову рівно 1/s. Сторона тут менша за одиницю, тому 1/s — це множник **угору**, і що точніше питання, то він більший.

```
N = 10⁶ точок, s = 0.01, d = 2

у вікні  = 0.01²·10⁶ =    100 точок
у смузі  = 0.01·10⁶  = 10 000 точок
```

### Скільки простору забирає «маленький» запит у d вимірах

Питання навпаки: якою мусить бути сторона кубика, щоб він накрив частку f об'єму?

```
f = side^d   ⟹   side = f^(1/d)
```

**Частка f = 0.01, тобто один відсоток об'єму:**

```
d        side = 0.01^(1/d)      запас 1 − side
2        0.100                  0.900
5        0.398                  0.602
10       0.631                  0.369
20       0.794                  0.206
50       0.912                  0.088
100      0.955                  0.045
```

Границя очевидна з логарифма: ln(side) = ln f / d → 0, тож side → 1 за будь-якої фіксованої частки f < 1. Цікавіша швидкість:

```
side = e^(ln f / d) ≈ 1 − ln(1/f)/d
```

Наближення робоче, доки ln(1/f)/d мале: за d = 50 воно дає 0.908 проти точних 0.912, за d = 100 — 0.954 проти 0.955. Читається воно так: запас, що лишається на кожній осі, спадає як 1/d, а сама частка входить лише під логарифмом. Через це зменшувати запит майже марно: у d = 20, звузивши питання з одного відсотка до однієї мільйонної, дістанемо сторону 0.501 замість 0.794 — і це все, чого вдалося домогтися шістьма порядками.

Тепер підставмо це у формулу першого розділу, записану для d вимірів. Множників стає d, і кожен обрізаний одиницею, бо ймовірність більшою не буває:

```
P(вузол прочитано) = Πᵢ min(wᵢ + q, 1)
```

Листок, що містить c об'єктів із N, у найкращому разі займає частку c/N об'єму й має форму куба, тобто його сторона wᵢ ≈ (c/N)^(1/d) — той самий корінь d-го степеня, що щойно з'їв запас у сторони запиту.

**Мільйон об'єктів, по 50 у листку, d = 20, запит на 1% об'єму:**

```
w = (5·10⁻⁵)^(1/20) = 0.609
q = 0.01^(1/20)     = 0.794

w + q = 1.403  →  обрізаємо до 1
```

Імовірність прочитати листок дорівнює одиниці. Не «висока», а точно одиниця, і то для найкомпактнішої з можливих коробок — реальні MBR більші. Формула, з якої випливли всі критерії розщеплення, тут сама й каже, що жодне розщеплення вже не допоможе: відсіювати нема чого.

### Комірки квадродерева: нутро й облямівка

Та сама арифметика працює й на сітці. Візьмімо рівень квадродерева, де комірка має сторону g, і спитаймо, скільки комірок перетне вікно.

Одна вісь. Проміжок [a, a + qw] перетинає колонку номер j, тобто [j·g, (j+1)·g], тоді й лише тоді, коли

```
a < (j+1)·g   і   a + qw > j·g

⟹   j·g − qw < a < (j+1)·g
```

Довжина цієї множини — g + qw. Поділивши на крок сітки (положення вікна рівномірне, тож на кожен крок припадає в середньому стільки колонок, скільки разів g вкладається в g + qw), дістаємо

```
E[колонок] = (g + qw)/g = qw/g + 1
```

Це знову формула Мінковського: «коробка» тут завширшки g, просто коробок багато й вони стоять регулярно. Осі незалежні, тож

```
E[комірок] = (qw/g + 1)·(qh/g + 1) = qw·qh/g² + (qw + qh)/g + 1
```

Три доданки читаються так само прозоро, як раніше. **qw·qh/g²** — нутро: комірок стільки, скільки вміщує площа вікна, і це неусувна частина, бо вона і є відповіддю. **(qw + qh)/g** — облямівка: півпериметр вікна, поділений на крок; комірки, зачеплені краєм. **+1** — кутова.

![Ліворуч — квадратна сітка вісім на сім комірок зі стороною g, поверх якої стоїть прямокутне вікно запиту, обведене синім; комірки, накриті вікном цілком, залиті зеленим, а зачеплені лише краєм — рожевим, і вони утворюють суцільну облямівку навколо зеленого нутра. Праворуч — формула очікуваного числа комірок як добутку двох множників і три підписи: нутро дорівнює площі вікна, поділеній на квадрат кроку; облямівка — це півпериметр вікна, поділений на крок; відношення облямівки до нутра дорівнює двом крокам, поділеним на сторону вікна](img/grid-cells.svg)
*Зелене нутро росте як площа вікна, рожева облямівка — як його периметр. Дрібніша сітка топить облямівку в нутрі, але множить загальне число комірок квадратично.*

Відношення облямівки до нутра за квадратного вікна зі стороною q дорівнює 2g/q. Звідси практичний висновок про вибір рівня: доки крок сітки більший за вікно, майже вся робота — це облямівка, тобто комірки, з яких згодиться дрібка; щойно крок стає помітно меншим за вікно, облямівка тоне в нутрі, зате саме число комірок росте як (q/g)². Оптимального g ця формула не дає — його визначає баланс із вартістю перебору об'єктів усередині комірки.

Лишилося з'ясувати, чи дорого коштує сам спуск деревом, а не лише його нижній рівень. На рівні ℓ комірка має сторону g_ℓ = 2^(−ℓ), і зачеплених комірок там (q·2^ℓ + 1)². Складімо всі рівні до L:

```
Σ_{ℓ=0..L} (q·2^ℓ + 1)² = q²·(4^(L+1) − 1)/3 + 2q·(2^(L+1) − 1) + (L + 1)

головний доданок = (4/3)·q²·4^L = (4/3)·(q/g_L)²
```

Геометричний ряд 1 + ¼ + ¹⁄₁₆ + … збігається до 4/3 — тобто повний обхід дерева згори коштує лише на третину більше, ніж один нижній рівень. Уся вартість віконного запиту в квадродереві сидить у листках; верхні рівні практично безплатні.

### Звідки взялася ця формула

Формулу для очікуваного числа прочитаних вузлів опублікували 1993 року, і незалежно дві групи: Ібрагім Камель і Крістос Фалутсос (Ibrahim Kamel, Christos Faloutsos, «On packing R-trees», CIKM 1993) та Бернд-Уве Паґель, Ганс-Вернер Зікс, Гайнріх Тобен і Петер Відмаєр (Pagel, Six, Toben, Widmayer, PODS 1993). Про подвійність відкриття одностайно свідчать пізніші огляди моделей вартості просторових індексів — це усталений факт, а не спірна атрибуція.

R*-дерево з його трьома критеріями старше на три роки (Norbert Beckmann, Hans-Peter Kriegel, Ralf Schneider, Bernhard Seeger, SIGMOD 1990), і критерії там обґрунтовано не викладкою, а великою серією вимірювань на стандартизованому наборі тестів. Тобто історичний порядок був зворотний до логічного: спершу намацали, що саме допомагає, і лише потім з'явилася формула, у якій ті самі величини стоять окремими доданками. Сам вивід вище — не переказ котроїсь із тих статей, а найкоротший шлях до тієї самої рівності.
