# ⚙️ Спуск і розщеплення в R-дереві

Форму коробок R-дерева не задає жодне правило, придумане наперед: вони виростають із того, як лягли вставки. Тому те, чи відсікатиме дерево гілки, чи виродиться в перебір із накладними витратами на обхід, вирішується рівно у двох місцях коду — коли новий запис обирає, у якого нащадка спускатися, і коли переповнений вузол ділиться на два. Обидва місця написано тут повністю, без жодної залежності, і на восьми прямокутниках пораховано кожне число, за яким вони ухвалюють рішення.

### Мірка

Єдина величина, якою R-дерево міряє свої рішення, — площа. Треба вміти чотири речі: порахувати площу коробки, скласти дві коробки в найменшу спільну, дізнатися, у скільки площі обійдеться впустити в коробку ще один запис, і перевірити, чи дві коробки взагалі перетинаються.

```cpp
#include <algorithm>
#include <cmath>
#include <limits>
#include <vector>

struct Rect { double x1, y1, x2, y2; };        // x1 ≤ x2, y1 ≤ y2

static double area(const Rect& r) { return (r.x2 - r.x1) * (r.y2 - r.y1); }

static Rect unite(const Rect& a, const Rect& b) {           // спільний MBR
    return Rect{ std::min(a.x1, b.x1), std::min(a.y1, b.y1),
                 std::max(a.x2, b.x2), std::max(a.y2, b.y2) };
}

static double enlargement(const Rect& box, const Rect& add) {
    return area(unite(box, add)) - area(box);               // ціна впустити add
}

static bool intersects(const Rect& a, const Rect& b) {
    return !(a.x2 < b.x1 || b.x2 < a.x1 || a.y2 < b.y1 || b.y2 < a.y1);
}
```

Вузол — це масив записів і прапорець, листок він чи внутрішній. Запис у листку тримає коробку об'єкта і його номер; запис усередині — коробку піддерева і вказівник на нього. Заповнення тримають між m і M, як у [B-дереві](book:algorithms/b-tree), тому масив зарезервовано на M+1: рівно на одну мить після вставки вузол буває переповнений, і саме тоді його ділять.

```cpp
static const int M = 4;      // максимум записів у вузлі (у житті — скільки влазить у сторінку)
static const int m = 2;      // мінімум; Гуттман радить 30–40 % від M

struct Node;
struct Entry { Rect box; Node* child; int id; };   // child або id — залежно від рівня

struct Node {
    bool leaf;
    Node* parent;
    std::vector<Entry> e;
    explicit Node(bool lf) : leaf(lf), parent(nullptr) { e.reserve(M + 1); }
};

static Rect cover(const Node* n) {                 // MBR усього вузла
    Rect r = n->e[0].box;
    for (size_t i = 1; i < n->e.size(); ++i) r = unite(r, n->e[i].box);
    return r;
}
```

### Куди спускатися

На кожному рівні новий запис мусить піти в одного з нащадків, і чийсь MBR доведеться розтягнути. Розтягнута коробка — це не тимчасова незручність: вона лишиться такою назавжди й братиме на себе кожен запит, що влучить у її новий порожній край. Тож платять найменшу з можливих цін.

При рівному прирості беруть меншу коробку. Найчастіше рівність — це два нулі: запис уже лежить усередині обох. Тоді дешевше довантажити тісний вузол, ніж і без того великий, — великому ще стане куди рости, а малий бажано лишити малим.

```cpp
static int chooseSubtree(const Node* n, const Rect& add) {
    int best = 0;
    double bestEnl = std::numeric_limits<double>::infinity();
    double bestArea = std::numeric_limits<double>::infinity();
    for (size_t i = 0; i < n->e.size(); ++i) {
        double enl = enlargement(n->e[i].box, add);
        double ar  = area(n->e[i].box);
        if (enl < bestEnl || (enl == bestEnl && ar < bestArea)) {
            best = (int)i; bestEnl = enl; bestArea = ar;
        }
    }
    return best;
}
```

### Розщеплення: квадратичний алгоритм Гуттмана

Коли в листку опинилося M+1 записів, їх треба розкласти на два вузли. Найкращу розкладку — ту, що дає найменшу сумарну площу двох коробок, — можна знайти повним перебором, але кількість розкладок росте як 2ᴹ, і при M у півсотні це не обговорюється. Антонін Гуттман у роботі, що ввела R-дерево (SIGMOD, 1984), запропонував замість перебору дві евристики; описана нижче зветься квадратичною за своєю вартістю.

Хід її думки такий. Спершу знайти двох, кому найгірше разом: для кожної пари порахувати, скільки **порожнечі** з'явиться, якщо їх накрити спільною коробкою, — площа об'єднання мінус площі обох. Пара з найбільшим d — це та, що ніколи не повинна опинитися в одному вузлі, тож вона й стає зернами двох груп.

```cpp
static void pickSeeds(const std::vector<Entry>& all, int& s1, int& s2) {
    double worst = -std::numeric_limits<double>::infinity();
    s1 = 0; s2 = 1;
    for (size_t i = 0; i < all.size(); ++i)
        for (size_t j = i + 1; j < all.size(); ++j) {
            double d = area(unite(all[i].box, all[j].box))
                     - area(all[i].box) - area(all[j].box);
            if (d > worst) { worst = d; s1 = (int)i; s2 = (int)j; }
        }
}
```

Далі решту записів роздають по одному. Черговість тут важить не менше за самий вибір групи: коробки груп ростуть із кожним прийнятим записом, і що більшими вони стануть, то менше різниці, куди класти наступного — усі різниці розмиються. Тому першими розбирають тих, у кого перевага **найвиразніша**: рахують приріст в обидві групи й беруть запис із найбільшим |d₁ − d₂|. Байдужі почекають — їм і пізніше буде байдуже.

Останнє в цьому коді — рядок про m. Якщо одній групі лишилося рівно стільки нерозібраних записів, скільки їй бракує до мінімуму, усі вони йдуть туди без розмов: вузол, заповнений менше ніж на m, зруйнував би гарантію висоти, заради якої дерево й балансують.

```cpp
static Node* quadraticSplit(Node* n) {
    std::vector<Entry> all;
    all.swap(n->e);                        // забираємо всі M+1 записів

    int s1, s2;
    pickSeeds(all, s1, s2);

    Node* nn = new Node(n->leaf);
    n->e.push_back(all[s1]);   Rect b1 = all[s1].box;
    nn->e.push_back(all[s2]);  Rect b2 = all[s2].box;

    std::vector<char> used(all.size(), 0);
    used[s1] = used[s2] = 1;
    size_t left = all.size() - 2;

    while (left > 0) {
        // групі бракує записів до m — віддаємо їй усе, що лишилось
        if (n->e.size() + left == (size_t)m || nn->e.size() + left == (size_t)m) {
            bool toFirst = (n->e.size() + left == (size_t)m);
            for (size_t i = 0; i < all.size(); ++i) if (!used[i]) {
                if (toFirst) { n->e.push_back(all[i]);  b1 = unite(b1, all[i].box); }
                else         { nn->e.push_back(all[i]); b2 = unite(b2, all[i].box); }
            }
            break;
        }
        // pickNext: запис із найвиразнішою перевагою
        int pick = -1; double bestDiff = -1.0;
        for (size_t i = 0; i < all.size(); ++i) {
            if (used[i]) continue;
            double diff = std::fabs(enlargement(b1, all[i].box)
                                  - enlargement(b2, all[i].box));
            if (diff > bestDiff) { bestDiff = diff; pick = (int)i; }
        }
        double d1 = enlargement(b1, all[pick].box);
        double d2 = enlargement(b2, all[pick].box);
        bool toFirst = (d1 != d2)                 ? (d1 < d2)
                     : (area(b1) != area(b2))     ? (area(b1) < area(b2))
                                                  : (n->e.size() <= nn->e.size());
        if (toFirst) { n->e.push_back(all[pick]);  b1 = unite(b1, all[pick].box); }
        else         { nn->e.push_back(all[pick]); b2 = unite(b2, all[pick].box); }
        used[pick] = 1;
        --left;
    }
    if (!n->leaf)                              // дітям, що переїхали, — новий батько
        for (Entry& en : nn->e) en.child->parent = nn;
    return nn;
}
```

### Вставка, підгін коробок і ріст угору

Тепер усе збирається. Спуск до листка йде за `chooseSubtree`, дорогою нічого не чіпаючи. Запис лягає в листок; якщо той переповнився — ділиться. Далі йдемо знизу вгору: у кожного батька перераховуємо коробку під наш вузол, і, якщо внизу народився новий вузол, додаємо про нього запис — від чого батько й сам може переповнитися. Коли ділиться корінь, дерево росте вгору: над двома половинами ставлять новий корінь. Це єдиний спосіб, яким R-дерево додає рівень, — і саме тому всі листки лишаються на одній глибині.

```cpp
struct Tree {
    Node* root;
    Tree() : root(new Node(true)) {}

    void insert(const Rect& box, int id) {
        Node* n = root;
        while (!n->leaf) n = n->e[chooseSubtree(n, box)].child;
        n->e.push_back(Entry{ box, nullptr, id });
        Node* split = (n->e.size() > (size_t)M) ? quadraticSplit(n) : nullptr;
        adjustTree(n, split);
    }

    void adjustTree(Node* n, Node* nn) {
        while (n != root) {
            Node* p = n->parent;
            for (Entry& en : p->e)
                if (en.child == n) { en.box = cover(n); break; }
            if (nn) {
                nn->parent = p;
                p->e.push_back(Entry{ cover(nn), nn, -1 });
                nn = (p->e.size() > (size_t)M) ? quadraticSplit(p) : nullptr;
            }
            n = p;
        }
        if (nn) {                                  // розщепився корінь
            Node* r = new Node(false);
            root->parent = r; nn->parent = r;
            r->e.push_back(Entry{ cover(root), root, -1 });
            r->e.push_back(Entry{ cover(nn),   nn,   -1 });
            root = r;
        }
    }

    void query(const Rect& w, std::vector<int>& out) const { search(root, w, out); }

    static void search(const Node* n, const Rect& w, std::vector<int>& out) {
        for (const Entry& en : n->e) {
            if (!intersects(en.box, w)) continue;  // ← усе відсікання дерева тут
            if (n->leaf) out.push_back(en.id);
            else search(en.child, w, out);
        }
    }
};
```

Запит вікном — сім рядків, і в них немає ані слова про те, як дерево будувалося. Уся його швидкість схована в одному `continue`: скільки разів він спрацює, стільки роботи вдалося не робити.

> 🔧 **Навіщо це.** M у справжніх реалізаціях беруть не зі стелі: вузол роблять розміром зі сторінку сховища, бо ціна читання сторінки однакова, скільки б записів у ній не лежало. Сторінка 8 КБ і запис на 40 байтів дають M ≈ 200 — і тоді дерево на мільйон об'єктів має три рівні. Але M входить у вартість розщеплення квадратом, тому надто велика сторінка перетворює вставку на важку операцію задовго до того, як почне економити читання.

### Вісім прямокутників, пораховані до останнього числа

Візьмімо M = 4, m = 2 і вісім однакових одиничних квадратів: чотири щільно збилися зліва, чотири — далеко справа, за порожнім проміжком.

```
A (0,0)-(1,1)   B (1,0)-(2,1)   C (0,1)-(1,2)   D (1,1)-(2,2)
E (8,0)-(9,1)   F (9,0)-(10,1)  G (8,1)-(9,2)   H (9,1)-(10,2)
```

Перші чотири лягають у корінь-листок без пригод. П'ятий, E, переповнює його — час ділити. `pickSeeds` рахує d для всіх десяти пар:

```
d(A,B) = 0    d(A,C) = 0    d(A,D) = 2    d(A,E) = 7
d(B,C) = 2    d(B,D) = 0    d(B,E) = 6
d(C,D) = 0    d(C,E) = 16   ← найгірша пара
d(D,E) = 14
```

Числа кажуть саме те, що видно оком: сусіди з лівого скупчення разом майже безплатні, а будь-хто зліва разом з E тягне коробку через увесь проміжок. Зернами стають C і E. Далі роздача:

```
крок 1:  A |d₁−d₂| = |1−8|  = 7
         B |d₁−d₂| = |3−7|  = 4
         D |d₁−d₂| = |1−15| = 14  ← найвиразніша перевага → G₁ (1 < 15)
крок 2:  A |d₁−d₂| = |2−8|  = 6   ← → G₁ (2 < 8)
         B |d₁−d₂| = |2−7|  = 5
крок 3:  у G₂ один запис, нерозібраний лишився один → правило m віддає B групі G₂
```

Останній рядок — найцікавіший. Геометрія хотіла B до лівих, але група E має лише один запис, а мінімум — два; тож B їде через увесь проміжок і розтягує коробку G₂ до (1,0)-(9,1). Це не помилка алгоритму, а видима ціна гарантії заповнення.

![Дві панелі, на кожній ті самі п'ять одиничних квадратів: чотири збиті в лівому куті (A, B, C, D) і один далеко праворуч (E). На верхній панелі показано результат квадратичного розщеплення: штрихова синя коробка G₁ площею 4 накриває A, C, D, а штрихова червона коробка G₂ площею 8 тягнеться від B через увесь порожній проміжок до E; підпис знизу — площі 4 плюс 8 дорівнює 12, перетин коробок 1. На нижній панелі та сама п'ятірка, поділена за порядком вставки: синя коробка H₁ площею 4 накриває A, B, C, а червона H₂ площею 16 накриває D і E й розтягнена і вшир, і на всю висоту; підпис знизу — площі 4 плюс 16 дорівнює 20, перетин коробок 2](img/split.svg)
*Та сама п'ятірка записів у двох розкладках. Наївне «перші три — решта» коштує 20 одиниць площі й дає перетин 2; квадратична евристика — 12 і перетин 1. Різницю вирішують один раз, а платить за неї кожен майбутній запит.*

Решта вставок іде спуском: для F приріст у ліву коробку — 16, у праву — 1, вибір очевидний; H взагалі не потребує розтягування (приріст 0). На H правий листок переповнюється, зернами знову беруть найгіршу пару — B і H (d = 16), і після роздачі виходить дерево:

```
корінь
├── (0,0)-(2,2)   площа 4    { C, D, A }
├── (1,0)-(9,1)   площа 8    { B, E }        ← коробка через увесь проміжок
└── (8,0)-(10,2)  площа 4    { F, G, H }
```

Запит на вікно (0.2,0.2)-(0.8,0.8) загляне лише в один листок і поверне A. А от запит навколо точки (1.5, 0.5) змушений спуститися у два листки з трьох — перший і другий перетинаються по квадрату площею 1, — щоб знайти єдиний об'єкт B. Один запис, покладений не за геометрією, а за арифметикою заповнення, зіпсував відсікання назавжди.

### Скільки це коштує

```
pickSeeds        C(M+1, 2) пар                        → O(M²)
роздача          ≤ M−1 кроків × O(M) кандидатів       → O(M²)
розщеплення      разом                                → O(M²)
вставка          спуск h·O(M) + розщеплення на рівнях → O(M²·h),  h = O(logₘ N)
запит            O(M) на кожен відвіданий вузол
```

Квадрат у розщепленні лякає менше, ніж здається. Після поділу в обох половинах щонайменше m записів, отже, більша з них має щонайбільше M+1−m, і до наступного переповнення її треба долити ще принаймні m разів. Тож розщеплення трапляється не частіше, ніж раз на m вставок у той самий вузол, і в [амортизованому](book:algorithms/amortized-analysis) перерахунку на одну вставку припадає O(M²/m) — при звичному m ≈ 0.4·M це просто O(M). А от у вартості запиту M взагалі не головне — число відвіданих вузлів визначає перекриття коробок, і жодна асимптотика його не оцінює: воно залежить від даних і від історії вставок.

### Пастки

**Виродження в одну величезну коробку.** Якщо `chooseSubtree` регулярно тягне записи в один і той самий вузол — а так буває, коли дані надходять посортованими або коли одна коробка вже велика й тому «дешева» для будь-чого, — її MBR росте, накриває півсвіту й перетинає кожен запит. Симптом видно без профайлера: площа кореневих коробок помітно більша за сумарну площу того, що в них лежить.

**Перекриття, що росте з часом.** Кожне розщеплення ухвалює остаточне рішення, спираючись на ті M+1 записів, які випадково зустрілися в одному вузлі саме тепер. Пізніші вставки цього рішення не переглядають, тож дрібні перекоси накопичуються, і після масових вставок дерево відсікає гірше, ніж на тих самих даних, укладених пакетно.

**Чому R\*-дерево вставляє наново.** Саме проти цього накопичення Norbert Beckmann, Hans-Peter Kriegel, Ralf Schneider і Bernhard Seeger (SIGMOD, 1990) додали примусову перевставку: коли вузол переповнюється **вперше** на своєму рівні під час однієї вставки, його не ділять, а виймають близько 30 % записів — найдальших від центра його коробки — і вставляють у дерево заново, від кореня. Запис, замкнений у чужій групі, дістає шанс переїхати туди, де йому місце; ту саму «поправку» дерево робить безперервно, а не раз на перебудову.

**Видалення без злиття вузлів.** У B-дереві недозаповнений вузол зливають із сусідом — там «сусід» означає суміжний діапазон ключів. На площині суміжності немає: два вузли під одним батьком можуть лежати як завгодно далеко один від одного, і їхнє злиття дало б коробку через півкарти. Тому в R-дереві недозаповнений вузол просто розпускають: його викидають із батька, а всі осиротілі записи вставляють наново — листкові як об'єкти, а записи внутрішніх вузлів на той самий рівень, з якого їх забрали, щоб листки їхніх піддерев лишилися на спільній глибині. Це виходить і простіше, і корисніше за злиття — перевставка дорогою ще й підправляє форму коробок.
