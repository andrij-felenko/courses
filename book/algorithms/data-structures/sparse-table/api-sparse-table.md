# 📋 Специфікація інтерфейсу та контракт операцій Sparse Table

Розріджена таблиця (Sparse Table) надає статичний інтерфейс для швидкої обробки інтервальних запитів над незмінними послідовностями даних. Цей документ містить повну специфікацію публічного інтерфейсу бібліотеки, контрактні інваріанти, правила обробки помилок, параметри просторової та часової складності для мов програмування C та C++.

## Загальні вимоги до контрактів та інваріанти структури

Будь-яка коректна реалізація таблиці розрідження повинна гарантувати виконання наступних інваріантів:

1. **Незмінність вхідних даних (Immutability):** Після успішної побудови таблиці модифікація вихідного масиву `A` не призводить до автоматичного оновлення `ST`. Будь-яка зміна даних вимагає повної перебудови або створення нового екземпляра структури.
2. **Інваріант коректності діапазону (Range Validity):** Для будь-якого запиту `query(L, R)` індекси меж повинні задовольняти умову `0 ≤ L ≤ R < N`. Порушення цієї умови трактується як помилка клієнтського коду та повертає код помилки (у C) або `std::nullopt` (у C++).
3. **Алгебраїчний інваріант ідемпотентності:** Метод константного запиту `query(L, R)` гарантує математично точну відповідь тоді й тільки тоді, коли бінарний оператор `⊕` задовольняє аксіоми асоціативності `(a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)` та ідемпотентності `x ⊕ x = x`.
4. **Інваріант виділення пам'яті:** Таблиця розрідження розміщується в єдиному або двох неперервних блоках динамічної пам'яті, що виключає внутрішню фрагментацію купи та забезпечує детерміноване звільнення ресурсів за одну операцію деалокації.

## Оголошення основних типів та структур даних

Для забезпечення максимальної продуктивності та просторової локальності розріджена таблиця зберігається у вигляді єдиного сплощеного динамічного буфера.

:::tabs
```c
/* Оголошення структури розрідженої таблиці мовою C */
typedef struct {
    size_t n;            /* Кількість елементів у вихідній послідовності */
    size_t levels;       /* Кількість рівнів таблиці: floor(log2(n)) + 1 */
    int32_t *data;       /* Неперервний буфер розміру (levels * n) елементів */
} sparse_table_t;
```
```cpp
/* Шаблонний клас розрідженої таблиці мовою C++20 */
template <typename T, typename BinaryOp = std::ranges::min>
requires std::invocable<BinaryOp, T, T> && 
         std::copy_constructible<T>
class SparseTable {
public:
    using value_type = T;
    using size_type = std::size_t;
    using binary_op_type = BinaryOp;

private:
    BinaryOp op_;
    size_type n_{0};
    size_type levels_{0};
    std::vector<T> table_;
};
```
:::

### Детальний опис полів структури та типів-членів
- **Поле `n` (C) / Метод `size()` (C++):** Зберігає кількість елементів у початковій послідовності. Має бути строго більшим за нуль для валідного екземпляра таблиці в мові C. У C++ об'єкт може бути порожнім (`size() == 0`).
- **Поле `levels` (C) / Метод `levels()` (C++):** Зберігає кількість двійкових ступенів `K = ⌊log₂ N⌋ + 1`. Для масиву довжини `N = 10^6` це значення дорівнює рівно `20`.
- **Буфер `data` (C) / Вектор `table_` (C++):** Неперервний блок оперативної пам'яті. Розташування даних відповідає рівнево-послідовній схемі (Level-Major), де значення рівня `j` для індексу `i` знаходиться за зміщенням `j * n + i`.

## Ініціалізація та побудова таблиці

Функція ініціалізації виділяє пам'ять та заповнює всі рівні таблиці розрідження за рекурентною формулою динамічного програмування.

:::tabs
```c
/* Створення та ініціалізація таблиці мовою C */
sparse_table_t *st_create(const int32_t *array, size_t n);
```
```cpp
/* Конструктори таблиці розрідження мовою C++ */
template <typename T, typename BinaryOp>
SparseTable<T, BinaryOp>::SparseTable(std::span<const T> values, BinaryOp op);

template <typename T, typename BinaryOp>
SparseTable<T, BinaryOp>::SparseTable(const std::vector<T>& values, BinaryOp op);
```
:::

### Контрактні передмови (Preconditions)
- Вхідний масив `array` або діапазон `values` повинен містити коректні ініціалізовані дані.
- Покажчик `array` у мові C не повинен бути `NULL`, а розмір `n` повинен задовольняти умову `n ≥ 1`.
- Переданий функціональний об'єкт `op` повинен задовольняти аксіому асоціативності.

### Післямови (Postconditions)
- У разі успішного завершення виділяється рівно `N · (⌊log₂ N⌋ + 1) · sizeof(T)` байтів пам'яті.
- Рівень `0` містить точну копію вхідного масиву `array`.
- Усі наступні рівні `j ∈ [1, K-1]` містять коректні проміжні згортки для підвідрізків довжини `2^j`.

### Обробка помилок
- Мова C: Якщо `array == NULL`, `n == 0` або системний виклик `malloc` повертає `NULL`, функція `st_create` негайно повертає `NULL`, не залишаючи частково виділених ресурсів.
- Мова C++: Надає строгу гарантію безпеки винятків (Strong Exception Safety). Якщо конструктор копіювання типу `T` або оператор `op` викидає виняток, виділена пам'ять `std::vector` автоматично звільняється без витоків.

## Виконання ідемпотентних запитів (RMQ) за O(1)

Запит мінімуму на відрізку виконується за константний час шляхом покриття інтервалу двома блоками найбільшого можливого степеня двійки `2^k`.

:::tabs
```c
/* Константний запит мінімуму на відрізку [l, r] мовою C */
bool st_query_min(const sparse_table_t *st, size_t l, size_t r, int32_t *result);
```
```cpp
/* Константний запит на відрізку [l, r] мовою C++ */
[[nodiscard]] std::optional<T> 
SparseTable<T, BinaryOp>::query(size_type l, size_type r) const noexcept;
```
:::

### Параметри запиту
- `st` / `this`: Вказівник на екземпляр розрідженої таблиці.
- `l`: Ліва межа запитуваного відрізка (0-індексація, включно).
- `r`: Права межа запитуваного відрізка (0-індексація, включно).
- `result`: Вказівник на змінну типу `int32_t` для запису обчисленого результату (у C).

### Повертані значення та гарантії
- Мова C: Повертає булеве значення `true` у разі успішного виконання запиту. Повертає `false`, якщо передано недійсні параметри (`st == NULL`, `result == NULL`, `l > r` або `r >= st->n`).
- Мова C++: Повертає об'єкт `std::optional<T>`, що містить результат операції, або `std::nullopt`, якщо передано некоректний діапазон чи таблиця є порожньою. Метод позначено як `noexcept`.

### Складність та апаратні характеристики
- **Часова складність:** Строго `O(1)` операцій. Потрібно рівно дві інструкції читання з оперативної пам'яті та один виклик бінарного оператора.
- **Просторова складність:** `O(1)` додаткової пам'яті. Усі обчислення виконуються суто в процесорних регістрах.

## Виконання неідемпотентних запитів за O(log N)

Для операцій, що не задовольняють закон ідемпотентності (наприклад, сума чисел або добуток матриць), перекриття блоків заборонено. Бібліотека надає диз'юнктний метод запиту.

:::tabs
```c
/* Диз'юнктний запит для неідемпотентних операцій мовою C */
bool st_query_disjoint(const sparse_table_t *st, size_t l, size_t r, int32_t *result);
```
```cpp
/* Диз'юнктний логарифмічний запит мовою C++ */
[[nodiscard]] std::optional<T> 
SparseTable<T, BinaryOp>::query_disjoint(size_type l, size_type r) const noexcept;
```
:::

### Алгоритм виконання
1. Довжина відрізка `len = R - L + 1` розкладається на суму двійкових степенів: `len = ∑ c_b · 2^b`.
2. Ітератор переміщується від `L` до `R`, послідовно акумулюючи блоки відповідних степенів двійки.
3. Кількість ітерацій циклу обмежена кількістю встановлених бітів `popcount(len) ≤ ⌊log₂ N⌋ + 1`.

## Звільнення ресурсів та керування пам'яттю

:::tabs
```c
/* Звільнення ресурсів таблиці мовою C */
void st_destroy(sparse_table_t *st);
```
```cpp
/* Деструктор класу SparseTable мовою C++ (автоматичний RAII) */
~SparseTable() = default;
```
:::

### Правила володіння пам'яттю
- У мові C функція `st_destroy` звільняє внутрішній буфер `data` та саму структуру `st`. Якщо передано покажчик `NULL`, функція безпечно завершує роботу.
- У мові C++ пам'ять керується автоматично через деструктор контейнера `std::vector<T>` відповідно до ідіоми RAII (Resource Acquisition Is Initialization).

## Двовимірна Sparse Table (2D RMQ)

Двовимірна розріджена таблиця призначена для швидкого знаходження мінімуму на прямокутних підматрицях розміру `[x1..x2] × [y1..y2]`.

:::tabs
```c
/* Інтерфейс двовимірної розрідженої таблиці мовою C */
sparse_table_2d_t *st2d_create(const int32_t *matrix, size_t rows, size_t cols);
bool st2d_query(const sparse_table_2d_t *st, size_t x1, size_t y1, size_t x2, size_t y2, int32_t *res);
void st2d_destroy(sparse_table_2d_t *st);
```
```cpp
/* Інтерфейс двовимірної розрідженої таблиці мовою C++ */
class SparseTable2D {
public:
    explicit SparseTable2D(const std::vector<std::vector<int32_t>>& matrix);
    [[nodiscard]] std::optional<int32_t> query(std::size_t x1, std::size_t y1, 
                                               std::size_t x2, std::size_t y2) const noexcept;
    [[nodiscard]] std::size_t rows() const noexcept;
    [[nodiscard]] std::size_t cols() const noexcept;
};
```
:::

### Контрактні характеристики 2D-запиту
- **Обмеження на координати:** `0 ≤ x1 ≤ x2 < rows` та `0 ≤ y1 ≤ y2 < cols`.
- **Час запиту:** `O(1)` (рівно 4 читання з пам'яті для покриття чотирьох кутів прямокутника).
- **Пам'ять:** `O(rows · cols · log(rows) · log(cols))` слів пам'яті.

## Діагностика та розширені коди помилок

Для використання в критично важливих промислових системах C-інтерфейс визначає стандартизовані статусні коди, а C++ підтримує безпечний тип `std::expected`.

:::tabs
```c
/* Перелік статусних кодів операцій мовою C */
typedef enum {
    ST_SUCCESS                 =  0, /* Операцію виконано успішно */
    ST_ERROR_NULL_POINTER      = -1, /* Передано нульовий вказівник */
    ST_ERROR_EMPTY_ARRAY       = -2, /* Розмір масиву n дорівнює нулю */
    ST_ERROR_ALLOCATION_FAILED = -3, /* Не вдалося виділити пам'ять */
    ST_ERROR_INVALID_RANGE     = -4, /* Ліва межа більша за праву (L > R) */
    ST_ERROR_OUT_OF_BOUNDS     = -5, /* Межі виходять за розмір масиву */
    ST_ERROR_INTEGER_OVERFLOW  = -6  /* Переповнення розміру буфера */
} st_status_t;
```
```cpp
/* Перелік помилок для сучасного C++23 std::expected */
enum class SparseTableError : std::uint8_t {
    InvalidRange,      /* Ліва межа більша за праву (L > R) */
    OutOfBounds,       /* Межа виходить за розмір контейнера (R >= N) */
    EmptyTable,        /* Запит до порожньої таблиці */
    AllocationFailed   /* Нестача оперативної пам'яті */
};
```
:::

### Таблиця діагностики збоїв та дій клієнтського коду
| Код помилки | Умова виникнення | Поведінка бібліотеки | Рекомендована реакція клієнта |
| :--- | :--- | :--- | :--- |
| **`ST_SUCCESS`** | Усі параметри коректні, операція успішна. | Записує результат у вихідну змінну. | Продовжити штатну обробку даних. |
| **`ST_ERROR_NULL_POINTER`** | `array == NULL` або `st == NULL`. | Перериває виконання без алокацій. | Перевірити валідність вказівників. |
| **`ST_ERROR_EMPTY_ARRAY`** | Передано `n == 0` при ініціалізації. | Повертає код помилки або `NULL`. | Перевірити розмір вхідного датасету. |
| **`ST_ERROR_ALLOCATION_FAILED`** | Брак оперативної пам'яті. | Очищає частково створені структури. | Зменшити розмір масиву або збільшити swap. |
| **`ST_ERROR_INVALID_RANGE`** | Порушено умову `L ≤ R`. | Не виконує звернення до таблиці. | Виправити логіку формування меж відрізка. |
| **`ST_ERROR_OUT_OF_BOUNDS`** | `R ≥ N` або `L ≥ N`. | Запобігає пошкодженню пам'яті. | Перевірити межі масиву перед запитом. |

## Специфікація інтерфейсу Disjoint Sparse Table

Розріджена таблиця неперетинних блоків забезпечує час виконання запиту `O(1)` для будь-яких напівгруп без вимоги ідемпотентності.

:::tabs
```c
/* Інтерфейс Disjoint Sparse Table мовою C */
typedef int32_t (*st_semigroup_op_t)(int32_t a, int32_t b);

typedef struct {
    size_t n;
    size_t padded_n;
    size_t levels;
    st_semigroup_op_t op;
    int32_t *table;
} disjoint_sparse_table_t;

disjoint_sparse_table_t *dst_create(const int32_t *arr, size_t n, st_semigroup_op_t op);
bool dst_query(const disjoint_sparse_table_t *dst, size_t l, size_t r, int32_t *result);
void dst_destroy(disjoint_sparse_table_t *dst);
```
```cpp
/* Інтерфейс Disjoint Sparse Table мовою C++ */
template <typename T, typename BinaryOp = std::plus<T>>
requires std::invocable<BinaryOp, T, T> && std::copy_constructible<T>
class DisjointSparseTable {
public:
    using value_type = T;
    using size_type = std::size_t;

    explicit DisjointSparseTable(std::span<const T> values, BinaryOp op = BinaryOp{});
    [[nodiscard]] std::optional<T> query(size_type l, size_type r) const noexcept;
    [[nodiscard]] size_type size() const noexcept;
    [[nodiscard]] bool empty() const noexcept;

private:
    BinaryOp op_;
    size_type n_{0};
    size_type padded_n_{0};
    size_type levels_{0};
    std::vector<T> table_;
};
```
:::

### Механізм константного запиту
Запит на відрізку `[L, R]` зводиться до знаходження рівня розбиття `j = 31 - __builtin_clz(L ^ R)` та виконання рівно однієї операції `op` між суфіксом лівого блоку та префіксом правого блоку: `Suffix[j][L] ⊕ Prefix[j][R]`.

## Специфікація статичного вбудованого API (Embedded / Static BSS)

Для застосування у мікроконтролерах (MCU) без використання динамічної пам'яті надається статичний API часу компіляції.

:::tabs
```c
/* Статичний API для вбудованих мікроконтролерів мовою C */
#define ST_STATIC_MAX_N 1024
#define ST_STATIC_MAX_LEVELS 11

void st_init_static(const int32_t *arr, size_t n);
int32_t st_query_static(size_t l, size_t r);
```
```cpp
/* Статичний шаблонний клас часу компіляції мовою C++ */
template <typename T, std::size_t MaxN>
class StaticSparseTable {
public:
    static constexpr std::size_t MaxLevels = std::bit_width(MaxN);
    constexpr void build(const T* data, std::size_t n) noexcept;
    [[nodiscard]] constexpr T query(std::size_t l, std::size_t r) const noexcept;
    [[nodiscard]] constexpr std::size_t size() const noexcept;
};
```
:::

## Серіалізація та взаємодія зі спільною пам'яттю (IPC / Memory Map)

Для миттєвого завантаження великих статичних таблиць без затримок ініціалізації використовується бінарний формат заголовка.

:::tabs
```c
/* Заголовок та функції серіалізації мовою C */

    uint64_t n;           /* Кількість елементів */
    uint32_t levels;      /* Кількість рівнів */
    uint32_t flags;       /* Бітові прапорці */

} st_file_header_t;
#pragma pack(pop)

bool st_save_to_file(const sparse_table_t *st, const char *filepath);
```

```cpp
    std::uint32_t levels{0};
```

## Підтримка користувацьких функторів зі станом

Якщо бінарна операція вимагає збереження стану (наприклад, посилання на зовнішню матрицю ваг або географічні коефіцієнти), бібліотека підтримує користувацькі контексти.

:::tabs
```c
/* Функтор зі станом через контекстний покажчик у C */
typedef struct {
    const double *weights;
    size_t count;
} weight_context_t;

static inline size_t weight_min_op(size_t a, size_t b, const void *ctx) {
    const weight_context_t *w = (const weight_context_t *)ctx;
    return (w->weights[a] < w->weights[b]) ? a : b;
}
```
```cpp
/* Функтор зі станом мовою C++ */
struct CustomWeightMin {
    const std::vector<double>& weights;

    [[nodiscard]] std::size_t operator()(std::size_t idx_a, std::size_t idx_b) const noexcept {
        return (weights[idx_a] < weights[idx_b]) ? idx_a : idx_b;
    }
};
```

## Інтеграція з поліморфними ресурсами пам'яті (C++17/20 std::pmr)

Для високопродуктивних фінансових торговельних систем та серверів обробки телеметрії, де стандартний алокатор викликає небажані системні виклики та фрагментацію купи, інтерфейс надає підтримку простору імен `std::pmr`.

:::tabs
```c
/* Виділення пам'яті через користувацький лінійний арена-алокатор у C */
typedef struct {
    uint8_t *buffer;
    size_t capacity;
    size_t offset;
} arena_t;

sparse_table_t *st_create_in_arena(arena_t *arena, const int32_t *array, size_t n);
```

```cpp
/* Шаблонний клас із підтримкою поліморфного алокатора std::pmr */
template <typename T, typename BinaryOp = std::ranges::min>
class PmrSparseTable {
public:
    using allocator_type = std::pmr::polymorphic_allocator<T>;

    explicit PmrSparseTable(std::span<const T> values, 
                            BinaryOp op = BinaryOp{}, 
                            allocator_type alloc = {});

    [[nodiscard]] std::optional<T> query(std::size_t l, std::size_t r) const noexcept;
    [[nodiscard]] allocator_type get_allocator() const noexcept;

    std::size_t levels_{0};
```

### Контракт поліморфного виділення
1. **Детермінований час ініціалізації:** Використання `std::pmr::monotonic_buffer_resource` забезпечує виділення всієї таблиці за одну лінійну операцію зсуву покажчика на стеку або в передсегментованій пам'яті.
2. **Нульова фрагментація купи:** Після завершення пакету запитів весь буфер арени звільняється одним системним скиданням `release()`, усуваючи необхідність поодиноких викликів деструкторів.

## Двійковий ABI та правила експорту динамічних бібліотек

При збиранні бібліотеки у вигляді спільного динамічного модуля (`.so` на Linux / macOS або `.dll` на Windows) застосовуються такі правила експорту двійкового інтерфейсу:

### Характеристики бінарного ABI
- **Угода про виклики (Calling Convention):** Усі функції використовують стандартну системну конвенцію платформи: `cdecl` на x86-32, System V AMD64 ABI на Linux x86-64 та Microsoft x64 Calling Convention на Windows.
- **Вирівнювання структур (Data Alignment):** Структура `sparse_table_t` має вирівнювання 8 байтів на 64-бітних архітектурах та загальний розмір 24 байти (без внутрішнього паддінгу між полями `size_t` та вказівником).
- **Сумісність компіляторів:** Експортовані C-символи є стабільними між різними версіями компіляторів GCC, Clang та MSVC, дозволяючи викликати бібліотеку з мов Python (через `ctypes`), Rust (через `extern "C"` FFI), Go (через `cgo`) та C#.

## Методологія валідації та тестовий фазинг-контракт

Для гарантування відсутності помилок індексації та стабільності у виробничих середовищах бібліотека визначає еталонний тестовий контракт.

:::tabs
```c
/* Функція диференційного тестування у C */
bool st_verify_against_naive(const sparse_table_t *st, const int32_t *orig, size_t n, size_t trials);
```
```cpp
/* Шаблонний тестовий harness у C++ */
template <typename T, typename Op>
bool verify_sparse_table(const SparseTable<T, Op>& st, 
                         std::span<const T> original, 
                         std::size_t num_random_queries);
```
:::

### Вимоги до перевірки коректності (Verification Invariants)
1. **Тест одиничних діапазонів:** Для всіх `i ∈ [0, N-1]` запит `query(i, i)` повинен строго дорівнювати `A[i]`.
2. **Тест суміжних пар:** Для всіх `i ∈ [0, N-2]` запит `query(i, i+1)` повинен строго дорівнювати `op(A[i], A[i+1])`.
3. **Тест глобального діапазону:** Запит `query(0, N-1)` повинен дорівнювати загальній згортці всього масиву.
4. **Стрес-фазинг:** Генерація не менше `10^7` випадкових запитів на випадкових масивах розміром від `N = 1` до `N = 10^6` із порівнянням результатів з наївним лінійним скануванням `O(N)`.

## Вимоги до вирівнювання пам'яті та кеш-ліній (64-byte Alignment)

Для забезпечення максимальної швидкості роботи векторних інструкцій (AVX2, AVX-512, ARM NEON) виділення внутрішнього буфера таблиці повинно відповідати суворим апаратним вимогам:

1. **Вирівнювання початкової адреси:** Буфер даних повинен бути вирівняний щонайменше за 64-байтною межею (розмір стандартної лінії кешу L1/L2 сучасних процесорів архітектури x86-64 та ARM). Для виділення пам'яті у C рекомендується використовувати `posix_memalign` або `_aligned_malloc`.
2. **Усунення розщеплення кеш-ліній (Cache Line Split):** Кожен рівень `j` займає рівно `N` елементів. Якщо розмір `N · sizeof(T)` не кратний 64 байтам, початок наступного рівня `j + 1` потрапляє всередину кеш-лінії попереднього рівня. Це створює накладні витрати під час паралельної побудови. Рекомендується доповнювати довжину рядка нульовими байтами (Padding) до кратності 64 байтам.

## Інтеграція з іншими мовами програмування через FFI (Foreign Function Interface)

Завдяки чистому двійковому ABI мови C та відсутності залежностей від середовища виконання C++ (Runtime), розріджена таблиця легко інтегрується у високорівневі мови програмування:

- **Python (ctypes / cffi):** Вихідний буфер передається як `ctypes.POINTER(ctypes.c_int32)`, а створення об'єкта `sparse_table_t` дозволяє виконувати мільйони RMQ-запитів без накладних витрат інтерпретатора CPython (GIL звільняється під час запиту).
- **Rust (bindgen / extern "C"):** Структура `sparse_table_t` обгортається у безпечний RAII-тип `struct SparseTable<'a>`, що реалізує трейти `Send` та `Sync` завдяки строгій незмінності (Immutability) структури після побудови.
- **Go (cgo):** C-функції викликаються безпосередньо через директиву `import "C"`, надаючи високоефективний константний RMQ-рушій для мікросервісів обробки геопросторових координат.
- **C# (.NET P/Invoke):** Використовуються атрибути `[DllImport]` зі структурою `LayoutKind.Sequential`, забезпечуючи пряму взаємодію з пам'яттю без маршалінгу.

## Повна матриця гарантій безпеки винятків (Exception Safety)

| Операція C++ | Рівень гарантії | Стан об'єкта у разі збою | Причина можливого збою |
| :--- | :--- | :--- | :--- |
| **`SparseTable(span, op)`** | Строга (Strong Guarantee) | Об'єкт не створюється, пам'ять звільняється | `std::bad_alloc` або виняток у конструкторі копіювання `T` |
| **`SparseTable(vector, op)`** | Строга (Strong Guarantee) | Об'єкт не створюється, пам'ять звільняється | `std::bad_alloc` або виняток у `op` |
| **`query(l, r)`** | `noexcept` | Стан не змінюється (Read-Only) | Винятки повністю виключені |
| **`query_disjoint(l, r)`** | `noexcept` | Стан не змінюється (Read-Only) | Винятки повністю виключені |
| **Конструктор переміщення** | `noexcept` | Джерело переходить у валідний порожній стан | Операція обміну покажчиками |
| **Переміщуюче присвоєння** | `noexcept` | Старі ресурси звільняються | Операція обміну покажчиками |

| **Деструктор `~SparseTable`** | `noexcept` | Пам'ять звільняється повністю | Деструктор вектора є `noexcept` |

## Контракт потокобезпеки та паралелізму (Thread Safety)

1. **Багатопотокове читання без блокувань (Concurrent Readers):** Після завершення фази побудови структура даних є строго незмінною (Read-Only). Довільна кількість паралельних потоків може одночасно викликати метод `query` без використання м'ютексів чи атомарних операцій.
2. **Відсутність внутрішнього стану:** Усі методи запиту є реентерабельними (`const noexcept`), не модифікують внутрішніх полів об'єкта та не містять статичних змінних.
3. **Публікація між потоками:** Передача покажчика або екземпляра таблиці між потоками потребує бар'єра пам'яті (Release-Acquire) для гарантування видимості всіх ініціалізованих рівнів іншим ядрам процесора.
4. **Конкурентне знищення:** Виклик функції деструктора або деалокації `st_destroy` одночасно з виконанням запитів іншими потоками є грубим порушенням контракту (Undefined Behavior) та вимагає зовнішньої синхронізації життєвого циклу об'єкта (наприклад, через `std::shared_ptr`).

## Розрахунок обсягу пам'яті для різних типів даних та розміщення в NUMA-доменах

Обсяг оперативної пам'яті, необхідний для побудови розрідженої таблиці, визначається розміром типу `T` та кількістю елементів `N`:

```text
Memory_Bytes(N, sizeof(T)) = (⌊log₂ N⌋ + 1) · N · sizeof(T)
```

### Таблиця характеристик пам'яті для N=10⁶ елементів

| Тип даних | `sizeof(T)` | Обсяг пам'яті для N=10⁶ (МБ) | Резиденція в кеші процесора | Прикладні сценарії |
| :--- | :--- | :--- | :--- | :--- |
| **`uint8_t` / `char`** | 1 байт | **20 МБ** | Повністю вміщується в кеш L3 (32–64 МБ) | Символьні послідовності ДНК, LCP латинських рядків |
| **`int16_t` / `uint16_t`** | 2 байти | **40 МБ** | Частково L3 / швидке читання з RAM | Карти висот рельєфу (DEM), сенсори тиску та температури |
| **`int32_t` / `float`** | 4 байти | **80 МБ** | Оперативна пам'ять RAM (висока пропускна здатність) | Стандартні RMQ-запити, ціни біржових активів, LCA у графах |
| **`int64_t` / `double`** | 8 байтів | **160 МБ** | Оперативна пам'ять RAM | Високоточні фінансові ряди, часові мітки наносекунд |
| **`Point2D { float x, y; }`** | 8 байтів | **160 МБ** | Оперативна пам'ять RAM | Обчислення обмежувальних габаритів AABB у просторі |

### Правила прив'язки до NUMA-вузлів (NUMA Node Pinning)
На багатопроцесорних серверах розміщення єдиного буфера на одному вузлі NUMA створює міжпроцесорні затримки доступу для ядер інших сокетів. Для промислових серверів з мільйонами запитів на секунду рекомендується дублювати екземпляр `sparse_table_t` на кожному окремому NUMA-вузлі через системні виклики `numa_alloc_onnode` або прив'язувати робочі потоки до відповідного сокета пам'яті.

## Узагальнення на багатовимірні тензори (3D / 4D Sparse Tables)

Принцип двійкового покриття прямокутних областей узагальнюється на `D`-вимірні просторові куби та тензори:
- **Кількість підблоків для запиту:** `2^D` кутових гіперпаралелепіпедів (для 1D — 2 відрізки, для 2D — 4 прямокутники, для 3D — 8 паралелепіпедів, для 4D — 16 гіперкубів).
- **Час виконання запиту:** Залишається строго **`O(2^D) = O(1)`** для будь-якої фіксованої розмірності `D`.
- **Просторова складність побудови:** `O(N_1 · N_2 · ... · N_D · ∏_{d=1}^D log(N_d))`.

## Підсумкова інструкція з інтеграції бібліотеки

1. **Для швидких запитів мінімуму/максимуму/НСД:** Використовуйте `SparseTable<T, Op>` та метод `query()`.
2. **Для операцій суми, добутку та матриць:** Використовуйте `DisjointSparseTable<T, Op>` для `O(1)` або `query_disjoint()` для `O(log N)`.
3. **Для вбудованих систем без купи:** Підключайте `st_init_static()` або `StaticSparseTable<T, MaxN>`.
4. **Для великих бінарних файлів:** Застосовуйте інтерфейс `st_load_from_mmap()` для миттєвого відображення в пам'ять без затримок ініціалізації.
