# 📜 Еволюція задачі Range Minimum Query та винайдення розріджених таблиць

Коли в 1970-х і 1980-х роках виникла потреба в аналізі великих масивів біологічних послідовностей (геномних ланцюгів ДНК) та стисненні суфіксних структур даних, обчислювальні системи зіткнулися з фундаментальним вузьким місцем. Кожна операція порівняння двох підрядків або пошук найдовшого спільного префікса (Longest Common Extension, LCE) зводилася до знаходження мінімального значення в масиві висот суфіксного дерева — задачі **Range Minimum Query (RMQ)**. Наївне сканування вимагало лінійного часу `O(N)` на кожен запит, що для мільйонів пар суфіксів призводило до астрономічного часу роботи алгоритмів.

Ця проблема вимагала принципово нового підходу до передпідрахунку: як витратити помірний обсяг пам'яті й часу на етапі ініціалізації, аби згодом відповідати на довільний запит RMQ миттєво, без обходу елементів.

## Витоки задачі: від LCA до RMQ у роботах Тар'яна та Габова

Історія розріджених таблиць нерозривно пов'язана з дослідженням зв'язку між двома класичними задачами дискретної математики: пошуком найменшого спільного предка (Lowest Common Ancestor, LCA) у довільному кореневому дереві та Range Minimum Query на одновимірному числовому масиві.

У 1979 році Роберт Тар'ян (Robert Tarjan) опублікував фундаментальну працю про оффлайн-пошук LCA за допомогою системи неперетинних множин (Disjoint Set Union, DSU) за майже лінійний час `O(N · α(N))`. Проте метод Тар'яна вимагав знання всіх запитів заздалегідь. Для інтерактивних систем, баз даних і потокової обробки потрібен був онлайн-алгоритм: структура, здатна відповідати на будь-який новий запит `[L, R]` без очікування решти запитів.

У 1984 році Дов Гарель (Dov Harel) та Роберт Тар'ян зробили прорив: вони вперше довели, що для задачі LCA можливий теоретичний оптимум — передобробка за лінійний час `O(N)` та відповідь на запит за константний час `O(1)`. Однак їхня оригінальна конструкція була настільки математично громіздкою й містила настільки великі приховані константи у використанні бітових векторів і стиснених дерев, що практична реалізація алгоритму виявилася майже нездійсненною на тогочасних комп'ютерах.

У 1987 році Гарольд Габов (Harold Gabow), Джон Бентлі (Jon Bentley) та Роберт Тар'ян розвинули ці ідеї, досліджуючи парадигму двійкового підйому (binary lifting) та розбиття інтервалів на блоки, кратні степеням двійки. Вони показали, що деревовидна ієрархія предків із кроками `2^0, 2^1, 2^2, ...` дозволяє зводити навігацію по дереву до компактних таблиць переходів.

## Народження ідеї двійкового перекриття: розріджена таблиця

Паралельно з розвитком деревних структур теоретики алгоритмів шукали прямий, безпосередній спосіб розв'язання RMQ на масивах чисел без переходу до складних дерев. 

Ключова ідея, яка лягла в основу **таблиці розрідження (Sparse Table)**, полягала у поєднанні двох концепцій:
1. **Двійкове масштабування інтервалів:** замість збереження відповідей для всіх `O(N^2)` можливих відрізків зберігати інформацію лише для відрізків, довжина яких є точною степеню двійки `2^j`. Це скоротило кількість збережених станів з `O(N^2)` до `O(N log N)`.
2. **Алгебраїчна ідемпотентність:** спостереження, що для операцій типу `min(a, b)` чи `max(a, b)` повторне врахування однакових елементів не змінює результату: `min(x, x) = x`. Отже, довільний відрізок `[L, R]` не обов'язково розбивати на диз'юнктні (неперетинні) частини — його достатньо накрити **двома блоками однакової довжини степеня двійки**, які перекриваються посередині.

Цей концептуальний стрибок дозволив позбутися потреби в рекурсивних спусках або логарифмічних циклах під час відповіді на запит. Якщо для неідемпотентних операцій (як-от обчислення суми в префіксному дереві) потрібне суворе диз'юнктне розбиття, то для RMQ два звернення до масиву `ST[k][L]` та `ST[k][R - 2^k + 1]` давали точну відповідь за один такт процесора `O(1)`.

Термін «розріджена таблиця» (англ. *sparse table*) закріпився за цією структурою завдяки тому, що у двовимірній матриці станів розглядаються не всі можливі довжини підмасивів `1, 2, 3, 4, ..., N`, а лише експоненційно розріджений набір довжин `2^0, 2^1, 2^2, ..., 2^k`.

## Спрощення Бендера та Фарах-Колтона: перетворення RMQ на ±1 RMQ (2000 рік)

Попри простоту розрідженої таблиці, теоретиків продовжувала хвилювати наявність логарифмічного множника `O(N log N)` у часі побудови та обсязі оперативної пам'яті. У 1993 році Омер Беркман (Omer Berkman) та Узі Вішкін (Uzi Vishkin) запропонували модель із рекурсивним трирівневим розбиттям масиву на блоки, яка досягала складності `<O(N), O(1)>` (лінійна побудова і константний запит), проте залишалася вкрай важкою для практичного програмування через надмірну кількість допоміжних структур.

Справжній переворот у сприйнятті алгоритмів RMQ відбувся у 2000 році, коли Майкл Бендер (Michael A. Bender) та Мартін Фарах-Колтон (Martin Farach-Colton) опублікували статтю *«The LCA Problem Revisited»*.

Вони запропонували витончений і практичний метод зведення загальної задачі LCA до спеціального випадку RMQ, названого **±1 RMQ**:
1. Дерево обходиться ейлеровим обходом (Euler Tour), записуючи глибину кожного відвіданого вузла.
2. Сусідні елементи в отриманому масиві глибин завжди відрізняються рівно на `+1` або `-1` (оскільки кожен крок обходу або спускається на один рівень глибше, або піднімається до предка).
3. Масив розбивається на мікроізольовані блоки розміру `B = (1/2) · log₂ N`.
4. Між блоками будується стандартна **Sparse Table** над мінімумами блоків. Оскільки кількість блоків дорівнює `N / B = 2N / log₂ N`, сама розріджена таблиця займає `O((N / log N) · log(N / log N)) = O(N)` слів пам'яті та будується за строго лінійний час `O(N)`.
5. Усередині кожного блоку відносний профіль висот визначається послідовністю різниць `+1` та `-1`. Застосовуючи класичний метод чотирьох росіян (Method of Four Russians), кожна можлива конфігурація з `B - 1` кроків кодується бітовою маскою. Оскільки довжина маски не перевищує `(1/2) · log₂ N - 1`, існує не більше ніж `2^(B-1) = 2^((1/2) log₂ N) = √N` унікальних типів блоків.
6. Для кожного з `√N` типів блоків усі можливі запити усередині блоку (яких є не більше `B^2 = O(log^2 N)`) передраховуються в окрему таблицю за час `O(√N · log^2 N) = o(N)`.

Завдяки цьому алгоритм Бендера — Фарах-Колтона вперше досяг теоретичного оптимуму `<O(N), O(1)>` без гігантських прихованих констант, а розріджена таблиця стала його ключовим макрорівневим скелетом.

## Декартове дерево та алгоритм Фішера — Гойна (2006 рік)

У 2006 році Йоганнес Фішер (Johannes Fischer) та Фолькер Гойн (Volker Heun) усунули останню перешкоду — необхідність переходу через суфіксні дерева для довільних масивів. Вони довели фундаментальну теорему про ізоморфізм між задачею RMQ на довільному масиві та декартовим деревом (Cartesian Tree).

Декартове дерево будується над довільним масивом чисел `A` за лінійний час `O(N)` за допомогою монотонного стека:
- Коренем піддерева стає мінімальний елемент відрізка.
- Його лівим сином є декартове дерево для лівого префікса масиву.
- Правим сином — декартове дерево для правого суфікса.

Фішер і Гойн показали, що запит `RMQ(L, R)` на початковому числовому масиві `A` еквівалентний знаходженню найменшого спільного предка `LCA(L, R)` у побудованому декартовому дереві. Виконавши ейлеровий обхід декартового дерева, вони отримали масив глибин із властивістю `±1`, до якого безпосередньо застосовується алгоритм Бендера — Фарах-Колтона. Це дало універсальний метод розв'язання загальної задачі RMQ на довільних числових масивах за лінійний час побудови `O(N)` і строго константний час запиту `O(1)`.

## Роль у біоінформатиці та суфіксних масивах

Окремою віхою в історії розріджених таблиць стало впровадження суфіксного масиву (Suffix Array) Уді Манбером (Udi Manber) та Джином Майєрсом (Gene Myers) у 1990 році. Для повнотекстового пошуку закономірностей у геномах розміром у гігабайти суфіксні дерева вимагали занадто багато пам'яті (до 20–40 байтів на символ). Суфіксний масив у комбінації з масивом довжин найдовших спільних префіксів (LCP, Longest Common Prefix) скоротив витрати пам'яті у рази.

Проте швидкий пошук LCP між двома довільними суфіксами `SA[i]` та `SA[j]` вимагав знаходження мінімального елемента в підмасиві `LCP[i+1 .. j]`. Саме побудова Sparse Table над масивом LCP дозволила відповідати на запити порівняння двох довільних підрядків за час `O(1)`. Це перетворило суфіксні масиви на основний інструмент біоінформатичного аналізу та повнотекстових індексів пошукових систем (Lucene, Sphinx, Elasticsearch).

## Практична еволюція: чому класична Sparse Table виграла у гібридів

Попри математичну досконалість гібридних алгоритмів `<O(N), O(1)>`, у реальному інженерному коді сталася неочікувана річ: більшість практиків і авторів бібліотек продовжують віддавати перевагу класичній **Sparse Table** із пам'яттю `O(N log N)`.

Причини цієї перемоги криються в архітектурі сучасного кремнію:
1. **Простота індексного доступу:** У класичній Sparse Table адресація клітинки `ST[k][i]` зводиться до найпростішого зсуву вказівника у плоскому двовимірному масиві. Вона не вимагає визначення маски блоку, непрямого звернення до таблиці типів блоків та комбінування внутрішньоблокових і міжблокових відповідей.
2. **Апаратна підтримка бітових інструкцій:** З появою інструкцій x86 `BSR` (Bit Scan Reverse), `LZCNT` (Leading Zero Count) та команд архітектури ARM `CLZ` (Count Leading Zeros) обчислення двійкового логарифма `k = 31 - __builtin_clz(R - L + 1)` стало виконуватися апаратно за рівно 1 такт центрального процесора.
3. **Передбачуваність для кешу та конвеєра:** Константний запит класичної Sparse Table виконує лише два незалежні читання з масиву `ST[k][L]` та `ST[k][R - (1 << k) + 1]`. Вони потрапляють в одну або дві сусідні кеш-лінії, що усуває промахи кешу (cache misses) та дозволяє суперскалярному конвеєру виконувати обидва зчитування паралельно.
4. **Помірні обсяги сучасних даних:** Для масиву з 1 000 000 32-бітних цілих чисел (`N = 10^6`) висота таблиці становить `log₂ N ≈ 20`. Повний обсяг таблиці розрідження складає лише `20 · 4 МБ ≈ 80 МБ`, що легко поміщається в оперативну пам'ять навіть бюджетних вбудованих контролерів і серверів.

Таким чином, розріджена таблиця пройшла шлях від теоретичного інструменту оптимізації деревних обходів до стандарту де-факто для статичних аналітичних запитів, поєднуючи математичну елегантність із максимальною ефективністю на рівні машинного коду.
