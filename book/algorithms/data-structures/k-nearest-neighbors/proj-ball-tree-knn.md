# ⚙️ Побудова та точний k-NN пошук у Ball Tree

Дерево сферичних оболонок (Ball Tree) розв'язує задачу точного пошуку `k` найближчих сусідів (k-NN) у багатовимірних та абстрактних метричних просторах, де координатні дерева (kd-дерева) страждають від кутових нахлестів прямокутних коробок або взагалі непридатні через відсутність ортогональних осей координат.

Тут наведено повну робочу реалізацію побудови збалансованого Ball Tree та алгоритму відсікання гілок (Branch and Bound) на основі нерівності трикутника з використанням черги з пріоритетом (Max-Heap) мовами C та C++, детальний аналіз евристик вибору півотів, покрокове трасування обходу, розбір узагальнених метрик без координат, оптимізацію розміру листків, інструментування профілювання, нуль-копійну серіалізацію через `mmap`, модифікацію для радіусного пошуку, обробку вироджених збігів точок, аналіз пам'яті вузлів та апаратні оптимізації для високонавантажених систем.

### Постановка задачі та математичні інваріанти

Дано множину з `N` точок `P = {p_1, p_2, ..., p_N}` у `d`-вимірному просторі або довільному метричному просторі `(X, d)`. Для довільної точки запиту `q` необхідно знайти підмножину `K ⊂ P` потужністю `|K| = k`, таку що для будь-якої точки `u ∈ K` та будь-якої точки `v ∈ P \ K` виконується нерівність:

```
d(q, u) ≤ d(q, v)
```

Головна мета структури даних — мінімізувати кількість викликів функції обчислення евклідової відстані `d(a, b)`, оскільки кожне таке обчислення у багатовимірному просторі коштує `d` операцій множення та додавання.

#### Інваріанти вузла Ball Tree

Кожен вузол дерева представляє непорожню підмножину точок `S ⊆ P` і зберігає два обов'язкові геометричні атрибути:
1. **Просторовий центр `c ∈ ℝ^d`** — центроїд підмножини точок:

```
c = (1 / |S|) · ∑_{p ∈ S} p
```

2. **Радіус сферичної оболонки `R ≥ 0`** — точна верхня межа відстані від центру до будь-якої точки підмножини:

```
R = max_{p ∈ S} d(c, p)
```

Завдяки цьому для будь-якої точки `p ∈ S` гарантовано виконується включення у замкнену метричну кулю: `p ∈ B(c, R) = { x ∈ ℝ^d | d(c, x) ≤ R }`.

У довільному метричному просторі, де вектори не мають координат (наприклад, відстань Левенштейна між рядками або відстань Жаккара між множинами), центр `c` обирають як **медоїд** (англ. *medoid*) — точку з самої підмножини `S`, яка мінімізує максимальну або сумарну відстань до решти точок:

```
c = argmin_{m ∈ S} max_{p ∈ S} d(m, p)
```

Це робить Ball Tree універсальною структурою даних для будь-якого метричного простору, на відміну від kd-дерева, яке принципово вимагає існування координатних осей.

### Алгоритм побудови: Евристика Гонсалеса та проекційне розбиття

Форма дерева та ефективність майбутніх відсікань критично залежать від того, як саме множина точок розбивається на дві дочірні підмножини. Якщо кулі дочірніх вузлів сильно перекриваються, алгоритм пошуку буде змушений відвідувати обидві гілки.

Для мінімізації об'єму та перекриття куль використовують проекційне розбиття за віссю найбільшої варіації:

1. **Пошук головної геометричної осі (Евристика найвіддаленішої точки Гонсалеса):**
   - Обирається довільна початкова точка вибірки (наприклад, точка з індексом 0).
   - Знаходиться точка `A ∈ S`, яка має максимальну відстань від початкової точки. Точка `A` гарантовано лежить на зовнішній межі просторового кластера.
   - Від точки `A` знаходиться найвіддаленіша точка `B ∈ S`. Відрізок `AB` є наближенням головного діаметра множини `S` (вектора максимальної дисперсії).

2. **Розподіл точок за двома центрами:**
   - Для кожної точки `p ∈ S` обчислюються дві відстані: `d(p, A)` та `d(p, B)`.
   - Точка відноситься до лівої підмножини `S_left`, якщо `d(p, A) ≤ d(p, B)`, і до правої `S_right` в іншому разі.
   - Геометрично цей поділ відповідає розрізанню простору гіперплощиною, яка проходить посередині відрізка `AB` і перпендикулярна до нього.

3. **Балансування дерева:**
   - Якщо одна з підмножин виявляється порожньою (наприклад, при збігу координат кількох точок), масив точок примусово ділиться навпіл за медіанним індексом.
   - Рекурсивний спуск зупиняється, коли розмір підмножини `|S| ≤ LEAF_CAPACITY` (зазвичай 4–16 точок).

```c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <stdbool.h>
#include <string.h>

#define DIM 3
#define LEAF_CAPACITY 2

typedef struct {
    double coords[DIM];
    int id;
} Point;

typedef struct {
    Point point;
    double dist;
} Neighbor;

/* Обмежена максимальна купа (Max-Heap) для збереження k найближчих кандидатів */
typedef struct {
    Neighbor *data;
    int size;
    int capacity;
} MaxHeap;

static void heap_init(MaxHeap *h, int capacity) {
    h->data = (Neighbor *)malloc(sizeof(Neighbor) * (capacity + 1));
    h->size = 0;
    h->capacity = capacity;
}

static void heap_free(MaxHeap *h) {
    free(h->data);
}

static void heap_swap(Neighbor *a, Neighbor *b) {
    Neighbor tmp = *a;
    *a = *b;
    *b = tmp;
}

static void heap_push(MaxHeap *h, Point pt, double dist) {
    if (h->size < h->capacity) {
        int i = ++h->size;
        h->data[i].point = pt;
        h->data[i].dist = dist;
        while (i > 1 && h->data[i].dist > h->data[i / 2].dist) {
            heap_swap(&h->data[i], &h->data[i / 2]);
            i /= 2;
        }
    } else if (dist < h->data[1].dist) {
        h->data[1].point = pt;
        h->data[1].dist = dist;
        int i = 1;
        while (2 * i <= h->size) {
            int child = 2 * i;
            if (child + 1 <= h->size && h->data[child + 1].dist > h->data[child].dist) {
                child++;
            }
            if (h->data[i].dist >= h->data[child].dist) break;
            heap_swap(&h->data[i], &h->data[child]);
            i = child;
        }
    }
}

static double heap_max_dist(const MaxHeap *h) {
    return (h->size < h->capacity) ? INFINITY : h->data[1].dist;
}

/* Евклідова відстань між точками */
static double distance(const Point *a, const Point *b) {
    double sum = 0.0;
    for (int i = 0; i < DIM; ++i) {
        double diff = a->coords[i] - b->coords[i];
        sum += diff * diff;
    }
    return sqrt(sum);
}

/* Структура вузла Ball Tree */
typedef struct BallNode {
    Point center;
    double radius;
    struct BallNode *left;
    struct BallNode *right;
    Point *points;
    int num_points;
    bool is_leaf;
} BallNode;

/* Обчислення центроїда та радіуса сферичної оболонки */
static void compute_bounding_ball(BallNode *node, Point *pts, int n) {
    for (int d = 0; d < DIM; ++d) {
        double sum = 0.0;
        for (int i = 0; i < n; ++i) {
            sum += pts[i].coords[d];
        }
        node->center.coords[d] = sum / n;
    }
    node->center.id = -1;

    double max_r = 0.0;
    for (int i = 0; i < n; ++i) {
        double d = distance(&node->center, &pts[i]);
        if (d > max_r) max_r = d;
    }
    node->radius = max_r;
}

/* Побудова Ball Tree */
BallNode *ball_tree_build(Point *pts, int n) {
    if (n <= 0) return NULL;

    BallNode *node = (BallNode *)calloc(1, sizeof(BallNode));
    compute_bounding_ball(node, pts, n);

    if (n <= LEAF_CAPACITY) {
        node->is_leaf = true;
        node->num_points = n;
        node->points = (Point *)malloc(sizeof(Point) * n);
        memcpy(node->points, pts, sizeof(Point) * n);
        return node;
    }

    /* Знаходження двох найвіддаленіших опорних точок (півотів) A та B */
    int pivot_a = 0;
    double max_d = -1.0;
    for (int i = 1; i < n; ++i) {
        double d = distance(&pts[0], &pts[i]);
        if (d > max_d) { max_d = d; pivot_a = i; }
    }

    int pivot_b = pivot_a;
    max_d = -1.0;
    for (int i = 0; i < n; ++i) {
        double d = distance(&pts[pivot_a], &pts[i]);
        if (d > max_d) { max_d = d; pivot_b = i; }
    }

    /* Розбиття точок: ближчі до A йдуть ліворуч, ближчі до B — праворуч */
    int left_count = 0;
    Point *temp = (Point *)malloc(sizeof(Point) * n);
    int l_idx = 0, r_idx = n - 1;

    for (int i = 0; i < n; ++i) {
        double da = distance(&pts[i], &pts[pivot_a]);
        double db = distance(&pts[i], &pts[pivot_b]);
        if (da <= db) {
            temp[l_idx++] = pts[i];
            left_count++;
        } else {
            temp[r_idx--] = pts[i];
        }
    }

    /* Запобігання виродженому розбиттю, якщо всі точки збігаються */
    if (left_count == 0 || left_count == n) {
        left_count = n / 2;
    }

    node->left = ball_tree_build(temp, left_count);
    node->right = ball_tree_build(temp + left_count, n - left_count);
    free(temp);

    return node;
}

/* Рекурсивний пошук k-NN з відсіканням гілок за нерівністю трикутника */
void ball_tree_knn(const BallNode *node, const Point *query, MaxHeap *heap) {
    if (!node) return;

    double d_center = distance(query, &node->center);
    double d_min = d_center - node->radius;
    if (d_min < 0.0) d_min = 0.0;

    /* Відсікання гілки: якщо навіть найближчий край кулі далі за k-го сусіда */
    if (d_min >= heap_max_dist(heap)) {
        return;
    }

    if (node->is_leaf) {
        for (int i = 0; i < node->num_points; ++i) {
            double d = distance(query, &node->points[i]);
            heap_push(heap, node->points[i], d);
        }
        return;
    }

    /* Вибір пріоритетного піддерева (спуск у ближчу кулю) */
    double d_left = node->left ? distance(query, &node->left->center) : INFINITY;
    double d_right = node->right ? distance(query, &node->right->center) : INFINITY;

    if (d_left < d_right) {
        ball_tree_knn(node->left, query, heap);
        ball_tree_knn(node->right, query, heap);
    } else {
        ball_tree_knn(node->right, query, heap);
        ball_tree_knn(node->left, query, heap);
    }
}

void ball_tree_free(BallNode *node) {
    if (!node) return;
    if (node->is_leaf) {
        free(node->points);
    } else {
        ball_tree_free(node->left);
        ball_tree_free(node->right);
    }
    free(node);
}

int main(void) {
    Point pts[] = {
        {{1.0, 2.0, 3.0}, 1},
        {{1.1, 2.1, 2.9}, 2},
        {{5.0, 6.0, 7.0}, 3},
        {{5.2, 5.9, 7.1}, 4},
        {{8.0, 9.0, 1.0}, 5},
        {{1.2, 1.9, 3.1}, 6},
        {{5.1, 6.2, 6.8}, 7}
    };
    int n = sizeof(pts) / sizeof(pts[0]);
    int k = 3;

    BallNode *root = ball_tree_build(pts, n);

    Point query = {{1.05, 2.05, 3.0}, 0};
    MaxHeap heap;
    heap_init(&heap, k);

    ball_tree_knn(root, &query, &heap);

    printf("Результати точного 3-NN пошуку для запиту (1.05, 2.05, 3.0):\n");
    for (int i = 1; i <= heap.size; ++i) {
        printf("  Сусід ID=%d, coords=(%.1f, %.1f, %.1f), dist=%.4f\n",
               heap.data[i].point.id,
               heap.data[i].point.coords[0],
               heap.data[i].point.coords[1],
               heap.data[i].point.coords[2],
               heap.data[i].dist);
    }

    heap_free(&heap);
    ball_tree_free(root);
    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <memory>
#include <queue>
#include <numeric>
#include <algorithm>
#include <span>
#include <limits>
#include <array>

template <size_t Dim = 3>
struct Point {
    std::array<double, Dim> coords{};
    int id{-1};

    [[nodiscard]] double distance_to(const Point& other) const noexcept {
        double sum = 0.0;
        for (size_t i = 0; i < Dim; ++i) {
            const double diff = coords[i] - other.coords[i];
            sum += diff * diff;
        }
        return std::sqrt(sum);
    }
};

struct Neighbor {
    int id;
    double dist;

    bool operator<(const Neighbor& other) const noexcept {
        return dist < other.dist; // Для max-heap: найбільша відстань нагорі
    }
};

template <size_t Dim = 3>
class BallTree {
public:
    static constexpr size_t LeafCapacity = 2;

    explicit BallTree(std::span<const Point<Dim>> points) {
        std::vector<Point<Dim>> pts(points.begin(), points.end());
        root_ = build(pts);
    }

    [[nodiscard]] std::vector<Neighbor> find_knn(const Point<Dim>& query, size_t k) const {
        std::priority_queue<Neighbor> max_heap;
        search(root_.get(), query, k, max_heap);

        std::vector<Neighbor> result;
        result.reserve(max_heap.size());
        while (!max_heap.empty()) {
            result.push_back(max_heap.top());
            max_heap.pop();
        }
        std::reverse(result.begin(), result.end()); // Від найближчого до найдальшого
        return result;
    }

private:
    struct Node {
        Point<Dim> center{};
        double radius{0.0};
        std::unique_ptr<Node> left;
        std::unique_ptr<Node> right;
        std::vector<Point<Dim>> leaf_points;
        bool is_leaf{false};
    };

    std::unique_ptr<Node> root_;

    static void compute_bounding_ball(Node& node, std::span<const Point<Dim>> pts) {
        std::array<double, Dim> sum{};
        for (const auto& p : pts) {
            for (size_t d = 0; d < Dim; ++d) {
                sum[d] += p.coords[d];
            }
        }
        for (size_t d = 0; d < Dim; ++d) {
            node.center.coords[d] = sum[d] / static_cast<double>(pts.size());
        }

        double max_r = 0.0;
        for (const auto& p : pts) {
            max_r = std::max(max_r, node.center.distance_to(p));
        }
        node.radius = max_r;
    }

    std::unique_ptr<Node> build(std::span<Point<Dim>> pts) {
        if (pts.empty()) return nullptr;

        auto node = std::make_unique<Node>();
        compute_bounding_ball(*node, pts);

        if (pts.size() <= LeafCapacity) {
            node->is_leaf = true;
            node->leaf_points.assign(pts.begin(), pts.end());
            return node;
        }

        // Пошук двох найвіддаленіших точок (півотів) A і B
        size_t pivot_a = 0;
        double max_d = -1.0;
        for (size_t i = 1; i < pts.size(); ++i) {
            if (double d = pts[0].distance_to(pts[i]); d > max_d) {
                max_d = d;
                pivot_a = i;
            }
        }

        size_t pivot_b = pivot_a;
        max_d = -1.0;
        for (size_t i = 0; i < pts.size(); ++i) {
            if (double d = pts[pivot_a].distance_to(pts[i]); d > max_d) {
                max_d = d;
                pivot_b = i;
            }
        }

        // Розбиття точок за відстанню до двох центрів
        const Point<Dim> pa = pts[pivot_a];
        const Point<Dim> pb = pts[pivot_b];

        auto mid = std::partition(pts.begin(), pts.end(), [&](const Point<Dim>& p) {
            return p.distance_to(pa) <= p.distance_to(pb);
        });

        size_t left_size = std::distance(pts.begin(), mid);
        if (left_size == 0 || left_size == pts.size()) {
            mid = pts.begin() + pts.size() / 2;
        }

        node->left = build(std::span<Point<Dim>>(pts.begin(), mid));
        node->right = build(std::span<Point<Dim>>(mid, pts.end()));

        return node;
    }

    void search(const Node* node, const Point<Dim>& query, size_t k,
                std::priority_queue<Neighbor>& heap) const {
        if (!node) return;

        const double d_center = query.distance_to(node->center);
        const double d_min = std::max(0.0, d_center - node->radius);

        const double current_max_dist = (heap.size() < k) ?
            std::numeric_limits<double>::infinity() : heap.top().dist;

        // Відсікання піддерева за нерівністю трикутника
        if (d_min >= current_max_dist) {
            return;
        }

        if (node->is_leaf) {
            for (const auto& pt : node->leaf_points) {
                const double d = query.distance_to(pt);
                if (heap.size() < k) {
                    heap.push(Neighbor{pt.id, d});
                } else if (d < heap.top().dist) {
                    heap.pop();
                    heap.push(Neighbor{pt.id, d});
                }
            }
            return;
        }

        // Пріоритетний спуск у ближчу сферу
        const double d_left = node->left ? query.distance_to(node->left->center) : std::numeric_limits<double>::infinity();
        const double d_right = node->right ? query.distance_to(node->right->center) : std::numeric_limits<double>::infinity();

        if (d_left < d_right) {
            search(node->left.get(), query, k, heap);
            search(node->right.get(), query, k, heap);
        } else {
            search(node->right.get(), query, k, heap);
            search(node->left.get(), query, k, heap);
        }
    }
};

int main() {
    std::vector<Point<3>> points = {
        {{{1.0, 2.0, 3.0}}, 1},
        {{{1.1, 2.1, 2.9}}, 2},
        {{{5.0, 6.0, 7.0}}, 3},
        {{{5.2, 5.9, 7.1}}, 4},
        {{{8.0, 9.0, 1.0}}, 5},
        {{{1.2, 1.9, 3.1}}, 6},
        {{{5.1, 6.2, 6.8}}, 7}
    };

    BallTree<3> tree(points);
    Point<3> query{{{1.05, 2.05, 3.0}}, 0};

    auto neighbors = tree.find_knn(query, 3);

    std::cout << "Результати точного 3-NN пошуку (C++):\n";
    for (const auto& n : neighbors) {
        std::cout << "  Сусід ID=" << n.id << ", dist=" << n.dist << "\n";
    }

    return 0;
}
```

### Покрокове трасування пошуку 3-NN

Розглянемо покроковий рух алгоритму на тестовій вибірці з 7 точок при пошуку `k = 3` найближчих сусідів для точки запиту `q = (1.05, 2.05, 3.0)`:

```
[Початковий стан]
Heap: порожня (size = 0, capacity = 3).
Радіус відсікання: r_max = +∞.

[Крок 1: Корінь дерева (Node 0, охоплює всі 7 точок)]
Центр c_root = (3.8, 4.3, 4.4), Радіус R_root = 5.2.
Відстань d(q, c_root) = 4.15.
d_min = max(0, 4.15 − 5.2) = 0.0 < +∞  →  Корінь не відсікається.
Обчислення відстаней до нащадків:
  d(q, c_left)  = 0.12 (кластер навколо (1, 2, 3))
  d(q, c_right) = 6.45 (кластер навколо (5, 6, 7))
Рішення: d_left < d_right → спершу спускаємося в ліву гілку.

[Крок 2: Лівий вузол (Node 1, точки ID 1, 2, 6)]
```

### Детальний аналіз реалізації Max-Heap проти Insertion Sort

Під час розробки алгоритму k-NN виникає парадоксальне питання: чому для збереження `k` **найменших** відстаней використовується саме **максимальна купа** (Max-Heap), а не мінімальна (Min-Heap)?

1. **Принцип роботи Max-Heap для k-NN:**
   - Нам потрібно знати поточну найбільшу відстань серед `k` найкращих кандидатів, щоб використовувати її як поріг відсікання `r_max`.
   - У максимальній купі елемент із максимальною відстанлю завжди знаходиться на вершині (в корені масиву за індексом 1). Зчитування порогу `heap_max_dist()` відбувається за час `O(1)`.
   - Коли з'являється нова точка з відстанлю `d_new < r_max`, ми виштовхуємо старий найгірший елемент із кореня і просіюємо нову точку вниз за час `O(log k)`.

2. **Альтернатива для малих `k` (Linear Insertion Array):**
   - Якщо `k ≤ 10` (типовий випадок для семантичного пошуку топ-5 чи топ-10 документів), купа на основі масиву дає додаткові накладні витрати на обчислення індексів нащадків `2*i` та умовні переходи просіювання.
   - Простий статичний масив розміром `k`, впорядкований за зростанням відстані, оновлюється звичайним лінійним зсувом (Insertion Sort). Для `k = 5` це займає всього 4–5 тактів процесора і повністю розгортається компілятором у скалярні регістри без звернень до динамічної пам'яті.

### Порівняння евристик розбиття

Якість структури Ball Tree повністю визначається тим, наскільки компактними та ізольованими виходять дочірні сферичні оболонки:

1. **Евристика 2-середніх (2-means split):**
   Випадковим чином обираються два центри, точки розбиваються на два кластери, центри перераховуються, і процедура повторюється 3–5 ітерацій. Цей метод мінімізує сумарну дисперсію, але додає значні накладні витрати на етапі індексації (`O(I · N · d)`).

2. **Метод найвіддаленіших точок (Furthest-Point Gonzalez Heuristic):**
   Реалізований у нашому коді підхід знаходить діаметрально протилежні точки кластера за два проходи `O(N · d)`. Він будує розділову гіперплощину вздовж напрямку найбільшої дисперсії, що практично еквівалентно першій головній компоненті (PCA, англ. *Principal Component Analysis*), але без необхідності обчислення коваріаційної матриці `d × d` та знаходження її власних векторів.

3. **Розбиття за медоїдами (K-Medoids):**
   У метриках без евклідових координат (наприклад, графові найкоротші шляхи чи відстані редагування) центри не можна усереднювати. Медоїд обирається як реальний об'єкт вибірки. Хоча побудова стає повільнішою (`O(N²)` для кожного вузла без оптимізацій), дерево зберігає строгі властивості відсікання.

### Точна сфера Вельцля проти центроїдної сфери

Під час обчислення сферичної оболонки `B(c, R)` для підмножини точок `S` існує два принципово різних підходи:

1. **Центроїдна сфера (Bounding Sphere via Centroid):**
   Центр `c` обчислюється як середнє арифметичне координат `c = (1/|S|) ∑ p_i`, а радіус `R = max ||c − p_i||`. Це вимагає всього одного проходу по точках (`O(|S| · d)`), але радіус може виявитися на 15–30% більшим за мінімально можливий через наявність асиметричних викидів.

2. **Мінімальна охоплювальна куля Вельцля (Welzl's Minimum Enclosing Ball):**
   Рандомізований рекурсивний алгоритм Емо Вельцля (1991) знаходить строго мінімальну сферу за очікуваний лінійний час `O(|S|)`. Проте при кожному оновленні опорної множини (до `d + 1` точок) алгоритм Вельцля розв'язує систему лінійних алгебраїчних рівнянь, що у високих вимірностях (`d > 10`) сповільнює фазу побудови індексу у 50–100 разів при мізерному виграші у відсіканні. Через це у практичних системах завжди застосовують центроїдну сферу.

### Модифікація для радіусного пошуку (Range Search)

Крім класичного пошуку фіксованої кількості сусідів `k`, Ball Tree ідеально підходить для радіусного пошуку: знайти всі точки, відстань до яких від `q` не перевищує заданого радіуса `r_fixed`.

Алгоритмічні відмінності від k-NN:
1. **Статичний радіус відсікання:** Порогове значення `r_fixed` є незмінною константою протягом усього обходу.
2. **Відсікання піддерева:** Якщо `d_min(q, B) = max(0, d(q, c) − R) > r_fixed`, піддерево відкидається.
3. **Безумовне включення цілого піддерева:** Якщо `d_max(q, B) = d(q, c) + R ≤ r_fixed`, то **всі** точки цього піддерева гарантовано лежать всередині радіуса пошуку. Алгоритм копіює всі точки піддерева у вихідний вектор гуртом за один системний виклик `memcpy`, не виконуючи жодних обчислень міжточкових відстаней!

### Оптимізація розміру листка та глибини дерева

Параметр місткості листка (`LEAF_CAPACITY`) безпосередньо визначає баланс між кількістю переходів по графу дерева та швидкістю сканування точок:

- **Випадок `LEAF_CAPACITY = 1`:** Дерево стає максимально глибоким (`h ≈ log₂ N`). Кількість внутрішніх вузлів дорівнює `N − 1`. Програма витрачає величезну кількість процесорних циклів на перевірку умов `d_min ≥ r_max` для кожного окремого елемента, розгортання рекурсивних кадрів та промахи передбачення переходів (Branch Mispredictions).
- **Випадок `LEAF_CAPACITY = 8..32`:** Дерево має помірну глибину (`h ≈ log₂(N / 16)`). Внутрішні вузли ефективно відсікають великі просторові кластери. Коли пошук доходить до листка, 16 точок скануються єдиним безперервним SIMD-циклом без умовних переходів. Векторні регістри процесора завантажують дані безпосередньо з кешу L1, забезпечуючи максимальну швидкість обчислень.

### Профілювання та діагностика відсікання

Для оцінки ефективності побудованого індексу в код пошуку вбудовують лічильники інструментування:

1. **Коефіцієнт просторового відсікання (Pruning Ratio):**
   Відношення кількості відкинутих точок до загального розміру бази даних:

```
Pruning_Ratio = 1 − ( Кількість_обчислених_відстаней / N )
```

2. **Залежність від розмірності даних:**
   - При розмірності `d = 2..4` дерево відсікає **98–99.5%** точок: пошук для `N = 10⁶` точок вимагає лише 2000–5000 обчислень відстані.
   - При розмірності `d = 10..15` коефіцієнт відсікання падає до **60–80%**: алгоритм перевіряє до третини всієї бази.
   - При розмірності `d > 25..30` коефіцієнт відсікання прямує до **0%**: дерево вироджується у повний перебір із додатковими накладними витратами на обхід дерева.

### Серіалізація та нуль-копійне відображення у пам'ять (mmap)

Для збереження збудованого Ball Tree у виробничих серверах дерево серіалізують у єдиний бінарний файл зі строгою бінарною структурою:
1. Заголовок (Header): магічне число `0x42414C4C` ("BALL"), версія формату, розмірність `DIM`, кількість точок `N`, кількість вузлів.
2. Масив вузлів фіксованого розміру `FlatNode[]`.
3. Неперервний масив вирівняних координат точок `Point[]`.

Під час запуску пошукового демона файл індексу відкривається через системний виклик `mmap(NULL, file_size, PROT_READ, MAP_SHARED, fd, 0)`. Це дозволяє запустити пошук миттєво (за 0.2 мілісекунди) без виділення динамічної пам'яті в купі (`malloc`) та без парсингу вказівників, а операційна система автоматично підкачує сторінки дерева з диска через механізм Page Cache.

### Апаратна оптимізація та типові пастки

1. **Несиметричний розрив при вироджених вибірках.** Якщо множина точок містить однакові або сильно згруповані дублікати, вибір півотів `A` та `B` може дати `da == db` для всіх точок. Функція `std::partition` або цикл C відправить усі точки в ліву гілку, спричинивши нескінченну рекурсію або переповнення стека. Код обов'язково перевіряє `left_size == 0 || left_size == n` і примусово розрізає масив навпіл за індексом.

2. **Зайвий розрахунок коренів `sqrt`.** Для порівняння відстаней між точками всередині листків достатньо порівнювати квадрати відстаней `sum (x_i - y_i)^2`. Однак для нерівності трикутника `d(q, c) - R` необхідна саме лінійна відстань `d`, тому центри та радіуси куль вимагають квадратного кореня.

3. **Оновлення радіуса пошуку `r_max`.** Радіус відсікання не є фіксованою константою — він динамічно зменшується з кожною точкою, що потрапляє в купу. Перевірка `d_min >= current_max_dist` повинна брати актуальне значення з вершини купи перед спуском у кожне піддерево.

4. **Кеш-локальність та плоске упаковане представлення (Flat Packed Layout).** У продакшн-бібліотеках (таких як scikit-learn або FLANN) Ball Tree розгортають у єдиний неперервний масив вузлів замість розрізнених покажчиків у купі. Точки сортуються так, що точки кожного листка утворюють неперервний діапазон у пам'яті, завдяки чому векторне ядро процесора завантажує їх у кеш L1/L2 без затримок пам'яті (DRAM stall). Вузол займає рівно 64 байти (розмір однієї лінії кешу x86-64), що мінімізує кількість звернень до шини пам'яті.

5. **Векторизація SIMD (AVX2 / AVX-512).** Обчислення евклідової відстані між запитом та точками листка є головним споживачем тактових циклів. Використання векторних інструкцій FMA (Fused Multiply-Add) дозволяє обробляти 8 чисел float32 (або 4 числа double) за один такт процесора, що дає 4–8-кратне прискорення перебору листків.

6. **Ітеративний обхід зі статичним стеком.** У вбудованих системах (Embedded) із суворим лімітом пам'яті рекурсивний виклик `ball_tree_knn` замінюють на явний масив-стек розміром `32..64` елементи. Оскільки глибина збалансованого дерева з мільйоном точок не перевищує `⌈log₂ 10⁶⌉ ≈ 20`, фіксованого буфера на 32 покажчики гарантовано вистачає для уникнення переповнення стека (Stack Overflow).

7. **Динамічне додавання точок та поріг перекосу.** При потоковому надходженні нових векторів перерахунок центроїдів і радіусів виконується знизу вгору по дереву. Для вибору гілки спуску обчислюється збільшення радіуса кулі `ΔR = max(0, d(c, p_new) − R)`. Точка вставляється у піддерево з мінімальним значенням `ΔR`. Якщо глибина однієї з гілок перевищує середню глибину більш ніж на 3 рівні, ініціюється фонова локальна перебудова відповідного піддерева.

8. **Паралелізація пакетного пошуку (Multi-threaded Batch Queries).** Оскільки дерево є незмінною (Read-Only) структурою під час фази виконання запитів, паралелізація батчу запитів реалізується без блокувань (Lock-Free). Кожен потік пулу обробляє окрему точку запиту, маючи власну локальну купу кандидатів. Це забезпечує лінійне прискорення продуктивності пропорційно кількості доступних процесорних ядер.

9. **Обробка вироджених збігів точок (Degenerate Coincident Points).** Якщо вибірка містить сотні дублікатів з ідентичними координатами, радіус кулі `R = 0`. Вибір півотів дає `max_d = 0`. Якщо не перевірити цей стан, поділ півотами не зможе розділити множину, що спричинить нескінченну рекурсію. Наша реалізація перевіряє `left_count == 0 || left_count == n` і примусово розбиває масив навпіл за медіаною індексів, що гарантує детерміноване завершення побудови за час `O(N log N)`.

10. **Пам'ять вузла та порівняння з kd-деревом.** На один вузол Ball Tree у тривимірному просторі `d = 3` з подвійною точністю (`double`): центр `3 · 8 = 24` байти, радіус `8` байтів, вказівники нащадків `16` байтів, прапорець листка та кількість точок `8` байтів. Загалом один вузол займає рівно 56 байтів (вирівнюється компілятором до 64 байтів під розмір лінії кешу процесора L1). Порівняно з kd-деревом, яке зберігає лише поріг та номер осі (12 байтів), вузол Ball Tree дещо важчий, проте забезпечує істотно вищий коефіцієнт просторового відсікання при `d ≥ 4` завдяки сферичній симетрії оболонок.
