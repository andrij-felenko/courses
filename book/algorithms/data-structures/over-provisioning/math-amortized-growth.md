# 🧮 Математика надлишкового виділення: амортизація, коефіцієнти росту та поріг φ

Операція динамічного розширення суцільного буфера, хеш-таблиці або вузлів дерев спирається на суворі математичні співвідношення між геометричним прогресуванням, коефіцієнтом заповнення, методом потенціалів та межами фрагментації пам'яті. Нижче наведено формальне математичне виведення фундаментальних властивостей надлишкового виділення пам'яті (Over-provisioning).

---

## 1. Доведення амортизованої сталості при геометричному рості

Розглянемо виділення динамічного масиву початковою місткістю `C₀ = 1` при доданні `N` елементів. Нехай при переповненні місткість множиться на сталий коефіцієнт росту `α > 1`.

Реалокації відбуваються на кроках, коли кількість елементів сягає значення `n = αᵏ` для `k = 0, 1, 2, ..., m`, де `m = ⌈log_α N⌉` — загальна кількість виконаних реалокацій.

 Обчислимо сумарну кількість копіювань елементів `S_copy` за всі `N` вставок:

```
S_copy = 1 + α + α² + α³ + ... + αᵐ⁻¹
       = (αᵐ − 1) / (α − 1)            [формула суми геометричної прогресії]
       < αᵐ / (α − 1)                  [верхня оцінка: відкидаємо −1 у чисельнику]
```

Оскільки останній розмір масиву перед `N`-ю вставкою `αᵐ⁻¹ < N`, то `αᵐ < α · N`. Підставимо цю оцінку в нерівність:

```
S_copy < (α / (α − 1)) · N             [заміна αᵐ на α·N]
```

Загальна вартість `T(N)` виконання `N` додатків складається з `N` простих записів (вартістю `1` кожен) та `S_copy` копіювань:

```
T(N) = N + S_copy
     < N + (α / (α − 1)) · N           [підстановка верхньої оцінки S_copy]
     = N · (1 + α / (α − 1))           [винесення N за дужки]
```

Розділивши загальну вартість `T(N)` на кількість операцій `N`, отримуємо середню амортизовану вартість однієї вставки `A_insert`:

```
A_insert = T(N) / N
         < 1 + α / (α − 1)             [ділення сумарної вартості на N]
         = (2α − 1) / (α − 1)          [зведення до спільного знаменника]
         = O(1)                        [константна верхня межа]
```

### Порівняльне значення для різних коефіцієнтів α:

- При `α = 2.0`: `A_insert < (2·2 − 1) / (2 − 1) = 3` операції на один `push_back`.
- При `α = 1.5`: `A_insert < (2·1.5 − 1) / (1.5 − 1) = 2 / 0.5 = 4` операції на один `push_back`.

Обидва значення є сталими величинами `O(1)`, які принципово не залежать від `N`.

## 2. Доведення за допомогою методу потенціалів (Lyapunov Function)

Агрегатний метод дає середню оцінку по всій послідовності, але не показує стан системи на кожному окремому кроці. Застосуємо **метод потенціалів** Роберта Тар'яна.

Введемо функцію потенціалу `Φ(Dᵢ)`, яка описує кількість накопиченого «кредиту» (або енергії) у стані буфера `Dᵢ` після `i`-ї операції.

Для масиву з коефіцієнтом розширення `α = 2.0`, поточною кількістю елементів `n` та місткістю `C` визначимо потенціал як:

```
Φ(D) = 2·n − C
```

Перевіримо властивості функції потенціалу:
1. **Початковий стан**: На початку `n = 0`, `C = 0`, тому `Φ(D₀) = 0`.
2. **Невід'ємність**: Оскільки масив розширюється при `n = C/2` (після попереднього розширення), то `n ≥ C/2`, звідки `2n ≥ C`, отже `Φ(D) ≥ 0` для всіх станів.

Розглянемо амортизовану вартість `aᵢ` операції `push_back`, яка обчислюється за формулою:

```
aᵢ = cᵢ + Φ(Dᵢ) − Φ(Dᵢ₋₁)
```

Де `cᵢ` — реальна вартість `i`-ї операції.

### Випадок А: Звичайний дешевий додаток (без реалокації)
* Реальна вартість `cᵢ = 1` (запис елемента).
* Кількість елементів зростає з `n − 1` до `n`, місткість `C` не змінюється.
* Зміна потенціалу: `ΔΦ = (2n − C) − (2(n − 1) − C) = 2`.
* Амортизована вартість:

```
aᵢ = 1 + 2 = 3 = O(1)
```

Дешевий додаток коштує реально 1, але ми забираємо амортизовану плату 3. Надлишок у 2 монети осідає у потенціалі `Φ`.

### Випадок Б: Дорогий додаток із реалокацією (при n − 1 = C)
* Реальна вартість `cᵢ = (n − 1) + 1 = n` (копіювання `n − 1` елементів плюс запис нового).
* Місткість зростає з `C` до `2C` (де `C = n − 1`).
* Потенціал до реалокації: `Φ(Dᵢ₋₁) = 2(n − 1) − (n − 1) = n − 1`.
* Потенціал після реалокації: `Φ(Dᵢ) = 2n − 2C = 2n − 2(n − 1) = 2`.
* Зміна потенціалу: `ΔΦ = Φ(Dᵢ) − Φ(Dᵢ₋₁) = 2 − (n − 1) = 3 − n`.
* Амортизована вартість:

```
aᵢ = cᵢ + ΔΦ = n + (3 − n) = 3 = O(1)
```

Падіння потенціалу на `n - 3` повністю оплачує важке копіювання `n` елементів! В обох випадках амортизована вартість строго дорівнює **3**, що доводить сталість `O(1)` для будь-якого кроку.

## 3. Недоліки лінійного розширення: квадратичний колапс

Якщо замість множника `α` використовувати додавання фіксованого кроку `K` (лінійне розширення `Cₖ = C₀ + k·K`), реалокації відбуваються через кожні `K` вставок.

Обчислимо сумарну кількість копіювань для `N` вставок (де `m = N / K` — кількість реалокацій):

```
S_linear = K + 2K + 3K + ... + m·K
         = K · (1 + 2 + 3 + ... + m)             [винесення кроку K за дужки]
         = K · (m · (m + 1) / 2)                [сума арифметичної прогресії]
         = K · ((N / K) · (N / K + 1) / 2)      [підстановка m = N / K]
         = (N² / (2K)) + (N / 2)                [раскриття дужок]
         = O(N²)                                [головний член квадратичного зростання]
```

Середня вартість однієї вставки при лінійному розширенні:

```
A_linear = S_linear / N
         = (N / (2K)) + 1/2                     [ділення сумарних копіювань на N]
         = O(N)                                 [лінійна складність на одну операцію]
```

Таким чином, лінійне розширення руйнує продуктивність, роблячи середній `push_back` лінійним від загального розміру масиву.

## 4. Теорема про перевикористання пам'яті та золотий перетин φ

Під час реалокації масив із початкового блоку розміру `Cₖ` копіюється в новий блок розміру `Cₖ₊₁ = α · Cₖ`, а старий блок розміру `Cₖ` звільняється й повертається в системну купу.

Щоб системний алокатор (buddy allocator або free-list allocator) зміг виділити новий блок розміру `Cₖ₊₁` із раніше звільнених блоків того самого контейнера, сума розмірів усіх раніше звільнених блоків повинна бути не меншою за новий розмір запиту.

Обчислимо суму розмірів усіх попередньо звільнених блоків після `k` кроків:

```
S_freed = C₀ + C₁ + C₂ + ... + Cₖ₋₂
        = 1 + α + α² + ... + αᵏ⁻²                 [підстановка Cᵢ = αⁱ]
        = (αᵏ⁻¹ − 1) / (α − 1)                    [сума геометричної прогресії]
```

Умова перевикористання пам'яті полягає в тому, що `S_freed ≥ Cₖ = αᵏ`:

```
(αᵏ⁻¹ − 1) / (α − 1) ≥ αᵏ                         [умова покриття нового запиту]
1 / (α − 1) ≥ α                                   [ділення обидвох частин на αᵏ⁻¹ при великих k]
1 ≥ α · (α − 1)                                   [множення на (α - 1)]
1 ≥ α² − α                                        [раскриття дужок]
α² − α − 1 ≤ 0                                    [зведення до квадратного нерівняння]
```

Знайдемо корінь квадратного рівняння `α² − α − 1 = 0`:

```
D = (−1)² − 4·(1)·(−1) = 1 + 4 = 5                [дискримінант]
α = (1 + √5) / 2 = φ ≈ 1.618033...                [додатний корінь рівняння]
```

### Висновок:
- Якщо `α > φ ≈ 1.618` (зокрема при `α = 2.0`), сума всіх раніше звільнених блоків *завжди* менша за новий розмір. Алокатор змушений щоразу виділяти пам'ять на новій межі купи (heap boundary), збільшуючи адресний простір програми.
- Якщо `α ≤ φ ≈ 1.618` (зокрема при `α = 1.5`), сума раніше звільнених блоків згодом перевищує розмір наступного запиту, що дозволяє перевикористати фрагменти пам'яті й зупинити ріст адресного простору.

## 5. Математика коефіцієнта заповнення у хеш-таблицях

У хеш-таблицях із відкритою адресацією (Open Addressing) та лінійним пробуванням (Linear Probing) коефіцієнт заповнення виражається відношенням кількості елементів `N` до місткості таблиці `M`:

```
α_load = N / M
```

Згідно з математичним аналізом Дональда Кнута, математичне сподівання кількості проб `E[probes]` для успішного пошуку елемента виражається формулою:

```
E[unsuccessful_search] ≈ (1 / 2) · (1 + 1 / (1 − α_load)²)
E[successful_search]   ≈ (1 / 2) · (1 + 1 / (1 − α_load))
```

Розглянемо зростання кількості проб при наближенні `α_load` до `1`:

| Коефіцієнт `α_load` | Неуспішний пошук `E[unsuccessful]` | Успішний пошук `E[successful]` |
| :--- | :--- | :--- |
| **0.50** (50% надлишок) | 2.50 проб | 1.50 проб |
| **0.70** (30% надлишок) | 6.05 проб | 2.16 проб |
| **0.80** (20% надлишок) | 13.00 проб | 3.00 проб |
| **0.90** (10% надлишок) | 50.50 проб | 5.50 проб |
| **0.99** (1% надлишок)  | 5000.50 проб | 50.50 проб |

Асимптотичний поріг `1 / (1 − α_load)` демонструє гіперболічний вибух затримок при `α_load > 0.75`. Це доводить необхідність виділення надлишкових бакетів (надлишок 30–50%) для забезпечення `O(1)` швидкодії.

## 6. Функція втрати пам'яті (Slack Space Function)

Надлишкове виділення викликає внутрішню фрагментацію — наявність невикористаних комірок. Нехай `N` — поточна кількість елементів у динамічному масиву з місткістю `C = αᵐ`.

Середній коефіцієнт втрати пам'яті `W(α)` виражається як відношення невільних комірок до виділених при випадковому розмірі `N ∈ [C/α, C]`:

```
W(α) = 1 − (1 / ln(α)) · ∫_{1/α}^{1} x dx 
     = 1 − (1 / (2 · ln(α))) · (1 − 1/α²)
```

Для масивів із ростом `α = 2.0`:
```
W(2.0) = 1 − (1 / (2 · 0.693)) · (1 − 0.25) = 1 − 0.721 / 0.693 ≈ 0.38 (38% середньої надлишкової пам'яті)
```

Для масивів із ростом `α = 1.5`:
```
W(1.5) = 1 − (1 / (2 · 0.405)) · (1 − 0.444) = 1 − 0.556 / 0.810 ≈ 0.31 (31% середньої надлишкової пам'яті)
```

Зменшення коефіцієнта росту з `2.0` до `1.5` зменшує середню втрату оперативної пам'яті з 38% до 31%, одночасно забезпечуючи умову перевикористання блоків алокатором.
