# 📋 Довідник системного інтерфейсу керування місткістю та резервуванням пам'яті

Цей довідник містить детальний опис контрактів, функцій, структур та параметрів системного рівня, що регулюють надлишкове виділення пам'яті (Over-provisioning) у мовах програмування C та C++. Описані інтерфейси є стандартизованою поверхнею взаємодії розробника з оперативною пам'яттю, куповими алокаторами (Heap Allocators) та середовищем виконання операційної системи.

---

## 1. Системний інтерфейс C та C++ для керування купою

У мові C керування оперативною пам'яттю здійснюється за допомогою функцій стандартної бібліотеки CRT (C Runtime). Оскільки мова C не має системних типів для об'єктних контейнерів, розробник мусить вручну підтримувати пару змінних «розмір-місткість» (`size` та `capacity`) для кожного динамічного масиву. У C++ керування пам'яттю спирається на RAII, оператори `new`/`delete` та алокатори.

### Базові сигнатури функцій виділення та зміни розміру

:::tabs
```c
#include <stdlib.h>

void *malloc(size_t size);
void *calloc(size_t num, size_t size);
void *realloc(void *ptr, size_t new_size);
void free(void *ptr);
```
```cpp
#include <memory>
#include <new>

// У C++ виділення та керування пам'яттю здійснюється через оператори new/delete
T* ptr = new T[count];
delete[] ptr;

// Для динамічних буферів використовується reserve() у контейнерах
std::vector<T> vec;
vec.reserve(new_cap);
```
:::

### Докладний аналіз поведінки та специфікація `realloc`

Функція `realloc` є основним інструментом реалізації надлишкового виділення пам'яті у мові C. Вона змінює розмір блоку пам'яті, на який вказує `ptr`, до нового значення `new_size` в байтах.

* **Вхідний аргумент `ptr`**:
  * Якщо `ptr == NULL`, функція поводиться точно так само, як `malloc(new_size)`, виділяючи новий блок пам'яті з купі.
  * Якщо `ptr` не є дійсним вказівником, раніше отриманим від `malloc`, `calloc` або `realloc`, або якщо пам'ять за цим вказівником уже була звільнена викликом `free`, виникає невизначена поведінка (Undefined Behavior).

* **Вхідний аргумент `new_size`**:
  * Якщо `new_size == 0` і `ptr != NULL`, у стандартах C99 та C11 поведінка залежить від реалізації: пам'ять може бути звільнена, або може бути повернуто унікальний вказівник мінімального розміру. У стандарті C23 виклик `realloc(ptr, 0)` оголошено застарілим і забороненим для уникнення витоків пам'яті.
  * Якщо `new_size` більший за поточний розмір блоку, алокатор намагається виділити новий простір.

* **Внутрішня механіка виконання `realloc`**:
  1. **Розширення на місці (In-place Expansion)**: Алокатор перевіряє, чи є ділянка пам'яті безпосередньо після поточного блоку вільною в купі. Якщо розмір вільної ділянки достатній, алокатор модифікує свої внутрішні метадані блоку, збільшує його зареєстровану місткість і повертає **початковий вказівник `ptr`** без виконання жодного копіювання даних. Це найшвидший сценарій (`O(1)`).
  2. **Виділення нового блоку та копіювання (Out-of-place Reallocation)**: Якщо після поточного блоку знаходяться зайняті дані інших змінних, алокатор шукає в купі новий підрядний блок пам'яті розміром `new_size`. Після успішного знаходження алокатор копіює вміст старого блоку в новий (копіюється `min(old_size, new_size)` байтів), повністю звільняє старий блок пам'яті й повертає **новий вказівник** на виділену ділянку.
  3. **Невдача виділення пам'яті**: Якщо в оперативній пам'яті або адресному просторі процесу немає підрядного блоку необхідного розміру, `realloc` повертає `NULL`. При цьому **старий блок пам'яті `ptr` залишається недоторканим і дійсним**, а його вміст не руйнується.

### Безпечний паттерн виклику `realloc`

Пряме присвоєння результату `realloc` у початкову змінну є поширеною небезпечною помилкою (витоком пам'яті):

:::tabs
```c
// КОРЕКТНИЙ ІДІОМАТИЧНИЙ ПАТТЕРН У C:
size_t new_cap = buf->capacity + (buf->capacity >> 1); // Геометричний ріст x1.5
int *tmp = (int*)realloc(buf->data, new_cap * sizeof(int));
if (!tmp) {
    // Обробка критичної ситуації: buf->data все ще доступний і містить коректні дані
    fprintf(stderr, "Помилка: не вдалося розширити надлишковий буфер\n");
    return false;
}
buf->data = tmp;
buf->capacity = new_cap;
```
```cpp
// ІДІОМАТИЧНЕ БЕЗПЕЧНЕ РОЗШИРЕННЯ У C++ (RAII):
try {
    std::size_t new_cap = capacity + (capacity >> 1); // Геометричний ріст x1.5
    auto new_data = std::make_unique<int[]>(new_cap);
    std::copy(data.get(), data.get() + size, new_data.get());
    data = std::move(new_data);
    capacity = new_cap;
} catch (const std::bad_alloc&) {
    std::cerr << "Помилка: не вдалося виділити пам'ять у C++\n";
    return false;
}
```
:::

### Інтроспекція фактичної місткості алокатора

Алокатори пам'яті часто округлюють розмір виділеного блоку убік збільшення (до кратності 8, 16 або розміру кеш-лінії). У системних бібліотеках доступні функції інтроспекції фактичної місткості виділеного блоку:

:::tabs
```c
#if defined(__linux__)
#include <malloc.h>
// Повертає реальну кількість байтів, виділених алокатором glibc для ptr
size_t actual_size = malloc_usable_size(ptr);
#elif defined(_WIN32)
#include <malloc.h>
// Повертає реальний розмір блоку у купі MS C Runtime (CRT)
size_t actual_size = _msize(ptr);
#endif
```
```cpp
#include <memory_resource>
#include <vector>

// У C++20 інтроспекція та керування виділенням здійснюється через Polymorphic Memory Resources
std::pmr::monotonic_buffer_resource pool{1024};
std::pmr::vector<int> vec{&pool};
```
:::

Використання цих функцій дозволяє дізнатися «безкоштовний» надлишок пам'яті, доданий алокатором при округленні, і скоригувати змінну `capacity` без виклику додаткових реалокацій.

## 2. Специфікація контейнерів C++ STL (`std::vector`, `std::string`)

У мові C++ стандартні неперервні контейнери `std::vector<T>` та `std::basic_string<CharT>` автоматизують надлишкове виділення пам'яті за допомогою системи методів керування місткістю.

### Контракт методів `std::vector`

```cpp
namespace std {
    template <typename T, typename Allocator = std::allocator<T>>
    class vector {
    public:
        using size_type       = std::size_t;
        using reference       = T&;
        using const_reference = const T&;

        // Поточні показники заповненості
        size_type size() const noexcept;
        size_type capacity() const noexcept;
        size_type max_size() const noexcept;
        bool empty() const noexcept;

        // Зміна місткості та виділення надлишку
        void reserve(size_type new_cap);
        void shrink_to_fit();
        void resize(size_type count);
        void resize(size_type count, const value_type& value);
        void clear() noexcept;
    };
}
```

### Деталізація методів керування місткістю у C++

1. **`size_type capacity() const noexcept`**:
   * **Опис**: Повертає кількість елементів типу `T`, для яких у поточний момент виділено оперативну пам'ять у суцільному блоці.
   * **Гарантія**: Виконання додатків `push_back()` або `emplace_back()` у кількості, що не перевищує `capacity() - size()`, гарантовано виконується за сталий час `O(1)` без інвалідації ітераторів, вказівників або посилань на існуючі елементи.
   * **Складність**: `O(1)` нон-строуінг (noexcept).

2. **`void reserve(size_type new_cap)`**:
   * **Опис**: Інформує вектор про намір зберегти щонайменше `new_cap` елементів. Якщо `new_cap > capacity()`, вектор виділяє новий блок пам'яті розміром не менше `new_cap` і переміщує (або копіює) існуючі елементи.
   * **Особливість**: Якщо `new_cap <= capacity()`, виклик **ігнорується й не робить нічого**. Метод `reserve` ніколи не зменшує місткість контейнера.
   * **Інвалідація**: Якщо відбулося виділення пам'яті (`new_cap > capacity()`), усі ітератори, вказівники та посилання на елементи вектора стають недійсними. Якщо реалокації не було, інвалідації не відбувається.
   * **Складність**: `O(N)` при виділенні пам'яті, `O(1)` якщо виділення не потрібне.

3. **`void shrink_to_fit()`**:
   * **Опис**: Запит до вектора із проханням звільнити невикористану надлишкову місткість, тобто зменшити `capacity()` до поточного значення `size()`.
   * **Семантика**: Є **необов'язковою підказкою** (non-binding request) для компілятора та стандартної бібліотеки. Реалізація C++ STL має право ігнорувати цей виклик задля оптимізації продуктивності.
   * **Механіка реалізації**: Більшість реалізацій створюють новий тимчасовий вектор точно за розміром `size()`, переміщують туди елементи й міняються з ним внутрішніми вказівниками (Swap Idiom).
   * **Складність**: `O(N)` при переміщенні елементів.

4. **`void resize(size_type count)`**:
   * **Опис**: Змінює кількість елементів у контейнері до `count`.
   * **Поведінка**:
     * Якщо `count > size()`, у вектор додаються нові елементи, конструйовані за замовчуванням. Якщо `count` перевищує поточний `capacity()`, відбувається автоматичне геометричне розширення надлишкової місткості.
     * Якщо `count < size()`, з кінця вектора вилучаються й знищуються `size() - count` елементи. **Місткість `capacity()` при цьому залишається незмінною**.

## 3. Специфікація керування хеш-таблицями (`std::unordered_map`, `std::unordered_set`)

У хеш-таблицях C++ over-provisioning регулюється за допомогою кількості бакетів (Buckets) та порогу коефіцієнта заповнення (Load Factor).

### Контракт методів `std::unordered_map`

```cpp
namespace std {
    template <
        typename Key,
        typename T,
        typename Hash = std::hash<Key>,
        typename KeyEqual = std::equal_to<Key>,
        typename Allocator = std::allocator<std::pair<const Key, T>>
    >
    class unordered_map {
    public:
        using size_type = std::size_t;

        // Робота з бакетами та заповненістю
        size_type bucket_count() const noexcept;
        size_type max_bucket_count() const noexcept;
        float load_factor() const noexcept;
        float max_load_factor() const noexcept;
        void max_load_factor(float ml);

        // Явне розширення надлишкових бакетів
        void rehash(size_type count);
        void reserve(size_type count);
    };
}
```

### Опис та специфікація методів хеш-таблиці

1. **`float load_factor() const noexcept`**:
   * Повертає поточне відношення кількості елементів до кількості бакетів: `α_load = size() / bucket_count()`.

2. **`float max_load_factor() const noexcept`**:
   * Повертає поточний поріг заповненості `α_max`. За замовчуванням у C++ STL значення дорівнює `1.0`.

3. **`void max_load_factor(float ml)`**:
   * Встановлює новий поріг заповненості `ml`. Зниження порогу (наприклад, до `0.7`) змушує таблицю тримати більший надлишок бакетів, що зменшує колізії та прискорює пошук. Якщо новий поріг менший за поточний `load_factor()`, наступна вставка викликає негайний `rehash()`.

4. **`void rehash(size_type count)`**:
   * Встановлює кількість бакетів щонайменше у `count`. Якщо `count` більший за поточний `bucket_count()`, виділяється новий масив бакетів, і всі існуючі елементи перерозподіляються по нових бакетах (`O(N)`).

5. **`void reserve(size_type count)`**:
   * Зручний метод, який обчислює необхідну кількість бакетів для збереження `count` елементів без перевищення порогу `max_load_factor()`.
   * **Математичний еквівалент**: Викликає `rehash(ceil(count / max_load_factor()))`.

## 4. Специфікація вирівнювання пам'яті (Memory Alignment)

При надлишковому виділенні системних буферів важливо округлювати місткість до кратності розміру кеш-ліній процесора (64 байти) або сторінок операційної системи (4096 байт).

### Сигнатури стандартних функцій вирівнювання

:::tabs
```c
// C11 Standard: alignment має бути кратним розміру вказівника
#include <stdlib.h>
void *ptr = aligned_alloc(64, new_cap * sizeof(int));
free(ptr);
```
```cpp
// C++17 operator new з вирівнюванням
#include <new>

int* ptr = static_cast<int*>(::operator new[](
    new_cap * sizeof(int),
    std::align_val_t{64}
));
::operator delete[](ptr, std::align_val_t{64});
```
:::

### Специфікація вирівнювання надлишкових блоків

| Рівень системної архітектури | Розмір вирівнювання | Технічне обґрунтування |
| :--- | :--- | :--- |
| **Векторні інструкції (SIMD AVX-512)** | 64 байти | Запобігає опрацюванню меж векторних регістрів у двох різних операціях шини. |
| **Кеш-лінія L1 (CPU Cache Line)** | 64 байти | Усуває ефект ложного розділення (False Sharing) між потоками виконання. |
| **Сторінка пам'яті (OS Page Boundary)** | 4096 байт (4 КБ) | Гарантує, що розширення буфера не перетинає додаткові межі сторінок TLB. |

Завдяки дотриманню вирівнювання при надлишковому виділенні буфери працюють із максимальною швидкістю на рівні апаратного забезпечення.
