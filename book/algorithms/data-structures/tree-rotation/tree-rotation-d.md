# Поворот дерева (Tree Rotation)

<preknowlist>
- [Двійкове дерево пошуку](book:algorithms/binary-search-tree) — властивість впорядкованості лівого та правого піддерев (`L < X < R`).
- [Двійкове дерево](book:algorithms/binary-tree) — структура вузла з вказівниками на лівого і правого нащадків.
- [Асимптотична складність](book:algorithms/asymptotic-complexity) — поняття сталого часу `O(1)` для маніпуляцій з вказівниками.
- [AVL-дерево](book:algorithms/avl-tree) — самоврівноважуване двійкове дерево пошуку, в якому збалансованість підтримується поодинокими та подвійними поворотами.
- [Червоно-чорне дерево](book:algorithms/red-black-tree) — самоврівноважуване дерево, де повороти відновлюють колірні інваріанти після встави або видалення.
- [Splay-дерево](book:algorithms/splay-tree) — самоадаптивне дерево пошуку, що переміщує часто запитувані вузли до кореня за допомогою каскаду повертань.
</preknowlist>

Уявіть, що ви розробляєте високонавантажену базову станцію мобільного зв'язку чи високопродуктивний сервер бази даних, де мільйони пошукових запитів мусять оброблятися за мікросекунди. Ви вибираєте [двійкове дерево пошуку](book:algorithms/binary-search-tree) (BST), розраховуючи на швидкий пошук за логарифмічний час `O(log n)`. Проте в реальній системі вхідні дані часто надходять у частково впорядкованому вигляді — наприклад, покази датчиків з часовими мітками, послідовні транзакції банківського рахунку або відсортовані списки ідентифікаторів користувачів. Звичайне двійкове дерево при такій вставці вироджується в однозв'язаний список висотою `h = n`. Замість 20 порівнянь на мільйон записів система починає робити мільйон кроків, процесорний клок вичерпується, а затримка виклику спалахує у тисячі разів.

Як перебалансувати дерево, коли одна його гілка стала надто довгою? Перебудувати дерево з нуля — це `O(n)` операцій, що вбивчо для кожної вставки. Необхідна точкова хірургічна операція, яка здатна змінити висоту гілок за строго сталий час `O(1)`, не переставляючи при цьому елементи у відсортованому порядку. З такої потреби й народжується **поворот дерева (Tree Rotation)** — фундаментальна топологічна трансформація, яка змінює висоту піддерев за сталий час `O(1)`, залишаючи центровий порядок елементів (`in-order`) абсолютно недоторканним.

## Першопричина: конфлікт між висотою та впорядкованістю

Щоб зрозуміти механіку повороту, подивімося на фундаментальне правило, за яким живе будь-яке двійкове дерево пошуку. Для кожного вузла `X` виконується інваріант впорядкованості:
- Усі елементи у лівому піддереві `L_X` строго менші за `X` (`L_X < X`).
- Усі елементи у правому піддереві `R_X` строго більші за `X` (`R_X > X`).

Швидкість будь-якої операції в дереві (пошуку, вставки, видалення) вимірюється не загальною кількістю елементів `n`, а його **висотою** `h`. На кожному кроці спуск зміщується на один рівень глибше. Якщо дерево збалансоване, його висота становить `h ≈ log₂ n`, і на мільйон елементів потрібні лише 20 кроків. Але висота — це не сталий параметр: вона змінюється при кожній вставці та видаленні.

Розглянемо найпростішу ситуацію: у порожнє дерево послідовно вставляють числа 1, 2, 3.

```
  1
   \
    2
     \
      3
```

Отримане дерево має висоту `h = 3`. Центровий обхід (`in-order`) повертає послідовність `1, 2, 3`. Проте те саме числове значення і той самий центровий порядок можна представити іншим, гілкуватим деревом з вузлом 2 у корені:

```
    2
   / \
  1   3
```

Тут висота зменшилася до `h = 2`! Відстань від кореня до будь-якого елемента скоротилася. Виникає питання: **як перейти від першого стану до другого локально, без повного перечитування та сортування масиву?**

Поворот дерева — це і є відповідь. Це операція, яка бере ребро між двома сусідніми вузлами (наприклад, між 1 і 2) і «перевертає» його: вузол, що був сином, стає батьком, а колишній батько опускається на щабель нижче.

## Анатомія поодинокого повороту

Поворот завжди виконується навколо ребра, яке з'єднує батьківський вузол та одного з його дітей. Залежно від того, який син піднімається нагору, розрізняють два дзеркальних типи повертань: **правий поворот (Right Rotation)** та **лівий поворот (Left Rotation)**.

![Поодинокі повороти дерева](/book/algorithms/data-structures/tree-rotation/img/rotation-left-right.svg)
*Поодинокі повороти дерева: правий поворот піднімає лівого сина X, лівий поворот піднімає правого сина Y. Центровий порядок A < X < B < Y < C залишається незмінним.*

### Правий поворот (Right Rotation / Zig)

Розглянемо фрагмент дерева, де вузол `Y` є коренем даного піддерева, а його лівим сином є вузол `X`. Вузол `X` має власне ліве піддерево `A` і праве піддерево `B`. У вузла `Y` є праве піддерево `C`.

```
         Y                  X
        / \                / \
       X   C    ====>     A   Y
      / \                    / \
     A   B                  B   C
```

Проаналізуємо відносний порядок усіх елементів за правилом BST:
1. Оскільки `X` лежить у лівому піддереві `Y`, маємо `X < Y`.
2. Піддерево `A` лежить ліворуч від `X`, отже `A < X`.
3. Піддерево `B` лежить праворуч від `X`, але ліворуч від `Y`, отже `X < B < Y`.
4. Піддерево `C` лежить праворуч від `Y`, отже `Y < C`.

Звівши ці нерівності в єдиний ланцюг, отримуємо центровий порядок:

```
A < X < B < Y < C
```

Тепер виконаємо **правий поворот навколо Y**:
1. Вузол `X` піднімається на місце `Y` і стає новим коренем піддерева.
2. Вузол `Y` опускається праворуч від `X` і стає його правим сином.
3. Піддерево `A` залишається лівим сином `X` (усі елементи `A < X`).
4. Піддерево `C` залишається правим сином `Y` (усі елементи `C > Y`).
5. **Критична деталь:** Куди діти піддерево `B`? Елементи `B` більші за `X`, але менші за `Y` (`X < B < Y`). Оскільки `Y` тепер став правим сином `X`, ліве піддерево `Y` звільнилося. Отже, `B` ідеально стає лівим сином `Y`!

Перевіримо центровий порядок нового дерева після правого повороту:
- Ліве піддерево `X` містить `A`.
- Потім іде корінь `X`.
- Праве піддерево `X` містить `Y`. Усередині `Y`: ліворуч `B`, корінь `Y`, праворуч `C`.
- Підсумковий порядок: `A, X, B, Y, C`.

Порядок елементів **абсолютно не змінився**. Але геометричний профіль змінився суттєво: піддерево `A` піднялося на один рівень вище (його елементи тепер шукаються швидше), а піддерево `C` опустилося на один рівень нижче.

### Лівий поворот (Left Rotation / Zag)

Лівий поворот — це точна дзеркальна копія правого повороту. Він застосовується тоді, коли праве піддерево вузла `X` має більшу висоту ніж ліве.

При лівому повороті навколо `X`:
1. Правий син `Y` піднімається на місце `X`.
2. `X` опускається ліворуч від `Y` і стає його лівим сином.
3. Середнє піддерево `B` (яке було лівим сином `Y`) стає правим сином `X`.

З [математичного аналізу інваріантів](book:algorithms/tree-rotation/math-rotation-invariants.md) видно, що поворот дерева є повним еквівалентом закону асоціативності для дужок у бінарній операції `(A * X * B) * Y * C ≡ A * X * (B * Y * C)`.

> 🔧 **Навіщо це.** В операційних системах та системах керування базами даних (наприклад, у реалізації `std::map` у C++ STL чи у файловій системі ext4) поворот дерева використовується для того, щоб гарантувати межу затримки запиту `O(log n)`. Без поворотів на зловмисному вхідному потоці база даних може перетворитися на лінійний список, згортаючи пропускну здатність сервера з сотень тисяч транзакцій на секунду до поодиноких одиниць.

## Перепідключення вказівників у пам'яті: як це працює в коді

На відміну від концептуальної картинки, у пам'яті комп'ютера немає «вертикалі» чи «горизонталі» — є лише вузли зі вказівниками на пам'ять (`left`, `right`, `parent`). Щоб поворот працював бездоганно, необхідно строго дотримуватися послідовності перепідключень.

![Перепідключення вказівників при лівому повороті](/book/algorithms/data-structures/tree-rotation/img/rotation-pointers.svg)
*Схема маніпулювання вказівниками при виконанні rotate_left(X): 1) X->right = B; 2) B->parent = X; 3) Y->parent = P; 4) P->link = Y; 5) Y->left = X; 6) X->parent = Y.*

Розглянемо крок за кроком виконання лівого повороту `rotate_left(X)` для вузла `X`, що має правого сина `Y` з середнім піддеревом `B`:

```
       P (Parent)
       |
       X
      / \
     A   Y
        / \
       B   C
```

Для виконання повороту потрібно модифікувати 6 вказівників у пам'яті:

1. **Захопити новий корінь `Y` та його ліве піддерево `B`:**
   Вказівник на нового кореневого сина отримується прямо: `Node* Y = X->right`, а його ліве піддерево захоплюється як `Node* B = Y->left`.
2. **Передати `B` піддереву `X`:**
   Правий вказівник `X` перенаправляється на `B`: `X->right = B`.
   Якщо `B` існує (`B != NULL`), його батьківський вказівник оновлюється: `B->parent = X`.
3. **Зв'язати `Y` з батьківським вузлом `P`:**
   Вказуємо батька для `Y`: `Y->parent = X->parent`.
   Якщо `X` був коренем усього дерева (`X->parent == NULL`), новий корінь дерева `root` стає `Y`.
   Якщо `X` був лівим сином `P`, оновлюємо `P->left = Y`.
   Якщо `X` був правим сином `P`, оновлюємо `P->right = Y`.
4. **Зробити `X` лівим сином `Y`:**
   Перепідключаємо `Y->left = X`, а зворотний вказівник оновлюємо як `X->parent = Y`.
5. **Перерахувати висоти та метадані:**
   Висоти вузлів `X` та `Y` змінилися. Спочатку оновлюється опусканий вузол `X`, а потім новий корінь `Y`:
:::tabs
```c
update_height(X);
update_height(Y);
```
```cpp
update_height(X);
update_height(Y);
```
:::

З [детальної практичної реалізації C/C++](book:algorithms/tree-rotation/proj-tree-rotation.md) випливає, що така процедура не містить жодного циклу чи рекурсії: вона виконує фіксовану кількість читань та записів у пам'ять, що гарантує суворий сталий час `O(1)`.

З [технічної специфікації API та контрактів](book:algorithms/tree-rotation/api-tree-rotation.md) можна дізнатися повний перелік прекондицій, посткондицій та чекліст перевірки безпеки пам'яті для операцій повертання.

## Подвійні повороти: усунення «зигзагового» дисбалансу

Поодинокі повороти ідеально працюють, коли дерево викривлене в один бік — так звана конфігурація **Left-Left (LL)** або **Right-Right (RR)**. Проте існує підступніший випадок: **зигзагоподібний дисбаланс (Left-Right / LR або Right-Left / RL)**.

Уявимо, що до вузла `Z` додають лівого сина `X`, а до `X` додають правого сина `Y`.

```
        Z
       /
      X
       \
        Y
```

Якщо спробувати усунути цей дисбаланс поодиноким правим поворотом навколо `Z`, отримаємо дзеркальний зигзаг:

```
      X
       \
        Z
       /
      Y
```

Висота дерева взагалі не зменшилася! Поодинокий поворот лишь перекинув зигзаг з одного боку в інший.

Щоб розплутати зигзаг, винайдено **подвійний поворот (Double Rotation)**.

![Подвійний поворот дерева](/book/algorithms/data-structures/tree-rotation/img/double-rotation.svg)
*Подвійний поворот Left-Right (LR): Крок 1 виконує лівий поворот для лівого сина X (випрямлення зигзага у форму LL), Крок 2 виконує правий поворот для кореня Z.*

### Алгоритм подвійного повороту Left-Right (LR Rotation)

Подвійний поворот складається з двох послідовних поодиноких повертань:

1. **Перший крок (Випрямлення):** Виконуємо **лівий поворот навколо лівого сина `X`**.
   Після цього `Y` піднімається на місце `X`, а `X` опускається ліворуч. Зигзаг `Z -> X -> Y` випрямляється у лівоважку лінію `Z -> Y -> X` (конфігурація LL).
2. **Другий крок (Балансування):** Виконуємо **правий поворот навколо кореня `Z`**.
   Тепер `Y` стає новим коренем усього піддерева, `X` залишається його лівим сином, а `Z` стає його правим сином.

```
Початковий стан (LR)       Після Left(X) (LL)         Після Right(Z) (Збалансовано)
      Z                          Z                          Y
     /                          /                          / \
    X                          Y                          X   Z
     \                        /
      Y                      X
```

Подвійний поворот Right-Left (RL) виконується дзеркально: спочатку правий поворот для правого сина, потім лівий поворот для кореня.

З [історичного нарису розвитку алгоритмів повертання](book:algorithms/tree-rotation/hist-tree-rotation.md) можна простежити, як саме Адельсон-Вельський та Ландіс 1962 року відкрили подвійні повороти, сформувавши базис класичної теорії збалансованих дерев.

## Повороти в реальних структурах даних

Поворот дерева — це не самостійна структура даних, а елементарний дрібний механізм («цеглинка»), на якому будуються склади самоврівноважуваних дерев.

### 1. AVL-дерева
У AVL-деревах кожен вузол зберігає балансовий фактор: `BF = height(Right) - height(Left)`.
Якщо після вставки чи видалення у вузла `Z` баланс стає `-2` або `+2`:
- Якщо `BF(Z) == -2` і `BF(Left_Child) <= 0` — виконується поодинокий **Right Rotation**.
- Якщо `BF(Z) == -2` і `BF(Left_Child) > 0` — виконується подвійний **Left-Right Rotation**.
- Якщо `BF(Z) == +2` і `BF(Right_Child) >= 0` — виконується поодинокий **Left Rotation**.
- Якщо `BF(Z) == +2` і `BF(Right_Child) < 0` — виконується подвійний **Right-Left Rotation**.

### 2. Червоно-чорні дерева (Red-Black Trees)
У червоно-чорних деревах повороти використовуються для усунення конфлікту «двох червоних вузлів поспіль» (`red-red violation`). Поворот у поєднанні з перефарбовуванням вузлів відновлює чорну висоту за максимум 2 повороти при вставці та 3 повороти при видаленні.

### 3. Splay-дерева
У Splay-деревах немає жорстких вимог до балансу. Натомість при кожному доступі до вузла `x` виконується серія повертань (`splay(x)`), яка викочує `x` у корінь дерева:
- `Zig`: поодинокий поворот (якщо батько `x` є коренем).
- `Zig-Zig`: два повертання в один бік (навколо діда, потім навколо батька).
- `Zig-Zag`: подвійний поворот у різні боки.

Це забезпечує амортизовану складність `O(log n)` і пристосовує дерево до повторних запитів.

### 4. Глобальне балансування: Алгоритм Day-Stout-Warren (DSW)

Окрім локальних вставок, повороти дозволяють повністю перебалансувати довільне знівечене дерево за `O(n)` часу й `O(1)` додаткової пам'яті.

![Алгоритм Day-Stout-Warren](/book/algorithms/data-structures/tree-rotation/img/dsw-algorithm.svg)
*Алгоритм Дей-Стоута-Воррена (DSW): Фаза 1 випрямляє BST у правий список (vine) правими поворотами; Фаза 2 згортає список в ідеальне дерево серіями лівих повертань.*

Алгоритм DSW працює у два кроки:
1. **Створення Vine (лози):** Проходимо по дереву. Поки у поточного вузла є лівий син, виконуємо правий поворот. У результаті дерево перетворюється на однозв'язаний список, що росте виключно праворуч.
2. **Згортання (Compress):** Обчисливши кількість вузлів `n` та висоту майбутнього ідеального дерева, виконуємо точно розраховану серію лівих повертань через один вузол, зменшуючи довжину лози вдвічі на кожному пасі, поки дерево не стане ідеально збалансованим.

## Практична конфігурація та типові помилки

Під час практичної реалізації повертань найчастіше припускаються п'яти характерних помилок:

1. **Забутий батьківський вказівник у середнього піддерева `B`:**
   При правому повороті навколо `X` піддерево `B` стає лівим сином `Y`. Якщо `B` існує, обов'язково треба оновити `B->parent = Y`. Забутий вказівник залишає старе значення `B->parent = X`, ламаючи зворотний обхід угору.
2. **Втрата кореня дерева (`root`):**
   Якщо поворот виконується навколо вузла, який був коренем усього дерева, новий корінь `Y` не має батька (`Y->parent == NULL`). Якщо не оновити зовнішній вказівник `root` у структурі дерева, програма продовжує посилатися на опущений вузол `X`.
3. **Порушення порядку перерахунку метрик:**
   Висоту вузлів або розмір піддерева `size` слід оновлювати знизу вгору. Спочатку обчислюються нові значення для опущеного вузла `X` (його діти вже стабільні), а лише потім для нового кореня `Y`.
4. **Некоректний вибір між поодиноким і подвійним поворотом:**
   Спроба виправити зигзаг (LR чи RL) поодиноким поворотом не зменшує висоту дерева. Слід завжди перевіряти знак балансового фактора дитини перед вибором схеми повертання.
5. **Створення циклів у вказівниках:**
   Якщо перед перепідключенням `Y->right = X` забути відв'язати `X->left = B`, виникає закольцьований вказівник `X->left == Y` та `Y->right == X`. Будь-який наступний обхід дерева входить у нескінченну рекурсію й спричиняє виснаження стека (`stack overflow`).

Поворот дерева — це фундаментальна інженерна абстракція. Вона перетворює статичну ідею впорядкованого дерева на гнучку, динамічну систему, здатну адаптуватися до будь-якого потоку даних за сталий час `O(1)`.
