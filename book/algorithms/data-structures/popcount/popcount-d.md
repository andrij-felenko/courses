Коли аналітична система виконує запит фільтрації над мільярдним стовпчиком бітових індексів, або коли персистентне дерево мапованого хешу (HAMT) шукає ключ серед мільйона записів, центральному процесору потрібно за частку наносекунди з'ясувати: скільки розрядів у 64-бітному масиві прапорців встановлено в одиницю? Наївний перебір 64 розрядів у циклі вимагає близько двохсот машинних тактів і спричиняє систематичні зупинки конвеєра через хибні передбачення переходів. Підрахунок одиничних розрядів у машинному слові є критичним примітивом для лаконічних структур даних, стиснених бітових векторів, криптографії та метричного пошуку.

Операція має загальноприйняту назву **population count** (англ. «підрахунок населення» бітів, або скорочено **popcount**); у комбінаториці та теорії завадостійкого кодування те саме число називають **вагою Гемінга** (англ. *Hamming weight*).

## 1. Чому звичайна арифметика не виконує підрахунок автоматично

Здавалося б, процесор спроєктовано для виконання операцій додавання, і скласти 64 окремі біти має бути найпростішою задачею. Проте тут криється фундаментальна відмінність між арифметичним додаванням та згорткою бітового слова.

Класичний арифметико-логічний пристрій (АЛП) оперує розрядами, кожен з яких має степеневу вагу `2ᵏ` (ваги 1, 2, 4, 8, 16...). Коли суматор додає два числа, кожен розряд результату залежить від відповідних бітів доданків і від біта переносу з сусіднього молодшого розряду. Інформація тече строго горизонтально від молодших розрядів до старших:

```
Розряди числа:     b₇     b₆     b₅     b₄     b₃     b₂     b₁     b₀
Арифметична вага:  128    64     32     16     8      4      2      1
Вага для popcount: 1      1      1      1      1      1      1      1
```

Операція popcount призначає кожному розряду слова **однакову вагу 1**. Результат операції є багатооперандною вертикальною згорткою: необхідно скласти 64 незалежні однобітні величини в єдине число в діапазоні `[0..64]`.

Звичайний двійковий суматор бере лише два операнди за раз. Щоб скласти 64 біти за допомогою послідовної двійкової арифметики, потрібно виконати 63 послідовні операції додавання. Вся історія алгоритмів підрахунку одиниць — це історія подолання цієї послідовної залежності та скорочення критичного шляху обчислення.

> 🔧 **Навіщо це.** Розуміння popcount як багатооперандної редукції з вагою 1 дозволяє правильно обирати алгоритми. Швидкість згортки визначається не зменшенням кількості бітів (усі 64 біти обов'язково мають бути опитані), а зменшенням глибини ланцюжка залежностей — переходом від лінійного часу `O(W)` до логарифмічного `O(log W)` або апаратного паралелізму `O(1)`.

## 2. Еволюція алгоритмічних методів

### Лінійний побітовий перебір

Найпростіший підхід полягає в послідовній перевірці кожного розряду слова зсувом праворуч:

:::tabs
```c
int popcount_linear(uint64_t x) {
    int count = 0;
    for (int i = 0; i < 64; i++) {
        count += (int)((x >> i) & 1ULL);
    }
    return count;
}
```
```cpp
#include <cstdint>

[[nodiscard]] constexpr int popcount_linear(uint64_t x) noexcept {
    int count = 0;
    for (int i = 0; i < 64; ++i) {
        count += static_cast<int>((x >> i) & 1ULL);
    }
    return count;
}
```
:::

Перевагою цього алгоритму є детермінований час виконання: він робить рівно 64 кроки для будь-якого вхідного числа. Проте для гарячого шляху виконання 64 ітерації зсуву, маскування та додавання є неприпустимо повільними.

### Алгоритм Вегнера-Кернігана: гасіння молодшої одиниці за O(k)

Якщо слово містить мало одиниць (розріджений масив), можна уникнути перевірки нульових розрядів за допомогою побітового виразу:

```
x & (x - 1)
```

Операція віднімання одиниці знаходить наймолодший одиничний біт у позиції `p`, скидає його в `0` та перетворює всі нулі правіше від `p` на одиниці. Старші розряди залишаються незмінними. Наступне побітове `AND` із початковим числом `x` обнуляє розряд `p`, а всі нульові розряди нижче `p` залишаються нулями (`0 & 1 = 0`).

**Числове трасування для x = 180 (двійкове 1011 0100₂):**

```
x         = 1011 0100      (180)
x - 1     = 1011 0011      (179)   [позика скинула біт 2, молодші розряди стали 1]
x & (x-1) = 1011 0000      (176)   [молодшу одиницю успішно знищено]
```

Цикл скидає по одній одиниці на кожній ітерації:

:::tabs
```c
int popcount_wegner(uint64_t x) {
    int count = 0;
    while (x != 0) {
        x &= (x - 1);
        count++;
    }
    return count;
}
```
```cpp
#include <cstdint>

[[nodiscard]] constexpr int popcount_wegner(uint64_t x) noexcept {
    int count = 0;
    while (x != 0) {
        x &= (x - 1);
        ++count;
    }
    return count;
}
```
:::

Кількість кроків дорівнює `k = popcount(x)`. Для розріджених даних (наприклад, 2–3 одиниці на слово) метод працює швидко. Проте на випадкових даних із рівномірним розподілом бітів середня кількість ітерацій дорівнює 32. Головна проблема полягає в тому, що умова виходу з циклу залежить від даних: кожне хибне передбачення переходу на сучасному процесорі скидає конвеєр інструкцій із штрафом у 15–20 тактів. Крім того, змінний час виконання неприпустимий у криптографічних алгоритмах через ризик витоку інформації каналом вимірювання часу.

Про історію появи цього прийому та його впровадження в перші суперкомп'ютери читайте у вставці про [історію створення та криптографічне минуле popcount](book:algorithms/popcount/hist-popcount.md).

### Табличний метод (LUT) та ціна кеш-пам'яті

Класичним інженерним компромісом є попередня підготовка таблиці пошуку (LUT — *Lookup Table*) для всіх 256 можливих значень байта:

:::tabs
```c
static const uint8_t POPCOUNT_TABLE_256[256] = {
    0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4,
    /* ... 256 попередньо обчислених значень ... */
};

int popcount_lut(uint64_t x) {
    return POPCOUNT_TABLE_256[x & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 8) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 16) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 24) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 32) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 40) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 48) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 56) & 0xFF];
}
```
```cpp
#include <cstdint>
#include <array>

namespace {
constexpr auto make_popcount_lut() {
    std::array<uint8_t, 256> lut{};
    for (size_t i = 0; i < 256; ++i) {
        uint8_t c = 0;
        for (size_t b = 0; b < 8; ++b) {
            c += static_cast<uint8_t>((i >> b) & 1U);
        }
        lut[i] = c;
    }
    return lut;
}
constexpr auto POPCOUNT_TABLE_256 = make_popcount_lut();
}

[[nodiscard]] constexpr int popcount_lut(uint64_t x) noexcept {
    return POPCOUNT_TABLE_256[x & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 8) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 16) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 24) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 32) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 40) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 48) & 0xFF] +
           POPCOUNT_TABLE_256[(x >> 56) & 0xFF];
}
```
:::

Табличний метод скорочує операцію до 8 звернень до масиву та 7 додавань. На мікроконтролерах без апаратного множника цей підхід лишається актуальним. Проте на сучасних високоефективних процесорах звернення до пам'яті коштує дорожче за арифметику. Якщо таблиця не знаходиться в найшвидшому кеші L1d, промах кеша коштує від десятків до сотень тактів. Крім того, доступ до таблиці витісняє інші дані з кеша процесора.

## 3. Дерево паралельного додавання SWAR (SIMD Within A Register)

Для досягнення максимальної швидкості без звернень до пам'яті застосовують підхід **SWAR**: паралельне додавання лічильників однакової розрядності безпосередньо всередині цілочисельного регістра.

![Дерево порозрядного паралельного додавання SWAR](/book/algorithms/data-structures/popcount/img/swar-tree.svg)
*Дерево порозрядного паралельного додавання SWAR: 64 біти згортаються у 6 логарифмічних кроків попарного складання лічильників.*

### Покроковий механізм згортки

1. **Крок 1 (2-бітні пари):** розбиваємо 64 біти на 32 пари. Щоб скласти біти `b₁ + b₀` у кожній парі без виходу за межі 2-бітного поля, застосовують тотожність:

```
b₁ + b₀ = (2·b₁ + b₀) - b₁ = x - (x >> 1)
```

Застосовуючи маску `0x5555555555555555` (чергування бітів `010101...₂`), отримуємо 32 2-бітні лічильники:

```c
x = x - ((x >> 1) & 0x5555555555555555ULL);
```

2. **Крок 2 (4-бітні четвірки):** додаємо сусідні 2-бітні лічильники за допомогою маски `0x3333333333333333` (`00110011...₂`):

```c
x = (x & 0x3333333333333333ULL) + ((x >> 2) & 0x3333333333333333ULL);
```

3. **Крок 3 (8-бітні байти):** складаємо сусідні 4-бітні значення. Оскільки максимальна сума становить `4 + 4 = 8` (вміщується у 4 біти), маскування можна виконати **після** додавання, уникнувши однієї операції `AND`:

```c
x = (x + (x >> 4)) & 0x0F0F0F0F0F0F0F0FULL;
```

4. **Крок 4 (згортка множенням):** після третього кроку слово містить 8 окремих байтів, кожен з яких зберігає кількість одиниць у своєму 8-бітному блоці (числа від 0 до 8). Сума всіх 8 байтів не перевищує 64.

Замість виконання наступних зсувів і додавань для 16-, 32- та 64-бітних полів, застосовують множення на константу `0x0101010101010101ULL`:

```
x * 0x0101010101010101ULL
```

Множення на цю константу еквівалентно обчисленню згортки: старший байт результату містить суму всіх восьми байтів `B₀ + B₁ + ... + B₇`. Зсув результату праворуч на 56 розрядів повертає підсумкову суму одиниць.

**Повний канонічний код алгоритму SWAR:**

:::tabs
```c
int popcount_swar(uint64_t x) {
    x = x - ((x >> 1) & 0x5555555555555555ULL);
    x = (x & 0x3333333333333333ULL) + ((x >> 2) & 0x3333333333333333ULL);
    x = (x + (x >> 4)) & 0x0F0F0F0F0F0F0F0FULL;
    return (int)((x * 0x0101010101010101ULL) >> 56);
}
```
```cpp
#include <cstdint>

[[nodiscard]] constexpr int popcount_swar(uint64_t x) noexcept {
    x = x - ((x >> 1) & 0x5555555555555555ULL);
    x = (x & 0x3333333333333333ULL) + ((x >> 2) & 0x3333333333333333ULL);
    x = (x + (x >> 4)) & 0x0F0F0F0F0F0F0F0FULL;
    return static_cast<int>((x * 0x0101010101010101ULL) >> 56);
}
```
:::

Алгоритм виконується строго за 12 базових арифметико-логічних інструкцій без розгалужень і без доступу до пам'яті. Детальне алгебраїчне доведення коректності кроків та властивостей модульної згортки наведено у вставці про [строге математичне доведення SWAR-тотожностей та згортки множенням](book:algorithms/popcount/math-popcount.md).

## 4. Векторизований підрахунок та Carry-Save Adders (CSA)

Коли потрібно порахувати одиниці не в одному слові, а у великому бітовому масиві (наприклад, у бітових індексах пошукових систем або стиснених мапах Roaring Bitmaps), виклик скалярного popcount у циклі обмежується пропускною здатністю скалярного конвеєра.

Для пакетної обробки застосовують алгоритм Харлі-Сіла на основі компресорів **Carry-Save Adder (CSA 3:2)**.

![Конвеєр компресорів Carry-Save Adder для векторизованого підрахунку](/book/algorithms/data-structures/popcount/img/csa-vectorized.svg)
*Конвеєр компресорів Carry-Save Adder: три вектори перетворюються на вектор суми (вага 1) та вектор переносу (вага 2) без горизонтального розповсюдження бітів.*

Тривходовий суматор CSA бере три однакові за довжиною вектори `A`, `B`, `C` і за допомогою двох побітових операцій генерує вектор суми `Sum` та вектор переносу `Carry`:

```
Sum   = A ⊕ B ⊕ C                      [розряди з вагою 1]
Carry = (A ∧ B) ∨ (B ∧ C) ∨ (C ∧ A)    [розряди з вагою 2]
```

Обидві операції є строго покомпонентними й не створюють горизонтальних бітових залежностей між сусідніми розрядами. Об'єднуючи каскади CSA 3:2 у дерева компресорів 7:3 та 15:4, можна обробляти до 16 слів пам'яті одночасно, накопичуючи переноси у векторних лічильниках SIMD (AVX2, AVX-512, ARM NEON).

## 5. Апаратні інструкції та мікроархітектурні пастки

Сучасні процесори виконують popcount на рівні виділеного апаратного блоку комбінаційної логіки (дерево суматорів Воллеса) за 1–3 такти.

| Архітектура | Інструкція | Підтримка | Латентність |
|---|---|---|---|
| **x86-64** | `POPCNT r64, r/m64` | SSE4.2 / ABM (2008+) | 1–3 такти |
| **x86 AVX-512** | `VPOPCNTQ zmm, zmm` | AVX-512 VPOPCNTDQ (2017+) | 3 такти (8 слів одночасно) |
| **ARM64** | `CNT` + `ADDV` | ARMv8-A NEON | 2–4 такти |
| **RISC-V** | `cpop rd, rs` | Zbb Bit-manipulation | 1 такт |

### Мікроархітектурна помилка хибної залежності (Intel Sandy Bridge / Ivy Bridge)

В архітектурах Intel від Sandy Bridge до Broadwell інструкція `POPCNT` мала апаратний дефект у таблиці декодера мікрооперацій: регістра-приймача помилково призначався статус операнда введення-виведення. Це створювало **хибну залежність за даними** (англ. *False Register Dependency*): інструкція чекала завершення попередньої операції, яка записувала в той самий регістр, хоча значення цього регістра насправді перезаписувалося.

Компілятори (зокрема GCC та Clang) для обходу цієї вади вставляють обнулення регістра перед викликом `POPCNT`:

```assembly
xor eax, eax        ; розрив хибного ланцюжка залежностей
popcnt rax, rdi     ; виконання апаратного підрахунку
```

Повний довідник системних інструкцій, інтринсиків компіляторів та інтерфейсів стандартних бібліотек (C++20 `<bit>`, Rust, Java, Go) наведено у [повному довіднику інтринсиків та стандартних бібліотек](book:algorithms/popcount/api-popcount.md).

## 6. Застосування в алгоритмах та структурах даних

### 1. Лаконічні структури даних (Succinct Data Structures): операція Rank

У стиснених бітових векторах, хвильових деревах (Wavelet Trees) та індексах FM-index (пошук у геномних базах даних та Burrows-Wheeler Transform) ключовою операцією є **rank**(i) — кількість одиничних бітів у діапазоні від початку вектора до позиції `i`:

```
rank₁(i) = ∑_{j=0}^{i} B[j]
```

![Дворівнева лаконічна структура rank1(i) через popcount](/book/algorithms/data-structures/popcount/img/succinct-rank.svg)
*Дворівнева структура Rank9: суперблоки фіксують абсолютний ранг, упаковані лічильники — відносний ранг блоку, а залишок слів обчислюється апаратною інструкцією popcount за O(1).*

Завдяки popcount дворівнева структура **Rank9** забезпечує виконання запиту `rank1(i)` за сталий час `O(1)` з накладними витратами пам'яті лише 25%:
- **Суперблок (512 бітів):** зберігає 64-бітне число абсолютного рангу від початку масиву;
- **Базовий блок (64 біти):** сім 9-бітних лічильників відносного зміщення упаковано в одне 64-бітне слово;
- **Залишок:** виділяється маскою `mask = (1ULL << (i % 64 + 1)) - 1` і рахується однією інструкцією `popcount(word & mask)`.

Повний робочий вихідний код лаконічного бітового вектора та векторизованого масиву мовами C та C++20 наведено у вставці про [практичну реалізацію лаконічного бітового вектора та векторизованого масиву](book:algorithms/popcount/proj-rank-bitset.md).

### 2. Hash Array Mapped Trie (HAMT) та персистентні словники

Структура HAMT (основа незмінних колекцій у Clojure, Scala, Rust `im::HashMap`) використовує 32-кратне розгалуження на кожному рівні дерева. Щоб уникнути збереження масиву з 32 вказівників (з яких більшість є порожніми `NULL`), вузол зберігає 32-бітну маску зайнятих слотів (`bitmap`) та компактний масив дійсних вказівників:

![Індексація розрідженого вузла HAMT через popcount](/book/algorithms/data-structures/popcount/img/hamt-indexing.svg)
*Індексація розрідженого вузла HAMT: 5-бітний фрагмент хешу визначає біт у мапі; popcount від маскованої частини знаходить точний індекс у компактному масиві вказівників.*

Коли для ключа визначено 5-бітний фрагмент хешу `chunk ∈ [0..31]`:
1. Перевіряємо наявність гілки: `(bitmap & (1U << chunk)) != 0`;
2. Обчислюємо точний індекс у компактному масиві вказівників за допомогою маски молодших розрядів:

```cpp
uint32_t mask = (1U << chunk) - 1U;
size_t compact_index = std::popcount(bitmap & mask);
```

Операція popcount за 1 такт перетворює розріджену бітову мапу на щільний індекс масиву, скорочуючи споживання пам'яті деревом на 70–80%.

### 3. Бітові множини та графові алгоритми

Для двох бітових множин `A` та `B` основні операції обчислюються побітовими інструкціями з наступним popcount:
- **Потужність множини:** `|A| = popcount(A)`;
- **Потужність перетину:** `|A ∩ B| = popcount(A & B)`;
- **Коефіцієнт подібності Жаккара:**

```
J(A, B) = popcount(A & B) / (double)popcount(A | B)
```

У графових алгоритмах матриця суміжності зберігається як масив 64-бітних бітових масок:
- **Кількість спільних сусідів вершин u та v:** `popcount(adj[u] & adj[v])`;
- **Алгоритм Брона-Кербоша (пошук максимальних клік):** підрахунок кандидатів `popcount(candidates)` дозволяє миттєво відтинати безперспективні гілки рекурсивного пошуку.

### 4. Метричний пошук, LSH та двійкові дескриптори

У комп'ютерному зорі (дескриптори ORB, BRIEF, BRISK) та векторному пошуку схожості (Locality-Sensitive Hashing, бінаризовані ембеддінги нейромереж) об'єкти подаються двійковими векторами довжиною 256–512 бітів.

Відстань Гемінга між двома дескрипторами `A` та `B` дорівнює:

```
d_H(A, B) = ∑_{i=0}^{N-1} popcount(A[i] ⊕ B[i])
```

Там, де евклідова відстань вимагає сотень операцій множення чисел з плавальною комою, відстань Гемінга обчислюється за кілька інструкцій `XOR` та `POPCNT`, забезпечуючи зіставлення мільйонів точок за секунду на мобільних процесорах.

### 5. Динамічне програмування на підмножинах (SOS DP) та матричний перманент

В алгоритмах динамічного програмування по підмножинах (SOS DP — *Sum Over Subsets*) та швидкому перетворенні Волша-Адамара парність розміру підмножини визначає знак доданка:

```
sign = (popcount(mask) & 1) ? -1 : 1;
```

В алгоритмі Райзера для обчислення перманенту матриці розміру `N × N` за допомогою кодів Ґрея знак кожного доданка обчислюється як `(-1)^{popcount(gray)}`. Використання апаратного `popcount` зменшує константу алгоритму в рази, роблячи точні обчислення можливими для матриць розмірності до `N = 40`.

## 7. Практичні рекомендації та типові помилки

1. **Уникайте переповнення при зсувах на розрядність слова:** вираз `1ULL << 64` у мовах C та C++ є невизначеною поведінкою. При генерації масок використовуйте безпечні конструкції:
   ```cpp
   uint64_t mask = (len == 64) ? ~0ULL : ((1ULL << len) - 1ULL);
   ```
2. **Обирайте правильний тип даних:** у C++20 `std::popcount` приймає виключно беззнакові типи (`unsigned int`, `uint64_t`). Передача знакового `int64_t` призведе до помилки компіляції.
3. **Вмикайте прапорці генерації коду:** компілятори GCC та Clang не генерують інструкцію `POPCNT` за замовчуванням для сумісності зі старими CPU. Завжди вказуйте прапорці `-mpopcnt` або `-march=native` для оптимізованих релізів.
4. **Використовуйте пакетну обробку:** для масивів обсягом від кількох кілобайтів векторизовані компресори CSA перевершують послідовний виклик скалярного `POPCNT` завдяки зняттю обмеження на кількість скалярних портів АЛП.
