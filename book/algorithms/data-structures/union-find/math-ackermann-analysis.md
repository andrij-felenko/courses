# 🧮 Математичний аналіз системи неперетинних множин та функції Аккермана

Система неперетинних множин (Disjoint Set Union, DSU) надає математично довершену структуру для підтримання динамічного розбиття скінченної множини на неперетинні класи еквівалентності. На відміну від багатьох інших алгоритмів, складність DSU визначається не логарифмами чи степеневими функціями, а надзвичайно повільно зростаючою оберненою функцією Аккермана.

## 1. Формальна математична постановка: Класи еквівалентності та факторалгебра

Нехай `S` — скінченна множина з `N` елементів. Бінарне відношення еквівалентності `R` на `S` (позначається символом `~`) — це підмножина декартового добутку `S × S`, яка задовольняє три фундаментальні аксіоми абстрактної алгебри:

1. **Рефлексивність**: для будь-якого елемента `x ∈ S` виконується `x ~ x` (або `(x, x) ∈ R`).
2. **Симетричність**: для будь-яких елементів `x, y ∈ S`, якщо `x ~ y`, то обов'язково `y ~ x`.
3. **Транзитивність**: для будь-яких елементів `x, y, z ∈ S`, якщо `x ~ y` та `y ~ z`, то виконується `x ~ z`.

Класом еквівалентності елемента `x ∈ S` (позначається `[x]`) називається підмножина усіх елементів, які знаходяться у відношенні еквівалентності з `x`:

```
[x] = { y ∈ S | x ~ y }
```

Фундаментальна теорема про розбиття стверджує, що сукупність усіх класів еквівалентності утворює факторалгебру або фактормножину `S / ~`, яка володіє двома строгими властивостями:

```
[x] ∩ [y] = ∅   [якщо [x] ≠ [y]: будь-які два класи або не перетинаються, або збігаються]
⋃_[x] ∈ S/~ [x] = S [об'єднання усіх класів покриває весь вихідний простір S]
```

Задача DSU полягає в ефективній підтримці цього динамічного розбиття при виконанні двох базових операцій над елементами `x, y ∈ S`:

- `find(x)`: визначити унікального канонічного представника (корінь) підмножини `[x]`. Двоє елементів `x` та `y` належать одному класу еквівалентності тоді й лише тоді, коли `find(x) = find(y)`.
- `union(x, y)`: якщо `find(x) ≠ find(y)`, утворити новий клас еквівалентності `[z] = [x] ∪ [y]`, модифікуючи фактормножину `S / ~`.

Початковий стан розбиття складається з `N` дискретних класів, де кожен елемент утворює свій власний клас `[x] = {x}`. У процесі виконання послідовності з `M` операцій `union` кількість класів неперетинних множин монотонно зменшується, прямуючи до 1 у граничному випадку повністю зв'язаної системи.

Розглянемо властивість транзитивного замикання. Якщо в систему почергово вводяться пари зв'язків `(x1, x2), (x2, x3), ..., (x_{k-1}, x_k)`, то побудова підсумкового класу еквівалентності відтворює транзитивне замикання графа зв'язків. Механізм DSU дозволяє обчислювати це замикання в режимі реального часу (online) без повторного аналізу всього графа.

Таке розбиття гарантує збереження інваріантів коректності на кожному кроці виконання алгоритму. Кожна підмножина виступає зв'язаною компонентою, а корінь дерева є її унікальним маркерним представником.

## 2. Анатомія висоти дерев: Верхня межа для Union by Rank та Union by Size

Представимо кожну множину як орієнтоване дерево із зануренням покажчиків догори від дочірнього вузла до батьківського. Для кожного вузла `x` введемо величину `rank[x]`, яка початково дорівнює 0 і позначає верхню межу висоти піддерева з коренем у `x`.

За правилом об'єднання за рангом (Union by Rank), при об'єднанні двох коренів `r1` та `r2`:

```
parent[r2] = r1            [якщо rank[r1] > rank[r2]: корінь із меншим рангом підпорядковується більшому]
parent[r1] = r2            [якщо rank[r2] > rank[r1]: аналогічно]
parent[r2] = r1, rank[r1]++ [якщо rank[r1] == rank[r2]: при однаковому ранзі ранг нового кореня зростає на 1]
```

Аналогічно працює об'єднання за розміром (Union by Size), де замість рангу зберігається `size[x]` — кількість вузлів у піддереві, і менше дерево завжди приєднується до більшого.

Доведемо теорему про фундаментальний зв'язок між рангом вузла та мінімальною кількістю елементів у його піддереві.

### Теорема 1 (Мінімальна кількість вузлів у дереві рангу `k`)

Для будь-якого вузла `x` із рангом `rank[x] = k`, кількість вузлів `size(x)` у його піддереві задовольняє нерівність:

```
size(x) ≥ 2^k
```

#### Доведення (методом математичної індукції)

**База індукції (`k = 0`)**:
Початково кожен з `N` елементів створюється як окреме ізольоване дерево з `rank[x] = 0`.
Кількість вузлів у такому дереві `size(x) = 1`.
Перевіряємо базову нерівність:

```
2^0 = 1
1 ≥ 1 [база індукції виконується строго]
```

**Індукційний крок**:
Припустимо, що твердження дійсне для всіх дерев з рангами `< k`.
Ранг вузла `x` може зрости від `k - 1` до `k` лише в одному випадку: коли відбувається операція `union` двох коренів `x` та `y`, які мають абсолютно однакові ранги `rank[x] = k - 1` та `rank[y] = k - 1`.

Після виконання `parent[y] = x` новий ранг `rank'[x]` обчислюється як:

```
rank'[x] = rank[x] + 1
= (k - 1) + 1
= k [ранг кореня x зростав строго на одиницю]
```

Обчислимо нову кількість вузлів `size'(x)` у піддереві кореня `x`:

```
size'(x) = size(x) + size(y)
≥ 2^(k - 1) + 2^(k - 1) [за індукційним припущенням для обох піддерев]
= 2 · 2^(k - 1)
= 2^k [індукційний крок доведено]
```

### Наслідок з Теореми 1: Логарифмічне обмеження висоти

Оскільки загальна кількість елементів у всій системі обмежена числом `N`, для будь-якого кореневого або внутрішнього вузла `x` виконується логарифмічна нерівність:

```
2^(rank[x]) ≤ size(x) ≤ N
rank[x] ≤ log2(N)
```

Враховуючи, що ранг є цілим числом, максимальна висота будь-якого дерева у DSU з використанням лише Union by Rank або Union by Size становить:

```
H_max ≤ ⌊log2(N)⌋
```

Це доводить, що без застосування стиснення шляхів часова складність виконання операцій `find` та `union` у найгіршому випадку не перевищує `O(log N)` операцій.

Звідси також випливає важливе обмеження на кількість вузлів з певним рангом: кількість вузлів із рангом `r` у будь-який момент часу не перевищує `N / (2^r)`. Загальна сума рангів усіх вузлів системи завжди обмежена значенням `O(N)`.

## 3. Ієрархія Аккермана та її обернена функція `α(N)`

Щоб дослідити граничну амортизовану складність при одночасному застосуванні об'єднання за рангом та стиснення шляхів (Path Compression), розглянемо рекурсивну ієрархію функцій Аккермана `A[k](j)` для цілих чисел `k ≥ 0` та `j ≥ 1`.

### Формальне визначення ієрархії функцій Аккермана

Кожен рівень `k` ієрархії визначає швидкоростучу функцію одного аргументу, яка є ітерованою версією функції з попереднього рівня:

```
A[0](j) = j + 1           [0-й рівень: проста інкрементація]
A[1](j) = 2j              [1-й рівень: додавання j сам з собою / множення на 2]
A[2](j) = 2^j · j          [2-й рівень: експоненційне зростання / степені двійки]
A[3](j) = 2^(2^(...))     [3-й рівень: гіперекспонента / вежа степенів двійки висотою j]
A[k](j) = A[k-1]^(j)(1)   [k-й рівень: j-кратна рекурсивна композиція функції A[k-1]]
```

Для математичного аналізу DSU зручно використовувати класичну двоаргументну функцію Аккермана `A(k, j)`:

```
A(0, j) = j + 1
A(k, 0) = A(k - 1, 1)           [при k > 0]
A(k, j) = A(k - 1, A(k, j - 1)) [при k > 0, j > 0]
```

Розгорнемо рекурсію для обчислення `A(2, 2)` щоб продемонструвати швидкість її вибухового зростання:

```
A(2, 2)
= A(1, A(2, 1))          [за базовим рекурсивним визначенням]
= A(1, A(0, A(2, 0)))    [розгортаємо inner A(2, 1)]
= A(1, A(0, A(1, 1)))    [за правилом A(2, 0) = A(1, 1)]
= A(1, A(0, 3))          [оскільки A(1, 1) = 3]
= A(1, 4)                [оскільки A(0, 3) = 4]
= 2 · 4                  [оскільки A(1, j) = 2j]
= 8
```

### Формальне визначення оберненої функції Аккермана `α(N)`

Визначимо двоаргументну обернену функцію `α(M, N)` для послідовності з `M` операцій над множиною з `N` елементів:

```
α(M, N) = min { k ≥ 1 | A(k, ⌊M / N⌋) ≥ log2(N) }
```

У повсякденному алгоритмічному аналізі використовують одноаргументну діагональну обернену функцію:

```
α(N) = min { k ≥ 1 | A(k, 1) ≥ N }
```

Обчислимо значення швидкості зростання `A(k, 1)` для початкових значень рівнів `k`:

```
A(0, 1) = 2
A(1, 1) = 3
A(2, 1) = 5
A(3, 1) = 2047
A(4, 1) = 2^2048 - 1 ≈ 10^616
```

Число `A(4, 1) ≈ 10^616` значно перевищує оцінку кількості атомів у спостережуваному Всесвіті (яка становить приблизно `10^80`). Отже, для будь-яких практичних чи теоретико-числових розмірів даних `N`:

```
α(N) ≤ 4 [для усіх N ≤ 10^600]
```

Це означає, що значення `α(N)` на практиці є невідмінним від невеликої константи.

## 4. Амортизаційне доведення методом потенціалів (Тарджан, 1975)

Амортизований аналіз дозволяє оцінити сумарну вартість послідовності з `M` операцій `find` та `union`, розподіляючи витрати між легкими та важкими операціями за допомогою функції потенціалу `Ф`.

### Рангові інваріанти при стиснення шляхів

Під час виконання операцій `find` зі стисненням шляхів зберігаються наступні інваріанти структури:

1. Якщо вузол `x` втрачає статус кореня, його ранг `rank[x]` заморожується і більше ніколи не змінюється.
2. Для будь-якого некореневого вузла `x` виконується строга нерівність `rank[x] < rank[parent[x]]`.
3. При зміні покажчика `parent[x]` новий ранг батька може лише зростати: `rank[parent'_new[x]] > rank[parent_old[x]]`.

### Визначення октав рангів та потенціалу вузла

Для кожного некореневого вузла `x` введемо рангову октаву `k(x)`, яка показує, у скільки разів ранг батька `rank[parent[x]]` перевищує ранг самого вузла `rank[x]` у масштабі функції Аккермана:

```
k(x) = max { k ≥ 0 | rank[parent[x]] ≥ A[k](rank[x]) }
```

Також введемо другорядну змінну зміщення `j(x)` у межах поточної октави:

```
j(x) = max { j ≥ 1 | rank[parent[x]] ≥ A[k(x)]^(j)(rank[x]) }
```

Визначимо потенціал `Ф(x)` для кожного вузла `x`:

```
Ф(x) = (α(N) - k(x)) · rank[x] - j(x) [для некореневих вузлів]
Ф(r) = α(N) · rank[r]                  [для коренів r]
```

Загальний потенціал всієї системи даних `Ф = ∑_{x ∈ S} Ф(x)` завжди задовольняє умову невід'ємності: `Ф ≥ 0`.

### Аналіз амортизованої вартості операції `find(v)`

Нехай шлях від вузла `v` до кореня `r` складається з `L` ребер. Реальна часова складність обходу становить `t = L` кроків.

Під час стиснення шляху покажчики всіх `L` вузлів перевизначаються на корінь `r`. Розглянемо зміну потенціалу для вузла `x` на шляху:

1. Якщо внаслідок наближення до кореня ранг нового батька `rank[r]` стає достатньо великим, щоб збільшити октаву `k(x)` хоча б на 1, потенціал вузла `Ф(x)` зменшується щонайменше на `rank[x] ≥ 1`.
2. Вивільнена енергія потенціалу `ΔФ(x) = Ф_old(x) - Ф_new(x)` повністю покриває реальну вартість переходу через ребро для даного вузла.

Обчислимо сумарну амортизовану вартість `a_i` для `i`-ї операції `find`:

```
a_i = t_i + Ф_after - Ф_before
≤ α(N) + 1 [амортизована вартість однієї операції]
```

Сумуючи амортизовані витрати для послідовності з `M` операцій `find` та `N` операцій `union`, отримуємо загальну складність:

```
T_total = ∑_{i=1}^M a_i
= O(M · α(M, N) + N)
```

Це математично доводить, що амортизований час виконання кожної операції у DSU зі стисненням шляхів та об'єднанням за рангом становить `O(α(N))`.

## 5. Модифікації стиснення шляхів: Path Halving та Path Splitting

На практиці замість повного двохпрохідного стиснення шляху (яке вимагає додаткового рекурсивного стеку або збереження проміжних вузлів) часто використовують однопрохідні альтернативи:

### 1. Розщеплення шляху (Path Splitting)

Під час обходу від `x` до кореня покажчик кожного вузла перенаправляється на його "діда" (parent of parent):

```
parent[x] = parent[parent[x]]
```

Це виконується для кожного вузла уздовж шляху під час одного проходу.

### 2. Уполовинення шляху (Path Halving)

Покажчик перевизначається лише для кожного другого вузла уздовж шляху:

```
parent[x] = parent[parent[x]]
x = parent[x]
```

### Математична еквівалентність

Тарік Тарджан та Роберт ван Леувен (Robert van Leeuwen) у 1984 році довели, що обидва однопрохідні варіанти (Path Halving та Path Splitting) зберігають абсолютно тотожну амортизовану верхню межу складності `O(α(N))`. Хоча дерево сплющується дещо повільніше, відсутність второго проходу та збереження локальності даних у кеші робить Path Halving найшвидшою практичною стратегією.

## 6. Аналіз складності Rollback DSU (відкочуваний DSU)

При використанні DSU у задачі динамічної зв'язності графа з можливістю видалення ребер (або при обході дерева рішень у алгоритмах оптимізації) виникає потреба скасовувати операції `union`.

Оскільки стиснення шляху безповоротно руйнує оригінальну топологію дерева, його застосування у Rollback DSU заборонене. Використовується лише Union by Rank або Union by Size.

### Оцінка складності Rollback DSU

Завдяки збереженню Union by Rank, максимальна висота будь-якого дерева строго обмежена `⌊log2(N)⌋`.

1. Операція `find(x)` виконує прохід до кореня без зміни покажчиків: `O(log N)` у найгіршому випадку.
2. Операція `union(x, y)` зберігає у стек відкоту запис про змінений покажчик `parent[r2] = r1` та факт збільшення рангу `rank[r1]`: `O(log N)` часу та `O(1)` додаткової пам'яті.
3. Операція `undo()` знімає останній запис зі стеку та відновлює попередні значення у пам'яті: `O(1)` часу.

Отже, Rollback DSU гарантує строго `O(log N)` часу на операції `find` та `union`, та `O(1)` на операцію `undo()`.

## 7. Математичні зважені DSU та парність шляхів

При розв'язанні задач перевірки дводольності графа або підтримання потенціалів на ребрах, кожен вузол `x` зберігає не лише покажчик `parent[x]`, а й величину відносної ваги або парності `weight[x]`, що описує зміщення між `x` та його батьком.

Під час стиснення шляхів у зваженому DSU виконується перевизначення потенціалу:

```
weight_new[x] = weight_old[x] ⊕ weight_old[parent[x]]
parent_new[x] = parent_old[parent[x]]
```

Де `⊕` позначає групову операцію (наприклад, додавання за модулем 2 для перевірки дводольності або додавання векторів у евклідовому просторі).

Доведено, що долучення групової операції до стиснення шляху не змінює амортизовану складність `O(α(N))`, оскільки кількість оновлень ваг уздовж шляху точно збігається з кількістю перевизначень батьківських покажчиків.

## 8. Математична складність паралельного Lock-free DSU

У багатопотокових середовищах об'єднання множин реалізується без м'ютексів за допомогою атомарної інструкції Compare-And-Swap (CAS).

Математичний аналіз гонок за дані (data races) у паралельному DSU показав, що при роботі `P` паралельних потоків складність однієї операції становить:

```
T_parallel = O(α(N) + C)
```

Де `C` — кількість невдалих операцій `CAS`, спричинених конкурентними змінами кореневих покажчиків іншими потоками. У середовищах із помірною конкуренцією `C` є константою в середньому.

У найгіршому випадку високої конкуренції (коли багато потоків одночасно намагаються об'єднати один і той самий корінь) кількість невдалих спроб `CAS` для одного потоку може досягати `O(P)`. Проте в середовищі з рівномірно розподіленими запитами об'єднання ймовірність конфлікту на конкретному корені прямує до нуля зі зростанням `N`.

## 9. Нижня межа у моделі коміркового зонда (Фредман-Сакс, 1989)

Дослідження Майкла Фредмана та Майкла Сакса у 1989 році встановили фундаментальну нижню межу обчислень для динамічної проблеми неперетинних множин.

У моделі коміркового зонда (cell-probe model) алгоритм розглядається як послідовність звернень до комірок пам'яті розміром `w` біт. Усі обчислення всередині процесора вважаються безкоштовними, а вимірюється лише кількість операцій читання/запису пам'яті.

### Теорема 2 (Нижня межа Фредмана-Сакса)

Для будь-якої структури даних, яка реалізує `N` операцій `union` та `M` операцій `find` над `N` елементами у моделі коміркового зонда з розміром комірки `w ≥ log2(N)` біт, загальна кількість звернень до пам'яті задовольняє нерівність:

```
T_probe = Ω(M · α(M, N) + N)
```

Це доводить, що комбінація Union by Rank та Path Compression досягає абсолютного теоретичного мінімуму складности, який неможливо перевищити жодним алгоритмом у класичній архітектурі комп'ютерів.

## 10. Практичні значення `α(N)` для реальних обчислювальних систем

Для ілюстрації швидкості зростання наведемо значення `α(N)` для різних масштабів обробки даних:

```
Розмір даних N      | Значення α(N) | Опис масштабу даних
-------------------+---------------+------------------------------------
N = 10             | 1             | Невеликий масив / навчальний приклад
N = 100            | 2             | Локальна граф-структура
N = 1 000 000      | 3             | 1 мільйон елементів (RAM сервера)
N = 10^9           | 3             | 1 мільярд елементів (Велика БД)
N = 10^80          | 4             | Кількість атомів у Всесвіті
N = 10^600         | 4             | Абсолютна межа для α(N) <= 4
```

Оскільки `α(N) ≤ 4` для будь-яких можливих розмірів систем, розробники програмного забезпечення можуть розглядати часову складність DSU як практично константну `O(1)` у реальних інженерних розрахунках.

## 11. Порівняльний математичний підсумок стратегій

У наведеній таблиці підсумовано асимптотичну складність операцій DSU для різних комбінацій еристик:

```
Стратегія об'єднання | Стиснення шляху | Складність find(x) | Складність union(x, y) | Найгірший випадок
--------------------+-----------------+--------------------+------------------------+------------------
Без еристик         | Ні              | O(N)               | O(N)                   | O(N)
Quick-Find (масив)  | Ні              | O(1)               | O(N)                   | O(N)
Union by Rank/Size  | Ні              | O(log N)           | O(log N)               | O(log N)
Без еристик         | Повне (Full)    | O(log N)           | O(log N)               | O(log N)
Union by Rank/Size  | Path Compression| O(α(N))            | O(α(N))                | O(α(N)) (аморт.)
Union by Rank/Size  | Path Halving    | O(α(N))            | O(α(N))                | O(α(N)) (аморт.)
Union by Rank/Size  | Path Splitting  | O(α(N))            | O(α(N))                | O(α(N)) (аморт.)
Union by Rank (Roll)| Заборонено      | O(log N)           | O(log N) [undo: O(1)]  | O(log N)
```

Завдяки цьому математичному аналізу підтверджується, що поєднання Union by Rank та Path Compression (або Path Halving) забезпечує оптимальну ефективність, яку неможливо перевищити в рамках класичної покажчикової та коміркової моделей обчислень.
