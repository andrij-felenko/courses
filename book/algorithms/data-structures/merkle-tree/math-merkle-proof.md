# 🧮 Математична модель та криптографічні гарантії Дерева Меркла

Математична строгість Дерева Меркла спирається на комбінацію криптографічних властивостей односторонніх хеш-функцій та геометричних інваріантів збалансованого двійкового дерева. У цьому додатку подано формальне математичне виведення параметрів дерева, асимптотичний аналіз складності обчислень, алгебраїчну модель доказу включення, доведення захисту від колізій (security reduction) та математичний аналіз криптографічних атак другого прообразу.

## 1. Формальне визначення та аксіоматика

Нехай `H: {0, 1}* → {0, 1}^b` є детермінованою криптографічною хеш-функцією, яка відображає бінарну послідовність довільної довжини у бінарний вектор фіксованої довжини `b` біт (наприклад, `b = 256` біт у разі використання стандартів SHA-256 або BLAKE3).

Припустимо, що вхідні дані подано у вигляді послідовності з `N` впорядкованих бінарних блоків:

```
D = (d₀, d₁, d₂, ..., d_{N-1}),   де кожне d_i ∈ {0, 1}*
```

Для побудови незламної криптографічної структури визначаються дві математичні операції з додаванням префікса розділення доменів (domain separation):

### Операція 1: Отримання листка (Leaf Hasher)
Кожен блок даних `d_i` відображається у листовий вузол `L_i` шляхом конкатенації з однобайтним префіксом `0x00`:

```
L_i = H(0x00 || d_i),   для всіх i ∈ [0, N - 1]
```

Префікс `0x00` фіксує той факт, що аргументом хеш-функції є первинні дані користувача, а не внутрішні структури дерева.

### Операція 2: Об'єднання двох вузлів (Node Combiner)
Для двох довільних вузлів `X, Y ∈ {0, 1}^b` функція об'єднання обчислює батьківський вузол із використанням префікса `0x01`:

```
Combine(X, Y) = H(0x01 || X || Y)
```

Префікс `0x01` гарантує, що результат хешування внутрішнього вузла лежить у строго відмінній криптографічній області від листків.

## 2. Геометричні характеристики та виведення параметрів

Розглянемо дерево, побудоване над `N` листками. Для забезпечення формальної симетрії припустимо на першому етапі, що `N = 2^h`, де `h ∈ ℕ` є цілим числом.

### Висота дерева `h`
Висота дерева `h` визначається як кількість ребер у найдовшому шляху від кореня до будь-якого листка. Оскільки на кожному підйомі кількість вузлів зменшується вдвічі, висота обчислюється через подвійний логарифм:

```
h = ⌈log₂ N⌉
```

Для масиву з `N = 1` елемента висота `h = 0` (дерево складається з єдиного листка, який сам є коренем). Для `N = 1 048 576` (мільйон елементів) висота дорівнює `h = 20`.

### Загальна кількість вузлів `M`
Загальна кількість вузлів `M` у повному двійковому дереві висоти `h` обчислюється як сума геометричної прогресії:

```
M = ∑_{k=0}^{h} 2^k
  = 2^(h+1) - 1
  = 2 · 2^h - 1
  = 2N - 1           [оскільки N = 2^h]
```

Звідси випливає фундаментальний інваріант: **кількість внутрішніх вузлів у повному двійковому дереві дорівнює `N - 1`**, а загальний обсяг пам'яті для зберігання всіх вузлів становить `(2N - 1) · b` біт, що є лінійною величиною `O(N)`.

## 3. Асимптотична складність операцій

Нижче наведено строгий асимптотичний аналіз основних алгоритмів роботи з Деревом Меркла:

```
+--------------------------+-----------------------+------------------------+
| Операція                 | Часова складність     | Просторова складність  |
+--------------------------+-----------------------+------------------------+
| Побудова повного дерева  | Θ(N)                  | Θ(N)                   |
| Генерація Proof          | O(log N)              | O(log N)               |
| Верифікація Proof        | O(log N)              | O(1)                   |
| Оновлення одного листка  | O(log N)              | O(1)                   |
+--------------------------+-----------------------+------------------------+
```

### Доведення складності побудови
Побудова дерева вимагає обчислення `N` листових хешів та `N - 1` внутрішніх хешів. Загальна кількість викликів хеш-функції дорівнює:

```
T(N) = N + (N - 1) = 2N - 1
```

Оскільки обчислення хешу для одного блока виконується за сталий час `O(1)` (для блоків однаковісінького розміру), сумарна часова складність є строго лінійною `Θ(N)`.

### Доведення складності верифікації
Перевірка доказу включення вимагає обчислення `1` листового хешу та `h = ⌈log₂ N⌉` внутрішніх хешів об'єднання. Загальна кількість обчислень хешів дорівнює:

```
T_verify(N) = 1 + ⌈log₂ N⌉
```

Оскільки `1 + ⌈log₂ N⌉ ∈ O(log N)`, час перевірки зростає надзвичайно повільно. Наприклад, для 1 мільярда елементів (`N = 10⁹`) потрібно виконати лише 31 операцію хешування, що займе менше 10 мікросекунд на сучасному процесорі.

## 4. Алгебраїчна модель доказу включення (Merkle Inclusion Proof)

Формально доказ включення (Merkle Proof) для `k`-го елемента `d_k` (де `0 <= k < N`) є послідовністю впорядкованих пар, кожна з яких містить сестринське хеш-значення та біт напрямку:

```
P_k = ( (S₁, dir₁), (S₂, dir₂), ..., (S_h, dir_h) )
```

де `S_i ∈ {0, 1}^b` — сестринський хеш на рівні `i`, а `dir_i ∈ {LEFT, RIGHT}` вказує, з якого боку розташована сестра відносно поточного піддерева.

### Алгоритм обчислення напрямків через двійкові біти індексу
Напрямок `dir_i` на кожному рівні `i` (від 1 до `h`) визначається `(i-1)`-им бітом двійкового представлення індексу `k`:

```
dir_i = LEFT,   якщо (k >> (i - 1)) & 1 == 1
dir_i = RIGHT,  якщо (k >> (i - 1)) & 1 == 0
```

Якщо біт дорівнює `0`, поточний вузол є лівим нащадком, тому його сестра розташована праворуч (`RIGHT`). Якщо біт дорівнює `1`, поточний вузол є правим нащадком, і сестра лежить ліворуч (`LEFT`).

### Рекурсивне правило відновлення кореня
Перевірник обчислює послідовність кандидатів вузлів `V₀, V₁, ..., V_h`:

```
V₀ = H(0x00 || d_k)

V_i = Combine(S_i, V_{i-1}) = H(0x01 || S_i || V_{i-1}),  якщо dir_i == LEFT
V_i = Combine(V_{i-1}, S_i) = H(0x01 || V_{i-1} || S_i),  якщо dir_i == RIGHT
```

Якщо після виконання `h` кроків кандидат `V_h` збігається з офіційно відомим коренем `R` (`V_h == R`), то елемент `d_k` визнається дійсним і належним даному Дереву Меркла.

## 5. Доведення криптографічної стійкості (Security Reduction)

Головною криптографічною гарантією Дерева Меркла є його **стійкість до підробки доказу** (Unforgeability).

### Теорема про безпеку
Якщо базово вжита хеш-функція `H` є стійкою до пошуку колізій (collision-resistant), то жоден ймовірнісний алгоритм із поліноміальним часом виконання (PPT-зловмисник) не здатний створити підроблений доказ `P*` для фальшивого елемента `d* ∉ D`, який би задовольнив умову `Verify(d*, P*, R) = true`, за винятком нехтовно малої ймовірності `ε`.

### Доведення методом зведення від супротивного (Reduction Proof)
Припустимо від протилежного, що існує ефективний зловмисник `Adv`, який здатний згенерувати фальшивий елемент `d* ∉ D` та підроблений доказ `P* = ((S₁*, dir₁*), ..., (S_h*, dir_h*))`, такі що обчислений корінь `V_h*` дорівнює справжньому кореню `R`.

Побудуємо редукційний алгоритм `B`, який використовує `Adv` як субрутину для знаходження колізії базової хеш-функції `H`:

1. Алгоритм `B` будує істинне Дерево Меркла над початковим масивом `D`, отримуючи коректні вузли `(V₀, V₁, ..., V_h = R)`.
2. Алгоритм `B` запускає `Adv` і отримує фальшиву трійку `(d*, P*, R)`.
3. Алгоритм `B` обчислює ланцюжок фальшивих вузлів `(V₀*, V₁*, ..., V_h*)`.
4. Оскільки `d* ∉ D`, початкові листові хеші розходяться: `V₀* = H(0x00 || d*) ≠ V₀ = H(0x00 || d_k)`.
5. Проте на останньому рівні маємо тотожність: `V_h* = V_h = R`.
6. Отже, уздовж ланцюжка від `0` до `h` обов'язково існує хоча б один найвищий рівень `j ∈ [1, h]`, на якому аргументи розходяться, але результати хешування збігаються:

```
V_j* = V_j
проте (Input_Left*, Input_Right*) ≠ (Input_Left, Input_Right)
```

7. Це означає, що пара бінарних векторів `(0x01 || Input_Left* || Input_Right*)` та `(0x01 || Input_Left || Input_Right)` утворює явну **колізію** для хеш-функції `H`, оскільки два різних входи дають однакове хеш-значення.
8. Оскільки хеш-функція `H` за припущенням є стійкою до колізій (знаходження колізії вимагає `O(2^(b/2))` операцій за парадоксом днів народження), існування такого зловмисника `Adv` є неможливим. Теорему доведено.

## 6. Математичний захист від атак другого прообразу (Second Pre-image Attack)

Розглянемо математичні наслідки відмови від префіксів доменів (`0x00` та `0x01`). Нехай хеш обчислюється просто як `H(x)` для даних та `H(A || B)` для вузлів.

### Механіка створення фальшивого доказу
Розглянемо дерево з 4 елементів: `L₁ = H(d₁), L₂ = H(d₂), L₃ = H(d₃), L₄ = H(d₄)`.
Внутрішні вузли: `N₁₂ = H(L₁ || L₂)` та `N₃₄ = H(L₃ || L₄)`.
Корінь: `R = H(N₁₂ || N₃₄)`.

Зловмисник хоче видати зліплену послідовність байтів `d* = L₁ || L₂` за новий листовий блок даних.

Без префіксів доменів «листовий» хеш цього позолоченого блока дорівнюватиме:

```
H(d*) = H(L₁ || L₂) = N₁₂
```

Тепер зловмисник формує короткий підроблений доказ усього з одного кроку: `P* = ((N₃₄, RIGHT))`.

Перевірник обчислює:
```
V₀* = H(d*) = N₁₂
V₁* = H(V₀* || N₃₄) = H(N₁₂ || N₃₄) = R
```

Доказ повністю пройшов верифікацію! Зловмисник зрізав глибину дерева з 2 до 1 і видав внутрішній вузол за листок.

### Математичний блок префіксами доменів
Введення префіксів створює дві ортогональні підпростори значень:

```
Space_Leaf = { H(0x00 || x) | x ∈ {0, 1}* }
Space_Internal = { H(0x01 || y) | y ∈ {0, 1}* }
```

Якщо зловмисник подає `d* = L₁ || L₂`, то листовий хеш обчислиться як:

```
V₀* = H(0x00 || L₁ || L₂)
```

Проте внутрішній вузол обчислено як:
```
N₁₂ = H(0x01 || L₁ || L₂)
```

Завдяки стійкості `H` до колізій маємо строгу нерівність `H(0x00 || L₁ || L₂) ≠ H(0x01 || L₁ || L₂)`. Можливість підробки доказу зрізанням глибини повністю ліквідовано.

## 7. Покроковий числовий приклад розрахунку

Розглянемо масив із `N = 4` елементів: `D = ("A", "B", "C", "D")`.
Застосуємо умовну 16-бітну хеш-функцію, яка повертає 4-символьний шістнадцятковий хеш.

### Крок 1: Хешування листків
```
L₀ = H(0x00 || "A") = 0xa1b2
L₁ = H(0x00 || "B") = 0xc3d4
L₂ = H(0x00 || "C") = 0xe5f6
L₃ = H(0x00 || "D") = 0x789a
```

### Крок 2: Хешування внутрішніх вузлів
```
N₀₁ = H(0x01 || 0xa1b2 || 0xc3d4) = 0x1122
N₂₃ = H(0x01 || 0xe5f6 || 0x789a) = 0x3344
```

### Крок 3: Хешування кореня
```
Merkle Root R = H(0x01 || 0x1122 || 0x3344) = 0x9999
```

### Крок 4: Створення доказу для елемента "B" (k = 1, двійкове 01)
- На рівні 1: сестра `L₀ = 0xa1b2`, напрямок `LEFT`.
- На рівні 2: сестра `N₂₃ = 0x3344`, напрямок `RIGHT`.
- Доказ `P₁ = [ (0xa1b2, LEFT), (0x3344, RIGHT) ]`.

### Крок 5: Перевірка доказу перевірником
1. Перевірник обчислює `V₀ = H(0x00 || "B") = 0xc3d4`.
2. Крок 1 (`LEFT`): `V₁ = H(0x01 || 0xa1b2 || 0xc3d4) = 0x1122`.
3. Крок 2 (`RIGHT`): `V₂ = H(0x01 || 0x1122 || 0x3344) = 0x9999`.
4. Звірка: `V₂ == R` (`0x9999 == 0x9999`). Елемент "B" визнано дійсним за 2 кроки.
