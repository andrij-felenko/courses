# 📋 Порівняльна довідка інтерфейсів масивів у C та C++

Контракти інтерфейсів, параметри складності операцій, правила безпеки та характеристики розташування в пам'яті визначають роботу п'яти основних форм масивів у мовах C та C++: статичного масиву C, `std::array`, динамічного масиву C, `std::vector` та абстракції неволодіючого зрізу `std::span`.

При проектуванні системного та прикладного програмного забезпечення вибір конкретного різновиду масиву визначає не лише зручність написання коду, але й фундаментальні характеристики виконання: рівень накладних витрат оперативної пам'яті, локальність процесорного кешу L1/L2, ймовірність виникнення помилок виходу за межі пам'яті та можливість застосування векторних інструкцій SIMD.

## Сведена матриця характеристик масивів

При виборі структури даних оцінюються час виділення, накладні витрати пам'яті, локальність кешу та захист від помилок індексації.

| Характеристика | Статичний масив C (`T a[N]`) | `std::array<T, N>` | Динамічний масив C (`T* p`) | `std::vector<T>` | `std::span<T>` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Місце виділення** | Стек / Сегмент BSS | Стек / Сегмент BSS | Купа (Heap) | Купа (Heap) | Не виділяє (View) |
| **Фіксація розміру** | Під час компіляції | Під час компіляції | Під час виконання | Динамічна зміна | Фіксована/Динамічна |
| **Накладні витрати пам'яті** | 0 байтів | 0 байтів | 8–16 байтів (`size`, `cap`) | 24 байти (3 вказівники) | 16 байтів (`ptr` + `size`) |
| **Доступ за індексом** | `O(1)` | `O(1)` | `O(1)` | `O(1)` | `O(1)` |
| **Вставка в кінець** | N/A | N/A | `O(1)` амортизовано | `O(1)` амортизовано | N/A |
| **Вставка в середину** | N/A | N/A | `O(n)` | `O(n)` | N/A |
| **Перевірка меж (Bounds)** | Відсутня (UB) | `.at(i)` перевіряє | Відсутня (UB) | `.at(i)` перевіряє | Залежить від субіндексу |
| **Array Decay у вказівник** | Автоматичний | Заборонений | Вже є вказівником | Заборонений | Заборонений |
| **Локальність кешу** | Абсолютна | Абсолютна | Висока (у купі) | Висока (у купі) | Відповідає джерелу |

## 1. Статичний C-масив (`T a[N]`)

Статичний масив мови C являє собою найпростішу безпосередню обгортку над безперервним блоком пам'яті. Розмір масиву `N` вимагає обов'язкової фіксації під час компіляції (за винятком константних виразів або динамічних масивів на стеку VLA, введених у C99, використання яких у сучасній розробці не рекомендується з міркувань безпеки).

### Основний контракт та синтаксис

:::tabs
```c
// Оголошення статичного масиву на 10 елементів
int arr[10]; 

// Ініціалізація зі списком значений
int arr_init[5] = {1, 2, 3, 4, 5};

// Доступ за індексом (перевірка меж відсутня)
int val = arr[2]; // Еквівалентно: *(arr + 2)
```
```cpp
// У C++ статичний масив C підтримується для сумісності з C:
int arr[10];

// Ініціалізація у C++
int arr_init[5] = {1, 2, 3, 4, 5};

// Доступ через покажчикову арифметику
int val = arr[2]; // Еквівалентно: *(arr + 2)
```
:::

### Детальний аналіз небезпек та пасток контракту
- **Явище Array Decay (Розпад масиву):** При передачі масиву у функцію як аргумента або при присвоєнні вказівнику ім'я масиву `arr` автоматично втрачає інформацію про тип масиву і розпадається у звичайний покажчик на перший елемент `int*`. Будь-яка інформація про початкову довжину `N` втрачається на етапі компіляції.
- **Втрата семантики `sizeof`:** Оператор `sizeof(arr)` повертає повний обсяг масиву у байтах (`N · sizeof(T)`) лише в тій області видимості (scope), де цей масив було безпосередньо оголошено. Усередині будь-якої функції, що прийняла масив як параметр `void foo(int arr[])`, оператор `sizeof(arr)` поверне розмір покажчика (8 байтів на 64-бітних архітектурах), що часто стає причиною важкопомітних багів.
- **Прихований Buffer Overflow:** Оператор `arr[i]` реалізований через покажчикову арифметику `*(arr + i)` і не виконує жодних апаратних чи програмних перевірок умови `0 ≤ i < N`. Запис за межами виділеного діапазону руйнує сусідні змінні на стеку або адресний простір програми (Undefined Behavior).

## 2. Контейнер `std::array<T, N>` (C++11)

Контейнер `std::array<T, N>` є стандартною обгорткою мови C++ над статичним C-масивом. Він реалізує концепцію Zero-Overhead Abstraction: у бінарному коді `std::array` займає точно стільки ж пам'яті, скільки й звичайний C-масив (`N · sizeof(T)` байтів), але надає повний об'єктний інтерфейс контейнера STL.

### Публічний API та методи класу

```cpp
#include <array>

std::array<int, 5> arr = {10, 20, 30, 40, 50};

// Операції доступу до елементів
int& v1 = arr[0];       // O(1), без перевірки меж (швидкий доступ)
int& v2 = arr.at(0);    // O(1), перевіряє межі й кидає std::out_of_range
int& v3 = arr.front();  // Доступ до першого елемента (еквівалент arr[0])
int& v4 = arr.back();   // Доступ до останнього елемента (еквівалент arr[N-1])
int* p  = arr.data();   // Прямий сирий вказівник для сумісності з C-API

// Метадані та розмірність
constexpr std::size_t s = arr.size();     // Повертає N як константу компіляції
constexpr bool e        = arr.empty();    // Повертає true, якщо N == 0

// Методи модифікації
arr.fill(0);            // Заповнює всі елементи значенням 0
```

### Ключові переваги порівняно зі статичним C-масивом
1. **Захист від Array Decay:** Об'єкт `std::array` не розпадається у покажчик при передачі у функції. Він зберігає інформацію про тип і розмір `N`.
2. **Семантика значень (Value Semantics):** Підтримується повноцінне копіювання та присвоєння `arr1 = arr2`, що виконує глибоке копіювання елементів.
3. **Програмний захист меж:** Метод `.at(index)` гарантує безпеку виконання, викидаючи виняток `std::out_of_range` при виході за межі.
4. **Повна сумісність із STL:** Підтримує стандартні ітератори `.begin()`, `.end()`, що дозволяє використовувати масив у алгоритмах `std::sort`, `std::find`, `std::accumulate`.

## 3. Динамічний C-масив (`malloc` / `free`)

Коли розмір масиву невідомий на етапі компіляції і визначається під час виконання програми, у мові C використовують динамічне виділення пам'яті у купі (Heap) через системні функції `malloc`, `calloc`, `realloc` та `free`.

### Публічний C API та управління пам'яттю

:::tabs
```c
#include <stdlib.h>

// 1. Виділення пам'яті
size_t n = 100;
int *arr = (int *)malloc(n * sizeof(int));
if (!arr) {
    // Обробка помилки браку пам'яті
}

// 2. Ініціалізація нулями (альтернатива через calloc)
int *zero_arr = (int *)calloc(n, sizeof(int));

// 3. Динамічна зміна розміру
size_t new_n = 200;
int *temp = (int *)realloc(arr, new_n * sizeof(int));
if (temp) {
    arr = temp;
} else {
    // У разі помилки старий блок arr залишається дійсним!
}

// 4. Обов'язкове звільнення пам'яті
free(arr);
arr = NULL;
```
```cpp
#include <memory>
#include <vector>

// 1. У C++ замість сирого malloc/free для динамічного масиву використовують std::unique_ptr<int[]>
std::size_t n = 100;
auto arr = std::make_unique<int[]>(n);

// 2. Або контейнер std::vector для динамічного розміру
std::vector<int> vec(n, 0); // Ініціалізація нулями

// 3. Зміна розміру у C++ (RAII автоматично звільняє пам'ять)
vec.resize(200);
```
:::

### Системні ризики та типові помилки розробки
- **Витоки пам'яті (Memory Leaks):** Якщо покажчик на виділений блок втрачається без виклику `free(arr)`, виділена пам'ять залишається зайнятою до завершення процесу.
- **Покажчики, що висять (Dangling Pointers):** Використання покажчика після виклику `free(arr)` призводить до читання або перезапису чужих даних у купі (Use-After-Free).
- **Подвійне звільнення (Double Free):** Повторний виклик `free()` для одного й того ж покажчика руйнує внутрішні службові структури даних аллокатора пам'яті.

## 4. Контейнер `std::vector<T>` (C++ Standard Library)

`std::vector<T>` є головним послідовним динамічним контейнером у мові C++. Він повністю автоматизує управління пам'яттю у купі на основі концепції RAII (Resource Acquisition Is Initialization), самостійно виділяючи та звільняючи буфер при створенні й знищенні об'єкта.

### Внутрішня структура об'єкта `std::vector`
На більшості 64-бітних платформ об'єкт `std::vector` займає всього 24 байти у пам'яті (три 8-байтові покажчики):
1. `T* begin_` — вказівник на перший елемент у динамічному буфері.
2. `T* end_` — вказівник на елемент, що слідує за останнім створеним елементом (`begin_ + size`).
3. `T* end_of_storage_` — вказівник на кінець виділеної області пам'яті (`begin_ + capacity`).

### Специфікація методів API та складність операцій

| Метод | Складність | Опис контракту |
| :--- | :--- | :--- |
| `push_back(val)` | `O(1)` амортизовано, `O(n)` найгірший | Додає елемент у кінець; при `size == capacity` виконує розширення буфера. |
| `emplace_back(args...)` | `O(1)` амортизовано | Конструює елемент безпосередньо в буфері вектора без зайвого копіювання. |
| `pop_back()` | `O(1)` | Вилучає останній елемент, викликаючи його деструктор. |
| `operator[](i)` | `O(1)` | Прямий доступ за індексом без перевірки меж. |
| `at(i)` | `O(1)` | Доступ із програмною перевіркою меж (викидає `std::out_of_range`). |
| `reserve(n)` | `O(n)` якщо `n > cap` | Заздалегідь виділяє пам'ять для `n` елементів, запобігаючи зайвим реалокаціям. |
| `resize(n)` | `O(|n - size|)` | Змінює кількість елементів у векторі (дотворює або знищує елементи). |
| `clear()` | `O(n)` | Знищує всі елементи, але **не звільняє** виділену місткість (capacity). |
| `shrink_to_fit()` | `O(n)` | Запит на зменшення `capacity` до поточного `size` для звільнення пам'яті. |

### Правила інвалідації ітераторів та покажчиків
При роботі з `std::vector` розробник повинен суворо враховувати правила інвалідації посилань:
- **При перевиділенні пам'яті (Reallocation):** Якщо вставка елемента спричиняє зростання `size > capacity`, виділяється новий буфер, а всі існуючі ітератори, покажчики та посилання на елементи вектора стають повністю **інвалідними** (Dangling References).
- **При вставці або вилученні в середині:** Інвалідними стають усі ітератори та посилання починаючи від позиції вставки/вилучення і до кінця вектора.

### Спеціалізація `std::vector<bool>` та її пастки
У C++ Стандартній бібліотеці контейнер `std::vector<bool>` має бітову спеціалізацію: кожен елемент упаковується в один біт пам'яті замість цілого байта. Це економить пам'ять у 8 разів, але руйнує базовий контракт векторів: оператор `operator[]` повертає не посилання `bool&` (оскільки окремий біт не має власної адреси в байтовій пам'яті), а проксі-об'єкт `std::vector<bool>::reference`. Це унеможливлює отримання покажчика на елемент `&vec[0]`. У високопродуктивному коді замість `std::vector<bool>` використовують `std::vector<uint8_t>` або `std::bitset`.

## 5. Неволодіючий зріз `std::span<T>` (C++20)

`std::span<T>` — це легковажна, неволодіюча абстракція (View), уведена у C++20. Вона надає єдиний безпечний інтерфейс до будь-якої безперервної послідовності елементів у пам'яті (будь то статичний C-масив, `std::array`, `std::vector` чи сирий динамічний вказівник із довжиною).

### Публічний API та синтаксис використання

```cpp
#include <span>
#include <vector>
#include <array>
#include <iostream>

// Функція приймає зріз будь-якого неперервного масиву
void process_elements(std::span<const int> s) {
    std::cout << "Розмір зрізу: " << s.size() << " елементів\n";
    for (int val : s) {
        std::cout << val << " ";
    }
    std::cout << "\n";
}

int main() {
    int raw_arr[4] = {1, 2, 3, 4};
    std::array<int, 4> std_arr = {10, 20, 30, 40};
    std::vector<int> vec = {100, 200, 300, 400};

    // span уніфікує виклики без копіювання даних та без виділення пам'яті
    process_elements(raw_arr);
    process_elements(std_arr);
    process_elements(vec);

    // Створення підзрізу (subspan)
    process_elements(vec.size() > 2 ? std::span<const int>(vec).subspan(1, 2) : std::span<const int>());
}
```

### Головні переваги `std::span`
1. **Поліморфізм без накладних витрат:** `std::span` дозволяє писати універсальні функції, що приймають будь-які масиви, без віртуальних функцій і без генерації багатьох шаблонів.
2. **Мінімальні накладні витрати:** Об'єкт `std::span` складається лише з двох полів — вказівника на початок пам'яті та розміру (всього 16 байтів). Він передається у функції за значенням.
3. **Безпечне зрізання (Subspans):** Надає зручні методи `.first(count)`, `.last(count)` та `.subspan(offset, count)` для створення зрізів без ризику виходу за межі пам'яті.
