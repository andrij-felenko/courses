# 🧮 Математика фільтра Кукушки: хибні спрацьовування, ємність та ймовірність витіснення

Фільтр Кукушки є ймовірнісною структурою даних, геометрична компактність та надійність якої спираються на строгий математичний зв'язок між трьома параметрами: довжиною відбитка `f` у бітах, кількістю слотів у кошику `b` (асоціативністю) та цільовою ймовірністю хибного спрацьовування `ε` (false positive rate, FPR).

Нижче наведено строге виведення формули хибного спрацьовування, розрахунок оптимального розміру відбитка, інформаційно-теоретичні нижні оцінки пам'яті, аналіз фазового переходу заповнення таблиці та ймовірнісні межі для довжини ланцюжка витіснень.

## Виведення ймовірності хибного спрацьовування

Нехай фільтр складається з `m` кошиків, кожен із яких містить `b` слотів для збереження `f`-бітних відбитків. Кожен відбиток генерується рівномірною хеш-функцією, тому набуває одного з `2ᶠ` можливих значень із однаковою ймовірністю `1 / 2ᶠ`.

Під час перевірки елемента `y`, який **не належить** множині, алгоритм обчислює його відбиток `f_y = fingerprint(y)` та перевіряє рівно два кошики: `T[i₁]` та `T[i₂]`. Загальна кількість слотів, що інспектуються під час запиту, становить:

```
slots_checked = 2 · b    [два кошики по b слотів кожен]
```

Хибне спрацьовування виникає тоді, коли хоча б один слот серед `2b` перевірених випадково містить значення, ідентичне `f_y`.

Ймовірність того, що конкретний окремий слот **не збігається** з відбитком `f_y`, дорівнює `1 - 1 / 2ᶠ`. Припускаючи незалежність відбитків, які вже зберігаються в таблиці, ймовірність того, що **жоден** із `2b` слотів не збіжиться з `f_y`, становить:

```
P_no_match = (1 - 1 / 2ᶠ)²ᵇ    [добуток імовірностей незбігу для всіх слотів]
```

Отже, ймовірність хибного спрацьовування `ε` (хоча б один збіг) дорівнює доповненню цієї величини до одиниці:

```
ε = 1 - P_no_match
= 1 - (1 - 1 / 2ᶠ)²ᵇ              [точна формула FPR]
```

Оскільки для практичних конфігурацій `2ᶠ ≫ 1` (наприклад, `2ᶠ = 256` для `f = 8`), ми можемо застосувати розклад бінома або наближення першого порядку через нерівність Бернуллі `(1 - x)ⁿ ≈ 1 - n · x` для малих `x`:

```
(1 - 1 / 2ᶠ)²ᵇ ≈ 1 - (2b) / 2ᶠ    [лінійне наближення першого порядку]
```

Підставляючи це спрощення у формулу для `ε`, отримуємо стандартну робочу оцінку:

```
ε ≈ 1 - (1 - 2b / 2ᶠ)
= 2b / 2ᶠ                          [асимптотична оцінка ймовірності хиби]
```

Ця формула демонструє важливий фундаментальний висновок: ймовірність помилки фільтра Кукушки спадає **експоненціально** зі зростанням довжини відбитка `f` і зростає **лінійно** з розміром кошика `b`.

## Розрахунок мінімальної довжини відбитка

Знаючи формулу для `ε`, ми можемо розв'язати нерівність відносно довжини відбитка `f`, щоб гарантувати заданий рівень надійності:

```
2b / 2ᶠ ≤ ε                        [умова неперевищення цільового FPR]
2ᶠ ≥ 2b / ε                        [множення на 2ᶠ та ділення на ε]
f ≥ log₂(2b / ε)                   [логарифмування обох частин за основою 2]
= log₂(1 / ε) + log₂(2b)           [розклад логарифма частки]
= log₂(1 / ε) + log₂(b) + 1        [властивість логарифма добутку]
```

Оскільки довжина відбитка у бітах повинна бути цілим числом, беремо операцію округлення вгору (стелю):

```
f = ⌈log₂(1 / ε) + log₂(2b)⌉       [необхідний розмір відбитка у бітах]
```

Для стандартної архітектури з кошиками асоціативності `b = 4`:

```
f = ⌈log₂(1 / ε) + log₂(2 · 4)⌉
= ⌈log₂(1 / ε) + log₂(8)⌉          [2 · 4 = 8]
= ⌈log₂(1 / ε) + 3⌉                [остаточна формула для b = 4]
```

Розрахуймо точні значення довжини відбитка для типових інженерних вимог:

1. **Цільовий FPR `ε = 0.03` (3%):**
   ```
   log₂(1 / 0.03) = log₂(33.33) ≈ 5.06
   f = ⌈5.06 + 3⌉ = ⌈8.06⌉ = 9 бітів (або 8 бітів при точній формулі: 8 / 256 = 0.03125 ≈ 3.1%)
   ```

2. **Цільовий FPR `ε = 0.01` (1%):**
   ```
   log₂(1 / 0.01) = log₂(100) ≈ 6.64
   f = ⌈6.64 + 3⌉ = ⌈9.64⌉ = 10 бітів (або 9 бітів при розрахунку: 8 / 512 = 0.0156 ≈ 1.56%)
   ```

3. **Цільовий FPR `ε = 0.001` (0.1%):**
   ```
   log₂(1 / 0.001) = log₂(1000) ≈ 9.97
   f = ⌈9.97 + 3⌉ = ⌈12.97⌉ = 13 бітів
   ```

## Інформаційно-теоретичні межі та ефективність пам'яті

Згідно з теорією інформації Картера та Вегмана, будь-яка структура даних, яка перевіряє належність до множини з `n` елементів у просторі `U` з імовірністю хибного спрацьовування `ε`, має фундаментальну нижню межу витрат пам'яті на елемент:

```
Bits_min = log₂(1 / ε)             [теоретична нижня межа Шеннона]
```

Класичний фільтр Блума використовує `k = ln(2) · (m / n)` хеш-функцій і досягає витрати пам'яті:

```
Bits_bloom = (1 / ln(2)) · log₂(1 / ε)
≈ 1.44 · log₂(1 / ε)               [витрата пам'яті фільтра Блума]
```

У фільтрі Кукушки загальна кількість виділених бітів пам'яті становить `m · b · f`. Якщо в таблиці збережено `n = α · m · b` елементів при коефіцієнті заповнення `α`, то питома витрата пам'яті на один збережений елемент становить:

```
Bits_cuckoo = (m · b · f) / n
= f / α                            [фактична витрата пам'яті на елемент]
= (⌈log₂(1 / ε) + log₂(2b)⌉) / α   [підстановка оптимального f]
```

Порівняймо поведінку цих двох структур при різних рівнях `ε` для `b = 4` та `α = 0.955`:

```
При ε = 0.01 (1%):
  Фільтр Блума:  1.44 · log₂(100) = 1.44 · 6.64 ≈ 9.56 бітів / елемент
  Фільтр Кукушки: (6.64 + 3) / 0.955 = 9.64 / 0.955 ≈ 10.09 бітів (або 9 / 0.955 ≈ 9.42 бітів для f = 9)

При ε = 0.001 (0.1%):
  Фільтр Блума:  1.44 · log₂(1000) = 1.44 · 9.97 ≈ 14.35 бітів / елемент
  Фільтр Кукушки: (9.97 + 3) / 0.955 = 12.97 / 0.955 ≈ 13.58 бітів / елемент

При ε = 0.0001 (0.01%):
  Фільтр Блума:  1.44 · log₂(10000) = 1.44 · 13.29 ≈ 19.13 бітів / елемент
  Фільтр Кукушки: (13.29 + 3) / 0.955 = 16.29 / 0.955 ≈ 17.05 бітів / елемент
```

Чим вищі вимоги до точності фільтрації (чим менше `ε`), тим більшою стає перевага фільтра Кукушки над фільтром Блума за обсягом пам'яті, оскільки постійний оверхед `log₂(2b) / α` стає нехтовно малим порівняно зі зростаючим членом `log₂(1/ε) / α`.

## Теорія гіперграфів та перколяція заповнення кошиків

Коефіцієнт заповнення таблиці `α` (load factor) визначається як відношення кількості збережених елементів `n` до сумарної кількості доступних слотів у таблиці `m · b`:

```
α = n / (m · b)                    [коефіцієнт використання ємності]
```

У класичному зозулиному хешуванні з розміром кошика `b = 1` структура утворює випадковий граф, у якому ребра представляють ключі, а вершини — комірки. Як тільки в такому графі виникає компонента зв'язності з двома або більше циклами, вставка закільцьовується. Через це теоретична межа заповнення для `b = 1` становить лише `α ≈ 0.50` (50%).

Коли ми переходимо до багатосекційних кошиків розміром `b ≥ 2`, модель перетворюється на гіперграф із більшим ступенем вершин. Межа перколяції (фазового переходу, за якого виникає гігантська циклічна компонента 2-ядра гіперграфа) різко зміщується в бік повного заповнення:

```
b = 1:  α_max ≈ 50.0%    [класичне зозулине хешування]
b = 2:  α_max ≈ 84.0%    [подвійні слоти]
b = 4:  α_max ≈ 95.5%    [оптимальний компроміс]
b = 8:  α_max ≈ 98.0%    [граничне ущільнення]
```

Чому саме `b = 4` обрано стандартом для фільтра Кукушки?
Розгляньмо питомі витрати пам'яті на один збережений елемент у бітах `Bits_per_item`:

```
Bits_per_item = (m · b · f) / n
= f / α                            [питома вартість зберігання одного елемента]
```

Якщо ми підставимо `f = ⌈log₂(1 / ε) + log₂(2b)⌉`, то отримаємо:

```
Bits_per_item = (log₂(1 / ε) + log₂(2b)) / α(b)
```

Порівняймо значення для `b = 2`, `b = 4` та `b = 8` при `ε = 0.01` (`log₂(1/ε) ≈ 6.64`):
- Для `b = 2`: `f = ⌈6.64 + 2⌉ = 9` бітів, `α ≈ 0.84` → `Bits_per_item = 9 / 0.84 ≈ 10.71` бітів/елемент.
- Для `b = 4`: `f = ⌈6.64 + 3⌉ = 10` бітів, `α ≈ 0.955` → `Bits_per_item = 10 / 0.955 ≈ 10.47` бітів/елемент.
- Для `b = 8`: `f = ⌈6.64 + 4⌉ = 11` бітів, `α ≈ 0.98` → `Bits_per_item = 11 / 0.98 ≈ 11.22` бітів/елемент.

При `b = 4` досягається ідеальний оптимум: високий коефіцієнт заповнення (95.5%) компенсує невелике збільшення `log₂(2b)`, забезпечуючи мінімальну витрату пам'яті серед усіх конфігурацій. Крім того, 4 відбитки по 8 або 16 бітів (4–8 байтів) ідеально вирівнюються в апаратній пам'яті.

## Марковські ланцюги та розподіл довжини витіснень

Під час вставки нового елемента в заповнені кошики алгоритм ініціює випадкове блукання (kicking walk). Нехай `L` — кількість витіснень, виконаних алгоритмом до знаходження порожнього слота.

Процес переміщення відбитків можна змоделювати як випадкове блукання Марковського ланцюга по випадковому `d`-регулярному зозулиному графу. Якщо поточний коефіцієнт заповнення менший за межу перколяції `α < α_max`, таблиця містить достатньо випадково розподілених вільних слотів.

Ймовірність того, що випадково обраний кошик на кроці `t` містить хоча б один вільний слот, дорівнює:

```
P_free_slot = 1 - αᵇ               [ймовірність наявності місця в кошику]
```

Для `b = 4` та `α = 0.90` маємо `P_free_slot = 1 - 0.90⁴ = 1 - 0.6561 = 0.3439` (близько 34.4% кошиків мають вільне місце).

Відповідно, ймовірність того, що ланцюжок витіснень продовжуватиметься довше ніж `k` кроків, спадає за геометричним законом:

```
P(L > k) ≤ (1 - P_free_slot)ᵏ
= (αᵇ)ᵏ = α^(b · k)                [експоненціальне згасання хвоста витіснень]
```

Для `α = 0.90, b = 4` та `k = 10`:

```
P(L > 10) ≤ (0.6561)¹⁰ ≈ 0.015     [лише 1.5% вставок вимагають понад 10 виселень]
```

Для `k = 50`:

```
P(L > 50) ≤ (0.6561)⁵⁰ ≈ 7.8 · 10⁻¹⁰ [ймовірність менше однієї на мільярд]
```

Звідси випливають строгі теореми продуктивності:
1. **Математичне сподівання довжини витіснення:** `E[L] = 1 / P_free_slot = 1 / (1 - αᵇ) = O(1)`. При заповненні до 90% середня кількість переміщень на одну вставку становить менше 1.5.
2. **Амортизована часова складність вставки:** залишається строго `O(1)`.
3. **Ймовірність збою вставки:** при встановленні ліміту `MAX_KICKS = 500` і заповненні `α ≤ 0.95` ймовірність передчасного збою становить менше `10⁻¹²`.

## Верхня межа кількості однакових ключів

Оскільки для кожного елемента `x` існує рівно два законних кошики `i₁` та `i₂`, сумарна місткість для запису ідентичних відбитків обмежена сумою слотів у цих двох кошиках:

```
Max_duplicates = 2 · b             [максимальна кількість дублікатів]
```

Для `b = 4` фільтр може зберегти **щонайбільше 8 ідентичних елементів** (або 8 різних елементів, чиї ключі випадково мають однакові індекси `i₁` та відбитки `f`). Спроба вставити дев'ятий дублікат гарантовано викличе нескінченне зациклення витіснень, оскільки 8 доступних гнізд будуть повністю заблоковані за принципом Діріхле. Це фундаментальне алгебраїчне обмеження архітектури, яке вимагає зовнішнього контролю кількості дублікатів у системах із високою повторюваністю ключів.
