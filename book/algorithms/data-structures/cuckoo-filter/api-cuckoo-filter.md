# 📋 Програмний інтерфейс Cuckoo Filter: конфігурація, контракти та обробка помилок

Фільтр Кукушки надає детермінований програмний інтерфейс для ймовірнісної перевірки належності множині з повноцінною підтримкою динамічного додавання та видалення елементів. Нижче специфіковано публічний контракт, конфігураційні параметри, детальні інваріанти структури, коди помилок, вимоги до потокобезпечності та гарантії часової і просторової складності.

## Конфігураційні параметри та їхній вплив на пам'ять

Створення та ініціалізація екземпляра фільтра вимагають визначення фундаментальних параметрів надійності та місткості:

| Параметр | Тип | За замовчуванням | Опис і допустимий діапазон |
| :--- | :--- | :--- | :--- |
| `capacity` | `size_t` | — | Очікувана максимальна кількість унікальних ключів `N > 0`. |
| `fpr` | `double` | `0.01` (1%) | Цільова ймовірність хибного спрацьовування `ε ∈ (0.0, 1.0)`. |
| `bucket_size` (`b`) | `size_t` | `4` | Кількість слотів для відбитків у кошику. Рекомендовано `4` (допустимо `2`, `4`, `8`). |
| `max_kicks` | `size_t` | `500` | Максимальна кількість ітерацій каскадного витіснення до фіксації переповнення. |

Внутрішня конфігурація пам'яті обчислюється алгоритмом автоматично на етапі створення:
1. **Довжина відбитка `f`:** обчислюється за формулою `f = ⌈log₂(2b / ε)⌉`. Для стандартного розміру кошика `b = 4` та `ε = 0.01` маємо `f = ⌈log₂(800)⌉ = 10` бітів. На практиці розрядність вирівнюється до 8 або 16 бітів (`uint8_t` або `uint16_t`) для максимальної швидкості апаратного доступу ЦП.
2. **Кількість кошиків `m`:** вибирається як найближчий ступінь двійки `m = 2ᵏ`, що задовольняє умову `m · b · 0.955 ≥ capacity`. Округлення до ступеня 2 гарантує коректність побітової маски `& (m - 1)` при обчисленні симетричного XOR.
3. **Загальний обсяг оперативної пам'яті:** становить строго `m · b · (f / 8)` байтів плюс фіксований оверхед структури дескриптора (близько 32–64 байтів).

## Детальний опис функцій та інваріантів

### 1. `cuckoo_init` / Конструктор `cuckoo_filter`

- **Попередні умови (Preconditions):**
  - `capacity > 0`: вимога ненульової очікуваної ємності.
  - `target_fpr > 0.0` та `target_fpr < 1.0`: допустимий інтервал імовірності хибного спрацьовування.
- **Поведінка та алгоритм ініціалізації:**
  1. На основі `target_fpr` та розміру кошика `b = 4` обчислюється розрядність відбитка `f = ⌈log₂(2b / target_fpr)⌉`.
  2. Розраховується мінімальна кількість кошиків: `min_buckets = ceil(capacity / (b · 0.955))`.
  3. Кількість кошиків `m` округлюється вгору до найближчого степеня двійки: `m = 2ᵏ`.
  4. Формується бітова маска індексації: `mask = m - 1`.
  5. Виділяється суцільний блок пам'яті розміром `m · b · (f / 8)` байтів за допомогою `calloc` або `posix_memalign` із вирівнюванням за межею 64 байтів (розмір процесорної кеш-лінії).
  6. Усі слоти зануляються значенням `EMPTY_SLOT = 0`.
- **Обробка помилок:** Якщо операційній системі бракує вільної пам'яті для виділення масиву кошиків, функція C API повертає `NULL`, а C++ конструктор генерує виняток `std::bad_alloc`.
- **Часова складність:** `O(m · b)` для занулення виділеної пам'яті.

### 2. `cuckoo_contains` / Метод `contains`

- **Попередні умови:** `filter != NULL`, `key != NULL`, `key_len > 0`.
- **Поведінка та алгоритм пошуку:**
  1. Обчислюється 64-бітний первинний хеш `h = hash_64(key, key_len)`.
  2. Формується відбиток `f`: виділяються молодші біти `h & ((1 << f) - 1)`. Якщо результат дорівнює нулю, йому присвоюється значення `1`.
  3. Розраховується первинний індекс кошика: `i₁ = (h >> f) & mask`.
  4. Розраховується вторинний індекс через XOR із хешем відбитка: `i₂ = (i₁ ⊕ hash_fingerprint(f)) & mask`.
  5. Виконується зчитування кошика `T[i₁]`. Відбиток `f` послідовно або паралельно (через SIMD) порівнюється з усіма `b` слотами кошика. Якщо знайдено збіг, функція негайно повертає `true`.
  6. Виконується зчитування кошика `T[i₂]`. Відбиток `f` порівнюється з його `b` слотами. Якщо знайдено збіг, функція повертає `true`.
  7. Якщо в обох кошиках збігів не знайдено, функція повертає `false`.
- **Гарантії надійності та семантичні інваріанти:**
  - **Одностороння похибка:** Якщо функція повернула `false`, елемент гарантовано відсутній у фільтрі (повна відсутність хибнонегативних відповідей за умови, що не виконувалося некоректне видалення).
  - **Ймовірність хибного позитиву:** Якщо функція повернула `true`, елемент присутній у фільтрі з імовірністю щонайменше `1 - ε`.
- **Часова складність:** строго детермінований час `O(1)` у найгіршому разі (не більше ніж `2b` порівнянь байтів і рівно два звернення до кеш-ліній пам'яті).

### 3. `cuckoo_insert` / Метод `insert`

- **Попередні умови:** `filter != NULL`, `key != NULL`.
- **Поведінка та алгоритм каскадної вставки:**
  1. Обчислюються `f`, `i₁`, `i₂`.
  2. Перевіряється наявність вільного слота `EMPTY_SLOT` у первинному кошику `T[i₁]`. Якщо знайдено, відбиток записується туди, лічильник `count` збільшується на 1, і повертається `CUCKOO_SUCCESS` (`true`).
  3. Перевіряється наявність вільного слота в альтернативному кошику `T[i₂]`. Якщо знайдено, відбиток записується туди, лічильник `count` збільшується на 1, і повертається `CUCKOO_SUCCESS` (`true`).
  4. Якщо обидва кошики повністю заповнені (всі `2b` слотів зайняті):
     - Вибирається випадковий стартовий кошик `curr_i` (між `i₁` та `i₂`) та випадковий слот `slot_idx ∈ [0, b-1]`.
     - Поточний мешканець слота витягується: `evicted_f = T[curr_i][slot_idx]`.
     - Новий відбиток записується на його місце: `T[curr_i][slot_idx] = f`.
     - Для вигнаного відбитка розраховується його альтернативна домівка: `curr_i = (curr_i ⊕ hash_fingerprint(evicted_f)) & mask`.
     - Якщо в новому кошику `T[curr_i]` є вільний слот, вигнаний відбиток оселяється там, лічильник `count` збільшується, і вставка завершується успіхом.
     - Якщо ж новий кошик також заповнений, процедура витіснення повторюється з черговим випадковим жителем нового кошика.
  5. Якщо кількість виселень досягає ліміту `MAX_KICKS = 500`, а вільне місце так і не знайдено, цикл зупиняється.
- **Обробка переповнення:** Функція повертає код помилки `CUCKOO_ERR_FULL` (`false`). При цьому інваріанти структури **не порушуються**: останній витіснений відбиток залишається записаним у таблиці, а раніше збережені елементи не втрачають своїх позицій.
- **Часова складність:** `O(1)` амортизована. У понад 98% випадків вставка завершується без жодного виселення.

### 4. `cuckoo_delete` / Метод `erase`

- **Попередні умови:** Ключ `key` повинен був попередньо успішно доданий до фільтра.
- **Поведінка та алгоритм видалення:**
  1. Обчислюються `f`, `i₁`, `i₂`.
  2. Перевіряються слоти кошика `T[i₁]`. Якщо знайдено перший слот зі значенням `f`, цей слот очищається (`slot = EMPTY_SLOT`), лічильник `count` зменшується на 1, і повертається `CUCKOO_SUCCESS` (`true`).
  3. Якщо в `T[i₁]` збігів немає, перевіряються слоти кошика `T[i₂]`. Якщо знайдено `f`, слот зануляється, лічильник `count` зменшується на 1, і повертається `CUCKOO_SUCCESS` (`true`).
  4. Якщо в обох кошиках потрібний відбиток відсутній, повертається `CUCKOO_NOT_FOUND` (`false`).
- **Критичні застереження безпеки (False Deletion Hazard):**
  - Якщо програма спробує видалити ключ, якого ніколи не було в системі, але чий відбиток через випадкову колізію збігся з відбитком іншого збереженого ключа, алгоритм видалить чужий відбиток. Після цього легітимний ключ почне давати хибнонегативну відповідь при перевірці.
  - Виклик `delete` дозволено здійснювати лише тоді, коли факт наявності запису підтверджено первинним джерелом даних (наприклад, перевіркою в основній таблиці бази даних).
- **Часова складність:** строго `O(1)` у найгіршому разі.

## Моделі паралелізму та потокобезпечність

Фільтр Кукушки оптимізований для побудови високонавантажених багатопотокових сервісів:

1. **Паралельне зчитування без блокувань (Lock-Free Reads):** Оскільки операція `contains` виконує лише зчитування 8-бітних або 16-бітних відбитків, на архітектурах x86-64 та ARM64 доступ до таких слотів є природно атомарним. Довільна кількість читацьких потоків може паралельно викликати `contains` без захоплення м'ютексів чи спінлоків.
2. **Смугові блокування для модифікацій (Striped Locking):** Для безпечного паралельного виконання вставок та видалень застосовується масив із `L` спінлоків (наприклад, `L = 1024` або `L = 4096`).
   - Для вставки або видалення ключ вимагає захоплення двох замків із номерами `lock_1 = i₁ % L` та `lock_2 = i₂ % L`.
   - Щоб виключити взаємні блокування (deadlocks), замки завжди захоплюються у строго зростаючому порядку їхніх індексів: `min(lock_1, lock_2)`, а потім `max(lock_1, lock_2)`.
   - Завдяки розбиттю таблиці на тисячі смуг потоки, що оновлюють різні кошики, працюють повністю паралельно без взаємних затримок.

## Двійкова серіалізація та нульове копіювання

Завдяки плоскій структурі пам'яті фільтр Кукушки підтримує блискавичну двійкову серіалізацію для збереження на диск або передачі по мережі:
- **Структура заголовка (16 байтів):**
  - `magic`: 4 байти (`0x4355434B` — ASCII рядок "CUCK").
  - `version`: 2 байти (версія формату, наприклад `1`).
  - `fingerprint_bits`: 2 байти (розрядність відбитка: 8, 12, 16).
  - `bucket_size`: 2 байти (кількість слотів у кошику, зазвичай 4).
  - `num_buckets`: 8 байтів (загальна кількість кошиків `m`).
  - `count`: 8 байтів (кількість активних елементів).
  - `checksum`: 4 байти (контрольна сума CRC32 або XXH3 заголовка та тіла).
- **Тіло структури:** Суцільний масив байтів кошиків, записаний послідовно без додаткових покажчиків.
- **Підтримка `mmap`:** Серіалізований файл фільтра може бути підключений у віртуальну пам'ять процесу за допомогою системного виклику `mmap(..., PROT_READ, MAP_SHARED, fd, 0)`. Це забезпечує миттєвий «холодний старт» серверів без витрат часу на виділення пам'яті та парсинг даних.
