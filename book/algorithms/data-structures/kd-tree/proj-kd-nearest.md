# ⚙️ kd-дерево: побудова й пошук найближчих на C++

Далі — робоче kd-дерево на C++: побудова через `std::nth_element`, пошук найближчого з відсіканням, k найближчих через купу і віконний запит із гуртовою віддачею. Сама умова відсікання займає один рядок; усе решта — рішення про те, де лежать дані й у якому порядку їх торкаються, і саме вони вирішують, буде код швидким чи ні.

Умова, за якої такий код має сенс: N точок відомі наперед і не міняються, а запитів багато. Тоді будувати можна один раз, зате будувати добре.

## Три масиви й жодної алокації на вузол

Перша спокуса — вузол зі вказівниками на нащадків і `std::vector` точок у листку. Порахуймо, у що це стане на мільйоні точок із кошиком на 16: близько шістдесяти тисяч листків, і кожен — окремий `vector` зі своїм викликом `operator new`. Шістдесят тисяч дрібних шматків, розкиданих по купі як прийдеться, а спуск деревом стає ланцюгом залежних читань: адресу наступного вузла не можна навіть почати завантажувати, доки не прочитано попередній. Процесор при цьому просто чекає.

Тому все дерево живе у трьох масивах: `pts_` — точки, як прийшли (побудова їх не рухає), `idx_` — їхні номери, які побудова переставляє, і `nodes_` — вузли. Ключова властивість, з якої випливає решта: після побудови кожне піддерево володіє **суцільним відрізком** `idx_`. Тому вузлові досить пари чисел `[begin, end)`, а листок перебирається звичайним циклом по масиву.

```cpp
#include <algorithm>
#include <cmath>
#include <numeric>
#include <queue>
#include <vector>

constexpr int D = 3;                 // вимірність відома під час компіляції

struct Point { float c[D]; };

struct Node {
    float split;       // значення розрізу
    int   axis;        // вісь розрізу; −1 → листок
    int   right;       // правий нащадок; лівий — завжди наступний вузол
    int   begin, end;  // відрізок idx_, яким володіє це піддерево
};
```

Номера лівого нащадка тут немає навмисно. Побудова кладе вузол у масив і аж потім рекурсивно будує ліве піддерево — тож лівий нащадок завжди осідає безпосередньо за батьком, і його номер дорівнює `n + 1`. Це не лише чотири зекономлені байти: спуск у ближчу половину — а туди йдуть завжди — читає сусідню комірку пам'яті, найчастіше вже підтягнуту в кеш разом із батьком. За стрибок платить лише дальня половина, тобто та, яку ми здебільшого відсікаємо.

`begin` і `end` тримає **кожен** вузол, не тільки листок. Вісім байтів на вузол — і за них ми купуємо гуртову віддачу у віконному запиті.

## Побудова: nth_element замість сортування

```cpp
class KdTree {
public:
    explicit KdTree(std::vector<Point> pts, int leaf = 16)
        : pts_(std::move(pts)), idx_(pts_.size()), leaf_(leaf) {
        std::iota(idx_.begin(), idx_.end(), 0);
        nodes_.reserve(4 * idx_.size() / leaf_ + 8);      // стеля кількості вузлів
        if (!idx_.empty()) build(0, static_cast<int>(idx_.size()));
    }

private:
    std::vector<Point> pts_;
    std::vector<int>   idx_;
    std::vector<Node>  nodes_;
    int                leaf_;

    int build(int b, int e) {
        const int me = static_cast<int>(nodes_.size());
        nodes_.push_back(Node{0.0f, -1, -1, b, e});       // поки що листок
        if (e - b <= leaf_) return me;

        float lo[D], hi[D];
        for (int a = 0; a < D; ++a) { lo[a] = +INFINITY; hi[a] = -INFINITY; }
        for (int i = b; i < e; ++i)
            for (int a = 0; a < D; ++a) {
                const float v = pts_[idx_[i]].c[a];
                lo[a] = std::min(lo[a], v);
                hi[a] = std::max(hi[a], v);
            }
        int axis = 0;
        for (int a = 1; a < D; ++a)
            if (hi[a] - lo[a] > hi[axis] - lo[axis]) axis = a;
        if (hi[axis] <= lo[axis]) return me;   // вся комірка — одна точка, ділити нічим

        const int mid = b + (e - b) / 2;
        std::nth_element(idx_.begin() + b, idx_.begin() + mid, idx_.begin() + e,
                         [&](int i, int j) { return pts_[i].c[axis] < pts_[j].c[axis]; });

        nodes_[me].axis  = axis;
        nodes_[me].split = pts_[idx_[mid]].c[axis];
        build(b, mid);                       // лівий нащадок = me + 1
        const int r = build(mid, e);         // ⚠ не писати одразу в nodes_[me].right
        nodes_[me].right = r;
        return me;
    }
```

**Чому не сортування.** Медіана потрібна лише як межа; повний порядок усередині половин нікому не здався. `std::nth_element` ставить на позицію `mid` рівно той елемент, що стояв би там після сортування, а решту тільки розкидає: ліворуч усе, що не більше, праворуч усе, що не менше. Стандарт обіцяє за це **лінійний час у середньому** — саме «в середньому», гарантії на найгірший випадок у стандарті немає. У libstdc++ це introselect: [швидкий вибір](book:algorithms/quickselect) з лічильником глибини, а коли глибина вичерпалася, керування переходить до `__heap_select`, і найгірший випадок виходить O(N·log N) замість квадрата. У libc++ такої страховки довго не було й найгірший випадок був квадратичним — тож на чужу реалізацію в цьому місці краще не покладатися сліпо.

**Вісь беремо за розкидом у цій комірці.** Прохід по вмісту комірки нічого не додає: `nth_element` усе одно пройде цим самим діапазоном. А рядок `if (hi[axis] <= lo[axis]) return me;` — не формальність. Він каже: якщо навіть найширша вісь має нульовий розкид, то вся комірка — це одна точка, повторена скільки завгодно разів, і жоден розріз її не розділить. Такий листок може вийти величезним, і його доведеться перебирати цілком; це чесна ціна за дані, у яких немає що розділяти.

**Розріз кладемо по позиції, а не по значенню.** Тут ламається більшість саморобних реалізацій. Проста ідея: узяти значення медіани s і розкласти комірку на «менше s» і «не менше s» через `std::partition`. Подайте тисячу однакових точок — ліва частина порожня, права дорівнює всій комірці, і рекурсія викликає себе з тим самим діапазоном довіку. Позиційний розріз цього не вміє: `mid` задано індексом, тож ліворуч завжди ⌊n/2⌋ елементів, а праворуч ⌈n/2⌉, хай значення хоч усі однакові. Глибина через це обмежена згори числом log₂(N/leaf) незалежно від даних. А для відсікання достатньо саме тієї слабкої властивості, яку `nth_element` і гарантує: ліворуч усе ≤ s, праворуч усе ≥ s.

## Найближчий: одне множення відкидає піддерево

```cpp
    static float dist2(const Point& a, const Point& b) {
        float s = 0.0f;
        for (int i = 0; i < D; ++i) { const float t = a.c[i] - b.c[i]; s += t * t; }
        return s;
    }

    void nn(int n, const Point& q, int& best, float& bestD2) const {
        const Node& nd = nodes_[n];
        if (nd.axis < 0) {                                // листок — перебір підряд
            for (int i = nd.begin; i < nd.end; ++i) {
                const float d2 = dist2(pts_[idx_[i]], q);
                if (d2 < bestD2) { bestD2 = d2; best = idx_[i]; }
            }
            return;
        }
        const float diff = q.c[nd.axis] - nd.split;
        const int near = (diff < 0.0f) ? n + 1 : nd.right;
        const int far  = (diff < 0.0f) ? nd.right : n + 1;
        nn(near, q, best, bestD2);                        // спершу СВОЯ половина
        if (diff * diff < bestD2) nn(far, q, best, bestD2);
    }

public:
    int nearest(const Point& q) const {
        int best = -1;
        float bestD2 = INFINITY;
        if (!nodes_.empty()) nn(0, q, best, bestD2);
        return best;
    }
```

Умова «не спускатися, якщо |q_a − s| ≥ r» записана як `diff * diff < bestD2`: обидві частини піднесено до квадрата, тому корінь не потрібен ніде — ані тут, ані в `dist2`. Порядок множників при цьому не змінюється: квадрат зростає монотонно на невід'ємних числах, тож найближча точка за квадратом відстані — та сама, що й за відстанню.

Зверніть увагу, що комірку вузла ми ніде не тримаємо, а перевірка все одно чесна. Достатньо знати, що всі точки дальньої половини лежать по інший бік площини `axis = split`, і `|diff|` — це відстань від запиту до тієї площини, тобто нижня оцінка відстані до будь-якої точки за нею.

## k найближчих: максикупа рівно на k елементів

```cpp
    using Cand = std::pair<float, int>;      // (квадрат відстані, номер точки)

    void knn(int n, const Point& q, int k, std::priority_queue<Cand>& heap) const {
        const Node& nd = nodes_[n];
        if (nd.axis < 0) {
            for (int i = nd.begin; i < nd.end; ++i) {
                const float d2 = dist2(pts_[idx_[i]], q);
                if (static_cast<int>(heap.size()) < k) heap.emplace(d2, idx_[i]);
                else if (d2 < heap.top().first) { heap.pop(); heap.emplace(d2, idx_[i]); }
            }
            return;
        }
        const float diff = q.c[nd.axis] - nd.split;
        const int near = (diff < 0.0f) ? n + 1 : nd.right;
        const int far  = (diff < 0.0f) ? nd.right : n + 1;
        knn(near, q, k, heap);
        const float r2 = (static_cast<int>(heap.size()) < k) ? INFINITY : heap.top().first;
        if (diff * diff < r2) knn(far, q, k, heap);
    }
```

`std::priority_queue` упорядковує через `std::less`, тобто згори лежить **найбільший** елемент — для нашої пари це найгірший зі збережених кандидатів. Він і є радіусом: доки купа не набрала k елементів, відсікати нема від чого й r² = ∞; щойно набрала — r² дорівнює `heap.top().first` і далі тільки спадає. Уся [черга з пріоритетом](book:algorithms/priority-queue) має розмір k, а не N, тож `push` і `pop` коштують log k, і жодного перерозподілу пам'яті після перших k вставок не буде.

Одна деталь на виході: `pop()` віддає кандидатів від найгіршого до найкращого, тож масив відповіді заповнюють із кінця.

## Вікно: гуртова віддача накритих піддерев

Комірку вузла зберігати не треба й тут — вона обчислюється дорогою вниз: у нащадка комірка та сама, у якої одну межу пересунуто на `split`.

```cpp
    struct Box { float lo[D], hi[D]; };

    static bool covers(const Box& w, const Box& c) {      // вікно накриває комірку цілком
        for (int a = 0; a < D; ++a)
            if (c.lo[a] < w.lo[a] || c.hi[a] > w.hi[a]) return false;
        return true;
    }
    static bool disjoint(const Box& w, const Box& c) {
        for (int a = 0; a < D; ++a)
            if (c.hi[a] < w.lo[a] || c.lo[a] > w.hi[a]) return true;
        return false;
    }
    static bool inside(const Box& w, const Point& p) {
        for (int a = 0; a < D; ++a)
            if (p.c[a] < w.lo[a] || p.c[a] > w.hi[a]) return false;
        return true;
    }

    void range(int n, const Box& w, const Box& cell, std::vector<int>& out) const {
        if (disjoint(w, cell)) return;                    // геть разом з усім піддеревом
        const Node& nd = nodes_[n];
        if (covers(w, cell)) {                            // ГУРТОМ, без перевірки точок
            out.insert(out.end(), idx_.begin() + nd.begin, idx_.begin() + nd.end);
            return;
        }
        if (nd.axis < 0) {
            for (int i = nd.begin; i < nd.end; ++i)
                if (inside(w, pts_[idx_[i]])) out.push_back(idx_[i]);
            return;
        }
        Box l = cell, r = cell;
        l.hi[nd.axis] = nd.split;
        r.lo[nd.axis] = nd.split;
        range(n + 1, w, l, out);
        range(nd.right, w, r, out);
    }
```

Гілка `covers` — це те, заради чого `begin` і `end` лежать у кожному вузлі: піддерево з мільйоном точок відповідає одним `insert` по суцільному діапазону, і жодну точку не перевірено окремо. Кореневу комірку беруть як габаритну коробку всієї хмари, а не як нескінченність: інакше найперша й найдешевша нагода віддати все гуртом пропаде.

## Скільки це коштує

```
рівнів побудови   = log₂(N / leaf)
робота на рівні   = розкид (D·N читань) + nth_element (≈ N порівнянь у середньому)
T(N) = 2·T(N/2) + O(N)   →   O(N·log N)

N = 10⁶, leaf = 16, D = 3
рівнів            = log₂(10⁶/16) ≈ 16
дій разом         ≈ 16 · 10⁶ · (3 + 1) ≈ 6·10⁷
```

Кожен рівень чіпає всі N номерів рівно раз, тож рівні коштують однаково, а вся побудова — лінійно за їхньою кількістю. Звідси видно й слабкість важеля: подвоєння кошика з 16 до 32 знімає рівно один рівень, тобто одну шістнадцяту роботи побудови. На боці пошуку той самий важіль тягне значно більше.

```

leaf   рівнів   вузлів (стеля 4N/leaf)   nodes_    відстаней у листку

```

За однієї точки в листку дерево важить утричі більше за самі точки — 40 МБ проти 12 МБ, — і вже цим випадає з кешу. Але головне не пам'ять, а те, чим ми міняємося. Один рівень спуску — це залежне читання за адресою, яку не вгадати наперед, плюс перехід, який передбачувач гілок вгадує погано, бо йде він то ліворуч, то праворуч. Одна відстань у кошику — три віднімання, три множення й два додавання поспіль по сусідніх адресах, без жодного переходу; компілятор такий цикл ще й векторизує. Тому обмін чотирьох рівнів спуску на шістнадцять зайвих відстаней часто виявляється вигідним, а межа лежить там, де кошик перестає вміщатися в кеш першого рівня.

Готові бібліотеки стоять на тому самому місці: у nanoflann `leaf_max_size` за замовчуванням 10 (документація радить 10–50, коли переважають запити), у SciPy `KDTree` — `leafsize=10`, у `cKDTree` — 16.

## Пастки

**`sqrt` у внутрішньому циклі.** Корінь має латентність у десятки тактів проти одного такту на множення, і стоїть він рівно в тому місці, яке виконується мільйони разів. Порівнюйте квадрати всюди: і в `dist2`, і в умові відсікання. Корінь беруть один раз наприкінці — якщо взагалі беруть.

**Дальня половина першою.** На відповідь порядок обходу не впливає зовсім, а на ціну — цілком. Поки `bestD2` дорівнює нескінченності, умова `diff * diff < bestD2` істинна скрізь, і дерево обходиться повністю. Ближча половина дає малий радіус за один спуск, і аж тоді відсікання починає працювати. Переставте два рядки місцями — і структура перетвориться на дорогий спосіб перебрати всі точки.

**Посилання в `nodes_` після `push_back`.** `Node& nd = nodes_[me];` перед рекурсією — і після першого ж переростання `vector` посилання вказує в звільнену пам'ять. З тієї самої причини рядок `nodes_[me].right = build(mid, e);` безпечний лише з C++17, де правий бік присвоєння обчислюється першим; до C++17 порядок не визначено й `nodes_[me]` могло бути обчислене до перерозподілу. Тому в коді вище результат спершу лягає в локальну змінну. `reserve` не рятує: варто помилитися зі стелею — і все повертається.

**Рекурсія і явний стек.** Глибина тут log₂(N/leaf) ≈ 16 на мільйоні, і стек нічим не загрожує — доки розріз позиційний. Явний стек беруть не від страху переповнення, а заради того, чого рекурсія не вміє: тримати відкладені піддерева впорядкованими за відстанню до запиту й обірвати обхід після сотні відвіданих листків. Це і є перехід від точної відповіді до наближеної, за якою йдуть у високих вимірах.

**Вставка без перебудови.** Спуститися до листка й покласти точку в кошик легко, але розріз переповненого кошика ляже по медіані **цих** точок, а не всієї хмари, тимчасом як межі, успадковані від батька, лишаться старими. Форма дерева знову починає залежати від порядку надходження — рівно того, від чого позбавляла побудова по медіані. Тому вставки накопичують і перебудовують піддерево, коли їх набирається помітна частка від його розміру: велике піддерево перебудовується рідко, тож у перерахунку на одну вставку це дешево ([амортизований аналіз](book:algorithms/amortized-analysis)). Видалення роблять так само — позначкою, яку прибирає найближча перебудова.
