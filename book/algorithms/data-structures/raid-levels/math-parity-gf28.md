# 🧮 Математика паритету та надійності: XOR, поля Галуа GF(2⁸) та ймовірність URE

Відновлення втрачених даних у дискових масивах спирається на алгебраїчні структури кодування з контролем помилок. У цьому файлі розібрано математичний апарат одиночного XOR-паритету RAID 5, подвійного паритету RAID 6 на основі арифметики полів Галуа `GF(2^8)` та ймовірнісні моделі відновлення й невідновних помилок читання (URE).

## 1. Алгебра побітового XOR-паритету (RAID 5)

Операція побітового виключного «АБО» (XOR, позначається як `⊕`) є базовим примітивом обчислення контрольних сум. На множині бітів `{0, 1}` XOR утворює абелеву групу з елементом 0 як нейтральним.

Ключовими алгебраїчними властивостями XOR є:
1. Комутативність: `A ⊕ B = B ⊕ A`
2. Асоціативність: `(A ⊕ B) ⊕ C = A ⊕ (B ⊕ C)`
3. Самоінверсність (інволюція): `A ⊕ A = 0` для будь-якого `A`
4. Нейтральний елемент: `A ⊕ 0 = A`

Нехай страйп складається з `k` блоків даних `D₀, D₁, ..., Dⲕ₋₁`. Блок паритету `P` обчислюється як побітова XOR-сума всіх блоків даних:

```
P = D₀ ⊕ D₁ ⊕ D₂ ⊕ ... ⊕ Dⲕ₋₁      [формула генерації паритету]
```

Якщо диск із номером `m` (де `0 ≤ m < k`) зазнає фізичної поломки, його вміст `D₴` відновлюється шляхом застосування операції XOR до решти справних дисків даних та диска паритету `P`:

```
P ⊕ (⨁_{i ≠ m} Dᵢ)
= (D₀ ⊕ ... ⊕ D₴ ⊕ ... ⊕ Dⲕ₋₁) ⊕ (⨁_{i ≠ m} Dᵢ)     [заміна P на його вираз]
= D₴ ⊕ (⨁_{i ≠ m} Dᵢ) ⊕ (⨁_{i ≠ m} Dᵢ)               [перестановка доданків]
= D₴ ⊕ 0                                               [властивість A ⊕ A = 0]
= D₴                                                   [результат відновлення]
```

Оскільки операція XOR є симетричною відносно кожного операнда, відновлення вимагає зчитування точно `k` блоків (решти дисків даних і паритету).

## 2. Подвійний паритет RAID 6: скінченні поля GF(2⁸)

Якщо з ладу виходять два диски одночасно, одного рівня паритету `P` недостатньо, оскільки виникає один лінійний вираз із двома невідомими (`Dᵢ ⊕ Dⱼ = Const`). Для відновлення двох невідомих необхідна система з двох лінійно незалежних рівнянь над скінченним полем.

Звичайне додавання XOR для другого паритету не підходить, бо друга XOR-сума була б лінійно залежною від першої. Замість цього RAID 6 використовує векторну арифметику у скінченному полі Галуа `GF(2^8)`. Поле `GF(2^8)` містить `2^8 = 256` елементів, що ідеально відповідає розміру одного байта (8 бітів).

### Арифметика полів Галуа GF(2^8)

У полях характеристика яких дорівнює 2, додавання та віднімання тотожні й виконуються через побітовий XOR:
```
A + B = A - B = A ⊕ B
```

Множення двох поліномів у `GF(2^8)` виконується за модулем непривідного примітивного полінома ступеня 8. Стандартом для RAID 6 згідно з кодуванням Ріда-Соломона є непривідний поліном:
```
p(x) = x⁸ + x⁴ + x³ + x² + 1      [двійкове значення: 0x11D / 285]
```

Припустимо, що мультиплікативну групу поля згенеровано примітивним елементом `g = 2` (у двійковому вигляді `00000010`). Множення елемента `A` на `g` виконується через зсув вліво на 1 біт із умовним XOR з `0x1D` у разі переповнення 8-го біта:

```
g · A = (A << 1) ⊕ (0x1D, якщо найстарший біт A дорівнює 1)
```

Тоді другий паритет `Q` обчислюється як лінійна комбінація блоків даних із коефіцієнтами, що є ступенями генератора `g`:

```
P = D₀ ⊕ D₁ ⊕ D₂ ⊕ ... ⊕ Dⲕ₋₁                     [перший паритет P: XOR-сума]
Q = g⁰·D₀ ⊕ g¹·D₁ ⊕ g²·D₂ ⊕ ... ⊕ gᵏ⁻¹·Dⲕ₋₁         [другий паритет Q: GF(2^8) сума]
```

де `gⁱ · Dᵢ` позначає множення байта `Dᵢ` на елемент `gⁱ` у полі `GF(2^8)`.

### Повний алгоритм відновлення при подвійній відмові дисків

Розглянемо найскладніший випадок, коли накопичувачі з індексами `i` та `j` (де `0 ≤ i < j < k`) вийшли з ладу. Решта дисків даних та диски паритету `P` і `Q` прочитані успішно.

Визначимо проміжні відомі значення `P_known` та `Q_known`, віднімаючи (що в `GF(2^8)` те саме, що й додаючи) зчитовані справні блоки:

```
P_known = P ⊕ (⨁_{m ∉ {i,j}} DⲘ) = Dᵢ ⊕ Dⱼ
Q_known = Q ⊕ (⨁_{m ∉ {i,j}} gᵐ·DⲘ) = gⁱ·Dᵢ ⊕ gʲ·Dⱼ
```

Отримуємо систему двох лінійних рівнянь з двома невідомими `Dᵢ` та `Dⱼ` над полем `GF(2^8)`:

```
Dᵢ ⊕ Dⱼ = P_known
gⁱ·Dᵢ ⊕ gʲ·Dⱼ = Q_known
```

Для розв'язання виразимо `Dⱼ` з першого рівняння: `Dⱼ = P_known ⊕ Dᵢ`. Підставимо у друге рівняння:

```
gⁱ·Dᵢ ⊕ gʲ·(P_known ⊕ Dᵢ) = Q_known                   [підстановка Dⱼ]
gⁱ·Dᵢ ⊕ gʲ·P_known ⊕ gʲ·Dᵢ = Q_known                   [розкриття дужок]
(gⁱ ⊕ gʲ)·Dᵢ = Q_known ⊕ gʲ·P_known                    [групування за Dᵢ]
Dᵢ = (Q_known ⊕ gʲ·P_known) / (gⁱ ⊕ gʲ)                 [знаходження Dᵢ]
```

Оскільки `g` є генератором поля `GF(2^8)` і всі його ступені `g⁰, g¹, ..., g²⁵⁴` є унікальними елементами, для `i ≠ j` виконується `gⁱ ≠ gʲ`. Отже, знаменник `gⁱ ⊕ gʲ ≠ 0`, а обернений елемент `(gⁱ ⊕ gʲ)⁻¹` завжди існує в `GF(2^8)`.

Після обчислення `Dᵢ` значення `Dⱼ` знаходять миттєво:

```
Dⱼ = P_known ⊕ Dᵢ
```

Завдяки властивостям полів Галуа алгоритм гарантує точне математичне відновлення даних двох будь-яких втрачених дисків масиву без втрати жодного байта.

## 3. Математика надійності масивів та ймовірність URE

Окрім повної відмови диска (Hardware Failure), ключовою загрозою є невідновна помилка читання сектора — **URE (Unrecoverable Read Error)**. Виробники жорстких дисків позначають специфікацію URE як максимальну ймовірність зчитування біта з помилкою (для споживчих HDD це зазвичай `p_ure = 10⁻¹⁴` бітів, для корпоративних — `10⁻¹⁵` бітів).

Показник `10⁻¹⁴` означає, що при зчитуванні 10¹⁴ бітів (`~12.5 терабайтів` даних) статистично виникає 1 некоректний сектор, який диск не здатний прочитати через збій магнітного шару.

### Формула ймовірності URE під час відбудови (Rebuild)

Під час відбудови дискового масиву RAID 5 після відмови одного диска система змушена повністю зчитати 100% вмісту решти `(N - 1)` дисків для переобчислення втрачених даних через XOR.

Нехай:
- `N` — загальна кількість дисків у масиві.
- `C` — обсяг одного диска у байтах.
- `B = (N - 1) · C · 8` — загальна кількість бітів, яку необхідно зчитати з решти дисків для відбудови.

Імовірність прочитати кожен біт без помилки дорівнює `(1 - p_ure)`.
Тоді ймовірність успішно зчитати всі `B` бітів без жодної помилки URE становить:

```
P_success = (1 - p_ure)^B
```

Відповідно, ймовірність `P_failure` виникнення щонайменше однієї помилки URE під час відбудови (що веде до зупинки відбудови RAID 5 або автоматичної втрати даних) обчислюється як:

```
P_failure = 1 - (1 - p_ure)^B
```

Застосовуючи наближення Бернуллі для малих `p_ure` (`(1 - x)ⁿ ≈ 1 - n·x` при `n·x < 1`):

```
P_failure ≈ B · p_ure = (N - 1) · C · 8 · p_ure
```

### Розрахунковий приклад: RAID 5 проти RAID 6

Розглянемо масив із `N = 8` дисків ємністю `C = 12 ТБ` кожен (`12 · 10¹²` байтів).
Використовуються диски зі специфікацією URE `p_ure = 10⁻¹⁴`.

Обчислимо обсяг зчитування при відбудові `B`:
```
B = (8 - 1) · 12 · 10¹² · 8 = 7 · 96 · 10¹² = 6.72 · 10¹⁴ бітів
```

Обчислимо ймовірність виникнення фатальної помилки URE під час відбудови RAID 5:
```
P_failure = 1 - (1 - 10⁻¹⁴)^(6.72 · 10¹⁴)
P_failure = 1 - e^(-6.72) ≈ 1 - 0.0012 = 0.9988 (тобто 99.88%)
```

**Висновок:** При відбудові масиву RAID 5 із 8 дисків по 12 ТБ імовірність фатального збою масиву через URE сягає майже **100%**.

У випадку **RAID 6** виникнення одного URE-сектора на одному зі справних дисків під час відбудови не руйнує масив. Завдяки наявності другого паритету `Q` алгоритм виконує локальне відновлення пошкодженого сектора через системи рівнянь `GF(2^8)`, і відбудова продовжується успішно. Саме ця математична реальність зробила RAID 5 непридатним для використання з дисками ємністю понад 2–4 ТБ.

## 4. Марковські моделі надійності масивів (MTTF Array)

Для оцінки загального середнього часу між відмовами масиву (MTTF_array) використовують безперервні марковські ланцюги загибелі та розмноження (Continuous-Time Markov Chains).

Нехай `λ` — інтенсивність відмов одного диска (`λ = 1 / MTTF_disk`), а `μ` — інтенсивність відбудови диска (`μ = 1 / MTTR_disk`).

Для масиву RAID 5 із `N` дисків середній час до безповоротної втрати даних `MTTF_RAID5` обчислюється за формулою:

```
MTTF_RAID5 = μ / (N · (N - 1) · λ²)
```

Для масиву RAID 6 із `N` дисків, який витримує 2 відмови, формула має вигляд:

```
MTTF_RAID6 = μ² / (N · (N - 1) · (N - 2) · λ³)
```

Оскільки швидкість відбудови `μ` набагато більша за інтенсивність відмов `λ` (`μ >> λ`), квадрат ступеня `μ²` у чисельнику RAID 6 дає приріст надійності на кілька порядків порівняно з RAID 5.
