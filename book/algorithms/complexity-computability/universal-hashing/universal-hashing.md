# Універсальне хешування

Уявімо звичайну хеш-таблицю, у яку додаток зберігає дані користувачів, конфігураційні параметри або словник мови. Хеш-функція перетворює вхідний рядок або число на індекс бакета у пам'яті. У класичних програмах алгоритм цієї хеш-функції є зафіксованим і не змінюється від запуску до запуску.

Якщо хеш-функція зафіксована, виникає небезпечна проблема: зовнішній користувач або зловмисник може заздалегідь підібрати тисячі таких ключів, які під цей конкретний алгоритм дають абсолютно одинаковий хеш-індекс. Коли всі ключі потрапляють у єдиний бакет, хеш-таблиця втрачає свою швидкість і перетворюється на звичайний зв'язаний список. Час пошуку даних деградує з квазі-миттєвого `O(1)` до повільного лінійного обходу `O(n)`. Сервер, який обробляє такий запит, повністю завантажує процесор і зупиняє обслуговування інших користувачів (атака Algorithmic Complexity DoS).

Універсальне хешування розв'язує цю фундаментальну проблему шляхом рандомізації вибору хеш-функції під час запуску програми. Замість однієї фіксованої хеш-функції розробник визначає ціле сімейство математично збалансованих функцій `H`. Коли програма створює нову хеш-таблицю, вона випадково обирає одну конкретну хеш-функцію `h` із цього сімейства. Оскільки зловмисник змушений готувати свої вхідні ключі до того, як програма згенерує випадкове зерно, він не може передбачити, які саме ключі викликають колізію.

## 1. Сутність 2-універсальності

Головна характеристика універсального сімейства хеш-функцій — це строге обмеження ймовірності колізії для будь-якої пари різних ключів.

Сімейство хеш-функцій `H` називається **2-універсальним**, якщо для двох довільних різних ключів `x` та `y` ймовірність того, що випадково обрана з сімейства функція `h` видасть однакові індекси `h(x) = h(y)`, не перевищує `1 / m`, де `m` — кількість бакетів хеш-таблиці.

```
P[h(x) = h(y)] ≤ 1 / m
```

Це означає, що для будь-яких вхідних даних випадковий вибір хеш-функції гарантує таку ж малу ймовірність колізії, як якби кожному ключу призначався абсолютно випадковий номер бакета.

З цієї математичної властивості випливає важливий практичний висновок: очікувана кількість ключів, які потрапляють у той самий бакет у таблиці з `m` комірками при збереженні `n` елементів, не перевищує `1 + n / m`. Якщо розробник підтримує розмір таблиці `m` не меншим за кількість елементів `n` (коефіцієнт завантаження `α ≤ 1`), середня довжина ланцюжка колізій не перевищує 2 елементів. Отже, середній час вставки, пошуку та видалення елемента строго становить `O(1)` для будь-якого вхідного набору даних.

## 2. Популярні конструкції універсальних функцій

На практиці обчислення хеш-функції повинно відбуватися за кілька тактів процесора без використання повільних операцій ділення.

### Модульне лінійне хешування
Цей метод обирає просте число `p`, яке перевищує діапазон можливих ключів, та два випадкових числа `a` і `b`. Значення хеш-функції обчислюється у два кроки:

```
h_{a,b}(x) = ((a · x + b) mod p) mod m
```

Перший крок `(a · x + b) mod p` виконує перемішування значення у полі простого числа `p`. Другий крок `mod m` звужує результат до кількості бакетів хеш-таблиці. Для прискорення обчислень як `p` обирають числа Мерсенна (наприклад `p = 2⁶¹ - 1`), що дозволяє замінити операцію ділення за модулем на швидкі побітові зсуви та додавання.

### Множильно-зсувне хешування (Multiply-Shift Hashing)
Якщо кількість бакетів у хеш-таблиці є ступенем двійки `m = 2ᴹ`, множильно-зсувний метод повністю усуває операцію ділення. Хеш-функція обирає випадкове непарне 64-бітне число `a` і виконує обчислення:

```
h_a(x) = (a · x mod 2⁶⁴) >> (64 - M)
```

Операція `mod 2⁶⁴` виконується процесором автоматично при переповненні 64-бітного регістра. Зсув `>> (64 - M)` виділяє старші `M` бітів добутку, які і стають індексом бакета. Обчислення виконується за два такти процесора (одна інструкція множення та один зсув).

### Табульоване хешування
Для обробки рядків або масивів байтів застосовують табульоване хешування. Ключ розбивається на окремі байти, і для кожного байта з випадково заповненої таблиці в пам'яті вибирається 64-бітне число. Підсумковий хеш обчислюється шляхом послідовного застосування побітової операції виключного АБО (`XOR`). Оскільки таблиці мають розмір лише 2 КБ, вони постійно перебувають у кеші L1 процесора, забезпечуючи максимальну швидкість обробки.

## 3. Спеціалізовані алгоритмічні схеми

Універсальні хеш-функції також застосовуються в складних імовірнісних структурах:

- **Зозулине хешування (Cuckoo Hashing)**: Використовує дві універсальні хеш-функції для забезпечення детермінованого часу пошуку `O(1)` у найгіршому випадку. Якщо при вставці виникає колізія, новий елемент витискає існуючий ключ у його альтернативну позицію у другій таблиці.
- **Оцінка подібності MinHash**: Застосовується для швидкого пошуку дублікатів великих текстових документів у Data Mining. Оцінка мінімального хеш-коду елементів множини дозволяє виміряти подібність Жакара між документами без їхнього повного порівняння.

## 4. Порівняння детермінованого та універсального підходів

Щоб чітко зрозуміти різницю між підходами, розглянемо порівняльну характеристику їхньої поведінки в різних умовах експлуатації:

| Властивість | Детермінована хеш-функція (FNV-1a, Murmur) | Універсальне хеш-сімейство (Carter-Wegman) |
| :--- | :--- | :--- |
| **Параметри ініціалізації** | Фіксовані алгоритмічні константи | Випадкове зерно (seed) з генератора ентропії |
| **Час пошуку на довільних даних** | `O(1)` у середньому випадковому разі | `O(1)` безумовно для **будь-якого** входу |
| **Стійкість до підбору ключів** | Уразлива (найгірший випадок `O(n)`) | Гарантовано стійка (імовірність колізії `≤ 1/m`) |
| **Додаткові витрати пам'яті** | `0` байтів додаткового стану | Від 8 байтів до 2 КБ під параметри зерна |

## 5. Динамічне перехешування (Reseeding) при виявленні колізій

У високозахищених системах застосовується активний моніторинг стану бакетів хеш-таблиці. Якщо внаслідок збігу або локальної аномалії даних довжина ланцюжка колізій у будь-якому бакеті перевищує встановлений критичний поріг (наприклад, 8 елементів), програма виявляє потенційну загрозу уповільнення.

У цей момент алгоритм виконує процедуру **reseed**:
1. Зчитується нова порція криптографічно стійких випадкових чисел із системного джерела ентропії (`/dev/urandom` або `getrandom()`).
2. Створюються нові значення коефіцієнтів `a` та `b`.
3. Всі наявні елементи хеш-таблиці заново розподіляються по бакетах за допомогою нової хеш-функції.

Цей механізм повністю анулює будь-які досягнення зловмисника, змушуючи його починати підбір ключів з нуля для абсолютно нової випадкової функції.

## 6. Сфери застосування та системний захист

Універсальне хешування є базовим стандартом безпеки сучасного системного програмного забезпечення:

- **Інтерпретатори та компілятори мов програмування**: Мови Python, Rust, Ruby, Go та Node.js за замовчуванням генерують випадкове зерно (seed) при кожному запуску процесу для захисту вбудованих словників (`dict`, `HashMap`) від атак колізій.
- **Мережеві стеки операційних систем**: Ядро Linux застосовує універсальні та псевдовипадкові хеш-функції у таблицях відстеження мережевих з'єднань (`netfilter`) та кешах маршрутизації для протидії мережевим DoS-атакам.
- **Криптографічні аутентифікатори (MAC)**: Протоколи безпечної передачі даних (Poly1305 у TLS 1.3 та SSH) використовують 2-універсальні поліноміальні сімейства над великими простими полями для генерації недоведених підписів автентичності повідомлень.

## 7. Практичний підсумок та рекомендації для розробників

При розробці практичних програм системні інженери повинні дотримуватися трьох фундаментальних правил:

1. **Генерувати зерно з системного CSPRNG**: Ніколи не ініціалізувати зерно функції через `time(NULL)`. Завжди зчитувати ентропію з `/dev/urandom` або використовувати `std::random_device`.
2. **Унікальне зерно для кожної таблиці**: Різні екземпляри хеш-таблиць у пам'яті повинні мати власні незалежні параметри, щоб унеможливити переносну колізійну атаку між словниками.
3. **Рехешування при аномаліях**: Якщо довжина ланцюжка колізій у бакеті перевищує 8 елементів, програма повинна згенерувати нове зерно та перебудувати таблицю.

Завдяки універсальному хешуванню розробники отримують гарантовану швидкодію `O(1)` та надійний захист комп'ютерних систем від штучно спровокованих уповільнень за будь-яких умов експлуатації, високоінтенсивного паралельного навантаження та мережевих атак. Застосування цієї концепції перетворює хеш-структури на фундаментальну теоретико-інформаційну фортецю.
