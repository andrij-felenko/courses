# ⚙️ Реалізація AM-протоколу неізоморфізму графів: інтерактивний верифікатор та доводжувач

Цей практичний матеріал демонструє повну програмну реалізацію двораундового імовірнісного AM-протоколу для перевірки неізоморфізму графів (Graph Non-Isomorphism, GNI) мовами C та C++, показуючи механіку генерування публічного виклику Артуром, розпізнавання графа Мерліном, аналіз структурних масивів суміжності та алгоритми підсилення надійності доведення.

## Алгоритмічна модель та математична підвалина протоколу GNI

Задача неізоморфізму графів полягає у визначенні того, чи є два задані неорієнтовані графи `G₀ = (V, E₀)` та `G₁ = (V, E₁)` **неізоморфними** (`G₀ ≇ G₁`). Якщо графи ізоморфні (`G₀ ≅ G₁`), існує перестановка вершин `π ∈ Sₙ`, яка повністю зберігає суміжність ребр між усіма парами вершин `(u, v) ∈ E₀ ⇔ (π(u), π(v)) ∈ E₁`.

Для доведення неізоморфізму у класичній моделі детермінованих свідків `NP` потрібен свідок експоненційного розміру або складний алгоритм перевірки всіх `n!` перестановок. Проте у двораундовому імовірнісному протоколі Артура — Мерліна перевірка виконується за поліномний час за допомогою імовірнісного виклику.

Покрокова алгоритмічна послідовність дій одного інтерактивного раунду:
1. **Артур (Верифікатор)** рівномірно і незалежно обирає випадковий біт `b ∈ {0, 1}` та будує випадкову перестановку вершин `π ∈ Sₙ`. Потім він генерує викликовий граф `H = π(G_b)` і публічно передає його Мерліну.
2. **Мерлін (Доводжувач)** обчислює, якому саме з вихідних графів (`G₀` чи `G₁`) ізоморфний отриманий граф `H`. Якщо вихідні графи неізоморфні (`G₀ ≇ G₁`), то викликовий граф `H` може бути ізоморфним лише одному з них, тому Мерлін безпомилково визначає вихідний біт `b'` і надсилає його Артуру. Якщо ж вихідні графи ізоморфні (`G₀ ≅ G₁`), то граф `H` одночасно ізоморфний обом графам `G₀` та `G₁`. У цьому випадку Мерлін позбавлений будь-якої інформації про вибір Артура і змушений вгадувати біт `b'`, тому імовірність його успіху не перевищує `1/2`.
3. **Артур** порівнює відповідь Мерліна `b'` із початковим бітом `b`. Якщо `b' == b`, раунд вважається успішним; інакше Артур миттєво відхиляє доказ і зупиняє роботу.

Повторюючи цей протокол `k` разів послідовно та незалежно, імовірність того, що Мерлін зможе обдурити Артура для двох ізоморфних графів, падає до `(1/2)^k`.

```
                  Схема інтерактивного раунду GNI
   Артур (Поліноміальний імовірнісний)        Мерлін (Обчислювальний оракул)
   ┌──────────────────────────────────┐      ┌─────────────────────────────┐
   │ 1. Обирає монету b ∈ {0, 1}      │      │                             │
   │ 2. Генерує перестановку π ∈ Sₙ   │      │                             │
   │ 3. Будує граф H = π(G_b)         │──H──>│ Перевіряє H ≅ G₀ чи H ≅ G₁  │
   │                                  │      │ Приймає рішення b' ∈ {0, 1} │
   │ 4. Приймає якщо b' == b          │<──b'─│                             │
   └──────────────────────────────────┘      └─────────────────────────────┘
```

## Вибір структур даних та генерація перестановок

Для ефективної програмної симуляції верифікатора Артура та оракула Мерліна критичним є вибір внутрішнього представлення графів та джерела випадкових перестановок.

### Представлення матрицею суміжності
У нашій реалізації графи розглядаються як двовимірні булеві матриці суміжності `adj[n][n]`. Для неорієнтованих графів без петель матриця є симетричною (`adj[i][j] == adj[j][i]`), а діагональні елементи є нульовими (`adj[i][i] == false`).
Перевагою матриці суміжності для малих і середніх графів (`n ≤ 64`) є константний час перевірки суміжності `O(1)` та висока локальність даних у кеші процесора. Застосування перестановки `π` до графа створює новий граф `H`, де елемент `H.adj[π[i]][π[j]] = G.adj[i][j]`.

### Алгоритм Фішера — Йейтса для генерації перестановок
Щоб Артур згенерував рівномірно випадкову перестановку `π ∈ Sₙ`, застосовується класичний алгоритм Фішера — Йейтса (Fisher-Yates shuffle). Починаючи з тотожної перестановки `perm[i] = i`, алгоритм на кожному кроці `i` від `n - 1` до `1` обирає випадковий індекс `j ∈ [0, i]` і міняє місцями елементи `perm[i]` та `perm[j]`. Це гарантує, що кожна з `n!` можливих перестановок генерується з однаковою ймовірністю `1 / n!`.

## Повна реалізація мовами C та C++

Нижче наведено повну та готову до компіляції реалізацію симуляції протоколу GNI. Версія мовою C використовує статично виділені матриці суміжності, процедурну стилістику та низькорівневі алгоритми перестановки елементів масиву. Версія мовою C++ застосовує сучасні стандартні контейнери `std::vector`, генератори вихідних випадкових чисел `<random>`, алгоритми `std::shuffle` та автоматичне керування ресурсами (RAII) з обробкою виняткових ситуацій.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <time.h>

#define MAX_V 32

/* Структура для представлення графа у вигляді матриці суміжності */
typedef struct {
    int num_vertices;
    bool adj[MAX_V][MAX_V];
} Graph;

/* Створення порожнього графа */
Graph create_graph(int n) {
    Graph g;
    g.num_vertices = n;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            g.adj[i][j] = false;
        }
    }
    return g;
}

/* Додавання неорієнтованого ребра */
void add_edge(Graph* g, int u, int v) {
    g->adj[u][v] = true;
    g->adj[v][u] = true;
}

/* Застосування перестановки p до графа g: H(p[i], p[j]) = g(i, j) */
Graph permute_graph(const Graph* g, const int* perm) {
    Graph h = create_graph(g->num_vertices);
    int n = g->num_vertices;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            if (g->adj[i][j]) {
                h.adj[perm[i]][perm[j]] = true;
            }
        }
    }
    return h;
}

/* Генерація випадкової перестановки (алгоритм Фішера — Йейтса) */
void generate_random_permutation(int* perm, int n) {
    for (int i = 0; i < n; i++) {
        perm[i] = i;
    }
    for (int i = n - 1; i > 0; i--) {
        int j = rand() % (i + 1);
        int temp = perm[i];
        perm[i] = perm[j];
        perm[j] = temp;
    }
}

/* Перевірка ізоморфізму графів через рекурсивний перебір перестановок */
bool check_isomorphism_recursive(const Graph* g1, const Graph* g2, int* perm, bool* used, int depth) {
    int n = g1->num_vertices;
    if (depth == n) {
        /* Перевірка збереження ребр */
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (g1->adj[i][j] != g2->adj[perm[i]][perm[j]]) {
                    return false;
                }
            }
        }
        return true;
    }

    for (int i = 0; i < n; i++) {
        if (!used[i]) {
            used[i] = true;
            perm[depth] = i;
            if (check_isomorphism_recursive(g1, g2, perm, used, depth + 1)) {
                return true;
            }
            used[i] = false;
        }
    }
    return false;
}

/* Оракул Мерліна: визначає, чи граф H ізоморфний G0 чи G1 */
int merlin_oracle(const Graph* g0, const Graph* g1, const Graph* h) {
    int n = h->num_vertices;
    int perm[MAX_V];
    bool used[MAX_V] = {false};

    if (check_isomorphism_recursive(g0, h, perm, used, 0)) {
        return 0;
    }

    for (int i = 0; i < n; i++) used[i] = false;
    if (check_isomorphism_recursive(g1, h, perm, used, 0)) {
        return 1;
    }

    /* Якщо не ізоморфний жодному, повертаємо випадок за замовчуванням */
    return 0;
}

/* Один раунд AM-протоколу для Артура */
bool arthur_am_round(const Graph* g0, const Graph* g1) {
    int n = g0->num_vertices;

    /* 1. Публічні монети Артура: вибір біта b та перестановки */
    int b = rand() % 2;
    int perm[MAX_V];
    generate_random_permutation(perm, n);

    /* 2. Побудова викликового графа H = pi(G_b) */
    const Graph* target = (b == 0) ? g0 : g1;
    Graph h = permute_graph(target, perm);

    /* 3. Отримання відповіді Мерліна b' */
    int merlin_choice = merlin_oracle(g0, g1, &h);

    /* 4. Перевірка відповіді Артуром */
    return (merlin_choice == b);
}

/* Повний AM-протокол з ампліфікацією точності (k раундів) */
bool run_gni_am_protocol(const Graph* g0, const Graph* g1, int rounds) {
    printf("--- Запуск AM-протоколу для GNI (%d раундів) ---\n", rounds);
    for (int r = 1; r <= rounds; r++) {
        bool accepted = arthur_am_round(g0, g1);
        if (!accepted) {
            printf("Раунд %d: Відхилено! Мерлін надав хибну відповідь.\n", r);
            return false; /* Неізоморфізм спростовано */
        }
    }
    printf("Всі %d раундів пройшли успішно. Графи НЕІЗОМОРФНІ з імовірністю >= 1 - (1/2)^%d\n", rounds, rounds);
    return true;
}

int main(void) {
    srand((unsigned int)time(NULL));

    /* Створення двох неізоморфних графів з 4 вершинами: Цикл C4 та Шлях P4 + ребро */
    Graph g0 = create_graph(4);
    add_edge(&g0, 0, 1); add_edge(&g0, 1, 2);
    add_edge(&g0, 2, 3); add_edge(&g0, 3, 0); /* Цикл C4 */

    Graph g1 = create_graph(4);
    add_edge(&g1, 0, 1); add_edge(&g1, 0, 2);
    add_edge(&g1, 0, 3); /* Зірка K_1,3 */

    printf("Тест 1: Неізоморфні графи (C4 та K_1,3)\n");
    run_gni_am_protocol(&g0, &g1, 10);

    printf("\nТест 2: Ізоморфні графи (G0 та перестановка G0)\n");
    int p[4] = {2, 3, 0, 1};
    Graph g0_iso = permute_graph(&g0, p);
    run_gni_am_protocol(&g0, &g0_iso, 10);

    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <random>
#include <algorithm>
#include <stdexcept>

class Graph {
private:
    std::size_t num_vertices_;
    std::vector<std::vector<bool>> adj_;

public:
    explicit Graph(std::size_t n)
        : num_vertices_(n), adj_(n, std::vector<bool>(n, false)) {}

    std::size_t size() const noexcept { return num_vertices_; }

    void add_edge(std::size_t u, std::size_t v) {
        if (u >= num_vertices_ || v >= num_vertices_) {
            throw std::out_of_range("Вершина виходить за межі графа");
        }
        adj_[u][v] = true;
        adj_[v][u] = true;
    }

    bool has_edge(std::size_t u, std::size_t v) const noexcept {
        return adj_[u][v];
    }

    /* Застосування перестановки до вершин графа */
    Graph permute(const std::vector<std::size_t>& perm) const {
        Graph h(num_vertices_);
        for (std::size_t i = 0; i < num_vertices_; ++i) {
            for (std::size_t j = 0; j < num_vertices_; ++j) {
                if (adj_[i][j]) {
                    h.adj_[perm[i]][perm[j]] = true;
                }
            }
        }
        return h;
    }
};

/* Клас оракула Мерліна для визначення ізоморфізму */
class MerlinOracle {
private:
    static bool is_isomorphic_recursive(const Graph& g1, const Graph& g2,
                                         std::vector<std::size_t>& perm,
                                         std::vector<bool>& used,
                                         std::size_t depth) {
        const std::size_t n = g1.size();
        if (depth == n) {
            for (std::size_t i = 0; i < n; ++i) {
                for (std::size_t j = 0; j < n; ++j) {
                    if (g1.has_edge(i, j) != g2.has_edge(perm[i], perm[j])) {
                        return false;
                    }
                }
            }
            return true;
        }

        for (std::size_t i = 0; i < n; ++i) {
            if (!used[i]) {
                used[i] = true;
                perm[depth] = i;
                if (is_isomorphic_recursive(g1, g2, perm, used, depth + 1)) {
                    return true;
                }
                used[i] = false;
            }
        }
        return false;
    }

public:
    static bool check_isomorphism(const Graph& g1, const Graph& g2) {
        const std::size_t n = g1.size();
        std::vector<std::size_t> perm(n);
        std::vector<bool> used(n, false);
        return is_isomorphic_recursive(g1, g2, perm, used, 0);
    }

    /* Мерлін визначає, якому з двох кандидатів відповідає викликовий граф H */
    static std::size_t identify_graph(const Graph& g0, const Graph& g1, const Graph& h) {
        if (check_isomorphism(g0, h)) return 0;
        if (check_isomorphism(g1, h)) return 1;
        return 0; /* Оракул не знайшов збігу */
    }
};

/* Клас верифікатора Артура */
class ArthurVerifier {
private:
    std::mt19937 rng_;

public:
    ArthurVerifier() : rng_(std::random_device{}()) {}

    bool execute_round(const Graph& g0, const Graph& g1) {
        const std::size_t n = g0.size();

        /* 1. Артур обирає випадковий біт b ∈ {0, 1} */
        std::uniform_int_distribution<std::size_t> dist(0, 1);
        std::size_t b = dist(rng_);

        /* 2. Генерація випадкової перестановки */
        std::vector<std::size_t> perm(n);
        std::iota(perm.begin(), perm.end(), 0);
        std::shuffle(perm.begin(), perm.end(), rng_);

        /* 3. Створення викликового графа H = π(G_b) */
        const Graph& selected_graph = (b == 0) ? g0 : g1;
        Graph h = selected_graph.permute(perm);

        /* 4. Мерлін надсилає відповідь */
        std::size_t merlin_response = MerlinOracle::identify_graph(g0, g1, h);

        /* 5. Перевірка відповіді */
        return (merlin_response == b);
    }

    bool verify_non_isomorphism(const Graph& g0, const Graph& g1, std::size_t rounds) {
        for (std::size_t r = 1; r <= rounds; ++r) {
            if (!execute_round(g0, g1)) {
                std::cout << "Раунд " << r << ": Відхилено Артуром! Графи ізоморфні.\n";
                return false;
            }
        }
        std::cout << "Успіх! " << rounds << " раундів підтвердили неізоморфність.\n";
        return true;
    }
};

int main() {
    try {
        Graph g0(4);
        g0.add_edge(0, 1); g0.add_edge(1, 2);
        g0.add_edge(2, 3); g0.add_edge(3, 0); // C4

        Graph g1(4);
        g1.add_edge(0, 1); g1.add_edge(0, 2);
        g1.add_edge(0, 3); // K_1,3

        ArthurVerifier arthur;

        std::cout << "--- Тест 1: Неізоморфні графи ---\n";
        arthur.verify_non_isomorphism(g0, g1, 10);

        std::cout << "\n--- Тест 2: Ізоморфні графи ---\n";
        std::vector<std::size_t> p = {1, 2, 3, 0};
        Graph g0_iso = g0.permute(p);
        arthur.verify_non_isomorphism(g0, g0_iso, 10);

    } catch (const std::exception& ex) {
        std::cerr << "Помилка: " << ex.what() << '\n';
        return 1;
    }
    return 0;
}
```

## Аналіз інженерних пасток та крайових випадків

При практичній розробці імовірнісних інтерактивних систем та верифікаторів Артура — Мерліна виникає низка критичних технологічних пасток, які можуть непомітно повністю зруйнувати коректність протоколу:

1. **Неякісні генератори випадкових чисел (Entropy Collapse).** Використання стандартного `rand()` мови C без криптографічно стійкого посіву призводить до того, що послідовність монет Артура стає передбачуваною. Якщо Мерлін зможе обчислити генератор випадкових чисел Артура, він зможе заздалегідь знати вибір біта `b` та перестановку `π`, що дозволить йому успішно обдурювати Артура навіть для абсолютно ізоморфних графів. Для промислових систем необхідно використовувати криптографічно стійкі джерела псевдовипадкових бітів (CSPRNG, такі як `std::random_device` або системний ентропійний пул `/dev/urandom`).

2. **Обчислювальна складність оракула Мерліна.** У нашій симуляції оракул Мерліна реалізований як простий рекурсивний алгоритм повного перебору перестановок вершини, складність якого становить `O(n!)`. Теоретична модель Артура — Мерліна припускає, що Мерлін має необмежену обчислювальну потужність, однак при локальному запуску програми розмір графів обмежений значеннями `n ≤ 10`. На практиці для більших графів використовуються спеціалізовані солвери ізоморфізму, такі як `Nauty` чи `Traces`.

3. **Аналіз імовірності помилки при ізоморфних графах.** У разі, коли на вхід подано два ізоморфні графи `G₀ ≅ G₁`, Мерлін змушений робити випадкову здогадку про значення біта `b`. Імовірність успішної відповіді Мерліна у кожному раунді становить точно `1/2`. Після `k = 10` раундів імовірність того, що Мерлін випадково вгадає відповіді у всіх 10 раундах поспіль, становить:

```
Pr [ Cheat ] = (1/2)¹⁰ = 1 / 1024 ≈ 0.000976 (менше 0.1%)
```

Для досягнення криптографічної точності (наприклад, ймовірність помилки менше `2⁻⁸⁰`) верифікатор Артур здійснює 80 паралельних або послідовних раундів виклику.

## Оптимізація продуктивності та порівняння складність

Нижче наведено таблицю порівняльного аналізу витрат ресурсів для детермінованого перебору ізоморфізму та імовірнісної AM-верифікації:

```
                 Порівняння підходів верифікації GNI
┌──────────────────────────────┬────────────────────────┬────────────────────────────┐
│ Параметр                     │ Детермінований перебір │ AM-протокол Артура         │
├──────────────────────────────┼────────────────────────┼────────────────────────────┤
│ Часова складність верифікатора│ O(n! · n²)             │ O(k · n²)                  │
│ Потребність у пам'яті        │ O(n²)                  │ O(n²)                      │
│ Тип монет                    │ Немає                  │ Публічні випадкові монети   │
│ Імовірність помилки (Soundness)│ 0.0 (Абсолютна)       │ (1/2)^k (Експоненційна)    │
│ Опорні теоретичні класи      │ coNP                   │ AM (Arthur-Merlin)         │
└──────────────────────────────┴────────────────────────┴────────────────────────────┘
```

Завдяки зниженню складності верифікатора до `O(k · n²)`, AM-протокол робить перевірку складних складнісних тверджень доступною навіть для найбільш обмежених обчислювальних пристроїв.
