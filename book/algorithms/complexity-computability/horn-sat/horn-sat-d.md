# Задовільненість хорнівських диз'юнктів (Horn-SAT)

У загальній задачі здійсненності булевих формул (SAT) спроба перевірити формулу зі 1000 змінних у найгіршому випадку впирається у виснажливий перебір $2^{1000}$ можливих комбінацій істинності, що перевершує кількість атомів у спостережуваному Всесвіті. Проте накладання одного-єдиного синтаксичного обмеження — вимоги, щоб кожен диз'юнкт містив **не більше одного позитивного (незаперечного) літерала**, — докорінно змінює обчислювальний ландшафт. Експоненційна стіна NP-повної задачі негайно рушиться, і проблема здійснюваності перетворюється на детермінований лінійний потік дедукції, що розв'язується за строго лінійний час `O(N)`. Цей підклас логічних формул отримав назву **хорнівських диз'юнктів** (англ. *Horn clauses*), а відповідна проблема здійсненності — **Horn-SAT**.

Дослідження Horn-SAT відкриває фундаментальну межу між детермінованими поліномними обчисленнями та NP-повною невизначеністю. Чому вилучення альтернативних симетричних виборів на зразок `(a ∨ b)` перетворює складний комбінаторний пошук на швидкий детермінований алгоритм? Як алгоритм Даулінґа — Ґальє досягає оцінки `O(N)`? Чому за свою високу швидкість Horn-SAT розплачується втратою легкого паралелізму, опиняючись у класі **P-повноти**? Відповіді на ці питання розкривають сутність логічного програмування (Prolog, Datalog), сучасних систем верифікації програмного забезпечення та автоматичного доведення теорем.

## Синтаксична анатомія: як один літерал знищує симетрію пошуку

Щоб зрозуміти, чому загальна задача SAT є важкою, згадаємо будову довільного диз'юнкта кон'юнктивної нормальної форми (КНФ), наприклад `(x₁ ∨ x₂ ∨ ¬x₃)`. Цей диз'юнкт пропонує декілька незалежних альтернативних шляхів для досягнення істинності: ми можемо зробити істинною змінну `x₁`, або змінну `x₂`, або зробити хибною `x₃`. Якщо алгоритм робить вибір `x₁ = 0`, це не зобов'язує `x₂` стати 1 — залишається вибір між `x₂` та `¬x₃`. Виникнення таких неорієнтованих вилок вимагає від розв'язувача будувати дерево рішень, перебирати альтернативні гілки та виконувати повернення назад (backtracking), коли обрана гілка заводить у глухий кут.

Поведінку класичної резолюції на загальних диз'юнктах можна виразити правилом:
```
(A ∨ B) ∧ (¬A ∨ C)  ⇒  (B ∨ C)
```
Як видно, резольвента `(B ∨ C)` знову є диз'юнкцією з двох позитивних літералів! Вона створює нові розгалуження, збільшуючи довжину та кількість диз'юнктів у системі.

**Хорнівський диз'юнкт** повністю припиняє це породження альтернатив. За означенням, це диз'юнкція літералів, яка містить **щонайбільше один позитивний (без заперечення) літерал**.

Залежно від наявності та ролі позитивного літерала, хорнівські диз'юнкти поділяються на три категоричні типи:

1. **Стверджувальні правила (Definite Clauses):** Містять **рівно один** позитивний літерал `q` та один або декілька негативних літералів `¬p₁, ¬p₂, ..., ¬pₖ`:
   ```
   ¬p₁ ∨ ¬p₂ ∨ ... ∨ ¬pₖ ∨ q
   ```
   Використовуючи закон еквівалентності `¬A ∨ B ≡ A → B` та правила Де Моргана, цей диз'юнкт переписується у вигляді канонічної імплікації:
   ```
   (p₁ ∧ p₂ ∧ ... ∧ pₖ) → q
   ```
   Семантика правила є абсолютно детермінованою: «Якщо всі умови `p₁, ..., pₖ` є істинними, то атом `q` **зобов'язаний** стати істинним». Тут немає жодного вибору чи альтернативи.

2. **Факти / Атоми (Facts / Unit Positive Clauses):** Містять **рівно один** позитивний літерал і нуль негативних літералів (`k = 0`):
   ```
   q  ≡  (⊤ → q)
   ```
   Семантика факту: «Атом `q` є безумовно істинним в усій системі». Факти виступають початковими точками (аксіомами), з яких розгортається потік виведення.

3. **Негативні обмеження / Диз'юнкти-мета (Integrity Constraints / Goal Clauses):** Містять **нуль** позитивних літералів та лише негативні літерали:
   ```
   ¬p₁ ∨ ¬p₂ ∨ ... ∨ ¬pₘ  ≡  (p₁ ∧ p₂ ∧ ... ∧ pₘ) → ⊥
   ```
   Семантика обмеження: «Умови `p₁, ..., pₘ` **не можуть бути істинними одночасно**». Якщо хвиля дедукції робить істинними всі `pᵢ`, виникає суперечність із хибою `⊥`, що означає нездійсненність (UNSAT) всієї формули.

![Класифікація та структура хорнівських диз'юнктів](/book/algorithms/complexity-computability/horn-sat/img/fig1-horn-clause-structure.svg)
*Класифікація хорнівських диз'юнктів: стверджувальні правила, факти та негативні обмеження цілісності.*

Формула `Φ` називається **хорнівською формулою**, якщо вона є кон'юнкцією хорнівських диз'юнктів: `Φ = C₁ ∧ C₂ ∧ ... ∧ Cₘ`.

### Порівняльний аналіз виведення на диз'юнктах

Щоб виразно відчути різницю між загальними диз'юнктами та хорнівськими правилами, розглянемо механізм резолюції одиничного факту `A` із хорнівським правилом:

```
(A) ∧ (¬A ∨ ¬B ∨ C)  ≡  (⊤ → A) ∧ ((A ∧ B) → C)
                     ⇒  ¬B ∨ C  ≡  (B → C)
```
Зверніть увагу: резольвента `(B → C)` містить **на один заперечений літерал менше**, ніж вихідне правило! Довжина тіла правила скорочується з 2 до 1. Жодних нових диз'юнкцій чи альтернативних варіантів не створюється. Одиниця `A` прямолінійно "випалює" заперечення `¬A` в усіх правилах.

| Параметр порівняння | Загальний SAT (КНФ) | Horn-SAT |
| :--- | :--- | :--- |
| **Максимальна кількість позитивних літералів у диз'юнкті** | Не обмежена (`0, 1, 2, ..., k`) | Строго `≤ 1` |
| **Еквівалентна логічна форма** | Неорієнтовані вилки `(A ∨ B ∨ C)` | Орієнтовані правила `(p₁ ∧ ... ∧ pₖ) → q` |
| **Результат резолюції** | Породжує нові диз'юнкції вигляду `(B ∨ C)` | Скорочує умови правил, наближаючи факти |
| **Потреба у гіпотезах та виборі** | Необхідна (дерево варіантів `2ⁿ`) | Відсутня (детермінований монотонний каскад) |
| **Причина нездійсненності (UNSAT)** | Провал усіх гілок перебору | Виведення суперечності з обмеженням `(1 ∧ ... ∧ 1) → ⊥` |

> 🔧 **Навіщо це.** В інженерії програмного забезпечення більшість правил бізнес-логіки, розмежування прав доступу (наприклад, AWS IAM чи Role-Based Access Control) та інференції типів у компіляторах будуються саме за хорнівською схемою: «Якщо користувач має роль Х та ресурс належить групі Y, то доступ дозволено». Відсутність вилок розгалуження дозволяє перевіряти мільйони правил безпеки за мілісекунди без ризику потрапити у комбінаторний вибух.

## Алгоритм Даулінґа — Ґальє: хвиля дедукції за час O(N)

Оскільки хорнівські правила є детермінованими, перевірка здійсненності формули Horn-SAT не вимагає пошуку з поверненнями (backtracking). У 1984 році Вільям Даулінґ та Жан Ґальє запропонували алгоритм, який розв'язує Horn-SAT за лінійний час `O(N)`, де `N` — сумарна кількість усіх літералів у формулі.

Ідея алгоритму Даулінґа — Ґальє спирається на **каскадне поширення одиниць (Unit Propagation)**. Усі змінні початково вважаються хибними (`0`). Алгоритм шукає безумовні факти `⊤ → q`, робить їх істинними (`1`) і запускає хвилю дедукції: щойно в якомусь правилі `(p₁ ∧ ... ∧ pₖ) → q` усі умови отримують значення 1, висновок `q` також оголошується істинним і додається до черги поширення.

### Структури даних для досягнення лінійної складності

Якщо перевіряти правила «наївно», скануючи формулу від початку до кінця на кожному кроці, складність алгоритму складе `O(N \cdot m)`, де `m` — кількість диз'юнктів. Щоб досягти строго лінійного часу `O(N)`, алгоритм використовує три спеціальні структури даних:

1. **Масив лічильників умов `count[c]`:** Для кожного диз'юнкта `c` зберігається кількість змінних у його лівій частині (в умові `body`), які ще не визнані істинними.
2. **Списки зворотного зв'язку `body_adj[x]`:** Для кожної змінної `x` зберігається список ідентифікаторів тих диз'юнктів, де змінна `x` входить до умови (з запереченням).
3. **Черга активних змінних `queue`:** Черга змінних, які вже змінили свій стан на `1`, але їхній вплив ще не розповсюджено на сусідні правила.

![Каскадне поширення одиниць у алгоритмі Даулінґа — Ґальє](/book/algorithms/complexity-computability/horn-sat/img/fig2-unit-propagation-cascade.svg)
*Каскадне поширення одиниць (Unit Propagation): детермінований потік виведення та перевірка обмежень за лінійний час O(N).*

### Покроковий траваж розгортання каскаду

Розглянемо трасування алгоритму Даулінґа — Ґальє на базі знань із 5 змінними `(A, B, C, D, E)` та 6 диз'юнктами:

```
(C1)  ⊤ → A                 [Факт 1]
(C2)  ⊤ → D                 [Факт 2]
(C3)  A → B                 [Правило 1]
(C4)  (B ∧ D) → C           [Правило 2]
(C5)  (C ∧ E) → A           [Правило 3]
(C6)  (C ∧ A) → ⊥           [Обмеження цілісності]
```

Початковий стан лічильників та списків суміжності:
- `count[C1] = 0`, `head[C1] = A`
- `count[C2] = 0`, `head[C2] = D`
- `count[C3] = 1`, `head[C3] = B`, `body_adj[A] = {C3, C6}`
- `count[C4] = 2`, `head[C4] = C`, `body_adj[B] = {C4}`, `body_adj[D] = {C4}`
- `count[C5] = 2`, `head[C5] = A`, `body_adj[C] = {C5, C6}`, `body_adj[E] = {C5}`
- `count[C6] = 2`, `head[C6] = ⊥`, `body_adj[A] = {C3, C6}`

| Крок `t` | Змінна `u` з черги | Оновлення `count[c]` для `c ∈ body_adj[u]` | Нові активовані правила | Зміни у черзі та модель |
| :--- | :--- | :--- | :--- | :--- |
| **Старт** | — | `count[C1]=0`, `count[C2]=0` | Факти C1, C2 | `queue = [A, D]`, `assignment = {A:1, D:1}` |
| **Крок 1** | `A` | `count[C3]: 1 → 0`, `count[C6]: 2 → 1` | `C3` спрацював (`head = B`) | `queue = [D, B]`, `assignment[B] = 1` |
| **Крок 2** | `D` | `count[C4]: 2 → 1` | Жодного | `queue = [B]` |
| **Крок 3** | `B` | `count[C4]: 1 → 0` | `C4` спрацював (`head = C`) | `queue = [C]`, `assignment[C] = 1` |
| **Крок 4** | `C` | `count[C5]: 2 → 1`, `count[C6]: 1 → 0` | `C6` спрацював (`head = ⊥`) | **КОНФЛІКТ ⊥!** Повертаємо **UNSAT** |

Під час кроку 4 декремент `count[C6]` дає 0. Оскільки `head[C6] == ⊥`, алгоритм негайно виявляє суперечність з обмеженням `(C ∧ A) → ⊥` і перериває виконання за відповіддю **UNSAT**. 

Зверніть увагу: змінна `E` взагалі не була активована, її значення залишилося `0`, а правило `C5` навіть не розглядалося вповну. Чому цей алгоритм гарантовано працює за час `O(N)`? Кожен літерал в умові кожного диз'юнкта обробляється рівно один раз — у момент, коли відповідна змінна виймається з черги і декрементує лічильник `count[c]`. Оскільки кожна змінна додається до черги не більше одного разу, сумарна кількість декрементів не перевищує загальну кількість літералів у формулі `N`.

### Гіперграфова інтерпретація дедукції

Алгоритм Даулінґа — Ґальє має просту геометричну інтуїцію. Представимо формулу Horn-SAT у вигляді **орієнтованого гіперграфа**:
- Вершини гіперграфа відповідають булевим змінним `V`, додатково містять джерело `⊤` та сток `⊥`.
- Гіперребро з'єднує **множину джерел** `{p₁, ..., pₖ}` з **однією вершиною-ціллю** `q`.
- Факти `⊤ → q` є гіперребрами з джерела `⊤` до `q`.
- Обмеження `(p₁ ∧ ... ∧ pₘ) → ⊥` є гіперребрами до стоку `⊥`.

У цій моделі каскад поширення одиниць є алгоритмом **пошуку досяжності гіпершляху** від джерела `⊤` до стоку `⊥`. Гіперребро вважається проходимим лише тоді, коли **всі** його початкові вершини активовані. Якщо існує гіпершлях від `⊤` до `⊥`, формула є **UNSAT**; якщо сток `⊥` недосяжний, формула є **SAT**.

З принципами проектирования та [детальній програмній реалізації алгоритму Даулінґа — Ґальє мовами C та C++](book:algorithms/complexity-computability/horn-sat/proj-horn-solver.md) можна ознайомитися в окремому практичному керівництві. Для інтеграції алгоритму в реальні проекти створено специфікацію [довіднику інтерфейсу та API розв'язувача Horn-SAT](book:algorithms/complexity-computability/horn-sat/api-horn-solver.md).

## Математична природа: перетин моделей та єдина мінімальна модель

Щоб зрозуміти глибоку алгебраїчну причину того, чому Horn-SAT є легкою задачею, необхідно звернутися до теорії моделей. Чому загальна КНФ вимагає перебору, а хорнівська формулювання — ні?

Відповідь полягає у фундаментальній алгебраїчній властивості: **множина моделей хорнівської формули є замкненою відносно покомпонентного кон'юнкту (перетину)**.

Представимо модель `M` (присвоєння істинності) як множину змінних, які приймають значення 1: `M = {x ∈ V | M(x) = 1}`.

> **Теорема про перетин моделей (Horn, 1951).** 
> Якщо `M₁` та `M₂` є модельними присвоєннями, що задовольняють хорнівську формулу `Φ` (тобто `M₁ ⊨ Φ` та `M₂ ⊨ Φ`), то їхній покомпонентний перетин `M₁ ∩ M₂` також є моделлю, що задовольняє `Φ`:
> ```
> (M₁ ⊨ Φ) ∧ (M₂ ⊨ Φ)  ⇒  (M₁ ∩ M₂) ⊨ Φ
> ```

Звідси негайно випливає ключовий наслідок: якщо хорнівська формула `Φ` є здійснюванною (існує хоча б одна модель), то серед усіх можливих моделей існує **єдина мінімальна за включенням модель** `Mₘᵢₙ`:

```
Mₘᵢₙ = ⋂ { M ⊆ V | M ⊨ Φ }
```

Загальні булеві формули цією властивістю не володіють. Розглянемо диз'юнкт `x₁ ∨ x₂`. Він має дві мінімальні моделі: `M₁ = {x₁}` та `M₂ = {x₂}`. Спробуємо взяти їхній перетин: `M₁ ∩ M₂ = ∅`. Але порожня множина `∅` (де `x₁ = 0, x₂ = 0`) **не задовольняє** диз'юнкт `x₁ ∨ x₂`! Наявність декількох незрівнянних мінімальних моделей і створює вилки розгалуження, що вимагають експоненційного перебору.

У хорнівській формулі каскад поширення одиниць Даулінґа — Ґальє будує саме цю єдину мінімальну модель `Mₘᵢₙ`. Він робить істинними лише ті змінні, які **необхідно** мають бути 1 у будь-якій можливій моделі. Якщо наприкінці каскаду всі обмеження задоволені, ми отримуємо розв'язок. Якщо ж мінімальна модель порушує хоча б одне обмеження `(p₁ ∧ ... ∧ pₘ) → ⊥`, це означає, що **жодна інша більша модель також не зможе його задовольнити** (оскільки додавання нових одиниць лише полегшує виконання умов обмеження).

### Дуально-хорнівські диз'юнкти (Dual-Horn Clauses)

Цікаво зазначити існування симетричного класу — **дуально-хорнівських диз'юнктів** (англ. *Dual-Horn clauses*). Це диз'юнкти, які містять **не більше одного негативного літерала** (наприклад, `p₁ ∨ p₂ ∨ ¬q`).

Множина моделей дуально-хорнівської формули замкнена відносно **покомпонентного диз'юнкту (об'єднання моделей)** `M₁ ∪ M₂`. Відповідно, будь-яка здійсненна дуально-хорнівська формула володіє **єдиною максимальною моделлю** `Mₘₐₓ`. Алгоритм розв'язання дуального Horn-SAT є дзеркальним: початково всі змінні приймають значення `1`, а каскад одиничних заперечень скидає необхідні змінні у `0`.

### Формули, перетворювані на хорнівські (Horn-Renamable)

Не кожна формула виглядає хорнівською на перший погляд. Проте існує розширений клас формул — **Horn-renamable** (або *перейменовувані хорнівські формули*). Формула є Horn-renamable, якщо існує така підмножина змінних `S ⊆ V`, що після заміни кожної змінної `x ∈ S` на її заперечення `¬x` (і заперечення `¬x` на `x`) кожний диз'юнкт формули стає хорнівським.

Гаррі Льюїс (Harry R. Lewis, 1978) та Бенгт Аспвалл (Bengt Aspvall, 1980) довели, що перевірити, чи є формула Horn-renamable, та знайти необхідну множину перейменування `S` можна за **лінійний час `O(N)`** шляхом зведення до задачі 2-SAT! Таким чином, коло розв'язуваних за лінійний час логічних задач розширюється за межі чисто хорнівських диз'юнктів.

Детальний математичний доказ теореми про перетин моделей, її наслідків та єдиності мінімальної моделі винесено в [математичному аналізі алгебраїчної дуальності та P-повноти](book:algorithms/complexity-computability/horn-sat/math-horn-solvability.md).

## Horn-SAT у заповіднику складності: P-повнота та межа паралелізму

Оскільки Horn-SAT розв'язується за лінійний час `O(N)`, вона безсумнівно належить до класу **P** (задач, що розв'язуються за детермінований поліномний час). Проте виникає питання: де саме всередині класу `P` розташована Horn-SAT? Чи можна її додатково прискорити за допомогою суперкомп'ютерів і масивного паралелізму?

Задачі з класу `P`, які допускають ефективне паралелізацію (розв'язуються за полілогарифмічний час `O(logᵏ n)` на поліномній кількості процесорів), утворюють клас **NC** (Nick's Class). Наприклад, задача 2-SAT (де кожен диз'юнкт містить не більше 2 літералів) належить до класу `NL ⊆ NC²`, що дозволяє розв'язувати її паралельно через пошук компонент сильної зв'язності в графі імплікацій.

Проте Horn-SAT виявляється значно складнішою. У 1977 році Ніл Джонс та Вільям Лааснер довели, що **Horn-SAT є P-повною задачею** (англ. *P-complete*) відносно зведень із логарифмічною пам'яттю.

![Ландшафт складності SAT-задач](/book/algorithms/complexity-computability/horn-sat/img/fig3-complexity-landscape.svg)
*Ландшафт обчислювальної складності: 2-SAT (NL-повна), Horn-SAT (P-повна) та 3-SAT (NP-повна).*

P-повнота означає два фундаментальні факти:

1. **Загальність:** Будь-який детермінований алгоритм, який виконується за поліномний час (будь-яка програма на звичайній обчислювальній машині), може бути за поліномний час зведений до розв'язання відповідної формули Horn-SAT. Доведення здійснюється через зведення від задачі обчислення значення монотонної логічної схеми (Monotone Circuit Value Problem, MCVP), де вентилі `AND` та `OR` кодуються хорнівськими правилами.
2. **Внутрішня послідовність (Inherently Sequential):** Horn-SAT неможливо паралелізувати до полілогарифмічного часу (тобто `Horn-SAT ∉ NC`), якщо тільки не справджується гіпотеза `P = NC` (що вважається настільки ж малоймовірним, як і `P = NP`).

Причина внутрішньої послідовності Horn-SAT криється у природі каскадного поширення. Кожен крок дедукції вимагає знання результатів попереднього кроку: щоб активувати правило `(A ∧ B) → C`, ми мусимо спочатку дочекатися, поки каскад обчислить значення `A` та `B`. Довжина цього ланцюжка залежностей у найгіршому випадку дорівнює кількості змінних `n`, що робить обчислення принципово послідовним.

### Зведення від задачі досяжності на графах (Path Accessibility / GAP)

Простим та наочним прикладом P-повності є зведення задачі досяжності вузлів у граф-схемах (Graph Accessibility Problem, GAP). Нехай дано орієнтований граф `G = (V, E)`, початкову вершину `s` та цільову вершину `t`. Запитання: чи існує шлях від `s` до `t`?

Кодуємо граф у хорнівську формулу:
1. Для початкової вершини створюємо факт: `⊤ → s`.
2. Для кожного орієнтованого ребра `(u, v) ∈ E` створюємо правило: `u → v`.
3. Перевірка цілі додає обмеження: `t → ⊥`.

Каскад поширення одиниць розв'яже цю формулу за лінійний час від кількості ребер `O(|V| + |E|)`:
- Якщо `t` є досяжною від `s`, каскад зробить `t = 1`, що порушить обмеження `t → ⊥` і дасть відповідь **UNSAT**.
- Якщо `t` недосяжна, обмеження не буде порушено, і відповідь буде **SAT**.

Цей приклад показує, що пошук досяжності в орієнтованих графах та гіперграфах є природною сутністю Horn-SAT.

### Зведена матриця порівняння класичних варіацій SAT

| Властивість / Характеристика | 2-SAT | Horn-SAT | 3-SAT / Загальний SAT |
| :--- | :--- | :--- | :--- |
| **Синтаксична межа** | `≤ 2` літерали у диз'юнкті | `≤ 1` позитивний літерал | `≥ 3` літерали у диз'юнкті |
| **Часова складність** | Лінійна `O(N)` | Лінійна `O(N)` | Експоненційна `O(2ⁿ)` |
| **Клас складності** | `NL`-повна | `P`-повна | `NP`-повна (Кук — Левіна) |
| **Паралелізуваність** | Легко паралелізується (`NC²`) | Внутрішньо послідовна (`P`-повна) | Не паралелізується (`NP`-важка) |
| **Алгебраїчна структура** | Симетричний граф імплікацій | Замкненість відносно перетину `M₁ ∩ M₂` | Втрата замкненості перетину |
| **Потреба у поверненнях** | Відсутня (пошук КСЗ) | Відсутня (каскад одиниць) | Необхідна (DPLL / CDCL) |

## Практичне застосування: від Prolog до автоматичної верифікації

Унікальна комбінація строго лінійної складності `O(N)` та високої виразності хорнівських імплікацій зробила Horn-SAT фундаментальним інструментом у багатьох галузях прикладної інформатики.

### 1. Логічне програмування та Prolog

У 1972 році Ален Колмерое та Роберт Ковальський створили мову програмування **Prolog**. Базовою одиницею програми в Prolog є саме стверджувальний диз'юнкт Хорна. Замість написання послідовних інструкцій програміст описує базу знань у вигляді фактів і правил:

```prolog
% Факти
parent(john, mary).
parent(mary, ann).

% Правило Хорна: grandparent(X, Y) :- parent(X, Z), parent(Z, Y).
grandparent(X, Y) :- parent(X, Z), parent(Z, Y).
```

Виконання запиту в Prolog спирається на **SLD-резолюцію** (англ. *Selective Linear Definite clause resolution*) — зворотне поширення одиниць за хорнівськими правилами. Докладніше про роль видатних науковців у цій революції можна прочитати в [історичному нарисі про Альфреда Хорна та еволюцію диз'юнктів Хорна](book:algorithms/complexity-computability/horn-sat/hist-horn-sat.md).

### 2. Datalog та дедуктивні бази даних

У базах даних та графічному аналізі великих обсягів даних широко застосовується **Datalog** — підмножина Prolog, що використовує пряме каскадне виведення (bottom-up fixpoint evaluation). Оскільки каскад Даулінґа — Ґальє гарантує досягнення нерухомої точки за лінійний час, Datalog-системи (наприклад, Soufflé чи Datomic) здатні миттєво обчислювати транзитивні замикання графів зв'язків із мільярдами ребер, що застосовується в аналізі вихідного коду для виявлення вразливостей (Static Program Analysis).

### 3. Інференція типів у сучасних мовах програмування (Hindley-Milner)

У компіляторах мов із статичною виведеністю типів (Rust, Haskell, OCaml, Swift) перевірка підтипування та реалізації інтерфейсів (traits / typeclasses) зводиться до обчислення хорнівських обмежень:

```
(T₁ ≤ T₂ ∧ T₂ ≤ T₃) → T₁ ≤ T₃
(Implementer(T, TraitA) ∧ Requirement(TraitA, TraitB)) → Implementer(T, TraitB)
```

Компілятор розгортає систему типів у хорнівські диз'юнкти і за допомогою каскаду Хорна за мілісекунди встановлює коректність усіх типів у програмі без виклику розгалуженого перебору.

### 4. Аналіз безпеки та прав доступу (AWS IAM / RBAC)

Системи розмежування прав доступу в хмарних інфраструктурах описуються хорнівськими обмеженнями. Наприклад, правило AWS IAM: «Користувач `U` отримує доступ до ресурсу `R`, якщо `U` належить до групи `G` та група `G` має дозвіл `P`».

Кодування у хорнівські правила:
```
(UserInGroup(u, g) ∧ GroupHasPolicy(g, p)) → Allowed(u, p)
(Allowed(u, p) ∧ SensitiveAction(p)) → AuditLogRequired(u)
```
Оцінка прав доступу при кожному запиті до API здійснюється каскадом Horn-SAT за мікросекунди.

### 5. Автоматичне доведення теорем та верифікація програм (SMT / CHC)

Сучасні системи автоматичного доведення теорем (SMT-соловери, такі як Z3 від Microsoft Research або CVC5) виражають задачі верифікації програмного забезпечення через **загальні хорнівські диз'узкти** (Constrained Horn Clauses, CHC). 

Кожна інваріантна властивість програми (наприклад, «індекс масиву не виходить за межі [0..N-1]») кодується хорнівським обмеженням. Якщо SMT-соловер доводить здійснюваність формули CHC, програма вважається строго верифікованою й вільною від багів; якщо знайдено суперечність із обмеженням, соловер генерує конкретний контрприклад (трасу виконання), який демонструє аварійне завершення програми.

Таким чином, хорнівські диз'юнкти, виявлені Альфредом Хорном у 1951 році під час суто теоретичних алгебраїчних розшуків, у XXI столітті стали надійним містом між теоретичною логікою, теорією складності та практичною надійністю критичного програмного забезпечення.
