# ⚙️ Класифікатор випадків: код, що за a, b і d називає випадок

Дайте цій підпрограмі три числа поділу — скільки підзадач `a`, у скільки разів вони менші `b` і показник `d` нерекурсивної роботи `f(n) = n^d` — і вона надрукує, котрий із трьох випадків майстер-теореми справджується, та готову Θ. Уся хитрість тут не в арифметиці (її на один рядок), а в тому, щоб **чесно** відповісти саме там, де плаваюча кома судити не має права.

## Задача

Вхід — рекурентність поділу `T(n) = a·T(n/b) + f(n)`, у якій робота на поділ і зліплювання степенева: `f(n) = n^d`. Вихід — номер випадку і підсумок:

```
d < c*   →  Θ(n^c*)          панує листя
d = c*   →  Θ(n^c* · log n)  баланс
d > c*   →  Θ(n^d)           панує корінь
```

Тут `c* = log_b a` — критичний показник, той самий [логарифм](book:math/binary-logarithm), що каже, як швидко множиться листя дерева рекурсії; а підсумок — це [асимптотика Θ](book:algorithms/asymptotic-complexity), верхня й нижня межа росту разом. Уся відповідь зводиться до **одного порівняння** `d` з `c*`. Здавалося б, три `if` — і кінець. Але саме в цьому порівнянні й ховається пастка, заради якої код варто написати з головою.

## Ідея: порівнянню не можна вірити наосліп

`c*` машина рахує як `ln a / ln b` — двома логарифмами у плаваючій комі. Клопіт у тому, що для більшості пар `a`, `b` число `c*` **ірраціональне**. Показник Карацуби `log₂3 ≈ 1.585` і Штрассена `log₂7 ≈ 2.807` — не дроби взагалі: якби `log₂3 = p/q`, то `2^p = 3^q`, а степінь двійки ніколи не збігається зі степенем трійки. Отже `c*` у пам'яті — завжди **округлення** нескінченного дробу, з похибкою десь у п'ятнадцятому знаку. З цього ростуть два висновки, що й формують код.

Перший: `d == c*` писати **не можна**. [Пряме порівняння двох float на рівність](book:programming/floating-point) майже завжди дає «не рівні» навіть там, де рівність математично є, бо округлене `ln a / ln b` не лягає точно в `d`. Наївний `==` проґавив би геть усі баланси.

Другий, підступніший: замінити `==` на «майже рівні», `|d − c*| ≤ ε` з якимось затишним `ε` на кшталт 0.01, — теж пастка, лише протилежна. Візьміть `T(n) = 2049·T(n/2) + n^11`. Тут `c* = log₂2049 ≈ 11.0007`, трохи більше за `d = 11`. Різниця `−0.0007` дрібна, та **справжня**: це чесний випадок 1, `Θ(n^11.0007)`. Широкий `ε` проковтнув би її й збрехав про баланс `Θ(n^11·log n)`. Тож `ε` мусить сидіти на рівні числового шуму — кілька останніх бітів, — а не «інженерного допуску».

Але й крихітний `ε` не знімає головного питання: коли `d` і `c*` збіглися в межах шуму — це справді баланс чи просто близька невдача? Плаваюча кома відповісти не може. Зате може арифметика цілих. Адже `d = c*` означає рівно `d = log_b a`, тобто `b^d = a` — рівняння **в цілих**, яке перевіряється без жодного логарифма. Дало `b^d` точно `a` — це баланс, крапка. Ні — `d` до `c*` лише притулилося, і чесна відповідь: «поза межами, тут потрібна точна арифметика».

Отже, алгоритм у три рухи: відсіяти безглуздий вхід; коли `|d − c*|` більше за шум — знак різниці надійний, тож сміливо випадок 1 чи 3; коли ж збіглися в межах шуму — не вірити float, а підтвердити баланс цілим рівнянням `b^d = a`.

![Горизонтальна вісь показника d із нулем біля c*: ліворуч зелена зона «панує листя, Θ(n^c*)», праворуч червона «панує корінь, Θ(n^d)», між ними вузька синя смуга ε; над смугою брама рішення — перевірити ціле b^d=a: рівно a дає баланс Θ(n^c*·log n), інакше — поза межами](img/classify-line.svg)
*Три зони за знаком різниці d − c*. Поза вузькою смугою ε знак надійний — одразу листя або корінь. У самій смузі float мовчить, і баланс підтверджують точним цілим рівнянням b^d = a; не підтвердився — чесно «поза межами».*

## Код

```c
#include <stdio.h>
#include <math.h>

/* Три випадки майстер-теореми — і чесна відмова, коли float не суддя. */
typedef enum { OUTSIDE = 0, LEAF = 1, BALANCE = 2, ROOT = 3 } Case;

typedef struct {
    Case        kind;   /* який випадок (або OUTSIDE — поза межами)  */
    double      cstar;  /* критичний показник  c* = log_b a          */
    const char *why;    /* чому OUTSIDE (для решти — порожньо)        */
} Verdict;

/* Баланс d == c* означає рівно b^d = a. Перевіряємо це в ЦІЛИХ —
   без ірраціонального логарифма: чи є ціле k ≈ d, для якого b^k == a. */
static int exact_balance(long a, long b, double d) {
    long k = lround(d);
    if (k < 0 || fabs(d - (double)k) > 1e-9) return 0;   /* d не ціле */
    long p = 1;
    for (long i = 0; i < k; i++) {
        if (p > a / b) return 0;        /* наступний множник перескочив би a */
        p *= b;
    }
    return p == a;
}

Verdict classify(long a, long b, double d) {
    Verdict v = { OUTSIDE, 0.0, "" };

    /* Пастка входу: a — кількість підзадач (>= 1); b — у скільки разів
       підзадача менша (>= 2, інакше вона не меншає й дна рекурсії нема). */
    if (a < 1 || b < 2) {
        v.why = "потрібні a >= 1 і b >= 2: підзадачі мусять меншати";
        return v;
    }

    double cstar = log((double)a) / log((double)b);      /* c* = log_b a */
    v.cstar = cstar;

    double gap = d - cstar;
    double eps = 1e-9 * (1.0 + fabs(cstar));             /* поріг числового шуму */

    if (gap < -eps) { v.kind = LEAF; return v; }         /* d < c*: панує листя  */
    if (gap >  eps) { v.kind = ROOT; return v; }         /* d > c*: панує корінь */

    /* |d - c*| у межах шуму — float мовчить. Підтверджуємо баланс точно. */
    if (exact_balance(a, b, d)) { v.kind = BALANCE; return v; }

    v.why = "d впритул до c*, та баланс не підтверджено точно "
            "(c* = log_b a, певно, ірраціональний) — тут треба точна арифметика";
    return v;
}

/* --- друк відповіді --- */
static void show_pow(char *buf, int n, double x) {
    if      (fabs(x)       < 1e-9) snprintf(buf, n, "1");   /* n^0 = 1 */
    else if (fabs(x - 1.0) < 1e-9) snprintf(buf, n, "n");   /* n^1 = n */
    else                           snprintf(buf, n, "n^%.6g", x);
}

static void report(const char *name, long a, long b, double d) {
    Verdict v = classify(a, b, d);
    char nc[32], nd[32];
    show_pow(nc, sizeof nc, v.cstar);
    show_pow(nd, sizeof nd, d);
    printf("%s (a=%ld, b=%ld, d=%g): ", name, a, b, d);
    switch (v.kind) {
        case LEAF:
            printf("випадок 1 — панує листя, T = Θ(%s)\n", nc);
            break;
        case BALANCE:
            if (fabs(v.cstar) < 1e-9)
                printf("випадок 2 — баланс, T = Θ(log n)\n");
            else
                printf("випадок 2 — баланс, T = Θ(%s · log n)\n", nc);
            break;
        case ROOT:
            printf("випадок 3 — панує корінь, T = Θ(%s)\n", nd);
            break;
        default:
            printf("поза межами — %s\n", v.why);
            break;
    }
}

int main(void) {
    report("сорт-злиттям",  2,    2, 1);   /* 2T(n/2)+n    -> баланс         */
    report("двійк-пошук",   1,    2, 0);   /*  T(n/2)+1    -> баланс (log n) */
    report("Карацуба",      3,    2, 1);   /* 3T(n/2)+n    -> листя n^1.585  */
    report("Штрассен",      7,    2, 2);   /* 7T(n/2)+n^2  -> листя n^2.807  */
    report("квадрат-поділ", 2,    2, 2);   /* 2T(n/2)+n^2  -> корінь n^2     */
    report("майже-тай",     2049, 2, 11);  /* c* ~ 11.0007 -> листя, не баланс */
    report("хибний-вхід",   3,    1, 1);   /* b=1: не меншає -> поза межами  */
    return 0;
}
```

Компілювати — `cc -std=c11 classify.c -lm` (логарифми беруться з `math.h`).

## Що воно друкує

```
сорт-злиттям (a=2, b=2, d=1): випадок 2 — баланс, T = Θ(n · log n)
двійк-пошук (a=1, b=2, d=0): випадок 2 — баланс, T = Θ(log n)
Карацуба (a=3, b=2, d=1): випадок 1 — панує листя, T = Θ(n^1.58496)
Штрассен (a=7, b=2, d=2): випадок 1 — панує листя, T = Θ(n^2.80735)
квадрат-поділ (a=2, b=2, d=2): випадок 3 — панує корінь, T = Θ(n^2)
майже-тай (a=2049, b=2, d=11): випадок 1 — панує листя, T = Θ(n^11.0007)
хибний-вхід (a=3, b=1, d=1): поза межами — потрібні a >= 1 і b >= 2: підзадачі мусять меншати
```

Три класичні поділи лягають кожен у свій випадок; `майже-тай` показує, що `c* ≈ 11.0007` — це **листя**, а не баланс, бо тісний `ε` не сплутав дрібну різницю з нулем; `хибний-вхід` чесно відмовляє.

> 🔧 **Навіщо це.** Спокуса — у сумнівному разі просто «вгадати баланс»: різниця ж крихітна. Але хибна Θ гірша за чесне «не знаю»: на неї спираються далі — оцінюють пам'ять, обирають алгоритм, обіцяють дедлайн, — і вся ця будова стоїть на піску. Відмова «поза межами» тут не слабкість коду, а його головна риса: класифікатор радше промовчить, ніж збреше правдоподібно.

## Складність і пастки

Робота — **O(1)**: два логарифми плюс, у межовому разі, коротка ціла петля завдовжки `log_b a` множень; пам'яті — теж стало. Уся вага не у швидкості, а в кутах, об які легко перечепитися.

- **`==` на float ніколи не спрацює.** `c*` округлений, тож рівність двох float — майже завжди «ні». Рішення бере знак різниці, а баланс підтверджує цілим рівнянням, не рівністю float.
- **Широкий `ε` бреше.** Приклад `2049·T(n/2)+n^11` вище: допуск, більший за числовий шум, ковтає справжню різницю й видає баланс замість листя. `ε` — це рівень шуму, а не «десь близько».
- **`c*` здебільшого ірраціональний.** `log₂3`, `log₂7` не є дробами (`2^p = 3^q` неможливо), тож випадок 2 буває **лише** тоді, коли `a` — точний степінь `b`; інакше рівного балансу немає взагалі. Через це в смузі й перевіряють `b^d = a` в цілих. Для раціонального `d = p/q` те саме узагальнюється на `a^q = b^p` — знову без плаваючої коми.
- **`a < 1` або `b ≤ 1`.** При `b = 1` підзадача `n/1 = n` не меншає — рекурсія без дна; `a < 1` — дробова кількість підзадач, безглуздя. І те, і те — поза теоремою.
- **Не плутати `f(n)` з `T(n)`.** Подавати треба показник **нерекурсивної** роботи — самого злиття чи поділу, — а не показник відповіді. У сортуванні злиттям `f(n) = n` (тобто `d = 1`), а `n·log n` — це вже готова `T`; сплутати їх — типова помилка.
- **Не-степенева `f`.** Класифікатор бачить лише скаляр `d`. Якщо справжня `f` — це `n·log n`, `n^d·log^k n` чи `2^n`, проста майстер-теорема не застосовна, і чесна відповідь та сама — «поза межами». Між випадками до того ж лишаються щілини (як-от `n^c*/log n`, що застрягає між 1 і 2), для яких потрібен важчий інструмент — теорема Акри–Баззі.
