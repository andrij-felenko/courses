# 📋 Інтерфейс модуля розширювальних графів та дерандомізованого вибіркового аналізу

Ця інструктивно-довідкова вставка описує C/C++ інтерфейс модуля `expander_graph` для побудови графів-розширювачів, проведення випадкових блукань (Expander Random Walks), обчислення спектральної щілини та дерандомізованого марківського вибіркового аналізу в ймовірнісних алгоритмах класу `BPP`.

## Архітектура та призначення модуля

Модуль `expander_graph` призначений для системних розробників та дослідників, які будують високонавантажені розподілені мережі, алгоритми дерандомізації або коди, що виправляють помилки. Модуль абстрагує конкретну комбінаторну чи алгебраїчну топологію розширювача (таких як графи Маргуліса — Габбера — Галіля, графи Рамануджана або Зіг-Заг добуток) за єдиним C-сумісним процедурним та C++ об'єктно-орієнтованим інтерфейсом.

Головні завдання, які вирішує цей модуль у високопродуктивних обчисленнях:
1. **Обчислення сусідів без збереження списків суміжності:** Для графів із мільйонами чи мільярдами вершин збереження всієї структури ребер у пам'яті вимагає гігабайтів оперативної пам'яті. Модуль надає аналітичні функції генерації сусідів за сталий час `O(1)` і `O(0)` додаткової пам'яті.
2. **Ампліфікація імовірності в алгоритмах BPP з економією ентропії:** Замість генерування нових незалежних випадкових бітів на кожній ітерації ймовірнісного алгоритму, модуль виконує блукання по вершинах графа-розширювача. Це скорочує використання дорогої системної ентропії з `k · r` бітів до `r + k · log₂ d` бітів при збереженні тотожного рівня зниження похибки до `2⁻ᵏ`.
3. **Аналітична спектральна верифікація:** Динамічне обчислення спектральної щілини `γ = d - λ₂` та другого за величиною власного значення `λ₂` за допомогою чисельного метода степеневих ітерацій (Power Iteration) з примусовою ортогоналізацією для контролю розширювальних властивостей графа під час виконання програми.

## Структури даних та типи

### `expander_type_t`
Тип генерації графа-розширювача визначає алгебраїчну сімейну тотожність та топологічні перетворення.

:::tabs
```c
typedef enum {
    EXPANDER_TYPE_MARGULIS = 0, // Граф Маргуліса — Габбера — Галіля (d = 8, на торі Z_m x Z_m)
    EXPANDER_TYPE_RAMANUJAN = 1, // Граф Рамануджана Любоцького — Філліпса — Сарнака (d = p + 1)
    EXPANDER_TYPE_ZIGZAG   = 2  // Зіг-Заг добуток графів G ∘ H
} expander_type_t;
```
```cpp
enum class ExpanderType : uint8_t {
    Margulis = 0, // Граф Маргуліса — Габбера — Галіля (d = 8, на торі Z_m x Z_m)
    Ramanujan = 1, // Граф Рамануджана Любоцького — Філліпса — Сарнака (d = p + 1)
    ZigZag = 2    // Зіг-Заг добуток графів G ∘ H
};
```
:::

Перелічувальний тип визначає вибір комбінаторної моделі під час створення об'єкта. Граф Маргуліса забезпечує швидке аналітичне обчислення сусідів через афінні матричні перетворення. Графи Рамануджана є оптимальними спектральними розширювачами, а Зіг-Заг добуток дозволяє гнучко підбирати степені вершин `d²`.

### `expander_config_t`
Параметри конфігурації для створення контексту графа.

| Поле | Тип C | Тип C++ | Опис та семантичні обмеження |
| :--- | :--- | :--- | :--- |
| `type` | `expander_type_t` | `ExpanderType` | Алгоритм побудови графа (Маргуліс, Рамануджан чи Зіг-Заг) |
| `param_m` | `int` | `int` | Розмір сітки `m` (для тора `ℤ_m × ℤ_m`, загальна кількість вершин `N = m²`) |
| `degree` | `int` | `int` | Степінь графа `d` (для Маргуліса — фіксовано 8) |
| `seed` | `uint64_t` | `uint64_t` | Зерно генератора псевдовипадкових чисел для вибору початкової вершини |

### `expander_graph_t`
Непрозорий контекст (Opaque Handle / Class Handle) графа-розширювача. Всі внутрішні масиви й параметри приховані для забезпечення ABI-сумісності та RAII-безпеки ресурсів.

:::tabs
```c
typedef struct expander_graph_s expander_graph_t;
```
```cpp
class ExpanderGraph; // Opaque forward declaration / RAII Class
```
:::

Непрозорий вказівник ховає внутрішній стан реалізації, включаючи виділені вектори для спектрального аналізу та внутрішні параметри геометрії тора. Це запобігає випадковій модифікації полів користувацьким кодом і дозволяє змінювати внутрішню структуру даних бібліотеки без порушення двійкової сумісності.

### `expander_walk_result_t`
Структура результату генерації випадкового блукання.

| Поле | Тип C | Тип C++ | Опис та семантичні обмеження |
| :--- | :--- | :--- | :--- |
| `path_vertices` | `uint32_t*` | `std::vector<uint32_t>` | Послідовність індексів відвіданих вершин на шляху |
| `length` | `size_t` | `size_t` | Кількість кроків виконаного блукання |
| `bits_used` | `size_t` | `size_t` | Кількість спожитих випадкових бітів ентропії |

## Специфікація функцій API

### 1. `expander_create`
Створює та ініціалізує контекст графа-розширювача відповідно до вказаних параметрів конфігурації.

:::tabs
```c
expander_error_t expander_create(
    const expander_config_t* config,
    expander_graph_t** out_graph
);
```
```cpp
std::expected<std::unique_ptr<ExpanderGraph>, expander_error_t> create_expander(
    const expander_config_t& config
);
```
:::

* **Опис та семантика:** Функція виділяє пам'ять під контекст графа та перевіряє коректність алгебраїчних параметрів. Для графа Маргуліса перевіряється, щоб `param_m > 1`.
* **Передумови (Preconditions):** `config != NULL`, `config->param_m > 1`, `out_graph != NULL`.
* **Постумови (Postconditions):** `*out_graph` вказує на готовий до роботи контекст графа у разі повернення `EXPANDER_OK`.
* **Стратегія обробки помилок:** У разі невдачі виділення оперативної пам'яті C++ API повертає `std::unexpected(EXPANDER_ERR_NO_MEMORY)`, а C API повертає код помилки і ґарантує `*out_graph = NULL`.
* **Часова складність:** `O(1)` для Маргуліса; `O(N)` для попереднього аналітичного розрахунку графів Рамануджана.

### 2. `expander_get_neighbors`
Обчислює та заповнює масив індексами всіх `d` сусідніх вершин для вказаної вершини `vertex_id`.

:::tabs
```c
expander_error_t expander_get_neighbors(
    const expander_graph_t* graph,
    uint32_t vertex_id,
    uint32_t* out_neighbors
);
```
```cpp
[[nodiscard]] std::span<const uint32_t> get_neighbors(
    uint32_t vertex_id
) const noexcept;
```
:::

* **Опис та семантика:** Застосовує афінні перетворення за модулем `m` для миттєвого визначення сусідів без звернення до дискової чи мережевої пам'яті. Для графа Маргуліса вершина з індексом `idx` перераховується у двовимірну координату `(x = idx / m, y = idx % m)`, до якої застосовуються зсувні матриці `T₁, T₂, S₁, S₂` та їхні обернені оператори.
* **Передумови:** `graph != NULL`, `vertex_id < N`, `out_neighbors` має виділений обсяг пам'яті під `d` елементів.
* **Постумови:** `out_neighbors[0 ... d-1]` містить точний перелік індексів сусідів.
* **Часова складність:** `O(d)` операцій (для Маргуліса — 8 арифметичних розрахунків за сталий час).
* **Гарантія безвиділення пам'яті:** Функція не виконує жодних динамічних алокацій (`Zero-allocation invariant`), що дозволяє викликати її у високошвидкісних обробниках переривань чи гарячих циклах.

### 3. `expander_random_walk`
Виконує дерандомізоване марківське блукання заданої довжини `walk_length` на графі-розширювачі для зниження похибки ймовірнісного алгоритму.

:::tabs
```c
expander_error_t expander_random_walk(
    const expander_graph_t* graph,
    uint32_t start_vertex,
    size_t walk_length,
    expander_walk_result_t* out_result
);
```
```cpp
[[nodiscard]] expander_walk_result_t random_walk(
    uint32_t start_vertex,
    size_t walk_length
) const;
```
:::

* **Опис та семантика:** Починаючи з `start_vertex`, алгоритм на кожному кроці рівномірно обирає один із `d` вихідних переходів. Це дозволяє генерувати псевдовипадкові вектори для перевірки алгоритмів `BPP`.
* **Передумови:** `graph != NULL`, `walk_length > 0`, `out_result != NULL`.
* **Постумови:** `out_result->path_vertices` містить послідовність вершин; `out_result->bits_used = log2(N) + walk_length * log2(d)`.
* **Заощадження ентропії:** Замість `walk_length · log2(N)` бітів випадковості вимагається лише `log2(N) + walk_length · log2(d)` бітів.
* **Часова складність:** `O(walk_length · d)`.

### 4. `expander_spectral_gap`
Обчислює другий за величиною власний номер `λ₂` та спектральну щілину `γ = d - λ₂` за допомогою методу степеневих ітерацій із примусовою ортогоналізацією.

:::tabs
```c
expander_error_t expander_spectral_gap(
    const expander_graph_t* graph,
    double tolerance,
    size_t max_iterations,
    double* out_spectral_gap,
    double* out_lambda2
);
```
```cpp
[[nodiscard]] double compute_spectral_gap(
    double tolerance = 1e-6,
    size_t max_iterations = 500
) const;
```
:::

* **Опис та семантика:** Чисельно знаходить значення `λ₂`, усуваючи вплив головного власного вектора `v₁ = (1, ..., 1)ᵀ` на кожному кроці за допомогою віднімання середнього значення елементів вектора.
* **Передумови:** `graph != NULL`, `tolerance > 0.0`, `out_spectral_gap != NULL`.
* **Постумови:** `*out_spectral_gap` містить обчислену спектральну щілину `d - λ₂`.
* **Часова складність:** `O(max_iterations · N · d)`.
* **Просторова складність:** `O(N)` оперативної пам'яті для двох робочих векторів.

### 5. `expander_bpp_sampler`
Автоматизований вибірковий аналізатор для ампліфікації BPP-алгоритмів через розширювальні блукання.

:::tabs
```c
expander_error_t expander_bpp_sampler(
    const expander_graph_t* graph,
    bool (*bpp_test_func)(uint32_t sample_id, void* user_data),
    void* user_data,
    size_t walk_length,
    bool* out_decision
);
```
```cpp
[[nodiscard]] bool sample_bpp(
    std::invocable<uint32_t> auto&& bpp_test_func,
    size_t walk_length
) const;
```
:::

* **Опис та семантика:** Обходить послідовність вершин випадкового блукання й запускає зворотний виклик `bpp_test_func` для кожної відвіданої вершини. Застосовує мажоритарний вибір (Majority Vote) для прийняття остаточного рішення з мінімальною ймовірністю похибки.
* **Передумови:** `graph != NULL`, `bpp_test_func != NULL`, `out_decision != NULL`.
* **Постумови:** `*out_decision` містить результат голосування більшості.
* **Часова складність:** `O(walk_length · (d + T_test))`, де `T_test` — час виконання одного тесту.

### 6. `expander_free`
Очищує й деалокує всі ресурси контексту графа-розширювача.

:::tabs
```c
void expander_free(expander_graph_t* graph);
```
```cpp
// У C++ виклик destructor здійснюється автоматично через RAII (std::unique_ptr)
~ExpanderGraph() noexcept;
```
:::

* **Передумови:** `graph` вказує на виділений контекст або `NULL`.
* **Постумови:** Пам'ять звільнено, вказівник деалоковано.

## Коди помилок та обробка виняткових ситуацій

Всі функції API (крім `expander_free`) повертають статус виконання `expander_error_t`:

| Код помилки | Числове значення | Причина виникнення | Стратегія відновлення |
| :--- | :--- | :--- | :--- |
| `EXPANDER_OK` | `0` | Успішне виконання операції | Продовжити стандартну обробку |
| `EXPANDER_ERR_NULL_POINTER` | `-1` | Передано `NULL` у критичний параметр | Перевірити виділення пам'яті перед викликом |
| `EXPANDER_ERR_INVALID_PARAM` | `-2` | Некоректні параметри `m <= 1` або `degree <= 0` | Перевірити конфігураційні файли |
| `EXPANDER_ERR_OUT_OF_BOUNDS` | `-3` | Індекс вершини `vertex_id >= N` | Перевірити діапазон індексів вершин |
| `EXPANDER_ERR_NO_MEMORY` | `-4` | Невдала спроба виділення пам'яті через `malloc` | Звільнити ресурси або збільшити swap |
| `EXPANDER_ERR_CONVERGENCE_FAILED` | `-5` | Метод Power Iteration не збігся за `max_iterations` | Збільшити `max_iterations` або послабити `tol` |

Детальна обробка кожної помилки гарантує відсутність аварійних зупинок (Crashes) у виробничому середовищі.

## Гарантії потокобезпечності (Thread Safety)

Модуль `expander_graph` надає суворі гарантії роботи у багатопотокових середовищах:

1. **Багатопотокове читання (`Thread-Safe & Immutable`):** Після створення об'єкт `expander_graph_t` є незмінним (Read-Only). Довільна кількість паралельних потоків може одночасно викликати `expander_get_neighbors` та `expander_random_walk` над одним контекстом без використання м'ютексів чи інших примітивів синхронізації (`Mutex-free`).
2. **Локальні генератори блукань:** Кожен потік під час виконання `expander_random_walk` повинен надавати власний локальний генератор випадкових чисел (`thread-local PRNG`) аби уникнути конфліктів за блокування у загальносистемному `rand()`.
3. **Ізоляція ресурсів:** Звільнення пам'яті через `expander_free` не є потокобезпечним відносно активних читачів. Програма повинна дочекатися завершення всіх робочих потоків перед викликом деструктора.
