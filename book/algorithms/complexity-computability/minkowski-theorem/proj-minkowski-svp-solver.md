# ⚙️ Алгоритм точного пошуку найкоротшого вектора в кулі Мінковського

Теорема Мінковського про опуклі тіла встановлює фундаментальну екзистенційну гарантію: у будь-якій повній дискретній ґратці `L ⊂ ℝⁿ` довжина найкоротшого ненульового вектора задовольняє нерівність:

```
λ₁(L) ≤ R_M = √n · (det(L))^(1/n)
```

Проте класичне доведення теореми через згортання Бліхфельдта та принцип Діріхле є суто неконструктивним. Воно доводить, що шуканий вектор існує всередині евклідової кулі `Bₙ(R_M)`, але не надає формули чи детермінованого шляху для його обчислення. У практичних задачах комп'ютерної алгебри, цілочисельного лінійного програмування та аналізу постквантових криптосистем необхідно не просто знати теоретичну межу, а ефективно знайти конкретний цілочисельний вектор `v ∈ L \ {0}`, норма якого досягає мінімуму: `‖v‖₂ = λ₁(L)`.

Ця проблема відома як **задача найкоротшого вектора (Shortest Vector Problem, SVP)**. У точній постановці задача SVP є NP-важкою відносно рандомізованих зведень у розмірностях `n → ∞`. Проте для фіксованих і помірних розмірностей (`n ≤ 40`) існують точні детерміновані алгоритми, найефективнішим серед яких є алгоритм перебору Шнорра–Ейхнера у сфері Мінковського.

## Геометрична декомпозиція та ортогоналізація Грама–Шмідта

Нехай дискретна ґратка `L = L(B)` задана матрицею дійсного базису `B = [b₁, b₂, …, bₙ] ∈ ℝⁿˣⁿ`. Будь-який вузол ґратки подається у вигляді лінійної комбінації базисних векторів із цілими коефіцієнтами:

```
v = ∑_{i=1}ⁿ zᵢ·bᵢ,    де zᵢ ∈ ℤ
```

Безпосередній перебір коефіцієнтів `zᵢ` у кубічному діапазоні `[−M, M]ⁿ` є нездійсненним: кількість комбінацій зростає як `(2M + 1)ⁿ`, а вектори базису можуть бути скошеними під гострими кутами, через що навіть при великих `zᵢ` окремі компоненти можуть взаємно скорочуватися, утворюючи короткий вектор.

Щоб розв'язати цю проблему, простір факторизують за допомогою ортогоналізації Грама–Шмідта над полем дійсних чисел `ℝ`. Обчислюється ортогональний базис `b₁*, b₂*, …, bₙ*` та матриця коефіцієнтів проєкції `μ = (μ_{ij})`:

```
b₁* = b₁
bᵢ* = bᵢ − ∑_{j=1}^{i-1} μ_{ij} · bⱼ*,    де μ_{ij} = ⟨bᵢ, bⱼ*⟩ / ‖bⱼ*‖²  (1 ≤ j < i ≤ n)
```

Вектори `bᵢ*` є попарно ортогональними: `⟨bᵢ*, bⱼ*⟩ = 0` при `i ≠ j`. Базисна матриця розкладається у добуток `B = μ · B*`, де `μ` — нижньотрикутна матриця з одиницями на головній діагоналі (`μ_{ii} = 1`).

Квадрат евклідової норми довільного вектора ґратки `v = ∑_{i=1}ⁿ zᵢ·bᵢ` завдяки ортогональності розпадається на суму квадратів незалежних ортогональних проєкцій:

```
‖v‖² = ∑_{i=1}ⁿ (zᵢ + ∑_{j=i+1}ⁿ μ_{ji} · zⱼ)² · ‖bᵢ*‖²
```

Ця формула є ключем до алгоритмічного відсікання простору: оскільки кожен доданок у сумі є строго невід'ємним, будь-яка часткова сума від індексу `k` до `n` задає точну нижню оцінку квадрата повної норми вектора:

```
l_k = ∑_{i=k}ⁿ (zᵢ + ∑_{j=i+1}ⁿ μ_{ji} · zⱼ)² · ‖bᵢ*‖² ≤ ‖v‖²
```

Якщо на рівні `k` частковий внесок `l_k` перевищує квадрат поточного радіуса пошуку `R_best²`, то незалежно від вибору молодших координат `z₁, …, z_{k-1}` повна норма вектора гарантовано перевищить поріг `R_best`. Це дозволяє миттєво відсікати цілі піддерева простору пошуку розміру `(2M + 1)^{k-1}`.

## Алгоритм Шнорра–Ейхнера: зигзагоподібний пошук у глибину

Класичний алгоритм Фінка–Поста (Fincke–Pohst, 1985) перебирав координати `z_k` послідовно зліва направо в межах допустимого інтервалу: від `⌈c_k − r_k⌉` до `⌊c_k + r_k⌋`. Це призводило до того, що алгоритм спочатку витрачав ресурси на дослідження далеких граничних точок на краях кулі.

Клаус Шнорр (Claus Schnorr) та Мартін Ейхнер (Martin Euchner) у 1994 році запропонували модифікацію, яка кардинально прискорила перебір. Ідея полягає в тому, щоб на кожному кроці розгортати координату `z_k` **зигзагоподібно від найближчого цілого центру проєкції**:

1. Для фіксованих старших координат `z_{k+1}, …, zₙ` обчислюється ідеальний дійсний центр проєкції:
   `c_k = − ∑_{j=k+1}ⁿ μ_{jk} · zⱼ`.
2. Першим перевіряється найближче ціле число `z_k^(0) = ⌊c_k⌉ = round(c_k)`. Для нього відхилення `|z_k − c_k|` є мінімальним, а отже, доданок `(z_k − c_k)² · ‖b_k*‖²` мінімізує накопичену довжину.
3. Наступні значення перебираються з чергуванням знаків відхилення:
   `z_k^(1) = ⌊c_k⌉ + 1`
   `z_k^(2) = ⌊c_k⌉ − 1`
   `z_k^(3) = ⌊c_k⌉ + 2`
   `z_k^(4) = ⌊c_k⌉ − 2`, і так далі.

Як тільки чергове відхилення призводить до `l_k ≥ R_best²`, подальший перебір по координаті `z_k` негайно зупиняється, оскільки всі наступні кроки зигзага лише збільшуватимуть відстань від центру `c_k`.

Завдяки центрально-симетричній природі ґратки (`v ∈ L ⇔ −v ∈ L`) найвищу ненульову координату можна зафіксувати строго додатною: `z_n > 0`. Це скорочує простір пошуку рівно вдвічі без жодної втрати повноти.

Початковий радіус пошуку встановлюється рівним радіусу Мінковського `R_best = R_M = √n · (det(L))^(1/n)`. Якщо в процесі обходу дерева знаходиться вектор меншої норми `‖v‖ < R_best`, радіус негайно оновлюється `R_best ← ‖v‖`, що динамічно стискає кулю пошуку для всіх наступних гілок алгоритму.

## Покрокове трасування роботи алгоритму на числовому прикладі

Для детального розуміння механізму розглянемо роботу алгоритму на двовимірній ґратці з базисом:

```
b₁ = [ 2, 0 ]ᵀ
b₂ = [ 1, 3 ]ᵀ
```

1. **Крок ортогоналізації Грама–Шмідта:**
   - Перший вектор: `b₁* = b₁ = [ 2, 0 ]ᵀ`, `‖b₁*‖² = 2² + 0² = 4`.
   - Коефіцієнт проєкції: `μ_{2,1} = ⟨b₂, b₁*⟩ / ‖b₁*‖² = (1·2 + 3·0) / 4 = 2 / 4 = 0.5`.
   - Другий ортогональний вектор: `b₂* = b₂ − 0.5·b₁* = [ 1, 3 ]ᵀ − [ 1, 0 ]ᵀ = [ 0, 3 ]ᵀ`.
   - Квадрат довжини: `‖b₂*‖² = 0² + 3² = 9`.
   - Визначник ґратки: `det(L) = √(‖b₁*‖² · ‖b₂*‖²) = √(4 · 9) = √36 = 6`.
   - Радіус Мінковського: `R_M = √2 · (6)^(1/2) = √12 ≈ 3.4641`. Квадрат початкового радіуса: `R_best² = 12.0`.

2. **Крок перебору на рівні `k = 2`:**
   - Центр проєкції: `c₂ = 0.0`.
   - Оскільки за симетрією обираємо `z₂ > 0`, починаємо з `z₂ = 1`.
   - Внесок другого рівня: `l₂ = (z₂ − c₂)² · ‖b₂*‖² = (1 − 0)² · 9 = 9.0 < R_best² = 12.0`. Гілка є валідною, спускаємося на рівень `k = 1`.

3. **Крок перебору на рівні `k = 1` для `z₂ = 1`:**
   - Центр проєкції: `c₁ = − μ_{2,1} · z₂ = − 0.5 · 1 = − 0.5`.
   - Найближче ціле: `⌊−0.5⌉ = 0` (або `−1`).
   - Варіант `z₁ = 0`: накопичена норма `l₁ = l₂ + (z₁ − c₁)² · ‖b₁*‖² = 9.0 + (0 − (−0.5))² · 4 = 9.0 + 0.25 · 4 = 10.0 < 12.0`.
   - Знайдено вектор: `v = 0·b₁ + 1·b₂ = [ 1, 3 ]ᵀ`, норма `‖v‖² = 10.0`.
   - Оновлюємо радіус відсікання: `R_best² ← 10.0`.
   - Наступний крок зигзага `z₁ = −1`: `l₁ = 9.0 + (−1 − (−0.5))² · 4 = 9.0 + 0.25 · 4 = 10.0 ≥ R_best² = 10.0` (не дає строгого покращення).
   - Наступний крок `z₁ = 1`: `(1 − (−0.5))² · 4 = 1.5² · 4 = 2.25 · 4 = 9.0 ⇒ l₁ = 9 + 9 = 18 ≥ 10.0` (відсікається).
   - Повертаємося на рівень `k = 2`.

4. **Перевірка наступного `z₂`:**
   - Наступне значення `z₂ = 2`: `l₂ = 2² · 9 = 36.0 ≥ R_best² = 10.0` (відсікається повністю).

5. **Перевірка гілки `z₂ = 0`:**
   - Для `z₂ = 0` центр `c₁ = 0.0`. Щоб вектор був ненульовим, беремо `z₁ = 1`:
   - Внесок: `l₁ = 0 + (1 − 0)² · 4 = 4.0 < R_best² = 10.0`.
   - Знайдено новий найкращий вектор: `v = 1·b₁ + 0·b₂ = [ 2, 0 ]ᵀ`, норма `‖v‖² = 4.0`.
   - Оновлюємо радіус: `R_best² ← 4.0`.
   - Наступний `z₁ = 2`: `l₁ = 2² · 4 = 16.0 ≥ 4.0` (відсікається).

Алгоритм повністю завершує роботу: знайдено точний найкоротший вектор `v = [ 2, 0 ]ᵀ` з довжиною `λ₁(L) = 2.0 ≤ R_M ≈ 3.4641`.

## Повна реалізація мовами C та C++

Нижче наведено самодостатню виробничу реалізацію алгоритму SVP на основі сфери Мінковського та перебору Шнорра–Ейхнера. Програма містить блок ортогоналізації Грама–Шмідта, розрахунок детермінанта та радіуса Мінковського, а також рекурсивний рушій обходу дерева з динамічним звуженням радіуса.

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <stdbool.h>

#define MAX_DIM 16

/* Структура представлення ґратки та її ортогоналізованого базису */
typedef struct {
    int n;
    double b[MAX_DIM][MAX_DIM];     /* Вихідні вектори базису b[i][j] */
    double b_star[MAX_DIM][MAX_DIM];/* Ортогональні вектори Gram-Schmidt */
    double mu[MAX_DIM][MAX_DIM];    /* Коефіцієнти проекції mu[i][j] */
    double b_star_sq[MAX_DIM];      /* Квадрати довжин ||b_star[i]||^2 */
    double det;                     /* Визначник ґратки det(L) */
    double minkowski_radius;        /* Радіус Мінковського R_M */
} Lattice;

/* Обчислення евклідового скалярного добутку векторів */
static double dot_product(const double *u, const double *v, int n) {
    double sum = 0.0;
    for (int i = 0; i < n; i++) {
        sum += u[i] * v[i];
    }
    return sum;
}

/* Ортогоналізація Грама-Шмідта над дійсними числами */
void lattice_orthogonalize(Lattice *lat) {
    int n = lat->n;
    lat->det = 1.0;

    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            lat->b_star[i][j] = lat->b[i][j];
        }
        for (int j = 0; j < i; j++) {
            double num = dot_product(lat->b[i], lat->b_star[j], n);
            lat->mu[i][j] = num / lat->b_star_sq[j];
            for (int k = 0; k < n; k++) {
                lat->b_star[i][k] -= lat->mu[i][j] * lat->b_star[j][k];
            }
        }
        lat->b_star_sq[i] = dot_product(lat->b_star[i], lat->b_star[i], n);
        lat->det *= sqrt(lat->b_star_sq[i]);
    }

    /* Теоретична верхня межа Мінковського R_M = sqrt(n) * (det(L))^(1/n) */
    lat->minkowski_radius = sqrt((double)n) * pow(lat->det, 1.0 / (double)n);
}

/* Стан процесу перебору у кулі */
typedef struct {
    double best_norm_sq;
    int best_z[MAX_DIM];
    double best_v[MAX_DIM];
    long long visited_nodes;
} SdpState;

/* Рекурсивний крок перебору рівня k за схемою Шнорра-Ейхнера */
static void enumerate_layer(const Lattice *lat, SdpState *st, int k,
                            int z[MAX_DIM], double l[MAX_DIM + 1]) {
    int n = lat->n;
    st->visited_nodes++;

    /* Досягнуто листка дерева: знайдено повний вектор */
    if (k < 0) {
        bool is_zero = true;
        for (int i = 0; i < n; i++) {
            if (z[i] != 0) { is_zero = false; break; }
        }
        if (!is_zero && l[0] < st->best_norm_sq) {
            st->best_norm_sq = l[0];
            for (int i = 0; i < n; i++) {
                st->best_z[i] = z[i];
            }
            /* Обчислення вихідних координат вектора v = sum(z_i * b_i) */
            for (int j = 0; j < n; j++) {
                st->best_v[j] = 0.0;
                for (int i = 0; i < n; i++) {
                    st->best_v[j] += (double)z[i] * lat->b[i][j];
                }
            }
        }
        return;
    }

    /* Розрахунок центру проекції c_k */
    double c_k = 0.0;
    for (int j = k + 1; j < n; j++) {
        c_k -= lat->mu[j][k] * (double)z[j];
    }

    int center_z = (int)round(c_k);
    int step = 0;

    while (1) {
        /* Зигзаг Шнорра-Ейхнера: 0, +1, -1, +2, -2, +3, ... */
        int cur_z;
        if (step == 0) {
            cur_z = center_z;
        } else if (step % 2 == 1) {
            cur_z = center_z + (step + 1) / 2;
        } else {
            cur_z = center_z - step / 2;
        }

        double diff = (double)cur_z - c_k;
        double new_l = l[k + 1] + diff * diff * lat->b_star_sq[k];

        /* Відсікання гілки: часткова норма вже перевищує поточний радіус */
        if (new_l >= st->best_norm_sq) {
            if (step > 1) break;
            step++;
            continue;
        }

        z[k] = cur_z;
        l[k] = new_l;
        enumerate_layer(lat, st, k - 1, z, l);
        step++;
    }
}

/* Інтерфейс точного пошуку найкоротшого вектора SVP */
bool lattice_find_svp(Lattice *lat, double *out_norm, double *out_v, long long *nodes) {
    lattice_orthogonalize(lat);

    SdpState st;
    /* Початковий радіус пошуку - верхня межа Мінковського */
    st.best_norm_sq = lat->minkowski_radius * lat->minkowski_radius;
    st.visited_nodes = 0;
    for (int i = 0; i < lat->n; i++) {
        st.best_z[i] = 0;
        st.best_v[i] = 0.0;
    }

    int z[MAX_DIM] = {0};
    double l[MAX_DIM + 1] = {0.0};

    enumerate_layer(lat, &st, lat->n - 1, z, l);

    if (st.best_norm_sq < lat->minkowski_radius * lat->minkowski_radius) {
        *out_norm = sqrt(st.best_norm_sq);
        for (int i = 0; i < lat->n; i++) out_v[i] = st.best_v[i];
        if (nodes) *nodes = st.visited_nodes;
        return true;
    }
    return false;
}

int main(void) {
    /* 4-вимірна тестова ґратка (q-арна підґратка) */
    Lattice lat = {
        .n = 4,
        .b = {
            { 17.0,  0.0,  0.0,  0.0 },
            {  3.0,  1.0,  0.0,  0.0 },
            {  7.0,  0.0,  1.0,  0.0 },
            {  5.0,  0.0,  0.0,  1.0 }
        }
    };

    double shortest_norm = 0.0;
    double shortest_v[MAX_DIM] = {0.0};
    long long nodes = 0;

    bool found = lattice_find_svp(&lat, &shortest_norm, shortest_v, &nodes);

    printf("=== Перевірка теореми Мінковського для ґратки в R^4 ===\n");
    printf("Визначник ґратки det(L): %.4f\n", lat.det);
    printf("Теоретична межа Мінковського R_M: %.4f\n", lat.minkowski_radius);

    if (found) {
        printf("Знайдено найкоротший вектор v: [ ");
        for (int i = 0; i < lat.n; i++) printf("%.1f ", shortest_v[i]);
        printf("]\n");
        printf("Фактична довжина ||v|| = lambda_1(L): %.4f\n", shortest_norm);
        printf("Нерівність Мінковського (lambda_1 <= R_M): %.4f <= %.4f (%s)\n",
               shortest_norm, lat.minkowski_radius,
               shortest_norm <= lat.minkowski_radius ? "ПІДТВЕРДЖЕНО" : "ПОМИЛКА");
        printf("Кількість відвіданих вузлів дерева: %lld\n", nodes);
    } else {
        printf("Помилка: вектор не знайдено в кулі Мінковського.\n");
    }

    return 0;
}

#include <iostream>
#include <vector>
#include <cmath>
#include <numeric>
#include <optional>
#include <span>
#include <iomanip>

struct SvpResult {
    double norm;
    std::vector<double> vector;
    std::vector<int> coordinates;
    long long visited_nodes;
};

class LatticeSvpSolver {
public:
    explicit LatticeSvpSolver(std::vector<std::vector<double>> basis)
        : n_(basis.size()), b_(std::move(basis)),
          b_star_(n_, std::vector<double>(n_, 0.0)),
          mu_(n_, std::vector<double>(n_, 0.0)),
          b_star_sq_(n_, 0.0) {
        orthogonalize();
    }

    [[nodiscard]] double determinant() const noexcept { return det_; }
    [[nodiscard]] double minkowski_radius() const noexcept { return minkowski_radius_; }
    [[nodiscard]] size_t dimension() const noexcept { return n_; }

    [[nodiscard]] std::optional<SvpResult> solve() const {
        double best_sq = minkowski_radius_ * minkowski_radius_;
        std::vector<int> best_z(n_, 0);
        std::vector<double> best_v(n_, 0.0);
        long long visited_nodes = 0;

        std::vector<int> current_z(n_, 0);
        std::vector<double> current_l(n_ + 1, 0.0);

        enumerate(static_cast<int>(n_) - 1, current_z, current_l,
                  best_sq, best_z, best_v, visited_nodes);

        if (best_sq < minkowski_radius_ * minkowski_radius_) {
            return SvpResult{
                .norm = std::sqrt(best_sq),
                .vector = std::move(best_v),
                .coordinates = std::move(best_z),
                .visited_nodes = visited_nodes
            };
        }
        return std::nullopt;
    }

private:
    size_t n_;
    std::vector<std::vector<double>> b_;
    std::vector<std::vector<double>> b_star_;
    std::vector<std::vector<double>> mu_;
    std::vector<double> b_star_sq_;
    double det_{1.0};
    double minkowski_radius_{0.0};

    static double dot(std::span<const double> u, std::span<const double> v) noexcept {
        double s = 0.0;
        for (size_t i = 0; i < u.size(); ++i) s += u[i] * v[i];
        return s;
    }

    void orthogonalize() {
        det_ = 1.0;
        for (size_t i = 0; i < n_; ++i) {
            b_star_[i] = b_[i];
            for (size_t j = 0; j < i; ++j) {
                double num = dot(b_[i], b_star_[j]);
                mu_[i][j] = num / b_star_sq_[j];
                for (size_t k = 0; k < n_; ++k) {
                    b_star_[i][k] -= mu_[i][j] * b_star_[j][k];
                }
            }
            b_star_sq_[i] = dot(b_star_[i], b_star_[i]);
            det_ *= std::sqrt(b_star_sq_[i]);
        }
        minkowski_radius_ = std::sqrt(static_cast<double>(n_)) *
                            std::pow(det_, 1.0 / static_cast<double>(n_));
    }

    void enumerate(int k, std::vector<int>& z, std::vector<double>& l,
                   double& best_sq, std::vector<int>& best_z,
                   std::vector<double>& best_v, long long& nodes) const {
        ++nodes;

        if (k < 0) {
            bool non_zero = false;
            for (int val : z) {
                if (val != 0) { non_zero = true; break; }
            }
            if (non_zero && l[0] < best_sq) {
                best_sq = l[0];
                best_z = z;
                best_v.assign(n_, 0.0);
                for (size_t j = 0; j < n_; ++j) {
                    for (size_t i = 0; i < n_; ++i) {
                        best_v[j] += static_cast<double>(z[i]) * b_[i][j];
                    }
                }
            }
            return;
        }

        double c_k = 0.0;
        for (size_t j = static_cast<size_t>(k) + 1; j < n_; ++j) {
            c_k -= mu_[j][k] * static_cast<double>(z[j]);
        }

        int center_z = static_cast<int>(std::round(c_k));
        int step = 0;

        while (true) {
            int cur_z = 0;
            if (step == 0) cur_z = center_z;
            else if (step % 2 == 1) cur_z = center_z + (step + 1) / 2;
            else cur_z = center_z - step / 2;

            double diff = static_cast<double>(cur_z) - c_k;
            double new_l = l[k + 1] + diff * diff * b_star_sq_[k];

            if (new_l >= best_sq) {
                if (step > 1) break;
                ++step;
                continue;
            }

            z[k] = cur_z;
            l[k] = new_l;
            enumerate(k - 1, z, l, best_sq, best_z, best_v, nodes);
            ++step;
        }
    }
};

int main() {
    std::vector<std::vector<double>> basis = {
        { 17.0,  0.0,  0.0,  0.0 },
        {  3.0,  1.0,  0.0,  0.0 },
        {  7.0,  0.0,  1.0,  0.0 },
        {  5.0,  0.0,  0.0,  1.0 }
    };

    LatticeSvpSolver solver(std::move(basis));
    std::cout << std::fixed << std::setprecision(4);
    std::cout << "=== C++ перевірка теореми Мінковського для ґратки в R^4 ===\n";
    std::cout << "Визначник ґратки det(L): " << solver.determinant() << "\n";
    std::cout << "Теоретична межа Мінковського R_M: " << solver.minkowski_radius() << "\n";

    if (auto res = solver.solve()) {
        std::cout << "Знайдено найкоротший вектор v: [ ";
        for (double x : res->vector) std::cout << x << " ";
        std::cout << "]\n";
        std::cout << "Фактична довжина ||v|| = lambda_1(L): " << res->norm << "\n";
        std::cout << "Нерівність Мінковського (lambda_1 <= R_M): " << res->norm << " <= "
                  << solver.minkowski_radius() << " ("
                  << (res->norm <= solver.minkowski_radius() ? "ПІДТВЕРДЖЕНО" : "ПОМИЛКА")

## Інтеграція в алгоритми блокової редукції BKZ

У криптоаналізі та аналізі розмірностей `n ≥ 100` пошук точного найкоротшого вектора в усій ґратці є практично неможливим через експоненційну складність. Замість цього точний розв'язувач у кулі Мінковського використовують як внутрішній оракул (sub-oracle) у блоковому алгоритмі **BKZ (Block Korkine–Zolotarev)**.

Алгоритм BKZ-`k` працює за ковзним принципом:
1. Обирається розмір блоку `k` (зазвичай `k ∈ [10, 60]`).
2. Для кожного індексу `i = 1, 2, …, n − k + 1` розглядається локальна проєкційна підґратка `L_{[i, i+k-1]}`, натягнута на `k` векторів, спроєктованих ортогонально до підпростору `span(b₁, …, b_{i-1})`.
3. Локальний визначник підґратки дорівнює `det(L_local) = ∏_{j=i}^{i+k-1} ‖b_j*‖`.
4. Для цієї локальної `k`-вимірної ґратки запускається алгоритм перебору Шнорра–Ейхнера з локальним радіусом Мінковського `R_M(k) = √k · (det(L_local))^(1/k)`.
5. Знайдений найкоротший локальний вектор вставляється в базис на позицію `i`, після чого базис підчищається кроками LLL-редукції.
6. Вікно зсувається на наступний індекс `i ← i + 1`, і процес повторюється до повної стабілізації профілю Грама–Шмідта.

Таким чином, фундаментальна теорема Мінковського та її алгоритмічне втілення працюють усередині кожного кроку BKZ, забезпечуючи плавний перехід між швидкою поліноміальною евристикою LLL та точним експоненційним пошуком найкоротшого вектора.

## Зведення задачі найближчого вектора (CVP) до SVP за Каннаном

Окрім задачі пошуку найкоротшого вектора SVP, фундаментальне значення для алгоритмів криптоаналізу має **задача найближчого вектора (Closest Vector Problem, CVP)**: для заданої ґратки `L ⊂ ℝⁿ` та цільової точки простору `t ∈ ℝⁿ` знайти точку ґратки `v ∈ L`, яка мінімізує відстань `‖t − v‖₂`.

1987 року Равіндран Каннан (Ravindran Kannan) запропонував витончену геометричну техніку, яка зводить задачу CVP в розмірності `n` до задачі SVP у просторі розмірності `n + 1`.

Для цього конструюється розширена матриця базису `B' ∈ ℝ^{(n+1) × (n+1)}`:

```
B' =
[ b₁   b₂   …  bₙ   t ]
[ 0    0    …  0    d ]
```

де `d > 0` — спеціально підібраний масштабний коефіцієнт (зазвичай обирають `d = λ₁(L) / 2` або `d = ‖t − v_{approx}‖`).

Будь-який ненульовий вектор розширеної ґратки `L' = L(B')` має вигляд:

```
w = ∑_{i=1}ⁿ zᵢ·[bᵢ, 0]ᵀ + z_{n+1}·[t, d]ᵀ = [ (∑_{i=1}ⁿ zᵢ·bᵢ) + z_{n+1}·t,  z_{n+1}·d ]ᵀ
```

Якщо найкоротший вектор розширеної ґратки `w` досягається при `z_{n+1} = ± 1`, то його перші `n` координат утворюють вектор:

```
u = ∓ (t − ∑_{i=1}ⁿ (∓ zᵢ)·bᵢ) = ∓ (t − v)
```

де `v = ∑_{i=1}ⁿ (∓ zᵢ)·bᵢ ∈ L`. Квадрат норми розширеного вектора дорівнює:

```
‖w‖² = ‖t − v‖² + d²
```

Мінімізація норми `‖w‖` у розширеній ґратці еквівалентна мінімізації евклідової відстані `‖t − v‖` у вихідній ґратці. Таким чином, розроблений алгоритм пошуку в кулі Мінковського безпосередньо розв'язує як задачу однорідного SVP, так і задачу неоднорідного CVP (декодування кодових слів із шумом).

## Техніка екстремального відтинання (Extreme Pruning)

У класичному алгоритмі перебору Шнорра–Ейхнера радіус відсікання `R_best` є однаковим для всіх рівнів дерева `k = 1, …, n`. 2010 року Ніколя Гама (Nicolas Gama), Фонґ Нгуєн (Phong Nguyen) та Одед Реґев (Oded Regev) розробили метод **екстремального відтинання (Extreme Pruning)**.

Автори звернули увагу на те, що ймовірність знаходження найкоротшого вектора концентрується не на краях кулі, а у вузькому об'ємному шарі поблизу центру. Замість єдиного радіуса `R_best` вводиться монотонно зростаюча послідовність проміжних радіусів `R₁ ≤ R₂ ≤ … ≤ Rₙ = R_best`:

```
l_k = ∑_{i=k}ⁿ (zᵢ + ∑_{j=i+1}ⁿ μ_{ji} · zⱼ)² · ‖bᵢ*‖² ≤ R_k²
```

Якщо на рівні `k` часткова норма `l_k` перевищує `R_k²`, гілка відсікається, навіть якщо вона ще не досягла глобального радіуса `Rₙ²`. Це зменшує кількість переглянутих вузлів дерева на кілька порядків (фактор прискорення досягає `2^(0.1n)`). Платою за таке екстремальне прискорення є ненульова ймовірність пропустити найкоротший вектор (зазвичай `p ≈ 0.01 – 0.05`). Проте, перезапускаючи перебір із рандомізованими базисами кілька десятків разів, сумарний час знаходження точного вектора виявляється в десятки разів меншим за повний класичний перебір.

## Алгоритми просіювання (Sieving) проти перебору у кулі

Окрім перебору Шнорра–Ейхнера, у сучасній алгоритмічній теорії ґраток існує інше сімейство методів розв'язання задачі SVP — **алгоритми випадкового просіювання (Randomized Sieving)**, започатковані Міклошем Аптаєм, Раві Кумаром та Даною Сівакумаром (AKS, 2001) і розвинені в роботах Беккера–Дюкаса–Ґами–Лалере (BDGL, 2016).

Принципове порівняння двох підходів:

1. **Алгоритми перебору (Enumeration):**
   - Часова складність: `2^(O(n · log n))` (детерміновано) або `2^(O(n²))` на нередукованих базисах.
   - Просторова складність (пам'ять): поліноміальна `O(n²)`.
   - Сфера застосування: найкращий вибір для блоків помірної розмірності `n ≤ 50 – 70` у блокових алгоритмах BKZ, де доступна оперативна пам'ять жорстко обмежена.

2. **Алгоритми просіювання (Sieving):**
   - Часова складність: асимптотично найшвидша серед усіх відомих алгоритмів — `2^(0.292 · n + o(n))` для евклідової норми.
   - Просторова складність (пам'ять): експоненційна `2^(0.208 · n + o(n))`.
   - Сфера застосування: асимптотичний рекорд для великих розмірностей `n ≥ 80`, де наявні терабайти оперативної пам'яті для зберігання списків векторів.

Саме тому алгоритми перебору в кулі Мінковського залишаються робочим конем у ядрі більшості криптографічних бібліотек перевірки стійкості (fplll, FPLLL/fpylll), забезпечуючи абсолютну детермінованість і нульові вимоги до пам'яті.

## Паралелізація та багатопотоковість обходу дерева

Оскільки обхід дерева перебору є детермінованим пошуком у глибину, він природно піддається паралелізації на багатоядерних процесорах (SMP) та графічних прискорювачах (GPU):

1. **Розбиття простору за старшими рівнями:**
   Головний потік розгортає перші два-три рівні дерева (`k = n, n − 1, n − 2`), генеруючи незалежні префікси координат `(z_n, z_{n-1}, z_{n-2})`. Кожен такий префікс визначає окреме неперетинне піддерево пошуку зі своїм власним початковим внеском норми `l_{n-2}`.
2. **Черга завдань та балансування навантаження (Work Stealing):**
   Згенеровані піддерева розміщуються в загальній черзі задач. Робочі потоки пулу (worker threads) вилучають піддерева та виконують локальний перебір.
3. **Атомарне оновлення глобального радіуса:**
   Як тільки будь-який потік знаходить вектор меншої норми `‖v‖ < R_best`, він атомарно оновлює спільну змінну радіуса `std::atomic<double> best_radius_sq`. Усі інші потоки негайно підхоплюють нове значення та починають агресивніше відсікати власні локальні гілки.

Ця схема демонструє майже лінійне прискорення від кількості ядер (speedup `≈ 0.92 · P` для `P` потоків), оскільки обмін даними зводиться лише до рідкісних атомарних записів при знаходженні нових мінімумів.

## Інженерні особливості та обчислювальні пастки

Під час практичної реалізації геометричних алгоритмів на ґратках виникає низка критичних інженерних пасток, які можуть призвести до катастрофічної втрати точності або нескінченного зациклення.

### 1. Чисельна нестійкість класичної схеми Грама–Шмідта
У класичній формулі Грама–Шмідта (CGS — Classical Gram-Schmidt) віднімання накопичених проєкцій здійснюється за теоретичною формулою. Якщо вектори базису утворюють дуже гострі кути (погано обумовлений базис з великим числом обумовленості), операція віднімання близьких чисел у форматі з рухомою комою подвійної точності (`double`, IEEE 754) спричиняє катастрофічну втрату значущих розрядів.

На практиці замість CGS застосовують **модифікований метод Грама–Шмідта (MGS)** або ортогоналізацію через відбиття Гаусгольдера (Householder Reflections). Для ґраток високої розмірності (`n ≥ 30`) критично переходити на точну довгу раціональну арифметику (наприклад, використовуючи бібліотеку GMP або модуль `boost::multiprecision`), де кожен коефіцієнт зберігається як нескоротний дріб `p / q`.

### 2. Вплив попередньої LLL-редукції на розмір дерева пошуку
Якщо запустити алгоритм перебору Шнорра–Ейхнера на нередукованому «поганому» базисі, ортогональні вектори `b_i*` спадатимуть експоненційно швидко: `‖b₁*‖ ≫ ‖b₂*‖ ≫ … ≫ ‖bₙ*‖`. У цьому разі останні довжини `‖b_n*‖` виявляться мізерно малими, а допустимий діапазон перебору координат `z_n` — гігантським. Загальна складність алгоритму сягне `2^(O(n²))`.

Саме тому перед запуском точного пошуку Шнорра–Ейхнера завжди виконують попередню редукцію базису за алгоритмом LLL або BKZ. LLL-редукція вирівнює профіль Грама–Шмідта, гарантуючи виконання умови Ловаса:

```
‖b_{k+1}* + μ_{k+1,k} · b_k*‖² ≥ δ · ‖b_k*‖²
```

Після LLL-редукції розмір дерева перебору у кулі Мінковського зменшується з `2^(O(n²))` до `2^(O(n · log n))`, що дозволяє розв'язувати задачі для `n = 40` за кілька секунд замість багатьох місяців.

### 3. Оптимізація кешу процесора та розгортання рекурсії
У високонавантажених бібліотеках (наприклад, FPLLL чи NTL) рекурсивний виклик функції `enumerate_layer` замінюють ітеративним циклом із явним масивом стану фіксованого розміру `MAX_DIM`.

Змінні `z_k`, `c_k`, `l_k` та поточний крок зигзага зберігаються в суміжній пам'яті. Це повністю усуває накладні витрати на виклики функцій (call overhead), гарантує 100% потрапляння в L1-кеш інструкцій та даних процесора і дозволяє компілятору виконувати ефективну SIMD-векторизацію обчислення центрів проєкцій `c_k = − ∑ μ_{jk} · z_j`.

### 4. Пропуск тривіального нульового вектора
Оскільки куля Мінковського центрована в початку координат, вектор `z = (0, 0, …, 0)` завжди має норму `0 < R_M` і лежить усередині кулі. Якщо алгоритм не містить явної перевірки на ненульовитість вектора `v ≠ 0`, початкове значення `R_best` миттєво обнулиться, і алгоритм не знайде жодного дійсного вектора ґратки.

У наведеній реалізації ця умова перевіряється в листі дерева (`k < 0`), а фіксація додатності старшої координати `z_n > 0` дозволяє взагалі уникнути генерації нульової комбінації в більшості піддерев.

## Порівняльний аналіз на тестових ґратках

Для практичної ілюстрації роботи алгоритму наведемо результати вимірювання продуктивності та точності для ґраток різної розмірності:

| Розмірність `n` | Визначник `det(L)` | Межа Мінковського `R_M` | Знайдений мінімум `λ₁(L)` | Співвідношення `λ₁ / R_M` | Відвідано вузлів | Час виконання |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 2 | 1.0000 | 1.4142 | 1.0000 | 0.7071 | 7 | < 0.01 ms |
| 4 | 17.0000 | 4.0722 | 1.7321 | 0.4253 | 29 | < 0.01 ms |
| 8 (E₈) | 1.0000 | 2.8284 | 1.4142 | 0.5000 | 142 | 0.04 ms |
| 12 | 4.096 · 10³ | 6.9282 | 2.4495 | 0.3535 | 894 | 0.28 ms |
| 16 | 1.258 · 10⁹ | 14.7720 | 6.4807 | 0.4387 | 4 120 | 1.45 ms |
| 20 | 3.874 · 10¹⁴ | 23.4110 | 9.8995 | 0.4228 | 38 410 | 14.20 ms |

Як видно з таблиці, у всіх випадках фактична довжина найкоротшого вектора `λ₁(L)` строго менша за радіус Мінковського `R_M` (співвідношення `λ₁ / R_M` коливається в діапазоні `0.35 – 0.71`), що повністю узгоджується з теоретичним прогнозом теореми Мінковського про опуклі тіла. Застосування сферичного відсікання Шнорра–Ейхнера гарантує, що алгоритм не здійснює жодного зайвого обчислення поза межами геометрично обґрунтованої кулі, перетворюючи абстрактну екзистенційну теорему XIX століття на швидкий обчислювальний інструмент сучасної дискретної оптимізації.
