# 📋 Інтерфейс модуля твістованої кривої та стиснення точок G₂

Специфікація програмного інтерфейсу (API) модуля твістованої кривої визначає контракт між криптографічним ядром нижнього рівня та високорівневими протоколами спарування (Miller loop, Ate pairing, ZK-SNARK verifier). Модуль забезпечує створення точок, валідацію, стиснення координат над полем розширення `𝔽_{p^2}` та операції розтвістування для точок групи `G_2`.

Цей документаційний модуль подає повний системний довідник API для бібліотек криптографії спарувань. Описано схеми бітових пакувань, контракти функцій, коди помилок, вимоги до константного часу виконання, а також точні специфікації вхідних та вихідних форматів для статичних прекомпайлів Віртуальної машини Ethereum (EVM precompiles).

Архітектурно інтерфейс розподілено на чотири рівні: шар системної конфігурації полів, шар перевірки геометричної валідності, шар трансформацій стиснення координат та шар підготовки коефіцієнтів для алгоритму Міллера. Кожен шар гарантує ізоляцію пам'яті, стійкість до атак за часом виконання та сумісність із бінарними стандартами криптографічних специфікацій.

Програмний контракт API розроблено з урахуванням суворих вимог криптографічної стійкості. Усі операції зчитування та запису буферів координат виконуються у фіксованому константному часі без використання таблиць пошуку (lookup tables), що розгалужуються за секретними даними. Це забезпечує повний захист від атак за побічними каналами часу виконання процесора (timing side-channel attacks) та витоків через кєш-пам'ять першого рівня (L1 cache leakages).

Специфікація інтерфейсу передбачає відсутність умовних розгалужень, залежних від даних, на всіх рівнях виконання. Усі операції порівняння координат здійснюються через побітові операції `OR` та `XOR` над масивами байтів, гарантуючи детермінований час відгуку системи під будь-яким навантаженням.

Безпека пам'яті контролюється на рівні типів даних C++20 через обгортки `std::span` та `std::expected`. Це робить неможливими помилки виходу за межі масиву (out-of-bounds access) або пошкодження стека при обробці невалідних мережевих пакетів.

## 1. Структури даних та бітові укладення

Модуль використовує фіксовані байтові буфери для представлення точок кривої в нестисненому та стисненому форматах. Буфери передаються через бінарні масиви у байтовому порядку Big-Endian (від старшого байта до молодшого), що є стандартом для протоколів мереж Ethereum, Zcash та RFC 9380.

Представлення координат над розширеним полем `𝔽_{p^2}` складається з двох послідовних компонентів `(c_0, c_1)`, де кожен компонент є елементом базового поля `𝔽_p`. Координата `x' = c_0 + c_1 · u` займає удвічі більше пам'яті, ніж координата у `𝔽_p`. Першим у буфері завжди записується молодший коефіцієнт `c_0`, за яким слідує старший коефіцієнт `c_1`.

### 1.1 Параметри полів та точок

Розміри байтових масивів залежать від обраного параметричного сімейства еліптичних кривих. Нижче подано конфігураційні константи для кривих BLS12-381 та BN254.

:::tabs
```c
// Формати точок для кривої BLS12-381 (Field p size = 381 bits / 48 bytes)
#define BLS12_381_FP_BYTES        48
#define BLS12_381_FP2_BYTES       96   // 2 * 48 bytes (c0, c1)
#define BLS12_381_G2_UNCOMPRESSED 192  // (x, y) in FP2 = 2 * 96 bytes
#define BLS12_381_G2_COMPRESSED   96   // x in FP2 + flags in top bits

// Формати точок для кривої BN254 / alt_bn128 (Field p size = 254 bits / 32 bytes)
#define BN254_FP_BYTES            32
#define BN254_FP2_BYTES           64   // 2 * 32 bytes
#define BN254_G2_UNCOMPRESSED     128  // (x, y) in FP2 = 2 * 64 bytes
#define BN254_G2_COMPRESSED       64   // x in FP2 + sign bit
```
```cpp
// Формати точок у стилі C++20 з constexpr
#include <cstddef>

namespace crypto::config {
    constexpr std::size_t kBls12_381FpBytes        = 48;
    constexpr std::size_t kBls12_381Fp2Bytes       = 96;  // 2 * 48 bytes
    constexpr std::size_t kBls12_381G2Uncompressed = 192; // (x, y) in Fp2
    constexpr std::size_t kBls12_381G2Compressed   = 96;  // x in Fp2 + flags

    constexpr std::size_t kBn254FpBytes            = 32;
    constexpr std::size_t kBn254Fp2Bytes           = 64;
    constexpr std::size_t kBn254G2Uncompressed     = 128;
    constexpr std::size_t kBn254G2Compressed       = 64;
}
```
:::

У системному середовищі вибір розміру буферів вирівнюється за межами 64-бітних слів (64-bit alignment), що дозволяє використовувати SIMD-інструкції (AVX2, AVX-512, ARM Neon) для паралельного виконання множень у полем `𝔽_p`.

Пакування елементів `c_0, c_1` у системній пам'яті здійснюється без проміжних байтів заповнення (zero-padding), що гарантує двійкову сумісність із бінарним представленням прекомпайлів віртуальних машин.

Внутрішня структура буфера зберігає координати у відносному форматі без урахування старших нулів. При читанні масиву модуль контролює відсутність байтів, що виходять за граничний модуль поля `p`.

Кожен буфер точки у пам'яті вирівнюється по межах 64 байтів для оптимального завантаження в регістри процесорного кєшу L1.

Представлення нульової точки `𝒪` у пакувальному масиві виконується шляхом очищення всіх компонентів буфера із встановленням біта нескінченності.

Для оптимізації обміну даними між вузлами блокчейна структура координат підтримує прямовисне ущільнення в пам'яті.

Сумісність специфікації бітових форматів перевіряється при складанні модулів через статичні вирази `static_assert`.

Кожен системний масив супроводжується метаінформацією про довжину у байтах, виключаючи мовну невизначеність.

### 1.2 Біти прапорів стисненого формату G₂

У стисненому форматі координата `y' ∈ 𝔽_{p^2}` вилучається, а її старший біт еквівалентності або старший біт знаку вбудовується у найстарші біти буфера координати `x'`. Оскільки модуль поля `p` для BLS12-381 має розмір 381 біт, а 48 байтів вміщують 384 біти, 3 найстарші біти першого байта є вільними і використовуються як кодувальні прапори:

Прапорець `COMPRESSED_BIT` (значення `0x80`) визначає спосіб інтерпретації вхідного масиву. Якщо цей біт встановлено у `1`, масив трактується як стиснена точка розміром 96 байтів, де записана координата `x'` та прапори знаку `y'`. Якщо біт дорівнює `0`, буфер вимагає довжини 192 байти і містить явні координати `(x', y')`.

Прапорець `INFINITY_BIT` (значення `0x40`) вказує на те, що точка є нейтральним елементом групи (точкою на нескінченності `𝒪`). При встановленні цього біта всі інші біти коефіцієнтів `x'` та `y'` повинні бути нульовими, інакше декомпресор повертає статус некоректного кодування.

Прапорець `LEXICOGRAPHICAL_Y` (значення `0x20`) задає знак координати `y'` під час відновлення точки. Оскільки квадратне рівняння `y'^2 = x'^3 + b_{twist}` має два корені у полем `𝔽_{p^2}`, цей біт обирає лексикографічно старший корінь, якщо встановлено `1`, або молодший корінь, якщо встановлено `0`.

Лексикографічне порівняння двох компонентів `y_0' = a_0 + a_1 u` та `y_1' = -y_0'` виконується послідовним зіставленням компонентів `a_1` та `a_0` з половинним значенням модуля `(p-1)/2`. Це забезпечує унікальність декомпресії для будь-якої вхідної точки.

Правила кодування прапорів регламентуються стандартом RFC 9380. Усі нереалізовані біти найстаршого байта повинні строго дорівнювати нулю, забезпечуючи детерміноване парсування бінарних структур.

Очищення прапорцевих бітів перед передачею в арифметичний блок здійснюється побітовим маскуванням `AND` із константою `0x1F`.

Перевірка коректності прапорців виключає можливість двозначної інтерпретації стисненого буфера різними реалізаціями спарувань.

Зміна прапорів під час передавання точок миттєво відхиляється декодером статусу.

## 2. Коди повернення та статус помилок

Усі функції API повертають цілочисельний статус або типізовану помилку виконання. Принцип детермінованості вимагає, щоб будь-яка спроба передачі невалідних точок чи некоректно закодованих прапорців викликала миттєве повернення відповідного коду помилки без порушення безпеки пам'яті.

Помилка `TWIST_ERR_NULL_POINTER` повертається у разі спроби передавання порожнього вказівника на контекст або буфер даних, захищаючи модуль від падіння процесу через некоректну адресацію.

Статус `TWIST_ERR_INVALID_X` інформує про те, що коефіцієнти координати `x'` перевищують значення модуля базового поля `p`. Кожен елемент `c_0, c_1` повинен строго задовольняти нерівність `0 ≤ c_i < p`.

Код `TWIST_ERR_NOT_ON_CURVE` виникає, коли відновлені або передані координати `(x', y')` не задовольняють рівняння твістованої кривої `y'^2 = x'^3 + b_{twist}`. Це гарантує геометричну цілісність точок.

Статус `TWIST_ERR_SUBGROUP_FAILED` свідчить про те, що точка належить кривій `E'`, але не належить до підгрупи `G_2` порядку `r`. Така ситуація сигналізує про можливу спробу проведения атаки малого порядку і вимагає негайного відхилення вхідних даних.

Помилка `TWIST_ERR_INVALID_FLAGS` виникає при виявленні суперечливих комбінацій прапорів у найстаршому байті, наприклад, при спробі встановити біт нескінченності разом із ненульовими коефіцієнтами координат.

Помилка `TWIST_ERR_DECOMPRESS_FAILED` сповіщає про те, що значення `x'^3 + b_{twist}` є квадратичним нелишком у полем `𝔽_{p^2}`, що вказує на фальсифікацію стисненого буфера.

:::tabs
```c
typedef enum {
    TWIST_SUCCESS               = 0x00, // Операцію виконано успішно
    TWIST_ERR_NULL_POINTER      = 0x01, // Передано вказівник NULL
    TWIST_ERR_INVALID_X         = 0x02, // Координата x не належить полю 𝔽_{p^2}
    TWIST_ERR_NOT_ON_CURVE      = 0x03, // Точка не задовольняє рівняння E'
    TWIST_ERR_SUBGROUP_FAILED   = 0x04, // Перевірка порядку r * Q' != O провалилася
    TWIST_ERR_INVALID_FLAGS     = 0x05, // Неприпустима комбінація прапорців стиснення
    TWIST_ERR_DECOMPRESS_FAILED = 0x06  // Квадратний корінь для y' не існує в 𝔽_{p^2}
} twist_status_t;
```
```cpp
#include <cstdint>

enum class TwistStatus : std::uint32_t {
    kSuccess          = 0x00, // Операцію виконано успішно
    kNullPointer      = 0x01, // Передано порожній вказівник
    kInvalidX         = 0x02, // Координата x не належить полю 𝔽_{p^2}
    kNotOnCurve       = 0x03, // Точка не задовольняє рівняння E'
    kSubgroupFailed   = 0x04, // Перевірка порядку r * Q' != O провалилася
    kInvalidFlags     = 0x05, // Неприпустима комбінація прапорців
    kDecompressFailed = 0x06  // Корінь для y' не існує в 𝔽_{p^2}
};
```
:::

Детермінована обробка статусу гарантує, що коди помилок є взаємно виключними (mutually exclusive) і дозволяють вищому рівню застосунку точно дігностувати причину відхилення точки.

Жоден із кодів помилок не витікає у вигляді неперехоплених системних винятків. Усі функції модуля повертають статус у вигляді строгого числового значення.

Системний журнал помилок підтримує детальний аудит без розкриття проміжних обчислювальних даних.

## 3. Сигнатури функцій C та C++ API

### 3.1 Створення та ініціалізація

Функції ініціалізації виділяють та налаштовують контекст кривої, завантажуючи константи Фробеніуса `γ = ξ^{(p-1)/6} ∈ 𝔽_{p^2}` та коефіцієнти твістованого рівняння `b_{twist} = b / ξ` (D-type) або `b_{twist} = b · ξ` (M-type).

Контекст кривої є незмінним (immutable) після створення і може безпечно використовуватися кількома потоками виконання паралельно без застосування заблокувань (thread-safe architecture).

Під час ініціалізації контексту проводиться попередня таблична генерація степенів Фробеніуса для прискорення розкладу GLS під час багатьох скалярних множень.

:::tabs
```c
/**
 * @brief Ініціалізує контекст твістованої кривої E'
 * @param ctx Повертає вказівник на створений контекст
 * @param curve_id Ідентифікатор кривої (BN254 = 1, BLS12_381 = 2)
 * @param twist_type Тип твісту (D_TYPE = 0, M_TYPE = 1)
 * @return TWIST_SUCCESS у разі успіху
 */
twist_status_t twist_ctx_init(
    twist_ctx_t** ctx,
    uint32_t curve_id,
    uint32_t twist_type
);

/**
 * @brief Звільняє ресурси контексту кривої
 */
void twist_ctx_free(twist_ctx_t* ctx);
```
```cpp
#include <memory>
#include <expected>

class TwistContext {
public:
    enum class CurveId : std::uint32_t { kBn254 = 1, kBls12_381 = 2 };
    enum class TwistType : std::uint32_t { kDType = 0, kMType = 1 };

    static std::expected<std::unique_ptr<TwistContext>, TwistStatus> create(
        CurveId curve_id,
        TwistType twist_type
    ) noexcept;

    ~TwistContext() noexcept;
};
```
:::

Контекст також виступає обгорткою над внутрішніми робочими буферами арифметики поля Монтгомері, гарантуючи ізоляцію стеків потоків виконання.

Багаторазове використання єдиного екземпляра контексту кількома потоками усуває накладні витрати на повторне завантаження параметрів полів.

### 3.2 Перевірка валідності та належності до групи

Функції перевірки виконують геометричну та алгебраїчну валідацію вхідних точок. Перевірка `twist_g2_is_on_curve` контролює підставлення координат `(x', y')` у рівняння твісту `y'^2 == x'^3 + b_{twist}`. Перевірка `twist_g2_validate_subgroup` підтверджує, що точка належить до криптографічної підгрупи `G_2` порядку `r`, захищаючи криптосистему від атак з використанням точок малого порядку.

Перевірка належності до підгрупи використовує швидкий поліном Фробеніуса Скотта `[x] π_p'(Q') - Q' == 𝒪`, що дозволяє підтвердити порядок точки у понад п'ять разів швидше, ніж повне скалярне множення на порядок `r`.

Ці перевірки є обов'язковими для кожного криптографічного виклику, який приймає точки `G_2` із зовнішніх або незахищених джерел мережі.

:::tabs
```c
/**
 * @brief Перевіряє, чи задовольняє точка рівняння твістованої кривої E'
 * @param ctx Контекст кривої
 * @param in_g2_uncompressed Буфер з координатами (x', y') над 𝔽_{p^2}
 * @return TWIST_SUCCESS якщо точка на кривій, TWIST_ERR_NOT_ON_CURVE інакше
 */
twist_status_t twist_g2_is_on_curve(
    const twist_ctx_t* ctx,
    const uint8_t* in_g2_uncompressed
);

/**
 * @brief Перевіряє належність точки до криптографічної підгрупи G₂ порядку r
 * @details Виконує множення r * Q' або оцінку ендоморфізму Фробеніуса Скотта
 * @param ctx Контекст кривої
 * @param in_g2_uncompressed Буфер точки (x', y')
 * @return TWIST_SUCCESS якщо r * Q' == O
 */
twist_status_t twist_g2_validate_subgroup(
    const twist_ctx_t* ctx,
    const uint8_t* in_g2_uncompressed
);
```
```cpp
#include <span>

class G2Validator {
public:
    [[nodiscard]] std::expected<void, TwistStatus> is_on_curve(
        std::span<const std::uint8_t> in_g2_uncompressed
    ) const noexcept;

    [[nodiscard]] std::expected<void, TwistStatus> validate_subgroup(
        std::span<const std::uint8_t> in_g2_uncompressed
    ) const noexcept;
};
```
:::

У разі виявлення точки малого порядку функція перевірки повертає помилку негайно, упереджуючи виконання алгоритму Міллера та захищаючи приватні ключі.

Системний виклик перевірки підгрупи автоматично очищає тимчасові регістри після виконання полінома Скотта.

### 3.3 Стиснення та декомпресія точок

Операції стиснення та відновлення (декомпресії) здійснюють конвертацію між розгорнутим форматом координат `(x', y')` та стисненим буфером, що містить лише координату `x'` та біт знаку. Процедура декомпресії обчислює корінь `y' = √(x'^3 + b_{twist})` у полі `𝔽_{p^2}` за алгоритмом Тонеллі-Шенкса.

У разі, якщо значення `x'^3 + b_{twist}` виявляється квадратичним нелишком у полем `𝔽_{p^2}`, квадратний корінь не існує. У цій ситуації функція декомпресії повертає статус `TWIST_ERR_DECOMPRESS_FAILED`, що вказує на пошкодження стисненого буфера або фальсифікацію даних.

Стиснення точок скорочує мережевий обсяг передавання відкритих ключів та цифрових підписів удвічі.

:::tabs
```c
/**
 * @brief Стискає точку G₂ з формату (x', y') у формат x' + біт знаку y'
 * @param ctx Контекст кривої
 * @param out_compressed Вихідний буфер розмінності FP2_BYTES
 * @param in_uncompressed Вхідна точка розмінності 2 * FP2_BYTES
 * @return TWIST_SUCCESS у разі успіху
 */
twist_status_t twist_g2_compress(
    const twist_ctx_t* ctx,
    uint8_t* out_compressed,
    const uint8_t* in_uncompressed
);

/**
 * @brief Відновлює нестиснену точку (x', y') зі стисненого буфера
 * @details Обчислює y'^2 = x'^3 + b_twist та знаходить квадратний корінь у 𝔽_{p^2}
 * @param ctx Контекст кривої
 * @param out_uncompressed Вихідний буфер 2 * FP2_BYTES
 * @param in_compressed Вхідний стиснений буфер FP2_BYTES
 * @return TWIST_SUCCESS або TWIST_ERR_DECOMPRESS_FAILED
 */
twist_status_t twist_g2_decompress(
    const twist_ctx_t* ctx,
    uint8_t* out_uncompressed,
    const uint8_t* in_compressed
);
```
```cpp

public:

        std::span<std::uint8_t> out_compressed,

    [[nodiscard]] std::expected<void, TwistStatus> decompress(
```

Процедура декомпресії контролює відсутність переповнення буфера та гарантує виконання в постійному часі незалежно від значення вхідних байтів.

Алгоритм Тонеллі-Шенкса у полем `𝔽_{p^2}` розгортається у фіксовану послідовність квадратів та множень без розгалужень за бітами коефіцієнтів.

### 3.4 Перетворення розтвістування (Untwisting Interface)

Інтерфейс розтвістування переводить точку `Q' ∈ E'(𝔽_{p^2})` у пару розріджених коефіцієнтів `(x' w^2, y' w^3)` поля `𝔽_{p^{12}}`. Отримані значення передаються безпосередньо у внутрішній цикл алгоритму Міллера для швидкої оцінки лінійних функцій `l_{P, Q'}(T)`.

Ця операція не виділяє динамічну пам'ять і гарантує виконання в констатному часі, оскільки множення координат `x'` та `y'` на фіксовані базисні елементи вежі `w^2` та `w^3` зводиться до перестановки та зсуву коефіцієнтів у структурі `𝔽_{p^{12}}`.

Завдяки прямій подачі розріджених коефіцієнтів у конвеєр алгоритму Міллера обчислювальний цикл повністю минає загальне множення у полем `𝔽_{p^{12}}`.

:::tabs
```c
/**
 * @brief Обчислює розтвістовані коефіцієнти для кроку алгоритму Міллера
 * @details Переводить Q' = (x', y') ∈ E'(𝔽_{p^2}) у розріджений елемент (x' w^2, y' w^3)
 * @param ctx Контекст кривої
 * @param out_x_coeff Вихідний коефіцієнт біля w^2 (в 𝔽_{p^2})
 * @param out_y_coeff Вихідний коефіцієнт біля w^3 (в 𝔽_{p^2})
 * @param in_g2_point Вхідна точка твістованої кривої
 * @return TWIST_SUCCESS
 */
twist_status_t twist_g2_untwist_for_miller(
    const twist_ctx_t* ctx,
    uint8_t* out_x_coeff,
    uint8_t* out_y_coeff,
    const uint8_t* in_g2_point
);
```

Перетворення розтвістування підтримує як D-type, так і M-type конфігурації залежно від вибраного прапора ініціалізації контексту.

## 4. Конфігурація для середовищ виконання (EVM Precompiles)

Для інтеграції твістованої арифметики у Віртуальну машину Ethereum (EVM) виклики зводяться до статичних прекомпайлів за фіксованими адресами.

### 4.1 Специфікація precompile `alt_bn128_pairing` (Адреса `0x08`)

Вхідний буфер прекомпайлу очікує послідовність пар точок `(P_i, Q_i)`, де кожна точка `Q_i ∈ G_2` представлена у нестисненому M-type твістованому вигляді:

```
Розмір вхідного блоку для однієї пари (P_i, Q_i): 192 байти
├── 0x00 .. 0x3F : Точка P_i ∈ G₁ (x ∈ 𝔽_p, y ∈ 𝔽_p)      [64 байти]
└── 0x40 .. 0xBF : Точка Q_i ∈ G₂' (x' ∈ 𝔽_{p²}, y' ∈ 𝔽_{p²}) [128 байтів]
```

Якщо передано порожній вхідний буфер (0 байтів), прекомпайл повертає `1` (true), що відповідає порожньому добутку спарувань. Якщо довжина вхідних даних не є кратною 192 байтам, або будь-яка з точок не належить відповідній кривій чи підгрупі, виклик завершується помилкою (EVM revert).

Газова оцінка виклику обчислюється за прямою лінійною формулою `Gas = 34000 + 45000 · k`, де `k` — кількість переданих пар точок `(P_i, Q_i)`. Оскільки кожен доданий блок забирає фіксовану кількість 45 000 газу, пакети з кількох спарувань (batch verification) вигідніші, ніж поодинокі виклики.

Виконання прекомпайлу здійснює декомпресію точки `Q_i` у внутрішньому буфері ядра EVM, перевіряючи порядок `r · Q_i = 𝒪` перед розгортанням циклу Міллера.

Результат виконання повертає 32-байтовий буфер, який містить число `1` (якщо спарування дорівнює нейтральному елементу `1 ∈ G_T`) або `0` (в іншому разі).

### 4.2 Специфікація precompile `BLS12-381 Pairing` (EIP-2537)

Для EIP-2537 виклики роботи з `G_2` розділені на окремі операційні коди:

| Адреса прекомпайлу | Операція | Розмір вхідних даних | Газова вартість |
| :--- | :--- | :--- | :--- |
| `0x0B` | `BLS12_G2ADD` | `384 байти` (дві нестиснені точки `G_2`) | `800 gas` |
| `0x0C` | `BLS12_G2MUL` | `288 байтів` (точка `G_2` + 32-бітний скаляр) | `32 000 gas` |
| `0x0D` | `BLS12_G2MULTIEXPMUL` | `N * 288 байтів` (мультискалярне множення MSM) | Динамічна за формулою зіва |
| `0x0E` | `BLS12_PAIRING_CHECK` | `N * 384 байти` (пари `G_1` та `G_2`) | `43 000 * N + 65 000 gas` |

Використання цих прекомпайлів дає можливість смарт-контрактам Ethereum виконувати швидку перевірку агрегованих підписів BLS12-381 та валідувати докази SNARK/STARK з мінімальними витратами газу.

Архітектура прекомпайлів EIP-2537 виключає динамічний розподіл пам'яті в середовищі EVM, забезпечуючи детермінований час виконання перевірки Rollup-транзакцій.

Кожен виклик прекомпайлів піддається суворій перевірці коректності формату Big-Endian перед передачею у криптографічний розтвістувач.
