# 🧮 Математична складність та нижні оцінки алгоритму Піппенджера

Обчислення мультискалярного множення (англ. *Multi-Scalar Multiplication*, MSM) або мультиекспоненціювання є фундаментальною задачею алгебраїчної теорії складності. У довільній абелевій групі `(G, +)` (зокрема, групі точок еліптичної кривої над скінченним полем) задача полягає в обчисленні лінійної комбінації `n` елементів групи з `n` цілочисельними скалярами довжиною `λ` бітів:

```
Q = ∑_{i=1}^n k_i · P_i   (де P_i ∈ G, k_i ∈ [0, 2^λ − 1])
```

Математичний аналіз алгоритму Піппенджера дає строгу відповідь на два ключові питання: яка мінімально можлива кількість групових операцій необхідна для розв'язання цієї задачі в найгіршому та середньому випадках (нижня межа складності), і як саме кошиковий алгоритм Піппенджера досягає цієї теоретичної межі через вибір оптимального параметра вікна `c`.

## 1. Формальна модель обчислень: прямі обчислювальні ланцюги та DAG-схеми

Алгебраїчна складність задачі MSM досліджується у стандартній моделі схем прямих обчислень (англ. *straight-line programs* або адитивних ланцюгів векторів) над вільною абелевою групою `G = Z^n`. У такій моделі алгоритм не має доступу до внутрішньої структури координат чи представлення поля, а може лише виконувати абстрактні групові операції додавання та віднімання елементів групи.

Прямий обчислювальний ланцюг довжини `L` для обчислення лінійної комбінації над базисом `(P₁, P₂, ..., P_n)` — це послідовність групових елементів `V = (v₁, v₂, ..., v_L)`, що утворює спрямований ациклічний граф (DAG), де:
1. Початкові `n` вершин є базисними точками: `v_i = P_i` для `1 ≤ i ≤ n`.
2. Кожна наступна вершина має вхідний напівстепінь 2 і є результатом групової операції додавання або віднімання двох попередніх вершин ланцюга:

```
v_k = v_i ± v_j   (де 1 ≤ i, j < k ≤ L)
```

3. Фінальний елемент ланцюга `v_L` дорівнює шуканій сумі: `v_L = Q = ∑_{i=1}^n k_i P_i`.

Довжина ланцюга `L − n` визначає точну кількість групових операцій додавання, необхідних для отримання результату. Кожен проміжний елемент `v_k` можна однозначно записати як цілочисельний вектор коефіцієнтів у базисі вхідних точок: `v_k = ∑_{i=1}^n a_{k, i} · P_i`, де `a_{k, i} ∈ Z`. Оскільки операції є лінійними над групою `Z`, матриця коефіцієнтів перетворень повністю фіксується вибором пар індексів на кожному кроці ланцюга.

## 2. Теоретична нижня межа складності (Теорема Піппенджера — Яо)

Оцінимо інформаційну ємність та кількість можливих прямих обчислювальних ланцюгів довжини `L` за допомогою комбінаторного підрахунку топологій графів та простору цільових станів. Цей підхід узагальнює класичну інформаційну ентропійну нерівність Шеннона на структури адитивних схем над абелевими групами.

### Комбінаторний підрахунок простору станів

Нехай фіксовано довжину обчислювального ланцюга `L`. На кожному кроці `k` (де `n + 1 ≤ k ≤ L`) алгоритм повинен обрати два індекси серед уже обчислених вершин `i, j ∈ {1, ..., k − 1}` та одну з двох бінарних операцій: додавання або віднімання.

Кількість можливих виборів на кроці `k` не перевищує:

```
C_k = 2 · (k − 1)² ≤ 2 · L²
```

Отже, загальна кількість різних прямих обчислювальних схем довжини `L` від `n` змінних обмежена зверху величиною:

```
N(L, n) ≤ ∏_{k=n+1}^L (2 · L²) = (2 · L²)^{L − n} ≤ (2 · L²)^L
```

З іншого боку, простір можливих входів задачі MSM складається з усіх можливих векторів скалярів `(k₁, k₂, ..., k_n)`, де кожен `k_i ∈ [0, 2^λ − 1]`. Загальна кількість різних комбінацій становить:

```
|K^n| = (2^λ)^n = 2^{λ · n}
```

Оскільки вільна абелева група `Z^n` не має нетривіальних співвідношень між генераторами (тобто базисні вектори `P_i` є лінійно незалежними), дві різні скалярні комбінації дають однакові результати для довільного базису тоді й лише тоді, коли їхні вектори коефіцієнтів ідентичні. Таким чином, щоб прямий обчислювальний ланцюг міг обчислити довільну лінійну комбінацію, кількість можливих схем повинна бути не меншою за кількість можливих цільових виразів:

```
(2 · L²)^L ≥ 2^{λ · n}
```

### Логарифмування нерівності та виведення асимптотики

Прологарифмуємо обидві частини нерівності за основою 2 для знаходження нижньої межі довжини `L`:

```
log₂((2 · L²)^L) ≥ log₂(2^{λ · n})
L · log₂(2 · L²) ≥ λ · n
L · (1 + 2 · log₂ L) ≥ λ · n
L · log₂ L ≥ (1 / 2) · λ · n
```

З асимптотичного співвідношення `L · log₂ L ≥ C` випливає, що `L ≥ C / log₂ C`. Підставляючи `C = (1 / 2) · λ · n`, отримуємо фундаментальну оцінку складності через логарифмічний дільник:

```
L ≥ Ω( (λ · n) / log₂(λ · n) )
```

Враховуючи, що для включення всіх `n` базисних точок у суму тривіально необхідно щонайменше `n − 1` операцій додавання (оскільки граф залежностей повинен бути зв'язним і містити всі вхідні вершини), сумарна нижня оцінка складності будь-якого алгоритму MSM становить:

```
L_{min}(n, λ) = Ω( n + (λ · n) / log₂(λ · n) )
```

Для типових криптографічних параметрів, де бітова довжина скаляра є фіксованою константою (`λ = 256`), а кількість точок `n` прямує до нескінченності (`n ≫ λ`), член `log₂(λ · n) = log₂ n + O(1)`, і нижня межа набуває вигляду:

```
L_{min}(n, λ) = Ω( n + (λ · n) / log₂ n )
```

Ця оцінка демонструє, що в найгіршому випадку неможливо обчислити мультискалярний вираз швидше, ніж за кількість операцій, пропорційну `λ · n / log₂ n`. Алгоритм Піппенджера є математично точною реалізацією цієї теоретичної межі.

## 3. Алгебраїчний доказ коректності алгоритму Піппенджера

Алгоритм Піппенджера розбиває `λ`-бітний простір на `b = ⌈λ / c⌉` вікон шириною `c` бітів кожне. Розглянемо детальний математичний механізм обчислення суми всередині одного фіксованого вікна `j`.

### Розклад скаляра на віконні коефіцієнти

Кожен скаляр `k_i` записується у системі числення за основою `2^c`:

```
k_i = ∑_{j=0}^{b−1} k_{i, j} · (2^c)^j   (де k_{i, j} ∈ [0, 2^c − 1])
```

Підставляючи цей розклад у вихідну формулу MSM `Q`, змінюємо порядок підсумовування завдяки дистрибутивності та комутативності групового додавання:

```
Q
= ∑_{i=1}^n [ ∑_{j=0}^{b−1} k_{i, j} · (2^c)^j ] · P_i       [підставили розклад скалярів k_i]
= ∑_{j=0}^{b−1} (2^c)^j · [ ∑_{i=1}^n k_{i, j} · P_i ]       [згрупували за степенями 2^c]
= ∑_{j=0}^{b−1} 2^{j · c} · S_j                               [позначили внутрішню суму через S_j]
```

де `S_j = ∑_{i=1}^n k_{i, j} · P_i` — зважена сума точок для вікна `j`.

### Розподіл по кошиках (Bucket Partitioning)

У виразі `S_j` коефіцієнти `k_{i, j}` приймають цілі значення з множини `{0, 1, 2, ..., 2^c − 1}`. Згрупуємо точки за значенням коефіцієнта:

```
B_u = ∑_{i : k_{i, j} = u} P_i   (для u = 1, 2, ..., 2^c − 1)
```

Елементи з коефіцієнтом `k_{i, j} = 0` не додаються до жодного кошика, оскільки `0 · P_i = O` (точка на нескінченності, або нейтральний елемент групи).

Тоді сума вікна `S_j` записується через суми кошиків `B_u`:

```
S_j = ∑_{u=1}^{2^c − 1} u · B_u
```

### Трюк накопичувальних сум (Running Sums / Triangular Summation)

Наївне обчислення суми `∑ u · B_u` вимагало б виконання скалярних множень `u · B_u`. Метод Піппенджера усуває всі скалярні множення за допомогою трикутного накопичення.

Визначимо зворотну послідовність накопичувачів `T_v`:

```
T_{2^c − 1} = B_{2^c − 1}
T_v = T_{v+1} + B_v   (для v = 2^c − 2, 2^c − 3, ..., 1)
```

За індукцією, кожен `T_v` містить суму кошиків від індексу `v` до максимального `2^c − 1`:

```
T_v = ∑_{u=v}^{2^c − 1} B_u
```

Просумуємо всі значення `T_v` від `v = 1` до `2^c − 1`:

```
∑_{v=1}^{2^c − 1} T_v
= ∑_{v=1}^{2^c − 1} [ ∑_{u=v}^{2^c − 1} B_u ]                [підставили явний вираз для T_v]
= ∑_{u=1}^{2^c − 1} B_u · [ ∑_{v=1}^u 1 ]                    [змінили порядок підсумовування]
= ∑_{u=1}^{2^c − 1} u · B_u                                  [оскільки сума одиниць від 1 до u дорівнює u]
= S_j                                                        [отримали шукану суму вікна]
```

Ця тотожність строго доводить коректність обчислення `S_j` без єдиного скалярного множення. Увесь процес обчислення всередині вікна зводиться виключно до операцій групового додавання.

## 4. Точний баланс групових операцій

Підрахуємо точну кількість групових операцій додавання (`A`, англ. *Point Addition*) та подвоєння (`D`, англ. *Point Doubling*) для всіх трьох етапів алгоритму:

1. **Етап 1: Розподіл точок по кошиках (Bucket Accumulation)**
   У кожному вікні `j` кожна з `n` точок додається щонайбільше до одного кошика. Оскільки перша точка в кожному непорожньому кошику записується без операції додавання (ініціалізація), кількість додавань не перевищує `n`.
   Для `b` вікон:

```
A_{buckets} = b · (n − (кількість непорожніх кошиків)) ≤ b · n
```

2. **Етап 2: Зведення кошиків через зворотні суми (Running Sums Reduction)**
   Обчислення послідовності `T_v` вимагає `2^c − 2` додавань.
   Обчислення фінальної суми `S_j = ∑ T_v` вимагає ще `2^c − 2` додавань.
   Сумарно на одне вікно: `2 · (2^c − 2) = 2^{c+1} − 4` додавань.
   Для всіх `b` вікон:

```
A_{running} = b · (2^{c+1} − 4)
```

3. **Етап 3: Міжвіконна агрегація за схемою Горнера (Horner's Rule)**
   Починаючи зі старшого вікна `Q = S_{b−1}`, на кожному з `b − 1` кроків акумулятор множиться на `2^c` (що вимагає `c` послідовних операцій подвоєння) та додається результат наступного вікна `S_j`:

```
D_{horner} = (b − 1) · c
A_{horner} = b − 1
```

Підсумовуючи всі компоненти з урахуванням `b = ⌈λ / c⌉ ≈ λ / c`:

```
Total(c)
  = A_{buckets} + A_{running} + A_{horner} + D_{horner}               [сума операцій усіх фаз алгоритму]
  = b · n · (1 - 2^{-c}) + 2 · b · (2^c - 2) + (b - 1) + (b - 1) · c  [підстановка кількостей додавання та подвоєння]
  ≈ (λ / c) · (n + 2^{c + 1}) + λ                                    [асимптотичне спрощення при b = λ / c]
```

## 5. Мінімізація цільової функції та оптимальний вибір вікна c

Для мінімізації загальної кількості групових операцій продиференціюємо функцію витрат `f(c) = (λ / c) · (n + 2^{c+1})` за змінною `c`:

```
d f(c) / d c
= λ · [ ( (d/dc)(n + 2^{c+1}) · c − (n + 2^{c+1}) · 1 ) / c² ]
= (λ / c²) · [ (2^{c+1} · ln 2) · c − n − 2^{c+1} ]
= (λ / c²) · [ 2^{c+1} · (c · ln 2 − 1) − n ]
```

Прирівнюючи похідну до нуля `d f(c) / d c = 0`, отримуємо характеристичне трансцендентне рівняння оптимальності:

```
2^{c+1} · (c · ln 2 − 1) = n
```

Для аналітичного розв'язання виразимо рівняння через W-функцію Ламберта (англ. *Lambert W-function* `W(z)`, де `W(z) · e^{W(z)} = z`). Перетворимо рівняння до канонічної форми:

```
(c − 1 / ln 2) · 2^c = n / (2 · ln 2)
(c − 1 / ln 2) · e^{c · ln 2} = n / (2 · ln 2)
(c · ln 2 − 1) · e^{c · ln 2 − 1} = (n / 2) · e^{−1}
```

Застосовуючи головну гілку функції Ламберта `W₀` до обох частин:

```
c · ln 2 − 1 = W₀( (n / (2 · e)) )
c^*(n) = (1 / ln 2) · [ 1 + W₀( n / (2 · e) ) ]
```

Використовуючи асимптотичний розклад функції Ламберта `W₀(x) = ln x − ln ln x + o(1)` при `x → ∞`:

```
c^*(n)
= (1 / ln 2) · [ 1 + ln(n / (2 · e)) − ln ln(n / (2 · e)) + o(1) ]
= (1 / ln 2) · [ ln n − ln(2 · e) + 1 − ln(ln n − ln(2 · e)) + o(1) ]
= log₂ n − log₂ log₂ n + O(1)
```

### Підстановка оптимуму в функцію складності

Підставимо отримане оптимальне значення `c^* ≈ log₂ n` у вихідну формулу сумарної складності:

```
Total(c^*)
  = (λ / log₂ n) · (n + 2^{log₂ n + 1}) + λ   [підстановка оптимального c^* = log₂ n]
  = (λ / log₂ n) · (n + 2 · n) + λ             [розкриття степеня 2^{log₂ n + 1} = 2n]
  = (3 · λ · n) / log₂ n + λ                   [зведення подібних доданків у дужках]
  = O( (λ · n) / log₂ n )                      [виділення провідного асимптотичного члена]
```

Отриманий результат строго збігається з теоретичною нижньою межею `Ω((λ · n) / log₂ n)`. Це доводить, що алгоритм Піппенджера є **асимптотично оптимальним** алгоритмом для задачі мультискалярного множення.

## 6. Ймовірнісний розподіл точок у кошиках та середній випадок

У реальних криптографічних системах (наприклад, zk-SNARK) скаляри `k_i` є випадковими або псевдовипадковими елементами поля `F_r`. Розглянемо поведінку алгоритму в середньому випадку (англ. *average-case complexity*).

Кожен коефіцієнт `k_{i, j}` приймає будь-яке значення з множини `{0, 1, ..., 2^c − 1}` з однаковою ймовірністю `p = 1 / 2^c`.

Для фіксованого вікна `j` та фіксованого кошика `u ∈ {1, ..., 2^c − 1}` кількість точок, що потрапляють у цей кошик, є біноміальною випадковою величиною:

```
X_u ~ Binomial(n, 1 / 2^c)
```

Математичне сподівання кількості точок у кошику дорівнює:

```
E[X_u] = n / 2^c
```

Ймовірність того, що конкретний кошик виявиться повністю порожнім (жодна з `n` точок не отримала значення `u`), дорівнює:

```
P(X_u = 0) = (1 − 1 / 2^c)^n ≈ e^{−n / 2^c}
```

Звідси отримуємо середню кількість непорожніх кошиків у вікні:

```
E[K_{non-empty}] = (2^c − 1) · (1 − e^{−n / 2^c})
```

Якщо `n ≫ 2^c` (що завжди виконується при оптимальному `c^*(n) ≈ log₂ n − log₂ log₂ n`, де `n / 2^c ≈ log₂ n → ∞`), ймовірність порожніх кошиків прямує до нуля `e^{−log₂ n} = 1 / n → 0`. Тобто практично всі кошики заповнюються, і дисперсія навантаження між кошиками є знехтовно малою:

```
Var(X_u) = n · (1 / 2^c) · (1 − 1 / 2^c) ≈ n / 2^c
```

Це гарантує стабільну та рівномірну продуктивність алгоритму без ризику деградації часу виконання на випадкових скалярах.

## 7. Знакове розбиття скалярів (Signed-Digit / wNAF)

На еліптичних кривих операція взяття протилежної точки `−P = (x, −y)` у полі `F_p` є обчислювально безкоштовною, оскільки полягає лише у зміні знаку координати `y`. Це фундаментальна алгебраїчна властивість, якою не володіють загальні мультиплікативні групи.

Використовуючи цю властивість, можна перетворити невід'ємний розклад скаляра на знаковий (англ. *signed-digit representation*):

```
k_i = ∑_{j=0}^{b−1} s_{i, j} · (2^c)^j   (де s_{i, j} ∈ [ −2^{c−1}, 2^{c−1} ])
```

Алгоритм перетворення виконується послідовним переносом одиниці у старший розряд:
1. Якщо `k_{i, j} ≥ 2^{c−1}`, покладаємо `s_{i, j} = k_{i, j} − 2^c` та додаємо `1` до наступного розряду `k_{i, j+1}`.
2. Якщо `k_{i, j} < 2^{c−1}`, покладаємо `s_{i, j} = k_{i, j}` без переносу.

Завдяки цьому абсолютне значення коефіцієнта не перевищує `2^{c−1}`. Кількість необхідних кошиків у кожному вікні зменшується рівно вдвічі: замість `2^c − 1` кошиків достатньо підтримувати `2^{c−1}` кошиків:
* Якщо `s_{i, j} > 0`, точка `P_i` додається до кошика `B_{s_{i, j}}`.
* Якщо `s_{i, j} < 0`, протилежна точка `−P_i = (x_i, −y_i)` додається до кошика `B_{|s_{i, j}|}`.

Сумарна кількість додавань для зведення кошиків скорочується:

```
A_{running}^{signed} = b · (2^c − 4)
```

Це зменшує експоненційний член удвічі та дозволяє збільшити оптимальну ширину вікна `c` на 1 біт, забезпечуючи додаткове прискорення обчислень на 10–15%.

## 8. Пакетна нормалізація Монтгомері (Batch Affine Inversion)

У високопродуктивних криптографічних системах точки вихідного базису `P_i` зберігаються в афінних координатах `(x, y)`, що вимагає лише 64 байти пам'яті на точку для 256-бітних полів замість 96 або 128 байтів для проективних координат Якобі. Це вдвічі знижує навантаження на підсистему пам'яті та кеш процесора (L3 cache), що є критичним при обробці масивів з мільйонів точок.

Додавання афінної точки до проективного кошика (змішане додавання, англ. *mixed addition*) вимагає 7 операцій множення та 4 операції піднесення до квадрата в базовому полі `F_p` (`7M + 4S`), тоді як повне додавання двох довільних проективних точок вимагає від 11 до 16 множень (`11M + 5S` для Якобі та `16M` для однорідних проективних координат). Таким чином, підтримка базису в афінній формі економить понад 35% арифметичних операцій поля на найдовшому етапі заповнення кошиків.

Коли кошики `B_u` заповнено, виникає потреба перетворити їхні координати назад в афінну форму перед виконанням редукції зворотних сум `T_v`. Пряме обчислення оберненого елемента `Z^{−1} \pmod p` для кожного кошика через малу теорему Ферма або розширений алгоритм Евкліда вимагає `O(log₂ p)` операцій множення (близько 256–300 множень на один кошик). При великій кількості кошиків сумарні витрати на інверсії могли б знівелювати вигоду від афінної арифметики.

Трюк Монтгомері для пакетного обернення (англ. *Montgomery Batch Inversion*) елегантно розв'язує цю проблему, дозволяючи знайти обернені значення для всіх `M = 2^c` кошиків за ціною **однієї єдиної інверсії** у полі та `3 · M` звичайних польових множень:

```
1. Обчислюємо префіксні добутки:
   p_1 = z_1
   p_k = p_{k−1} · z_k   (для k = 2, ..., M)

2. Обчислюємо єдину інверсію спільного добутку:
   I = p_M^{−1} \pmod p

3. Обчислюємо суфіксні добутки та відновлюємо окремі інверсії у зворотному порядку:
   Для k від M вниз до 2:
     z_k^{−1} = I · p_{k−1}
     I = I · z_k
   z_1^{−1} = I
```

Завдяки цьому вартість нормалізації всіх кошиків стає знехтовно малою порівняно з накопиченням точок, що дозволяє виконувати другий етап редукції кошиків виключно в надшвидких афінних координатах.

## 9. Вплив алгебраїчних ендоморфізмів GLV на мультискалярне множення

Якщо еліптична крива володіє ефективно обчислюваним ендоморфізмом `phi(P) = [lambda]P` над полем `F_p` (як у кривих `secp256k1` та `BN254`), кожен `λ`-бітний скаляр `k_i` можна попередньо розкласти на два скаляри половинної довжини `k_{i, 1}, k_{i, 2} ≈ 2^{λ / 2}`:

```
k_i = k_{i, 1} + k_{i, 2} · lambda \pmod r
```

Тоді задача MSM розмірності `n` з довжиною скалярів `λ` зводиться до еквівалентної задачі MSM подвоєної розмірності `2n`, але зі скалярами удвічі меншої бітової довжини `λ / 2`:

```
Q = ∑_{i=1}^n k_{i, 1} · P_i + ∑_{i=1}^n k_{i, 2} · phi(P_i)
```

Застосовуючи формулу складності Піппенджера до нових параметрів `N' = 2n` та `λ' = λ / 2`:

```
Total_{GLV}(n, λ)
≈ ( (λ / 2) / log₂(2n) ) · (2n + 2 · 2n)
= (λ · n) / (log₂ n + 1) · (3 / 2)
```

Це скорочує сумарну кількість групових операцій ще приблизно на 25–33% та демонструє глибокий взаємозв'язок між алгебраїчною геометрією кривих та асимптотичною теорією складності.

## 10. Чисельне порівняння та баланс операцій для практичних параметрів

Розглянемо практичний випадок криптографічних еліптичних кривих BN254 та BLS12-381, де довжина скаляра становить `λ = 256` бітів.

Обчислимо точну кількість операцій додавання та подвоєння для різних розмірів базису `n` при наївному методі, методі Штрауса та алгоритмі Піппенджера:

```
1. Наївний метод (wNAF з вікном w = 5 для кожного скаляра окремо):
   Кожне множення: 256 подвоєнь + (256 / 6) ≈ 43 додавань.
   Сума n результатів: n − 1 додавань.
   Разом для n = 2¹⁶ (65 536 точок):
   - Подвоєння: 65 536 · 256 = 16 777 216 D
   - Додавання: 65 536 · 43 + 65 535 = 2 883 583 A
   - Сумарно групових операцій: ≈ 19,66 мільйона операцій.

2. Метод Штрауса / трюк Шаміра (вікно w = 4 на 4 скаляри одночасно):
   Масштабується лише на невеликі групи точок, дає прискорення не більше ніж у 2–3 рази.

3. Алгоритм Піппенджера (n = 2¹⁶, оптимальне c = 13 бітів):
   Кількість вікон: b = ⌈256 / 13⌉ = 20 вікон.
   - Етап 1 (кошики): b · n = 20 · 65 536 = 1 310 720 A.
   - Етап 2 (зворотні суми): b · 2^{c+1} = 20 · 16 384 = 327 680 A.
   - Етап 3 (міжвіконна агрегація): (b − 1) · c = 19 · 13 = 247 D та 19 A.
   - Сумарно групових операцій: ≈ 1,64 мільйона операцій.
```

Приріст швидкодії алгоритму Піппенджера для `n = 2¹⁶` точок становить:

```
Speedup(2¹⁶) = 19 660 000 / 1 638 666 ≈ 12,0 разів
```

Для розмірності `n = 2²⁰` (1 048 576 точок, типовий розмір для доведень PLONK у Rollup-мережах):

```
Наївний метод:
- Подвоєння: 1 048 576 · 256 = 268 435 456 D
- Додавання: 1 048 576 · 43 + 1 048 575 = 46 137 343 A
- Сумарно: ≈ 314,5 мільйона операцій.

Алгоритм Піппенджера (c = 16 бітів, b = 16 вікон):
- Етап 1 (кошики): 16 · 1 048 576 = 16 777 216 A.
- Етап 2 (зворотні суми): 16 · 2¹⁷ = 2 097 152 A.
- Етап 3 (міжвіконна агрегація): 15 · 16 = 240 D та 15 A.
- Сумарно: ≈ 18,87 мільйона операцій.

Speedup(2²⁰) = 314 500 000 / 18 874 623 ≈ 16,7 разів
```

Ці чисельні результати наочно демонструють, що зі зростанням `n` перевага алгоритму Піппенджера лише збільшується завдяки логарифмічному скороченню кількості операцій на одну точку базису.
