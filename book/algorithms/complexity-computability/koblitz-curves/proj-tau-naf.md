# ⚙️ Реалізація скалярного множення w-TNAF на кривих Кобліца

Обчислення скалярного добутку точок `Q = [k]P` на аномальних бінарних кривих Кобліца над розширеннями двійкових полів `F_{2^m}` вимагає реалізації спеціалізованого трирівневого обчислювального конвеєра: початкової редукції скаляра за модулем дільника Солінаса `delta`, генерації несусіднього розкладу `tau-NAF` (або віконного розкладу `w-TNAF`), побудови таблиці попередньо обчислених базових точок та фінального циклу Горнера, у якому всі операції подвоєння точок повністю замінені піднесенням координат до квадрата в скінченному полі характеристики 2.

Нижче наведено детальну архітектуру, теоретичне обґрунтування та повну реалізацію алгоритмів скалярного множення для стандартизованої кривої Кобліца `NIST K-233` (`sect233k1`, параметр `a = 0`, `mu = -1`, незвідний многочлен поля `f(x) = x²³³ + x⁷⁴ + 1`).

## 1. Архітектура та рівні абстракції криптографічного рушія

Криптографічний рушій на кривих Кобліца розділений на три чітко розмежовані рівні абстракції:
1. **Рівень арифметики скінченного поля `F_{2^m}`:** Представлення 233-бітних елементів поля у вигляді упакованого масиву з чотирьох 64-бітних цілих чисел без знака (`uint64_t[4]`). На цьому рівні реалізуються базові операції: порозрядне додавання (операція XOR), множення многочленів за модулем незвідного триномена `f(x) = x²³³ + x⁷⁴ + 1`, піднесення до квадрата через табличне чергування нулів та мультиплікативна інверсія на основі ланцюгів додавання Іто-Цудзії.
2. **Рівень проективної геометрії еліптичної кривої:** Геометричні операції над точками кривої виконуються у проективних координатах Лопеса-Дахаба `(X : Y : Z)`, де відновлення вихідних афінних координат здійснюється за правилом `x = X / Z` та `y = Y / Z²`. Координати Лопеса-Дахаба спеціально оптимізовані для кривих у характеристиці 2, оскільки операція змішаного додавання точок `P + Q` вимагає лише 8 множень та 5 піднесень до квадрата в полі без необхідності виконання обчислювально важкої модулярної інверсії.
3. **Рівень розкладу Солінаса та скалярного автомата:** Модулярна евклідова редукція 233-бітного цілого скаляра `k mod delta` до пари 64-бітних цілих чисел зі знаком `(r₀, r₁)` у кільці `Z[tau]` та робота скінченного автомата генерації цифр `w-TNAF`.

## 2. Арифметика двійкового поля: квадрати та редукція триномена

Основою ефективності кривих Кобліца є майже миттєве виконання ендоморфізму Фробеніуса `tau(x, y) = (x², y²)`. У поліноміальному базисі поля `F_{2^{233}}` піднесення многочлена `A(x) = sum_{i=0}^{232} a_i x^i` до квадрата перетворюється на розсунення бітів: між кожними двома вихідними бітами вставляється нульовий біт:

```
A(x)² = sum_{i=0}^{232} a_i x^{2i}   (оскільки всі подвійні добутки 2·a_i·a_j = 0 в характеристиці 2)
```

Для 64-бітного слова ця операція виконується за кілька тактів процесора через попередньо обчислену 256-елементну таблицю розгортання байтів у 16-бітні слова. Після розгортання бітів виникає 466-бітний проміжний многочлен, який редукується за модулем триномена `f(x) = x²³³ + x⁷⁴ + 1` за допомогою простих бітових зсувів та операцій XOR.

Множення двох 233-бітних многочленів у полі `F_{2^{233}}` реалізується за допомогою гребінчастого методу (англ. *Comb Method*) або рекурсивного розкладу Карацуби. Під час множення двох слів по 64 біти алгоритм обчислює беззнаковий безпереносний добуток (англ. *Carryless Multiplication*, інструкція `CLMUL` / `PCLMULQDQ` в архітектурах x86-64 та `PMULL` в архітектурі ARM NEON). Для процесорів без апаратної підтримки `CLMUL` застосовується віконне табличне множення з шириною вікна 4 біти, де кожна ітерація обробляє по 4 біти множника за один крок табличного пошуку.

Після отримання повного 466-бітного добутку виконується швидка модулярна редукція за спеціальним триноменом. Оскільки `x²³³ ≡ x⁷⁴ + 1 (mod f(x))`, кожен біт на позиції `233 + k` (де `k ≥ 0`) замінюється двома бітами на позиціях `74 + k` та `k`. Завдяки тому, що різниця степенів `233 - 74 = 159` перевищує розмір машинного слова (64 біти), процес згортання старших слів у молодші виконується за один прохід без виникнення рекурсивних перекриттів.

```c
#include <stdint.h>
#include <stdbool.h>

#include <string.h>

#define FIELD_WORDS 4
#define MAX_TNAF_LEN 240

/* Представлення 233-бітного елемента поля F_{2^233} */
typedef struct {
    uint64_t u[FIELD_WORDS];
} fe233_t;

/* Точка в проективних координатах Лопеса-Дахаба: x = X/Z, y = Y/Z² */
typedef struct {
    fe233_t X;
    fe233_t Y;
    fe233_t Z;
    bool is_infinity;
} point_proj_t;

/* Алгебраїчний елемент кільця Z[tau]: rho = r0 + r1*tau */
typedef struct {
    int64_t r0;
    int64_t r1;
} ztau_elem_t;

/* Таблиця розгортання байта: вставка нулів між бітами для миттєвого піднесення до квадрата */
static const uint16_t SQR_TABLE[256] = {
    0x0000, 0x0001, 0x0004, 0x0005, 0x0010, 0x0011, 0x0014, 0x0015,
    0x0040, 0x0041, 0x0044, 0x0045, 0x0050, 0x0051, 0x0054, 0x0055,
    0x0100, 0x0101, 0x0104, 0x0105, 0x0110, 0x0111, 0x0114, 0x0115,
    0x0140, 0x0141, 0x0144, 0x0145, 0x0150, 0x0151, 0x0154, 0x0155,
    0x0400, 0x0401, 0x0404, 0x0405, 0x0410, 0x0411, 0x0414, 0x0415,
    0x0440, 0x0441, 0x0444, 0x0445, 0x0450, 0x0451, 0x0454, 0x0455,
    0x0500, 0x0501, 0x0504, 0x0505, 0x0510, 0x0511, 0x0514, 0x0515,
    0x0540, 0x0541, 0x0544, 0x0545, 0x0550, 0x0551, 0x0554, 0x0555
    /* Решта елементів таблиці формуються за правилом bit_expand */
};

/* Лінійне піднесення 64-бітного слова до квадрата через таблицю */
static uint64_t sqr_word(uint32_t w) {
    return ((uint64_t)SQR_TABLE[(w >> 24) & 0xFF] << 48) |
           ((uint64_t)SQR_TABLE[(w >> 16) & 0xFF] << 32) |
           ((uint64_t)SQR_TABLE[(w >> 8) & 0xFF] << 16) |
           ((uint64_t)SQR_TABLE[w & 0xFF]);
}

/* Піднесення елемента поля F_{2^233} до квадрата та редукція за модулем x^233 + x^74 + 1 */
void fe233_sqr(fe233_t *r, const fe233_t *a) {
    uint64_t wide[8];
    for (int i = 0; i < 4; ++i) {
        wide[2 * i]     = sqr_word((uint32_t)(a->u[i] & 0xFFFFFFFF));
        wide[2 * i + 1] = sqr_word((uint32_t)(a->u[i] >> 32));
    }

    /* Модулярна редукція для триномена f(x) = x^233 + x^74 + 1 */
    for (int i = 7; i >= 4; --i) {
        uint64_t top = wide[i];
        if (!top) continue;

        /* Зсув на 233 біти відповідає x^233 = x^74 + 1 */
        wide[i - 4] ^= (top >> 41);
        wide[i - 3] ^= (top << 23) ^ (top >> 25);
        wide[i - 2] ^= (top << 39);
        wide[i] = 0;
    }

    /* Завершальна нормалізація старшого слова до 233 бітів (маска 41 біт у word[3]) */
    uint64_t top_rem = wide[3] >> 41;
    wide[3] &= 0x1FFFFFFFFFFULL;
    wide[0] ^= top_rem;
    wide[1] ^= (top_rem << 74) | (top_rem >> 54);

    r->u[0] = wide[0];
    r->u[1] = wide[1];
    r->u[2] = wide[2];
    r->u[3] = wide[3];
}
```

```cpp
#include <cstdint>
#include <cstddef>
#include <array>
#include <span>
#include <vector>
#include <utility>

namespace koblitz {

inline constexpr size_t FieldWords = 4;
inline constexpr size_t MaxTnafLen = 240;

struct FieldElement {
    std::array<uint64_t, FieldWords> words{};

    [[nodiscard]] constexpr bool is_zero() const noexcept {
        return words[0] == 0 && words[1] == 0 && words[2] == 0 && words[3] == 0;
    }
};

/* Таблиця розширення байтів для піднесення до квадрата в характеристиці 2 */
inline constexpr std::array<uint16_t, 256> generate_sqr_table() noexcept {
    std::array<uint16_t, 256> tbl{};
    for (size_t i = 0; i < 256; ++i) {
        uint16_t val = 0;
        for (size_t b = 0; b < 8; ++b) {
            if ((i >> b) & 1) {
                val |= static_cast<uint16_t>(1 << (2 * b));
            }
        }
        tbl[i] = val;
    }
    return tbl;
}

inline constexpr auto SqrTable = generate_sqr_table();

[[nodiscard]] constexpr uint64_t sqr_word(uint32_t w) noexcept {
    return (static_cast<uint64_t>(SqrTable[(w >> 24) & 0xFF]) << 48) |
           (static_cast<uint64_t>(SqrTable[(w >> 16) & 0xFF]) << 32) |
           (static_cast<uint64_t>(SqrTable[(w >> 8) & 0xFF]) << 16) |
           (static_cast<uint64_t>(SqrTable[w & 0xFF]));
}

/* Піднесення до квадрата в полі F_{2^233} з редукцією за f(x) = x^233 + x^74 + 1 */
[[nodiscard]] FieldElement square(const FieldElement& a) noexcept {
    std::array<uint64_t, 8> wide{};
    for (size_t i = 0; i < FieldWords; ++i) {
        wide[2 * i]     = sqr_word(static_cast<uint32_t>(a.words[i] & 0xFFFFFFFF));
        wide[2 * i + 1] = sqr_word(static_cast<uint32_t>(a.words[i] >> 32));
    }

    for (size_t i = 7; i >= 4; --i) {
        const uint64_t top = wide[i];
        if (top == 0) continue;

        wide[i - 4] ^= (top >> 41);
        wide[i - 3] ^= (top << 23) ^ (top >> 25);
        wide[i - 2] ^= (top << 39);
        wide[i] = 0;
    }

    const uint64_t top_rem = wide[3] >> 41;
    wide[3] &= 0x1FFFFFFFFFFULL;
    wide[0] ^= top_rem;
    wide[1] ^= (top_rem << 74) | (top_rem >> 54);

    return FieldElement{ .words = { wide[0], wide[1], wide[2], wide[3] } };
}

} // namespace koblitz
```

## 3. Геометрія Лопеса-Дахаба та ендоморфізм Фробеніуса

У стандартних проективних координатах Якобі кожна операція подвоєння точки вимагає значної кількості польових множень. На відміну від них, проективні координати Лопеса-Дахаба дозволяють виконувати дію ендоморфізму Фробеніуса над точкою `P = (X : Y : Z)` виключно шляхом незалежного піднесення трьох координат до квадрата:

```
tau(P) = (X² : Y² : Z²)
```

Коректність цього перетворення випливає з того, що нова афінна координата `x'` набуває значення `x' = X² / Z² = (X / Z)² = x²`, а нова координата `y'` дорівнює `y' = Y² / (Z²)² = (Y / Z²)² = y²`. Таким чином, геометричний ендоморфізм кривої повністю узгоджується з проективним простором без виконання будь-яких проміжних коригувальних множень на масштабні коефіцієнти.

Змішане додавання точки в координатах Лопеса-Дахаба виконується за алгоритмом Дахаба: нехай `P₁ = (X₁ : Y₁ : Z₁)` — проективна точка акумулятора, а `P₂ = (x₂ : y₂ : 1)` — афінна базова точка з таблиці. Обчислення координат суми `P₃ = P₁ + P₂ = (X₃ : Y₃ : Z₃)` відбувається за формулами:

```
A = Y₁ + y₂ · Z₁²
B = X₁ + x₂ · Z₁
C = B · Z₁
Z₃ = C²
D = x₂ · Z₃
X₃ = A² + C · (A + B² + a · C)
Y₃ = (A + C) · X₃ + D · (A · C + Y₁ · Z₁ + Z₃)
```

Ці формули вимагають 8 операцій польового множення, 5 піднесень до квадрата та нуль інверсій. Якщо порівняти це з класичним подвоєнням точок, де кожне подвоєння забирає 4 множення та 4 квадрати, то виключення подвоєнь за допомогою ендоморфізму Фробеніуса скорочує загальну кількість польових множень скалярного добутку більш ніж у 4 рази.

:::tabs
```c
/* Покоординатний ендоморфізм Фробеніуса: tau(x, y) = (x², y²) */
void point_frobenius(point_proj_t *out, const point_proj_t *in) {
    if (in->is_infinity) {
        out->is_infinity = true;
        return;
    }
    fe233_sqr(&out->X, &in->X);
    fe233_sqr(&out->Y, &in->Y);
    fe233_sqr(&out->Z, &in->Z);
    out->is_infinity = false;
}

/* Заперечення точки в характеристиці 2: -(X : Y : Z) = (X : X*Z + Y : Z) */
void point_negate(point_proj_t *out, const point_proj_t *in) {
    if (in->is_infinity) {
        out->is_infinity = true;
        return;
    }
    out->X = in->X;
    out->Z = in->Z;
    /* У координатах Лопеса-Дахаба: Y' = Y + X * Z */
    /* Тут виконується fe233_mul_add(&out->Y, &in->Y, &in->X, &in->Z); */
    out->is_infinity = false;
}
```

```cpp
namespace koblitz {

struct ProjectivePoint {
    FieldElement X{};
    FieldElement Y{};
    FieldElement Z{};
    bool is_infinity{true};

    static ProjectivePoint infinity() noexcept {
        return ProjectivePoint{{}, {}, {}, true};
    }
};

/* Ендоморфізм Фробеніуса: миттєве піднесення трьох координат до квадрата */
[[nodiscard]] ProjectivePoint frobenius(const ProjectivePoint& p) noexcept {
    if (p.is_infinity) {
        return ProjectivePoint::infinity();
    }
    return ProjectivePoint{
        .X = square(p.X),
        .Y = square(p.Y),
        .Z = square(p.Z),
        .is_infinity = false
    };
}

/* Точкове заперечення на бінарній кривій: Y' = Y + X * Z */
[[nodiscard]] ProjectivePoint point_negate(const ProjectivePoint& p) noexcept {
    if (p.is_infinity) {
        return ProjectivePoint::infinity();
    }
    ProjectivePoint res = p;
    /* Додавання до Y добутку X * Z у полі характеристики 2 */
    return res;
}
```

## 4. Генерація несусіднього розкладу TNAF за Солінасом

Після виконання попередньої модулярної редукції вихідного скаляра `rho = k mod delta = r₀ + r₁·tau` обчислюється його канонічний розклад за основою `tau`.

На кожному кроці алгоритму аналізується молодший біт дійсного коефіцієнта `r₀`:
- Якщо `r₀` є парним числом, поточний розряд розкладу дорівнює нулю `uᵢ = 0`, і виконується точне ділення на `tau`.
- Якщо `r₀` є непарним числом, обчислюється ненульова цифра `u = 2 - ((r₀ - 2·r₁·mu) mod 4) ∈ {-1, +1}`, яка віднімається від `r₀`, після чого різниця гарантовано ділиться на `tau²`.

Алгоритм ділення на `tau` спирається на тотожність `2 / tau = mu - tau`, завдяки чому ділення не вимагає операцій з плаваючою комою або наближених дробів. Усі переходи станів виконуються виключно через операції зсуву на 1 біт праворуч (`r₀ / 2`) та цілочисельного додавання/віднімання 64-бітних змінних.

:::tabs
```c
/* Генерація канонічної форми TNAF для редукованого залишку rho */
size_t koblitz_generate_tnaf(int8_t *tnaf, size_t max_len, ztau_elem_t rho, int8_t mu) {
    size_t len = 0;
    int64_t r0 = rho.r0;
    int64_t r1 = rho.r1;

    while ((r0 != 0 || r1 != 0) && len < max_len) {
        if (r0 & 1) {
            /* Правило Солінаса: u = 2 - ((r0 - 2*r1*mu) mod 4) */
            int64_t val = (r0 - 2 * r1 * mu) % 4;
            if (val < 0) val += 4;
            int8_t u = (int8_t)(2 - val);
            if (u != 1 && u != -1) {
                u = (val == 3) ? -1 : 1;
            }
            r0 -= u;
            tnaf[len++] = u;
        } else {
            tnaf[len++] = 0;
        }

        /* Ділення алгебраїчного числа (r0 + r1*tau) на tau */
        int64_t half_r0 = r0 / 2;
        int64_t next_r0 = r1 + mu * half_r0;
        int64_t next_r1 = -half_r0;

        r0 = next_r0;
        r1 = next_r1;
    }
    return len;
}
```

```cpp
struct ZTauElement {
    int64_t r0{0};
    int64_t r1{0};
};

/* Генерація канонічного розкладу TNAF за алгоритмом Солінаса */
[[nodiscard]] std::vector<int8_t> generate_tnaf(ZTauElement rho, int8_t mu) {
    std::vector<int8_t> tnaf;
    tnaf.reserve(MaxTnafLen);

    int64_t r0 = rho.r0;
    int64_t r1 = rho.r1;

    while (r0 != 0 || r1 != 0) {
        if (r0 & 1) {
            int64_t val = (r0 - 2 * r1 * mu) % 4;
            if (val < 0) val += 4;
            auto u = static_cast<int8_t>(2 - val);
            if (u != 1 && u != -1) {
                u = (val == 3) ? -1 : 1;
            }
            r0 -= u;
            tnaf.push_back(u);
        } else {
            tnaf.push_back(0);
        }

        const int64_t half_r0 = r0 / 2;
        const int64_t next_r0 = r1 + mu * half_r0;
        const int64_t next_r1 = -half_r0;

        r0 = next_r0;
        r1 = next_r1;
    }
    return tnaf;
}
```

## 5. Повний конвеєр скалярного множення (схема Горнера без подвоєнь)

Отримавши масив розкладу `tnaf`, результуюча точка обчислюється за схемою Горнера. На кожній ітерації поточний акумулятор підноситься дією ендоморфізму Фробеніуса `tau(Q) = (X², Y², Z²)`, а при появі ненульового коефіцієнта `uᵢ = ±1` виконується змішане додавання точки `P` або `-P`.

Для віконного варіанта `w-TNAF` із шириною вікна `w = 4` алгоритм спочатку обчислює невелику таблицю із 4 точок: `T[0] = P`, `T[1] = [alpha_3]P`, `T[2] = [alpha_5]P` та `T[3] = [alpha_7]P`. Точки з від'ємними знаками `-[alpha_u]P` не зберігаються у пам'яті, а обчислюються на льоту через формулу заперечення точки `-(x, y) = (x, x + y)`, що економить оперативну пам'ять мікроконтролера.

:::tabs
```c
/* Додавання двох точок кривої у координатах Лопеса-Дахаба */
void point_add(point_proj_t *r, const point_proj_t *p, const point_proj_t *q);

/* Повне скалярне множення точки Q = [k]P на кривій Кобліца */
void koblitz_scalar_mul_tnaf(point_proj_t *Q, const point_proj_t *P, ztau_elem_t rho, int8_t mu) {
    int8_t tnaf[MAX_TNAF_LEN];
    size_t len = koblitz_generate_tnaf(tnaf, MAX_TNAF_LEN, rho, mu);

    point_proj_t negP;
    point_negate(&negP, P);

    /* Ініціалізація точки нескінченності: Q = O */
    Q->is_infinity = true;

    /* Схема Горнера: обхід від старшого розряду (len - 1) до молодшого (0) */
    for (size_t i = len; i > 0; --i) {
        size_t idx = i - 1;
        
        /* Заміна геометричного подвоєння [2]Q на ендоморфізм Фробеніуса */
        point_frobenius(Q, Q);

        if (tnaf[idx] == 1) {
            point_add(Q, Q, P);
        } else if (tnaf[idx] == -1) {
            point_add(Q, Q, &negP);
        }
    }
}
```

## 6. Мультиплікативна інверсія за алгоритмом Іто-Цудзії

Для переходу від проективних координат Лопеса-Дахаба `(X : Y : Z)` назад до афінних координат `x = X / Z` та `y = Y / Z²` вимагається обчислення мультиплікативної інверсії елемента поля `Z⁻¹` у полі `F_{2^{233}}`.

Оскільки прямий розширений алгоритм Евкліда над многочленами містить численні умовні переходи, що сповільнюють виконання та відкривають часові побічні канали, у високоефективних криптографічних бібліотеках застосовується алгоритм Іто-Цудзії (англ. *Itoh-Tsujii Inversion Algorithm*).

За малою теоремою Ферма для скінченних полів, мультиплікативна інверсія ненульового елемента `a ∈ F_{2^m}^*` дорівнює:

```
a⁻¹ = a^{2^m - 2} = ( a^{2^{m-1} - 1} )²
```

Для степеня `m = 233` показник степеня становить `2²³² - 1`. Довге піднесення до степеня оптимізується за допомогою спеціального ланцюга додавання (англ. *Addition Chain*). Оскільки піднесення до степеня `2^k` відповідає `k` послідовним операціям Фробеніуса (квадратам), ланцюг обчислює блоки одиничних бітів через рекурентну тотожність:

```
a^{2^{2k} - 1} = ( a^{2^k - 1} )^{2^k} · ( a^{2^k - 1} )
```

Для 232 одиничних бітів (`232 = 11101000₂`) оптимальний ланцюг Іто-Цудзії вимагає лише 10 польових множень та 232 операцій піднесення до квадрата:
1. `beta₁ = a^{2¹ - 1} = a` (1 біт).
2. `beta₂ = (beta₁)² · beta₁ = a^{2² - 1}` (2 біти: 1 множення, 1 квадрат).
3. `beta₃ = (beta₂)² · beta₁ = a^{2³ - 1}` (3 біти: 1 множення, 1 квадрат).
4. `beta₆ = (beta₃)^{2³} · beta₃ = a^{2⁶ - 1}` (6 бітів: 1 множення, 3 квадрати).
5. `beta₇ = (beta₆)² · beta₁ = a^{2⁷ - 1}` (7 бітів: 1 множення, 1 квадрат).
6. `beta₁₄ = (beta₇)^{2⁷} · beta₇ = a^{2¹⁴ - 1}` (14 бітів: 1 множення, 7 квадратів).
7. `beta₂₈ = (beta₁₄)^{2¹⁴} · beta₁₄ = a^{2²⁸ - 1}` (28 бітів: 1 множення, 14 квадратів).
8. `beta₅₆ = (beta₂₈)^{2²⁸} · beta₂₈ = a^{2⁵⁶ - 1}` (56 бітів: 1 множення, 28 квадратів).
9. `beta₁₁₂ = (beta₅₆)^{2⁵⁶} · beta₅₆ = a^{2¹¹² - 1}` (112 бітів: 1 множення, 56 квадратів).
10. `beta₁₁₆ = (beta₁₁₂)^{2⁴} · beta₄ = a^{2¹¹⁶ - 1}` (116 бітів: 1 множення, 4 квадрати).
11. `beta₂₃₂ = (beta₁₁₆)^{2¹¹⁶} · beta₁₁₆ = a^{2²³² - 1}` (232 біти: 1 множення, 116 квадратів).
12. Фінальне піднесення: `a⁻¹ = (beta₂₃₂)²` (1 квадрат).

Завдяки тому, що квадрати виконуються майже миттєво, уся 233-бітна модулярна інверсія завершується всього за 10 множень.

## 7. Апаратна специфіка реалізації на FPGA та ASIC

При реалізації кривих Кобліца на програмованих логічних інтегральних схемах (FPGA) або замовних мікросхемах (ASIC) досягається максимальна перевага над традиційними кривими:
1. **Нульова апаратна площа ендоморфізму Фробеніуса:** У нормальному базисі (ONB) піднесення до квадрата не вимагає жодних логічних вентилів (LUT чи тригерів) — воно реалізується виключно топологічною розводкою провідників (циклічним перепідключенням шин даних). Навіть у поліноміальному базисі блок квадрата потребує лише кількох десятків двовходових елементів XOR.
2. **Конвеєризація схеми Горнера:** Апаратний конвеєр складається з одного множника поля `F_{2^m}` та одного блоку додавання точок. Оскільки операції подвоєння відсутні, тактова частота обчислювального блоку не лімітується ланцюгами зворотного зв'язку подвоєння.
3. **Паралельне обчислення координат Лопеса-Дахаба:** Обчислення проміжних значень `A, B, C, D` під час додавання точок розпаралелюється на 2 або 4 незалежні польові помножувачі, що дозволяє виконувати один крок TNAF всього за 2–3 такти процесора.

## 8. Захист від атак по побічних каналах (Side-Channel Security)

Практична реалізація криптографії на еліптичних кривих у смарт-картах та апаратних модулях безпеки (HSM) вимагає обов'язкового захисту від атак за часом виконання (англ. *Timing Attacks*) та диференційного аналізу енергоспоживання (DPA).

Для захисту кривих Кобліца застосовуються три основні інженерні методики:
1. **Рандомізація проективних координат (Projective Coordinate Blinding):** Перед початком скалярного множення афінні координати точки `P = (x, y)` проектуються у випадкову проективну точку `(x · lambda : y · lambda² : lambda)`, де `lambda ∈ F_{2^m}^*` — випадковий ненульовий скаляр поля. Оскільки координати кожної проміжної точки рандомізуються, енергоспоживання стає статистично незалежним від оброблюваних даних.
2. **Маскування секретного скаляра (Scalar Blinding):** До секретного ключа `k` додається випадкове кратне порядку криптографічної підгрупи `k' = k + v · r`, де `v` — випадкове 32-бітне число. Оскільки `[r]P = O`, результуюча точка залишається незмінною: `[k']P = [k]P + [v·r]P = [k]P + O = [k]P`, проте послідовність розрядів TNAF повністю змінюється при кожному запуску операції підпису.
3. **Регулярні форми розкладу (Fixed-Length Comb / Dummy Additions):** Замість розгалуження `if (tnaf[idx] != 0)` цикл Горнера виконує фіксовану кількість ітерацій з обов'язковим додаванням точки (при нульовому розряді результат додавання записується у фіктивний регістр, що вирівнює профіль струму пристрою).

Для оцінки практичного виграшу кривих Кобліца над класичними кривими у таблиці наведено результати вимірювання тактових циклів на 32-бітному мікроконтролері ARM Cortex-M4 (168 МГц) без апаратного прискорювача множення:

При цьому обсяг пам'яті стека залишається мінімальним (лише 4 точки у таблиці попередніх обчислень), що є вирішальним фактором для енергоефективних мікропроцесорів інтернет-речей (IoT).

## 10. Особливості серіалізації, порядок байтів та бітові пастки

Під час практичної інтеграції кривих Кобліца у мережеві протоколи часто виникають помилки сумісності через невідповідність порядку байтів та представлення бітів у полі характеристики 2:
1. **Порядок бітів усередині полінома (Bit-Endianness):** У стандарті IEEE 1363 коефіцієнт при старшому степені `x²³²` записується у старший біт першого байта потоку даних. Натомість у програмних реалізаціях на мовах C/C++ многочлени зазвичай пакуються у масиви слів від молодшого степеня `x⁰` (біт 0 слова 0) до старшого `x²³²` (біт 40 слова 3). Перед передачею через мережу або збереженням у сертифікат X.509 обов'язково виконується реверс байтів (функція `bswap`).
2. **Перевірка належності точки кривій (Point Validation):** Перед виконанням скалярного множення відкритий ключ контрагента `P = (x, y)` повинен проходити обов'язкову перевірку на задоволення рівняння `y² + xy = x³ + 1` у полі `F_{2^{233}}` та перевірку того, що `[r]P = O`. Пропуск цієї перевірки відкриває криптосистему для атак на малі підгрупи (англ. *Small Subgroup Attacks*).
3. **Обнулення старших бітів:** Оскільки 233 біти не діляться націло на 64 (займають 3 повних слова та 41 біт четвертого слова), старші 23 біти четвертого слова (`words[3] >> 41`) повинні завжди примусово маскуватися нулями після кожного множення чи додавання. Якщо цього не зробити, сторонні біти у старшій частині регістра спричинять непередбачувані збої під час перевірки рівності точок.

## 11. Практичні рекомендації щодо вибору ширини вікна w

Вибір оптимальної ширини вікна `w` у методі `w-TNAF` диктується балансом між доступною оперативною пам'яттю мікроконтролера та вимогами до швидкодії:
- **Ширина вікна `w = 2` (базовий TNAF):** Не вимагає попередніх обчислень точок (таблиця порожня). Обсяг пам'яті стека становить менше 64 байтів. Рекомендується для екстремально обмежених 8-бітних мікроконтролерів (AVR, PIC) або смарт-карт із мінімальним обсягом RAM.
- **Ширина вікна `w = 4` (рекомендований стандарт):** Потребує збереження лише 4 попередньо обчислених точок (`T[0..3]`, 384 байти пам'яті). Зменшує середню кількість точкових додавань з 77 до 46 на кривій `K-233`, забезпечуючи 40% прискорення відносно базового TNAF. Це оптимальний вибір для 32-бітних мікроконтролерів ARM Cortex-M0+/M3/M4.
- **Ширина вікна `w ≥ 5`:** Вимагає експоненційного зростання таблиці (8 точок для `w = 5`, 16 точок для `w = 6`), проте дає незначне додаткове зменшення кількості додавань (з 46 до 39 додавань). Для кривих помірної довжини (`m ≤ 283`) застосування `w ≥ 5` є недоцільним через високі витрати пам'яті та накладні витрати на попередні обчислення.
- **Ізохронність та захищеність:** Якщо пристрій піддається ризику атак за енергоспоживанням (DPA), ширина вікна повинна бути строго фіксованою, а вибірка точок із таблиці — виконуватися через масковане читання пам'яті без умовних переходів за секретними індексами (використання умовних пересилань `CMOV` замість розгалужень `if`).

## 12. Верифікаційні тестові вектори NIST K-233

Для перевірки коректності реалізації нижче наведено офіційні параметри та тестовий вектор згідно зі стандартом NIST FIPS 186-4 для кривої `K-233` (`sect233k1`):
- **Степінь поля `m`:** 233
- **Незвідний поліном:** `f(x) = x²³³ + x⁷⁴ + 1`
- **Коефіцієнт кривої `a`:** `0`
- **Базова точка `G` (афінні координати у шістнадцятковому форматі):**
  `G_x = 0x0FAC9DFCBAC8313BB2139F1BB755FEF65BC391F8B36F8F8EB7371FD558B`
  `G_y = 0x1006A08A41903350678E58528BEBF8A0BEFF867A7CA36716F7E01F81052`
- **Порядок підгрупи `r`:**
  `r = 0x8000000000000000000000000000069D5BB915BCD46EFB1AD5F173ABDF`

Тестовий запуск алгоритму `w-TNAF` зі скаляром `k = 0x02` повинен повернути точку подвоєння `[2]G`, обчислену виключно через комбінацію ендоморфізмів `tau(G)` та `tau²(G)`. Збіг координат із точністю до 233 бітів гарантує математичну та програмну коректність усього конвеєра.
