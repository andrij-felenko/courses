# 📋 Специфікація параметрів кривих Кобліца та інтерфейс TNAF

Цей документ містить повну технічну специфікацію математичних параметрів офіційних стандартизованих кривих Кобліца (згідно зі стандартами NIST FIPS 186-4, SECG SEC 2 та ANSI X9.62), детальний опис внутрішніх форматів представлення даних, повні сигнатури функцій та програмні контракти криптографічного інтерфейсу C/C++ для виконання розкладу `tau-NAF` і швидкого скалярного множення точок.

## 1. Загальні конвенції, представлення полів та формати даних

Усі елементи скінченних двійкових полів `F_{2^m}` представляються в канонічному поліноміальному базисі `{ 1, x, x², ..., x^{m-1} }` як двійкові многочлени `A(x) = sum_{i=0}^{m-1} a_i x^i` степеня строго менше `m` з коефіцієнтами `a_i ∈ {0, 1}`.

В оперативній пам'яті многочлен зберігається як щільно упакований масив 64-бітних слів `uint64_t` у порядку від молодших степенів до старших (Little-Endian на рівні слів та бітів):
- Коефіцієнт `a₀` відповідає наймолодшому біту 0 слова `words[0]`;
- Коефіцієнт `a_{63}` відповідає найстаршому біту 63 слова `words[0]`;
- Коефіцієнт `a_{64}` відповідає біту 0 слова `words[1]`;
- Старший коефіцієнт многочлена `a_{m-1}` розміщується у біті `(m - 1) mod 64` слова `words[⌊(m-1)/64⌋]`.

**Правило обов'язкової маски:** Усі невикористані старші біти останнього 64-бітного слова (від біта `m mod 64` до біта 63) повинні бути строго обнулені після завершення кожної польової операції. Наявність сміттєвих бітів у старшій частині слова є критичним порушенням інваріантів пам'яті, що призводить до некоректних результатів порівняння точок та обчислення інверсій.

Точки на еліптичній кривій задаються у двох взаємозамінних представленнях:
1. **Афінна форма `koblitz_affine_point_t`:** Пара координат `(x, y)`, де `x, y ∈ F_{2^m}` задовольняють рівняння кривої Кобліца `y² + xy = x³ + ax² + 1`. Точка нескінченності `O` позначається прапорцем `is_infinity = true`.
2. **Проективна форма Лопеса-Дахаба `koblitz_proj_point_t`:** Трійка координат `(X : Y : Z)`, де відновлення афінних координат здійснюється як `x = X / Z` та `y = Y / Z²`. Проективне представлення використовується для всіх внутрішніх проміжних обчислень, оскільки воно дозволяє додавати точки без виконання операцій модулярної інверсії.

## 2. Доменні специфікації кривих NIST

Криві Кобліца над полями характеристики 2 стандартизовані Національним інститутом стандартів і технологій США (NIST) та Консорціумом з ефективної криптографії (SECG).

Головною перевагою кривих Кобліца є те, що їхні рівняння визначені над базовим полем `F_2`, тому коефіцієнт `b = 1`, а коефіцієнт `a ∈ {0, 1}`. Параметр `mu` визначається формулою `mu = (-1)^{1-a}`:
- Якщо `a = 0`, то `mu = -1`, характеристичне рівняння Фробеніуса має вигляд `tau² + tau + 2 = 0`, а кофактор кривої дорівнює `h = 4` (для непарних `m`);
- Якщо `a = 1`, то `mu = +1`, характеристичне рівняння Фробеніуса має вигляд `tau² - tau + 2 = 0`, а кофактор кривої дорівнює `h = 2` (для непарних `m`).

Нижче наведено вичерпні параметри п'яти стандартизованих кривих Кобліца:

### 2.1. Крива NIST K-163 (sect163k1)
Крива `K-163` забезпечує базовий 80-бітний рівень симетричної стійкості, орієнтований на низькоресурсні смарт-карти та RFID-чипи:
- **Степінь поля `m`:** 163 (використовує 3 слова `uint64_t`, старше слово містить 35 інформаційних бітів із маскою `0x7FFFFFFFFULL`).
- **Незвідний многочлен:** `f(x) = x¹⁶³ + x⁷ + x⁶ + x³ + 1` (пентаном мінімальної ваги).
- **Коефіцієнти кривої:** `a = 1`, `b = 1` (звідси `mu = +1`).
- **Кофактор кривої `h`:** 2.
- **Порядок криптографічної підгрупи `r` (просте число 163 біти):**
  `r = 0x04000000000000000000020108A2E0CC0D99F8A5EF`
- **Константи Солінаса для редукції `k mod delta`:**
  `s₀(163) = 0x0800000000000000000004021145C1981B33F14BDE`
  `s₁(163) = 0x00000000000000000000020108A2E0CC0D99F8A5EF`
- **Базова точка генератора `G` (афінні координати):**
  `G_x = 0x2FE13C0537BBC11ACAA07D793DE4E6D5E5C94EEE8`

## 3. Структури даних C та C++

:::tabs
== C (ABI / Embedded)
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#define KOBLITZ_MAX_WORDS 9
#define KOBLITZ_MAX_TNAF_DIGITS 600

/* Статусні коди помилок */
typedef enum {
    KOBLITZ_OK                     = 0,
    KOBLITZ_ERR_NULL_PARAM         = -1,
    KOBLITZ_ERR_INVALID_CURVE      = -2,
    KOBLITZ_ERR_POINT_NOT_ON_CURVE = -3,
    KOBLITZ_ERR_POINT_AT_INFINITY  = -4,
    KOBLITZ_ERR_SCALAR_OUT_OF_RANGE= -5,
    KOBLITZ_ERR_BUFFER_TOO_SMALL   = -6,
    KOBLITZ_ERR_DIV_BY_ZERO        = -7,
    KOBLITZ_ERR_SELF_TEST_FAILED   = -8
} koblitz_status_t;

/* Елемент скінченного поля F_{2^m} */
typedef struct {
    uint64_t words[KOBLITZ_MAX_WORDS];
} koblitz_fe_t;

/* Точка кривої в афінних координатах: (x, y) */
typedef struct {
    koblitz_fe_t x;
    koblitz_fe_t y;
    bool is_infinity;
} koblitz_affine_point_t;

/* Точка кривої в проективних координатах Лопеса-Дахаба: (X : Y : Z) */
typedef struct {
    koblitz_fe_t X;
    koblitz_fe_t Y;
    koblitz_fe_t Z;
    bool is_infinity;
} koblitz_proj_point_t;

/* Алгебраїчне число в кільці Z[tau]: rho = r0 + r1 * tau */
typedef struct {
    int64_t r0;
    int64_t r1;
} koblitz_ztau_t;

/* Дескриптор доменних параметрів кривої Кобліца */
typedef struct {
    uint16_t m;                    /* Степінь розширення поля (163, 233, 283, 409, 571) */
    uint8_t a;                     /* Коефіцієнт кривої a in {0, 1} */
    int8_t mu;                     /* Параметр ендоморфізму mu = (-1)^{1-a} in {-1, +1} */
    uint8_t h;                     /* Кофактор кривої h in {2, 4} */
    size_t num_words;              /* Кількість 64-бітних слів для представлення поля */
    uint64_t top_word_mask;        /* Бітова маска для нормалізації старшого слова */
    koblitz_fe_t poly;             /* Незвідний многочлен поля f(x) */
    koblitz_fe_t r;                /* Порядок криптографічної підгрупи r */
    koblitz_affine_point_t G;      /* Базова точка генератора G */
} koblitz_params_t;

/* Таблиця попередньо обчислених кратних точок для w-TNAF (w=4) */
typedef struct {
    koblitz_affine_point_t points[8]; /* Точки [alpha_u]P для непарних u */
    size_t count;
} koblitz_precomp_table_t;
```
== C++20 (Strong Types)
```cpp
#include <cstdint>
#include <array>
#include <span>
#include <expected>

namespace koblitz {

enum class Status : int32_t {
    Ok                  = 0,
    ErrNullParam        = -1,
    ErrInvalidCurve     = -2,
    ErrPointNotOnCurve  = -3,
    ErrPointAtInfinity  = -4,
    ErrScalarOutOfRange = -5,
    ErrBufferTooSmall   = -6,
    ErrDivByZero        = -7,
    ErrSelfTestFailed   = -8
};

template <size_t M>
struct DomainParams {
    static constexpr size_t Degree = M;
    static constexpr size_t Words = (M + 63) / 64;
    uint8_t a{0};
    int8_t mu{-1};
    uint8_t h{4};
    uint64_t top_mask{0};
    std::array<uint64_t, Words> poly{};
    std::array<uint64_t, Words> r{};
};

template <size_t M>
struct Point {
    static constexpr size_t Words = (M + 63) / 64;
    std::array<uint64_t, Words> x{};
    std::array<uint64_t, Words> y{};
    bool is_infinity{true};
};

struct AlgebraicZTau {
    int64_t r0{0};
    int64_t r1{0};
};

template <size_t M>
struct PrecompTable {
    static constexpr size_t Capacity = 8;
    std::array<Point<M>, Capacity> points{};
    size_t count{0};
};

} // namespace koblitz

Крім того, перевіряється умова, що точка не є точкою нескінченності, і що координати лежать строго в межах поля `F_{2^m}` (старші невикористані біти дорівнюють нулю).
- **Перед-умови:** `params != NULL`, `point != NULL`.
- **Повертає:** `KOBLITZ_OK` якщо точка коректно належить кривій; `KOBLITZ_ERR_POINT_NOT_ON_CURVE` якщо рівняння не виконується; `KOBLITZ_ERR_POINT_AT_INFINITY` якщо передано точку `O`.

### 4.4. Модулярна редукція Солінаса `koblitz_solinas_reduce`

:::tabs
== C (ABI)
```c

```
== C++20
```cpp
namespace koblitz {
template <size_t M>
[[nodiscard]] std::expected<AlgebraicZTau, Status> solinas_reduce(
    const DomainParams<M>& params,
    std::span<const uint64_t, DomainParams<M>::Words> scalar

```
:::
- **Призначення:** Зводить довільний `m`-бітний скаляр `k` до алгебраїчного залишку `rho = r₀ + r₁·tau` за модулем дільника Солінаса `delta = (tau^m - 1) / (tau - 1)`.
- **Математична гарантія:** Комплексна норма отриманого залишку строго задовольняє нерівність `N(rho) ≤ (4/7) · r < r`, що гарантує довжину наступного розкладу TNAF не більше `m + a`.

- **Призначення:** Перетворює алгебраїчний залишок `rho` у послідовність коефіцієнтів `u_i ∈ {0, ±1}`, таких що `rho = sum u_i tau^i`, причому жодні два сусідні розряди не є ненульовими одночасно (`u_i · u_{i+1} = 0`).
- **Вихідний буфер:** Масив `tnaf_digits` повинен мати розмір не менше `m + a + 1` байтів (зазвичай виділяється `MAX_TNAF_LEN = 240` байтів).

### 4.6. Скалярне множення віконним методом `koblitz_scalar_mul_wtnaf`

:::tabs
== C (ABI)
```c
koblitz_status_t koblitz_scalar_mul_wtnaf(
    const koblitz_params_t *params,
    koblitz_affine_point_t *Q,
    const koblitz_affine_point_t *P,
    const koblitz_fe_t *scalar,
    uint8_t window_size
);
```
== C++20
```cpp
namespace koblitz {
template <size_t M>
[[nodiscard]] std::expected<Point<M>, Status> scalar_multiply_wtnaf(
    const DomainParams<M>& params,
    const Point<M>& P,
    std::span<const uint64_t, DomainParams<M>::Words> scalar,
    uint8_t window_size = 4
) noexcept;
}
```
:::
- **Призначення:** Обчислює результуючу точку `Q = [k]P` на кривій Кобліца з використанням віконного розкладу `w-TNAF`.
- **Параметр `window_size`:** Рекомендоване значення `window_size = 4`. Підтримуються значення від 2 до 5.
- **Властивості виконання:** Усі подвоєння точок усунуті та замінені автоморфізмами Фробеніуса. Кількість операцій додавання точок становить у середньому `m / (window_size + 1)`.

## 6. Інтеграція в криптографічні протоколи: ECDSA та ECDH

Представлений API безпосередньо інтегрується в стандартні протоколи цифрового підпису ECDSA та протокол узгодження ключів ECDH (Elliptic Curve Diffie-Hellman):
1. **Генерація пари ключів (ECDH Keygen):** Генерується криптографічно стійкий випадковий скаляр `d ∈ [1, r - 1]`. Відкритий ключ обчислюється як `Q = [d]G` за допомогою виклику `koblitz_scalar_mul_wtnaf`.
2. **Обчислення спільного секрету (ECDH Shared Secret):** Отримавши відкритий ключ контрагента `Q_A`, сторона перевіряє його дійсність функцією `koblitz_point_validate`, після чого обчислює спільну точку `K = [d_B] Q_A`. `X`-координата точки `K` передається у функцію формування ключа (KDF на основі SHA-256 або SHA-3).
3. **Цифровий підпис ECDSA:** Для підписання хеш-повідомлення `e` генерується ефемерний скаляр `k ∈ [1, r - 1]`, обчислюється точка `(x₁, y₁) = [k]G`, визначається параметр підпису `s₁ = x₁ mod r`. Значення `s₂ = k⁻¹ · (e + d · s₁) mod r` обчислюється за допомогою стандартної скалярної модулярної арифметики.

## 7. Специфікація форматів серіалізації точок SEC 1 та ANSI X9.62

Згідно зі стандартом SECG SEC 1 (Elliptic Curve Cryptography), точки на двійкових еліптичних кривих кодуються у байти одним із трьох стандартизованих форматів:
1. **Незжатий формат (Uncompressed Format):**
   - Перший байт-заголовок дорівнює `0x04`;
   - Наступні `⌈m/8⌉` байтів містять біг-ендіан серіалізацію координати `x`;
   - Завершальні `⌈m/8⌉` байтів містять біг-ендіан серіалізацію координати `y`.
   - Загальна довжина октетного рядка: `2 · ⌈m/8⌉ + 1` байтів (для кривої `K-233` це `2 · 30 + 1 = 61` байт).
2. **Стиснений формат (Compressed Format):**
   - Перший байт-заголовок дорівнює `0x02` (якщо біт сліду `ỹ = 0`) або `0x03` (якщо `ỹ = 1`);
   - Наступні `⌈m/8⌉` байтів містять серіалізацію координати `x`.
   - Загальна довжина рядка: `⌈m/8⌉ + 1` байт (для `K-233` лише 31 байт, що економить 50% мережевого трафіку).
   - Відновлення координати `y` на стороні отримувача полягає у розв'язанні квадратного рівняння `z² + z = beta` (де `z = y / x`, `beta = x + a + 1/x²`) за допомогою функції напівсліду (англ. *Half-Trace*) у полі характеристики 2. Біт `ỹ` визначає вибір одного з двох коренів.
3. **Гібридний формат (Hybrid Format):**
   - Заголовок `0x06` або `0x07` супроводжується повними координатами `x` та `y`, що дозволяє одночасно передавати повну точку та валідувати її стиснений біт.

## 8. Вимоги до ентропії та генерація детермінованих нонсів (RFC 6979)

У протоколі цифрового підпису ECDSA критично важливо, щоб ефемерний скаляр `k` генерувався абсолютно непередбачуваним або повністю детермінованим чином:
- Якщо генератор випадкових чисел (RNG) має дефект і видає навіть кілька однакових або частково корельованих бітів `k` для різних повідомлень, зловмисник може повністю відновити закритий ключ `d` за допомогою атак на основі редукції ґраток (проблема прихованого числа, англ. *Hidden Number Problem*, алгоритм LLL/BKZ).
- Для гарантії повної стійкості у бібліотеці рекомендовано застосовувати стандарт RFC 6979: детерміновану генерацію скаляра `k` через криптографічну хеш-функцію HMAC-SHA256 від закритого ключа та хешу підписуваного повідомлення: `k = HMAC_SHA256(d, hash(m))`.

## 9. Самотестування криптографічного модуля (FIPS 140-3 Power-Up Self-Tests)

Для відповідності вимогам безпеки стандартів FIPS 140-3 та NIST SP 800-140C модуль реалізує автоматичне самотестування при старті:

:::tabs
== C (ABI)
```c
koblitz_status_t koblitz_self_test(void);
```
== C++20
```cpp
namespace koblitz {
[[nodiscard]] Status run_self_tests() noexcept;
}
```
:::

Функція виконує такі перевірки за відомими еталонними векторами (англ. *Known Answer Tests*, KAT):
1. **Тест базової польової арифметики:** Множення, піднесення до квадрата та інверсія Іто-Цудзії для тестових поліномів кривої `K-233`.
2. **Тест ендоморфізму Фробеніуса:** Перевірка тотожності `tau²(G) - mu·tau(G) + [2]G = O`.
3. **Тест генерації підпису ECDSA:** Формування та перевірка цифрового підпису для фіксованого тестового вектора NIST з порівнянням результатів байт-у-байт.
4. Якщо будь-який із тестів повертає невідповідність, модуль переходить у стан блокування `KOBLITZ_ERR_SELF_TEST_FAILED` та блокує всі подальші виклики криптографічних операцій.

## 12. Інваріанти пам'яті та потокобезпечність

1. **Reentrancy та Thread-Safety:** Усі функції бібліотеки є строго реентерабельними та потокобезпечними. Жодна функція не використовує глобальних або статичних змінних стану.
2. **Нульове динамічне виділення пам'яті (Zero Heap Allocation):** Реалізація повністю уникає викликів `malloc()` та `free()`. Усі проміжні структури та таблиці попередніх обчислень розміщуються на стеку виклику (`koblitz_precomp_table_t`), що гарантує детермінований час виконання та надійність у вбудованих операційних системах жорсткого реального часу (FreeRTOS, Zephyr).
3. **Очищення секретних буферів (Secure Zeroing):** Буфери, що містять закриті ключі, редуковані залишки `rho` або ефемерні скаляри, перед виходом з функцій обов'язково затираються за допомогою `explicit_bzero()` або бар'єрів пам'яті компілятора для запобігання витоку ключів через стек.
4. **Вирівнювання структур даних:** Для досягнення максимальної швидкодії векторних інструкцій обробки бітів (SIMD/NEON) структури даних `koblitz_fe_t` вирівнюються за межею 64 байтів (`alignas(64)`), що запобігає затримкам через міжрядковий доступ до кеш-пам'яті L1 процесора.

## 13. Рекомендації щодо переходу на постквантову гібридну криптографію

У сучасних протоколах зв'язку (наприклад, у гібридному обміні ключами TLS 1.3 згідно з IETF draft-ietf-tls-hybrid-design) криві Кобліца застосовуються у поєднанні з постквантовими алгоритмами на ґратках (ML-KEM / Kyber):
- **Схема комбінування:** Спільний секрет формується шляхом конкатенації результату класичного протоколу ECDH на кривій `K-233` та результату інкапсуляції ключа `ML-KEM-512`: `SS = KDF(SS_{K233} || SS_{MLKEM})`.
- **Переваги гібридного підходу:** Якщо постквантовий алгоритм на ґратках буде скомпрометований через майбутній математичний прорив, захист гарантується перевіреною часом стійкістю кривої Кобліца; якщо ж з'явиться повномасштабний квантовий комп'ютер, захист забезпечить алгоритм ML-KEM.
- **Енергоефективність на сенсорах:** Завдяки відсутності подвоєнь точок у методі `w-TNAF`, накладні витрати на класичну частину гібридного рукостискання є практично невідчутними для мікроконтролерів із батарейним живленням.
