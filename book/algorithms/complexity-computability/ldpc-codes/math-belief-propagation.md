# 🧮 Математика алгоритму Belief Propagation та матриць Таннера

Математичний апарат кодів з низькою щільністю перевірок на парність (LDPC) спирається на лінійну алгебру над скінченними полями `GF(2)`, теорію графів, теорію ймовірностей та імовірнісні графічні моделі. У цьому документі наведено суворе математичне виведення структури матриці `H`, рівнянь ітеративного декодування за алгоритмом Sum-Product (Belief Propagation), його спрощеної модифікації Min-Sum, аналітичного методу еволюції щільності (Density Evolution) та апарату оцінки швидкості коду.

## 1. Алгебраїчна структура перевірочної матриці H та матриці інцидентності

Лінійний двовимірний кодовий блок `(n, k)` над скінченним полем Галуа `GF(2)` задається перевірочною матрицею `H` розміру `m x n`, де `m = n - k` є кількістю лінійно незалежних перевірочних рівнянь на парність (за припущення, що матриця `H` має повний ранг `rank(H) = m`).

Перевірочна матриця `H` визначає лінійне відображення з двовимірного векторного простору кодових слів `GF(2)^n` у простір синдромів `GF(2)^m`. Множина всіх дійсних кодових слів `C` становить ядро (Kernel / Null Space) лінійного оператора `H` у векторному просторі `GF(2)^n`:

```
C = Ker(H) = { c ∈ GF(2)^n : H · c^T = 0 (mod 2) }
```

Для кожної строки `i` матриці `H` виконується рівняння перевірки на парність, яке можна розглядати як скалярний добуток у полем `GF(2)` між `i`-м рядком матриці `H` та кодовим вектором `c`:

```
∑_{j=1}^n H_{i,j} · c_j = 0 (mod 2)      [сумування в GF(2) / побітова операція XOR]
```

Для регулярного LDPC-коду `(n, d_v, d_c)` матриця `H` задовольняє наступним суворим топологічним обмеженням:
1. Вага кожного стовпця (ступінь символьного вузла `d_v`) дорівнює константі:

```
∑_{i=1}^m H_{i,j} = d_v      [для кожного стовпця j ∈ {1, ..., n}]
```

2. Вага кожного рядка (ступінь перевірочного вузла `d_c`) дорівнює константі:

```
∑_{j=1}^n H_{i,j} = d_c      [для кожного рядка i ∈ {1, ..., m}]
```

Підрахунок загальної кількості одиниць (ребер графа Таннера `|E|`) у матриці `H` двома незалежними способами (по стовпцях і по рядках) дає фундаментальне тотожне співвідношення:

```
n · d_v = m · d_c = |E|
```

Звідси отримуємо алгебраїчні вирази для відношення розмірів матриці та конструктивної швидкості коду (Design Rate `R_design`):

```
m / n = d_v / d_c                        [поділили обидві частини на n · d_c]
R_design = (n - m) / n                  [визначення швидкості коду]
         = 1 - m / n                    [розкрили дріб]
         = 1 - d_v / d_c                [підставили відношення d_v / d_c]
```

Конструктивна швидкість `R_design` визначає нижню межу дійсної швидкості коду. Якщо в матриці `H` наявні лінійно залежні рядки, то дійсний ранг `r = rank(H) < m`, і фактична швидкість коду `R_actual = 1 - r/n` буде трохи вищою за конструктивну.

Матриця суміжності двочасткового графа Таннера `A_G` розміру `(n + m) x (n + m)` будується з матриці `H` та її транспонованої матриці `H^T`:

```
A_G = [ 0   H^T ]
      [ H    0  ]
```

Спектральні властивості матриці суміжності `A_G` (зокрема її друге за величиною власне значення `λ_2`) визначають коефіцієнт розширення графа Таннера, який безпосередньо впливає на мінімальну кодову відстань `d_min` та швидкість збіжності ітеративного декодера.

## 2. Логарифмічні відношення правдоподібності (LLR) та канал AWGN

Під час передачі біта `x_j ∈ {0, 1}` через фізичний канал із адитивним білим гаусовим шумом (AWGN) із дисперсією `σ²`, бінарний знак модулюється у двополярний амплітудний сигнал `s_j ∈ {+1, -1}` за правилом BPSK-модуляції:

```
s_j = 1 - 2 · x_j      [де 0 -> +1, 1 -> -1]
```

Приймач отримує відсвіт `y_j = s_j + n_j`, де шум `n_j` підпорядковується нормальному гаусовому розподілу `N(0, σ²)`.

Умовна щільність ймовірності отримання значення `y_j` при заданому переданому біті `x_j`:

```
P(y_j | x_j = 0) = (1 / (√(2π) · σ)) · exp( -(y_j - 1)² / (2σ²) )
P(y_j | x_j = 1) = (1 / (√(2π) · σ)) · exp( -(y_j + 1)² / (2σ²) )
```

У теорії імовірнісного декодування замість прямих ймовірностей `P(x_j = 0 | y_j)` використовують логарифмічне відношення правдоподібності (Log-Likelihood Ratio, LLR). Використання LLR має дві фундаментальні переваги: воно перетворює множення ймовірностей на просте додавання та запобігає втраті чисельної точності (Underflow) при опрацюванні малих ймовірностей.

Логарифмічне відношення правдоподібності `L_j` визначається як логарифм частки апостеріорних ймовірностей:

```
L_j = ln( P(x_j = 0 | y_j) / P(x_j = 1 | y_j) )
```

За теоремою Баєса, якщо апостеріорні ймовірності `P(x_j = 0) = P(x_j = 1) = 1/2` є рівноймовірними, то відношення апостеріорних ймовірностей дорівнює відношенню умовних правдоподібностей каналу. Виведемо канальне значення `L_j` підставленням гаусових щільностей ймовірності:

```
L_j = ln( exp( -(y_j - 1)² / (2σ²) ) / exp( -(y_j + 1)² / (2σ²) ) )
    = ( -(y_j - 1)² / (2σ²) ) - ( -(y_j + 1)² / (2σ²) )    [властивість ln(exp(z)) = z]
    = ( -(y_j² - 2y_j + 1) + (y_j² + 2y_j + 1) ) / (2σ²)    [розкрили квадрати]
    = ( 4 · y_j ) / (2σ²)                                    [звели подібні доданки]
    = (2 · y_j) / σ²                                         [скоротили на 2]
```

Знак `L_j` визначає найбільш ймовірне значення біта (`L_j > 0 => x_j = 0`, `L_j < 0 => x_j = 1`), а модуль `|L_j|` характеризує ступінь впевненості каналу в прийнятому рішенні. Якщо `|L_j|` велике, канал абсолютно впевнений у прийомі; якщо `|L_j| ≈ 0`, біт є сильно зашумленим і невизначеним.

Формула переходу від LLR до точної ймовірності `P(x_j = 0)` має вигляд нелінійної сигмоїди:

```
P(x_j = 0) = 1 / (1 + exp(-L_j)) = exp(L_j / 2) / (exp(L_j / 2) + exp(-L_j / 2))
```

## 3. Точні рівняння алгоритму Sum-Product (Belief Propagation)

Алгоритм Sum-Product працює шляхом ітеративного обміну повідомленнями вздовж ребер графа Таннера.
Позначимо через `N(v)` множину перевірочних вузлів, з'єднаних із символьним вузлом `v`, а через `N(c)` — множину символьних вузлів, з'єднаних із перевірочним вузлом `c`.

### 3.1. Фаза 1: Оновлення від Символьного до Перевірочного вузла (VN -> CN)

Символьний вузол `v` агрегує інформацію від каналу та від усіх сусідніх перевірочних вузлів, за винятком того вузла `c`, якому надсилається повідомлення. Це забезпечує дотримання принципу неітеративної зворотності (Extrinsic Information):

Повідомлення `q_{v → c}` від символьного вузла `v` до перевірочного вузла `c` обчислюється як сума початкового канального LLR та вхідних LLR від усіх *інших* сусідніх перевірочних вузлів:

```
q_{v → c} = L_v + ∑_{c' ∈ N(v) \ {c}} r_{c' → v}
```

Фізичний зміст цього рівняння полягає в тому, що символьний вузол додає незалежні підтвердження від інших рівнянь перевірки парності до своєї початкової канальної оцінки `L_v`.

### 3.2. Фаза 2: Оновлення від Перевірочного до Символьного вузла (CN -> VN)

Перевірочний вузол `c` вимагає, щоб сума всіх приєднаних бітів була парною (дорівнювала 0 mod 2). Розглянемо два бінарні біти `x_1` та `x_2` з LLR `q_1` та `q_2`. Ймовірність того, що їхня сума `x_1 ⊕ x_2 = 0`, дорівнює `P(x_1=0)P(x_2=0) + P(x_1=1)P(x_2=1)`.

Використовуючи тотожність `P(x=0) - P(x=1) = tanh(L / 2)`, перевірочний вузол перетворює ймовірності парності в точну алгебраїчну тотожність для гіперболічного тангенса:

```
tanh( r_{c → v} / 2 ) = ∏_{v' ∈ N(c) \ {v}} tanh( q_{v' → c} / 2 )
```

Виведемо вираження для `r_{c → v}` через розділення знака та модуля LLR:

```
sign(r_{c → v}) = ∏_{v' ∈ N(c) \ {v}} sign(q_{v' → c})
|r_{c → v}| = 2 · arctanh( ∏_{v' ∈ N(c) \ {v}} tanh( |q_{v' → c}| / 2 ) )
```

Повне точне рівняння оновлення перевірочного вузла в алгоритмі Sum-Product має вигляд:

```
r_{c → v} = ( ∏_{v' ∈ N(c) \ {v}} sign(q_{v' → c}) ) · 2 · arctanh( ∏_{v' ∈ N(c) \ {v}} tanh( |q_{v' → c}| / 2 ) )
```

Математично це означає, що перевірочний вузол підтверджує 0, якщо кількість від'ємних входів (одиниць) серед інших бітів є парною, а впевненість обмежена найменш впевненим бітом серед приєднаних.

## 4. Математичне спрощення: Алгоритм Min-Sum

Обчислення нелінійних функцій `tanh` та `arctanh` вимагає значних обчислювальних витрат або великих таблиць LUT (Look-Up Tables). Скористаємося асимптотичною властивістю функції `tanh(x / 2)`: при зростанні аргументу `x` функція `tanh(x/2)` швидко прямує до 1, тому добуток тангенсів повністю домінується найменшим аргументом.

Розглянемо апроксимацію для добутку:

```
∏_{i=1}^k tanh( |q_i| / 2 ) ≈ tanh( (min_{i} |q_i|) / 2 )
```

Застосовуючи обернену функцію `2 · arctanh`, отримуємо тотожне спрощення:

```
2 · arctanh( tanh( (min_{i} |q_i|) / 2 ) ) = min_{i} |q_i|
```

Таким чином, модуль повідомлення перевірочного вузла у наближенні Min-Sum спрощується до мінімуму вхідних модулів:

```
|r_{c → v}| ≈ min_{v' ∈ N(c) \ {v}} |q_{v' → c}|
```

Підсумкова формула оновлення перевірочного вузла Min-Sum:

```
r_{c → v} = ( ∏_{v' ∈ N(c) \ {v}} sign(q_{v' → c}) ) · min_{v' ∈ N(c) \ {v}} |q_{v' → c}|
```

Для виправлення систематичної переоцінки правдоподібності в Min-Sum застосовують нормалізований Min-Sum (Normalized Min-Sum) із множником `γ ∈ (0.7, 0.9)`:

```
r_{c → v}^{norm} = γ · r_{c → v}^{Min-Sum}
```

Альтернативою є Min-Sum зі зміщенням (Offset Min-Sum), де від мінімуму віднімається константа `β > 0`:

```
r_{c → v}^{offset} = sign(r_{c → v}) · max( min_{v'} |q_{v'}| - β, 0 )
```

Математичні симуляції показують, що нормалізований Min-Sum з `γ = 0.8` програє точного алгоритму Sum-Product не більше `0.05 дБ`, вимагаючи при цьому у 5 разів менше арифметичних операцій.

## 5. Апарат еволюції щільності (Density Evolution)

Еволюція щільності — це математичний метод розрахунку порогу декодування LDPC-коду при довжині блоку `n -> ∞`. За припущення про відсутність циклів у графі Таннера, LLR-повідомлення є незалежними випадковими величинами.

Нехай `f_k` — функція щільності ймовірності LLR-повідомлення `q_{v → c}` на ітерації `k`.

1. **Еволюція на перевірочному вузлі (CN):** Операція над знаками є множенням, а операція над модулями `2 · arctanh(∏ tanh)` у дуальному домені відповідає згортці щільностей у так званому `R`-домені.
2. **Еволюція на символьному вузлі (VN):** Оскільки оновлення символьного вузла є звичайною сумою незалежних випадкових величин `L_v + ∑ r`, підсумкова щільність ймовірності є прямою згорткою (Convolution) функцій щільності:

```
f_{k+1}(x) = f_0(x) ⊛ ( g_k(x) )^{\circledast (d_v - 1)}
```

де `f_0(x)` — щільність початкового канального LLR, a `⊛` позначує оператор згортки функцій щільності.

Обчислення дискретної згортки на практиці виконується через швидке перетворення Фур'є (FFT) на сітці з кількох тисяч точок.

### Гаусове наближення (Gaussian Approximation)

У спрощеному виді еволюцію щільності моделюють гаусовим наближенням, припускаючи, що LLR-повідомлення зберігають нормальний розподіл `N(m, 2m)` із виконуванням умови симетрії `σ² = 2m`. Це дозволяє відстежувати лише один параметр — математичне сподівання LLR `m_k` від ітерації до ітерації:

```
m_{k+1} = m_0 + (d_v - 1) · ϕ^{-1}\left( 1 - \left( 1 - ϕ(m_k) \right)^{d_c - 1} \right)
```

де нелінійна монотонна функція `ϕ(x)` визначається як математичне сподівання `tanh`:

```
ϕ(x) = (1 / √(4πx)) · ∫_0^∞ tanh(u/2) · exp( -(u - x)² / (4x) ) du
```

Якщо при заданому рівні шуму `σ` послідовність математичних сподівань `m_k -> ∞` при `k -> ∞`, це означає, що ймовірність помилки декодування прямує до нуля. Найбільше значення `σ`, при якому `m_k -> ∞`, називається теоретичним порогом декодування `σ*`.

## 6. Алгебра пасток (Trapping Sets) та алгебраїчний аналіз

Навіть при `n -> ∞` локальні підграфи можуть створювати конфігурації, які блокують збіжність Belief Propagation. Пастка (Trapping Set) `T(a, b)` визначається як підмножина з `a` символьних вузлів, індукований підграф яких має точно `b` неоцінених (непарних) перевірочних вузлів.

Формально, нехай `S ⊂ V_v` — множина символьних вузлів розміру `|S| = a`. Позначимо через `N(S) ⊂ V_c` множину сусідніх перевірочних вузлів. Множина `N(S)` розбивається на дві підмножини:
- `E(S)` — множина парних перевірочних вузлів, які з'єднані з `S` принаймні двома ребрами.
- `O(S)` — множина непарних перевірочних вузлів, які з'єднані з `S` точно одним ребром.

Пастка є критичною, якщо `|O(S)| = b` є малим числом, а `|E(S)|` є відносно великим. У цьому випадку перевірочні вузли з `E(S)` постійно надсилають підтвердження неправильних значень бітів усередині `S`, пригнічуючи поодинокі сигнали виправлення від `O(S)`.

Для регулярного коду з `d_v = 3` найменшими пастками є конфігурації `(5, 2)` та `(4, 2)`, які визначають поріг помилок (Error Floor) у каналах із високим співвідношенням сигнал/шум.

Пошук спектра пасток здійснюється алгебраїчними методами шляхом аналізу нульових просторів підматриць `H_S`. Якщо мінімальна вага вузлів у пастці дорівнює `w_min`, поріг помилок визначається як `P_e ≈ C · exp(-w_min · E_b / N_0)`.

## 7. Завершення ітерації та обчислення апостеріорного LLR

Після виконання обох фаз для кожного символьного вузла `v` обчислюється підсумкове апостеріорне LLR `L_total(v)`:

```
L_total(v) = L_v + ∑_{c ∈ N(v)} r_{c → v}
```

Тверде рішення (Hard Decision) щодо значення біта `ĉ_v`:

```
ĉ_v = 0,  якщо L_total(v) ≥ 0
ĉ_v = 1,  якщо L_total(v) < 0
```

Алгоритм перевіряє умову зупинки. Обчислюється вектор синдрому `s`:

```
s = H · ĉ^T (mod 2)
```

Якщо `s = 0` (усі елементи вектору `s` дорівнюють нулю), це означає, що `ĉ` є дійсним кодовим словом. Алгоритм негайно припиняє ітерації та повертає `ĉ`. Якщо `s ≠ 0`, процес повторюється до досягнення ліміту ітерацій `I_max`.

## 8. Обчислювальна складність однієї ітерації

Нехай `|E| = n · d_v = m · d_c` — загальна кількість ребер у графі Таннера.
1. **Фаза VN -> CN:** Для кожного ребра виконується одне додавання. Загальна складність `O(|E|) = O(n · d_v)`.
2. **Фаза CN -> VN (Min-Sum):** Для кожного перевірочного вузла знаходження першого та другого мінімуму серед `d_c` елементів вимагає `O(d_c)` операцій. Загалом по всіх `m` вузлах: `O(m · d_c) = O(|E|) = O(n · d_v)`.
3. **Обчислення L_total та синдрому:** `O(n · d_v)`.

Оскільки `d_v` є малою константою (наприклад, `d_v = 3` або `4`), складність однієї ітерації декодування LDPC строго лінійна від довжини коду: `O(n)`.
