# 📋 Програмний інтерфейс безпечних криптографічних примітивів постійного часу

Реалізація криптографічних алгоритмів вимагає спеціалізованого програмного інтерфейсу (API), де кожна функція гарантує виконання за строго детермінований час та незмінний профіль звернень до пам'яті незалежно від значень аргументів. Звичайні стандартні бібліотеки мов C та C++ оптимізовані під максимальну продуктивність для узагальнених задач, що призводить до катастрофічних витоків секретних ключів через передбачення переходів (BPU), варіації латентності АЛП та кеш-ієрархію процесора.

Нижче наведено повну структурну специфікацію уніфікованого прикладного інтерфейсу безпечних криптографічних операцій постійного часу `libctcrypto`, типи даних, контракти функцій, контексти ізольованого середовища, захист від спекулятивних атак (Spectre), багаторозрядну арифметику, операції на еліптичних кривих, поліноміальну алгебру постквантових схем, безпечне кодування даних, інтерфейс маскування часток, апаратні розширення, перед- і післяумови, інваріанти платформної сумісності, автоматизоване TVLA-тестування та інструменти динамічного контролю витоків пам'яті.

## 1. Заголовний файл, макроси сумісності та базові типи

Інтерфейс оголошено в заголовному файлі `<ctcrypto/constant_time.h>`.

```c
#ifndef CT_CRYPTO_CONSTANT_TIME_H
#define CT_CRYPTO_CONSTANT_TIME_H

#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

#if defined(__cplusplus)
extern "C" {
#endif
```

### 1.1 Тип логічного вибору (ct_choice_t)

У класичному стандарті C булевий тип `bool` або цілочисельний тип `int` використовує числове значення `0` для представлення хибності (`false`) та ненульове значення `1` для істини (`true`). У постійночасових алгоритмах усі операції умовного вибору та маскування вимагають повнорозрядних бітових масок: або слова з усіх нулів, або слова з усіх одиниць.

Для усунення неоднозначностей та запобігання випадковому використанню звичайних булевих змінних у побітових формулах вводиться фундаментальний тип `ct_choice_t`:
```c
typedef uint32_t ct_choice_t;
```

**Інваріанти значень `ct_choice_t`:**
- `CT_FALSE = 0x00000000U` (всі 32 біти слова дорівнюють нулю, семантично відповідає невиконанню умови);
- `CT_TRUE  = 0xFFFFFFFFU` (всі 32 біти слова дорівнюють одиниці, семантично відповідає виконанню умови).

Будь-яке проміжне значення `ct_choice_t`, відмінне від `0x00000000` та `0xFFFFFFFF` (наприклад, значення `1`), є порушенням контракту API і призводить до некоректної роботи побітових масок.

```c
#define CT_FALSE ((ct_choice_t)0x00000000U)
#define CT_TRUE  ((ct_choice_t)0xFFFFFFFFU)
```

### 1.2 Макроси бар'єрів компілятора

Сучасні оптимізуючі компілятори Clang, GCC та MSVC під час статичного аналізу коду розпізнають типові ідіоми побітового вибору виду `y ^ (mask & (x ^ y))` і намагаються згорнути їх у машинний код з умовними переходами `JNE/JE` або умовними інструкціями `CMOV`. Для гарантованого придушення такої оптимізації визначено системні бар'єри:

```c
#if defined(__GNUC__) || defined(__clang__)
#define CT_BARRIER_32(x) do { __asm__ volatile ("" : "+r" (x)); } while(0)
#define CT_BARRIER_64(x) do { __asm__ volatile ("" : "+r" (x)); } while(0)
#define CT_BARRIER_PTR(p) do { __asm__ volatile ("" : "+r" (p)); } while(0)
#elif defined(_MSC_VER)
#define CT_BARRIER_32(x) do { _ReadWriteBarrier(); } while(0)
#define CT_BARRIER_64(x) do { _ReadWriteBarrier(); } while(0)
#define CT_BARRIER_PTR(p) do { _ReadWriteBarrier(); } while(0)
#else
#define CT_BARRIER_32(x) ((void)0)
#define CT_BARRIER_64(x) ((void)0)
#define CT_BARRIER_PTR(p) ((void)0)
#endif
```

## 2. Захист від спекулятивних атак (Spectre Mitigations API)

Мікроархітектурні атаки типу Spectre (зокрема Variant 1: Bounds Check Bypass) використовують спекулятивне виконання процесора за межами масиву до того, як блок передбачення переходів підтвердить умову `if (index < length)`.

Модуль надає апаратні бар'єри серіалізації та маски безпечного спекулятивного індексування:

```c
/* Примусова серіалізація конвеєра для зупинки спекулятивного виконання (LFENCE / CSDB) */
static inline void ct_speculation_barrier(void) {
    #if defined(__x86_64__) || defined(_M_X64)
    #if defined(__GNUC__) || defined(__clang__)
    __asm__ volatile ("lfence" ::: "memory");
    #else
    _mm_lfence();
    #endif
    #elif defined(__aarch64__)
    __asm__ volatile ("isb" ::: "memory");
    #else
    CT_BARRIER_32(0);
    #endif
}

/* Безпечне обмеження індексу масиву без умовних переходів для запобігання Spectre-v1 */
static inline size_t ct_speculative_clamp_index(size_t idx, size_t max_len) {
    /* Якщо idx < max_len, маска = 0xFF..FF, інакше 0x00..00 */
    size_t diff = idx ^ max_len;
    size_t sub = idx - max_len;
    size_t borrow = (idx & ~max_len) | ((~diff) & sub);
    size_t mask = -((borrow >> ((sizeof(size_t) * 8) - 1)) & 1);
    
    #if defined(__GNUC__) || defined(__clang__)
    __asm__ volatile ("" : "+r" (mask));
    #endif
    
    return idx & mask;
}
```

### Гарантія спекулятивного захисту:
- Навіть якщо процесор спекулятивно виконує інструкції читання пам'яті за хибно передбаченим розгалуженням, `ct_speculative_clamp_index` перетворює позамежовий індекс на `0`, гарантуючи відсутність витоку рядків кешу чутливих областей пам'яті.

## 3. Логічні операції та предикати порівняння

Усі предикати приймають цілочисельні аргументи і повертають значення типу `ct_choice_t` (`CT_TRUE` або `CT_FALSE`). Час виконання функцій строго фіксований і не залежить від значень аргументів.

| Назва функції | Сигнатура | Призначення та поведінка |
| :--- | :--- | :--- |
| `ct_is_zero_u32` | `ct_choice_t ct_is_zero_u32(uint32_t x)` | Повертає `CT_TRUE`, якщо `x == 0`, інакше `CT_FALSE`. |
| `ct_is_nonzero_u32`| `ct_choice_t ct_is_nonzero_u32(uint32_t x)`| Повертає `CT_TRUE`, якщо `x != 0`, інакше `CT_FALSE`. |
| `ct_is_equal_u32` | `ct_choice_t ct_is_equal_u32(uint32_t a, uint32_t b)` | Повертає `CT_TRUE`, якщо `a == b`, інакше `CT_FALSE`. |
| `ct_is_equal_u64` | `ct_choice_t ct_is_equal_u64(uint64_t a, uint64_t b)` | Повертає `CT_TRUE`, якщо `a == b` для 64-бітних слів. |
| `ct_is_less_u32` | `ct_choice_t ct_is_less_u32(uint32_t a, uint32_t b)` | Повертає `CT_TRUE`, якщо `a < b` (беззнакове порівняння). |
| `ct_is_less_u64` | `ct_choice_t ct_is_less_u64(uint64_t a, uint64_t b)` | Повертає `CT_TRUE`, якщо `a < b` (64-бітне беззнакове). |
| `ct_bool_to_choice`| `ct_choice_t ct_bool_to_choice(bool b)` | Перетворює `true` -> `CT_TRUE`, `false` -> `CT_FALSE`. |
| `ct_choice_to_bool`| `bool ct_choice_to_bool(ct_choice_t c)` | Розсекречує значення: повертає `true` якщо `c == CT_TRUE`. |

### Специфікація предикатів

#### `ct_is_zero_u32`
```c
ct_choice_t ct_is_zero_u32(uint32_t x);
```
- **Параметри:** `x` — 32-бітне беззнакове число.
- **Повертає:** `CT_TRUE` (0xFFFFFFFF), якщо `x == 0`; `CT_FALSE` (0x00000000), якщо `x != 0`.
- **Перед-умови:** Немає.
- **Після-умови:** Повернене значення є валідним `ct_choice_t`.
- **Гарантія безпеки:** Виконується рівно за 4 арифметичні операції без розгалужень. Механізм базується на виразі `((x | -x) >> 31) ^ 1`.

#### `ct_is_less_u32`
```c
ct_choice_t ct_is_less_u32(uint32_t a, uint32_t b);
```
- **Параметри:** `a`, `b` — 32-бітні беззнакові числа.
- **Повертає:** `CT_TRUE`, якщо `a < b`, інакше `CT_FALSE`.
- **Механізм:** Аналізує біт позики при відніманні `a - b` через вираз `(a & ~b) | ((~(a ^ b)) & (a - b))`.
- **Гарантія безпеки:** Повністю стійка до арифметичного переповнення розрядної сітки без використання інструкцій порівняння з умовними прапорцями.

## 4. Умовний вибір та перестановка операндів

Функції цієї групи реалізують умовний вибір значень та перестановку пам'яті за маскою `ct_choice_t`.

| Назва функції | Сигнатура | Опис |
| :--- | :--- | :--- |
| `ct_select_u8` | `uint8_t ct_select_u8(ct_choice_t c, uint8_t a, uint8_t b)` | Повертає `a`, якщо `c == CT_TRUE`, інакше `b`. |
| `ct_select_u16` | `uint16_t ct_select_u16(ct_choice_t c, uint16_t a, uint16_t b)` | Повертає `a`, якщо `c == CT_TRUE`, інакше `b`. |
| `ct_select_u32` | `uint32_t ct_select_u32(ct_choice_t c, uint32_t a, uint32_t b)` | Повертає `a`, якщо `c == CT_TRUE`, інакше `b`. |
| `ct_select_u64` | `uint64_t ct_select_u64(ct_choice_t c, uint64_t a, uint64_t b)` | Повертає `a`, якщо `c == CT_TRUE`, інакше `b`. |
| `ct_select_bytes`| `void ct_select_bytes(ct_choice_t c, uint8_t *dst, const uint8_t *src, size_t len)` | Якщо `c == CT_TRUE`, копіює `src` в `dst`. |
| `ct_cswap_u32` | `void ct_cswap_u32(ct_choice_t c, uint32_t *a, uint32_t *b)` | Міняє місцями `*a` та `*b`, якщо `c == CT_TRUE`. |
| `ct_cswap_u64` | `void ct_cswap_u64(ct_choice_t c, uint64_t *a, uint64_t *b)` | Міняє місцями `*a` та `*b`, якщо `c == CT_TRUE`. |
| `ct_cswap_bytes`| `void ct_cswap_bytes(ct_choice_t c, void *a, void *b, size_t len)` | Міняє вміст буферів `a` та `b`, якщо `c == CT_TRUE`. |

### Специфікація `ct_select_bytes`
```c
void ct_select_bytes(ct_choice_t c, uint8_t *dst, const uint8_t *src, size_t len);
```
- **Параметри:**
  - `c` — маска вибору (`CT_TRUE` або `CT_FALSE`);
  - `dst` — вказівник на буфер призначення (має бути доступний для запису `len` байтів);
  - `src` — вказівник на вихідний буфер (має бути доступний для читання `len` байтів);
  - `len` — кількість байтів для обробки.
- **Перед-умови:** Буфери `dst` та `src` не повинні перекриватися (non-overlapping). Вказівники `dst != NULL`, `src != NULL`.
- **Після-умови:** Якщо `c == CT_TRUE`, то `dst[0..len-1] == src[0..len-1]`. Якщо `c == CT_FALSE`, вміст `dst` залишається незмінним.
- **Гарантія безпеки:** Час виконання залежить виключно від довжини `len`. Доступ до пам'яті виконується лінійно без залежності від `c`.

### Специфікація `ct_cswap_bytes`
```c
void ct_cswap_bytes(ct_choice_t c, void *a, void *b, size_t len);
```
- **Параметри:** `c` — маска вибору; `a`, `b` — вказівники на буфери довжиною `len`.
- **Перед-умови:** `a != NULL`, `b != NULL`, області пам'яті не перекриваються.
- **Після-умови:** Якщо `c == CT_TRUE`, вміст областей `a` та `b` взаємно обмінюється. Якщо `c == CT_FALSE`, стан пам'яті не змінюється.
- **Гарантія безпеки:** Кількість операцій читання та запису в пам'ять абсолютно однакова для `c == CT_TRUE` та `c == CT_FALSE`.

## 5. Порівняння пам'яті та криптографічна верифікація

Функції порівняння забезпечують перевірку ідентичності буферів без дострокового виходу.

### 5.1 `ct_memequal`
```c
ct_choice_t ct_memequal(const void *a, const void *b, size_t len);
```
- **Призначення:** Безпечна перевірка рівності двох криптографічних об'єктів (хеш-тегів HMAC, відкритих ключів, підписів).
- **Параметри:** `a`, `b` — вказівники на порівнювані блоки; `len` — розмір у байтах.
- **Повертає:** `CT_TRUE`, якщо всі `len` байтів повністю ідентичні; `CT_FALSE`, якщо є хоча б один відмінний біт.
- **Часова складність:** Строго `O(len)` операцій, незалежно від позиції першого неспівпалого байта.

### 5.2 `ct_memcmp_lex`
```c
int ct_memcmp_lex(const void *a, const void *b, size_t len);
```
- **Призначення:** Лексикографічне порівняння двох блоків пам'яті в постійному часі (потрібне для канонічного впорядкування ключів у протоколах консенсусу та підписах).
- **Повертає:** 
  - `-1`, якщо блок `a` лексикографічно менший за `b`;
  - `0`, якщо блоки `a` та `b` повністю ідентичні;
  - `+1`, якщо блок `a` лексикографічно більший за `b`.
- **Механізм:** Здійснює повний прохід по всіх байтах від кінця до початку або використовує побітову акумуляцію першої різниці без переривання циклу.

## 6. Безпечні табличні вибірки (Table Lookup)

Функції вибірки замінюють небезпечне пряме звернення до пам'яті `table[secret_idx]` на повне лінійне сканування, ізолюючи кеш процесора від секретного індексу.

```c
/* Вибірка 8-бітного байта з таблиці довільного розміру */
uint8_t ct_lookup_u8(const uint8_t *table, size_t table_len, size_t secret_idx);

/* Вибірка 32-бітного слова з масиву */
uint32_t ct_lookup_u32(const uint32_t *table, size_t table_len, size_t secret_idx);

/* Вибірка 64-бітного слова з масиву */
uint64_t ct_lookup_u64(const uint64_t *table, size_t table_len, size_t secret_idx);

/* Копіювання елемента довільного фіксованого розміру elem_size з масиву */
void ct_lookup_element(void *dst, const void *table, size_t num_elems, size_t elem_size, size_t secret_idx);
```

### Інваріанти безпеки табличної вибірки:
1. Функція зчитує кожен елемент масиву `table[0..table_len-1]` рівно один раз у строго послідовному порядку адрес.
2. Якщо `secret_idx >= table_len`, поведінка детермінована: функція повертає нульовий результат без аварійного завершення та витоку інформації.
3. Послідовність звернень до ліній кешу є публічною і повністю незалежною від значення `secret_idx`.

## 7. Багаторозрядна арифметика постійного часу (Big-Integer API)

Для реалізації асиметричної криптографії (RSA, криві Едвардса Ed25519, криві Вейєрштрасса secp256k1) інтерфейс надає структури та примітиви 256-бітної та 384-бітної арифметики.

### 7.1 Типи багаторозрядних чисел
```c
typedef struct {
    uint64_t limbs[4]; /* 4 x 64 = 256 бітів */
} ct_bn256_t;

typedef struct {
    uint64_t limbs[6]; /* 6 x 64 = 384 біти */
} ct_bn384_t;
```

### 7.2 Арифметичні функції
```c
/* Додавання двох 256-бітних чисел із поверненням біта перенесення */
uint64_t ct_bn256_add(ct_bn256_t *r, const ct_bn256_t *a, const ct_bn256_t *b);

/* Віднімання двох 256-бітних чисел із поверненням біта позики */
uint64_t ct_bn256_sub(ct_bn256_t *r, const ct_bn256_t *a, const ct_bn256_t *b);

/* Модульне додавання r = (a + b) mod p */
void ct_bn256_mod_add(ct_bn256_t *r, const ct_bn256_t *a, const ct_bn256_t *b, const ct_bn256_t *p);

/* Модульне віднімання r = (a - b) mod p */
void ct_bn256_mod_sub(ct_bn256_t *r, const ct_bn256_t *a, const ct_bn256_t *b, const ct_bn256_t *p);

/* Умовний вибір 256-бітного числа */
void ct_bn256_select(ct_choice_t c, ct_bn256_t *r, const ct_bn256_t *a, const ct_bn256_t *b);

/* Умовна перестановка двох 256-бітних чисел */
void ct_bn256_cswap(ct_choice_t c, ct_bn256_t *a, ct_bn256_t *b);
```

### Інваріанти модульної арифметики:
- Усі операції модульного додавання та віднімання гарантують, що результат `r < p`, за умови що вхідні операнди `a < p` та `b < p`.
- Фінальна редукція виконується за допомогою віднімання модуля під побітовою маскою без умовних операторів `if (r >= p)`.

## 8. Операції на еліптичних кривих та скалярне множення (ECC API)

Для запобігання атакам SPA/DPA на алгоритми ECDSA, Ed25519 та протокол Діффі-Геллмана на еліптичних кривих (ECDH) модуль надає постійночасовий інтерфейс групових операцій.

### 8.1 Структура точки в проективних координатах
```c
typedef struct {
    ct_bn256_t X;
    ct_bn256_t Y;
    ct_bn256_t Z;
} ct_ec_point256_t;
```

### 8.2 Функції скалярного множення та рандомізації координат
```c
/* Скалярне множення точки R = scalar * P за постійний час (Montgomery ladder / Fixed-window) */
int ct_ec256_scalarmult(ct_ec_point256_t *r, const uint8_t *scalar, size_t scalar_len, const ct_ec_point256_t *p);

/* Рандомізація проективних координат (Z-blinding): (X : Y : Z) -> (lambda * X : lambda * Y : lambda * Z) */
int ct_ec256_point_blind(ct_ec_point256_t *p, const uint8_t *random_scalar32);

/* Перевірка, чи є точка нейтральним елементом (точкою на нескінченності) */
ct_choice_t ct_ec256_is_infinity(const ct_ec_point256_t *p);
```

### Контракт Z-blinding:
Рандомізація координат множить проективні компоненти на випадкове ненульове число `lambda ∈ GF(p)`. Оскільки геометрична точка на еліптичній кривій не змінюється, проміжні обчислювальні значення в кожному раунді множення стають випадковими і повністю некорельованими зі споживанням потужності, захищаючи чіп від атак CPA.

## 9. Поліноміальна алгебра постквантових схем (PQC Lattice API)

Алгоритми постквантової криптографії на ґратках (Kyber / ML-KEM, Dilithium / ML-DSA, Falcon) оперують поліномами над кільцями `R_q = Z_q[X]/(X^n + 1)`. Наївне відхиляюче вибіркове декодування (Rejection Sampling) та нерегулярні цикли призводять до витоку інформації про секретні коефіцієнти.

### 9.1 Типи поліномів
```c
#define CT_PQC_POLY_DEGREE 256

typedef struct {
    int16_t coeffs[CT_PQC_POLY_DEGREE]; /* 256 коефіцієнтів у кільці Z_q */
} ct_pqc_poly256_t;
```

### 9.2 Функції теоретико-числового перетворення та вибірки
```c
/* Постійночасове пряме теоретико-числове перетворення (NTT) */
void ct_poly_ntt(ct_pqc_poly256_t *p, const int16_t *zetas_table, int16_t q);

/* Постійночасове обернене теоретико-числове перетворення (InvNTT) */
void ct_poly_invntt(ct_pqc_poly256_t *p, const int16_t *zetas_inv_table, int16_t q);

/* Поточкове множення двох поліномів у просторі NTT */
void ct_poly_basemul(ct_pqc_poly256_t *r, const ct_pqc_poly256_t *a, const ct_pqc_poly256_t *b, int16_t q);

/* Постійночасове зведення за модулем q за алгоритмом Барретта/Монтгомері */
void ct_poly_reduce_coefficients(ct_pqc_poly256_t *p, int16_t q);
```

### Контракт NTT-обчислень:
Усі метеликові операції (Cooley-Tukey та Gentleman-Sande) виконуються з використанням константних таблиць твідових множників `zetas_table` за строго фіксовану кількість тактів без залежності від нульових коефіцієнтів.

## 10. Безпечне перетворення форматів (Constant-Time Hex та Base64)

Парсинг та експорт ключів у текстові формати (HEX-рядки, PEM, Base64) у стандартних бібліотеках виконується через таблиці символів або каскади розгалужень `if (c >= '0' && c <= '9')`, що створює витік секретних байтів через BPU та кеш.

Модуль надає безпечні безтабличні конвертери:

```c
/* Безпечне перетворення байта в два шістнадцяткові символи */
void ct_bin_to_hex(char *dst_hex, const uint8_t *src_bin, size_t bin_len);

/* Безпечний парсинг шістнадцяткового рядка в двійкові байти */
ct_choice_t ct_hex_to_bin(uint8_t *dst_bin, const char *src_hex, size_t hex_len);

/* Безпечне декодування символу Base64 без звернення до таблиць пам'яті */
uint8_t ct_base64_decode_char(char c, ct_choice_t *is_valid);
```

### Контракт шістнадцяткового декодування:
- Функція `ct_hex_to_bin` обробляє абсолютно всі символи рядка без дострокового виходу при некоректних символах.
- Якщо рядок містить заборонені символи, функція повертає `CT_FALSE`, а вихідний буфер заповнюється нулями в постійному часі.

## 11. Керування безпечним криптографічним контекстом (Context API)

Для координації обчислювальних ресурсів, керування захищеними областями пам'яті та налаштування політик захисту бібліотека надає структуру контексту `ct_context_t`.

```c
typedef enum {
    CT_FLAG_NONE             = 0x00,
    CT_FLAG_SECURE_WIPE      = 0x01, /* Автоматичне занулення буферів при звільненні */
    CT_FLAG_LOCK_PAGES       = 0x02, /* Фіксація пам'яті в RAM (mlock) */
    CT_FLAG_DISABLE_COREDUMP = 0x04, /* Заборона створення дампів пам'яті процесу */
    CT_FLAG_BARRIER_STRICT   = 0x08  /* Примусова вставка асемблерних бар'єрів */
} ct_context_flags_t;

typedef struct {
    ct_context_flags_t flags;
    ct_rng_fn custom_rng;
    void *user_data;
} ct_context_t;

/* Ініціалізація криптографічного контексту */
int ct_context_init(ct_context_t *ctx, ct_context_flags_t flags, ct_rng_fn rng);

/* Звільнення ресурсів та деактивація контексту */
void ct_context_destroy(ct_context_t *ctx);

/* Виділення пам'яті з охоронними сторінками (Guard Pages) */
void *ct_alloc_guarded(ct_context_t *ctx, size_t size);

/* Звільнення захищеної пам'яті з гарантованим зануленням */
void ct_free_guarded(ct_context_t *ctx, void *ptr, size_t size);
```

### Контракт охоронних сторінок (Guard Pages):
Функція `ct_alloc_guarded` оточує виділений буфер пам'яті двома недоступними сторінками пам'яті зі статусом `PROT_NONE`. Будь-яка спроба переповнення або недоповнення буфера (Buffer Overflow/Underflow) викликає негайне апаратне переривання `SIGSEGV`, запобігаючи несанкціонованому зчитуванню сусідніх криптографічних ключів у купі.

## 12. Програмний інтерфейс маскування часток (Masking API)

Для побудови алгоритмів із захистом вищих порядків (ISW probing security) інтерфейс надає структури та оператори розділення секретів на `d + 1` часток.

### 12.1 Типи замаскованих змінних
```c
#define CT_MAX_MASKING_SHARES 8

typedef struct {
    uint8_t shares[CT_MAX_MASKING_SHARES];
    size_t order; /* Порядок маскування d (кількість часток = d + 1) */
} ct_masked_byte_t;

typedef struct {
    uint32_t shares[CT_MAX_MASKING_SHARES];
    size_t order;
} ct_masked_word32_t;
```

### 12.2 Функції маскування та відновлення
```c
/* Створення замаскованого представлення секретного байта */
int ct_mask_byte_create(ct_masked_byte_t *dst, uint8_t secret, size_t order, ct_rng_fn rng);

/* Відновлення відкритого байта з часток: secret = share_0 ^ share_1 ^ ... ^ share_d */
uint8_t ct_mask_byte_reconstruct(const ct_masked_byte_t *src);

/* Безпечне почасткове додавання за модулем 2 (XOR): z = x ^ y */
void ct_mask_byte_xor(ct_masked_byte_t *z, const ct_masked_byte_t *x, const ct_masked_byte_t *y);

/* Безпечне нелінійне множення ISW: z = x & y */
int ct_mask_byte_and_isw(ct_masked_byte_t *z, const ct_masked_byte_t *x, const ct_masked_byte_t *y, ct_rng_fn rng);
```

### Контракт гаджета множення ISW:
- Функція `ct_mask_byte_and_isw` вимагає передачі свіжої ентропії через `rng` обсягом `d * (d + 1) / 2` випадкових байтів.
- Внутрішній конвеєр гарантує математичну стійкість у моделі `d`-зондового супротивника.

## 13. Програмний інтерфейс TVLA-тестування витоків (Leakage Detection API)

Для автоматизованої перевірки відсутності витоків у модульних тестах бібліотека надає стандартизований інтерфейс статистичного аналізу за критерієм Велча (TVLA).

```c
typedef struct {
    double mean_fixed;
    double m2_fixed;
    uint64_t count_fixed;
    double mean_random;
    double m2_random;
    uint64_t count_random;
} ct_tvla_accumulator_t;

/* Ініціалізація структури статистичного збору */
void ct_tvla_init(ct_tvla_accumulator_t *acc);

/* Додавання вимірювання до вибірки (is_fixed == true для фіксованого класу) */
void ct_tvla_feed(ct_tvla_accumulator_t *acc, bool is_fixed, double metric_val);

/* Обчислення підсумкового значення статистики t-критерію Велча */
double ct_tvla_compute_t(const ct_tvla_accumulator_t *acc);

/* Перевірка, чи не перевищує статистика критичний поріг (дефолтний поріг 4.5) */
bool ct_tvla_is_leakage_free(const ct_tvla_accumulator_t *acc, double threshold);
```

### Інтерпретація результатів TVLA:
- Якщо `ct_tvla_compute_t(acc)` повертає значення за абсолютною величиною `|t| <= 4.5`, гіпотеза про відсутність витоку приймається.
- Якщо `|t| > 4.5`, тестовий стенд формує детальний звіт про витік інформації з рівнем значущості `p < 0.00001`.

## 14. Апаратне прискорення та векторні інструкції

Сучасні мікропроцесорні архітектури містять апаратні інструкції, які виконують криптографічні перетворення безпосередньо у векторних регістрах АЛП без використання таблиць у пам'яті.

### 14.1 Інструкції AES-NI (x86_64)
Інструкції `_mm_aesenc_si128` та `_mm_aesdec_si128` виконують раунд AES за фіксовані 4–7 тактів усередині кремнієвого конвеєра:
```c
/* Безпечний раунд AES на процесорах x86 із підтримкою AES-NI */
#if defined(__AES__)
#include <wmmintrin.h>
static inline __m128i ct_aes_round_ni(__m128i state, __m128i round_key) {
    return _mm_aesenc_si128(state, round_key);
}
#endif
```

### 14.2 Векторні перестановки AVX2 / NEON
Для алгоритмів без апаратного блоку AES бібліотека використовує векторні перестановки `_mm256_shuffle_epi8` або `vtbl1_u8`, які виконують одночасну паралельну вибірку 32 байтів за 1 такт процесора.

## 15. Керування пам'яттю, занулення та захист сторінок

Криптографічні секрети не повинні залишатися у стеку, неініціалізованих купах або скидатися операційною системою у файл підкачки (Swap).

### 15.1 `ct_cleanse` / `ct_explicit_bzero`
```c
void ct_cleanse(void *ptr, size_t len);
```
- **Призначення:** Безпечне занулення чутливих даних у пам'яті (ключі, паролі, проміжні змінні).
- **Гарантія компілятора:** Функція захищена від оптимізації видалення мертвого збереження (Dead Store Elimination). Компілятор не має права пропустити очищення пам'яті, навіть якщо блок пам'яті звільняється або виходить з області видимості негайно після виклику.
- **Платформна реалізація:** Використовує `explicit_bzero` (POSIX), `memset_s` (C11 Annex K), `SecureZeroMemory` (Windows) або власну реалізацію з `volatile`-вказівниками та бар'єрами пам'яті.

### 15.2 Блокування сторінок у фізичній пам'яті (`ct_mlock` / `ct_munlock`)
```c
int ct_mlock(void *addr, size_t len);
int ct_munlock(void *addr, size_t len);
```
- **Призначення:** Фіксація сторінок пам'яті в фізичному ОЗП (RAM) для запобігання їх запису на жорсткий диск або SSD через механізм свопінгу (Swap/Paging).
- **Повертає:** `0` у разі успіху, або від'ємний код помилки (`-1`), якщо перевищено ліміт привілеїв ОС (`RLIMIT_MEMLOCK`).

## 16. Інструментація динамічного аналізу та Taint-контролю

Для інтеграції з динамічними валідаторами безпеки (Valgrind CTgrind, AddressSanitizer, MemorySanitizer) надаються спеціальні макроси розмітки пам'яті.

```c
/* Позначення пам'яті як секретної (отруєної) */
void ct_poison(const void *ptr, size_t len);

/* Розсекречення пам'яті для публічного використання */
void ct_unpoison(const void *ptr, size_t len);

/* Явне розсекречення одного предикату вибору */
void ct_declassify_choice(ct_choice_t *c);
```

### Правила використання Taint-макросів у тестах:
1. Одразу після генерації або імпорту секретного ключа викликається `ct_poison(key, key_len)`.
2. Будь-яке проміжне значення, обчислене на основі `key`, автоматично успадковує статус «отруєного».
3. Якщо код містить пряме розгалуження `if (secret)` або табличний індекс `table[secret]`, Valgrind негайно завершує виконання з помилкою.
4. Після перевірки підпису кінцевий булевий прапорець статусу перевірки явно очищується викликом `ct_declassify_choice(&is_valid)`.

## 17. Багатопотокова безпека та асинхронні сигнали

Усі функції бібліотеки `libctcrypto`, які не модифікують глобальний контекст і оперують виключно переданими буферами пам'яті, є реентерабельними (Reentrant) та потокобезпечними (Thread-Safe) без необхідності використання примітивів блокування (м'ютексів). 

Оскільки м'ютекси створюють варіації часу очікування та контеншн-ефекти в планувальнику потоків ядра операційної системи, використання замків усередині постійночасових контурів суворо заборонено.

Обробники асинхронних сигналів ОС (Signal Handlers) мають право викликати виключно `ct_cleanse` та `ct_explicit_bzero` для аварійного стирання секретів під час переривання процесу.
