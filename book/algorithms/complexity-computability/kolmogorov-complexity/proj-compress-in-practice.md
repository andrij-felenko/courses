# ⚙️ Практичне обчислення складності та метрики NCD

Оцінка алгоритмічної складності за Колмогоровим на практиці здійснюється через реальні алгоритми стиснення даних та розрахунок нормалізованої стиснювальної відстані (Normalized Compression Distance, NCD) мовами C та C++.

## Від абстрактної обчислюваності до практичних компресорів

Теоретична складність за Колмогоровим `K(x)` заснована на універсальній машині Тюринга `𝒰` і є необчислювальною функцією через проблему зупинки. Жодна програма не може за скінченний час знайти абсолютно найкоротшу програму генерації для довільного бінарного рядка. Проте для інженерних та дослідницьких задач це не є безвиходістю.

У практичному програмуванні замість гіпотетичної універсальної машини Тюринга використовують реальні алгоритми та бібліотеки стиснення даних загального призначення: `zlib` (алгоритм Deflate, що поєднує LZ77 та кодування Хаффмана), `bzip2` (перетворення Барроуза–Вілера та кодування Move-To-Front), `liblzma` (алгоритм LZMA2 з велетенським словником) або `zstd` (Zstandard, що використовує скінченні автомати FSE).

Якщо компресор `C` є нормалізованим (тобто задовольняє вимогам симетрії, монотонності та логарифмічної точності), розмір стисненого файла `C(x)` (виражений у бітах або байтах) слугує практичною нижньою оцінкою зверху для теоретичної складності за Колмогоровим:

```
K(x) ≤ C(x) + O(1)
```

Чим потужніший компресор і чим більше закономірностей він здатен знайти у вхідному потоці, тим ближче `C(x)` підходить до теоретичного межі `K(x)`.

## Механізм нормалізованої стиснювальної відстані (NCD)

На основі оцінки `K(x) ≈ C(x)` Пауль Вітаньї та Руді Сіладі запропонували метрику нормалізованої стиснювальної відстані (Normalized Compression Distance, NCD). Вони довели, що NCD є практичним наближенням до теоретичної універсальної інформаційної відстані (Universal Information Distance).

Нормалізована стиснювальна відстань між двома об'єктами `x` та `y` визначається формулою:

```
NCD(x, y) = ( C(xy) - min( C(x), C(y) ) ) / max( C(x), C(y) )
```

де:
- `C(x)` — розмір стисненого об'єкта `x`;
- `C(y)` — розмір стисненого об'єкта `y`;
- `C(xy)` — розмір стисненої конкатенації рядків `x` та `y` (тобто бінарного буфера, утвореного зчепленням `x` з `y`).

### Чому ця формула працює: аналіз трьох граничних випадків

1. **Ідентичні або алгоритмічно еквівалентні об'єкти (`x = y`):**
   При стисненні конкатенації `xx` словниковий компресор (наприклад, LZ77) запам'ятовує всі послідовності першої половини `x`. При переході до другої половини компресор не кодує нові символи, а видає короткі посилання (зсув, довжина) на вже наявний у словнику текст `x`. Тому `C(xx) ≈ C(x)`. Підставляючи це у формулу, отримуємо:
   `NCD(x, x) = (C(x) - C(x)) / C(x) = 0`.
   Відстань дорівнює нулю, що відповідає повній алгоритмічній тотожності.

2. **Об'єкти зі спільними закономірностями (частковий перекрит):**
   Якщо `x` та `y` є різними версіями того самого сирцевого файлу або фрагментами ДНК одного біологічного виду, частина шаблонів з `x` повторюється у `y`. Компресор використовує інформацію з `x` для стиснення `y`, тому розмір конкатенації `C(xy)` виявляється значно меншим за суму `C(x) + C(y)`. У результаті `NCD(x, y)` набуває значень у діапазоні від `0.1` до `0.4`.

3. **Абсолютно незалежні об'єкти (немає спільних шаблонів):**
   Якщо `x` — це скомпільований бінарний файл для архітектури ARM, а `y` — це текст українською мовою, компресор не може використати жоден фрагмент `x` для покращення стиснення `y`. Розмір стисненої конкатенації дорівнює сумі окремо стиснених частин: `C(xy) ≈ C(x) + C(y)`.
   Підставляючи це у формулу при припущенні `C(x) ≥ C(y)`:
   `NCD(x, y) = ((C(x) + C(y)) - C(y)) / C(x) = C(x) / C(x) = 1`.
   Відстань прямує до одиниці, засвідчуючи повну алгоритмічну незалежність.

## Програмна реалізація NCD

Нижче наведено ідіоматичні реалізації модуля обчислення NCD мовами C та C++. Для самодостатності прикладу в якості компресора використано алгоритм Run-Length Encoding (RLE) із словниковим вікном, що дозволяє запустити код без зовнішніх залежностей.

:::tabs
```c
/* ncd_calculator.c — Обчислення NCD мовою C */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>

/* Проста реалізація стиснення методом Run-Length Encoding (RLE)
   для демонстрації оцінки розміру C(x).
   У виробничих системах використовується zlib або liblzma. */
size_t compress_rle_size(const uint8_t *data, size_t len) {
    if (len == 0) return 0;
    size_t compressed_len = 0;
    size_t i = 0;
    
    while (i < len) {
        uint8_t run_byte = data[i];
        size_t run_len = 1;
        while (i + run_len < len && data[i + run_len] == run_byte && run_len < 255) {
            run_len++;
        }
        compressed_len += 2; /* 1 байт лічильника + 1 байт значення */
        i += run_len;
    }
    return compressed_len;
}

/* Обчислення NCD для двох бінарних буферів */
double compute_ncd_c(const uint8_t *x, size_t len_x,
                     const uint8_t *y, size_t len_y) {
    size_t cx = compress_rle_size(x, len_x);
    size_t cy = compress_rle_size(y, len_y);
    
    /* Конкатенація x та y */
    size_t len_xy = len_x + len_y;
    uint8_t *xy = (uint8_t *)malloc(len_xy);
    if (!xy) {
        return -1.0; /* Помилка виділення пам'яті */
    }
    memcpy(xy, x, len_x);
    memcpy(xy + len_x, y, len_y);
    
    size_t cxy = compress_rle_size(xy, len_xy);
    free(xy);
    
    size_t min_c = (cx < cy) ? cx : cy;
    size_t max_c = (cx > cy) ? cx : cy;
    
    if (max_c == 0) return 0.0;
    
    double ncd = (double)(cxy - min_c) / (double)max_c;
    return (ncd < 0.0) ? 0.0 : ((ncd > 1.0) ? 1.0 : ncd);
}

int main(void) {
    const char *text1 = "AAAAABBBBBCCCCCDDDDDAAAAABBBBBCCCCCDDDDD";
    const char *text2 = "AAAAABBBBBCCCCCDDDDDAAAAABBBBBCCCCCDDDDE";
    const char *text3 = "XYZ1234567890QWERTYSDFGHJKLZXCVBNMUIOP12";

    double ncd_12 = compute_ncd_c((const uint8_t *)text1, strlen(text1),
                                  (const uint8_t *)text2, strlen(text2));
    double ncd_13 = compute_ncd_c((const uint8_t *)text1, strlen(text1),
                                  (const uint8_t *)text3, strlen(text3));

    printf("NCD(text1, text2) = %.4f (близькі тексти)\n", ncd_12);
    printf("NCD(text1, text3) = %.4f (різні тексти)\n", ncd_13);

    return 0;
}
```
```cpp
// ncd_calculator.cpp — Обчислення NCD мовою C++ (C++20, RAII, std::span)
#include <iostream>
#include <vector>
#include <string_view>
#include <span>
#include <algorithm>
#include <cstdint>
#include <stdexcept>

class NcdCalculator {
public:
    // Оцінка стисненого розміру на основі RLE/словникового аналізу
    static size_t compressed_size(std::span<const uint8_t> data) noexcept {
        if (data.empty()) return 0;
        size_t compressed_len = 0;
        size_t i = 0;
        
        while (i < data.size()) {
            uint8_t run_byte = data[i];
            size_t run_len = 1;
            while (i + run_len < data.size() && data[i + run_len] == run_byte && run_len < 255) {
                run_len++;
            }
            compressed_len += 2;
            i += run_len;
        }
        return compressed_len;
    }

    // Обчислення NCD між двома послідовностями байтів
    static double distance(std::span<const uint8_t> x, std::span<const uint8_t> y) {
        const size_t cx = compressed_size(x);
        const size_t cy = compressed_size(y);

        // RAII-буфер для конкатенації xy
        std::vector<uint8_t> xy;
        xy.reserve(x.size() + y.size());
        xy.insert(xy.end(), x.begin(), x.end());
        xy.insert(xy.end(), y.begin(), y.end());

        const size_t cxy = compressed_size(xy);

        const double min_c = static_cast<double>(std::min(cx, cy));
        const double max_c = static_cast<double>(std::max(cx, cy));

        if (max_c == 0.0) return 0.0;

        const double ncd = (static_cast<double>(cxy) - min_c) / max_c;
        return std::clamp(ncd, 0.0, 1.0);
    }
};

int main() {
    std::string_view text1 = "AAAAABBBBBCCCCCDDDDDAAAAABBBBBCCCCCDDDDD";
    std::string_view text2 = "AAAAABBBBBCCCCCDDDDDAAAAABBBBBCCCCCDDDDE";
    std::string_view text3 = "XYZ1234567890QWERTYSDFGHJKLZXCVBNMUIOP12";

    auto span1 = std::span<const uint8_t>(reinterpret_cast<const uint8_t*>(text1.data()), text1.size());
    auto span2 = std::span<const uint8_t>(reinterpret_cast<const uint8_t*>(text2.data()), text2.size());
    auto span3 = std::span<const uint8_t>(reinterpret_cast<const uint8_t*>(text3.data()), text3.size());

    double ncd_12 = NcdCalculator::distance(span1, span2);
    double ncd_13 = NcdCalculator::distance(span1, span3);

    std::cout << "NCD(text1, text2) = " << ncd_12 << " (близькі тексти)\n";
    std::cout << "NCD(text1, text3) = " << ncd_13 << " (різні тексти)\n";

    return 0;
}
```

## Оптимізація та інженерні пастки при роботі з NCD

При практичному розрахунку NCD на великих обсягах даних (наприклад, при побудові матриці відстаней `N × N` для тисяч файлів) розробник спотикається об кілька підступних інженерних обмежень.

### 1. Переповнення словникового вікна (Sliding Window Overflow)
Більшість реальних компресорів мають фіксований розмір словника. Наприклад, класичний `zlib` (Deflate) використовує ковзне вікно розміром 32 КБ. Якщо розмір файлу `x` перевищує 32 КБ (скажімо, `|x| = 10` МБ), компресор при стисненні конкатенації `xy` повністю витіснить початкові байти `x` зі свого словника до того часу, як дійде до кодування `y`.
- **Наслідок:** Компресор «забуде» початок `x` і не зможе використати його для стиснення `y`. Розрахована `NCD(x, y)` штучно наблизиться до 1.0, навіть якщо файли ідентичні.
- **Рішення:** Для великих файлів обов'язково використовувати компресори з великим вікном (наприклад, `zstd` з вікном до 128 МБ або `liblzma` з вікном до 1 ГБ) або проводити блочне розбиття даних.

### 2. Заголовок компресора та похибка для малих даних (Header Overhead)
Кожен стиснений файл містить метадані: заголовок формату (magic bytes, прапори), опис дерева Хаффмана та контрольне число (CRC32/Adler32). Для малих рядків (наприклад, `|x| = 10` байтів) заголовок розміром 20–50 байтів може перевищувати розмір самих даних.
- **Наслідок:** Малі ряди виглядають «нестиснюваними», а значення `C(xy)` викривляється додаванням заголовка.
- **Рішення:** Перед обчисленням `NCD` віднімають базовий розмір заголовка порожнього компресора `C(ε)` або використовують сирі компресійні стрими без контейнерних обгорток.

### 3. Асиметрія реальних компресорів
У теорії `C(xy) = C(yx)`. Проте в реальних реалізаціях через заздалегідь визначені стратегії пошуку зсувів у хеш-таблицях розмір `C(xy)` може на декілька байтів відрізнятися від `C(yx)`.
- **Рішення:** У критичних математичних застосуваннях використовують симетризоване значення конкатенації:
  `C_sym(x, y) = min( C(xy), C(yx) )`.

### 4. Асимптотична складність побудови матриці подібності
Для `N` об'єктів обчислення попарної матриці NCD вимагає `N(N - 1) / 2` викликів компресора. Якщо кожен виклик стискає 1 МБ даних, для `N = 1000` знадобиться стиснути близько 500 ГБ даних.
- **Оптимізація:** Оскільки кожен виклик `compute_ncd(x, y)` є повністю незалежним, обчислення матриці ідеально паралелиться за допомогою OpenMP або потокових пулів `std::async`. Заздалегідь обчислені й кешовані значення `C(x_i)` дозволяють уникнути повторного стиснення окремих об'єктів.
