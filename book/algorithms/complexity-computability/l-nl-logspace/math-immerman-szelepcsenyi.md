# 🧮 Теорема Іммермана-Сделепченей: доведення NL = coNL методом індуктивного підрахунку

Теорема Іммермана-Сделепченей (1987) є одним із найдивовижніших результатів теорії складності обчислень. Вона стверджує, що недетермінована логарифмічна пам'ять замкнена відносно доповнення:
```
NL = coNL
```

Це означає, що проблема перевірки **недосяжності** у графі (перевірити, що між початковою вершиною `s` та цільовою вершиною `t` **не існує** жодного орієнтованого шляху) вирішується недетермінованою машиною Тюринга з використанням робочої пам'яті `O(\log n)`.

Головний теоретичний бар'єр полягає у тому, що недетермінований алгоритм здатен легко підтверджувати наявність об'єкта (шляхом вгадування послідовності кроків), але для підтвердження **відсутності** об'єкта зазвичай потрібно перебрати всі варіанти. Збереження списку знайдених досяжних вершин вимагало б `O(n)` бітів пам'яті, що неприпустимо в `O(\log n)`.

Розв'язання даної суперечності полягає у **методі індуктивного підрахунку (Inductive Counting)**.

---

## 1. Формальне математичне визначення досяжних множин

Нехай `G = (V, E)` — орієнтований граф із `n = |V|` вершинами. Нехай `s, t ∈ V` — дві виділені вершини.

Визначимо послідовність множин `R_k ⊆ V` для `k = 0, 1, ..., n`:
- **`R_k`** — множина всіх вершин `v ∈ V`, до яких існує орієнтований шлях від `s` довжиною не більше ніж `k` ребер.
- **`r_k = |R_k|`** — кількість елементів у множині `R_k`.

Очевидні фундаментальні властивості:
1. `R_0 = {s}`, тому `r_0 = 1`.
2. Множини монотонно розширюються: `R_0 ⊆ R_1 ⊆ R_2 ⊆ ... ⊆ R_n ⊆ V`.
3. Розміри оцінюються як: `1 ≤ r_0 ≤ r_1 ≤ ... ≤ r_n ≤ n`.
4. Якщо між `s` та `t` існує шлях у `G`, то найкоротший простій шлях містить не більше `n-1` ребер. Отже, вершина `t` є недосяжною з `s` тоді й лише тоді, коли `t ∉ R_n`.

Математична проблема полягає у тому, що множина `R_k` може містити до `n` вершин. Якщо намагатися зберегти вектор бітів належності `[b₁, b₂, ..., bₙ]`, де `b_i = 1 ⇔ i ∈ R_k`, це вимагатиме точно `n` бітів пам'яті. У логарифмічній пам'яті `O(\log n)` у нас є лише `c · \log_2 n` бітів, що достатньо для зберігання лише сталої кількості чисел від `1` до `n`.

---

## 2. Основна ідея індуктивного обчислення розміру r_k

Колосальне відкриття Іммермана та Сделепченей полягає у тому, що недетермінований логарифмічний алгоритм може **обчислити точне значення `r_{k+1}`**, знаючи лише точне значення `r_k`.

При цьому алгоритму **не потрібно зберігати саму множину `R_k`** у пам'яті (що зайняло б `O(n)` бітів). Йому достатньо зберігати єдине число `r_k ∈ [1..n]`, яке займає лише `\lceil \log_2 n \rceil` бітів!

### Покроковий алгоритм обчислення r_{k+1} з r_k

Для обчислення `r_{k+1}` алгоритм послідовно перебирає всі вершини графа `v ∈ V` (від `1` до `n`) і перевіряє, чи належить `v` до `R_{k+1}`:

```
Обчислення r_{k+1} за відомим r_k:
1. Встановлюємо новий лічильник count_next = 0.
2. Для кожної вершини v ∈ V (від 1 до n):
    a. Недетерміновано перевіряємо, чи v ∈ R_{k+1}.
    b. Якщо так, збільшуємо count_next = count_next + 1.
3. Повертаємо r_{k+1} = count_next.
```

Ключовим елементом є **недетермінована процедура перевірки `v ∈ R_{k+1}`**, яка спирається на знання числа `r_k`.

---

## 3. Математична процедура недетермінованої перевірки належності v ∈ R_{k+1}

Для фіксованої вершини `v ∈ V` та відомого точного значення `r_k`, недетермінований процедурний модуль працює так:

```
Процедура TestReachable(v, r_k, k):
1. Встановлюємо лічильник підтверджених вершин: count_k = 0.
2. Встановлюємо прапорець досяжності: reached_v = ХИБНІСТЬ.
3. Для кожної вершини u ∈ V (від 1 до n):
    a. Недетерміновано вгадуємо, чи u ∈ R_k.
    b. Якщо вгадано «u ∈ R_k»:
        i.  Недетерміновано вгадуємо шлях від s до u довжиною ≤ k.
        ii. Перевіряємо шлях крок за кроком. Якщо шлях хибний, блокуємо гілку.
        iii.Якщо шлях вірний, підтверджуємо u ∈ R_k і робимо count_k = count_k + 1.
        iv. Перевіряємо, чи можна дістатися v з u:
            якщо (u == v) або (існує ребро (u, v) ∈ E), то reached_v = ІСТИНА.
4. Перевіряємо лічильник: якщо count_k != r_k, блокуємо гілку!
5. Повертаємо значення прапорця reached_v.
```

### Доведення коректності процедури та аналіз інваріантів
Чому цей алгоритм є математично строгим і чому недетермінований вибір не може призвести до хибнопозитивного розв'язку?

1. **Захист від несправжнього підтвердження (No False Positives):** Припустимо, гілка вгадує, що вершина `u ∈ R_k`. Алгоритм вимагає пред'явити послідовність вершин `s = w₀, w₁, ..., w_m = u` де `m ≤ k`. Оскільки на кожному кроці алгоритм перевіряє наявність реального ребра `(w_j, w_{j+1}) ∈ E` за вхідною стрічкою, неможливо фальсифікувати належність вершини `u` до `R_k`. Будь-яке фальшиве твердження негайно призведе до блокування даної гілки обчислення.
2. **Захист від пропуску вершин (No False Negatives):** Припустимо, гілка намагається «пропустити» деякі дійсні вершини з `R_k`, щоб спростити перевірку. Проте на кроці 4 алгоритм перевіряє умову `count_k == r_k`. Якщо гілка пропустила хоча б одну дійсно досяжну вершину, її лічильник знайдених вершин `count_k` виявиться строго меншим за `r_k`. В результаті така гілка буде негайно заблокована і не зробить внесок у фінальне прийняття рішення.
3. **Існування коректної гілки (Completeness):** Оскільки `r_k` дорівнює точній кількості вершин у `R_k`, обов'язково існує хоча б одна гілка недетермінованого вибору, яка правильно вгадає всі `r_k` вершин множини `R_k`, пред'явить для кожної з них дійсний шлях і правильно встановить значення прапорця `reached_v`.

Отже, недетермінований алгоритм за допомогою перевірки лічильника `count_k == r_k` перетворює недетерміноване вгадування на **гарантовано точну детерміновану відповідь**.

## 4. Конкретний числовий приклад обчислення на графах

Для наочності розглянемо граф з `n = 4` вершинами `V = {1, 2, 3, 4}`, де `s = 1`, `t = 4`, а ребра сформовані так: `E = {(1, 2), (2, 3)}`. Вершина `4` ізольована і недосяжна з `1`.

Трасування індуктивного підрахунку проходить такі етапи:

```
Крок k = 0:
  R₀ = {1}, r₀ = 1.

Крок k = 1 (обчислюємо r₁ з r₀ = 1):
  Перевіряємо v = 1: вгадуємо u = 1 ∈ R₀ (знайшли 1 вершину, count₀ = 1 = r₀). Оскільки u == v, reached_1 = ІСТИНА.
  Перевіряємо v = 2: вгадуємо u = 1 ∈ R₀ (count₀ = 1). Оскільки ребро (1, 2) ∈ E, reached_2 = ІСТИНА.
  Перевіряємо v = 3: вгадуємо u = 1 ∈ R₀ (count₀ = 1). Ребра (1, 3) немає, u ≠ v, reached_3 = ХИБНІСТЬ.
  Перевіряємо v = 4: вгадуємо u = 1 ∈ R₀ (count₀ = 1). Ребра (1, 4) немає, reached_4 = ХИБНІСТЬ.
  Підсумок: R₁ = {1, 2}, r₁ = 2.

Крок k = 2 (обчислюємо r₂ з r₁ = 2):
  Перевіряємо v = 3: вгадуємо u = 1 ∈ R₁ та u = 2 ∈ R₁ (знайшли 2 вершини, count₁ = 2 = r₁). 
  Для u = 2 існує ребро (2, 3) ∈ E, отже reached_3 = ІСТИНА.
  Перевіряємо v = 4: вгадуємо u = 1, 2 ∈ R₁ (count₁ = 2). Для жодної немає ребра в 4, reached_4 = ХИБНІСТЬ.
  Підсумок: R₂ = {1, 2, 3}, r₂ = 3.

Фінальна перевірка k = 4 (при r₄ = 3):
  Вгадуємо всі 3 досяжні вершини u = {1, 2, 3} ∈ R₄. 
  Перевіряємо, що жодна з них не дорівнює t = 4. 
  Успіх: підтверджено 4 ∉ R₄!
```

## 5. Підсумковий алгоритм підтвердження недосяжності (UNREACHABILITY)

Тепер сформулюємо повну недетерміновану процедуру підтвердження того, що `t ∉ R_n`:

```
Алгоритм ProofUnreachable(G, s, t):
1. Встановлюємо r_0 = 1 (оскільки R_0 = {s}).
2. Для k = 0 до n - 1:
    a. Обчислюємо r_{k+1} за вищенаведеним алгоритмом, використовуючи r_k.
    b. Оновлюємо r_k = r_{k+1}.
3. Тепер ми маємо точне значення r_n = |R_n|.
4. Встановлюємо лічильник count_n = 0.
5. Для кожної вершини u ∈ V (від 1 до n):
    a. Недетерміновано вгадуємо, чи u ∈ R_n.
    b. Якщо вгадано «u ∈ R_n»:
        i.  Перевіряємо досяжність u з s за ≤ n кроків.
        ii. Якщо перевірка успішна, count_n = count_n + 1.
        iii.Перевіряємо: якщо u == t, БЛОКУЄМО гілку! (бо t знайшовся в R_n).
6. Якщо count_n != r_n, БЛОКУЄМО гілку!
7. Приймаємо вхід: вершина t гарантовано НЕ належить до R_n!
```

## 6. Детальний розподіл реєстрів пам'яті та аналіз складності

Перевіримо точний розподіл змінних на робочій стрічці тристрічкової машини Тюринга для підтвердження дотримання обмеження `O(\log n)`.

Для виконання алгоритму на робочій стрічці створюється фіксований набір змінних (реєстрів):

1. **Реєстр довжини шляху `k`:** зберігає поточний крок індукції від `0` до `n`. Вимагає `\lceil \log_2 n \rceil` бітів.
2. **Реєстр `r_k`:** зберігає точну кількість вершин, досяжних за `k` кроків. Вимагає `\lceil \log_2 n \rceil` бітів.
3. **Реєстр `r_{k+1}`:** зберігає акумульоване значення розміру наступної множини. Вимагає `\lceil \log_2 n \rceil` бітів.
4. **Реєстр поточної перевіряємої вершини `v`:** номер вершини від `1` до `n`. Вимагає `\lceil \log_2 n \rceil` бітів.
5. **Реєстр підтверджуваної вершини `u`:** номер проміжної вершини під час перевірки. Вимагає `\lceil \log_2 n \rceil` бітів.
6. **Реєстр лічильника підтверджених вершин `count_k`:** кількість успішно підтверджених елементів `R_k`. Вимагає `\lceil \log_2 n \rceil` бітів.
7. **Реєстр поточної вершини пути `curr`:** використовується під час недетермінованої перевірки шляху від `s` до `u`. Вимагає `\lceil \log_2 n \rceil` бітів.
8. **Реєстр лічильника кроків пути `step_count`:** вимагає `\lceil \log_2 n \rceil` бітів.

Всі ці 8 змінних зберігаються у робочій пам'яті одночасно. Загальний просторовий розмір становить:
```
S(n) = 8 · \lceil \log_2 n \rceil = O(\log n)
```

Варто підкреслити різницю між просторовою складною теореми Іммермана-Сделепченей та теореми Савича:
- **Алгоритм Савича:** використовує детерміновану рекурсію ділення навпіл, вимагаючи `O(\log² n)` пам'яті та `O(n^{\log n})` часу.
- **Алгоритм Іммермана-Сделепченей:** використовує недетермінований індуктивний підрахунок, вимагаючи жорстко `O(\log n)` пам'яті та поліноміальний час `O(n⁴)` на підрахунок усіх переборів.

Це доводить, що задача підтвердження недосяжності належить до класу NL, а отже:
```
coNL ⊆ NL
```

Зважаючи на симетрію означень недетермінованої пам'яті, звідси негайно випливає тотожність:
```
NL = coNL
```

Цей елегантний результат показує, як за допомогою математичного інваріанта індуктивного підрахунку можна підтвердити відсутність об'єктів у недетермінованій пам'яті без зберігання списків відвіданих вершин.
