# 📋 Специфікація інтерфейсу бібліотеки парного кодування (Cantor Pairing API)

Бібліотека парного кодування та просторового індексування надає набір низькорівневих детермінованих функцій для взаємно однозначного відображення дискретних багатовимірних координат у скалярні цілочисельні індекси. Інтерфейс спроєктовано для використання у високонавантажених обчислювальних середовищах: рушіях обробки графів, базах даних з просторовим хешуванням, компіляторах, трансляторах та системах верифікації формальних моделей. Усі функції є реентерабельними (reentrant), не мають внутрішнього глобального або статичного стану, не виконують неявного виділення динамічної пам'яті на купі (`heap-free`) та забезпечують роботу виключно на цілочисельних регістрах процесора.

Нижче наведено повну структурну специфікацію інтерфейсу для мов C (стандарт C99/C11) та C++ (стандарт C++20), включно з типами даних, сигнатурами функцій, перед- та післяумовами, інваріантами, гарантіями часової складності, конвенціями передачі параметрів на рівні ABI, формальними контрактами верифікації, протоколами мережевої серіалізації, аксіоматизацією для SMT-солверів, архітектурою спільної пам'яті IPC, роботою в операційних системах реального часу RTOS, векторними розширеннями SIMD/SVE, міжмовними зв'язками FFI, правилами безпеки MISRA C та детальним описом кодів помилок.

### 1. Заголовні файли, простори імен та конвенції зв'язування

Бібліотека поширюється у вигляді двох заголовних файлів, оптимізованих під відповідні мовні стандарти:

| Мова | Заголовний файл | Простір імен / Префікс | Вимоги стандарту | Конвенція зв'язування |

| **C** | `<cantor_pairing.h>` | Префікс `cantor_` | ISO/IEC 9899:1999 (C99) | `extern "C"` (C linkage) |

### 2. Типи даних, структури та концептуальні обмеження

Для забезпечення максимальної переносимості між 32-бітними та 64-бітними архітектурами всі типи спираються на стандартні фіксовані розміри з `<stdint.h>` та концептуальні обмеження C++20 Concepts.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

/* Коди завершення та статуси виконання операцій */
typedef enum {
    CANTOR_SUCCESS           =  0, /* Операцію виконано успішно без помилок */
    CANTOR_ERR_NULL_POINTER  = -1, /* Передано нульовий покажчик для вихідних даних */
    CANTOR_ERR_OVERFLOW      = -2, /* Арифметичне переповнення цілочисельної розрядної сітки */
    CANTOR_ERR_INVALID_DIM   = -3  /* Некоректна розмірність кортежу (k == 0 або k > MAX_DIM) */

/* Двовимірна пара 32-бітних невід'ємних координат (ℕ₀ × ℕ₀) */
typedef struct {
    uint32_t x; /* Горизонтальна координата точки */
    uint32_t y; /* Вертикальна координата точки (зсув всередині діагоналі) */
} cantor_pair32_t;

/* Двовимірна пара 64-бітних невід'ємних координат */
typedef struct {
    uint64_t x;

} cantor_pair64_t;

/* Двовимірна пара 32-бітних знакових цілих чисел для простору ℤ × ℤ */
typedef struct {
    int32_t x;  /* Знакова координата x */
    int32_t y;  /* Знакова координата y */
} cantor_signed_pair32_t;
```

```cpp
#include <cstdint>
#include <optional>
#include <vector>
#include <span>
#include <concepts>
#include <type_traits>

namespace pairing {

/* Поняття для перевірки цілочисельних беззнакових типів */
template<typename T>
concept UnsignedIntegral = std::is_unsigned_v<T> && std::integral<T>;

/* Поняття для перевірки цілочисельних знакових типів */
```

### 3. Специфікація функцій двовимірного спарювання Кантора (2D API)

#### 3.1. Функція прямого кодування: `cantor_encode32` / `cantor_encode`

##### Сигнатури
- **C (C99):** `cantor_status_t cantor_encode32(uint32_t x, uint32_t y, uint64_t *out_code);`
- **C++ (C++20):** `[[nodiscard]] constexpr std::optional<uint64_t> cantor_encode(uint32_t x, uint32_t y) noexcept;`

##### Детальний опис та призначення
Функція обчислює скалярний індекс Кантора `z = π(x, y)` за аналітичною формулою діагонального обходу:
```
w = x + y
z = ((w · (w + 1)) / 2) + y
```
Функція здійснює взаємно однозначне перетворення точки дискретної площини `(x, y)` у єдине натуральне число `z`. Результат кодування є компактним числовим значенням без виникнення порожніх проміжків (бієкція на множину `ℕ₀`).

##### Параметри
- `x` [вхідний]: перша координата точки на площині (ціле невід'ємне число `uint32_t`).
- `y` [вхідний]: друга координата точки на площині (ціле невід'ємне число `uint32_t`).
- `out_code` [вихідний у версії C]: покажчик на попередньо виділену змінну типу `uint64_t`, куди записується згенерований скалярний індекс.

##### Перед- та післяумови (Contracts)
- **Предумова 1:** У версії для C покажчик `out_code` не повинен дорівнювати `NULL`.
- **Предумова 2:** Сума вхідних координат `x + y` не повинна перевищувати критичний арифметичний поріг `6 074 000 999` (`6.074 × 10⁹`). Якщо `x + y > 6074000999ULL`, значення `(w · (w + 1)) / 2` переповнює 64-бітну розрядну сітку `uint64_t`.
- **Постумова:** При успішному завершенні гарантується рівність `π⁻¹(z) = (x, y)`.

##### Повернені значення
- **У мові C:**
  - `CANTOR_SUCCESS (0)`: кодування успішно виконано, вихідна змінна `*out_code` містить валідний індекс Кантора.
  - `CANTOR_ERR_NULL_POINTER (-1)`: передано недійсний нульовий покажчик `out_code == NULL`.
  - `CANTOR_ERR_OVERFLOW (-2)`: сума `x + y` перевищує допустимий ліміт переповнення.
- **У мові C++:**
  - Повертає `std::optional<uint64_t>`, який містить 64-бітне ціле число при успіху або `std::nullopt` у разі виникнення переповнення розрядності.

##### Обчислювальна складність та апаратні ресурси
- **Часова складність:** `O(1)` — строго детермінований час виконання, що становить 3 машинних інструкції ALU (одне додавання, одне множення, один логічний зсув праворуч). Латентність на процесорах x86-64 становить 3–4 такти.
- **Просторова складність:** `O(1)` — 0 байтів додаткової пам'яті на стеку та купі.
- **Винятки:** Гарантія `noexcept` (винятки принципово не генеруються).

#### 3.2. Функція аналітичного декодування: `cantor_decode32` / `cantor_decode`

##### Сигнатури
- **C (C99):** `cantor_status_t cantor_decode32(uint64_t code, cantor_pair32_t *out_pair);`
- **C++ (C++20):** `[[nodiscard]] constexpr std::optional<Pair32> cantor_decode(uint64_t code) noexcept;`

##### Детальний опис та призначення
Здійснює точне відновлення координат початкової пари `(x, y)` за заданим числовим індексом `code = z`. Алгоритм спирається на точне цілочисельне добування квадратного кореня дискримінанта:
```
1. disc = 8 · code + 1
2. s = ⌊ √disc ⌋  (через точний цілочисельний алгоритм isqrt)
3. w = ⌊ (s - 1) / 2 ⌋
4. base = (w · (w + 1)) / 2
5. y = code - base
6. x = w - y
```

##### Параметри
- `code` [вхідний]: скалярний 64-бітний індекс Кантора `z ∈ ℕ₀`.
- `out_pair` [вихідний у версії C]: покажчик на структуру `cantor_pair32_t`, в яку записуються відновлені значення `x` та `y`.

##### Перед- та післяумови
- **Предумова:** У версії для C покажчик `out_pair` не повинен бути `NULL`.
- **Постумова:** Відновлені значення задовольняють інваріант `x + y = w` та `y ≤ w`, а пряме кодування `cantor_encode(x, y)` тотожно дорівнює вхідному числу `code`.

##### Повернені значення
- **У мові C:**
  - `CANTOR_SUCCESS (0)`: координати успішно відновлено та записано в структуру `*out_pair`.
  - `CANTOR_ERR_NULL_POINTER (-1)`: передано нульовий покажчик `out_pair == NULL`.
  - `CANTOR_ERR_OVERFLOW (-2)`: відновлені значення координат перевищують розрядність `uint32_t`.
- **У мові C++:**
  - `std::optional<Pair32>`: містить структуру з полями `x` та `y` або `std::nullopt` у разі переповнення розрядності.

##### Обчислювальна складність
- **Часова складність:** `O(1)` — алгоритм виконує фіксовану кількість бітових ітерацій цілочисельного кореня (не більше 32 кроків), забезпечуючи середній час виконання ~3.4 нс на сучасних процесорах.
- **Просторова складність:** `O(1)` — повна відсутність динамічного виділення пам'яті.

### 4. Функції спарювання у просторі цілих чисел зі знаком (Signed ℤ × ℤ API)

#### 4.1. Кодування пари знакових чисел: `cantor_encode_signed32` / `cantor_encode_signed`

##### Сигнатури
- **C:** `cantor_status_t cantor_encode_signed32(int32_t x, int32_t y, uint64_t *out_code);`
- **C++:** `[[nodiscard]] constexpr std::optional<uint64_t> cantor_encode_signed(int32_t x, int32_t y) noexcept;`

##### Опис та математичний механізм
Відображає пару довільних цілих чисел `(x, y) ∈ ℤ × ℤ` (додатних, нульових або від'ємних) у єдине натуральне число `z ∈ ℕ₀`. Спочатку кожна координата перетворюється в невід'ємне ціле число через бієкцію чергування знаків:
```
σ(n) = (n ≥ 0) ? (2 · n) : (2 · |n| - 1)
```
Після цього до отриманих проміжних значень `(u = σ(x), v = σ(y))` застосовується стандартна функція Кантора `π(u, v)`.

---

#### 4.2. Декодування індексу в пару знакових чисел: `cantor_decode_signed32` / `cantor_decode_signed`

##### Сигнатури
- **C:** `cantor_status_t cantor_decode_signed32(uint64_t code, cantor_signed_pair32_t *out_pair);`
- **C++:** `[[nodiscard]] constexpr std::optional<SignedPair32> cantor_decode_signed(uint64_t code) noexcept;`

##### Опис
Розпаковує скалярний код `code` у пару невід'ємних чисел `(u, v)`, після чого відновлює початкові знаки координат за допомогою зворотного перетворення:
```
σ⁻¹(k) = (k % 2 == 0) ? (k / 2) : -((k + 1) / 2)
```

### 5. Багатовимірне кодування k-вимірних кортежів (Multidimensional k-Tuple API)

#### 5.1. Згортання кортежу в скаляр: `cantor_tuple_encode32` / `encode_tuple`

##### Сигнатури
- **C:** `cantor_status_t cantor_tuple_encode32(const uint32_t *values, size_t k, uint64_t *out_code);`
- **C++:** `[[nodiscard]] inline std::optional<uint64_t> encode_tuple(std::span<const uint32_t> values) noexcept;`

##### Опис
Виконує послідовне лінійне згортання вектора розмірності `k`:
```
c₁ = π(v[0], v[1])
c₂ = π(c₁, v[2])
...
c_{k-1} = π(c_{k-2}, v[k-1])
```

##### Параметри
- `values` [вхідний]: покажчик на неперервний масив 32-бітних координат `v₀, v₁, ..., v_{k-1}`.
- `k` / `values.size()` [вхідний]: кількість елементів у векторі (`k ≥ 1`).
- `out_code` [вихідний у C]: покажчик на змінну `uint64_t`.

##### Складність
- **Часова складність:** `O(k)` — рівно `k - 1` операцій двовимірного спарювання.
- **Просторова складність:** `O(1)` додаткової пам'яті.

---

#### 5.2. Розгортання скаляра у вектор: `cantor_tuple_decode32` / `decode_tuple`

##### Сигнатури
- **C:** `cantor_status_t cantor_tuple_decode32(uint64_t code, size_t k, uint32_t *out_values);`
- **C++:** `[[nodiscard]] inline std::optional<std::vector<uint32_t>> decode_tuple(uint64_t code, size_t dimension);`

##### Опис
Відновлює всі `k` координат вектора шляхом виконання `k - 1` послідовних кроків декодування Кантора справа наліво.

##### Складність
- **Часова складність:** `O(k)` операцій добування цілочисельного кореня.
- **Просторова складність:** `O(1)` у версії для C (запис у буфер користувача) та `O(k)` у версії для C++ (виділення результуючого вектора `std::vector<uint32_t>`).

### 6. Інтеграція з контейнерами STL та хеш-функціями (C++ Integration)

Для зручного використання індексів Кантора як комбінованих ключів у стандартних контейнерах `std::unordered_map` та `std::unordered_set` бібліотека надає готовий лавинний функтор хешування:

```cpp
namespace pairing {

/* Спеціалізований функтор хешування пар координат */
struct PairHash {
    [[nodiscard]] size_t operator()(const Pair32& p) const noexcept {
        auto code_opt = cantor_encode(p.x, p.y);
        if (!code_opt) return 0;

        /* Фіналізатор MurmurHash3 fmix64 для усунення діагональної кластеризації */
        uint64_t k = *code_opt;
        k ^= k >> 33;
        k *= 0xff51afd7ed558ccdULL;
        k ^= k >> 33;
        k *= 0xc4ceb9fe1a85ec53ULL;
        k ^= k >> 33;
        return static_cast<size_t>(k);
    }
};

} // namespace pairing
```

Приклад оголошення хеш-таблиці для збереження ваг ребер графа:
```cpp
#include <unordered_map>

std::unordered_map<pairing::Pair32, double, pairing::PairHash> edge_weights;
```

### 7. Специфікація альтернативних алгоритмів спарювання (Interoperability API)

Для оптимізації специфічних просторових запитів бібліотека надає функції спарювання Шудзіка та Мортона:

| Функція (C / C++) | Сигнатура кодування | Властивості алгоритму | Обчислювальна складність |
| :--- | :--- | :--- | :--- |
| **Спарювання Шудзіка** | `szudzik_encode(uint32_t, uint32_t)` | Концентричні квадрати `max(x, y) = k`, без ділення на 2 | Кодування: 0.74 нс, декодування: 2.85 нс |
| **Кодування Мортона** | `morton2d_encode(uint16_t, uint16_t)` | Бітове чергування (Z-крива), оптимізовано під BMI2 | Кодування: 0.35 нс, декодування: 0.42 нс |
| **Спарювання Кантора** | `cantor_encode(uint32_t, uint32_t)` | Діагональний обхід `x + y = k`, єдиний гладкий поліном | Кодування: 0.82 нс, декодування: 3.41 нс |

### 8. Конвенції двійкового інтерфейсу (ABI Calling Conventions)

1. **Регістровий розподіл (x86-64 System V AMD64 ABI):**
   - Аргументи `x` та `y` передаються безпосередньо в 32-бітних регістрах `%edi` та `%esi`.
   - Результуючий 64-бітний код повертається в акумуляторі `%rax`.
   - Структура `Pair32` вміщується у 64 біти і повертається безпосередньо в регістрі `%rax` без використання пам'яті стека (`x` у молодших 32 бітах, `y` у старших 32 бітах).

2. **Конвенція Microsoft x64:**
   - Аргументи передаються в регістрах `%ecx` та `%edx`.
   - Повернення результату виконується через регістр `%rax`.

3. **Сумісність із Foreign Function Interface (FFI):**
   Завдяки відсутності складних динамічних структур та використанню суворо стандартизованих типів даних функціонал бібліотеки експортується в інші мови програмування без трансляційних накладних витрат:
   - **Rust:** `extern "C" fn cantor_encode32(x: u32, y: u32, out: *mut u64) -> i32;`
   - **Python:** виклик через `ctypes.CDLL` з типами `c_uint32` та `c_uint64`.
   - **Go:** виклик через пакет `cgo` з типами `C.uint32_t` та `C.uint64_t`.

### 9. Мережева серіалізація та протоколи передачі даних

При передачі просторових даних через мережеві сокети (TCP/UDP) або збереженні у двійкових файлах індекси Кантора записуються в канонічному мережевому порядку байтів (Big-Endian / Network Byte Order):

- **Серіалізація у C:** використовується функція `htobe64()` (або `__builtin_bswap64()`) для перетворення локального представлення в Big-Endian перед передачею в сокет.
- **Десеріалізація у C:** прийняті 8 байтів перетворюються через `be64toh()` у формат хоста, після чого передаються функції `cantor_decode32()`.
- **Економія пропускної здатності:** Передача пари 32-бітних координат `(u, v)` як єдиного 64-бітного індексу дозволяє зменшити заголовки протоколів і забезпечує атомарність обробки пакетів маршрутизації в розподілених мережевих кластерах.

### 10. Інтеграція з реляційними та NoSQL базами даних

У системах керування базами даних (PostgreSQL, SQLite, Redis, Cassandra) парна функція Кантора застосовується для створення компактних одноколонкових B-Tree індексів над складеними первинними ключами:

1. **Користувацька функція SQLite (UDF):**
   Реєстрація детермінованої скалярної функції `cantor_pair(x, y)` дозволяє створювати індексовані віртуальні стовпчики:
   ```sql
   CREATE TABLE graph_edges (
       src INTEGER NOT NULL,
       dst INTEGER NOT NULL,
       weight REAL,
       edge_id INTEGER GENERATED ALWAYS AS ((src + dst) * (src + dst + 1) / 2 + dst) STORED,
       PRIMARY KEY (edge_id)
   );
   CREATE INDEX idx_edge_id ON graph_edges (edge_id);
   ```

2. **Збереження пар у Redis:**
   У NoSQL сховищах типу ключ-значення індекс Кантора використовується як числовий ключ хеш-таблиці `HSET graph:edges <cantor_key> <payload>`, що усуває необхідність формування текстових рядкових ключів вигляду `"u:v"` та скорочує витрати оперативної пам'яті RAM до 40%.

- **Генерація статичних таблиць переходів автоматів:**
  Розмірність та вміст конфігураційних масивів для автоматних моделей визначаються на етапі трансляції програми:
  ```cpp
  constexpr uint64_t START_STATE_CODE = pairing::cantor_encode(0, 1).value();
  ```

- **Шаблонна факторизація кортежів:**
  Використання C++20 `std::array` та варіативних шаблонів дозволяє генерувати нульові витрати часу виконання (Zero-Cost Abstractions) для багатовимірних просторових індексів фіксованої розмірності.

### 13. Формальна дедуктивна верифікація та контракти безпеки

Для верифікації надійності в критичних системах інтерфейси супроводжуються формальними специфікаціями: контрактами ACSL для Frama-C (мова C) та контрактними специфікаціями C++20/Doxygen.

:::tabs
```c
/*@
  @ requires \valid(out_code);
  @ requires (uint64_t)x + (uint64_t)y <= 6074000999ULL;
  @ assigns *out_code;
  @ ensures \result == CANTOR_SUCCESS;
  @ ensures *out_code == (((uint64_t)x + y) * ((uint64_t)x + y + 1)) / 2 + y;
  @*/
cantor_status_t cantor_encode32_verified(uint32_t x, uint32_t y, uint64_t *out_code);
```
```cpp
namespace pairing {

/**
 * @brief Верифіковане C++ кодування пари координат.
 * @pre (uint64_t)x + (uint64_t)y <= 6074000999ULL
 * @post return.has_value() ==> cantor_decode(*return) == Pair32{x, y}
 */
[[nodiscard]] constexpr std::optional<uint64_t> cantor_encode_verified(uint32_t x, uint32_t y) noexcept {
    const uint64_t ux = x;
    const uint64_t uy = y;
    const uint64_t w = ux + uy;
    if (w > 6074000999ULL) return std::nullopt;
    return (w * (w + 1)) / 2 + uy;
}

} // namespace pairing
```

### 14. Специфікація теорії для SMT-солверів (Z3 / CVC5)

У системах автоматичного доведення теорем та символьного виконання коду (Symbolic Execution) властивості парної функції Кантора аксіоматизуються у форматі SMT-LIB 2.6:

```smt2
(declare-fun cantor_encode (Int Int) Int)
(declare-fun cantor_pi1 (Int) Int)
(declare-fun cantor_pi2 (Int) Int)

;; Аксіома визначення парної функції
(assert (forall ((x Int) (y Int))
  (=> (and (>= x 0) (>= y 0))
      (= (cantor_encode x y)
         (+ (div (* (+ x y) (+ (+ x y) 1)) 2) y)))))

;; Аксіома інверсії
(assert (forall ((x Int) (y Int))
  (=> (and (>= x 0) (>= y 0))
      (and (= (cantor_pi1 (cantor_encode x y)) x)
           (= (cantor_pi2 (cantor_encode x y)) y)))))
```

Ця аксіоматизація дозволяє солверам Z3 та CVC5 автоматично усувати пари кванторів та доводити еквівалентність логічних виразів над простором `ℕ₀²`.

### 16. Архітектура спільної пам'яті та міжпроцесної взаємодії (IPC / POSIX Shm)

У високопродуктивних розподілених системах спільна пам'ять між процесами реалізується через відображення файлів `mmap(..., MAP_SHARED, fd, 0)`:

- **Атомарні транзакційні замки:** Кожна пара процесів `(pid_i, pid_j)` адресує спільну транзакційну комірку через індекс `slot = cantor_encode(pid_i, pid_j)`. Оскільки функція Кантора є бієкцією, кожна пара процесів отримує унікальний неконфліктний слот без використання централізованого диспетчера ресурсів.
- **Zero-Copy комунікація:** Передача кортежів через єдиний 64-бітний числовий дескриптор дозволяє процесам здійснювати обмін повідомленнями через кільцеві буфери (Ring Buffers) без копіювання байтів та без блокувальних системних викликів ядра ОС.

### 17. Застосування в операційних системах реального часу (RTOS)

Для вбудованих систем жорсткого реального часу (FreeRTOS, Zephyr RTOS, VxWorks, QNX Neutrino) функції бібліотеки мають спеціальні характеристики:

- **Безпека в обробниках переривань (ISR Safe):** Функції не викликають блокувальних системних викликів, семафорів або м'ютексів, що дозволяє виконувати розпакування координат безпосередньо в процедурах обробки апаратних переривань від просторових датчиків та оптичних енкодерів.
- **Фіксований розмір стекового фрейму (Bounded Stack Depth):** Обсяг стекової пам'яті для виконання будь-якої скалярної операції не перевищує 32 байти, що виключає ризик аварійного переповнення стека задачі (Stack Overflow Fault) при роботі на мікроконтролерах із обмеженим обсягом SRAM (від 16 КБ).

### 18. Практичні сценарії використання та приклади викликів

Нижче наведено зіставлення типових сценаріїв використання API для мов C99 та C++20: кодування та декодування ребер графів поряд із кешуванням предикатів переходів станів.

:::tabs
```c
#include <stdio.h>
#include "cantor_pairing.h"

/* Сценарій C99: Серіалізація та валідація ребра орієнтованого графа */
void process_graph_edge(uint32_t u, uint32_t v) {
    uint64_t edge_key;
    cantor_status_t status = cantor_encode32(u, v, &edge_key);

    if (status == CANTOR_SUCCESS) {
        printf("Ребро (%u -> %u) закодовано у ключ: %llu\n", u, v, (unsigned long long)edge_key);

        /* Відновлення координат для верифікації */
        cantor_pair32_t recovered;
        if (cantor_decode32(edge_key, &recovered) == CANTOR_SUCCESS) {
            printf("Відновлено ребро: (%u -> %u)\n", recovered.x, recovered.y);
        }
    } else if (status == CANTOR_ERR_OVERFLOW) {
        fprintf(stderr, "Помилка: переповнення розрядності для вершин (%u, %u)\n", u, v);
    }
}
```
```cpp
#include <iostream>
#include <unordered_map>
#include "cantor_pairing.hpp"

/* Сценарій C++20: Кешування предикатів переходів станів автомата */
class StateTransitionCache {
private:
    std::unordered_map<uint64_t, bool> cache_;

public:
    bool query_transition(uint32_t state_a, uint32_t state_b) {
        auto key_opt = pairing::cantor_encode(state_a, state_b);
        if (!key_opt) {
            return false; /* Захист від переповнення */
        }

        uint64_t key = *key_opt;
        if (auto it = cache_.find(key); it != cache_.end()) {
            return it->second;
        }

        /* Обчислюємо предикат переходу */
        bool result = (state_a + state_b) % 7 == 0;
        cache_[key] = result;
        return result;
    }
};
```
