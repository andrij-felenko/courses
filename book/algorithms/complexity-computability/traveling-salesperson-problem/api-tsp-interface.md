# 📋 Специфікація програмного інтерфейсу солвера задачі комівояжера (libtsp)

Модуль `libtsp` надає уніфікований C та C++ інтерфейс для розв'язання дискретних та метричних екземплярів задачі комівояжера (TSP). Бібліотека призначена для інтеграції у промислові логістичні платформи, системи автоматизованого проектування друкованих плат (САПР/EDA) та модулі управління автопілотами безпілотних літальних апаратів (БПЛА).

Інтерфейс розроблено з дотриманням принципу мінімального подиву, повної потокобезпеки (Thread Safety) на рівні викликів функцій та суворого розмежування відповідальності за виділення й визволення динамічної пам'яті.

---

## 1. Архітектура заголовочних файлів та перелічувані типи

Модуль надає два заголовочні файли:
- `tsp/tsp.h` — класичний ANSI C (C99) заголовочний файл з підтримкою прямого виклику з мов C, C++, Rust, Python (через CFFI/ctypes) та C# (P/Invoke). Він не має зовнішніх залежностей і використовує стандартні типи `stdint.h` та `stdbool.h`.
- `tsp/tsp.hpp` — сучасна обгортка для C++20 з використанням концептів, RAII-контейнерів `std::vector`, `std::span` та розумних вказівників.

### 1.1. Перелічувані типи та геометрія задач

Низькорівневий C-інтерфейс кодує режими обчислення та типи геометрій через перелічувані типи `enum`. Усі значення типів є строго фіксованими цілими числами для забезпечення сумісності на рівні бінарного ABI (Application Binary Interface).

:::tabs
@tab C
```c
/**
 * @brief Тип геометрії або метрики відстаней між містами.
 */
typedef enum {
    TSP_METRIC_EUCLIDEAN_2D = 0, /* Двовимірна евклідова відстань */
    TSP_METRIC_MANHATTAN    = 1, /* Мангеттенська відстань (|x1-x2| + |y1-y2|) */
    TSP_METRIC_GENERAL      = 2, /* Загальна симетрична матриця відстаней */
    TSP_METRIC_ASYMMETRIC   = 3  /* Асиметрична матриця (w[i][j] != w[j][i]) */
} tsp_metric_type_t;

/**
 * @brief Алгоритм, що застосовується для розв'язання задачі.
 */
typedef enum {
    TSP_ALG_HELD_KARP       = 0, /* Точний алгоритм DP: O(n^2 * 2^n), n <= 22 */
    TSP_ALG_BRANCH_AND_BOUND= 1, /* Точний алгоритм гілок і меж, n <= 60 */
    TSP_ALG_CHRISTOFIDES    = 2, /* 1.5-апроксимація для метричних задач, n <= 5000 */
    TSP_ALG_2OPT_HEURISTIC  = 3  /* Швидка евристика локального пошуку, n <= 100000 */
} tsp_algorithm_t;

/**
 * @brief Коди статусу та помилок виконання солвера.
 */
typedef enum {
    TSP_SUCCESS             =  0, /* Успішне завершення, оптимальний або наближений розв'язок знайдено */
    TSP_ERR_INVALID_PARAM   = -1, /* Некоректні вхідні аргументи (NULL вказівники, n = 0) */
    TSP_ERR_NON_METRIC      = -2, /* Граф не задовольняє нерівність трикутника для алгоритму Крістофідеса */
    TSP_ERR_TIMEOUT         = -3, /* Перевищено максимальний відведений час виконання */
    TSP_ERR_OUT_OF_MEMORY   = -4, /* Неможливо виділити необхідний обсяг системної пам'яті */
    TSP_ERR_OVERFLOW        = -5  /* Кількість вершин n перевищує межу алгоритму (наприклад n > 31 для DP) */
} tsp_status_t;
```

Детальний функціональний опис кожного значення перелічуваного типу:

1. `TSP_METRIC_EUCLIDEAN_2D`: Оптимізує обчислення шляхом прямого розрахунку декартової відстані `√((x1-x2)² + (y1-y2)²)` між точками на площині. При цьому повна квадратна матриця `n x n` взагалі не виділяється у пам meті; солвер обчислює відстані на льоту за координатами точок, що дозволяє економити гігабайти ОЗП при `n > 10 000`.
2. `TSP_METRIC_MANHATTAN`: Використовує сіткову метрику `|x1-x2| + |y1-y2|`, що є стандартом при трасуванні доріжок у напівпровідникових мікросхемах та траєкторій маніпуляторів складавних роботів.
3. `TSP_METRIC_GENERAL`: Вказує на довільну симетричну матрицю відстаней, задану вхідним одновимірним масивом у форматі row-major (`matrix[i * n + j]`).
4. `TSP_METRIC_ASYMMETRIC`: Вказує на орієнтований граф, де вага переходу `w(u, v)` не дорівнює `w(v, u)`. При виборі цієї метрики алгоритми Крістофідеса та 2-Opt повертають код помилки `TSP_ERR_NON_METRIC`, оскільки вони спираються на властивості неупорядкованих графів.

Коди помилок та сценарії їх виклику:
- `TSP_SUCCESS`: Запитуване обчислення успішно завершено. Структура результату містить коректну сумарну вагу `tour_cost` та виділений масив послідовності вершин `tour`.
- `TSP_ERR_INVALID_PARAM`: Повертається у разі передачі нульового вказівника `matrix == NULL`, `result == NULL`, або при значеннях розмірності `n == 0`.
- `TSP_ERR_NON_METRIC`: Виникає при спробі запуску алгоритму Крістофідеса-Сердюкова на графі, для якого перевірка `tsp_validate_triangle_inequality` виявила принаймні одну трійку вершин `(i, j, k)`, де `w(i, j) > w(i, k) + w(k, j)`.
- `TSP_ERR_TIMEOUT`: Повертається, якщо час виконання обчислювального потоку перевищив ліміт, заданий у `config->time_limit_sec`. При цьому виділена тимчасова пам meть очищається.
- `TSP_ERR_OUT_OF_MEMORY`: Виникає у разі невдалої спроби системного виклику `malloc` при створенні великих таблиць динамічного програмування або матриць суміжності.
- `TSP_ERR_OVERFLOW`: Виникає при спробі виклику точного алгоритму Хелда-Карпа для `n > 31` (через обмеження 32-бітних масок) або при значному числовому переповненні сумарних ваг.

## 2. Конфігурація солвера та структури результату

Для гнучкого налаштування режимів обчислення застосовується паттерн параметричної структури `tsp_config_t`. Результати роботи повертаються через структуру `tsp_result_t`.

### 2.1. Опис полів конфігурації та результату

:::tabs
@tab C
```c
/**
 * @brief Функція зворотного виклику для відстеження прогресу (Callback).
 * @param progress Дробове значення від 0.0 (початок) до 1.0 (завершення).
 * @param user_data Вказівник на контекст користувача.
 * @return true — продовжувати обчислення, false — негайно перервати обчислення.
 */
typedef bool (*tsp_progress_cb)(double progress, void* user_data);

/**
 * @brief Конфігураційна структура параметрів солвера.
 */
typedef struct {
    tsp_algorithm_t algorithm;  /* Обраний алгоритм розв'язання */
    tsp_metric_type_t metric;   /* Тип метрики вхідних даних */
    double time_limit_sec;      /* Ліміт часу в секундах (0.0 — без обмеження) */
    double target_precision;    /* Бажаний коефіцієнт точності (наприклад 0.05 = 5%) */
    size_t num_threads;         /* Кількість паралельних потоків обробки */
    tsp_progress_cb callback;   /* Функція зворотного виклику для прогресу */
    void* user_data;            /* Контекстний вказівник для колбеку */
} tsp_config_t;

/**
 * @brief Структура для повернення результату розв'язання.
 */
typedef struct {
    tsp_status_t status;        /* Код статусу виконання */
    double tour_cost;           /* Загальна довжина/вага знайденого маршруту */
    int* tour;                  /* Динамічний масив послідовності вершин розміру (n + 1) */
    size_t tour_size;           /* Кількість елементів у масиві tour (n + 1) */
    double elapsed_time_sec;    /* Фактично витрачений час обчислення у секундах */
    uint64_t nodes_evaluated;   /* Кількість переглянутих станів/вузлів дерева */
} tsp_result_t;
```

@tab C++
```cpp
#include <vector>
#include <chrono>
#include <functional>

namespace tsp {

using ProgressCallback = std::function<bool(double progress)>;

struct Config {
    Algorithm algorithm{Algorithm::Christofides};
    MetricType metric{MetricType::General};
    std::chrono::duration<double> time_limit{0};
    double target_precision{0.0};
    size_t num_threads{1};
    ProgressCallback callback{nullptr};
};

struct Result {
    Status status{Status::Success};
    double tour_cost{0.0};
    std::vector<size_t> tour;
    std::chrono::duration<double> elapsed_time{0};
    uint64_t nodes_evaluated{0};
};

} // namespace tsp
```
:::

Детальна семантика полів конфігурації та результату:

- `time_limit_sec`: Визначає максимальний неперервний астрономічний час обчислення у секундах. Якщо поле дорівнює `0.0`, часовий ліміт відсутній і солвер працює до повного завершення. Для багатопотокових режимів Branch and Bound такий контроль виконується періодичною перевіркою таймера на кожному рівні рекурсії.
- `target_precision`: Використовується наближеними та евристичними солверами. Наприклад, якщо значення встановлено в `0.02`, то при досягненні гарантованого зазору апроксимації 2% від нижньої межі обчислення припиняються достроково.
- `num_threads`: Кількість робочих POSIX-потоків (std::thread). Якщо значення дорівнює `0`, бібліотека автоматично визначає кількість фізичних ядер процесора через `sysconf(_SC_NPROCESSORS_ONLN)` або `std::thread::hardware_concurrency()`.
- `callback` та `user_data`: Дозволяють інтегрувати солвер із графічними інтерфейсами або сервісами моніторингу. Солвер періодично викликає передану функцію, передаючи їй прогрес у діапазоні `[0.0, 1.0]`. Якщо колбек повертає `false`, солвер негайно зупиняє розгалуження й повертає частковий розв meзок зі статусом `TSP_ERR_TIMEOUT`.
- `tour`: Динамічний масив індексів вершин розміру `n + 1`. Масив представляє замкнений маршрут, де `tour[0]` є початковою вершиною, а `tour[n] == tour[0]` є завершальною вершиною цикла. Пам'ять під цей масив виділяється всередині `tsp_solve_matrix`.
- `nodes_evaluated`: Кількісний показник обчислювальної складності, витраченої на даний екземпляр:
  - Для Хелда-Карпа: кількість заповнених осередків таблицы `n · 2ⁿ`.
  - Для Branch & Bound: кількість згенерованих та оцінених вузлів дерева.
  - Для 2-Opt: кількість успішно виконаних реверсів підмасивів.

## 3. Публічні функції та сигнатури

Публічний інтерфейс реалізує функції ініціалізації, перевірки вхідних даних, виконання обчислень та звільнення ресурсів.

:::tabs
@tab C
```c
#ifdef __cplusplus
extern "C" {
#endif

/**
 * @brief Ініціалізація структури конфігурації за замовчуванням.
 * @param config Вказівник на структуру конфігурації.
 */
void tsp_config_init(tsp_config_t* config);

/**
 * @brief Головна функція розв'язання задачі комівояжера за матрицею відстаней.
 * @param matrix Матриця відстаней розміру n x n (одномірний масив row-major).
 * @param n Кількість вершин/міст у графі.
 * @param config Налаштування солвера (якщо NULL, використовуються за замовчуванням).
 * @param result Вихідна структура результату.
 * @return TSP_SUCCESS у разі успіху або код помилки.

tsp_status_t tsp_solve_matrix(const double* matrix, size_t n, 
                             const tsp_config_t* config, 
                             tsp_result_t* result);

/**
 * @brief Звільнення динамічної пам'яті, виділеної у структурі результату.
 * @param result Вказівник на структуру результату.
 */
void tsp_result_free(tsp_result_t* result);

/**
 * @brief Перевірка матриці відстаней на відповідність нерівності трикутника.
 * @param matrix Матриця розміру n x n.

 * @return true — якщо нерівність трикутника виконується для всіх трійок вершин.

namespace tsp {

class Solver {

        return *this;
    }

    [[nodiscard]] Result solve(std::span<const double> matrix_flat, size_t n) const;
    [[nodiscard]] Result solve(const std::vector<std::vector<double>>& matrix) const;
    [[nodiscard]] static bool validate_triangle_inequality(const std::vector<std::vector<double>>& matrix);

    Config config_;
};

} // namespace tsp
```

Детальний порядок виклику функцій:
1. Клієнтський код створює змінну конфігурації та викликає `tsp_config_init(&config)`. Це забезпечує заповнення полів безпечними значеннями за замовчуванням (алгоритм Крістофідеса, без ліміту часу, 1 потік).
2. При необхідності клієнт модифікує окремі поля структури `config`.
3. Викликається функція `tsp_solve_matrix(matrix, n, &config, &result)`.
4. Перевіряється повернутий статус: якщо `result.status == TSP_SUCCESS`, зчитується довжина `result.tour_cost` та обходиться масив `result.tour`.
5. Після завершення обробки обов'язково викликається `tsp_result_free(&result)`.

## 4. Гарантії безпеки, управління пам'яттю та обробка помилок

Правила використання інтерфейсу:

1. **Життєвий цикл пам'яті у C API:**
   Функція `tsp_solve_matrix` виділяє динамічну пам'ять під масив `result->tour` за допомогою системного виклику `malloc`. Обов'язком клієнтського коду є виклик функції `tsp_result_free(result)` після завершення роботи з результатом. Передача `NULL` або повторний виклик `tsp_result_free` є безпечним (ідемпотентним). У C++ API пам meть автоматично інкапсулюється в `std::vector<size_t>`, унеможливлюючи витоки пам'яті.

2. **Потокобезпека (Thread Safety):**
   Функції `tsp_solve_matrix` та метод `tsp::Solver::solve` є повністю чистими (stateless) та потокобезпечними. Вони не використовують глобальних або статичних змінних. Безліч паралельних потоків можуть одночасно викликати розв meзання для різних екземплярів матриць без застосування м'ютексів або блокувань.

3. **Обробка та відновлення при помилках:**
   Якщо солвер повертає код помилки (наприклад, `TSP_ERR_TIMEOUT` або `TSP_ERR_NON_METRIC`), масив `result->tour` залишається дорівнювати `NULL`, а значення `result->tour_cost` встановлюється в `INF`. Клієнтський код зобов'язаний перевіряти статус повернення перед зверненням до елементів масиву маршруту.

4. **Інтеграція з іншими мовами через FFI:**
   Завдяки відсутності складних структур C++ у заголовочному файлі `tsp.h`, бібліотека легко імпортується у мову Python за допомогою пакета `ctypes`:

```python
import ctypes

class TSPResult(ctypes.Structure):
    _fields_ = [
        ("status", ctypes.c_int),
        ("tour_cost", ctypes.c_double),
        ("tour", ctypes.POINTER(ctypes.c_int)),
        ("tour_size", ctypes.c_size_t),
        ("elapsed_time_sec", ctypes.c_double),
        ("nodes_evaluated", ctypes.c_uint64)
    ]
```

Це дозволяє використовувати високопродуктивне C-ядро `libtsp` у високорівневих скриптах аналізу даних без втрати швидкодії.
