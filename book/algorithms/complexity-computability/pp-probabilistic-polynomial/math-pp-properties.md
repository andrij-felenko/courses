# 🧮 Математичний апарат класу PP: порогове обчислення та доведення замкненості

Математична теорія ймовірнісного поліноміального часу описує поведінку монетних машин Тюрінга із строго пороговою функцією прийняття. На відміну від імовірнісних моделей із відокремленою хибою, де межа прийняття захищена зазором, клас PP (Probabilistic Polynomial-time) працює на точній межі імовірності 1/2. Ця вставка містить формальні математичні означення, покрокові доведення фундаментальних теорем про вміщення NP ⊆ PP, симетрію coPP = PP та еквівалентність оракульних обчислень між PP і підрахунковим класом #P.

## 1. Формальна модель ймовірнісної машини та означення PP

Імовірнісна машина Тюрінга (PTM) `M` — це недетермінована машина Тюрінга, яка на кожному кроці обчислення має рівно два можливі варіанти переходу, кожен з яких обирається з імовірністю 1/2.

Нехай `x ∈ {0, 1}*` — вхідне слово довжини `n = |x|`. Машина `M` виконує обчислення за поліноміальний час `p(n)`. Випадковий вибір машини на кожному з `p(n)` кроків повністю визначається послідовністю випадкових бітів `r ∈ {0, 1}ᵖ⁽ⁿ⁾`.

Загальна кількість обчислювальних шляхів на вкладі `x` дорівнює `2ᵖ⁽ⁿ⁾`. Позначимо через `M(x, r) ∈ {0, 1}` результат обчислення машини `M` на вкладі `x` із випадковим вектором `r`:
- `M(x, r) = 1` — машина зупинилася у стані прийняття (ACCEPT);
- `M(x, r) = 0` — машина зупинилася у стані відхилення (REJECT).

Імовірність прийняття слова `x` машиною `M` визначається як відношення кількості успішних шляхів до загальної кількості шляхів у бінарному дереві:

```
P_M(x) = |{ r ∈ {0, 1}ᵖ⁽ⁿ⁾ : M(x, r) = 1 }| / 2ᵖ⁽ⁿ⁾
```

**Означення мови в класі PP:**
Мова `L ⊆ {0, 1}*` належить до класу PP тоді й лише тоді, коли існує така ймовірнісна поліноміальна машина Тюрінга `M`, що для кожного `x ∈ {0, 1}*`:

```
x ∈ L  ⇔  P_M(x) > 1/2
x ∉ L  ⇔  P_M(x) ≤ 1/2
```

Позначивши через `N_accept(x) = |{ r : M(x, r) = 1 }|` кількість шляхів прийняття, умову належності мові можна переписати через цілі числа:

```
x ∈ L  ⇔  N_accept(x) > 2ᵖ⁽ⁿ⁾⁻¹
x ∉ L  ⇔  N_accept(x) ≤ 2ᵖ⁽ⁿ⁾⁻¹
```

Отже, вирішення проблеми належності мові в PP зводиться до порівняння кількості успішних шляхів із строгою половиною `2ᵖ⁽ⁿ⁾⁻¹`.

## 2. Доведення вміщення NP ⊆ PP

Сформулюємо теорему: кожен мовний вираз, що належить до класу NP, також належить до класу PP (`NP ⊆ PP`).

**Доведення:**
Нехай мова `L ∈ NP`. За означенням класу NP, існує детермінований поліноміальний верифікатор `V(x, y)`, який працює за час `q(|x|)`, та поліном `m(n) = |y|` такі, що:

```
x ∈ L  ⇔  ∃ y ∈ {0, 1}ᵐ⁽ⁿ⁾ : V(x, y) = 1
```

Побудуємо ймовірнісну машини `M_NP`, яка розпізнаватиме мову `L` за правилом класу PP.

Машина `M_NP` робить випадковий вибір `r = (b, y, z)`, де:
- `b ∈ {0, 1}` — один біт контролю режиму;
- `y ∈ {0, 1}ᵐ⁽ⁿ⁾` — потенційний сертифікат (свідок);
- `z ∈ {0, 1}ᵐ⁽ⁿ⁾⁻¹` — додатковий балансувальний вектор випадкових бітів.

Загальна кількість випадкових бітів машини дорівнює:

```
p(n) = 1 + m(n) + (m(n) - 1) = 2m(n)
```

Отже, загальна кількість обчислювальних шляхів дорівнює `2²ᵐ⁽ⁿ⁾`.

Алгоритм роботи `M_NP` на вхідному векторі `(b, y, z)`:
1. Якщо `b = 0`: машина ігнорує `y` та `z` і відразу **ПРИЙМАЄ** (повертає 1).
2. Якщо `b = 1`: машина запускає верифікатор `V(x, y)`:
   - Якщо `V(x, y) = 1` (сертифікат дійсний), машина **ПРИЙМАЄ** (повертає 1).
   - Якщо `V(x, y) = 0` (сертифікат недійсний), машина **ВІДХИЛЯЄ** (повертає 0).

Порахуємо кількість шляхів прийняття `N_accept(x)`:

```
N_accept(x) 
= [шляхи при b = 0] + [шляхи при b = 1]
= 2²ᵐ⁽ⁿ⁾⁻¹ + K(x) · 2ᵐ⁽ⁿ⁾⁻¹
```

де `K(x) = |{ y ∈ {0, 1}ᵐ⁽ⁿ⁾ : V(x, y) = 1 }|` — точна кількість дійсних сертифікатів для `x`.

Проаналізуємо два випадки:

**Випадок 1: `x ∈ L`.**
Тоді існує щонайменше один дійсний сертифікат, отже `K(x) ≥ 1`.

```
N_accept(x)
= 2²ᵐ⁽ⁿ⁾⁻¹ + K(x) · 2ᵐ⁽ⁿ⁾⁻¹
≥ 2²ᵐ⁽ⁿ⁾⁻¹ + 1 · 2ᵐ⁽ⁿ⁾⁻¹
> 2²ᵐ⁽ⁿ⁾⁻¹      [оскільки 2ᵐ⁽ⁿ⁾⁻¹ ≥ 1]
```

Отже, `P_M_NP(x) > 1/2`, що задовольняє умову належності до PP.

**Випадок 2: `x ∉ L`.**
Жодного дійсного сертифіката не існує, отже `K(x) = 0`.

```
N_accept(x)
= 2²ᵐ⁽ⁿ⁾⁻¹ + 0 · 2ᵐ⁽ⁿ⁾⁻¹
= 2²ᵐ⁽ⁿ⁾⁻¹      [рівно половина шляхів]
```

Отже, `P_M_NP(x) = 1/2 ≤ 1/2`, що означає відхилення за умовою PP.

Висновок: Побудована машина `M_NP` розпізнає мову `L` в режимі PP за поліноміальний час. Це доводить, що `NP ⊆ PP`. ∎

Аналогічним способом будується машина для доведення `coNP ⊆ PP`. Для мови `L ∈ coNP` ми перевіряємо, чи всі гілки є істинними, балансуючи дерево так, щоб навіть один виявлений контраприклад зсував імовірність нижче порогу 1/2.

## 3. Доведення замкненості відносно доповнення: coPP = PP

Сформулюємо теорему: Клас PP замкнений відносно операції доповнення мови, тобто `coPP = PP`.

**Аналітична складність:**
Якщо мова `L ∈ PP` розпізнається машиною `M`, то умовою належності `x ∈ L` є `N_accept(x) > 2ᵖ⁽ⁿ⁾⁻¹`.
Доповнення мови `L̄ = {x : x ∉ L}` вимагає умови `x ∈ L̄ ⇔ N_accept(x) ≤ 2ᵖ⁽ⁿ⁾⁻¹`.
Якщо ми просто поміняємо місцями стани ACCEPT та REJECT у машині `M`, то нова машина `M̄` матиме кількість шляхів прийняття `N_M̄(x) = 2ᵖ⁽ⁿ⁾ - N_accept(x)`.
Умова прийняття нової машини `M̄` стане:

```
N_M̄(x) > 2ᵖ⁽ⁿ⁾⁻¹
⇔ 2ᵖ⁽ⁿ⁾ - N_accept(x) > 2ᵖ⁽ⁿ⁾⁻¹
⇔ N_accept(x) < 2ᵖ⁽ⁿ⁾⁻¹
```

Проблема полягає у строгій нерівності: у випадку `N_accept(x) = 2ᵖ⁽ⁿ⁾⁻¹` початкова машина відхиляла `x ∉ L`, але після інверсії нова машина матиме `N_M̄(x) = 2ᵖ⁽ⁿ⁾⁻¹`, що НЕ є строго більшим за `2ᵖ⁽ⁿ⁾⁻¹`, тому нова машина також відхилить `x`! Проста інверсія результатів не працює через точну рівність на порозі.

**Доведення через калібрувальну модифікацію шляхів (Трюк Ґілла):**

Побудуємо модифіковану ймовірнісну машину `M''`, яка подвоює кількість шляхів і додає один гарантований шлях прийняття.

Нехай початкова машина `M` має `2ᵖ⁽ⁿ⁾` шляхів.
Створимо машину `M''`, яка виконує наступну покрокову процедуру:

1. Машина `M''` з імовірністю 1/2 просто копіює роботу початкової машини `M`.
2. З імовірністю 1/2 машина `M''` виконує спеціально відкаліброване випробування: створює `2ᵖ⁽ⁿ⁾` шляхів, з яких рівно `2ᵖ⁽ⁿ⁾⁻¹ + 1` шляхів приймають, а `2ᵖ⁽ⁿ⁾⁻¹ - 1` відхиляють.

Порахуємо загальну кількість шляхів прийняття машини `M''`:

```
N_M''(x)
= N_accept(x) + (2ᵖ⁽ⁿ⁾⁻¹ + 1)
```

Загальна кількість шляхів машини `M''` дорівнює `2 · 2ᵖ⁽ⁿ⁾ = 2ᵖ⁽ⁿ⁾⁺¹`.
Половина від загальної кількості шляхів `M''` дорівнює `2ᵖ⁽ⁿ⁾`.

Перевіримо умову прийняття для `M''`:

```
N_M''(x) > 2ᵖ⁽ⁿ⁾
⇔ N_accept(x) + 2ᵖ⁽ⁿ⁾⁻¹ + 1 > 2ᵖ⁽ⁿ⁾
⇔ N_accept(x) + 1 > 2ᵖ⁽ⁿ⁾ - 2ᵖ⁽ⁿ⁾⁻¹
⇔ N_accept(x) + 1 > 2ᵖ⁽ⁿ⁾⁻¹
⇔ N_accept(x) ≥ 2ᵖ⁽ⁿ⁾⁻¹       [оскільки це цілі числа]
```

Отриманий результат є фундаментальним: машина `M''` приймає `x` тоді й лише тоді, коли `N_accept(x) ≥ 2ᵖ⁽ⁿ⁾⁻¹` (нестрога нерівність!).

Тепер, інвертувавши стани ACCEPT та REJECT у модифікованій машині `M''`, ми отримуємо інвертований предикат:

```
x ∈ L̄  ⇔  N_accept(x) ≤ 2ᵖ⁽ⁿ⁾⁻¹
        ⇔  NOT ( N_accept(x) ≥ 2ᵖ⁽ⁿ⁾⁻¹ + 1 )
```

Оскільки нестрога нерівність піддається суворій арифметичній інверсії без втрати межової точки, ми отримали ймовірнісну машини за поліноміальний час, яка розпізнає доповнення мови `L̄` у класі PP.

Отже, `coPP ⊆ PP`, з чого випливає `coPP = PP`. ∎

## 4. Еквівалентність оракулів: Pᵖᵖ = P────────

Розглянемо зв'язок між рішенням порогових задач (PP) та обчисленням точної кількості розв'язків (#P).

Нехай `f ∈ #P` — функція, яка повертає кількість виконуючих наборі для формули `φ`. Значення `f(x)` лежить у діапазоні `0 ≤ f(x) ≤ 2ⁿ`, де `n` — кількість змінних.

**Теорема:** Детермінована машина Тюрінга з оракулом до PP може обчислити точне значення `f(x)` за поліноміальну кількість викликів оракула.

**Доведення (Метод бінарного пошуку):**

Побудуємо допоміжну мову `L_binary ∈ PP`:

```
L_binary = { (x, K) : f(x) > K }
```

Для довільного фіксованого цілого числа `K` мова `L_binary` належить до PP, оскільки ми можемо створити PTM, яка повертає `f(x)` шляхів прийняття та додатково створює балансувальні шляхи так, щоб загальна кількість прийнятних шляхів перевищувала 1/2 тоді й лише тоді, коли `f(x) > K`.

Алгоритм детермінованого оракульного обчислення значення `f(x)`:

```
Низька_межа = 0
Висока_межа = 2ⁿ

Поки Низька_межа < Висока_межа:
    Кандидат_K = ⌊ (Низька_межа + Висока_межа) / 2 ⌋
    Звернутися до оракула PP із запитом: «Чи належить (x, Кандидат_K) до L_binary?»
    
    Якщо Оракул повернув «ТАК»:
        [Це означає f(x) > Кандидат_K]
        Низька_межа = Кандидат_K + 1
    Інакше:
        [Це означає f(x) ≤ Кандидат_K]
        Висока_межа = Кандидат_K

Повернути Низька_межа
```

Покроковий аналіз складності:
- Початковий інтервал пошуку дорівнює `2ⁿ`.
- Кожен виклик оракула зменшує інтервал удвічі.
- Кількість кроків бінарного пошуку дорівнює `log2(2ⁿ) = n`.

Оскільки кількість змінних `n` є поліноміальною від довжини входу, детермінована машина обчислює точне значення `f(x) ∈ #P` за `n` поліноміальних запитів до оракула PP.

Це доводить, що `P──────── ⊆ Pᵖᵖ`. Зворотне вміщення `Pᵖᵖ ⊆ P────────` є очевидним, оскільки знаючи точне число `f(x)`, детермінована машина за 1 крок порівнює його з порогом.

Отже, `Pᵖᵖ = P────────`. ∎

## 5. Алгебраїчний крах ампліфікації Чернова для ерадикації хиби

Пояснимо математичну причину, чому неможливо зменшити хибу алгоритмів класу PP за поліноміальний час.

У класі BPP імовірність прийняття `p` задовольняє умову `|p - 1/2| ≥ ε`, де `ε = 1/nᶜ` для деякої константи `c`.

За нерівністю Чернова, для `N` незалежних запусків машини імовірність того, що мажоритарне голосування похибить, обмежена зверху:

```
P_error ≤ exp( -2 · N · ε² )
```

Щоб зменшити імовірність хиби до малого значення `δ = 2⁻ᵏ`, необхідно виконати кількість запусків:

```
N = O( (1 / ε²) · ln(1 / δ) )       [нерівність Чернова: виражаємо кількість запусків]
  = O( (nᶜ)² · k )                  [підставляємо ε = 1/nᶜ та ln(1/δ) = O(k)]
  = O( n²ᶜ · k )                    [спрощуємо показники степеня]
```

Оскільки `n²ᶜ · k` є поліномом від `n`, ампліфікація в BPP виконується за поліноміальний час.

У класі PP зазор між `x ∈ L` та `x ∉ L` може становити `ε = 2⁻ᵖ⁽ⁿ⁾`.
Підставивши це значення в формулу оцінки кількості випробувань Чернова, отримуємо:

```
N = O( 1 / (2⁻ᵖ⁽ⁿ⁾)² )              [підставляємо експоненційно малий зазор ε = 2⁻ᵖ⁽ⁿ⁾]
  = O( (2ᵖ⁽ⁿ⁾)² )                   [підносимо від'ємну степень до знаменника]
  = O( 2²ᵖ⁽ⁿ⁾ )                     [перемножуємо показники степеня]
```

Кількість запусків `N = O(2²ᵖ⁽ⁿ⁾)` зростає експоненційно від розміру входу. Жоден поліноміальний алгоритм не здатний виконати експоненційну кількість фізичних випробувань. Це доводить математичну неможливість перетворення алгоритму класу PP на практичний алгоритм із малим рівнем хиби за поліноміальний час.
