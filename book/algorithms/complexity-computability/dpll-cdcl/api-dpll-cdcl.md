# 📋 Інтерфейс SAT-солверів та специфікація формату DIMACS CNF

Ця вставка містить структурну специфікацію текстового формату DIMACS CNF, який є міжнародним стандартом подання булевих формул у КНФ, а також розширений програмний інтерфейс (API), правила володіння пам'яттю, механізми інкрементного розв'язання під допущеннями, специфікацію трасування доведень DRAT та параметри конфігурації для інтеграції CDCL SAT-солверів у прикладне програмне забезпечення.

## 1. Специфікація текстового формату DIMACS CNF

Формат DIMACS (створений Центром дискретної математики та теоретичної інформатики США) є лінійним ASCII-форматом для збереження КНФ-формул. Він використовується як вхідний стандарт для змагань SAT Competition та інструментів верифікації апаратури і програмного забезпечення.

### Правила синтаксису та обробки крайових випадків у DIMACS CNF

1. **Рядки коментарів:** починаються з символу `c` у першій позиції рядка. Вони можуть містити будь-яку текстову інформацію (назву проблеми, параметри генерації, авторство) і повністю ігноруються парсером.
2. **Рядок специфікації (Header Line):** повинен передувати всім диз'юнктам і мати точний формат:
   ```text
   p cnf <NUM_VARIABLES> <NUM_CLAUSES>
   ```
   де `<NUM_VARIABLES>` — позитивне ціле число, що задає максимальний індекс змінної, а `<NUM_CLAUSES>` — кількість диз'юнктів у файлі.
3. **Опис дизюнктів:** кожен диз'юнкт подається послідовністю значущих цілих чисел, розділених пробілами або переносом рядка.
   - Позитивне число `k` (від `1` до `NUM_VARIABLES`) відповідає стверджувальному літералу `x[k]`.
   - Від'ємне число `-k` відповідає запереченню `¬x[k]`.
   - **Термінатор диз'юнкта:** кожний диз'юнкт **обов'язково завершується числом `0`**.
4. **Порожній диз'юнкт:** подається окремим термінатором `0` на початку рядка і означає явне утворення конфлікту (нездійсненність формули).
5. **Обробка крайових випадків у парсері:**
   - **Тавтологічні диз'юнкти:** якщо диз'юнкт містить одночасно літерали `x` та `-x` (наприклад, `1 -1 2 0`), парсер повинен проігнорувати такий диз'юнкт, оскільки він задовольняється при будь-якій інтерпретації (`x ∨ ¬x ≡ 1`).
   - **Дубльовані літерали:** якщо диз'юнкт містить однаковий літерал декілька разів (наприклад, `1 1 2 0`), парсер видаляє дублікати (`1 2 0`).
   - **Одиничні диз'юнкти на вході:** диз'юнкти з одного літерала (наприклад, `5 0`) фіксуються на рівні рішення 0 ще до початку обчислювального циклу BCP.

### Формальна граматика у формі Бэкуса — Наура (BNF)

```text
<dimacs_file>  ::= <comment_lines> <header_line> <clause_list>
<comment_line> ::= "c" <text> "\n"
<header_line>  ::= "p" "cnf" <positive_int> <positive_int> "\n"
<clause_list>  ::= <clause> | <clause> <clause_list>
<clause>       ::= <literal_seq> "0" "\n"
<literal_seq>  ::= <literal> | <literal> <literal_seq>
<literal>      ::= <non_zero_int>
```

### Альтернативні формати розширення DIMACS

- **wcnf (Weighted MaxSAT):** використовується для задач умовного оптимізування, де кожному диз'юнкту присвоюється вага або статус (тверде чи м'яке обмеження).
- **qdimacs (Quantified Boolean Formulas):** розширює КНФ кванторами загальності `∀` та існування `∃` для вираження задач класу PSPACE.

### Приклад файлу у форматі DIMACS CNF

Формула `F = (x₁ ∨ ¬x₂ ∨ x₃) ∧ (¬x₁ ∨ x₂) ∧ (¬x₃)` подається файлом:

```text
c Приклад КНФ-формули у стандарту DIMACS CNF
c Трьохзмінна формула з трьома диз'юнктами
p cnf 3 3
1 -2 3 0
-1 2 0
-3 0
```

## 2. Специфікація програмного C/C++ API для SAT-солверів

Сучасні CDCL SAT-солвери (такі як MiniSat, Glucose, CaDiCaL) надають програмний інтерфейс для динамічного створення змінних, додавання диз'юнктів та отримання розв'язку.

### Таблиця кодів повернення та типів даних

| Тип / Код | Назва | Значення та опис |
| :--- | :--- | :--- |
| `sat_result_t` | `SAT_RESULT_SAT` | `10` — Формула є здійсненною (знайдено модель) |
| `sat_result_t` | `SAT_RESULT_UNSAT` | `20` — Формула є нездійсненною (існує доведення ⊥) |
| `sat_result_t` | `SAT_RESULT_UNKNOWN` | `0` — Обчислення перервано за таймаутом або лімітом |
| `lit_t` | `sat_makeres_pos(v)` | Створення позитивного літерала `+v` (`2v`) |
| `lit_t` | `sat_makeres_neg(v)` | Створення негативного літерала `-v` (`2v + 1`) |

### Правила володіння пам'яттю та безпека викликів API

1. **Життєвий цикл екземпляра:** функція `sat_solver_new()` повертає непрозорий вказівник `sat_solver_t*`. Клієнт відповідає за звільнення пам'яті через `sat_solver_free()`.
2. **Копіювання масивів:** масиви літералів, передані у `sat_solver_add_clause()`, копіюються внутрішнім алокатором солвера. Клієнт може безпечно звільняти передані буфери одразу після виклику.
3. **Асинхронне скасування:** виклик `sat_solver_solve()` запускає обчислювальне ядро у поточному потоці виконання. Для підтримки скасування обчислень з інших потоків (наприклад, при встановленні таймауту) солвер надає функцію зворотного виклику `sat_solver_set_terminate(s, callback, state)`.

#define SAT_SOLVER_API_HPP

#include <optional>
#include <cstdint>

namespace sat {

enum class State : uint8_t {
    Unknown = 0,
    Sat     = 10,
    Unsat   = 20

enum class LBool : int8_t {
    Undefined = -1,
    False     = 0,
    True      = 1

inline Lit make_lit(Var v, bool sign) noexcept {
    return sign ? -v : v;

    virtual bool add_clause(std::span<const Lit> lits) = 0;

## 3. Інкрементне розв'язання під допущеннями (Incremental Solving) та UNSAT Core

Сучасний режим **Incremental SAT Solving** дозволяє викликати солвер багаторазово на одній і тій самій базі диз'юнктів із тимчасовим накладанням гіпотез (Assumptions).

При виклику `solve_assumptions([a₁, a₂, ..., a_k])` солвер призначає вказані літерали на рівні прийняття рішення 0 як тимчасові гіпотези. Якщо виявляється конфлікт, солвер виводить **Unsat Core** — мінімальну підмножину допущення, яка викликала нездійсненність, і повертає стан `UNSAT` без втрати вивчених раніше дизюнктів. Це використовується у SAA/SMT-солверах та інструментах верифікації Bounded Model Checking.

### Семантика збереження вивчених диз'юнктів при інкрементних викликах

1. Диз'юнкти, вивчені під час виклику з допущеннями `solve_assumptions()`, є логічними наслідками початкової КНФ і залишаються цілком коректними для всіх наступних викликів `solve()`, навіть якщо самі допущення зміняться.
2. При видаленні або зміні допущень на наступному кроці солвер не видаляє вивчені диз'юнкти з бази, а лише скасовує тимчасові BCP-призначення у стеку до рівня 0.
3. Функція `get_unsat_core()` аналізує граф імплікацій останнього конфлікту та повертає точну підмножину допущень, які безпосередньо спричинили суперечність. Це використовується в алгоритмі Fu-Malik для розв'язання задач MaxSAT.

## 4. Специфікація DRAT (Delete Resolution Asymmetry Trace) та сертифікація UNSAT

При верифікації критичного програмного та апаратного забезпечення відповідь `UNSAT` не може прийматися на віру, оскільки сам SAT-солвер містить десятки тисяч рядків складного коду і може володіти скрітими помилками.

Для підтвердження коректності результату `UNSAT` сучасні солвери генерують **сертифікат нездійсненності (UNSAT Certificate)** у форматі DRAT:
- Кожен вивчений диз'юнкт записується у форматі DRAT як рядок літералів, що завершується `0`.
- Кожен видалений диз'юнкт записується з префіксом `d`.
- Незалежна перевірочна утиліта (така як `drat-trim` або `lrat-check`) зчитує початкову КНФ та DRAT-файл і відновлює ланцюжок резолюцій від початкових диз'юнктів до порожнього диз'юнкта `⊥`. Якщо перевірка успішна, результат `UNSAT` вважається математично доведеним.

## 5. Специфікація CLI-параметрів та форматів керування CDCL-солверами

При запуску CDCL-солверів як окремих консольних утиліт (консольний інтерфейс CaDiCaL, Kissat, MiniSat) керування алгоритмічними фазами здійснюється через прапори командного рядка:

| Прапор CLI | Тип / Значення | Опис впливу на алгоритм |
| :--- | :--- | :--- |
| `--restart=<mode>` | `luby` / `geom` | Схема перезапусків (послідовність Любі чи геометрична прогресія) |
| `--lbd-cut=<int>` | За замовчуванням `6` | Поріг LBD, вище якого вивчені диз'юнкти періодично видаляються |
| `--phase-saving=<int>`| `0` / `1` / `2` | Режим збереження фази полярності змінних |
| `--elim=<bool>` | `true` / `false` | Увімкнення фази препроцесингу (Bounded Variable Elimination) |
| `--proof=<file>` | Шлях до `.drat` | Запис траси доведення нездійсненності у форматі DRAT |

Коди повернення бінарного файлу згідно з міжнародними стандартами SAT Competition:
- `10` — Формула здійсненна (`SAT`). У стандартний вивід `stdout` друкується вектор моделей у форматі `v 1 -2 3 0`.
- `20` — Формула нездійсненна (`UNSAT`). У `stdout` друкується рядок `s UNSATISFIABLE`.
- `0` — Обчислення перервано за часом чи пам'яттю (`UNKNOWN`).
