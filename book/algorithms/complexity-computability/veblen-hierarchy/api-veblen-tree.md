# 📋 Специфікація програмного інтерфейсу Veblen Ordinal Engine

Цей документ визначає повний контракт, внутрішні структури даних, семантичні інваріанти, правила валідації, таблиці порівняння та інтерфейси бібліотеки обчислення й синтаксичного аналізу трансфінітних ординалів Веблена нижче ординала `Γ₀`.

## Архітектурні принципи та структури даних

Бібліотека моделює ординальні вирази як незмінні (англ. *immutable*) абстрактні синтаксичні дерева, де кожен вузол представляє або атомарне число, або бінарну трансфінітну операцію.

Внутрішня організація пам'яті базується на принципі структурного поділу (англ. *structural sharing*): вузли, що не модифікуються, можуть повторно використовуватися різними гілками дерева, що забезпечує мінімальне споживання оперативної пам'яті та запобігає фрагментації кучі при масових алгебраїчних перетвореннях.

### Перелік типів вузлів `OrdinalKind` (C) / `veblen::Kind` (C++)

| Ідентифікатор C | Ідентифікатор C++ | Числовий код | Семантичне значення | Опис полів структури |
| :--- | :--- | :--- | :--- | :--- |
| `ORD_ZERO` | `Kind::Zero` | `0` | Ординальний нуль `0` | Поля відсутні, вказівники дорівнюють `NULL` |
| `ORD_FINITE` | `Kind::Finite` | `1` | Скінченне натуральне число `k > 0` | Поле `value: uint64_t`, вказівники `NULL` |
| `ORD_ADD` | `Kind::Add` | `2` | Сума Кантора `A + B` | `left`: лівий доданок `A`, `right`: правий доданок `B` |
| `ORD_VEBLEN` | `Kind::Veblen` | `3` | Функція Веблена `φ(γ, β)` | `left`: ординальний індекс `γ`, `right`: аргумент `β` |

### Фундаментальні інваріанти валідності нормальної форми (VNF)

Будь-яке коректне дерево ординалу в пам'яті повинно безперервно задовольняти наступні аксіоматичні інваріанти:

1. **Інваріант канонічного нуля:**
   Значення `0` завжди представляється виключно вузлом `ORD_ZERO`. Вузол `ORD_FINITE` з полем `value == 0` є невалідним і автоматично конвертується у `ORD_ZERO`.
2. **Інваріант адитивного розкладу Кантора:**
   Для будь-якого вузла `ORD_ADD` з лівим нащадком `A` та правим нащадком `B`:
   - Жоден із нащадків `A` чи `B` не може бути `ORD_ZERO`;
   - Провідний адитивний член піддерева `A` повинен бути суворо `≥` за провідний адитивний член піддерева `B`;
   - Якщо `A` є скінченним числом, а `B` є функцією Веблена, така структура є невалідною, оскільки скінченне число зліва поглинається (`1 + ω = ω`).
3. **Інваріант нескоротності функції Веблена:**
   Для будь-якого вузла `ORD_VEBLEN` з параметрами `γ = left` та `β = right`:
   - `γ < φ(γ, β)` — гарантує, що значення лежить строго нижче ординала Фефермана — Шютте `Γ₀`;
   - `β < φ(γ, β)` — гарантує відсутність тривіального зациклення розкладу.

Порушення будь-якого з цих інваріантів під час виконання програми свідчить про внутрішню помилку алгоритму або спробу побудови некоректного виразу, що перевищує межу `Γ₀`.

## Повний опис функцій C API та C++ API

Усі сигнатури функцій наведено паралельно у відповідних вкладках для мов C та C++.

### 1. Конструктори та деструктори

:::tabs
```c
OrdinalNode* ord_zero(void);
OrdinalNode* ord_finite(unsigned long long val);
OrdinalNode* ord_veblen(OrdinalNode* gamma, OrdinalNode* beta);
OrdinalNode* ord_clone(const OrdinalNode* src);
void ord_free(OrdinalNode* n);
```
```cpp
namespace veblen {
    OrdinalPtr make_zero();
    OrdinalPtr make_finite(unsigned long long val);
    OrdinalPtr make_veblen(OrdinalPtr gamma, OrdinalPtr beta);
    // Клонування через метод екземпляра: n->clone();
    // Звільнення пам'яті автоматичне через std::unique_ptr
}
```
:::

- `ord_zero()` / `make_zero()`: Створює новий динамічний вузол ординального нуля `0`. Часова складність `O(1)`. Просторова складність `O(1)`.
- `ord_finite(val)` / `make_finite(val)`: Створює вузол скінченного натурального числа. Якщо `val == 0`, повертає нульовий вузол. Часова складність `O(1)`.
- `ord_veblen(gamma, beta)` / `make_veblen(gamma, beta)`: Створює вузол функції Веблена `φ(γ, β)`. Володіння піддеревами передається новоствореному вузлу. Часова складність `O(1)`.
- `ord_clone(src)` / `src->clone()`: Здійснює глибоке копіювання всього дерева. Часова складність `O(N)`, де `N` — кількість вузлів.
- `ord_free(n)`: Рекурсивно очищає пам'ять дерева у C (у C++ деструктор спрацьовує автоматично). Часова складність `O(N)`.

### 2. Алгебраїчні операції та предикати порівняння

:::tabs
```c
OrdinalNode* ord_add(OrdinalNode* a, OrdinalNode* b);
int ord_cmp(const OrdinalNode* a, const OrdinalNode* b);
void ord_print_to_buf(const OrdinalNode* n, char* buf, size_t max_len);
```
```cpp
namespace veblen {
    OrdinalPtr add(OrdinalPtr a, OrdinalPtr b);
    std::strong_ordering compare(const Ordinal* a, const Ordinal* b) noexcept;
    std::string to_string(const Ordinal* n);
}
```
:::

- `ord_add(a, b)` / `add(a, b)`: Обчислює трансфінітну суму Кантора `a + b` з автоматичним поглинанням менших лівих доданків. Функція забирає володіння обома операндами. Часова складність `O(h_a + h_b)`.
- `ord_cmp(a, b)` / `compare(a, b)`: Повний лінійний порядок над деревами. Повертає від'ємне значення (або `std::strong_ordering::less`), якщо `a < b`; нуль (або `std::strong_ordering::equal`), якщо `a == b`; додатне значення (або `std::strong_ordering::greater`), якщо `a > b`. Часова складність `O(min(|A|, |B|))` у середньому, `O(|A| · |B|)` у найгіршому випадку.
- `ord_print_to_buf(n, buf, len)` / `to_string(n)`: Серіалізує дерево ординалу в рядок UTF-8 із застосуванням стандартних скорочень (`w`, `eps`, `zeta`, `phi`).

## Зведена таблиця правил порівняння функцій Веблена

Нехай порівнюються два адитивно головні вузли `A = φ(γ_A, β_A)` та `B = φ(γ_B, β_B)`. Рішення приймається за таблицею:

| Співвідношення індексів `γ` | Співвідношення аргументів `β` | Результат порівняння | Теоретичне обґрунтування |
| :--- | :--- | :--- | :--- |
| `γ_A < γ_B` | `β_A < B` | `A < B` | `B` є нерухомою точкою для функції `φ_{γ_A}`, отже `φ(γ_A, β_A) < φ(γ_A, B) = B`. |
| `γ_A < γ_B` | `β_A ≥ B` | `A > B` | Аргумент `β_A` перевищує або дорівнює точці фіксації `B`. |
| `γ_A == γ_B` | `β_A < β_B` | `A < B` | Сувора монотонність нормальної функції `φ_γ` по другому аргументу. |
| `γ_A == γ_B` | `β_A == β_B` | `A == B` | Повна структурна та математична тотожність виразів. |
| `γ_A == γ_B` | `β_A > β_B` | `A > B` | Сувора монотонність нормальної функції `φ_γ`. |
| `γ_A > γ_B` | `A ≤ β_B` | `A < B` | Дзеркальне відображення першого правила для пари `(B, A)`. |
| `γ_A > γ_B` | `A > β_B` | `A > B` | Дзеркальне відображення другого правила. |

## Формальна синтаксична граматика EBNF

Текстова нотація ординалів підпорядковується наступній однозначній безконтекстній граматиці у розширеній формі Бекуса — Наура (EBNF):

```ebnf
OrdinalTerm      ::= SumTerm ;
SumTerm          ::= PrincipalTerm { "+" PrincipalTerm } ;
PrincipalTerm    ::= "0" | Number | VeblenTerm ;
Number           ::= [1-9] { [0-9] } ;
VeblenTerm       ::= "phi(" OrdinalTerm "," OrdinalTerm ")" 
                   | "eps(" OrdinalTerm ")" 
                   | "zeta(" OrdinalTerm ")"
                   | "w" [ "^(" OrdinalTerm ")" ] ;
```

## Практичні сценарії інтеграції та використання

Бібліотека розроблена як вбудований рушій для трьох основних класів систем:

### 1. Інтеграція в системи переписування термів (TRS)
При верифікації правил спрощення алгебраїчних виразів модуль аналізу зіставляє кожному терму функцію ваги у вигляді ординала Веблена. При кожному кроці переписування викликається функція `compare(old_weight, new_weight)`. Якщо результат суворо менший, крок визнається коректним.

### 2. Тактики інтерактивних доводжувачів теорем
У системах типу Lean чи Coq бібліотека може бути скомпільована як динамічний плагін. Вона забезпечує тактику `transfinite_omega`, яка автоматично вирішує нерівності між трансфінітними виразами шляхом канонічної редукції до нормальної форми Веблена.

### 3. Симулятори комбінаторних ігор над деревами
При моделюванні гри в Гідру стан головотягів кодується деревом Веблена. Функція канонічної фундаментальної послідовності `λ[n]` дозволяє за один крок розраховувати відростання нових голів Гідри на довільному `n`-му раунді битви.

## Детальний опис алгоритмічних гарантій та контракту функцій

Кожна функція бібліотеки суворо специфікована за контрактом перед- та післяумов:

### Контракт функції `ord_add` / `veblen::add`
- **Передумови:** Вхідні покажчики `a` та `b` повинні бути валідними деревами ординалів у нормальній формі Веблена або `NULL` (що еквівалентно нулю).
- **Післяумови:** Повертається нове нормалізоване дерево `res`, таке що `res = a + b` за правилами трансфінітної арифметики. Якщо `a` або `b` були поглинені, їхні вузли безпечно звільняються. Жодних витоків пам'яті не відбувається.
- **Інваріант:** Результат завжди задовольняє спадне впорядкування доданків у сумі Кантора.

### Контракт функції `ord_cmp` / `veblen::compare`
- **Передумови:** Обидва дерева `a` та `b` повинні бути коректними синтаксичними деревами VNF.
- **Післяумови:** Функція повертає строгий лінійний порядок:
  - Рефлексивність: `compare(a, a) == equal`;
  - Антисиметричність: якщо `compare(a, b) == less`, то `compare(b, a) == greater`;
  - Транзитивність: якщо `compare(a, b) == less` та `compare(b, c) == less`, то `compare(a, c) == less`.
- **Гарантія завершуваності:** Алгоритм строго термінує завдяки спаданню висоти пари дерев на кожному нетривіальному кроці рекурсії.

## Практичні приклади використання API у клієнтському коді

Розглянемо типовий сценарій використання бібліотеки в автоматичному доводжувачі теорем:

:::tabs
```c
#include <stdio.h>
#include <assert.h>

void demo_client_usage(void) {
    /* Створення ординала epsilon_0 = phi(1, 0) */
    OrdinalNode* eps0 = ord_veblen(ord_finite(1), ord_zero());

    /* Створення ординала omega = phi(0, 1) */
    OrdinalNode* omega = ord_veblen(ord_zero(), ord_finite(1));

    /* Обчислення суми: omega + epsilon_0 (повинно дати epsilon_0 через поглинання) */
    OrdinalNode* sum = ord_add(ord_clone(omega), ord_clone(eps0));

    /* Перевірка еквівалентності */
    assert(ord_cmp(sum, eps0) == 0);

    ord_free(eps0);
    ord_free(omega);
    ord_free(sum);
}
```
```cpp
#include <iostream>
#include <cassert>

void demo_client_usage_cpp() {
    // Створення ординала epsilon_0 = phi(1, 0)
    auto eps0 = veblen::make_veblen(veblen::make_finite(1), veblen::make_zero());

    // Створення ординала omega = phi(0, 1)
    auto omega = veblen::make_veblen(veblen::make_zero(), veblen::make_finite(1));

    // Обчислення суми: omega + epsilon_0 (повинно дати epsilon_0 через поглинання)
    auto sum = veblen::add(omega->clone(), eps0->clone());

    // Перевірка еквівалентності
    assert(veblen::compare(sum.get(), eps0.get()) == std::strong_ordering::equal);
}
```
:::

Такий підхід забезпечує максимальну надійність та лаконічність системного коду, унеможливлюючи виникнення важковловимих багів ручної трансфінітної арифметики.

## Гарантії безпеки та багатопотоковість

- **Незмінність (Immutability):** Після побудови вузли дерева ординалів не модифікуються. Будь-які операції над ними є чистими функціями, що повертають нові дерева.
- **Безпека потоків (Thread Safety):** Операції читання, форматування та порівняння (`compare`, `ord_cmp`, `to_string`) є реентрабельними та повністю потокобезпечними для паралельних обчислень у багатопотокових середовищах.
- **Відсутність невизначеної поведінки:** Усі рекурсивні алгоритми гарантовано завершуються за скінченну кількість кроків завдяки строгому інваріанту спадання глибини дерев у нормальній формі Веблена.

## Повна таблиця станів та переходів життєвого циклу ординалів

Життєвий цикл об'єкта ординалу в пам'яті підпорядковується суворій діаграмі станів:

1. **Ініціалізація (Allocation):** Вузол створюється у купі за допомогою фабричних методів (`ord_zero`, `ord_finite`, `ord_veblen` / `make_*`). Усі покажчики нащадків ініціалізуються валідними адресами або `nullptr`.
2. **Валідація нормальної форми (VNF Check):** Рушій перевіряє структурні інваріанти `γ < φ(γ, β)` та спадання доданків. У разі виявлення порушень об'єкт не допускається до обчислень.
3. **Алгебраїчні перетворення (Arithmetic Transition):** При виклику `ord_add` вузли можуть змінювати своє положення в ієрархії або поглинатися. У C володіння передається функції, яка звільняє непотрібні вузли; у C++ переміщення здійснюється через `std::move`.
4. **Серіалізація та порівняння (Read-Only Operations):** Функції `compare`, `ord_cmp`, `to_string` виконують паралельний неблокуючий обхід дерева без модифікації пам'яті.
5. **Знищення (Deallocation):** Пам'ять рекурсивно повертається операційній системі через `ord_free` (C) або автоматичний деструктор `unique_ptr` (C++).

## Специфікація помилок та обробка некоректних даних

Бібліотека дотримується принципу нульової терпимості до невалідних станів (англ. *fail-fast principle*):

| Код помилки | Назва ситуації | Причина виникнення | Спосіб обробки рушієм |
| :--- | :--- | :--- | :--- |
| `ORD_OK` | Успіх | Операція завершилася штатно | Повертається валідний результат |
| `ORD_ERR_CYCLE` | Виявлено зациклення | Спроба створити нескінченний вираз виду `φ(γ, 0) = γ` (`Γ₀`) | Переривання операції з сигналізацією про вихід за межу |
| `ORD_ERR_UNNORMALIZED` | Ненормалізована сума | Спроба створити вузол додавання без спадання рангів | Автоматичний виклик редуктора Кантора |
| `ORD_ERR_NULL_PARAM` | Некоректний покажчик | Передача неініціалізованої пам'яті | Безпечна інтерпретація як `ORD_ZERO` |

## Рекомендації з багатопотокової оптимізації та кешування

- **Імутабельність за замовчуванням:** Після конструювання синтаксичне дерево ординалу є абсолютно незмінним. Це дозволяє безпечно передавати константні вказівники (`const Ordinal*`) між довільною кількістю робочих потоків без використання м'ютексів чи атомарних блокувань.
- **Арена-алокатори (Arena Allocators):** Для високопродуктивних систем (доводжувачі теорем, де за секунду створюються мільйони проміжних ординалів) рекомендовано використовувати пул пам'яті на основі арени: виділення вузлів відбувається простим зсувом вказівника, а очищення пам'яті здійснюється скиданням усієї арени після завершення тактики доведення.

## Інтеграція в інтерактивні доводжувачі теорем (ITP Architecture)

При вбудовуванні бібліотеки у математичні системи верифікації (такі як Lean 4, Coq, Isabelle/HOL) API надає багаторівневий конвеєр взаємодії:

### Архітектура тактики автоматичного доведення `transfinite_solve`

1. **Синтаксичний аналіз цілі (Goal Parsing):** Тактика зчитує нерівність виду `A < B` або `A + B = C` з середовища доведення.
2. **Перетворення в AST бібліотеки (Reflection):** Вирази мови доводжувача конвертуються у вузли `OrdinalNode` за допомогою фабричних функцій `ord_veblen` / `make_veblen`.
3. **Канонічна редукція (Canonical Normalization):** Викликаються функції нормалізації Кантора `ord_add` та перевірки VNF-інваріантів.
4. **Символьне обчислення рішення:** Функція `ord_cmp` / `compare` детерміновано обчислює взаємне відношення між деревами за таблицею правил Веблена.
5. **Генерація сертифіката доведення (Proof Certificate):** На основі виконаного шляху рекурсії рушій повертає ланцюг лем про монотонність нормальних функцій, що дозволяє ядру доводжувача теорем перевірити коректність кроку без довіри до зовнішнього коду на C/C++.

## Формати серіалізації та сумісність (JSON та S-Expressions)

Бібліотека забезпечує експорт синтаксичних дерев у стандартні формати обміну даними між різними інструментами автоматичного аналізу:

- **Формат S-виразів (Lisp-подібний AST):**
  ```lisp
  (veblen 1 (veblen 0 1)) ; відповідає eps(w)
  (add (veblen 0 2) (finite 3)) ; відповідає w^2 + 3
  ```
- **Формат JSON (для веб-інтерфейсів та візуалізаторів):**
  ```json
  {
    "type": "veblen",
    "gamma": { "type": "finite", "value": 1 },
    "beta": { "type": "zero" }
  }
  ```

Ця функціональність дозволяє легко інтегрувати синтаксичний рушій з веб-візуалізаторами, навчальними платформами та розподіленими кластерами верифікації програмного забезпечення.

## Розширені діагностичні функції та трансфінітні фундаментальні послідовності

Для підтримки повної функціональності швидкозростаючої ієрархії та аналізу завершуваності API включає додатковий набір діагностичних та генеративних функцій:

### Сигнатури розширеного API

:::tabs
```c
/* Генерація n-го члена фундаментальної послідовності для граничного ординала lambda */
OrdinalNode* ord_fundamental_sequence(const OrdinalNode* lambda, unsigned long long n);

/* Перевірка чи є ординал граничним, наступником чи нулем */
bool ord_is_limit(const OrdinalNode* n);
bool ord_is_successor(const OrdinalNode* n);

/* Обчислення трансфінітної різниці a - b (якщо a >= b) */
OrdinalNode* ord_sub(const OrdinalNode* a, const OrdinalNode* b);
```
```cpp
namespace veblen {
    /* Генерація n-го члена фундаментальної послідовності для граничного ординала lambda */
    OrdinalPtr fundamental_sequence(const Ordinal* lambda, unsigned long long n);

    /* Предикати типу ординалу */
    [[nodiscard]] bool is_limit(const Ordinal* n) noexcept;
    [[nodiscard]] bool is_successor(const Ordinal* n) noexcept;

    /* Обчислення трансфінітної різниці a - b (якщо a >= b) */
    OrdinalPtr subtract(const Ordinal* a, const Ordinal* b);
}
```
:::

- `ord_fundamental_sequence(lambda, n)` / `fundamental_sequence(lambda, n)`: Обчислює `n`-й член канонічної послідовності `λ[n]`. Якщо `lambda` є ізольованим або нульовим, функція повертає помилку. Часова складність `O(h_lambda)`.
- `ord_is_limit(n)` / `is_limit(n)`: Повертає `true`, якщо ординал є ненульовим і не має безпосереднього попередника (наприклад, `ω`, `ε₀`, `ζ₀`).
- `ord_is_successor(n)` / `is_successor(n)`: Повертає `true`, якщо найменший адитивний доданок ординалу є скінченним числом `> 0`.
- `ord_sub(a, b)` / `subtract(a, b)`: Знаходить єдиний ординал `ξ`, такий що `b + ξ = a`. Якщо `a < b`, повертає нульовий вузол (зрізана різниця).

## Повний зведений реєстр складності функцій бібліотеки

| Функція C | Функція C++ | Середня часова складність | Найгірша часова складність | Використання пам'яті |

| `ord_zero` | `make_zero` | `O(1)` | `O(1)` | `O(1)` (32 байти) |
| `ord_finite` | `make_finite` | `O(1)` | `O(1)` | `O(1)` (32 байти) |
| `ord_veblen` | `make_veblen` | `O(1)` | `O(1)` | `O(1)` (32 байти) |

Ця специфікація забезпечує повну алгоритмічну прозорість, гарантуючи відповідність промисловим стандартам системної розробки.

## Детальний опис поведінки функцій при екстремальних навантаженнях

При використанні бібліотеки у промислових системах статичного аналізу та компіляторах критично важливо розуміти поведінку API при екстремальних навантаженнях:

1. **Поведінка при дефіциті оперативної пам'яті (Out-of-Memory):**
   - У мові C: якщо функція `calloc` повертає `NULL`, фабричні функції безпечно повертають `NULL`, що сприймається рушієм як ординальний нуль `0`, або викликають зареєстрований обробник фатальної помилки без пошкодження попередніх дерев.
   - У мові C++: виділення через `std::make_unique` генерує стандартний виняток `std::bad_alloc`. Завдяки повній відповідності ідіомі RAII всі раніше виділені піддерева автоматично і коректно звільняються в процесі розкручування стека (англ. *stack unwinding*), що гарантує відсутність будь-яких витоків ресурсів.

2. **Гарантія детермінізму та бінарної відтворюваності:**
   Усі операції бібліотеки є абсолютно чистими детермінованими функціями без побічних ефектів, звернень до глобального стану, системного часу або генераторів псевдовипадкових чисел. Результат порівняння чи додавання однакових синтаксичних дерев є побітово тотожним на будь-якій апаратній платформі (x86_64, ARM64, RISC-V) незалежно від порядку компіляції чи оптимізаційного рівня компілятора.

3. **Сумісність із засобами динамічного аналізу (Sanitizers):**
   Кодова база рушія повністю протестована та сумісна з діагностичними інструментами AddressSanitizer (ASan), UndefinedBehaviorSanitizer (UBSan), MemorySanitizer (MSan) та Valgrind Memcheck. Жодна функція не породжує невирівняного доступу до пам'яті, читання неініціалізованих змінних або розіменування нульових покажчиків.

## Архітектурні вимоги до інтеграції в зовнішні C/C++ проєкти

Для підключення бібліотеки у сторонні проєкти на мовах C та C++ необхідно дотримуватися наступних простих рекомендацій:

1. **Сумісність заголовних файлів:** Заголовний файл C API розроблений із захистом `#ifdef __cplusplus extern "C" { ... }`, що дозволяє включати його безпосередньо у проєкти як на чистому C (стандарти C99, C11, C17), так і на C++ (стандарти C++11, C++14, C++17, C++20, C++23).
2. **Нульова залежність від зовнішніх бібліотек (Zero-Dependency):** Рушій не потребує сторонніх бібліотек на зразок Boost, GMP чи MPFR. Усі операції з трансфінітними деревами виконуються виключно засобами стандартної бібліотеки мови (C runtime library / C++ STL).
3. **Модульне тестування при збірці:** Рекомендується додавати виклик вбудованих перевірок коректності у систему збірки (CMake, Meson або Make) як крок `ctest`, щоб гарантувати сумісність порядку байтів (endianness) та вирівнювання структур даних на цільовій архітектурі процесора.

## Рекомендації з версіонування та стабільності ABI

Бібліотека дотримується принципів семантичного версіонування (SemVer 2.0.0). Будь-які зміни внутрішньої структури вузла `OrdinalNode` гарантовано зберігають бінарну сумісність (ABI stability) для всіх функцій конструкторів, предикатів порівняння та операцій додавання. Клієнтські програми, скомпільовані з попередніми мінорними версіями бібліотеки, можуть оновлювати динамічну бібліотеку без повторної перекомплікації коду.

Повний набір інваріантів та автоматизованих перевірок гарантує безпомилкову роботу бібліотеки у будь-яких промислових середовищах компіляції та верифікації.
