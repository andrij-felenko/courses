Проте спроба перевірити **всі** можливі нескінченні шляхи виконання призводить до того, що аналізатор зависає сам, так і не віддавши остаточного вироку. ## 1. Асиметрія перевірки та спростування

У класичній булевій логіці твердження та його заперечення здаються повністю рівноправними. Якщо ми вміємо за скінченний час перевіряти, чи є число парним, ми автоматично вміємо за той самий скінченний час перевіряти, чи є воно непарним. Проте у світі теорії обчислюваності ця природна симетрія руйнується, щойно ми переходимо від скінченних математичних об'єктів до потенційно нескінченних обчислювальних процесів.

Припустимо, що маємо підмножину натуральних чисел `S ⊆ ℕ` (або множину рядків `S ⊆ Σ*` у деякому алфавіті) та алгоритм `M`. Ми подаємо алгоритму число `x` і чекаємо на результати його роботи. Якщо елемент дійсно належить множині (`x ∈ S`), алгоритм `M` виконує серію послідовних кроків, зупиняється за скінчений час і повертає стверджувану відповідь «ТАК» (або 1). Проте якщо елемент **не належить** множині (`x ∉ S`), алгоритм `M` може повернути відповідь «НІ» (0), а може потрапити у нескінченний цикл і працювати вічно, не видаючи жодного вироку.

Така властивість в інформатиці називається **напіврозв'язністю** (англ. *semi-decidability*) або **напіввирішуваністю**. Множина `S`, для якої існує подібний алгоритм прийняття, називається **рекурсивно перелічною** (англ. *recursively enumerable*, скорочено **RE**).

![Асиметрія напіврозв'язності: зупинка гарантована лише для належних елементів](/book/algorithms/complexity-computability/recursively-enumerable-sets/img/re-asymmetry.svg)

*Дві відповіді напіввирішувача нерівноправні. Якщо елемент x належить множині S, алгоритм гарантовано зупиняється за скінченну кількість кроків k і дає стверджувану відповідь (ліворуч). Якщо ж елемент x не належить S, алгоритм потрапляє у нескінченний цикл, і вирок відсутності не настає ніколи (праворуч).*

Відмінність між розв'язними (рекурсивними) множинами та рекурсивно перелічними множинами полягає у ступені надійності алгоритму:
- **Розв'язна множина (Decidable / Recursive, клас R):** Існує алгоритм-вирішувач, який **завжди** зупиняється за скінченний час на будь-якому вхідному елементі `x` і дає чітку відповідь: 1 (належить) або 0 (не належить). Жодного зависання чи зациклення не допускається за жодних умов.
- **Рекурсивно перелічна множина (Recursively Enumerable, клас RE):** Існує алгоритм-напіввирішувач, який гарантовано зупиняється за скінченний час і повертає 1 **тільки тоді**, коли елемент належить множині (`x ∈ S`). Якщо ж `x ∉ S`, алгоритм має право зависнути вічно, оскільки відсутність елемента не вимагає стверджуваного сигналу.

Оця відсутність гарантії зупинки для «негативних» вхідних даних є ціною, яку доводиться платити за можливість описувати набагато ширший клас обчислювальних явищ.

### Фізичний та логічний корінь асиметрії
Чому виникає ця асиметрія? Її корінь криється у локальності підтвердження та глобальності спростування. Для того щоб підтвердити, що програма має помилку (наприклад, ділення на нуль), достатньо пред'явити **один скінченний сценарій** виконання (трасу), де ця помилка виникає. Симулятор може просто пробігтися цією трасою за `k` кроків і переконатися у її наявності. Проте для того щоб довести, що програма **ніколи** не поділить на нуль, довелося б перевірити нескінченну кількість усіх можливих вхідних даних та всіх можливих трас виконання. Скінченний спостерігач не здатний осягнути нескінченність за один крок.

## 2. Три еквівалентні обличчя однієї множини

Назва «рекурсивно перелічна» звучить як динамічний процес друку елементів, тоді як означення через напіввирішувач здається статичним фільтром. Подив полягає в тому, що ці два принципово різних підходи (а також третій — логічна проекція розв'язних відношень) описують **абсолютно один і той самий клас множин**.

Розглянемо три еквівалентні способи означення рекурсивно перелічної множини `S ⊆ ℕ`:

### Спосіб 1: Область визначення часткової функції (Обчислювальний фільтр)
Множина `S` є областю визначення деякої частково рекурсивної функції `φ[e]: ℕ → ℕ`:

```
S = dom(φₑ) = { x ∈ ℕ  ∣  φₑ(x) ↓ }
```

Тут програма `e` працює як тестер: ми запускаємо `φ[e](x)` і дивимося, чи зупиниться обчислення. Позначення `φ[e](x) ↓` означає зупинку за скінченну кількість кроків. Якщо обчислення зупинилося — `x` зараховується до `S`. Якщо зациклилося (`φ[e](x) ↑`) — `x` залишається поза множиною `S`.

### Спосіб 2: Область значень скрізь визначеної функції (Генератор / Друкар)
Множина `S` є або порожньою (`S = ∅`), або є областю значень (образом) деякої скрізь визначеної (загально рекурсивної) обчислюваної функції `g: ℕ → ℕ`:

```
S = img(g) = { g(0), g(1), g(2), g(3), ... }
```

У цьому підході існує спеціальна програма-друкар `g`, яка працює безкінечно і послідовно виводить на екран елементи множини `S`. Порядок виводу відповідає натуральним індексам `n = 0, 1, 2, ...` При цьому:
- Жодне стороннє число, яке не належить `S`, ніколи не буде надруковано.
- Будь-яке число `x ∈ S` обов'язково з'явиться у цьому виведеному списку на якомусь скінченному кроці `n` (тобто `g(n) = x`).
- Елементи у списку можуть повторюватися довільну кількість разів, і вони не зобов'язані виходити у зростаючому порядку.

### Спосіб 3: Проекція розв'язного відношення (Логічний свідок / Σ₁⁰-представлення)
Множина `S` складається з усіх чисел `x`, для яких існує хоча б один математичний **свідок** `y`, який задовольняє повністю розв'язний предикат `R(x, y)`:

```
x ∈ S  ⇔  ∃ y ∈ ℕ : R(x, y) = 1
```

Тут `R(x, y)` є простим алгоритмом, який за скінчений час перевіряє, чи є число `y` дійсним підтвердженням для `x`. Наприклад, якщо `x` — це твердження про наявність помилки в коді, то `y` — це конкретний трасувальний лог виконання, який розгортає цю помилку. Перевірити готову трасу `y` дуже легко й швидко (`R(x, y)` повертає 1 або 0 за кілька мілісекунд), проте знайти таке `y` серед нескінченного простору варіантів вимагає потенційно нескінченного перебору.

Математичне доведення того, що всі три способи подають один і той самий клас множин, спирається на канторівське кодування пар та теорему Кліні про нормальну форму; детальні строгі виводи наведено у вставочному матеріалі [доведення еквівалентності означень](book:algorithms/complexity-computability/recursively-enumerable-sets/math-re-equivalence.md).

Детальний перебіг математичних дискусій довкола цих означень та внесок Еміля Поста висвітлено в [історичному нарисі розвитку теорії перелічності](book:algorithms/complexity-computability/recursively-enumerable-sets/hist-recursively-enumerable.md).

## 3. Механізм Dovetailing: як не застрягти у нескінченності

Еквівалентність між другим способом (генератор `img(g)`) та першим способом (фільтр `dom(φ[e])`) висуває практичне питання: як перетворити напіввирішувач, який вміє зависати, на генератор, який послідовно друкує елементи без жодних зависань?

Уявимо наївну спробу побудувати генератор `g` для множини `S = dom(φ[e])`. Ми могли б послідовно запускати перевірку для всіх чисел `x = 0, 1, 2, 3, ...`:
1. Запускаємо `φ[e](0)`. Якщо зупинилося — друкуємо `0`.
2. Запускаємо `φ[e](1)`. Якщо зупинилося — друкуємо `1`.
3. Запускаємо `φ[e](2)`...

Цей наївний підхід завалиться на першому ж числі `x`, для якого `φ[e](x)` зациклиться. Якщо `φ[e](0)` виявиться вічним циклом, наш друкар застрягне на кроці 1 і не надрукує жодного числа, навіть якщо `φ[e](1)`, `φ[e](2)` і всі наступні значення зупиняються за один крок!

Щоб розв'язати цю проблему, застосовують фундаментальний алгоритмічний прийом — **Dovetailing** (ластівчин хвіст або діагональне обходити). Ідея полягає у квантуванні часу симуляції та розгортанні обчислень у двовимірну сітку.

![Механізм Dovetailing для уникнення нескінченного зациклення на одному вході](/book/algorithms/complexity-computability/recursively-enumerable-sets/img/dovetailing-grid.svg)

*Діагональний обхід сітки (Dovetailing). Рядки відповідають завданням i, а колонки — кількості виконаних кроків k. Планувальник обходить сітку за антидіагоналями s = i + k. Жодна вічна програма не може заблокувати інші, бо кожна задача отримує строго квантовану кількість кроків.*

У сітці Dovetailing:
- Рядок `i` відповідає вхідному елементу `x = i`.
- Колонка `k` відповідає кількості виконаних кроків симуляції машини `φ[e](i)`.

Замість того щоб рухатися вздовж одного рядка `i` до нескінченності, планувальник обходить сітку по діагоналях `s = i + k`:
- На діагоналі `s = 1`: виконуємо 1 крок для задачі `i = 0` (пари `(0, 1)`).
- На діагоналі `s = 2`: виконуємо 2-й крок для `i = 0` та 1-й крок для `i = 1` (пари `(0, 2)` і `(1, 1)`).
- На діагоналі `s = 3`: виконуємо кроки для `(0, 3)`, `(1, 2)` та `(2, 1)`.

Якщо на будь-якому кроці симуляція машини `φ[e](i)` досягає зупинки, елемент `i` негайно друкується й додається до вихідного списку. 

Оскільки кожна діагональ `s` містить лише скінченну кількість клітинок, а кожен крок виконується за скінченний час, планувальник ніколи не застрягає. Якщо число `x` дійсно належить `S`, то машина `φ[e](x)` зупиняється за деяку скінченну кількість кроків `k`. Це означає, що точка `(x, k)` лежить на діагоналі `s = x + k`. Планувальник дістанеться цієї діагоналі за скінченний час і гарантовано надрукує `x`.

### Алгоритмічна ціна чесного обходу
Діагональний обхід забезпечує абсолютну чесність (англ. *fairness*): жодна вічна програма не може загарбати процесорний час назавжди. Проте платою за цю чесність є квадратичний ріст загальної кількості кроків. Для перевірки `S` діагоналей обчислювачу доводиться виконати `T(S) = S · (S + 1) / 2` кроків симуляції. Якщо шуканий результат вимагає `k` кроків у задачі `i`, він буде знайдений за загальний час `O((i + k)²)`.

Практичні аспекти побудови такого планувальника, структури даних та ідіоматичні реалізації мовами C та C++20 детально розібрано у матеріалі [практична реалізація паралельного перебирача](book:algorithms/complexity-computability/recursively-enumerable-sets/proj-dovetailing-enumerator.md).

Для розробників систем верифікації та компіляторів повну специфікацію API та типів даних подано у [довіднику інтерфейсів перебирача](book:algorithms/complexity-computability/recursively-enumerable-sets/api-enumerator-interface.md).

## 4. Теорема Поста: симетрія як джерело розв'язності

Виникає природне питання: які відносини пов'язують клас повністю розв'язних множин `R` та клас напіврозв'язних множин `RE`? Очевидно, що кожна розв'язна множина є рекурсивно перелічною (`R ⊆ RE`): якщо ми маємо алгоритм, який завжди відповідає 1 або 0, ми можемо перетворити його на напіввирішувач, зробивши так, щоб замість відповіді 0 він входив у нескінченний цикл.

Проте коли напіврозв'язна множина стає повністю розв'язною? Відповідь дає фундаментальна **теорема Поста** (названа на честь Еміля Поста).

Сформулюємо поняття доповнення множини. Для множини `S ⊆ ℕ` її доповненням `S̄` є множина всіх елементів, які не належать `S`:

```
S̄ = ℕ \ S = { x ∈ ℕ  ∣  x ∉ S }
```

Якщо множина `S̄` є рекурсивно перелічною, ми кажемо, що `S` належить класу **coRE** (ко-рекурсивно перелічні множини).

> **Теорема Поста:** Множина `S` є повністю розв'язною (рекурсивною) тоді й лише тоді, коли як сама множина `S`, так і її доповнення `S̄` є рекурсивно перелічними:
> 
> ```
> S ∈ R  ⇔  S ∈ RE  ∧  S ∈ coRE
> ```

![Побудова двостороннього вирішувача за теоремою Поста](/book/algorithms/complexity-computability/recursively-enumerable-sets/img/posts-theorem.svg)

*Конструкція двостороннього вирішувача за теоремою Поста. Маючи два напіввирішувачі — MS для множини S та M_barS для її доповнення S̄, — ми запускаємо їх паралельно кроковим обходом. Оскільки будь-яке число належить або S, або S̄, один з двох напіввирішувачів обов'язково зупиниться за скінченний час, забезпечуючи гарантовану зупинку загального вирішувача.*

Доведення теореми Поста дає елегантний алгоритмічний рецепт побудови повного вирішувача:
1. Припустимо, ми маємо два напіввирішувачі: `M₁` (який зупиняється на `S`) та `M₂` (який зупиняється на `S̄`).
2. Для довільного вхідного числа `x` ми запускаємо `M₁(x)` та `M₂(x)` паралельно (покроковим обходом Dovetailing).
3. Оскільки за законом виключеного третього число `x` обов'язково належить або `S`, або `S̄` (і не може належати обом одразу, бо `S ∩ S̄ = ∅`), **один із двох напіввирішувачів обов'язково зупиниться за скінченний час**.
4. Якщо першим зупинився `M₁`, ми видаємо відповідь 1 (`x ∈ S`). Якщо першим зупинився `M₂`, ми видаємо відповідь 0 (`x ∉ S`).

Завдяки паралельному запуску двох напіввирішувачів ми отримали новий об'єднаний алгоритм, який **завжди** зупиняється за скінченний час. Отже, множина `S` є повністю розв'язною (`S ∈ R`).

Теорема Поста показує, що повна розв'язність — це результат **симетрії інформації**: наявності двох підтверджувачів, один з яких доводить приналежність, а інший — відсутність. Якщо ж ми володіємо підтверджувачем лише з одного боку, об'єкт залишається напіврозв'язним.

## 5. Ієрархія обчислюваності та нерозв'язні множини

Теорема Поста дозволяє легко довести існування множин, які є рекурсивно перелічними, але **не є розв'язними** (`RE \ R ≠ ∅`).

Розглянемо класичну множину проблеми зупинки `K`, яка кодує всі номери програм, що зупиняються на власному коді:

```
K = { e ∈ ℕ  ∣  φₑ(e) ↓ }
```

Множина `K` є рекурсивно перелічною (`K ∈ RE`), бо її напіввирішувач дуже простий: він бере номер `e` і симулює виконання `φ[e](e)`. Якщо програма `e` зупиняється, напіввирішувач теж зупиняється й повертає 1.

Проте [проблема зупинки](book:algorithms/halting-problem) доводить, що множина `K` не є розв'язною (`K ∉ R`). Спираючись на теорему Поста, ми робимо негайний висновок про доповнення `K̄`:

```
K ∈ RE  ∧  K ∉ R  ⇒  K̄ ∉ RE
```

Множина `K̄ = { e ∈ ℕ ∣ φ[e](e) ↑ }` (множина програм, які зациклюються на власному коді) **взагалі не є рекурсивно перелічною**. Для неї не існує навіть напіввирішувача! Не існує жодного алгоритму, який міг би за скінченний час підтвердити, що програма `e` буде крутитися вічно.

![Ієрархія класів R, RE, coRE та всіх підмножин натуральних чисел](/book/algorithms/complexity-computability/recursively-enumerable-sets/img/re-hierarchy.svg)

*Ієрархія обчислюваності множин. Всі розв'язні множини R лежать на перетині RE ∩ coRE. Множина K (проблема зупинки) лежить в RE \ R. Її доповнення K̄ лежить в coRE \ RE. Поза обома Oval-областями лежить переважна більшість підмножин ℕ, які не є навіть напіврозв'язними.*

Цей розподіл формує ієрархію обчислювальних класів:

```
R = RE ∩ coRE  ⊂  RE  ⊂  2ⁿ
```

Загальна кількість усіх можливих підмножин натуральних чисел є нерахованною (континуальною, `2^ℵ₀`), тоді як кількість усіх можливих програм (машин Тюрінга) є лише зліченною (`ℵ₀`). Це означає, що переважна більшість математичних множин взагалі перебуває поза межами будь-якої обчислюваності — вони не є ані розв'язними, ані рекурсивно перелічними.

Зв'язок класу RE з вищими рівнями математичної логіки вивчається у межах [арифметичної ієрархії](book:algorithms/arithmetic-hierarchy), де RE-множини утворюють найнижчий нетривіальний клас `Σ₁⁰`, а також у [теоремі Ґеделя про неповноту](book:algorithms/godel-incompleteness), яка показує, що множина всіх вивідних теорем у будь-якій формальній системі є рекурсивно перелічною, але множина всіх істинних арифметичних тверджень такою не є.

### Формальні системи як перелічувачі теорем
Теорема Ґеделя розкриває глибоку аналогію між теорією алгоритмів та математичною логікою. Будь-яка аксіоматична система (наприклад, арифметика Пеано PA або теорія множин ZFC) володіє механічним правилом перевірки доведень. Ми можемо побудувати алгоритм-перелічувач, який послідовно перебирає всі можливі скінченні тексти доведень і друкує лише ті формули, для яких знайдено коректне доведення.

Таким чином, множина всіх довідних теорем формальної системи є **рекурсивно перелічною множиною**. Перша теорема Ґеделя про неповноту стверджує, що якщо система є несуперечливою та достатньо багатою, то множина істинних тверджень не є рекурсивно перелічною. Це означає, що жодна алгоритмічна система виводу не здатна охопити всі математичні істини.

## 6. Зведення за Постом: m-зведення, T-зведення та RE-повнота

Щоб порівнювати складність різних нерозв'язних рекурсивно перелічних множин, Еміль Пост увів фундаментальний математичний інструмент — **зведення** (англ. *reducibility*).

### 6.1 m-зведення (Many-one reducibility)
Множина `A ⊆ ℕ` m-зводиться до множини `B ⊆ ℕ` (позначення `A ≤[m] B`), якщо існує загально обчислювана функція `f: ℕ → ℕ` така, що для будь-якого `x ∈ ℕ`:

```
x ∈ A  ⇔  f(x) ∈ B
```

Геометричний зміст `m`-зведення полягає в тому, що функція `f` перетворює питання приналежності `x` до множини `A` на еквівалентне питання приналежності `f(x)` до множини `B`. Якщо ми маємо напіввирішувач для `B`, ми миттєво отримуємо напіввирішувач для `A`, просто обчислюючи `f(x)` і передаючи його `B`.

### 6.2 Зведення Тюрінга (Turing reducibility)
Більш загальним є зведення Тюрінга (позначення `A ≤[T] B`), яке дозволяє алгоритму для `A` запитувати оракул для `B` довільну скінченну кількість разів під час обчислення.

### 6.3 RE-повні множини (RE-complete sets)
Множина `B ∈ RE` називається **RE-повною** відносно `m`-зведення (або `m`-повною), якщо будь-яка інша рекурсивно перелічна множина `A ∈ RE` зводиться до неї: `A ≤[m] B`.

Множина проблеми зупинки `K = { e ∣ φ[e](e) ↓ }` є канонічним прикладом RE-повної множини. Це означає, що проблему зупинки можна вважати **найскладнішою** серед усіх напіврозв'язних задач: будь-яке інше напіврозв'язне питання (наприклад, існування коренів у діофантового рівняння чи можливість виводу теореми у ZFC) можна за допомогою обчислюваної функції `f` перетворити на питання зупинки певної програми на власному коді.

### 6.4 Проблема Поста та степені Тюрінга
1944 року Еміль Пост поставив питання: чи існують рекурсивно перелічні множини, які перебувають за складністю строго **між** розв'язними множинами `R` та RE-повними множинами `K`? Тобто чи існує множина `A ∈ RE` така, що:

```
A ∉ R   та   K ≰[T] A
```

Ця задача залишалася відкритою понад десятиліття, доки у 1956–1957 роках Альберт Мучник (у СРСР) та Річард Фрідберг (у США) незалежно не довели існування таких множин за допомогою винайденого ними **методу пріоритету** (англ. *priority method*). Це відкриття поклало початок сучасній теорії степенів Тюрінга та показало, що структура рекурсивно перелічних множин володіє нескінченною складністю та багатим розшаруванням.

## 7. Граматики типу-0 за Хомським та алгоритмічна формалізація

Теорія рекурсивно перелічних множин знаходить пряме відображення у формальних мовах та теорії компіляторів через ієрархію Ноама Хомського (англ. *Noam Chomsky*).

У класичній класифікації формальних граматик:
- **Тип 3 (Регулярні граматики):** Розпізнаються скінченними автоматами (DFA/NFA) і відповідають розв'язним мовам низької складності.
- **Тип 2 (Контекстно-вільні граматики):** Розпізнаються автоматами з магазинной пам'яттю (PDA) і є повністю розв'язними.
- **Тип 1 (Контекстно-залежні граматики):** Розпізнаються лінійно обмеженими автоматами (LBA) і належать до класу розв'язних мов (`R`).
- **Тип 0 (Граматики без обмежень / Unrestricted Grammars):** Правила заміни мають довільний вигляд `α → β`, де `α, β ∈ (Σ ∪ V)*`.

> **Теорема про граматики типу-0:** Мова `L` генерується граматикою без обмежень (Тип-0) тоді й лише тоді, коли вона є **рекурсивно перелічною** (`L ∈ RE`).

Вивід у граматиці типу-0 є кроковим застосуванням правил заміни рядків. Послідовне застосування правил виводу точно відповідає крокам виконання машини Тюрінга. Оскільки ми можемо послідовно друкувати всі можливі виводи у граматиці за допомогою Dovetailing, множина згенерованих слів є рекурсивно перелічною. Це доводить, що концепція RE-множини є природною межею для довільних систем синтаксичного виводу рядків.

## 8. Практичне значення для верифікації та розробки

Розуміння структури рекурсивно перелічних множин є фундаментальним для розробників системного програмного забезпечення, компіляторів та інструментів автоматичного аналізу коду.

> 🔧 **Навіщо це.** Усі інструменти статичного аналізу коду, лінтери, верифікатори та фазери працюють у межах обмежень класу RE. Оскільки властивість «програма містить помилку некоректного звільнення пам'яті» або «програма ділить на нуль» є напіврозв'язною, будь-який аналізатор мусить обирати один з трьох практичних компромісів:
> 1. **Бути напіввирішувачем (зависати на складних кодах):** Інструмент гарантує 100% точність підтвердження помилок, але може працювати нескінченно довго на деяких вихідних файлах.
> 2. **Вводити таймаути й наближення (Soundness vs Completeness):** Інструмент штучно перериває обчислення за таймаутом, допускаючи помилкові спрацьовування (англ. *false positives*) або пропуски дефектів (англ. *false negatives*).
> 3. **Обмежувати мову до розв'язної підмножини:** Інструмент забороняє довільні цикли та рекурсію (як у мовах верифікації смарт-контрактів або eBPF-валідаторі ядра Linux), роблячи мову повністю розв'язною.

Знати, що досконалого універсального аналізатора без помилкових спрацювань і без зависань **не існує за математичним законами**, — це основа інженерної зрілості. Це позбавляє від марних спроб «полагодити останній баг у лінтері» і спрямовує зусилля на побудову ефективних наближених інструментів з контрольованими межами похибки.

### Застосування у сучасних інженерних системах
1. **eBPF-валідатор ядра Linux:** Щоб запобігти зависанню ядра Linux при виконанні завантаженого користувачем байт-коду в просторі ядра (kernel space), валідатор eBPF аналізує граф керування виконанням (CFG). Він допускає лише програми без нескінченних циклів із обмеженою кількістю інструкцій (наприклад, до 1 мільйона кроків). Цим самим валідатор примусово звужує мову eBPF з класу RE до класу R, гарантуючи безпеку ядра.
2. **Символьні симулятори (Symbolic Execution Engines):** Інструменти на кшталт KLEE перетворюють гілки коду на системи логічних обмежень для SMT-рішувачів. Для обходу нескінченних шляхів KLEE застосовує алгоритм Dovetailing на рівні генерації тестових покриттів, гарантуючи, що жоден глибокий цикл не заблокує аналіз інших функцій програми.

## 9. Властивості замкненості та операції над RE-множинами

Підсумуємо алгебраїчні властивості класу RE відносно стандартних множинних операцій, які активно використовуються при комбінуванні аналізаторів:

- **Об'єднання (`A ∪ B`):** Клас RE **замкнений**. Якщо ми маємо два напіввирішувачі для `A` та `B`, ми можемо побудувати напіввирішувач для `A ∪ B`, запустивши їх паралельно через Dovetailing. Якщо хоча б один зупиняється — об'єднаний напіввирішувач зупиняється.
- **Перетин (`A ∩ B`):** Клас RE **замкнений**. Напіввирішувач для `A ∩ B` запускає напіввирішувач для `A`, а після його успішної зупинки — напіввирішувач для `B`. Якщо обидва зупиняються, елемент належить перетину.
- **Декартів добуток (`A × B`):** Клас RE **замкнений**. Пара елементів кодується числом через канторівську функцію спарювання `⟨x, y⟩`.
- **Образ та прообраз обчислюваної функції (`f(A)` та `f⁻¹(A)`):** Клас RE **замкнений**. Якщо `A ∈ RE`, а `f` — загально обчислювана функція, то як образ, так і прообраз є рекурсивно перелічними.
- **Доповнення (`Ā`):** Клас RE **НЕ замкнений**. Якби клас RE був замкнений відносно доповнення, то за теоремою Поста кожна RE-множина була б розв'язною (`R = RE`), що суперечить існуванню нерозв'язної множини `K`.

### 9.1 Теорема Райса–Шапіро для індексних множин
Окремим вагомим алгебраїчним наслідком теорії рекурсивно перелічних множин є теорема Райса–Шапіро (англ. *Rice–Shapiro Theorem*), яка описує властивості підмножин рекурсивних функцій. Вона стверджує, що якщо індексна множина програм `A = { e ∣ φ[e] ∈ C }` є рекурсивно перелічною, то клас функцій `C` мусить бути **компактним та монотонним**. Це означає, що функція `f` належить `C` тоді й лише тоді, коли існує скінченна часткова функція `θ ⊆ f`, яка вже належить `C`. Якщо ж властивість вимагає перевірки нескінченної кількості точок (наприклад, «чи є область визначення `dom(φ[e])` нескінченною»), така множина виходить за межі класу RE і стає ко-напіврозв'язною (`Π₁⁰`) або складною напіврозв'язною третього порядку (`Σ₂⁰`).

### 9.2 Підсумковий інженерний висновок
Рекурсивно перелічні множини виступають природною та неподоланою межею ефективного механічного аналізу. Будь-яка спроба побудувати досконалий аналізатор, який ловив би всі помилки виконання й при цьому завжди зупинявся за скінченний час, впирається у фундаментальну асиметрію обчислень. Розуміння цієї межі дозволяє розробникам будувати гнучкі системні інструменти — фазери, верифікатори, символьні симулятори та SMT-рішувачі — спираючись на чесні алгоритми обходу на кшталт Dovetailing та контрольовані часові кванти.

### Зведена таблиця порівняння класів R та RE

| Властивість / Операція | Розв'язні множини (R) | Рекурсивно перелічні множини (RE) |
| :--- | :--- | :--- |
| **Гарантія зупинки алгоритму** | 100% для всіх елементів `x ∈ ℕ` | Тільки для елементів `x ∈ S` (зависає при `x ∉ S`) |
| **Спосіб генерації** | Можна друкувати строго за зростанням | Друкуються у довільному порядку із повторами |
| **Замкненість відносно доповнення** | Так (`S ∈ R ⇒ S̄ ∈ R`) | НІ (`K ∈ RE`, але `K̄ ∉ RE`) |
| **Замкненість відносно об'єднання** | Так (`A ∪ B ∈ R`) | Так (`A ∪ B ∈ RE`) |
| **Замкненість відносно перетину** | Так (`A ∩ B ∈ R`) | Так (`A ∩ B ∈ RE`) |
| **Статус проблеми зупинки K** | Не належить (`K ∉ R`) | Належить (`K ∈ RE`) |

Ці алгебраїчні властивості формують математичну основу для конструювання складних мовних граматик, аналізаторів формальних мов та систем типування у сучасних мовах програмування.
