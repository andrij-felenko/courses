# 📋 Інтерфейс та специфікація модулів системи формальної верифікації

Публічний програмний контракт (API) системи синтаксичного аналізу, Ґеделевого кодування та автоматичної верифікації доведень першого порядку регламентує специфікації структур даних, підписи функцій, класи помилок, перед- та постумови, а також системні інваріанти модулів верифікації.

## 1. Загальна специфікація типів даних та констант

Система автоматичної верифікації та кодування оперує чотирма основними концептуальними абстракціями:

1. **`Token`** — атомарний синтаксичний елемент логічного алфавіту.
2. **`ASTNode`** — вузол синтаксичного дерева формули або терму.
3. **`GodelNumber`** — типубезпечна обгортка над 64-бітним (або довільної точності) цілим числом.
4. **`VerificationStatus`** — результат синтаксичної перевірки кроку або всього доведення.

### Таблиця токенів логічного алфавіту

| Ідентифікатор токена | Символ | Тип токена | Числовий код Ґеделя | Опис |
| :--- | :--- | :--- | :--- | :--- |
| `TOK_ZERO` | `0` | Константа | 1 | Елементарний нуль |
| `TOK_SUCC` | `S` | Унарний функтор | 2 | Операція додавання одиниці |
| `TOK_PLUS` | `+` | Бінарний функтор | 3 | Додавання арифметики Пеано |
| `TOK_MULT` | `·` | Бінарний функтор | 4 | Множення арифметики Пеано |
| `TOK_EQ` | `=` | Предикат | 5 | Рівність термів |
| `TOK_NOT` | `¬` | Модальний оператор | 6 | Заперечення |
| `TOK_IMPL` | `→` | Логічна зв'язка | 7 | Імпликація |
| `TOK_EX` | `∃` | Квантор | 8 | Квантор існування |
| `TOK_ALL` | `∀` | Квантор | 9 | Квантор загальності |
| `TOK_VAR` | `v_i` | Змінна | 10 + i | Змінна з індексом `i` |
| `TOK_LPAR` | `(` | Пунктуація | 30 | Ліва дужка |
| `TOK_RPAR` | `)` | Пунктуація | 31 | Права дужка |

### Структури даних C++ API

```cpp
namespace godel::api {

enum class StatusCode : uint32_t {
    Success = 0,
    InvalidTokenSequence = 1,
    UnbalancedParentheses = 2,
    FreeVariableMismatch = 3,
    ModusPonensViolation = 4,
    AxiomMismatch = 5,
    IntegerOverflow = 6,
    EmptyProof = 7
};

struct VerificationResult {
    StatusCode code;
    size_t failed_step_index;
    std::string_view error_message;

    [[nodiscard]] bool is_valid() const noexcept {
        return code == StatusCode::Success;
    }
};

using GodelInt = uint64_t;

struct ASTNode {
    uint32_t token_code;
    std::vector<ASTNode> children;
};

struct ProofStep {
    size_t step_id;
    std::vector<uint32_t> tokens;
    GodelInt godel_number;
    std::vector<size_t> premise_indices; // Індекси передумов для Modus Ponens
};

} // namespace godel::api
```

## 2. Детальна специфікація та класифікація кодів помилок (StatusCode)

Модуль верифікації повертає об'єкт `VerificationResult`, який містить числовий код статусу `StatusCode`. Кожен код описує чітку синтаксичну або обчислювальну ситуацію:

1. **`StatusCode::Success` (код 0):**
   Синтаксична перевірка пройшла успішно. Послідовність формул або окремий крок строго відповідає аксіомам або правилам виведення.

2. **`StatusCode::InvalidTokenSequence` (код 1):**
   Вхідний масив чисел містить неіснуючі коди токенів (наприклад, числа, що не входять до таблиці алфавіту) або порушує граматику побудови термів (наприклад, два послідовні бінарні оператори `+ +`).

3. **`StatusCode::UnbalancedParentheses` (код 2):**
   Вектор токенів порушує дужкову структуру: кількість відкриваючих дужок `TOK_LPAR` не збігається з кількістю закриваючих `TOK_RPAR`, або закриваюча дужка передує відкриваючій.

4. **`StatusCode::FreeVariableMismatch` (код 3):**
   Спроба здійснення підставлення у формулу, де вказана змінна є зв'язаною квантором `∀` або `∃`, що призводить до конфлікту імен або захоплення змінної.

5. **`StatusCode::ModusPonensViolation` (код 4):**
   Перевірений крок `C` вказаний як висновок з `A` та `B`, проте формула `B` не має синтаксичного вигляду `(A → C)`.

6. **`StatusCode::AxiomMismatch` (код 5):**
   Крок виведення позначено як аксіому, проте його вектор токенів не збігається з жодною з 8 канонічних схем аксіом Пеано.

7. **`StatusCode::IntegerOverflow` (код 6):**
   Обчислення Ґеделевого номера `g = p₁ˢ¹ · p₂ˢ² · ...` вийшло за межі доступної розрядності `uint64_t`.

8. **`StatusCode::EmptyProof` (код 7):**
   У модуль верифікації передано порожній масив кроків виведення.

## 3. Інтерфейс кодувальника та декодувальника (Encoder API)

Кодувальник відповідає за двостороннє перетворення між послідовністю синтаксичних токенів та їхніми унікальними Ґеделевими номерами відповідно до Основної теореми арифметики.

### Сигнатура `encode_formula`

```cpp
[[nodiscard]] std::expected<GodelInt, StatusCode> 
encode_formula(std::span<const uint32_t> tokens) noexcept;
```

**Опис функціоналу та контракту:**

Метод `encode_formula` приймає неперервний послідовний масив кодів токенів і обчислює унікальний Ґеделів номер за формулою `g = p₁ˢ¹ · p₂ˢ² · ... · p⡭ˢᵏ`, де `pᵢ` — `i`-те просте число, а `sᵢ` — цілочисельний код відповідного токена.

- **Вхідні параметри:** `tokens` — типубезпечний зріз `std::span` числових кодів токенів.
- **Вихідне значення:** об'єкт `std::expected`, що містить або успішно обчислений `GodelInt`, або код помилки `StatusCode::IntegerOverflow` / `StatusCode::InvalidTokenSequence`.
- **Передблоки та інваріанти:**
  - Масив `tokens` не може бути порожнім: `tokens.empty() == false`.
  - Кількість токенів `k` не перевищує розмір вбудованої статичної таблиці простих чисел (`k ≤ 15`).
  - Усі елементи `tokens[i]` є додатними цілими числами з визначеного діапазону алфавіту.

### Сигнатура `decode_formula`

```cpp
[[nodiscard]] std::expected<std::vector<uint32_t>, StatusCode> 
decode_formula(GodelInt godel_number) noexcept;
```

**Опис функціоналу та контракту:**

Метод `decode_formula` здійснює зворотну реконструкцію вихідного масиву токенів за заданим Ґеделевим номером. Алгоритм виконує послідовне ділення числа `godel_number` на канонічний набір простих чисел `2, 3, 5, 7, ...`, підраховуючи показники степенів доти, доки частка не дорівнюватиме 1.

- **Вхідні параметри:** `godel_number` — 64-бітне натуральне число `g > 1`.
- **Вихідне значення:** вектор кодів токенів у порядку їхнього слідування або `StatusCode::InvalidTokenSequence`.
- **Постумови:**
  - Для будь-якої синтаксично коректної послідовності `T` виконується рівність: `decode_formula(encode_formula(T)) == T`.

### Сигнатура `substitute_diagonal`

```cpp
[[nodiscard]] std::expected<GodelInt, StatusCode> 
substitute_diagonal(GodelInt formula_godel_num, GodelInt term_godel_num) noexcept;
```

**Опис функціоналу та контракту:**

Метод `substitute_diagonal` реалізує фундаментальну примітивно-рекурсивну функцію діагонального підставлення `subst(x, y)`. Він приймає Ґеделів номер формули `A(v₁)` з вільною змінною `v₁` та Ґеделів номер терму `term_godel_num`, здійснює синтаксичну заміну всіх вільних входжень `v₁` на відповідний нумерал і повертає Ґеделів номер одержаної формули.

## 4. Інтерфейс верифікатора доведень (Proof Verifier API)

Верифікатор доведень перевіряє скінченну послідовність кроків виведення у формальній арифметиці Пеано, гарантуючи, що кожен крок є або аксіомою, або коректним застосуванням правила Modus Ponens.

### Сигнатура `verify_step`

```cpp
[[nodiscard]] VerificationResult 
verify_step(std::span<const ProofStep> proof_history, const ProofStep& current_step) noexcept;
```

**Опис функціоналу та контракту:**

Метод `verify_step` виконує синтаксичну перевірку одного кроку `current_step` відносно раніше перевіреної історії виведення `proof_history`.

- **Алгоритм перевірки:**
  1. Метод спочатку викликає підсистему `AxiomChecker` для аналізу, чи є `current_step` однією з аксіом `PA`.
  2. Якщо крок не є аксіомою, перевіряються вказані індекси передумов у `current_step.premise_indices`.
  3. Здійснюється перевірка правила Modus Ponens: у `proof_history` повинні існувати кроки `S_i` та `S_j` такі, що `S_j` має точну синтаксичну структуру `(S_i → current_step)`.

### Сигнатура `verify_full_proof`

```cpp
[[nodiscard]] VerificationResult 
verify_full_proof(std::span<const ProofStep> full_proof) noexcept;
```

**Опис функціоналу та контракту:**

Метод `verify_full_proof` виконує повну послідовну перевірку всього масиву кроків виведення від першої формули до останньої.

- **Вхідні параметри:** `full_proof` — неперервний зріз кроків доведення `[F₁, F₂, ..., F⡭]`.
- **Вихідне значення:** об'єкт `VerificationResult` з кодом `StatusCode::Success`, якщо всі кроки є синтаксично коректними, або індекс першого помилкового кроку та текстовий опис причини відхилення.

## 5. Специфікація предикатів довідності та ролей верифікації

У таблиці нижче наведено підсистеми верифікатора та їхні обчислювальні гарантії:

| Функціональний модуль | Сигнатура методу | Повертане значення | Опис інваріанта |
| :--- | :--- | :--- | :--- |
| **AxiomChecker** | `is_pa_axiom(tokens)` | `bool` | Повертає `true`, якщо формула збігається з однією з 8 схем аксіом `PA`. |
| **SubstitutionEngine** | `subst(f_id, var_id, val)` | `GodelInt` | Гарантує унікальність заміни вільних змінних без зв'язування кванторами. |
| **ProofVerifier** | `check_proof(proof_seq)` | `VerificationResult` | Часова складність: `O(N · M)`, де `N` — довжина доведення, `M` — довжина формули. |
| **Diagonalizer** | `build_godel_sentence()` | `ProofStep` | Автоматично будує самореферентний крок `G` за лемою про нерухому точку. |

## 6. Деталізація алгоритмів побудови AST та валідації граматики

Для забезпечення точної підстрокової та деревної перевірки модуль верифікації використовує двофазний синтаксичний аналізатор (Parser):

1. **Фаза лексичного аналізу (Lexing):** перетворює вхідний бітовий або текстовий потік у масив числових токенів `TokenSequence`. На цій фазі здійснюється перевірка валідності символів за таблицею токенів. Якщо виявлено невідомий символ, лексер миттєво генерує помилку `StatusCode::InvalidTokenSequence`.
2. **Фаза побудови дерев виразу (AST Construction):** рекурсивний спуск конструює дерево `ASTNode`. Оператори `+` та `·` об'єднують піддерева двох лівих і правих термів. Оператор заперечення `¬` додає один дочірній вузол, а квантори `∀` та `∃` зв'язують відповідну змінну.

Якщо під час побудови дерева виявляється розходження між дужками або відсутність необхідного аргументу у бінарного оператора, система повертає `StatusCode::UnbalancedParentheses`.

## 7. Обробка крайових випадків та виняткові ситуації

Під час роботи з синтаксичними структурами та Ґеделевими номерами можливі такі виняткові ситуації:

1. **Переповнення 64-бітних цілих чисел (`StatusCode::IntegerOverflow`):**
   При спробі закодувати формулу, довжина якої вимагає піднесення простих чисел у високі степені, функція `encode_formula` повертає `StatusCode::IntegerOverflow`. Система вимагає переключення на модуль довгої арифметики `BigIntEncoder`.
2. **Небаланс дужок у синтаксичному дереві (`StatusCode::UnbalancedParentheses`):**
   Якщо вектор токенів містить розходження між лівими та правими дужками (`TOK_LPAR` / `TOK_RPAR`), метод `encode_formula` повертає помилку `StatusCode::UnbalancedParentheses`.
3. **Виклики без передумов (`StatusCode::EmptyProof`):**
   Передача порожнього зрізу `full_proof` у `verify_full_proof` повертає `StatusCode::EmptyProof`.

Цей інтерфейс забезпечує повний математично строгий контракт для реалізації автоматичних систем верифікації доведень першого порядку та перевірки фундаментальних меж довідності.
