# 🧮 Доведення теореми Савича: рекурсивна досяжність у графі конфігурацій

Ця математична вставка містить строге та вичерпне доведення теореми Савича (1970). Вона розкриває формальну модель конфігурацій недетермінованої машини Тюринга, будує детермінований алгоритм рекурсивної перевірки досяжності `Reach(C₁, C₂, i)`, детально моделює процес роботи стеку та алгебраїчно виводить підсумкову оцінку детермінованої пам'яті `O(S(n)²)`.

---

## 1. Конфігураційний граф машини Тюринга

Нехай `M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)` — недетермінована машина Тюринга (NDTM), яка розпізнає мову вхідних слів `w` довжини `n = |w|` у просторі `S(n) ≥ log n`.

### 1.1. Структура та кодування конфігурації
**Конфігурація** `C` машини `M` — це повний вектор стану обчислення в певний крок часу. Вона складається з таких компонентів:
1. Поточний внутрішній стан управляючого пристрою `q ∈ Q`.
2. Позиція зчитувальної головки на вхідній стрічці `p_in ∈ {1, 2, ..., n}`.
3. Позиція головки на робочій стрічці `p_work ∈ {1, 2, ..., S(n)}`.
4. Вміст `S(n)` комірок робочої стрічки (символи з алфавіту `Γ`).

Формально конфігурацію кодують у вигляді рядка фіксованої двійкової довжини:
```
|C| = log₂|Q| + log₂ n + log₂ S(n) + S(n) · log₂|Γ|
```
Оскільки за умовою `S(n) ≥ log n`, логарифми `log₂ n` та `log₂ S(n)` обмежені величиною `O(S(n))`. Тому довжина коду конфігурації дорівнює:
```
|C| = O(S(n))  бітів
```

### 1.2. Обмеження на кількість можливих конфігурацій
Обчислимо абсолютну верхню межу для кількості унікальних конфігурацій `N`, у яких може опинитися машина `M`:
```
N = |Q| · n · S(n) · |Γ|^{S(n)}
```
Запишемо цю кількість через двійкову експоненту:
```
N ≤ 2^{c · S(n)}   для деякої сталої c > 0
```
де константа `c` виражається через параметри машини: `c = log₂|Γ| + O(1)`.

### 1.3. Граф конфігурацій G = (V, E)
Складемо орієнтований граф обчислень `G = (V, E)`:
- Множина вершин `V` — це всі допустимі конфігурації машини `M` на вхідному слові `w`. Кількість вершин `|V| = N ≤ 2^{c · S(n)}`.
- Орієнтоване ребро `(C₁, C₂) ∈ E` існує тоді й лише тоді, коли машина `M` за один крок може перейти з конфігурації `C₁` у конфігурацію `C₂` згідно з недетермінованою функцією переходу `δ`.

Без втрати загальності припустимо, що:
- Існує канонічна початкова конфігурація `C_start`.
- Існує єдина приймаюча конфігурація `C_accept` (перед зупинкою машина повністю очищає стрічку й переводить головку в початковий стан).

Отже, машина `M` приймає вхідне слово `w` тоді й лише тоді, коли у графі `G` існує орієнтований шлях від `C_start` до `C_accept`.

## 2. Предикат досяжності та рекурсивний поділ

Оскільки граф `G` містить `|V| = N` вершин, найкоротший шлях між двома вершинами (якщо він існує) не містить циклів, а його довжина не перевищує `N ≤ 2^{c · S(n)}`.

Позначимо через `m = ⌈c · S(n)⌉` верхню межу показника степеня. Завдання полягає у доказі існування шляху довжиною не більше `2ᵐ` між `C_start` та `C_accept`.

### 2.1. Алгоритм Reach(C₁, C₂, i)
Побудуємо детерміновану рекурсивну функцію `Reach(C₁, C₂, i)`, яка повертає `1` (True), якщо у графі `G` існує шлях від `C₁` до `C₂` довжиною `≤ 2ⁱ`, і `0` (False) у протилежному випадку.

```
Повна специфікація алгоритму Reach(C₁, C₂, i):

1. БАЗА РЕКУРСІЇ (i == 0):
   Якщо C₁ == C₂:
       Повернути 1
   Якщо (C₁, C₂) ∈ E (є direct transition за 1 крок):
       Повернути 1
   Інакше:
       Повернути 0

2. РЕКУРСИВНИЙ КРОК (i > 0):
   Для кожного послідовного бітового рядку C_mid довжини O(S(n)):
       1. Викликати res1 = Reach(C₁, C_mid, i - 1)
       2. Якщо res1 == 0:
              продовжити цикл (перейти до наступної C_mid)
       3. Викликати res2 = Reach(C_mid, C₂, i - 1)
       4. Якщо res2 == 1:
              Повернути 1 (шлях знайдено!)

   Якщо жодна C_mid не підійшла:
       Повернути 0 (шляху довжиною ≤ 2ⁱ не існує)
```

### 2.2. Трасування роботи алгоритму на прикладі
Розглянемо невеликий граф із 4 конфігураціями `{C_in, A, B, C_acc}` та шляхом `C_in ──> A ──> B ──> C_acc` довжиною 3 кроки (`m = 2`, оскільки `2² = 4 ≥ 3`).

1. Виклик `Reach(C_in, C_acc, 2)` перебирає проміжні конфігурації `C_mid`:
   - Випробовується `C_mid = A`. Перший крок розгалуження запускає `Reach(C_in, A, 1)`.
   - Для `Reach(C_in, A, 1)` перебирається проміжна точка. Оскільки між `C_in` та `A` є пряма дуга, вибір `C_mid' = C_in` дає `Reach(C_in, C_in, 0) = 1` та `Reach(C_in, A, 0) = 1`. Отже `Reach(C_in, A, 1)` повертає `1`.
   - Переходимо до другого виклику `Reach(A, C_acc, 1)`. Для нього випробовується `C_mid' = B`. Рекурсивні перевірки `Reach(A, B, 0) = 1` та `Reach(B, C_acc, 0) = 1` повертають `1`.
2. Обидва виклики повернули істину. Головний алгоритм `Reach(C_in, C_acc, 2)` повертає `1` (прийняти слово).

Зверніть увагу: на кожному етапі стек містить лише поточний ланцюжок рекурсивних викликів. Тільки-но відгалуження `Reach(C_in, A, 1)` завершилося, його фрейми вивільнилися для збереження виклику `Reach(A, C_acc, 1)`.

## 3. Алгебраїчний вивід просторової складності

Проаналізуємо обсяг оперативної пам'яті `Space(i)`, який споживає детермінований алгоритм для виконання виклику `Reach(C₁, C₂, i)`.

### 3.1. Витрати пам'яті в одному фреймі стеку
На рівні `i` алгоритм перебирає всі можливі конфігурації `C_mid`. Для реалізації цього перебору детермінована машина повинна зберігати у поточному фреймі стеку:
1. Вхідні параметри виклику: конфігурації `C₁` та `C₂` (розмір `2 · O(S(n))`).
2. Поточний кандидат проміжного стану `C_mid` (розмір `O(S(n))`).
3. Параметр рівня `i` (розмір `log₂ m = O(log S(n))`).

Сумарний розмір одного стекового фрейму дорівнює:
```
FrameSize = O(S(n)) бітів
```

Ключовий момент полягає у **перезавикористанні пам'яті**: після завершення виклику `Reach(C₁, C_mid, i - 1)` його фрейм повністю очищається й виділяється заново для наступного виклику `Reach(C_mid, C₂, i - 1)`.

### 3.2. Рекурентне співвідношення
Отже, оперативна пам'ять `Space(i)` для рівня `i` складається з пам'яті власного фрейму плюс пам'ять, яку споживає один глибший виклик на рівні `i - 1`:

```
Space(i) = Space(i - 1) + FrameSize   [рекурентний крок: долучаємо 1 фрейм]
Space(0) = O(S(n))                    [база рекурсії: перевірка суміжності в E]
```

### 3.3. Розв'язання рекурентного рівняння
Розгорнемо рекурентну залежність від верхнього рівня `m = O(S(n))` до бази `i = 0`:

```
Space(m)
= Space(m - 1) + O(S(n))               [підстановка Space(m): 1 крок розгортання]
= Space(m - 2) + O(S(n)) + O(S(n))     [підстановка Space(m-1): 2 крок розгортання]
= Space(m - 3) + 3 · O(S(n))           [згруповано доданки для 3-го кроку]
= Space(0) + m · O(S(n))               [повнота рекурсії: за m кроків підстановки]
= O(S(n)) + m · O(S(n))                [значення бази Space(0) = O(S(n))]
```

Підставимо значення верхньої межі глибини `m = ⌈c · S(n)⌉`:

```
Space(m)
= O(S(n)) + (c · S(n)) · O(S(n))        [підставлено m = c · S(n)]
= O(S(n) + c · S(n)²)                  [розкрито дужки доданка]
= O(S(n)²)                             [домінуючий член квадратичної складності]
```

## 4. Граничні випадки та сублінійні класи пам'яті

Розглянемо важливі крайові випадки умови теореми Савича та її застосування до сублінійних класів складності.

### 4.1. Чому потрібна умова S(n) ≥ log n?
Умова `S(n) ≥ log n` є строго необхідною для того, щоб підіндекс вхідного вказівника `p_in ∈ {1, ..., n}` вміщався в бітовий рядок конфігурації `|C|`. Для збереження числа `n` у двійковій системі потрібно `⌈log₂ n⌉` бітів.

Якщо розпросторитися на сублінійний простір `S(n) = o(log n)` (наприклад, `S(n) = O(log log n)` або `S(n) = O(1)`), звичайна машина Тюринга навіть не може зберегти позицію своєї головки на вхідній стрічці. Для таких дрібних класів конфігураційний граф вироджується, і загальна теорема Савича у формі `NSPACE(S(n)) ⊆ DSPACE(S(n)²)` ламається, оскільки кодування конфігурацій займає більше пам'яті, ніж робоча стрічка.

### 4.2. Наслідок для логарифмічної пам'яті (L та NL)
Застосуємо теорему Савича до недетермінованого логарифмічного простору `NL = NSPACE(log n)`:

```
S_DSPACE(n) = O( (log n)² )
```

Звідси випливає фундаментальне включення для логарифмічних класів:
```
NL ⊆ DSPACE(log² n)
```
Це означає, що будь-яку NL-повну задачу (наприклад, перевірку досяжності у графі `ST-CON`) можна розв'язати детерміновано у полілогарифмічній пам'яті `O(log² n)`.

## 5. Математичні наслідки для ієрархії класів

Ми отримали строго доведений результат: будь-яке недетерміноване обчислення простору `S_NDTM(n)` моделюється детермінованим алгоритмом у просторі:

```
S_DSPACE(n) = O( (S_NPSPACE(n))² )
```

### 5.1. Тотожність NPSPACE = PSPACE
Для поліноміальних обмежень пам'яті `S_NDTM(n) = nᵏ`:

```
S_DSPACE(n) = O((nᵏ)²) = O(n^{2k})
```

Оскільки `n^{2k}` залишається поліномом, ми маємо включення:

```
NPSPACE = ⋃_{k≥1} NSPACE(nᵏ) ⊆ ⋃_{k≥1} DSPACE(n^{2k}) = PSPACE
```

Зважаючи на банальне включення `PSPACE ⊆ NPSPACE`, отримуємо фундаментальну тотожність:

```
PSPACE = NPSPACE
```

### 5.2. Часово-просторовий компроміс (Time-Space Tradeoff)
Варто підкреслити часову ціну цього перетворення. Якщо недетермінована машина виконує `2^{O(S(n))}` кроків, то детермінований алгоритм Савича на кожному з `m = O(S(n))` рівнів породжує подвійне розгалуження:

```
Time(m) = 2 · Time(m - 1) + O(N)       [подвійне розгалуження на кожному рівні m]
Time(m) = 2^{O(S(n))} · 2^{O(S(n))}     [добуток гілок глибини O(S(n))]
        = 2^{O(S(n)²)}                 [сумарна часова складність]
```

У результаті алгоритм Савича працює за експоненційний час `2^{O(S(n)²)`. Це строго ілюструє фундаментальний часово-просторовий компроміс комп'ютерних наук: ми звели недетермінований простір до квадратичного детермінованого простору, але сплатили за це експоненційним часом виконання.
