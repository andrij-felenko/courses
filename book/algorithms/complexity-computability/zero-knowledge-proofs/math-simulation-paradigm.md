# 🧮 Математичний апарат симуляції та розрізненності розподілів

Центральним поняттям доведень з нульовим розголошенням (англ. *Zero-Knowledge Proofs*) є математично суворий формалізм імовірнісних розподілів та парадигми симуляції. Щоб довести, що верифікатор не дізнався жодного біта нової інформації впродовж виконання протоколу, необхідно показати, що всю інформацію, яку він отримав, він міг би згенерувати самостійно, не спілкуючись із доводжувачем. 

У класичній математиці факт відсутності витоку інформації вимірювати не вміли. Теорія криптографії та складності вирішила цю задачу через порівняння двох імовірнісних просторів: реального середовища виконання протоколу та ідеалізованого середовища симулятора.

## 1. Стенограма взаємодії та вигляд верифікатора

Нехай `x` — спільний вхідний рядок бітів довжиною `n` (наприклад, графічна структура або публічний ключ), а `w` — секретна інформація (свідок NP-твердження або приватний ключ), доступна лише доводжувачу `P`.

Під час інтерактивного виконання протоколу між імовірнісним доводжувачем `P` та зловмисним імовірнісним верифікатором `V*` фіксується повний стан верифікатора, який називається виглядом (англ. *view*):

```
View_V*(P(x, w) ↔ V*(x)) = (r, m₁, m₂, ..., mₖ)
```

де елементи мають таке значення:
- `r` — послідовність випадкових бітів (монет), які використала імовірнісна машина Тюринга `V*` зі свого внутрішнього криптографічного джерела ентропії;
- `m₁, m₂, ..., mₖ` — усі повідомлення (зобов'язання та відповіді), надіслані доводжувачем `P` у відповідь на виклики верифікатора `V*`.

Оскільки машини `P` та `V*` підкидають випадкові монети, об'єкт `View_V*` є випадковою величиною, що належить до певного розподілу імовірностей `D_real(x)` над множиною усіх можливих стенограм виконання.

## 2. Класифікація розрізненності розподілів

Для порівняння реального розподілу стенограм `D_real(x)` із розподілом `D_sim(x)`, згенерованим алгоритмом симулятора `S`, у математичній криптографії використовують три ступені близькості випадкових величин.

### Статистична відстань (Total Variation Distance)

Для двох випадкових величин `X` та `Y`, визначених на скінченній множині `Ω`, статистична відстань між їхніми розподілами імовірностей розраховується як половина суми абсолютних різниць:

```
Δ(X, Y) = (1/2) · ∑ |Pr[X = v] - Pr[Y = v]|
          v∈Ω
```

Функція `ε(n)` називається нехтовною (англ. *negligible function*), якщо для будь-якого додатного полінома `p(n)` існує таке порогове значення `n₀`, що для всіх `n > n₀` виконується нерівність:

```
ε(n) < 1 / p(n)
```

Нехтовні функції спадають швидше за будь-який обернений поліном (наприклад, експоненційно спадні функції `2⁻ⁿ`).

### Три класи нульового розголошення

1. **Досконале нульове розголошення (Perfect Zero-Knowledge, PZK):**
   Розподіли реального виконання та симуляції є абсолютними математичними двійниками (тотожностями). Статистична відстань дорівнює нулю:
   ```
   Δ(View_V*(P(x, w) ↔ V*(x)), S(x)) = 0
   ```
   Симулятор будує стенограми з точно тими самими імовірностями для кожного елемента, що й справжній доводжувач.

2. **Статистичне нульове розголошення (Statistical Zero-Knowledge, SZK):**
   Статистична відстань між розподілами є нехтовною функцією від довжини входу `n`:
   ```
   Δ(View_V*(P(x, w) ↔ V*(x)), S(x)) ≤ ε(n)
   ```
   Навіть спостерігач з нескінченною обчислювальною потужністю не здатний статистично відрізнити справжні докази від симульованих з помітною перевагою.

3. **Обчислювальне нульове розголошення (Computational Zero-Knowledge, CZK):**
   Для будь-якої імовірнісної машини Тюринга поліноміального часу `D` (дистингвішера або розрізнювача) різниця імовірностей прийняття рішення є нехтовною функцією:
   ```
   |Pr[D(x, View_V*) = 1] - Pr[D(x, S(x)) = 1]| ≤ ε(n)
   ```
   Практично всі криптографічні системи з нульовим розголошенням для загальних NP-задач є обчислювальними (CZK), оскільки вони спираються на припущення про важкість обчислення однонаправлених функцій або еліптичних кривих.

## 3. Математика симуляції на прикладі протоколу Шнорра

Розглянемо чесного верифікатора (англ. *Honest Verifier*) у протоколі доведення знання дискретного логарифма `x = log_g Y (mod p)`.

### Справжній протокол взаємодії

Чесний доводжувач виконує такі математичні кроки:
1. Обирає випадкове значення `r ∈_R Z_q` та відправляє зобов'язання `R = gʳ mod p`.
2. Отримує випадковий виклик `e ∈_R Z_q` від верифікатора.
3. Надсилає відповідь `s = (r + e · x) mod q`.

Верифікатор перевіряє рівняння: `gˢ ≡ R · Yᵉ (mod p)`.

### Конструкція симулятора для чесного верифікатора (HVZK)

Симулятор `S` **не знає** секретного ключа `x`. Щоб згенерувати валідну трійку `(R, e, s)`, симулятор змінює порядок обчислення елементів задом наперед:

1. Симулятор обирає випадковий виклик `e ∈_R Z_q`.
2. Симулятор обирає випадкову відповідь `s ∈_R Z_q`.
3. Симулятор **вираховує** зобов'язання `R`, яке б задовольнило рівняння верифікації:
   ```
   gˢ ≡ R · Yᵉ  (mod p)
   ↓
   R = gˢ · Y⁻ᵉ  (mod p)
   ```

Проаналізуємо розподіл імовірностей потрійного значення `(R, e, s)` у симуляторі:
- Елемент `e` є рівномірно розподіленим випадковим елементом з `Z_q`.
- Елемент `s` є рівномірно розподіленим випадковим елементом з `Z_q`.
- Елемент `R` однозначно фіксується виразом `gˢ · Y⁻ᵉ mod p`.

У реальному протоколі: `e` обирається рівномірно з `Z_q`, `r` обирається рівномірно з `Z_q`, тому `s = r + e·x mod q` також є рівномірно розподіленим випадковим значенням в `Z_q`. Елемент `R = gʳ = gˢ⁻ᵉˣ = gˢ · Y⁻ᵉ mod p` має абсолютно тотожну алгебраїчну залежність! 

Отже, стенограма симулятора `(R, e, s)` має тотожний розподіл імовірностей з реальним транскриптом. Це доводить досконале нульове розголошення проти чесного верифікатора (HVZK).

## 4. Симуляція з перемотуванням для зловмисного верифікатора

Якщо верифікатор `V*` є зловмисним, він може обирати виклик `e` не випадково, а залежно від отриманого значення `R`, наприклад, через складну внутрішню функцію `e = V*(R)`.

Симулятор `S` використовує право керування монетами та станом машини `V*` за допомогою технології перемотування (англ. *rewinding*):

```
Крок 1. S обирає випадкову відповідь s' ∈_R Z_q та випадкове e' ∈_R Z_q.
Крок 2. S обчислює фальшиве зобов'язання R' = gˢ' · Y⁻ᵉ' mod p.
Крок 3. S передає R' на вхід верифікатора V* і отримує виклик e = V*(R').
Крок 4. Якщо e == e':
            Симулятор успішно повертає транскрипт (R', e, s').
        Якщо e ≠ e':
            S ПЕРЕМОТУЄ внутрішній стан V* до Кроку 1 і повторює спробу!
```

Математичний аналіз часу роботи симулятора: якщо верифікатор видає кожен виклик з певною імовірністю, очікувана кількість спроб симулятора до першого збігу `e == e'` становить `|Z_q|` для рівномірного вибору. Щоб зробити час роботи поліноміальним, використовують Fiat-Shamir трансформацію або редукцію до криптографічних зобов'язань.

## 5. Доведення надійності через екстрактор знань

Надійність (англ. *soundness*) гарантує, що нечесний доводжувач `P*`, який не знає секрету `x`, не може переконати верифікатора. Формально надійність доводиться через існування алгоритму **екстрактора знань** (англ. *knowledge extractor*) `E`.

Якщо доводжувач `P*` проходить перевірку верифікатора з імовірністю, вищою за `1 / |Z_q| + ε`, то екстрактор `E`, маючи доступ до перемотування `P*`, може видобути секрет `x`.

### Алгоритм екстракції:

1. Екстрактор `E` запускає `P*`, отримує зобов'язання `R`.
2. `E` надсилає перший виклик `e₁` і отримує відповідь `s₁ = r + e₁ · x mod q`.
3. `E` перемотує стан `P*` до моменту після видачі `R`.
4. `E` надсилає **другий** некорельований виклик `e₂ ≠ e₁` і отримує відповідь `s₂ = r + e₂ · x mod q`.

Екстрактор будує систему алгебраїчних рівнянь:

```
s₁ = r + e₁ · x  (mod q)
s₂ = r + e₂ · x  (mod q)
```

Віднімаючи друге рівняння від першого, отримуємо:

```
s₁ - s₂ = (e₁ - e₂) · x  (mod q)
```

Оскільки `e₁ ≠ e₂` та `q` — просте число, різниця `(e₁ - e₂)` має обернений елемент `(e₁ - e₂)⁻¹ mod q`. Екстрактор обчислює секретний ключ `x`:

```
s₁ - s₂
= (e₁ - e₂) · x                     [віднімання рівнянь відповідй]

x = (s₁ - s₂) · (e₁ - e₂)⁻¹  (mod q) [помножили на обернений елемент]
```

Це доводить, що будь-який доводжувач, здатний відповісти на два різні виклики для одного й того самого зобов'язання `R`, **фізично володіє** секретом `x`. Цей математичний механізм гарантує надійність інтерактивного протоколу.
