# 🧮 Математичний апарат розподілу регістрів: NP-повність, графова інтерференція та хордальні графи

Розподіл регістрів у компіляторній теорії є однією з найглибших дисциплін, де теорія комбінаторних графів, абстрактна алгебра граток (англ. *lattices*) та теорія складності обчислень безпосередньо керують генерацією машинного коду. У цій вставці наведено строгі математичні доведення фундаментальних теорем, що лежать в основі аналізу життєвості змінних, K-розфарбовуваності графів інтерференції, теорем про злиття регістрів, а також поліноміальної розв'язності для коду у SSA-формі.

### 1. Математичні рівняння аналізу життєвості (Liveness Dataflow Lattice)

Нехай програма представлена орієнтованим графом потоку керування (CFG) `G_CFG = (B, E_CFG)`, де `B` — множина базових блоків, а `E_CFG` — орієнтовані дуги переходу між блоками. Для кожного блоку `b ∈ B` визначено дві множини віртуальних змінних:
- `Def[b]` — множина змінних, яким присвоюється нове значення в блоці `b` до їх першого використання в цьому ж блоці.
- `Use[b]` — множина змінних, значення яких зчитується в блоці `b` до будь-якого можливого повторного присвоєння в цьому блоці.

#### Означення (Життєвість змінної)
Змінна `v` називається **живою** (англ. *live*) у точці програми `p`, якщо у графі `G_CFG` існує орієнтований шлях від `p` до деякого блоку `b_use`, де `v ∈ Use[b_use]`, і на цьому шляху відсутні блоки `b_def`, у яких `v ∈ Def[b_def]`.

Позначаємо через `In[b]` множину змінних, живих на вході в базовий блок `b`, а через `Out[b]` — множину змінних, живих на виході з блоку `b`. Система рівнянь потоку даних має вигляд:

```
In[b] = Use[b] ∪ (Out[b] \ Def[b])               [Рівняння входу базового блоку]
Out[b] = ⋃_{s ∈ Succ[b]} In[s]                    [Рівняння виходу: об'єднання по наступниках Succ[b]]
```

#### Теорема 1 (Існування та єдиність найменшої нерухомої точки)
*Система рівнянь життєвості завжди має єдину найменшу нерухому точку (Least Fixed Point), яка обчислюється за скінченне число ітерацій.*

**Доведення:**
Розглянемо множину рішень як булеву ґратку `L = (P(V))^{2|B|}`, де `P(V)` — булеан множини всіх змінних `V`, впорядкований за відношенням включення `⊆`. Ґратка `L` є скінченною та повною.

Оператор перерахунку `F: L → L`, визначений через вирази `In[b]` та `Out[b]`, складається виключно з монотонних теоретико-множинних операцій об'єднання (`∪`) та різниці з константною множиною (`\ Def[b]`).

Для будь-яких двох станів `X, Y ∈ L` таких, що `X ⊆ Y`:
```
(Out_X[b] \ Def[b]) ⊆ (Out_Y[b] \ Def[b])          [монотонність різниці множин]
⇒ Use[b] ∪ (Out_X[b] \ Def[b]) ⊆ Use[b] ∪ (Out_Y[b] \ Def[b])
⇒ F(X) ⊆ F(Y)
```
Отже, оператор `F` є строго монотонним на повній скінченній ґратці `L`. За теоремою Тарського–Кнастера (англ. *Knaster-Tarski Theorem*), множина нерухомих точок монотонного відображення на повній ґратці утворює повну підґратку і має найменший елемент `LFP`. Оскільки множина змінних `V` скінченна, послідовна ітерація `X_{k+1} = F(X_k)` починаючи з порожнього стану `X_0 = ∅` досягає нерухомої точки не більше ніж за `2 · |B| · |V|` кроків. `■`

#### Числовий приклад обчислення ітерацій непорушної точки
Розглянемо граф потоку керування з трьох блоків `B1 → B2 → B3` та двох змінних `{x, y}`:
- `B1`: `Def[B1] = {x}`, `Use[B1] = ∅`, `Succ[B1] = {B2}`
- `B2`: `Def[B2] = {y}`, `Use[B2] = {x}`, `Succ[B2] = {B3}`
- `B3`: `Def[B3] = ∅`, `Use[B3] = {y}`, `Succ[B3] = ∅`

Кроки ітераційного обчислення нерухомої точки:

```
Ітерація 0 (Початковий стан ∅):
In[B1]=∅, Out[B1]=∅;  In[B2]=∅, Out[B2]=∅;  In[B3]=∅, Out[B3]=∅

Ітерація 1 (Зворотний прохід B3 → B2 → B1):
Out[B3] = ∅
In[B3]  = Use[B3] ∪ (Out[B3] \ Def[B3]) = {y} ∪ (∅ \ ∅) = {y}

Out[B2] = In[B3] = {y}
In[B2]  = Use[B2] ∪ (Out[B2] \ Def[B2]) = {x} ∪ ({y} \ {y}) = {x} ∪ ∅ = {x}

Out[B1] = In[B2] = {x}
In[B1]  = Use[B1] ∪ (Out[B1] \ Def[B1]) = ∅ ∪ ({x} \ {x}) = ∅

Ітерація 2 (Перевірка стабілізації):
Значення In та Out усіх блоків збігаються з Ітерацією 1. 
Нерухому точку знайдено за 2 кроки: LFP = {In[B1]=∅, Out[B1]={x}, In[B2]={x}, Out[B2]={y}, In[B3]={y}, Out[B3]=∅}.
```

### 2. Граф інтерференції та доведення NP-повноти розподілу регістрів

Нехай `V` — множина віртуальних змінних програми. Кожній змінній `v ∈ V` відповідає її діапазон життєвості `LiveRange(v) ⊆ T`, де `T` — множина точок виконання (інструкцій) програми.

#### Означення (Граф інтерференції)
Графом інтерференції програми називається неорієнтований граф `G_int = (V, E_int)`, у якому невиважені ребра `(u, v) ∈ E_int` проводяться тоді й лише тоді, коли їхні діапазони життєвості мають спільні точки виконання:
```
(u, v) ∈ E_int  ⇔  LiveRange(u) ∩ LiveRange(v) ≠ ∅
```

Задача розподілу `K` фізичних регістрів полягає в знаходженні функції розфарбування `c: V → {1, 2, ..., K}` такої, що для кожного ребра `(u, v) ∈ E_int` виконується `c(u) ≠ c(v)`.

#### Теорема 2 (NP-повність розподілу регістрів Чейтіна)
*Задача визначення, чи існує для довільного графа інтерференції програма, розподіл регістрів якої еквівалентний K-розфарбуванню даного графа, є NP-повною для будь-якого фіксованого K ≥ 3.*

**Доведення:**
Доведення здійснюється шляхом поліноміального зведення класичної NP-повної задачі `K-COLORING` (розфарбування довільного графа `H = (V_H, E_H)` `K` кольорами) до задачі побудови графа інтерференції.

Побудуємо лінійну програму `P_H` без розгалужень, яка складається з послідовності інструкцій. Для кожної вершини `u ∈ V_H` введемо віртуальну змінну `x_u`.

Побудова програми здійснюється у два етапи:
1. **Етап ініціалізації:** На початку програми послідовно виконуються інструкції присвоєння `x_u = 0` для всіх `u ∈ V_H`. У цей момент усі змінні стають живими.
2. **Етап інтерференції:** Для кожного ребра `e = (u, v) ∈ E_H` створимо окрему інструкцію `dummy_e = x_u + x_v` у точці часу `t_e`. У точці `t_e` обидві змінні `x_u` та `x_v` одночасно є живими (оскільки вони були ініціалізовані вище і зчитуються в цій інструкції).

Діапазон життєвості кожної змінної `x_u` охоплює інтервал від її початкової ініціалізації до останнього використання в інструкціях `dummy_e`. Якщо у вихідному графі `H` існує ребро `(u, v) ∈ E_H`, то діапазони життєвості `x_u` та `x_v` перетинаються в точці `t_e`, отже у графі `G_int` виникає ребро `(x_u, x_v)`. Якщо ребра немає, за відповідного впорядкування інструкцій перетин відсутній.

Таким чином, побудований граф інтерференції `G_int` ізоморфний вихідному графу `H`. Оскільки розфарбування `G_int` `K` кольорами еквівалентне `K`-розфарбуванню `H`, а зведення здійснюється за поліноміальний час `O(|V_H| + |E_H|)`, задача розподілу регістрів є NP-повною. `■`

### 3. Алгебраїчна лема Кемпе та вибір кандидатів для скидання (Spill Cost)

Наявність NP-повноти унеможливлює точний пошук розфарбування для великих графів. Алгоритм Чейтіна–Бріґґса використовує редукційну лему Альфреда Кемпе.

#### Лема 1 (Лема Кемпе про спрощення графа)
*Нехай G = (V, E) — граф, і v ∈ V — вершина із степенем deg(v) < K. Граф G є K-розфарбовуваним тоді й лише тоді, коли підграф G' = G \ {v} (отриманий вилученням вершини v та пов'язаних ребер) є K-розфарбовуваним.*

**Доведення:**
- **Пряме твердження (G є K-розфарбовуваним ⇒ G' є K-розфарбовуваним):** Очевидно, оскільки звуження будь-якої валідної розфарбування `c: V → {1, ..., K}` на множину вершин `V \ {v}` залишається валідним розфарбуванням для `G'`.
- **Зворотне твердження (G' є K-розфарбовуваним ⇒ G є K-розфарбовуваним):** Нехай `c': (V \ {v}) → {1, ..., K}` — валідне `K`-розфарбування підграфа `G'`. Кількість сусідів вершини `v` у вихідному графі `G` дорівнює `deg(v)`. Оскільки `deg(v) < K`, ці сусіди можуть використовувати у розфарбуванні `c'` **щонайбільше** `deg(v)` різних кольорів з множини `{1, 2, ..., K}`.
Оскільки `deg(v) ≤ K - 1`, у множині з `K` кольорів залишається принаймні один вільний колір `c_free ∈ {1, ..., K}`, який не призначений жодному із сусідів `v`. Розширимо розфарбування `c'`, поклавши `c(v) = c_free`. Отримане розфарбування `c` є валідним `K`-розфарбуванням усього графа `G`. `■`

#### Вагова функція пріоритету скидання Чейтіна
Коли всі залишкові вершини мають `deg(v) ≥ K`, алгоритм має обрати вершину для скидання у стек пам'яті. Для мінімізації накладних витрат Чейтін ввів функцію пріоритету (Spill Cost):

```
Cost(v) = ∑_{b ∈ Blocks(v)} (UseCount(v,b) + DefCount(v,b)) · 10^{LoopDepth(b)}
Priority(v) = Cost(v) / deg(v)
```

Обирається вершина `v` з мінімальним `Priority(v)`: це гарантує, що скидається змінна з високим ступенем інтерференції (видалення якої розблокує багато сусідів), яка рідко використовується у критичних вкладених циклах. Множник `10^{LoopDepth(b)}` виражає експоненційну вагу звернень углиб вкладеності циклів.

### 4. Математичні критерії консервативного злиття (Coalescing Criteria)

Для усунення інструкцій копіювання `mov u, v` компілятор може спробувати об'єднати вузли `u` та `v` у єдиний вузол `uv`. Однак наївне злиття може збільшити степені сусідніх вершин і зробити розфарбовуваний граф нерозфарбовуваним. Щоб гарантувати збереження `K`-розфарбовуваності, використовуються два консервативні критерії:

#### Теорема 5 (Критерій злиття Бріґґса)
*Вузли u та v можна консервативно об'єднати в вузол uv, якщо об'єднаний вузол uv має менше ніж K сусідів зі степенем deg(w) ≥ K у вихідному графі.*

**Доведення:**
Розглянемо спрощення об'єднаного графа за лемою Кемпе. Усі сусіди вузла `uv`, які мають `deg(w) < K`, будуть послідовно вилучені алгоритмом спрощення. Після їх вилучення залишкові сусіди вузла `uv` мають кількість менше ніж `K`. Отже, у залишковому графі сам вузол `uv` буде мати ступінь `deg(uv) < K` і також буде успішно вилучений без загрози виникнення заторного скидання в пам'ять. `■`

#### Теорема 6 (Критерій злиття Джорджа)
*Вузли u та v можна консервативно об'єднати у вузол uv, якщо для кожного сусіда t вузла u виконується принаймні одна з двох умов:*
1. `t` вже є сусідом `v` (інтерферує з `v`), АБО
2. `deg(t) < K` (ступінь `t` є малим).

**Доведення:**
Вилучення сусідів з `deg(t) < K` не створює нових перешкод. Сусіди, що вже інтерферували з `v`, не збільшують степінь `v` при об'єднанні з `u`. Отже, об'єднання не створює нових проблемних вершин високого степеня у підграфі, що доводить збереження розфарбовуваності. `■`

### 5. Математична формалізація та інваріанти Linear Scan (Poletto & Sarkar)

У лінійному скануванні програма розглядається як 1D-впорядкована множина відрізків життєвості `I = { [start_i, end_i] }_{i=1}^N`.

#### Означення (Активний набір)
Для кожної часової мітки `t` активним набором `Active(t)` називається множина інтервалів:
```
Active(t) = { i ∈ I : start_i ≤ t ≤ end_i }
```

#### Теорема 7 (Коректність 1D-розфарбування Linear Scan)
*Якщо для всіх часових точок t виконується |Active(t)| ≤ K, то графічну інтерференцію інтервалів можна розфарбувати K кольорами за один послідовний прохід O(N log N).*

**Доведення:**
Впорядкуємо всі інтервали за зростанням `start_i`. Скануємо точку `t = start_i`. Перед обробкою `i` з `Active` вилучаються всі інтервали `j`, у яких `end_j < start_i`. Ті інтервали, що залишилися в `Active`, утворюють кліку. Оскільки `|Active| ≤ K`, у множині з `K` регістрів завжди знайдеться вільний регістр для новодійшлого інтервалу `i`. `■`

#### Лема 2 (Евристика скидання з найдовшим залишком)
*Якщо в точці t виникає переповнення |Active(t)| = K + 1, вибір для скидання у стек інтервалу j ∈ Active(t) з максимальним значенням end_j мінімізує кількість майбутніх конфліктів у точках t' > t.*

**Доведення:**
Інтервал `j` з максимальним `end_j` перебуватиме у наборі `Active(t')` найдовше серед усіх конкуруючих інтервалів. Вилучення `j` знижує розмір `|Active(t')|` для найтривалішого проміжку часу, звільняючи регістр для найбільшої кількості подальших коротших інтервалів. `■`

### 6. Хордальні графи у SSA-формі та точне розфарбування за поліноміальний час

У програмах, згенерованих у SSA-формі (Single Static Assignment), кожній змінній присвоюється значення строго один раз. Це створює унікальну топологічну структуру діапазонів життєвості.

#### Означення (Хордальний граф)
Граф `G = (V, E)` називається **хордальним** (англ. *chordal graph* або *triangulated graph*), якщо кожен його простий цикл довжиною `n ≥ 4` має **хорду** — ребро, яке з'єднує два несусідні вузли цього циклу.

```
C_4 без хорди (Не хордальний):     C_4 з хордою (Хордальний):
    A ────── B                         A ────── B
    │        │                         │  ╲     │
    │        │                         │    ╲   │
    C ────── D                         C ────── D
(Цикл довжиною 4)                 (Ребро A-D є хордою)
```

#### Теорема 3 (Структурна теорема Хака для SSA)
*Граф інтерференції змінних програми у SSA-формі на строго декомпозованому графі потоку керування є хордальним графом.*

**Доведення (Схема):**
У SSA-формі через єдиність оператора `Def` діапазон життєвості кожної змінної `LiveRange(v)` утворює зв'язане піддерево в графі домінування (Dominator Tree). За теоремою Гаврила (1974 рік), графи перетинів зв'язаних піддерев у дереві є строго **інтервальними або хордальними графами**.

#### Означення (Perfect Elimination Order — PEO)
Порядок впорядкування вершин `v_1, v_2, ..., v_n` графа `G` називається **порядком ідеального вилучення** (PEO), якщо для кожного `i ∈ {1, ..., n}` множина сусідів вершини `v_i` серед пізніших вершин `{v_j : j > i, (v_i, v_j) ∈ E}` утворює **кліку** (повний підграф).

#### Теорема 4 (Фундаментальна теорема про розфарбування PEO)
*Будь-який хордальний граф володіє принаймні одним порядком PEO. Якщо впорядкувати вершини хордального графа за PEO, то жадібний алгоритм розфарбування (Greedy Coloring) знаходить точний хроматичне число χ(G) = ω(G) за лінійний час O(|V| + |E|).*

```
Алгоритм розфарбування PEO (Linear-Time Chordal Coloring):
Input: Хордальний граф G=(V,E), впорядкований за PEO v_1, ..., v_n
Output: Валідне точне розфарбування c()

1. Для i = n downto 1 do:
2.   Розглянути вершину v_i
3.   Призначити c(v_i) = найменший колір k ∈ {1, 2, ...}, який НЕ зайнятий сусідніми вершинами Adj(v_i), що вже розфарбовані.
```

**Доведення точності:**
Нехай `k = χ_greedy(G)` — максимальна кількість кольорів, використана жадібним алгоритмом у порядку PEO, і нехай `v_m` — перша вершина, яка отримала колір `k`.

Згідно з алгоритмом, перед призначенням кольору `k` вершині `v_m`, усі попередні кольори `{1, 2, ..., k-1}` вже були зайняті сусідніми з `v_m` вершинами з вищими індексами в порядку PEO. Тобто `v_m` має принаймні `k - 1` сусідів у підграфі пізніших вершин.

За означенням PEO, множина цих `k - 1` сусідів утворює кліку. Разом із самою вершиною `v_m` ці вершини утворюють кліку розміром `k` вершин!

Оскільки розмір максимальної кліки `ω(G)` є очевидною нижньою межею для хроматичного числа (`χ(G) ≥ ω(G)`), а жадібний алгоритм використав `k` кольорів при наявності кліки розміру `k`:
```
k ≤ ω(G) ≤ χ(G) ≤ k  ⇒  χ(G) = ω(G) = k
```
Отже, оцінка жадібного алгоритму на PEO є строго точною. `■`

#### Оцінка складності та числовий приклад алгоритму MCS (Maximum Cardinality Search)
Для знаходження порядку PEO у хордальному графі використовується алгоритм MCS Таряна–Яннакакіса (1984 рік):
1. Кожній вершині присвоюється ваговий лічильник `weight[v] = 0`.
2. На кожному кроці обирається невідвідана вершина `u` з максимальним `weight[u]`, додається в PEO і для всіх її невідвіданих сусідів `w ∈ Adj[u]` виконується `weight[w] += 1`.

Приклад для хордального графа з ребрами `(A,B), (B,C), (C,D), (B,D)`:
- Крок 1: Обираємо `D`. PEO = `[D]`. `weight[C]=1, weight[B]=1`.
- Крок 2: Обираємо `B` (`weight[B]=1`). PEO = `[D, B]`. `weight[C]` стає `2`, `weight[A]` стає `1`.
- Крок 3: Обираємо `C` (`weight[C]=2`). PEO = `[D, B, C]`.
- Крок 4: Обираємо `A`. Підсумковий PEO = `[D, B, C, A]`.

Порядок `[D, B, C, A]` задовольняє умову PEO: для кожної вершини її сусіди далі по списку утворюють кліку. Алгоритм MCS виконується за час `O(|V| + |E|)` із використанням масиву списків (Bucket Queue). Таким чином, у SSA-формі розподіл регістрів без скидання в пам'ять розв'язується точним алгоритмом за **лінійний час `O(|V| + |E|)`**.
