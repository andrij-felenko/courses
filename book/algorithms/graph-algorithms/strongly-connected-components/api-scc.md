# 📋 Інтерфейс та специфікація API для роботи з компонентами сильної зв'язаності

Цей документ визначає повну формальну специфікацію програмного інтерфейсу (API) для аналізу орієнтованих графів, виділення компонент сильної зв'язаності (Strongly Connected Components, SCC) та побудови графа топологічної конденсації. Інтерфейс розроблений для застосування у системному програмуванні, статичних аналізаторах сирцевого коду, інструментах перевірки циклічних залежностей та системах управління транзакційними базами даних.

Головною метою цього API є надання чітко сформульованого, потокобезпечного та продуктивного контракту взаємодії між структурою графа та обчислювальним ядром. Інтерфейс гарантує строго визначену часову складність `O(|V| + |E|)` та передбачуваний профіль використання оперативної пам'яті без прихованих динамічних перерозподілів.

## 1. Архітектурні принципи та нумерація сутностей

Для забезпечення максимальної кеш-локальності процесора та мінімізації накладних витрат усі вершини графа пронумеровані послідовними цілими числами від `0` до `V - 1`, де `V` — загальна кількість вершин у графі. Передача даних списків суміжності здійснюється через пласкі масиви індексів або стандартні контейнери без використання хеш-таблиць чи вказівникових дерев.

Результати обчислень повертаються у вигляді агрегованих структур, які надають прямий доступ до ID компонент, списків вершин кожної SCC та ациклічного графа конденсації.

:::tabs
```c
#include <stddef.h>
#include <stdbool.h>

/* Повертаний результат обчислення компонент сильної зв'язаності */
typedef struct {
    int num_vertices;       /* Загальна кількість вершин у вихідному графі */
    int num_scc;            /* Кількість виявлених компонент сильної зв'язаності */
    int* comp_id;           /* Масив розміру num_vertices: comp_id[u] — ID компоненти u (0..num_scc-1) */
    int* scc_sizes;         /* Масив розміру num_scc: кількість вершин у кожній компоненті */
    int** scc_members;      /* Двовимірний масив: scc_members[i][j] — j-та вершина i-тої SCC */
} SCCResult;

/* Структура графа конденсації (DAG) */
typedef struct {
    int num_scc;            /* Кількість мета-вершин (дорівнює SCCResult.num_scc) */
    int num_dag_edges;      /* Загальна кількість унікальних мета-ребер у DAG */
    int** dag_adj;          /* Список суміжності DAG: dag_adj[i] містить сусіди компоненти i */
    int* dag_degrees;       /* Вихідні ступені мета-вершин у DAG */
    int* in_degrees;        /* Вхідні ступені мета-вершин у DAG */
} CondensationGraph;

/* Конфігураційні параметри обчислювального модуля */
typedef struct {
    bool enable_condensation; /* Автоматично будувати граф конденсації */
    bool check_invariants;   /* Виконувати перевірку діапазону індексів вершин */
    size_t stack_capacity;   /* Початковий розмір внутрішнього стека */
} SCCConfig;
```
```cpp
#include <vector>
#include <memory>
#include <span >
#include <string_view>
#include <expected>
#include <system_error>

namespace scc {

/* Інформація про одну компоненту сильної зв'язаності */
struct ComponentInfo {
    int id{0};
    std::vector<int> members;
};

/* Результат обчислення та аналізу графа у C++20 */
struct AnalysisResult {
    int vertex_count{0};
    int component_count{0};
    std::vector<int> component_map;                 // comp_map[u] -> scc_id
    std::vector<ComponentInfo> components;          // scc_id -> ComponentInfo
    std::vector<std::vector<int>> condensation_dag; // scc_id -> list of adjacent scc_ids

    /* Перевірка взаємної досяжності двох вершин за O(1) */
    [[nodiscard]] bool are_mutually_reachable(int u, int v) const noexcept {
        if (u < 0 || u >= vertex_count || v < 0 || v >= vertex_count) return false;
        return component_map[u] == component_map[v];
    }
};

/* Конфігураційні налаштування аналізатора C++ */
struct AnalyzerConfig {
    bool build_condensation{true};
    bool validate_inputs{true};
    size_t initial_buffer_size{1024};
};

} // namespace scc
```
:::

Масив `comp_id` (або `component_map` у C++) дозволяє за час `O(1)` визначити, до якої саме компоненти належить будь-яка вершина графа. Це є вирішальною інженерною перевагою при швидкій перевірці еквівалентності досяжності у прикладних задачах, таких як виявлення тупикових блокувань (deadlocks) або перевірка логічних імплікацій 2-SAT.

Поле `scc_members` (та `components` у C++) впорядковує вершини у зворотній топологічній послідовності відносно графа конденсації. Першими у списку розміщуються компоненти-стоки (які не мають вихідних ребер до інших компонент), а останніми — компоненти-джерела.

## 2. Повний функціональний контракт та сигнатури

C-інтерфейс розроблено з урахуванням сумісності з стандартом C99 та можливості легкого виклику з інших мов програмування через FFI (Foreign Function Interface), зокрема Python, Rust чи Go. C++20 обгортка надає безпечну об'єктно-орієнтовану поверхню з керуванням ресурсами за принципом RAII.

:::tabs
```c
/**
 * Обчислює компоненти сильної зв'язаності орієнтованого графа за алгоритмом Таржана.

 * @param num_vertices Загальна кількість вершин (пронумеровані 0..num_vertices-1).

 * @param adj_sizes Масив вихідних ступенів вершин (adj_sizes[u] — довжина adj_list[u]).
 * @param config Показчик на структуру конфігурації (або NULL для замовчуваних значень).

 */
SCCResult* scc_compute(
    int num_vertices,
    const int** adj_list,
    const int* adj_sizes,

 * Будує орієнтований ациклічний граф конденсації G^SCC.
 * Автоматично усуває дубльовані мета-ребра між однаковими компонентами.
 *
 * @param original_num_vertices Кількість вершин вихідного графа.
 * @param adj_list Список суміжності вихідного графа.
 * @param adj_sizes Вихідні ступені вершин вихідного графа.
 * @param result Результат виконання scc_compute().
 * @return Вказівник на структуру CondensationGraph. Пам'ять звільняється через scc_free_condensation().

    const int** adj_list,

/**
 * Експортує граф конденсації в текстовий формат Graphviz DOT для візуалізації.
 *
 * @param dag Вказівник на граф конденсації.

 * Безпечно звільняє пам'ять, виділену під структуру SCCResult.

/**
 * Безпечно звільняє пам'ять, виділену під структуру CondensationGraph.

void scc_free_condensation(CondensationGraph* dag);
```

## 3. Детальний опис функцій та семантика викликів

Розглянемо семантику кожної функції та її специфічні інваріанти:

### Функція `scc_compute`
Функція `scc_compute` приймає граф у форматі списків суміжності. Вона виконує один прохід обходу в глибину за алгоритмом Таржана, підтримуючи допоміжний стек active-вершин та масиви часів входу `tin` і досяжності `low`.

Преумови виклику `scc_compute`:
- Аргумент `num_vertices` повинен бути додатним цілим числом (`num_vertices > 0`).
- Вказівники `adj_list` та `adj_sizes` не повинні дорівнювати `NULL`.
- Кожен елемент `adj_list[u]` повинен містити масив із `adj_sizes[u]` цілих чисел, кожне з яких лежить у діапазоні `[0, num_vertices - 1]`.

Постумови та гарантії повернення:
- Функція повертає вказівник на новостворену структуру `SCCResult`.
- Поле `num_scc` містить число виявлених компонент у діапазоні `1 <= num_scc <= num_vertices`.
- Пам'ять під `comp_id`, `scc_sizes` та `scc_members` виділяється динамічно через `malloc` і повинна бути звільнена викликом `scc_free_result`.

### Функція `scc_build_condensation`
Функція `scc_build_condensation` використовує вже обчислені результати `SCCResult` для створення конденсованого графа `G^SCC`. Вона проходить по всіх оригінальних ребрах `u -> v`, знаходить відповідні компоненти `C_u = comp_id[u]` та `C_v = comp_id[v]`, і якщо `C_u != C_v`, додає мета-ребро `C_u -> C_v`.

Важливою властивістю `scc_build_condensation` є автоматична дедуплікація мета-ребер. Якщо в оригінальному графі існувало кілька ребер між різними вершинами першої та другої компонент, у граф конденсації додається лише одне унікальне мета-ребро.

### Функція `scc_export_dot`
Функція `scc_export_dot` генерує текстове представлення графа у форматі Graphviz DOT. Це дозволяє візуалізувати ациклічну структуру конденсації за допомогою утиліт `dot` або `neato`. Кожна мета-вершина відображається у вигляді вузла із зазначенням списку оригінальних вершин, що входять до її складу.

## 4. Управління пам'яттю та передача володіння

Розподіл оперативної пам'яті у C-інтерфейсі виконується за схемою єдиного володіння (single ownership). Вся пам'ять, виділена під `SCCResult` та `CondensationGraph`, належить відповідному об'єкту і звільняється парними функціями `scc_free_result` та `scc_free_condensation`.

Структура пам'яті об'єкта `SCCResult`:
1. Головний заголовок `SCCResult`: один блок пам'яті `sizeof(SCCResult)`.
2. Масив відображення `comp_id`: один плаский масив `int[num_vertices]`.
3. Масив розмірів компонент `scc_sizes`: один плаский масив `int[num_scc]`.
4. Двовимірний масив складу компонент `scc_members`: один масив вказівників `int*[num_scc]`, де кожен елемент вказує на окремо виділений масив `int[scc_sizes[i]]`.

Виклик `scc_free_result` ітерується по всіх елементах `scc_members[i]`, звільняє їхній вміст, після чого звільняє самі масиви `scc_members`, `scc_sizes`, `comp_id` та головну структуру. Для запобігання витокам пам'яті не допускається часткове звільнення полів структури.

У C++20 версії API всі масиви реалізовані через об'єктні контейнери `std::vector`. Передача результатів з аналізатора виконується через семантику переміщення (move semantics), що унеможливлює накладні витрати на копіювання даних та повністю усуває ризик витоків пам'яті.

## 5. Обробка помилок та гарантії потокобезпечності

Обчислювальні функції ядра розроблені за принципом чистих функцій (pure functions): вони не використовують глобальних змінних, не модифікують вхідні масиви графа і є повністю потокобезпечними (reentrant and thread-safe).

Детальний регламент обробки помилкових станів:
1. **Некоректні вхідні індекси:** Якщо вказівник `adj_list` містить індекс вершини `v < 0` або `v >= num_vertices`, функція `scc_compute` у режимі перевірки інваріантів перериває обчислення, встановлює `errno = EINVAL` і повертає `NULL`. У C++20 версії повертається `ErrorCode::InvalidVertexIndex`.
2. **Нестача пам'яті:** При невдалій спробі виділення пам'яті у функціях C повертається `NULL` із виставленням `errno = ENOMEM`. У C++20 версії повертається `ErrorCode::AllocationFailure` або генерується виняток `std::bad_alloc`.
3. **Потокобезпечність:** Кілька потоків можуть одночасно викликати `scc_compute()` або `analyze()` для різних графів без будь-якого взаємного впливу чи потреби в синхронізації м'ютексами.

## 6. Інтеграція з іншими мовами програмування (FFI Bindings)

C99-сумісність бібліотеки дозволяє легко використовувати її з інших мов програмування без перевизначення алгоритму.

### Виклики з Python через `ctypes`
Взаємодія з Python здійснюється за допомогою стандартного модуля `ctypes`. Вхідні списки суміжності перетворюються на ctypes-масиви покажчиків, після чого викликається `scc_compute()`. Отримані масиви `comp_id` зчитуються безпосередньо у виділені списки Python.

### Виклики з Rust через `extern "C"`
У мові Rust бібліотека імпортується як `unsafe extern "C"` модуль. Отриманий вказівник `*mut SCCResult` обгортається у безпечну RAII-структуру із реалізацією трейту `Drop`, який автоматично викликає `scc_free_result` при виході з області видимості.

### Виклики з Go через `cgo`
У мові Go зв'язок реалізується через імпорт пакета `"C"`. Вхідні срізи `[]int` передаються як неуправляючі C-масиви, а результати конвертуються у native Go-структури перед очищенням пам'яті.

## 7. Специфікація консольної утиліти (CLI Tool: `scc-tool`)

Для аналізу графів у скриптах автоматизації, конвеєрах компіляції та CI/CD надається консольна утиліта `scc-tool`.

```
Використання: scc-tool [ОПЦІЇ] <ВХІДНИЙ_ФАЙЛ_ГРАФА>

Опції:
  -f, --format <fmt>       Формат вхідного файла: 'adjlist', 'edges', 'dot', 'json'.
  -o, --output <file>      Шлях до вихідного файла результату JSON.
  -c, --condense           Згенерувати граф конденсації DAG.
  -d, --dot-output <file>  Зберегти результат у форматі Graphviz DOT.
  -v, --verbose            Виводити розширений лог трасування обходу.
  -h, --help               Показати довідку.
```

Приклади застосування консольної утиліти:

```bash
# Проаналізувати граф залежностей C++ модулів у форматі списку ребер
scc-tool --format edges --condense --output report.json --dot-output condensation.dot deps.txt

# Візуалізувати конденсований DAG за допомогою утиліти Graphviz
dot -Tsvg condensation.dot -o condensation.svg
```

Формат вихідного JSON файлу, згенерованого `scc-tool`:

```json
{
  "vertex_count": 5,
  "component_count": 3,
  "components": [
    {"id": 0, "members": [4]},
    {"id": 1, "members": [3]},
    {"id": 2, "members": [0, 1, 2]}
  ],
  "condensation_dag": [
    {"from": 2, "to": 1},
    {"from": 1, "to": 0}
  ]
}
```

## 8. Таблиця складності та гарантії продуктивності

Усі операції даного API забезпечують оптимальну складність, що відповідає нижній теоретичній межі.

| Операція / Функція | Часова складність (Worst-case) | Допоміжна пам'ять | Преумови та обмеження |
| :--- | :--- | :--- | :--- |
| `scc_compute()` / `analyze()` | `O(|V| + |E|)` | `O(|V|)` | Vertices in `[0, V-1]`, Non-null pointers |
| `scc_build_condensation()` | `O(|V| + |E|)` | `O(|V^SCC| + |E^SCC|)` | Valid `SCCResult` handle |
| `scc_export_dot()` / `to_dot()` | `O(|V^SCC| + |E^SCC|)` | `O(1)` | Valid `CondensationGraph` handle |
| Lookup `are_mutually_reachable()` | `O(1)` | `O(1)` | `u, v < vertex_count` |
| `scc_free_result()` | `O(|V^SCC|)` | `O(1)` | Non-null `SCCResult*` |
| `scc_free_condensation()` | `O(|V^SCC|)` | `O(1)` | Non-null `CondensationGraph*` |

## 9. Інваріанти топологічного сортування

API гарантує наступні топологічні інваріанти при поверненні результатів:
1. **Реверсивний топологічний порядок:** Індекси компонент `comp_id` та порядок елементів у масиві `components` відповідають зворотному топологічному порядку мета-вершин графа конденсації `G^SCC`. Компоненти-стоки (які не мають вихідних ребер до інших компонент) отримують найменші індекси `comp_id = 0, 1, ...`, а компоненти-джерела — найбільші індекси.
2. **Усунення кратних ребер:** Граф конденсації `CondensationGraph` гарантовано не містить паралельних дуг між однаковими мета-вершинами.
3. **Ізольовані вершини:** Кожна ізольована вершина вихідного графа утворює окрему компоненту сильної зв'язаності розміром в один елемент.
