# 🧮 Математичні моделі масштабування: від Амдала до USL

Аналіз продуктивності паралельних систем вимагає точних математичних співвідношень між часом виконання, кількістю обчислювальних вузлів та структурою алгоритму. У цьому документі послідовно виведено та проаналізовано фундаментальні моделі масштабування: класичний закон Амдала, метрику Карпа — Флатта, закон Густафсона — Барсіса, закон Суна — Ні та універсальний закон масштабованості Ґюнтера (USL).

---

## 1. Закон Амдала (сильне масштабування, Strong Scaling)

Нехай загальний обсяг обчислювальної роботи фіксований (розмір входу не залежить від кількості ядер). Позначимо час виконання алгоритму на одному процесорі як `T₁`.

Розкладемо `T₁` на дві складові:
1. `T_s` — час, витрачений на суто послідовні операції, які неможливо розпаралелити;
2. `T_p` — час, витрачений на операції, що можуть виконуватися повністю паралельно.

```
T₁ = T_s + T_p
```

Введемо відносні частки:
- Послідовна частка: `s = T_s / T₁`, де `0 ≤ s ≤ 1`.
- Паралельна частка: `p = T_p / T₁ = 1 - s`, де `0 ≤ p ≤ 1`.

Припускаємо, що паралельна частина ділиться між `N` процесорами ідеально рівномірно і без накладних витрат. Тоді час виконання на `N` процесорах `T(N)` становить:

```
T(N) = T_s + T_p / N
     = T₁·s + (T₁·p) / N          [підстановка T_s = s·T₁, T_p = p·T₁]
     = T₁ · (s + p / N)           [винесення T₁ за дужки]
     = T₁ · ((1 - p) + p / N)     [заміна s = 1 - p]
```

### Коефіцієнт прискорення (Speedup)

Прискорення `S(N)` визначається як відношення часу виконання на одному процесорі до часу на `N` процесорах:

```
S(N) = T₁ / T(N)
     = T₁ / (T₁ · ((1 - p) + p / N))  [підстановка формули T(N)]
     = 1 / ((1 - p) + p / N)          [скорочення на T₁]
     = 1 / (s + (1 - s) / N)          [еквівалентний запис через s]
```

### Асимптотична межа

Дослідимо поведінку функції `S(N)` при прямуванні кількості процесорів `N` до нескінченності:

```
lim_{N → ∞} S(N)
= lim_{N → ∞} [ 1 / ((1 - p) + p / N) ]
= 1 / ((1 - p) + 0)                     [оскільки lim p/N = 0]
= 1 / (1 - p)
= 1 / s
```

**Висновок:** максимальне теоретичне прискорення алгоритму при фіксованому обсязі даних обмежене величиною `1 / s` і не залежить від потужності обчислювальної системи.

### Диференціальний аналіз та спадна віддача

Знайдемо першу та другу похідні функції прискорення за кількістю процесорів `N` (розглядаючи `N` як неперервну змінну на інтервалі `[1, ∞)`):

```
S(N) = ( (1 - p) + p·N⁻¹ )⁻¹

dS/dN
= -1 · ( (1 - p) + p·N⁻¹ )⁻² · (-p·N⁻²)   [правило диференціювання складеної функції]
= p / ( N² · ((1 - p) + p / N)² )          [спрощення знаків]
```

Оскільки `p > 0` та `N ≥ 1`, перша похідна `dS/dN > 0` строго додатна. Це означає, що додавання нових процесорів завжди монотонно збільшує прискорення, але швидкість приросту стрімко падає.

Обчислимо другу похідну `d²S/dN²`:

```
d²S/dN²
= d/dN [ p · ( (1 - p)·N + p )⁻² ]
= p · (-2) · ( (1 - p)·N + p )⁻³ · (1 - p)
= -2·p·(1 - p) / ( (1 - p)·N + p )³
```

Оскільки `0 < p < 1`, друга похідна `d²S/dN² < 0` строго від'ємна для всіх `N ≥ 1`. Функція `S(N)` є строго увігнутою (англ. *strictly concave*), що формалізує фундаментальний закон спадної віддачі (англ. *diminishing returns*).

### Паралельна ефективність

Паралельна ефективність `E(N)` показує частку потужності ядер, яка реально використовується для корисної роботи:

```
E(N) = S(N) / N
     = 1 / ( N · ((1 - p) + p / N) )      [підстановка формули прискорення S(N)]
     = 1 / ( N·(1 - p) + p )              [внесення множника N у дужки]
     = 1 / ( N·s + (1 - s) )              [заміна p = 1 - s]
```

Границя ефективності при `N → ∞` (якщо `s > 0`):

```
lim_{N → ∞} E(N) = lim_{N → ∞} [ 1 / (s·N + (1 - s)) ] = 0   [знаменник зростає необмежено при s > 0]
```

Ефективність прямує до нуля. При великих `N` більшість процесорів практично весь час очікують завершення послідовної фази.

## 2. Метрика Карпа — Флатта (Karp-Flatt Metric)

На практиці виміряне на реальній машині прискорення `S_exp(N)` завжди менше за теоретичне `S(N)`. Причиною цього є не лише алгоритмічна послідовна частка `s`, а й накладні витрати паралелізму: створення потоків, синхронізація через м'ютекси, пересилання повідомлень мережею та промахи повз кеш.

1990 року Алан Карп (Alan H. Karp) та Горас Флатт (Horace P. Flatt) запропонували метрику експериментально визначеної послідовної частки `e`.

### Виведення формули

Виходимо з формули закону Амдала, розглядаючи `e` як невідому ефективну послідовну частку:

```
1 / S(N) = e + (1 - e) / N
1 / S(N) = e + 1/N - e/N            [розкриття дужок у чисельнику]
1 / S(N) - 1/N = e · (1 - 1/N)      [винесення e за дужки та перенесення 1/N]
e = ( 1 / S(N) - 1 / N ) / ( 1 - 1 / N )  [ділення на вираз (1 - 1/N)]
```

### Діагностичне значення метрики `e`

Метрика Карпа — Флатта дозволяє розрізнити два принципово різні джерела поганого масштабування системи:

1. **Якщо `e(N)` залишається приблизно сталим** при збільшенні `N`:
   Причиною обмеження швидкості є внутрішня алгоритмічна послідовна частка коду (алгоритм треба оптимізувати за алгоритмічною декомпозицією).
2. **Якщо `e(N)` монотонно зростає** зі збільшенням `N`:
   Причиною є накладні витрати міжпроцесорної взаємодії, конкуренція за спільні ресурси (блокування, шина пам'яті, когерентність кешів) або затримки мережі.

## 3. Закон Густафсона — Барсіса (слабке масштабування, Weak Scaling)

1988 року Джон Густафсон і Едвін Барсіс запропонували іншу модель масштабування, що описує поведінку систем при розв'язанні задач із масштабованим обсягом даних.

Припущення моделі: із додаванням нових процесорів час розрахунку залишається сталим, а обсяг розв'язуваної задачі збільшується пропорційно до кількості ядер `N`.

Нехай час виконання масштабованої задачі на `N` процесорах дорівнює `T(N) = 1` (нормалізована одиниця часу).
У межах цієї одиниці часу:
- `s'` — частка часу, витрачена на послідовну роботу на одному ядрі;
- `p' = 1 - s'` — частка часу, витрачена на паралельну роботу на `N` ядрах одночасно.

Якби той самий збільшений обсяг роботи виконувався на одному процесорі, послідовна частина зайняла б час `s'`, а паралельна — `N · p'`. Загальний час на одному процесорі склав би:

```
T₁ = s' + N · p'
```

### Масштабоване прискорення (Scaled Speedup)

```
S_G(N) = T₁ / T(N)
       = (s' + N · p') / 1           [нормалізація T(N) = 1]
       = s' + N · (1 - s')           [заміна p' = 1 - s']
       = s' + N - N·s'               [розкриття дужок]
       = N - s' · (N - 1)            [групування доданків із коефіцієнтом s']
```

### Порівняння лінійності

На відміну від закону Амдала, функція Густафсона — Барсіса `S_G(N)` є строго лінійною за `N`:

```
dS_G / dN = 1 - s' = p' = const      [похідна лінійної функції]
```

Якщо послідовна частка масштабованої задачі становить `s' = 0.01` (1%), то на `N = 1024` процесорах прискорення дорівнює:

```
S_G(1024) = 1024 - 0.01 · (1024 - 1)    [підстановка N = 1024 та s' = 0.01]
          = 1024 - 0.01 · 1023          [віднімання в дужках]
          = 1024 - 10.23                [множення на частку 0.01]
          = 1013.77×                    [кінцевий розрахунок прискорення]
```

Це пояснює, чому суперкомп'ютери з сотнями тисяч ядер демонструють майже лінійне масштабування для великих наукових симуляцій: розмір сітки розбиття просто збільшують разом із кластером.

## 4. Закон Суна — Ні (Memory-Bounded Speedup)

Сянь-Хе Сун (Xian-He Sun) та Лайонел Ні (Lionel M. Ni) 1993 року узагальнили закони Амдала та Густафсона для випадку, коли розмір задачі обмежений загальним обсягом оперативної пам'яті системи.

Якщо система з `N` вузлів має сумарну пам'ять `M(N) = N · M₁`, то обсяг обчислювальної роботи зростає як функція від коефіцієнта масштабування пам'яті `G(N)`:

```
S_SN(N) = ( s + (1 - s) · G(N) ) / ( s + (1 - s) · G(N) / N )
```

Граничні випадки закону Суна — Ні:
1. Якщо обсяг роботи не змінюється зі зростанням пам'яті (`G(N) = 1`), формулу зведено до **закону Амдала**:
   `S_SN(N) = 1 / (s + (1 - s)/N)`.
2. Якщо обсяг роботи зростає строго лінійно з пам'яттю (`G(N) = N`), формулу зведено до **закону Густафсона**:
   `S_SN(N) = (s + (1 - s)·N) / (s + (1 - s)) = s + (1 - s)·N`.
3. Якщо складність алгоритму перевищує обсяг даних (наприклад, множення щільних матриць розміром `M`, де обсяг пам'яті `O(M²)`, а операцій `O(M³) = O(M^{3/2})`), то `G(N) = N^{3/2} > N`. У цьому випадку досягається надлінійне прискорення масштабованої задачі.

## 5. Універсальний закон масштабованості Ґюнтера (USL, Universal Scalability Law)

Усі попередні моделі припускають, що прискорення є або обмеженим константою (Амдал), або монотонно зростаючим (Густафсон). Проте в реальних комп'ютерних системах (бази даних, веб-сервери, розподілені черги) при перевищенні певної кількості потоків продуктивність починає **падати** (ретроградне масштабування, англ. *retrograde scalability*).

Ніл Ґюнтер (Neil J. Gunther) 1993 року на основі теорії масового обслуговування вивів універсальний закон масштабованості (USL), який враховує два фундаментальні фізичні фактори деградації:

1. **Конкуренція за ресурси (Contention / Serialization, `σ`):** черги до спільних блокувань, пам'яті чи диска (еквівалент послідовної частки Амдала).
2. **Накладні витрати узгодження (Coherency / Crosstalk, `κ`):** затримки на обмін повідомленнями між ядрами для підтримання когерентності кешів (протоколи MESI/MOESI), попарні звірки статусів вузлів тощо. Кількість таких зв'язків у системі з `N` вузлів зростає як `N · (N - 1)`.

### Формула USL

Відносне прискорення (або масштабованість пропускної здатності) `C(N)` задається рівнянням:

```
C(N) = N / ( 1 + σ·(N - 1) + κ·N·(N - 1) )
```

де:
- `N` — кількість ядер / робочих вузлів;
- `σ` — коефіцієнт конкуренції (`0 ≤ σ ≤ 1`);
- `κ` — коефіцієнт когерентності (`0 ≤ κ ≤ 1`).

### Граничні переходи USL

1. Якщо накладні витрати відсутні (`σ = 0, κ = 0`):
   `C(N) = N / 1 = N` (ідеальне лінійне масштабування).
2. Якщо відсутня когерентність (`κ = 0`), але є черги (`σ > 0`):
   `C(N) = N / (1 + σ·(N - 1)) = 1 / (σ + (1 - σ)/N)` (закон Амдала з послідовною часткою `s = σ`).
3. Якщо `κ > 0`: доданок другого порядку `κ·N·(N - 1)` у знаменнику зростає пропорційно до `N²`. При великих `N` знаменник зростає швидше за чисельник, через що `C(N) → 0`.

### Знаходження точки пікової продуктивності

Щоб знайти кількість ядер `N*`, при якій досягається максимальна продуктивність, візьмемо похідну `dC/dN` та прирівняємо її до нуля:

```
C(N) = N · ( 1 + σ·(N - 1) + κ·N·(N - 1) )⁻¹
     = N · ( (1 - σ) + σ·N + κ·N² - κ·N )⁻¹
     = N · ( (1 - σ) + (σ - κ)·N + κ·N² )⁻¹

dC/dN = [ 1·( (1 - σ) + (σ - κ)·N + κ·N² ) - N·( (σ - κ) + 2·κ·N ) ] / ( Знаменник )²
      = [ (1 - σ) + (σ - κ)·N + κ·N² - (σ - κ)·N - 2·κ·N² ] / ( Знаменник )²
      = [ (1 - σ) - κ·N² ] / ( Знаменник )²
```

Прирівнюємо чисельник до нуля:

```
(1 - σ) - κ · (N*)² = 0
κ · (N*)² = 1 - σ
(N*)² = (1 - σ) / κ
N* = √[ (1 - σ) / κ ]
```

Підставивши знайдене оптимальне `N*` у вихідну формулу `C(N)`, отримуємо максимальну теоретичну ємність системи.

### Приклад розрахунку

Нехай у багатопотоковій базі даних частка блокувань становить `σ = 0.04` (4%), а накладні витрати когерентності кешів `κ = 0.001` (0.1%).

1. Оптимальна кількість потоків:
   `N* = √[ (1 - 0.04) / 0.001 ] = √[ 0.96 / 0.001 ] = √960 ≈ 30.98` (тобто 31 потік).
2. Максимальне досяжне прискорення:
   `C(31) = 31 / ( 1 + 0.04 · 30 + 0.001 · 31 · 30 ) = 31 / ( 1 + 1.2 + 0.93 ) = 31 / 3.13 ≈ 9.90×`.

Якщо ми запустимо цю систему на сервері зі 128 ядрами:
`C(128) = 128 / ( 1 + 0.04 · 127 + 0.001 · 128 · 127 ) = 128 / ( 1 + 5.08 + 16.256 ) = 128 / 22.336 ≈ 5.73×`.

Продуктивність на 128 ядрах впала майже вдвічі порівняно з 31 ядром. Додавання нових обчислювальних потужностей перетворилося на пряме погіршення сервісу через шторм міжядерних інвалідацій кеш-ліній.
