# 🧮 Формальне математичне доведення теореми FLP

У розподілених системах часто виникає спокуса вважати, що труднощі консенсусу спричинені винятково втратою повідомлень або підступними візантійськими збоями. Теорема Фішера, Лінч та Патерсона (Fischer, Lynch, Paterson, 1985), відома як **FLP**, спростовує цю ілюзію. Вона доводить фундаментальний факт: в асинхронній системі навіть за абсолютно надійних каналів зв'язку не існує детермінованого алгоритму, який гарантує одностайність і завершення, якщо хоча б один вузол може зазнати простої аварійної зупинки.

Нижче наведено повне математичне доведення цього результату з формалізацією станів, валентності та аналізом комутативності подій.

## Формальна модель системи

Система складається зі скінченної множини процесів `P = {p₁, p₂, ..., p_N}`, де `N ≥ 2`.

Кожен процес `pᵢ` має внутрішній стан `sᵢ`. Серед можливих станів є початкові стани з вхідним бітом `xᵢ ∈ {0, 1}` та кінцеві стани, в яких зафіксовано рішення `yᵢ ∈ {0, 1}`. Зміна стану детермінована й регулюється локальною функцією переходів.

Мережа моделюється як спільний буфер повідомлень `M`, що є мультимножиною не доставлених пакетів. Повідомлення має вигляд `m = (dest, data)`, де `dest ∈ P` — процес-одержувач, а `data` — корисне навантаження.

**Конфігурація системи** `C` — це зріз станів усіх процесів та поточного вмісту буфера повідомлень:

```
C = (s₁, s₂, ..., s_N, M)
```

**Крок (подія)** `e = (p, m)` складається з двох атомарних дій:
1. Процес `p` вилучає повідомлення `m` із буфера `M` (або отримує порожнє повідомлення `∅`, якщо в буфері для нього нічого немає).
2. Процес `p`, залежно від свого поточного стану `s_p` та повідомлення `m`, змінює свій стан на `s_p'` і додає скінченну множину нових повідомлень `M'` до буфера `M`.

Подія `e = (p, m)` застосовна до конфігурації `C`, якщо `m ∈ M` або `m = ∅`. Результат застосування події позначається як `e(C)`.

**Виконанням (execution)** із початкової конфігурації `C₀` називається скінченна або нескінченна послідовність кроків:

```
C₀ ─e₁→ C₁ ─e₂→ C₂ ─e₃→ ...
```

Виконання є **справедливим (fair)**, якщо кожне повідомлення, що потрапило в буфер `M`, зрештою доставляється адресату, і кожен процес, який не зазнав збою, нескінченно часто отримує можливість зробити крок.

## Вимоги до алгоритму консенсусу

Детермінований алгоритм є коректним алгоритмом консенсусу, стійким до одного збою аварійної зупинки (`f = 1`), якщо він задовольняє три аксіоми:

1. **Узгодженість (Agreement):** Жодні два процеси не приймають різних рішень. Для будь-якої конфігурації `C`, де процес `p` вирішив `y_p`, а процес `q` вирішив `y_q`, виконується:
```
y_p = y_q
```
2. **Слушність / Валідність (Validity):** Якщо всі процеси стартують із вхідним значенням `0`, єдиним можливим рішенням є `0`. Якщо всі стартують із `1`, єдиним можливим рішенням є `1`.
3. **Завершуваність (Termination / Liveness):** У будь-якому справедливому виконанні, де щонайбільше один процес зазнає аварійної зупинки (перестає робити кроки), кожен працюючий процес зрештою фіксує рішення.

## Поняття валентності конфігурації

Нехай `C` — довільна конфігурація. Множиною досяжних рішень `V(C) ⊆ {0, 1}` називається множина всіх значень, які можуть бути вирішені процесами в усіх конфігураціях, досяжних із `C`.

* Конфігурація `C` називається **0-валентною**, якщо `V(C) = {0}`. З цього стану система за будь-якого подальшого розвитку подій приречена вирішити `0`.
* Конфігурація `C` називається **1-валентною**, якщо `V(C) = {1}`. Система приречена вирішити `1`.
* Конфігурація `C` називається **унівалентною**, якщо вона є 0-валентною або 1-валентною (`|V(C)| = 1`).
* Конфігурація `C` називається **бівалентною**, якщо `V(C) = {0, 1}`. Тобто з `C` існують як виконання, що приводять до рішення `0`, так і виконання, що приводять до рішення `1`.

У бівалентному стані майбутній результат системи ще не визначений: він залежить від відносного порядку доставки майбутніх повідомлень.

## Лема про комутативність (Diamond Lemma)

Якщо дві події стосуються різних процесів, порядок їх виконання не змінює результуючої конфігурації.

**Формулювання:** Нехай `e₁ = (p₁, m₁)` та `e₂ = (p₂, m₂)` — дві події, де `p₁ ≠ p₂`. Якщо обидві події застосовні до конфігурації `C`, то:
1. `e₂` застосовна до `e₁(C)`;
2. `e₁` застосовна до `e₂(C)`;
3. Обидва шляхи приводять до тотожної конфігурації:

```
e₂(e₁(C))
= e₁(e₂(C))      [комутативність дій над незалежними локальними станами]
```

**Доведення:** Подія `e₁` змінює лише локальний стан процесу `p₁` та вилучає `m₁` із буфера, додаючи нові повідомлення `M₁`. Подія `e₂` змінює локальний стан `p₂` та взаємодіє з `m₂`. Оскільки процеси різні (`p₁ ≠ p₂`), їхні локальні стани диз'юнктні. Мультимножина повідомлень змінюється однаково: вилучаються `{m₁, m₂}` та додаються `M₁ ∪ M₂`. Отже, кінцеві конфігурації збігаються по всіх компонентах.

## Лема 1: Існування початкової бівалентної конфігурації

**Твердження:** Існує початкова конфігурація системи `C₀`, яка є бівалентною.

**Доведення від супротивного:**
Припустимо зворотне: усі початкові конфігурації є унівалентними (або 0-валентними, або 1-валентними).

Початкова конфігурація повністю визначається вектором вхідних значень `X = (x₁, x₂, ..., x_N)`.
За вимогою валідності:
* Конфігурація `(0, 0, ..., 0)` зобов'язана бути 0-валентною.
* Конфігурація `(1, 1, ..., 1)` зобов'язана бути 1-валентною.

Впорядкуємо всі можливі вектори входів у ланцюжок так, щоб кожен сусідній вектор відрізнявся вхідним значенням рівно одного процесу:

```
I₀ = (0, 0, 0, ..., 0)
I₁ = (1, 0, 0, ..., 0)
I₂ = (1, 1, 0, ..., 0)
...
I_N = (1, 1, 1, ..., 1)
```

Оскільки `I₀` є 0-валентним, а `I_N` є 1-валентним, у цьому ланцюжку мусить існувати індекс `k`, для якого конфігурація `I_k` є 0-валентною, а конфігурація `I_{k+1}` є 1-валентною.

Ці дві конфігурації різняться лише вхідним значенням одного процесу `p = p_{k+1}`:
* У `I_k` процес `p` має вхід `0`.
* У `I_{k+1}` процес `p` має вхід `1`.

Розглянемо виконання системи, в якому процес `p` зазнає аварійної зупинки на самому початку (не робить жодного кроку й не надсилає жодного повідомлення).

Оскільки алгоритм за умовою завершуваний за одного збою (`f = 1`), решта `N - 1` процесів зобов'язані дійти рішення. Нехай вони виконують справедливу послідовність кроків `σ`, в якій процес `p` не бере участі:

```
C_A = σ(I_k)
C_B = σ(I_{k+1})
```

Оскільки жоден процес, крім `p`, не бачить початкового стану `p` і не отримує від нього повідомлень, для всіх інших процесів стани в `I_k` та `I_{k+1}` ідентичні. Отже, послідовність дій `σ` виконується абсолютно однаково в обох випадках, приводячи до однакового рішення `v`:

```
decision(σ(I_k))
= decision(σ(I_{k+1}))      [нерозрізненість станів іншими N-1 процесами]
```

Але `I_k` є 0-валентною, тому `decision(σ(I_k)) = 0`. Водночас `I_{k+1}` є 1-валентною, тому `decision(σ(I_{k+1})) = 1`. Отримуємо суперечність:

```
0 = 1
```

Ця суперечність доводить, що не всі початкові конфігурації унівалентні. Отже, існує початкова конфігурація `C₀`, яка є бівалентною.

## Лема 2: Збереження бівалентності під час кроків

**Твердження:** Нехай `C` — довільна бівалентна конфігурація, а `e = (p, m)` — подія, застосовна до `C`. Нехай `E` — множина всіх конфігурацій, досяжних із `C` без застосування події `e`. Тоді в множині `e(E) = { e(D) | D ∈ E }` існує конфігурація, яка є бівалентною.

**Доведення від супротивного:**
Припустимо, що множина `e(E)` не містить жодної бівалентної конфігурації. Тобто для кожної `D ∈ E` стан `e(D)` є суворо унівалентним (0-валентним або 1-валентним).

Оскільки `C` є бівалентною, із неї досяжні як 0-валентні, так і 1-валентні конфігурації. Отже, у множині `E` мусять існувати такі конфігурації `D₀` та `D₁`, що `e(D₀)` є 0-валентною, а `e(D₁)` є 1-валентною.

Оскільки граф переходів між конфігураціями зв'язний, у множині `E` існує пара сусідніх конфігурацій `C₁` та `C₂ = e'(C₁)`, таких що:
* `e(C₁)` є 0-валентною;
* `e(C₂)` є 1-валентною, де `C₂ = e'(C₁)`, а `e' = (p', m')` — деяка подія.

Розглянемо взаємне відношення подій `e` та `e'`.

### Випадок 1: Події e та e' стосуються різних процесів (p ≠ p')

Подія `e` виконується процесом `p`, а подія `e'` виконується процесом `p'`.
За лемою про комутативність:

```
e(C₂)
= e(e'(C₁))
= e'(e(C₁))      [лема про комутативність подій незалежних процесів]
```

Але `e(C₁)` є 0-валентною, тому будь-який стан, досяжний із неї, зокрема `e'(e(C₁))`, також зобов'язаний бути 0-валентним.
З іншого боку, `e(C₂)` за припущенням є 1-валентною. Отримуємо, що та сама конфігурація одночасно є 0-валентною і 1-валентною:

```
V(e(C₂)) = {0} ∧ V(e(C₂)) = {1}
```

Суперечність.

### Випадок 2: Події e та e' стосуються одного процесу (p = p')

Нехай обидві події виконуються процесом `p`.
Розглянемо скінченне справедливе виконання `σ`, в якому процес `p` не робить жодного кроку (імітація його аварійної зупинки), що стартує з `C₁`.

Оскільки алгоритм стійкий до збою одного процесу, послідовність `σ` мусить привести систему до деякої термінальної конфігурації `A = σ(C₁)`, в якій зафіксовано певне рішення (нехай, без обмеження загальності, це рішення `0`).

Оскільки кроки в `σ` не зачіпають процес `p`, подія `e` залишається застосовною до всіх проміжних станів у `σ`, а також до `A`.
За лемою про комутативність:

```
e(A)
= e(σ(C₁))
= σ(e(C₁))      [комутативність кроків σ та події e над процесом p]
```

Оскільки `e(C₁)` є 0-валентною, стан `σ(e(C₁))` зобов'язаний мати рішення `0`.
Тепер застосуємо послідовність дій `σ` до конфігурації `C₂ = e'(C₁)`:

```
e(σ(C₂))
= e(σ(e'(C₁)))
= σ(e(e'(C₁)))
= σ(e(C₂))      [комутативність кроків σ та події e]
```

Але `e(C₂)` є 1-валентною, отже `σ(e(C₂))` зобов'язана мати рішення `1`.
Проте процеси, що брали участь у кроках `σ`, не можуть відрізнити стан `A = σ(C₁)` від стану `σ(C₂)`, оскільки різниця між `C₁` та `C₂` полягає винятково у внутрішніх змінах процесу `p`, які він не встиг повідомити іншим вузлам. Отримуємо суперечність щодо узгодженості рішень.

Суперечність в обох випадках доводить лему: завжди існує крок, який зберігає бівалентність системи.

## Головна теорема (Fischer, Lynch, Paterson)

**Теорема:** Жоден детермінований протокол асинхронного консенсусу не може гарантувати одночасно узгодженість, валідність та завершуваність за наявності хоча б одного можливого збою аварійної зупинки.

**Доведення:**
Побудуємо нескінченне справедливе виконання, в якому система ніколи не досягає унівалентного стану й, отже, ніколи не приймає остаточного рішення.

1. За **Лемою 1** обираємо початкову бівалентну конфігурацію `C₀`.
2. Підтримуємо чергу очікуваних повідомлень `Q = (m₁, m₂, m₃, ...)`, упорядковану за часом їх створення.
3. На кожному кроці `i ≥ 0`:
   - Беремо найстаріше повідомлення `m` із черги `Q`, адресоване процесу `p`. Нехай подія `e = (p, m)`.
   - За **Лемою 2** у дереві досяжних конфігурацій із `C_i` існує послідовність кроків `σ_i` (що не використовує `e`) та стан `D_i = σ_i(C_i)`, для якого конфігурація `C_{i+1} = e(D_i)` є **бівалентною**.
   - Переводимо систему в стан `C_{i+1}` шляхом виконання кроків `σ_i`, за якими слідує подія `e`.
   - Додаємо всі новостворені повідомлення в кінець черги `Q`.

Оскільки на кожному кроці `i` чергове повідомлення `m` гарантовано доставляється (через виконання події `e`), побудоване виконання є **справедливим**: жодне повідомлення не застрягає в буфері назавжди.

Проте за побудовою кожна нова конфігурація `C_i` є **бівалентною**. У бівалентному стані жоден процес не має права зафіксувати остаточне рішення, оскільки з такого стану все ще залишаються досяжними як рішення `0`, так і рішення `1`.

Отже, система виконує нескінченну кількість кроків, не порушуючи правил протоколу й не втрачаючи пакетів, але так і не приймає рішення:

```
lim [t → ∞] decision_time(t) = ∞
```

Це завершує доведення теореми неможливості FLP.
