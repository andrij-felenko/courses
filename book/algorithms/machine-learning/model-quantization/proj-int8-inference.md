# ⚙️ int8-вивід одного шару на C: акумулятор, реквантування, пастки

## Задача

Ідея, що множення нейромережі можна вести самими цілими, красива на папері: `wᵢ·xᵢ` в int8, сума в широкому цілому, дробове множення винесене за цикл. Але між цією ідеєю і працюючою прошивкою лежить пропасть із дрібниць, кожна з яких мовчки псує відповідь: скільки бітів витримає скарбничка-сума, у якому саме порядку відняти zero-point, чим замінити те «останнє дробове множення», щоб і воно стало цілим, і як округлити при зсуві, щоб мережа не поїхала в один бік.

Мета тут — **дописати ідею до кінця**: один самодостатній шматок C, що рахує повноз'вязний (dense) шар int8-мережі від сирих int8-входів до int8-виходів, без жодної операції з рухомою комою в гарячому циклі. Такий, який реально лягає у прошивку мікроконтролера без блоку float — і дає **точно ту саму** відповідь, що й еталонний рушій на кшталт TFLite Micro, до останнього біта. Бо квантований вивід тим і підступний: майже правильний код, який округлює «якось інакше», розходиться з навченою моделлю не на шумі, а на систематичному зсуві, і мережа тихо дурнішає.

Розберемо dense-шар — `y = W·x + b` — бо він оголює всю механіку без зайвого клопоту з індексами. Згортка ([convolution](book:algorithms/cnn)) арифметично — той самий скалярний добуток, лише вікном по зображенню; усе про акумулятор і реквантування переноситься на неї слово в слово, змінюється тільки, звідки брати `q_x`.

## Ідея

Три речі треба розкласти по поличках, перш ніж писати цикл.

**Перше — що де лежить у пам'яті.** Ваги вже квантовані офлайн і зашиті у флеш як `int8`. Кожен вихідний нейрон (рядок матриці `W`) має **власний** scale — це **per-channel** квантування, тож масштаб — не одне число, а масив, по одному на вихід. Активації на вході — `int8` зі **спільним** (per-tensor) scale `s_x` і своїм zero-point `z_x`; ваги симетричні, тож їхній zero-point нуль і в коді його просто немає. Зсув `b` (bias) зберігають одразу в **int32** у масштабі акумулятора — так його можна додати прямо до цілої суми, не переводячи нічого в float.

**Друге — сам цикл множення-накопичення.** Для одного виходу `j` беремо його рядок ваг і весь вектор входу, перемножуємо код на код, віднявши zero-point активації, і накопичуємо в широке ціле:

```
acc(j) = Σᵢ (q_x[i] − z_x) · q_w[j][i]     ← int32-акумулятор
```

Тут ховається перша тонкість, до якої повернемось у пастках: **чому зсув `z_x` віднімають від активації, а не «правильно» від обох чисел одночасно**, і чому насправді його взагалі виносять за цикл. Поки що досить: доданок — це int8, помножений на (int8 − int8), а тисячі таких доданків сумуються в **int32**, бо у 8 біт така сума не влізе й близько.

**Третє — як перевести int32-суму назад у int8 наступного шару, не торкнувшись float.** Математика вимагає домножити суму на дробовий коефіцієнт `M = s_w · s_x / s_вих` (він завжди між 0 і 1) і додати вихідний zero-point. Оце `M` — і є те саме «останнє дробове множення». Хитрість, на якій тримається весь цілочисельний вивід: `M` розкладають **раз, при збірці моделі**, на пару цілих — множник `M0` у діапазоні [0.5, 1), збережений як int32 (формат Q31, тобто дріб зі знаменником 2³¹), і **правий зсув** `n`:

```
M = M0 · 2⁻ⁿ,   де M0 ∈ [0.5, 1) — ціле Q31,  n — мале ціле ≥ 0
```

Тоді в рантаймі домноження на дробове `M` — це ціле множення на `M0` (у старші 32 біти 64-бітного добутку) плюс округлений зсув праворуч на `n`. Жодного float. Саме цей прийом (його ввела команда gemmlowp/TFLite; докладніше — у [історичній вставці](book:algorithms/model-quantization/hist-int8-jacob.md)) робить int8-вивід можливим на найдешевшому чипі.

![Тракт даних одного нейрона в розрядностях: int8-вага та int8-активація множаться з відніманням zero-point у int32-доданок, сума накопичується в int32-акумуляторі, реквантування множить на цілий M0 і зсуває праворуч на n, clamp повертає у int8](/book/algorithms/machine-learning/model-quantization/img/datapath.svg)
*Весь шлях одного виходу в бітах: сині клітини — 8-бітні (вага, активація, вихід), червона й зелена — 32-бітні. Множення й накопичення живуть у широкому int32-акумуляторі, бо тисячі int8-добутків там не вміщаються у 8 біт; єдина дробова величина — добуток масштабів — заздалегідь перетворена на цілий множник M0 і зсув n, тож float у гарячому циклі не з'являється взагалі.*

Складемо це в код. Спершу — структура шару: усе, що зашите офлайн, в одному місці.

## Код

Оголошення шару. Ваги, bias і два масиви реквантування (`M0` та зсув на кожен вихідний канал) готують інструменти квантування ще до збірки прошивки; тут лишається тільки на них послатися:

```c
#include <stdint.h>

typedef struct {
    int32_t  in_dim;       /* довжина вектора входу                        */
    int32_t  out_dim;      /* кількість вихідних нейронів (рядків W)       */
    const int8_t  *W;      /* ваги, out_dim×in_dim, рядок за рядком        */
    const int32_t *bias;   /* зсув, у масштабі акумулятора (int32)         */
    const int32_t *M0;     /* реквант-множник Q31 на КОЖЕН вихід (per-channel) */
    const int32_t *shift;  /* правий зсув n на КОЖЕН вихід (≥ 0)           */
    int32_t  in_zp;        /* zero-point входу  z_x                        */
    int32_t  out_zp;       /* zero-point виходу z_вих                      */
} DenseLayerS8;
```

Тепер два цілочисельні примітиви реквантування — точно ті, що в еталонних рушіях; від їхньої побітової відповідності залежить, чи збіжиться вихід із навченою моделлю. Перший — **подвоєне множення-з-округленням у старші біти** (в асемблері ARM це одна команда `SQRDMULH`; тут — переносний C):

```c
/* t = округл(a · b · 2 / 2^32): множимо два Q31, беремо старші 32 біти,
   з подвоєнням і округленням до найближчого. Сатурація — лише на єдиному
   поганому випадку a = b = INT32_MIN (де точний результат +2^31 не влазить). */
static inline int32_t sat_round_dbl_high(int32_t a, int32_t b)
{
    if (a == INT32_MIN && b == INT32_MIN) return INT32_MAX;   /* єдине переповнення */
    int64_t ab = (int64_t)a * (int64_t)b;                     /* точний 64-біт добуток */
    /* «підштовх» на округлення: +2^30 як знаки збігаються, інакше −(2^30−1) */
    int32_t nudge = (a ^ b) >= 0 ? (1 << 30) : -((1 << 30) - 1);
    return (int32_t)((ab + nudge) / (int64_t)(1LL << 31));     /* /2^31 = старші 32 біти ×2 */
}
```

Другий — **округлений правий зсув** (ділення на 2ⁿ із округленням до найближчого, а не відкиданням):

```c
/* y = округл(x / 2^exp), round-half-up; для від'ємних x поправка на 1,
   щоб напрям округлення був симетричний і не зсував середнє. */
static inline int32_t round_shift_right(int32_t x, int32_t exp)
{
    if (exp <= 0) return x;
    int32_t mask      = (1 << exp) - 1;          /* біти, що відкидаємо        */
    int32_t remainder = x & mask;                /* сам відкинутий залишок     */
    int32_t threshold = (mask >> 1) + (x < 0);   /* половина; для x<0 зсув на 1 */
    return (x >> exp) + (remainder > threshold); /* арифм. зсув + округлення +1 */
}
```

Ці дві разом і є реквантування: домножити int32-акумулятор на дробове `M = M0·2⁻ⁿ` і повернути у 8-бітний масштаб. Обгорнемо в одну функцію разом із додаванням вихідного zero-point і затиском у int8:

```c
static inline int8_t requantize(int32_t acc, int32_t M0, int32_t shift, int32_t out_zp)
{
    int32_t v = sat_round_dbl_high(acc, M0);     /* ×M0 (старша частина Q31)   */
    v = round_shift_right(v, shift);             /* ≫ n з округленням          */
    v += out_zp;                                 /* у сітку виходу             */
    if (v < -128) v = -128;                      /* clamp у діапазон int8      */
    if (v >  127) v =  127;
    return (int8_t)v;
}
```

І сам шар — подвійний цикл. Зовнішній по вихідних нейронах, внутрішній — скалярний добуток у int32-акумулятор; на кожен вихід свій `M0` і `shift`, бо квантування per-channel:

```c
void dense_s8(const DenseLayerS8 *L, const int8_t *in, int8_t *out)
{
    for (int32_t j = 0; j < L->out_dim; ++j) {
        const int8_t *w = L->W + (int64_t)j * L->in_dim;   /* рядок ваг виходу j */
        int32_t acc = L->bias[j];                          /* bias одразу в int32 */

        for (int32_t i = 0; i < L->in_dim; ++i) {
            /* (активація − zero-point) × вага; кожен доданок — до ±32 640,       */
            /* сума тисяч таких безпечно живе в int32                            */
            acc += (int32_t)((int32_t)in[i] - L->in_zp) * (int32_t)w[i];
        }

        out[j] = requantize(acc, L->M0[j], L->shift[j], L->out_zp);
    }
}
```

Оце й усе. Двадцять рядків роблять повний int8-прохід шару, і в гарячому внутрішньому циклі немає нічого, крім цілого віднімання, цілого множення й цілого додавання — рівно те, що дешевий процесор виконує швидко й майже задарма по енергії. Уся дробова частина сколапсувала у два цілі числа `M0[j]` і `shift[j]`, порахованих раз при збірці.

## Worked-приклад: один вихід по числах

Візьмемо один вихідний нейрон із коротким входом на 4 елементи. Хай zero-point входу `z_x = −8` (асиметрична сітка після зсуву), bias у масштабі акумулятора `bias = 512`, реквант-множник `M0 = 1 300 000 000` (це Q31 для дробового `M0 ≈ 0.6053`), зсув `shift = 8`, а вихідний zero-point `z_вих = −5`. Входи й ваги:

```
in   = [ 20,  −8,  60,  −8 ]     (int8-коди активацій)
w    = [ 40,  −70,  25,  10 ]    (int8-ваги цього виходу)
z_x  = −8
```

Спершу скалярний добуток із відніманням zero-point, накопичення в int32:

```
acc  = bias = 512
i=0:  (20 − (−8)) · 40  = 28 · 40  =  1120   → acc = 1632
i=1:  (−8 − (−8)) · −70 =  0 · −70 =     0   → acc = 1632
i=2:  (60 − (−8)) · 25  = 68 · 25  =  1700   → acc = 3332
i=3:  (−8 − (−8)) · 10  =  0 · 10  =     0   → acc = 3332
```

Зверни увагу: там, де активація дорівнює своєму zero-point (`in = −8`), доданок точно нуль — код нуля активації після віднімання зсуву дає справжній нуль, як і має бути. Тепер реквантування. Крок 1 — подвоєне множення-з-округленням у старші біти:

```
ab   = acc · M0 = 3332 · 1 300 000 000 = 4 331 600 000 000     (точно, у int64)
знаки збігаються → nudge = +2³⁰ = +1 073 741 824
t    = (4 331 600 000 000 + 1 073 741 824) / 2³¹
     = 4 332 673 741 824 / 2 147 483 648
     = 2017          (ціла частина; це acc·M0-подвоєне у старших бітах)
```

Крок 2 — округлений правий зсув на `n = 8` (ділення на 256 з округленням до найближчого):

```
mask       = 2⁸ − 1 = 255
remainder  = 2017 & 255 = 2017 − 7·256 = 225
threshold  = 255 ≫ 1 = 127   (t ≥ 0 → без поправки)
225 > 127  → округлюємо вгору, +1
y          = (2017 ≫ 8) + 1 = 7 + 1 = 8
```

Нарешті зсув у сітку виходу й clamp:

```
y = 8 + z_вих = 8 + (−5) = 3
3 у межах [−128, 127] → без зрізу
out = 3
```

Перевіримо змістовність. Коефіцієнт `M ≈ 0.6053 · 2⁻⁸ ≈ 0.002365`; «наївно» `acc · M = 3332 · 0.002365 ≈ 7.88`, плюс `z_вих = −5` дає `≈ 2.88`, округлення — `3`. Точний цілочисельний шлях дав рівно `3` — але зробив це **самими цілими**, і, що головне, **округлив у той самий бік**, що зробив би еталонний float-рушій. Якби на кроці 2 ми відкинули залишок замість округлення (`2017 ≫ 8 = 7`, без `+1`), вийшло б `7 − 5 = 2` — і на кожному такому виході модель систематично з'їжджала б униз. Ось чому округлення тут не косметика.

## Прискорення: ARM NEON і dot-product

Написаний цикл переносний, але на реальному ядрі його не лишають скалярним. Векторні розширення роблять кілька множень-накопичень за одну команду, і саме int8-вивід із них тисне максимум.

Базовий інструмент — **NEON** (SIMD-розширення ARM): регістри по 128 біт вміщають 16 значень int8, і одна команда множить-розширює їх пачками у 16-бітні добутки, які потім парами складаються у 32-бітні лічильники. Замість шістнадцяти окремих ітерацій — кілька векторних команд.

Але справжній стрибок для квантованих мереж дала окрема команда — **SDOT** (signed dot product, «знаковий скалярний добуток»). Одна `SDOT` бере по чотири сусідні int8 з кожного операнда, множить попарно й **одразу додає всі чотири добутки в 32-бітний акумулятор-лейн**:

```
для кожного 32-бітного лейна:  acc += a₀·b₀ + a₁·b₁ + a₂·b₂ + a₃·b₃
```

Тобто за одну команду — чотири множення-накопичення, точно та операція, з якої складається наш внутрішній цикл. На 128-бітному регістрі це 16 множень-додавань за такт. За фактами: SDOT/UDOT з'явилися як **необов'язкове розширення в Armv8.2-A** (ознака `FEAT_DotProd`, прапорець `ID_AA64ISAR0_EL1.DP`), а **з Armv8.4-A стали обов'язковими** для всіх реалізацій; їх додають у ядра рівня Cortex-A55/A75 і вище саме заради машинного навчання (усталений факт, документація ARM). Дешеві Cortex-M здебільшого їх не мають — там граничну швидкодію на int8 дає бібліотека CMSIS-NN, яка вичавлює максимум із наявних DSP-команд ядра.

Одна тонкість про zero-point, яка робить `SDOT` придатним. Команда рахує **голий** добуток `Σ q_x · q_w`, без жодного віднімання зсуву. Тому в промислових рушіях `z_x` **не віднімають усередині циклу** — його виносять за суму алгебраїчно:

```
Σ (q_x − z_x)·q_w  =  Σ q_x·q_w  −  z_x · Σ q_w
```

Правий доданок `z_x · Σ q_w` не залежить від входу: `Σ q_w` — стала цього виходу, її рахують раз офлайн і **вкладають прямо в bias**. Тоді гарячий цикл — це чиста сума добутків `Σ q_x·q_w` (саме її й дає `SDOT`), а весь вплив zero-point уже сидить у наперед поправленому int32-bias. Наш переносний код віднімає `z_x` у циклі заради ясності; реальний швидкий шлях цього не робить — і від цього результат не міняється ані на біт. Повний вивід цього розкладу — у [математичній вставці про афінну сітку](book:algorithms/model-quantization/math-affine-quant.md).

## Складність і пастки на МК

**Вартість.** Скалярний варіант — `O(in_dim · out_dim)` цілих множень-додавань на шар, як і у float-версії, але кожна операція **дешевша в рази** на ядрі без апаратного float, а даних учетверо менше (краще лягають у кеш). З `SDOT` внутрішній цикл коротшає ще вчетверо-увосьмеро. Пам'яті під сам шар — ваги int8 (×4 менше за float32) плюс два масиви реквантування по `out_dim` int32. Тепер граблі, кожні з яких мовчки псують відповідь.

- **Переповнення акумулятора.** Один доданок — це (int8 − int8) × int8, найгірший випадок `(127 − (−128)) · (−128) = 255 · (−128) = −32 640`, тобто ~15 біт зі знаком. У int32 лишається запас на суму: `2³¹ / 32 640 ≈ 65 800` доданків, перш ніж теоретично можливе переповнення. Для звичайних шарів (вхід у сотні-тисячі) запас велетенський, і int32 безпечний. Але у **широкому** шарі чи великій згортці (`in_dim` під сотню тисяч і більше) сума може підійти до межі — тоді або тримають акумулятор у **int64**, або квантувальник заздалегідь обмежує масштаби так, щоб сума гарантовано влазила. Мовчазне переповнення int32 не «зашкалює», а **перевертається** через знак — і один нейрон видає повну нісенітницю, яку важко зловити. Правило: перш ніж довіритись int32, перемнож найгірший доданок на `in_dim` і подивись на запас.

- **Знак у множенні (signed проти unsigned).** Тут криється підступ, який коштував багатьом днів налагодження. Ранній стандарт TFLite квантував в **unsigned int8** (`uint8`, коди 0…255), і тоді добуток `q_x · q_w` — це `uint8 × int8`, змішаний за знаком. У C таке множення тихо приводить обидва операнди до одного типу за правилами перетворень — і якщо не пильнувати ширину, `uint8`, підвищений до `int`, поводиться правильно, а от зберігання проміжку в **завузькому** типі (`int16`, `uint16`) втрачає знак або старші біти. Сучасний стандарт (**int8**, коди −128…127, симетричні ваги) цю пастку прибирає — обидва операнди знакові, — і саме тому індустрія на нього перейшла. Практичне правило: тримай усе множення в явно знаковому `int32`, приводь `int8` до `int32` **до** множення (як у коді вище: `(int32_t)in[i]`), і не намагайся заощадити на ширині проміжку — заощадиш кілька байтів і купиш собі невловний зсув знаку.

- **Округлення при зсуві.** Правий зсув `x >> n` у C — це **округлення донизу** (до −∞ для знакових), а не до найближчого. Якщо реквантувати простим зсувом, кожен вихід систематично занижується на майже пів кроку, і по багатьох шарах ця похибка **накопичується в один бік** — мережа помітно з'їжджає. Тому `round_shift_right` додає `+1`, коли відкинутий залишок перевищує половину, **з окремою поправкою для від'ємних** (`threshold = (mask>>1) + (x<0)`): без неї від'ємні числа округлялися б не симетрично додатним, і знову виник би зсув середнього. Це не педантизм — саме побітова відповідність цього округлення еталону визначає, чи збіжиться прошивка з навченою моделлю. Скопіював формулу з gemmlowp — маєш той самий результат; «спростив» до `>> n` — маєш тихо іншу мережу.

- **Порядок віднімання zero-point.** Віднімати треба від **активації** (`q_x − z_x`), бо симетричні ваги мають `z_w = 0` і для них віднімати нема чого. Спокуса «спростити» й відняти zero-point від **готової суми** (`Σ q_x·q_w − z_x·in_dim`) — **хибна**: правильна поправка — `z_x · Σ q_w`, тобто зсув множиться на **суму ваг**, а не на їхню кількість. Переплутати `Σ q_w` з `in_dim` — типова помилка, що дає майже правильні, але зміщені виходи (найгірше — саме «майже правильні»: тести проходять, точність тихо просіла). І навпаки, коли активація асиметрична (`z_x ≠ 0`), а ваги симетричні, віднімати `z_w` не треба взагалі — його там нема. Тримай у голові точну алгебру `Σ(q_x−z_x)(q_w−z_w)` і розкривай її свідомо, а не «на око».

*Три сходинки реквантування без жодного float. Зверху — те, що роблять раз при збірці: дробовий коефіцієнт M = s_w·s_x/s_вих (завжди між 0 і 1) розкладають на цілий множник M0 ∈ [0.5, 1) у форматі Q31 і правий зсув n. Знизу — рантайм: подвоєне множення-з-округленням дає старші біти добутку acc·M0, тоді округлений (не відкидний!) зсув на n повертає у масштаб виходу, додається zero-point і результат затискають у int8. Кожна сходинка — суто цілі операції.*

- **Дрібніші, але живучі.** `bias` **мусить** бути в масштабі акумулятора (`s_w·s_x`), а не в масштабі виходу — інакше він додається «не в тих одиницях» і зсуває все. `shift` беруть **невід'ємним** (розклад дає `M0 ∈ [0.5,1)` і `n ≥ 0`); якщо інструмент видав від'ємний зсув, його треба обробити окремою гілкою (лівий зсув), інакше `round_shift_right` мовчки поверне вхід без зміни. І `M0` зберігають саме як **int32 Q31** — узяв ширший чи вужчий формат, не помінявши константу `2³¹` у `sat_round_dbl_high`, і масштаб поїде на степінь двійки.

## Підсумок

Робочий int8-вивід шару — це три речі, доведені до цілих чисел. **Розкладка пам'яті**: ваги int8 per-channel, bias одразу в int32, а масштаб — пара наперед порахованих цілих `M0` (Q31) і `shift` на кожен вихід. **Цикл множення-накопичення**: `(q_x − z_x)·q_w` у int32-акумулятор, де в гарячому місці немає нічого, крім цілого віднімання, множення й додавання. **Реквантування без float**: домножити суму на дробове `M = M0·2⁻ⁿ` через подвоєне множення-з-округленням у старші біти плюс округлений правий зсув, додати вихідний zero-point і затиснути в int8. Уся сила квантування — саме тут: єдине дробове множення сколапсувало у два цілі числа, порахованих раз при збірці, а тисячі операцій біжать цілими — тому це можливо на чипі без апаратного float, а з командою `SDOT` ще й учетверо швидше за такт. Пастки не косметичні: переповнення int32 **перевертає** нейрон, зсув замість округлення **накопичує** систематичну похибку, а плутанина зі знаком чи з порядком віднімання zero-point дає найгірший різновид бага — «майже правильний» вихід, що тихо розходиться з навченою моделлю. Тому реквантувальні примітиви беруть **побітово** такими, як в еталоні, і перевіряють запас акумулятора **наперед**, а не по факту аварії.
