# 🧮 Виведення еквалізації гістограми через CDF

Вирівнювання гістограми (англ. *equalization* — «вирівнювання», від лат. *aequalis* — рівний) робить дивну на перший погляд річ: бере кадр із купою тонів, збитих в одному місці шкали, і перерозподіляє яскравості так, щоб гістограма стала майже рівною по всій ширині. Деталі, що тулилися в тінях, розходяться й стають видні. Формула, яку для цього застосовують, коротка:

```
H_new(v) = round( CDF(v) · 255 )
```

Тут `v` — стара яскравість пікселя (0…255), `CDF(v)` — нормована кумулятивна функція розподілу в точці `v`, а `H_new(v)` — нова яскравість. Питання, на яке тут відповідаємо: **чому саме ця формула** — чому застосування власної CDF кадру дає на виході рівномірний розподіл, а не якийсь інший. Це не магія і не підгін: рівність виходу випливає строго, від першопринципів, і варто побачити чому — тоді стане зрозуміло, коли еквалізація працює, а коли підводить.

## Що таке гістограма й що таке CDF

Почнімо з означень, бо все тримається на них. Кадр має `N` пікселів. **Гістограма** `h(v)` — це просто лічильник: скільки пікселів мають яскравість рівно `v`. Якщо в кадрі 50000 пікселів зі значенням 100, то `h(100) = 50000`. Сума всіх стовпчиків дорівнює загальній кількості пікселів:

```
h(0) + h(1) + … + h(255) = N
```

Поділивши кожен стовпчик на `N`, дістаємо **нормовану гістограму** `p(v) = h(v) / N` — частку пікселів даної яскравості. Тепер сума дорівнює одиниці, і `p(v)` читається як **імовірність** того, що навмання взятий піксель має яскравість `v`. Це той самий розподіл імовірностей, тільки дискретний — по 256 кошиках.

**Кумулятивна функція розподілу** (англ. *cumulative distribution function*, CDF; від лат. *cumulare* — нагромаджувати) — це накопичена сума нормованої гістограми. У точці `v` вона дорівнює частці пікселів, чия яскравість **не перевищує** `v`:

```
CDF(v) = p(0) + p(1) + … + p(v)
       = ( h(0) + h(1) + … + h(v) ) / N
```

Прочитаймо це по-людськи. `CDF(0)` — це частка найтемніших пікселів (рівно значення 0). `CDF(128)` — частка всіх пікселів, темніших або рівних середині шкали. `CDF(255)` — це вже **всі** пікселі, тож завжди рівно 1. CDF починається біля нуля, тільки росте (бо ми весь час додаємо невід'ємні частки) і закінчується одиницею. Вона **монотонно неспадна** — це її головна властивість, і саме на ній усе тримається.

> 🔧 **Навіщо це.** CDF — не абстракція з підручника теорії ймовірностей, а буквально те, що рахує прошивка камери: один прохід по кадру дає гістограму, один прохід по 256 кошиках дає CDF. Зрозумівши, що CDF — це «скільки тонів уже позаду», ви читаєте її графік як рівень води, що наповнюється зліва направо, і одразу бачите, де в кадрі скупчені тони (там, де CDF стрімко лізе вгору).

## Ключова ідея: рівномірний розподіл має лінійну CDF

Перш ніж вивести формулу, треба зрозуміти, **до чого ми прагнемо**. Мета еквалізації — рівномірний вихід: щоб кожна яскравість на виході траплялася приблизно однаково часто, тобто щоб вихідна гістограма була плоскою.

Запитаймо: а яка CDF у **ідеально рівномірного** розподілу? Якщо яскравості від 0 до 255 трапляються однаково часто, то частка пікселів, темніших або рівних `v`, росте **прямо пропорційно** до `v`. До половини шкали — половина пікселів, до чверті — чверть. Тобто CDF рівномірного розподілу — це **пряма лінія** від (0, 0) до (255, 1):

```
CDF_рівн(v) = v / 255
```

Ось зв'язок, який усе пояснює: **плоска гістограма ⇄ лінійна CDF**. Це дві сторони однієї монети. Сказати «хочу рівномірний вихід» — те саме, що сказати «хочу, щоб CDF виходу була прямою лінією». І ось ідея еквалізації одним реченням: підберімо перетворення яскравості так, щоб CDF результату стала прямою. А підкаже нам це перетворення — сама CDF вхідного кадру.

## Виведення: чому застосування власної CDF випрямляє розподіл

Тепер головне. Маємо перетворення `T(v)`, що бере стару яскравість `v` і дає нову. Хочемо знайти таке `T`, щоб вихід був рівномірний. Стверджуємо, що шукане перетворення — це **сама нормована CDF**, розтягнута на діапазон 0…255:

```
T(v) = CDF(v) · 255
```

Подивімося, чому це працює. Розглянемо спершу неперервний випадок — він прозоріший, а дискретний відрізняється лише округленням. Нехай `X` — випадкова яскравість пікселя з CDF, яку позначимо `F(x)`. Застосуємо перетворення і дістанемо нову змінну `Y = F(X)` (поки що без множника 255 — додамо його наприкінці, він лише масштабує). Питання: який розподіл у `Y`?

Знайдімо CDF нової змінної — частку пікселів, чиє нове значення не перевищує деякого порога `y`:

```
CDF_Y(y) = P( Y ≤ y )
         = P( F(X) ≤ y )
```

Тепер ключовий крок. `F` монотонно неспадна, тож нерівність `F(X) ≤ y` можна «розгорнути»: застосуємо до обох боків обернену функцію `F⁻¹`. Подія `F(X) ≤ y` — це те саме, що `X ≤ F⁻¹(y)`:

```
CDF_Y(y) = P( X ≤ F⁻¹(y) )
```

Але `P(X ≤ щось)` — це за означенням сама CDF змінної `X`, тобто `F`, узята в тій точці:

```
CDF_Y(y) = F( F⁻¹(y) )
         = y
```

Функція й обернена до неї скасовуються, лишається просто `y`. Отримали `CDF_Y(y) = y`. А `CDF_Y(y) = y` — це і є означення рівномірного розподілу на відрізку від 0 до 1 (його CDF — пряма лінія `y`). Тобто `Y = F(X)` розподілена **рівномірно**, хай якою химерною була вихідна форма `X`. Це класичний результат, відомий як **інтегральне перетворення ймовірності** (англ. *probability integral transform*): пропусти будь-яку неперервну величину через її ж CDF — отримаєш рівномірну.

Лишилося розтягнути з [0, 1] на [0, 255], помноживши на 255 — і це рівно наша формула `T(v) = CDF(v) · 255`. Ось чому еквалізація працює: ми **нав'язуємо** кадру те перетворення, яке за побудовою випрямляє його власний розподіл у пряму, а пряма CDF — це і є рівний вихід.

## Чому дискретна гістограма дає лише *майже* рівний результат

У неперервному світі вихід ідеально рівномірний. На реальному кадрі — лише **майже** рівномірний, і важливо розуміти причину, інакше дивуєшся «щербатій» вихідній гістограмі.

Причина — округлення й те, що тони дискретні. Формула дає дробове число `CDF(v) · 255`, а яскравість мусить бути цілою, тож ми округляємо: `round( CDF(v) · 255 )`. Через це **кілька різних вхідних значень можуть округлитися в одне й те саме вихідне**. Скажімо, якщо `CDF` стрибає круто (там, де в кадрі скупчені тони), сусідні `v` можуть дати після округлення однакове нове значення — вони злипаються. А там, де `CDF` майже пласка (тонів обмаль), цілі ділянки вихідної шкали лишаються порожніми — у них просто не відображається жоден вхідний тон.

Звідси характерний вигляд вихідної гістограми після еквалізації: не гладенька поличка, а **рідкий частокіл** окремих стовпчиків із прогалинами між ними. Кількість *різних* значень не зростає — еквалізація не вигадує нових тонів, вона лише розсуває наявні. Тому формально розподіл не ідеально рівний; рівним стає радше **накопичений** розподіл — CDF виходу лягає близько до прямої, навіть якщо сама гістограма щербата. І це нормально: для зору важливо саме те, що тони розсунулися й деталі стали відрізнятися.

## Покрокове обчислення на крихітному прикладі

Проженімо формулу руками на маленькому кадрі, щоб не лишилося туману. Хай зображення має лише 4 рівні яскравості (0…3) замість 256, і всього `N = 16` пікселів із таким підрахунком:

```
рівень v :  0    1    2    3
h(v)     :  2    8    4    2      (сума = 16)
```

Крок 1 — нормуємо, ділячи на `N = 16`:

```
p(0) = 2/16  = 0.125
p(1) = 8/16  = 0.500
p(2) = 4/16  = 0.250
p(3) = 2/16  = 0.125
```

Крок 2 — накопичуємо в CDF (кожен наступний = попередній плюс поточний `p`):

```
CDF(0) = 0.125
CDF(1) = 0.125 + 0.500 = 0.625
CDF(2) = 0.625 + 0.250 = 0.875
CDF(3) = 0.875 + 0.125 = 1.000
```

Крок 3 — множимо на максимум шкали (тут 3, бо рівнів 0…3) і округляємо:

```
T(0) = round(0.125 · 3) = round(0.375) = 0
T(1) = round(0.625 · 3) = round(1.875) = 2
T(2) = round(0.875 · 3) = round(2.625) = 3
T(3) = round(1.000 · 3) = round(3.000) = 3
```

Крок 4 — застосуємо до пікселів. Кожен старий рівень міняємо на новий за таблицею `T`. Подивімося на нову гістограму: старий рівень 0 (2 пікс.) → 0; рівень 1 (8 пікс.) → 2; рівень 2 (4 пікс.) → 3; рівень 3 (2 пікс.) → 3.

```
новий рівень :  0    1    2    3
h_new        :  2    0    8    6
```

Видно обидва ефекти разом. Тони **розтяглися**: масивна купа з рівня 1 поїхала на рівень 2, темні й світлі розійшлися ширше по шкалі — кадр став контрастнішим. І водночас видно **дискретний дефект**: рівень 1 на виході порожній (прогалина), а рівні 2 та 3 злиплися (значення 2 і 3 на вході обидва дали 3). Гістограма не стала ідеально плоскою — вона стала ширшою й рідшою. Саме це й відбувається на справжньому 256-рівневому кадрі, тільки кошиків більше, а ефект м'якший.

Якраз цю таблицю `T` і називають **таблицею замін** (англ. *look-up table*, LUT): 256 наперед порахованих чисел «старе значення → нове». Порахувавши її один раз, далі весь кадр обробляють без жодного множення чи ділення — просто читають `lut[старе]`. Тому еквалізація така дешева, що її тягне навіть найскромніший мікроконтролер: уся «математика» — це один прохід для гістограми, накопичення 256 значень у CDF і ще один прохід із підстановкою з таблиці.

## Що це означає на практиці

З виведення випливають межі методу — і вони важливіші за саму формулу. Перше: еквалізація **не додає інформації**, вона лише перерозподіляє наявні тони. Якщо деталь утрачена через обрізання (тони прилипли до 0 чи 255), жодна CDF її не поверне — у числах її просто немає. Друге: метод **глобальний** — одна CDF на весь кадр, тож він підсилює те, чого в кадрі багато. На великій однорідній ділянці (небо, стіна) скупчені близькі тони дають круту CDF, і еквалізація розтягує їхні дрібні відмінності — разом із шумом, який раптом стає помітним. Саме цю ваду лікують локальним варіантом з обрізанням піку, але це вже окрема, складніша конструкція. Третє: на повністю однорідному кадрі (усі пікселі однакові) CDF — одна сходинка, і перетворення вироджується: виходить майже те саме значення скрізь, ділити нема чого. Тож еквалізація — потужний, але тупий інструмент: вона завжди штовхає розподіл до прямої, не питаючи, чи це доречно саме тут.
