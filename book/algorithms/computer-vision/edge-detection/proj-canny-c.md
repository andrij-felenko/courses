# ⚙️ Конвеєр Канні на C без бібліотек

**Задача.** Дано сирий восьмибітний кадр у градаціях сірого — масив `uint8_t in[H*W]`, по одному байту яскравості на піксель. Треба віддати **бінарну мапу меж** `uint8_t edges[H*W]`, де 255 стоїть там, де проходить тонкий контур, і 0 — усюди інде. Без OpenCV, без жодної зовнішньої бібліотеки: лише стандартний C, щоб це лягло й на бортовий комп'ютер, і на досить ситий мікроконтролер. Реалізуємо всі чотири ланки конвеєра Канні чесно — згладжування Гаусом, градієнт Собелем, придушення немаксимумів із інтерполяцією та двопороговий гістерезис із обходом у ширину.

**Ідея.** Канні — не один фільтр, а **конвеєр**, де кожна ланка лікує ваду попередньої. Гола похідна на сирому кадрі дала б ліс фальшивих меж із шуму, тож спершу шум приглушуємо Гаусом. Похідна по згладженому дає товсту смугу навколо кожної межі — її стоншуємо, лишаючи тільки гребінь. Гребінь усе одно поцяткований розривами й окремими шумовими сплесками — їх відсіває гістерезис, що зберігає слабкі точки лише як продовження сильних. Розберемо кожну ланку як окрему функцію, а наприкінці зберемо їх в один прохід і пройдемося по пастках, на яких така реалізація зазвичай ламається.

Усюди працюємо з буферами, а не «на місці»: майже кожна ланка читає сусідів пікселя, тож писати результат у той самий масив, який ще читаєш, не можна — затреш дані, потрібні сусідньому пікселю. Розмір кадру невеликий і відомий наперед, тож для простоти беремо `int` для всіх індексів і координат — це знімає цілий клас помилок із переповненням індексу, до яких ще повернемося.

## Ланка 1: згладжування Гаусом 5×5

Гаус приглушує шум, але майже не розмиває справжні межі — бо вони сильні, а шум слабкий і дрібнозернистий. Беремо ядро 5×5 — стандартне для Канні; воно достатньо широке, щоб збити сенсорний шум, і досить вузьке, щоб не «з'їсти» тонкі деталі. Замість дробових ваг беремо цілочислове наближення гаусіани й ділимо на їхню суму (159) — так увесь фільтр лишається в цілих числах, що швидше й передбачуваніше за float, особливо на мікроконтролері.

:::tabs
```cpp
#include <stdint.h>
#include <math.h>
#include <stdlib.h>

#define IDX(y, x) ((y) * W + (x))

// Ціле ядро Гаусса 5×5 (σ≈1), сума ваг = 159.
static const int GAUSS5[5][5] = {
    {2,  4,  5,  4, 2},
    {4,  9, 12,  9, 4},
    {5, 12, 15, 12, 5},
    {4,  9, 12,  9, 4},
    {2,  4,  5,  4, 2},
};

// Згладити in[H*W] → out[H*W]. Край (рамку 2 пікселі) лишаємо як є (копіюємо).
static void gauss_blur(int H, int W, const uint8_t *in, uint8_t *out) {
    for (int y = 0; y < H; y++) {
        for (int x = 0; x < W; x++) {
            if (y < 2 || y >= H - 2 || x < 2 || x >= W - 2) {
                out[IDX(y, x)] = in[IDX(y, x)];   // край — без обробки
                continue;
            }
            int acc = 0;                          // до 255*159 = 40545 — влазить у int
            for (int ky = -2; ky <= 2; ky++)
                for (int kx = -2; kx <= 2; kx++)
                    acc += GAUSS5[ky + 2][kx + 2] * in[IDX(y + ky, x + kx)];
            out[IDX(y, x)] = (uint8_t)(acc / 159);
        }
    }
}
```
```python
import numpy as np

# Ціле ядро Гаусса 5×5 (σ≈1), сума ваг = 159.
GAUSS5 = np.array([
    [2,  4,  5,  4, 2],
    [4,  9, 12,  9, 4],
    [5, 12, 15, 12, 5],
    [4,  9, 12,  9, 4],
    [2,  4,  5,  4, 2],
], dtype=np.int32)

def gauss_blur(img):
    """Згладити img (H×W, uint8) → uint8. Край (рамку 2 пікселі) лишаємо як є."""
    H, W = img.shape
    out = img.copy()
    for y in range(2, H - 2):
        for x in range(2, W - 2):
            # до 255*159 = 40545 — int32 тримає без обгортання
            win = img[y - 2:y + 3, x - 2:x + 3].astype(np.int32)
            acc = int((GAUSS5 * win).sum())
            out[y, x] = acc // 159
    return out
```
:::

Зверни увагу на тип акумулятора. Найбільше можливе значення — коли всі 25 пікселів під ядром дорівнюють 255: сума `255 * 159 = 40545`. Це далеко за межу `uint8_t` (255) і навіть за межу `int16_t` (32767), але спокійно влазить у `int` (щонайменше ±32767 за стандартом, а на практиці ±2 мільярди). Якби ми необачно накопичували в `uint8_t` чи `int16_t`, дістали б **обгортання** — і замість згладженого кадру отримали б кольоровий шум там, де яскраво. Це перша з пасток, до яких повернемося: розмір акумулятора рахують **за найгіршим випадком**, а не «на око».

## Ланка 2: градієнт Собелем (сила й напрям)

По згладженому кадру рахуємо дві похідні — `Gx` (різниця право−ліво, ловить вертикальні межі) і `Gy` (різниця низ−верх, ловить горизонтальні) — [оператором Собеля](book:algorithms/edge-detection). З них дістаємо **силу** межі `|G| = √(Gx²+Gy²)` і **напрям** `θ = atan2(Gy, Gx)`. Силу зберігаємо в `int`-буфері (не в байтах — вона легко перевищує 255), а напрям одразу **квантуємо у чотири сектори** (0°, 45°, 90°, 135°), бо саме ці чотири осі знадобляться придушенню немаксимумів.

:::tabs
```cpp
// Собелеві ядра.  Gx — вертикальні межі, Gy — горизонтальні.
static const int SOBEL_X[3][3] = {{-1,0,1},{-2,0,2},{-1,0,1}};
static const int SOBEL_Y[3][3] = {{-1,-2,-1},{0,0,0},{1,2,1}};

// mag[] — сила градієнта (int), dir[] — сектор напряму 0..3.
// Сектор — це ВІСЬ ГРАДІЄНТА (впоперек межі); двох сусідів уздовж неї й порівнює NMS.
// 0 = ліво/право (межа вертикальна);           2 = верх/низ (межа горизонтальна);
// 1 = ~45°: градієнт на діагоналі \ (межа /);  3 = ~135°: градієнт на діагоналі / (межа \).
static void sobel_grad(int H, int W, const uint8_t *in, int *mag, uint8_t *dir) {
    for (int y = 1; y < H - 1; y++) {
        for (int x = 1; x < W - 1; x++) {
            int gx = 0, gy = 0;
            for (int ky = -1; ky <= 1; ky++)
                for (int kx = -1; kx <= 1; kx++) {
                    int v = in[IDX(y + ky, x + kx)];
                    gx += SOBEL_X[ky + 1][kx + 1] * v;
                    gy += SOBEL_Y[ky + 1][kx + 1] * v;
                }
            // сила: округлене евклідове; для МК можна |gx|+|gy| (дешевше, трохи грубіше)
            mag[IDX(y, x)] = (int)(sqrt((double)gx * gx + (double)gy * gy) + 0.5);

            // напрям → один із 4 секторів (кут за модулем 180°)
            double ang = atan2((double)gy, (double)gx) * 180.0 / M_PI; // -180..180
            if (ang < 0) ang += 180.0;                                  // 0..180
            uint8_t s;
            if      (ang < 22.5  || ang >= 157.5) s = 0;  // ~0°   → сусіди ліво/право
            else if (ang < 67.5)                  s = 1;  // ~45°  → сусіди по діагоналі \ (↖↘)
            else if (ang < 112.5)                 s = 2;  // ~90°  → сусіди верх/низ
            else                                  s = 3;  // ~135° → сусіди по діагоналі / (↙↗)
            dir[IDX(y, x)] = s;
        }
    }
}
```
```python
# Собелеві ядра.  Gx — вертикальні межі, Gy — горизонтальні.
SOBEL_X = np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]], dtype=np.int32)
SOBEL_Y = np.array([[-1, -2, -1], [0, 0, 0], [1, 2, 1]], dtype=np.int32)

def sobel_grad(img):
    """Повертає (mag: int32, dir: uint8 0..3).
    Сектор — вісь градієнта (впоперек межі), уздовж неї й порівнює NMS.
    0 = ліво/право (межа вертикальна);           2 = верх/низ (межа горизонтальна);
    1 = ~45°: градієнт на діагоналі \\ (межа /);  3 = ~135°: градієнт на діагоналі / (межа \\)."""
    H, W = img.shape
    mag = np.zeros((H, W), dtype=np.int32)
    dir = np.zeros((H, W), dtype=np.uint8)
    for y in range(1, H - 1):
        for x in range(1, W - 1):
            win = img[y - 1:y + 2, x - 1:x + 2].astype(np.int32)
            gx = int((SOBEL_X * win).sum())
            gy = int((SOBEL_Y * win).sum())
            # сила: округлене евклідове; для МК можна abs(gx)+abs(gy)
            mag[y, x] = int(np.hypot(gx, gy) + 0.5)

            # напрям → один із 4 секторів (кут за модулем 180°)
            ang = np.degrees(np.arctan2(gy, gx))  # -180..180
            if ang < 0:
                ang += 180.0                       # 0..180
            if ang < 22.5 or ang >= 157.5:
                s = 0   # ~0°   → сусіди ліво/право
            elif ang < 67.5:
                s = 1   # ~45°  → сусіди по діагоналі \ (↖↘)
            elif ang < 112.5:
                s = 2   # ~90°  → сусіди верх/низ
            else:
                s = 3   # ~135° → сусіди по діагоналі / (↙↗)
            dir[y, x] = s
    return mag, dir
```
:::

Чому напрям береться за модулем 180°, а не 360°? Бо межа не має «передньої» й «задньої» сторони: градієнт `+45°` і `−135°` лежать на одній прямій і для стоншення це той самий напрям. Звідси `if (ang < 0) ang += 180.0` — складаємо протилежні напрями в один. Це не косметика: без зведення до 0..180 умови на сектори довелося б писати вдвічі довше й легко наплутати з межами діапазонів.

Про силу: тут вона рахується чесним коренем у `double`. На бортовому комп'ютері це нормально. На мікроконтролері без апаратного float корінь дорогий, тож часто беруть **манхеттенську** оцінку `|gx| + |gy|` — вона завищує силу на косих межах десь до 40%, але працює без жодного множення-з-плаваючою-комою й цілком годиться, якщо пороги підібрати під неї. Це свідомий компроміс точність-проти-швидкості, а не недбалість.

## Ланка 3: придушення немаксимумів

Собелева мапа сили — товста: навколо кожної справжньої межі є ціла смуга великих значень. [Придушення немаксимумів](book:algorithms/object-detection) стоншує її до лінії в один піксель: піксель лишається, **тільки якщо його сила більша за двох сусідів уздовж напряму градієнта** (тобто впоперек межі). Якщо хоч один із двох сусідів сильніший — поточний піксель не на гребені, його занулюємо.

Найдешевший варіант — узяти двох **цілих** сусідів за квантованим сектором: для сектора 0 це ліво/право, для 2 — верх/низ, для 1 і 3 — відповідні діагоналі.

:::tabs
```cpp
// За квантованим сектором лишаємо тільки локальні максимуми вздовж градієнта.
static void nms_quantized(int H, int W, const int *mag, const uint8_t *dir,
                          int *out) {
    for (int i = 0; i < H * W; i++) out[i] = 0;        // обнулити, край лишиться 0
    for (int y = 1; y < H - 1; y++) {
        for (int x = 1; x < W - 1; x++) {
            int m = mag[IDX(y, x)];
            int a, b;                                   // два сусіди вздовж градієнта
            switch (dir[IDX(y, x)]) {                                      // порівнюємо ВЗДОВЖ градієнта
                case 0: a = mag[IDX(y,   x-1)]; b = mag[IDX(y,   x+1)]; break;  // ліво / право
                case 1: a = mag[IDX(y-1, x-1)]; b = mag[IDX(y+1, x+1)]; break;  // діаг. \ : ↖ / ↘
                case 2: a = mag[IDX(y-1, x)];   b = mag[IDX(y+1, x)];   break;  // верх / низ
                default:a = mag[IDX(y+1, x-1)]; b = mag[IDX(y-1, x+1)]; break;  // діаг. / : ↙ / ↗
            }
            if (m >= a && m >= b) out[IDX(y, x)] = m;   // гребінь — лишаємо силу
        }
    }
}
```
```python
def nms_quantized(mag, dir):
    """За квантованим сектором лишаємо тільки локальні максимуми вздовж градієнта."""
    H, W = mag.shape
    out = np.zeros((H, W), dtype=np.int32)   # край лишиться 0
    for y in range(1, H - 1):
        for x in range(1, W - 1):
            m = mag[y, x]
            s = dir[y, x]                    # два сусіди вздовж градієнта
            if s == 0:
                a, b = mag[y, x - 1], mag[y, x + 1]          # ліво / право
            elif s == 1:
                a, b = mag[y - 1, x - 1], mag[y + 1, x + 1]  # діаг. \ : ↖ / ↘
            elif s == 2:
                a, b = mag[y - 1, x], mag[y + 1, x]          # верх / низ
            else:
                a, b = mag[y + 1, x - 1], mag[y - 1, x + 1]  # діаг. / : ↙ / ↗
            if m >= a and m >= b:
                out[y, x] = m                # гребінь — лишаємо силу
    return out
```
:::

Квантований варіант швидкий, але грубуватий: він округлює напрям до найближчої з чотирьох осей, тож на межах під «незручним» кутом гребінь місцями двоїться. Точніший підхід — **білінійна інтерполяція**: замість двох цілих сусідів беремо два значення сили **точно вздовж напряму градієнта**, інтерполюючи між цілими пікселями. Якщо напрям градієнта `θ`, то одиничний вектор уздовж нього — `(cos θ, sin θ)`; точка на відстані 1 піксель уперед лягає між чотирма цілими сусідами, і її силу беремо лінійним змішуванням. Так стоншення йде точно впоперек справжньої межі, а не впоперек найближчої з чотирьох осей.

:::tabs
```cpp
// Білінійна сила в (точно дробовій) точці (fx, fy) — змішування 4 сусідів.
static double bilerp(int H, int W, const int *mag, double fy, double fx) {
    int x0 = (int)floor(fx), y0 = (int)floor(fy);
    if (x0 < 0 || y0 < 0 || x0 + 1 >= W || y0 + 1 >= H) return 0.0;
    double tx = fx - x0, ty = fy - y0;
    double top = mag[IDX(y0,   x0)] * (1 - tx) + mag[IDX(y0,   x0+1)] * tx;
    double bot = mag[IDX(y0+1, x0)] * (1 - tx) + mag[IDX(y0+1, x0+1)] * tx;
    return top * (1 - ty) + bot * ty;
}

// NMS із білінійною інтерполяцією двох сусідів уздовж напряму градієнта.
static void nms_interp(int H, int W, const int *mag,
                       const double *gx, const double *gy, int *out) {
    for (int i = 0; i < H * W; i++) out[i] = 0;
    for (int y = 1; y < H - 1; y++) {
        for (int x = 1; x < W - 1; x++) {
            int m = mag[IDX(y, x)];
            if (m == 0) continue;
            double n = sqrt(gx[IDX(y,x)] * gx[IDX(y,x)] + gy[IDX(y,x)] * gy[IDX(y,x)]);
            if (n < 1e-9) continue;
            double ux = gx[IDX(y, x)] / n, uy = gy[IDX(y, x)] / n;  // одиничний градієнт
            double f1 = bilerp(H, W, mag, y + uy, x + ux);          // вперед
            double f2 = bilerp(H, W, mag, y - uy, x - ux);          // назад
            if (m >= f1 && m >= f2) out[IDX(y, x)] = m;
        }
    }
}
```
```python
import math

def bilerp(mag, fy, fx):
    """Білінійна сила в (точно дробовій) точці (fy, fx) — змішування 4 сусідів."""
    H, W = mag.shape
    x0, y0 = math.floor(fx), math.floor(fy)
    if x0 < 0 or y0 < 0 or x0 + 1 >= W or y0 + 1 >= H:
        return 0.0
    tx, ty = fx - x0, fy - y0
    top = mag[y0,     x0] * (1 - tx) + mag[y0,     x0 + 1] * tx
    bot = mag[y0 + 1, x0] * (1 - tx) + mag[y0 + 1, x0 + 1] * tx
    return top * (1 - ty) + bot * ty

def nms_interp(mag, gx, gy):
    """NMS із білінійною інтерполяцією двох сусідів уздовж напряму градієнта."""
    H, W = mag.shape
    out = np.zeros((H, W), dtype=np.int32)
    for y in range(1, H - 1):
        for x in range(1, W - 1):
            m = mag[y, x]
            if m == 0:
                continue
            n = math.hypot(gx[y, x], gy[y, x])
            if n < 1e-9:
                continue
            ux, uy = gx[y, x] / n, gy[y, x] / n   # одиничний градієнт
            f1 = bilerp(mag, y + uy, x + ux)       # вперед
            f2 = bilerp(mag, y - uy, x - ux)       # назад
            if m >= f1 and m >= f2:
                out[y, x] = m
    return out
```
:::

Різниця між двома варіантами на практиці помітна на діагональних і плавно вигнутих контурах: квантований лишає сходинки, інтерпольований дає рівну тонку лінію. Ціна — кілька множень і floor на піксель та зберігання `gx`/`gy` як `double` (а не лише їхньої сили). Для мікроконтролера зазвичай беруть квантований; для бортового комп'ютера, де float дешевий, — інтерпольований.

## Ланка 4: двопороговий гістерезис обходом у ширину

Після стоншення лишилася тонка, але **поцяткована розривами** мапа: справжні контури перемежовано окремими шумовими сплесками, а сильні межі подекуди рвуться на слабкі ділянки. [Гістерезис](book:algorithms/edge-detection) (гр. *hysteresis* — відставання) розв'язує це двома порогами. Піксель, сильніший за **верхній** поріг, — напевно межа («сильний»). Слабший за **нижній** — напевно не межа, геть. Проміжний («слабкий») лишаємо **лише якщо** він сполучений ланцюжком слабких із якимось сильним, тобто є **продовженням** справжнього контуру.

Реалізуємо це класично: спершу позначаємо всі сильні пікселі й кладемо їх у чергу; тоді **обходом у ширину** (англ. *breadth-first search*, BFS) розповзаємося від кожного сильного по його 8 сусідах, забираючи всі слабкі, до яких дотягнулися. Слабкі, до яких не дотягнулися, наприкінці гасимо.

:::tabs
```cpp
// Двопороговий гістерезис. nms[] — сила після NMS; edges[] — бінарний вихід (0/255).
// lo, hi — нижній і верхній пороги. Стек на H*W пар координат.
static void hysteresis(int H, int W, const int *nms, int lo, int hi,
                       uint8_t *edges) {
    enum { WEAK = 1, STRONG = 2 };
    uint8_t *mark = (uint8_t *)calloc((size_t)H * W, 1);
    int *stack = (int *)malloc((size_t)H * W * sizeof(int));
    int sp = 0;

    // 1) класифікація + засів стеку сильними
    for (int i = 0; i < H * W; i++) {
        if      (nms[i] >= hi) { mark[i] = STRONG; stack[sp++] = i; }
        else if (nms[i] >= lo)   mark[i] = WEAK;
        // інакше mark[i] лишається 0 (не межа)
    }

    // 2) BFS від сильних: будь-який слабкий сусід стає сильним і йде в стек
    static const int DY[8] = {-1,-1,-1, 0, 0, 1, 1, 1};
    static const int DX[8] = {-1, 0, 1,-1, 1,-1, 0, 1};
    while (sp > 0) {
        int i = stack[--sp];
        int y = i / W, x = i % W;
        for (int k = 0; k < 8; k++) {
            int ny = y + DY[k], nx = x + DX[k];
            if (ny < 0 || nx < 0 || ny >= H || nx >= W) continue;
            int j = IDX(ny, nx);
            if (mark[j] == WEAK) { mark[j] = STRONG; stack[sp++] = j; }
        }
    }

    // 3) вихід: лишилися тільки сильні (сильні від народження + дотягнуті слабкі)
    for (int i = 0; i < H * W; i++)
        edges[i] = (mark[i] == STRONG) ? 255 : 0;

    free(stack);
    free(mark);
}
```
```python
def hysteresis(nms, lo, hi):
    """Двопороговий гістерезис. nms — сила після NMS; повертає бінарний вихід (0/255).
    Стек на H*W позицій (найгірший випадок)."""
    WEAK, STRONG = 1, 2
    H, W = nms.shape
    mark = np.zeros((H, W), dtype=np.uint8)
    stack = []

    # 1) класифікація + засів стеку сильними
    for i in range(H):
        for j in range(W):
            if nms[i, j] >= hi:
                mark[i, j] = STRONG
                stack.append((i, j))
            elif nms[i, j] >= lo:
                mark[i, j] = WEAK
            # інакше mark лишається 0 (не межа)

    # 2) BFS від сильних: будь-який слабкий сусід стає сильним і йде в стек
    DY = (-1, -1, -1, 0, 0, 1, 1, 1)
    DX = (-1, 0, 1, -1, 1, -1, 0, 1)
    while stack:
        y, x = stack.pop()
        for k in range(8):
            ny, nx = y + DY[k], x + DX[k]
            if ny < 0 or nx < 0 or ny >= H or nx >= W:
                continue
            if mark[ny, nx] == WEAK:
                mark[ny, nx] = STRONG
                stack.append((ny, nx))

    # 3) вихід: лишилися тільки сильні (сильні від народження + дотягнуті слабкі)
    return np.where(mark == STRONG, 255, 0).astype(np.uint8)
```
:::

Тонкий момент — **розмір стеку**. У найгіршому випадку (весь кадр — суцільна межа) у стек по черзі потрапить кожен піксель, тож `H*W` елементів достатньо й переповнення стеку бути не може. Важливо, що піксель кладемо в стек **рівно тоді, коли міняємо його мітку** на `STRONG`: мітка — це водночас і «вже відвіданий», тож той самий піксель не потрапить у стек двічі, і BFS гарантовано завершиться. Якби ми позначали пізніше (вже діставши зі стеку), той самий слабкий міг би потрапити в чергу від кількох сусідів — і стек переповнився б. Це класична пастка реалізації BFS: **позначай при додаванні, а не при витяганні**.

Чому BFS, а не проста рекурсія? Рекурсивний обхід контуру на великому кадрі легко переповнює апаратний стек викликів (глибина — у тисячі рівнів уздовж довгого контуру), і програма падає. Власний стек у купі цього уникає: його глибина обмежена `H*W`, і пам'ять береться передбачувано. На мікроконтролері це принципово — там стек викликів крихітний.

## Збираємо конвеєр

:::tabs
```cpp
// Повний Канні. in[H*W] → edges[H*W] (0/255). lo, hi — пороги гістерезису.
// Повертає 0 при успіху, -1 при браку пам'яті.
int canny(int H, int W, const uint8_t *in, uint8_t *edges, int lo, int hi) {
    size_t n = (size_t)H * W;
    uint8_t *blur = malloc(n);
    int     *mag  = malloc(n * sizeof(int));
    uint8_t *dir  = malloc(n);
    int     *thin = malloc(n * sizeof(int));
    if (!blur || !mag || !dir || !thin) {
        free(blur); free(mag); free(dir); free(thin);
        return -1;
    }
    gauss_blur(H, W, in, blur);          // 1) шум геть
    sobel_grad(H, W, blur, mag, dir);    // 2) сила + сектор напряму
    nms_quantized(H, W, mag, dir, thin); // 3) стоншити до гребеня
    hysteresis(H, W, thin, lo, hi, edges); // 4) сполучити й відсіяти
    free(blur); free(mag); free(dir); free(thin);
    return 0;
}
```
```python
def canny(img, lo, hi):
    """Повний Канні. img (H×W, uint8) → edges (0/255). lo, hi — пороги гістерезису."""
    blur = gauss_blur(img)               # 1) шум геть
    mag, dir = sobel_grad(blur)          # 2) сила + сектор напряму
    thin = nms_quantized(mag, dir)       # 3) стоншити до гребеня
    return hysteresis(thin, lo, hi)      # 4) сполучити й відсіяти
```

Чотири ланки, чотири буфери, лінійна складність `O(H·W)` — кожен піксель торкаються сталу кількість разів. Виклик гранично простий: дав сирий сірий кадр і два пороги — дістав бінарну мапу меж.

**Worked-приклад: як спрацює гістерезис на маленькому ланцюжку.** Хай після стоншення вздовж однієї лінії стоять сили `[90, 70, 30, 55, 80]`, а пороги `lo = 40`, `hi = 75`. Класифікація: `90 → STRONG`, `70 → WEAK`, `30 → нижче lo, геть`, `55 → WEAK`, `80 → STRONG`. У стек сіли позиції 0 і 4. BFS від позиції 0 забирає сусіда-WEAK на позиції 1 (`70`) — він стає STRONG. Далі від позиції 1 наступний сусід — позиція 2 (`30`), але вона вже не WEAK (вибула за порогом lo), тож ланцюг тут **рветься**. BFS від позиції 4 забирає сусіда на позиції 3 (`55`). Підсумок: `[255, 255, 0, 255, 255]` — лінія лишилася зв'язною з обох кінців, а провал у `30` її розірвав. Видно суть гістерезису: слабка точка виживає не сама по собі, а тільки якщо доторкається до сильної; і видно, як надто високий `lo` (тут він відсік `30`) може порвати справжній контур.

## Пастки

- **Переповнення акумулятора.** Сума під ядром Гаусса доходить до `255*159 = 40545`, під Собелем `|Gx|` — до `255*4 = 1020`, а сила `√(Gx²+Gy²)` — до ~1443. Усе це за межею `uint8_t` і навіть `int16_t`. Накопичуй у `int` і рахуй найгірший випадок наперед, інакше дістанеш обгортання — кольорові плями там, де яскраво. Це найчастіша помилка цілочислової обробки зображень.

- **Запис у буфер, який ще читаєш.** Кожна ланка читає сусідів, тож обробляти «на місці» (вхід = вихід) не можна: затреш дані, потрібні наступному пікселю того ж рядка. Завжди окремий вихідний буфер (або хоча б два рядки історії, якщо женеш потоком із сенсора).

- **Граничні пікселі.** На рамці шириною 2 (для Гаусса) і 1 (для Собеля) частини сусідів не існує. Найбезпечніше — **не обробляти край** (лишити 0 чи копію), як вище. Гірша, але поширена помилка — читати поза масивом: `in[IDX(y-1, x)]` при `y=0` зчитує чужу пам'ять і дає сміття або аварію. Ніколи не звертайся за межі; межі циклу став так, щоб ядро завжди лягало повністю.

- **Сектори напряму на стиках діапазонів.** Квантування кута легко наплутати на межах 22.5°/67.5°/112.5°/157.5° — особливо забути звести кут до 0..180 (склавши протилежні напрями). Підступніша плутанина — на діагоналях: придушення немаксимумів порівнює сусідів **упоперек межі, тобто вздовж градієнта**, тож градієнт ~45° (а межа тоді йде як `/`) перевіряють по діагоналі `\` (сусіди ↖ та ↘), а ~135° — навпаки, по `/` (сусіди ↙ та ↗). Переплутати ці дві діагоналі легко: програма не падає, а тихо стоншує не в той бік, і діагональні контури двояться або рвуться. Перевір кожен сектор на простому тесті — вертикальна межа дає сектор 0 (ліво/право), горизонтальна — сектор 2 (верх/низ), а чисті діагоналі `/` і `\` — сектори 1 і 3 відповідно.

- **Вибір порогів.** Канні дуже чутливий до `lo`/`hi`. Емпіричне правило — `hi/lo ≈ 2..3`; самі значення прив'язують до **розподілу сили** в кадрі (наприклад, `hi` = такий, що вище нього лишається верхні кілька відсотків пікселів). Зашиті «магічні» пороги, підібрані під один кадр, на іншій сцені або заллють кадр шумом, або зітруть слабкі межі. Краще рахувати пороги з гістограми сили щокадру.

- **Стек гістерезису й позначання.** Розмір стеку — рівно `H*W` (найгірший випадок). Позначай піксель `STRONG` **при додаванні** в стек, а не при витяганні, інакше той самий піксель потрапить у чергу кілька разів і стек переповниться. І не роби обхід рекурсією: на довгому контурі вона переповнить апаратний стек викликів.

- **Манхеттенська сила змінює пороги.** Якщо заради швидкості замінив `√(Gx²+Gy²)` на `|Gx|+|Gy|`, пам'ятай, що друга оцінка завищує силу на косих межах — тож пороги, підібрані під евклідову силу, доведеться перебрати наново. Не змішуй дві метрики в одному конвеєрі.

Це повний робочий кістяк Канні без жодної бібліотеки. Для бортового комп'ютера ставлять інтерпольований NMS і евклідову силу; для мікроконтролера — квантований NMS і манхеттенську силу, а пороги рахують із гістограми. Головне розуміти, що Канні дає чисті межі **не одним трюком, а конвеєром**, де кожна ланка прибирає ваду попередньої, — і саме тому його не можна «спростити», викинувши якусь ланку, без втрати тієї якості, заради якої його й беруть.
