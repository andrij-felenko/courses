# ⚙️ Постобробка виходу YOLO на C

Прискорювач (NPU/TPU) поверне тобі сирий тензор — простий масив `float`. Усе цікаве починається **після** цього: масив чисел треба перетворити на список рамок, які можна показати, відстежити чи передати в керування. Цей крок — постобробка — цілком на боці процесора, і його зазвичай пишуть вручну в прошивці, бо він легкий і не вартий важкої бібліотеки. Зберімо повний робочий постпроцесор на чистому C — декодування тензора, фільтр за впевненістю, NMS — без жодної зовнішньої залежності, готовий лягти у firmware.

## Що на вході й що треба на виході

На вході — масив `out[S·S·K]`, де `K = B·5 + C`: для кожної з S×S клітинок сітки лежить B якорів по 5 чисел (`tx, ty, tw, th, objectness`) і далі C class-logits, спільних на якорі клітинки. Числа — **сирі**: координати закодовані як поправки до якорів, упевненість і класи — як logits до сигмоїди/softmax.

На виході треба список **рамок у пікселях** із класом і підсумковою оцінкою, очищений від двійників. Шлях туди — три кроки: **декодувати** кожен якір у рамку, **відсіяти** слабкі за порогом упевненості, **придушити** двійники через NMS.

Варто розуміти, **як саме** тензор до тебе приходить, бо від цього залежить уся індексація. Прискорювач після прогону мережі лишає результат у шматку пам'яті — або у власному буфері, який мапиться в адресний простір процесора, або скопійованим у звичайну оперативну пам'ять драйвером. У будь-якому разі для твого коду це просто `const float *out` і відоме число елементів `S·S·K`. Жодної структури в цих байтах немає — лише домовленість про порядок, яку задав експортер моделі. Уся постобробка — це читання цього плаского масиву за **правильною** формулою адреси; помилишся у формулі — дістанеш не ту п'ятірку чисел, і рамки розсиплються. Тому почнемо з типів і параметрів, які цю формулу фіксують.

## Крок 0: типи й параметри

Усе тримаємо на статичних масивах — жодного `malloc`, щоб код був придатний навіть для МК без купи. Стелю кандидатів задаємо константою.

:::tabs
```cpp
#include <math.h>
#include <string.h>

#define S        13          // сітка S×S
#define B        3           // якорів на клітинку
#define C        20          // класів
#define STRIDE   32          // крок сітки: вхід 416 / S(13) = 32
#define K        (B*5 + C)   // глибина на клітинку = 35
#define MAX_DET  256         // стеля рамок після фільтра

typedef struct {
    float x1, y1, x2, y2;    // рамка у пікселях (кути)
    float score;             // підсумкова оцінка = objectness · max(class)
    int   cls;               // індекс класу
} det_t;

// форми якорів у пікселях (ширина, висота) — підібрані під дані, не випадкові
static const float ANCHOR_W[B] = { 116.0f, 30.0f, 60.0f };
static const float ANCHOR_H[B] = {  90.0f, 61.0f, 45.0f };

static float sigmoidf(float x) { return 1.0f / (1.0f + expf(-x)); }
```
```python
import math
from dataclasses import dataclass

S       = 13          # сітка S×S
B       = 3           # якорів на клітинку
C       = 20          # класів
STRIDE  = 32          # крок сітки: вхід 416 / S(13) = 32
K       = B * 5 + C   # глибина на клітинку = 35
MAX_DET = 256         # стеля рамок після фільтра

@dataclass
class Det:
    x1: float; y1: float; x2: float; y2: float   # рамка у пікселях (кути)
    score: float                                 # підсумкова оцінка = objectness · max(class)
    cls: int                                     # індекс класу

# форми якорів у пікселях (ширина, висота) — підібрані під дані, не випадкові
ANCHOR_W = (116.0, 30.0, 60.0)
ANCHOR_H = ( 90.0, 61.0, 45.0)

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))
```
:::

Якорі тут — **не довільні** числа: їх рахують кластеризацією розмірів реальних рамок навчального набору, тож вони мусять збігатися з тими, на яких модель навчена. Поставиш чужі — декодування «попливе»: `bw = anchor_w · e^tw` дасть систематично не той розмір.

## Крок 1: декодування одного якоря в рамку

Серце постобробки. Беремо п'ятірку якоря й перетворюємо поправки на абсолютні пікселі. Зсуви центру `tx, ty` проганяємо крізь σ (щоб лишилися в межах клітинки) і додаємо до позиції клітинки; розміри беремо як `e^tw`, `e^th` від форми якоря.

:::tabs
```cpp
// розкладка out: канали останні — спершу всі K чисел клітинки (0,0), потім (0,1)...
// клас k якоря a лежить ПІСЛЯ всіх п'ятірок: зсув B*5 + k (класи спільні на клітинку)
static det_t decode(const float *out, int cx, int cy, int a) {
    int base = (cy * S + cx) * K;     // початок вектора клітинки
    const float *t = out + base + a * 5;   // п'ятірка якоря a

    float bx = (cx + sigmoidf(t[0])) * STRIDE;   // центр X, пікселі
    float by = (cy + sigmoidf(t[1])) * STRIDE;   // центр Y, пікселі
    float bw = ANCHOR_W[a] * expf(t[2]);         // ширина, пікселі
    float bh = ANCHOR_H[a] * expf(t[3]);         // висота, пікселі
    float obj = sigmoidf(t[4]);                  // упевненість «тут об'єкт»

    // найкращий клас: max class-logit (softmax зберігає порядок, тож max logit = max p)
    const float *cl = out + base + B * 5;        // C class-logits клітинки
    int best = 0; float best_logit = cl[0];
    for (int k = 1; k < C; k++)
        if (cl[k] > best_logit) { best_logit = cl[k]; best = k; }
    float cls_p = sigmoidf(best_logit);          // ймовірність найкращого класу

    det_t d;
    d.x1 = bx - bw * 0.5f;  d.y1 = by - bh * 0.5f;   // центр+розмір → кути
    d.x2 = bx + bw * 0.5f;  d.y2 = by + bh * 0.5f;
    d.score = obj * cls_p;                        // обидва мають бути високі
    d.cls = best;
    return d;
}
```
```python
# розкладка out: канали останні — спершу всі K чисел клітинки (0,0), потім (0,1)...
# клас k якоря a лежить ПІСЛЯ всіх п'ятірок: зсув B*5 + k (класи спільні на клітинку)
def decode(out, cx, cy, a):
    base = (cy * S + cx) * K          # початок вектора клітинки
    t = base + a * 5                  # п'ятірка якоря a

    bx = (cx + sigmoid(out[t + 0])) * STRIDE   # центр X, пікселі
    by = (cy + sigmoid(out[t + 1])) * STRIDE   # центр Y, пікселі
    bw = ANCHOR_W[a] * math.exp(out[t + 2])    # ширина, пікселі
    bh = ANCHOR_H[a] * math.exp(out[t + 3])    # висота, пікселі
    obj = sigmoid(out[t + 4])                  # упевненість «тут об'єкт»

    # найкращий клас: max class-logit (softmax зберігає порядок, тож max logit = max p)
    cl = base + B * 5                          # C class-logits клітинки
    best, best_logit = 0, out[cl]
    for k in range(1, C):
        if out[cl + k] > best_logit:
            best_logit, best = out[cl + k], k
    cls_p = sigmoid(best_logit)                # ймовірність найкращого класу

    return Det(
        x1=bx - bw * 0.5, y1=by - bh * 0.5,    # центр+розмір → кути
        x2=bx + bw * 0.5, y2=by + bh * 0.5,
        score=obj * cls_p,                     # обидва мають бути високі
        cls=best,
    )
```
:::

Два місця тут варті уваги. Перше — **порядок у пам'яті**: класи лежать `base + B*5 + k`, тобто **після** всіх п'ятірок якорів, бо C class-logits спільні на всі якорі клітинки, а не вкладені в кожен якір. Друге — підсумкова `score = obj · cls_p`: рамку беремо лише коли мережа певна **і** що тут щось є (`obj`), **і** що це конкретний клас (`cls_p`); якщо хоч одне низьке — оцінка падає, і рамка не пройде поріг. (Для пошуку найкращого класу досить порівнювати logits — монотонні σ/softmax не міняють, який із них найбільший.)

## Крок 2: пройти всю сітку й відсіяти слабкі

Тепер просто оббігаємо всі клітинки й усі якорі, декодуємо кожен і лишаємо тільки тих, чия оцінка вища за поріг упевненості. Так із S·S·B = 507 потенційних рамок зазвичай лишаються одиниці-десятки.

:::tabs
```cpp
// повертає кількість рамок, записаних у dets[]; не більше MAX_DET
static int collect(const float *out, float conf_thr, det_t *dets) {
    int n = 0;
    for (int cy = 0; cy < S; cy++)
        for (int cx = 0; cx < S; cx++)
            for (int a = 0; a < B; a++) {
                det_t d = decode(out, cx, cy, a);
                if (d.score < conf_thr) continue;     // слабка — геть одразу
                if (n < MAX_DET) dets[n++] = d;       // стеля — захист від переповнення
            }
    return n;
}
```
```python
# повертає список рамок; не більше MAX_DET
def collect(out, conf_thr):
    dets = []
    for cy in range(S):
        for cx in range(S):
            for a in range(B):
                d = decode(out, cx, cy, a)
                if d.score < conf_thr:
                    continue                  # слабка — геть одразу
                if len(dets) < MAX_DET:
                    dets.append(d)            # стеля — захист від переповнення
    return dets
```
:::

Поріг `conf_thr` тут — перший і найдешевший фільтр: він відрубує переважну більшість порожніх якорів **до** дорогого NMS. Перевірка `n < MAX_DET` — не косметика: у патологічному кадрі (або з надто низьким порогом) рамок може набратися більше за буфер, і без цієї межі був би вихід за масив.

## Крок 3: NMS — прибрати двійників

Лишається класичний NMS: сортуємо за оцінкою, ідемо від найвпевненіших і гасимо все, що того ж класу й перекривається понад поріг IoU.

:::tabs
```cpp
static float iou(det_t a, det_t b) {
    float ix1 = fmaxf(a.x1, b.x1), iy1 = fmaxf(a.y1, b.y1);
    float ix2 = fminf(a.x2, b.x2), iy2 = fminf(a.y2, b.y2);
    float iw = ix2 - ix1, ih = iy2 - iy1;
    if (iw <= 0.0f || ih <= 0.0f) return 0.0f;        // не торкаються
    float inter = iw * ih;
    float uni = (a.x2-a.x1)*(a.y2-a.y1) + (b.x2-b.x1)*(b.y2-b.y1) - inter;
    return inter / uni;
}

// NMS на місці: лишені позначає keep[i]=1; повертає їх кількість.
static int nms(det_t *d, int n, float iou_thr, int *keep) {
    // сортування за спаданням оцінки (n мала після фільтра — бульбашки досить)
    for (int i = 0; i < n - 1; i++)
        for (int j = 0; j < n - 1 - i; j++)
            if (d[j].score < d[j+1].score) {
                det_t tmp = d[j]; d[j] = d[j+1]; d[j+1] = tmp;
            }
    for (int i = 0; i < n; i++) keep[i] = 1;
    for (int i = 0; i < n; i++) {
        if (!keep[i]) continue;                       // вже придушена
        for (int j = i + 1; j < n; j++) {             // лише слабші за i
            if (!keep[j] || d[j].cls != d[i].cls) continue;   // різні класи не конкурують
            if (iou(d[i], d[j]) > iou_thr) keep[j] = 0;       // двійник — геть
        }
    }
    int kept = 0; for (int i = 0; i < n; i++) kept += keep[i];
    return kept;
}
```
```python
def iou(a, b):
    ix1, iy1 = max(a.x1, b.x1), max(a.y1, b.y1)
    ix2, iy2 = min(a.x2, b.x2), min(a.y2, b.y2)
    iw, ih = ix2 - ix1, iy2 - iy1
    if iw <= 0.0 or ih <= 0.0:
        return 0.0                                    # не торкаються
    inter = iw * ih
    uni = (a.x2-a.x1)*(a.y2-a.y1) + (b.x2-b.x1)*(b.y2-b.y1) - inter
    return inter / uni

# NMS на місці: лишені позначає keep[i]=True; повертає їх кількість.
def nms(d, iou_thr, keep):
    n = len(d)
    # сортування за спаданням оцінки (n мала після фільтра — бульбашки досить)
    d.sort(key=lambda x: x.score, reverse=True)
    for i in range(n):
        keep[i] = True
    for i in range(n):
        if not keep[i]:
            continue                                  # вже придушена
        for j in range(i + 1, n):                     # лише слабші за i
            if not keep[j] or d[j].cls != d[i].cls:
                continue                              # різні класи не конкурують
            if iou(d[i], d[j]) > iou_thr:
                keep[j] = False                       # двійник — геть
    return sum(keep)
```
:::

## Усе разом: один виклик постобробки

Зведемо три кроки в одну функцію, яку прошивка кличе на кожен кадр одразу після прискорювача.

```c
// out — сирий тензор від NPU [S*S*K]; final[] — куди скласти лишені рамки.
// Повертає кількість знайдених об'єктів.
int yolo_postprocess(const float *out, float conf_thr, float iou_thr,
                     det_t *final, int final_cap) {
    static det_t dets[MAX_DET];
    static int   keep[MAX_DET];

    int n = collect(out, conf_thr, dets);             // декодувати + відсіяти слабкі
    nms(dets, n, iou_thr, keep);                      // прибрати двійників

    int m = 0;
    for (int i = 0; i < n && m < final_cap; i++)
        if (keep[i]) final[m++] = dets[i];            // зібрати лишені
    return m;
}

// приклад виклику:
//   det_t found[64];
//   int k = yolo_postprocess(npu_output, 0.30f, 0.45f, found, 64);
//   for (int i = 0; i < k; i++)
//       printf("cls=%d score=%.2f  [%.0f %.0f %.0f %.0f]\n",
//              found[i].cls, found[i].score,
//              found[i].x1, found[i].y1, found[i].x2, found[i].y2);
```

Буфери `dets` і `keep` — `static`, тобто живуть не на стеку, а в статичній пам'яті: на МК зі скромним стеком великий локальний масив легко спричинив би переповнення стеку. Параметри `conf_thr` і `iou_thr` винесені назовні навмисно — їх крутять під борт уже на місці: вищий `conf_thr` менше бреше, нижчий — менше сліпне; нижчий `iou_thr` агресивніше чистить двійників, але ризикує злити сусідні цілі.

## Скільки це коштує на борту

Приємна новина: уся ця постобробка — **дешева** проти самого прогону мережі. Прогін — це мільйони множень, які бере на себе прискорювач; постобробка ж працює з готовим тензором на процесорі й коштує копійки. Прикиньмо порядки на нашому прикладі (S = 13, B = 3, C = 20).

Декодування проходить S·S·B = 13·13·3 = 507 якорів. На кожен — кілька `expf`/`sigmoidf` і прохід по C = 20 класах: разом десятки тисяч простих операцій. Це частки мілісекунди навіть на скромному процесорі. Фільтр за впевненістю йде в тому ж проході — задарма. NMS працює вже з тим, що пройшло поріг, а це зазвичай **одиниці-десятки** рамок; його `O(n²)` від n = 20 — це 400 порівнянь IoU, теж дрібниця. Підсумок: постобробка кадру вкладається в долі мілісекунди, тоді як сам інференс — десятки. Тому оптимізувати тут майже нічого; головне — **коректність**, а не швидкість.

Пам'ять теж скромна. Сирий тензор `out` — найбільший шматок: S·S·K = 13·13·35 = 5915 чисел `float`, тобто ≈ 23 КБ; його тримає драйвер прискорювача. Наші власні буфери — `dets[256]` (по кілька `float` на рамку, ≈ 6 КБ) і `keep[256]` (1 КБ). Усе разом — десятки кілобайт, що влізе навіть у середній МК. Якщо й це багато, `MAX_DET` сміливо зменшують: після розумного `conf_thr` рамок рідко більше за кілька десятків, тож 64 замість 256 нічого не втрачає.

Один практичний наслідок дешевизни: пороги можна **підбирати в польоті**, не боячись ціни. Хочеш у складній сцені тимчасово підняти повноту — опусти `conf_thr` на ходу; код від цього не сповільниться помітно. Це робить постобробку зручним місцем для адаптації поведінки детектора під обставини, тоді як саму важку мережу чіпати не можна.

## Пастки, що мовчать

Цей код компілюється й «працює» навіть коли видає мотлох — тому помилки тут тихі. Найчастіші:

**Не та розкладка тензора.** Тут припущено «канали останні» (клітинка за клітинкою, всередині — K чисел). Частина моделей віддає «канали перші» (спершу вся площина `tx`, потім уся `ty`, ...). Переплутаєш — індексація поїде, рамки стануть випадковими, **без жодної помилки компілятора**. Перевір розкладку експортера моделі, перш ніж вірити виходу.

**Чужі якорі.** `ANCHOR_W/H` мусять бути **ті самі**, на яких модель навчена. Інші числа — і `e^tw` дасть систематично не той розмір рамки: ціль начебто ловиться, а рамка завжди завелика чи замала.

**Забутий `stride`.** Якщо в моделі кілька виходів-масштабів (дрібна, середня, груба сітка), у кожного **свій** `stride` і **свій** набір якорів. Прогнати всі через один `STRIDE` — і дрібні чи великі цілі систематично зміщуються.

**Координати поза кадром.** Після декодування рамка може частково вилазити за межі зображення (центр близько краю, розмір великий). Перед малюванням чи передачею в керування координати варто обрізати в `[0, width]×[0, height]` — інакше далі по конвеєру можливі від'ємні індекси.

Кожна з цих пасток не валить програму — вона тихо псує результат. Тому постобробку завжди звіряють очима на кількох кадрах: намалюй рамки поверх зображення й переконайся, що вони лягають на справжні об'єкти, перш ніж довіряти числам у польоті.
