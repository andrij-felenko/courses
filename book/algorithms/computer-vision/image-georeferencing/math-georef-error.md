# 🧮 Похибка геоприв'язки: якобіан, еліпс на землі, CEP

Координата без радіуса невірогідності — половина відповіді, і цю другу половину дає чиста арифметика: продиференціювати формулу перетину по кожному вхідному числу, скласти з похідних якобіан, прогнати крізь нього коваріацію давачів. Далі — самі викладки та два порахованих випадки для дрона на висоті 120 м.

## Природна пара напрямків

Диференціюємо формулу перетину променя з поверхнею:

```
P = C + (h / d_вниз) · d_n
```

Вхідних чисел сім: три кути орієнтації, три складові положення камери **C** і висота поверхні під променем. Вихідних — два: горизонтальні координати точки на землі (третя не вільна, точка лежить на поверхні).

Записувати похідні в осях «північ–схід» — марна робота: кожна залежатиме від азимута зйомки, і в матриці не буде видно нічого. Але задача має власну пару напрямків. Нехай γ — кут між променем і горизонталлю. Тоді промінь визначає горизонтальний напрямок **û** — від точки під дроном до цілі, назвімо його **дальністю**, — і перпендикулярний до нього горизонтальний **v̂**, **поперек**. Три величини, що знадобляться далі:

```
d_вниз = sin γ          похила дальність  t = h / sin γ
|d_гор| = cos γ         горизонтальна відстань  D = h · ctg γ
```

Одразу видно річ, яку в осях NED помітити важко: поворот навколо самого променя не рухає точку на землі взагалі. З трьох обертових ступенів вільності на відповідь працюють лише дві — нахили променя вбік і вгору-вниз.

## Нахил: звідки береться 1/sin²γ

Нехай промінь хитнувся на малий кут δ. Кінець відрізка завдовжки t при такому повороті зсувається **впоперек променя** на t·δ — це важіль, спільний для обох напрямків. А от далі шляхи розходяться.

Якщо нахил стався у вертикальній площині променя, зсунута точка вже не на землі: щоб знайти нове влучання, треба продовжити промінь до поверхні. Горизонтальний відрізок завдовжки L проєктується на перпендикуляр до променя всього в L·sin γ — отже, щоб покрити зсув t·δ, на землі треба відійти на t·δ/sin γ. Косий погляд розтягує все, що міряється вздовж дальності.

Якщо ж нахил горизонтальний, зсув t·δ сам лежить у площині землі: жодної проєкції, ділити ні на що.

```
уздовж дальності   Δ = t·δ₁ / sin γ = h·δ₁ / sin²γ
упоперек           Δ = t·δ₂         = h·δ₂ / sin γ
```

Два множники 1/sin γ уздовж дальності мають різні причини: перший сидить у самій похилій дальності t = h/sin γ (важіль), другий приходить від проєкції косого зсуву на землю. Пряме диференціювання дає те саме одним рядком:

```
D = h · ctg γ        →        dD/dγ = − h / sin²γ
```

![Промінь, нахилений на δ: зсув t·δ упоперек променя і його розтягнута проєкція на землю](/book/algorithms/computer-vision/image-georeferencing/img/two-levers.svg)
*Важіль дає перше 1/sin γ, проєкція косого зсуву на землю — друге.*

Лишилося сказати, звідки беруться δ₁ і δ₂. Похибка орієнтації — це малий вектор повороту **ε**; зміна напрямку променя дорівнює **ε** × **d̂**, тобто на нахил працює лише складова **ε**, перпендикулярна до променя. Розкладімо її по двох перпендикулярах:

```
ê₁ = (−sin γ·cos α, −sin γ·sin α, cos γ)      у вертикальній площині променя
ê₂ = (−sin α,        cos α,       0     )      горизонтальний, упоперек
```

де α — азимут зйомки. Нахил у вертикальній площині живить обертання навколо горизонтальної осі **v̂** (крен-тангаж), нахил убік — обертання навколо **û** і навколо вертикалі. Підставмо реальну модель давачів: крен і тангаж із похибкою σ_кр кожен, курс — гірший, σ_курс (акселерометри вимірюють вертикаль по силі тяжіння, а північ доводиться брати з магнетометра).

```
Σ_ε = diag(σ_кр², σ_кр², σ_курс²)     у осях «північ, схід, вниз»

σ_δ1² = ê₂ᵀ·Σ_ε·ê₂ = σ_кр²·(sin²α + cos²α) = σ_кр²
σ_δ2² = ê₁ᵀ·Σ_ε·ê₁ = σ_кр²·sin²γ + σ_курс²·cos²γ
cov(δ₁, δ₂) = ê₁ᵀ·Σ_ε·ê₂ = σ_кр²·(sin γ·cos α·sin α − sin γ·sin α·cos α) = 0
```

Курс не входить у поздовжню похибку **зовсім**, за жодного кута. А в поперечну він входить із множником cos γ, який після множення на t дає рівно D — помилка курсу обертає горизонтальний винос навколо надира, і під собою (D = 0) не коштує нічого.

## Висота поверхні і положення камери

Висота входить у ту саму формулу D = h·ctg γ, тільки тепер сталим тримаємо кут:

```
∂D/∂h = ctg γ
```

Тут h — висота камери **над поверхнею**, тому в неї стікаються дві незалежні похибки: вертикальна складова GNSS і помилка моделі рельєфу. Обидві діють однаково (одна піднімає камеру, друга опускає землю), тож складаються квадратами:

```
σ_h² = σ_GNSS,верт² + σ_рельєф²
```

Горизонтальне ж положення камери входить у формулу доданком, а не множником: **C** стоїть окремо від усього, що залежить від кута й висоти. Похідна дорівнює одиниці — зсув приймача на метр на північ переносить цільову точку на метр на північ, байдуже, за 50 метрів ціль чи за два кілометри. Це єдиний доданок бюджету, що не росте з дальністю.

## Якобіан і перенесення коваріації

Складімо похідні в матрицю 2×5. Стовпці — джерела похибки (два нахили променя, дві горизонтальні складові положення, висота над поверхнею), рядки — координати точки в осях «дальність / поперек»:

```
        δ₁         δ₂        e_д   e_п    e_h
g_д [ h/sin²γ       0         1     0    ctg γ ]
g_п [    0       h/sin γ      0     1      0   ]
```

Далі — звичайне [лінійне перенесення коваріації](book:math/error-propagation): якщо входи описано матрицею Σ, то [якобіан](book:math/jacobian-matrix) переносить її на вихід як Σ_g = J·Σ·Jᵀ. Вважаймо горизонтальну похибку GNSS ізотропною (σ_гор по обох осях) — тоді її внесок однаковий у будь-якому повороті, і Σ входів діагональна. Перемножмо:

```
σ_д² = (h/sin²γ)²·σ_кр²  +  σ_гор²  +  ctg²γ·σ_h²
σ_п² = h²·σ_кр²  +  D²·σ_курс²  +  σ_гор²
cov(g_д, g_п) = 0
```

Позадіагональний елемент [матриці коваріації](book:math/covariance-matrix-intuition) вийшов нулем, і це не наближення: усі три доданки, що дають кореляцію, скоротилися точно. Отже, головні осі еліпса похибки **збігаються з дальністю й поперечником** — шукати власні вектори не треба, [вони вже знайдені](book:math/eigenvalues) геометрією задачі. Досить узяти анізотропну горизонтальну похибку GNSS або різні σ крену й тангажа — і кореляція з'явиться, а еліпс разом із нею трохи розвернеться.

Друга формула читається просто: крен-тангаж дає поперек h·σ_кр незалежно від кута зйомки, а курс — D·σ_курс, пропорційно виносу.

```

```

           t = 240.00 м       D = 207.85 м

  кути вздовж   (120/0.25)·0.0087266     = 4.189 м   → 17.546 м²   (18 %)
  GNSS          1.5                                  →  2.250 м²   ( 2 %)

Удвічі пологіший промінь — і еліпс із 3.54 × 1.93 м робиться 9.74 × 2.58 м: розтягується у два з половиною рази вздовж дальності й лише на третину впоперек. Панує ж в обох випадках **не орієнтація, а рельєф**: 66 % дисперсії при 60° і 79 % при 30°. П'ять метрів невизначеності по висоті з множником ctg 30° коштують 8.7 м на землі — більше, ніж пів градуса кутів і GNSS разом.

## Від еліпса до кола: CEP і CE90

Еліпс — повна відповідь, але оператору потрібне одне число. Спершу про сам еліпс. Для [двовимірного нормального розподілу](book:math/normal-distribution) ймовірність опинитися всередині еліпса, розтягнутого в k разів проти одиничного, дорівнює

```
P(k) = 1 − exp(−k²/2)
```

і — що зручно — **не залежить від того, наскільки еліпс витягнутий**. Звідси таблиця множників, однакова для будь-якої задачі: k = 1 → 39.3 %, k = 1.1774 → 50 %, k = 2.1460 → 90 %, k = 2.4477 → 95 %. Той самий еліпс «одна сигма» накриває лише дві п'ятих випадків, а не дві третини, як звик читач одновимірних σ.

З колом складніше. [Кругова ймовірна похибка](book:math/circular-error-probable) CEP — це радіус кола навколо оцінки, у яке потрапляє половина реалізацій; CE90 — те саме для 90 %, стандартна міра точності знімків і GNSS. Коли еліпс вироджується в коло (σ_д = σ_п = σ), інтеграл береться і дає

```
CEP  = σ·√(2·ln 2)  = 1.1774·σ
CE90 = σ·√(2·ln 10) = 2.1460·σ
```

Для витягнутого еліпса замкненої формули немає — ймовірність потрапити в коло радіуса r рахують інтегралом по куту:

```
P(r) = (1/2π) · ∫₀^2π [ 1 − exp( −r² / (2·(σ_д²·cos²φ + σ_п²·sin²φ)) ) ] dφ
```

і розв'язують P(r) = 0.5 половинним діленням. Кишенькове наближення — CEP ≈ 0.589·(σ_д + σ_п); чисельна перевірка проти цього інтеграла показує, що воно розходиться з ним не більше ніж на 2.1 % для відношення півосей від 0.2 до 1 і розповзається за межами смуги (при 0.1 уже −5 %). Наші випадки — 0.54 і 0.26, обидва всередині:

```
γ = 60°:   CEP = 3.18 м    CE90 =  6.23 м    (наближення дає 3.22 м)
γ = 30°:   CEP = 7.13 м    CE90 = 16.23 м    (наближення дає 7.25 м)
```

Відношення CE90/CEP для круглої похибки дорівнює √(ln 10 / ln 2) = 1.823, але для витягнутого еліпса воно росте: 1.96 у першому випадку й 2.28 у другому. Перерахунок «на око» через сталий множник тут занижує хвіст.

## Куди дівати гроші

Поздовжня дисперсія — сума двох доданків, і обидва ростуть, коли промінь пологішає. Корисно знати, де вони міняються місцями; прирівняймо їх:

```
(h/sin²γ)·σ_кут = ctg γ·σ_h        →        σ_h* = 2·h·σ_кут / sin 2γ
```

Нижче за цей поріг задачу тримають кути, вище — рельєф. Для наших умов (h = 120 м, σ_кут = 0.5°) поріг дорівнює 2.42 м і при 60°, і при 30° — множник sin 2γ симетричний навколо 45°, де поріг найнижчий: 2.09 м.

> 🔧 **Навіщо це.** Формула порога відповідає на питання, що купувати. При σ_h = 5 м ми глибоко в зоні рельєфу, тож кращий інерціальний блок майже нічого не дасть: уп'ятеро точніші кути (0.1°) зменшують CEP при 30° лише з 7.13 до 6.17 м, а RTK замість звичайного GNSS — до 6.85 м. Замінити сітку висот на метрову — і CEP падає до 4.28 м; зробити обидві речі — до 2.34 м. Порядок дій диктує не паспорт давача, а множник, з яким його похибка входить у якобіан.
