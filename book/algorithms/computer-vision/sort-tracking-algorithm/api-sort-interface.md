# 📋 Специфікація інтерфейсу та параметрів SORT (API Reference)

Цей документ містить повний структурний опис інтерфейсу, конфігураційних параметрів, внутрішніх структур даних та протоколу взаємодії модуля мультиоб'єктного трекінгу SORT із зовнішніми підсистемами детекції та аналітики.

## 1. Архітектурне призначення та принципи інтеграції

Модуль SORT реалізує концепцію чистого функціонального конвеєра обробки просторових даних. Він приймає на вхід некоординовані масиви габаритних прямокутників детектора з поточного відеокадру та повертає стабілізований масив активних треків із присвоєними глобальними ідентифікаторами (ID).

Модуль розроблений з урахуванням жорстких вимог систем реального часу:
- **Детермінізм пам'яті:** Усі внутрішні буфери та пули треків можуть виділятися одноразово під час ініціалізації (`sort_tracker_create`), що виключає затримки на динамічну алокацію пам'яті під час обробки відеопотоку.
- **Низька затримка (Low Latency):** Час виконання функції оновлення `sort_tracker_update` для сцени з 50 об'єктами не перевищує 0.5 мілісекунди на типовому процесорі архітектури ARM Cortex-A53 / x86-64.
- **Ізоляція від піксельних даних:** Інтерфейс трекера оперує виключно нормалізованими чи піксельними координатами габаритних рамок, що усуває пряму залежність від бібліотек обробки зображень (OpenCV, FFmpeg).
- **Асинхронна розв'язка з нейромережею:** Оскільки інференс детектора (наприклад, YOLOv8 або TensorRT) виконується на GPU чи NPU, трекер виконується на центральному процесорі (CPU), споживаючи менше 1% одного ядра і не блокуючи графічний конвеєр.

## 2. Конфігураційні параметри трекера (`sort_config_t` / `SortConfig`)

Конфігураційна структура визначає динамічну поведінку фільтра Калмана, порогові правила відсікання асоціацій та часові межі життя треків.

| Параметр | Тип даних | За замовчуванням | Допустимий діапазон | Призначення та фізичний зміст |
| :--- | :--- | :--- | :--- | :--- |
| `max_age` | `int` | `1` | `1 .. 30` | Максимальна кількість послідовних кадрів без детекції до повного знищення треку. |
| `min_hits` | `int` | `3` | `1 .. 10` | Мінімальна кількість підтверджених асоціацій поспіль для переведення треку в активний стан. |
| `iou_threshold` | `float` | `0.3` | `0.05 .. 0.8` | Поріг просторового перекриття. Пари з `IoU < iou_threshold` примусово відхиляються. |
| `q_pos_scale` | `float` | `0.01` | `1e-5 .. 1.0` | Масштаб шуму процесу для координат положення та масштабу `(u, v, s)`. |
| `q_vel_scale` | `float` | `0.1` | `1e-4 .. 10.0` | Масштаб шуму процесу для лінійних швидкостей `(u̇, v̇, ṡ)`. |
| `r_meas_scale` | `float` | `1.0` | `0.1 .. 100.0` | Масштаб дисперсії шуму вимірів детектора. |

:::tabs
```c
typedef struct {
    int max_age;
    int min_hits;
    float iou_threshold;
    float q_pos_scale;
    float q_vel_scale;
    float r_meas_scale;
} sort_config_t;
```
```cpp
struct SortConfig {
    int max_age{1};
    int min_hits{3};
    float iou_threshold{0.3f};
    float q_pos_scale{0.01f};
    float q_vel_scale{0.1f};
    float r_meas_scale{1.0f};
};
```
:::

### Детальний опис впливу ключових параметрів

1. **Параметр `max_age` (максимальний вік вибігу):**
   У класичному SORT встановлено `max_age = 1`. Якщо об'єкт не виявлено протягом 2 кадрів поспіль, його трек негайно знищується. Збільшення цього значення до `5..15` дозволяє проходити короткочасні пропуски детектора, але без Re-ID це різко збільшує ймовірність перескакування «сліпого» треку на сусідні чужі об'єкти.
2. **Параметр `min_hits` (поріг підтвердження цілі):**
   Визначає інерційність створення нової цілі. Значення `min_hits = 3` означає, що поодинокі шумові рамки детектора, які протрималися лише 1–2 кадри, ніколи не будуть видані назовні, що гарантує захист від хибнопозитивних спрацьовувань.
3. **Параметр `iou_threshold` (геометричний поріг збігу):**
   Встановлює мінімально допустиме відносне перекриття між прогнозом Калмана та детекцією. Значення `0.3` (30% перекриття) є оптимальним компромісом: менші значення (`0.1`) призводять до помилкового зв'язування різних об'єктів у натовпі, а більші (`0.6`) викликають зрив супроводження при швидкому русі або раптових змінах пози.
4. **Параметри шумів `q_pos_scale` та `q_vel_scale` (динаміка Калмана):**
   Керують довірою фільтра до власної фізичної моделі руху. Збільшення шуму швидкостей `q_vel_scale` робить трекер більш чутливим до різких прискорень та маневрів, але підвищує тремтіння згладженої рамки на виході. Зменшення шуму робить рух дуже плавним, проте викликає відставання рамки від реального об'єкта під час поворотів.

## 3. Структури даних C та C++ API

### 3.1. Вхідна детекція (`sort_detection_t` / `Detection`)

Описує результат роботи нейромережевого детектора на поточному відеокадрі.

:::tabs
```c
typedef struct {
    float x1;          // Координата лівої межі рамки (пікселі)
    float y1;          // Координата верхньої межі рамки (пікселі)
    float x2;          // Координата правої межі рамки (пікселі)
    float y2;          // Координата нижньої межі рамки (пікселі)
    float confidence;  // Оцінка впевненості детектора [0.0 .. 1.0]
    int class_id;      // Ідентифікатор семантичного класу (наприклад, 0 = person, 2 = car)
} sort_detection_t;
```
```cpp
struct Detection {
    float x1{0.0f};
    float y1{0.0f};
    float x2{0.0f};
    float y2{0.0f};
    float confidence{0.0f};
    int class_id{0};

    [[nodiscard]] constexpr float width() const noexcept { return x2 - x1; }
    [[nodiscard]] constexpr float height() const noexcept { return y2 - y1; }
    [[nodiscard]] constexpr float area() const noexcept { return width() * height(); }
};
```
:::

### 3.2. Вихідний підтверджений трек (`sort_output_track_t` / `TrackedTarget`)

Репрезентує верифіковану ціль, що передається клієнтській програмі після завершення асоціації та фільтрації.

:::tabs
```c
typedef struct {
    float x1;          // Згладжена ліва межа рамки
    float y1;          // Згладжена верхня межа рамки
    float x2;          // Згладжена права межа рамки
    float y2;          // Згладжена нижня межа рамки
    float vx;          // Оцінена швидкість руху центра за віссю X (пікс/кадр)
    float vy;          // Оцінена швидкість руху центра за віссю Y (пікс/кадр)
    int track_id;      // Унікальний глобальний ідентифікатор цілі (ID > 0)
    int class_id;      // Клас цілі
    int age;           // Повний час життя треку від народження (кількість кадрів)
} sort_output_track_t;
```
```cpp
struct TrackedTarget {
    float x1{0.0f};
    float y1{0.0f};
    float x2{0.0f};
    float y2{0.0f};
    float vx{0.0f};
    float vy{0.0f};
    int track_id{-1};
    int class_id{0};
    int age{0};
};
```
:::

### 3.3. Внутрішній стан окремого треку (`sort_internal_track_t` / `TrackInternal`)

:::tabs
```c
typedef struct {
    float state[7];             // [u, v, s, r, u_dot, v_dot, s_dot]
    float covariance[7][7];      // Симетрична додатно визначена матриця P
    int track_id;               // Унікальний номер треку
    int class_id;               // Семантичний клас
    int hits;                   // Загальна кількість успішних асоціацій
    int hit_streak;             // Кількість асоціацій поспіль без пропусків
    int age;                    // Кількість кадрів з моменту ініціалізації
    int time_since_update;      // Кількість кадрів з моменту останньої детекції
    bool is_active;             // Прапорець занятості слота в пулі пам'яті
} sort_internal_track_t;
```
```cpp
struct TrackInternal {
    std::array<float, 7> state{};
    std::array<float, 49> covariance{};
    int track_id{-1};
    int class_id{0};
    int hits{0};
    int hit_streak{0};
    int age{0};
    int time_since_update{0};
    bool is_active{false};
};
```

## 4. Функціональний інтерфейс C та C++ API

### Ініціалізація та життєвий цикл трекера

:::tabs
```c
sort_tracker_t* sort_tracker_create(const sort_config_t *config, int max_capacity);
void sort_tracker_destroy(sort_tracker_t *tracker);
void sort_tracker_reset(sort_tracker_t *tracker);
```
```cpp
class ISortTracker {
public:
    virtual ~ISortTracker() = default;
    virtual void reset() noexcept = 0;
    virtual std::vector<TrackedTarget> update(std::span<const Detection> detections) = 0;
};
```
:::

- **Параметри створення:**
  - `config`: Вказівник на структуру конфігурації. Якщо передано `NULL`, трекер використовує рекомендовані значення за замовчуванням.
  - `max_capacity`: Максимальна кількість одночасно підтримуваних треків у пам'яті (типово 128 або 256).
- **Повертає:** Вказівник на екземпляр `sort_tracker_t` або `NULL` у разі нестачі системної пам'яті.

### Оновлення та обробка кадру

Головна точка входу для покадрової обробки відеопотоку. Виконує повний цикл прогнозування Калмана, розрахунку матриці перекриття IoU, асоціації та оновлення стану.

:::tabs
```c
int sort_tracker_update(
    sort_tracker_t *tracker,
    const sort_detection_t *detections,
    int num_detections,
    sort_output_track_t *out_tracks,
    int max_out_tracks
);
```
```cpp
std::vector<TrackedTarget> update_stream(
    ISortTracker& tracker,
    std::span<const Detection> detections
);
```
:::

## 5. Обробка крайових випадків та контракт помилок

| Крайова ситуація | Поведінка алгоритму та системні гарантії |
| :--- | :--- |
| **Порожній кадр (`num_detections = 0`)** | Усі наявні треки виконують крок `predict()`. Лічильник `time_since_update` інкрементується. Треки, у яких `time_since_update > max_age`, автоматично деактивуються. Функція повертає `0` підтверджених треків. |
| **Переповнення пулу треків (`num_tracks > max_capacity`)** | Нові незв'язані детекції ігноруються із записом попередження в системний журнал; наявні активні треки продовжують стабільно супроводжуватися без виділення нових ID. |
| **Некоректні координати детектора (`x2 <= x1` або `y2 <= y1`)** | Такі детекції відкидаються на етапі первинної валідації входу й не беруть участі в розрахунку матриці IoU. |
| **Переповнення лічильника ID (`track_id` досягає `INT_MAX`)** | Лічильник циклічно скидається до `1`, пропускаючи значення, які наразі закріплені за живими активними треками. |
| **Потокова безпека (Thread Safety)** | Функції трекера не використовують глобального або статичного стану. Один екземпляр `sort_tracker_t` є реентерабельним і може безпечно обробляти окремий відеопотік в індивідуальному робочому потоці. |

## 6. Типовий життєвий цикл інтеграції в цикл обробки кадрів

Інтеграція модуля SORT у виробничий конвеєр відеоаналітики зазвичай реалізується за наступною схемою:

1. **Етап ініціалізації:** Під час запуску застосунку створюється екземпляр `sort_tracker_create` із заданою максимальною місткістю (наприклад, 128 треків) та виділяються фіксовані масиви `detections` та `out_tracks`.
2. **Головний цикл обробки кадрів:**
   - Кадр з камери декодується та передається в нейромережу детекції.
   - Вихідний тензор нейромережі фільтрується за порогом упевненості (Confidence Threshold) та проходить алгоритм придушення немаксимумів (NMS).
   - Очищені детекції формують масив `sort_detection_t` і передаються у `sort_tracker_update`.
   - Отримані активні треки `sort_output_track_t` використовуються бізнес-логікою (малювання рамок, підрахунок ліній перетину, детекція зупинки об'єктів).
3. **Етап завершення:** При зупинці відеопотоку викликається `sort_tracker_destroy` для коректного вивільнення ресурсів.

## 7. Бюджет пам'яті та часова складність

Для вбудованих платформ із обмеженими ресурсами (наприклад, ARM Cortex-M7 або мікрокомп'ютери з 512 МБ ОЗП) важливо оцінити накладні витрати пам'яті:
- Розмір структури одного треку `sizeof(sort_internal_track_t)` складає приблизно 260 байт (7 чисел стану `float`, матриця `7x7` `float` та лічильники `int`).
- Для пулу на 128 треків повний обсяг пам'яті трекера складає менше ніж 35 КБ, що дозволяє розміщувати контекст у швидкій SRAM пам'яті процесора.
- Часова складність одного кроку оновлення для `N` треків та `M` детекцій складає `O(N · M)` операцій обчислення IoU плюс `O(max(N, M)³)` операцій Угорського алгоритму (або `O(N · M)` для жадібної асоціації), що займає частки мілісекунди навіть при роботі на базових тактових частотах 200–400 МГц.
