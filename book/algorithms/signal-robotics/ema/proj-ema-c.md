# ⚙️ EMA на C: float, цілі числа й варіанти

## Задача

Сама формула EMA — один рядок: `y += α·(x − y)`. Та між «формулою на папері» й «фільтром, що роками працює в полі» лежить кілька дрібниць, на яких спотикаються майже всі. Якщо стартувати з нуля — фільтр перші секунди бреше. Якщо рахувати цілими (а на дешевому ядрі без апаратної коми так і роблять) — крок α·(x − y) округлюється до нуля, і оцінка **застрягає**, не дійшовши до істини. Якщо взяти α «гарним» числом 0.1 — процесор змушений множити з комою там, де міг би обійтися одним зсувом. Мета — кілька самодостатніх модулів на C: чесний `float`-варіант для ядер із комою, цілочисловий варіант, що не застрягає, версія зовсім без множення, і два корисні розширення — подвійне та адаптивне EMA. Усе коротке, реальне й готове до виклику з переривання.

## Ідея

EMA має **пам'ять** — одну згладжену оцінку, що живе від відліку до відліку. Тож тримати її в локальній змінній не можна: складемо стан і коефіцієнт в одну структуру, а роботу одного кроку — в одну гарячу функцію. Параметр α задаємо раз; далі функція лише читає відлік і повертає оцінку.

Дві засади рятують фільтр на старті. Перша: оцінку ініціалізуємо **першим відліком**, а не нулем, — тоді EMA одразу стоїть біля істини й лише згладжує, замість повзти до неї від нуля кілька десятків кроків. Друга стосується цілих чисел: щоб крихітний крок α·(x − y) не округлявся в нуль, оцінку тримають у **ширшому, дробовому** масштабі (множать на 2ᵏ — формат із фіксованою комою), а назовні віддають зсунутою назад. Так дрібні підштовхування накопичуються, і фільтр доходить до істини, а не зупиняється за крок до неї.

Окрема приємність цілого варіанту: якщо взяти α степенем половини (1/2, 1/4, 1/8…), множення α·(x − y) перетворюється на **зсув** `(x − y) >> k` — найдешевшу операцію процесора. Виходить EMA без жодного множення.

Лишається питання, звідки брати саму α. Зручних шляхів два, і обидва уникають угадування наосліп. Думаєте «вікнами» — згладжуйте «як ковзне середнє з вікном N», і тоді α ≈ 2/(N+1). Думаєте частотами — EMA це фільтр нижніх частот першого порядку, тож α пов'язана з бажаною частотою зрізу f_c і періодом відліку Δt тією самою сталою часу, що й в аналоговій RC-ланці: чим менша α, тим нижчий зріз і довша пам'ять. На практиці α майже завжди беруть із одного з цих двох міркувань, а тоді трохи підправляють на слух, дивлячись на вихід; підбирати її «на око» з порожнього місця — найгірший спосіб.

## Код

Спершу чесний `float`-варіант для ядер з апаратною комою. Стан — оцінка `y`, коефіцієнт `alpha` і прапорець, чи вже стартували першим відліком:

:::tabs
```c
#include <stdbool.h>

typedef struct {
    float y;          /* поточна згладжена оцінка        */
    float alpha;      /* коефіцієнт згладжування, 0..1   */
    bool  primed;     /* чи ініціалізовано першим відліком */
} ema_t;

void ema_init(ema_t *f, float alpha) {
    f->alpha  = alpha;
    f->primed = false;            /* y задамо першим же відліком */
}

float ema_step(ema_t *f, float x) {
    if (!f->primed) {             /* старт біля істини, не від нуля */
        f->y = x;
        f->primed = true;
    } else {
        f->y += f->alpha * (x - f->y);   /* одне множення, одне додавання */
    }
    return f->y;
}
```

Коефіцієнт α не підбирають на око. Якщо звичніше думати «вікном» — згладжувати «як вікно N» дає α ≈ 2/(N+1):

```
вікно N = 20  →  α ≈ 2 / (20 + 1) ≈ 0.0952 ≈ 0.1
```

Тепер ціле ядро без коми. Тримаємо оцінку зсунутою вліво на `Q` біт (формат Qx.Q): справжнє значення — це `acc >> Q`, а дробові біти всередині `acc` накопичують ті самі крихітні кроки, що в коми округлилися б у нуль. Коефіцієнт задаємо як цілий чисельник `a_num` зі знаменником 256 (тобто α = a_num/256):

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define EMA_Q 8                  /* стільки дробових біт тримає acc */

typedef struct {
    int32_t acc;                 /* оцінка у форматі з фіксованою комою (<<Q) */
    int32_t a_num;               /* α = a_num / 256                           */
    bool    primed;
} ema_fx_t;

void ema_fx_init(ema_fx_t *f, int32_t a_num) {  /* напр. a_num=26 ≈ α 0.1 */
    f->a_num  = a_num;
    f->primed = false;
}

int32_t ema_fx_step(ema_fx_t *f, int32_t x) {
    if (!f->primed) {
        f->acc = x << EMA_Q;                 /* старт першим відліком */
        f->primed = true;
    } else {
        int32_t err = (x << EMA_Q) - f->acc; /* різниця у тому ж масштабі */
        f->acc += (f->a_num * err) >> 8;     /* + α·(x − y), знаменник 256 */
    }
    return f->acc >> EMA_Q;                   /* назовні — звичайне число */
}
```
```cpp
#include <cstdint>

class EmaFx {
    static constexpr int Q = 8;      // стільки дробових біт тримає acc
    std::int32_t acc = 0;            // оцінка у форматі з фіксованою комою (<<Q)
    std::int32_t a_num;              // α = a_num / 256
    bool primed = false;

public:
    explicit EmaFx(std::int32_t num) : a_num(num) {}  // напр. num=26 ≈ α 0.1

    std::int32_t step(std::int32_t x) {
        if (!primed) {
            acc = x << Q;                    // старт першим відліком
            primed = true;
        } else {
            std::int32_t err = (x << Q) - acc;  // різниця у тому ж масштабі
            acc += (a_num * err) >> 8;          // + α·(x − y), знаменник 256
        }
        return acc >> Q;                     // назовні — звичайне число
    }
};
```

Чому це не застрягає, а наївний цілий EMA застрягає? Наївний рахує `y += (a_num*(x − y))/256` просто в цілих: коли різниця `x − y` мала, добуток `a_num*(x − y)` менший за 256, ціле ділення дає нуль, і оцінка завмирає за кілька одиниць від мети — назавжди. Тут же різниця й оцінка живуть зсунутими на `Q` біт, тож «нуль» настає аж на роздільній здатності `1 >> Q`, а не `1`; крок лишається ненульовим набагато довше, і фільтр доходить.

Якщо α взяти степенем половини, чисельник зникає зовсім — лишається голий зсув. Це найдешевший EMA, який існує:

:::tabs
```c
/* EMA без жодного множення: α = 1/2^SHIFT (напр. SHIFT=3 → α=1/8). */
#define EMA_SHIFT 3

static int32_t ema_pow2(int32_t y, int32_t x) {
    return y + ((x - y) >> EMA_SHIFT);   /* одне віднімання, зсув, додавання */
}
```
```cpp
// EMA без жодного множення: α = 1/2^SHIFT (напр. SHIFT=3 → α=1/8).
constexpr int EMA_SHIFT = 3;

constexpr std::int32_t ema_pow2(std::int32_t y, std::int32_t x) {
    return y + ((x - y) >> EMA_SHIFT);   // одне віднімання, зсув, додавання
}
```

Один зсув замість множення — саме тому в кволих прошивках α так часто дорівнює 1/8 чи 1/16, а не 0.1.

Тепер два корисні розширення. **Подвійне EMA** додає окрему оцінку **тренду** — куди й як швидко повзе величина, — щоб не відставати від рівномірного руху (одиночний EMA на лінійно наростальному сигналі завжди тягнеться позаду сталим відставанням; оцінка тренду це відставання компенсує):

:::tabs
```c
typedef struct {
    float level, trend;          /* оцінка рівня й оцінка тренду */
    float alpha, beta;           /* α — для рівня, β — для тренду */
    bool  primed;
} dema_t;

float dema_step(dema_t *f, float x) {
    if (!f->primed) {
        f->level = x; f->trend = 0.0f; f->primed = true;
        return f->level;
    }
    float prev = f->level;
    f->level += f->alpha * (x - f->level) + f->trend;       /* рівень + хід тренду */
    f->trend += f->beta  * ((f->level - prev) - f->trend);  /* оновлюємо сам тренд */
    return f->level;
}
```
```cpp
struct Dema {
    float alpha, beta;           // α — для рівня, β — для тренду
    float level = 0.0f;          // оцінка рівня
    float trend = 0.0f;          // оцінка тренду
    bool  primed = false;

    Dema(float a, float b) : alpha(a), beta(b) {}

    float step(float x) {
        if (!primed) {
            level = x; trend = 0.0f; primed = true;
            return level;
        }
        float prev = level;
        level += alpha * (x - level) + trend;        // рівень + хід тренду
        trend += beta  * ((level - prev) - trend);   // оновлюємо сам тренд
        return level;
    }
};
```
```python
class Dema:
    def __init__(self, alpha, beta):
        self.alpha = alpha        # α — для рівня
        self.beta = beta          # β — для тренду
        self.level = None         # оцінка рівня
        self.trend = 0.0          # оцінка тренду

    def step(self, x):
        if self.level is None:
            self.level = x
            self.trend = 0.0
            return self.level
        prev = self.level
        self.level += self.alpha * (x - self.level) + self.trend      # рівень + хід тренду
        self.trend += self.beta * ((self.level - prev) - self.trend)  # оновлюємо сам тренд
        return self.level
```
:::

**Адаптивна α** елегантно обходить головний компроміс EMA. Ідея: стежити за різницею (x − y). Поки вона мала (давач спокійний) — тримати α малою й сильно згладжувати; щойно різниця підскочила (величина різко змінилась) — тимчасово збільшити α, щоб спритно встигнути за подією, і знову опустити, коли вляжеться:

:::tabs
```c
float ema_adaptive_step(ema_t *f, float x, float scale) {
    if (!f->primed) { f->y = x; f->primed = true; return f->y; }
    float err = x - f->y;
    float d   = err < 0 ? -err : err;          /* |x − y| */
    float a   = d / (d + scale);               /* мала різниця → мала α; велика → α→1 */
    f->y += a * err;
    return f->y;
}
```
```cpp
float ema_adaptive_step(Ema &f, float x, float scale) {
    if (!f.primed) { f.y = x; f.primed = true; return f.y; }
    float err = x - f.y;
    float d   = std::abs(err);                 // |x − y|
    float a   = d / (d + scale);               // мала різниця → мала α; велика → α→1
    f.y += a * err;
    return f.y;
}
```
```python
def ema_adaptive_step(f, x, scale):
    if f.y is None:
        f.y = x
        return f.y
    err = x - f.y
    d = abs(err)                               # |x − y|
    a = d / (d + scale)                        # мала різниця → мала α; велика → α→1
    f.y += a * err
    return f.y
```
:::

Тут `scale` задає, яка різниця вважається «великою»: при `d == scale` коефіцієнт виходить рівно 0.5. Так фільтр сам перемикається між «гладко в спокої» і «швидко на події», рухаючись по шкалі, замість сидіти в одній точці.

## Пастки

**Старт із нуля.** Найчастіша й найпомітніша. Якщо не ініціалізувати оцінку першим відліком, перші кроки фільтр повзтиме від нуля до справжнього значення й видаватиме дурниці саме тоді, коли давач щойно ввімкнули і його показам найбільше вірять. Завжди кладіть перший відлік прямо в оцінку (прапорець `primed`).

**Застрягання в цілих.** Якщо рахувати EMA просто в цілих без дробового масштабу, крок α·(x − y) при малій різниці округлиться в нуль, і оцінка завмре за кілька одиниць від мети назавжди. Лік один — тримати оцінку у форматі з фіксованою комою (зсунутою на `Q` біт), як у `ema_fx_step`, щоб дробові кроки накопичувалися.

**Переповнення акумулятора.** У цілому варіанті `x << EMA_Q` і добуток `a_num * err` мають уміститися в `int32_t`. Прикиньте найбільший можливий відлік: якщо `x` буває близько 2²³, то після зсуву на 8 він уже впритул до межі. За потреби беріть ширший тип або менший `Q`.

**α поза діапазоном.** Коефіцієнт мусить лежати в (0, 1]. α ≥ 1 (чи від'ємна) — це вже не згладжування: фільтр або точно повторює вхід, або розгойдується. У цілому записі це означає `a_num` у (0, 256].

**EMA не вбиває викиди.** Фільтр лінійний (у мові фільтрів — рекурсивний, [IIR](book:algorithms/iir-filter)), тож один дикий відлік підштовхне оцінку й лишатиме слід, поки той не згасне. Якщо в потоці бувають спайки — ставте EMA **після** [медіани](book:algorithms/median-filter), а не замість неї. Особливо це стосується адаптивної α: великий викид вона може сприйняти за «подію» й кинутися за ним, тож її теж прикривають медіаною.

**Спільний стан на кілька каналів.** Фільтруєте три осі акселерометра — заведіть **окремий** `ema_t` (окремий стан) на кожну вісь. Один спільний стан змішає канали й дасть химерний результат, який важко діагностувати.

Зробивши все це — старт першим відліком, дробовий масштаб у цілих, звірений діапазон α і медіана попереду проти спайків — ви отримаєте фільтр, що коштує одну змінну й одне множення (а то й самий зсув), доходить до істини без застрягання й чесно згладжує роками, не вимагаючи ні буфера, ні турботи.
