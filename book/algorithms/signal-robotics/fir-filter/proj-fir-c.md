# ⚙️ КІХ на C: кільцевий буфер, симетрія і ціла арифметика

## Задача

Згортка КІХ — це один цикл множень-додавань, і написати його «в лоб» уміє кожен. Та між навчальним циклом і модулем, який щотакту крутиться в перериванні АЦП, лежить кілька рішень, кожне з яких колись комусь коштувало годин. Потрібен самодостатній КІХ на C, який можна викликати з переривання на 1–48 кГц і бути певним, що: новий відлік додається **однією** операцією (без зсуву масиву), симетрія коефіцієнтів **ділить множення навпіл**, а проміжна сума **не переповнюється** на цілій арифметиці. Зробимо дві версії — чисту `float` (коли є FPU) і `Q15` на цілих (коли FPU немає), бо саме вибір між ними найчастіше й постає на дешевому МК.

## Ідея

Фільтр має пам'ять: між тактами живуть `M+1` останніх відліків. Тримати їх у масиві, який щотакту зсувається, — марнотратство: зсув `N` елементів коштує `N` записів. Натомість заведемо **кільцевий буфер** — масив плюс індекс «голови»; новий відлік перезаписує найстарішу комірку, а голова просувається по колу за модулем розміру. Додавання відліку стає однією операцією незалежно від довжини фільтра.

Друга ідея — **симетрія**. Лінійно-фазовий КІХ має дзеркальні коефіцієнти (`b[k] = b[M−k]`), тож пару дзеркальних відліків можна **додати до** множення й помножити суму на один спільний коефіцієнт. Виходить удвічі менше множень — а множення на МК без апаратного множника якраз найдорожче.

Третя, найпідступніша, — **переповнення**. Коли коефіцієнти й відліки тримають цілими (формат `Q15`: дробове число в діапазоні [−1, 1) кодуємо як `int16`, множачи на 2¹⁵), добуток двох `int16` уже не влазить у `int16`. Сумувати треба в **ширшому** регістрі — `int32` чи `int64`, — інакше сума тихо «загорнеться» й вихід стрибне. Тому акумулятор завжди ширший за відліки, а результат стискаємо назад зсувом лише наприкінці.

## Код

Спершу `float`-версія з кільцевим буфером — коли FPU є, вона найпрозоріша:

:::tabs
```cpp
#include <stdint.h>

#define NTAPS 31                 /* непарне: є центральний відвід */

typedef struct {
    float  b[NTAPS];             /* коефіцієнти (імпульсна характеристика) */
    float  buf[NTAPS];           /* кільцевий буфер відліків */
    int    head;                 /* індекс найновішого відліку */
} FirF;

void firf_init(FirF *f, const float *taps)
{
    for (int i = 0; i < NTAPS; i++) { f->b[i] = taps[i]; f->buf[i] = 0.0f; }
    f->head = 0;
}

float firf_step(FirF *f, float x)
{
    f->buf[f->head] = x;                 /* новий відлік у голову */

    float acc = 0.0f;
    int idx = f->head;
    for (int k = 0; k < NTAPS; k++) {
        acc += f->b[k] * f->buf[idx];    /* згортка b[k]·x[n−k] */
        idx = (idx == 0) ? NTAPS - 1 : idx - 1;   /* назад по колу */
    }

    f->head = (f->head + 1) % NTAPS;     /* голова — вперед по колу */
    return acc;
}
```
```python
NTAPS = 31                       # непарне: є центральний відвід

class FirF:
    def __init__(self, taps):
        self.b = list(taps)            # коефіцієнти (імпульсна характеристика)
        self.buf = [0.0] * NTAPS       # кільцевий буфер відліків
        self.head = 0                  # індекс найновішого відліку

    def step(self, x):
        self.buf[self.head] = x        # новий відлік у голову

        acc = 0.0
        idx = self.head
        for k in range(NTAPS):
            acc += self.b[k] * self.buf[idx]      # згортка b[k]·x[n−k]
            idx = NTAPS - 1 if idx == 0 else idx - 1   # назад по колу

        self.head = (self.head + 1) % NTAPS        # голова — вперед по колу
        return acc
```
:::

Тепер симетрія. Дзеркальні відліки складаємо **до** множення — і робимо вдвічі менше множень. Щоб не блукати кільцем туди-сюди, тут зручніше тримати лінійний буфер зі зсувом (для коротких фільтрів зсув дешевший за подвійну індексацію по колу):

:::tabs
```cpp
/* лінійно-фазовий КІХ: buf[0] — найновіший, buf[NTAPS-1] — найстаріший */
float firf_sym_step(FirF *f, float x)
{
    for (int i = NTAPS - 1; i > 0; i--)  /* зсув на один (короткий фільтр) */
        f->buf[i] = f->buf[i - 1];
    f->buf[0] = x;

    float acc = 0.0f;
    int half = NTAPS / 2;
    for (int k = 0; k < half; k++)
        acc += f->b[k] * (f->buf[k] + f->buf[NTAPS - 1 - k]);  /* пара на один множник */
    acc += f->b[half] * f->buf[half];    /* центральний відвід — окремо */
    return acc;
}
```
```python
def firf_sym_step(f, x):
    """лінійно-фазовий КІХ: buf[0] — найновіший, buf[NTAPS-1] — найстаріший"""
    f.buf[1:] = f.buf[:-1]           # зсув на один (короткий фільтр)
    f.buf[0] = x

    acc = 0.0
    half = NTAPS // 2
    for k in range(half):
        acc += f.b[k] * (f.buf[k] + f.buf[NTAPS - 1 - k])   # пара на один множник
    acc += f.b[half] * f.buf[half]   # центральний відвід — окремо
    return acc
```

І `Q15`-версія для МК без FPU. Тут уся суть — у **ширині акумулятора**: `int16 × int16 → int32`, сума в `int64`, стиск назад на 15 біт лише наприкінці:

:::tabs
```cpp
#include <stdint.h>

#define QSHIFT 15                /* формат Q15: 1.0 == 32768 */

typedef struct {
    int16_t b[NTAPS];            /* коефіцієнти у Q15 */
    int16_t buf[NTAPS];
    int     head;
} FirQ;

int16_t firq_step(FirQ *f, int16_t x)
{
    f->buf[f->head] = x;

    int64_t acc = 0;             /* ширший за відліки — проти переповнення */
    int idx = f->head;
    for (int k = 0; k < NTAPS; k++) {
        acc += (int32_t)f->b[k] * (int32_t)f->buf[idx];   /* int16·int16 → int32 */
        idx = (idx == 0) ? NTAPS - 1 : idx - 1;
    }
    f->head = (f->head + 1) % NTAPS;

    acc >>= QSHIFT;              /* стиск Q15 назад у масштаб відліків */
    if (acc >  32767) acc =  32767;       /* насичення замість загортання */
    if (acc < -32768) acc = -32768;
    return (int16_t)acc;
}
```
```python
QSHIFT = 15                      # формат Q15: 1.0 == 32768

class FirQ:
    def __init__(self, taps):
        self.b = list(taps)            # коефіцієнти у Q15
        self.buf = [0] * NTAPS
        self.head = 0

    def step(self, x):
        self.buf[self.head] = x

        acc = 0                        # Python int безмежний — проти переповнення
        idx = self.head
        for k in range(NTAPS):
            acc += self.b[k] * self.buf[idx]    # int16·int16 → широкий int
            idx = NTAPS - 1 if idx == 0 else idx - 1
        self.head = (self.head + 1) % NTAPS

        acc >>= QSHIFT                 # стиск Q15 назад у масштаб відліків
        if acc >  32767: acc =  32767  # насичення замість загортання
        if acc < -32768: acc = -32768
        return acc
```
:::

## Числовий прогон одного такту

Перевіримо `Q15`-крок на симетричному 3-відводі `(0.25, 0.5, 0.25)`. У Q15 ці ваги — `b = {8192, 16384, 8192}` (бо `0.25·32768 = 8192`). Подамо відліки `x[n]=6, x[n−1]=8, x[n−2]=4` (цілі АЦП-відліки, не дробові):

```c
acc  = 8192·6 + 16384·8 + 8192·4
     = 49152  + 131072   + 32768
     = 212992                          /* int32: влізло з величезним запасом */

acc >>= 15  →  212992 / 32768 = 6      /* = 6.5, обрізане вниз до 6 */
```

Та сама `6.5`, що й у дробовому прикладі, лише стиснута назад у ціле (`>> 15` округлює вниз — тому `6`, не `6.5`; для симетричного округлення додають `1 << (QSHIFT−1)` **перед** зсувом). Головне видно інакше: проміжна сума `212992` далеко переросла діапазон `int16` (`±32768`) — якби акумулятор був `int16`, вона б загорнулась і вихід стрибнув би в безглуздя. Саме ширший `acc` і рятує.

## Пастки

- **Вузький акумулятор.** Найтиповіша пастка цілого КІХ: добуток `int16·int16` тримають в `int16` чи `int` неясної ширини — і довга сума мовчки переповнюється. Акумулятор має бути явно `int32` (а для довгих фільтрів чи Q31 — `int64`); підсумок стискають зсувом **лише наприкінці**. Детальніше про вибір масштабу — у [реалізації fixed-point](book:algorithms/fixed-point-implementation).
- **Загортання замість насичення.** Коли результат таки виходить за діапазон, «голий» зсув дає загортання (велике додатне раптом стає від'ємним) — клац у звуці, стрибок у керуванні. Завжди **насичуйте** результат до меж типу, як у `firq_step`.
- **Збитий порядок у кільці.** У кільцевому буфері легко переплутати напрям обходу: голова рухається **вперед**, а відліки для згортки читаються **назад** від голови (`x[n], x[n−1], …`). Помилка тут не валить програму — вона тихо дає дзеркальну імпульсну характеристику, а отже зіпсовану фазу. Перевірте імпульсом: на вхід `1, 0, 0, …` модуль має видати рівно `b[]` у правильному порядку.
- **Симетрія без центрального відводу.** Згортаючи симетричний фільтр парами, не забудьте окремо додати **центральний** коефіцієнт у фільтрі непарної довжини — інакше один відвід просто випаде, і підсилення поїде. Для парної довжини центрального немає, цикл іде до `NTAPS/2` без додатку.
- **Зсув масиву в довгому фільтрі.** Версія `firf_sym_step` зсуває буфер щотакту — це дешево лише для коротких фільтрів. Від кількох десятків відводів зсув `N` елементів дорожчий за саму згортку; там беріть кільцевий буфер (як у `firf_step`), а симетрію реалізуйте подвійною індексацією по колу від обох кінців.
