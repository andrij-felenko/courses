# ⚙️ Біквад-каскад на C

**Задача.** Треба гострий цифровий фільтр на мікроконтролері — скажімо, вирізати мережеві 50 Гц або згладити шум гіроскопа смугою нижніх частот — і вкластися в кілька множень на відлік. Інструмент проєктування вже видав коефіцієнти БІХ-фільтра 4-го чи 6-го порядку. Лишилося перетворити ці числа на код, що **стабільно** працює на залізі й не вибухає від похибок арифметики. Зробімо це правильно з першого разу.

## Ідея: ланцюжок ланок 2-го порядку

Спокуса написати БІХ високого порядку однією довгою формулою — пряма дорога до нестабільності. У такій формулі полюси сидять близько один до одного, і найменша зміна коефіцієнта (а ціла арифметика округлює кожен) зрушує їх із місця; кілька зрушень — і фільтр, що мав згасати, починає розгойдуватися. Тому реальний БІХ **завжди розбивають на ланки 2-го порядку — біквади** (*bi-quadratic*, «двічі квадратичний»: і чисельник, і знаменник передавальної функції — квадратні многочлени). Кожна ланка має лише два полюси, вони стоять далеко й до округлення майже байдужі.

Один біквад — це п'ять коефіцієнтів і п'ять множень:

```
y[n] = b₀·x[n] + b₁·x[n−1] + b₂·x[n−2]  −  a₁·y[n−1] − a₂·y[n−2]
```

Складніший фільтр будуємо **каскадом**: вихід одного біквада йде на вхід наступного. Фільтр 6-го порядку — це три біквади поспіль, кожен зі своїм набором п'яти коефіцієнтів. Саме так подають БІХ і всі серйозні бібліотеки (CMSIS-DSP, scipy `sos` — «second-order sections»). Наша робота — акуратно перенести коефіцієнти й правильно вести стан кожної ланки.

Чому розбиття на ланки взагалі рятує? Полюси фільтра — це корені знаменника його передавальної функції. У формулі високого порядку знаменник — многочлен великого степеня, а корені многочлена **надзвичайно чутливі** до коефіцієнтів: зсунь один коефіцієнт на тисячну — і пара полюсів стрибне помітно вбік, бо помилка в коефіцієнтах множиться на величезну похідну кореня. У біквада ж знаменник лише квадратний; його два корені від дрібних змін коефіцієнтів майже не рухаються. Розбивши фільтр на квадратні ланки, ми **розв'язуємо полюси між собою** — кожна пара живе у своїй ланці й не тягне за собою решту. Тому каскад біквадів зберігає задуману характеристику навіть тоді, коли коефіцієнти грубо заокруглені під цілу арифметику, а еквівалентна «довга» формула в тих самих умовах давно б розповзлася.

## Одна ланка: пряма форма I

Біквад можна реалізувати кількома способами («формами»), що математично тотожні, але по-різному поводяться з похибками. Для мікроконтролера, де часто рахують у цілих, найнадійніша — **пряма форма I** (*Direct Form I*): вона тримає окрему пам'ять для двох минулих входів і двох минулих виходів і має ширший запас на проміжні суми, тож стійкіша до переповнення й округлення. (Поширена пряма форма II ощадливіша на пам'ять — лише дві комірки стану замість чотирьох, — але вимагає більшого динамічного діапазону проміжних величин; саме тому в CMSIS-DSP цілочислові біквади Q15/Q31 зроблено на прямій формі I, а форму II лишено тільки для чисел із комою, що пливе.)

Ось одна ланка в коді. Стан — два минулі входи й два минулі виходи; усе чесно й наочно:

:::tabs
```c
#include <stddef.h>

// Один біквад, пряма форма I. Стан — два минулі входи й два минулі виходи.
typedef struct {
    float b0, b1, b2;     // коефіцієнти прямої гілки (входи)
    float a1, a2;         // коефіцієнти зворотної гілки (виходи), УЖЕ зі знаком «−»
    float x1, x2;         // x[n-1], x[n-2]
    float y1, y2;         // y[n-1], y[n-2]
} biquad_t;

float biquad_step(biquad_t *s, float x) {
    float y = s->b0 * x  + s->b1 * s->x1 + s->b2 * s->x2
                         - s->a1 * s->y1 - s->a2 * s->y2;   // 5 множень
    // зсуваємо лінії затримки на один такт
    s->x2 = s->x1;  s->x1 = x;
    s->y2 = s->y1;  s->y1 = y;
    return y;
}
```
```cpp
// Один біквад, пряма форма I. Стан — два минулі входи й два минулі виходи.
struct Biquad {
    float b0, b1, b2;     // коефіцієнти прямої гілки (входи)
    float a1, a2;         // коефіцієнти зворотної гілки (виходи), УЖЕ зі знаком «−»
    float x1 = 0, x2 = 0; // x[n-1], x[n-2]
    float y1 = 0, y2 = 0; // y[n-1], y[n-2]

    float step(float x) {
        float y = b0 * x  + b1 * x1 + b2 * x2
                          - a1 * y1 - a2 * y2;   // 5 множень
        // зсуваємо лінії затримки на один такт
        x2 = x1;  x1 = x;
        y2 = y1;  y1 = y;
        return y;
    }
};
```
```python
from dataclasses import dataclass

# Один біквад, пряма форма I. Стан — два минулі входи й два минулі виходи.
@dataclass
class Biquad:
    b0: float; b1: float; b2: float   # коефіцієнти прямої гілки (входи)
    a1: float; a2: float              # коефіцієнти зворотної гілки, УЖЕ зі знаком «−»
    x1: float = 0.0; x2: float = 0.0  # x[n-1], x[n-2]
    y1: float = 0.0; y2: float = 0.0  # y[n-1], y[n-2]

    def step(self, x: float) -> float:
        y = (self.b0 * x  + self.b1 * self.x1 + self.b2 * self.x2
                          - self.a1 * self.y1 - self.a2 * self.y2)   # 5 множень
        # зсуваємо лінії затримки на один такт
        self.x2 = self.x1;  self.x1 = x
        self.y2 = self.y1;  self.y1 = y
        return y
```
:::

Зверніть увагу на знаки в `biquad_step`: зворотні доданки **віднімаються** (`- a1*y1 - a2*y2`). Це найзвичніша пастка, до якої повернемося нижче: різні інструменти віддають `a1, a2` із протилежним знаком, і якщо не узгодити їх із цією формулою, фільтр поведеться зовсім не так, як замовляли.

## Каскад: ланцюжок біквадів

Каскад — це масив ланок, через який відлік проходить одна по одній. Нічого складного: вихід попередньої стає входом наступної.

:::tabs
```c
typedef struct {
    biquad_t *stage;      // масив ланок
    size_t    n;          // скільки їх
} biquad_chain_t;

float chain_step(biquad_chain_t *c, float x) {
    float v = x;
    for (size_t i = 0; i < c->n; ++i)
        v = biquad_step(&c->stage[i], v);   // вихід однієї → вхід наступної
    return v;
}
```
```cpp
#include <vector>

struct BiquadChain {
    std::vector<Biquad> stage;   // масив ланок

    float step(float x) {
        float v = x;
        for (auto &s : stage)
            v = s.step(v);       // вихід однієї → вхід наступної
        return v;
    }
};
```
```python
class BiquadChain:
    def __init__(self, stages: list[Biquad]):
        self.stage = stages      # масив ланок

    def step(self, x: float) -> float:
        v = x
        for s in self.stage:
            v = s.step(v)        # вихід однієї → вхід наступної
        return v
```
:::

Коефіцієнти кожної ланки ви не рахуєте руками — їх видає інструмент проєктування за вашою специфікацією (тип фільтра, порядок, частоти зрізу, частота дискретизації). Лишається заповнити масив. Скажімо, фільтр нижніх частот 4-го порядку — це дві ланки:

:::tabs
```c

    { .b0=1.0000f, .b1=2.0000f, .b2=1.0000f, .a1=-1.1430f, .a2=0.4128f },

static biquad_chain_t lp = { .stage = lp4, .n = 2 };

float v = chain_step(&lp, sample);   // один відфільтрований відлік
```

Стан кожної ланки (`x1, x2, y1, y2`) обов'язково обнуліть на старті — інакше перші відліки порахуються від випадкового сміття в пам'яті, і фільтр почне з кидка. Для статичних змінних це робить нуль за замовчуванням, але звичку **явно ініціалізувати стан** варто мати завжди.

## Перевірка стабільності: подати імпульс

Перш ніж довіряти фільтру реальні дані, переконайтеся, що він **згасає**. Найпростіший і найнадійніший тест — подати одиничний імпульс (`1`, далі самі нулі) і подивитися на хвіст: у стабільного фільтра вихід прямує до нуля, у нестабільного — наростає або дзвенить без кінця.

:::tabs
```c
void biquad_reset_chain(biquad_chain_t *c) {
    for (size_t i = 0; i < c->n; ++i) {
        c->stage[i].x1 = c->stage[i].x2 = 0.0f;
        c->stage[i].y1 = c->stage[i].y2 = 0.0f;
    }
}

// Повертає 1, якщо хвіст згас (фільтр стабільний), інакше 0.
int biquad_is_stable(biquad_chain_t *c) {
    biquad_reset_chain(c);
    float out = chain_step(c, 1.0f);              // імпульс
    float peak = (out < 0 ? -out : out);
    for (int n = 1; n < 1000; ++n) {
        out = chain_step(c, 0.0f);               // далі — нулі
        float m = (out < 0 ? -out : out);
        if (m > peak) peak = m;
        if (m > 1e6f) { biquad_reset_chain(c); return 0; }  // вибухає
    }
    biquad_reset_chain(c);
    return (out < 1e-3f && out > -1e-3f);         // хвіст справді згас
}
```
```cpp
void reset(BiquadChain &c) {
    for (auto &s : c.stage) {
        s.x1 = s.x2 = 0.0f;
        s.y1 = s.y2 = 0.0f;
    }
}

// Повертає true, якщо хвіст згас (фільтр стабільний), інакше false.
bool is_stable(BiquadChain &c) {
    reset(c);
    float out = c.step(1.0f);                     // імпульс
    float peak = std::abs(out);
    for (int n = 1; n < 1000; ++n) {
        out = c.step(0.0f);                      // далі — нулі
        peak = std::max(peak, std::abs(out));
        if (std::abs(out) > 1e6f) { reset(c); return false; }  // вибухає
    }
    reset(c);
    return std::abs(out) < 1e-3f;                 // хвіст справді згас
}
```
```python
def reset(c: BiquadChain) -> None:
    for s in c.stage:
        s.x1 = s.x2 = 0.0
        s.y1 = s.y2 = 0.0

# Повертає True, якщо хвіст згас (фільтр стабільний), інакше False.
def is_stable(c: BiquadChain) -> bool:
    reset(c)
    out = c.step(1.0)                     # імпульс
    peak = abs(out)
    for _ in range(1, 1000):
        out = c.step(0.0)                 # далі — нулі
        peak = max(peak, abs(out))
        if abs(out) > 1e6:                # вибухає
            reset(c)
            return False
    reset(c)
    return abs(out) < 1e-3               # хвіст справді згас
```
:::

Цей тест ловить найгірше: каскад, що розганяється через переплутані знаки коефіцієнтів, помилку в порядку ланок чи похибку квантування, яка зрушила полюс за одиничне коло. Проганяти його варто **на самому залізі**, бо в цілій арифметиці фільтр може бути стабільним на ПК (де рахунок іде в числах із комою, що пливе) і нестабільним на чипі — нестабільність любить ховатися саме там.

## Пастки

**Знак коефіцієнтів `a`.** Найчастіша причина «дивної» поведінки щойно перенесеного фільтра. Формула біквада існує у двох записах: з **відніманням** зворотних доданків (`y = … − a1·y1 − a2·y2`, як у нас і в CMSIS-DSP) і з **додаванням** (`y = … + a1·y1 + a2·y2`). Інструменти й бібліотеки віддають `a1, a2` під «свій» запис. Якщо взяти коефіцієнти, розраховані під додавання, і підставити у формулу з відніманням (чи навпаки), полюси опиняться не там — у кращому разі АЧХ поїде, у гіршому фільтр піде в розгін. Завжди звіряйте, під яку угоду про знак видано числа, і за потреби інвертуйте `a1, a2`.

**Порядок ланок і масштаб.** У цілій арифметиці порядок біквадів у каскаді **впливає** на результат: одна послідовність ланок переповнюється на проміжній сумі, інша — ні. Інструменти, що дають `sos`, зазвичай уже впорядковують ланки й розкидають коефіцієнт підсилення між ними так, щоб ніде не вилетіти за діапазон. Не переставляйте ланки навмання й не зливайте все підсилення в одну ланку — це найкоротший шлях до переповнення.

**Стан на ввімкненні.** Неочищений стан (`x1,x2,y1,y2` зі сміттям) дає кидок на перших відліках, а в інтегрувальних структурах кидок може довго відлунювати. Обнуляйте стан при старті й після будь-якого розриву потоку даних (зміна режиму, перепідключення давача).

**Накопичення в цілих.** Кожне множення `1.31 × 1.31` дає довший результат, який десь треба зберегти без втрати точності. Робіть проміжні суми в **ширшому** акумуляторі (32→64 біти або апаратний акумулятор DSP-розширення) і насичуйте (`saturate`), а не дозволяйте переповненню «загорнутися» — загортання миттєво перетворює стабільний фільтр на генератор шуму. Готові цілочислові біквади з CMSIS-DSP уже роблять це правильно; якщо пишете самі — повторіть їхній підхід, а не винаходьте свій.

**Один спільний стан на кілька каналів.** Якщо фільтруєте кілька сигналів (три осі гіроскопа) тим самим набором коефіцієнтів — заведіть **окремий** `biquad_chain_t` (окремий стан) на кожен канал. Спільний стан змішає канали й дасть химерний результат, який важко діагностувати.

**Коефіцієнти беруться з інструмента, не з голови.** Жодне з п'яти чисел ланки не варто підбирати на око. У scipy це один рядок — `scipy.signal.iirfilter(N, Wn, btype=…, ftype='butter', output='sos')` віддає масив рядків по шість чисел (`b0, b1, b2, 1, a1, a2`); ви переносите по п'ять із кожного рядка в окрему `biquad_t`, пам'ятаючи, що scipy записує знаменник із **додаванням**, тож `a1, a2` у форму з відніманням переходять зі зміною знака. У світі STM32 ту саму роль грає графічний майстер у CubeMX або готові таблиці в CMSIS-DSP. Хоч би звідки прийшли числа, останнє слово — за тестом імпульсом на залізі: він мовчки підтвердить, що перенесення вдалося, або одразу викриє переплутаний знак чи загублену ланку.

Зробивши все це — каскад коротких ланок, пряма форма I, звірені знаки, чистий стан і перевірка імпульсом — ви отримаєте БІХ, що дає гострий зріз за кілька множень на відлік і роками працює в полі, не дзвенячи й не розганяючись.
