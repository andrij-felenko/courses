# ⚙️ Кодек Гаффмана на C: від частот до бітів і назад

## Задача

Алгоритм Гаффмана легко описати й легко зіпсувати на реалізації. Між «побудувати дерево» й «робочим кодеком, що тисне файл і розтискає його байт-у-байт» лежить службова обв'язка, на якій спотикаються всі: як **писати окремі біти** в потік байтів і дочитувати останній неповний байт; як **передати декодеру дерево**, не змарнувавши на заголовок весь виграш; як **декодувати** без повільного спуску деревом на кожен біт; що робити з **єдиним** символом у вході (дерево з одного листка) і з **порожнім** входом. Мета — цілісний, компільований кодек на C, який стискає довільний потік байтів і точно його відновлює, з канонічним заголовком і табличним декодером, придатний і для файлу на ПК, і для скромного процесора. Усе коротке, без зовнішніх залежностей і чесно доведене до кінця.

## Ідея

Кодек стоїть на трьох опорах. Перша — **бітовий ввід-вивід**: дані Гаффмана не вирівняні на байти, тож потрібні два дрібні автомати, що накопичують біти в проміжному регістрі й висипають/набирають байти, коли регістр повний чи порожній. Друга — **канонічний код**: замість пересилати дерево ми передаємо в заголовку лише **довжину коду кожного символу** (один байт на символ), а обидві сторони відновлюють із цих довжин **ті самі** коди за фіксованим правилом — символи в порядку (довжина, потім символ) дістають послідовні двійкові числа. Третя — **табличний декодер**: із канонічних довжин будуємо таблицю, що за вікном біт одразу віддає символ і його довжину, тож декодування йде символами, а не побітово.

Дві дрібниці рятують від типових збоїв. Єдиний символ у вході дав би дерево з одного вузла й код довжини нуль — нонсенс; тому такому символу примусово призначаємо довжину 1. А щоб декодер знав, **де спинитися** (останній байт майже завжди доповнений сміттєвими бітами), пишемо в заголовок точну кількість символів вхідного потоку й декодуємо рівно стільки.

## Код

### Бітовий потік

Пишемо й читаємо біти через проміжний 32-бітовий буфер. Писач накопичує біти від старших до молодших і висипає готові байти; наприкінці доповнює останній байт нулями:

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    uint8_t *buf;        /* вихідний буфер           */
    size_t   cap, len;   /* місткість і заповнення    */
    uint32_t acc;        /* накопичувач біт           */
    int      nbits;      /* скільки біт в acc (0..31) */
} bitw_t;

static void bw_init(bitw_t *w, uint8_t *buf, size_t cap) {
    w->buf = buf; w->cap = cap; w->len = 0; w->acc = 0; w->nbits = 0;
}

static void bw_put(bitw_t *w, uint32_t bits, int n) {  /* записати n молодших біт */
    w->acc |= (bits & ((n == 32) ? 0xFFFFFFFFu : ((1u << n) - 1))) << (32 - n - w->nbits);
    w->nbits += n;
    while (w->nbits >= 8) {
        if (w->len < w->cap) w->buf[w->len++] = (uint8_t)(w->acc >> 24);
        w->acc <<= 8;
        w->nbits -= 8;
    }
}

static void bw_flush(bitw_t *w) {                      /* доповнити останній байт */
    if (w->nbits > 0 && w->len < w->cap) {
        w->buf[w->len++] = (uint8_t)(w->acc >> 24);
        w->acc = 0; w->nbits = 0;
    }
}
```

Читач — дзеркало: підкачує байти у буфер і віддає по біту або одразу вікно з кількох біт (для табличного декодера):

```c
typedef struct {
    const uint8_t *buf;
    size_t cap, pos;
    uint32_t acc;
    int nbits;
} bitr_t;

static void br_init(bitr_t *r, const uint8_t *buf, size_t cap) {
    r->buf = buf; r->cap = cap; r->pos = 0; r->acc = 0; r->nbits = 0;
}

static void br_fill(bitr_t *r) {                       /* підкачати до >=24 біт */
    while (r->nbits <= 24 && r->pos < r->cap) {
        r->acc |= (uint32_t)r->buf[r->pos++] << (24 - r->nbits);
        r->nbits += 8;
    }
}

static uint32_t br_peek(bitr_t *r, int n) {            /* глянути n біт, не споживаючи */
    br_fill(r);
    return r->acc >> (32 - n);
}

static void br_skip(bitr_t *r, int n) {                /* спожити n біт */
    r->acc <<= n;
    r->nbits -= n;
}
```

### Побудова дерева й довжини кодів

Частоти й купа — як у базовому розборі; тут нам із дерева потрібні лише **довжини кодів** на символ (канонічний код відновить решту). Обходимо дерево, накопичуючи глибину:

```c
#define SYMS 256
#define MAXLEN 32

typedef struct {
    uint32_t freq;
    int16_t  left, right, symbol;
} node_t;

/* (huff_build з купою — як у докладному розборі; повертає індекс кореня) */
int16_t huff_build(node_t *nodes, const uint32_t *freq);   /* оголошення */

static void collect_lengths(const node_t *nodes, int16_t i, int depth, uint8_t *len) {
    if (nodes[i].symbol >= 0) {
        len[nodes[i].symbol] = (uint8_t)(depth ? depth : 1);  /* один символ → 1 біт */
        return;
    }
    collect_lengths(nodes, nodes[i].left,  depth + 1, len);
    collect_lengths(nodes, nodes[i].right, depth + 1, len);
}
```

### Канонічні коди з довжин

Маючи `len[256]`, обидві сторони будують **той самий** код. Порядок — за (довжина, символ); коди — послідовні числа з дописуванням нулів при зміні довжини. Стандартний рецепт рахує, скільки кодів кожної довжини, і стартовий код кожної довжини:

```c
typedef struct { uint32_t bits; uint8_t len; } code_t;

static void canonical_codes(const uint8_t *len, code_t *code) {
    uint32_t bl_count[MAXLEN + 1] = {0};
    for (int s = 0; s < SYMS; s++)
        if (len[s]) bl_count[len[s]]++;

    uint32_t next[MAXLEN + 1] = {0};
    uint32_t c = 0;
    for (int bits = 1; bits <= MAXLEN; bits++) {        /* стартовий код довжини bits */
        c = (c + bl_count[bits - 1]) << 1;
        next[bits] = c;
    }
    for (int s = 0; s < SYMS; s++) {                    /* роздати по порядку символів */
        if (!len[s]) { code[s].len = 0; continue; }
        code[s].bits = next[len[s]]++;
        code[s].len  = len[s];
    }
}
```

### Стиснення

Тепер ціле стиснення: частоти → дерево → довжини → канонічні коди → заголовок (кількість символів + 256 довжин) → бітовий потік:

```c
/* Повертає розмір стиснутого; out має бути достатньо великий. */
size_t huff_compress(const uint8_t *in, size_t n, uint8_t *out, size_t out_cap) {
    uint32_t freq[SYMS] = {0};
    for (size_t i = 0; i < n; i++) freq[in[i]]++;

    uint8_t len[SYMS] = {0};
    if (n > 0) {
        node_t nodes[2 * SYMS];
        int16_t root = huff_build(nodes, freq);
        collect_lengths(nodes, root, 0, len);
    }
    code_t code[SYMS];
    canonical_codes(len, code);

    /* заголовок: 4 байти довжини потоку + 256 байтів довжин кодів */
    size_t p = 0;
    out[p++] = (uint8_t)(n);       out[p++] = (uint8_t)(n >> 8);
    out[p++] = (uint8_t)(n >> 16); out[p++] = (uint8_t)(n >> 24);
    memcpy(out + p, len, SYMS); p += SYMS;

    bitw_t w; bw_init(&w, out + p, out_cap - p);
    for (size_t i = 0; i < n; i++)
        bw_put(&w, code[in[i]].bits, code[in[i]].len);
    bw_flush(&w);
    return p + w.len;
}
```

### Декодування таблицею

Декодер читає заголовок, відновлює канонічні коди (те саме `canonical_codes`) і будує **плоску таблицю** на `1 << MAXBITS` входів, де `MAXBITS` — найбільша наявна довжина коду. У кожну комірку, чий префікс дорівнює коду символу, кладемо символ і його довжину; потім декодуємо вікном:

```c
typedef struct { int16_t sym; uint8_t len; } dentry_t;

size_t huff_decompress(const uint8_t *in, size_t n_in, uint8_t *out, size_t out_cap) {
    if (n_in < 4 + SYMS) return 0;
    size_t p = 0;
    size_t n = (size_t)in[p] | ((size_t)in[p+1] << 8)
             | ((size_t)in[p+2] << 16) | ((size_t)in[p+3] << 24);
    p += 4;
    uint8_t len[SYMS];
    memcpy(len, in + p, SYMS); p += SYMS;
    if (n == 0) return 0;

    code_t code[SYMS];
    canonical_codes(len, code);

    int maxbits = 1;
    for (int s = 0; s < SYMS; s++) if (len[s] > maxbits) maxbits = len[s];

    size_t tsize = (size_t)1 << maxbits;
    dentry_t *table = (dentry_t *)malloc(tsize * sizeof(dentry_t));
    if (!table) return 0;
    for (size_t i = 0; i < tsize; i++) { table[i].sym = -1; table[i].len = 0; }

    for (int s = 0; s < SYMS; s++) {                   /* розкласти кожен код по комірках */
        if (!len[s]) continue;
        int shift = maxbits - len[s];
        size_t base = (size_t)code[s].bits << shift;   /* старші біти = код, решта вільна */
        size_t cnt  = (size_t)1 << shift;
        for (size_t k = 0; k < cnt; k++) {
            table[base + k].sym = (int16_t)s;
            table[base + k].len = len[s];
        }
    }

    bitr_t r; br_init(&r, in + p, n_in - p);
    size_t produced = 0;
    while (produced < n && produced < out_cap) {
        uint32_t window = br_peek(&r, maxbits);
        dentry_t e = table[window];
        if (e.len == 0) break;                         /* пошкоджений потік — спинитися */
        out[produced++] = (uint8_t)e.sym;
        br_skip(&r, e.len);
    }
    free(table);
    return produced;
}
```

Зверни увагу на симетрію: і кодувальник, і декодер викликають **те саме** `canonical_codes`, тож гарантовано дістають однакові коди з однакових довжин — у цьому вся суть канонічного підходу. А `n` із заголовка каже декодеру спинитися рівно на справжній кількості символів, не плутаючи доповнення останнього байта за дані.

## Пастки

**Доповнення останнього байта.** Потік Гаффмана майже ніколи не кінчається на межі байта, тож `bw_flush` доповнює хвіст нулями. Ці зайві біти можуть випадково скластися у валідний код — і декодер видасть **зайвий** символ. Лік один і надійний: зберігати точну кількість символів (`n`) у заголовку й декодувати **рівно** стільки, як тут і зроблено. Покладатися на «спеціальний символ кінця потоку» теж можна, але лічильник простіший.

**Єдиний символ у вході.** Файл із самих байтів `'A'` дав би дерево з одного листка глибини 0 — код нульової довжини, який нічого не записує, і декодер зациклиться. Тому такому символу примусово ставимо довжину 1 (`collect_lengths` і окремий випадок у `huff_build`). Тоді кожен `'A'` коштує 1 біт — не оптимально за теорією (вистачило б 0), але працює, а такий вхід і так вироджений.

**Порожній вхід.** `n == 0` мусить пройти без падіння: будувати дерево нема з чого. Обробляємо це до побудови (`huff_compress` лишає всі довжини нульовими; `huff_decompress` повертає 0 одразу після заголовка).

**Переповнення вихідного буфера.** Стиснення **не завжди зменшує** дані: на випадковому чи вже стиснутому вході вихід Гаффмана разом із 260-байтовим заголовком може бути **більшим** за вхід. `bw_put` тому перевіряє `len < cap` і мовчки спиняє запис при переповненні — а викличний код мусить дати `out_cap` із запасом (надійно: `n + n/2 + 512`) і звірити, що результат влізнув. Промислові формати на такий випадок зберігають блок **як є**, нестиснутим, із прапорцем.

**Розрядність коду й розмір таблиці.** Тут довжина коду тримається в `uint8_t` і теоретично сягає кільканадцяти на перекошених частотах; таблиця декодера росте як `1 << maxbits`, тож код довжиною 24 дав би таблицю на 16 мільйонів входів. На дрібному залізі це неприйнятно — там **обмежують** довжину коду (15–16 біт) ще на побудові, трохи жертвуючи оптимальністю заради компактної таблиці; на ПК для байтового алфавіту `maxbits` рідко переходить за ~16, тож пласка таблиця прийнятна, але для довгих кодів варто перейти на **дворівневу** (часті короткі коди прямо, рідкісні довгі — у підтаблицю).

**Порядок біт.** Писач і читач мусять трактувати біти **однаково** (тут — від старших до молодших, MSB-first). Сплутати порядок між кодувальником і декодером — найпідступніша помилка: коди ніби й правильні, а потік розкодовується в кашу. Якщо стикуєш свій кодек із чужим форматом (DEFLATE, наприклад, пакує біти LSB-first), вирівняй порядок насамперед.

Зробивши все це — лічильник символів у заголовку, довжина 1 для єдиного символу, захист від порожнього входу й переповнення, узгоджений порядок біт і свідома межа довжини коду — ти дістанеш кодек на пару сотень рядків, що чесно тисне довільні дані до ентропійної межі посимвольного коду й точно їх відновлює, не вимагаючи ні зовнішніх бібліотек, ні динамічної пам'яті на боці кодувальника.
