# 🧮 Математична модель затримок і пропускної здатності Network-on-Chip (NoC)

Коли кількість процесорних ядер, графічних кластерів, нейроприскорювачів та контролерів пам'яті на одному кремнієвому кристалі перевищує 16–64 вузли, класичні матричні комутатори (Crossbar) стикаються з геометричним глухим кутом: площа комутаційної матриці та кількість довгих паразитних провідників зростають як квадрат кількості агентів `O(N²)`. Перехід до регулярної пакетної мікромережі на кристалі — Network-on-Chip (NoC) із топологією 2D Mesh — зменшує просторову складність з'єднань до лінійної `O(N)`, але вводить принципово нові фізичні фактори затримки: час серіалізації пакетів, транзитну затримку проходження через чергу маршрутизаторів та затримки очікування у віртуальних каналах при виникненні мережевих заторів.

Щоб точно оцінити продуктивність інтерконекту ще на етапі архітектурного проектування SoC, поведінку NoC описують аналітичною математичною моделлю. Ця модель пов'язує геометричні параметри сітки, ширину каналів передавання, глибину конвеєра маршрутизаторів та інтенсивність генерації трафіку з підсумковою затримкою доставки повідомлень і точкою насичення пропускної здатності.

*Топологічна сітка 2D Mesh: детермінована розмірно-впорядкована маршрутизація XY та розбиття пакета на базові одиниці керування потоком (фліти).*

## 1. Геометрія 2D Mesh та середня топологічна відстань

Розглянемо двовимірну прямокутну сітку `N × M` вузлів, де кожен вузол позначається парою цілочисельних координат `(x, y)`, де `0 ≤ x < N` та `0 ≤ y < M`.

Топологічна відстань між вузлом-джерелом `S = (x_s, y_s)` та вузлом-приймачем `D = (x_d, y_d)` визначається манхеттенською метрикою (кількістю міжвузлових переходів або хопів, англ. *hop count*):

```
d(S, D) = |x_d − x_s| + |y_d − y_s|
```

Для аналізу середньої затримки в системі з рівномірним випадковим розподілом трафіку (Uniform Random Traffic), коли кожен вузол відправляє пакети будь-якому іншому вузлу з однаковою ймовірністю, необхідно знайти математичне сподівання відстані `H_avg`.

Розглянемо спершу одновимірний масив із `N` вузлів. Середня відстань між двома довільними вузлами `i` та `j` обчислюється як сума модулів різниць за всіма парами, поділена на загальну кількість пар `N²`:

```
d_1D = (1 / N²) · ∑_{i=0}^{N-1} ∑_{j=0}^{N-1} |i − j|
```

Розкриємо подвійну суму через властивість симетрії:

```
∑_{i=0}^{N-1} ∑_{j=0}^{N-1} |i − j|
= 2 · ∑_{i=0}^{N-1} ∑_{j=0}^{i} (i − j)      [симетрія відносно діагоналі]
= 2 · ∑_{i=0}^{N-1} (i · (i + 1) / 2)       [сума арифметичної прогресії]
= ∑_{i=0}^{N-1} (i² + i)                    [скорочення двійки]
= ( (N − 1) · N · (2N − 1) / 6 ) + ( (N − 1) · N / 2 )  [табличні суми квадратів і чисел]
= (N · (N − 1) / 6) · ( (2N − 1) + 3 )      [винесення спільного множника]
= (N · (N − 1) · (2N + 2)) / 6              [спрощення дужки]
= (N · (N − 1) · 2 · (N + 1)) / 6           [винесення двійки]
= (N · (N² − 1)) / 3                        [різниця квадратів]
```

Підставляючи отриману суму у вираз для середньої одновимірної відстані, маємо:

```
d_1D = (N · (N² − 1)) / (3 · N²)    [підстановка суми у вираз середньої відстані]
     = (N² − 1) / (3 · N)            [скорочення N у чисельнику й знаменнику]
     = (1 / 3) · (N − 1 / N)         [почленне ділення дужки на N]
```

Оскільки в топології 2D Mesh координати `x` та `y` є незалежними та ортогональними, загальна середня кількість хопів `H_avg` для квадратної сітки `N × N` дорівнює подвоєній одновимірній відстані:

```
H_avg = 2 · d_1D                  [сума двох незалежних проекцій X та Y]
      = (2 / 3) · (N − 1 / N)     [підстановка одновимірної відстані]
```

Для практичного випадку сітки `8 × 8` вузлів (64 обчислювальні плитки):

```
H_avg = (2 / 3) · (8 − 1 / 8)     [підстановка розмірності N = 8]
      = (2 / 3) · 7.875           [обчислення виразу в дужках]
      = 5.25 хопів                [підсумковий результат]
```

## 2. Доведення відсутності взаємних блокувань (Deadlock-Free XY Routing)

Найважливішою математичною вимогою до алгоритму маршрутизації в NoC є гарантована відсутність циклічних взаємних блокувань (дедлоків), коли група пакетів утворює замкнене кільце очікування вихідних буферів.

Згідно з фундаментальною теоремою Даллі–Зейца (William Dally, Charles Seitz, 1987), алгоритм маршрутизації є вільним від дедлоків тоді й лише тоді, коли його **граф залежності каналів (Channel Dependency Graph, CDG)** є ациклічним (не містить орієнтованих циклів).

У сітці 2D Mesh кожен вузол має канали зв'язку у чотирьох напрямках: `+X` (East), `−X` (West), `+Y` (South), `−Y` (North). У повному нерегульованому комутаторі між цими чотирма напрямками можливі 8 типів поворотів:
- Повороти з осі X на вісь Y: `East → North`, `East → South`, `West → North`, `West → South` (4 типи).
- Повороти з осі Y на вісь X: `North → East`, `North → West`, `South → East`, `South → West` (4 типи).

Алгоритм розмірно-впорядкованої маршрутизації (Dimension-Order Routing, DOR або **XY Routing**) вводить суворе правило: **пакет спочатку вичерпує всю різницю координат по осі X, і лише після цього починає рух по осі Y**. Повороти з осі Y назад на вісь X суворо заборонені.

Доведемо ациклічність графа залежностей CDG для алгоритму XY:
1. Заборона всіх чотирьох поворотів виду `Y → X` означає, що жодне ребро в графі CDG не може вести від каналу напрямку `±Y` до каналу напрямку `±X`.
2. Розіб'ємо множину всіх каналів на дві підмножини: підмножину `C_X` (канали вздовж осі X) та підмножину `C_Y` (канали вздовж осі Y).
3. Будь-який маршрут пакета є послідовністю переходів вигляду:
   ```
   c_{x,1} → c_{x,2} → ... → c_{x,k} → c_{y,1} → c_{y,2} → ... → c_{y,m}
   ```
   де `c_{x,i} ∈ C_X`, а `c_{y,j} ∈ C_Y`.
4. Зворотний перехід `c_{y,j} → c_{x,i}` неможливий за визначенням алгоритму.
5. Оскільки всередині підмножини `C_X` рух відбувається або суворо праворуч (`+X`), або суворо ліворуч (`−X`) без зміни знака, у підграфі `C_X` орієнтовані цикли відсутні.
6. Аналогічно, у підграфі `C_Y` рух відбувається суворо монотонно по координаті Y, тому цикли в `C_Y` також відсутні.
7. Оскільки між підмножинами існує зв'язок лише в один бік (`C_X → C_Y`), загальний граф залежності каналів `CDG` є строго спрямованим ациклічним графом (DAG):

```
Cycles(CDG) = ∅  ⇒  Дедлоки фізично неможливі
```

Це доводить, що маршрутизація XY гарантує надійність без потреби у складних механізмах динамічного виявлення глухих кутів.

## 3. Серіалізація пакетів та одиниці передавання (Flits)

Мережеве повідомлення довжиною `L_pkt` бітів (наприклад, рядок кешу на 64 байти плюс 16 байтів адресного заголовка, разом 640 бітів) не можна передати по кристалу єдиним широким паралельним фронтом через обмеження площі металізації.

Пакет розбивається на послідовність дрібних блоків однакового розміру — флітів (англ. *flits*, *flow control units*), розрядність яких `W` відповідає фізичній ширині каналу зв'язку між сусідніми маршрутизаторами (зазвичай `W = 64, 128, 256` бітів):

```
F = ⌈ L_pkt / W ⌉    [кількість флітів у пакеті]
```

Пакет складається з трьох типів флітів:
1. **Head Flit (Голова):** Містить координати призначення `(x_d, y_d)`, клас пріоритету та номер віртуального каналу. Голова резервує вихідні порти в маршрутизаторах за маршрутом слідування.
2. **Body Flits (Тіло):** Несуть безпосереднє інформаційне навантаження.
3. **Tail Flit (Хвіст):** Замикає транзакцію та звільняє зарезервовані стани комутаторів.

## 4. Модель затримки без навантаження (Zero-Load Latency)

Затримка доставки пакета за відсутності мережевих заторів складається з двох компонентів: часу проходження голови пакета через усі маршрутизатори та часу протягування хвоста пакета через приймальний інтерфейс.

Конвеєр сучасного NoC-маршрутизатора виконує такі послідовні фази:
1. Запис у буфер вхідного віртуального каналу (Buffer Write, BW).
2. Обчислення напрямку маршрутизації (Route Computation, RC).
3. Арбітраж віртуальних каналів (Virtual Channel Allocation, VA).
4. Арбітраж комутатора (Switch Allocation, SA).
5. Проходження комутаційної матриці (Switch Traversal, ST).

Позначимо сумарну тривалість конвеєра маршрутизатора як `t_r` тактів (у сучасних оптимізованих NoC зі спекулятивним арбітражем `t_r = 1 ... 3` такти), а час передавання сигналу по міжвузловому металевому лінку — як `t_w` тактів (типово `t_w = 1` такт).

### Порівняння способів комутації

При комутації з проміжним накопиченням (**Store-and-Forward**): кожен маршрутизатор зобов'язаний повністю прийняти всі `F` флітів пакета перед тим, як почати передавати першу голову наступному вузлу. Затримка для шляху довжиною `H` хопів становить:

```
T_SF = H · (t_r + F · t_w)
```

При червоточинній комутації (**Wormhole Switching**): маршрутизатор аналізує лише Head Flit і негайно перенаправляє його у вихідний порт. Тіло та хвіст рухаються слідом по конвеєру через відкритий віртуальний канал без очікування прибуття повного пакета.

Виведемо аналітичну формулу затримки Wormhole:
- Головний фліт проходить `H` маршрутизаторів за час `H · t_r` та долає `H` міжвузлових лінків за час `H · t_w`.
- Решта `(F − 1)` флітів надходять до вузла призначення на кожному наступному такті `t_w` одразу за головою.

```
T_zero = H · t_r + H · t_w + (F − 1) · t_w    [сума часу транзиту голови та черги флітів]
       = H · t_r + (H + F − 1) · t_w          [винесення затримки лінку t_w за дужки]
```

Це фундаментальна перевага черв'ячної комутації: **затримка доставки мало залежить від загальної довжини пакета `F` на довгих дистанціях**, оскільки пакет утворює безперервний конвеєр крізь усю структуру кристала.

## 5. Пропускна здатність бісекції та межа насичення

Максимальна пропускна здатність мережі обмежена перетином бісекції (англ. *bisection bandwidth*).

**Розріз бісекції** — це мінімальна кількість ліній зв'язку, яку необхідно перерізати, щоб розділити мережу з `N × N` вузлів на дві рівні половини по `N²/2` вузлів кожна. Для двовимірної сітки 2D Mesh такий розріз перетинає рівно `N` двоспрямованих ліній (тобто `2 · N` односпрямованих каналів).

Сумарна бісекційна смуга пропускання (у бітах за секунду) становить:

```
B_bis = 2 · N · W · f_clk
```

де `W` — ширина каналу в бітах, а `f_clk` — тактова частота NoC у герцах.

Нехай кожен вузол генерує трафік з інтенсивністю `lambda` пакетів за один такт. При рівномірному розподілі випадкового трафіку ймовірність того, що пакет, згенерований у лівій половині сітки, прямує до правої половини (тобто перетинає бісекційний розріз), становить:

```
P_cross = (N² / 2) / (N² − 1) ≈ 1 / 2
```

Кількість пакетів, які намагаються перетнути бісекцію за один такт:

```
R_cross = (N² / 2) · λ · P_cross     [визначення інтенсивності перетину розрізу]
        = (N² / 2) · λ · (1 / 2)     [підстановка ймовірності P_cross = 1/2]
        = (N² · λ) / 4               [спрощення коефіцієнтів, пакетів за такт]
```

Оскільки кожен пакет складається з `F` флітів, а бісекційний перетин здатний пропустити не більше `2 · N` флітів за такт, межа стійкості мережі без переповнення черг (Saturation Throughput) визначається умовою:

```
R_cross · F ≤ 2 · N                  [умова неперевищення ємності бісекції]
(N² · λ_sat · F) / 4 = 2 · N         [підстановка R_cross на межі насичення]
N² · λ_sat · F = 8 · N               [множення обох частин рівняння на 4]
λ_sat = 8 / (N · F)                  [скорочення N та вираження інтенсивності]
```

Перераховуючи у фліти на вузол за такт:

```
γ_sat = λ_sat · F = 8 / N    [флітів на вузол за такт через сітку]
```

Звідси випливає важливий закон масштабування: **зі зростанням лінійного розміру сітки `N` гранична інтенсивність інжекції трафіку на один вузол спадає як `1/N`**.

## 6. Вплив віртуальних каналів на блокування початку черги (Head-of-Line Blocking)

У класичній черзі FIFO, якщо перший пакет у черзі (Head) заблокований через зайнятість потрібного вихідного порту, всі наступні пакети в цій черзі також вимушені чекати, навіть якщо їхні власні вихідні порти повністю вільні. Це явище називають блокуванням початку черги (англ. *Head-of-Line (HoL) Blocking*).

У класичній теорії комутації Кароля–Хлухія–Моргана (Karol, Hluchyj, Morgan, 1987) доведено, що для простої вхідної черги FIFO максимальна пропускна здатність вхідного порту комутатора через HoL-блокування обмежена величиною:

```
Th_FIFO_max = 2 − √2 ≈ 0.5858 (тобто лише 58.6% від фізичної смуги)
```

Для подолання цієї межі фізичний вхідний канал розділяють на `V` незалежних **віртуальних каналів (Virtual Channels, VC)**. Кожен віртуальний канал має власний невеликий буфер пам'яті (глибиною в кілька флітів), але всі `V` каналів розділяють єдину фізичну лінію зв'язку через мультиплексор арбітражу комутатора (Switch Allocator).

Імовірність того, що всі `V` віртуальних каналів одночасно заблокуються неможливістю просування, стрімко падає зі зростанням `V`:

```
P_all_blocked ≈ (P_block)^V
```

Завдяки цьому введення всього `V = 4 ... 8` віртуальних каналів на порт дозволяє підняти реальну пропускну здатність NoC з 58.6% до `> 90–95%` від теоретичної межі бісекції.

## 7. Затримка очікування в чергах під навантаженням (Queueing Latency)

Коли реальна інтенсивність генерації трафіку `lambda` наближається до теоретичної межі `lambda_sat`, буфери маршрутизаторів починають заповнюватися, створюючи затримку очікування в чергах `W_q(lambda)`.

Згідно з теорією масового обслуговування (модель `M/G/1` за формулою Полячека–Хінчина), затримка пакетного передавання з урахуванням конкуренції за вихідні порти описується виразом:

```
T_total(λ) = T_zero + W_q(λ)

W_q(λ) = ( λ · E[S²] ) / ( 2 · (1 − λ · E[S]) )
```

де `E[S]` — середній час обслуговування пакета, а `E[S²]` — другий момент часу обслуговування.

При коефіцієнті завантаження мережі `rho = lambda / lambda_sat`:

```
T_total(ρ) ≈ T_zero + ( ρ / (1 − ρ) ) · ( F / 2 ) · t_w
```

Коли навантаження `rho` перевищує `0.75 ... 0.80`, затримка зростає експоненційно (ефект хокейної ключки), перетворюючи NoC на нестабільну систему з масовим блокуванням віртуальних каналів.

## 8. Модель гарячих точок (Hotspot Traffic Model)

У реальних SoC трафік рідко буває абсолютно однорідним. Частина пакетів прямує до спільних ресурсів (наприклад, до чотирьох контролерів пам'яті DDR, розташованих по кутах або в центрі сітки).

Нехай частка трафіку `alpha` генерується як «гарячий потік» (Hotspot), спрямований до одного виділеного вузла пам'яті `(x_m, y_m)`, а частка `(1 − alpha)` залишається рівномірним фоновим трафіком.

Сумарна інтенсивність надходження трафіку до вузла гарячої точки становить:

```
λ_hotspot = λ · [ α · (N² − 1) + 1 ]
```

Оскільки пропускна здатність вхідного порту цільового вузла обмежена 1 пакетом за такт (або `1/F` пакетів при багатофлітових транзакціях), нова точка насичення всієї системи різко знижується:

```
λ_sat_hotspot = 1 / ( F · [ α · (N² − 1) + 1 ] )
```

Якщо в сітці `8 × 8` (63 інші вузли) усього `alpha = 5%` трафіку спрямовано до одного контролера, маємо знаменник:

```
α · (N² − 1) + 1 = 0.05 · 63 + 1 = 3.15 + 1 = 4.15
```

Це означає, що **лише 5% нерівномірності знижують точку колапсу мережі більш ніж у 4 рази**. Для усунення цього ефекту в архітектурі SoC контролери пам'яті чергують за адресами (Memory Interleaving) та розносять по різних краях кристала.

## 9. Практичний покроковий розрахунок параметрів NoC

**Вхідні параметри проектованої системи:**
- Топологія: 2D Mesh розміром `8 × 8` (64 ядра/агенти).
- Частота інтерконекту: `f_clk = 2.0 ГГц` (період `T_clk = 0.5 нс`).
- Фізична ширина лінку: `W = 128 біт` (16 байтів).
- Розмір пакета транзакції когерентності (читання рядка кешу): 64 байти даних + 8 байтів заголовка = 72 байти = `576 бітів`.
- Глибина конвеєра роутера: `t_r = 2 такти`.
- Затримка провідника лінку: `t_w = 1 такт`.

**Покроковий розрахунок:**

1. **Кількість флітів на пакет:**
   ```
   F = ⌈ 576 / 128 ⌉ = 5 флітів (1 Head, 3 Body, 1 Tail)
   ```

2. **Середня кількість хопів між довільними вузлами:**
   ```
   H_avg = (2 / 3) · (8 − 1 / 8) = 5.25 хопів
   ```

3. **Середня затримка без навантаження (Zero-Load Latency):**
   ```
   T_zero = H_avg · t_r + (H_avg + F − 1) · t_w   [загальна формула затримки Wormhole]
          = 5.25 · 2 + (5.25 + 5 − 1) · 1          [підстановка значень H_avg, t_r, F, t_w]
          = 10.5 + 9.25                           [сума часу транзиту та протягування флітів]
          = 19.75 тактів                          [підсумковий результат у циклах]
   ```
   У фізичному часі:
   ```
   t_latency = 19.75 · 0.5 нс = 9.875 нс
   ```

4. **Бісекційна пропускна здатність кристала:**
   ```
   B_bis = 2 · N · W · f_clk                       [формула смуги перетину бісекції]
         = 2 · 8 · 128 біт · 2.0 · 10⁹ Гц          [підстановка розрядності лінків та частоти]
         = 4096 · 10⁹ біт/с                        [обчислення у бітах за секунду]
         = 4.096 Тбіт/с = 512 ГБ/с                 [переведення у терабіти та гігабайти]
   ```

5. **Гранична точка насичення трафіку на один вузол:**
   ```
   λ_sat = 8 / (8 · 5) = 0.20 пакетів / вузол / такт
   ```
   У перерахунку на бітрейт одного процесорного ядра:
   ```
   BW_max_node = 0.20 · 576 біт · 2.0 · 10⁹ Гц = 230.4 Гбіт/с = 28.8 ГБ/с
   ```

6. **Оцінка затримки при робочому завантаженні 50% (`rho = 0.5`):**
   ```
   T_total(0.5) ≈ 19.75 + ( 0.5 / (1 − 0.5) ) · ( 5 / 2 ) · 1   [підстановка rho = 0.5]
                = 19.75 + 1.0 · 2.5                             [обчислення коефіцієнта черги]
                = 22.25 тактів (11.125 нс)                      [затримка під 50% навантаженням]
   ```

Розрахунок показує, що при половинному завантаженні мережі середня затримка доставки даних між будь-якими двома ядрами на кристалі становить усього 11.1 наносекунди, що повністю задовольняє вимоги до системної кеш-пам'яті L3 у сучасних серверах та мобільних чіпсетах.
