# 🔌 Технічні формати та межі відповідальності: Soft, Firm та Hard IP

Коли системний архітектор інтегрує в кремнієвий кристал системи-на-кристалі (SoC) десятки різнорідних функціональних вузлів від сторонніх постачальників, він стикається з фундаментальним компромісом між технологічною гнучкістю та фізичною гарантією параметрів. Якщо надати розробнику весь чіп у вигляді вихідного коду на мові опису апаратури, інтегратор отримує свободу вибору будь-якої кремнієвої фабрики та будь-якої бібліотеки стандартних комірок, проте бере на себе повний тягар логічного синтезу, розведення та закриття критичних часових затримок на частотах у гігагерцовому діапазоні.

Якщо ж постачальник передає повністю готовий топологічний макет у форматі масок, інтегратор отримує блок із гарантованою швидкодією та кремнієвою перевіркою, але втрачає будь-яку можливість модифікувати внутрішню структуру й виявляється намертво прив'язаним до конкретного техпроцесу та конкретної фабрики. Щоб збалансувати ці суперечливі вимоги, індустрія напівпровідникової інтелектуальної власності розділила IP-блоки на три чіткі технічні градації: **Soft IP**, **Firm IP** та **Hard IP**.

![Матриця пакетів поставки (Deliverables) для Soft, Firm та Hard IP](/book/electronics/microelectronics/ip-licensing/img/ip-deliverables-matrix.svg)
*Матриця пакетів поставки (Deliverables): порівняння форматів вихідних файлів, моделей таймінгів, геометричних описів та тестових засобів для трьох категорій напівпровідникової IP.*

## Детальний огляд технічних форматів і структури поставки

Кожна градація IP має власний стандартизований набір інженерних файлів (англ. *Deliverables*), який визначає, на якому етапі автоматизованого проєктування (EDA Flow) блок вбудовується в загальний проєкт мікросхеми.

### 1. Soft IP: Програмно реалізовані ядра на рівні реєстрових передач

Soft IP постачається у вигляді вихідного тексту на мовах апаратного опису (HDL — Hardware Description Language). Це найвища точка абстракції в напівпровідниковому проєктуванні.

```
   ┌─────────────────────────────────────────────────────────┐
   │                   Пакет поставки Soft IP                │
   ├──────────────────────────┬──────────────────────────────┤
   │ Вихідний логічний опис   │ RTL (.sv, .v, .vhd)          │
   │ Часові обмеження         │ Synopsys Constraints (.sdc)  │
   │ Домени живлення          │ UPF / CPF (.upf, .cpf)       │
   │ Верифікаційне оточення   │ UVM Testbench + SVA          │
   │ Моделі симуляції         │ Поведінковий SystemVerilog   │
   └──────────────────────────┴──────────────────────────────┘
```

- **RTL-код (`.v`, `.sv`, `.vhd`):** Текстовий опис логіки функціонування блоку у вигляді скінченних автоматів, конвеєрних регістрів, мультиплексорів та комбінаційних обчислювачів. Часто RTL параметризується через директиви `parameter` або `generic`, дозволяючи замовнику налаштовувати розрядність шин даних, глибину буферів FIFO, обсяги локальної пам'яті та набір підтримуваних інструкцій.
- **SDC-файли (`.sdc` — Synopsys Design Constraints):** Скрипти на базі Tcl, які формалізують часові вимоги до блоку: визначення вхідних тактових генераторів (`create_clock`), періоди синхронізації, затримки вхідних і вихідних сигналів відносно тактового фронту (`set_input_delay`, `set_output_delay`), а також хибні й мультитактові шляхи (`set_false_path`, `set_multicycle_path`).
- **Специфікації живлення (`.upf` / `.cpf` — Unified Power Format):** Опис архітектури енергозбереження: виділення блоку в окремий комутований домен живлення (Power Domain), визначення рівнів напруг, стратегій вимкнення живлення (Power Gating), а також правила розміщення комірок ізоляції (Isolation Cells) та збереження стану (Retention Registers).

### 2. Firm IP: Структурно оптимізовані списки з'єднань

Firm IP є проміжною ланкою між програмною гнучкістю та топологічною фіксацією. Постачальник виконує синтез власного RTL-коду під певне сімейство стандартних комірок, оптимізуючи критичні конвеєрні шляхи.

- **Gate-level Netlist (`.v`):** Список логічних вентилів (NAND, NOR, D-тригери, мультиплексори) та з'єднань між їхніми виводами. Вихідний RTL-код при цьому прихований, що захищає авторські права постачальника від викрадення або несанкціонованої модифікації.
- **DEF-файли (`.def` — Design Exchange Format) та RBM-обмеження:** Специфікація відносного просторового розміщення макросів та критичних вентилів (Relative Placement Constraints). Це гарантує, що паразитна ємність з'єднувальних провідників між арифметичними блоками не перевищить критичного порогу, уможливлюючи роботу на високих частотах.

### 3. Hard IP: Повністю завершені топологічні блоки

Hard IP є повністю спроєктованим, перевіреним і топологічно завершеним прямокутним або полігональним блоком, який інтегрується в кремній методом фізичного вклеювання на фінальних етапах складання кристала.

```
   ┌─────────────────────────────────────────────────────────┐
   │                   Пакет поставки Hard IP                │
   ├──────────────────────────┬──────────────────────────────┤
   │ Повна геометрія масок    │ GDSII (.gds) / OASIS (.oas)  │
   │ Абстрактний макет        │ LEF (.lef) — Pins & Blockage │
   │ Таймінгові бібліотеки    │ Liberty (.lib / .db) PVT     │
   │ Електрична схема         │ CDL / SPICE Transistor Level │
   │ Моделі поведінки         │ Verilog Shell + FastSPICE    │
   │ Правила перевірок        │ DRC / LVS Tech Decks         │
   └──────────────────────────┴──────────────────────────────┘
```

- **LEF (`.lef` — Library Exchange Format):** Абстрактна геометрична модель блоку для САПР трасування (Place & Route). LEF містить лише зовнішні фізичні габарити блоку, координати та металеві шари контактних площадок (пінів), а також зони заборони трасування (Routing and Placement Obstructions). Внутрішня геометрія мільйонів транзисторів прихована.
- **Liberty-бібліотеки (`.lib` / бінарний `.db`):** Файли нелінійних моделей затримок (NLDM) або композитних струмових моделей джерела (CCS — Composite Current Source / ECSM). Вони містять точні таблиці затримок поширення сигналів залежно від крутості вхідного фронту (Input Transition Slew) та вихідної ємності навантаження (Output Load Capacitance), часових вимог встановлення/утримання (Setup/Hold) та енергоспоживання для десятків технологічних кутів (PVT Corners: Process Fast/Slow/Typical, Voltage ±10%, Temperature від −40°C до +125°C).
- **CDL / SPICE Netlist (`.cdl`, `.sp`):** Повний список транзисторів, діодів, варикапів, резисторів і паразитно видобутих ємностей для перевірки топологічної еквівалентності схемі (LVS — Layout Versus Schematic).
- **GDSII / OASIS (`.gds`, `.oas`):** Фінальні бінарні файли всіх фізичних фотолітографічних шарів (дифузія, імплантація, полікремній, діелектричні перехідні отвори Vias, металеві шари від Metal 1 до Metal 12–16), які на фінальному етапі Chip Assembly автоматично зливаються (Stream-in Merge) у загальний файл масок чіпа.

## Розподіл зон інженерної відповідальності

При використанні різних типів IP межа між тим, за що відповідає постачальник (IP Vendor), і тим, за що відповідає команда інтегратора (SoC Integrator), зміщується по всьому маршруту проєктування.

```
Етап проєктування          Soft IP                Firm IP               Hard IP
──────────────────────────────────────────────────────────────────────────────────
Архітектура логіки         Постачальник           Постачальник          Постачальник
Логічний синтез            Інтегратор             Постачальник          Постачальник
Вибір бібліотек комірок    Інтегратор             Постачальник          Постачальник
Аналогова схемотехніка     Відсутня               Відсутня              Постачальник
Трасування (P&R)           Інтегратор             Інтегратор (частково) Постачальник
Синтез дерева такту (CTS)  Інтегратор             Інтегратор            Постачальник
Закриття таймінгів (STA)   Інтегратор             Спільно               Постачальник
DRC / LVS усередині блоку  Інтегратор             Інтегратор            Постачальник
Гарантія Silicon Proven    Відповідає інтегратор  Спільно               Постачальник
```

### Відповідальність за часове закриття (Timing Closure)
У Soft IP вендор гарантує лише функціональну правильність алгоритму в симуляції. Якщо після синтезу в 5-нм техпроцесі процесорне ядро не може досягти цільової частоти 3.2 ГГц через довгий комбінаційний шлях в АЛП, інтегратор змушений самостійно змінювати конвеєризацію, вставляти додаткові регістри або вручну перевизначати обмеження синтезу.

У Hard IP уся відповідальність за внутрішні таймінги лежить на постачальнику: усередині блоку гарантовано відсутні порушення Setup/Hold. Завдання інтегратора зводиться лише до забезпечення таймінгів на межі блоку (Boundary Timing) — від зовнішніх виводів LEF до перших регістрів системного інтерконекту.

## Технологічна міграція та ризики блокування фабрикою

Головна стратегічна різниця між градаціями IP проявляється під час зміни фабрики чи переходу на наступний вузол техпроцесу (Technology Node Migration).

```
   Soft IP:
   [Вихідний RTL] ──▶ Синтез під нову бібліотеку (TSMC / Intel / Samsung) ──▶ Готово (1–2 тижні)

   Hard IP:
   [Hard IP TSMC N7] ──▶ Перехід на Samsung SF4 ──▶ ПОВНИЙ РЕДИЗАЙН (9–15 місяців, $2–5 млн)
```

1. **Міграція Soft IP:**
   Повна технологічна нейтральність. Перехід із 28-нм вузла TSMC на 3-нм процес Samsung вимагає лише заміни файлу бібліотеки стандартних комірок (`.db`) у скрипті синтезу Synopsys Design Compiler або Cadence Genus. Увесь RTL-код компілюється під нові напівпровідникові норми автоматично.
2. **Міграція Hard IP (Foundry Lock-in):**
   Повна прив'язка до фізичних параметрів кремнію: товщини підзатворного діелектрика, геометрії FinFET/GAA-ребер, пробивних напруг, паразитного опору металевих ліній та температурних коефіцієнтів підкладки. Перенесення Hard IP SerDes чи DDR PHY на іншу фабрику або інший вузол вимагає від вендора ручного перемальовування всіх аналогових транзисторів, розрахунку нової матриці резисторів, повторного CTS і обов'язкового виготовлення тестових кристалів (Test Chip Shuttle) для кремнієвої валідації.

## Типові інтеграційні пастки та методи їхнього подолання

Невдала інтеграція сторонніх IP є головною причиною збиткових повторних ітерацій виготовлення масок (Respin).

### 1. Метастабільність на стику тактових доменів (CDC) у Soft IP
При конфігурації Soft IP розробники часто підключають шину керування та шину даних до різних тактових генераторів. Якщо всередині RTL-коду відсутні коректні двотригерні або FIFO-синхронізатори із сірим кодуванням покажчиків (Gray code), на перетині доменів виникає метастабільність, що призводить до спорадичних збоїв системи під час зміни температури. 
*Метод контролю:* обов'язковий автоматизований аналіз CDC (Clock Domain Crossing) за допомогою інструментів формальної верифікації (наприклад, Synopsys SpyGlass CDC або Questa CDC).

### 2. Неузгодженість металевого стеку (Metal Stack Mismatch) у Hard IP
Кремнієва фабрика пропонує різні варіанти шарування металізації для одного й того ж вузла (наприклад, стек 1P11M з 11 шарами металу для недорогих мікросхем або 1P15M з 15 шарами та товстими верхніми шарами Ultra-thick Metal для високих струмів). Якщо Hard IP блок спроєктовано під стек із товстим шаром Metal 8, а загальний чіп розводиться за дешевшим металевим сценарієм, інтеграція фізично неможлива.
*Метод контролю:* перевірка сумісності PDK та узгодження фінального стеку металізації з постачальником IP до підписання комерційного контракту.

### 3. Топологічні крайові дефекти та правила DRC на стику Hard IP
Під час фізичного розміщення Hard IP блоку на кристалі на межі між макросом і оточуючою стандартною логікою часто виникають специфічні порушення правил проєктування (DRC Violations):
- **Ефект близькості кишені (Well Proximity Effect, WPE):** Відстань від краю Hard IP до найближчих стандартних комірок змінює порогову напругу прилеглих транзисторів через розсіювання іонів під час імплантації. Постачальник IP надає спеціальні граничні комірки (Boundary / End-cap Cells) та зони відчуження (Keep-out Margins), які інтегратор зобов'язаний закласти у Floorplan.
- **Антенний ефект (Antenna Rule Violations):** Довгі металеві провідники верхніх шарів, підключені до вхідних пінів Hard IP під час плазмового травлення, накопичують статичний заряд, здатний пробити надтонкий діелектрик затвора вхідних транзисторів блоку. Інтегратор мусить встановлювати захисні діоди (Antenna Diodes) на кожній довгій лінії зв'язку.

### 4. Субстратні струмові завади (Substrate Coupling) від цифрової логіки
Розміщення цифрового Soft IP ядра високої потужності (CPU, GPU) безпосередньо поруч із прецизійним аналоговим Hard IP блоком (генератором такту PLL чи чутливим ADC) призводить до інжекції высокочастотного шуму `dI/dt` крізь спільну підкладку. Шум викликає фазове тремтіння тактової частоти (Jitter) та паразитні гармоніки в радіочастотних трактах.
*Метод контролю:* створення охоронних дифузійних кілець (Guard Rings), застосування глибоких N-кишень (Deep N-Well) та дотримання фізичних зон відчуження навколо аналогових Hard IP блоків згідно з інструкцією інтеграції вендора.
