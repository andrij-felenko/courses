# 📋 Специфікація інтерфейсу UCIe: рівні PHY, D2D-адаптер та регістри конфігурації

Специфікація Universal Chiplet Interconnect Express (UCIe версій 1.0–2.0) визначає повний стек відкритого інтерфейсу зв'язку Die-to-Die (D2D) для з'єднання гетерогенних кристалів у межах єдиного пакувального корпусу. Цей довідник містить поглиблений архітектурний опис фізичних ліній зв'язку, форматів пакетів (флітів), протоколів службового каналу Sideband, кінцевого автомата тренування каналу LTSSM, електричних параметрів узгодження сигналів, тестових режимів BIST, оптичних ретаймерів та повної карти пам'яті регістрів конфігурації.

---

### 1. Рівнева архітектура та внутрішні межі інтерфейсів

Стек UCIe стандартизує взаємодію між трьома функціональними рівнями за допомогою двох апаратно фіксованих внутрішніх шин:

```
+-------------------------------------------------------------------+
|               Рівень протоколів (Protocol Layer)                  |
|  - PCIe 6.0 Flit Mode   - CXL.io / CXL.cache / CXL.mem (2.0/3.0)  |
|  - Streaming Protocol (прямий користувацький потік AXI / NoC)     |
+-------------------------------------------------------------------+
                                 │
                   Шина FDI (Flit-to-Die Interface)
                                 │
+-------------------------------------------------------------------+
|            Адаптер зв'язку (Die-to-Die Adapter Layer)             |
|  - Арбітраж і мультиплексування протокольних потоків              |
|  - Контроль цілісності: генерація та перевірка CRC-16 / CRC-32    |
|  - Буфер повторної передачі (Link-Level ARQ Replay Buffer)        |
|  - Керування станами низького енергоспоживання (PM FSM)           |
+-------------------------------------------------------------------+
                                 │
                    Шина RDI (Raw Die Interface)
                                 │
+-------------------------------------------------------------------+
|              Фізичний рівень (Physical Layer / PHY)               |
|  - Аналогові передавачі TX та приймачі RX (Single-Ended AFE)      |
|  - Супутнє тактування (Forwarded Clock) та трекінг фази           |
|  - Схеми вирівнювання затримок (Per-Lane Deskew DLL)              |
|  - Службовий канал Sideband (800 Мбіт/с)                          |
|  - Мультиплексори ремонту ліній (Lane Repair / Redundancy Mux)    |
+-------------------------------------------------------------------+
```

#### Шина FDI (Flit-to-Die Interface)
Шина FDI з'єднує протокольний контролер (PCIe Core, CXL Controller або NoC Bridge) з адаптером D2D. Вона передає цілісні сформовані фліти (Flits) фіксованої довжини разом із сигналами протокольного квитування:
- `pl_trdy` (Protocol Layer Target Ready) та `lp_valid` (Link Layer to Protocol Valid) — двостороннє квитування передавання фліта;
- `lp_stream_id[3:0]` — ідентифікатор активного логічного протоколу при мультиплексуванні потоків;
- `pl_flit_cancel` — сигнал негайного анулювання передавання поточного фліта у разі виявлення внутрішнього апаратного збою на верхньому рівні;
- `lp_rx_active_sts` — індикатор готовності приймального конвеєра до обробки пакетів;
- `pl_speed_mode[2:0]` — інформаційний вектор поточної узгодженої швидкості передавання для адаптації тактових частот верхніх блоків;
- `lp_stall_req` — запит адаптера на тимчасове призупинення генерації нових флітів протокольним рівнем через заповнення буфера повторної передачі.

#### Шина RDI (Raw Die Interface)
Шина RDI розділяє цифрову логіку D2D-адаптера та аналогово-цифровий блок PHY. Вона забезпечує обмін непакетованими паралельними бітовими шинами:
- `rdi_tx_data[N-1:0]` та `rdi_rx_data[N-1:0]` — синхронні паралельні дані шириною 64 біти (або кратні їй) на тактовій частоті ядра PHY;
- `rdi_lp_state_req[3:0]` — запит адаптера на зміну стану живлення аналогового фронтенду (перехід у стани L0, L1, L2 або скидання);
- `rdi_pl_state_sts[3:0]` — підтвердження від PHY про фактичне завершення аналогового переходу між станами;
- `rdi_retrain_req` — запит адаптера на примусове повторне калібрування фази затримок (Deskew) без повного перезапуску протокольного з'єднання;
- `rdi_error_sts` — строб виявлення апаратної помилки на фізичних лініях (наприклад, зрив синхронізації DLL або втрата тактового сигналу);
- `rdi_rx_valid` — сигнал валідності даних, що надходять від аналогових приймачів PHY у поточному такті.

### 2. Типи корпусів та конфігурація сигнальних ліній PHY

Специфікація UCIe визначає два типи фізичного пакування, які кардинально різняться щільністю розміщення контактних майданчиків та електричними параметрами каналу зв'язку:

1. **Standard Package:** оптимізований для недорогих традиційних органічних багатошарових підкладок. Використовує мікрокулькові виводи C4 з кроком 100–130 мкм. Передавання здійснюється однополярними лініями (16 або 32 лінії на модуль) із диференційним супутнім тактовим сигналом. Пропускна здатність на міліметр межі кристала становить 100–250 Гбіт/с.
2. **Advanced Package:** розроблений для кремнієвих інтерпозерів (TSMC CoWoS), вбудованих кремнієвих містків (Intel EMIB) та прямого 3D-зрощування (TSMC SoIC). Використовує мікростовпчики з кроком 25–45 мкм або гібридні мідні контакти з кроком менше 9 мкм. Модуль містить 64 паралельні лінії даних із однополярним супутнім тактуванням. Пропускна здатність сягає 1300–3240 Гбіт/с на міліметр краю кристала при енерговитратах менше 0.25–0.5 пДж/біт.

#### Електричні параметри та фізичне узгодження сигналів
- **Тип сигналізації:** Однополярні цифрові рівні безпосереднього зв'язку (DC-coupled Single-Ended NRZ). Відмова від диференційних пар дозволяє подвоїти кількість сигнальних ліній на одиницю площі.
- **Амплітуда напруги:** Робоча амплітуда перемикання становить від `0.4 В` до `0.9 В` (типово `0.75 В`), що забезпечує мінімальну комутаційну енергію `0.5 · C · V²`.
- **Вихідний імпеданс передавача:** Програмований вихідний опір драйвера `R_on = 40 Ом`, `50 Ом` або `85 Ом` для точного узгодження з хвильовим імпедансом мікросмужкових ліній інтерпозера та придушення вторинних відбиттів сигналу.
- **Приймальний тракт:** Вхідний каскад приймача містить прецизійний регульований компаратор із можливістю підстроювання опорної напруги `V_ref` індивідуально для кожної лінії з кроком 2.5 мВ (Receiver Margining).
- **Стійкість до електростатичного розряду (ESD):** Оскільки лінії інтерконекту замкнені всередині захищеного корпусу модуля і не мають виходу назовні, структури ESD-захисту зменшені до мінімуму (ємність діодів ESD < 10 фФ), що усуває паразитне навантаження на високочастотний тракт.

#### Повний перелік сигналів модуля UCIe Advanced Package (64 Data Lanes)

| Група ліній | Назва сигналу | Напрямок | Кількість | Опис електричного призначення |
| :--- | :--- | :---: | :---: | :--- |
| **Дані TX** | `TX_DATA[63:0]` | Вихід | 64 | Однополярні лінії передавання даних (амплітуда 0.4–0.9 В, NRZ кодування). |
| **Дані RX** | `RX_DATA[63:0]` | Вхід | 64 | Однополярні лінії приймання даних від передавача сусіднього чиплета. |
| **Тактування TX** | `TX_CLK_P / N` | Вихід | 2 | Супутній тактовий сигнал передавача (Forwarded Clock). Працює в режимі DDR (частота = половині бітрейту). |
| **Тактування RX** | `RX_CLK_P / N` | Вхід | 2 | Вхідний тактовий сигнал, синхронізований із вхідним потоком `RX_DATA`. |
| **Трекінг фази** | `TX_TRACK / RX_TRACK` | Вихід/Вхід | 2 | Сигнал періодичного трекінгу динамічного дрейфу напруги та температури (PVT Tracking). |
| **Валідність TX** | `TX_VALID` | Вихід | 1 | Сигнал валідності даних на лініях `TX_DATA` для поточного тактового циклу. |
| **Валідність RX** | `RX_VALID` | Вхід | 1 | Вхідний строб валідності даних від передавача. |
| **Ремонтні лінії** | `TX_REPAIR[3:0]` | Вихід | 4 | Резервні лінії для апаратної заміни фізично розірваних контактних площадок. |
| **Ремонтні лінії** | `RX_REPAIR[3:0]` | Вхід | 4 | Резервні лінії приймання даних. |
| **Службовий канал** | `TX_SB / RX_SB` | Вихід/Вхід | 2 | Однопровідний повнодуплексний інтерфейс Sideband (800 Мбіт/с, рівень 0.9 В, манчестерський код). |
| **Службовий такт** | `TX_SB_CLK / RX_SB_CLK`| Вихід/Вхід | 2 | Синхронний тактовий сигнал службового каналу Sideband (800 МГц). |

### 3. Структура флітів (Flit Formats) на рівні D2D-адаптера

Усі транзакції верхніх протоколів пакуються в уніфіковані блоки фіксованого розміру — **фліти** (Flow Control Units, Flits).

#### 1. Стандартний 68-байтовий фліт (Standard 68B Flit)
Оптимізований для протоколів PCIe 6.0 та CXL.io:
- **Заголовок (Header, 2 байти):** містить 6-бітний порядковий номер пакета (`Sequence ID`), 4-бітний ідентифікатор протоколу (`Protocol ID`), 4-бітний лічильник повернення кредитів керування потоком (`Credit Return`) та 2 службові біти стану зв'язку;
- **Корисне навантаження (Payload, 64 байти):** дані протокольного пакета TLP або CXL.io Flit;
- **Контрольна сума (CRC-16, 2 байти):** апаратний циклічний надлишковий код, згенерований за поліномом `x¹⁶ + x¹² + x⁵ + 1` (CCITT).

```
+-------------------+---------------------------------------------+-----------+
| Заголовок (2B)    |            Payload (64 байти)               |  CRC-16   |
| [SeqID | ProtoID] |       Пакет TLP PCIe 6.0 або CXL.io         | (2 байти) |
+-------------------+---------------------------------------------+-----------+
|<------------------------------ 68 байтів ---------------------------------->|
```

#### 2. Оптимізований за латентністю 256-байтовий фліт (Latency-Optimized 256B Flit)
Розроблений спеціально для когерентного доступу до пам'яті CXL.cache / CXL.mem:
- **Заголовок (Header, 4 байти):** розширене мультиплексування до 4 незалежних протокольних підпотоків;
- **Корисне навантаження (Payload, 236 байтів):** чотири 64-байтні кеш-рядки пам'яті або змішані слоти запитів/відповідей;
- **Контрольна сума (CRC-32, 8 байтів):** подвійна 32-бітна контрольна сума для незалежної перевірки кожної половини пакета;
- **Захист від бітових збоїв (Parity / FEC, 8 байтів):** біти парності для миттєвого апаратного виправлення поодиноких бітових помилок без перезапиту фліта.

#### 3. Розширений 544-байтовий фліт (Advanced 544B Flit)
Застосовується у високонавантажених прискорювачах для масивного паралельного потокового обміну даними між кристалами. Фліт містить 512 байтів чистих даних, 16 байтів розширеного заголовка та 16 байтів контрольних кодів захисту.

### 4. Протокол службового каналу Sideband

Службовий канал Sideband є критично важливим незалежним апаратним каналом, який функціонує навіть тоді, коли основні швидкісні лінії передавання даних `TX_DATA` ще не натреновані або вимкнені через аварійний стан.

#### Характеристики та кодування Sideband
- **Фізична швидкість:** 800 Мбіт/с на фіксованій базовій тактовій частоті 800 МГц;
- **Кодування даних:** Манчестерське диференційне кодування (або NRZ із супутнім тактом `SB_CLK`), що гарантує наявність перепадів напруги в кожному бітовому інтервалі для стабільної синхронізації;
- **Пакетний формат:** Пакет Sideband складається з 32-бітного або 64-бітного кадру, що містить 5-бітне поле операції (Opcode), 16-бітну адресу регістра, 32-бітне поле даних та 8-бітну контрольну суму CRC-8.

#### Основні опкоди команд Sideband

| Опкод (Opcode) | Назва команди | Функціональне призначення |
| :---: | :--- | :--- |
| `0x01` | `SB_REG_READ` | Читання 32-бітного значення конфігураційного регістра сусіднього чиплета. |
| `0x02` | `SB_REG_WRITE` | Запис 32-бітного значення в конфігураційний простір регістра. |
| `0x05` | `SB_MSG_PARAM` | Обмін параметрами зв'язку під час фази `PARAM_EXCHANGE`. |
| `0x08` | `SB_REPAIR_REQ` | Передача бітової маски пошкоджених ліній та узгодження схеми перепризначення. |
| `0x0A` | `SB_PWR_REQ` | Запит на переведення аналогового блоку PHY в стан енергозбереження L1 або L2. |
| `0x0F` | `SB_ACK` | Підтвердження успішного виконання попередньої службової операції. |

### 5. Кінцевий автомат тренування каналу LTSSM

Ініціалізація та контроль стану фізичного каналу здійснюються апаратним кінцевим автоматом **LTSSM (Link Training and Status State Machine)**:

```
[ RESET ]
    │  (Подання живлення, скидання PHY)
    ▼
[ SB_INIT ]  <─────────── Ініціалізація службового каналу Sideband (800 Мбіт/с)
    │  (Успішне квитування по Sideband)
    ▼
[ PARAM_EXCHANGE ]  <──── Обмін конфігурацією: бітрейт, тип корпусу, ширина шини
    │  (Параметри узгоджено)
    ▼
[ LANE_REPAIR ]  <─────── Тестування мікростовпчиків, обхід бракованих ліній через SPARE
    │  (Мапу ліній зафіксовано)
    ▼
[ DESKEW_TRAINING ]  <─── Вирівнювання фаз тактових сигналів, калібрування затримок DLL
    │  (Джитер усунено, бітрейт зафіксовано)
    ▼
[ ACTIVE_L0 ]  <───────── Повношвидкісний режим передавання даних (Active)
    │           ▲
    │ (Таймаут) │ (Запит на пробудження)
    ▼           │
[ STANDBY_L1 / SLEEP_L2 ]  (Енергозберігаючі стани зі зниженням живлення)
```

#### Етапи функціонування LTSSM
1. **`RESET`:** Стан апаратного скидання. Аналогові приймачі вимкнені, лінії знаходяться у високоімпедансному стані.
2. **`SB_INIT`:** Запуск низькошвидкісного службового каналу Sideband на фіксованій частоті 800 МГц. Передавач надсилає тестовий 32-бітний патерн `0x55AA55AA` для синхронізації фази манчестерського декодера приймача.
3. **`PARAM_EXCHANGE`:** Через канал Sideband чиплети обмінюються реєстрами можливостей: узгоджують підтримувану швидкість (4, 8, 12, 16, 24 або 32 Гбіт/с), ширину паралельної шини (16, 32 чи 64 лінії) та формат флітів.
4. **`LANE_REPAIR`:** Фізичне зондування ліній даних. Передавач інжектує тестові псевдовипадкові послідовності PRBS-23 по черзі в кожну лінію. Якщо лінія має обрив або коротке замикання, адаптер перепризначає її на одну з 4 резервних ліній `REPAIR[3:0]` та фіксує мапу в регістрах.
5. **`DESKEW_TRAINING`:** Вирівнювання фазового розкиду сигналів між паралельними доріжками. Схеми затримки з фазовим автопідстроюванням (DLL) у кожній лінії підганяють затримку з точністю до 1 пікосекунди, забезпечуючи відкриття «ока» діаграми сигналу.
6. **`ACTIVE_L0`:** Канал повністю працездатний, передавання даних дозволено на повній швидкості.

#### Часові обмеження переходів станів енергозбереження
- **Перехід `L0 → L1` (Standby Entry):** час переходу не перевищує 8 наносекунд;
- **Перехід `L1 → L0` (Standby Exit / Wakeup):** пробудження та стабілізація тактових буферів займає менше 10 наносекунд;
- **Перехід `L0 → L2` (Deep Sleep Entry):** вимкнення живлення аналогового фронтенду займає близько 50 наносекунд;
- **Перехід `L2 → L0` (Deep Sleep Wakeup):** увімкнення живлення та повторна фіксація частоти генераторів DLL займає менше 100 наносекунд.

### 6. Вбудоване тестування BIST та граничне сканування IEEE 1838

Тестування тисяч міжчиплетних контактів на рівні збірки здійснюється за допомогою спеціалізованих апаратних блоків самотестування (Built-In Self-Test, BIST) та архітектури граничного сканування за стандартом IEEE 1838:
- **Генератори патернів PRBS-31:** Вбудований у кожну лінію апаратний генератор псевдовипадкових бітових послідовностей на базі 31-розрядного зсувного регістра з лінійним зворотним зв'язком (LFSR). Дозволяє верифікувати коефіцієнт бітових помилок на рівні `BER < 10⁻¹⁵`.
- **Архітектура Wrapper IEEE 1838:** Кожен чиплет містить шар тестового доступу (Die Wrapper), що складається з обгорткового регістра команд (Wrapper Instruction Register, WIR) та обгорткового граничного регістра (Wrapper Boundary Register, WBR). Це дозволяє ізолювати окремий чиплет і перевірити всі внутрішні логічні ланцюги незалежно від стану сусідніх кристалів.

### 7. Карта пам'яті регістрів конфігурації (UCIe Memory-Mapped Registers)

Доступ до регістрів здійснюється через внутрішню шину керування (APB / AXI-Lite) або через службовий канал Sideband із базовою адресою `UCIE_BASE_ADDR`.

#### Таблиця регістрів модуля UCIe

| Зсув (Offset) | Назва регістра | Тип | Скидання | Функціональне призначення |

### 8. Порозрядний опис керуючих бітових полів

#### 1. Регістр керування з'єднанням (`UCIE_LINK_CTRL`, зсув `0x08`)
- **Біт `[0]` (`LINK_ENABLE`):** `1` — активувати аналоговий фронтенд PHY та запустити автомат тренування каналу LTSSM; `0` — примусовий перехід PHY у стан скидання `RESET`.
- **Біти `[3:1]` (`TARGET_SPEED`):** бажана швидкість передавання даних на лінію:
  - `000b` — 4 Гбіт/с;
  - `001b` — 8 Гбіт/с;
  - `010b` — 12 Гбіт/с;
  - `011b` — 16 Гбіт/с;
  - `100b` — 24 Гбіт/с;
  - `101b` — 32 Гбіт/с.
- **Біти `[5:4]` (`POWER_STATE_REQ`):** запит зміни стану енергозбереження:
  - `00b` — `NOP` (стан не змінюється);
  - `01b` — Запит переходу в стан `L1` (Low-Power Standby, час відновлення <10 нс);
  - `10b` — Запит переходу в стан `L2` (Deep Sleep, живлення PHY вимкнено, час виходу <100 нс);
  - `11b` — Запит повернення в активний стан `L0`.
- **Біт `[8]` (`RETRAIN_LINK`):** запис `1` ініціює повторне калібрування затримок (Deskew) без скидання стану протокольних рівнів.
- **Біт `[12]` (`PVT_TRACK_ENABLE`):** `1` — дозволити періодичну фонову підстройку фази DLL для компенсації теплового дрейфу кремнію під час роботи.

#### 2. Регістр стану з'єднання (`UCIE_LINK_STATUS`, зсув `0x0C`)
- **Біти `[3:0]` (`LTSSM_STATE`):** поточний стан кінцевого автомата тренування:
  - `0x0` — `RESET`;
  - `0x1` — `SB_INIT`;
  - `0x2` — `PARAM_EXCHANGE`;
  - `0x3` — `LANE_REPAIR`;
  - `0x4` — `DESKEW_TRAINING`;
  - `0x5` — `ACTIVE_L0`;
  - `0x6` — `STANDBY_L1`;
  - `0x7` — `SLEEP_L2`;
  - `0xE` — `LINK_ERROR` (критичний невідновлюваний збій зв'язку).
- **Біт `[4]` (`LINK_TRAINED`):** виставляється апаратно в `1`, коли канал успішно завершив вирівнювання затримок і готовий до передавання флітів.
- **Біти `[7:5]` (`CURRENT_SPEED`):** фактично узгоджена швидкість передавання даних (кодування аналогічне полю `TARGET_SPEED`).
- **Біт `[16]` (`CRC_ERROR_FLAG`):** виставляється в `1`, якщо адаптер зафіксував помилку CRC у прийнятому фліті. Скидається записом одиниці (W1C).
- **Біт `[17]` (`RETRY_BUFFER_FULL`):** сигналізує про переповнення буфера повторної передачі через високий рівень завад у каналі зв'язку.
- **Біт `[20]` (`DESKEW_LOCK_LOST`):** апаратний прапорець зриву синхронізації DLL-фазообертачів у процесі роботи.

#### 3. Регістр керування ремонтом ліній (`UCIE_LANE_REPAIR_CTRL`, зсув `0x20`)
- **Біт `[0]` (`REPAIR_ENABLE`):** `1` — дозволити апаратне перемикання мультиплексорів PHY з дефектних ліній на резервні (`TX_REPAIR` / `RX_REPAIR`);
- **Біти `[7:1]` (`BAD_LANE_INDEX`):** індекс фізичної лінії даних (від 0 до 63), яка визнана несправною під час тестування;
- **Біти `[11:8]` (`SPARE_LANE_SELECT`):** індекс резервної лінії (від 0 до 3), на яку спрямовується потік даних замість дефектного контакту;
- **Біт `[31]` (`REPAIR_FROZEN`):** запис `1` блокує подальші зміни таблиці перепризначення та ініціює запис конфігурації в постійні перемички eFuse після заводського тестування.

#### 4. Регістр керування марджинінгом (`UCIE_MARGIN_CTRL`, зсув `0x38`)
- **Біти `[6:0]` (`VREF_OFFSET`):** цифровий код зсуву вхідної опорної напруги компаратора приймача від номінального рівня (крок 2.5 мВ, діапазон ±160 мВ);
- **Біти `[14:8]` (`TIME_OFFSET`):** цифровий код зсуву точки стробування тактового сигналу щодо центру бітового інтервалу (крок 0.5 пікосекунди, діапазон ±32 пс);
- **Біт `[16]` (`MARGIN_EXECUTE`):** запуск автоматичного апаратного тесту побудови контуру ока сигнальної діаграми з фіксацією коефіцієнта бітових помилок BER.

#### 5. Регістр керування BIST (`UCIE_BIST_CTRL`, зсув `0x44`)
- **Біт `[0]` (`BIST_ENABLE`):** `1` — перевести модуль PHY у режим генерації та аналізу тестових патернів;
- **Біти `[3:1]` (`PATTERN_SELECT`):** вибір тестового патерна:
  - `000b` — PRBS-7;
  - `001b` — PRBS-15;
  - `010b` — PRBS-23;
  - `011b` — PRBS-31;
  - `100b` — чергування нулів та одиниць `0101b` (тестування максимальної частоти перемикання Clock Pattern).
- **Біт `[8]` (`BIST_CLEAR_ERR`):** запис `1` скидає лічильник помилок `UCIE_BIST_ERR_CNT`.
