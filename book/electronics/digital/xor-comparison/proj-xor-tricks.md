# ⚙️ XOR-трюки: парність, обмін без тимчасової, відмінний біт

> Алгоритмічна вставка про [XOR як детектор різниці](book:electronics/xor-comparison): порівняння, парність, додавання. Тут спускаємося на рівень коду: три коротенькі прийоми на C, які тримаються на двох властивостях XOR — він **самозворотний** (x ⊕ x = 0, тож x ⊕ y ⊕ y = x) і **асоціативно-комутативний** (порядок і групування байдужі). Усе інше — наслідки цих двох фактів.

### Задача

У прошивці постійно виринають три дрібні питання, на які хочеться відповісти **без циклів і без зайвої пам'яті**. Скільки одиниць у слові — парна їх кількість чи ні (це [біт парності](book:communications/parity-bit) для UART)? Як поміняти місцями два значення, коли регістрів обмаль і шкода навіть однієї тимчасової змінної? І як швидко з'ясувати, **де саме** різняться два слова — наприклад, які піни порту змінили стан від попереднього опитування? Кожну з цих задач XOR розв'язує майже даром, і всі три — варіації однієї думки.

### Ідея

Почнімо з **парності**. Найпростіший спосіб порахувати її — прогнати біти ланцюжком XOR один за одним (саме так працює [XOR як детектор різниці](book:electronics/xor-comparison)): наочно, але для 32-бітного слова це 31 крок. XOR асоціативний, тож суму всіх бітів можна рахувати **деревом**, а не низкою: складаємо слово саме із собою, зсунутим навпіл, і повторюємо. За кожен крок ширина «живої» частини зменшується вдвічі, тож кроків не 31, а лише log₂N — для 32 біт п'ять.

![Парність слова згортанням навпіл](/book/electronics/digital/xor-comparison/img/parity-fold.svg)
*Ліворуч — серійний XOR-ланцюг: один крок на біт. Праворуч — згортання (англ. *folding* — складання): `x ^= x >> 16; x ^= x >> 8; …; x ^= x >> 1`. Оскільки XOR асоціативний і комутативний, кожен крок XOR-ить біт i з бітом i+16, потім i з i+8 і так далі — наприкінці молодший біт несе XOR-суму **всіх** бітів, тобто парність. Та сама відповідь, але за log₂N кроків замість N.*

Другий прийом — **обмін без тимчасової змінної** — спирається вже на самозворотність. Три рядки `a ^= b; b ^= a; a ^= b;` міняють значення місцями, не заводячи третьої комірки.

![Обмін двох змінних трьома XOR](/book/electronics/digital/xor-comparison/img/xor-swap.svg)
*Слідкуймо за бітами: після `a ^= b` змінна a несе a₀⊕b₀. Тоді `b ^= a` кладе в b значення (a₀⊕b₀)⊕b₀, а зайва пара b₀ скорочується — лишається a₀. Нарешті `a ^= b` дає a = (a₀⊕b₀)⊕a₀ = b₀. Значення помінялися; уся «магія» — у тому, що x ⊕ y ⊕ y = x.*

Третій прийом відповідає на «де різниця?». XOR двох слів **підсвічує** саме ті розряди, де вони не збігаються: на виході 1 стоїть там, де біти різні, і 0 — де однакові. А якщо потрібен лише **один** відмінний біт (щоб обходити зміни по черзі), є класична ідіома `x & (−x)`, що лишає від числа його **наймолодшу** одиницю.

![Пошук відмінного біта: A⊕B і x & −x](/book/electronics/digital/xor-comparison/img/diff-bit.svg)
*`A ⊕ B` дає маску відмінностей (зелені розряди — там, де A і B різні); кількість одиниць у ній — це **відстань Геммінга** між словами. Далі `x & (−x)` вихоплює молодший відмінний біт: у поширеному поданні від'ємних чисел `−x` дорівнює (інверсія x)+1, і це додавання лишає недоторканою саме наймолодшу одиницю, обнуляючи все під нею.*

### Псевдокод

Усі три прийоми вкладаються в кілька рядків C:

:::tabs
```cpp
// 1. Парність слова згортанням (log2 N кроків)
uint32_t v = word;
v ^= v >> 16;            // склали верхню й нижню половини
v ^= v >> 8;
v ^= v >> 4;
v ^= v >> 2;
v ^= v >> 1;
int parity = v & 1;      // 1 = непарна кількість одиниць

// 2. Обмін без тимчасової (a і b — РІЗНІ комірки!)
a ^= b;  b ^= a;  a ^= b;

// 3. Що змінилося від минулого опитування — і обхід по одному біту
uint32_t changed = now ^ prev;       // маска відмінних бітів
while (changed) {
    uint32_t bit = changed & -changed;   // молодший відмінний біт
    handle(bit);                         // обробити саме його
    changed ^= bit;                      // зняти й піти далі
}
prev = now;
```
```py
# 1. Парність слова згортанням (log2 N кроків)
v = word
v ^= v >> 16             # склали верхню й нижню половини
v ^= v >> 8
v ^= v >> 4
v ^= v >> 2
v ^= v >> 1
parity = v & 1           # 1 = непарна кількість одиниць

# 2. Обмін без тимчасової (a і b — РІЗНІ імена!)
a ^= b;  b ^= a;  a ^= b
# (у Python зазвичай просто: a, b = b, a)

# 3. Що змінилося від минулого опитування — і обхід по одному біту
changed = now ^ prev                 # маска відмінних бітів
while changed:
    bit = changed & -changed         # молодший відмінний біт
    handle(bit)                      # обробити саме його
    changed ^= bit                   # зняти й піти далі
prev = now
```

### Складність і пастки на МК

- **Складність.** Згортання парності — O(log N): п'ять «зсув + XOR» на 32-бітне слово, без циклу й без таблиці. Обмін — три інструкції. Обхід відмінностей крутиться **рівно стільки разів, скільки бітів змінилося**, а не всі 32 — тож для типового «змінилась одна кнопка» це одна ітерація.
- **Обмін через XOR і однакові адреси.** Найгостріша пастка: якщо `a` і `b` — це **та сама** комірка (наприклад, `swap(arr[i], arr[j])` за `i == j`), то перший же `a ^= b` обнулить її, і значення зникне. Звичайний обмін через тимчасову змінну такого не робить — тому на сучасному МК XOR-обмін майже завжди зайвий: компілятор і так тримає обидва значення в регістрах, а ризик `i == j` нікуди не дівається. Знати його варто (трапляється в чужому коді), застосовувати — лише там, де він справді щось дає.
- **`−x` для беззнакових типів.** Ідіома `x & -x` спирається на «згортковий» характер [додаткового коду від'ємних чисел](book:math/twos-complement); пишіть її над **беззнаковим** типом (`unsigned`), щоб уникнути невизначеної поведінки знакового переповнення. Тут досить факту, що `−x` = (інверсія x)+1.
- **Ширина типу і зсуви.** Послідовність згортання залежить від розрядності: для 16-бітного слова починайте з `>> 8`, для 8-бітного — з `>> 4`. Зсув на величину, що дорівнює ширині типу або більша (наприклад, `>> 32` для 32-бітного), — теж невизначена поведінка; не «дописуйте зайвий крок про запас».
- **Парність — це не виявлення кратних помилок.** Один [біт парності](book:communications/parity-bit) ловить будь-яку **непарну** кількість перекидань і сліпий до **парної**. Швидке згортання лише пришвидшує обчислення тієї самої парності — надійнішим воно код не робить; для серйозного захисту потрібні сильніші схеми, як-от [код Геммінга](book:communications/hamming-code) чи [CRC](book:communications/crc).
