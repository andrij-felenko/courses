## Що означає кожен токен

Токени йдуть у довільному порядку, регістр не має значення, суфікси — інженерні (`f` = 10⁻¹⁵, `p` = 10⁻¹², `n` = 10⁻⁹, `m` = 10⁻³). Розкладімо картку 2N3904 за роллю кожного числа.

| Токен | Значення | Роль |
|---|---|---|
| `IS=6.734f` | струм насичення переносу, 6.734·10⁻¹⁵ А | масштаб усіх струмів: I_К ∝ I_S |
| `BF=416.4` | ідеальне пряме β | відношення двох ідеальних струмів насичення |
| `NF=1` (за замовч.) | показник ідеальності прямого струму | нахил прямої I_К: 1/(NF·Vₜ) |
| `VAF=74.03` | напруга Ерлі, В | нахил плато вихідних характеристик |
| `IKF=66.78m` | струм коліна високої інжекції, 66.78 мА | де β валиться праворуч |
| `ISE=6.734f`, `NE=1.259` | витік у переході Б–Е та його показник | ліве коліно дзвону β |
| `BR=.7371`, `NR=1` | зворотне β та його показник | режим насичення / інверсний |
| `ISC=0`, `NC=2` | витік у переході Б–К | інверсний бік |
| `IKR=0` | коліно інжекції у зворотному режимі | інверсний бік |
| `RB=10`, `RC=1`, `RE` (0) | опори бази, колектора, емітера, Ом | падіння напруги на виводах |
| `CJE`, `VJE`, `MJE` | ємність переходу Б–Е, її контактний потенціал і показник | динаміка, заряд переходу |
| `CJC`, `VJC`, `MJC`, `FC` | те саме для переходу Б–К | динаміка, ефект Міллера |
| `TF=301.2p`, `TR=239.5n` | пряма й зворотна сталі часу прольоту | швидкодія, f_T |
| `ITF`, `VTF`, `XTF` | як τ_F росте зі струмом і напругою | спад f_T на краях |
| `XTI=3`, `EG=1.11`, `XTB=1.5` | температурні показники I_S та β, ширина забороненої зони | поведінка з нагрівом |

Двадцять чисел, а порядок у них є. Перша група — **постійний струм у прямому режимі**: `IS, BF, NF, VAF, IKF, ISE, NE`. Саме вона й малює графік Ґуммеля. Друга — **зворотний бік** (`BR, NR, ISC, NC, IKR`), який працює лише в насиченні чи інверсії. Третя — **паразитні опори**. Четверта — **ємності й часи прольоту**, тобто вся динаміка. П'ята — **температура**. Симулятор під час аналізу постійного струму вживає передусім першу групу; решта вмикається, коли з'являються змінний сигнал, перемикання чи нагрів.

> 🔧 **Навіщо це.** Коли ваша схема в симуляторі поводиться не так, як залізо, винен майже завжди `.model`-рядок, а не топологія. Транзистор, узятий із чужої бібліотеки «на око», може мати `IKF`, зняте для іншого струму, або взагалі дефолтні ємності — і ваш підсилювач у симуляції матиме смугу, якої в платі не буде. Уміти прочитати ці двадцять чисел — це вміти не довіряти моделі наосліп.

Ідеальний струм — це той, що йде чистою експонентою Шоклі, з показником рівно V_BE/Vₜ; тепловий потенціал [Vₜ = kT/q ≈ 25.85 мВ при 300 К і сама експонента](book:electronics/diode-iv-curve) — той самий кістяк, що й у діода. `NF` близько 1 означає «майже ідеально»; `NE` близько 2 каже, що витік іде вдвічі пологішою експонентою.

## Ідея: рівняння вже всі перед нами

Графік Ґуммеля знімають при короткозамкнених базі й колекторі, тобто V_BC = 0. Це різко спрощує рівняння моделі. У множнику нормованого заряду бази член Ерлі q₁ = 1/(1 − V_BC/VAF) при V_BC = 0 обертається на одиницю — **напруга Ерлі просто зникає з графіка Ґуммеля**. Лишається:

```
ef = e^(V_BE/(NF·Vₜ))
q₂ = (I_S/IKF)·(ef − 1)                    ← високий рівень інжекції
q_b = ½·(1 + √(1 + 4·q₂))                  ← нормований заряд бази (q₁=1)
I_К = (I_S/q_b)·ef
I_Б = (I_S/BF)·(ef − 1) + ISE·e^(V_BE/(NE·Vₜ))
β   = I_К / I_Б
```

Тобто графік Ґуммеля залежить рівно від шести чисел: `IS, NF, BF, IKF, ISE, NE`. Напруга Ерлі `VAF` на ньому невидима — її доведеться діставати з іншого знімка. Це не дрібниця, а перше правило видобування: **різні параметри живуть на різних кривих**, і мірний план треба будувати так, щоб кожен з них десь та й проявився наодинці.

## Робочий код: від рядка до кривих

Переклад цих п'яти формул на Python з numpy — майже дослівний. Параметри беремо просто як словник, зчитаний із рядка `.model`; функцію пишемо векторно, щоб одразу гнати весь масив напруг.

```py
import numpy as np
import matplotlib.pyplot as plt

Vt = 0.025852                       # kT/q при 300 K, В

# --- числа просто з рядка .model 2N3904 (Fairchild) ---
p = dict(IS=6.734e-15, BF=416.4, NF=1.0,
         IKF=66.78e-3, ISE=6.734e-15, NE=1.259, VAF=74.03)

def gummel_poon(vbe, vbc=0.0, p=p, Vt=Vt):
    """I_К, I_Б, β у прямому активному режимі; vbe — число або масив."""
    ef = np.exp(vbe / (p['NF'] * Vt))
    er = np.exp(vbc / Vt)
    q1 = 1.0 / (1.0 - vbc / p['VAF'])                  # звуження бази (Ерлі)
    q2 = (p['IS'] / p['IKF']) * (ef - 1.0)             # високий рівень інжекції
    qb = 0.5 * q1 * (1.0 + np.sqrt(1.0 + 4.0 * q2))    # нормований заряд бази
    ic = p['IS'] / qb * (ef - er)
    ib = p['IS'] / p['BF'] * (ef - 1.0) + p['ISE'] * (np.exp(vbe / (p['NE'] * Vt)) - 1.0)
    return ic, ib, ic / ib

vbe = np.linspace(0.30, 0.85, 400)
ic, ib, beta = gummel_poon(vbe)          # V_BC = 0 — це і є графік Ґуммеля

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 4))
ax1.semilogy(vbe, ic, label='I_К'); ax1.semilogy(vbe, ib, label='I_Б')
ax1.set_xlabel('V_BE, В'); ax1.set_ylabel('струм, А'); ax1.legend(); ax1.grid(True, which='both')
ax2.semilogx(ic, beta); ax2.set_xlabel('I_К, А'); ax2.set_ylabel('β'); ax2.grid(True)
plt.tight_layout(); plt.show()

i = beta.argmax()
print(f"β_макс = {beta[i]:.0f} при I_К = {ic[i]*1e3:.1f} мА;  BF = {p['BF']}")
```

Двадцять п'ять рядків — і ліва панель показує дві криві графіка Ґуммеля, а права — той самий дзвін β, який знімають на тестері. Жодного симулятора: усередині нього для цієї деталі крутиться рівно ця арифметика.

Звірмо кілька точок, щоб переконатися, що це не «майже те»:

**Перевірка β у трьох напругах (2N3904, Vₜ = 25.85 мВ).**

```
V_BE = 0.55 В:  I_К = 1.17·10⁻⁵ А   I_Б = 1.75·10⁻⁷ А   q_b = 1.000   β = 66.8
V_BE = 0.70 В:  I_К = 3.67·10⁻³ А   I_Б = 2.40·10⁻⁵ А   q_b = 1.055   β = 152.6
V_BE = 0.80 В:  I_К = 8.27·10⁻² А   I_Б = 7.63·10⁻⁴ А   q_b = 2.239   β = 108.4
```

Три різні β з одного транзистора — і саме такий дзвін тестер знімає з живого 2N3904: унизу його рубає витік у базі, угорі — роздутий інжекцією q_b (майже втричі при 0.80 В).

## Перше, що вибиває з колії: `BF` — не те β, що вимірюєш

Запустіть код — і `print` видасть дещо несподіване:

```
β_макс = 160 при I_К = 10.2 мА;  BF = 416.4
```

Пікове β цього транзистора — близько **160**, а параметр `BF` у рядку — **416**. Не округлення, не помилка: пік удвічі з половиною менший за «пряме β». Хто читає `BF` як «коефіцієнт підсилення транзистора», щойно програв фізиці.

Причина — у тому, що на 2N3904 просто немає чистого «ідеального вікна». Порахуймо, де що бере гору. Ідеальна частина струму бази наздоганяє витік лише при

```
V_BE, де (I_S/BF)·e^(V/Vₜ) = ISE·e^(V/(NE·Vₜ))   →   V_BE ≈ 0.758 В
```

а високий рівень інжекції (q₂ = 1, тобто ідеальний I_К дорівнює IKF = 66.78 мА) починається вже при

```
V_BE = NF·Vₜ·ln(IKF/I_S) ≈ 0.774 В
```

Вікно між цими двома напругами — якихось 16 мілівольтів. Витік панує в струмі бази мало не до самого порога інжекції; щойно він відступає, q_b уже роздимається й тягне I_К вниз. Ідеальна ділянка, де β дорівнювало б `BF`, майже не встигає відкритися. Тому `BF` — це **асимптота**, число, до якого β прямувало б, якби витік і інжекція чемно розступилися. У реального 2N3904 вони не розступаються, і пік β застряє на 160 — рівно там, де його показує даташит (h_FE типово 100–300).

> 🔧 **Навіщо це.** Проєктуючи струмове дзеркало чи джерело струму, ви ділите на β похибку. Візьмете `BF` = 416 замість реального β ≈ 150 — і закладете вчетверо меншу помилку, ніж буде. Правильний β — не з рядка `.model`, а з піку дзвону, порахованого при вашому робочому струмі. Той самий код вище дає його за секунду.

## Зворотна задача: витягти числа з кривих

Тепер навпаки. Виробник не вигадав ці двадцять чисел — він зняв графік Ґуммеля та вихідні характеристики й **видобув** параметри з форми кривих. Кожен параметр лишає на графіку свій, ні на що не схожий підпис; уся справа — знати, де дивитися.

![Мапа видобування: яка риса графіка Ґуммеля дає який параметр](/book/electronics/analog/gummel-poon/img/extract-map.svg)

*Кожна риса кривої видає свій параметр. Середня пряма I_К дає I_S (перетин) і NF (нахил); проміжок між прямими на плато — це ln β, тобто BF; низьке пологіше коліно I_Б дає ISE й NE; коліно, де I_К відстає від прямої, — це IKF. Напруга Ерлі VAF на цьому графіку невидима: її знімають окремо, з нахилу плато вихідної кривої I_К–V_CE.*

Щоб побачити, що метод справді повертає закладені числа, зробімо чесний експеримент: **синтезуймо «виміряні» криві з відомого приладу**, домішаймо трохи шуму — і спробуймо відновити параметри наосліп, звіряючи наприкінці з істиною. Візьмімо чистий модельний транзистор із добре рознесеними зонами (щоб кожен параметр проявився наодинці): `IS=1e-14, BF=250, NF=1, VAF=80, IKF=80 мА, ISE=8e-13, NE=2`.

```py
# «виміряні» криві синтезуємо з відомого приладу — щоб було з чим звіряти
true = dict(IS=1e-14, BF=250.0, NF=1.0, VAF=80.0, IKF=80e-3, ISE=8e-13, NE=2.0)
vbe = np.arange(0.30, 0.85, 0.01)
ic0, ib0, _ = gummel_poon(vbe, p=true)
rng = np.random.default_rng(0)
ic_m = ic0 * np.exp(0.01 * rng.standard_normal(vbe.size))   # ±1% шуму виміру
ib_m = ib0 * np.exp(0.01 * rng.standard_normal(vbe.size))
beta_m = ic_m / ib_m

def fit_log_line(v, y, lo, hi):
    """нахил a та перетин b для ln y = a·v + b на відрізку [lo, hi]"""
    m = (v >= lo) & (v <= hi)
    a, b = np.polyfit(v[m], np.log(y[m]), 1)
    return a, b

# I_S та NF — із СЕРЕДНЬОЇ прямої I_К (де q_b≈1 і витік уже позаду)
a, b = fit_log_line(vbe, ic_m, 0.50, 0.62)
NF_x = 1.0 / (a * Vt);   IS_x = np.exp(b)

# ISE та NE — із НИЗЬКОСТРУМОВОГО коліна I_Б (там панує лише витік)
a, b = fit_log_line(vbe, ib_m, 0.30, 0.40)
NE_x = 1.0 / (a * Vt);   ISE_x = np.exp(b)

# BF — це ПЛАТО β (де обидві прямі йдуть в унісон, проміжок сталий)
BF_x = beta_m.max()

# IKF — струм, де β впало до 0.618 плато з боку ВЕЛИКИХ струмів
peak = beta_m.argmax()
tail = np.arange(peak, vbe.size)
j = tail[np.argmax(beta_m[tail] < 0.618 * BF_x)]
IKF_x = 1.618 * ic_m[j]

# VAF — з ОКРЕМОГО знімка: I_К проти V_CE при сталому V_BE (нахил плато)
vce = np.arange(1.0, 6.0, 0.5)
ic_out = np.array([gummel_poon(0.62, vbc=0.62 - v, p=true)[0] for v in vce])
slope, _ = np.polyfit(vce, ic_out, 1)
VAF_x = ic_out[0] / slope - vce[0]

for name, got, ref in [("IS ", IS_x, true['IS']), ("NF ", NF_x, true['NF']),
                       ("BF ", BF_x, true['BF']), ("VAF", VAF_x, true['VAF']),
                       ("IKF", IKF_x*1e3, true['IKF']*1e3),
                       ("ISE", ISE_x, true['ISE']), ("NE ", NE_x, true['NE'])]:
    print(f"{name}:  видобуто {got:10.4g}   істина {ref:10.4g}")
```

Що друкує цей код:

```
IS :  видобуто  1.061e-14   істина      1e-14
NF :  видобуто      1.003   істина          1
BF :  видобуто      236.7   істина        250
VAF:  видобуто      79.38   істина         80
IKF:  видобуто      112.7   істина         80
ISE:  видобуто  6.307e-13   істина      8e-13
NE :  видобуто      1.919   істина          2
```

Придивімося до цифр — вони чесніші за гасло «метод працює». Нахили лягли точно: NF = 1.003, NE близько двох, VAF на відсоток. А от **перетини й коліно поповзли систематично**: I_S завищене на 6 %, ISE занижене на чверть, IKF завищене на 40 %. Шум тут лише 1 % — отже це не розкид виміру, а вбудований нахил самого графічного методу, і кожен зсув має свою причину. Розберімо логіку кожного видобутку разом із його межею.

**I_S і NF — із середньої прямої.** Там, де q_b ще коло одиниці й витік уже відступив, I_К = I_S·e^(V_BE/(NF·Vₜ)). Логарифм робить це прямою: ln I_К = ln I_S + V_BE/(NF·Vₜ). Нахил дає NF (перевірка ідеальності: далеко від 1 — щось не так із приладом), перетин при V_BE = 0 — це ln I_S. Одна лінійна регресія — і два параметри в кишені. Але зверніть увагу на пастку перетину: I_S — це екстраполяція на пів вольта, тобто на ~20 Vₜ ліворуч від даних, тож похибка нахилу множиться на цю довжину. Мізерні 0.3 % у NF роздимаються в I_S до 6 % (1.06·10⁻¹⁴ замість 10⁻¹⁴). **Нахили завжди певніші за перетини** — це наскрізне правило будь-якого видобування.

**ISE і NE — із низу I_Б.** Найнижче по струму крива бази йде **власною**, пологішою експонентою — це чистий витік ISE·e^(V_BE/(NE·Vₜ)), бо ідеальний доданок там ще в β разів менший. Та сама лінійна регресія по log I_Б на низькому відрізку: нахил → NE, перетин → ISE. NE вийшло 1.92 — трохи занижене, бо на верхньому краю вікна вже підмішується крутіший ідеальний доданок і тягне нахил донизу. А ISE — знову перетин — успадковує цю похибку нахилу й падає на 21 %. Обидва зсуви лікуються тим самим: вужчим низькострумовим вікном і чеснішим стартом.

**BF — це висота плато β.** Найпростіше з усіх: там, де обидві прямі йдуть в унісон, β виходить на пласку вершину — просто `beta.max()`. Вершина 236.7 не дотягла до 250 на 5 %, і це закономірно: β_пік **завжди** трохи нижчий за BF, бо навіть на плато q_b уже почав рости, а витік ще не зовсім згас, тож повного ідеального відношення не буває. На нашому чистому приладі недотяг — 5 %; на реальному 2N3904, як ми бачили, він сягає 2.6 раза. «BF із плато» тим точніший, чим ширші рознесені зони.

**IKF — найгидкіший.** Струм коліна ловлять із боку великих струмів: у чистій інжекції q_b ≈ √q₂, тож β = BF/q_b, і в точці q₂ = 1 (де ідеальний I_К саме дорівнює IKF) маємо q_b = ½(1+√5) = 1.618, отже β = 0.618·BF. Знаходимо, де β впало до 0.618 плато, і множимо тамтешній I_К на 1.618. Метод дав 113 мА замість 80 — на 40 % більше, і це не випадковість: поріг 0.618·BF ми беремо від уже заниженого β_піку, та й сама точка сидить на зігнутій кривій, де все «пливе». `IKF` завжди видобувають найгірше з усіх DC-параметрів.

**VAF — з іншого графіка.** Оскільки на графіку Ґуммеля (V_BC = 0) напруги Ерлі не видно, її знімають окремим прогоном: тримають V_BE сталим, женуть V_CE — і плато I_К легенько повзе вгору саме через [ефект Ерлі](book:electronics/early-effect). Нахил плато dI_К/dV_CE разом зі значенням струму дає VAF = I_К/нахил − V_CE: продовжені вліво, усі лінії плато сходяться в точці −VAF на осі напруги.

Звідси головний висновок про видобування, який відрізняє новачка від інженера-характеризатора: **графічні readout-и — це не остаточні числа, а карта й гарний перший здогад.** Вони кажуть, яка риса кривої за який параметр відповідає, і дають старт у межах кількох відсотків для нахилів і десятків — для перетинів та коліна. Точні числа виробник дістає інакше: **нелінійним припасуванням усієї моделі до всієї виміряної кривої одразу** (`scipy.optimize.curve_fit` чи фаховий екстрактор), стартуючи саме з цих графічних оцінок. Глобальний фіт розмазує похибку рівномірно й не залежить від вдало обраного вікна — але без графічного здогаду він або не збіжиться, або сповзе в хибний мінімум. Тому обидва кроки потрібні: очима — карту, солвером — точність.

## Складність і пастки

Тридцять рядків коду відтворюють транзистор — але між «порахувати рівняння» і «симулювати схему» лежать три ями, у кожну з яких падають реальні проєкти.

**Збіжність.** Наш код лише **обчислює** рівняння в заданій точці — і тому не має проблем: e^(0.85/Vₜ) ≈ e³³ ≈ 10¹⁴ спокійно вміщується у float64. Але симулятор розв'язує кола [методом Ньютона](book:electronics/spice-simulation), а там та сама експонента стає джерелом лиха. Її похідна — це [крутість g_m = I_К/Vₜ](book:electronics/transconductance), і вона росте зі струмом без стелі; біля відкритого переходу якобіан стає майже виродженим, і крок Ньютона перестрибує розв'язок, вганяючи V_BE у ще крутішу частину експоненти. Тому симулятори не беруть модель голою: вони **обмежують стрибок напруги переходу** за ітерацію (junction limiting) і додають до кожного вузла крихітну провідність `GMIN`, щоб матриця ніколи не була строго виродженою. Коли ваш SPICE пише «No convergence» на схемі з транзистором, винна майже завжди ця стрімкість, а не топологія: рятують менший крок, більший `GMIN` або м'якший старт (`.option` чи gmin-stepping).

**Температура.** Усі числа в рядку `.model` зняті при 300 К, і симулятор перераховує їх на робочу температуру за трьома показниками — `XTI`, `EG`, `XTB`. Струм насичення летить угору найшвидше:

```py
k, q = 1.380649e-23, 1.602177e-19
def at_T(p, T, Tnom=300.0):
    r = dict(p)
    r['IS'] = p['IS'] * (T/Tnom)**p.get('XTI',3) \
              * np.exp(q*p.get('EG',1.11)/k * (T - Tnom)/(T*Tnom))
    r['BF'] = p['BF'] * (T/Tnom)**p.get('XTB',1.5)
    return r, k*T/q                     # також повертає Vₜ(T)
```

Порахуймо, наскільки лютий цей перерахунок для 2N3904 (XTI=3, EG=1.11, XTB=1.5):

```
T = 250 K (−23 °C):  I_S × 0.00011   Vₜ = 21.5 мВ   BF = 317
T = 300 K (baseline): I_S × 1         Vₜ = 25.9 мВ   BF = 416
T = 350 K (+77 °C):  I_S × 732        Vₜ = 30.2 мВ   BF = 525
T = 398 K (+125 °C): I_S × 90000      Vₜ = 34.3 мВ   BF = 636
```

Струм насичення від кімнатної до 125 °C зростає у дев'яносто тисяч разів. Ось чому при сталому V_BE колекторний струм скажено біжить із нагрівом, а біполярні каскади зміщують **сталим струмом**, не сталою напругою. Обернений бік того самого: щоб утримати сталий I_К, напругу V_BE доводиться опускати — у цій моделі приблизно на **−1.7 мВ на кожен градус** (звідси знайомий інженерний орієнтир «близько −2 мВ/°C»):

```
I_К = 1 мА:  V_BE(275 K) = 0.709 В → V_BE(325 K) = 0.622 В   (−1.7 мВ/K)
```

Саме ця пара — крутий підйом I_S і опускання V_BE — і живить [тепловий розгін](book:electronics/bjt-thermal-runaway): гарячіша ділянка кристала бере на себе більший струм, гріється ще дужче й тягне струм на себе, поки не спалить перехід. Модель це передбачає, тільки-но ви ввімкнете температурний аналіз; без нього — ні.

**Межі застосування.** Рядок `.model` чесний рівно настільки, наскільки чесно його зняли, і сама модель Ґуммеля — Пуна має свою стелю. По-перше, **зворотні параметри зазвичай грубі**: у нашій картці `ISE` дорівнює `IS`, а `ISC` = 0 — це не виміряні числа, а заглушки. Для прямого підсилювача байдуже, але транзистор у насиченні чи ключ, заведений в інверсію, змоделюється абияк. По-друге, Ґуммель — Пун **не знає квазінасичення** (розширення бази в слабко легований колектор при великому струмі) і **саморозігріву** окремого пальця; опір бази `RB` вона хоч і вміє робити струмозалежним (`IRB`, `RBM`), але спрощено. Для звичайних кіл на дискретних транзисторах цього з головою; а для НВЧ-приладів, кремній-германієвих гетеропереходів чи силових IGBT симулятор бере нащадків — **VBIC, Mextram, HICUM**, — де ці ефекти дописані поверх того самого заряд-контрольного ядра.

Підсумок простий. Рядок `.model` — не магія, а двадцять коефіцієнтів до п'яти формул; тридцять рядків Python перетворюють його на ті самі криві, що й повний симулятор, і назад — виміряні криві на ці двадцять чисел. Щойно ви це проробили руками, ви більше не берете чужу модель на віру: ви знаєте, яка риса кривої за яке число відповідає, де воно точне, а де — ввічлива заглушка.
