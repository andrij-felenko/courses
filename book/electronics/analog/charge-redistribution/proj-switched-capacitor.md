# ⚙️ Скільки тримати ключ вибірки: розрахунок часу для АЦП

Вбудований АЦП «запам'ятовує» вхідну напругу, заряджаючи нею крихітний конденсатор вибірки крізь опір джерела й відкритого ключа. Якщо не дати цьому конденсатору зарядитися до кінця — показання систематично занижені й тим сильніше «пливуть», чим швидше ви опитуєте вхід. Ось як порахувати мінімальний час вибірки, щоб заряд устиг перетекти, і код, що переводить цей час у такти АЦП.

З погляду мікроконтролера SC-вузол найчастіше захований **усередині** периферійного АЦП — і керування ним зводиться до одного-двох параметрів: **час вибірки** (скільки тактів ключ тримати замкненим, щоб конденсатор устиг зарядитися) і **частота перетворень**. Це і є той «перший байт», який ви насправді пишете, коли працюєте з таким вузлом.

Розгляньмо це на прикладі типового вбудованого АЦП послідовного наближення (його ядро — це і є SC-схема перерозподілу заряду). У реєстрі вибірки задається число тактів, протягом яких відкрито ключ вибірки. Замало тактів — конденсатор не дозарядиться, результат занижений; забагато — даремно втрачаєте швидкість. Розрахунок мінімального часу йде саме з RC-сталої вхідного кола.

**Умова: вхідний конденсатор вибірки C_вх = 4 пФ, опір відкритого ключа разом із джерелом R = 1 кОм. Скільки треба тримати ключ, щоб похибка заряду впала нижче ½ молодшого розряду 12-бітного АЦП?**

Конденсатор заряджається за експонентою, і щоб похибка стала меншою за 1 частину з 2¹², треба перечекати приблизно ln(2¹²) ≈ 8.3 сталих часу (округлюють до 9–10 для запасу):

```
τ        = R · C_вх = 1000 · 4·10⁻¹²  = 4 нс
N_τ      = ln(2¹²)  ≈ 8.3            (стільки τ на 12 розрядів)
t_вибірки = 9 · τ    = 9 · 4 нс       = 36 нс  (з запасом)
```

А в коді це виглядає так — ви просто переводите цей час у такти АЦП і кладете в реєстр:

```c
// Мінімальний час вибірки для заряду конденсатора SAR-АЦП до ½ LSB.
// Вхід: опір джерела+ключа (Ом), ємність вибірки (Ф), розрядність, частота такту АЦП (Гц).
// Повертає потрібне число тактів вибірки (округлене вгору).
#include <math.h>
#include <stdint.h>

uint32_t sample_clocks(float r_ohm, float c_farad, uint8_t bits, float adc_hz) {
    float tau      = r_ohm * c_farad;          // стала часу вхідного кола
    float n_tau    = (float)bits * 0.6931f;    // ln(2^bits) = bits·ln2
    float t_sample = (n_tau + 1.0f) * tau;     // +1 τ запасу
    float clocks   = t_sample * adc_hz;        // час → такти
    return (uint32_t)ceilf(clocks);
}

// Приклад: R=1 кОм, C=4 пФ, 12 біт, такт АЦП 20 МГц
uint32_t n = sample_clocks(1000.0f, 4e-12f, 12, 20e6f);  // ≈ 1 такт (округлено вгору)
```

Якщо джерело «слабке» (великий R), формула одразу покаже: потрібен непомірно довгий час вибірки — сигнал, що джерело треба буферувати. Це і є практичний бік усього класу: ви не «налаштовуєте АЦП наосліп», а рахуєте, чи встигне заряд перетекти, бо в основі — той самий перерозподіл заряду між ємностями, лише з годинником.

> 🔧 **Навіщо це.** Найпоширеніша «загадкова» помилка новачка з вбудованим АЦП: показання занижені й «пливуть» тим сильніше, чим швидше опитуєш. Майже завжди причина — закороткий час вибірки при зависокому опорі джерела: конденсатор вибірки фізично не встигає зарядитися. Розуміння SC-природи входу перетворює цю «магію» на просту арифметику RC — збільшити час вибірки, зменшити опір джерела або поставити буфер.
