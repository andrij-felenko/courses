# 🧮 Часовий бюджет I²C: звідки береться множник 0.8473

Усі часові межі I²C виростають з одного рівняння — заряду ємності шини крізь резистор підтяжки, — і тут вони виводяться по черзі: множник 0.8473 у формулі максимальної підтяжки, стеля часу наростання, мінімальні півхвилі такту й вікна встановлення та тримання даних. Кожне число спершу отримуємо самі, а потім звіряємо з першоджерелом — специфікацією NXP **UM10204** (Rev. 5, 9 жовтня 2012, таблиці 9 і 10); самі значення параметрів без виводу зібрано окремо, у [довіднику з протоколу](topic:electronics/i2c/api-i2c.md).

---

## Рівняння фронту

Лінія в стані «1» — це ємність шини Cb, яку крізь резистор підтяжки Rp заряджає живлення VDD. Струм у резисторі та струм у ємність — той самий струм, і цього досить, щоб скласти рівняння:

```
i = (VDD − V) / Rp        закон Ома на резисторі
i = Cb · dV/dt            означення ємності
⟹  Rp·Cb · dV/dt = VDD − V
```

Розв'язувати його зручніше не для напруги, а для **залишку** — того, чого ще бракує лінії до повного рівня. Позначимо Δ = VDD − V. Тоді dΔ/dt = −dV/dt, і рівняння стає найпростішим із можливих:

```
Rp·Cb · dΔ/dt = −Δ        ⟹        Δ(t) = Δ₀ · e^(−t/RC),   RC = Rp·Cb
```

Це те саме [експоненційне рівняння](topic:math/exponential-ode), де швидкість спаду пропорційна самій величині; його розв'язок — спадна експонента зі [сталою часу](topic:electronics/rc-time-constant) RC. Читати його треба так: **за кожен інтервал RC залишок меншає в e ≈ 2.718 раза, і байдуже, звідки почати відлік**. Саме ця байдужість до початку зараз дасть увесь результат.

Для напруги на лінії те саме виглядає звичніше: V(t) = VDD − Δ₀·e^(−t/RC), а якщо фронт починається з чистого нуля, то Δ₀ = VDD і V(t) = VDD·(1 − e^(−t/RC)).

## Два пороги і число ln(7/3)

Вхід мікросхеми не бачить напруги — він бачить, з якого боку від порога вона опинилася. Специфікація задає пороги як частки живлення: нижче **0.3·VDD** — гарантований «0», вище **0.7·VDD** — гарантована «1», а між ними смуга, де нічого не обіцяно ([логічні рівні це діапазони](topic:electronics/logic-levels-as-ranges), а не точки). Тому час наростання t_r за означенням — не «весь підйом», а час переходу саме між цими двома перетинами. Знайдімо обидва моменти.

**Перетин порогів на фронті, що починається з нуля.**
```
V(t₁) = 0.3·VDD:   0.3 = 1 − e^(−t₁/RC)   ⟹   e^(−t₁/RC) = 0.7   ⟹   t₁ = RC·ln(1/0.7)
V(t₂) = 0.7·VDD:   0.7 = 1 − e^(−t₂/RC)   ⟹   e^(−t₂/RC) = 0.3   ⟹   t₂ = RC·ln(1/0.3)

t_r = t₂ − t₁ = RC·[ln(1/0.3) − ln(1/0.7)] = RC·ln(0.7/0.3) = RC·ln(7/3)

t₁ = 0.3567·RC,   t₂ = 1.2040·RC,   t_r = 0.8473·RC
ln(7/3) = 0.847297860…
```

Ось і все походження числа 0.8473: це логарифм відношення двох порогів, а не емпіричний коефіцієнт і не підгін під вимірювання. Різниця двох логарифмів згорнулася в логарифм частки за звичайною [властивістю логарифма](topic:math/logarithms) — і в цій частці 0.7/0.3 напруга живлення скоротилася сама собою.

Скорочення VDD — не випадковість цього конкретного викладу, і варто побачити його в загальному вигляді. Візьмімо фронт, що починається з довільного рівня V₀ нижче за 0.3·VDD (реальна лінія стартує не з нуля, а з залишкової напруги VOL на відкритому транзисторі):

**Той самий t_r без припущення про початок.**
```
у мить перетину нижнього порога залишок  Δ₁ = VDD − 0.3·VDD = 0.7·VDD
у мить перетину верхнього порога залишок  Δ₂ = VDD − 0.7·VDD = 0.3·VDD

Δ спадає експонентою, тож час між двома значеннями залишку:
   t_r = RC · ln(Δ₁/Δ₂) = RC · ln(0.7·VDD / 0.3·VDD) = RC · ln(7/3)
```

Ані VDD, ані початковий рівень V₀ у відповідь не входять — вони скоротилися разом із Δ₀. Наслідок практичний: **той самий множник 0.8473 обслуговує шину на 5 В, на 3.3 В і на 1.8 В однаково**, і він не міняється від того, наскільки глибоко вихід притиснув лінію перед тим, як її відпустити. Фронт, що стартує вище, перетне обидва пороги раніше — але проміжок між перетинами лишиться той самий.

Найкраще це видно, якщо намалювати не напругу, а залишок, і по вертикалі відкласти логарифм. Тоді експонента стає прямою з нахилом −1/RC, а час між двома рівнями — просто горизонтальна відстань між двома горизонталями.

![Дві панелі. Ліворуч крива заряду V(t) від нуля до VDD з пунктирними порогами 0.3·VDD і 0.7·VDD, позначеними моментами t₁ і t₂ та дужкою t_r між ними. Праворуч той самий процес, але по вертикалі відкладено залишок до VDD у логарифмічному масштабі: залишок лягає в пряму, пороги стають двома горизонталями 0.7·VDD і 0.3·VDD, і горизонтальна відстань між їхніми перетинами з прямою — той самий t_r.](img/rc-thresholds.svg)

*Час наростання — відстань між двома перетинами; у логарифмічній осі вона перетворюється на різницю логарифмів, тобто на логарифм відношення 7/3.*

Звідси одразу видно, наскільки все залежить від **вибору порогів**, а не від фізики фронту:

```
пороги 0.3 … 0.7  (I²C)         →  ln(7/3) = 0.8473
пороги 0.2 … 0.8                →  ln(4)   = 1.3863   у 1.64 раза довше
пороги 0.1 … 0.9  (осцилограф)  →  ln(9)   = 2.1972   у 2.59 раза довше
```

Осцилографи за замовчуванням міряють наростання від 10 % до 90 %, тому ту саму лінію прилад і специфікація описують різними числами. Виміряні на екрані 700 нс перераховуються в порогову пару I²C простим діленням констант:

```
t_r(30…70 %) = 700 нс · 0.8473 / 2.1972 = 270 нс
```

Отже шина вкладається у стелю швидкого режиму (300 нс), хоч на екрані число здається більш ніж удвічі завеликим. Плутанина конвенцій — звичайна причина, чому «фронт не в допуску, а шина працює».

Є й зворотний бік. Пороги 0.3 і 0.7 — це гарантія специфікації, а конкретний вхід перемикається десь усередині смуги й ще й має гістерезис не менш як 0.05·VDD ([тригер Шмітта](topic:electronics/schmitt-trigger) навмисно рознесе поріг «вгору» й поріг «вниз»). Якщо реальний вхід зарахує «1» лише на 0.75·VDD, дорога від нижнього порога до нього подовшає:

```
RC·ln(0.7/0.25) = 1.0296·RC     на 21.5 % більше за 0.8473·RC
```

Ці двадцять відсотків і є та частина запасу, яку з'їдає розкид порогів, — тому опір беруть не впритул до верхньої межі.

## Дві межі на підтяжку і точка, де вікно зачиняється

Опір підтяжки затиснуто з двох боків, і обидві межі тепер записуються одразу. Згори тисне фронт: він не сміє тривати довше за дозволене, а тривалість пропорційна опору.

```
t_r = 0.8473 · Rp · Cb ≤ t_r,макс        ⟹        Rp,макс = t_r,макс / (0.8473 · Cb)
```

Знизу тисне здатність виходу притягнути «0». Коли транзистор притиснув лінію, крізь підтяжку тече струм (VDD − VOL)/Rp, і весь він мусить пройти крізь той транзистор, не піднявши на ньому напругу вище за VOL:

```
Rp,мін = (VDD − VOL,макс) / IOL,мін
```

Далі найцікавіше запитання, якого зазвичай не ставлять: а чи завжди між цими межами взагалі щось є? Вікно існує лише поки Rp,мін ≤ Rp,макс, і ця нерівність легко розв'язується відносно ємності:

**Найбільша ємність, за якої вікно підтяжки ще не порожнє.**
```
(VDD − VOL)/IOL ≤ t_r,макс/(0.8473·Cb)

⟹   Cb,макс = IOL · t_r,макс / (0.8473 · (VDD − VOL))
```

Підставмо найгірший випадок звичайного п'ятивольтового вузла у швидкому режимі. Живлення 5 В із допуском +10 % дає 5.5 В; специфікація вимагає від виходу приймати 3 мА, лишаючись під VOL = 0.4 В; стеля фронту — 300 нс.

**Швидкий режим, VDD = 5.5 В, вихід на 3 мА.**
```
Rp,мін  = (5.5 − 0.4) / 0.003 = 1700 Ом
Cb,макс = 0.003 · 300·10⁻⁹ / (0.8473 · 5.1) = 2.08·10⁻¹⁰ Ф ≈ 208 пФ
```

Специфікація розбирає рівно цей приклад у розділі про перемикану підтяжку й називає «близько 200 пФ» — збіг до округлення. А тепер повторімо з виходом, який тримає 6 мА за VOL = 0.6 В:

```
Rp,мін  = (5.5 − 0.6) / 0.006 = 817 Ом
Cb,макс = 0.006 · 300·10⁻⁹ / (0.8473 · 4.9) = 4.34·10⁻¹⁰ Ф ≈ 434 пФ  >  400 пФ
```

Ось звідки в таблиці електричних параметрів окремим рядком стоїть вимога «6 мА за VOL = 0.6 В, щоб витягнути повне навантаження на 400 кГц». З виходом на 3 мА нерівність не виконується вже на 208 пФ: **не існує жодного опору, який задовольнив би обидві межі одночасно**. Слабкому виходові бракує не швидкості — йому бракує права на достатньо малий резистор.

![Графік: по горизонталі ємність шини від 100 до 600 пФ, по вертикалі опір підтяжки від 0 до 2600 Ом. Спадна крива Rp,max = t_r/(0.8473·Cb) для t_r = 300 нс; дві горизонтальні лінії Rp,min — 1700 Ом для виходу на 3 мА і 817 Ом для виходу на 6 мА; вертикальна пунктирна лінія на 400 пФ. Крива перетинає лінію 1700 Ом на 208 пФ і лінію 817 Ом на 434 пФ.](img/rp-window.svg)

*Вікно опору — вузький клин між спадною кривою фронту й горизонталлю мінімального опору; він зачиняється там, де вони перетинаються, і сильніший вихід відсуває цю точку праворуч.*

> 🔧 **Навіщо це.** Формула Cb,макс відповідає на питання, яке не має відповіді в жодній таблиці: чи взагалі можлива задумана шина. Якщо порахована ємність (по ~10 пФ на кожен вивід кожної мікросхеми плюс доріжки) перевищує Cb,макс для вашого живлення, режиму й струму виходів, то підбирати опір безглуздо — треба міняти вихідні каскади, ділити шину буфером на сегменти або спускатися на нижчу частоту.

Та сама пара нерівностей пояснює й долю славнозвісних 4.7 кОм. Питання ставимо навпаки: яку ємність цей опір іще витягує?

```
Cb ≤ t_r,макс / (0.8473 · 4700):
   стандартний режим  (t_r ≤ 1000 нс)  →  Cb ≤ 251 пФ
   швидкий режим      (t_r ≤  300 нс)  →  Cb ≤  75 пФ
   швидкий-плюс       (t_r ≤  120 нс)  →  Cb ≤  30 пФ
```

Кожен вивід мікросхеми додає до 10 пФ, тож 75 пФ — це приблизно три-чотири чипи разом із кількома сантиметрами доріжки. Отже 4.7 кОм — це не «типове значення», а цілком конкретний резистор стандартного режиму на короткій шині; у швидкому він тримається лише на майже порожній платі. Звідси й правило [добирати підтяжку під конкретну шину](topic:electronics/i2c-pull-up-resistor), а не переносити те саме число з проєкту в проєкт.

## Спад: інша фізика, інша формула

Угору лінію тягне резистор, а вниз — транзистор, і це вже не той самий процес. Транзистор, щойно відкрившись, працює радше як джерело струму: доки напруга на ньому велика, він забирає з ємності приблизно постійний струм IOL. Тоді замість експоненти виходить пряма:

```
Cb · dV/dt = −IOL   ⟹   t_f ≈ Cb · ΔV / IOL,   ΔV = 0.7·VDD − 0.3·VDD = 0.4·VDD
```

Перевірмо цим найгірший дозволений випадок звичайних режимів — повна ємність 400 пФ на тій самій п'ятивольтовій шині з допуском (5.5 В), стеля спаду 300 нс:

```
потрібний струм = 400·10⁻¹² · 0.4·5.5 / 300·10⁻⁹ = 2.93·10⁻³ А = 2.93 мА
```

І саме 3 мА специфікація вимагає від кожного виходу. Тобто мінімальний струм стоку взято не зі стелі: він рівно такий, щоб найбільша дозволена ємність устигла провалитися крізь обидва пороги за відведений час, із запасом хіба на округлення.

Якщо ж моделювати відкритий транзистор не джерелом струму, а опором R_on, спад теж виходить експонентою — і тим самим множником, бо пороги ті самі: t_f = 0.8473·R_on·Cb. Реальний вихід поводиться десь між двома моделями, бо ближче до нуля транзистор виходить із насичення і стає більше схожим на резистор. Для бюджету це не критично: обидві оцінки дають той самий порядок, а спад у будь-якому разі в кілька разів коротший за наростання.

## Період такту: чотири шматки без щілин

Тепер видно, як складається сам такт. Усі чотири часові параметри виміряні від перетинів тих самих порогів, і це робить їхню суму не наближенням, а тотожністю:

```
t_LOW  — від спадного перетину 0.3·VDD до наступного висхідного перетину 0.3·VDD
t_r    — від висхідного 0.3·VDD до висхідного 0.7·VDD
t_HIGH — від висхідного 0.7·VDD до спадного 0.7·VDD
t_f    — від спадного 0.7·VDD до спадного 0.3·VDD

кінець кожного відрізка — початок наступного, а разом вони замикають коло:
   1/f_SCL = t_LOW + t_r + t_HIGH + t_f
```

Підставмо мінімальні значення з таблиці для кожного режиму — і виявиться, що вони не просто вкладаються в період, а вкривають його точно:

```
стандартний:    4.7 + 1.0  + 4.0  + 0.3  = 10.0 мкс = 1/100 кГц
швидкий:        1.3 + 0.3  + 0.6  + 0.3  =  2.5 мкс = 1/400 кГц
швидкий-плюс:   0.5 + 0.12 + 0.26 + 0.12 =  1.0 мкс = 1/1 МГц
```

![Три горизонтальні смуги однакової довжини — по одному періоду такту для стандартного, швидкого й швидкого-плюс режимів. Кожну смугу поділено на чотири кольорові частки: t_LOW, t_r, t_HIGH, t_f, із числом усередині кожної. Під кожною смугою — рівність, у якій ці чотири числа дають рівно період.](img/period-budget.svg)

*Мінімальні півхвилі й максимальні фронти складено так, що на номінальній частоті запасу не лишається зовсім: період поділено між ними без залишку.*

Наслідок жорсткий. Якщо фронт вийшов довшим за стелю, скорочувати доводиться півхвилі — а вони вже на мінімумі. Лишається єдиний хід: знизити частоту рівно настільки, наскільки розтягнувся фронт. Специфікація записує це прямо:

```
f_max = 1 / (t_LOW,мін + t_HIGH,мін + t_r,факт + t_f,факт)
```

Порахуймо для шини, зібраної з тих самих «типових» деталей: підтяжка 4.7 кОм, ємність 200 пФ, живлення 3.3 В, виходи на 3 мА.

**Чи витягне така шина стандартні 100 кГц.**
```
t_r = 0.8473 · 4700 · 200·10⁻¹² = 797 нс          (стеля 1000 нс — тримається)
t_f = 200·10⁻¹² · 0.4·3.3 / 0.003 =  88 нс        (стеля 300 нс — тримається)

f_max = 1 / (4.7 + 4.0 + 0.797 + 0.088) мкс = 1 / 9.585 мкс = 104 кГц
```

Витягне — але із запасом усього 4 %. Досить додати на ту саму шину ще два чипи й пів метра шлейфа, щоб ємність подвоїлася: фронт виросте до 1.59 мкс, вийде за стелю стандартного режиму, а f_max упаде до 96 кГц — обіцяних 100 кГц уже не буде.

## Усередині низької півхвилі: тримання, поява даних, встановлення

Дисципліна шини вимагає, щоб SDA мінялася лише тоді, коли SCL внизу. Отже вся зміна біта мусить уміститися в одну низьку півхвилю, і в ній послідовно стоять три різні речі:

- **тримання** (hold) — старий біт іще стоїть після спаду такту, поки всі приймачі його точно зчитали;
- **поява нового біта** — передавач перемикає SDA, і та доїжджає до свого рівня, витрачаючи власний час наростання;
- **встановлення** (setup) — новий біт стоїть нерухомо перед тим, як SCL піде вгору.

Це та сама пара вимог, що й у будь-якій синхронній логіці: дані не сміють ворушитися ні незадовго до тактового фронту, ні одразу після нього — інакше приймач зафіксує рівень, якого ніхто не надсилав ([порушення тримання](topic:electronics/hold-violation) в цифровій схемі влаштоване точно так само). I²C вимірює їх так: **t_VD;DAT** — від спаду SCL до миті, коли новий біт уже дійсний на лінії, а **t_SU;DAT** — від цієї миті до початку підйому SCL. Нерівність, яку вони мусять задовольнити, випливає з того, що обидва відрізки лежать в одній півхвилі й не накладаються:

```
t_VD;DAT + t_SU;DAT ≤ t_LOW

стандартний:   3.45 + 0.25 = 3.70 ≤ 4.70 мкс      лишається 1.00 мкс
швидкий:       0.90 + 0.10 = 1.00 ≤ 1.30 мкс      лишається 0.30 мкс
швидкий-плюс:  0.45 + 0.05 = 0.50 ≤ 0.50 мкс      не лишається нічого
```

Залишок у перших двох рядках дорівнює точнісінько стелі часу наростання того самого режиму — 1000 нс і 300 нс. Це не збіг, і специфікація сама пояснює його в примітці до параметра встановлення: пристрій, який притримує низьку півхвилю, мусить виставити наступний біт на SDA за **t_r(макс) + t_SU;DAT = 1000 + 250 = 1250 нс** до того, як відпустить SCL. Тобто до чистого встановлення додається повний час наростання лінії — поки SDA повзе вгору, біта ще нема, і відлік встановлення починається лише з моменту, коли вона доповзла.

У швидкому-плюс так уже не виходить: 0.45 + 0.05 + 0.12 = 0.62 мкс проти 0.5 мкс півхвилі. Там час наростання SDA мусить уміститися всередину самого t_VD;DAT — окремого місця під нього не лишили, і це прямий наслідок того, що на 1 МГц бюджет вичерпано до дна.

![Одна низька півхвиля SCL завширшки 1.3 мкс і під нею лінія SDA, що міняє біт. Під ними — лінійка бюджету з трьох частин: t_VD;DAT до 0.9 мкс, t_SU;DAT від 100 нс і залишок 300 нс під час наростання. Окремою стрілкою від перетину SCL рівня 0.7·VDD показано внутрішнє тримання SDA не менш як 300 нс.](img/low-window.svg)

*Низька півхвиля ділиться на три послідовні відрізки, і сума перших двох плюс запас на фронт дорівнює всій півхвилі — місця для четвертого учасника немає.*

Тепер до тримання, з яким пов'язана найпідступніша пастка таблиці: **мінімум t_HD;DAT у ній дорівнює нулю**. Невже дані можна міняти тієї ж миті, коли падає такт? Пастка в тому, що́ вважати миттю падіння. Усі числа таблиці відлічують від перетину порогів, і «SCL низький» для неї означає, що такт **уже перетнув 0.3·VDD**, тобто спад завершився. А приймач перестає довіряти рівню «1» набагато раніше — щойно SCL опускається нижче свого VIH = 0.7·VDD, вхід уже нічого не гарантує, і всередині смуги між 0.7·VDD і 0.3·VDD різні мікросхеми перемкнуться в різні миті. Нуль у таблиці означає лише те, що після завершення спаду тримати більше не треба; сам спад уже покрито.

Покрито окремою вимогою, яка стоїть у примітці, а не в стовпчику: **пристрій зобов'язаний внутрішньо тримати SDA щонайменше 300 нс, відлічуючи від перетину SCL рівня VIH**. Звідки взялося саме це число, видно з тієї самої таблиці: 300 нс — це стеля часу спаду t_f для стандартного й швидкого режимів.

```
внутрішнє тримання ≥ 300 нс = t_f,макс (Sm, Fm)
```

Тобто тримання зроблено рівно таким, щоб цілком перекрити найдовший дозволений спад такту: хоч би де всередині невизначеної смуги перемкнувся конкретний вхід, старий біт іще стоятиме, коли він це зробить. Ось чому передавач, який міняє SDA «одразу за фронтом SCL», може працювати на столі й розсипатися на довшій шині: там спад повільніший, а у власноруч написаному майстрі жодної внутрішньої затримки немає.

Коли ведений розтягує низьку півхвилю, стелі t_VD;DAT перестають діяти — часу в нього стільки, скільки треба. Незмінним лишається одне: дані мусять бути дійсні за t_SU;DAT до того, як він відпустить SCL. Розтягування зсуває межі періоду, але не скасовує вікна встановлення.

## Скільки коштує кадр

Останній поверх бюджету — довжина обміну. Байт займає не вісім тактів, а дев'ять: вісім біт, а тоді окремий такт під підтвердження. Це і є стеля корисності самого формату:

```
8 біт вантажу з 9 тактів  →  8/9 = 88.9 %
```

Обрамлення теж не безкоштовне: START вимагає тримання перед першим тактом, STOP — встановлення перед підйомом SDA, а після нього шина мусить постояти вільною. Складімо ці три числа й порівняймо з періодом такту (з точністю до невеликих перекриттів із сусідніми півхвилями):

```
стандартний:   4.0  + 4.0  + 4.7 = 12.70 мкс = 1.27 періоду
швидкий:       0.6  + 0.6  + 1.3 =  2.50 мкс = 1.00 періоду
швидкий-плюс:  0.26 + 0.26 + 0.5 =  1.02 мкс = 1.02 періоду
```

У всіх трьох режимах обрамлення транзакції коштує приблизно один зайвий такт. Для довгого читання це дрібниця, для короткого — вирок. Порахуймо обидва крайні випадки на 400 кГц, де період такту 2.5 мкс.

**Записати один байт у регістр давача.**
```
кадр: S + [адреса+W] + [номер регістра] + [байт даних] + P
такти:      3 байти · 9 = 27  →  27 · 2.5 мкс = 67.5 мкс
обрамлення: 0.6 + 0.6 + 1.3   =  2.5 мкс
разом ≈ 70.0 мкс на 8 біт корисного вантажу

дійсна швидкість = 8 біт / 70.0 мкс = 114 кбіт/с   — 29 % від номінальних 400
```

**Прочитати 32 байти поспіль (через повторний START).**
```
кадр: S + [адреса+W] + [номер регістра] + Sr + [адреса+R] + 32 байти + P
такти:      9·3 + 9·32 = 315  →  315 · 2.5 мкс = 787.5 мкс
обрамлення: 0.6 + (0.6 + 0.6) + 0.6 + 1.3 = 3.7 мкс
разом ≈ 791 мкс на 256 біт корисного вантажу

дійсна швидкість = 256 біт / 791 мкс = 324 кбіт/с   — 81 % від номіналу
```

Одна й та сама шина віддає то 29 %, то 81 % свого номіналу, і різниця тут не в частоті, а в довжині пакета. Тому на I²C майже завжди вигідніше зчитати кілька сусідніх регістрів одним неперервним читанням, ніж ганяти за кожним окремо: перехід із 400 кГц на 1 МГц дасть виграш у два з половиною рази, а склеювання дрібних звертань в одне — майже втричі.
