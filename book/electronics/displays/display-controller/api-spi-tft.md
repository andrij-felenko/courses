# 🔌 Дисплей класу ST7789/ILI9341: SPI, GRAM, вікна й DMA

Найпоширеніший дрібний кольоровий екран у любительській і серійній техніці — невелика TFT-панель із вбудованим контролером, що сам тримає [пам'ять кадру «на склі»](book:electronics/display-controller) і освіжає її без участі мікроконтролера. Ця вставка конкретизує **як саме** заговорити з таким модулем: які в нього ніжки, як побудувати кадр у його GRAM (англ. *graphics RAM* — «графічна оперативна пам'ять»), де ховаються типові граблі класу й чому DMA тут вирішує. Мова про **клас**, а не про один партномер: контролери ST7789, ILI9341, ST7735, ILI9488 та їхні родичі відрізняються роздільністю й дрібницями регістрів, але фізика підключення й протокол у них спільні.

---

## Клас пристрою

Модуль такого класу — це скляна TFT-панель, наклеєна разом із кристалом-контролером (англ. *controller* — «той, хто керує»; родові імена — від виробників кремнію: ST — STMicroelectronics, ILI — Ilitek, SSD — Solomon Systech). Контролер несе на борту повну **GRAM** під увесь кадр і власний двигун освіження, тому мікроконтролерові не треба ні власної RAM під зображення, ні безперервної роботи: він лише шле команди й змінені пікселі, а далі вільний.

Канонічні представники класу різняться роздільністю, але не способом підключення:

| Контролер | Типова панель | Колір |
|---|---|---|
| **ST7735** | 128×160, 1.8″ | RGB565 |
| **ST7789** | 240×240, 240×320, 1.3–2.0″ | RGB565 |
| **ILI9341** | 240×320, 2.2–2.8″ | RGB565 |
| **ILI9488** | 320×480, 3.5″ | RGB565/RGB666 |

Поруч у тій самій сім'ї дрібних дисплейних контролерів живе й **SSD1306** — але це монохромний OLED 128×64 з кадром по 1 біту на піксель і власним набором команд; фізика шини схожа, та формат кадру інший. Нижче — усе про кольоровий TFT-клас RGB565.

---

## Розпіновка модуля

Типовий SPI-модуль виводить 8 контактів. Чотири з них — звичайний апаратний SPI, ще три — службові ніжки контролера, плюс живлення підсвітки:

| Контакт | Призначення |
|---|---|
| **VCC / GND** | живлення логіки (3.3 В; на 5-вольтових платах потрібен [рівнезсувач](book:electronics/level-shifter)) |
| **SCK** | такт SPI (англ. *serial clock*) |
| **SDA / MOSI** | дані від МК до панелі (англ. *master-out-slave-in*) |
| **CS** | вибір кристала (англ. *chip select*); низький рівень — «слухай мене» |
| **DC / RS** | data/command: рівень розрізняє байт-команду (0) від байта даних (1) |
| **RST** | апаратне скидання контролера (активний нуль) |
| **BLK / LED** | живлення [підсвітки](book:electronics/backlight-dimming) (часто через власний транзистор) |

Ключова особливість класу — окрема ніжка **DC** (інколи звана RS, register select). SPI сам собою передає лише байти й не знає, команда це чи піксель; саме рівень на DC каже контролерові, як трактувати кожен байт. Переплутати DC з іншою ніжкою — найтиповіша причина «екран білий або сміттєвий», бо тоді команди читаються як дані й навпаки.

## Послідовність вмикання

Контролер після подачі живлення сидить у скиді: GRAM не ініціалізована, двигун освіження не запущений, панель темна. Щоб вона ожила, МК має пройти коротку послідовність команд — вона майже однакова для всього класу:

1. **Апаратне скидання** — смикнути RST у нуль на кілька мілісекунд, тоді відпустити (приводить регістри у відоме знане).
2. **Sleep-out** (`0x11`) — вивести контролер зі сну; після команди витримати паузу (типово ~120 мс), доки запуститься внутрішній генератор напруг.
3. **Формат пікселя** (`0x3A`) — задати глибину кольору; значення `0x55` означає RGB565 (16 біт на піксель).
4. **Орієнтація** (`0x36`, MADCTL — memory access control) — порядок розгортки рядків/стовпців і порядок кольорів (RGB ↔ BGR); цим одним регістром панель повертають і дзеркалять.
5. **Display-on** (`0x29`) — увімкнути вивід на скло.

Після цього панель освіжається сама, а МК лишається тільки заливати в GRAM пікселі.

## Кадр у GRAM: вікно адрес і запис

Найважливіша операція класу — **вікно адрес** (англ. *address window*): МК оголошує прямокутник, а тоді ллє в нього пікселі підряд, не рахуючи жодної адреси сам. Три команди задають вікно й відкривають потік: `0x2A` (CASET — діапазон стовпців x0…x1), `0x2B` (RASET — діапазон рядків y0…y1), `0x2C` (RAMWR — писати в пам'ять). Далі контролер сам розкладає кожні два байти кольору по вікні, рядок за рядком, аж доки воно не заповниться.

Кадр у форматі **RGB565** — це 16 біт на піксель: 5 старших бітів червоного, 6 зеленого, 5 синього (зеленому віддали зайвий біт, бо око до нього найчутливіше). Передають старший байт уперед.

> **Умова.** Намалювати один піксель кольору `color` (RGB565) у точці (x, y) на панелі ST7789/ILI9341 по SPI; ніжки CS, DC налаштовані, контролер ініціалізований.

:::tabs
```cpp
#include <stdint.h>

// низькорівневі примітиви платформи (HAL)
void cs_low(void);   void cs_high(void);     // вибір кристала
void dc_command(void); void dc_data(void);   // рівень ніжки DC
void spi_write(const uint8_t *buf, uint32_t n);

static void wr_cmd(uint8_t c)  { dc_command(); spi_write(&c, 1); }
static void wr_data(const uint8_t *b, uint32_t n) { dc_data(); spi_write(b, n); }

void draw_pixel(uint16_t x, uint16_t y, uint16_t color) {
    uint8_t win[4];
    cs_low();

    wr_cmd(0x2A);                                   // CASET: x..x
    win[0] = x >> 8; win[1] = x; win[2] = x >> 8; win[3] = x;
    wr_data(win, 4);

    wr_cmd(0x2B);                                   // RASET: y..y
    win[0] = y >> 8; win[1] = y; win[2] = y >> 8; win[3] = y;
    wr_data(win, 4);

    wr_cmd(0x2C);                                   // RAMWR: писати в пам'ять
    uint8_t px[2] = { color >> 8, color };          // RGB565, старший байт уперед
    wr_data(px, 2);

    cs_high();
}
```
```py
from machine import Pin, SPI

# низькорівневі примітиви платформи (ніжки CS і DC + шина SPI)
spi = SPI(1, baudrate=40_000_000, polarity=0, phase=0)
cs  = Pin(15, Pin.OUT, value=1)   # вибір кристала (активний нуль)
dc  = Pin(2,  Pin.OUT, value=1)   # рівень ніжки DC

def wr_cmd(c):
    dc(0)                          # DC = 0 → команда
    spi.write(bytes([c]))

def wr_data(b):
    dc(1)                          # DC = 1 → дані
    spi.write(b)

def draw_pixel(x, y, color):
    cs(0)

    wr_cmd(0x2A)                                    # CASET: x..x
    wr_data(bytes([x >> 8, x & 0xFF, x >> 8, x & 0xFF]))

    wr_cmd(0x2B)                                    # RASET: y..y
    wr_data(bytes([y >> 8, y & 0xFF, y >> 8, y & 0xFF]))

    wr_cmd(0x2C)                                    # RAMWR: писати в пам'ять
    wr_data(bytes([color >> 8, color & 0xFF]))      # RGB565, старший байт уперед

    cs(1)
```
:::

Один піксель — це навчальний випадок; на практиці так само заливають цілий прямокутник, лише замість двох байтів висипають `width × height` кольорів поспіль (вікно ширше за один піксель, а потік даних — довший). Жодної арифметики адрес у МК немає: уся вона захована в лічильнику контролера.

## Чому тут вирішує DMA

Запис кадру по SPI — це тисячі байтів через одну й ту саму процедуру `spi_write`. Якщо ганяти їх процесором байт за байтом (так званий поллінг), ядро застрягає в циклі «поклади байт у регістр SPI → почекай, доки виллється → наступний», і нічого іншого робити не може. Для панелі 240×320 один повний кадр — це 240 × 320 × 2 = 153 600 байтів; на SPI у 40 МГц це десятки мілісекунд суцільного очікування щотакту.

Рятує [DMA](book:programming/dma-controller) (англ. *direct memory access* — «прямий доступ до пам'яті»): спеціальний апаратний блок сам перекладає байти з буфера в регістр SPI, поки ядро рахує наступний кадр чи спить. МК лише оголошує вікно трьома командами, тоді віддає DMA вказівник на масив пікселів і довжину — і займається своїми справами, доки апаратура виллє весь блок. Саме DMA робить плавну анімацію на таких панелях узагалі можливою; без нього процесор більшість часу просто чекав би SPI.

> 🔧 **Навіщо це.** Малий буфер-смужка плюс DMA — стандартний прийом «бідного» рендеру: тримати не весь кадр, а кілька рядків, малювати їх у RAM МК і виливати DMA-блоком у вікно панелі, поки готуєш наступну смужку. Так на МК із десятками кілобайтів RAM виходить плавно перемальовувати екран, для якого повного кадрового буфера в хості й близько немає місця.

## Типові граблі класу

- **Переплутана ніжка DC/RS.** Команди читаються як дані — екран білий, чорний або заповнений сміттям. Перше, що перевіряти.
- **Замало паузи після sleep-out (`0x11`).** Якщо одразу слати кадр, внутрішні напруги ще не піднялися — панель темна або бліда. Витримуйте ~120 мс.
- **Невідповідний MADCTL (`0x36`).** Зображення дзеркальне, повернуте на 90° або з переставленими кольорами (синє замість червоного) — лікується бітами орієнтації й біта BGR.
- **Зсув вікна на кілька пікселів.** Деякі панелі мають «мертві» рядки/стовпці на краю GRAM; той самий контролер у різних модулях вимагає невеликого зміщення x/y — звідси кольорова смужка по краю.
- **5-вольтова логіка без рівнезсувача.** Контролер живиться 3.3 В; пряме під'єднання до 5-вольтового МК ушкоджує входи або працює «іноді». Ставте [рівнезсувач](book:electronics/level-shifter).
- **Підсвітка напряму від ніжки МК.** BLK тягне десятки міліампер; живіть її через транзистор, а не з [виводу контролера](book:electronics/pin-drive-limits).
- **Поллінг замість DMA на великому кадрі.** Працює, але ядро застрягає на десятки мілісекунд щокадру — анімація смикається, інші задачі простоюють.
- **Спільний SPI без розрулення CS.** Якщо на шині ще пристрої, а CS панелі не знятий між обмінами, чужі байти потрапляють у GRAM. Тримайте CS активним лише на час обміну з панеллю.

## Варіації класу

Усередині класу різниця — здебільшого в роздільності й дрібних регістрах. **ST7735** — найменший (128×160), популярний у крихітних модулях. **ST7789** і **ILI9341** — робоча конячка 240×320, майже взаємозамінні в коді (різні тільки коди ініціалізації й зсуви вікна). **ILI9488** тягне 320×480, але має нюанс: у режимі RGB565 деякі модулі вимагають 18-бітної передачі (RGB666), тож пакування пікселя інше. Поза SPI ті самі кристали часто вміють і **паралельний 8080-інтерфейс** (8 чи 16 ліній даних) — швидший за SPI ціною ніжок; протокол вікон (CASET/RASET/RAMWR) при цьому той самий, міняється лише фізичний спосіб віддати байт. Хоч який варіант — принцип незмінний: контролер тримає GRAM і освіжає скло сам, а МК шле йому команди й вікна пікселів.
