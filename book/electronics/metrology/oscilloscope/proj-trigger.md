# ⚙️ Тригер: алгоритм, що зупиняє хвилю на екрані

Тригер потрібен, щоб періодична хвиля завмерла на екрані; тут — **як** він влаштований усередині: проста умова на кожен відлік, що перетворює мерехтливу кашу на нерухому картинку. Алгоритм навдивовижу дешевий — і саме його ставлять у власні «осцилографи» на мікроконтролері.

## Задача

Осцилограф малює сигнал **знову й знову**, проходячи екран зліва направо. Якщо кожен прохід починати «з будь-де», періодична хвиля щоразу зсувається по фазі — і на екрані виходить розмита пляма. Треба, щоб **кожен** прохід (а в цифровому приладі — кожен захоплений кадр) починався з **однієї й тієї самої точки** сигналу. Якої саме — задає **умова тригера**: сигнал перетинає обраний **рівень** L у обраний **бік** (висхідний чи нисхідний фронт).

## Ідея

![Умова тригера: рівень і фронт](/book/electronics/metrology/oscilloscope/img/edge.svg)
*Висхідний тригер: момент, коли попередній відлік був нижчий за рівень L, а поточний став ≥ L (ліворуч). Обраний фронт (↑ чи ↓) визначає, який перетин ловити, а протилежний ігнорується (праворуч).*

Стежимо за сигналом і ловимо **момент перетину**. Висхідний фронт — це коли **попередній** відлік був **нижчий** за рівень, а **поточний** став **не нижчим**: `prev < L` і `cur ≥ L`. Цей момент і оголошуємо за `t = 0`. В аналоговому осцилографі подія тригера **запускає розгортку**; у цифровому (DSO) відліки безперервно течуть у пам'ять, а тригер лише позначає точку, навколо якої виставити кадр.

Та проста умова має дві відомі вади, і обидві лікують класично.

**Шум.** Якщо сигнал брудний, біля рівня він **дрижить** і перетинає L багато разів поспіль — виходить купа хибних тригерів, картинка знову «біжить».

![Гістерезис і голдофф](/book/electronics/metrology/oscilloscope/img/hysteresis.svg)
*Дві біди простої умови. Шум коло рівня дає купу хибних тригерів (ліворуч); смуга L±h (гістерезис) лишає один чистий (праворуч). Голдофф (внизу) після спрацювання глушить зайві фронти аж до нового періоду.*

Рятує **гістерезис**: замість одного рівня беремо **смугу** L ± h. Тригеримо на перетині `L + h` вгору — і потім **не дозволяємо** наступний тригер, поки сигнал не впаде нижче `L − h`. Дрібне дрижання в межах смуги просто не помічається (це той самий принцип, що в [тригера Шмітта](book:electronics/schmitt-trigger)).

**Складні хвилі.** У пакетного чи багатогорбого сигналу за період є **кілька** придатних фронтів — і тригер стрибає між ними. Тут допомагає **голдофф**: після спрацювання прилад певний час **взагалі не тригерить**, пропускаючи зайві фронти, аж поки не почнеться новий період.

Нарешті, три **режими** на всі випадки: **Auto** — якщо тригера довго нема, розгортка йде сама (бачиш бодай щось); **Normal** — малюємо **лише** на тригер (нема умови — екран порожній); **Single** — зловити **один** кадр і спинитися (для рідкісних подій).

## Реалізація

![Кільцевий буфер: pre- і post-trigger](/book/electronics/metrology/oscilloscope/img/buffer.svg)
*Цифровий осцилограф пише відліки в кільцевий буфер безперервно. На подію тригера він лишає частину буфера ДО неї (pre-trigger) і дописує ще трохи ПІСЛЯ (post-trigger) — тому на екрані видно й те, що передувало події.*

Цифровий варіант пише відліки в **кільцевий буфер** — тому показує й те, що було **перед** тригером (pre-trigger), чого аналоговий не вміє. Ось стан-машина; її `trigger_feed()` викликають на **кожен** новий відлік АЦП:

```c
// Тригер по фронту з гістерезисом і голдоффом.
// trigger_feed() викликають на КОЖЕН новий відлік АЦП (рівний темп вибірки).
#include <stdbool.h>
#include <stdint.h>

#define BUF_LEN   4096u     // кільцевий буфер; степінь двійки → дешеве обгортання
#define POST_LEN  2048u     // скільки відліків дописати ПІСЛЯ точки тригера
#define HOLDOFF   3000u     // голдофф: пауза після спрацювання, у відліках

static uint16_t buf[BUF_LEN];   // безперервний потік відліків (дає pre-trigger)
static uint32_t head;           // індекс, куди ляже наступний відлік

// Налаштування тригера (задають з UI при зміні рівня/фронту):
static uint16_t level;          // рівень L (у кодах АЦП)
static uint16_t hyst;           // напівширина смуги гістерезису h
static bool     rising = true;  // true — висхідний фронт, false — нисхідний

// Робочий стан стан-машини:
static bool     armed   = true; // курок зведено (готові спрацювати)
static uint32_t hold    = 0;    // лічильник голдоффа
static uint16_t prev    = 0;    // попередній відлік
static bool     filling = false;// t0 знайдено, добираємо post-trigger
static uint32_t post    = 0;    // скільки ще відліків дописати після t0

// Перетин крізь ДАЛЬНІЙ край смуги в обраний бік: L+h вгору / L−h вниз.
// Рахуємо через int32_t, щоб L±h не переповнило uint16_t на краях шкали.
static bool crossed(uint16_t p, uint16_t c) {
    int32_t hi = (int32_t)level + hyst;
    int32_t lo = (int32_t)level - hyst;
    if (rising) return (int32_t)p <  hi && (int32_t)c >= hi;
    else        return (int32_t)p >  lo && (int32_t)c <= lo;
}

// Повернення за ПРОТИЛЕЖНИЙ край смуги знову «зводить курок» (гістерезис).
static bool rearmed(uint16_t c) {
    int32_t hi = (int32_t)level + hyst;
    int32_t lo = (int32_t)level - hyst;
    return rising ? ((int32_t)c < lo) : ((int32_t)c > hi);
}

// Повертає true у мить, коли кадр [PRE | t0 | POST] повністю захоплено.
bool trigger_feed(uint16_t cur) {
    buf[head] = cur;                       // пишемо відлік у кільцевий буфер
    head = (head + 1u) & (BUF_LEN - 1u);   // обгортання (BUF_LEN — степінь 2)

    if (filling) {                         // уже добираємо хвіст після t0
        if (--post == 0u) {                // зібрано POST відліків
            filling = false;               // кадр готовий; далі — голдофф і re-arm
            return true;                   // сигнал: можна показувати [PRE | t0 | POST]
        }
        return false;
    }
    if (hold > 0u) {                       // ще в зоні голдоффа — мовчимо
        --hold;
    } else if (armed && crossed(prev, cur)) {  // умова тригера виконана
        post    = POST_LEN;                // зафіксувати t0, добрати POST відліків
        filling = true;
        hold    = HOLDOFF;                 // пауза: не тригерити N відліків
        armed   = false;
    } else if (rearmed(cur)) {             // вийшли за протилежний поріг
        armed = true;                      // курок знову зведено
    }
    prev = cur;
    return false;
}
```

## Складність і пастки на МК

**Обчислень — копійки:** на кожен відлік лише кілька порівнянь, тобто **O(1)** на відлік і O(N) на буфер. Вузьке місце — не математика, а **швидкість** і **детермінізм у часі**: відліки мусять іти рівним темпом, а момент `t = 0` — бути точним.

Коли таке роблять на **мікроконтролері** (а самопальний DSO — популярна вправа), вилазять характерні граблі:

- **Шум → хибні тригери.** Без гістерезису `h` картинка дрижатиме; програмний компаратор без смуги не варто й пробувати.
- **Замала частота вибірки** — пропустиш швидкий фронт, та ще й дістанеш [**аліасинг**](book:communications/nyquist-aliasing): хвиля на екрані буде брехливою.
- **Джитер переривань.** Якщо ловити фронт софтово в обробнику переривання, затримка «плаває» — і `t = 0` розмазується. Краще **апаратний аналоговий компаратор** МК: він порівнює з рівнем у залізі й сам смикає **захоплення таймера** чи DMA — момент виходить точний.
- **Кільцевий буфер.** Новий відлік **затирає** найстаріший; треба акуратно вести вказівник запису й рахувати, скільки ще дописати після тригера (post-trigger).
- **«Тригера нема».** Обов'язково передбачте **авто-таймаут** (режим Auto), інакше за відсутності умови екран лишиться порожнім, і здаватиметься, що прилад завис.

Висновок: алгоритм тригера простий до смішного — пара порівнянь на відлік, — але саме він відрізняє осцилограф від «мерехтливої лампи». А вся інженерія ховається не в логіці, а в тому, щоб ловити фронт **швидко** й **точно в часі**.
