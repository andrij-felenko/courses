# 📋 Програмний інтерфейс драйвера Чарліплексингу: структури даних, функції керування та таблиці станів виводів

Цей документ визначає повну контрактну специфікацію програмно-апаратного інтерфейсу (API) для бібліотеки керування світлодіодною матрицею Чарліплексингу. Специфікація стандартизує таблиці станів цифрових ліній, типи конфігураційних структур, сигнатури функцій життєвого циклу, вимоги до часових інтервалів обробки переривань та електричні інваріанти безпечної комутації виводів мікроконтролера.

---

### 1. Таблиця станів виводів (Truth Table)

Для матриці Чарліплексингу на базі `N = 3` цифрових виводів (`P0, P1, P2`) існує рівно `3 · 2 = 6` робочих станів вибіркового запалювання індикаторів. У кожен дискретний момент часу сканування рівно один вивід перебуває в стані активного джерела струму (`HIGH`), рівно один — у стані активного стоку струму (`LOW`), а всі інші виводи системи конфігуруються у стан високого імпедансу (`Hi-Z`):

| Світлодіод | Анод (Джерело) | Катод (Стік) | Стан P0 | Стан P1 | Стан P2 | Фізичний результат у колі |
|---|---|---|---|---|---|---|
| **D01** | P0 | P1 | **HIGH (+VCC)** | **LOW (0V)** | **Hi-Z** | Струм тече P0→P1; горить D01, решта вимкнені |
| **D10** | P1 | P0 | **LOW (0V)** | **HIGH (+VCC)** | **Hi-Z** | Струм тече P1→P0; горить D10, решта вимкнені |
| **D02** | P0 | P2 | **HIGH (+VCC)** | **Hi-Z** | **LOW (0V)** | Струм тече P0→P2; горить D02, решта вимкнені |
| **D20** | P2 | P0 | **LOW (0V)** | **Hi-Z** | **HIGH (+VCC)** | Струм тече P2→P0; горить D20, решта вимкнені |
| **D12** | P1 | P2 | **Hi-Z** | **HIGH (+VCC)** | **LOW (0V)** | Струм тече P1→P2; горить D12, решта вимкнені |
| **D21** | P2 | P1 | **Hi-Z** | **LOW (0V)** | **HIGH (+VCC)** | Струм тече P2→P1; горить D21, решта вимкнені |
| **ALL_OFF** | — | — | **Hi-Z** | **Hi-Z** | **Hi-Z** | Усі лінії відключені (пауза / фаза мертвого часу) |

Для конфігурації з `N = 4` виводами таблиця розширюється до 12 рядків за аналогічним комбінаторним правилом.

### 2. Специфікація типів даних і структур

Інтерфейс відокремлює логіку розгортки від апаратних особливостей конкретного кристала за допомогою таблиці функцій зворотного виклику (HAL). Розробник кінцевого пристрою реалізує лише низькорівневі маніпуляції бітами портів, тоді як бібліотека бере на себе керування таймингами, чергою кадрів та програмним ШІМ.

:::tabs
```c
#ifndef CHARLIEPLEX_API_H
#define CHARLIEPLEX_API_H

#include <stdint.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

/**
 * @brief Фізичні режими роботи виводу в матриці Чарліплексингу.
 */
typedef enum {
    CHARLIE_PIN_HIZ  = 0, /**< Вхід, високий опір (Pull-Up/Down примусово вимкнено) */
    CHARLIE_PIN_HIGH = 1, /**< Вихід, високий рівень (+VCC, активне джерело струму) */
    CHARLIE_PIN_LOW  = 2  /**< Вихід, низький рівень (GND, активний стік струму) */
} CharliePinState;

/**
 * @brief Статуси виконання функцій API.
 */
typedef enum {
    CHARLIE_OK               =  0, /**< Успішне виконання операції */
    CHARLIE_ERR_INVALID_ARG  = -1, /**< Передано невалідний покажчик або нульовий розмір */
    CHARLIE_ERR_OUT_OF_BOUND = -2, /**< Індекс світлодіода виходить за межі діапазону N*(N-1) */
    CHARLIE_ERR_UNINITIALIZED= -3  /**< Драйвер не було ініціалізовано перед викликом */
} CharlieStatus;

/**
 * @brief Впорядкована пара виводів для підключення одного діода.
 */
typedef struct {
    uint8_t anode_pin;   /**< Індекс лінії, до якої підключено анод */
    uint8_t cathode_pin; /**< Індекс лінії, до якої підключено катод */
} CharlieLedDef;

/**
 * @brief Апаратні функції адаптера портів (Hardware Abstraction Layer).
 */
typedef struct {
    void (*set_pin_state)(uint8_t pin_index, CharliePinState state);
    void (*enter_critical)(void);
    void (*exit_critical)(void);
} CharlieHalConfig;

/**
 * @brief Контекст екземпляра драйвера матриці.
 */
typedef struct {
    const CharlieHalConfig *hal;
    const CharlieLedDef *led_map;
    uint8_t *frame_buffer;
    uint16_t led_count;
    uint8_t pin_count;
    uint8_t pwm_levels;
    uint16_t current_led_idx;
    uint8_t current_pwm_step;
    bool is_initialized;
} CharlieMatrixContext;

#ifdef __cplusplus
}
#endif

#endif /* CHARLIEPLEX_API_H */
```

### 3. Функціональний контракт (Сигнатури та детальний опис поведінки)

#### `CharlieStatus charlie_matrix_init(CharlieMatrixContext *ctx, const CharlieHalConfig *hal, ...)`
- **Призначення:** Здійснює первинну конфігурацію контексту драйвера, прив'язує апаратний рівень HAL, скидає кадровий буфер у нуль та переводить усі виводи системи в безпечний високоімпедансний стан (`Hi-Z`).
- **Вхідні аргументи:**
  - `ctx`: покажчик на виділену користувачем структуру контексту драйвера. Не повинен бути `NULL`.
  - `hal`: покажчик на заповнену таблицю функцій керування апаратурою. Функція `set_pin_state` є строго обов'язковою, функції критичних секцій можуть бути відсутні, якщо переривання блокуються на вищому рівні.
- **Повертане значення:** `CHARLIE_OK` при успішній ініціалізації; `CHARLIE_ERR_INVALID_ARG` якщо будь-який обов'язковий покажчик є нульовим.
- **Вимоги до стану:** Після виконання функції жоден світлодіод не повинен проводити струм, усі лінії мікроконтролера гарантовано перебувають у режимі `INPUT` без підтяжок.

#### `CharlieStatus charlie_matrix_set_pixel(CharlieMatrixContext *ctx, uint16_t led_idx, uint8_t brightness)`
- **Призначення:** Встановлює рівень яскравості для обраного світлодіода за його лінійним індексом.
- **Вхідні аргументи:**
  - `ctx`: валідний ініціалізований контекст драйвера.
  - `led_idx`: порядковий номер діода в діапазоні `[0 .. led_count - 1]`.
  - `brightness`: дискретне значення яскравості в діапазоні `[0 .. pwm_levels - 1]`. Значення, що перевищують максимальний рівень, автоматично обмежуються стелею діапазону.
- **Повертане значення:** `CHARLIE_OK` при успішному записі або `CHARLIE_ERR_OUT_OF_BOUND`, якщо індекс перевищує кількість діодів у схемі.
- **Потокобезпечність:** Функція записує значення у виділений байт кадрового буфера. На 8-бітних, 16-бітних та 32-бітних процесорах атомарний запис одного байта гарантує цілісність даних без потреби блокування переривань.

#### `void charlie_matrix_clear(CharlieMatrixContext *ctx)`
- **Призначення:** Миттєво очищає кадровий буфер, встановлюючи нульову яскравість для всіх світлодіодів матриці.
- **Поведінка:** Під час наступного таймерного циклу всі діоди залишаються темними, виводи перебувають виключно у стані `Hi-Z`.

#### `void charlie_matrix_fill(CharlieMatrixContext *ctx, uint8_t brightness)`
- **Призначення:** Заповнює весь кадровий буфер однаковим рівнем яскравості, вмикаючи всі світлодіоди матриці. Застосовується для тестування цілісності контактів та створення рівномірного фонового підсвічування.

#### `void charlie_matrix_tick_isr(CharlieMatrixContext *ctx)`
- **Призначення:** Виконує один атомарний крок часового мультиплексування. Викликається строго періодично з обробника апаратного переривання таймера.
- **Алгоритмічні гарантії:**
  1. **Фаза мертвого часу (Dead-time):** Першим кроком функція вимикає попередньо активні виходи, встановлюючи їх у стан `CHARLIE_PIN_HIZ`.
  2. **Оцінка порогу ШІМ:** Якщо яскравість поточного світлодіода `brightness > current_pwm_step`, на лінію анода подається `CHARLIE_PIN_HIGH`, а на лінію катода — `CHARLIE_PIN_LOW`. Якщо яскравість дорівнює нулю або менша за лічильник, виводи залишаються у `Hi-Z`.
  3. **Інкремент індексу:** Перехід до наступного світлодіода. При повному обході матриці лічильник світлодіодів скидається в 0, а лічильник ШІМ інкрементується за модулем `pwm_levels`.
- **Часова складність:** `O(1)`, відсутність будь-яких циклів очікування чи блокувань всередині переривання. Загальний час виконання обробника на мікроконтролері з частотою 16 МГц не перевищує 2–4 мікросекунд.

### 4. Часові інваріанти та електричні гарантії

1. **Мінімальний інтервал мертвого часу (`t[dead]`):** Тривалість стану, коли всі лінії вимкнені перед увімкненням нової пари, повинна становити не менше 100 нс. Це гарантує повне закриття вихідних польових транзисторів порту і виключає короткочасні наскрізні струми.
2. **Вимкнення внутрішніх підтяжок (`Pull-Up Disable`):** Переведення лінії у стан `Hi-Z` зобов'язане супроводжуватися записом 0 у вихідний регістр (`PORT = 0` або `GPIO_NOPULL`). В іншому разі струм витоку через внутрішній резистор 30 кОм спричинить небажане фонове світіння індикаторів у темряві.
3. **Діапазон частот розгортки кадру:** Мінімальна частота зміни повного кадру становить 60 Гц (поріг злиття миготінь), рекомендована частота для комфортного спостереження — від 100 до 200 Гц.
4. **Максимальна паразитна ємність монтажу:** Сумарна ємність провідників матриці разом із виводами світлодіодів не повинна перевищувати 50 пФ на лінію, щоб постійна часу заряду лінії `τ = R · C` не перевищувала 1 мікросекунди.

### 5. Використання пам'яті та діагностичний протокол валідації

Обсяг оперативної пам'яті (RAM), необхідний для роботи драйвера, є фіксованим і визначається виключно кількістю світлодіодів. Для типової матриці на `N = 4` виводи (`12` діодів) статичні структури контексту займають 24 байти RAM, а кадровий буфер — 12 байтів. Загальний відбиток у пам'яті програм (Flash) разом із таблицею пар виводів становить менше 400 байтів для архітектури AVR і близько 600 байтів для ARM Cortex-M.

При первинному введенні друкованої плати в експлуатацію рекомендується виконати стандартний протокол апаратної діагностики:
- **Тест 1 (Опір ізоляції):** Перевести всі виводи у стан `Hi-Z` та виміряти струм споживання всієї плати від джерела живлення. Струм витоку справної матриці не повинен перевищувати 1–5 мкА.
- **Тест 2 (Послідовний біговий тест):** По черзі подати живлення на кожну пару `D[i, j]` на час 500 мс. Цей тест виявляє перевернуті діоди (не світиться у свій слот, але світиться у зворотний) та короткі замикання між сусідніми доріжками друкованої плати.
- **Тест 3 (Тест максимального навантаження):** Заповнити кадровий буфер максимальною яскравістю (`charlie_matrix_fill`) та виміряти падіння напруги на виводах живлення мікроконтролера за допомогою осцилографа для виключення просідань живлення від імпульсних струмів.
