# 📋 Модуль оточення по цифровій шині: виводи, адреси, карта регістрів

Готовий цифровий модуль оточення (температура + вологість + тиск, як-от BME280 і його рідня) віддає вже відкаліброване число цифровою шиною — але щоб його «розговорити», треба знати контракт: якою шиною він говорить, за якою адресою відгукується і які регістри керують вимірами. Це — довідник того контракту (виводи, адреси, регістри та їхні поля); а покрокове піднімання з кодом і граблі винесено окремо, у [практичне піднімання модуля](topic:electronics/environment-sensors/proj-env-module.md).

## Дві шини на вибір: I²C і SPI

Майже кожен такий модуль говорить двома мовами, і вибір між ними — типовий вбудований компроміс «менше дротів проти простішої електрики».

| | I²C | SPI |
|---|---|---|
| Ліній даних/такту | 2: `SDA` + `SCL` | 4: `SCK`, `SDI`, `SDO`, `CSB` |
| Підтяжки | обов'язкові на `SDA`, `SCL` | не потрібні |
| Кого як вибирають | **адресою** (спільні дроти) | окремим `CS` на кожен пристрій |
| Багато давачів | на тій самій парі | по ніжці `CS` на кожен |
| Швидкість | нижча | вища |

Для повільних величин оточення швидкість SPI зайва, тому на практиці майже завжди беруть **I²C**: дві лінії на всіх, а кілька давачів живуть на спільній парі з різними адресами.

## I²C-адреса — одним виводом

Адресу зазвичай роблять перемикною виводом `SDO`: його рівень задає молодший біт адреси.

| `SDO` під'єднано до | Адреса (7-біт) |
|---|---|
| землі (`GND`) | `0x76` |
| живлення (`VDDIO`) | `0x77` |

Звідси проста, але часта пастка: **два однакові модулі на одній шині** співіснують лише тоді, коли їм дати різні адреси цим виводом (один `SDO` на землю, другий на живлення). Інакше вони відповідають разом, і шина «бачить» кашу.

## Виводи в I²C-режимі

| Вивід | Призначення |
|---|---|
| `VDD` | живлення аналогової частини (звич. 1.8–3.6 В) |
| `VDDIO` | живлення й опорний рівень цифрових ліній |
| `GND` | спільна земля |
| `SCL` | такт I²C (з підтяжкою) |
| `SDA` | дані I²C, двонапрямні (з підтяжкою) |
| `SDO` | вибір адреси: `GND`→`0x76`, `VDDIO`→`0x77` |
| `CSB` | вибір шини: до `VDDIO` = режим I²C; як `CS` = режим SPI |

> 🔧 **Навіщо це.** Коли на платі вже є I²C-шина (а вона є майже завжди — на ній сидять годинник, дисплей, інші давачі), додати модуль оточення коштує **двох дротів і однієї адреси**. Перше, що варто перевірити при «давач не відповідає», — підтяжки на `SDA`/`SCL`, рівень `CSB` (чи ввімкнено I²C) і чи не збіглися адреси двох модулів.

## Карта регістрів

Модуль — це набір 8-бітних регістрів, доступних за їхніми адресами. Керувальні задають режим вимірів; регістри даних віддають сирий код; службові тримають заводські коефіцієнти. Адреси нижче — типові для класу (родина BME280).

| Адреса | Регістр | Що робить |
|---|---|---|
| `0xD0` | `id` | код моделі (перевірити «чи той чип на шині») |
| `0xE0` | `reset` | запис `0xB6` — програмне скидання |
| `0xF2` | `ctrl_hum` | передискретизація вологості |
| `0xF3` | `status` | прапорці «іде вимір», «оновлюються коефіцієнти» |
| `0xF4` | `ctrl_meas` | передискретизація T і тиску + режим |
| `0xF5` | `config` | пауза між циклами + IIR-фільтр |
| `0xF7…0xF9` | `press` | сирий код тиску, 20 біт (старший уперед) |
| `0xFA…0xFC` | `temp` | сирий код температури, 20 біт |
| `0xFD…0xFE` | `hum` | сирий код вологості, 16 біт |
| `0x88…0xA1`, `0xE1…0xE7` | `calib` | заводські коефіцієнти цього екземпляра (OTP) |

## Поля керувальних регістрів

**`ctrl_meas` (`0xF4`)** — три поля в одному байті:

```
біти:  7  6  5 | 4  3  2 | 1  0
поле:  osrs_t  | osrs_p  | mode
```

**`config` (`0xF5`)**:

```
біти:  7  6  5 | 4  3  2 |  0
поле:  t_sb    | filter  | spi3w_en
```

**`ctrl_hum` (`0xF2`)** — лише молодші три біти `osrs_h`.

Кодування **передискретизації** (`osrs_*`) — однакове для всіх трьох величин: скільки разів модуль міряє й усереднює за один цикл.

| Код | Передискретизація |
|---|---|
| `000` | вимкнено (величину не міряти) |
| `001` | ×1 |
| `010` | ×2 |
| `011` | ×4 |
| `100` | ×8 |
| `101` | ×16 |

**Режим** (`mode`) визначає, як модуль працює в часі:

| Код | Режим | Поведінка |
|---|---|---|
| `00` | сон (*sleep*) | нічого не міряє, мінімум струму |
| `01`/`10` | за запитом (*forced*) | один вимір і назад у сон |
| `11` | неперервний (*normal*) | міряє цикл за циклом із паузою `t_sb` |

**IIR-фільтр** (`filter`) згладжує короткі сплески (переважно тиску) — чим більший коефіцієнт, тим сильніше згладжування й повільніша реакція на справжню зміну:

| Код | Фільтр |
|---|---|
| `000` | вимкнено |
| `001` | ×2 |
| `010` | ×4 |
| `011` | ×8 |
| `100` | ×16 |

Поле `t_sb` задає **паузу між циклами** в неперервному режимі — від часток мілісекунди до ~1000 мс (наприклад, `011` = 250 мс, `101` = 1000 мс): рідші виміри = менший самонагрів і струм.

## Порядок запису й читання — два правила протоколу

Два тонкі місця контракту, через які буває «все написав правильно, а не працює»:

- **`ctrl_hum` записувати ПЕРЕД `ctrl_meas`.** Зміна передискретизації вологості набуває чинності лише при наступному записі в `ctrl_meas`. Якщо записати `ctrl_meas` першим, а `ctrl_hum` потім, вологість так і лишиться зі старим налаштуванням — до наступного дотику `ctrl_meas`.
- **Регістри даних читати одним пакетом.** Читання від `press` до `hum` за один I²C-burst бере узгоджений набір T/тиск/вологість з одного циклу; читання порізно ризикує «зшити» половинки різних вимірів.

Сам сирий код із регістрів даних — ще не фізична величина: його треба пропустити через індивідуальні коефіцієнти з `calib`. Як це роблять на практиці (послідовність увімкнення, читання, компенсація й типові граблі) — у [практичному пійманні модуля](topic:electronics/environment-sensors/proj-env-module.md).
