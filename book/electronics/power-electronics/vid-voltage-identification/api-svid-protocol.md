# 📋 Протокол та реєстрова карта шини Intel SVID

Шина послідовної ідентифікації напруги (SVID — Serial Voltage Identification) є стандартним фізичним та логічним інтерфейсом зв'язку між мікропроцесорами Intel (починаючи з мікроархітектур Nehalem і Sandy Bridge за специфікаціями VR12.0, VR12.5, VR13, VR14, VR14HC) та ШІМ-контролерами багатофазних модулів стабілізації напруги (VRM). Інтерфейс забезпечує динамічне цифрове керування робочими точками напруги живлення, моніторинг струму й температури в реальному часі, а також асинхронну сигналізацію про аварійні події.

---

### Фізичний рівень (Physical Layer)

Інтерфейс SVID побудовано за топологією спільної шини «один ведучий (Master — процесор) — до 16 підпорядкованих пристроїв (Slaves — канали контролерів VRM)». Фізичний рівень використовує три сигнальні лінії:

```
┌──────────────┐                               ┌──────────────┐
│  ПРОЦЕСОР    │             SCLK (25 МГц)     │  ШІМ-КОНТР.  │
│  (Master)    ├──────────────────────────────►│  (Slave 0)   │
│              │             SDATA (1.05 В)    │              │
│              │◄─────────────────────────────►│  Vcore Rail  │
│              │             ALERT#            │              │
│              │◄──────────────────────────────┤              │
│              │                               └──────────────┘
│              │                               ┌──────────────┐
│              │                               │  ШІМ-КОНТР.  │
│              │                               │  (Slave 1)   │
│              │                               │              │
│              │                               │  Vgt/iGPU    │
│              │                               └──────────────┘
└──────────────┘
```

#### Електричні параметри та специфікація ліній:

1. **`SCLK` (Serial Clock):**
   * Односпрямований тактовий сигнал, що генерується виключно процесором.
   * Номінальна частота тактування: **25.0 МГц** (період тактового імпульсу `T_clk = 40.0 нс`). Допустимий діапазон тактування становить від 100 кГц у тестових режимах до 25.0 МГц у штатному режимі роботи.
   * Рівень напруги логічної одиниці: `V_high = 1.05 В ± 5 %` (для специфікацій VR12.0/VR12.5) або `1.00–1.20 В` (для специфікацій VR13/VR14).
   * Тривалість наростання та спаду фронтів (`t_rise`, `t_fall`): не більше 2.5 нс при ємності навантаження 15 пФ.
   * Вихідний каскад: симетричний комплементарний драйвер (Push-Pull), що забезпечує чіткі прямокутні імпульси без спотворень форми сигналу.

2. **`SDATA` (Serial Data):**
   * Двоспрямована лінія передачі адрес, команд, даних та підтверджень.
   * Рівні логіки: напруга логічного нуля `V_IL ≤ 0.30 В`, напруга логічної одиниці `V_IH ≥ 0.75 В` (при опорній напрузі шини 1.05 В).
   * Вихідний каскад: відкритий стік (Open-Drain) або керований Push-Pull з автоматичним перемиканням напрямку на час слота відповіді підпорядкованого пристрою.
   * Резистор підтяжки: на материнській платі біля сокета встановлюється прецизійний резистор підтяжки `R_pullup = 100–200 Ом` до шини напруги системного агента `VTT` або `VCCIO`. Значення резистора підбирається так, щоб постійна часу `RC` шини не перевищувала 5 нс при максимальній сумарній паразитній ємності доріжок і входів мікросхем до 15 пФ.
   * Час встановлення та утримання даних: час випередження встановлення даних до наростаючого фронту такту `t_setup ≥ 5.0 нс`, час утримання після фронту `t_hold ≥ 5.0 нс`.

3. **`ALERT#` (Asynchronous Alert):**
   * Двоспрямована сигнальна лінія асинхронного запиту переривання з активним низьким рівнем (Active Low).
   * Вихідний каскад контролерів VRM: відкритий стік (Open-Drain).
   * Усі підпорядковані контролери об'єднуються на лінії `ALERT#` за схемою «монтажного АБО» (Wired-OR). Якщо хоча б один із контролерів фіксує аварійний стан, лінія примусово стягується до нуля.
   * Притискання лінії до землі сигналізує про критичну подію: перевантаження за струмом (OCP), перегрів силових каскадів (`VR_HOT`), неприпустиме просідання напруги або успішне завершення стабілізації напруги після динамічної зміни вольтажу.

### Структура кадру протоколу (Frame Format)

Будь-яка взаємодія на шині SVID складається з неподільної транзакції, синхронізованої наростаючим фронтом тактового сигналу `SCLK`. Повна транзакція містить послідовність бітів запиту від ведучого процесора, захисний інтервал перемикання шини та обов'язковий пакет відповіді від адресованого підпорядкованого стабілізатора.

```
Анатомія повного кадру транзакції SVID (команда Master + відповідь Slave):
┌───────┬────────────┬───────────┬──────────────┬────────┬───────┬───────────┬─────────┬────────┬───────┐
│ START │ SLAVE ADDR │  CMD CODE │ DATA PAYLOAD │ PARITY │ TURN  │ SLAVE ACK │ SLAVE D │ PARITY │ IDLE  │
│ 1 біт │   4 біти   │   5 бітів │    8 бітів   │ 1 біт  │ 2 так │  2 біти   │ 8 бітів │ 1 біт  │  —    │
└───────┴────────────┴───────────┴──────────────┴────────┴───────┴───────────┴─────────┴────────┴───────┘
```

#### Поля заголовка та команди (Master Packet):

* **`START` (1 біт):** Початок передачі. Лінія `SDATA` переводиться з високого стану спокою в логічний нуль `0` за один такт до передачі адреси, сигналізуючи всім слухачам про початок активного фрейму.
* **`SLAVE ADDR` (4 біти):** Адреса цільового регулятора живлення. Дозволяє адресувати до 16 незалежних перетворювачів на одній трипровідній магістралі:
  * `0x0` (`0000b`): Силовий домен обчислювальних ядер процесора (`Vcore`);
  * `0x1` (`0001b`): Силовий домен інтегрованого графічного ядра (`Vgt` / `Vgfx`);
  * `0x2` (`0010b`): Силовий домен системного агента (`Vccsa` / System Agent — контролер пам'яті та лінії PCIe);
  * `0x3` (`0011b`): Силовий домен шини вводу-виводу або живлення пам'яті (`Vccio` / `Vddq`);
  * `0x4`–`0xE`: Додаткові допоміжні перетворювачі на серверних та високопродуктивних платах (Vccin, FIVR supply, Vring);
  * `0xF` (`1111b`): Широкомовна адреса (Broadcast), що сприймається всіма регуляторами одночасно для синхронного оновлення станів.
* **`CMD CODE` (5 бітів):** Код операції, що визначає тип дії, алгоритм виконання та внутрішню структуру поля даних.
* **`DATA PAYLOAD` (8 бітів):** Інформаційне навантаження від процесора. Залежно від команди це поле містить байт цільового коду напруги VID, номер внутрішнього регістра конфігурації або бітову маску налаштування параметрів.
* **`PARITY` (1 біт):** Біт непарного паритету (Odd Parity). Обчислюється апаратним блоком ведучого за всіма попередніми бітами кадру (`ADDR + CMD + DATA`). Сума всіх одиничних розрядів разом із бітом паритету завжди має становити непарне число. Якщо підпорядкований контролер фіксує парну суму, транзакція відкидається як пошкоджена завадою, а у відповідь повертається код помилки `NACK`.

#### Поля перемикання напрямку та відповіді (Slave Response):

* **`TURN-AROUND` (TA, 1–2 такти):** Захисний часовий інтервал у два тактові періоди (80 нс), протягом якого процесор переводить свій вихідний буфер `SDATA` у високоомний стан (Hi-Z), а адресований контролер VRM готується керувати лінією зв'язку, активуючи свій передавач.
* **`SLAVE ACK` (2 біти):** Статус підтвердження прийому від регулятора:
  * `00b` (`ACK`): Команду прийнято успішно, помилок парності немає, контролер розпочав виконання операції.
  * `01b` (`NACK`): Помилка контрольної суми паритету або спроба викликати непідтримуваний код команди.
  * `10b` (`BUSY`): Контролер зайнятий виконанням попередньої довготривалої команди перемикання напруги або ініціалізацією фаз.
* **`SLAVE DATA` (8 бітів):** Байт телеметрії, що повертається стабілізатором у відповідь на запит процесора (значення струму `IMON`, температури `TMON`, напруги `VOUT` або вміст запитуваного регістра). Передається лише при виконанні команд зчитування `GetReg`. При командах запису `SetVID` це поле пропускається для прискорення транзакції.
* **`SLAVE PARITY` (1 біт):** Біт непарного паритету для байта відповіді підпорядкованого пристрою, що захищає телеметричні дані від спотворень при зворотному русі до процесора.

### Набір базових команд (Command Set)

Специфікація SVID визначає фіксований набір інструкцій швидкого прямого доступу та реєстрових операцій:

```
Таблиця основних команд інтерфейсу Intel SVID:
┌──────────┬───────────┬───────────────────────────────────────────────────────┐
│ Код CMD  │ Назва     │ Функціональне призначення                            │
├──────────┼───────────┼───────────────────────────────────────────────────────┤
│  0x00    │ SetVID_F  │ Встановлення напруги з максимальною швидкістю (Fast)  │
│  0x01    │ SetVID_S  │ Встановлення напруги зі зниженою швидкістю (Slow)     │
│  0x02    │ SetVID_D  │ Переведення лінії в режим пасивного згасання (Decay)  │
│  0x03    │ SetReg    │ Запис 8-бітного значення в конфігураційний регістр    │
│  0x04    │ GetReg    │ Зчитування 8-бітного значення з регістра телеметрії   │
│  0x05    │ SetWP     │ Встановлення точки збереження енергії (Set Wakeup/WP) │
│  0x07    │ SetOffset │ Запис динамічного зміщення напруги (Voltage Offset)   │
└──────────┴───────────┴───────────────────────────────────────────────────────┘
```

#### Поведінка та часові діаграми команд зміни вольтажу:

1. **`SetVID_Fast` (CMD `0x00`):**
   Процесор передає 8-бітний код цільової напруги. ШІМ-контролер негайно оновлює опорний рівень внутрішнього ЦАП і починає перехід з максимально запрограмованою швидкістю наростання (типово від 25 до 40 мВ/мкс). У момент досягнення нової напруги та завершення перехідного процесу контролер сигналізує про готовність. Ця інструкція є базовою для реалізації технології підвищення тактової частоти Intel Turbo Boost, де затримка переходу на підвищену напругу має становити лічені мікросекунди.

2. **`SetVID_Slow` (CMD `0x01`):**
   Процесор передає 8-бітний код напруги. Контролер здійснює плавне ступеневе перемикання зі швидкістю, зниженою у 4–8 разів (типово 2.5–5 мВ/мкс). Це виключає виникнення чутного акустичного шуму в керамічних конденсаторах материнської плати та запобігає появі струмових ударів заряджання ємностей `I_cap = C_out · (dV/dt)`. Застосовується при планових змінах станів P-States під час плавного зростання фонового навантаження.

3. **`SetVID_Decay` (CMD `0x02`):**
   Команда для переведення процесора в глибокі енергоощадні стани (C-States: C6, C7, C8). Контролер переводить усі силові транзистори у високоомний стан (Hi-Z), дозволяючи вихідній напрузі плавно спадати до нуля виключно за рахунок природного розряду ємностей залишковим струмом кристала. Це повністю виключає примусове закорочування вихідних ємностей на землю через нижні польові транзистори, запобігаючи небезпечним зворотним струмам індуктивностей та перезаряджанню вхідної шини 12 В.

4. **`SetReg` (CMD `0x03`) та `GetReg` (CMD `0x04`):**
   Універсальні інструкції конфігурації та збору телеметрії. При виклику `GetReg` процесор у полі корисного навантаження передає адресу запитуваного регістра, а контролер після фази перемикання шини повертає його поточний 8-бітний вміст разом із бітом паритету. При виклику `SetReg` після адреси регістра передається байт нових конфігураційних параметрів.

### Карта стандартних регістрів VRM (Register Map)

Кожен підпорядкований канал VRM містить стандартизований масив 8-бітних регістрів стану, конфігурації та телеметрії:

```
┌──────────┬──────────────┬──────┬─────────────────────────────────────────────┐
│ Адреса   │ Назва        │ Тип  │ Опис та бітові поля                         │
├──────────┼──────────────┼──────┼─────────────────────────────────────────────┤
│ 0x00     │ Vendor ID    │ R    │ Унікальний ідентифікатор виробника ШІМ (ID) │
│ 0x01     │ Product ID   │ R    │ Апаратний номер моделі мікросхеми           │
│ 0x02     │ Revision ID  │ R    │ Номер ревізії кремнію контролера            │
│ 0x05     │ Protocol ID  │ R    │ Версія специфікації (VR12, VR13, VR14)      │
│ 0x06     │ Capability   │ R    │ Біти апаратних можливостей (Slew rate, I2C) │
│ 0x10     │ Status1      │ R/W1C│ Головний регістр апаратних статусів та аварій│
│ 0x11     │ Status2      │ R/W1C│ Допоміжний регістр стану фаз та термісторів │
│ 0x15     │ IOUT (IMON)  │ R    │ Поточний оцифрований струм навантаження     │
│ 0x16     │ Temperature  │ R    │ Поточна температура найгарячішої фази (°C)  │
│ 0x17     │ POUT (Power) │ R    │ Розрахункова споживана потужність           │
│ 0x21     │ Target VID   │ R    │ Поточний активний код напруги ЦАП           │
│ 0x24     │ Slew Rate    │ R/W  │ Конфігурація швидкості наростання напруги   │
│ 0x30     │ VOUT_Max     │ R/W  │ Верхня апаратна межа безпечної напруги ядра │
│ 0x33     │ Voltage Offset│ R/W │ Регістр зміщення вольтажу (Undervolting)    │
└──────────┴──────────────┴──────┴─────────────────────────────────────────────┘
```

#### Деталізація бітів головного регістра стану `Status1` (Регістр `0x10`):

* **Біт 0 (`VR_HOT`):** Апаратний перегрів стабілізатора. Встановлюється в `1`, коли температура фаз перевищує встановлений тепловий ліміт (наприклад, +115 °C). Супроводжується негайним апаратним опусканням лінії `ALERT#` до нуля.
* **Біт 1 (`VR_OCP`):** Перевантаження за струмом (Over-Current Protection). Струм навантаження перевищив гранично допустимий розрахунковий максимум системи `I_max`.
* **Біт 2 (`VR_OVP`):** Спрацьовування захисту від перенапруги. Виникає при перевищенні напругою виходу порогу `VID + 200 мВ`.
* **Біт 3 (`VR_UVP`):** Спрацьовування захисту від неприпустимого просідання напруги (`VID - 300 мВ`).
* **Біт 4 (`Comm_Error`):** Помилка контролю непарності або невідома команда протоколу SVID.
* **Біт 5 (`Slew_Busy`):** Прапорець активного перехідного процесу. Дорівнює `1` під час зміни напруги та скидається в `0` після завершення стабілізації на новому рівні.
* **Біт 6 (`Power_Good`):** Готовність лінії живлення. Вказує, що напруга стабілізатора увійшла в нормативний коридор толерантності та придатна для надійної роботи логіки процесора.

Регістр `Status1` має тип `R/W1C` (Read / Write '1' to Clear): біти помилок фіксуються в одиницю апаратно і скидаються процесором шляхом запису одиниці у відповідний розряд після успішної обробки переривання.

#### Регістр керування швидкістю наростання `Slew Rate` (Регістр `0x24`):

Цей конфігураційний регістр дозволяє програмно перемикати дискретні ступені швидкості наростання для команд `SetVID_Fast` та `SetVID_Slow`:
* Біти `[1:0]` (`Fast Slew Rate`): `00b` = 10 мВ/мкс, `01b` = 20 мВ/мкс, `10b` = 30 мВ/мкс, `11b` = 40 мВ/мкс.
* Біти `[3:2]` (`Slow Slew Rate`): `00b` = 2.5 мВ/мкс, `01b` = 5.0 мВ/мкс, `10b` = 7.5 мВ/мкс, `11b` = 10.0 мВ/мкс.
* Біт `[7]` (`Decay Enable`): Дозвіл переведення силових ключів у високоомний стан при зниженні напруги.

#### Регістр зміщення напруги `Voltage Offset` (Регістр `0x33`):

Регістр містить 8-бітне число зі знаком у форматі додаткового коду (two's complement), що дозволяє процесору або BIOS зміщувати базову криву напруг VID:
* Діапазон регулювання: від `-200 мВ` до `+196.875 мВ` із дискретним кроком `6.25 мВ` або `5.0 мВ`.
* Значення `0x00` відповідає нульовому зміщенню (заводська калібрована крива).
* Від'ємні значення (наприклад, `0xF8` = -40 мВ) забезпечують режим апаратного андервольтингу (Undervolting), що дозволяє знизити робочу температуру процесора та зменшити шум системи охолодження без втрати продуктивності.

#### Регістр керування конфігурацією фаз та енергозбереженням `Phase Control` (Регістр `0x25`):

Сучасні багатофазні стабілізатори (8–24 фази) при малих струмах споживання (до 10–20 А) демонструють низький ККД через домінування динамічних втрат на перезаряджання затворів польових транзисторів. Регістр `0x25` дозволяє процесору динамічно керувати кількістю активних фаз (Phase Shedding / PSI):
* Біти `[2:0]` (`Active Phase Count`): задають примусову кількість працюючих фаз (наприклад, перехід із 12 фаз на 2 фази під час простою).
* Біт `[3]` (`DCM / Diode Emulation Enable`): дозвіл переходу в режим переривчастих струмів (DCM — Discontinuous Conduction Mode) з вимкненням нижніх синхронних ключів при переході струму дроселя через нуль.
* Біт `[4]` (`Pulse Skipping Enable`): дозвіл пропуску імпульсів ШІМ при ультранизькому споживанні в режимах глибокого сну C8–C10.

#### Регістр телеметрії потужності `POUT` (Регістр `0x17`):

Регістр містить оцифроване значення розрахункової повної вихідної потужності стабілізатора:
* Масштабування: визначається значенням регістра максимальної потужності `PMAX` (Регістр `0x32`), де `0xFF` відповідає 100 % від `PMAX` (наприклад, 400 Вт).
* Дискретність: `1 LSB = PMAX / 255` (для системи на 400 Вт один крок становить приблизно 1.57 Вт).
* Процесор використовує цей апаратний вимір для прямої корекції динамічних лімітів PL1/PL2 без потреби в програмному інтегруванні струмів.

### Таблиця перетворення коду VID у вихідну напругу

У специфікації **Intel VR12.0 / VR12.5** (8-бітний код, крок 5 мВ, зміщення 0.250 В) залежність напруги від двійкового значення описується співвідношенням:

```
Для коду VID від 0x01 до 0xFF:
  V_out = 0.245 В + (код_VID · 0.005 В)

Винятки:
  код_VID = 0x00 : Вихід вимкнено (0.000 В / OFF)
  код_VID = 0x01 : 0.250 В (мінімальна напруга)
  код_VID = 0x65 (101d) : 0.245 + (101 · 0.005) = 0.750 В (стан спокою C-State)
  код_VID = 0xC9 (201d) : 0.245 + (201 · 0.005) = 1.250 В (номінальний стан)
  код_VID = 0xF5 (245d) : 0.245 + (245 · 0.005) = 1.470 В (максимальний Turbo Boost)
  код_VID = 0xFF : Зарезервовано / Аварійне вимкнення
```

У специфікаціях **Intel VR13 / VR14** для процесорів сімейств Skylake/Ice Lake/Alder Lake впроваджено альтернативні режими з кроком 10 мВ (діапазон регулювання до 2.55 В) та 9-бітний режим адресації для серверних процесорів Xeon Scalable з кроком 5 мВ у розширеному діапазоні до 3.0 В.

### Механіка асинхронного переривання ALERT#

Шина SVID виключає необхідність постійного опитування регістрів процесором (polling), що економить енергію та зменшує навантаження на системний агент.

```
Часова послідовність обробки аварії через ALERT#:
1. Нормальна робота:     ALERT# = 1 (підтяжка 1.05 В).
2. Аварія у фазі VRM:    Контролер фіксує перегрів DrMOS (+115 °C) і притискає ALERT# -> 0.
3. Реакція процесора:    PCU через 40 нс бачить спад ALERT# і негайно надсилає GetReg(0x10).
4. Очищення переривання: Контролер повертає байт статусу Status1 (біт VR_HOT = 1) і відпускає ALERT#.
5. Дія захисту:          Процесор негайно активує PROCHOT# і скидає частоту ядер до 800 МГц.
```

Така двоспрямована взаємодія перетворює інтерфейс SVID на замкнений високошвидкісний цифровий контур, що гарантує цілісність живлення та захист кристала мікропроцесора в будь-яких динамічних режимах експлуатації.
