# ⚙️ Алгоритм станції гіпоту: автомат проб, тригер, розряд

Станція гіпоту — машина з подвійним обличчям. Її єдине призначення — навмисно створити ту саму небезпеку, від якої вона ж і рятує: підняти на виробі кілька кіловольтів і подивитися, чи хтось не пробʼється. Тому її керівна програма — не зручність, а сама по собі захисний пристрій. Вона мусить встигати чотири речі одночасно: провести проби в **правильному порядку**, зловити пробій **швидше, ніж він устигне пропалити** ізоляцію, ніколи не лишити виріб чи оператора **під зарядом**, і взагалі відмовитися стріляти, поки людина не в безпеці.

Уся інженерія тут крутиться навколо одного спостереження: у станції цокають **два годинники** різної швидкості. Повільний веде послідовність — заземлення, опір ізоляції, гіпот, розряд; його крок міряють у мілісекундах і навіть секундах, і зайва мілісекунда там нічого не міняє. Швидкий стежить за струмом крізь ізоляцію; його крок — десятки мікросекунд, і кожна протермінована мікросекунда — це ізоляція, що вже горить. Спроба вести обидва годинники з однієї петлі — головна помилка новачка. Розділити їх — головне рішення проєкту.

## Кістяк: машина станів для послідовності

Повільний годинник — це [машина станів](book:programming/state-machine): скінченний набір станів і жорсткі переходи між ними. Кожна проба — окремий стан; перехід далі дозволено лише після того, як попередня проба **пройдена**. Не можна подати гіпот, не переконавшись у заземлювальному звʼязку й опорі ізоляції; не можна оголосити «прохід», не розрядивши виріб. Порядок тут — не формальність, а безпека: кожен крок звужує невизначеність перед тим, як підняти напругу ще вище.

![Автомат станів станції: IDLE озброюється двома кнопками й зачиненим кожухом, далі послідовно заземлювальний звʼязок, опір ізоляції, гіпот (наростання й витримка); будь-яка помилка, відкритий кожух чи тайм-аут ведуть в ABORT; і успіх, і ABORT проходять крізь спільний РОЗРЯД, і лише розряджений виріб дістає вирок PASS або FAIL.](/book/electronics/power-electronics/mains-hipot-test/img/hipot-fsm.svg)

*Одна дорога вперед, одна аварійна рейка вниз — і обидві сходяться на розряді: жоден виріб не покидає станцію під зарядом.*

Зверніть увагу на форму автомата. Уперед веде одна пряма дорога. Униз, з будь-якого стану, веде спільна **аварійна рейка** — відкритий кожух, спрацьований тригер, тайм-аут, провалена проба скидають автомат у той самий стан `ABORT`. І — найважливіше — обидві дороги, і тріумфальна, і аварійна, зливаються в одному вузлі: `РОЗРЯД`. Це не випадковість компонування, а вимога безпеки, зашита в топологію: **немає** шляху від «під напругою» до «оператор бере виріб», який оминав би розряд.

```c
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    ST_IDLE, ST_GROUND_BOND, ST_INSUL_RES,
    ST_HIPOT_RAMP, ST_HIPOT_DWELL, ST_DISCHARGE, ST_PASS, ST_FAIL
} state_t;

typedef enum { V_NONE, V_PASS, V_FAIL } verdict_t;

typedef struct {
    state_t   state;
    verdict_t verdict;
    uint32_t  t_ms;        // час у поточному стані, мс
    uint16_t  dac_code;    // поточний код ЦАП (команда напруги джерела)
    uint16_t  dac_target;  // код на кінець наростання
    uint16_t  dac_step;    // приріст коду за один 1-мс такт
    const char *fail_reason;
} hipot_t;

// Прапорці, спільні з обробником переривання (тому volatile):
volatile bool     g_arc_armed   = false;  // детектор дуги активний (уся HV-фаза)
volatile bool     g_level_armed = false;  // абсолютний поріг активний (лише витримка)
volatile uint16_t g_i_limit     = 0;      // поріг струму в кодах АЦП
volatile uint8_t  g_trip        = 0;      // 1 = тригер спрацював (ставить ISR)

// Межа апаратури — реалізує плата (contactor, ЦАП, шунт, реле баласту):
extern bool  hv_is_live(void);
extern void  hv_off(void);           // мʼяко зняти джерело
extern void  hv_off_hard(void);      // найшвидший розрив, безпечно з ISR
extern void  hv_enable(void);
extern void  dac_write(uint16_t code);
extern uint16_t hv_meas_volts(void); // зчитати вихідну напругу (для розряду)
extern void  bleed_on(void);
extern void  bleed_off(void);
extern bool  enclosure_open(void);
extern bool  button_l(void), button_r(void);
extern float ground_bond_ohms(void);
extern float insul_res_megohm(void);
extern uint16_t volts_to_code(uint16_t v);
extern void  latch_fault(const char *why);
extern void  log_result(const hipot_t *h);

#define DWELL_MS              1000     // витримка гіпоту (конвеєр: 1 с)
#define DISCHARGE_TIMEOUT_MS  500

static void enter(hipot_t *h, state_t s) { h->state = s; h->t_ms = 0; }

static void abort_test(hipot_t *h, const char *why) {
    hv_off_hard();
    h->verdict = V_FAIL;
    h->fail_reason = why;
    g_trip = 0;                 // прапорець спожито
    enter(h, ST_DISCHARGE);     // навіть у провалі — СПЕРШУ розрядити
}
```

Тепер сам такт автомата. Його викликає таймер кожну мілісекунду. Перше, що він робить у **будь-якому** стані, — перевіряє аварійні умови; лише потім розгалужується за станом. Порядок тут навмисний: небезпека має пріоритет над логікою послідовності.

```c
void hipot_tick(hipot_t *h) {          // виклик кожні 1 мс
    // ── Аварійні умови — найперше, у будь-якому стані ──
    bool live = hv_is_live();
    if (live && enclosure_open())                 abort_test(h, "кожух відчинено");
    else if (live && !(button_l() && button_r())) abort_test(h, "відпущено кнопку");
    else if (g_trip)                              abort_test(h, "тригер: поріг або дуга");

    switch (h->state) {
    case ST_IDLE:
        hv_off(); bleed_off();
        g_level_armed = g_arc_armed = false;
        if (two_hand_ok() && !enclosure_open())
            enter(h, ST_GROUND_BOND);
        break;

    case ST_GROUND_BOND:                        // Клас I: 25 А, R < 0.1 Ом
        if (ground_bond_ohms() > 0.10f) abort_test(h, "заземл. звʼязок > 0.1 Ом");
        else if (h->t_ms > 500)         enter(h, ST_INSUL_RES);
        break;

    case ST_INSUL_RES:                          // 500 В=, R має бути > 10 МОм
        if (insul_res_megohm() < 10.0f) abort_test(h, "опір ізоляції < 10 МОм");
        else if (h->t_ms > 1000) {
            ramp_setup(h, volts_to_code(2121), 2000);
            g_arc_armed = true;                 // дугу стежимо вже з наростання
            enter(h, ST_HIPOT_RAMP);
        }
        break;

    case ST_HIPOT_RAMP:                         // наростання: активний ЛИШЕ детектор дуги
        h->dac_code += h->dac_step;
        if (h->dac_code >= h->dac_target) {
            h->dac_code = h->dac_target;
            g_level_armed = true;               // у витримці вмикаємо й абсолютний поріг
            enter(h, ST_HIPOT_DWELL);
        }
        dac_write(h->dac_code);
        break;

    case ST_HIPOT_DWELL:                        // витримка: поріг + дуга
        if (h->t_ms > DWELL_MS) { h->verdict = V_PASS; enter(h, ST_DISCHARGE); }
        break;

    case ST_DISCHARGE:                          // спільний вузол: і успіх, і ABORT
        hv_off(); bleed_on();
        g_level_armed = g_arc_armed = false;
        if (hv_meas_volts() < 50) {             // ВИМІР, не таймер
            bleed_off();
            enter(h, h->verdict == V_FAIL ? ST_FAIL : ST_PASS);
        } else if (h->t_ms > DISCHARGE_TIMEOUT_MS) {
            latch_fault("розряд не завершився"); // баласт відгорів — станцію в стоп
        }
        break;

    case ST_PASS:
    case ST_FAIL:
        log_result(h);
        enter(h, ST_IDLE);
        break;
    }
    h->t_ms++;
}
```

Цей кістяк уже вміщує чотири з пʼяти обіцянок керма: порядок проб, аварійний скид, обовʼязковий розряд, вирок наприкінці. Бракує серця — швидкого годинника, що ловить пробій. Але спершу подивімося на порядок проб під іншим кутом, бо саме тут ховається найтонший різновид помилки.

## Порядок проб як інваріант: два способи його оборонити

У коді вище порядок тримається на перевірках під час виконання: `case ST_INSUL_RES` пускає в гіпот лише через `if (insul_res_megohm() >= 10)`. Це чесно працює, але покладається на дисципліну програміста: ніщо, крім його уважності, не заважає десь дописати перехід у `ST_HIPOT_RAMP` в обхід перевірки. Помилку такого штибу впіймають хіба на стенді — якщо пощастить.

Мова з типами-станами (typestate) переносить цю оборону з часу виконання в **час компіляції**: недозволений порядок просто не збереться. Це той рідкісний випадок, коли інша мова не переписує той самий код, а дає інакшу гарантію, тож варто побачити обидва підходи поряд.

:::tabs
```c
// C: порядок — перевірка під час ВИКОНАННЯ.
// Помилку («гіпот без опору ізоляції») ловимо на стенді, не в компіляторі.
static void go_hipot(hipot_t *h) {
    if (h->state != ST_INSUL_RES || h->verdict == V_FAIL) {
        abort_test(h, "гіпот без пройденого опору ізоляції");
        return;
    }
    ramp_setup(h, volts_to_code(2121), 2000);
    g_arc_armed = true;
    enter(h, ST_HIPOT_RAMP);
}
```
```rust
// Rust: кожна фаза — окремий ТИП. Метод `hipot` існує лише на `Station<InsulOk>`,
// тож «гіпот без опору ізоляції» — помилка КОМПІЛЯЦІЇ, а не сюрприз на стенді.
use core::marker::PhantomData;

struct GroundOk;
struct InsulOk;
struct Station<S> { hv: Hv, _s: PhantomData<S> }

impl Station<GroundOk> {
    // Пройти опір ізоляції можна лише звідси; успіх ВИДАЄ новий тип-стан.
    fn insulation(self, r_meg: f32) -> Result<Station<InsulOk>, Fail> {
        if r_meg > 10.0 { Ok(Station { hv: self.hv, _s: PhantomData }) }
        else            { Err(Fail::Insulation) }
    }
}

impl Station<InsulOk> {
    // `hipot` НЕ існує ніде, крім цього impl — раніше його не викликати.
    fn hipot(self, v: u16, dwell_ms: u32) -> Charged {
        self.hv.ramp_dwell(v, dwell_ms)
    }
}

// `Charged` неможливо «забути»: єдиний спосіб його позбутися — знищення,
// а воно ЗАВЖДИ розряджає — навіть на ранньому return чи паніці.
struct Charged { hv: Hv }
impl Charged {
    fn leakage(&mut self) -> f32 { self.hv.read_leak() }
}
impl Drop for Charged {
    fn drop(&mut self) { self.hv.bleed_until(50); }   // страж розряду
}
```
:::

Обидва варіанти обороняють той самий інваріант — «гіпот лише після опору ізоляції, розряд обовʼязково». Різниця в тому, **де** стоїть оборона. У C вона стоїть уголові програміста й перевіряється числом під час роботи; забудькуватість коштує баг, який доведеться ловити пробами. У Rust illegal-стан **непредставний**: тип `Station<GroundOk>` фізично не має методу `hipot`, а `Drop` для `Charged` робить пропущений розряд неможливим — компілятор не дасть скомпонувати програму, де виріб лишається зарядженим. Для станції, що може вбити, ця різниця не косметична.

Чому ж тоді все решта — на C? Бо серце станції живе там, куди typestate не дотягується: у регістрах АЦП і ЦАП, у перериванні, на гарячому шляху, де рахунок іде на мікросекунди. Там код замкнений на конкретне залізо, і мова стека нічого не додасть — лише забере передбачуваність. Тож розумний поділ такий: **холодну** логіку послідовності, де важить виразність, можна писати чим завгодно; **гарячий** тригер — там, де важить лише детермінізм, — пишуть однією системною мовою, і це майже завжди C.

## Швидкий годинник: наростання напруги

Перш ніж ловити пробій, напругу треба дбайливо **наростити**. Різкий стрибок — це кидок, який сам собою здатен пробити навіть здорову ізоляцію, тож напругу підводять похилою. Джерелом напруги керує [цифро-аналоговий перетворювач](book:electronics/dac) (ЦАП): автомат щотакту трохи піднімає код ЦАП, а той піднімає вихід високовольтного джерела.

```c
// Налаштувати наростання: від 0 до цільового коду за t_ramp_ms (крок автомата 1 мс).
void ramp_setup(hipot_t *h, uint16_t target_code, uint32_t t_ramp_ms) {
    h->dac_code   = 0;
    h->dac_target = target_code;
    // приріст за один такт; ділення з округленням угору — щоб дійти вчасно
    h->dac_step   = (uint16_t)((target_code + t_ramp_ms - 1) / t_ramp_ms);
    dac_write(0);
    hv_enable();
}
```

**Наростання до постійних 2121 В за 2 с (12-бітний ЦАП, джерело 0…3000 В):**

```
LSB    = 3000 / 4095 ≈ 0.733 В на код ЦАП
ціль   = 2121 В → код = 2121 / 0.733 ≈ 2894
такт   = 1 мс,  t_нар = 2000 мс
крок   = ⌈2894 / 2000⌉ = 2 коди за такт ≈ 1.47 В за такт
```

Округлення кроку вгору дає пологу, але передбачувану похилу: за 2894 / 2 ≈ 1447 тактів (≈1.45 с) напруга сягне цілі, після чого стан `ST_HIPOT_RAMP` замкне код на цілі й перейде у витримку. Тут напрошується перше запитання, у якому ховається тонка пастка: скільки струму тече крізь здоровий виріб просто через те, що напруга **росте**?

Струм крізь ємність визначає не сама напруга, а швидкість її зміни: I = C · dU/dt. Поки напруга нарощується, кожен конденсатор поперек рубежу — насамперед [Y-конденсатори](book:electronics/capacitance) — тягне зарядний струм, і виглядає він в очах датчика точнісінько як виток.

**Зарядний струм під час наростання (сумарна ємність 4.7 нФ):**

```
dU/dt = 2121 В / 2 с = 1060 В/с
I_нар = C · dU/dt = 4.7·10⁻⁹ · 1060 ≈ 5·10⁻⁶ А = 5 мкА     (лише Y-конд.)

а якщо додати вихідну ємність джерела 0.05 мкФ:
I_нар = 0.05·10⁻⁶ · 1060 ≈ 53 мкА
і за швидшого наростання (0.2 с): dU/dt = 10605 В/с → I_нар ≈ 530 мкА
```

Ось чому в такті автомата абсолютний поріг струму (`g_level_armed`) вмикається **лише у витримці**, а не під час наростання. Якби він діяв на похилій, зарядний струм здорового виробу — тим більший, чим крутіша похила, — брав би добрі вироби за браковані. Під час наростання лишають активним тільки детектор дуги: раптовий пробій усе одно дасть різкий стрибок, а плавний зарядний струм його не збудить. Абсолютний поріг набирає сенсу тільки на **сталій** напрузі, коли ємності вже заряджені й dU/dt = 0.

## Серце: семплування струму й тригер у перериванні

Тепер найтонше. Струм крізь ізоляцію [АЦП](book:electronics/adc) знімає з вимірювального шунта, і робить це не головний цикл, а [переривання](book:programming/interrupts): апаратура сама будить обробник на кожен готовий відлік. Чому не з головного циклу — видно з простого рахунку.

**Чому тригер мусить жити в перериванні:**

```
АЦП на 10 кГц → відлік кожні 1/10000 = 100 мкс
тригер в ISR:   «пробій → HV off» ≤ 100 мкс + затримка реле/оптрона
тригер у циклі: головний такт 1 мс → пробій горить удесятеро довше
                1 мс проти 100 мкс — ціла вічність для дуги-різака
```

Різниця в порядок величини — це різниця між ізоляцією, що встигла лише клацнути, й ізоляцією, пропаленою наскрізь. Тому рішення «рвати HV» ухвалює найшвидша ланка системи — сам обробник переривання, не питаючи дозволу в повільного автомата. Автомат він лише **повідомляє** прапорцем.

![Дві петлі керування: ліворуч повільний автомат станів на такті ~1 мс веде послідовність, читає прапорці, тримає таймери й журнал; праворуч швидка петля — переривання АЦП на 10 кГц знімає струм, дві перевірки (перевищення абсолютного порогу й стрибок di/dt як ознака дуги) через АБО негайно рвуть HV реле й GPIO та піднімають прапорець, який автомат бачить наступним тактом і завершує пробу як FAIL.](/book/electronics/power-electronics/mains-hipot-test/img/trip-arch.svg)

*Автомат вирішує повільно й точно; переривання вирішує миттєво й грубо. Розрив HV — за перериванням, вирок — за автоматом.*

Сам обробник робить дві незалежні перевірки. Перша — **абсолютний поріг**: якщо струм перевищив дозволене, виток завеликий. Друга — **виявлення дуги за похідною**: якщо струм від відліку до відліку **стрибнув**, це ознака дуги чи часткового пробою, бо здоровий виток міняється плавно, а дуга бʼє різко.

```c
// Викликається апаратно на кожен готовий відлік АЦП (10 кГц).
#define DI_ARC_ADC  40          // поріг стрибка |I[n]-I[n-1]| у кодах АЦП

extern volatile uint32_t g_sum_sq;  // накопичувач для СКЗ (читає автомат)
extern volatile uint32_t g_n;

void ADC_IRQHandler(void) {
    uint16_t i_now = (uint16_t)ADC_DR;      // читання DR знімає прапорець EOC
    static uint16_t i_prev = 0;

    int32_t di = (int32_t)i_now - (int32_t)i_prev;
    if (di < 0) di = -di;

    // Дуга: різкий стрибок — стежимо всю HV-фазу (наростання + витримка).
    // Поріг: перевищення рівня — лише у витримці (сталій напрузі).
    if ((g_arc_armed   && di    > DI_ARC_ADC) ||
        (g_level_armed && i_now > g_i_limit)) {
        hv_off_hard();          // РОЗІРВАТИ HV негайно, прямо з ISR
        g_trip = 1;             // повідомити повільний автомат
    }

    // Накопичити квадрати для СКЗ витоку у витримці (потрібне для змінної проби):
    g_sum_sq += (uint32_t)i_now * i_now;
    g_n++;
    i_prev = i_now;
}
```

Детектор дуги за di/dt — це чесна, але спрощена модель. Справжні промислові тестери ловлять дугу не за одним стрибком відліку, а за **високочастотним** вмістом струму: дуга шумить широкосмугово, тож її виказує смуговий фільтр, налаштований на сотні кілогерц. Стрибок «відлік до відліку» — це перше наближення тієї ж ідеї, і ламається воно там, де пробій розвивається **повільно**: поверхневе трекінгове проростання по забрудненому діелектрику наростає плавно й похідну не збудить. Саме тому три проби стоять разом і страхують одна одну: те, що проґавить швидкий детектор дуги, зловить абсолютний поріг витоку, а те, що проґавить гіпот загалом, — виловить попередня проба опору ізоляції, чутлива до вологи й бруду.

Для **змінної** проби одного порогу мало: там струм синусоїдний, і рішення ухвалюють за його діючим значенням. Обробник накопичує суму квадратів, а автомат наприкінці витримки бере [СКЗ](book:electronics/rms-current):

```
I_скз = √( (Σ I[n]²) / N )
```

з однією неодмінною умовою: N має накрити **ціле** число періодів мережі. Інакше сума квадратів обірветься на півперіоді, СКЗ зсунеться, і поріг попливе. За 10 кГц семплування й 50 Гц проби один період — це рівно 200 відліків; накопичувати треба кратно 200.

## Розряд: не таймером, а виміром

Після постійної проби виріб лишається зарядженим на ті самі кілька кіловольтів — і цей заряд кусає не гірше за мережу. Тому стан `ST_DISCHARGE` — не формальність, а обовʼязковий шлюз, крізь який проходить **кожен** виріб, і той, що пройшов, і той, що провалився. Джерело відʼєднують, до виробу підмикають розрядний (баластний) резистор і чекають — але чекають **не годинника, а вольтметра**.

Різниця принципова. Час розряду можна порахувати наперед:

**Час розряду до безпечних 50 В (C = 22 нФ, R_баласт = 500 кОм):**

```
τ = R · C = 5·10⁵ · 22·10⁻⁹ = 1.1·10⁻² с = 11 мс
t(до 50 В) = τ · ln(U₀ / U)
           = 11 мс · ln(2121 / 50)
           = 11 · ln(42.4) = 11 · 3.75 ≈ 41 мс
```

Сорок одна мілісекунда — і виріб безпечний. Спокусливо просто зачекати, скажімо, 100 мс і піти далі. Але це вбивча самовпевненість: розрахунок припускає, що баластний резистор **цілий**. А якщо він відгорів, обрив у реле баласту чи хтось поставив не той номінал — таймер спокійно відлічить свої 100 мс і випустить оператора до виробу, який усе ще тримає дві тисячі вольтів. Тому код **міряє** залишкову напругу й відпускає виріб лише коли вона реально впала нижче 50 В; а якщо за відведений час не впала — це не «щось затяглося», це відмова розрядного шляху, і станцію треба зупинити (`latch_fault`), а не мовчки пропустити виріб.

## Дворучний пуск і блокування кожуха

Лишилася пʼята обіцянка: станція не має стріляти, поки оператор не в безпеці. Дві ортогональні речі стережуть це. **Блокування кожуха** знеструмлює високу напругу, щойно кришку відчинено, — і в такті автомата ми вже бачили, що відкритий кожух за живої HV миттєво скидає в `ABORT`. **Дворучний пуск** змушує оператора тримати обидві руки на кнопках — отже, подалі від виробу — весь час, поки триває небезпека.

Стандарт на дворучне керування (EN ISO 13851, тип III) вимагає двох речей: обидві кнопки натиснуті **одночасно** — у вікні 0.5 с одна від одної, — і обидві слід **відпустити**, перш ніж почати новий цикл. Друга вимога — захист від фіксації: щоб оператор не заклинив одну кнопку скотчем і не запускав станцію однією рукою.

```c
// Дві кнопки: обидві натиснуті у вікні 500 мс, і обидві відпущені перед новим пуском.
bool two_hand_ok(void) {
    static uint16_t l_ms = 0, r_ms = 0;   // як довго кожна тримається, мс
    static bool armed = true;             // чи відпускали обидві після минулого пуску
    bool l = button_l(), r = button_r();

    l_ms = l ? (uint16_t)(l_ms + 1) : 0;
    r_ms = r ? (uint16_t)(r_ms + 1) : 0;

    if (!l && !r) armed = true;           // обидві відпущено — знову дозволено

    if (armed && l && r && l_ms < 500 && r_ms < 500) {
        armed = false;                    // до наступного відпускання — блок
        return true;                      // одночасне свіже натискання
    }
    return false;
}
```

Умова `l_ms < 500 && r_ms < 500` при обох натиснутих означає, що жодна з кнопок не тримається довше пів секунди, — тобто друга наздогнала першу в межах вікна. Прапорець `armed` спадає в момент пуску й підіймається лише коли **обидві** кнопки відпущено, — це і є захист від фіксації: заклинена кнопка не дасть `armed` піднятися, і другого пуску не буде. А неперервність утримання під час небезпеки стереже вже знайомий рядок в аварійному блоці такту: `live && !(button_l() && button_r())` рве HV, щойно оператор прибрав руку.

## Журнал: слід, що переживе виріб

Остання дія кожної проби — запис у **журнал**. Для мережевого виробу це не діагностика для себе, а слід простежуваності: за серійним номером має лишитися, коли, якою напругою й з яким витоком виріб пройшов гіпот. Тому журнал ведуть у енергонезалежній памʼяті й лише **дописують** (append-only): переписати чи стерти рядок не можна — інакше слід нічого не вартий.

```c
typedef struct {
    uint32_t  serial;     // серійний номер виробу
    uint32_t  t_unix;     // мітка часу
    verdict_t verdict;    // V_PASS / V_FAIL
    uint16_t  v_test;     // напруга проби, В
    uint16_t  i_leak_ua;  // виміряний виток, мкА
    char      reason[24]; // причина провалу (або "")
} record_t;

void log_result(const hipot_t *h) {
    record_t r = {0};
    r.serial    = current_serial();
    r.t_unix    = rtc_now();
    r.verdict   = h->verdict;
    r.v_test    = code_to_volts(h->dac_target);
    r.i_leak_ua = leak_microamps();
    if (h->verdict == V_FAIL && h->fail_reason)
        strncpy(r.reason, h->fail_reason, sizeof r.reason - 1);
    fram_append(&r, sizeof r);   // тільки дозапис, у FRAM/SD
}
```

## Складність і пастки

Автомат вище виглядає простим — і саме в цьому пастка: небезпека тут не в складному алгоритмі, а в тихих, розумно-виглядних скороченнях. Ось ті, що коштують найдорожче.

**Тригер у головному циклі.** Найспокусливіше — читати струм у головній петлі поряд з рештою логіки. Порахунок вище показав ціну: замість 100 мкс дуга горітиме до мілісекунди. Тригер мусить жити в перериванні з високим пріоритетом, і те переривання **не можна** маскувати надовго — жодних довгих критичних секцій із вимкненими перериваннями під час HV-фази.

**Абсолютний поріг під час наростання.** Зарядний струм здорового виробу під час наростання прямо пропорційний крутості похилої (I = C · dU/dt). Хто лишить абсолютний поріг активним на наростанні, той бракуватиме добрі вироби з великими Y-конденсаторами або вихідними ємностями — і що крутіша похила, то більше. Абсолютний поріг має сенс лише на сталій напрузі; на наростанні стережуть тільки дугу.

**СКЗ на неповному періоді.** Для змінної проби діюче значення обраховують по цілому числу періодів. Обірвіть накопичення на півперіоді — і поріг попливе від проби до проби без видимої причини.

**Розряд за таймером.** Годинник не знає, чи цілий баластний резистор. Розряд завершують за **виміряною** напругою, а невкладання у відведений час трактують як відмову розрядного шляху й зупиняють станцію, а не мовчки випускають виріб.

**Блокування кожуха лише в прошивці.** Прошивка може зависнути. Тому блокування кожуха мусить бути ще й **апаратним** — фізичний контакт, що розриває живлення джерела незалежно від коду. Прошивка тут друга лінія оборони, не єдина. Це загальний принцип: критичну для життя функцію не довіряють лише програмі.

**Небезпечний стан за замовчуванням.** Спитайте себе, що станеться, коли MCU скинеться посеред проби або пропаде живлення логіки. Правильна відповідь: HV має зникнути, а баласт — підмкнутися, **самі по собі**, без участі коду. Це закладають у залізо: реле HV нормально-розімкнене, реле баласту нормально-замкнене. Тоді знеструмлений стан і є безпечний стан, і будь-який збій падає в нього.

**Сторожовий таймер без безпечного скидання.** [Сторожовий таймер](book:programming/watchdog) поверне завислу станцію до життя — але лише якщо скидання за замовчуванням лишає HV знятою (див. попередній пункт). Watchdog, що перезапускає код у стан із живою HV, — не рятівник, а друге лихо.

**Гонитва за прапорцем.** `g_trip`, `g_arc_armed`, `g_i_limit` спільні між обробником переривання й автоматом, тому позначені `volatile`, а зчитувати й скидати їх треба свідомо: автомат споживає `g_trip` в `abort_test` (ставить у 0), і між зчитуванням і скиданням не має бути логіки, що знову його прогледить. Однобайтові прапорці на типовому MCU пишуться атомарно, тож мʼютекс тут зайвий, — але порядок доступу все одно тримають у голові, а не покладаються на випадок.

Зведіть це докупи — і побачите, що вся станція стоїть на одному принципі, знайомому з [самої філософії гіпоту](book:electronics/mains-safety): навантаж захисника до найгіршого випадку й переконайся, що встоїть, — а сам не стань джерелом лиха, яке ловиш. Автомат веде порядок, переривання ловить пробій за мікросекунди, розряд не відпускає виріб під зарядом, дві кнопки й кожух тримають оператора подалі, а журнал лишає слід. Кожна з цих пʼяти обіцянок — окремий рядок коду, який колись стане різницею між спрацьованим автоматом на конвеєрі й ударом струму в чиїхось руках.
