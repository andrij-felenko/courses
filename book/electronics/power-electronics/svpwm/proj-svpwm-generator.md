# ⚙️ Швидкий алгоритм генератора SVPWM для таймерів мікроконтролера

У контурі векторного керування електродвигуном (FOC) просторово-векторний модулятор викликається щомиті в перериванні ШІМ на частотах 10–50 кГц. Будь-яка затримка в цьому розрахунку безпосередньо збільшує фазовий зсув контуру струму, погіршує запас стійкості регуляторів і зменшує корисний час, що залишається процесорному ядру для виконання завдань вищого рівня. Тут наведено високоефективний алгоритм розрахунку секторів, тривалостей активних векторів і значень регістрів порівняння таймера без викликів важких тригонометричних функцій, розглянуто оптимізації з плаваючою та фіксованою комою, а також детально розібрано апаратну конфігурацію силових таймерів, компенсацію мертвого часу та методи подолання обмежень вимірювання струму.

## 1. Архітектура та математична постановка задачі

Модулятор SVPWM є кінцевою ланкою математичного тракту прямого векторного керування. На кожному кроці регулювання він отримує дві ортогональні компоненти напруги завдання `V_α` та `V_β` у нерухомій системі координат статора. Вони формуються на виході блоку зворотного перетворення Парка:

```
V_α = V_d · cos(θ_e) - V_q · sin(θ_e)
V_β = V_d · sin(θ_e) + V_q · cos(θ_e)
```

де `θ_e` — поточний електричний кут положення ротора, отриманий від енкодера, давачів Голла або алгоритму безсенсорного спостерігача потоку (*Sensorless Observer*), а `V_d`, `V_q` — виходи двох незалежних пропорційно-інтегральних регуляторів струму по поздовжній (потік) та поперечній (момент) осях.

Окрім напруг завдання, модулятору відомі поточна виміряна напруга шини живлення `V_dc` та період лічильника апаратного таймера `ARR` (*Auto-Reload Register*). Мета алгоритму — за мінімальну кількість процесорних тактів обчислити три цілочисельні пороги порівняння `CCR_A`, `CCR_B`, `CCR_C` для триканального силового таймера з симетричним підрахунком угору-вниз (*Center-Aligned Mode*).

## 2. Швидка ідентифікація сектора за три операції порівняння

Традиційний підхід із розрахунком кута через виклик `atan2(V_β, V_α)` вимагає десятків або сотень тактів процесора, інтерполяції тригонометричних таблиць і подальшого ділення на `60°`. На практиці застосовують проекційний метод розбиття площини: визначають положення вектора відносно трьох розділових прямих, що проходять через початок координат під кутами `0°`, `60°` та `120°`.

Проекції вектора на напрямки, ортогональні до цих розділових прямих, задаються трьома лінійними функціями:

```
U_1 = V_β
U_2 = (√3 / 2) · V_α - 0.5 · V_β
U_3 = -(√3 / 2) · V_α - 0.5 · V_β
```

Знаки цих трьох функцій формують унікальний 3-бітний цифровий код:

```
код = (U_1 > 0 ? 1 : 0) + (U_2 > 0 ? 2 : 0) + (U_3 > 0 ? 4 : 0)
```

Комбінації `0` (`000`) та `7` (`111`) математично неможливі, оскільки сума `U_1 + U_2 + U_3 = 0` тотожно дорівнює нулю для будь-якої точки площини. Решта шість комбінацій однозначно вказують номер сектора через компактну таблицю прямої адресації:

| 3-бітний код `(b₂ b₁ b₀)` | `U_3 > 0` | `U_2 > 0` | `U_1 > 0` | Номер сектора | Діапазон кута вектора |
|:---:|:---:|:---:|:---:|:---:|:---:|
| `1` (`001`) | Ні | Ні | Так | **Сектор II** | `60° .. 120°` |
| `2` (`010`) | Ні | Так | Ні | **Сектор VI** | `300° .. 360°` |
| `3` (`011`) | Ні | Так | Так | **Сектор I** | `0° .. 60°` |
| `4` (`100`) | Так | Ні | Ні | **Сектор IV** | `180° .. 240°` |
| `5` (`101`) | Так | Ні | Так | **Сектор III** | `120° .. 180°` |
| `6` (`110`) | Так | Так | Ні | **Сектор V** | `240° .. 300°` |

Таблиця перекодування зберігається у флеш-пам'яті як статичний масив на 8 байтів: `sector_map[8] = {0, 2, 6, 1, 4, 3, 5, 0}`. У результаті весь процес локалізації сектора зводиться до трьох операцій порівняння з нулем, кількох бітових зсувів і одного зчитування з масиву.

## 3. Алгебраїчний розрахунок тривалостей векторів

Для обчислення тривалостей активних векторів визначаються три проміжні базисні змінні:

```
X = √3 · (ARR / V_dc) · V_β
Y = (ARR / V_dc) · (1.5 · V_α + (√3 / 2) · V_β)
Z = (ARR / V_dc) · (-1.5 · V_α + (√3 / 2) · V_β)
```

Константи `√3 ≈ 1.7320508`, `1.5` та `√3/2 ≈ 0.8660254` обчислюються на етапі компіляції програми. Якщо напруга живлення `V_dc` стабільна, коефіцієнт `ARR / V_dc` також попередньо кешується і перераховується лише у повільному контурі моніторингу батареї.

Залежно від визначеного сектора, тривалості першого активного вектора `T_1` та другого активного вектора `T_2` вибираються за симетричною таблицею перестановок:

| Номер сектора | Перший активний інтервал `T_1` | Другий активний інтервал `T_2` |
|:---:|:---:|:---:|
| **Сектор 1** | `-Z` | `X` |
| **Сектор 2** | `Z` | `Y` |
| **Сектор 3** | `X` | `-Y` |
| **Сектор 4** | `-X` | `Z` |
| **Сектор 5** | `-Y` | `-Z` |
| **Сектор 6** | `Y` | `-X` |

## 4. Обмеження та масштабування в зоні перемодуляції

Якщо вектор напруги завдання за амплітудою перевищує радіус вписаного кола гексагона (`|V_ref| > V_dc / √3`), сума обчислених активних тривалостей перевищує доступний період таймера: `T_1 + T_2 > ARR`. Якщо проігнорувати цей стан, залишковий нульовий час стане від'ємним, що при перетворенні у беззнакові регістри таймера `uint16_t` спричинить катастрофічне переповнення лічильника, перемикання ключів у протилежні стани та апаратне спрацювання захисту від короткого замикання.

Для забезпечення безперебійної та безпечної роботи застосовується динамічне лінійне масштабування:

```
T_sum = T_1 + T_2
якщо T_sum > ARR:
    T_1 = (T_1 · ARR) / T_sum
    T_2 = (T_2 · ARR) / T_sum
```

Це масштабування зменшує модуль вектора рівно настільки, щоб його вершина лягла строго на контур шестикутника, зберігаючи при цьому правильний кут просторової орієнтації магнітного поля `θ`. Двигун отримує максимальну напругу, яку силова частина здатна видати в цьому напрямку, без спотворення фазового кута моменту.

## 5. Симетричний розподіл часів на регістри порівняння

У 7-сегментному режимі таймер рахує симетрично від `0` до `ARR` і назад до `0`. Регістри порівняння `CCR` визначають моменти перемикання силових транзисторів. Залишковий час нульового стану ділиться порівну між векторами `V₀ (000)` та `V₇ (111)`:

```
T_0 = ARR - T_1 - T_2
t_a = T_0 / 4
t_b = t_a + T_1 / 2
t_c = t_b + T_2 / 2
```

Прив'язка розрахованих порогів `t_a, t_b, t_c` до фізичних фаз двигуна `A, B, C` виконується залежно від поточного сектора:

| Сектор | Фаза A (`CCR_A`) | Фаза B (`CCR_B`) | Фаза C (`CCR_C`) |
|:---:|:---:|:---:|:---:|
| **1** | `t_a` | `t_b` | `t_c` |
| **2** | `t_b` | `t_a` | `t_c` |
| **3** | `t_c` | `t_a` | `t_b` |
| **4** | `t_c` | `t_b` | `t_a` |
| **5** | `t_b` | `t_c` | `t_a` |
| **6** | `t_a` | `t_c` | `t_b` |

## 6. Реалізація алгоритму на C та C++ з плаваючою крапкою

Нижче наведено готову виробничу реалізацію модулятора, оптимізовану під процесорні ядра з апаратним FPU (ARM Cortex-M4F/M7/C2000).

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define SQRT3       1.732050807568877f
#define SQRT3_HALF  0.8660254037844386f
#define ONE_AND_HALF 1.5f

typedef struct {
    float v_alpha;      // Вхідна напруга alpha [В]
    float v_beta;       // Вхідна напруга beta [В]
    float v_dc;         // Напруга шини DC [В]
    uint16_t arr;       // Період лічильника таймера
} SvpwmInput;

typedef struct {
    uint16_t ccr_a;     // Поріг таймера для фази A
    uint16_t ccr_b;     // Поріг таймера для фази B
    uint16_t ccr_c;     // Поріг таймера для фази C
    uint8_t sector;     // Номер сектора (1..6)
} SvpwmOutput;

static const uint8_t SECTOR_MAP[8] = { 0, 2, 6, 1, 4, 3, 5, 0 };

SvpwmOutput svpwm_calculate(const SvpwmInput* in) {
    SvpwmOutput out;
    if (in->v_dc <= 0.0f || in->arr == 0) {
        out.ccr_a = in->arr / 2;
        out.ccr_b = in->arr / 2;
        out.ccr_c = in->arr / 2;
        out.sector = 0;
        return out;
    }

    // 1. Швидка ідентифікація сектора
    float u1 = in->v_beta;
    float u2 = SQRT3_HALF * in->v_alpha - 0.5f * in->v_beta;
    float u3 = -SQRT3_HALF * in->v_alpha - 0.5f * in->v_beta;

    uint8_t code = 0;
    if (u1 > 0.0f) code |= 1;
    if (u2 > 0.0f) code |= 2;
    if (u3 > 0.0f) code |= 4;

    uint8_t sector = SECTOR_MAP[code];
    out.sector = sector;

    // 2. Базові проекції тривалостей
    float scale = (float)in->arr / in->v_dc;
    float x = SQRT3 * scale * in->v_beta;
    float y = scale * (ONE_AND_HALF * in->v_alpha + SQRT3_HALF * in->v_beta);
    float z = scale * (-ONE_AND_HALF * in->v_alpha + SQRT3_HALF * in->v_beta);

    // 3. Вибір активних інтервалів
    float t1 = 0.0f, t2 = 0.0f;
    switch (sector) {
        case 1: t1 = -z; t2 =  x; break;
        case 2: t1 =  z; t2 =  y; break;
        case 3: t1 =  x; t2 = -y; break;
        case 4: t1 = -x; t2 =  z; break;
        case 5: t1 = -y; t2 = -z; break;
        case 6: t1 =  y; t2 = -x; break;
        default: t1 = 0.0f; t2 = 0.0f; break;
    }

    // 4. Захист від перемодуляції
    float t_sum = t1 + t2;
    float arr_f = (float)in->arr;
    if (t_sum > arr_f) {
        float norm = arr_f / t_sum;
        t1 *= norm;
        t2 *= norm;
    }

    // 5. Симетричний 7-сегментний розподіл
    float t0 = arr_f - t1 - t2;
    float ta = t0 * 0.25f;
    float tb = ta + t1 * 0.5f;
    float tc = tb + t2 * 0.5f;

    // 6. Призначення фазам
    switch (sector) {
        case 1:
            out.ccr_a = (uint16_t)ta;
            out.ccr_b = (uint16_t)tb;
            out.ccr_c = (uint16_t)tc;
            break;
        case 2:
            out.ccr_a = (uint16_t)tb;
            out.ccr_b = (uint16_t)ta;
            out.ccr_c = (uint16_t)tc;
            break;
        case 3:
            out.ccr_a = (uint16_t)tc;
            out.ccr_b = (uint16_t)ta;
            out.ccr_c = (uint16_t)tb;
            break;
        case 4:
            out.ccr_a = (uint16_t)tc;
            out.ccr_b = (uint16_t)tb;
            out.ccr_c = (uint16_t)ta;
            break;
        case 5:
            out.ccr_a = (uint16_t)tb;
            out.ccr_b = (uint16_t)tc;
            out.ccr_c = (uint16_t)ta;
            break;
        case 6:
            out.ccr_a = (uint16_t)ta;
            out.ccr_b = (uint16_t)tc;
            out.ccr_c = (uint16_t)tb;
            break;
        default:
            out.ccr_a = in->arr / 2;
            out.ccr_b = in->arr / 2;
            out.ccr_c = in->arr / 2;
            break;
    }

    return out;
}
```
```cpp
#include <cstdint>
#include <array>
#include <algorithm>

namespace motor_control {

struct SvpwmInput {
    float v_alpha{0.0f};      // Напруга alpha [В]
    float v_beta{0.0f};       // Напруга beta [В]
    float v_dc{48.0f};        // Напруга шини DC [В]
    uint16_t arr{2400};       // Межа лічильника таймера
};

struct SvpwmOutput {
    uint16_t ccr_a{0};        // Фаза A
    uint16_t ccr_b{0};        // Фаза B
    uint16_t ccr_c{0};        // Фаза C
    uint8_t sector{0};        // Сектор 1..6
};

class SpaceVectorModulator {
public:
    static constexpr float SQRT3        = 1.732050807568877f;
    static constexpr float SQRT3_HALF   = 0.8660254037844386f;
    static constexpr float ONE_AND_HALF = 1.5f;

    [[nodiscard]] static constexpr SvpwmOutput calculate(const SvpwmInput& in) noexcept {
        if (in.v_dc <= 0.0f || in.arr == 0) {
            const uint16_t mid = in.arr / 2;
            return { mid, mid, mid, 0 };
        }

        // 1. Швидкий пошук сектора
        const float u1 = in.v_beta;
        const float u2 = SQRT3_HALF * in.v_alpha - 0.5f * in.v_beta;
        const float u3 = -SQRT3_HALF * in.v_alpha - 0.5f * in.v_beta;

        const uint8_t code = static_cast<uint8_t>(u1 > 0.0f) |
                            (static_cast<uint8_t>(u2 > 0.0f) << 1) |
                            (static_cast<uint8_t>(u3 > 0.0f) << 2);

        constexpr std::array<uint8_t, 8> sector_map{ 0, 2, 6, 1, 4, 3, 5, 0 };
        const uint8_t sector = sector_map[code];

        // 2. Розрахунок проекцій
        const float scale = static_cast<float>(in.arr) / in.v_dc;
        const float x = SQRT3 * scale * in.v_beta;
        const float y = scale * (ONE_AND_HALF * in.v_alpha + SQRT3_HALF * in.v_beta);
        const float z = scale * (-ONE_AND_HALF * in.v_alpha + SQRT3_HALF * in.v_beta);

        // 3. Вибір часів активних векторів
        float t1 = 0.0f;
        float t2 = 0.0f;
        switch (sector) {
            case 1: t1 = -z; t2 =  x; break;
            case 2: t1 =  z; t2 =  y; break;
            case 3: t1 =  x; t2 = -y; break;
            case 4: t1 = -x; t2 =  z; break;
            case 5: t1 = -y; t2 = -z; break;
            case 6: t1 =  y; t2 = -x; break;
            default: break;
        }

        // 4. Обмеження перемодуляції
        const float arr_f = static_cast<float>(in.arr);
        const float t_sum = t1 + t2;
        if (t_sum > arr_f) {
            const float norm = arr_f / t_sum;
            t1 *= norm;
            t2 *= norm;
        }

        // 5. Симетричні пороги комутації
        const float t0 = arr_f - t1 - t2;
        const float ta = t0 * 0.25f;
        const float tb = ta + t1 * 0.5f;
        const float tc = tb + t2 * 0.5f;

        // 6. Розподіл по каналах
        const auto u_ta = static_cast<uint16_t>(ta);
        const auto u_tb = static_cast<uint16_t>(tb);
        const auto u_tc = static_cast<uint16_t>(tc);

        switch (sector) {
            case 1: return { u_ta, u_tb, u_tc, sector };
            case 2: return { u_tb, u_ta, u_tc, sector };
            case 3: return { u_tc, u_ta, u_tb, sector };
            case 4: return { u_tc, u_tb, u_ta, sector };
            case 5: return { u_tb, u_tc, u_ta, sector };
            case 6: return { u_ta, u_tc, u_tb, sector };
            default: {
                const uint16_t mid = in.arr / 2;
                return { mid, mid, mid, 0 };
            }
        }
    }
};

} // namespace motor_control
```

## 7. Цілочисельна оптимізація у форматі з фіксованою комою Q15

Для мікроконтролерів без апаратного блока FPU (ARM Cortex-M0, Cortex-M3 тощо) обчислення з числами одинарної точності `float` емулюються програмно через бібліотечні виклики, що займає сотні тактів і неприпустимо перевантажує процесор. У таких архітектурах усі вхідні напруги та внутрішні змінні нормалізують до відносного діапазону `[-1.0, +1.0)` і подають у форматі Q15, де одиниці відповідає ціле число `32768` (`2¹⁵`).

:::tabs
```c
#include <stdint.h>

#define Q15_ONE          32768
#define Q15_SQRT3        56756   // 1.7320508 * 32768
#define Q15_SQRT3_HALF   28378   // 0.8660254 * 32768
#define Q15_ONE_AND_HALF 49152   // 1.5 * 32768

typedef struct {
    int16_t q_alpha;    // Q15 напруга V_alpha / V_dc [-32768..32767]
    int16_t q_beta;     // Q15 напруга V_beta / V_dc  [-32768..32767]
    uint16_t arr;       // Період таймера
} SvpwmQ15Input;

typedef struct {
    uint16_t ccr_a;
    uint16_t ccr_b;
    uint16_t ccr_c;
    uint8_t sector;
} SvpwmQ15Output;

static const uint8_t SECTOR_MAP_Q15[8] = { 0, 2, 6, 1, 4, 3, 5, 0 };

SvpwmQ15Output svpwm_q15_calc(const SvpwmQ15Input* in) {
    SvpwmQ15Output out;

    // 1. Ідентифікація сектора
    int32_t u1 = in->q_beta;
    int32_t u2 = ((int32_t)Q15_SQRT3_HALF * in->q_alpha - (int32_t)(Q15_ONE / 2) * in->q_beta) >> 15;
    int32_t u3 = (-(int32_t)Q15_SQRT3_HALF * in->q_alpha - (int32_t)(Q15_ONE / 2) * in->q_beta) >> 15;

    uint8_t code = 0;
    if (u1 > 0) code |= 1;
    if (u2 > 0) code |= 2;
    if (u3 > 0) code |= 4;

    uint8_t sector = SECTOR_MAP_Q15[code];
    out.sector = sector;

    // 2. Базові складові в масштабі ARR
    int32_t x = (((int32_t)Q15_SQRT3 * in->q_beta) >> 15) * in->arr >> 15;
    int32_t y = (((int32_t)Q15_ONE_AND_HALF * in->q_alpha + (int32_t)Q15_SQRT3_HALF * in->q_beta) >> 15) * in->arr >> 15;
    int32_t z = (((int32_t)-Q15_ONE_AND_HALF * in->q_alpha + (int32_t)Q15_SQRT3_HALF * in->q_beta) >> 15) * in->arr >> 15;

    // 3. Активні часи
    int32_t t1 = 0, t2 = 0;
    switch (sector) {
        case 1: t1 = -z; t2 =  x; break;
        case 2: t1 =  z; t2 =  y; break;
        case 3: t1 =  x; t2 = -y; break;
        case 4: t1 = -x; t2 =  z; break;
        case 5: t1 = -y; t2 = -z; break;
        case 6: t1 =  y; t2 = -x; break;
        default: break;
    }

    // 4. Обмеження перемодуляції
    int32_t t_sum = t1 + t2;
    if (t_sum > in->arr && t_sum > 0) {
        t1 = (t1 * in->arr) / t_sum;
        t2 = (t2 * in->arr) / t_sum;
    }

    // 5. Симетричні пороги
    int32_t t0 = in->arr - t1 - t2;
    uint16_t ta = (uint16_t)(t0 >> 2);
    uint16_t tb = (uint16_t)(ta + (t1 >> 1));
    uint16_t tc = (uint16_t)(tb + (t2 >> 1));

    switch (sector) {
        case 1: out.ccr_a = ta; out.ccr_b = tb; out.ccr_c = tc; break;
        case 2: out.ccr_a = tb; out.ccr_b = ta; out.ccr_c = tc; break;
        case 3: out.ccr_a = tc; out.ccr_b = ta; out.ccr_c = tb; break;
        case 4: out.ccr_a = tc; out.ccr_b = tb; out.ccr_c = ta; break;
        case 5: out.ccr_a = tb; out.ccr_b = tc; out.ccr_c = ta; break;
        case 6: out.ccr_a = ta; out.ccr_b = tc; out.ccr_c = tb; break;
        default:
            out.ccr_a = in->arr >> 1;
            out.ccr_b = in->arr >> 1;
            out.ccr_c = in->arr >> 1;
            break;
    }

    return out;
}
```

## 8. Апаратна інтеграція з таймерами та конфігурація периферії

Для бездоганного функціонування силового каскаду таймер мікроконтролера (наприклад, розширений таймер TIM1/TIM8 у сімействі STM32 або апаратний модуль ePWM у мікроконтролерах Texas Instruments C2000) має бути сконфігурований у строго визначений режим:

1. **Режим лічильника (Center-Aligned Mode 1 / Up-Down Count):**
   Лічильник безперервно рахує від `0` до `ARR` і вниз від `ARR` до `0`. Це забезпечує симетрію імпульсів відносно центру періоду та усуває парні гармоніки комутації. Подія прапорця напрямку (`DIR`) дозволяє точно визначати фазу підйому або спаду лічильника.

2. **Подвійне буферизування регістрів (Preload Enabled):**
   Біти `OCxPE` (Output Compare Preload Enable) мають бути встановлені в одиницю. У цьому разі запис нових значень у регістри `CCR1..CCR3` не змінює стан активного ШІМ-сигналу безпосередньо в момент виклику. Нові значення спочатку потрапляють у тіньові буфери (*Shadow Registers*) і одночасно копіюються в робочі регістри лише за апаратною подією оновлення (*Update Event*, UEV) у точці верхівки (`CNT == ARR`) або в долині (`CNT == 0`). Це повністю унеможливлює появу асиметричних «зламаних» імпульсів та наскрізних струмів при стрибках напруги чи зміні сектора.

3. **Синхронізація вибірки АЦП (ADC Triggering):**
   Вимірювання струмів на нижніх шунтах напівмостів можливе виключно тоді, коли нижні силові транзистори повністю відкриті (стан нульового вектора `V₀ (000)`). У 7-сегментному патерні стан `V₀` діє на початку і наприкінці періоду, коли лічильник таймера проходить через нуль. Таймер налаштовують на генерацію вихідного тригера `TRGO` за подією скидання лічильника (`CNT == 0`), що запускає інжекційну групу АЦП точно посередині нульового вектора, далеко від комутаційних дзвінків та ємнісних сплесків струму.

## 9. Компенсація мертвого часу (Dead-Time Compensation)

Щоб запобігти наскрізному короткому замиканню стійки інвертора, апаратний генератор мертвого часу (*Dead-Time Generator*, DTG) затримує вмикання кожного верхнього транзистора після вимикання нижнього і навпаки на час `t_dead` (типово 200–1000 нс).

Протягом мертвого часу обидва ключі стійки закриті, а фазний струм протікає через антипаралельні захисні діоди польових транзисторів. Напрямок струму однозначно диктує, яка з шин живлення підключається до вихідної клеми двигуна:

- Якщо струм витікає з фази в обмотку (`i_phase > 0`), відкривається нижній діод, і вихідна напруга падає до нуля на весь інтервал `t_dead`. Фактична вихідна напруга виявляється меншою за задану: `V_real = V_target - ΔV`.
- Якщо струм втікає з обмотки в інвертор (`i_phase < 0`), відкривається верхній діод, і напруга підтягується до `+V_dc`. Фактична напруга виявляється більшою за задану: `V_real = V_target + ΔV`.

Величина помилки напруги пропорційна мертвому часу: `ΔV = (t_dead / T_s) · V_dc`.

Ця помилка спричиняє сходинкові спотворення фазної напруги при кожному переході струму через нуль, що породжує виражені 5-ту та 7-му паразитичні гармоніки струму і викликає пульсації крутного моменту двигуна на малих обертах.

Для компенсації мертвого часу перед подачею напруг у модулятор SVPWM до них додають коригувальний вектор `ΔV_αβ`:

:::tabs
```c

else if (i_a < -current_threshold) v_a_comp -= dt_volt;

if (i_b > current_threshold)       v_b_comp += dt_volt;
else if (i_b < -current_threshold) v_b_comp -= dt_volt;

else if (i_c < -current_threshold) v_c_comp -= dt_volt;
```

```cpp
// Ідіоматична C++ функція компенсації мертвого часу
template <typename PhaseArray>
constexpr void apply_dead_time_compensation(PhaseArray& voltages,
                                           const PhaseArray& currents,
                                           float dt_voltage,
                                           float threshold) noexcept {
    for (size_t i = 0; i < voltages.size(); ++i) {
        if (currents[i] > threshold) {
            voltages[i] += dt_voltage;
        } else if (currents[i] < -threshold) {
            voltages[i] -= dt_voltage;
        }
    }
}
```

## 10. Проблема мінімального вікна вибірки струму (Current Sampling Limit)

У тришунтовій системі вимірювання для коректного оцифрування фазного струму нижній транзистор відповідної фази повинен залишатися увімкненим щонайменше протягом інтервалу `t_min_sample`:

```
t_min_sample = t_dead + t_ringing + t_adc_sample
```

де `t_ringing` — час затухання комутаційного дзвінка напруги на шунті після відкриття ключа (типово 300–600 нс), а `t_adc_sample` — тривалість вибірки пристрою вибірки-зберігання АЦП (150–500 нс). Загальний мінімальний час зазвичай становить `1.5 .. 2.5 мкс`.

Коли референсний вектор напруги наближається до межі сектора або до максимальної амплітуди гексагона, тривалість увімкнення одного з нижніх ключів спадає нижче `t_min_sample`. АЦП не встигає провести достовірне вимірювання струму, що призводить до збою контуру FOC.

Для вирішення цієї проблеми застосовують два взаємодоповнюючі методи:

1. **Реконструкція двох струмів із трьох:**
   У будь-якому секторі один із трьох нижніх ключів завжди відкритий довше за інші. Достатньо виміряти струми лише у двох фазах із найдовшим часом відкритого стану нижнього плеча, а струм третьої фази миттєво обчислити за першим законом Кірхгофа: `i_third = -i_first - i_second`.
2. **Алгоритм фазового зсуву імпульсів (PWM Phase Shifting):**
   Якщо в секторі два нижні імпульси стають коротшими за `t_min_sample`, модулятор асиметрично зсуває центри імпульсів двох фаз у часі на один такт ШІМ у протилежні боки. Це штучно розширює вікно для вимірювання струму без зміни середнього вольт-секундного балансу за період.

## 11. Повний цикл обробника переривання ШІМ (FOC ISR Walkthrough)

Типова послідовність дій всередині високопріоритетного переривання таймера ШІМ виконується у строгому хронологічному порядку:

1. **Зчитування результатів АЦП:** отримання сирих значень струмів фаз `ia_raw, ib_raw` та напруги шини `vdc_raw` за DMA або регістрами перетворення.
2. **Калібрування та переведення в ампери:** віднімання нуля підсилювача `ia = (ia_raw - ia_offset) · k_gain`.
3. **Пряме перетворення Кларк:** отримання `i_α, i_β` з фазних струмів.
4. **Зчитування положення ротора:** отримання електричного кута `θ_e` від давача положення.
5. **Пряме перетворення Парка:** обчислення поздовжнього `i_d` та поперечного `i_q` струмів ротора.
6. **Контур регулювання струму:** виконання двох паралельних PI-регуляторів для отримання напруг завдання `V_d, V_q`.
7. **Компенсація перехресних зв'язків та мертвого часу:** додавання швидкохідних складових `ω · L · I` та корекції мертвого часу.
8. **Зворотне перетворення Парка:** отримання напруг статора `V_α, V_β`.
9. **Модулятор SVPWM:** виклик функції `svpwm_calculate()` для обчислення `CCR1, CCR2, CCR3`.
10. **Запис у тіньові регістри таймера:** оновлення регістрів захоплення/порівняння для наступного періоду комутації.

## 12. Відновлення струмів в одношунтовій топології (Single-Shunt Sensing)

У недорогих серійних електроприводах (наприклад, у побутовій техніці, насосах та масових ESC для квадрокоптерів) замість трьох фазних шунтів встановлюють лише один струмовимірювальний резистор у спільній мінусовій шині живлення інвертора `GND`.

У такій схемі струм, що протікає через спільний шунт `R_shunt`, у будь-яку мить часу відображає струм тієї фази, чий верхній ключ увімкнений (а нижній вимкнений), за умови, що інші дві фази приєднані до землі:

- Під час дії першого активного вектора Сектора 1 `V₁ (100)` верхній ключ фази A відкритий, а ключі фаз B і C закриті. Струм шини дорівнює струму фази A: `i_shunt = +i_a`.
- Під час дії другого активного вектора `V₂ (110)` верхні ключі фаз A і B відкриті, а фаза C заземлена. За першим законом Кірхгофа струм шини становить `i_shunt = i_a + i_b = -i_c`. Звідси струм фази B знаходиться як `i_b = -i_a - i_c`.
- Під час нульових станів `V₀ (000)` та `V₇ (111)` струм по шині живлення не протікає (`i_shunt = 0`).

Для реалізації одношунтового методу мікроконтролер повинен виконати два швидкі вимірювання АЦП за один період ШІМ: першу вибірку `ADC_Sample_1` посередині інтервалу першого активного вектора `T_1`, а другу `ADC_Sample_2` — посередині інтервалу другого активного вектора `T_2`.

Головна інженерна проблема одношунтового методу — **зона нечутливості на межах секторів та при малій напрузі**. Якщо вектор `V_ref` знаходиться близько до осі або має малу амплітуду, один із часів `T_1` або `T_2` стає меншим за мінімальний час встановлення операційного підсилювача `t_settling` (типово 1.2–2.0 мкс). У цьому разі застосовують алгоритм асиметричного фазового зсуву імпульсів ШІМ (*PWM Phase Shift Algorithm*), який розсуває фронти перемикання стійок інвертора рівно настільки, щоб утворити необхідне часове вікно для спрацювання АЦП, зберігаючи середній вольт-секундний інтеграл незмінним.

## 13. Методика лабораторного тестування та налагодження SVPWM

Перше вмикання новоствореного модулятора SVPWM на реальному залізі завжди проводять за суворою покроковою процедурою:

1. **Тест у розімкненому контурі (Open-Loop V/f Spin Test):**
   Контур зворотного зв'язку за струмом повністю відключають. Замість виходів регуляторів задають віртуальний обертовий вектор зі сталою амплітудою та повільно зростаючим кутом:
   `V_α = V_test · cos(ω_test · t)`, `V_β = V_test · sin(ω_test · t)`.
   Двигун підключають через джерело живлення з обмеженням струму. Якщо алгоритм і таблиці перекодування секторів реалізовані вірно, двигун починає плавно та безшумно обертатися без ривків і вібрацій.
2. **Осцилографічний контроль фазної напруги:**
   Щуп осцилографа підключають до однієї з фазних клем двигуна відносно мінусової шини `GND` через низькочастотний RC-фільтр (`R = 1 кОм, C = 100 нФ`, частота зрізу `1.6 кГц`). На екрані осцилографа має спостерігатися характерна двогорба «сідлоподібна» форма сигналу з чітко сплющеною верхівкою. Наявність гострих синусоїд або прямокутних зрізів свідчить про помилку в формулах розрахунку нульових часів `t_a, t_b, t_c`.
3. **Контроль лінійної напруги:**
   За допомогою диференційного щупа вимірюють напругу безпосередньо між клемами `Phase A` та `Phase B`. Сигнал після фільтра повинен бути ідеально чистою синусоїдою без жодної сідлоподібності, оскільки синфазна третя гармоніка зобов'язана повністю віднятися між двома фазами.
4. **Перевірка правильності напрямку обертання:**
   Якщо при додатній швидкості двигун обертається у зворотному напрямку або регулятор струму йде у рознос, перевіряють послідовність чергування фаз: пряме чергування векторів відповідає послідовності `V₁ → V₂ → V₃ → V₄ → V₅ → V₆`. Якщо порядок переплутано, змінюють знак координати `V_β` або міняють місцями фази B і C.

## 14. Таблиця діагностики типових помилок реалізації

| Симптом несправності | Фізична першопричина | Метод усунення |
|:---|:---|:---|
| **Двигун гуде і смикається на малих обертах** | Переплутані номери секторів або фази в таблиці | Звірити бітову маску `U1..U3` з таблицею `SECTOR_MAP` |
| **Стрибки струму при переході між секторами** | Запис у регістри `CCR` без подвійного буферизування | Увімкнути тіньові регістри `OCxPE` в таймері |
| **Швидкий нагрів транзисторів без навантаження** | Наскрізні струми через замалий мертвий час | Збільшити регістр мертвого часу `DTG` таймера |
| **Сходинки струму при нульовому струмі фази** | Відсутність або перекомпенсація мертвого часу | Налаштувати поріг `current_threshold` у компенсаторі |
| **Аварійне вибивання захисту при макс. обертах** | Переповнення `CCR` через відсутність захисту від перемодуляції | Додати перевірку `T1 + T2 > ARR` та масштабування |
