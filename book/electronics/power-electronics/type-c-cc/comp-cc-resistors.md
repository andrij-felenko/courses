# 🔌 Резистори CC у USB-C

Уся «домовленість» базового USB-C тримається на двох резисторах на лінії конфігурації **CC** (*Configuration Channel*, англ. «канал налаштування»). Джерело вішає підтяжку вгору — **Rp** (*pull-up*); пристрій-споживач вішає підтяжку вниз — **Rd** (*pull-down*), стандартного номіналу **5.1 кОм**. Тут зібрано точні числа, яких бракує для практики: які саме номінали дозволені, які пороги напруги відповідають кожному струмовому рівню, як sink їх читає рядком коду й чому хибний або відсутній Rd залишає пристрій без живлення. Партномери й конкретні мікросхеми названо як приклад — сама поведінка однакова в будь-якій реалізації, бо її диктує специфікація USB Type-C, а не виробник.

## Чому саме 5.1 кОм, а не «будь-який» резистор

Rd — це не просто «якийсь» опір донизу: специфікація вимагає рівно **5.1 кОм ±5 %**, і це число несе подвійний зміст. По-перше, воно мусить бути достатньо малим, щоб упевнено перемогти будь-яку підтяжку Rp джерела й стягнути CC у робочий діапазон, — інакше слабка підтяжка лишила б лінію в невизначеності. По-друге, воно мусить бути достатньо великим, щоб джерело відрізнило **пристрій** (Rd) від **кабелю** (Ra ≈ 0.8–1.2 кОм, набагато менший опір e-marker, про який нижче). 5.1 кОм лягає рівно посередині цих двох вимог: явно «жорсткіше» за будь-який Rp і явно «м'якіше» за Ra. Тому довільний резистор «приблизно того ж порядку» не годиться — 4.7 кОм із сусіднього ряду E12 формально поза допуском, і обережне джерело має право вас не побачити.

> 🔧 **Навіщо це.** Коли під рукою немає 5.1 кОм, спокуса поставити 4.7 кОм велика — ряд E12 його має, а 5.1 кОм це вже E24. Не робіть цього в продукті: рівно 5.1 кОм ±5 % — це те, на що калібровані пороги джерел; усе інше працює «у когось», а у прискіпливого зарядного — ні.

## Rp на боці джерела: три номінали, три обіцянки струму

Джерело кодує дозволений струм **вибором Rp**. Канонічних значень рівно три, і кожне жорстко прив'язане до струмового профілю:

```
Rp на джерелі   опорна напруга   профіль струму (при 5 В)
56 кОм          до 1.7–5.5 В     Default USB   — 0.5 А (USB2) / 0.9 А (USB3)
22 кОм          до 1.7–5.5 В     1.5 А
10 кОм          до 1.7–5.5 В     3.0 А         — тобто 15 Вт
```

Закономірність проста й важлива: **менший Rp → сильніша підтяжка → вища напруга на CC → більший дозволений струм**. 56 кОм підтягує найслабше (звідси й найнижча напруга, і найскромніший «дефолтний» рівень), 10 кОм — найсильніше (найвища напруга, повні 3 А). Запам'ятати легко через спадання: 56 → 22 → 10 кОм відповідає зростанню 0.9 → 1.5 → 3.0 А.

Багато контролерів реалізують Rp **не резистором, а джерелом сталого струму** — електрично це те саме (струм через 5.1 кОм sink дає ту саму напругу), просто точніше:

```
струм-джерело   еквівалент Rp   профіль струму
80 мкА          ≈ 56 кОм        Default USB (0.5 / 0.9 А)
180 мкА         ≈ 22 кОм        1.5 А
330 мкА         ≈ 10 кОм        3.0 А
```

Перевіримо, що це справді те саме. Джерело струму 330 мкА, протікаючи через Rd = 5.1 кОм споживача, за законом Ома дає:

```
V(CC) = I × Rd = 330 мкА × 5.1 кОм
      = 330e-6 × 5100
      = 1.683 В      ← глибоко в зоні «3.0 А»
```

А найскромніший рівень, 80 мкА:

```
V(CC) = 80 мкА × 5.1 кОм
      = 80e-6 × 5100
      = 0.408 В       ← зона «Default»
```

Ось чому пристрою достатньо **виміряти одну напругу**: 0.41 В означає «бери як від звичайного USB-порту», 1.68 В — «можна всі 3 ампери». Резистор на боці джерела безмовно оголосив контракт, а число на CC — це його підпис.

## Що бачить пристрій: пороги декодування

Зі свого боку sink не знає ні Rp, ні струму джерела — він бачить лише **напругу на активному піні CC** (тому, де реально стоїть дільник). Специфікація задає три пороги, за якими ця напруга декодується у профіль:

```
напруга на CC (вхід sink)      висновок
< 0.20 В                        нічого не під'єднано (CC «висить»)
0.20 … 0.66 В                   Default USB     → бери 0.5 / 0.9 А
0.66 … 1.23 В                   1.5 А дозволено
> 1.23 В                        3.0 А дозволено  (15 Вт)
```

![Шкала напруги на CC з трьома порогами декодування у пристрої](/book/electronics/power-electronics/type-c-cc/img/cc-decode.svg)
*Пристрій міряє одну напругу на активному CC і потрапляє в одну зону. Пороги 0.20 / 0.66 / 1.23 В розділяють «нема пристрою», Default, 1.5 А і 3.0 А — без жодної цифрової розмови.*

Важлива тонкість для тих, хто звіряється зі специфікацією: ці **0.20 / 0.66 / 1.23 В — пороги з боку sink** (як він ділить шкалу). З боку source ті самі рівні задано **вікнами допуску** на власну напругу — наприклад, для профілю 3.0 А джерело має тримати на Cb справного пристрою приблизно **0.85–2.45 В**, для 1.5 А — вужче вікно, для Default — найнижче. Числа не суперечать одне одному: вікна source лежать усередині зон, які sink відсікає своїми порогами. Для розробника пристрою орієнтир простий — **пороги sink (0.20 / 0.66 / 1.23 В)**: саме між ними впаде ваша виміряна напруга.

Усі рівні **нижчі за 3.3 В**, і це зручно: напругу CC можна завести прямо на вхід АЦП мікроконтролера з повним розмахом живлення 3.3 В без жодного дільника. Звідси й типова схема найпростішого розумного sink — Rd на CC плюс один аналоговий вхід.

## Орієнтація і VCONN: чому пінів CC два

У роз'ємі Type-C пінів CC **два** — CC1 і CC2, симетрично з обох боків. Кабель усередині штекера з'єднує наскрізь **лише один** із них (залежно від того, яким боком увімкнено), тож дільник Rp/Rd «оживає» рівно на одному піні, а другий лишається осторонь. За тим, **який** із двох побачив підтяжку, система й визначає **орієнтацію** штекера. Практичний наслідок прямий: Rd треба ставити **на обидва** піни CC незалежно — інакше пристрій працюватиме лише одним боком кабелю.

Другий, незадіяний пін не марнується: він стає **VCONN** — лінією живлення для електроніки самого кабелю. Щоб джерело зрозуміло, що до цього піна підключений саме кабель (а не другий пристрій), у штекер «розумного» кабелю вшито марковий резистор **Ra ≈ 0.8–1.2 кОм** від CC до землі. Джерело розрізняє три стани опору на кожному CC: **5.1 кОм** = пристрій (Rd, сюди подавати дані й живлення), **0.8–1.2 кОм** = кабель (Ra, сюди подати VCONN), **відкрито** = нічого. Саме контраст між 5.1 кОм і ~1 кОм робить це розрізнення можливим — ще одна причина не відступати від 5.1 кОм.

![Два піни CC: активний несе дільник Rp/Rd, другий стає VCONN з марковим Ra](/book/electronics/power-electronics/type-c-cc/img/cc-pins.svg)
*Активний пін CC1 несе дільник Rp/Rd і визначає профіль струму та орієнтацію; пасивний CC2 стає VCONN. Source відрізняє пристрій (Rd 5.1k) від кабелю (Ra 0.8–1.2k) за опором.*

## Типова пастка: немає або хибний Rd → немає живлення

Найчастіша помилка з USB-C — **забути Rd** або поставити його неправильно. Механізм невблаганний: поки на CC немає Rd, джерело тримає **VBUS вимкненим** (це вбудована безпека — голий роз'єм без пристрою знеструмлений). Пристрій без Rd для джерела просто **не існує**, і жодних 5 вольтів на VBUS не з'явиться. Звідси канонічне «увімкнув — нічого не світиться», за яким стоїть не несправність, а відсутній резистор. Три різновиди тієї самої пастки:

```
симптом                                        причина
зовсім немає 5 В на VBUS                        Rd відсутній на обох CC → пристрій не виявлено
працює лише одним боком штекера                Rd лише на одному CC → другу орієнтацію не видно
ставив 4.7 кОм «бо був під рукою»               поза допуском 5.1k ±5 % → прискіпливе джерело ігнорує
з'єднав CC1 і CC2 разом одним резистором        паралель ламає Ra-детект e-marker → з деякими кабелями глухо
```

Останній рядок — окрема історія, на якій спіткнулися навіть інженери Raspberry Pi 4: вони поставили **один** Rd на обидва закорочені піни CC. З простим кабелем це працює, але з e-marker-кабелем закорочені CC створюють паралель, у якій Ra кабелю й спільний Rd зливаються — і деякі зарядні відмовляються вмикати VBUS. Урок прямий: **два окремі Rd 5.1 кОм, по одному на CC1 і CC2**, ніколи не з'єднані разом.

## Рецепт найпростішого sink і код читання профілю

Зробити коректний 5-вольтовий USB-C-пристрій без жодного протоколу — це буквально два резистори:

```
1. Rd = 5.1 кОм від CC1 на землю.
2. Rd = 5.1 кОм від CC2 на землю.   (обов'язково обидва — роз'єм реверсивний)
3. VBUS → ваше живлення 5 В.
4. (за бажання) активний CC → вхід АЦП, щоб дізнатися дозволений струм.
5. Не брати більше, ніж прочитано.
```

Якщо профіль струму не потрібен (пристрій і так споживає менше 0.5 А), кроки 4–5 пропускають — досить самих резисторів, і це найнадійніший варіант, бо ламатися нема чому. Якщо ж треба знати стелю — ось читання порогів на мікроконтролері з 12-бітним АЦП і опорною 3.3 В:

:::tabs
```c
// Прочитати дозволений струм USB-C із напруги на активному CC.
// adc_read_mv(pin) повертає напругу на піні в мілівольтах.

typedef enum { CC_NONE, CC_DEFAULT, CC_1A5, CC_3A0 } cc_level_t;

static cc_level_t cc_decode(uint16_t mv) {
    if (mv < 200)   return CC_NONE;     // < 0.20 В — нічого не під'єднано
    if (mv < 660)   return CC_DEFAULT;  // 0.20–0.66 В — звичайний USB
    if (mv < 1230)  return CC_1A5;      // 0.66–1.23 В — 1.5 А
    return CC_3A0;                       // > 1.23 В — повні 3.0 А
}

// Роз'єм реверсивний: активний той CC, на якому є напруга.
cc_level_t usbc_read_profile(void) {
    uint16_t v1 = adc_read_mv(PIN_CC1);
    uint16_t v2 = adc_read_mv(PIN_CC2);
    uint16_t cc = (v1 > v2) ? v1 : v2;   // живий пін — з вищою напругою
    return cc_decode(cc);
}
```
```python
# Прочитати дозволений струм USB-C із напруги на активному CC.
# adc_read_mv(pin) повертає напругу на піні в мілівольтах.

from enum import Enum

class CcLevel(Enum):
    NONE    = 0   # нічого не під'єднано
    DEFAULT = 1   # звичайний USB (0.5 / 0.9 А)
    A1V5    = 2   # 1.5 А
    A3V0    = 3   # 3.0 А

def cc_decode(mv):
    if mv < 200:    return CcLevel.NONE     # < 0.20 В — нічого не під'єднано
    if mv < 660:    return CcLevel.DEFAULT  # 0.20–0.66 В — звичайний USB
    if mv < 1230:   return CcLevel.A1V5     # 0.66–1.23 В — 1.5 А
    return CcLevel.A3V0                      # > 1.23 В — повні 3.0 А

# Роз'єм реверсивний: активний той CC, на якому є напруга.
def usbc_read_profile():
    cc = max(adc_read_mv(PIN_CC1), adc_read_mv(PIN_CC2))  # живий пін — з вищою напругою
    return cc_decode(cc)
```
:::

Далі прошивка обмежує апетит під прочитаний рівень — наприклад, тримає вхідний струм перетворювача в межах профілю:

```c
cc_level_t lvl = usbc_read_profile();

uint16_t budget_ma;
switch (lvl) {
    case CC_3A0:     budget_ma = 3000; break;   // 15 Вт при 5 В
    case CC_1A5:     budget_ma = 1500; break;
    case CC_DEFAULT: budget_ma = 500;  break;   // консервативно: рівень USB2
    default:         budget_ma = 0;    break;    // нічого не під'єднано
}
set_input_current_limit(budget_ma);
```

Це і є вся «розумність» базового USB-C: два резистори оголошують роль і виявлення, одна виміряна напруга дає профіль струму, кілька рядків коду тримають пристрій у межах контракту. Коли ж 15 ват замало й треба підняти **напругу** (9, 12, 20 В), самих резисторів не вистачить — починається цифрова розмова [USB Power Delivery](book:electronics/usb-pd), і тоді на лінії CC замість статичного дільника з'являються пакети BMC-кодування. Але доти, доки межа — 5 В і до 3 А, надійніше за пару Rd 5.1 кОм немає нічого.
