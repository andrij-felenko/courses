# 📋 Електрична специфікація та часові діаграми USB BC 1.2

Специфікація USB Battery Charging Revision 1.2 строго регламентує електричні параметри, часові інтервали переходів автомата станів, граничні рівні напруг, тестові струми та вимірювальні опори для всіх типів зарядних портів і клієнтських пристроїв. Усі наведені параметри є обов'язковими для забезпечення повної апаратної взаємосумісності між обладнанням різних виробників.

### Фізичні величини та електричні пороги фізичного рівня BC 1.2

В основі специфікації лежить чіткий поділ напруг, струмів та імпедансів між станом пасивної лінії, станом активного зондування та станом стандартної передачі цифрових сигналів інтерфейсу USB 2.0.

| Параметр | Позначення | Мінімум | Типове | Максимум | Одиниця | Фізичне призначення та умови вимірювання |
| :--- | :--- | :---: | :---: | :---: | :---: | :--- |
| Напруга дійсної шини VBUS | `V_BVALID` | 4.40 | 5.00 | 5.25 | В | Поріг фіксації підключення активного джерела живлення. Нижче цього порогу робота автомата детекції блокується |
| Випробувальна напруга D+ | `V_DP_SRC` | 0.50 | 0.60 | 0.70 | В | Тестова напруга джерела зміщення лінії D+ під час Primary Detection при струмі навантаження від 0 до 250 мкА |
| Випробувальна напруга D− | `V_DM_SRC` | 0.50 | 0.60 | 0.70 | В | Тестова напруга джерела зміщення лінії D− під час Secondary Detection при струмі навантаження від 0 до 250 мкА |

| Струм джерела контакту даних | `I_DP_SRC` | 7.0 | 10.0 | 13.0 | мкА | Калібрований струм інжекції в лінію D+ під час виконання фази Data Contact Detect |

| Струм стягу на лінії D+ | `I_DP_SINK` | 25.0 | 50.0 | 175.0 | мкА | Струмовий стік на лінії D+ для розряджання ємності та відведення витоків під час Secondary Detection |
| Опір перемички порту DCP | `R_DCP_DAT` | — | — | 200 | Ом | Електричний опір постійного зв'язку між контактами D+ та D− всередині зарядного блока DCP |
| Опір стягувального резистора хоста | `R_PD` | 14.25 | 15.00 | 15.75 | кОм | Стандартний резистор підтяжки сигнальних ліній D+/D− до загального проводу GND у портах SDP та CDP |
| Опір витоку приймача даних | `R_DAT_LKG` | 300 | 500 | 1000 | кОм | Вхідний імпеданс високоомних входів компараторів та вимкнених буферів фізичного рівня USB PHY |

### Аналіз електричних порогів та запасу завадостійкості

Вибір величин випробувальних напруг `V_DP_SRC` = 0.60 В та порогу компаратора `V_DAT_REF` = 0.40 В базується на суворих вимогах завадостійкості та сумісності з логічними рівнями інтерфейсу USB 2.0.

По-перше, випробувальний рівень повинен повністю виключати випадкову хибну енумерацію шини. За базовим стандартом USB 2.0 диференціальний приймач фіксує стан активності шини (Single-Ended Zero або SE0), якщо напруга на обох лініях D+ та D− менша за 0.80 В. Подача тестової напруги 0.60 В (максимальне значення з урахуванням розкиду становить 0.70 В) гарантовано не сприймається хост-контролером як спроба передачі цифрових даних або запит на апаратне скидання шини (Bus Reset).

По-друге, рівень напруги повинен забезпечувати надійне спрацьовування компараторів навіть за наявності значного паразитного опору кабелю та перемички. Коли тестова напруга 0.60 В подається на лінію D+ у блоці DCP, напруга на лінії D− з урахуванням опору перемички `R_DCP_DAT` ≤ 200 Ом та струму стягу `I_DM_SINK` = 100 мкА розраховується за законом Ома:

```
V_DM = V_DP_SRC − (I_DM_SINK · R_DCP_DAT)
V_DM = 0.60 В − (100·10⁻⁶ А · 200 Ом)
V_DM = 0.60 В − 0.02 В = 0.58 В
```

Оскільки виміряна напруга 0.58 В значно перевищує максимальний поріг спрацьовування компаратора `V_DAT_REF` = 0.40 В (запас становить 180 мВ), вихід компаратора стабільно фіксує наявність перемички.

У випадку звичайного порту SDP лінія D− підтягнута до землі через хостовий резистор `R_PD` = 15 кОм. Напруга на лінії D− визначається лише струмом внутрішнього витоку компаратора та шунтується опором:

```
V_DM_SDP = I_LEAK · R_PD ≈ 1 мкА · 15 кОм = 0.015 В
```

Потенціал 0.015 В знаходиться далеко нижче мінімального порогу спрацьовування компаратора `V_DAT_REF` = 0.25 В (запас завадостійкості понад 235 мВ), що повністю виключає помилкове визначення порту SDP як зарядного пристрою.

### Часові інтервали та затримки автомата детекції (Таймінги)

Для гарантування коректної роботи аналогового автомата в умовах перехідних процесів підключення кабелю специфікація встановлює жорсткі часові обмеження на тривалість кожного кроку тестування:

| Параметр | Позначення | Мінімум | Типове | Максимум | Одиниця | Опис поведінки та призначення інтервалу |
| :--- | :--- | :---: | :---: | :---: | :---: | :--- |
| Таймаут контакту даних | `T_DCD_TIMEOUT` | 300 | 600 | 900 | мс | Максимальний інтервал очікування фізичного замикання контактів D+/D− до примусового переходу до Primary Detection |
| Час антибрязкоту контакту | `T_DCD_DBNC` | 10 | — | — | мс | Мінімальний час стабільного утримання логічного нуля на лінії D+ для підтвердження успішного завершення фази DCD |
| Час подачі V_DP_SRC | `T_VDPSRC_ON` | 40 | — | — | мс | Мінімальна тривалість утримання тестової напруги 0.6 В на лінії D+ для заряду паразитної ємності кабелю |
| Час стабілізації компаратора | `T_BC_EVAL` | — | — | 40 | мс | Максимальний час очікування відгуку виходу компаратора після подачі тестової напруги на сигнальну лінію |
| Час подачі V_DM_SRC | `T_VDMSRC_ON` | 40 | — | — | мс | Тривалість активного утримання напруги 0.6 В на лінії D− під час виконання вторинного тесту (Secondary Detection) |
| Час зняття напруг зміщення | `T_VDPSRC_DIS` | — | — | 20 | мс | Час гарантованого вимкнення тестових джерел напруги перед переходом до стандартної процедури енумерації USB |
| Фільтр завад на шині | `T_GLITCH_BC` | 10 | — | — | мкс | Апаратний фільтр короткочасних імпульсних завад на лініях D+/D− |

Інтервал `T_DCD_TIMEOUT` (до 900 мс) має фундаментальне практичне значення: якщо користувач підключає кабель повільно або використовує нестандартний адаптер (наприклад, застарілий блок з обірваними лініями даних або пропрієтарними підтяжками, де струм 10 мкА не здатний просадити лінію D+ нижче логічного порогу), пристрій не зависає у стані очікування назавжди. Після закінчення 900 мс автомат примусово переходить до фази Primary Detection, гарантуючи, що користувач отримає заряджання акумулятора за будь-яких умов.

Час `T_VDPSRC_ON` (мінімум 40 мс) розрахований на повний перезаряд сумарної ємності кабелю (яка за стандартом USB може досягати 100–150 пФ) через внутрішній опір джерела напруги. Якщо опитувати компаратор раніше, ніж завершиться заряд ємності, короткочасний перехідний процес може призвести до хибного висновку про відсутність зв'язку між лініями.

### Повний граф переходів автомата станів (Finite State Machine)

Процедура розпізнавання зарядного порту клієнтським пристроєм строго детермінована й описується послідовністю наступних дискретних станів керуючого автомата:

```
[Стан 0: UNATTACHED / IDLE]
   │
   ├─ Подія: VBUS зростає та перевищує поріг V_BVALID (4.4 В)
   ▼
[Стан 1: ATTACH / VBUS_DETECT]
   │ Вхідне споживання струму обмежено на рівні <= 2.5 мА
   │ Запуск таймера таймауту T_DCD_TIMEOUT (900 мс)
   │ Підключення джерела струму I_DP_SRC (10 мкА) до лінії D+
   │ Підключення внутрішнього стягувального резистора до лінії D−
   │
   ├─ Умова А: D+ < V_DAT_LGC протягом T_DCD_DBNC (10 мс) -> Контакт зафіксовано
   ├─ Умова Б: Таймер T_DCD_TIMEOUT (900 мс) вичерпано -> Примусовий перехід
   ▼
[Стан 2: PRIMARY_DETECTION]
   │ Вимкнення джерела I_DP_SRC
   │ Підключення джерела напруги V_DP_SRC (0.6 В) до лінії D+
   │ Підключення струмового стоку I_DM_SINK (50–100 мкА) до лінії D−
   │ Очікування інтервалу стабілізації T_VDPSRC_ON (40 мс)
   │ Опитування компаратора лінії D− відносно порогу V_DAT_REF (0.4 В)
   │
   ├── Гілка 1: V_DM < V_DAT_REF (0.4 В)
   │      │
   │      ▼
   │   [Стан 3A: SDP_DETECTED]
   │      Вимкнення V_DP_SRC та I_DM_SINK
   │      Очікування часу розряду T_VDPSRC_DIS (20 мс)
   │      Встановлення ліміту струму 100 мА
   │      Запуск енумерації USB 2.0 (перехід на 500 мА після дозволу хоста)
   │
   └── Гілка 2: V_DM >= V_DAT_REF (0.4 В) -> Зафіксовано зарядний порт (CDP або DCP)
          │
          ▼
       [Стан 3B: SECONDARY_DETECTION]
          Вимкнення джерела V_DP_SRC на D+
          Підключення джерела напруги V_DM_SRC (0.6 В) до лінії D−
          Підключення струмового стоку I_DP_SINK до лінії D+
          Очікування інтервалу стабілізації T_VDMSRC_ON (40 мс)
          Опитування компаратора лінії D+ відносно порогу V_DAT_REF (0.4 В)
          │
          ├── Гілка 2.1: V_DP < V_DAT_REF (0.4 В)
          │      │
          │      ▼
          │   [Стан 4A: CDP_DETECTED]
          │      Вимкнення джерел напруги та струмових стоків
          │      Очікування часу T_VDPSRC_DIS (20 мс)
          │      Встановлення ліміту зарядного струму 1.5 А
          │      Запуск передачі сигналів енумерації USB 2.0 (дані дозволені)
          │
          └── Гілка 2.2: V_DP >= V_DAT_REF (0.4 В)
                 │
                 ▼
              [Стан 4B: DCP_DETECTED]
                 Вимкнення джерел тестової напруги
                 Встановлення ліміту зарядного струму 1.5 А
                 Енумерація даних USB заблокована (автономний зарядний блок)
```

### Забезпечення живлення при глибоко розрядженому акумуляторі (Dead Battery Provisioning)

Специфікація BC 1.2 окремо регламентує сценарій запуску пристрою з повністю розрядженим («мертвим») акумулятором, напруга на якому впала нижче робочого порогу контролера живлення (менше 3.0 В). У такому стані процесор не здатний стартувати, а внутрішній генератор тактової частоти вимкнений.

Для розв'язання цієї проблеми аналоговий фронтенд детектора BC 1.2 проектується як повністю автономна апаратна схема, що живиться безпосередньо від сирої напруги VBUS через вбудований ультра-LDO стабілізатор. Після появи напруги VBUS схема виконує апаратну детекцію без участі процесора. Якщо виявляється порт DCP або CDP, силове коло вмикає лінійний каскад попереднього заряду малим безпечним струмом (Pre-Charge, 100–200 мА) безпосередньо в акумулятор. Коли напруга на банці піднімається вище порогу безпечного старту (3.4–3.6 В), основна система запускається й починає повноцінне заряджання максимальним дозволеним струмом 1.5 А.

Під час перебування у стані розрядженої батареї пристрій зобов'язаний виставляти на лінії D+ постійний слабкий витік струму (Weak Pull-up) для запобігання переходу порту CDP у стан призупинення шини (Suspend). Хост-контролер CDP бачить наявність підключеного клієнта і не відключає силову напругу VBUS протягом усього періоду відновлення акумулятора.

### Перехід до передавання даних USB 2.0 High-Speed після детекції CDP

Коли пристрій підтверджує тип порту як CDP (*Charging Downstream Port*), перед ним постає подвійне завдання: споживати максимальний зарядний струм 1.5 А та одночасно запустити повноцінний канал зв'язку USB 2.0 High-Speed (480 Мбіт/с).

Для переходу в робочий режим передавання даних клієнтський пристрій повинен виконати строгу послідовність дій з відключення аналогового тестового обладнання:

1. **Вимкнення тестових генераторів напруги**: джерела V_DP_SRC та V_DM_SRC негайно відключаються від ліній.
2. **Вимкнення струмових стоків**: стоки I_DM_SINK та I_DP_SINK розмикаються, щоб не спотворювати форму диференціальних сигналів.
3. **Очікування інтервалу розряду T_VDPSRC_DIS (20 мс)**: напруга на сигнальних лініях повинна повністю впасти нижче рівня 0.15 В за рахунок розряду через хостові резистори R_PD (15 кОм).
4. **Підключення резистора підтяжки Full-Speed R_PU (1.5 кОм)**: клієнт підтягує лінію D+ до напруги 3.3 В, сигналізуючи хосту про підключення повношвидкісного пристрою.
5. **Виконання рукостискання High-Speed (Chirp Handshake)**: хост надсилає сигнал скидання шини (Bus Reset, стан SE0 тривалістю понад 10 мс). У відповідь клієнтський трансівер PHY генерує серію струмових імпульсів Chirp-K (подача струму 17.78 мА в лінію D−), на що хост відповідає почерговими імпульсами Chirp-K та Chirp-J. Після завершення рукостискання обидві сторони підключають внутрішні термінуючі резистори 45 Ом на землю (формуючи хвильовий диференціальний опір 90 Ом) і переходять у режим передачі даних з амплітудою сигналу 400 мВ.

Протягом усього сеансу передачі даних на швидкості 480 Мбіт/с силовий контролер пристрою продовжує безперервно споживати до 1.5 А від шини VBUS.

### Специфікація динамічної стабілізації напруги VBUS під навантаженням

Під час споживання струму 1.5 А на омічному опорі кабелю USB (який для бюджетних дротів довжиною 1.0–1.5 м може досягати 0.3–0.6 Ом у сумі для жил VBUS та GND) виникає значне падіння напруги. Якщо на виході адаптера напруга становить рівно 5.00 В, то при струмі 1.5 А на контакт роз'єму смартфона надійде:

```
V_DEVICE = V_SRC − (I_CHG · R_CABLE)
V_DEVICE = 5.00 В − (1.5 А · 0.5 Ом) = 4.25 В
```

Оскільки напруга 4.25 В знаходиться нижче стандартного порогу `V_BVALID` (4.40 В), некомпенсований зарядний контролер міг би сприйняти це як відключення адаптера та розірвати коло зарядки. Щоб запобігти виникненню таких циклічних автоколивань (циклів увімкнення-скидання), стандарт BC 1.2 дозволяє джерелам живлення DCP знижувати напругу на клемах аж до 2.0 В у режимі стабілізації струму (Constant Current Collapse Mode), а клієнтські контролери зарядки зобов'язані підтримувати алгоритм Dynamic Power Management (DPM). Алгоритм DPM автоматично знижує споживання струму рівно настільки, щоб утримати напругу на роз'ємі вище критичного порогу 4.40–4.50 В, витискаючи максимальну доступну потужність із тонкого кабелю.

### Специфікація адаптерів живлення аксесуарів (Accessory Charger Adapter, ACA)

Для портативних пристроїв стандарту USB On-The-Go (OTG), оснащених 5-контактними роз'ємами типу Micro-AB, специфікація BC 1.2 визначає розпізнавання комбінованих док-станцій за значенням опору між контактом `ID` (5-й контакт конектора) та загальним проводом `GND`. Це дозволяє смартфону або планшету одночасно заряджати свій акумулятор струмом до 1.5 А і виконувати роль хост-контролера для зовнішньої периферії (наприклад, флеш-накопичувача або клавіатури).

Вимірювання опору контакту ID здійснюється за допомогою внутрішнього аналогово-цифрового перетворювача (АЦП) або багатопорогової схеми компараторів у складі контролера живлення. На контакт ID подається вимірювальний струм або напруга через внутрішній прецизійний резистор підтяжки R_ID_PU (типово 100 кОм до внутрішньої шини 3.3 В), і падіння напруги інтерпретується згідно з таблицею:

| Позначення опору | Номінал опору (±1%) | Допустимий діапазон АЦП | Стан контакту ID | Роль пристрою (OTG Device) | Стан шини VBUS | Режим роботи аксесуара |
| :--- | :---: | :---: | :--- | :--- | :--- | :--- |
| `RID_GND` | 0 Ом (коротке) | < 10 Ом | Закорочено на GND | Хост (USB A-device) | Пристрій сам живить лінію VBUS (струм 0 мА від порту) | Стандартний пасивний кабель USB OTG (підключення спалах-диска, клавіатури) |
| `RID_C` | 36.5 кОм | 34.0–39.0 кОм | Аналоговий поділ | Периферія (B-device) | Пристрій споживає струм до 1.5 А від зовнішнього джерела | Док-станція аксесуара: пристрій заряджається як клієнт комп'ютера |
| `RID_B` | 68.0 кОм | 64.0–72.0 кОм | Аналоговий поділ | Не визначено | Пристрій споживає струм до 1.5 А | Автономний зарядний пристрій аксесуара без підключеного хоста |
| `RID_A` | 124.0 кОм | 119.0–132.0 кОм | Аналоговий поділ | Хост (A-device) | Пристрій споживає струм до 1.5 А від зовнішнього джерела | Активна док-станція: смартфон працює як USB-хост для миші/диска і одночасно заряджається |
| `RID_FLOAT` | Нескінченність (обрив) | > 220 кОм | Розімкнено | Периферія (B-device) | Струм залежить від детекції SDP/CDP/DCP | Звичайний стандартний кабель USB Micro-B без підтримки протоколу ACA |

У режимі `RID_A` реалізується найбільш технологічно складний сценарій: смартфон виступає в ролі хост-контролера шини (генерує пакети SOF, керує передачею даних на периферійний пристрій), проте сам не витрачає енергію акумулятора на живлення лінії VBUS. Зовнішня док-станція подає напругу 5 В на шину VBUS, від якої смартфон заряджає власну батарею струмом до 1.5 А і одночасно живить підключену периферію.

### Регістрова модель та програмний інтерфейс детектора

У типових інтегрованих мікросхемах контролерів живлення (PMIC) та трансіверів фізичного рівня USB стан процесу детекції BC 1.2 транслюється у внутрішні цифрові регістри, доступні керуючому мікроконтролеру через послідовні шини I2C або SPI:

- **Регістр статусу детекції (`BC_STATUS`, адреса 0x01)**:
  - Біт `VBUS_VALID` (ReadOnly, біт 7): апаратний прапорець фіксації напруги на силовій шині VBUS понад 4.40 В. Використовується для виходу мікроконтролера з режиму глибокого сну (Deep Sleep Wakeup).
  - Біти `PORT_TYPE[2:0]` (ReadOnly, біти [6:4]): двійковий код розпізнаного порту. Значення `000` вказує, що порт не визначено або процес детекції ще триває; `001` — стандартний порт комп'ютера SDP (ліміт 100/500 мА); `010` — порт комп'ютера з посиленим живленням CDP (ліміт 1.5 А та дозвіл даних); `011` — виділений зарядний блок DCP (ліміт 1.5 А без даних); `100` — пропрієтарний зарядний пристрій Apple (ліміт від 1.0 А до 2.4 А); `101` — адаптер Samsung (ліміт 2.0 А); `110` — нестандартний порт або помилка таймауту DCD.
  - Біт `DCD_TIMEOUT_FLAG` (ReadOnly, біт 3): сигналізує про завершення фази виявлення контакту за таймером 900 мс замість штатного апаратного сигналу, що свідчить про використання нестандартного кабелю або адаптера.
  - Біт `DETECTION_DONE` (ReadOnly, біт 0): виставляється в логічну одиницю після стабілізації результатів вторинного тесту, повідомляючи програмний драйвер про готовність даних.

- **Регістр конфігурації детектора (`BC_CTRL`, адреса 0x02)**:
  - Біт `AUTO_DETECT_EN` (Read/Write, біт 7): дозвіл автоматичного запуску кінцевого автомата при появі напруги VBUS. Якщо біт скинуто, запуск виконується виключно за командою центрального процесора.
  - Біт `FORCE_MANUAL_START` (Read/Write, біт 6): примусовий перезапуск повної процедури тестування ліній D+/D− за командою програмного стека.
  - Біт `DCD_ENABLE` (Read/Write, біт 5): увімкнення фази виявлення контакту даних перед Primary Detection. Рекомендується тримати увімкненим для захисту від брязкоту роз'єму.
  - Біти `INPUT_CURRENT_LIMIT[3:0]` (Read/Write, біти [3:0]): прямий програмний вибір максимального порогу вхідного струму перетворювача живлення (100 мА, 500 мА, 900 мА, 1500 мА, 2000 мА, 2400 мА). Драйвер операційної системи може перевизначити апаратно виявлений ліміт, якщо цього вимагає тепловий профіль пристрою.

- **Регістр переривань та масок (`BC_INT` / `BC_INT_MASK`, адреси 0x03 / 0x04)**:
  - Формує активний низький рівень на виводі переривання `nINT` мікросхеми у разі настання наступних подій: зміна типу зарядного порту, підключення або відключення кабелю живлення VBUS, завершення розпізнавання резистора ACA ID, а також спрацьовування захисту від перенапруги на шині VBUS (Over-Voltage Protection, OVP) чи перегріву кристала.

### Програмний драйвер обробки переривань детектора порту

Для взаємодії з апаратним детектором мікроконтролер реалізує драйвер з асинхронною обробкою переривань. Нижче наведено приклад коду, що зчитує регістри детектора та налаштовує вхідний лімітер струму зарядного контролера:

```c
#include <stdint.h>
#include <stdbool.h>

#define REG_BC_STATUS 0x01
#define REG_BC_CTRL   0x02

typedef enum {
    PORT_UNKNOWN = 0,
    PORT_SDP     = 1,
    PORT_CDP     = 2,
    PORT_DCP     = 3,
    PORT_APPLE   = 4,
    PORT_SAMSUNG = 5
} usb_port_type_t;

extern uint8_t i2c_read_reg(uint8_t reg);
extern void i2c_write_reg(uint8_t reg, uint8_t val);
extern void charger_set_input_current_limit(uint16_t current_ma);
extern void usb_stack_enable_data(bool enable);

void bc12_interrupt_handler(void)
{
    uint8_t status = i2c_read_reg(REG_BC_STATUS);
    bool vbus_valid = (status & (1 << 7)) != 0;
    bool done = (status & (1 << 0)) != 0;

    if (!vbus_valid) {
        charger_set_input_current_limit(0);
        usb_stack_enable_data(false);
        return;
    }

    if (done) {
        uint8_t port_code = (status >> 4) & 0x07;
        switch (port_code) {
            case PORT_SDP:
                charger_set_input_current_limit(500);
                usb_stack_enable_data(true);
                break;
            case PORT_CDP:
                charger_set_input_current_limit(1500);
                usb_stack_enable_data(true);
                break;
            case PORT_DCP:
                charger_set_input_current_limit(1500);
                usb_stack_enable_data(false);
                break;
            case PORT_APPLE:
                charger_set_input_current_limit(2400);
                usb_stack_enable_data(false);
                break;
            case PORT_SAMSUNG:
                charger_set_input_current_limit(2000);
                usb_stack_enable_data(false);
                break;
            default:
                charger_set_input_current_limit(100);
                usb_stack_enable_data(false);
                break;
        }
    }
}
```

```cpp
#include <cstdint>
#include <span>
#include <concepts>

enum class PortType : uint8_t {
    Unknown = 0,
    SDP     = 1,
    CDP     = 2,
    DCP     = 3,
    Apple   = 4,
    Samsung = 5
};

struct ChargerProfile {
    uint16_t maxCurrentMa;
    bool allowData;
};

class UsbBatteryChargingDetector {
public:
    static constexpr uint8_t RegBcStatus = 0x01;
    static constexpr uint8_t RegBcCtrl   = 0x02;

    virtual ~UsbBatteryChargingDetector() = default;

    virtual uint8_t readRegister(uint8_t reg) = 0;
    virtual void writeRegister(uint8_t reg, uint8_t val) = 0;
    virtual void applyCurrentLimit(uint16_t currentMa) = 0;
    virtual void setUsbDataEnabled(bool enabled) = 0;

    void handleInterrupt() {
        const uint8_t status = readRegister(RegBcStatus);
        const bool vbusValid = (status & (1 << 7)) != 0;
        const bool detectionDone = (status & (1 << 0)) != 0;

        if (!vbusValid) {
            applyCurrentLimit(0);
            setUsbDataEnabled(false);
            return;
        }

        if (detectionDone) {
            const auto port = static_cast<PortType>((status >> 4) & 0x07);
            const auto profile = resolveProfile(port);
            applyCurrentLimit(profile.maxCurrentMa);
            setUsbDataEnabled(profile.allowData);
        }
    }

private:
    [[nodiscard]] static constexpr ChargerProfile resolveProfile(PortType port) noexcept {
        switch (port) {
            case PortType::SDP:     return { 500,  true  };
            case PortType::CDP:     return { 1500, true  };
            case PortType::DCP:     return { 1500, false };
            case PortType::Apple:   return { 2400, false };
            case PortType::Samsung: return { 2000, false };
            default:                return { 100,  false };
        }
    }
};
```
