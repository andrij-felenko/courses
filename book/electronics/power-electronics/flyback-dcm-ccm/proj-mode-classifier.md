# ⚙️ Класифікатор режиму flyback у прошивці: DCM, BCM чи CCM за виміряним струмом

Цифровий контролер flyback — чи то повністю цифрова петля, чи просто мікроконтролер, що наглядає за аналоговим ШІМ, — часто мусить **сам знати**, у якому режимі зараз працює перетворювач. Від режиму залежить майже все керування: які коефіцієнти петлі ввімкнути (жваві для DCM, повільні для CCM з його нулем правої півплощини), чи вже потрібна компенсація нахилом, чи час переходити на пропуск імпульсів на легкому ході. Джерело правди тут одне-єдине: порівняти виміряний струм навантаження з **межовим** — тим струмом, на якому поличка залишкового струму в осерді щойно зникає. Вищий за межу струм — flyback у CCM (поличка ще є); нижчий — у DCM (осердя щоцикл порожніє до дна); у вузькій смузі коло самої межі — BCM. Ця вставка показує, як звести межу до кількох цілочислових множень і зробити стійкий класифікатор, який не смикається на кордоні.

## Звідки береться поріг

Межовий струм дає flyback-специфічна форма умови межі — та сама рівновага, коли трикутник струму намагнічування щойно торкається нуля в мить наступного вмикання ключа. Її виведення з балансу вольт-секунд і геометрії трикутника (разом із поправкою на витки) розібрано в [🧮 математиці режимів flyback](topic:electronics/flyback-dcm-ccm/math-flyback-modes.md); тут беремо готовий результат:

```
              n · Vвх · D · (1−D)
Iвих_межа = ─────────────────────
                  2 · Lм · f
```

де `n = Np/Ns` — коефіцієнт витків (первинних на одну вторинну), `Vвх` — напруга на первинній у фазі ВКЛ, `D` — коефіцієнт заповнення, `Lм` — намагнічувальна індуктивність первинної, `f` — частота. Множник `n` стоїть тому, що струм у навантаження тече вторинною обмоткою, а вона при знижувальному витку несе **більший** струм, ніж первинна (рівні ампер-витки: Iсек = n·Iпри). Читати формулу так: поки реальний вихідний струм **вищий** за `Iвих_межа`, у осерді лишається поличка — це CCM; тільки-но струм падає нижче, поличка зникає — це DCM.

## Ідея й код

Алгоритм прямий: на кожному циклі регулювання беремо поточні `Vвх`, `D` і виміряний `Iвих`, рахуємо `Iвих_межа` за формулою вище й порівнюємо. Уся тонкість — у **числах**. На дрібному Cortex-M0 без апаратної коми множення й ділення роблять у **фіксованій комі** Q16.16 (16 бітів на цілу частину, 16 на дробову), а щоб класифікатор не «тремтів» туди-сюди рівно на межі, порівняння роблять не з одним порогом, а з **гістерезисом** — вузькою мертвою смугою, яку й оголошуємо режимом BCM.

:::tabs
```c
// Оцінка режиму flyback за виміряним струмом навантаження.
// Усе у фіксованій комі Q16.16; величини заздалегідь відмасштабовані.
// Lm_uH — намагнічувальна індукт. первинної, мкГн; n_q16 — Np/Ns у Q16.16.

#include <stdint.h>

typedef enum { MODE_DCM, MODE_BCM, MODE_CCM } fb_mode_t;

// Межовий вихідний струм (мА) за поточної робочої точки.
// Iбм[А] = n·Vin·D·(1−D) / (2·Lm·f).  Розкриваємо масштаби:
//   n = n_q16/2^16 ;  D·(1−D) = dd/2^16 ;  Lm[Гн]=Lm_uH·1e-6 ;  f[Гц]=f_khz·1e3.
// Отже Iбм[мА] = n_q16·Vin·dd·1e6 / ( 2^32 · 2 · Lm_uH · f_khz ).
static int32_t boundary_iout_ma(int32_t vin_v, int32_t d_q16,
                                int32_t n_q16, int32_t lm_uH, int32_t f_khz)
{
    int32_t one = (int32_t)(1 << 16);
    int64_t dd  = ((int64_t)d_q16 * (one - d_q16)) >> 16;   // D·(1−D) у Q16.16

    // Чисельник у 64 бітах. Стеж за розміром: n_q16·Vin·dd·1e6 для типових
    // (n≈4·2^16, Vin≈100, dd≈0.25·2^16, 1e6) ~ 4·10¹⁷ — влазить у int64 (< 9.2·10¹⁸),
    // але за великих Vin чи n перевіряй запас або зменшуй множник 1e6 → крок мА.
    int64_t num = (int64_t)n_q16 * vin_v * dd * 1000000LL;

    int64_t den = ((int64_t)1 << 32) * 2 * lm_uH * f_khz;
    if (den == 0) return 0;
    return (int32_t)(num / den);
}

// Класифікація з гістерезисом ±9%, щоб не «тремтіло» на самій межі.
static fb_mode_t classify_mode(int32_t iout_ma, int32_t vin_v, int32_t d_q16,
                               int32_t n_q16, int32_t lm_uH, int32_t f_khz)
{
    int32_t ibnd = boundary_iout_ma(vin_v, d_q16, n_q16, lm_uH, f_khz);
    int32_t hi = ibnd + (ibnd >> 4) + (ibnd >> 5);   // +~9%
    int32_t lo = ibnd - (ibnd >> 4) - (ibnd >> 5);   // −~9%
    if (iout_ma > hi) return MODE_CCM;               // струм вищий за межу → поличка є
    if (iout_ma < lo) return MODE_DCM;               // нижчий → осердя порожніє
    return MODE_BCM;                                 // у вузькій смузі — на межі
}
```
```python
# Оцінка режиму flyback за виміряним струмом навантаження.
# Усе у фіксованій комі Q16.16; величини заздалегідь відмасштабовані.
# lm_uH — намагнічувальна індукт. первинної, мкГн; n_q16 — Np/Ns у Q16.16.
# Python має довгі цілі, тож переповнення тут немає — але той самий цілочисловий
# тракт лишаємо навмисно, щоб код був дзеркалом прошивки (крок за кроком той самий).

from enum import IntEnum


class FbMode(IntEnum):
    DCM = 0
    BCM = 1
    CCM = 2


def boundary_iout_ma(vin_v, d_q16, n_q16, lm_uH, f_khz):
    """Межовий вихідний струм (мА) за поточної робочої точки.

    Iбм[А] = n·Vin·D·(1−D) / (2·Lm·f).  Розкриваємо масштаби:
      n = n_q16/2^16 ;  D·(1−D) = dd/2^16 ;  Lm[Гн]=lm_uH·1e-6 ;  f[Гц]=f_khz·1e3.
    Отже Iбм[мА] = n_q16·Vin·dd·1e6 / ( 2^32 · 2 · lm_uH · f_khz ).
    """
    dd = (d_q16 * ((1 << 16) - d_q16)) >> 16          # D·(1−D) у Q16.16

    num = n_q16 * vin_v * dd * 1_000_000
    den = (1 << 32) * 2 * lm_uH * f_khz
    if den == 0:
        return 0
    return num // den                                 # цілочислове ділення, як у C


def classify_mode(iout_ma, vin_v, d_q16, n_q16, lm_uH, f_khz):
    """Класифікація з гістерезисом ±9%, щоб не «тремтіло» на самій межі."""
    ibnd = boundary_iout_ma(vin_v, d_q16, n_q16, lm_uH, f_khz)
    hi = ibnd + (ibnd >> 4) + (ibnd >> 5)             # +~9%
    lo = ibnd - (ibnd >> 4) - (ibnd >> 5)             # −~9%
    if iout_ma > hi:
        return FbMode.CCM                             # струм вищий за межу → поличка є
    if iout_ma < lo:
        return FbMode.DCM                             # нижчий → осердя порожніє
    return FbMode.BCM                                 # у вузькій смузі — на межі
```

## Перевіримо на числі

Візьмімо робочу точку 65-ватного адаптера ноутбука, який навмисне тримають у CCM (вихід 20 В, найгірший — найглибший — D на просілому вході): `Vвх = 100 В`, `D = 0.45`, `n = Np/Ns ≈ 4.09`, `Lм = 400 мкГ`, `f = 65 кГц`. Для цих чисел `boundary_iout_ma` повертає **1946 мА** — рівно те, що дає аналітична формула. Тож класифікатор чесно кличе CCM на повних 3.25 А, DCM на 1 А (ноутбук дозарядився) і BCM у вузькій смузі коло 1.95 А — саме там, де той самий фізичний трансформатор без жодної зміни сповзає з CCM у DCM.

## Дві пастки, обидві з арифметики

Перша — **переповнення**. Чисельник `n_q16·Vin·dd·1e6` для наших значень сягає ~4·10¹⁷ — це ще з добрим запасом під стелею `int64_t` (9.2·10¹⁸, тобто пройдено ~5% шляху), але запас з'їдається швидко: підняти вхід до 400-вольтової шини PFC — уже ×4, збільшити `n` — ще стільки ж, і множник `1e6` штовхає туди ж. Тому за вищого входу чи більшого `n` або звужуй множник `1e6` (рахуй десятками мА замість одиниць), або переставляй порядок множень так, щоб ділити раніше. Про те, як не проґавити переповнення й де ставити зсуви у фіксованій комі, — у [практиці фіксованої коми](topic:programming/fixed-point).

Друга — **гістерезис обов'язковий**. Без нього, коли реальний струм тремтить рівно біля межі, класифікатор смикатиметься CCM↔DCM щотакту, і петля перемикатиме свої коефіцієнти туди-сюди — вузол засвистить не гірше, ніж від некомпенсованої субгармоніки. Смуга BCM у ±9% це прибирає: у ній ми просто лишаємо поточні (компромісні) параметри й не перемикаємось, доки струм не вийде за смугу впевнено.

> 🔧 **Навіщо це.** Класифікатор режиму — це те, що перетворює один flyback на два прилади в одному. Цифрова петля бачить, коли навантаження впало й вузол сповз у DCM, і на льоту перемикає компенсатор із повільного (обов'язкового для CCM з його RHP-нулем) на жвавий (можливий у DCM, де нуля немає). Без такої оцінки доводиться жити на одному компромісному наборі коефіцієнтів — млявому там, де можна було б бути швидким, і на межі стійкості там, де треба бути обережним. Поточний режим і межовий струм — два числа, на яких стоїть уся адаптивна петля сучасного цифрового flyback.
