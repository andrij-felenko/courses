Протокол взаємодії з електронним маркером кабелю в специфікаціях USB Type-C та USB Power Delivery базується на механізмі структурованих повідомлень, визначених виробником (англ. *Structured Vendor Defined Messages*, Structured VDM). Усі пакети опитування та відповіді транслюються на фізичному рівні BMC зі швидкістю 300 кбіт/с по активній лінії CC з використанням спеціальної адресації `SOP'` (для зв'язку з ближнім штекером) або `SOP''` (для зв'язку з протилежним штекером кабелю).

Специфікація Structured VDM є чітко типізованим протокольним інтерфейсом типу «запит — відповідь». Вона перетворює лінію CC на шину цифрового менеджменту параметрів кабельної збірки, дозволяючи зчитувати електричні паспорти, конфігурувати альтернативні режими (*Alternate Modes*) та відстежувати стан вбудованої електроніки в активних кабелях.

## Структура кадру та заголовок Structured VDM Header

Кожен кадр Structured VDM містить обов'язковий 32-бітовий заголовок (*VDM Header*), який розташовується першим словом даних безпосередньо після 16-бітового стандартного заголовка пакета USB PD (*Message Header*). Заголовок VDM визначає тип операції, адресата команди та версію протоколу.

```
 31                          16 15 14 13 12 11 10 9  8  7  6  5  4       0
┌──────────────────────────────┬──┬─────┬─────┬───────┬─────┬──┬──────────┐
│         Standard SVID        │VT│Ver  │ Rsv │ObjPos │CmdT │R │ Command  │
│           (0xFF00)           │1 │     │     │       │     │  │          │
└──────────────────────────────┴──┴─────┴─────┴───────┴─────┴──┴──────────┘
```

Розподіл бітових полів заголовка Structured VDM регламентовано стандартом:

- **B31..B16 (`Standard SVID`):** 16-бітовий ідентифікатор постачальника або стандарту. Для всіх базових команд опитування ідентичності та можливостей кабелю використовується виділений консорціумом ідентифікатор `0xFF00` (*Universal Serial Bus Implementers Forum Standard SVID*). Якщо кабель підтримує спеціалізовані альтернативні режими, на наступних етапах переговорів можуть застосовуватися інші SVID, наприклад `0xFF01` (DisplayPort Alternate Mode) або `0x8087` (Intel Thunderbolt).
- **B15 (`VDM Type`):** Визначає структуру повідомлення. Для структурованих повідомлень встановлюється значення `1b` (*Structured VDM*). Значення `0b` зарезервовано для неструктурованих повідомлень довільного формату (*Unstructured VDM*), які в процедурах стандартизованої автентифікації кабелів не використовуються.
- **B14..B13 (`Structured VDM Version`):** Версія протоколу Structured VDM. Значення `00b` відповідає версії 1.0 (застосовувалася в ранніх ревізіях USB PD 2.0). Сучасні пристрої USB PD 3.0 та USB PD 3.1 обов'язково встановлюють значення `01b` (версія 2.0).
- **B12..B11 (`Reserved`):** Зарезервовані біти стандарту; при передачі завжди заповнюються нулями `00b`.
- **B10..B8 (`Object Position`):** Номер об'єкта альтернативного режиму (діапазон від `001b` до `110b`, тобто від 1 до 6). Використовується виключно в командах входу/виходу з режиму (`Enter Mode` та `Exit Mode`) для вказівки, який саме режим активується. У базових запитах ідентифікації `Discover Identity` це поле завжди містить `000b`.
- **B7..B6 (`Command Type`):** Тип операції та роль відправника в транзакції:
  - `00b` (`REQ` / *Initiator Request*) — ініціативний запит від хоста або джерела живлення;
  - `01b` (`ACK` / *Responder Acknowledge*) — успішна відповідь із корисними даними від чипа маркера;
  - `10b` (`NAK` / *Responder Negative Acknowledge*) — відмова чипа обробити команду (наприклад, непідтримувана команда або помилка стану);
  - `11b` (`BUSY` / *Responder Busy*) — повідомлення про тимчасову зайнятість маркера (ініціатор зобов'язаний зачекати перед повтором).
- **B5 (`Reserved`):** Зарезервований біт; передається як `0b`.
- **B4..B0 (`Command Code`):** 5-бітовий код виконуваної операції. Стандарт визначає п'ять обов'язкових команд та одну допоміжну:
  - `00001b` (`0x01`) — **Discover Identity** (запит паспорта кабельної збірки та дескрипторів VDO);
  - `00010b` (`0x02`) — **Discover SVIDs** (запит переліку ідентифікаторів SVID, підтримуваних кабелем);
  - `00011b` (`0x03`) — **Discover Modes** (запит списку альтернативних режимів для обраного SVID);
  - `00100b` (`0x04`) — **Enter Mode** (команда активації конкретного альтернативного режиму в кабелі);
  - `00101b` (`0x05`) — **Exit Mode** (команда деактивації альтернативного режиму та повернення до стандартного стану);
  - `00110b` (`0x06`) — **Attention** (асинхронне сповіщення, яке активний кабель може надіслати хосту у разі виникнення критичної події).

## Процедура Discover Identity та послідовність VDO

Під час ініціалізації з'єднання хост або джерело живлення надсилає пакет `Discover Identity` з адресацією `SOP'`. У відповідь мікросхема E-Marker формує кадр `Discover Identity ACK`, що містить від чотирьох до шести 32-бітових слів даних — об'єктів даних виробника (*Vendor Data Objects*, VDO).

Послідовність розташування слів у кадру строго фіксована специфікацією:
1. **Слово 0:** Заголовок `Structured VDM Header` (SVID: `0xFF00`, `Command = 0x01`, `Command Type = 01b` / ACK).
2. **Слово 1:** `ID Header VDO` — базовий дескриптор пристрою, що оголошує тип продукту (пасивний чи активний кабель) та ідентифікатор виробника VID.
3. **Слово 2:** `Cert Stat VDO` — 32-бітовий сертифікаційний ідентифікатор XID, присвоєний тестовою лабораторією USB-IF.
4. **Слово 3:** `Product VDO` — номер продукту PID та версія апаратної ревізії bcdDevice.
5. **Слово 4:** `Passive Cable VDO 1` (для пасивних кабелів) або `Active Cable VDO 1` (для активних кабелів) — силові параметри струму, напруги та швидкість ліній даних.
6. **Слово 5 (опціональне в USB PD 3.1):** `Passive Cable VDO 2` або `Active Cable VDO 2` — розширені параметри режиму EPR 240 Вт, максимальна робоча температура та наявність термодатчика.

## 1. Дескриптор ID Header VDO

Дескриптор `ID Header VDO` є першим обов'язковим об'єктом у відповіді на команду ідентифікації. Він класифікує пристрій у топології USB Type-C.

```
 31 30 29   27 26 25   23 22 21 20   16 15                      0
┌──┬──┬───────┬──┬───────┬──┬──┬───────┬──────────────────────────┐
│HC│DC│ProdTyp│MO│DFPTyp │R │CT│  Rsv  │      USB Vendor ID       │
│0 │0 │ 011b  │0 │ 000b  │0 │10│ 00000 │          (VID)           │
└──┴──┴───────┴──┴───────┴──┴──┴───────┴──────────────────────────┘
```

### Деталізація полів ID Header VDO:

- **B31 (`Host Capable`):** Ознака спроможності пристрою виконувати роль хоста шини USB (Data Host). Для мікросхеми кабелю цей біт завжди встановлюється в `0b`.
- **B30 (`Device Capable`):** Ознака спроможності пристрою бути кінцевим периферійним пристроєм USB (Data Device). Для кабельного маркера завжди встановлюється в `0b`.
- **B29..B27 (`Product Type UFP / Cable Plug`):** Визначає категорію пристрою на стороні UFP або штекера кабелю:
  - `011b` (`3`) — **Passive Cable** (пасивний кабель без підсилювачів сигналу, що містить маркер);
  - `100b` (`4`) — **Active Cable** (активний кабель з вбудованими ретаймерами або оптичними трансиверами);
  - `000b` (`0`) — Не визначено / Звичайний порт.
- **B26 (`Modal Operation Supported`):** Прапорець підтримки альтернативних режимів роботи:
  - `1b` — кабель підтримує перемикання диференційних ліній в альтернативні режими (DisplayPort Alt Mode, Thunderbolt);
  - `0b` — кабель функціонує виключно за стандартними протоколами USB.
- **B25..B23 (`Product Type DFP`):** Тип продукту для сторони DFP. Для кабельного маркера завжди заповнюється нулями `000b`.
- **B22 (`Reserved`):** Зарезервований біт; передається як `0b`.
- **B21..B20 (`Connector Type`):** Тип встановленого роз'єму. Значення `10b` строго вказує на наявність роз'єму стандарту USB Type-C.
- **B19..B16 (`Reserved`):** Зарезервовано стандартом; передається як `00000b`.
- **B15..B0 (`USB Vendor ID`):** 16-бітовий унікальний номер постачальника (VID), призначений консорціумом USB-IF компанії-виробнику кабелю.

## 2. Дескриптор Cert Stat VDO

Дескриптор `Cert Stat VDO` містить єдине 32-бітове поле `Test ID` (також відоме як `XID` або `TID`).

```
 31                                                             0
┌────────────────────────────────────────────────────────────────┐
│                   USB-IF Test ID (XID / TID)                   │
│                          (32 біти)                             │
└────────────────────────────────────────────────────────────────┘
```

- **B31..B0 (`Test ID`):** Унікальний числовий ідентифікатор випробувань, який надається тестовою лабораторією USB-IF після успішного проходження кабельною збіркою повного комплексу сертифікаційних тестів (*USB-IF Compliance Testing*). Присутність ненульового значення `XID` є обов'язковою вимогою для маркування продукту офіційними логотипами USB-IF. Якщо мікросхема E-Marker містить `0x00000000`, кабель вважається несертифікованим, і корпоративні політики безпеки можуть блокувати роботу з ним на підвищеній потужності.

---

## 3. Дескриптор Product VDO

Дескриптор `Product VDO` зберігає інформацію про конкретну модель виробу та ревізію апаратного забезпечення.

```
 31                            16 15                            0
┌────────────────────────────────┬────────────────────────────────┐
│      USB Product ID (PID)      │       bcdDevice Revision       │
│           (16 бітів)           │           (16 бітів)           │
└────────────────────────────────┴────────────────────────────────┘
```

- **B31..B16 (`USB Product ID`):** 16-бітовий код моделі кабелю (PID), що призначається безпосередньо виробником виробу для внутрішнього обліку та каталогізації.
- **B15..B0 (`bcdDevice`):** 16-бітовий двійково-десятковий номер версії виробу (наприклад, значення `0x0120` позначає апаратну ревізію 1.2.0).

## 4. Дескриптор Passive Cable VDO 1 (USB PD 3.0 / PD 3.1)

Дескриптор `Passive Cable VDO 1` є найбільш критичним блоком даних для силової електроніки, оскільки саме він визначає граничні межі струму та напруги, які джерело має право подати в шину VBUS.

```
 31    28 27    24 23    21 20  19 18  17 16 15 14 13 12 11 10 9 8 7 6  5 4 3 2     0
┌────────┬────────┬────────┬──────┬──────┬────────────────────────┬────┬───┬────────┐
│ HW/FW  │  Rsv   │Latency │ Term │ VBUS │        Reserved        │Cur │Rsv│ Speed  │
│  Ver   │ 0000b  │        │ 00b  │ Volt │        0000000b        │    │00 │        │
└────────┴────────┴────────┴──────┴──────┴────────────────────────┴────┴───┴────────┘
```

### Деталізація бітових полів Passive Cable VDO 1:

- **B31..B28 (`HW / FW Version`):** 4-бітовий номер ревізії апаратної частини та прошивки чипа маркера (значення від `0000b` до `1111b`).
- **B27..B24 (`Reserved`):** Зарезервовано; передається як `0000b`.
- **B23..B21 (`Cable Latency`):** Затримка розповсюдження електромагнітного сигналу по провідниках кабелю в один бік. Використовується контролерами USB4 та Thunderbolt для розрахунку таймінгів буферизації пакетів:
  - `000b` — затримка менше 10 нс (типова довжина кабелю до 1.5 м);
  - `001b` — затримка від 10 до 20 нс (довжина кабелю від 1.5 до 3.0 м);
  - `010b` — затримка від 20 до 30 нс;
  - `011b` — затримка від 30 до 40 нс;
  - `100b` — затримка від 40 до 50 нс;
  - `101b` — затримка від 50 до 60 нс;
  - `110b` — затримка від 60 до 70 нс;
  - `111b` — затримка понад 70 нс.
- **B20..B19 (`Cable Termination Type`):** Тип термінації та конфігурація живлення VCONN:
  - `00b` — для функціонування кабелю постійне живлення VCONN не потрібне;
  - `01b` — живлення VCONN необхідне лише для одного штекера кабельної збірки;
  - `10b` — живлення VCONN вимагається для обох штекерів кабелю.
- **B18..B17 (`Maximum VBUS Voltage`):** Гранично допустима робоча напруга силової ізоляції кабелю:
  - `00b` — **20 В максимум** (діапазон Standard Power Range — SPR, потужність до 100 Вт);
  - `01b` — **30 В максимум**;
  - `10b` — **40 В максимум**;
  - `11b` — **50 В максимум** (діапазон Extended Power Range — EPR, потужність до 240 Вт).
- **B16..B7 (`Reserved`):** Зарезервовано стандартом; заповнюється нулями.
- **B6..B5 (`VBUS Current-Handling Capability`):** Гранична навантажувальна здатність силових провідників VBUS та GND:
  - `00b` — Зарезервовано стандартом (заборонена комбінація);
  - `01b` — **3 А максимум** (номінальний струм для звичайних силових збірок);
  - `10b` — **5 А максимум** (підвищений струм для високопотужних кабелів 100 Вт та 240 Вт);
  - `11b` — Зарезервовано стандартом.
- **B4..B3 (`Reserved`):** Зарезервовано; передається як `00b`.
- **B2..B0 (`USB Highest Speed`):** Максимальна смуга пропускання швидкісних ліній передачі даних:
  - `000b` — **USB 2.0 only** (швидкість до 480 Мбіт/с; лінії SuperSpeed фізично відсутні в кабелі);
  - `001b` — **USB 3.2 Gen1** (швидкість 5 Гбіт/с);
  - `010b` — **USB 3.2 Gen2 / USB4 Gen2** (швидкість 10 Гбіт/с на пару);
  - `011b` — **USB4 Gen3** (швидкість 20 Гбіт/с на пару, сумарно 40 Гбіт/с);
  - `100b` — **USB4 Gen4** (швидкість 40 Гбіт/с на пару, сумарно 80 Гбіт/с симетрично або 120 Гбіт/с асиметрично).

## 5. Дескриптор Passive Cable VDO 2 (USB PD 3.1 EPR)

Дескриптор `Passive Cable VDO 2` є обов'язковим для всіх кабелів, які декларують підтримку розширеного діапазону потужності EPR 240 Вт (напруги 28 В, 36 В та 48 В).

```
 31                    24 23              16 15        12 11       8 7    4 3    0
┌────────────────────────┬──────────────────┬────────────┬──────────┬──────┬──────┐
│  Max Cable Temperature │     Reserved     │  Thermal   │   EPR    │ SBU  │ Conn │
│          (°C)          │     00000000b    │   Sensor   │ Capable  │ Type │ Type │
└────────────────────────┴──────────────────┴────────────┴──────────┴──────┴──────┘
```

### Деталізація бітових полів Passive Cable VDO 2:

- **B31..B24 (`Maximum Cable Operating Temperature`):** 8-бітове беззнакове ціле число, що визначає максимальну температуру навколишнього середовища та штекера в градусах Цельсія, при якій гарантується безпечна експлуатація кабелю (наприклад, значення `0x69` відповідає температурі 105 °C; значення `0x00` означає, що параметр не визначено).
- **B23..B16 (`Reserved`):** Зарезервовано; передається як `0x00`.
- **B15..B12 (`Thermal Sensor Presence`):** Конфігурація вбудованих термодатчиків у роз'ємах:
  - `0000b` — термодатчик відсутній;
  - `0001b` — датчик температури встановлено у Штекері 1 (ближній роз'єм);
  - `0010b` — датчик температури встановлено у Штекері 2 (дальній роз'єм);
  - `0011b` — незалежні датчики температури встановлені в обох штекерах кабелю.
- **B11..B8 (`EPR Capable`):** Офіційний прапорець сертифікації кабелю для роботи в режимі EPR 240 Вт:
  - `0000b` — кабель не підтримує режим EPR (дозволено роботу лише в режимі SPR до 20 В);
  - `0001b` — **50V EPR Capable** (кабель повністю відповідає нормам діелектричної міцності та теплового розсіювання на напругах до 48 В при струмі 5 А).
- **B7..B4 (`SBU Supported`):** Наявність сигнальних ліній додаткового призначення SBU (*Sideband Use*):
  - `0000b` — лінії SBU відсутні або не підключені;
  - `0001b` — пасивні провідники SBU присутні в кабельному джгуті (необхідні для передачі допоміжних каналів DisplayPort AUX Channel).
- **B3..B0 (`Connector Type`):** Механічна конфігурація кабельної збірки:
  - `0000b` — знімний кабель із двома роз'ємами USB Type-C на обох кінцях;
  - `0001b` — незнімний кабель (*Captive Cable*), жорстко впаяний в корпус блока живлення або док-станції.

## 6. Дескриптор Active Cable VDO 1 та Active Cable VDO 2

Активні кабелі (*Active Cables*) містять додаткові електронні компоненти (лінійні редрайвери або повноцінні ретаймери) для компенсації високочастотного загасання сигналу на довжинах понад 2 метри. У відповіді на `Discover Identity` замість пасивних дескрипторів вони повертають `Active Cable VDO 1` та `Active Cable VDO 2`.

Ключові специфічні поля дескриптора активного кабелю включають:
- **`SOP'' Controller Present` (B20 у VDO 1):** Прапорець наявності незалежного контролера в дальньому штекері кабелю, здатного приймати команди з адресацією `SOP''`.
- **`VBUS Generated / Optically Isolated` (B19..B18):** Вказує, чи є кабель оптоелектронним (з гальванічною ізоляцією мідних ліній передачі даних).
- **`Shut Down Temperature` (B23..B16 у VDO 2):** Поріг спрацьовування апаратного теплового захисту ретаймерів, при досягненні якого активні підсилювачі автоматично вимикаються для захисту кремнієвих кристалів.

## Часові нормативи та обробка помилок у протоколі

Для забезпечення стабільності шини стандарт USB PD встановлює жорсткі часові обмеження (*Timing Constraints*) на обробку Structured VDM:

```
       DFP (Хост)                                      E-Marker
           │                                              │
           │───── SOP' Discover Identity (REQ) ──────────►│
           │                                              │──┐ tVDMReceiverResponse
           │                                              │  │ (0.2 .. 15 мс)
           │◄──── SOP' Discover Identity ACK ─────────────│◄─┘
           │                                              │
           │◄───────────── tVDMResponse ─────────────────►│
           │              (max 30 мс)                     │
```

- **`tVDMResponse` (максимум 30 мс):** Часовий інтервал від закінчення останнього біта CRC пакета запиту до прийому преамбули відповіді `ACK` або `NAK`. Якщо маркер не вклався у 30 мс, контролер DFP фіксує таймаут зв'язку.
- **`tVDMReceiverResponse` (від 0.2 до 15 мс):** Нормативний час, необхідний чипу маркера для декодування запиту та формування відповіді.
- **Ліміт повторних спроб (`nCapsCount = 3`):** У разі відсутності відповіді хост має право надіслати запит повторно до трьох разів. Якщо всі три спроби завершилися таймаутом, опитування кабелю припиняється, а інтерфейс фіксує статус «кабель без маркера».

Практичну реалізацію декодера цих дескрипторів мовами C та C++ для вбудованих мікроконтролерів представлено у проєкті [⚙️ Розбір та валідація дескрипторів кабелю на C/C++](book:electronics/power-electronics/e-marker/proj-vdm-decoder.md).
