# ⚙️ Три точки — і вся крива: код моделі втрат перетворювача

Уся модель втрат — це три числа: фіксовані втрати P_фікс, комутаційний коефіцієнт k і послідовний опір R. Маючи їх, ефективність η на будь-якому струмі — рядок арифметики. Але цією дорогою можна їхати в обидва боки. **Уперед** — із трьох коефіцієнтів намалювати всю криву й точно вказати, де вона має пік. **Назад** — із трьох виміряних точок (I, η), знятих із даташитного графіка, відновити ті самі три коефіцієнти, а разом із ними й усю криву.

Зворотний бік — той, що дивує: три цятки на папері тримають увесь бюджет втрат перетворювача. Обидва напрямки — десяток рядків на Python. Це числове моделювання й підгін, холодний шлях, а не гарячий, тож numpy читається найчистіше: той самий код на C потопив би думку в риштуванні циклів і ручному розв'язанні систем.

## Пряма задача: з коефіцієнтів — крива й пік

Означення просте: η = P_вих / (P_вих + P_втрат), де P_вих = V·I. Цікаве діється не в одному місці, а на цілих порядках струму — від міліампер, де перетворювач ледь животіє на власному споживанні, до амперів, де його душить I²·R. Тому струм прогонимо **логарифмічно**: лінійний прогін збив би всю роздільність у високострумний кінець і лишив би голодним лівий злам на легкому навантаженні. Пік шукаємо просто — `argmax` по масиву η — і звіряємо з закритою формою √(P_фікс/R).

```python
import numpy as np

# коефіцієнти моделі втрат (ті самі, що в тексті)
V_out = 3.3      # В    — регульована вихідна напруга
P_fix = 0.030    # Вт   — фіксовані втрати: спокій + затвор + осердя
k_sw  = 0.05     # Вт/А — комутаційні, ростуть ∝ I
R     = 0.20     # Ом   — провідні, ростуть ∝ I²

def p_loss(I):                       # повні втрати за струмом
    return P_fix + k_sw*I + R*I**2

def efficiency(I):                   # η = P_вих / (P_вих + P_втрат)
    p_out = V_out * I
    return p_out / (p_out + p_loss(I))

# логарифмічний прогін струму: 10 мА … 5 А
I   = np.logspace(np.log10(0.01), np.log10(5.0), 4000)
eta = efficiency(I)

j          = np.argmax(eta)          # чисельний пік
I_peak_num = I[j]
I_peak_ana = np.sqrt(P_fix / R)      # закрита форма: √(P_фікс/R)

print(f"чисельний пік:  I = {I_peak_num:.4f} А,  η = {eta[j]*100:.2f} %")
print(f"√(P_фікс/R):    I = {I_peak_ana:.4f} А,  η = {efficiency(I_peak_ana)*100:.2f} %")
```

```
чисельний пік:  I = 0.3873 А,  η = 94.15 %
√(P_фікс/R):    I = 0.3873 А,  η = 94.15 %
```

Чисельний пошук і формула збіглися до останньої цифри: горб стоїть рівно на I = 0.3873 А, де √(0.030/0.20) = 0.3873. Не наближено — точно.

І тут напрошується здогад, який варто перевірити, а не проковтнути. Комутаційний доданок k·I — це справжні втрати, що ростуть зі струмом; здавалося б, вони мусять тягти пік кудись убік. Дамо k погуляти й подивімося:

```python
for k_test in (0.0, 0.2, 0.5):          # хоч який комутаційний доданок…
    e = V_out*I / (V_out*I + P_fix + k_test*I + R*I**2)
    print(f"k = {k_test:.1f} Вт/А  →  пік при I = {I[np.argmax(e)]:.4f} А")
```

```
k = 0.0 Вт/А  →  пік при I = 0.3873 А
k = 0.2 Вт/А  →  пік при I = 0.3873 А
k = 0.5 Вт/А  →  пік при I = 0.3873 А
```

Пік не зрушив ані на йоту. Чому? Максимізувати η — те саме, що мінімізувати відношення втрат до виходу ρ = P_втрат/P_вих (бо η = 1/(1+ρ), і що менше ρ, то більше η). Розпишімо це відношення:

```
ρ(I) = (P_фікс + k·I + R·I²) / (V·I) = P_фікс/(V·I)  +  k/V  +  R·I/V
```

Середній член k/V не залежить від I **зовсім** — це рівна поличка, що піднімає все відношення вгору, але має нульовий нахил. А що не має нахилу, те не може посунути мінімум. Похідна dρ/dI = −P_фікс/(V·I²) + R/V обертається на нуль там, де R·I² = P_фікс, тобто I = √(P_фікс/R) — і k в цій умові немає й близько. Комутаційні втрати опускають криву всюди, але вершини не чіпають.

Пік таки повзе вліво в живому перетворювачі — тільки не через цей доданок. Опір R сам росте з температурою, тож під великим струмом ефективний R більший, ніж біля зламу; цей крутіший правий край і стягує справжню вершину трохи нижче за √(P_фікс/R). Чиста формула припускає один сталий R; щойно якийсь доданок утрат ламає охайний поділ на {стала, ∝I, ∝I²} — вершина дістає волю блукати.

## Обернена задача: з трьох точок — усі три коефіцієнти

Даташит дає криву не коефіцієнтами, а точками. Обернімо кожну точку назад у рівняння на коефіцієнти. З виміряної (I, η) втрати на цьому струмі дістаються чистою алгеброю — переставлянням того самого означення η:

```
P_втрат = P_вих · (1 − η)/η = V·I · (1 − η)/η
```

А модель утрат **лінійна** за трьома невідомими:

```
P_втрат = P_фікс·1  +  k·I  +  R·I²
```

Отже кожна точка — це одне лінійне рівняння на (P_фікс, k, R). Три точки — три рівняння — звичайна [лінійна система](topic:math/linear-systems) 3×3. Складаємо рядки [1, I, I²] у матрицю, розв'язуємо — і по всьому. Більше ніж три точки — система перевизначена, тоді переходимо на [метод найменших квадратів](topic:math/least-squares); у numpy це той самий виклик, тільки `lstsq` замість `solve`.

```python
def recover(I_meas, eta_meas):
    """З виміряних (I, η) відновити (P_фікс, k, R) моделі втрат."""
    I_meas   = np.asarray(I_meas, float)
    eta_meas = np.asarray(eta_meas, float)
    # крок-ключ: з кожної точки дістаємо ВТРАТИ на цьому струмі
    p_loss_meas = V_out * I_meas * (1.0 - eta_meas) / eta_meas
    # P_втрат = P_фікс·1 + k·I + R·I²  — лінійно за невідомими
    A = np.column_stack([np.ones_like(I_meas), I_meas, I_meas**2])
    if len(I_meas) == 3:
        return np.linalg.solve(A, p_loss_meas)                    # точна система
    coeffs, *_ = np.linalg.lstsq(A, p_loss_meas, rcond=None)      # МНК
    return coeffs

# три точки, «як із даташита» — беремо їх із самої моделі (повна точність)
I3   = np.array([0.03, 0.387, 3.0])
eta3 = efficiency(I3)
P_fix_r, k_r, R_r = recover(I3, eta3)
print(f"відновлено:  P_фікс = {P_fix_r:.4f} Вт   k = {k_r:.4f} Вт/А   R = {R_r:.4f} Ом")
```

```
відновлено:  P_фікс = 0.0300 Вт   k = 0.0500 Вт/А   R = 0.2000 Ом
```

Три цятки повернули ввесь бюджет втрат — точно. Тепер η на будь-якому струмі й пік √(P_фікс/R) випливають самі. Це даташитна обіцянка, доведена до буквального сенсу: три точки, що виробник друкує (легке, типове, повне навантаження), — не ввічливий приклад, а **повна специфікація фізики втрат**, якщо знати, як її обернути.

> 🔧 **Навіщо це.** Виробник майже ніколи не друкує P_фікс, k і R окремо — він друкує графік. Але вам ці числа потрібні: без них не скласти власний бюджет потужності, не порахувати нагрів, не порівняти два чипи на *своєму* робочому струмі, а не на їхньому пікові. Обернений хід дає модель із будь-якого графіка ефективності — навіть із чужого, зісканованого з PDF по трьох знятих цятках. Далі ця модель ваша: підставляй свій струм, свою напругу, свій тепловий сценарій.

Чому саме три і які три? Трьом невідомим треба три незалежні факти — і рознесені. Точка на легкому навантаженні — там, де показує себе P_фікс (втрати майже цілком фіксовані); точка на повному — там, де панує R·I²; середня прив'язує k. Дай розв'язувачу три струми на октаву врізнобіч — він і не змигне; дай три сусідні — вдавиться. Це вже перша пастка.

## Складність і пастки

**Округлене η з даташита.** Справжній даташит друкує η до якихось 0.1 %. Погодуймо округлену трійку:

```python
eta_ds = np.array([0.758, 0.942, 0.833])          # ті самі точки, «як у даташиті»
print("округлене:  P_фікс=%.4f  k=%.4f  R=%.4f" % tuple(recover(I3, eta_ds)))
```

```
округлене:  P_фікс=0.0300  k=0.0478  R=0.2013
```

P_фікс і R ледь ворухнулися, а k з'їхав на ~4 % (0.050 → 0.048). Винна тут пікова точка. При 94 % втрати — тонюсінька скибка виходу, тож (1−η)/η крихітне, і округлення η в останній друкованій цифрі гойдає обчислені втрати на велику **відносну** частку. Розв'язок 3×3 звалює цю похибку на той коефіцієнт, що найдужче зав'язаний на цю точку, — на середній. Урок парадоксальний: пікова точка найефектніша на графіку й найменш інформативна для підгону. Несуть інформацію ті, де втрати — відчутна частка: легке навантаження для P_фікс, важке для R.

**Обумовленість.** Візерунок рядка [1, I, I²] — це структура Вандермонда, і її [умовне число](topic:math/condition-number) вибухає, щойно струми збиваються докупи:

```python
def cond(Is):
    A = np.column_stack([np.ones(3), Is, np.asarray(Is)**2])
    return np.linalg.cond(A)
print("cond розкидані [0.03, 0.387, 3.0] = %.0f" % cond([0.03, 0.387, 3.0]))
print("cond скупчені  [1.0, 1.1, 1.2]    = %.0f" % cond([1.0, 1.1, 1.2]))
```

```
cond розкидані [0.03, 0.387, 3.0] = 46
cond скупчені  [1.0, 1.1, 1.2]    = 1104
```

Рознесені на порядки — умовне число 46, сумирне. Три сусіди при 1.0/1.1/1.2 А — 1104, і кожен мікровольт шуму вимірювання множиться на цю величину, перш ніж осісти у ваших коефіцієнтах. Бери три точки врозкид по логарифмічній осі — тій самій, якою йде прямий прогін; це не оздоба, а те, що тримає обернений хід чесним.

**Більше точок, МНК.** Надійна звичка — не грати на трьох, а прогнати з десяток і підігнати найменшими квадратами:

```python
I8   = np.array([0.03, 0.06, 0.12, 0.25, 0.5, 1.0, 2.0, 3.0])
eta8 = np.round(efficiency(I8), 3)                # даташитне округлення до 0.1 %
c = recover(I8, eta8)
print("МНК(8):  P_фікс=%.4f  k=%.4f  R=%.4f  →  пік √(P/R)=%.4f А"
      % (c[0], c[1], c[2], np.sqrt(c[0]/c[2])))
```

```
МНК(8):  P_фікс=0.0297  k=0.0508  R=0.2004  →  пік √(P/R)=0.3847 А
```

Вісім округлених точок відновлюють 0.0297 / 0.0508 / 0.2004 і передбачають пік на 0.385 А — перевизначеність усереднює поточкове округлення. Якщо пікові точки все одно набридають, зваж кожне рівняння на те, скільки втрат воно насправді несе, щоб тонкоскибкові точки перестали кричати гучніше, ніж знають, — це [зважений МНК](topic:math/weighted-least-squares).

**Здоровий глузд і чесність моделі.** Дві сторожі. Перша: коефіцієнти фізичні, P_фікс, k, R ≥ 0. Підгін, що повертає від'ємне k, — це не відкриття, а сигнал моделі, що дані чи припущення кульгають (не та V_вих, забутий доданок утрат, переплутаний струм). Найменші квадрати фізики не знають — знаки перевіряєш ти. Друга: пам'ятай, що таке I тут — це вихідний струм. Єдиний R убирає в себе все, що охайна модель ігнорує: RMS пульсацій понад середнє, поділ шпаруватості між верхнім і нижнім ключем, дрейф R із температурою. Це ефективний, усереднений підгоном R: чудовий для інтерполяції всередині зміряного діапазону, хисткий для екстраполяції далеко за нього. Самі точки беруть із даташитного графіка — або, для власної плати, з [прогону електронним навантаженням](topic:electronics/converter-measure), і це чесніше джерело, бо даташитний графік знято на ідеальній розводці.

Одна позамодельна дрібниця для тих, хто запускатиме цей код: рядки виводу несуть η і √. Консоль Windows у типовому кодуванні на них давиться (`UnicodeEncodeError`) — запускай зі змінною `PYTHONIOENCODING=utf-8` або тримай ці знаки подалі від stdout. На арифметику це не впливає жодним чином: спотикається термінал, а не модель.

Три числа з паперу відтворюють криву, що біжить крізь порядки струму, — не тому, що код хитрий, а тому, що фізика скупа: увесь бюджет утрат має рівно три ручки, тож рівно три чесні виміри їх повертають. Читай криву вперед, щоб поставити своє навантаження під її пік; читай назад, щоб украсти модель, яку даташит майже задарма поклав тобі в руки.
