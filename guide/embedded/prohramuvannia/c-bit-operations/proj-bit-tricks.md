# ⚙️ Бітові хаки: колекція прийомів із виведеннями

Ми вже маємо в руках дві цеглинки, з яких виростає цілий пласт бітових алгоритмів: `x & (x-1)` гасить наймолодшу одиницю, а `x & -x` виділяє її. Обидві — не магія, а прозорий наслідок того, як віднімання й доповняльний код рухають біти. Тут зберемо на цих цеглинках набір робочих прийомів, кожен із яких реально трапляється в прошивці: обійти всі встановлені біти маски, порахувати одиниці трьома різними способами, округлити число вгору до степеня двійки, дзеркально перевернути порядок бітів. Для кожного — та сама дисципліна: **задача → ідея → чому воно працює → робочий C → де підстелити соломку**.

Це не збірка фокусів заради краси. Кожен прийом розв'язує конкретну проблему дешевше, ніж наївний код: там, де цикл по всіх 32 бітах робить 32 ітерації, ці техніки роблять стільки, скільки насправді треба, а інколи взагалі кілька інструкцій без жодного циклу. У драйвері, що крутиться в перериванні кожні кілька мікросекунд, така різниця — не естетика, а те, укладаєтесь ви в бюджет тактів чи ні.

## Обійти всі встановлені біти — по одному, без порожніх обертів

**Задача.** Прийшла бітова маска — скажімо, `uint32_t pending`, де кожен піднятий біт означає «канал з таким номером просить обслуговування». Треба обробити рівно ті канали, чиї біти стоять, і не витрачати оберти циклу на нулі. Наївний шлях — пройти всі 32 позиції й для кожної спитати `if (pending & (1u << i))`. Але якщо піднято два біти з тридцяти двох, це тридцять перевірок дарма.

**Ідея.** `x & -x` дає нам **саме наймолодший піднятий біт** — одне число з єдиною одиницею. Обробили його, скинули через `x &= x - 1` — і наступний `x & -x` віддасть уже наступну одиницю знизу. Цикл робить рівно стільки обертів, скільки в масці одиниць: порожніх ітерацій немає взагалі.

Лишається дрібниця — від виділеного біта дізнатися його **номер** (позицію), бо канал ідентифікують числом, а не бітовою маскою. Порахувати, скільки нулів іде знизу до першої одиниці, — це операція «кількість кінцевих нулів» (англ. *count trailing zeros*, `ctz`). Майже кожен процесор уміє її однією інструкцією, і компілятор дає до неї доступ через `__builtin_ctz`.

```c
#include <stdint.h>

void service_pending(uint32_t pending, void (*handle)(int ch)) {
    while (pending) {
        int ch = __builtin_ctz(pending);   // номер наймолодшого піднятого біта
        handle(ch);                         // обробити цей канал
        pending &= pending - 1;             // скинути цей біт, іти далі
    }
}
```

Три рядки в тілі циклу читаються прямо як задача: «дізнайся номер найнижчого прапорця → обслужи його → прибери його». Для маски `0b10110100` цикл віддасть канали 2, 4, 5, 7 — і зупиниться, зробивши рівно чотири оберти.

> 🔧 **Навіщо це.** Так насправді влаштований диспетчер переривань і всілякі «хто з давачів озвався» цикли. Регістр стану периферії — це бітова маска подій; ви хочете обробити тільки ті, що сталися, і не крутити цикл по решті. `__builtin_ctz` + `&= x-1` — канонічний спосіб «пройтися по піднятих бітах», і він настільки поширений, що варто впізнавати його з першого погляду.

**Пастка.** `__builtin_ctz(0)` — **невизначена поведінка**: для нуля кількість кінцевих нулів не означена, і на різних платформах ви дістанете різне сміття, а не «32». Тому виклик стоїть **усередині** `while (pending)` — коли ми туди заходимо, `pending` гарантовано ненульове. Ніколи не викликайте `ctz`/`clz` на нулі поза такою перевіркою. І ще: `__builtin_ctz` бере `unsigned int` (зазвичай 32 біти); для 64-бітної маски є `__builtin_ctzll`. Якщо потрібна переносність поза GCC/Clang, номер біта можна дістати й без вбудованої функції (класичний трюк — послідовність де Брейна), але в прошивці під конкретний компілятор `__builtin_ctz` — найпростіший і найшвидший вибір.

## Порахувати одиниці — три способи, від наївного до паралельного

Кількість одиничних бітів (популяція, англ. *population count*; історична назва — вага Геммінга) потрібна всюди: скільки каналів активні, скільки помилок у контрольному коді, наскільки «щільна» бітова множина. Три способи це порахувати — гарна драбина від очевидного до майже чарівного, і всі три варто розуміти, бо кожен має свою нішу.

### Спосіб перший, наївний: перевіряй кожен біт

Найпряміший переклад означення в код — пройти всі розряди й додати ті, що стоять:

```c
int popcount_naive(uint32_t x) {
    int n = 0;
    for (int i = 0; i < 32; i++)
        n += (x >> i) & 1;   // молодший біт зсунутого x — це біт номер i
    return n;
}
```

Він завжди робить **32** оберти, скільки б одиниць не було — навіть для нуля. Зате очевидний і не має пасток. Для рідкісного виклику на повільному коді цього досить.

### Спосіб другий, Кернігана: гаси одиниці по одній

Ми вже бачили цей прийом: `x &= x - 1` прибирає наймолодшу одиницю. Скільки разів так можна зробити до нуля, стільки в числі й одиниць — і цикл робить рівно стільки обертів, **скільки є одиниць**, а не скільки всього бітів:

```c
int popcount_kernighan(uint32_t x) {
    int n = 0;
    while (x) { x &= x - 1; n++; }
    return n;
}
```

Для розрідженого числа (кілька одиниць серед нулів) це велика перемога: маска з двома одиницями — два оберти замість тридцяти двох. Для щільного числа виграшу нема — там одиниць якраз багато.

Варто назвати цей прийом чесно. У книзі Кернігана й Рітчі він стоїть вправою, і ім'я «метод Кернігана» до нього прилипло, — але вигадав його не Керніган. Спосіб рахувати одиниці через `x & (x-1)` опублікував **Пітер Вегнер (Peter Wegner) 1960 року** в *Communications of the ACM*; незалежно його знайшов і **Деррік Лемер (Derrick Henry Lehmer)**. Керніган і Рітчі лише зробили прийом широко відомим. Це усталений факт (першоджерела — стаття Вегнера 1960 і пізніші історичні огляди алгоритму), і згадати справжнього автора — звичайна коректність.

### Спосіб третій, паралельний (SWAR): рахуй усі поля воднораз

А тепер найцікавіше. Обидва попередні способи чіпають біти по одному. Але ж процесор оперує цілим 32-бітним словом за раз — то чому не змусити його рахувати **в усіх частинах слова одночасно**? Саме це робить паралельний підрахунок, відомий як **SWAR** (англ. *SIMD Within A Register* — «векторні дії всередині одного регістра»): трактуємо одне слово як багато вузьких полів і виконуємо ту саму дію над усіма полями воднораз, звичайними арифметично-логічними операціями.

Ідея — **дерево часткових сум**, що подвоює ширину поля щокроку. Спершу розбиваємо 32 біти на **пари** й у кожній парі рахуємо, скільки там одиниць (0, 1 чи 2) — виходить 16 двобітових лічильників, і всі 16 порахувалися **однією** операцією над цілим словом. Далі складаємо сусідні пари в **четвірки**, четвірки — у **байти**, байти — у **половини**, і нарешті все зводиться в одне число. Кожен рівень дерева — кілька операцій над цілим словом, і таких рівнів лише log₂32 = 5.

![Дерево часткових сум: 16-бітний приклад, де на кожному кроці сусідні поля складаються воднораз, а ширина поля подвоюється](/guide/embedded/prohramuvannia/c-bit-operations/img/swar-tree.svg)
*Паралельний підрахунок на 16-бітному прикладі (для 32 бітів усе те саме, лише на один рівень довше). Верхній рядок — сирі біти. Далі кожен рядок складає сусідні поля попереднього: пари → четвірки → байти → усе разом. Головне — кожен рівень рахує **всі** свої поля однією дією над цілим словом, тож замість 16 перевірок виходить log₂16 = 4 кроки. Числа в зелених полях — це вже кількість одиниць у відповідному відрізку, а не самі біти.*

Тепер найтонше — **як** скласти всі пари воднораз, не переплутавши сусідів. Ключ у тому, що двобітове поле вміщає число до 3, тож сума двох однобітових значень (максимум 1+1=2) ніколи не переллється в сусіднє поле. Ось перший крок, і він хитромудрий:

```c
x = x - ((x >> 1) & 0x55555555);
```

Розберімо, чому це рахує одиниці в кожній парі. Константа `0x55555555` у двійковому — це `0101...0101`: одиниці стоять на всіх **парних** (молодших у кожній парі) позиціях. Вираз `(x >> 1) & 0x55555555` бере старший біт кожної пари й ставить його на місце молодшого. Відняти це від `x` — і в кожній двобітовій ділянці лишається саме кількість одиниць, що там була. (Це не випадковість, а маленька арифметична тотожність: для двобітового значення `ab` різниця `ab − a` дорівнює `a + b`. Спробуйте всі чотири комбінації — сходиться.) Одна операція — і 16 лічильників готові.

Далі складаємо сусідні двобітові поля в чотирибітові, потім чотирибітові — у восьмибітові:

```c
int popcount_swar(uint32_t x) {
    x = x - ((x >> 1) & 0x55555555);                  // суми в парах
    x = (x & 0x33333333) + ((x >> 2) & 0x33333333);   // суми в четвірках
    x = (x + (x >> 4)) & 0x0F0F0F0F;                   // суми в байтах
    return (x * 0x01010101) >> 24;                     // додати всі 4 байти
}
```

Маски тут — це «гребінці», що виділяють потрібні поля: `0x33333333` — це `0011...0011` (виділяє чотирибітові групи попарно), `0x0F0F0F0F` — `00001111...` (виділяє байти). На кроці з четвірками ми **окремо** беремо парні й непарні двобітові поля (маскою й зсунутою маскою) і складаємо — так суми не наступають одна на одну. На кроці з байтами число вже настільки мале в кожному байті, що можна скласти простіше — `x + (x >> 4)` — і лише потім одним `& 0x0F0F0F0F` прибрати сміття зі старших половинок байтів.

Останній рядок — окрема краса. Після третього кроку кожен **байт** слова містить свою кількість одиниць (число 0…8), а треба їх усі скласти. Замість трьох додавань зі зсувами це роблять **одним множенням**. Множення на `0x01010101` (тобто на `1 + 2⁸ + 2¹⁶ + 2²⁴`) — це те саме, що додати число до себе, зсунутого на 8, 16 і 24. Позначмо байти лічильників як A, B, C, D (від старшого до молодшого); множення накладає їх одне на одне так, що **найстарший байт добутку стає A+B+C+D** — сумою всіх чотирьох. Зсув `>> 24` дістає цей найстарший байт — і це шукана відповідь. Одне множення замість ланцюжка додавань — на процесорі з апаратним множником це швидко.

Цей паралельний метод — не новинка: його **описали ще 1957 року** Дональд Гілліс (Donald B. Gillies) і Джеффрі Міллер (Jeffrey C. P. Miller) у ранньому підручнику з програмування (Вілкс, Вілер і Ґілл, «The Preparation of Programs for an Electronic Digital Computer»). Пізніший знаменитий збірник хаків MIT — **HAKMEM 169 (1972)** Білла Ґоспера й колег — дає споріднений варіант, але через трибітові поля, і він трохи менш ефективний за двійковий SWAR. Тобто «магічні маски 0x5555…» старші за півстоліття — усталений факт (першоджерело 1957 року й порівняння варіантів наводить, зокрема, вікі з популяційного підрахунку). А на сучасних мікроконтролерах усе це часто зводиться до **однієї інструкції**: `__builtin_popcount(x)` компілятор перекладе в апаратну команду підрахунку, якщо ядро її має (наприклад, на багатьох Cortex-M). Тож у реальному коді пишіть `__builtin_popcount` — а SWAR тримайте в голові, щоб розуміти, що робить залізо, і мати запасний варіант там, де апаратної команди нема.

**Пастки SWAR.** По-перше, константи прив'язані до **ширини 32 біти**; для 64-бітного слова маски треба розширити (`0x5555555555555555` і так далі) або взяти `__builtin_popcountll`. По-друге, останнє множення покладається на те, що добуток лишається в межах 32 бітів — для 32-бітного входу це так (максимальна сума 32 вміщається в байт), але переносячи ідею на ширші слова, перевіряйте, що поля не переповнюються. По-третє, як завжди з операндами вужчими за `int`, стежте за неявним підвищенням типу — для `uint32_t` на 32-бітній платформі все сходиться, але на екзотиці варто бути уважним.

## Округлити вгору до степеня двійки

**Задача.** Треба виділити кільцевий буфер, і хочеться, щоб його розмір був степенем двійки, — тоді загортання індексу робиться дешевим `& (size - 1)` замість дорогого `%`. Користувач попросив буфер на 1000 елементів; треба округлити це **вгору** до найближчого степеня двійки — до 1024. Тобто: дано число, знайти найменший степінь двійки, не менший за нього.

**Ідea.** Степінь двійки — це одна одиниця й нулі: `1000...0`. А число трохи менше за степінь двійки — це суцільні одиниці: `0111...1`. Звідси план у два ходи. Спершу «розмазати» найстарший піднятий біт **вниз**, заповнивши все під ним одиницями, — з будь-якого числа зробити `0...0111...1`. Тоді додати 1 — і весь цей хвіст одиниць перекинеться в один-єдиний біт на розряд вище: `1000...0`, рівно наступний степінь двійки.

Розмазування робиться каскадом «АБО із власним зсувом». `x |= x >> 1` гарантує, що після найстаршої одиниці стоїть іще одна (тепер їх щонайменше дві поспіль). `x |= x >> 2` подвоює довжину суцільної смуги одиниць до чотирьох, `x >> 4` — до восьми, і так подвоюючи, доки смуга не накриє всі молодші розряди. Для 32 бітів вистачає зсувів 1, 2, 4, 8, 16 — п'ять кроків, бо кожен подвоює довжину, а 2⁵ = 32:

```c
#include <stdint.h>

uint32_t next_pow2(uint32_t x) {
    x--;                 // щоб точний степінь двійки лишився собою, а не подвоївся
    x |= x >> 1;
    x |= x >> 2;
    x |= x >> 4;
    x |= x >> 8;
    x |= x >> 16;        // тепер x = 0...0111...1 (усе під старшою 1 — одиниці)
    x++;                 // хвіст одиниць перекидається в наступний степінь двійки
    return x;
}
```

Навіщо `x--` на початку? Без нього число, що **вже є** степенем двійки (скажімо, 16), розмазалось би до `0...011111` і після `+1` стрибнуло б на 32 — тобто на наступний степінь, а не лишилося собою. Віднявши 1 перед розмазуванням, ми зсуваємо точний степінь двійки на межу так, що він округлюється **сам у себе**. Перевіримо на числах: `next_pow2(1000)` = 1024, `next_pow2(1024)` = 1024, `next_pow2(1025)` = 2048, `next_pow2(5)` = 8. Сходиться.

Є й другий шлях до тієї самої відповіді — через уже знайому нам операцію «кількість старших нулів» (англ. *count leading zeros*, `clz`). Якщо ми знаємо позицію найстаршого піднятого біта, то степінь двійки будується прямим зсувом:

```c
uint32_t next_pow2_clz(uint32_t x) {
    if (x <= 1) return 1;
    return 1u << (32 - __builtin_clz(x - 1));
}
```

`__builtin_clz(x-1)` каже, скільки нулів іде згори до першої одиниці числа `x-1`; відняти від 32 — дістати позицію **над** найстаршою одиницею; зсунути туди одиницю — і маємо потрібний степінь. На ядрі з апаратним `clz` (а таких серед мікроконтролерів багато) цей варіант — буквально кілька інструкцій без жодного циклу.

> 🔧 **Навіщо це.** Розміри кільцевих буферів, вирівнювання блоків пам'яті, розрядність геш-таблиць — усе це любить степені двійки, бо тоді ділення й остача перетворюються на дешеві зсуви й маски. `next_pow2` — типовий помічник в аллокаторі чи в ініціалізації драйвера, коли треба «підтягнути» довільний запитаний розмір до зручного.

**Пастки.** Обидва варіанти мають злі граничні випадки, і на них варто підстелити соломку. Перше: **нуль**. У версії з розмазуванням `x--` перетворить 0 на `0xFFFFFFFF`, каскад лишить його таким, а `x++` дасть 0 назад — тобто `next_pow2(0)` поверне 0, що степенем двійки не є. Якщо нуль на вході можливий, обробіть його окремо. Друге, злостивіше: **переповнення**. Якщо на вході число більше за 2³¹ (найбільший степінь двійки, що вміщається в 32 біти), наступного степеня в типі просто немає — і функція «загорнеться» в 0. Мовчазний нуль замість очікуваного великого числа — рідкісний, але дуже підступний баг; у коді, де вхід не обмежений згори, поставте перевірку. Третє стосується лише `clz`-версії: `__builtin_clz(0)` — знову **невизначена поведінка**, тому там стоїть ранній `if (x <= 1) return 1`, який не дає аргументу `x-1` стати нулем.

## Перевернути порядок бітів (дзеркалення)

**Задача.** Деякі апаратні протоколи посилають байти «молодшим бітом уперед» (LSB-first), а інші — «старшим уперед» (MSB-first). Коли ваш зсувний регістр чи SPI-периферія віддає біти в одному порядку, а пристрій на тому кінці чекає на протилежний, треба **дзеркально перевернути** біти: біт 0 стає бітом 31, біт 1 — бітом 30, і так далі. Так само реверс бітів потрібен в обчисленні деяких контрольних кодів (CRC) і в перестановках для швидкого перетворення Фур'є.

**Ідея.** Наївно — цикл на 32 оберти, що бере біти з одного кінця й ставить на дзеркальні місця. Але є набагато елегантніший шлях, той самий поділ навпіл, що й у SWAR: **обмінюємо блоки, що подвоюються**. Спершу міняємо місцями кожен біт із його сусідом (усі 16 пар — однією операцією над словом). Потім міняємо місцями сусідні **пари**. Потім — сусідні **четвірки**, **байти**, і нарешті дві **половини** слова. Після log₂32 = 5 таких кроків кожен біт опиняється точно на дзеркальній позиції — і жодного циклу.

![Дзеркалення 8-бітного числа обміном блоків, що подвоюються: сусідні біти → пари → половини](/guide/embedded/prohramuvannia/c-bit-operations/img/bit-reverse.svg)
*Реверс на 8-бітному прикладі (для 32 бітів — так само, лише кроків п'ять). Щокроку міняємо місцями вдвічі більші сусідні блоки: спершу окремі біти, тоді пари, тоді половини. Дужки показують, що з чим обмінюється. Після трьох кроків (log₂8 = 3) число повністю дзеркальне до вихідного. Кожен обмін робиться однією парою масок над цілим словом, тож усі блоки одного рівня міняються воднораз.*

Як обміняти сусідні блоки шириною `k` однією операцією? Двома масками. Маска виділяє «ліві» блоки кожної пари, її доповнення — «праві». Зсуваємо ліві на `k` праворуч, праві на `k` ліворуч, і склеюємо через АБО:

```c
#include <stdint.h>

uint32_t reverse_bits(uint32_t x) {
    x = ((x & 0x55555555) << 1)  | ((x & 0xAAAAAAAA) >> 1);   // обмін сусідніх бітів
    x = ((x & 0x33333333) << 2)  | ((x & 0xCCCCCCCC) >> 2);   // обмін сусідніх пар
    x = ((x & 0x0F0F0F0F) << 4)  | ((x & 0xF0F0F0F0) >> 4);   // обмін четвірок
    x = ((x & 0x00FF00FF) << 8)  | ((x & 0xFF00FF00) >> 8);   // обмін байтів
    x = ((x & 0x0000FFFF) << 16) | ((x & 0xFFFF0000) >> 16);  // обмін половин
    return x;
}
```

Придивіться до масок — вони ті самі «гребінці», що й у SWAR, просто застосовані по-іншому. `0x55555555` виділяє парні біти, `0xAAAAAAAA` (його доповнення) — непарні; перший рядок зсуває одні ліворуч, інші праворуч і зшиває — рівно обмін кожного біта з сусідом. Наступний рядок робить те саме з парами (маски `0x33333333`/`0xCCCCCCCC`), тоді з четвірками, байтами, половинами — щоразу блок удвічі ширший. П'ять рядків, жодного циклу, і на будь-якому вході однакова робота.

> 🔧 **Навіщо це.** У прошивці реверс бітів найчастіше зринає на стику з залізом: SPI-давач чи РК-контролер очікує біти в порядку, зворотному до того, як їх кладе ваш зсувний регістр; апаратний CRC-блок рахує «з іншого кінця». Мати під рукою швидкий `reverse_bits` без циклу — практична дрібниця, що рятує, коли реверс треба робити на кожен переданий байт у гарячому циклі.

**Пастки.** Головне — стежити, що маска й **тип** узгоджені за шириною. Наведений код — суто для `uint32_t`; для байта (`uint8_t`) масок і кроків менше, а константи інші (`0x55`, `0x33`, `0x0F` без старших повторів). І пам'ятайте про неявне підвищення до `int`: коли пишете реверс восьмибітного значення, проміжні `(x << 4)` рахуються в ширшому `int`, тож наприкінці варто явно звузити результат назад до `uint8_t`, інакше в старших бітах може лишитися сміття, якого ви не чекали. Ці граничні тонкощі з шириною типу — той самий підводний камінь, що переслідує всі бітові операції: маска бездоганно виділяє **біти**, але не рятує від того, як мова роздуває **тип** проміжних значень.

## Ізолювати й скинути наймолодший біт — і як це складається в патерн

Наостанок зберемо докупи дві вихідні цеглинки, бо разом вони дають готовий шаблон, який ви бачитимете знову й знову.

`x & -x` **ізолює** наймолодший піднятий біт — лишає одне число з єдиною одиницею на місці найправішої одиниці `x`. `x & (x - 1)` **скидає** цей самий біт — прибирає найправішу одиницю, лишаючи решту. Дві дзеркальні дії над тим самим бітом: одна його **дістає**, друга — **прибирає**.

Разом вони утворюють універсальний патерн «обробити елементи бітової множини»: `x & -x` дає поточний елемент (або, через `ctz`, його номер), а `x &= x - 1` викреслює його й переводить до наступного. Саме цей патерн ми вже застосували в найпершому прийомі цієї добірки — обході встановлених бітів. Він же лежить в основі черг пріоритетів на бітових масках (наймолодший піднятий біт — найпріоритетніша готова задача), у планувальниках, у розкладанні множин. Один рядок дає елемент, другий — прибирає його; цикл природно зупиняється, коли `x` доходить до нуля.

Варто відзначити ще одну корисну дрібницю тієї самої природи: `x & (x - 1)` дорівнює нулю **тоді й лише тоді**, коли в `x` не більш ніж одна одиниця. Ми вже вживали це для перевірки «чи є число степенем двійки». Той самий вираз відповідає й на трохи інше питання — «чи піднято щонайбільше один прапорець у масці»: якщо `(x & (x-1)) == 0`, то активний найбільше один. Одна перевірка — і ви знаєте, що ситуація «нуль або один», без підрахунку всіх бітів.

Ось у чому спільна суть усієї добірки. Кожен прийом тут — не завчена формула, а прямий наслідок кількох простих фактів: віднімання одиниці розмазує позику знизу вгору; доповняльний код робить `-x` дзеркальним до `x` рівно до наймолодшої одиниці; поділ слова навпіл дозволяє рахувати чи переставляти всі частини воднораз. Тримаючи ці механізми перед очима, ви не мусите запам'ятовувати трюки — ви щоразу можете **вивести** їх наново. А коли доведеться писати драйвер, кодек чи планувальник, ці прийоми чекатимуть напоготові — уже не як загадкові рядки з чужого коду, а як ясна механіка, яку видно наскрізь.
