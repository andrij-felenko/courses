# ⚙️ Шум у коді: від rand() до гаусового (Бокс—Мюллер)

> Розмова про [шум і заваду](guide:embedded/noise-interference) ділить причини на внутрішні джерела й зовнішні наводки, а [сусідня вставка про випадкову величину](guide:embedded/noise-interference/math-random-variables.md) показує, що тепловий шум має **гаусів розподіл** (*Gaussian / normal distribution*) із середнім нуль і відхиленням σ. Тут — практичний бік: як **отримати** такий шум у програмі. Це треба, коли хочеш промоделювати давач із шумом, перевірити фільтр на синтетичних даних або «потрусити» алгоритм, перш ніж вмикати реальне залізо.

### Задача

Стандартна бібліотечна `rand()` дає число **рівномірно** (*uniformly*) по діапазону: будь-яке значення між 0 і 1 (або 0…RAND_MAX) однаково ймовірне. Це плаский «брусок» імовірності. А тепловий шум, дробовий шум, похибка АЦП — усі вони скупчуються **біля нуля**: маленькі відхилення часті, великі рідкі. Це дзвін Гаусса. Питання: як із плаского `rand()` зробити дзвін?

![Ліворуч плаский розподіл rand(), праворуч гаусів дзвін; між ними — перетворення Бокса—Мюллера](/guide/embedded/zminnyi-strum/noise-interference/img/noisegen-uniform-vs-gauss.svg)
*Дві форми випадковості. `rand()` (ліворуч) сипле рівно по всьому діапазону — U(0, 1). Реальний шум (праворуч) розподілений за Гауссом N(0, σ): найчастіші значення — біля нуля, рідкі — за ±σ. Завдання алгоритму — перетворити перше на друге.*

### Ідея: усереднити або повернути на коло

Перетворити плаский розподіл на дзвін можна двома шляхами — їх і називає заголовок. Перший, наївний, спирається на **центральну граничну теорему** (*central limit theorem*): сума багатьох незалежних рівномірних чисел сама прямує до Гаусса. Складеш дванадцять викликів `rand()` (кожен у [0,1)), віднімеш 6 — і дістанеш величину з середнім 0 і σ ≈ 1. Просто, але неточно: «хвости» обрізані на ±6, та й дванадцять викликів `rand()` на одне число — недешево.

Точний і елегантний шлях — **перетворення Бокса—Мюллера** (*Box—Muller transform*, 1958). Воно бере **два** рівномірні числа u₁, u₂ і повертає **два** незалежні гаусові z₁, z₂. Геометрична суть: u₁ задає кут θ на колі, u₂ — радіус R; проєкції цієї точки на осі вже розподілені точно за Гауссом.

![Квадрат двох рівномірних чисел задає точку на колі; її проєкції — два гаусові числа](/guide/embedded/zminnyi-strum/noise-interference/img/noisegen-box-muller.svg)
*Геометрія Бокса—Мюллера. Пара u₁, u₂ ~ U(0,1) (ліворуч) задає кут θ = 2π·u₁ і радіус R = √(−2·ln u₂) точки на площині (центр). Її проєкції z₁ = R·cos θ та z₂ = R·sin θ (праворуч) — два незалежні числа з N(0, 1). Один логарифм і один синус-косинус дають одразу два гаусові значення.*

Формули виходять короткі:

```
θ  = 2·π·u₁
R  = √(−2·ln u₂)
z₁ = R·cos(θ)        # перше гаусове, N(0, 1)
z₂ = R·sin(θ)        # друге гаусове, N(0, 1)
```

Щоб дістати шум із потрібним середнім μ і відхиленням σ, масштабуємо: `x = μ + σ·z`. Логарифм тут невипадковий — саме він «розтягує» рівномірний радіус так, щоб щільність точок спадала експоненційно від центра, як і має бути в Гаусса.

### Псевдокод

Лишається загорнути ці чотири рядки у функцію, що віддає по одному числу на виклик:

:::tabs
```c
#include <stdlib.h>
#include <math.h>

// рівномірне у (0, 1]: зсув на +1 гарантує, що нуль під ln не випаде
static double rand_0_1(void) {
    return (rand() + 1.0) / (RAND_MAX + 1.0);
}

double gauss(void) {
    static int    has_spare = 0;   // один із двох виходів кешуємо
    static double spare     = 0.0;
    if (has_spare) {
        has_spare = 0;
        return spare;              // віддаємо раніше пораховане z₂
    }
    double u1 = rand_0_1();
    double u2 = rand_0_1();
    double theta = 2.0 * M_PI * u1;
    double R     = sqrt(-2.0 * log(u2));
    spare     = R * sin(theta);    // z₂ — на потім
    has_spare = 1;
    return R * cos(theta);         // z₁ — зараз
}
```
```python
import math
import random


def gauss():
    """Нескінченний потік N(0, 1): по одному числу на next()."""
    while True:
        u1 = random.random()                 # рівномірне у [0, 1)
        u2 = 1.0 - random.random()           # рівномірне у (0, 1]: нуль під ln не випаде
        theta = 2.0 * math.pi * u1
        R     = math.sqrt(-2.0 * math.log(u2))
        yield R * math.cos(theta)            # z₁ — зараз
        yield R * math.sin(theta)            # z₂ — пара віддається наступним next()
```
:::

Дрібниця з наслідком: Бокс—Мюллер народжує числа **парами**, тож друге значення гріх викидати — кешуємо його й віддаємо за наступним викликом. Так один логарифм і одна пара синус-косинус припадають на **два** гаусові числа.

### Складність і пастки на МК

Псевдокод вище працює на ПК без застережень, але на мікроконтролері кожен його рядок ховає окрему пастку:

- **Логарифм нуля.** Якщо u₂ під логарифмом виявиться рівно 0, `ln(0)` = −∞ і все ламається. Тому це число беруть із напіввідкритого (0, 1]: зсувають `(rand()+1)/(RAND_MAX+1)` так, щоб нуль не випадав.
- **Дорогі функції.** `ln`, `sin`, `cos`, `sqrt` — важкі для мікроконтролера без FPU: десятки-сотні тактів кожна. На «голому» МК часто беруть **полярний варіант** (Marsaglia): кидаєш точки в квадрат, поки не влучиш у коло, — там лишаються тільки `ln` і `sqrt`, без тригонометрії. Або взагалі готують **таблицю** заздалегідь порахованих гаусових чисел і просто крутять її по колу.
- **Генератор має бути добрий.** Бібліотечна `rand()` часто має короткий період і слабкі молодші біти. Для чесного шуму беруть нормальний PRNG (*pseudo-random number generator*) — xorshift, PCG чи `<random>` у C++.
- **Це не справжня випадковість.** PRNG детермінований: той самий seed дає ту саму послідовність. Для моделювання це навіть плюс (тест відтворюваний); для криптографії — категорично ні.
- **Не плутай рівномірний із гаусовим.** Якщо просто масштабувати `rand()` у ±σ, дістанеш брусок, а не дзвін: «трава» на екрані виглядатиме неправильно, а оцінки усереднення (σ/√N, як у [полюванні на шум](guide:embedded/noise-hunting)) збіжаться не так, як від реального шуму.

### Де ще це трапляється

Той самий Бокс—Мюллер живе всюди, де треба «природна» випадковість: симуляція давачів і каналів зв'язку, метод Монте-Карло, ініціалізація ваг у нейромережах, додавання реалістичного дрижання (*dithering*) до звуку чи зображення. Один короткий рецепт — рівномірне на коло, радіус через логарифм — і плаский `rand()` стає справжнім гаусовим шумом.
