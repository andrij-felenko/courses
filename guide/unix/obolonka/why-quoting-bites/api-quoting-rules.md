# 📋 Довідник правил цитування та матриця розкриття оболонок

Командні оболонки сімейства Bourne/POSIX (sh, dash, bash, zsh, ksh93) застосовують стандартизовані правила екранування символів та керування розкриттями. Цей довідник містить формальні специфікації синтаксичних механізмів цитування, таблиці проникності фаз розкриття, правила обробки спеціальних змінних і матриці поведінки виразів у різних контекстах інтерпретації.

## 1. Скінченний автомат цитування та лексичний аналіз

Стандарт POSIX IEEE Std 1003.1 (розділ Shell Command Language, §2.2–§2.3) визначає процес синтаксичного розбору командного рядка як роботу скінченного автомата з чотирма базовими станами:
1. **Звичайний стан (Unquoted State)**: будь-який пробіл, табуляція або символ переведення рядка розглядається як роздільник токенів. Метасимволи `;`, `&`, `|`, `<`, `>`, `(`, `)` розривають потік слів і формують керуючі оператори.
2. **Стан одинарних лапок (Single-Quote State)**: активується символом `'`. Автомат ігнорує будь-які керуючі символи, знаки долара та зворотні слеші. Єдиний символ, який обробляється у цьому стані — закриваюча одинарна лапка `'`, яка повертає автомат у звичайний стан.
3. **Стан подвійних лапок (Double-Quote State)**: активується символом `"`. Автомат блокує поділ слів і глобінг, але розпізнає символи `$`, `` ` ``, `"` та `\`.
4. **Стан екранування (Escape State)**: активується зворотним слешем `\`. Наступний одиночний символ читається буквально без синтаксичної інтерпретації.

```
Схема переходів скінченного автомата розбору лапок:
┌─────────────────┐       символ '       ┌──────────────────────┐
│                 │ ───────────────────► │                      │
│ Звичайний стан  │                      │ Стан одинарних лапок │
│   (Unquoted)    │ ◄─────────────────── │   (Strong Quoting)   │
│                 │       символ '       └──────────────────────┘
└─────────────────┘
   ▲     │
   │     │ символ "
   │     ▼
┌─────────────────┐       символ \       ┌──────────────────────┐
│  Стан подвійних │ ───────────────────► │  Стан екранування    │
│  лапок (Weak)   │ ◄─────────────────── │  (1 наступний байт)  │
└─────────────────┘   наступний символ   └──────────────────────┘
```

## 2. Порівняльна матриця механізмів цитування

Механізми цитування в командних оболонках слугують для скасування спеціального значення керівних метасимволів. Вибір конкретного типу лапок визначає, які саме фази розгортання будуть застосовані до тексту всередині них, а які — повністю заблоковані.

| Механізм цитування | Синтаксис | Обробка змінних `$VAR` | Підстановка команд `$(cmd)` | Арифметика `$((expr))` | Поділ на слова (Word Splitting) | Глобінг файлів (`*`, `?`, `[]`) | Екранування зворотним слешем `\` | Примітки стандарту |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Без лапок (Unquoted)** | `text` | Виконується | Виконується | Виконується | **Активний (за IFS)** | **Активний (VFS)** | Екранує 1 наступний символ | Будь-який пробіл є роздільником слів. |
| **Подвійні лапки (Weak)** | `"text"` | Виконується | Виконується | Виконується | **Заблоковано** | **Заблоковано** | Діє лише для `$`, `"`, `` ` ``, `\`, `\n` | Стандарт POSIX.2. Зберігає пробіли та маски. |
| **Одинарні лапки (Strong)** | `'text'` | Заблоковано | Заблоковано | Заблоковано | **Заблоковано** | **Заблоковано** | Не діє (дослівний символ `\`) | Абсолютний захист. Не може містити `'`. |
| **ANSI-C лапки** | `$'text'` | Заблоковано | Заблоковано | Заблоковано | **Заблоковано** | **Заблоковано** | Інтерпретує C-ескейпи | Розширення POSIX.1-2024, Bash, Zsh, Ksh. |
| **Локалізовані лапки** | `$"text"` | Виконується | Виконується | Виконується | **Заблоковано** | **Заблоковано** | Як у подвійних лапках | GNU gettext переклад перед розкриттям. |

### Правила інтерпретації метасимволів у подвійних лапках

Подвійні лапки забезпечують селективний захист. Вони блокують розщеплення тексту на окремі аргументи за роздільниками `IFS` та перешкоджають зверненню до файлової системи через метасимволи масок, проте дозволяють інтерпретатору виконати обчислення динамічних значень.

Всередині подвійних лапок лише чотири метасимволи зберігають своє синтаксичне призначення:
1. `$` — ініціює розгортання параметрів (`$VAR`), підстановку команд (`$(...)`) або арифметику (`$((...))`).
2. `` ` `` — ініціює застарілу підстановку команд.
3. `"` — позначає закінчення блоку слабкого цитування.
4. `\` — зберігає значення символу екранування виключно тоді, коли за ним слідує `$`, `` ` ``, `"`, `\` або символ нового рядка `\n`. Перед будь-яким іншим символом зворотний слеш залишається звичайним буквальним символом косої риски.

## 3. Фазова послідовність конвеєра розгортання

Стандарт POSIX IEEE Std 1003.1 встановлює суворий, лінійний порядок виконання фаз розкриття. Кожен етап приймає на вхід список токенів, згенерованих попереднім кроком, і виконує їхню трансформацію відповідно до правил цитування.

```
Вхідний токен
  │
  ├─► [1] Brace Expansion {a,b}          (не-POSIX: Bash, Zsh, Ksh)
  │
  ├─► [2] Tilde Expansion ~
  │
  ├─► [3] Потрійна підстановка (один прохід зліва направо):
  │     ├── Parameter Expansion $VAR
  │     ├── Command Substitution $(cmd)
  │     └── Arithmetic Expansion $((expr))
  │
  ├─► [4] Word Splitting                 (лише для підстановок фази 3 без лапок)
  │
  ├─► [5] Pathname Expansion (Globbing)  (лише для незахищених масок)
  │
  └─► [6] Quote Removal                  (видалення захисних лапок)
        │
        ▼
   Масив char *argv[] для системного виклику execve(2)
```

### Деталізація фаз розгортання

1. **Фаза фігурних дужок**: виконується виключно на основі синтаксичного аналізу без доступу до таблиці змінних або файлової системи. Вона множить токени, комбінуючи префікси та суфікси зі списками у фігурних дужках.
2. **Фаза розкриття тильди**: перевіряє початкові символи незахищених слів. Замінює `~` на значення домашнього каталогу користувача.
3. **Фаза потрійної підстановки**: сканує рядок зліва направо в один прохід. Якщо зустрічається вкладений вираз підстановки команд `$(...)`, оболонка породжує підпроцес і чекає на його завершення для підстановки результату.
4. **Фаза поділу на слова**: активується виключно для тих результатів підстановок фази 3, які перебували поза подвійними лапками. Оболонка сканує текст і розриває його на незалежні токени за роздільниками зі змінної `IFS`.
5. **Фаза розгортання імен файлів**: кожен токен, отриманий після фази поділу на слова, перевіряється на наявність незахищених символів `*`, `?` або `[...]`. Якщо маска містить збіги у файловій системі, токен замінюється впорядкованим списком знайдених файлів.
6. **Фаза видалення лапок**: з усіх сформованих токенів видаляються символи лапок (`'`, `"`) та зворотні слеші, які використовувалися для захисту символів на попередніх фазах.

## 4. Алгоритм роботи Word Splitting та правила змінної IFS

Змінна `IFS` (*Internal Field Separator*) визначає правила розбиття неогорнутих у подвійні лапки підстановок на слова. Її символи поділяються на дві категорії з принципово різною поведінкою:

1. **Білі символи IFS (IFS Whitespace)**: стандартний пробіл, табуляція та символ переведення рядка (`IFS=$' \t\n'`).
   - Будь-яка кількість послідовних білих символів на початку або в кінці розкритого значення повністю ігнорується (не створює порожніх аргументів).
   - Будь-яка послідовність з одного або кількох білих символів всередині значення розглядається як один роздільник слів.
2. **Небілі символи IFS (Non-whitespace Characters)**: будь-які інші символи, призначені користувачем (наприклад `IFS=":"` для файлу `/etc/passwd` або `IFS=","` для CSV).
   - Кожен небілий символ ділить слово рівно один раз.
   - Дві послідовні коми чи двокрапки `::` породжують між собою явний порожній аргумент (`argv[i] = ""`).
   - Білі символи навколо небілого роздільника ігноруються, якщо вони також присутні в `IFS`.

```bash
# Приклад обробки небілого IFS:
IFS=":"
DATA="root::0:System Admin:"
set -- $DATA
# $1="root", $2="", $3="0", $4="System Admin", $5="" (порожній хвіст)
```

## 5. Таблиця спеціальних позиційних і системних змінних

Спеціальні параметри оболонки надають доступ до контексту виконання процесу, списку переданих аргументів та системних статусів.

| Змінна | Призначення | Поведінка без лапок | Поведінка у подвійних лапках |
| :--- | :--- | :--- | :--- |
| **`$*`** | Усі позиційні параметри | Розбивається на слова за роздільниками `IFS` після підстановки. | Склеюється в **рівно один аргумент**: `"$1c$2c$3"` (де `c` — перший байт `IFS`). |
| **`$@`** | Усі позиційні параметри | Розбивається на слова за роздільниками `IFS` після підстановки. | Розгортається у **список окремих аргументів**: `"$1" "$2" "$3"...`. Межі збережено. |
| **`$#`** | Кількість позиційних параметрів | Ціле число десяткового формату (довжина масиву аргументів). | Розгортається в число як рядок. |
| **`$?`** | Код виходу попередньої команди | 0 при успіху, 1–255 при помилці (128+N при смерті від сигналу N). | Розгортається в число як рядок. |
| **`$$`** | PID поточного процесу оболонки | Ідентифікатор процесу (не змінюється у підкомандах subshell). | Розгортається в число як рядок. |
| **`$!`** | PID останнього фонового процесу | Ідентифікатор процесу, запущеного з суфіксом `&`. | Порожній рядок, якщо фонових процесів не було. |
| **`$-`** | Поточні прапорці оболонки | Рядок активованих опцій (наприклад `himBHs` або `errexit`). | Рядок прапорців. |
| **`$0`** | Ім'я оболонки або шлях до скрипту | Назва бінарного файлу або шлях до виконуваного файлу скрипту. | Рядок імені. |
| **`$_`** | Останній аргумент попередньої команди | Останній токен перед виконанням команди. | Рядок аргументу. |

### Семантика "$@" проти "$*"

Конструкція `"$@"` є фундаментальним механізмом передачі аргументів між функціями та скриптами. Вона гарантує збереження кількості елементів і цілісності аргументів, що містять пробіли, символи табуляції або переведення рядків. На відміну від неї, `"$*"` виконує деструктивне злиття масиву в єдиний монолітний рядок, де роздільником виступає перший символ змінної `IFS` (якщо `IFS` порожній, параметри зливаються без проміжків).

## 6. Модифікатори розгортання параметрів (POSIX і розширення)

Стандарт POSIX визначає набір синтаксичних модифікаторів для перевірки наявності змінних, встановлення резервних значень та маніпуляцій з рядками без виклику зовнішніх утиліт на кшталт `sed` чи `awk`.

### Базові умовні модифікатори POSIX

| Модифікатор | Умова застосування | Результат підстановки | Вплив на змінну |
| :--- | :--- | :--- | :--- |
| **`${VAR:-word}`** | `VAR` не встановлено або порожнє | Підставляється `word` | `VAR` не змінюється |
| **`${VAR-word}`** | `VAR` не встановлено (unset) | Підставляється `word` | `VAR` не змінюється |
| **`${VAR:=word}`** | `VAR` не встановлено або порожнє | Підставляється `word` | `VAR` присвоюється `word` |
| **`${VAR=word}`** | `VAR` не встановлено (unset) | Підставляється `word` | `VAR` присвоюється `word` |
| **`${VAR:?message}`** | `VAR` не встановлено або порожнє | Виводить `message` у `stderr` | Перериває виконання скрипту |
| **`${VAR?message}`** | `VAR` не встановлено (unset) | Виводить `message` у `stderr` | Перериває виконання скрипту |
| **`${VAR:+word}`** | `VAR` встановлено і не порожнє | Підставляється `word` | Якщо порожнє — повертає порожній рядок |
| **`${VAR+word}`** | `VAR` встановлено (set) | Підставляється `word` | Якщо unset — повертає порожній рядок |

### Модифікатори видалення префіксів і суфіксів за масками (POSIX)

Обрізання рядків виконується на основі зіставлення масок глобінгу:
- Символ `#` вказує на видалення префікса з початку рядка.
- Символ `%` вказує на видалення суфікса з кінця рядка.
- Одинарний символ (`#` або `%`) виконує нежадібне зіставлення (найкоротший збіг).
- Подвійний символ (`##` або `%%`) виконує жадібне зіставлення (найдовший збіг).

| Модифікатор | Опис дії | Приклад для `F="/var/log/nginx/access.log"` | Результат |
| :--- | :--- | :--- | :--- |
| **`${VAR#pattern}`** | Видаляє найкоротший збіг `pattern` з початку рядка | `${F#*/}` | `var/log/nginx/access.log` |
| **`${VAR##pattern}`** | Видаляє найдовший збіг `pattern` з початку рядка (basename) | `${F##*/}` | `access.log` |
| **`${VAR%pattern}`** | Видаляє найкоротший збіг `pattern` з кінця рядка (extension) | `${F%.*}` | `/var/log/nginx/access` |
| **`${VAR%%pattern}`** | Видаляє найдовший збіг `pattern` з кінця рядка | `${F%%/*}` | `""` (порожній рядок) |
| **`${#VAR}`** | Довжина рядка у символах (байтах) | `${#F}` | `29` |

### Розширені модифікатори рядків (Bash 4.0+, Zsh)

Сучасні оболонки надають розширені можливості трансформації рядків:

| Модифікатор | Опис дії | Приклад | Результат |
| :--- | :--- | :--- | :--- |
| **`${VAR:offset:len}`** | Зріз рядка від позиції `offset` довжиною `len` | `S="abcdef"; echo "${S:2:3}"` | `cde` |
| **`${VAR/pattern/rep}`** | Заміна першого входження `pattern` на `rep` | `S="a_b_c"; echo "${S/_/-}"` | `a-b_c` |
| **`${VAR//pattern/rep}`** | Заміна всіх входжень `pattern` на `rep` | `S="a_b_c"; echo "${S//_/-}"` | `a-b-c` |
| **`${VAR/#pattern/rep}`** | Заміна `pattern` лише на початку рядка | `S="prefix_val"; echo "${S/#prefix_/}"` | `val` |
| **`${VAR/%pattern/rep}`** | Заміна `pattern` лише в кінці рядка | `S="val_suffix"; echo "${S/%_suffix/}"` | `val` |
| **`${VAR^^}`** | Переведення всіх символів у верхній регістр | `S="test"; echo "${S^^}"` | `TEST` |
| **`${VAR,,}`** | Переведення всіх символів у нижній регістр | `S="TEST"; echo "${S,,}"` | `test` |

## 7. Контексти інтерпретації та правила розкриття

Поведінка лапок і фаз розкриття істотно варіюється залежно від синтаксичного контексту мови оболонки. Знання цих відмінностей дозволяє уникати зайвого екранування там, де воно є надлишковим, і вчасно застосовувати захист у вразливих конструкціях.

| Контекст | Word Splitting | Globbing | Parameter Expansion | Приклад коректного використання |
| :--- | :--- | :--- | :--- | :--- |
| **Стандартна команда** | Так (якщо без лапок) | Так (якщо без лапок) | Так | `ls -l "$FILE"` |
| **Присвоєння змінної** (`VAR=...`) | **Ні** (лапки не обов'язкові) | **Ні** (до знака `:`) | Так | `BACKUP=$ORIGINAL` |
| **Класичний тест** `[ ... ]` / `test` | **Так** (вимагає лапок!) | **Так** (вимагає лапок!) | Так | `[ "$VAR" = "ok" ]` |
| **Розширений тест** `[[ ... ]]` | **Ні** (лапки не потрібні для слів) | Тільки для правої частини `==` | Так | `[[ $VAR == *.log ]]` |
| **Арифметичний блок** `(( ... ))` | **Ні** | **Ні** | Так (і без знака `$`) | `(( count += 1 ))` |
| **Конструкція case** `case $V in` | **Ні** для селектора | Тільки у шаблонах `pattern)` | Так | `case $VAR in "*.txt") ... ;;` |
| **Here-Document** `<<EOF` | **Ні** | **Ні** | Так (якщо EOF без лапок) | `cat <<EOF\n$VAR\nEOF` |
| **Here-Document** `<<'EOF'` | **Ні** | **Ні** | **Ні (дослівний текст)** | `cat <<'EOF'\n$VAR\nEOF` |

### Граматичні особливості контекстів

- **Контекст присвоєння (`VAR=$VALUE`)**: синтаксичний аналізатор розпізнає присвоєння як єдиний токен. Поділ на слова тут вимкнено за стандартом POSIX. Проте подвійні лапки необхідні, якщо значення формується з кількох фрагментів або містить пробіли в буквальному тексті.
- **Класичний тест `[`**: оскільки `[` є звичайною зовнішньою командою або вбудованою функцією, її аргументи проходять через повний конвеєр розгортання, включно з фазою Word Splitting. Будь-яка змінна всередині `[` зобов'язана бути огорнута в подвійні лапки.
- **Розширений тест `[[ ... ]]`**: є вбудованою синтаксичною конструкцією мови Bash/Zsh. Оболонка не виконує поділ на слова для змінних всередині `[[`. Права частина оператора `==` або `!=` розглядається як шаблон глобінгу, якщо вона не взята в лапки. Якщо ж праву частину взято в лапки `[[ $VAR == "$PATTERN" ]]`, зіставлення виконується як точний посимвольний збіг рядків.
- **Блок Here-Document**: цитування обмежувального маркера (`<<'EOF'` або `<<"EOF"`) вимикає всі підстановки змінних, команд та арифметики у всьому тілі переданого тексту, перетворюючи його на чистий літерал.

## 8. Таблиця ESC-послідовностей ANSI-C (`$'...'`)

Синтаксис цитування `$'...'` стандартизовано в POSIX.1-2024 (Issue 8). Він замінює керуючі послідовності відповідними байтовими значеннями ще на етапі лексичного розбору команди.

| Послідовність | Назва символу | Код ASCII (Hex / Dec) | Опис та застосування |
| :--- | :--- | :--- | :--- |
| **`\a`** | Alert (Bell) | `0x07` (7) | Звуковий сигнал або візуальний дзвінок термінала. |
| **`\b`** | Backspace | `0x08` (8) | Повернення курсора на одну позицію назад. |
| **`\e`** або **`\E`** | Escape | `0x1B` (27) | Символ ESC для генерації кольорових ANSI-послідовностей. |
| **`\f`** | Form Feed | `0x0C` (12) | Перехід на нову сторінку друку. |
| **`\n`** | Line Feed (LF) | `0x0A` (10) | Стандартний символ переведення рядка Unix. |
| **`\r`** | Carriage Return (CR) | `0x0D` (13) | Повернення каретки на початок поточного рядка. |
| **`\t`** | Horizontal Tab | `0x09` (9) | Горизонтальна табуляція. |
| **`\v`** | Vertical Tab | `0x0B` (11) | Вертикальна табуляція. |
| **`\\`** | Backslash | `0x5C` (92) | Буквальний зворотний слеш. |
| **`\'`** | Single Quote | `0x27` (39) | Буквальна одинарна лапка (апостроф). |
| **`\"`** | Double Quote | `0x22` (34) | Буквальна подвійна лапка. |
| **`\0NNN`** | Octal byte | `0x00..0xFF` | Байт із вісімковим значенням `NNN` (1–3 цифри). |
| **`\xHH`** | Hexadecimal byte | `0x00..0xFF` | Байт із шістнадцятковим значенням `HH` (1–2 цифри). |
| **`\uHHHH`** | Unicode code point | UTF-8 | 16-бітний символ Unicode (наприклад `\u0444` — «ф»). |
| **`\UHHHHHHHH`** | Unicode code point | UTF-8 | 32-бітний символ Unicode (наприклад `\U0001F4C4` — 📄). |

## 9. Опції оболонки для керування розкриттям (Shell Options)

Оболонка надає набір прапорців середовища, які дозволяють глобально змінювати правила розкриття для підвищення безпеки або налагодження:

| Опція (set) | Опція (shopt) | Призначення та вплив на конвеєр розкриття |
| :--- | :--- | :--- |
| **`set -f`** або **`set -o noglob`** | — | **Повністю вимикає фазу 5 (Globbing)**. Символи `*`, `?`, `[...]` ніколи не сканують файлову систему. |
| **`set -u`** або **`set -o nounset`** | — | Генерує фатальну помилку при зверненні до неоголошеної змінної на фазі 3. |
| **`set -e`** або **`set -o errexit`** | — | Негайно перериває виконання скрипту при ненульовому коді виходу будь-якої команди. |
| **`set -x`** або **`set -o xtrace`** | — | Друкує кожну команду в `stderr` після всіх фаз розкриття, але до її виклику. |
| — | **`shopt -s nullglob`** | Якщо маска глобінгу не знайшла файлів, вона розгортається в порожнє місце замість збереження маски. |
| — | **`shopt -s failglob`** | Якщо маска глобінгу не знайшла файлів, оболонка генерує помилку виконання. |
| — | **`shopt -s extglob`** | Вмикає розширені регулярні шаблони глобінгу: `?(pat)`, `*(pat)`, `+(pat)`, `@(pat)`, `!(pat)`. |
| — | **`shopt -s globstar`** | Вмикає рекурсивний глобінг каталогу через маску `**` (наприклад `**/*.c`). |
