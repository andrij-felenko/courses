# 🧮 Економічна модель атаки та межі доцільності захисту

Математичне моделювання економіки атаки дозволяє перевести концепцію «безпеки» з описового ремесла у кількісно оцінювану архітектурну дисципліну. У цій вставці виводиться фундаментальне рівняння рентабельності атаки (Attacker ROI), аналізується асиметрія витрат захисника та нападника, будується ігрово-теоретична модель Штакельберга й визначається умова економічного відлякування (Economic Disincentive Condition), за якої система стає стійкою до конкретного профілю супротивника.

Безпека системи не вимагає абсолютної незламності, оскільки абсолютний захист вимагає нескінченних ресурсів. Мета архітектора — побудувати таку структуру меж довіри та засобів контролю, за якої вартість успішного пробою перевищує потенційну вигоду нападника.

## 1. Рівняння сподіваної вартості атаки (Expected Attacker Value)

Розглянемо супротивника, який розглядає систему як об'єкт атаки з метою отримання фінансової, інформаційної або ресурсної вигоди.

Нехай:
- `V_asset` — грошова або ресурсова цінність активу, який нападник прагне здобути чи скомпрометувати (у доларах або абстрактних одиницях корисності);
- `P_success` — ймовірність успішного пробою системи за наявного рівня її захисту `S`;
- `C_attack` — сумарні витрати нападника на підготовку та проведення атаки (включно із часом, обчислювальними ресурсами, купівлею 0-day вразливостей, інфраструктурою ботнету);
- `C_penalty` — потенційні збитки нападника у разі викриття (деанонімізація, юридичне переслідування, втрата інфраструктури).

Математичне сподівання чистого прибутку нападника `E(V_attacker)` визначається як:

```
E(V_attacker)
= P_success · V_asset - (1 - P_success) · C_penalty - C_attack    [означення сподіваного виграшу мінус збитки та витрати]
```

Для більшості кіберзлочинців та автоматизованих сканерів у мережі ймовірність викриття з реальними правовими наслідками мала, тому `C_penalty ≈ 0`. Рівняння спрощується до вигляду:

```
E(V_attacker)
= P_success · V_asset - C_attack    [спрощення рівняння за умови C_penalty = 0]
```

Рентабельність інвестицій нападника (Attacker Return on Investment, ROI_attacker) записується як:

```
ROI_attacker
= E(V_attacker) / C_attack                       [означення ROI як відношення чистого прибутку до витрат]
= (P_success · V_asset - C_attack) / C_attack    [підстановка виразу E(V_attacker)]
= (P_success · V_asset) / C_attack - 1           [подільний розклад дробу: C_attack / C_attack = 1]
```

## 2. Умова економічного відлякування (Economic Disincentive Condition)

Супротивник діятиме раціонально: атака проводиться лише тоді, коли сподіваний прибуток позитивний (`ROI_attacker > 0`). Якщо `E(V_attacker) < 0`, атака стає економічно збитковою, і раціональний нападник переключається на іншу ціль.

Звідси випливає фундаментальна умова архітектурного захисту:

```
E(V_attacker) < 0                                [умова нерентабельності атаки]
⇒ P_success · V_asset - C_attack < 0             [підстановка розрахованого сподіваного прибутку]
⇒ C_attack > P_success · V_asset                 [перенесення C_attack у праву частину нерівності]
```

Якщо ймовірність успіху за умови подолання правильно спроєктованих меж довіри наближається до вимірюваного значення `P_success ≈ 1` (за умови наявності невідомої вразливості), підсумкове правило вимагає від архітектора підняття прямих витрат нападника вище цінності активу:

```
C_attack > V_asset    [гранична умова для випадку P_success = 1]
```

### Покроковий приклад розрахунку для Digital Homes

Розглянемо випадок спроби компрометації розумного дверного замка в системі Digital Homes.

**Вихідні дані:**
1. Актив (`V_asset`): Фізичний доступ до будинку або можливість масового відчинення дверей для здирництва. Оцінка корисності атаки на один будинок для масового зловмисника: `V_asset = \$1 000`.
2. Базовий захист без апаратної безпеки:
   - `C_attack_naive = \$50` (купівля дешевого Wi-Fi деавтентифікатора або підслуховування незашифрованого радиоефіру).
   - `P_success_naive = 0.9`.

Обчислимо сподівану вартість атаки для наївної системи:

```
E(V_naive)
= 0.9 · 1000 - 50      [підстановка P_success = 0.9, V_asset = 1000, C_attack = 50]
= 900 - 50             [множення 0.9 · 1000]
= 850 \$               [вирахування різниці: прибуток позитивний, ROI = 1700%]
```

3. Архітектурне посилення (впровадження mTLS з криптографічним чипом secure element у замку, валідація інваріантів та короткоживучі підписані токени):
   - Щоб подолати цей захист, нападникові потрібна фізична компрометація мікроконтролера з використанням мікроскопічного аналізу чипа (side-channel attack / fault injection) або 0-day екплойт у криптографічній бібліотеці.
   - `C_attack_secure = \$80 000` (вартість лабораторного обладнання та часу інженера-дослідника).
   - `P_success_secure = 0.05`.

Обчислимо сподівану вартість атаки для захищеної системи:

```
E(V_secure)
= 0.05 · 1000 - 80000    [підстановка P_success = 0.05, V_asset = 1000, C_attack = 80000]
= 50 - 80000             [множення 0.05 · 1000]
= -79 950 \$             [вирахування різниці: атака глибоко збиткова, ROI = -99.9%]
```

Висновок: Для профілю звичайного злочинця атака стає неможливою через економічну недоцільність.

## 3. Модель асиметрії витрат захисника та нападника

Важливим аспектом є залежність між витратами захисника `C_defense` та зростанням витрат нападника `C_attack`.

Захисник змушений закривати всі можливі шляхи атаки в системі (граничні випадки, конфігурації, межі модулів). Нехай система має `N` потенційних точок взаємодії (поверхня атаки). Якщо захист кожної точки коштує `k`, загальні витрати захисника для забезпечення базового рівня покриття складають:

```
C_defense = ∑ᵢ₌₁ᴺ kᵢ    [сумування витрат на захист усіх N точок поверхні атаки]
```

Витрати захисника для зменшення ймовірності успіху `P_success` описуються параболічною або експоненційною функцією від відносного рівня безпеки `α ∈ [0, 1)`:

```
C_defense(α) = (C₀ · α) / (1 - α)    [модель залежності витрат захисника від рівня покриття α]
```

Де:
- `C₀` — базова вартість розробки системи;
- `α` — частка закритих ризиків (наприклад, `α = 0.99` відповідає 99% закриття).

Як видно з формули, при наближенні `α → 1` (спроба досягти «абсолютної» безпеки) витрати захисника прямують до нескінченності:

```
lim_{α → 1} C_defense(α)
= lim_{α → 1} (C₀ · α) / (1 - α)     [граничний перехід при α → 1]
= ∞                                  [ділення на нуль: абсолютний захист коштує нескінченно]
```

Натомість витрати нападника `C_attack` для пробою системи з покриттям `α` зростають як:

```
C_attack(α) = C_base · (1 / (1 - α)ᵏ)    [зростання витрат нападника зі збільшенням рівня безпеки α]
```

Де `k ≥ 1` визначає ефективність архітектурних завад (стекові канарейки, ASLR, mTLS, ізоляція процесів).

## 4. Граничний аналіз оптимуму безпеки (Security Target)

Мета архітектора — знайти рівноважну точку `α*`, у якій гранична вартість додаткового захисту дорівнює граничному зменшенню очікуваних збитків від компрометації.

Визначаємо сумарну функцію вартості володіння ризиком для бізнесу `TCO_security(α)`:

```
TCO_security(α)
= C_defense(α) + P_success(α) · V_asset    [сума прямих витрат на захист та сподіваних втрат від атаки]
```

Мінімум цієї функції досягається взяттям похідної по `α` та прирівнюванням її до нуля:

```
d/dα [ TCO_security(α) ] = 0                                       [умова екстремуму сумарних витрат]
⇒ d/dα [ C_defense(α) ] + d/dα [ P_success(α) · V_asset ] = 0      [диференціювання суми двох функцій]
⇒ d/dα [ C_defense(α) ] = - V_asset · d/dα [ P_success(α) ]        [перенесення похідної втрат у праву частину]
```

Ліва частина рівняння являє собою граничні витрати на захист (Marginal Cost of Defense), а права — граничне зменшення збитків від атаки (Marginal Risk Reduction).

## 5. Графові моделі атак (Attack Tree Probabilities)

У складних розподілених системах нападник діє через послідовні або паралельні кроки. Представимо процес атаки як дерево атак (Attack Tree) з вершинами двох типів:
- **AND-вузли:** Для досягнення мети нападник мусить успішно виконати всі підкроки.
- **OR-вузли:** Нападникові достатньо використати хоча б один із доступних альтернативних шляхів.

Нехай крок `i` характеризується ймовірністю пробою `p_i` та витратами нападника `c_i`.

### А. Для AND-послідовності з `m` кроків:

```
P_success_AND = ∏ᵢ₌₁ᵐ pᵢ                                          [імовірність пробою усіх кроків ланцюга]
C_attack_AND = ∑ᵢ₌₁ᵐ cᵢ                                           [сумування витрат на кожен крок]
```

Оскільки `p_i <= 1`, перемноження ймовірностей при довгому ланцюгу оборони експоненційно зменшує підсумкову ймовірність успіху нападника:

```
lim_{m → ∞} ∏ᵢ₌₁ᵐ pᵢ = 0                                           [багатошаровий захист прямує до нульової ймовірності]
```

### Б. Для OR-галуження з `n` альтернативних вразливостей:

```
P_success_OR = 1 - ∏ⱼ₌₁ⁿ (1 - pⱼ)                                  [імовірність знаходження хоча б однієї дірки]
C_attack_OR = min(c₁, c₂, ..., cₙ)                                 [нападник обирає найдешевший шлях]
```

Звідси випливає ключове математичне правило архітектурної безпеки: **Наявність навіть одного незахищеного OR-шляху з високою ймовірністю `p_j ≈ 1` руйнує всю стійкість багатошарової системи.** 

Впровадження глибокої оборони (Defense in Depth) означає перетворення всіх потенційних OR-галужень на монолітні AND-послідовності завдяки обов'язковій перевірці на кожній межі довіри.

## 6. Ігрово-теоретична модель Штакельберга (Stackelberg Game Model)

Моделювання взаємодії захисника та нападника можна уявити як асиметричну гру Штакельберга (Leader-Follower Game), де:
- **Захисник (Leader)** першим обирає конфігурацію захисту та розстановку меж довіри `S`, витрачаючи `C_defense(S)`.
- **Нападник (Follower)** спостерігає обраний захист `S` (у межах відкритого дизайну) та обирає оптимальну стратегію атаки `A(S)`, яка максимізує його прибуток `E(V_attacker)`.

Рівновага Штакельберга досягається оптимізацією двоуровневої задачі:

```
max_{S} [ - C_defense(S) - P_success(S, A*(S)) · V_asset ]          [захисник мінімізує свої сумарні витрати]
де A*(S) = argmax_{A} [ P_success(S, A) · V_asset - C_attack(S, A) ] [нападник обирає найкращу відповідь]
```

## 7. Байєсівська оцінка загроз та розвідка супротивника

В архітектурах із високими вимогами до безпеки оцінка ймовірності атаки `P_success` оновлюється динамічно на основі спостережуваних подій за допомогою теореми Байєса.

Нехай `H_attack` — гіпотеза про те, що поточна аномальна активність на межі довіри є фазою підготовки цілеспрямованої атаки, а `E_obs` — спостережувані аномальні запити (наприклад, сканування портів або серія помилок HMAC).

Апостеріорна ймовірність `P(H_attack | E_obs)` обчислюється як:

```
P(H_attack | E_obs)
= (P(E_obs | H_attack) · P(H_attack)) / P(E_obs)                    [формула Байєса для оцінки атаки]
```

Де:
- `P(H_attack)` — апріорна ймовірність атаки для даного типу середовища;
- `P(E_obs | H_attack)` — ймовірність генерації таких аномалій супротивником;
- `P(E_obs)` — повна ймовірність спостереження таких аномалій у системі (включно із випадковими мережевими збоями або помилками легітимних користувачів).

Якщо апостеріорна ймовірність перевищує поріг `P_threshold`, архітектура автоматично активує режим підвищеного захисту (Security Circuit Breaker), знижуючи `P_success` до нуля ціною тимчасового обмеження продуктивності.

## 8. Еластичність атак та ефект дезорієнтації (Honeytokens Economics)

Математичний аналіз дезорієнтації нападника за допомогою декойних об'єктів (honeytokens / honeypots) показує штучне зростання `C_attack`.

Якщо архітектор додає в систему `K` фальшивих API-ендпоінтів або секретних ключів, які не несуть цінності (`V_honey = 0`), але вимагають від нападника аналізу та перевірки, сумарні витрати нападника зростають лінійно або квадратично:

```
C_attack_total = C_attack_real + ∑ₖ₌₁ K · c_investigate              [сумування витрат на дослідження пасток]
```

Оскільки нападник не знає заздалегідь, який ключ є справжнім, ймовірність обрати справжній актив з першої спроби падає:

```
P_choice_real = 1 / (K + 1)                                          [ймовірність влучання у справжній актив]
```

Підставляючи це значення у формулу сподіваної вартості:

```
E(V_attacker)
= (1 / (K + 1)) · P_success · V_asset - C_attack_total               [падіння сподіваного прибутку через пастки]
```

При достатньо великому `K` значення `E(V_attacker)` гарантовано стає негативним, унеможливлюючи атаки методом суцільного перебору.

### Архітектурні висновки з математичної моделі

1. Інвестувати в захист доцільно лише доти, доки кожен витрачений долар зменшує сподівані збитки від атаки більше ніж на один долар (`d(C_defense) < - d(P_success · V_asset)`).
2. Замість нескінченного збільшення витрат на один модуль (`α → 1`), архітектор зменшує цінність активу `V_asset` для окремого модуля шляхом **сегментації та ізоляції радіусу ураження** (Blast Radius Isolation).
3. Перетворення OR-галужень на AND-послідовності через перевірку на кожній межі довіри створює математичну гарантію експоненційного згасання ймовірності пробою.
4. Впровадження пасток (honeytokens) штучно зменшує ймовірність влучання `P_choice_real`, роблячи розвідку системи дорожчою за здобутий актив.
