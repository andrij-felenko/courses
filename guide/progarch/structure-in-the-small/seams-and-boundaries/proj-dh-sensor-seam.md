# ⚙️ Робочий шов у Digital Homes: тест, що доводить підміну

Означення шва легко кивнути головою й забути. Тож зробімо його руками на тому самому коді, який ми вже знаємо напам'ять, — на зварці v0. Візьмемо цикл, де давач прибитий цвяхом до тіла, **відкриємо об'єктний шов** упорскуванням давача й розетки в політику, а тоді напишемо **справжній тест**, що жене крізь цей шов підробку й доводить чорним по білому: поведінка змінилася, а жодного рядка політики ми не торкнулися. Потім — коли коду немає в наших руках зовсім — покажемо **лінк-шов** для чужої бібліотеки, яку зсередини не переписати. Усе — робочі файли, які кладуться на диск і запускаються.

## Ідея: винести давач і розетку у входи

Уся хвороба зварки v0 в одному русі: політика **сама створювала** те, від чого залежала. Рядок `t = read_sensor()` не приймав давача — він кликав конкретний глобальний драйвер, єдиний, який знав. Щоб дати політиці інше число, доводилося правити політику. Це і є «шва нема».

Ліки прості до банальності й саме тому потужні: хай політика **не створює, а приймає**. Давач і розетку передаємо їй ззовні як входи — і на тому вхідному стику народжується шов. Тіло вже не знає, чим є `sensor`; воно кличе `sensor.read()` за спільним інтерфейсом, а чим той інтерфейс наповнити, вирішує хтось інший і в іншому місці. Це та сама [інверсія залежностей](book:programming/dependency-inversion) у дії: замість «політика тягнеться по конкретний давач» стрілка розвертається — «політика оголошує, якого давача потребує (інтерфейс), а конкретного їй подають». Принцип каже, *що* робити; шов — це те, що ти за нього *отримуєш*: готову точку підміни.

## Крок 1 — політика зі швом

Ось політика, витягнута в окремий модуль. Дивитися тут особливо нема на що — і це найкраща новина. Уся хитрість у тому, чого код **не** робить: не створює давача, не знає його марки, не здогадується, справжній він чи підроблений.

:::tabs
```py
# thermostat.py — політика керування теплом із відкритим об'єктним швом.
# Тіло decide НЕ знає, звідки береться число й куди йде команда.
from typing import Protocol


class Sensor(Protocol):
    def read(self) -> float: ...      # контракт: віддати °C; не кидати виняток крізь межу


class Heater(Protocol):
    def on(self) -> None: ...
    def off(self) -> None: ...


def decide(sensor: Sensor, heater: Heater, threshold: float) -> None:
    t = sensor.read()                 # ← шов: чим є sensor, вирішують ЗЗОВНІ
    if t < threshold:
        heater.on()
    else:
        heater.off()
```
```ts
// thermostat.ts — політика з відкритим об'єктним швом.
export interface Sensor { read(): number; }              // контракт: °C, без винятку крізь межу
export interface Heater { on(): void; off(): void; }

export function decide(sensor: Sensor, heater: Heater, threshold: number): void {
  const t = sensor.read();                                // ← шов: чим є sensor, вирішують ЗЗОВНІ
  if (t < threshold) heater.on();
  else heater.off();
}
```
:::

`Sensor` і `Heater` — це **не класи, а обіцянки**: будь-хто, кого встромлять у шов, мусить уміти `read()` і повертати число в градусах. Це той самий [контракт на межі](book:programming/design-by-contract) — тонка домовленість, за яку тримаються обидві сторони, не знаючи одна одної в обличчя. У Python його стережуть структурно (`Protocol` — «качина типізація» з перевіркою типів: підійде будь-що з потрібними методами), у TypeScript — `interface`. Механіка різна, суть одна: політика залежить від форми, а не від конкретного заліза.

## Крок 2 — драйвери справжнього заліза й точка ввімкнення

Тепер напишемо те, що в продакшені під'єднають до шва: справжні драйвери. Щоб файл був робочим без дроту, тіла драйверів, як і у v0, мокують фізику кімнати — вона холоне сама, гріється від розетки. У живому домі ці ж класи говорили б із DS18B20 та Wi-Fi-розеткою; шва це не обходить — він приймає будь-що, що дотримало контракту.

І найважливіший файл усієї історії — `main.py`. Це **точка ввімкнення**: єдине місце, де вимовлено вголос, *що саме* під'єднано до шва цього разу. Вимикач стоїть тут, зовні політики, — і саме тому політику можна лишити недоторканою.

:::tabs
```py
# drivers.py — справжні драйвери. Тіла мокують фізику; у продакшені — залізо.
import random


class Room:                            # прихована «фізика»: у реальності це саме повітря кімнати
    def __init__(self, temp: float = 18.0) -> None:
        self.temp = temp
        self.heating = False


class RealSensor:                      # дотримує контракт Sensor структурно
    def __init__(self, room: Room) -> None:
        self._room = room
    def read(self) -> float:
        self._room.temp += (0.4 if self._room.heating else -0.2) + random.uniform(-0.05, 0.05)
        return round(self._room.temp, 1)          # °C дробом — таким є контракт


class RealHeater:
    def __init__(self, room: Room) -> None:
        self._room = room
    def on(self) -> None:
        if not self._room.heating:                # ідемпотентно: не смикати реле дарма
            self._room.heating = True
            print("[розетка] обігрівач УВІМКНЕНО")
    def off(self) -> None:
        if self._room.heating:
            self._room.heating = False
            print("[розетка] обігрівач вимкнено")


# main.py — точка ввімкнення. САМЕ ТУТ вирішено, що під'єднати до шва.
from time import sleep

def run() -> None:
    room = Room(temp=18.0)
    sensor, heater = RealSensor(room), RealHeater(room)   # ← вимикач стоїть ТУТ
    while True:
        decide(sensor, heater, threshold=20.0)            # політику не чіпаємо
        sleep(30)

if __name__ == "__main__":
    run()
```
```ts
// drivers.ts — справжні драйвери. Тіла мокують фізику; у продакшені — залізо.
import type { Sensor, Heater } from "./thermostat.ts";

export class Room {
  constructor(public temp = 18.0, public heating = false) {}
}

export class RealSensor implements Sensor {
  constructor(private readonly room: Room) {}
  read(): number {
    this.room.temp += (this.room.heating ? 0.4 : -0.2) + (Math.random() - 0.5) * 0.1;
    return Math.round(this.room.temp * 10) / 10;          // °C дробом — контракт
  }
}

export class RealHeater implements Heater {
  constructor(private readonly room: Room) {}
  on(): void {
    if (!this.room.heating) {                             // ідемпотентно
      this.room.heating = true;
      console.log("[розетка] обігрівач УВІМКНЕНО");
    }
  }
  off(): void {
    if (this.room.heating) {
      this.room.heating = false;
      console.log("[розетка] обігрівач вимкнено");
    }
  }
}

// main.ts — точка ввімкнення: тут вирішено, що під'єднати до шва.
import { decide } from "./thermostat.ts";
const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

async function run(): Promise<void> {
  const room = new Room(18.0);
  const sensor = new RealSensor(room), heater = new RealHeater(room);   // ← вимикач ТУТ
  while (true) {
    decide(sensor, heater, 20.0);                                        // політику не чіпаємо
    await sleep(30_000);
  }
}
run();
```
:::

Запусти `python main.py` — і кімната задихає, як у v0: холоне до порога, гріється, вимикається. Ззовні поведінка та сама. Але всередині сталося головне: рядок `decide(sensor, heater, ...)` — це шов з увімкненим у нього справжнім залізом, і вимикач цей стоїть **у `run()`, а не в `decide`**. Запам'ятай це розташування — у пастках побачимо, як його підступно тягне назад усередину.

## Крок 3 — тест, що жене крізь шов підробку

Тепер — заради чого все й затівалося. Ми хочемо перевірити політику, **жодного разу не запустивши ні справжнього давача, ні розетки**: у тесті не буває ані кімнати, що холоне три хвилини, ані Wi-Fi, що відпадає. Тож у той самий шов, куди `main` встромляв залізо, встромимо дві підробки.

Перша — **давач-підробка (fake)**: замість фізики він просто віддає заготовлене число, яке ми йому наказали. Друга — **розетка-шпигун (spy)**: вона нічого не гріє, лише записує в список, що їй наказували. Обидві — [дублери в тестах](guide:progarch/test-doubles-when); зараз досить знати, що дублер — це те, що вставляють у шов замість справжнього, а їхню механіку й точні імена (stub, fake, spy, mock) курс розкладе по поличках згодом. Головне вже видно тут: підробка стає можливою **тільки тому, що шов є**.

:::tabs
```py
# test_thermostat.py — женемо крізь шов підробки. decide НЕ редагуємо.
from thermostat import decide


class FakeSensor:
    """Давач-підробка: завжди віддає заготовлений показник."""
    def __init__(self, reads: float) -> None:
        self._reads = reads
    def read(self) -> float:
        return self._reads


class SpyHeater:
    """Розетка-шпигун: нічого не гріє, лише записує, що їй наказали."""
    def __init__(self) -> None:
        self.calls: list[str] = []
    def on(self) -> None:
        self.calls.append("on")
    def off(self) -> None:
        self.calls.append("off")


def test_cold_turns_on():
    spy = SpyHeater()
    decide(FakeSensor(reads=19.0), spy, threshold=20.0)   # 19.0 < 20.0 → холодно
    assert spy.calls == ["on"]


def test_warm_turns_off():
    spy = SpyHeater()
    decide(FakeSensor(reads=21.0), spy, threshold=20.0)   # 21.0 ≥ 20.0 → тепло
    assert spy.calls == ["off"]


def test_boundary_is_off():
    spy = SpyHeater()
    decide(FakeSensor(reads=20.0), spy, threshold=20.0)   # рівно поріг: 20.0 < 20.0 хибно
    assert spy.calls == ["off"]                            # «<» строгий — на порозі НЕ гріємо
```
```ts
// thermostat.test.ts — женемо крізь шов підробки. decide НЕ редагуємо.
import { test } from "node:test";
import assert from "node:assert/strict";
import { decide, type Sensor, type Heater } from "./thermostat.ts";

class FakeSensor implements Sensor {
  constructor(private readonly reads: number) {}
  read(): number { return this.reads; }                  // завжди заготовлене
}

class SpyHeater implements Heater {
  readonly calls: string[] = [];
  on(): void { this.calls.push("on"); }
  off(): void { this.calls.push("off"); }
}

test("холодно → вмикаємо", () => {
  const spy = new SpyHeater();
  decide(new FakeSensor(19.0), spy, 20.0);               // 19.0 < 20.0
  assert.deepEqual(spy.calls, ["on"]);
});

test("тепло → вимикаємо", () => {
  const spy = new SpyHeater();
  decide(new FakeSensor(21.0), spy, 20.0);               // 21.0 ≥ 20.0
  assert.deepEqual(spy.calls, ["off"]);
});

test("рівно поріг → НЕ гріємо", () => {
  const spy = new SpyHeater();
  decide(new FakeSensor(20.0), spy, 20.0);               // 20.0 < 20.0 хибно
  assert.deepEqual(spy.calls, ["off"]);                  // «<» строгий
});
```
:::

Запусти — `pytest -q` або `node --test` — і побачиш три зелені галочки. Спинися й придивися, що саме вони доводять. У `test_cold_turns_on` ми згодували політиці 19.0 — і шпигун засвідчив: політика наказала `on`. У `test_warm_turns_off` згодували 21.0 — шпигун засвідчив `off`. **Та сама функція `decide`, не змінена ні на символ, повелася по-різному — бо ми підмінили те, що проходить крізь шов.** Ось воно, означення на дотик: змінити поведінку вдалося, не редагуючи там, де вона живе.

І третій тест — тихий, але найцінніший. Він пришпилює **межу контракту**: рівно на порозі, коли `20.0 < 20.0` хибне, гріти не треба. У зварці v0 таку перевірку годі було й уявити — щоб побачити, як політика поводиться на порозі, довелося б реально виморозити кімнату рівно до 20.0, а це неможливо. Шов зробив недосяжне тривіальним: заготовив показник — і межа перевірена за мілісекунду.

> 🔧 **Навіщо це.** Три зелені тести коштували нам рівно нуль правок робочого коду — і в цьому вся економіка шва. Без нього єдиний спосіб перевірити «що станеться на 19 градусах» — довести кімнату до 19 градусів, тобто запустити пів системи й почекати. Зі швом перевірка коштує один рядок конструктора підробки. Тому, зустрівши код, який «неможливо протестувати», досвідчений розробник не пише героїчних інтеграційних риштувань — він шукає очима вхід, на якому вже є (або можна відкрити) шов, і годує крізь нього передбачуване. Тестопридатність — це не властивість коду сама по собі; це наявність швів у потрібних місцях.

## Крок 4 — коли коду немає в руках: лінк-шов

Об'єктний шов ми відкрили, бо політика була наша — досить було додати параметр. А тепер злам: уяви, що давач ховається в **чужій закритій бібліотеці**. Вендор дав тобі заголовок `sensor.h` і скомпільований `libsensor.so`, а вихідного коду не дав. Твій `hub.c` кличе `sensor_read()` **прямим викликом** — немає куди впорснути об'єкт, бо немає й параметра-інтерфейса, є гола функція, вшита в місце виклику. Об'єктний шов недоступний. Але шов усе одно є — глибше, на рівні **лінкування**.

Тут доречна саме C: `LD_PRELOAD` і підміна об'єктного файла — це механізми системного компонувальника, а не мовна абстракція, тож показувати їх якоюсь «зручнішою» мовою було б брехнею про те, як воно працює насправді. Ось твій бік — його ми не редагуємо:

```c
/* sensor.h — заголовок чужої бібліотеки (єдине, що ти маєш) */
double sensor_read(void);        /* повертає °C; тіло — у закритій libsensor.so */

/* hub.c — твій код. Давач кличеться НАПРЯМУ, без параметра-інтерфейса. */
#include <stdio.h>
#include "sensor.h"

int main(void) {
    double t = sensor_read();                    /* ← прямий виклик у чужу бібліотеку */
    printf("%.1f°C → %s\n", t, t < 20.0 ? "гріти" : "не гріти");
    return 0;
}
```

Збираєш і запускаєш із справжньою бібліотекою вендора — воно читає реальний давач:

```sh
cc hub.c -L. -lsensor -o hub && ./hub        # → напр. 21.4°C → не гріти
```

Тепер відкриймо шов, не торкнувшись ані `hub.c`, ані `libsensor.so`. Пишемо власну підробку **тієї самої функції** в окремому файлі:

```c
/* fake_sensor.c — наша підробка тієї самої функції sensor_read */
double sensor_read(void) {
    return 19.0;                 /* заготовлений показник для тесту */
}
```

І далі — два роди лінк-шва, за тим, на якому щаблі підсовуємо підробку.

**Форма перша — підміна об'єктного файла при збірці.** Просто злінкуй у бінарник свій `fake_sensor.c` замість вендорської бібліотеки. Точка ввімкнення — сам рядок збірки:

```sh
cc hub.c fake_sensor.c -o hub_test && ./hub_test     # → 19.0°C → гріти
```

Той самий `hub.c`, той самий заголовок — інший об'єкт на вході компонувальника, інша поведінка на виході. Це найпортативніша форма: працює й тоді, коли все злінковано статично.

**Форма друга — `LD_PRELOAD`, підміна при завантаженні.** Тут ти не перезбираєш `hub` узагалі. Компілюєш підробку в окремий динамічний об'єкт і кажеш завантажувачу підвантажити його **першим**:

```sh
cc -shared -fPIC fake_sensor.c -o fake_sensor.so
LD_PRELOAD=./fake_sensor.so ./hub                    # → 19.0°C → гріти
```

Механіку варто побачити ясно, бо в ній уся сіль. Коли `hub` дійде до `sensor_read()`, символ шукає **динамічний завантажувач** — і бере перше знайдене визначення. `LD_PRELOAD` ставить твій `fake_sensor.so` попереду за вендорський, тож завантажувач натрапляє на твою `sensor_read` раніше, ніж на справжню, і зупиняється. Тіло вендорської функції не виконується взагалі — його навіть не питали.

*Точка ввімкнення лінк-шва — змінна оточення `LD_PRELOAD`, що стоїть цілком поза кодом `hub`: жодного рядка твого чи вендорського не змінено, а поведінку підмінено.*

Це і є лінк-шов у чистому вигляді: поведінку змінено, вихідний код обох сторін недоторканий, а вимикач — рядок збірки або змінна оточення — стоїть зовні. `LD_PRELOAD` — механізм Linux; на macOS йому відповідає `DYLD_INSERT_LIBRARIES` (тепер сильно обмежений захистом цілісності системи та підписом коду), а Windows прямого аналога не має — там ідуть іншим шляхом (перехоплення таблиці імпорту чи та сама підміна об'єкта при збірці).

> 🔧 **Навіщо це.** Лінк-шов — інструмент останнього рубежу, коли код не твій і всередину не дотягтися. Ціна за це — грубість (нижче в пастках побачиш, чому). Тому послідовність вибору саме така: якщо код у твоїх руках — відкривай об'єктний шов параметром, як ми зробили з `decide`; аж коли джерела немає — берися за лінк. Не навпаки: тягнутися по `LD_PRELOAD` там, де досить було б додати аргумент функції, — це бити молотком по гвинтику.

У керованих стеках (Node, Python-пакети) прямого `LD_PRELOAD` для чистого коду немає, але лінк-шов існує на рівні **розв'язання модулів**. У Node це, наприклад, умовні підшляхи в `package.json`: той самий імпорт `#sensor` розв'язується в різні файли залежно від умови збірки, а сам код виклику не змінюється:

```json
// package.json — точка ввімкнення тепер тут, у конфізі розв'язання
{
  "imports": {
    "#sensor": { "test": "./sensor.fake.js", "default": "./sensor.real.js" }
  }
}
```

Код пише `import { sensorRead } from "#sensor";`, а `node --conditions=test` підсуне підробку. Це той самий лінк-шов: підміна не в коді, а в тому, *що* компонувальник (тут — розв'язувач модулів) підставить під незмінну назву.

## Складність і пастки

Шов дає силу — і рівно тому має гострі краї. Кожна пастка нижче — це спосіб, яким шов тихо бреше, що все гаразд.

**Підробка, чесніша за реальність.** Це найпідступніша й найчастіша. Наш `FakeSensor` повертає охайне `19.0` — дробове число градусів. Але багато реальних давачів так не роблять: класичний 1-Wire DS18B20, як його віддає Linux через `w1_therm`, повертає температуру не дробом, а **цілими мілі-градусами** — рядок `t=19000` означає 19.000 °C ([документація ядра підтверджує: значення після `t=` — мілі-градуси, ділити на 1000](https://www.kernel.org/doc/html/v5.5/w1/slaves/w1_therm.html)). І ось що з цього виходить:

**Умова.** Тест зелений: підробка віддає `19.0`, `decide` вмикає грілку. Продакшен ставить справжній DS18B20, чий чесний драйвер віддає `19000`.
```
поріг = 20.0
підробка:   19.0   < 20.0  →  True   →  heater.on()    ← тест доводить «гріємо»
залізо:    19000   < 20.0  →  False  →  heater.off()   ← кімната НЕ гріється НІКОЛИ
```
**Висновок.** Тести зелені, дім вимерзає. Шов пропустив підробку, яка дотримала контракту («°C дробом»), тоді як справжній драйвер його порушив — і жоден із трьох тестів цього не спіймав, бо перевіряли ми проти брехливо-охайної підробки. Це той самий баг, що ламав вітальню у v0, тільки тепер він ховається **за зеленим тестом** — а це гірше, ніж без тесту, бо дає фальшивий спокій. Мораль: **шов чесний рівно настільки, наскільки чесний контракт, який ти на нього повісив.** Підробка мусить дотримувати той самий контракт, що й залізо, — а сам контракт («°C дробом, не мілі-градусами») варто прибити хоча б одним тестом проти справжнього драйвера чи вірного емулятора.

**Дірявий об'єктний шов: тип — це не весь контракт.** `interface Sensor { read(): number }` пришпилює *форму* — «повертає число», — але мовчить про *поведінку*: у яких одиницях число, чи може `read()` кинути виняток (погана контрольна сума!), чи блокує він на секунду, чи здатен повернути `NaN`. Наша підробка відповідає миттєво, ніколи не кидає, завжди свіжа — тож політику **жодного разу не перевірено** проти таймауту, винятку чи `NaN`, а це те, що справжнє залізо робить першим. Шов «протікає»: найтвердіші частини реальності просочуються повз нього неперевіреними. Вірна підробка мусить уміти й збрехати правдоподібно — кинути на третьому виклику, раз повернути `NaN`, — інакше зелений тест означає лише «на ідеальному залізі працює».

**Шпигун, що перевіряє забагато.** Ми звіряли `spy.calls == ["on"]` — увесь список викликів. Для одноразового `decide` це точно. Але спокуса — пришпилювати повний список і там, де важить лиш один факт. Уяви, що завтра політика з міркувань безпеки на старті кличе `off()` раз, перш ніж вирішувати: усі тести з `== ["on"]` попадають, хоча нічого не зламано. Шпигун, від якого вимагають дослівний протокол, робить тести крихкими — вони ловлять не баги, а будь-яку зміну *як саме* діємо. Правило: звіряй **вирішальний факт** (`"on" in spy.calls`, останній виклик), а весь ланцюг — лише коли сам ланцюг і є контрактом.

**Точка ввімкнення, що заповзла всередину.** Найкоротший шлях знівечити щойно відкритий шов — сховати вимикач у самій політиці:
```py
def decide(heater, threshold):
    sensor = FakeSensor(19.0) if os.getenv("TESTING") else RealSensor(room)  # ← отрута
    ...
```
Виглядає зручно, а насправді шва більше немає. Згадай перевірку: щоб перемкнути поведінку, ти тепер мусиш редагувати **саме `decide`** — отже, за означенням, це вже не шов. Гірше: у продакшен-код заповз тестовий мотлох, і одного дня забутий `TESTING=1` в оточенні тихо пустить у бойовий дім підроблений давач. Вимикач мусить лишатися зовні — у `main()`, у рядку збірки, у змінній оточення, — завжди поза кодом, який шов береже.

**`LD_PRELOAD` — груба сокира.** Він перехоплює лише символи, що розв'язуються **динамічно й не вбудовані**: `static`-функцію, виклик, який компілятор вбудував (inline/LTO), чи символ зі статично злінкованого архіву він не візьме — і ти годину гадатимеш, чому підробка «не спрацювала». Він **глобальний на весь процес**: перехопиш `malloc` — і ловитимеш чужі виклики теж, не лише свої. І він **прив'язаний до платформи** — Linux-glibc; на macOS `DYLD_INSERT_LIBRARIES` обрізаний захистом системи, на Windows його нема зовсім. Усе це — плата за те, що ти ліземо в код, якого не писав. Коли код твій, об'єктний шов дає те саме дешевше, точніше й переносно; лінк-шов лишай на випадок, коли іншого шва просто немає.

Зведімо. Об'єктний шов ми відкрили одним параметром і купили за нього тест, який доводить підміну; лінк-шов дістав ту саму підміну там, куди руки не дотягуються, — ціною грубості. Обидва проходять ту саму перевірку — «чи можу я змінити поведінку, не редагуючи тут?» — і обидва чесні рівно настільки, наскільки чесна підробка, яку крізь них пускаєш. Шов дає точку зміни; що саме крізь неї пройде — і чи не збреше воно про контракт — лишається на тобі.
