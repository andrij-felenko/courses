# ⚙️ Робочий v1 — той самий дім за швами, і чотири правки, що вже не розповзаються

Кістяк `run`, який ми щойно розглянули, чесно показує форму: кожна стрілка `read → decide → act` тепер перетинає названий шов. Але кістяк легко прийняти за картинку зі слайда — гарну доти, доки її не спробуєш запустити. Тож зберімо **справжній** v1: файл, який кладеться на диск, стартує з `python hub.py` і жене ту саму кімнату — холоне, доходить до порога, вмикає обігрівач, гріється, вимикає, — тільки тепер усе тіло розсічене на чотири шматки за швами. Ані дроту, ані давача за десять доларів, ані розетки: замість заліза, як і в [нульовій версії](guide:progarch/dh-v0-one-sensor), підставимо **моки** (англ. *mock* — підробка, що вдає справжнє).

Робочий файл потрібен не «щоб запускалося». Він потрібен, бо саме на ньому можна виконати обіцянку оглядового кроку — прогнати крізь v1 ті самі чотири вимоги, що [роздирали v0](guide:progarch/dh-v0-one-sensor), і поміряти пальцем, докуди тепер дістає кожна. У v0 три з них розповзалися хвилею; тут, стверджували ми, кожна впирається в стіну свого модуля. Ствердити — легко; заслужити цю тезу в коді — ось за це й беремось.

## Ідея: та сама фізика в пам'яті, але тепер за швами

Мок мусить чесно вдавати фізику кімнати: повітря само поволі холоне, а під струмом обігрівача — гріється. У v0 цей прихований «фізичний» стан жив у двох глобальних змінних, `_room` і `_heater`, які код тримав в одних руках: той самий файл і посував температуру, і читав її, і перемикав живлення.

Але у v1 код навмисно **розчеплено**. Давач і розетка — тепер окремі об'єкти за окремими портами, і жоден не знає про інший: `MockThermometer` не має посилання на `MockPlug`, `decide` не бачить ні того, ні того. Куди ж тоді подітися зв'язку «розетка гріє → давач це відчуває»? Він нікуди не зникає — він **переїжджає туди, де йому й місце в реальності**: у саме повітря кімнати. У справжньому домі термометр і радіатор не з'єднані дротом; їх пов'язує спільне повітря, яке один нагріває, а інший міряє. Мок моделює рівно це: заводимо один спільний `MockRoom`, розетка пише в його прапорець `heating`, давач читає його `temp` (і трошки посуває), а фізика кімнати замикає між ними коло. Розчеплений код, зчеплена фізика — і зчеплення сидить там, де воно справжнє.

![Ланцюжок MockRoom → MockThermometer → decide → MockPlug, замкнений у коло зворотним швом heating через спільний MockRoom; над швом Reading висить червоний тап, що вкидає ok=false](/guide/progarch/structure-in-the-small/dh-v1-modules/img/mock-loop.svg)
*Дім живе в пам'яті: спільний MockRoom стоїть за фізичне повітря, розетка пише в heating, давач читає temp і перекладає діалект на краю, а рішення диригує; збій вкидається саме на шві давача — там, де в реальності його й ловлять.*

> 🔧 **Навіщо це.** Спільний `MockRoom` — не недогляд і не приховане глобальне зчеплення, яке ми ганьбили у v0. Це навпаки — **найчесніша межа мока**: він виносить назовні рівно те єдине, що справді спільне між давачем і грілкою, — повітря, — і більше нічого. Код лишається розчепленим (порти нічого не знають одне про одного), а зв'язок живе там, де фізика його й тримає. Коли завтра `MockPlug` поміняють на драйвер справжньої розетки, а `MockThermometer` — на справжній 1-Wire, спільний `MockRoom` просто зникне, бо його роль — повітря — візьме на себе жива кімната. Мок імітує не код, а **світ**, у який код упирається; переплутати ці дві речі — і почнеш ховати за портами те, чого ховати не треба.

## Увесь дім за швами — повний файл

Ось повний v1. Ліворуч Python, праворуч той самий дім мовою TypeScript — обидва запускаються як є. Придивіться, як кожен шматок сидить у своїй частині файлу й спілкується з рештою лише через названі значення `Reading` та `Command`.

```py
# hub.py — Digital Homes v1: той самий дім, але за швами. Драйвери — мокові.
from dataclasses import dataclass
from enum import Enum, auto
from typing import Protocol
from time import sleep
import random

# ── Значення на межах: одиниця й статус живуть у типі, не в чиїйсь голові ──
@dataclass(frozen=True)
class Reading:                       # DTO давача
    celsius: float                   # ЗАВЖДИ °C
    ok: bool = True                  # чи це справжнє свіже число

@dataclass(frozen=True)
class Config:
    threshold: float = 20.0          # поріг — вхід рішення, а не його нутрощі

class Command(Enum):                 # рішення — це ЗНАЧЕННЯ, а не вчинок
    HEAT = auto()
    IDLE = auto()

# ── Порти: логіка залежить від них, а не від марки заліза ──
class Sensor(Protocol):
    def read(self) -> Reading: ...

class Heater(Protocol):
    def on(self) -> None: ...        # ідемпотентно
    def off(self) -> None: ...

# ── Мокова фізика: те єдине, що справді спільне — повітря кімнати ──
class MockRoom:
    def __init__(self, temp=18.0):
        self.temp = temp             # «справжня» температура повітря, °C
        self.heating = False         # чи подано струм на грілку
    def drift(self):                 # холоне сама, гріється під струмом, + шум виміру
        self.temp += (0.4 if self.heating else -0.2) + random.uniform(-0.05, 0.05)

# ── Драйвер давача: мову СВОГО заліза знає тільки він ──
class MockThermometer:               # реалізує порт Sensor
    def __init__(self, room, fault_plan=()):
        self._room = room
        self._faults = iter(fault_plan)          # напр. (0,0,1,0): 1 імітує збій заліза
    def read(self) -> Reading:
        self._room.drift()                       # фізика марширує далі, дарма що давач німий
        if next(self._faults, 0):                # таймаут / CRC=NO — числа немає
            return Reading(celsius=float("nan"), ok=False)   # переклад збою на «не вірю»
        milli = round(self._room.temp * 1000)    # сирий діалект: цілі мілі-°C, як 1-Wire
        return Reading(celsius=milli / 1000, ok=True)        # переклад одиниць ТУТ, на краю

# ── Драйвер розетки: ідемпотентний ──
class MockPlug:                      # реалізує порт Heater
    def __init__(self, room, name="вітальня"):
        self._room = room
        self._name = name
    def on(self):
        if not self._room.heating:   # повторний «увімкни» реле дарма не смикає
            self._room.heating = True
            print(f"[{self._name}] обігрівач УВІМКНЕНО")
    def off(self):
        if self._room.heating:
            self._room.heating = False
            print(f"[{self._name}] обігрівач вимкнено")

# ── Чисте рішення: ті самі входи → той самий вихід, жодних ефектів ──
def decide(r: Reading, cfg: Config) -> Command:
    if not r.ok:
        return Command.IDLE          # давач мовчить → безпечний спокій, не «грій наосліп»
    return Command.HEAT if r.celsius < cfg.threshold else Command.IDLE

# ── Збірка: тонкий цикл, що лише диригує ──
def run(sensor: Sensor, heater: Heater, cfg: Config, ticks=None):
    n = 0
    while ticks is None or n < ticks:
        reading = sensor.read()              # драйвер ховає діалект і збої заліза
        if not reading.ok:
            print("[давач] мовчить — тримаю безпечний спокій")   # видимість збою нагорі
        if decide(reading, cfg) is Command.HEAT:
            heater.on()
        else:
            heater.off()
        sleep(30)
        n += 1

# ── Корінь склеювання: конкретне зустрічає конкретне рівно тут ──
if __name__ == "__main__":
    room = MockRoom(temp=18.0)               # спільне «повітря» для давача й розетки
    run(sensor=MockThermometer(room),
        heater=MockPlug(room),
        cfg=Config(threshold=20.0))
```

```ts
// hub.ts — Digital Homes v1: той самий дім, але за швами. Драйвери — мокові.

// ── Значення на межах: одиниця й статус живуть у типі, не в чиїйсь голові ──
interface Reading {
  readonly celsius: number;   // ЗАВЖДИ °C
  readonly ok: boolean;       // чи це справжнє свіже число
}
interface Config { readonly threshold: number; }   // поріг — вхід рішення
type Command = "HEAT" | "IDLE";                     // рішення — це ЗНАЧЕННЯ

// ── Порти: логіка залежить від них, а не від марки заліза ──
interface Sensor { read(): Reading; }
interface Heater { on(): void; off(): void; }       // on/off — ідемпотентні

// ── Мокова фізика: те єдине, що справді спільне — повітря кімнати ──
class MockRoom {
  temp: number;
  heating = false;
  constructor(temp = 18.0) { this.temp = temp; }
  drift(): void {             // холоне сама, гріється під струмом, + шум виміру
    this.temp += (this.heating ? 0.4 : -0.2) + (Math.random() - 0.5) * 0.1;
  }
}

// ── Драйвер давача: мову СВОГО заліза знає тільки він ──
class MockThermometer implements Sensor {
  private i = 0;
  constructor(private room: MockRoom, private faults: number[] = []) {}
  read(): Reading {
    this.room.drift();                         // фізика марширує далі, дарма що давач німий
    if (this.faults[this.i++]) return { celsius: NaN, ok: false };  // збій → «не вірю»
    const milli = Math.round(this.room.temp * 1000);   // сирий діалект: цілі мілі-°C, як 1-Wire
    return { celsius: milli / 1000, ok: true };        // переклад одиниць ТУТ, на краю
  }
}

// ── Драйвер розетки: ідемпотентний ──
class MockPlug implements Heater {
  constructor(private room: MockRoom, private name = "вітальня") {}
  on(): void {
    if (!this.room.heating) {                  // повторний «увімкни» реле дарма не смикає
      this.room.heating = true;
      console.log(`[${this.name}] обігрівач УВІМКНЕНО`);
    }
  }
  off(): void {
    if (this.room.heating) {
      this.room.heating = false;
      console.log(`[${this.name}] обігрівач вимкнено`);
    }
  }
}

// ── Чисте рішення: ті самі входи → той самий вихід, жодних ефектів ──
function decide(r: Reading, cfg: Config): Command {
  if (!r.ok) return "IDLE";                    // давач мовчить → безпечний спокій
  return r.celsius < cfg.threshold ? "HEAT" : "IDLE";
}

// ── Збірка: тонкий цикл, що лише диригує ──
const sleep = (ms: number) => new Promise((res) => setTimeout(res, ms));

async function run(sensor: Sensor, heater: Heater, cfg: Config, ticks = Infinity) {
  for (let n = 0; n < ticks; n++) {
    const reading = sensor.read();             // драйвер ховає діалект і збої заліза
    if (!reading.ok) console.log("[давач] мовчить — тримаю безпечний спокій");
    if (decide(reading, cfg) === "HEAT") heater.on();
    else heater.off();
    await sleep(30_000);
  }
}

// ── Корінь склеювання: конкретне зустрічає конкретне рівно тут ──
const room = new MockRoom(18.0);               // спільне «повітря» для давача й розетки
run(new MockThermometer(room), new MockPlug(room), { threshold: 20.0 });
```
:::

Запустивши це, ви побачите те саме розмірене дихання, що й у v0, — драйвер розетки подає голос лише коли грілка **перемикається**, а не щотакту:

```
[вітальня] обігрівач УВІМКНЕНО     ← кімната стартувала з 18 °C, нижче за поріг
[вітальня] обігрівач вимкнено      ← за кілька хвилин дійшло до ~20.1 °C
[вітальня] обігрівач УВІМКНЕНО     ← холонучи, знову впало під 20
```

Поведінка — байдужа до того, що всередині все переставлено: дім гріє так само, як гріло. Це і є найперший тест рефакторингу — форма інша, поведінка ціла. Щоб не чекати пів години на цикл, під час гри поставте `ticks=` невелике число або тимчасово `sleep(1)`: фізика мока не прив'язана до годинника й задихає в десятки разів швидше.

## Коли давач замовкає — збій, проведений крізь шар

Тепер зробимо те, чого зварений v0 не вмів навіть спробувати, — **вкинемо збій давача** і подивимось, як він проходить крізь шари. У полі 1-Wire з поганою контрольною сумою поверне `CRC=NO`, а розетка через Wi-Fi відпаде на пів хвилини з таймаутом; чесний драйвер у такому разі не має правдоподібного числа. Наш мок імітує це полем `fault_plan`, де одиниця означає «цього такту заліза не дочитались»:

```py
room = MockRoom(temp=19.5)                          # трохи нижче порога
faulty = MockThermometer(room, fault_plan=(0, 0, 1, 1, 0))   # такти 3–4 — «збій»
run(faulty, MockPlug(room), Config(threshold=20.0), ticks=5)
```
```
[вітальня] обігрівач УВІМКНЕНО              ← такт 1: ~19.3 °C < 20 → гріємо
                                           ← такт 2: ~19.7 °C, уже гріється — реле мовчить
[давач] мовчить — тримаю безпечний спокій    ← такт 3: вкинуто ok=false → decide каже IDLE
[вітальня] обігрівач вимкнено                ←        … і збірка виконує безпечний спокій
[давач] мовчить — тримаю безпечний спокій    ← такт 4: знову збій → знову спокій (реле вже off)
[вітальня] обігрівач УВІМКНЕНО              ← такт 5: давач ожив, ~19.7 °C < 20 → знову гріємо
```

Простежмо шлях збою — і побачимо, що він не «обробляється» в одному місці, а **перекладається на кожній межі**. Залізо говорить мовою збоїв: таймаут, зіпсована контрольна сума. Драйвер, і тільки він, розуміє цю мову — і перекладає її на **доменне слово**: не кидає виняток нагору, не підставляє нуль, а повертає `Reading(ok=false)`, тобто чесне «числу вірити не можна». Рішення на це доменне слово свідомо відповідає: перше, що робить `decide`, — читає `ok`, і лише потім дивиться на градуси. Немає `ok` — немає й порівняння; повертається `IDLE`. А збірка виконує цей `IDLE` як безпечний спокій: не гріти наосліп. Кожен шар говорить своєю мовою, і на кожному шві стоїть переклад — [саме так помилку й проводять крізь шари](guide:progarch/errors-through-layers), а не проносять сиру з дна на поверхню.

![Ряд: залізо (таймаут/CRC=NO) → драйвер перекладає збій → Reading(ok=false) «не вірю» → decide: not ok → IDLE, і вниз стрілка на зелений «безпечний спокій»; унизу червона смуга — у v0 такого слова не було](/guide/progarch/structure-in-the-small/dh-v1-modules/img/fault-path.svg)
*Залізна поломка не летить сирою нагору: драйвер перекладає її на доменне «не вірю», рішення читає це слово першим і обирає спокій. У v0 доменного «не вірю» не існувало — була сліпа довіра, той самий ризик R2.*

Зверніть увагу на такт 4: «справжня» температура там ~19.9 °C, тобто кімната холодна, — а ми **все одно** не гріємо. Це не помилка, а свідома межа: коли числу вірити не можна, безпечніше тримати спокій, ніж гріти за неправдою. У v0 такого вибору не було взагалі — цикл сліпо довіряв, що `t` справжнє, тож застряглий чи німий давач тихо ламав рішення, і ніхто цього не бачив. Тут «не вірю» — це видиме слово, яке можна залогувати, а завтра й перетворити на сповіщення. Межа не зробила давач надійнішим; вона дала ненадійності **де проявитися чесно**.

## Чотири правки — кожну міряємо від того самого v1

Тепер обіцяний тест. Щоб побачити **чистий радіус** кожної вимоги, прикладаймо їх не стосом, а поодинці — щоразу від того самого базового v1 вище. Так видно рівно те, що торкнула ця вимога, і нічого зайвого. Пригадаймо мірку з v0: ціну правки міряють не рядками, а тим, **як далеко по файлу вона мусить дотягтися**.

### Нічний поріг — торкається лише Config

Удень тримати 20 °C, а вночі відпускати до 18. Ця вимога була дешевою вже у v0, бо влучала в те, що v0 і без того тримав окремо, — у число порога. У v1 поріг живе в `Config`, тож правка й падає рівно туди:

```diff
-from time import sleep
+from time import sleep, localtime

-@dataclass(frozen=True)
-class Config:
-    threshold: float = 20.0
+class Config:                          # поріг тепер залежить від часу доби
+    def __init__(self, day=20.0, night=18.0):
+        self._day, self._night = day, night
+    @property
+    def threshold(self) -> float:      # decide читає cfg.threshold — і різниці не помічає
+        return self._day if 7 <= localtime().tm_hour < 23 else self._night
```

Порахуймо радіус: означення `Config`, рядок імпорту й той єдиний рядок кореня, де `Config` будують. `decide` не змінився — він і далі пише `cfg.threshold`, просто тепер за цим ім'ям стоїть обчислення, а не літерал. Драйвери, цикл, `Reading`, порти — не ворухнулись. Це наш **контрольний зразок**: правка, дешева і в v0, і в v1, — еталон «улитості», проти якого міряємо решту три, що у v0 коштували перебудови.

### Другий давач — росте лише збірка

«Постав другий давач — у спальні, зі своїм порогом і своєю розеткою». У v0 ця вимога тріщала по всіх швах: зникали обидві глобальні змінні, три драйвери поверталися **фабрикою** `make_room`, поріг-константа ставав полем кожної кімнати, простий цикл — циклом у циклі. ### Сповіщати замість гріти — +ALERT і одна гілка

«У спальні не вмикай грілку, а надішли мені сповіщення, коли холодно». У v0 ця крихітна на вигляд вимога змушувала братися за ніж: рішення й дія були **зварені** в один жест `if холодно: увімкнути`, і щоб устромити друге «тому» («холодно — тому напиши»), доводилось спершу **розтяти** зварене — витягти `cold` в окреме значення посеред робочого коду. У v1 рішення вже є значенням `Command`. Тому шов не розрізають — у нього **дописують**:

Це різниця між «прорубати двері в несучій стіні» і «зайти в уже прорубані».

### Інший вендор — новий драйвер за тим самим портом

Остання вимога у v0 була найпідступнішою: «поміняли давач у вітальні на іншу модель». Один рядок заміни — і вітальня тихо переставала грітися, без жодного сліду в консолі, бо новий драйвер віддавав цілі мілі-градуси (`18000`), які текли просто в порівняння `18000 < 20.0` — завжди хибне. Діалект заліза був вплетений у логіку. У v1:

```diff

+    def __init__(self, room):
+        self._room = room
+    def read(self) -> Reading:

+        deci_f = round((self._room.temp * 9 / 5 + 32) * 10)   # сирий діалект: десяті °F
+        celsius = ((deci_f / 10) - 32) * 5 / 9                # переклад на °C ТУТ, на краю
+        return Reading(celsius=celsius, ok=True)

+    run(AcmeThermometer(room), MockPlug(room), Config(threshold=20.0))
```

Радіус: новий клас за портом `Sensor` плюс один рядок кореня. Новий вендор говорить іншим діалектом — не мілі-°C, а десятими градуса Фаренгейта (`18 °C → 644`), — і перекладає **свій** діалект у себе, на краю, віддаючи чесний `Reading` у градусах Цельсія. `decide` не бачить різниці: до нього фізично не доходять ані мілі-°C, ані десяті °F — контракт шва пропускає лише °C.

> 🔧 **Навіщо це.** Придивіться: у v0 і v1 правка «інший вендор» — **однакова завширшки**, буквально один рядок заміни в корені. Але у v0 цей рядок був тихою міною, що ламала рішення за файл від себе, а у v1 це безпечна, замкнена підстановка. Різницю робить не обсяг дифа, а **шов**: у v0 діалект тік прямо в порівняння, тож заміна драйвера міняла те, що бачило рішення; у v1 порт зобов'язує кожен діалект померти на краю, тож знизу завжди тече той самий `Reading` у °C. Порт — це страховий поліс проти вимирання заліза: давач, куплений сьогодні, за три роки знімуть із виробництва, а на заміну прийде інша модель зі своїм діалектом, і ти хочеш, щоб та заміна лишалась одним класом збоку, а не хірургією по всьому опаленню в проді.

Складімо чотири радіуси в одну картину. Нічний поріг лишився у `Config`; другий давач виріс лише у збірці; сповіщення вписалось у наперед лишену щілину; новий вендор став класом збоку. Жодна правка не вийшла за стіну свого модуля — те, що оглядовий крок пообіцяв сіткою локальності, тут відбулося наживо, рядок за рядком. У v0 три з цих чотирьох розповзалися хвилею; у v1 кожна впирається в межу й далі не йде. Ми не зробили дім розумнішим — ми зробили його **дешевшим до зміни**, і рівно там, куди зміни, як ми перевіряли аудитом, і приходять.

## Складність і пастки

### Надмодульність — та сама передчасна складність, лише навиворіт

Найспокусливіша пастка чигає саме тепер, коли межі щойно так гарно погасили чотири правки. Реакція проситься сама: якщо шви такі корисні — нарубаймо їх ще! Інтерфейс на `Config`, ієрархія `Notifier` із фабрикою, шар над логом, порт до кожного `print`. Це була б **та сама передчасна складність**, від якої ми застерігали у v0, тільки з дзеркального боку. У v0 гріхом було навести абстракцій під один давач завчасно; тут гріхом було б наводити межі там, куди **жодна реальна вимога ще не тицьнула**.

Погляньте на код чесно: наш `notify` — гола функція, а не порт `Notifier` із єдиною реалізацією `PrintNotifier`, загорнутою у `NotifierFactory` й упорснутою через `NotifierProvider`. І це **правильно**, поки сповіщення одне. Той день, коли з'явиться друга вимога — «слати ще й у Telegram», — сам покаже, де вводити порт `Notifier`; до того дня ця межа була б церемонією, а не розчепленням: код, який щодня читаєш і супроводжуєш, за нуль користі. Ми провели рівно три шви, бо болів було рівно три, і кожен показав пальцем, де різати. Дисципліна залізна в обидва боки: не варити шви наглухо завчасно (для одного дому зварений v0 ідеальний) — і не різати їх наперед «про всяк випадок». Шов вводять **у день, коли приходить тікет**, а не за рік до нього.

### Застиглий давач проти мертвого — де проходить межа ok-прапорця

Треба чесно окреслити, що `ok=false` ловить, а що ні. Він ловить давач, що **замовк** чи віддав сміття, — таймаут, `CRC=NO`, обрив. Але він **не** ловить давач, що завис на правдоподібному числі: якщо 1-Wire застряг і вперто віддає `20.0 °C`, кожен його `Reading` має `ok=true`, і `decide` чесно йому вірить. Застиглий вимір v1 поки що прийме за свіжий — це той самий ризик надійності, що [перше рев'ю занесло другим номером (R2)](guide:progarch/dh-v0-scenario-audit).

Де ж тоді проходить межа прапорця? `ok` відповідає на питання «чи **цей** дотик до заліза дав достовірне свіже число» — переклад миттєвої, разової поломки. Він **не** відповідає на питання «чи давач ще **живий** — чи число взагалі ворушиться». Це інше питання, і живе воно на іншому шарі. Але — і в цьому вся сила швів — тепер для нього **є де стати**: обгортка над портом `Sensor`, що стежить за живістю:

```py
class FreshnessGuard:                 # обгортка над портом Sensor: ловить ЗАСТИГЛИЙ давач
    def __init__(self, inner: Sensor, limit=10):
        self._inner, self._limit = inner, limit
        self._last, self._same = None, 0
    def read(self) -> Reading:
        r = self._inner.read()
        if not r.ok:                              # уже визнаний збій — пропускаємо як є
            self._same = 0
            return r
        self._same = self._same + 1 if r.celsius == self._last else 0
        self._last = r.celsius
        if self._same >= self._limit:             # надто довго те саме число → застигло
            return Reading(celsius=r.celsius, ok=False)   # доводимо застиглість до «не вірю»
        return r
```

Вартового **вставляють у корені**, не торкаючись нічого іншого: `run(FreshnessGuard(MockThermometer(room)), MockPlug(room), Config())`. `decide` і цикл не знають про його існування — порт робить обгортку сумісною, як перехідник між двома розетками. У зварному v0 такому вартовому ніде було й стати: між читанням і рішенням не було межі, у яку його вкласти. Ось точна межа того, що купив рефакторинг: він **не** долагодив надійність до кінця — він дав кожному новому вартовому **де жити**, за тим самим портом, не чіпаючи рішення.

### Мок чемніший за залізо

Найтихіша пастка — у тому, як **чемно** бреше мок. Він завжди віддає свіже число (крім тих збоїв, які ми самі вкинули), його `MockRoom` реагує на струм миттєво, без теплової інерції, а спільне повітря замикає коло без затримки. Справжній дім грубіший: обігрівач, увімкнений щойно, не гріє вмить — стіни й повітря мають **теплову масу**, тож температура повзе з відставанням і проскакує поріг за інерцією; Wi-Fi-розетка відповість за секунду, а то й відпаде на пів хвилини; годинник хоста попливе (а від нього, до речі, залежить наш нічний поріг!). Головна брехня мока — його **послух**.

Але тут криється й мірило того, що ми виграли. Той самий збій, який ми змогли вкинути через `fault_plan`, у зварному v0 **не було куди вкинути** — не було ні `ok`, ні порту, ні шва, який його прийняв би. Мок v1 можна навчити брехати **менше** — імітувати таймаути, застиглі значення, повільні відповіді — саме тому, що для кожної такої халепи у формі вже є місце: прапорець `ok`, обгортка за портом, гілка в збірці. Чистота циклу — почасти лабораторна ілюзія; різниця в тім, що тепер її є куди псувати наближенням до реальності.

І остання, успадкована від v0: `sleep` у циклі, що обходить список кімнат, стопорить **усіх** одразу. Один давач, який відповідає повільно, підвішує весь дім; десять кімнат «одночасно» насправді обслуговуються послідовно в одному потоці. Ми навмисно не чіпали цього у v1 — це [той-таки super-loop, чиї межі проступають, коли роботи стає більше, ніж один нероздільний цикл встигає вчасно](guide:embedded/super-loop-limits). Рефакторинг лікував змінюваність, а не паралельність, бо жодна з чотирьох вимог паралельності не зажадала. Це не недогляд, а дисципліна: v1 виправив рівно те, на що тицьнули реальні болі, і зупинився. Кожне порожнє місце, яке шви щойно виточили, — куди вставити сховище на випадок рестарту, де проляге шов між домом і хмарою, де стане потік на кімнату, — чекає свого тікета. Ми заповнюватимемо їх по одному, коли за кожне з'явиться справжня причина заплатити.
