# writer_ua

Конвеєр письма для корпусу в `root/`. Самодостатній: нічого зі `scripts/` не бере.

**Алгоритм** — `ALGORITHM.md`, словами автора. Де код чи інший документ розходяться з
ним — правда там.

**Правила** — `rules/`, мапа файлів і збирання запитів — `rules/README.md`.

**Скрипти** — `API.md`: локальні команди (`local/`), перевірки (`checkers/`), рушій
(`runners/`).

## Два рівні

**Оркестратор** (`runners/orchestrator.js`) тримає чергу одиниць, пул активних, стан батчу
в `inwork/<хеш>/`, приймає виклики від алгоритму (завести вставку, код, фігуру, нову тему)
і в кінці пише маніфест.

**Алгоритм** (`runners/algorithm.js`) веде одну одиницю етапами 1–10. Запити збирає
`runners/prompt.js` з файлів `rules/`, відповіді розбирає `runners/parse.js` — блоками туди
й назад, ніколи JSON. Локальні кроки — `runners/local.js`.

## Одиниця

Версія статті (`<тема>-d.md`, `<тема>.md`) або вставка (`<тип>-<ім'я>.md`); код і фігура —
свої одиниці з власною дорогою. Адреса — `книга/тема:detailed`, `книга/тема:hist-<ім'я>`.

## Перевірки конвеєра — локально, нуль токенів

    node writer_ua/checkers/contract.js   чи розбере парсер те, що просить кожен контракт
    node writer_ua/checkers/delivery.js   чи доїжджає кожен клас правил тому, кому треба, і не доїжджає зайве
    node writer_ua/checkers/balance.js    чи не штовхає запит в один бік; які числа бачить агент
    node writer_ua/checkers/dryrun.js     весь алгоритм з підробним агентом; SCORE=5 · SHORT=1 · OVER=1 · TYPE=…

## Рішення виконавця, не підтверджені автором

Дрібне, що довелось вирішити, щоб алгоритм працював; автор може перевирішити.

- лінк на ще не заведену тему письменник ставить у формі `root:new/<слуг>`; етап 8 замінює
  її на справжню адресу або на адресу знайденого дубля;
- тези повертають лише детальна й базова — вставкам не треба;
- фігури, названі письмом, дістають імена від конвеєра й ставляться на місце режимом
  «вставка зображення» — тим самим, що й каркасні фігури без місця;
- вставка зображення — два запити, як описано: «у який розділ», тоді «постав»;
- базова: статус `pending`, якщо треба; `empty` — лише якщо стояв `pending` (`status-if`);
- новій темі розділ — лише з переліку: чужий слуг заводить у маніфесті новий розділ, тому
  такий кладеться поруч із темою, і це йде у звіт;
- відповідь, що з'їла понад десяту частину прози розділу (дописування, вставка зображення),
  не приймається — лишається попередній текст;
- дописування з дефіцитом понад третину і без названого матеріалу йде через аналіз
  «де дописати», названі місця беруться як рівень 5.
