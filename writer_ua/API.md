# Локальні команди `writer_ua` — API й користування

Шість команд і чотири бібліотеки. Усе локальне: **нуль токенів**, детерміноване, працює на
повному корпусі за секунди.

```
writer_ua/
  lib/manifest.js      читач і писар маніфесту, схема 7
  lib/text.js          лічильники: проза, огорожі, код у файлах
  lib/dupes.js         підказки про можливий дубль поняття
  local/lib/units.js   бібліотека: одиниця роботи + мова відбору
  local/find.js        пошук
  local/status.js      зміна статусу · рівня · recode
  local/count.js       міряє прозу й код
  local/add.js         заводить тему · вставку · крок-ref
  local/move.js        перейменування й перекладання
  checkers/lang.js     маркер @@ і словник
```

Маніфест читає й пише **лише** `writer_ua/lib/manifest.js` — жодна з цих команд не має
власного розбору схеми 7.

⛔ **Конвеєр стоїть на власних модулях.** Нічого зі старого `scripts/` він не підключає:
там свої домовленості й свій конвеєр, і спільний модуль зв'язав би два різні порядки
роботи в один. Замір при переході: обидва сита прози дали однакове число на всіх 17 867
файлах корпусу, а дванадцять операцій маніфесту — байт-у-байт однакові файли.

---

## Спільні поняття

### Одиниця

Статус, рівень і прапорець `recode` висять **не на темі**, а на версії (`basic`,
`detailed`) і на **кожній вставці окремо**. Тому одиниця відбору — не тема, а те, що має
власний статус. Їх у корпусі **28 569**: 13 764 версії + 11 617 вставок + 3188 вказівників.

### Адреса

```
embedded/cherha-oflainu:detailed        версія
embedded/cherha-oflainu:basic           версія
embedded/cherha-oflainu:proj-queue      вставка (ім'я файла без .md)
```

**Вказівник (`ref`) адреси не має** — статусу в нього немає, писати нічого. У `--ids` він
не потрапляє, а в stderr іде рядок, скільки таких пропущено.

### Три способи сказати, кого брати

| спосіб | як |
|---|---|
| фільтри | `--book unix --status pending` |
| адреси | `--addr a,b,c` |
| труба | `find … --ids \| status …` |

⚠️ **Спосіб задає НАЯВНІСТЬ джерела, а не кількість адрес у ньому.** Порожня труба — це
«адрес не надійшло», а не «візьми фільтри». Інакше `find … --ids | status --book X --set
recheck --apply` при нулі знахідок переписав би всю книгу. Адреси разом із фільтрами —
помилка; труба разом із `--addr` — теж.

### Сухий прогін

`status`, `add`, `move` і `lang --add` **типово нічого не пишуть** — показують, що
змінилося б. Пише лише `--apply`.

Показане — це **звіт `manifest.applyOps(dry:true)`**, тобто ті самі операції, що потім і
запишуться, а не власний переказ чужих правил. Доти вивід розходився з дійсністю мовчки:
рівень при статусі, який його не тримає, зникав без слова.

### Коди виходу й потоки

| код | що означає |
|---|---|
| 0 | зробило, що просили (зокрема «нічого не знайшлося» — це не помилка) |
| 1 | знайдено дефекти (`lang`) або маніфест повернув `errors` |
| 2 | помилка виклику: невідомий прапорець, крива адреса, суперечка режимів |

**stdout — результат, stderr — попередження.** Тому `find … --ids | status …` не отруює
трубу попередженнями про вказівники чи повторені адреси.

## Мова відбору — одна на всі команди

Живе в `local/lib/units.js`, тож `find`, `status`, `count` і `lang` розуміють однакове.

| прапорець | що відбирає |
|---|---|
| `--kind sci,course` | вид книги |
| `--book embedded,unix` | книга за слугом |
| `--group <слуг,…>` | група в маніфесті |
| `--chapter <слуг,…>` | розділ у маніфесті |
| `--type detailed,proj` | `basic detailed hist comp math proj api` |
| `--status deeper,pending` | `done pending empty update deeper recheck` |
| `--not-status done` | усе, крім названого |
| `--slug "i2c-*"` | слуг теми, `*` дозволена |
| `--title "черга"` | підрядок назви, без регістру |
| `--level 3 \| 2-4 \| 3-` | рівень (лише де проставлений) |
| `--recode` / `--no-recode` | борг «код ще не переписаний як проєкт» |
| `--own` / `--ref` | власна стаття / вказівник |
| `--has-file` / `--no-file` | чи лежить `.md` на диску |
| `--has-code` / `--no-code` | чи є поруч тека коду |

**Повтор перелічного прапорця об'єднує:** `--status done --status recheck` ⇒ `done` **або**
`recheck`. `--slug`, `--title`, `--level` мають одне значення, тож повтор — помилка.

**Невідоме значення падає, а не дає тихий нуль.** `--status recheсk` із кириличною «с» →
код 2. Слуги груп і розділів звіряються зі справжніми з маніфестів відібраних книг.

## Команди

### `find` — пошук. Нічого не пише

```bash
node writer_ua/local/find.js --book embedded --status deeper --has-code
```

Вивід (взаємовиключні): таблиця типово · `--ids` (адреси в трубу) · `--json` · `--count` ·
`--by <поле>` (`book kind status type group level`). `--limit N` ріже таблицю й `--json`;
з `--count` і `--by` не поєднується — вони рахують усе.

`--json` віддає на кожну одиницю:

```json
{ "addr":"unix/choosing-ipc:detailed", "book":"unix", "kind":"course",
  "slug":"choosing-ipc", "part":"detailed", "type":"detailed",
  "group":"…", "chapter":"…", "title":"…",
  "status":"recheck", "level":null, "recode":false, "ref":null, "file":"…/choosing-ipc-d.md" }
```

### `status` — єдина команда, що пише статус

```bash
node writer_ua/local/find.js --book embedded --status deeper --has-code --ids \
  | node writer_ua/local/status.js --set recheck --set-recode off --apply
```

| що міняти | |
|---|---|
| `--set <статус>` | новий статус |
| `--if <статус>` | змінити, **лише** якщо зараз саме цей (це `status-if` маніфесту) |
| `--set-level N \| none` | рівень 1–5 |
| `--set-recode on\|off` | борг переписування коду |

Прапорці запису названо `--set-*` навмисно: `--level` і `--recode` — це **фільтри**, і
однакове ім'я для «відібрати за» й «записати» рано чи пізно перепише не те. Тому
`--level 3 --set-level 4` читається однозначно.

⚠️ **Рівень маніфест тримає тільки при `deeper`** — на інших статусах він стирається. Тому
`--set-level` при іншому статусі попереджає, а не мовчить.

`--quiet` ховає подетальний перелік змін; **пропущене показується завжди**, бо непорожній
`skipped` означає рівно одне: намір розійшовся з тим, що зробив маніфест.

### `count` — міряє. Звітує, а не судить

```bash
node writer_ua/local/count.js --book unix --type detailed --sum
```

⛔ Тут немає підлог, стель, смуг і слова «порушення». Показане число стає ціллю: поки в
таблиці стояв орієнтир, детальні лягали в ±2% від нього.

| колонка | що це |
|---|---|
| `слова` | проза за ситом `_lib.proseWords` (огорожі й `:::` не рахуються) |
| `симв` | символи прози тим самим ситом |
| `рядки` | рядки файла, як він лежить |
| `фіг` | підключених зображень |
| `огор` | рядків коду, що **ще** в огорожах — мало б виїхати у файли |
| `код` | рядки по теках мов: `c=120 cpp=140`; `*` — у теці лише збірка чи тести |

⚠️ Числа **не збігаються з `scripts/wordcount.js`**: те сито рядки `:::` рахує, це — ні.
По корпусу різниця 162 705 слів на 8239 файлах, і це вся вона, до слова.

`--sum` дає медіану, чверті, край і разом; з `--limit` не поєднується.

### `add` — заводить тему, вставку або крок курсу

```bash
node writer_ua/local/add.js --book sys-unix \
  --topic dma-buf-sharing --title "Спільний буфер DMA" \
  --group foundations --chapter unix-idea --apply
```

Три режими: `--topic` · `--insert <тема> --type … --file …` · `--ref <книга>/<тема>` (лише
курси). Прапорець, чужий обраному режимові, — помилка.

⛔ **Книгу, том і курс не створює ніколи** — це робить тільки автор. Книга вважається
наявною, лише якщо в неї є `manifest.json`: перелік книг має падбек на скан диска, тож
гола тека приходила звідти «книгою», і `--apply` через `ensureManifest` цю книгу завів би.

⚠️ **Перед заведенням завжди друкуються підказки про можливі дублі** (`lib/dupes.js`)
— і не блокують: об'єднувати чи ні, вирішує людина. Але побачити це треба до запису.

Нова тема має рівно два дозволені статуси — `empty` і `pending`; обидва `empty` разом
заборонені (така тема не потрапить у жодну чергу). **На диску не створюється нічого:** файл
пише письменник, а ім'я вставки вже тримає маніфест у записі `{file,status}`.

Тема й крок стають **у кінець розділу**; переставляння — операція, якої поки немає.

### `move` — перейменування й перекладання

```bash
node writer_ua/local/move.js --from sf-visual/homography --to homografiia
```

`--to <слуг>` рухає **все**: теку, обидві версії, теки коду, директиви `:::code`,
посилання `root:` по корпусу (зокрема хвіст `…/тема.md`, що теж перейменовується), `ref` у
маніфестах курсів, запис у маніфесті.

`--to-chapter <група>/<розділ>` — **правка самого лише JSON**: група й розділ у шляху не
живуть, тема лежить пласко під книгою. Неіснуючі група чи розділ заводяться тільки з
`--group-title` / `--chapter-title` — інакше одруківка створила б порожню групу з назвою-слугом.

**Порядок запису: текст → файли → маніфест**, і він не довільний. Правки зібрані за старими
шляхами, тож робити їх треба, поки ті шляхи ще існують: 4657 тем посилаються самі на себе,
і при зворотному порядку такий файл уже переїхав, а запис у нього падає посеред роботи.

**Передполіт** перевіряє все, що можна, до першого запису: джерела на місці, цілі вільні,
файли пишуться, писар маніфесту насухо не заперечує. Не пройшло — не починаємо взагалі. Якщо
`git mv` усе-таки впав, у stderr іде «переписано X з N, перенесено Y з M, МАНІФЕСТ НЕ
ОНОВЛЕНО» — щоб було видно, звідки підбирати.

⛔ Між книгами не переносить: це два різні маніфести, і чесно робиться парою «завести там +
зняти тут», зі своїм рішенням про долю статусів.

### `lang` — маркер `@@` і словник

```bash
node writer_ua/checkers/lang.js --book sys-unix --type detailed --latin
node writer_ua/checkers/lang.js --orphans
node writer_ua/checkers/lang.js --add "en|garbage collection" \
  --uk "збирання сміття" --gloss "…" --topic sf-algorithms/gc --apply
```

Перевіряє: маркер закритий і на одному рядку · ключ **є** у словнику
(`root/dictionary.json`) · той самий термін не позначено двічі в одній статті.

⚠️ **Маркер шукається в рядку без інлайн-коду.** `@@` у корпусі таки є — 63 штуки в 36
файлах, і всі до одної в backtick-ах: версійні теги ELF (`memcpy@@GLIBC_2.14`), манглінг
MSVC, `@@version` у SQL. Поза кодом — рівно нуль, як і обіцяв замір.

`--latin` — **сирий сигнал для очей, не гейт**: у коді виходу не рахується. Власну назву від
терміна воно відрізняє лише регістром, а юніксові назви пишуться малими, тож
`systemd-nspawn` і `vfio-pci` світитимуться завжди.

`--orphans` **завжди обходить увесь корпус** — сирота це «ніхто ніде не вживає», тож із
фільтрами й `--addr` не поєднується (звужений відбір оголосив би сиротою чинний термін).

## Бібліотека `local/lib/units.js`

```js
const U = require("./lib/units.js");            // з writer_ua/local
const U = require("../local/lib/units.js");     // з writer_ua/checkers
```

### Сталі

`ROOT` `CONTENT` · `VERSIONS` = `["basic","detailed"]` · `INSERTS` = `["hist","comp","math","proj","api"]`
· `TYPES` = обидва разом · `STATUSES` = шість статусів.

### Одиниця

```js
{ book, kind, bookDir, group, chapter, title,
  slug,        // null у вказівника
  part,        // "basic" | "detailed" | "<ім'я вставки без .md>" | "" у вказівника
  insert,      // тип вставки, лише у вставок
  file,        // ім'я файла вставки
  ref,         // ціль, лише у вказівника
  node, topic, // вузли маніфесту — правити ЛИШЕ через lib/manifest.js
  status, level, recode }
```

### Функції

| виклик | що повертає |
|---|---|
| `enumerate({kinds, books})` | масив одиниць; диск **не** чіпає |
| `filter(units, flags)` | відібране; диск читає лише під `--has-file`/`--has-code` |
| `parseArgs(argv)` | `{flags, rest}` — `rest` це те, чого мова відбору не знає |
| `validate(flags)` | кидає на невідомому значенні (статус, тип, вид, книга, група, розділ) |
| `addrOf(u)` | адреса або **`null`** для вказівника |
| `parseAddr(s)` | `{book, slug, part}` або `null` |
| `fileOf(u)` | абсолютний шлях `.md` або `null` |
| `codeDirOf(u)` | тека коду (названа `.md`-носієм) або `null` |
| `byAddrs(addrs)` | `{units, missing, ambiguous}` |
| `stdinAddrs()` | `{given, addrs}` |
| `bookList({kinds, books})` | `[{slug, kind, title, dir}]`, назва з `manifest.json` |

**`byAddrs` не падає на неоднозначній адресі** — віддає її в `ambiguous:[{addr, types}]`,
а решту обробляє. Кинутий виняток убивав трубу з 25 тисяч адрес через одну ваду даних.

**`stdinAddrs().given`** — чи джерело адрес узагалі є; це не те саме, що «прийшла хоч одна
адреса». Труба й перенаправлений файл — джерело; термінал і `/dev/null` — ні (тип fd
визначається бітами `mode`, бо на Windows Node каже `isFIFO() === false` навіть для
справжньої труби).

### Свій скрипт на цій мові

```js
const U = require("./lib/units.js");
const { flags, rest } = U.parseArgs(process.argv.slice(2));
U.validate(flags);
const units = U.filter(U.enumerate({ kinds: flags.kinds, books: flags.books }), flags)
               .filter((u) => u.slug != null);        // вказівники не мають файла
for (const u of units) console.log(U.addrOf(u), U.fileOf(u));
```

## Рецепти

```bash
# що взагалі лишилося писати, по книгах
node writer_ua/local/find.js --status pending --by book

# теми з кодом, які чекають переписування
node writer_ua/local/find.js --book embedded --recode --has-code --count

# зміряти те саме, що відібрав
node writer_ua/local/find.js --book unix --type detailed --ids \
  | node writer_ua/local/count.js --sum

# перевести партію в recheck, але тільки те, що зараз deeper
node writer_ua/local/find.js --book sys-unix --status deeper --ids \
  | node writer_ua/local/status.js --if deeper --set recheck --apply

# знайти написане, що маніфест ще не знає
node writer_ua/local/find.js --status pending --has-file

# і навпаки: обіцяне маніфестом, чого на диску немає
node writer_ua/local/find.js --status done --no-file

# перейменувати тему разом з усім, що на неї вказує
node writer_ua/local/move.js --from sf-visual/homography --to homografiia   # подивитися
node writer_ua/local/move.js --from sf-visual/homography --to homografiia --apply
```

## Межі й пастки

- **Переставляння кроку в курсі** — операції немає; `add` кладе крок у кінець розділу, а
  нумерація курсу йде з порядку в маніфесті.
- **Правило слуга продубльоване** в `add` і `move`; його місце — `lib/units.js`.
- **Дефект даних, знайдений по дорозі:** `comp-history-mpu.md` зареєстровано і під `hist`,
  і під `comp` (`root/eng/sf-lang/data-in-memory.json`) — дві одиниці з однією адресою.
  `find` і `count` про це попереджають, `byAddrs` таку адресу пропускає.
- **`--limit` не змінює підсумків.** `count` рахує медіану по всьому відбору й ріже лише
  показане; `--count` і `--by` у `find` рахують усе.
