# Як тримати ці файли

Два види файлів.

**Спільні** — те, що не залежить від типу: prose, code, formulas, figures, links, language, structure, process.

**На тип — три**, бо це три різні роботи:

    <тип>-goals.md    → запит 1 (ціль) і запит 5 (аналіз)
    <тип>-karkas.md   → запит 2 (каркас)
    <тип>-rules.md    → запити 3, 4, 6, 7 (письмо, дописування, викладка, перепис)

Типів вісім: article, basic, hist, comp, math, proj, api, code.

## Звідки береться вміст

Спільні файли й блоки між `<!-- канон: початок -->` … `<!-- канон: кінець -->` у типових
наповнює `cut.py` — по сенсу, дослівно, без перетину: кожен шматок береться з
`AUTHORING.md` за точним підрядком, і скрипт перевіряє, що він там є. Таблиця маршрутів
у самому скрипті — це і є відповідь, яке речення куди пішло. Поза маркерами типовий
файл правиться руками.

## Дві секції в кожному файлі

**Що знаємо** — усталене: те, що вже вирішено.
**Що треба зробити** — відкрите: дірки й суперечності, рішення за автором.

⛔ Усе, що при різанні канону захотілося дописати від себе, іде в ДРУГУ секцію як питання,
а не в першу як правило. Тоді вигадка фізично не може стати каноном.

## Тип тримає лише РІЗНИЦЮ

Навіщо він існує, чим відрізняється, які спільні файли бере. Інакше буде вісім копій
правил про код, і вони розійдуться.

## Дві шкали рівня, і плутати їх не можна

**Глибина** — math, proj, code: що читач зможе після.
**Обсяг** — article, api, comp, hist: яку частку предмета беремо.
**Без рівня** — basic.
