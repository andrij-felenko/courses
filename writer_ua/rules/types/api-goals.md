# api — правила ЦІЛІ

**опис продукту.** Документація чогось: фізичний пристрій, стандарт — те, що має УНІФІКОВАНУ
документацію. Її не «відтворюють».

Іде в запит 1 (етап 2) і в запит 5 (аналіз). Більше нікуди.

## Треба зробити

Сформулюй, що читач має знати про цей інтерфейс, щоб упевнено ним користуватися: навіщо
він, що йому дати, що він поверне, як поводиться на межі й коли щось пішло не так.
Перелік сигнатур цієї мети не досягає — його читач бачить і без нас; знати інтерфейс
означає знати, чого від нього чекати.

Ціль — це те, що читач має винести, а не перелік підтем.
Ціль зберігається текстом і далі просто передається: аналіз більше не повторюється.

## Рівень

Задає не розмір тексту, а МЕЖУ, де спинитися:

  1 — та частина поверхні, якою користуються щодня
  2 — уся поверхня, якою користуються
  3 — уся поверхня, включно з рідкісним і застарілим

⛔ Рівень каже, яку ЧАСТКУ предмета беремо. Два піни «вичерпно» — це пів сторінки;
велике API «те, чим користуються щодня» — більше за них. Число не задає обсяг.
