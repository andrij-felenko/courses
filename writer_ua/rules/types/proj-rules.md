# proj — правила ПИСЬМА

Іде в запити 3, 4, 6, 7. Це найдорожчий текст у системі: його носить кожен письменник і
перечитує на кожному ході. ⛔ Тут лише те, без чого текст буде НЕПРАВИЛЬНИМ.

## Треба зробити

Проведи крок за кроком так, щоб результат можна було відтворити.

<!-- канон: початок -->
⚙️ `proj-` — **алгоритм/код/реалізація:** **НЕ МУСИТЬ бути голим шматком коду з 2-3 коментарями**. Код мусить мати повноцінне пояснення з першопричин: навіщо розробляється реалізація, яка алгоритмічна та архітектурна ідея стоїть за кодом, як працюють ключові фрагменти, які інваріанти й межі (edge cases) обробляються, та які I/O / складність має рішення. Жорсткі формальні заголовки не потрібні — головне, щоб код був робочим і глибоко поясненим.
