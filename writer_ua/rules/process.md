# process

**Обсяг:** статуси, маніфест — тільки оркестраторові

## Треба зробити

<!-- канон: початок -->
**Маніфест — єдине джерело** навігації, плану, черги, статусів. **Схема 7, JSON, розбита по групах**; нові поля поза схемою не вигадуємо.

```
root/<вид>/<книга>/manifest.json     { schema:7, kind, slug, title, groups:[слуг…] }
root/<вид>/<книга>/<група>.json      { schema:7, kind, book, slug, title, scope,
                                       chapters:[ {slug, title, topics:[…]} ],
                                       megachapters?:[{title, chapters:[слуг…]}] }   ← НЕ рендериться
```

Тема в розділі — **або власна**, **або вказівник** на чужу (тільки в курсах):

```json
{ "slug": "…", "title": "…",
  "basic":    { "status": "…" },
  "detailed": { "status": "…" },
  "hist": [ { "file": "hist-<name>.md", "status": "…" } ],
  "comp": [ … ], "math": [ … ], "proj": [ … ], "api": [ … ] }

{ "ref": "<книга>/<тема>", "title": "…" }
```

**Кожна версія (`basic`, `detailed`) має власний `status`** (enum §9); версія доступна читачу ⟺ її статус `done`. Вставки — масив на тип, елемент `{file, status}`.

**Група й розділ живуть ТІЛЬКИ тут.** У шляху їх немає, тема лежить пласко під книгою. Тому перекроїти книгу — правка одного JSON, а не рух файлів. Нумерація курсу (Модуль · Розділ · Крок) рахується з **порядку** в маніфесті, не з поля-числа.

**Маніфест руками не редагують.** Письменник маніфесту не чіпає взагалі: статуси розставляє окрема фаза батчу.

**Обсяг і гейт базової тут НЕ живуть.**

- Смуги обсягу — `runners/local.js`, `BANDS`. Це рішення автора, і воно свіжіше за
  канонні числа; агентові смуги не показують — показане число стає ціллю.
- Чи треба базова — вирішує конвеєр без агента, етап 10 `algorithm.js`: детальна довша
  за стелю базової в півтора раза, або етап 2 сказав «бажана». Це рішення автора.

⛔ Копію сюди НЕ повертати. Вона тут уже лежала — написана, повна й мертва, бо цього
файла не читає жоден агент; а щойно з'явився живий примірник, мертвий став другим
джерелом правди, яке розходиться мовчки.

**Цілі ще нема — створюємо й ref-имо заздалегідь.** Ціль — або **тема-стаття**, або **допоміжна вставка** (історія/приклад/математика/пристрій — `<type>-<name>.md`):
1. Визнач **правильне місце** (тема — книга+галузь; вставка — тека теми).
2. Створи **порожній файл** (md теми або `<type>-<name>.md`).
3. **ПЕРЕД заведенням — перевір, чи це не СИНОНІМ наявної теми.** Три патерни, на яких
   корпус набрав понад тридцять пар дублів, і застереження «схожа назва — ще не дубль»
   живуть в `rules/links.md`: цей файл їде письменникові, а той, що ти читаєш, — ні.
   ⛔ Другого примірника патернів тут не заводити.

4. Зареєструй у маніфесті: тема — **`basic:{status:"empty"}` + `detailed:{status:"pending"}`** (у чергу йде **детальна** — вона основна версія, §3; базову вирішують ПІСЛЯ детальної: вийшла велика — тоді `basic:pending`). Вставка — `pending` у масиві свого типу. **Новій темі `basic:pending` не ставимо.**
4. Постав ref — попап покаже стаб, **підтягне текст** по заповненні.

 (У конвеєрі `write-batch.js` це поле `newTopics` автора статті; фаза «Маніфест» реєструє нове як `pending` і відсіює дублі.)

**Опційний файл правил книги — `<тека-книги>/_canon.md`.** Якщо в корені книги/курсу/каталогу/довідника лежить `_canon.md` (`root/<вид>/<книга>/_canon.md`, `root/course/<курс>/_canon.md`, `root/cat/<каталог>/_canon.md`, `root/sys/<довідник>/_canon.md`) — це **додаткові правила саме для неї** понад цей загальний канон: наскрізний приклад, єдині терміни та імена, мова прикладів, стильові домовленості. Письменник (і статті, і вставки) **першою дією читає його**, якщо він існує, і суворо тримається — там, де `_canon` уточнює загальне, **перевагу має `_canon`**. **Файлу немає → для цієї книги/курсу/каталогу/довідника додаткових правил немає**, пишемо за загальним каноном. (Технічно `write-batch` перевіряє наявність файлу перед письмом кожної теми.)

**Статуси (enum у маніфесті, на КОЖНУ версію `basic`/`detailed` й КОЖНУ вставку):** `done` (написано, канон, доступно читачу) · **`pending`** (**треба написати** — саме це беруть скрипти-письма) · **`empty`** (**писати НЕ треба** — версія/вставка не передбачена) · `update` (переписати) · `deeper` (поглибити; зокрема — на тему посилаються як на детальну `/detail`, §6) · `recheck` (передивитися за чинними правилами; **явні неточності** — число/факт/дата/одиниця/формула/логіка — виправляємо точково, але **готове не переписуємо**). Міняємо **прямо в маніфесті** одразу після правки. *(Зміна v4→v5: раніше `empty` означало «не почато» — тепер це `pending`; `empty` = «не потрібно».)*

**Процес.** Беремо **найперший** `pending`/`update`/`deeper`/`recheck` (саме **`pending`** — черга на письмо; `empty` НЕ беремо, це «не треба»). **Одна версія = один хід** (текст + фігури + статус версії→`done`). Великий крок **делегуємо сабагенту** з повними шляхами; у головну loop-сесію — лише короткий звіт.

**Порядок у батчі — детальні, тоді базові.** Черга набирається з **пріоритетом на `detailed`**; `basic` беремо, лише коли детальних у черзі не вистачає. Пишемо **спершу всі детальні**, і вже за готовою детальною вирішуємо, **чи потрібна їй базова**. Виходів рівно три: базова **вже написана** → **нічого не міняємо** (ні файла, ні статусу); базової **нема й вона потрібна** (детальна велика, §3) → пишемо її на наступному етапі; базової **нема й вона не потрібна** (детальна коротка/вузька) → `basic:empty`, і то лише якщо стояло `pending` (інших статусів не рухаємо). Аж тоді пишемо базові: **ті, що знайшов скаут, плюс ті, що додалися після детальних**. Далі — вставки, локальний гейт фігур, маніфест. **Нові залежні теми (§6) можуть зʼявитися на будь-якому етапі** — і зі статті, і зі вставки; усі вони реєструються `basic:empty` + `detailed:pending`.

**Паралельність.** Маніфест **один на книгу/курс/каталог/довідник** → ізоляція **по книзі**: кілька `/loop` працюють паралельно, лише якщо кожен — у **своїй** книзі/курсі. Двох `/loop` на одну книгу **не запускати** (спільний маніфест → конфлікт). Працюй лише в маніфесті своєї книги.

**Дисципліна.** **Слідуй інструкціям точно — завжди.** Узгоджену чи готову структуру/зміст **самовільно не міняй** і не чіпай того, що просили не чіпати. Бачиш, як покращити, — **спершу спитай** (про структуру й зміст), не роби сам.
