# Конвеєр книг: як це працює

Це **операційні** правила (вантажаться самі). Пояснення «чому саме так» і повна таблиця
перевірок — `agents/antigravity/pipeline.md`. Канон письма — `AUTHORING.md`. Тут механіка.

## Три ролі, які не суміщаються

| роль | агент | що робить |
|---|---|---|
| автор | `write-topic` | пише статті, вставки, `figs.py` |
| дописувач | `grow-file` | доводить ОДИН `.md` до підлоги його рівня. Нічого не переписує наново |
| суддя | `check-all` | проганяє гейт, читає теку ОДИН раз, кладе вироки під усіма номерами. **Інструментів запису не має** |
| ремонтник | `repair-topic` | переписує рівно те, що завалили перевірки |

Хто пише — не судить, хто судить — не править: у суддів немає інструментів запису, в решти —
доступу до `verdict.js`.

## Виклик сабагента

`invoke_subagent`, один спек на агента; кілька спеків — паралельно.

* `TypeName` — ім'я з `.agents/agents/<name>/agent.md`; `Role` — чия це робота;
* `Prompt` — **шлях теки теми** плюс, для ремонтника, дефекти з доказами дослівно: сабагент
  стартує з чистим контекстом, усе потрібне має бути в промпті;
* `Workspace` — **завжди `inherit`**: `branch` кладе правки в іншу копію репо.

**Суддя на тему ОДИН**, розводити перевірки по агентах **заборонено**.
Забути щось не може — вирок кладеться під СВОЇМ
номером, і гейт червоний, доки номер порожній. Порядок непорушний: **11-та ПЕРША, до файлу**.

## Правила книги — `_canon.md`

Є **`<вид>/<книга>/_canon.md`** — його читає **ПЕРШОЮ дією КОЖЕН агент**: автор, дописувач,
суддя, ремонтник. Це правила саме цієї книги; де уточнює загальне — перевага за ним, де мовчить —
`AUTHORING.md`. Судді це потрібно не менше: не знаючи домовленостей, він визнає дефектом
свідоме рішення.

## Цикл теми

```
write-topic пише тему (або grow-file дописує файл)
     ↓
node scripts/checks/gate.js "<тека теми>"     0 = ГОТОВО · 4 = ЗАСТІЙ, до людини · 1 = далі
     ↓
ОДИН check-all на тему: 11-та сліпо, тоді читання теки, тоді вироки під усіма номерами
     код 1 — дефекти вже перелічив скрипт, вироку не треба
     код 2 — вирок на кожен пункт: ok (закрито) | defect (у ремонт)
     ВСІ дефекти кола йдуть в ОДИН repair-topic, а не по одному
     ↓
repair-topic переписує рівно те, що завалилось   (дефект 13-ї — назад до write-topic)
     ↓
знову gate.js
```

**Вирок прив'язаний до хеша пункту:** переписаний текст його протухає.
**Стеля — 2 кола НА НЕЗМІННОМУ ТЕКСТІ** (`CHECKS_MAX_ROUNDS`), далі `4` — до людини. **Коло —
це зміна, а не запуск.**

## Команди

```
node scripts/checks/gate.js "<тека>"                    # стан теми: 0 / 1 / 4
node scripts/checks/gate.js --topics "<тека>" …         # по кількох; --batch <файл>
node scripts/checks/NN-*.js "<тека>"                    # одна перевірка
node scripts/checks/verdict.js NN "<тека>" --item <N> --status ok|defect --proof "<доказ>"
   кілька --item в ОДНОМУ виклику — серія вироків;  --list — пункти й вироки
node scripts/antigravity/newtopic.js --book … --kind … --section … --slug … --title … --why … --meets <ознаки>
node scripts/manifest-patch.js <книга> --ops <json>   # op:status приймає level (deeper) і recode
node scripts/antigravity/inserts.js --batch <файл> --list | --apply <рівні.txt>
node scripts/antigravity/update-queue.js --book … [--status deeper,update] [--limit N] [--write]
node scripts/antigravity/assess-gate.js --batch <файл> [--inserts]   # 1 = оцінювати НАНОВО
node scripts/antigravity/finish-batch.js --book … --kind … [--batch <файл>] [--apply]
node scripts/audit-layout.js                            # диск ↔ маніфест
```

Команди — з кореня репо; шлях теки і відносний, і абсолютний.

## Сімнадцять перевірок, один суддя

`01` формули · `02` мова · `03` фігури · `04` текст у фігурах · `05` лінки й вставки · `06` обсяг ·
`07` числа · `08` арифметика · `09` терміни · `10` факти (вебпошук) · `11` вступ (СЛІПО, перша) ·
`12` нитка · `13` гейт базової · `14` пояснення чи підручник · `15` обґрунтованість тверджень ·
`16` зобов'язання теми · `17` де є C — має бути й C++.

Усі сімнадцять судить `check-all` за одне читання теки. **03, 04, 05 вироку не потребують** —
там його дає скрипт. **13 і 16** повертаються АВТОРОВІ: це нова робота (написати базову,
дописати обіцяну вставку), а не правка наявного.

Судять **читанням**, ніколи списком слів. Виняток — заборонені каноном ФОРМИ (сирий LaTeX,
«у цій статті ми розглянемо»). Вирок без доказу `verdict.js` відкидає сам.

## Обсяг: рівень розкриття підіймає підлогу

**Спільного орієнтиру немає** — показане число стає ціллю (довідник §4). Число **своє на
кожну тему**: рівень підіймає **нижній** край смуги, верхній спільний для всіх рівнів.
Драбина **одна на всі види, крок наростає**: Р5 стоїть на ПОЛОВИНІ смуги, вище — зона
винятку. Підлогу друкує `06-size.js`, таблиця — `agents/antigravity/pipeline.md`.
**Базова рівня не має**: смуга 650–1550.

⛔ **Підлоги не бачить той, хто пише.** Ні в завданні, ні в доборі, ні в звіті — числа
живуть у гейті й в оркестратора. Дописувачеві кажуть роботу словами: «розкрито мілко,
поясни повніше, розпиши суть, яку могли пропустити». Заміряно 29.08 на `ph-condensed`:
з числом у промпті дев'ять статей лягли в межах ±2% від підлоги свого рівня — писали в
мішень, а не за предметом.

Нижче підлоги — дефект. Понад стелю — дефект (ділити тему). Переріс зону під стелею —
рівень недооцінили, текст правильний; на дві зони вище своєї — вирок «рівень занижено чи
текст роздутий», судиться **читанням**. **Скорочувати заборонено:** недобір лікується
дописуванням, перебір — поділом.

### Рівень: хто ставить і де лежить

Ставить **окрема фаза оцінки**, **не той, хто писатиме**: оцінювач розкладає одиниці батчу
**одну проти одної** — спершу полюси, тоді решта.

Р1 дотична · Р2 звичайна · Р3 робоча (спираються сусіди) · Р4 несуча (без неї розділ не
читається) · Р5 наріжна (книга стоїть на ній). Ознаки: скільки тем назвали її в
`<preknowlist>` · чи вона ціль `ref` у курсі · скільки механізмів показати (1 · 2–3 · 4–6 · >6).

**Розкладку приймає гейт:** `assess-gate.js` бачить батч як ціле й відхиляє той, де майже все
дотичне (`--inserts` — по вставках). Відхилив — оцінка НАНОВО: свіжий агент, той самий промпт.
⛔ **Порогів оцінювачеві не показують.** Переоцінка ТИХА. Третє відхилення — до людини.

**При `deeper` рівень лежить У МАНІФЕСТІ** — `"detailed": {"status":"deeper","level":4}`: там це
не параметр прогону, а вже виміряний факт (оцінювачі + `levels-recount.js`), і дописувач бере
глибину звідти, не вигадуючи своєї. Поле тимчасове — `finish-batch` знімає його зі статусом.
Інакше рівень живе **у батч-файлі прогону** `scripts/_finish/_batch-<книга>.json`:
`{ "dir": …, "level": 3, "inserts": { "proj-x.md": 2 } }` — параметр прогону, не файл у теці.

**Дві фази оцінки, і в обох оцінює не той, хто пише.** Теми — на старті батчу. **Вставки — після
письма** (`inserts.js --list` → агент → `--apply` → `assess-gate --inserts`): наперед вставки не
існує, а щойно письменники відпрацювали, усі імена на диску. Спершу аналіз, тоді межі. Письменник
не оцінює нічого. Рівень вставки рівню теми **не дорівнює**.

**Рівень не міняється посеред письма.** Не вліз — це привід дописати, а не понизити оцінку.
Єдиний законний вихід — звіт «НЕМА ЧОГО ДОДАТИ» з доказом, які напрямки матеріалу в цій темі
порожні й чому; рішення ухвалює людина. Рівня в цьому звіті немає: дописувач підлоги не бачив,
тож і пропонувати замість неї іншу не може.

## Гейт базової (перевірка 13)

Детальну пишемо завжди, базову — за потреби, і потреба рідкісна. Рішення ухвалюють **за готовою
детальною**: `< 3150` слів прози — базової не пишемо · `3150–5600` — вирішує зміст (ознаки §3,
вагання → ні) · `> 5600` — базова потрібна, дефолт «ні» тут не діє. Дефект 13-ї — авторська
робота, не ремонтна.

## Що означає «тема закрита» (перевірка 16)

Тема закрита, коли справджуються всі:

1. **детальна** написана; **рішення про базову** ухвалене (13-та);
2. **кожна вставка** — обіцяна в прозі `root:`-лінком і записана в маніфесті `pending` — написана;
3. **кожне вагоме поняття**, на яке стаття спирається, має тему або стоїть у черзі нових;
4. усі 17 перевірок дали `0`.

Аж тоді `finish-batch.js` ставить `detailed: recheck`, `basic: recheck|empty`, вставки
`recheck` — і **щойно тоді ж** реєструє нові теми з черги (`basic:empty` + `detailed:pending`).

**Чому `recheck`, а не `done`:** сімнадцять перевірок означають «конвеєр свою частину зробив»,
а не «людина це читала». У `done` переводить людина, не батч.

**`recode: true` — завжди, де є код.** `finish-batch` ставить його кожному файлу цього
конвеєра з кодом: тут краще пишуть прозу, тож код за означенням чекає на переписування.
Поки прапорець стоїть, 06-та код **міряє, але дефекту не дає**.

### Вставка чи нова тема — рішення свідоме (§6)

**Вставка** — матеріал ЦІЄЇ теми (історія механізму, виведення формули): поза статтею він не
має власного читача. **Тема** — самостійне поняття, на яке стаття лише **спирається**: про
нього можна написати статтю, яку читатимуть окремо. Планка — рахунок: чотири ознаки (`too-big`, `key`,
`eases`, `searchable`), вистачає ДВОХ, перелічуєш їх у `--meets`. Поняття чужої галузі йде в ІНШУ книгу
(`--book math`), не відкидається. Заводить `newtopic.js` — у чергу, не в роботу; стеля дві на
статтю. Лінк ставиться одразу й битим не вважається.

Перевір, чи це не синонім наявної: `aslr` ↔ `rop-and-aslr`, `ksm` ↔ `ksm-page-merging`.
Знайшов близьке — ref-ни наявну.

## Код лежить у файлах

Блок від **10 рядків** іде у файл `<тема>/<ім'я .md без розширення>/<мова>/…` —
`i2c-bus/proj-driver/c/main.c`, `…/cpp/Ring.hpp`. Тека названа файлом-носієм, тому `proj`
і `api` однієї теми не стикаються; дрібніше лишається в прозі. Тека мови — **корінь
проєкту**: звичайна для мови розкладка (`rust/src/`, пакет Python), розбиття на модулі як
у справжніх проєктах, **спірно — розбивай**. З прози — `:::code <шлях>`, по одному
на вкладку `:::tabs`.

Підлога — на **кожну мову**, з рівня; числа друкує гейт. Роль
названа прямо: **професіонал показує студентам, як це працює, і пише при них**: програма
мусить працювати, але будується не для користувачів і не для ринку.

Пиши те, **про що файл**: про збірку — `CMakeLists.txt`, про тести — тести, про
тулчейн — тулчейн. Решта — обв'язка: README ніколи, конфіг середовища чи
скрипт відлагоджувача — лише як предмет, файл збірки — лише коли без нього не запустити.
Обв'язка й тести в залік не йдуть; скрипти (`sh`, `sql`, `cmake`) дістають файл без
підлоги. Код реалізує **все**, що проза назвала механізмом: ні «за аналогією», ні заглушок.

## Батч і маніфест

```
перед:  node scripts/audit-layout.js <вид>/<книга> — тека ≠ секція ламає запис маніфесту
старт:  список тем батчу → scripts/_finish/_batch-<книга>.json
оцінка: ОДИН агент розкладає теми одна проти одної → рівень 1–5 кожній, назад у той самий
        файл: [{"dir": …, "level": N}, …] → assess-gate.js: код 1 = оцінювати НАНОВО
письмо: теми своїми циклами, ≤4 одночасно; рівень іде письменникові в завданні
нове:   помітив залежну тему → newtopic.js (У ЧЕРГУ, не в роботу й не в маніфест)
кінець: усі теми дали gate = 0 → finish-batch.js --apply
```

**Маніфест чіпаємо раз — останнім рядком:** `finish-batch.js` сам ганяє гейт і не пише нічого,
доки хоч одна тема не готова.

## Дописування вже написаного — `/update-batch`

Файл у статусі **`deeper`** («правильний, але мілкий») чи `update` — свій цикл. Робота
**файлова** (статус має кожна версія і вставка окремо), суд — темний. Чергу дає
`update-queue.js` (дефолт `deeper,update`; файли під `recode` пропускає — спершу код,
тоді глибина), дописує `grow-file`, далі гейт, суд, ремонт,
`finish-batch`. `deeper` ставить `levels-recount.js`: рівень проти обсягу прози, Δ ≥ 2 — мілко.

Дописувач, якому нема чого пояснювати далі без води, **зупиняється й пише «НЕМА ЧОГО ДОДАТИ»**
з доказом; рівня не міняє — рішення за людиною.

## Заборонено

Ставити `done` за власною заявою · правити `manifest.json` будь-чим, крім `finish-batch.js` ·
зводити в одного агента перевірки поза таблицею вище (і розводити зведені) · спавнити сабагента
з `Workspace: branch` · судити текст, який сам написав, і правити текст, який сам судив ·
**ставити рівень темі, яку сам писатимеш, і міняти свій рівень посеред роботи** · лікувати обсяг
чи ясність скороченням · починати нову тему посеред батчу · чіпати щось поза текою своєї теми ·
запускати наступний пакет, доки поточний не дав `gate = 0` · робити `git commit`.
