# Перевірка 16 — зобов'язання теми

Тобі дають **одну теку теми**. Твоє питання одне: **чи можна цю тему закрити — чи в ній
лишились обіцянки без файлів.**

Тема закрита, коли детальна на диску, рішення про базову ухвалене (це 13-та), **кожна** вставка,
обіцяна в прозі або записана в маніфесті, написана, і кожне вагоме поняття, на яке стаття
спирається, або має тему, або вже стоїть у черзі нових.

Без цієї перевірки тему можна «закрити» з діркою: проза кличе `math-`-вставку, файла немає,
маніфест і далі тримає її `pending` — і ніхто цього не побачив.

## 1. Прожени

```
node scripts/checks/16-promises.js <тека>
```

* `1` — **зобов'язання не виконані**: перелік у виводі. Це робота **автора** (`write-topic`),
  не ремонтника: писати вставку — авторська справа. Перепиши перелік у звіт дослівно;
* `2` — механіка чиста, лишилось питання про прогалини плану. Далі крок 2.

## 2. Прогалини плану

Пройдись по вагомих поняттях, які стаття **припускає відомими** або на яких **тримається**. По
кожному перевір, чи є така тема:

```
grep -n "<слуг>" book/*/manifest.js reference/*/manifest.js catalog/*/manifest.js
```

Маніфести пишуть ключ у лапках (`"slug": "…"`) — шукай саме так.

Поріг — **справжня залежність**, без якої теми не зрозуміти, а не кожна побіжна згадка. Немає
ніде — це прогалина плану, а не привід прибрати згадку: краще зайвий стаб, ніж мовчазна діра.

**Перед заведенням перевір, чи це не синонім наявної теми.** Три пастки, на яких це ламається:
вужче й ширше про те саме (`aslr` ↔ `rop-and-aslr`) · абревіатура й розшифровка
(`ksm` ↔ `ksm-page-merging`) · два боки одного механізму. Знайшов близьке — теми **не заводь**,
хай стаття ref-иться на наявну.

## ⚖️ Вставка чи тема

Рішення ухвалюється свідомо, і воно не про обсяг:

* **вставка** — матеріал **цієї** теми: історія цього механізму, виведення цієї формули, проект
  на цьому предметі, поверхня саме цієї речі. Файл у теці теми. Ознака: поза цією статтею
  матеріал не має власного читача;
* **тема** — самостійне поняття, на яке стаття лише **спирається**. Ознака: про нього можна
  написати статтю, яку читатимуть, не читавши цієї. Заводиться в чергу:

```
node scripts/antigravity/newtopic.js --book <книга> --kind <вид> --section <секція> \
     --slug <слуг> --title "<назва>" --why "<навіщо>" --from "<тека, що породила>"
```

Це кладе тему **в чергу**, не в маніфест і не в роботу: зареєструє її `finish-batch.js`
наприкінці батчу як `basic:empty` + `detailed:pending`. Лінк на таку тему битим не вважається —
05-та знає про чергу.

Помилка в будь-який бік дорога: самостійне поняття, заховане у вставку, читач не знайде пошуком;
роздута до теми вставка розриває нитку статті.

## 3. Вирок

```
node scripts/checks/verdict.js 16 <тека> --item <N> --status ok|defect --proof "<що показав grep>"
```

Доказ «ok» — перелік понять із результатом `grep` по кожному. Доказ «defect» — чого бракує і що
саме покладено в чергу.

## 4. Прожени знову

Доки код не стане `0` або доки пункт не матиме вироку.

## Три залізні правила

1. **Одна перевірка — твоя.** Цілісність самих лінків — не сюди, це 05-та.
2. **Доказ, а не заява.** У звіті — дослівний вивід команди й результати `grep`.
3. **Нічого не переписуєш.** Не чіпаєш `manifest.js` (його править лише `finish-batch.js`
   наприкінці батчу), не виходиш за теку своєї теми, не робиш `git commit`.
