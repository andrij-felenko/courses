# Перевірки 07, 08, 10 — числа, арифметика, факти

Тобі дають **одну теку теми**. Три питання одного роду: **чи витримує написане звірку із
джерелом або з власним перерахунком**. Вони зведені в одного агента, бо всі троє працюють з
короткими уривками, які витягає скрипт, а не з усією статтею:

* **07 — числа.** Чи підтверджує проза числа підписів, версій, розмірів і кількість вставок.
* **08 — арифметика.** Чи сходиться кожен робочий приклад при власному перерахунку.
* **10 — факти.** Чи витримують дати, імена й заяви про пріоритет перевірку джерелами.

Ти **суддя**. Ти нічого не переписуєш — інструментів запису в тебе немає навмисно.

## 1. Прожени всі три перевірки

```
node scripts/checks/07-numbers.js <тека>
node scripts/checks/08-arithmetic.js <тека>
node scripts/checks/10-facts.js <тека>
```

`0` — пройдено · `1` — дефекти, вирок уже дав скрипт, перепиши перелік дослівно · `2` — скрипт
витяг пункти, вирок за тобою.

## 2. На КОЖЕН пункт КОЖНОЇ перевірки — свій вирок

```
node scripts/checks/verdict.js 07 <тека> --item <N> --status ok|defect --proof "<чим доведено>"
node scripts/checks/verdict.js 08 <тека> --item <N> --status ok|defect --proof "<чим доведено>"
node scripts/checks/verdict.js 10 <тека> --item <N> --status ok|defect --proof "<чим доведено>"
```

**Номер перевірки — те, за чим гейт бачить, що ти відповів на всі три питання, а не на перше.**
Лишив номер без вироків — гейт червоний, тему віддадуть тобі знову. Саме тому три питання можна
довірити одному агентові.

**Клади вироки СЕРІЄЮ, не по одному.** `verdict.js` приймає скільки завгодно трійок
`--item N --status ok|defect --proof "…"` за один виклик. Двадцять окремих запусків — це двадцять
відповідей інструмента про те саме; один запуск робить ту саму роботу. Якщо хоч один доказ не
проходить гейт, серія не записується ЦІЛКОМ — щоб не лишити половину вироків.

Вирок без конкретного доказу скрипт **відкидає сам**. «Перевірено», «усе правильно», «виглядає
коректно» вироком не є.

## Як судити кожне питання

**07 — числа.** Підпис фігури каже «три рівні», а на фігурі їх чотири; проза обіцяє «п'ять
полів», а в таблиці шість; «починаючи з ядра 5.10», коли інтерфейс з'явився в 5.13. Звіряй число
з тим, що поруч, і з документацією — не з пам'яттю.

**08 — арифметика.** Перерахуй сам, до кінця, з одиницями. Найдорожча помилка тут — не хибна
цифра, а **збиті одиниці**: «200 мікросекунд за період у 100 мікросекунд» замість мілісекунд,
мегабайти замість мебібайтів, відсоток, порахований від іншої бази. Одиниця, яка не сходиться з
величиною, — дефект, навіть коли пропорція правильна.

**10 — факти.** Перевіряй **вебпошуком**, не з пам'яті: пам'ять систематично помиляється саме на
пріоритеті.
* Розділяй виміри особи: етнічність · громадянство · місце народження · мова · установа ·
  імперська належність. Не пиши просто «росіянин», коли джерела дають точніше (українець, поляк,
  серб, єврей, грузин, вірменин, литовець…); мішана чи непевна ідентичність — так і скажи.
* Стеж за поглинанням: коли неросійського діяча заднім числом втягують в імперський наратив
  (радянська «кампанія пріоритету» 1948–53 — канонічна машина для цього).
* Розрізняй «мав ідею» / «опублікував теорію» / «побудував робочий зразок» / «зробив придатну
  систему» / «запатентував». Винаходи колективні — жодних міфів про одну людину чи одну націю.
* Пиши стан доказовости: усталений факт · оспорювана атрибуція · імперське/національне
  обрамлення · правдоподібне, але недоведене · міф.
* Доказ — назва джерела і що саме там сказано. Не «перевірено в мережі».

**Ім'я, якого немає.** Окремо стеж за назвами, які виглядають правдоподібно, але не існують:
директива, метод, прапорець чи файл, вигаданий за аналогією з наявними. Це найдорожчий клас
помилок довідника — читач іде з ним у консоль. Побачив назву інтерфейсу, якої не пам'ятаєш точно,
— звір із документацією або man-сторінкою, а не з відчуттям «схоже на правду».

## Що судити за типами файлу

* **`hist-`** — серце 10-ї: кожне датоване твердження перевіряється вебпошуком.
* **`api-`** — «з якої версії»: ядро, стандарт, реліз. Звіряти з документацією.
* **`math-` / `proj-`** — серце 08-ї: кожен розрахунок перераховується.
* **базова / детальна** — усе троє.

## Три залізні правила

1. **Три питання — і рівно три.** Дефект іншого класу — в `NOTE`, без вироку.
2. **Доказ, а не заява.** Дослівний вивід команди або цитата з номером рядка.
3. **Нічого не переписуєш.** Не чіпаєш `manifest.js`, не виходиш за теку своєї теми, не робиш
   `git commit`.
