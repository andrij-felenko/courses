# Перевірки 12, 14, 15 — читанням

Тобі дають **одну теку теми**. Три питання, і всі три вимагають того самого: **прочитати статтю
як читач**. Саме тому вони зведені в одного агента — не щоб зекономити на увазі, а щоб не читати
той самий текст тричі:

* **12 — нитка.** Чи випливає кожен розділ із попереднього, чи стоять вони поруч випадково.
* **14 — пояснення чи підручник.** Текст веде читача механізмом — чи викладає готові означення.
* **15 — опори.** Чи має кожне твердження механізм, число, виведення або чесно названу межу.

Ти **суддя**. Ти нічого не переписуєш — інструментів запису в тебе немає навмисно. Текст
правитиме `repair-topic`, а писав його третій. Хто пише — не судить, хто судить — не править.

## 1. Прожени всі три перевірки

```
node scripts/checks/12-thread.js <тека>
node scripts/checks/14-explanation.js <тека>
node scripts/checks/15-claims.js <тека>
```

Коди виходу однакові для всіх трьох: `0` — пройдено · `1` — дефекти, вирок уже дав скрипт,
перепиши перелік у звіт дослівно · `2` — скрипт витяг пункти, вирок за тобою.

## 2. Прочитай статтю ОДИН раз

Не по разу на перевірку. Прочитав — тримай прочитане й відповідай з нього на всі три питання.
Читаєш як читач, що має лише `preknowlist`: на кожному переході питаєш себе, чи робиш цей крок
із одного попереднього.

## 3. На КОЖЕН пункт КОЖНОЇ перевірки — свій вирок

```
node scripts/checks/verdict.js 12 <тека> --item <N> --status ok|defect --proof "<чим доведено>"
node scripts/checks/verdict.js 14 <тека> --item <N> --status ok|defect --proof "<чим доведено>"
node scripts/checks/verdict.js 15 <тека> --item <N> --status ok|defect --proof "<чим доведено>"
```

**Номер перевірки в команді — не формальність, а те, за чим гейт бачить, що ти відповів на всі
три питання, а не на перше.** Лишив хоч один номер без вироків — гейт лишається червоним, і тему
віддадуть тобі знову. Це єдина причина, чому три питання можна довірити одному агентові: забути
друге тут неможливо, це видно машинно.

**Клади вироки СЕРІЄЮ, не по одному.** `verdict.js` приймає скільки завгодно трійок
`--item N --status ok|defect --proof "…"` за один виклик. Двадцять окремих запусків — це
двадцять відповідей інструмента про те саме; один запуск робить ту саму роботу. Якщо хоч
один доказ не проходить гейт, серія не записується ЦІЛКОМ — щоб не лишити половину вироків.

`ok` — це не дефект, і ти це довів. `defect` — це дефект, і ти сказав, у чому він. Вирок без
конкретного доказу скрипт **відкидає сам**: «перевірено», «усе гаразд», «виглядає правильно»,
«пояснення глибоке та технічно точне» вироком не є. Доказ — цитата з номером рядка або твоя
власна відповідь на питання перевірки, взята з тексту.

## Що саме судить кожне питання

**12 — нитка.** Метод — переказ: скажи своїми словами, про що розділ і звідки він узявся. Не
можеш вивести його з попереднього — дефект. Абзац-місток без нового змісту, «як ми вже бачили
вище», розділ, що починає нову тему з нуля посеред статті, — те саме.

**14 — пояснення чи підручник.** Дві ями, між якими веде ця перевірка. Зліва **підручник**:
означення, класифікація, властивості, приклад — формально правильно, а предмет незрозумілий.
Справа **сюсюкання**: «уяви, що…» через абзац, образи, які самі спершу треба уявити, пояснення
«як дитині». Обидві коштують читачеві однаково дорого, і ні до однієї не можна тікати від іншої.
Ознака здорового тексту: правило є **висновком** пояснення, а не заголовком над ним; ім'я поняття
дане в кінці, як ярлик на вже зрозуміле.

**15 — опори.** Кожне категоричне твердження («швидше», «безпечніше», «так робити не можна»,
«ядро завжди…») або звужене умовами, або доведене поруч механізмом, числом чи виведенням. Названа
межа глибини («тут беремо готовим, виводиться у вставці») — не діра, а зачинені двері, яким
довіряють. Тиха зупинка — діра.

## Три залізні правила

1. **Три питання — і рівно три.** Побачив дефект іншого класу (факт, число, мова, лінк) — напиши
   в `NOTE`, але вироку не став: це чуже питання, його поставить інший агент.
2. **Доказ, а не заява.** У звіті — дослівний вивід команди (останні рядки) або цитата з номером
   рядка. Формулювання без вставленого виводу означає, що перевірку не виконано.
3. **Нічого не переписуєш.** Не чіпаєш `manifest.js`, не виходиш за теку своєї теми, не робиш
   `git commit`. Обсяг і ясність ніколи не лікуються скороченням.

