# ⚙️ ESP-01S у мережі: під'єднатися до Wi-Fi і керувати світлодіодом із браузера

Найдешевша Wi-Fi-плата варта своїх копійок лише тоді, коли реально виходить у мережу й слухає команди. Доведімо ESP-01S саме до цього: під'єднаємо її до домашньої точки доступу як клієнта, а тоді піднімемо на ній крихітний веб-сервер, що вмикає й вимикає світлодіод із браузера телефона. Дорогою розберемо, чому `WiFi.begin` не блокує, звідки береться IP-адреса, з чого насправді складається HTTP-сервер — і які дві пастки (просіле живлення на піку передачі й активний низький рівень LED) чигають саме тут.

Прошивати плату ми вже вміємо: конфігурацію Arduino IDE, вхід у завантажувач через GPIO0 і рецепт `esptool` зібрано окремо в [довідці з прошивки ESP-01S](topic:boards/esp-01s/api-flash-esp01s.md). Щоразу, коли нижче сказано «заллємо цей скетч», мається на увазі саме той танець: притиснути GPIO0 до землі, скинути, залити, відпустити GPIO0, скинути ще раз. Код пишемо в тому ж Arduino IDE з ядром ESP8266 — воно дає бібліотеку `ESP8266WiFi`, що ховає всю ініціалізацію радіо за кількома рядками.

## Вийти в Wi-Fi

Уся магія радіо ховається за бібліотекою `ESP8266WiFi`: ви кажете «під'єднайся ось до цієї мережі», а вона сама налаштовує радіоблок, проходить рукостискання WPA2 і бере IP-адресу по DHCP.

Ось скелет, який під'єднується до вашої точки доступу й **блимає світлодіодом, поки триває під'єднання** — зручний живий індикатор: миготить швидко → ще шукає мережу; засвітився рівно → у мережі.

:::tabs
```cpp
#include <ESP8266WiFi.h>

const char* SSID = "ВашаМережа";        // ім'я вашої Wi-Fi
const char* PASS = "ВашПароль";         // пароль WPA/WPA2

const int LED = 2;                       // GPIO2, активний НИЗЬКИЙ

void setup() {
  pinMode(LED, OUTPUT);
  digitalWrite(LED, HIGH);               // погашено

  Serial.begin(115200);                  // щоб бачити діагностику
  Serial.println();

  WiFi.mode(WIFI_STA);                   // режим клієнта (station), не точки доступу
  WiFi.begin(SSID, PASS);                // почати під'єднання

  Serial.print("Під'єднуюсь до ");
  Serial.print(SSID);

  // чекаємо мережу, блимаючи LED, поки статус не стане «під'єднано»
  while (WiFi.status() != WL_CONNECTED) {
    digitalWrite(LED, LOW);              // блимнути (LOW = світиться)
    delay(100);
    digitalWrite(LED, HIGH);
    delay(100);
    Serial.print(".");
  }

  digitalWrite(LED, LOW);                // у мережі — лишаємо LED засвіченим
  Serial.println(" готово!");
  Serial.print("IP-адреса: ");
  Serial.println(WiFi.localIP());        // ось за цією адресою нас видно в мережі
}

void loop() {
  // поки нічого — уся робота попереду, у веб-сервері
}
```
```micropython
import network                           # бібліотека Wi-Fi
from machine import Pin
from time import sleep_ms

SSID = "ВашаМережа"                       # ім'я вашої Wi-Fi
PASS = "ВашПароль"                        # пароль WPA/WPA2

led = Pin(2, Pin.OUT)                     # GPIO2, активний НИЗЬКИЙ
led.value(1)                             # погашено

wlan = network.WLAN(network.STA_IF)      # режим клієнта (station), не точки доступу
wlan.active(True)
wlan.connect(SSID, PASS)                  # почати під'єднання

print("Під'єднуюсь до", SSID, end="")

# чекаємо мережу, блимаючи LED, поки статус не стане «під'єднано»
while not wlan.isconnected():
    led.value(0)                         # блимнути (0 = світиться)
    sleep_ms(100)
    led.value(1)
    sleep_ms(100)
    print(".", end="")

led.value(0)                             # у мережі — лишаємо LED засвіченим
print(" готово!")
print("IP-адреса:", wlan.ifconfig()[0])  # ось за цією адресою нас видно в мережі
```
:::

Розберімо, що тут насправді відбувається, бо за трьома рядками ховається чимала машинерія.

`WiFi.mode(WIFI_STA)` каже чипу бути **клієнтом** (station) — тим, хто під'єднується до чужої точки доступу, а не роздає власну. ESP8266 уміє й протилежне (`WIFI_AP` — сам стає точкою доступу, до якої підключаються інші), і навіть обоє разом, але для «датчик шле дані в мою мережу» потрібен саме режим клієнта. Що таке точка доступу й клієнт у мережі 802.11 — розкладає [книга про Wi-Fi](topic:communications/wifi); тут досить, що ми — той, хто приєднується.

`WiFi.begin(SSID, PASS)` **не блокує**: вона лише запускає під'єднання й одразу повертає керування. Тому далі йде цикл, що крутиться, доки `WiFi.status()` не поверне `WL_CONNECTED`. Це може зайняти від часток секунди до кількох секунд — залежно від того, як швидко відповість роутер і чи не помилилися ви в паролі. Якщо пароль хибний, цикл крутитиметься **вічно** (статус так і не стане «під'єднано») — тож на реальному пристрої сюди зазвичай додають лічильник спроб і скидання, але для першого запуску нескінченне блимання само по собі — чесний сигнал «мережу не взяв, перевір ім'я й пароль».

`WiFi.localIP()` після під'єднання повертає адресу, яку роутер видав платі по DHCP. Саме її треба вписати в браузер, щоб достукатися до майбутнього веб-сервера. Тому ми й друкуємо її в `Serial` — це єдиний спосіб дізнатися, «де» плата в мережі.

> 🔧 **Навіщо `Serial` тут критичний.** На ESP-01S немає екрана, тож послідовний порт — ваше єдине вікно всередину. Не побачивши в моніторі порту рядок «IP-адреса: 192.168.…», ви не знатимете ані що плата під'єдналася, ані куди стукати браузером. Перший запуск завжди роблять із відкритим монітором порту (на тій самій швидкості, 115200) — інакше працюєте наосліп.

Важлива пастка, що вилазить саме тут, а не раніше: **під час під'єднання радіо вперше вмикається на повну** — і саме на цій миті кволе живлення видає себе. Плата спокійно прошилася, спокійно почала виконувати код, а на слові `WiFi.begin` смикнула з живлення пік близько **300 мА** — і, якщо джерело тонке, напруга просіла, чип скинувся. Збоку: «доходить до під'єднання й перезавантажується по колу». Це та сама проблема живлення, і лік до неї — окреме джерело з запасом струму й конденсатор біля плати; повний механізм цього провалу напруги (бро́унауту) розбирає [книга про brown-out](topic:programming/brownout).

## Керувати світлодіодом із браузера

Тепер найсмачніше — зробимо так, щоб LED вмикався й вимикався з телефона. Для цього піднімемо на платі **найпростіший веб-сервер**: він слухатиме порт 80 (той самий, куди стукає будь-який браузер), і на різні адреси реагуватиме по-різному — засвітити, погасити.

Ідея веб-сервера, якщо здерти церемонії, гранично проста. Браузер відкриває TCP-з'єднання й шле рядок-запит, наприклад `GET /on HTTP/1.1`. Наша програма читає цей рядок, дивиться, що там за шлях (`/on`, `/off` чи просто `/`), робить дію й відсилає назад коротку HTML-сторінку. Усе. Жодного «фреймворку» тут не треба — `ESP8266WiFi` дає клас `WiFiServer`, який приймає з'єднання, і `WiFiClient`, через якого ми читаємо запит і пишемо відповідь.

Ось повний робочий скетч. Він під'єднується до мережі (як вище) і піднімає сервер із двома кнопками:

:::tabs
```cpp
#include <ESP8266WiFi.h>

const char* SSID = "ВашаМережа";
const char* PASS = "ВашПароль";

const int LED = 2;                       // GPIO2, активний НИЗЬКИЙ

WiFiServer server(80);                   // сервер на 80-му порту (HTTP)

void setup() {
  pinMode(LED, OUTPUT);
  digitalWrite(LED, HIGH);               // старт: погашено

  Serial.begin(115200);
  Serial.println();

  WiFi.mode(WIFI_STA);
  WiFi.begin(SSID, PASS);
  while (WiFi.status() != WL_CONNECTED) { delay(200); Serial.print("."); }

  Serial.println();
  Serial.print("Відкрий у браузері: http://");
  Serial.println(WiFi.localIP());        // ось цю адресу — в адресний рядок

  server.begin();                        // почати слухати з'єднання
}

void loop() {
  WiFiClient client = server.accept();   // хтось під'єднався?
  if (!client) return;                   // ні — виходимо, спробуємо в наступному циклі

  // читаємо ПЕРШИЙ рядок запиту — у ньому весь потрібний нам зміст:
  //   "GET /on HTTP/1.1"  →  шлях "/on"
  String req = client.readStringUntil('\r');
  client.readStringUntil('\n');          // дочитати кінець рядка

  // за шляхом вирішуємо, що робити зі світлодіодом
  // (пам'ятаємо: LOW = світиться, HIGH = гасне)
  bool on;
  if (req.indexOf("/on") != -1) {
    digitalWrite(LED, LOW);              // увімкнути
    on = true;
  } else if (req.indexOf("/off") != -1) {
    digitalWrite(LED, HIGH);             // вимкнути
    on = false;
  } else {
    on = (digitalRead(LED) == LOW);      // просто "/" — лишити як є, показати стан
  }

  // проковтуємо решту заголовків запиту, поки браузер їх шле
  while (client.available()) client.read();

  // ── відповідь: спершу HTTP-заголовок, потім HTML-сторінка ──
  client.print(
    "HTTP/1.1 200 OK\r\n"
    "Content-Type: text/html; charset=utf-8\r\n"
    "Connection: close\r\n"
    "\r\n");                             // порожній рядок = кінець заголовків

  client.print("<!DOCTYPE html><html><head><meta charset='utf-8'>");
  client.print("<meta name='viewport' content='width=device-width'>");
  client.print("<title>ESP-01S</title></head><body>");
  client.print("<h2>Світлодіод зараз: ");
  client.print(on ? "<b>увімкнено</b>" : "<b>вимкнено</b>");
  client.print("</h2>");
  client.print("<p><a href='/on'>Увімкнути</a> &nbsp; ");
  client.print("<a href='/off'>Вимкнути</a></p>");
  client.print("</body></html>");

  client.stop();                         // закрити з'єднання
}
```

Пройдімо ключові місця, бо кожне ховає урок.

`server.accept()` — це «чи є нове з'єднання?». Якщо ніхто не стукав, вона повертає «порожнього» клієнта, і ми одразу виходимо з `loop`, звільняючи чип для інших справ (наприклад, обслуговування радіо). Ця форма — сучасна; у старших прикладах ту саму роль грала `server.available()`, і ви ще натрапите на неї в мережі, але офіційне ядро тепер радить `accept()`. Обидві повертають `WiFiClient`, з яким далі працюємо однаково.

`client.readStringUntil('\r')` читає **перший рядок** HTTP-запиту — той самий `GET /on HTTP/1.1`. Нам більше нічого й не потрібно: увесь зміст «що хоче користувач» — у шляху. Тому ми не морочимося з повним розбором заголовків, а просто питаємо `req.indexOf("/on")`: чи є в рядку підрядок `/on`? Це грубо (спрацює й на `/on-щось`), зате коротко й для двох кнопок цілком досить. Коли запитів стане більше й розбирати треба акуратніше, беруть готовий клас `ESP8266WebServer`, що сам мапить шляхи на функції-обробники, — але щоб *зрозуміти*, що відбувається всередині, корисно раз написати сервер руками, як тут.

Порожній рядок (`"\r\n"`) між заголовком і тілом — не примха, а частина протоколу HTTP: саме він каже браузеру «заголовки скінчилися, далі йде сторінка». Забудете його — браузер вважатиме HTML частиною заголовків і покаже порожнечу.

`client.stop()` закриває з'єднання. Ми відповіли й попрощалися — це модель «одне з'єднання на один запит», найпростіша й для нашого завдання ідеальна. Браузер, коли треба, відкриє нове.

> 🔧 **Навіщо саме так, а не «фреймворк».** Тут видно кістяк будь-якого веб-сервера у світі — прийняти з'єднання, прочитати рядок-запит, відповісти текстом і закрити. Усі великі бібліотеки роблять те саме, лише ховають це за зручностями. Написавши раз вручну, ви більше не боятиметеся слова «HTTP-сервер»: це просто читання одного рядка й друк відповіді в сокет.

Заллємо цей скетч (той самий танець із GPIO0), відкриємо монітор порту, дочекаємось рядка з IP-адресою — і вб'ємо цю адресу в браузер телефона, що в тій самій мережі. З'явиться сторінка з двома посиланнями; тиснемо «Увімкнути» — і синій світлодіод на платі спалахує. Ви щойно керуєте залізом через мережу.

## Пастки цього проєкту: карта мін

Проєкт простий концептуально, але встелений граблями, і майже всі вони — не в коді. Зберімо ті, що б'ють саме на етапі мережі й керування; пастки самої заливки — «Failed to connect», порядок GPIO0-танцю, перехрещення TX/RX — розкладено в [довідці з прошивки](topic:boards/esp-01s/api-flash-esp01s.md).

**Живлення на піку передачі — головна міна.** ESP8266 у спокої їсть мало, але на кожен радіопакет смикає короткий пік до ~300 мА. Тонке джерело (3.3 В із самого перехідника чи з виводу Arduino — там лише 50–150 мА) на цю мить просідає нижче робочої напруги, і чип скидається. Симптом підступний: плата працює, аж поки не спробує вийти в мережу, — і саме тоді «падає» чи перезавантажується по колу. Лік у двох частинах: **окремий стабілізатор 3.3 В із запасом струму** (хоча б 500 мА; типовий — [лінійний регулятор LDO](topic:electronics/ldo)) плюс **конденсатор 10–100 мкФ прямо біля ніжки VCC** (і маленький 100 нФ поряд), що віддає заряд у пік швидше, ніж устигне просісти лінія. Це найдешевша й найбільш недооцінена деталь усієї схеми.

**Рівні 3.3 В — і тільки.** Усі ніжки ESP8266 працюють на 3.3 В і **не терплять 5 В**. Подати п'ятивольтовий сигнал на RX чи будь-який вхід — поступово (а то й одразу) пошкодити чип. Особливо болить, коли плату чіпляють до п'ятивольтового Arduino: його лінії видають 5 В, тож перед входом ESP-01S сигнал треба знизити — [перетворювачем рівнів](topic:electronics/level-shifter) або хоча б дільником напруги. У зворотний бік простіше: 3.3-вольтовий сигнал плати п'ятивольтовий вхід зазвичай читає як одиницю.

**GPIO2 у високому при старті.** Ніжка, до якої припаяно наш світлодіод, водночас є стрепінг-ніжкою: **у момент скидання вона мусить бути у високому рівні**, інакше чип не завантажиться. Сам вбудований LED цьому не заважає (він тягне ніжку лише трохи). Але якщо ви **довісите на GPIO2 щось своє, що при вмиканні притягує лінію до землі** (наприклад, вхід, замкнений на землю, або низькоомне навантаження), — чип може мовчати при старті. Тому GPIO2 добирають під навантаження з оглядкою: усе, що на ній висить, при старті має лишати їй свободу піднятись до одиниці.

**Активний низький рівень LED.** Повторюся навмисне, бо це спотикач номер один у коді: `LOW` світить, `HIGH` гасить. Кожен `digitalWrite` для цього світлодіода треба подумки перевертати.

Ось як пастки етапу мережі розкладаються за симптомом:

```
Етап              Що ламається                     Перша перевірка
────────────────────────────────────────────────────────────────────────
Під'єднання       перезавантаження по колу          окреме 3.3 В із запасом? конденсатор?
до Wi-Fi          вічне блимання (не бере мережу)   вірні ім'я/пароль? режим WIFI_STA?
Керування         сторінка порожня                  є порожній рядок після заголовків?
з браузера        LED «навпаки»                     LOW = увімкнено (активний низький)
```

Порядок роботи, що економить години: спершу заллійте порожнє блимання (перевірте ланцюг заливки за [довідкою з прошивки](topic:boards/esp-01s/api-flash-esp01s.md)) → додайте Wi-Fi (перевірте живлення й пароль) → підніміть сервер (перевірте мережу) — а не все одразу. Коли кожен крок окремо доведено робочим, зібраний із них пристрій просто працює.
