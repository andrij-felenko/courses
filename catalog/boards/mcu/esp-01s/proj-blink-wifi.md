# ⚙️ Прошити ESP-01S і блимнути світлодіодом із мережі

Задача звучить майже по-дитячому: узяти найдешевшу Wi-Fi-плату, залити на неї програму й змусити блимати світлодіод. Але на цій крихті кожен із трьох кроків — залити, під'єднатися до мережі, засвітити LED — має власну пастку, і саме на них новачок застрягає надовго. Пройдімо весь шлях від голої плати на столі до світлодіода, яким можна клацнути з браузера телефона, і на кожному кроці розберімо не тільки *що* натиснути, а *чому* воно ламається, коли натиснути не те.

Домовимося про інструмент. Писати код ми будемо в **Arduino IDE з ядром ESP8266** — це найкоротший шлях: ядро дає бібліотеку `ESP8266WiFi`, ховає ініціалізацію радіо за трьома рядками й саме кличе `esptool`, щоб залити зібране. Той самий скетч на тому ж ядрі можна зібрати й з командного рядка (PlatformIO, `arduino-cli`), а залити — `esptool` напряму; обидва шляхи ми покажемо, бо розуміти, що робить IDE «під капотом», варто хоча б для того, щоб полагодити, коли IDE мовчить.

## Крок нуль: наставити Arduino IDE на ESP8266

«Із коробки» Arduino IDE не знає про ESP8266 — вона вміє лише класичні AVR-плати. Треба доставити ядро — набір компілятора, бібліотек і опису плат для цього чипа.

У налаштуваннях IDE є поле **Additional Boards Manager URLs**; туди вписують адресу індексу пакунків спільноти ESP8266:

```
http://arduino.esp8266.com/stable/package_esp8266com_index.json
```

Після цього в **Boards Manager** з'являється пакунок «esp8266 by ESP8266 Community» — ставимо його. Це верифікований, офіційний спосіб (репозиторій `esp8266/Arduino` на GitHub, він же тримає й документацію ядра). Тепер у списку плат є десятки варіантів ESP8266, і тут перша тонкість вибору.

**Яку плату обрати в меню.** Окремого пункту «ESP-01S» немає й не треба — згадаймо, що це лише носій навколо чипа. Беремо **Generic ESP8266 Module** (узагальнена плата на цьому чипі) і в її параметрах виставляємо те, що стосується саме нашої плати:

```
Board:        Generic ESP8266 Module
Flash Size:   1MB (FS:none OTA:~500KB)   ← у ESP-01S зазвичай 1 МБ
Flash Mode:   DOUT   ← найбезпечніший для дрібних модулів; QIO ESP-01S часто не тягне
Upload Speed: 115200 ← починайте з поміркованої; вище — коли впевнитесь
```

Три речі варто пояснити, бо вони не косметичні.

**Flash Size** має відповідати реальній мікросхемі пам'яті. У ESP-01S це майже завжди 1 МБ, але трапляються партії з 2–4 МБ; надійніше не вгадувати з напису, а спитати сам чип — про це нижче, у рецепті `esptool`. Якщо тут збрехати (сказати 4 МБ там, де 1 МБ), файлова система й дані опиняться за межами наявної флеші, і пристрій поводитиметься примхливо.

**Flash Mode** — це скільки ліній чип читає з флеші паралельно. `QIO` (чотири лінії) швидший, але на дрібних модулях типу ESP-01S ті додаткові лінії часто розведені так, що швидкий режим збоїть. `DOUT` (дві лінії на читання) повільніший на частки секунди при старті, зате заводиться всюди. Правило просте: **не заводиться після заливки — першим ділом переставте на `DOUT`**.

> 🔧 **Навіщо ці три поля.** Це три найчастіші причини «залилося, а не працює» саме на ESP-01S. Неправильний розмір флеші губить дані; агресивний `QIO` дає плату, що вічно перезавантажується; зависока швидкість заливки рве зв'язок посеред запису. Виставили консервативно — `1MB`, `DOUT`, `115200` — і зняли три класи проблем ще до першого рядка коду.

## Крок перший: залити перевірочний скетч

Перш ніж мудрувати з Wi-Fi, залиймо найдрібнішу можливу програму — просто блимання світлодіодом. Якщо *воно* заллється й побіжить, значить, увесь ланцюг «IDE → перехідник → GPIO0-танець → флеш» справний, і далі можна нарощувати логіку, не гадаючи, чи то код поганий, чи то плата не прошилась.

Ось цей скетч. Він уже враховує головну тонкість плати — світлодіод на GPIO2 світиться **навпаки**:

:::tabs
```cpp
// Найдрібніший скетч: блимаємо вбудованим синім LED на ESP-01S.
// LED сидить на GPIO2 і УВІМКНЕНО ЗА НИЗЬКИМ РІВНЕМ:
//   LOW  → світиться,   HIGH → гасне.

const int LED = 2;              // GPIO2 — до нього припаяно синій світлодіод

void setup() {
  pinMode(LED, OUTPUT);         // ніжка працює на вихід
  digitalWrite(LED, HIGH);      // старт із погашеним (HIGH = вимкнено!)
}

void loop() {
  digitalWrite(LED, LOW);       // світиться
  delay(500);                   // 0.5 с
  digitalWrite(LED, HIGH);      // гасне
  delay(500);
}
```
```micropython
# Найдрібніший скрипт: блимаємо вбудованим синім LED на ESP-01S.
# LED сидить на GPIO2 і УВІМКНЕНО ЗА НИЗЬКИМ РІВНЕМ:
#   value(0) → світиться,   value(1) → гасне.

from machine import Pin
from time import sleep_ms

led = Pin(2, Pin.OUT)      # GPIO2 — до нього припаяно синій світлодіод
led.value(1)               # старт із погашеним (1 = вимкнено!)

while True:
    led.value(0)           # світиться
    sleep_ms(500)          # 0.5 с
    led.value(1)           # гасне
    sleep_ms(500)
```
:::

Зверніть увагу на `digitalWrite(LED, HIGH)` як стан «вимкнено». Той, хто звик до звичайних плат, де `HIGH` світить, тут отримає світлодіод, що горить, коли має бути темно, і навпаки, — і півгодини шукатиме проблему в коді, якої там немає. **Активний низький рівень** (active-low): струм тече через LED, коли ніжка тягне його до землі, тож нуль — це «увімкнено». Ця дрібниця повторюється в кожному скетчі для ESP-01S, тож звикайте одразу.

### Танець із GPIO0: як реально залити

Тиснемо в IDE **Upload** — і тут вступає в дію те, чим ESP-01S відрізняється від Arduino. На Arduino заливка автоматична: плата сама вміє скинутись у режим прийому. На голому ESP-01S кнопок немає, і чип треба **вручну загнати в завантажувач**.

Механізм такий. При кожному скиданні ESP8266 дивиться на ніжку GPIO0: якщо вона притиснута до землі — чип входить у режим завантажувача (bootloader) і чекає нову прошивку по UART; якщо вільна — біжить те, що вже у флеші. Отже, послідовність фіксована:

![Заливка ESP-01S у часі: три фази — вхід у завантажувач, запис флеші через esptool на 115200 бод, запуск прошивки; під ними доріжка рівня GPIO0, що показує, коли ніжка на землі, а коли вільна](/catalog/boards/mcu/esp-01s/img/flashcycle.svg)
*Три фази заливки в часі. Спершу GPIO0 притискають до землі й коротко скидають чип (RST на землю й назад) — чип входить у завантажувач. Поки esptool пише флеш, GPIO0 лишається на землі. Аж коли запис завершився, GPIO0 відпускають і скидають ще раз — тепер чип бачить вільну ніжку й запускає свіжу прошивку. Червона доріжка знизу — коли GPIO0 має бути на нулі.*

Словами той самий рецепт:

```
1. Притиснути GPIO0 до землі (джампером або дротом).
2. Коротко замкнути RST на землю й відпустити  → чип у завантажувачі.
3. У IDE натиснути Upload (або запустити esptool).
4. Коли запис завершився — прибрати GPIO0 із землі.
5. Ще раз коротко замкнути RST на землю      → чип біжить нову прошивку.
```

Це та сама процедура, що описана в [книзі про прошивку у Flash](book:programming/flashing): будь-який чип, у якого програма живе в окремій флеш-пам'яті, потребує способу сказати йому «зараз приймай нове, а не виконуй старе», і завантажувач із стрепінг-ніжкою — класична відповідь. На ESP8266 цю роль грає саме GPIO0.

> 🔧 **Навіщо руками.** Готові USB-перехідники «під ESP-01» часто мають дві кнопки — RST і FLASH (вона ж GPIO0), — які роблять цей танець самі: тримаєш FLASH, тиснеш RST, відпускаєш RST, відпускаєш FLASH. З таким перехідником заливка стає двома натисканнями. На зовсім голій платі ті самі два дроти доводиться замикати пінцетом — незручно, але один раз, поки не спаяєте собі колодку з кнопками.

### Коли IDE каже «Failed to connect»

Це найчастіше повідомлення на старті, і воно майже ніколи не про те, що здається. Розшифрую за спаданням імовірності — саме в такому порядку й перевіряйте:

**GPIO0 не був на землі в момент скидання.** Дев'ять із десяти випадків. Чип просто не ввійшов у завантажувач, тож нема кому відповідати. Повторіть танець: землю на GPIO0 → скидання → *тоді* Upload. Ключове — порядок: спершу земля й скидання, аж потім заливка.

**Лінії TX/RX переплутані.** Послідовний порт з'єднується **навхрест**: TX перехідника йде на RX плати, а TX плати — на RX перехідника. Якщо з'єднати «прямо», обидва пристрої передають назустріч і жоден не чує іншого. Помінялися ролями дротів — і зв'язок з'явився. Механіку самого перехрещення розбирає [асинхронна передача (UART)](book:communications/async-serial): передавач одного боку мусить дивитися у приймач іншого.

**Не той COM-порт.** У списку портів IDE виберіть саме той, що з'явився, коли ви ввімкнули перехідник у USB (від'єднайте-під'єднайте й подивіться, який пункт зникає-з'являється).

**Кволе живлення.** Навіть заливка вимагає струму, а якщо годувати плату від 3.3-вольтового виводу самого перехідника, його часто бракує вже на стадії завантажувача. Дайте окреме чисте 3.3 В — про це наступний крок.

**Зависока швидкість.** Довгий чи шумний дріт не тягне 115200 бод. Спробуйте у налаштуваннях повільніше; `esptool` це вміє прямо: `--baud 9600`. Повільно, зате доходить.

Той самий діагноз мовою `esptool`, якщо заливаєте з командного рядка (адреса `0x0`, бо на ESP8266 образ пишеться від початку флеші):

```
# спершу спитаймо сам чип — скільки в нього флеші й що він за один
esptool --port COM4 flash_id
#   → у відповіді буде розмір (напр. "Detected flash size: 1MB")
#     і MAC — так ви ПЕРЕВІРИТЕ реальний обсяг, а не вгадуєте з напису

# заливка зібраного образу від початку флеші
esptool --port COM4 --baud 115200 write_flash 0x0 firmware.bin
```

Дрібна, але свіжа деталь: у нових версіях (`esptool` 5) команди перейменували з підкреслень на дефіси — `write_flash` → `write-flash`, `flash_id` → `flash-id`. Стара форма з підкресленням поки працює, але друкує попередження «deprecated». Це верифіковано за нотатками випуску `esptool`; Arduino IDE донедавна кликала саме форму з підкресленням, тож ви побачите обидві — вони роблять те саме.

## Крок другий: вийти в Wi-Fi

Плата прошивається — можна давати їй мережу. Уся магія радіо ховається за бібліотекою `ESP8266WiFi`: ви кажете «під'єднайся ось до цієї мережі», а вона сама налаштовує радіоблок, проходить рукостискання WPA2 і бере IP-адресу по DHCP.

Ось скелет, який під'єднується до вашої точки доступу й **блимає світлодіодом, поки триває під'єднання** — зручний живий індикатор: миготить швидко → ще шукає мережу; засвітився рівно → у мережі.

:::tabs
```cpp
#include <ESP8266WiFi.h>

const char* SSID = "ВашаМережа";        // ім'я вашої Wi-Fi
const char* PASS = "ВашПароль";         // пароль WPA/WPA2

const int LED = 2;                       // GPIO2, активний НИЗЬКИЙ

void setup() {
  pinMode(LED, OUTPUT);
  digitalWrite(LED, HIGH);               // погашено

  Serial.begin(115200);                  // щоб бачити діагностику
  Serial.println();

  WiFi.mode(WIFI_STA);                   // режим клієнта (station), не точки доступу
  WiFi.begin(SSID, PASS);                // почати під'єднання

  Serial.print("Під'єднуюсь до ");
  Serial.print(SSID);

  // чекаємо мережу, блимаючи LED, поки статус не стане «під'єднано»
  while (WiFi.status() != WL_CONNECTED) {
    digitalWrite(LED, LOW);              // блимнути (LOW = світиться)
    delay(100);
    digitalWrite(LED, HIGH);
    delay(100);
    Serial.print(".");
  }

  digitalWrite(LED, LOW);                // у мережі — лишаємо LED засвіченим
  Serial.println(" готово!");
  Serial.print("IP-адреса: ");
  Serial.println(WiFi.localIP());        // ось за цією адресою нас видно в мережі
}

void loop() {
  // поки нічого — уся робота попереду, у веб-сервері
}
```
```micropython
import network                           # бібліотека Wi-Fi
from machine import Pin
from time import sleep_ms

SSID = "ВашаМережа"                       # ім'я вашої Wi-Fi
PASS = "ВашПароль"                        # пароль WPA/WPA2

led = Pin(2, Pin.OUT)                     # GPIO2, активний НИЗЬКИЙ
led.value(1)                             # погашено

wlan = network.WLAN(network.STA_IF)      # режим клієнта (station), не точки доступу
wlan.active(True)
wlan.connect(SSID, PASS)                  # почати під'єднання

print("Під'єднуюсь до", SSID, end="")

# чекаємо мережу, блимаючи LED, поки статус не стане «під'єднано»
while not wlan.isconnected():
    led.value(0)                         # блимнути (0 = світиться)
    sleep_ms(100)
    led.value(1)
    sleep_ms(100)
    print(".", end="")

led.value(0)                             # у мережі — лишаємо LED засвіченим
print(" готово!")
print("IP-адреса:", wlan.ifconfig()[0])  # ось за цією адресою нас видно в мережі
```
:::

Розберімо, що тут насправді відбувається, бо за трьома рядками ховається чимала машинерія.

`WiFi.mode(WIFI_STA)` каже чипу бути **клієнтом** (station) — тим, хто під'єднується до чужої точки доступу, а не роздає власну. ESP8266 уміє й протилежне (`WIFI_AP` — сам стає точкою доступу, до якої підключаються інші), і навіть обоє разом, але для «датчик шле дані в мою мережу» потрібен саме режим клієнта. Що таке точка доступу й клієнт у мережі 802.11 — розкладає [книга про Wi-Fi](book:communications/wifi); тут досить, що ми — той, хто приєднується.

`WiFi.begin(SSID, PASS)` **не блокує**: вона лише запускає під'єднання й одразу повертає керування. Тому далі йде цикл, що крутиться, доки `WiFi.status()` не поверне `WL_CONNECTED`. Це може зайняти від часток секунди до кількох секунд — залежно від того, як швидко відповість роутер і чи не помилилися ви в паролі. Якщо пароль хибний, цикл крутитиметься **вічно** (статус так і не стане «під'єднано») — тож на реальному пристрої сюди зазвичай додають лічильник спроб і скидання, але для першого запуску нескінченне блимання само по собі — чесний сигнал «мережу не взяв, перевір ім'я й пароль».

`WiFi.localIP()` після під'єднання повертає адресу, яку роутер видав платі по DHCP. Саме її треба вписати в браузер, щоб достукатися до майбутнього веб-сервера. Тому ми й друкуємо її в `Serial` — це єдиний спосіб дізнатися, «де» плата в мережі.

> 🔧 **Навіщо `Serial` тут критичний.** На ESP-01S немає екрана, тож послідовний порт — ваше єдине вікно всередину. Не побачивши в моніторі порту рядок «IP-адреса: 192.168.…», ви не знатимете ані що плата під'єдналася, ані куди стукати браузером. Перший запуск завжди роблять із відкритим монітором порту (на тій самій швидкості, 115200) — інакше працюєте наосліп.

Важлива пастка, що вилазить саме тут, а не раніше: **під час під'єднання радіо вперше вмикається на повну** — і саме на цій миті кволе живлення видає себе. Плата спокійно прошилася, спокійно почала виконувати код, а на слові `WiFi.begin` смикнула з живлення пік близько **300 мА** — і, якщо джерело тонке, напруга просіла, чип скинувся. Збоку: «доходить до під'єднання й перезавантажується по колу». Це та сама проблема живлення, і лік до неї — окреме джерело з запасом струму й конденсатор біля плати; повний механізм цього провалу напруги (бро́унауту) розбирає [книга про brown-out](book:programming/brownout).

## Крок третій: керувати світлодіодом із браузера

Тепер найсмачніше — зробимо так, щоб LED вмикався й вимикався з телефона. Для цього піднімемо на платі **найпростіший веб-сервер**: він слухатиме порт 80 (той самий, куди стукає будь-який браузер), і на різні адреси реагуватиме по-різному — засвітити, погасити.

Ідея веб-сервера, якщо здерти церемонії, гранично проста. Браузер відкриває TCP-з'єднання й шле рядок-запит, наприклад `GET /on HTTP/1.1`. Наша програма читає цей рядок, дивиться, що там за шлях (`/on`, `/off` чи просто `/`), робить дію й відсилає назад коротку HTML-сторінку. Усе. Жодного «фреймворку» тут не треба — `ESP8266WiFi` дає клас `WiFiServer`, який приймає з'єднання, і `WiFiClient`, через якого ми читаємо запит і пишемо відповідь.

Ось повний робочий скетч. Він під'єднується до мережі (як вище) і піднімає сервер із двома кнопками:

:::tabs
```cpp
#include <ESP8266WiFi.h>

const char* SSID = "ВашаМережа";
const char* PASS = "ВашПароль";

const int LED = 2;                       // GPIO2, активний НИЗЬКИЙ

WiFiServer server(80);                   // сервер на 80-му порту (HTTP)

void setup() {
  pinMode(LED, OUTPUT);
  digitalWrite(LED, HIGH);               // старт: погашено

  Serial.begin(115200);
  Serial.println();

  WiFi.mode(WIFI_STA);
  WiFi.begin(SSID, PASS);
  while (WiFi.status() != WL_CONNECTED) { delay(200); Serial.print("."); }

  Serial.println();
  Serial.print("Відкрий у браузері: http://");
  Serial.println(WiFi.localIP());        // ось цю адресу — в адресний рядок

  server.begin();                        // почати слухати з'єднання
}

void loop() {
  WiFiClient client = server.accept();   // хтось під'єднався?
  if (!client) return;                   // ні — виходимо, спробуємо в наступному циклі

  // читаємо ПЕРШИЙ рядок запиту — у ньому весь потрібний нам зміст:
  //   "GET /on HTTP/1.1"  →  шлях "/on"
  String req = client.readStringUntil('\r');
  client.readStringUntil('\n');          // дочитати кінець рядка

  // за шляхом вирішуємо, що робити зі світлодіодом
  // (пам'ятаємо: LOW = світиться, HIGH = гасне)
  bool on;
  if (req.indexOf("/on") != -1) {
    digitalWrite(LED, LOW);              // увімкнути
    on = true;
  } else if (req.indexOf("/off") != -1) {
    digitalWrite(LED, HIGH);             // вимкнути
    on = false;
  } else {
    on = (digitalRead(LED) == LOW);      // просто "/" — лишити як є, показати стан
  }

  // проковтуємо решту заголовків запиту, поки браузер їх шле
  while (client.available()) client.read();

  // ── відповідь: спершу HTTP-заголовок, потім HTML-сторінка ──
  client.print(
    "HTTP/1.1 200 OK\r\n"
    "Content-Type: text/html; charset=utf-8\r\n"
    "Connection: close\r\n"
    "\r\n");                             // порожній рядок = кінець заголовків

  client.print("<!DOCTYPE html><html><head><meta charset='utf-8'>");
  client.print("<meta name='viewport' content='width=device-width'>");
  client.print("<title>ESP-01S</title></head><body>");
  client.print("<h2>Світлодіод зараз: ");
  client.print(on ? "<b>увімкнено</b>" : "<b>вимкнено</b>");
  client.print("</h2>");
  client.print("<p><a href='/on'>Увімкнути</a> &nbsp; ");
  client.print("<a href='/off'>Вимкнути</a></p>");
  client.print("</body></html>");

  client.stop();                         // закрити з'єднання
}
```

Пройдімо ключові місця, бо кожне ховає урок.

`server.accept()` — це «чи є нове з'єднання?». Якщо ніхто не стукав, вона повертає «порожнього» клієнта, і ми одразу виходимо з `loop`, звільняючи чип для інших справ (наприклад, обслуговування радіо). Ця форма — сучасна; у старших прикладах ту саму роль грала `server.available()`, і ви ще натрапите на неї в мережі, але офіційне ядро тепер радить `accept()`. Обидві повертають `WiFiClient`, з яким далі працюємо однаково.

`client.readStringUntil('\r')` читає **перший рядок** HTTP-запиту — той самий `GET /on HTTP/1.1`. Нам більше нічого й не потрібно: увесь зміст «що хоче користувач» — у шляху. Тому ми не морочимося з повним розбором заголовків, а просто питаємо `req.indexOf("/on")`: чи є в рядку підрядок `/on`? Це грубо (спрацює й на `/on-щось`), зате коротко й для двох кнопок цілком досить. Коли запитів стане більше й розбирати треба акуратніше, беруть готовий клас `ESP8266WebServer`, що сам мапить шляхи на функції-обробники, — але щоб *зрозуміти*, що відбувається всередині, корисно раз написати сервер руками, як тут.

Порожній рядок (`"\r\n"`) між заголовком і тілом — не примха, а частина протоколу HTTP: саме він каже браузеру «заголовки скінчилися, далі йде сторінка». Забудете його — браузер вважатиме HTML частиною заголовків і покаже порожнечу.

`client.stop()` закриває з'єднання. Ми відповіли й попрощалися — це модель «одне з'єднання на один запит», найпростіша й для нашого завдання ідеальна. Браузер, коли треба, відкриє нове.

> 🔧 **Навіщо саме так, а не «фреймворк».** Тут видно кістяк будь-якого веб-сервера у світі — прийняти з'єднання, прочитати рядок-запит, відповісти текстом і закрити. Усі великі бібліотеки роблять те саме, лише ховають це за зручностями. Написавши раз вручну, ви більше не боятиметеся слова «HTTP-сервер»: це просто читання одного рядка й друк відповіді в сокет.

Заллємо цей скетч (той самий танець із GPIO0), відкриємо монітор порту, дочекаємось рядка з IP-адресою — і вб'ємо цю адресу в браузер телефона, що в тій самій мережі. З'явиться сторінка з двома посиланнями; тиснемо «Увімкнути» — і синій світлодіод на платі спалахує. Ви щойно керуєте залізом через мережу.

## Складність і пастки: карта мін

Проєкт простий концептуально, але встелений граблями, і майже всі вони — не в коді. Зберімо їх в одну карту, за причинами.

**Живлення на піку передачі — головна міна.** ESP8266 у спокої їсть мало, але на кожен радіопакет смикає короткий пік до ~300 мА. Тонке джерело (3.3 В із самого перехідника чи з виводу Arduino — там лише 50–150 мА) на цю мить просідає нижче робочої напруги, і чип скидається. Симптом підступний: плата працює, аж поки не спробує вийти в мережу, — і саме тоді «падає» чи перезавантажується по колу. Лік у двох частинах: **окремий стабілізатор 3.3 В із запасом струму** (хоча б 500 мА; типовий — [лінійний регулятор LDO](book:electronics/ldo)) плюс **конденсатор 10–100 мкФ прямо біля ніжки VCC** (і маленький 100 нФ поряд), що віддає заряд у пік швидше, ніж устигне просісти лінія. Це найдешевша й найбільш недооцінена деталь усієї схеми.

**Рівні 3.3 В — і тільки.** Усі ніжки ESP8266 працюють на 3.3 В і **не терплять 5 В**. Подати п'ятивольтовий сигнал на RX чи будь-який вхід — поступово (а то й одразу) пошкодити чип. Особливо болить, коли плату чіпляють до п'ятивольтового Arduino: його лінії видають 5 В, тож перед входом ESP-01S сигнал треба знизити — [перетворювачем рівнів](book:electronics/level-shifter) або хоча б дільником напруги. У зворотний бік простіше: 3.3-вольтовий сигнал плати п'ятивольтовий вхід зазвичай читає як одиницю.

**GPIO2 у високому при старті.** Ніжка, до якої припаяно наш світлодіод, водночас є стрепінг-ніжкою: **у момент скидання вона мусить бути у високому рівні**, інакше чип не завантажиться. Сам вбудований LED цьому не заважає (він тягне ніжку лише трохи). Але якщо ви **довісите на GPIO2 щось своє, що при вмиканні притягує лінію до землі** (наприклад, вхід, замкнений на землю, або низькоомне навантаження), — чип може мовчати при старті. Тому GPIO2 добирають під навантаження з оглядкою: усе, що на ній висить, при старті має лишати їй свободу піднятись до одиниці.

**Активний низький рівень LED.** Повторюся навмисне, бо це спотикач номер один у коді: `LOW` світить, `HIGH` гасить. Кожен `digitalWrite` для цього світлодіода треба подумки перевертати.

**Порядок GPIO0-танцю.** Спершу земля на GPIO0 **і** скидання, аж потім заливка. Переставите місцями (спершу Upload, тоді землю) — чип уже вийшов зі стану, де приймає прошивку, і ви отримаєте «Failed to connect».

**Навхрест TX/RX.** Передача одного боку — на прийом іншого. Друга за поширеністю причина невдалої заливки після GPIO0.

Ось як ці пастки розкладаються за етапом, де вони бʼють:

```
Етап              Що ламається                     Перша перевірка
────────────────────────────────────────────────────────────────────────
Заливка           «Failed to connect»              GPIO0 на землі ПЕРЕД скиданням?
                                                    TX/RX навхрест? той COM-порт?
Старт після       чип зависає / не біжить код       GPIO2 не притиснутий до землі?
заливки                                             Flash Mode = DOUT? розмір флеші вірний?
Під'єднання       перезавантаження по колу          окреме 3.3 В із запасом? конденсатор?
до Wi-Fi          вічне блимання (не бере мережу)   вірні ім'я/пароль? режим WIFI_STA?
Керування         сторінка порожня                  є порожній рядок після заголовків?
з браузера        LED «навпаки»                     LOW = увімкнено (активний низький)
```

Розберетеся з цією карткою — і ESP-01S перестає бути капризною. Кожна з мін має один-два конкретні лік, і всі вони, крім хіба активного низького рівня, лежать поза кодом — у дротах, живленні й порядку натискань. Саме тому перший запуск варто робити методично, крок за кроком: залити блимання (перевірити ланцюг заливки) → додати Wi-Fi (перевірити живлення й пароль) → підняти сервер (перевірити мережу) — а не все одразу. Коли кожен крок окремо доведено робочим, зібраний із них пристрій просто працює.
