# ⚙️ Голос на два дроти: патерни біпів KY-012 і біп, що не глушить програму

Стаття про сам модуль зводить усе програмне керування KY-012 до одного речення: `digitalWrite(pin, HIGH)` — пищить, `LOW` — тиша, і жодних частот. Це правда, і водночас це рівно та точка, з якої починається справжня робота. Бо активний зумер зумисне позбавив тебе ручки висоти тону — генератор зашитий усередині, ноту він веде одну, — і весь виражальний засіб, що лишився, — це **час**: коли ввімкнути, на скільки, скільки разів. Один і той самий пін, той самий рівний писк на 2.5 кГц, але «біп… біп… біп» на кожну секунду означає «працюю», три швидкі поспіль — «помилка», а рівний безперервний тон — «тривога, підійди». Уся мова зумера — це **ритм увімкнень**, і саме її ми тут навчимося записувати кодом.

Зберемо невелику, але чесну бібліотечку: спершу найпростіші патерни в лоб — біп раз, біп N разів, тривога, — тоді покажемо, чому наївний код на `delay()` перетворює зумер на кайдани для решти програми, і як зробити той самий біп **неблокуючим** через `millis()`, щоб він грав тлом, поки чип робить свою справу. Наостанок згорнемо все в акуратну обгортку, якою можна засіяти проєкт і забути. І по дорозі назвемо кожну пастку — HIGH-тригер, тон, що дратує на робочому столі, спокусу «зіграти мелодію» на тому, що мелодій не вміє, — поки вона не з'їла твій вечір.

Зумер сидить на залізі мікроконтролера, тож приклади природно лягають і на Arduino-фреймворк (C++), і на MicroPython — покажемо обидва, вони майже дзеркальні.

## Найпростіше: біп раз

Почнімо з атома всієї мови — одного біпу заданої довжини. Умова банальна, але на ній уже видно головне.

**Умова.** Сигнальний штир `S` модуля заведено на цифровий пін (D8 на Arduino Uno; GPIO 8 на ESP32-подібній платі під MicroPython), мінус — на GND, середній штир не чіпаємо. Треба один раз пискнути на 80 мілісекунд — короткий «тик» на підтвердження.

:::tabs
```cpp
const uint8_t BUZZER = 8;          // S модуля на цифровому виході

void setup() {
  pinMode(BUZZER, OUTPUT);
  digitalWrite(BUZZER, LOW);       // старт із тиші — відомий початковий стан
}

// Один біп заданої довжини (мс). Блокуючий — годиться для найпростіших місць.
void beep(unsigned int ms) {
  digitalWrite(BUZZER, HIGH);      // одиниця → транзистор відкрився → пищить
  delay(ms);
  digitalWrite(BUZZER, LOW);       // забрали → тиша
}

void loop() {
  beep(80);                        // короткий «тик»
  delay(2000);                     // раз на дві секунди
}
```
```micropython
from machine import Pin
import time

buzzer = Pin(8, Pin.OUT)           # S модуля на цифровому виході
buzzer.value(0)                    # старт із тиші

# Один біп заданої довжини (мс). Блокуючий.
def beep(ms):
    buzzer.value(1)                # одиниця → транзистор відкрився → пищить
    time.sleep_ms(ms)
    buzzer.value(0)                # тиша

while True:
    beep(80)                       # короткий «тик»
    time.sleep_ms(2000)
```
:::

Тут немає нічого, окрім вмикання, паузи й вимикання, — і саме тому варто затриматися на трьох речах, які легко проґавити.

Перше — **HIGH вмикає, LOW вимикає**, без інверсії. Це не самоочевидно: половина KY-модулів (компаратори з виходом `DO`) працюють навиворіт — спокій у них це одиниця, спрацювання нуль. KY-012 такого викрутаса не робить: транзистор-ключ на платі відкривається саме високим рівнем, тож «пищати» = `HIGH`, «мовчати» = `LOW`. Пиши прямо, не інвертуй.

Друге — довжина. 80 мілісекунд — це вже виразний короткий біп; коротший за ~30 мс на слух перетворюється на ледь чутне клацання, бо зумер не встигає розгойдати мембрану на повну гучність. Для «тику» бери 40–100 мс, для «сигналу готовності» — 150–300, для «уваги» — півсекунди й більше. Час — твоя єдина ручка виразності, тож ці числа й є вся «інтонація».

Третє — і найважливіше, хоч поки й непомітне — **`delay(ms)` усередині `beep` зупиняє геть усе**. Поки триває той писк, `loop()` не крутиться, кнопка не читається, давач мовчить. Для одного біпу раз на дві секунди це байдуже. Але саме ця дрібниця розростеться в головну проблему, щойно біпів стане більше, а програма — складнішою. Поки просто запам'ятай, що `beep()` тут — блокуючий, тобто на час звучання чіп сліпий.

> 🔧 **Навіщо це.** Активний зумер зробив керування смішно простим — це просто цифровий вихід, як світлодіод, — і саме тому вся інженерія тут не в «як видати звук», а в **як розпорядитися часом**. Ти не крутиш ШІМ, не задаєш частоту, не тримаєш зайнятим апаратний таймер: одна лінія, два рівні. Ціна цієї простоти — весь сенс доводиться кодувати ритмом, а ритм на `delay` конфліктує з рештою роботи чіпа. Тому проста функція `beep()` — правильний початок, але не кінець: далі вся боротьба буде за те, щоб цей ритм не крав час у логіки.

## Мова ритму: короткий і довгий, N біпів, тривога

Маючи атом `beep()`, зберемо з нього словник. Ідея та сама, що з абеткою Морзе: з двох тривалостей — короткої й довгої — та пауз між ними складається скільки завгодно розрізнюваних сигналів. Висоту ми не міняємо (не можемо), але вухо чудово розрізняє **візерунок у часі**, і цього досить, щоб зумер «сказав» помітно різні речі.

![Чотири патерни на одній часовій осі: один короткий біп, три короткі біпи поспіль, довгий сигнал і безперервна тривога — усі складені з тих самих увімкнень різної тривалості](/catalog/actuators/signaling/ky-012-buzzer/img/beep-patterns.svg)

*Уся «мова» KY-012 — це ритм увімкнень на незмінній частоті. Заповнені смужки — зумер пищить, проміжки — тиша. «Готово» — один короткий біп; «помилка» — три швидкі поспіль; «увага» — один довгий; «тривога» — безперервний тон. Висота тону скрізь однакова (≈2.5 кГц); розрізняє сигнали лише малюнок у часі.*

Ось ці патерни кодом. Зверни увагу: тут ми будуємо їх поверх блокуючого `beep()` — це найпряміший спосіб побачити структуру, а неблокуючий варіант зробимо далі окремо.

:::tabs
```cpp
const uint8_t BUZZER = 8;

void setup() {
  pinMode(BUZZER, OUTPUT);
  digitalWrite(BUZZER, LOW);
}

void beep(unsigned int ms) {
  digitalWrite(BUZZER, HIGH);
  delay(ms);
  digitalWrite(BUZZER, LOW);
}

// N однакових біпів по on мс зі паузою gap мс між ними.
void beepN(uint8_t n, unsigned int on, unsigned int gap) {
  for (uint8_t i = 0; i < n; i++) {
    beep(on);
    if (i < n - 1) delay(gap);     // паузу ставимо МІЖ біпами, не після останнього
  }
}

// Іменовані сигнали — це просто зручні назви для конкретних ритмів.
void signalReady() { beep(120); }                 // готово: один короткий
void signalError() { beepN(3, 60, 80); }          // помилка: три швидкі
void signalAttention() { beep(600); }             // увага: один довгий
void alarm(uint8_t times) { beepN(times, 400, 200); } // тривога: довгі з паузами

void loop() {
  signalReady();
  delay(1500);
  signalError();
  delay(1500);
  alarm(3);
  delay(3000);
}
```
```micropython
from machine import Pin
import time

buzzer = Pin(8, Pin.OUT)
buzzer.value(0)

def beep(ms):
    buzzer.value(1)
    time.sleep_ms(ms)
    buzzer.value(0)

# N однакових біпів по on мс з паузою gap мс між ними.
def beep_n(n, on, gap):
    for i in range(n):
        beep(on)
        if i < n - 1:
            time.sleep_ms(gap)      # паузу — МІЖ біпами, не після останнього

# Іменовані сигнали — зручні назви для конкретних ритмів.
def signal_ready():     beep(120)              # готово: один короткий
def signal_error():     beep_n(3, 60, 80)      # помилка: три швидкі
def signal_attention(): beep(600)              # увага: один довгий
def alarm(times):       beep_n(times, 400, 200)  # тривога: довгі з паузами

while True:
    signal_ready()
    time.sleep_ms(1500)
    signal_error()
    time.sleep_ms(1500)
    alarm(3)
    time.sleep_ms(3000)
```
:::

Розберімо, чому саме так, і де тут дрібні, але кусючі деталі.

**Пауза стоїть МІЖ біпами, а не після кожного.** Умова `if (i < n - 1)` пропускає затримку після останнього біпу. Здавалося б, дрібниця — та без неї `beepN(3, …)` лишав би зайву тишу в хвості, і якщо ти зшиваєш два сигнали підряд, вони «злипалися» б із неправильним інтервалом. Три біпи — це «біп-пауза-біп-пауза-біп», рівно дві паузи, а не три. Ця межа «`n − 1` розділювачів на `n` елементів» — та сама, що при склеюванні рядків комами, і плутають її регулярно.

**Іменовані сигнали — це просто назви для ритмів.** `signalError()` не робить нічого, крім `beepN(3, 60, 80)`, але в тілі програми `signalError()` читається як намір, а не як магічні числа. Коли за місяць захочеш зробити «помилку» п'ятьма біпами замість трьох — правиш **одне** місце, а не полюєш на `beepN(3, …)` по всьому скетчу. Це та сама дисципліна єдиної точки, що рятує в будь-якому коді: назви наміри, сховай числа.

**Різниця «короткий/довгий» несе весь сенс.** 60 мс проти 600 — на слух це «тик» проти «гудка», і вухо ловить різницю миттєво, навіть не рахуючи біпи. Тому найнадійніші сигнали будують на **контрасті тривалостей**, а не на точній кількості: людина радше почує «часте дрібне» проти «рідке протяжне», ніж полічить, три було біпи чи чотири. Проєктуй ритми так, щоб вони різнилися характером, а не лише лічбою.

> 🔧 **Навіщо це.** Ця табличка сигналів — і є весь інтерфейс, який зумер дає користувачеві, тож до неї варто ставитися як до мови, а не як до випадкових `delay`. Кілька усталених ритмів («готово», «помилка», «увага»), стабільних по всьому пристрою, — і людина за тиждень починає розуміти прилад **не дивлячись** на нього, самим слухом. Це справжня цінність активного зумера: дешевий, гучний, чутний крізь шум канал зворотного зв'язку, який не займає ні екрана, ні очей. Зіпсувати його легко — досить щоразу пищати по-різному, і сигнали злипнуться в невиразний шум; тримай словник маленьким і сталим.

## Чому `delay()` — кайдани, а не просто «повільно»

Тепер про стелю, у яку впирається весь код вище, і чому далі ми його переписуємо. Проблема не в тому, що `delay(400)` повільний, — проблема в тому, що він **зупиняє геть усе**. Поки триває та затримка, мікроконтролер не крутить `loop()`, не читає кнопку, не опитує давач, не відповідає по шині: він сидить у порожньому циклі й рахує мілісекунди, глухий і сліпий.

Уяви типовий вузол: давач руху, а на спрацювання — тривога зумером. Пишеш `alarm(3)` через `beepN` — це три біпи по 400 мс із паузами, разом близько півтори секунди суцільного `delay`. І всі ці півтори секунди пристрій **не бачить нічого іншого**: не реагує на кнопку «стоп», не читає інші давачі, не оновлює екран. Гірше — якщо за цей час давач спрацює ще раз, подія просто загубиться, бо чіп зайнятий пищанням. Зумер, який мав би обслуговувати логіку, натомість її паралізує.

Правильний спосіб робити кілька справ водночас на одному ядрі без операційної системи — не спати, а **дивитися на годинник**. Замість «поспати 400 мс» ми питаємо на кожному оберті циклу: «а чи минуло вже 400 мс від минулого перемикання?» Годинником служить `millis()` — лічильник мілісекунд від старту плати. `loop()` при цьому крутиться вільно, тисячі разів на секунду, і лише зрідка, коли настав час, клацає станом зумера. Увесь інший час ядро вільне.

![Дві осі часу одна під одною: угорі на delay() програма 'спить' весь час звучання і сліпа до подій; унизу на millis() зумер пищить того ж ритму, але loop() увесь час вільний і бачить події між перемиканнями](/catalog/actuators/signaling/ky-012-buzzer/img/blocking-vs-nonblocking.svg)

*Той самий ритм біпів, два способи його зіграти. Угорі — `delay()`: увесь час звучання (і пауз) ядро «спить», події поза цим вікном не помічаються — натиск кнопки в цю мить пропаде. Унизу — `millis()`: зумер клацає станом лише у визначені моменти, а між ними `loop()` пролітає вільно тисячі разів і встигає читати кнопки й давачі. Звук на слух однаковий; різниця — в тому, чи живий чіп під час нього.*

> 🔧 **Навіщо це.** Різниця між `delay()` і `millis()` — це різниця між іграшкою й вузлом реального пристрою. Скетч на `delay` неможливо «доростити»: кожна нова справа б'ється за ті самі паузи, і код швидко стає плутаниною вкладених затримок, яку годі налагодити. Скетч на `millis()` росте лінійно — додаєш іще один незалежний таймер, і він живе своїм ритмом, не заважаючи попереднім. Для зумера це особливо гостро: сигнал майже завжди **не головна** справа скетчу, а тонке тло поверх реальної логіки, і тло не має права красти в логіки час. Той самий підхід докладніше розібрано на прикладі світлодіодного блимача в [неблокуючому вогнику KY-034](book:actuators/ky-034-flash/proj-ky034-blink.md) — механіка тотожна, бо і там, і тут ми керуємо лише фактом «увімкнено».

## Неблокуючий біп: той самий ритм, вільний loop()

Перепишемо `beep` так, щоб він **запускав** звук і одразу повертав керування, а гасіння робив пізніше сам, коли надійде час. Уся ідея вкладається в кілька змінних стану й одну перевірку часу в циклі.

**Умова.** KY-012 на D8 (GPIO 8). Хочемо пискнути на 80 мс на якусь подію — і щоб `loop()` увесь цей час лишався вільним для іншої роботи. Ніяких `delay`.

:::tabs
```cpp
const uint8_t BUZZER = 8;

bool          beeping   = false;   // чи зараз триває біп
unsigned long beepUntil = 0;       // момент (мс), коли біп треба вимкнути

void setup() {
  pinMode(BUZZER, OUTPUT);
  digitalWrite(BUZZER, LOW);
}

// Запустити біп на ms мілісекунд і ОДРАЗУ повернути керування.
void beepStart(unsigned int ms) {
  digitalWrite(BUZZER, HIGH);      // вмикаємо звук зараз
  beeping   = true;
  beepUntil = millis() + ms;       // запам'ятовуємо, КОЛИ вимкнути
}

// Смикати в КОЖНОМУ loop(): гасить біп, коли настав його час. Нічого не блокує.
void beepUpdate() {
  if (beeping && (long)(millis() - beepUntil) >= 0) {  // час вийшов?
    digitalWrite(BUZZER, LOW);
    beeping = false;
  }
}

void loop() {
  // приклад події: раз на 2 с пускаємо короткий біп
  static unsigned long lastEvent = 0;
  if (millis() - lastEvent >= 2000) {
    lastEvent = millis();
    beepStart(80);                 // пустили й полетіли далі — loop() не завмер
  }

  beepUpdate();                    // єдиний обов'язок біпа щоцикл

  // ...тут будь-яка інша логіка: читання кнопок, давачів — вона не блокована
}
```
```micropython
from machine import Pin
import time

buzzer = Pin(8, Pin.OUT)
buzzer.value(0)

beeping   = False                  # чи зараз триває біп
beep_until = 0                     # момент (мс), коли біп треба вимкнути

# Запустити біп на ms мс і ОДРАЗУ повернути керування.
def beep_start(ms):
    global beeping, beep_until
    buzzer.value(1)                # вмикаємо звук зараз
    beeping = True
    beep_until = time.ticks_add(time.ticks_ms(), ms)  # КОЛИ вимкнути

# Смикати в КОЖНІЙ ітерації: гасить біп, коли настав час. Нічого не блокує.
def beep_update():
    global beeping
    if beeping and time.ticks_diff(time.ticks_ms(), beep_until) >= 0:
        buzzer.value(0)
        beeping = False

last_event = time.ticks_ms()
while True:
    now = time.ticks_ms()
    # приклад події: раз на 2 с пускаємо короткий біп
    if time.ticks_diff(now, last_event) >= 2000:
        last_event = now
        beep_start(80)             # пустили й полетіли далі — цикл не завмер

    beep_update()                  # єдиний обов'язок біпа щоцикл
    # ...тут будь-яка інша логіка, вона не блокована
```
:::

Механіка проста, але в ній є два місця, повз які проходять усі, хто пише таймери на `millis()` уперше.

**Ми запам'ятовуємо момент, а не спимо до нього.** `beepStart` вмикає звук і кладе в `beepUntil` майбутній момент вимкнення (`millis() + ms`), після чого **одразу повертається**. Далі `beepUpdate`, який ти смикаєш щоцикл, лише порівнює: чи `millis()` уже дійшов до `beepUntil`? Якщо ні — нічого не робить, `loop()` летить далі; якщо так — гасить зумер. Звук триває рівно ті ж 80 мс, але всі 80 мс чіп вільний.

**Порівнюй різницю, а не самі мітки — через переповнення лічильника.** Ось найтихіша пастка всього неблокуючого коду. `millis()` — це `unsigned long`, 32-бітне беззнакове число; воно рахує до 4 294 967 295 і **переповнюється, обнуляючись, приблизно за 49.7 доби** безперервної роботи (це 2³² мілісекунд). Якби ми писали «в лоб» `if (millis() >= beepUntil)`, то в ту мить, коли `beepUntil` порахувався біля стелі, а `millis()` уже перескочив через нуль і став маленьким, порівняння збрехало б — біп або не вимкнувся б, або вимкнувся негайно. Рятунок — рахувати **різницю** й дивитися на її знак: `(long)(millis() - beepUntil) >= 0`. Беззнакове віднімання коректно переживає переповнення (старший біт просто відкидається й компенсує сам себе), а приведення різниці до знакового `long` дає правильну відповідь «час настав / ще ні» навіть у ту єдину мить на 49 діб.

> 🔧 **Навіщо це.** Правило залізне й переноситься на будь-який таймер: **усі мітки часу з `millis()` — `unsigned long`, і порівнюй різницю, а не самі мітки.** Візьмеш `int` замість `unsigned long` — і на Arduino Uno, де `int` лише 16-бітний (стеля 32767), таймер зламається вже за 33 секунди, бо `millis()` переросте `int` майже одразу. У MicroPython ту саму роль грають `time.ticks_add` (додати інтервал до мітки) і `time.ticks_diff` (різниця двох міток) — вони навмисне зроблені так, щоб коректно проходити переповнення платформозалежного лічильника `ticks_ms`; **напряму віднімати `ticks_ms()` там не можна**, діапазон лічильника не гарантований. Це та сама арифметика переповнення, докладніше розкрита в [неблокуючому вогнику KY-034](book:actuators/ky-034-flash/proj-ky034-blink.md), — і вона однакова, керуєш ти світлодіодом чи зумером.

## Патерн-програвач: N біпів і тривога без `delay`

Один неблокуючий біп — це добре, але справжня мова — це **послідовності**: три біпи на помилку, серія на тривогу. Тут з'являється нова складність — у патерна тепер є не лише «увімкнено/вимкнено», а й **лічильник кроків, що лишилися**, і його треба довести до кінця, жодного разу не заблокувавши програму.

Спокуса написати це через `for` із `delay` усередині — і знову впертися в те, від чого тікаємо: поки грає серія з п'яти біпів, чіп на дві-три секунди глухне. Тому патерн теж робимо неблокуючим — на тому самому таймері, але з лічильником півфаз, що лишилися. Ідея та сама, що з пачкою спалахів світлодіода: один «біп» для вуха — це **дві** зміни стану (увімкнути + вимкнути), тож серію з N біпів ми проганяємо як ланцюжок із 2·N однакових кроків, і сама парність лічильника каже, у якій ми зараз фазі.

**Умова.** KY-012 на D8. За подією (тут — натиск кнопки на D2, замкнутої на землю) зумер має видати серію: **три біпи по 100 мс** із паузами по 100 мс, після чого затихнути й чекати. Нові натиски під час серії ігноруємо, доки вона не добіжить.

:::tabs
```cpp
const uint8_t BUZZER = 8;
const uint8_t PIN_BTN = 2;         // кнопка між піном і землею

const unsigned long HALF_MS = 100; // тривалість кожної півфази (біп / пауза)

uint8_t       stepsLeft = 0;       // скільки перемикань стану ще лишилось
bool          soundOn   = false;
unsigned long lastFlip  = 0;

void setup() {
  pinMode(BUZZER, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);  // у спокої HIGH; натиск замикає на землю → LOW
  digitalWrite(BUZZER, LOW);
}

// Запустити серію з n біпів. Один біп = увімкнути + вимкнути = 2 перемикання.
void beepSeries(uint8_t n) {
  stepsLeft = n * 2;               // n біпів = 2·n змін стану
  lastFlip  = millis();
  soundOn   = true;                // перший крок — одразу вмикаємо звук
  digitalWrite(BUZZER, HIGH);
}

bool seriesBusy() { return stepsLeft > 0; }

void loop() {
  unsigned long now = millis();

  // 1) подія: натиск запускає серію, лише коли попередня вже добігла
  static bool wasPressed = false;
  bool pressed = (digitalRead(PIN_BTN) == LOW);
  if (pressed && !wasPressed && !seriesBusy()) {
    beepSeries(3);                 // три біпи на помилку
  }
  wasPressed = pressed;

  // 2) неблокуючий прогін серії
  if (stepsLeft > 0 && now - lastFlip >= HALF_MS) {
    lastFlip = now;
    stepsLeft--;
    if (stepsLeft == 0) {
      soundOn = false;             // остання фаза — гарантовано гасимо
    } else {
      soundOn = !soundOn;          // перемикаємо далі: біп / пауза / біп …
    }
    digitalWrite(BUZZER, soundOn ? HIGH : LOW);
  }

  // loop() лишається вільним увесь час, і під час серії теж
}
```
```micropython
from machine import Pin
import time

BUZZER  = 8
PIN_BTN = 2                        # кнопка між піном і землею

HALF_MS = 100                      # тривалість кожної півфази (біп / пауза)

buzzer = Pin(BUZZER, Pin.OUT)
btn    = Pin(PIN_BTN, Pin.IN, Pin.PULL_UP)  # у спокої 1; натиск → 0
buzzer.value(0)

steps_left = 0                     # скільки перемикань стану ще лишилось
sound_on   = False
last_flip  = time.ticks_ms()

# Запустити серію з n біпів. Один біп = 2 перемикання стану.
def beep_series(n):
    global steps_left, last_flip, sound_on
    steps_left = n * 2             # n біпів = 2·n змін стану
    last_flip  = time.ticks_ms()
    sound_on   = True              # перший крок — одразу вмикаємо
    buzzer.value(1)

def series_busy():
    return steps_left > 0

was_pressed = False
while True:
    now = time.ticks_ms()

    # 1) подія: натиск запускає серію, лише коли попередня добігла
    pressed = (btn.value() == 0)
    if pressed and not was_pressed and not series_busy():
        beep_series(3)             # три біпи на помилку
    was_pressed = pressed

    # 2) неблокуючий прогін серії
    if steps_left > 0 and time.ticks_diff(now, last_flip) >= HALF_MS:
        last_flip = now
        steps_left -= 1
        if steps_left == 0:
            sound_on = False       # остання фаза — гарантовано гасимо
        else:
            sound_on = not sound_on
        buzzer.value(1 if sound_on else 0)
```
:::

Тут кілька рішень, кожне з яких неочевидне, доки не наступиш на граблі.

**Чому лічильник рахує перемикання, а не біпи.** Один біп для вуха — це «пискнув і замовк», тобто **два** перемикання стану. Тому `beepSeries(3)` кладе `stepsLeft = 6`, і кожне спрацювання таймера зменшує лічильник на одиницю, послідовно перемикаючи `soundOn`: увімк, вимк, увімк, вимк, увімк, вимк. Так уся серія стає рівномірним ланцюжком однакових кроків по `HALF_MS`, і не треба окремо стежити «я зараз пищу чи мовчу» — про це каже сама парність лічильника.

**Чому остання фаза гаситься примусово.** Якби ми просто чергували `soundOn = !soundOn`, результат залежав би від парності: за парного числа перемикань зумер урешті замовк би сам, за непарного — лишився б пищати **безкінечно**. А це найгірше, що може статися з зумером: застряглий увімкнений тон, який не гасне. Явне `if (stepsLeft == 0) soundOn = false` прибирає цю залежність: **серія завжди закінчується тишею**, скільки б біпів ти не замовив. Дрібниця, без якої «пискнути чотири рази» іноді лишало б зумер тихо (ні, гучно!) гудіти.

**Чому ловимо фронт натиску, а не рівень.** Умова `pressed && !wasPressed` спрацьовує лише в **мить переходу** з «не натиснуто» в «натиснуто» — це фронт. Якби ми запускали серію просто за `pressed`, то поки палець тримає кнопку, `loop()` пролітав би тисячі разів і намагався б перезапускати серію щоразу. Друга умова, `!seriesBusy()`, додає запобіжник: нова серія не почнеться, доки не добігла попередня. Разом вони роблять поведінку передбачуваною — один натиск дає рівно одну серію з трьох біпів.

> 🔧 **Навіщо це.** Оцей візерунок — стан у кількох змінних, уся механіка в одній перевірці часу, яку смикаєш щоцикл, лічильник кроків, що сам себе доводить до тиші, — і є азбука неблокуючого коду на мікроконтролері без операційної системи. Він не про зумер зокрема: так само проганяють пачку спалахів світлодіода, серію імпульсів на реле, будь-яку скінченну послідовність у часі. І тут є ще один суто «зумерний» наголос, якого немає у світлодіода: **застряглий увімкнений вихід у зумера болючіший**, бо світлодіод, що не згас, — це косметика, а зумер, що не замовк, — це нестерпний писк, який доводиться гасити висмикуванням дроту. Тому примусове гасіння останнього кроку тут не «акуратність», а необхідність.

## Обгортка-клас: щоб не тримати таймери в голові

Приклади вище робочі, але глобальні змінні `soundOn`, `lastFlip`, `stepsLeft` розповзлися по скетчу. Щойно захочеш **другий** зумер (чи зумер плюс окремий світлодіод-індикатор), доведеться дублювати весь набір змінних із новими іменами — і код заплутається. Правильно спакувати весь стан і всю логіку в **одну сутність**, якій ти лише кажеш «пискни раз», «видай серію з трьох», а вона сама тримає свій час. У C++ це клас; у MicroPython — теж клас.

Зберемо клас `Buzzer`, який уміє три речі: короткий одиночний біп, серію з N біпів, і безперервну тривогу (увімкнено, доки не скажеш «стоп»). Уся неблокуюча механіка ховається всередину `update()`, який ти смикаєш у кожному `loop()`.

:::tabs
```cpp
// --- Buzzer: неблокуючий драйвер активного зумера (KY-012 і подібних) ---
// Керує ЛИШЕ ввімкненням/вимкненням: висоту тону активного зумера змінити не можна.
class Buzzer {
public:
  explicit Buzzer(uint8_t pin) : _pin(pin) {}

  void begin() {
    pinMode(_pin, OUTPUT);
    _write(false);
  }

  // Один біп на ms мілісекунд.
  void beep(unsigned int ms) {
    _mode  = ONESHOT;
    _write(true);
    _until = millis() + ms;
  }

  // Серія з n біпів по half мс на півфазу (біп / пауза), тоді сама затихає.
  void series(uint8_t n, unsigned long half) {
    _mode  = SERIES;
    _left  = n * 2;                // n біпів = 2·n перемикань
    _half  = half;
    _last  = millis();
    _write(true);
  }

  // Безперервний тон, доки не викличеш stop(). Для тривоги.
  void on()  { _mode = SOLID; _write(true);  }
  void stop() { _mode = SOLID; _write(false); }

  bool busy() const { return _mode == SERIES && _left > 0; }

  // Смикати в КОЖНОМУ loop(). Нічого не блокує.
  void update() {
    unsigned long now = millis();

    if (_mode == ONESHOT) {
      if (_isOn && (long)(now - _until) >= 0) { _write(false); _mode = SOLID; }
      return;
    }
    if (_mode == SERIES) {
      if (_left > 0 && now - _last >= _half) {
        _last = now;
        _left--;
        if (_left == 0) { _write(false); _mode = SOLID; }  // серія добігла — тиша
        else            { _write(!_isOn); }
      }
      return;
    }
    // SOLID — нічого рахувати: тримаємо заданий стан
  }

private:
  enum Mode { SOLID, ONESHOT, SERIES };

  void _write(bool onState) {
    _isOn = onState;
    digitalWrite(_pin, onState ? HIGH : LOW);   // HIGH-тригер: HIGH пищить
  }

  uint8_t       _pin;
  Mode          _mode  = SOLID;
  bool          _isOn  = false;
  unsigned long _until = 0, _last = 0, _half = 100;
  uint8_t       _left  = 0;
};

// ---------- використання ----------
Buzzer buz(8);                      // модуль на D8
const uint8_t PIN_BTN = 2;

void setup() {
  buz.begin();
  pinMode(PIN_BTN, INPUT_PULLUP);
}

void loop() {
  static bool wasPressed = false;
  bool pressed = (digitalRead(PIN_BTN) == LOW);
  if (pressed && !wasPressed && !buz.busy()) {
    buz.series(3, 100);             // натиск → три біпи на помилку
  }
  wasPressed = pressed;

  buz.update();                     // єдиний обов'язок: смикати щоцикл
  // ...тут будь-яка інша логіка скетчу, вона не блокована
}
```
```micropython
# --- Buzzer: неблокуючий драйвер активного зумера (KY-012 і подібних) ---
# Керує ЛИШЕ ввімкненням/вимкненням: висоту тону змінити не можна.
from machine import Pin
import time

SOLID, ONESHOT, SERIES = 0, 1, 2

class Buzzer:
    def __init__(self, pin):
        self._pin  = Pin(pin, Pin.OUT)
        self._mode = SOLID
        self._is_on = False
        self._until = 0
        self._last  = time.ticks_ms()
        self._half  = 100
        self._left  = 0
        self._write(False)

    def _write(self, on_state):
        self._is_on = on_state
        self._pin.value(1 if on_state else 0)   # HIGH-тригер: 1 пищить

    # Один біп на ms мс.
    def beep(self, ms):
        self._mode = ONESHOT
        self._write(True)
        self._until = time.ticks_add(time.ticks_ms(), ms)

    # Серія з n біпів по half мс на півфазу, тоді сама затихає.
    def series(self, n, half):
        self._mode = SERIES
        self._left = n * 2                # n біпів = 2·n перемикань
        self._half = half
        self._last = time.ticks_ms()
        self._write(True)

    # Безперервний тон, доки не викличеш stop(). Для тривоги.
    def on(self):   self._mode = SOLID; self._write(True)
    def stop(self): self._mode = SOLID; self._write(False)

    def busy(self):
        return self._mode == SERIES and self._left > 0

    # Смикати в КОЖНІЙ ітерації. Нічого не блокує.
    def update(self):
        now = time.ticks_ms()

        if self._mode == ONESHOT:
            if self._is_on and time.ticks_diff(now, self._until) >= 0:
                self._write(False); self._mode = SOLID
            return
        if self._mode == SERIES:
            if self._left > 0 and time.ticks_diff(now, self._last) >= self._half:
                self._last = now
                self._left -= 1
                if self._left == 0:
                    self._write(False); self._mode = SOLID   # серія добігла — тиша
                else:
                    self._write(not self._is_on)
            return
        # SOLID — тримаємо заданий стан

# ---------- використання ----------
buz = Buzzer(8)                      # модуль на пін 8
btn = Pin(2, Pin.IN, Pin.PULL_UP)

was_pressed = False
while True:
    pressed = (btn.value() == 0)
    if pressed and not was_pressed and not buz.busy():
        buz.series(3, 100)           # натиск → три біпи на помилку
    was_pressed = pressed

    buz.update()                     # єдиний обов'язок: смикати щоцикл
    # ...тут будь-яка інша логіка, вона не блокована
```
:::

Що ця обгортка дає й чому вона краща за розсипані глобальні змінні.

По-перше, **увесь стан зумера живе в об'єкті**. Хочеш два незалежні звукові канали — оголошуєш `Buzzer buzA(8), buzB(9);`, кожен зі своїм таймером, і смикаєш обидва `update()` у циклі. Жодного дублювання змінних, жодної плутанини, чий зараз `lastFlip`.

По-друге, **зовні лишився чистий намір**: `buz.beep(80)`, `buz.series(3, 100)`, `buz.on()`, `buz.stop()`. Читаючи `loop()`, ти бачиш **що** роблять зі звуком, а не **як** влаштований його таймер. Уся неблокуюча механіка — розрахунок фаз, лічильник, примусове гасіння в кінці — сховалася за `update()`.

По-третє, режими **чисто витісняють один одного**. Виклик `on()` чи `stop()` переводить `_mode` у `SOLID`, і `update()` для такого режиму нічого не рахує — зумер просто стоїть у заданому стані. Одиночний біп і серія після завершення самі повертають режим у `SOLID`, тож не лишають по собі «завислого» таймера. А `busy()` дає зовнішньому коду спитати «серія ще триває?» — саме ним ми не даємо натиску перезапустити серію, доки попередня не добігла.

> 🔧 **Навіщо це.** Один клас `Buzzer` перетворює всю писанину з таймерами на чотири зрозумілі дієслова, і це різниця між кодом, у який можна повернутися за місяць, і кашею з глобальних змінних. Але головна вигода — **безпека тиші**: усі три режими сходяться в `SOLID` із вимкненим виходом, тобто зумер за замовчуванням тяжіє до мовчання, а не до писку. Для пристрою, який стоятиме на столі й пищатиме людині у вухо, це не педантизм — це різниця між «спрацював і замовк» і «застряг і виє, поки не висмикнеш живлення». Той самий кістяк неблокуючого драйвера — стан у полях, механіка в одному `update()` — розібрано й для світлодіода в [обгортці KY-034](book:actuators/ky-034-flash/proj-ky034-blink.md); зумер відрізняється лише тим, що ціна застряглого виходу тут вища.

## Чому tone() і ШІМ на активному зумері — марна робота

Окремо варто прибити хибну надію, бо на неї витрачають години. Побачивши, що висоту тону змінити не вдається, новачок тягнеться до Arduino-функції `tone(pin, frequency)` — вона ж «грає ноту заданої частоти». На активному зумері **вона нічого не дасть**, і важливо розуміти, *чому саме*, а не просто «так не можна».

`tone()` подає на пін меандр (прямокутну хвилю) заданої частоти — швидке `HIGH-LOW-HIGH-LOW` рівно стільки разів на секунду, скільки ти замовив. Для **пасивного** зумера це і є пісня: у нього немає власного генератора, він голий п'єзоелемент, тож він коливається рівно з тією частотою, яку йому нав'язує пін, — постав `tone(pin, 440)`, і він видасть ноту «ля». Активний зумер влаштований інакше: у нього **всередині сидить власний генератор** на заводській частоті (≈2.5 кГц), і мембраною командує саме він, а не твій пін. Пін для активного зумера — це лише вимикач живлення тієї внутрішньої схеми: є напруга — генератор працює й веде свою ноту, немає — мовчить.

Що ж станеться, як подати `tone(pin, 440)` на активний зумер? Пін почне вмикати-вимикати живлення генератора 440 разів на секунду. Генератор при цьому щоразу, коли на нього приходить напруга, силкується завести свою ноту 2.5 кГц — але його раз по раз обривають. У результаті ти почуєш не «ля», а **той самий заводський писк 2.5 кГц, порізаний на шматочки з частотою 440 Гц** — брудне деренчання, а не музику. Висота головного тону не зрушила ні на герц, бо її задає внутрішній генератор, до якого твоя частота не має доступу.

```
пасивний зумер:  пін ── меандр 440 Гц ──► голий п'єзо коливається з 440 Гц → нота «ля»
активний зумер:  пін ── меандр 440 Гц ──► вмикає/вимикає ГЕНЕРАТОР 2.5 кГц
                                          → чуємо 2.5 кГц, порізаний на 440 Гц (брудно)
```

Висновок практичний: на KY-012 `tone()`, `analogWrite()` (ШІМ) і будь-яке жонглювання частотою — **марна робота**. Єдине, що працює, — `digitalWrite(HIGH/LOW)` і ритм у часі, яким ми й займалися весь цей текст. Якщо в задачі справді потрібна **змінна висота, мелодія чи сирена з ковзанням тону** — це фізично не про активний зумер, а про [пасивний](book:actuators/ky-006-buzzer), якому `tone()` віддає саме те, для чого зроблено. Вибір між ними — це вибір «один простий біп задарма» проти «будь-яка нота, але грай її сам сигналом».

> 🔧 **Навіщо це.** Ця відмінність — не дрібниця API, а сама межа між двома класами пристроїв, і плутанина тут коштує найбільше часу з усього зумерного коду: людина годину крутить `tone()` з різними частотами, чує однаковий писк і думає, що «зумер бракований» або «бібліотека глючить», хоча все справне — просто інструмент не про цей зумер. Запам'ятай механізм — «активний носить генератор усередині, пін лише вмикає його» — і питання «як зіграти мелодію на KY-012» відпадає само: ніяк, бо він знає рівно одну ноту й видає її бездоганно.

## Складність і пастки: що ловить у цьому коді

Код тут неважкий, але кілька місць чіпляють навіть тих, хто вже писав неблокуючі таймери. Зберімо їх докупи.

**HIGH-тригер — не інвертуй.** KY-012 пищить від `HIGH` і мовчить від `LOW`, без викрутасів, — на відміну від багатьох компараторних KY-модулів із вивернутим `DO`. Не переноси на нього звичку «нуль — це активний стан»; тут навпаки, і сплутаєш — зумер або мовчатиме весь час, або, гірше, гудітиме безперервно, бо ти тримаєш його в «спокої», який насправді ввімкнений.

**`delay()` глушить усе, а не лише зумер.** Найпідступніша пастка, бо код на `delay` виглядає простим і «працює» в іграшковому скетчі. Щойно додаси кнопку чи давач — вони почнуть «не помічатися» рівно тоді, коли зумер звучить. Для будь-чого, складнішого за один біп у порожньому `loop()`, бери неблокуючий варіант: запусти звук, запам'ятай момент вимкнення, гаси в `update()`.

**Тип часу — тільки беззнаковий і широкий, порівнюй різницю.** Усі мітки з `millis()` — `unsigned long`, і звіряй `now - mark`, а не самі мітки. `int` зламається за 33 секунди (16-бітний на Uno переповниться майже одразу), знаковий `long` збреше в мить переповнення на 49-й добі. У MicroPython напряму віднімати `ticks_ms()` не можна взагалі — тільки через `time.ticks_diff` (і `time.ticks_add`, щоб додати інтервал до мітки), бо лише вони коректно проходять переповнення платформозалежного лічильника.

**Серія має чисто закінчуватися тишею.** Якщо чергувати `!soundOn` без явного гасіння в кінці, зумер за непарного числа перемикань лишиться **пищати безкінечно** — а це для зумера значно болючіше, ніж для світлодіода: застряглий тон нестерпний і гаситься хіба висмикуванням живлення. Примусове `_write(false)` на останньому кроці робить кінець серії детермінованим — **завжди тиша**, скільки б біпів не замовили.

**Безперервний писк дратує на робочому столі.** 85 децибел зблизька — це справді голосно й швидко набридає під час налагодження. Поки крутиш код, зменшуй тривалість біпів, розводь їх довшими паузами або тимчасово заклей отвір зумера пальцем чи стрічкою — суцільний тон над клавіатурою витримати важко, і спокуса «просто вимкнути перевірку звуку» шкодить самому налагодженню.

**tone() і ШІМ марні — не гай на них час.** Активний зумер має власний генератор на фіксованій частоті; `tone()` лише ріже цей писк на шматки, а висоти не міняє. Змінний тон і мелодії — це [пасивний зумер](book:actuators/ky-006-buzzer), не цей. На KY-012 працює тільки `digitalWrite` і ритм.

**Один пін тягне зумер напряму — але через ключ на платі.** KY-012 можна чіпляти прямо до GPIO, бо робочий струм (до ~30 мА) бере не пін, а транзистор на платі; від піна йдуть лише мікроампери в базу. Тому окремий зовнішній транзистор для одного модуля не потрібен — обв'язка вже про це подбала. Це зручність активного модуля супроти голого зумера, який довелося б живити обережніше.

Оце, власне, і вся програмна робота з KY-012, зроблена чесно — так, щоб зумер вписався в живий скетч, а не в порожній `loop()`. Модуль уміє рівно одне: рівний писк на одній ноті, поки на нього подано одиницю. Наша справа з боку коду — **розпорядитися цією одиницею в часі розумно**: скласти з біпів маленький словник сигналів, видавати їх без `delay`, тримати весь стан в акуратній обгортці, яка тяжіє до тиші, — і не гаяти годин на `tone()`, якому тут нема чим керувати. Усе інше — висоту, тембр, гучність — вирішив завод усередині чорного циліндрика, і в це ми не втручаємось, бо й не можемо.
