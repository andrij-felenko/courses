# ⚙️ Термокероване охолодження: вентилятор, що сам підганяє швидкість під температуру

Вентилятор, який завжди крутиться на повну, розв'язує задачу охолодження найгрубішим способом: він шумить у тиші, дарма зношується й ганяє пил навіть тоді, коли всередині прохолодно. Куди краще, щоб він **мовчав, поки холодно, і прискорювався рівно настільки, наскільки нагрілося** — а ще щоб система **знала, що вентилятор живий**, і зчинила тривогу, якщо той раптом став, поки радіатор гарячий. Зберемо саме таку річ із трьох готових [рецептів керування вентилятором у коді](book:actuators/fan-5v/api-fan-control.md): генерації 25-кГц ШІМ, підрахунку обертів і — якщо треба — ключа. Тут не самі рецепти, а те, як вони складаються в закінчений вузол.

Логіка керування вкладається в один ланцюжок: **читаємо температуру → переводимо її в бажаний відсоток швидкості → віддаємо на ШІМ → а оберти з тахометра тримаємо як сторожа**. Перші три ланки — це просто робота; уся хитрість — у кривій «температура→швидкість» і в тому, як чесно зробити сторожа, щоб він не бив на сполох дарма.

## Крива швидкості: від тиші до повної

Питання, на яке відповідає крива, одне: **скільки відсотків швидкості давати при цій температурі?** Найгрубіша відповідь — «вмикати на повну, коли гаряче» — повертає нас до шумного вентилятора, тільки з паузами. Потрібне плавне: нижче певної температури — тиша (0 %), вище другої — повна (100 %), а між ними швидкість росте поступово, щоб вентилятор саме встигав відводити стільки тепла, скільки додається.

Найпростіша така крива — **лінійна між двома порогами**. Нижче `tMin` вентилятор стоїть; вище `tMax` крутить на повну; між ними відсоток пропорційний тому, наскільки температура зайшла у вікно `tMin…tMax`:

```cpp
// Крива швидкості: нижче tMin — стоп; вище tMax — повна; між — лінійно
uint8_t tempToPercent(float t) {
  const float tMin = 35.0f, tMax = 65.0f;
  if (t <= tMin) return 0;                               // прохолодно — тиша
  if (t >= tMax) return 100;                             // гаряче — повна
  return (uint8_t)((t - tMin) / (tMax - tMin) * 100.0f); // між — лінійно
}
```

Два пороги задають характер охолодження. Низький `tMin` (тут 35 °C) — це поріг тиші: доти вентилятор просто не потрібен. Високий `tMax` (65 °C) — температура, за якої вже треба видувати все, що можеш. Ставте їх під свою залізяку: `tMax` — трохи нижче за небезпечну для неї температуру, `tMin` — там, де тепло вже варто відводити, але ще не терміново.

## Складаємо цикл

Тепер видно, як усе зшивається в один цикл, що працює раз на секунду. Секунда — зручний крок: температура так швидко не стрибає, а тахометр саме встигає накопичити досить імпульсів для точного числа обертів.

```cpp
// esp32-fan-thermal.ino — швидкість за температурою + сторож обертів
#include <Arduino.h>
#include "driver/pulse_cnt.h"

const int PWM_PIN  = 25;
const int PWM_FREQ = 25000;   // 25 кГц — генерацію див. у рецепті ШІМ
const int PWM_BITS = 8;
const int TACH_PIN = 27;
const int DUTY_MAX = (1 << PWM_BITS) - 1;

pcnt_unit_handle_t    unit = nullptr;   // лічильник обертів
pcnt_channel_handle_t chan = nullptr;   // (налаштування — у рецепті TACH)

float readTempC();       // ← ваш давач (NTC, DS18B20, BME280 — байдуже)
void  tachPcntBegin();   // ← як у рецепті з апаратним лічильником PCNT

uint8_t tempToPercent(float t) {
  const float tMin = 35.0f, tMax = 65.0f;
  if (t <= tMin) return 0;
  if (t >= tMax) return 100;
  return (uint8_t)((t - tMin) / (tMax - tMin) * 100.0f);
}

void fanSetSpeed(uint8_t percent) {     // деталі — у рецепті ШІМ
  if (percent > 100) percent = 100;
  ledcWrite(PWM_PIN, (uint32_t)percent * DUTY_MAX / 100);
}

void setup() {
  Serial.begin(115200);
  ledcAttach(PWM_PIN, PWM_FREQ, PWM_BITS);
  pinMode(TACH_PIN, INPUT_PULLUP);
  tachPcntBegin();
}

uint8_t  deadSeconds = 0;    // скільки секунд поспіль наказ є, а обертів нема
uint32_t lastMs = 0;

void loop() {
  uint32_t now = millis();
  if (now - lastMs < 1000) return;      // один крок керування на секунду
  lastMs = now;

  float   t   = readTempC();
  uint8_t pct = tempToPercent(t);
  fanSetSpeed(pct);

  int count = 0;
  pcnt_unit_get_count(unit, &count);
  pcnt_unit_clear_count(unit);
  uint32_t rpm = (count / 2) * 60;      // ÷2 (2 імпульси/оберт) ×60 (у хвилини)

  // Сторож зі стартовою відстрочкою (нижче — чому не «в лоб»)
  if (pct > 0 && rpm == 0) {
    if (deadSeconds < 255) deadSeconds++;
  } else {
    deadSeconds = 0;                     // закрутився або наказ знято — лічильник у нуль
  }
  if (deadSeconds >= 3) {                // 3 с наказу без жодного оберту — біда
    Serial.println("!!! ТРИВОГА: наказано крутитися, а обертів нема — перевір вентилятор");
    // тут: аварійний вихід, скид навантаження, зниження тактової тощо
  }

  Serial.printf("t=%.1f°C  швидкість=%u%%  оберти=%u об/хв\n", t, pct, rpm);
}
```

Три робочі ланки — `tempToPercent`, `fanSetSpeed`, читання PCNT — тут навмисне тонкі: як саме народжується 25-кГц ШІМ і як налаштувати апаратний лічильник обертів, розписано в [рецептах керування](book:actuators/fan-5v/api-fan-control.md); у цьому прикладі важить не вони, а те, що між ними діється.

## Сторож, який не бреше на старті

Найспокусливіший сторож — «наказали крутитися, а обертів нема, отже вентилятор мертвий»:

```cpp
if (pct > 0 && rpm == 0) alarm();   // ← наївно, дає хибну тривогу
```

Він гарний рівно до першого запуску. Вентилятор **не закручується миттєво**: від подачі ШІМ до перших зчитаних обертів минає частка секунди на розгін ротора, та ще й тахометр рахує за цілий інтервал — тобто в ту саму першу секунду, коли наказ уже є, обертів у лічильнику ще нуль. Наївний сторож саме тут і зчиняє тривогу на цілком справному вентиляторі, який просто ще не встиг набрати оберти. Те саме буде щоразу, коли температура перетне `tMin` і вентилятор тільки рушає з місця.

Ліки — **відстрочка**: бити на сполох не з першого нульового зчитування, а лише коли наказ крутитися тримається кілька секунд поспіль, а обертів усе нема. Лічильник `deadSeconds` рахує такі секунди підряд і обнуляється, щойно з'явився бодай один оберт (вентилятор ожив) або знявся наказ (`pct` упав у нуль). Три секунди поспіль без жодного оберту при живому наказі — це вже не розгін, а справжня біда: заклинило, запилилося, відпав роз'єм. Поріг у три секунди — з запасом більший за час розгону будь-якого дрібного вентилятора, тож хибних тривог він не дає, а справжню зупинку ловить швидко.

> 🔧 **Навіщо це.** Сторож обертів — головна причина взагалі тягнути третій дріт вентилятора в код. Вентилятор стоїть у глухому кутку приладу, ніхто на нього не дивиться, а від нього залежить, чи не звариться те, що він охолоджує. Мовчазний сторож, який ловить зупинку за три секунди й устигає скинути навантаження чи знизити тактову, — це різниця між «прилад пригальмував і охолов» і «прилад згорів, бо вентилятор тихо помер півгодини тому».

## Гістерезис: щоб не смикався на межі

Лишається одна прикрість, помітна саме на межі ввімкнення. Температура біля порогу `tMin` ніколи не стоїть рівно — вона тремтить на десяті градуса туди-сюди. Проста крива на це реагує буквально: 34.9 °C — стоп, 35.1 °C — пуск, 34.9 — знову стоп. Вентилятор починає **клацати ввімк-вимк** кілька разів на хвилину, і це чутно й неприємно, а часті пуски ще й зношують мотор дужче за рівномірне обертання.

Ліки — **гістерезис**: розвести поріг пуску й поріг зупину. Вмикати вентилятор при `tOn`, а вимикати не там само, а помітно нижче — при `tOff`. Поки температура гуляє в зазорі між ними, вентилятор не змінює рішення, і тремтіння на межі його вже не смикає:

```cpp
// Крива з гістерезисом: пуск на tOn, а стоп аж на tOff (нижче за tOn)
uint8_t tempToPercentHyst(float t) {
  static bool running = false;                 // пам'ять рішення між викликами
  const float tOn = 35.0f, tOff = 30.0f, tMax = 65.0f;
  if (!running && t >= tOn)  running = true;   // нагрілося до tOn — вмикаємось
  if ( running && t <  tOff) running = false;  // охололо аж до tOff — вимикаємось
  if (!running) return 0;
  if (t >= tMax) return 100;
  return (uint8_t)((t - tOff) / (tMax - tOff) * 100.0f);
}
```

П'ятиградусний зазор (35 на пуск, 30 на стоп) означає: раз закрутившись на 35 °C, вентилятор працюватиме, аж поки не охолодить залізо до 30 — і тільки тоді змовкне. Одне ввімкнення й одне вимкнення на цикл нагріву замість нервового клацання. Розмір зазору — під ваш смак і теплову інерцію: більший зазор тихіший, зате тримає вентилятор увімкненим довше.

## Пастки саме цього застосування

Загальні граблі керування — надто повільний ШІМ, забута підтяжка тахометра, живлення мотора з ніжки — розібрані в рецептах керування вентилятором. Тут — ті, що вилазять саме коли складаєш термокероване охолодження.

**Наївний сторож без відстрочки.** `pct > 0 && rpm == 0` дає хибну тривогу щоразу на розгоні: вентилятор ще не набрав оберти, а код уже кричить, що той помер. Лічіть секунди підряд і бийте на сполох лише після кількох.

**Крива без гістерезису.** Один поріг на пуск і стоп — і вентилятор клацає ввімк-вимк, коли температура тремтить на межі. Розведіть пуск і стоп зазором.

**Забути про поштовховий струм на старті.** Крива, що стартує одразу з малих відсотків, може не зрушити вентилятор із місця: на дуже малому заповненні ШІМ моменту не вистачає на розгін, вентилятор тільки дзижчить. Якщо таке буває — давайте на пуску короткий поштовх повною швидкістю (kick-start), а вже потім спускайте на потрібний відсоток.

**Занизький `tMax`.** Якщо повна швидкість вмикається лише під самою небезпечною температурою, у різкий стрибок навантаження вентилятор не встигне. Лишайте `tMax` із запасом нижче критичної, щоб на повну виходити завчасно.

Ці чотири — уже не про те, як крутити вентилятор (це роблять рецепти), а про те, як зробити керування **розумним**: тихим, коли можна, повним, коли треба, і чесним щодо того, чи вентилятор живий.
