# ⚙️ Читаємо MQ із коду: від сирого відліку до ppm і сторожа порога

Ти під'єднав MQ-давач, живлення на місці, дротом усе гаразд. З аналогового виходу приходить якесь число — на Arduino десь від 0 до 1023, на ESP32 від 0 до 4095. Що з ним робити далі? Прочитати `analogRead()` — це одна строчка. А от перетворити цей відлік на щось, чому можна довіряти — «газу стало більше» або, якщо дуже треба, «стільки-то проміле», — це вже інженерна задача з чотирьох кроків, і кожен крок можна зробити чесно або самообманом. Розберімо всі чотири так, щоб наприкінці був робочий скетч, який ти вставиш і він поведеться передбачувано.

Задача звучить оманливо просто: **дістати з давача осмислене число**. Але «осмислене» тут — ключове слово. Сирий відлік АЦП сам по собі не значить нічого: сьогодні 300, завтра 320, і ти не знаєш, це газ прийшов чи просто стало тепліше й вологіше. Щоб число заговорило, його треба прив'язати до фізики давача — до його **опору**. А опір — до опорної точки, знятої в чистому повітрі. І лише тоді, за кривою з даташита, — до концентрації. Пройдімо цей ланцюжок ланка за ланкою.

## Крок перший: відлік АЦП назад в опір Rₛ

Згадаймо, що фізично міряє давач. Усередині — дільник напруги: живлення Vc проходить крізь змінний опір давача Rₛ, тоді крізь навантажувальний резистор Rₗ на землю, а точку між ними виведено на AO. АЦП читає напругу саме в цій точці. Отже, відлік — це не опір і не концентрація, а **напруга на Rₗ**, і з неї треба відновити Rₛ.

Дільник дає просте співвідношення. Напруга на Rₗ:

```
V_ao = Vc · Rₗ / (Rₛ + Rₗ)
```

А АЦП переганяє напругу в число пропорційно: `raw = V_ao / Vc · MAX`, де MAX — це 1023 для 10-бітного АЦП Arduino або 4095 для 12-бітного ESP32. Підставмо й виразимо Rₛ. Vc скорочується (ось чому нам не треба точно знати живлення!), і лишається чиста алгебра:

```
raw / MAX = Rₗ / (Rₛ + Rₗ)
Rₛ + Rₗ = Rₗ · MAX / raw
Rₛ = Rₗ · (MAX − raw) / raw
```

Ось і вся формула переведення. Вона гарна тим, що **не залежить від напруги живлення**: 5.0 В у тебе чи 4.85 В із USB — байдуже, бо і сигнал, і опорна шкала АЦП ростуть однаково, відношення зберігається. Залежить вона лише від одного числа — **Rₗ, опору навантажувального резистора на платі**. У класичному коді MQ (той, що ходить по всіх Arduino-туторіалах ще від Sandbox Electronics) для Rₗ беруть 5 кОм; на реальній платі це може бути 5, 10, 20 кОм — залежить від модуля, тож ідеально виміряти мультиметром той резистор або довіритися підпису. Похибка в Rₗ входить у Rₛ лінійно, але — і це рятує — вона **скорочується у відношенні Rₛ/R₀**, бо R₀ ми виміряємо тим самим Rₗ. Тому навіть якщо Rₗ у коді трохи не той, ppm майже не постраждають; постраждало б лише абсолютне Rₛ, яке нам саме по собі й не потрібне.

Ось ця ланка в коді. Одна функція, яку далі кличемо звідусіль:

:::tabs
```cpp
// Скільки квантів дає наш АЦП: 1023 для Arduino (10 біт), 4095 для ESP32 (12 біт)
const float ADC_MAX = 1023.0f;

// Опір навантажувального резистора на платі модуля, кОм.
// Класичне значення з коду MQ; на своїй платі перевір мультиметром.
const float RL_KOHM = 5.0f;

// Відлік АЦП → опір давача Rₛ (у кОм), через математику дільника.
// Живлення тут не потрібне — воно скорочується.
float mqReadRs(int raw) {
  if (raw <= 0) return INFINITY;          // 0 у знаменнику: давач «нескінченно» великий
  return RL_KOHM * (ADC_MAX - (float)raw) / (float)raw;
}
```

> 🔧 **Навіщо це.** Тут ховається перша й найтихіша пастка: **сире число з АЦП — це не опір і тим паче не проміле**. Хто пише `if (analogRead(A0) > 400) alarm()`, той прив'язав тривогу до напруги на конкретному резисторі конкретної плати за конкретної погоди — і поріг 400 нічого не значить деінде. Переведення у Rₛ — це той крок, що робить число фізичним: опір давача не залежить ні від того, який у тебе АЦП, ні від живлення, а лише від того, скільки газу на поверхні. Далі вся робота — з опором, не з відліком.

## Крок другий: опорна точка R₀ у чистому повітрі

Rₛ сам по собі теж мало каже: у одного екземпляра MQ-2 у чистому повітрі опір 3 кОм, у сусіднього — 8 кОм, і обидва справні. Розкид між екземплярами величезний, тому крива з даташита побудована не на абсолютному опорі, а на **відношенні** Rₛ/R₀, де R₀ — опір **цього самого давача** в чистому повітрі. R₀ — це особистий «нуль» кожного екземпляра, і поки ти його не знайдеш, крива не працює.

Знайти R₀ — і є **калібрування**. Ідея пряма: постав давач у явно чисте повітря, дай йому прогрітися, поміряй Rₛ багато разів, усередни — і це майже R₀. «Майже» — бо в чистому повітрі опір давача не дорівнює R₀ рівно, а більший за нього у сталу кількість разів. Ця стала для MQ-2 — **9.83** (її знімають із того самого графіка даташита: у чистому повітрі Rₛ/R₀ ≈ 9.8). Тобто:

```
R₀ = (Rₛ, виміряне в чистому повітрі) / 9.83
```

Цей множник 9.83 — не магія й не універсальна константа всіх давачів; це просто точка на кривій MQ-2, де крива перетинає «чисте повітря». Для іншої букви серії він інший. Ось калібрування в коді — окрема функція, яку кличеш **один раз** після прогріву:

```cpp
// У чистому повітрі Rₛ більше за R₀ у стільки разів (з графіка даташита MQ-2).
const float CLEAN_AIR_FACTOR = 9.83f;

// Виміряти R₀ цього екземпляра: усереднити Rₛ у чистому повітрі й поділити на множник.
float mqCalibrateR0(int analogPin) {
  const int   N = 50;        // скільки замірів усереднити
  const int   MS = 500;      // пауза між ними
  float rsSum = 0.0f;
  for (int i = 0; i < N; i++) {
    rsSum += mqReadRs(analogRead(analogPin));
    delay(MS);
  }
  float rsAir = rsSum / N;              // середній опір у чистому повітрі
  return rsAir / CLEAN_AIR_FACTOR;      // → R₀ цього давача
}
```

П'ятдесят замірів по півсекунди — це двадцять п'ять секунд стояння в чистому повітрі; усереднення гасить шум і випадкові поштовхи. Отримане R₀ ти або тримаєш у пам'яті на весь сеанс роботи, або — розумніше — **зберігаєш у флеш** (EEPROM на Arduino, Preferences/NVS на ESP32), щоб не калібруватися щоразу після ввімкнення.

Тепер — де тут закопана міна. **R₀ треба міряти на прогрітому й «випеченому» давачі, у справді чистому повітрі.** Три «якщо» — і кожне псує все далі:

Якщо давач ще не вийшов на робочу температуру (короткий розпал — десятки секунд після ввімкнення), Rₛ повзе, і R₀ вийде завищеним. Тому калібрування **не роби першою дією в `setup()`** — дай нагрівачу час.

Якщо давач **новий, щойно з пакета**, він потребує довгого початкового випалу (burn-in, порядку доби-двох безперервної роботи), поки поверхня SnO₂ не позбудеться набраної за зберігання вологи й бруду. Відкалібруєшся до випалу — і R₀ поповзе за кілька днів, коли елемент випечеться сам, а з R₀ попливуть усі ppm. Тому **калібруй після burn-in**, не раніше.

І якщо «чисте повітря» насправді не чисте — поряд курили, працює плита, стоїть відкритий розчинник — R₀ вийде заниженим, і давач потім буде занижувати газ. Калібруй там, де повітря справді свіже.

> 🔧 **Навіщо це.** R₀ — це фундамент, на якому стоїть усе інше, і якщо він кривий, кривими будуть **усі** подальші проміле, хоч би якою точною була формула. Дві третини «мій MQ показує дурню» — це погане R₀: калібрувалися на холодному давачі, або на новому до випалу, або в накуреній кімнаті. Тому не поспішай із калібруванням: увімкнув → зачекав прогрів → (для нового — прогнав добу) → переконався, що повітря чисте → тоді R₀. Один раз зроблене як слід R₀ рятує від тижня загадок.

## Крок третій: степенева формула ppm = a·(Rₛ/R₀)^b

Тепер у нас є все для головного: перетворити відношення Rₛ/R₀ на концентрацію. Крива з даташита в подвійному логарифмічному масштабі — **пряма**, а пряма в log-log означає степеневу залежність. Запишемо її так, як просив автор статті:

```
ppm = a · (Rₛ / R₀)^b
```

де a і b — сталі **для конкретного газу** (не для давача взагалі!). Показник b **від'ємний**: коли газу більше, Rₛ падає, відношення Rₛ/R₀ меншає, а ppm росте — отже, зі зменшенням основи степеня результат має рости, що й дає від'ємний показник.

Звідки беруть a і b? З двох точок на кривій даташита. У класичному коді MQ криву задають трійкою `{x, y, slope}`, де це логарифми: **x = lg(ppm)** у опорній точці, **y = lg(Rₛ/R₀)** у ній же, а **slope** — нахил прямої в log-log. Для MQ-2 ходять такі трійки (джерело — код Sandbox Electronics, знятий із графіків даташита Winsen; це де-факто стандарт по всіх туторіалах, а не офіційна таблиця виробника):

```
Газ      x=lg(ppm)   y=lg(Rₛ/R₀)   нахил b
──────────────────────────────────────────────
LPG       2.3         0.21          −0.47
CO        2.3         0.72          −0.34
Дим       2.3         0.53          −0.44
```

Число 2.3 — це lg(200), бо опорну точку взято при 200 ppm (нижня межа діапазону MQ-2). Тобто для LPG крива проходить через точку (200 ppm; Rₛ/R₀ = 10^0.21 ≈ 1.62) з нахилом −0.47.

Перейдімо від цієї трійки до звичного `ppm = a·(Rₛ/R₀)^b`. Пряма в log-log:

```
lg(ppm) = x + (lg(Rₛ/R₀) − y) / slope
```

(рухаємось від опорної точки вздовж прямої: наскільки lg(Rₛ/R₀) відійшов від y, поділити на нахил — і додати до опорного lg(ppm)). Піднесемо 10 у цей степінь — і дістанемо ppm. А якщо розкрити й згорнути до степеневого вигляду, показник **b = 1/slope**, а коефіцієнт **a = 10^(x − y/slope)**. Порахуймо для LPG:

**Приклад: сталі a, b для LPG з трійки {2.3, 0.21, −0.47}**
```
b = 1 / slope = 1 / (−0.47) ≈ −2.13
a = 10^(x − y/slope) = 10^(2.3 − 0.21/(−0.47))
  = 10^(2.3 + 0.447) = 10^2.747 ≈ 558
```
Отже для LPG: **ppm ≈ 558 · (Rₛ/R₀)^(−2.13)**. Перевірка на опорній точці: при Rₛ/R₀ = 1.62 маємо 558 · 1.62^(−2.13) ≈ 558 · 0.36 ≈ 201 ppm — сходиться з 200 ppm, звідки трійку й брали.

У коді зручніше **не** розкривати до a і b, а лишити точковий вигляд — менше втрати точності й видно, звідки що. Ось функція, що приймає трійку-криву й повертає ppm:

:::tabs
```cpp
// Крива газу: {x = lg(ppm), y = lg(Rₛ/R₀) у опорній точці, slope = нахил}.
// Значення для MQ-2 з коду Sandbox Electronics (зняті з графіків даташита).
struct MqCurve { float x, y, slope; };

const MqCurve LPG_CURVE   = { 2.3f, 0.21f, -0.47f };
const MqCurve CO_CURVE    = { 2.3f, 0.72f, -0.34f };
const MqCurve SMOKE_CURVE = { 2.3f, 0.53f, -0.44f };

// Відношення Rₛ/R₀ → ppm за степеневою кривою (у точковій формі).
float mqPpm(float rsR0, const MqCurve& c) {
  // lg(ppm) = x + (lg(Rₛ/R₀) − y) / slope,  далі 10 у цей степінь
  float lgPpm = c.x + (log10f(rsR0) - c.y) / c.slope;
  return powf(10.0f, lgPpm);
}
```
```python
import math
from collections import namedtuple

# Крива газу: {x = lg(ppm), y = lg(Rₛ/R₀) у опорній точці, slope = нахил}.
# Значення для MQ-2 з коду Sandbox Electronics (зняті з графіків даташита).
MqCurve = namedtuple("MqCurve", ("x", "y", "slope"))

LPG_CURVE   = MqCurve(2.3, 0.21, -0.47)
CO_CURVE    = MqCurve(2.3, 0.72, -0.34)
SMOKE_CURVE = MqCurve(2.3, 0.53, -0.44)


def mq_ppm(rs_r0, c):
    """Відношення Rₛ/R₀ → ppm за степеневою кривою (у точковій формі)."""
    # lg(ppm) = x + (lg(Rₛ/R₀) − y) / slope,  далі 10 у цей степінь
    lg_ppm = c.x + (math.log10(rs_r0) - c.y) / c.slope
    return 10.0 ** lg_ppm
```
```micropython
import math

# Крива газу: (x = lg(ppm), y = lg(Rₛ/R₀) у опорній точці, slope = нахил).
# Значення для MQ-2 з коду Sandbox Electronics (зняті з графіків даташита).

CO_CURVE    = (2.3, 0.72, -0.34)
SMOKE_CURVE = (2.3, 0.53, -0.44)


def mq_ppm(rs_r0, curve):
    # Відношення Rₛ/R₀ → ppm за степеневою кривою (у точковій формі).
    x, y, slope = curve
    # lg(ppm) = x + (lg(Rₛ/R₀) − y) / slope,  далі 10 у цей степінь
    lg_ppm = x + (math.log10(rs_r0) - y) / slope

```
:::

Тут `log10f` — десятковий логарифм (у чистому C через `<math.h>` можна `log10()`), `powf(10, …)` — піднесення десятки. Одна тонкість: якщо десь у тебе натуральний логарифм `log()` (як у старих скетчах), то й основа степеня має бути `e` — головне не змішувати основи, інакше числа поїдуть у рази.

> 🔧 **Навіщо це.** Пам'ятай, звідки ці a, b, x, y: **вони прив'язані до газу, а не до давача**. Одна й та сама плата MQ-2 з тим самим R₀ дасть тобі 400 ppm «як LPG» і водночас 900 ppm «як CO» з того самого Rₛ — бо це різні криві, і давач не знає, який газ перед ним. Тому «показати ppm» чесно можна **лише коли ти вже знаєш, який газ міряєш** (або чесно підписати «еквівалент LPG»). MQ не ідентифікує газ — він дає опір, а яку криву до нього прикласти, вирішуєш ти. Це і є межа, за якою дешевий давач перестає бути вимірювачем концентрації й лишається сигналізатором «щось горюче».

## Крок четвертий: сторож порога з гістерезисом

Дуже часто ppm тобі й не потрібні — треба лише вчасно крикнути «забагато!» і не деренчати на межі. Тут прошиваємо **сторожа порога**. І головне в ньому — **гістерезис**: два пороги замість одного, щоб сигнал не смикався туди-сюди, коли значення тремтить рівно на межі.

Уяви один поріг: тривога вмикається при 300 і вимикається при 300. Значення реально шумить — 298, 301, 299, 302 — і реле клацає десять разів на секунду, світлодіод миготить, буфер дзижчить. Гидко й шкодить контактам. Ліки: **вмикати при вищому порозі, вимикати при нижчому**. Скажімо, спрацювати при 350, відпустити лише коли впаде нижче 250. Проміжок 250…350 — «мертва зона», у якій стан не міняється: раз увімкнулось — тримається, поки не впаде добряче нижче. Дзеркально для DO, якщо стережеш цифровий вихід.

Ось сторож у коді — універсальний, тримає стан між викликами:

struct Hysteresis {

Той самий сторож годиться і для **цифрового виходу DO**, тільки там значення — не ppm, а рівень піна, і треба зважити на **інверсію**. На багатьох платах MQ вихід DO у спокої тримається у «1», а спрацювання порога (газу забагато) притягує його в «0» — тобто логіка перевернута. Тому перш ніж писати `if (digitalRead(DO) == HIGH) alarm()`, звір по світлодіоду DO на платі, **у який бік** він міняється, коли підносиш газ, і вистав поріг гвинтиком так, щоб у спокої давач не був уже спрацьований. Код тоді простий, але напрямок порівняння — за фактом твоєї плати:

```cpp
const int DO_PIN = 2;
// ПЕРЕВІР по світлодіоду: на багатьох платах спрацювання = LOW (інверсія).
const bool DO_ACTIVE_LOW = true;

bool doTriggered() {
  int level = digitalRead(DO_PIN);
  return DO_ACTIVE_LOW ? (level == LOW) : (level == HIGH);
}
```

> 🔧 **Навіщо це.** Гістерезис — це різниця між пристроєм, який працює, і пристроєм, який дратує. Без нього будь-який давач на межі перетворює тривогу на нервове тремтіння; з ним поведінка спокійна й передбачувана. А інверсія DO — класична пастка на пів дня: людина бачить «1» у спокої, вирішує, що вже тривога, і плутає всю логіку. Дві прості звички — **два пороги замість одного** і **звірити напрямок DO по світлодіоду** — знімають більшість «чому воно клацає / чому воно завжди спрацьоване».

## Збираємо все: Arduino (5 В, прямий AO)

Тепер складімо чотири кроки в один робочий скетч. Спершу — **Arduino Uno/Nano**: 5-вольтова плата, AO заходить прямо на аналоговий вхід без жодного узгодження рівнів (бо і давач, і АЦП на 5 В). Це найпростіший випадок.

```cpp
#include <Arduino.h>
#include <math.h>

// ── Піни й сталі ─────────────────────────────────────────────
const int   AO_PIN   = A0;      // AO модуля → аналоговий вхід
const float ADC_MAX  = 1023.0f; // Arduino: 10-бітний АЦП
const float RL_KOHM  = 5.0f;    // навантажувальний резистор на платі (перевір!)
const float CLEAN_AIR_FACTOR = 9.83f;

struct MqCurve { float x, y, slope; };
const MqCurve LPG_CURVE = { 2.3f, 0.21f, -0.47f };

float R0 = 0.0f;                 // визначимо калібруванням у setup()

// ── Ланки ланцюжка ───────────────────────────────────────────
float mqReadRs(int raw) {
  if (raw <= 0) return INFINITY;
  return RL_KOHM * (ADC_MAX - (float)raw) / (float)raw;
}

float mqCalibrateR0(int pin) {
  float rsSum = 0.0f;
  for (int i = 0; i < 50; i++) { rsSum += mqReadRs(analogRead(pin)); delay(500); }
  return (rsSum / 50.0f) / CLEAN_AIR_FACTOR;
}

float mqPpm(float rsR0, const MqCurve& c) {
  return powf(10.0f, c.x + (log10f(rsR0) - c.y) / c.slope);
}

// ── Сторож порога з гістерезисом ─────────────────────────────
struct Hysteresis {
  float on, off; bool state = false;
  bool update(float v) {
    if (!state && v >= on)  state = true;
    if ( state && v <= off) state = false;
    return state;
  }
};
Hysteresis lpgWatch = { 350.0f, 250.0f };  // ppm-еквівалент LPG

void setup() {
  Serial.begin(9600);
  Serial.println(F("MQ: розпал... (даємо нагрівачу вийти на температуру)"));
  delay(30000);                     // короткий розпал; НЕ калібруй холодним давачем
  Serial.println(F("MQ: калібрую R0 у чистому повітрі..."));
  R0 = mqCalibrateR0(AO_PIN);       // роби це у справді чистому повітрі
  Serial.print(F("R0 = ")); Serial.print(R0); Serial.println(F(" кОм"));
}

void loop() {
  int   raw  = analogRead(AO_PIN);
  float rs   = mqReadRs(raw);
  float rsR0 = rs / R0;
  float ppm  = mqPpm(rsR0, LPG_CURVE);
  bool  alarm = lpgWatch.update(ppm);

  Serial.print(F("raw=")); Serial.print(raw);
  Serial.print(F("  Rs/R0=")); Serial.print(rsR0, 2);
  Serial.print(F("  LPG~")); Serial.print(ppm, 0); Serial.print(F(" ppm"));
  Serial.println(alarm ? F("  [ТРИВОГА]") : F(""));
  delay(1000);
}
```

Зверни увагу на `delay(30000)` перед калібруванням: це той короткий розпал, без якого R₀ вийде хибним. Для **нового** давача цього мало — його треба прогнати добу-дві, перш ніж узагалі довіряти R₀; у робочому пристрої це означає: перший запуск нового модуля лиши на випал, а калібрування зроби потім і збережи R₀.

## Те саме на ESP32 (3.3 В, дільник на вході)

**ESP32** — 3.3-вольтова плата, і тут дві різниці, обидві важливі. Перша: **AO не можна вести прямо на ніжку**, бо вихід давача 5-вольтовий (живлення модуля все одно 5 В — нагрівачу треба саме стільки), а ніжка ESP32 не терпить понад 3.3 В. Тому між AO і GPIO ставлять **дільник напруги** з двох резисторів (наприклад R1=10 кОм зверху, R2=20 кОм на землю), що ділить 5 В приблизно до 3.3 В.

Друга різниця — **сам дільник псує нашу математику Rₛ**, якщо про нього забути. Наша формула `Rₛ = Rₗ·(MAX−raw)/raw` виведена для випадку, коли АЦП бачить голу напругу дільника давача. А зовнішній дільник R1/R2 масштабує цю напругу перед АЦП у сталу кількість разів — значить, і відлік виходить меншим у стільки ж разів. Найчистіше не переписувати формулу опору, а **повернути відлік до «повного» масштабу перед mqReadRs**: помножити raw на коефіцієнт, зворотний до дільника. Дільник 10/20 кОм передає на вхід частку 20/(10+20) = 2/3 напруги, отже, щоб відновити повну, множимо відлік на (10+20)/20 = 1.5.

Плюс дрібниці ESP32: АЦП 12-бітний (`ADC_MAX = 4095`), а вхідний діапазон варто розширити `analogSetAttenuation(ADC_11db)`, щоб міряти близько до повних 3.3 В. Ось зміни (решта ланок — ті самі функції, що вище):

```cpp
#include <Arduino.h>
#include <math.h>

const int   AO_PIN   = 34;        // ADC1-пін ESP32 (напр. GPIO34) через дільник
const float ADC_MAX  = 4095.0f;   // ESP32: 12-бітний АЦП
const float RL_KOHM  = 5.0f;      // навантажувальний резистор НА ПЛАТІ МОДУЛЯ
const float CLEAN_AIR_FACTOR = 9.83f;

// Зовнішній дільник AO→GPIO: R_top зверху, R_bot на землю.
// Він передає на вхід частку R_bot/(R_top+R_bot). Щоб відновити повну
// напругу давача, відлік домножуємо на обернений коефіцієнт.
const float DIV_TOP = 10.0f, DIV_BOT = 20.0f;
const float DIV_COMP = (DIV_TOP + DIV_BOT) / DIV_BOT;   // = 1.5

struct MqCurve { float x, y, slope; };
const MqCurve LPG_CURVE = { 2.3f, 0.21f, -0.47f };
float R0 = 0.0f;

// Відлік → Rₛ, з поправкою на зовнішній дільник ПЕРЕД математикою опору.
float mqReadRs(int raw) {
  float rawFull = (float)raw * DIV_COMP;              // повернули «повний» масштаб
  if (rawFull >= ADC_MAX) rawFull = ADC_MAX - 1;      // захист від ділення на 0
  if (rawFull <= 0)       return INFINITY;
  return RL_KOHM * (ADC_MAX - rawFull) / rawFull;
}

float mqCalibrateR0(int pin) {
  float rsSum = 0.0f;
  for (int i = 0; i < 50; i++) { rsSum += mqReadRs(analogRead(pin)); delay(500); }
  return (rsSum / 50.0f) / CLEAN_AIR_FACTOR;
}

float mqPpm(float rsR0, const MqCurve& c) {
  return powf(10.0f, c.x + (log10f(rsR0) - c.y) / c.slope);
}

struct Hysteresis {
  float on, off; bool state = false;
  bool update(float v) {
    if (!state && v >= on)  state = true;
    if ( state && v <= off) state = false;
    return state;
  }
};
Hysteresis lpgWatch = { 350.0f, 250.0f };

void setup() {
  Serial.begin(115200);
  analogSetAttenuation(ADC_11db);   // розширити діапазон АЦП ~до 3.3 В
  Serial.println("MQ: розпал...");
  delay(30000);                     // короткий розпал (новому давачу — доба випалу окремо)
  Serial.println("MQ: калібрую R0 у чистому повітрі...");
  R0 = mqCalibrateR0(AO_PIN);
  Serial.printf("R0 = %.2f кОм\n", R0);
}

void loop() {
  int   raw  = analogRead(AO_PIN);
  float rsR0 = mqReadRs(raw) / R0;
  float ppm  = mqPpm(rsR0, LPG_CURVE);
  bool  alarm = lpgWatch.update(ppm);
  Serial.printf("raw=%4d  Rs/R0=%.2f  LPG~%.0f ppm%s\n",
                raw, rsR0, ppm, alarm ? "  [ТРИВОГА]" : "");
  delay(1000);
}
```

Ключова думка про ESP32: **зовнішній дільник — це не тільки захист ніжки, а й член у формулі**. Забудеш поправку `DIV_COMP` — і Rₛ вийде систематично зміщеним, R₀ теж, і хоча відношення Rₛ/R₀ частково витягне (бо зсув в обох), крива в log-log нелінійна, тож ppm однаково поповзуть. Тому поправку кладемо там, де відлік уперше стає опором — у `mqReadRs`, — і далі весь ланцюжок працює як на Arduino.

## Складність і пастки: де це ламається

Ланцюжок «відлік → Rₛ → Rₛ/R₀ → ppm → сторож» чесний рівно настільки, наскільки чесна найслабша його ланка. Зберемо, де саме він тріщить.

**Сире число ≠ ppm — і це не дрібниця, а суть.** Найпоширеніша ілюзія: узяти `analogRead`, помножити на якийсь коефіцієнт «на око» й підписати «проміле». Так робити не можна: між відліком і концентрацією стоять і математика дільника, і особисте R₀ давача, і нелінійна степенева крива газу. Пропустиш котрусь ланку — число буде схоже на правду, але не буде правдою. Якщо тобі досить «більше/менше», взагалі не рахуй ppm: стеж за Rₛ/R₀ або за відхиленням відліку від базового рівня — це чесніше, ніж фальшиві проміле.

**R₀ дрейфує — від вологості й від часу.** Навіть ідеально відкаліброване R₀ не вічне. Вологість зсуває опір SnO₂ помітно: у сирому теплому повітрі те саме R₀ вже трохи «не те», і ppm зміщуються. А з місяцями давач старіє, поверхня повільно міняється, і R₀ повзе. Практичні ліки: калібруй **у типових для роботи умовах** (не в сухому холоді, якщо працюватимеш у теплій вологій кухні); зберігай R₀ у флеш, але **періодично перекалібровуй**, коли впевнений, що повітря чисте; а для серйозних вимірів клади температурно-вологісну поправку (окремий давач температури/вологості й корекція Rₛ за графіком даташита). Для сигнального застосування дрейф терпимий — тривога спрацює однак; для «чесних ppm» це головне джерело брехні після поганого калібрування.

**Інверсія DO — пів дня на порожньому місці.** Уже казали, але воно ловить усіх: на багатьох платах DO у спокої «1», а спрацювання — «0». Плюс поріг DO ти виставляєш **гвинтиком уручну**, і поки не покрутив, давач або завжди «спрацьований», або ніколи. Порядок: підніс газ → дивись на світлодіод DO, у який бік міняється → крути гвинтик, щоб у чистому повітрі був відбій, а на газ — спрацювання → лише тоді пиши логіку, звіривши напрямок порівняння (`ACTIVE_LOW` чи ні). DO — це зручність «готовий поріг у залізі», але задарма вона не дається.

**Rₗ у коді не той, що на платі.** Формула Rₛ спирається на Rₗ. Якщо в туторіалі стоїть 5 кОм, а на твоїй платі 10 чи 20, абсолютне Rₛ вийде не те. Рятує те, що у відношенні Rₛ/R₀ помилка Rₗ скорочується (R₀ ти міряв тим самим Rₗ), тож ppm майже не страждають — але якщо колись захочеш абсолютний опір, виміряй Rₗ мультиметром. Це радше «знай про це», ніж «щодня болить».

**Калібрування на холодному чи новому давачі.** Повторимо, бо це коштує найдорожче: R₀, зняте до короткого розпалу або до довгого випалу нового елемента, — хибне, і воно потягне за собою **всі** ppm, а за кілька днів іще й «поїде», коли давач нарешті прогріється й випечеться. Розпал перед першим читанням і калібрування **після** burn-in — не формальність, а фізика поверхні SnO₂.

**Степенева крива — не істина, а наближення з чужого графіка.** Трійки `{x, y, slope}` зняті з друкованих кривих даташита (і то усереднених по партії), а не виміряні на твоєму екземплярі. Тому навіть за бездоганного R₀ абсолютні ppm мають право бути «в рази» поряд із правдою, надто на краях діапазону (нижче ~200 і вище ~10000 ppm крива взагалі не визначена — там числа фантазійні). Використовуй їх для порядку величини й для порогів, а не як покази газоаналізатора.

Підсумок ланцюжка простий: **відлік → Rₛ** (математика дільника, живлення скорочується) **→ R₀** (одноразове калібрування в чистому повітрі, ділиш на 9.83, роби на прогрітому й випеченому давачі) **→ Rₛ/R₀ → ppm** (степенева крива газу, яку сам і обираєш) **→ сторож** (два пороги з гістерезисом, звірена інверсія DO). Кожна ланка проста; сила — у тому, щоб не пропустити жодної й пам'ятати, що остання цифра чесна лише як «приблизно стільки цього газу», не більше.
