## I2C-адреса: 0xA4 і 0x52 — те саме число

Паспорт модуля пише адресу як байт `0xA4`. Але шина I2C кладе в перший байт звертання **сім біт адреси плюс один біт напрямку** (читати чи писати), тож «адреса» у звичному сенсі — це старші сім біт байта. Зсунь `0xA4` праворуч на біт — дістанеш `0x52`. Яке з двох чисел класти в код, вирішує не модуль, а драйвер шини: більшість API просять саме 7-бітне `0x52` й біт напрямку домальовують самі (Arduino `Wire`, ESP-IDF `i2c`, Linux `i2c-dev`), а STM32 HAL, навпаки, чекає вже зсунутий байт `0xA4`.

```
0xA4 = 1010 0100   ← байт із даташита (7 біт адреси + біт напрямку 0)
       └───────┘
       1010 010 = 0x52   ← 7-бітна адреса, яку кладуть у драйвер шини
```

```
Представлення      Значення   Де вживається
──────────────────────────────────────────────────────────
байт (даташит)     0xA4       команда s7, регістр 0x0F, STM32 HAL
7-бітна адреса     0x52       Arduino Wire, ESP-IDF, Linux i2c-dev
```

Зв'язок сталий: `0xA4 = 0x52 << 1`. Помилка коштує однаково в обидва боки: даси 7-бітному API `0xA4` — адресуєш не туди, і модуль мовчить; даси STM32 HAL `0x52` — мовчатиме так само. Ось одне й те саме читання регістра `0x00` трьома середовищами — уся різниця в тому, якого представлення просить API:

:::tabs

```arduino
// Wire бере 7-бітну адресу — біт напрямку домалює сам
Wire.beginTransmission(0x52);
Wire.write(0x00);                  // вказівник на регістр відстані
Wire.endTransmission(false);       // повторний старт, шину не відпускаємо
Wire.requestFrom((uint8_t)0x52, (uint8_t)2);
uint8_t hi = Wire.read(), lo = Wire.read();
uint16_t mm = ((uint16_t)hi << 8) | lo;   // старший байт перший
```

```esp-idf
#include "driver/i2c.h"            // адреса теж 7-бітна
uint8_t reg = 0x00, buf[2];
esp_err_t err = i2c_master_write_read_device(
    I2C_NUM_0, 0x52, &reg, 1, buf, 2, pdMS_TO_TICKS(100));
if (err == ESP_OK) {
    uint16_t mm = ((uint16_t)buf[0] << 8) | buf[1];
    ESP_LOGI(TAG, "відстань %u мм", mm);
}
```

```stm32
// HAL, навпаки, хоче вже зсунутий БАЙТ 0xA4
extern I2C_HandleTypeDef hi2c1;
uint8_t buf[2];
if (HAL_I2C_Mem_Read(&hi2c1, 0xA4, 0x00, I2C_MEMADD_SIZE_8BIT,
                     buf, 2, 100) == HAL_OK) {
    uint16_t mm = ((uint16_t)buf[0] << 8) | buf[1];
}
```

:::

## Карта регістрів

По I2C модуль — звичайний ведений із набором регістрів. **Читання:** ведучий ставить внутрішній вказівник на регістр (пише його номер), тоді читає N байтів (для відстані — два, старший перший, MSB-first). **Запис:** ведучий шле `[номер регістра][значення…]`.

![Таблиця семи I2C-регістрів TOF10120: 0x00 миттєва відстань (R), 0x04 згладжена відстань (R), 0x06 зсув нуля ±99 мм (R/W), 0x08 режим даних 0/1 (R/W), 0x09 режим видачі (R/W), 0x0C стеля дальності (R/W), 0x0F I2C-адреса (R/W); для кожного — що зберігає, формат і чи можна писати](img/registers.svg)
*Два верхні регістри лише читаються — це відстань, сира й згладжена. Решта — читання й запис: зсув нуля, вибір сирого чи згладженого джерела, активний чи пасивний вивід, стеля дальності й навіть власна I2C-адреса. Тобто налаштувати модуль можна цілком по I2C, жодної UART-команди не торкаючись.*

```
Регістр  Що зберігає                        Формат              Доступ
──────────────────────────────────────────────────────────────────────
0x00     миттєва (сира) відстань            2 байти MSB, мм     R
0x04     згладжена відстань                 2 байти MSB, мм     R
0x06     зсув нуля (юстування)              2 байти зі знаком   R/W
0x08     режим даних (0 згл. / 1 сира)      1 байт              R/W
0x09     режим видачі (0 потік / 1 запит)   1 байт              R/W
0x0C     стеля дальності                    2 байти, мм         R/W
0x0F     I2C-адреса (байт, напр. 0xA4)      1 байт              R/W
```

Два верхні регістри лише читаються — це відстань. `0x00` віддає сире миттєве число (реагує вмить, але стрибає від замору до замору), `0x04` — усереднене власним мікроконтролером (стабільніше, з невеликою затримкою реакції на різку зміну). Обидва — двобайтові, старший байт перший. Стеля внутрішнього числа — близько `1993` мм (`0x07C9`) за паспортної верхньої межі 1800 мм; значення біля неї означає радше «нічого не бачу», ніж «ціль там».

## UART: потік і його формат

За замовчуванням по UART модуль **сам, без запиту** диктує відстань текстом на **9600 8N1** (9600 біт за секунду, вісім біт даних, без парності, один стоп-біт, без апаратного керування потоком). Формат рядка — десяткове число, літери `mm`, завершення поверненням каретки й переведенням рядка (`\r\n`):

```
748mm
751mm
749mm
```

Перевести модуль у режим «на запит» (мовчить, віддає лише коли спитали командою `r6#` чи читанням I2C-регістра) — команда `s5-1#` або запис `1` у регістр `0x09`.

## Мова команд: граматика

Лінія `RXD` приймає короткі текстові команди сталого вигляду:

```
<дія><номер><значення>#

  дія      r = read (прочитати параметр)   s = set (задати параметр)
  номер    цифра — який саме параметр
  значення для s: знак і число (напр. +05, -500, 168); для r часто порожньо
  #        обов'язкова решітка — кінець команди
```

Модуль відповідає теж рядком: на `r`-команду — значенням (напр. `L=0748`), на `s`-команду — коротким `ok`, а якщо команду не прийнято (кривий синтаксис, значення поза межами) — `fail`.

## Таблиця команд

```
Команда     Що робить                                     Відповідь
────────────────────────────────────────────────────────────────────
r6#         прочитати відстань на запит (мм)              L=0748
s3-0#       режим даних: 0 = згладжена (типово)           ok
s3-1#       режим даних: 1 = сира, миттєва                ok
s5-0#       видача: 0 = сам безперервно шле (типово)      ok
s5-1#       видача: 1 = мовчати, віддавати лише на запит  ok
s2-500#     інтервал видачі, мс (діапазон 10..9999)       ok
s1+05#      зсув нуля, мм (юстування; діапазон ±99)       ok
s7-085#     змінити I2C-адресу (значення — БАЙТ адреси)   ok
```

Значення `s7` — це **байт** адреси (той, що `0xA4`), не 7-бітне число, і воно має бути **парним**: непарний байт зачепив би біт напрямку й дав би дробову 7-бітну адресу, яку `Wire` не адресує чисто. Наприклад, байт `0xAA` = 170 дає 7-бітну `0x55`, тож команда — `s7-170#`; байт `0xA8` = 168 дає `0x54`.

## Команда ↔ регістр: та сама кімната

Кожна `s`-команда по UART має регістр-двійник по I2C — це два входи до тих самих налаштувань:

```
Команда UART   Регістр I2C   Параметр
──────────────────────────────────────────────────────
s1             0x06          зсув нуля
s3             0x08          режим даних (сира / згладжена)
s5             0x09          режим видачі (потік / на запит)
s7             0x0F          I2C-адреса
```

Тобто налаштувати модуль можна цілком по I2C, жодної UART-команди не торкаючись: записати `1` у `0x08` — те саме, що надіслати `s3-1#`. Одне «але» щодо адреси: зміна через регістр `0x0F` по I2C дійде до **всіх** однаково-адресованих модулів на шині одночасно, тож для розведення кількох штук за адресами надійніша UART-команда `s7` по одному модулю за раз. Робочі приклади обох способів — у [прикладі коду](topic:sensors/tof10120/proj-tof10120.md).
