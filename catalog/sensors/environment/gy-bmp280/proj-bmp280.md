# ⚙️ BMP280 у коді: від готової бібліотеки до сирих регістрів

<preknowlist>
- [Шина I²C](book:communications/i2c-bus) — дві лінії SDA/SCL, ведучий шле адресу й байти по регістрах, ведений відповідає ACK/NACK; на цьому стоїть кожен рядок нижче.
- [Адресація I²C](book:communications/i2c-addressing) — 7-бітна адреса пристрою, окремий біт «читання/запис»; BMP280 сидить на `0x76` або `0x77` залежно від піна SDO.
- [Шина SPI](book:communications/spi-bus) — такт, дані туди й назад, окремий вибір пристрою; той самий чип уміє і її, тож наприкінці глянемо, чим відрізняється код.
- [Математика компенсації BMP280](book:sensors/gy-bmp280/math-compensation.md) — звідки беруться коефіцієнти `dig_T*`/`dig_P*` і як улаштована компенсаційна формула крок за кроком; тут ми нею **користуємося**, а виводимо її там.
</preknowlist>

Плата під'єднана шістьма дротами, живлення рівно 3.3 В, `CSB` притягнутий догори, шина знайшла на ній щось за адресою `0x76`. Далі — код. І тут, як майже з кожним цифровим давачем, є два зовсім різні шляхи, які варто пройти обидва — не тому, що один «навчальний», а другий «справжній», а тому, що вони відповідають на різні питання. Готова бібліотека відповідає на «як за п'ять хвилин побачити тиск і температуру й піти далі». Сирі регістри відповідають на «що насправді сидить у чипі, чому одне число без іншого — брехня, і як усе це запхати в 8 кілобайт пам'яті крихітного МК, куди бібліотека не влазить».

Візьмемо обидва по черзі. Спершу — бібліотека, щоб на екрані з'явилися перші гектопаскалі. Потім розберемо той самий вимір голими руками: перевірка ідентифікатора чипа (щоб не сплутати BMP280 з BME280), читання заводських коефіцієнтів, налаштування передискретизації й фільтра, і — головне — той самий **обов'язковий порядок «спершу температура, потім тиск»**, без якого тиск попливе. Наприкінці — режими sleep/forced/normal (вибір між ними вирішує, скільки давач з'їсть енергії) і пастки, на яких обпікаються навіть із робочим кодом.

Весь код — справжній C/C++ під Arduino-ядро (`Wire`); він однаково збирається під ESP32, під Raspberry Pi Pico і під класичну Arduino (з тим застереженням, що Uno п'ятивольтова — про це в пастках). Це не псевдокод «для ілюстрації» — його можна скопіювати в скетч і залити.

## Шлях перший: готова бібліотека Adafruit_BMP280

Найшвидший старт — узяти бібліотеку, яку хтось уже написав, вивірив і супроводжує. Для BMP280 стандарт де-факто — **`Adafruit_BMP280`**. Ставиться з менеджера бібліотек Arduino IDE (`Sketch → Include Library → Manage Libraries`, шукати «Adafruit BMP280»); разом із нею менеджер запропонує підтягнути `Adafruit Unified Sensor` і `Adafruit BusIO` — погоджуйтеся, це її залежності.

Ось повний робочий скетч, що раз на секунду друкує температуру, тиск і оцінку висоти в монітор порту.

```cpp
#include <Wire.h>
#include <Adafruit_BMP280.h>

Adafruit_BMP280 bmp(&Wire);   // об'єкт давача на шині I2C

void setup() {
  Serial.begin(115200);
  while (!Serial && millis() < 2000) { }   // дочекатись термінала, але не вічно

  // На ESP32/Pico задайте свої ніжки шини ДО bmp.begin():
  //   Wire.begin(21, 22);        // SDA=21, SCL=22 — типово для ESP32
  //   Wire.begin(4, 5);          // SDA=GP4, SCL=GP5 — типово для Pico
  // На класичній Arduino (UNO/Nano) ніжки жорсткі (A4/A5) — Wire.begin() без аргументів.
  Wire.begin();

  // УВАГА: типова плата GY-BMP280 за замовчуванням сидить на 0x76,
  // а не на 0x77 (це «рідна» адреса Adafruit). Тому адресу задаємо явно.
  if (!bmp.begin(0x76)) {
    Serial.println(F("BMP280 не знайдено. Перевірте: 3.3 В, CSB вгору, адресу 0x76/0x77."));
    while (true) { delay(1000); }           // далі йти немає сенсу
  }
  Serial.println(F("BMP280 на зв'язку."));

  // Один раз налаштувати режим виміру: неперервний, обидва канали з
  // передискретизацією, помірний згладжувальний фільтр.
  bmp.setSampling(Adafruit_BMP280::MODE_NORMAL,     // міряє сам, без запитів
                  Adafruit_BMP280::SAMPLING_X2,     // температура ×2
                  Adafruit_BMP280::SAMPLING_X16,    // тиск ×16 (найважливіше)
                  Adafruit_BMP280::FILTER_X16,      // сильний IIR-фільтр
                  Adafruit_BMP280::STANDBY_MS_500); // пауза 500 мс між вимірами
}

void loop() {
  float t = bmp.readTemperature();          // °C
  float p = bmp.readPressure();             // Па (не гПа!)
  float h = bmp.readAltitude(1013.25f);     // м, відносно стандартного рівня моря

  Serial.print(F("T = "));   Serial.print(t, 2);        Serial.print(F(" C   "));
  Serial.print(F("P = "));   Serial.print(p / 100.0f, 2); Serial.print(F(" hPa   "));
  Serial.print(F("h = "));   Serial.print(h, 1);        Serial.println(F(" m"));

  delay(1000);
}
```

Кілька місць варті окремого слова, бо вони не випадкові.

`bmp.begin(0x76)` **повертає `bool`** — і його треба перевіряти. Усередині бібліотека читає регістр ідентифікатора чипа й переконується, що на шині справді BMP280, а тоді підтягує заводські коефіцієнти. Якщо ви подали 5 В і спалили чип, забули притягнути `CSB`, переплутали `SDA` зі `SCL` або лишили адресу за замовчуванням `0x77`, коли плата насправді на `0x76`, — `begin()` поверне `false`. Спіймати це тут набагато легше, ніж потім гадати, чому висота дорівнює `NaN`.

**Аргумент адреси — обов'язковий саме для GY-BMP280.** Виклик `bmp.begin()` без аргументу підставляє `0x77` — «рідну» адресу плат Adafruit. Але типова синя плата GY-BMP280 має на піні `SDO` резистор, що тягне його донизу, тому вона за замовчуванням відповідає на `0x76`. Це причина №1, чому «бібліотека не бачить давач, хоча сканер I²C його знаходить»: сканер бачить `0x76`, а `begin()` без аргументу стукає в `0x77`. Задавайте адресу явно.

`readPressure()` **повертає паскалі, не гектопаскалі.** Це стала пастка: людина чекає ≈1013 і бачить ≈101300, вирішує, що «давач бракований». Ні — це та сама величина в базових одиницях СІ, поділіть на 100 і матимете звичні гПа. Температура — у °C, висота — у метрах.

`readAltitude(seaLevelhPa)` **чесна рівно настільки, наскільки чесний ваш аргумент.** Ви передаєте опорний тиск на рівні моря; якщо взяти стандартний `1013.25`, а сьогодні антициклон і насправді `1030`, висота промахнеться на сотню метрів. Барометр не знає погоди — ви мусите йому сказати. Тому для абсолютної висоти підставляють свіжий місцевий тиск (з METAR аеропорту чи звірений на землі перед злетом), а для **зміни** висоти беруть власний нуль (див. нижче).

### Що робить setSampling і чому це не косметика

Виклик `setSampling` — не «тонке налаштування для перфекціоністів», а те, що визначає, наскільки давач шумить і скільки їсть. Тут сходяться три різні речі, і кожну варто розуміти.

**Передискретизація (oversampling).** Замість одного відліку АЦП давач може взяти 2, 4, 8 чи 16 і всереднити їх усередині себе. Кожне подвоєння прибирає шум ціною часу й струму: тиск при `×16` помітно тихіший, ніж при `×1`, бо випадкові дрижання АЦП гасяться усередненням. Для тиску (заради якого барометр і беруть) ставлять `SAMPLING_X16`; для температури вистачає `×2` — вона й так змінюється повільно й потрібна здебільшого для поправки тиску, а не сама по собі.

**IIR-фільтр.** Передискретизація гасить дрібний шум АЦП, але не гасить **короткі поштовхи тиску** — грюкнули дверима в кімнаті, дмухнув вітер у отвір давача, крутнувся пропелер поряд. Ці стрибки реальні, але для вимірювання висоти вони — завада. Усередині чипа є цифровий низькочастотний фільтр (нескінченно-імпульсний, IIR — infinite impulse response), що згладжує такі викиди, не навантажуючи ні шину, ні процесор: кожне нове число — зважена суміш свіжого виміру й попереднього згладженого значення. Коефіцієнт `FILTER_X16` — сильне згладження (повільніша реакція, дуже гладка крива), `FILTER_OFF` — жодного (миттєва реакція, але видно кожен поштовх). Для стабільного висотоміра беруть сильний фільтр; для швидкого детектора зміни висоти — слабкіший.

**Режим і пауза.** `MODE_NORMAL` означає, що давач міряє сам, циклічно, а між циклами спить `STANDBY_MS_*` мілісекунд — вам лишається тільки читати готовий результат. Про режими — окремий розділ наприкінці, бо саме вибір режиму вирішує долю батареї.

> 🔧 **Навіщо це.** Значення за замовчуванням у бібліотеці (`SAMPLING_X16` на обох каналах, `FILTER_OFF`) годяться для столу, але не для реального приладу. У квадрокоптері вібрація від моторів б'є по мембрані тиску безперервно — без IIR-фільтра висота стрибала б на метри, і апарат «клював» би вгору-вниз. У метеостанції на батарейці навпаки: `×16` на температурі — марнотратство, а `NORMAL` без потреби виснажує елемент. `setSampling` — це те місце, де ви кажете давачу, у якому саме приладі він живе.

Що бібліотека зробила за вас у кожному `readPressure()`: перевірила ідентифікатор чипа на старті, прочитала й зберегла всі одинадцять коефіцієнтів, у потрібному порядку зчитала сирі відліки температури й тиску, порахувала службове число `t_fine` з температури, підставила його в поліном тиску й повернула готові паскалі. Усе це ховається за одним викликом. Зручно. Але щоб **лагодити** дивну поведінку — числа, що пливуть, тиск, який «відстає» від температури, зависання на старті, — треба знати, що саме там усередині. Тож розберемо той самий вимір без бібліотеки.

## Шлях другий: сирі регістри, крок за кроком

Тепер зробимо те саме голими руками. Уся робота з BMP280 через I²C — це читання й запис байтів у регістри за їхніми адресами, і всього таких дій чотири типи: прочитати один байт, прочитати кілька поспіль, записати один байт, зібрати з байтів багатобітне число. Спершу — крихітний шар доступу, на якому стоятиме все інше.

```cpp
#include <Wire.h>

static const uint8_t BMP280_ADDR = 0x76;   // типова адреса GY-BMP280 (SDO донизу)

// Прочитати ОДИН байт із регістра reg. Повертає true й кладе значення в *out.
static bool rd8(uint8_t reg, uint8_t *out) {
  Wire.beginTransmission(BMP280_ADDR);
  Wire.write(reg);
  if (Wire.endTransmission() != 0) return false;   // давач не підтвердив адресу
  if (Wire.requestFrom((int)BMP280_ADDR, 1) != 1) return false;
  *out = Wire.read();
  return true;
}

// Прочитати `len` байтів ПОСПІЛЬ, починаючи з регістра reg, у буфер buf.
// BMP280 сам збільшує внутрішній лічильник адреси, тож блок читається одним заходом.
static bool rdN(uint8_t reg, uint8_t *buf, uint8_t len) {
  Wire.beginTransmission(BMP280_ADDR);
  Wire.write(reg);
  if (Wire.endTransmission() != 0) return false;
  if (Wire.requestFrom((int)BMP280_ADDR, (int)len) != len) return false;
  for (uint8_t i = 0; i < len; i++) buf[i] = Wire.read();
  return true;
}

// Записати ОДИН байт val у регістр reg. Повертає true при ACK.
static bool wr8(uint8_t reg, uint8_t val) {
  Wire.beginTransmission(BMP280_ADDR);
  Wire.write(reg);
  Wire.write(val);
  return (Wire.endTransmission() == 0);
}
```

Три деталі тут навмисні. `Wire.endTransmission()` **повертає 0 на успіх** (давач відповів ACK на адресу) — ненульове означає «мовчить»: не та адреса, обірвана земля, `CSB` висить у повітрі. `Wire.requestFrom` **повертає, скільки байтів реально прийшло** — звіряємо це заздалегідь, бо читати наосліп із пристрою, що віддав менше очікуваного, небезпечно (`Wire.read()` поверне `-1`, який мовчки стане `0xFF`). А блокове читання `rdN` спирається на приємну властивість BMP280: після кожного відданого байта чип **сам** просуває внутрішній вказівник на наступний регістр, тож 26 байтів калібрування чи 6 байтів даних беруться одним запитом, а не двадцятьма шістьма окремими.

### Крок 1 — упізнати чип: 0x58 проти 0x60

Перше, що робить будь-яка сумлінна прошивка, — питає давач, хто він. У регістрі `0xD0` лежить незмінний **ідентифікатор чипа** (chip id), який доступний одразу після подачі живлення. У BMP280 це `0x58`, а в дуже схожого зовні BME280 (той, що вміє ще й вологість) — `0x60`. Платки не розрізнити оком, а код, що чекає від BMP280 вологості, читатиме сміття з неіснуючого регістра. Тому — звіряємо.

```cpp
#define BMP280_CHIP_ID  0x58   // це BMP280 (тиск + температура)
#define BME280_CHIP_ID  0x60   // це BME280 (тиск + температура + вологість)

// Прочитати ідентифікатор чипа з регістра 0xD0.
bool bmp280_who_am_i(uint8_t *id_out) {
  return rd8(0xD0, id_out);
}
```

Значення `0x58` — це «так, переді мною BMP280, продовжуємо». `0x60` — «це BME280, я читаю не ту плату» (код формально запрацює для тиску й температури, бо ця частина сумісна, але вологості від BMP280-логіки ви не отримаєте, а від BME280 калібрувальний блок трохи довший). Будь-що інше — `0x00`, `0xFF`, випадкове число — означає, що давача на шині немає або він мертвий: перевіряйте живлення, `CSB` і адресу.

### Крок 2 — прочитати заводські коефіцієнти від 0x88

Тепер найважливіша й найменш очевидна частина. Сире число з АЦП BMP280 — це **не** тиск і **не** температура; це просто відлік, пов'язаний із виміряною величиною нелінійно й до того ж по-різному для кожного окремого екземпляра чипа. Щоб перетворити сирий відлік на паскалі, потрібні **калібрувальні коефіцієнти**, які Bosch виміряла на заводі для цього конкретного кристала й зашила в його незмінну пам'ять. Вони лежать блоком, що починається з адреси `0x88`: спершу три коефіцієнти температури `dig_T1…dig_T3`, потім дев'ять коефіцієнтів тиску `dig_P1…dig_P9` — усього 12 значень, кожне по два байти, тобто 24 байти від `0x88` до `0x9F` (у BMP280 калібрувальний блок доходить до `0xA1`, але останні байти — для BME280; нам вистачає перших 24).

Тонкість, на якій легко втратити півдня: **типи чисел різні**. Перший коефіцієнт кожної групи (`dig_T1`, `dig_P1`) — **беззнаковий** (unsigned, `uint16_t`), а всі решта — **знакові** (signed, `int16_t`). Переплутаєте знак — і компенсаційна формула дасть безглуздий результат. Порядок байтів — молодший перший (little-endian): у пам'яті спершу йде молодший байт числа, потім старший.

```cpp
// Заводські коефіцієнти BMP280 (з даташита; типи саме такі!).
struct bmp280_calib {
  uint16_t dig_T1;   // беззнаковий
  int16_t  dig_T2, dig_T3;
  uint16_t dig_P1;   // беззнаковий
  int16_t  dig_P2, dig_P3, dig_P4, dig_P5, dig_P6, dig_P7, dig_P8, dig_P9;
};

static bmp280_calib calib;      // сюди прочитаємо один раз на старті

// Прочитати всі 24 байти калібрування від 0x88 і розкласти в структуру.
bool bmp280_read_calibration(void) {
  uint8_t b[24];
  if (!rdN(0x88, b, 24)) return false;

  // Кожні два байти: молодший перший (little-endian) → 16-бітне число.
  calib.dig_T1 = (uint16_t)(b[0]  | (b[1]  << 8));
  calib.dig_T2 = (int16_t) (b[2]  | (b[3]  << 8));
  calib.dig_T3 = (int16_t) (b[4]  | (b[5]  << 8));
  calib.dig_P1 = (uint16_t)(b[6]  | (b[7]  << 8));
  calib.dig_P2 = (int16_t) (b[8]  | (b[9]  << 8));
  calib.dig_P3 = (int16_t) (b[10] | (b[11] << 8));
  calib.dig_P4 = (int16_t) (b[12] | (b[13] << 8));
  calib.dig_P5 = (int16_t) (b[14] | (b[15] << 8));
  calib.dig_P6 = (int16_t) (b[16] | (b[17] << 8));
  calib.dig_P7 = (int16_t) (b[18] | (b[19] << 8));
  calib.dig_P8 = (int16_t) (b[20] | (b[21] << 8));
  calib.dig_P9 = (int16_t) (b[22] | (b[23] << 8));
  return true;
}
```

Читаємо це **один раз** на старті й запам'ятовуємо — коефіцієнти не змінюються, поки живе чип. Далі вони підуть у формулу; звідки саме вони беруться й чому формула має саме такий вигляд — розібрано в [математиці компенсації](book:sensors/gy-bmp280/math-compensation.md), а тут ми просто застосовуємо еталонний код Bosch.

### Крок 3 — налаштувати передискретизацію, фільтр і режим

Перш ніж міряти, скажемо давачу, як саме міряти. Два регістри керують усім: `0xF4` (`ctrl_meas`) задає передискретизацію й режим живлення, `0xF5` (`config`) — паузу між вимірами й силу IIR-фільтра. Розкладемо їх по бітах, бо саме тут «магічні числа» перестають бути магічними.

Регістр **`0xF4` (`ctrl_meas`)** ділиться на три поля:

```
біти [7:6:5] = osrs_t  — передискретизація температури
біти [4:3:2] = osrs_p  — передискретизація тиску
біти [1:0]   = mode    — режим живлення
```

Коди передискретизації однакові для обох каналів: `000` — канал вимкнено, `001` — ×1, `010` — ×2, `011` — ×4, `100` — ×8, `101` — ×16. Коди режиму: `00` — сон (sleep), `01` або `10` — разовий вимір на вимогу (forced), `11` — неперервний (normal).

Регістр **`0xF5` (`config`)**:

```
біти [7:6:5] = t_sb      — пауза між вимірами в режимі normal
біти [4:3:2] = filter    — коефіцієнт IIR-фільтра
біт  [0]     = spi3w_en  — увімкнути 3-провідний SPI (для I2C = 0)
```

Коди фільтра: `000` — вимкнено, `001` — коефіцієнт 2, `010` — 4, `011` — 8, `100` — 16 (що більший коефіцієнт, то сильніше згладження й повільніша реакція).

Зберемо потрібні значення зсувами бітів — так у коді видно, з чого складається кожен байт:

```cpp
// Поля ctrl_meas (0xF4):
#define OSRS_T_X2   (0x02 << 5)   // температура ×2
#define OSRS_P_X16  (0x05 << 2)   // тиск ×16
#define MODE_NORMAL  0x03         // неперервний
#define MODE_FORCED  0x01         // разовий на вимогу
#define MODE_SLEEP   0x00         // сон

// Поля config (0xF5):
#define T_SB_500MS  (0x04 << 5)   // пауза 500 мс між вимірами
#define FILTER_16   (0x04 << 2)   // IIR-коефіцієнт 16

// Налаштувати давач на неперервний вимір: T×2, P×16, фільтр 16, пауза 500 мс.
bool bmp280_configure(void) {
  // config пишемо ПЕРШИМ: у режимі normal запис у config може бути проігнорований,
  // тож безпечно міняти його, поки давач ще спить (mode=00 після живлення).
  if (!wr8(0xF5, T_SB_500MS | FILTER_16)) return false;
  // ctrl_meas із режимом normal — з цієї миті давач починає міряти сам.
  if (!wr8(0xF4, OSRS_T_X2 | OSRS_P_X16 | MODE_NORMAL)) return false;
  return true;
}
```

Тонкість у коментарі не випадкова: даташит попереджає, що запис у `config` у режимі `normal` може бути **проігнорований**, тому `config` виставляють, поки давач ще в режимі `sleep` (а він саме там одразу після подачі живлення), і лише потім переводять у `normal` через `ctrl_meas`. Порушите порядок — фільтр і пауза можуть не застосуватися, і ви довго не зрозумієте, чому крива шумніша, ніж просили.

### Крок 4 — прочитати сирі відліки й порахувати справжні величини

Тепер серце всього. Дані лежать шістьма байтами поспіль: тиск у `0xF7…0xF9`, температура у `0xFA…0xFC`. Кожна величина — **20-бітна**, розкладена на три регістри: старший байт (MSB), молодший (LSB) і «додатковий» (XLSB), у якому корисні лише старші 4 біти. Зібрати 20-бітне число з трьох байтів треба саме так:

```
raw = (MSB << 12) | (LSB << 4) | (XLSB >> 4)
```

Читаємо обидві величини одним блоковим запитом на 6 байтів — так вони гарантовано з одного циклу виміру, а не «температура з попереднього, тиск із наступного».

```cpp
// Прочитати сирі 20-бітні відліки тиску й температури (одним блоком, 6 байтів).
bool bmp280_read_raw(int32_t *adc_T, int32_t *adc_P) {
  uint8_t d[6];
  if (!rdN(0xF7, d, 6)) return false;            // 0xF7..0xFC: тиск, потім температура
  *adc_P = ((int32_t)d[0] << 12) | ((int32_t)d[1] << 4) | (d[2] >> 4);
  *adc_T = ((int32_t)d[3] << 12) | ((int32_t)d[4] << 4) | (d[5] >> 4);
  return true;
}
```

А тепер — компенсація, і саме тут криється правило, яке порушують найчастіше. Порядок **обов'язковий**: спершу температура, і не лише заради самої температури. Її формула дає побічний продукт — ціле число `t_fine`, що несе «температурну поправку». Мембрана тиску поводиться трохи по-різному при різній температурі, і формула тиску **вживає** `t_fine`, щоб це скомпенсувати. Тому порахуєте тиск, не оновивши перед тим температуру (і `t_fine`), — дістанете похибку, що росте, коли давач гріється чи холоне.

Нижче — еталонний цілочисловий (fixed-point) код Bosch із даташита, дослівно; писати його «на око» не варто — це вивірені поліноми, і будь-яка самодіяльність у коефіцієнтах ламає точність.

```cpp
static int32_t t_fine;   // «температурна поправка»; спільна для T і P

// Температура в сотих градуса Цельсія (напр. 2534 = 25.34 °C).
// ПОБІЧНО виставляє глобальний t_fine — його потім вживає формула тиску.
int32_t bmp280_compensate_T(int32_t adc_T) {
  int32_t var1 = ((((adc_T >> 3) - ((int32_t)calib.dig_T1 << 1))) *
                  ((int32_t)calib.dig_T2)) >> 11;
  int32_t var2 = (((((adc_T >> 4) - ((int32_t)calib.dig_T1)) *
                    ((adc_T >> 4) - ((int32_t)calib.dig_T1))) >> 12) *
                  ((int32_t)calib.dig_T3)) >> 14;
  t_fine = var1 + var2;
  return (t_fine * 5 + 128) >> 8;
}

// Тиск у Па як число з фіксованою комою Q24.8:
// повертає, напр., 24674867 = 24674867/256 = 96386.2 Па = 963.9 гПа.
// ВИМАГАЄ, щоб t_fine був щойно оновлений bmp280_compensate_T()!
uint32_t bmp280_compensate_P(int32_t adc_P) {
  int64_t var1 = ((int64_t)t_fine) - 128000;
  int64_t var2 = var1 * var1 * (int64_t)calib.dig_P6;
  var2 = var2 + ((var1 * (int64_t)calib.dig_P5) << 17);
  var2 = var2 + (((int64_t)calib.dig_P4) << 35);
  var1 = ((var1 * var1 * (int64_t)calib.dig_P3) >> 8) +
         ((var1 * (int64_t)calib.dig_P2) << 12);
  var1 = (((((int64_t)1) << 47) + var1)) * ((int64_t)calib.dig_P1) >> 33;
  if (var1 == 0) return 0;                    // ділення на нуль — захист
  int64_t p = 1048576 - adc_P;
  p = (((p << 31) - var2) * 3125) / var1;
  var1 = (((int64_t)calib.dig_P9) * (p >> 13) * (p >> 13)) >> 25;
  var2 = (((int64_t)calib.dig_P8) * p) >> 19;
  p = ((p + var1 + var2) >> 8) + (((int64_t)calib.dig_P7) << 4);
  return (uint32_t)p;   // Q24.8: поділіть на 256, щоб дістати Па
}
```

Дві речі про цей код. По-перше, `t_fine` — глобальний навмисно: він народжується в температурній формулі й «доживає» до формули тиску; це той самий місток між двома вимірами, про який ідеться весь час. По-друге, тиск рахується у **64-бітній** арифметиці (`int64_t`) — на 8-бітному AVR це коштує помітно, але без 64 біт проміжні добутки переповнюються й точність падає; на 32-бітних ESP32/Pico це взагалі непомітно. Bosch дає і 32-бітний варіант тиску (трохи менш точний) — його беруть лише коли 64-бітної арифметики шкода; чому саме потрібні 64 біти й чим версії різняться, розкрито в [математиці компенсації](book:sensors/gy-bmp280/math-compensation.md).

Тепер — зручні обгортки, що ховають одиниці й **гарантують правильний порядок**:

```cpp
// Температура в °C.
float bmp280_temperature(void) {
  int32_t adc_T, adc_P;
  if (!bmp280_read_raw(&adc_T, &adc_P)) return NAN;
  return bmp280_compensate_T(adc_T) / 100.0f;      // соті градуса → °C
}

// Тиск у гПа. САМ читає й температуру (щоб оновити t_fine) перед тиском.
float bmp280_pressure_hpa(void) {
  int32_t adc_T, adc_P;
  if (!bmp280_read_raw(&adc_T, &adc_P)) return NAN;
  bmp280_compensate_T(adc_T);                       // 1) спершу T → оновлює t_fine
  uint32_t p_q248 = bmp280_compensate_P(adc_P);     // 2) потім P, з готовим t_fine
  return (p_q248 / 256.0f) / 100.0f;                // Q24.8 → Па → гПа
}
```

Зверніть увагу: `bmp280_pressure_hpa()` **завжди** спершу викликає компенсацію температури, навіть якщо саме температура вас не цікавить, — бо без свіжого `t_fine` тиск попливе. Це і є той «обов'язковий порядок» у коді, а не на словах. І весь старт разом виглядає так:

```cpp
void setup() {
  Serial.begin(115200);
  Wire.begin();                                    // (на ESP32/Pico — зі своїми ніжками)

  uint8_t id;
  if (!bmp280_who_am_i(&id) || id != BMP280_CHIP_ID) {
    Serial.println(F("Це не BMP280 (або давач мовчить). Стоп."));
    while (true) delay(1000);
  }
  bmp280_read_calibration();                        // один раз — коефіцієнти
  bmp280_configure();                               // передискретизація, фільтр, режим
  Serial.println(F("BMP280 готовий (сирий драйвер)."));
}

void loop() {
  Serial.print(F("T = ")); Serial.print(bmp280_temperature(), 2);   Serial.print(F(" C   "));
  Serial.print(F("P = ")); Serial.print(bmp280_pressure_hpa(), 2);  Serial.println(F(" hPa"));
  delay(1000);
}
```

Порівняйте це з бібліотечним `bmp.readPressure()`: рівно ця логіка — упізнати чип, прочитати коефіцієнти, налаштувати, зчитати сире, порахувати температуру, порахувати тиск, — тільки згорнута в кілька викликів. Тепер видно, що саме там усередині, і чому воно іноді повертає `NaN` (давач не відповів) чи «застиглий» тиск (забули оновити температуру).

> 🔧 **Навіщо це.** Сирий драйвер потрібен, коли (1) готова бібліотека не влазить у пам'ять крихітного МК разом із рештою прошивки, (2) ви пишете під ядро без Arduino-обгортки — голий регістровий доступ, ESP-IDF, RTOS, Zephyr, — де `Wire` просто немає, (3) треба щось, чого бібліотека не дає зручно: наприклад, читати тиск у режимі `forced` рівно тоді, коли ви хочете, заради економії струму. І, зрештою, поки не проженеш обмін руками, не відчуваєш, чому «одне число без іншого — брехня».

## Від тиску до висоти

Останній крок — перетворити тиск у висоту, заради чого барометр здебільшого й беруть. Залежність описує барометрична формула; у зручному для МК спрощенні висоту рахують так:

```
h = 44330 · (1 − (p / p₀) ^ 0.1903)
```

Тут `p` — виміряний тиск, `p₀` — опорний тиск «на нулі висоти», `44330` і `0.1903` — сталі зі стандартної моделі атмосфери. У коді:

```cpp
#include <math.h>

// Висота в метрах над рівнем, де тиск дорівнює p0 (обидва тиски — у гПа).
float bmp280_altitude(float p_hpa, float p0_hpa) {
  return 44330.0f * (1.0f - powf(p_hpa / p0_hpa, 0.1903f));
}
```

**Давач показує `p = 954.6 гПа`; за опорний беремо рівень моря `p₀ = 1013.25 гПа`.**
```c
float h = 44330.0f * (1.0f - powf(954.6f / 1013.25f, 0.1903f));
//      = 44330 * (1 - (0.94211)^0.1903)
//      = 44330 * (1 - 0.98867)
//      = 44330 * 0.011327
//      ≈ 502 м
```

Отже, 954.6 гПа відповідає висоті приблизно **500 метрів** — типово для міста в передгір'ї. Але тримайте твердо головне застереження: **абсолютна висота настільки точна, наскільки точний `p₀`**. Погода щодня зсуває тиск на рівні моря на десятки гПа, а кожен гПа — це близько 8 метрів. Тому барометр чудово міряє **зміну** висоти (піднявся дрон на метр — тиск ледь упав, це видно миттєво), а абсолютну дає надійно лише зі свіжим місцевим `p₀`. Практичний прийом — запам'ятати поточний тиск як власний нуль перед стартом:

```cpp
static float p0_ref = 1013.25f;    // опорний тиск «нуля висоти»

// Викликати на землі перед злетом: зробити поточне місце нульовою висотою.
void bmp280_set_zero_here(void) {
  p0_ref = bmp280_pressure_hpa();  // «тут і зараз» = 0 метрів
}

// Висота ВІДНОСНО запам'ятованого нуля (надійна, не залежить від погоди).
float bmp280_relative_altitude(void) {
  return bmp280_altitude(bmp280_pressure_hpa(), p0_ref);
}
```

Саме так роблять у польотних контролерах: перед стартом фіксують тиск як «нуль», і далі рахують висоту відносно нього — тоді антициклон за вікном на результат не впливає.

## Режими живлення: sleep, forced, normal

Ми весь час трималися `MODE_NORMAL`, але вибір режиму — це вибір між зручністю й батареєю, і його варто розуміти. BMP280 має три режими, і перемикають їх тими самими двома бітами `mode` в регістрі `0xF4`.

**Normal (`11`)** — давач міряє **сам, циклічно**: вимір → пауза `t_sb` → вимір → … Вам лишається читати готовий результат будь-коли. Зручно для приладу «на розетці» (метеостанція, стаціонарний висотомір), де струм не шкода. Але між вимірами давач не спить глибоко, тож на батарейці це найненажерливіший режим.

**Forced (`01`)** — давач робить **рівно один вимір на вашу команду**, а потім **сам засинає** й чекає наступної. Це режим для економних приладів: розбудили → зробили вимір → приспали, і між вимірами чип їсть одиниці мікроампер. Ідеально для датчика погоди на сонячній батареї чи трекера висоти, що прокидається раз на секунду.

**Sleep (`00`)** — давач нічого не міряє й майже нічого не їсть; сюди він потрапляє сам після живлення і сам — після кожного `forced`-виміру.

Робота в `forced` виглядає так: пишемо в `ctrl_meas` ті самі біти передискретизації плюс `MODE_FORCED`, чекаємо, поки вимір завершиться, і читаємо. Дочекатися можна двома способами — просто витримати паузу з запасом (найпростіше) або опитувати біт `measuring` у **статусному регістрі `0xF3`** (біт 3): поки він `1`, давач ще міряє.

```cpp
// Зробити ОДИН вимір у режимі forced і прочитати тиск (гПа). Між вимірами давач спить.
float bmp280_read_forced_pressure(void) {
  // Запустити разовий вимір (ті самі передискретизації + MODE_FORCED):
  wr8(0xF4, OSRS_T_X2 | OSRS_P_X16 | MODE_FORCED);

  // Дочекатися завершення: біт 3 (measuring) у статусі 0xF3 = 0, коли готово.
  uint8_t st;
  do {
    delay(2);
    if (!rd8(0xF3, &st)) return NAN;
  } while (st & 0x08);          // біт measuring ще виставлений — чекаємо

  return bmp280_pressure_hpa(); // читає T (оновлює t_fine) і P
}
```

> 🔧 **Навіщо це.** Різниця між `normal` і `forced` — це різниця між приладом, що живе тиждень від батарейки, і приладом, що живе рік. У трекері висоти на CR2032, що прокидається раз на секунду зняти один відлік і знову засинає, `forced` — єдиний правильний вибір: `normal` розрядив би елемент у рази швидше, бо давач без потреби міряв би тисячі разів між вашими читаннями. На стаціонарному приладі з зовнішнім живленням, навпаки, простіший `normal` — і не треба щоразу будити чип вручну.

## Пастки, на яких обпікаються навіть із робочим кодом

Код може бути бездоганним, а показ — брехати або взагалі не з'явитися. Ось речі, що дають майже всі скарги на цей давач.

**5 вольтів — смерть, а не «пробачить».** Найпоширеніша причина мертвого модуля. На типовій платі GY-BMP280 немає ні регулятора напруги, ні перетворювача рівня — сам чип живиться не вище 3.6 В. Подасте на `VCC` 5 В або заведете 5-вольтові лінії I²C від Arduino Uno — з великою ймовірністю спалите чип або не дочекаєтеся жодного байта. Живлення й уся логіка — рівно 3.3 В. Тому 3.3-вольтові ESP32/STM32/Pico до цього давача пасують без клопоту, а на 5-вольтовій Uno доведеться ставити зовнішній перетворювач рівня на `SDA`/`SCL` і живити `VCC` від 3.3-вольтового виходу плати.

**Забутий `CSB` — і чип мовчить.** Пін `CSB` вибирає інтерфейс: притягнутий до VCC — I²C, смикається тактами — SPI. Лишите його висіти в повітрі — чип може не визначитися, який інтерфейс йому обрати, і не відгукнеться на жоден I²C-запит. У режимі I²C `CSB` **завжди** на 3.3 В. Багато плат уже мають підтяжку `CSB` догори, але не всі — якщо давач не відповідає, а живлення точно 3.3 В, перевірте `CSB` другим ділом.

**Не та адреса: 0x76 проти 0x77.** Друга за поширеністю причина «бібліотека/код не бачить давач, хоча він живий». Пін `SDO` задає адресу: донизу — `0x76`, догори — `0x77`. Типова GY-BMP280 має підтяжку `SDO` донизу, тобто сидить на `0x76`, а `Adafruit_BMP280::begin()` без аргументу стукає в `0x77`. Спершу проженіть по шині сканер I²C, дізнайтеся реальну адресу — і задавайте її явно. І пам'ятайте, що `SDO` дає спосіб повісити **два** барометри на одну шину: один на `0x76`, другому притягнути `SDO` догори — стане `0x77`.

**Тиск у паскалях, а не гектопаскалях.** `readPressure()` (і сирий `bmp280_compensate_P` після ділення на 256) повертає **паскалі**: ≈101300, а не ≈1013. Це не поломка — поділіть на 100. Найчастіша хвилина розгубленості новачка з цим давачем.

**Порушений порядок «температура → тиск».** Найпідступніше в сирому драйвері, бо код «працює», просто числа тихо пливуть. Порахуєте тиск, не оновивши перед тим температуру (а отже `t_fine`), — і тиск матиме похибку, що росте разом зі зміною температури давача. Тому обгортка тиску **завжди** спершу рахує температуру, навіть якщо вона вам не потрібна. Бібліотека це робить за вас; сирий код мусите впорядкувати самі.

**Переплутані типи коефіцієнтів.** `dig_T1` і `dig_P1` — беззнакові (`uint16_t`), решта — знакові (`int16_t`). Прочитаєте всі як знакові чи всі як беззнакові — компенсаційна формула дасть безглуздий тиск (наприклад, від'ємний чи в десятки разів завеликий). Тип має бути точно за даташитом, як у структурі вище.

**32-бітна арифметика там, де потрібна 64.** Формула тиску Bosch у повній точності вимагає `int64_t` для проміжних добутків. Візьмете `int32_t` (наприклад, механічно спростивши код під 8-бітний AVR) — проміжки переповняться й тиск стане сміттям. Або беріть 64-бітний варіант, або свідомо переходьте на офіційний 32-бітний варіант формули, а не «обрізайте» 64-бітний.

**Запис у `config` у режимі normal мовчки ігнорується.** Виставляйте `0xF5` (пауза й фільтр), поки давач у `sleep` (одразу після живлення), і лише потім переводьте його в `normal` через `0xF4`. Зробите навпаки — фільтр і пауза можуть не застосуватися, і крива буде шумніша, ніж ви замовляли, без жодної видимої помилки.

**Це давач повітря.** Дірочка в металевій кришці чипа веде до чутливої мембрани. Крапля води, пил, струмінь розчинника чи різкий подув просто в отвір псують вимір або сам давач. У вологих чи брудних умовах модуль ховають за пилозахисною мембраною або в продувний, але захищений корпус.

Підсумок усього шляху: почніть із `Adafruit_BMP280`, щоб побачити перші гектопаскалі за п'ять хвилин — тільки задайте адресу `0x76` явно й пам'ятайте, що тиск повертається в паскалях. Коли захочете розуміти й лагодити — перепишіть той самий вимір сирими регістрами: упізнайте чип за `0xD0`, прочитайте коефіцієнти від `0x88`, налаштуйте `0xF4`/`0xF5`, і **завжди рахуйте температуру перед тиском**. Оберіть `forced`, коли живете від батарейки, і `normal`, коли струму не шкода. А головне пам'ятайте: більшість «мертвих модулів» — це не баг у коді, а 5 вольтів, забутий `CSB` чи не та адреса. Знаєте ці три — і BMP280 стає давачем, якому можна вірити.
