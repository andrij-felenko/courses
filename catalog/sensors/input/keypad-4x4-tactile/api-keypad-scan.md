# ⚙️ Драйвер клавіатури 4×4: від голого скану до бібліотеки Keypad

<preknowlist>
- [GPIO](book:electronics/gpio) — вивід мікроконтролера, який програмно роблять то входом, то виходом і читають/виставляють на ньому 0/1; на перемиканні напряму й тримається весь скан.
- [Підтяжки](book:electronics/floating-pullups) — резистор, що тримає вхід у HIGH, поки його ніхто активно не тягне донизу; без них рядки клавіатури «пливуть» і читаються сміттям. Тут беруть внутрішні (`INPUT_PULLUP`).
- [Брязкіт контактів](book:electronics/contact-debounce) — механічний контакт при дотику кілька разів відскакує, даючи пачку хибних перемикань за ~1–10 мс; без антибрязкоту один натиск читається як кілька.
</preknowlist>

Матриця 4×4 — це вісім проводів на цифрові ніжки й жодної електроніки всередині: самі кнопки на перетинах рядків і стовпців. Уся «розумність» такої клавіатури живе не в залізі, а **в прошивці**. Завдання тут цілком практичне: написати код, який шістнадцять кнопок під вісьмома ногами перетворює на охайний потік символів — натиснув `5`, у поле лягла рівно одна `5`, без примарних дублів і без пропусків. Розберемо цей драйвер двічі: спершу **голими руками**, щоб побачити кожен такт струму й кожну пастку зблизька, а тоді через готову бібліотеку `Keypad`, яка ту саму роботу ховає за трьома рядками — але ховає її не безкоштовно, і знати, що саме вона робить усередині, треба, аби її налаштувати.

Стрижень, який протягнемо крізь увесь код, — одне розділення. **Скан каже, ЯКІ рядок і стовпець замкнені** (це чиста фізика: жени LOW по стовпцях, читай рядки). **Розкладка каже, ЯКИЙ це символ** (це чиста таблиця: пара «рядок, стовпець» обирає літеру з масиву). Ці дві дії незалежні, і поки тримаєш їх окремо, драйвер лишається простим: скан не знає про літери, таблиця не знає про ніжки, а між ними — пара цілих чисел `(row, col)`.

## Крок 1: оголосити ніжки й роздати ролі

Почнемо з найпершого — з того, які ноги куди. У матриці вісім ліній: чотири рядки й чотири стовпці. Ми домовимося (це домовленість драйвера, а не закон природи): **стовпці — виходи**, ними ми **женемо** сигнал; **рядки — входи з підтяжкою**, їх ми **читаємо**. Можна й навпаки — гнати по рядках, читати стовпці, — суть та сама; головне, обрати один бік і триматися його весь код.

:::tabs
```cpp
#include <stdint.h>

// Фізичні ніжки МК. Порядок у масиві = логічний порядок Row0..Row3 / Col0..Col3.
// Підстав СВОЇ номери за маркуванням плати (див. пастку про порядок нижче).
static const uint8_t ROW_PIN[4] = { 2, 3, 4, 5 };   // рядки — читаємо (входи з підтяжкою)
static const uint8_t COL_PIN[4] = { 6, 7, 8, 9 };   // стовпці — женемо (виходи)
```
```micropython
from machine import Pin

# Фізичні ніжки МК. Порядок у списку = логічний порядок Row0..Row3 / Col0..Col3.
# Підстав СВОЇ номери за маркуванням плати (див. пастку про порядок нижче).
ROW_PIN = (2, 3, 4, 5)   # рядки — читаємо (входи з підтяжкою)
COL_PIN = (6, 7, 8, 9)   # стовпці — женемо (виходи)
```
:::

Тепер найважливіший рядок ініціалізації — **вибір напряму й підтяжок**. Рядки треба зробити входами, але не голими: голий вхід, поки його ніхто не тягне, [«пливе»](book:electronics/floating-pullups) — ловить наведення й читається як випадковий шум. Тому рядок — це **вхід із підтяжкою до плюса** (`INPUT_PULLUP`): поки нічого не натиснуто, підтяжка легенько тримає ногу в HIGH, і читання дає стабільну одиницю. Підтяжки беремо **внутрішні**, ті, що вже вбудовані в мікроконтролер, — жодних зовнішніх резисторів чіпляти не треба.

:::tabs
```cpp
void keypad_begin(void)
{
    // Рядки — входи з ВНУТРІШНЬОЮ підтяжкою: спокій = HIGH, натиск потягне в LOW.
    for (uint8_t i = 0; i < 4; i++)
        pinMode(ROW_PIN[i], INPUT_PULLUP);

    // Стовпці — виходи, і в СПОКОЇ тримаємо їх HIGH (неактивні).
    // Активним стовпець стане лише на мить свого скану (виставимо LOW).
    for (uint8_t j = 0; j < 4; j++) {
        pinMode(COL_PIN[j], OUTPUT);
        digitalWrite(COL_PIN[j], HIGH);   // неактивний стовпець = HIGH
    }
}
```
```micropython
rows = []
cols = []

def keypad_begin():
    # Рядки — входи з ВНУТРІШНЬОЮ підтяжкою: спокій = HIGH, натиск потягне в LOW.
    for p in ROW_PIN:
        rows.append(Pin(p, Pin.IN, Pin.PULL_UP))

    # Стовпці — виходи, і в СПОКОЇ тримаємо їх HIGH (неактивні).
    # Активним стовпець стане лише на мить свого скану (виставимо LOW).
    for p in COL_PIN:
        col = Pin(p, Pin.OUT)
        col.value(1)          # неактивний стовпець = HIGH
        cols.append(col)
```
:::

Зверни увагу на останній рядок: неактивні стовпці стоять у **HIGH**, а не в LOW. Це прямий наслідок логіки скану. Рядок вважається натиснутим, коли він **просів у LOW**; просісти він може лише тоді, коли **активний** (притиснутий до землі) стовпець дотягнувся до нього через натиснуту кнопку. Якби всі стовпці стояли в LOW одночасно, кожна натиснута кнопка тягла б свій рядок донизу незалежно від того, який стовпець ми зараз опитуємо, — і скан не зміг би відрізнити, у якому стовпці кнопка. Тому правило: **у спокої всі стовпці HIGH; активним робимо рівно один, і лише на час його зчитування**.

> 🔧 **Навіщо це.** `INPUT_PULLUP` — це те, що дозволяє клавіатурі не мати ані живлення, ані жодного резистора. Уся електрична визначеність рядка тримається на цій крихітній вбудованій підтяжці: вона задає «тихий» стан HIGH, від якого натиск відхиляє ногу в LOW. Забудеш `INPUT_PULLUP` (лишиш просто `INPUT`) — і клавіатура почне «натискатися сама»: рядки ловитимуть наведення від руки, від проводів, від мережі 50 Гц, і в поле полізуть символи, яких ніхто не торкався. Це найперша річ, яку перевіряють, коли матриця «бачить привидів».

## Крок 2: один прохід скану — читаємо всі шістнадцять кнопок

Тепер серце драйвера. Прохід скану — це чотири однакові кроки, по одному на стовпець: **притиснути цей стовпець до землі (LOW), прочитати всі чотири рядки, відпустити стовпець назад у HIGH**. Якщо під час активного стовпця якийсь рядок читається як LOW — значить, кнопка на перетині «цей рядок × цей стовпець» натиснута: активний стовпець дотягнувся до рядка крізь неї.

:::tabs
```cpp
// Прочитати весь стан клавіатури в бітову карту 4×4.
// Повертає 16 бітів: біт (row*4 + col) = 1, якщо кнопка (row,col) натиснута.
static uint16_t keypad_scan_raw(void)
{
    uint16_t bits = 0;

    for (uint8_t col = 0; col < 4; col++) {
        digitalWrite(COL_PIN[col], LOW);        // 1) активуємо стовпець: тягнемо до землі
        // тут корисна крихітна пауза — див. пастку «повільний loop / надто швидкий скан»
        for (uint8_t row = 0; row < 4; row++) { // 2) читаємо всі рядки
            if (digitalRead(ROW_PIN[row]) == LOW)   // рядок просів → кнопка натиснута
                bits |= (uint16_t)1 << (row * 4 + col);
        }
        digitalWrite(COL_PIN[col], HIGH);       // 3) відпускаємо стовпець назад у HIGH
    }
    return bits;
}
```
```micropython
# Прочитати весь стан клавіатури в бітову карту 4×4.
# Повертає 16 бітів: біт (row*4 + col) = 1, якщо кнопка (row,col) натиснута.
def keypad_scan_raw():
    bits = 0

    for col in range(4):
        cols[col].value(0)              # 1) активуємо стовпець: тягнемо до землі
        # тут корисна крихітна пауза — див. пастку «повільний loop / надто швидкий скан»
        for row in range(4):            # 2) читаємо всі рядки
            if rows[row].value() == 0:  # рядок просів → кнопка натиснута
                bits |= 1 << (row * 4 + col)
        cols[col].value(1)              # 3) відпускаємо стовпець назад у HIGH
    return bits
```
:::

Простежмо один такт до кінця, бо саме тут ховається вся інтуїція. Скажімо, `col == 1`. Ми пишемо `LOW` на дев'яту ногу (`COL_PIN[1]`) — стовпець Col1 тепер притиснутий до землі. Читаємо рядки. Якщо натиснута кнопка на перетині Col1 і Row2, вона з'єднує притиснутий-до-землі стовпець із рядком Row2, і той **просідає в LOW**, перемагаючи слабеньку внутрішню підтяжку (підтяжка навмисно «слабка» — десятки кілоом, — саме щоб пряме з'єднання зі стовпцем її пересилило). `digitalRead(ROW_PIN[2])` повертає `LOW` → ставимо біт `(2*4 + 1) = 9`. Решта рядків, куди «земля» через натиснуту кнопку не дістає, спокійно лишаються HIGH. Відпустили Col1 назад у HIGH — і за мить те саме робимо з Col2. Чотири стовпці × чотири рядки = усі шістнадцять кнопок опитано.

Уся карта натисків лягла у **шістнадцять бітів** одного `uint16_t` — компактно й зручно порівнювати: щоб дізнатися, чи змінилося щось від минулого разу, досить порівняти два числа. Ця карта — суто фізичний результат скану: вона каже, **де** замкнено, і поки що нічого не знає про літери. Літери — наступний крок.

> 🔧 **Навіщо це.** Логіка «активний = LOW, а не HIGH» здається дрібницею, але вона визначає весь код і збиває з пантелику новачків. Ми женемо стовпець у **нуль** і шукаємо рядок у **нулі**, бо підтяжка тримає спокій у **HIGH** — тобто клавіатура працює на **інверсній** логіці: натиснуто = LOW, відпущено = HIGH. Це не примха, а найдешевша схема: одна вбудована підтяжка на вхід і жодного зовнішнього компонента. Хто чекає «натиснуто = 1», той читає все навпаки й довго не розуміє, чому «всі кнопки натиснуті, поки я нічого не тисну».

## Крок 3: розкладка — від пари (row, col) до символу

Карта бітів каже, що замкнено перетин `(row, col)`. Людині потрібен **символ**. Зв'язок між ними — проста двовимірна таблиця, **розкладка** (англ. *keymap* — «карта клавіш»): рядок таблиці — рядок клавіатури, стовпець — стовпець, а на перетині лежить той символ, що надрукований на ковпачку.

:::tabs
```cpp
// Розкладка: що надруковано на кнопці на перетині [row][col].
// Рядок масиву = рядок клавіатури, стовпець = стовпець. Типовий телефонний розклад.
static const char KEYMAP[4][4] = {
    { '1', '2', '3', 'A' },
    { '4', '5', '6', 'B' },
    { '7', '8', '9', 'C' },
    { '*', '0', '#', 'D' },
};

// За індексом (row,col) повертає символ клавіші.
static inline char keypad_char(uint8_t row, uint8_t col)
{
    return KEYMAP[row][col];
}
```
```micropython
# Розкладка: що надруковано на кнопці на перетині [row][col].
# Рядок = рядок клавіатури, стовпець = стовпець. Типовий телефонний розклад.
KEYMAP = (
    ('1', '2', '3', 'A'),
    ('4', '5', '6', 'B'),
    ('7', '8', '9', 'C'),
    ('*', '0', '#', 'D'),
)

# За індексом (row,col) повертає символ клавіші.
def keypad_char(row, col):
    return KEYMAP[row][col]
```
:::

Уся таблиця — це просто відповідність: натиснули на перетині Row2 і Col1 → `KEYMAP[2][1]` → `'8'`. Ніякої логіки, самий пошук. І саме тому розкладка — місце, де найлегше й найтихіше зробити помилку. Якщо порядок ніжок у `ROW_PIN[]`/`COL_PIN[]` не збігається з фізичним порядком рядків і стовпців на платі, індекс `(row, col)`, який дає скан, **зсунеться відносно таблиці** — і та сама кнопка віддасть чужий символ. Нічого не згорить, помилки не буде: `8` просто перетвориться на `9` чи на `B`.

![Ліворуч: правильний порядок пінів — фізична кнопка на перетині Row2×Col1 дає «8». Праворуч: стовпці Col1 і Col2 переплутані місцями в масиві пінів, і та сама кнопка тепер віддає «9». Помилки нема, просто зсув індексу.](/catalog/sensors/input/keypad-4x4-tactile/img/keymap.svg)

*keymap[row][col] — це таблиця: фізичний перетин (рядок, стовпець) обирає з неї символ. Переплутав порядок у rowPins[] чи colPins[] — індекс зсунувся, і та сама кнопка віддає іншу букву. Ліки — звірити порядок пінів тестером, а не вгадувати.*

Як звірити? Натисни кутову кнопку й тестером (у режимі «продзвону») знайди, які два штирі замкнулися — це її рядок і стовпець. Занеси їх у масиви так, щоб `KEYMAP` дала на цьому перетині ту літеру, яка надрукована. Пройди чотири кути — і порядок гарантовано правильний. Це п'ять хвилин роботи, які економлять годину пізнішого «чому клавіатура плутає цифри».

## Крок 4: брязкіт — чому один натиск виглядає як «555»

Скан і розкладка вже дають робочу клавіатуру — але робочу **грубо**. Набери `5` і подивись у монітор: замість однієї п'ятірки, найпевніше, прилетить `555` або `55`. Причина не в коді скану, а в самій кнопці.

Кнопка тут — механічний контакт, а механічний контакт **брязкає** (англ. *bounce* — «відскок»). Коли металева пластинка стуляється, вона не сідає намертво з першого дотику: пружний метал кілька разів відскакує, і за перші **1–10 мілісекунд** контакт устигає замкнутися-розмкнутися пачку разів. Для ока це один чіткий натиск. Для скану, що крутиться сотні разів на секунду, — це серія окремих натисків підряд.

![Сира ніжка при натиску дає пачку переходів LOW-HIGH за 1..10 мс. Наївний скан рахує кожне LOW окремим натиском і видає «555». Антибрязкіт чекає, поки стан устоявся на T_db мілісекунд, і зараховує рівно один натиск.](/catalog/sensors/input/keypad-4x4-tactile/img/scan_bounce.svg)

*Механічний контакт після дотику кілька разів відскакує — сира ніжка дає пачку LOW-HIGH. Наївний скан рахує кожне LOW окремим натиском («555»). Антибрязкіт чекає, поки стан устоявся на T_db мс, і лише тоді зараховує один натиск — та сама пачка стає єдиною подією.*

Ліки — [**антибрязкіт**](book:electronics/contact-debounce): не вірити кожному окремому читанню, а зараховувати натиск лише тоді, коли стан **устоявся**. Найпростіший і найнадійніший спосіб — **реагувати на зміну, а тоді витримати паузу**: помітив, що кнопка з відпущеної стала натиснутою, — зафіксуй момент і кілька мілісекунд ігноруй подальші метання цієї кнопки; вони й є брязкіт. Ключова ідея: **нас цікавить не сам стан кнопки, а край — перехід із „відпущено“ у „натиснуто“**, і рахувати ми маємо саме краї, по одному на фізичний натиск.

Ось скан, доповнений антибрязкотом. Ми пам'ятаємо попередню карту натисків і час останньої зафіксованої зміни; новий натиск на клавіші зараховуємо лише коли з моменту минулої події на **цій** клавіші минуло досить часу:

:::tabs
```cpp
#include <stdint.h>

#define DEBOUNCE_MS   30        // скільки чекати, поки стан устоявся (типово 20..50)

static uint16_t last_stable = 0;             // остання «устояна» карта натисків
static uint32_t last_change_ms[16] = {0};    // коли востаннє змінилася кожна клавіша

// Опитати клавіатуру з антибрязкотом. У key кладе символ нового натиску (0 = нема).
// Повертає true, якщо цього виклику з'явився свіжий натиск.
static bool keypad_read(char *key)
{
    uint16_t now_bits = keypad_scan_raw();   // сирий стан усіх 16 кнопок
    uint32_t t = millis();
    bool got = false;
    *key = 0;

    for (uint8_t i = 0; i < 16; i++) {
        uint16_t mask = (uint16_t)1 << i;
        bool now_down  = now_bits   & mask;      // зараз натиснута?
        bool was_down  = last_stable & mask;     // була натиснута в устояному стані?

        if (now_down != was_down) {              // стан клавіші змінився
            if (t - last_change_ms[i] >= DEBOUNCE_MS) {
                // зміна протрималась досить довго — вважаємо її СПРАВЖНЬОЮ
                last_change_ms[i] = t;
                if (now_down) {                  // саме натиснення (не відпускання)
                    *key = keypad_char(i / 4, i % 4);   // row = i/4, col = i%4
                    got = true;
                }
                // оновлюємо устояний біт цієї клавіші
                if (now_down) last_stable |=  mask;
                else          last_stable &= ~mask;
            }
            // якщо не витримало паузу — це брязкіт, ігноруємо (устояний стан не чіпаємо)
        }
    }
    return got;
}
```
```micropython
import time

DEBOUNCE_MS = 30        # скільки чекати, поки стан устоявся (типово 20..50)

last_stable = 0                 # остання «устояна» карта натисків
last_change_ms = [0] * 16       # коли востаннє змінилася кожна клавіша

# Опитати клавіатуру з антибрязкотом. Повертає символ нового натиску або None.
def keypad_read():
    global last_stable
    now_bits = keypad_scan_raw()        # сирий стан усіх 16 кнопок
    t = time.ticks_ms()
    key = None

    for i in range(16):
        mask = 1 << i
        now_down = now_bits   & mask    # зараз натиснута?
        was_down = last_stable & mask   # була натиснута в устояному стані?

        if bool(now_down) != bool(was_down):    # стан клавіші змінився
            if time.ticks_diff(t, last_change_ms[i]) >= DEBOUNCE_MS:
                # зміна протрималась досить довго — вважаємо її СПРАВЖНЬОЮ
                last_change_ms[i] = t
                if now_down:            # саме натиснення (не відпускання)
                    key = keypad_char(i // 4, i % 4)    # row = i//4, col = i%4
                # оновлюємо устояний біт цієї клавіші
                if now_down:
                    last_stable |=  mask
                else:
                    last_stable &= ~mask
            # якщо не витримало паузу — це брязкіт, ігноруємо (устояний стан не чіпаємо)
    return key
```
:::

Прочитаймо, що тут відбувається. Для кожної з шістнадцяти клавіш ми порівнюємо **теперішній** стан з **устояним** (`last_stable`). Якщо вони збігаються — клавіша спокійна, нічого не робимо. Якщо різняться — щось міняється, але ми **ще не віримо**: дивимось, чи протрималась ця відмінність довше за `DEBOUNCE_MS`. Брязкіт — це швидкі метання по кілька мілісекунд; вони не переживуть паузу в тридцять мілісекунд і будуть відкинуті. А справжній натиск триває довго (палець на кнопці — це сотні мілісекунд), тож він паузу переживає, і його ми зараховуємо — **рівно раз**, у мить переходу «відпущено → натиснуто». Та сама пачка з п'яти брязків стає однією подією `'5'`.

Чому паузу міряють **на кожну клавішу окремо** (масив `last_change_ms[16]`), а не одним таймером на всю клавіатуру? Бо натиски можуть накладатися: ти ще тримаєш `5`, коли починаєш тиснути `6`. Спільний таймер антибрязкоту з'їв би другий натиск як «зарано». Окремий лічильник на клавішу дає кожній кнопці власне вікно спокою й не плутає сусідів.

> 🔧 **Навіщо це.** Антибрязкіт — не косметика, а різниця між іграшкою й приладом. Кодовий замок без нього прийме `1234` як `1122334` і не відчинить; калькулятор напише `77` замість `7`. І помилка ця **невидима під час швидкого тесту**: тицьнеш раз обережно — спрацює, а користувач у полі натисне звично різко, кнопка брязне сильніше, і полізуть дублі. Тому антибрязкіт кладуть **одразу**, не «потім, якщо знадобиться», — знадобиться завжди.

## Крок 5: складаємо голий драйвер докупи

Тепер частини стають робочою прошивкою. Головний цикл лише опитує клавіатуру й реагує на свіжий символ; уся механіка скану й антибрязкоту схована в `keypad_read`:

:::tabs
```cpp
#include <stdint.h>
#include <stdbool.h>

/* --- keypad_begin / keypad_scan_raw / keypad_char / keypad_read — з кроків 1..4 --- */

void setup(void)
{
    Serial.begin(115200);
    keypad_begin();          // ніжки: рядки INPUT_PULLUP, стовпці OUTPUT=HIGH
}

void loop(void)
{
    char key;
    if (keypad_read(&key)) { // з'явився свіжий натиск?
        Serial.print("натиснуто: ");
        Serial.println(key);
        // тут — своя реакція: додати цифру до PIN, зрушити меню, ввести число…
    }
    // loop крутиться швидко й вільно; скан коштує лічені мікросекунди на прохід
}
```
```micropython
# --- keypad_begin / keypad_scan_raw / keypad_char / keypad_read — з кроків 1..4 ---

keypad_begin()          # ніжки: рядки PULL_UP, стовпці OUT=HIGH

while True:
    key = keypad_read()     # з'явився свіжий натиск?
    if key:
        print("натиснуто:", key)
        # тут — своя реакція: додати цифру до PIN, зрушити меню, ввести число…
    # цикл крутиться швидко й вільно; скан коштує лічені мікросекунди на прохід
```
:::

Уся принада — в тому, що `loop()` **не блокується**. Він не чекає натиску в порожньому циклі (`while (!pressed)`), не спить у `delay()` — він щоразу коротко опитує клавіатуру й одразу йде далі, лишаючи час на решту роботи (дисплей, давачі, зв'язок). Один прохід `keypad_scan_raw` — це чотири виставлення стовпця й шістнадцять читань, лічені мікросекунди; його можна робити хоч тисячі разів на секунду. Саме тому клавіатура здається людині миттєвою: між двома дотиками пальця скан устигає пройти сотні разів.

Тут причаїлась пастка, яку варто назвати прямо: **повільний `loop()`**. Якщо десь у циклі стоїть довгий `delay(200)` чи важка операція на пів секунди, скан за цей час не виконається жодного разу — і короткий натиск, що стався й скінчився в цю паузу, буде **пропущено назовсім**. Клавіатуру треба опитувати **часто й без блокувань**; будь-який `delay` у головному циклі — прямий ворог чутливості вводу. Якщо десь потрібна витримка часу, роби її **неблокуючою** (звіряйся з `millis()`), а не через `delay`, щоб скан не зупинявся.

## Крок 6: те саме через бібліотеку Keypad

Тепер, коли видно кожну шестерню, подивимось на готове рішення. Для Arduino й ESP32 (у середовищі Arduino) стандарт де-факто — бібліотека **`Keypad`**, яку написали **Марк Стенлі (Mark Stanley) і Александер Бревіг (Alexander Brevig)** (усталений факт; бібліотека давня, живе в реєстрі Arduino й на сторінці PJRC). Вона робить рівно те, що ми щойно розписали: скан матриці, антибрязкіт, відстеження станів клавіш, — і ховає це за короткий інтерфейс.

Той самий приклад через `Keypad`:

```cpp
#include <Keypad.h>

const byte ROWS = 4;
const byte COLS = 4;

// Розкладка — та сама таблиця символів, що й у голому драйвері.
char keys[ROWS][COLS] = {
    { '1', '2', '3', 'A' },
    { '4', '5', '6', 'B' },
    { '7', '8', '9', 'C' },
    { '*', '0', '#', 'D' },
};

byte rowPins[ROWS] = { 2, 3, 4, 5 };   // ніжки рядків
byte colPins[COLS] = { 6, 7, 8, 9 };   // ніжки стовпців

// makeKeymap(keys) віддає бібліотеці таблицю; далі — ніжки й розміри.
Keypad keypad = Keypad(makeKeymap(keys), rowPins, colPins, ROWS, COLS);

void setup() {
    Serial.begin(115200);
}

void loop() {
    char key = keypad.getKey();     // 0 (NO_KEY), якщо нічого свіжого нема
    if (key) {
        Serial.print("натиснуто: ");
        Serial.println(key);
    }
}
```

Порівняй із голим драйвером — і побачиш, що зникло, а не додалося. `pinMode` для ніжок бібліотека виставляє **сама** всередині: рядки — на `INPUT_PULLUP`, стовпці жене по одному, точно як ми вручну. Антибрязкіт **уже вбудований** — типова витримка **50 мс** (її видно нижче, як її змінити). Відстеження «свіжий натиск чи той самий, що вже тримають» — теж усередині: `getKey()` повертає символ **лише в мить нового натиску**, а не щоразу, поки палець на кнопці. Ти пишеш `makeKeymap(keys)` — і забуваєш про скан.

`makeKeymap(keys)` — це просто спосіб віддати бібліотеці твою таблицю символів (він загортає двовимірний масив у формат, який очікує конструктор). Далі йдуть масиви ніжок і розміри — і об'єкт `keypad` готовий. Уся щоденна робота зводиться до одного виклику `getKey()` у циклі.

> 🔧 **Навіщо це.** Бібліотека варта того не тому, що «менше писати», а тому, що вона **вже наступила на всі граблі за тебе**: правильні підтяжки, витриманий антибрязкіт, один символ на натиск, коректний скан. Але вона не звільняє від **розуміння** — навпаки. Коли клавіатура плутає літери, мовчить чи двоїть, лагодити доведеться саме те, що всередині: порядок пінів, час антибрязкоту, частоту опитування. Хто пройшов голий драйвер, той відкриє потрібну ручку за хвилину; хто знає лише `getKey()` — тицятиметься наосліп.

## Крок 7: коли треба кілька клавіш разом — getKeys

`getKey()` віддає **один** символ за раз — цього досить для набору коду, меню, введення числа, де тиснуть по одній клавіші. Але буває треба ловити **кілька одночасних натисків** (акорд, «стрілка + дія» в грі). Для цього в бібліотеці є `getKeys()` — вона за один прохід оновлює список активних клавіш, кожна зі своїм станом.

```cpp
void loop() {
    if (keypad.getKeys()) {                      // оновити список; true, якщо є активні
        for (int i = 0; i < LIST_MAX; i++) {     // LIST_MAX = 10 (стеля бібліотеки)
            if (keypad.key[i].stateChanged) {    // саме ця клавіша щойно змінила стан
                char k = keypad.key[i].kchar;
                switch (keypad.key[i].kstate) {
                    case PRESSED:  Serial.print("натиснуто "); Serial.println(k); break;
                    case HOLD:     Serial.print("утримують ");  Serial.println(k); break;
                    case RELEASED: Serial.print("відпущено ");  Serial.println(k); break;
                    case IDLE:     break;        // спокій — нічого не робимо
                }
            }
        }
    }
}
```

Кожна клавіша в списку проходить через чотири стани: **IDLE** (спокій), **PRESSED** (щойно натиснуто), **HOLD** (тримають довше за поріг), **RELEASED** (щойно відпущено). Прапорець `stateChanged` каже, що саме **цієї** миті стан змінився, — тож ти реагуєш на подію один раз, а не щокадру. Список умістить до **десяти** клавіш одночасно (`LIST_MAX = 10` — стеля бібліотеки; усталено з її вихідників).

Тут важлива чесна засторога, яка веде назад до фізики матриці. Починаючи з версії 3.0, `Keypad` **типово багатоклавішна** — вона *програмно* готова відстежувати кілька натиснень разом. Але **сама матриця без діодів** цього по-справжньому не вміє: натисни три клавіші в кутах прямокутника — і скан «побачить» четверту, якої ніхто не торкався. Це [**примара** (ghosting)](book:sensors/keypad-4x4-tactile/hist-ghosting.md) — обхідний шлях струму через спільні рядок і стовпець, і **жодна бібліотека його не прибере**: код чесно читає те, що є на ніжках, а на ніжках справді хибний LOW. Тому `getKeys()` надійно ловить кілька клавіш лише для **не-конфліктних** комбінацій (наприклад, дві клавіші — примара потребує щонайменше трьох); повна незалежність усіх клавіш вимагає **діода послідовно з кожною кнопкою**, а на готовій тактильній платі їх нема.

> 🔧 **Навіщо це.** `getKeys()` розв'язує задачі, де подія — не сам символ, а **перехід**: затиснув клавішу — увімкнулось, відпустив — вимкнулось (стани `PRESSED`/`RELEASED`); тримаєш довго — інша дія (`HOLD`, зручно для «утримуй для скидання»). Але не проси від неї того, чого не дає **залізо**: на матриці без діодів більш ніж дві довільні клавіші разом — це територія примар. Хочеш справжні акорди — це вже не питання коду, а питання конструкції з діодами.

## Налаштувати час: антибрязкіт і утримання

Дві ручки бібліотеки, які найчастіше крутять, — **час антибрязкоту** й **поріг утримання**. Обидві задають у мілісекундах, обидві мають розумні типові значення, які іноді треба підправити під конкретну клавіатуру.

```cpp
void setup() {
    keypad.setDebounceTime(30);   // типово 50 мс; менше — жвавіше, але ризик дублів
    keypad.setHoldTime(600);      // типово 1000 мс; за скільки натиск стане HOLD
}
```

**Антибрязкіт** (`setDebounceTime`) — та сама пауза «поки стан устоявся», що й у голому драйвері. Типово **50 мс** — надійно, але для дуже «чистих» кнопок відчувається трохи млявим; можна опустити до 20–30 мс, якщо кнопки хороші й дублів нема. Занизиш надто — повернуться `555`. **Поріг утримання** (`setHoldTime`) — за скільки мілісекунд натиснута клавіша перейде зі стану `PRESSED` у `HOLD`; типово **1000 мс** (секунда). Його підбирають під сценарій: «утримуй пів секунди для повтору» — `setHoldTime(500)`.

Ці два числа — головне, що ти реально налаштовуєш у готовій бібліотеці. Решту вона робить сама, і робить правильно, — тому для переважної більшості проєктів вистачає п'яти рядків опису й `getKey()` у циклі.

## Типові пастки — коротко

Зберемо в одному місці те, на чому драйвер клавіатури спотикається найчастіше:

- **Переплутаний порядок пінів.** Порядок у `rowPins[]`/`colPins[]` (чи в `ROW_PIN[]`/`COL_PIN[]`) не збігається з фізичним порядком на платі — і та сама кнопка віддає чужий символ. Нічого не горить, помилки нема: `8` стає `9`. Ліки — **звірити тестером** по кутових кнопках, а не вгадувати.
- **Забув `INPUT_PULLUP`.** Лишив рядки просто `INPUT` (без підтяжки) — вони «пливуть», ловлять наведення, і клавіатура «натискається сама». Рядки **завжди** з підтяжкою; у голому драйвері — `INPUT_PULLUP`, у бібліотеці це вже всередині.
- **Немає антибрязкоту.** Один натиск лягає як `555`. Найпідступніше — що на обережному тесті все працює, а в полі при різкому натиску йдуть дублі. Антибрязкіт кладуть **одразу**: у голому коді — пауза «поки устоялось», у бібліотеці — `setDebounceTime` (типово 50 мс).
- **Повільний `loop()`.** `delay(200)` чи важка операція в циклі — і скан не встигає, короткі натиски пропадають. Клавіатуру опитуй **часто й без блокувань**; витримки часу роби неблокуючими (через `millis()`), не через `delay`.
- **Активні стовпці в LOW.** Якщо в спокої тримати всі стовпці LOW (замість HIGH), скан не відрізнить, у якому стовпці кнопка, — рядок просідатиме від будь-якої натиснутої кнопки. У спокої **всі стовпці HIGH**, активним роблять рівно один на час зчитування.
- **Чекати кілька клавіш від матриці без діодів.** Затиснув три-чотири клавіші разом — з'явилась примара, і жодна бібліотека її не прибере, бо хибний LOW реально є на ніжці. Для акордів потрібні **діоди на кожній кнопці**; на готовій тактильній платі їх нема, і `getKeys()` надійна лише для не-конфліктних комбінацій.
- **Плутати «стан клавіші» з «подією».** Реагувати щокадру на те, що клавіша натиснута (а не на **перехід** у натиснуто), — і одне натиснення дасть сотні спрацювань, поки палець на кнопці. Лови **край**: `getKey()` уже віддає символ раз на натиск; у `getKeys()` дивись `stateChanged`, а не голий `kstate`.

Драйвер вийшов невеликий — оголосити ніжки, чотири рази притиснути стовпець і прочитати рядки, звірити пару чисел із таблицею, відсіяти брязкіт паузою. Але кожен його рядок стоїть на фізичній причині: підтяжка задає спокій, інверсна логіка родить «натиск = LOW», окремі лічильники бережуть від злипання сусідніх клавіш, а пауза відрізняє палець від брязкоту. Розберешся, **чому** кожен шматок саме такий, — і чужу клавіатуру на чужій платі оживиш за вечір, хоч голими руками, хоч трьома рядками через `Keypad`, і точно знатимеш, яку ручку крутити, коли вона раптом почне двоїти чи мовчати.
