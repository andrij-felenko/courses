# Репозиторій курсів-книг (збираються в браузері)

Книги збираються прямо в браузері з Markdown. Три теки верхнього рівня:

- **`book/`** — предметні книги: самодостатні статті в галузях предмета, **без порядку й нумерації**. 8 книг: `electronics`, `physics`, `math`, `programming`, `algorithms`, `communications`, `chemistry`, `philosophy`.
- **`guide/`** — навчальні книги (курси): **послідовні** доріжки, що **спираються на пройдене й поступово поглиблюють**. Крок — або `ref` на готову `book/`-статтю (коли standalone-атом покриває крок), або **власна стаття курсу** (кумулятивний кут / поєднання кількох). **ЗАЛІЗНЕ: послідовне/кумулятивне/«припускає відоме» → `guide`, НІКОЛИ `book`; самодостатній атом → `book`.** Курси: `embedded`, `basic-chemistry`.
- **`catalog/`** — книги-каталоги: описи конкретних об'єктів (плати, модулі, прилади, деталі). Поводиться як `book/`. **7 родин за функцією (§1):** `sensors`, `power`, `connect`, `boards`, `actuators`, `instruments`, `components`. Усі 7 наживо — hardware-інвентар (111 топіків) заведено як `pending`. Правило (§8): каталожна плата/модуль зі схемою устрою/підключення → обов'язково обидві SVG + опис + `proj-`-вставка з API.

Обгортка — корінь репо: `index.html` (бібліотека), `read.html` (універсальний читач `?book=` / `?guide=`), рушій `book.js`, адаптер `scripts/bookbuild.js`.

## Канон письма — один файл

**`AUTHORING.md`** у корені — ЄДИНИЙ канон для всіх книг (§1 структура · §2 нейминг/нумерація/маніфест · §3 версії та вставки · §4 ядро письма · §5 формули/приклади/фігури · §6 крос-посилання · §7 історія · §8 голос/каталог · §9 статуси/процес). Правила письма — лише там; план/черга/статуси — у маніфесті.

**v6 (зміни ПРАВИЛ, схема маніфесту БЕЗ змін):** (1) кожна **нова** стаття починається згорнутим блоком `<preknowlist>` під H1 — передумови «що треба знати перед читанням» (§6): book/catalog — усі справжні; guide — лише не-пройдене по курсу; рідер-рендер (згортання) — **окремим кроком, ще не зроблено**. (2) `svgcheck.py` ловить і **накладання тексту** на текст/лінії (§5) — консервативний гейт для НОВИХ фігур. **Уже написане не чіпаємо.**

## Єдине джерело правди — маніфест книги

- **Один маніфест на книгу/курс/каталог:** `book/<book>/manifest.js` реєструє `window.__BOOKS__.push({…})`; `guide/<course>/manifest.js` → `window.__GUIDES__`. Схема — в `AUTHORING.md §2`.
- **book/catalog (v6, схема з v5 без змін):** `{ type, slug, title, sections:[ {slug,title,scope, topics:[ {slug,title, basic:{status}, detailed:{status}, hist/comp/math/proj:[{file,status}] } ]} ] }`. `section` = галузь; `topic` = стаття; **кожна версія `basic`/`detailed` має СВІЙ `status`** (версія доступна читачу ⟺ `done`); вставки — масив на тип, елемент `{file,status}`. Прибрано `status`/`levels`/`origin`.
- **guide (v6, схема з v5 без змін):** `{ type:"guide", slug, title, modules:[ {n,slug,title,scope:"", chapters:[ {title, steps:[ {ref:"<книга>/<галузь>/<slug>",title} | {slug,title,basic:{status},detailed:{status},hist/comp/math/proj:[…]} ]} ]} ] }`. Крок `{ref}` — book-стаття (3 сегменти; рушій вживає перший+останній); крок `{slug}` — власна стаття курсу зі статусами як у book, файл `guide/<course>/<module-slug>/<slug>/<slug>.md` (тека кроку в теці свого модуля → переїзд між модулями = `git mv` теки + правка абсолютних `/guide/...`-img-шляхів). `scope:""` на модулі — маркер рядка для скаутів; `n` — довідкове. Легасі-форма `sections→topics` (2-сег ref) підтримується рушієм/скриптами про запас; обидва курси вже v5, нове — лише v5.
- **Статуси (enum, на КОЖНУ версію `basic`/`detailed` й КОЖНУ вставку):** `done` · **`pending` (треба написати — саме це беруть скрипти-письма)** · **`empty` (писати НЕ треба)** · `update` (переписати) · `deeper` (поглибити) · `recheck` (передивитися за чинними правилами). Міняй ПРЯМО в маніфесті одразу після правки. *(v5: раніше `empty`=«не почато» → тепер це `pending`; `empty`=«не потрібно».)*
- **Нейминг slug-only** (без номерів): `book/<book>/<галузь>/<slug>/<slug>.md`, детальна `<slug>-d.md`, вставки `<type>-<name>.md` (type ∈ hist/comp/math/proj). Номерів немає ні в book/, ні в catalog/; guide нумерується з ПОРЯДКУ в маніфесті: Модуль·Розділ·Крок (модуль без розділів — Модуль·Крок).

## Скрипти — усі в `scripts/` (універсальні, параметр — книга)

- **Утиліти:** `bookbuild.js` (адаптер маніфест→рушій), `svgkit.py`/`svgcheck.py` (фігури; `figs.py` у теці теми імпортує `svgkit`), `wordcount.js` (проза за §3), `linkcheck.js` (биті лінки/book:-цілі; `empty` = легітимний стаб).
- **Воркфлоу письма (`Workflow scriptPath="scripts/write-batch.js"`):** повний v6-батч в один прогін, 4 фази — **Скаут** (перші N `pending` за `level`) → **Статті** (opus-max агенти, стагер 2с; кожен пише статтю + лишає список своїх вставок і нових залежних тем, ref-лінки вже в прозі; вставок і маніфесту НЕ чіпає) → **Вставки** (opus-max агенти пишуть зібрані вставки під ці статті) → **Маніфест** (серійно: статті→`done`, вставки→`done`, нові теми→`pending`). args = `{book, kind?:"book"|"catalog"|"guide", level?:"basic"|"detailed", limit?:10, scope?, units?}`. Скаут можна обійти, передавши готовий `units:[{section,slug,title,scope?}]`.
- `migrate-manifests-v2.js` — разова міграція маніфестів під схему §2 (запис ведеться).

## Паралельність і loop-сесії

- **Маніфест один на книгу** → ізоляція **по книзі**: кілька `/loop` працюють паралельно лише якщо кожен у своїй книзі/курсі. Двох `/loop` на одну книгу не запускати (спільний маніфест).
- Кожна ітерація **самодостатня**: усе потрібне — у маніфесті книги + `AUTHORING.md`.
- Великий крок (повна стаття/вставка) **делегуй сабагенту** з повними шляхами; у головну loop-сесію — лише короткий звіт (що зроблено, які статуси переставлено).
