# 📋 Системні виклики та інтерфейси живучості: setsid, nohup, disown, prctl

Управління життєвим циклом, сеансами та стійкістю процесів у системі Linux спирається на стандартизовані системні виклики ядра POSIX, спеціальні керівні виклики драйвера термінала (`ioctl`), розширення ядра Linux (`prctl`), функцію конфігурації сигналів (`sigaction`), групову сигнальну адресацію (`killpg`) та вбудовані опції командних оболонок. Нижче наведено формальну довідку інтерфейсів, їхніх сигнатур, кодів помилок, інваріантів та поведінкових гарантій.

---

## 1. Системні виклики керування сеансами та групами процесів

### `setsid` — Створення нового сеансу

:::tabs
```c
#include <sys/types.h>
#include <unistd.h>

pid_t setsid(void);
```
```cpp
#include <unistd.h>
#include <sys/types.h>
#include <system_error>

namespace process_control {
    inline pid_t create_session() {
        pid_t sid = ::setsid();
        if (sid < 0) {
            throw std::system_error(errno, std::generic_category(), "setsid failed");
        }
        return sid;
    }
}
```
:::

- **Призначення**: Створює новий сеанс ядра та нову групу процесів, якщо викликаючий процес не є лідером своєї поточної групи процесів (`PID != PGID`).
- **Повертане значення**: 
  - Успіх: новий ідентифікатор сеансу `SID` (який дорівнює `PID` викликаючого процесу).
  - Помилка: `(pid_t)-1`, змінна `errno` містить код помилки.
- **Коди помилок**:
  - `EPERM`: Викликаючий процес уже є лідером групи процесів (`getpid() == getpgrp()`). Для подолання цієї умови перед викликом `setsid()` обов'язково виконують `fork()`, а батьківський процес завершують.
- **Інваріанти та побічні ефекти в ядрі**:
  1. Викликаючий процес стає лідером нового сеансу (`Session Leader`) з ідентифікатором `SID = PID`.
  2. Викликаючий процес стає лідером нової групи процесів (`Process Group Leader`) з ідентифікатором `PGID = PID`.
  3. Процес стає єдиним процесом у новоствореній групі та новому сеансі.
  4. Процес повністю втрачає зв'язок із будь-яким керівним терміналом: у структурі `signal_struct` ядра вказівник на об'єкт `tty` встановлюється у `NULL` (`controlling TTY = NULL`).

### `getsid` — Отримання ідентифікатора сеансу

:::tabs
```c
#include <sys/types.h>
#include <unistd.h>

pid_t getsid(pid_t pid);
```
```cpp
#include <unistd.h>
#include <sys/types.h>
#include <system_error>

namespace process_control {
    inline pid_t get_session_id(pid_t pid = 0) {
        pid_t sid = ::getsid(pid);
        if (sid < 0) {
            throw std::system_error(errno, std::generic_category(), "getsid failed");
        }
        return sid;
    }
}
```
:::

- **Призначення**: Повертає ідентифікатор сеансу `SID` процесу з ідентифікатором `pid`. Якщо аргумент `pid` дорівнює `0`, повертає `SID` поточного процесу.
- **Повертане значення**:
  - Успіх: ідентифікатор `SID` цільового процесу.
  - Помилка: `(pid_t)-1`, `errno` встановлено у відповідне значення.
- **Коди помилок**:
  - `ESRCH`: Процес із заданим `pid` не знайдено у таблиці процесів ядра.
  - `EPERM`: Процес існує, але викликаючий процес не має прав на читання його атрибутів (актуально для старих стандартів Unix; у сучасному Linux дозволено читати `SID` будь-якого процесу в межах того самого простору імен PID).

### `tcgetsid` — Отримання SID керівного термінала

:::tabs
```c
#include <termios.h>
#include <unistd.h>

pid_t tcgetsid(int fd);
```
```cpp
#include <termios.h>
#include <unistd.h>
#include <system_error>

namespace terminal_control {
    inline pid_t get_terminal_session(int fd) {
        pid_t sid = ::tcgetsid(fd);
        if (sid < 0) {
            throw std::system_error(errno, std::generic_category(), "tcgetsid failed");
        }
        return sid;
    }
}
```
:::

- **Призначення**: Отримує ідентифікатор сеансу, асоційованого з відкритим термінальним пристроєм за файловим дескриптором `fd`.
- **Помилки**:
  - `EBADF`: Недійсний файловий дескриптор.
  - `ENOTTY`: Файловий дескриптор `fd` не вказує на термінальний пристрій або термінал не є керівним для жодного сеансу.

## 2. Керування зв'язком із терміналом через `ioctl`

Драйвер термінала Linux підтримує системні виклики `ioctl` для явного керування прив'язкою керівного термінала:

:::tabs
```c
#include <sys/ioctl.h>
#include <termios.h>

int ioctl(int fd, unsigned long request, ...);
```
```cpp
#include <sys/ioctl.h>
#include <termios.h>
#include <system_error>

namespace terminal_control {
    template <typename... Args>
    inline int terminal_ioctl(int fd, unsigned long request, Args... args) {
        int res = ::ioctl(fd, request, args...);
        if (res < 0) {
            throw std::system_error(errno, std::generic_category(), "ioctl terminal request failed");
        }
        return res;
    }
}
```
:::

| Запит `request` | Опис та сигнатура | Призначення та поведінка |
|---|---|---|
| `TIOCNOTTY` | `ioctl(fd, TIOCNOTTY);` | Явно від'єднує поточний процес від керівного термінала, зв'язаного з дескриптором `fd`. Якщо викликаючий процес був лідером сеансу, ядро розсилає сигнали `SIGHUP` та `SIGCONT` усій групі переднього плану і звільняє термінал для нових сесій. |
| `TIOCSCTTY` | `ioctl(fd, TIOCSCTTY, int arg);` | Робить відкритий термінал `fd` керівним терміналом викликаючого процесу. Викликаючий процес обов'язково має бути лідером сесії без призначеного термінала (`c_tty == NULL`). Якщо передано аргумент `arg == 1`, термінал примусово відбирається в іншої сесії (вимагає привілеїв суперкористувача `CAP_SYS_ADMIN`). |
| `TIOCGPGRP` | `ioctl(fd, TIOCGPGRP, pid_t *pgrp);` | Отримує `PGID` поточної групи процесів переднього плану (foreground process group), прив'язаної до термінала. Еквівалентно виклику `tcgetpgrp(fd)`. |
| `TIOCSPGRP` | `ioctl(fd, TIOCSPGRP, const pid_t *pgrp);` | Встановлює групу процесів з ідентифікатором `pgrp` як групу переднього плану на терміналі `fd`. Еквівалентно `tcsetpgrp(fd, pgrp)`. |

## 3. Групова сигнальна адресація: `killpg` та негативний PID

Для надсилання сигналу усім процесам, що входять до певної групи процесів (конвеєра або фонового завдання), ядро Unix надає механізм групової адресації:

:::tabs
```c
#include <signal.h>

int killpg(pid_t pgrp, int sig);
int kill(pid_t pid, int sig);
```
```cpp
#include <csignal>
#include <system_error>

namespace signal_control {
    inline void send_group_signal(pid_t pgrp, int sig) {
        if (::killpg(pgrp, sig) < 0) {
            throw std::system_error(errno, std::generic_category(), "killpg failed");
        }
    }
}
```
:::

- **Семантика виклику `killpg(pgrp, sig)`**: розсилає сигнал `sig` кожному процесу, чий `PGID == pgrp`. Якщо `pgrp == 0`, сигнал надсилається поточній групі викликаючого процесу.
- **Семантика виклику `kill(-pgid, sig)`**: системний виклик `kill()` з від'ємним першим аргументом (`pid < -1`) є системним еквівалентом `killpg()` і транслює сигнал усій групі процесів із номером `|pid|`.
- **Помилки**:
  - `EINVAL`: Недійсний номер сигналу `sig`.
  - `EPERM`: Викликаючий процес не має прав надсилати сигнали цільовим процесам групи.
  - `ESRCH`: Групи процесів з вказаним `PGID` не існує.

## 4. Зворотний контракт: гарантоване завершення через `prctl`

У деяких архітектурах супервізорів, мікросервісів та контейнерних середовищ потрібна поведінка, протилежна до `nohup`: якщо батьківський процес раптово гине (наприклад, по `SIGKILL`), дочірній процес повинен негайно завершитися, не переходячи у стан осиротілого демона під опіку PID 1. Для цього ядро Linux надає прапорець `PR_SET_PDEATHSIG`.

:::tabs
```c
#include <sys/prctl.h>
#include <signal.h>
#include <unistd.h>
#include <stdio.h>

int enable_parent_death_signal(int signum) {
    /* Надіслати signum дочірньому процесу, коли його батько завершується */
    if (prctl(PR_SET_PDEATHSIG, signum) < 0) {
        return -1;
    }
    /* Перевіряємо race condition: чи не помер батько до виклику prctl */
    if (getppid() == 1) {
        /* Батько вже загинув до реєстрації сигналу */
        kill(getpid(), signum);
    }
    return 0;
}
```
```cpp
#include <sys/prctl.h>
#include <csignal>
#include <unistd.h>
#include <system_error>

namespace process_safety {

void enable_parent_death_signal(int signum) {
    if (::prctl(PR_SET_PDEATHSIG, signum) < 0) {
        throw std::system_error(errno, std::generic_category(), "prctl PR_SET_PDEATHSIG failed");
    }
    // Захист від стану гонитви (race condition), якщо батьківський процес помер до prctl
    if (::getppid() == 1) {
        ::kill(::getpid(), signum);
    }
}

} // namespace process_safety
```
:::

**Особливості та обмеження `PR_SET_PDEATHSIG`**:
1. Сигнал надсилається ядром потоку або процесу-нащадку, коли батьківський процес (потік) завершує роботу.
2. При виконанні системного виклику `execve()` значення `PR_SET_PDEATHSIG` скидається в `0` (вимкнено), якщо бінарний файл має встановлені біти `setuid` чи `setgid`, або якщо процес змінює привілеї безпеки.
3. Прапорець прив'язується до конкретного потоку (task struct), тому в багатопотокових батьківських процесах завершення окремого потоку-ініціатора призведе до передчасної доставки сигналу.

## 5. Специфікація утиліти командного рядка `nohup` (POSIX.1-2017)

### Синтаксис
```bash
nohup command [argument...]
```

### Алгоритм поведінки утиліти
1. **Встановлення диспозиції сигналу**: встановлює дію для сигналу `SIGHUP` у `SIG_IGN` (`signal(SIGHUP, SIG_IGN)`). За правилами POSIX стан ігнорування `SIG_IGN` зберігається у виконуваному образі після виклику `execve()`.
2. **Перевірка стандартного введення `stdin`** (`isatty(STDIN_FILENO)`):
   - Якщо `stdin` є терміналом, перенаправляє дескриптор `0` на `/dev/null` у режимі лише для читання (`O_RDONLY`).
3. **Перевірка стандартного виведення `stdout`** (`isatty(STDOUT_FILENO)`):
   - Якщо `stdout` є терміналом, відкриває файл `nohup.out` у поточному каталозі на дозапис (`O_WRONLY | O_CREAT | O_APPEND`, права `S_IRUSR | S_IWUSR`, тобто `0600`).
   - Якщо поточний каталог недоступний для запису, відкриває файл `$HOME/nohup.out`.
   - Якщо файл не вдалося відкрити у жодному місці, утиліта повертає код помилки `127` і завершується без виконання команди.
4. **Перевірка стандартного потоку помилок `stderr`** (`isatty(STDERR_FILENO)`):
   - Якщо `stderr` є терміналом, перенаправляє дескриптор `2` на дескриптор `1` (`dup2(1, 2)`).
5. **Запуск цільової програми**: виконує системний виклик `execvp(command, arguments)`.

### Коди виходу `nohup`
- `126`: Команду знайдено, але не вдалося виконати (відсутні права на виконання бінарного файлу).
- `127`: Внутрішня помилка `nohup` (неможливо відкрити вихідний файл `nohup.out`) або вказану команду не знайдено в каталогах `$PATH`.
- `Інше`: Код виходу викликаної програми `command`.

## 6. Вбудована команда оболонки `disown` (Bash / Zsh)

### Синтаксис
```bash
disown [-h] [-a] [-r] [jobspec ... | pid ...]
```

### Прапорці та семантика

| Опція | Назва | Механізм дії |
|---|---|---|
| `-h` | Keep in table, no HUP | Залишає завдання в таблиці завдань оболонки (`jobs`), але виставляє внутрішній бітовий прапорець `JOB_NOSIGHUP` (або `J_NOHUP`). Оболонка не надсилатиме `SIGHUP` цьому завданню при виході (`exit`). |
| `-a` | All jobs | Застосовує вказану дію до **всіх** завдань у таблиці завдань поточної оболонки. |
| `-r` | Running only | Застосовує дію лише до тих завдань, що перебувають у стані **виконання** (running), ігноруючи призупинені завдання (stopped). |
| `Без опцій` | Remove from table | Повністю **вилучає** завдання з внутрішньої таблиці завдань оболонки. Оболонка більше не контролює це завдання через `fg`/`bg` і не надсилатиме йому жодних сигналів при закритті сеансу. |

### Стани та таблиця завдань Bash

У вихідному коді Bash (`jobs.c`) кожне завдання описується структурою `struct job` (цитата з коду `bash-5.2`):

```text
typedef struct job {
    char *name;               /* Текстовий рядок команди */
    PROCESS *pipe;            /* Зв'язаний список процесів конвеєра */
    pid_t pgrp;               /* Ідентифікатор групи процесів завдання */
    int state;                /* Стан: JRUNNING, JSTOPPED, JDEAD */
    int flags;                /* Прапорці: J_FOREGROUND, J_NOTIFIED, J_NOHUP */
} JOB;
```

Коли користувач виконує команду `disown -h %1`, внутрішня функція `disown_builtin` знаходить відповідне завдання за номером або PGID і встановлює прапорець `job->flags |= J_NOHUP`. 

Під час виходу з оболонки (команда `exit` або отримання `SIGHUP` від ядра) функція `hangup_all_jobs()` виконує послідовний обхід масиву активних завдань:

```text
for (i = 0; i < js.j_njobs; i++) {
    if (jobs[i] && (jobs[i]->flags & J_NOHUP) == 0) {
        killpg(jobs[i]->pgrp, SIGHUP);
    }
}
```

Завдання з встановленим прапорцем `J_NOHUP` або завдання, попередньо вилучені з масиву `jobs` командою `disown %1`, пропускаються і не отримують сигнал розриву від оболонки.

## 7. Опція оболонки `huponexit` у Bash

Поведінка командної оболонки Bash щодо розсилки сигналів фоновим завданням при нормальному виході через `exit` регулюється опцією `huponexit`:

```bash
# Перевірити поточний стан опції
shopt huponexit

# Увімкнути надсилання SIGHUP фоновим завданням при виході з оболонки
shopt -s huponexit

# Вимкнути надсилання SIGHUP фоновим завданням при виході
shopt -u huponexit
```

- **За замовчуванням у Bash**: для інтерактивної оболонки, яка не є login-оболонкою, опція `huponexit` вимкнена (`off`). Проте, якщо розривається зв'язок із псевдотерміналом (PTY hangup), ядро надсилає `SIGHUP` самій оболонці як лідеру сеансу, і обробник `sighup_handler` оболонки за замовчуванням розсилає `SIGHUP` усім підлеглим групам процесів незалежно від налаштування `huponexit`.

## 8. Семантика диспозицій сигналу SIGHUP у `sigaction`

Для налаштування реакції на сигнал `SIGHUP` у програмах простору користувача використовується системний виклик `sigaction(2)`:

:::tabs
```c
#include <signal.h>

int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
```
```cpp
#include <csignal>
#include <system_error>

namespace signal_control {
    inline void set_signal_action(int signum, const struct sigaction& act, struct sigaction* oldact = nullptr) {
        if (::sigaction(signum, &act, oldact) < 0) {
            throw std::system_error(errno, std::generic_category(), "sigaction failed");
        }
    }
}
```
:::

| Диспозиція | Семантика обробки | Спадкування через `fork()` | Спадкування через `execve()` |
|---|---|---|---|
| `SIG_DFL` | За замовчуванням: аварійне завершення процесу (`terminate`) без створення дампу пам'яті (core dump). | Зберігається | Зберігається |
| `SIG_IGN` | Повне ігнорування сигналу на рівні ядра: ядро відкидає сигнал без генерації подій для процесу. | Зберігається | **Зберігається** (ключова властивість для `nohup`) |
| Функція-обробник (`sa_handler`) | Виклик користувацької функції в контексті процесу (наприклад, перечитування конфігурації демона). | Зберігається | **Скидається до `SIG_DFL`** (оскільки адреса функції втрачає сенс у новому адресному просторі) |
