# Еволюційний шлях Landlock LSM: від BPF-прототипів до ABI v4/v5

Підсистема Landlock є унікальним прикладом того, як безпековий інструмент Linux пройшов п'ятирічний шлях від експериментальних начерків у розсипці Linux Kernel Mailing List (LKML) до інтеграції в офіційне ядро як ключовий фреймворк безпривілейованої ізоляції процесів.

## 1. Зародження ідеї та BPF-прототипи (2016–2017)

Розробка Landlock розпочалася у 2016 році за ініціативи французького дослідника безпеки Мікаеля Салоена (Mickaël Salaün). Головною мотивацією було створення механізму "самоізоляції" (self-sandboxing), який дозволяв би будь-якому непривілейованому процесу обмежувати власні права доступу до системних ресурсів без необхідності отримання прав суперкористувача (`root` / `CAP_SYS_ADMIN`) або завантаження глобальних конфігурацій AppArmor чи SELinux.

У початкових патчах (Landlock v1–v5, 2016–2017 роки) автор пропонував використовувати розширений eBPF (extended Berkeley Packet Filter). За задумом, користувацький процес мав конструювати eBPF-програму і завантажувати її в ядро через системний виклик `seccomp()` або `bpf()`, після чого ця програма прикріплювалася до безпекових хуків LSM (Linux Security Modules).

Проте цей підхід викликав гострі дискусії серед провідних розробників ядра Linux (зокрема Лінуса Торвальдса, Енді Лутомірскі та Олексія Старовойтова):
- **Складність верифікації eBPF**: Дозволяти безпривілейованим користувачам завантажувати довільний eBPF-код у мандатні хуки LSM створювало значну площу атаки на саме ядро. Існував ризик вразливостей типу Use-After-Free чи спотворення внутрішніх структур VFS та мережевого стеку.
- **Проблема TOCTOU та пам'яті**: eBPF-програма в хуку мала безпечно зчитувати вказівники у пам'яті користувацького простору, що загрожувало атаками Time-of-Check to Time-of-Use.
- **Підтримка та сумісність**: Довільні eBPF-програми не мали стабільного двокомпонентного інтерфейсу (ABI), що ускладнювало оновлення ядра без поломки існуючих пісочниць.

## 2. Зміна архітектурної парадигми: Декларативний системний API (2018–2020)

Після тривалих обговорень у розсипці LKML було прийнято фундаментальне рішення: відмовитися від завантаження довільного користувацького eBPF-коду на користь чітко визначеного декларативного системного API.

Замість написання BPF-інструкцій програма створює анонімний файловий дескриптор набору правил (`landlock_create_ruleset`), наповнює його структуризованими правилами (`landlock_add_rule`) та застосовує до себе (`landlock_restrict_self`). Усередині ядра Landlock самостійно керує внутрішніми eBPF-картами та мандатними хуками, гарантуючи повну безпеку та відсутність побічних ефектів.

Цей крок дозволив сформувати версіонований ABI (Application Binary Interface), де кожна нова версія ядра чітко повідомляє програмі свій рівень можливостей.

## 3. Хронологія версій ABI у стабільному ядрі Linux

### Linux 5.13 (ABI v1, травень 2021) — Запуск VFS-ізоляції
Після п'яти років розробки та 34 ітерацій патчів Landlock було офіційно включено до основного дерева ядра Linux 5.13. Перша версія ABI фокусувалася виключно на обмеженні доступу до віртуальної файлової системи (VFS). Було реалізовано 13 прапорців доступу `LANDLOCK_ACCESS_FS_*`:
- Читання, запис та виконання файлів (`READ_FILE`, `WRITE_FILE`, `EXECUTE`).
- Навігація та читання каталогів (`READ_DIR`).
- Створення спеціальних вузлів VFS: каталогів, блочних та символьних пристроїв, FIFO, сокетів, символьних та жорстких посилань (`MAKE_DIR`, `MAKE_CHAR`, `MAKE_BLOCK`, `MAKE_FIFO`, `MAKE_SOCK`, `MAKE_SYM`, `REMOVE_DIR`, `REMOVE_FILE`).

### Linux 5.19 (ABI v2, липень 2022) — Контроль усічення файлів
У версії ABI v2 було додано прапорець `LANDLOCK_ACCESS_FS_TRUNCATE`. До цього виклики `truncate()` та `ftruncate()` не перевірялися маскою запису `WRITE_FILE`, що створювало прогалину в політиці доступу: процес міг обнулити вміст файла, не маючи права на його зміну.

### Linux 6.2 (ABI v3, лютий 2023) — Контроль перейменування та посилань
Версія ABI v3 ввела прапорець `LANDLOCK_ACCESS_FS_REFER`. Це розв'язало складну проблему безпеки VFS: переміщення файлів (`rename()`) та створення жорстких посилань (`link()`) між різними каталогами чи точками монтування. Без цього прапорця зловмисник міг обійти обмеження пісочниці, перемістивши файл із захищеного каталогу в дозволений.

### Linux 6.7 (ABI v4, січень 2024) — Вихід у мережевий стек TCP
Landlock ABI v4 став революційним етапом розвитку, вийшовши за межі VFS у підсистему BSD-сокетів. Додано прапорці:
- `LANDLOCK_ACCESS_NET_BIND_TCP`: Контроль прив'язки TCP-сокетів до портів (`bind()`).
- `LANDLOCK_ACCESS_NET_CONNECT_TCP`: Контроль ініціалізації вихідних TCP-з'єднань (`connect()`).

Це дозволило заборонити ізольованому процесу піднімати слухаючі порти (backdoor bind shell) або з'єднуватися з зовнішніми Command & Control серверами (reverse shell).

### Linux 6.8 (ABI v5, березень 2024) — Блокування небезпечних `ioctl()`
Landlock ABI v5 закрив вектор локального підвищення привілеїв (LPE) через файли пристроїв. Введено прапорець `LANDLOCK_ACCESS_FS_IOCTL_DEV`, який за замовчуванням блокує виконання системного виклику `ioctl()` на символьних та блочних пристроях у `/dev/` (зокрема TTY-терміналах, GPU-пристроях, KVM-інтерфейсах), залишаючи лише мінімальний безпечний білий список системних команд.

## 4. Майбутній вектор розвитку Landlock

Еволюція Landlock триває. Спільнота розробників ядра під керівництвом Мікаеля Салоена працює над наступними розширеннями ABI:
- **Підтримка UDP та UNIX сокетів**: Розширення мережевого домену на датаграмні протоколи та міжпроцесну взаємодію (IPC).
- **Ізоляція міжпроцесних сигналів (Scoped Signals)**: Заборона надсилання сигналів (`kill`, `sigqueue`) та трасування (`ptrace`) між різними деревами пісочниць (введено частково у ABI v6).
- **Аудит та логування подій**: Інтеграція підсистеми Landlock із системним аудитом `auditd` для автоматичної фіксації спроб порушення обмежень.

Завдяки послідовному розширенню можливостей Landlock перетворився з експериментального BPF-патча на фундаментальний стандарт ізоляції у сучасних операційних системах Linux.
