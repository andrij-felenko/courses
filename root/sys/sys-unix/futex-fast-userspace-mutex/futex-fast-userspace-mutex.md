# Futex (Fast Userspace Mutex)

<preknowlist>
- [Ядро й простір користувача](topic:sys-unix/kernel-and-userspace) — базовий устрій системних викликів та простору користувача.
- [Системний виклик: як програма просить ядро](topic:sys-unix/syscall-mechanics) — механіка переходу в режим ядра та перемикання контексту.
</preknowlist>

Futex (Fast Userspace Mutex) — це фундаментальний механізм синхронізації в операційній системі Linux, який забезпечує створення високоефективних користувацьких примітивів блокування (таких як `pthread_mutex`, умовні змінні та семафори). Головна ідея Futex полягає в оптимальному розподілі роботи між процесором та ядром: якщо за ресурс немає конкуренції між потоками, захоплення або звільнення м'ютекса відбувається повністю у просторі користувача за кілька тактів CPU без виконання дорогих системних викликів. Операційна система залучається лише тоді, коли виникає реальний конфлікт і потік необхідно заблокувати або розбудити.

## Концепція та принцип двошляхового виконання

В основі механізму Futex лежить звичайна 32-бітна цілочисельна змінна (`uint32_t`), розташована у спільній пам'яті процесів або потоків. Ця змінна репрезентує стан примітива блокування (наприклад, `0` — ресурс вільний, `1` — ресурс зайнятий одним потоком, `2` — ресурс зайнятий і є очікуючі потоки).

Процес синхронізації ділиться на два шляхи виконання:
- **Fast Path (Швидкий шлях)**: Потік намагається атомарно змінити значення futex-змінної у пам'яті користувача (наприклад, змінити `0` на `1` за допомогою атомарної інструкції Compare-And-Swap). Якщо операція вдається, потік негайно входить у критичну секцію. Втрати часу становлять лише кілька наносекунд, а межа ядра не перетинається.
- **Slow Path (Повільний шлях)**: Якщо атомарна операція показує, що ресурс вже зайнятий іншим потоком, програма здійснює системний виклик `futex()`, просячи ядро заблокувати поточний потік і перевести його у стан очікування.

## Основні операції: FUTEX_WAIT та FUTEX_WAKE

Всі маніпуляції з засинанням та розбудженням потоків виконуються через єдиний системний виклик `futex(uint32_t *uaddr, int futex_op, uint32_t val, ...)`:

1. **`FUTEX_WAIT`**:
   Ядро атомарно перевіряє, чи значення за адресою `uaddr` у пам'яті користувача все ще дорівнює очікуваному параметру `val`. Якщо значення збігається, ядро додає потік до черги очікування `futex_hash_bucket` і блокує його виконання у стані `TASK_INTERRUPTIBLE`. Якщо значення вже змінилося (наприклад, власник м'ютекса звільнив ресурс прямо перед системним викликом), `futex()` повертає помилку `EWOULDBLOCK`. Цей механізм гарантує відсутність гонки «втраченого пробудження» (lost wakeup).

2. **`FUTEX_WAKE`**:
   Пробуджує вказану кількість потоків (передану в параметрі `val`), заблокованих на адресі `uaddr`. Ядро шукає відповідний хеш-бакет очікування, вилучає потоки з черги й повертає їх до стану виконання.

## Захист від аварій та підтримка реального часу

Окрім базових операцій, підсистема Futex підтримує розширені механізми захисту від збоїв:

- **Robust Futexes**: Запобігають «зависанню» блокувань у разі аварійного завершення потоку-власника (наприклад, при збої `SIGSEGV`). Кожен потік реєструє у ядрі список утримуваних м'ютексів. При смерті потоку ядро автоматично виставляє прапорець `FUTEX_OWNER_DIED` і розбуджує очікуючі потоки, дозволяючи їм перехопити м'ютекс та відновити цілісність даних.
- **Priority Inheritance (PI Futex)**: Запобігають інверсії пріоритетів у системах реального часу. Якщо високопріоритетний потік засинає в очікуванні м'ютекса, утримуваного низькопріоритетним потоком, ядро тимчасово підвищує пріоритет власника до пріоритету очікуючого потоку, уникаючи витіснення власника середньопріоритетними завданнями.

## Приватні та спільні futex-змінні

При використанні futex у межах одного процесу застосовується прапорець `FUTEX_PRIVATE_FLAG`. Це вказує ядру, що futex-змінна не поділяється між різними процесами через shared memory. Ядро оптимізує адресацію й обчислює хеш-ключ очікування без звернення до фізичних сторінок пам'яті через `get_user_pages()`, що прискорює повільний шлях на 20-30%. Якщо м'ютекс призначений для міжпроцесної синхронізації, використовується shared futex, де ядро ідентифікує змінну за фізичною адресою сторінки RAM.

## Інтеграція з системними бібліотеками (NPTL та POSIX)

Стандартна реалізація POSIX-потоків у Linux (бібліотека NPTL у складі `glibc`) повністю побудована на механізмі Futex.

Коли програма викликає функцію `pthread_mutex_lock()`:
- Спочатку виконується спроба захоплення через атомарну інструкцію процесора у просторі користувача.
- Якщо м'ютекс вільний, захоплення відбувається миттєво без виклику ядра.
- Якщо м'ютекс зайнятий, NPTL переходить у повільний шлях і робить системний виклик `futex(FUTEX_WAIT)`, переводячи потік у сон.

При виклику `pthread_mutex_unlock()` відбуваються зворотні дії: м'ютекс атомарно звільняється у юзерспейсі, і якщо прапорці стану вказують на наявність очікуючих потоків, здійснюється системний виклик `futex(FUTEX_WAKE)` для розбудження наступного потоку.

## Векторні futex'и: futex2 та sys_futex_waitv

Починаючи з версії ядра Linux 5.16, до підсистеми додано новий системний виклик `sys_futex_waitv` (ініціатива futex2). Цей виклик приймає масив структур `struct futex_waitv` і дозволяє потоку заснути доти, доки **хоча б один** із вказаних у масиві futex-об'єктів не змінить свій стан.

Можливість векторного очікування стала критично важливою для шарів сумісності (зокрема Wine та Valve Proton), дозволяючи ефективно емулювати Windows API виклик `WaitForMultipleObjects` під час запуску багатопотокових ігор на Linux.

:::tabs
```c
#include <linux/futex.h>
#include <sys/syscall.h>
#include <unistd.h>
#include <stdatomic.h>

int futex_wait(int *uaddr, int val) {
    return syscall(SYS_futex, uaddr, FUTEX_WAIT_PRIVATE, val, NULL, NULL, 0);
}

int futex_wake(int *uaddr, int count) {
    return syscall(SYS_futex, uaddr, FUTEX_WAKE_PRIVATE, count, NULL, NULL, 0);
}
```
```cpp
#include <atomic>
#include <unistd.h>
#include <sys/syscall.h>
#include <linux/futex.h>

int futex_wait(std::atomic<int>* uaddr, int val) {
    return ::syscall(SYS_futex, uaddr, FUTEX_WAIT_PRIVATE, val, nullptr, nullptr, 0);
}

int futex_wake(std::atomic<int>* uaddr, int count) {
    return ::syscall(SYS_futex, uaddr, FUTEX_WAKE_PRIVATE, count, nullptr, nullptr, 0);
}
```
