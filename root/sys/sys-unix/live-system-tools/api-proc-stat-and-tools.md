# 📋 Довідник полів /proc, метрик top та параметрів lsof

Цей довідник містить точні сигнатури системних структур псевдофайлової системи `/proc`, таблиці зміщень полів для парсингу стану процесів у Linux, опис алгоритмів обчислення метрик утиліт `top` / `htop` та повний перелік прапорців фільтрації дескрипторів для утиліти `lsof`. Інформація охоплює формати виводу ядерних інтерфейсів, внутрішню семантику лічильників пам'яті та процесорного часу, а також правила безпечного синтаксичного аналізу даних у користувацькому просторі.

---

## 1. Специфікація та семантика полів псевдофайлу /proc/[pid]/stat

Псевдофайл `/proc/[pid]/stat` формується ядром Linux у функції `do_task_stat()` (вихідний файл ядра `fs/proc/array.c`). Він містить зріз поточного стану задачі (процесу або окремого потоку LWP) у вигляді одного неперервного рядка, розділеного пробілами. Усі числові поля часу наводяться в системних тактах планувальника (clock ticks), значення яких визначається константою `USER_HZ` (зазвичай 100 тактів на секунду на архітектурі x86_64, що відповідає 10 мілісекундам на один такт).

Під час парсингу цього файлу розробники стикаються з критичним крайовим випадком: поле `comm` (номер 2) містить назву виконуваного файлу, взяту в круглі дужки. Оскільки процес може встановити довільне ім'я через системний виклик `prctl(PR_SET_NAME)` або модифікацію `argv[0]`, у назві можуть бути присутні пробіли, символи нового рядка та додаткові круглі дужки (наприклад, `(my (daemon) worker)`).

Через це пряме використання функцій на зразок `sscanf()` або розділення рядка за пробілами з початку файлу є грубою інженерною помилкою. Коректний алгоритм парсингу зобов'язаний виконувати пошук першої відкритої дужки `(` зліва для фіксації початку імені та останньої закритої дужки `)` справа для знаходження кінця поля `comm`. Усі наступні числові поля гарантовано йдуть після останньої дужки з фіксованими позиціями.

Нижче наведено повний перелік полів файлу `/proc/[pid]/stat` із зазначенням їхніх типів, форматів та внутрішньої семантики в ядрі Linux:

| № | Поле | Тип | Формат | Опис та семантика |
|---|---|---|---|---|
| 1 | `pid` | `pid_t` | `%d` | Ідентифікатор процесу (або ID потоку TID при перегляді `/proc/[pid]/task/[tid]/stat`). |
| 2 | `comm` | `char[]` | `(%s)` | Назва виконуваного бінарного файлу (обрізається ядром до `TASK_COMM_LEN - 1` = 15 символів). |
| 3 | `state` | `char` | `%c` | Поточний стан планування: `R` (Running), `S` (Sleeping), `D` (Disk/Uninterruptible), `Z` (Zombie), `T` (Stopped), `t` (Tracing stop), `X` (Dead), `I` (Idle kernel thread). |
| 4 | `ppid` | `pid_t` | `%d` | PID батьківського процесу (Parent PID). |
| 5 | `pgrp` | `int` | `%d` | Ідентифікатор процесної групи (Process Group ID). |
| 6 | `session` | `int` | `%d` | Ідентифікатор сесії (Session ID). |
| 7 | `tty_nr` | `int` | `%d` | Керувальний термінал процесу (старший і молодший номери пристрою TTY). Якщо TTY немає — значення 0. |
| 8 | `tpgid` | `int` | `%d` | Ідентифікатор процесної групи переднього плану (Foreground Process Group) для термінала TTY. |
| 9 | `flags` | `unsigned int` | `%u` | Прапорці ядра процесу (`PF_*`, визначені в `<linux/sched.h>`, наприклад `PF_KTHREAD`). |
| 10 | `minflt` | `unsigned long` | `%lu` | Кількість незначних відмов сторінок (Minor Page Faults), які не вимагали читання з диска. |
| 11 | `cminflt` | `unsigned long` | `%lu` | Сума minor page faults для всіх завершених дочірніх процесів, на які було виконано `wait4()`. |
| 12 | `majflt` | `unsigned long` | `%lu` | Кількість значних відмов сторінок (Major Page Faults), які потребували завантаження блоків з диска або swap. |
| 13 | `cmajflt` | `unsigned long` | `%lu` | Сума major page faults для всіх завершених дочірніх процесів. |
| 14 | `utime` | `unsigned long` | `%lu` | Час виконання у просторі користувача (User CPU Time) у тактах `USER_HZ`. |
| 15 | `stime` | `unsigned long` | `%lu` | Час виконання у просторі ядра (System/Kernel CPU Time) у тактах `USER_HZ`. |
| 16 | `cutime` | `long` | `%ld` | Сумарний `utime` завершених дочірніх процесів, які очікувалися через `wait4()`. |
| 17 | `cstime` | `long` | `%ld` | Сумарний `stime` завершених дочірніх процесів. |
| 18 | `priority` | `long` | `%ld` | Пріоритет планувальника (для звичайних процесів значення від 60 до 99 або від 0 до 39 залежно від ядра). |
| 19 | `nice` | `long` | `%ld` | Значення поступливості (Nice Value) у діапазоні від `-20` (найвищий) до `+19` (найнижчий). |
| 20 | `num_threads`| `long` | `%ld` | Кількість активних потоків виконання (LWP) у цьому процесі. |
| 21 | `itrealvalue`| `long` | `%ld` | Застаріле поле інтервального таймера (завжди 0 у сучасних ядрах). |
| 22 | `starttime` | `unsigned long long` | `%llu` | Час запуску процесу після завантаження операційної системи (в тактах `USER_HZ`). |
| 23 | `vsize` | `unsigned long` | `%lu` | Загальний обсяг віртуальної пам'яті (Virtual Memory Size) у байтах. |
| 24 | `rss` | `long` | `%ld` | Резидентний розмір пам'яті (Resident Set Size) у сторінках пам'яті (`PAGE_SIZE`, зазвичай 4096 байтів). |
| 25 | `rsslim` | `unsigned long` | `%lu` | Поточний ліміт на розмір RSS у байтах (`RLIMIT_RSS`). |
| 26 | `startcode` | `unsigned long` | `%lu` | Адреса початку виконуваного сегмента коду (Text segment) у віртуальній пам'яті. |
| 27 | `endcode` | `unsigned long` | `%lu` | Адреса завершення виконуваного сегмента коду. |
| 28 | `startstack` | `unsigned long` | `%lu` | Початкова адреса дна стека процесу. |
| 29 | `kstkesp` | `unsigned long` | `%lu` | Поточне значення покажчика стека ядра ESP/RSP процесу. |
| 30 | `kstkeip` | `unsigned long` | `%lu` | Поточне значення покажчика інструкцій ядра EIP/RIP. |
| 31 | `signal` | `unsigned long` | `%lu` | Бітова маска сигналів, які очікують на доставку (Pending Signals). |
| 32 | `blocked` | `unsigned long` | `%lu` | Бітова маска заблокованих сигналів (Blocked Signals Mask). |
| 33 | `sigignore` | `unsigned long` | `%lu` | Бітова маска ігнорованих сигналів (Ignored Signals). |
| 34 | `sigcatch` | `unsigned long` | `%lu` | Бітова маска сигналів, для яких встановлено власний обробник (Caught Signals). |
| 35 | `wchan` | `unsigned long` | `%lu` | Числова адреса функції ядра, у якій процес спить (символьна назва доступна у `/proc/[pid]/wchan`). |
| 39 | `processor` | `int` | `%d` | Номер ядра процесора (CPU core), на якому процес виконувався востаннє. |
| 40 | `rt_priority`| `unsigned int` | `%u` | Пріоритет планування реального часу (Real-Time Priority від 1 до 99 для політик SCHED_FIFO/SCHED_RR). |
| 41 | `policy` | `unsigned int` | `%u` | Політика планування (0 = SCHED_NORMAL, 1 = SCHED_FIFO, 2 = SCHED_RR, 3 = SCHED_BATCH, 5 = SCHED_IDLE). |
| 42 | `delayacct_blkio_ticks` | `unsigned long long` | `%llu` | Сумарна затримка процесу в очікуванні блокового дискового вводу-виводу (у тактах). |

Для обчислення точного віку процесу системні утиліти зчитують час завантаження системи `btime` із файлу `/proc/stat` та додають значення `starttime / USER_HZ`. Це дозволяє отримати абсолютний Unix Timestamp моменту створення процесу без прив'язки до локального системного годинника `gettimeofday()`, який може змінюватися адміністратором або демоном NTP.

## 2. Специфікація глобальної статистики CPU у /proc/stat

Файл `/proc/stat` містить глобальні агреговані лічильники використання процесорного часу від моменту ініціалізації ядра операційної системи. Кожен запис для окремого логічного ядра або сумарного лічильника `cpu` містить десять послідовних числових значень, виражених у тактах `USER_HZ` (jiffies).

Формат рядка процесора:

```text
cpu  <user> <nice> <system> <idle> <iowait> <irq> <softirq> <steal> <guest> <guest_nice>
```

Розподіл часу між цими категоріями визначає стан навантаження обчислювального вузла:

- **`user` (User Time):** Час, витрачений процесором на виконання коду користувацьких програм зі стандартним або підвищеним пріоритетом (`nice <= 0`). Сюди входить робота прикладних алгоритмів, веб-серверів та баз даних.
- **`nice` (Nice User Time):** Час виконання коду користувацьких процесів із низьким пріоритетом (`nice > 0`). Використовується для фонових задач обробки даних, щоб вони автоматично поступалися ресурсами критичним службам.
- **`system` (System / Kernel Time):** Час, проведений ядром під час обслуговування системних викликів, обробки помилок сторінок та виконання внутрішніх підсистем (менеджер пам'яті, планувальник задач).
- **`idle` (Idle Time):** Час, протягом якого на процесорі не було готових до виконання задач, і ядро виконувало спеціальний цикл енергозбереження `cpu_idle` (інструкція `HLT` або перехід у C-стани процесора).
- **`iowait` (IO Wait Time):** Час простою процесора, коли в черзі планувальника не було активних задач `TASK_RUNNING`, проте існували задачі у стані `TASK_UNINTERRUPTIBLE` (стан D), заблоковані очікуванням завершення операцій дискового або мережевого введення-виведення. Високий показник свідчить про вузьке місце у дисковій підсистемі або сховищі даних.
- **`irq` (Hardware Interrupts):** Час, витрачений ядром на безпосереднє обслуговування апаратних переривань від фізичних контролерів (мережеві карти, дискові контролери NVMe/SATA).
- **`softirq` (Software Interrupts):** Час обробки відкладених програмних переривань (Tasklets, обробка мережевого стека ksoftirqd). Високе значення часто свідчить про перевантаження мережевого інтерфейсу великою кількістю дрібних пакетів (PPS flooding).
- **`steal` (Steal Time):** Час, примусово відібраний апаратним гіпервізором у віртуальної машини для обслуговування інших віртуальних середовищ на тому ж фізичному хості (актуально для хмарних інфраструктур AWS EC2, GCP, Azure).
- **`guest` та `guest_nice`:** Час роботи віртуальних процесорів (vCPU), запущених під керуванням локального гіпервізора KVM/QEMU для обслуговування гостьових ОС.

Окрім рядків процесорів, файл `/proc/stat` містить глобальні системні лічильники:

```text
intr 129482194 ...      # Загальна кількість оброблених апаратних переривань
ctxt 481920194         # Кількість перемикань контексту (Context Switches)
btime 1708849200       # Час завантаження системи (Boot Time) в епоху Unix
processes 148201       # Загальна кількість створених процесів (forks) з моменту старту
procs_running 4        # Поточна кількість задач у стані TASK_RUNNING
procs_blocked 1        # Поточна кількість задач, заблокованих на очікуванні I/O (стан D)
```

## 3. Специфікація лічильників пам'яті у /proc/meminfo

Файл `/proc/meminfo` надає деталізований звіт підсистеми віртуальної та фізичної пам'яті ядра Linux. Утиліти `free`, `top` та `vmstat` використовують цей файл як джерело правди про стан RAM:

- **`MemTotal`:** Загальний обсяг фізичної оперативної пам'яті, доступної ядру після резервування пам'яті під бінарний код самого ядра та статичні структури сторінок (Page Tables).
- **`MemFree`:** Обсяг абсолютно вільної пам'яті, яка взагалі не містить даних або кешів і готова до негайного виділення.
- **`MemAvailable`:** Оцінка обсягу пам'яті, доступної для запуску нових додатків без використання swap. Вона розраховується ядром як сума `MemFree` та частини сторінкових кешів (`Cached`, `Buffers`, `SReclaimable`), які можуть бути миттєво скинуті без шкоди для стабільності системи.
- **`Buffers`:** Відносно невелика тимчасова пам'ять для сирих блоків дискових пристроїв (метадані файлових систем, суперблоки, бітові карти інод).
- **`Cached`:** Обсяг сторінкового кеша (Page Cache), у якому зберігаються прочитані та записані файли. За необхідності ця пам'ять негайно вивільняється ядром.
- **`Dirty`:** Обсяг даних у Page Cache, які були змінені додатками у RAM, але ще не записані фоновим потоком `flusher` на фізичний диск.
- **`Writeback`:** Пам'ять, яка в цей самий момент активно передається контролеру сховища для запису на дискові пластини або flash-пам'ять.
- **`AnonPages`:** Сторінки анонімної пам'яті додатків (купи `heap`, стеки `stack`, анонімні виділення через `mmap()`), які не мають прив'язки до дискових файлів і за браку RAM скидаються у swap.
- **`Mapped`:** Файли, відображені в адресний простір процесів через системний виклик `mmap()` (наприклад, виконувані бінарники та бібліотеки `.so`).
- **`Shmem`:** Пам'ять, зайнята спільними ресурсами POSIX/SysV Shared Memory та файловою системою `tmpfs` (включно з каталогами `/dev/shm` та `/run`).
- **`Slab` / `SReclaimable` / `SUnreclaim`:** Пам'ять, виділена внутрішнім алокатором ядра SLAB/SLUB під службові структури (dentry, inode, buffer_head). Поле `SReclaimable` показує обсяг кешів інод і каталогів, які ядро може звільнити за запитом.

## 4. Матриця опцій та прапорців утиліти ps

Утиліта `ps` у Linux (з пакету `procps-ng`) підтримує одночасне використання трьох стандартів синтаксису: стандарту POSIX / System V (з одним дефісом `-`), стандарту BSD (без дефіса) та стандарту довгих опцій GNU (з двома дефісами `--`).

| Синтаксис | Формат команди | Опис виводу та семантика прапорців |
|---|---|---|
| **POSIX / SysV** | `ps -ef` | Повний лістинг (`-f`) усіх процесів системи (`-e`). Формує стандартні колонки: `UID` (власник), `PID` (ідентифікатор), `PPID` (батьківський PID), `C` (використання процесора), `STIME` (час старту), `TTY` (термінал), `TIME` (сумарний час CPU), `CMD` (команда). |
| **POSIX / SysV** | `ps -el` | Довгий технічний формат (`-l`). Додає низькорівневі поля: `F` (системні прапорці ядра), `S` (стан процесу), `PRI` (динамічний пріоритет планувальника), `NI` (nice), `ADDR` (адреса в пам'яті), `SZ` (розмір образу в сторінках), `WCHAN` (точка очікування в ядрі). |
| **BSD** | `ps aux` | Вивід процесів усіх користувачів (`a`), з детальними метриками пам'яті та процесора (`u`), включно з системними демонами без прив'язки до TTY (`x`). Формує колонки: `USER`, `PID`, `%CPU`, `%MEM`, `VSZ`, `RSS`, `TTY`, `STAT`, `START`, `TIME`, `COMMAND`. |
| **BSD** | `ps axms` | Відображення детального статусу обробки сигналів для кожного процесу (маски Pending, Blocked, Ignored, Caught). |
| **GNU Custom** | `ps -eo pid,ppid,user,stat,%cpu,%mem,wchan:20,args` | Власне форматування списку полів. Дозволяє вибирати точні колонки та задавати їхню фіксовану ширину для автоматизованого парсингу скриптами. |
| **Аналіз потоків** | `ps -eLf` або `ps -eT` | Відображення кожного окремого потоку процесу (Lightweight Process). Додає колонку `LWP` (числовий TID потоку), `NLWP` (кількість потоків у процесі) та показує індивідуальний час CPU для кожного потоку. |
| **Дерево процесів** | `ps -ejH` або `ps --forest` | Побудова візуального ієрархічного дерева процесів з відступами та графічними символами зв'язку батьківських і дочірніх задач. |

## 5. Довідник параметрів фільтрації утиліти lsof

Утиліта `lsof` (List Open Files) сканує каталог `/proc` та таблиці дескрипторів ядра для побудови карти відкритих файлів, сокетів, каналів IPC та пристроїв. Вона надає гнучкий синтаксис фільтрації:

| Прапорець | Приклад використання | Призначення та поведінка |
|---|---|---|
| `-i` | `lsof -i` | Список усіх відкритих мережевих сокетів Інтернет-домену (IPv4 та IPv6). |
| `-i :port` | `lsof -i :8080` | Пошук усіх процесів, які відкрили або прослуховують порт TCP/UDP `8080`. |
| `-i tcp:port` | `lsof -i tcp:443` | Фільтрація виключно за протоколом TCP для заданого порту (ігнорує UDP). |
| `-i @host:port` | `lsof -i @192.168.1.10:22` | Фільтрація мережевих сокетів, підключених до конкретної віддаленої або локальної IP-адреси. |
| `-p PID` | `lsof -p 1420` | Вивід повного списку відкритих файлів та дескрипторів конкретного процесу за його PID. |
| `-p ^PID` | `lsof -p ^1` | Виключення процесу з виводу (символ `^` означає логічне заперечення). |
| `-u USER` | `lsof -u nginx` | Фільтрація відкритих ресурсів за іменем або числовим UID системного користувача. |
| `-c COMM` | `lsof -c postgres` | Фільтрація за початком назви виконуваної програми (префіксне співпадіння). |
| `-d FD` | `lsof -d 0-2` | Фільтрація за числовим номером файлового дескриптора (наприклад, 0=stdin, 1=stdout, 2=stderr). |
| `-d txt` | `lsof -d txt` | Пошук виконуваного коду програми, завантаженого в пам'ять процесу. |
| `-d mem` | `lsof -d mem` | Пошук динамічних бібліотек (`.so`) та файлів, відображених у пам'ять через `mmap()`. |
| `-d cwd` | `lsof -d cwd` | Пошук процесів, для яких заданий каталог є поточним робочим каталогом. |
| `+D DIR` | `lsof +D /var/log` | Рекурсивний пошук процесів, які утримують відкриті файли всередині зазначеного каталогу. |
| `+f -- /dev/sda1` | `lsof /mnt/data` | Пошук процесів, що блокують точку монтування або дисковий пристрій перед розмонтуванням `umount`. |
| `-n` | `lsof -n` | Вимкнення зворотного резолвінгу IP-адрес у доменні імена DNS (критично для швидкості під час аварій мережі). |
| `-P` | `lsof -P` | Вимкнення перетворення номерів портів на назви протоколів з `/etc/services` (виводить `80` замість `http`). |
| `-F` | `lsof -F pftn` | Машиночитаний вивід для парсингу в автоматизованих скриптах: `p` (PID), `f` (дескриптор), `t` (тип вузла), `n` (ім'я файлу). |
| `(deleted)` | `lsof +L1` | Пошук відкритих файлів із лічильником жорстких посилань менше ніж 1 (`i_nlink < 1`), які видалено з файлової системи. |

### Машиночитаний формат виводу lsof (`-F`)

При виклику `lsof -F <fields>` утиліта формує вертикальний потік рядків, де кожен рядок починається з одного символу-ідентифікатора поля:

- `p<PID>` — початок блоку нового процесу (наприклад, `p4821`).
- `g<PGID>` — ідентифікатор групи процесу.
- `u<UID>` — числовий ідентифікатор власника процесу.
- `c<COMMAND>` — назва процесу.
- `f<FD>` — номер файлового дескриптора (наприклад, `f3` або `fcwd`, `ftxt`, `fmem`).
- `a<ACCESS>` — режим доступу до файлу: `r` (read), `w` (write), `u` (read/write).
- `l<LOCK>` — тип блокування файлу (`R` для читання, `W` для запису, `N` без блокування).
- `t<TYPE>` — тип файлового вузла VFS: `REG` (звичайний файл), `DIR` (каталог), `CHR` (символьний пристрій), `FIFO` (іменований канал), `unix` (UNIX-сокет), `IPv4` / `IPv6` (мережевий сокет).
- `d<DEVICE>` — старший і молодший номери пристрою файлової системи (Device ID).
- `i<INODE>` — номер іноди файлу у файловій системі.
- `n<NAME>` — абсолютний шлях до файлу, мережева адреса сокета (`127.0.0.1:8080->127.0.0.1:54321`) або мітка видаленого файлу (`/var/log/app.log (deleted)`).

Такий формат дозволяє надійно обробляти мільйони відкритих дескрипторів у скриптах моніторингу без ризику помилок позиційного вирівнювання колонок.
