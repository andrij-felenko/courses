# 🔌 Узагальнена структура апаратного контролера I3C (IP Core)

Апаратний контролер шини I3C (Master Controller IP Core) є складним системним периферійним блоком сучасних систем на кристалі (SoC). На відміну від простих ссувних регістрів класичного I2C, контролер I3C є повноцінним протокольним автоматом (Protocol State Machine), який підтримує динамічну зміну електричних режимів шини, побітовий арбітраж, генерацію загальних команд (CCC) та автономну обробку асинхронних внутрішньосмугових переривань (IBI).

## 1. Внутрішня апаратна архітектура I3C IP Core

Типовий синтезований модуль I3C Master IP (наприклад, DesignWare I3C Controller від Synopsys чи Cadence I3C IP) складається з п'яти основних функціональних підсистем, кожна з яких відповідає за окремий шар взаємодії між системною шиною SoC та фізичною двопровідною лінією.

### 1.1. Інтерфейс системної шини (Host Bus Interface)

Підключає контролер до внутрішньої системної шини SoC (AMBA AHB, AXI4-Lite або APB). Містить регістрову карту керування, статусу, конфігурації таймінгів та масок переривань контролера. Регістрова карта включає:

- **Регістр конфігурації швидкості (SCL Timing Register):** Визначає значення дільників тактової частоти для формування інтервалів `t_high` та `t_low` у режимах Open-Drain та Push-Pull SDR.
- **Регістр масок переривань (Interrupt Enable Register):** Дозволяє генерувати апаратне переривання процесора при виникненні подій IBI, переповненні RX FIFO, спорожнінні TX FIFO або помилках на шині.
- **Регістри стану черг (FIFO Status Registers):** Відображають поточний рівень заповнення черг команд, відповідей та даних.

### 1.2. Черги чергування транзакцій та черги даних (FIFO Queues)

Для забезпечення високої продуктивності та зменшення навантаження на центральний процесор контролер використовує чотири окремі апаратні черги FIFO:

1. **Command FIFO (Черга команд):** Накопичує 32-бітні командні дескриптори транзакцій. Кожен дескриптор визначає тип транзакції (CCC, Private Write, Private Read, I2C Transfer), динамічну адресу цілі, довжину буфера, режим швидкості (SDR/HDR) та прапорці завершення.
2. **TX Data FIFO (Черга вихідних даних):** Буфер для збереження даних, що передаються на шину. Підтримує пакетну передачу через прямий доступ до пам'яті (DMA).
3. **RX Data FIFO (Черга вхідних даних):** Накопичує дані, зчитані з периферійних пристроїв.
4. **Response FIFO (Черга відповідей):** Записує підсумковий статус виконання кожної транзакції (успіх, NACK, програш арбітражу, помилка парності, таймаут) та кількість реально переданих байтів.

### 1.3. Блок автономної обробки переривань (IBI Status Manager)

Апаратно відстежує стан лінії SDA у періоди спокою шини (Bus IDLE). При виявленні умови START, ініційованої підлеглим пристроєм, модуль виконує такі автономні дії:

- Зчитує 7-бітну динамічну адресу пристрою, що ініціював переривання;
- Порівнює її з конфігураційною таблицею дозволених IBI;
- Надсилає підтвердження ACK (якщо IBI дозволено) або відхилення NACK;
- Зчитує обов'язковий байт даних (Mandatory Data Byte — MDB) та зберігає його у буфер IBI Status FIFO;
- Генерує апаратне переривання процесора для виклику драйвера ядра.

### 1.4. Генератор тактування та автомат станів (SCL & Protocol FSM)

Протокольний автомат станів (Finite State Machine) керує послідовністю формування сигналів SCL/SDA. Він підтримує такі основні стани:

- `IDLE`: Стан спокою шини (обидві лінії у високому рівні);
- `START` / `REPEATED_START`: Формування умови початку кадру;
- `DAA_ARBITRATION`: Побітовий зсув та арбітраж 48-бітного PID у режимі відкритого стоку;
- `CCC_EXECUTION`: Формування кадрів загальних команд;
- `PUSH_PULL_DATA`: Високошвидкісна передача даних у режимі SDR/HDR;
- `STOP`: Формування умови завершення кадру.

### 1.5. Фізичний каскад вводу-виводу (Push-Pull / Open-Drain IO PHY)

Апаратні драйвери ліній SDA та SCL, які динамічно перемикаються між режимом відкритого стоку (Open-Drain із зовнішньою або внутрішньою підтяжкою) та активним симетричним виходом (Push-Pull із двома протифазними транзисторами).

## 2. Апаратні пастки та класичні проблеми реалізації

Під час проектування та експлуатації апаратних контролерів I3C на системному рівні виникають типові класичні проблеми:

- **Обмеження ємності шини в режимі Push-Pull (Capacitive Loading Falloff):**
  На частотах 12.5 МГц (SDR) та вище сумарна паразитна ємність друкованої плати та входів мікросхем не повинна перевищувати 50 pF. Якщо паразитна ємність перевищує цей поріг через довгі провідники, крутизна фронтів високого рівня падає, що призводить до помилок парності (Parity Errors) у режимах HDR. Рішення полягає у використанні активних буферів шини (I3C Bus Repeaters/Redrivers).
- **Холодні хибні спалахи Hot-Join при подачі живлення (Power Ramp-up Glitches):**
  Під час подачі живлення на сенсори деякі мікросхеми можуть короткочасно притягувати лінію SDA до землі до завершення внутрішнього скидання (POR — Power-On Reset). Апаратний контролер I3C може помилково інтерпретувати це як запит Hot-Join та ініціювати небажану процедуру ENTDAA, коли шина ще не готова.
- **Особливості підтримки класичних I2C пристроїв з 50ns Spike Filter:**
  Якщо на шині присутні legacy I2C пристрої, вони повинні мати вбудований фільтр коротких сплесків (50ns spike filter). Без цього фільтра високі частоти тактування I3C (SCL 12.5 МГц, тривалість імпульсу 40ns) будуть помилково сприйматися I2C пристроями як логічні рівні, спричиняючи збої внутрішніх автоматів I2C.
- **Переповнення черг FIFO при високій частоті IBI:**
  Якщо декілька сенсорів одночасно генерують переривання IBI з високою частотою, а процесор затримав обробку переривання у зв'язку з вищим пріоритетом інших задач, черга Response/IBI FIFO контролера може переповнитися. Це призводить до скидання нових IBI та втрати подій сенсорів.
