# 🧮 Електричний розрахунок та математика арбітражу шини I3C

Фізична сутність та висока енергетична ефективність шини MIPI I3C ґрунтуються на математичному та електричному розмежуванні двох режимів роботи: режим відкритого стоку (Open-Drain, OD) та симетричний режим активованого виходу (Push-Pull, PP).

Розуміння часових констант, параметрів ємності шини та розрахунку енергоспоживання дозволяє інженерам точно визначати фізичні межі швидкостей та оптимізувати топологію друкованих плат для забезпечення стабільної передачі даних на частотах до 12.5 МГц і вище.

## 1. Розрахунок часу наростання фронту та обмеження швидкості Open-Drain

У класичному режимі I2C та під час виконання арбітражних процедур DAA або IBI в I3C лінія даних SDA працює у режимі відкритого стоку. У цьому стані n-канальний МОП-транзистор виходу пристрою може лише притягувати лінію до потенціалу землі (логічний нуль). Повернення лінії до високого логічного рівня (потенціал живлення `V_dd`) відбувається виключно за рахунок заряджання паразитної ємності шини через зовнішній підтягувальний резистор `R_pullup`.

### 1.1. Фізична модель паразитної ємності шини

Сумарна ємність лінії шини `C_bus` складається з трьох основних компонентів:

1. **Ємність провідників друкованої плати (`C_trace`):** Залежить від довжини, ширини та відстані до шару землі (GND plane). Для стандартних текстолітів FR-4 погонна ємність становить приблизно `1.2 - 1.5 pF/cm`.
2. **Вхідна ємність виводів мікросхем (`C_pin`):** Вхідна ємність виводів SDA/SCL кожного підключеного пристрою (зазвичай `5 - 10 pF` на пристрій).
3. **Ємність захисних діодів ESD (`C_esd`):** Захист від статичної електрики додає ще `2 - 5 pF` на кожен порт.

Загальна ємність для шини з `N` пристроями розраховується за формулою:

```
C_bus = C_trace + ∑ (C_pin_k + C_esd_k)    [сумарна ємність лінії шини]
```

### 1.2. Виведення часової константи та часу наростання фронту

Часова константа `τ` (тау) експоненційного заряджання ємності `C_bus` через опір `R_pullup` описується як:

```
τ = R_pullup · C_bus
```

Зміна напруги на лінії SDA як функція часу `V(t)` під час розмикання транзистора визначається диференціальним рівнянням першого порядку, розв'язок якого має вигляд:

```
V(t) = V_dd · (1 - e^(-t / τ))
```

Згідно зі специфікацією MIPI I3C та I2C, час наростання фронту `t_rise` вимірюється як інтервал часу, протягом якого напруга зростає від 30% (`0.3 · V_dd`) до 70% (`0.7 · V_dd`) від рівня живлення.

Обчислимо моменти часу `t_1` та `t_2`, коли напруга досягає цих порогів:

```
V(t_1) = 0.3 · V_dd

0.3 · V_dd = V_dd · (1 - e^(-t_1 / τ))
0.7 = e^(-t_1 / τ)
t_1 = -τ · ln(0.7) = τ · ln(1 / 0.7) ≈ 0.3567 · τ    [час досягнення 30% V_dd]

V(t_2) = 0.7 · V_dd

0.7 · V_dd = V_dd · (1 - e^(-t_2 / τ))
0.3 = e^(-t_2 / τ)
t_2 = -τ · ln(0.3) = τ · ln(1 / 0.3) ≈ 1.2040 · τ    [час досягнення 70% V_dd]
```

Віднімаючи `t_1` від `t_2`, отримуємо точний вираз для часу наростання фронту `t_rise`:

```
t_rise = t_2 - t_1
       = 1.2040 · τ - 0.3567 · τ
       = 0.8473 · τ
       ≈ 0.847 · R_pullup · C_bus    [формула часу наростання фронту Open-Drain]
```

### 1.3. Числовий розрахунок для I2C та порівняння з I3C Push-Pull

Для класичної плати з ємністю `C_bus = 400 pF` та стандартним підтягувальним опором `R_pullup = 2 kΩ`:

```
t_rise = 0.847 · 2000 Ω · 400·10⁻¹² F
       = 0.847 · 800·10⁻⁹ s
       = 677.6 ns    [тривалість фронту наростання Open-Drain]
```

Оскільки для коректного зчитування логічного рівня тривалість тактового імпульсу `T_high` повинна перевищувати `t_rise`, а повний період тактування складається з `T_scl = T_high + T_low ≥ 2 · t_rise`, гранична частота Open-Drain становить:

```
f_max_od = 1 / (2 · t_rise)
         = 1 / (2 · 677.6·10⁻⁹ s)
         ≈ 738 kHz    [теоретична межа частоти Open-Drain]
```

У режимі Push-Pull шини I3C опір `R_pullup` замінюється активним p-канальним МОП-транзистором вихідного каскаду з внутрішнім опором каналу `R_ds_on ≈ 50 Ω`.

Обчислимо час наростання фронту у режимі Push-Pull для ємності `C_bus = 50 pF` (рекомендований максимум для I3C SDR):

```
t_rise_pp = 0.847 · 50 Ω · 50·10⁻¹² F
          = 2.11 ns    [тривалість фронту наростання Push-Pull]
```

Зменшення часу наростання фронту у 320 разів дозволяє підвищити частоту SCL до 12.5 МГц (період `T_scl = 80 ns`, `T_high = 40 ns`, `T_low = 40 ns`), забезпечення чистої пропускної здатності 12.5 Мбіт/с у режимі SDR.

## 2. Математика енергетичного балансу на один біт

Важливою перевагою переходу від Open-Drain до Push-Pull є радикальне зменшення енергії, що розсіюється на передачу одного біта даних.

### 2.1. Енергетична модель відкритого стоку (Open-Drain)

Під час передачі логічного нуля у режимі Open-Drain n-канальний транзистор замкнений на землю протягом усього інтервалу біта `t_bit`. Через підтягувальний резистор `R_pullup` протікає постійний струм короткого замикання на землю:

```
I_stat = V_dd / R_pullup
```

Енергія `E_stat`, розсіювана у вигляді тепла за один біт нуля тривалістю `t_bit`, дорівнює:

```
E_stat = P_stat · t_bit = (V_dd² / R_pullup) · t_bit
```

До цієї стаціонарної енергії додається динамічна енергія перезаряджання ємності `C_bus` при переході від нуля до одиниці `E_dyn = C_bus · V_dd²`. Таким образом, загальна енергія на біт становить:

```
E_od = (V_dd² / R_pullup) · t_bit + C_bus · V_dd²    [загальна енергія на біт у Open-Drain]
```

### 2.2. Енергетична модель Push-Pull

У режимі Push-Pull стаціонарний струм відсутній, оскільки при стабільному логічному нулі чи одиниці один із транзисторів каскаду повністю закритий. Енергія витрачається виключно на динамічний перезаряд ємності лінії:

```
E_pp = C_bus · V_dd²    [енергія на біт у Push-Pull]
```

### 2.3. Порівняльний розрахунок енергоефективності

Порівняємо енергетичні витрати на передачу 1 Мегабіта даних при напрузі живлення `V_dd = 1.8 V`, ємності `C_bus = 50 pF` та опорі `R_pullup = 2 kΩ`.

#### Для I2C Fast-Mode Plus (1 Мбіт/с, `t_bit = 1 μs`):

```
E_od = ((1.8)² / 2000) · 10⁻⁶ + 50·10⁻¹² · (1.8)²
     = (3.24 / 2000) · 10⁻⁶ + 50·10⁻¹² · 3.24
     = 1.62·10⁻⁹ J + 0.162·10⁻⁹ J
     = 1.782 nJ на біт    [енергоспоживання I2C]

Загальна енергія на 1 Мбіт = 10⁶ · 1.782 nJ = 1.782 mJ
```

#### Для I3C SDR (12.5 Мбіт/с, Push-Pull):

```
E_pp = 50·10⁻¹² · (1.8)²
     = 0.162 nJ на біт    [енергоспоживання I3C]

Загальна енергія на 1 Мбіт = 10⁶ · 0.162 nJ = 0.162 mJ
```

Коефіцієнт енергетичного виграшу `K_energy` обчислюється як:

```
K_energy = E_od / E_pp
         = 1.782 / 0.162
         11.0    [виграш в енергоефективності у 11 разів]
```

Таким чином, використання push-pull сигналізації в I3C дає змогу передавати той самий обсяг даних, витрачаючи в одинадцять разів менше енергії акумулятора.

## 3. Математична модель побітового арбітражу DAA

Під час виконання процедури DAA (команда `ENTDAA`) усі підключені пристрої, які ще не мають динамічної адреси, одночасно передають свій 48-бітний Provisional ID (PID), 8-бітний BCR та 8-бітний DCR на відкритому стоці.

### 3.1. Логічна функція монтажного І (Wired-AND)

Оскільки лінія SDA працює у режимі відкритого стоку, рівень напруги на шині у будь-який момент часу описується логічною кон'юнкцією бітів усіх випромінюючих пристроїв:

```
SDA_bus(t) = Bit_1(t) ∧ Bit_2(t) ∧ ... ∧ Bit_N(t)
```

Якщо пристрій `k` намагається передати логічну одиницю (`Bit_k = 1`, транзистор вимкнено), але на шині зчитується логічний нуль (`SDA_bus = 0`, оскільки пристрій `j` увімкнув транзистор), пристрій `k` фіксує програш арбітражу:

```
Collision_k = Transmitted_Bit_k ∧ ¬(SDA_bus)
```

Пристрій, у якого `Collision_k == 1`, негайно вимикає свій вихідний транзистор і переходить у стан слухача до наступного запуску `ENTDAA`.

### 3.2. Доведення унікальності та оптимізація розподілу адрес

Оскільки 48-бітний Provisional ID є строго унікальним для кожного фізичного екземпляра мікросхеми, ймовірність того, що два пристрої матимуть ідентичний PID, дорівнює нулю.

Процес відбору переможця описується математичною функцією мінімізації чисельного значення ідентифікатора:

```
Winner_index = argmin( PID_1, PID_2, ..., PID_N )
```

Перемагає пристрій із найменшим двійковим значенням PID. Оскільки у кожному раунді DAA вибуває рівно один пристрій (переможець отримує динамічну адресу і припиняє участь у DAA), кількість раундів `R` для шини з `N` пристроями строго дорівнює:

```
R = N    [кількість раундів DAA дорівнює кількості пристроїв]
```

Обчислимо максимальну кількість доступних 7-бітних динамічних адрес `N_available` з урахуванням зарезервованих специфікацією MIPI I3C адрес:

```
N_total = 2⁷ = 128

Зарезервовані адреси:
- 0x00: Broadcast / General Call
- 0x01: Reserved
- 0x02: Hot-Join Target Address
- 0x7E: I3C Broadcast Address
- 0x7F: Reserved

N_available = 128 - 5 = 123 адреси    [максимальна кількість периферійних пристроїв на одній шині I3C]
```
