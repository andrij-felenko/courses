Цей технічний довідник містить вичерпну специфікацію синтаксису файлів конфігурації `sysusers.d`, алгоритмів утиліти `systemd-sysusers`, специфіку обробки типів директив `u`, `g`, `m`, `r`, механізм автоматичного виділення UID/GID, декларативне запечатування акаунтів, взаємодію з підсистемами NSS/PAM, інтеграцію з мандатним розмежуванням доступу (SELinux) та програмний парсинг специфікації мовами C і C++.

## Каталоги конфігурації та порядок пріоритетів

Файли конфігурації мають обов'язкове розширення `.conf` і зчитуються утилітою `systemd-sysusers` із системних каталогів у суворо визначеній ієрархії пріоритетів:

| Каталог | Пріоритет | Призначення |
| :--- | :--- | :--- |
| `/etc/sysusers.d/*.conf` | 1 (найвищий) | Локальні конфігураційні правила системного адміністратора |
| `/run/sysusers.d/*.conf` | 2 (середній) | Динамічні тимчасові правила, створені під час виконання (volatile runtime) |
| `/usr/local/lib/sysusers.d/*.conf` | 3 (проміжний) | Конфігурації локально встановленого програмного забезпечення |
| `/usr/lib/sysusers.d/*.conf` | 4 (найнижчий) | Базові правила від постачальників пакетів дистрибутива |

### Поведінка перекриття, маскування та сортування

1. **Лексикографічне перекриття (Lexicographical Override).** Якщо файл із однаковим іменем (наприклад, `50-httpd.conf`) існує у кількох каталогах, зчитується та виконується лише файл із каталогу з найвищим пріоритетом. Файл `/usr/lib/sysusers.d/50-httpd.conf` повністю нехтується, якщо присутній `/etc/sysusers.d/50-httpd.conf`. Це дозволяє системному адміністраторові перевизначати дистрибутивні конфігурації без безпосереднього редагування файлів у `/usr/lib/sysusers.d/`.
2. **Декларативне маскування (Masking).** Для повного вимкнення конфігураційного файлу, що поставляється дистрибутивом у `/usr/lib/sysusers.d/foo.conf`, адміністратор створює символічне посилання у `/etc/sysusers.d/foo.conf`, яке вказує на `/dev/null`, або створює за вказаним шляхом порожній файл нульової довжини. Утиліта `systemd-sysusers` виявляє такі файли й повністю пропускає їх опрацювання під час злиття конфігураційного маніфесту.
3. **Алфавітне сортування виконання (Global Lexicographical Ordering).** Усі файли з усіх каталогів (після усунення перекритих і замаскованих) об'єднуються у єдиний логічний список та сортуються за алфавітним іменем файлу, незалежно від каталогів походження. Конфігурація `00-system.conf` буде опрацьована раніше за `90-application.conf`, що дозволяє жорстко контролювати порядок створення базових системних користувачів перед прикладною службою.

## Формальний синтаксис та структура рядків конфігурації

Кожен непророжній рядок, який не є коментарем (рядок коментаря починається з символу `#`), визначає окрему декларативну директиву створення чи модифікації облікових записів. Рядок складається з 6 позиційних полів, розділених пробілами або символами табуляції:

```text
Тип   Назва   ID   "Коментар (GECOS)"   Домашній_каталог   Оболонка
```

Якщо значення будь-якого поля містить пробіли або розділювачі, воно обов'язково обрамляється подвійними лапками `"..."`. Символ дефіса `-` використовується у будь-якому полі як маркер значення за замовчуванням (default).

## Детальна специфікація типів директив (u, g, m, r)

### 1. Тип u (User — Створення користувача та його первинної групи)

Директива `u` описує створення системного користувача. У разі відсутності однойменної групи директива `u` також автоматично створює первинну групу з тим самим іменем та ідентифікатором GID, який збігається з призначеним UID.

Синтаксис:
```text
u  НАЗВА  [ID[:ГРУПА]]  ["КОМЕНТАР"]  [ДОМАШНІЙ_КАТАЛОГ]  [ОБОЛОНКА]
```

#### Правила валідації та інтерпретації полів для типу u:
* **НАЗВА**: Системне ім'я користувача. Повинно відповідати вимогам POSIX та суворим правилам найменування systemd (починатися з літери або підкреслення, містити лише латинські літери, цифри, дефіси та підкреслення, довжиною до 31 символу). Якщо ім'я починається з модифікатора `!`, будь-яка помилка створення акаунту фатально зупиняє виконання утиліти `systemd-sysusers`.
* **ID**: Числовий UID, комбінація UID:GID, UID:Groupname або діапазон values:
  * `-` — автоматичний вибір першого вільного системного UID (у діапазоні від 1 до `SYSTEM_UID_MAX`, зазвичай 999).
  * `150` — призначення фіксованого статичного UID 150 та фіксованого GID 150 для первинної групи.
  * `150:200` — призначення фіксованого UID 150 та використання фіксованої первинної групи з GID 200.
  * `150:systemd-journal` — призначення UID 150 та прив'язка до існуючої первинної групи `systemd-journal`.
  * `100..200` — вибір першого вільного UID у строго визначеному діапазоні від 100 до 200 включно.
* **КОМЕНТАР**: Текстовий опис користувача (поле GECOS у `/etc/passwd`). За замовчуванням `-` (залишає порожнє коментарне поле).
* **ДОМАШНІЙ_КАТАЛОГ**: Абсолютний шлях до домашньої теки. За замовчуванням `-` (інтерпретується як `/`).
* **ОБОЛОНКА**: Абсолютний шлях до командного інтерпретатора. За замовчуванням `-` (використовується неінтерактивна оболонка блокування `/usr/sbin/nologin` або `/sbin/nologin`).

Приклад:
```text
# Створення системного користувача postgres з авто-UID, коментарем та домом /var/lib/postgresql
u postgres - "PostgreSQL Server" /var/lib/postgresql /bin/false
```

### 2. Тип g (Group — Створення окремої системної групи)

Директива `g` призначена для створення системної групи без прив'язаного користувача.

Синтаксис:
```text
g  НАЗВА  [ID]
```

#### Правила валідації полів для типу g:
* **НАЗВА**: Назва групи (наприклад, `wheel`, `kvm`, `render`, `input`).
* **ID**: Числовий GID або діапазон:
  * `-` — вибір першого вільного системного GID у виділеному системному діапазоні.
  * `10` — призначення статичного GID 10.
  * `500..599` — вибір першого вільного GID у діапазоні від 500 до 599.

Приклад:
```text
# Створити системну групу render з фіксованим GID 105
g render 105
```

### 3. Тип m (Member — Додавання користувача до додаткової групи)

Директива `m` встановлює членство існуючого користувача у додатковій (вторинній) системній групі.

Синтаксис:
```text
m  КОРИСТУВАЧ  ГРУПА
```

#### Механізм обробки типом m:
* **КОРИСТУВАЧ**: Назва користувача, якого необхідно додати до групи.
* **ГРУПА**: Назва додаткової групи.

Обидві сутності можуть бути оголошені у поточних або попередньо зчитаних файлах `sysusers.d` або вже існувати у системній базі даних (`/etc/passwd` та `/etc/group`). Якщо користувач чи група відсутні, утиліта реєструє відкладену зв'язку й застосовує її після обробки всіх маніфестів.

Приклад:
```text
# Додати користувача systemd-journal до групи systemd-journal-remote
m systemd-journal systemd-journal-remote
```

### 4. Тип r (Range — Резервування діапазонів UID/GID)

Директива `r` резервує діапазон числових ідентифікаторів UID/GID, унеможливлюючи їх автоматичне виділення утилітою `systemd-sysusers` під час обробки значень `-`.

Синтаксис:
```text
r  -  LOW..HIGH
```

#### Параметри:
* **LOW..HIGH**: Нижня та верхня межі зарезервованого діапазону (включно).

Приклад:
```text
# Зарезервувати діапазон UID/GID від 500 до 599 для зовнішнього інструменту розгортання
r - 500..599
```

## Детальний розбір поля GECOS та POSIX-стандартів

Поле коментаря (гекос, GECOS — від назви операційної системи General Electric Comprehensive Operating System) традиційно використовується у файлі `/etc/passwd` для збереження метаданих про користувача. Згідно зі стандартом IEEE Std 1003.1 (POSIX), поле GECOS складається з п'яти елементів, розділених комами:

1. **Full Name** — повне ім'я користувача або опис службового акаунту (наприклад, `"Nginx Web Server"`).
2. **Room Number** — номер кабінету або системної стійки.
3. **Work Phone** — робочий телефонний номер.
4. **Home Phone** — домашній телефонний номер.
5. **Other Information** — додаткові системні метадані (наприклад, конфігураційні прапорці).

Під час обробки конфігураційних рядків `sysusers.d` утиліта `systemd-sysusers` очищає переданий рядок від символів двокрапки `:`, які є роздільниками полів у файлі `/etc/passwd`. Це запобігає потенційній вразливості розділення рядків (line injection). Якщо коментар містить комі, утиліта коректно зберігає їх у першому підполі Full Name.

## Таблиця модифікаторів та спеціальних символів

| Символ | Контекст | Функціональне призначення |
| :--- | :--- | :--- |
| `-` | Будь-яке поле | Використання значення за замовчуванням (Default value) |
| `!` | Префікс назви (`!postgres`) | Переривання виконання при помилці створення акаунту |
| `:` | Поле ID (`UID:GID` або `UID:Group`) | Роздільник між ID користувача та ID/іменем первинної групи |
| `..` | Поле ID (`LOW..HIGH`) | Позначення діапазону для автоматичного пошуку вільного ID |

## Алгоритм автоматичної генерації та алокації UID/GID

Під час опрацювання директив зі значенням `-` або діапазоном `LOW..HIGH` утиліта `systemd-sysusers` виконує алгоритм детермінованого пошуку та алокації числових ідентифікаторів.

### Кроки алгоритму алокації:

1. **Побудова списку зайнятих ідентифікаторів.** Утиліта парсить існуючі файли `/etc/passwd` та `/etc/group` (а також звертається до NSS backend, якщо прапорці не обмежують лише локальні файли) і створює внутрішню хеш-таблицю та бітову маску (bitmap) використаних UID та GID.
2. **Визначення системного діапазону.** Межі системного діапазону зчитуються з файлу `/etc/login.defs` (параметри `SYS_UID_MIN`–`SYS_UID_MAX` та `SYS_GID_MIN`–`SYS_GID_MAX`). За їх відсутності використовуються стандартні константи systemd: мінімальний системний UID/GID = 1, максимальний системний UID/GID = `SYSTEM_UID_MAX` (зазвичай 999).
3. **Облік зарезервованих діапазонів r.** Усі діапазони, оголошені директивами `r`, маскуються у бітовій карті як зайняті.
4. **Забезпечення збігу UID та GID.** Для директиви `u` з невідомим ID (`-`) алгоритм здійснює ітеративний пошук найменшого числа `N` у діапазоні системних UID, для якого **одночасно** вільні і `UID = N`, і `GID = N`. Це гарантує симетричність первинної групи користувача.
5. **Вичерпання діапазону.** Якщо вільного парного ідентифікатора `N` у системному діапазоні не знайдено, утиліта робить повторний прохід, шукаючи вільний `UID = N` та виділяючи для нього окремий вільний `GID = M` з іншим номером. При повному вичерпанні діапазону генерується помилка.

## Взаємодія з підсистемою Name Service Switch (NSS)

Підсистема Name Service Switch (NSS) у Linux відповідає за маршрутизацію запитів до баз даних користувачів та груп через конфігураційний файл `/etc/nsswitch.conf`. Джерелами даних можуть бути локальні файли (`files`), системний демон `systemd-machined` (`mymachines`), мережеві каталоги LDAP (`ldap`) або Windows Active Directory (`winbind`).

Під час виконання на ранніх етапах завантаження операційної системи або під час генерації образів файлової системи утиліта `systemd-sysusers` дотримується наступних правил взаємодія з NSS:

1. **Прямий доступ до локальних файлів.** Для запобігання блокуванням та зацикленням до підняття мережевих інтерфейсів утиліта читає та модифікує текстові файли `/etc/passwd` та `/etc/group` безпосередньо, минаючи мережеві модулі NSS (`ldap`, `sssd`).
2. **Усунення конфліктів з nss-systemd.** Динамічні користувачі, створені через `DynamicUser=yes` у юнітах systemd, керуються модулем `nss-systemd` і не записуються у `/etc/passwd`. Утиліта `systemd-sysusers` опрацьовує лише статичні декларативні акаунти.
3. **Перевірка наявних ідентифікаторів.** Перед створенням нового запису утиліта викликає системні функції `getpwnam()` та `getgrnam()`, щоб переконатися, що ім'я акаунту не зайняте у зовнішніх базах даних.

## Декларативне запечатування (Sealing) та безстановий стан (Stateless)

Однією з ключових властивостей `systemd-sysusers` є забезпечення безпечного декларативного запечатування системних акаунтів.

### Механіка блокування пароля та аутентифікації

При створенні нового користувача утиліта формує записи не лише у `/etc/passwd` та `/etc/group`, а й у захищених базах даних `/etc/shadow` та `/etc/gshadow`:

1. **Запис /etc/shadow**:
   ```text
   postgres:!:19000:0:99999:7:::
   ```
   Поле хешу пароля заповнюється єдиним символом знак оклику `!`. Згідно зі специфікацією підсистеми PAM (`pam_unix`) та системного виклику `crypt()`, зашифрований хеш, що починається з `!`, робить неможливим підбір або перевірку будь-якого введеного пароля. Це повністю виключає можливість інтерактивного входу у систему під іменем системного користувача через SSH, локальну консоль чи display manager.

2. **Запис /etc/gshadow**:
   ```text
   postgres:!::
   ```
   Аналогічно блокується можливе використання паролів груп утилітою `newgrp`.

### Ідемпотентність та поведінка у безстанових системах (Stateless OS)

* **Ідемпотентне виконання.** Якщо користувач `postgres` вже існує у `/etc/passwd` з UID 105, при повторному запуску `systemd-sysusers` утиліта перевіряє його наявність і **не перевизначає** його наявний UID, домашній каталог чи оболонку. Вона лише додає відсутні додаткові групи чи створює відсутні записи у `/etc/shadow`.
* **Автоматична ініціалізація порожнього /etc.** У безстанових системах (де `/etc` монтується у `tmpfs` або є порожнім на момент завантаження), `systemd-sysusers` автоматично створює мінімальні базові файли `/etc/passwd`, `/etc/group`, `/etc/shadow` та `/etc/gshadow`, заповнюючи їх на основі маніфестів із `/usr/lib/sysusers.d/`.

## Інтеграція з системним завантаженням та безпековими контекстами (SELinux)

Служба `systemd-sysusers.service` виконується на дуже ранній стадії завантаження операційної системи Linux — у межах цілі `sysinit.target`, до запуску основної більшості системних демонів і мережевих служб.

### Контексти безпеки SELinux та AppArmor

У системах із ввімкненим мандатним розмежуванням доступу (Mandatory Access Control — MAC, наприклад, SELinux у Fedora/RHEL або AppArmor в Ubuntu/SUSE):

1. **Відновлення контексту файлів (SELinux Labeling).** Під час створення або атомарного перезапису файлів `/etc/passwd`, `/etc/group`, `/etc/shadow` та `/etc/gshadow` утиліта `systemd-sysusers` звертається до бібліотеки `libselinux` і встановлює точні безпекові контексти типів `passwd_file_t` та `shadow_t`. Це гарантує, що демони, які запускаються пізніше, не будуть заблоковані політикою SELinux при спробі читання бази даних облікових записів.
2. **Права доступу файлової системи (POSIX Permissions).** Тимчасові та підсумкові файли створюються з мінімально необхідними правами:
   * `/etc/passwd` та `/etc/group`: маска `0644` (читання для всіх, запис лише для root).
   * `/etc/shadow` та `/etc/gshadow`: маска `0000` або `0600` / `0640` (доступ лише для root або спеціальної групи `shadow`).

## Крайові випадки та обробка конфліктів конфігурації

Під час опрацювання складних маніфестів `sysusers.d` у реальних системних середовищах можуть виникати нетипові крайові випадки:

1. **Конфлікт статичних UID у різних маніфестах.** Якщо файл `10-first.conf` оголошує `u userA 150`, а файл `20-second.conf` оголошує `u userB 150`, утиліта створює користувача `userA` з UID 150, а під час обробки `userB` реєструє помилку конфлікту ідентифікатора. Якщо для `userB` ім'я було вказане з модифікатором `!userB`, виконання `systemd-sysusers` фатально зупиняється з кодом помилки.
2. **Неузгодженість первинних груп.** Якщо у файлі маніфесту вказано `u userC 160:nonexistentgroup`, але група `nonexistentgroup` ще не створена і не оголошена в інших маніфестах, утиліта автоматично створює групу `nonexistentgroup` із GID 160.
3. **Порушення цілісності базових файлів.** Якщо у файлі `/etc/passwd` користувач існує, але відповідний запис у `/etc/shadow` відсутній (наприклад, внаслідок ручного редагування або збою некоректного скрипту), `systemd-sysusers` виявляє цей прогалин і дозаписує запечатаний рядок shadow.

## Командний інтерфейс утиліти systemd-sysusers

```bash
systemd-sysusers [ОПЦІЇ...] [ФАЙЛ...]
```

### Ключові прапорці командного рядка

| Прапорець | Опис та застосування |
| :--- | :--- |
| `--root=PATH` | Застосувати правила до альтернативної кореневої файлової системи (наприклад, `--root=/mnt/target` при створенні образів ОС) |
| `--cat-config` | Вивести злитий підсумковий конфігураційний маніфест із розкриттям перекриттів без модифікації файлів даних |

## Специфікація записів у системних файлах бази даних

При виконанні `systemd-sysusers` у системні файли бази даних вносяться такі структуровані зміни:

1. **/etc/passwd**: Додається рядок формату:
   ```text
   name:x:UID:GID:GECOS:home:shell
   ```
2. **/etc/group**: Додається рядок формату:
   ```text
   groupname:x:GID:member1,member2
   ```
3. **/etc/shadow**: Додається запечатаний рядок формату:
   ```text
   name:!:19000:0:99999:7:::
   ```
4. **/etc/gshadow**: Додається рядок формату:
   ```text
   groupname:!::member1,member2
   ```

### Атомарність запису та запобігання пошкодженням

Для уникнення станів гонки та пошкодження бази даних під час аварійного вимкнення живлення `systemd-sysusers` не редагує файли напряму. Вона створює тимчасовий файл (наприклад, `/etc/passwd.tmp`), записує оновлений вміст, викликає системний виклик `fsync()` для примусового скидання буферів на диск і виконує атомарне перейменування через `rename()`.
