# 📋 Довідник системного та ядерного API hrtimers

Цей довідник надає вичерпний опис інтерфейсів програмування підсистеми `hrtimers` у ядрі Linux (`<linux/hrtimer.h>`) та відповідних системних викликів простору користувача (`<sys/timerfd.h>`).

## Архітектурний контракт підсистеми hrtimers

Підсистема `hrtimers` побудована на чіткому поділі між простором ядра та простором користувача. Всередині ядра таймер є об'єктом прямого відстеження червоно-чорним деревом `timerqueue`, де кожна операція додавання чи скасування супроводжується синхронізацією з апаратними пристроями подій часу (`clock_event_device`). Для простору користувача ядро надає абстракцію файлового дескриптора `timerfd`, який дозволяє обробляти високоточні таймери безпосередньо у неблокуючих циклах вводу-виводу.

## Ядерний інтерфейс (<linux/hrtimer.h>)

### 1. Головні структури даних ядра

#### Структура `struct hrtimer`
Являє собою базову одиницю обліку високоточного таймера у ядрі:

```c
struct hrtimer {
    struct timerqueue_node  node;
    ktime_t                 _softexpires;
    enum hrtimer_restart    (*function)(struct hrtimer *);
    struct hrtimer_clock_base *base;
    u8                      state;
    u8                      is_rel;
    u8                      is_soft;
    u8                      is_hard;
};
```

Детальний опис функціонального призначення кожного поля:

- **`node`**: Внутрішній вузол черги `struct timerqueue_node`, який огортає вузол червоно-чорного дерева `struct rb_node` та містить поле `expires` — **пізню** межу спрацьовування (`_softexpires` плюс таймерний люфт). Саме за `node.expires` дерево відсортоване й за ним програмують апаратуру.
- **`_softexpires`**: **Рання** межа — бажаний наносекундний час спрацьовування таймера (`ktime_t`), запрошений при виклику `hrtimer_start()`. Без люфту дорівнює `node.expires`.
- **`function`**: Вказівник на функцію зворотного виклику (callback), яка буде автоматично виконана ядром, коли поточний час `ktime_get()` досягне або перевищить значення `_softexpires`.
- **`base`**: Вказівник на базу часу `struct hrtimer_clock_base`, яка належить конкретному процесорному ядру і містить червоно-чорне дерево, у якому лежить цей таймер.
- **`state`**: Маска поточного стану таймера у підсистемі:
  - `HRTIMER_STATE_INACTIVE` (`0x00`): Таймер перебуває у неактивному стані і не включений до жодного дерева.
  - `HRTIMER_STATE_ENQUEUED` (`0x01`): Таймер успішно доданий у дерево і чекає наступного переривання.
- **`is_soft` / `is_hard`**: Прапорці, що визначають контекст виконання `function`:
  - `is_hard = 1`: Функція зворотного виклику буде виконана безпосередньо в атомарному контексті апаратного переривання (hardirq) з вимкненими перериваннями процесора.
  - `is_soft = 1`: Функція зворотного виклику буде передана на виконання в контекст програмних переривань `HRTIMER_SOFTIRQ` (у звичайному ядрі — здебільшого на виході з переривання, під завалом softirq'ів — у нитці `ksoftirqd/X`; у PREEMPT_RT — завжди в контексті нитки).

#### Структура `struct hrtimer_clock_base`
Описує базу часу для конкретної часової системи на одному процесорному ядрі:

```c
struct hrtimer_clock_base {
    struct hrtimer_cpu_base *cpu_base;
    unsigned int            index;
    clockid_t               clockid;
    seqcount_raw_spinlock_t seq;
    struct hrtimer          *running;
    struct timerqueue_head  active;
    ktime_t                 (*get_time)(void);
    ktime_t                 offset;
};
```

Поля структури забезпечують роботу сортованого дерева:

- **`cpu_base`**: Вказівник на загальнопроцесорну структуру `struct hrtimer_cpu_base`, що об'єднує всі бази часу цього ядра.
- **`index`**: Унікальний числовий індекс бази часу в масиві.
- **`clockid`**: Системний ідентифікатор годинника (`CLOCK_MONOTONIC`, `CLOCK_REALTIME` тощо).
- **`running`**: Вказівник на таймер цієї бази, чий callback виконується просто зараз на цьому процесорному ядрі.
- **`active`**: Голова черги `struct timerqueue_head`, яка впорядковує вузли у червоно-чорному дереві і зберігає кешований вказівник на найлівіший вузол `rb_leftmost`.
- **`get_time`**: Вказівник на ядерну функцію зчитування поточного часу (наприклад, `ktime_get()`).
- **`offset`**: Системний зсув цього годинника відносно монотонного часу.

**Про версії.** Наведена форма — це ядра 5.x та 6.1x. У найновіших ядрах поля `index` і `clockid` стали `const` (базу створюють раз і назавжди), `active` дістав тип `struct timerqueue_linked_head`, з'явилося поле `expires_next` — абсолютний час найближчої події саме цієї бази, — а вказівника `get_time` у базі більше немає. Порядок роботи підсистеми ці зміни не міняють: усе, описане далі, справедливе для обох поколінь.

### 2. Функції ініціалізації та управління

```c
void hrtimer_setup(struct hrtimer *timer,
                   enum hrtimer_restart (*function)(struct hrtimer *),
                   clockid_t clock_id, enum hrtimer_mode mode);
```

Функція `hrtimer_setup` готує структуру `struct hrtimer` до роботи: обнуляє внутрішні вузли, зв'язує таймер із вказаною базою часу, виставляє режим відліку та записує функцію зворотного виклику.

**Про версії.** Довгі роки ініціалізацію робила пара кроків — `void hrtimer_init(struct hrtimer *timer, clockid_t clock_id, enum hrtimer_mode mode)` і окреме присвоєння `timer->function = …`. Присвоєння в обхід ініціалізатора було джерелом помилок (таймер із порожнім `function`), тому обидва кроки звели в один виклик: `hrtimer_setup()` доступний уже в ядрі 6.14, а у 6.15 `hrtimer_init()` з ядра прибрано зовсім. Код для старіших ядер тримає обидві форми під `#if LINUX_VERSION_CODE`.

#### Допустимі значення аргументу `clock_id`:

1. **`CLOCK_MONOTONIC`**: Монотонний годинник, відлік якого починається від моменту завантаження операційної системи. Цей годинник гарантує відсутність стрибків назад або уперед при корекціях часу системним адміністратором або демоном NTP.
2. **`CLOCK_REALTIME`**: Календарний системний час. Може піддаватися стрибкоподібним змінам при оновленні системного годинника через `settimeofday()` чи синхронізації NTP.
3. **`CLOCK_BOOTTIME`**: Монотонний годинник, який, на відміну від `CLOCK_MONOTONIC`, продовжує відлік часу під час перебування операційної системи у глибокому стані сну (suspend/hibernate).
4. **`CLOCK_TAI`**: Міжнародний атомний час. Не містить стрибків високосних секунд, що важливо для телекомунікаційних систем.

Інших значень підсистема не приймає: `hrtimer` можна завести лише на один із цих чотирьох годинників (у масиві `clock_base[]` кожному з них відповідає пара баз — «жорстка» й «м'яка», за контекстом виконання callback). Зокрема `CLOCK_MONOTONIC_RAW` (сирий апаратний час `clocksource` без фазового підлаштування NTP) бази з чергою таймерів не має — його лише читають через `clock_gettime()`.

#### Допустимі значення аргументу `mode`:

- `HRTIMER_MODE_REL`: Час спрацьовування інтерпретується як відносний інтервал від поточного моменту (`now + offset`).
- `HRTIMER_MODE_ABS`: Час спрацьовування інтерпретується як абсолютна позначка `ktime_t`.
- `HRTIMER_MODE_HARD`: Примусово виконувати callback у суворому контексті апаратного переривання.
- `HRTIMER_MODE_SOFT`: Примусово виконувати callback у контексті програмних переривань `HRTIMER_SOFTIRQ`.

### 3. Запуск та модифікація таймерів

```c
void hrtimer_start(struct hrtimer *timer, ktime_t tim, const enum hrtimer_mode mode);
```

Функція `hrtimer_start` активує таймер і вставляє його у сортоване червоно-чорне дерево відповідної бази часу.

- Якщо таймер вже знаходився у черзі, він попередньо вилучається з дерева і додається на нову позицію.
- Якщо обчислений час спрацьовування є найближчим серед усіх активних таймерів цього ядра, ядро негайно перепрограмовує апаратний `clock_event_device` викликом `tick_program_event()`.

```c
void hrtimer_start_range_ns(struct hrtimer *timer, ktime_t tim, u64 delta_ns, const enum hrtimer_mode mode);
```

Розширена версія запуску таймера, яка враховує припустимий таймерний люфт `delta_ns` (Timer Slack). Дозволяє ядру групувати спрацьовування цього таймера з іншими в інтервалі `[tim; tim + delta_ns]` для зниження кількості переривань процесора та збереження енергії.

### 4. Скасування та перевірка стану

```c
int hrtimer_cancel(struct hrtimer *timer);
```

Функція `hrtimer_cancel` безпечно вилучає таймер з підсистеми.

- Якщо таймер знаходиться у дереві, він вилучається з черги.
- Якщо функція зворотного виклику таймера прямо зараз виконується на іншому процесорному ядрі, `hrtimer_cancel` блокує поточний потік виконання й чекає на повне завершення callback.
- **Обмеження контексту**: Функцію не можна викликати з атомарного контексту hardirq/softirq для таймерів, чий callback може виконуватися на іншому ядрі, щоб уникнути взаємного блокування (deadlock).
- **Повертає**: `0`, якщо таймер був неактивним; `1`, якщо таймер був успішно скасований до його спрацьовування.

```c
int hrtimer_try_to_cancel(struct hrtimer *timer);
```

Неблокуючий варіант скасування таймера.

- **Повертає**: `0` — таймер неактивний; `1` — успішно скасовано; `-1` — callback виконується прямо зараз на іншому ядрі (скасування не відбулося).

```c
bool hrtimer_active(const struct hrtimer *timer);
```

Перевіряє, чи є таймер взведеним або чи виконується його callback просто зараз. Повертає `true`, якщо активний, і `false`, якщо неактивний.

### 5. Обробка періодичних таймерів

```c
u64 hrtimer_forward(struct hrtimer *timer, ktime_t now, ktime_t interval);
```

Пересуває час спрацьовування періодичного таймера на майбутнє без накопичення похибки. Зазвичай викликається всередині функції зворотного виклику.

- **Параметри**: `now` — поточний час `ktime_get()`; `interval` — період повторення.
- **Алгоритм**: Зсуває вперед **обидві** межі таймера — і `_softexpires`, і `node.expires` — на ціле число періодів, доки час спрацьовування не опиниться після `now`. Пропущені періоди в такий спосіб не накопичуються як борг: сітка лишається кратною `interval`, просто кілька її вузлів проминули.
- **Повертає**: Кількість інтервалів, що минули (overruns). Значення `1` означає нормальну роботу без пропусків; `0` повертається, коли функцію викликали ще до моменту спрацьовування (`now` раніший за `node.expires`) — тоді таймер не рухається взагалі.

```c
u64 hrtimer_forward_now(struct hrtimer *timer, ktime_t interval);
```

Зручна обгортка над `hrtimer_forward`, яка автоматично зчитує поточний час через `ktime_get()`.

---

### 6. Значення повернення функції зворотного виклику

Функція `function` мусить мати сигнатуру:

```c
enum hrtimer_restart (*function)(struct hrtimer *timer);
```

Допустимі значення повернення:

- `HRTIMER_NORESTART`: Таймер одноразовий і завершив свою роботу. Ядро не перевставляє його у дерево.
- `HRTIMER_RESTART`: Таймер є періодичним і має бути перезапущений. Перед поверненням функція зобов'язана викликати `hrtimer_forward()` або `hrtimer_forward_now()`.

## Інтерфейс простору користувача (<sys/timerfd.h>)

Системні виклики `timerfd` створюють файловий дескриптор, який сигналізує про спрацьовування `hrtimer` у просторі користувача.

### 1. Системний виклик timerfd_create

```c
int timerfd_create(int clockid, int flags);
```

Створює новий екземпляр таймера й повертає його файловий дескриптор.

- **`clockid`**: `CLOCK_REALTIME`, `CLOCK_MONOTONIC`, `CLOCK_BOOTTIME`, а також `CLOCK_REALTIME_ALARM` і `CLOCK_BOOTTIME_ALARM` — «будильники», які здатні підняти систему з режиму сну (потрібна можливість `CAP_WAKE_ALARM`; за ними стоїть не чистий `hrtimer`, а підсистема `alarmtimer` поверх апаратного RTC).
- **`flags`**:
  - `TFD_NONBLOCK`: Встановити режим неблокуючого вводу-виводу (`O_NONBLOCK`).
  - `TFD_CLOEXEC`: Автоматично закривати дескриптор при виклику `execve` (`FD_CLOEXEC`).
- **Повертає**: Невід'ємний файловий дескриптор або `-1` при помилці (з установкою `errno`).

---

### 2. Системний виклик timerfd_settime

```c
int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *old_value);
```

Встановлює період та час спрацьовування таймера.

```c
struct timespec {
    time_t tv_sec;  /* секунди */
    long   tv_nsec; /* наносекунди */
};

struct itimerspec {
    struct timespec it_interval; /* Період повторення (0 = одноразовий) */
    struct timespec it_value;    /* Час першого спрацьовування (0 = деактивація) */
};
```

- **`flags`**:
  - `0`: `it_value` інтерпретується як відносний час від поточного моменту.
  - `TFD_TIMER_ABSTIME`: `it_value` інтерпретується як абсолютне значення часу `clockid`.
  - `TFD_TIMER_CANCEL_ON_SET`: Якщо `clockid` дорівнює `CLOCK_REALTIME`, таймер буде скасовано з помилкою `ECANCELED`, якщо відбудеться стрибок системного годинника через NTP.
- **`old_value`**: Якщо не `NULL`, ядро записує сюди попередні налаштування таймера.
- **Повертає**: `0` при успіху, `-1` при помилці.

---

### 3. Системний виклик read

```c
ssize_t read(int fd, void *buf, size_t count);
```

Зчитує стан спрацьовування таймера.

- Розмір буфера `count` має бути не меншим за 8 байтів (`sizeof(uint64_t)`).
- При успішному зчитуванні ядро записує у буфер 64-бітне ціле число `uint64_t` — **кількість спрацьовувань (overrun count)**, що відбулися з моменту останнього читання `read()`.
- Якщо таймер ще жодного разу не спрацював:
  - у блокуючому режимі виклик засинає до першого спрацьовування;
  - у неблокуючому режимі (`TFD_NONBLOCK`) повертає `-1` з `errno = EAGAIN`.

---

### 4. Системний виклик timerfd_gettime

```c
int timerfd_gettime(int fd, struct itimerspec *curr_value);
```

Записує у `curr_value` поточний період `it_interval` та час, що залишився до наступного спрацьовування `it_value`. Якщо таймер деактивовано, `it_value` міститиме нулі.

---

### 5. Повна матриця помилок системних викликів timerfd

| Помилка (`errno`) | Причина виникнення у системі | Метод усунення у коді |
| :--- | :--- | :--- |
| `EINVAL` | Недійсний `clockid`, невідомі прапорці або `tv_nsec >= 1000000000` | Перевірити діапазон наносекунд `[0; 999999999]` |
| `EMFILE` | Перевищено ліміт відкритих файлових дескрипторів процесу (`RLIMIT_NOFILE`) | Збільшити ліміт дескрипторів або закрити невикористовувані |
| `ENFILE` | Перевищено системний ліміт відкритих файлів ядра | Збільшити `/proc/sys/fs/file-max` |
| `EAGAIN` | Виклик `read()` на неблокуючому `timerfd`, який ще не спрацював | Чекати подій через `epoll_wait()` |
| `ECANCELED` | Встановлено `TFD_TIMER_CANCEL_ON_SET` і відбувся стрибок системного часу | Переініціалізувати таймер після коригування часу |
| `EBADF` | Передано недійсний файловий дескриптор `fd` | Перевірити відкриття дескриптора |
| `EFAULT` | Вказівник `new_value` або `old_value` вказує на недоступну пам'ять | Передати буфер на стеку або в динамічній пам'яті |
