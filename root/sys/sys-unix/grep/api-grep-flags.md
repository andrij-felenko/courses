# 📋 Інтерфейс утиліти grep: опції, діалекти, змінні оточення та коди виходу

Утиліта `grep` є стандартизованим POSIX-інструментом для пошуку текстових фрагментів за заданими регулярними виразами або точними підрядками. За півстоліття еволюції інтерфейс командного рядка розширився десятками прапорців, які керують вибором рушія зіставлення, форматуванням вихідного потоку, глибиною обходу файлових ієрархій та взаємодією з пам'яттю операційної системи.

Нижче наведено систематизований довідник параметрів, кодів завершення, специфікаторів контексту та змінних середовища для реалізацій POSIX та GNU `grep`.

---

### Синопсис виклику та структура аргументів

Командний рядок утиліти приймає шаблони або як позиційні аргументи, або через спеціалізовані прапорці введення:

```text
grep [ОПЦІЇ] ШАБЛОН [ФАЙЛ...]
grep [ОПЦІЇ] -e ШАБЛОН... [-f ФАЙЛ_ШАБЛОНІВ...] [ФАЙЛ...]
```

Якщо перелік файлів не вказано, або якщо замість імені файлу передано символ дефіса `-`, утиліта зчитує дані зі стандартного входу (дескриптор `0`).

---

### Коди завершення (Exit Statuses) та поведінка в конвеєрах

Код повернення процесу в операційну систему відображає не лише технічну успішність виконання системних викликів, а й семантичний результат операції пошуку:

- **Код `0` (Успіх / Match):** Знайдено щонайменше один відповідний рядок (або байт при використанні тихих режимів).
- **Код `1` (Не знайдено / No Match):** Сканування завершено успішно без системних збоїв, але жоден рядок вхідного потоку не задовольнив критерій пошуку. Також повертається при скануванні порожніх файлів.
- **Код `2` (Синтаксична або системна помилка):** Виникає при неможливості відкрити вхідний файл (помилки `ENOENT`, `EACCES`), некоректному синтаксисі регулярного виразу або передачі невідомих опцій.

У командних оболонках Unix результат роботи `grep` часто аналізується умовними конструкціями. При об'єднанні утиліти в конвеєр слід враховувати, що стандартний статус завершення конвеєра повертає код останньої команди. Для перевірки коду самого `grep` усередині ланцюжка процесів утиліту використовують разом із масивом `${PIPESTATUS[@]}` у Bash або директивою `set -o pipefail`.

### Вибір рушія та діалекту регулярних виразів

Діалект регулярного виразу визначає, як саме інтерпретуються символи пунктуації та оператори групування під час компіляції шаблону в скінченний автомат:

- **`-G`, `--basic-regexp` (Базові регулярні вирази, BRE):** Поведінка за замовчуванням згідно зі стандартом POSIX.1-2017. У цьому режимі символи дужок `( )` та фігурних дужок `{ }` вважаються звичайними літералами тексту. Для активації їхніх спеціальних функцій (створення груп або визначення діапазонів повторень) потрібне обов'язкове екранування зворотним слешем: `\( \)`, `\{m,n\}`.
- **`-E`, `--extended-regexp` (Розширені регулярні вирази, ERE):** Вмикає синтаксис розширених виразів, еквівалентний класичній утиліті `egrep`. Усі метасимволи `( )`, `{ }`, `+`, `?`, `|` активні без зворотних слешів. Шаблон компілюється у швидкий детермінований скінченний автомат (DFA), що гарантує лінійний час виконання `O(N)`.
- **`-F`, `--fixed-strings` (Фіксовані рядки):** Вимикає компіляцію регулярних виразів (аналог утиліти `fgrep`). Усі символи шаблону розглядаються як точні байти. Для одного шаблону застосовується алгоритм Боєра-Мура, для множини шаблонів — автомат Ахо-Корасік.
- **`-P`, `--perl-regexp` (Perl-сумісні вирази, PCRE2):** Специфічне для GNU розширення, що підключає зовнішню бібліотеку PCRE2. Дозволяє використовувати нежадібні квантифікатори `.*?`, випереджувальні та ретроспективні перевірки `(?=...)`, `(?<=...)` та атомарні групи. Рушій працює через механізм зворотного повернення (backtracking).

### Керування зіставленням (Matching Control)

Параметри цієї групи визначають логіку порівняння шаблону з байтами вхідного потоку:

- **`-e ШАБЛОН`, `--regexp=ШАБЛОН`:** Явна передача шаблону. Обов'язкова для пошуку рядків, що починаються з символу дефіса `-`, які інакше сприймаються парсером опцій як прапорці. Дозволяє передавати кілька шаблонів одночасно — рядок вважається знайденим, якщо відповідає хоча б одному з них.
- **`-f ФАЙЛ`, `--file=ФАЙЛ`:** Зчитує перелік пошукових шаблонів із вказаного текстового файлу (один шаблон на рядок).
- **`-i`, `--ignore-case`:** Регістронезалежний пошук. Переводить порівняння символів у режим збігу без урахування регістру згідно з поточною системною локаллю.
- **`-v`, `--invert-match`:** Інвертує результат перевірки. Пропускає лише ті рядки, які **НЕ** збіглися із заданим шаблоном.
- **`-w`, `--word-regexp`:** Збіг зараховується лише тоді, коли знайдений фрагмент утворює ціле слово — тобто оточений початком/кінцем рядка або символами, що не належать до словесних знаків (букв, цифр, підкреслень).
- **`-x`, `--line-regexp`:** Вимагає точного збігу шаблону з усім рядком від першого символу до кінцевого `\n`.

### Форматування та фільтрація вихідного потоку (Output Control)

Прапорці керування виводом дозволяють адаптувати формат представлення даних для читання людиною або автоматизованого парсингу скриптами:

- **`-o`, `--only-matching`:** Друкує виключно знайдений фрагмент рядка замість усього рядка цілком. Якщо один рядок містить кілька входжень шаблону, кожне друкується на окремому новому рядку.
- **`-n`, `--line-number`:** Додає порядковий номер рядка у файлі (починаючи з 1) перед кожним знайденим записом, відокремлюючи його двокрапкою `:`.
- **`-b`, `--byte-offset`:** Друкує абсолютне зміщення вхідного потоку в байтах (починаючи з 0) перед кожним знайденим фрагментом.
- **`-c`, `--count`:** Пригнічує друк самих рядків і виводить лише загальне число знайдених збігів для кожного вхідного файлу.
- **`-l`, `--files-with-matches`:** Виводить лише імена файлів, що містять хоча б один збіг. Читання кожного окремого файлу зупиняється на першому знайденому входженні.
- **`-L`, `--files-without-match`:** Виводить імена файлів, у яких не виявлено жодного збігу.
- **`-m КІЛЬКІСТЬ`, `--max-count=КІЛЬКІСТЬ`:** Припиняє читання поточного файлу після знаходження вказаної кількості рядків. Заощаджує операції дискового введення-виведення на гігабайтних масивах.
- **`-q`, `--quiet`, `--silent`:** Повністю пригнічує стандартний вивід. Процес негайно завершується з кодом `0` при виявленні першого збігу.
- **`-s`, `--no-messages`:** Пригнічує виведення системних повідомлень про помилки доступу до файлів у потік `stderr`.
- **`-H`, `--with-filename`:** Завжди додає префікс імені файлу перед кожним знайденим рядком.
- **`-h`, `--no-filename`:** Примусово пригнічує друк імен файлів у вихідному потоці.
- **`--line-buffered`:** Вмикає порядкову буферизацію стандартного виводу замість блокової, що дозволяє передавати рядки в конвеєри реального часу без затримок.

### Контекстні вікна (Context Control)

Для аналізу оточення помилок та структурованих записів використовуються прапорці контексту:

- **`-B КІЛЬКІСТЬ`, `--before-context=КІЛЬКІСТЬ`:** Друкує вказану кількість рядків, що передують рядку зі збігом. Рядки контексту відокремлюються від номера рядка дефісом `-` замість двокрапки `:`.
- **`-A КІЛЬКІСТЬ`, `--after-context=КІЛЬКІСТЬ`:** Друкує вказану кількість рядків після рядка зі збігом.
- **`-C КІЛЬКІСТЬ`, `--context=КІЛЬКІСТЬ`:** Друкує симетричне вікно рядків до і після збігу.
- **`--group-separator=МАРКЕР`:** Замінює стандартний рядок-роздільник `--` між несуміжними блоками контексту на вказаний текст.
- **`--no-group-separator`:** Вимикає виведення маркерів розділення контекстних блоків.

### Рекурсивний обхід та фільтрація дерева каталогів

При переході до пакетного аналізу каталогів використовуються параметри рекурсивного сканування:

- **`-r`, `--recursive`:** Фізичний рекурсивний спуск. Сканує всі каталоги, але ігнорує символічні посилання, що вказують на каталоги.
- **`-R`, `--dereference-recursive`:** Логічний рекурсивний спуск. Розкриває та обходить усі символічні посилання на каталоги, контролюючи цикли за таблицею inode.
- **`--include=ГЛОБ`:** Обмежує пошук лише тими файлами, чиє ім'я відповідає glob-масці.
- **`--exclude=ГЛОБ`:** Пропускає файли з відповідною glob-маскою.
- **`--exclude-dir=ГЛОБ`:** Повністю виключає зі сканування каталоги, що відповідають масці (наприклад, `.git`, `node_modules`).
- **`-I`:** Автоматично ігнорує бінарні файли, вважаючи їх такими, що не містять збігів.
- **`-a`, `--text`:** Примусово обробляє будь-які файли як звичайний текст.

### Змінні середовища (Environment Variables)

Поведінка утиліти суттєво модулюється змінними оточення операційної системи:

- **`LC_ALL`, `LC_CTYPE`:** Визначають кодування тексту та таблиці еквівалентності символів. У локалях UTF-8 вмикається повноцінна валідація багатобайтових послідовностей, що створює помітні обчислювальні накладні витрати. Перемикання на `LC_ALL=C` прискорює сканування в 5–10 разів за рахунок переходу на сирий 8-бітний ASCII-режим.
- **`POSIXLY_CORRECT`:** Вмикає суворий режим стандарту POSIX. Примушує парсер аргументів GNU припиняти розбір опцій на першому не-опціональному позиційному аргументі.
- **`GREP_COLORS`:** Налаштовує колірні ANSI-послідовності для виділення знайдених фрагментів, номерів рядків та імен файлів при використанні параметра `--color=auto`.
