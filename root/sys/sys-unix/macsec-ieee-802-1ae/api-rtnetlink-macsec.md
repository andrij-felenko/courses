# 📋 Інтерфейс Netlink та атрибути IFLA_MACSEC для управління MACsec

У ядрі Linux програмування, створення та динамічна конфігурація віртуальних пристроїв MACsec здійснюється через системний сокетний інтерфейс **Netlink** (`NETLINK_ROUTE`) за допомогою стандартизованих повідомлень `RTM_NEWLINK`, `RTM_DELLINK`, `RTM_GETLINK` та `RTM_SETLINK`. Підсистема MACsec реалізована як модульний драйвер `macsec.ko`, що реєструється у сервісі інформації про посилання `rtnl_link_ops`. Всі специфічні атрибути конфігурації передаються всередині вкладеного бінарного контейнера `IFLA_INFO_DATA`, коли атрибут типу посилання (`IFLA_INFO_KIND`) встановлено в значення рядка `"macsec"`.

Публічний бінарний контракт, числові константи, атрибути конфігурації та вкладені структури статистики визначені в офіційному заголовковому файлі ядра `<linux/if_macsec.h>`.

## 1. Головні атрибути конфігурації пристрою (IFLA_MACSEC_*)

Під час створення нового віртуального пристрою MACsec або зміни параметрів наявного інтерфейсу повідомлення Netlink містить атрибут `IFLA_INFO_DATA`, усередині якого упаковується послідовність атрибутів `IFLA_MACSEC_*`.

Кожен атрибут складається з 4-байтного заголовка `struct rtattr` (де вказуються тип та довжина) та відповідного блоку даних. Усі атрибути вимагають суворого 4-байтного вирівнювання в пам'яті.

| Атрибут Netlink | Тип даних | Опис, бінарний формат та припустимі значення |
| :--- | :--- | :--- |
| `IFLA_MACSEC_SCI` | `u64` | 64-бітний унікальний ідентифікатор Secure Channel Identifier (SCI). Складається з 48-бітної MAC-адреси передавача у мережевому порядку байтів (Big-Endian) та 16-бітного номера порта (`MAC + Port`). |
| `IFLA_MACSEC_PORT` | `u16` | Номер порта системи в мережі MACsec. За замовчуванням дорівнює `1`. Використовується для автоматичного формування SCI на основі MAC-адреси базового пристрою. |
| `IFLA_MACSEC_ICV_LEN` | `u8` | Довжина вектора перевірки цілісності ICV (Integrity Check Value) у байтах. Стандартне значення за замовчуванням — `16` (128 біт). Стандарт дозволяє значення від 8 до 16 байт. |
| `IFLA_MACSEC_CIPHER_SUITE` | `u64` | 64-бітний ідентифікатор алгоритму шифрування. Включає унікальний ідентифікатор IEEE OID. |
| `IFLA_MACSEC_ENCRYPT` | `u8` | Прапорець активації шифрування вихідного трафіку TX. `0` — шифрування вимкнено (режим захисту цілісності Integrity-only); `1` — увімкнено повне AES-GCM шифрування корисного навантаження. |
| `IFLA_MACSEC_PROTECT` | `u8` | Прапорець захисту вхідного трафіку. `0` — пропускати незахищені кадри; `1` — вимагати наявність обов'язкового криптографічного заголовка SecTAG та підпису ICV. |
| `IFLA_MACSEC_ENCODING_SA` | `u8` | Індекс активної вихідної асоціації захисту TX SA (`0`, `1`, `2` або `3`). Визначає, який саме слот ключа SAK застосовується ядром для шифрування вихідних кадрів. |
| `IFLA_MACSEC_WINDOW` | `u32` | Розмір вікна захисту від повторного відтворення кадрів (Replay Protection Window) в пакетах. `0` — вимоги суворого порядку; `>0` — розмір допустимого розсинхрону кадрів. |
| `IFLA_MACSEC_VALIDATION` | `u8` | Режим валідації вхідних кадрів RX прийомною стороною. |
| `IFLA_MACSEC_INC_SCI` | `u8` | Прапорець примусового включення 8-байтного SCI в заголовок SecTAG на дроті. `1` — завжди додавати SCI; `0` — вилучати SCI для економії оверхеду, якщо порт дорівнює 1. |
| `IFLA_MACSEC_ES` | `u8` | Прапорець End Station: увімкнення біта ES у заголовку SecTAG для позначення того, що відправник є кінцевим хостом, а не комутатором. |
| `IFLA_MACSEC_SCB` | `u8` | Прапорець Single Copy Broadcast: увімкнення біта SCB у заголовку SecTAG для роботи з груповими кадрами. |
| `IFLA_MACSEC_OFFLOAD` | `u8` | Режим апаратного розвантаження обчислень шифрування на мережеву карту. |

### Деталізація криптографічних сюїт (`IFLA_MACSEC_CIPHER_SUITE`)

Ядро Linux підтримує стандартизовані криптографічні сюїти, визначені поправками IEEE 802.1AE. Передача непідтримуваного значення `CIPHER_SUITE` призводить до повернення помилки `EINVAL` від ядра.

:::tabs
```c
/* Константи заголовочного файла ядра <linux/if_macsec.h> */
#define MACSEC_CIPHER_ID_GCM_AES_128     0x0080C20001000001ULL
#define MACSEC_CIPHER_ID_GCM_AES_256     0x0080C20001000002ULL
#define MACSEC_CIPHER_ID_GCM_AES_XPN_128 0x0080C20001000003ULL
#define MACSEC_CIPHER_ID_GCM_AES_XPN_256 0x0080C20001000004ULL
```
```cpp
// Ідіоматичні типи C++20 у просторі імен macsec::ciphers
#include <cstdint>

namespace macsec::ciphers {
    constexpr std::uint64_t gcm_aes_128     = 0x0080C20001000001ULL;
    constexpr std::uint64_t gcm_aes_256     = 0x0080C20001000002ULL;
    constexpr std::uint64_t gcm_aes_xpn_128 = 0x0080C20001000003ULL;
    constexpr std::uint64_t gcm_aes_xpn_256 = 0x0080C20001000004ULL;
}
```
:::

- **GCM-AES-128**: Базовий стандарт 802.1AE-2006. Використовує 128-бітні ключі SAK та 32-бітні лічильники пакетів `PN`.
- **GCM-AES-256**: Стандарт 802.1AEbn-2011. Забезпечує криптографічну міцність рівня 256 біт для високих вимог безпеки.
- **GCM-AES-XPN-128 / XPN-256**: Стандарт 802.1AEbw-2013 із розширеним 64-бітним лічильником пакетів (Extended Packet Number). Запобігає швидкому вичерпанню лічильника `PN` на швидкісних каналах 10G/40G/100G+.

### Семантика режимів валідації вхідних кадрів (`IFLA_MACSEC_VALIDATION`)

Атрибут `IFLA_MACSEC_VALIDATION` задає поведінку підсистеми ядра при отриманні кадрів від мережевої карти:

- `MACSEC_VALIDATE_DISABLED` (`0`): Перевірку цілісності ICV вимкнено. Ядро розпаковує заголовок SecTAG, але пропускає кадри без валідації підпису. Режим застосовується виключно для діагностики або пасивного моніторингу трафіку.
- `MACSEC_VALIDATE_CHECK` (`1`): М'який режим перевірки. Ядро перевіряє підпис ICV, якщо кадр містить SecTAG. При виявленні помилки ICV або простроченого `PN` ядро збільшує відповідні лічильники помилок (`InPktsInvalid`, `InPktsLate`), проте **не знищує** кадр, передаючи його вищим рівням.
- `MACSEC_VALIDATE_STRICT` (`2`): Суворий виробничий режим (за замовчуванням). Будь-який кадр із відсутнім SecTAG, невалідним підписом ICV або порушеним номерам `PN` **негайно знищується** у контексті переривання, запобігаючи проникненню підроблених пакетів у мережевий стек.

### Семантика режимів апаратного розвантаження (`IFLA_MACSEC_OFFLOAD`)

Атрибут `IFLA_MACSEC_OFFLOAD` переключає обробку криптографії між програмним модулем ядра та кремнієм мережевого адаптера:

- `MACSEC_OFFLOAD_OFF` (`0`): Апаратне розвантаження вимкнено. Обчислення AES-GCM виконуються програмно центральним процесором за допомогою Crypto API ядра та інструкцій AES-NI.
- `MACSEC_OFFLOAD_PHY` (`1`): Розвантаження передається на зовнішній трансивер фізичного рівня (PHY chip).
- `MACSEC_OFFLOAD_MAC` (`2`): Розвантаження виконується інтегрованим контролером MAC або сопроцесором SmartNIC (наприклад, NVIDIA ConnectX або Intel E810).

## 2. Конфігурація асоціацій захисту (SA) та ключів SAK

Додавання, зміна або видалення конкретних ключів шифрування SAK виконується шляхом передачі вкладеного атрибута `IFLA_MACSEC_SA_CONFIG` у повідомленні Netlink.

### Структура конфігурації TX SA (`MACSEC_SA_ATTR_*`)

Всередині контейнера `IFLA_MACSEC_SA_CONFIG` передається перелік атрибутів конкретного слота вихідної асоціації:

:::tabs
```c
/* Перелічення атрибутів SA в <linux/if_macsec.h> */
enum enum_macsec_sa_attrs {
    MACSEC_SA_ATTR_UNSPEC,
    MACSEC_SA_ATTR_AN,        /* u8: Номер асоціації (Association Number: 0..3) */
    MACSEC_SA_ATTR_ACTIVE,    /* u8: 1 = SA активна для шифрування, 0 = неактивна */
    MACSEC_SA_ATTR_PN,        /* u32 або u64 (для XPN): Початковий/поточний номер пакета */
    MACSEC_SA_ATTR_KEYID,     /* 16 байт: Ідентифікатор ключа (Key ID / CKN) */
    MACSEC_SA_ATTR_KEY,       /* 16/32 байти: Секретний ключ SAK (AES-128 або AES-256) */
    MACSEC_SA_ATTR_STATS,     /* Вкладений атрибут статистики цієї конкретної SA */
    MACSEC_SA_ATTR_PAD,
    __MACSEC_SA_ATTR_END,
};
```
```cpp
// Strong-typed enum class у C++20 для безпечної роботи з атрибутами Netlink
#include <cstdint>

enum class MacsecSaAttr : std::uint16_t {
    Unspec = 0,
    AssociationNumber, // MACSEC_SA_ATTR_AN (u8: 0..3)
    Active,            // MACSEC_SA_ATTR_ACTIVE (u8: 0 або 1)
    PacketNumber,      // MACSEC_SA_ATTR_PN (u32/u64)
    KeyId,             // MACSEC_SA_ATTR_KEYID (16B)
    KeyMaterial,       // MACSEC_SA_ATTR_KEY (16B/32B)
    Stats              // MACSEC_SA_ATTR_STATS
};
```
:::

### Конфігурація прийому RX SC та масиву RX SA (`MACSEC_RXSC_ATTR_*`)

Для прийому та розшифровки трафіку від віддалених хостів ядро повинно мати зареєстрований приймальний канал RX SC, який прив'язаний до SCI відправника. Контейнер `IFLA_MACSEC_RXSC_CONFIG` містить:

- `MACSEC_RXSC_ATTR_SCI`: `u64` значення SCI віддаленого хоста-відправника.
- `MACSEC_RXSC_ATTR_ACTIVE`: `u8` прапорець активності приймального каналу.
- `MACSEC_RXSC_ATTR_SA_CONFIG`: Вкладена конфігурація приймальної SA (містить `MACSEC_SA_ATTR_AN`, `MACSEC_SA_ATTR_KEYID`, `MACSEC_SA_ATTR_KEY` тощо).

## 3. Статистика та лічильники помилок MACsec у ядрі

Отримання інформації про стан та лічильники оброблених пакетів здійснюється шляхом надсилання Netlink-повідомлення `RTM_GETLINK`. Ядро повертає бінарні структури статистики, визначені у `<linux/if_macsec.h>`.

:::tabs
```c
/* Структури статистики ядра Linux у C */
struct macsec_dev_stats {
    __u64 OutPktsUntagged;  /* Пакетів відправлено без SecTAG (коли encrypt off) */
    __u64 InPktsUntagged;   /* Вхідних кадрів без SecTAG при validate strict */
    __u64 InPktsBadTag;     /* Вхідних кадрів із пошкодженим/невалідним заголовком SecTAG */
    __u64 InPktsUnknownSCI; /* Вхідних кадрів із невідомим SCI (немає відповідного RX SC) */
    __u64 InPktsNoSCI;      /* Вхідних кадрів без SCI, коли SCI вимагається */
    __u64 InPktsOverrun;    /* Кадрів відкинуто через перевищення апаратних лімітів */
};

struct macsec_rx_sc_stats {
    __u64 InPktsOK;         /* Успішно дешифрованих та автентифікованих кадрів */
    __u64 InPktsUnchecked;  /* Кадрів пропущено в режимі validate disabled */
    __u64 InPktsDelayed;    /* Кадрів отримано із запізненням, але в межах вікна Replay Window */
    __u64 InPktsLate;       /* Кадрів відкинуто через старий PN (поза межами Replay Window) */
    __u64 InPktsInvalid;    /* Кадрів відкинуто через помилку підпису ICV */
    __u64 InPktsNotValid;   /* Кадрів із невалідним ICV у режимі validate check */
};
```
```cpp
// Об'єктно-орієнтовані структури статистики в C++20
#include <cstdint>

struct MacsecDevStats {
    std::uint64_t out_pkts_untagged{0};
    std::uint64_t in_pkts_untagged{0};
    std::uint64_t in_pkts_bad_tag{0};
    std::uint64_t in_pkts_unknown_sci{0};
    std::uint64_t in_pkts_no_sci{0};
    std::uint64_t in_pkts_overrun{0};
};

struct MacsecRxScStats {
    std::uint64_t in_pkts_ok{0};
    std::uint64_t in_pkts_unchecked{0};
    std::uint64_t in_pkts_delayed{0};
    std::uint64_t in_pkts_late{0};
    std::uint64_t in_pkts_invalid{0};
    std::uint64_t in_pkts_not_valid{0};
};
```

## 4. Інтерфейси псевдофайлової системи sysfs та розширені розширення Netlink

Окрім сокетів `NETLINK_ROUTE`, підсистема MACsec експонує системну інформацію через псевдофайлову систему `/sys/class/net/`. Для кожного віртуального пристрою `macsec0` у каталозі `/sys/class/net/macsec0/` створюються стандартні вузли VFS, а також специфічні каталоги моніторингу:

- `/sys/class/net/macsec0/operstate`: Поточний операційний стан пристрою (`up`, `down`, `lowerlayerdown`).
- `/sys/class/net/macsec0/lower/`: Символічне посилання на каталог базового фізичного мережевого адаптера (наприклад `eth0`).
- `/sys/class/net/macsec0/statistics/`: Стандартні лічильники пристрою (`rx_packets`, `tx_packets`, `rx_bytes`, `tx_bytes`, `rx_errors`, `tx_errors`), які інтегровано у загальний підрахунок `struct net_device_stats`.

### Отримання розширених описових помилок (NETLINK_EXT_ACK)

При програмуванні Netlink сокетів для MACsec рекомендовано вмикати механізм розширених сповіщень про помилки ядра **`NETLINK_EXT_ACK`**. Це виконується за допомогою системного виклику `setsockopt()`:

:::tabs
```c
/* Увімкнення розширених сповіщень розбору Netlink у C */
int ext_ack = 1;
setsockopt(fd, SOL_NETLINK, NETLINK_EXT_ACK, &ext_ack, sizeof(ext_ack));
```
```cpp
// Увімкнення NETLINK_EXT_ACK у C++20
int ext_ack = 1;
::setsockopt(nl_sock.native_handle(), SOL_NETLINK, NETLINK_EXT_ACK, &ext_ack, sizeof(ext_ack));
```
:::

При увімкненому `NETLINK_EXT_ACK`, якщо ядро відхиляє конфігураційне повідомлення (наприклад, при спробі встановити `offload mac` на карту без підтримки `macsec_ops`), у відповіді `NLMSG_ERROR` передаються розширені атрибути:
- `NLMSGERR_ATTR_MSG`: Текстовий наочний рядок помилки ядра (наприклад, `"hardware offload not supported by device"`).
- `NLMSGERR_ATTR_OFFS`: Байтний зсув у наданому буфері, де саме ядро спотикнулося при розборі атрибутів `IFLA_MACSEC_*`.

## Інтерпретація статистичних лічильників при локалізації несправностей

Аналіз статистичних лічильників дає змогу інженерам та розробникам систем моніторингу здійснювати точну діагностику апаратних та криптографічних проблем у мережевому трафіку:

1. **Зростання `InPktsInvalid`**: Свідчить про те, що підпис ICV не збігається з розрахованим. Це є прямим симптомом криптографічного розсинхрону (хости на двох кінцях каналу мають різні ключі SAK у слоті `AN`) або виникнення пошкоджень бітів у фізичному оптичному/мідному кабелі.
2. **Зростання `InPktsLate`**: Вказує на відкидання кадрів через старий лічильник `PN`. Це виникає, коли мережа суттєво переупорядковує пакети (Packet Reordering), а розмір вікна `IFLA_MACSEC_WINDOW` на занадто малий для даного затримкового профілю з'єднання.
3. **Зростання `InPktsUnknownSCI`**: Виникає, коли на інтерфейс надходить зашифрований MACsec-трафік від нового хоста, для якого ядро ще не отримало конфігурацію RX SC через Netlink або MKA.
4. **Зростання `InPktsUntagged`**: Сигналізує про те, що сусідній хост відправляє незашифровані кадри без SecTAG, які віддаються в жертву і знищуються в суворому режимі `validate strict`.
