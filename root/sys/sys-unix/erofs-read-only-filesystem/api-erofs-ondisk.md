Цей довідник визначає точний бінарний формат дискових структур даних файлової системи EROFS, які використовуються драйвером ядра Linux (`fs/erofs/`) та утилітами простору користувача `erofs-utils`. Усі багатобайтові цілі числа в дискових структурах EROFS зберігаються строго в порядку від молодшого до старшого байта (Little Endian).

## Позиціонування Суперблоку (`erofs_super_block`)

Суперблок EROFS розміщується у першому фізичному блоці дискового тома (блок 0) з фіксованим зсувом 1024 байти від початку носія. Перші 1024 байти свідомо залишені порожніми для забезпечення сумісності з таблицями розділів x86 MBR, завантажувачами GRUB/U-Boot або специфічними заголовками файлових систем.

```
[ 0x0000..0x03FF: Порожня область / MBR / Bootloader (1024 байти) ]
[ 0x0400..0x047F: Структура erofs_super_block (128 байтів)        ]
[ 0x0480..0x0FFF: Зарезервовано / Початок блоку метаданих         ]
```

### Поля структури `erofs_super_block`

Низькорівнева структура суперблоку описує загальну геометрію образу, розташування дерева метаданих, кореневого індексного вузла та прапорці функціональних розширень. Ядро Linux читає цей блок під час виконання системного виклику `mount` і зберігає його в пам'яті у формі структури `erofs_sb_info`.

| Зсув (Байт) | Тип даних | Назва поля | Опис та механізм інтерпретації |
| :--- | :--- | :--- | :--- |
| `0x00` | `uint32_t` | `magic` | Магічна сигнатура EROFS: `0xE0F5E1E2`. Використовується ядром для ідентифікації образу. |
| `0x04` | `uint32_t` | `checksum` | Чексума структури суперблоку, обчислена алгоритмом CRC32c. |
| `0x08` | `uint32_t` | `feature_compat` | Бітова маска сумісних розширень. Ядро може монтувати том, навіть якщо не знає цих бітів. |
| `0x0C` | `uint8_t` | `blkszbits` | Логарифм розміру блоку за основою 2. Значення 12 відповідає розміру блоку 2^12 = 4096 байт. |
| `0x0D` | `uint8_t` | `sb_extslots` | Кількість додаткових слотів по 16 байтів: розмір суперблоку = 128 + `sb_extslots` × 16. |
| `0x0E` | `uint16_t` | `root_nid` | Ідентифікатор вузла (NID) кореневого каталогу `/`. Визначає зсув `root_nid * 32` в блоці метаданих. |
| `0x10` | `uint64_t` | `inos` | Загальна кількість дійсних індексних вузлів у томі (використовується для `statfs`). |
| `0x18` | `uint64_t` | `build_time` | Час генерації образу у секундах (POSIX Epoch timestamp). |
| `0x20` | `uint32_t` | `build_time_nsec` | Наносекундна частина часу генерації образу. |
| `0x24` | `uint32_t` | `blocks` | Загальна кількість 4 КБ фізичних блоків у даному томі. |
| `0x28` | `uint32_t` | `meta_blkaddr` | Фізичний номер блоку, з якого починається область метаданих та індексних вузлів. |
| `0x2C` | `uint32_t` | `xattr_blkaddr` | Фізичний номер блоку, де розташована глобальна таблиця спільних атрибутів (Shared xattr). |
| `0x30` | `uint8_t[16]`| `uuid` | 128-бітний UUID тома. |
| `0x40` | `uint8_t[16]`| `volume_name` | Назва тома (Volume Label). |
| `0x50` | `uint32_t` | `feature_incompat` | Бітова маска несумісних розширень. Якщо ядро не підтримує біт, монтування відхиляється (`-EINVAL`). |
| `0x54` | `uint16_t` | `available_compr_algs` | Бітова маска алгоритмів стиснення, ужитих в образі (у старих образах на цьому місці — `lz4_max_distance`). |
| `0x56` | `uint16_t` | `extra_devices` | Кількість додаткових пристроїв у таблиці multi-device. |
| `0x58` | `uint16_t` | `devt_slotoff` | Зсув слота таблиці пристроїв, у 128-байтових одиницях. |
| `0x5A..0x7F`| `uint8_t[38]`| `reserved` | Зарезервовані байти для майбутніх розширень дискового формату EROFS. |

## Формати індексних вузлів (Inodes)

Кожен файл, каталог, символьне посилання чи спеціальний об'єкт у EROFS описується індексним вузлом. Драйвер підтримує два класи індексних вузлів: компактний (`erofs_inode_compact`, 32 байти) та розширений (`erofs_inode_extended`, 64 байти). Використання 32-байтного компактного inode дозволяє розмістити до 128 індексних вузлів у одному 4-кілобайтному дисковому блоці. Власних міток часу такий вузол не має: `stat` віддає для нього спільну позначку `build_time` із суперблоку.

:::tabs
```c
/* Компактний індексний вузол EROFS (32 байти) */
struct erofs_inode_compact {
    uint16_t i_format;       /* Біти 0..0: 0=compact, 1=extended; Біти 1..3: layout */
    uint16_t i_xattr_icount; /* Кількість інлайн-атрибутів xattr */
    uint16_t i_mode;         /* Прапорці доступу та тип файла (POSIX mode_t) */
    uint16_t i_nlink;        /* Лічильник жорстких посилань */
    uint32_t i_size;         /* Розмір файла в байтах (до 4 ГБ) */
    uint32_t i_reserved;     /* Зарезервовано для вирівнювання */
    union {
        uint32_t raw_blkaddr;/* Фізична адреса першого блоку даних */
        uint32_t rdev;       /* Номер пристрою для mknod (major/minor) */
    } i_u;
    uint32_t i_ino;          /* Унікальний номер індексного вузла */
    uint16_t i_uid;          /* UID власника */
    uint16_t i_gid;          /* GID власника */
    uint32_t i_reserved2;    /* Зарезервовано; окремої чексуми вузол не має */
};

/* Розширений індексний вузол EROFS (64 байти) */
struct erofs_inode_extended {
    uint16_t i_format;       /* Біти 0..0: 1=extended; Біти 1..3: layout */
    uint16_t i_xattr_icount; /* Кількість інлайн-атрибутів xattr */
    uint16_t i_mode;         /* Прапорці доступу та тип файла */
    uint16_t i_reserved1;    /* Зарезервовано */
    uint64_t i_size;         /* Повний 64-бітний розмір файла в байтах */
    union {
        uint32_t raw_blkaddr;/* Фізична адреса першого блоку даних */
        uint32_t rdev;       /* Номер пристрою для special node */
    } i_u;
    uint32_t i_ino;          /* Унікальний номер індексного вузла */
    uint32_t i_uid;          /* Повний 32-бітний UID власника */
    uint32_t i_gid;          /* Повний 32-бітний GID власника */
    uint64_t i_mtime;        /* Час модифікації у секундах (POSIX Epoch) */
    uint32_t i_mtime_nsec;   /* Наносекунди часу модифікації */
    uint32_t i_nlink;        /* 32-бітний лічильник жорстких посилань */
    uint8_t  i_reserved2[16];/* Зарезервоване поле вирівнювання */
};
```

## Бітові прапорці компонування даних (`i_format` Layouts)

Формат розміщення вмісту файла на диску визначається бітами 1..3 у полі `i_format` (маска `0x000E`). Драйвер використовує це поле під час обробки виклику `erofs_map_blocks()`:

- **`EROFS_INODE_FLAT_PLAIN` (`0`)**: Файл не стискається. Усі блоки даних лежать на диску послідовно один за одним. Поле `raw_blkaddr` вказує на перший фізичний блок. Трансляція зсуву зводиться до `raw_blkaddr + (offset >> 12)`.
- **`EROFS_INODE_FLAT_INLINE` (`1`)**: Файл не стискається. Початкові блоки даних лежать послідовно на диску, а останній хвіст (менший за розмір блоку) упакований безпосередньо у той самий блок метаданих одразу після структури індексного вузла.
- **`EROFS_INODE_COMPRESSED_FULL` (`2`)**: Файл стиснений. Одразу за індексним вузлом розташовується заголовок стиснення `struct z_erofs_map_header`, за яким слідує масив індексів екстентів (Compressed Block Map).
- **`EROFS_INODE_CHUNK_BASED` (`3`)**: Файл ділиться на фрагменти (chunks) однакового розміру, кратного розміру блоку. Замість прямих адрес блоків індексний вузол містить масив записів `erofs_inode_chunk_index`: номер пристрою з таблиці multi-device плюс адреса блоку, звідки брати фрагмент.

## Заголовок карт стиснених екстентів (`z_erofs_map_header`)

Для файлів у режимі `EROFS_INODE_COMPRESSED_FULL` дискове картування стиснених блоків описується заголовком `z_erofs_map_header` та наступними за ним індексами кластерів:

| Зсув (Байт) | Тип даних | Назва поля | Опис |
| :--- | :--- | :--- | :--- |
| `0x00` | `uint32_t` | `h_fragmentoff` | Зсув хвостового фрагмента; у старих образах — зарезервоване поле вирівнювання |
| `0x04` | `uint16_t` | `h_advise` | Прапорці розкладки карти: `Z_EROFS_ADVISE_COMPACTED_2B`, `Z_EROFS_ADVISE_BIG_PCLUSTER_1/2`, `Z_EROFS_ADVISE_INLINE_PCLUSTER` |
| `0x06` | `uint8_t` | `h_algorithmtype` | Алгоритми стиснення (по 4 біти на голову): `0`=LZ4, `1`=LZMA (MicroLZMA), `2`=DEFLATE, `3`=Zstd |
| `0x07` | `uint8_t` | `h_clusterbits` | Розмір логічного кластера, закодований як приріст над розміром блоку (`0` → 4 КБ) |

Індекси екстентів у таблиці бувають двох типів:
- **Head entry** (`Z_EROFS_VLE_CLUSTER_TYPE_HEAD`): Вказує на початок нового стисненого фізичного кластера (pcluster) на диску, містить фізичний номер блоку та зсув декомпресії.
- **Non-head / Link entry**: Вказує, що даний логічний блок продовжує декомпресію попереднього фізичного кластера.

## Структури розширених атрибутів (Extended Attributes / xattr)

Для підтримки міток безпеки SELinux та довільних атрибутів користувача EROFS розрізняє **інлайн-атрибути** (Inline xattr) та **спільні атрибути** (Shared xattr).

Якщо `i_xattr_icount > 0`, одразу після структури inode (і перед inline-даними) розташовується заголовок `struct erofs_xattr_ibody_header`:

| Зсув (Байт) | Тип даних | Назва поля | Опис |
| :--- | :--- | :--- | :--- |
| `0x00` | `uint32_t` | `h_reserved` | Зарезервоване поле (у новіших ядрах — фільтр імен атрибутів) |
| `0x04` | `uint8_t` | `h_shared_count` | Кількість індексів у масиві спільних атрибутів (Shared xattr) |
| `0x05` | `uint8_t[7]`| `h_reserved2` | Вирівнювання заголовка до 12 байтів |
| `0x0C` | `uint32_t[]`| `h_shared_xattrs` | Масив 32-бітних індексів, що посилаються на таблицю `xattr_blkaddr` |

Одразу після масиву індексів розміщуються власні інлайн-записи `struct erofs_xattr_entry`:

```
[ e_name_len (1B) ] [ e_name_index (1B) ] [ e_value_size (2B) ] [ Name String ] [ Value Bytes ]
```

Поле `e_name_index` визначає префікс атрибута для економії дискового простору:
- `1`: `user.` (атрибути користувача)
- `2`: `system.posix_acl_access` (списки контролю доступу)
- `3`: `system.posix_acl_default` (типові списки для каталогів)
- `4`: `trusted.` (довірені атрибути ядра)
- `6`: `security.` (використовується для SELinux-контекстів `security.selinux`).

## Прапорці несумісності (`feature_incompat`)

Значення поля `feature_incompat` у суперблоці визначають обов'язкові вимоги до ядра Linux для успішного монтування тома. Якщо ядро виявляє невідомий біт у цьому полі, операція `mount` повертає помилку `-EINVAL`:

- `EROFS_FEATURE_INCOMPAT_ZERO_PADDING` (`0x00000001`): Хвостова частина стиснених фізичних кластерів доповнена нульовими байтами — саме це й уможливлює декомпресію за місцем для LZ4.
- `EROFS_FEATURE_INCOMPAT_COMPR_CFGS` / `EROFS_FEATURE_INCOMPAT_BIG_PCLUSTER` (`0x00000002`): один біт на дві пов'язані речі — у суперблоці присутній блок налаштувань алгоритмів стиснення, а фізичний кластер може бути більшим за один блок.
- `EROFS_FEATURE_INCOMPAT_CHUNKED_FILE` (`0x00000004`): в образі є файли у режимі `EROFS_INODE_CHUNK_BASED`.
- `EROFS_FEATURE_INCOMPAT_DEVICE_TABLE` / `EROFS_FEATURE_INCOMPAT_COMPR_HEAD2` (`0x00000008`): таблиця додаткових пристроїв (multi-device) та другий тип head-запису в карті екстентів.
- `EROFS_FEATURE_INCOMPAT_ZTAILPACKING` (`0x00000010`): хвостовий pcluster стисненого файла запакований поруч із індексним вузлом.
- `EROFS_FEATURE_INCOMPAT_FRAGMENTS` / `EROFS_FEATURE_INCOMPAT_DEDUPE` (`0x00000020`): спільний файл фрагментів та дедуплікація однакових стиснених екстентів між файлами.
