# 📋 Специфікація FHS 3.0 та XDG Base Directory

Повна структурована довідка інтерфейсу каталогів стандарту **Filesystem Hierarchy Standard (FHS 3.0)** та **XDG Base Directory Specification**. Документ містить точні вимоги до розміщення системних та користувацьких файлів, квадрантну класифікацію (Static/Variable, Shareable/Unshareable), рекомендовані атрибути прав доступу (`chmod`/`chown`), правила монтування у режимі захисту від запису, прапорці файлових систем POSIX та стандартизовані змінні середовища користувацького оточення.

## 1. Повний контракт каталогів стандарту FHS 3.0

Стандарт FHS 3.0 визначає точні межі відповідальності кожного системного каталогу. Дотримання цих правил гарантує сумісність пакетів між різними дистрибутивами Linux та запобігає виникненню колізій під час оновлення операційної системи.

## 2. Аналіз модальностей монтування та атрибутів безпеки

Кожен каталог у вищенаведеній специфікації володіє унікальним набором системних вимог до безпеки та продуктивності.

### 2.1. Каталоги Read-Only Mountable (`/usr`, `/usr/share`, `/opt`)
Каталог `/usr` містить стабільний бінарний код та архітектурно-незалежні ресурси. У високонадійних системних конфігураціях ці каталоги монтуються з прапором `MS_RDONLY` (`ro` у `/etc/fstab`). 

Основні наслідки Read-Only монтування:
- Жоден процес у системі (включаючи процес із правами `root`) не може модифікувати бінарний код у `/usr/bin` або бібліотеку у `/usr/lib` через системні виклики `write()`, `unlink()`, `rename()`;
- Оновлення системи вимагає перемонтування каталогу в режим запису (`mount -o remount,rw /usr`) або атомарного перемикання дискового снапшота;
- Захищає систему від випадкового руйнування командним скриптом чи впровадження шкідливого коду у системні бінарники.

### 2.2. Каталоги інтенсивного запису (`/var`, `/tmp`, `/run`)
Ці каталоги призначені для збереження стану, логів та тимчасових даних:
- **`/tmp`**: Зазвичай монтується у вигляді оперативного диска `tmpfs` у RAM. Обмеження розміру задається параметром `size=50%`. При перезавантаженні системи вміст `/tmp` повністю втрачається.
- **`/var/tmp`**: Відповідно до FHS 3.0, вміст `/var/tmp` повинен зберігатися між перезавантаженнями системи. Цей каталог розташовується на фізичному накопичувачі та використовується програмами для обробки великих тимчасових масивів даних.
- **`/run`**: Монтується як `tmpfs` на самому ранньому етапі завантаження системи під управлінням `systemd`. Містить файли ідентифікаторів процесів (PID), сокети міжпроцесної взаємодії (UNIX domain sockets) та прапори блокування пристроїв.

## 3. Специфікація XDG Base Directory

Специфікація **XDG Base Directory Specification** від консорціуму freedesktop.org регулює розміщення конфігурацій, персональних даних та кешу в домашньому каталозі користувача `$HOME`. Вона запобігає засміченню домашньої папки прихованими каталогами та файлами.

| Змінна середовища | Значення за замовчуванням | Призначення та вміст |
| :--- | :--- | :--- |
| `XDG_CONFIG_HOME` | `$HOME/.config` | Конфігураційні файли користувача (ini, json, yaml, tompl). |
| `XDG_DATA_HOME` | `$HOME/.local/share` | Персональні дані програм, локальні бази даних, десктоп-файли `.desktop`. |
| `XDG_CACHE_HOME` | `$HOME/.cache` | Непринципові кешовані дані (іконки, мініатюри зображень, кеш браузерів). |
| `XDG_STATE_HOME` | `$HOME/.local/state` | Стан сесій, історія командного рядка, журнали роботи користувацьких програм. |
| `XDG_RUNTIME_DIR` | `/run/user/$UID` | Тимчасові сокети IPC (Wayland, PipeWire, D-Bus), прапори безпеки в RAM. |
| `XDG_CONFIG_DIRS` | `/etc/xdg` | Двокрапковий список баз конфігурацій за замовчуванням для всієї системи. |
| `XDG_DATA_DIRS` | `/usr/local/share:/usr/share` | Двокрапковий список баз даних системного рівня (.desktop файли, шрифти). |

### 3.1. Алгоритм каскадного пошуку конфігурацій XDG

Застосунок, який підтримує специфікацію XDG, виконує пошук конфігураційних файлів за каскадною схемою з пріоритетами:

```
1. Персональні налаштування користувача:
   $XDG_CONFIG_HOME/appname/config.ini  (~/.config/appname/config.ini)
   ↓ (якщо відсутній)

2. Системні налаштування адміністратора:
   /etc/xdg/appname/config.ini  (значення з XDG_CONFIG_DIRS)
   ↓ (якщо відсутній)

3. Дистрибутивні конфігурації за замовчуванням:
   /usr/share/appname/config.ini  (значення з XDG_DATA_DIRS)
```

Цей каскадний підхід дозволяє системному адміністраторові задати глобальні налаштування у `/etc/xdg`, залишаючи користувачеві можливість перевизначити окремі параметри у своєму `~/.config`.

## 4. Спеціальні прапори прав доступу та опції fstab

FHS 3.0 вимагає використання бітових масок прав доступу POSIX для забезпечення безпеки системи:

### 4.1. Спеціальні біти атрибутів POSIX
1. **Sticky Bit (`01000` / `t`)**:
   Застосовується до загальнодоступних тимчасових каталогів `/tmp` та `/var/tmp` (`chmod 1777 /tmp`). Позначка `t` гарантує, що хоча створювати та читати файли у папці може будь-який користувач, **видаляти або перейменовувати файл має право лише його безпосередній власник** або суперкористувач `root`. Це унеможливлює атаки типу «відмова у обслуговуванні», коли один користувач видаляє тимчасові файли іншого.

2. **Setuid (`04000` / `s`) та Setgid (`02000` / `s`)**:
   Дозволяють виконувати процес з привілеями власника файла або групи файла. Наприклад, бінарний файл `/usr/bin/passwd` має встановлений біт `suid` (`chmod 4755`), що дозволяє звичайному користувачу тимчасово отримати привілеї `root` для внесення змін до захищеного файла паролів `/etc/shadow`. При встановленні `setgid` на каталог (`chmod 2775 /var/log/journal`), усі новостворені файли всередині успадковують групу цього каталогу.

### 4.2. Прапорці монтування файлових систем (`mount flags`)

| Прапор монтування | Опис та безпековий ефект | Застосування за FHS |
| :--- | :--- | :--- |
| `ro` (`MS_RDONLY`) | Блокує будь-які операції запису на рівні VFS ядра. | `/usr`, `/usr/share`, `/boot` |
| `nodev` (`MS_NODEV`) | Забороняє інтерпретацію блочних та символьних нодів пристроїв. | `/tmp`, `/var`, `/home` |
| `nosuid` (`MS_NOSUID`) | Ігнорує біти Setuid та Setgid для виконуваних бінарників. | `/tmp`, `/var`, `/home` |
| `noexec` (`MS_NOEXEC`) | Забороняє прямий запуск бінарного коду з даного розділу. | `/tmp`, `/var/tmp` |
| `relatime` | Оновлює атрибут `atime` (час доступу) лише якщо він старший за `mtime`. | Рекомендовано для всіх ФС |
| `noatime` | Повністю вимикає оновлення часу доступу при читанні файлів. | Оптимізація SSD / NVMe |

## 5. Модель розмежування Linux Capabilities

У сучасних системах Linux класична модель прав `root` розбивається на окремі привілеї — **capabilities**:
- `CAP_DAC_OVERRIDE` — обхід перевірок прав доступу до файлів (read, write, execute);
- `CAP_DAC_READ_SEARCH` — обхід перевірок лише на читання та перегляд каталогів;
- `CAP_FOWNER` — обхід перевірок власника при зміні атрибутів файлів;
- `CAP_CHOWN` — право змінювати власника та групу будь-якого файла в FHS.

Використання Linux capabilities у поєднанні з правилами FHS 3.0 дозволяє відмовитися від небезпечних битів `setuid` на користь точкового надання привілеїв бінарним файлам (наприклад, `setcap cap_net_raw+ep /usr/bin/ping`).

## 6. Параметри безпеки ядра `/proc/sys/fs/`

Для захисту цілісності ієрархії FHS ядро Linux надає ряд інтерфейсів керування через `/proc/sys/fs/`:

- **`fs.protected_symlinks` (за замовчуванням `1`)**: Забороняє перехід за символічними посиланнями у тимчасових каталогах з атрибутом sticky bit (`/tmp`), якщо власник симлінка не збігається з власником каталогу або поточним користувачем. Захищає від симлінк-атак у `/tmp`.
- **`fs.protected_hardlinks` (за замовчуванням `1`)**: Забороняє створення жорстких посилань на файли, якими користувач не володіє або до яких не має прав на читання та запис.
- **`fs.file-max`**: Задає системний ліміт на максимальну кількість відкритих файлових дескрипторів для всіх процесів у операційній системі.
- **`fs.suid_dumpable`**: Визначає правила дампа пам'яті (core dump) для процесів із прапорами `setuid`/`setgid`, запобігаючи витоку чутливих даних у тимчасові каталоги.

## 7. Застарілі каталоги, видалені або об'єднані в FHS 3.0

Протягом еволюції FHS декілька застарілих каталогів були вилучені зі специфікації або оголошені застарілими:
- **`/usr/X11R6`**: Історичний каталог для графічної системи X Window System (X11). У сучасних дистрибутивах бінарники перенесені у `/usr/bin`, а конфігурації — у `/etc/X11`.
- **`/usr/tmp`**: Застаріле посилання на `/var/tmp`. Вилучено зі специфікації FHS 3.0 для запобігання дублюванню шляхів.
- **`/etc/mtab`**: Історично містив список змонтованих файлових систем, що оновлювався утилітою `mount` у юзерспейсі. У сучасних Linux-системах `/etc/mtab` є символічним посиланням на ядрову віртуальну таблицю `/proc/self/mounts`.
