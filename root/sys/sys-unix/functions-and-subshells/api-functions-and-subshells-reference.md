# 📋 Довідник інтерфейсів: функції, підоболонки та змінні інспекції

Цей довідник містить формальний опис синтаксичних конструкцій, вбудованих команд керування областю видимості, спеціальних змінних середовища та параметрів конфігурації для роботи з функціями і підоболонками в Unix-оболонках (POSIX sh та GNU Bash).

---

## 1. Життєвий цикл та синтаксис оголошення функцій

Функція в командній оболонці є іменованим фрагментом синтаксичного дерева (AST), який зберігається у внутрішній хеш-таблиці процесу інтерпретатора. На відміну від скриптів на диску, функція завантажується в пам'ять один раз і виконується без звернення до файлової системи.

### Форми оголошення та їхня семантика

```sh
# POSIX-сумісна форма (рекомендована для всіх переносних скриптів)
cleanup_temp() {
    rm -f /tmp/app_*.tmp
}

# POSIX-форма з перенаправленням на рівні всього тіла функції
log_event() {
    printf "[%s] %s\n" "$(date +%T)" "$*"
} >> /var/log/app.log 2>&1

# Форма KornShell / Bash з ключовим словом function
function backup_data {
    tar -czf /backup/data.tar.gz /var/data
}
```

### Порядок пошуку та підміни команд

Коли оболонка обробляє перший токен введеного командного рядка, вона шукає відповідний виконуваний об'єкт у такій послідовності:
1. **Спеціальні вбудовані команди (Special Builtins)**: `break`, `: `, `eval`, `exec`, `exit`, `return`, `set`, `shift`, `trap`, `unset`. Вони мають абсолютний пріоритет.
2. **Функції оболонки**: користувацькі функції та бібліотечні процедури, завантажені через `source`.
3. **Звичайні вбудовані команди (Regular Builtins)**: `cd`, `echo`, `read`, `kill`, `pwd`.
4. **Зовнішні виконувані файли**: пошук бінарних файлів та скриптів у каталогах змінної `$PATH`.

Якщо ім'я функції збігається зі звичайною вбудованою командою або зовнішньою програмою (наприклад, `cd` або `grep`), функція повністю перехоплює виконання. Для явного виклику оригінальної команди використовують службову конструкцію `builtin cd` або `command grep`.

## 2. Позиційні параметри та стек аргументів

Під час виклику функції оболонка не створює нового процесу, але виділяє новий локальний фрейм для позиційних аргументів. Попередні аргументи скрипту зберігаються у внутрішньому стеку та автоматично відновлюються при поверненні.

### Спеціальні змінні аргументів

- **`$0`**: Ім'я файлу сценарію або назва процесу оболонки. **Важливий інваріант**: значення `$0` всередині функції ніколи не змінюється на назву самої функції. Воно завжди посилається на вихідний скрипт.
- **`$1`, `$2`, ..., `$9`**: Позиційні параметри з першого по дев'ятий.
- **`${10}`, `${11}`, ..., `${N}`**: Позиційні параметри з індексами десять і більше. Фігурні дужки є обов'язковими: запис `$10` без дужок розгортається як `$1` та символ `0`.
- **`$#`**: Кількість аргументів, переданих поточній функції. При вході у функцію без аргументів `$#` дорівнює нулю.
- **`"$@"`**: Масив усіх переданих аргументів. У подвійних лапках розкривається як окремі слова `"$1" "$2" ... "$N"`, зберігаючи пробіли та порожні аргументи всередині кожного елемента.
- **`"$*"`**: Рядок, що об'єднує всі аргументи в єдине слово через перший символ роздільника полів `IFS` (за замовчуванням — пробіл).
- **`shift [N]`**: Вбудована команда, яка зсуває позиційні параметри поточної функції на `N` позицій уліво. Аргумент `$1` знищується, колишній `$2` стає новим `$1`, а `$#` зменшується на `N`.
- **`set -- arg1 arg2`**: Вбудована команда, що повністю перезаписує поточний набір позиційних параметрів новими значеннями.

## 3. Команди керування виконанням та областю видимості

### `return [N]`
Завершує виконання поточної функції або файлу, завантаженого через `source` (`.`).
- **Код виходу `N`**: Ціле число у діапазоні від `0` до `255`. Якщо вказано значення понад 255, воно обрізається за правилом `N % 256`.
- **Відсутність аргументу**: Якщо `N` опущено, функція повертає код завершення останньої виконаної перед `return` команди.
- **Відмінність від `exit`**: `return` передає керування у викликач поточної функції. Команда `exit` негайно завершує весь системний процес оболонки незалежно від глибини вкладеності викликів.

### `local [option] name[=value] ...`
Оголошує змінну в локальному фреймі поточної функції. Реалізує динамічну область видимості (Dynamic Scope): змінна доступна поточній функції та всім дочірнім функціям, які вона викликає.
- **`-r`**: Зробити змінну доступною лише для читання (readonly) у межах фрейму.
- **`-i`**: Встановити цілочисельний атрибут (арифметичні операції виконуються автоматично при присвоєнні).
- **`-a`**: Оголосити індексований масив.
- **`-A`**: Оголосити асоціативний масив (хеш-таблицю, доступно в Bash 4.0+).
- **`-n`**: Оголосити посилання за іменем (nameref, доступно в Bash 4.3+). Змінна стає аліасом іншої змінної.

### `declare` та `typeset`
Універсальні вбудовані команди Bash для типізації. При виклику всередині функції за замовчуванням діють аналогічно до `local`.
- **`-g`**: Примусово створити або змінити змінну в **глобальній** області видимості, навіть якщо виклик відбувається всередині функції.
- **`-p [name]`**: Надрукувати точні атрибути та значення змінної у вигляді коду.
- **`-f [name]`**: Вивести визначення функцій або список їхнього коду.
- **`-F [name]`**: Вивести лише назви функцій, номери рядків та файли оголошення без тіла функцій.

### `unset`
Видаляє змінні або функції з поточної таблиці символів процесу.
- **`unset -v varname`**: Видаляє змінну. Всередині функції спочатку видаляється локальна змінна поточного фрейму, відновлюючи видимість однойменної змінної з попереднього фрейму або глобальної області.
- **`unset -f funcname`**: Повністю видаляє функцію з пам'яті інтерпретатора.

### `export -f funcname`
Специфічне розширення Bash, яке експортує тіло функції у змінні середовища процесу. Це дозволяє дочірнім процесам `bash`, запущеним через `execve()`, автоматично імпортувати та виконувати функцію без завантаження вихідного файлу.

## 4. Спеціальні змінні інспекції стека та підоболонок

| Змінна | Середовище | Тип / Структура даних | Призначення та поведінка |
|---|---|---|---|
| **`FUNCNAME`** | Bash | Масив рядків | Стек імен функцій. `${FUNCNAME[0]}` — поточна функція, `${FUNCNAME[1]}` — викликач. На верхньому рівні масив порожній або містить `main`. |
| **`BASH_SOURCE`** | Bash | Масив шляхів | Шляхи до файлів вихідного коду для кожного рівня стека викликів `FUNCNAME`. |
| **`BASH_LINENO`** | Bash | Масив чисел | Номери рядків у файлах, з яких було здійснено виклик функції. |
| **`BASHPID`** | Bash 4.0+ | Ціле число | **Фактичний PID процесу** в ядрі Linux. Змінюється при кожному виклику `fork()` усередині конвеєрів та дужок `( )`. |
| **`$$`** | POSIX, усі sh | Ціле число | **PID головного процесу** скрипту. Лишається незмінним у всіх дочірніх підоболонках для стабільності генерації тимчасових файлів. |
| **`BASH_SUBSHELL`** | Bash 3.0+ | Ціле число | Лічильник поточної глибини вкладеності підоболонок (`0` для основного процесу, `1` для першого рівня `( )`, `2` для вкладених дужок). |
| **`SHLVL`** | POSIX / Bash | Ціле число | Лічильник глибини незалежних процесів оболонок. Збільшується на 1 щоразу, коли запускається новий екземпляр бінарника оболонки. |
| **`$?`** | POSIX, усі sh | Число (0..255) | Статус завершення останньої виконаної команди, функції чи конвеєра. |
| **`_`** | POSIX / Bash | Рядок | Останній переданий аргумент попередньої виконаної команди. |

## 5. Опції конфігурації для функцій, підоболонок та конвеєрів

### `shopt -s lastpipe` (Bash 4.2+)
Змушує оболонку виконувати останню праву команду конвеєра `cmd1 | cmd2` безпосередньо в поточному процесі оболонки замість форкання підоболонки.
- **Умови активації**: Працює виключно тоді, коли вимкнено керування завданнями (Job Control, опція `set +m`). У неінтерактивних скриптах керування завданнями вимкнено за замовчуванням.
- **Ефект**: Змінні, змінені в останньому циклі конвеєра, зберігаються в пам'яті батьківського процесу.

### `set -o pipefail`
Змінює алгоритм розрахунку коду повернення конвеєра.
- **За замовчуванням**: Код повернення конвеєра дорівнює коду виходу останньої команди. Якщо перша команда впала, а друга завершилася успішно, конвеєр повертає 0.
- **З опцією `pipefail`**: Статус конвеєра дорівнює коду виходу останньої команди, що повернула ненульовий статус, або 0, якщо всі команди завершилися успішно.

### `set -E` або `set -o errtrace`
Примушує функції, підстановки команд та підоболонки успадковувати глобальний обробник сигналу помилки `trap ... ERR`. Без цього прапорця пастка `ERR` спрацьовує лише на верхньому рівні скрипту.

### `set -T` або `set -o functrace`
Примушує функції та підоболонки успадковувати обробники налагоджувальних сигналів `trap ... DEBUG` та `trap ... RETURN`.

### `shopt -s inherit_errexit` (Bash 4.4+)
Забезпечує успадкування суворого режиму обробки помилок `set -e` (`errexit`) усередині підстановок команд `$(cmd)`. У старіших версіях Bash підстановка команди автоматично вимикала `set -e` усередині підоболонки.
