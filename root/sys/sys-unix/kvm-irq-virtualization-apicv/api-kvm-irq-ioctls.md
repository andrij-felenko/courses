# 📋 Інтерфейс керування віртуалізацією переривань: ioctl, структури та параметри KVM

Керування підсистемою емуляції та апаратної акселерації переривань у гіпервізорі KVM здійснюється через набір системних викликів `ioctl()` на файловому дескрипторі віртуальної машини (`vm_fd`) та окремих vCPU (`vcpu_fd`). Цей інтерфейс визначає контракт низькорівневої взаємодії між простором користувача (QEMU, Cloud-Hypervisor, crosvm, Firecracker) та внутрішніми структурами модуля ядра `kvm.ko`.

Нижче наведено вичерпний довідник структур даних ядра Linux (`<linux/kvm.h>`), операцій `ioctl`, кодів помилок, параметрів модулів ядра та точок трасування `tracepoints`.

---

## 1. Системні виклики `ioctl` віртуальної машини (`vm_fd`)

### `KVM_CREATE_IRQCHIP`
Ініціалізує емуляцію апаратних контролерів переривань безпосередньо в просторі ядра Linux.

* **Контекст виклику:** Файловий дескриптор віртуальної машини (`vm_fd`).
* **Сигнатура:** `int ioctl(int vm_fd, KVM_CREATE_IRQCHIP, 0);`
* **Внутрішній механізм ядра:** Викликає функцію `kvm_vm_ioctl_create_irqchip()`, яка виділяє та ініціалізує структуру `struct kvm_pic` (два каскадних контролери 8259A PIC), структуру `struct kvm_ioapic` (контролер I/O APIC на 24 лінії) та готує базові структури `struct kvm_lapic` для майбутніх процесорів vCPU.
* **Вимоги до порядку викликів:** Системний виклик обов'язково має бути виконаний **до** створення будь-яких потоків vCPU (`KVM_CREATE_VCPU`). Якщо викликати його після ініціалізації vCPU, операція завершиться помилкою.
* **Можливі коди помилок:**
  * `EEXIST`: Контролер переривань уже було створено для цієї віртуальної машини раніше.
  * `EINVAL`: Некоректний дескриптор або спроба виклику після створення vCPU.
  * `ENOMEM`: Недостатньо пам'яті ядра для виділення внутрішніх структур контролерів.

---

### `KVM_IRQFD`
Пов'язує дескриптор асинхронних подій `eventfd` ядра Linux безпосередньо з конкретною лінією переривання (GSI) віртуальної машини.

* **Контекст виклику:** `vm_fd`.
* **Сигнатура:** `int ioctl(int vm_fd, KVM_IRQFD, struct kvm_irqfd *args);`
* **Структура параметрів:**

```c
struct kvm_irqfd {
    __u32 fd;           /* Файловий дескриптор eventfd */
    __u32 gsi;          /* Номер лінії Global System Interrupt (GSI) */
    __u32 flags;        /* Бітові прапорці керування (KVM_IRQFD_FLAG_*) */
    __u32 resamplefd;   /* Дескриптор eventfd для сигналізації EOI при RESAMPLE */
    __u8  pad[16];      /* Вирівнювання структури для сумісності */
};
```

#### Прапорці `flags` для `struct kvm_irqfd`:
1. `0` (за замовчуванням): Реєстрація зв'язки для імпульсних (Edge-triggered) переривань. Щоразу, коли будь-який потік хоста записує ненульове число в `fd`, KVM інжектує вектор `gsi` у віртуальний контролер.
2. `KVM_IRQFD_FLAG_DEASSIGN` (біт 0): Скасовує та знищує раніше зареєстровану прив'язку `eventfd ↔ GSI`. Після цього запис у `eventfd` більше не генеруватиме віртуальних переривань.
3. `KVM_IRQFD_FLAG_RESAMPLE` (біт 1): Вмикає підтримку рівневих (Level-triggered) переривань застарілих шин (INTx). При цьому поле `resamplefd` має містити валідний дескриптор `eventfd`.
   
   Коли гостьовий обробник переривання завершує роботу і виконує запис у регістр `EOI` віртуального APIC, KVM генерує сигнал у `resamplefd`, повідомляючи емулятор пристрою на хості про те, що лінію переривання можна повторно звести у разі наявності нових даних.

* **Можливі коди помилок:**
  * `EBADF`: Передано недійсний дескриптор `fd` або `resamplefd`.
  * `EINVAL`: Некоректний номер GSI або непідтримувані комбінації прапорців.
  * `ENOENT`: Спроба деактивації (`DEASSIGN`) зв'язки, яка не була попередньо зареєстрована.

---

### `KVM_SET_GSI_ROUTING`
Встановлює повну таблицю статичної та динамічної маршрутизації між глобальними системними номерами переривань (GSI) та конкретними пінами апаратних контролерів або повідомленнями MSI.

* **Контекст виклику:** `vm_fd`.
* **Сигнатура:** `int ioctl(int vm_fd, KVM_SET_GSI_ROUTING, struct kvm_irq_routing *routing);`
* **Структура параметрів:**

```c
struct kvm_irq_routing {
    __u32 nr;           /* Кількість записів у масиві entries[] */
    __u32 flags;        /* Зарезервовано для розширень, обов'язково 0 */
    struct kvm_irq_routing_entry entries[0];
};

struct kvm_irq_routing_entry {
    __u32 gsi;          /* Номер Global System Interrupt */
    __u32 type;         /* Тип трансляції: IRQCHIP або MSI */
    __u32 flags;        /* Специфічні прапорці маршрутизації (зазвичай 0) */
    __u32 pad;
    union {
        struct kvm_irq_routing_irqchip irqchip;
        struct kvm_irq_routing_msi     msi;
        __u32 hv_sint;  /* Для синтетичних контролерів Hyper-V SynIC */
        __u32 pad[8];
    } u;
};
```

#### Формати записів об'єднання `u`:
* **`struct kvm_irq_routing_irqchip` (`type == KVM_IRQ_ROUTING_IRQCHIP`):**
  * `irqchip`: Ідентифікатор емульованого контролера (`KVM_IRQCHIP_PIC_MASTER = 0`, `KVM_IRQCHIP_PIC_SLAVE = 1`, `KVM_IRQCHIP_IOAPIC = 2`).
  * `pin`: Фізичний номер піна (0–7 для контролерів 8259 PIC; 0–23 для I/O APIC).
* **`struct kvm_irq_routing_msi` (`type == KVM_IRQ_ROUTING_MSI`):**
  * `address_lo`: Молодші 32 біти фізичної адреси MSI (базовий діапазон `0xFEE00000`).
  * `address_hi`: Старші 32 біти фізичної адреси MSI.
  * `data`: 32-розрядний блок даних MSI (містить 8-бітний вектор переривання, delivery mode, trigger mode та destination mode).

* **Внутрішній механізм ядра:** KVM створює нову структуру `struct kvm_irq_routing_table`, заповнює її записами та атомарно замінює старий вказівник за допомогою механізму RCU (Read-Copy Update), гарантуючи відсутність блокувань на гарячому шляху інжекції переривань.

---

### `KVM_SIGNAL_MSI`
Здійснює безпосередню програмну генерацію одного повідомлення MSI у віртуальну машину з простору користувача.

* **Контекст виклику:** `vm_fd`.
* **Сигнатура:** `int ioctl(int vm_fd, KVM_SIGNAL_MSI, struct kvm_msi *msi);`
* **Структура параметрів:**

```c
struct kvm_msi {
    __u32 address_lo;   /* Молодші 32 біти адреси MSI (0xFEE00000) */
    __u32 address_hi;   /* Старші 32 біти адреси MSI */
    __u32 data;         /* Формат даних MSI (вектор, пріоритет) */
    __u32 flags;        /* Прапорці (KVM_MSI_VALID_DEVID тощо) */
    __u8  pad[16];
};
```

Цей виклик є зручним для емуляторів пристроїв у просторі користувача, які генерують поодинокі переривання без налаштування постійного дескриптора `eventfd`.

## 2. Системні виклики `ioctl` віртуального процесора (`vcpu_fd`)

### `KVM_GET_LAPIC` та `KVM_SET_LAPIC`
Зчитує або перезаписує повний внутрішній стан регістрів Local APIC для конкретного vCPU. Використовується під час збереження контрольних точок (snapshots), динамічної міграції (Live Migration) або налагодження.

* **Контекст виклику:** Файловий дескриптор віртуального процесора (`vcpu_fd`).
* **Сигнатури:**
  * `int ioctl(int vcpu_fd, KVM_GET_LAPIC, struct kvm_lapic_state *state);`
  * `int ioctl(int vcpu_fd, KVM_SET_LAPIC, struct kvm_lapic_state *state);`
* **Структура параметрів:**

```c
#define KVM_APIC_REG_SIZE 0x400

struct kvm_lapic_state {
    char regs[KVM_APIC_REG_SIZE]; /* 1024 байти простору регістрів Local APIC */
};
```

* **Особливості міграції стану:**
  * Під час збереження стану функція копіює дані безпосередньо з виділеної Virtual-APIC Page та внутрішніх кешів KVM, фіксуючи поточні значення бітових масок `vIRR`, `vISR`, `vTMR` та конфігурацію таймера APIC.
  * Під час відновлення через `KVM_SET_LAPIC` ядро KVM валідує конфігурацію регістрів, оновлює тіньові поля VMCS (зокрема RVI та SVI) і перезапускає таймери `hrtimer` відповідно до збереженого значення початкового лічильника `APIC_TMICT`. Це запобігає втраті таймерних переривань або порушенню пріоритетів під час перенесення віртуальної машини на інший фізичний хост.

## 3. Параметри модулів ядра Linux у sysfs

Налаштування апаратної віртуалізації переривань здійснюється під час завантаження модулів ядра `kvm_intel` та `kvm_amd` (або динамічно через файлову систему `/sys/module/`):

| Шлях у sysfs | Тип | За замовчуванням | Опис і вплив на систему |
| :--- | :--- | :--- | :--- |
| `/sys/module/kvm_intel/parameters/enable_apicv` | `bool` | `Y` (1) | Вмикає підтримку Intel APICv (Virtualize APIC-accesses, APIC-register virtualization, Virtual-interrupt delivery). При вимкненні KVM переходить у режим повної програмної емуляції з перехопленням MMIO. |
| `/sys/module/kvm_intel/parameters/enable_posted_events` | `bool` | `Y` (1) | Дозволяє використання апаратних Posted Interrupts для зовнішніх пристроїв VFIO та міжпроцесорних переривань IPI. |
| `/sys/module/kvm_amd/parameters/avic` | `bool` | `Y` (1) | Активує апаратний контролер AMD AVIC для процесорів архітектури Zen. |
| `/sys/module/kvm_amd/parameters/nested_avic` | `bool` | `Y` (1) | Дозволяє прокидання контролера AVIC у вкладені віртуальні машини другого рівня (L2). |

### Перевірка активності апаратної віртуалізації:
```bash
# Перевірка для систем на базі Intel
cat /sys/module/kvm_intel/parameters/enable_apicv
cat /sys/module/kvm_intel/parameters/enable_posted_events

# Перевірка для систем на базі AMD
cat /sys/module/kvm_amd/parameters/avic
```

Якщо параметр `enable_apicv` повертає `N` або `0`, це свідчить про те, що апаратна віртуалізація вимкнена в BIOS/UEFI, процесор не підтримує відповідні розширення або її було примусово деактивовано через несумісність з іншими налагоджувальними модулями ядра.

## 4. Точки трасування ядра (Tracepoints)

Підсистема KVM надає розширений набір подій `tracepoints` для детального профілювання, моніторингу затримок та налагодження життєвого циклу переривань за допомогою утиліт `trace-cmd` або `perf`:

```bash
# Запис подій доставки переривань та оновлення контролерів
trace-cmd record -e kvm:kvm_apic \
                 -e kvm:kvm_apic_accept_irq \
                 -e kvm:kvm_eoi \
                 -e kvm:kvm_pi_irte_update \
                 -e kvm:kvm_exit

# Перегляд зібраних даних із часовими мітками
trace-cmd report
```

### Довідник подій трасування KVM:
1. `kvm:kvm_apic`: Фіксує операції читання та запису регістрів Local APIC. Дозволяє виявити неакселеровані звернення до регістрів за їхнім зсувом (наприклад, зсув `0x300` для `ICR Low`).
2. `kvm:kvm_apic_accept_irq`: Сигналізує про успішне прийняття переривання конкретним vCPU та встановлення біта у векторі `vIRR`. Подія відображає `apicid`, `vec` (номер вектору) та `dm` (режим доставки).
3. `kvm:kvm_eoi`: Фіксує завершення обробки переривання гостем. Подія містить номер завершеного вектора та прапорець наявності очікуваних переривань у черзі `vIRR`.
4. `kvm:kvm_pi_irte_update`: Фіксує оновлення дескриптора IRTE в Intel VT-d IOMMU під час прив'язки фізичного пристрою VFIO до структури `struct pi_desc` віртуального процесора. Відображає `vcpu_id`, `gsi`, `vector` та цільовий `host_apic_id`.
5. `kvm:kvm_exit`: Відображає причину виходу з віртуальної машини. Дозволяє відстежувати застарілі або небажані виходи `EXIT_REASON_APIC_ACCESS` (код 44), `EXIT_REASON_APIC_WRITE` (код 56) та `EXIT_REASON_TPR_BELOW_THRESHOLD` (код 43), допомагаючи локалізувати джерела втрати продуктивності.
