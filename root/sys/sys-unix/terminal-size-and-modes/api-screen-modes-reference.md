# 📋 Довідник керування розміром, буферами та режимами термінала

Цей довідник містить вичерпний опис системних структур ядра Linux, числових констант системних викликів `ioctl`, параметрів сигналів, керуючих послідовностей ANSI/DEC та прапорців структури `termios`, що відповідають за керування геометрією вікна, екранними буферами та дисципліною термінальної лінії в операційних системах сімейства Unix.

## 1. Геометрія термінала в ядрі Linux

Заголовні файли: `<sys/ioctl.h>`, `<termios.h>`, `<asm/ioctls.h>`.

### Структура struct winsize

У підсистемі TTY ядра Linux геометрія термінального вікна зберігається безпосередньо у внутрішній структурі лінії зв'язку `struct tty_struct`. Для передачі цих даних між ядром та користувацьким простором застосовується структура `struct winsize`:

:::tabs
```c
#include <sys/ioctl.h>

struct winsize {
    unsigned short ws_row;    /* кількість рядків у символьних комірках */
    unsigned short ws_col;    /* кількість стовпців у символьних комірках */
    unsigned short ws_xpixel; /* горизонтальний розмір вікна у пікселях */
    unsigned short ws_ypixel; /* вертикальний розмір вікна у пікселях */
};
```
```cpp
#include <sys/ioctl.h>
#include <cstdint>

// У C++ структура struct winsize доступна через заголовок <sys/ioctl.h>
// Її двійкове представлення повністю відповідає стандарту POSIX та Linux ABI
struct TerminalWindowSize {
    std::uint16_t ws_row{0};
    std::uint16_t ws_col{0};
    std::uint16_t ws_xpixel{0};
    std::uint16_t ws_ypixel{0};
};
```
:::

Поля структури мають чітко розмежоване функціональне призначення:
- `ws_row`: кількість видимих рядків екрана (знакомісць по вертикалі). Типові значення варіюються від 24 (історичний стандарт VT100) до 60–120 на сучасних моніторах високої роздільної здатності.
- `ws_col`: кількість видимих стовпців екрана (знакомісць по горизонталі). Базовий розмір становить 80 символів; у розгорнутих вікнах типовими є значення від 120 до 240+ стовпців.
- `ws_xpixel`: повна горизонтальна ширина клієнтської області вікна емулятора в пікселях. Якщо емулятор не передає графічні метрики або зв'язок здійснюється через класичний апаратний RS-232 UART, ядро містить у цьому полі `0`.
- `ws_ypixel`: повна вертикальна висота клієнтської області вікна емулятора в пікселях. Заповнюється емулятором аналогічно до `ws_xpixel`.

### Системні виклики ioctl для розміру екрана

Команди запиту та встановлення розмірів вікна кодуються за допомогою системного макроса побудови номерів `ioctl`:

:::tabs
```c
#include <sys/ioctl.h>
#include <unistd.h>

/* Прототип системного виклику ioctl у мові C */
int ioctl(int fd, unsigned long request, ...);
```
```cpp
#include <sys/ioctl.h>
#include <unistd.h>

// Системний виклик ioctl у C++ має C-зв'язування (extern "C")
extern "C" int ioctl(int fd, unsigned long request, ...) noexcept;
```
:::

Числові константи команд для архітектури Linux x86_64:

| Запит (`request`) | Шістнадцятковий код | Тип операції | Опис та механізм передачі |
| :--- | :--- | :--- | :--- |
| `TIOCGWINSZ` | `0x5413` | Читання (Get) | **Отримати розмір вікна:** копіює поточний стан `tty->winsize` з адресного простору ядра в структуру `struct winsize`, вказану користувацьким вказівником. |
| `TIOCSWINSZ` | `0x5414` | Запис (Set) | **Встановити розмір вікна:** оновлює `tty->winsize` у ядрі значеннями з переданої структури. Якщо нові параметри відрізняються від попередніх, ядро ініціює доставку сигналу `SIGWINCH` усім процесам поточної активної групи термінала. |
| `TIOCGSIZE` | `0x5438` | Читання (Legacy) | Застарілий аналог `TIOCGWINSZ` у старих версіях BSD та SunOS, що оперував структурою `struct ttysize`. Підтримується ядром Linux виключно для зворотної двійкової сумісності. |
| `TIOCSSIZE` | `0x5439` | Запис (Legacy) | Застарілий аналог `TIOCSWINSZ` для структури `struct ttysize`. |

### Коди помилок системного виклику ioctl

У разі невдалого виконання виклик `ioctl` повертає `-1` та встановлює значення глобальної змінної `errno`:

- `EBADF`: переданий файловий дескриптор `fd` не є дійсним або відкритим дескриптором у таблиці файлів поточного процесу.
- `ENOTTY`: файловий дескриптор `fd` вказує на об'єкт, який не є термінальним пристроєм (наприклад, потік перенаправлено у звичайний дисковий файл, анонімний канал `pipe` або мережевий сокет).
- `EFAULT`: вказівник на структуру `struct winsize` вказує за межі доступного адресного простору процесу або в область пам'яті, захищену від запису.
- `EINVAL`: передано невідомий код запиту або некоректні параметри конфігурації лінії TTY.

## 2. Сигнал зміни розміру вікна: SIGWINCH

Сигнал `SIGWINCH` є єдиним асинхронним механізмом сповіщення користувацьких процесів про зміну фізичних або логічних розмірів термінального вікна.

### Характеристики сигналу SIGWINCH

- **Назва:** `SIGWINCH` (Window Change Signal).
- **Числовий номер у системі:** `28` на більшості архітектур (x86_64, ARM, ARM64, RISC-V); `20` на архітектурах Alpha та SPARC.
- **Стандартна дія за замовчуванням:** `SIG_IGN` (ігнорування ядром). Якщо процес не встановлює власний обробник або не читає сигнал через `signalfd`, надходження `SIGWINCH` не призводить до переривання чи завершення програми.
- **Адресат доставки:** ядро надсилає сигнал не поодинокому процесу, а всій групі процесів переднього плану (foreground process group, `pgrp`), пов'язаній із сеансом керуючого термінала, викликаючи функцію `kill_pgrp(tty->pgrp, SIGWINCH, 1)`.
- **Властивості доставки:** `SIGWINCH` є стандартним (не realtime) сигналом. Якщо вікно змінює розмір багатократно за короткий проміжок часу (наприклад, під час плавного перетягування мишею), сигнал не стає в чергу: повторні сповіщення об'єднуються (coalescing) в один сигнал, доки процес не почне його обробку.

## 3. Керуючі послідовності режимів екрана (DEC Private Modes)

Керування режимами відображення здійснюється шляхом запису в дескриптор виводу керуючих послідовностей стандарту ECMA-48 та приватних розширень корпорації Digital Equipment Corporation (DEC).

Послідовності увімкнення (`DECSET`) мають вигляд `\e[?<номер>h` (`0x1B 0x5B 0x3F <номер> 0x68`).
Послідовності вимкнення (`DECRST`) мають вигляд `\e[?<номер>l` (`0x1B 0x5B 0x3F <номер> 0x6C`).

### Таблиця приватних режимів DEC

| Номер режиму | Увімкнення (`DECSET`) | Вимкнення (`DECRST`) | Повна назва та призначення |
| :--- | :--- | :--- | :--- |
| **`?1049`** | `\e[?1049h` | `\e[?1049l` | **Alternate Screen Buffer & Cursor Management:** основний сучасний стандарт для TUI. При увімкненні зберігає позицію та атрибути курсора основного екрана, перемикає термінал на альтернативний екранний буфер і повністю очищує його. При вимкненні очищує альтернативний буфер, повертає відображення основного екрана та відновлює збережені координати й налаштування курсора. |
| **`?47`** | `\e[?47h` | `\e[?47l` | **Alternate Screen Buffer (Legacy):** ранній варіант перемикання на альтернативний буфер без автоматичного збереження та відновлення позиції курсора. |
| **`?1047`** | `\e[?1047h` | `\e[?1047l` | **Alternate Screen with Clean on Exit:** перемикає екранні буфери та гарантує очищення альтернативного буфера при поверненні, але вимагає окремого керування збереженням курсора. |
| **`?1048`** | `\e[?1048h` | `\e[?1048l` | **Save / Restore Cursor State:** окремий приватний режим для збереження (`h`) або відновлення (`l`) поточних координат курсора, активного набору символів і графічних атрибутів. |
| **`?25`** | `\e[?25h` | `\e[?25l` | **DECTCEM (DEC Text Cursor Enable Mode):** керування видимістю апаратного текстового курсора. Послідовність `\e[?25l` робить курсор невидимим під час перемалювання кадру; `\e[?25h` повертає курсор перед очікуванням вводу. |
| **`?1000`** | `\e[?1000h` | `\e[?1000l` | **X10 Mouse Compatibility:** вмикає надсилання координат `(x, y)` у потік вводу при натисканні кнопок миші. |
| **`?1002`** | `\e[?1002h` | `\e[?1002l` | **Button Event Mouse Tracking:** передає координати та стан при натисканні, відпусканні та переміщенні миші з затиснутою кнопкою (drag). |
| **`?1003`** | `\e[?1003h` | `\e[?1003l` | **Any Event Mouse Tracking:** передає координати при будь-якому переміщенні вказівника миші в межах вікна термінала. |
| **`?1006`** | `\e[?1006h` | `\e[?1006l` | **SGR Extended Mouse Mode:** передає координати миші у десятковому форматі CSI `\e[<btn;x;yM` або `\e[<btn;x;ym`, що усуває ліміт у 223 стовпці, притаманний застарілому однобайтовому кодуванню. |
| **`?2004`** | `\e[?2004h` | `\e[?2004l` | **Bracketed Paste Mode:** вмикає безпечний режим вставки блоків тексту. Вставлений користувачем текст обрамляється маркерами `\e[200~` на початку та `\e[201~` у кінці, запобігаючи виконанню вставлених символів нового рядка як команд. |

## 4. Керування курсором та очищення екрана (ANSI CSI)

Команди позиціонування та очищення використовують стандартний префікс CSI (`\e[` або байти `0x1B 0x5B`):

| Команда | Синтаксис керуючої послідовності | Опис дії |
| :--- | :--- | :--- |
| **Cursor Position (CUP)** | `\e[<row>;<col>H` | Переміщує курсор у вказані координати `row` (рядок) та `col` (стовпець). Нумерація починається з `1, 1` (верхній лівий кут екрана). Скорочена форма `\e[H` еквівалентна `\e[1;1H`. |
| **Cursor Up (CUU)** | `\e[<n>A` | Зміщує курсор вгору на `n` рядків без зміни поточного стовпця. |
| **Cursor Down (CUD)** | `\e[<n>B` | Зміщує курсор униз на `n` рядків без зміни поточного стовпця. |
| **Cursor Forward (CUF)** | `\e[<n>C` | Зміщує курсор праворуч на `n` стовпців. |
| **Cursor Back (CUB)** | `\e[<n>D` | Зміщує курсор ліворуч на `n` стовпців. |
| **Cursor Horizontal Absolute (CHA)** | `\e[<col>G` | Переміщує курсор у вказаний стовпець `col` поточного рядка. |
| **Erase in Display (ED 2)** | `\e[2J` | Очищує всю видиму область екрана (заповнює пробілами зі збереженням поточних кольорів). |
| **Erase Scrollback (ED 3)** | `\e[3J` | Очищує весь буфер прокрутки (scrollback history) емулятора термінала (розширення Xterm). |
| **Erase to End of Display (ED 0)** | `\e[0J` або `\e[J` | Очищує екран від поточної позиції курсора до правого нижнього кута. |
| **Erase in Line (EL 2)** | `\e[2K` | Повністю очищує поточний рядок, у якому знаходиться курсор. |
| **Erase to End of Line (EL 0)** | `\e[0K` або `\e[K` | Очищує поточний рядок від позиції курсора до правого краю вікна. |
| **Reset Graphics Attributes (SGR 0)** | `\e[0m` або `\e[m` | Скидає всі активні атрибути форматування: повертає стандартний колір тексту, стандартний фон, вимикає жирність, курсив, інверсію та підкреслення. |

## 5. Прапорці структури termios для конфігурації режимів TTY

Заголовні файли: `<termios.h>`, `<unistd.h>`.

Структура `struct termios` керує лінійною дисципліною вводу/виводу драйвера TTY. Вона містить чотири бітові маски прапорців (`c_iflag`, `c_oflag`, `c_cflag`, `c_lflag`) та масив спеціальних керуючих символів `c_cc`.

### Прапорці локального режиму (`c_lflag`)

Локальні прапорці визначають взаємодію драйвера з користувачем на рівні термінального рядка:

- `ICANON`: канонічний режим (Canonical Mode). Якщо біт встановлено, ядро здійснює рядкову буферизацію: введені символи зберігаються в буфері редагування лінії, обробляються клавішами Backspace і `Ctrl+U`, а виклик `read()` розблоковується лише після натискання Enter (`\n`). У сирому режимі (Raw Mode) цей біт обов'язково **скидається в 0**.
- `ECHO`: автоматичне відлуння символів. Якщо встановлено, драйвер TTY автоматично друкує кожну натиснуту клавішу у вихідний потік. У TUI цей біт **скидається в 0**, щоб програма сама вирішувала, що і де малювати.
- `ECHOE`: якщо встановлено разом з `ECHO`, символ Backspace візуально стирає попередній знак на екрані. У сирому режимі **скидається в 0**.
- `ECHONL`: якщо встановлено, символ нового рядка `\n` друкується на екрані навіть за вимкненого загального прапорця `ECHO`. У сирому режимі **скидається в 0**.
- `ISIG`: генерація термінальних сигналів. Якщо біт встановлено, ядро перехоплює символи `VINTR` (код `0x03`, `Ctrl+C`), `VQUIT` (код `0x1C`, комбінація Ctrl і зворотний слеш) та `VSUSP` (код `0x1A`, `Ctrl+Z`) і надсилає процесу відповідні сигнали `SIGINT`, `SIGQUIT`, `SIGTSTP`. У сирому режимі цей біт скидають, якщо програма обробляє ці комбінації як звичайні клавіші.
- `IEXTEN`: увімкнення розширених символів введення POSIX (зокрема екранування через `Ctrl+V`). У сирому режимі **скидається в 0**.

### Прапорці вхідного режиму (`c_iflag`)

Вхідні прапорці керують обробкою байтів, що надходять від клавіатури або емулятора до драйвера TTY:

- `IXON`: програмне керування потоком даних за протоколом XON/XOFF. Якщо встановлено, натискання `Ctrl+S` (символ `XOFF`, `0x13`) призупиняє передачу виводу на екран, а `Ctrl+Q` (`XON`, `0x11`) відновлює її. У TUI цей біт **скидається в 0**, щоб комбінації `Ctrl+S` та `Ctrl+Q` були доступні програмі (наприклад, для збереження файлу).
- `ICRNL`: трансляція повернення каретки (Carriage Return, `\r`, код `13`) у символ нового рядка (Newline, `\n`, код `10`). У сирому режимі **скидається в 0**, щоб розрізняти натискання клавіш `Enter` (`\r`) та `Ctrl+J` (`\n`).
- `BRKINT`: генерувати сигнал `SIGINT` при отриманні стану розриву лінії (Break Condition) на послідовному порті. У сирому режимі **скидається в 0**.
- `INPCK`: увімкнути перевірку парності вхідних байтів на апаратному рівні. У сирому режимі **скидається в 0**.
- `ISTRIP`: обрізати старший 8-й біт кожного вхідного байта до 7-бітного ASCII. У TUI цей біт обов'язково **скидається в 0**, інакше багатобайтові послідовності UTF-8 будуть незворотно пошкоджені.

### Прапорці вихідного режиму (`c_oflag`)

- `OPOST`: увімкнення системної пост-обробки вихідного потоку. Якщо біт встановлено, драйвер автоматично виконує низку перетворень, головним із яких є `ONLCR` — заміна кожного відправленого символу `\n` на пару `\r\n`. У сирому режимі цей біт **скидається в 0**. При вимкненому `OPOST` програма повинна самостійно явно передавати `\r\n` для переходу на початок наступного рядка.

### Масив керуючих символів `c_cc` для неблокуючого або таймованого вводу

У неканонічному (сирому) режимі поля `c_cc[VMIN]` та `c_cc[VTIME]` визначають поведінку системного виклику `read()`:

| `VMIN` | `VTIME` | Поведінка виклику `read(fd, buf, count)` |
| :--- | :--- | :--- |
| `> 0` | `0` | **Суворо блокуючий ввід:** виклик `read()` блокує потік виконання процесу доти, доки в черзі не з'явиться щонайменше `VMIN` байтів. Для інтерактивного TUI зазвичай встановлюють `c_cc[VMIN] = 1`, щоб отримувати кожну натиснуту клавішу миттєво. |
| `0` | `> 0` | **Ввід за таймаутом:** виклик `read()` очікує дані протягом `VTIME` десятих долей секунди (значення `1` відповідає 100 мс). Якщо за цей час не надійшло жодного байта, `read()` повертає `0`. |
| `> 0` | `> 0` | **Міжсимвольний таймаут:** `read()` блокується до надходження першого байта, після чого запускається таймер на `VTIME` десятих секунди для кожного наступного символу. Виклик завершується після зчитування `VMIN` байтів або при спрацьовуванні таймауту. |
| `0` | `0` | **Повністю неблокуючий опитувальний ввід:** виклик `read()` повертає наявні в буфері байти негайно. Якщо буфер порожній, `read()` миттєво повертає `0`. |

### Застосування змін через функцію tcsetattr

:::tabs
```c
#include <termios.h>

int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);
```
```cpp
#include <termios.h>

extern "C" int tcsetattr(int fd, int optional_actions, const struct termios *termios_p) noexcept;
```
:::

Параметр `optional_actions` задає момент і спосіб набуття чинності новими налаштуваннями:
- `TCSANOW`: зміни застосовуються ядром негайно.
- `TCSADRAIN`: зміни застосовуються лише після того, як усі байти, записані у чергу виводу термінала, будуть фізично передані пристрою або відображені емулятором.
- `TCSAFLUSH`: **стандарт для переходу в сирий режим і повернення з нього.** Дія чекає передачі всього накопиченого виводу, після чого повністю очищує (відкидає) чергу непрочитаного вводу перед застосуванням нових правил. Це гарантує, що випадкові символи, набрані користувачем до старту програми, не будуть сприйняті TUI як команди.
