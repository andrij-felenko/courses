# 📋 Внутрішній інтерфейс ядра swiotlb та параметри ядра

Підсистема Software I/O TLB надає внутрішній контракт ядра Linux для виділення низьких підмінних буферів, управління життєвим циклом слотів трансляції та діагностики роботи підсистеми введення-виведення через інтерфейс debugfs. Цей довідник описує ключові структури, сигнатури внутрішніх функцій, алгоритми пошуку вільних слотів, динамічне розширення пулу, параметри завантаження ядра та метрики стану підсистеми.

## Константи та структури ядра

Конфігурація пулу базується на апаратних константах вирівнювання та масивах дескрипторів слотів, визначених у заголовку `include/linux/swiotlb.h` та файлі реалізації `kernel/dma/swiotlb.c`.

### Головні константи підсистеми

| Константа | Значення за замовчуванням | Опис |
| :--- | :--- | :--- |
| `IO_TLB_SHIFT` | `11` | Бітовий зсув розміру одного слота (`1 << 11 = 2048` байтів). |
| `IO_TLB_SIZE` | `2048` (2 КіБ) | Базовий квант виділення пам'яті в пулі swiotlb. Будь-яке відображення округлюється вгору до цілого числа слотів. |
| `IO_TLB_SEGSIZE` | `128` | Максимальна кількість суміжних слотів в одному виділеному блоці (`128 · 2048 = 262144` байтів, або 256 КіБ). |
| `IO_TLB_DEFAULT_SIZE` | `64 * 1024 * 1024` (64 МіБ) | Розмір пулу за замовчуванням на більшості 64-бітних архітектур (x86-64, ARM64). |

### Базові структури даних ядра

Внутрішній стан пулу організовано у три взаємопов'язані структури, що відповідають за глобальний масив пам'яті, багатоядерні ділянки виділення та метадані кожного слота:

```c
/* Дескриптор окремого слота або ланцюжка слотів у пулі */
struct io_tlb_slot {
    phys_addr_t orig_addr;       /* Фізична адреса оригінального буфера пам'яті */
    size_t alloc_size;           /* Повний виділений розмір пам'яті з урахуванням вирівнювання */
    unsigned int list;           /* Кількість вільних суміжних слотів, доступних після цього слота */
};

/* Окрема ділянка пулу для паралельного виділення на багатоядерних системах */
struct io_tlb_area {
    spinlock_t lock;             /* Спин-блокування, що захищає розподіл слотів у межах цієї ділянки */
    unsigned long index;         /* Поточний індекс кругового пошуку для рівномірного зносу слотів */
    unsigned int used;           /* Поточна кількість зайнятих слотів у цій конкретній ділянці */
};

/* Головний контекст пулу пам'яті swiotlb */
struct io_tlb_mem {
    phys_addr_t start;           /* Початкова фізична адреса суцільного діапазону пулу */
    phys_addr_t end;             /* Кінцева фізична адреса суцільного діапазону пулу */
    void *vaddr;                 /* Віртуальна адреса відображення пулу в адресному просторі ядра */
    unsigned long nslabs;        /* Загальна кількість доступних слотів по 2 КіБ */
    unsigned int nareas;         /* Кількість незалежних ділянок (типово дорівнює числу CPU) */
    struct io_tlb_area *areas;   /* Динамічний масив ділянок із власними блокуваннями */
    struct io_tlb_slot *slots;   /* Масив метаданих усіх слотів для відстеження адрес повернення */
    bool force_bounce;           /* Прапорець примусової підміни для всіх пристроїв системи */
    bool for_alloc;              /* Дозвіл використовувати пул для узгоджених виділень dma_alloc_coherent */
    struct list_head pools;      /* Список додаткових пулів у разі динамічного розширення */
};
```

Поле `list` у структурі `struct io_tlb_slot` відіграє роль оптимізації пошуку вільних ділянок: якщо значення `list > 0`, алгоритм виділення може одразу перестрибнути відповідну кількість вільних або зайнятих слотів, уникаючи покрокового сканування масиву пам'яті.

## Функції ядра та внутрішній життєвий цикл

Внутрішні функції підсистеми swiotlb не призначені для прямого виклику з драйверів пристроїв. Їх використовує спільний шар `dma-direct` підсистеми DMA Mapping ядра Linux.

### 1. Ініціалізація пулу під час завантаження системи

```c
int swiotlb_init(size_t nslabs, unsigned int flags);
```

- **Призначення:** Виділяє неперервний блок фізичної пам'яті на найбільш ранньому етапі завантаження ядра за допомогою низькорівневого розподільника `memblock`.
- **Параметри:**
  - `nslabs` — кількість запитуваних слотів по 2 КіБ. Якщо передано `0`, ядро обчислює розмір автоматично за замовчуванням.
  - `flags` — бітові прапорці конфігурації: `SWIOTLB_VERBOSE` (виводити докладну інформацію в кільцевий буфер dmesg) та `SWIOTLB_FORCE` (увімкнути примусову підміну для всіх пристроїв).
- **Повертає:** `0` у разі успішного виділення діапазону або `-ENOMEM`, якщо в низькій пам'яті (`ZONE_DMA` або `ZONE_DMA32`) бракує неперервного регіону.

```c
int swiotlb_init_late(size_t size, gfp_t gfp_mask,
                      int (*remap)(void *tlb, size_t size));
```

- **Призначення:** Пізня ініціалізація пулу після активації сторінкового розподільника ядра (`buddy allocator`). Застосовується, якщо під час раннього старту виділення не виконувалося, але під час підключення периферійного пристрою виникла потреба в підміні.
- **Параметри:**
  - `size` — необхідний обсяг пам'яті в байтах (округлюється до розміру сторінки).
  - `gfp_mask` — прапорці сторінкового розподільника (типово `GFP_DMA` для 24-бітних шин або `GFP_DMA32` для 32-бітних шин).
  - `remap` — необов'язковий покажчик на функцію перепризначення адрес (використовується гостями Xen та KVM).

### 2. Виділення слотів та зворотне перенесення даних

```c
dma_addr_t swiotlb_tbl_map_single(struct device *hwdev,
                                  phys_addr_t orig_addr,
                                  size_t mapping_size,
                                  size_t alloc_size,
                                  unsigned int alloc_aligned_mask,
                                  enum dma_data_direction dir,
                                  unsigned long attrs);
```

- **Призначення:** Виділяє послідовність суміжних слотів у локальній ділянці `io_tlb_area`, зберігає фізичну адресу оригінального буфера `orig_addr` у метаданих слота та здійснює копіювання `memcpy` корисного навантаження у підмінний слот для операцій передачі.
- **Алгоритм роботи:**
  1. Визначає поточний процесор і відповідну ділянку `area = &mem->areas[smp_processor_id() % mem->nareas]`.
  2. Захоплює спин-блокування `spin_lock_irqsave(&area->lock, flags)`.
  3. Виконує круговий пошук послідовності слотів довжиною `nslots = DIV_ROUND_UP(alloc_size, IO_TLB_SIZE)`. При пошуку враховується маска вирівнювання `alloc_aligned_mask`: молодші біти адреси слота повинні точно збігатися з молодшими бітами вихідної адреси `orig_addr`, щоб зберегти зсув у сторінці та вимоги пристрою до апаратного вирівнювання.
  4. Якщо слоти знайдено, записує `orig_addr` та `alloc_size` у таблицю дескрипторів `slots`, оновлює лічильник `area->used` та звільняє блокування.
  5. Якщо напрямок передачі `DMA_TO_DEVICE` або `DMA_BIDIRECTIONAL`, виконує функцію `swiotlb_bounce()`, яка копіює дані з `orig_addr` у виділений фізичний слот.
- **Повертає:** Фізичну адресу шини `dma_addr_t`, розташовану в межах маски пристрою, або спеціальне значення `DMA_MAPPING_ERROR` (`~0ULL`), якщо пул переповнено.

```c
void swiotlb_tbl_unmap_single(struct device *hwdev,
                              phys_addr_t tlb_addr,
                              size_t mapping_size,
                              enum dma_data_direction dir,
                              unsigned long attrs);
```

- **Призначення:** Завершує життєвий цикл відображення після завершення DMA-транзакції пристроєм.
- **Алгоритм роботи:**
  1. Знаходить індекс початкового слота за фізичною адресою `tlb_addr`.
  2. Витягує збережену фізичну адресу `orig_addr` із дескриптора `struct io_tlb_slot`.
  3. Якщо напрямок був `DMA_FROM_DEVICE` або `DMA_BIDIRECTIONAL`, викликає `swiotlb_bounce()`, копіюючи отримані пристроєм байти з підмінного слота назад в оригінальний буфер процесора.
  4. Захоплює блокування ділянки та повертає слоти до списку вільних, оновлюючи ланцюжок `list` і зменшуючи лічильник `area->used`.

### 3. Проміжна синхронізація та службові перевірки

```c
void swiotlb_tbl_sync_single(struct device *hwdev,
                             phys_addr_t tlb_addr,
                             size_t size,
                             enum dma_data_direction dir,
                             enum dma_sync_target target);
```

- **Призначення:** Здійснює перенесення змінених байтів між підмінним слотом і буфером програми без розбирання відображення. Якщо `target == SYNC_FOR_CPU`, дані копіюються зі слота в пам'ять процесора; якщо `target == SYNC_FOR_DEVICE`, дані копіюються з пам'яті процесора в слот swiotlb перед наступною апаратною транзакцією.

```c
bool is_swiotlb_buffer(struct device *dev, phys_addr_t paddr);
```

- **Призначення:** Швидка предикатна перевірка: повертає `true`, якщо фізична адреса `paddr` потрапляє в інтервал `[mem->start, mem->end)`. Дозволяє підсистемі DMA миттєво відрізнити пряме відображення від підмінного буфера під час виклику unmap.

```c
size_t swiotlb_max_segment(void);
```

- **Призначення:** Повертає максимальний розмір суцільного сегмента, який підсистема swiotlb здатна виділити за один виклик (`IO_TLB_SEGSIZE << IO_TLB_SHIFT = 256` КіБ). Це значення враховується блоковим рівнем і мережевим стеком ядра при розбитті запитів введення-виведення.

## Динамічне розширення пулу (Dynamic SWIOTLB)

Починаючи з версії ядра Linux 6.6, підсистема підтримує динамічне додавання нових пулів пам'яті (`CONFIG_SWIOTLB_DYNAMIC=y`). Це вирішує історичну проблему вичерпання статично виділеного пулу в захищених віртуальних машинах Confidential Computing:

```c
/* Додавання нового динамічного пулу при вичерпанні базового */
int swiotlb_dynamic_alloc_pool(struct io_tlb_mem *mem, size_t nslabs);
```

Коли активні ділянки фіксують високе заповнення (`io_tlb_used` наближається до `nslabs`), фоновий обробник виділяє додаткові сторінки пам'яті через сторінковий розподільник, переводить їх у незашифрований спільний стан (`set_memory_decrypted`) та зв'язує у список `mem->pools`. Якщо навантаження спадає, динамічні пули можуть бути повернуті системі.

## Обробка спеціальних атрибутів відображення

Під час виклику `dma_map_single()` драйвер може передавати атрибути `enum dma_attr`. Поведінка підсистеми swiotlb при цьому має важливі особливості:

- `DMA_ATTR_SKIP_CPU_SYNC`: У прямому DMA цей прапорець дозволяє пропустити дорогі операції скидання кешів процесора, якщо драйвер керує ними самостійно. Проте у разі підміни через swiotlb пропустити операцію копіювання пам'яті `memcpy` неможливо: дані повинні фізично опинитися в низькому слоті. Тому для підмінних буферів прапорець `DMA_ATTR_SKIP_CPU_SYNC` ігнорується, і копіювання виконується завжди.
- `DMA_ATTR_NO_WARN`: Забороняє ядру виводити попередження у системний журнал `dmesg`, якщо під час виділення слота сталося переповнення пулу. Драйвер самостійно обробляє повернене значення `DMA_MAPPING_ERROR`.

## Параметри командного рядка ядра

Параметри конфігурації передаються під час завантаження через рядок команд ядра Linux (`/proc/cmdline`):

| Параметр | Формат значення | Поведінка та призначення |
| :--- | :--- | :--- |
| `swiotlb=<N>` | Ціле десяткове число | Встановлює загальну кількість слотів у пулі (кожен слот дорівнює 2 КіБ). Наприклад, `swiotlb=131072` виділяє 256 МіБ оперативної пам'яті. |
| `swiotlb=<size>[KMG]` | Розмір із суфіксом | Встановлює точний розмір пулу пам'яті. Наприклад, `swiotlb=128M` створює пул на 65536 слотів. |
| `swiotlb=force` | Прапорець без значення | Вмикає примусове проходження всіх DMA-операцій через підмінні буфери, навіть якщо пристрій підтримує 64-бітну адресацію і може досягти буфера напряму. |
| `swiotlb=noforce` | Прапорець без значення | Вимикає примусову підміну. Підмінні буфери задіюються виключно тоді, коли буфер фізично лежить поза адресною маскою пристрою. |
| `swiotlb=nobounce` | Прапорець без значення | Повністю блокує використання підмінних буферів. Якщо адреса недосяжна для пристрою, `dma_map_single()` повертає `DMA_MAPPING_ERROR`. |
| `swiotlb=<N>,force` | Комбіноване значення | Одночасно виділяє вказану кількість слотів та активує режим примусової підміни (типовий вибір для захищених віртуальних машин). |

## Вузли діагностичної файлової системи debugfs

Якщо ядро зібрано з увімкненою файловою системою debugfs (`CONFIG_DEBUG_FS=y`), у каталозі `/sys/kernel/debug/swiotlb/` створюються такі системні файли:

| Вузол у debugfs | Тип доступу | Опис системної метрики |
| :--- | :--- | :--- |
| `io_tlb_nslabs` | Тільки читання | Загальна кількість слотів по 2 КіБ, виділених у поточному активному пулі пам'яті. |
| `io_tlb_used` | Тільки читання | Поточна кількість слотів, що прямо зараз утримуються активними DMA-відображеннями. |
| `io_tlb_used_highwater` | Читання й запис | Максимальна пікова кількість одночасно зайнятих слотів з моменту завантаження ядра або останнього скидання. Запис значення `0` очищує пік. |
| `io_tlb_overflow` | Тільки читання | Лічильник випадків вичерпання пулу, коли запит на виділення слотів повернув помилку через брак пам'яті. |
| `force_bounce` | Читання й запис | Прапорець примусової підміни: `1` змушує всі наступні відображення проходити через swiotlb, `0` повертає стандартну поведінку за маскою пристрою. |

## Події трасування ядра ftrace

Для динамічного моніторингу затримок і частоти викликів підсистема swiotlb містить вбудовану подію трасування в каталозі `/sys/kernel/tracing/events/swiotlb/swiotlb_bounced/`:

```text
swiotlb:swiotlb_bounced(
    const char *dev_name,
    dma_addr_t dev_addr,
    size_t size,
    size_t alloc_size
)
```

Ця подія генерується щоразу, коли ядро змушене виконати `memcpy` для підмінного буфера. Наявність полів `size` (корисний розмір) та `alloc_size` (виділений розмір із вирівнюванням) дозволяє виявляти надмірну фрагментацію та внутрішні втрати пам'яті під час передачі малих незбіжних блоків.
