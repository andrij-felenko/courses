# 📋 Каталог інтерфейсів та файлів procfs

Цей довідник містить детальний систематизований опис точок доступу, структур даних, полів, одиниць вимірювання та внутрішніх специфікацій файлової системи `procfs` у ядрі Linux. Він призначений для розробників системного програмного забезпечення, інженерів з продуктивності та адміністраторів, яким необхідно здійснювати точну інтерпретацію метрик спостережуваності та конфігураційних файлів ядра.

---

## 1. Специфікація полів та лічильників `/proc/[pid]/stat`

Файл `/proc/[pid]/stat` містить стан процесу у вигляді одного текстового рядка з полями, розділеними пробілами. Ядро Linux формує цей рядок у функції `proc_tgid_stat()` за допомогою системного ітератора `seq_file`. Оскільки цей файл зчитується системними утилітами моніторингу (`ps`, `top`, `htop`, `glances`) тисячі разів на секунду, формати полів жорстко зафіксовані й прономеровані з 1 відповідно до стандартів POSIX та документації ядра `proc(5)`:

| Порядковий № | Назва поля у ядрі | Тип даних | Докладний опис, одиниці вимірювання та механізм ядра |
| :--- | :--- | :--- | :--- |
| **1** | `pid` | `int` | Ідентифікатор процесу (Process ID) у поточному просторі імен `PID namespace`. |
| **2** | `comm` | `char[]` | Назва виконуваного файлу в круглих дужках (наприклад `(bash)` чи `(nginx)`). Обрізається ядром до 16 символів (`TASK_COMM_LEN`). Може містити будь-які символи, включно з пробілами та дужками. |
| **3** | `state` | `char` | Поточний стан процесу з точки зору планувальника задач: `R` (Running / Runnable), `S` (Interruptible sleep), `D` (Uninterruptible disk sleep), `Z` (Zombie), `T` (Stopped by signal), `t` (Tracing stop), `W` (Paging — лише до ядра 2.6), `X` (Dead). |
| **4** | `ppid` | `int` | Ідентифікатор батьківського процесу (Parent PID). |
| **5** | `pgrp` | `int` | Ідентифікатор групи процесів (Process Group ID). |
| **6** | `session` | `int` | Ідентифікатор сесії процесу (Session ID). |
| **7** | `tty_nr` | `int` | Номер керуючого термінала процесу (розбивається на major/minor номери пристрою). Дорівнює 0, якщо процес не має термінала. |
| **8** | `tpgid` | `int` | Ідентифікатор процесної групи термінала, яка в даний момент виконується на передньому плані (foreground process group). |
| **9** | `flags` | `unsigned` | Прапорці ядра (внутрішня бітова маска `task_struct->flags`, наприклад `PF_KTHREAD` для потоків ядра чи `PF_EXITING` для тих, що завершуються). |
| **10** | `minflt` | `unsigned long` | Кількість незначних (minor) помилок сторінки пам'яті (Page Faults), які не вимагали зчитування даних із дискового накопичувача. |
| **11** | `cminflt` | `unsigned long` | Кількість незначних помилок сторінки пам'яті для всіх завершених дочірніх процесів, очікуваних через `waitpid()`. |
| **12** | `majflt` | `unsigned long` | Кількість значних (major) помилок сторінки пам'яті, які вимагали звернення до диска (зчитування коду, mmap-файлів чи сторінок підкачки Swap). |
| **13** | `cmajflt` | `unsigned long` | Кількість значних помилок сторінки пам'яті для всіх завершених дочірніх процесів. |
| **14** | `utime` | `unsigned long` | Час виконання процесу в режимі користувача (User CPU time), виміряний у системних тиках `clock ticks` (значення `USER_HZ`, зазвичай 100 тиків на секунду). |
| **15** | `stime` | `unsigned long` | Час виконання процесу в режимі ядра (System CPU time), виміряний у тиках CPU. |
| **16** | `cutime` | `long` | Час виконання у режимі користувача для всіх завершених дочірніх процесів. |
| **17** | `cstime` | `long` | Час виконання у режимі ядра для всіх завершених дочірніх процесів. |
| **18** | `priority` | `long` | Поточний пріоритет планування ядра (значення від -100 для задач реального часу RT до 39). |
| **19** | `nice` | `long` | Значення рівності процесу `nice` (від -20 найвищий пріоритет до 19 найнижчий). |
| **20** | `num_threads` | `long` | Кількість активних потоків виконання у цій групі процесів (`thread group`). |
| **21** | `itrealvalue` | `long` | Час до наступного сигналу `SIGALRM` у тиках (застаріло у сучасних ядрах, завжди дорівнює 0). |
| **22** | `starttime` | `unsigned long long` | Час запуску процесу після завантаження системи, виміряний у системних тиках від `boot time`. |
| **23** | `vsize` | `unsigned long` | Загальний обсяг віртуальної пам'яті процесу в байтах (Virtual Memory Size). |
| **24** | `rss` | `long` | Resident Set Size: кількість фізичних сторінок пам'яті у RAM, зайнятих процесом. Щоб отримати обсяг у байтах, значення множать на розмір сторінки пам'яті `sysconf(_SC_PAGESIZE)`. |
| **25** | `rsslim` | `unsigned long` | Поточний ліміт RSS у байтах (значення `RLIMIT_RSS`). |
| **26-52** | `startcode` .. `exit_code` | `unsigned long` | Внутрішні адреси сегментів коду, стека, покажчик інструкцій IP, покажчик стека SP, маски заблокированих та ігнорованих сигналів. |

### Механізм обчислення завантаження CPU

Утиліти моніторингу не можуть визначити миттєве використання CPU з одного зчитування `/proc/[pid]/stat`. Вони зчитують значення `utime` та `stime` у момент часу `T1`, чекають інтервал `delta_T`, зчитують значення у момент `T2` і розраховують відсоток завантаження процесора:

```
delta_ticks = (utime[2] + stime[2]) - (utime[1] + stime[1])
cpu_usage   = (delta_ticks / (delta_T · USER_HZ · num_cores)) · 100%
```

## 2. Структура файлу `/proc/[pid]/status`

Файл `/proc/[pid]/status` надає форматований текстовий вивід статистик процесу у вигляді пар `Ключ: Значення`. Він використовується системними адміністраторами для аналізу привілеїв, лімітів пам'яті та системних сигналів.

### Пояснення ключових секцій `/proc/[pid]/status`:

1. **Ідентифікатори користувачів та груп (`Uid`, `Gid`)**:
   Наводять 4 значення у порядку: Real (реальний), Effective (ефективний), Saved (збережений) та Filesystem (файловий) UID/GID. Зміна ефективного UID (eUID) відбувається при виконанні setuid-бінарників.
2. **Метрики віртуальної та фізичної пам'яті (`Vm*`)**:
   - `VmPeak`: Піковий обсяг віртуальної пам'яті за увесь час життя процесу.
   - `VmSize`: Поточний обсяг віртуальної пам'яті.
   - `VmHWM`: High Water Mark — піковий обсяг фізичної пам'яті (RSS) за час життя процесу.
   - `VmRSS`: Поточна фізична пам'ять у RAM, яка розбивається на `RssAnon` (анонімна пам'ять), `RssFile` (маповані файли) та `RssShmem` (спільна пам'ять).
   - `VmData`, `VmStk`, `VmExe`, `VmLib`: Розміри окремих сегментів купи, стека, коду виконуваного бінарника та динамічних бібліотек.
   - `VmPTE` / `VmPMD`: Обсяг оперативної пам'яті ядра, виділений під самі таблиці сторінок даного процесу.
3. **Маски системних сигналів (`Sig*`)**:
   Наводять 64-бітну маску сигналів у 16-ричному форматі: `SigPnd` (очікувані сигналі потоку), `ShdPnd` (сигнали групи процесів), `SigBlk` (заблоковані сигналі), `SigIgn` (ігноровані), `SigCgt` (перехоплювані власними обробниками).
4. **Маски привілеїв та capabilities (`Cap*`)**:
   - `CapInh`: Наслідувані привілеї (Inheritable capabilities).
   - `CapPrm`: Дозволені привілеї (Permitted capabilities).
   - `CapEff`: Ефективні діючі привілеї (Effective capabilities).
   - `CapBnd`: Обмежувальна маска (Capability Bounding Set).
   - `CapAmb`: Амбієнтні привілеї (Ambient capabilities).
5. **Контекстні перемикання (`voluntary_ctxt_switches`, `nonvoluntary_ctxt_switches`)**:
   - `voluntary`: Кількість добровільних перемикань контексту, коли процес сам заблокувався на виклику вводу/выводу (`read`, `poll`, `mutex_lock`).
   - `nonvoluntary`: Кількість примусових перемикань контексту, коли планувальник ядра вичерпав квант часу процесу (`time slice`) і передав CPU іншому процесу.

## 3. Структура файлів віртуальної пам'яті: `/proc/[pid]/maps` та `/proc/[pid]/smaps`

Файл `/proc/[pid]/maps` описує всі безперервні регіони віртуальної пам'яті (VMA — `vm_area_struct`), які виділені процесу його мапою пам'яті `mm_struct`.

```text
address           perms offset  dev   inode       pathname
00400000-00452000 r-xp 00000000 08:02 1234567     /usr/bin/dbus-daemon
00651000-00652000 r--p 00051000 08:02 1234567     /usr/bin/dbus-daemon
00652000-00653000 rw-p 00052000 08:02 1234567     /usr/bin/dbus-daemon
01234000-01255000 rw-p 00000000 00:00 0           [heap]
7ffda1200000-7ffda1221000 rw-p 00000000 00:00 0   [stack]
7ffda1300000-7ffda1302000 r--p 00000000 00:00 0   [vvar]
7ffda1302000-7ffda1304000 r-xp 00000000 00:00 0   [vdso]
```

### Деталізація полів карти пам'яті:

1. **`address`**: Початкова та кінцева віртуальна адреса регіону пам'яті у 16-нному форматі (`start-end`).
2. **`perms`**: 4-символьний рядок прав доступу до сторінок:
   - Позиція 1: `r` (читання дозволено) або `-`.
   - Позиція 2: `w` (запис дозволено) або `-`.
   - Позиція 3: `x` (виконання дозволено) або `-`.
   - Позиція 4: `p` (приватний регіон `private`, механізм Copy-On-Write) або `s` (спільна пам'ять `shared`).
3. **`offset`**: Зміщення у байтах від початку файлу, якщо регіон відображає диск.
4. **`dev`**: Номер блочного пристрою у 16-нному форматі (`major:minor`), на якому лежить файл.
5. **`inode`**: Номер файлового вузла `inode` на файловій системі. Значення `0` вказує на анонімну пам'ять (`anonymous memory`), створену через `mmap(MAP_ANONYMOUS)` або `brk()`.
6. **`pathname`**: Абсолютний шлях до мапованого файлу на диску або псевдонім ядра:
   - `[heap]`: Динамічна купа процесу, яка керується через `brk()`.
   - `[stack]`: Основний стек головного потоку процесу.
   - `[stack:TID]`: Стек конкретного додаткового потоку `TID`.
   - `[vdso]`: Virtual Dynamic Shared Object — спеціальна сторінка ядра для прискорення системних викликів (`gettimeofday`, `clock_gettime`) у користувацькому просторі без перемикання контексту.
   - `[vvar]`: Змінні ядра, які використовуються кодом vDSO.
   - `[anon_shmem]`: Спільна анонімна пам'ять `POSIX shared memory`.

### Детальна статистика у `/proc/[pid]/smaps`

Файл `/proc/[pid]/smaps` надає глибокий розріз використання фізичної оперативної пам'яті для кожного VMA регіону:

- **`Size`**: Загальний віртуальний розмір регіону пам'яті.
- **`KernelPageSize` / `MMUPageSize`**: Розмір сторінки пам'яті апаратного юніта MMU (зазвичай 4 КБ).
- **`Rss` (Resident Set Size)**: Обсяг фізичної пам'яті, який у даний момент завантажено у RAM для цього регіону.
- **`Pss` (Proportional Set Size)**: Пропорційна частка фізичної пам'яті. Якщо 10 процесів мапують спільну бібліотеку розміром 40 МБ, `Pss` кожного процесу становитиме 4 МБ. Сума `Pss` по всіх процесах дає точне фізичне споживання RAM системою.
- **`Shared_Clean`**: Обсяг спільної пам'яті, яка не модифікувалася (код бінарників та бібліотек).
- **`Shared_Dirty`**: Обсяг спільної пам'яті, модифікованої процесом (зазвичай спільні буфери IPC).
- **`Private_Clean`**: Обсяг приватної пам'яті, яка збігається з дисковим файлом.
- **`Private_Dirty`**: Обсяг приватної пам'яті, виділеної під змінні, купу та стек, яка вимагатиме скидання в Swap при дефіциті RAM.
- **`Referenced`**: Обсяг пам'яті, до якої процесор звертався останнім часом (використовується алгоритмом витіснення сторінок LRU).
- **`Anonymous`**: Пам'ять, не пов'язана з жодним файлом на диску.
- **`Swap` / `SwapPss`**: Обсяг сторінок цього регіону, які були витіснені у розділ підкачки Swap.

## 4. Каталог відкритих дескрипторів: `/proc/[pid]/fd/` та `/proc/[pid]/fdinfo/`

Каталог `/proc/[pid]/fd/` містить віртуальні символічні посилання для кожного файлового дескриптора, відкритого процесом у таблиці `files_struct`:

```bash
$ ls -l /proc/1234/fd/
lr-x------ 1 root root 64 Aug 14 12:00 0 -> /dev/null
lrwx------ 1 root root 64 Aug 14 12:00 1 -> /var/log/app.log
lrwx------ 1 root root 64 Aug 14 12:00 2 -> /var/log/app.err
lrwx------ 1 root root 64 Aug 14 12:00 3 -> 'socket:[98765]'
lr-x------ 1 root root 64 Aug 14 12:00 4 -> 'anon_inode:[eventpoll]'
lr-x------ 1 root root 64 Aug 14 12:00 5 -> 'anon_inode:[signalfd]'
```

### Структура файлів у `/proc/[pid]/fdinfo/[fd]`

Файли у підкаталозі `fdinfo/` містять метадані про поточний стан файлового покажчика та специфічні прапорці ядра:

```text
pos:    1048576
flags:  0100002
mnt_id: 24
ino:    123456
```

- **`pos`**: Поточне зміщення покажчика читання/запису у файлі в байтах.
- **`flags`**: Вісімкове значення прапорців відкриття файлу (`O_RDWR`, `O_NONBLOCK`, `O_CLOEXEC`, `O_APPEND`).
- **`mnt_id`**: Ідентифікатор точки монтування у `/proc/self/mountinfo`.
- **Для `eventpoll` дескрипторів (`epoll`)**: Файл `fdinfo` додатково перераховує всі файлові дескриптори, додані у підсистему моніторингу подій, із їхніми масками `tfd`, `events`, `data`.
- **Для `timerfd` дескрипторів**: Відображає інтервал та час до наступного спрацьовування таймера.
- **Для `inotify` дескрипторів**: Містить перелік масок та інодів усіх каталогів, за якими встановлено спостереження.

## 5. Системна статистика пам'яті: `/proc/meminfo`

Файл `/proc/meminfo` надає вичерпну інформацію про підсистему віртуальної пам'яті системи. Усі значення наводяться у кілобайтах (`1 kB = 1024 bytes`):

- **`MemTotal`**: Загальна фізична оперативна пам'ять RAM, яка доступна ядру після завантаження.
- **`MemFree`**: Обсяг абсолютно вільної пам'яті RAM, яка взагалі не використовується системою.
- **`MemAvailable`**: Оцінка обсягу пам'яті, доступного для запуску нових застосунків без створення дефіциту та витіснення в Swap:
  ```
  MemAvailable = MemFree + Cached + SReclaimable - Watermarks
  ```
- **`Buffers`**: Пам'ять, виділена під буфери сирих блоків дискових пристроїв.
- **`Cached`**: Обсяг сторінкового кешу (`page cache`), який зберігає зчитані з диска файли.
- **`SwapTotal` / `SwapFree`**: Загальний та вільний обсяг підсистеми підкачки Swap.
- **`Active` / `Inactive`**: Пам'ять у списку активного та неактивного використання (неактивна пам'ять першою витісняється при дефіциті RAM).
- **`Active(anon)` / `Inactive(anon)`**: Анонімна пам'ять процесів (купа, стек).
- **`Active(file)` / `Inactive(file)`**: Пам'ять сторінкового кешу файлів.
- **`Unevictable`**: Пам'ять, заблокована у RAM системним викликом `mlock()`, яку заборонено витісняти на диск.
- **`Mlocked`**: Загальний обсяг заблокованої пам'яті.
- **`Dirty`**: Пам'ять сторінкового кешу, яка була модифікована процесами й очікує запису на диск фоновим потоком `kswapd` / `wb`.
- **`Writeback`**: Пам'ять, яка в даний момент фізично записується контролером диска.
- **`AnonPages`**: Обсяг анонімних сторінок, мапованих у таблиці сторінок процесів.
- **`Mapped`**: Пам'ять файлів, мапованих через `mmap()`.
- **`Shmem`**: Обсяг спільної пам'яті (`tmpfs`, `devtmpfs`, `POSIX IPC`).
- **`Slab`**: Пам'ять, виділена під внутрішні об'єкти ядра алокатором `Slab/Slub`.
- **`SReclaimable`**: Частина пам'яті Slab (наприклад кеш інодів dentries), яку ядро може звільнити при дефіциті RAM.
- **`SUnreclaim`**: Незвільнювана частина пам'яті Slab під критичні структури ядра.
- **`KernelStack`**: Пам'ять, виділена під стеки режимів ядра для всіх потоків (зазвичай 16 КБ на потік).
- **`PageTables`**: Пам'ять, виділена під самі таблиці сторінок (PGD, P4D, PUD, PMD, PTE) усіх процесів.
- **`Bounce`**: Пам'ять під буфери для застарілих пристроїв DMA.
- **`VmallocTotal` / `VmallocUsed`**: Загальний та використаний простір адресної пам'яті `vmalloc`.
- **`HugePages_Total` / `HugePages_Free`**: Статистика використання великих сторінок пам'яті (HugeTLB 2 МБ / 1 ГБ).

## 6. Системна статистика CPU: `/proc/stat`

Файл `/proc/stat` містить агреговані лічильники виконання CPU від моменту завантаження системи. Усі значення наводяться у системних тиках (`clock ticks` `USER_HZ`):

```text
cpu  123456 234 45678 9876543 1234 567 890 0 0 0
cpu0 61728 117 22839 4938271 617 283 445 0 0 0
cpu1 61728 117 22839 4938272 617 284 445 0 0 0
intr 12345678 0 0 10 ...
ctxt 987654321
btime 1700000000
processes 54321
procs_running 2
procs_blocked 0
softirq 1234567 0 123 456 ...
```

### Значення стовпчиків у рядку `cpu`:
1. `user`: Час виконання звичайних процесів у режимі користувача.
2. `nice`: Час виконання процесів зі зниженим пріоритетом (`nice > 0`).
3. `system`: Час виконання коду ядра у системних викликах.
4. `idle`: Час простою CPU у стані очікування задач.
5. `iowait`: Час простою CPU під час очікування завершення дискових операцій вводу/виводу.
6. `irq`: Час обробки апаратних переривань (Hardware IRQs).
7. `softirq`: Час обробки програмних переривань (Software IRQs / Softirqs).
8. `steal`: Час, "вкрадений" гіпервізором віртуалізації у віртуальної машини.
9. `guest`: Час виконання віртуального процесора гостьової ОС під KVM.
10. `guest_nice`: Час виконання гостьової ОС із пріоритетом nice.

### Решта системних лічильників у `/proc/stat`:
- **`ctxt`**: Загальна сукупна кількість перемикань контексту (`context switches`) між процесами від моменту запуску системи.
- **`btime`**: Час завантаження системи у форматі Unix Timestamp (секунди з 1 січня 1970 року).
- **`processes`**: Загальна кількість створених процесів у системі (сумарна кількість системних викликів `fork()`/`clone()`).
- **`procs_running`**: Кількість процесів, які у даний момент знаходяться у стані виконання `R` (Running).
- **`procs_blocked`**: Кількість процесів, заблокованих у стані очікування дискового вводу/виводу `D` (Uninterruptible disk sleep).

## 7. Довідник параметрів `/proc/sys/` (sysctl)

Каталог `/proc/sys/` розгортає структуру параметрів `sysctl` у вигляд дерева файлів:

| Шлях до файлу у `/proc/sys/` | Тип даних | Діапазон / Одиниці | Опис та вплив на поведінку ядра |
| :--- | :--- | :--- | :--- |
| `kernel/pid_max` | `int` | 301 до 4194304 | Максимально можливе значення PID у системі. При досягненні ліміту ядро закольцовує нумерацію PID. |
| `kernel/threads-max` | `int` | `1 .. INT_MAX` | Максимальна сукупна кількість потоків виконання для всіх процесів у системі. |
| `kernel/hostname` | `string` | До 64 символів | Мережеве ім'я вузла (hostname). Зміна записом у файл рівносильна виклику `sethostname()`. |
| `kernel/panic` | `int` | Секунди | Затримка у секундах перед автоматичним перезавантаженням після паніки ядра Kernel Panic (0 — вимкнено). |
| `kernel/random/entropy_avail` | `int` | Біти | Обсяг доступної ентропії у системному генераторі випадкових чисел `/dev/urandom`. |
| `vm/swappiness` | `int` | 0 до 200 | Агресивність витіснення анонімної пам'яті в Swap. Значення 0 вимикає витіснення анонімних сторінок до крайньої потреби, 100 означає рівні права анонімної пам'яті та кешу файлів. |
| `vm/drop_caches` | `int` | 1, 2, 3 | Запис тригерує звільнення кешів: 1 — pagecache, 2 — dentries/inodes, 3 — pagecache + dentries/inodes. |
| `vm/overcommit_memory` | `int` | 0, 1, 2 | Політика виділення пам'яті: 0 — евристичний оверкоміт, 1 — дозволяти оверкоміт завжди, 2 — суворий ліміт `overcommit_ratio`. |
| `vm/dirty_ratio` | `int` | Відсоток RAM | Максимальний відсоток пам'яті з "брудними" сторінками, при досягненні якого процеси блокуються на виклику `write()` до скидання даних на диск. |
| `net/ipv4/ip_forward` | `boolean` | 0 або 1 | Прапорець маршрутизації IP-пакетів між мережевими інтерфейсами. |
| `net/core/somaxconn` | `int` | Сокети | Максимальне значення аргументу `backlog` у системному виклику `listen()` для сокетів TCP. |
| `fs/file-max` | `unsigned long` | Дескриптори | Максимальна загальна кількість відкритих файлових дескрипторів у всій системі. |
