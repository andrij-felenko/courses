# 📋 Інструменти потокової обробки: кодування, кінці рядків і NUL-роздільники

Цей довідник містить систематизований опис командних утиліт POSIX та Linux, їхніх специфічних прапорців, системних викликів, поведінки буферизації та кодів повернення під час роботи з різними кодуваннями тексту, маркерами кінців рядків і нульовим байтом `0x00` (NUL) як безпечним роздільником.

## 1. Конвертація кодувань: утиліта та інтерфейс `iconv`

Утиліта командного рядка `iconv` є обгорткою над однойменним набором бібліотечних функцій POSIX (`iconv_open`, `iconv`, `iconv_close`). Її головне завдання — перетворення байтового потоку з одного набору символів у інший (наприклад, з успадкованих однобайтових кодувань `CP1251`, `KOI8-U` або `ISO-8859-5` у стандартне мультибайтове кодування `UTF-8`).

```sh
iconv -f <FROM_ENCODING> -t <TO_ENCODING> [options] [file...]
```

### Системний механізм обробки помилок та стану

На рівні системної бібліотеки `libc` функція `iconv()` підтримує внутрішній дескриптор перетворення `iconv_t`. Під час потокової обробки виникають три типові ситуації, які утиліта транслює у відповідні коди завершення:

1. **Невалідний байт (`EILSEQ`):** Вхідний потік містить послідовність байтів, що не належить до зазначеного вхідного кодування `-f`. За замовчуванням утиліта негайно перериває роботу з кодом `1` та виводить позицію помилки.
2. **Неповний символ на межі буфера (`EINVAL`):** Мультибайтовий символ розірвано між двома блоками читання `read()`. Бібліотека очікує наступну порцію даних, зберігаючи проміжний стан.
3. **Переповнення вихідного буфера (`E2BIG`):** Вихідний буфер заповнено, програма повинна скинути дані через `write()` і продовжити обробку.

### Основні прапорці та суфікси

| Прапорець / Суфікс | Призначення | Поведінка при виявленні помилки |
|---|---|---|
| `-f <enc>`, `--from-code` | Вхідне кодування потоку. | Якщо не вказано, береться поточне значення локалі `LC_CTYPE`. |
| `-t <enc>`, `--to-code` | Вихідне кодування потоку. | Якщо не вказано, береться поточне значення локалі `LC_CTYPE`. |
| `-o <file>`, `--output` | Запис результату у файл замість `stdout`. | Файл створюється або перезаписується атомарно після відкриття. |
| `-c` | Мовчки відкидати невалідні байти у вхідному потоці. | Запобігає аварійній зупинці конвеєра при пошкоджених байтах. |
| `//TRANSLIT` (суфікс до `-t`) | Транслітерація непідтримуваних символів у схожі гліфи цільового набору. | Якщо візуального аналога немає, символ замінюється на знак питання `?`. |
| `//IGNORE` (суфікс до `-t`) | Мовчки ігнорувати символи, які неможливо представити в цільовому кодуванні. | Несумісні символи вилучаються з вихідного потоку. |
| `-l`, `--list` | Вивести перелік усіх підтримуваних кодувань. | Завершує роботу з кодом `0`. |

```sh
# Надійне перетворення файлу з CP1251 в UTF-8 з відкиданням пошкоджених байтів
iconv -f CP1251 -t UTF-8//IGNORE -o converted.txt input_cp1251.txt
```

## 2. Керування кінцями рядків та BOM: `dos2unix` та `unix2dos`

Утиліти `dos2unix` та `unix2dos` призначені для масової та надійної конвертації маркерів кінця рядка між форматами CRLF (`0x0D 0x0A`, Windows/DOS) та LF (`0x0A`, Unix/Linux). Вони також контролюють наявність або відсутність маркера порядку байтів UTF-8 BOM (`0xEF 0xBB 0xBF`).

```sh
dos2unix [options] [-n infile outfile ...] [file ...]
unix2dos [options] [-n infile outfile ...] [file ...]
```

### Механіка безпечної заміни файлів на місці

За замовчуванням `dos2unix` працює в режимі заміни на місці (in-place). Щоб запобігти втраті даних при раптовому вимкненні живлення чи збої диска, утиліта створює тимчасовий файл у тому самому каталозі, виконує потокове перетворення, копіює права доступу (`chmod`), власника (`chown`) і лише після успішного закриття файлу викликає системний виклик `rename()`.

Сучасні версії `dos2unix` об'єднують функціональність старого пакета `mac2unix`: вони однаково надійно обробляють як пари `\r\n` (CRLF), так і поодинокі символи `\r` (стиль Mac OS до версії OS X).

| Прапорець | Опис дії та вплив на файлову систему |
|---|---|
| `-k`, `--keepdate` | Зберігати оригінальну часову позначку модифікації файлу (`mtime`) незмінною. |
| `-n <in> <out>`, `--newfile` | Режим нового файлу: читати з `<in>`, писати в `<out>` без модифікації оригіналу. |
| `-o <file>`, `--oldfile` | Перезаписувати вхідний файл на місці через безпечний атомарний `rename()`. |
| `-q`, `--quiet` | Приховати інформаційні повідомлення та попередження про бінарні файли. |
| `-r`, `--remove-bom` | Видалити UTF-8 BOM (`0xEF 0xBB 0xBF`), якщо він присутній на початку файлу. |
| `-m`, `--add-bom` | Додати UTF-8 BOM на початок вихідного файлу. |
| `-u`, `--keep-bom` | Зберігати наявність або відсутність BOM у вихідному файлі без змін. |
| `-f`, `--force` | Примусова конвертація, навіть якщо у файлі виявлено бінарні нульові байти. |

## 3. Базові фільтри потоку: `tr`, `sed`, `awk`

### Утиліта `tr` (Translate / Delete)

Утиліта `tr` є найшвидшим фільтром операційної системи, оскільки її алгоритм базується на прямій 256-елементній таблиці підстановки в оперативній пам'яті. Вона читає потік блоками та працює **виключно з 1-байтовими октетами**.

```sh
# Видалення всіх символів Carriage Return (\r, 0x0D) з вхідного потоку
tr -d '\r' < input.txt > output.txt

# Заміна нульового байта (0x00) на символ нового рядка \n (0x0A)
tr '\0' '\n' < null_separated.bin > lines.txt

# Очищення тексту від недрукованих керуючих символів, крім табуляції та перенесення рядка
tr -cd '\11\12\40-\176' < raw_input.txt > clean_ascii.txt
```

> ⚠️ **Архітектурне обмеження `tr`:** Оскільки `tr` не знає про багатобайтову структуру UTF-8, заміна символів з не-ASCII діапазону (наприклад, спроба замінити літеру «і» на «i») призведе до заміни окремих байтів усередині мультибайтових послідовностей, що неминуче пошкодить сусідні символи тексту.

### Утиліта `sed` (Stream Editor)

На відміну від `tr`, потоковий редактор `sed` дозволяє застосовувати контекстні регулярні вирази, видаляючи символ `\r` лише наприкінці рядка.

```sh
# Видалення \r тільки тоді, коли він стоїть безпосередньо перед кінцем рядка
sed -i 's/\r$//' filename.sh

# Адресне видалення трьох байтів UTF-8 BOM на самому початку першого рядка файлу
sed -i '1s/^\xEF\xBB\xBF//' script.py

# Робота з потоками, де роздільником є нульовий байт (GNU sed, ключ -z)
sed -z 's/старе_значення/нове_значення/g' < input_nul.bin > output_nul.bin
```

### Утиліта `awk`

Утиліта `awk` розділяє потік на записи (records) та поля (fields). Керування роздільниками виконується через спеціальні системні змінні:

- `RS` (Record Separator) — роздільник вхідних записів (типово `\n`).
- `ORS` (Output Record Separator) — роздільник вихідних записів (типово `\n`).
- `FS` (Field Separator) — роздільник полів усередині запису (типово пробіл або табуляція).

```sh
# Безпечна обробка файлів як з LF, так і з CRLF без збереження сміттєвого \r у змінних
awk 'BEGIN { RS="\r?\n" } { print "Оброблено:", $1 }' data.csv

# Обробка потоку, розділеного нульовими байтами, з виводом через стандартний LF
awk 'BEGIN { RS="\0"; ORS="\n" } { print "Файл:", $0 }'
```

## 4. Конвеєри з нульовим байтом: `find`, `xargs`, `sort`, `cut`, `grep`

Символ `0x00` (NUL) — єдиний байт, який фундаментально не може входити до складу імен файлів Unix, оскільки ядро використовує його як обмежувач рядків у мові C. Це робить NUL єдиним математично надійним роздільником для системних конвеєрів.

### Прапорці утиліт для роботи з NUL-роздільниками

| Утиліта | Прапорець | Призначення прапорця | Приклад у системному конвеєрі |
|---|---|---|---|
| `find` | `-print0` | Виводити повні шляхи файлів, розділяючи їх байтом `\0` замість `\n`. | `find . -type f -name "*.log" -print0` |
| `xargs` | `-0`, `--null` | Розбирати аргументи виключно по байту `\0`, вимикаючи парсинг лапок та пробілів. | `find . -print0 \| xargs -0 -r rm -f` |
| `sort` | `-z`, `--zero-terminated` | Вважати кінцем рядка байт `\0`, що дозволяє сортувати шляхи з переносами рядків. | `find . -print0 \| sort -z` |
| `cut` | `-z`, `--zero-terminated` | Читати та фільтрувати поля з роздільником записів `\0`. | `cut -z -d '/' -f 3-` |
| `grep` | `-Z`, `--null` | Додавати `\0` після імені знайденого файлу замість двокрапки `:`. | `grep -lZ "ERROR" *.log \| xargs -0 gzip` |
| `grep` | `-z`, `--null-data` | Розглядати вхідні дані як потік, розділений `\0`, ігноруючи внутрішні `\n`. | `grep -z "рядок1.*рядок2" dump.bin` |
| `read` (Bash) | `-d ''` | Читати потік до першого знайденого байта `\0`. | `while IFS= read -r -d '' f; do ...; done` |

### Механізм пакетування в `xargs` та ліміти ядра `ARG_MAX`

Коли утиліта `xargs -0` зчитує тисячі імен файлів, вона не викликає цільову програму для кожного файлу окремо (що було б занадто повільно через накладні витрати на `fork`/`execve`). Замість цього `xargs` накопичує максимальну кількість аргументів у межах системного ліміту ядра Linux `ARG_MAX` (зазвичай від 2 МіБ до 6 МіБ, доступно для перевірки через `getconf ARG_MAX` або `xargs --show-limits`), після чого викликає одну команду:

```sh
# Пошук, сортування та безпечне видалення старих логів незалежно від символів в іменах
find /var/log -type f -name "*.log" -mtime +30 -print0 | sort -z | xargs -0 -r rm -f
```

Прапорець `-r` (`--no-run-if-empty`) в `xargs` критично важливий для скриптів автоматизації: він запобігає виклику цільової команди з порожнім списком аргументів, якщо `find` не повернув жодного файлу.

### Продуктивність сортування: вплив локалі на `sort -z`

Під час сортування великих масивів шляхів або текстових записів у конвеєрі `sort -z` поведінка утиліти суттєво залежить від змінної оточення `LC_ALL`:

- Якщо активна юнікодна локаль (наприклад, `uk_UA.UTF-8` або `en_US.UTF-8`), утиліта `sort` застосовує складні алгоритми мовного сортування Unicode Collation Algorithm (з урахуванням регістру, діакритики та правил еквівалентності), що вимагає виклику `strcoll()`.
- Якщо перед конвеєром встановити байтову локаль `LC_ALL=C`, утиліта перемикається на пряме побайтове порівняння через `memcmp()`. Це прискорює сортування у 10–50 разів і гарантує детермінований порядок байтів без прив'язки до системних мовних таблиць.

```sh
# Високошвидкісне побайтове сортування списку файлів
find /data -type f -print0 | LC_ALL=C sort -z | xargs -0 -r process_files
```

## 5. Інструменти низькорівневого байтового аналізу

Коли скрипт або конвеєр завершується з незрозумілою помилкою синтаксису, інженери використовують утиліти побайтового дампу для виявлення невидимих керуючих символів `\r`, маркерів BOM чи невалідних послідовностей UTF-8.

### Утиліта `file`

Утиліта `file` аналізує магічні числа та структуру файлу за допомогою бібліотеки `libmagic`:

```sh
$ file script.sh
script.sh: Bourne-Again shell script, UTF-8 Unicode (with BOM) text executable, with CRLF line terminators
```

### Утиліти `hexdump` та `od` (Octal Dump)

```sh
# Перегляд перших 16 байтів файлу в шістнадцятковому та символьному вигляді
hexdump -C -n 16 script.sh
# 00000000  ef bb bf 23 21 2f 62 69  6e 2f 73 68 0d 0a 65 63  |...#!/bin/sh..ec|

# Посимвольне відображення керуючих кодів через od
od -c script.sh | head -n 2
# 0000000   #   !   /   b   i   n   /   s   h  \r  \n   e   c   h   o
```

## 6. Налаштування обробки кінців рядків у Git

Система контролю версій Git дозволяє уніфікувати збереження файлів у спільних репозиторіях, запобігаючи випадковому коміту символів `\r` розробниками на платформі Windows.

### Конфігурація на рівні репозиторію: `.gitattributes`

Файл `.gitattributes` у корені проєкту має найвищий пріоритет над локальними конфігураціями користувачів:

```gitattributes
# Автоматичне визначення текстових файлів: нормалізація в LF при збереженні в репозиторій
* text=auto

# Скрипти оболонок Linux завжди повинні мати LF у робочому дереві на будь-якій ОС
*.sh text eol=lf
*.bash text eol=lf

# Специфічні сценарії Windows завжди вивантажуються з CRLF
*.bat text eol=crlf
*.cmd text eol=crlf

# Бінарні формати виключаються з будь-яких текстових евристик
*.png binary
*.tar.gz binary
```

### Конфігурація клієнта: `core.autocrlf`

| Параметр `core.autocrlf` | Дія під час `git commit` | Дія під час `git checkout` | Рекомендована сфера |
|---|---|---|---|
| `true` | Конвертує `CRLF` → `LF` у сховищі. | Конвертує `LF` → `CRLF` у робочому каталозі. | Тільки робочі станції Windows. |
| `input` | Конвертує `CRLF` → `LF` у сховищі. | Залишає `LF` без змін у робочому каталозі. | Робочі станції macOS та Linux. |
| `false` | Зберігає байти файлу без змін. | Вивантажує байти файлу без змін. | Сервери збірки (CI/CD), Docker-контейнери. |
