## 1. Конвертація кодувань: утиліта та системний інтерфейс `iconv`

### 1.1. Специфікація утиліти командного рядка `iconv`

Утиліта `iconv` є стандартним інструментом POSIX.1-2008 для перетворення послідовностей символів з одного кодування в інше.

```sh
iconv [-c] [-s] [-l] [-f from-code] [-t to-code] [-o outputfile] [file...]
```

#### Параметри та прапорці командного рядка

| Прапорець | Довга форма | Тип аргументу | Опис і специфікація поведінки |
|---|---|---|---|
| `-f <enc>` | `--from-code=<enc>` | Назва кодування | Вхідне кодування потоку. Якщо параметр не задано, утиліта використовує значення поточної локалі системи (`nl_langinfo(CODESET)` або змінну `LC_CTYPE`). |
| `-t <enc>` | `--to-code=<enc>` | Назва кодування | Вихідне кодування потоку. Якщо параметр не задано, використовується кодування поточної локалі. Підтримує модифікатори `//TRANSLIT` та `//IGNORE`. |
| `-o <file>` | `--output=<file>` | Шлях до файлу | Спрямувати вихідний потік у зазначений файл замість стандартного виводу `stdout`. Якщо файл існує, він відкривається на запис і перезаписується. |
| `-c` | — | Прапорець | Мовчки відкидати (omit/discard) невалідні вхідні байти замість аварійного припинення роботи. Запобігає зупинці конвеєра при зустрічі з пошкодженими октетами у вхідному потоці. |
| `-s` | `--silent` | Прапорець | Придушити діагностичні повідомлення про помилки перетворення у потік `stderr` (при цьому код повернення залишається ненульовим `1`, якщо виникали помилки). |
| `-l` | `--list` | Прапорець | Вивести у `stdout` перелік усіх підтримуваних бібліотекою кодувань та їхніх зареєстрованих псевдонімів (aliases). |
| — | `--unicode-subst=<fmt>` | Шаблон підстановки | Розширення GNU `libiconv`: визначає рядок форматування для заміни кодових точок Unicode, відсутніх у цільовому кодуванні (наприклад, `&#%u;` для HTML entity або `\u%04X`). |
| — | `--byte-subst=<fmt>` | Шаблон підстановки | Розширення GNU `libiconv`: визначає рядок форматування для недійсних вхідних байтів (наприклад, `<0x%02X>`). |
| — | `--widechar-subst=<fmt>` | Шаблон підстановки | Розширення GNU `libiconv`: визначає формат підстановки для неконвертованих широких символів `wchar_t`. |

#### Модифікатори та суфікси цільового кодування (`-t`)

Суфікси додаються безпосередньо до назви кодування після подвійної косої риски `//`:

- **`//TRANSLIT` (Транслітерація та апроксимація):** Вмикає механізм транслітерації через внутрішні таблиці модуля `gconv` (GNU C Library) або `libiconv` з урахуванням поточної категорії `LC_CTYPE`. Якщо символ із вхідного потоку не може бути представлений у цільовому наборі безпосередньо, бібліотека намагається підібрати один або кілька візуально чи фонетично еквівалентних знаків цільового кодування:
  - Типографічні лапки та тире: `“` / `”` → `"`, `‘` / `’` → `'`, `—` → `--`, `…` → `...`.
  - Діакритичні літери: `ä` → `ae`, `ü` → `ue`, `ö` → `oe`, `é` → `e`, `ł` → `l`, `ß` → `ss`.
  - Спеціальні символи та знаки валют: `©` → `(C)`, `®` → `(R)`, `™` → `(TM)`, `€` → `EUR`, `£` → `GBP`, `§` → `S.`.
  
  Якщо в таблицях транслітерації відповідного наближення для кодової точки знайти не вдається, функція перетворення генерує помилку `EILSEQ` (або замінює знак на `?` залежно від реалізації).
- **`//IGNORE` (Ігнорування неконвертованих символів):** Наказує конвертеру мовчки відкидати будь-які кодові точки, які неможливо представити в цільовому кодуванні, не перериваючи обробку потоку.
- **Комбінація `//TRANSLIT//IGNORE`:** Дозволяє об'єднати обидва режими. Бібліотека спершу намагається транслітерувати символ у наближений еквівалент цільового кодування; якщо ж апроксимація неможлива, символ мовчки відкидається замість генерації аварійної зупинки.

> ⚠️ **Фундаментальна різниця між `-c` та `//IGNORE`:**
> - Прапорець `-c` працює на рівні **вхідного декодера (`-f`)**: він відкидає сирі **невалідні байти** (октетні послідовності, які не утворюють допустимого символу у вихідному кодуванні, наприклад збійні октети `0xFF` у потоці UTF-8).
> - Суфікс `//IGNORE` працює на рівні **вихідного енкодера (`-t`)**: він відкидає повністю **валідні символи**, які коректно декодовано з `-f`, але які фізично відсутні в наборі символів вихідного кодування `-t` (наприклад, кирилична літера `ї` при конвертації з UTF-8 в `ISO-8859-1`).

#### Поведінка при обробці часткових і пошкоджених послідовностей

Коли утиліта `iconv` зустрічає невалідні або розірвані дані, її поведінка суворо регламентується прапорцями:

1. **Неповна послідовність байтів наприкінці файлу (Truncated Multibyte Sequence):**
   - *Без `-c`:* Утиліта завершує роботу з помилкою `iconv: incomplete multibyte or wide-character sequence at end of output`, виводить код повернення `1` і не скидає неповний хвіст.
   - *З `-c`:* Утиліта мовчки ігнорує залишковий обірваний байт і коректно завершує запис вихідного файлу з кодом повернення `0`.
2. **Пошкоджений або заборонений байт у середині потоку (Illegal Byte Sequence):**
   - *Без `-c`:* Утиліта негайно перериває запис на позиції збійного байта, виводить у `stderr` діагностику виду `iconv: illegal input sequence at position 1042` та повертає код `1`. Усі байти після збійної позиції втрачаються.
   - *З `-c`:* Утиліта пропускає пошкоджений октет, продовжує конвертацію з наступного байта й завершує роботу з кодом `0`.

#### Коди повернення (Exit Status) утиліти `iconv`

- `0` — успішне завершення. Усі вхідні байти коректно декодовано та збережено у вихідний файл.
- `1` — помилка обробки. Виникає при виявленні невалідного байта (без `-c`), неконвертованого символу (без `//IGNORE` чи `//TRANSLIT`), неповної послідовності наприкінці файлу, невідомого імені кодування або апаратного збою вводу-виводу.

#### Типові сценарії виклику

```sh
# 1. Конвертація файлу з CP1251 в UTF-8 з записом у новий файл
iconv -f CP1251 -t UTF-8 -o document_utf8.txt document_cp1251.txt

# 2. Транслітерація західноєвропейських символів в ASCII
iconv -f UTF-8 -t ASCII//TRANSLIT < input_utf8.txt > ascii_translit.txt

# 3. Транслітерація з ігноруванням непідтримуваних знаків (//TRANSLIT//IGNORE)
iconv -f UTF-8 -t ISO-8859-1//TRANSLIT//IGNORE < mixed_unicode.txt > output_latin1.txt

# 4. Надійне масове очищення потоку від невалідних байтів з ігноруванням непідтримуваних символів
iconv -c -f UTF-8 -t ISO-8859-1//IGNORE < damaged_utf8.txt > clean_latin1.txt

# 5. Підстановка шістнадцяткових кодових позначок замість втрачених символів (GNU libiconv)
iconv -f UTF-8 -t ASCII --unicode-subst="&#x%04X;" < input_unicode.txt > web_entities.txt
```

### 1.2. Бібліотечний контракт `<iconv.h>` (C та C++)

Системний інтерфейс POSIX.1-2008 визначає три базові функції для роботи з дескрипторами перетворення кодувань.

:::tabs
```c
#include <iconv.h>

iconv_t iconv_open(const char *tocode, const char *fromcode);
size_t  iconv(iconv_t cd,
              char **restrict inbuf, size_t *restrict inbytesleft,
              char **restrict outbuf, size_t *restrict outbytesleft);
int     iconv_close(iconv_t cd);
```
```cpp
#include <iconv.h>
#include <cstddef>

namespace posix {
    using ::iconv_t;
    using ::iconv_open;
    using ::iconv;
    using ::iconv_close;
}
```
:::

#### Функція `iconv_open()`

Виділяє внутрішні ресурси, завантажує необхідні динамічні модулі трансляції (наприклад, `/usr/lib/gconv/*.so` у GNU C Library) та повертає дескриптор перетворення `iconv_t`.

- **Аргументи:**
  - `tocode` — назва цільового кодування (дозволяє додавати суфікси `//TRANSLIT` та `//IGNORE` у glibc та libiconv).
  - `fromcode` — назва вихідного кодування.
- **Повернене значення:** Дескриптор `iconv_t` при успіху, або `(iconv_t) -1` при помилці (зі встановленням `errno`).
- **Коди помилок `errno`:**
  - `EINVAL` — конвертація між зазначеними кодуваннями не підтримується реалізацією бібліотеки.
  - `ENOMEM` — недостатньо системної пам'яті для виділення внутрішніх структур дескриптора.
  - `EMFILE` / `ENFILE` — досягнуто ліміт відкритих дескрипторів процесу або операційної системи.

#### Функція `iconv()`

Виконує потокову конвертацію байтів із вхідного буфера у вихідний відповідно до правил дескриптора `cd`.

- **Параметри та їхня мутація:**
  - `cd` — дійсний дескриптор, отриманий з `iconv_open()`.
  - `inbuf` — покажчик на покажчик на перший байт вхідного масиву (`char**`). Функція змінює значення покажчика `*inbuf`, зміщуючи його вперед на кількість фактично спожитих байтів.
  - `inbytesleft` — покажчик на кількість байтів, доступних у вхідному буфері (`size_t*`). Зменшується на кількість прочитаних октет.
  - `outbuf` — покажчик на покажчик на початок вільного місця у вихідному буфері (`char**`). Зміщується вперед на кількість успішно записаних байтів.
  - `outbytesleft` — покажчик на кількість вільних байтів у вихідному буфері (`size_t*`). Зменшується на кількість записаних октет.
- **Спеціальні режими скидання стану (State Reset & Flush):**
  - Якщо `inbuf == NULL` або `*inbuf == NULL`, функція скидає внутрішній стан зсуву (shift state) для кодувань зі змінним станом (наприклад, `ISO-2022-JP`, `UTF-7`) і записує термінальну послідовність повернення до базового стану у `*outbuf`.
  - Якщо `inbuf == NULL` та `outbuf == NULL`, функція скидає внутрішній стан зсуву дескриптора `cd` у початковий стан без запису будь-яких байтів у вихідний потік.
- **Повернене значення:**
  - При успіху повертає кількість невиправних (транслітерованих або замінених) символів, перетворених під час виклику (для абсолютно точних 1:1 перетворень повертає `0`).
  - При виникненні помилки повертає `(size_t) -1` і встановлює значення змінної `errno`.

#### Коди помилок `errno` функції `iconv()` та протокол їх обробки

| Код `errno` | Причина виникнення | Протокол реакції та алгоритм обробника |
|---|---|---|
| `E2BIG` | У вихідному буфері недостатньо вільного місця (`*outbytesleft` замалий) для запису наступного перетвореного символу. | 1. Скинути наповнену частину вихідного буфера на диск або в сокет (`write()` / `fwrite()`), або динамічно розширити масив у пам'яті (`std::string::resize()`).<br>2. Оновити покажчик `*outbuf` на початок вільного простору.<br>3. Оновити значення `*outbytesleft` на новий доступний розмір.<br>4. Повторити виклик `iconv()`, **не змінюючи** `inbuf` та `inbytesleft`. |
| `EILSEQ` | Вхідний потік містить послідовність байтів, яка не є валідним символом у кодуванні `fromcode` або не підтримується у вихідному `tocode` (без `//IGNORE`). Покажчик `*inbuf` вказує на початок збійного байта. | **Режим суворої валідації:** Зафіксувати збійний зсув `(total_read + (pin - in_buf))` та перервати процес.<br>**Режим відновлення (Lossy / Sanitization):**<br>1. Пропустити збійний байт: змістити `(*inbuf)++` та зменшити `(*inbytesleft)--`.<br>2. За потреби записати у вихідний буфер маркер заміни (наприклад, UTF-8 `U+FFFD` `\xEF\xBF\xBD` або ASCII `?`).<br>3. Продовжити цикл конвертації. |
| `EINVAL` | Вхідний буфер закінчується неповною мультибайтовою послідовністю (наприклад, прочитано лише 2 байти з 4-байтового символу UTF-8 через розрив блоку читання `read()`). | **Ситуація А (потік триває, не EOF):**<br>1. Перенести залишкові неспожиті байти (`*inbytesleft`) на початок вхідного буфера за допомогою `memmove(in_buf, *inbuf, *inbytesleft)`.<br>2. Дочитати наступний блок даних із дескриптора у буфер одразу після збереженого залишку: `fread(in_buf + in_left, 1, sizeof(in_buf) - in_left, in)`.<br>3. Оновити `inbytesleft` на сумарну довжину залишку і нових даних.<br>4. Повторити виклик `iconv()`.<br>**Ситуація Б (досягнуто кінця файлу `feof()`):** Потік обірвано на неповному символі. Обробити як невідновну помилку або пропустити хвіст. |

#### Функція `iconv_close()`

- **Сигнатура:** `int iconv_close(iconv_t cd);`
- **Опис:** Звільняє всі системні ресурси, таблиці перетворення та вивантажує пов'язані бібліотечні модулі дескриптора `cd`.
- **Повернене значення:** `0` при успіху, або `-1` при помилці (зі встановленням `errno = EBADF`, якщо дескриптор недійсний).

#### Приклад надійної потокової конвертації блоками

:::tabs
```c
#define _POSIX_C_SOURCE 200809L
#include <iconv.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

#define IN_BUF_SIZE  4096
#define OUT_BUF_SIZE 8192

/*
 * convert_stream: надійна потокова конвертація між кодуваннями блоками.
 * allow_lossy: якщо 1 — пропускає пошкоджені байти (EILSEQ) з підстановкою '?',
 *              якщо 0 — повертає -1 при першому пошкодженому байті.
 */
int convert_stream(FILE *in, FILE *out, const char *from_enc, const char *to_enc, int allow_lossy) {
    iconv_t cd = iconv_open(to_enc, from_enc);
    if (cd == (iconv_t)-1) {
        perror("iconv_open failed");
        return -1;
    }

    char in_buf[IN_BUF_SIZE];
    char out_buf[OUT_BUF_SIZE];
    size_t in_left = 0;

    while (1) {
        size_t bytes_read = fread(in_buf + in_left, 1, sizeof(in_buf) - in_left, in);
        in_left += bytes_read;
        if (in_left == 0) break;

        char *pin = in_buf;
        char *pout = out_buf;
        size_t out_left = sizeof(out_buf);

        while (in_left > 0) {
            size_t res = iconv(cd, &pin, &in_left, &pout, &out_left);
            size_t bytes_to_write = sizeof(out_buf) - out_left;

            if (bytes_to_write > 0) {
                if (fwrite(out_buf, 1, bytes_to_write, out) != bytes_to_write) {
                    iconv_close(cd);
                    return -1;
                }
                pout = out_buf;
                out_left = sizeof(out_buf);
            }

            if (res == (size_t)-1) {
                if (errno == E2BIG) {
                    /* Вихідний буфер скинуто на диск, продовжуємо конвертацію залишку */
                    continue;
                } else if (errno == EINVAL) {
                    /* Неповний символ на межі блоку */
                    if (feof(in)) {
                        /* Неповний символ на самому кінці файлу */
                        fprintf(stderr, "Помилка: неповний мультибайтовий символ у кінці файлу\n");
                        iconv_close(cd);
                        return -1;
                    }
                    /* Зсуваємо залишок на початок буфера і виходимо на дочитування */
                    break;
                } else if (errno == EILSEQ) {
                    if (allow_lossy) {
                        /* Пропускаємо 1 збійний байт */
                        pin++;
                        in_left--;
                        /* Записуємо символ заміни '?' у вихідний потік */
                        if (out_left > 0) {
                            *pout++ = '?';
                            out_left--;
                        }
                        continue;
                    } else {
                        fprintf(stderr, "Помилка: невалідна байтова послідовність у вхідному потоці\n");
                        iconv_close(cd);
                        return -1;
                    }
                }
            }
        }

        /* Зсуваємо залишок неспожитих байтів (після EINVAL або завершення порції) */
        if (in_left > 0) {
            memmove(in_buf, pin, in_left);
        }
    }

    /* Завершальний скид стану для кодувань зі змінним станом (stateful encodings) */
    char *pout = out_buf;
    size_t out_left = sizeof(out_buf);
    iconv(cd, NULL, NULL, &pout, &out_left);
    size_t flush_bytes = sizeof(out_buf) - out_left;
    if (flush_bytes > 0) {
        if (fwrite(out_buf, 1, flush_bytes, out) != flush_bytes) {
            iconv_close(cd);
            return -1;
        }
    }

    iconv_close(cd);
    return 0;
}
```
```cpp
#include <iconv.h>
#include <iostream>
#include <vector>
#include <string>
#include <stdexcept>
#include <system_error>
#include <memory>
#include <cerrno>

class IconvConverter {
public:
    IconvConverter(const std::string& from_enc, const std::string& to_enc, bool lossy = false)
        : lossy_(lossy) {
        cd_ = iconv_open(to_enc.c_str(), from_enc.c_str());
        if (cd_ == reinterpret_cast<iconv_t>(-1)) {
            throw std::system_error(errno, std::generic_category(), "iconv_open failed");
        }
    }

    ~IconvConverter() noexcept {
        if (cd_ != reinterpret_cast<iconv_t>(-1)) {
            iconv_close(cd_);
        }
    }

    IconvConverter(const IconvConverter&) = delete;
    IconvConverter& operator=(const IconvConverter&) = delete;

    IconvConverter(IconvConverter&& other) noexcept
        : cd_(other.cd_), lossy_(other.lossy_) {
        other.cd_ = reinterpret_cast<iconv_t>(-1);
    }

    IconvConverter& operator=(IconvConverter&& other) noexcept {
        if (this != &other) {
            if (cd_ != reinterpret_cast<iconv_t>(-1)) {
                iconv_close(cd_);
            }
            cd_ = other.cd_;
            lossy_ = other.lossy_;
            other.cd_ = reinterpret_cast<iconv_t>(-1);
        }
        return *this;
    }

    std::string convert(const std::string& input) {
        size_t in_left = input.size();
        char* in_ptr = const_cast<char*>(input.data());

        size_t out_capacity = input.size() * 4 + 32;
        std::string result(out_capacity, '\0');
        char* out_ptr = result.data();
        size_t out_left = result.size();

        while (in_left > 0) {
            size_t res = iconv(cd_, &in_ptr, &in_left, &out_ptr, &out_left);
            if (res == static_cast<size_t>(-1)) {
                if (errno == E2BIG) {
                    size_t written = out_ptr - result.data();
                    result.resize(result.size() * 2);
                    out_ptr = result.data() + written;
                    out_left = result.size() - written;
                    continue;
                } else if (errno == EILSEQ && lossy_) {
                    in_ptr++;
                    in_left--;
                    if (out_left > 0) {
                        *out_ptr++ = '?';
                        out_left--;
                    }
                    continue;
                }
                throw std::system_error(errno, std::generic_category(), "iconv conversion failed");
            }
        }

        /* Завершальний скид стану для stateful-кодувань */
        iconv(cd_, nullptr, nullptr, &out_ptr, &out_left);
        result.resize(out_ptr - result.data());
        return result;
    }

private:
    iconv_t cd_{reinterpret_cast<iconv_t>(-1)};
    bool lossy_{false};
};
```

## 2. Системний інтерфейс локалей та визначення кодувань: `<locale.h>` і `<langinfo.h>`

Стандарт POSIX.1-2008 визначає програмні інтерфейси для ініціалізації мовного середовища, запиту активного набору символів і створення ізольованих об'єктів локалей для багатопотокових програм.

### 2.1. Контракт `setlocale()` та категорії локалей

:::tabs
```c
#include <locale.h>

char *setlocale(int category, const char *locale);
```
```cpp
#include <clocale>

namespace posix {
    using std::setlocale;
}
```
:::

#### Специфікація поведінки `setlocale()`

1. **Ініціалізація із середовища (`locale == ""`):** Зчитує змінні оточення процесу за суворим пріоритетом:
   `LC_ALL` → `LC_<category>` → `LANG` → системний дефолт (`"C"` / `"POSIX"`).
2. **Запит поточного значення (`locale == NULL`):** Повертає покажчик на рядок з назвою поточної активної локалі для вказаної категорії без зміни конфігурації процесу.
3. **Примусове встановлення (`locale == "C"` або `"POSIX"`):** Перемикає процес у базовий стандартний 7-бітний ASCII режим.
4. **Повернене значення:** Рядок ідентифікатора локалі при успіху або `NULL`, якщо запитана локаль не підтримується системою (значення локалі процесу залишається незмінним).

#### Категорії локалей (`category`)

| Константа | Область впливу на системні функції та бібліотеки |
|---|---|
| `LC_ALL` | Усі категорії одночасно (глобальне налаштування процесу). |
| `LC_CTYPE` | Класифікація символів (`isalpha`, `isspace`), перетворення регістру (`toupper`), функції мультибайтової конвертації (`mbtowc`, `mbstowcs`, `wctomb`) та дефолтне кодування для утиліт `iconv` і `nl_langinfo(CODESET)`. |
| `LC_COLLATE` | Правила порівняння та сортування рядків (`strcoll`, `strxfrm`, діапазони регулярних виразів `[a-z]`, сортування `sort`). |
| `LC_MESSAGES` | Мова системних діагностичних повідомлень і відповідей («так/ні»). |
| `LC_NUMERIC` | Символ десяткового роздільника (крапка `.` або кома `,`) та групування розрядів (`printf`, `scanf`, `strtod`). |
| `LC_MONETARY` | Форматування грошових сум і валютних символів (`strfmon`). |
| `LC_TIME` | Форматування дати і часу (`strftime`, `strptime`). |

> ⚠️ **Потокова небезпека `setlocale()`:** Функція модифікує глобальний стан усього процесу і не є потокобезпечною (`thread-unsafe`). У багатопотокових серверах виклик `setlocale()` під час роботи інших потоків призводить до стану гонитви (race condition).

---

### 2.2. Запит кодування через `nl_langinfo(CODESET)`

Заголовний файл `<langinfo.h>` надає інтерфейс для отримання конкретних параметрів активної локалі.

:::tabs
```c
#include <langinfo.h>

char *nl_langinfo(nl_item item);
char *nl_langinfo_l(nl_item item, locale_t loc);
```
```cpp
#include <langinfo.h>

namespace posix {
    using ::nl_langinfo;
    using ::nl_langinfo_l;
}
```
:::

- **Константа `CODESET`:** Повертає назву кодування символів, що використовується поточною категорією `LC_CTYPE` (наприклад, `"UTF-8"`, `"ISO-8859-1"`, `"CP1251"`, `"ANSI_X3.4-1968"` для ASCII).
- **Інваріант старту процесу:** Якщо програма не викликала `setlocale(LC_ALL, "")` або `setlocale(LC_CTYPE, "")`, процес стартує в локалі `"C"`, де `nl_langinfo(CODESET)` завжди повертає `"ANSI_X3.4-1968"` або `"US-ASCII"`, навіть якщо термінал працює в UTF-8.

### 2.3. Потокобезпечний об'єктний інтерфейс локалей POSIX.1-2008

Для усунення глобальних блокувань у стандарті POSIX.1-2008 запроваджено типи `locale_t` та функції для роботи з локалями потоків:

:::tabs
```c
#include <locale.h>

locale_t newlocale(int category_mask, const char *locale, locale_t base);
locale_t uselocale(locale_t newloc);
void     freelocale(locale_t loc);
locale_t duplocale(locale_t loc);
```
```cpp
#include <locale.h>

namespace posix {
    using ::locale_t;
    using ::newlocale;
    using ::uselocale;
    using ::freelocale;
    using ::duplocale;
}
```
:::

- `newlocale()` — створює незалежний об'єкт локалі з бітовою маскою (наприклад, `LC_CTYPE_MASK | LC_COLLATE_MASK`).
- `uselocale()` — встановлює локаль виключно для поточного потоку виконання (`pthread`). Повертає попередню локаль потоку (або `LC_GLOBAL_LOCALE`).
- `freelocale()` — звільняє пам'ять виділеного об'єкта локалі.

### 2.4. Програмне визначення кодування поточного оточення

:::tabs
```c
#define _POSIX_C_SOURCE 200809L
#include <locale.h>
#include <langinfo.h>
#include <stdio.h>
#include <string.h>
#include <strings.h>

int check_system_encoding(void) {
    /* 1. Ініціалізація локалі процесу зі змінних оточення */
    char *current_locale = setlocale(LC_ALL, "");
    if (!current_locale) {
        fprintf(stderr, "Попередження: не вдалося завантажити локаль із середовища\n");
    }

    /* 2. Запит назви активного кодування для LC_CTYPE */
    const char *codeset = nl_langinfo(CODESET);
    printf("Поточна локаль процесу: %s\n", current_locale ? current_locale : "C");
    printf("Активний набір символів (CODESET): %s\n", codeset);

    /* 3. Валідація підтримки UTF-8 */
    if (strcasecmp(codeset, "UTF-8") == 0 || strcasecmp(codeset, "UTF8") == 0) {
        printf("Середовище підтримує повноцінне кодування UTF-8.\n");
    } else {
        printf("Увага: середовище працює у застарілому або однобайтовому кодуванні.\n");
    }

    /* 4. Потокобезпечний запит через об'єкт locale_t (POSIX.1-2008) */
    locale_t thread_loc = newlocale(LC_CTYPE_MASK, "C.UTF-8", (locale_t)0);
    if (thread_loc != (locale_t)0) {
        const char *t_codeset = nl_langinfo_l(CODESET, thread_loc);
        printf("Кодування виділеного об'єкта локалі: %s\n", t_codeset);
        freelocale(thread_loc);
    }

    return 0;
}
```

```cpp
#include <string>
#include <algorithm>
#include <cctype>

class LocaleEnvironment {
public:
    LocaleEnvironment() {
        // Ініціалізуємо системне C-оточення згідно зі змінними середовища
        const char* loc = std::setlocale(LC_ALL, "");
        locale_name_ = loc ? loc : "C";

        // Синхронізуємо глобальну локаль C++
        try {
            std::locale::global(std::locale(""));
            std::cin.imbue(std::locale());
            std::cout.imbue(std::locale());
        } catch (const std::runtime_error&) {
            // Фолбек на стандартну локаль при відсутності системних файлів локалі
            std::locale::global(std::locale::classic());
        }
    }

        const char* cs = nl_langinfo(CODESET);
        return cs ? std::string(cs) : std::string("UNKNOWN");
    }

    std::string locale_name() const noexcept {
        return locale_name_;
    }

    bool is_utf8() const {
        std::string cs = codeset();
        std::transform(cs.begin(), cs.end(), cs.begin(), [](unsigned char c) {
            return static_cast<char>(std::toupper(c));
        });
        return (cs == "UTF-8" || cs == "UTF8");
    }

private:
    std::string locale_name_;
};
```

## 3. Керування кінцями рядків та BOM: `dos2unix`, `unix2dos`, `mac2unix`

Утиліти родини `dos2unix` призначені для масової безпечної конвертації маркерів кінця рядка між стандартами DOS/Windows (`\r\n`, CRLF, `0x0D 0x0A`), Unix/Linux (`\n`, LF, `0x0A`) та Classic Mac OS (`\r`, CR, `0x0D`), а також для керування маркером порядку байтів (UTF-8 BOM), перетворення між 7-бітним та 8-бітним простором і табличного ремапінгу кодових сторінок.

```sh
dos2unix [options] [-n infile outfile ...] [file ...]
unix2dos [options] [-n infile outfile ...] [file ...]
mac2unix [options] [-n infile outfile ...] [file ...]
unix2mac [options] [-n infile outfile ...] [file ...]
```

### 3.1. Механіка безпечної заміни на місці (In-Place Conversion)

За замовчуванням утиліти працюють у режимі перезапису на місці (old file mode `-o`). Для запобігання пошкодженню або обнуленню файлу при раптовому збої живлення, нестачі дискового простору чи перериванні процесу сигналом алгоритм виконує транзакційну послідовність кроків:

1. **Створення тимчасового файлу:** У тому самому каталозі створюється тимчасовий файл із шаблоном імені `d2utmpXXXXXX` через системний виклик `mkstemp()`. Розміщення тимчасового файлу в тому самому каталозі гарантує його перебування на тій самій точці монтування файлової системи (VFS mount point), що є обов'язковою умовою для подальшого атомарного перейменування.
2. **Потокове читання та запис:** Виконується блокове читання з дескриптора вхідного файлу, фільтрація маркерів рядків і запис перетвореного потоку у тимчасовий дескриптор.
3. **Копіювання атрибутів і метаданих:** Утиліта зчитує статус оригінального файлу через системний виклик `fstat()` і відтворює його метадані на тимчасовому файлі:
   - Права доступу: виклик `fchmod()` з точним бітовим режимом (`st_mode & 07777`).
   - Власник і група: виклик `fchown()` (якщо процес має привілеї `CAP_CHOWN` або запущений від `root`).
   - Часові позначки: якщо активовано прапорець збереження дати `-k`, викликається `futimens()` або `utimensat()` для збереження оригінальних значень часу останнього доступу (`atime`) та модифікації (`mtime`). Без `-k` час `mtime` встановлюється на поточний системний час.
4. **Атомарне заміщення (Atomic Rename):** Викликається системний виклик `rename(temp_file, original_file)`. На рівні файлової системи запис у каталозі перемикається на новий inode як єдина неподільна операція. Оригінальний файл ніколи не перебуває у частково записаному стані.

### 3.2. Нормативна специфікація параметрів та прапорців

| Прапорець | Довга форма | Тип | Опис поведінки та специфікація |
|---|---|---|---|
| `-o <file...>` | `--oldfile` | Шляхи | **Режим перезапису на місці (дефолт):** конвертувати зазначений файл і атомарно замінити його через тимчасовий файл. |
| `-n <in> <out>` | `--newfile` | Пари шляхів | **Режим нового файлу:** прочитати вхідний файл `<in>`, зберегти результат у `<out>`, залишивши оригінальний файл недоторканим. |
| `-k` | `--keepdate` | Прапорець | Зберігати часову позначку модифікації файлу (`mtime` та `atime`) незмінною. |
| `-q` | `--quiet` | Прапорець | Придушити інформаційні повідомлення, статистику та попередження. |
| `-v` | `--verbose` | Прапорець | Виводити детальну статистику перетворення у `stderr`. |
| `-s` | `--safe` | Прапорець | **Безпечний режим (дефолт):** автоматично пропускати файли, якщо під час сканування першого блоку виявлено бінарні нульові байти `0x00`. Запобігає пошкодженню скомпільованих бінарників ELF або архівів. |
| `-f` | `--force` | Прапорець | Примусово виконувати конвертацію, навіть якщо у файлі виявлено бінарні байти `0x00` (ігнорувати перевірку `--safe`). |
| `-r` | `--remove-bom` | Прапорець | Видалити маркер порядку байтів UTF-8 BOM (`0xEF 0xBB 0xBF`) або UTF-16 BOM, якщо він присутній на початку файлу. |
| `-m` | `--add-bom` | Прапорець | Додати маркер порядку байтів UTF-8 BOM (`0xEF 0xBB 0xBF`) на початок вихідного файлу. Якщо BOM уже присутній, дублювання не відбувається. |
| `-u`, `-b` | `--keep-bom` | Прапорець | **Збереження BOM (дефолт):** якщо BOM був присутній на вході — зберегти його; якщо був відсутній — не додавати. |
| `-l` | `--newline` | Прапорець | Додавати **додатковий новий рядок** після кожного перетвореного рядка. Утиліта `dos2unix` генерує подвійний `\n\n`, а `unix2dos` — подвійний `\r\n\r\n`. |
| `-c <mode>` | `--convmode <mode>` | Режим | Встановити режим конвертації символів: `ascii`, `7bit`, `iso`, `mac` (детальніше див. розділ 3.3). Дефолт — `ascii`. |
| `-F` | `--follow-symlink` | Прапорець | Переходити за символічними посиланнями та модифікувати кінцевий цільовий файл. |
| `-R` | `--replace-symlink` | Прапорець | Замінити символічне посилання на звичайний регулярний конвертований файл (оригінальний цільовий файл залишається без змін). |
| `-S` | `--stubborn` | Прапорець | **Пропуск посилань (дефолт):** не змінювати символічні посилання та цільові файли, на які вони вказують. |
| `-i[flags]` | `--info[=flags]` | Опційні прапорці | Вивести статистичну інформацію про файл без виконання конвертації. Підтримує прапорці формату (див. нижче). |
| — | `--allow-chown` | Прапорець | Дозволити зміну власника файлу в режимі `--oldfile`, якщо зберегти оригінального власника неможливо (наприклад, через обмеження прав доступу). |

#### Специфікація прапорця інформаційного звіту (`-i`)

Прапорець `-i` сканує файл і виводить колонки з кількістю маркерів та характеристиками кодування:
- `d` — кількість DOS-маркерів кінця рядка (`\r\n`, CRLF).
- `u` — кількість Unix-маркерів кінця рядка (`\n`, LF).
- `m` — кількість Mac-маркерів кінця рядка (`\r`, CR).
- `b` — статус BOM: `BOM_UTF8`, `BOM_UTF16LE`, `BOM_UTF16BE`, `BOM_NONE`.
- `t` — тип файлу за бінарною евристикою: `text` або `binary`.
- `c` — активний режим перетворення `convmode`.
- `a` — вивести всі доступні параметри одночасно (дефолт для `-i`).

```sh
$ dos2unix -i script.sh
       0      42       0  BOM_UTF8       text  script.sh
```

### 3.3. Специфікація роботи з BOM та режими перетворення (`--convmode`)

#### Байтові сигнатури маркерів порядку байтів (BOM)

| Тип кодування | Сигнатура у шістнадцятковому форматі | Довжина у байтах | Дія прапорця `-r` | Дія прапорця `-m` |
|---|---|---|---|---|
| **UTF-8 BOM** | `0xEF 0xBB 0xBF` | 3 байти | Видаляє 3 байти на зміщенні 0 | Записує `0xEF 0xBB 0xBF` на зміщення 0 |
| **UTF-16LE BOM** | `0xFF 0xFE` | 2 байти | Видаляє 2 байти при 16-бітному режимі | Записує `0xFF 0xFE` |
| **UTF-16BE BOM** | `0xFE 0xFF` | 2 байти | Видаляє 2 байти при 16-бітному режимі | Записує `0xFE 0xFF` |
| **UTF-32LE BOM** | `0xFF 0xFE 0x00 0x00` | 4 байти | Розпізнається детектором | — |
| **UTF-32BE BOM** | `0x00 0x00 0xFE 0xFF` | 4 байти | Розпізнається детектором | — |
| **GB18030 BOM** | `0x84 0x31 0x95 0x33` | 4 байти | Розпізнається детектором | — |

- **Механіка `-r` (`--remove-bom`):** Утиліта зчитує перші байти файлу. Якщо виявлено сигнатуру `0xEF 0xBB 0xBF`, покажчик вихідного запису встановлюється після 3-го байта, і BOM вилучається з вихідного файлу без порушення структури наступних символів UTF-8.
- **Механіка `-m` (`--add-bom`):** Якщо у вихідному файлі BOM відсутній, утиліта записує три байти `0xEF 0xBB 0xBF` першими у вихідний дескриптор, після чого виконує стандартне перетворення тексту.

#### Специфікація режимів перетворення `--convmode`

Режим `--convmode <mode>` визначає, як утиліта обробляє байти поза маркерами кінців рядків:

1. **`ascii` (Режим за замовчуванням):**
   - Конвертує **виключно** символи перенесення рядків (`CRLF` ↔ `LF` ↔ `CR`).
   - Усі 8-бітні байти, розширені кодові сторінки та багатобайтові послідовності UTF-8 (значення октет від `0x80` до `0xFF`) проходять через конвертер **без жодних змін**.
2. **`7bit` (Скидання 8-го біта):**
   - Перетворює всі 8-бітні символи у 7-бітний простір ASCII шляхом побітового маскування `byte & 0x7F` або заміни непідтримуваних знаків на пробіли.
   - Застосовується для очищення текстів для успадкованих 7-бітних протоколів передачі даних або телетайпів.
3. **`iso` (Таблична конвертація DOS ↔ ISO-8859-1):**
   - `dos2unix -c iso`: конвертує текст зі стандартної кодової сторінки DOS (CP437 або поточної активної OEM-сторінки DOS) у стандарт ISO-8859-1 (Latin-1). Псевдографічні символи DOS (рамки, лінії) замінюються на найближчі ASCII-аналоги (`+`, `-`, `|`), а міжнародні літери з діакритикою ремапляться на їхні позиції в ISO-8859-1.
   - `unix2dos -c iso`: виконує зворотне відображення з ISO-8859-1 у кодову сторінку DOS.
4. **`mac` (Конвертація Mac OS Roman ↔ ISO-8859-1):**
   - Перетворює текст між кодуванням Apple Mac OS Roman та стандартом ISO-8859-1.

#### Коди повернення (Exit Status) `dos2unix`

- `0` — успішне завершення. Усі вказані файли оброблено.
- `1` — помилка в синтаксисі аргументів командного рядка або вичерпання системної пам'яті.
- `2` — операцію пропущено: файл визначено як бінарний у безпечному режимі `--safe`.
- `3` — системна помилка доступу до файлу (файл не існує, заборонено читання або запис).
- `4` — помилка створення тимчасового файлу або системного виклику `rename()`.

#### Типові інженерні рецепти `dos2unix`

```sh
# 1. Масове рекурсивне видалення CRLF та BOM у всіх скриптах проєкту
find . -type f -name "*.sh" -exec dos2unix -r -k {} +

# 2. Перевірка статусу файлів без зміни даних на диску
dos2unix -i src/*.cpp

# 3. Конвертація з додаванням UTF-8 BOM для сумісності зі старими програмами Windows
unix2dos -m -n config.json config_win.json

# 4. Форматування тексту з подвійним міжрядковим інтервалом (double spacing)
dos2unix -l single_spaced.txt double_spaced.txt

# 5. Примусова конвертація DOS-файлу зі сторінки CP437 в ISO-8859-1
dos2unix -c iso -f legacy_dos_doc.txt
```

## 4. Базові потокові фільтри: `tr`, `sed`, `awk`

### 4.1. Утиліта `tr` (Translate / Delete / Squeeze)

`tr` — це потоковий фільтр ядра користувацького простору POSIX, оптимізований для високої пропускної здатності.

```sh
tr [OPTION]... SET1 [SET2]
```

#### Внутрішня архітектура та обмеження `tr`

- **Таблиця підстановки `table[256]`:** Утиліта ініціалізує 256-байтовий масив прямого доступу в RAM і виконує обробку блоками через `read()`/`write()` з часовою складністю `O(1)` на кожен байт.
- **Відсутність обізнаності з UTF-8:** `tr` сприймає потік виключно як послідовність незалежних 8-бітних байтів. Будь-яка спроба замінити мультибайтовий символ замінить окремі октети всередині послідовностей, що зруйнує UTF-8 кодування тексту.

#### Прапорці та параметри `tr`

| Прапорець | Опис дії |
|---|---|
| `-d`, `--delete` | Видалити всі байти, що входять до множини `SET1`, із вихідного потоку. |
| `-c`, `-C`, `--complement` | Інвертувати множину `SET1` (застосовувати дію до всіх байтів від `0x00` до `0xFF`, крім зазначених у `SET1`). |
| `-s`, `--squeeze-repeats` | Замінити послідовності однакових сусідніх символів із множини `SET1` на один такий символ. |
| `-t`, `--truncate-set1` | Урізати `SET1` до довжини `SET2` перед виконанням заміни. |

#### Ідіоматичні системні рецепти `tr`

```sh
# 1. Видалення всіх символів Carriage Return (\r, 0x0D) з вхідного потоку
tr -d '\r' < dos_file.txt > unix_file.txt

# 2. Перетворення кінців рядків Classic Mac (\r) у стандартний Unix LF (\n)
tr '\r' '\n' < mac_classic.txt > unix_file.txt

# 3. Заміна NUL-байтів (0x00) на символи перенесення рядка (0x0A)
tr '\0' '\n' < null_separated.bin > newline_separated.txt

# 4. Санітизація потоку: залишити лише друковані ASCII-символи, табуляцію та новий рядок
tr -cd '\011\012\040-\176' < raw_corrupted.txt > clean_ascii.txt

# 5. Стиснення множинних порожніх рядків у поодинокі
tr -s '\n' < sparse.txt > compact.txt
```

### 4.2. Потоковий редактор `sed` (Stream Editor)

`sed` обробляє текст по рядках, дозволяючи застосовувати контекстну регулярну фільтрацію з прив'язкою до меж.

```sh
sed [-n] [-e script] [-f script-file] [-i[SUFFIX]] [-z] [input-file...]
```

#### Прапорці `sed`

| Прапорець | Опис дії |
|---|---|
| `-i[SUFFIX]`, `--in-place` | Редагувати файл на місці. Якщо вказано суфікс (наприклад, `-i.bak`), створюється резервна копія оригіналу. |
| `-z`, `--null-data` | Розділяти записи у вхідному потоці байтом `\0` (NUL) замість `\n`. |
| `-E`, `-r`, `--regexp-extended` | Використовувати розширені регулярні вирази (ERE) замість базових (BRE). |
| `-n`, `--quiet`, `--silent` | Придушити автоматичний вивід простору шаблонів (pattern space). |

#### Спеціалізовані шаблони обробки

```sh
# 1. Видалення \r лише тоді, коли він стоїть безпосередньо перед кінцем рядка \n
sed -i 's/\r$//' script.sh

# 2. Конвертація Unix LF у DOS CRLF (додавання \r перед кінцем кожного рядка)
sed -i 's/$/\r/' unix_file.txt

# 3. Видалення трьох байтів UTF-8 BOM (0xEF 0xBB 0xBF) на початку першого рядка
sed -i '1s/^\xEF\xBB\xBF//' script.py

# 4. Додавання UTF-8 BOM на початок файлу
sed -i '1s/^/\xEF\xBB\xBF/' document.txt

# 5. Робота з NUL-розділеними даними (заміна переносів рядків всередині NUL-запису)
sed -z 's/\n/ /g' < input_nul.bin > normalized_nul.bin
```

### 4.3. Мова обробки записів `awk`

Утиліта `awk` розбирає потік на структуровані записи (records) та поля (fields), конфігуровані системними змінними.

#### Керуючі системні змінні `awk`

- `RS` (Record Separator) — роздільник вхідних записів (за замовчуванням `\n`).
- `ORS` (Output Record Separator) — роздільник вихідних записів (за замовчуванням `\n`).
- `FS` (Field Separator) — роздільник полів усередині запису (за замовчуванням пробіл/табуляція).
- `OFS` (Output Field Separator) — роздільник полів при виводі (за замовчуванням пробіл).

#### Рецепти нормалізації

```sh
# 1. Універсальне видалення CRLF у стандартному POSIX awk
awk '{ sub(/\r$/, ""); print }' windows.txt > unix.txt

# 2. Автоматична уніфікація файлу зі змішаними кінцями рядків (LF та CRLF)
awk 'BEGIN { RS="\r?\n"; ORS="\n" } { print }' mixed.txt > uniform.txt

# 3. Трансформація потоку з NUL-роздільниками у звичайний потік рядків LF
awk 'BEGIN { RS="\0"; ORS="\n" } { print "Елемент:", $0 }' < nul_stream.bin

# 4. Редагування на місці утилітою GNU Awk (gawk версії 4.1+)
gawk -i inplace '{ sub(/\r$/, ""); print }' config.cfg
```

## 5. Нумерація рядків, перенесення та форматування відступів: `nl`, `fold`, `fmt`, `expand`, `unexpand`

### 5.1. Утиліта `nl` (Нумерація рядків та логічні секції тексту)

Утиліта `nl` стандарту POSIX.1-2008 виконує нумерацію рядків у вхідному потоці або файлах з урахуванням логічної структури документа (заголовок, тіло, підвал), фільтрації за регулярними виразами та налаштування форматування числових полів.

```sh
nl [-p] [-b type] [-d delim] [-f type] [-h type] [-i incr] [-l num] [-n format] [-s sep] [-v startnum] [-w width] [file...]
```

#### Логічна розмітка документа та роздільники секцій

Стандарт POSIX визначає можливість розбиття тексту на логічні сторінки (секції), кожна з яких складається з трьох опційних частин:
- **Заголовок (Header):** починається з керівного рядка `\:\:\:` (три послідовні роздільники).
- **Тіло (Body):** починається з керівного рядка `\:\:` (два послідовні роздільники).
- **Підвал (Footer):** починається з керівного рядка `\:` (один роздільник).

Керівні послідовності `\:` є дефолтними роздільниками секцій. Самі рядки роздільників не нумеруються і видаляються з вихідного потоку. При переході між секціями `nl` застосовує відповідний стиль нумерації (`-h`, `-b`, `-f`) і скидає лічильник рядків до значення `startnum` (якщо не вказано прапорець `-p`).

#### Параметри командного рядка `nl`

| Прапорець | Довга форма | Тип | Опис поведінки та специфікація |
|---|---|---|---|
| `-b <type>` | `--body-numbering=<type>` | Стиль нумерації | Стиль нумерації рядків у секції **тіла** (Body). Дефолт — `t`. |
| `-h <type>` | `--header-numbering=<type>` | Стиль нумерації | Стиль нумерації рядків у секції **заголовка** (Header). Дефолт — `n`. |
| `-f <type>` | `--footer-numbering=<type>` | Стиль нумерації | Стиль нумерації рядків у секції **підвалу** (Footer). Дефолт — `n`. |
| `-d <delim>` | `--section-delimiter=<delim>` | 1 або 2 символи | Задати символи-роздільники логічних секцій замість стандартного `\:`. Якщо передано 1 символ `C`, другий символ за замовчуванням вважається `:` (наприклад, `-d '!'` встановлює роздільник `!:`). |
| `-n <format>` | `--number-format=<format>` | Формат виводу | Формат вирівнювання номера рядка:<ul><li>`ln` — вирівнювання по лівому краю без провідних нулів (left justified).</li><li>`rn` — вирівнювання по правому краю з пробілами спереду (right justified, дефолт).</li><li>`rz` — вирівнювання по правому краю з провідними нулями (leading zeros, наприклад `000001`).</li></ul> |
| `-w <N>` | `--number-width=<N>` | Ціле число | Ширина колонки номера рядка (дефолт — 6 символів). |
| `-s <sep>` | `--number-separator=<sep>` | Рядок | Роздільник між полем номера рядка та вмістом самого рядка (дефолт — символ табуляції `\t`). |
| `-v <N>` | `--starting-line-number=<N>` | Ціле число | Початковий номер рядка на початку кожної логічної сторінки (дефолт — 1). |
| `-i <N>` | `--line-increment=<N>` | Ціле число | Крок приросту номера рядка (дефолт — 1). |
| `-l <N>` | `--join-blank-lines=<N>` | Ціле число | Кількість послідовних порожніх рядків, які групуються і нумеруються як один рядок (дефолт — 1, тобто кожен порожній рядок нумерується окремо при стилі `a`). |
| `-p` | `--no-renumber` | Прапорець | Не перезапускати лічильник нумерації на початку нових логічних сторінок/секцій (наскрізна нумерація через весь потік). |

#### Специфікація стилів нумерації (`<type>`)

Аргумент `<type>` для прапорців `-b`, `-h`, `-f` приймає одне з таких значень:
- `a` (All) — нумерувати абсолютно всі рядки, включно з порожніми.
- `t` (Text only) — нумерувати виключно непорожні рядки (рядки, що містять щонайменше один символ, відмінний від кінця рядка).
- `n` (None) — не нумерувати рядки цієї секції.
- `p<BRE>` (Pattern) — нумерувати лише ті рядки, що містять збіг із базовим регулярним виразом `<BRE>` (Basic Regular Expression).

> ℹ️ **Інваріант вирівнювання ненумерованих рядків:** Якщо рядок не нумерується (наприклад, порожній рядок при `-b t` або рядок без збігу при `-b p...`), `nl` вставляє перед ним відступ із пробілів шириною `width` плюс довжину роздільника `sep`. Завдяки цьому текстові колонки зберігають суворе візуальне вирівнювання по вертикалі.

#### Коди повернення `nl`

- `0` — усі файли успішно прочитано та виведено.
- `>0` — помилка відкриття або читання файлу чи невалідний синтаксис аргументів/регулярного виразу.

#### Типові приклади використання `nl`

```sh
# 1. Нумерація вихідного коду C/C++ з вирівнюванням праворуч, шириною 4 і двокрапкою з пробілом
nl -b a -n rn -w 4 -s ": " main.c

# 2. Формування фіксованих числових ID з провідними нулями (rz) для списку записів
nl -b a -n rz -w 5 -s " | " records.txt

# 3. Нумерація виключно рядків помилок (regex-фільтр) із наскрізним лічильником
nl -b p'^\[ERROR\]' -n ln -w 3 -s " -> " app.log

# 4. Нумерація лише непорожніх рядків з інкрементом 10, починаючи зі 100
nl -b t -v 100 -i 10 script.sh
```

### 5.2. Утиліта `fold` (Жорстке та по слівне розбиття рядків)

Утиліта `fold` стандарту POSIX.1-2008 призначена для розбиття довгих рядків вхідного потоку на короткі фрагменти фіксованої ширини.

```sh
fold [-b] [-s] [-w width | -width] [file...]
```

#### Параметри командного рядка `fold`

| Прапорець | Довга форма | Тип | Опис поведінки та специфікація |
|---|---|---|---|
| `-b` | `--bytes` | Прапорець | Рахувати ширину у фізичних байтах замість екранних колонок. За замовчуванням `fold` враховує символи керування: `\b` (Backspace) зменшує позицію на 1, `\t` зміщує курсор до наступної позиції, кратної 8, а `\r` скидає лічильник колонки в 0. З прапорцем `-b` кожен байт має вагу 1. |
| `-s` | `--spaces` | Прапорець | Переносити рядок по останньому пробільному символу (пробіл або табуляція), що передує ліміту ширини. Запобігає розриву слів навпіл. Якщо слово довше за `width` і не містить пробілів, воно примусово розривається на позиції `width`. |
| `-w <N>` | `--width=<N>` | Ціле число | Максимальна ширина рядка у колонках або байтах (дефолт POSIX — 80). Дозволяється скорочений запис у вигляді `-N` (наприклад, `-w72` або `-72`). |

#### Коди повернення `fold`

- `0` — усі вхідні файли успішно оброблено.
- `>0` — помилка відкриття або читання файлу.

#### Типові приклади використання `fold`

```sh
# 1. Форматування тексту під ширину 72 колонки зі збереженням цілісності слів
fold -s -w 72 long_document.txt > wrapped_document.txt

# 2. Жорстке розбиття бінарного base64 потоку на фіксовані блоки по 64 байти
openssl base64 -in data.bin | fold -b -w 64 > base64_block.txt

# 3. Нормалізація виводу компілятора для перегляду на вузькому терміналі
make 2>&1 | fold -s -w 100
```

### 5.3. Утиліта `fmt` (Форматування параграфів та оптимізація відступів)

Утиліта `fmt` (Coreutils / BSD) є інтелектуальним форматувальником тексту: вона оптимізує довжину рядків усередині параграфів, склеюючи занадто короткі рядки та розбиваючи довгі, зберігаючи при цьому порожні рядки та початкові відступи.

```sh
fmt [-c] [-m] [-p prefix] [-P prefix] [-s] [-t] [-u] [-w width | -width] [-g goal] [file...]
```

#### Параметри командного рядка `fmt`

| Прапорець | Довга форма | Тип | Опис поведінки |
|---|---|---|---|
| `-w <N>` | `--width=<N>` | Ціле число | Максимально допустима ширина вихідного рядка (дефолт — 75 символів). |
| `-g <N>` | `--goal=<N>` | Ціле число | Цільова ширина рядка (дефолт — приблизно 93% від `width`, тобто 70 символів при `width=75`). `fmt` намагається тримати довжину рядків якомога ближче до `goal`. |
| `-s` | `--split-only` | Прапорець | Режим лише розбиття: розбиває рядки, довші за `width`, але не склеює короткі рядки між собою. |
| `-u` | `--uniform-spacing` | Прапорець | Уніфіковані інтервали: замінює довільну кількість пробілів між словами на 1 пробіл, а після знаків завершення речень (`.`, `?`, `!`) вставляє рівно 2 пробіли. |
| `-p <pfx>` | `--prefix=<pfx>` | Рядок | Форматувати лише рядки, що починаються з префікса `<pfx>` (наприклад, `# ` або `// `), зберігаючи цей префікс на початку кожного переформатованого рядка. |
| `-P <pfx>` | `--prefix-only=<pfx>` | Рядок | Форматувати виключно рядки з префіксом `<pfx>`, залишаючи рядки без префікса абсолютно незмінними. |
| `-t` | `--tagged-paragraph` | Прапорець | Обробка «висячих» (tagged) списків: зберігає відступ першого рядка (наприклад, маркер `* ` або `1. `), а всі наступні рядки абзацу вирівнює за відступом другого рядка. |
| `-c` | `--crown-margin` | Прапорець | Режим збереження відступів: фіксує відступи перших двох рядків абзацу і застосовує відступ другого рядка до всіх наступних. |

#### Приклади застосування `fmt`

```sh
# 1. Автоматичне вирівнювання тексту коміт-повідомлення під стандарти Git (72 символи)
fmt -w 72 -u raw_commit_msg.txt > clean_commit_msg.txt

# 2. Переформатування багаторядкового коментаря в коді C/C++ із збереженням префікса
fmt -p '//' -w 80 source_comment.cpp > formatted_comment.cpp

# 3. Розбиття довгих логів без злиття сусідніх рядків
fmt -s -w 120 server.log > readable_server.log
```

### 5.4. Утиліта `expand` (Конвертація табуляцій у пробіли)

Утиліта `expand` стандарту POSIX.1-2008 замінює символи табуляції (`\t`, `0x09`) на відповідну кількість пробілів, розраховану відповідно до позицій колонок.

```sh
expand [-i] [-t tablist | -tablist] [file...]
```

#### Прапорці `expand`

| Прапорець | Довга форма | Специфікація поведінки |
|---|---|---|
| `-i` | `--initial` | Конвертувати лише **початкові** табуляції (відступи на початку рядка). Усі табуляції, що з'являються після першого символу, відмінного від пробілу/табуляції, залишаються без змін. |
| `-t <list>` | `--tabs=<list>` | Встановити позиції табуляцій. Приймає:<ul><li>Одне число `N` — позиції кожні `N` колонок (дефолт 8).</li><li>Список чисел через кому `N1,N2,N3...` — явні позиції колонок.</li><li>Розширення GNU `/N` — крок для всіх наступних позицій після останньої вказаної.</li></ul> |

```sh
# 1. Перетворення коду: заміна всіх табуляцій на 4 пробіли
expand -t 4 source.c > source_spaces.c

# 2. Заміна лише початкових відступів (leading tabs) зі збереженням табуляцій всередині таблиць
expand -i -t 4 indented.py > clean_indented.py
```

### 5.5. Утиліта `unexpand` (Згортання пробілів у табуляції)

`unexpand` стандарту POSIX.1-2008 виконує зворотну операцію: замінює послідовності з двох або більше пробілів на символи табуляції у місцях збігу з позиціями табуляцій.

```sh
unexpand [-a | --all] [--first-only] [-t tablist] [file...]
```

#### Прапорці `unexpand`

| Прапорець | Довга форма | Специфікація поведінки |
|---|---|---|
| `-a` | `--all` | Конвертувати всі послідовності з двох або більше пробілів у табуляції по всій довжині рядка. (За замовчуванням без `-a` POSIX обробляє лише початкові пробіли; у GNU `unexpand` параметр `-t` автоматично вмикає `-a`, якщо не передано `--first-only`). |
| — | `--first-only` | Конвертувати лише початкові пробіли на початку рядка (дефолтна поведінка POSIX). Зупиняє перетворення при зустрічі першого непробільного символу. |
| `-t <list>` | `--tabs=<list>` | Встановити крок або список позицій табуляцій (аналогічно до `expand`). |

```sh
# 1. Відновлення табуляцій у Makefile (де початковий відступ вимагає суворого \t)
unexpand --first-only -t 8 Makefile.bad > Makefile

# 2. Тотальне стиснення пробілів у табуляції з кроком 4
unexpand -a -t 4 legacy_data.txt > compressed_tabs.txt
```

## 6. Горизонтальне об'єднання та реляційне з'єднання потоків: `paste` і `join`

### 6.1. Утиліта `paste` (Паралельне та послідовне злиття файлів)

Утиліта `paste` стандарту POSIX.1-2008 з'єднує відповідні рядки одного або кількох вхідних файлів горизонтально через роздільник (за замовчуванням табуляція `\t`).

```sh
paste [-s] [-d list] [file...]
```

#### Прапорці та параметри `paste`

| Прапорець | Довга форма | Опис поведінки |
|---|---|---|
| `-d <list>` | `--delimiters=<list>` | Задати список символів-роздільників між стовпцями. Символи з `<list>` використовуються циклічно зліва направо для кожного сусіднього стовпця. Підтримує escape-символи: `\t` (табуляція), `\n` (новий рядок), `\\` (зворотна коса риска), `\0` (порожній символ — пряме склеювання колонок без роздільника). |
| `-s` | `--serial` | **Послідовний режим:** з'єднує всі рядки одного файлу в один довгий горизонтальний рядок через роздільник, потім обробляє наступний файл. |
| `-` | — | Спеціальне ім'я файлу, що позначає читання зі стандартного вводу `stdin`. Вказування декількох дефісів (`paste - - -`) споживає елементи з `stdin` по черзі, формуючи `N`-колонкову таблицю. |

#### Коди повернення `paste`

- `0` — успішне виконання.
- `>0` — помилка відкриття або читання файлу.

#### Типові приклади застосування `paste`

```sh
# 1. Горизонтальне злиття трьох файлів у єдину CSV-таблицю з комою як роздільником
paste -d ',' users.txt hosts.txt ips.txt > network_map.csv

# 2. Трансформація одного вертикального списку у 4-колонкову матрицю
cat items.txt | paste -d '\t' - - - -

# 3. Згортання рядків одного файлу в єдиний рядок через двокрапку (формування PATH-подібного рядка)
paste -s -d ':' directories.txt
```

### 6.2. Утиліта `join` (Реляційне з'єднання за ключовими полями)

Утиліта `join` стандарту POSIX.1-2008 реалізує операцію реляційного з'єднання (Equi-Join) між двома структурованими текстовими файлами за спільним ключовим полем.

```sh
join [-1 field] [-2 field] [-j field] [-t char] [-a file_num] [-v file_num] [-e string] [-o list] [--check-order] file1 file2
```

#### ⚠️ Фундаментальний інваріант сортування

Обидва файли (`file1` та `file2`) **повинні бути попередньо відсортовані** за полем з'єднання у поточній локалі (`LC_COLLATE` або `LC_ALL=C`). Якщо файли не відсортовані, `join` мовчки пропустить незбіжні записи або перерве роботу з фатальною помилкою.

```sh
# Обов'язкова попередня підготовка вхідних потоків:
LC_ALL=C sort -k1,1 file1.txt -o file1_sorted.txt
LC_ALL=C sort -k1,1 file2.txt -o file2_sorted.txt
```

#### Прапорці та параметри `join`

| Прапорець | Аргумент | Опис специфікації поведінки |
|---|---|---|
| `-1 <N>` | Номер поля (від 1) | Номер ключового поля у першому файлі `file1` (дефолт 1). |
| `-2 <N>` | Номер поля (від 1) | Номер ключового поля у другому файлі `file2` (дефолт 1). |
| `-j <N>` | Номер поля (від 1) | Встановити однаковий номер поля з'єднання для обох файлів (еквівалент `-1 N -2 N`). |
| `-t <char>` | Один символ | Символ-роздільник полів. Якщо не вказано, роздільником вважається будь-яка послідовність пробільних символів (пробіли та табуляції), а початкові пробіли ігноруються. |
| `-a <N>` | `1` або `2` | **Зовнішнє з'єднання (Outer Join):** виводити непарні рядки з файлу `1` (`-a 1`), файлу `2` (`-a 2`) або обох (`-a 1 -a 2`). |
| `-v <N>` | `1` або `2` | **Анти-з'єднання (Anti-Join):** виводити **виключно** непарні рядки із зазначеного файлу, придушуючи вивід спільних зіставлених пар. |
| `-e <str>` | Рядок | Замінювати порожні/відсутні поля у виводі на рядок `<str>` при використанні прапорця форматування `-o`. |
| `-o <list>` | Список полів | Специфікація вихідного формату. Приймає список через кому чи пробіл: `0` (ключове поле з'єднання) або `M.N`, де `M` — номер файлу (`1` чи `2`), а `N` — номер поля (наприклад, `-o 0,1.2,2.2,2.3`). |
| — | `--check-order` | (Розширення GNU): примусово перевіряти, чи вхідні дані строго відсортовані. |
| — | `--nocheck-order` | (Розширення GNU): вимкнути перевірку сортування при роботі з потоками. |

#### Коди повернення `join`

- `0` — усі пари успішно знайдено та об'єднано.
- `>0` — помилка (порушення порядку сортування, неможливість відкрити файл, невірний синтаксис).

#### Рецепти реляційного з'єднання

```sh
# 1. Внутрішнє з'єднання (Inner Join) файлу користувачів /etc/passwd та метаданих відділів
# passwd_clean: user:x:uid:gid:...
# depts.txt:    uid:department_name
join -t ':' -1 3 -2 1 -o 1.1,0,2.2 passwd_clean.txt depts.txt

# 2. Ліве зовнішнє з'єднання (Left Outer Join) з підстановкою прочерка для відсутніх полів
join -t ',' -1 1 -2 1 -a 1 -e 'N/A' -o 0,1.2,2.2 employees.csv salaries.csv

# 3. Знаходження записів, присутніх у першому списку, але відсутніх у другому (Anti-Join / Різниця множин)
join -t $'\t' -v 1 active_nodes.tsv maintenance_nodes.tsv
```

## 7. Сегментація та розбиття файлів і потоків: `split` і `csplit`

### 7.1. Утиліта `split` (Фіксована побайтова, рядкова та блокова сегментація)

Утиліта `split` стандарту POSIX.1-2008 та GNU coreutils призначена для фрагментації файлів або безперервних потоків даних на окремі частини за заданим розміром у байтах, кількістю рядків або фіксованою кількістю рівномірних блоків.

```sh
split [OPTION]... [INPUT [PREFIX]]
```

#### Режими сегментації вхідного потоку

| Прапорець | Довга форма | Тип | Опис поведінки та специфікація |
|---|---|---|---|
| `-b <size>` | `--bytes=<size>` | Розмір пам'яті | Розбивати вхідний потік на файли фіксованого розміру `<size>` байтів. Підтримує мультиплікативні суфікси (див. нижче). |
| `-C <size>` | `--line-bytes=<size>` | Розмір пам'яті | Записувати у кожен файл не більше `<size>` байтів **цілих рядків**. Рядки не розриваються посередині (розбиття відбувається суворо по символу `\n`), окрім випадків, коли довжина одного рядка перевищує `<size>`. |
| `-l <N>` | `--lines=<N>` | Ціле число | Розбивати потік на файли по `<N>` рядків у кожному (дефолт за відсутності опцій — 1000 рядків). |
| `-n <chunks>` | `--number=<chunks>` | Специфікатор чанків | (Розширення GNU): розбити вхідний потік на фіксовану кількість частин за спеціальним алгоритмом (див. матрицю режимів `-n`). |
| `-t <sep>` | `--separator=<sep>` | Символ | (Розширення GNU): використовувати символ `<sep>` замість `\n` як роздільник записів (наприклад, `-t '\0'` для безпечного розбиття NUL-потоків). |

#### Матриця режимів розбиття за кількістю чанків (`-n <chunks>`)

| Значення `<chunks>` | Алгоритм розбиття та поведінка |
|---|---|
| `N` | Розбити вхідний файл на `N` файлів однакового розміру (вимагає можливості позиціювання `lseek()` або відомого розміру). |
| `K/N` | Вивести `K`-ту частину з `N` розрахованих блоків безпосередньо у `stdout` (без створення файлів на диску). |
| `l/N` | Розбити файл на `N` частин приблизно однакового розміру, але без розриву рядків (split strictly on newlines). |
| `l/K/N` | Вивести `K`-ту частину з `N` рядкових блоків у `stdout`. |
| `r/N` | Циклічний розподіл рядків (round-robin) між `N` вихідними файлами (1-й рядок у файл 1, 2-й у файл 2, ..., `N`-й у файл `N`, `(N+1)`-й знову у файл 1). |
| `r/K/N` | Вивести у `stdout` лише `K`-ту чергу рядків при циклічному розподілі round-robin на `N` потоків. |

#### Керування іменами файлів та суфіксами

| Прапорець | Довга форма | Тип | Опис дії |
|---|---|---|---|
| `-a <N>` | `--suffix-length=<N>` | Ціле число | Довжина суфікса згенерованих імен (дефолт — 2). При вичерпанні простору імен утиліта повертає помилку. |
| `-d` | `--numeric-suffixes[=FROM]` | Число (опц.) | Використовувати десяткові числові суфікси (`00`, `01`, `02`...) замість літерних (`aa`, `ab`...). Значення `FROM` задає початкове число. |
| — | `--hex-suffixes[=FROM]` | Число (опц.) | Використовувати шістнадцяткові числові суфікси (`00`..`0f`, `10`...). |
| — | `--additional-suffix=<str>` | Рядок | Додавати фіксоване розширення/суфікс наприкінці кожного генерованого імені файлу (наприклад, `.csv` або `.chunk.gz`). |
| — | `--filter=<cmd>` | Команда оболонки | Спрямовувати потік кожного фрагмента у команду `<cmd>` через конвеєр. Змінна середовища `$FILE` містить згенероване ім'я вихідного файлу. |
| `-e` | `--elide-empty-files` | Прапорець | Придушити створення файлів нульового розміру (0 байтів) при використанні прапорця `-n`. |
| `-u` | `--unbuffered` | Прапорець | Негайно передавати байти у вивід при роботі в режимі `-n r/...`. |
| — | `--verbose` | Прапорець | Виводити діагностичне повідомлення у `stderr` перед відкриттям кожного вихідного файлу. |

#### Підтримувані суфікси розміру пам'яті (`-b`, `-C`)

- Двійкові степені (1024): `K`, `k` ($2^{10}$ = 1024), `M` ($2^{20}$), `G` ($2^{30}$), `T` ($2^{40}$), `P` ($2^{50}$), `E` ($2^{60}$), `Z` ($2^{70}$), `Y` ($2^{80}$), `b` (512 байтів).
- Десяткові степені (1000, GNU): `KB` ($10^3 = 1000$), `MB` ($10^6$), `GB` ($10^9$), `TB` ($10^{12}$) тощо.

#### Коди повернення `split`

- `0` — успішне виконання.
- `>0` — помилка вводу/виводу, вичерпання суфіксів імен або некоректні параметри.

#### Типові приклади використання `split`

```sh
# 1. Розбиття великого архіву на фрагменти по 100 МіБ із числовими суфіксами та розширенням
split -b 100M -d -a 3 --additional-suffix=.part backup.tar.gz archive_chunk_

# 2. Сегментація CSV-файлу по 50 000 рядків із збереженням цілісності рядків
split -l 50000 -d dataset.csv dataset_split_ --additional-suffix=.csv

# 3. Розбиття на 4 рівні частини з паралельним стисненням zstd «на льоту»
split -n 4 --filter='zstd -q -o $FILE.zst' large_database.dump db_part_

# 4. Вибірка 2-ї чверті файлу по рядках безпосередньо у конвеєр без запису на диск
split -n l/2/4 huge_log.txt | grep "CRITICAL_ERROR"
```

### 7.2. Утиліта `csplit` (Контекстне розбиття за шаблонами та регулярними виразами)

Утиліта `csplit` (*Context Split*) стандарту POSIX.1-2008 розділяє файл або вхідний потік на частини на основі змісту — регулярних виразів, маркерів розділів або номерів рядків.

```sh
csplit [OPTION]... FILE PATTERN...
```

#### Граматика та синтаксис шаблонів (`PATTERN`)

Шаблони передаються позиційними аргументами і виконуються послідовно зліва направо:

| Шаблон | Тип | Опис поведінки та специфікація меж |
|---|---|---|
| `/REGEX/[OFFSET]` | Регулярний вираз (BRE) | Створює вихідний файл, що містить рядки від поточної позиції до рядка, який відповідає виразу `REGEX` (не включаючи рядок збігу). Рядок збігу стає початком наступного вихідного файлу. Опційний `OFFSET` (`+N` або `-N`) зміщує межу розбиття на `N` рядків вперед або назад. |
| `%REGEX%[OFFSET]` | Пропуск блоку (Skip) | Працює аналогічно до `/REGEX/[OFFSET]`, але **відкидає (пропускає)** виділений блок рядків — вихідний файл для нього не створюється. Застосовується для ігнорування заголовків, преамбул та сміттєвих даних. |
| `<N>` | Номер рядка | Створює вихідний файл від поточної позиції до абсолютного номера рядка `<N>` у файлі (не включаючи рядок `<N>`). Рядок `<N>` стає першим рядком наступного файлу. |
| `{REPEAT}` | Модифікатор повторення | Застосовує попередній шаблон повторно:<ul><li>`{N}` — повторити попередній шаблон рівно `N` разів (де `N >= 1`).</li><li>`{*}` — повторювати попередній шаблон максимальну кількість разів до досягнення кінця файлу (EOF).</li></ul> |

#### Параметри командного рядка `csplit`

| Прапорець | Довга форма | Тип | Опис специфікації |
|---|---|---|---|
| `-f <prefix>` | `--prefix=<prefix>` | Рядок | Префікс імен вихідних файлів (дефолт — `'xx'`). |
| `-b <format>` | `--suffix-format=<format>` | Формат `sprintf` | Рядок форматування суфікса у синтаксисі функції `sprintf()` (дефолт — `"%02d"`). Мусить містити рівно один специфікатор перетворення цілого числа (`%d`, `%u`, `%x`, `%o`). |
| `-n <digits>` | `--digits=<digits>` | Ціле число | Кількість десяткових цифр у суфіксі (дефолт — 2; еквівалент `-b "%0Nd"`). |
| `-k` | `--keep-files` | Прапорець | Зберігати вже створені вихідні файли при виникненні помилки. За замовчуванням при помилці пошуку шаблону або неочікуваному EOF `csplit` негайно видаляє всі створені під час поточного запуску файли. |
| `-z` | `--elide-empty-files` | Прапорець | Видаляти створені вихідні файли нульової довжини (0 байтів). Запобігає появі порожнього файлу `xx00`, коли перший рядок вхідного потоку одразу збігається з першим шаблоном. |
| `-s`, `-q` | `--silent`, `--quiet` | Прапорець | Придушити вивід розміру (кількості байтів) кожного створеного файлу у стандартний вивід `stdout`. |
| — | `--suppress-matched` | Прапорець | (Розширення GNU): вилучити рядок, що збігся з шаблоном, з вихідних файлів (рядок не потрапляє ні в кінець попереднього, ні на початок наступного файлу). |

#### Коди повернення `csplit`

- `0` — успішне завершення. Усі шаблони знайдено та виконано, або досягнуто кінця файлу в циклі `{*}`.
- `>0` — помилка: шаблон не знайдено у вхідному потоці, неочікуваний EOF без прапорця повторення `{*}` або збій запису на диск.

#### Типові приклади використання `csplit`

```sh
# 1. Розбиття поштової скриньки mbox на окремі листи з числовим префіксом
csplit -s -f email_ -b "%04d.eml" -k mailbox.mbox '/^From /' '{*}'

# 2. Розбиття C/C++ коду за заголовками секцій з видаленням початкового преамбульного блоку
csplit -z -f section_ -b "%02d.c" source.c '%/\* === SECTION%' '//\* === SECTION/' '{*}'

# 3. Розбиття за фіксованими номерами рядків (рядки 1-99 у file00, 100-499 у file01, 500+ у file02)
csplit -f part_ input.txt 100 500

# 4. Виділення блоку логу з відступом у 2 рядки перед маркером критичної помилки
csplit -f crash_ report.log '/FATAL ERROR/-2'
```

## 8. Конвеєри з нульовим байтом: `find`, `xargs`, `sort`, `cut`, `grep`

Байт `0x00` (NUL) є єдиним октетом, який заборонено використовувати в іменах файлів та шляхах Unix на рівні системних викликів VFS ядра Linux. Це робить його математично надійним роздільником для системної автоматизації.

### 8.1. Матриця прапорців утиліт для підтримки NUL-роздільників

| Утиліта | Прапорець | Призначення та поведінка | Приклад у системному конвеєрі |
|---|---|---|---|
| `find` | `-print0` | Виводити знайдені шляхи, завершуючи кожен запис байтом `\0` замість `\n`. | `find . -type f -name "*.log" -print0` |
| `xargs` | `-0`, `--null` | Розбирати вхідний потік виключно по байту `\0`. Вимикає екранування лапок, бекслешів і пробілів. | `... \| xargs -0 -r rm -f` |
| `sort` | `-z`, `--zero-terminated` | Вважати кінцем рядка байт `\0`, що дозволяє безпечно сортувати шляхи з переносами рядків. | `find . -print0 \| sort -z` |
| `cut` | `-z`, `--zero-terminated` | Читати та фільтрувати записи з роздільником `\0`. | `find /var -print0 \| cut -z -d '/' -f 3-` |
| `grep` | `-Z`, `--null` | Виводити байт `\0` після імені знайденого файлу замість стандартної двокрапки `:`. | `grep -lZ "ERROR" *.log \| xargs -0 gzip` |
| `grep` | `-z`, `--null-data` | Розглядати вхідні дані як суцільний потік записів, розділених `\0`, ігноруючи внутрішні `\n`. | `grep -z "рядок1.*рядок2" memory.dump` |
| `read` (Bash) | `-d ''` | Читати символи з дескриптора до зустрічі байта `\0`. | `while IFS= read -r -d '' f; do ...; done` |
| `tar` | `--null -T -` | Читати список файлів для архівації з `stdin` у форматі NUL-потоку. | `find . -name "*.c" -print0 \| tar -cf src.tar --null -T -` |

### 8.2. Механізм пакетування в `xargs` та ліміти ядра `ARG_MAX`

Утиліта `xargs` агрегує елементи у великі масиви аргументів `argv[]`, мінімізуючи кількість викликів `fork()`/`execve()`.

#### Ключові прапорці `xargs`

- `-0`, `--null`: перемикає розбір аргументів суто на байт `0x00`.
- `-r`, `--no-run-if-empty`: не виконувати цільову команду, якщо вхідний потік порожній (запобігає випадковому запуску `rm` без аргументів).
- `-n <max-args>`: обмежити максимальну кількість аргументів на один виклик команди.
- `-P <max-procs>`: виконувати команди паралельно у вказаній кількості паралельних процесів (worker pool).
- `-I <replace-str>`: підставляти аргумент у вказане місце команди (вимикає групування, виконуючи 1 процес на 1 елемент).

```sh
# Паралельне стиснення файлів у 8 потоків з безпечним розбором імен
find /data -type f -name "*.raw" -print0 | xargs -0 -r -P 8 -n 16 zstd -q --rm
```

#### Системні ліміти ядра Linux

Максимальний сумарний обсяг пам'яті під аргументи командного рядка та змінні оточення задається константою `ARG_MAX` (зазвичай від 2 МіБ до 6 МіБ, перевіряється командою `getconf ARG_MAX`). Крім того, ядро обмежує довжину одного аргументу величиною `MAX_ARG_STRLEN` (32 сторінки пам'яті, тобто 128 КіБ на архітектурі x86_64). `xargs` автоматично розраховує розмір буфера з запасом 2048 байтів під змінні оточення, уникаючи помилки `E2BIG` (Argument list too long).

### 8.3. Вплив локалі на сортування в `sort -z`

Під час обробки списків файлів або текстових записів у конвеєрі `sort -z` поведінка порівняння контролюється змінною `LC_ALL`:

- **`LC_ALL=C` або `LC_ALL=POSIX`:** `sort` виконує пряме побайтове порівняння масивів через системну функцію `memcmp()`. Це забезпечує максимальну продуктивність (прискорення у 10–40 разів) і строго детермінований бінарний порядок сортування.
- **Юнікодна локаль (наприклад, `uk_UA.UTF-8` або `en_US.UTF-8`):** `sort` застосовує алгоритм Unicode Collation Algorithm (UCA) через `strcoll()`, що вимагає розрахунку ваги символів, регістру та діакритики, створюючи значні накладні витрати CPU.

```sh
# Високошвидкісне бінарне сортування NUL-потоку
find /srv/storage -type f -print0 | LC_ALL=C sort -z | xargs -0 -r process_batch
```

## 9. Інструменти діагностики, інспекції та побайтового аналізу

### 9.1. Утиліта `file` (Аналіз сигнатур, MIME та структура `/etc/magic`)

Утиліта `file` використовує бібліотеку `libmagic` для розпізнавання типів файлів, кодувань, структури заголовків та маркерів кінців рядків на основі багаторівневої бази магічних чисел, сигнатурного сканування та статистичних евристик.

```sh
file [options] [file...]
```

#### Повний перелік прапорців утиліти `file`

| Прапорець | Довга форма | Тип | Опис поведінки та специфікація виводу |
|---|---|---|---|
| `-i` | `--mime` | Прапорець | Вивести результат у повному форматі MIME: `Content-Type; charset=Content-Encoding` (наприклад, `text/x-shellscript; charset=utf-8`). |
| — | `--mime-type` | Прапорець | Вивести **виключно** рядок MIME-типу (наприклад, `text/plain`, `text/x-shellscript`, `application/x-executable`, `application/pdf`, `application/zip`). |
| — | `--mime-encoding` | Прапорець | Вивести **виключно** рядок MIME-кодування символів (наприклад, `utf-8`, `us-ascii`, `iso-8859-1`, `binary`, `unknown-8bit`). |
| `-k` | `--keep-going` | Прапорець | Не зупинятися на першому знайденому збігу сигнатури, а продовжувати повну перевірку всіх правил бази `libmagic`. Дозволяє виявляти поліглотні файли, приховані корисні навантаження та складені формати (виводить усі збіги через перенесення рядка). |
| `-z` | `--uncompress` | Прапорець | Прозоро розпаковувати та інспектувати вміст стиснених файлів (`gzip`, `bzip2`, `xz`, `zstd`, `compress`, `lzma`). Утиліта розпаковує потік у тимчасовий буфер/канал і визначає тип запакованого файлу замість контейнера. |
| `-b` | `--brief` | Прапорець | **Короткий режим:** приховати ім'я файлу у виводі (залишити виключно діагностичний рядок опису або MIME). |
| `-m <list>` | `--magic-file=<list>` | Шлях | Використовувати альтернативний список текстових файлів або скомпільованих бінарних баз `magic.mgc` (розділяються двокрапкою `:`). |
| `-C` | `--compile` | Прапорець | Скомпілювати текстовий файл правил `magic` у бінарний індексований файл `magic.mgc` для оптимізації доступу через `mmap()`. |
| `-e <test>` | `--exclude=<test>` | Назва тесту | Виключити зазначену категорію тестів із конвеєра аналізу. Дозволяє прискорити обробку або ізолювати конкретну підсистему (перелік категорій див. нижче). |
| `-f <file>` | `--files-from=<file>` | Шлях | Зчитувати список файлів для перевірки з зазначеного файлу (по одному імені на рядок) або зі стандартного вводу `stdin` при `-f -`. |
| `-N` | `--no-pad` | Прапорець | Не вирівнювати імена файлів пробілами по ширині колонок у виводі. |
| `-L` | `--dereference` | Прапорець | Переходити за символічними посиланнями та аналізувати кінцевий цільовий файл. |
| `-h` | `--no-dereference` | Прапорець | **Не переходити за посиланнями (дефолт):** аналізувати саме символічне посилання (`symbolic link to ...`). |

#### Категорії тестів для прапорця `--exclude` (`-e`)

- `apptype` — перевірка типу застосунків для старих систем (EMX, DOS, OS/2).
- `ascii` — табличні перевірки набору символів ASCII та 8-бітних кодових сторінок.
- `cdf` — аналіз структури Composite Document File (формати Microsoft Office 97-2003 OLE).
- `compress` — детектування заголовків стиснених архівів.
- `csv` — структурний аналізатор файлів значень, розділених комами.
- `elf` — детальний парсер заголовків бінарних виконуваних файлів ELF.
- `encoding` — класифікація кодувань тексту (UTF-8, UTF-16, ISO-8859).
- `soft` — виконання сигнатурних правил із бази даних `libmagic`.
- `tar` — перевірка блокових заголовків архівів TAR.
- `text` — загальні евристики визначення текстових файлів.
- `json` — валідація синтаксичної структури JSON-документів.

---

#### Структура, граматика та синтаксис файлів `/etc/magic`

База даних магічних сигнатур `libmagic` (розміщується у файлах `/etc/magic`, `/usr/share/misc/magic` або скомпільованому `/usr/share/file/magic.mgc`) складається з рядкових правил, які виконуються послідовно та ієрархічно.

Граматика одного рядка правила складається з 4 обов'язкових та 1 опційного стовпця, розділених пробілами або табуляціями:

```text
[>]...[>]offset  type  [test-operator]value  message  [directives]
```

##### 1. Рівень ієрархії та зміщення (`[>]offset`)

- **Рівень вкладеності (`>`):**
  - Без префікса `>` (рівень 0) — кореневе правило. Виконується для кожного перевіреного файлу.
  - `>` (рівень 1) — дочірнє правило. Виконується **лише якщо батьківське правило рівня 0 збіглося**.
  - `>>` (рівень 2), `>>>` (рівень 3) тощо — глибоко вкладені правила для розбору внутрішніх полів структур.
- **Синтаксис зміщення (`offset`):**
  - *Абсолютне:* числове зміщення у байтах від початку файлу (наприклад `0`, `4`, `0x10`, `1024`).
  - *Відносне:* префікс `&offset` — зміщення рахується від кінця останнього збіглого поля попереднього правила.
  - *Непряме (Indirect):* запис `(offset[.type][+adjust])` — зчитує значення покажчика з адреси `offset`, інтерпретує його як абсолютну адресу в файлі і виконує перевірку за цією новою адресою (наприклад, `(0x3c.l)` зчитує 4-байтове зміщення заголовка PE у файлах Windows EXE).

##### 2. Тип даних (`type`)

- **Цілі числа фіксованого розміру:**
  - `byte` — 1-байтове число (`0`..`255`).
  - `short` / `leshort` (Little-Endian) / `beshort` (Big-Endian) — 16-бітне ціле число (2 байти).
  - `long` / `lelong` / `belong` — 32-бітне ціле число (4 байти).
  - `quad` / `lequad` / `bequad` — 64-бітне ціле число (8 байтів).
- **Текстові та байтові рядки:**
  - `string` — послідовність байтів із підтримкою escape-символів (`\n`, `\t`, `\xHH`, `\0`). Підтримує прапорці модифікації: `/c` (нечутливий до регістру), `/b` (ігнорувати пробіли), `/W` (стискати множинні пробіли), `/t` (текстовий режим).
  - `pstring` — Pascal-подібний рядок, де перший байт/слово містить довжину тексту.
- **Пошукові типи та вирази:**
  - `regex` — пошук регулярного виразу POSIX у межах перших байтів файлу.
  - `search[/flags]` — пошук заданого рядка у діапазоні зміщень.
  - `use` / `name` — механізм функціональних макросів та підпрограм усередині magic-файлів.
  - `default` — спрацьовує, якщо жодне правило поточного рівня не дало збігу.
  - `clear` — скидання ланцюжка збігів.

##### 3. Оператор порівняння та значення (`[test-operator]value`)

- **Оператори:** `=` (збіг, дефолт), `<`, `>`, `!`, `&` (побітове «ТА»), `^` (побітове «XOR»), `x` (будь-яке значення — правило завжди вважається успішним).
- **Значення:** числові константи (десяткові `42`, hex `0x454c46`, вісімкові `\177`) або рядкові літерали.

##### 4. Діагностичне повідомлення (`message`)

- Текст, що додається до опису файлу. Підтримує специфікатори формату `printf` (`%s`, `%d`, `%x`, `%u`), у які автоматично підставляється зчитане значення поля.
- Спеціальний керівний символ `\b` (Backspace) на початку повідомлення прибирає стандартний пробіл між фразами, що дозволяє формувати цілісні описи виду `UTF-8 Unicode text, with CRLF line terminators`.

##### 5. Мета-директиви (`directives`)

- `!:mime <mimetype>` — визначає MIME-тип файлу для виводу за прапорцем `--mime-type`.
- `!:ext <extension>` — визначає канонічне розширення файлу.
- `!:strength <value>` — ваговий коефіцієнт пріоритету правила при розв'язанні конфліктів сигнатур.

### 9.2. Утиліта детектування кодувань `uchardet`

`uchardet` — це консольна утиліта на базі рушія Universal Charset Detector (розробленого Mozilla), яка використовує статистичний аналіз n-грамів та скінченні автомати валідації переходів для визначення кодувань невідомих текстів.

```sh
uchardet [file...]
```

- **Підтримувані набори:** `UTF-8`, `UTF-16LE`, `UTF-16BE`, `UTF-32LE`, `WINDOWS-1251`, `KOI8-U`, `KOI8-R`, `ISO-8859-5`, `IBM866`, `WINDOWS-1252`, `SHIFT_JIS`, `EUC-JP`, `GB18030` тощо.
- **Коди завершення:**
  - `0` — кодування успішно визначено.
  - `1` — помилка відкриття або читання вхідного файлу.

```sh
$ uchardet legacy_data.txt
WINDOWS-1251
 
# Автоматична конвертація невідомого файлу в UTF-8 за результатами детектора
encoding=$(uchardet input.txt)
iconv -f "$encoding" -t UTF-8 -o input_utf8.txt input.txt
```

### 9.3. Шістнадцяткові та символьні інспектори: `hexdump`, `od`, `xxd`

#### Утиліта `hexdump` (BSD / Linux)

```sh
hexdump [-C] [-n length] [-s offset] [file...]
```

- `-C` (Canonical): канонічний вивід у шістнадцятковому форматі з лівого боку та друкованими ASCII-символами праворуч. Недруковані байти (включно з `\0`, `\r`, `\n`) позначаються крапкою `.`.
- `-n <length>`: обробити лише зазначену кількість байтів від початку.
- `-s <offset>`: пропустити вказане зміщення від початку файлу.

```sh
# Діагностика перших 16 байтів файлу (виявлення BOM 0xEF 0xBB 0xBF та CRLF 0x0D 0x0A)
hexdump -C -n 16 script.sh
# 00000000  ef bb bf 23 21 2f 62 69  6e 2f 73 68 0d 0a 65 63  |...#!/bin/sh..ec|
```

#### Утиліта `od` (Octal Dump / POSIX Standard)

`od` є обов'язковою стандартною утилітою POSIX для детального інспектування керуючих послідовностей.

```sh
od [-c] [-t type] [-A radix] [-N bytes] [-j bytes] [file...]
```

- `-c`: виводити байти як друковані символи або стандартні C-escape послідовності (`\0`, `\r`, `\n`, `\t`, `\b`, `\f`, `\a`, `\v`).
- `-t <type>`: формат представлення даних:
  - `x1` — шістнадцяткові 1-байтові числа (`0x00`..`0xff`).
  - `u1` — беззнакові десяткові 1-байтові числа (`0`..`255`).
  - `a` — назви символів за стандартом ASCII (наприклад, `nl`, `cr`, `nul`, `sp`).
- `-A <radix>`: система числення адрес зміщення (`x` — hex, `d` — десяткова, `n` — приховати адреси).
- `-N <bytes>`: обмежити аналіз заданою кількістю байтів.

```sh
# Наочний показ невидимих керуючих символів \r та \n
od -c script.sh | head -n 2
# 0000000   #   !   /   b   i   n   /   s   h  \r  \n   e   c   h   o
```

#### Утиліта `xxd` (Hex Dump та реверсивна бінарна збірка)

```sh
xxd [-p] [-r] [-b] [-g bytes] [-c cols] [-l len] [-s offset] [infile [outfile]]
```

| Прапорець | Довга форма | Опис дії |
|---|---|---|
| `-p` | `--plain` | Вивести безперервний плоский hex-дамп без колонок адрес і без ASCII-візуалізації. |
| `-r` | `--reverse` | **Реверсивний режим:** перетворити шістнадцятковий текст назад у бінарний файл. |
| `-b` | `--bits` | Вивести дані у вигляді двійкових бітових послідовностей (`01100001` тощо). |
| `-g <bytes>` | `--groupsize` | Кількість байтів, що групуються пробілом (дефолт 2; `-g 1` виводить окремі байти). |
| `-l <len>` | `--length` | Зупинити читання після вказаної кількості октетів. |
| `-s <offset>` | `--seek` | Почати читання з абсолютного або відносного зміщення у файлі. |

```sh
# 1. Швидкий перегляд бінарного дампу
xxd -g 1 -l 16 script.sh

# 2. Патчинг бінарних даних через текстовий дамп:
xxd input.bin dump.hex
# ... редагування dump.hex у текстовому редакторі ...
xxd -r dump.hex patched.bin
```

## 10. Системна конфігурація Git для кінців рядків та кодувань

### 10.1. Матриця налаштувань `.gitattributes`

Файл `.gitattributes` у кореневому каталозі репозиторію має найвищий пріоритет над локальними конфігураціями розробників і фіксує поведінку нормалізації.

```gitattributes
# 1. Автоматична евристика: нормалізація всіх текстових файлів у LF у сховищі
* text=auto

# 2. Скрипти оболонок та конфігурації POSIX: суворий LF у робочому дереві на всіх ОС
*.sh        text eol=lf
*.bash      text eol=lf
*.zsh       text eol=lf
Makefile    text eol=lf
*.service   text eol=lf

# 3. Специфічні сценарії Windows: збереження CRLF у робочому дереві
*.bat       text eol=crlf
*.cmd       text eol=crlf
*.ps1       text eol=crlf

# 4. Бінарні формати: повна заборона будь-яких текстових евристик та конвертацій
*.png       binary
*.jpg       binary
*.tar.gz    binary
*.so        binary
*.elf       binary

# 5. Спеціальне кодування для файлів UTF-16 (зберігаються в Git як UTF-8)
*.strings   text working-tree-encoding=UTF-16LE-BOM eol=crlf
```

### 10.2. Глобальні параметри конфігурації `core.*`

| Параметр | Можливі значення | Поведінка при `git commit` | Поведінка при `git checkout` | Рекомендована область застосування |
|---|---|---|---|---|
| `core.autocrlf` | `true` | Конвертує `CRLF` → `LF`. | Конвертує `LF` → `CRLF`. | Робочі станції Windows без налаштованого `.gitattributes`. |
| | `input` | Конвертує `CRLF` → `LF`. | Залишає `LF` без змін. | Робочі станції macOS та Linux. |
| | `false` | Записує байти без змін. | Вивантажує байти без змін. | Сервери CI/CD, Docker-контейнери, середовища з суворим `.gitattributes`. |
| `core.eol` | `lf` | — | Застосовує `LF` для файлів із атрибутом `text`. | Уніфіковані середовища Unix/Linux. |
| | `crlf` | — | Застосовує `CRLF` для файлів із атрибутом `text`. | Специфічні середовища збірки Windows. |
| | `native` | — | Застосовує системний формат за замовчуванням (LF на Unix, CRLF на Windows). | Стандартне значення Git за замовчуванням. |
| `core.safecrlf` | `true` | Забороняє коміт і повертає фатальну помилку, якщо конвертація кінців рядків є незворотною (наприклад, у файлі змішано LF та CRLF). | Забороняє вивантаження, якщо конвертація незворотна. | Суворий захист репозиторіїв від пошкодження бінарних або змішаних файлів. |
| | `warn` | Виводить попередження в консоль, але дозволяє виконання операції. | Виводить попередження. | Рекомендовано для станцій розробки. |
| | `false` | Мовчки виконує конвертацію без сповіщень. | Мовчки виконує конвертацію. | Автоматизовані конвеєри CI/CD. |

#### Нормалізація наявного репозиторію після оновлення `.gitattributes`

```sh
# Застосувати нові правила .gitattributes до всіх файлів індексу (Git 2.16+)
git add --renormalize .
git commit -m "chore: нормалізація кінців рядків згідно з .gitattributes"
```
