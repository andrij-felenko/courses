# 📋 Специфікація форматів та типів директив tmpfiles.d

Специфікація форматів `tmpfiles.d` визначає синтаксис декларативних файлів конфігурації, які зчитує та виконує утиліта `systemd-tmpfiles`. Файли мають розширення `.conf` і розміщуються в каталогах `/usr/lib/tmpfiles.d/`, `/run/tmpfiles.d/` та `/etc/tmpfiles.d/`. Кожен непорожній рядок у конфігураційному файлі описує один файловий об'єкт або операцію над групою шляхів у тимчасових чи волотильних файлових системах.

### Загальна структура та правила синтаксису рядка

Рядок конфігурації складається з семи обовязкових полів, які розділяються пробілами або символами табуляції. Якщо поле містить пробіли, його значення огортається подвійними або поодинокими лапками. Порожні рядки та рядки, що починаються із символу `#`, ігноруються парсером як коментарі.

```text
# Тип  Шлях               Режим  Власник  Група  Вік   Аргумент
d      /run/mydaemon       0755   myuser   mygroup -     -
f      /run/mydaemon/pid   0644   myuser   mygroup -     -
L+     /run/mydaemon.sock  -      -        -       -     /run/mydaemon/service.sock
```

Призначення кожного з семи полів описується наступним чином:

1. **Тип (`Type`)**: один або декілька символів, що визначають дію над файловим об'єктом. Тип вказує утиліті `systemd-tmpfiles`, що саме необхідно зробити — створити каталог, обрізати файл, налаштувати права access control list (ACL), створити символьне посилання чи вилучити застарілі об'єкти.
2. **Шлях (`Path`)**: абсолютний шлях до файлового об'єкта у файловій системі. Шлях може містити маски-шаблони (глобінг `*`, `?`, `[...]`), а також системні підстановки специфікаторів (наприклад, `%t` для позначення рантайм-каталогу `/run` або `%S` для каталогу стану `/var/lib`).
3. **Режим (`Mode`)**: вісімковий режим доступу POSIX (наприклад, `0755` для каталогів чи `0640` для файлів). Якщо вказано дефіс `-`, використовується режим за замовчуванням (`0755` для каталогів, `0644` для файлів). Якщо перед режимом стоїть символ `~`, режим застосовується із врахуванням `umask`.
4. **Власник (`User`)**: ім'я користувача або числовий UID. Якщо користувача не існує у момент виконання, `systemd-tmpfiles` намагається розпізнати його через службу `systemd-sysusers` або підсистему NSS. Дефіс `-` залишає власника без змін або використовує `root`.
5. **Група (`Group`)**: ім'я групи або числовий GID. Поведінка аналогічна полю `User`.
6. **Вік (`Age`)**: поріг часу для автоматичного очищення об'єкта під час виконання процедури `systemd-tmpfiles --clean`. Дефіс `-` повністю вимикає очищення даного об'єкта.
7. **Аргумент (`Argument`)**: додаткові параметри, зміст яких залежить від типу директиви. Для символьних посилань `L` аргумент вказує цільовий шлях; для типів `f` та `F` — початковий вміст файлу; для пристроїв `c` та `b` — мажорні та мінорні номери; для `t` — атрибути файлової системи `xattr`.

### Детальний довідник типів директив

Таблиця та наступні роз'яснення описують повний алфавітний перелік типізованих дій, які підтримує парсер `systemd-tmpfiles`:

| Символ | Назва та призначення | Опис детальної поведінки та специфікацій |
| :--- | :--- | :--- |
| `f` | **Create File** | Створює новий порожній файл, якщо він відсутній. Якщо файл вже існує, його вміст не змінюється, але права та власники оновлюються. Якщо в аргументі передано рядок, він записується у файл при створенні. |
| `F` | **Truncate File** | Створює новий файл або обрізає наявний файл до нульової довжини перед записом вмісту з аргументу. |
| `w` | **Write Argument** | Записує рядок з аргументу в існуючий файл (корисно для налаштування параметрів ядра у `/sys` чи `/proc`). Якщо файл відсутній, виникає помилка. |
| `d` | **Create Directory** | Створює каталог, якщо він відсутній, та встановлює режим доступу й власників. Вміст каталогу зберігається. |
| `D` | **Create & Clean Directory** | Створює каталог. Якщо каталог існував до запуску, його вміст повністю очищається під час виконання фази `--create`. |
| `v` | **Btrfs Subvolume** | Створює подтом (subvolume) у файловій системі Btrfs. Якщо цільова файлова система не є Btrfs, створюється звичайний каталог. |
| `q` | **Btrfs Subvolume Quota** | Створює подтом Btrfs та додає його до відповідної групи квот файлової системи. |
| `Q` | **Btrfs Subvolume Sub-Quota** | Створює подтом Btrfs у складі внутрішньої ієрархічної групи квот. |
| `p` | **Named Pipe (FIFO)** | Створює іменований канал FIFO за допомогою системного виклику `mkfifo()`. |
| `L` | **Symlink** | Створює символьне посилання на вказаний в аргументі шлях. Якщо посилання вже існує, воно не перезаписується (якщо не додано модифікатор `L+`). |
| `c` | **Character Device** | Створює вузол символьного пристрою за допомогою `mknod()`. В аргументі вказуються номери `Major:Minor`. |
| `b` | **Block Device** | Створює вузол блочного пристрою. В аргументі передаються номери `Major:Minor`. |
| `C` | **Copy File/Dir** | Копіює файл або каталог із вказаного в аргументі джерела (або з каталогів за замовчуванням `/usr/share/factory/`), якщо цільовий об'єкт відсутній. |
| `x` | **Exclude Path** | Виключає конкретний шлях з процедури очищення за віком під час запуску `systemd-tmpfiles --clean`. |
| `X` | **Exclude Path Recursive** | Виключає вказаний шлях та увесь його внутрішній рекурсивний вміст з очищення за віком. |
| `r` | **Remove File/Empty Dir** | Видаляє конкретний файл або порожній каталог під час виконання фаз `--remove` чи `--create`. |
| `R` | **Remove Recursive** | Рекурсивно видаляє каталог із усім вкладеним вмістом та деревоподібними каталогами. |
| `z` | **Set Ownership/Mode** | Коригує власника, права доступу та контекст безпеки SELinux для існуючого об'єкта без створення нового файлу. |
| `Z` | **Set Ownership/Mode Recursive** | Рекурсивно коригує права, власника та контексти SELinux для каталогу та всіх вкладених об'єктів. |
| `t` | **Set Extended Attributes** | Виставляє розширені атрибути файлової системи (`xattr`). |
| `T` | **Set Xattr Recursive** | Рекурсивно виставляє розширені атрибути `xattr` для каталогу та вкладеного вмісту. |
| `a` | **Set POSIX ACL** | Додає або модифікує списки контролю доступу POSIX ACL для об'єкта. |
| `A` | **Set POSIX ACL Recursive** | Рекурсивно застосовує списки POSIX ACL до всього файлового дерева. |

### Модифікатори та префіксні символи типів

Префікси та суфікси дозволяють тонко налаштовувати умову виконання кожної окремої директиви:

1. **Модифікатор `!` (Завантажувальний режим)**:
   Приписується перед символом типу (наприклад, `!d` або `!r`). Означає, що дана директива повинна виконуватися **виключно під час старт-процесу завантаження системи** (при виклику юніта `systemd-tmpfiles-setup.service`). Під час періодичних запусків за таймером або ручного виклику `systemd-tmpfiles --clean` ця директива ігнорується.

2. **Модифікатор `+` (Перезапис)**:
   Використовується як суфікс після типу (наприклад, `L+` або `C+`). Змушує `systemd-tmpfiles` видалити наявний об'єкт, якщо він заважає створенню нового (наприклад, видаляє існуючий файл для створення символьного посилання).

3. **Модифікатор `=` (Суворий збіг)**:
   Перевіряє тип існуючого об'єкта. Якщо на диску замість очікуваного каталогу виявлено символьне посилання чи файл, операція зупиняється і в журнал записується застереження про відсутність збігу.

4. **Модифікатор `-` (Ігнорування помилок)**:
   Префіксний знак мінус вказує інструменту ігнорувати будь-які помилки файлової системи під час обробки даного рядка (наприклад, відсутність файлу чи непідтримувані розширені атрибути).

5. **Модифікатор `~` (Base64 декодування)**:
   Означає, що аргумент у шостому полі закодовано у форматі Base64. Це дозволяє безпечно передавати двійкові дані або рядки із символами переходу рядка у текстових конфігураціях.

6. **Модифікатор `^` (Атрибути файлів)**:
   Використовується для встановлення низькорівневих прапорців файлової системи Linux (`chattr`), таких як `i` (immutable) або `a` (append-only).

### Специфікація опису часових інтервалів (`Age`)

Поле `Age` визначає тривалість життя файлового об'єкта у тимчасовому сховищі. Формат значення складається з числового величини та літерного суфікса одиниці виміру:

- `s` — секунди (наприклад, `45s`)
- `m` — хвилини (наприклад, `30m`)
- `h` — години (наприклад, `12h`)
- `d` — дні (наприклад, `10d`)
- `w` — тижні (наприклад, `4w`)

Одиниці часу можна комбінувати у межах одного поля без пробілів: `2d12h` відповідає 60 годинам.

Під час виконання очистки `systemd-tmpfiles --clean` аналізує метадані файлів за допомогою виклику `statx()`:
- Перевіряється час останньої модифікації вмісту (`mtime`), час останнього доступу (`atime`) та час зміни стану метаданих (`ctime`). За наявності підтримки файлової системи також враховується час створення файлу (`btime`).
- Файл підлягає видаленню лише тоді, коли **усі** доступні позначки часу перевищують значення, вказане у полі `Age`.
- Для каталогів очищення діє запобіжний механізм: каталог видаляється лише після того, як із нього були вилучені всі вкладені файли, а сам каталог залишався незмінним протягом вказаного часу `Age`.

### Специфікатори підстановки у шляхах та аргументах

У полях `Path` та `Argument` дозволяється використовувати розширювані специфікатори systemd, які динамічно підставляють системні шляхи під час виконання:

- `%t` — розгортається у системний рантайм-каталог `/run`.
- `%S` — розгортається у каталог стану служб `/var/lib`.
- `%C` — розгортається у каталог кешу `/var/cache`.
- `%L` — розгортається у каталог журналів `/var/log`.
- `%m` — підставляє машинний ідентифікатор системи (Machine ID z `/etc/machine-id`).
- `%b` — підставляє ідентифікатор поточного сеансу завантаження (Boot ID).
- `%H` — підставляє мережеве ім'я хоста (hostname).
- `%U` — підставляє UID користувача, від імені якого запущено екземпляр `systemd-tmpfiles`.
