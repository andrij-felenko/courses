# 📋 Довідник опцій OpenSSH для тунелювання портів і сокетів

Цей довідник містить повну технічну специфікацію параметрів командного рядка клієнта `ssh`, директив конфігураційних файлів клієнта (`~/.ssh/config`, `/etc/ssh/ssh_config`), директив демона сервера (`/etc/ssh/sshd_config`) та бінарних повідомлень протоколу Connection Layer (RFC 4254), які керують життєвим циклом, маршрутизацією та безпекою SSH-тунелів.

## 1. Порядок застосування та пріоритет конфігурації

При визначенні параметрів з'єднання клієнт OpenSSH застосовує сувору ієрархію пріоритетів (від найвищого до найнижчого):

1. **Прапорці командного рядка:** Наприклад, `-L`, `-R`, `-D` або `-o Option=Value`. Значення, передані безпосередньо в командному рядку під час виклику, мають найвищий пріоритет і перекривають будь-які конфігураційні файли.
2. **Конфігураційний файл користувача (`~/.ssh/config`):** Індивідуальні налаштування для конкретних секцій `Host` або глобальної секції `Host *`. OpenSSH використовує правило «першого збігу» (first match wins) — якщо директива була визначена у першій відповідній секції, наступні секції для того ж хоста не можуть її перезаписати.
3. **Загальносистемний конфігураційний файл клієнта (`/etc/ssh/ssh_config`):** Системні налаштування за замовчуванням для всіх користувачів операційної системи.
4. **Вбудовані значення за замовчуванням (Compiled Defaults):** Стандартна поведінка кодової бази OpenSSH, якщо параметр не визначено в жодному джерелі.

## 2. Прапорці командного рядка утиліти ssh

Утиліта командного рядка `ssh` надає набір спеціалізованих прапорців для ініціалізації та налаштування поведінки тунелів:

### Прапорець `-L` (Локальне прокидання)
- **Синтаксис:**
  - `-L [bind_address:]port:host:hostport` — прокидання локального TCP-порту на віддалений TCP-вузол.
  - `-L [bind_address:]port:remote_socket` — прокидання локального TCP-порту у віддалений сокет UNIX.
  - `-L local_socket:remote_socket` — прокидання локального UNIX-сокета у віддалений UNIX-сокет.
  - `-L local_socket:host:hostport` — прокидання локального UNIX-сокета у віддалений TCP-вузол.
- **Механізм:** Клієнтський процес відкриває слухаючий сокет на локальній машині. Коли прикладний процес підключається до цього порту, клієнт надсилає серверу запит `SSH_MSG_CHANNEL_OPEN` типу `direct-tcpip`. Віддалений сервер виконує системний виклик `connect()` до `host:hostport` від свого імені та зв'язує обидва потоки. Якщо `bind_address` опущено, прив'язка здійснюється виключно до `127.0.0.1`.

### Прапорець `-R` (Віддалене реверсивне прокидання)
- **Синтаксис:**
  - `-R [bind_address:]port:host:hostport` — відкриття TCP-порту на сервері з перенаправленням на локальний TCP-порт.
  - `-R [bind_address:]port:local_socket` — відкриття TCP-порту на сервері з перенаправленням у локальний сокет UNIX.
  - `-R remote_socket:local_socket` — прокидання віддаленого UNIX-сокета в локальний UNIX-сокет.
  - `-R 0:host:hostport` — динамічний вибір вільного ефемерного порту ядром віддаленого сервера.
- **Механізм:** Клієнт надсилає серверу глобальний запит `SSH_MSG_GLOBAL_REQUEST` типу `tcpip-forward`. Демон `sshd` відкриває слухаючий порт на сервері. При отриманні вхідного з'єднання `sshd` надсилає клієнту запит `SSH_MSG_CHANNEL_OPEN` типу `forwarded-tcpip`, а клієнт підключається до локального хоста.

### Прапорець `-D` (Динамічне прокидання на рівні застосунку)
- **Синтаксис:** `-D [bind_address:]port`
- **Механізм:** Клієнт OpenSSH створює локальний SOCKS4/SOCKS5 проксі-сервер. Прикладні програми надсилають запити `CONNECT` протоколу SOCKS, які клієнт на льоту перетворює у відповідні канали `direct-tcpip` через віддалений сервер.

### Допоміжні прапорці керування сесією
- **`-N` (Do not execute a remote command):** Забороняє виділення процесу оболонки та виконання команд на сервері. Призначений виключно для утримання відкритих каналів перенаправлення портів.
- **`-f` (Fork into background):** Переводить процес `ssh` у фоновий режим безпосередньо перед виконанням команди (після успішної автентифікації та перевірки з'єднання).
- **`-q` (Quiet mode):** Пригнічує попередження, інформаційні банери та більшість повідомлень про помилки.
- **`-T` (Disable pseudo-terminal allocation):** Забороняє виділення псевдотермінала (PTY) на віддаленому сервері.
- **`-g` (Allow remote hosts to connect to local forwarded ports):** Дозволяє віддаленим машинам локальної мережі підключатися до портів, прокинутих через `-L` (еквівалентно прив'язці до адреси `0.0.0.0`).
- **`-W host:port` (Stdio Forwarding):** Перенаправляє стандартний ввід (`stdin`) та вивід (`stdout`) клієнта безпосередньо до вказаного `host:port` через віддалений `sshd` без відкриття локального мережевого порту. Використовується як основа директиви `ProxyJump` та команд бастіонного доступу.
- **`-O ctl_cmd` (Control multiplexing):** Передає команду керування (`check`, `forward`, `cancel`, `exit`, `stop`) майстер-процесу OpenSSH через сокет `ControlPath`. Дозволяє додавати нові правила `-L` або `-R` без розриву активного з'єднання.

## 3. Директиви конфігурації клієнта (`~/.ssh/config`)

Нижче наведено повний перелік директив файлу `~/.ssh/config`, які регулюють поведінку тунелів:

### `LocalForward`
- **Формат:** `LocalForward [bind_address:]port host:hostport` або `LocalForward socket_path socket_path`
- **Опис:** Декларативний аналог прапорця `-L`. Дозволяє описати конфігурацію постійних локальних тунелів для конкретного сервера. В одній секції `Host` дозволяється вказувати довільну кількість директив `LocalForward`.

### `RemoteForward`
- **Формат:** `RemoteForward [bind_address:]port host:hostport` або `RemoteForward socket_path socket_path`
- **Опис:** Декларативний аналог прапорця `-R`.

### `DynamicForward`
- **Формат:** `DynamicForward [bind_address:]port`
- **Опис:** Декларативний аналог прапорця `-D` для автоматичного запуску SOCKS5-проксі при підключенні до даного хоста.

### `ServerAliveInterval`
- **Формат:** `ServerAliveInterval <секунди>` (за замовчуванням `0` — вимкнено)
- **Опис:** Встановлює таймаут у секундах, після закінчення якого за відсутності мережевого трафіку клієнт надсилає через зашифрований транспортний рівень контрольне повідомлення `keepalive@openssh.com`. Це запобігає видаленню запису про з'єднання з таблиць станів маршрутизаторів NAT та брандмауерів.

### `ServerAliveCountMax`
- **Формат:** `ServerAliveCountMax <число>` (за замовчуванням `3`)
- **Опис:** Визначає максимальну кількість поспіль невідповідальних зондів `ServerAliveInterval`, після якої клієнт вважає TCP-з'єднання з сервером повністю мертвим, закриває всі пов'язані локальні сокети та завершує процес з кодом помилки `255`.

### `ExitOnForwardFailure`
- **Формат:** `ExitOnForwardFailure yes | no` (за замовчуванням `no`)
- **Опис:** Якщо параметр увімкнено (`yes`), клієнт `ssh` негайно перериває з'єднання та завершує роботу з кодом `255`, якщо хоча б один із портів або сокетів, вказаних у правилах `-L`, `-R` чи `-D`, не вдалося успішно відкрити (наприклад, через конфлікт зайнятого порту або відмову сервера у правах). Якщо встановлено `no`, клієнт ігнорує збій прокидання і продовжує утримувати термінальну сесію.

### `ForkAfterAuthentication`
- **Формат:** `ForkAfterAuthentication yes | no` (за замовчуванням `no`)
- **Опис:** Декларативний аналог прапорця `-f`. Переводить клієнтський процес у фон після проходження автентифікації.

### `ClearAllForwardings`
- **Формат:** `ClearAllForwardings yes | no` (за замовчуванням `no`)
- **Опис:** Очищує всі попередньо визначені правила прокидання портів, успадковані з глобальних або раніше оброблених секцій конфігураційного файлу.

### `StreamLocalBindUnlink`
- **Формат:** `StreamLocalBindUnlink yes | no` (за замовчуванням `no`)
- **Опис:** Автоматично викликає `unlink()` для видалення існуючого файлу сокета UNIX перед спробою створити новий слухач. Запобігає виникненню помилки `Address already in use`, якщо попередній процес завершився аварійно і залишив файл сокета на диску.

### `StreamLocalBindMask`
- **Формат:** `StreamLocalBindMask <вісімкова_маска>` (за замовчуванням `0177`)
- **Опис:** Встановлює системну маску прав доступу (`umask`) для створюваного UNIX-сокета, обмежуючи доступ до нього іншим користувачам операційної системи.

### `ControlMaster`, `ControlPath`, `ControlPersist`
- **Формат:**
  - `ControlMaster auto | yes | no`
  - `ControlPath ~/.ssh/cm-%r@%h:%p`
  - `ControlPersist 10m | yes | no`
- **Опис:** Вмикає мультиплексування декількох сесій через спільний сокет керування. Дозволяє на льоту додавати нові тунелі до існуючого з'єднання через команду `ssh -O forward -L ...`.

## 4. Директиви конфігурації сервера (`/etc/ssh/sshd_config`)

Налаштування безпеки та дозволів на стороні сервера OpenSSH виконуються у файлі `/etc/ssh/sshd_config`:

### `AllowTcpForwarding`
- **Формат:** `AllowTcpForwarding yes | no | local | remote | all` (за замовчуванням `yes`)
- **Опис:** Головний перемикач безпеки тунелювання TCP:
  - `yes` або `all`: дозволено всі види прокидання портів (`-L`, `-R`, `-D`).
  - `no`: повністю заборонено відкриття будь-яких каналів `direct-tcpip` та `forwarded-tcpip`.
  - `local`: дозволено лише локальне прокидання (`-L` та `-D`), реверсивні тунелі (`-R`) заблоковано.
  - `remote`: дозволено лише віддалене реверсивне прокидання (`-R`), локальні тунелі заблоковано.

### `AllowStreamLocalForwarding`
- **Формат:** `AllowStreamLocalForwarding yes | no | local | remote | all` (за замовчуванням `yes`)
- **Опис:** Регулює дозвіл на прокидання локальних та віддалених сокетів простору імен UNIX.

### `GatewayPorts`
- **Формат:** `GatewayPorts no | yes | clientspecified` (за замовчуванням `no`)
- **Опис:** Контролює адресу прив'язки для віддалених (реверсивних) тунелів `-R`:
  - `no`: демон `sshd` примусово прив'язує порт виключно до `127.0.0.1` на сервері. Зовнішні підключення з інтернету неможливі.
  - `yes`: демон `sshd` примусово прив'язує всі віддалені тунелі до `0.0.0.0`, відкриваючи їх для всього світу.
  - `clientspecified`: сервер дозволяє клієнту явно вказувати адресу інтерфейсу у команді `-R [bind_address:]port:...`.

### `PermitOpen`
- **Формат:** `PermitOpen host:port [host:port ...]` або `PermitOpen any | none` (за замовчуванням `any`)
- **Опис:** Створює білий список дозволених кінцевих адрес і портів для локального прокидання `-L`. Сервер відхиляє відкриття каналів `direct-tcpip` до будь-яких цілей, не зазначених у списку.

### `PermitListen`
- **Формат:** `PermitListen [bind_address:]port [...]` або `PermitListen any | none` (за замовчуванням `any`)
- **Опис:** Створює білий список дозволених портів для реверсивного прокидання `-R`.

### `ClientAliveInterval` та `ClientAliveCountMax`
- **Формат:** `ClientAliveInterval <секунди>`, `ClientAliveCountMax <число>`
- **Опис:** Серверний механізм надсилання контрольних повідомлень клієнту для перевірки його працездатності та автоматичного закриття сесій у разі розриву з'єднання.

### `DisableForwarding`
- **Формат:** `DisableForwarding yes | no` (за замовчуванням `no`)
- **Опис:** Комплексна директива безпеки: якщо встановлено `yes`, сервер повністю вимикає всі види перенаправлення — TCP, UNIX-сокети, X11, пересилання агентів автентифікації та віртуальні мережеві інтерфейси TUN/TAP.

## 5. Протокольні повідомлення Connection Layer (RFC 4254)

Під час створення та обслуговування тунелів клієнт і сервер обмінюються бінарними пакетами наступної структури:

### 1. `SSH_MSG_CHANNEL_OPEN` (код 90) для `direct-tcpip`

Запит клієнта на локальне прокидання порту до віддаленої цілі:

| Поле | Тип даних | Опис значення |
| :--- | :--- | :--- |
| `type` | `byte` | Числовий код `90` |
| `channel_type` | `string` | Значення `"direct-tcpip"` |
| `sender_channel` | `uint32` | Локальний числовий ідентифікатор каналу на клієнті |
| `initial_window_size` | `uint32` | Розмір буфера прийому клієнта в байтах (зазвичай 2 МБ) |
| `max_packet_size` | `uint32` | Максимальний розмір корисного навантаження одного пакета (32 КБ) |
| `host_to_connect` | `string` | Доменне ім'я або IP-адреса цілі (розпізнається сервером) |
| `port_to_connect` | `uint32` | Цільовий TCP-порт призначення |
| `originator_IP` | `string` | IP-адреса вихідного локального клієнта (наприклад, `"127.0.0.1"`) |
| `originator_port` | `uint32` | Локальний порт клієнтського застосунку |

### 2. `SSH_MSG_CHANNEL_OPEN` (код 90) для `forwarded-tcpip`

Повідомлення сервера клієнту про прийом вхідного підключення на віддалений порт:

| Поле | Тип даних | Опис значення |
| :--- | :--- | :--- |
| `type` | `byte` | Числовий код `90` |
| `channel_type` | `string` | Значення `"forwarded-tcpip"` |
| `sender_channel` | `uint32` | Номер каналу на сервері |
| `initial_window_size` | `uint32` | Розмір буфера прийому сервера |
| `max_packet_size` | `uint32` | Максимальний розмір пакета |
| `connected_address` | `string` | Адреса інтерфейсу сервера, на яку надійшло підключення |
| `connected_port` | `uint32` | Порт сервера, на який надійшло підключення |
| `originator_IP` | `string` | IP-адреса зовнішнього клієнта в інтернеті |
| `originator_port` | `uint32` | Вихідний порт зовнішнього клієнта |

### 3. `SSH_MSG_GLOBAL_REQUEST` (код 80) для реєстрації `tcpip-forward`

Запит клієнта на відкриття слухаючого порту на сервері:

| Поле | Тип даних | Опис значення |
| :--- | :--- | :--- |
| `type` | `byte` | Числовий код `80` |
| `request_name` | `string` | Значення `"tcpip-forward"` |
| `want_reply` | `boolean` | `true` (вимагати підтвердження `REQUEST_SUCCESS` / `REQUEST_FAILURE`) |
| `address_to_bind` | `string` | Бажана адреса прив'язки (`"127.0.0.1"`, `"0.0.0.0"` або `""`) |
| `port_to_bind` | `uint32` | Бажаний TCP-порт сервера (`0` для динамічного виділення) |

### 4. Відповіді та коди помилок

- **`SSH_MSG_CHANNEL_OPEN_CONFIRMATION` (код 91):** Підтвердження відкриття каналу. Містить поля `recipient_channel`, `sender_channel`, `initial_window_size` та `max_packet_size`.
- **`SSH_MSG_CHANNEL_OPEN_FAILURE` (код 92):** Відхилення запиту на створення тунелю. Містить поле `reason_code`:
  - `1` (`SSH_OPEN_ADMINISTRATIVELY_PROHIBITED`) — операцію заблоковано конфігурацією (`AllowTcpForwarding no`, `PermitOpen` тощо).
  - `2` (`SSH_OPEN_CONNECT_FAILED`) — системний виклик `connect()` до цілі зазнав невдачі (хост недоступний, порт закритий, збій маршрутизації).
  - `3` (`SSH_OPEN_UNKNOWN_CHANNEL_TYPE`) — непідтримуваний тип каналу.
  - `4` (`SSH_OPEN_RESOURCE_SHORTAGE`) — вичерпано ліміти файлових дескрипторів або системної пам'яті на вузлі.
- **`SSH_MSG_CHANNEL_WINDOW_ADJUST` (код 93):** Повідомлення про звільнення буфера прийому та додавання зазначеної кількості байтів (`bytes to add`) до доступного вікна відправника.
- **`SSH_MSG_CHANNEL_DATA` (код 94):** Пакет передачі корисного навантаження TCP-потоку.
- **`SSH_MSG_CHANNEL_EOF` (код 96):** Сигнал про завершення передачі даних у даному напрямку (аналог закриття сокета на запис через `shutdown(SHUT_WR)`).
- **`SSH_MSG_CHANNEL_CLOSE` (код 97):** Остаточне закриття та утилізація логічного каналу з обох сторін з'єднання.
