# 📋 Інтерфейси анотацій Lockdep та статистика /proc

Підсистема Lockdep надає розробникам ядра Linux та авторам модулів широкий набір макросів, системних анотацій, опцій конфігурації ядра та діагностичних файлів у псевдофайлових системах `/proc` та `/sys`. Ці інтерфейси дозволяють керувати поведінкою валідатора, усувати хибні спрацьовування при роботі зі складними ієрархічними структурами даних, явно гарантувати дотримання контрактів синхронізації та збирати детальну статистику про стан примітивів під час виконання.

## С-макроси та API анотацій (`<linux/lockdep.h>`)

Для запобігання помилковим спрацьовуванням та явного декларування інваріантів у коді ядра використовуються спеціальні API-функції та макроси, оголошені в заголовочному файлі `<linux/lockdep.h>`.

### 1. Ієрархічні підкласи блокувань (`_nested`)

Коли код ядра бере кілька блокувань одного і того ж типу в ієрархічній структурі (наприклад, м'ютекс батьківського каталогу, а потім м'ютекс дочірнього каталогу у VFS), Lockdep за замовчуванням сприймає це як спробу рекурсивного захоплення одного й того самого класу лока. Для явного вказівки рівня вкладеності застосовуються варіанти функцій із суфіксом `_nested`:

```c
void mutex_lock_nested(struct mutex *lock, unsigned int subclass);
int spin_lock_nested(spinlock_t *lock, unsigned int subclass);
void down_read_nested(struct rw_semaphore *sem, int subclass);
void down_write_nested(struct rw_semaphore *sem, int subclass);
```

#### Параметри викликів:
- **`lock`**: Вказівник на екземпляр примітива синхронізації (`struct mutex`, `spinlock_t`, `struct rw_semaphore`).
- **`subclass`**: Цілочисельний рівень вкладеності (константа від `0` до `7`, визначена для відповідної підсистеми).

#### Поширені значення підкласів у ядрі:
- **`SINGLE_DEPTH_NESTING`**: Базовий підклас (`1`) для стандартних подвійних блокувань однакових об'єктів.
- **`I_MUTEX_NORMAL`**: Стандартний рівень вкладеності для звичайного іноду VFS (`0`).
- **`I_MUTEX_PARENT`**: М'ютекс батьківського каталогу при операціях перейменування чи створення файлів (`1`).
- **`I_MUTEX_CHILD`**: М'ютекс дочірнього об'єкта у VFS (`2`).
- **`I_MUTEX_XATTR`**: М meтекc розширених атрибутів файлової системи (`3`).

Застосування `mutex_lock_nested()` повідомляє Lockdep, що замок береться на строго визначеному глибшому рівні ієрархії, що розриває хибне припущення про рекурсію або циклічну залежність.

---

### 2. Динамічне призначення класів та ключів

Коли блоки пам'яті або структури даних виділяються динамічно (наприклад, при створенні нового мережевого пристрою чи монтуванні файлової системи) і потребують власних ізольованих класів блокування, що не залежать від статичного місця оголошення `spinlock_t`:

```c
void lockdep_set_class(struct lockdep_map *lock, struct lock_class_key *key);
void lockdep_set_class_and_name(struct lockdep_map *lock, 
                               struct lock_class_key *key, 
                               const char *name);
void lockdep_set_subclass(struct lockdep_map *lock, 
                          unsigned int subclass, 
                          struct lock_class_key *key);
```

#### Деталізація аргументів:
- **`lock`**: Вказівник на мапу блокування (поле `dep_map`, вбудоване у `spinlock_t` або `struct mutex`).
- **`key`**: Вказівник на статичний об'єкт `struct lock_class_key`. Ключ мусить зберігатися у статичній пам'яті ядра (`static struct lock_class_key my_key`), оскільки Lockdep використовує його адресу як унікальний ідентифікатор класу протягом усього часу роботи системи.
- **`name`**: Символьний рядок із назвою класу, який буде виводитися у звітах `dmesg` та інтерфейсі `/proc/lockdep`.

---

### 3. Твердження та перевірки володіння (Asserts)

Макроси тверджень призначені для статичної та динамічної перевірки того, що потік тримає необхідний замок перед виконанням критичної операції. Якщо замок не утримується, Lockdep виводить стек викликів (stack trace) і попередження у системний журнал, запобігаючи виконанню некоректного коду.

```c
lockdep_assert_held(lock);
lockdep_assert_held_once(lock);
lockdep_assert_not_held(lock);
lockdep_assert_held_exclusive(lock);
lockdep_assert_held_read(lock);
```

#### Семантика перевірок:
- **`lockdep_assert_held(lock)`**: Гарантує, що поточний процес тримає блокування `lock` (у режимі читання або запису). Якщо замок не взято, виводиться WARNING. Використовується на початку внутрішніх функцій підсистем, які вимагають попереднього захоплення блокування зовнішнім викликом.
- **`lockdep_assert_held_once(lock)`**: Працює аналогічно до `lockdep_assert_held()`, але виводить попередження лише один раз за час роботи ядра, щоб уникнути заспамлювання системного логу у високочастотних циклах.
- **`lockdep_assert_not_held(lock)`**: Гарантує, що блокування *не* утримується поточною задачею. Використовується перед викликом функцій, які будуть брати це блокування монопольно, де повторне захоплення спричинить рекурсивний дедлок.
- **`lockdep_assert_held_exclusive(lock)`**: Перевіряє, що блокування утримується у монопольному режимі (режим запису для `rwlock_t` або `rw_semaphore`).
- **`lockdep_assert_held_read(lock)`**: Перевіряє, що блокування утримується хоча б у режимі читання.

---

### 4. Фіксація стану блокувань (Lock Pinning)

Застосовується у критичних системних підсистемах (наприклад, у планировщику задач scheduler) для запобігання випадковому звільненню або повторному взяттю замка всередині складного ланцюжка викликів:

```c
struct pin_cookie lockdep_pin_lock(struct lockdep_map *lock);
void lockdep_unpin_lock(struct lockdep_map *lock, struct pin_cookie cookie);
```

- **`lockdep_pin_lock()`**: Повертає спеціальну структуру-печиво (`struct pin_cookie`) і заморожує стан блокування. Будь-яка спроба звільнити замок `lock` до виклику `lockdep_unpin_lock()` із відповідним `cookie` призведе до миттєвого спрацьовування WARNING.

---

### 5. Ручне керування та вимкнення валідатора

```c
void lockdep_off(void);
void lockdep_on(void);
int lockdep_is_held(void *lock);
```

- **`lockdep_off()` / `lockdep_on()`**: Пригнічує перевірки Lockdep для поточного потоку. Використовується виключно у низькорівневих обробниках аварійних ситуацій (panic handlers, kdump, architecture exception handlers), де сам Lockdep може спричинити рекурсивний збій.
- **`lockdep_is_held(lock)`**: Повертає `1`, якщо замок утримується поточним потоком, і `0` у протилежному випадку. Корисно для умовних викликів `WARN_ON(!lockdep_is_held(lock))`.

## Опції конфігурації ядра (Kconfig)

Перевірка залежностей Lockdep керується набором прапорців конфігурації ядра при збірці (`.config`).

| Параметр Kconfig | Функціональне призначення | Вплив на розмір ядра та RAM | Накладні витрати (CPU Overhead) |
| :--- | :--- | :--- | :--- |
| `CONFIG_LOCKDEP_SUPPORT` | Базова архітектурна підтримка Lockdep у коді ядра (визначається у коді `arch/`). | Незначний (<1 КБ) | Відсутні (0%) |
| `CONFIG_LOCKDEP` | Вмикає внутрішній рушій відстеження класів блокувань та побудови графа залежностей. | +200–500 КБ код | Низькі (~5% CPU) |
| `CONFIG_PROVE_LOCKING` | Головний прапорець. Вмикає активний аналіз графа на наявність дедлоків ABBA та IRQ-інваріантів. | Додає таблиці графа | Високі (20–40% CPU) |
| `CONFIG_LOCK_STAT` | Збирає статистику часових затримок очікування, володіння та рівня конкуренції (contention). | +100 КБ коду | Середні (10–15% CPU) |
| `CONFIG_DEBUG_LOCK_ALLOC` | Додає поля `struct lockdep_map` до всіх примітивів блокувань для відстеження виділення. | +16–24 байти на lock | Малі (~3% RAM) |
| `CONFIG_LOCKDEP_SMALL` | Зменшує розміри внутрішніх масивів `MAX_LOCKDEP_KEYS` для систем із обмеженою RAM. | Економія до 8 МБ RAM | Більший ризик переповнення |
| `CONFIG_DEBUG_LOCKING_API_SELFTESTS` | Запускає серію автоматичних самотестів Lockdep під час завантаження ядра. | +50 КБ коду | Лише при старті ядра |

## Діагностичні інтерфейси `/proc` та `/sys`

При ввімкненій опції `CONFIG_LOCKDEP` ядро експортує стан валідатора через псевдофайли у `/proc`.

### 1. `/proc/lockdep` — Перелік зареєстрованих класів

Містить список усіх активних класів блокувань, відомих ядру на даний момент.

```text
# cat /proc/lockdep | head -n 25
all lock classes:
ffffffff832a4e80 ops: 124505 [ffffffff832a4e80] &(&sb->s_type->i_mutex_key)#2
 -> max cycle-stuff: 12
 -> min cycle-stuff: 0
ffffffff832a5120 ops: 84201  [ffffffff832a5120] &(&ip->i_lock)#3
 -> hardirq-safe: 0, hardirq-unsafe: 1
 -> softirq-safe: 0, softirq-unsafe: 1
 -> hardirq-read-safe: 0, hardirq-read-unsafe: 0
 -> softirq-read-safe: 0, softirq-read-unsafe: 0
```

#### Деталізація полів звіту:
- **`ffffffff832a4e80`**: Шеснадцятирічна адреса ключа класу `struct lock_class_key` у пам'яті ядра.
- **`ops`**: Сумарна кількість операцій захоплення та звільнення блокувань даного класу від моменту старту ядра.
- **`&(&sb->s_type->i_mutex_key)#2`**: Символьна назва класу із зазначенням рівня підкласу (`#2`).
- **`hardirq-safe / hardirq-unsafe`**: Лічильники спостережуваних контекстів виконання. Збільшення `hardirq-unsafe` до `1` означає, що замок хоча б один раз беруть у процесному контексті з увімкненими апаратними перериваннями.

---

### 2. `/proc/lockdep_stats` — Загальна лічильна статистика

Показує використання внутрішніх таблиць Lockdep, стан пам'яті та лічильники перевірок.

```text
# cat /proc/lockdep_stats
 lock-classes:                         1420 [max: 8191]
 direct dependencies:                  4812 [max: 32768]
 chain-deps:                          18920 [max: 65536]
 fixed-chains:                        12401
 dependency chains:                   11042 [max: 65536]
 dependency chain hlocks:             42105 [max: 327680]
 in-hardirq chains:                     312
 in-softirq chains:                     845
 in-process chains:                   17763
 max lock-depth:                         11
 max stack-depth:                        24
 lockdep internal errors:                 0
```

#### Розшифровка важливих лічильників:
- **`lock-classes`**: Поточна кількість виявлених класів відносно максимального ліміту `MAX_LOCKDEP_KEYS` (8191).
- **`direct dependencies`**: Кількість прямих ребер залежності `A -> B` у графі залежностей.
- **`dependency chains`**: Кількість захешованих послідовностей захоплення блокувань (`lock_chain`).
- **`max lock-depth`**: Максимальна глибина одночасно утримуваних блокувань одним потоком (наприклад, 11 означає, що один потік тримав 11 замків одночасно).
- **`lockdep internal errors`**: Лічильник внутрішніх помилок або переповнень масивів (значення > 0 свідчить про те, що Lockdep вимкнувся через брак пам'яті для графа).

---

### 3. `/proc/lockdep_chains` — Хеш-таблиця ланцюжків блокувань

Показує захешовані послідовності захоплення блокувань (`lock_chain`). Кожен унікальний ланцюжок (наприклад, потік бере `Lock1 -> Lock2 -> Lock3`) отримує 64-бітне хеш-значення. Це дозволяє Lockdep виконувати швидкий пошук `O(1)` і не перевіряти граф повторно для послідовностей, які вже були звалідовані раніше.

---

### 4. `/proc/lock_stat` — Статистика затримок та аналіз конкуренції

Доступний при ввімкненому `CONFIG_LOCK_STAT`. На відміну від валідатора дедлоків, цей інтерфейс слугує профайлером продуктивності блокувань:

```text
# cat /proc/lock_stat | head -n 20
lock_stat version 0.4
-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
                              class name    contentions   waittime-min   waittime-max   waittime-total   acquisitions   holdtime-min   holdtime-max   holdtime-total
-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
                      &rq->lock:                  142          0.12           45.12         1204.30         458102           0.05          120.45        84920.10
             &(&ip->i_lock)#3:                   12          0.45           12.30           89.10          94210           0.10           54.12        12450.00
```

#### Пояснення метрик продуктивності:
- **`contentions`**: Кількість випадків, коли потік мусив чекати, бо блокування вже було зайнято іншим потоком.
- **`acquisitions`**: Загальна кількість успішних операцій захоплення блокувань даного класу.
- **`waittime-min / max / total`**: Мінімальний, максимальний та сумарний час очікування блокування у мікросекундах (μs). Великі значення `waittime-total` вказують на вузькі місця продуктивності (lock bottlenecks).
- **`holdtime-min / max / total`**: Тривалість утримання блокування у критичній секції у мікросекундах. Великий `holdtime-max` свідчить про те, що якийсь потік виконував тривалі обчислення або I/O всередині критичної секції спінлока.

### 5. Інтерфейси Debugfs (`/sys/kernel/debug/lockdep/`)

При збірці ядра з підтримкою Debugfs (`CONFIG_DEBUG_FS`) у каталозі `/sys/kernel/debug/lockdep/` з'являються додаткові важелі керування та поглибленого інспектування:

- **`/sys/kernel/debug/lockdep/lock_chains`**: Розширена дампова таблиця всіх ланцюжків із виведенням повних назв класів.
- **`/sys/kernel/debug/lockdep/stats`**: Поточні системні метрики викликів валідатора.
- **`/sys/kernel/debug/clear_lock_stat`**: Запис `1` у цей файл скидає всі накопичені лічильники у `/proc/lock_stat`, що дозволяє проводити чисті заміри продуктивності під час виконання конкретного бенчмарка.
