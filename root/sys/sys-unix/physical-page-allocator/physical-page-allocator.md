# Фізичні сторінки в ядрі: зони, блоки за порядками й ущільнення

<preknowlist>
- [Сторінки, таблиці сторінок і MMU](root:sf-os/paging-and-mmu) — пам'ять нарізана на кадри, а MMU транслює віртуальні адреси у фізичні.
- [Віртуальний адресний простір процесу](root:sf-os/virtual-address-space) — процес бачить власну безперервну пам'ять незалежно від розташування фізичних кадрів.
- [Свопінг і витіснення сторінок](root:sys-unix/swap-and-reclaim) — позначки рівня вільної пам'яті та витіснення сторінок на диск.
- [Прямий доступ до пам'яті (DMA)](root:hw-arch/dma) — пристрої читають і пишуть фізичну пам'ять напряму без участі процесора.
</preknowlist>

Уявіть ситуацію: системна утиліта `free` показує кілька гігабайтів вільної оперативної пам'яті, але драйвер мережевої карти чи відеокодека не може виділити суцільний буфер на 256 кілобайтів і повертає помилку про брак пам'яті (`-ENOMEM`).

Це не помилка лічильника і не збій ядра. Звичайна прикладна програма взагалі не вимагає суцільності у фізичній пам'яті: MMU процесора непомітно зшиває розрізнені фізичні кадри (по 4 КіБ) у суцільний віртуальний простір адрес. Але для апаратури, самого ядра та великих сторінок форма вільного фізичного простору має вирішальне значення.

Потреба в суцільних фізичних кадрах виникає у трьох основних випадках:
1. **Апаратні пристрої (DMA)**: Багато контролерів периферійних шин виставляють фізичні адреси напряму на шину в обхід процесорного MMU. Якщо у системі немає спеціального контролера IOMMU, пристрою потрібен суцільний фізичний буфер, інакше він почне писати дані в кадри інших процесів.
2. **Пряме відображення ядра**: Ядро Linux тримає фізичну пам'ять відображеною у свій власний адресний простір простим додаванням зсуву адрес. Якщо ядерній структурі даних потрібен буфер на 32 КіБ, під ним мають лежати 8 фізичних кадрів поспіль, інакше покажчики всередині структури вкажуть у порожнечу.
3. **Великі сторінки (Huge Pages)**: Велика сторінка розміром 2 МіБ значно зменшує промахи в кеші перекладу адрес (TLB), але вимагає строго 512 суцільних кадрів, вирівняних на межу двох мегабайтів.

Для роздачі фізичної пам'яті ядро використовує найнижчий рівень — розподільник фізичних сторінок, який працює за алгоритмом системи приятелів (Buddy Allocator).

## Система приятелів (Buddy Allocator)

Головна вимога до будь-якого базового розподільника — це не просто швидке виділення пам'яті, а миттєве злиття сусідніх вільних шматків при її поверненні. Якщо дозволити блоки довільного розміру, при звільненні доведеться сканувати списки за адресами. При мільйонах операцій на секунду такий пошук миттєво заблокує систему.

Система приятелів розв'язує цю проблему обмеженням можливих форм. Вся пам'ять ділиться на блоки, розмір яких — строго степінь двійки; показник цього степеня звуть **порядком** (order):
- Порядок 0: 1 кадр (4 КіБ)
- Порядок 1: 2 кадри (8 КіБ)
- Порядок 2: 4 кадри (16 КіБ)
- …
- Порядок 10: 1024 кадри (4 МіБ на x86-64) — межа `MAX_PAGE_ORDER`.

Коли потрібен блок порядку k, а у списку є лише більший блок порядку k+1, той ділиться навпіл на двох "приятелів". Головна властивість такого поділу — індекс партнера не треба шукати у списку, він обчислюється однією побітовою операцією виключного «або» (`index ⊕ (1 << order)`). При звільненні блок перевіряє стан свого приятеля: якщо той теж вільний, вони миттєво об'єднуються у блок порядку k+1. Злиття відбувається за сталий час O(1).

Для одинарних кадрів (порядок 0) перед системою приятелів стоїть швидкий локальний кеш — посторінкові списки на кожне ядро (PCP, per-CPU page sets). Вони дозволяють роздавати одинарні кадри взагалі без взяття спільного замка зони.

Базовий API ядра повертає покажчик на першу структуру `struct page` виділеного блоку:

```c
#include <linux/gfp.h>
#include <linux/mm.h>

/* Просимо 4 кадри (порядок 2) звичайної пам'яті */
struct page *pages = alloc_pages(GFP_KERNEL, 2);
if (!pages) {
    /* Немає суцільного блоку потрібного розміру */
    return -ENOMEM;
}

/* Отримуємо віртуальну адресу з прямого відображення */
void *buffer = page_address(pages);

/* Звільняємо ці 4 кадри назад системі приятелів */
__free_pages(pages, 2);
```

## Зони пам'яті й рівневі позначки

Не всі кадри фізичної пам'яті однаково придатні для всіх замовників через апаратні обмеження шин.

Тому фізична пам'ять поділена на **зони**:
- `ZONE_DMA`: перші 16 МіБ для застарілої периферії (ISA).
- `ZONE_DMA32`: пам'ять під межею 4 ГіБ для 32-бітних пристроїв.
- `ZONE_NORMAL`: звичайна пам'ять, доступна для всіх замовників.
- `ZONE_MOVABLE`: спеціальна зона лише для рухомих сторінок.

Зона `ZONE_MOVABLE` гарантує відсутність нерухомих кадрів за побудовою, тому з неї завжди можна вилучити суцільний масив пам'яті під гаряче вимкнення планок або великі сторінки.

Кожна зона веде власні списки вільних блоків за порядками та власний набір рівневих позначок (`min`, `low`, `high`). Якщо рівень вільної пам'яті в зоні падає нижче `low`, ядро будить фонову нитку `kswapd` для витіснення сторінок. Розподільник ніколи не зшиває кадри з різних зон в один блок.

## Зовнішня фрагментація та ущільнення

З часом суцільні блоки розпадаються. Якщо посеред 1024 вільних кадрів опиниться хоча б один нерухомий зайнятий кадр (наприклад, закріплена структура ядра або DMA-буфер), великий 4-мегабайтний блок там більше ніколи не складеться. Це явище називається **зовнішньою фрагментацією** — вільної пам'яті сумарно багато, але потрібної суцільної форми немає.

Справжній стан вільних блоків за порядками показує файл `/proc/buddyinfo`. Для лікування та профілактики фрагментації Linux застосовує два засоби:

1. **Групування за рухомістю**: Фізична пам'ять ділиться на "блоки сторінок" (pageblocks по 2 МіБ). Сторінки прикладних процесів та кешу файлів (які можна непомітно перенести в інший кадр, оновивши записи таблиць сторінок) розміщують окремо від нерухомих структур ядра. Один нерухомий кадр псує лише свій блок, лишаючи сусідні блоки чистими.
2. **Ущільнення (Compaction)**: Якщо великого блоку бракує, фонова нитка `kcompactd` або сам процес запускають два зустрічні сканери. Один сканер іде знизу зони й збирає зайняті рухомі сторінки, а другий іде згори й шукає вільні кадри. Сторінки копіюються нагору, а вивільнений простір знизу зшивається у великі блоки вищих порядків.

Якщо пам'яті фізично недостатньо, ущільнення не допоможе — у цьому разі ядро повертається до витіснення сторінок або свопінгу. Обирати між ущільненням і витісненням ядру допомагає спеціальне обчислюване число — індекс фрагментації (fragmentation index). Головні системні важелі керування цими процесами — сисктли `vm.min_free_kbytes` (задає аварійний резерв вільного простору) та `vm.compaction_proactiveness` (керує агресивністю фонового ущільнення).
