# 📋 Матриця параметрів cp, tar, rsync та системні виклики реплікації метаданих

Копіювання дерев файлової системи вимагає узгодженого перенесення двох шарів: потоку корисних даних та структурної інформації інодів VFS. Стандартні утиліти `cp`, `tar` та `rsync` мають різні історичні корені, тому їхні набори прапорців суттєво відрізняються як за синтаксисом, так і за поведінкою за замовчуванням. Нижче наведено зведену матрицю прапорців командного рядка для кожної категорії метаданих, розширений аналіз спеціалізованих ключів утиліт та системні виклики ядра Linux, які забезпечують їхнє зчитування й відновлення.

## Зведена матриця прапорців утиліт

## Детальний розбір прапорців командного рядка

### 1. GNU `cp` (розширені параметри coreutils)

- `--preserve[=LIST]` — дозволяє вибірково зберігати певні класи метаданих. Можливі значення: `mode`, `ownership`, `timestamps`, `xattr`, `context`, `links`, або `all`. За замовчуванням при звичайному запуску `cp src dst` не зберігається жоден атрибут; при вказанні `-p` зберігаються `mode,ownership,timestamps`.
- `--no-dereference` (`-P`) — ніколи не розіменовувати символьні посилання. Посилання копіюються як окремі вузли типу symlink, що зберігають вихідний текст цілі.
- `--dereference` (`-L`) — завжди слідувати за символьними посиланнями і копіювати вміст цільових файлів замість створення посилання.
- `--sparse=WHEN` — керує детекцією розріджених дірок. Варіанти: `auto` (евристичний пошук блоків нулів у буфері), `always` (примусове створення дірок на кожній нульовій послідовності), `never` (фізичний запис нулів на диск).
- `--reflink[=WHEN]` — керує механізмом Copy-on-Write (CoW). `auto` виконує спробу виклику `copy_file_range` або `ioctl(FICLONE)`, а при неможливості переходить на стандартне копіювання; `always` повертає помилку, якщо CoW не підтримується.
- `--attributes-only` — створює дерево каталогу та файлів нульової довжини, копіюючи лише їхні метадані (права, власника, мітки часу) без перенесення вмісту.
- `--remove-destination` — видаляє наявний файл призначення перед відкриттям, що дозволяє розірвати старі жорсткі посилання та перезаписати файли, недоступні для прямого запису через права `0444`.

### 2. GNU `tar` (архівація та розпакування потоків)

- `--format=FORMAT` — вибір двійкового стандарту архіву. Найчастіше вживаються `gnu` (розширення GNU tar) та `pax` (стандарт POSIX.1-2001). Формат `pax` є рекомендованим для кросплатформної передачі, оскільки знімає будь-які обмеження на розмір файлів, довжину шляхів та підтримує наносекундні мітки часу.
- `--acls` — зберігає та розгортає розширені списки контролю доступу POSIX ACL у потоці архіву.
- `--xattrs` — зберігає розширені атрибути файлів. За замовчуванням зберігає всі атрибути з простору `user.*`.
- `--xattrs-include=PATTERN` та `--xattrs-exclude=PATTERN` — фільтрація імен розширених атрибутів за регулярним виразом або шаблоном (наприклад, `--xattrs-include='security.*'`).
- `--selinux` — окремий прапорець для обов'язкового збереження контекстів безпеки SELinux у заголовках `pax`.
- `--sparse` (`-S`) — перевіряє файли на наявність дірок і зберігає лише блоки даних у спеціальних розріджених заголовках.
- `--sparse-version=MAJOR[.MINOR]` — вибір версії формату розрідженості (`0.0`, `0.1` або `1.0` у форматі `pax`).
- `--numeric-owner` — ігнорує імена користувачів і груп у системній базі під час створення або розпакування архіву, записуючи й відновлюючи винятково числові значення UID та GID.
- `--warning=no-file-changed` — вимикає попередження та аварійне завершення роботи, якщо під час читання активного файлу його розмір або час змінилися.

### 3. `rsync` (синхронізація та дельта-передача)

- `-a` (`--archive`) — макрос, що вмикає рекурсивний обхід (`-r`), копіювання symlinks (`-l`), збереження прав (`-p`), часу модифікації (`-t`), групи (`-g`), власника (`-o`) та файлів пристроїв/спеціальних вузлів (`-D`).
- `-H` (`--hard-links`) — вмикає підтримку жорстких посилань. На відміну від `cp -a`, в `rsync` цей прапорець не входить у базовий макрос `-a` через високі витрати пам'яті на відстеження таблиці `(dev, ino)`.
- `-A` (`--acls`) — зберігає списки доступу ACL (автоматично вмикає збереження прав доступу).
- `-X` (`--xattrs`) — зберігає розширені атрибути файлів.
- `-S` (`--sparse`) — оптимізує передачу та запис розріджених файлів на боці приймача.
- `--numeric-ids` — вимикає мапінг імен користувачів на приймачі; зберігає точні числові UID/GID джерела.
- `--partial` та `--partial-dir=DIR` — зберігає частково завантажені файли у разі обриву зв'язку для подальшого докачування.
- `--delay-updates` — накопичує всі оновлені файли в тимчасових локаціях до завершення повної передачі і перейменовує їх одночасно наприкінці сесії, що запобігає стану неузгодженості системи під час тривалої синхронізації.
- `--inplace` — записує оновлені байти безпосередньо в цільовий файл без створення тимчасової копії `.filename.XXXXXX`. Заощаджує дисковий простір, але робить файл пошкодженим у разі переривання передачі.
- `--checksum` (`-c`) — примусово порівнює вміст файлів за 128-бітними хешами замість швидкої евристики `розмір + mtime`.

## Системні виклики VFS ядра Linux: призначення та параметри

Повна точність копіювання спирається на сучасні системні виклики родини `*at`, які приймають файловий дескриптор каталогу і запобігають атакам підміни шляхів (Time-of-Check to Time-of-Use, TOCTOU).

### 1. Зчитування розширеного стану: `statx`

Системний виклик `statx` (введений у ядрі Linux 4.11) замінив застарілі `stat`, `fstat` та `lstat`. Він дозволяє запитувати точну маску потрібних полів та повертає наносекундні мітки часу разом із часом створення файла (`btime`), якщо його підтримує базова файлова система (ext4, Btrfs, XFS).

```
int statx(int dirfd, const char *pathname, int flags,
          unsigned int mask, struct statx *statxbuf);
```

- **`dirfd`**: `AT_FDCWD` або файловий дескриптор відкритого каталогу.
- **`pathname`**: шлях до вузла (може бути порожнім рядком, якщо передано прапорець `AT_EMPTY_PATH` для перевірки дескриптора `dirfd`).
- **`flags`**: `AT_SYMLINK_NOFOLLOW` — забороняє перехід за символьними посиланнями для отримання метаданих самого посилання; `AT_STATX_SYNC_AS_STAT` — стандартна семантика синхронізації кешів.
- **`mask`**: бітова маска запитуваних атрибутів (`STATX_TYPE`, `STATX_MODE`, `STATX_UID`, `STATX_GID`, `STATX_ATIME`, `STATX_MTIME`, `STATX_CTIME`, `STATX_BTIME`, `STATX_SIZE`).

Структура `struct statx` також повертає розширені прапорці стану інода в полі `stx_attributes`:
- `STATX_ATTR_COMPRESSED` — файл стиснутий на рівні файлової системи;
- `STATX_ATTR_IMMUTABLE` — встановлено прапорець незмінності (`chattr +i`);
- `STATX_ATTR_APPEND` — файл доступний лише для дописування в кінець (`chattr +a`);
- `STATX_ATTR_NODUMP` — файл виключено з резервного копіювання (`chattr +d`).

Типові коди помилок `statx`: `EACCES` (відсутні права на пошук у компоненті шляху), `ENOENT` (файл не існує), `ENOTDIR` (елемент шляху не є каталогом), `EFAULT` (недійсний покажчик на буфер).

### 2. Встановлення міток часу: `utimensat`

Оновлює час останнього доступу (`atime`) та модифікації вмісту (`mtime`) із наносекундною точністю.

```
int utimensat(int dirfd, const char *pathname,
              const struct timespec times[2], int flags);
```

- **`times[0]`**: часова позначка доступу (`st_atim`).
- **`times[1]`**: часова позначка модифікації даних (`st_mtim`).
- Якщо поле `tv_nsec` дорівнює спеціальній константі `UTIME_OMIT`, відповідна мітка часу залишається незмінною в іноді.
- Якщо поле `tv_nsec` дорівнює `UTIME_NOW`, ядро встановлює поточний системний час.
- **`flags`**: `AT_SYMLINK_NOFOLLOW` дозволяє змінювати мітки часу самого символьного посилання (підтримується на Linux для запобігання підміни цільових файлів).

### 3. Зміна власника: `fchownat`

Прив'язує інод до нових ідентифікаторів користувача (`uid`) та групи (`gid`).

```
int fchownat(int dirfd, const char *pathname,
             uid_t owner, gid_t group, int flags);
```

- Вимагає адміністративного привілею `CAP_CHOWN` для призначення довільного UID/GID.
- Якщо значення `owner` або `group` передано як `-1`, відповідне поле інода не змінюється.
- **`flags`**: `AT_SYMLINK_NOFOLLOW` змінює власника символьного посилання, а не цільового файлу.
- **Особливість взаємодії з VFS**: ядро Linux скидає біти `S_ISUID` та `S_ISGID` при виклику `fchownat` (механізм `ATTR_KILL_SUID` / `ATTR_KILL_SGID`). Тому відновлення режиму доступу (`fchmodat`) завжди виконується **після** встановлення власника.

### 4. Зміна прав доступу: `fchmodat`

Задає режим доступу `mode_t` (9 бітів доступу + SUID/SGID/Sticky).

```
int fchmodat(int dirfd, const char *pathname, mode_t mode, int flags);
```

- Встановлює біти прав в обхід поточної маски процесу `umask`.
- На рівні ядра Linux системний виклик `fchmodat` не підтримує `AT_SYMLINK_NOFOLLOW` для зміни прав самих символьних посилань (у POSIX права symlink не враховуються під час розв'язання шляху і фіксовані на рівні `0777`).
- Для звичайних файлів встановлення біта `S_ISVTX` (Sticky) ігнорується більшістю сучасних файлових систем, але для каталогів цей біт забороняє видалення файлів невласникам.

### 5. Робота з розширеними атрибутами: `llistxattr`, `lgetxattr`, `lsetxattr`

Розширені атрибути зберігають метадані змінної довжини, включно з POSIX ACL (`system.posix_acl_access`, `system.posix_acl_default`) та мітками безпеки SELinux (`security.selinux`).

```
ssize_t llistxattr(const char *path, char *list, size_t size);
ssize_t lgetxattr(const char *path, const char *name, void *value, size_t size);
int lsetxattr(const char *path, const char *name, const void *value, size_t size, int flags);
```

- Префікс `l*` гарантує роботу із самим символьним посиланням без розіменування.
- Читання списку імен атрибутів здійснюється у двоетапному режимі: перший виклик із `size = 0` повертає необхідний розмір буфера в байтах; другий виклик заповнює виділений буфер списком рядків, розділених нульовим байтом `\0`.
- Запис атрибутів через `lsetxattr` із просторів `system.*`, `security.*` та `trusted.*` вимагає відповідних можливостей процесу (`CAP_SYS_ADMIN`, `CAP_SETFCAP`).
- Коди помилок: `ENOTSUP` (файлова система не змонтована з підтримкою xattr), `ENODATA` (запитаного атрибута не існує), `E2BIG` (значення атрибута перевищує максимальний розмір блоку атрибутів, зазвичай 64 КБ).

### 6. Навігація розрідженими файлами: `lseek` з розширеннями POSIX

Для ефективного копіювання великих файлів із прогалинами (дірками) без зчитування гігабайтів нулів використовується пошук меж дірок та блоків даних:

```
off_t lseek(int fd, off_t offset, int whence);
```

- **`whence = SEEK_DATA`**: переміщує файловий покажчик на найближчий зсув, починаючи з `offset`, де розташовано реальні дані. Якщо `offset` уже вказує на дані, повертається сам `offset`. Якщо від `offset` і до кінця файлу даних немає, виклик повертає `-1` із `errno = ENXIO`.
- **`whence = SEEK_HOLE`**: переміщує покажчик на найближчий зсув, де починається дірка (невиділений простір). У кінці файлу повертається віртуальна дірка, координата якої дорівнює логічному розміру файлу (`st_size`).

### 7. Клонування екстентів на рівні ядра: `copy_file_range` та `ioctl(FICLONE)`

Дозволяє файловій системі виконати блочне клонування Copy-on-Write (Btrfs, XFS) або пряме внутрішнє копіювання в пам'яті ядра без перекачування байтів у простір користувача.

```
ssize_t copy_file_range(int fd_in, loff_t *off_in,
                        int fd_out, loff_t *off_out,
                        size_t len, unsigned int flags);
```

- Передає до `len` байтів безпосередньо між двома файловими дескрипторами в просторі ядра.
- Якщо обидва файли розташовані на одній CoW файловій системі, ядро на рівні VFS створює спільні посилання на фізичні блоки диска, що виконується практично миттєво незалежно від розміру файлу.
- Помилка `EXDEV` виникає, коли файли розташовані на різних точках монтування файлових систем, що вимагає від програми переходу на звичайний цикл читання й запису.
