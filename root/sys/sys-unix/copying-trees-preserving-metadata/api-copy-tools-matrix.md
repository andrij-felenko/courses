# 📋 Матриця параметрів cp, tar, rsync, cpio, pax та системні виклики VFS

Точне копіювання файлових ієрархій вимагає паралельного перенесення двох шарів: корисного потоку байтів даних та структурного стану інодів у віртуальній файловій системі (VFS). Інструменти копіювання та архівації Unix мають різні історичні передумови: `cp` оптимізовано для локальних файлових операцій, `tar` і `cpio` — для серіалізації в послідовні потоки байтів, `pax` — для стандартизованого перенесення за стандартом POSIX, а `rsync` — для мережевої дельта-синхронізації. Кожна з цих утиліт має власний набір прапорців, різну поведінку за замовчуванням та різний ступінь взаємодії з системними викликами ядра Linux.

## Специфікація параметрів GNU cp

Утиліта GNU `cp` (пакет GNU coreutils) є базовим інструментом локального копіювання у дистрибутивах Linux. Її архітектура оптимізована під роботу в межах одного ядра VFS через прямі системні виклики введення-виведення.

### Архітектура прапорця архіву `-a`

Прапорець `-a` (`--archive`) розгортається у точний еквівалент:

```sh
cp -dR --preserve=all
```

- **`-d`**: скорочення для комбінації `-P --preserve=links`. Прапорець `-P` (`--no-dereference`) запобігає переходу за символьними посиланнями, змушуючи `cp` копіювати саме посилання як новий вузол `S_IFLNK`. Прапорець `--preserve=links` наказує утиліті підтримувати хеш-таблицю виявлених пар `(dev_t, ino_t)` і при повторній зустрічі викликати системний виклик `linkat()` замість створення нового інода.
- **`-R`** (`-r`, `--recursive`): рекурсивне сканування дерева каталогів із відтворенням структури підкаталогів та копіюванням спеціальних файлів (FIFO, блокових та символьних пристроїв).
- **`--preserve=all`**: вимога зберегти повний спектр атрибутів інода, що включає всі допустимі ключі списку `ATTR_LIST`.

### Прапорці керування атрибутами

- **`--preserve[=ATTR_LIST]`**: явний список класів метаданих, розділених комами:
  - `mode`: права доступу `0777` разом із бітами SUID (`04000`), SGID (`02000`) та Sticky (`01000`);
  - `ownership`: ідентифікатори користувача `st_uid` та групи `st_gid`;
  - `timestamps`: наносекундні мітки часу модифікації `st_mtim` та доступу `st_atim`;
  - `links`: зв'язки між жорсткими посиланнями;
  - `xattr`: усі розширені атрибути файлової системи, включно з просторами імен `user.*`, `trusted.*` та `system.posix_acl_*`;
  - `context`: мітки контексту безпеки SELinux (`security.selinux`);
  - `all`: вмикає всі перелічені вище категорії.
  Якщо `ATTR_LIST` не передано, значення за замовчуванням дорівнює `mode,ownership,timestamps`.
- **`--no-preserve=ATTR_LIST`**: вимикає збереження окремих класів метаданих (наприклад, `cp -a --no-preserve=ownership,context`).
- **`-p`**: класичний сумісний прапорець POSIX, еквівалентний `--preserve=mode,ownership,timestamps`.
- **`--attributes-only`**: створює структуру каталогів та файлів нульового розміру, копіюючи винятково метадані (права, власника, мітки часу, розширені атрибути) без перенесення тіла файлів.

### Клонування екстентів (Copy-on-Write) та розрідженість

- **`--reflink[=WHEN]`**: визначає режим блочного клонування Copy-on-Write (CoW) на файлових системах із підтримкою shared extents (Btrfs, XFS):
  - `auto` (типово при стандартному виконанні на сучасних системах): `cp` робить спробу виклику `ioctl(dst_fd, FICLONE, src_fd)` або `copy_file_range()`. Якщо файлова система повертає `EXDEV` (різні точки монтування) або `EOPNOTSUPP` (відсутня підтримка CoW), `cp` автоматично перемикається на стандартний цикл читання й запису;
  - `always`: примусове блочне клонування. Якщо виклики CoW завершуються помилкою, операція негайно переривається з ненульовим кодом повернення без створення звичайної копії;
  - `never`: вимикає перевірку CoW і завжди виконує фізичне копіювання байтів на рівні VFS.
- **`--sparse[=WHEN]`**: керує виявленням нерозподілених дірок у файлах:
  - `auto`: евристичний режим. Якщо вихідний файл містить дірки (перевіряється співвідношенням `st_blocks * 512 < st_size` або системними викликами `SEEK_DATA`/`SEEK_HOLE`), або якщо в прочитаному буфері даних виявлено суцільний блок нулів, `cp` замість виклику `write()` викликає `lseek(dst_fd, len, SEEK_CUR)`, створюючи дірку на цільовій файловій системі;
  - `always`: примусово перевіряє кожен буфер на наявність нульових послідовностей і генерує дірки навіть у файлах, які на джерелі займали фізичні блоки;
  - `never`: записує всі нулі як фізичні байти даних на диск через `write()`, повністю розгортаючи розріджені файли.

### Керування поведінкою файлової системи

- **`-x`**, **`--one-file-system`**: запам'ятовує ідентифікатор пристрою `st_dev` початкового каталогу. Якщо в процесі рекурсивного спуску зустрічається каталог, чий `st_dev` відрізняється від початкового (точка монтування іншого розділу, віртуальні ФС `/proc`, `/sys`, `/dev`), цей каталог пропускається без сканування.
- **`--remove-destination`**: перед створенням або відкриттям цільового файлу видаляє наявний файл за допомогою системного виклику `unlink()`. Це гарантує:
  1. Розрив старих жорстких посилань на цільовий інод (запобігає випадковій зміні вмісту інших файлів, що вказували на цей самий інод);
  2. Можливість перезапису файлів, відкриття яких на запис завершилося б `EACCES` через права `0444`.
- **`-f`**, **`--force`**: якщо цільовий файл не може бути відкритий для запису, `cp` робить спробу видалити його через `unlink()` і відкрити наново.
- **`-i`**, **`--interactive`**: запитує підтвердження користувача перед перезаписом кожного наявного файлу.
- **`-n`**, **`--no-clobber`**: ніколи не перезаписує наявний файл (ігнорує попередні прапорці `-i` та `-f`).
- **`-u`**, **`--update[=WHEN]`**: копіює файл лише тоді, коли вихідний файл новіший за часом `mtime`, ніж цільовий, або коли цільовий файл відсутній. Допустимі параметри: `all`, `none`, `older`.
- **`-T`**, **`--no-target-directory`**: розглядає шлях призначення як звичайний файл або каталог, а не як каталог, всередину якого слід копіювати джерело.
- **`-t DIRECTORY`**, **`--target-directory=DIRECTORY`**: вказує каталог призначення першим, що дозволяє передавати довільну кількість вихідних файлів наприкінці команди.
- **`-b`**, **`--backup[=CONTROL]`**: створює резервну копію кожного наявного цільового файлу перед перезаписом (режими: `none`, `numbered`, `existing`, `simple`).
- **`-S SUFFIX`**, **`--suffix=SUFFIX`**: задає суфікс для створюваних резервних копій (за замовчуванням `~`).
- **`--strip-trailing-slashes`**: видаляє кінцеві слеші з кожного аргументу командного рядка перед початком обробки.

### Розіменування символьних посилань

- **`-P`** (`--no-dereference`): ніколи не переходити за symlinks (створює новий вузол `S_IFLNK`).
- **`-L`** (`--dereference`): завжди розіменовувати symlinks — копіювати файл або каталог, на який посилається symlink, замість створення самого посилання.
- **`-H`**: розіменовувати лише ті символьні посилання, які передано безпосередньо в аргументах командного рядка як джерела; вкладені посилання в дереві копіювати як symlink.

### Коди завершення (Exit Codes) GNU cp

- **`0`**: Успішне завершення. Усі файли та дерева скопійовано без помилок.
- **`>0`** (зазвичай `1`): Сталася помилка доступу (`EACCES`), відсутній вихідний файл (`ENOENT`), брак дискового простору (`ENOSPC`), помилка блочного клонування при `--reflink=always` або неможливість встановити метадані.

```sh
# Повне клонування із CoW-рефлінками та ізоляцією ФС
cp -a --reflink=auto --one-file-system /var/lib/containers /mnt/backup/containers
```

## Специфікація параметрів GNU tar

Утиліта GNU `tar` призначена для послідовної серіалізації структури каталогів у єдиний неперервний потік байтів, що робить її стандартом для резервного копіювання на стрічкові накопичувачі, передачі через конвеєри (pipes) та міжмережевої міграції через SSH.

### Основні операційні режими GNU tar

- **`-c`**, **`--create`**: створення нового архіву з файлів та каталогів.
- **`-x`**, **`--extract`**, **`--get`**: вилучення файлів з архіву у файлову систему.
- **`-t`**, **`--list`**: перегляд змісту архіву без розпакування на диск.
- **`-r`**, **`--append`**: дописування файлів у кінець наявного архіву (не підтримується для стиснутих архівів).
- **`-u`**, **`--update`**: дописування лише тих файлів, які новіші за відповідні копії всередині архіву.
- **`-d`**, **`--diff`**, **`--compare`**: порівняння файлів в архіві з файлами у поточній файловій системі.
- **`-A`**, **`--catenate`**, **`--concatenate`**: приєднання одного tar-архіву до кінця іншого.

### Формати архівів та розширені заголовки

Прапорець `--format=FORMAT` задає двійковий стандарт архіву:

- **`v7`**: старий формат Unix V7. Максимальний розмір файлу — 8 ГБ, довжина шляху — до 99 символів.
- **`oldgnu`**: формат GNU tar версій до 1.12.
- **`gnu`**: розширений формат GNU tar (типовий для GNU tar 1.x). Знімає обмеження на довжину шляхів і розмір файлів через спеціальні типи блоків `L` (LongLink) та `K` (LongName), підтримує розріджені файли.
- **`ustar`**: стандарт POSIX.1-1988. Максимальний розмір файлу — 8 ГБ, максимальна довжина шляху — 256 символів (розбивається на 100 символів імені та 155 символів префікса каталогу). Дискретність міток часу — 1 секунда (наносекунди відкидаються). Метадані xattr, ACL та SELinux не підтримуються.
- **`pax`** (`posix`): стандарт POSIX.1-2001. Використовує розширені заголовки типу `x` (для окремого файлу) та `g` (глобальні для всього архіву) у форматі UTF-8 записів `LENGTH KEYWORD=VALUE\n`. Підтримує необмежені розміри, наносекундні мітки часу та довільні атрибути.
- **`star`**: формат утиліти Joerg Schilling star.

### Прапорці збереження та відновлення метаданих

- **`-p`**, **`--preserve-permissions`**, **`--same-permissions`**: при вилученні (`-x`) встановлює повну маску прав `st_mode` вихідного файлу, ігноруючи поточну маску процесу `umask`. Для користувача `root` увімкнено за замовчуванням.
- **`--same-owner`**: відновлює числові значення UID та GID із заголовків архіву. Увімкнено за замовчуванням при виконанні від імені суперкористувача `root`.
- **`--no-same-owner`**: встановлює власником усіх розпакованих файлів поточного користувача, який викликав `tar` (типово для непривілейованих користувачів).
- **`--numeric-owner`**: ігнорує текстові імена користувачів і груп у системній базі `/etc/passwd` і `/etc/group` під час створення або розпакування архіву, записуючи та відновлюючи винятково числові UID/GID.
- **`--acls`**: зберігає та відновлює розширені списки контролю доступу POSIX ACL. У форматі `pax` записуються в розширені поля `SCHILY.acl.access` та `SCHILY.acl.default`.
- **`--no-acls`**: вимикає збереження та відновлення списків POSIX ACL.
- **`--xattrs`**: зберігає всі розширені атрибути файлів простору `user.*`. Записуються у форматі `pax` як `SCHILY.xattr.<name>`.
- **`--no-xattrs`**: вимикає обробку розширених атрибутів.
- **`--xattrs-include=PATTERN`** та **`--xattrs-exclude=PATTERN`**: фільтрація розширених атрибутів за маскою glob. Наприклад: `--xattrs-include='security.*'` або `--xattrs-include='trusted.*'`.
- **`--selinux`**: зберігає мітки безпеки SELinux у спеціальних полях заголовків (`RHT.security.selinux` або `LIBARCHIVE.xattr.security.selinux`).
- **`--no-selinux`**: вимикає збереження контекстів SELinux.
- **`--atime-preserve[=METHOD]`**: керує збереженням мітки часу доступу файлів, що читаються під час пакування:
  - `replace`: після вичитування даних відновлює початковий `atime` за допомогою системного виклику `utimensat()`. Недолік: змінює час модифікації інода `ctime`;
  - `system`: відкриває файли для читання із системним прапорцем `O_NOATIME` (вимагає права власності на файл або адміністративної можливості `CAP_FOWNER`), що запобігає зміні `atime` на рівні VFS без генерації операцій запису.
- **`--mtime=DATE_OR_FILE`**: примусово встановлює фіксовану дату `mtime` для всіх файлів в архіві (критично для відтворюваних збірок / Reproducible Builds).
- **`--clamp-mtime`**: у поєднанні з `--mtime` змінює дату файлу лише тоді, коли його реальний `mtime` новіший за вказану межу.
- **`--touch`**: при розпакуванні встановлює час модифікації файлів рівним поточному системному часу замість часу з архіву.
- **`--mode=CHANGES`**: примусово змінює права доступу файлів в архіві за символьною нотацією (наприклад, `a+rX,u+w`).
- **`--owner=NAME_OR_UID`** та **`--group=NAME_OR_GID`**: примусово перезаписує ім'я/ID власника або групи у заголовках.

### Керування зв'язками, розрідженістю та файловими системами

- **`-S`**, **`--sparse`**: перевіряє файли під час створення архіву на наявність дірок і зберігає лише блоки реальних даних разом із картою зсувів у спеціальних розріджених заголовках. При розпакуванні відтворює дірки на диску через `lseek()` або `fallocate()`.
- **`--sparse-version=MAJOR[.MINOR]`**: версія внутрішнього формату розрідженості GNU tar (`0.0`, `0.1` або `1.0` у стандарті `pax`).
- **`--hard-dereference`**: розриває жорсткі посилання під час пакування: якщо кілька записів каталогу посилаються на один інод, `tar` пакує повний вміст файлу для кожного запису як окремий незалежний файл.
- **`-h`**, **`--dereference`**: розіменовує символьні посилання, пакуючи файли, на які вони вказують.
- **`-C DIR`**, **`--directory=DIR`**: змінює поточний робочий каталог процесу перед виконанням операцій.
- **`--one-file-system`**: обмежує архівацію межами початкової файлової системи (ігнорує каталоги з іншим `st_dev`).
- **`--warning=no-file-changed`**: вимикає попередження та статус завершення `exit 1`, якщо файл було змінено іншим процесом під час його вичитування архіватором.
- **`--transform=EXPR`**, **`--xform=EXPR`**: виконує sed-подібну заміну імен файлів під час архівації чи розпакування (наприклад, `s,^src,dst,`).
- **`--exclude=PATTERN`**: виключає файли, що збігаються з маскою glob.
- **`--exclude-vcs`**: автоматично виключає службові каталоги систем контролю версій (`.git`, `.svn`, `.hg`).
- **`-T FILE`**, **`--files-from=FILE`**: зчитує список імен файлів для архівації з файлу (або `-` для stdin).
- **`--null`**: у поєднанні з `-T` читає імена файлів, розділені нульовим байтом `\0`.

### Коди завершення (Exit Codes) GNU tar

- **`0`**: Успішне виконання без помилок.
- **`1`**: Некритичні попередження. Файли відрізняються (у режимі `--compare`) або файл було змінено іншим процесом під час вичитування (`file changed as we read it`).
- **`2`**: Фатальна помилка. Пошкоджений заголовок архіву, помилка введення-виведення, відсутність доступу до каталогу.

```sh
# Потоковий конвеєр між серверами через SSH з повною реплікацією метаданих
tar --format=pax --acls --xattrs --selinux --sparse -cpf - -C /source . | \
  ssh root@backup.lan "tar --format=pax --acls --xattrs --selinux --sparse --numeric-owner -xpf - -C /destination"
```

## Специфікація параметрів rsync (3.x)

Утиліта `rsync` реалізує клієнт-серверний протокол віддаленої синхронізації файлових дерев. Головна особливість — алгоритм дельта-передачі блоків, який виявляє змінені фрагменти файлів на основі ковзних хешів Adler-32 та стійких хешів MD4/MD5/XXH64, мінімізуючи мережевий трафік.

### Розгортання базового макросу `-a`

Прапорець `-a` (`--archive`) є скороченням для комбінації семи прапорців:

```sh
rsync -rlptgoD
```

- **`-r`** (`--recursive`): рекурсивний обхід підкаталогів.
- **`-l`** (`--links`): копіює символьні посилання як символьні посилання (відтворює вузли `S_IFLNK` без розіменування).
- **`-p`** (`--perms`): передає права доступу `st_mode` (9 бітів `rwxrwxrwx` разом із бітами SUID/SGID/Sticky, якщо процес має відповідні права на приймачі).
- **`-t`** (`--times`): передає часові позначки модифікації `mtime` з наносекундною точністю.
- **`-g`** (`--group`): зберігає групу володіння файлом.
- **`-o`** (`--owner`): зберігає власника файлу (діє лише у тому разі, якщо процес на приймачі запущено від імені суперкористувача `root`).
- **`-D`**: комбінований макрос, що розгортається у:
  - `--devices`: відновлює файли символьних (`S_IFCHR`) та блокових (`S_IFBLK`) пристроїв через виклик `mknodat()`;
  - `--specials`: відновлює спеціальні вузли файлової системи — іменовані канали FIFO (`S_IFIFO`) та сокети домену Unix (`S_IFSOCK`).

### Спеціальні розширені прапорці метаданих

Прапорці максимальної точності, що **не входять** у базовий `-a`:

- **`-H`**, **`--hard-links`**: відстежує топологію жорстких посилань на джерелі та відтворює їх на приймачі через системний виклик `linkat()`.
  *Інженерна ціна:* `rsync` зберігає в оперативній пам'яті хеш-таблицю всіх пар `(dev, ino)` оброблених файлів. Для файлових систем із десятками мільйонів файлів прапорець `-H` вимагає кількох гігабайтів RAM.
- **`-A`**, **`--acls`**: передає розширені списки контролю доступу (POSIX Access ACL та Default ACL для каталогів). Автоматично активує прапорець `--perms`.
- **`-X`**, **`--xattrs`**: передає розширені атрибути файлів. За замовчуванням передає атрибути простору `user.*` та контексти безпеки SELinux `security.selinux`.
- **`-S`**, **`--sparse`**: оптимізує запис розріджених файлів на приймачі: шукає блоки нулів у вхідному потоці даних і викликає `lseek()` замість `write()`, створюючи дірки у цільовому файлі.
- **`--numeric-ids`**: передає числові ідентифікатори UID та GID без спроби зіставити їх з іменами користувачів на стороні приймача через системні бази `/etc/passwd` та `/etc/group`. Це критично важливо під час міграції образів операційних систем, системних коренів chroot та контейнерів.
- **`-U`**, **`--atimes`**: передає час останнього доступу `atime`.
- **`-N`**, **`--crtimes`**: передає час створення/народження файлу (`btime`), якщо цільова операційна система та файлова система підтримують його збереження.
- **`-M`, `--fake-super`**: зберігає всі права доступу, UID/GID та спеціальні файли пристроїв у вигляді розширених атрибутів `user.rsync.*`. Це дозволяє створювати повні резервні копії системних коренів непривілейованим користувачем без прав `root`.
- **`--chmod=CHMOD_SPEC`**: примусово змінює маску прав створюваних файлів та каталогів (наприклад, `--chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r`).
- **`--chown=USER:GROUP`**: примусово встановлює користувача та групу для всіх створених файлів на приймачі.
- **`--super`** / **`--no-super`**: явно вимагає або вимикає виконання суперкористувацьких дій (зміна власника через `chown`, створення dev-файлів через `mknod`).

### Керування передачею, атомарністю та видаленням

- **`--inplace`**: записує оновлені блоки безпосередньо у наявний цільовий файл замість створення тимчасового файлу виду `.filename.XXXXXX`. Заощаджує дисковий простір (не потребує 100% запасу під час оновлення гігабайтних файлів), але робить цільовий файл пошкодженим у разі переривання з'єднання.
- **`--delay-updates`**: зберігає всі оновлені тимчасові файли до повного завершення передачі всієї сесії і виконує їхнє перейменування через `rename()` наприкінці. Запобігає стану неузгодженості, коли частина файлів уже оновлена, а інша ще ні.
- **`--partial`**: не видаляє частково завантажений тимчасовий файл у разі обриву мережевого з'єднання, залишаючи його для подальшого докачування.
- **`--partial-dir=DIR`**: вказує каталог, у якому накопичуються частково завантажені файли (замість розміщення їх у цільовому каталозі).
- **`--delete`**: видаляє з каталогу призначення файли, яких більше немає у вихідному дереві джерела:
  - `--delete-before`: видаляє старі файли перед початком передачі нових даних;
  - `--delete-during`: видаляє старі файли паралельно з процесом передачі під час обходу каталогу;
  - `--delete-after`: видаляє старі файли лише після успішної передачі всіх оновлень;
  - `--delete-excluded`: видаляє на приймачі навіть ті файли, які було виключено правилами `--exclude`.
- **`-x`**, **`--one-file-system`**: забороняє рекурсивному скануванню перетинати межі файлових систем (перевіряє збіг `st_dev`).
- **`-W`**, **`--whole-file`**: вимикає дельта-алгоритм і завжди копіює файл цілком. Для швидких локальних дисків або NVMe накопичувачів цей режим працює значно швидше через відсутність витрат CPU на обчислення хешів.
- **`--append`** та **`--append-verify`**: докачує дані в кінець файлів, вважаючи початкові дані ідентичними (з верифікацією повного хешу при `--append-verify`).
- **`-b`**, **`--backup`**: створює резервні копії файлів перед їхньою зміною або видаленням на приймачі.
- **`--backup-dir=DIR`**: переміщує резервні копії у вказаний ієрархічний каталог.

### Контроль пропускної здатності, діагностика та безпека rsync

- **`--bwlimit=RATE`**: обмежує максимальну швидкість передачі даних по мережі або між дисками.
  - Параметр `RATE` задається у кілобайтах за секунду (КБ/с). Сучасний `rsync` підтримує суфікси розмірності: `K` (КБ/с), `M` (МБ/с), `G` (ГБ/с). Значення `0` вимикає ліміт (необмежена швидкість).
  - *Внутрішній алгоритм:* `rsync` використовує алгоритм шейпінгу трафіку Token Bucket або періодичний виклик `nanosleep()` на файловому дескрипторі сокета, вимірюючи фактично переданий обсяг байтів за кожне часове вікно. Якщо швидкість перевищує `RATE`, потік призупиняється. Це запобігає перевантаженню виробничих каналів зв'язку під час фонової синхронізації.
- **`-c`**, **`--checksum`**: вимикає стандартну евристику Quick Check (порівняння розміру `st_size` та часу `st_mtime`) і примусово обчислює повний криптографічний хеш (MD5 / XXH64 / SHA1 залежно від версії rsync та погодження протоколу) для кожного файлу на джерелі й приймачі перед передачею.
  - *Ціна прапорця:* викликає 100% вичитування всіх файлів з обох файлових систем, що створює високе дискове навантаження (I/O bottleneck), але гарантує виявлення пошкоджень даних (bit rot) у файлах, чиї `size` та `mtime` не змінилися.
- **`-n`**, **`--dry-run`**: виконує повну імітацію синхронізації без здійснення будь-яких системних викликів запису, створення вузлів або видалення (`open(O_CREAT)`, `unlink`, `rename`, `lsetxattr`, `fchmodat`, `fchownat`). Дозволяє безпечно перевірити правила фільтрації, список запланованих до видалення файлів та топологію призначення.
- **`-i`**, **`--itemize-changes`**: виводить деталізований 11-символьний рядок діагностики для кожного зміненого або створеного об'єкта:
  - Символ 1 (тип дії): `>` (файл передається на ціль), `<` (файл передається на джерело), `c` (локальна зміна/створення), `h` (створення hardlink), `.` (оновлення атрибутів без зміни даних), `*` (повідомлення).
  - Символ 2 (тип вузла VFS): `f` (звичайний файл), `d` (каталог), `L` (символьне посилання), `D` (файл пристрою), `S` (спеціальний файл FIFO/сокет).
  - Символи 3–11 (атрибути):
    - `c`: зміна контрольної суми або створення файлу (`+` для нових об'єктів);
    - `s`: зміна розміру файлу;
    - `t`: оновлення мітки часу `mtime`;
    - `p`: зміна прав доступу `mode`;
    - `o`: зміна власника `UID`;
    - `g`: зміна групи `GID`;
    - `u`: зарезервовано;
    - `a`: оновлення списків POSIX ACL;
    - `x`: оновлення розширених атрибутів xattr.
  - *Приклад виводу:* `>f+++++++++ app.bin` (створено новий звичайний файл з усіма атрибутами), `.d..t...... /var/log` (оновлено лише час модифікації каталогу).
- **`--timeout=SECONDS`**: встановлює граничний час очікування операцій читання/запису на мережевому сокеті (I/O timeout). Якщо протягом `SECONDS` секунд не надійшло жодного байта, сесія аварійно закривається з кодом `30`. Запобігає вічному зависанню скриптів автоматизації при «тихому» обриві TCP-сесій або зависанні віддаленого демона.
- **`--contimeout=SECONDS`**: задає таймаут встановлення початкового TCP-з'єднання з демоном rsync (`rsync://`).
- **Безпека символьних посилань:**
  - `--safe-links`: ігнорує будь-які символьні посилання, які вказують на файли за межами цільового дерева каталогів.
  - `--copy-unsafe-links`: якщо символьне посилання веде за межі дерева, копіює сам файл, на який воно вказує, замість збереження небезпечного symlink.
  - `--munge-links`: захисне кодування шляхів symlinks із префіксом `/rsyncd-munged/` при роботі через демон rsync, що блокує атаки обходу каталогів (directory traversal).

### Коди завершення (Exit Codes) утиліти rsync

- **`0`**: Success — успішне завершення передачі всіх файлів.
- **`1`**: Syntax or usage error — синтаксична помилка у параметрах командного рядка.
- **`2`**: Protocol incompatibility — несумісність версій клієнт-серверного протоколу rsync.
- **`3`**: Errors selecting input/output files, dirs — помилка відкриття початкового каталогу або списку файлів.
- **`4`**: Requested action not supported — спроба використати дію або алгоритм, не скомпільований у двійковий файл.
- **`5`**: Error starting client-server protocol — збій ініціалізації міжпроцесного зв'язку через SSH або rsync daemon.
- **`10`**: Error in socket I/O — помилка мережевого сокета (обрив зв'язку, скидання з'єднання TCP RST).
- **`11`**: Error in file I/O — помилка читання/запису файлу на диску (помилка `EIO`, переповнення диска `ENOSPC`).
- **`12`**: Error in rsync protocol data stream — пошкодження двійкового потоку протоколу.
- **`23`**: Partial transfer due to error — часткова передача: частину файлів передано успішно, але для деяких виникли помилки доступу (`EACCES`).
- **`24`**: Partial transfer due to vanished source files — файл джерела зник (був видалений іншим процесом) під час спроби його читання.
- **`30`**: Timeout in data send/receive — перевищено ліміт часу очікування введення-виведення (`--timeout`).
- **`35`**: Timeout waiting for daemon connection — перевищено час очікування підключення до сокета демона (`--contimeout`).

```sh
# Виробничий еталон синхронізації з обмеженням швидкості та контролем помилок
rsync -aHAX -S --numeric-ids --delete --delay-updates --bwlimit=50M --timeout=60 --partial-dir=.rsync-partial /srv/data/ backup.lan:/srv/data/
```

## Специфікація утиліти POSIX pax (Portable Archive Interchange)

Утиліта `pax` стандартизована у POSIX.1-1988 та POSIX.1-2001 (IEEE Std 1003.1-2001 / Open Group Base Specifications Issue 6 & 7) як єдина універсальна заміна несумісних між собою історичних утиліт `tar` та `cpio`. Вона забезпечує переносність архівів між різними сертифікованими UNIX-системами (Linux, FreeBSD, OpenBSD, macOS, AIX, Solaris).

### Три режими функціонування pax

1. **Режим читання / розпакування (`-r`):**
   Зчитує потік архіву зі стандартного вводу або з файлу, вказаного через `-f ARCHIVE`, вибирає файли за зазначеними патернами `pattern` і розгортає їх у файлову систему.
   ```sh
   pax -r [-cdeiknuvXZ] [-f archive] [-p string] [-s replstr] [pattern ...]
   ```

2. **Режим запису / архівації (`-w`):**
   Зчитує список імен файлів зі стандартного вводу (розділених символом нового рядка `\n`), пакує ці файли у вихідний потік архіву на стандартний вивід або у файл `-f ARCHIVE`.
   ```sh
   pax -w [-adituvXZ] [-b blocksize] [-f archive] [-s replstr] [-x format] [file ...]
   ```

3. **Режим копіювання / прохідного перенесення (`-rw` / copy-pass):**
   Зчитує дерево файлів джерела і відтворює його безпосередньо у вказаному каталозі призначення без створення проміжного архівного файлу на диску.
   ```sh
   pax -r -w [-deiklntuvXZ] [-p string] [-s replstr] [file ...] directory
   ```

### Специфікація прапорця збереження характеристик `-p STRING`

Прапорець `-p` приймає рядок керуючих символів, які визначають, які саме атрибути інода VFS слід зберегти під час операцій читання або копіювання:

- **`a`**: не зберігати / відновлювати час доступу файлу джерела `atime`. Після операції читання `atime` вихідного файлу залишається незмінним.
- **`e`** (everything): зберігати повний спектр усіх доступних метаданих: маску прав доступу `mode`, власника `UID`, групу `GID`, час модифікації `mtime`, час доступу `atime`, а також розширені атрибути файлової системи, якщо вони підтримуються форматом архіву.
- **`m`**: не оновлювати / не зберігати час модифікації `mtime` (при вилученні файли отримують час розпакування, якщо не вказано інше).
- **`o`**: зберігати числових ідентифікаторів власника `UID` та групи `GID`. Вимагає прав суперкористувача або привілею `CAP_CHOWN`; для непривілейованих процесів ігнорується, і файли створюються з UID/GID поточного користувача.
- **`p`**: зберігати повну маску прав доступу `mode` (включно зі спеціальними бітами `S_ISUID` 04000, `S_ISGID` 02000 та `S_ISVTX` 01000), ігноруючи поточну маску процесу `umask`.

*Комбінування символів:* символи рядка `-p` можуть поєднуватися у довільному порядку:
- `-p e`: максимальне збереження всіх атрибутів;
- `-p p`: збереження лише прав доступу;
- `-p po`: збереження прав та власника;
- `-p a`: збереження вихідного часу доступу.
Якщо зазначені несумісні літери, діє правило останнього символу в рядку.

### Формати вихідного архіву `-x FORMAT`

- **`pax`** (типовий розширений стандарт POSIX.1-2001):
  Базується на структурі `ustar`, але використовує розширені заголовки типу `x` (extended header для окремого файлу) та `g` (global header для всього архіву), що складаються з текстових UTF-8 записів `LENGTH KEYWORD=VALUE\n`. Підтримує:
  - Файли довільного розміру (понад 8 ГБ);
  - Шляхи довільної довжини (без ліміту 256 байтів);
  - Наносекундну точність для `atime`, `mtime`, `ctime`;
  - Розширені атрибути файлів (xattr) та списки доступу ACL;
  - Числові ідентифікатори UID/GID довільної розрядності.
- **`ustar`** (стандарт POSIX.1-1988 tar):
  Класичний архів із фіксованими 512-байтними блоками. Обмеження: розмір файлу до 8 ГБ (2³³ - 1 байт), довжина шляху до 256 байтів (100 байтів імені + 155 байтів префікса), дискретність часу — 1 секунда, відсутня підтримка xattr/ACL.
- **`cpio`** (стандартний POSIX cpio format):
  Формат обміну `cpio` з текстовими ASCII-заголовками (сумісний із форматом `odc`).

### Повна таблиця додаткових параметрів pax

- **`-b BLOCKSIZE`**: розмір блоку вводу/виводу в байтах. Число може мати суфікс `b` (множення на 512 байтів) або `k` (множення на 1024 байти). Стандартний розмір блоку за замовчуванням — 10 КБ (20 блоків по 512 байтів = 10240 байтів).
- **`-c`**: інвертування вибору шаблонів (match complement) — обробляє всі файли, крім тих, що збігаються з переданими патернами `pattern`.
- **`-d`**: заборона рекурсивного спуску в каталоги. Якщо аргумент є каталогом, копіюється або пакується лише сам запис каталогу, але не його дочірній вміст.
- **`-f ARCHIVE`**: вказує шлях до файлу архіву або файлу пристрою (замість використання стандартного вводу або виводу).
- **`-H`**: розіменовувати лише ті символьні посилання, які передано безпосередньо в аргументах командного рядка; вкладені symlinks копіювати як symlink.
- **`-L`**: завжди розіменовувати всі символьні посилання в ієрархії дерева.
- **`-k`**: захист від перезапису наявних файлів (prevent clobbering).
- **`-l`**: у режимі `-rw` створювати жорсткі посилання (`linkat`) між джерелом і призначенням замість фізичного копіювання файлів (якщо обидва каталоги знаходяться на одній файловій системі).
- **`-n`**: зупиняти пошук після першого збігу файлу для кожного заданого патерну.
- **`-s REPLACEMENT`**: підстановка та зміна імен файлів на льоту за допомогою регулярних виразів `sed` виду `/old/new/[gp]`.
- **`-u`**: копіювати або розпаковувати файл лише у разі, якщо файл джерела новіший за цільовий файл за часом `mtime`.
- **`-v`**: детальний вивід списку оброблених файлів та їхніх метаданих (verbose).
- **`-X`**: забороняти рекурсивному обходу перетинати межі точок монтування файлових систем (`one-file-system`).

### Коди завершення (Exit Codes) pax

- **`0`**: Усі операції архівації, вилучення або копіювання завершено успішно без жодних помилок.
- **`>0`** (зазвичай `1` або `2`): Сталася помилка читання/запису, пошкоджено заголовок архіву, відмовлено в доступі або неможливо відтворити метадані.

```sh
# Пряме клонування дерева каталогів через POSIX pax із збереженням усіх атрибутів
pax -rw -pe -v -X /source /destination
```

## Специфікація утиліти GNU cpio

Утиліта GNU `cpio` (пакет GNU cpio) призначена для серіалізації структури файлових ієрархій у послідовні двійкові архіви та їхнього подальшого розпакування. Вона є системним стандартом для пакування образів початкового завантаження ядра Linux `initramfs` (керується підсистемою `init/initramfs.c` ядра) та внутрішнім форматом пакетів RPM.

### Три фундаментальні режими функціонування cpio

1. **Copy-out (`-o`, `--create`):**
   Зчитує список відносних або абсолютних імен файлів зі стандартного вводу (`stdin`) і формує послідовний двійковий потік архіву на стандартний вивід (`stdout`) або у файл `-F ARCHIVE`.
   ```sh
   find . -depth -print0 | cpio -o -0 [options] > archive.cpio
   ```

2. **Copy-in (`-i`, `--extract`):**
   Зчитує архів зі стандартного вводу або з файлу `-F ARCHIVE` і розпаковує його файли та каталоги у файлову систему, фільтруючи файли за необов'язковими шаблонами glob.
   ```sh
   cpio -i [options] [pattern ...] < archive.cpio
   ```

3. **Copy-pass (`-p`, `--pass-through`):**
   Зчитує перелік імен файлів зі стандартного вводу і копіює їх безпосередньо у вказаний каталог призначення без створення проміжного архівного файлу на диску.
   ```sh
   find /source -depth -print0 | cpio -p -0 -a -m -u -d -v /destination
   ```

### Специфікація форматів архівів `-H FORMAT` / `--format=FORMAT`

- **`newc`** (**SVR4 Portable Format without CRC**):
  Сучасний стандарт за замовчуванням для створення образів початкового RAM-диска Linux `initramfs`.
  - Заголовки файлів кодуються у вигляді 110-байтових шістнадцяткових ASCII-рядків (hex), що робить архів повністю незалежним від порядку байтів процесора (Big-Endian / Little-Endian);
  - Підтримує мажорні та мінорні номери пристроїв до 32 біт;
  - Підтримує ідентифікатори UID та GID до 32 біт;
  - Максимальний розмір файлу — 4 ГБ (2³² - 1 байт);
  - Розмір номера інода — 32 біти;
  - Заголовки та блоки даних вирівнюються по межі 4 байтів.
- **`crc`** (**SVR4 Portable Format with CRC-32**):
  Аналогічний до формату `newc`, але містить 32-бітну контрольну суму CRC-32 для кожного блоку даних файлу, що автоматично перевіряється при розпакуванні.
- **`odc`** (**Old Portable POSIX.1-1988 Format**):
  Історичний переносний формат із вісімковими (octal) ASCII-заголовками.
  - Обмеження: мажорні/мінорні номери пристроїв до 18 біт, UID/GID до 18 біт (значення до 262143), розмір файлу до 8 ГБ (2³³ - 1 байт);
  - Відсутні наносекундні мітки часу та підтримка xattr.
- **`bin`** (**Old Binary Format / Unix V7**):
  Історичний двійковий формат. Заголовки зберігаються у структурах C, через що архів залежить від порядку байтів платформи (потребує перестановки байтів `-b` / `-S` / `-s` при міжплатформовому читанні). Обмеження: UID/GID до 16 біт, розмір файлу до 2 ГБ.
- **`tar`** та **`ustar`**:
  Режим сумісності з архівами у форматі tar Unix V7 або POSIX.1-1988 ustar.
- **`hpbin`** та **`hpodc`**:
  Специфічні формати сумісності з ОС HP-UX.

### Повна таблиця параметрів GNU cpio

- **`-d`**, **`--make-directories`**: автоматично створює всі необхідні проміжні підкаталоги під час розпакування або в режимі copy-pass.
- **`-m`**, **`--preserve-modification-time`**: зберігає початковий час модифікації файлу `mtime` замість призначення поточного системного часу.
- **`-a`**, **`--reset-access-time`**: скидає та відновлює початковий час доступу `atime` вихідних файлів після їхнього зчитування у режимах `-o` та `-p` (за допомогою виклику `utimensat`).
- **`-u`**, **`--unconditional`**: безумовно перезаписує всі наявні файли в каталозі призначення без запиту підтвердження (без `-u` `cpio` не перезаписує новіші файли).
- **`-l`**, **`--link`**: у режимі `-p` створює жорсткі посилання (`linkat`) замість копіювання байтів даних, якщо вихідні й цільові файли розташовані на одній файловій системі.
- **`-R [user][:.][group]`**, **`--owner=[user][:.][group]`**: примусово призначає зазначеного власника та/або групу для всіх створених файлів.
- **`--numeric-uid-gid`**: записує в заголовки винятково числові значення UID/GID без текстового розв'язання через `/etc/passwd`.
- **`--no-preserve-owner`**: при розпакуванні непривілейованим користувачем створювати файли у власності поточного процесу.
- **`--sparse`**: (розширення GNU cpio) виявляє блоки нулів і записує файли як розріджені дірки на диск при вилученні файлів у режимах `-i` та `-p`.
- **`-0`**, **`--null`**: зчитує список імен файлів зі стандартного вводу з розділювачем `\0` (NUL-байт), що забезпечує коректну обробку імен із пробілами, лапками та символами переходу рядка.
- **`-t`**, **`--list`**: виводить перелік файлів усередині архіву без їхнього розпакування.
- **`-v`**, **`--verbose`**: детальний вивід імен оброблених файлів (із `-tv` — вивід у стилі `ls -l`).
- **`-F ARCHIVE`**, **`--file=ARCHIVE`**: вказує файл архіву для операцій читання або запису замість використання стандартних потоків `stdin`/`stdout`.
- **`--to-stdout`**: вилучає вміст файлів на стандартний вивід.

### Коди завершення (Exit Codes) GNU cpio

- **`0`**: Успішне завершення всіх операцій.
- **`1`**: Помилка при обробці окремих файлів (помилка читання, відсутність доступу).
- **`2`**: Фатальна системна або синтаксична помилка (недоступний архів, невідомий формат, пошкодження двійкового потоку).

```sh
# Генерація канонічного образу Linux initramfs
find . -mindepth 1 -print0 | cpio -o -0 -H newc | zstd -19 > /boot/initramfs-linux.img

# Клонування каталогу в режимі pass-through через cpio із збереженням усіх атрибутів
find . -depth -print0 | cpio -pamvd0 /destination
```

## Зведена таблиця та семантика кінцевих слешів у rsync та cp

Поведінка утиліт копіювання суттєво залежить від наявності символу скісної риски `/` (trailing slash) у кінці шляху джерела. У таблиці розібрано всі варіанти поведінки команд.

| Команда | Стан цільового каталогу `/dst` | Результуюча структура на приймачі | Пояснення механізму VFS |
| :--- | :--- | :--- | :--- |
| `rsync -a /src /dst` | Каталог `/dst` існує | `/dst/src/...` | Копіює сам каталог `src` як підкаталог всередину `/dst` |
| `rsync -a /src /dst` | Каталог `/dst` відсутній | `/dst/...` | Створює каталог `/dst` і поміщає в нього вміст `src` |
| `rsync -a /src/ /dst` | Каталог `/dst` існує | `/dst/...` | Кінцевий слеш означає «копіювати вміст каталогу `src` без створення підкаталогу `src`» |
| `rsync -a /src/ /dst` | Каталог `/dst` відсутній | `/dst/...` | Створює каталог `/dst` і наповнює його вмістом `src` |
| `rsync -a /src /dst/` | Каталог `/dst` існує | `/dst/src/...` | Слеш на цілі не змінює логіку: оскільки на джерелі немає слеша, створюється `dst/src` |
| `rsync -a /src/ /dst/` | Каталог `/dst` існує | `/dst/...` | Вміст `src` копіюється безпосередньо в корінь `/dst` |
| `cp -a /src /dst` | Каталог `/dst` існує | `/dst/src/...` | GNU `cp` розміщує джерело всередині наявного каталогу призначення |
| `cp -a /src /dst` | Каталог `/dst` відсутній | `/dst/...` | GNU `cp` створює новий каталог `/dst` як пряму копію каталогу `/src` |
| `cp -a /src/. /dst` | Каталог `/dst` існує | `/dst/...` | Крапка `.` змушує `cp` розгорнути вміст `src` безпосередньо у `/dst` |
| `cp -a -T /src /dst` | Каталог `/dst` існує | помилка `EISDIR` або перезапис вмісту | Прапорець `-T` (`--no-target-directory`) вимикає створення підкаталогу |

> ⚠️ **Критичне правило rsync:**
> Наявність кінцевого слеша на шляху **джерела** (`/src/`) вказує `rsync` копіювати винятково **вміст** каталогу. Відсутність слеша (`/src`) наказує копіювати **сам каталог** разом із його ім'ям. На шляху **призначення** наявність або відсутність кінцевого слеша не змінює топологію розміщення файлів.

## Системні виклики реплікації VFS ядра Linux

Кожна високорівнева операція утиліт копіювання спирається на сучасні системні виклики ядра Linux родини `*at`, які приймають файловий дескриптор базового каталогу (`dirfd`), що гарантує захист від атак підміни компонентів шляху (Time-of-Check to Time-of-Use, TOCTOU).

### 1. Зчитування розширеного стану інода: statx

Системний виклик `statx` (введений у ядрі Linux 4.11) замінив застарілі виклики `stat`, `lstat` та `fstat`. Він дозволяє запитувати точну бітову маску полів та повертає наносекундні часові мітки разом із часом створення файлу (`btime`).

```
int statx(int dirfd, const char *pathname, int flags,
          unsigned int mask, struct statx *statxbuf);
```

- **`dirfd`**: дескриптор каталогу або спеціальна константа `AT_FDCWD` (поточний робочий каталог процесу).
- **`pathname`**: відносний або абсолютний шлях до файлу. Якщо передано порожній рядок `""` разом із прапорцем `AT_EMPTY_PATH` у `flags`, виклик повертає стан інода самого дескриптора `dirfd`.
- **`flags`**:
  - `AT_SYMLINK_NOFOLLOW`: якщо файл є символьним посиланням, повертає метадані самого посилання, а не цільового інода;
  - `AT_STATX_SYNC_AS_STAT`: стандартна синхронізація атрибутів із файловою системою;
  - `AT_STATX_FORCE_SYNC`: примусове скидання кешів для отримання актуальних атрибутів мережевих ФС (NFS, CIFS);
  - `AT_STATX_DONT_SYNC`: вимкнення синхронізації (читання винятково з локального кешу ядра).
- **`mask`**: бітова маска запитуваних атрибутів:
  - `STATX_TYPE` (`stx_mode & S_IFMT`);
  - `STATX_MODE` (біти прав `07777`);
  - `STATX_NLINK` (кількість жорстких посилань `stx_nlink`);
  - `STATX_UID`, `STATX_GID` (ідентифікатори володіння);
  - `STATX_ATIME`, `STATX_MTIME`, `STATX_CTIME` (наносекундні позначки);
  - `STATX_BTIME` (час народження/створення файлу `stx_btime`);
  - `STATX_SIZE`, `STATX_BLOCKS` (розмір та кількість блоків по 512 байтів);
  - `STATX_BASIC_STATS` (макрос, що вмикає всі стандартні поля POSIX `stat`).

Структура `struct statx` також повертає прапорці інода в полі `stx_attributes` (підтверджені в `stx_attributes_mask`):
- `STATX_ATTR_COMPRESSED`: файл стиснутий на рівні ФС;
- `STATX_ATTR_IMMUTABLE`: встановлено прапорець незмінності (`chattr +i`);
- `STATX_ATTR_APPEND`: файл дозволено лише дописувати (`chattr +a`);
- `STATX_ATTR_NODUMP`: файл виключено з резервного копіювання (`chattr +d`).

Коди помилок `statx`: `EACCES` (відсутній доступ до каталогу), `ENOENT` (файл не існує), `ENOTDIR` (елемент шляху не є каталогом), `EINVAL` (некоректна маска або невідомий прапорець).

### 2. Створення вузлів файлової системи: openat, symlinkat, mknodat, linkat

- **Створення регулярних файлів**:
  ```
  int openat(int dirfd, const char *pathname, int flags, mode_t mode);
  ```
  Використовується комбінація прапорців `O_CREAT | O_WRONLY | O_TRUNC | O_NOFOLLOW | O_CLOEXEC`. Початковий `mode` задається як суворо обмежений (`0600`), щоб сторонні непривілейовані процеси не могли прочитати дані до накладання оригінальних списків ACL та прав доступу.

- **Створення символьних посилань**:
  ```
  int symlinkat(const char *target, int newdirfd, const char *linkpath);
  ```
  Створює новий вузол типу `S_IFLNK`. Текст цілі `target` попередньо вичитується з вихідного посилання за допомогою системного виклику `readlinkat(dirfd, pathname, buf, bufsiz)`.

- **Створення спеціальних файлів (FIFO, пристроїв)**:
  ```
  int mknodat(int dirfd, const char *pathname, mode_t mode, dev_t dev);
  int mkfifoat(int dirfd, const char *pathname, mode_t mode);
  ```
  Для блокових (`S_IFBLK`) та символьних (`S_IFCHR`) пристроїв аргумент `dev` формується викликом `makedev(major, minor)` на основі значення `stx_rdev_major` та `stx_rdev_minor`. Створення файлів пристроїв вимагає наявності адміністративного привілею `CAP_MKNOD`.

- **Створення жорстких посилань**:
  ```
  int linkat(int olddirfd, const char *oldpath,
             int newdirfd, const char *newpath, int flags);
  ```
  Якщо `flags` дорівнює `0`, створює жорстке посилання на наявний інод. Помилка `EXDEV` виникає, якщо `oldpath` та `newpath` розташовані на різних точках монтування файлових систем.

### 3. Блочне клонування екстентів: copy_file_range та ioctl(FICLONE)

- **Системний виклик copy_file_range**:
  ```
  ssize_t copy_file_range(int fd_in, loff_t *off_in,
                          int fd_out, loff_t *off_out,
                          size_t len, unsigned int flags);
  ```
  Виконує пряму передачу даних між двома файловими дескрипторами в просторі ядра. На файлових системах із підтримкою Copy-on-Write (Btrfs, XFS) виклик створює спільні посилання на фізичні екстенти диска без виділення нового дискового простору.
  Коди помилок: `EXDEV` (файли на різних ФС або несумісних розділах), `EOPNOTSUPP` (операція не підтримується ФС), `EBADF` (дескриптор не відкритий для читання або запису).

- **Клонування всього файлу через ioctl(FICLONE)**:
  ```
  int ioctl(int dest_fd, FICLONE, int src_fd);
  ```
  Атомарно прив'язує всі екстенти вихідного файлу до цільового файлу. У разі успіху операція виконується за O(1) операцій ядра.

### 4. Навігація розрідженими файлами: lseek та fallocate

- **Пошук меж даних та дірок через lseek**:
  ```
  off_t lseek(int fd, off_t offset, int whence);
  ```
  - `whence = SEEK_DATA`: переміщує файловий покажчик на найближчий зсув, починаючи з `offset`, де містяться реальні виділені байти. Якщо від `offset` до кінця файлу даних немає, виклик повертає `-1` із кодом помилки `ENXIO`.
  - `whence = SEEK_HOLE`: переміщує покажчик на найближчий зсув, де починається дірка (невиділений простір нулів). Якщо `offset` потрапляє всередину дірки, повертається сам `offset`. Якщо файл не містить дірок, повертається координата кінця файлу (`st_size`).

- **Перфорація дірок через fallocate**:
  ```
  int fallocate(int fd, int mode, off_t offset, off_t len);
  ```
  Передача маски `mode = FALLOC_FL_PUNCH_HOLE | FALLOC_FL_KEEP_SIZE` звільняє фізичні блоки диска в діапазоні `[offset, offset + len)`, перетворюючи їх на розріджену дірку без зміни загального логічного розміру файлу.

### 5. Розширені атрибути та POSIX ACL: llistxattr, lgetxattr, lsetxattr

Розширені атрибути представляють пари «ім'я → значення», асоційовані з інодом. Префікс `l*` гарантує опрацювання самого символьного посилання без переходу за ним.

```
ssize_t llistxattr(const char *path, char *list, size_t size);
ssize_t lgetxattr(const char *path, const char *name, void *value, size_t size);
int lsetxattr(const char *path, const char *name, const void *value, size_t size, int flags);
```

- **Двоетапний алгоритм вичитування**:
  1. Перший виклик `llistxattr(path, NULL, 0)` повертає необхідний розмір буфера в байтах;
  2. Виділяється буфер пам'яті відповідного розміру;
  3. Повторний виклик `llistxattr(path, buffer, size)` заповнює буфер списком рядків імен атрибутів, розділених нульовим байтом `\0`;
  4. Для кожного імені викликається `lgetxattr(path, name, NULL, 0)` для визначення розміру значення, виділяється пам'ять і вичитується двійковий вміст через `lgetxattr(path, name, val_buf, val_size)`.
- **Запис атрибута**:
  Виклик `lsetxattr(path, name, value, size, flags)` записує атрибут на цільовий вузол. Параметр `flags` може приймати значення `0`, `XATTR_CREATE` (помилка `EEXIST`, якщо атрибут уже є) або `XATTR_REPLACE` (помилка `ENODATA`, якщо атрибута ще немає).
- **Простори імен xattr**:
  - `user.*`: довільні дані додатків;
  - `system.posix_acl_access`, `system.posix_acl_default`: двійкові структури списків доступу POSIX ACL;
  - `security.selinux`, `security.capability`: мітки безпеки SELinux та бінарні маски привілеїв файлів Linux Capabilities;
  - `trusted.*`: службові атрибути, доступні лише процесам із можливістю `CAP_SYS_ADMIN`.

### 6. Встановлення власника: fchownat

```
int fchownat(int dirfd, const char *pathname,
             uid_t owner, gid_t group, int flags);
```

- Призначає числові ідентифікатори `owner` (UID) та `group` (GID). Якщо значення дорівнює `-1`, відповідне поле не змінюється.
- Прапорець `flags = AT_SYMLINK_NOFOLLOW` змінює власника самого символьного посилання.
- **Критична взаємодія з VFS ядра**: системний виклик `fchownat()` з міркувань безпеки **завжди скидає біти `S_ISUID` та `S_ISGID`** (внутрішній прапорець ядра `ATTR_KILL_SUID` / `ATTR_KILL_SGID`), щоб запобігти створенню привілейованих двійкових файлів непривілейованим користувачам. Через це встановлення режиму доступу (`fchmodat`) зобов'язане виконуватися **суворо після** зміни власника.

### 7. Встановлення режиму доступу: fchmodat

```
int fchmodat(int dirfd, const char *pathname, mode_t mode, int flags);
```

- Встановлює маску прав `mode_t` (9 бітів доступу + біти SUID `04000`, SGID `02000`, Sticky `01000`).
- На рівні ядра Linux системний виклик `fchmodat()` не підтримує прапорець `AT_SYMLINK_NOFOLLOW` (у POSIX права доступу самого символьного посилання не перевіряються під час маршрутизації шляхів і фіксовані як `0777`).

### 8. Встановлення часових позначок: utimensat

```
int utimensat(int dirfd, const char *pathname,
              const struct timespec times[2], int flags);
```

- Встановлює наносекундні часові мітки:
  - `times[0]` (`st_atim`): час останнього доступу;
  - `times[1]` (`st_mtim`): час останньої модифікації даних.
- Спеціальні значення в полі `tv_nsec`:
  - `UTIME_NOW`: ядро встановлює поточний системний час;
  - `UTIME_OMIT`: відповідна мітка часу залишається незмінною в іноді.
- Прапорець `flags = AT_SYMLINK_NOFOLLOW` дозволяє оновлювати мітки часу самого символьного посилання.
- **Вимога черговості**: виклик `utimensat()` **завжди має бути останнім системним викликом** у ланцюжку клонування файлу, оскільки будь-який попередній виклик запису даних (`write`, `copy_file_range`) або зміни прав (`fchmodat`) автоматично скидає `mtime` та `ctime` до поточного системного годинника ядра.

## Інваріанти послідовності викликів та фази обходу дерева

Для гарантії збереження всіх метаданих VFS без їхнього випадкового скидання ядром процес клонування одного файлового вузла та рекурсивного обходу дерева має суворо дотримуватися послідовності кроків.

### 1. Канонічний життєвий цикл реплікації окремого вузла VFS

```
[1. statx(AT_SYMLINK_NOFOLLOW)] ──────► Читання типу вузла, прав, UID/GID, міток часу, xattr
               │
               ▼
[2. openat / symlinkat / mknodat] ───► Створення цільового вузла з тимчасовими безпечними правами (0600)
               │
               ▼
[3. copy_file_range / lseek] ────────► Копіювання даних або перфорація розріджених дірок
               │
               ▼
[4. llistxattr / lsetxattr] ─────────► Запис розширених атрибутів, POSIX ACL та міток SELinux
               │
               ▼
[5. fchownat(AT_SYMLINK_NOFOLLOW)] ──► Встановлення UID/GID (ядро скидає біти SUID/SGID)
               │
               ▼
[6. fchmodat] ───────────────────────► Фіксація повного mode (відновлення бітів SUID/SGID/Sticky)
               │
               ▼
[7. utimensat(AT_SYMLINK_NOFOLLOW)] ─► Фіксація наносекундних atime/mtime (завжди фінальний крок)
```

### 2. Двоетапний обхід каталогів (Post-Order Traversal)

Особливістю обробки каталогів є те, що створення будь-якого файлу всередині каталогу змінює таблицю імен цього каталогу, що змушує ядро оновити його `mtime` і `ctime`. Крім того, каталог із вихідними правами `0555` (тільки читання) заблокує створення файлів всередині нього.

Через це утиліти копіювання реалізують двоетапний обхід:
1. **Фаза спуску (Pre-Order)**: каталоги створюються через `mkdirat()` із тимчасовими правами запису (`0700` або `mode | 0700`), а їхні вихідні параметри (права, власник, мітки часу) поміщаються у внутрішній стек утиліти;
2. **Фаза наповнення**: створюються всі вкладені файли, спеціальні вузли та підкаталоги, виконується копіювання даних і фіксація їхніх метаданих;
3. **Фаза підйому (Post-Order)**: після завершення обробки всіх дітей каталогу зі стека вилучаються його початкові метадані, викликається `fchownat()`, потім `fchmodat()` для встановлення точних прав (наприклад, `0555`), і наприкінці — `utimensat()` для фіксації `mtime` та `atime` каталогу.
