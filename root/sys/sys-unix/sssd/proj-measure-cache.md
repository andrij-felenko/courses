# ⚙️ Секундомір: звідки насправді прийшла відповідь про користувача

Напишемо коротку програму мовою C, яка питає про того самого користувача кілька разів поспіль і міряє кожен виклик окремо — бо жоден програмний інтерфейс не повідомляє, з відображеної пам'яті прийшла відповідь, з бази на диску чи з мережі, а час це видає безпомилково.

## Чому час узагалі про щось говорить

Три шляхи, якими може прийти ім'я, коштують принципово різного.

Влучення в кеш у пам'яті — це читання з [відображеної в процес сторінки](root:sys-unix/mmap-model): жодного системного виклику, жодного перемикання контексту, одиниці мікросекунд. Звертання до респондера — це [сокет домену Unix](root:sys-unix/unix-domain-sockets): записати запит, приспати процес, розбудити демона, дочекатися відповіді, розбудити нас назад, а між тим ще й прочитати запис із бази на диску; виходять сотні мікросекунд. Похід у каталог додає до всього цього повний оберт по мережі й пошук на сервері — десятки мілісекунд.

Відстань між сусідніми рівнями — приблизно два порядки. Це набагато більше за розкид самого вимірювання, тому здогадуватися не доводиться: число саме називає рівень.

Тут же видно, чому [трасування системних викликів](root:sys-unix/syscall-tracing) цього питання не розв'язує. `strace` чесно покаже `connect` і `sendto` на сокеті респондера — але влучення в кеш у пам'яті він не покаже ніколи, бо там немає жодного системного виклику. Найдешевший рівень невидимий саме тому, що він найдешевший.

## Спершу лінійка, потім вимірювання

Міряти треба [монотонним годинником](root:sys-unix/kernel-timekeeping), `CLOCK_MONOTONIC`, а не `CLOCK_REALTIME`. Причина не в точності: календарний час підтягує служба синхронізації, і підтягнути вона може назад, тож різниця двох позначок буває від'ємною. Монотонний годинник назад не ходить за побудовою.

Друге питання — скільки коштує сам замір. `clock_gettime` для монотонного годинника виконується [через vDSO](root:sys-unix/vdso), тобто без входу в ядро, і триває кілька десятків наносекунд. Перевірити це має сама програма, першою ж дією:

```
роздільність секундоміра ≈ 25 нс
найдешевший вимір        ≈ 3000 нс
відношення               ≈ 120
```

Лінійка в сто разів дрібніша за найменшу поділку, яку ми хочемо розрізнити, — цього досить. Якби вихід у ядро коштував нам мікросекунду, найдешевший рівень утонув би у власному вимірюванні.

## Три результати, а не два

Перш ніж міряти, треба навчитися правильно читати відповідь, бо `getpwnam_r` розрізняє три випадки, а недбалий код бачить два.

Контракт такий. Функція повертає `0` і кладе в `*result` вказівник на заповнену структуру — **знайшов**. Повертає `0` і кладе в `*result` порожній вказівник — **спитали, і такого користувача нема**. Повертає ненульове число — **відповіді немає**: ми не змогли спитати або не змогли вмістити відповідь.

Останній випадок ділиться далі. Код `ERANGE` — це взагалі не про користувача, а про наш буфер: місця забракло, треба взяти більший і повторити. Інші коди — це справжня неспроможність.

> 🔧 **Навіщо це.** Скрипт прибирання, що видаляє домашні каталоги людей, яких «уже нема в базі», зазвичай перевіряє рівно одне: чи повернулася структура. Поки каталог доступний, він працює правильно. У день, коли демон не піднявся, «не зміг спитати» стане для нього «нема такого» — і він прибере домашні каталоги всієї установи.

І тут же пастка, через яку третій випадок майже ніколи не доходить до програми. [Перемикач імен](root:sys-unix/user-database-nss) має для кожного джерела таблицю дій, і типова дія для стану `unavail` — `continue`: недоступне джерело мовчки пропускають і йдуть до наступного. Коли наступних не лишилося, підсумок усього ланцюжка — `notfound`, тобто ті самі `0` і порожній вказівник. Мертвий SSSD за типового налаштування виглядає з програми не як аварія, а як порожня установа.

Висновок практичний: розрізняти три результати в коді обов'язково, але покладатися на те, що третій прийде сам, не можна. Про недоступність питають демона — командою `sssctl domain-status`.

## Програма

```c
/* whence.c — звідки прийшла відповідь про користувача.
 * збірка: cc -O2 -o whence whence.c
 * вжиток: ./whence <повторів> <ім'я> [ім'я ...]           */
#define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

enum answer { FOUND, ABSENT, NO_ANSWER };

static long long now_ns(void)
{
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return (long long)t.tv_sec * 1000000000LL + t.tv_nsec;
}

/* один пошук із чесним розрізненням трьох результатів */
static enum answer lookup(const char *name, uid_t *uid, int *err)
{
    long hint = sysconf(_SC_GETPW_R_SIZE_MAX);
    size_t size = (hint > 0) ? (size_t)hint : 1024;
    char *buf = NULL;

    for (;;) {
        char *bigger = realloc(buf, size);
        if (bigger == NULL) { free(buf); *err = ENOMEM; return NO_ANSWER; }
        buf = bigger;

        struct passwd pw;
        struct passwd *res = NULL;
        int rc = getpwnam_r(name, &pw, buf, size, &res);

        if (rc == ERANGE && size < (1u << 20)) {   /* тісний буфер — не відповідь */
            size *= 2;
            continue;
        }

        enum answer out;
        if (rc != 0)          { *err = rc;         out = NO_ANSWER; }
        else if (res == NULL) {                    out = ABSENT;    }
        else                  { *uid = res->pw_uid; out = FOUND;    }

        free(buf);          /* res указує в buf — uid уже скопійовано */
        return out;
    }
}

int main(int argc, char **argv)
{
    if (argc < 3) {
        fprintf(stderr, "вжиток: %s <повторів> <ім'я> [ім'я ...]\n", argv[0]);
        return 2;
    }
    int reps = atoi(argv[1]);
    uid_t uid = 0;
    int err = 0;

    /* 1. міряємо сам секундомір */
    long long t0 = now_ns();
    for (int i = 0; i < 1000; i++) (void)now_ns();
    printf("сам замір часу: %lld нс на виклик\n\n", (now_ns() - t0) / 1000);

    /* 2. розігрів на імені, якого напевно нема: перший виклик у процесі ще й
     *    відображає файли кеша в пам'ять, і ця одноразова ціна нам не потрібна
     *    у вимірюваних числах                                                */
    (void)lookup("nemaje-takoho-91731", &uid, &err);

    /* 3. власне вимірювання: кожен виклик окремим рядком, без усереднення */
    for (int a = 2; a < argc; a++) {
        for (int r = 0; r < reps; r++) {
            long long t = now_ns();
            enum answer ans = lookup(argv[a], &uid, &err);
            long long dt = now_ns() - t;

            printf("%-12s %2d  %9.1f мкс  %s", argv[a], r, dt / 1000.0,
                   ans == FOUND ? "знайшов" :
                   ans == ABSENT ? "нема такого" : "не зміг спитати");
            if (ans == FOUND)     printf("  (uid %u)", (unsigned)uid);
            if (ans == NO_ANSWER) printf("  (%s)", strerror(err));
            putchar('\n');
        }
    }
    return 0;
}
```

Усереднювати тут не можна принципово: цікавий саме розкид між першим викликом і рештою, а середнє його якраз і ховає.

## Як чесно перевести систему між станами

Лишається питання, з якого починається будь-який експеримент: як опинитися в потрібному стані навмисно.

Ключ — у поведінці `sssctl cache-expire` (це обгортка навколо давнішої `sss_cache`). Команда робить дві різні речі: позначає застарілим **той запис, який названо**, і додатково скидає **весь** кеш у пам'яті, бо викреслити з відображеного файлу один запис вибірково вона не вміє. Ця асиметрія і дає нам експеримент: після `cache-expire -u alice` запис `bob` у базі на диску лишається чинним, але з пам'яті зник — тобто питання про `bob` дійде до респондера й спиниться на диску, а питання про `alice` піде далі, у мережу.

```
# у якому стані домен — інакше «в мережу» не станеться
$ sssctl domain-status firma.ua
Online status: Online

Active servers:
LDAP: ldap01.firma.ua

# скільки ще житиме запис
$ sudo sssctl user-show alice
Name: alice
Cache entry creation date: 08/09/26 09:12:41
Cache entry last update time: 08/09/26 09:12:41
Cache entry expiration time: 08/09/26 10:42:41
Initgroups expiration time: 08/09/26 10:42:41
Cached in InfoPipe: No

# знецінюємо запис alice — і разом з ним весь кеш у пам'яті
$ sudo sssctl cache-expire -u alice

$ ./whence 2 bob alice
сам замір часу: 24 нс на виклик

bob           0      377.2 мкс  знайшов  (uid 1042)
bob           1        3.1 мкс  знайшов  (uid 1042)
alice         0    17904.6 мкс  знайшов  (uid 1017)
alice         1        2.9 мкс  знайшов  (uid 1017)
```

Чотири рядки — три рівні. Перший `bob` — сокет і диск. Другий `bob` — пам'ять, куди респондер поклав відповідь, віддаючи її нам же секундою раніше. Перший `alice` — мережа, і вона дорожча за сокет приблизно у півсотні разів. Другий `alice` — знову пам'ять, і байдуже, що хвилину тому цей самий запит коштував майже двадцять мілісекунд.

Абсолютні числа залежать від машини й від того, як далеко стоїть каталог. Осмислені тут відношення: приблизно ×100 між пам'яттю й сокетом і ще ×50 між сокетом і мережею.

Помножте будь-яке з них на кількість імен у звичайній команді — і побачите, чому найдешевший рівень узагалі з'явився:

```
5000 файлів, кожен власник — окреме питання

через мережу:  5000 · 17.9 мс  ≈ 89 с
через сокет:   5000 · 377 мкс  ≈ 1.9 с
через пам'ять: 5000 · 3.1 мкс  ≈ 0.016 с
```

Перший рядок — це система, якою неможливо користуватися; другий — команда, яка помітно думає; третій — команда, що виконалася миттєво. Одні й ті самі п'ять тисяч питань.

Щоб зміряти рівно те, що робить `ls -l`, замініть у програмі `getpwnam_r` на `getpwuid_r`: ім'я в списку файлів шукають за номером. Контракт у неї той самий до літери — три результати, ті самі `ERANGE` і той самий буфер, — тому міняється рівно один виклик.

## Пастки, через які виміряти можна не те

**Теплий кеш псує перше вимірювання.** Найчастіша помилка — зміряти й вирішити, що мережа швидка. Насправді хтось питав про цю людину десять секунд тому. Перед кожним прогоном стан треба ставити руками; повторний запуск без нового `cache-expire` дає самі мікросекунди.

**Перелічення міряє інше.** `getpwent` і команда `getent passwd` без аргументу обходять кеш у пам'яті завжди: він побудований на пошуку за іменем і за номером, а не на видачі всього підряд. Такий запит іде до респондера навіть тоді, коли всі окремі імена вже в пам'яті, — і міряє він не той шлях, яким ходить `ls -l`.

**Фонове оновлення підмінює висновок.** SSSD уміє віддати запис, який дожив до певної частки свого терміну, негайно — а оновити його вже після відповіді. Такий виклик виглядає дешевим, хоча в мережу сходили; просто не в нашому часі. Побачити це можна за тим, що `sssctl user-show` після «швидкого» виклику показує свіжішу дату оновлення.

**Чужий кеш посередині.** Якщо на машині працює `nscd`, він стає ще одним шаром між бібліотекою й SSSD, і числа починають описувати його, а не демона. Разом із SSSD його не тримають саме тому.

**`id` — не той вимір.** Крім самого запису, `id` дістає ще й членство в групах, а це окремий запит із власним терміном життя — тим самим, який `sssctl user-show` показує окремим рядком. Міряти шлях імені треба саме пошуком імені.

**Файл бази руками не чіпають.** Спокуса заглянути в `/var/lib/sss/db/cache_firma.ua.ldb` через `ldbsearch` велика, а писати туди — тим паче. Робити цього не варто з трьох причин: у файл прямо зараз пише бекенд, набір службових атрибутів і терміни в ньому — внутрішня домовленість версії, а не інтерфейс, і саме на ці позначки спирається вся логіка свіжості. Підтримуване вікно в цей файл — `sssctl user-show`, щоб подивитися, і `sssctl cache-expire`, щоб змінити.
