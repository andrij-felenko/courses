# Довідник інтерфейсів BPF_MAP_TYPE_CPUMAP та BPF_MAP_TYPE_DEVMAP

Цей довідник містить вичерпний опис специфікацій BPF-карт `BPF_MAP_TYPE_CPUMAP`, `BPF_MAP_TYPE_DEVMAP` та `BPF_MAP_TYPE_DEVMAP_HASH`, системних структур даних ядра Linux, сигнатур допоміжних eBPF-функцій, а також подій підсистеми трасування (tracepoints).

Усі розглянуті BPF-карти є спеціалізованими типами карт перенаправлення (redirect maps), які працюють у тісному зв'язку з підсистемою NAPI та двофазним механізмом `XDP_REDIRECT`. Головна мета цих карт полягає у тому, щоб забезпечити швидку табличну індексацію цільових ресурсів (інших ядер ЦП або інших мережевих інтерфейсів) та надати контекстний простір для додаткових eBPF-програм обробки кадра.

---

## 1. Специфікація та значення BPF-карт

### BPF_MAP_TYPE_CPUMAP

Карта `BPF_MAP_TYPE_CPUMAP` призначена для асинхронного перенаправлення кадрів XDP з персивного ядра ЦП (RX CPU) на цільове ядро ЦП з метою паралельного створення сокетних буферів `sk_buff` або повторного виконання BPF-програми.

Кожен слот карти відповідає конкретному ідентифікатору ядра ЦП у системі. При спробі запису значення для CPU ID, якого не існує в поточній конфігурації ядра (наприклад, `cpu_id >= num_possible_cpus()`), системний виклик повертає помилку `-EINVAL`.

- **Тип ключа:** `__u32` (Ідентифікатор цільового CPU: `cpu_id`, від `0` до `max_cpus - 1`).
- **Тип значення (старий формат, ядра < 5.9):** `__u32` (Розмір безблокувальної черги `qsize`).
- **Тип значення (сучасний формат, ядра >= 5.9):** `struct bpf_cpumap_val`.

```c
struct bpf_cpumap_val {
    __u32 qsize;       /* Розмір черги ptr_ring (кількість елементів xdp_frame) */
    struct {
        __u32 fd;      /* Файловий дескриптор eBPF програми на цільовому CPU */
        __u32 id;      /* Внутрішній BPF ID програми (використовується ядром) */
    } bpf_prog;
};
```

Детальний опис параметрів конфігурації `qsize`:
1. Значення `qsize` визначає ємність безблокувального кільцевого буфера `ptr_ring` для конкретного цільового ядра ЦП. 
2. Значення має бути обов'язково кратним 2 (наприклад, 128, 512, 1024, 2048, 4096), оскільки алгоритм обчислення залишкового простору в `ptr_ring` використовує швидкі бітові маски замість операцій ділення.
3. Рекомендоване значення для 10G/40G/100G мережевих адаптерів становить `2048`. Занадто малий розмір черги призводить до частих відкидань пакетів при пікових сплесках трафіку, а занадто великий збільшує затримку (bufferbloat) та марно виділяє оперативну пам'ять під масиви покажчиків.
4. При записі `qsize = 0` слот вважається неактивним. Спроба перенаправити пакет на CPU з неактивним слотом призводить до того, що функція `bpf_redirect_map()` сигналізує про неможливість операції, і ядро відкидає пакет із викликом трасування `xdp_redirect_err` та поверненням коду `XDP_ABORTED`.

### BPF_MAP_TYPE_DEVMAP та BPF_MAP_TYPE_DEVMAP_HASH

Типи карт `BPF_MAP_TYPE_DEVMAP` (масив) та `BPF_MAP_TYPE_DEVMAP_HASH` (хеш-таблиця) використовуються для перенаправлення кадрів XDP у драйвер вихідного мережевого пристрою (`net_device`).

Карта `DEVMAP` використовується в ситуаціях, коли мережеві інтерфейси проіндексовані щільним послідовним діапазоном цілих чисел. Вона забезпечує максимальну швидкість вибірки O(1) за рахунок прямого індексування масиву ядра. Карта `DEVMAP_HASH` застосовується, коли ключі перенаправлення є розрідженими (наприклад, довільні ID віртуальних портів у Kubernetes, VLAN ID чи хеш-мітки), оскільки вона не вимагає виділення пам'яті під невикористовувані елементи масиву.

- **Тип ключа для DEVMAP:** `__u32` (Індекс вихідного мережевого пристрою `ifindex` або умовний портовий індекс).
- **Тип ключа для DEVMAP_HASH:** `__u32` або довільна цілочисельна структура (наприклад, VLAN ID, ідентифікатор тунелю).
- **Тип значення (старий формат, ядра < 5.8):** `__u32` (`ifindex` цільового пристрою).
- **Тип значення (сучасний формат, ядра >= 5.8):** `struct bpf_devmap_val`.

```c
struct bpf_devmap_val {
    __u32 ifindex;     /* Системний індекс вихідного мережевого інтерфейсу */
    struct {
        __u32 fd;      /* Файловий дескриптор egress BPF-програми */
        __u32 id;      /* Внутрішній ID BPF-програми (визначений ядром) */
    } bpf_prog;
};
```

Поле `ifindex` у структурі `struct bpf_devmap_val` вказує системний індекс вихідного мережевого пристрою в ОС Linux (відповідний виводу `ip link`). Якщо вказаний `ifindex` не існує у системі або мережевий пристрій знаходиться у стані `DOWN`, спроба додавання елемента у карту повертає помилку `-EINVAL` або `-ENODEV`.

## 2. Сигнатури допоміжних eBPF-функцій (Helpers)

### bpf_redirect_map()

Допоміжна функція `bpf_redirect_map()` є головним інструментом реєстрації наміру перенаправлення кадра в програмах XDP.

```c
long bpf_redirect_map(void *map, __u64 key, __u64 flags);
```

Функція працює за наступними правилами:
1. Записує покажчик на карту, цільовий ключ та конфігураційні прапорці у локальну per-CPU структуру ядра `struct bpf_redirect_info`.
2. Перевіряє наявність запису у вказаній BPF-карті за вказаним ключем.
3. Якщо запис існує та є валідним, функція завжди повертає числову константу `XDP_REDIRECT` (значення `7`).
4. Якщо запис у карті відсутній або містить невалідні параметри, функція аналізує маску прапорців `flags`. За замовчуванням (якщо прапорці `BPF_F_ACTION_MASK` не вказані) ядро повертає `XDP_ABORTED`. За допомогою прапорців розробник може наказати ядру повернути `XDP_PASS` або `XDP_DROP` у разі відсутності ключа у карті.

### bpf_redirect()

```c
long bpf_redirect(__u32 ifindex, __u64 flags);
```

Функція `bpf_redirect()` перенаправляє пакет безпосередньо на мережевий пристрій за вказаним `ifindex` без використання BPF-карти.

Вона має фундаментальні обмеження порівняно з `bpf_redirect_map()`: вона не підтримує пакетне групування `bulk transmit`, не дозволяє використовувати egress BPF-програми та позбавлена можливості перенаправлення на інші ядра ЦП через `CPUMAP`. У високопродуктивних мережевих застосунках використання `bpf_redirect()` вважається застарілим підходом.

### bpf_xdp_adjust_head()

```c
long bpf_xdp_adjust_head(struct xdp_md *xdp_md, int delta);
```

Функція `bpf_xdp_adjust_head()` зміщує покажчик початку пакетних даних (`xdp->data`) на величину `delta` байт.

- Якщо `delta` від'ємне (наприклад, `-14`), покажчик `data` зміщується вліво у напрямку заголовка сторінки (headroom), що дозволяє eBPF-програмі додавати нові заголовки (наприклад, Ethernet, VLAN, VXLAN).
- Якщо `delta` додатне (наприклад, `14`), покажчик `data` зміщується вправо, що дозволяє обрізати вхідні заголовки кадра.
- При спробі змістити покажчик за межі виділеного headroom (менше ніж `data_hard_start`) або за межі `data_end` функція повертає помилку `-EINVAL`.

## 3. Системні структури даних ядра Linux

### Context `struct xdp_buff` (Вхідний контекст XDP)

Структура `struct xdp_buff` використовується драйвером мережевої карти під час первинного отримання кадра та його передачі в eBPF-програму:

```c
struct xdp_buff {
    void *data;             /* Початок пакетних даних у сторінці пам'яті */
    void *data_end;         /* Кінець пакетних даних */
    void *data_meta;        /* Початок метаданих для передачі між BPF-програмами */
    void *data_hard_start;  /* Фізичний початок виділеної сторінки пам'яті */
    struct xdp_rxq_info *rxq;/* Інформація про RX-чергу та page_pool */
    struct net_device *frame_sz;/* Розмір кадра / конфігурація метаданих */
    __u32 flags;            /* Прапорці (наприклад, наявність додаткових фрагментів) */
};
```

Поле `data_hard_start` вказує на точний початок виділеної сторінки пам'яті. Відстань між `data_hard_start` та `data` визначає доступний розмір headroom (за замовчуванням 256 байт). Поле `data_meta` вказує на область користувацьких метаданих, які можуть передаватися між eBPF-програмами перед основним заголовком Ethernet.

### Context `struct xdp_frame` (Конвертований кадр перенаправлення)

Коли пакет переходить у стан `XDP_REDIRECT`, ядро конвертує `struct xdp_buff` у компактну структуру `struct xdp_frame`, яка записується безпосередньо у заголовочну частину (headroom) сторінки пам'яті:

```c
struct xdp_frame {
    void *data;             /* Вказівник на початок корисного навантаження кадра */
    u16 len;                /* Довжина пакетного кадра у байтах */
    u16 headroom;           /* Доступний розмір headroom (мінімум 256 байт) */
    u32 metasize;           /* Розмір збережених eBPF-метаданих */
    struct xdp_mem_info mem;/* Інформація про модель пам'яті (page_pool) */
    struct net_device *dev_rx;/* Вказівник на вхідний мережевий пристрій */
    u32 frame_sz;           /* Загальний розмір виділеного буфера сторінки */
    u32 flags;              /* Прапорці (включаючи мультибуферні фрагменти) */
};
```

Завдяки збереженню структури `struct xdp_frame` безпосередньо в заголовочній частині сторінки, ядру не потрібно виділяти додаткові системні об'єкти з динамічної пам'яті (heap). Це гарантує максимальну локальність кешу та нульові накладні витрати на аллокацію пам'яті.

## 4. Точки трасування (Tracepoints) підсистеми XDP

Підсистема трасування Linux (Ftrace / perf / eBPF tracepoints) надає низькорівневі події для спостереження за поведінкою `CPUMAP` та `DEVMAP`:

### 1. `tracepoint:xdp:xdp_redirect`
Викликається при успішній реєстрації наміру перенаправлення в `xdp_do_redirect()`.
- **Поля:** `int prog_id`, `u32 act`, `int ifindex`, `int err`, `int to_ifindex`, `u32 map_id`, `u32 map_index`.

### 2. `tracepoint:xdp:xdp_redirect_err`
Викликається у випадку помилки перенаправлення (невалідний `ifindex`, заповнена черга `ptr_ring`, відсутність `ndo_xdp_xmit`).
- **Поля:** `int prog_id`, `u32 act`, `int ifindex`, `int err`, `int to_ifindex`, `u32 map_id`, `u32 map_index`.

### 3. `tracepoint:xdp:xdp_cpumap_enqueue`
Повідомляє про постановку кадра в чергу `ptr_ring` цільового процесора.
- **Поля:** `int map_id`, `u32 act`, `int cpu`, `unsigned int drops`, `unsigned int processed`.

### 4. `tracepoint:xdp:xdp_cpumap_kthread`
Відображає роботу ядерного потоку `xdp_cpu_kthread` на цільовому ЦП при вичитенні пакетів.
- **Поля:** `int map_id`, `int cpu`, `unsigned int action`, `int drops`, `int processed`.

### 5. `tracepoint:xdp:xdp_devmap_xmit`
Повідомляє про результат пакетної передачі через `ndo_xdp_xmit()` в драйвері вихідного пристрою.
- **Поля:** `int map_id`, `u32 act`, `int src_ifindex`, `int target_ifindex`, `int sent`, `int drops`, `int err`.

## 5. Інспекція за допомогою bpftool та sysfs

### Перегляд та дамп BPF-карт

Для оперативного аналізу стану карт у системі використовується офіційна утиліта `bpftool`:

```bash
# Перелік усіх активних BPF-карт у системі
bpftool map show

# Перегляд детальної інформації про конкретну карту за ID
bpftool map show id 42

# Дамп вмісту CPUMAP або DEVMAP
bpftool map dump id 42
```

### Приклад виводу `bpftool map dump` для CPUMAP:

```json
[{
        "key": 0,
        "value": {
            "qsize": 2048,
            "bpf_prog": {
                "id": 0
            }
        }
    },{
        "key": 1,
        "value": {
            "qsize": 2048,
            "bpf_prog": {
                "id": 108
            }
        }
    }
]
```

Утиліта `bpftool` дозволяє в режимі реального часу відстежувати, які саме CPU ID чи мережеві інтерфейси прописані у картах, а також перевіряти ідентифікатори прикріплених eBPF-програм.

### Лічильники драйвера у sysfs та ethtool

Драйвери мережевих карт оновлюють власні системні лічильники XDP, доступні через `ethtool`:

```bash
# Перегляд статистики XDP на інтерфейсі eth0
ethtool -S eth0 | grep xdp
```

Типові назви системних лічильників:
- `rx_xdp_redirect`: Кількість успішно перенаправлених вхідних пакетів.
- `rx_xdp_redirect_errors`: Кількість помилок перенаправлення (відкинуті пакети).
- `tx_xdp_xmit`: Кількість пакетів, відправлених через `DEVMAP` у вихідний TX Ring.
- `tx_xdp_xmit_errors`: Помилки передачі у вихідному драйвері.
