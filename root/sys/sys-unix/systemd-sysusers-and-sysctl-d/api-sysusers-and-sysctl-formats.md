# 📋 Специфікація синтаксису конфігурацій sysusers.d та sysctl.d

Конфігураційні файли у каталогах `sysusers.d` та `sysctl.d` визначають декларативні правила для створення системних облікових записів і налаштування параметрів ядра Linux під час раннього етапу завантаження системи. Вони дозволяють розробникам пакетів дистрибутива та системним адміністраторам описувати необхідний стан операційного середовища без використання імперативних скриптів оболонки.

Цей довідник описує повну специфікацію синтаксису, типів даних, правил обробки рядків, правил пріоритетів та команд діагностики для обох підсистем.

---

## 1. Специфікація синтаксису файлів sysusers.d

Файли з розширенням `.conf` у каталогах `sysusers.d` зчитуються службою `systemd-sysusers.service` у лексикографічному порядку. Кожен незакоментований рядок описує один обліковий запис, групу, членство або зарезервований діапазон ідентифікаторів.

### Формат конфігураційного рядка sysusers.d

Кожен декларативний рядок складається з шести окремих полів, відокремлених один від одного одного або кількома символами пробілу чи табуляції:

```text
Type  Name  ID  "Comment"  Home  Shell
```

| Поле | Опис | Приклади / Значення за замовчуванням |
| :--- | :--- | :--- |
| **Type** | Тип декларації (`u`, `g`, `m`, `r`) | `u` (user+group), `g` (group only), `m` (membership), `r` (range) |
| **Name** | Унікальне ім'я користувача або групи | `systemd-journal`, `nginx`, `nobody` |
| **ID** | Фіксований UID/GID, діапазон, шлях або `-` | `999`, `100:500`, `/var/lib/metrics`, `-` (автоматичний вибір) |
| **Comment** | Текстовий опис облікового запису (GECOS) | `"Nginx web server"`, `-` (порожньо) |
| **Home** | Абсолютний шлях до домашнього каталогу | `/var/lib/nginx`, `-` (за замовчуванням `/`) |
| **Shell** | Шлях до командної оболонки | `/usr/bin/nologin`, `-` (за замовчуванням `/sbin/nologin`) |

### Деталізація типів записів (Type)

- **`u` (User — Користувач та первинна група)**:
  Створює системного користувача у `/etc/passwd` та одноіменну первинну групу у `/etc/group` з однаковим числове значенням UID та GID.
  - Якщо в полі `ID` вказано конкретне число (наприклад, `u systemd-journal 999`), утиліта перевіряє, чи вільний UID 999 та GID 999. Якщо UID вільний, створюється відповідний запис.
  - Якщо в полі `ID` вказано дефіс `-`, система вибирає найменший вільний UID/GID у діапазоні системних користувачів (`SYS_UID_MIN`..`SYS_UID_MAX` з `/etc/login.defs`, зазвичай 100–999).
  - Якщо в полі `ID` вказано комбінацію `UID:GID` (наприклад, `1001:1002`), створюється користувач із UID 1001 та первинна група з GID 1002.
  - Якщо в полі `ID` вказано абсолютний шлях до файлу або каталогу (наприклад, `u metrics /var/lib/metrics`), UID та GID нового користувача скопіюються з власника вказаного файлового об'єкта.

- **`g` (Group — Група)**:
  Створює лише системну групу у файлі `/etc/group` без створення запису у файлі `/etc/passwd`. Поля `Comment`, `Home` та `Shell` для цього типу записів ігноруються і повинні заповнюватися символом дефісу `-`.

- **`m` (Membership — Додаткове членство)**:
  Додає існуючого користувача до додаткової групи у файлі `/etc/group`. Синтаксис задекларовано як `m UserName GroupName`. Якщо користувач або група ще не створені на момент обробки рядка, `systemd-sysusers` відкладає виконання цього запису до створення обох сутностей під час поточного проходу.

- **`r` (Range — Резервування діапазону)**:
  Запобігає автоматичному виділенню ідентифікаторів у вказаному числовому діапазоні. Синтаксис: `r - 500-600`. Використовується для захисту статичних системних UID/GID дистрибутива від випадкового призначення при динамічному розподілі.

### Правила синтаксичного аналізу файлів sysusers.d

1. **Коментарі та порожні рядки**: Рядки, що починаються з символів `#` або `;`, а також порожні рядки повністю ігноруються парсером.
2. **Екранування та лапки**: Поле `Comment` може містити пробіли, якщо воно взято в подвійні лапки (наприклад, `"Systemd Journal Logging Daemon"`). Всередині лапок підтримуються стандартні екрановані послідовності `\"` та `\\`.
3. **Ідемпотентність повторного виконання**: Якщо користувач з вказаним ім'ям вже існує в `/etc/passwd`, `systemd-sysusers` перевіряє відповідність наявного UID задекларованому значенням. Якщо UID збігається, запис вважається успішно виконаним. Якщо виявлено невідповідність UID, утиліта логує попередження і не змінює наявний обліковий запис.

## 2. Специфікація синтаксису файлів sysctl.d

Конфігураційні файли `sysctl.d` описують параметри ядра Linux у формі ключових пар "ключ = значення". Вони застосовуються службою `systemd-sysctl.service` шляхом трансляції ключів у шляхи віртуальної файлової системи `/proc/sys/`.

### Формат конфігураційного рядка sysctl.d

```text
[префікс]ключ = значення
```

| Елемент | Опис | Приклади |
| :--- | :--- | :--- |
| **Ключ (Key)** | Назва параметра ядра у крапковій нотації | `net.ipv4.ip_forward`, `kernel.sysrq` |
| **Значення (Value)** | Рядок, число або масив чисел, що записуються у `/proc/sys/` | `1`, `65536`, `250 32000 32 128` |
| **Префікс `-`** | Маска ігнорування помилок відсутності вузла | `-net.ipv6.conf.all.disable_ipv6 = 1` |

### Механізм трансляції ключів у шляхи VFS та обробка масок

1. **Заміна крапок на косі риски**: Кожна крапка в імені ключа замінюється на символ `/`. Ключ `net.ipv4.ip_forward` транслюється у відносний шлях `net/ipv4/ip_forward`.
2. **Формування absolute VFS path**: Шлях поєднується з префіксом віртуальної файлової системи `/proc/sys/`, формуючи шлях `/proc/sys/net/ipv4/ip_forward`.
3. **Глобальні маски (Wildcards)**: Парсер підтримує масове застосування через символ зірочки (`*`). Рядок `net.ipv4.conf.*.rp_filter = 1` призведе до сканування всіх підкаталогів у `/proc/sys/net/ipv4/conf/` і запису значення `1` у кожен виявлений файл `rp_filter`.
4. **Масивні значення (Array Values)**: Деякі параметри ядра приймають кілька чисел, розділених пробілами. Наприклад, `kernel.sem = 250 32000 32 128` налаштовує параметри семафорів IPC (SEMMSL, SEMMNS, SEMOPM, SEMMNI) в один системний виклик `write()`.
5. **Префікс ігнорування помилок (`-`)**: Якщо знак мінуса стоїть перед ім'ям ключа, `systemd-sysctl` не буде повертати помилку завантаження та логувати критичні зауваження, якщо відповідний модуль ядра відсутній і вузол у `/proc/sys/` не існує.

## 3. Таблиця пріоритетів та правила затінення каталогів .d

При наявності файлів з однаковою базовою назвою у різних каталогах перемагає файл із каталогу з найвищим пріоритетом.

| Порядок пріоритету | Каталог | Призначення та поведінка |
| :---: | :--- | :--- |
| **1 (Найвищий)** | `/etc/sysusers.d/*.conf`<br>`/etc/sysctl.d/*.conf` | Конфігурації системного адміністратора. Мають абсолютний пріоритет над іншими шарами. |
| **2** | `/run/sysusers.d/*.conf`<br>`/run/sysctl.d/*.conf` | Динамічні конфігурації часу виконання. Зберігаються в `tmpfs` і зникають при перезавантаженні. |
| **3** | `/usr/lib/sysusers.d/*.conf`<br>`/usr/lib/sysctl.d/*.conf` | Заводські конфігурації пакетів дистрибутива. Створюються менеджером пакетів. |
| **4 (Найнижчий)** | `/lib/sysusers.d/*.conf`<br>`/lib/sysctl.d/*.conf` | Застарілий каталог системних конфігурацій для сумісності зі старими дистрибутивами. |

*Механізм маскування*: Створення символічного посилання на `/dev/null` або порожнього файлу у `/etc/sysusers.d/foo.conf` повністю блокує виконання конфігураційного файлу `foo.conf` із `/usr/lib/sysusers.d/foo.conf`.

## 4. Команди діагностики та інспектування конфігурації

Для перевірки підсумкової конфігурації, розв'язання конфліктів та діагностики затінених файлів systemd надає вбудовані команди з прапорцем `--cat-config`:

```bash
# Відображення об'єднаної конфігурації sysusers з урахуванням затінення
systemd-sysusers --cat-config

# Відображення об'єднаної конфігурації sysctl з урахуванням затінення
systemd-sysctl --cat-config

# Перевірка виконання sysusers у тестовому режимі без внесення змін у /etc/passwd
systemd-sysusers --inline "u testuser - \"Test User Account\" /var/lib/test /bin/false"
```

Команда `systemd-sysctl --cat-config` виводить у консоль єдиний розгорнутий список усіх правил `sysctl.d`, відсортованих у порядку їхнього підсумкового виконання, із зазначенням шляхів до файлів, з яких було зчитано кожен параметр.
