# 📜 Еволюція захищених режимів оболонки: від Bourne Shell до стандартів POSIX

Командна оболонка Unix створювалася в 1970-х роках передусім як інтерактивне середовище спілкування з операційною системою через телетайп, а не як мова системного програмування для безпілотної автоматизації критичної інфраструктури. Коли користувач вводив команду `grep "user" /etc/passwd`, яка нічого не знаходила й повертала код `1`, або припускався друкарської помилки в імені файлу у виклику `ls`, оболонка не повинна була розривати сесію й викидати людину з термінала. Дозволена, всепрощаюча поведінка за замовчуванням — коли будь-який ненульовий код завершення мовчки ігнорується, а наступні інструкції продовжують виконуватися — була свідомим та ергономічним вибором для діалогового режиму.

Проте в міру того, як прості набори команд у файлах перетворювалися на складні багатотисячні скрипти адміністрування, ініціалізації операційної системи та розгортання серверних кластерів, дозволена модель стала головним джерелом катастрофічних збоїв. Програмістам знадобилися десятиліття еволюції інтерпретаторів, стандартизації POSIX та польового досвіду, щоб сформувати сучасний набір захисних прапорців, відомий як «суворий режим» (Strict Mode).

## Витоки в Bourne Shell (1978): народження прапорців `-e` та `-u`

У сьомій редакції Research Unix (V7, 1979) Стівен Борн (Stephen Bourne) представив Bourne Shell (`/bin/sh`), що прийшла на зміну примітивній оболонці Томпсона (Thompson Shell). Борн заклав основи мови керування потоком (`if`, `for`, `while`, `case`), змінні середовища та вбудовану команду `set` для конфігурації поведінки інтерпретатора.

Саме в Bourne Shell уперше з'явилися два фундаментальні захисні перемикачі:

* **`-e` (`errexit`):** вказівка негайно завершити роботу скрипту, якщо будь-яка проста команда повертає ненульовий статус. Борн додав цей прапорець для пакетної обробки завдань (Batch Processing) на магнітних стрічках, де зупинка при першій помилці запобігала марнуванню дорогого процесорного часу.
* **`-u` (`nounset`):** заборона читання неініціалізованих змінних. Якщо інтерпретатор зустрічав змінну, якій не було присвоєно значення, він виводив помилку в `stderr` і переривав виконання замість тихої підстановки порожнього рядка.

Попри геніальність задуму, реалізація `set -e` у V7 Shell була примітивною. Правила зупинки не враховували складних конструкцій, логічних операторів `&&` та `||`, а також поведінки всередині умовних блоків `if`. Якщо розробник хотів перевірити результат виконання утиліти без аварійної зупинки всього скрипту, прапорець `-e` створював нерозв'язні конфлікти, змушуючи розробників постійно вмикати й вимикати його викликами `set +e` та `set -e`.

## Korn Shell (1988) та розв'язання проблеми «сліпоти конвеєрів»

У 1980-х роках Девід Корн (David Korn) у лабораторіях Bell Labs розробив Korn Shell (`ksh88`), яка стала стандартом де-факто для комерційних Unix-систем (AIX, Solaris, HP-UX). Корн звернув увагу на фундаментальну діру в архітектурі конвеєрів Unix.

У класичному конвеєрі:

```bash
mysqldump --all-databases | gzip > /backup/db.sql.gz
```

Ядро Unix запускає всі процеси конвеєра паралельно через системні виклики `fork()` і з'єднує їх анонімними каналами `pipe()`. Оболонка очікує завершення процесів через `waitpid()`. Проте за стандартом статус усього конвеєра визначався виключно кодом завершення **останньої команди** (`gzip`). Якщо `mysqldump` зазнавав аварії через відмову авторизації або збій диска і завершувався з кодом `1`, `gzip` успішно стискав порожній вхідний потік і повертав код `0`. Оболонка вважала конвеєр успішним, а `set -e` не спрацьовував.

Щоб подолати цю сліпоту, Корн у версії `ksh88` (а згодом у `ksh93`) впровадив опцію:

```bash
set -o pipefail
```

Цей прапорець змінив логіку агрегації статусів: якщо хоча б одна команда в ланцюжку каналів завершувалася з ненульовим кодом, підсумковим статусом конвеєра ставав код останньої (найправішої) команди, що зазнала збою.

У 2004 році, з виходом версії **Bash 3.0**, розробник Чет Ремей (Chet Ramey) портував `set -o pipefail` та масив `${PIPESTATUS[@]}` до GNU Bash, зробивши контроль конвеєрів доступним для всієї екосистеми Linux.

## Війни специфікації POSIX та неоднозначності `errexit`

Комітет зі стандартизації POSIX (IEEE Std 1003.1, Austin Group) зіткнувся з тим, що поведінка `set -e` у різних оболонках (`sh`, `ksh`, `bash`, `ash`, `zsh`) кардинально різнилася в крайових випадках.

Головними точками суперечок протягом 1990–2010-х років стали:

1. **Поведінка всередині тіл функцій під час перевірки умов:** якщо функція викликається як умова `if my_func; then`, чи повинні команди всередині `my_func` підпорядковуватися `set -e`? POSIX Issue 6 (2001) та Issue 7 (2008) постановили, що `errexit` має придушуватися для всіх команд у ланцюжку перевірки умови, що призвело до появи відомої пастки «тихого ігнорування помилок у функціях».
2. **Успадкування прапорців у підоболонках:** чи повинна команда підстановки `$(cmd)` успадковувати стан `set -e` батьківського процесу? До версії Bash 4.4 підоболонки скидали `errexit` у деяких контекстах, що змусило розробників додати спеціальний перемикач `shopt -s inherit_errexit` у 2016 році.
3. **Взаємодія з пастками `trap ... ERR`:** стандарт POSIX узагалі не стандартизував сигнал `ERR`, тому в Bash довелося запровадити прапорець `set -E` (`errtrace`), щоб пастки обробки помилок не губилися всередині функцій.

## Маніфест Аарона Максвелла (2014) та кристалізація суворого режиму

Попри наявність прапорців у ядрі інтерпретатора, у спільноті системних адміністраторів тривалий час не існувало єдиного стандарту безпечного написання скриптів. Розробники або не використовували захисні прапорці взагалі, або додавали лише одинокий `set -e`, регулярно потрапляючи в пастки конвеєрів та неініціалізованих змінних.

У травні 2014 року інженер Аарон Максвелл (Aaron Maxwell) опублікував програмну статтю під назвою *«Use the Unofficial Bash Strict Mode (Unless You Looove Debugging)»*. Максвелл запропонував канонічний преамбульний блок, який слід було розміщувати на початку кожного виробничого сценарію:

```bash
#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'
```

Максвелл детально обґрунтував синергію цих параметрів:

* `set -e` зупиняє скрипт при збої простих команд;
* `set -u` унеможливлює випадкове видалення критичних каталогів через друкарські помилки у змінних;
* `set -o pipefail` закриває сліпу зону фільтрів у конвеєрах;
* `IFS=$'\n\t'` запобігає небезпечному розщепленню рядків за пробілами під час ітерацій за масками файлів.

Публікація миттєво стала вірусною у середовищі DevOps, Infrastructure as Code та CI/CD. Вона задала стандарт надійності для інструментів автоматизації на десятиліття вперед, трансформувавши ставлення до Bash із «ненадійної командної склейки» на повноцінну інженерну платформу.
