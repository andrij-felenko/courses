# 📋 Довідник прапорців захищеного режиму та змінних стану інтерпретатора

Цей довідник містить вичерпну специфікацію параметрів конфігурації інтерпретатора командної оболонки, розширених опцій `shopt`, спеціальних масивів інтроспекції та таблиць поведінки розгортання параметрів за умов увімкненого суворого режиму. Довідник відкривають у процесі розробки та налагодження складних автоматизованих сценаріїв для перевірки меж успадкування прапорців функціями й підоболонками, аналізу поведінки кодів виходу системних сигналів та запобігання помилкам доступу до неініціалізованих змінних.

## 1. Базові прапорці виконання (`set` та `set -o`)

Команда `set` змінює внутрішні прапорці стану процесу оболонки. Прапорець активується знаком мінус (`-`) і вимикається знаком плюс (`+`). Усі базові прапорці мають як однолітерне скорочення (наприклад, `-e`), так і повну описову назву для використання через синтаксис `set -o <option>` / `set +o <option>`.

| Короткий прапорець | Довга опція (`set -o`) | Стандарт | Межі дії та успадкування | Механізм поведінки |
| :--- | :--- | :--- | :--- | :--- |
| `set -e` | `set -o errexit` | POSIX, Bash, Zsh, Dash | Поточний процес оболонки. Скидається у subshell без `inherit_errexit`. | Перериває виконання скрипту, якщо проста команда або конвеєр повертає ненульовий статус. Придушується всередині перевірок умов `if`, `while`, `until` та лівої частини `\|\|`, `&&`. |
| `set -u` | `set -o nounset` | POSIX, Bash, Zsh, Dash | Успадковується функціями та підоболонками. | Вважає звернення до неініціалізованої змінної або позиційного параметра фатальною помилкою, друкує повідомлення в `stderr` і виходить із кодом `1`. |
| — | `set -o pipefail` | Bash 3.0+, Zsh, Ksh88+ (Не POSIX) | Успадковується підоболонками. | Статусом завершення конвеєра стає код повернення останньої (найправішої) команди, що завершилася з ненульовим статусом (або `0`, якщо всі команди виконані успішно). |
| `set -E` | `set -o errtrace` | Bash, Zsh (Не POSIX) | Поширює пастки `ERR` на функції та підоболонки. | Змушує функції, заміщення команд та підоболонки успадковувати обробник `trap ... ERR`. Без цього прапорця пастка `ERR` діє лише на верхньому рівні скрипту. |
| `set -T` | `set -o functrace` | Bash (Не POSIX) | Поширює пастки `DEBUG` і `RETURN`. | Змушує функції та підоболонки успадковувати пастки `trap ... DEBUG` та `trap ... RETURN`. |
| `set -x` | `set -o xtrace` | POSIX, Bash, Zsh, Dash | Поточна оболонка, розгортає префікс `PS4`. | Друкує кожну команду в потік діагностики (`stderr` або `BASH_XTRACEFD`) після проходження всіх етапів розгортання безпосередньо перед її виконанням. |
| `set -v` | `set -o verbose` | POSIX, Bash, Zsh, Dash | Поточна оболонка. | Друкує сирі вхідні рядки скрипту в момент їх зчитування лексером (до розгортання змінних). |
| `set -n` | `set -o noexec` | POSIX, Bash, Zsh, Dash | Поточна оболонка. | Зчитує команди та перевіряє синтаксичну валідність без їх виконання. Ігнорується в інтерактивному режимі. |
| `set -C` | `set -o noclobber` | POSIX, Bash, Zsh, Dash | Поточна оболонка. | Забороняє оператору перенаправлення `>` перезаписувати наявні звичайні файли (для примусового перезапису вимагає оператора `>|`). |

### Механізм контекстного придушення `errexit` у граматиці POSIX

Стандарт POSIX.1-2017 (IEEE Std 1003.1-2017) та оновлена редакція POSIX.1-2024 (Issue 8) формально описують механізм придушення `set -e` через структуру абстрактного синтаксичного дерева (AST). Під час обходу вузлів дерева інтерпретатор встановлює внутрішній прапорець ігнорування помилок у трьох строго визначених ситуаціях:

1. **Вузол умовної перевірки (Compound Condition):** коли команда розташована між ключовими словами `if` і `then`, або між `while`/`until` та `do`. Ненульовий код виходу в цьому вузлі інтерпретується як логічне значення «хибність» (False) і перемикає виконання на альтернативну гілку `else` або перериває цикл, не активуючи аварійний вихід з процесу.
2. **Лівий дочірній вузол бінарного логічного списку (List Operators):** у виразах `cmd1 && cmd2` та `cmd1 || cmd2`. Якщо перша інструкція `cmd1` у ланцюжку `||` повертає статус `!= 0`, дія `errexit` блокується для `cmd1`, оскільки семантика оператора вимагає спроби виконання правого виразу `cmd2`. Проте для останньої (найправішої) команди в списку придушення не застосовується: якщо `cmd2` завершиться з ненульовим кодом, скрипт негайно перерве роботу.
3. **Вузол унарного заперечення (Pipeline Inversion):** коли перед командою або конвеєром стоїть знак оклику `! pipeline`. Ненульовий статус виконання інвертується ядром оболонки у нульовий код `$? = 0`, що формально вважається успішним завершенням інструкції.

## 2. Розширені налаштування інтерпретатора (`shopt`)

Утиліта `shopt` керує специфічними для Bash внутрішніми перемикачами роботи інтерпретатора. Опція активується командою `shopt -s <opt>` і деактивується командою `shopt -u <opt>`. Якщо опція несумісна з поточною версією Bash або скрипт запускається під іншою POSIX-оболонкою (наприклад, `/bin/dash`), виклик `shopt` завершиться з кодом `127` або `1`, тому у виробничих скриптах активацію супроводжують конструкцією `shopt -s <opt> 2>/dev/null || true`.

| Опція `shopt` | Версія Bash | Опис та вплив на надійність сценарію |
| :--- | :--- | :--- |
| `inherit_errexit` | 4.4+ | Змушує підстановку команд `$(...)` успадковувати налаштування `set -e`. За замовчуванням у старіших версіях Bash підстановка команд скидала прапорець `errexit`. |
| `nullglob` | 2.0+ | Якщо маска файлів (`*.log`) не знаходить жодного збігу, вона розгортається в порожній список замість збереження сирого рядка `'*.log'`. |
| `failglob` | 2.0+ | Якщо маска файлів не знаходить збігів, оболонка генерує фатальну помилку розгортання (Expansion Error) і зупиняє команду. |
| `dotglob` | 2.0+ | Включає приховані файли (файли, що починаються з крапки, крім `.` та `..`) у результати розгортання масок імен файлів. |
| `globstar` | 4.0+ | Дозволяє рекурсивне розгортання файлів за шаблоном `**` (наприклад, `src/**/*.cpp`). |
| `lastpipe` | 4.2+ | Виконує останню команду конвеєра в поточному процесі оболонки замість підоболонки (діє лише за вимкненого job control `set +m`), зберігаючи мутації змінних після циклів `while read`. |
| `extglob` | 2.0+ | Вмикає розширені регулярні оператори зіставлення шаблонів: `?(...)`, `*(...)`, `+(...)`, `@(...)`, `!(...)`. |

### Відмінності між `nullglob` та `failglob`

При побудові надійних файлових обробників вибір між `nullglob` та `failglob` визначає стратегію обробки відсутніх даних:

* За стандартної поведінки Bash вираз `for f in /var/log/app/*.log; do` за відсутності файлів виконає тіло циклу один раз для літерального рядка `"/var/log/app/*.log"`, що призведе до помилки `No such file or directory` у першій же операції над файлом.
* Увімкнення `shopt -s nullglob` перетворює маску без збігів на порожній перелік аргументів `()`, завдяки чому цикл `for` просто не виконає жодної ітерації.
* Увімкнення `shopt -s failglob` перетворює відсутність збігів на фатальну помилку рівня лексера, негайно зупиняючи виконання команди ще до запуску зовнішніх процесів. Це ідеально підходить для критичних завдань резервування, де відсутність вхідних файлів сигналізує про аварійний стан системи.

## 3. Змінні стану, інтроспекції та діагностики

Інтерпретатор Bash підтримує розширений набір внутрішніх змінних, що дозволяють здійснювати інтроспекцію стану процесу, стека викликів та кодів завершення дочірніх програм.

| Змінна | Тип | Опис та механізм оновлення |
| :--- | :--- | :--- |
| `$?` | Ціле (`0..255`) | Код повернення останньої виконаної команди, функції або конвеєра. |
| `PIPESTATUS` | Індексований масив | Масив (Bash), що містить коди завершення всіх процесів останнього виконаного конвеєра переднього плану. У Zsh еквівалентом є масив `$pipestatus`. |
| `IFS` | Рядок | Внутрішній роздільник полів (Internal Field Separator). Визначає символи для поділу на слова під час розгортання та роботи команди `read`. За замовчуванням: `$' \t\n'`. |
| `BASH_COMMAND` | Рядок | Текст команди, яка виконується в поточний момент або викликала спрацювання пастки `trap ... DEBUG` / `trap ... ERR`. |
| `BASH_SOURCE` | Індексований масив | Стек імен файлів вихідного коду, починаючи від поточного виконання (`[0]`) до кореневого файлу скрипту. |
| `BASH_LINENO` | Індексований масив | Стек номерів рядків у вихідних файлах, де відбувалися виклики функцій. `BASH_LINENO[0]` вказує на рядок виклику поточної функції. |
| `FUNCNAME` | Індексований масив | Стек імен функцій у поточному стеку викликів. `FUNCNAME[0]` — назва поточної функції, `FUNCNAME[1]` — ім'я функції, яка її викликала. |
| `LINENO` | Ціле число | Номер поточного рядка в активному сценарії чи функції. |
| `$$` | Ціле число | Ідентифікатор процесу (PID) основного процесу інтерпретатора. Зберігає значення навіть усередині підоболонок. |
| `$BASHPID` | Ціле число | Фактичний ідентифікатор процесу поточного екземпляра оболонки. На відміну від `$$`, оновлюється під час виклику `fork()` усередині subshell. |
| `$!` | Ціле число | Ідентифікатор процесу (PID) останньої команди, запущеної у фоновому режимі (`&`). |

### Механіка оновлення масиву `PIPESTATUS`

Усередині ядра інтерпретатора під час виконання конвеєра `cmd1 | cmd2 | cmd3` процес батьківської оболонки реєструє таблицю дочірніх завдань. Для кожного дочірнього процесу зберігається його системний дескриптор процесу (PID). Коли конвеєр переходить у стан очікування, оболонка викликає системний виклик `waitpid(-1, &status, 0)` у циклі, доки всі процеси групи конвеєра не завершать роботу.

Отримані макросом `WEXITSTATUS(status)` коди повернення записуються в індексований масив `PIPESTATUS` у строгому порядку зліва направо: `PIPESTATUS[0]` відповідає першій команді конвеєра, а `PIPESTATUS[N-1]` — останній. При увімкненому прапорці `set -o pipefail` інтерпретатор сканує цей масив справа наліво і повертає перший знайдений ненульовий елемент як підсумковий статус `$?`.

## 4. Матриця розгортання параметрів за умов `set -u` (nounset)

За увімкненого прапорця `set -u` пряме звернення до неініціалізованої змінної спричиняє фатальну помилку інтерпретатора. Таблиця демонструє поведінку безпечних конструкцій розгортання за різних початкових станів змінної.

| Синтаксична конструкція | Стан: Не встановлена (`unset var`) | Стан: Встановлена як порожня (`var=""`) | Стан: Встановлена зі значенням (`var="abc"`) |
| :--- | :--- | :--- | :--- |
| `${var:-default}` | `default` (Помилки немає) | `default` | `abc` |
| `${var-default}` | `default` (Помилки немає) | `""` (Порожній рядок) | `abc` |
| `${var:=default}` | Присвоює `var="default"`, повертає `default` | Присвоює `var="default"`, повертає `default` | `abc` |
| `${var=default}` | Присвоює `var="default"`, повертає `default` | `""` (Не змінює `var`) | `abc` |
| `${var:?error_msg}` | **Фатальна помилка:** друкує `error_msg` і виходить | **Фатальна помилка:** друкує `error_msg` і виходить | `abc` |
| `${var?error_msg}` | **Фатальна помилка:** друкує `error_msg` і виходить | `""` (Помилки немає) | `abc` |
| `${var:+alternate}` | `""` (Порожній рядок) | `""` (Порожній рядок) | `alternate` |
| `${var+alternate}` | `""` (Порожній рядок) | `alternate` | `alternate` |
| `${#var}` | **Фатальна помилка під `set -u`** | `0` | `3` |
| `${var:-}` | `""` (Безпечний порожній рядок) | `""` | `abc` |

### Практичне застосування операторів заміщення

Оператори з двокрапкою (`:-`, `:=`, `:?`, `:+`) перевіряють, чи змінна встановлена **І** чи є вона непорожньою (Non-null). Оператори без двокрапки (`-`, `=`, `?`, `+`) перевіряють виключно факт існування змінної (Set/Unset), ігноруючи те, що вона містить порожній рядок `""`.

* Конструкція `${1:-}` є канонічним засобом безпечного читання необов'язкових позиційних параметрів, що дозволяє уникнути аварійного падіння скрипту за відсутності переданих аргументів.
* Конструкція `${CONFIG_FILE:?Вкажіть шлях до файлу конфігурації}` дозволяє позбутися громіздких перевірок `if [[ -z "${CONFIG_FILE}" ]]` на початку сценарію, автоматично генеруючи зрозуміле повідомлення про помилку в потік `stderr` та завершуючи процес з ненульовим статусом.

## 5. Системні коди завершення та розрахунок статусів сигналів

Згідно зі специфікацією POSIX та угодами GNU, числовий статус завершення процесу є 8-бітним цілим числом без знака у діапазоні `0..255`. Якщо процес завершився добровільно через системний виклик `exit(n)`, статус формується молодшими 8 бітами значення `n`.

Якщо процес був аварійно знищений операційною системою через отримання системного сигналу POSIX, інтерпретатор обчислює підсумковий статус за канонічною формулою:

```
Код завершення процесу = 128 + Номер сигналу POSIX
```

| Код завершення | Стандартне значення / Джерело | Типовий сценарій виникнення |
| :--- | :--- | :--- |
| `0` | `EXIT_SUCCESS` | Успішне завершення програми. |
| `1` | `EXIT_FAILURE` | Загальна помилка виконання, збій синтаксису, спрацювання `set -u`. |
| `2` | Невірне використання вбудованої команди | Помилка синтаксису у виклику `builtin` (наприклад, `read -Z`). |
| `126` | Команда не є виконуваною | Файл знайдено, але відсутні права на виконання (`chmod -x`) або невірний шебанг. |
| `127` | Команду не знайдено | Бінарний файл або утиліта відсутня в каталогах змінної `$PATH`. |
| `128` | Невалідний аргумент `exit` | Виклик `exit 3.14` або `exit out_of_range`. |
| `130` (`128 + 2`) | Перервано сигналом `SIGINT` | Користувач натиснув комбінацію `Ctrl+C`. |
| `137` (`128 + 9`) | Знищено сигналом `SIGKILL` | Примусове завершення ядром (Out-Of-Memory Killer) або командою `kill -9`. |
| `141` (`128 + 13`) | Знищено сигналом `SIGPIPE` | Запис у канал `pipe`, звідки зчитувач уже закрив свій кінець дескриптора (`head -n 1`). |
| `143` (`128 + 15`) | Завершено сигналом `SIGTERM` | Стандартний запит на коректне завершення від менеджера служб `systemd` або `kill`. |

## 6. Порівняльна таблиця поведінки оболонок (Cross-Shell Compatibility)

Поведінка захисних прапорців варіюється залежно від сімейства та реалізації командної оболонки:

* **GNU Bash (`/bin/bash`):** найповніша підтримка інтроспекції (`PIPESTATUS`, `shopt -s inherit_errexit`, `BASH_SOURCE`, `caller`, `set -E`). Суворий режим `set -euo pipefail` є стандартом де-факто для скриптів автоматизації Linux.
* **Debian Almquist Shell (`/bin/dash` / `/bin/sh` на Ubuntu/Debian):** мінімалістична POSIX-оболонка. Не підтримує масиви, не підтримує `pipefail`, не підтримує `shopt`, не підтримує `trap ... ERR`. Скрипти, розраховані на `/bin/sh`, мають спиратися виключно на `set -eu` та явну перевірку кодів виходу кожного конвеєра.
* **Z Shell (`/bin/zsh` на macOS):** підтримує суворий режим, використовує масив `$pipestatus` (усі масиви в Zsh за замовчуванням мають індексацію з 1, а не з 0), підтримує прапорці `ERR_EXIT`, `NO_UNSET`, `PIPE_FAIL`. Забезпечує високу сумісність із сучасними ідіомами безпеки.
* **MirBSD Korn Shell (`mksh` на Android/Alpine):** повністю реалізує `set -o pipefail` та базові прапорці POSIX. Підходить для вбудованих систем із жорсткими обмеженнями пам'яті.
