# 📋 Таблиця й інтерфейс dm-integrity

Це формальний бік цілі `integrity`: рядок таблиці, який приймає ядро, кожен необов'язковий параметр із його усталеним значенням, поля суперблока, у яких частина цих параметрів застигає назавжди, і команди `integritysetup`, що все це складають за вас. Довідка потрібна тому, що межа проходить не там, де здається: одні параметри міняються перезавантаженням таблиці на живому пристрої, інші вибрані раз і назавжди при форматуванні, а найголовніший — сам алгоритм — не записаний на носії ніде, і забути його означає втратити доступ до даних.

Усе нижче звірено з мейнлайновим кодом (`drivers/md/dm-integrity.c`), документацією ядра (`Documentation/admin-guide/device-mapper/dm-integrity.rst`) і джерелами cryptsetup (`src/integritysetup.c`, `lib/integrity/integrity.c`, `man/integritysetup.8.adoc`).

## 1. Рядок таблиці

Загальну граматику рядка — «початок, довжина, ім'я цілі, аргументи», хвіст із лічильника опцій, числову форму імені пристрою — описано окремо: [таблиця, команди й керуючий канал device mapper](root:sys-unix/device-mapper). Аргументна частина `integrity` така:

```
<пристрій> <зарезервовані сектори> <розмір тега> <режим> <к-сть опцій> [опція …]
```

| поле | значення |
| --- | --- |
| `<пристрій>` | носій під даними; шлях або пара `старший:молодший` |
| `<зарезервовані сектори>` | скільки секторів на початку ціль не чіпає взагалі. Місце під чужі метадані — саме сюди LUKS2 кладе свій заголовок. Для окремого пристрою — `0` |
| `<розмір тега>` | скільки байтів на блок під тег, до `255` (`MAX_TAG_SIZE`). `-` означає «взяти з `internal_hash`»: сума виходить повної довжини алгоритму |
| `<режим>` | одна літера — `D`, `J`, `B`, `R` або `I` |
| `<к-сть опцій>` | скільки слів іде далі. Кожна опція — одне слово виду `ключ:значення` або самотній прапорець |

Літери режиму:

| режим | що робить | обмеження |
| --- | --- | --- |
| `J` | журнальний запис: дані й тег ідуть у журнал, комітяться, аж потім лягають на місця | усталений; кожен байт пишеться двічі |
| `D` | прямий запис: дані й тег окремо, без синхронізації між ними | після аварії пара може розійтися назавжди |
| `B` | бітова мапа брудних ділянок замість журналу | лише разом з `internal_hash`; з ядра 5.2 |
| `R` | режим відновлення: журнал не програється, теги не перевіряються, запис заборонено | спосіб дістати дані з пристрою, який не піднімається |
| `I` | теги лягають прямо в апаратні поля цілісності секторів носія | носій мусить мати профіль цілісності; з ядра 6.11 |

## 2. Необов'язкові параметри

| параметр | усталене | коли діє |
| --- | --- | --- |
| `journal_sectors:<N>` | з обсягу пристрою (у коді — `DEFAULT_JOURNAL_SIZE_FACTOR` = 7, тобто зсув на сім бітів — 1/128), стеля `DEFAULT_MAX_JOURNAL_SECTORS` = 131072 сектори (64 МіБ) на 64-бітних ядрах і 8192 (4 МіБ) на 32-бітних | форматування |
| `interleave_sectors:<N>` | `32768` (16 МіБ); округлюється вниз до степеня двійки, log2 у межах 3…31 | форматування |
| `block_size:<N>` | `512`; дозволені 512, 1024, 2048, 4096 | форматування |
| `meta_device:<пристрій>` | немає — теги чергуються з даними на тому самому носії | форматування |
| `sectors_per_bit:<N>` | `32768` (`DEFAULT_SECTORS_PER_BITMAP_BIT`); степінь двійки | форматування, режим `B` |
| `journal_mac:<алг>(:<ключ>)` | немає | форматування |
| `fix_padding` | вимкнено — тобто під теги береться зайво велике вирівнювання, залишене заради сумісності зі старими ядрами; прапорець вмикає ощадливе | форматування |
| `fix_hmac` | вимкнено | форматування |
| `internal_hash:<алг>(:<ключ>)` | немає — тоді теги приймаються згори | щоразу в таблиці |
| `journal_crypt:<алг>(:<ключ>)` | немає | щоразу в таблиці |
| `buffer_sectors:<N>` | `128`; округлюється вниз до степеня двійки | перезавантаження таблиці |
| `journal_watermark:<%>` | `50` — по досягненні заповнення журналу прокидається потік скидання | перезавантаження таблиці |
| `commit_time:<мс>` | `10000` — за цей час журнал комітять без сторонніх причин | перезавантаження таблиці |
| `bitmap_flush_interval:<мс>` | `10000` (`BITMAP_FLUSH_INTERVAL` = 10 · HZ) | перезавантаження таблиці |
| `recalculate` | вимкнено; лише з `internal_hash` | перезавантаження таблиці |
| `legacy_recalculate` | вимкнено | перезавантаження таблиці |
| `allow_discards` | вимкнено; лише з `internal_hash`, з ядра 5.7 | перезавантаження таблиці |

Імена алгоритмів у трьох параметрах — це імена трансформацій [криптопідсистеми ядра](root:sys-unix/kernel-crypto-api), тобто той самий рядок, що його очікує `crypto_alloc_*`: `crc32c`, `sha256`, `hmac(sha256)`, `cbc(aes)`, `chacha20`. Ключ дописують після другої двокрапки шістнадцятковим рядком — і він лежить у таблиці відкритим текстом, як і в `dm-crypt`.

Три параметри варто прочитати уважніше, ніж рядок таблиці.

**`fix_hmac`** робить три речі одразу: домішує до згортки номер секції журналу (щоб не можна було перекласти сектори з однієї секції в іншу), накриває `journal_mac`'ом сам суперблок і домішує 16-байтову сіль із суперблока — щоб не було видно, що два диски мають однаковий ключ, і щоб сектор не переносився з диска на диск.

**`legacy_recalculate`** знімає заборону перераховувати том із HMAC-ключем, а сама заборона стоїть не з обережності, а через конкретну атаку: зловмисник змінює дані, ставить `recalc_sector` у нуль — і ядро підпише його зміни справжнім ключем, нічого не помітивши.

**`allow_discards`** без `internal_hash` не має сенсу взагалі: [discard](root:sf-data/discard-and-trim) лишає на місці невизначений вміст, і тег, отриманий згори, після нього завідомо не збігатиметься.

## 3. Що застигає при форматуванні

Ядро не вірить рядкові таблиці на слово. Прочитавши суперблок, воно звіряє з ним подані аргументи й відмовляється підніматися при розбіжності — `Invalid tag size`, `Invalid block size`, `Invalid interleave`, `Journal mac mismatch`. `journal_sectors` та `interleave_sectors` при цьому просто ігноруються, якщо пристрій уже відформатовано: значення беруть із суперблока.

Але звірити можна лише те, що на носії записано. Розмір тега там є — а імені алгоритму немає. Тому суперблок однаково приймає `crc32c` і будь-який інший чотирибайтовий тег, і хибний `internal_hash` при відкритті дає не відмову, а пристрій, на якому кожне читання скаржиться на невідповідність. Звідси й формулювання довідки `integritysetup`: якщо алгоритм не усталений, його **треба** назвати при відкритті. Усталений — `crc32c` (`DEFAULT_ALG_NAME` у джерелах cryptsetup).

## 4. Мінімальний робочий виклик

```bash
# 4-байтовий crc32c, блок 4 КіБ, журнальний режим
integritysetup format /dev/sdb1 --integrity crc32c --tag-size 4 --sector-size 4096
integritysetup open   /dev/sdb1 idata --integrity crc32c

# те саме руками: довжину беруть НЕ з розділу, а з поля provided_data_sectors суперблока
SECT=$(integritysetup dump /dev/sdb1 | awk '/^provided_data_sectors/ {print $2}')
dmsetup create idata --table \
  "0 $SECT integrity /dev/sdb1 0 4 J 2 internal_hash:crc32c block_size:4096"
```

Довжина відрізка тут — це `provided_data_sectors` із суперблока, тобто вже за відрахуванням журналу й тегів. Подати розмір самого розділу означає дістати пристрій, який виходить за власні межі.

## 5. Суперблок

Перші 4 КіБ одразу за зарезервованими секторами. Зайнято 64 байти, решта — нулі.

| зсув | поле | тип | значення |
| --- | --- | --- | --- |
| 0 | `magic` | `u8[8]` | `"integrt"` |
| 8 | `version` | `u8` | 1…6 |
| 9 | `log2_interleave_sectors` | `u8` | 15 для усталених 32768 |
| 10 | `integrity_tag_size` | `le16` | байтів на блок |
| 12 | `journal_sections` | `le32` | скільки секцій у журналі |
| 16 | `provided_data_sectors` | `le64` | видима нагору довжина; коментар у коді: «userspace uses this value» |
| 24 | `flags` | `le32` | див. нижче |
| 28 | `log2_sectors_per_block` | `u8` | 0 для блока 512 Б, 3 для 4096 Б |
| 29 | `log2_blocks_per_bitmap_bit` | `u8` | зернистість бітової мапи |
| 32 | `recalc_sector` | `le64` | докуди дійшов фоновий перерахунок |
| 48 | `salt` | `u8[16]` | сіль для `fix_hmac` |

| прапорець | біт | що означає |
| --- | --- | --- |
| `SB_FLAG_HAVE_JOURNAL_MAC` | `0x01` | журнал накрито кодом автентичності |
| `SB_FLAG_RECALCULATING` | `0x02` | перерахунок незавершений, `recalc_sector` значущий |
| `SB_FLAG_DIRTY_BITMAP` | `0x04` | бітову мапу не очищено — вимкнення було неохайне |
| `SB_FLAG_FIXED_PADDING` | `0x08` | ощадливе вирівнювання тегової області |
| `SB_FLAG_FIXED_HMAC` | `0x10` | увімкнено посилення `fix_hmac` |
| `SB_FLAG_INLINE` | `0x20` | теги в апаратних полях носія |

`integritysetup dump <пристрій>` друкує саме ці поля під їхніми власними іменами, по одному на рядок: `superblock_version`, `log2_interleave_sectors`, `integrity_tag_size`, `journal_sections`, `provided_data_sectors` (завжди у 512-байтових одиницях, хоч би який був `--sector-size`), `sector_size`, `log2_blocks_per_bitmap` і `flags` — словами, а не числом. Команда читає носій, тому працює і на закритому пристрої.

## 6. Стан живого пристрою

```
dmsetup status idata
0 2088960 integrity <невідповідностей> <provided_data_sectors> <позиція перерахунку|->
```

Перше число — лічильник невідповідностей від часу відкриття; воно росте разом із рядками `Checksum failed at sector 0x…` у журналі ядра. Третє поле дорівнює `-`, якщо перерахунок не виконується.

`integritysetup status <ім'я>` показує те саме людською мовою, додаючи те, чого в `status` цілі немає, — режим і чинні параметри таблиці: `tag size`, `integrity`, `device`, `metadata device`, `sector size`, `interleave sectors`, `size`, `mode`, `failures`, а далі або `journal: not active`, або `journal size`, `journal watermark`, `journal commit time`, `journal integrity MAC`, `journal encryption`; у бітовому режимі натомість `bitmap 512-byte sectors per bit` і `bitmap flush interval`.

## 7. Команди integritysetup

| команда | що робить |
| --- | --- |
| `format <пристрій>` | рахує розкладку, пише суперблок і **затирає** пристрій, щоб теги стали правильними |
| `open <пристрій> <ім'я>` | складає рядок таблиці й заводить `/dev/mapper/<ім'я>` |
| `close <ім'я>` | знімає відображення (`--deferred` — до останнього користувача) |
| `status <ім'я>` | параметри чинної таблиці |
| `dump <пристрій>` | поля суперблока з носія |
| `resize <ім'я>` | міняє довжину живого відображення |

Відповідність прапорців полям таблиці:

| прапорець | поле таблиці |
| --- | --- |
| `--tag-size, -t` | третій позиційний аргумент |
| `--integrity, -I` + `--integrity-key-file`, `--integrity-key-size` | `internal_hash:<алг>(:<ключ>)` |
| `--sector-size, -s` | `block_size` |
| `--journal-size, -j` (байти) | `journal_sectors` (сектори) |
| `--interleave-sectors` | `interleave_sectors` |
| `--buffer-sectors` | `buffer_sectors` |
| `--journal-watermark` | `journal_watermark` |
| `--journal-commit-time` | `commit_time` |
| `--journal-integrity` + ключові файли | `journal_mac` |
| `--journal-crypt` + ключові файли | `journal_crypt` |
| `--integrity-no-journal, -D` | режим `D` |
| `--integrity-bitmap-mode, -B` | режим `B` |
| `--integrity-recovery-mode, -R` | режим `R` |
| `--integrity-inline` | режим `I` |
| `--bitmap-sectors-per-bit` | `sectors_per_bit` |
| `--bitmap-flush-time` | `bitmap_flush_interval` |
| `--integrity-recalculate` | `recalculate` |
| `--integrity-recalculate-reset` | `recalculate` зі скиданням `recalc_sector` у нуль (з ядра 5.13) |
| `--allow-discards` | `allow_discards` |
| `--no-wipe` | відповідника немає: пропускає затирання при `format`, і сектори лишаються з неправильними тегами, доки в них не запишуть |

Один прапорець міняє ролі аргументів, і це найлегше місце помилитися. У ядрі перший позиційний аргумент — це **пристрій даних**, а метадані виносить `meta_device:`. У `integritysetup` навпаки: `<пристрій>` у командному рядку стає носієм тегів і журналу, а дані живуть на тому, що названо в `--data-device`.

## 8. Стос із dm-crypt

```bash
cryptsetup luksFormat --type luks2 --integrity hmac-sha256 /dev/sdb1
```

Виходить два dm-пристрої один над одним: знизу `integrity`, що резервує місце під теги й тримає журнал, зверху [dm-crypt](root:sys-unix/dm-crypt), який шифрує й сам обчислює код автентичності. `internal_hash` у нижній цілі при цьому **порожній**: тег приходить згори готовим. Заголовок LUKS2 лягає в зарезервовані сектори. Довідка cryptsetup позначає цю можливість як експериментальну.

Дотичні прапорці: `--integrity-no-wipe` (той самий `--no-wipe`, з тим самим наслідком), `--integrity-no-journal` (режим `D`, «збій живлення може дати неатомарний запис і псування даних»), `--integrity-legacy-padding` (не ставити `fix_padding` — лише заради сумісності зі старим ядром), `--sector-size` (степінь двійки в межах 512…4096).
