# 📋 Параметри конфігурації SFTP і прапорці метаданих rsync

Ця довідка містить вичерпний опис конфігураційних директив підсистеми SFTP у `sshd_config`, параметрів ізоляції в `ChrootDirectory`, розширень протоколу OpenSSH SFTP, інтерактивних і пакетних команд клієнта `sftp`, констант протоколу SFTP v3 та повної матриці прапорців збереження метаданих і фільтрації утиліти `rsync`.

## Конфігурація підсистеми SFTP у sshd_config

Демон `sshd` надає два варіанти реалізації підсистеми передачі файлів: зовнішній бінарний обробник `sftp-server` або внутрішній модуль `internal-sftp`.

### Визначення підсистеми (Subsystem)

Директива `Subsystem` визначає ім'я підсистеми, яке клієнт запитує через канал SSH за допомогою повідомлення `SSH_MSG_CHANNEL_REQUEST` типу `subsystem`, та програму, яка оброблятиме запити.

```text
Subsystem sftp internal-sftp [параметри]
```

Вибір модуля `internal-sftp` має вирішальну перевагу над зовнішнім виконуваним файлом: він виконується безпосередньо в адресному просторі процесу `sshd` після автентифікації користувача. Це дозволяє уникнути виклику `execve()`, що робить можливим роботу в ізольованому каталозі без створення утиліт, бібліотек та пристроїв усередині jail.

Основні параметри запуску `internal-sftp`:

| Параметр | Призначення |
|---|---|
| `-f FACILITY` | Категорія системного журналу syslog (`AUTH`, `AUTHPRIV`, `LOCAL0`..`LOCAL7`, типово `AUTH`). Дозволяє винести події передачі файлів в окремий лог-файл за допомогою правил rsyslog або journald. |
| `-l LEVEL` | Рівень деталізації журналювання (`QUIET`, `FATAL`, `ERROR`, `INFO`, `VERBOSE`, `DEBUG`). Значення `VERBOSE` або `DEBUG` записує кожен запит на відкриття, читання, запис і видалення файлів із зазначенням шляху та байтового зміщення. |
| `-u UMASK` | Маска прав доступу за замовчуванням для новостворених файлів і каталогів (наприклад, `-u 0022` для файлів 0644 та каталогів 0755). Якщо параметр не вказано, застосовується системна маска umask облікового запису користувача. |
| `-d DIRECTORY` | Початковий робочий каталог користувача після автентифікації відносно chroot-кореня. Підтримує змінні підстановки `%u` (ім'я користувача) та `%h` (домашній каталог). Запобігає ситуації, коли клієнт опиняється в корені `/`, де запис заблокований. |
| `-R` | Режим «лише читання» (*read-only*). Забороняє будь-які операції модифікації файлової системи: запис, створення, перейменування, видалення та зміну атрибутів через `chmod`/`chown`. |
| `-P BLACKLIST` | Список заборонених команд або операцій протоколу SFTP через кому (наприклад, `open,symlink,setstat`). |

### Блок ізоляції користувача (Match Group / ChrootDirectory)

Для обмеження доступу користувачів без надання інтерактивної оболонки в конфігураційному файлі `/etc/ssh/sshd_config` створюється умовний блок `Match`:

```text
# Загальне визначення підсистеми
Subsystem sftp internal-sftp -l VERBOSE

# Блок обмеження для групи sftponly
Match Group sftponly
    ChrootDirectory /var/sftp/%u
    ForceCommand internal-sftp -u 0022
    AllowTcpForwarding no
    X11Forwarding no
    AllowAgentForwarding no
    AuthorizedKeysFile /etc/ssh/authorized_keys/%u
```

Механіка роботи директив умовної секції:
- `Match Group sftponly` — застосовує перелічені нижче директиви виключно до сеансів користувачів, які є членами групи `sftponly`.
- `ChrootDirectory /var/sftp/%u` — виконує системний виклик `chroot()` до вказаного каталогу перед тим, як передати керування підсистемі або оболонці. Змінна `%u` замінюється на ім'я користувача під час входу.
- `ForceCommand internal-sftp -u 0022` — ігнорує будь-яку команду, яку клієнт намагається передати в командному рядку SSH, і примусово запускає внутрішній обробник SFTP. Навіть якщо користувач спробує виконати `ssh user@host /bin/sh`, замість термінала запуститься бінарний обробник SFTP.
- `AllowTcpForwarding no` / `X11Forwarding no` / `AllowAgentForwarding no` — повністю вимикають прокидання мережевих TCP-портів, графічних X11-сеансів та ключів SSH-агента, перетворюючи сеанс виключно на точку передавання файлів.
- `AuthorizedKeysFile /etc/ssh/authorized_keys/%u` — виносить відкриті SSH-ключі за межі домашнього каталогу користувача у системний каталог `root`, запобігаючи модифікації ключів самим користувачем через SFTP.

Правила безпеки файлової системи для каталогу `ChrootDirectory`:
1. Кожен каталог у повному шляху до точки монтування chroot (у наведеному прикладі це `/`, `/var`, `/var/sftp` та `/var/sftp/%u`) повинен належати користувачеві `root:root`.
2. Жоден каталог у цьому ланцюгу не може мати прав доступу на запис для групи чи сторонніх користувачів (`chmod 0755` або `chmod 0750`).
3. Якщо хоча б один із батьківських каталогів має права `0777` або належить звичайному користувачеві, демон `sshd` заблокує вхід із фатальною помилкою в системному лозі.
4. Запис файлів організовується через створення вкладених підкаталогів (наприклад, `/var/sftp/%u/uploads`), де власником призначається користувач `%u:sftponly` з правами `0755` або `0775`.

## Команди клієнта sftp та пакетний режим

Клієнтська утиліта `sftp` надає командний рядок для інтерактивного керування файлами та підтримує пакетне виконання команд із текстових файлів.

### Інтерактивні команди

Кожна інтерактивна команда відповідає одному або кільком викликам бінарного протоколу SFTP.

| Команда | Опис і прапорці |
|---|---|
| `get [-a] [-f] [-p] [-r] remote [local]` | Завантаження файлу з сервера на локальну машину. Прапорець `-p` зберігає права доступу та час модифікації; `-r` рекурсивно викачує весь каталог; `-a` вмикає режим відновлення (*resume*), дописуючи дані в існуючий локальний файл; `-f` примусово скидає буфери на диск після запису. |
| `put [-a] [-f] [-p] [-r] local [remote]` | Вивантаження локального файлу або каталогу на сервер із можливістю збереження прав (`-p`), рекурсії (`-r`) та відновлення (`-a`). |
| `reget remote [local]` | Явне відновлення перерваного завантаження файлу: клієнт визначає поточний розмір локального файлу і надсилає запити читання, починаючи з цього зміщення. |
| `reput local [remote]` | Явне відновлення перерваного вивантаження: клієнт запитує атрибути віддаленого файлу через `SSH_FXP_STAT` і продовжує передачу байтів зі зміщення кінця віддаленого файлу. |
| `ls [-1] [-a] [-l] [-S] [-t] [path]` | Перегляд списку файлів на віддаленому сервері. Прапорець `-l` показує розширені метадані (права, розмір, mtime); `-t` сортує за часом зміни; `-S` сортує за розміром. |
| `lls [flags] [path]` | Перегляд списку файлів у поточному локальному каталозі клієнта без надсилання мережевих пакетів до сервера. |
| `cd path` / `lcd path` | Зміна поточного робочого каталогу на віддаленій (`cd`) або локальній (`lcd`) машині. |
| `pwd` / `lpwd` | Друк абсолютного шляху поточного робочого каталогу на віддаленій (`pwd`) або локальній (`lpwd`) машині. |
| `mkdir path` / `lmkdir path` | Створення нового каталогу на віддаленому сервері (`SSH_FXP_MKDIR`) або локально. |
| `rm path` / `rmdir path` | Видалення віддаленого файлу (`SSH_FXP_REMOVE`) або порожнього каталогу (`SSH_FXP_RMDIR`). |
| `chmod mode path` | Зміна вісімкових бітів прав доступу на віддаленому об'єкті (`SSH_FXP_SETSTAT`). |
| `chown uid path` / `chgrp gid path` | Зміна числового ідентифікатора власника або групи віддаленого файлу. |
| `df [-h] [path]` | Друк статистики про вільний та зайнятий дисковий простір віддаленої файлової системи (використовує розширення протоколу `statvfs@openssh.com`). |
| `lumask umask` | Встановлення локальної маски прав створення файлів для поточного сеансу клієнта. |
| `ln [-s] target linkpath` | Створення жорсткого посилання (`SSH_FXP_LINK`) або символьного посилання (`-s`, `SSH_FXP_SYMLINK`) на віддаленому сервері. |
| `bye` / `exit` / `quit` | Надсилання запиту закриття сеансу та коректне розірвання з'єднання SSH. |

### Пакетний режим (Batch Mode)

Пакетний режим дозволяє виконувати заздалегідь підготовлені послідовності команд без участі оператора.

Запуск сценарію:

```bash
sftp -b /path/to/batchfile.txt -i /path/to/id_ed25519 user@backup-server.local
```

Особливості обробки помилок у пакетному режимі:
- За замовчуванням у режимі `-b` будь-яка помилка виконання команди (наприклад, помилка `SSH_FX_NO_SUCH_FILE` при спробі завантажити неіснуючий файл) призводить до негайного переривання сеансу з ненульовим кодом завершення процесу. Це гарантує, що автоматизований конвеєр не продовжить роботу, якщо проміжний етап не вдався.
- Прапорець `-B batchfile` змінює поведінку на толерантну до збоїв: клієнт фіксує помилку в stderr, але продовжує виконувати наступні рядки файлу.
- Для вибіркового ігнорування помилок окремих рядків у суворому режимі `-b` використовується префікс `-` перед назвою команди (наприклад, `-mkdir temp`). Якщо вказаний каталог уже існує, помилка буде проігнорована, а наступні команди продовжать виконуватися.

Зразок виробничого пакетного файлу `deploy.sftp`:

```text
# Створення цільової версійної директорії (ігнорувати помилку, якщо існує)
-mkdir releases/v2.4.1
cd releases/v2.4.1

# Вивантаження бінарних файлів зі збереженням прав і міток часу
put -p bin/app-server
put -p config/production.yaml

# Оновлення символьного посилання через тимчасовий об'єкт
-rm current_new
symlink releases/v2.4.1 current_new
rename current_new current

# Перевірка вільного дискового простору та вихід
df -h
quit
```

## Типи повідомлень та розширення OpenSSH протоколу SFTP

Протокол SFTP версії 3 (стандартний для OpenSSH) оперує дискретними повідомленнями, кожне з яких має фіксовану структуру заголовка: 4 байти довжини, 1 байт типу команди та 4 байти ідентифікатора запиту.

### Коди базових операцій протоколу (Packet Types)

| Тип | Назва | Призначення |
|---|---|---|
| 1 | `SSH_FXP_INIT` | Початкове повідомлення від клієнта для узгодження підтримуваної версії протоколу. |
| 2 | `SSH_FXP_VERSION` | Відповідь сервера з підтвердженням версії протоколу та списком підтримуваних розширень вендора. |
| 3 | `SSH_FXP_OPEN` | Запит на відкриття або створення файлу з вказанням прапорців доступу (`SSH_FXF_READ`, `SSH_FXF_WRITE`, `SSH_FXF_CREAT`, `SSH_FXF_TRUNC`, `SSH_FXF_EXCL`). Повертає `SSH_FXP_HANDLE`. |
| 4 | `SSH_FXP_CLOSE` | Закриття файлового дескриптора або дескриптора відкритого каталогу. |
| 5 | `SSH_FXP_READ` | Читання блоку даних за точним 64-бітним зміщенням (offset) і запитаною довжиною (length). Повертає `SSH_FXP_DATA` або `SSH_FXP_STATUS` з кодом `EOF`. |
| 6 | `SSH_FXP_WRITE` | Запис масиву байтів за точним 64-бітним зміщенням (offset). Повертає `SSH_FXP_STATUS`. |
| 7 | `SSH_FXP_LSTAT` | Отримання метаданих файлу без переходу за символьним посиланням. |
| 8 | `SSH_FXP_FSTAT` | Отримання метаданих за відкритим дескриптором файлу. |
| 9 | `SSH_FXP_SETSTAT` | Зміна прав доступу, власника, розміру або міток часу файлу за вказаним шляхом. |
| 10 | `SSH_FXP_FSETSTAT`| Зміна атрибутів за відкритим файловим дескриптором. |
| 11 | `SSH_FXP_OPENDIR` | Відкриття каталогу для послідовного читання списку файлів (повертає дескриптор каталогу). |
| 12 | `SSH_FXP_READDIR` | Читання порції записів каталогу. Повертає `SSH_FXP_NAME` зі списком імен та їхніх атрибутів або `SSH_FX_EOF`, коли каталог вичерпано. |
| 13 | `SSH_FXP_REMOVE`  | Видалення файлу за шляхом. |
| 14 | `SSH_FXP_MKDIR`   | Створення нового каталогу з заданими початковими атрибутами. |
| 15 | `SSH_FXP_RMDIR`   | Видалення порожнього каталогу. |
| 16 | `SSH_FXP_REALPATH`| Розгортання відносного шляху або ланцюжка символьних посилань у канонічний абсолютний шлях на сервері. |
| 17 | `SSH_FXP_STAT`    | Отримання метаданих об'єкта з переходом за символьним посиланням. |
| 18 | `SSH_FXP_RENAME`  | Перейменування або переміщення файлу чи каталогу. |
| 19 | `SSH_FXP_READLINK`| Читання цільового шляху, на який вказує символьне посилання. |
| 20 | `SSH_FXP_SYMLINK` | Створення символьного посилання. |
| 101 | `SSH_FXP_STATUS` | Статус завершення операції (містить числовий код результату та повідомлення про помилку). |
| 102 | `SSH_FXP_HANDLE` | Повернення непрозорого масиву байтів, який ідентифікує відкритий файловий об'єкт. |
| 103 | `SSH_FXP_DATA`   | Повернення прочитаного блоку сирих байтів файлу. |
| 104 | `SSH_FXP_NAME`   | Повернення масиву записів каталогу з іменами та метаданими. |
| 105 | `SSH_FXP_ATTRS`  | Повернення бінарної структури атрибутів файлу (розмір, uid, gid, permissions, atime, mtime). |
| 200 | `SSH_FXP_EXTENDED`| Виклик нестандартного розширення протоколу від вендора. |

### Розширення OpenSSH для SFTP

Оскільки офіційний стандарт SFTP v3 не мав багатьох необхідних викликів POSIX, розробники OpenSSH додали власні розширення через повідомлення `SSH_FXP_EXTENDED`:

- `statvfs@openssh.com` та `fstatvfs@openssh.com` — запитують інформацію про файлову систему (розмір блоку, кількість вільних і загальних блоків, ліміти inode), що дозволяє утиліті `sftp` реалізовувати команду `df`.
- `hardlink@openssh.com` — створює жорстке посилання на сервері безпосередньо через системний виклик `link()`.
- `fsync@openssh.com` — примусово синхронізує відкритий файловий дескриптор на фізичний накопичувач сервера через виклик `fsync()`, гарантуючи стійкість запису при раптовому вимкненні живлення.
- `lsetstat@openssh.com` — дозволяє змінювати атрибути самого символьного посилання, а не об'єкта, на який воно вказує.
- `limits@openssh.com` — повертає клієнту максимальні розміри буферів для пакетів читання й запису (наприклад, ліміт 256 КБ на один пакет), дозволяючи клієнту оптимізувати розмір запитів.

### Статус-коди результату операції (Status Codes)

Повідомлення `SSH_FXP_STATUS` містить 32-бітний беззнаковий код помилки, який відображає результат системного виклику:

| Код | Назва | Значення |
|---|---|---|
| 0 | `SSH_FX_OK` | Операцію успішно виконано без помилок. |
| 1 | `SSH_FX_EOF` | Досягнуто кінця файлу при читанні або завершено перелік записів каталогу. |
| 2 | `SSH_FX_NO_SUCH_FILE` | Файл або каталог за вказаним шляхом не існує (системна помилка `ENOENT`). |
| 3 | `SSH_FX_PERMISSION_DENIED` | Недостатньо прав для виконання операції (системні помилки `EACCES` або `EPERM`). |
| 4 | `SSH_FX_FAILURE` | Неспецифікована помилка операційної системи або файлової підсистеми. |
| 5 | `SSH_FX_BAD_MESSAGE` | Отримано пошкоджений пакет протоколу або невідомий тип повідомлення. |
| 6 | `SSH_FX_NO_CONNECTION` | Клієнт намагається відправити запит без встановленого з'єднання з підсистемою. |
| 7 | `SSH_FX_CONNECTION_LOST` | З'єднання з віддаленою підсистемою було несподівано розірвано під час передачі. |
| 8 | `SSH_FX_OP_UNSUPPORTED` | Запитана операція або прапорець не підтримується поточною версією сервера SFTP. |

## Матриця прапорців метаданих, фільтрації та оптимізації rsync

Утиліта `rsync` надає широкий набір параметрів командного рядка для керування збереженням структури файлової системи, дельта-алгоритмом, фільтрацією та транспортом.

### Режим архівування `-a` (`--archive`)

Прапорець `-a` є комплексним макросом, що об'єднує сім обов'язкових прапорців збереження структури:

```text
-a  ===  -r -l -p -t -g -o -D
```

| Прапорець | Довга форма | Збережений атрибут файлової системи |
|---|---|---|
| `-r` | `--recursive` | Рекурсивний обхід усіх вкладених підкаталогів. Без цього прапорця rsync обробляє лише файли у корені вказаного каталогу, ігноруючи підпапки. |
| `-l` | `--links` | Копіювання символьних посилань як симлінків. Симлінк відтворюється на цільовій машині у вигляді посилання на той самий шлях без розіменування та копіювання цільового файлу. |
| `-p` | `--perms` | Збереження стандартних вісімкових бітів прав доступу POSIX (права читання, запису та виконання для власника, групи та інших). |
| `-t` | `--times` | Збереження точної мітки часу модифікації файлу (mtime). Це ключовий прапорець оптимізації: rsync за замовчуванням визначає, чи змінився файл, порівнюючи його точний розмір та mtime. Якщо mtime не зберігати, кожне наступне сканування вважатиме всі файли зміненими. |
| `-g` | `--group` | Збереження групи-власника файлу (GID). За замовчуванням rsync намагається зіставити текстове ім'я групи на цільовій системі. |
| `-o` | `--owner` | Збереження користувача-власника файлу (UID). Працює лише за умови запуску процесу rsync від імені суперкористувача (`root`) на цільовому хості. |
| `-D` | `--devices --specials` | Збереження файлів спеціальних пристроїв: блокових і символьних пристроїв (`--devices`, вимагає привілеїв суперкористувача) та каналів FIFO і UNIX-сокетів (`--specials`). |

### Розширені метадані (поза складом `-a`)

Для створення точних копій операційної системи прапорця `-a` недостатньо, оскільки він не переносить жорсткі посилання, розширені атрибути та списки ACL.

| Прапорець | Довга форма | Призначення |
|---|---|---|
| `-H` | `--hard-links` | Збереження структури жорстких посилань. Rsync сканує файлову систему, фіксує номери `(device, inode)` і відтворює жорсткі посилання на цілі замість створення дублікатів файлів. Вимагає додаткової оперативної пам'яті для зберігання таблиці inode. |
| `-A` | `--acls` | Збереження списків контролю доступу (POSIX ACL). Автоматично вмикає збереження стандартних прав доступу (`-p`). |
| `-X` | `--xattrs` | Збереження розширених атрибутів файлової системи (xattr), зокрема контекстів безпеки систем примусового контролю доступу SELinux/AppArmor та призначених для користувача метаданих `user.*`. |
| `--numeric-ids` | `--numeric-ids` | Передача та збереження числових ідентифікаторів UID та GID без перекладу в текстові імена через системну службу NSS на віддаленій системі. Це запобігає спотворенню прав доступу, якщо один і той самий числовий UID на різних машинах належить різним обліковим записам. |

### Правила фільтрації та виключення файлів

Rsync підтримує гнучкі правила ігнорування та включення файлів за допомогою прапорців `--exclude`, `--include` та `--filter`:

- `--exclude='*.tmp'` — виключає всі файли з розширенням `.tmp`.
- `--exclude-from=/path/to/rules.txt` — завантажує список шаблонів виключення з текстового файлу.
- `--filter='- .git/'` — правило виключення каталогу версійного контролю.
- `--filter='+ *.c'` та `--filter='- *'` — патерн білого списку: включає лише файли з розширенням `.c`, ігноруючи всі інші об'єкти.

Правила застосовуються послідовно зверху вниз до першого збігу. Якщо жодне правило не спрацювало, файл включається до списку передачі.

### Контроль дельта-алгоритму та надійності

| Прапорець | Довга форма | Опис механізму |
|---|---|---|
| `-z` | `--compress` | Стиснення блоків дельти на льоту за алгоритмом zlib (або zstd у нових версіях). Зменшує мережевий трафік на повільних каналах, але збільшує навантаження на процесор. |
| `--inplace` | `--inplace` | Оновлення цільового файлу безпосередньо за місцем без створення проміжного тимчасового файлу `.file.XXXXXX`. Економить дисковий простір при роботі з гігантськими файлами (наприклад, образами дисків VM), але робить оновлення неатомарним: у разі збою файл залишиться у пошкодженому стані. |
| `--partial` | `--partial` | Збереження частково переданого файлу в разі обриву мережі, що дозволяє продовжити передачу з місця розриву при наступному запуску команди. |
| `--partial-dir=DIR` | `--partial-dir=DIR` | Збереження незавершених файлів у спеціальному прихованому каталозі замість цільового розташування, запобігаючи використанню напівзаписаних файлів іншими службами. |
| `--delay-updates` | `--delay-updates` | Усі змінені файли спочатку збираються у приховані тимчасові файли, а наприкінці сеансу синхронізації одночасно перейменовуються. Забезпечує атомарність оновлення всього каталогу. |
| `--delete` | `--delete` | Видалення файлів на цільовому боці, яких більше немає у джерельному каталозі, забезпечуючи точне дзеркальне відображення. |
| `--delete-after` | `--delete-after` | Видалення застарілих файлів на цілі лише після повного завершення успішного передавання всіх нових файлів, мінімізуючи час недоступності сервісу. |
| `--checksum` (`-c`) | `--checksum` | Порівняння файлів за криптографічним хешем (MD5 / xxHash) замість швидкої перевірки за розміром та mtime. Спричиняє високе навантаження на дискову підсистему джерела і цілі. |
| `--bwlimit=RATE` | `--bwlimit=RATE` | Обмеження швидкості передачі даних у кілобайтах на секунду (KiB/s) для запобігання перевантаженню загального каналу зв'язку. |
| `-e COMMAND` | `--rsh=COMMAND` | Вказання кастомного командного рядка для запуску захищеного транспорту (наприклад, `-e "ssh -p 2222 -c aes128-gcm@openssh.com -T -o Compression=no"`). |
