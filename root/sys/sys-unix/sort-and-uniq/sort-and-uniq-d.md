Спроба відсортувати 50-гігабайтний файл системних логів за допомогою наївного завантаження всіх рядків у пам'ять на машині з 8 ГБ RAM неминуче завершується аварійним знищенням процесу ядром через вичерпання віртуальної пам'яті (Out-Of-Memory killer). Ба більше, навіть якщо обсяг пам'яті достатній, просте виконання команди `sort access.log | uniq -c` у сучасному дистрибутиві Linux із локаллю за замовчуванням `en_US.UTF-8` працює в 5–10 разів повільніше, ніж очікується, а підрахунок унікальних значень дає хибні результати через те, що сортування за правилами UTF-8 коллації ігнорує пунктуацію та вважає різні послідовності байтів еквівалентними.

Утиліти `sort` та `uniq` є фундаментальними будівельними блоками обробки даних у Unix-подібних операційних системах. Їхня ефективність і коректність тримаються на трьох інженерних стовпах: алгоритмі зовнішнього сортування злиттям (External Merge Sort), математично строгій системі виділення ключів порівняння та низькорівневому розумінні того, як змінні середовища `LC_ALL` і `LC_COLLATE` перемикають системні виклики порівняння між важким мовним аналізом `strcoll()` та апаратним побайтовим скануванням `memcmp()`.

## 1. Алгоритмічна основа sort: зовнішнє сортування злиттям

Більшість класичних алгоритмів внутрішнього сортування (Quicksort, Heapsort, Timsort) проектуються в розрахунку на прямий довільний доступ до оперативної пам'яті. Усі елементи масиву покажчиків мають одночасно розміщуватися в адресному просторі процесу, а алгоритм довільно стрибає між індексами для розбиття на підмасиви. Якщо розмір масиву значно перевищує фізичну пам'ять, кожне таке звернення викликає промах сторінки пам'яті (page fault), підкачування блоків із повільного дискового swap-розділу (thrashing) і повну деградацію системи.

Утиліта GNU `sort` розв'язує цю задачу на рівні операційної системи, реалізуючи алгоритм **зовнішнього сортування злиттям (External Merge Sort)**. Процес впорядкування даних довільного обсягу розбивається на дві ізольовані фази: фазу генерації локально відсортованих блоків (серій) та фазу багатовходового k-way злиття.

![Зовнішнє сортування злиттям](/root/sys/sys-unix/sort-and-uniq/img/external-merge-sort.svg)
*Зовнішнє сортування злиттям: фаза розбиття на блоки (runs) у межах RAM та багатовходове k-way злиття з тимчасових файлів на диску.*

### Фаза 1: Генерація відсортованих серій (Run Generation)

Процес зчитує вхідний потік байтів (із файлу або каналу `stdin`) послідовними порціями, розмір яких не перевищує ліміт виділеного буфера оперативної пам'яті. Цей ліміт визначається параметром `-S` або `--buffer-size`:

```bash
# Виділення 2 ГБ оперативної пам'яті під буфер внутрішнього сортування
sort -S 2G large_access.log -o sorted_access.log
```

Коли буфер пам'яті заповнюється, `sort` виконує внутрішнє сортування завантаженого блоку (застосовуючи паралельний Quicksort або Mergesort) і скидає впорядковані рядки у тимчасовий файл на диску. Такий локально відсортований блок називається **серією** (run). Після скидання буфер пам'яті повністю очищається, і процес повертається до зчитування наступної порції вхідного потоку.

У результаті першої фази вхідний файл розміром 50 ГБ при буфері пам'яті 2 ГБ перетворюється на 25 локально відсортованих тимчасових файлів на файловій системі.

### Фаза 2: K-входове злиття (K-Way Merge)

На другому етапі `sort` відкриває всі 25 тимчасових файлів одночасно. Щоб об'єднати їх у єдиний глобально впорядкований вихідний потік без повторного завантаження всього масиву в пам'ять, утиліта створює структуру даних **мін-купа (min-heap)** або **турнірне дерево вибування (loser tree)** розміром `K = 25`.

1. З кожного з `K` тимчасових файлів зчитується його перший (найменший) рядок і поміщається у вершину купи.
2. Алгоритм витягує абсолютний мінімум із вершини купи за час `O(log K)` і записує його у вихідний потік `stdout` або цільовий файл.
3. З того файлу, з якого було взято цей мінімальний елемент, зчитується наступний рядок і додається до купи.
4. Процес повторюється до повного вичерпання всіх `K` тимчасових файлів.

Детальний аналіз алгоритмічної складності, I/O-передач і формул моделі Аґґарвала–Віттера наведено у вставці [Математичний аналіз складності зовнішнього сортування](root:sys-unix/sort-and-uniq/math-external-sort-complexity.md). Повноцінну програмну реалізацію алгоритму мовами C та C++ розібрано у вставці [Реалізація зовнішнього сортування злиттям](root:sys-unix/sort-and-uniq/proj-external-sort.md).

### Керування каталогами скидання та пастка tmpfs

За замовчуванням GNU `sort` створює тимчасові файли серій у каталозі, визначеному змінною оточення `TMPDIR`, або у стандартному системному каталозі `/tmp`. 

У більшості сучасних дистрибутивів Linux каталог `/tmp` монтується як віртуальна файлова система в оперативній пам'яті (`tmpfs`). Якщо виконувати сортування 100-гігабайтного файлу на сервері з 32 ГБ RAM, скидання проміжних серій у `/tmp` миттєво вичерпає доступну пам'ять `tmpfs` і призведе до фатальної помилки:

```
sort: write failed: /tmp/sortXXXXXX: No space left on device
```

Для усунення цієї проблеми слід явно вказувати шлях до фізичного дискового сховища за допомогою прапорця `-T` або змінної оточення:

```bash
# Явне перенесення каталогу серій на NVMe-накопичувач
sort -T /var/scratch/tmp -S 4G big_access.log -o big_access.sorted.log

# Балансування дискового I/O між різними фізичними накопичувачами (round-robin)
sort -T /mnt/nvme1/tmp -T /mnt/nvme2/tmp -S 8G huge_data.txt
```

### Багаторівневе ієрархічне злиття (--batch-size)

Якщо розмір вхідного масиву становить 1 ТБ, а буфер пам'яті обмежено 100 МБ, кількість сформованих серій сягає 10 000 файлів. У стандартній конфігурації Linux максимальна кількість одночасно відкритих файлових дескрипторів одного процесу (`ulimit -n`) зазвичай становить 1024.

Спроба відкрити всі 10 000 файлів на початку другої фази неминуче призведе до помилки ядра `EMFILE (Too many open files)`. GNU `sort` автоматично вирішує цю проблему за допомогою **багаторівневого ієрархічного злиття (multi-pass merge)**. Параметр `--batch-size=N` задає максимальну кількість файлів, які зливаються за один прохід (за замовчуванням 32 або 16). Якщо серій більше, ніж `--batch-size`, `sort` спочатку об'єднує їх підгрупами у проміжні серії більшого розміру, і лише потім виконує фінальне злиття.

### Паралелізм виконання (--parallel)

Сучасний GNU `sort` автоматично визначає кількість доступних процесорних ядер (`nproc`) і масштабує роботу на декілька потоків виконання. Паралелізація застосовується як на фазі сортування блоків у RAM, так і під час побудови дерева злиття. Опція `--parallel=N` дозволяє жорстко обмежити кількість потоків, щоб уникнути блокування ресурсів спільного виробничого сервера:

```bash
# Обмеження навантаження чотирма робочими потоками
sort --parallel=4 -S 2G access.log
```

### Злиття попередньо відсортованих потоків (-m / --merge)

Коли дані надходять із кількох розподілених вузлів кластера або щоденних журналів, які вже впорядковані за часом, пересортовувати їх заново — це марна трата процесорного часу та I/O. Прапорець `-m` (`--merge`) змушує `sort` пропустити першу фазу і одразу запустити k-way злиття вхідних файлів через мін-купу:

```bash
# Швидке злиття логів за 7 днів без повторного внутрішнього сортування
sort -m -k1,1 -k2,2 logs_2026-08-*.log -o full_week_sorted.log
```

## 2. Синтаксис і механіка ключів -k (Key Specification)

За замовчуванням `sort` розглядає весь рядок від першого до останнього байта як єдиний ключ порівняння. Проте аналіз табличних записів, журналів web-серверів та виводу системних утиліт моніторингу потребує точного впорядкування за окремими полями.

![Синтаксис ключів sort -k](/root/sys/sys-unix/sort-and-uniq/img/sort-key-parsing.svg)
*Синтаксис специфікатора ключа: визначення меж полів, символьних зсувів та локальних модифікаторів порівняння.*

Специфікатор ключа в POSIX описується форматом:

```
-k POS1[,POS2]
```

де кожна позиція описується виразом `FIELD[.CHAR][FLAGS]`:
- `FIELD` — номер поля (позитивне ціле число, починаючи з 1).
- `CHAR` — номер символу всередині поля (починаючи з 1). Якщо опущено, для `POS1` береться початок поля, а для `POS2` — його останній символ.
- `FLAGS` — локальні прапорці модифікації порівняння (`n`, `r`, `b`, `f`, `h`, `V`), що діють виключно на цей ключ.

### Головна пастка синтаксису: -k2 проти -k2,2

Найпоширенішою помилкою інженерів під час роботи з утилітою `sort` є запис виду `sort -k2`.

Якщо кінцеву позицію `POS2` опущено, стандарт POSIX вимагає вважати ключем фрагмент **від початку поля POS1 до самого кінця рядка**:

```bash
# Вхідний файл requests.txt:
# 2026-08-25 500 GET
# 2026-08-25 200 POST
# 2026-08-25 200 DELETE

# ПОМИЛКОВИЙ ВИКЛИК:
sort -k2n requests.txt
```

У наведеному прикладі `sort` виділяє як ключ весь залишок рядка: `"500 GET"`, `"200 POST"` та `"200 DELETE"`. Числовий парсер `-n` успішно зчитає число 200 для другого і третього записів. Оскільки числові значення рівні, алгоритм продовжить текстове порівняння наступних символів ключа (`" POST"` проти `" DELETE"`), що призведе до неочікуваної зміни порядку рядків!

Щоб ізолювати сортування суворо за другим стовпцем, необхідно явно вказати межу завершення ключа:

```bash
# ПРАВИЛЬНИЙ ВИКЛИК: ключ обмежено другим полем
sort -k2,2n requests.txt
```

### Розділювачі полів (-t) та пробільні пастки

За замовчуванням роздільником полів у `sort` є перехід від непробільного символу до пробільного. Це створює важливий підводний камінь: послідовність кількох пробілів вважається одним роздільником, але самі пробіли вважаються префіксом наступного поля!

Розглянемо вирівняні текстові дані:

```
сервер1    100
сервер2     20
```

Якщо роздільник явно не вказано, першим символом другого поля першого рядка буде пробіл, а другого рядка — два пробіли. Під час текстового лексикографічного порівняння код ASCII пробілу (`0x20`) менший за будь-яку цифру, що спотворює алфавітне впорядкування.

Для розв'язання цієї проблеми застосовують:
1. Модифікатор `-b` (`--ignore-leading-blanks`), який змушує утиліту пропускати пробіли на початку поля: `sort -k2,2b`.
2. Явне задання символу-роздільника через параметр `-t`:

```bash
# Сортування файлу облікових записів /etc/passwd за третім полем (UID) як числом
sort -t: -k3,3n /etc/passwd

# Сортування TSV-файлу (символ табуляції як роздільник)
sort -t$'\t' -k1,1 -k2,2n data.tsv
```

### Внутрішньопольові зміщення символів

Коли стовпці файлу містять складні складені ідентифікатори (наприклад, дати у форматі `YYYY-MM-DD` або серійні номери `SRV-042-PROD`), `sort` дозволяє вибирати підрядки всередині поля:

```bash
# Вхідний рядок: 2026-08-25
# Виділення та числове сортування за місяцем (символи з 6 по 7 першого поля):
sort -k1.6,1.7n dates.txt

# Багатоключове сортування дати: спочатку рік, потім місяць, потім день:
sort -k1.1,1.4n -k1.6,1.7n -k1.9,1.10n dates.txt
```

### Стабільність сортування (-s) та резервне порівняння

Алгоритм сортування називається **стабільним**, якщо він гарантовано зберігає початковий відносний порядок тих рядків, чиї ключі сортування виявилися ідентичними.

За замовчуванням GNU `sort` **не є стабільним**. Після того як вичерпано всі визначені ключі `-k`, у разі повної рівності ключів утиліта виконує так зване **резервне порівняння (last-resort comparison)** — побайтове порівняння всього рядка повністю.

```bash
# Вхідні дані (початковий порядок):
# hostB 10.0.0.1
# hostA 10.0.0.1

# Виконання без -s за другим полем:
sort -k2,2 data.txt
# Виведе:
# hostA 10.0.0.1
# hostB 10.0.0.1 (last-resort порівняння змінило початковий порядок!)
```

Прапорець `-s` (`--stable`) вимикає last-resort comparison і забезпечує суворе збереження вихідного порядку при збігу ключів:

```bash
# Стабільне сортування: порядок рядків з однаковою IP-адресою не змінюється
sort -s -k2,2 data.txt
```

Повний довідник усіх параметрів командного рядка, ключів та кодів повернення наведено у вставці [Довідник опцій sort та uniq](root:sys-unix/sort-and-uniq/api-sort-uniq-options.md).

## 3. Типи сортування та логіка парсерів

`sort` підтримує набір спеціалізованих парсерів даних, кожен із яких реалізує власні правила перетворення послідовності байтів у порівнювану величину.

### Лексикографічне сортування (дефолтний режим)

Рядки порівнюються посимвольно зліва направо за їхніми кодами (у C-локалі — за числовими значеннями байтів від `0x00` до `0xFF`).
- Головний наслідок: текстовий рядок `"10"` передує рядку `"2"`, оскільки символ `'1'` (`0x31`) має менший числовий код за символ `'2'` (`0x32`).
- Імена файлів `"file10.txt"` стають перед `"file2.txt"`.

### Числове сортування (-n / --numeric-sort)

Парсер `-n` шукає на початку ключа необов'язкові пробіли, необов'язковий знак (`+` або `-`), після чого сканує неперервну послідовність десяткових цифр та десятковий роздільник згідно з `LC_NUMERIC`.

```bash
# Впорядкування від'ємних і додатних чисел: -10 < -2 < 0 < 5 < 100.5
sort -n metrics.txt
```

**Крайові випадки та обмеження `-n`:**
- Експоненційна нотація: рядок `"1e6"` інтерпретується як число `1` (парсер зупиняється на першому нецифровому символі `'e'`).
- Шістнадцяткові значення: префікс `"0x20"` інтерпретується як число `0`.
- Нечислові рядки: рядок `"N/A"` розглядається як `0`.

### Загальне числове сортування (-g / --general-numeric-sort)

Для коректної обробки експоненційної форми чисел (`1.5e-4`), дробових значень довільної довжини, значень нескінченності (`+Inf`, `-Inf`) та `NaN` застосовується опція `-g`. Вона викликає системну функцію `strtod()`. Через складність перетворень плаваючої коми цей режим працює повільніше за `-n` і потребує значно більшої кількості процесорних тактів на кожен рядок.

### Версійне сортування (-V / --version-sort)

Опція `-V` реалізує "природний" порядок сортування (natural sort order), спеціально спроектований для імен файлів, версій пакетів та тегів релізів:

```bash
# Порівняння версій ПЗ:
# kernel-5.4.0
# kernel-5.10.0
# kernel-5.10.2
sort -V packages.txt
```

Парсер розбиває рядок на чергування літерних і цифрових фрагментів. Числові блоки порівнюються як невід'ємні цілі числа без урахування провідних нулів (`1` < `02` < `10`).

### Сортування розмірів даних (-h / --human-numeric-sort)

Спеціально розроблено для сортування виводу системних утиліт `ls -lh`, `du -h`, `df -h`. Парсер розпізнає десяткові числа та стандартні суфікси масштабування (K, M, G, T, P, E, Z, Y):

```bash
# Пошук найбільших каталогів на диску:
du -h /var/log/* | sort -h -k1,1 -r | head -n 10
```

`sort -h` коректно ранжує розміри: `500K < 2M < 1.5G < 4T`.

### Зворотне сортування (-r) та перемішування (-R)

- `-r` (`--reverse`): інвертує результат будь-якого компаратора на протилежний (сортування за спаданням).
- `-R` (`--random-sort`): перемішує рядки випадковим чином за допомогою хешування зі спонтанною сіллю. Важлива властивість: рядки з **однаковими значеннями ключів** після перемішування все одно гарантовано опиняються поруч у вихідному потоці.

## 4. Локалі та пастка коллації: LC_COLLATE і LC_ALL=C

Найбільш підступні дефекти продуктивності та логіки в обробці даних у Unix виникають через нерозуміння того, як локаль керує операціями порівняння.

![Конвеєр сортування й дедуплікації](/root/sys/sys-unix/sort-and-uniq/img/sort-uniq-pipeline.svg)
*Потокова модель uniq, взаємодія в конвеєрі та різниця між багатопрохідною коллацією UTF-8 і побайтовим режимом LC_ALL=C.*

### Як влаштована коллація у glibc (strcoll проти memcmp)

Коли у системі активна мовна локаль на зразок `en_US.UTF-8` або `uk_UA.UTF-8`, утиліти сортування зобов'язані порівнювати рядки відповідно до стандарту POSIX через виклики функції `strcoll()` або попереднє перетворення ваг через `strxfrm()`.

Коллація в Unicode — це складний багатопрохідний алгоритм (Unicode Collation Algorithm, DUCET), який порівнює символи на чотирьох послідовних рівнях ваг:
1. **Первинний рівень (Primary weights)**: базові літери абетки. Регістр та діакритичні знаки ігноруються (`'a' == 'A' == 'á'`).
2. **Вторинний рівень (Secondary weights)**: діакритика (`'a' != 'á'`).
3. **Третинний рівень (Tertiary weights)**: регістр літер (`'a' != 'A'`).
4. **Четвертинний рівень (Quaternary weights)**: розділові знаки, пробіли, дефіси.

Нижче наведено програмну демонстрацію різниці між функціями `strcoll()` та `strcmp()` мовами C та C++:

:::tabs

@tab C (POSIX / C11)
```c
#define _POSIX_C_SOURCE 200809L
#include <stdio.h>
#include <string.h>
#include <locale.h>

int main(void) {
    const char *s1 = "abc-1";
    const char *s2 = "abc1";

    // 1. Стандартна UTF-8 локаль
    setlocale(LC_ALL, "en_US.UTF-8");
    printf("en_US.UTF-8 strcoll: %d\n", strcoll(s1, s2)); // Дефіс ігнорується на первинному рівні

    // 2. Стандартна C-локаль
    setlocale(LC_ALL, "C");
    printf("C locale strcmp:     %d\n", strcmp(s1, s2));  // Побайтове порівняння ASCII ('-' < '1')

    return 0;
}
```

@tab C++ (C++20)
```cpp
#include <iostream>
#include <string_view>
#include <locale>
#include <cstring>

int main() {
    std::string_view s1 = "abc-1";
    std::string_view s2 = "abc1";

    // 1. Стандартна UTF-8 локаль через std::locale
    try {
        std::locale utf8_loc("en_US.UTF-8");
        const auto& coll = std::use_facet<std::collate<char>>(utf8_loc);
        int res_utf8 = coll.compare(s1.data(), s1.data() + s1.size(),
                                    s2.data(), s2.data() + s2.size());
        std::cout << "en_US.UTF-8 collate: " << res_utf8 << '\n';
    } catch (const std::exception& e) {
        std::cerr << "Помилка завантаження локалі: " << e.what() << '\n';
    }

    // 2. Побайтове ASCII порівняння
    int res_c = std::strcmp(s1.data(), s2.data());
    std::cout << "C locale strcmp:     " << res_c << '\n';

    return 0;
}
```

:::

### Пастки коллації UTF-8 на практиці

1. **Ігнорування розділових знаків**:
   У локалі `en_US.UTF-8` символи дефіса `-`, крапки та підкреслення мають нульову первинну вагу. Через це рядки `"abc-1"` та `"abc1"` вважаються рівними на першому проході, що руйнує природний порядок записів:
   ```
   # Порядок у LC_ALL=C:          Порядок у en_US.UTF-8:
   abc-1                          abc-1
   abc-2                          abc1
   abc1                           abc-2
   abc2                           abc2
   ```
2. **Чергування регістру (Case Interleaving)**:
   Замість суворого блоку великих літер `A-Z`, за якими слідують малі `a-z`, UTF-8 локаль чергує їх: `a`, `A`, `b`, `B`, `c`, `C`.
3. **Несумісність із потоковим uniq**:
   Якщо `sort` працює під впливом UTF-8 коллації, а `uniq` виконує пряме побайтове порівняння, виникає розсинхронізація: рядки, які `sort` вважає однаковими за ключем, утиліта `uniq` розглядає як різні, і навпаки.

### Чому LC_ALL=C — золотий інженерний стандарт

Перевизначення `LC_ALL=C` або `LC_COLLATE=C` перемикає системні бібліотеки в базовий режим:
- Кожен символ інтерпретується як беззнаковий 8-бітний байт від `0x00` до `0xFF`.
- Замість важких багатопрохідних таблиць `strcoll()` викликаються швидкі векторизовані інструкції `memcmp()`.
- Сучасні компілятори та ядра автоматично транслюють `memcmp()` у векторні інструкції SIMD (AVX-512 / AVX2 / SSE4.2), порівнюючи по 32 або 64 байти за один такт процесора.

**Наслідки для системної інженерії:**
1. **Прискорення в 5–10 разів**: Сортування логів великих обсягів у `LC_ALL=C` завершується у рази швидше та споживає мінімум ресурсів CPU.
2. **Абсолютний детермінізм**: Результат сортування є суворо однаковим на будь-якому сервері, дистрибутиві Linux, BSD або macOS.
3. **100% сумісність з іншими фільтрами**: `uniq`, `comm`, `join` та бінарний пошук `look` гарантовано працюють коректно.

```bash
# Золотий стандарт конвеєрної обробки системних даних:
LC_ALL=C sort -S 4G -T /var/tmp input.log | LC_ALL=C uniq -c
```

## 5. Утиліта uniq: потокова дедуплікація суміжних рядків

Утиліта `uniq` реалізує потоковий фільтр, призначений для виявлення та дедуплікації **суміжних** однакових рядків у вхідному потоці.

### Потокова природа та потреба у попередньому sort

На відміну від `sort`, утиліті `uniq` не потрібна оперативна пам'ять для збереження всього файлу. Вона працює за алгоритмом з константною пам'яттю `O(1)`:
1. Виділяється буфер для зберігання рівно одного рядка — попереднього зчитаного запису.
2. Зчитується поточний рядок.
3. Поточний рядок порівнюється з рядком у буфері.
4. Якщо рядки збігаються, лічильник повторів збільшується, а поточний рядок відкидається.
5. Якщо рядки різняться, попередній рядок виводиться (залежно від прапорців), буфер перезаписується поточним рядком, а лічильник скидається.

```
Вхідний потік:    A -> B -> A -> A -> C
uniq (без sort):  A -> B -> A -> C        (перша й друга 'A' не злилися!)
sort | uniq:      A -> A -> A -> B -> C -> A -> B -> C (ідеальна дедуплікація)
```

Звідси випливає фундаментальне системне правило: **`uniq` знаходить дублікати лише тоді, коли вхідний потік попередньо відсортовано за допомогою `sort`**.

### Режими виведення та підрахунку частотності

1. **Підрахунок кількості повторень (`-c` / `--count`)**:
   Додає кількість входжень перед кожним унікальним рядком. Класичний конвеєр для аналізу частотності подій:

   ```bash
   # Топ-10 IP-адрес за кількістю запитів у журналі web-сервера:
   awk '{print $1}' access.log | LC_ALL=C sort | LC_ALL=C uniq -c | LC_ALL=C sort -rn | head -n 10
   ```

2. **Виділення тільки дублікатів (`-d` / `--repeated`)**:
   Друкує рівно один екземпляр тих записів, які зустрічаються два або більше разів підряд:

   ```bash
   # Пошук дубльованих ідентифікаторів у вивантаженні бази даних:
   LC_ALL=C sort ids.txt | uniq -d
   ```

3. **Виведення всіх копій повторів (`-D` / `--all-repeated`)**:
   Друкує всі копії дубльованих записів. Дозволяє візуально проаналізувати всі екземпляри колізій:

   ```bash
   # Вивід усіх екземплярів дублікатів з порожнім рядком-роздільником між групами:
   LC_ALL=C sort transactions.csv | uniq --all-repeated=separate
   ```

4. **Виділення тільки унікальних рядків (`-u` / `--unique`)**:
   Друкує виключно ті рядки, які зустрічаються рівно один раз у всьому файлі. Будь-який запис, що мав бодай один повтор, повністю відкидається.

### Тонке керування полями та символами (-f, -s, -w)

- `-f N` (`--skip-fields=N`): пропускає перші `N` полів (розділених пробілами чи табуляціями).
- `-s N` (`--skip-chars=N`): пропускає перші `N` символів після пропущених полів.
- `-w N` (`--check-chars=N`): порівнює не більше ніж `N` символів кожного рядка.
- `-i` (`--ignore-case`): ігнорує регістр літер під час порівняння.

```bash
# Порівняння системних логів, ігноруючи дату й час (перші 3 поля):
# Feb 25 14:30:00 server sshd[1234]: Failed password
# Feb 25 14:30:01 server sshd[1234]: Failed password
LC_ALL=C sort syslog.txt | uniq -f 3 -c
```

### sort -u проти sort | uniq: архітектурна різниця

1. **Область дії дедуплікації при використанні ключів `-k`**:
   - `sort -k1,1 -u file`: дедуплікація виконується **суворо за ключем сортування**. Якщо два рядки мають однакове перше поле, але абсолютно різні наступні стовпці, `sort -u` залишить лише один перший рядок і безповоротно видалить другий!
   - `sort -k1,1 file | uniq`: `sort` впорядкує записи за першим полем, але `uniq` порівнюватиме **весь рядок повністю**. У результаті рядки з однаковим першим стовпцем, але різним вмістом, повністю збережуться.
2. **Ефективність I/O та утилізація ресурсів**:
   - `sort -u` дедуплікує записи безпосередньо під час формування блоків у RAM та на кожному кроці k-way злиття. Це суттєво зменшує обсяг тимчасових файлів на диску та розвантажує дискову підсистему.
   - `sort | uniq` змушений передавати всі дубльовані записи через міжпроцесний канал (pipe). Проте `uniq` забезпечує гнучкість підрахунку частотності (`-c`) та фільтрації (`-d`, `-u`), яку `sort -u` реалізувати не може.

### Робота з нульовими роздільниками (-z)

Під час обробки імен файлів, які можуть містити пробіли, символи нового рядка або лапки, використовується роздільник `ASCII NUL` (`\0`):

```bash
# Безпечний пошук та дедуплікація імен файлів:
find . -type f -name "*.log" -print0 | LC_ALL=C sort -z | LC_ALL=C uniq -z | xargs -0 ls -l
```
