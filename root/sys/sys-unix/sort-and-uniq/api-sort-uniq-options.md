# Довідник інтерфейсу утиліт сортування та вибірки даних: sort, uniq, shuf, comm та tsort

Специфікація параметрів командного рядка, форматів визначення ключів, правил розбору полів, керування буферами пам'яті, стиснення серій, взаємодії потоків, обробки графів залежностей, змінних середовища та кодів повернення системних фільтрів `sort`, `uniq`, `shuf`, `comm` та `tsort` у стандартах POSIX.1-2017/2024 та реалізації GNU Coreutils.

## 1. Синопсис виклику та архітектурні моделі

Утиліти `sort`, `uniq`, `shuf`, `comm` та `tsort` складають базовий інструментарій операційної системи для впорядкування, вибірки, фільтрації, зіставлення та аналізу зв'язності текстових даних. Вони взаємодіють з операційною системою через стандартні файлові дескриптори: `0` (`stdin`), `1` (`stdout`) та `2` (`stderr`).

```bash
# Синопсис виклику sort (сортування та k-way злиття)
sort [ОПЦІЯ]... [ФАЙЛ]...
sort -c [ОПЦІЯ]... [ФАЙЛ]
sort -C [ОПЦІЯ]... [ФАЙЛ]

# Синопсис виклику uniq (фільтрація суміжних рядків)
uniq [ОПЦІЯ]... [ВХІД [ВИХІД]]

# Синопсис виклику shuf (генерація випадкових перестановок і вибірок)
shuf [ОПЦІЯ]... [ФАЙЛ]
shuf -e [ОПЦІЯ]... [АРГУМЕНТ]...
shuf -i LO-HI [ОПЦІЯ]...

# Синопсис виклику comm (порівняння двох відсортованих файлів по рядках)
comm [ОПЦІЯ]... ФАЙЛ1 ФАЙЛ2

# Синопсис виклику tsort (топологічне сортування спрямованого графа)
tsort [ОПЦІЯ] [ФАЙЛ]
```

### Потокова обробка, бар'єрна семантика та робота з графами

Між моделлю виконання цих п'яти утиліт існує фундаментальна архітектурна різниця:

1. **`uniq` та `comm` — лінійні однопрохідні фільтри (Streaming Single-Pass Filters).**
   - `uniq` утримує в оперативній пам'яті лише один попередній рядок (або його порівнювану частину). Рішення про друк чи пропуск ухвалюється негайно при зчитуванні наступного рядка. Часова складність становить `O(N)`, а додаткова просторова пам'ять — `O(1)`.
   - `comm` паралельно зчитує по одному рядку з двох відсортованих вхідних потоків за допомогою двовказівникового алгоритму злиття. Часова складність становить `O(N + M)` порівнянь рядків, просторова — `O(1)`.
2. **`sort` та `shuf` (у стандартному режимі) — бар'єрні операції (Barrier Pipeline Operations).**
   - `sort` не може видати жодного байта у `stdout` доти, доки не прочитає вхідний потік повністю (за винятком режимів верифікації `-c`/`-C`, які завершуються на першій невідповідності). Якщо обсяг даних перевищує виділений буфер RAM, утиліта автоматично перемикається на зовнішнє сортування злиттям (External Merge Sort), скидаючи проміжні серії (runs) на диск.
   - `shuf` при повному перемішуванні файлу завантажує весь потік рядків у пам'ять для виконання перестановки Фішера–Йетса `O(N)`. Проте при вибірці малого підмножини `-n K` з потоку `stdin` утиліта автоматично застосовує алгоритм резервуарної вибірки (Reservoir Sampling), знижуючи споживання пам'яті до `O(K)`.
3. **`tsort` — структурний аналізатор орієнтованого графа (Graph DAG Resolver).**
   - `tsort` зчитує весь потік токенів, формує в пам'яті списки суміжності та масив степенів входу (in-degree) вершин орієнтованого графа, після чого виконує топологічне сортування за алгоритмом Кана зі складністю `O(V + E)`. У разі виявлення циклів утиліта генерує діагностику та застосовує евристику розриву петель.

### Правила обробки аргументів файлів

- Якщо замість імені файлу передано дефіс `-` або список вхідних файлів порожній, дані зчитуються зі стандартного вводу `stdin`.
- Утиліта `sort` приймає довільну кількість файлів (`sort file1.txt file2.txt file3.txt`): вони конкатенуються у єдиний логічний потік, після чого сортуються глобально.
- Утиліта `uniq` приймає щонайбільше два позиційні аргументи: `ВХІД` та `ВИХІД`. Якщо аргумент `ВИХІД` вказано, `uniq` відкриває його на запис (`O_WRONLY | O_CREAT | O_TRUNC`).
- Утиліта `comm` приймає строго два позиційні аргументи: `ФАЙЛ1` та `ФАЙЛ2`. Рівно один із них може бути дефісом `-` для читання зі `stdin`.
- Утиліта `tsort` приймає щонайбільше один позиційний аргумент файлу (або читає зі `stdin`, якщо файл не вказано або передано `-`).

> [!WARNING]
> Виклик `uniq input.txt input.txt` призводить до миттєвого затирання та повної втрати вмісту `input.txt`, оскільки процес відкриває вихідний файл із прапорцем утинання `O_TRUNC` до зчитування даних. Для безпечного перезапису результату слід використовувати `sort -o file file`, `shuf -o file file` або проміжний тимчасовий файл.

## 2. Повна специфікація параметрів утиліти sort

### Керування ресурсами, пам'яттю та зовнішнім сортуванням

| Опція | Довга назва | Тип аргументу | Опис та системна поведінка |
|---|---|---|---|
| `-S` | `--buffer-size=SIZE` | Число з суфіксом | Встановлює граничний розмір буфера оперативної пам'яті для внутрішнього сортування серій. Допустимі суфікси розміру: `b` (512 байтів), `B` або `c` (1 байт), `K` або `k` (КіБ, 1024), `M` або `m` (МіБ, 1024^2), `G` або `g` (ГіБ, 1024^3), `T`, `P`, `E`, `Z`, `Y`, або `%` (відсоток від доступної фізичної пам'яті RAM). За замовчуванням GNU `sort` евристично виділяє близько 80% вільної фізичної пам'яті, але не менше ніж 512 КіБ. |
| `-T` | `--temporary-directory=DIR` | Шлях до каталогу | Задає каталог для розміщення тимчасових файлів скидання серій замість системного `$TMPDIR` або `/tmp`. Параметр можна вказувати багаторазово (`-T /mnt/d1/tmp -T /mnt/d2/tmp`): утиліта розподіляє файли між каталогами за циклічним алгоритмом round-robin для паралелізації дискового вводу-виводу. |
| `--batch-size=N` | `--batch-size=N` | Ціле число (>= 2) | Максимальна кількість тимчасових файлів, які процес відкриває одночасно під час однієї фази k-way злиття. Запобігає вичерпанню ліміту файлових дескрипторів процесу (`RLIMIT_NOFILE`). Якщо кількість серій перевищує `N`, `sort` виконує ієрархічне багаторівневе проміжне злиття. За замовчуванням дорівнює 32 (або 16 у затиснутих середовищах). |
| `--parallel=N` | `--parallel=N` | Ціле число (>= 1) | Обмежує кількість одночасно виконуваних робочих потоків (threads). Паралелізуються як внутрішнє сортування блоків у RAM, так і побудова дерева k-way злиття. За замовчуванням кількість потоків дорівнює значенню `sysconf(_SC_NPROCESSORS_ONLN)`. |
| `--compress-program=PROG` | `--compress-program=PROG` | Ім'я утиліти | Виконує стиснення проміжних файлів серій за допомогою зовнішньої програми (`lz4`, `gzip`, `zstd`, `bzip2`, `xz`). Стиснення активується автоматично під час запису серії на диск і розпаковується (виклик `PROG -d`) під час зчитування у фазі злиття. Дозволяє заощадити дисковий простір та зменшити обсяг дискового I/O ціною витрат CPU. |
| `--files0-from=FILE` | `--files0-from=FILE` | Шлях до файлу | Зчитує нульовими байтами (`\0`) відокремлений список імен файлів для сортування з вказаного файлу (або `stdin`, якщо передано `-`). Запобігає помилці переповнення довжини командного рядка (`E2BIG`) при обробці десятків тисяч файлів. |
| `-m` | `--merge` | Немає | Режим чистого злиття: розглядає всі вхідні файли як попередньо відсортовані серії. Повністю оминає фазу внутрішнього розбиття на блоки та сортування в пам'яті, одразу відкриваючи вхідні файли через мін-купу. Потребує `O(K)` пам'яті, де K — кількість вхідних файлів. |
| `-o` | `--output=FILE` | Шлях до файлу | Спрямовує результат сортування у вказаний файл замість `stdout`. На відміну від оболонкового перенаправлення `> file`, файл відкривається на запис лише після того, як усі вхідні дані повністю прочитано та збережено у внутрішніх структурах або тимчасових серіях. Це дозволяє безпечно сортувати файл «на місці»: `sort -o data.txt data.txt`. |
| `-z` | `--zero-terminated` | Немає | Встановлює нульовий байт (`ASCII NUL`, `\0`) як роздільник записів (рядків) як на вході, так і на виході, замість стандартного символу нового рядка `\n`. |

### Режими перевірки та стабільності

| Опція | Довга назва | Тип аргументу | Опис та системна поведінка |
|---|---|---|---|
| `-c` | `--check`, `--check=diagnose-first` | Немає | Перевіряє, чи впорядкований вхідний потік за заданими критеріями сортування. Якщо виявлено рядок, що порушує порядок, утиліта виводить у `stderr` діагностичне повідомлення (ім'я файлу, номер рядка та вміст рядка) і негайно завершує роботу з кодом `1`. Якщо файл відсортовано — вивід відсутній, код завершення `0`. |
| `-C` | `--check=quiet`, `--check=silent` | Немає | Працює аналогічно до `-c`, але повністю пригнічує діагностичні повідомлення у `stderr`. Повертає `0`, якщо потік відсортовано, і `1` при першому ж порушенні порядку. Використовується в умовних конструкціях shell-скриптів. |
| `-s` | `--stable` | Немає | Вмикає режим стабільного сортування: рядки з однаковими значеннями всіх вказаних ключів гарантовано зберігають свій початковий відносний порядок. Вимикає стандартне резервне побайтове порівняння всього рядка (last-resort comparison). |
| `-u` | `--unique` | Немає | Виводить лише перший рядок із групи рядків з однаковими ключами порівняння. Якщо вказано параметри `-k`, дедуплікація відбувається виключно за полями, визначеними ключами. Якщо використовується разом із `-c`/`-C`, утиліта додатково перевіряє відсутність суміжних дублікатів (строгий порядок зростання). |
| `--debug` | `--debug` | Немає | Виводить у `stderr` візуальну розмітку виділених ключів сортування для перших рядків вхідного потоку, попереджає про сумнівні конфігурації (наприклад, невизначені кінці ключів, невикористані модифікатори) та повідомляє про поточну активну локаль коллації. |

### Визначення ключів та розділювачів полів

| Опція | Довга назва | Тип аргументу | Опис та системна поведінка |
|---|---|---|---|
| `-k` | `--key=KEYDEF` | Специфікатор ключа | Визначає діапазон полів та символів, що утворюють ключ порівняння, у форматі `F[.C][OPTS][,F[.C][OPTS]]`. Може повторюватися багаторазово для задання ієрархічного каскаду пріоритетів порівняння. |
| `-t` | `--field-separator=SEP` | Символ (1 байт) | Встановлює символ-роздільник полів. Якщо параметр не задано, поля розділяються переходами між непробільними та пробільними символами (пробіли та табуляції). |
| `-b` | `--ignore-leading-blanks` | Немає | Ігнорує пробільні символи на початку полів при визначенні позицій символів та під час порівняння. Може встановлюватися глобально або локально для конкретного ключа. |

### Алгоритми та модифікатори порівняння

Модифікатори визначають спосіб інтерпретації виділеного тексту. Вони можуть задаватися як глобальні прапорці командного рядка (діють на весь рядок або на всі ключі без власних прапорців) або індивідуально всередині кожного ключа `-k`:

| Опція | Довга назва | Локальний прапорець | Опис алгоритму порівняння |
|---|---|---|---|
| `-n` | `--numeric-sort` | `n` | Рядкове числове сортування: зчитує необов'язковий початковий пробіл, знак `+` або `-`, десяткові цифри та десятковий роздільник згідно з `LC_NUMERIC`. Зчитування зупиняється на першому нечисловому символі. Рядки без розпізнаних чисел розглядаються як числове значення 0. |
| `-g` | `--general-numeric-sort` | `g` | Загальне числове сортування з плаваючою крапкою подвійної точності (`double`): парсить числа через системну функцію `strtod()`. Підтримує експоненційну нотацію (`1.5e-3`, `2E+10`), дробові числа, `+Inf`, `-Inf` та `NaN`. Працює повільніше за `-n` через накладні витрати на конвертацію чисел. |
| `-h` | `--human-numeric-sort` | `h` | Порівняння розмірів із суфіксами масштабування (Human-Readable): парсить числа з суфіксами десяткових та двійкових одиниць вимірювання (`2K`, `500M`, `4G`, `1.5T`, `P`, `E`, `Z`, `Y`). Адаптовано для сортування виводу утиліт `ls -lh`, `du -h`, `df -h`. |
| `-V` | `--version-sort` | `V` | Версійне сортування (Natural Sort): розбиває рядок на послідовності літер і невід'ємних цілих чисел. Числові блоки порівнюються за їхнім математичним значенням без урахування провідних нулів (`v1.2.3` < `v1.2.10`). |
| `-M` | `--month-sort` | `M` | Сортування за назвами місяців: пропускає початкові пробіли, бере перші три літери поля, переводить їх у верхній регістр і зіставляє з календарем у поточній локалі `LC_TIME` (`JAN` < `FEB` < ... < `DEC`). Невідомі назви вважаються меншими за будь-який коректний місяць і розташовуються на початку. |
| `-r` | `--reverse` | `r` | Інвертує результат порівняння (впорядкування за спаданням). |
| `-R` | `--random-sort` | `R` | Випадкове перемішування на основі хешування: обчислює хеш ключа з використанням випадкової солі (seed), згенерованої під час старту процесу (або з файлу `--random-source`). Рядки з однаковими ключами групуються разом, але самі групи розташовуються у псевдовипадковому порядку. |
| `--random-source=FILE` | `--random-source=FILE` | — | Використовує вказаний файл або пристрій (наприклад, `/dev/urandom`) як джерело байтів випадковості для опції `-R` або утиліти `shuf`. |
| `-f` | `--ignore-case` | `f` | Регістронезалежне порівняння: переводить символи нижнього регістру у верхній перед виконанням порівняння байтів. |
| `-d` | `--dictionary-order` | `d` | Словниковий порядок: під час порівняння враховуються лише літери, десяткові цифри та пробіли; усі знаки пунктуації та спеціальні символи ігноруються. |
| `-i` | `--ignore-nonprinting` | `i` | Ігнорує недруковані символи (байти ASCII з кодами < 32 або > 126, а також відповідні керуючі символи Unicode). |
| `--sort=WORD` | `--sort=WORD` | — | Альтернативний синтаксис вибору алгоритму порівняння: `general-numeric` (`-g`), `human-numeric` (`-h`), `month` (`-M`), `numeric` (`-n`), `random` (`-R`), `version` (`-V`). |

## 3. Специфікатор ключа sort -k: граматика та повна семантика розбору

Специфікація ключів дозволяє точно визначати підрядки всередині запису, які беруть участь у порівнянні. Синтаксис описується формальною граматикою стандарту POSIX:

```
KEYDEF = POS1[,POS2]
POS    = FIELD[.CHAR][FLAGS]
```

### Формальні правила інтерпретації компонентів

1. **`POS1` (Початок ключа):**
   - Задає початкову позицію вибірки тексту для порівняння.
   - `FIELD` — номер поля (1-індексація, ціле число >= 1). Якщо `FIELD` перевищує фактичну кількість полів у рядку, ключ вважається порожнім і порівнюється як рядок нульової довжини.
   - `.CHAR` — номер початкового символу в межах поля `FIELD` (1-індексація, ціле число >= 1). Якщо `.CHAR` опущено, за замовчуванням береться перший символ поля (`.1`).
   - Якщо прапорець `b` відсутній, відлік `.CHAR` починається від самого першого байта поля. У дефолтному режимі (без `-t`) для всіх полів, крім першого, першими символами є пробіли розділювача.
   - Якщо вказано прапорець `b` (`.CHARb` або `FIELDb`), провідні пробіли поля `FIELD` пропускаються перед відліком `.CHAR` (`.1b` означає перший непробільний символ).
2. **`POS2` (Кінець ключа):**
   - Задає кінцеву позицію вибірки тексту (включно).
   - Якщо `POS2` **вказано явно** (`-k F1.C1,F2.C2`), ключ закінчується на символі `C2` поля `F2`. Якщо `C2` опущено (`-k F1.C1,F2`), кінцем ключа є **останній символ** поля `F2`.
   - Якщо біля `POS2` вказано прапорець `b` (`-k 1.1b,2.4b`), то у кінцевому полі `F2` провідні пробіли пропускаються перед відліком `C2` символів. Якщо прапорця `b` біля `POS2` немає (`-k 1.1b,2.4`), відлік `C2` ведеться від початку поля `F2`, включаючи його провідні пробіли.
   - Якщо `POS2` **опущено взагалі** (`-k F1.C1` або `-k F1`), ключ продовжується **від початкової позиції `POS1` до самого кінця фізичного рядка** (включаючи всі наступні поля, символи-роздільники та перенесення рядків).
3. **`FLAGS` (Модифікатори позицій та ключів):**
   - Локальні прапорці `b`, `d`, `f`, `g`, `h`, `i`, `M`, `n`, `r`, `R`, `V`, вказані після номерів полів або символів, перевизначають відповідні глобальні опції для цього ключа.
   - Якщо прапорець встановлено біля `POS1` (наприклад, `-k2n,2`), він задає режим порівняння для всього ключа.
   - Прапорець `b` (пропуск провідних пробілів) може встановлюватися окремо для `POS1` та `POS2`.
   - Якщо в ключі не вказано жодного прапорця порівняння, він успадковує активні глобальні прапорці командного рядка (наприклад, `sort -n -k1,1 -k2,2r` застосує числовий порядок до першого ключа та числовий зворотний — до другого).

### Пастка пропуску POS2 (сортування до кінця рядка)

Найпоширенішою помилкою при використанні `sort` є запис виду `sort -k 2 file.txt` замість `sort -k 2,2 file.txt`:

```bash
# Припустимо, вхідні дані (роздільник — кома):
# Alice,100,Berlin
# Bob,20,Amsterdam
# Charlie,100,Aachen

# Помилковий виклик: -k 2 охоплює все від стовпця 2 до кінця рядка ("100,Berlin", "20,Amsterdam", "100,Aachen")
sort -t, -k 2 data.csv

# Коректний виклик: -k 2,2n ізолює строго другий стовпець
sort -t, -k 2,2n data.csv
```

У разі текстового порівняння без обмеження кінця ключа рядок `Alice,100,Berlin` порівнюється як `"100,Berlin"`, а `Charlie,100,Aachen` — як `"100,Aachen"`. Запис `Charlie` опиниться раніше за `Alice`, навіть якщо розробник планував сортувати лише за другим полем, а третє залишити незмінним.

### Ієрархія та порядок обчислення ключів

Під час порівняння двох рядків `sort` послідовно оцінює визначені ключі у порядку їх появи в командному рядку:

1. Порівнюються значення першого ключа `-k`. Якщо одне значення строго менше або більше за інше, відносний порядок рядків визначено, і подальші ключі не обчислюються.
2. Якщо значення першого ключа виявилися еквівалентними, утиліта переходить до другого ключа `-k`, потім до третього і так далі.
3. **Резервне порівняння (Last-Resort Comparison):** Якщо всі ключі `-k` вичерпано, а рядки залишаються еквівалентними, `sort` за замовчуванням виконує побайтове порівняння всього вихідного рядка (від першого до останнього байта, з урахуванням глобального прапорця `-r`, якщо він активний).
4. **Вплив прапорця `-s` (`--stable`):** Прапорець `-s` повністю вимикає last-resort comparison. Рядки з однаковими ключами зберігають свій початковий порядок у вхідному потоці.

### Таблиця граничних інтерпретацій специфікаторів ключів

У таблиці показано, який саме фрагмент тексту виділяється у якості ключа для тестового рядка:
`"  ALPHA   12345  ZETA"` (де роздільником є пробіл за замовчуванням):

| Специфікатор | Межі виділення тексту | Виділений ключ | Результат та наслідки |
|---|---|---|---|
| `-k 1,1` | Поле 1 (без явного `-t`) | `"  ALPHA"` | Захоплює початкові пробіли рядка, оскільки вони належать до поля 1. |
| `-k 1,1b` | Поле 1 з модифікатором `b` | `"ALPHA"` | Пропускає початкові пробіли, порівнює чистий текст. |
| `-k 2` | Від поля 2 до кінця рядка | `"   12345  ZETA"` | **Пастка:** порівнює число разом із залишком рядка. |
| `-k 2,2` | Суворо поле 2 | `"   12345"` | Текстове порівняння другого стовпця з провідними пробілами. |
| `-k 2,2n` | Поле 2, числовий тип | `"   12345"` (число 12345) | Числовий парсер автоматично ігнорує провідні пробіли. |
| `-k 2.4,2.6` | З 4-го по 6-й символ поля 2 | `" 12"` | Символи відраховуються від початку поля (включаючи пробіли роздільника). |
| `-k 2.2b,2.4b` | З 2-го по 4-й символ після `b` | `"234"` | Пропускає пробіли перед відліком позицій символів. |
| `-k 2,2n -k 3,3r` | Каскадне сортування | Ключ 1: `12345`, Ключ 2: `"ZETA"` | Сортує за числом 2-го поля за зростанням; при збігу — за 3-м полем за спаданням. |

## 4. Спеціальні алгоритмічні режими сортування sort

### Режим -h / --human-numeric-sort (Human-Readable)

Параметр `-h` призначено для впорядкування числових значень із суфіксами кратності, що генеруються утилітами `ls -lh`, `du -h`, `df -h`.

1. **Підтримувані суфікси одиниць вимірювання:**
   - `K` або `k` (Кіло, 1024 або 10^3)
   - `M` або `m` (Мега, 1024^2 або 10^6)
   - `G` або `g` (Гіга, 1024^3 або 10^9)
   - `T` або `t` (Тера, 1024^4)
   - `P` або `p` (Пета, 1024^5)
   - `E` або `e` (Екса, 1024^6)
   - `Z` або `z` (Зета, 1024^7)
   - `Y` або `y` (Йота, 1024^8)
   - Також коректно розпізнаються суфікси з літерами одиниць (наприклад, `KiB`, `MiB`, `KB`, `MB`), оскільки парсер оцінює перший символьний суфікс після числа.
2. **Правила числового зіставлення:**
   - Числа без суфікса вважаються чистими одиницями (байтами) і завжди менші за будь-яке число з суфіксом `K` (наприклад, `500` < `1K`).
   - Значення з однаковими суфіксами порівнюються за їхньою чисельною мантисою: `1.5M` < `2.0M` < `200M`.
   - Значення з різними суфіксами впорядковуються за рангом суфікса: `900M` < `1G`.
3. **Від'ємні числа та крайні випадки:**
   - Від'ємні величини масштабуються дзеркально: `-2G` < `-100M` < `-1K` < `-500` < `0` < `500` < `1K` < `100M` < `2G`.
   - Нечислові рядки, що не починаються з цифри або знака, розглядаються як нульові або розташовуються перед валідними числами.

```bash
# Сортування виводу дискового простору за спаданням розміру
du -h /var/log/* | sort -h -r -k1,1
```

### Режим -V / --version-sort (Natural / Version Sort)

Опція `-V` активує версійне сортування (реалізація функції `filevercmp` у GNU Coreutils). Вона розв'язує проблему лексикографічного сортування, за якого рядок `v1.10` помилково вважається меншим за `v1.2`.

1. **Алгоритм розбиття:**
   - Рядок розбивається на чергування нечислових префіксів та неперервних числових послідовностей десяткових цифр.
   - Нечислові сегменти порівнюються побайтово або за локаллю.
   - Числові сегменти конвертуються у цілі числа довільної розрядності і порівнюються за їхнім математичним значенням: `2` < `10`.
2. **Семантика pre-release суфікса тильди (`~`):**
   - Символ `~` має спеціальний найнижчий пріоритет порівняння (згідно зі стандартом версіонування пакунків Debian/DPKG).
   - Будь-який суфікс, що починається з `~`, робить версію меншою за версію без суфікса:
     `1.0~beta1` < `1.0~rc1` < `1.0~rc2` < `1.0` < `1.0-1` < `1.0.1` < `1.1`.
3. **Обробка провідних нулів:**
   - Значення `01` та `1` мають однакове математичне значення, проте для збереження строгої стабільності запис із більшою кількістю провідних нулів ранжується як менший: `001` < `01` < `1`.

```bash
# Сортування імен файлів релізів та Git-тегів
printf '%s\n' "app-1.2.tar.gz" "app-1.10.tar.gz" "app-1.2.1.tar.gz" | sort -V
# Результат:
# app-1.2.tar.gz
# app-1.2.1.tar.gz
# app-1.10.tar.gz
```

### Режим -M / --month-sort (Календарні назви місяців)

Опція `-M` зіставляє початковий текст поля з календарем:

1. **Алгоритм аналізу:**
   - Пропускаються початкові пробільні символи.
   - Беруться перші три літери поля, які приводяться до верхнього регістру (`toupper()`).
   - Виконується пошук у таблиці скорочених назв місяців, згенерованій для поточної локалі `LC_TIME` через `nl_langinfo(ABMON_1)` ... `nl_langinfo(ABMON_12)`.
2. **Порядок зіставлення в локалі C:**
   `JAN` (1) < `FEB` (2) < `MAR` (3) < `APR` (4) < `MAY` (5) < `JUN` (6) < `JUL` (7) < `AUG` (8) < `SEP` (9) < `OCT` (10) < `NOV` (11) < `DEC` (12).
3. **Обробка невідомих рядків:**
   - Рядки, які не вдалося зіставити з жодним місяцем, отримують внутрішній ранг `0` (менше за `JAN`).
   - Група нерозпізнаних рядків розташовується на початку виводу і впорядковується між собою за звичайними лексикографічними правилами.

### Режим -R / --random-sort та --random-source

Опція `-R` реалізує випадкове псевдоперемішування на основі хешування ключів:

1. **Механізм хешування проти утиліти `shuf`:**
   - Утиліта `shuf` перемішує рядки цілком незалежно, порушуючи групування ідентичних записів.
   - Опція `sort -R` обчислює криптографічний або некриптографічний хеш від байтів виділеного ключа порівняння, використовуючи випадкову сіль (seed), згенеровану при старті процесу.
   - **Гарантія групування:** Рядки з однаковими ключами дають строго однаковий хеш. Вони гарантовано групуються разом у вихідному потоці, але самі групи слідують у випадковому порядку.
2. **Детерміноване джерело випадковості (`--random-source=FILE`):**
   - За замовчуванням сіль ініціалізується з `/dev/urandom` або системного генератора ентропії `getrandom()`.
   - Параметр `--random-source=FILE` змушує `sort` читати байти ініціалізації з вказаного файлу. Якщо файл містить фіксовані байти, порядок перемішування `sort -R` буде строго однаковим (відтворюваним) між повторними запусками, що необхідно для регресійного тестування.

```bash
# Відтворюване перемішування масиву з фіксованим джерелом випадковості
sort -R --random-source=/etc/machine-id dataset.txt
```

### Порівняння числового -n та загального -g сортування

| Параметр | `-n` (`--numeric-sort`) | `-g` (`--general-numeric-sort`) |
|---|---|---|
| **Внутрішній тип** | Довільна розрядність цілих або фіксована крапка | 64-бітний двійковий float (`double`, IEEE 754) |
| **Системний парсер** | Власний швидкий посимвольний скан `sort` | Системний виклик `strtod()` |
| **Експоненти (`1e-4`)** | **Ні** (зупиняється на літері `e`, порівнює як `1`) | **Так** (`1e-4` коректно розпізнається як `0.0001`) |
| **Нечислові символи** | Зупиняє парсинг, повертає накопичене число | Зупиняє парсинг згідно з правилами `strtod()` |
| **Спеціальні значення** | Не розпізнає | Підтримує `-Inf` < від'ємні < `0` < додатні < `+Inf` < `NaN` |
| **Швидкодія** | Дуже висока (прямі арифметичні операції) | Помітно нижча через конвертацію у float |

## 5. Розділювачі полів (-t), пробільна модель та нульовий термінатор (-z)

### Дефолтна модель розділення полів (без опції -t)

Якщо параметр `-t` не задано, стандарт POSIX визначає специфічні правила поділу на поля:

1. **Роздільник поля** — це перехід від непробільного символу до пробільного символу (пробіл `0x20` або знак табуляції `\t` / `0x09`).
2. **Початкові пробіли рядка:** якщо рядок починається з пробілів, усі вони вважаються складовою частиною першого поля (`FIELD 1`).
3. **Подальші поля:** послідовність пробілів між полями вважається префіксом наступного поля. Наприклад, у рядку `A   B` поле 1 — це `"A"`, а поле 2 — це `"   B"`.
4. Через це при лексикографічному порівнянні другого поля без прапорця `b` код пробілу `0x20` впливає на алфавітний порядок.

### Модель явного роздільника (-t SEP)

Коли задано опцію `-t SEP` (наприклад, `-t:`, `-t,`, `-t$'\t'`):

1. Символ `SEP` повинен бути рівно одним однобайтовим символом (або валідним символом у поточній багатобайтовій локалі).
2. Полем `N` вважається текст строго між `(N-1)`-м та `N`-м входженням символу `SEP`.
3. Символ `SEP` не входить до складу жодного поля.
4. Суміжні символи-роздільники утворюють порожні поля нульової довжини.
5. Провідні пробіли всередині полів більше не розглядаються як роздільники і є звичайними символами даних.

```bash
# Приклад обробки CSV з порожніми полями
# Рядок: alpha,,gamma
# Поле 1: "alpha", Поле 2: "" (порожній рядок), Поле 3: "gamma"
sort -t, -k2,2 data.csv
```

### Нульовий термінатор записів (-z / --zero-terminated)

За замовчуванням записи утиліт `sort`, `uniq`, `shuf` та `comm` відокремлюються символом переводу рядка `\n` (`0x0A`). Прапорець `-z` перемикає роздільник записів на байт `ASCII NUL` (`0x00`).

Це забезпечує надійність конвеєрів обробки файлових систем, де шляхи файлів можуть містити пробіли, табуляції, лапки або перенесення рядків:

```bash
# Безпечне сортування та дедуплікація списку знайдених файлів
find /var/log -type f -print0 | sort -z -u | xargs -0 -r ls -ld
```

## 6. Внутрішня підсистема пам'яті та дискового I/O (External Sort Runtime)

### Механізм розрахунку буфера (-S)

GNU `sort` обробляє масиви довільного обсягу за допомогою буфера рядків у пам'яті:

1. **Динамічний розрахунок за замовчуванням:** якщо опцію `-S` не вказано, утиліта звертається до системного інтерфейсу ядра (через виклики `sysconf(_SC_AVPHYS_PAGES)` або читання `/proc/meminfo`) для визначення доступної фізичної пам'яті. Виділяється приблизно 80% вільного простору RAM, щоб запобігти витісненню інших процесів у swap.
2. **Структура внутрішньої пам'яті:** Пам'ять буфера ділиться між масивом сирих байтів рядків та масивом вказівників на структури рядків (`struct line`). На кожен рядок витрачається від 16 до 24 байтів службових метаданих (вказівник на початок тексту, довжина, ключові зміщення).
3. **Кількість генерованих серій:** Загальна кількість проміжних файлів серій `M` становить:
   ```
   M = ceil( Розмір_Даних / Розмір_Буфера )
   ```
   Якщо буфер встановлено занадто малим (наприклад, 10 МБ для 100 ГБ файлу), утворюється 10 000 серій, що спричиняє масові накладні витрати на дисковий I/O та багаторівневе проміжне злиття.

### Керування тимчасовими каталогами (-T) та балансування I/O

Під час заповнення буфера пам'яті відсортований блок скидається у тимчасовий файл, створений системним викликом `mkstemp()` у каталозі `$TMPDIR` або `/tmp`.

> [!WARNING]
> У більшості дистрибутивів Linux каталог `/tmp` монтується як віртуальна пам'ять `tmpfs`. Спроба відсортувати файл обсягом 100 ГБ на машині з 32 ГБ RAM зі скиданням серій у `/tmp` призведе до аварійного завершення процесу з помилкою `sort: write failed: /tmp/sortXXXXXX: No space left on device`.

Для усунення цієї проблеми слід явно перенаправляти тимчасові серії на дискові накопичувачі:

```bash
# Розподіл серій між двома незалежними NVMe-дисками (round-robin I/O striping)
sort -T /mnt/nvme0/tmp -T /mnt/nvme1/tmp -S 8G huge_dataset.csv -o sorted.csv
```

### Стиснення проміжних файлів серій (--compress-program)

Опція `--compress-program=PROG` інтегрує потокове стиснення на етапі запису тимчасових серій на диск:

1. **Контракт взаємодії з процесом компресора:**
   - **Запис серії (Compression):** `sort` створює дочірній процес викликом `execvp("PROG", ...)`. Дані передаються через анонімний канал `pipe` на `stdin` компресора, а його `stdout` спрямовується у тимчасовий файл.
   - **Фаза k-way злиття (Decompression):** `sort` відкриває тимчасовий файл, перенаправляє його на `stdin` дочірнього процесу, викликаного як `PROG -d`, і зчитує розпакований потік рядків через канал зі `stdout`.
2. **Вибір компресора та інженерний компроміс:**
   - Важкі алгоритми (`bzip2`, `xz`, стандартний `gzip`) є CPU-bound вузьким місцем і можуть сповільнити сортування у 3–5 разів.
   - Швидкісні потокові компресори (`lz4`, `zstd -1`, `lzop`) забезпечують швидкість компресії понад 500 МБ/с на ядро, зменшуючи фізичний обсяг дискового запису у 2–4 рази без просідання загальної швидкості сортування.

```bash
# Високопродуктивне сортування з надшвидким стисненням серій через lz4
sort -S 4G -T /var/scratch --compress-program=lz4 huge_log.txt -o huge_log.sorted.txt
```

### Багаторівневе злиття та ліміт файлових дескрипторів (--batch-size)

Коли кількість тимчасових файлів серій перевищує значення `--batch-size` (за замовчуванням 32), процес не може відкрити всі файли одночасно через обмеження дескрипторів ядра `RLIMIT_NOFILE`.

У цьому разі `sort` перемикається на багаторівневе ієрархічне злиття:
1. Серії об'єднуються групами по N файлів (де N = `batch-size`).
2. Для кожної групи створюється новий проміжний тимчасовий файл більшого розміру.
3. Процес повторюється ієрархічно, доки загальна кількість файлів не зменшиться до величини, меншої або рівної `batch-size`, після чого виконується фінальне k-way злиття у вихідний потік.

### Багатопотокова паралелізація (--parallel)

Опція `--parallel=N` активує багатопотокову модель:
- **Фаза генерації серій:** завантажений у пам'ять блок рядків розбивається між N потоками, кожен із яких паралельно сортує свій сегмент алгоритмом швидкого сортування, після чого виконується локальне паралельне злиття в межах RAM.
- **Фаза k-way злиття:** побудова турнірного дерева злиття та розбір черг введення-виведення також масштабуються на кілька процесорних ядер.

## 7. Повна специфікація параметрів утиліти uniq

Утиліта `uniq` видаляє або знаходить суміжні дублікати рядків у вхідному потоці.

```bash
uniq [ОПЦІЯ]... [ВХІД [ВИХІД]]
```

| Опція | Довга назва | Тип аргументу | Опис та системна поведінка |
|---|---|---|---|
| `-c` | `--count` | Немає | Додає на початку кожного вихідного рядка число його входжень у вхідному потоці. Формат вирівнювання за стандартом POSIX містить пробіли для створення фіксованого стовпця: `"%7lu %s\n"`. Якщо кількість входжень перевищує 9 999 999, поле автоматично розширюється без утинання числа. |
| `-d` | `--repeated` | Немає | Виводить виключно ті рядки, які зустрічаються два або більше разів підряд. Для кожної групи дублікатів друкується рівно один екземпляр. Унікальні рядки повністю відкидаються. |
| `-D` | `--all-repeated[=METHOD]` | Метод групування | Виводить усі екземпляри повторюваних рядків (включно з усіма копіями). Необов'язковий аргумент `METHOD` визначає візуальне розділення груп: `none` (за замовчуванням — без розділювачів), `prepend` (порожній рядок перед кожною групою дублікатів), `separate` (порожній рядок між групами дублікатів). |
| `-u` | `--unique` | Немає | Виводить виключно унікальні рядки (кількість суміжних входжень яких дорівнює рівно 1). Рядки, що мали хоча б один суміжний дублікат, повністю відкидаються. |
| `-i` | `--ignore-case` | Немає | Регістронезалежне порівняння: рядки, що відрізняються лише регістром символів (`"Alpha"` та `"alpha"`), вважаються ідентичними. |
| `-f` | `--skip-fields=N` | Ціле число (>= 0) | Пропускає перші `N` полів перед початком порівняння. Полем вважається неперервна послідовність непробільних символів, відокремлена пробілами або знаками табуляції. На відміну від `sort`, `uniq` не підтримує вибір довільного роздільника `-t`. Якщо в рядку менше ніж `N` полів, порівнюється порожній залишок рядка. |
| `-s` | `--skip-chars=N` | Ціле число (>= 0) | Пропускає перші `N` символів рядка (або перші `N` символів після полів, пропущених через `-f`) перед виконанням порівняння. |
| `-w` | `--check-chars=N` | Ціле число (>= 0) | Обмежує порівняння першими `N` символами рядка (з урахуванням зсувів після `-f` та `-s`). Символи після позиції `N` повністю ігноруються при оцінці еквівалентності. |
| `-z` | `--zero-terminated` | Немає | Встановлює нульовий байт `\0` як роздільник вхідних та вихідних записів замість символу переведення рядка `\n`. |

### Режими групування всіх дублікатів (-D / --all-repeated)

Опція `-D` має три режими візуального відокремлення груп повторень:

1. **`--all-repeated=none` (або просто `-D`):** Усі копії дубльованих рядків друкуються суцільним потоком без додаткових символів нового рядка.
2. **`--all-repeated=prepend`:** Перед кожною групою повторюваних рядків (включаючи найпершу групу у виводі) процесор друкує один порожній рядок `\n`.
3. **`--all-repeated=separate`:** Порожній рядок друкується виключно **між** групами дублікатів (перед першою групою порожній рядок не додається).

```bash
# Приклад аналізу повторень у відсортованому списку:
# alpha
# beta
# beta
# gamma
# gamma
# gamma

uniq -D --all-repeated=separate list.txt
# Вивід:
# beta
# beta
#
# gamma
# gamma
# gamma
```

### Матриця взаємодії та поведінки фільтраційних опцій uniq

На тестовому вхідному масиві з чотирьох записів:
```
apple
banana
banana
cherry
```

| Комбінація опцій | Згенерований вивід | Логіка фільтрації |
|---|---|---|
| *(без опцій)* | `apple`<br>`banana`<br>`cherry` | Стандартна дедуплікація: суміжні дублікати згортаються в один запис. |
| `-c` | `      1 apple`<br>`      2 banana`<br>`      1 cherry` | Підрахунок суміжних входжень з форматуванням кількості. |
| `-d` | `banana` | Вивід рівно одного екземпляра кожної групи дублікатів. |
| `-D` (`-D --all-repeated=none`) | `banana`<br>`banana` | Вивід усіх наявних копій повторюваних рядків. |
| `-u` | `apple`<br>`cherry` | Вивід виключно унікальних записів, що не мали дублікатів. |
| `-c -d` | `      2 banana` | Підрахунок кількості повторень лише для дубльованих записів. |
| `-c -u` | `      1 apple`<br>`      1 cherry` | Підрахунок кількості лише для суворо унікальних записів. |
| `-d -u` | *(порожній вивід)* | Взаємно виключні фільтри: рядків, що одночасно є унікальними та повторюваними, не існує. |

## 8. Повна специфікація утиліти shuf: генерація перестановок і вибірок

Утиліта `shuf` генерує випадкові перестановки вхідних рядків або формує випадкові вибірки з поверненням чи без повернення.

```bash
# Режим 1: Перемішування рядків файлу або стандартного вводу
shuf [ОПЦІЯ]... [ФАЙЛ]

# Режим 2: Перемішування позиційних аргументів командного рядка
shuf -e [ОПЦІЯ]... [АРГУМЕНТ]...

# Режим 3: Перемішування цілочисельного діапазону
shuf -i LO-HI [ОПЦІЯ]...
```

### Взаємовиключні режими джерела даних

Три режими джерела вхідних даних є строго взаємовиключними:
1. **Файловий вхід (за замовчуванням):** зчитує рядки з вказаного файлу або зі `stdin` (якщо файл не вказано або передано `-`).
2. **Аргументний режим (`-e` / `--echo`):** розглядає кожен наступний позиційний аргумент командного рядка як окремий вхідний рядок.
3. **Числовий інтервал (`-i LO-HI` / `--input-range=LO-HI`):** розглядає кожне десяткове ціле число в діапазоні від `LO` до `HI` (включно) як окремий вхідний рядок. Числа `LO` та `HI` мають бути невід'ємними цілими числами, що задовольняють умову `0 <= LO <= HI <= UINTMAX_MAX`.

Спроба одночасного використання `-e` та `-i` або передача позиційного імені файлу разом із цими прапорцями призводить до помилки парсингу аргументів: `shuf: cannot combine -e and -i options` або `shuf: extra operand` із завершенням процесу з кодом `1`.

### Таблиця параметрів shuf

| Опція | Довга назва | Тип аргументу | Опис та системна поведінка |
|---|---|---|---|
| `-e` | `--echo` | Немає | Трактує кожен наступний аргумент командного рядка як окремий вхідний рядок. Не може поєднуватися з `-i` або з аргументами вхідних файлів. |
| `-i` | `--input-range=LO-HI` | Діапазон `LO-HI` | Генерує псевдовипадкову послідовність цілих чисел від `LO` до `HI` включно. Якщо `LO > HI`, утиліта аварійно завершується з повідомленням `invalid input range`. |
| `-n` | `--head-count=COUNT` | Ціле число (>= 0) | Обмежує вивід щонайбільше `COUNT` випадковими рядками. Якщо `COUNT == 0`, утиліта зчитує/валідує вхідні дані, але не виводить жодного рядка. Якщо `COUNT` перевищує загальну кількість елементів, виводяться всі елементи у випадковому порядку (за відсутності прапорця `-r`). |
| `-o` | `--output=FILE` | Шлях до файлу | Записує результат у вказаний файл замість `stdout`. Файл відкривається на запис лише після повного зчитування вхідних даних, що гарантує безпечне перемішування файлу «на місці»: `shuf -o list.txt list.txt`. |
| `-r` | `--repeat` | Немає | Дозволяє повторення вихідних рядків (вибірка з поверненням / sampling with replacement). Якщо опцію `-n` не задано разом із `-r`, утиліта генерує **нескінченний потік** випадкових рядків до примусового переривання сигналом (`SIGPIPE` або `SIGINT`). |
| `-z` | `--zero-terminated` | Немає | Встановлює нульовий байт `\0` як роздільник вхідних та вихідних записів замість `\n`. |
| `--random-source=FILE` | `--random-source=FILE` | Шлях до файлу | Зчитує байти випадковості з вказаного файлу чи пристрою замість системного генератора ядра `getrandom()`. Використовується для детермінованого та відтворюваного тестування. |

### Внутрішні алгоритми та керування оперативною пам'яттю

GNU `shuf` оптимізує споживання ресурсів відповідно до переданих параметрів та джерела вхідних даних:

1. **Алгоритм Фішера–Йетса (Knuth Shuffle) у пам'яті:**
   - Застосовується, коли вхідні дані надходять із файлу або аргументів, і потрібна повна перестановка всіх рядків.
   - Утиліта зчитує всі рядки в пам'ять, формує масив покажчиків довжиною `N` і виконує перестановку за `N - 1` ітерацій: на кроці `i` (від `N-1` до 1) обирається випадковий індекс `j ∈ [0, i]`, і елементи `array[i]` та `array[j]` міняються місцями.
   - Часова складність: строго `O(N)`. Просторова пам'ять: `O(N)` для зберігання рядків та таблиці покажчиків.
2. **Алгоритм резервуарної вибірки (Reservoir Sampling / Algorithm R):**
   - Автоматично активується, коли дані зчитуються з нескінченного або невідомого за розміром потоку `stdin` (каналу pipe), і задано параметр `-n K` (де `K` суттєво менше за загальну кількість рядків `N`).
   - Утиліта виділяє буфер (резервуар) строго під `K` рядків. Перші `K` рядків потоку заповнюють резервуар. Кожен наступний `i`-й рядок (`i > K`) замінює випадковий елемент резервуара з імовірністю `K / i`.
   - Це дозволяє вибрати випадкові 100 рядків із 50-гігабайтного потоку за один прохід, споживаючи лише кілька кілобайтів RAM замість гігабайтів пам'яті.
3. **Генерація числового діапазону `-i LO-HI`:**
   - Для генерації чисел утиліта не створює рядкові представлення в пам'яті заздалегідь.
   - Якщо діапазон великий (наприклад, `-i 1-1000000000 -n 5`), утиліта генерує 5 випадкових чисел без виділення пам'яті під мільярд текстових записів.
4. **Нескінченна генерація (`-r`):**
   - Утиліта завантажує доступні варіанти в масив і в нескінченному циклі генерує псевдовипадковий індекс `idx ∈ [0, N-1]`, друкуючи відповідний рядок з часовою складністю `O(1)` на кожен згенерований елемент.

### Відмінність між shuf та sort -R

| Характеристика | `shuf` | `sort -R` (`--random-sort`) |
|---|---|---|
| **Принцип роботи** | Повноцінне рівномірне випадкове перемішування рядків або вибірка. | Хешування ключів з випадковою сіллю (keyed hash). |
| **Групування однакових рядків** | **Порушується:** однакові рядки розкидаються по різних випадкових позиціях. | **Зберігається:** однакові рядки завжди мають однаковий хеш і виводяться суміжним блоком. |
| **Вибірка підмножини (`-n`)** | Підтримується безпосередньо з `O(K)` пам'яті (Reservoir Sampling). | Не підтримується (потребує передачі через конвеєр у `head`). |
| **Генерація повторень (`-r`)** | Підтримується (sampling with replacement). | Відсутня. |

## 9. Повна специфікація утиліти comm: порівняння двох відсортованих потоків

Утиліта `comm` виконує швидке порядкове зіставлення двох попередньо відсортованих файлів і розділяє результати на три категорії (стовпці).

```bash
comm [ОПЦІЯ]... ФАЙЛ1 ФАЙЛ2
```

### Архітектурна модель та вивід у три стовпці

`comm` одночасно відкриває `ФАЙЛ1` та `ФАЙЛ2` і переміщує два покажчики рядків зліва направо. За замовчуванням вивід формується у вигляді трьох текстових стовпців, розділених символом табуляції `\t`:

```
[Стовпець 1] \t [Стовпець 2] \t [Стовпець 3]
```

- **Стовпець 1:** рядки, наявні виключно у `ФАЙЛ1` (відсутні у `ФАЙЛ2`).
- **Стовпець 2:** рядки, наявні виключно у `ФАЙЛ2` (відсутні у `ФАЙЛ1`). Рядок має префікс з одного символу табуляції `\t`.
- **Стовпець 3:** рядки, спільні для обох файлів. Рядок має префікс із двох символів табуляції `\t\t`.

### Таблиця параметрів comm

| Опція | Довга назва | Тип аргументу | Опис та системна поведінка |
|---|---|---|---|
| `-1` | — | Немає | Пригнічує вивід стовпця 1 (рядки, унікальні для `ФАЙЛ1`). |
| `-2` | — | Немає | Пригнічує вивід стовпця 2 (рядки, унікальні для `ФАЙЛ2`). |
| `-3` | — | Немає | Пригнічує вивід стовпця 3 (рядки, спільні для обох файлів). |
| `--check-order` | `--check-order` | Немає | Суворо перевіряє, чи правильно відсортовані обидва вхідні файли відповідно до активної локалі `LC_COLLATE`. Якщо виявлено порушення порядку сортування, утиліта виводить помилку у `stderr` і завершує роботу з кодом `1`. У GNU Coreutils це є поведінкою за замовчуванням. |
| `--nocheck-order` | `--nocheck-order` | Немає | Вимикає перевірку впорядкованості вхідних файлів. Утиліта продовжує двохвказівникове порівняння рядків навіть у разі порушення порядку, видаючи часткові результати до вичерпання файлів. |
| `--output-delimiter=STR` | `--output-delimiter=STR` | Рядок | Замінює стандартний символ табуляції `\t` між стовпцями на вказаний рядок `STR`. Якщо передано порожній рядок `--output-delimiter=""`, стовпці зливаються без відступів. |
| `-z` | `--zero-terminated` | Немає | Встановлює нульовий байт `\0` як роздільник вхідних та вихідних записів замість `\n`. |

### Реалізація операцій теорії множин

Комбінації прапорців пригнічення `-1`, `-2`, `-3` дозволяють реалізувати всі класичні операції над множинами `A` (`ФАЙЛ1`) та `B` (`ФАЙЛ2`):

```bash
# Перетин множин A ∩ B (лише спільні елементи)
comm -12 fileA.sorted fileB.sorted

# Різниця множин A \ B (елементи, присутні виключно в A)
comm -23 fileA.sorted fileB.sorted

# Різниця множин B \ A (елементи, присутні виключно в B)
comm -13 fileA.sorted fileB.sorted

# Симетрична різниця (A \ B) ∪ (B \ A) (елементи, присутні в одному з файлів, але не в обох)
comm -3 fileA.sorted fileB.sorted
```

### Обробка мультимножин (повторювані рядки)

Якщо вхідні файли містять дублікати рядків, `comm` зіставляє їх за принципом мультимножин:
- Якщо рядок `X` зустрічається `K1` разів у `ФАЙЛ1` та `K2` разів у `ФАЙЛ2`:
  - `min(K1, K2)` екземплярів виводяться у стовпець 3 (спільні).
  - Якщо `K1 > K2`, то `K1 - K2` залишкових екземплярів виводяться у стовпець 1.
  - Якщо `K2 > K1`, то `K2 - K1` залишкових екземплярів виводяться у стовпець 2.

### Вимоги до сортування та локалей

Обидва вхідні файли повинні бути відсортовані за **абсолютно однаковими** правилами коллації, які використовуються під час виклику `comm`.

> [!WARNING]
> Якщо `fileA` був відсортований командою `LC_ALL=C sort`, а `fileB` — командою `sort` у локалі `en_US.UTF-8`, виклик `comm fileA fileB` завершиться помилкою `comm: file 2 is not in sorted order` або призведе до пропуску спільних рядків. Конвеєри порівняння слід завжди виконувати в єдиній локалі `LC_ALL=C`.

```bash
# Ідіоматичне та безпечне порівняння через Process Substitution
LC_ALL=C comm -12 <(LC_ALL=C sort list1.txt) <(LC_ALL=C sort list2.txt)
```

## 10. Повна специфікація утиліти tsort: топологічне сортування спрямованих графів

Утиліта `tsort` виконує топологічне сортування орієнтованого графа (Directed Acyclic Graph, DAG), заданого у вигляді потоку пар вершин.

```bash
tsort [ОПЦІЯ] [ФАЙЛ]
```

### Формат вхідного потоку та граматика токенів

Вхідний потік утиліти `tsort` розглядається як неперервна послідовність текстових токенів (імен вершин графа), відокремлених будь-якою комбінацією пробільних символів (пробіли, знаки табуляції, символи нового рядка `\n`):

1. **Токени об'єднуються у пари:** кожні два послідовні токени `U` та `V` утворюють спрямовану дугу графа `U -> V`, яка декларує, що елемент `U` повинен передувати елементу `V` у підсумковому топологічному порядку (тобто `U` є передумовою або залежністю для `V`).
2. **Непарна кількість токенів:** Якщо загальна кількість токенів у вхідному потоці є непарною, граф є синтаксично некоректним. `tsort` виводить у `stderr` повідомлення `tsort: input contains an odd number of tokens` і негайно завершує роботу з кодом `1`.
3. **Ізольовані вершини та петлі (`A A`):** Для включення до графа вершини `A`, яка не має залежностей і від якої ніщо не залежить, використовується стандартна ідіома петлі: пара `A A`. `tsort` розпізнає таку пару як декларацію існування вершини `A`, не створюючи циклічного блокування.

```
# Приклад вхідного файлу graph.txt (залежності збирання модулів):
# libc.a     main.o
# libm.a     physics.o
# physics.o  main.o
# config.h   config.h
```

### Алгоритм топологічного сортування (Алгоритм Кана)

GNU `tsort` реалізує алгоритм Кана:

1. **Побудова графа:** Процес зчитує всі пари, формує списки суміжності `adj[U]` та підраховує степінь входу `in_degree[V]` (кількість спрямованих дуг, що входять у вершину `V`).
2. **Черга джерел:** Усі вершини зі степенем входу `in_degree == 0` (вершини без попередніх залежностей) поміщаються у чергу обробки.
3. **Ітеративне розгортання:**
   - З черги вилучається вершина `U` і друкується у `stdout`.
   - Для кожної суміжної вершини `V ∈ adj[U]` значення `in_degree[V]` зменшується на 1.
   - Якщо `in_degree[V]` стає рівним 0, вершина `V` додається до черги.
4. **Завершення:** Процес триває до повного спорожнення черги.

### Виявлення та евристика розриву циклів (Cycle Detection & Breaking)

Якщо граф містить циклічні залежності (наприклад, `A -> B -> C -> A`), степені входу вершин циклу ніколи не зменшаться до 0 за стандартними правилами:

1. Коли черга вершин з `in_degree == 0` порожня, але в графі залишаються невиведені вершини, `tsort` фіксує наявність одного або декількох циклів.
2. Для кожного виявленого циклу утиліта виводить у `stderr` діагностичний ланцюг заблокованих вершин:
   ```
   tsort: graph.txt: input contains a loop:
   tsort: graph.txt: A
   tsort: graph.txt: B
   tsort: graph.txt: C
   ```
3. **Евристика розриву циклу:** Щоб не блокувати виконання системних конвеєрів, `tsort` примусово вибирає одну з вершин циклу, виводить її у `stdout`, видаляє всі її вихідні ребра (розриваючи петлю) і продовжує топологічне сортування для залишку графа.
4. Після завершення обробки всього потоку процес завершує роботу з ненульовим кодом `1`.

### Історичне походження та практичне призначення

Утиліта `tsort` була створена для розв'язання задачі оптимального порядку об'єднання об'єктних файлів (`.o`) у статичні бібліотечні архіви (`.a`) утилітою `ar`. Ранні однопрохідні компонувальники Unix (`ld`) не мали таблиць глобальних символів (`ranlib`) і сканували архіви послідовно від початку до кінця. Якщо функція з файлу `A.o` викликала функцію з `B.o`, файл `A.o` обов'язково мав передувати `B.o` в архіві.

У сучасних системах `tsort` застосовується для:
- Визначення черговості компіляції модулів у системах збирання.
- Розрахунку порядку встановлення системних пакунків з урахуванням взаємних залежностей.
- Визначення порядку застосування SQL-міграцій реляційних баз даних із зовнішніми ключами.

## 11. Вплив локалей, підсистеми коллації та змінних середовища

Поведінка утиліт `sort`, `uniq` та `comm` критично залежить від змінних середовища міжнародної локалізації POSIX:

```
LC_ALL > LC_COLLATE / LC_CTYPE / LC_NUMERIC / LC_TIME > LANG
```

### Ланцюг пріоритетів та призначення категорій

1. `LC_ALL`: якщо встановлена, перекриває значення всіх інших категорій `LC_*` та `LANG`.
2. `LC_COLLATE`: визначає правила алфавітного порядку, ваги символів, обробку діакритики та чутливість до пунктуації при виклику системної функції `strcoll()`.
3. `LC_CTYPE`: визначає кодування символів (наприклад, однобайтове ASCII чи багатобайтове UTF-8), класифікацію символів (букви, цифри, пробіли) та коректні межі символів для зміщень `-s` і `-w`.
4. `LC_NUMERIC`: визначає символ десяткового роздільника (крапка `.` чи кома `,`) та групування розрядів для числових парсерів `-n`, `-g`, `-h`.
5. `LC_TIME`: визначає мовні назви місяців для прапорця `-M`.
6. `TMPDIR`: шлях до каталогу розміщення тимчасових файлів скидання серій за відсутності прапорця `-T`.

### Механізм LC_ALL=C (POSIX) проти багатомовних UTF-8 локалей

Під час роботи в середовищі стандартної локалі (наприклад, `en_US.UTF-8` або `uk_UA.UTF-8`) та в середовищі базової локалі `C` (або `POSIX`) задіюються принципово різні механізми ядра та бібліотеки `glibc`:

```
Локаль C / POSIX:
Рядки  ───►  memcmp()  ───►  Пряме порівняння байтових значень (0x00 .. 0xFF)

Локаль UTF-8:
Рядки  ───►  strcoll() ───►  Багаторівневі ваги таблиць Unicode Collation Algorithm (UCA)
```

| Характеристика | `LC_ALL=C` / `LC_ALL=POSIX` | Багатомовні локалі (`en_US.UTF-8`, `uk_UA.UTF-8`) |
|---|---|---|
| **Функція порівняння** | Апаратне побайтове сканування `memcmp()`. | Багатопрохідне обчислення `strcoll()` / `wcscoll()`. |
| **Швидкодія** | Максимальна (у 5–10 разів швидше за UTF-8). | Низька (через складний розбір ваг юнікодних символів). |
| **Врахування регістру** | Чіткий порядок ASCII: всі великі літери передують малим (`A` < `Z` < `a` < `z`). | Букви однакової назви групуються разом: `a` < `A` < `b` < `B`. |
| **Пунктуація та пробіли** | Символи пунктуації мають фіксовані коди ASCII (`0x20`–`0x2F`) і завжди враховуються. | Багато мовних правил коллації ігнорують знаки пунктуації на першому рівні порівняння. |
| **Детермінованість** | 100% ідентичний результат на будь-яких ОС та архітектурах CPU. | Результат залежить від версії бібліотеки `glibc` та файлів локалей конкретної ОС. |

### Пастка еквівалентності пунктуації в UTF-8 конвеєрах

У деяких версіях системних локалей `en_US.UTF-8` алгоритм коллації ігнорує дефіси та пробіли на первинному рівні зважування. Через це рядки `"foo-bar"` та `"foo bar"` можуть бути визнані еквівалентними при сортуванні за ключем.

Якщо такий потік передається утиліті `uniq` чи `comm`, виникає спотворення даних. Для гарантованої детермінованої роботи системних скриптів та максимальної швидкодії конвеєрів слід завжди явно встановлювати `LC_ALL=C`:

```bash
# Гарантовано швидке та детерміноване сортування
LC_ALL=C sort -k1,1 -u input.txt
```

## 12. Обробка системних сигналів, безпека та очищення ресурсів

Під час виконання зовнішнього сортування `sort` створює на файловій системі проміжні файли. Для запобігання витоку дискового простору та вразливостей спільного доступу реалізовано такі інженерні гарантії:

1. **Безпечне створення тимчасових файлів:**
   - Кожен тимчасовий файл створюється викликом `mkstemp()` або викликом `openat()` із прапорцями `O_RDWR | O_CREAT | O_EXCL`.
   - Файли створюються з маскою прав доступу `0600` (читання та запис дозволено виключно власнику процесу), що унеможливлює несанкціонований доступ інших користувачів системи у каталозі `/tmp`.
2. **Перехоплення системних сигналів (Signal Handling):**
   - Процес реєструє власні обробники для сигналів переривання та завершення: `SIGINT`, `SIGTERM`, `SIGHUP`, `SIGPIPE`.
   - У разі надходження сигналу обробник ітерує глобальний список активних тимчасових файлів і викликає системний виклик `unlink()` для кожного з них, після чого процес відновлює стандартну поведінку сигналу та завершує роботу.
3. **Обробка розриву конвеєра (`SIGPIPE`):**
   - Якщо `sort` або `shuf -r` працює у конвеєрі, кінець якого достроково закриває дескриптор читання (наприклад, `sort access.log | head -n 10` або `shuf -r -i 1-100 | head -n 5`), спроба запису у закритий канал генерує сигнал `SIGPIPE`.
   - Обробник перехоплює `SIGPIPE`, негайно видаляє всі згенеровані файли серій із диска і коректно завершує процес, не залишаючи сміття у каталозі тимчасових файлів.

## 13. Діагностика через --debug та системне трасування strace

### Вбудований діагностичний режим sort --debug

Прапорець `--debug` дозволяє візуалізувати виділення ключів та виявити помилки в аргументах:

```bash
sort --debug -t: -k2,2n -k1,1 /etc/passwd
```

У виводі утиліта демонструє:
- Поточну активну локаль коллації (наприклад, `sort: using ‘en_US.UTF-8’ sorting rules`).
- Попередження про взаємно суперечливі або неефективні опції (наприклад, попередження про те, що опція `-n` не діє через наявність опції `-M`).
- Підкреслення символами `^` точних меж підрядків, виділених для кожного специфікатора `-k` у перших рядках вхідного файлу.

### Системне трасування викликів утиліти через strace

За допомогою системного трасувальника `strace` можна спостерігати всі низькорівневі етапи роботи утиліти `sort`:

```bash
strace -f -e trace=mmap,openat,unlink,clone,read,write sort -S 100M -T /tmp/sort_test large.txt -o out.txt
```

Під час виконання фіксуються такі характерні виклики ядра:
- `mmap(NULL, 104857600, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0)` — виділення буфера RAM розміром 100 МіБ.
- `openat(AT_FDCWD, "/tmp/sort_test/sortXXXXXX", O_RDWR|O_CREAT|O_EXCL, 0600)` — створення файлів тимчасових серій.
- `clone(...)` або `clone3(...)` — створення дочірніх робочих потоків при використанні багатопотоковості.
- `unlink("/tmp/sort_test/sortXXXXXX")` — видалення тимчасового файлу після зчитування даних у фазі k-way злиття.

## 14. Коди завершення процесів (Exit Codes)

Утиліти повертають стандартизовані коди завершення, що використовуються для обробки помилок у shell-скриптах:

| Код повернення | Утиліти | Причина завершення та семантика |
|---|---|---|
| `0` | `sort`, `uniq`, `shuf`, `comm`, `tsort` | Успішне завершення без помилок. У режимі верифікації (`sort -c`, `sort -C`, `comm --check-order`) — вхідні файли повністю відповідають вимогам порядку. Для `tsort` — граф не містить циклів і має парну кількість токенів. |
| `1` | `sort` | Порушення порядку сортування (при виклику з перевірочними прапорцями `-c` або `-C`). Також повертається, якщо в режимі `-u` виявлено суміжний дублікат при перевірці. |
| `1` | `comm` | Порушення порядку сортування одного з вхідних файлів при увімкненому прапорці `--check-order`. |
| `1` | `tsort` | Виявлено циклічну залежність (loop) у графі або виявлено непарну кількість токенів у вхідному потоці. |
| `1` | `shuf` | Синтаксична помилка виклику (наприклад, одночасне використання взаємовиключних параметрів `-e` та `-i`, некоректний числовий діапазон `LO > HI` або неприпустиме значення для `-n`). |
| `1` | `uniq` | Синтаксична помилка або несумісність параметрів у класичних реалізаціях Unix. |
| `2` | `sort`, `uniq`, `shuf`, `comm`, `tsort` | Фатальна системна помилка введення-виведення: неможливість відкрити або прочитати файл (`ENOENT`, `EACCES`), переповнення дискового простору (`ENOSPC`), вичерпання віртуальної пам'яті (`ENOMEM`), збій запису у вихідний файл або некоректний синтаксис специфікатора `-k`. |
| `> 128` | `sort`, `uniq`, `shuf`, `comm`, `tsort` | Аварійне завершення процесу системним сигналом (`128 + номер сигналу`, наприклад, `130` для `SIGINT` або `141` для `SIGPIPE`). |

## 15. Практичні рецепти викликів та комплексні сценарії

### Сценарій 1: Багаторівневе сортування веб-логів Nginx/Apache

Вхідний формат логу: `IP-адреса [Час] "HTTP_МЕТОД URL" HTTP_КОД БАЙТИ`

```bash
# Завдання: відсортувати за HTTP-кодом (стовпець 9, число), 
# а для однакових кодів — за обсягом переданих байтів (стовпець 10, число за спаданням)
LC_ALL=C sort -t' ' -k9,9n -k10,10nr access.log -o access.sorted.log
```

### Сценарій 2: Дедуплікація та топ-10 IP-адрес у багатогігабайтному масиві

```bash
# Оптимізований конвеєр з паралелізмом, буферизацією та побайтовою коллацією
LC_ALL=C awk '{print $1}' access.log | \
  LC_ALL=C sort -S 4G --parallel=8 | \
  LC_ALL=C uniq -c | \
  LC_ALL=C sort -k1,1nr | \
  head -n 10
```

### Сценарій 3: Сортування за обсягом дискового простору (Human-Readable)

```bash
# Сортування виводу du за зменшенням зайнятого місця з урахуванням суфіксів K, M, G, T
du -h --max-depth=1 /var | LC_ALL=C sort -k1,1hr
```

### Сценарій 4: Впорядкування версій пакунків (Natural / Version Sort)

```bash
# Правильне ранжування релізів з версіями 1.2, 1.10 та pre-release суфіксами ~rc
printf '%s\n' "pkg-1.2.tar.gz" "pkg-1.10.tar.gz" "pkg-1.2~rc1.tar.gz" | LC_ALL=C sort -V
```

### Сценарій 5: Дедуплікація CSV-файлу за вторинним стовпцем зі збереженням первинного запису

```bash
# CSV-файл: user_id,email,registration_date
# Завдання: залишити лише один запис для кожного унікального email (стовпець 2)
# -s забезпечує стабільність (зберігається перший знайдений запис)
LC_ALL=C sort -t, -k2,2 -u -s users.csv -o unique_users.csv
```

### Сценарій 6: Пошук дублікатів файлів за хеш-сумами SHA-256

```bash
# Обчислення хешів, сортування за першим полем (хеш) 
# та вивід усіх груп повторюваних файлів з візуальним роздільником
sha256sum /storage/* | \
  LC_ALL=C sort -k1,1 | \
  uniq -w64 -D --all-repeated=separate
```

### Сценарій 7: Безпечна обробка довільних шляхів файлової системи

```bash
# Пошук, сортування та видалення дублікатів шляхів, що містять пробіли або нові рядки
find /data -type f -print0 | \
  LC_ALL=C sort -z -u | \
```

### Сценарій 8: Випадкова вибірка контрольної підмножини (Reservoir Sampling через shuf)

```bash
# Вибірка 1000 випадкових транзакцій із 50-гігабайтного потоку без виділення пам'яті під весь файл
cat /var/log/transactions.csv | shuf -n 1000 -o sample_1k.csv
```

### Сценарій 9: Генерація криптостійких випадкових паролів та токенів

## 16. Сумісність та відмінності реалізацій: POSIX, GNU Coreutils та BSD / macOS

Під час портування системних скриптів між Linux, FreeBSD, OpenBSD та macOS слід враховувати відмінності у наборі підтримуваних параметрів утиліт:

| `sort -c, -C` | Так | Так | Так |

| `sort -h` (Human numeric) | Ні (розширення) | Так | Так (сучасні FreeBSD/macOS) |

| `sort --compress-program` | Ні (розширення) | Так | Відсутнє |

### Застарілий синтаксис визначення позицій sort (+POS1 -POS2)

У ранніх версіях Unix (V7, System V) поля визначалися через відносні зміщення: `sort +1 -2 file.txt`.
- `+1` означало «пропустити 1 поле» (тобто почати з 2-го поля, 0-індексація зміщення).
- `-2` означало «зупинитися перед 2-м полем» (тобто обмежити вибірку 2-м полем).
- Цей синтаксис повністю еквівалентний сучасному стандарту `sort -k 2,2`.
- Стандарт POSIX оголосив запис `+POS` застарілим. Сучасний GNU `sort` підтримує його лише за умови встановлення змінної середовища `_POSIX2_VERSION=199209`. У нових скриптах слід використовувати виключно специфікатор `-k`.
