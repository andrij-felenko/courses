# Довідник інтерфейсу утиліт sort і uniq

Специфікація параметрів командного рядка, форматів визначення ключів, змінних середовища, поведінки системних сигналів та кодів завершення системних фільтрів `sort` і `uniq` у середовищі POSIX і GNU Coreutils.

## 1. Синопсис виклику та базова модель потоків

Утиліти `sort` і `uniq` належать до базового набору текстових фільтрів стандарту POSIX. Вони спроектовані для безшовної інтеграції у конвеєри операційної системи через стандартні дескриптори вводу-виводу (`stdin`, `stdout`, `stderr`).

```bash
# Синтаксис виклику sort
sort [ОПЦІЯ]... [ФАЙЛ]...
sort [-c | -C] [ОПЦІЯ]... [ФАЙЛ]

# Синтаксис виклику uniq
uniq [ОПЦІЯ]... [ВХІД [ВИХІД]]
```

Якщо аргумент `ФАЙЛ` або `ВХІД` не вказано взагалі або передано як одиночний дефіс `-`, процес читає вхідний потік байтів із дескриптора `0` (`stdin`). Якщо утиліті `sort` передано кілька файлів у списку аргументів (`sort file1.txt file2.txt file3.txt`), вона логічно об'єднує їхній вміст у єдину послідовність так, ніби вони були попередньо зчеплені утилітою `cat`, і виконує спільне глобальне сортування.

Якщо у виклику `uniq` не вказано аргумент `ВИХІД`, результат фільтрації спрямовується у дескриптор `1` (`stdout`). Задання позиційного аргументу `ВИХІД` змушує `uniq` відкрити відповідний файл на запис із прапорцями `O_WRONLY | O_CREAT | O_TRUNC`.

## 2. Повна таблиця параметрів утиліти sort

### Керування ресурсами, буферизацією та тимчасовими файлами

Утиліта `sort` відрізняється від більшості лінійних Unix-фільтрів тим, що вона є бар'єрною операцією: вона не може видати жодного байта у вихідний потік, доки не зчитає та не впорядкує абсолютно всі вхідні дані. Для обробки масивів, що перевищують розмір RAM, утиліта містить розвинену підсистему керування дисковою підкачкою та пам'яттю.

| Опція | Довга назва | Тип аргументу | Опис та механізм дії |
|---|---|---|---|
| `-S` | `--buffer-size=SIZE` | Число з суфіксом (`K`, `M`, `G`, `T` або `%`) | Задає максимальний обсяг оперативної пам'яті для буфера внутрішнього сортування. При досягненні ліміту заповнений буфер сортується в пам'яті та скидається як тимчасовий блок (run) на диск. За замовчуванням GNU `sort` визначає ліміт динамічно: за наявності системної інформації береться близько 80% доступної фізичної пам'яті, але не менше фіксованого мінімуму (зазвичай 512 КБ). Суфікс `%` задає відсоток від загального обсягу RAM. |
| `-T` | `--temporary-directory=DIR` | Шлях до каталогу | Вказує каталог для розміщення проміжних файлів злиття замість системного `$TMPDIR` або `/tmp`. Опцію можна вказувати багаторазово: утиліта розподілятиме тимчасові файли між заданими каталогами за циклічним алгоритмом round-robin для балансування навантаження на різні дискові контролери. |
| `--parallel=N` | `--parallel=N` | Ціле число | Обмежує кількість одночасно запущених робочих потоків виконання (threads) у процесі. Утиліта розпаралелює фазу внутрішнього сортування завантажених блоків у RAM та обчислення злиття піддерев. За замовчуванням кількість потоків дорівнює значенню, повернутому системним викликом `sysconf(_SC_NPROCESSORS_ONLN)`. |
| `--batch-size=N` | `--batch-size=N` | Ціле число (мін. 2) | Максимальна кількість тимчасових файлів, які процес відкриває одночасно під час однієї фази k-way злиття. Запобігає аварійному завершенню через вичерпання ліміту дескрипторів файлів (`RLIMIT_NOFILE`). Якщо кількість серій перевищує цей ліміт, `sort` автоматично виконує проміжне ієрархічне злиття підгруп серій. |
| `-m` | `--merge` | Немає | Виконує виключно фазу злиття попередньо впорядкованих вхідних файлів. Кожен зазначений файл розглядається як готова відсортована серія. Алгоритм не витрачає час на завантаження та пересортування кожного файлу в пам'яті, а одразу запускає мін-купу, читаючи дані по одному блоку. |
| `-c` | `--check`, `--check=diagnose-first` | Немає | Перевіряє, чи відсортовано вхідний файл за вказаними правилами. У разі виявлення першого ж рядка, що порушує порядок сортування, утиліта виводить у `stderr` номер рядка, ім'я файлу та проблемний текст, після чого негайно завершується з кодом 1 без запису в `stdout`. |
| `-C` | `--check=quiet`, `--check=silent` | Немає | Працює аналогічно до `-c`, але повністю пригнічує будь-який вивід у `stderr`. Повертає статус 0, якщо вхідні дані ідеально відсортовано, і статус 1 при першому ж порушенні послідовності. |
| `-o` | `--output=FILE` | Шлях до файлу | Записує результат у вказаний файл замість `stdout`. На відміну від оболонкового перенаправлення `> file`, опція `-o` відкриває цільовий файл лише після повного завершення читання вхідних даних. Це дозволяє безпечно сортувати файл «на місці» (`sort -o data.txt data.txt`) без ризику його попереднього затирання. |
| `-z` | `--zero-terminated` | Немає | Використовує нульовий байт (`ASCII NUL`, `\0`) як роздільник записів замість символу переведення рядка (`\n`). Забезпечує коректну обробку шляхів до файлів, які містять пробіли, лапки або перенесення рядків, у зв'язці з `find -print0` та `xargs -0`. |

### Визначення ключів та виділення полів

Специфікація ключів дозволяє ізолювати конкретні стовпці або підрядки всередині структурованих записів.

| Опція | Довга назва | Тип аргументу | Опис та механізм дії |
|---|---|---|---|
| `-k` | `--key=KEYDEF` | Специфікатор ключа | Задає позицію початку та необов'язкового кінця ключа сортування у форматі `F[.C][OPTS][,F[.C][OPTS]]`. Може вказуватися багаторазово для визначення ієрархії пріоритетів порівняння. |
| `-t` | `--field-separator=SEP` | Одиночний символ | Встановлює символ-роздільник полів. Якщо параметр не задано, роздільником є перехід від непробільного символу до пробільного або табуляції. |
| `-b` | `--ignore-leading-blanks` | Немає | Ігнорує пробільні символи (пробіли та табуляції) на початку полів при визначенні їх меж та порівнянні. Може задаватися як глобально, так і локально всередині конкретного ключа (`-k1,1b`). |
| `-s` | `--stable` | Немає | Вмикає режим стабільного сортування: рядки з абсолютно однаковими значеннями всіх ключів зберігають свій початковий відносний порядок. Вимикає стандартне резервне побайтове порівняння (last-resort comparison) залишку рядка. |
| `-u` | `--unique` | Немає | Виводить лише перший рядок із групи записів, що мають однакові ключі сортування. Якщо задано один або кілька ключів `-k`, дедуплікація здійснюється виключно за значеннями цих ключів, навіть якщо решта полів у рядках відрізняються. |

### Режими та алгоритми порівняння

| Опція | Довга назва | Опис та правила порівняння |
|---|---|---|
| `-n` | `--numeric-sort` | Числове сортування: парсер зчитує початковий числовий префікс поля (необов'язковий знак `+`/`-`, послідовність десяткових цифр та десятковий роздільник згідно з `LC_NUMERIC`). Текстові символи після цифр ігноруються. Рядки без розпізнаних чисел розглядаються як число 0. |
| `-g` | `--general-numeric-sort` | Загальне числове сортування: здійснює повний розбір чисел із плаваючою крапкою подвійної точності за допомогою бібліотечної функції `strtod()`. Підтримує наукову експоненційну нотацію (`1.5e-3`), дробові значення, нескінченності (`+Inf`, `-Inf`) та `NaN`. Через витрати на конвертацію працює повільніше за `-n`. |
| `-h` | `--human-numeric-sort` | Порівняння розмірів із суфіксами масштабу: парсер розпізнає десяткові й двійкові суфікси (`2K`, `500M`, `4G`, `1.2T`, `P`, `E`, `Z`, `Y`). Коректно масштабує одиниці вимірювання при аналізі виводу утиліт `ls -lh` та `du -h`. |
| `-V` | `--version-sort` | Версійне сортування: реалізує природний порядок сортування рядків (natural sort order). Текст розбивається на чергування літерних і числових фрагментів. Числові блоки порівнюються як невід'ємні цілі числа без урахування провідних нулів, що дає природне впорядкування `v1.2.3 < v1.2.10`. |
| `-M` | `--month-sort` | Сортування за назвами місяців: перші три непробільні символи поля переводяться у верхній регістр і зіставляються з назвами місяців у поточній локалі (`JAN < FEB < ... < DEC`). Невідомі рядки вважаються меншими за будь-який місяць і ставляться на початок. |
| `-r` | `--reverse` | Інвертує результат порівняння на протилежний (сортування за спаданням). Може застосовуватися як глобальний прапорець або локально для окремого ключа (`-k2,2nr`). |
| `-R` | `--random-sort` | Псевдовипадкове перемішування рядків: обчислює криптографічний або хеш-код ключа з використанням випадкової солі (seed), згенерованої на старті процесу, і сортує рядки за отриманими хеш-значеннями. Рядки з ідентичними ключами гарантовано залишаються суміжними. |
| `-f` | `--ignore-case` | Регістронезалежне порівняння: перетворює всі малі літери у верхній регістр перед порівнянням байтів. |
| `-d` | `--dictionary-order` | Словниковий порядок: під час порівняння враховуються виключно літери, цифри та пробіли; всі символи пунктуації та спеціальні знаки відкидаються. |
| `-i` | `--ignore-nonprinting` | Ігнорує недруковані керуючі символи (байти ASCII з кодами, меншими за 32 або більшими за 126, а також керуючі коди Unicode). |

## 3. Специфікатор ключа sort: повний синтаксис та правила розбору

Специфікатор ключа в командному рядку описується строгою граматикою:

```
KEYDEF = POS1[,POS2]
POS    = FIELD[.CHAR][FLAGS]
```

### Порядок інтерпретації компонентів

1. `FIELD` (номер поля):
   Позитивне ціле число, нумерація починається з 1. Перше поле рядка — це поле 1. Якщо значення виходить за межі фактичної кількості полів у рядку, ключ вважається порожнім рядком.
2. `CHAR` (номер символу в межах поля):
   Позитивне ціле число, нумерація символів починається з 1. Символ 1 відповідає першому знаку поля. Якщо номер символу не вказано явно:
   - Для початкової позиції `POS1` за замовчуванням береться перший символ (`.1`).
   - Для кінцевої позиції `POS2` береться останній символ поля `FIELD`.
3. `FLAGS` (локальні прапорці):
   Складаються з комбінації літер `b`, `d`, `f`, `g`, `h`, `i`, `M`, `n`, `r`, `R`, `s`, `V`. Прапорці, вказані після номерів полів або символів, перекривають глобальні параметри утиліти виключно для цього конкретного ключа.

### Таблиця граничних інтерпретацій ключів

| Вираз ключа | Межі вибірки тексту | Приклад поведінки на рядку `ALPHA 456 ZETA` |
|---|---|---|
| `-k 1,1` | Суворо поле 1. | Виділений ключ: `ALPHA` |
| `-k 2,2n` | Суворо поле 2, числовий тип. | Виділений ключ: `456` (числове значення 456) |
| `-k 2` | Від початку поля 2 до кінця всього рядка. | Виділений ключ: `456 ZETA` (порівнюється весь залишок рядка) |
| `-k 2.2,2.3` | З 2-го по 3-й символ другого поля. | Виділений ключ: `56` |
| `-k 1.3,2.2` | З 3-го символу поля 1 до 2-го символу поля 2 включно. | Виділений ключ: `PHA 45` (захоплює залишок поля, роздільник та початок поля 2) |
| `-k 2,2n -k 1,1r` | Багаторівневе ранжування. | Сортує за полем 2 як числом за зростанням; при однакових числах сортує за полем 1 лексикографічно за спаданням. |

## 4. Повна таблиця параметрів утиліти uniq

Утиліта `uniq` призначена для потокового виявлення суміжних однакових записів. Вона обробляє дані в один прохід, зберігаючи в пам'яті лише один попередній рядок.

| Опція | Довга назва | Тип аргументу | Опис та механізм дії |
|---|---|---|---|
| `-c` | `--count` | Немає | Додає на початку кожного вихідного рядка число його входжень у вхідному потоці, за яким слідує пробіл. Формат вирівнювання зазвичай містить відступи для зручності читання в терміналі. |
| `-d` | `--repeated` | Немає | Виводить виключно ті рядки, які зустрічаються у вхідному потоці два або більше разів підряд. Для кожної групи дублікатів друкується рівно один екземпляр. Унікальні рядки повністю пригнічуються. |
| `-D` | `--all-repeated[=METHOD]` | Рядок методу (`none`, `prepend`, `separate`) | Виводить абсолютно всі екземпляри повторюваних рядків (включно з першим екземпляром). Опціональний метод `separate` вставляє порожній рядок між групами дублікатів, `prepend` додає порожній рядок перед кожною групою, а `none` (за замовчуванням) друкує рядки неперервно. |
| `-u` | `--unique` | Немає | Виводить виключно унікальні рядки (кількість суміжних входжень яких дорівнює рівно 1). Рядки, що мали бодай один дублікат, повністю відкидаються. |
| `-i` | `--ignore-case` | Немає | Ігнорує регістр символів при порівнянні сусідніх рядків на рівність. |
| `-f` | `--skip-fields=N` | Ціле число `N` | Пропускає перші `N` полів перед початком порівняння. Поле визначається як непорожня послідовність непробільних символів, відокремлена пробілами чи знаками табуляції. |
| `-s` | `--skip-chars=N` | Ціле число `N` | Пропускає перші `N` символів рядка (або перші `N` символів після пропущених через `-f` полів) перед порівнянням. |
| `-w` | `--check-chars=N` | Ціле число `N` | Обмежує порівняння першими `N` символами рядка. Усі символи після позиції `N` ігноруються при визначенні рівності. |
| `-z` | `--zero-terminated` | Немає | Використовує нульовий байт (`\0`) як роздільник вхідних та вихідних записів замість символу нового рядка (`\n`). |

## 5. Взаємодія зі змінними середовища

Поведінка системних функцій виділення пам'яті, порівняння рядків та відкриття тимчасових файлів в утилітах `sort` і `uniq` залежить від конфігурації змінних оточення:

- `LC_ALL`:
  Має найвищий пріоритет у системній бібліотеці C. Якщо змінна встановлена у значення `C` або `POSIX`, системні виклики перемикаються на пряме побайтове порівняння кодів символів від `0` до `255` через апаратні інструкції `memcmp()`. Це вимикає багатопрохідні таблиці мовної коллації, гарантує абсолютну детермінованість порядку сортування на будь-яких серверах і прискорює виконання `sort` у 5–10 разів.
- `LC_COLLATE`:
  Визначає правила алфавітного порядку, врахування регістру, діакритичних знаків та ваг розділових знаків під час виклику функції `strcoll()`. Діє, якщо не встановлено `LC_ALL`.
- `LC_CTYPE`:
  Визначає класифікацію символів (буквені, цифрові, пробільні) та межі багатобайтових послідовностей у кодуванні UTF-8. Впливає на розбиття полів без явного роздільника `-t`, а також на коректне зміщення символів у параметрах `-s` і `-w` утиліти `uniq`.
- `LC_NUMERIC`:
  Встановлює десятковий роздільник (крапка або кома) та правила групування розрядів чисел для опцій `-n`, `-g` та `-h`.
- `LC_TIME`:
  Задає мовні назви місяців року для опції сортування `-M`.
- `TMPDIR`:
  Вказує шлях до каталогу для створення тимчасових файлів скидання серій під час зовнішнього сортування `sort`. Якщо змінна не задана, послідовно перевіряються шляхи `P_tmpdir` (зазвичай `/tmp`) або поточний каталог.

## 6. Обробка системних сигналів та безпека

Під час виконання зовнішнього сортування утиліта `sort` створює на диску тимчасові файли під унікальними іменами через функцію `mkstemp()`. Для запобігання витоку дискового простору та колізій безпеки реалізовано такі механізми:

1. **Права доступу до тимчасових файлів**:
   Усі файли серій створюються з маскою прав `0600` (читання та запис лише для власника процесу). Це унеможливлює підглядання або підміну даних іншими користувачами у спільному каталозі `/tmp`.
2. **Обробники сигналів (Signal Handlers)**:
   Процес реєструє обробники сигналів `SIGINT`, `SIGTERM`, `SIGHUP` та `SIGPIPE`. У разі надходження сигналу завершення обробник виконує системний виклик `unlink()` для кожного відкритого тимчасового файлу зі списку активних серій і лише після цього передає керування ядру для завершення процесу.
3. **Обробка розриву каналу (`SIGPIPE`)**:
   Якщо утиліта працює в конвеєрі, який обривається командою `head` (`sort access.log | head -n 10`), спроба запису у закритий канал генерує сигнал `SIGPIPE`. `sort` перехоплює його, негайно видаляє всі згенеровані тимчасові файли на диску та завершується без зависання сміття у `/tmp`.

## 7. Відмінності реалізацій: GNU Coreutils проти BSD і macOS

Під час перенесення скриптів автоматизації між Linux, FreeBSD та macOS інженери стикаються з розбіжностями в реалізації утиліти `sort`:

1. **Сумісність специфікаторів розміру (`-h`) та версій (`-V`)**:
   Опції `-h` (`--human-numeric-sort`) та `-V` (`--version-sort`) є розширеннями GNU Coreutils. У багатьох стандартних версіях BSD `sort` прапорець `-V` відсутній або вимагає встановлення пакету `coreutils` (виклик `gsort`).
2. **Паралелізація та керування потоками (`--parallel`)**:
   Опція `--parallel` підтримується виключно в GNU `sort`. BSD-версія використовує власні евристики багатопотоковості або працює в однопотоковому режимі.
3. **Застарілий синтаксис позицій полів (`+POS1 -POS2`)**:
   У ранніх версіях Unix (V7, System V) поля визначалися як `sort +1 -2 file.txt` (нумерація полів починалася з нуля: пропустити 1 поле і зупинитися перед 2-м полем). Стандарт POSIX оголосив цей синтаксис застарілим на користь `-k 2,2`. Сучасний GNU `sort` за замовчуванням вимагає змінної `_POSIX2_VERSION=199209` для підтримки застарілих форм `+1`.

## 8. Простеження виконання та діагностика через strace

Для діагностики поведінки `sort` під час обробки великих файлів застосовують системний трасувальник `strace`:

```bash
# Відстеження викликів створення тимчасових файлів, буферизації та сигналів:
strace -e trace=openat,unlink,mmap,read,write,clone sort -S 100M large.txt
```

Під час аналізу виводу спостерігаються такі характерні системні виклики:
- `mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, ...)` — виділення буфера внутрішнього сортування пам'яті.
- `openat(AT_FDCWD, "/tmp/sortXXXXXX", O_RDWR|O_CREAT|O_EXCL, 0600)` — безпечне створення файлів проміжних серій.
- `clone(child_stack=..., flags=CLONE_VM|CLONE_FS|CLONE_FILES|CLONE_SIGHAND|CLONE_THREAD, ...)` — запуск робочих потоків при паралельному сортуванні.
- `unlink("/tmp/sortXXXXXX")` — негайне видалення файлів серій після завершення k-way злиття.

## 9. Коди завершення процесу (Exit Codes)

| Код повернення | Утиліти | Причина завершення процесу |
|---|---|---|
| `0` | `sort`, `uniq` | Успішне виконання операції. Для `sort -c` або `sort -C` — вхідний файл повністю відсортовано відповідно до заданих критеріїв. |
| `1` | `sort` | Порушення порядку сортування у вхідних даних (повертається виключно при виклику з перевірочними прапорцями `-c` або `-C`). |
| `1` | `uniq` | Синтаксична помилка або несумісність параметрів у деяких класичних реалізаціях Unix. |
| `2` | `sort`, `uniq` | Критична помилка операційної системи: неможливість відкрити або прочитати вхідний файл, збій створення або переповнення каталогу тимчасових файлів (`ENOSPC`), помилка виділення оперативної пам'яті (`ENOMEM`), некоректний синтаксис ключів або помилка запису у вихідний потік. |
