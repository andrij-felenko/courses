# Математичний аналіз складності зовнішнього сортування

Аналітичний розрахунок часової, просторової та дискової складності алгоритму External Merge Sort у моделі зовнішньої пам'яті Аґґарвала–Віттера (Aggarwal-Vitter I/O model).

## 1. Параметри аналітичної моделі

Для кількісного аналізу алгоритму введемо базові параметри системи:

- `N` — загальний розмір вхідного набору даних у байтах.
- `M` — обсяг оперативної пам'яті (RAM), виділений під буфер внутрішнього сортування (`sort -S`). За умовою зовнішнього сортування `M < N`.
- `B` — розмір апаратного або системного блоку введення-виведення (I/O block size / page size), який зчитується або записується за один дисковий запит.
- `L` — середня довжина одного рядка в байтах. Кількість елементів для сортування дорівнює `n = N / L`.
- `k` — коефіцієнт злиття (fan-in / merge order), тобто кількість одночасно відкритих потоків серій на фазі злиття.

Основною метрикою продуктивності зовнішніх алгоритмів є кількість операцій дискового блокового обміну (I/O complexity), оскільки швидкість роботи з накопичувачами (HDD/SSD) на кілька порядків нижча за швидкість доступу до оперативної пам'яті.

## 2. Фаза 1: Генерація початкових серій (Run Generation)

На першому етапі вхідний файл розміром `N` послідовно завантажується в оперативну пам'ять блоками розміром `M`.

### Кількість сформованих серій

Кількість первинних відсортованих тимчасових файлів (серій) `R` становить:

```
R = ceil(N / M)
```

### Дискові операції на фазі 1

1. **Читання вхідних даних**: зчитується весь файл розміром `N`, що вимагає `N / B` операцій читання блоків.
2. **Запис відсортованих серій**: на диск скидаються тимчасові файли сумарним розміром `N`, що вимагає `N / B` операцій запису блоків.

Сумарна кількість дискових операцій на фазі 1:

```
I/O_phase1 = 2 * (N / B)
```

### Процесорна складність на фазі 1

У кожному блоці розміром `M` міститься `m = M / L` рядків. Їх сортування алгоритмом Quicksort або Timsort потребує `O(m * log m)` операцій порівняння.

Для всіх `R` блоків сумарний процесорний час складає:

```
T_cpu_phase1 = R * O(m * log m)                  [визначення: R блоків по m елементів]
             = (N / M) * O((M / L) * log(M / L)) [підстановка R = N / M та m = M / L]
             = O((N / L) * log(M / L))           [скорочення множника M]
             = O(n * log m)                      [визначення n = N / L та m = M / L]
```

## 3. Фаза 2: K-входове злиття (K-Way Merge)

На фазі злиття необхідно об'єднати `R` відсортованих файлів в один результуючий потік.

### Обмеження на коефіцієнт злиття k

Щоб одночасно зливати `k` файлів, оперативна пам'ять повинна містити:
- `k` вхідних буферів розміром щонайменше `B` байтів кожен (по одному для кожного відкритого файлу).
- 1 вихідний буфер розміром `B` для накопичення результату перед записом на диск.

Звідси випливає фізичне обмеження на максимальний коефіцієнт злиття за один прохід:

```
(k + 1) * B <= M  ===>  k <= (M / B) - 1
```

### Кількість проходів злиття (Merge Passes)

Якщо кількість початкових серій `R` не перевищує доступний коефіцієнт `k` (`R <= k`), достатньо **одного проходу** (Single-pass merge).

Якщо ж даних настільки багато, що `R > k`, злиття виконується ієрархічно за кілька проходів. На кожному проході кількість тимчасових файлів зменшується у `k` разів. Загальна кількість проходів злиття `P` дорівнює:

```
P = ceil(log_k R) = ceil(log_k (N / M))
```

### Дискові операції на фазі 2

На кожному з `P` проходів весь обсяг даних `N` повністю зчитується з тимчасових файлів попереднього рівня та записується у проміжні файли наступного рівня (або у фінальний вихідний потік на останньому кроці):

```
I/O_phase2 = 2 * (N / B) * P
           = 2 * (N / B) * ceil(log_k (N / M))
```

### Процесорна складність на фазі 2

Під час злиття для вибору найменшого елемента серед `k` потоків використовується мін-купа (min-heap) або дерево вибування (loser tree).
- Ініціалізація купи: `O(k)`.
- Для кожного з `n` рядків операція вилучення мінімуму та вставки наступного елемента займає `O(log k)` операцій.

За один прохід злиття витрачається `O(n * log k)` операцій процесора. Для `P` проходів:

```
T_cpu_phase2 = P * O(n * log k)                    [P проходів по n елементів у купі]
             = ceil(log_k (N / M)) * O(n * log k)  [підстановка P = log_k(N / M)]
             = O(n * (log(N / M) / log k) * log k) [перехід до логарифмів з спільною основою]
             = O(n * log(N / M))                   [скорочення log k]
```

## 4. Підсумкова складність External Merge Sort

### Повна I/O складність (Aggarwal-Vitter Bound)

Додаючи дискові витрати обох фаз, отримуємо фундаментальну теорему складності сортування в зовнішній пам'яті:

```
Total_I/O = I/O_phase1 + I/O_phase2               [сума дискових витрат обох фаз]
          = 2 * (N / B) + 2 * (N / B) * P         [підстановка I/O_phase1 та I/O_phase2]
          = 2 * (N / B) * (1 + ceil(log_k (N / M))) [винесення спільного множника 2*(N/B)]
```

При оптимальному виборі `k = theta(M / B)`:

```
Total_I/O = O((N / B) * log_(M / B) (N / B))
```

Ця формула доводить, що збільшення обсягу RAM буфера `M` (`sort -S`) зменшує не лише кількість початкових серій `N / M`, але й логарифмічну основу кількості проходів `M / B`, мінімізуючи витрати на повторний дисковий I/O.

### Повна обчислювальна складність CPU

Сумарний час роботи процесора:

```
Total_CPU = T_cpu_phase1 + T_cpu_phase2 [сума процесорного часу фази 1 та 2]
          = O(n * log m) + O(n * log(n / m)) [підстановка T_cpu_phase1 та T_cpu_phase2]
          = O(n * (log m + log(n / m)))     [винесення спільного множника n]
          = O(n * log n)                    [властивість логарифма: log a + log(n/a) = log n]
```

External Merge Sort досягає теоретичного інформаційного оптимуму порівняльного сортування `O(n * log n)` за кількістю порівнянь елементів, незважаючи на розбиття та роботу через дискові тимчасові файли.

## 5. Практичний числовий приклад розрахунку

Нехай потрібно відсортувати лог-файл розміром `N = 100 GB` з середньою довжиною рядка `L = 100 B` (`n = 1 000 000 000` рядків).

Параметри сервера:
- Доступна RAM для sort: `M = 4 GB` (`sort -S 4G`).
- Розмір системного I/O блоку: `B = 64 KB` (розмір буфера читання VFS).

### Розрахунок параметрів:

1. Кількість початкових серій:
   `R = ceil(100 GB / 4 GB) = 25` тимчасових файлів.
2. Максимально допустимий коефіцієнт злиття:
   `k_max = M / B = 4 GB / 64 KB = 65 536`.
3. Оскільки `R = 25 <= k_max = 65 536`, алгоритм виконує злиття за **рівно один прохід** (`P = 1`).
4. Сумарний обсяг переданих даних через диск:
   - Фаза 1 (запис 25 серій): 100 GB читання + 100 GB запису = 200 GB I/O.
   - Фаза 2 (однопрохідне злиття 25 серій): 100 GB читання + 100 GB запису (у фінальний файл) = 200 GB I/O.
   - Загальний дисковий I/O: **400 GB** (`4 * N`).

Якби буфер пам'яті було обмежено дефолтним значенням `M = 10 MB` (без прапорця `-S`), кількість серій склала б `R = 10 000`. При вичерпанні ліміту відкритих дескрипторів файлів системі знадобилося б 2 проходи злиття, збільшуючи загальний дисковий I/O до `6 * N = 600 GB`, що на повільних HDD призводить до триразового зростання часу виконання.
