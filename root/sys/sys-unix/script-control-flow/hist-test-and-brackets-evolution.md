# 📜 Еволюція перевірок: від окремого бінарника test до ключового слова [[ ]]

Історія умовних виразів у командних оболонках Unix демонструє класичний шлях системної оптимізації: перехід від зовнішніх утиліт простору користувача, що запускалися через дорогі системні виклики `fork` та `exec`, до вбудованих функцій інтерпретатора і, зрештою, до повноцінних синтаксичних конструкцій граматики парсера.

## Народження утиліти test у Unix Version 7

У ранніх версіях Unix (V1–V6) оболонка Thompson shell (`/bin/sh`) була вкрай примітивним інтерпретатором: вона не мала вбудованих синтаксичних засобів для обчислення логічних виразів. Керування потоком базувалося на операторі `if`, який просто запускав наступну вказану команду та аналізував її код повернення (exit status).

У 1979 році разом із виходом Seventh Edition Unix (V7) Стівен Борн (Stephen Bourne) представив Bourne shell, а в складі базових системних утиліт з'явилася програма `/bin/test`. Її автором був дослідник Bell Labs Кен Томпсон (Ken Thompson). Утиліта `test` призначалася для однієї конкретної мети: оцінити передані їй позиційні аргументи (наявність файлів, рівність рядків або порівняння чисел) і завершитися з кодом `0` (істина) або `1` (хиба).

Синтаксис виклику виглядав так:

```sh
if test -f /etc/passwd; then
    echo "Файл існує"
fi
```

### Поява квадратних дужок: бінарник /bin/[

Для того щоб надати скриптам вигляду, звичного для програмістів високорівневих мов (зокрема Algol 68, який сильно вплинув на синтаксис Bourne shell), розробники пішли на дотепний інженерний трюк. Вони створили жорстке посилання (hard link) або окремий виконуваний файл `/bin/[`, який являв собою ту саму програму `test`, але з однією обов'язковою вимогою: останнім аргументом у векторі `argv[]` мав стояти символ `]`.

Коли запускалася програма `/bin/[`, її точка входу аналізувала аргументи виклику. Нижче наведено історичну логіку перевірки закриваючої дужки мовою C та її сучасний еквівалент на C++:

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(int argc, char *argv[]) {
    if (strcmp(argv[0], "[") == 0 || strcmp(argv[0], "/bin/[") == 0) {
        if (argc < 2 || strcmp(argv[argc - 1], "]") != 0) {
            fprintf(stderr, "[: missing ]\n");
            exit(2);
        }
        /* Відкидаємо закриваючу дужку перед аналізом виразу */
        argc--;
        argv[argc] = NULL;
    }
    /* Подальший розбір предикатів test */
    return 0;
}
```
```cpp
#include <iostream>
#include <string_view>
#include <span>
#include <cstdlib>

int main(int argc, char* argv[]) {
    std::span<char*> args(argv, argc);
    if (!args.empty()) {
        std::string_view prog_name = args.front();
        if (prog_name == "[" || prog_name == "/bin/[" || prog_name.ends_with("/[")) {
            if (args.size() < 2 || std::string_view(args.back()) != "]") {
                std::cerr << "[: missing ]\n";
                return 2;
            }
            /* Відкидаємо останній аргумент ']' */
            args = args.subspan(0, args.size() - 1);
        }
    }
    /* Подальший розбір предикатів test */
    return 0;
}
```
:::

Через це пробіли довкола дужок `[ ` та ` ]` стали священним правилом Unix: `[` — це ім'я виконуваної програми, а `]` — її останній аргумент. Якщо автор скрипту писав `[foo = bar]`, оболонка намагалася запустити неіснуючу програму з іменем `[foo` або шукати файл `bar]`.

## Проблема продуктивності та перетворення на builtin

У 1980-х роках на повільних процесорах архітектур PDP-11 та VAX виконання скриптів із розгалуженнями створювало колосальне навантаження на підсистему пам'яті й планувальник процесів. Кожен крок циклу `while [ $i -lt 1000 ]` виконував системні виклики `fork()`, `execve("/bin/[", ...)` та `wait()`. На створення нового адресного простору, завантаження бінарника з диска (або буферного кеша) та обробку таблиці дескрипторів витрачалися тисячі тактів CPU.

З появою AT&T System V (1983) та розробкою стандарту POSIX.2 (1992) команди `test` та `[` були перенесені безпосередньо у внутрішній код оболонки — вони стали **вбудованими командами** (builtins). Зовнішній бінарник `/bin/[` (а згодом `/usr/bin/[`) зберігся у складі базового дистрибутива виключно задля сумісності зі стандартом POSIX, який вимагає наявності виконуваного файлу для виклику через `execvp` або утиліту `env` (`env [ -f /etc/passwd ]`).

## Криза синтаксичної неоднозначності POSIX test

Хоча перетворення `[` на builtin розв'язало проблему швидкодії, воно не усунуло фундаментальної проблеми: `[` залишалася звичайною командою, для якої оболонка застосовувала стандартні правила розширення (parameter expansion, word splitting, globbing) **до того**, як передати масив аргументів на оцінку.

Це породжувало знамениті пастки:
1. Якщо змінна `$var` була порожньою або містила пробіли, вираз `[ $var = "admin" ]` після підстановки перетворювався на `[ = "admin" ]` (синтаксична помилка: бракує унарного оператора) або `[ John Doe = "admin" ]` (помилка: забагато аргументів).
2. Застарілі логічні оператори `-a` (логічне «І») та `-o` (логічне «АБО») у поєднанні з круглими дужками `\( ... \)` призводили до граматичної неоднозначності. Оскільки користувацькі дані могли збігатися з іменами операторів (наприклад, якщо рядок містив значення `!`, `(`, `-a` або `-f`), алгоритм розбору аргументів у `test` не міг детерміновано відрізнити операнд від оператора.

У стандарті POSIX.1-2008 комітет був змушений зафіксувати суворий покроковий алгоритм розбору аргументів для `test`: чіткі правила визначено лише для 0, 1, 2, 3 та 4 аргументів. Для 5 і більше аргументів поведінка `test` була оголошена невизначеною (unspecified), а оператори `-a` та `-o` отримали статус застарілих (obsolescent).

## Поява ключового слова [[ ]] у KornShell та Bash

Для остаточного подолання цих обмежень Девід Корн (David Korn) у 1988 році при розробці KornShell (ksh88) реалізував розширений оператор `[[ ... ]]`. Пізніше його було перенесено до Zsh та вдосконалено в GNU Bash 2.02 (1998) під керівництвом Чета Реймі (Chet Ramey).

Головна архітектурна відмінність `[[` від `[` полягає в тому, що `[[` є **зарезервованим ключовим словом граматики оболонки** (reserved word / compound command), а не командою.

Коли лексичний аналізатор парсера Bash зустрічає лексему `[[`, він перемикає парсер у спеціальний режим:
- Розбиття на слова (word splitting) за символами `IFS` вимикається.
- Генерація імен файлів (globbing) не застосовується до аргументів зліва та справа від операторів (якщо вони явно не використовуються як шаблон).
- Логічні зв'язки позначаються природними операторами `&&`, `||` та дужками `( ... )`, що обчислюються за правилами короткого замикання (short-circuit evaluation) на рівні синтаксичного дерева.
- З'явилася підтримка зіставлення рядків з шаблонами glob (`[[ $str == *.tar.gz ]]`), а у Bash 3.0 (2004) — оператор зіставлення з регулярними виразами POSIX Extended Regular Expressions (`[[ $str =~ ^[0-9]+$ ]]`) з автоматичним збереженням знайдених груп у масив `BASH_REMATCH`.

У результаті `[[ ... ]]` став стандартом де-факто для написання сучасних надійних сценаріїв Bash, усунувши тридцятирічний пласт системних пасток та історичних компромісів.
