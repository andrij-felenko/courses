# 📋 Повний довідник операторів test, [ ], [[ ]] та (( ))

Цей довідник містить вичерпну технічну специфікацію операторів перевірки умов, порівняння даних, файлових предикатів, арифметичних виразів та шаблонів розгалуження, що використовуються в оболонках POSIX sh, GNU Bash, KornShell (ksh) та Zsh. Кожна секція описує не лише синтаксис виклику, але й базові системні виклики ядра Linux, особливості взаємодії з правами доступу, правила приведення типів, алгоритми синтаксичного аналізу аргументів та крайові випадки обчислень.

## 1. Предикати перевірки файлової системи

Усі перевірки файлів на рівні ядра операційної системи спираються на системні виклики сімейства `stat()`, `lstat()` та `access()`. Оператори повертають код завершення `0` (істина), якщо умова виконується, або `1` (хиба), якщо файл не відповідає критеріям, не існує або недоступний через обмеження прав доступу до одного з проміжних батьківських каталогів у шляху.

### Механізм взаємодії з ядром та розмежування прав

Більшість файлових предикатів (зокрема `-r`, `-w`, `-x`) у стандарті POSIX перевіряють можливість доступу за допомогою системного виклику `access(path, mode)` або шляхом аналізу бітової маски `st_mode` у структурі `struct stat`.
* **Реальний проти ефективного ідентифікатора**: виклик `access()` перевіряє права доступу від імені **реального** ідентифікатора користувача (real UID), тоді як оболонка зазвичай виконується з **ефективними** правами (effective UID). Якщо скрипт запущено через механізм Set-UID, поведінка утиліти `test` залежить від конкретної реалізації оболонки (Bash у `[[ ... ]]` використовує ефективні права через системну функцію `euidaccess()`).
* **Символічні посилання**: оператори `-e`, `-f`, `-d`, `-s` використовують системний виклик `stat()`, який автоматично переходить за всіма символічними посиланнями до кінцевого цільового файлу. Якщо посилання веде на неіснуючий об'єкт (бите посилання, broken symlink), предикат `-e` поверне хибу (`1`). На противагу цьому, оператор `-L` (або `-h`) викликає системний виклик `lstat()`, який інспектує саме символічне посилання, тому `-L` поверне `0` (успіх) навіть для битого посилання.
* **Таймстемпи високої точності**: оператори порівняння часу модифікації `-nt` (newer than) та `-ot` (older than) у сучасних версіях Linux спираються на поля наносекундної точності `st_mtim.tv_nsec` структури `struct stat`. Це усуває стан гонитви (race condition), коли два файли створювалися в межах однієї секунди.

| Оператор | Стандарт | Системний виклик / Макрос | Опис та системна семантика |
| :--- | :--- | :--- | :--- |
| `-e file` | POSIX | `stat(file)` | Існування файлу будь-якого типу (повертає істину, якщо `stat()` успішний). |
| `-a file` | Застарілий | `stat(file)` | Синонім до `-e` (не рекомендовано через конфлікт з логічним оператором `-a`). |
| `-f file` | POSIX | `S_ISREG(st_mode)` | Звичайний файл (regular file на диску, не каталог і не пристрій). |
| `-d file` | POSIX | `S_ISDIR(st_mode)` | Каталог (directory). |
| `-h file`, `-L file` | POSIX | `lstat()`, `S_ISLNK` | Символічне посилання (symbolic link, перевіряє сам лінк без резолвінгу цілі). |
| `-b file` | POSIX | `S_ISBLK(st_mode)` | Блоковий пристрій введення-виведення (наприклад, дисковий розділ `/dev/sda1`). |
| `-c file` | POSIX | `S_ISCHR(st_mode)` | Символьний пристрій (наприклад, термінал `/dev/tty` або генератор `/dev/urandom`). |
| `-p file` | POSIX | `S_ISFIFO(st_mode)` | Іменований канал (FIFO / named pipe, створений через `mkfifo`). |
| `-S file` | POSIX | `S_ISSOCK(st_mode)` | Unix-сокет локального домену (UNIX domain socket, наприклад сокет демона Docker). |
| `-s file` | POSIX | `st_size > 0` | Розмір файлу строго більший за нуль байтів (файл не є порожнім). |
| `-t [fd]` | POSIX | `isatty(fd)` | Файловий дескриптор відкритий і веде на інтерактивний термінал (за замовчуванням `fd=1`). |
| `-r file` | POSIX | `access(R_OK)` | Файл доступний для читання поточним процесом. |
| `-w file` | POSIX | `access(W_OK)` | Файл доступний для запису поточним процесом (для каталогу — дозвіл створення файлів). |
| `-x file` | POSIX | `access(X_OK)` | Файл доступний для виконання (для каталогу — дозвіл на проходження та пошук). |
| `-u file` | POSIX | `st_mode & S_ISUID` | Встановлено біт Set-UID (виконання з правами власника файлу). |
| `-g file` | POSIX | `st_mode & S_ISGID` | Встановлено біт Set-GID (успадкування групи каталогу або прав групи). |
| `-k file` | POSIX | `st_mode & S_ISVTX` | Встановлено біт збереження тексту (Sticky Bit, видалення файлів лише власником). |
| `-O file` | Bash / Ksh | `st_uid == geteuid()` | Власником файлу є ефективний користувач процесу. |
| `-G file` | Bash / Ksh | `st_gid == getegid()` | Групою файлу є ефективна група процесу. |
| `-N file` | Bash | `st_mtime >= st_atime` | Файл було модифіковано з моменту останнього читання. |
| `f1 -nt f2` | Bash / Ksh | `st_mtime(f1) > st_mtime(f2)` | Файл `f1` новіший за `f2` за часом модифікації, або `f1` існує, а `f2` — ні. |
| `f1 -ot f2` | Bash / Ksh | `st_mtime(f1) < st_mtime(f2)` | Файл `f1` старіший за `f2` за часом модифікації, або `f2` існує, а `f1` — ні. |
| `f1 -ef f2` | Bash / Ksh | `st_dev == st_dev && st_ino == st_ino` | `f1` та `f2` посилаються на один і той самий inode (жорстке посилання на одному пристрої). |

## 2. Оператори перевірки та порівняння рядків

Рядкові оператори виконують посимвольний аналіз даних у пам'яті процесу. Поведінка суттєво відрізняється між утилітою `[` та розширеним оператором `[[`.

### Вплив локалі та правила зіставлення

* **Лексикографічне сортування**: оператори `<` та `>` всередині `[[ ... ]]` враховують поточну системну локаль сортування `LC_COLLATE` (через функцію бібліотеки C `strcoll`). Якщо локаль налаштована на UTF-8 (наприклад, `uk_UA.UTF-8`), порядок сортування може відрізнятися від строгого числового порядку байтів ASCII. Для детермінованого бінарного порівняння слід встановлювати змінну `LC_ALL=C`.
* **Оператор `=~` та регулярні вирази**: використовує бібліотеку регулярних виразів ядра libc (POSIX Extended Regular Expressions, ERE). Зіставлення виконується з прапорцем `REG_EXTENDED`. Результати пошуку підрядків, згрупованих у виразі круглими дужками `( ... )`, автоматично експортуються у вбудований масив Bash `BASH_REMATCH`.

| Оператор | Контекст | Опис та системні нюанси |
| :--- | :--- | :--- |
| `-z str` | POSIX / Bash | Довжина рядка дорівнює нулю (`strlen(str) == 0`). Повертає `0` для порожніх або неініціалізованих змінних. |
| `-n str`, `str` | POSIX / Bash | Довжина рядка більша за нуль (`strlen(str) > 0`). У `[` вимагає лапок: `[ -n "$var" ]`. |
| `s1 = s2` | POSIX / Bash | Строгий посимвольний збіг рядків. |
| `s1 == s2` | `[[ ]]` (Bash) | Зіставлення з рядком або glob-шаблоном (`*`, `?`, `[...]`), якщо `s2` не в лапках. |
| `s1 != s2` | POSIX / Bash | Рядки не збігаються (або рядок не відповідає glob-шаблону в `[[ ]]`). |
| `s1 < s2` | `[[ ]]` (Bash) | `s1` лексикографічно передує `s2` за поточною локаллю `LC_COLLATE`. У `[` вимагає екранування `\<`. |
| `s1 > s2` | `[[ ]]` (Bash) | `s1` лексикографічно слідує за `s2`. У `[` вимагає екранування `\>`. |
| `s1 =~ regex` | `[[ ]]` (Bash 3.0+) | Зіставлення з регулярним виразом POSIX ERE. Знайдені групи зберігаються в масиві `BASH_REMATCH`. |

## 3. Детермінований алгоритм розбору аргументів у POSIX test / [ ]

Через історичні проблеми неоднозначності стандарт POSIX.1-2008 зафіксував строго детермінований алгоритм, за яким утиліта `test` розбирає переданий їй масив позиційних аргументів:

1. **0 аргументів**: повертає статус `1` (хиба).
2. **1 аргумент**: повертає статус `0` (істина), якщо аргумент не є порожнім рядком; інакше повертає `1`.
3. **2 аргументи**:
   - Якщо перший аргумент дорівнює `!`, результат є інверсією перевірки другого аргументу як 1-аргументного виразу.
   - Якщо перший аргумент є унарним оператором (наприклад, `-f`, `-d`, `-z`, `-n`), обчислюється відповідний предикат.
   - Інакше — результат не визначено стандартом (синтаксична помилка).
4. **3 аргументи**:
   - Якщо другий аргумент є бінарним оператором (`=`, `!=`, `-eq`, `-lt`, `-gt` тощо), обчислюється бінарне порівняння між першим і третім аргументами.
   - Якщо перший аргумент дорівнює `!`, результат є запереченням 2-аргументного виразу з другого та третього елементів.
   - Якщо перший аргумент дорівнює `(` і третій дорівнює `)`, обчислюється 1-аргументний вираз всередині дужок.
   - Інакше — синтаксична помилка.
5. **4 аргументи**:
   - Якщо перший аргумент дорівнює `!`, заперечується результат 3-аргументного виразу.
   - Якщо перший аргумент дорівнює `(` і четвертий `)`, обчислюється 2-аргументний вираз.
   - Інакше поведінка вважається невизначеною (unspecified).
6. **5 і більше аргументів**: поведінка повністю не визначена стандартом POSIX, саме тому складні вирази з операторами `-a` та `-o` призводять до збоїв.

## 4. Числові порівняння та цілочисельна арифметика

Оболонка Unix підтримує два кардинально різних методи обробки чисел: унарні оператори текстового порівняння утиліти `test`/`[` та повноцінний арифметичний процесор у блоці подвійних круглих дужок `(( ... ))`.

### Порівняння цілих чисел у `test` та `[` (POSIX)

Оператори працюють виключно зі знаковими цілими числами розрядності `intmax_t` (зазвичай 64 біти в сучасних системах Linux). Якщо операнд містить нечислові символи, пробіли або дробову крапку, утиліта `[` аварійно повертає помилку `integer expression expected`.

| Оператор | Походження | Призначення | Приклад у коді |
| :--- | :--- | :--- | :--- |
| `-eq` | Equal | Рівність чисел (`$a == $b`) | `[ "$count" -eq 10 ]` |
| `-ne` | Not Equal | Нерівність чисел (`$a != $b`) | `[ "$status" -ne 0 ]` |
| `-lt` | Less Than | Менше (`$a < $b`) | `[ "$used" -lt "$total" ]` |
| `-le` | Less or Equal | Менше або дорівнює (`$a <= $b`) | `[ "$retries" -le 3 ]` |
| `-gt` | Greater Than | Більше (`$a > $b`) | `[ "$load" -gt 8 ]` |
| `-ge` | Greater or Equal | Більше або дорівнює (`$a >= $b`) | `[ "$free_mem" -ge 1024 ]` |

### Арифметичний контекст `(( ... ))` та `$(( ... ))` (Bash / Ksh / Zsh)

Усередині конструкцій `(( ... ))` та `$(( ... ))` парсер Bash будує повноцінне дерево абстрактного синтаксису (AST) для обчислення числових виразів. Змінні розгортаються автоматично за їхніми іменами без використання префікса `$`. Якщо змінна містить порожній рядок або не визначена, її числове значення автоматично приймається рівним `0`.

#### Підтримка систем числення
Парсер підтримує різні основи числення:
- Десяткові числа: `100`.
- Вісімкові числа (префікс `0`): `0755` (дорівнює `493` у десятковій системі).
- Шістнадцяткові числа (префікс `0x` або `0X`): `0xFF` (дорівнює `255`).
- Довільна система числення від 2 до 64 (синтаксис `основа#число`): `2#101010` (дорівнює `42`), `16#1A` (дорівнює `26`).

Результат обчислення виразу транслюється у статус виходу команди:
* Якщо підсумкове значення виразу **не дорівнює нулю**, статус виходу становить `0` (істина / успіх).
* Якщо значення виразу **дорівнює нулю**, статус виходу становить `1` (хиба / помилка).

| Категорія операцій | Оператори (за спаданням пріоритету) | Системна семантика та приклади |
| :--- | :--- | :--- |
| Постфіксний інкремент/декремент | `var++`, `var--` | Повертає старе значення, потім змінює змінну: `(( x++ ))` |
| Префіксний інкремент/декремент | `++var`, `--var` | Змінює змінну, потім повертає нове значення: `(( ++x ))` |
| Унарні операції | `+`, `-`, `~` (побітове NOT), `!` (логічне NOT) | Інверсія знаку або бітів: `(( mask = ~flags ))` |
| Піднесення до степеня | `**` | Степінь цілих чисел: `(( size = 2 ** 10 ))` (1024) |
| Множення, ділення, остача | `*`, `/`, `%` | Цілочисельне ділення з відкиданням дробу: `(( min = sec / 60 ))` |
| Додавання та віднімання | `+`, `-` | Базове додавання/віднімання: `(( total = a + b ))` |
| Побітові зсуви | `<<`, `>>` | Арифметичний зсув бітів ліворуч/праворуч: `(( val = 1 << 8 ))` |
| Порівняння величин | `<`, `<=`, `>`, `>=` | Повертає `1` (true) або `0` (false): `(( free_space >= limit ))` |
| Рівність та нерівність | `==`, `!=` | Числова рівність/нерівність: `(( code == 200 ))` |
| Побітове І (AND) | `&` | Побітова маска: `(( is_set = flags & 0x04 ))` |
| Побітове виключне АБО (XOR) | `^` | Побітовий XOR: `(( diff = reg_a ^ reg_b ))` |
| Побітове АБО (OR) | `\|` | Встановлення бітів: `(( flags = flags \| 0x01 ))` |
| Логічне І (AND) | `&&` | Логічне І з коротким замиканням: `(( x > 0 && y < 10 ))` |
| Логічне АБО (OR) | `\|\|` | Логічне АБО з коротким замиканням: `(( port == 80 \|\| port == 443 ))` |
| Тернарний умовний оператор | `cond ? expr1 : expr2` | Вибір значення за умовою: `(( max = (a > b) ? a : b ))` |
| Присвоєння зі зміною | `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=`, `&=`, `^=`, `\|=` | Оновлення значення змінної: `(( offset += stride ))` |
| Послідовне обчислення | `,` (оператор кома) | Послідовне виконання виразів зліва направо: `(( x = 1, y = 2, z = x + y ))` |

## 5. Логічні оператори та групування виразів

Поєднання кількох умовних виразів залежить від синтаксичного контексту. Використання операторів `-a` та `-o` утиліти `[` суворо не рекомендовано стандартом POSIX через неоднозначність граматичного розбору.

| Операція | Утиліта `[` (POSIX) | Ключове слово `[[ ]]` (Bash) | Арифметичний блок `(( ))` | Ланцюжки команд оболонки |
| :--- | :--- | :--- | :--- | :--- |
| Логічне І (AND) | `-a` *(застаріле)* | `&&` *(внутрішнє)* | `&&` | `cmd1 && cmd2` |
| Логічне АБО (OR) | `-o` *(застаріле)* | `\|\|` *(внутрішнє)* | `\|\|` | `cmd1 \|\| cmd2` |
| Заперечення (NOT) | `!` | `!` | `!` | `! cmd` |
| Групування | `\( expr \)` *(екрановане)* | `( expr )` | `( expr )` | `{ list; }` або `( list )` |

## 6. Специфікація зіставлення шаблонів оператора `case`

Оператор `case` реалізує зіставлення значення рядка з послідовністю шаблонів на рівні синтаксичного аналізатора оболонки. На відміну від багаторазових викликів `if`, інтерпретатор оптимізує розбір шаблонів, не створюючи дочірніх процесів та не виконуючи повторного розширення виразу.

### Базові синтаксичні шаблони globbing

| Шаблон | Тип зіставлення | Опис поведінки |
| :--- | :--- | :--- |
| `*` | Довільний рядок | Збігається з будь-якою послідовністю символів довільної довжини (включно з порожнім рядком). |
| `?` | Один символ | Збігається з рівно одним будь-яким символом. |
| `[abc]`, `[a-z]` | Набір / діапазон | Збігається з одним символом із переліку або діапазону символів поточної локалі. |
| `[!abc]`, `[^abc]` | Заперечення набору | Збігається з будь-яким одним символом, що НЕ входить до зазначеного переліку. |
| `p1 \| p2` | Альтернативи | Логічне «АБО» між кількома взаємовиключними шаблонами в межах однієї гілки. |
| `[[:class:]]` | POSIX класи | Символьні класи: `[:alnum:]`, `[:alpha:]`, `[:digit:]`, `[:lower:]`, `[:upper:]`, `[:space:]`, `[:punct:]`. |

### Розширені шаблони Extglob (`shopt -s extglob` у Bash)

Розширений механізм шаблонів додає до globbing потужність регулярних виразів, використовуючи детерміновані скінченні автомати без накладних витрат на виклик зовнішніх бібліотек:

| Синтаксис Extglob | Еквівалент у Regex | Опис семантики |
| :--- | :--- | :--- |
| `?(p1\|p2)` | `(p1\|p2)?` | Нуль або один збіг із зазначеними шаблонами. |
| `*(p1\|p2)` | `(p1\|p2)*` | Нуль або більше повторень зазначених шаблонів. |
| `+(p1\|p2)` | `(p1\|p2)+` | Один або більше повторень зазначених шаблонів підряд. |
| `@(p1\|p2)` | `(p1\|p2)` | Рівно один точний збіг з одним із перелічених варіантів. |
| `!(p1\|p2)` | `^(?!(p1\|p2)$)` | Усе, крім рядків, що збігаються із зазначеними шаблонами. |

### Термінатори гілок `case` у Bash

```bash
case "$target_value" in
    pattern1)
        # Команди гілки 1
        ;;  # BREAK: стандартне завершення оператора case після виконання цієї гілки (POSIX)
    pattern2)
        # Команди гілки 2
        ;&  # FALLTHROUGH: виконання команд гілки 2 з безумовним переходом у тіло наступної гілки (Bash 4.0+)
    pattern3)
        # Команди гілки 3
        ;;& # RESUME: виконання команд гілки 3 із продовженням перевірки наступних шаблонів за списком (Bash 4.0+)
    *)
        # Гілка за замовчуванням
        ;;
esac
```
