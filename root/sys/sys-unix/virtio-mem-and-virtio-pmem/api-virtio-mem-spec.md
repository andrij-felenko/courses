# 📋 Специфікація та бінарні структури virtio-mem і virtio-pmem

У цій довідковій вставці систематизовано специфікації OASIS Virtio для пристроїв динамічної пам'яті `virtio-mem` (Device ID 24) та `virtio-pmem` (Device ID 27): конфігураційні простори адрес, бінарні формати запитів і відповідей у віртчергах, вузли файлової системи `sysfs` ядра Linux, параметри запускного командного рядка гіпервізора QEMU та QMP-команди керування.

## 1. Специфікація virtio-mem (Device ID 24)

Пристрій `virtio-mem` використовує конфігураційний простір PCI/MMIO для узгодження геометрії вікна пам'яті та одну віртчергу (guest-to-host request virtqueue) для виконання операцій динамічного підключення (plug) та відключення (unplug) суб-блоків.

### Конфігураційний простір (virtio_mem_config)

Структура конфігурації розташована у відповідній зоні BAR пристрою virtio (little-endian порядок байтів). Гіпервізор оновлює значення полів у цій зоні й надсилає переривання конфігурації гостю, коли змінюються умови виділення ресурсів:

:::code api-virtio-mem-spec/c/konfihuratsiinyi-prostir.c

Детальний аналіз значень полів конфігурації:
* **`block_size`**: Задає розмір елементарного суб-блоку пам'яті. Усі операції додавання та вилучення відбуваються кратно цьому значенню. Зазвичай становить 2 МБ (2 097 152 байти) на архітектурі x86_64 для збігу з межею Transparent Huge Pages (THP).
* **`addr`**: Базова фізична адреса в просторі GPA (Guest Physical Address), з якої починається зарезервоване вікно пристрою. Повинна бути вирівняна за межею `block_size` та межею системного блоку пам'яті ядра Linux (128 МБ).
* **`region_size`**: Максимальний потенційний обсяг адресного простору, який може зайняти даний пристрій. Резервується в топології гостя під час старту віртуальної машини.
* **`usable_region_size`**: Поточний розмір активного вікна всередині `region_size`. Гіпервізор може збільшувати цей параметр у міру того, як гостю виділяється більше пам'яті, запобігаючи використанню незаповнених хвостів адресації.
* **`requested_size`**: Динамічне поле, через яке гіпервізор виражає бажаний обсяг підключеної пам'яті. Драйвер гостя прагне довести `plugged_size` до рівня `requested_size`.
* **`plugged_size`**: Поле зворотного зв'язку, яке зчитує господар. Воно відображає фактичний обсяг пам'яті, який драйвер гостя успішно онлайнив і передав підсистемі `mm`.
* **`node_id`**: Ідентифікатор NUMA-вузла (Proximity Domain), до якого прив'язано дане вікно пам'яті.

Прапорці можливостей (Feature Bits):
* `VIRTIO_MEM_F_ACPI_PXM` (bit 0): Поле `node_id` містить дійсний ідентифікатор вузла NUMA з ACPI SRAT (System Resource Affinity Table).
* `VIRTIO_MEM_F_UNPLUGGED_INACCESSIBLE` (bit 1): Вказує гостю, що читання або запис у суб-блоки в стані `UNPLUGGED` призведе до фатального збою пристрою або трапу гіпервізора. Драйвер повинен гарантувати, що ядро не чіпатиме ці сторінки.

### Формат запиту та відповіді у віртчерзі virtio-mem

Обмін командами між драйвером гостя та гіпервізором відбувається через єдину віртчергу запитів (request virtqueue). Драйвер формує запит `struct virtio_mem_req` у доступному кільці (avail ring), а хост повертає відповідь `struct virtio_mem_resp` в ужитому кільці (used ring).

:::code api-virtio-mem-spec/c/format-zapytu-ta-vidpovidi.c

Семантика команд:
* **`VIRTIO_MEM_REQ_PLUG`**: Драйвер просить хост виділити фізичну RAM під `nb_blocks` суб-блоків, починаючи з фізичної адреси `addr`. Поле `nb_blocks` 16-бітове, тож один запит покриває щонайбільше 65535 суб-блоків, і велику зміну розміру драйвер надсилає низкою запитів. При отриманні `ACK` драйвер реєструє цей діапазон у Buddy Allocator.
* **`VIRTIO_MEM_REQ_UNPLUG`**: Драйвер сповіщає хост, що він успішно вилучив із використання `nb_blocks` суб-блоків, і господар може зняти відображення фізичних сторінок через `madvise(MADV_DONTNEED)`.
* **`VIRTIO_MEM_REQ_UNPLUG_ALL`**: Спеціальна команда, що надсилається під час перезавантаження або скидання віртуальної машини, яка миттєво відключає весь обсяг пам'яті пристрою.
* **`VIRTIO_MEM_REQ_STATE`**: Дозволяє драйверу дізнатися стан діапазону суб-блоків при ініціалізації. Відповідь `MIXED` означає, що діапазон підключений частково; про непереміщувані сторінки пристрій не знає нічого — це бухгалтерія гостя.

## 2. Специфікація virtio-pmem (Device ID 27)

Пристрій `virtio-pmem` надає гостю неперервний регіон пам'яті, відображений просто у фізичні адреси гостя (адресу й розмір гість читає з полів `start` і `size`), та одну віртчергу для виконання команд примусової синхронізації кешу (flush).

### Конфігураційний простір (virtio_pmem_config)

```c
/* include/uapi/linux/virtio_pmem.h */

struct virtio_pmem_config {
    /* Початкова фізична адреса регіону pmem у просторі адрес гостя */
    __le64 start;

    /* Розмір регіону перзистентної пам'яті в байтах */
    __le64 size;
};
```

### Формат флаш-запиту virtio-pmem

Оскільки читання та запис відбуваються напряму через відображені сторінки регіону (DAX), віртчерга використовується виключно для гарантії стійкості збереження на носії хоста:

:::code api-virtio-mem-spec/c/format-flash-zapytu-virtio.c

При отриманні запиту `VIRTIO_PMEM_REQ_TYPE_FLUSH` гіпервізор викликає `fdatasync()` або `msync()` на бекенд-файлі хоста. Лише після підтвердження від контролера диска хоста у віртчергу відправляється статус `0`.

## 3. Інтерфейси sysfs у ядрі Linux

Після завантаження модулів ядра `virtio_mem.ko` та `virtio_pmem.ko` наслідки їхньої роботи видно у звичних вузлах підсистеми пам'яті.

### Де гість бачить геометрію пристрою

Окремих файлів `block_size` чи `plugged_size` під `/sys/bus/virtio/devices/virtioX/` драйвер не заводить: усі ці поля живуть у конфігураційному просторі пристрою, і читає їх драйвер, а не адміністратор. Ззовні ті самі числа дає хост — командою QMP `query-memory-devices` (див. §4). У гості лишається наслідок:

* **`/proc/meminfo`, поле `MemTotal`** — обсяг, доведений до відома підсистеми `mm`: початкова пам'ять VM плюс `plugged_size`.
* **`/sys/devices/system/memory/memoryX/`** — системні блоки пам'яті (по 128 МБ на x86_64), через які драйвер заводить суб-блоки.
* **`lsmem`** — той самий перелік у зведеному вигляді, з колонкою зони (`Normal` / `Movable`).

### Взаємодія з системним менеджером пам'яті `/sys/devices/system/memory/`

Драйвер `virtio-mem` створює системні блоки пам'яті Linux `memoryX`. Кожен такий блок охоплює один або кілька суб-блоків пристрою:

:::code api-virtio-mem-spec/sh/main.sh

Якщо системний адміністратор намагається вручну перевести блок у стан offline (`echo offline > state`), ядро кличе підсистему `virtio-mem` для вилучення відповідних суб-блоків.

## 4. Конфігурація QEMU та QMP (QEMU Monitor Protocol)

Гіпервізор QEMU надає інструменти для створення та оперативної зміни параметрів пристроїв пам'яті.

### Параметри запускного командного рядка QEMU

Для підключення пристрою `virtio-mem` у QEMU створюється бекенд пам'яті `memory-backend-ram` та відповідний PCI-пристрій:

```bash
# Запуск QEMU з зарезервованим вікном virtio-mem на 16 ГБ та початковим розміром 2 ГБ
qemu-system-x86_64 \
  -m 4G,maxmem=32G,slots=2 \
  -object memory-backend-ram,id=mem0,size=16G \
  -device virtio-mem-pci,id=vm0,memdev=mem0,node=0,requested-size=2G,block-size=2M
```

Для підключення `virtio-pmem` використовується бекенд-файл на хості:

```bash
qemu-system-x86_64 \
  -object memory-backend-file,id=pmem_back,share=on,mem-path=/var/lib/libvirt/images/pmem.img,size=8G \
  -device virtio-pmem-pci,id=nv0,memdev=pmem_back
```

### Опитування стану пристрою пам'яті (`query-memory-devices`)

Запит від керуючого софту (Libvirt / KubeVirt):

```json
{
  "execute": "query-memory-devices"
}
```

Відповідь QEMU для пристрою `virtio-mem`:

```json
{
  "return": [
    {
      "type": "virtio-mem",
      "data": {
        "id": "vm0",
        "memdev": "mem0",
        "node": 0,
        "requested-size": 8589934592,
        "plugged-size": 4294967296,
        "size": 17179869184,
        "block-size": 2097152,
        "addr": 17179869184
      }
    }
  ]
}
```

---

### Динамічна зміна розміру пам'яті (`qom-set`)

Щоб збільшити або зменшити обсяг пам'яті віртуальної машини, QEMU надсилає команду зміни параметра `requested-size` об'єкта `virtio-mem`:

```json
{
  "execute": "qom-set",
  "arguments": {
    "path": "/machine/peripheral/vm0",
    "property": "requested-size",
    "value": 12884901888
  }
}
```

Після виконання цієї команди QEMU генерує переривання для гостя, драйвер `virtio_mem.ko` зчитує нове значення `requested_size` з конфігураційного простору і доводить обсяг підключеної пам'яті до 12 ГБ — тобто підключає ще 8 ГБ понад наявні 4 ГБ, блоками по 2 МБ.
