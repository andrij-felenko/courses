# 📋 Довідник sysfs-атрибутів транспорту SCSI та налаштувань multipath

Транспортний рівень SCSI ядра Linux надає уніфікований інтерфейс керування портами, сесіями та таймерами через псевдофайлову систему `sysfs`. Кожен клас транспорту експортує власні структури даних у вигляді ієрархії каталогів і псевдофайлів, через які системний адміністратор або фонові служби на кшталт `multipathd` та `udevd` можуть відстежувати стан фізичних лінків, налаштовувати ліміти часу реакції на аварії та ініціювати примусове пересканування топології фабрики.

## Дерево атрибутів Fibre Channel (fc_remote_ports)

Кожен виявлений віддалений порт на фабриці Fibre Channel (цільовий контролер масиву або порт комутатора) реєструється драйвером HBA через клас `scsi_transport_fc` і отримує вузол у `/sys/class/fc_remote_ports/rport-H:B-R/`, де `H` — номер хост-адаптера (Host), `B` — номер шини/каналу (Bus), `R` — порядковий індекс віддаленого порту (Remote Port ID).

Коли драйвер адаптера виявляє новий цільовий пристрій під час сканування тканини Fibre Channel, він викликає функцію `fc_remote_port_add()`. Ядро виділяє структуру `struct fc_rport` і створює відповідний каталог у `sysfs`. Атрибути цього каталогу відображають як статичні ідентифікатори пристрою (всесвітні імена вузлів і портів), так і динамічні параметри таймерів і поточного стану підключення.

| Атрибут sysfs | Тип доступу | Опис та семантика |
| :--- | :--- | :--- |
| `port_state` | Тільки читання | Поточний стан порту: `Online`, `Blocked`, `Bypass`, `Diagnostic`, `Linkdown`, `Error`, `Unbound`, `Deleted`, `Marginal`. |
| `fast_io_fail_tmo` | Читання / Запис | Час у секундах до переходу заблокованого порту в режим швидкого відхилення I/O. Допустимі значення: цілі числа `≥ 0`, `off` (вимкнено) або `0` (миттєвий failfast). |
| `dev_loss_tmo` | Читання / Запис | Час у секундах до повного видалення пристрою `rport` та всіх пов'язаних логічних одиниць SCSI (`scsi_device`). Діапазон: `1..2147483647` (або `infinity`). |
| `port_name` | Тільки читання | Всесвітній номер порту (WWPN — *World Wide Port Name*) у форматі шістнадцяткового рядка `0x50060e801049b320`. |
| `node_name` | Тільки читання | Всесвітній номер вузла (WWNN — *World Wide Node Name*) цільового контролера. |
| `port_id` | Тільки читання | 24-бітний Fibre Channel Fibre Address Identifier (FC-ID), виділений комутатором під час ініціалізації (`FLOGI`), наприклад `0x011a00`. |
| `roles` | Тільки читання | Роль порту на фабриці: `FCP Target`, `FCP Initiator`, `Unknown`. |
| `supported_classes` | Тільки читання | Підтримувані класи обслуговування Fibre Channel (наприклад, `Class 3`). |
| `scsi_target_id` | Тільки читання | Номер цілі SCSI (`Target ID`), зіставлений даному віддаленому порту в підсистемі `scsi_mid_layer` (наприклад, `0`). |

Запис нових значень у псевдофайли `fast_io_fail_tmo` та `dev_loss_tmo` виконується звичайним перенаправленням рядка у файл. Ядро проводить обов'язкову перевірку коректності: значення `fast_io_fail_tmo` не може перевищувати значення `dev_loss_tmo`. Якщо адміністратор спробує записати число, більше за поточний `dev_loss_tmo`, функція збереження поверне помилку `-EINVAL`. Тому під час конфігурації спочатку збільшують `dev_loss_tmo`, і лише після цього піднімають `fast_io_fail_tmo`.

Спеціальне значення `off` для `fast_io_fail_tmo` вимикає таймер швидкого відхилення. У цьому режимі заблокований порт утримуватиме всі запити введення-виведення у внутрішній черзі ядра аж до повного вичерпання ліміту `dev_loss_tmo`. Такий режим використовують на конфігураціях з одним фізичним шляхом, де швидке перемикання не має сенсу через відсутність резервного маршруту.

## Дерево атрибутів iSCSI (iscsi_session)

Сесії протоколу iSCSI реєструються модулем `scsi_transport_iscsi` у каталозі `/sys/class/iscsi_session/sessionN/`. На відміну від Fibre Channel, де зв'язок визначається фізичним портом HBA, сесія iSCSI є логічним з'єднанням поверх одного або кількох TCP-сокетів.

Під час розриву мережевого з'єднання або неотримання відповіді на службовий пінг `NOP-Out` стек `open-iscsi` переводить сесію у стан `FAILED`. У цей момент запускається таймер відновлення `recovery_tmo`, який виконує в підсистемі iSCSI таку саму роль, яку `dev_loss_tmo` відіграє у Fibre Channel.

| Атрибут sysfs | Тип доступу | Опис та семантика |
| :--- | :--- | :--- |
| `state` | Тільки читання | Стан сесії: `LOGGED_IN` (активна), `FAILED` (втрата зв'язку / розрив TCP), `FREE` (у процесі знищення). |
| `recovery_tmo` | Читання / Запис | Аналог `dev_loss_tmo` для iSCSI. Час у секундах очікування відновлення сесії до демонтажу SCSI-пристроїв. За замовчуванням: `120`. |
| `targetname` | Тільки читання | iSCSI Qualified Name (IQN) або EUI цільового вузла, наприклад `iqn.2001-04.com.example:storage.tape1.sys1.xyz`. |
| `tpgt` | Тільки читання | Target Portal Group Tag — числовий ідентифікатор групи порталів на боці сховища. |
| `initiatorname` | Тільки читання | IQN локального ініціатора, що відкрив дану сесію. |
| `data_seq_in_order` | Тільки читання | Ознака обов'язкового послідовного надходження Data PDU (`1` або `0`). |
| `erl` | Тільки читання | Рівень відновлення після помилок (Error Recovery Level: `0`, `1` або `2`). |

Параметр `replacement_timeout` демона `iscsid.conf` керує затримкою перед запуском процедури перепідключення сокетів. Якщо відновлення зв'язку не відбулося протягом `recovery_tmo`, транспортний шар iSCSI викликає видалення всіх асоційованих дисків, а користувацькі запити повертаються з помилкою зникнення вузла.

## Дерево атрибутів SAS (sas_rphy)

Фізичні інтерфейси розширювачів (SAS Expanders) та дисків SAS реєструються модулем `scsi_transport_sas` у каталозі `/sys/class/sas_rphy/rphy-H:B-R/`. Кожен об'єкт `sas_rphy` описує фізичне з'єднання між хост-контролером або комутатором та кінцевим дисковим накопичувачем.

| Атрибут sysfs | Тип доступу | Опис та семантика |
| :--- | :--- | :--- |
| `dev_loss_tmo` | Читання / Запис | Час очікування відновлення PHY-з'єднання в секундах до вилучення SCSI-пристрою (типово `30`). |
| `sas_address` | Тільки читання | 64-бітна унікальна адреса SAS (наприклад, `0x5000c50012345678`). |
| `negotiated_linkrate` | Тільки читання | Поточна узгоджена швидкість фізичного каналу: `1.5 Gbit`, `3.0 Gbit`, `6.0 Gbit`, `12.0 Gbit` або `Unknown`. |
| `phy_identifier` | Тільки читання | Локальний числовий номер фізичного порту (PHY) на контролері або експандері. |
| `target_port_protocols`| Тільки читання | Протокол кінцевого пристрою: `ssp` (Serial SCSI Protocol), `smp` (Management), `stp` (SATA Tunneling). |

У середовищі SAS обрив фізичної лінії фіксується на рівні PHY-контролера практично миттєво. Якщо диск підключено через SAS Expander з двома альтернативними лінками (dual-port SAS drives), ядро запускає таймер `dev_loss_tmo` для відключеного PHY, дозволяючи підсистемі багатошляховості перенаправити запити через другий порт ще до того, як диск буде видалено з топології.

## Стани віддаленого порту Fibre Channel (enum fc_port_state)

У вихідному коді ядра (`include/scsi/scsi_transport_fc.h`) стан віддаленого порту описується переліком `enum fc_port_state`. Перехід між цими станами відбувається синхронно з подіями на оптичній магістралі та повідомленнями від мікропрограми HBA-адаптера.

Коли порт перебуває у стані `FC_PORTSTATE_ONLINE`, усі команди SCSI передаються драйверу HBA без затримок. Перехід у `FC_PORTSTATE_BLOCKED` викликає заморожування черги запитів: ядро зупиняє відправку нових команд, накопичуючи їх у системній пам'яті. Якщо протягом дії таймера `fast_io_fail_tmo` оптичний зв'язок не відновлюється, ядро змінює логіку обробки черги, примусово повертаючи всі нові та накопичені команди з кодом швидкого збою транспорту.

```c
enum fc_port_state {
    FC_PORTSTATE_UNKNOWN,     /* Стан не визначено (початкова ініціалізація) */
    FC_PORTSTATE_NOTPRESENT,  /* Порт відсутній у таблиці фабрики */
    FC_PORTSTATE_ONLINE,      /* Нормальна робота: порт доступний, I/O виконується */
    FC_PORTSTATE_BLOCKED,     /* Зв'язок обірвано: черги заблоковано, очікування відновлення */
    FC_PORTSTATE_BYPASS,      /* Порт тимчасово виведено з топології (FC-AL bypass) */
    FC_PORTSTATE_DIAGNOSTICS, /* Виконуються діагностичні тести адаптера */
    FC_PORTSTATE_LINKDOWN,    /* Низькорівневий обрив оптичного лінку на боці HBA */
    FC_PORTSTATE_ERROR,       /* Непоправна апаратна помилка порту */
    FC_PORTSTATE_UNBOUND,     /* Порт виявлено, але прив'язку до SCSI target ще не завершено */
    FC_PORTSTATE_DELETED,     /* Сплив dev_loss_tmo: пристрій вилучається з системи */
    FC_PORTSTATE_MARGINAL,    /* Порт демонструє високий рівень бітових помилок (marginal) */
};
```

Стан `FC_PORTSTATE_MARGINAL` є відносно новим доповненням ядра. Він активується у випадках, коли оптичний лінк фізично не обірваний, але на ньому спостерігається критична деградація сигналу (наприклад, забруднення роз'єму або пошкодження оптоволокна), що викликає масове скидання кадрів через помилки контрольної суми CRC. Демон `multipathd` може ізолювати такий ненадійний порт ще до повного розриву зв'язку.

## Байт результату команди ядра (Host Byte / SCSI Result)

Коли команда SCSI повертається від драйвера транспорту в середній рівень `scsi_mid_layer`, результат виконання упаковується в 32-бітне ціле число `cmd->result`. Це число складається з чотирьох незалежних байтів: байта статусу пристрою, байта повідомлення, байта хоста та байта драйвера.

Старший за пріоритетом байт хоста (`host_byte`) формується саме транспортним класом та низькорівневим драйвером. Він повідомляє ядру, що саме сталося на шляху від процесора до цільового пристрою.

```c
#define DID_OK                  0x00 /* Команда передана успішно */
#define DID_NO_CONNECT          0x01 /* Немає зв'язку з портом або сплив dev_loss_tmo */
#define DID_BUS_BUSY            0x02 /* Шина зайнята */
#define DID_TIME_OUT            0x03 /* Сплив таймер виконання команди (rq_timeout) */
#define DID_BAD_TARGET          0x04 /* Цільовий пристрій не відповідає на вибір */
#define DID_ABORT               0x05 /* Команду перервано обробником помилок (abort) */
#define DID_PARITY              0x06 /* Помилка парності на шині */
#define DID_ERROR               0x07 /* Внутрішня помилка хост-адаптера */
#define DID_RESET               0x08 /* Команду скинуто через SCSI Reset */
#define DID_BAD_INTR            0x09 /* Неочікуване або спотворене переривання */
#define DID_PASSTHROUGH         0x0a /* Прямий пасстру без втручання ядра */
#define DID_SOFT_ERROR          0x0b /* М'яка відновлювана помилка */
#define DID_IMM_RETRY           0x0c /* Негайний повтор команди без затримки */
#define DID_REQUEUE             0x0d /* Повернення запиту в початок черги планувальника */
#define DID_TRANSPORT_DISRUPTED 0x0e /* Тимчасове порушення зв'язку на транспорті */
#define DID_TRANSPORT_FAILFAST  0x0f /* Сплив fast_io_fail_tmo: негайна відмова для failover */
#define DID_TARGET_FAILURE      0x10 /* Апаратна відмова контролера цілі */
#define DID_NEXUS_FAILURE       0x11 /* Втрата I_T Nexus зв'язку */
#define DID_ALLOC_FAILURE       0x12 /* Брак ресурсів пам'яті для обробки */
#define DID_MEDIUM_ERROR        0x13 /* Помилка фізичного носія */
#define DID_TRANSPORT_MARGINAL  0x14 /* Лінк нестабільний (деградація якості сигналу) */
```

Для підсистеми багатошляховості `dm-multipath` принципове значення має відмінність між `DID_TRANSPORT_FAILFAST` та `DID_NO_CONNECT`. Статус `DID_TRANSPORT_FAILFAST` змушує драйвер device-mapper негайно перенаправити запит на резервний шлях, не чекаючи демонтажу блокового пристрою. Натомість `DID_NO_CONNECT` сигналізує про остаточну втрату вузла після завершення `dev_loss_tmo`.

## Параметри /etc/multipath.conf для таймерів транспорту

У конфігураційному файлі `multipath.conf` поведінка таймерів SCSI транспорту налаштовується в секціях `defaults`, `overrides` або `devices`. Демон `multipathd` під час запуску та при виявленні нових пристроїв зчитує ці директиви й автоматично записує відповідні значення в псевдофайли `sysfs` для всіх віддалених портів.

```
defaults {
    # Скільки секунд тримати порт заблокованим до швидкого відхилення I/O
    # Значення: число (напр. 5), "off" (вимкнено) або "0" (миттєво)
    fast_io_fail_tmo        5

    # Скільки секунд чекати перед видаленням пристрою rport з ядра
    # Значення: число (напр. 30, 300, 600) або "infinity" / 2147483647
    dev_loss_tmo            300

    # Скільки разів опитувати шлях перед тим, як вважати його остаточно мертвим
    # Значення: "queue" (тримати чергу вічно), "fail" (негайна відмова) або число спроб
    no_path_retry           queue

    # Граничний час роботи обробника помилок ядра scsi_eh (у секундах)
    # Запобігає нескінченному зависанню потоку scsi_eh
    eh_deadline             30

    # Таймаут опитування працездатності шляху модулем path_checker (у секундах)
    checker_timeout         10

    # Спосіб перевірки працездатності шляху (SCSI Test Unit Ready)
    path_checker            tur

    # Політика вибору активного шляху в групі
    path_grouping_policy    group_by_prio

    # Алгоритм розподілу навантаження між активними шляхами
    path_selector           "service-time 0"

    # Скидати чергу заблокованих I/O при видаленні останнього шляху
    flush_on_last_del       "yes"
}
```

Директива `no_path_retry` взаємодіє з таймерами транспорту на рівні Device Mapper. Якщо всі фізичні шляхи перейшли в аварійний стан через спрацювання `fast_io_fail_tmo`, значення `queue` змушує `dm-multipath` призупинити передачу запитів застосункам і утримувати їх у буфері оперативної пам'яті до відновлення хоча б одного маршруту або до перевищення ліміту спроб.

Директива `eh_deadline` обмежує сумарний час, який ядро може витратити на ескалацію стандартного обробника помилок `scsi_eh`. Якщо апаратні скидання адаптера та шини не повертають пристрій до життя протягом цього часу, ядро примусово перериває спроби відновлення, запобігаючи нескінченному блокуванню системних процесів.

## Зіставлення параметрів між Fibre Channel, iSCSI та SAS

Різні транспортні протоколи використовують власні терміни та механізми виявлення обривів, проте загальна схема реакції ядра залишається уніфікованою: виявлення збою апаратною частиною, блокування черги запитів для згладжування мікрозбоїв, швидке відхилення команд після короткого очікування та фінальне видалення структур вузла при тривалій відсутності зв'язку.

| Концепція | Fibre Channel (`rport`) | iSCSI (`iscsi_session`) | SAS (`sas_rphy`) |
| :--- | :--- | :--- | :--- |
| **Шлях у sysfs** | `/sys/class/fc_remote_ports/rport-*` | `/sys/class/iscsi_session/session*` | `/sys/class/sas_rphy/rphy-*` |
| **Таймаут швидкої відмови** | `fast_io_fail_tmo` | `replacement_timeout` / сокетний RST | відсутній (керується LLD) |
| **Таймаут видалення вузла** | `dev_loss_tmo` | `recovery_tmo` | `dev_loss_tmo` |
| **Сигнал втрати лінку** | LOS / NOS / OLS / LIP | TCP Connection Timeout / RST | SAS PHY link drop |
| **Виклик ядра при обриві** | `fc_remote_port_delete()` | `iscsi_session_failure()` | `sas_rphy_delete()` |
| **Стан черги при збої** | `FC_PORTSTATE_BLOCKED` | `ISCSI_SESSION_FAILED` | PHY offline |
