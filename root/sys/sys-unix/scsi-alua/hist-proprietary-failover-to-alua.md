# 📜 Від закритих команд перемикання LUN до відкритого стандарту ALUA

На початку 2000-х років корпоративні дискові масиви мереж зберігання даних (SAN, *Storage Area Network*) майже без винятків будувалися за двоконтролерною архітектурою. Щоб захистити дані від апаратної відмови одного процесорного модуля, дві плати контролерів встановлювали в одне шасі, з'єднували між собою внутрішньою шиною синхронізації та підключали до спільної дискової полиці з двопортовими накопичувачами.

Попри фізичну наявність зв'язку обох контролерів з усіма дисками, програмна архітектура масивів того часу була жорстко асиметричною: конкретний логічний том (LUN, *Logical Unit Number*) у кожен момент часу міг повноцінно обслуговуватися лише одним контролером — його «власником» (*Owner Controller*). Власник тримав у своїй оперативній пам'яті кеш запису, відповідав за блокування секторів і контролював метадані томів. Другий контролер перебував у пасивному резерві (*Standby*). Якщо сервер надсилав команду запису чи читання на порти пасивного контролера, масив повертав помилку SCSI `CHECK CONDITION` зі статусом `NOT READY` (*Logical Unit Not Ready*).

Це створювало фундаментальну проблему для операційних систем хостів: як саме хост повинен повідомити дисковий масив, що основний контролер вийшов з ладу і пасивний контролер має негайно перебрати на себе права володіння томом?

## Епоха закритих команд: Trespass, RDAC та непереносимі драйвери

У стандартах SCSI-2 та ранньому SPC-2 (*SCSI Primary Commands 2*) не існувало жодної стандартизованої команди для передачі прав володіння логічним томом між контролерами. Кожен виробник обладнання зберігання створив власний закритий протокол і власну послідовність специфічних команд SCSI (*Vendor-Specific Commands*).

Найвідомішим прикладом став механізм **Trespass** у масивах EMC CLARiiON (пізніше серії VNX). Коли сервер виявляв зникнення зв'язку з активним контролером, він мав сформувати спеціальну вендорну команду SCSI `0x14` або `0x17` з бінарним дескриптором зміни власника LUN і надіслати її через порт резервного контролера. Отримавши цю команду, резервний контролер скидав чужий кеш на диск, забирав монопольне право керування LUN на себе і починав приймати стандартні операції вводу-виводу.

Інший підхід розробила компанія LSI Logic (системи Engenio, які постачалися за OEM-угодами як IBM TotalStorage DS4000/FastT, Sun StorEdge, SGI та NetApp E-Series). Вони впровадили протокол **RDAC** (*Redundant Array of Inexpensive Disks Controller*) та механізм **AVT** (*Auto Volume Transfer*). У режимі RDAC перемикання здійснювалося відправкою особливої сторінки режиму через команду SCSI `MODE SELECT` (сторінка `0x2C`), а в режимі AVT масив намагався самостійно змінити власника при отриманні першого звичайного запиту `READ`/`WRITE` на пасивний порт — що часто призводило до катастрофічних «пінг-понгів» між серверами кластера.

Компанії HP (для дискових масивів EVA та StorageWorks MSA), Hitachi Data Systems, Sun Microsystems та IBM (для лінійок Enterprise Storage Server Shark) мали власні несумісні протоколи сигналізації.

```
+──────────────────────────────────────────────────────────────────────────+
|  Стан індустрії до стандартизації ALUA (1998–2004 роки)                  |
|                                                                          |
|  EMC CLARiiON  ──► Команда SCSI Trespass (CDB 0x14 / 0x17)               |
|  IBM / LSI     ──► Протокол RDAC / Сторінка MODE SELECT 0x2C             |
|  HP EVA        ──► HP Active/Passive Command Set / Secure Path           |
|  Sun StorEdge  ──► Вендорні сторінки керування та перемикання LUN        |
|                                                                          |
|  Наслідок для хоста:                                                     |
|  Кожен масив вимагає власного закритого монопольного драйвера в ядрі ОС  |
+──────────────────────────────────────────────────────────────────────────+
```

Для користувачів та системних адміністраторів це обернулося експлуатаційним глухим кутом. Щоб сервер міг працювати з масивом конкретного виробника, на нього було необхідно встановлювати фірмовий програмний стек багатошляховості:
- для масивів EMC — пакет **EMC PowerPath**;
- для систем IBM — драйвер **IBM RDAC Multipath Subsystem Device Driver (MPXIO/SDDF)**;
- для сховищ HP — пакет **HP Secure Path**;
- для систем під керуванням Solaris — набір розширень **Sun Traffic Manager (MPxIO)**;
- для гетерогенних середовищ — комерційний пакет **Veritas Dynamic Multi-Pathing (DMP)**.

Ці драйвери поширювалися у вигляді закритих бінарних модулів ядра (*out-of-tree kernel modules*). Будь-яке оновлення ядра Linux або дистрибутива операційної системи ламало бінарну сумісність. Більше того, якщо до одного сервера через фабрику Fibre Channel одночасно підключалися два дискові масиви різних вендорів (наприклад, старий EMC CLARiiON і новий IBM DS4000), їхні фірмові драйвери вступали в конфлікт за перехоплення SCSI-пристроїв, що призводило до збоїв усієї операційної системи.

## Криза в екосистемі Linux і вихід стандарту SPC-3

У ядрі Linux спроба підтримати зоопарк вендорних протоколів безпосередньо призвела до фрагментації підсистеми SCSI. У середині 2000-х років розробники ядра створили спеціалізовані модулі обробників апаратних пристроїв SCSI (*SCSI Device Handlers*): `scsi_dh_emc`, `scsi_dh_rdac`, `scsi_dh_hp_sw` та `scsi_dh_aloff`. Кожен такий модуль містив реверс-інжиніринговий код надсилання специфічних команд перемикання для конкретної моделі дискової полиці.

Складність супроводу цих обробників зростала експоненційно. При виході кожної нової версії мікропрограми (*firmware*) масиву поведінка перемикання могла змінюватися, викликаючи зависання черг введення-виведення на хостах.

Усвідомлюючи кризу несумісності в індустрії SAN, технічний комітет T10 організації ANSI INCITS (*InterNational Committee for Information Technology Standards*) розпочав розробку єдиного уніфікованого механізму асиметричного доступу.

Результатом цієї роботи стала специфікація **SPC-3** (*SCSI Primary Commands - 3*, прийнята у 2005 році), де вперше було формалізовано стандарт **ALUA** (*Asymmetric Logical Unit Access* — асиметричний доступ до логічного пристрою).

Стандарт SPC-3 замінив десятки несумісних протоколів єдиною чіткою моделлю:
1. Порти сховища об'єднуються у цільові групи портів (*Target Port Groups*, TPG).
2. Стан доступу кожної групи стандартизовано у вигляді 5 фіксованих кодів: *Active/Optimized*, *Active/Non-Optimized*, *Standby*, *Unavailable* та *Transitioning*.
3. Для отримання поточної карти станів запроваджено універсальну команду SCSI `REPORT TARGET PORT GROUPS` (RTPG, код операції `0xA3`, service action `0x0A`).
4. Для явного перемикання власника або групи портів з боку хоста запроваджено стандартну команду SCSI `SET TARGET PORT GROUPS` (STPG, код операції `0xA4`, service action `0x0A`).
5. Для сповіщення хоста про автономну зміну станів масиву стандартизовано спеціальний сенс-код SCSI `06h/2Ah/06h` (*Asymmetric Access State Changed*).

## Розвиток у SPC-4 і перехід до повної інтеграції

У наступній версії стандарту — **SPC-4** (затвердженій у 2014 році) — робоча група T10 розширила можливості ALUA. Було додано розширений формат команди RTPG (*Extended Header*), який дозволив дисковому масиву повідомляти хосту точні очікувані значення тайм-аутів переходу (*Transition Timeout*) та рекомендовані інтервали опитування, що усунуло випадкові помилки передчасного тайм-ауту під час тривалого скидання кешу великих LUN.

```
Хронологія стандартизації багатошляхового доступу SCSI:

1998  ──► Початок епохи SAN: поява закритих механізмів EMC Trespass та LSI RDAC
2001  ──► Перші чернетки робочої групи ANSI T10 щодо асиметричних пристроїв
2005  ──► Ратифікація стандарту ANSI INCITS 408-2005 (SPC-3) з базовим ALUA
2008  ──► Впровадження уніфікованого модуля scsi_dh_alua в основну гілку ядра Linux
2014  ──► Ратифікація стандарту ANSI INCITS 514-2014 (SPC-4) з розширеними дескрипторами
2018  ──► Перенесення ідей ALUA в протокол NVMe over Fabrics у формі механізму ANA
```

З появою ALUA індустрія систем збереження даних позбулася залежності від пропрієтарних програмних стеків. Сьогодні практично всі комерційні та відкриті дискові масиви — від NetApp ONTAP, Dell EMC PowerStore/Unity, HPE Nimble/Primera, IBM FlashSystem, Pure Storage до підсистеми ядра Linux LIO Target — підтримують стандартний протокол ALUA SPC-3/SPC-4.

У ядрі Linux це дозволило зробити модуль `scsi_dh_alua` головним універсальним обробником для всього корпоративного обладнання. Будь-який сучасний дисковий масив при підключенні до Linux автоматично розпізнається підсистемою `dm-multipath`, конфігурує оптимальні групи пріоритетів і забезпечує безшовний прозорий failover без встановлення жодного додаткового драйвера від виробника.
