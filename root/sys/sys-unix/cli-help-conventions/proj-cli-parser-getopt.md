# ⚙️ Надійний розбір аргументів командного рядка: від C до ідіоматичного C++

Коли системна програма приймає параметри командного рядка, спроба розібрати масив рядків `argv` вручну за допомогою саморобних циклів `for` та викликів `strcmp` неминуче перетворюється на джерело дефектів безпеки та нестабільної поведінки. Ручний розбір майже завжди втрачає підтримку групування коротких прапорців (як-от `-xvf`), не здатний коректно обробити злитий запис аргументів (`-oFile` замість `-o File`), плутає передачу параметрів через знак рівності `--file=name` із передачею через пробіл, ігнорує захисний маркер завершення опцій `--` та провокує вихід за межі виділеної пам'яті (*out-of-bounds read*) при зверненні до наступного елемента масиву.

У цьому практичному проєкті реалізовано повнофункціональний, безпечний та стандартизований парсер параметрів командного рядка для утиліти потокової обробки даних `fileproc` на базі POSIX `getopt()` та GNU `getopt_long()` у двох інженерних парадигмах: класичний низькорівневий C та сучасний ідіоматичний C++20 із нульовими накладними витратами на алокацію пам'яті (*zero-copy parsing*).

## Архітектурні вимоги до інтерфейсу утиліти

Утиліта `fileproc` спроєктована у суворій відповідності до настанов POSIX.1-2017 (Utility Syntax Guidelines) та розширень стандарту GNU Coding Standards:

1. **Короткі прапорці без аргументів:**
   - Прапорець `-v` активує режим розширеного діагностичного журналювання (*verbose mode*).
   - Прапорець `-q` вмикає тихий режим (*quiet mode*), пригнічуючи будь-які попередження та інформаційні повідомлення.
   - Обидва прапорці є взаємовиключними: одночасне вказання `-v -q` (або їхніх довгих аналогів) викликає помилку семантичної валідації конфігурації.
2. **Короткі опції з аргументами:**
   - Опція `-o <file>` задає шлях до цільового файлу виводу. Парсер підтримує як роздільний запис `-o output.bin`, так і злитий `-ooutput.bin`.
   - Опція `-b <bytes>` визначає розмір внутрішнього буфера обробки в байтах. Парсер виконує сувору числову перевірку рядка на додатне ціле значення без сторонніх символів.
3. **Групування коротких прапорців (*flag bundling*):**
   - Користувач може вводити прапорці разом: виклик `-vq` еквівалентний `-v -q`, а комбінація `-vo out.txt` або `-voout.txt` еквівалентна послідовності `-v -o out.txt`.
4. **Довгі описові опції GNU:**
   - Повна підтримка парних довгих опцій: `--verbose`, `--quiet`, `--output=FILE` (та `--output FILE`), `--buffer=BYTES` (та `--buffer BYTES`), `--help`, `--version`.
5. **Опції з опціональним значенням (*optional arguments*):**
   - Опція `--color[=WHEN]` дозволяє керувати виводом кольорів у термінал. За замовчуванням діє режим `auto`, користувач може явно передати `always`, `never` або `auto`.
   - Відповідно до стандарту GNU, опціональний аргумент довгої опції приймається **виключно через знак рівності** (`--color=always`), що усуває неоднозначність із наступними позиційними іменами файлів.
6. **Захисний маркер завершення опцій `--`:**
   - Будь-які аргументи, що слідують після окремого токена `--`, розглядаються суто як позиційні операнди (імена файлів), навіть якщо вони починаються з символу дефіса (наприклад, `-- -file.txt`).
7. **Конвенція читання зі стандартного вводу:**
   - Якщо файлів не вказано взагалі або передано одинарний дефіс `-`, програма перемикається на читання потоку `stdin`.
8. **Стандартизовані коди завершення процесу:**
   - Повернення `0` (`EXIT_SUCCESS`) при штатній роботі або запиті довідкових даних (`--help` / `--version`).
   - Повернення `2` при будь-якій синтаксичній помилці командного рядка, пропущеному обов'язковому аргументі чи конфлікті взаємовиключних опцій.

## Внутрішній стан та механіка POSIX `getopt()` і GNU `getopt_long()`

Функції сімейства `getopt` не створюють власних структур-дескрипторів на купі, а керують процесом сканування масиву `argv` через набір глобальних змінних стану бібліотеки C (`glibc` або `musl`):

- **`optind` (*option index*):** Індекс наступного елемента в масиві `argv`, який підлягає обробці. На старті програми ядро та рантайм C ініціалізують його значенням `1` (оскільки `argv[0]` містить ім'я самої програми). Під час роботи парсер поступово інкрементує `optind`. Після завершення циклу розбору змінна `optind` вказує на перший позиційний аргумент, який не є опцією. Кількість позиційних файлів обчислюється виразом `argc - optind`.
- **`optarg` (*option argument*):** Вказівник типу `char *` на початок рядка значення поточної опції. Для опцій з обов'язковим або опціональним аргументом `optarg` адресує відповідний фрагмент рядка всередині масиву `argv`. Якщо опція не приймає аргументу або опціональний аргумент пропущено, `optarg` дорівнює `NULL`.
- **`opterr` (*option error*):** Керівний прапорець виводу повідомлень про помилки самою бібліотекою. За замовчуванням встановлений в `1`, що змушує `getopt` автоматично друкувати діагностику в потік `stderr` при виявленні невідомої літери або пропущеного значення. Встановлення `opterr = 0` вимикає бібліотечні повідомлення, дозволяючи програмі самостійно генерувати текст помилок.
- **`optopt` (*option character*):** Зберігає символ короткої опції, на якій сталася помилка (невідомий прапорець або пропущений обов'язковий аргумент).

### Керівний рядок коротких опцій (`optstring`)

Рядок `optstring` описує дозволений алфавіт коротких прапорців і правила очікування аргументів:

- **Звичайний символ (`v`, `q`, `h`, `V`):** Прапорець без аргументу. При його виявленні `getopt_long` повертає ASCII-код цього символу, а `optarg` залишається `NULL`.
- **Символ з однією двокрапкою (`o:`, `b:`):** Опція з **обов'язковим аргументом**. Значення може передаватися як роздільно (`-o output.bin`), так і злитно (`-ooutput.bin`). Якщо аргумент відсутній у кінці командного рядка, функція повертає символ `'?'` (або `':'`, якщо ввімкнено спеціальний префікс).
- **Символ із двома двокрапками (`c::`):** Опція з **опціональним аргументом** (розширення GNU). Значення приймається **лише злитно** у форматі `-cWHEN` (наприклад, `-calways`). Якщо користувач передає `-c always`, рядок `always` вважатиметься наступним аргументом командного рядка, а для `-c` значення `optarg` залишиться `NULL`.

Спеціальні символи на початку рядка `optstring` кардинально змінюють поведінку парсера:

- **Префікс `:` (наприклад, `:o:b:vqhV`):** Вимикає стандартні повідомлення бібліотеки в `stderr` і змушує `getopt` повертати символ `':'` замість `'?'`, коли для опції пропущено обов'язковий аргумент. Це дає змогу програмі чітко розрізняти дві нештатні ситуації: появу абсолютно невідомої опції (повертається `'?'`, дефектний символ у `optopt`) та відсутність обов'язкового параметра для відомої опції (повертається `':'`, символ опції в `optopt`).
- **Префікс `+` (наприклад, `+o:b:vqhV`):** Примусово вмикає **строгий режим POSIX**. Сканування опцій зупиняється на першому ж елементі `argv`, який не починається з дефіса. Усі подальші елементи масиву вважаються позиційними аргументами.
- **Префікс `-` (наприклад, `-o:b:vqhV`):** Вмикає режим `RETURN_IN_ORDER`. Парсер не зупиняється на позиційних аргументах і не переставляє їх: кожен позиційний параметр повертається викликом `getopt` як псевдоопція з числовим кодом `1`, а сам рядок записується в `optarg`.

## Специфікація довгих опцій: масив `struct option`

Для обробки довгих описових опцій стандарту GNU функція `getopt_long()` приймає масив структур `struct option`, оголошених у заголовку `<getopt.h>`:

:::tabs
```c
/* Структура опису довгої опції в <getopt.h> */
struct option {
    const char *name;
    int         has_arg;
    int        *flag;
    int         val;
};
```
```cpp
// Структура option у C++ (заголовок <getopt.h>)
struct option {
    const char *name;
    int         has_arg;
    int        *flag;
    int         val;
};
```
:::

Призначення полів структури:

1. **`name`:** Вказівник на нуль-термінований рядок з назвою довгої опції без початкових дефісів (наприклад, `"output"`, `"verbose"`).
2. **`has_arg`:** Числовий прапорець наявності аргументу, що приймає одну з трьох констант:
   - `no_argument` (`0`) — опція не приймає параметрів (`--verbose`, `--help`);
   - `required_argument` (`1`) — опція вимагає значення через знак рівності чи пробіл (`--output=file.txt` або `--output file.txt`);
   - `optional_argument` (`2`) — опція може приймати значення тільки через знак рівності (`--color[=WHEN]`).
3. **`flag`:** Вказівник на змінну типу `int`, що визначає спосіб повернення результату:
   - Якщо `flag == NULL`, функція `getopt_long()` повертає значення поля `val`. Це стандартний підхід для обробки опцій через конструкцію `switch (opt)`.
   - Якщо `flag != NULL`, функція записує значення `val` у змінну, на яку вказує `flag`, а сама повертає число `0`. Цей підхід зручний для прямої модифікації глобальних булевих прапорців без ручного написання гілок `switch`.
4. **`val`:** Значення, яке повертається або записується у `*flag`. Якщо довга опція має короткий еквівалент, у поле `val` записують ASCII-код відповідної літери (наприклад, `'o'` для `"output"`). Якщо опція існує лише в довгій формі, їй присвоюють унікальне числове значення за межами діапазону ASCII (наприклад, `256`, `257`), щоб уникнути колізій із короткою літерою.

Масив `long_options[]` обов'язково завершується термінальним елементом із нульовими полями `{NULL, 0, NULL, 0}`, який сигналізує бібліотеці про кінець таблиці.

### Скорочення префіксів та функція `getopt_long_only()`

Парсер `getopt_long()` автоматично підтримує скорочення унікальних префіксів довгих опцій. Якщо в таблиці присутня опція `--verbose` і немає жодної іншої опції, що починається на `--verb`, користувач може передати скорочений варіант `--verb` або `--ver`. Проте в системних скриптах автоматизації скорочення використовувати категорично не рекомендується: якщо в наступному релізі програми з'явиться опція `--verbosity`, старий виклик `--verb` стане неоднозначним, викликавши аварійне завершення з кодом помилки `2`.

Функція `getopt_long_only()` відрізняється від `getopt_long()` тим, що розпізнає довгі опції не лише з префіксом подвійного дефіса (`--output`), а й з **одинарним дефісом** (`-output`). Якщо токен з одним дефісом збігається з короткою опцією (або списком згрупованих коротких прапорців), `getopt_long_only()` віддає пріоритет короткій формі. Синтаксис з одним дефісом для довгих опцій традиційно використовується у графічній системі X11 (`-display :0.0`, `-geometry 80x24`), компіляторах GCC/Clang (`-O2`, `-shared`) та утилітах аналізу бінарних файлів GNU binutils (`objdump -disassemble`).

## Перестановка аргументів (Argument Permutation) у GNU проти POSIX

За замовчуванням у реалізації GNU `glibc` функція `getopt_long()` виконує динамічну **перестановку аргументів** (*argument permutation*). Якщо користувач передає прапорці впереміш із позиційними операндами:

```bash
./fileproc input1.txt -v input2.txt -o out.bin
```

Парсер GNU не перериває роботу на першому ж файлі `input1.txt`. Натомість він сканує весь масив `argv`, поступово переставляючи його елементи в оперативній пам'яті так, щоб усі опції (`-v`, `-o out.bin`) перемістилися на початок, а позиційні файли (`input1.txt`, `input2.txt`) опинилися в кінці масиву. Після завершення циклу змінна `optind` вказуватиме на елемент `input1.txt`.

Поведінку перестановки можна вимкнути двома способами:
1. Встановленням змінної оточення `POSIXLY_CORRECT=1`. У цьому випадку парсер суворо дотримується настанови POSIX Guideline 9: перший аргумент без дефіса (`input1.txt`) безумовно зупиняє розпізнавання прапорців, а рядок `-v` розглядається як ім'я другого позиційного файлу.
2. Вказанням префікса `+` на початку рядка коротких опцій `optstring`.

### Дія захисного маркера `--`

Маркер `--` діє незалежно від налаштувань перестановки: коли парсер зустрічає токен `--`, він безумовно завершує сканування опцій. Елемент `--` пропускається, а змінна `optind` зміщується на наступний за ним аргумент. Усі подальші елементи масиву `argv` сприймаються суто як позиційні операнди без перестановки, захищаючи програму від ін'єкцій прапорців через файли з іменами на зразок `-rf` чи `-data.txt`.

## Інженерний розбір реалізації на C

Низькорівневий парсер у файлі `cli_parser.c` демонструє максимальну продуктивність і суворий контроль системних ресурсів:

1. **Структура конфігурації `Config`:**
   Всі параметри утиліти згруповані в єдину структуру з чіткими дефолтними значеннями (`buffer_size = 4096`, `color_mode = "auto"`). Змінна `output_file` має тип `const char *` і спочатку ініціалізується як `NULL`, що інтерпретується як вивід у `stdout`.
2. **Нульове виділення динамічної пам'яті для рядків:**
   При розборі опції `-o` вказівник `cfg->output_file` напряму приймає значення бібліотечного вказівника `optarg`. Жодних викликів `malloc()` або `strdup()` не здійснюється, що виключає ризик витоків пам'яті (*memory leaks*). Позиційні аргументи зберігаються як зріз масиву: `cfg->input_files = &argv[optind]`, а їхня кількість фіксується виразом `cfg->input_file_count = argc - optind`.
3. **Сувора числова валідація через `strtol()`:**
   Розбір розміру буфера `-b` здійснюється за допомогою функції `strtol()` з обов'язковою перевіркою кінцевого вказівника `endptr`. Якщо `*endptr != '\0'` (у рядку були нечислові символи) або значення менше або дорівнює нулю (`val <= 0`), програма негайно припиняє роботу, друкує точне повідомлення про помилку в `stderr` і повертає код `2`.
4. **Валідація семантичних обмежень:**
   Після завершення циклу `while (getopt_long(...) != -1)` виконується крос-валідація параметрів. Якщо користувач одночасно передав прапорці розширеного та тихого режимів (`cfg->verbose && cfg->quiet`), парсер виводить повідомлення про несумісність у `stderr` і викликає `exit(2)`.
5. **Розподіл потоків виводу:**
   Штатні інформаційні запити (`-h` / `--help` та `-V` / `--version`) надсилають форматований текст у потік `stdout` через функції `print_help()` та `print_version()` і завершують процес із кодом `0`. Будь-які синтаксичні та валідаційні збої скеровуються виключно в потік помилок `stderr` із підказкою `Try 'fileproc --help' for more information.` та кодом виходу `2`.

## Інженерний розбір ідіоматичної реалізації на C++20

Реалізація у файлі `cli_parser.cpp` переносить класичний C API у сучасний типобезпечний дизайн C++20:

1. **Інкапсуляція метаданих програми в `ProgramInfo`:**
   Константи назви та версії програми оголошені як `static constexpr std::string_view`, розміщені в сегменті константних даних (`.rodata`). Статичні методи `print_help()` та `print_version()` приймають цільовий потік `std::ostream &os = std::cout` з кваліфікатором `noexcept`, що спрощує тестування виводу без прив'язки до глобальних потоків.
2. **Типобезпечна структура `cli::Config`:**
   - Поле `output_file` оголошене як `std::optional<std::string_view>`, що робить факт відсутності явного файлу явним у системі типів і усуває потребу в магічних нульових вказівниках (`nullptr`).
   - Позиційні аргументи збираються в контейнер `std::vector<std::string_view>`, який зберігає лише легковагі структури з вказівника та довжини без динамічної алокації тіл рядків.
3. **Інтерфейс на базі `std::span`:**
   Метод `CommandLineParser::parse` приймає аргументи як неволодіючий зріз пам'яті `std::span<char *> args`, позбавляючи функцію залежності від сигнатури `main()`.
4. **Безалокаційний та незалежний від локалей парсинг чисел:**
   Для конвертації розміру буфера використовується функція `std::from_chars` із заголовка `<charconv>`. На відміну від `std::stoi` або `std::stringstream`, `std::from_chars`:
   - Не виділяє пам'ять на купі;
   - Не викидає винятків C++ (`std::invalid_argument`, `std::out_of_range`);
   - Повністю незалежна від поточної регіональної локалі C (`setlocale`), коректно обробляючи цифри за фіксованим десятковим форматом;
   - Повертає структуру результату `std::from_chars_result` із вказівником `ptr` та кодом помилки `ec`, що дозволяє перевірити вичерпання вхідного рядка без накладних витрат.
5. **Скидання індексу сканування:**
   На початку виклику `parse()` змінна `optind` примусово скидається в значення `1`. Це усуває стан гонитви при повторному виклику парсера в тестових наборах (*unit tests*).

## Аналіз життєвого циклу пам'яті та керування станом

У системному програмуванні на C та C++ вказівник `optarg` посилається безпосередньо на відрізок пам'яті всередині масиву `argv`.

Масив покажчиків `argv` та самі нуль-терміновані рядки аргументів виділяються ядром операційної системи Linux у стеку нового процесу під час виконання системного виклику `execve()`. Вони ініціалізуються до передачі керування точці входу `_start` і залишаються незмінно валідними протягом усього життєвого циклу процесу аж до його завершення викликом `exit_group()`.

Звідси випливають три фундаментальні інженерні висновки:
1. **Безпека нульового копіювання:** Збереження `const char *output_file = optarg` у C та створення `std::string_view{optarg}` у C++ є абсолютно безпечними операціями. Об'єкти `std::string_view` посилаються на первинний буфер аргументів у стеку, не вимагаючи динамічного виділення пам'яті в купі (`malloc`/`operator new`).
2. **Заборона звільнення пам'яті:** Категорично заборонено викликати `free()` або `delete` на вказівниках, отриманих з `optarg` чи масиву `argv`. Оскільки ця пам'ять належить стеку завантажувача ядра, спроба її звільнення викличе падіння процесу з помилкою пошкодження купи (`SIGSEGV` або `SIGABRT` від glibc allocator).
3. **Незмінність рядків:** Якщо програма виконує розбір аргументів у кілька проходів або передає конфігурацію в інші компоненти, вихідний масив `argv` не слід модифікувати функціями на кшталт `strtok()`, які замінюють розділювачі на нульові байти.

## Проблема реентерабельності та потокобезпечності

Класичний C API `getopt_long()` спирається на глобальний стан бібліотеки `glibc` (змінні `optind`, `optarg`, `opterr`, `optopt`, а також внутрішні бібліотечні змінні `__optpos` та `nonopt_start/end`). Через це функція **не є потокобезпечною** (*non-reentrant* / *not thread-safe*).

Якщо два фонових потоки спробують одночасно викликати `getopt_long()` для розбору різних наборів аргументів, їхній внутрішній стан буде взаємно спотворено, що призведе до непередбачуваної поведінки або нескінченного зациклення.

Для забезпечення надійності в багатопотокових сервісах застосовують такі правила проєктування:
1. **Ізоляція на етапі запуску:** Розбір параметрів командного рядка завжди виконується **виключно в головному потоці** процесу під час ініціалізації в функції `main()`, до створення будь-яких робочих потоків (`pthread_create()` чи `std::jthread`).
2. **Незмінна конфігурація (*Immutable State*):** Результат розбору записується в незмінну конфігураційну структуру `Config`. Доступ до неї з робочих потоків надається виключно за константними посиланнями у режимі лише для читання (`const Config &`), що усуває потребу в блокуваннях м'ютексами.
3. **Скидання стану для модульного тестування:** Для повторного запуску парсера в тестах або вбудованих оболонках змінну `optind` необхідно примусово скидати в значення `1` перед кожним новим циклом сканування. У бібліотеці `glibc` при перемиканні між різними масивами `argv` також рекомендується встановлювати `optind = 0`, що змушує бібліотеку повністю переініціалізувати внутрішні таблиці перестановки аргументів.

## Валідація крайових випадків та простеження поведінки

Розроблений парсер перевіряється на всіх типових крайових сценаріях вводу в системному терміналі:

### 1. Штатний запуск із роздільними аргументами
```bash
$ ./fileproc -v -b 8192 -o output.dat input1.txt input2.txt
[DEBUG] Буфер: 8192 байт, Колір: auto, Вивід: output.dat
[DEBUG] Вхідних файлів для обробки: 2
Обробка файлу: input1.txt
Обробка файлу: input2.txt
$ echo $?
0
```
Парсер коректно зчитує діагностичний прапорець `-v`, конвертує буфер у число `8192`, записує цільовий файл `output.dat` та формує список із двох позиційних операндів. Процес повертає код завершення `0`.

### 2. Групування коротких опцій та злитий запис параметрів
Користувач може записати команду трьома еквівалентними способами:
```bash
$ ./fileproc -v -o out.bin file1.txt
$ ./fileproc -vo out.bin file1.txt
$ ./fileproc -voout.bin file1.txt
```
Усі три варіанти сприймаються парсером абсолютно однаково: вмикається діагностика `verbose = true`, ім'я вихідного файлу встановлюється в `out.bin`, а файл `file1.txt` потрапляє до списку позиційних операндів.

При злитому записі числового буфера та прапорця версії:
```bash
$ ./fileproc -voout.bin -b16384 data.log
```
Опція `-b16384` успішно парситься числом `16384` без необхідності пробілу між літерою опції та її числовим значенням.

### 3. Робота з опціональними аргументами (`--color`)
```bash
$ ./fileproc --color
# color_mode = "always" (значення за замовчуванням при вказанні опції)

$ ./fileproc --color=never
# color_mode = "never" (явне значення через знак рівності)
```
Якщо викликати команду з пробілом:
```bash
$ ./fileproc --color never
```
Слово `never` буде трактовано парсером як ім'я першого позиційного файлу для обробки, а режим кольору отримає значення `always`. Ця поведінка повністю відповідає специфікації GNU Long Options і захищає парсер від неоднозначності при розборі необов'язкових параметрів.

### 4. Захист від ін'єкцій прапорців через маркер `--`
Якщо у файловій системі створено файли з назвами, що починаються з дефіса:
```bash
$ ./fileproc -v -- -strange-name.txt -another.txt
[DEBUG] Буфер: 4096 байт, Колір: auto, Вивід: <stdout>
[DEBUG] Вхідних файлів для обробки: 2
Обробка файлу: -strange-name.txt
Обробка файлу: -another.txt
$ echo $?
0
```
Завдяки наявності маркера `--` парсер негайно перериває обробку прапорців. Обидва рядки потрапляють до масиву вхідних файлів без помилок синтаксису.

### 5. Обробка стандартного вводу за замовчуванням
Коли програма викликається без вхідних файлів у конвеєрі:
```bash
$ cat data.txt | ./fileproc -q -o result.bin
$ echo $?
0
```
У тихому режимі `-q` діагностичні повідомлення не виводяться, а дані читаються зі стандартного потоку `stdin`.

### 6. Обробка синтаксичних та семантичних помилок

**Невідомий прапорець:**
```bash
$ ./fileproc -z
fileproc: invalid option -- 'z'
Try 'fileproc --help' for more information.
$ echo $?
2
```

**Пропущений обов'язковий аргумент:**
```bash
$ ./fileproc -o
fileproc: option requires an argument -- 'o'
Try 'fileproc --help' for more information.
$ echo $?
2
```

**Некоректний числовий буфер:**
```bash
$ ./fileproc -b invalid_size
fileproc: invalid buffer size 'invalid_size'
Try 'fileproc --help' for more information.
$ echo $?
2
```

**Конфлікт взаємовиключних прапорців:**
```bash
$ ./fileproc --verbose --quiet
fileproc: options --verbose and --quiet are mutually exclusive
$ echo $?
2
```
В усіх випадках збоїв повідомлення про помилку скеровується виключно в потік `stderr`, повний текст довідки не засмічує екран термінала, а процес гарантовано завершується зі стандартизованим кодом виходу `2`.
