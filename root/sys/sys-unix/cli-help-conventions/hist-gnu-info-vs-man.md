# 📜 Війна форматів: чому Texinfo не замінив man-сторінки

У листопаді 1971 року разом із першою редакцією Unix вийшов перший том *UNIX Programmer's Manual*, упорядкований Денісом Рітчі (Dennis Ritchie) та Кеном Томпсоном (Ken Thompson). Кожна системна утиліта й кожен системний виклик отримали окремий стандартизований опис, набраний макросами форматування `roff` (пізніше `nroff` та `troff`). Ця система була оптимізована під друк на телетайпах та папері, а пізніше — під перегляд на текстових терміналах через утиліту `man`. Сторінка man мала бути атомарною: відкрив, швидко прочитав синтаксис прапорців і сигнатуру, закрив і продовжив роботу в терміналі.

П'ятнадцять років потому, у 1986 році, засновник проекту GNU Річард Столмен (Richard Stallman) виступив із жорсткою критикою сторінок man. На його думку, формат `troff` був архаїчним, не підтримував структурної гіпертекстової навігації й змушував авторів створювати ізольовані довідки-шпаргалки замість повноцінних, глибоких навчальних посібників. Як заміну Столмен представив систему **GNU Texinfo** та утиліту термінального перегляду `info`. Це рішення породило один із найтриваліших ідеологічних конфліктів в екосистемі вільного програмного забезпечення.

## Бачення GNU: єдиний гіпертекстовий мануал

Столмен створював GNU як цілісну операційну систему, а не просто набір розрізнених утиліт. З погляду філософії GNU, операційна система потребувала повної, зв'язної документації: користувач мав мати змогу не лише підглянути прапорець команди, а й вивчити теорію роботи програми, зрозуміти алгоритми, прочитати про типові сценарії застосування та пов'язані бібліотеки.

Формат Texinfo базувався на мові розмітки TeX Дональда Кнута (Donald Knuth). Головна його перевага полягала в концепції «єдиного першоджерела» (*single source publishing*): з одного `.texi` файлу автоматично генерувалися як високоякісні друковані книги (через `tex` у формат DVI чи PostScript), так і структуровані електронні файли `.info`.

Електронний формат `.info` являв собою спрямований граф вузлів (*nodes*):
- кожен вузол мав заголовок, покажчики на сусідні вузли (`Next`, `Prev`), батьківський вузол (`Up`);
- всередині тексту містилися гіпертекстові меню (`* Menu:`) та перехресні посилання (`*Note...::`);
- утиліта `info` надавала повноцінний TUI-інтерфейс (на базі клавіатурних скорочень Emacs) для миттєвих переходів між розділами, пошуку за тематичними індексами та читання великих томів технічної документації.

Офіційні правила кодування GNU (*GNU Coding Standards*) оголосили Texinfo єдиним офіційним форматом документації для всіх програм проекту GNU. Сторінки `man` у проекті GNU було офіційно оголошено «другорядними» (*secondary*) або взагалі небажаними.

## Опір мейнтейнерів дистрибутивів та Unix-спільноти

Попри технічну витонченість гіпертекстової моделі Texinfo, масового витіснення `man` не відбулося. Навпаки, спільнота розробників Unix/Linux зустріла `info` значним спротивом. Причини крилися в різниці робочих процесів та звичок користувачів.

1. **Невідповідність парадигмі командного рядка.** Користувач термінала здебільшого звертається до довідки, щоб згадати точну назву прапорця або порядок аргументів (наприклад, прапорці архівації `tar` чи регулярний вираз для `sed`). Сторінка `man` відкривається за лічені мілісекунди у звичному пейджері (`less`), легко гортається клавішами `j`/`k`, шукається через `/` і миттєво закривається клавішею `q`. Запуск `info` занурював користувача в чужорідний інтерфейс Emacs-подібної навігації, де клавіші `Space`, `n`, `p`, `u`, `l`, `Tab` та `Enter` мали власну незвичну поведінку.
2. **Дублювання зусиль авторів.** Підтримка актуальності двох окремих довідок — короткої сторінки `man` і великого посібника Texinfo — вимагала подвійної роботи. Багато розробників GNU-утиліт перестали оновлювати файли `man`, залишаючи в них лише заглушку: *«Ця сторінка man застаріла; повну документацію дивіться в info»*.
3. **Позиція дистрибутивів (зокрема Debian).** Мейнтейнери дистрибутивів Linux зіткнулися з тим, що користувачі масово скаржилися на відсутність або застарілість сторінок `man` для базових системних утиліт (`coreutils`, `tar`, `grep`, `gawk`). Політика дистрибутиву Debian вимагала наявності повноцінної сторінки `man` для кожного виконуваного файлу в системі без винятків.

## Народження help2man: автоматичний міст між світами

Щоб вирішити кризу розриву документації, у 1997 році розробник Брендан О'Ді (Brendan O'Dea) створив утиліту `help2man`.

Ідея `help2man` полягала в автоматичній генерації сторінки `man` на етапі збірки програми. Утиліта запускає скомпільований бінарник із прапорцями `--help` та `--version`, парсить структурований текстовий вивід утиліти й автоматично транслює його у валідну сторінку формату `groff` (розділ 1 або 8).

Завдяки `help2man` розробникам GNU більше не потрібно було писати файли `man` вручну: достатньо було підтримувати акуратний, структурований вивід прапорця `--help` у самій програмі та повний посібник у Texinfo. Система збірки дистрибутиву автоматично генерувала `man`-сторінку для кінцевого користувача.

## Сучасний консенсус: спеціалізовані генератори та Markdown

На початку 2000-х років застарілий та громіздкий синтаксис макропакетів `troff` (`.TH`, `.SH`, `.PP`, `.TP`, `.B`, `.I`) остаточно перестав влаштовувати розробників нового програмного забезпечення. Писати документацію мовою шістдесятих років для сучасних утиліт на C, C++, Rust чи Go було надто повільно й незручно.

Це привело до створення нового покоління інструментів, що компілюють документацію з полегшених мов розмітки (Markdown, AsciiDoc, reStructuredText) у сторінки `man` та формати HTML/PDF:

- **`scdoc`** — мінімалістичний і швидкий генератор сторінок `man` на мові C, створений спеціально для POSIX-систем і сучасних утиліт Linux (використовує підмножину Markdown).
- **`ronn` / `ronn-ng`** — популярний генератор, що перетворює звичайний Markdown на сторінки `roff` та стилізований HTML.
- **`asciidoctor` (через `asciidoctor-manpage`)** — стандарт де-факто для великих інфраструктурних проектів (зокрема Git, де вся довідка пишеться в AsciiDoc і транслюється як у `man`, так і в HTML-сайт).
- **`mandoc`** — сучасний модульний компілятор та рендерер документації BSD, що замінив важкий `groff` у багатьох дистрибутивах (OpenBSD, Alpine Linux, Void Linux), забезпечуючи миттєвий розбір `mdoc` та `man` сторінок із перевіркою синтаксичних помилок.

Сьогодні інженерне протистояння вирішене природним розділенням обов'язків:
- **`--help`** слугує миттєвою локальною підказкою прямо під час вводу команди;
- **`man`** залишається непорушним системним стандартом швидкого довідника для утиліт, форматів конфігурацій та API ядра;
- **Texinfo (`info`)** зберігся як поглиблена документація для складних класичних підсистем GNU (GCC, GDB, GNU Make, Emacs, Glibc), де деревоподібна структура справді виправдана обсягом матеріалу;
- **Веб-документація та посібники в `/usr/share/doc/`** покривають комплексні архітектурні гайди та навчальні курси.
