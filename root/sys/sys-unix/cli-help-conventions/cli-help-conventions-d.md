Коли системний адміністратор підключається до віддаленого сервера без доступу до інтернету або вбудована система переходить в аварійний режим відновлення (*rescue mode*), єдиним джерелом істини про поведінку сотень утиліт, системних викликів та конфігураційних файлів стає сама операційна система. Якщо процес отримує невідомий прапорець чи неправильний тип аргументу, він завершується з помилкою, блокуючи виконання складного конвеєра. Щоб інженер міг з'ясувати точний формат параметрів, системний розробник — сигнатуру бібліотечного виклику та коди помилок `errno`, а сценарій автоматизації — безпечно передати довільні імена файлів, в Unix склалася багаторівнева екосистема самоопису.

![Рівні довідкової системи в терміналі](/root/sys/sys-unix/cli-help-conventions/img/terminal-help-levels.svg)
*Чотири рівні довідки в операційних системах Unix та Linux: від миттєвих вбудованих підказок оболонки до розгорнутих гіпертекстових дерев info.*

Ця екосистема охоплює чотири взаємодоповнюючі рівні: вбудовані підказки оболонки (*shell builtins*), прапорці швидкої самодіагностики бінарників (`--help`), системні сторінки керівництва (`man` з вісьмома класичними розділами) та гіпертекстові дерева документації (`info`). Поруч із форматами самої документації діють суворі стандарти оформлення параметрів командного рядка — від класичних коротких однолітерних прапорців POSIX до описових довгих опцій GNU та захисного розділювача `--`.

## Чотири рівні термінальної допомоги

Різні інженерні задачі вимагають різного балансу між часом відгуку, глибиною матеріалу та ступенем ізоляції компонентів. Якщо користувач забув точну назву прапорця фільтрації, йому потрібна коротка шпаргалка на 20 рядків за 5 мілісекунд прямо у вікні термінала. Якщо ж програміст пише багатопотоковий мережевий сервіс, йому необхідна вичерпна специфікація системного виклику з гарантіями безпеки сигналів (*async-signal-safety*) та поведінкою при блокуванні.

### Вбудована допомога оболонки: команди, яких немає у файловій системі

Коли користувач набирає в терміналі команду `cd`, `read`, `eval`, `export` або `history`, операційна система не виконує системний виклик `execve()` і не завантажує виконуваний ELF-файл із каталогів `/bin` чи `/usr/bin`. Ці команди змінюють внутрішній стан самого процесу командного інтерпретатора (поточний робочий каталог процесу, таблицю змінних оточення чи чергу псевдонімів) і реалізовані безпосередньо в тілі оболонки як вбудовані команди (*builtins*).

Звідси виникає класична проблема пошуку довідки: виклик `man cd` у багатьох дистрибутивах або повертає помилку, або відкриває гігантську загальну сторінку `BASH_BUILTINS(1)` чи `ZSHBUILTINS(1)`. Щоб визначити справжню природу команди, використовується внутрішня утиліта оболонки `type` з ключем `-a`:

```bash
$ type -a cd
cd is a shell builtin

$ type -a echo
echo is a shell builtin
echo is /usr/bin/echo
```

Для миттєвого отримання синтаксису саме внутрішніх команд інтерпретатори Bash та Zsh надають вбудовану команду `help`:

```bash
$ help cd
cd: cd [-L|[-P [-e]] [-@]] [dir]
    Change the shell working directory.
    
    Change the current directory to DIR.  The default DIR is the value of the
    HOME shell variable.
    
    Options:
      -L	force symbolic links to be followed: resolve symbolic
    		links in DIR after processing instances of `..'
      -P	use the physical directory structure without following symbolic
    		links: resolve symbolic links in DIR before processing instances
    		of `..'
```

Команда `help` зчитує стислий текст безпосередньо зі статичних таблиць рядків у пам'яті процесу оболонки. Вона працює миттєво (менше 1 мілісекунди) і доступна навіть у середовищах із повністю пошкодженою чи демонтованою кореневою файловою системою.

### Швидка довідка утиліти: прапорці `--help` та `-h`

Коли виконуваний файл запускається з прапорцем `--help` або `-h`, сам процес друкує структуровану шпаргалку безпосередньо у стандартний потік виводу `stdout`.

Переваги цього рівня:
1. **Автономність:** Довідка скомпільована в тіло самого бінарника. Навіть якщо в контейнері чи мінімалістичному образі дистрибутиву видалено каталог `/usr/share/man` для економії дискового простору, прапорець `--help` продовжує працювати.
2. **Абсолютна версійна відповідність:** Текст `--help` гарантовано відповідає саме тій версії програми, яка встановлена й запущена, виключаючи розсинхронізацію між бінарним файлом та зовнішніми пакунками документації.
3. **Швидкість:** Процес виконує форматування та вивід без звернення до зовнішніх індексованих баз даних чи запуску сторонніх програм-переглядачів (*pagers*).

> 🔧 **Навіщо це.**
> У скриптах автоматизації та конвеєрах CI/CD виклик `команда --help` є найпростішим тестом працездатності двійкового файлу після збірки: він перевіряє, що програма коректно завантажує динамічні бібліотеки, проходить ініціалізацію середовища C/C++ і повертає код завершення `0`.

### Сторінки системного керівництва (man pages)

Команда `man` (від лат. *manualis* — підручний, посібник) — це головний довідковий стандарт операційних систем Unix з 1971 року. Сторінки `man` надають формальну технічну специфікацію утиліт, системних викликів, функцій бібліотеки C, спеціальних пристроїв та конфігураційних файлів.

Виклик `man <ім'я>` запускає складний ланцюжок дій:
1. **Пошук шляху:** Утиліта сканує каталоги змінної оточення `$MANPATH` (за замовчуванням `/usr/share/man`, `/usr/local/share/man`).
2. **Індексація:** Для прискорення пошуку використовується база даних `mandb` (раніше `whatis`), що оновлюється демонами `systemd-tmpfiles` або `cron`.
3. **Рендеринг:** Файли документації зберігаються у стисненому вигляді (`.gz`) мовою розмітки `troff`/`groff` (або макропакетів `man`/`mdoc`). Утиліта `man` розпаковує файл, пропускає його через транслятор `groff -Tutf8` і передає форматований текст у термінальний пейджер (`less`).

Для пошуку необхідної сторінки за описом використовуються команди `apropos` (еквівалент `man -k`) та `whatis` (еквівалент `man -f`):

```bash
$ apropos "create process"
clone (2)            - create a child process
fork (2)             - create a child process
pdfork (2)           - create a new process
vfork (2)            - create a child process and block parent
```

### Гіпертекстові дерева документації: GNU Texinfo (`info`)

Проект GNU запропонував альтернативу лінійним сторінкам `man` — систему **Texinfo** та утиліту перегляду `info`. Докладніше про те, чому виник цей формат і як розгорталася історична боротьба за стандарт системного мануалу, описано у вставці [Історія протистояння man та info](root:sys-unix/cli-help-conventions/hist-gnu-info-vs-man.md).

На відміну від атомарної сторінки `man`, документація `info` являє собою деревоподібну гіпертекстову структуру, розбиту на окремі взаємопов'язані вузли (*nodes*). Вона містить багаторівневі змісти, перехресні посилання та предметні покажчики. Для складних інструментів (таких як компилятор GCC, відлагоджувач GDB або інтерпретатор GAWK) документація `info` являє собою повноцінні електронні книги обсягом у сотні сторінок.

### Додаткова документація пакунків: `/usr/share/doc/`

Для розширених посібників, прикладів конфігураційних файлів, списків змін (*ChangeLog*) та ліцензій стандартом ієрархії файлової системи FHS (*Filesystem Hierarchy Standard*) виділено каталог `/usr/share/doc/<пакунок>/`. Тут зберігаються готові приклади конфігурацій (наприклад, складні конфігурації для демонів `nginx`, `bind`, `dhcpd`), які занадто великі для сторінки `man`.

## Архітектура та організація розділів man

Система документації Unix розбита на 8 стандартизованих числових розділів. Таке структурування вирішує критичну проблему колізії імен, коли одне й те саме слово позначає команду користувача, системний виклик ядра, функцію бібліотеки C та конфігураційний файл.

![Структура 8 числових розділів керівництва](/root/sys/sys-unix/cli-help-conventions/img/man-sections-map.svg)
*Класифікація восьми числових розділів системного керівництва UNIX та типові приклади їхнього наповнення.*

### Карта восьми числових розділів

| Розділ | Категорія вмісту | Що описує | Типові приклади |
|---|---|---|---|
| **1** | **User Commands** | Виконувані програми та утиліти командного рядка, доступні звичайним користувачам. | `ls(1)`, `grep(1)`, `tar(1)`, `bash(1)`, `gcc(1)` |
| **2** | **System Calls** | Точки входу в простір ядра Linux/Unix (обгортки glibc над `syscall`). | `open(2)`, `fork(2)`, `read(2)`, `epoll_create(2)` |
| **3** | **Library Functions** | Функції стандартної бібліотеки C (`glibc`) та спеціалізованих бібліотек (`libssl`, `libpthread`). | `printf(3)`, `malloc(3)`, `fopen(3)`, `dlopen(3)` |
| **4** | **Special Files** | Файли пристроїв у каталозі `/dev` та драйвери ядра. | `null(4)`, `zero(4)`, `tty(4)`, `random(4)`, `sd(4)` |
| **5** | **File Formats** | Структура та синтаксис конфігураційних файлів, системних баз даних і заголовків пакетів. | `passwd(5)`, `fstab(5)`, `crontab(5)`, `systemd.unit(5)` |
| **6** | **Games** | Ігри, демонстраційні програми та екранні заставки. | `bsd-games(6)`, `fortune(6)`, `factor(6)` |
| **7** | **Miscellaneous** | Оглядові концептуальні статті, конвенції, стандарти та протоколи зв'язку. | `man(7)`, `ip(7)`, `socket(7)`, `signal(7)`, `pthreads(7)` |
| **8** | **System Administration** | Утиліти керування системою та мережеві демони, що вимагають привілеїв суперкористувача (`root`). | `mount(8)`, `iptables(8)`, `systemd(8)`, `fdisk(8)` |

*(Примітка: в історичних версіях Unix існував розділ 9 для внутрішніх викликів ядра, а також літерні суфікси, як-от `3p` для специфікацій стандарту POSIX або `3ssl` для OpenSSL).*

### Розв'язання колізій імен: чому номер розділу має вирішальне значення

Якщо викликати `man` без вказівки розділу, утиліта повертає перший знайдений результат відповідно до порядку пошуку (зазвичай `1 8 2 3 4 5 6 7`).

Розглянемо класичні колізії імен у системному програмуванні:

1. **`printf`:**
   - `man printf` відкриває `printf(1)` — зовнішню утиліту форматованого друку для сценаріїв shell.
   - `man 3 printf` відкриває функцію `int printf(const char *format, ...)` зі стандартної бібліотеки C.
2. **`write`:**
   - `man write` відкриває `write(1)` — термінальну програму для відправки повідомлень іншим залогіненим користувачам.
   - `man 2 write` відкриває системний виклик `ssize_t write(int fd, const void *buf, size_t count)`.
3. **`passwd`:**
   - `man passwd` відкриває `passwd(1)` — утиліту зміни пароля користувача.
   - `man 5 passwd` відкриває `passwd(5)` — опис структури файлу конфігурації `/etc/passwd` (розділення двокрапками, поля UID, GID, домашній каталог).
4. **`stat`:**
   - `man 1 stat` — утиліта виводу метаданих файлу на екран.
   - `man 2 stat` — системний виклик отримання структури `struct stat` через inode.

### Стандартизована анатомія сторінки man

Кожна якісна сторінка `man` будується за фіксованим скелетом секцій:

- **NAME:** Ім'я утиліти чи функції та однорядкове резюме призначення. Цей рядок парситься базою даних `mandb` для команд `apropos` і `whatis`.
- **SYNOPSIS:** Формальна сигнатура виклику. Для команд показує допустимі комбінації опцій та аргументів; для функцій C — необхідні `#include` файли, прототип функції та прапорці компонування (`-lpthread`, `-lrt`).
- **DESCRIPTION:** Детальний текстовий розбір логіки роботи програми чи системного виклику.
- **OPTIONS:** Алфавітний або логічний перелік усіх підтримуваних прапорців із розкриттям їхнього впливу на стан процесу.
- **RETURN VALUE:** *(для розділів 2 та 3)* Що повертає функція при успіху (`0`, кількість байтів або вказівник) та при помилці (`-1` або `NULL`).
- **ERRORS:** *(для розділів 2 та 3)* Повний перелік можливих значень глобальної змінної `errno` (`EINTR`, `EAGAIN`, `ENOMEM`, `EFAULT`) із точним зазначенням умов їх виникнення.
- **ATTRIBUTES:** Таблиця потокобезпечності (*Thread Safety*), безпеки при скасуванні потоку (*Async-Cancel-Safety*) та безпеки виклику в обробниках сигналів (*Async-Signal-Safety*).
- **CONFORMING TO / STANDARDS:** Відповідність стандартам (POSIX.1-2001, POSIX.1-2008, C99, C11, SVr4, 4.3BSD).
- **NOTES:** Тонкощі реалізації в ядрі Linux, відмінності між різними версіями `glibc`.
- **BUGS:** Відомі обмеження або недоліки реалізації.
- **EXAMPLE:** Робочі приклади коду або сценаріїв виклику.
- **SEE ALSO:** Перехресні посилання на пов'язані сторінки керівництва із зазначенням розділів (наприклад, `fork(2)`, `execve(2)`, `waitpid(2)`).

## Еволюція синтаксису прапорців командного рядка

Протягом п'ятдесяти років розвитку Unix способи передачі прапорців процесу змінювалися від простих однолітерних перемикачів до складних ієрархічних систем із валідацією типів. Докладний нормативний звід правил наведено у вставці [Специфікація синтаксису CLI](root:sys-unix/cli-help-conventions/api-cli-option-grammar.md).

![Стилі прапорців CLI та правила розбору аргументів](/root/sys/sys-unix/cli-help-conventions/img/cli-syntax-styles.svg)
*Еволюція та взаємодія синтаксисів аргументів командного рядка: POSIX, GNU, BSD та захисний маркер подвійного дефіса.*

### Стиль UNIX V7 та стандарт POSIX: короткі опції та групування

У ранніх версіях Unix (1970-ті роки) ресурси пам'яті були вкрай обмежені, тому опції кодувалися однією латинською літерою з початковим дефісом: `-a`, `-l`, `-f`.

Стандарт POSIX закріпив цей стиль через стандартизовану функцію C `getopt()`:
1. **Групування опцій без аргументів (*bundling*):** Якщо утиліта підтримує прапорці `-a`, `-b`, `-c`, користувач може записати їх окремо (`-a -b -c`) або згрупувати разом під одним дефісом: `-abc` чи `-cba`.
2. **Передача аргументів короткій опції:** Якщо опція вимагає значення (наприклад, `-o`), воно може передаватися як окремим наступним токеном (`-o output.txt`), так і записуватися злитно без пробілу (`-ooutput.txt`).
3. **Обмеження POSIX:** Коротка опція в чистому стандарті POSIX не може мати опціонального аргументу. Якщо опція оголошена як така, що приймає аргумент, наступний токен завжди вважається її значенням, що виключає неоднозначність розбору.

### Стиль GNU: довгі описові опції

Зі зростанням складності системних програм 26 літер латинського алфавіту (навіть з урахуванням великих і малих літер — 52 символи) виявилося недостатньо. Крім того, виклики на кшталт `tar -zxvf file.tar.gz` складно читати в автоматизованих shell-скриптах.

Проект GNU ввів концепцію **довгих опцій** (*GNU Long Options*), що починаються з подвійного дефіса `--`:
- **Повні слова через дефіс:** `--all`, `--ignore-case`, `--max-depth=2`.
- **Два формати аргументів:** Обов'язкове значення може відокремлюватися знаком рівності (`--file=archive.tar`) або пробілом (`--file archive.tar`).
- **Опціональні аргументи:** Довгі опції підтримують необов'язкові значення, але **виключно через знак рівності**: `--color[=WHEN]`. Якщо користувач вводить `--color`, вмикається режим за замовчуванням; якщо вводить `--color=always`, передається явне значення. Формат із пробілом `--color always` заборонений, бо `always` буде інтерпретовано як наступний позиційний файл.
- **Скорочення однозначних префіксів:** Якщо в системі є опція `--verbose` і немає інших опцій на `--verb*`, парсер `getopt_long` дозволяє користувачеві ввести скорочений варіант `--verb`. Проте в продуктових скриптах слід завжди писати повну назву: якщо в новій версії програми з'явиться опція `--verbosity`, скорочення `--verb` стане неоднозначним і скрипт зламається.

### Стиль BSD: прапорці без дефісів

В операційних системах сімейства BSD історично закріпився синтаксис виклику утиліт взагалі без дефісів для команд, що приймають фіксовані режими дій:
- `tar xvf archive.tar` замість `tar -x -v -f archive.tar`
- `ps aux` замість `ps -aux`

> ⚠️ **Пастка семантики `ps aux`:**
> В утиліті `ps` стиль BSD (`ps aux`) та стиль POSIX (`ps -aux`) мають кардинально різну семантику!
> - `ps aux` (стиль BSD) розшифровується як: `a` (процеси всіх користувачів на терміналах), `u` (орієнтований на користувача формат виводу зі стовпчиками пам'яті та CPU), `x` (процеси без керуючого термінала, включно з системними демонами).
> - `ps -aux` (стиль POSIX) сприймає `-a` (всі процеси з терміналами), а прапорець `-u` сприймає наступний символ `x` як ім'я користувача! Якщо в системі немає користувача з іменем `x`, команда поверне помилку; якщо ж такий користувач існує, команда покаже процеси лише цього користувача.

### Стиль X11 / Xt

Графічна підсистема X Window System використовувала власний синтаксис розбору параметрів: довгі описові назви з одним дефісом (`-display :0.0`, `-geometry 80x24`, `-background black`). Цей синтаксис повністю ламає сумісність із правилом групування POSIX: парсер `getopt` розібрав би `-display` як конкатенацію коротких прапорців `-d -i -s -p -l -a -y`. Сьогодні в сучасних утилітах Linux стиль X11 вважається застарілим і не рекомендується до використання.

## Стандарти завершення опцій: захисний маркер `--`

Одна з найнебезпечніших проблем інтерфейсу командного рядка виникає тоді, коли позиційний аргумент (ім'я файлу чи каталогу) починається з символу дефіса `-`.

### Проблема «ін'єкції прапорців» через імена файлів

Уявімо ситуацію: зловмисник або некоректно написана програма створює в поточному каталозі файл із назвою `-rf` або `-i`:

```bash
$ touch -- -rf
$ ls -l
-rw-r--r-- 1 user user 0 сер 25 12:00 -rf
```

Якщо користувач або недосвідчений розробник у скрипті спробує видалити всі файли каталогу командою видалення з маскою:

```bash
$ rm *
```

Командна оболонка розгортає маску `*` в алфавітному порядку. Першим аргументом утиліта `rm` отримує токен `-rf`. Парсер аргументів `rm` інтерпретує рядок `-rf` не як ім'я файлу для видалення, а як власні системні прапорці: `-r` (*recursive*) та `-f` (*force*). Утиліта починає рекурсивно та без попереджень видаляти всі підкаталоги.

### Механізм роботи маркера `--`

Стандарт POSIX Guideline 10 визначає фундаментальне правило: **два дефіси без додаткових символів (`--`) слугують маркером безумовного завершення списку опцій**.

Коли системний парсер (`getopt` або `getopt_long`) зустрічає токен `--`:
1. Він негайно зупиняє розпізнавання будь-яких прапорців.
2. Вказівник або індекс поточного аргументу (`optind`) переміщується на наступний елемент масиву `argv`.
3. Усі наступні елементи `argv` розглядаються суворо як позиційні аргументи (шляхи до файлів, текстові рядки), навіть якщо вони починаються з одного чи кількох дефісів.

Правильні способи безпечної роботи з довільними файлами:

```bash
# Спосіб 1: використання розділювача опцій --
rm -- -rf
grep --pattern="error" -- -filename.log

# Спосіб 2: ясне зазначення шляху від поточного каталогу ./
rm ./-rf
cat ./-data.txt
```

### Конвенція одинарного дефіса `-`

Якщо замість імені файлу в командному рядку передається одинарний дефіс `-`, утиліти Unix за загальноприйнятою домовленістю інтерпретують його як **стандартний ввід (`stdin`)** для читання або **стандартний вивід (`stdout`)** для запису:

```bash
# Створення архіву в пам'яті та передача по SSH без проміжних файлів
tar -czf - . | ssh backup-server 'tar -xzf - -C /var/backups'

# Порівняння згенерованого виводу з еталонним файлом
./generate_report | diff -u reference.txt -
```

## Анатомія якісного виводу `--help`

Висвітлення довідки через прапорець `--help` — це не просто довільний текст, а формалізований інтерфейс. Недбало оформлений `--help` ускладнює автоматизований парсинг і створює проблеми для користувачів.

### Структурні блоки ідеальної довідки

```text
Usage: fgrep [OPTION]... PATTERNS [FILE]...
Search for PATTERNS in each FILE.

Pattern selection and interpretation:
  -e, --regexp=PATTERNS   use PATTERNS for matching
  -f, --file=FILE         take PATTERNS from FILE
  -i, --ignore-case       ignore case distinctions in patterns and data

Output control:
  -c, --count             print only a count of selected lines per FILE
  -l, --files-with-matches  print only names of FILEs with selected lines
  -n, --line-number       print line number with output lines
      --color[=WHEN]      use markers to highlight the matching strings;
                            WHEN may be 'always', 'never', or 'auto' [default: auto]

Context control:
  -B, --before-context=NUM  print NUM lines of leading context
  -A, --after-context=NUM   print NUM lines of trailing context

Miscellaneous:
  -h, --help              display this help and exit
  -V, --version           output version information and exit

When FILE is '-', read standard input.  Exit status is 0 if any line was
selected, 1 if no lines were selected, and 2 if an error occurred.

Full documentation at: <https://www.gnu.org/software/grep/manual/>
Report bugs to: <bug-grep@gnu.org>
```

Головні інженерні правила побудови виводу:
1. **Рядок Usage (синопсис):** Показує порядок операндів. Квадратні дужки `[ ]` позначають необов'язкові елементи, три крапки `...` — можливість повторення, вертикальна риска `|` — взаємовиключний вибір.
2. **Логічне групування опцій:** Опції розбиваються на смислові блоки (*Modes*, *Input/Output*, *Filtering*, *Diagnostics*), а не звалюються в один безладний список за алфавітом.
3. **Вирівнювання стовпчиків:** Короткі опції, довгі опції, назви параметрів та тексти описів мають чітке фіксоване вирівнювання за допомогою пробілів (табуляція в терміналах із різною шириною може спотворювати форматування).
4. **Явні значення за замовчуванням:** Для параметрів із числовими значеннями чи режимами обов'язково вказується дефолт: `[default: 4096]`, `[default: auto]`.
5. **Коди повернення (*Exit status*):** Довідка має явно декларувати, що означають статуси завершення процесу.
6. **Посилання на документацію та зворотний зв'язок:** Завершальний блок містить URL або команду перегляду повної інструкції та електронну адресу/трекер для звітів про дефекти.

### Правило розподілу потоків та кодів повернення

- Якщо користувач **явно запитав довідку** (`cmd --help` або `cmd -h`): текст надсилається у потік **`stdout`**, а процес завершується з кодом **`0`** (*EXIT_SUCCESS*). Це дозволяє читати довідку через пейджер: `mycmd --help | less`.
- Якщо користувач **зробив помилку в аргументах** (ввів невідомий прапорець `cmd -z` чи забув параметр): коротке повідомлення про помилку надсилається у потік **`stderr`**, процес завершується з кодом **`2`** (*помилка аргументів CLI*), а повний текст `--help` **не друкується**, щоб не засмічувати екран. Натомість виводиться підказка: `Try 'mycmd --help' for more information.`.

## Розбір аргументів у коді: практична реалізація

Для побудови надійного CLI у системному програмуванні на C використовується бібліотека `getopt_long`, а в сучасному C++ — типобезпечні обгортки над системним масивом `argv`. Повнофункціональний зразок реалізації парсера з підтримкою всіх розглянутих стандартів доступний у вставці [Парсер аргументів на C та C++](root:sys-unix/cli-help-conventions/proj-cli-parser-getopt.md).

### Механіка глобального стану в C `getopt_long`

Функція `getopt_long()` спирається на глобальний стан бібліотеки `glibc`:
- `optind` (*option index*) — індекс наступного елемента в масиві `argv`, який буде оброблено. Початкове значення `1`. Після завершення циклу `while (getopt(...) != -1)` змінна `optind` вказує на перший позиційний аргумент.
- `optarg` (*option argument*) — вказівник на рядок значення поточної опції (якщо вона вимагає аргументу).
- `opterr` — якщо встановлено в `1`, бібліотека автоматично друкує повідомлення про помилки в `stderr`; якщо `0` — програма формує повідомлення самостійно.
- `optopt` — містить символ невідомої опції при виникненні помилки.

:::tabs
```c
#include <getopt.h>

static const struct option long_options[] = {
    {"output",  required_argument, NULL, 'o'},
    {"verbose", no_argument,       NULL, 'v'},
    {"color",   optional_argument, NULL, 'c'},
    {"help",    no_argument,       NULL, 'h'},
    {NULL, 0, NULL, 0} /* Маркер кінця таблиці */
};
```
```cpp
#include <getopt.h>
#include <array>
#include <string_view>

// Типобезпечна таблиця опцій у C++20
inline constexpr std::array<option, 5> LongOptions{{
    {"output",  required_argument, nullptr, 'o'},
    {"verbose", no_argument,       nullptr, 'v'},
    {"color",   optional_argument, nullptr, 'c'},
    {"help",    no_argument,       nullptr, 'h'},
    {nullptr, 0, nullptr, 0}
}};
```
:::

Таблиця `struct option` складається з чотирьох полів:
1. `name` — текстова назва довгої опції (`const char *`).
2. `has_arg` — константа `no_argument` (0), `required_argument` (1) або `optional_argument` (2).
3. `flag` — якщо `NULL`, функція повертає значення поля `val`; якщо вказано вказівник на `int`, туди записується `val`, а функція повертає `0`.
4. `val` — значення, що повертається при виявленні цієї опції (зазвичай код відповідної короткої опції).

### Перестановка аргументів (Argument Permutation) у GNU проти строгого POSIX

За замовчуванням у GNU/Linux функція `getopt_long()` реалізує механізм перестановки: якщо користувач викликає програму у вигляді:

```bash
$ mygrep file1.txt -i file2.txt --color=always
```

Парсер GNU автоматично переставляє елементи `argv` так, щоб усі опції опинилися на початку, а позиційні операнди `file1.txt` та `file2.txt` — наприкінці.

Якщо системі потрібна сувора сумісність із POSIX (зупинка розбору на першому ж аргументі без дефіса), поведінку можна змінити двома способами:
1. Встановити системну змінну оточення `POSIXLY_CORRECT=1`.
2. Поставити символ плюса `+` на початку рядка коротких опцій: `+o:vh`.

## Сучасні інструменти створення документації

Створення сторінок `man` безпосередньо макросами `groff` у XXI столітті практично відійшло в минуле. Сучасні системні проекти (такі як `systemd`, `git`, `ripgrep`, `docker`, `kubernetes`) використовують автоматизовані конвеєри складання документації з єдиного першоджерела.

### Генерація з легких мов розмітки

1. **AsciiDoc (`asciidoctor-manpage`):** Використовується проектом Git. Один файл `.adoc` компілюється в офіційний сайт з документацією, PDF-книгу та повний набір сторінок `man` (розділи 1, 5, 7).
2. **`scdoc`:** Мінімалістичний компілятор, написаний на чистому C, який використовується в сучасних утилітах Wayland та Linux (наприклад, `sway`, `waybar`). Він транслює спрощений діалект Markdown у валідний вивід `troff` без залежностей від важких середовищ виконання.
3. **`help2man`:** Автоматичний інструмент збірки, що запускає скомпільовану програму з прапорцем `--help` і транслює вивід у файл сторінки `man`.

### Бібліотеки розбору CLI з автоматичною генерацією довідки

У сучасних мовах програмування генерація виводу `--help`, перевірка типів аргументів та валідація діапазонів значень виконуються декларативними бібліотеками:
- **C++:** Бібліотеки `CLI11`, `argparse`, `cxxopts` дозволяють описати інтерфейс за допомогою типізованих об'єктів, автоматично формуючи кольоровий, структурований `--help` із перевіркою обмежень.
- **Rust:** Бібліотека `clap` (через макроси `derive`) генерує парсер аргументів, вивід `--help`, автодоповнення для shell (Bash, Zsh, Fish) та сторінки `man` безпосередньо з коментарів до структур даних.
- **Go:** Пакунки `cobra` та `pflag` забезпечують єдиний стандарт CLI для всієї екосистеми хмарних утиліт (`kubectl`, `docker`, `helm`).

Завдяки поєднанню строгого синтаксичного стандарту POSIX/GNU, швидких вбудованих підказок `--help` та структурованих сторінок `man` операційні системи Unix забезпечують повну автономність, передбачуваність взаємодії та довговічність написаних системних сценаріїв.
