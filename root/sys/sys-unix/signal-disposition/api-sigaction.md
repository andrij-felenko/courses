# 📋 `struct sigaction`, прапорці `SA_*` і всі 64 номери сигналів

Це контракт, яким процес заповнює рядок таблиці диспозицій: точний склад структури, значення кожного прапорця доставки, вміст `siginfo_t`, коди помилок — і повний перелік номерів Linux із типовою дією та позначкою, чи можна цей номер перехопити.

## Структура, яку читає ядро

```c
#include <signal.h>

struct sigaction {
    void     (*sa_handler)(int);                          /* або SIG_DFL / SIG_IGN */
    void     (*sa_sigaction)(int, siginfo_t *, void *);   /* лише з SA_SIGINFO */
    sigset_t   sa_mask;
    int        sa_flags;
    void     (*sa_restorer)(void);                        /* не для програм */
};
```

| Поле | Тип | Що означає |
|---|---|---|
| `sa_handler` | `void (*)(int)` | адреса простого обробника або `SIG_DFL` (число 0) чи `SIG_IGN` (число 1), приведені до вказівника на функцію |
| `sa_sigaction` | `void (*)(int, siginfo_t *, void *)` | розширений обробник: номер, опис події, знімок регістрів (`ucontext_t *`) |
| `sa_mask` | `sigset_t` | які сигнали **додатково** заблокувати на час роботи обробника |
| `sa_flags` | `int` | набір `SA_*` — як саме доставляти |
| `sa_restorer` | `void (*)(void)` | трамплін, через який обробник повертається в ядро; ставить libc |

Два перші поля на більшості архітектур лежать в одному об'єднанні, тож присвоювати обидва не можна: обираєте `sa_sigaction` — зводите `SA_SIGINFO`, обираєте `sa_handler` — не зводите. Структуру перед заповненням обнуляють (`memset`), бо невизначені поля ядро прочитає як сміття.

`sa_mask` діє тільки на час обробника й відновлюється при поверненні з нього. Сам сигнал, що доставляється, ядро блокує саме́ — окремо його в маску вносити не треба (і не буде заблоковано, якщо стоїть `SA_NODEFER`). Маска в цьому полі — не диспозиція, а відкладення доставки ([маска сигналів і `signalfd`](topic:sys-unix/signal-mask-signalfd) — чим тимчасове блокування відрізняється від рішення про реакцію й куди дівається сигнал, поки маска стоїть).

`sa_restorer` POSIX не описує зовсім. На більшості архітектур ядро не має куди повернути обробник самотужки й вимагає готовий шматочок коду з викликом `rt_sigreturn`; його підставляє libc разом із внутрішнім прапорцем `SA_RESTORER` ([сигнальний кадр і `rt_sigreturn`](topic:sys-unix/signal-frame-and-sigreturn) — що ядро кладе на стек перед викликом обробника і як звідти повертається керування).

## Прапорці `sa_flags`

| Прапорець | Що саме змінює |
|---|---|
| `SA_SIGINFO` | кликати `sa_sigaction` із трьома аргументами замість `sa_handler` з одним (від Linux 2.2) |
| `SA_RESTART` | системний виклик, перерваний цим сигналом, ядро переграє заново замість того, щоб віддати `EINTR` |
| `SA_NODEFER` | не блокувати сам сигнал на час його ж обробника — обробник може перервати сам себе (старе ім'я `SA_NOMASK`) |
| `SA_RESETHAND` | перед входом в обробник скинути диспозицію в `SIG_DFL`, тобто спрацювати рівно раз (старе ім'я `SA_ONESHOT`) |
| `SA_ONSTACK` | виконувати обробник на окремому стеку, заведеному `sigaltstack(2)`; якщо такого стеку нема — на звичайному |
| `SA_NOCLDSTOP` | не слати `SIGCHLD` про зупинку й продовження нащадків — лише про завершення (має сенс тільки для `SIGCHLD`) |
| `SA_NOCLDWAIT` | завершені нащадки не стають зомбі, коди виходу пропадають (тільки для `SIGCHLD`) |
| `SA_EXPOSE_TAGBITS` | зберігати в `si_addr` архітектурні біти-мітки адреси (ARM MTE, SPARC ADI), які інакше обнуляються (від Linux 5.11) |
| `SA_UNSUPPORTED` | доставки не міняє: спосіб спитати ядро, які прапорці воно взагалі розуміє (від Linux 5.11) |
| `SA_RESTORER` | взяти трамплін повернення з поля `sa_restorer`; внутрішній прапорець libc |

Пара `SA_RESETHAND | SA_NODEFER` відтворює давню семантику System V, а самотній `SA_RESTART` — семантику 4.2BSD; саме тому обидва й існують окремими бітами.

`SA_RESTART` рятує не завжди: перезапустними є не всі виклики, а перелічений набір, і навіть у ньому виклики з таймаутом після переривання повертають `EINTR` ([`EINTR` і перезапуск](topic:sys-unix/eintr-and-restart) — які саме виклики ядро переграє, які повертають помилку завжди і як писати цикл, що не залежить від прапорця).

Історично ядро мовчки ігнорувало невідомі йому біти в `sa_flags`, тож програма не могла дізнатися, чи прапорець спрацював. Із Linux 5.11 є проба: звести `SA_UNSUPPORTED` разом із сумнівним прапорцем, а потім прочитати диспозицію назад — якщо в прочитаному `sa_flags` біт `SA_UNSUPPORTED` знято, решта бітів у ньому й показує, що ядро підтримує.

## Що приходить в обробник із `SA_SIGINFO`

```c
siginfo_t {
    int          si_signo;   /* номер сигналу — той самий, що в першому аргументі */
    int          si_errno;   /* errno події, якщо ядро його дає; здебільшого 0     */
    int          si_code;    /* ХТО або ЩО породило сигнал                          */
    pid_t        si_pid;     /* pid відправника   (SI_USER, SI_QUEUE, SI_TKILL, SIGCHLD) */
    uid_t        si_uid;     /* реальний uid відправника                            */
    int          si_status;  /* код виходу або номер сигналу нащадка      (SIGCHLD) */
    void        *si_addr;    /* адреса збою  (SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGTRAP) */
    union sigval si_value;   /* значення від sigqueue(3): .sival_int / .sival_ptr   */
    long         si_band;    /* яка саме подія вводу-виводу      (SIGIO / SIGPOLL)  */
    int          si_fd;      /* дескриптор                       (SIGIO / SIGPOLL)  */
}
```

У справжньому оголошенні це велике об'єднання; наведено поля, які читають найчастіше. Значущі з них лише ті, що відповідають конкретному `si_code`, — решта містить довільні байти. Тому `si_pid` заслуговує довіри тільки за кодів `SI_USER`, `SI_QUEUE`, `SI_TKILL` і для `SIGCHLD`, а `si_addr` — лише для апаратних винятків.

| `si_code` | Звідки сигнал |
|---|---|
| `SI_USER` | `kill(2)` або `raise(3)` |
| `SI_KERNEL` | породжено самим ядром |
| `SI_QUEUE` | `sigqueue(3)` — разом зі значенням у `si_value` |
| `SI_TIMER` | спрацював POSIX-таймер (`timer_create(2)`); `alarm(2)` і `setitimer(2)` дають натомість `SI_KERNEL` |
| `SI_MESGQ` | змінився стан черги повідомлень (`mq_notify(3)`) |
| `SI_ASYNCIO` | завершилася асинхронна операція вводу-виводу |
| `SI_TKILL` | `tkill(2)` / `tgkill(2)` — сигнал конкретному потокові, а не процесові |

| Сигнал | Найуживаніші коди |
|---|---|
| `SIGSEGV` | `SEGV_MAPERR` — за адресою нічого не відображено; `SEGV_ACCERR` — відображено, але права не ті; `SEGV_PKUERR` — заборонив ключ захисту пам'яті |
| `SIGBUS` | `BUS_ADRALN` — невирівняна адреса; `BUS_ADRERR` — фізичної адреси не існує; `BUS_OBJERR` — апаратна помилка об'єкта; `BUS_MCEERR_AR`, `BUS_MCEERR_AO` — збійна сторінка пам'яті |
| `SIGFPE` | `FPE_INTDIV`, `FPE_INTOVF` — цілочислове ділення на нуль і переповнення; `FPE_FLTDIV`, `FPE_FLTOVF`, `FPE_FLTUND`, `FPE_FLTINV` — плаваюча кома |
| `SIGILL` | `ILL_ILLOPC` — недійсний код операції; `ILL_PRVOPC`, `ILL_PRVREG` — привілейована інструкція чи регістр; `ILL_BADSTK` — внутрішня помилка стека |
| `SIGTRAP` | `TRAP_BRKPT` — точка спину; `TRAP_TRACE` — покроковий слід; `TRAP_HWBKPT` — апаратна точка спостереження |
| `SIGCHLD` | `CLD_EXITED`, `CLD_KILLED`, `CLD_DUMPED`, `CLD_TRAPPED`, `CLD_STOPPED`, `CLD_CONTINUED` |
| `SIGSYS` | `SYS_SECCOMP` — виклик заборонив фільтр, поруч заповнено `si_syscall`, `si_arch`, `si_call_addr` ([seccomp](topic:sys-unix/seccomp-filter-mechanism) — фільтр системних викликів, який може відповісти пасткою замість відмови) |
| `SIGIO`, `SIGPOLL` | `POLL_IN`, `POLL_OUT`, `POLL_MSG`, `POLL_ERR`, `POLL_PRI`, `POLL_HUP` |

## Виклики, помилки, мінімальний зразок

```c
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);      /* однопотокова програма */
int pthread_sigmask(int how, const sigset_t *set, sigset_t *oldset);  /* багатопотокова        */

int sigemptyset(sigset_t *set);        /* набір ОБОВ'ЯЗКОВО спорожнити або заповнити */
int sigfillset(sigset_t *set);         /* перед першим sigaddset                     */
int sigaddset(sigset_t *set, int signum);
int sigdelset(sigset_t *set, int signum);
int sigismember(const sigset_t *set, int signum);   /* 1 — є, 0 — нема, -1 — помилка */

/* how для (pthread_)sigprocmask: SIG_BLOCK | SIG_UNBLOCK | SIG_SETMASK */

int sigaltstack(const stack_t *ss, stack_t *old_ss);       /* стек для SA_ONSTACK */
int sigqueue(pid_t pid, int sig, const union sigval value); /* сигнал зі значенням */
```

Два виклики з цього списку самі по собі диспозиції не міняють, але без них частина контракту не працює. `sigaltstack` заводить окремий стек (`ss.ss_sp`, `ss.ss_size` не менше за `MINSIGSTKSZ`, `ss.ss_flags = 0`) — і лише після цього `SA_ONSTACK` має куди перемкнути обробник; без нього прапорець мовчки нічого не робить, а `SIGSEGV` від переповнення стека спіймати не вдасться, бо обробникові ніде виконуватися. `sigqueue` шле сигнал разом зі значенням, яке доїде в `si_value` при `si_code == SI_QUEUE`; черга таких сигналів обмежена лімітом `RLIMIT_SIGPENDING`, а при його вичерпанні виклик повертає `EAGAIN`.

| Виклик | Код | Коли |
|---|---|---|
| `sigaction` | `EINVAL` | недійсний номер; спроба змінити `SIGKILL` чи `SIGSTOP`; у glibc — ще й службові 32 і 33 |
| `sigaction` | `EFAULT` | `act` або `oldact` указує поза адресний простір процесу |
| `sigprocmask` | `EINVAL` | недійсне значення `how` |
| `sigprocmask` | `EFAULT` | `set` або `oldset` указує поза адресний простір |
| `sigaddset`, `sigdelset`, `sigismember` | `EINVAL` | недійсний номер сигналу |
| `rt_sigaction` (сирий) | `EINVAL` | `sigsetsize` не дорівнює розмірові ядрового `sigset_t` (8 байтів) |

Несиметричність, на якій часто спотикаються: `sigaction(SIGKILL, …)` — це помилка `EINVAL`, а `SIGKILL` у наборі для `sigprocmask` жодної помилки не дає — його просто мовчки викидають із маски. Тобто «заблокувати `SIGKILL`» виглядає як успіх і не робить нічого.

Другий підводний камінь тієї ж таблиці — номери 32 і 33. Це не звичайні реальночасові сигнали: `SIGCANCEL` (скасування потоку) і `SIGSETXID` (зміна ідентичності одразу в усіх потоках) належать реалізації потоків у glibc, тож бібліотека відсіює їх сама — `sigaction` і `sigaddset` на них повертають `EINVAL`, не доходячи до ядра.

Виклик із `act == NULL` нічого не змінює, а лише читає поточну диспозицію — саме так перевіряють успадковане `SIG_IGN`, перш ніж ставити своє:

```c
#define _POSIX_C_SOURCE 200809L
#include <signal.h>
#include <string.h>

static volatile sig_atomic_t last_sender = 0;

static void on_usr1(int signo, siginfo_t *si, void *uctx) {
    (void)signo; (void)uctx;
    last_sender = (si->si_code == SI_USER || si->si_code == SI_QUEUE)
                ? (sig_atomic_t)si->si_pid    /* si_pid значущий лише за цих кодів */
                : -1;
}

int arm_usr1(void) {
    struct sigaction sa, old;

    if (sigaction(SIGUSR1, NULL, &old) == -1)   /* act == NULL — тільки прочитати */
        return -1;
    if (old.sa_handler == SIG_IGN)              /* хтось згори вже сказав «ігнорувати» */
        return 0;                               /* — не перебиваємо його рішення      */

    memset(&sa, 0, sizeof sa);
    sa.sa_sigaction = on_usr1;                  /* НЕ sa_handler: поля в об'єднанні */
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_SIGINFO | SA_RESTART;

    return sigaction(SIGUSR1, &sa, NULL);       /* 0 або -1 з errno */
}
```

Порівняння `old.sa_handler == SIG_IGN` тут дозволене попри об'єднання: `SIG_IGN` несумісне з `SA_SIGINFO`, тож у цьому полі лежить саме воно. Обробник же обмежений тим, що в ньому взагалі можна викликати ([безпека в обробнику](topic:sys-unix/async-signal-safety) — чому туди годяться лише асинхронно-сигнально-безпечні виклики, а `printf` і `malloc` — ні).

## Усі номери: типова дія й чи можна перехопити

Номери в таблиці — для x86, ARM і більшості інших архітектур; розбіжності зібрано нижче. «Дамп» означає завершення з аварійним образом пам'яті ([аварійний дамп](topic:sys-unix/core-dump) — знімок пам'яті й регістрів у мить смерті, з якого налагоджувач відновлює стек викликів).

| № | Сигнал | Типова дія | Перехопити | Подія |
|---|---|---|---|---|
| 1 | `SIGHUP` | завершити | так | обрив термінала або смерть керівного процесу |
| 2 | `SIGINT` | завершити | так | Ctrl+C |
| 3 | `SIGQUIT` | дамп | так | Ctrl+\ |
| 4 | `SIGILL` | дамп | так | недійсна інструкція |
| 5 | `SIGTRAP` | дамп | так | точка спину, крок налагоджувача |
| 6 | `SIGABRT` = `SIGIOT` | дамп | так | `abort(3)`, невдале твердження `assert` |
| 7 | `SIGBUS` | дамп | так | звернення, яке не лягає на пам'ять: невирівняне, за кінцем відображеного файлу |
| 8 | `SIGFPE` | дамп | так | хибна арифметика: ділення на нуль, переповнення |
| 9 | `SIGKILL` | завершити | **ні** | безумовне вбивство |
| 10 | `SIGUSR1` | завершити | так | зміст визначає сама програма |
| 11 | `SIGSEGV` | дамп | так | звернення за недійсною адресою |
| 12 | `SIGUSR2` | завершити | так | зміст визначає сама програма |
| 13 | `SIGPIPE` | завершити | так | запис у канал чи сокет, який ніхто не читає |
| 14 | `SIGALRM` | завершити | так | `alarm(2)`, таймер `ITIMER_REAL` |
| 15 | `SIGTERM` | завершити | так | прохання завершитися |
| 16 | `SIGSTKFLT` | завершити | так | «збій стека співпроцесора»; ядро Linux його не породжує |
| 17 | `SIGCHLD` = `SIGCLD` | ігнорувати | так | нащадок завершився, зупинився або продовжився |
| 18 | `SIGCONT` | продовжити | так¹ | продовжити зупинений процес |
| 19 | `SIGSTOP` | зупинити | **ні** | безумовна зупинка |
| 20 | `SIGTSTP` | зупинити | так | Ctrl+Z |
| 21 | `SIGTTIN` | зупинити | так | фонове читання з термінала |
| 22 | `SIGTTOU` | зупинити | так | фоновий запис у термінал (за `TOSTOP`) |
| 23 | `SIGURG` | ігнорувати | так | термінові (out-of-band) дані в сокеті |
| 24 | `SIGXCPU` | дамп | так | вичерпано `RLIMIT_CPU` |
| 25 | `SIGXFSZ` | дамп | так | вичерпано `RLIMIT_FSIZE` |
| 26 | `SIGVTALRM` | завершити | так | таймер `ITIMER_VIRTUAL` — час у просторі користувача |
| 27 | `SIGPROF` | завершити | так | таймер `ITIMER_PROF` — час користувача плюс системний |
| 28 | `SIGWINCH` | ігнорувати | так | змінився розмір вікна термінала |
| 29 | `SIGIO` = `SIGPOLL` | завершити | так | на дескрипторі став можливий ввід-вивід |
| 30 | `SIGPWR` | завершити | так | збій живлення |
| 31 | `SIGSYS` = `SIGUNUSED` | дамп | так | хибний системний виклик; пастка `SECCOMP_RET_TRAP` |

¹ `SIGCONT` перехопити можна, але зупинений процес він продовжить у будь-якому разі — навіть якщо його заблоковано або переведено в `SIG_IGN`; обробник (якщо є) відпрацює вже після відновлення роботи ([керування завданнями](topic:sys-unix/job-control) — як оболонка перекладає групи процесів між станами «працює» й «зупинена»).

Номери 32–64 — реальночасові. Наперед визначеного змісту в них немає, типова дія в усіх одна — завершити, перехопити можна кожен.

| № | Ім'я | Примітка |
|---|---|---|
| 32 | `SIGCANCEL` | зайнято glibc: скасування потоку (`pthread_cancel`) |
| 33 | `SIGSETXID` | зайнято glibc: `setuid` та рідня одразу в усіх потоках |
| 34 | `SIGRTMIN` | перший, доступний програмі |
| 35–63 | `SIGRTMIN+1` … `SIGRTMIN+29` | вільні |
| 64 | `SIGRTMAX` | останній |

`SIGRTMIN` у glibc — не стала, а виклик: бібліотека рахує його з урахуванням своїх службових номерів (34 для NPTL, 35 для давньої LinuxThreads). Тому номер 34 у коді не пишуть — пишуть `SIGRTMIN+n` і перевіряють, що `SIGRTMIN+n <= SIGRTMAX`.

### Розбіжності за архітектурами

Порядкові номери — не частина інтерфейсу: у програмі вживають імена, а числа доводиться знати, коли читаєш чужі журнали, `strace` або маски з `/proc/<pid>/status`.

| Сигнал | x86, ARM, більшість | Alpha, SPARC | MIPS | PARISC |
|---|---|---|---|---|

На Alpha номер 29 має ще й друге ім'я `SIGINFO`, а на SPARC той самий номер зайнято під `SIGLOST`. MIPS вибивається окремо: там ядро визначає 128 номерів замість 64 (`_NSIG` дорівнює 128), тож реальночасовий діапазон тягнеться до 127 — єдина архітектура з таким розширенням, і саме через неї трапляються програми, що спотикаються на сигналі з номером, більшим за 64.
