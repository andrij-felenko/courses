# 📋 Інтерфейс системного виклику BPF Maps: структури, команди та операції

Структури збереження стану **BPF Maps** є єдиним штатним механізмом передачі даних між програмами ядра eBPF та процесами простору користувача, а також збереження агрегованих метрик між викликами обробників подій. Довідник охоплює системний виклик `bpf()`, структури атрибутів `union bpf_attr`, внутрішні механізми виділення пам'яті в ядрі, пакетні операції (*batch operations*), прапорці операцій, допоміжні функції ядра та функції користувацької бібліотеки `libbpf`.

---

## 1. Системний виклик `bpf()` та команди BPF Maps

Будь-яка взаємодія з картами BPF із простору користувача виконується за допомогою універсального системного виклику `bpf()`:

```c
#include <linux/bpf.h>
#include <unistd.h>
#include <sys/syscall.h>

int syscall(__NR_bpf, int cmd, union bpf_attr *attr, unsigned int size);
```

Кожен виклик приймає числову команду `cmd`, вказівник на об'єднання параметрів `attr` та розмір переданої структури `size` (для забезпечення зворотної сумісності ядра при додаванні нових полів).

### Команди маніпуляції картами (`enum bpf_cmd`)

| Команда `cmd` | Числове значення | Призначення та поведінка |
|---|---|---|
| `BPF_MAP_CREATE` | 0 | Створює нову структуру BPF Map у пам'яті ядра та повертає файловий дескриптор `map_fd` |
| `BPF_MAP_LOOKUP_ELEM` | 1 | Пошук значення за вказівником на ключ у вказаній карті; копіює значення у буфер |
| `BPF_MAP_UPDATE_ELEM` | 2 | Додавання або перезапис значення за ключем відповідно до встановлених прапорців |
| `BPF_MAP_DELETE_ELEM` | 3 | Видалення пари ключ-значення з карти (не підтримується для масивів) |
| `BPF_MAP_GET_NEXT_KEY` | 4 | Пошук наступного ключа для послідовної ітерації по всій карті |
| `BPF_MAP_LOOKUP_AND_DELETE_ELEM` | 21 | Атомарне зчитування значення з наступним негайним видаленням елемента |
| `BPF_MAP_FREEZE` | 22 | Переведення карти в стан лише для читання (`Read-Only`) з боку програм eBPF |
| `BPF_MAP_LOOKUP_BATCH` | 24 | Пакетне вичитування множини ключів і значень за один системний виклик |
| `BPF_MAP_LOOKUP_AND_DELETE_BATCH` | 25 | Атомарне пакетне зчитування та видалення блоку елементів |
| `BPF_MAP_UPDATE_BATCH` | 26 | Пакетне оновлення або додавання масиву ключів та значень |
| `BPF_MAP_DELETE_BATCH` | 27 | Пакетне видалення множини елементів за списком ключів |

## 2. Структури параметрів `union bpf_attr`

Для кожної команди у системний виклик передається відповідна анонімна структура всередині об'єднання `union bpf_attr`.

### Створення карти (`BPF_MAP_CREATE`)

```c
struct {
    __u32 map_type;           /* Тип карти з переліку enum bpf_map_type */
    __u32 key_size;           /* Розмір ключа в байтах */
    __u32 value_size;         /* Розмір значення в байтах */
    __u32 max_entries;        /* Максимальна місткість карти (кількість елементів) */
    __u32 map_flags;          /* Прапорці налаштування виділення пам'яті (BPF_F_*) */
    __u32 inner_map_fd;       /* FD внутрішньої карти для map-in-map */
    __u32 numa_node;          /* Ідентифікатор вузла NUMA для оптимізації пам'яті */
    char  map_name[16];       /* Текстова назва карти для діагностики у bpftool */
    __u32 map_ifindex;        /* Індекс мережевого інтерфейсу для апаратного розвантаження */
    __u32 btf_fd;             /* FD завантаженого об'єкта BTF для типізації */
    __u32 btf_key_type_id;    /* ID типу ключа у метаданих BTF */
    __u32 btf_value_type_id;  /* ID типу значення у метаданих BTF */
};
```

### Операції з елементами карти (`LOOKUP`, `UPDATE`, `DELETE`)

```c
struct {
    __u32 map_fd;             /* Файловий дескриптор карти */
    __aligned_u64 key;        /* Вказівник у просторі користувача на буфер ключа */
    union {
        __aligned_u64 value;  /* Вказівник на буфер значення (для LOOKUP / UPDATE) */
        __aligned_u64 next_key; /* Вказівник на наступний ключ (для GET_NEXT_KEY) */
    };
    __u64 flags;              /* Прапорці поведінки операції оновлення */
};
```

### Пакетні операції (`*_BATCH`)

```c
struct {
    __aligned_u64 in_batch;   /* Вхідний токен ітерації (або NULL для старту) */
    __aligned_u64 out_batch;  /* Вихідний токен для продовження ітерації */
    __aligned_u64 keys;       /* Вказівник на масив ключів у просторі користувача */
    __aligned_u64 values;     /* Вказівник на масив значень у просторі користувача */
    __u32 count;              /* Кількість елементів для обробки (вхід/вихід) */
    __u32 map_fd;             /* Файловий дескриптор карти */
    __u64 elem_flags;         /* Прапорці елементів (BPF_EXIST, BPF_NOEXIST) */
    __u64 flags;              /* Прапорці пакетної операції */
};
```

## 3. Прапорці операцій та налаштування пам'яті

### Прапорці створення карти (`map_flags`)

* `BPF_F_NO_PREALLOC` (0x01): Вимикає попереднє виділення пулу пам'яті під час створення карти. За замовчуванням ядро виділяє всю пам'ять під `max_entries` елементів одразу під час виклику `BPF_MAP_CREATE`, щоб уникнути викликів алокатора сторінок у контексті переривань. Встановлення `BPF_F_NO_PREALLOC` економить оперативну пам'ять, але операція вставки може повертати `-ENOMEM` під високим навантаженням.
* `BPF_F_NUMA_NODE` (0x04): Вказує ядру прив'язати пам'ять карти до конкретного вузла NUMA (`numa_node`), що усуває міжвузловий трафік шини процесора.
* `BPF_F_RDONLY` (0x08): Дозволяє програмам eBPF лише читати дані з цієї карти.
* `BPF_F_WRONLY` (0x10): Дозволяє програмам eBPF лише записувати дані в карту.
* `BPF_F_MMAPABLE` (0x400): Дозволяє відображати пам'ять карти безпосередньо в адресний простір користувача за допомогою виклику `mmap()`. Доступно лише для масивів `BPF_MAP_TYPE_ARRAY` і усуває накладні витрати на виклик системних викликів зчитування.

### Прапорці оновлення значень (`flags` у `BPF_MAP_UPDATE_ELEM`)

* `BPF_ANY` (0): Створити новий елемент, якщо ключ відсутній, або перезаписати існуючий.
* `BPF_NOEXIST` (1): Створити елемент лише за умови, що такого ключа ще немає в карті. Якщо ключ уже існує, системний виклик повертає помилку `-EEXIST`.
* `BPF_EXIST` (2): Оновити елемент лише якщо вказаний ключ уже присутній у карті. Якщо ключ відсутній, повертається помилка `-ENOENT`.
* `BPF_F_LOCK` (4): Виконувати операцію оновлення під захистом вбудованого блокування `bpf_spin_lock` у структурі значення.

## 4. Класифікація типів карт та організація пам'яті ядра

Підсистема BPF підтримує спеціалізовані структури даних під конкретні системні сценарії:

### Хеш-таблиця (`BPF_MAP_TYPE_HASH`)
Організована як масив кошиків (*hash buckets*) зі зв'язаними списками колізій `struct htab_elem`. Пошук ключа виконується за допомогою функції `jhash` (або `siphash`). За замовчуванням пам'ять під усі елементи попередньо виділяється у внутрішній пул (*freelist*), що гарантує захист від фрагментації пам'яті ядра. Дозволяє довільний розмір ключа та значення.

### Масив фіксованого розміру (`BPF_MAP_TYPE_ARRAY`)
Виділяється ядром як один неперервний блок віртуальної пам'яті `struct bpf_array`. Ключем завжди є 32-розрядне беззнакове ціле число `0 <= index < max_entries`. Оскільки зміщення кожного елемента обчислюється за сталою формулою `offset = index * value_size`, операції пошуку та оновлення виконуються за гарантований час `O(1)` без використання хешування. Масиви не підтримують операцію видалення елемента (`BPF_MAP_DELETE_ELEM` повертає `-EINVAL`).

### Per-CPU карти (`BPF_MAP_TYPE_PERCPU_ARRAY` / `PERCPU_HASH`)
Виділяють пам'ять за допомогою внутрішнього алокатора ядра `alloc_percpu()`. Кожне логічне ядро процесора володіє власною локальною копією структури даних. Коли програма eBPF виконує оновлення лічильника, запис іде виключно у локальний кеш процесора. Це усуває конфлікти кеш-ліній (*cache line bouncing*) між ядрами процесора та забезпечує лінійне масштабування продуктивності. Простір користувача при виклику `bpf_map_lookup_elem()` отримує буфер розміром `value_size * num_cpus` і виконує підсумовування локально.

### LRU-карти (`BPF_MAP_TYPE_LRU_HASH`)
Хеш-таблиця з автоматичним витісненням елементів за алгоритмом Least Recently Used. Всередині ядра підтримуються списки активних та неактивних елементів. Коли таблиця досягає ліміту `max_entries`, новий запис не відхиляється помилкою `-E2BIG`, а витісняє найстаріший невикористовуваний елемент. Застосовується для відстеження мережевих з'єднань, де неможливо передбачити точну кількість активних сесій.

### Кільцевий буфер подій (`BPF_MAP_TYPE_RINGBUF`)
Спроєктований як багатопроцесорна черга формату MPSC (*Multi-Producer Single-Consumer*). Пам'ять буфера розбита на службову сторінку метаданих (індекси споживача `consumer_pos` та виробників `producer_pos`) і сторінки даних, розмір яких має бути ступенем двійки. Сторінки даних відображаються у віртуальну пам'ять двічі поспіль (*double-mapping*), що дозволяє ядру записувати неперервні блоки подій на межі буфера без фрагментації та розриву пам'яті.

### Спеціалізовані мережеві карти (`DEVMAP`, `CPUMAP`, `SOCKMAP`)
* `BPF_MAP_TYPE_DEVMAP`: Масив мережевих інтерфейсів для швидкісної переадресації пакетів у драйвері XDP через функцію `bpf_redirect_map()`.
* `BPF_MAP_TYPE_CPUMAP`: Масив ядер процесора для розподілу обробки мережевого трафіку XDP між ядрами CPU без накладних витрат на блокування.
* `BPF_MAP_TYPE_SOCKMAP` та `SOCKHASH`: Зберігають посилання на відкриті TCP-сокети `struct sock *` і дозволяють перенаправляти дані між сокетами безпосередньо в ядрі в обхід повного мережевого стеку TCP/IP.

## 5. Допоміжні функції ядра (In-Kernel BPF Helpers)

Програми eBPF всередині ядра звертаються до карт за допомогою строго типізованих функцій-хелперів:

```c
/* Пошук вказівника на значення за адресою ключа. Повертає NULL якщо ключ відсутній */
void *bpf_map_lookup_elem(struct bpf_map *map, const void *key);

/* Вставка або оновлення значення. Повертає 0 у разі успіху або від'ємний код помилки */
long bpf_map_update_elem(struct bpf_map *map, const void *key, const void *value, __u64 flags);

/* Видалення ключа з карти. Повертає 0 або від'ємний код помилки */
long bpf_map_delete_elem(struct bpf_map *map, const void *key);

/* Пряме копіювання події в кільцевий буфер Ring Buffer */
long bpf_ringbuf_output(void *ringbuf, void *data, __u64 size, __u64 flags);

/* Резервування слоту пам'яті в Ring Buffer з нульовим копіюванням */
void *bpf_ringbuf_reserve(void *ringbuf, __u64 size, __u64 flags);

/* Публікація зарезервованого запису для зчитування процесом простору користувача */
void bpf_ringbuf_submit(void *data, __u64 flags);

/* Скасування зарезервованого запису у разі виникнення помилки */
void bpf_ringbuf_discard(void *data, __u64 flags);
```

## 6. Приклад роботи з картами BPF із простору користувача

Приклад створення хеш-карти через бібліотеку `libbpf`, додавання елемента та зчитування результату:

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <bpf/bpf.h>
#include <bpf/libbpf.h>

int main(void)
{
    /* 1. Створення хеш-карти: ключ = uint32_t (PID), значення = uint64_t (лічильник) */
    int map_fd = bpf_map_create(BPF_MAP_TYPE_HASH, "proc_stats",
                                sizeof(uint32_t), sizeof(uint64_t),
                                1024, NULL);
    if (map_fd < 0) {
        fprintf(stderr, "Помилка створення карти: %s\n", strerror(errno));
        return 1;
    }

    uint32_t key = 1337;
    uint64_t initial_val = 1;

    /* 2. Запис значення з прапорцем BPF_ANY */
    if (bpf_map_update_elem(map_fd, &key, &initial_val, BPF_ANY) != 0) {
        fprintf(stderr, "Помилка оновлення елемента: %s\n", strerror(errno));
        close(map_fd);
        return 1;
    }

    /* 3. Зчитування збереженого значення */
    uint64_t lookup_val = 0;
    if (bpf_map_lookup_elem(map_fd, &key, &lookup_val) == 0) {
        printf("Знайдено значення для PID %u: %lu\n", key, lookup_val);
    }

    close(map_fd);
    return 0;
}
```
```cpp
#include <iostream>
#include <cstdint>
#include <cstring>
#include <system_error>
#include <unistd.h>
#include <bpf/bpf.h>
#include <bpf/libbpf.h>

class BpfMapHandle {
public:
    explicit BpfMapHandle(int fd) : fd_(fd) {
        if (fd_ < 0) {
            throw std::system_error(errno, std::generic_category(), "bpf_map_create failed");
        }
    }

    ~BpfMapHandle() noexcept {
        if (fd_ >= 0) {
            close(fd_);
        }
    }

    BpfMapHandle(const BpfMapHandle&) = delete;
    BpfMapHandle& operator=(const BpfMapHandle&) = delete;

    BpfMapHandle(BpfMapHandle&& other) noexcept : fd_(other.fd_) {
        other.fd_ = -1;
    }

    BpfMapHandle& operator=(BpfMapHandle&& other) noexcept {
        if (this != &other) {
            if (fd_ >= 0) close(fd_);
            fd_ = other.fd_;
            other.fd_ = -1;
        }
        return *this;
    }

    [[nodiscard]] int get() const noexcept { return fd_; }

private:
    int fd_{-1};
};

int main()
{
    try {
        BpfMapHandle map{bpf_map_create(BPF_MAP_TYPE_HASH, "proc_stats",
                                        sizeof(uint32_t), sizeof(uint64_t),
                                        1024, nullptr)};

        const uint32_t key = 1337;
        const uint64_t initial_val = 1;

        if (bpf_map_update_elem(map.get(), &key, &initial_val, BPF_ANY) != 0) {
            throw std::system_error(errno, std::generic_category(), "bpf_map_update_elem failed");
        }

        uint64_t lookup_val = 0;
        if (bpf_map_lookup_elem(map.get(), &key, &lookup_val) == 0) {
            std::cout << "Знайдено значення для PID " << key << ": " << lookup_val << "\n";
        }
    } catch (const std::exception& ex) {
        std::cerr << "Помилка: " << ex.what() << "\n";
        return 1;
    }

    return 0;
}
```

## 7. Життєвий цикл пам'яті та коди помилок

Пам'ять BPF Map утилізується автоматично, коли останній файловий дескриптор `map_fd` закривається у просторі користувача і жодна завантажена програма eBPF не посилається на цю карту. Для відкладеного звільнення ядро використовує RCU-виклик `bpf_map_free_deferred()`. Якщо карту закріплено у віртуальній файловій системі BPF FS (`/sys/fs/bpf/my_map`) через команду `BPF_OBJ_PIN`, вона залишається в пам'яті ядра навіть після завершення всіх процесів.

Під час взаємодії із системним викликом `bpf()` операційна система повертає стандартні коди помилок у змінній `errno`:

| Код помилки | Константа | Причина виникнення та діагностика |
|---|---|---|
| `ENOENT` | 2 | Запитаний ключ відсутній у карті при виконанні `BPF_MAP_LOOKUP_ELEM` або `BPF_MAP_DELETE_ELEM` |
| `EEXIST` | 17 | Спроба створити існуючий ключ при виклику з прапорцем `BPF_NOEXIST` |
| `E2BIG` | 7 | Карта заповнена (`max_entries` вичерпано) при спробі вставити новий елемент без LRU |
| `ENOMEM` | 12 | Нестача оперативної пам'яті ядра або перевищення користувацького ліміту `RLIMIT_MEMLOCK` |
| `EINVAL` | 22 | Некоректні розміри ключа чи значення (наприклад, `key_size == 0`), невідомий тип карти або непідтримувані прапорці |
| `EBUSY` | 16 | Спроба видалити або змінити карту, яка наразі заблокована іншою паралельною операцією |
| `EPERM` | 1 | Недостатньо привілеїв процесу (відсутній `CAP_BPF` або `CAP_SYS_ADMIN` у просторі імен) |
