# 📋 Поверхня конфігурацій та утиліт адміністрування облікових записів

Керування обліковими записами в Unix-подібних операційних системах спирається на набір утиліт пакунка `shadow-utils` та два основні конфігураційні файли, що визначають системні політики за замовчуванням: `/etc/login.defs` та `/etc/default/useradd`. Кожен інструмент цієї підсистеми відповідає за конкретну ланку життєвого циклу обліковця, від виділення числових діапазонів ідентифікаторів до налаштування криптографічних гешів та перевірки синтаксичної консистентності баз.

## Глобальні параметри безпеки та діапазони: `/etc/login.defs`

Файл `/etc/login.defs` визначає загальносистемні конфігураційні директиви для всіх утиліт пакета `shadow-utils` (`useradd`, `usermod`, `userdel`, `chage`, `pwck`, `newusers`). Кожен параметр задається окремим рядком у форматі `ДИРЕКТИВА ЗНАЧЕННЯ`. Порожні рядки та рядки, що починаються з символу решітки (`#`), ігноруються аналізатором.

Цей конфігураційний файл визначає межі безпеки системи: від правил поділу простору числових ідентифікаторів на системні та користувацькі до криптографічних параметрів алгоритмів гешування паролів.

### Простори ідентифікаторів (UID/GID)

Система Unix розрізняє системних користувачів (демони, фонові служби) та звичайних людей, які входять в інтерактивні сесії. Такий поділ реалізується через неперетинні числові інтервали, що налаштовуються такими директивами:

* `UID_MIN` та `UID_MAX` — визначають діапазон числових ідентифікаторів для звичайних користувачів (типово від `1000` до `60000`). Коли утиліта `useradd` викликається без прапорця `-u`, вона виконує лінійний пошук у базі `/etc/passwd` і знаходить найменший вільний номер у межах цього відрізка.
* `SYS_UID_MIN` та `SYS_UID_MAX` — задають простір для системних служб (типово від `100` або `201` до `999`). Ці значення використовуються, коли `useradd` запускається з прапорцем `-r` (`--system`). Системні ідентифікатори зазвичай не мають домашніх каталогів, термінів придатності пароля чи реєстраційних оболонок.
* `GID_MIN`, `GID_MAX`, `SYS_GID_MIN`, `SYS_GID_MAX` — аналогічні межі для числових ідентифікаторів груп у файлі `/etc/group`.
* `SUB_UID_MIN`, `SUB_UID_MAX`, `SUB_UID_COUNT` — діапазони субідентифікаторів, які записуються у файл `/etc/subuid` і використовуються механізмом просторів імен користувачів (User Namespaces) для запуску rootless-контейнерів у Podman чи Docker.

### Модель персональних груп користувача (User Private Groups)

Директива `USERGROUPS_ENAB` (приймає значення `yes` або `no`) визначає фундаментальну модель розмежування прав у системі:

* Якщо встановлено `USERGROUPS_ENAB yes`, утиліта `useradd` за замовчуванням створює для кожного нового користувача однойменну первинну групу з числовим GID, що дорівнює UID. При цьому маска створення файлів `UMASK` у системі може бути безпечно встановлена у `002` або `022`.
* Якщо для користувача діє схема UPG, видалення обліковця утилітою `userdel` автоматично перевіряє його однойменну первинну групу. Якщо в цій групі більше немає інших учасників, утиліта автоматично видаляє і саму групу з `/etc/group`.
* Якщо встановлено `USERGROUPS_ENAB no`, усі новостворені користувачі за замовчуванням отримують спільну загальну групу (наприклад, `users` із GID `100`), що вимагає значно суворішої маски `UMASK 027` або `077` для запобігання несанкціонованому читанню файлів колегами.

### Політики паролів та алгоритми шифрування

* `ENCRYPT_METHOD` — визначає криптографічний алгоритм, який використовується бібліотекою `libcrypt` під час створення нових гешів утилітами `passwd` або `useradd -p`. Можливі значення: `SHA512` (префікс гешу `$6$`), `SHA256` (`$5$`), `YESCRYPT` (`$y$`), `BCRYPT` (`$2b$`), `MD5` (`$1$`, застарілий) та `DES` (історичний, небезпечний).
* `SHA_CRYPT_MIN_ROUNDS` та `SHA_CRYPT_MAX_ROUNDS` — задають межі кількості циклів розтягування ключа (Key Stretching) для алгоритмів SHA-256 та SHA-512. За замовчуванням використовується 5000 раундів. Збільшення цього числа ускладнює офлайн-перебір гешу зловмисником ціною збільшення навантаження на процесор під час автентифікації.
* `PASS_MAX_DAYS` — максимальна кількість днів чинності пароля (за замовчуванням `99999`, тобто практично безстроково). Це значення автоматично заноситься у 5-те поле файлу `/etc/shadow` для кожного нового користувача.
* `PASS_MIN_DAYS` — мінімальний інтервал у днях між змінами пароля (типово `0`).
* `PASS_WARN_AGE` — кількість днів попередження до закінчення чинності пароля (типово `7`).

### Параметри створення та прав домівки

* `CREATE_HOME` — булевий перемикач (`yes`/`no`), що вказує утиліті `useradd`, чи слід автоматично створювати домашній каталог, якщо адміністратор не вказав явно прапорець `-m` або `-M`.
* `HOME_MODE` — вісімковий режим прав доступу, що накладається на новостворений домашній каталог (наприклад, `0700` для повної ізоляції або `0750` для надання прав читання членам первинної групи). Якщо параметр відсутній, права обчислюються шляхом інверсії системної маски `UMASK`.
* `NONEXISTENT` — шлях до псевдокаталогу (зазвичай `/nonexistent`), який призначається системним демонам, яким заборонено мати реальний каталог домівки.

| Директива login.defs | Тип значення | Системне призначення |
| :--- | :--- | :--- |
| `UID_MIN` / `UID_MAX` | цілі числа | Межі автоматичного виділення ідентифікаторів звичайним користувачам. |
| `SYS_UID_MIN` / `SYS_UID_MAX` | цілі числа | Межі автоматичного виділення системних ідентифікаторів (демонів). |
| `USERGROUPS_ENAB` | `yes` / `no` | Увімкнення моделі персональних груп користувачів (UPG). |
| `ENCRYPT_METHOD` | рядок | Алгоритм гешування паролів (`SHA512`, `YESCRYPT`, `BCRYPT`). |
| `PASS_MAX_DAYS` | ціле число | Термін чинності пароля за замовчуванням у днях. |
| `PASS_MIN_DAYS` | ціле число | Мінімальний період між змінами пароля. |
| `PASS_WARN_AGE` | ціле число | Період завчасного попередження про застарівання пароля. |
| `HOME_MODE` | вісімкове | Явні права доступу на створений каталог домівки (`0700`/`0750`). |
| `CREATE_HOME` | `yes` / `no` | Автоматичне створення каталогу домівки без явного прапорця `-m`. |

## Параметри утиліти `useradd`: `/etc/default/useradd`

Файл `/etc/default/useradd` використовується виключно самою утилітою `useradd`. Поточний набір параметрів можна переглянути командою `useradd -D`, а змінити будь-яке значення — передавши нове значення разом із прапорцем `-D` (наприклад, `useradd -D -s /usr/bin/zsh` встановить оболонку Zsh за замовчуванням для всіх наступних викликів `useradd`).

Параметри файлу та їхній вплив на новостворювані облікові записи:

* `GROUP` — число або ім'я первинної групи, якщо у системі вимкнено механізм UPG (`USERGROUPS_ENAB no`). Зазвичай вказує на групу `users` (GID `100`).
* `HOME` — базовий каталог (префікс), всередині якого `useradd` створює персональні теки користувачів. За замовчуванням `/home`. При створенні користувача `andrij` домівка розміститься за шляхом `/home/andrij`.
* `INACTIVE` — кількість днів після застарівання пароля, після закінчення яких обліковий запис автоматично деактивується. Значення `-1` вимикає цей механізм. Будь-яке додатне число записується у 7-ме поле `/etc/shadow`.
* `EXPIRE` — абсолютна дата закінчення дії облікового запису за замовчуванням у форматі `YYYY-MM-DD`. Зазвичай це поле залишене порожнім, що означає безстроковий обліковий запис.
* `SHELL` — повний шлях до командної оболонки входу за замовчуванням. Якщо адміністратор не передав прапорець `-s`, використовується значення з цього рядка (зазвичай `/bin/bash` або `/bin/sh`).
* `SKEL` — абсолютний шлях до каталогу шаблонів файлів ініціалізації (за замовчуванням `/etc/skel`).
* `CREATE_MAIL_SPOOL` — перемикач (`yes`/`no`), що вказує, чи слід утиліті автоматично створювати поштовий файл у `/var/mail/користувач` під час заведення обліковця.

| Параметр за замовчуванням | Типове значення | Поведінка утиліти useradd |
| :--- | :--- | :--- |
| `GROUP` | `100` | Первинна група, якщо не діє схема UPG. |
| `HOME` | `/home` | Батьківський каталог для розташування домівок. |
| `INACTIVE` | `-1` | Період блокування простроченого обліковця (-1 — вимкнено). |
| `EXPIRE` | порожньо | Термін закінчення дії облікового запису за замовчуванням. |
| `SHELL` | `/bin/bash` | Реєстраційна оболонка входу за замовчуванням. |
| `SKEL` | `/etc/skel` | Каталог-шаблон для наповнення нової домівки. |
| `CREATE_MAIL_SPOOL` | `no` | Створення поштової скриньки у `/var/mail/`. |

## Довідник інтерфейсу командного рядка утиліт

Нижче наведено детальний опис прапорців, семантики виклику та крайових випадків для кожної утиліти підсистеми `shadow-utils`.

### 1. `useradd` — заведення облікового запису

Синтаксис: `useradd [опції] ЛОГІН`

* `-m`, `--create-home` — створити домашній каталог за шляхом `$HOME/ЛОГІН` і скопіювати в нього структуру файлів із каталогу шаблонів (`/etc/skel`).
* `-M`, `--no-create-home` — примусово заборонити створення домашнього каталогу, навіть якщо в `/etc/login.defs` директива `CREATE_HOME` дорівнює `yes`.
* `-s ШЛЯХ`, `--shell ШЛЯХ` — призначити командну оболонку користувача. Програма повинна бути валідним виконуваним файлом, зазначеним у `/etc/shells`.
* `-u UID`, `--uid UID` — призначити конкретний числовий ідентифікатор користувача. За замовчуванням утиліта відмовиться створювати запис, якщо такий UID уже існує.
* `-o`, `--non-unique` — дозволити створення користувача з дубльованим (неунікальним) UID. Це створює псевдонім (аліас) для існуючого облікового запису, що має ідентичні права доступу на рівні ядра, але окреме ім'я та пароль.
* `-g ГРУПА`, `--gid ГРУПА` — призначити первинну групу користувача (назва або числовий GID). Група повинна існувати в системі до виклику `useradd`.
* `-G ГР1,ГР2...`, `--groups ГР1,ГР2...` — перелік додаткових (supplementary) груп через кому без пробілів.
* `-c ТЕКСТ`, `--comment ТЕКСТ` — заповнити інформаційне поле GECOS (повне ім'я, кімната, контакти).
* `-d ШЛЯХ`, `--home-dir ШЛЯХ` — явно вказати нестандартний шлях до домашнього каталогу.
* `-e РРРР-ММ-ДД`, `--expiredate РРРР-ММ-ДД` — встановити дату повного закінчення дії облікового запису.
* `-f ДНІ`, `--inactive ДНІ` — встановити кількість днів після застарівання пароля до повного блокування входу.
* `-k ШЛЯХ`, `--skel ШЛЯХ` — вказати альтернативний каталог шаблонів замість `/etc/skel` (працює лише разом із `-m`).
* `-p ГЕШ`, `--password ГЕШ` — передати готовий криптографічний геш пароля. Передавати пароль відкритим текстом суворо заборонено, оскільки він потрапить у відкритий рядок процесу `ps` та історію командної оболонки.
* `-r`, `--system` — створити системного користувача з ідентифікатором у межах системного діапазону (`SYS_UID_MIN`..`SYS_UID_MAX`).
* `-U`, `--user-group` — примусово створити однойменну персональну групу (UPG), навіть якщо глобально це вимкнено.
* `-N`, `--no-user-group` — не створювати однойменну групу, використати системну за замовчуванням.
* `-D`, `--defaults` — вивести або змінити глобальні налаштування утиліти за замовчуванням.

### 2. `usermod` — модифікація наявного обліковця

Синтаксис: `usermod [опції] ЛОГІН`

* `-a`, `--append` — додає користувача до вказаних груп у `-G` без видалення з наявних груп. Працює **виключно** у комбінації з `-G`.
* `-G ГРУПИ`, `--groups ГРУПИ` — встановлює перелік додаткових груп. Без прапорця `-a` користувач автоматично видаляється з усіх груп, які не згадані в цьому списку.
* `-g ГРУПА`, `--gid ГРУПА` — змінює первинну групу користувача в `/etc/passwd`.
* `-l НОВИЙ_ЛОГІН`, `--login НОВИЙ_ЛОГІН` — змінює реєстраційне ім'я користувача у файлах `/etc/passwd` та `/etc/shadow`.
* `-d ШЛЯХ`, `--home ШЛЯХ` — змінює шлях до домашнього каталогу в базі.
* `-m`, `--move-home` — фізично переміщує файли зі старого домашнього каталогу в новий (працює лише разом із `-d`).
* `-s ШЛЯХ`, `--shell ШЛЯХ` — змінює командну оболонку користувача.
* `-u UID`, `--uid UID` — змінює числовий UID. Усі файли в межах домашнього каталогу користувача автоматично отримують новий числовий власник через системний виклик `chown()`. Файли за межами домівки не змінюються і потребують ручного аудиту.
* `-L`, `--lock` — блокує пароль, додаючи символ `!` на початку гешу в `/etc/shadow`.
* `-U`, `--unlock` — розблоковує пароль, видаляючи символ `!` на початку гешу.
* `-e РРРР-ММ-ДД`, `--expiredate РРРР-ММ-ДД` — встановлює нову дату закінчення дії облікового запису. Значення `""` знімає обмеження.
* `-f ДНІ`, `--inactive ДНІ` — змінює пільговий період неактивності.

### 3. `userdel` — видалення облікового запису

Синтаксис: `userdel [опції] ЛОГІН`

* `-r`, `--remove` — видаляє домашній каталог користувача та його файл поштової скриньки у `/var/mail/`.
* `-f`, `--force` — примусове видалення: дозволяє видалити обліковий запис, навіть якщо користувач має активні запущені процеси або його домашній каталог належить іншому UID.
* `-Z`, `--selinux-user` — видаляє прив'язку користувача в політиці безпеки SELinux.

### 4. `chage` — керування термінами дії паролів

Синтаксис: `chage [опції] ЛОГІН`

* `-l`, `--list` — вивести поточний стан усіх полів старіння пароля та терміну дії у зрозумілому для людини форматі.
* `-d ДАТА`, `--lastday ДАТА` — встановити дату останньої зміни пароля (кількість днів від 1970-01-01 або формат `YYYY-MM-DD`). Значення `0` примушує користувача змінити пароль при першому вході.
* `-E ДАТА`, `--expiredate ДАТА` — дата завершення дії облікового запису (`-1` для зняття обмеження).
* `-m ДНІ`, `--mindays ДНІ` — мінімальна кількість днів між змінами пароля.
* `-M ДНІ`, `--maxdays ДНІ` — максимальний термін чинності пароля в днях.
* `-W ДНІ`, `--warndays ДНІ` — кількість днів попередження про застарівання пароля.
* `-I ДНІ`, `--inactive ДНІ` — кількість днів неактивності після застарівання пароля до блокування.

### 5. `pwck` та `grpck` — верифікація цілісності

Синтаксис: `pwck [опції] [файл_passwd [файл_shadow]]` та `grpck [опції] [файл_group [файл_gshadow]]`

* `-r`, `--read-only` — режим перевірки без можливості внесення змін у файли баз даних.
* `-s`, `--sort` — відсортувати записи у файлах за зростанням числових ідентифікаторів (UID/GID).
* `-q`, `--quiet` — тихий режим, виводить тільки повідомлення про критичні помилки.

## Стандартизовані коди виходу утиліт пакунка `shadow-utils`

Кожна утиліта повертає числове значення статусу завершення процесу (`exit status`), яке можна перевірити у змінній `$?` командної оболонки або обробити у скриптах автоматизації.

| Код виходу | Символічна назва в C-коді | Опис стану та причина помилки |
| :---: | :--- | :--- |
| `0` | `E_SUCCESS` | Операцію виконано успішно без зауважень. |
| `1` | `E_CANT_UPDATE` | Помилка оновлення файлів баз даних (відсутній доступ, заблокований файл `ptmp`). |
| `2` | `E_USAGE` | Помилка синтаксису виклику команди (невідомий прапорець, відсутній обов'язковий аргумент). |
| `3` | `E_BAD_ARG` | Передано некоректне значення параметра (неприпустимі символи, від'ємне число там, де очікується додатне). |
| `4` | `E_UID_IN_USE` | Запитаний числовий UID уже зайнятий іншим користувачем (без прапорця `-o`). |
| `6` | `E_NOTFOUND` | Вказаного користувача або групу не знайдено в базах даних системи. |
| `8` | `E_USER_BUSY` | Користувач наразі залогінений або виконує процеси в системі (блокує видалення без `-f`). |
| `9` | `E_NAME_IN_USE` | Запитане ім'я облікового запису або групи вже використовується іншим записом. |
| `10` | `E_GRP_UPDATE` | Помилка оновлення бази груп (`/etc/group` або `/etc/gshadow`). |
| `12` | `E_HOMEDIR` | Не вдалося створити, скопіювати файли skel або видалити домашній каталог. |
| `14` | `E_SELINUX` | Помилка взаємодії з підсистемою безпеки SELinux під час налаштування контекстів файлів. |
