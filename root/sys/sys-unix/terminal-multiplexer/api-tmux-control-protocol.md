# 📋 Програмний інтерфейс tmux: протокол керування, IPC та скриптування

Мультиплексор `tmux` надає три взаємопов'язані рівні програмного керування: стандартний командний інтерфейс командного рядка (CLI), текстовий протокол режиму керування (*Control Mode*, який активується прапорцем `tmux -C` або `tmux -CC`), та вбудовану систему підстановки форматних змінних і перехоплення життєвих подій (*hooks*).

## Режим керування (Control Mode: tmux -C)

Режим керування перетворює `tmux` на повноцінний бекенд-рушій для зовнішніх графічних емуляторів термінала (таких як iTerm2, Ghostty або браузерних вебінтерфейсів). Замість малювання сітки комірок за допомогою термінальних послідовностей ANSI на фізичному екрані, `tmux` обмінюється з керуючою програмою структурованими текстовими рядками через стандартні потоки `stdin` та `stdout`.

Запуск режиму керування виконується так:
```sh
tmux -C attach-session -t my-session
# або у режимі з вимкненим відлунням вхідних команд:
tmux -CC attach-session -t my-session
```

Коли клієнт підключається з прапорцем `-C`, серверний демон вимикає генерацію диференційних перемальовувань екрана для цього клієнта. Замість цього клієнт отримує сповіщення про створення вікон, поділ панелей та зміни розмірів у вигляді рядків повідомлень, а сам клієнт може надсилати звичайні команди `tmux` у текстовому вигляді безпосередньо у свій стандартний ввід.

### Протокол фреймінгу та екранування даних

У звичайному терміналі вивід від запущеної програми може містити довільні керуючі коди, бінарні дані та символи переведення рядка. Якби протокол керування просто передавав цей потік у `stdout`, клієнтський парсер не міг би надійно відрізнити службові команди сервера від тексту програми.

Щоб запобігти неоднозначності, протокол Control Mode використовує суворий рядковий фреймінг:
1. Кожне службове сповіщення сервера починається з символу `%` на початку рядка.
2. Кожна відповідь на команду клієнта обмежується маркерами `%begin` та `%end` (або `%error`), які містять часову мітку в епосі Unix, порядковий номер команди та прапорці завершення.
3. Вихідні дані від дочірніх процесів передаються виключно в рамках події `%output`. Усі недруковані керуючі символи, байти з встановленим восьмим бітом, пробіли, символи нового рядка та зворотні слеші кодуються у вигляді вісімкових послідовностей (наприклад, символ `ESC` кодується як `\033`, а переведення рядка `LF` — як `\012`). Це гарантує, що рядок події `%output` ніколи не розірветься посередині.

Якщо керуючій програмі потрібно надіслати ввід до конкретної панелі, вона викликає команду `send-keys -t %pane_id -l <keys>` або `send-keys -t %pane_id -H <hex_bytes>`, що дозволяє точно контролювати введення без ризику спотворення спеціальними символами оболонки.

### Структура сповіщень сервера (%notifications)

Усі асинхронні події, що генеруються сервером `tmux` під час зміни внутрішнього стану, передаються окремими рядками:

| Подія протоколу | Формат аргументів | Опис системної події |
|---|---|---|
| `%begin` | `timestamp cmd_id flags` | Початок синхронного виконання команди клієнта |
| `%end` | `timestamp cmd_id flags` | Успішне завершення виконання команди клієнта |
| `%error` | `timestamp cmd_id flags` | Помилка виконання команди (текст повідомлення слідує наступним рядком) |
| `%output` | `%<pane_id> <octal_data>` | Вивід даних від дочірнього процесу вказаної панелі |
| `%window-add` | `@<window_id>` | Створено нове вікно у поточному сеансі |
| `%window-close` | `@<window_id>` | Вікно було закрито або знищено |
| `%window-renamed` | `@<window_id> <name>` | Змінено назву вікна (вручну або автоматично) |
| `%layout-change` | `@<window_id> <layout>` | Змінилася геометрія або розкладка панелей вікна |
| `%pane-mode-changed` | `%<pane_id>` | Панель перейшла у спеціальний режим (наприклад, scroll/copy mode) |
| `%client-detached` | `[client_name]` | Клієнтський сеанс від'єднано від сервера |
| `%exit` | `[reason]` | Сервер `tmux-server` завершив роботу |

Приклад реального діалогу між графічним емулятором і сервером:

```text
C: new-window -n "monitor"
S: %begin 1724590120 1 0
S: %window-add @1
S: %layout-change @1 c4b1,160x45,0,0,1
S: %end 1724590120 1 0
S: %output %1 \033[32muser@srv:~$ \033[0m
```

### Синтаксис опису розкладок (Layout String)

Подія `%layout-change` передає компактний рядок, який описує повне дерево розбиття вікна на панелі. Рядок має формат:
`checksum,widthxheight,x_offset,y_offset[child_nodes]`

Контрольна сума на початку генерується спеціальним хеш-алгоритмом `tmux` (16-бітний циклічний зсув із додаванням) для швидкої перевірки цілісності рядка:
- Фігурні дужки `{...}` позначають горизонтальний поділ (панелі стоять поруч у стовпчиках);
- Квадратні дужки `[...]` позначають вертикальний поділ (панелі розташовані одна під одною у рядках);
- Кожен листовий вузол дерева закінчується числовим ідентифікатором панелі (наприклад, `,0` або `,1`).

Графічний емулятор, що підтримує Control Mode, парсить це дерево і створює відповідні нативні вікна операційної системи, забезпечуючи плавне масштабування мишею та коректне відображення вкладок.

## Командні примітиви IPC

Будь-яка команда, набрана в оболонці як `tmux <command>` або передана через сокет керування, транслюється у бінарне повідомлення IPC через локальний сокет `/tmp/tmux-$UID/default`.

### Керування сеансами, вікнами та розкладками

Команди маніпуляції топологією робочого простору приймають широкий набір прапорців для точного налаштування:

| Команда | Основні прапорці | Системна дія |
|---|---|---|
| `new-session` | `-d`, `-s <name>`, `-n <win>`, `-x <cols>`, `-y <rows>`, `-c <dir>` | Створити новий сеанс (опція `-d` створює сеанс у фоні без підключення клієнта) |
| `attach-session` | `-t <target>`, `-d`, `-r`, `-f <flags>` | Підключити поточний термінал до сеансу (`-r` — режим лише для читання) |
| `detach-client` | `-s <session>`, `-a`, `-P` | Від'єднати поточного клієнта, групу клієнтів або надіслати `SIGHUP` батьківському процесу |
| `kill-session` | `-t <session>`, `-a` | Завершити сеанс, усі його вікна та надіслати `SIGHUP` дочірнім процесам панелей |
| `new-window` | `-d`, `-n <name>`, `-t <target>`, `-c <dir>` | Створити нову вкладку-вікно в активному або вказаному сеансі |
| `split-window` | `-h`, `-v`, `-p <pct>`, `-l <size>`, `-c <dir>`, `-b`, `-f` | Розбити активну панель горизонтально (`-h`) чи вертикально (`-v`); `-f` розбиває вікно на всю ширину |
| `select-pane` | `-t <target>`, `-U`, `-D`, `-L`, `-R`, `-m`, `-M` | Змінити активну панель; `-m` ставить позначку для подальшого об'єднання панелей |
| `resize-pane` | `-t <target>`, `-U`, `-D`, `-L`, `-R` `<cells>`, `-Z`, `-x <cols>`, `-y <rows>` | Змінити розмір панелі на задану кількість комірок або розгорнути на весь екран (`-Z`) |

### Маніпуляція потоками даних і текстом

Мультиплексор надає примітиви для читання та ін'єкції даних у псевдотермінали:

| Команда | Параметри | Системна дія |
|---|---|---|
| `send-keys` | `-t <pane> [-l] [-R] [-M] <keys...>` | Надіслати натискання клавіш у slave PTY панелі (опція `-l` вимикає парсинг назв клавіш і передає сирий текст) |
| `capture-pane` | `-t <pane> [-p] [-S <start>] [-E <end>] [-e] [-C] [-J]` | Зняти текстовий вміст або історію скролу панелі (`-e` зберігає escape-послідовності ANSI, `-J` об'єднує розірвані рядки) |
| `pipe-pane` | `-t <pane> [-o] [<shell_command>]` | Перенаправити вихідний потік панелі на вхід зовнішній утиліті через канал `pipe` (наприклад, для безперервного логування у файл) |
| `display-message` | `-p [-t <pane>] "<format_string>"` | Обчислити та вивести рядок із підстановкою форматних змінних tmux у `stdout` |

## Двигун форматних змінних (Format Engine)

Форматні змінні використовуються для конфігурації статус-рядків, динамічних назв вікон та вилучення системної інформації через `display-message`.

Форматний рушій `tmux` підтримує не лише просту підстановку значень, а й обчислювальні вирази, логічні умови та маніпуляції з рядками:
- `#{?condition,true_branch,false_branch}` — умовне розгалуження (якщо вираз `condition` повертає ненульове значення або непорожній рядок, підставляється `true_branch`, інакше `false_branch`);
- `#{==:#{session_name},dev}` — перевірка рівності двох рядків;
- `#{!=:#{window_panes},1}` — перевірка нерівності числових або рядкових значень;
- `#{m:*pattern*,#{window_name}}` — зіставлення рядка з маскою пошуку (glob pattern);
- `#{m/r/regexp/replacement/target}` — пошук і заміна за регулярним виразом;
- `#{e|+:#{pane_width},10}` — арифметичні операції над цілими числами (`+`, `-`, `*`, `/`, `%`, `==`, `!=`, `<`, `>`);
- `#{t/f:%H:%M:%S:session_created}` — форматування часових міток епохи Unix за правилами функції `strftime`.

### Таблиця основних форматних змінних

| Форматна змінна | Тип значення | Детальний опис системного значення |
|---|---|---|
| `#{session_name}` | Рядок | Назва поточного активного сеансу |
| `#{session_id}` | Рядок (`$0`, `$1`) | Унікальний числовий ідентифікатор сеансу |
| `#{session_windows}` | Число | Кількість вікон, зареєстрованих у сеансі |
| `#{window_id}` | Рядок (`@0`, `@1`) | Унікальний глобальний ідентифікатор вікна |
| `#{window_index}` | Число | Порядковий номер вікна всередині сеансу (від 0 або 1) |
| `#{window_name}` | Рядок | Поточна назва вікна |
| `#{window_width}` / `#{window_height}` | Число | Геометричні розміри вікна у стовпцях і рядках |
| `#{window_layout}` | Рядок | Контрольна сума та деревоподібний опис розміщення панелей |
| `#{pane_id}` | Рядок (`%0`, `%1`) | Унікальний ідентифікатор панелі |
| `#{pane_index}` | Число | Порядковий номер панелі у поточному вікні |
| `#{pane_pid}` | Число (PID) | Ідентифікатор процесу-лідера, запущеного на slave PTY цієї панелі |
| `#{pane_tty}` | Шлях до файлу | Абсолютний шлях до підлеглого пристрою термінала (`/dev/pts/X`) |
| `#{pane_current_path}` | Шлях | Поточний робочий каталог процесу в панелі (визначається через `/proc/<pid>/cwd`) |
| `#{pane_current_command}` | Рядок | Назва бінарного файлу, що виконується на передньому плані (через `/proc/<pid>/stat`) |
| `#{pane_dead}` | Логічне (0 або 1) | Чи завершився дочірній процес панелі (у режимі `remain-on-exit`) |
| `#{pane_dead_status}` | Число | Код повернення або номер сигналу завершеного процесу панелі |
| `#{cursor_x}` / `#{cursor_y}` | Число | Координати віртуального курсора у сітці панелі |
| `#{client_width}` / `#{client_height}` | Число | Фізичний розмір термінала підключеного клієнта |
| `#{client_readonly}` | Логічне (0 або 1) | Чи підключено клієнта у режимі спостереження без права вводу |

Приклад скриптового запиту інформації про активний процес:

```sh
$ tmux display-message -p 'Панель #{pane_id} (TTY: #{pane_tty}, PID: #{pane_pid}): #{pane_current_command} у #{pane_current_path}'
Панель %4 (TTY: /dev/pts/8, PID: 28419): cargo у /home/user/backend/core
```

## Безпека та керування доступом до UNIX-сокета

Файл сокета за замовчуванням створюється з правами `0700` у тимчасовому каталозі `/tmp/tmux-$UID/`, власником якого є користувач, що запустив сервер. Це запобігає несанкціонованому підключенню інших локальних користувачів операційної системи.

Якщо потрібно організувати спільний доступ до сеансу для кількох системних користувачів (наприклад, для командного аудиту чи парного програмування на спільному сервері), застосовують явне вказування сокета з правами групи:

```sh
# Створення спільного каталогу з правами групи
mkdir -p /var/tmux-shared
chgrp devteam /var/tmux-shared
chmod 2775 /var/tmux-shared

# Запуск сервера на спільному сокеті
tmux -S /var/tmux-shared/pairing-socket new-session -s shared-dev

# Підключення іншого користувача з групи devteam:
tmux -S /var/tmux-shared/pairing-socket attach-session -t shared-dev
```

## Система гачків (Hooks) та перехоплення подій

Гачки дозволяють системному адміністратору або розробнику прив'язувати автоматичні дії до критичних переходів станів у життєвому циклі сеансів, клієнтів, вікон та окремих панелей.

Встановлення гачка виконується командою `set-hook`:

```sh
tmux set-hook -g <hook-name> '<command>'
```

Прапорець `-g` застосовує гачок глобально для всіх сеансів сервера, тоді як прапорець `-t <target>` дозволяє прив'язати реакцію до конкретного сеансу чи вікна.

### Перелік життєвих гачків сервера

| Назва гачка | Умова та контекст спрацювання |
|---|---|
| `client-attached` | Клієнт успішно пройшов автентифікацію та підключився до сеансу через UNIX-сокет |
| `client-detached` | Клієнтський процес завершився або сокет було розірвано |
| `client-resized` | Змінився розмір фізичного вікна клієнтського термінала (`SIGWINCH`) |
| `client-session-changed` | Підключений клієнт перемкнувся на інший сеанс |
| `session-created` | Створено новий сеанс |
| `session-closed` | Сеанс знищено (всі його процеси завершилися або виконано `kill-session`) |
| `window-layout-changed` | Змінилося просторове розташування чи пропорції панелей у вікні |
| `pane-exited` | Головний дочірній процес панелі завершив роботу (отримано `EOF` або код виходу) |
| `pane-died` | Процес у панелі загинув при увімкненій опції `remain-on-exit` |
| `pane-focus-in` | Панель отримала фокус введення |
| `pane-focus-out` | Фокус введення перейшов на іншу панель |
| `after-split-window` | Успішно виконано поділ вікна на панелі |

### Практичні сценарії використання гачків

1. **Автоматичне логування всіх сеансів на диск:**
```tmux
# Автоматичний запуск запису виводу нової панелі у файл журналу
set-hook -g after-split-window 'pipe-pane -o "cat >> ~/logs/tmux-pane-#{pane_id}.log"'
```

2. **Сповіщення про падіння довготривалих збірок:**
```tmux
# Збереження панелі після виходу процесу для аналізу коду повернення
set -g remain-on-exit on
set-hook -g pane-died 'display-message "УВАГА: процес у панелі #{pane_id} впав із кодом #{pane_dead_status}"'
```

3. **Синхронізація робочого каталогу нової панелі з поточною:**
```tmux
bind '"' split-window -v -c "#{pane_current_path}"
bind % split-window -h -c "#{pane_current_path}"
```

4. **Автоматичне виконання дій при підключенні першого клієнта:**
```tmux
# Оновлення змінних середовища SSH_AUTH_SOCK при перепідключенні
set-hook -g client-attached 'run-shell "tmux show-environment -s | grep SSH_AUTH_SOCK | sh"'
```

Ці примітиви перетворюють `tmux` на універсальний інженерний фундамент, на базі якого створюються автоматизовані середовища CI/CD, диспетчери тривалих наукових обчислень, тестові стенди та нативні графічні клієнти терміналів.
