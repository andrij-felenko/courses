# 📋 Довідник масок, атрибутів та прапорців системного виклику statx

Цей довідник містить вичерпну нормативну специфікацію бітових масок, прапорців атрибутів, системних констант та кодів помилок системного виклику `statx(2)`. Він призначений для використання під час розробки системного програмного забезпечення для Linux, коли вимагається точний контроль за набором запитуваних атрибутів, узгодженістю мережевих кешів та сумісністю між версіями ядра.

## Сигнатура та заголовки

Системний виклик `statx` вимагає визначення макросу `_GNU_SOURCE` перед підключенням стандартних системних заголовочних файлів C-бібліотеки. Без цього макросу структури та сталі `statx` не експортуються заголовочними файлами `<fcntl.h>` та `<sys/stat.h>`.

:::tabs
```c
#define _GNU_SOURCE
#include <fcntl.h>           /* Сталі AT_* та прапорці відносних шляхів */
#include <sys/stat.h>        /* Контракт struct statx та біти STATX_* */

int statx(int dirfd, const char *restrict path, int flags,
          unsigned int mask, struct statx *restrict stx);
```
```cpp
#define _GNU_SOURCE
#include <fcntl.h>           // Сталі AT_* та прапорці відносних шляхів
#include <sys/stat.h>        // Контракт struct statx та біти STATX_*

int statx(int dirfd, const char *path, int flags,
          unsigned int mask, struct statx *stx) noexcept;
```
:::

Якщо програма компілюється на старій версії C-бібліотеки glibc (старішій за 2.28), де офіційна обгортка `statx()` ще відсутня, виклик можна виконувати напряму через системний виклик `syscall()` та заголовок `<sys/syscall.h>` з умовною перевіркою існування константи `__NR_statx`:

:::tabs
```c
#include <sys/syscall.h>

#ifndef __NR_statx
# error "Архітектура ядра не визначає системний виклик __NR_statx"
#endif

static inline int my_statx(int dirfd, const char *path, int flags,
                           unsigned int mask, struct statx *stx) {
    return syscall(__NR_statx, dirfd, path, flags, mask, stx);
}
```
```cpp
#include <sys/syscall.h>
#include <unistd.h>
#include <system_error>

#ifndef __NR_statx
# error "Архітектура ядра не визначає системний виклик __NR_statx"
#endif

inline int my_statx(int dirfd, const char *path, int flags,
                     unsigned int mask, struct statx *stx) noexcept {
    return static_cast<int>(::syscall(__NR_statx, dirfd, path, flags, mask, stx));
}
```
:::

### Детальний опис параметрів виклику

Параметр `dirfd` визначає базовий каталоговий дескриптор для відносного адресування. Якщо параметр `path` описує відносний шлях, ядро обчислює його відносно каталогу, відкритого у `dirfd`. Використання спеціального значення `AT_FDCWD` означає, що відносний шлях розпізнається відносно поточного робочого каталогу процесу. Якщо ж програма передає прапорець `AT_EMPTY_PATH`, а шлях `path` містить порожній рядок `""`, то системний виклик виконується безпосередньо над об'єктом, відкритим у самому дескрипторі `dirfd` (що дозволяє замінити класичний виклик `fstat`).

Параметр `path` містить вказівник на рядок із шляхом до файлу або каталогу. Шлях може бути як відносним, так і абсолютним. Якщо передано абсолютний шлях (що починається з косої риски `/`), параметр `dirfd` мовчно ігнорується ядром.

Параметр `flags` є бітовою маскою, яка керує поведінкою виклику. Вона контролює розпізнавання символьних посилань (`AT_SYMLINK_NOFOLLOW`), автоматичне монтування каталогів (`AT_NO_AUTOMOUNT`), а також визначає жорсткість синхронізації атрибутів із мережевими сховищами за допомогою групи прапорців `AT_STATX_*_SYNC`.

Параметр `mask` задає набір маскових бітів, які програма явним чином просить ядро заповнити у структурах метаданих. Ядро обробляє цей параметр як побажання: воно намагається заповнити всі запитані поля, але не повертає помилку, якщо конкретна файлова система не має технічної можливості надати певний атрибут.

Параметр `stx` є вказівником на буфер пам'яті у просторі користувача, у який ядро записує результуючу 256-байтну структуру `struct statx`.

## Бітові маски запиту полів (STATX_*)

Параметр `mask` приймає побітове «АБО» нижченаведених системних констант. Після завершення виклику ядро повертає діючу маску у полі `stx.stx_mask`, вказуючи, які саме з цих полів були успішно прочитані та записані у буфер.

Маска полів розділяє права та тип файлу на два окремих біти: `STATX_TYPE` та `STATX_MODE`. Це дозволяє утилітам обходу каталогів запитувати лише тип файлу (наприклад, щоб відрізнити каталог від звичайного файлу), не витрачаючи ресурси на зчитування та формування повних масок прав доступу POSIX.

| Константа бітової маски | Значення | Заповнювані поля в `struct statx` | Пояснення та призначення |
| :--- | :--- | :--- | :--- |
| `STATX_TYPE` | `0x00000001U` | `stx_mode` (маска `S_IFMT`) | Повертає тільки біти типу об'єкта (файл, каталог, сокет, symlink, пристрій). |
| `STATX_MODE` | `0x00000002U` | `stx_mode` (маска `07777`) | Повертає тільки біти прав доступу (rwxrwxrwx, setuid, setgid, sticky bit). |
| `STATX_NLINK` | `0x00000004U` | `stx_nlink` | Заповнює лічильник жорстких посилань на inode. |
| `STATX_UID` | `0x00000008U` | `stx_uid` | Заповнює числове ID користувача-власника файлу. |
| `STATX_GID` | `0x00000010U` | `stx_gid` | Заповнює числове ID групи-власника файлу. |
| `STATX_ATIME` | `0x00000020U` | `stx_atime` | Повертає час останнього читання або доступу до файлу. |
| `STATX_MTIME` | `0x00000040U` | `stx_mtime` | Повертає час останньої зміни вмісту файлу. |
| `STATX_CTIME` | `0x00000080U` | `stx_ctime` | Повертає час останньої зміни метаданих або статусу inode. |
| `STATX_INO` | `0x00000100U` | `stx_ino` | Заповнює унікальний 64-бітний номер inode у межах ФС. |
| `STATX_SIZE` | `0x00000200U` | `stx_size` | Заповнює точний розмір файлу у байтах. |
| `STATX_BLOCKS` | `0x00000400U` | `stx_blocks`, `stx_blksize` | Повертає кількість виділених 512-байтових блоків та оптимальний розмір блоку вводу/виводу. |
| `STATX_BASIC_STATS` | `0x000007ffU` | Усі поля вище | Комбінація усіх полів класичного виклику `stat`. |
| `STATX_BTIME` | `0x00000800U` | `stx_btime` | Повертає час створення файлу (birth time). |
| `STATX_MNT_ID` | `0x00001000U` | `stx_mnt_id` | Повертає 64-бітний ідентифікатор точки монтування (Linux 5.8+). |
| `STATX_DIOALIGN` | `0x00002000U` | `stx_dio_mem_align`, `stx_dio_offset_align` | Повертає вимоги вирівнювання для режиму `O_DIRECT` (Linux 6.1+). |
| `STATX_MNT_ID_UNIQUE` | `0x00004000U` | `stx_mnt_id` | Повертає унікальний ID монтування, який ядро не перевикористовує після відмонтування (Linux 6.8+). |
| `STATX_WRITE_ATOMIC` | `0x00010000U` | `stx_atomic_write_*` | Повертає межі розмірів для атомарних записів на апаратний носій (Linux 6.11+). |
| `STATX_ALL` | `0x00000fffU` | Базові + BTIME | Маска для отримання всіх стандартних атрибутів включно з датою створення. |

Перевірка повернутої маски є обов'язковим кроком після кожного виклику `statx`. Якщо програма запитувала `STATX_BTIME`, але у повернутому `stx_mask` цей біт дорівнює нулю, читання поля `stx_btime` поверне сміття або нульові значення.

## Прапорці керування маршрутизацією та кешуванням (flags)

Параметр `flags` дає можливість контролювати поведінку переходу по символьних посиланнях, спричинення автомонтування та керувати режимом синхронізації кешу метаданих.

### Базові прапорці монтування та посилань

Прапорець `AT_SYMLINK_NOFOLLOW` вказує ядру не виконувати перехід по символьному посиланню, якщо останній компонент переданого шляху `path` є символьним посиланням. У цьому разі повертаються атрибути самого файлу посилання.

Прапорець `AT_NO_AUTOMOUNT` забороняє автоматичне монтування точки автомонтування, якщо останній компонент шляху є каталогом з автоматичним монтуванням (automount). Це корисно для адміністративних утиліт інспектування файлових систем.

Прапорець `AT_EMPTY_PATH` дозволяє оперувати безпосередньо дескриптором `dirfd`, коли шлях `path` є порожнім рядком. Це критично для роботи з дескрипторами `O_PATH`.

### Прапорці керування когерентністю кешу метаданих

Група прапорців `AT_STATX_*_SYNC` контролює баланс між актуальністю атрибутів та швидкістю їх отримання у мережевих файлових системах (NFS, Ceph, SMB):

:::tabs
```c
/* Прапорці належать до маски AT_STATX_SYNC_TYPE (0x6000) */
#define AT_STATX_SYNC_AS_STAT   0x0000  /* Стандартний виклик stat */
#define AT_STATX_FORCE_SYNC     0x2000  /* Примусовий мережевий RPC */
#define AT_STATX_DONT_SYNC      0x4000  /* Читання лише з кешу VFS */
```
```cpp
// Прапорці належать до маски AT_STATX_SYNC_TYPE (0x6000)
constexpr int AT_STATX_SYNC_AS_STAT_VAL = 0x0000;  // Стандартний виклик stat
constexpr int AT_STATX_FORCE_SYNC_VAL   = 0x2000;  // Примусовий мережевий RPC
constexpr int AT_STATX_DONT_SYNC_VAL    = 0x4000;  // Читання лише з кешу VFS
```
:::

Прапорець `AT_STATX_SYNC_AS_STAT` використовує типові правила ядра: метадані беруться з кешу VFS, якщо їхній термін дії не закінчився, або запитуються з сервера, якщо таймер кешу вичерпано.

Прапорець `AT_STATX_FORCE_SYNC` інвалідує локальний кеш і змушує драйвер ФС виконати примусову синхронізацію з носієм або мережевим сервером. Це гарантує отримання найсвіжіших даних за ціною мережевої затримки (RTT).

Прапорець `AT_STATX_DONT_SYNC` забороняє будь-які мережеві запити або звернення до блокового носія. Ядро негайно повертає метадані з кешу VFS. Це забезпечує миттєвий результат, але повернуті дані можуть бути застарілими.

## Розширені атрибути файлу (stx_attributes та stx_attributes_mask)

Поле `stx_attributes` у `struct statx` містить 64-бітний набір розширених прапорців inode. Одночасно поле `stx_attributes_mask` показує, які з цих прапорців узагалі підтримуються цією файловою системою.

| Атрибут файлу | Значення біта | Опис внутрішньої властивості |
| :--- | :--- | :--- |
| `STATX_ATTR_COMPRESSED` | `0x00000004` | Вміст файлу стиснено прозорим алгоритмом ФС (Btrfs, ZFS, NTFS). |
| `STATX_ATTR_IMMUTABLE` | `0x00000010` | Файл захищено від запису, змінення, вилучення чи перейменування (`chattr +i`). |
| `STATX_ATTR_APPEND` | `0x00000020` | Дозволено лише додавання нових даних у кінець файлу (`chattr +a`). |
| `STATX_ATTR_NODUMP` | `0x00000040` | Файл ігнорується утилітою резервного копіювання `dump(8)`. |
| `STATX_ATTR_ENCRYPTED` | `0x00000800` | Вміст файлу зашифровано на рівні inode (fscrypt). |
| `STATX_ATTR_AUTOMOUNT` | `0x00001000` | Каталог є точкою автоматичного монтування. |
| `STATX_ATTR_MOUNT_ROOT` | `0x00002000` | Каталог є кореневим каталогом змонтованої ФС. |
| `STATX_ATTR_VERITY` | `0x00100000` | Для файлу ввімкнено захист цілісності деревоподібними хешами fs-verity. |
| `STATX_ATTR_DAX` | `0x00200000` | Файл знаходиться в режимі прямого доступу до енергонезалежної пам'яті (DAX). |

Перевірка атрибута вимагає двох умов: `(stx.stx_attributes_mask & ATTR)` має бути не нулем, і `(stx.stx_attributes & ATTR)` має бути встановлено в один.

## Ідентифікатори пристроїв та порівняння з POSIX dev_t

У класичному виклику `stat` старший і молодший номери пристрою пакувалися у єдине 64-бітне значення `st_dev` через бітові зсуви. На різних платформах (x86_64 vs MIPS vs SPARC) формула пакування була різною, що вимагало виклику системного макросу `major(dev)` та `minor(dev)` у просторі користувача.

У `statx` номери пристрою файлової системи (`stx_dev_major`, `stx_dev_minor`) та символьного/блокового пристрою (`stx_rdev_major`, `stx_rdev_minor`) представлені чотирма явними 32-бітними полями. Це дозволяє читати номери пристрою напряму без використання будь-яких препроцесорних макросів та усуває розбіжності між C-бібліотеками glibc, musl та uClibc.

## Реалізація у драйверах файлових систем (ext4, btrfs, xfs)

Кожна файлова система в ядрі Linux реалізує власний метод `getattr()` для заповнення полів `struct statx`:

- **ext4 (fs/ext4/inode.c):** Заповнює `STATX_BTIME` з розширеного inode розміром 256 або 512 байтів (поле `i_crtime`). Підтримує прапорці `IMMUTABLE`, `APPEND`, `ENCRYPTED` та `VERITY`.
- **Btrfs (fs/btrfs/inode.c):** Отримує час створення `btime` з елемента `btrfs_inode_item.otime`. Підтримує стиснення `STATX_ATTR_COMPRESSED` та розпізнає точки монтування підтомів (subvolumes).
- **XFS (fs/xfs/xfs_iops.c):** Отримує `btime` з поля `di_crtime` в inode v3. Повертає атрибути `DAX` та детальні параметри вирівнювання блоків `stx_blksize`.

## Внутрішнє представлення у ядрі: перетворення з kstat

Усередині ядра Linux системний виклик `statx` спирається на внутрішню ядерну структуру `struct kstat`. Коли драйвер файлової системи заповнює атрибути у своєму методі `getattr()`, він записує дані у структуру `kstat`.

Після цього внутрішня функція ядра `cp_statx()` копіює значення з `struct kstat` у буфер користувача `struct statx`:

1. **Копіювання базових полів:** Значення `kstat.mode`, `kstat.nlink`, `kstat.uid`, `kstat.gid`, `kstat.size`, `kstat.blocks`, `kstat.blksize` копіюються у відповідні поля `stx_*`.
2. **Конверсія часових позначок:** Структура `struct timespec64` ядра конвертується у `struct statx_timestamp` із розширенням секунд до 64 бітів.
3. **Обробка розширених полів:** Якщо у масці були запитані `STATX_DIOALIGN` або `STATX_MNT_ID`, ядро звертається до структур `struct block_device` та `struct vfsmount` для заповнення геометрії вирівнювання та номера монтування.

## Внутрішня перевірка прав доступу та сумісність із LSM

Під час виконання системного виклику `statx` підсистема VFS здійснює послідовний обхід усіх каталогів шляху `path` та після успішного розпізнавання цільового inode викликає ядерний хук `security_inode_getattr()`. Саме з цього кроку перевірки прав файлу випливає контроль доступу в підсистемі Linux Security Modules (LSM: SELinux, AppArmor, Smack).

Процес розпізнавання шляху VFS вимагає прав виконання (пошуку, `execute permission`) на кожен каталог, який входить до складу шляху `path`. Проте для самого файлу права читання або запису **не вимагаються**: будь-який процес, який здатний досягти об'єкта через дерево каталогів, має право зчитати його метадані через `statx`.

У внутрішній структурі ядра після виконання VFS `lookup` спрацьовує хук `security_inode_getattr()`. Якщо LSM-модуль забороняє доступ до інспектування атрибутів конкретного об'єкта за правилами мандатного контролю доступу (MAC), системний виклик переривається і повертає помилку `EACCES` або `EPERM`.

## Коди помилок (errno)

При успішному виконанні `statx` повертає `0`. При виникненні помилки повертається `-1`, а системна змінна `errno` містить код причини:

- `EINVAL`: Передано недійсні прапорці у `flags` (наприклад, одночасно `FORCE_SYNC` та `DONT_SYNC`) або зарезервований біт `STATX__RESERVED` у масці `mask`.
- `ENOENT`: Файл або один із каталогів у шляху `path` не існує, або шлях є порожнім без прапорця `AT_EMPTY_PATH`.
- `EBADF`: Передано некоректний файловий дескриптор `dirfd`.
- `ENOTDIR`: Елемент шляху, який має бути каталогом, є звичайним файлом.
- `EACCES`: Відсутні права пошуку (виконання) для одного з каталогів у складі шляху.
- `EFAULT`: Вказівник `path` або `stx` посилається на недоступну область пам'яті.
- `EOPNOTSUPP`: Операція або запитані розширення не підтримуються файловою системою чи її драйвером.
- `ENOSYS`: Системний виклик `statx` не підтримується поточним ядром Linux.

---

## Історія версій ядер Linux та бібліотеки glibc

Системний виклик `statx` розвивався поступово, додаючи нові біти масок у кожному великому випуску ядра Linux:

- **Linux 4.11 / glibc 2.28:** Початковий реліз системного виклику `statx`, впровадження `STATX_BASIC_STATS`, `STATX_BTIME`, прапорців керування кешем `AT_STATX_*_SYNC` та розширених атрибутів `stx_attributes`.
- **Linux 5.8 / glibc 2.32:** Додано підтримку читання ідентифікатора точки монтування `STATX_MNT_ID`.
- **Linux 5.5 / glibc 2.33:** Додано атрибут контролю цілісності `STATX_ATTR_VERITY`.
- **Linux 5.8 / glibc 2.34:** Додано атрибути `STATX_ATTR_DAX` та `STATX_ATTR_MOUNT_ROOT`.
- **Linux 6.1 / glibc 2.38:** Додано біт `STATX_DIOALIGN` для визначення вимог вирівнювання режиму `O_DIRECT`.
- **Linux 6.8 / glibc 2.40:** Додано біт `STATX_MNT_ID_UNIQUE` для гарантовано унікальних ідентифікаторів монтування.
- **Linux 6.11 / glibc 2.41:** Додано біт `STATX_WRITE_ATOMIC` для визначення апаратних меж атомарних записів.
