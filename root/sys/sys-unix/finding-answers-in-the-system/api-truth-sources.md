# 📋 Матриця джерел системної правди в Linux

Цей довідник систематизує архітектурні шари, файлові шляхи, внутрішні структури ядра та системні інтерфейси операційної системи Linux, де зберігається достовірна інформація про конфігурацію, внутрішній стан ядра, процеси, апаратне забезпечення, віртуальну пам'ять, мережевий стек та журнали подій. У середовищі Unix стан розподілений між різними підсистемами, тому під час діагностики збоїв інженер має орієнтуватися не на окремий файл на диску, а на сукупність взаємопов'язаних площин правди.

Нижче наведено вичерпні специфікації кожної площини, формати представлення даних, вимоги до привілеїв доступу, механізми захисту від модифікації та контракт діагностичних утиліт низькорівневого аналізу.

## 1. Площини системного стану та ієрархія авторитетності

Усі джерела системної інформації поділяються на фундаментальні рівні, кожен із яких має власний життєвий цикл, тип сховища, механізм оновлення та модель безпеки.

| Площина стану | Розташування у VFS | Тип файлової системи | Персистентність | Хто пише | Хто читає |
|---|---|---|---|---|---|
| **Статичний канон (Vendor)** | `/usr/share/man`, `/usr/lib/systemd/`, `/usr/lib/sysctl.d/` | ext4 / XFS / Btrfs (rootfs) | Постійна (пакетний менеджер) | Пакетний менеджер (`apt`, `dnf`, `pacman`) | Адміністратор, утиліти конфігурації |
| **Декларативна конфігурація (Host)** | `/etc/`, `/etc/sysctl.d/`, `/etc/systemd/system/` | ext4 / XFS / Btrfs (rootfs) | Постійна (зберігається на диску) | Системний адміністратор, Ansible, Puppet | Демони під час старту або `SIGHUP` |
| **Летючий рантайм (Runtime)** | `/run/`, `/run/systemd/system/`, `/run/user/<UID>/` | `tmpfs` (оперативна пам'ять) | Летюча (втрачається при перезавантаженні) | PID 1 (`systemd`), активні демони | Клієнти IPC, `systemctl`, `journalctl` |
| **Процесний стан ядра (Process VFS)** | `/proc/<PID>/` | `procfs` (синтетична пам'ять ядра) | Динамічна (живе разом із процесом) | Ядро Linux (`task_struct`) | `ps`, `top`, зневаджувачі, застосунки |
| **Глобальний стан ядра (Kernel VFS)** | `/proc/sys/`, `/proc/meminfo`, `/proc/net/`, `/proc/stat` | `procfs` (синтетична пам'ять ядра) | Динамічна (поки працює ядро) | Ядро Linux (`sysctl_table`, підсистеми) | `sysctl`, утиліти моніторингу, демони |
| **Модель пристроїв (Device VFS)** | `/sys/devices/`, `/sys/bus/`, `/sys/class/`, `/sys/block/` | `sysfs` (об'єкти `kobject`) | Динамічна (поки пристрій підключено) | Драйвери пристроїв ядра | `udev`, `ip`, `lsblk`, `lspci` |
| **Контрольні групи (cgroups v2)** | `/sys/fs/cgroup/` | `cgroup2` (ієрархія ресурсів) | Динамічна (керується ядром/PID 1) | `systemd`, контейнерні рушії, ядро | Планувальники ресурсів, моніторинг |
| **Діагностика ядра (Debug VFS)** | `/sys/kernel/debug/` | `debugfs` (внутрішні хуки) | Динамічна (вимагає CAP_SYS_ADMIN) | Підсистеми ядра (ftrace, DRM, Wi-Fi) | Розробники, трасувальники (`bpftrace`) |
| **Кільцевий буфер ядра (Telemetry)** | `/dev/kmsg`, `klogctl` | Символьний пристрій / IPC | Кільцева RAM (перезаписується по колу) | `printk()` у ядрі | `dmesg`, `systemd-journald` |
| **Структурований журнал (Events)** | `/var/log/journal/<machine-id>/` | Спеціальний бінарний формат | Постійна або `tmpfs` у `/run` | `systemd-journald` | `journalctl`, утиліти аудиту |

Головний принцип вирішення системних суперечностей: **живий стан ядра в оперативній пам'яті (`procfs`, `sysfs`, `cgroupfs`) завжди превалює над декларативним текстом на диску (`/etc`)**. Якщо файл `/etc/sysctl.d/99-network.conf` містить директиву `net.ipv4.ip_forward = 1`, але у вузлі `/proc/sys/net/ipv4/ip_forward` записано `0`, ядро відкидатиме транзитні пакети.

## 2. Специфікація процесного простору /proc/[pid]/

Каталог `/proc/[pid]/` синтезується підсистемою `procfs` у момент звернення на основі структури ядра `struct task_struct` та пов'язаних дескрипторів пам'яті `struct mm_struct` і файлів `struct files_struct`.

Псевдопосилання `/proc/self/` автоматично відображає каталог процесу, який виконує системний виклик, а `/proc/thread-self/` — каталог конкретного потоку виконання (`struct task_struct`).

### 2.1. Загальна модель доступу та безпеки

Доступ до конфіденційних вузлів (`environ`, `maps`, `smaps_rollup`, `mem`, `pagemap`, `stack`) регулюється функцією ядра `ptrace_may_access()` з режимом `PTRACE_MODE_READ_FSCREDS`.

Процес-читач отримує доступ лише за виконання однієї з умов:
1. Читач має той самий дійсний, ефективний та збережений UID/GID, що й цільовий процес, і цільовий процес не змінював привілеїв через `setuid()` / `setgid()`;
2. Читач володіє системним привілеєм `CAP_SYS_PTRACE` у просторі імен користувача (`user namespace`) цільового процесу;
3. Модуль безпеки ядра LSM (зокрема Yama LSM через `/proc/sys/kernel/yama/ptrace_scope`) не блокує інспекцію неспоріднених процесів.

### 2.2. Командний рядок та оточення: /proc/[pid]/cmdline та /proc/[pid]/environ

- **`/proc/[pid]/cmdline`** (`r--r--r--`): послідовність рядків аргументів запуску, розділених нульовими байтами (`\0`). Завершується нульовим байтом.
  - *Особливості*: для процесів-зомбі читання повертає `0` байтів (EOF). Для потоків ядра (kernel threads) файл порожній.
  - *Модифікація*: процес може перезаписати область пам'яті `argv` через системний виклик `prctl(PR_SET_MM, PR_SET_MM_ARG_START, ...)` або прямим записом у початковий буфер `argv[0]`. Для отримання гарантованого незмінного імені бінарника слід читати символьне посилання `/proc/[pid]/exe`.
- **`/proc/[pid]/environ`** (`r--------`, захищено `ptrace_may_access`): послідовність пар `KEY=VALUE`, розділених нульовими байтами (`\0`).
  - Відображає початковий блок змінних середовища, переданих під час виклику `execve()`. Динамічні зміни середовища через `setenv()` у просторі користувача не оновлюють початковий буфер ядра, якщо процес явно не викликав `prctl(PR_SET_MM_ENV_START, ...)`.

### 2.3. Повна специфікація полів /proc/[pid]/stat (поля 1–52)

Файл `/proc/[pid]/stat` містить рівно один рядок із 52 числовими та текстовими полями, розділеними пробілами.

> ⚠️ **Пастка синтаксичного аналізу:** поле 2 (`comm`) містить назву виконуваного файлу в круглих дужках `(comm)`. Оскільки процес може встановити довільне ім'я команди, що містить пробіли та круглі дужки (наприклад, `(worker (1) proc)`), простий поділ рядка за пробілами (`sscanf` чи `split(" ")`) неминуче ламається. Коректний алгоритм парсингу зобов'язаний знайти першу відкриваючу дужку `(` та **останню закриваючу дужку** `)` у рядку. Усі поля після останньої `)` є строго позиційними й починаються з поля 3 (`state`).

### 2.4. Метрики пам'яті /proc/[pid]/statm

Файл `/proc/[pid]/statm` надає компактний зріз використання пам'яті у вигляді семи числових полів через пробіл. **Усі значення вказані в кількості сторінок віртуальної пам'яті** (типово 4096 байтів на архітектурах x86_64 та ARM64):

```
size       resident  shared    text   lib  data   dt
1048576    262144    32768     1024   0    524288 0
```

1. `size`: загальний розмір виділеного віртуального адресного простору (`VmSize` у сторінках);
2. `resident`: кількість резидентних сторінок у фізичній пам'яті (`VmRSS` у сторінках);
3. `shared`: кількість сторінок, розділених з іншими процесами (маповані файли та `shmem`);
4. `text`: розмір сегмента виконуваного коду (`VmExe` у сторінках);
5. `lib`: сторінки динамічних бібліотек (не використовується в Linux 2.6+, завжди `0`);
6. `data`: сторінки даних, купи та стека (`VmData + VmStk` у сторінках);
7. `dt`: «брудні» сторінки (не використовується в Linux 2.6+, завжди `0`).

### 2.5. Зведений людиночитаний статус /proc/[pid]/status

Файл `/proc/[pid]/status` транслює структури ядра у текстові пари `Ключ: Значення\n`, стійкі до додавання нових полів між версіями ядра.

Ключові діагностичні групи полів:

- **Ідентифікація та планування**:
  - `Name`: ім'я команди (`task_struct->comm`);
  - `Umask`: вісімкова маска створення файлів процесу (наприклад, `0022`);
  - `State`: поточний стан планувальника (наприклад, `S (sleeping)`);
  - `Tgid`: Thread Group ID (дорівнює головному PID процесу);
  - `Pid`: Thread ID (для головного потоку збігається з TGID, для потоків у `/proc/[pid]/task/[tid]/status` містить TID);
  - `PPid`: PID батьківського процесу;
  - `TracerPid`: PID процесу, що здійснює трасування через `ptrace` (0, якщо зневаджувач не підключено);
  - `Uid`, `Gid`: чотири числа через табуляцію: `Real`, `Effective`, `Saved set`, `Filesystem` ідентифікатори;
  - `FDSize`: поточна місткість таблиці дескрипторів (виділені слоти пам'яті під FD);
  - `Groups`: список додаткових числових ідентифікаторів груп процесу;
  - `NStgid`, `NSpid`, `NSpgid`, `NSsid`: ідентифікатори процесу всередині вкладених просторів імен (PID namespaces), від зовнішнього хоста до найглибшого контейнера.
- **Використання пам'яті (у кілобайтах)**:
  - `VmPeak`: піковий розмір віртуальної пам'яті за весь час життя процесу;
  - `VmSize`: поточний розмір віртуального адресного простору;
  - `VmLck`: обсяг пам'яті, заблокованої від скидання в swap викликом `mlock()`;
  - `VmPin`: обсяг пам'яті, зафіксованої драйверами для прямого доступу DMA;
  - `VmHWM`: «High Water Mark» — піковий обсяг фізичної пам'яті (RSS), зайнятий процесом;
  - `VmRSS`: поточний обсяг фізичної пам'яті в RAM (`RssAnon + RssFile + RssShmem`);
  - `RssAnon`: анонімна пам'ять (купи `malloc`, стеки потоків);
  - `RssFile`: пам'ять кешу файлів та динамічних бібліотек;
  - `RssShmem`: пам'ять спільних сегментів (`tmpfs`, `shmget`);
  - `VmData`, `VmStk`, `VmExe`, `VmLib`: розміри окремих віртуальних сегментів;
  - `VmPTE`: обсяг пам'яті ядра, виділений під самі таблиці сторінок процесу (Page Table Entries);
  - `VmSwap`: обсяг пам'яті процесу, витіснений у swap-простір;
  - `HugetlbPages`: пам'ять, виділена у величезних сторінках (HugeTLB).
- **Потоки та маски сигналів (шістнадцяткові бітові маски)**:
  - `Threads`: загальна кількість активних потоків у процесі;
  - `SigQ`: співвідношення поточної кількості сигналів у черзі до системного ліміту (наприклад, `0/128320`);
  - `SigPnd`: сигнали, що очікують обробки конкретно цим потоком;
  - `ShdPnd`: сигнали, що очікують обробки процесом загалом;
  - `SigBlk`: маска заблокованих сигналів (`pthread_sigmask`);
  - `SigIgn`: маска ігнорованих сигналів (`SIG_IGN`);
  - `SigCgt`: маска сигналів із зареєстрованими функціями-обробниками.
- **Привілеї та ізоляція (Capabilities & Security)**:
  - `CapInh`, `CapPrm`, `CapEff`, `CapBnd`, `CapAmb`: 64-бітні бітові маски системних можливостей (Inheritable, Permitted, Effective, Bounding, Ambient);
  - `NoNewPrivs`: заборона підвищення привілеїв через `setuid`-бінарники (0 або 1);
  - `Seccomp`: режим системного фільтра викликів (0 = вимкнено, 1 = strict, 2 = seccomp-bpf);
  - `Speculation_Store_Bypass`: стан апаратного захисту від уразливостей спекулятивного виконання (Spectre/Meltdown).
- **Прив'язка до процесорів та перемикання контексту**:
  - `Cpus_allowed`: бітова маска доступних процесорних ядер;
  - `Cpus_allowed_list`: список доступних ядер (наприклад, `0-3,7`);
  - `Mems_allowed_list`: список доступних вузлів пам'яті NUMA;
  - `voluntary_ctxt_switches`: кількість добровільних віддач кванта CPU (очікування I/O, блокування сокетів, виклик `sched_yield()`);
  - `nonvoluntary_ctxt_switches`: кількість примусових переривань процесу планувальником після вичерпання виділеного кванта часу.

### 2.6. Каталог відкритих дескрипторів /proc/[pid]/fd/ та метадані /proc/[pid]/fdinfo/

Каталог `/proc/[pid]/fd/` містить символьні посилання для кожного відкритого дескриптора (від 0 до ліміту `RLIMIT_NOFILE`).

Типи цілей посилань:
- Звичайні файли: `/var/log/app.log` (якщо файл видалено з диску іншим процесом, ядро додає суфікс: `/var/log/app.log (deleted)`);
- Мережеві сокети: `socket:[145293]` (число — унікальний `inode` сокета в мережевому просторі імен);
- Анонімні канали IPC: `pipe:[84102]`;
- Анонімні дескриптори ядра: `anon_inode:[eventpoll]`, `anon_inode:[eventfd]`, `anon_inode:[signalfd]`, `anon_inode:[timerfd]`, `anon_inode:[userfaultfd]`, `anon_inode:sync_file`.

Підкаталог `/proc/[pid]/fdinfo/<FD>` надає внутрішні зміщення та прапорці відкриття:

```
pos:    8192
flags:  0100002
mnt_id: 28
```

- `pos`: поточна позиція зчитування/запису у файлі (у десяткових байтах);
- `flags`: прапорці відкриття у вісімковій системі числення. Молодші 2 біти кодують режим доступу: `00` = `O_RDONLY`, `01` = `O_WRONLY`, `02` = `O_RDWR`. Старші біти кодують модифікатори: `02000` = `O_NONBLOCK`, `04000` = `O_APPEND`, `040000` = `O_DIRECTORY`, `0100000` = `O_LARGEFILE`, `02000000` = `O_CLOEXEC`;
- `mnt_id`: ідентифікатор точки монтування файлової системи (відповідає першому полю у `/proc/[pid]/mountinfo`).

Спеціалізовані розширення `fdinfo`:
- **eventfd**: містить рядок `eventfd-count: <число>` (поточне 64-бітне значення лічильника);
- **epoll**: містить записи для кожного зареєстрованого дескриптора: `tfd: <FD> events: <hex> data: <uint64> pos: <dec> ino: <hex> sdev: <hex>`;
- **inotify**: містить записи про спостережувані вузли: `inotify wd:<WD> ino:<inode> sdev:<dev> mask:<hex_events> ignored_mask:<hex>`;
- **timerfd**: містить `clockid: <ID>`, `ticks: <кількість_спрацювань>`, `settime_flags: <flags>`, `it_value: (<sec>, <nsec>)`, `it_interval: (<sec>, <nsec>)`;
- **signalfd**: містить `sigmask: <hex_bitmask>`.

### 2.7. Карта віртуальної пам'яті /proc/[pid]/maps

Кожен рядок описує неперервну область віртуальної пам'яті (VMA, Virtual Memory Area) процесу:

```
00400000-00452000 r-xp 00000000 08:01 123456 /usr/bin/app
00651000-00652000 r--p 00051000 08:01 123456 /usr/bin/app
00652000-00653000 rw-p 00052000 08:01 123456 /usr/bin/app
01a2b000-01a4c000 rw-p 00000000 00:00 0      [heap]
7fff5be00000-7fff5be21000 rw-p 00000000 00:00 0 [stack]
7fff5beff000-7fff5bf03000 r-xp 00000000 00:00 0 [vdso]
7fff5bf03000-7fff5bf05000 r--p 00000000 00:00 0 [vvar]
ffffffffff600000-ffffffffff601000 --xp 00000000 00:00 0 [vsyscall]
```

Поля зліва направо:
1. `address`: діапазон віртуальних адрес `початок-кінець` у шістнадцятковому форматі;
2. `perms`: права доступу з 4 символів:
   - символ 1: `r` (читання) або `-`;
   - символ 2: `w` (запис) або `-`;
   - символ 3: `x` (виконання коду) або `-`;
   - символ 4: `p` (приватна пам'ять / Copy-On-Write) або `s` (спільна пам'ять / Shared, синхронізується з файлом або іншими процесами);
3. `offset`: зміщення від початку файлу (у шістнадцяткових байтах);
4. `dev`: старший та молодший номери пристрою накопичувача у hex (`major:minor`, наприклад `08:01` для `/dev/sda1`);
5. `inode`: номер inode на файловій системі (дорівнює 0 для анонімної пам'яті);
6. `pathname`: шлях до файлу на диску або спеціальний псевдошлях ядра:
   - `[heap]`: динамічна купа головного процесу;
   - `[stack]`: стек головного потоку процесу;
   - `[stack:<TID>]`: стек конкретного додаткового потоку;
   - `[vdso]`: Virtual Dynamically linked Shared Object (код швидких системних викликів ядра, що виконується без перемикання кілець захисту CPU);
   - `[vvar]`: змінні ядра, доступні для прямого зчитування користувацьким кодом (наприклад, дані точного таймера `CLOCK_REALTIME`);
   - `[vsyscall]`: застаріла сторінка емуляції старих системних викликів;
   - порожнє поле: анонімна область пам'яті, виділена через `mmap(MAP_ANONYMOUS)`.

### 2.8. Агрегований профіль пам'яті /proc/[pid]/smaps_rollup

Файл `/proc/[pid]/smaps_rollup` (доступний починаючи з Linux 4.14) розв'язує проблему продуктивності читання `/proc/[pid]/smaps`. Сканування класичного `smaps` вимагає обходу сотень або тисяч об'єктів VMA з блокуванням семафора пам'яті процесу `mmap_lock` (що викликає затримки виконання сервісу). `smaps_rollup` агрегує всі діапазони за один швидкий прохід `O(1)` часу:

- `Rss`: сумарна фізична пам'ять у RAM;
- `Pss` (Proportional Set Size): сумарний пропорційний розмір пам'яті. Сторінки, спільні між N процесами, враховуються з вагою 1/N, що дає найточнішу оцінку реального споживання пам'яті сервісом;
- `Pss_Dirty`, `Pss_Anon`, `Pss_File`, `Pss_Shmem`: деталізація пропорційної пам'яті за типами;
- `Shared_Clean` / `Shared_Dirty`: спільні незмінені та модифіковані сторінки;
- `Private_Clean` / `Private_Dirty`: приватні сторінки, що належать виключно цьому процесу (не розділяються з іншими);
- `Referenced`: сторінки, до яких звертався процесор за останній цикл сканування;
- `Anonymous`: загальний обсяг анонімної пам'яті;
- `LazyFree`: сторінки, позначені викликом `madvise(MADV_FREE)`, які можуть бути миттєво звільнені ядром без скидання в swap;
- `AnonHugePages`: пам'ять, алокована прозорими гігантськими сторінками (Transparent Huge Pages, 2 МіБ);
- `Swap` та `SwapPss`: витіснений у swap обсяг пам'яті (загальний та пропорційний);
- `Locked`: пам'ять, утримувана через `mlock()`.

### 2.9. Стан очікування та стек викликів: /proc/[pid]/wchan та /proc/[pid]/stack

- **`/proc/[pid]/wchan`** (`r--r--r--`): текстова назва функції ядра, у якій процес перебуває в стані сну (наприклад, `futex_wait_queue_me`, `do_sys_poll`, `ep_poll`, `sk_wait_data`, `pipe_read`).
  - Якщо процес виконується на процесорі або готовий до виконання (`TASK_RUNNING`), повертає символ `0`.
  - Вимагає наявності символьної таблиці ядра (`CONFIG_KALLSYMS`).
- **`/proc/[pid]/stack`** (`r--------`, вимагає `CAP_SYS_ADMIN` або `ptrace_may_access`): поточний стек викликів ядра цільового потоку (потрібен параметр збірки `CONFIG_STACKTRACE`):

```
[<0>] futex_wait_queue_me+0xc8/0x130
[<0>] futex_wait+0xf5/0x250
[<0>] do_futex+0x14f/0x590
[<0>] __x64_sys_futex+0x13c/0x170
[<0>] do_syscall_64+0x5b/0x90
[<0>] entry_SYSCALL_64_after_hwframe+0x63/0xcd
```

## 3. Специфікація глобальних вузлів /proc

Глобальні файли у корені `/proc` відображають агреговану телеметрію підсистем операційної системи.

### 3.1. Розподіл фізичної пам'яті: /proc/meminfo

Файл `/proc/meminfo` містить інформацію про баланс пам'яті ядра та простору користувача (значення вказані в кілобайтах, 1024 байти):

- **`MemTotal`**: загальний обсяг фізичної пам'яті RAM, доступний ядру (за винятком пам'яті, зарезервованої бінарним кодом ядра під час завантаження);
- **`MemFree`**: пам'ять, яка взагалі не використовується і перебуває у списках вільних сторінок (Buddy Allocator);
- **`MemAvailable`**: розрахунковий обсяг пам'яті, доступний для запуску нових застосунків без необхідності витіснення в swap. Ядро обчислює його за формулою: `MemAvailable ≈ MemFree + Cached + SReclaimable - Watermarks_low`. Враховує, що частина сторінкового кешу та slab-структур не може бути звільнена через обмеження ядра;
- **`Buffers`**: пам'ять під тимчасові буфери необроблених дискових блоків (метадані файлових систем, суперблоки);
- **`Cached`**: сторінковий кеш файлів (Page Cache), що зберігає в пам'яті прочитані або записані файли;
- **`SwapCached`**: сторінки, які були скинуті в swap, згодом прочитані назад у RAM, але їхня копія все ще зберігається у файлі підкачки;
- **`Active(anon)` / `Inactive(anon)`**: анонімна пам'ять на LRU-списках ядра. Неактивна пам'ять є першим кандидатом на скидання в swap при дефіциті RAM;
- **`Active(file)` / `Inactive(file)`**: файловий кеш на LRU-списках. Неактивний кеш може бути миттєво відкинутий ядром без звернення до диска;
- **`Unevictable` / `Mlocked`**: сторінки, які категорично заборонено витісняти з оперативної пам'яті (через виклики `mlock` або використання ramfs);
- **`Dirty`**: сторінки файлового кешу, модифіковані застосунками, які ще не записані на фізичний накопичувач;
- **`Writeback`**: сторінки, які просто зараз передаються драйвером на накопичувач;
- **`AnonPages`**: анонімні сторінки, замаповані в адресні простори користувацьких процесів;
- **`Mapped`**: файли, замаповані у віртуальну пам'ять через виклик `mmap()` (наприклад, динамічні бібліотеки `.so`);
- **`Shmem`**: пам'ять файлових систем `tmpfs`, спільних сегментів POSIX/SysV та каталогу `/dev/shm`;
- **`Slab`**: внутрішні кеші структур ядра (`struct inode`, `struct dentry`, буфери сокетів);
- **`SReclaimable`**: частина Slab-пам'яті, яку ядро здатне вивільнити при нестачі RAM (переважно кеш dentry та inode);
- **`SUnreclaim`**: частина Slab-пам'яті, яку не можна звільнити під навантаженням (дескриптори задач, системні черги);
- **`KernelStack`**: пам'ять, виділена під стеки викликів ядра для кожного створеного потоку (типово 16 КіБ на потік на x86_64);
- **`PageTables`**: пам'ять, виділена під самі багаторівневі таблиці сторінок віртуальної пам'яті;
- **`CommitLimit`**: граничний ліміт виділення віртуальної пам'яті в режимі `vm.overcommit_memory = 2`: `CommitLimit = SwapTotal + (MemTotal × vm.overcommit_ratio / 100)`;
- **`Committed_AS`**: сумарний обсяг віртуальної пам'яті, гарантований усім процесам системи за найгіршого сценарію 100% заповнення;
- **`HugePages_Total`**, **`HugePages_Free`**, **`Hugepagesize`**: лічильники статично виділених величезних сторінок пам'яті (HugeTLB).

### 3.2. Системний час CPU та переривання: /proc/stat

Файл `/proc/stat` містить глобальні агреговані лічильники планувальника та підсистем ядра з моменту завантаження комп'ютера.

Рядок `cpu` (та індивідуальні рядки `cpu0`, `cpu1`, ...) містить 10 числових полів, виміряних в одиницях **`USER_HZ`** (типово 1/100 секунди):

```
cpu  2255 34 2290 22625563 6290 127 456 0 0 0
```

1. `user`: час виконання звичайних процесів у просторі користувача;
2. `nice`: час виконання низькопріоритетних процесів у просторі користувача (із додатним `nice`);
3. `system`: час виконання коду ядра (системні виклики);
4. `idle`: час простою процесора (виконання задачі `idle`);
5. `iowait`: час простою процесора, під час якого очікувалося завершення дискових операцій введення-виведення;
6. `irq`: час обслуговування апаратних переривань;
7. `softirq`: час обслуговування програмних переривань (мережеві нижні половини, тасклети);
8. `steal`: час, примусово відібраний гіпервізором у віртуальної машини під час роботи на перевантаженому хості;
9. `guest`: час виконання віртуального процесора гостьової ОС;
10. `guest_nice`: час виконання гостьової ОС із низьким пріоритетом.

Інші ключові рядки `/proc/stat`:
- `intr`: загальна кількість оброблених переривань та їхній розподіл за номерами ліній IRQ;
- `ctxt`: сумарна кількість перемикань контексту (`context switches`) між процесами;
- `btime`: час завантаження системи в секундах від початку епохи Unix (Unix Timestamp);
- `processes`: загальна кількість процесів і потоків, створених викликами `fork()` / `clone()`;
- `procs_running`: кількість процесів, які виконуються або очікують на чергу CPU просто зараз;
- `procs_blocked`: кількість процесів, заблокованих в очікуванні завершення операцій введення-виведення (стан `D`).

### 3.3. Середнє навантаження системи: /proc/loadavg

Файл `/proc/loadavg` містить п'ять полів через пробіл:

```
0.15 0.24 0.30 2/415 18452
```

1. `load1`: експоненційно зважене середнє навантаження за 1 хвилину;
2. `load5`: середнє навантаження за 5 хвилин;
3. `load15`: середнє навантаження за 15 хвилин;
4. `runnable/total`: кількість задач, що виконуються або готові до виконання в планувальнику (`TASK_RUNNING`), через скісну риску від загальної кількості потоків виконання в системі;
5. `last_pid`: ідентифікатор останнього створеного в системі процесу.

> ℹ️ **Архітектурна відмінність Linux:** на відміну від класичних систем BSD та Unix, які враховували в Load Average виключно процеси у стані `TASK_RUNNING`, ядро Linux додає до розрахунку процеси у стані **`TASK_UNINTERRUPTIBLE`** (стан `D`, очікування дискового або мережевого I/O). Завдяки цьому високий Load Average у Linux може свідчити не лише про дефіцит процесорного часу, але й про деградацію дискового масиву або зависання монтувань NFS.

### 3.4. Телеметрія блокових пристроїв: /proc/diskstats

Файл `/proc/diskstats` містить статистику роботи накопичувачів та їхніх розділів. Кожен рядок описує один блоковий пристрій.

Поля рядка (поля 1–14 — базовий контракт ядра; 15–18 додані в Linux 4.18 для Discard/TRIM; 19–20 додані в Linux 5.5 для Flush-операцій):

1. `major`: старший номер типу пристрою (наприклад, 8 для SCSI/SATA дисків `sdX`, 259 для `nvme`);
2. `minor`: молодший номер пристрою або розділу;
3. `dev_name`: системна назва блокового пристрою (`sda`, `nvme0n1`, `dm-0`);
4. `reads_completed`: кількість успішно завершених операцій читання;
5. `reads_merged`: кількість операцій читання, об'єднаних планувальником I/O в один суміжний запит;
6. `sectors_read`: кількість прочитаних секторів (розмір одного сектора завжди фіксований як **512 байтів**);
7. `time_reading_ms`: сумарний час, витрачений на операції читання (у мілісекундах);
8. `writes_completed`: кількість успішно завершених операцій запису;
9. `writes_merged`: кількість операцій запису, об'єднаних планувальником I/O;
10. `sectors_written`: кількість записаних секторів (по 512 байтів);
11. `time_writing_ms`: сумарний час, витрачений на операції запису (у мілісекундах);
12. `ios_in_progress`: кількість операцій введення-виведення, які перебувають у черзі обробки просто зараз;
13. `time_io_ms`: сумарний час, протягом якого пристрій мав активні запити I/O (використовується для розрахунку `%util` в `iostat`);
14. `weighted_time_io_ms`: зважений час I/O (кожна мілісекунда множиться на кількість активних запитів у черзі);
15. `discards_completed`: кількість успішних операцій очищення блоків (Discard/TRIM);
16. `discards_merged`: кількість об'єднаних операцій Discard;
17. `sectors_discarded`: кількість очищених 512-байтних секторів;
18. `time_discarding_ms`: сумарний час операцій Discard (у мілісекундах);
19. `flushes_completed`: кількість операцій примусового скидання кешу на диск (Flush/FUA);
20. `time_flushing_ms`: сумарний час операцій Flush (у мілісекундах).

### 3.5. Мережеві таблиці ядра: /proc/net/tcp, /proc/net/udp та /proc/net/dev

Підкаталог `/proc/net/` є посиланням на мережевий простір імен процесу (`/proc/self/net/`).

#### Таблиці активних сокетів: /proc/net/tcp та /proc/net/tcp6

Рядки містять стан сокетів транспортного рівня:

```
  sl  local_address rem_address   st tx_queue rx_queue tr tm->when retrnsmt   uid  timeout inode
   0: 0100007F:0050 00000000:0000 0A 00000000:00000000 00:00000000 00000000     0        0 145293 1 0000000000000000 100 0 0 10 0
```

- `local_address` та `rem_address`: шістнадцяткове кодування IPv4-адреси та порту. Адреса записана в порядку байтів процесора (little-endian для x86), а порт — у мережевому порядку байтів (big-endian). Наприклад, `0100007F:0050` означає IP `127.0.0.1` (`0x7F000001`) та порт `80` (`0x0050 = 80`);
- `st`: шістнадцятковий код стану з'єднання TCP:

| Код у hex | Символьна константа ядра | Опис стану TCP |
|---|---|---|
| `01` | `TCP_ESTABLISHED` | З'єднання успішно встановлено, передача даних активна. |
| `02` | `TCP_SYN_SENT` | Відправлено пакет SYN, очікування підтвердження SYN-ACK. |
| `03` | `TCP_SYN_RECV` | Отримано SYN, відправлено SYN-ACK, очікування фінального ACK. |
| `04` | `TCP_FIN_WAIT1` | Локальний застосунок закрив сокет, відправлено FIN. |
| `05` | `TCP_FIN_WAIT2` | Отримано ACK на наш FIN, очікування FIN від віддаленого боку. |
| `06` | `TCP_TIME_WAIT` | Очікування закриття для вичерпання старих пакетів у мережі (2MSL). |
| `07` | `TCP_CLOSE` | Сокет закрито (використовується також для непідключених сокетів UDP). |
| `08` | `TCP_CLOSE_WAIT` | Отримано FIN від віддаленого боку, очікування закриття локальним застосунком. |
| `09` | `TCP_LAST_ACK` | Відправлено фінальний FIN, очікування останнього підтвердження ACK. |
| `0A` | `TCP_LISTEN` | Сокет перебуває в режимі очікування нових з'єднань (`listen()`). |
| `0B` | `TCP_CLOSING` | Обидві сторони одночасно ініціювали закриття з'єднання. |
| `0C` | `TCP_NEW_SYN_RECV` | Напіввідкрите з'єднання в черзі SYN ядра без виділення повного сокета. |

- `tx_queue:rx_queue`: шістнадцяткові розміри буферів відправки та прийому сокета в байтах;
- `inode`: унікальний ідентифікатор сокета, який дозволяє зіставити запис сокета з дескриптором процесу у `/proc/<PID>/fd/` (`socket:[inode]`).

#### Таблиця лічильників інтерфейсів: /proc/net/dev

Містить зведені лічильники пакетів для кожного інтерфейсу:

```
Inter-|   Receive                                                |  Transmit
 face |bytes    packets errs drop fifo frame compressed multicast|bytes    packets errs drop fifo colls carrier compressed
  eth0: 1048576   12500    0    0    0     0          0         0   524288    6200    0    0    0     0       0          0
```

Лічильники охоплюють прийняті/відправлені байти, пакети, апаратні помилки (`errs`), скинуті пакети через переповнення черги (`drop`), помилки кільцевого буфера (`fifo`), пошкодження кадрів (`frame`), колізії CSMA/CD (`colls`) та втрату несучої частоти (`carrier`).

### 3.6. Таблиці керування ядром: /proc/sys/ (sysctl)

Каталог `/proc/sys/` надає доступ до зміни поведінки ядра в режимі реального часу. Крапковий запис ключа `sysctl` транслюється у файловий шлях заміною крапок на похилі риски:

| Ключ sysctl | Шлях у /proc/sys/ | Тип даних | Діапазон / Значення | Призначення |
|---|---|---|---|---|
| `fs.file-max` | `/proc/sys/fs/file-max` | uint64 | 1..18446744073709551615 | Системний ліміт на максимальну сумарну кількість відкритих дескрипторів для всіх процесів разом. |
| `fs.nr_open` | `/proc/sys/fs/nr_open` | uint32 | 1024..1073741824 | Верхня межа ліміту відкритих дескрипторів для одного окремого процесу (`RLIMIT_NOFILE`). |
| `net.core.somaxconn` | `/proc/sys/net/core/somaxconn` | uint32 | 1..65535 | Максимальна довжина черги повністю встановлених з'єднань слухаючого сокета TCP (`listen(fd, backlog)`). |
| `net.ipv4.ip_forward` | `/proc/sys/net/ipv4/ip_forward` | boolean | `0` або `1` | Дозвіл ядру маршрутизувати транзитні IP-пакети між різними мережевими інтерфейсами. |
| `net.ipv4.tcp_syncookies` | `/proc/sys/net/ipv4/tcp_syncookies` | integer | `0`, `1`, `2` | Захист від атак SYN-flood за допомогою криптографічних SYN-кукі без виділення пам'яті в ядрі. |
| `net.ipv4.tcp_max_syn_backlog` | `/proc/sys/net/ipv4/tcp_max_syn_backlog` | uint32 | 1..65535+ | Максимальна кількість напіввідкритих з'єднань (SYN-пакетів) у черзі очікування. |
| `vm.swappiness` | `/proc/sys/vm/swappiness` | integer | 0..200 | Співвідношення агресивності витіснення анонімних сторінок пам'яті в swap до скидання сторінкового кешу файлів. |
| `vm.overcommit_memory` | `/proc/sys/vm/overcommit_memory` | integer | `0`, `1`, `2` | Режим оверкоміту пам'яті: `0` — евристичний оверкоміт, `1` — завжди виділяти віртуальну пам'ять, `2` — суворе обмеження за `CommitLimit`. |
| `vm.dirty_ratio` | `/proc/sys/vm/dirty_ratio` | percentage | 1..100 | Відсоток системної пам'яті, зайнятої брудними сторінками, при досягненні якого процес примусово блокується на час скидання даних на диск. |
| `kernel.panic` | `/proc/sys/kernel/panic` | integer | Секунди | Кількість секунд затримки перед автоматичним перезавантаженням після паніки ядра (0 — зупинити систему назавжди). |
| `kernel.pid_max` | `/proc/sys/kernel/pid_max` | uint32 | До 4194304 | Максимальне значення ідентифікатора процесу, після якого лічильник PID обнуляється. |

## 4. Топологія та специфікація вузлів /sys (sysfs)

Файлова система `sysfs` відображає ієрархію внутрішніх об'єктів ядра `struct kobject` та дотримується правила: **один файл — один атомарний атрибут**.

### 4.1. Мережева статистика: /sys/class/net/[iface]/statistics/

На відміну від комбінованого файлу `/proc/net/dev`, каталог `/sys/class/net/<iface>/statistics/` містить окремі файли для кожного 64-бітного лічильника мережевого драйвера. На 32-бітних ядрах ці лічильники позбавлені ризику переповнення 32-бітних слів.

- `rx_bytes`, `tx_bytes`: загальна кількість прийнятих та переданих корисних байтів на канальному рівні;
- `rx_packets`, `tx_packets`: кількість успішно переданих та прийнятих Ethernet-кадрів;
- `rx_errors`, `tx_errors`: загальна кількість помилок прийому та передачі;
- `rx_dropped`, `tx_dropped`: пакети, відкинуті ядром або драйвером через дефіцит системних буферів сокетів (`netdev_max_backlog`);
- `rx_fifo_errors`, `tx_fifo_errors`: апаратне переповнення кільцевого FIFO-буфера мережевого адаптера (Ring Buffer overrun);
- `rx_crc_errors`: кадри, відкинуті мережевою картою через помилку контрольної суми CRC;
- `rx_frame_errors`: кадри з порушенням вирівнювання або некоректною довжиною преамбули;
- `rx_missed_errors`: кадри, пропущені адаптером через брак внутрішніх дескрипторів прийому;
- `tx_carrier_errors`: помилки втрати несучої частоти або фізичного розриву кабелю під час передачі;
- `tx_collisions`, `collisions`: кількість колізій у напівдуплексних мережах.

### 4.2. Топологія та керування процесорами: /sys/devices/system/cpu/

- **Стан та класифікація ядер**:
  - `/sys/devices/system/cpu/online`: список активних ядер процесора (наприклад, `0-7`);
  - `/sys/devices/system/cpu/offline`: вимкнені ядра (наприклад, через CPU Hotplug);
  - `/sys/devices/system/cpu/isolated`: ядра, виключені із загального планувальника завдань (задаються параметром ядра `isolcpus=...` для задач реального часу);
  - `/sys/devices/system/cpu/present`: фізично присутні ядра в процесорних сокетах;
  - `/sys/devices/system/cpu/possible`: максимальна кількість ядер, яку ядро підтримує для гарячого підключення.
- **Топологія ядра `/sys/devices/system/cpu/cpu[N]/topology/`**:
  - `core_id`: числовий ідентифікатор фізичного ядра;
  - `physical_package_id`: числовий ідентифікатор фізичного сокета процесора на материнській платі;
  - `thread_siblings_list`: список логічних процесорів Hyper-Threading, що ділять одне фізичне ядро (наприклад, `0,4`);
  - `core_cpus_list`: список логічних ядер, розташованих на одному кристалі / NUMA-вузлі.
- **Керування тактовою частотою `/sys/devices/system/cpu/cpu[N]/cpufreq/`**:
  - `scaling_governor`: активний алгоритм регулювання частоти (`performance`, `powersave`, `schedutil`, `ondemand`, `conservative`);
  - `scaling_available_governors`: список доступних у ядрі регуляторів частоти;
  - `scaling_cur_freq`: поточна тактова частота ядра в кілогерцах (кГц);
  - `scaling_min_freq` / `scaling_max_freq`: апаратні межі регулювання частоти.
- **Стани енергозбереження `/sys/devices/system/cpu/cpu[N]/cpuidle/state[M]/`**:
  - `name`: назва стану C-State (`C1`, `C2`, `C6`);
  - `desc`: опис механізму зупинки блоків ядра;
  - `time`: сумарний час перебування в цьому стані сну (в мікросекундах);
  - `usage`: кількість входжень ядра в цей стан енергозбереження.
- **Апаратні вразливості `/sys/devices/system/cpu/vulnerabilities/`**:
  - Містить файли стану захисту ядра від атак на базі спекулятивного виконання інструкцій: `meltdown`, `spectre_v1`, `spectre_v2`, `spec_store_bypass`, `l1tf`, `mds`, `retbleed`, `srbds`, `tsx_async_abort`, `gather_data_sampling`, `itlb_multihit`, `mmio_stale_data`. Кожен файл містить вердикт: `Not affected`, `Mitigation: ...` або `Vulnerable`.

### 4.3. Статистика та планувальники дисків: /sys/block/[dev]/

- **`/sys/block/[dev]/stat`**: містить один рядок зі статистикою блокового введення-виведення для конкретного накопичувача (поля повністю відповідають полям 4–20 файлу `/proc/diskstats`);
- **`/sys/block/[dev]/queue/`**: черга планувальника блокового пристрою:
  - `scheduler`: список доступних алгоритмів планування введення-виведення з виділенням поточного у квадратних дужках: `none [mq-deadline] kyber bfq`;
  - `nr_requests`: глибина черги запитів I/O;
  - `read_ahead_kb`: розмір вікна попереджувального читання (Read-Ahead) у кілобайтах;
  - `rotational`: тип носія: `0` для твердотільних накопичувачів (SSD, NVMe), `1` для механічних обертових дисків (HDD);
  - `rq_affinity`: прив'язка обробки переривань завершення I/O до ядра CPU, що ініціювало запит (`1` — м'яка прив'язка, `2` — суворе виконання на тому ж ядрі).

### 4.4. Діагностика ядра: /sys/kernel/debug/ (debugfs)

Монтується за шляхом `/sys/kernel/debug/` з правами доступу `0700` (`root`). **Не має стабільного ABI**: структури файлів можуть змінюватися між мінорними релізами ядра Linux.

- **`/sys/kernel/debug/tracing/` (підсистема Ftrace)**:
  - `current_tracer`: активний трасувальник (`nop`, `function`, `function_graph`, `blk`, `mmiotrace`);
  - `available_tracers`: перелік трасувальників, зібраних у поточному ядрі;
  - `trace`: текстовий буфер результатів трасування;
  - `trace_pipe`: неперервний блокуючий потік подій трасування (читання вичитує байти з кільцевого буфера);
  - `events/`: ієрархія динамічних статичних точок трасування (Tracepoints) ядра: `events/sched/sched_switch/enable`, `events/net/netif_receive_skb/enable`;
  - `set_ftrace_filter`: фільтр імен функцій ядра для відстеження;
  - `set_ftrace_pid`: фільтр відстеження конкретного PID;
  - `buffer_size_kb`: розмір кільцевого буфера Ftrace на кожне ядро CPU.
- **`/sys/kernel/debug/kprobes/`**:
  - `list`: список усіх динамічно встановлених зондів kprobes/kretprobes у пам'яті ядра;
  - `enabled`: глобальний вимикач виконання коду зондів (`0` або `1`).
- **`/sys/kernel/debug/fault_injection/`**: інтерфейс симуляції апаратних збоїв та відмов виділення пам'яті ядра (`fail_page_alloc`, `fail_futex`, `fail_make_request`).

### 4.5. Контрольні групи ресурсів: /sys/fs/cgroup/ (cgroups v2)

У сучасних дистрибутивах Linux підсистема контрольних груп змонтована за схемою **уніфікованої ієрархії cgroups v2** (єдине дерево ресурсів замість розрізнених каталогів cgroups v1).

#### Базові керівні файли каталогу cgroup:
- `cgroup.controllers`: перелік контролерів, доступних у цій cgroup (`cpu memory io pids rdma cpuset`);
- `cgroup.subtree_control`: контролери, активовані для безпосередніх дочірніх груп (запис `+cpu +memory -io` активує/деактивує підсистеми);
- `cgroup.procs`: список PID процесів, що належать цій групі (запис PID у цей файл переміщує процес у відповідну cgroup);
- `cgroup.threads`: список TID окремих потоків;
- `cgroup.events`: атрибути життєвого циклу: `populated` (1, якщо є живі процеси) та `frozen` (1, якщо процеси заморожені);
- `cgroup.freeze`: запис `1` атомарно заморожує виконання всіх процесів cgroup без надсилання сигналів, `0` — розморожує;
- `cgroup.kill` (доступний починаючи з Linux 5.14): запис `1` атомарно відправляє сигнал `SIGKILL` усім процесам групи, унеможливлюючи витоки процесів під час завершення контейнерів.

#### Специфікація контролерів ресурсів cgroups v2:

| Контролер | Файл у cgroup | Формат / Одиниці | Призначення |
|---|---|---|---|
| **Memory** | `memory.current` | Байти | Поточне сумарне використання пам'яті групою (анонімна пам'ять + кеш + пам'ять ядра). |
| **Memory** | `memory.min` | Байти | Жорстко гарантований захист: ядро ніколи не відбирає цю пам'ять навіть при глобальному дефіциті RAM. |
| **Memory** | `memory.low` | Байти | М'який захист: пам'ять вивільняється лише у випадку, коли пам'ять не вдалося отримати з незахищених груп. |
| **Memory** | `memory.high` | Байти | Поріг тротлінгу: при перевищенні процеси групи примусово уповільнюються, а ядро асинхронно скидає кеш. |
| **Memory** | `memory.max` | Байти | Абсолютний жорсткий ліміт пам'яті. Перевищення ліміту запускає синхронний OOM-killer для групи. |
| **Memory** | `memory.swap.current` | Байти | Поточний обсяг використаного swap-простору процесами групи. |
| **Memory** | `memory.swap.max` | Байти | Жорсткий ліміт на розмір swap-простору для групи. |
| **Memory** | `memory.events` | Текстові пари | Лічильники аварійних подій: `low`, `high`, `max`, `oom`, `oom_kill`, `oom_group_kill`. |
| **CPU** | `cpu.max` | `QUOTA PERIOD` | Ліміт квоти CPU у мікросекундах. Наприклад, `200000 100000` виділяє рівно 2 ядра CPU (200 мс на період 100 мс). Значення `max 100000` вимикає обмеження. |
| **CPU** | `cpu.weight` | Число (1..10000) | Пропорційна частка процесорного часу при дефіциті CPU (за замовчуванням `100`). |
| **CPU** | `cpu.stat` | Мікросекунди | Телеметрія CPU: `usage_usec` (загальний час), `user_usec`, `system_usec`, `nr_periods` (кількість минулих періодів), `nr_throttled` (кількість обмежень), `throttled_usec` (час примусового тротлінгу). |
| **IO** | `io.weight` | Число (1..10000) | Пропорційна вага доступу до блокового введення-виведення. |
| **IO** | `io.max` | `MAJ:MIN rbps=N wbps=N riops=N wiops=N` | Суворе обмеження пропускної здатності (байт/с) та кількості операцій (IOPS) для конкретного блокового пристрою. |
| **IO** | `io.stat` | Байти та операції | Статистика виконаних операцій читання/запису/скидання по кожному пристрою. |
| **PIDs** | `pids.current` | Число | Поточна сумарна кількість процесів і потоків у цій cgroup. |
| **PIDs** | `pids.max` | Число або `max` | Максимально дозволена кількість процесів і потоків у групі (захист від fork-бомб). |

## 5. Пріоритети конфігураційних каталогів systemd

Системний менеджер `systemd` завантажує unit-файли, правила монтування та конфігурації відповідно до суворої трирівневої ієрархії:

```
[1. Найвищий пріоритет]  /etc/systemd/system/       — Локальні налаштування адміністратора хоста.
[2. Середній пріоритет]  /run/systemd/system/       — Динамічно синтезовані юніти генераторів у RAM.
[3. Найнижчий пріоритет] /usr/lib/systemd/system/   — Стандартні пакункові файли постачальника ОС.
```

- Якщо однойменний файл юніта присутній у кількох каталогах, версія з вищим пріоритетом повністю заміщує версії з нижчих каталогів;
- **Точкові доповнення (Drop-in Overrides)**: каталог `/etc/systemd/system/<unit>.d/*.conf` дозволяє перевизначити окремі параметри без клонування всього юніта. Директиви застосовуються поверх базового опису після виклику `systemctl daemon-reload`;
- **Повне блокування (Masking)**: створення символьного посилання на псевдопристрій `/dev/null` у каталозі `/etc/systemd/system/<unit>` робить запуск сервісу неможливим навіть за явною залежністю інших служб:
  ```sh
  $ ln -s /dev/null /etc/systemd/system/unwanted.service
  $ systemctl daemon-reload
  ```

## 6. Метадані структурованого журналу systemd-journald

Підсистема `systemd-journald` зберігає повідомлення як набір бінарно індексованих пар «КЛЮЧ=ЗНАЧЕННЯ». Поля, що починаються із символу підкреслення (`_`), заповнюються **самим ядром** під час прийому повідомлення через системний виклик `getsockopt(..., SO_PEERCRED)` і захищені від підробки прикладним кодом.

| Поле журналу | Тип значення | Джерело походження | Опис та семантика |
|---|---|---|---|
| `MESSAGE` | Рядок UTF-8 або бінарні дані | Застосунок | Тіло повідомлення логу (передане через API або виведене в `stdout`/`stderr`). |
| `PRIORITY` | Число (0..7) | Застосунок / Syslog | Рівень важливості: `0` (emerg), `1` (alert), `2` (crit), `3` (err), `4` (warning), `5` (notice), `6` (info), `7` (debug). |
| `_PID` | Число (PID) | Ядро Linux | Дійсний ідентифікатор процесу-відправника. |
| `_UID` | Число (UID) | Ядро Linux | Реальний ідентифікатор користувача процесу. |
| `_GID` | Число (GID) | Ядро Linux | Реальний ідентифікатор групи користувача. |
| `_COMM` | Рядок (до 16 байтів) | Ядро Linux | Системна назва команди процесу з `task_struct->comm`. |
| `_EXE` | Абсолютний шлях | Ядро Linux | Канонічний шлях до виконуваного бінарного файлу на диску (через `/proc/<PID>/exe`). |
| `_CMDLINE` | Текстовий рядок | Ядро Linux | Повний рядок аргументів запуску процесу з `/proc/<PID>/cmdline`. |
| `_SYSTEMD_UNIT` | Текстовий рядок | systemd | Назва системного сервісу (наприклад, `nginx.service`), до cgroup якого належить процес. |
| `_SYSTEMD_CGROUP` | Шлях cgroup | systemd | Повний шлях контрольної групи процесу у файловій системі `cgroupfs`. |
| `_SELINUX_CONTEXT` | Текстовий рядок | Ядро Linux | Контекст безпеки SELinux/AppArmor процесу на момент відправки. |
| `_BOOT_ID` | 128-бітний UUID | Ядро Linux | Унікальний ідентифікатор завантаження ОС (з `/proc/sys/kernel/random/boot_id`). |
| `_MACHINE_ID` | 128-бітний Hex | `/etc/machine-id` | Постійний ідентифікатор хоста. |
| `_HOSTNAME` | Текстовий рядок | Ядро Linux | Мережеве ім'я хоста на момент генерації запису. |
| `_TRANSPORT` | Текстовий перелік | journald | Механізм доставки: `driver` (внутрішній), `syslog` (сокет `/dev/log`), `journal` (нативний сокет `/run/systemd/journal/socket`), `stdout` (перехоплення потоку виводу сервісу), `kernel` (з `/dev/kmsg`). |

### Криптографічна верифікація журналів (Forward Secure Sealing)

Механізм FSS на базі алгоритму FSP (Forward Secure Pseudorandom Generator) ділить журнал на часові епохи (за замовчуванням 15 хвилин). Кожна епоха опечатується новим ключем, після чого ключ безповоротно знищується з RAM. Спроба зловмисника з правами `root` модифікувати записи минулих епох призводить до порушення криптографічного ланцюжка:

```sh
# Перевірка цілісності бінарних журналів за допомогою публічного ключа верифікації
$ journalctl --verify --verify-key=xxxx-xxxx-xxxx-xxxx/xxxx-xxxx
```

## 7. Довідник діагностичних утиліт низькорівневого аналізу

Діагностичні утиліти транслюють неструктуровані таблиці VFS у точний стан системи. Нижче наведено специфікацію параметрів, прапорців оптимізації та синтаксису викликів трьох ключових інструментів інспекції.

### 7.1. Утиліта lsof (List Open Files)

Утиліта `lsof` сканує структури `/proc/[pid]/fd`, `/proc/[pid]/maps` та мережеві таблиці для відображення відкритих файлів, сокетів, бібліотек та каталогів.

#### Специфікація параметрів вибірки:
- `-p <PID1,PID2,...>`: вибірка дескрипторів конкретних процесів. Підтримує заперечення через символ `^` (наприклад, `-p ^1` виключає PID 1);
- `-u <user1,user2,...>`: вибірка за ім'ям або числовим UID власника процесу. Підтримує виключення: `-u ^root`;
- `-i [46][proto][@hostname|hostaddr][:service|port]`: вибірка сокетів мережі IPv4/IPv6:
  - `-i :80` — усі з'єднання на порту 80 (TCP та UDP);
  - `-i tcp@127.0.0.1:5432` — локальні з'єднання TCP на порт PostgreSQL;
  - `-i 4tcp` — виключно протокол IPv4 TCP;
  - `-i 6udp` — виключно протокол IPv6 UDP;
- `-a`: логічний оператор **AND** (І) для об'єднання умов. За замовчуванням кілька прапорців вибірки об'єднуються як **OR** (АБО). Наприклад, `lsof -u www-data -i :443 -a` вибирає лише сокети порту 443, що належать користувачу `www-data`;
- `+D <directory>`: рекурсивний пошук процесів, що утримують відкриті файли всередині дерева каталогів;
- `+d <directory>`: нерекурсивний пошук відкритих файлів у конкретному каталозі;
- `-c <command_prefix>`: фільтрація за назвою команди процесу (або регулярним виразом `lsof -c /^nginx/`);
- `-t`: «тихий» тернарний режим (Terse Output) — друкує лише числові PID без заголовків і деталей (ідеально для конвеєрів: `kill -9 $(lsof -t -i :8080)`).

#### Прапорці оптимізації та усунення блокувань:
- **`-n`**: категорично забороняє перетворення IP-адрес на доменні імена (вимкнення зворотного DNS-резолвінгу). **Обов'язковий прапорець під час розслідування інцидентів**: при недоступності DNS-сервера `lsof` без `-n` зависає на десятки секунд на кожному сокеті;
- **`-P`**: забороняє трансляцію номерів портів у назви служб із `/etc/services` (виводить порт як число `8080` замість псевдоімені).

#### Машиночитаний режим виводу для парсерів (-F):
Прапорець `-F [<fields>]` перемикає `lsof` у детермінований формат виводу, призначений для скриптів автоматизації. Кожен рядок починається з однобуквеного ідентифікатора поля:

| Символ | Поле | Опис |
|---|---|---|
| `p` | PID | Ідентифікатор процесу. Починає новий блок процесу. |
| `g` | PGID | Ідентифікатор групи процесів. |
| `u` | UID | Числовий ідентифікатор користувача. |
| `c` | Command | Ім'я виконуваної команди. |
| `f` | FD | Номер дескриптора або тип: `cwd`, `rtd` (root), `txt` (код), `mem` (mmap), `DEL` (видалений). |
| `t` | Type | Тип файлу: `REG`, `DIR`, `CHR`, `FIFO`, `unix`, `IPv4`, `IPv6`. |
| `D` | Device | Старший та молодший номери пристрою. |
| `s` | Size | Розмір файлу в байтах. |
| `i` | Inode | Номер inode файлу. |
| `n` | Name | Назва файлу, шлях, сокет (`127.0.0.1:80->127.0.0.1:41234`). |
| `T` | TCP/TPI Info | Стан TCP-з'єднання: `TST=LISTEN`, `TST=ESTABLISHED`, `QR=...`, `QS=...`. |

Прапорець `-0` перемикає розділювач полів з нового рядка `\n` на нульовий байт `\0`, що дозволяє коректно розбирати імена файлів із символами перенесення рядків.

```sh
# Збір структурованих даних PID, FD, типу та імені відкритих сокетів
$ lsof -n -P -i TCP -F pcfnt
```

### 7.2. Утиліта fuser (Find processes using files or sockets)

Утиліта `fuser` визначає ідентифікатори процесів, які утримують конкретні файли, відкриті сокети або змонтовані файлові системи, та дозволяє надсилати їм сигнали.

#### Специфікація параметрів:
- **`-m <path|device>`** (або `-c`): вибирає всі процеси, які використовують будь-які файли на тій самій змонтованій файловій системі або блоковому пристрої, що й зазначений шлях. Критично важливий під час діагностики помилки `umount: target is busy`;
- **`-k`**: відправляє сигнал завершення усім знайденим процесам. За замовчуванням надсилається сигнал `SIGKILL` (`-9`);
- **`-<SIGNAL>`**: перевизначає сигнал для прапорця `-k` за назвою або номером: `fuser -k -TERM -m /mnt/storage` або `fuser -k -HUP /var/run/nginx.pid`;
- **`-v`**: докладний табличний режим (Verbose). Виводить колонки `USER`, `PID`, `ACCESS`, `COMMAND`;
- **`-s`**: абсолютно тихий режим (Silent). Нічого не виводить у потік; повертає код завершення `0`, якщо знайдено хоча б один процес, і ненульовий код, якщо ресурс вільний (використовується в shell-скриптах перевірки готовності);
- **`-u`**: додає ім'я власника процесу в круглих дужках після кожного виведеного PID;
- **`-n <namespace> <name>`**: вибір простору імен ресурсів:
  - `file` (за замовчуванням): файловий шлях;
  - `tcp`: локальний або віддалений TCP-порт (`fuser -v -n tcp 80`);
  - `udp`: сокет UDP (`fuser -v -n udp 53`).

#### Таблиця однобуквених кодів доступу (ACCESS):

| Символ коду | Назва режиму | Семантика утримання ресурсу |
|---|---|---|
| `c` | Current directory | Каталог є поточним робочим каталогом процесу (`cwd`). |
| `e` | Executable | Файл є виконуваним бінарником, який запущено на виконання. |
| `f` | Open file | Файл відкрито на читання або запис (у стандартному виводі без `-v` цей символ опускається). |
| `F` | Open for writing | Файл відкрито в режимі запису. |
| `r` | Root directory | Каталог є кореневим каталогом процесу (`chroot` / `pivot_root`). |
| `m` | Mmap / Library | Файл замаповано у віртуальну пам'ять як динамічну бібліотеку `.so` або файл даних (`mmap`). |
| `t` | Traced | Процес зупинено або трасується іншою програмою (`ptrace`). |
| `x` | Executable text | Завантажений виконуваний сегмент коду спільної бібліотеки. |

### 7.3. Утиліта ss (Socket Statistics)

Утиліта `ss` є сучасним високоефективним інструментом діагностики мережевих сокетів із пакету `iproute2`. Вона вилучає дані безпосередньо з ядра через протокол **Netlink** (`sock_diag`), що унеможливлює зависання системи при десятках тисяч активних з'єднань (на відміну від застарілої утиліти `netstat`, яка лінійно парсила текстовий `/proc/net/tcp`).

#### Базові прапорці режимів та протоколів:
- `-t`: фільтрація сокетів TCP;
- `-u`: фільтрація сокетів UDP;
- `-x`: фільтрація локальних Unix domain сокетів (`AF_UNIX`);
- `-w`: фільтрація необроблених сокетів (`RAW`);
- `-l`: відображення **виключно слухаючих сокетів** (Listening sockets у стані `TCP_LISTEN`). За замовчуванням `ss` показує лише встановлені з'єднання;
- `-a`: відображення **всіх сокетів** (як слухаючих, так і клієнтських з'єднань);
- `-n`: вимкнення резолвінгу IP-адрес у хости та номерів портів у назви служб (числовий вивід);
- `-p`: відображення процесу, потоку та номера файлового дескриптора, що утримує сокет: `users:(("nginx",pid=1234,fd=6))`. Вимагає прав `root` або привілею `CAP_NET_ADMIN` для перегляду процесів інших користувачів;
- `-e`: відображення розширених метаданих сокета: числовий UID власника, номер `inode` сокета та внутрішній `cookie` ядра;
- `-i`: вивід внутрішніх метрик продуктивності TCP зі структури ядра `struct tcp_info`: час кругового обігу (`rtt`), дисперсія (`rttvar`), розмір вікна перевантаження (`cwnd`), поріг повільного старту (`ssthresh`), ефективна швидкість передачі (`delivery_rate`) та кількість повторних передач (`retrans`);
- `-m`: вивід виділеної оперативної пам'яті під сокетні буфери ядра: `rmem_alloc`, `rcv_buf`, `wmem_alloc`, `snd_buf`, `fwd_alloc`, `wmem_queued`;
- **`-K`**: примусове аварійне закриття активного TCP-з'єднання з простору користувача через операцію ядра Netlink `SOCK_DESTROY` (вимагає привілею `CAP_NET_ADMIN`);
- `-s`: зведений звіт за всіма типами сокетів із `/proc/net/sockstat`.

#### Синтаксис фільтрів станів TCP:
Формат запису: `state <STATE-NAME>` або `exclude <STATE-NAME>`.

- Стандартні стани: `established`, `syn-sent`, `syn-recv`, `fin-wait-1`, `fin-wait-2`, `time-wait`, `closed`, `close-wait`, `last-ack`, `listening`, `closing`;
- Псевдостани-макроси:
  - `all`: усі можливі стани сокетів;
  - `connected`: усі стани, крім `listening` та `closed`;
  - `synchronized`: усі `connected` стани, крім `syn-sent`;
  - `bucket`: сокети в станах `time-wait` та `syn-recv`.

```sh
# Пошук усіх TCP-з'єднань у стані TIME_WAIT або SYN_SENT
$ ss -t state time-wait or state syn-sent
```

#### Синтаксис предикатів вибірки адрес, портів та CIDR:
Вирази фільтрації задаються в кінці команди.

Оператори порівняння: `==` (або `=`), `!=`, `<`, `<=`, `>`, `>=`.
Поля вибірки: `sport` (source port / локальний порт), `dport` (destination port / віддалений порт), `src` (source IP / підмережа), `dst` (destination IP / підмережа).

```sh
# Фільтрація з'єднань із локального HTTP/HTTPS порту
$ ss -t -a 'sport = :http or sport = :https'

# Фільтрація віддалених з'єднань на конкретну підмережу із портом вище 1024
$ ss -t '( dst 192.168.1.0/24 and dport >= :1024 )'

# Пошук процесів, які слухають сокети на локальній петлі 127.0.0.1
$ ss -t -l -n -p 'src 127.0.0.1'

# Перегляд TCP-з'єднань із детальною діагностикою втрат пакетів та RTT
$ ss -t -i -e 'state established and dport = :443'
```
