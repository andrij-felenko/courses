# Довідник керуючих викликів VT та режимів клавіатури

Інтерфейс керування віртуальними консолями та шаром TTY у ядрі Linux реалізовано через системний виклик `ioctl` (англ. *input/output control*). Цей довідник описує структури даних, числові константи, механізми обробки запитів, вимоги до привілеїв процесу та поведінку крайових випадків для підсистем `drivers/tty/vt/`, `drivers/tty/n_tty.c` та `drivers/tty/tty_io.c`. Заголовні файли ядра, що визначають ці контракти: `<linux/vt.h>`, `<linux/kd.h>`, `<linux/tty.h>` та `<sys/ioctl.h>`.

## Керування режимами клавіатури консолі

Керуючі виклики клавіатури дозволяють перемикати спосіб інтерпретації апаратних подій клавіш драйвером `keyboard.c`. Для виконання модифікуючих операцій процес повинен мати дескриптор відкритого термінала консолі (`/dev/tty`, `/dev/tty0` або `/dev/ttyN`). Коли графічний сервер або спеціалізована програма перехоплює введення, вона зобов'язана змінити стан обробника клавіатури в ядрі, щоб уникнути конфліктів між друком символів у термінал та обробкою подій графічного інтерфейсу.

| Код ioctl | Аргумент | Опис | Необхідні права |
| :--- | :--- | :--- | :--- |
| `KDGKBMODE` | `long *mode` | Зчитує поточний режим клавіатури активної консолі | Читання TTY |
| `KDSKBMODE` | `long mode` | Встановлює новий режим трансляції клавіатури | Запис TTY / root |
| `KDGETMODE` | `int *mode` | Отримує режим відображення (`KD_TEXT` або `KD_GRAPHICS`) | Читання TTY |
| `KDSETMODE` | `int mode` | Перемикає консоль у графічний або текстовий режим | Запис TTY / root |
| `KDGETLED` | `char *leds` | Зчитує стан світлодіодів клавіатури (Caps/Num/Scroll) | Читання TTY |
| `KDSETLED` | `long leds` | Примусово встановлює стан світлодіодів клавіатури | Запис TTY |
| `KDMKTONE` | `long tone` | Генерує звуковий сигнал динаміка (довжина й частота) | Запис TTY |
| `KDGKBENT` | `struct kbentry *` | Зчитує запис таблиці розкладки за кодом і модифікатором | Читання TTY |
| `KDSKBENT` | `struct kbentry *` | Модифікує запис у таблиці розкладки клавіатури | `CAP_SYS_ADMIN` |

### Режими трансляції клавіатури (`KDSKBMODE`)

Константи режимів передаються як цілочисельне значення типу `long` безпосередньо третім аргументом системного виклику `ioctl`. Кожен режим кардинально змінює шлях, яким апаратні коди клавіш (англ. *scancodes*) перетворюються всередині ядра:

- `K_RAW` (`0x00`): драйвер віртуальної консолі генерує сирі сканкоди стандарту XT (Set 1). На кожне натискання клавіші видається один байт у діапазоні `0x01..0x7F`. Відпускання клавіші кодується встановленням старшого сьомого біта: значенням стає `код | 0x80`. Для розширених клавіш (наприклад, стрілок курсора або правого Ctrl) ядро генерує префіксний байт `0xE0`, за яким слідує байт коду. Цей режим використовувався ранніми версіями сервера X11 до появи підсистеми `evdev`.
- `K_XLATE` (`0x01`): стандартний текстовий режим. Коди клавіш проходять через таблиці трансляції розкладки ядра (`key_maps`), враховують поточний стан модифікаторів (Shift, Ctrl, Alt, AltGr, CapsLock) і генерують 8-бітні символи кодування ISO-8859-1 (або ASCII). Функціональні клавіші транслюються в керуючі послідовності термінала стандарту VT102.
- `K_MEDIUMRAW` (`0x02`): режим проміжних сканкодів. Для клавіш із кодами від 0 до 127 ядро видає 1 байт (зі старшим бітом як ознакою відпускання). Для клавіш із розширеними кодами від 128 до 255 ядро транслює подію у два байти: перший байт містить маску `0x80 | (код >> 7)`, а другий — `код & 0x7F`. Це дозволило позбутися апаратних відмінностей між контролерами клавіатур без повної прив'язки до архітектури PC.
- `K_UNICODE` (`0x03`): розширений Unicode-режим. Таблиця розкладки повертає 16-бітні кодові точки UCS-2, які обробник `keyboard.c` автоматично транслює в потік байтів кодування UTF-8 (від 1 до 4 байтів на символ) і передає в буферну чергу TTY.
- `K_OFF` (`0x04`): режим повного вимкнення трансляції. Підсистема віртуальної консолі скидає та ігнорує всі події клавіатури, не генеруючи жодних байтів у чергу TTY. Сучасні композитори Wayland (Sway, Weston, GNOME Mutter) та сервери Xorg встановлюють цей режим, отримуючи події вводу напряму через вузли `/dev/input/event*` за допомогою бібліотеки `libinput`.

### Структура елемента розкладки `struct kbentry`

Для модифікації та зчитування внутрішньої таблиці трансляції розкладки ядра використовується структура `kbentry`. Вона дозволяє призначати довільну дію (символ, функціональну дію чи перемикач) для комбінації клавіші та модифікатора:

```c
struct kbentry {
    unsigned char kb_table; /* індекс таблиці модифікаторів (0..15: Plain, Shift, AltGr, Control...) */
    unsigned char kb_index; /* номер клавіші / сканкод (0..127) */
    unsigned short kb_value;/* призначена дія (код символу Unicode, функціональна дія K_F1..K_F20) */
};
```

Поле `kb_table` вказує стан клавіш-модифікаторів як бітову маску (наприклад, 0 — базовий стан без модифікаторів, 1 — натиснуто Shift, 2 — AltGr, 4 — Control, 8 — Alt). Поле `kb_value` кодує або числовий код символу, або спеціальний внутрішній макрос дії ядра (наприклад, `K_ENTER`, `K_CAPS`, `K_DOWN`, `K_F1` або комбінацію перемикання консолей `K_CONS`).

## Керування віртуальними терміналами (VT)

Виклики групи `VT_*` керують життєвим циклом, виділенням пам'яті, деактивацією, зміною розміру та кооперативним перемиканням активних екранів віртуальних терміналів у файлі `drivers/tty/vt/vt_ioctl.c`.

| Код ioctl | Тип аргументу | Призначення | Помилки |
| :--- | :--- | :--- | :--- |
| `VT_OPENQRY` | `int *vt_num` | Повертає номер першої вільної невідкритої віртуальної консолі | `EINVAL`, `EPERM` |
| `VT_GETMODE` | `struct vt_mode *` | Зчитує структуру конфігурації режиму перемикання VT | `EFAULT`, `EINVAL` |
| `VT_SETMODE` | `struct vt_mode *` | Встановлює автоматичний (`VT_AUTO`) або узгоджений (`VT_PROCESS`) режим | `EPERM`, `EINVAL` |
| `VT_ACTIVATE` | `int vt_num` | Ініціює перемикання на консоль з номером `vt_num` (1..63) | `ENXIO`, `EINVAL` |
| `VT_WAITACTIVE` | `int vt_num` | Блокує викликаючий потік до завершення перемикання на `vt_num` | `EINTR`, `ENXIO` |
| `VT_RELDISP` | `long ack` | Підтвердження готовності процесу до зміни VT (`1`, `0` або `VT_ACKACQ`) | `EINVAL`, `EPERM` |
| `VT_GETSTATE` | `struct vt_stat *` | Повертає маску відкритих консолей та номер активної VT | `EFAULT` |
| `VT_DISALLOCATE` | `int vt_num` | Звільняє виділену пам'ять консолі `vt_num` (або всіх, якщо `0`) | `EBUSY`, `EINVAL` |
| `VT_RESIZEX` | `struct vt_consize *` | Змінює екранну геометрію та розміри символьних шрифтів | `EINVAL`, `EPERM` |

### Структура `struct vt_mode` та протокол `VT_PROCESS`

Структура `vt_mode` описує контракт взаємодії між ядром та дисплейним сервером для плавного перемикання відеоадаптера між графічними та текстовими сесіями:

```c
struct vt_mode {
    char mode;    /* режим перемикання: VT_AUTO (автоматично) або VT_PROCESS (узгоджено) */
    char waitv;   /* прапорець очікування завершення записів перед перемиканням */
    short relsig; /* сигнал ядру надіслати процесу перед віддачею консолі (наприклад, SIGUSR1) */
    short acqsig; /* сигнал ядру надіслати процесу після повернення консолі (наприклад, SIGUSR2) */
    short frsig;  /* зарезервовано (має дорівнювати 0) */
};
```

Поведінка режимів перемикання:
1. `VT_AUTO` (`0x00`): ядро виконує перемикання самостійно й негайно. Щойно надходить запит на перемикання (через гарячу комбінацію клавіш або виклик `VT_ACTIVATE`), ядро негайно перепризначає покажчики активної консолі, копіює відеопам'ять і перемикає курсор. Цей режим застосовується для стандартних текстових консолей, але непридатний для графічних оболонок, оскільки ядро не знає, як скинути стан GPU.
2. `VT_PROCESS` (`0x01`): узгоджений режим. Ядро блокує безпосередню зміну відеопам'яті й надсилає процесу-власнику сигнал `relsig` (зазвичай `SIGUSR1`). Процес перехоплює сигнал, зупиняє конвеєр малювання, віддає права головного пристрою DRM (`drmDropMaster()`), вимикає сканування пристроїв введення й викликає `ioctl(vt_fd, VT_RELDISP, 1)` для підтвердження. Тільки після цього ядро завершує перемикання на нову консоль.
3. При зворотному перемиканні на графічну консоль ядро активує її в пам'яті й надсилає процесу сигнал `acqsig` (зазвичай `SIGUSR2`). Графічний сервер захоплює статус `drmSetMaster()`, відновлює віртуальні площини, перемальовує кадр і підтверджує готовність викликом `ioctl(vt_fd, VT_RELDISP, VT_ACKACQ)`.

### Структура `struct vt_stat`

Повертає загальну діагностичну інформацію про активні віртуальні термінали в системі:

```c
struct vt_stat {
    unsigned short v_active; /* номер поточної активної віртуальної консолі (1..63) */
    unsigned short v_signal; /* невикористане поле статусу сигналу */
    unsigned short v_state;  /* бітова маска відкритих віртуальних консолей (біти 1..15) */
};
```

Значення бітів у полі `v_state` відповідають номерам відкритих віртуальних консолей: якщо біт `N` дорівнює одиниці, консоль `/dev/ttyN` наразі створена та утримується щонайменше одним процесом у системі.

## Керування лінійною дисципліною та параметрами TTY

Для конфігурації шару лінійної дисципліни, розмірів вікна та термінальних параметрів застосовуються стандартні керуючі виклики підсистеми TTY:

| Код ioctl | Аргумент | Опис |
| :--- | :--- | :--- |
| `TIOCGETD` | `int *ldisc` | Отримує числовий номер поточної лінійної дисципліни |
| `TIOCSETD` | `int *ldisc` | Змінює лінійну дисципліну термінала (`N_TTY`, `N_PPP` тощо) |
| `TCGETS2` | `struct termios2 *` | Зчитує розширену структуру termios (підтримка довільних baud) |
| `TCSETS2` | `struct termios2 *` | Застосовує нову конфігурацію termios2 негайно |
| `TCSETSW2` | `struct termios2 *` | Застосовує termios2 після спустошення черги виводу |
| `TCSETSF2` | `struct termios2 *` | Застосовує termios2 після очищення черг вводу й виводу |
| `TIOCGWINSZ` | `struct winsize *` | Зчитує геометрію вікна (кількість рядків, стовпчиків, пікселів) |
| `TIOCSWINSZ` | `struct winsize *` | Встановлює розмір вікна й генерує сигнал `SIGWINCH` групі TTY |
| `TIOCSCTTY` | `int force` | Робить термінал керуючим для лідера поточної сесії |
| `TIOCNOTTY` | `void` | Від'єднує викликаючий процес від його керуючого термінала |

### Номери стандартних лінійних дисциплін ядра

Лінійна дисципліна встановлюється викликом `ioctl(fd, TIOCSETD, &ldisc_number)` і змінює обробник байтового потоку для дескриптора TTY:

- `N_TTY` (`0`): стандартна термінальна лінійна дисципліна ядра. Реалізує канонічний буфер рядка (4096 байтів), генерацію термінальних сигналів `SIGINT`, `SIGQUIT`, `SIGTSTP`, керування луною (`ECHO`), розкриття символів табуляції та програмне керування потоком (XON/XOFF).
- `N_SLIP` (`1`): протокол кадрування Serial Line Internet Protocol. Перетворює символьний послідовний потік UART у мережевий інтерфейс типу `sl0`.
- `N_MOUSE` (`2`): лінійна дисципліна для зчитування пакетів старовинних послідовних мишей (Serial Mouse).
- `N_PPP` (`3`): протокол Point-to-Point Protocol. Забезпечує інкапсуляцію IP-пакетів, стиснення заголовків та перевірку контрольних сум для комутованих з'єднань.
- `N_STRIP` (`4`): протокол передавання пакетів Starmode Radio IP.
- `N_AX25` (`5`): аматорський пакетний радіопротокол AX.25.
- `N_HDLC` (`13`): високошвидкісне синхронне бітове кадрування HDLC.
- `N_GSM0710` (`21`): протокол мультиплексування GSM 07.10, що дозволяє розбити один фізичний послідовний UART-канал до стільникового модема на кілька віртуальних каналів (одночасне передавання даних, AT-команд та GPS).
- `N_SLCAN` (`25`): драйвер драйвера послідовного інтерфейсу CAN (SocketCAN), що транслює текстові команди послідовного порту в двійкові CAN-фрейми ядра.

## Детальний опис кодів помилок (errno)

При некоректному виклику керуючих команд підсистема TTY та VT повертає значення `-1`, виставляючи глобальну змінну `errno`. Аналіз значення дозволяє визначити точну причину збою операції:

1. `EPERM` (Operation not permitted): виникає при спробі виконати `KDSKBMODE`, `KDSETMODE` або змінити розкладку `KDSKBENT` з процесу, який не є лідером сесії на даному TTY, не володіє активним дескриптором консолі або не має системного привілею `CAP_SYS_ADMIN`.
2. `EBUSY` (Device or resource busy): спроба звільнити пам'ять консолі викликом `ioctl(fd, VT_DISALLOCATE, vt_num)`, коли вказана віртуальна консоль наразі є активною (відображається на дисплеї) або відкрита іншим процесом (наприклад, фоновою службою `agetty`).
3. `EINVAL` (Invalid argument): передано номер віртуальної консолі поза допустимим діапазоном `1..63`, непідтримуваний числовий номер лінійної дисципліни у виклику `TIOCSETD` або неіснуючий код режиму клавіатури у виклику `KDSKBMODE`.
4. `ENXIO` (No such device or address): спроба активувати консоль (`VT_ACTIVATE`), яка не була попередньо виділена в системі або не має зареєстрованого драйвера відображення.
5. `EINTR` (Interrupted system call): системний виклик очікування завершення зміни консолі `VT_WAITACTIVE` перервано доставкою асинхронного сигналу процесу до моменту, коли ядро встигло перемкнути дисплейний буфер.
6. `EFAULT` (Bad address): вказівник на структуру (`struct vt_mode`, `struct vt_stat`, `struct winsize`), переданий у третьому аргументі `ioctl`, посилається на недійсну або недоступну для запису область пам'яті процесу.
