# Довідник керуючих викликів VT та режимів клавіатури

Підсистема віртуальних консолей (англ. *Virtual Terminals*, VT) та драйвер клавіатури ядра Linux надають набір низькорівневих інтерфейсів керування через системний виклик `ioctl` (англ. *input/output control*). Ці інтерфейси зосереджені у двох функціональних підсистемах: підсистемі керування консолями VT (`drivers/tty/vt/vt_ioctl.c`, заголовний файл `<linux/vt.h>`) та підсистемі дисплея й клавіатури KD (англ. *Keyboard/Display*, файли `drivers/tty/vt/keyboard.c`, `drivers/tty/vt/vt.c`, `drivers/tty/vt/consolemap.c`, заголовний файл `<linux/kd.h>`).

Цей довідник визначає числові константи, структури даних, семантику параметрів, взаємодію з системними привілеями (`CAP_SYS_ADMIN`), поведінку граничних випадків, растрові формати шрифтів PSF v1/v2, структури трансляції Юнікоду, палітру VGA DAC та зіставлення стандартних системних утиліт (`chvt`, `openvt`, `deallocvt`, `kbd_mode`, `setleds`, `setvtrgb`, `setfont`, `loadunimap`) із системними викликами ядра.

## Керування віртуальними терміналами (`<linux/vt.h>`)

Керуючі виклики групи `VT_*` регулюють життєвий цикл віртуальних консолей, виділення екранної пам'яті, динамічну зміну розмірів текстового буфера та протокол узгодженого перемикання графічних і текстових сесій.

### Структури даних підсистеми VT

#### Структура `struct vt_mode`

Описує контракт перемикання віртуальної консолі між ядром та дисплейним сервером (Wayland-композитором, Xorg або користувацьким сесійним менеджером):

```c
struct vt_mode {
    char mode;    /* режим перемикання: VT_AUTO, VT_PROCESS або VT_ACKACQ */
    char waitv;   /* блокувати запис у неактивну консоль (якщо ненульове) */
    short relsig; /* сигнал, який ядро надсилає процесу для звільнення дисплея */
    short acqsig; /* сигнал, який ядро надсилає процесу після активації консолі */
    short frsig;  /* зарезервовано для майбутніх розширень (має дорівнювати 0) */
};
```

Значення констант поля `mode`:
- `VT_AUTO` (`0x00`): стандартний автоматичний режим ядра. Перемикання виконується драйвером консолі негайно без участі користувацьких процесів. Застосовується для текстових терміналів.
- `VT_PROCESS` (`0x01`): узгоджений (кооперативний) режим. Ядро призупиняє перемикання дисплея, надсилає сигнал `relsig` процесу-власнику й чекає на підтвердження через `VT_RELDISP`.
- `VT_ACKACQ` (`0x02`): режим підтвердження захоплення. Вимагає від процесу обов'язкового виклику `ioctl(fd, VT_RELDISP, VT_ACKACQ)` після обробки сигналу `acqsig`.

Вимоги та обмеження:
- Поля `relsig` та `acqsig` повинні містити дійсні номери сигналів POSIX (наприклад, `SIGUSR1`, `SIGUSR2`) або `0` (якщо обробка сигналу вимкнена). Передавання недійсного номера сигналу або сигналів, які не можна перехопити (`SIGKILL`, `SIGSTOP`), повертає помилку `EINVAL`.
- Якщо встановлено `waitv != 0`, виклики `write()` у дескриптор консолі, коли вона є фоновою (неактивною), призупиняються до повернення консолі на передній план.

#### Семантика підтвердження `VT_RELDISP`

Системний виклик `ioctl(fd, VT_RELDISP, ack)` приймає третім аргументом ціле число `long`:
- `0` (або `VT_RELNOT`): процес **відхиляє** або скасовує запит на перемикання (наприклад, у критичній секції ініціалізації). Ядро перериває процедуру зміни VT і залишає поточну консоль активною.
- `1`: процес **підтверджує звільнення** дисплея. До виклику процес зобов'язаний скинути статус DRM-майстра (`drmDropMaster()`), вимкнути апаратні сканери введення та перевести графічний конвеєр у фоновий стан. Отримавши `1`, ядро перемикає відеорежим і активує нову VT.
- `VT_ACKACQ` (`2`): процес **підтверджує відновлення** консолі після отримання сигналу `acqsig`. До виклику процес відновлює статус `drmSetMaster()`, регенерує кадровий буфер та відновлює таймери рендерингу.

Виклик `VT_RELDISP` поза контекстом активного перемикання або на консолі, яка не переведена в `VT_PROCESS`, повертає `-1` з кодом помилки `EINVAL`.

#### Структура `struct vt_stat` та виклик `VT_GETSTATE`

Повертає стан та маску розподілу віртуальних консолей:

```c
struct vt_stat {
    unsigned short v_active; /* номер поточної активної віртуальної консолі (1..63) */
    unsigned short v_signal; /* зарезервовано ядром (не використовується) */
    unsigned short v_state;  /* 16-бітна маска відкритих консолей 1..15 */
};
```

Семантика полів та бітової маски:
- `v_active`: цілочисельний номер (1-індексований) віртуальної консолі, яка наразі виведена на фізичний дисплей (`fg_console + 1` у ядрі). Діапазон значень: від `1` до `MAX_NR_CONSOLES` (типово `63`).
- `v_state`: 16-бітна бітова маска активних терміналів. Біт `1 << N` (де `1 <= N <= 15`) дорівнює `1`, якщо віртуальна консоль `/dev/ttyN` виділена підсистемою VT і відкрита хоча б одним користувацьким процесом або системним демоном `getty`/`login`. Біт `0` (`1 << 0`) завжди виставлений в `1` як ознака наявності системної консолі.
- **Обмеження 16-бітної маски:** через історичний формат структури `struct vt_stat`, консолі з номерами від 16 до 63 не можуть бути представлені у полі `v_state`. Проте якщо активною стає консоль з номером ≥ 16, її номер коректно повертається в полі `v_active`.
- `v_signal`: історичне поле, зарезервоване ядром. У сучасних версіях Linux завжди повертає `0`.

Виклик `ioctl(fd, VT_GETSTATE, &stat)` не вимагає привілеїв суперкористувача (`CAP_SYS_ADMIN`) і застосовується системними утилітами (`chvt`, `systemd-logind`, сесійними менеджерами) для моніторингу списку зайнятих консолей та визначення фонового стану сесії.

#### Блокування перемикання консолей: `VT_LOCKSWITCH` та `VT_UNLOCKSWITCH`

Системні виклики `VT_LOCKSWITCH` (`0x560B`) та `VT_UNLOCKSWITCH` (`0x560C`) призначені для глобального блокування будь-якої зміни активної консолі на рівні ядра:

```c
/* Блокування перемикання */
ioctl(tty_fd, VT_LOCKSWITCH, 1);

/* Розблокування перемикання */
ioctl(tty_fd, VT_UNLOCKSWITCH, 1);
```

Механіка роботи в ядрі (`drivers/tty/vt/vt_ioctl.c`):
- Виклик `VT_LOCKSWITCH` встановлює внутрішній атомарний прапорець ядра `vt_dont_switch = 1`.
- При виставленому `vt_dont_switch`:
  1. Драйвер клавіатури (`drivers/tty/vt/keyboard.c`) повністю ігнорує будь-які комбінації апаратного перемикання віртуальних консолей (`Ctrl+Alt+F1`..`Ctrl+Alt+F12`, `Alt+LeftArrow`, `Alt+RightArrow` та дії типу `KT_CONS`). Натискання цих комбінацій не генерує подій зміни активного термінала.
  2. Програмні системні виклики активації інших консолей (`ioctl(fd, VT_ACTIVATE, n)`) негайно завершуються поверненням `-1` з кодом помилки `EBUSY`.
  3. Будь-які запити на звільнення дисплея через механізм `VT_PROCESS` призупиняються до зняття блокування.
- Виклик `VT_UNLOCKSWITCH` скидає прапорець `vt_dont_switch = 0`, відновлюючи стандартну обробку клавіатурних комбінацій та виконання системних викликів `VT_ACTIVATE`.
- **Безпека та застосування:** `VT_LOCKSWITCH` застосовується програмами блокування екрана (екранними блокувальниками `physlock`, `vlock`, `swaylock`), кіоск-системами та безпечними терміналами для запобігання обходу автентифікації шляхом перемикання на сусідні відкриті консолі з активними сесіями користувачів чи правами `root`.
- **Вимоги до привілеїв:** вимагає наявності привілею `CAP_SYS_ADMIN`. Спроба виклику неініційованим процесом повертає `-1` з помилкою `EPERM`.

#### Атомарне перемикання та конфігурація: `VT_SETACTIVATE`

Виклик `VT_SETACTIVATE` (`0x560D`) дозволяє атомарно перемкнути активну консоль і одночасно налаштувати параметри її сесійного режиму `struct vt_mode`:

```c
struct vt_setactivate {
    unsigned int console;   /* номер цільової консолі (1..63) */
    struct vt_mode mode;    /* бажана конфігурація vt_mode */
};
```

Семантика та переваги:
- Усуває стан гонитви (англ. *race condition*), що виникає при роздільних викликах `VT_ACTIVATE` та `VT_SETMODE`, коли консоль на короткий проміжок часу опиняється в автоматичному режимі `VT_AUTO`, перш ніж графічний сервер устигне зареєструвати обробники сигналів `relsig`/`acqsig`.
- Вимагає привілеїв `CAP_SYS_ADMIN` або володіння відкритим керуючим терміналом.

#### Структури геометрії `struct vt_sizes` та `struct vt_consize`

```c
struct vt_sizes {
    unsigned short v_rows;       /* кількість рядків символьної матриці */
    unsigned short v_cols;       /* кількість стовпчиків символьної матриці */
    unsigned short v_scroll;     /* кількість рядків буфера зворотної прокрутки */
};

struct vt_consize {
    unsigned short v_rows;       /* кількість рядків на екрані */
    unsigned short v_cols;       /* кількість стовпчиків на екрані */
    unsigned short v_scroll;     /* розмір буфера прокрутки (scrollback) */
    unsigned short v_vlin;       /* висота екрана у відеолініях / растрових пікселях */
    unsigned short v_clin;       /* висота символьного гліфа у пікселях */
    unsigned short v_vcol;       /* ширина екрана у відеоточках */
    unsigned short v_ccol;       /* ширина символьного гліфа у пікселях */
};
```

### Режими відображення та енергозбереження DPMS: `KDSETMODE`, `KDGETMODE`, `KD_TEXT0`/`KD_TEXT1`

Підсистема відображення ядра підтримує кілька режимів взаємодії з драйверами графічного виводу (`fbcon`, `vgacon`, `drm`):

```c
#define KD_TEXT         0x00
#define KD_GRAPHICS     0x01
#define KD_TEXT0        0x02  /* історичний аліас текстового режиму */
#define KD_TEXT1        0x03  /* історичний аліас текстового режиму */
```

#### Семантика режимів відображення:
- `KD_TEXT` (`0x00`): стандартний текстовий режим. Емулятор термінала (`vt.c`) здійснює синтаксичний аналіз керівних послідовностей ANSI/ECMA-48, рендерить гліфи символьних матриць, обслуговує екранний буфер зворотної прокрутки (scrollback) та керує таймером миготіння курсора.
- `KD_GRAPHICS` (`0x01`): сирий графічний режим. Використовується серверами відображення (Wayland-композиторами, Xorg, DirectFB) для монопольного виводу зображення у відеопам'ять DRM/KMS.
- `KD_TEXT0` (`0x02`) та `KD_TEXT1` (`0x03`): застарілі константи ранніх версій Linux SVGA, які в сучасному ядрі семантично еквівалентні `KD_TEXT`. Їхня підтримка збережена для бінарної сумісності зі старим системним ПЗ.

#### Механізм керування курсором та очищення екранних буферів:
1. **Перехід у `KD_GRAPHICS`:**
   - Ядро викликає `set_cursor(vc, false)`, що негайно відключає програмний та апаратний текстовий курсор.
   - Призупиняється таймер періодичного блимання курсора `cursor_timer`.
   - Драйвер `fbcon`/`vgacon` припиняє перемальовування знакомісць при надходженні нових символів через `write()`.
   - Виклики запису у TTY продовжують наповнювати внутрішній буфер емулятора, але не викликають скидання на фізичний екран.
2. **Повернення в `KD_TEXT`:**
   - Ядро переводить `vc->vc_mode = KD_TEXT`.
   - Викликається функція `con_unblank()`, що скидає статус енергозбереження екрана.
   - Викликається `update_screen(vc)`, яка повністю перечитує вміст символьного та атрибутного буферів активної консолі й здійснює повне перемальовування екрана.
   - Відновлюється робота текстового курсора `set_cursor(vc, true)`.

#### Енергозбереження та режими VESA DPMS (Display Power Management Signaling)

Підсистема віртуальних консолей Linux містить вбудований диспетчер гасіння екрана та керування лініями синхронізації монітора (DPMS) за стандартом VESA.

Консоль підтримує 4 стандартні стани енергозбереження VESA:

```
┌──────────────────────┬──────┬─────────┬─────────┬──────────────────────────────────────────┐
│ Стан VESA DPMS       │ Код  │ HSync   │ VSync   │ Опис режиму та споживання                │
├──────────────────────┼──────┼─────────┼─────────┼──────────────────────────────────────────┤
│ VESA_NO_BLANKING     │ 0x00 │ Увімкн  │ Увімкн  │ Нормальний робочий режим (On).           │
│                      │      │         │         │ Екран активний, повна розгортка.         │
├──────────────────────┼──────┼─────────┼─────────┼──────────────────────────────────────────┤
│ VESA_VSYNC_SUSPEND   │ 0x01 │ Увімкн  │ Вимкн   │ Режим очікування (Standby).              │
│                      │      │         │         │ Швидке пробудження (< 1 с), -20% енергії.│
├──────────────────────┼──────┼─────────┼─────────┼──────────────────────────────────────────┤
│ VESA_HSYNC_SUSPEND   │ 0x02 │ Вимкн   │ Увімкн  │ Режим призупинення (Suspend).            │
│                      │      │         │         │ Пробудження ~2-3 с, суттєва економія.    │
├──────────────────────┼──────┼─────────┼─────────┼──────────────────────────────────────────┤
│ VESA_POWERDOWN       │ 0x03 │ Вимкн   │ Вимкн   │ Глибокий сон / вимкнення (Off/PowerOff). │
│                      │      │         │         │ Повне знеструмлення тракту підсвітки.    │
└──────────────────────┴──────┴─────────┴─────────┴──────────────────────────────────────────┘
```

#### Таймери та механіка автогасіння екрана:
- **Інтервал автогасіння (`consoleblank`):** ядро утримує глобальний таймер `blankinterval` (за замовчуванням 600 секунд / 10 хвилин). Параметр можна змінити через завантажувальний рядок ядра (`consoleblank=N` у секундах, де `0` — вимкнено), файл `/sys/module/kernel/parameters/consoleblank` або термінальну escape-послідовність `ESC [ 9 ; N ]` (де `N` — хвилини).
- **Процедура гасіння (`con_blank()`):** якщо протягом інтервалу `blankinterval` не зафіксовано натискань клавіш чи виводу символів у консоль, таймер викликає процедуру `do_blank_screen()`. Драйвер консолі заливає відеопам'ять чорним кольором (Software Blanking) та переводить контролер відеовиходу в обраний режим VESA DPMS (`VESA_VSYNC_SUSPEND`, `VESA_HSYNC_SUSPEND` або `VESA_POWERDOWN`).
- **Автоматичне пробудження (`unblank_screen()`):** будь-яка апаратна подія введення від драйвера клавіатури (`keyboard.c`), переміщення миші (GPM) або запис даних у TTY викликає функцію `unblank_screen()`, яка негайно повертає сигнал синхронізації відеокарти у стан `VESA_NO_BLANKING` та відновлює активний відеокадр.

### Генерація звукових сигналів: `KDMKTONE` та `KIOCSOUND`

Підсистема KD дозволяє керувати системним таймером генерації звуку PC Speaker (канал 2 програмованого інтервального таймера Intel 8254 PIT з опорною частотою `1 193 180` Гц):

#### `KDMKTONE`

Приймає 32-бітне числове значення типу `long`, скомпоноване з двох 16-бітних полів:
- Старші 16 бітів (`(tone >> 16) & 0xFFFF`): тривалість звучання в мілісекундах (або тіках системного годинника ядра).
- Молодші 16 бітів (`tone & 0xFFFF`): дільник частоти таймера PIT.

Обчислення значення дільника за бажаною частотою у герцах (`freq_hz`):

```
tone_div = 1193180 / freq_hz
```

Повний аргумент для системного виклику:

```
tone = (duration_ms << 16) | (tone_div & 0xFFFF)
```

Якщо передано `tone == 0`, відтворення звуку негайно припиняється.

#### `KIOCSOUND`

Приймає єдине 32-бітне ціле значення дільника `tone_div`:
- Якщо `tone_div > 0`: таймер запускає безперервну генерацію звуку частотою `1193180 / tone_div` Гц.
- Якщо `tone_div == 0`: генерація звуку вимикається.

### Керування світлодіодами клавіатури: `KDSETLED` та `KDGETLED`

Стан індикаторів клавіатури визначається бітовою маскою з трьох констант:
- `LED_SCR` (`0x01`): індикатор Scroll Lock.
- `LED_NUM` (`0x02`): індикатор Num Lock.
- `LED_CAP` (`0x04`): індикатор Caps Lock.

#### `KDGETLED`
Записує в переданий покажчик `char *` поточний стан фізичних світлодіодів клавіатури як комбінацію бітів `LED_SCR | LED_NUM | LED_CAP`.

#### `KDSETLED`
Приймає аргумент типу `long`:
- Значення від `0x00` до `0x07`: примусово виставляє стан фізичних світлодіодів. При цьому ядро **призупиняє автоматичну синхронізацію** світлодіодів зі станом клавіш Caps/Num/Scroll Lock.
- Значення `LED_FLAGS_MASK` (`0xFF` або `0x7F` залежно від архітектури): скидає примусовий режим і повертає ядру автоматичне керування індикаторами відповідно до прапорців розкладки.

#### Відмінність від `KDGKBLED` / `KDSKBLED`
Виклики `KDGKBLED` та `KDSKBLED` оперують станом логічних прапорців блокування конкретної віртуальної консолі (`K_SCROLLLOCK` = `0x01`, `K_NUMLOCK` = `0x02`, `K_CAPSLOCK` = `0x04`, `K_KANALOCK` = `0x08`), зберігаючи індивідуальний стан блокування регістру для кожної VT окремо.

## Керування консольними шрифтами (`<linux/kd.h>`)

Підсистема віртуальних консолей дозволяє динамічно зчитувати та завантажувати растрові шрифти символьних матриць для текстового режиму (`vgacon`, `fbcon`). Інтерфейси підтримують як застарілі фіксовані формати розміром 8×16 точок, так і довільні матриці з динамічною кількістю гліфів (256 або 512 символів) та висотою до 32 сканліній.

### Структури даних та компонування пам'яті шрифтів

#### Структура `struct consolefontdesc`

Використовується викликами `GIO_FONTX` та `PIO_FONTX` для роботи зі шрифтами змінної висоти:

```c
struct consolefontdesc {
    unsigned short charcount;  /* кількість символів у таблиці: 256 або 512 */
    unsigned short charheight; /* висота гліфа у пікселях / сканлініях (1..32) */
    char *chardata;            /* вказівник на буфер растрових даних у просторі користувача */
};
```

Особливості розміщення даних у буфері `chardata`:
- Кожен гліф у пам'яті ядра та буфері користувача займає рівно **32 байти**, незалежно від фактичної висоти `charheight`.
- Кожен рядок пікселів (сканлінія) гліфа завширшки до 8 пікселів кодується 1 байтом (старший біт `0x80` відповідає крайньому лівому пікселю).
- Якщо `charheight < 32`, значущими є перші `charheight` байтів кожного 32-байтного блоку гліфа, а решта байтів заповнюються нулями.
- Повний розмір буфера, на який вказує `chardata`, дорівнює `charcount × 32` байтів (для 256 символів — `8192` байти; для 512 символів — `16384` байти).
- Якщо при виклику `GIO_FONTX` поле `chardata == NULL`, ядро не копіює растрові дані, а лише записує фактичні розміри активного шрифту в поля `charcount` та `charheight`.

> ⚠️ **Апаратне обмеження 512-символьних шрифтів на VGA:**
> У стандартному текстовому режимі VGA кожен знакомісцевий атрибут кодується 1 байтом: 4 біти фону та 4 біти тексту (16 кольорів). При завантаженні шрифту на 512 символів 3-й біт атрибута кольору символу (інтенсивність / яскравість) апаратно перепризначається як вибір 256-символьного банку шрифту (Font Bank Select). Унаслідок цього кількість одночасно доступних кольорів тексту на екрані скорочується з 16 до 8.

#### Структура `struct console_font_op` (`KDFONTOP`)

Сучасний універсальний інтерфейс, що підтримує як текстові консолі VGA, так і графічні драйвери `fbcon` з довільною шириною символів:

```c
struct console_font_op {
    unsigned int op;        /* код операції: KD_FONT_OP_* */
    unsigned int flags;     /* системні прапорці: KD_FONT_FLAG_* */
    unsigned int width;     /* ширина гліфа у пікселях (1..32, типово 8 або 16) */
    unsigned int height;    /* висота гліфа у пікселях (1..32) */
    unsigned int charcount; /* кількість гліфів (256, 512 або більше для fbcon) */
    unsigned char *data;    /* вказівник на масив растрових даних */
};
```

Значення поля `op`:
- `KD_FONT_OP_SET` (`0`): завантажити новий шрифт із буфера `data`.
- `KD_FONT_OP_GET` (`1`): зчитати параметри та растрові дані активного шрифту (якщо `data == NULL`, повертає лише `width`, `height` та `charcount`).
- `KD_FONT_OP_SET_DEFAULT` (`2`): скинути шрифт до вбудованого за замовчуванням у ядро.
- `KD_FONT_OP_COPY` (`3`): скопіювати шрифт із іншої віртуальної консолі (номер вихідної VT передається у полі `height`).

Прапорці поля `flags`:
- `KD_FONT_FLAG_DONT_RECALC` (`0x01`): забороняє ядру автоматично перераховувати кількість екранних рядків і стовпчиків після зміни розміру символьної матриці.

### Формати растрових файлів шрифтів: PSF v1 та PSF v2

Консольні утиліти (зокрема `setfont`) завантажують файли формату PC Screen Font (PSF). Драйвер консолі ядра очікує сирі бітові матриці, тому користувацька програма розбирає заголовок PSF перед викликом `PIO_FONTX` або `KDFONTOP`:

#### Формат PSF v1 (`struct psf1_header`)
Заголовок довжиною 4 байти:
```c
struct psf1_header {
    unsigned char magic[2]; /* магічне число: 0x36, 0x04 (PSF1_MAGIC) */
    unsigned char mode;     /* бітові прапорці: PSF1_MODE512, PSF1_MODEHASTAB, PSF1_MODEHASSEQ */
    unsigned char charsize; /* висота гліфа у байтах (ширина завжди фіксована — 8 пікселів) */
};
```
- `PSF1_MODE512` (`0x01`): якщо біт виставлено, файл містить 512 символів; інакше — 256 символів.
- `PSF1_MODEHASTAB` (`0x02`): за растровими даними слідує таблиця трансляції Юнікоду.
- Растрові дані починаються з байта зі зміщенням `4`. Загальний обсяг растрових даних у файлі становить `charcount × charsize` байтів.

#### Формат PSF v2 (`struct psf2_header`)
Заголовок довжиною 32 байти (змінна ширина, висота та довільна кількість гліфів):
```c
struct psf2_header {
    unsigned char magic[4];  /* магічне число: 0x72, 0xb5, 0x4a, 0x86 (PSF2_MAGIC) */
    unsigned int version;    /* версія формату (0x00) */
    unsigned int headersize; /* зміщення початку растрових даних у байтах (типово 32) */
    unsigned int flags;      /* прапорці: PSF2_HAS_UNICODE_TABLE (0x01) */
    unsigned int length;     /* загальна кількість символів у файлі */
    unsigned int charsize;   /* кількість байтів на один гліф: ((width + 7) / 8) * height */
    unsigned int height;     /* висота гліфа у пікселях */
    unsigned int width;      /* ширина гліфа у пікселях */
};
```

### Структури даних таблиць Юнікоду

#### Структури `struct unimapdesc` та `struct unipair`

Використовуються викликами `GIO_UNIMAP` та `PIO_UNIMAP`:

```c
struct unipair {
    unsigned short unicode; /* 16-бітна кодова точка Unicode (UCS-2 / UTF-16) */
    unsigned short fontpos; /* індекс гліфа у шрифті (0..255 або 0..511) */
};

struct unimapdesc {
    unsigned short entry_ct; /* кількість елементів у масиві entries */
    struct unipair *entries; /* вказівник на масив пар у просторі користувача */
};
```

Семантика роботи:
- Кожен запис `unipair` пов'язує одну кодову точку Unicode (`unicode`) з відповідним позиційним номером гліфа (`fontpos`) у поточному шрифті. Декілька різних символів Юнікоду можуть вказувати на один і той самий гліф (наприклад, кирилична `А` U+0410 та латинська `A` U+0041).
- При виклику `GIO_UNIMAP` поле `entry_ct` на вході визначає розмір виділеного буфера `entries`. Якщо буфер замалий для збереження всіх правил ядра, ядро повертає `-1` з `errno = ENOMEM` або `E2BIG`. На виході ядро записує в `entry_ct` фактичну кількість повернутих правил.
- При виклику `PIO_UNIMAP` ядро додає нові правила до існуючої таблиці. Якщо потрібно повністю замінити таблицю, перед викликом `PIO_UNIMAP` слід викликати `PIO_UNIMAPCLR`.

#### Структура скидання `struct unimapinit`

```c
struct unimapinit {
    unsigned short advised_hashsize;  /* рекомендований розмір хеш-таблиці (0 — дефолт ядра) */
    unsigned short advised_hashstep;  /* крок хешування (0 — дефолт ядра) */
    unsigned short advised_hashlevel; /* рівень вкладеності (0 — дефолт ядра) */
};
```

Виклик `ioctl(fd, PIO_UNIMAPCLR, &cr)` видаляє всі користувацькі правила Юнікоду і відновлює початкову пряму ідентичність `unicode == fontpos`.

#### Екранні карти прямої трансляції `GIO_UNISCRNMAP` та `PIO_UNISCRNMAP`

Приймають вказівник на масив із `256` 16-бітних слів (`unsigned short[256]`, обсяг `512` байтів, константа `E_TABSZ = 256`):
- Задають пряму таблицю для 8-бітного режиму: коли в TTY надходить байт зі значенням `b` (`0..255`), емулятор підставляє Unicode-значення `scrnmap[b]`, після чого знаходить відповідний гліф через таблицю `unimap`.
- Дозволяє перемикати 8-бітні національні кодування (KOI8-U, CP1251, ISO-8859-5) без зміни самого шрифту.

### Режими трансляції клавіатури (`KDSKBMODE`)

Параметр `mode` передається цілим числом типу `long`:

```
┌──────────────┬──────┬────────────────────────────────────────────────────────────┐
│ Режим        │ Код  │ Що генерує підсистема у чергу TTY                          │
├──────────────┼──────┼────────────────────────────────────────────────────────────┤
│ K_RAW        │ 0x00 │ Сканкоди XT (Set 1): 1 байт на натискання, 0x80 | код на   │
│              │      │ відпускання, префікс 0xE0 для розширених клавіш            │
├──────────────┼──────┼────────────────────────────────────────────────────────────┤
│ K_XLATE      │ 0x01 │ 8-бітні символи (ISO-8859-1/ASCII) через розкладку ядра    │
│              │      │ та VT102 escape-послідовності для функціональних клавіш    │
├──────────────┼──────┼────────────────────────────────────────────────────────────┤
│ K_MEDIUMRAW  │ 0x02 │ 7/14-бітні незалежні від платформи сканкоди (0..127: 1B;   │
│              │      │ 128..255: 2B з маскою 0x80 | (код >> 7))                   │
├──────────────┼──────┼────────────────────────────────────────────────────────────┤
│ K_UNICODE    │ 0x03 │ Символи кодування UTF-8 (від 1 до 4 байтів на кодову точку)│
├──────────────┼──────┼────────────────────────────────────────────────────────────┤
│ K_OFF        │ 0x04 │ Повне блокування введення в TTY (використовують Wayland/X11│
│              │      │ для монопольного отримання подій через evdev)              │
└──────────────┴──────┴────────────────────────────────────────────────────────────┘
```

#### Детальний аналіз режимів:

1. **`K_RAW` (`0x00`):** генерує низькорівневі сканкоди IBM PC/XT (Set 1). Натискання клавіші генерує значення `0x01..0x7F`. Відпускання кодується підняттям сьомого біта (`scancode | 0x80`). Розширені клавіші (навігаційні стрілки, клавіші Insert/Delete/PageUp/PageDown, правий Ctrl та Alt) надсилають двобайтну послідовність із префіксом `0xE0`. Режим застосовувався застарілими серверами XFree86 до впровадження стандарту `evdev`.
2. **`K_XLATE` (`0x01`):** традиційний режим трансляції. Апаратні події транслюються крізь таблиці розкладки `key_maps` у 8-бітні символи кодування ISO-8859 або ASCII. Функціональні клавіші транслюються в послідовності керування стандарту ANSI/VT102 (наприклад, клавіша F1 генерує `\033[[A`).
3. **`K_MEDIUMRAW` (`0x02`):** проміжний двійковий формат, незалежний від типу контролера клавіатури (PS/2, USB HID, AT). Коди від 0 до 127 кодуються одним байтом (зі старшим бітом як ознакою відпускання). Коди від 128 до 255 розбиваються на два байти: перший байт містить маску `0x80 | (код >> 7)`, другий — `код & 0x7F`.
4. **`K_UNICODE` (`0x03`):** стандартний сучасний режим консолі. Обробник розкладки транслює комбінації клавіш у 16-бітні кодові точки Unicode (UCS-2), які функція `to_utf8()` у `drivers/tty/vt/keyboard.c` кодує в потік байтів UTF-8.
5. **`K_OFF` (`0x04`):** драйвер клавіатури повністю блокує відправку байтів у чергу TTY (окрім комбінацій Magic SysRq, якщо вони ввімкнені в системі). Сучасні графічні композитори (Sway, GNOME Shell, KWin) вмикають `K_OFF`, читаючи події введення через `/dev/input/event*` за допомогою бібліотеки `libinput`.

### Структури конфігурації клавіш

#### Елемент розкладки `struct kbentry`

```c
struct kbentry {
    unsigned char kb_table; /* індекс таблиці модифікаторів (0..15) */
    unsigned char kb_index; /* сканкод / індекс клавіші (0..127 або 0..255) */
    unsigned short kb_value;/* дія ядра або кодова точка символу */
};
```

Поле `kb_table` визначає активний шар модифікаторів:
- `0`: базовий шар (Plain — без модифікаторів).
- `1`: натиснуто Shift (`KG_SHIFT`).
- `2`: натиснуто AltGr (`KG_ALTGR`).
- `4`: натиснуто Control (`KG_CTRL`).
- `8`: натиснуто Alt (`KG_ALT`).
- Похідні комбінації формуються бітовим або (наприклад, `5` = Shift + Control).

Поле `kb_value` містить тип і значення дії, закодовані макросом ядра `K(type, value)`:
- `KT_LATIN` / `KT_LETTER`: генерація звичайного латинського або національного символу.
- `KT_FN`: функціональні клавіші (`K_F1`..`K_F246`).
- `KT_SPEC`: спеціальні системні дії (`K_ENTER`, `K_CAPS`, `K_NUM`, `K_HOLD`).
- `KT_CONS`: перемикання на конкретну віртуальну консоль (`K_CONS` + номер VT).
- `KT_CUR`: навігація курсора (`K_DOWN`, `K_LEFT`, `K_RIGHT`, `K_UP`).

#### Рядки функціональних клавіш `struct kbsentry`

```c
struct kbsentry {
    unsigned char kb_func;        /* числовий номер функціональної клавіші (0..255) */
    unsigned char kb_string[512]; /* нуль-термінований рядок керуючої послідовності */
};
```

Дозволяє перевизначати послідовність символів, яку ядро генерує при натисканні клавіш `F1`..`F20` або комбінацій модифікаторів.

### Налаштування автоповтору клавіш (Typematic Rate): `KDKBDREP`

Системний виклик `ioctl(fd, KDKBDREP, &krep)` (`0x4B52`) надає прямий інтерфейс зчитування та налаштування часових характеристик апаратного й програмного автоповтору клавіш (англ. *Typematic delay and rate*):

```c
struct kbd_repeat {
    int delay;  /* затримка перед початком автоповтору в мілісекундах */
    int period; /* інтервал між повторними генераціями в мілісекундах */
};
```

#### Семантика зчитування та запису:
Інтерфейс `KDKBDREP` об'єднує функції читання та запису в одному виклику:
- **Зчитування поточних налаштувань (Get):** якщо у структурі `struct kbd_repeat` передати `delay <= 0` або `period <= 0` (традиційно передають `-1` в обидва поля), ядро **не змінює** налаштувань апаратури. Замість цього воно зчитує поточні активні параметри з драйвера клавіатури або підсистеми `input_dev` та записує їх у передану структуру.
- **Встановлення нових параметрів (Set):** якщо передано додатні значення `delay > 0` та `period > 0`, ядро валідує параметри, перераховує їх у частоту й записує в апаратний контролер або шар введення.

#### Співвідношення параметрів та типові значення:
- `delay`: час утримання клавіші до першого повторення. Типові значення: `250` мс (швидкий відгук), `500` мс (стандартний дефолт ядра), `1000` мс (повільний).
- `period`: період генерації повторів. Частота повтору в герцах (символів на секунду) обчислюється як:
  `rate = 1000 / period` (симв/с)
  Наприклад, `period = 33` мс відповідає ≈ 30.3 симв/с (максимальна швидкість стандарту AT), а `period = 100` мс — 10.0 симв/с.

#### Апаратна трансляція та драйвери:
1. **Контролери AT / PS/2 (`i8042` / `atkbd.c`):** значення `delay` квантується до одного з чотирьох апаратних рівнів (`250`, `500`, `750`, `1000` мс), а частота повтору — до 32 дискретних значень у діапазоні від 2.0 до 30.0 Гц. Драйвер пакує ці значення в 8-бітний параметр команди контролера `0xF3` (Set Typematic Rate/Delay).
2. **Підсистема USB HID / `evdev` (`input.c`):** ядро оновлює масив часових констант автоповтору `input_dev->rep[REP_DELAY]` та `input_dev->rep[REP_PERIOD]`, що забезпечує однаковий інтервал генерації повторів як для USB-клавіатур, так і для віртуальних пристроїв `uinput`.

#### Обробка помилок:
- `EINVAL`: передано некоректні числові значення поза допустимими межами ядра.
- `EFAULT`: вказівник на структуру `struct kbd_repeat` вказує на недійсну адресу пам'яті.
- `ENODEV`: до консолі не підключено клавіатурного пристрою, що підтримує зміну параметрів повтору.

### Номери стандартних лінійних дисциплін ядра

Лінійна дисципліна встановлюється викликом `ioctl(fd, TIOCSETD, &ldisc_number)`:

- `N_TTY` (`0`): стандартна термінальна лінійна дисципліна ядра. Реалізує канонічний буфер рядка (4096 байтів), генерацію термінальних сигналів `SIGINT`, `SIGQUIT`, `SIGTSTP`, керування луною (`ECHO`), розкриття символів табуляції та програмне керування потоком (XON/XOFF).
- `N_SLIP` (`1`): протокол кадрування Serial Line Internet Protocol.
- `N_MOUSE` (`2`): лінійна дисципліна для зчитування пакетів послідовних мишей (Serial Mouse).
- `N_PPP` (`3`): протокол Point-to-Point Protocol.
- `N_STRIP` (`4`): протокол передавання пакетів Starmode Radio IP.
- `N_AX25` (`5`): аматорський пакетний радіопротокол AX.25.
- `N_HDLC` (`13`): високошвидкісне синхронне бітове кадрування HDLC.
- `N_GSM0710` (`21`): протокол мультиплексування GSM 07.10 (поділ одного послідовного UART-каналу на кілька віртуальних підканалів).
- `N_SLCAN` (`25`): драйвер послідовного інтерфейсу CAN (SocketCAN), що транслює текстові команди послідовного порту в CAN-фрейми ядра.

## Зіставлення утиліт командного рядка з системними викликами `ioctl`

Стандартні утиліти пакета `kbd` та системних середовищ Linux безпосередньо транслюють параметри командного рядка у відповідні виклики `ioctl`:

### 1. `chvt N` (Change Virtual Terminal)
- **Призначення:** перемикає активний екран на віртуальну консоль `N`.
- **Алгоритм роботи:**
  1. Відкриває дескриптор `/dev/tty0` (або за його відсутності `/dev/console` чи `/dev/tty`).
  2. Виконує системний виклик `ioctl(fd, VT_ACTIVATE, N)`.
  3. Виконує блокуючий виклик `ioctl(fd, VT_WAITACTIVE, N)`.
  4. Закриває файловий дескриптор.

### 2. `openvt` (Open Virtual Terminal)
- **Призначення:** запускає команду на новому або вільному віртуальному терміналі.
- **Алгоритм роботи:**
  1. Якщо номер консолі не вказано явно (прапорець `-c N`), знаходить першу доступну консоль викликом `ioctl(fd, VT_OPENQRY, &vt_num)`.
  2. Створює дочірній процес викликом `fork()`.
  3. Дочірній процес викликає `setsid()` для започаткування нової сесії.
  4. Відкриває `/dev/ttyN`, перенаправляє файлові дескриптори `0`, `1`, `2` (`dup2`) і робить термінал керуючим через `ioctl(tty_fd, TIOCSCTTY, 0)`.
  5. Якщо передано прапорець `-s`, перемикає дисплей викликом `ioctl(fd, VT_ACTIVATE, vt_num)`.
  6. Викликає `execvp()` для виконання цільової програми.

### 3. `deallocvt [N ...]` (Deallocate Virtual Terminal)
- **Призначення:** звільняє пам'ять текстових і графічних буферів невикористовуваних віртуальних консолей.
- **Алгоритм роботи:**
  1. Якщо аргументи відсутні: виконує `ioctl(fd, VT_DISALLOCATE, 0)`, змушуючи ядро звільнити пам'ять усіх неактивних і закритих консолей.
  2. Якщо передано номери консолей `N`: для кожного номера послідовно викликає `ioctl(fd, VT_DISALLOCATE, N)`. Якщо консоль наразі утримується процесом, виклик завершується з помилкою `EBUSY`.

### 4. `kbdrate [-r rate] [-d delay] [-s] [-C /dev/ttyN]`
- **Призначення:** налаштовує частоту автоповтору (символів/с) та затримку перед початком повтору клавіш.
- **Алгоритм роботи:**
  1. Зчитує параметри командного рядка: частоту `rate` (наприклад, `30.0`) та затримку `delay` (наприклад, `250`).
  2. Обчислює період: `period = (int)(1000.0 / rate)`.
  3. Відкриває дескриптор консолі `/dev/tty0` або вказаної через `-C`.
  4. Заповнює структуру `struct kbd_repeat krep = { .delay = delay, .period = period };`.
  5. Виконує системний виклик `ioctl(fd, KDKBDREP, &krep)`.

### 5. `setterm [-blank [0-60]] [-powersave on|vsync|hsync|powerdown|off] [-repeat on|off]`
- **Призначення:** налаштовує таймери гасіння екрана, режими енергозбереження VESA DPMS та стан автоповтору.
- **Алгоритм роботи:**
  - Опція `-blank N`: надсилає в TTY керуючу escape-послідовність `\033[9;N]` (де `N` — хвилини таймера `blankinterval`). Значення `0` вимикає гасіння.
  - Опція `-powersave vsync|hsync|powerdown|off`: надсилає керівну послідовність `\033[14;M]`, де `M` набуває значень 1, 2, 3 або 0, що перемикає ядерний режим VESA DPMS під час спрацьовування таймера гасіння.
  - Опція `-repeat on|off`: вмикає або вимикає автоповтор через escape-послідовність `\033[?8h` / `\033[?8l` або виклик `KDKBDREP`.

### 6. `physlock` / `vlock [-a | -c]`
- **Призначення:** блокує сесію віртуальної консолі й запобігає несанкціонованому перемиканню.
- **Алгоритм роботи:**
  1. Відкриває активний дескриптор TTY.
  2. Викликає `ioctl(fd, VT_LOCKSWITCH, 1)` для блокування гарячих клавіш `Ctrl+Alt+Fn`.
  3. Запитує пароль користувача через PAM.
  4. Після успішної перевірки автентифікації виконує `ioctl(fd, VT_UNLOCKSWITCH, 1)` і завершує роботу.

### 7. `kbd_mode [-a | -u | -k | -s] [-C /dev/ttyN]`
- **Призначення:** перевіряє або перемикає режим трансляції клавіатури.
- **Алгоритм роботи:**
  - Без параметрів зміни режиму: викликає `ioctl(fd, KDGKBMODE, &mode)` і виводить текстовий опис отриманого режиму.
  - З прапорцями вибору: викликає `ioctl(fd, KDSKBMODE, mode_val)`:
    - `-a`: встановлює `K_XLATE` (`0x01`).
    - `-u`: встановлює `K_UNICODE` (`0x03`).
    - `-k`: встановлює `K_MEDIUMRAW` (`0x02`).
    - `-s`: встановлює `K_RAW` (`0x00`).

### 8. `setleds [-+caps] [-+num] [-+scroll] [-D] [-F] [-L] [-C /dev/ttyN]`
- **Призначення:** встановлює або відображає стан світлодіодів та прапорців блокування.
- **Алгоритм роботи:**
  - Отримує поточний стан викликами `ioctl(fd, KDGETLED, &leds)` та `ioctl(fd, KDGKBLED, &flags)`.
  - З прапорцем `-L`: змінює виключно апаратні світлодіоди через `ioctl(fd, KDSETLED, leds)`.
  - З прапорцем `-F` (за замовчуванням): змінює прапорці блокування термінала через `ioctl(fd, KDSKBLED, flags)` та оновлює світлодіоди.
  - З прапорцем `-D`: змінює системні прапорці за замовчуванням.

### 9. `setvtrgb [-C /dev/ttyN] [FILE | -]`
- **Призначення:** налаштовує 16-колірну колірну схему VGA DAC.
- **Алгоритм роботи:**
  1. Зчитує 16 значень для каналів Red, 16 для Green та 16 для Blue.
  2. Формує 48-байтний буфер у чергуванні `R, G, B`.
  3. Викликає системний виклик `ioctl(fd, PIO_CMAP, colormap)`.

### 10. `setfont [FONTFILE] [-u UNIMAPFILE] [-C /dev/ttyN]`
- **Призначення:** завантажує растровий шрифт PSF та відповідну таблицю Юнікоду.
- **Алгоритм роботи:**
  1. Зчитує заголовок файлу шрифту (PSF1 або PSF2).
  2. Викликає `ioctl(fd, KDFONTOP, &op)` з операцією `KD_FONT_OP_SET` (або `ioctl(fd, PIO_FONTX, &cfd)`).
  3. Якщо файл шрифту містить вбудовану таблицю Юнікоду або вказано `-u`: викликає `ioctl(fd, PIO_UNIMAPCLR, &init)`, після чого завантажує масив правил викликом `ioctl(fd, PIO_UNIMAP, &unimap)`.

### 11. `loadunimap [-C /dev/ttyN] [UNIMAPFILE]`
- **Призначення:** завантажує текстову або двійкову таблицю відповідності Юнікод → гліф.
- **Алгоритм роботи:**
  1. Очищає активну таблицю викликом `ioctl(fd, PIO_UNIMAPCLR, &init)`.
  2. Завантажує розпарсені пари `(unicode, fontpos)` через `ioctl(fd, PIO_UNIMAP, &unimap)`.

### 1. Виділення вільної VT, перемикання в графічний режим та безпечне відновлення

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/ioctl.h>
#include <linux/vt.h>
#include <linux/kd.h>

int main(void) {
    int tty0_fd = open("/dev/tty0", O_RDWR | O_NOCTTY);
    if (tty0_fd < 0) {
        perror("Помилка відкриття /dev/tty0");
        return EXIT_FAILURE;
    }

    /* Знаходимо першу вільну віртуальну консоль */
    int vt_num = 0;
    if (ioctl(tty0_fd, VT_OPENQRY, &vt_num) < 0 || vt_num <= 0) {
        perror("Не вдалося знайти вільну VT");
        close(tty0_fd);
        return EXIT_FAILURE;
    }
    printf("Знайдено вільну консоль: /dev/tty%d\n", vt_num);

    /* Відкриваємо цільову віртуальну консоль */
    char vt_path[32];
    snprintf(vt_path, sizeof(vt_path), "/dev/tty%d", vt_num);
    int vt_fd = open(vt_path, O_RDWR | O_NOCTTY);
    if (vt_fd < 0) {
        perror("Помилка відкриття цільової VT");
        close(tty0_fd);
        return EXIT_FAILURE;
    }

    /* Зберігаємо початкові режими для коректного відновлення */
    long orig_kb_mode = 0;
    int orig_kd_mode = 0;
    ioctl(vt_fd, KDGKBMODE, &orig_kb_mode);
    ioctl(vt_fd, KDGETMODE, &orig_kd_mode);

    /* Активуємо нову консоль і чекаємо завершення перемикання */
    if (ioctl(tty0_fd, VT_ACTIVATE, vt_num) < 0 ||
        ioctl(tty0_fd, VT_WAITACTIVE, vt_num) < 0) {
        perror("Помилка активації VT");
        close(vt_fd);
        close(tty0_fd);
        return EXIT_FAILURE;
    }

    /* Блокуємо перемикання консолей на час графічної сесії */
    ioctl(tty0_fd, VT_LOCKSWITCH, 1);

    /* Переводимо дисплей у графічний режим і вимикаємо TTY-трансляцію клавіатури */
    ioctl(vt_fd, KDSETMODE, KD_GRAPHICS);
    ioctl(vt_fd, KDSKBMODE, K_OFF);

    printf("Консоль переведено в графічний режим (VT_LOCKSWITCH активний) на 2 секунди...\n");
    sleep(2);

    /* Відновлюємо початковий стан термінала та знімаємо блокування */
    ioctl(vt_fd, KDSKBMODE, orig_kb_mode);
    ioctl(vt_fd, KDSETMODE, orig_kd_mode);
    ioctl(tty0_fd, VT_UNLOCKSWITCH, 1);

    close(vt_fd);
    close(tty0_fd);
    printf("Режими успішно відновлено, перемикання розблоковано.\n");
    return EXIT_SUCCESS;
}
```

```cpp
#include <iostream>
#include <string>
#include <stdexcept>
#include <chrono>
#include <thread>
#include <format>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <linux/vt.h>
#include <linux/kd.h>

class VirtualTerminalSession {
public:
    VirtualTerminalSession() {
        tty0_fd_ = ::open("/dev/tty0", O_RDWR | O_NOCTTY | O_CLOEXEC);
        if (tty0_fd_ < 0) {
            throw std::system_error(errno, std::generic_category(), "Не вдалося відкрити /dev/tty0");
        }

        int target_vt = 0;
        if (::ioctl(tty0_fd_, VT_OPENQRY, &target_vt) < 0 || target_vt <= 0) {
            ::close(tty0_fd_);
            throw std::system_error(errno, std::generic_category(), "Немає вільних VT");
        }
        vt_num_ = target_vt;

        const std::string path = std::format("/dev/tty{}", vt_num_);
        vt_fd_ = ::open(path.c_str(), O_RDWR | O_NOCTTY | O_CLOEXEC);
        if (vt_fd_ < 0) {
            ::close(tty0_fd_);
            throw std::system_error(errno, std::generic_category(), "Не вдалося відкрити " + path);
        }

        ::ioctl(vt_fd_, KDGKBMODE, &orig_kb_mode_);
        ::ioctl(vt_fd_, KDGETMODE, &orig_kd_mode_);
    }

    void activate_graphics_with_lock() {
        if (::ioctl(tty0_fd_, VT_ACTIVATE, vt_num_) < 0 ||
            ::ioctl(tty0_fd_, VT_WAITACTIVE, vt_num_) < 0) {
            throw std::system_error(errno, std::generic_category(), "Помилка перемикання VT");
        }

        // Блокуємо перемикання консолей під час сесії
        ::ioctl(tty0_fd_, VT_LOCKSWITCH, 1);
        switch_locked_ = true;

        ::ioctl(vt_fd_, KDSETMODE, KD_GRAPHICS);
        ::ioctl(vt_fd_, KDSKBMODE, K_OFF);
        is_graphics_ = true;
    }

    ~VirtualTerminalSession() {
        if (is_graphics_ && vt_fd_ >= 0) {
            ::ioctl(vt_fd_, KDSKBMODE, orig_kb_mode_);
            ::ioctl(vt_fd_, KDSETMODE, orig_kd_mode_);
        }
        if (switch_locked_ && tty0_fd_ >= 0) {
            ::ioctl(tty0_fd_, VT_UNLOCKSWITCH, 1);
        }
        if (vt_fd_ >= 0) ::close(vt_fd_);
        if (tty0_fd_ >= 0) ::close(tty0_fd_);
    }

    [[nodiscard]] int vt_number() const noexcept { return vt_num_; }

private:
    int tty0_fd_{-1};
    int vt_fd_{-1};
    int vt_num_{0};
    long orig_kb_mode_{K_XLATE};
    int orig_kd_mode_{KD_TEXT};
    bool is_graphics_{false};
    bool switch_locked_{false};
};

int main() {
    try {
        VirtualTerminalSession vt;
        std::cout << "Захоплено консоль /dev/tty" << vt.vt_number() << '\n';
        vt.activate_graphics_with_lock();
        std::cout << "Графічний режим активовано (VT_LOCKSWITCH) на 2 секунди...\n";
        std::this_thread::sleep_for(std::chrono::seconds(2));
    } catch (const std::exception& e) {
        std::cerr << "Помилка: " << e.what() << '\n';
        return EXIT_FAILURE;
    }
    std::cout << "Ресурси VT безпечно звільнено, блокування знято.\n";
    return EXIT_SUCCESS;
}
```

### 2. Керування світлодіодами, генерація звуку та налаштування автоповтору клавіатури

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/ioctl.h>
#include <linux/kd.h>

#define PIT_CLOCK_RATE 1193180

int main(void) {
    int fd = open("/dev/tty0", O_RDWR | O_NOCTTY);
    if (fd < 0) {
        perror("Не вдалося відкрити консоль");
        return EXIT_FAILURE;
    }

    /* 1. Блимання світлодіодами CapsLock та NumLock */
    printf("Вмикаємо індикатори CapsLock та NumLock...\n");
    ioctl(fd, KDSETLED, LED_CAP | LED_NUM);
    sleep(1);

    printf("Повертаємо ядру автоматичне керування індикаторами...\n");
    ioctl(fd, KDSETLED, 0xFF); /* Скидання в автоматичний режим */

    /* 2. Інспекція та налаштування автоповтору клавіш (KDKBDREP) */
    struct kbd_repeat orig_rep = { .delay = -1, .period = -1 };
    if (ioctl(fd, KDKBDREP, &orig_rep) == 0) {
        printf("Поточний автоповтор: delay=%d мс, period=%d мс (%.1f симв/с)\n",
               orig_rep.delay, orig_rep.period,
               orig_rep.period > 0 ? 1000.0 / orig_rep.period : 0.0);

        /* Встановлюємо швидкий автоповтор: 250 мс затримки, 33 мс період (~30 Гц) */
        struct kbd_repeat fast_rep = { .delay = 250, .period = 33 };
        if (ioctl(fd, KDKBDREP, &fast_rep) == 0) {
            printf("Застосовано швидкий автоповтор (250 мс, 30 Гц) на 1 секунду...\n");
            sleep(1);
            /* Відновлюємо початковий автоповтор */
            ioctl(fd, KDKBDREP, &orig_rep);
            printf("Початковий автоповтор відновлено.\n");
        }
    }

    /* 3. Генерація звукового сигналу 440 Гц (нота Ля) тривалістю 500 мс через KDMKTONE */
    int freq_hz = 440;
    int duration_ms = 500;
    int tone_div = PIT_CLOCK_RATE / freq_hz;
    long tone_arg = (duration_ms << 16) | (tone_div & 0xFFFF);

    printf("Генерація сигналу 440 Гц через KDMKTONE...\n");
    ioctl(fd, KDMKTONE, tone_arg);
    usleep(600000);

    /* 4. Генерація безперервного сигналу через KIOCSOUND */
    int freq2_hz = 880;
    int tone2_div = PIT_CLOCK_RATE / freq2_hz;
    printf("Генерація сигналу 880 Гц через KIOCSOUND...\n");
    ioctl(fd, KIOCSOUND, tone2_div);
    usleep(300000);
    ioctl(fd, KIOCSOUND, 0); /* Зупинка звуку */

    close(fd);
    return EXIT_SUCCESS;
}
```

```cpp
#include <iostream>
#include <chrono>
#include <thread>
#include <format>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <linux/kd.h>

class KeyboardRepeatGuard {
public:
    explicit KeyboardRepeatGuard(int fd) : fd_(fd) {
        orig_repeat_.delay = -1;
        orig_repeat_.period = -1;
        if (::ioctl(fd_, KDKBDREP, &orig_repeat_) == 0) {
            has_orig_ = true;
        }
    }

    void set_repeat(int delay_ms, int period_ms) {
        struct kbd_repeat rep{.delay = delay_ms, .period = period_ms};
        if (::ioctl(fd_, KDKBDREP, &rep) < 0) {
            throw std::system_error(errno, std::generic_category(), "Помилка встановлення KDKBDREP");
        }
    }

    [[nodiscard]] struct kbd_repeat original() const noexcept { return orig_repeat_; }

    ~KeyboardRepeatGuard() {
        if (has_orig_) {
            ::ioctl(fd_, KDKBDREP, &orig_repeat_);
        }
    }

private:
    int fd_;
    struct kbd_repeat orig_repeat_{};
    bool has_orig_{false};
};

class ConsoleSpeaker {
public:
    static constexpr int pit_base_clock = 1193180;

    explicit ConsoleSpeaker(int fd) : fd_(fd) {}

    void play_tone(int freq_hz, int duration_ms) {
        if (freq_hz <= 0) return;
        const int divider = pit_base_clock / freq_hz;
        const long arg = (static_cast<long>(duration_ms) << 16) | (divider & 0xFFFF);
        ::ioctl(fd_, KDMKTONE, arg);
    }

    void start_tone(int freq_hz) {
        if (freq_hz <= 0) return;
        const int divider = pit_base_clock / freq_hz;
        ::ioctl(fd_, KIOCSOUND, divider);
    }

    void stop_tone() noexcept {
        ::ioctl(fd_, KIOCSOUND, 0);
    }

    ~ConsoleSpeaker() {
        stop_tone();
    }

private:
    int fd_;
};

int main() {
    int fd = ::open("/dev/tty0", O_RDWR | O_NOCTTY | O_CLOEXEC);
    if (fd < 0) {
        std::cerr << "Помилка відкриття /dev/tty0\n";
        return EXIT_FAILURE;
    }

    // 1. Керування індикаторами
    ::ioctl(fd, KDSETLED, LED_SCR | LED_CAP);
    std::this_thread::sleep_for(std::chrono::milliseconds(500));
    ::ioctl(fd, KDSETLED, 0xFF); // відновлення автосинхронізації

    // 2. Безпечне налаштування автоповтору клавіш (RAII)
    try {
        KeyboardRepeatGuard repeat_guard(fd);
        const auto orig = repeat_guard.original();
        std::cout << std::format("Поточний автоповтор: delay={} мс, period={} мс\n",
                                 orig.delay, orig.period);

        repeat_guard.set_repeat(250, 33);
        std::cout << "Встановлено швидкий автоповтор (250 мс, 30 Гц)...\n";
        std::this_thread::sleep_for(std::chrono::milliseconds(500));
    } catch (const std::exception& e) {
        std::cerr << "Попередження автоповтору: " << e.what() << '\n';
    }

    // 3. Керування звуком PC Speaker
    ConsoleSpeaker speaker(fd);
    speaker.play_tone(440, 300);
    std::this_thread::sleep_for(std::chrono::milliseconds(400));

    speaker.start_tone(880);
    std::this_thread::sleep_for(std::chrono::milliseconds(200));
    speaker.stop_tone();

    ::close(fd);
    std::cout << "Усі параметри клавіатури та динаміка безпечно відновлено.\n";
    return EXIT_SUCCESS;
```

### 3. Інспекція палітри VGA DAC та параметрів консольного шрифту

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <linux/kd.h>

int main(void) {
    int fd = open("/dev/tty0", O_RDWR | O_NOCTTY);
    if (fd < 0) {
        perror("Помилка відкриття /dev/tty0");
        return EXIT_FAILURE;
    }

    /* 1. Зчитування поточної 16-колірної палітри VGA DAC */
    unsigned char orig_cmap[48];
    if (ioctl(fd, GIO_CMAP, orig_cmap) < 0) {
        perror("Помилка GIO_CMAP");
        close(fd);
        return EXIT_FAILURE;
    }

    printf("Поточна палітра кольорів консолі:\n");
    for (int i = 0; i < 16; i++) {
        printf("  Колір %2d: R=0x%02X G=0x%02X B=0x%02X\n",
               i, orig_cmap[i * 3], orig_cmap[i * 3 + 1], orig_cmap[i * 3 + 2]);
    }

    /* 2. Інспекція геометрії активного консольного шрифту через KDFONTOP */
    struct console_font_op font_op;
    memset(&font_op, 0, sizeof(font_op));
    font_op.op = KD_FONT_OP_GET;

    if (ioctl(fd, KDFONTOP, &font_op) == 0) {
        printf("Параметри шрифту (KDFONTOP): %ux%u пікселів, %u гліфів\n",
               font_op.width, font_op.height, font_op.charcount);
    } else {
        /* Fallback на GIO_FONTX, якщо KDFONTOP не підтримується драйвером */
        struct consolefontdesc cfd;
        memset(&cfd, 0, sizeof(cfd));
        if (ioctl(fd, GIO_FONTX, &cfd) == 0) {
            printf("Параметри шрифту (GIO_FONTX): висота %u сканліній, %u гліфів\n",
                   cfd.charheight, cfd.charcount);
        }
    }

    /* 3. Встановлення модифікованої палітри (інверсія кольору 1) та відновлення */
    unsigned char mod_cmap[48];
    memcpy(mod_cmap, orig_cmap, sizeof(orig_cmap));
    mod_cmap[3] = 0xFF; /* Червоний компонент кольору 1 у максимум */
    mod_cmap[4] = 0x88;
    mod_cmap[5] = 0x00;

    if (ioctl(fd, PIO_CMAP, mod_cmap) == 0) {
        printf("Тимчасову палітру застосовано на 1 секунду...\n");
        sleep(1);
        /* Відновлення оригінальної палітри */
        ioctl(fd, PIO_CMAP, orig_cmap);
        printf("Оригінальну палітру відновлено.\n");
    }

    close(fd);
    return EXIT_SUCCESS;
}
```

```cpp
#include <iostream>
#include <array>
#include <vector>
#include <cstring>
#include <chrono>
#include <thread>
#include <format>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <linux/kd.h>

class ConsolePaletteGuard {
public:
    explicit ConsolePaletteGuard(int fd) : fd_(fd) {
        if (::ioctl(fd_, GIO_CMAP, orig_cmap_.data()) < 0) {
            throw std::system_error(errno, std::generic_category(), "Не вдалося зчитати палітру GIO_CMAP");
        }
    }

    [[nodiscard]] const std::array<unsigned char, 48>& palette() const noexcept {
        return orig_cmap_;
    }

    void set_palette(const std::array<unsigned char, 48>& new_cmap) {
        if (::ioctl(fd_, PIO_CMAP, new_cmap.data()) < 0) {
            throw std::system_error(errno, std::generic_category(), "Не вдалося записати палітру PIO_CMAP");
        }
    }

    ~ConsolePaletteGuard() {
        ::ioctl(fd_, PIO_CMAP, orig_cmap_.data());
    }

private:
    int fd_;
    std::array<unsigned char, 48> orig_cmap_{};
};

int main() {
    int fd = ::open("/dev/tty0", O_RDWR | O_NOCTTY | O_CLOEXEC);
    if (fd < 0) {
        std::cerr << "Помилка відкриття /dev/tty0\n";
        return EXIT_FAILURE;
    }

    try {
        ConsolePaletteGuard guard(fd);

        std::cout << "Поточна палітра VGA DAC:\n";
        const auto& cmap = guard.palette();
        for (std::size_t i = 0; i < 16; ++i) {
            std::cout << std::format("  Колір {:2d}: R=0x{:02X} G=0x{:02X} B=0x{:02X}\n",
                                     i, cmap[i * 3], cmap[i * 3 + 1], cmap[i * 3 + 2]);
        }

        // Інспекція розмірів шрифту
        struct console_font_op font_op{};
        font_op.op = KD_FONT_OP_GET;
        if (::ioctl(fd, KDFONTOP, &font_op) == 0) {
            std::cout << std::format("Шрифт консолі: {}x{} пікселів, {} гліфів\n",
                                     font_op.width, font_op.height, font_op.charcount);
        }

        // Тимчасова зміна першого кольору
        auto mod_cmap = cmap;
        mod_cmap[3] = 0xFF; // R
        mod_cmap[4] = 0x55; // G
        mod_cmap[5] = 0x00; // B
        guard.set_palette(mod_cmap);
        std::cout << "Палітру модифіковано на 1 секунду...\n";
        std::this_thread::sleep_for(std::chrono::seconds(1));

    } catch (const std::exception& e) {
        std::cerr << "Помилка: " << e.what() << '\n';
        ::close(fd);
        return EXIT_FAILURE;
    }

    ::close(fd);
    std::cout << "Оригінальну палітру гарантовано відновлено (RAII).\n";
    return EXIT_SUCCESS;
}
```
