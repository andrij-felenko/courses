# 📋 Інтерфейс утиліт структурованого тексту: jq, yq, xsv та xmlstarlet

Цей довідник містить систематизований опис параметрів командного рядка, прапорців керування буферизацією, режимів зв'язування змінних та кодів виходу основних утиліт обробки структурованих форматів даних (JSON, YAML, CSV, XML) у середовищі Unix/Linux.

У традиційних конвеєрах Unix програми оперують нетипізованими послідовностями байтів, де роздільником за замовчуванням виступає символ нового рядка. При переході до структурованих форматів кожна утиліта встановлює строгий контракт взаємодії: спосіб завантаження документа в пам'ять, поведінку при обриві каналу, правила екранування спеціальних символів та семантику кодів повернення.

## 1. Процесор JSON: jq

Утиліта `jq` виконує синтаксичний розбір і трансформацію потоку документів JSON відповідно до переданого виразу. Вона спроєктована на основі парадигми функціональних генераторів: кожен фільтр приймає одне значення на вході й продукує потік із нуля, одного або багатьох значень на виході.

### Сигнатура виклику

Команда приймає набір опцій, обов'язковий вираз мови фільтрів та необов'язковий список файлів для обробки. Якщо файли не вказано, читання здійснюється зі стандартного вхідного потоку.

```
jq [параметри] '<вираз-фільтр>' [файл ...]
```

### Прапорці керування потоком і форматуванням

- `-r` (`--raw-output`): якщо результуюче значення є рядком, воно виводиться безпосередньо у стандартний потік виводу без обрамлення подвійними лапками та без екранування керуючих символів. Числові, булеві значення, масиви та об'єкти виводяться у стандартному форматі JSON. Цей прапорець є основним інструментом для передачі текстових значень іншим утилітам POSIX (`xargs`, `curl`, `tee`). Використання пам'яті залишається константним для кожного запису.
- `-c` (`--compact-output`): форматує кожен вихідний JSON-документ у вигляді єдиного суцільного рядка без переносів і зайвих пробілів. Саме цей режим використовується для генерації потоків у форматі JSON Lines (ndjson), забезпечуючи потокову обробку записів наступними ланками конвеєра.
- `-n` (`--null-input`): утиліта повністю ігнорує стандартний вхід і не очікує передачі даних через канал; натомість у фільтр передається єдине значення `null`. Застосовується для генерації нових структур або об'єднання зовнішніх файлів за допомогою функцій `inputs` чи прапорця `--slurpfile`.
- `-s` (`--slurp`): перемикає утиліту зі стрімінгового режиму в режим повної акумуляції. Усі вхідні JSON-об'єкти вичитуються з потоку до досягнення кінця файлу (`EOF`) і збираються в єдиний масив у пам'яті. Це блокує передачу даних по конвеєру до повного завершення читання і вимагає обсягу оперативної пам'яті, пропорційного повному розміру вхідних даних.
- `-R` (`--raw-input`): читає кожен рядок вхідного потоку як звичайний текст, не намагаючись розпарсити його як JSON. Рядок загортається в об'єкт типу string і передається у фільтр. У поєднанні з прапорцем `-s` весь вхідний потік стає одним суцільним рядком.
- `-e` (`--exit-status`): модифікує логіку встановлення коду повернення процесу на основі обчисленого результату. Якщо останнє значення виразу дорівнює `false` або `null`, процес завершується з кодом 1. Якщо фільтр взагалі не згенерував жодного значення, повертається код 4. За відсутності помилок і наявності істинного значення повертається 0.
- `-f <шлях>` (`--from-file <шлях>`): зчитує вираз-фільтр із зазначеного файлу. Це дозволяє організовувати складні багаторядкові сценарії трансформації з коментарями, уникаючи проблем з екрануванням лапок у командному рядку оболонки.
- `--tab`: примусово використовує символ табуляції для кожного рівня відступу замість стандартних двох пробілів.
- `--unbuffered`: вимикає буферизацію стандартного потоку виводу на рівні бібліотеки libc. Кожен згенерований об'єкт негайно скидається в дескриптор виводу системним викликом `write(2)`. Це критично для обробки журналів подій у реальному часі.
- `-S` (`--sort-keys`): впорядковує ключі всіх об'єктів за алфавітом перед виводом, що забезпечує детермінізм тексту для подальшого порівняння за допомогою `diff`.

### Параметризоване зв'язування змінних

Безпечна передача змінних оточення та аргументів сценарію у фільтри `jq` здійснюється виключно через спеціальні прапорці зв'язування, які гарантують ізоляцію даних від синтаксичного дерева виразу:

- `--arg <ім'я> <значення>`: зв'язує вказане рядкове значення зі змінною `$<ім'я>`. Значення трактується суворо як рядковий літерал, символи лапок і службові оператори всередині нього не інтерпретуються парсером, що унеможливлює ін'єкції коду.
- `--argjson <ім'я> <json-текст>`: виконує синтаксичний розбір переданого тексту як JSON і прив'язує отриманий об'єкт, масив, число чи булеве значення до змінної `$<ім'я>`. Якщо рядок не є валідним JSON, процес завершується з помилкою парсингу до початку виконання основного фільтра.
- `--slurpfile <ім'я> <шлях>`: зчитує всі JSON-документи з файлу за вказаним шляхом, поміщає їх у масив і зберігає у змінну `$<ім'я>`.
- `--rawfile <ім'я> <шлях>`: вичитує весь вміст файлу як єдиний рядковий літерал без модифікації та прив'язує його до змінної `$<ім'я>`.

### Коди завершення процесу

- `0`: Успішне завершення виконання фільтра без помилок часу виконання чи синтаксичних збоїв.
- `1`: Останній вираз повернув `false` або `null` (за умови використання прапорця `-e`).
- `2`: Помилка розбору аргументів командного рядка або некоректно передані прапорці.
- `3`: Синтаксична помилка під час компіляції виразу `jq` в абстрактне синтаксичне дерево.
- `4`: Фільтр повернув порожній потік значень (за умови використання прапорця `-e`).
- `5`: Фатальна помилка часу виконання (наприклад, спроба ділення на нуль або індексація скалярного значення як об'єкта).

## 2. Процесор YAML: yq (Go-реалізація Майка Фараха)

Утиліта `yq` реалізує мову запитів і трансформацій для формату YAML. На відміну від ранніх Python-обгорток, вона зберігає структуру вихідного документа, включаючи коментарі, порядок полів та специфічні стилі оформлення відступів.

### Сигнатура виклику

```
yq [параметри] '<вираз-фільтр>' [файл ...]
```

### Прапорці операцій і керування форматом

- `-i` (`--inplace`): виконує редагування файлу безпосередньо на диску. Для забезпечення надійності утиліта створює тимчасовий файл у тій самій файловій системі, записує результат, синхронізує буфери і виконує системний виклик `rename(2)`. Це гарантує атомарність оновлення: при збої живлення чи падінні процесу оригінальний файл не буде пошкоджений або обрізаний.
- `-o=<формат>` (`--output-format=<формат>`): визначає вихідний формат представлення даних. Можливі значення: `yaml` (за замовчуванням), `json`, `props` (формат ключ-значення Java), `csv`, `tsv`, `xml`.
- `-p=<формат>` (`--input-format=<формат>`): явно задає формат вхідного потоку, якщо його неможливо визначити автоматично за розширенням файлу чи структурою байтів.
- `-r` (`--unwrapScalar`): витягує скалярні значення у чистому вигляді без лапок і службових префіксів YAML.
- `-e` (`--exit-status`): встановлює ненульовий код виходу, якщо результат фільтрації є порожнім або повертає значення `false`.
- `--indent <N>`: визначає кількість пробілів для формування одного рівня відступу (типово 2).
- `-C` (`--colors`): примусово активує кольорове оформлення виводу через escape-послідовності ANSI.
- `-M` (`--no-colors`): примусово вимикає кольорове підсвічування для забезпечення чистої передачі даних у наступні ланки конвеєра.
- `-N` (`--no-doc`): вимикає генерацію стандартного роздільника документів `---` на початку вихідного YAML.

### Семантика коментарів у YAML AST

Утиліта моделює коментарі як спеціальні метадані вузлів абстрактного синтаксичного дерева:
- `head_comment`: текстовий блок коментаря, розташований безпосередньо над оголошенням вузла.
- `line_comment`: коментар, розміщений на тому самому рядку праворуч від значення поля.
- `foot_comment`: коментар, розташований під блоком або структурою даних.

При модифікаціях вузлів ці атрибути можна оновлювати або очищати окремими функціями мови `yq`, що критично для автоматизованого супроводу конфігураційних файлів Kubernetes чи CI/CD.

## 3. Табличний процесор CSV/TSV: xsv

Утиліта `xsv` написана мовою Rust і спроєктована для високоефективної обробки табличних текстових даних формату CSV та TSV за стандартом RFC 4180. Її внутрішній парсер оптимізовано під векторні інструкції процесора (SIMD), що дозволяє обробляти потік зі швидкістю数百 мегабайтів на секунду.

### Сигнатура виклику

```
xsv <підкоманда> [параметри] [файл]
```

### Спеціалізовані підкоманди

- `index`: сканує вхідний CSV-файл і створює бінарний супровідний файл `<файл>.csv.idx`. Цей файл містить компактну таблицю байтових зміщень для кожного рядка даних. Наявність індексу дозволяє іншим підкомандам миттєво переходити до довільного запису через виклик `lseek(2)` без послідовного читання попередніх даних.
- `select`: виконує вибірку, фільтрацію та зміну порядку стовпців. Підтримує звернення як за назвами полів із заголовка (`xsv select "Status,UserID"`), так і за числовими індексами та діапазонами (`xsv select 1,3-5`). Працює в суто потоковому режимі з константним використанням пам'яті `O(1)`.
- `stats`: збирає повну описову статистику по кожній колонці таблиці в один або два проходи: автоматично визначає тип даних (Unicode, Integer, Float, Date), мінімальне та максимальне значення, середнє арифметичне, стандартне відхилення та кількість порожніх значень.
- `search`: фільтрує записи за допомогою регулярних виразів. Прапорець `-s <стовпець>` обмежує пошук конкретним полем, що значно прискорює сканування порівняно з неструктурованим `grep`.
- `slice`: витягує діапазон рядків за номерами. За наявності індексного файлу операція виконується за частки мілісекунди незалежно від того, чи вибираються рядки з початку десятигігабайтного файлу, чи з його кінця.
- `sort`: впорядковує таблицю за обраними стовпцями. Для сортування потрібне завантаження відповідних ключів у пам'ять, проте числове сортування (`-N`) оптимізоване за швидкістю.
- `join`: реалізує реляційне з'єднання двох CSV-таблиць (внутрішнє, ліве зовнішнє або повне) за зазначеними ключовими полями.
- `count`: підраховує точну кількість записів у файлі. За наявності індексу результат повертається миттєво з заголовка індексного файлу.
- `headers`: виводить нумерований список усіх назв колонок, що дозволяє швидко визначити структуру незнайомого датасету.

### Ключові глобальні параметри

- `-d <символ>` (`--delimiter <символ>`): перевизначає роздільник полів. Для обробки файлів TSV передається символ табуляції.
- `-n` (`--no-headers`): повідомляє утиліту, що перший рядок є звичайними даними, а не заголовком. У цьому режимі стовпці адресуються виключно порядковими номерами `1, 2, 3...`.
- `-o <шлях>` (`--output <шлях>`): перенаправляє результуючий вивід безпосередньо у файл на диску, оминаючи стандартний потік виводу.

## 4. Процесор XML: xmlstarlet

Утиліта `xmlstarlet` базується на системній бібліотеці `libxml2` і надає повноцінний інтерфейс для навігації, фільтрації та модифікації XML-документів за допомогою стандарту XPath 1.0.

### Сигнатура виклику

```
xmlstarlet <режим> [параметри] [файл ...]
```

### Основні режими роботи

- `sel` (`select`): режим вибірки даних і генерації текстових або табличних звітів за допомогою виразів XPath.
- `ed` (`edit`): режим редагування структури XML-документа: оновлення значень атрибутів і текстових вузлів, створення нових елементів та видалення непотрібних піддерев.
- `val` (`validate`): перевірка синтаксичної коректності документа та валідація проти схем DTD, XML Schema (XSD) або RelaxNG.
- `fo` (`format`): вирівнювання структури, форматування відступів або канонічне видалення зайвих пробільних символів.
- `c14n` (`canonicalize`): канонізація структури XML за специфікацією W3C для подальшої криптографічної перевірки цифрових підписів.

### Структура виклику режиму xmlstarlet sel

Режим вибірки вимагає створення шаблону перетворення через прапорець `-t`, після якого слідує послідовність дій над кожним вузлом:
- `-m <xpath>`: встановлює контекст ітерації (аналог конструкції циклу), перебираючи всі вузли, що відповідають зазначеному виразу.
- `-v <xpath>`: виводить обчислене значення виразу XPath або вміст атрибута поточного контекстного вузла.
- `-o <текст>`: вставляє у вихідний потік фіксований текстовий літерал (наприклад, кому або символ табуляції).
- `-n`: додає символ переходу на новий рядок після завершення обробки поточного елемента циклу.
- `-N <префікс>=<URI>`: реєструє простір імен XML. Це дозволяє адресувати вузли в документах зі складною схемою, усуваючи неоднозначність однакових тегів.
- `--var <ім'я>=<значення>`: безпечно прив'язує значення змінної XPath без використання склеювання рядків у командному рядку оболонки.

### Операції модифікації в режимі xmlstarlet ed

- `-u <xpath> -v <значення>`: змінює значення вузла чи атрибута, обраного за виразом XPath.
- `-d <xpath>`: безповоротно видаляє вибраний вузол або атрибут з дерева документа.
- `-s <xpath> -t elem -n <ім'я> -v <значення>`: додає новий дочірній елемент до обраного вузла.
- `-i <xpath> -t attr -n <ім'я> -v <значення>`: вставляє новий атрибут перед зазначеним елементом.

## 5. Зведена системна поведінка утиліт

| Утиліта | Модель пам'яті | Внутрішній буфер | Обробка сигналу SIGPIPE | Рекомендований сценарій у конвеєрі |
| :--- | :--- | :--- | :--- | :--- |
| **jq** | `O(1)` для NDJSON, `O(doc)` для звичайного JSON | Стандартний буфер libc (налаштовується через `--unbuffered`) | Завершується коректно без виводу помилок при закритті каналу читачем | Фільтрація, трансформація та агрегація ієрархічних потоків |
| **yq** | `O(doc)` на кожен документ | Повний буфер документа в пам'яті | Завершується після скидання поточного документа | Модифікація файлів конфігурації та трансляція YAML у JSON |
| **xsv** | `O(1)` для більшості підкоманд | Власний буфер блоків читання 64 КіБ | Миттєво перериває сканування великих файлів при зупинці конвеєра (`head`) | Високошвидкісна вибірка, сортування та статистика гігабайтних CSV |
| **xmlstarlet** | `O(doc)` — повне дерево DOM у RAM | Буферизація бібліотеки `libxml2` | Завершується лише після закінчення обробки поточного дерева DOM | Запити за схемами з просторами імен та точкова модифікація XML |
