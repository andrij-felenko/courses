# 📜 Від однорідної UMA до гетерогенної CXL: еволюція ієрархій пам'яті в Linux

Цей історичний нарис розкриває еволюцію підходів до організації адресного простору в ядрі Linux — від спрощеного припущення про однакову швидкість усієї оперативної пам'яті до створення багаторівневої підсистеми ярусів пам'яті (англ. *memory tiers*). Без розуміння того, чому класична модель NUMA виявилася непридатною для енергонезалежної та CXL-пам'яті, неможливо збагнути логіку сучасних алгоритмів деградації та підвищення сторінок.

## Епоха симетричної пам'яті: UMA та спрощена модель плоского адресного простору

На світанку розвитку Linux на архітектурі x86 панувала архітектура UMA (англ. *Uniform Memory Access*, однорідний доступ до пам'яті). У цій парадигмі всі центральні процесори підключалися до єдиної системної шини (Front Side Bus, FSB) і зверталися до єдиного контролера пам'яті на материнській платі (північного мосту). З погляду ядра кожна комірка пам'яті була еквівалентною будь-якій іншій: час доступу до адреси `0x1000` збігався з часом доступу до адреси `0x10000000` і складав усереднені 60–100 наносекунд.

Аллокатор ядра `mm/page_alloc.c` спирався на структуру `contig_page_data` типу `pg_data_t` (node 0) і ділив пам'ять лише за апаратними обмеженнями контролерів прямого доступу: `ZONE_DMA` (перші 16 МБ для ISA-пристроїв), `ZONE_NORMAL` (пам'ять, яку 32-бітне ядро могло напряму відобразити у свій простір) та `ZONE_HIGHMEM` (пам'ять понад 896 МБ). Ієрархія швидкодії всередині самої фізичної RAM була відсутня — будь-яке витіснення за межі доступного обсягу означало неминуче скидання сторінки у дисковий swap.

```
       [ CPU 0 ]    [ CPU 1 ]
            │           │
            └───┬───────┘
                │  Front Side Bus (FSB)
         [ Northbridge ] ──── [ Flat DRAM Pool ]
```

## Поява NUMA: географічна відстань між процесорами (2002–2012)

Із виходом багатопроцесорних серверів на базі Alpha, SGI Altix, а згодом Intel Xeon та AMD Opteron із вбудованими у кристал контролерами пам'яті (інтерфейси HyperTransport та Intel QPI), спільна шина стала вузьким місцем. Виникла архітектура NUMA (англ. *Non-Uniform Memory Access*, неоднорідний доступ до пам'яті, від лат. *non-uniformis* — неоднорідний).

У ядрі Linux 2.6 (завдяки роботам Мартіна Блаєва, Андрі ван де Вена та Мела Гормана) з'явилася підтримка кількох структур `pg_data_t` — по одній на кожен фізичний процесорний роз'єм (сокет). Фізичну пам'ять було розділено на вузли (NUMA nodes):
* **Локальна пам'ять (Local node):** пам'ять, підключена до контролера того самого процесора, на якому виконується потік. Затримка — мінімальна (≈60–80 нс).
* **Віддалена пам'ять (Remote node):** пам'ять сусіднього сокета. Запит проходить через міжпроцесорну шину (QPI/UPI/Infinity Fabric), що збільшує затримку у 1.5–2.5 рази (≈120–160 нс) та зменшує пропускну здатність.

Ядро навчилося враховувати цю неоднорідність за допомогою матриці відстаней SLIT (англ. *System Locality Information Table*) з таблиць ACPI. Локальний доступ отримав нормалізовану відстань `10`, а віддалений сокет — `20` чи `30`.

```
  [ Socket 0 / Node 0 ] ◄─── UPI / IF (1.5x Latency) ───► [ Socket 1 / Node 1 ]
         │                                                        │
  [ Local DDR5 RAM ]                                       [ Local DDR5 RAM ]
```

Проте ця модель передбачала важливу симетрію:
1. Кожен NUMA-вузол мав у своєму складі як фізичну пам'ять, так і процесорні ядра (`N_CPU` та `N_MEMORY`).
2. Тип пам'яті на всіх вузлах був однаковим — динамічна пам'ять (DRAM).
3. Головним завданням ядра була прив'язка обчислень до пам'яті: якщо потік працює на сокеті 0, його пам'ять має виділятися на вузлі 0. Якщо потік мігрує на сокет 1, підсистема AutoNUMA (розроблена Петером Зейлстрою та Мелом Горманом у ядрі 3.8) поступово перетягує за ним і його сторінки.

## Криза моделі: поява Persistent Memory та перші спроби розшарування (2015–2020)

У середині 2010-х років концепція симетричної NUMA зіткнулася з новою реальністю. Поява енергонезалежної пам'яті NVDIMM (зокрема Intel Optane DC Persistent Memory) принесла в сервери модулі, які встановлювалися у звичайні слоти DDR4, але мали принципово інші характеристики:
* Величезний обсяг за нижчою ціною (до 512 ГБ на модуль).
* Затримка читання у 2–4 рази вища за звичайну DRAM (200–350 нс).
* Швидкість запису значно нижча за швидкість читання через фізику фазового переходу (Phase Change Memory, PCM).

Спочатку ядра Linux надавали доступ до такої пам'яті як до блокових пристроїв `/dev/pmemX` із підтримкою прямого доступу через DAX (Direct Access). Але розробники баз даних (In-Memory DB) вимагали прозорого використання цього гігантського пулу як звичайної системної пам'яті для розширення адресного простору процесів.

Драйвер `kmem` дозволив ініціалізувати PMEM як звичайний безпроцесорний NUMA-вузол (CPU-less node). Однак класичне ядро Linux не розуміло різниці між DRAM та PMEM:
1. **Сліпе виділення пам'яті:** функція `alloc_pages()` могла виділити для стеку або гарячих структур ядра сторінку з повільної PMEM замість швидкої DRAM.
2. **Збій AutoNUMA:** демон автоматичного балансування намагався переміщувати сторінки між вузлом сокета та вузлом PMEM так, ніби це два звичайні сокети, генеруючи нескінченний трафік міграції без жодного виграшу в локальності (адже на вузлі PMEM не було CPU, до яких можна було б наблизити дані).
3. **Витіснення на диск замість другого ярусу:** коли на сокеті 0 закінчувалася швидка DRAM, демон `kswapd` починав вивантажувати анонімні сторінки у swap на диск або стискати їх у zRAM, замість того щоб скинути їх у вільні терабайти доступної PMEM.

## Революція CXL та народження підсистеми memory_tiers (2020–2023)

Остаточним поштовхом до повної перебудови підсистеми управління пам'яттю стала стандартизація інтерфейсу Compute Express Link (CXL 1.1 / 2.0 / 3.0). Протокол CXL.mem дозволив підключати контролери пам'яті через шину PCIe 5.0/6.0, надаючи процесору апаратну когерентність кешів та пряму адресацію фізичної пам'яті розширювачів (Memory Expanders).

У серверах з'явилася принципово багаторівнева гетерогенна пам'ять:
* **Ярус 0 (Верхній, Top-tier):** надшвидка локальна пам'ять HBM або DDR5 (60–80 нс, сотні гігабайтів/с).
* **Ярус 1 (Нижній, Slow-tier):** масштабована CXL.mem-пам'ять через комутатори PCIe (150–250 нс).
* **Ярус 2:** пули розділюваної пам'яті (CXL Shared Memory) та енергонезалежні сховища.

Інженери Intel (Хуан Ін, Дейв Хансен, Фенгуан У) та Meta (Йоганнес Вайнер) запропонували відмовитися від спроби вмістити гетерогенну пам'ять у застарілу метрику ACPI SLIT. У серії патчів для ядер Linux 5.15–6.1 вони створили окрему підсистему **Memory Tiers** (`mm/memory-tiers.c`):

1. **Абстрактна дистанція (Abstract Distance):** замість геометричних відстаней сокетів ядро ввело числову метрику продуктивності (латентність + пропускна здатність), яка автоматично зчитується з таблиць ACPI HMAT (Heterogeneous Memory Attribute Table) та CXL CDAT (Coherent Device Attribute Table).
2. **Асинхронний спуск (Demotion) замість Swap:** підсистему витіснення `kswapd` навчили новому кроку — перед вивантаженням сторінки на блоковий пристрій вона мігрує по конвеєру пам'яті вниз (`Top-tier DRAM → Slow-tier CXL`) за допомогою `migrate_pages(MR_DEMOTION)`.
3. **Адаптивна AutoNUMA для промоції:** механізм перехоплення звернень (NUMA Hint Faults) було адаптовано для розрізнення напрямку міграції: він піднімає гарячі сторінки з CXL у DRAM з урахуванням квот пропускної здатності шини.

Ця еволюція перетворила Linux із системи з пласкою моделлю оперативної пам'яті на повноцінну багаторівневу ієрархічну платформу, здатну автоматично керувати петабайтами комбінованої швидкої та повільної пам'яті без втручання коду прикладних програм.
