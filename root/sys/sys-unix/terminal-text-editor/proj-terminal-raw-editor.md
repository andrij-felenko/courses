# ⚙️ Реалізація мінімального рушія термінального редактора

Побудова повноекранного текстового редактора для термінала без використання високорівневих бібліотек (на кшталт `ncurses`) вимагає безпосередньої взаємодії з лінійною дисципліною ядра операційної системи, протоколом керуючих послідовностей ANSI/VT100 та організації низькорівневої буферизації введення-виведення.

Програма керує терміналом як матрицею моноширинних комірок, де кожне натискання клавіші обробляється миттєво, а оновлення екрана відбувається без візуальних артефактів та мерехтіння.

## Архітектурна модель: відмова від бібліотечних абстракцій

Класичні консольні програми використовують стандартну бібліотеку `stdio` (`printf`, `scanf`, `fgets`), розраховану на потоковий ввід-вивід. У такій моделі взаємодії виникають три фундаментальні обмеження:

1. **Рядкова буферизація ядра:** системний виклик `read(STDIN_FILENO, ...)` блокує виконання процесу доти, доки користувач не натисне клавішу `Enter`. Редактор не може реагувати на натискання окремих символів, навігаційних стрілок чи комбінацій модифікаторів у реальному часі.
2. **Локальне відлуння (Echo):** драйвер TTY автоматично малює кожен введений символ на екрані на поточній позиції апаратного курсора. Якщо програма намагається самостійно позиціонувати текст, автоматичне відлуння ядра руйнує кадр інтерфейсу.
3. **Перехоплення керуючих сигналів:** натискання комбінацій `Ctrl+C`, `Ctrl+Z` або `Ctrl+\` генерує асинхронні сигнали ядра `SIGINT`, `SIGTSTP` та `SIGQUIT`, які за замовчуванням аварійно завершують або зупиняють процес замість передачі кодів клавіш у редактор.

Щоб подолати ці обмеження, архітектура автономного текстового редактора будується на п'яти узгоджених підсистемах:

```
[ Клавіатура ] ---> [ TTY Driver (Raw Mode) ] ---> [ read() / 100ms Timeout ]
                                                               |
                                                               v
                                                    [ Input Event Parser ]
                                                    (Escape State Machine)
                                                               |
                                                               v
[ Double-Buffered Frame ] <--- [ Viewport & Cursor ] <--- [ Command Dispatcher ]
(Append Buffer: abuf)         (Translation: doc->scr)          |
         |                                                     v
         v                                             [ Text Storage ]
[ write(STDOUT_FILENO) ]                             (Gap Buffer / Array)
```

1. **Підсистема керування терміналом (TTY Control):** конфігурація структури `termios` для перемикання термінальної лінії в сирий режим (Raw Mode) та гарантоване відновлення початкового стану термінала при завершенні процесу.
2. **Парсер вхідного потоку подій (Input Event Parser):** скінченний автомат, що зчитує потік сирих байтів з `STDIN_FILENO`, розпізнає багатобайтові Escape-послідовності (ANSI/VT100) та транслює їх у внутрішні кодові константи дій (`EditorKey`).
3. **Ядро зберігання тексту (Text Storage & State):** структури даних для представлення рядків документа в пам'яті, що оптимізують операції вставки, видалення символів та вертикальної навігації.
4. **Контролер проєкції (Viewport & Coordinate Translation):** модуль трансляції логічних двовимірних координат документа `(file_row, file_col)` у фізичні екранні координати матриці `(screen_row, screen_cols)` з урахуванням зміщення прокрутки (`row_offset`, `col_offset`).
5. **Подвійна буферизація виведення (Double-Buffered Frame Renderer):** генератор графічного кадру, який компонує весь вміст екрана разом із керуючими послідовностями позиціонування курсора в єдиному акумулюючому буфері оперативної пам'яті (`struct ABuffer` або `std::string`) і скидає його в термінал рівно одним системним викликом `write()`.

## Керування термінальною лінією через termios

У середовищі POSIX/Linux терміналом керує підсистема лінійної дисципліни `N_TTY`, яка розташована в ядрі між фізичним чи емульованим пристроєм введення та системними викликами процесу. За замовчуванням лінія працює в **канонічному режимі** (Canonical Mode).

Для отримання повного контролю редактор використовує системні виклики `tcgetattr()` та `tcsetattr()`, модифікуючи бітові поля структури `struct termios` (`#include <termios.h>`).

### Бітові маски та призначення прапорців

Переведення термінала в сирий режим (Raw Mode) вимагає скидання конкретних бітових масок у чотирьох конфігураційних полях структури:

:::tabs
```c
struct termios raw = orig_termios;

// 1. Вхідні прапорці (Input Modes)
raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON);

// 2. Вихідні прапорці (Output Modes)
raw.c_oflag &= ~(OPOST);

// 3. Прапорці керування лінією (Control Modes)
raw.c_cflag |= (CS8);

// 4. Локальні прапорці (Local Modes)
raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG);

// 5. Керуючі символи та таймаути (Control Characters)
raw.c_cc[VMIN] = 0;
raw.c_cc[VTIME] = 1;
```
```cpp
// Конфігурація бітових масок у конструкторі сесії C++
struct termios raw = orig_termios_;

raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON);
raw.c_oflag &= ~(OPOST);
raw.c_cflag |= (CS8);
raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG);
raw.c_cc[VMIN] = 0;
raw.c_cc[VTIME] = 1;

if (tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw) == -1) {
    throw std::runtime_error("Не вдалося встановити сирий режим термінала");
}
```
:::

Кожен прапорець відповідає за ізольовану функцію низькорівневої обробки:

* **`ECHO` (Local Modes):** вимикає локальне відлуння. Коли користувач натискає символ на клавіатурі, ядро більше не відсилає його назад на екран. Редактор бере малювання символів під свій абсолютний контроль.
* **`ICANON` (Local Modes):** вимикає канонічний режим. Виклики `read()` перестають чекати символу закінчення рядка `\n` і повертають байти негайно по мірі їх надходження.
* **`ISIG` (Local Modes):** вимикає генерацію сигналів переривання. Натискання `Ctrl+C` (ASCII `0x03`), `Ctrl+Z` (ASCII `0x1A`) та `Ctrl+\` (ASCII `0x1C`) більше не надсилають процесу сигнали `SIGINT`, `SIGTSTP` і `SIGQUIT`, а потрапляють у вхідний буфер як звичайні числові байти. Це дає змогу призначати ці комбінації на команди програми (наприклад, скасування пошуку або вихід).
* **`IEXTEN` (Local Modes):** вимикає розширену обробку вводу POSIX. Зокрема, вимикає спеціальну поведінку `Ctrl+V` (яка змушує термінал чекати наступного символу для вставки його байтового значення без інтерпретації) та `Ctrl+O`.
* **`IXON` (Input Modes):** вимикає програмне керування потоком передачі даних (Software Flow Control / XON-XOFF). За замовчуванням комбінація `Ctrl+S` призупиняє передачу даних на термінал доти, доки не буде натиснуто `Ctrl+Q`. Вимкнення `IXON` звільняє комбінацію `Ctrl+S` для використання як команди збереження файлу.
* **`ICRNL` (Input Modes):** вимикає автоматичну трансляцію повернення каретки в новий рядок. За замовчуванням ядро перетворює байт `\r` (ASCII 13, що генерується клавішею Enter) на `\n` (ASCII 10). Після скидання прапорця редактор отримує точний байт `13`.
* **`BRKINT`, `INPCK`, `ISTRIP` (Input Modes):** захисні налаштування послідовної лінії. `BRKINT` вимикає надсилання `SIGINT` при розриві зв'язку (Break Condition), `INPCK` вимикає перевірку парності, а `ISTRIP` запобігає примусовому обнуленню 8-го біта кожного байта, що є обов'язковою вимогою для коректної обробки багатобайтового кодування UTF-8.
* **`OPOST` (Output Modes):** вимикає постобробку виведення (Output Post-Processing). У канонічному режимі ядро автоматично додає повернення каретки `\r` до кожного символу переведення рядка `\n`. Після вимкнення `OPOST` символ `\n` зміщує курсор лише на один рядок вниз, залишаючи його в тій самій горизонтальній колонці. Редактор бере керування курсором на себе і для переходу на початок нового рядка зобов'язаний явно надсилати послідовність `\r\n`.
* **`CS8` (Control Modes):** бітова маска встановлює довжину символу у 8 бітів на байт.

### Налаштування таймаутів у неканонічному режимі: VMIN і VTIME

Коли канонічний режим (`ICANON`) вимкнено, елементи масиву `c_cc` (Control Characters) із ключами `VMIN` та `VTIME` кардинально змінюють семантику системного виклику `read()`:

* `c_cc[VMIN]` — мінімальна кількість байтів, яку очікує системний виклик `read()`, перш ніж повернути керування процесу (діапазон від 0 до 255).
* `c_cc[VTIME]` — максимальний інтервал очікування даних, виражений у децисекундах (одиницях по 100 мілісекунд, діапазон від 0 до 255).

У реалізації редактора задано комбінацію `VMIN = 0` та `VTIME = 1`:

```
VMIN = 0, VTIME = 1  ===>  Таймаут читання = 1 × 100 мс = 100 мс
```

Якщо в черзі вводу з'являється хоча б один байт, виклик `read()` повертає його негайно. Якщо протягом 100 мілісекунд жодна клавіша не була натиснута, `read()` не зависає назавжди, а повертає `0`.

Це дає дві принципові переваги:
1. Цикл подій не навантажує процесор на 100% (як це було б при `VMIN = 0, VTIME = 0` у режимі безперервного опитування), але водночас регулярно прокидається для обробки фонових завдань чи оновлення статусу.
2. Алгоритм розбору клавіш отримує можливість надійно розрізняти одиночне натискання клавіші `Escape` від багатобайтових Escape-послідовностей навігації.

### Системний виклик tcsetattr і дія TCSAFLUSH

Застосування нової конфігурації здійснюється викликом `tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw)`.

Використання модифікатора `TCSAFLUSH` є критичним: він змушує ядро дочекатися, поки весь накопичений вихідний буфер буде передано на термінал, і одночасно **очищає (скидає) чергу вхідних даних**, які надійшли до виклику, але ще не були прочитані. Це запобігає випадковому виконанню залишкових символів, натиснутих користувачем у консолі перед стартом редактора.

## Гарантоване відновлення термінала: C проти C++

Якщо процес завершується аварійно (падіння по `SIGSEGV`, вихід по необробленому винятку або `exit()`), а термінал залишається в сирому режимі, користувач стикається з ефектом «зламаного термінала» (Broken Terminal): введений текст стає невидимим (немає `ECHO`), натискання `Enter` не повертає каретку на початок рядка (немає `ICRNL`), а команди шелу відмовляються працювати у звичному режимі.

Для запобігання цій ситуації мови C та C++ пропонують принципово різні механізми гарантії очищення ресурсів:

:::tabs
```c
// Реалізація на C: atexit() та обробники сигналів
static void disable_raw_mode(void) {
    tcsetattr(STDIN_FILENO, TCSAFLUSH, &E.orig_termios);
}

static void enable_raw_mode(void) {
    if (tcgetattr(STDIN_FILENO, &E.orig_termios) == -1) {
        perror("tcgetattr");
        exit(EXIT_FAILURE);
    }
    atexit(disable_raw_mode);
}

static void signal_handler(int sig) {
    disable_raw_mode();
    write(STDOUT_FILENO, "\x1b[?1049l\x1b[?25h", 14);
    signal(sig, SIG_DFL);
    raise(sig);
}
```
```cpp
// Реалізація на C++: інкапсуляція в RAII-клас TerminalSession
class TerminalSession {
public:
    TerminalSession() {
        if (tcgetattr(STDIN_FILENO, &orig_termios_) == -1) {
            throw std::runtime_error("Не вдалося отримати параметри termios");
        }

        struct termios raw = orig_termios_;
        raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON);
        raw.c_oflag &= ~(OPOST);
        raw.c_cflag |= (CS8);
        raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG);
        raw.c_cc[VMIN] = 0;
        raw.c_cc[VTIME] = 1;

        if (tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw) == -1) {
            throw std::runtime_error("Не вдалося встановити сирий режим термінала");
        }

        std::cout << "\x1b[?1049h" << std::flush;
    }

    ~TerminalSession() noexcept {
        std::cout << "\x1b[?1049l\x1b[?25h" << std::flush;
        tcsetattr(STDIN_FILENO, TCSAFLUSH, &orig_termios_);
    }

    TerminalSession(const TerminalSession&) = delete;
    TerminalSession& operator=(const TerminalSession&) = delete;

private:
    struct termios orig_termios_{};
};
```
:::

Переваги RAII-підходу:
1. **Безпека винятків (Exception Safety):** якщо будь-який компонент програми викидає виняток (`std::runtime_error`, `std::bad_alloc`), механізм розкручування стека (Stack Unwinding) автоматично викликає деструктор `~TerminalSession()`, гарантовано повертаючи термінал у вихідний стан.
2. **Семантика володіння:** видалені конструктор копіювання та оператор присвоєння виключають ситуацію, коли копія об'єкта сесії скидає параметри TTY посеред виконання програми.

### Альтернативний екранний буфер (Alternate Screen Buffer)

Професійні термінальні програми не повинні затирати історію командного рядка, з якого їх було викликано. Термінали стандарту ANSI/xterm підтримують два роздільні екранні буфери:

* **Вхід у редактор:** надсилання послідовності `\x1b[?1049h` перемикає дисплей на альтернативний буфер. Вміст консолі шелу залишається збереженим у пам'яті емулятора.
* **Вихід із редактора:** надсилання послідовності `\x1b[?1049l` повертає користувача в основний буфер зі збереженням усієї попередньої історії прокрутки.

## Парсинг ANSI/VT100 Escape-послідовностей

У сирому режимі термінал передає натискання клавіш у вигляді байтового потоку:
* Друковані символи ASCII (`'a'`, `'1'`, пробіл) приходять як окремі байти з числовими кодами від `32` до `126`.
* Керуючі комбінації з `Ctrl` транслюються бітовою маскою `ch & 0x1f`. Наприклад, `Ctrl+A` передає байт `1`, `Ctrl+Q` — байт `17`, `Ctrl+S` — байт `19`.
* Навігаційні та спеціальні клавіші не мають власних 8-бітних кодів в ASCII і надсилаються емулятором як багатобайтові Escape-послідовності.

### Структура керуючих послідовностей CSI та SS3

Майже всі функціональні послідовності починаються з байта `ESC` (`0x1B` або `\x1b`), за яким слідує префікс введення керуючої послідовності:

1. **CSI (*Control Sequence Introducer*) — `\x1b[` (байти `0x1B`, `0x5B`):**
   * **Двобайтові суфікси стрілок:**
     * `\x1b[A` — Стрілка вгору (Up)
     * `\x1b[B` — Стрілка вниз (Down)
     * `\x1b[C` — Стрілка вправо (Right)
     * `\x1b[D` — Стрілка вліво (Left)
     * `\x1b[H` — Home
     * `\x1b[F` — End
   * **Числові послідовності з тільдою `~`:**
     * `\x1b[1~` або `\x1b[7~` — Home
     * `\x1b[3~` — Delete
     * `\x1b[4~` або `\x1b[8~` — End
     * `\x1b[5~` — Page Up
     * `\x1b[6~` — Page Down
2. **SS3 (*Single Shift Select 3*) — `\x1bO` (байти `0x1B`, `0x4F`):**
   * `\x1bOH` — Альтернативний код клавіші Home на деяких терміналах
   * `\x1bOF` — Альтернативний код клавіші End

### Скінченний автомат декодера клавіш

Головний виклик полягає в тому, що коли системний виклик `read()` повертає байт `0x1B`, програма не може знати наперед: чи користувач натиснув одиночну клавішу `Escape`, чи це перший байт три- або чотирибайтової послідовності навігації.

Розв'язання базується на таймаутному дочитуванні черги дескриптора `STDIN_FILENO`:

```
                 +-----------------+
                 |  read() byte c  |
                 +--------+--------+
                          |
                  c == 0x1B (\x1b)?
                 /                 \
              [TAK]               [NI] ---> Повернути ASCII символ
                |
     read() 1 байт у seq[0]
     з таймаутом VTIME = 1
        /               \
     [Помилка/Таймаут] [Успіх]
       |                  |
   Повернути 0x1B     seq[0] == '[' чи 'O'?
   (Клавіша Escape)   /                   \
                   [TAK]                 [NI] ---> Повернути 0x1B
                     |
            read() 1 байт у seq[1]
            з таймаутом VTIME = 1
                     |
            Розбір суфікса:
            - 'A'..'D' -> Стрілки
            - '0'..'9' -> read() seq[2] для '~' -> PageUp, PageDown, Delete
            - 'H' / 'F' -> Home / End
```

### Обробка системних помилок EINTR та EAGAIN

Під час виконання блокуючого або таймаутного виклику `read()` ядро може надіслати процесу сигнал (наприклад, `SIGWINCH` при зміні розміру вікна). У цьому випадку виклик `read()` переривається, повертає `-1`, а змінна `errno` встановлюється у значення `EINTR` (*Interrupted System Call*).

Якщо ж у черзі немає даних під час неблокуючого читання, `errno` набуває значення `EAGAIN` або `EWOULDBLOCK`.

Декодер зобов'язаний явно фільтрувати ці помилки:

:::tabs
```c
static int editor_read_key(void) {
    int nread;
    char c;
    while ((nread = read(STDIN_FILENO, &c, 1)) != 1) {
        if (nread == -1 && errno != EAGAIN && errno != EINTR) {
            perror("read");
            exit(EXIT_FAILURE);
        }
    }

    if (c == '\x1b') {
        char seq[3];
        if (read(STDIN_FILENO, &seq[0], 1) != 1) return '\x1b';
        if (read(STDIN_FILENO, &seq[1], 1) != 1) return '\x1b';
        if (seq[0] == '[') {
            if (seq[1] >= '0' && seq[1] <= '9') {
                if (read(STDIN_FILENO, &seq[2], 1) != 1) return '\x1b';
                if (seq[2] == '~') {
                    switch (seq[1]) {
                        case '1': return HOME_KEY;
                        case '3': return DEL_KEY;
                        case '4': return END_KEY;
                        case '5': return PAGE_UP;
                        case '6': return PAGE_DOWN;
                        case '7': return HOME_KEY;
                        case '8': return END_KEY;
                    }
                }
            } else {
                switch (seq[1]) {
                    case 'A': return ARROW_UP;
                    case 'B': return ARROW_DOWN;
                    case 'C': return ARROW_RIGHT;
                    case 'D': return ARROW_LEFT;
                    case 'H': return HOME_KEY;
                    case 'F': return END_KEY;
                }
            }
        }
        return '\x1b';
    }
    return c;
}
```

## Опитування геометрії вікна та адаптація до розміру екрана

Щоб побудувати коректний кадр і розрахувати межі в'юпорту, редактор повинен знати точну кількість рядків і колонок термінала.

### Системний виклик ioctl(TIOCGWINSZ)

Основним способом отримання розмірів екрана в Unix є системний виклик `ioctl` до дескриптора термінала з командою `TIOCGWINSZ` (*Terminal I/O Control Get Window Size*):

:::tabs
```c
static int get_window_size(int *rows, int *cols) {
    struct winsize ws;
    if (ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws) == -1 || ws.ws_col == 0) {
        return -1;
    }
    *cols = ws.ws_col;
    *rows = ws.ws_row;
    return 0;
}
```
```cpp
void TerminalEditor::update_window_size() {
    struct winsize ws{};
    if (ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws) == 0 && ws.ws_col > 0) {
        screen_cols_ = ws.ws_col;
        screen_rows_ = ws.ws_row;
    } else {
        throw std::runtime_error("Не вдалося визначити геометрію вікна через ioctl");
    }
}
```
:::

Структура `struct winsize` містить поля `ws_row` (кількість рядків) та `ws_col` (кількість колонок). Опитування виконується через дескриптор `STDOUT_FILENO`, оскільки він гарантовано вказує на активний термінальний дисплей.

### Запасний спосіб через звіт позиції курсора (CPR)

На нестандартних або віртуальних послідовних лініях виклик `ioctl(TIOCGWINSZ)` може повернути нульові значення або помилку. У такому разі застосовується резервний алгоритм:

1. Редактор надсилає команду переміщення курсора у завідомо недосяжні координати правого нижнього кута: `write(STDOUT_FILENO, "\x1b[999C\x1b[999B", 12)` (зсув на 999 позицій вправо і 999 вниз). Емулятор термінала обмежує рух реальними межами вікна.
2. Програма надсилає запит звіту про статус пристрою: `write(STDOUT_FILENO, "\x1b[6n", 4)` (*Device Status Report / Cursor Position Report*).
3. Термінал надсилає у відповідь через `STDIN_FILENO` послідовність формату `\x1b[<rows>;<cols>R`.
4. Програма зчитує цю відповідь і парсить максимальні значення рядків та колонок.

## Рендеринг екрана: подвійна буферизація (Append Buffer) без мерехтіння

Прямий запис кожного символу або керуючої команди у вихідний потік термінала через сотні дрібних викликів `printf()` чи `write()` породжує дві критичні інженерні проблеми:

1. **Мерехтіння екрана (Screen Flickering):** очищення екрана командою `\x1b[2J` перед кожним кадром змушує термінал на частку мілісекунди відображати порожній екран. Око людини фіксує цей стробоскопічний ефект, створюючи відчуття нестабільності інтерфейсу.
2. **Перемикання контексту ядра (User ↔ Kernel Context Switches):** кожен системний виклик `write()` змушує процесор переходити з простору користувача в простір ядра і назад. Оновлення матриці розміром 80×24 окремими викликами сповільнює рендеринг у десятки разів.

### Архітектура акумулюючого буфера

Для усунення мерехтіння редактор застосовує **подвійну буферизацію**: весь графічний кадр — від приховування курсора до позиціонування у фінальній точці — спочатку формується в оперативній пам'яті в єдиному блоці (Append Buffer), а потім скидається в термінал **рівно одним системним викликом `write()`**.

:::tabs
```c
// Динамічний акумулюючий буфер у мові C
struct ABuffer {
    char *b;
    int len;
};

#define ABUF_INIT { NULL, 0 }

static void ab_append(struct ABuffer *ab, const char *s, int len) {
    char *new_buf = realloc(ab->b, ab->len + len);
    if (!new_buf) return;
    memcpy(&new_buf[ab->len], s, len);
    ab->b = new_buf;
    ab->len += len;
}

static void ab_free(struct ABuffer *ab) {
    free(ab->b);
}
```
```cpp
// Буферизація на основі std::string з оптимізацією алокацій
void TerminalEditor::render() {
    std::string frame;
    // Одноразове виділення блоку під повну площину кадру разом із керуючими кодами
    frame.reserve(screen_rows_ * (screen_cols_ + 16));

    frame += "\x1b[?25l\x1b[H";
    // ... формування рядків ...
    frame += std::format("\x1b[{};{}H\x1b[?25h", cursor_y_ + 1, cursor_x_ + 1);

    ::write(STDOUT_FILENO, frame.data(), frame.size());
}
```
:::

Завдяки попередньому розрахунку максимального розміру кадру `std::string` уникає повторних динамічних алокацій під час рендерингу (Zero Allocations Per Frame), що гарантує максимальну продуктивність.

### Конвеєр побудови кадру (Frame Pipeline)

Формування кадру відбувається за строго визначеною послідовністю із семи кроків:

```
[ Крок 1: \x1b[?25l ] ---> Приховати курсор (прибрати мерехтіння)
         |
[ Крок 2: \x1b[H ]    ---> Повернути курсор у початок екрана (1, 1)
         |
[ Крок 3: Рядки ]     ---> Записати видимі рядки тексту або маркер '~'
         |
[ Крок 4: \x1b[K ]    ---> Очистити рядок праворуч від тексту (Erase in Line)
         |
[ Крок 5: \r\n ]      ---> Перевести рядок (обидва символи, бо OPOST вимкнено)
         |
[ Крок 6: \x1b[y;xH ] ---> Позиціонувати курсор у координати редактора
         |
[ Крок 7: \x1b[?25h ] ---> Показати курсор
         |
[ write(stdout) ]    ---> Єдиний системний виклик на весь кадр
```

1. **Приховати курсор (`\x1b[?25l`):** поки буфер переписує символи рядків, курсор тимчасово вимикається. Це усуває візуальні артефакти «стрибаючого курсора» по екрану під час оновлення тексту.
2. **Перемістити курсор у верхній лівий кут (`\x1b[H`):** замість повільного і мерехтливого стирання всього екрана `\x1b[2J`, програма просто повертає точку друку в позицію `(1, 1)`. Нові символи безпосередньо перезаписують старі.
3. **Відобразити вміст видимих рядків:** відмалювати символи буфера документа або вивести тильди `~` на порожніх рядках поза текстом (як у `vi`).
4. **Очистити залишок рядка (`\x1b[K`):** після виведення кожного рядка тексту надсилається послідовність `\x1b[K` (*Erase in Line*). Вона стирає старі символи від кінця нового рядка до правого краю вікна. Це усуває графічне сміття від попереднього довшого рядка без повного очищення екрана.
5. **Явний перехід на новий рядок (`\r\n`):** оскільки прапорець `OPOST` вимкнено, обов'язково надсилаються обидва символи: `\r` (повернення каретки в крайню ліву позицію) та `\n` (зсув на рядок вниз).
6. **Встановити координати курсора (`\x1b[<row>;<col>H`):** обчислити позицію курсора з урахуванням логічного зміщення редактора і транслювати 0-індексовані координати програми в 1-індексовані координати ANSI: `snprintf(buf, sizeof(buf), "\x1b[%d;%dH", E.cy + 1, E.cx + 1);`.
7. **Показати курсор (`\x1b[?25h`):** увімкнути видимість курсора у фінальній позиції перед відправкою кадру.
8. **Атомарне скидання:** надіслати готовий масив байтів через `write(STDOUT_FILENO, ab.b, ab.len)`.

## Структури даних для буфера тексту: масиви, Gap Buffer та Piece Table

Спосіб організації тексту в пам'яті визначає алгоритмічну складність редагування та масштабованість програми при роботі з файлами різного розміру.

### 1. Динамічний масив рядків (Array of Lines)

Документ зберігається як масив покажчиків на динамічні рядки (`char**` у C або `std::vector<std::string>` у C++):

* **Довільний доступ:** знайти рядок за номером `N` коштує `O(1)`.
* **Вставка символу:** вимагає виклику `realloc()` та зсуву пам'яті всередині рядка через `memmove()` за час `O(L)`, де `L` — довжина рядка.
* **Вставка нового рядка:** вимагає зсуву масиву покажчиків рядків за час `O(N)`, де `N` — кількість рядків у файлі.
* **Застосування:** мінімалістичні та навчальні редактори (Kilo, Nano). Ідеальний баланс простоти та швидкодії для файлів розміром до кількох мегабайтів.

### 2. Буфер із проміжком (Gap Buffer)

Текст зберігається в одному суцільному блоці пам'яті, всередині якого виділено штучний вільний простір («проміжок», Gap). Початок проміжку завжди синхронізований із поточною позицією курсора:

```
Пам'ять буфера:
[ Текст до курсора ][       Вільний простір (Gap)       ][ Текст після курсора ]
                     ^                                   ^
                 gap_start                            gap_end
```

* **Вставка символу:** символ записується в позицію `gap_start`, індекс `gap_start` збільшується на 1. Це операція зі складністю `O(1)`.
* **Видалення символу (Backspace):** зменшує індекс `gap_start` на 1, що також виконується за `O(1)`.
* **Переміщення курсора:** текст між старою і новою позиціями курсора копіюється через вільний проміжок функцією `memmove()` за час `O(K)`, де `K` — відстань переміщення. Оскільки людина зазвичай вводить багато символів підряд в одному місці, витрати на зсув проміжку амортизуються.
* **Застосування:** GNU Emacs, внутрішні буфери рядків у Kilo.

### 3. Таблиця фрагментів (Piece Table)

Текст розділяється на два незмінних (immutable) буфери:
1. **Original Buffer:** вихідний файл, відображений у пам'ять у режимі тільки для читання (часто через `mmap()`).
2. **Append Buffer:** буфер, куди послідовно дописуються всі нові символи, введені користувачем.

Сам документ описується послідовністю або збалансованим деревом дескрипторів (Pieces), де кожен дескриптор зберігає покажчик на буфер, початкове зміщення та довжину фрагмента:

* **Вставка тексту:** розбиває один дескриптор на два і додає між ними посилання на щойно записані байти в Append Buffer за час `O(log P)` (де `P` — кількість дескрипторів).
* **Переваги:** миттєве відкриття файлів гігабайтного розміру без копіювання пам'яті та природна, майже безкоштовна підтримка багаторівневого скасування дій (Undo/Redo) шляхом збереження знімків списку дескрипторів.
* **Застосування:** AbiWord, Visual Studio Code.

### Порівняльна характеристика моделей

| Модель буфера | Вставка в курсор | Видалення | Позиціонування курсора | Масштабування (>100 МБ) | Складність реалізації |
|---|---|---|---|---|---|
| **Масив рядків** | `O(L)` | `O(L)` | `O(1)` | Низька (зсуви масивів) | Мінімальна |
| **Gap Buffer** | `O(1)` аморт. | `O(1)` | `O(K)` | Середня (суцільний буфер) | Низька |
| **Piece Table** | `O(log P)` | `O(log P)` | `O(log P)` | Висока (`mmap`) | Середня |

## Математика в'юпорту та прокрутка документа

Коли розмір текстового документа перевищує фізичну кількість рядків і колонок термінала, редактор реалізує механізм віртуального вікна перегляду (Viewport).

### Логічні проти фізичних координат

Стан редактора оперує двома системами координат:
* **Локальні координати у файлі:** `(E.cy, E.cx)` — номер рядка в документі та зміщення символу від початку рядка.
* **Зсув вікна перегляду:** `E.rowoff` (вертикальний зсув рядків) та `E.coloff` (горизонтальний зсув колонок).
* **Екранні координати:** обчислюються як `screen_y = E.cy - E.rowoff` та `screen_x = E.cx - E.coloff`.

### Алгоритм вертикальної та горизонтальної прокрутки

Перед кожним рендерингом кадру викликається функція `editor_scroll()`, яка коригує зміщення в'юпорту так, щоб курсор гарантовано залишався у видимій зоні екрана:

:::tabs
```c
static void editor_scroll(void) {
    // 1. Вертикальна прокрутка вгору: курсор вище видимого вікна
    if (E.cy < E.rowoff) {
        E.rowoff = E.cy;
    }
    // 2. Вертикальна прокрутка вниз: курсор опустився нижче краю вікна
    if (E.cy >= E.rowoff + E.screen_rows) {
        E.rowoff = E.cy - E.screen_rows + 1;
    }
    // 3. Горизонтальна прокрутка вліво
    if (E.cx < E.coloff) {
        E.coloff = E.cx;
    }
    // 4. Горизонтальна прокрутка вправо
    if (E.cx >= E.coloff + E.screen_cols) {
        E.coloff = E.cx - E.screen_cols + 1;
    }
}
```
```cpp
void TerminalEditor::update_scroll_offsets(int doc_rows, int doc_cols) {
    if (cursor_y_ < row_offset_) {
        row_offset_ = cursor_y_;
    }
    if (cursor_y_ >= row_offset_ + screen_rows_) {
        row_offset_ = cursor_y_ - screen_rows_ + 1;
    }
    if (cursor_x_ < col_offset_) {
        col_offset_ = cursor_x_;
    }
    if (cursor_x_ >= col_offset_ + screen_cols_) {
        col_offset_ = cursor_x_ - screen_cols_ + 1;
    }
}
```
:::

У функції малювання рядків `editor_draw_rows()` індекс вихідного рядка документа розраховується як `file_row = y + E.rowoff`. Якщо `file_row` знаходиться в межах документа, на екран виводиться відповідний горизонтальний зріз тексту, починаючи зі зміщення `E.coloff`.

## Реалізація на C та ідіоматичному C++

## Інженерні нюанси, профілювання та типові пастки

1. **Атомарність викликів write() та профілювання через strace:**
   Для перевірки відсутності зайвих системних викликів використовується утиліта `strace`:
   ```bash
   strace -e trace=read,write ./editor
   ```
   При натисканні кожної клавіші в лозі повинен з'являтися рівно один виклик `read(0, ...)` на отримання коду клавіші та **рівно один виклик `write(1, ...)` на кількасот байтів**, що містить весь скомпільований кадр. Якщо у виводі з'являються десятки дрібних викликів `write()` по 1–3 байти — подвійна буферизація зламана і термінал почне мерехтіти при зростанні навантаження.

2. **Обробка табуляцій і розрахунок позиції рендерингу (rx):**
   Символ табуляції `\t` займає в буфері тексту 1 байт, але на екрані моноширинного термінала повинен відображатися як кілька пробілів (зазвичай до наступної позиції, кратної 8).
   Тому координата курсора для рендерингу `rx` розраховується окремо від логічної координати `cx`:

:::tabs
```c
int rx = 0;
for (int j = 0; j < cx; j++) {
    if (row[j] == '\t') {
        rx += (TAB_STOP - 1) - (rx % TAB_STOP);
    }
    rx++;
}
```
```cpp
int calculate_render_x(std::string_view row, int cursor_x, int tab_stop = 8) {
    int rx = 0;
    for (int j = 0; j < cursor_x && j < static_cast<int>(row.size()); ++j) {
        if (row[j] == '\t') {
            rx += (tab_stop - 1) - (rx % tab_stop);
        }
        rx++;
    }
    return rx;
}
```
:::

   Фізичний курсор позиціонується на екрані саме за координатою `rx - E.coloff`.

3. **Багатобайтові послідовності UTF-8 та функція wcwidth():**
   У кодуванні UTF-8 один друкований символ може займати від 1 до 4 байтів. Крім того, деякі символи (наприклад, ієрогліфи CJK або емодзі) мають візуальну ширину у 2 екранні комірки, тоді як комбінувальні діакритичні знаки займають 0 комірок.
   Для коректного рендерингу редактор зобов'язаний розбирати байти у кодові точки Unicode та визначати їхню екранну ширину за допомогою функції POSIX `wcwidth(wchar_t c)`.

4. **Захист від блокування при читанні Escape:**
   Якщо після зчитування `\x1b` наступні байти не надходять протягом таймауту `VTIME = 1` (100 мс), функція `read()` повертає `0`. Парсер зобов'язаний негайно перервати розбір послідовності й повернути одиночний символ `\x1b`. Спроба виконати блокуюче читання наступного байта без таймауту призведе до зависання редактора щоразу, коли користувач натискає одиночну клавішу `Escape`.

5. **Очищення ресурсів при аварійних збоях:**
   Якщо під час виконання програми виникає помилка `SIGSEGV` через некоректну роботу з пам'яттю, термінал зобов'язаний повернутися в канонічний режим до того, як процес завершиться аварійним дампом. Поєднання RAII у C++ з обробниками сигналів POSIX забезпечує стабільність робочого середовища розробника за будь-яких умов.
