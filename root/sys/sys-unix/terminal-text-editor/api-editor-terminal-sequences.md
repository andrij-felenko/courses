# 📋 Протокол взаємодії редактора з TTY: послідовності, прапорці termios та ioctl

Довідник системних структур ядра, бітових масок термінальної підсистеми `termios` (POSIX.1-2008 / POSIX.1-2024), системних викликів `ioctl` та керуючих послідовностей ANSI/VT100 (ECMA-48), на яких базується взаємодія повноекранного текстового редактора з емулятором термінала.

## Контракт підсистеми `termios` (POSIX.1)

Драйвер термінальної лінії ядра (`N_TTY`) у канонічному стані буферизує вхідний потік до отримання байта переведення рядка, виконує локальне відлуння (`echo`) та генерує асинхронні сигнали процесу на спеціальні керуючі коди. Переведення термінала в небуферизований сирий режим (`Raw Mode`) вимагає прямої маніпуляції бітовими масками структури `struct termios` (`#include <termios.h>`).

### Системні виклики конфігурації лінії

#### 1. `tcgetattr` — зчитування поточного стану
```
int tcgetattr(int fd, struct termios *termios_p);
```
- **Параметри:** `fd` — відкритий файловий дескриптор термінала (`STDIN_FILENO`), `termios_p` — вказівник на структуру `struct termios`, куди ядро записує поточну конфігурацію.
- **Повертає:** `0` при успіху, `-1` при помилці.
- **Коди помилок (`errno`):**
  - `EBADF` — передано невалідний файловий дескриптор.
  - `ENOTTY` — дескриптор `fd` не асоційований із термінальним пристроєм (наприклад, потік перенаправлено у звичайний файл або анонімний пайп).
  - `EFAULT` — вказівник `termios_p` вказує на недосяжну або некоректну область пам'яті.
  - `EINTR` — виклик перервано сигналом ядра до завершення зчитування.

#### 2. `tcsetattr` — застосування нової конфігурації
```
int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);
```
- **Параметри:** `fd` — дескриптор термінала, `optional_actions` — режим застосування змін, `termios_p` — вказівник на структуру з новими параметрами.
- **Режими дії (`optional_actions`):**
  - `TCSANOW` — зміни набувають чинності негайно. Використовується для налаштувань, що не впливають на виведення (наприклад, зміна швидкості читання або локальних прапорців).
  - `TCSADRAIN` — зміни застосовуються лише після того, як увесь черговий потік вихідних даних із дескриптора `fd` буде фізично передано на термінал. Застосовується при зміні вихідних параметрів для запобігання пошкодженню кадру.
  - `TCSAFLUSH` — зміни застосовуються після повної передачі вихідних даних на термінал, при цьому весь незчитаний вхідний буфер термінала скидається (flush). Запобігає обробці залишкових натискань клавіш, введених користувачем до старту або завершення редактора.
- **Повертає:** `0` при успіху, `-1` при помилці.
- **Пастка часткового успіху (Partial Success):** За стандартом POSIX `tcsetattr()` повертає `0`, якщо вдалося застосувати *хоча б одне* з переданих налаштувань. Щоб переконатися, що всі критичні прапорці справді записані, після виклику `tcsetattr()` викликають `tcgetattr()` і перевіряють результуючі бітові маски.

#### 3. Допоміжні функції швидкості та стандартний помічник
- `speed_t cfgetispeed(const struct termios *termios_p);` — повертає швидкість вхідного потоку в бодах (`B9600`, `B38400`, `B115200`).
- `speed_t cfgetospeed(const struct termios *termios_p);` — повертає швидкість вихідного потоку.
- `int cfsetispeed(struct termios *termios_p, speed_t speed);` — задає вхідну швидкість.
- `int cfsetospeed(struct termios *termios_p, speed_t speed);` — задає вихідну швидкість.
- `void cfmakeraw(struct termios *termios_p);` — стандартна функція розширення glibc/BSD, яка встановлює набір прапорців, еквівалентний:
```
termios_p->c_iflag &= ~(IGNBRK | BRKINT | PARMRK | ISTRIP | INLCR | IGNCR | ICRNL | IXON);
termios_p->c_oflag &= ~OPOST;
termios_p->c_lflag &= ~(ECHO | ECHONL | ICANON | ISIG | IEXTEN);
termios_p->c_cflag &= ~(CSIZE | PARENB);
termios_p->c_cflag |= CS8;
termios_p->c_cc[VMIN] = 1;
termios_p->c_cc[VTIME] = 0;
```

### Поля структури `struct termios`

Структура `struct termios` містить п'ять незалежних полів конфігурації:
```
struct termios {
    tcflag_t c_iflag;      /* Режими вводу (Input Modes) */
    tcflag_t c_oflag;      /* Режими виводу (Output Modes) */
    tcflag_t c_cflag;      /* Режими керування лінією (Control Modes) */
    tcflag_t c_lflag;      /* Локальні режими (Local Modes) */
    cc_t     c_cc[NCCS];   /* Спеціальні керуючі символи та таймаути */
    speed_t  c_ispeed;     /* Вхідна швидкість (POSIX розширення) */
    speed_t  c_ospeed;     /* Вихідна швидкість (POSIX розширення) */
};
```

#### Вхідні прапорці (`c_iflag`)
Керують попередньою обробкою байтів, які надходять від клавіатури в ядро перед передачею в буфер процесу:

| Прапорець | Значення за замовчуванням | Дія при увімкненому прапорці | Наслідок вимкнення для редактора |
|---|---|---|---|
| `IXON` | Увімкнено | Програмне керування вихідним потоком XON/XOFF. `Ctrl+S` (`0x13`) призупиняє вивід, `Ctrl+Q` (`0x11`) відновлює. | `Ctrl+S` та `Ctrl+Q` передаються в процес як звичайні коди, звільняючи комбінації для збереження та виходу. |
| `IXOFF` | Вимкнено | Програмне керування вхідним потоком: система надсилає STOP/START, коли вхідний буфер ядра переповнюється. | Не використовується в емуляторах термінала; тримається вимкненим. |
| `IXANY` | Вимкнено | Будь-який введений символ (не лише XON) відновлює призупинений вивід. | Запобігає випадковому розблокуванню потоку. |
| `ICRNL` | Увімкнено | Автоматична трансляція вхідного символу повернення каретки `\r` (`0x0D`, Enter) у символ нового рядка `\n` (`0x0A`). | Редактор отримує точний байт `0x0D` (13) при натисканні Enter замість підміненого `0x0A`. |
| `INLCR` | Вимкнено | Трансляція вхідного `\n` у `\r`. | Вимикається, щоб зберегти пряме кодування. |
| `IGNCR` | Вимкнено | Ігнорування всіх вхідних символів `\r`. | Вимикається; інакше клавіша Enter не генеруватиме жодного коду. |
| `BRKINT` | Увімкнено | При виявленні сигналу переривання лінії (Break) скидаються черги TTY і процесу надсилається `SIGINT`. | Стан Break не генерує сигнал аварійної зупинки процесу. |
| `IGNBRK` | Вимкнено | Повне ігнорування стану Break на лінії. | Вмикається або залишається без змін у сирому режимі. |
| `INPCK` | Вимкнено | Увімкнення апаратної перевірки парності вхідних байтів. | Вимикається для усунення перевірок послідовного порту. |
| `ISTRIP` | Вимкнено | Скидання (обнулення) 8-го біта кожного вхідного байта (обрізання до 7-бітного ASCII). | Вимикається обов'язково: інакше всі багатобайтові послідовності UTF-8 спотворюються. |
| `PARMRK` | Вимкнено | Маркування помилок парності та Break префіксами `\377 \0`. | Вимикається для усунення службового сміття в потоці. |
| `IMAXBEL` | Увімкнено (Linux) | Подача сигналу дзвінка (BEL), якщо черга введення переповнена. | Залишається вимкненим або нейтральним. |
| `IUTF8` | Увімкнено (Linux) | Вказує драйверу лінії, що вхідні дані закодовані в UTF-8 (для коректного Backspace у канонічному режимі). | У сирому режимі не впливає на потік, оскільки ядро не обробляє Backspace. |

#### Вихідні прапорці (`c_oflag`)
Керують постобробкою байтів, які процес надсилає у вихідний потік термінала:

| Прапорець | Значення за замовчуванням | Дія при увімкненому прапорці | Наслідок вимкнення для редактора |
|---|---|---|---|
| `OPOST` | Увімкнено | Увімкнення системної постобробки виводу. | Вимикає будь-яке автоматичне втручання ядра у вихідний байтовий потік. |
| `ONLCR` | Увімкнено (при `OPOST`) | Автоматична трансляція вихідного `\n` (`0x0A`) у пару `\r\n` (`0x0D 0x0A`). | Вимикається разом з `OPOST`. Редактор зобов'язаний надсилати `\r\n` явно для переходу на початок нового рядка. |
| `OCRNL` | Вимкнено | Трансляція вихідного `\r` у `\n`. | Вимикається. |
| `ONOCR` | Вимкнено | Заборона надсилання `\r` у нульовій колонці. | Вимикається. |
| `ONLRET` | Вимкнено | Вважати символ `\n` поверненням каретки. | Вимикається. |

#### Прапорці керування лінією (`c_cflag`)
Визначають апаратні параметри передачі сигналів:

| Прапорець / Маска | Призначення | Значення для сирого режиму |
|---|---|---|
| `CSIZE` | Бітова маска розміру символу (`CS5`, `CS6`, `CS7`, `CS8`). | Встановлюється в `CS8` (8 бітів на байт) через вираз `c_cflag = (c_cflag & ~CSIZE) | CS8`. |
| `CSTOPB` | Кількість стоп-бітів: увімкнено — 2 стоп-біти, вимкнено — 1 стоп-біт. | Вимикається (`1` стоп-біт). |
| `CREAD` | Дозвіл прийому символів приймачем термінала. | Обов'язково встановлюється в `1` (`c_cflag |= CREAD`). |
| `PARENB` | Генерація біта парності при передачі та перевірка при прийомі. | Вимикається (`c_cflag &= ~PARENB`). |
| `PARODD` | Непарна парність (якщо `PARENB` увімкнено). | Вимикається. |
| `CLOCAL` | Ігнорування ліній керування модемом (Local Line). | Встановлюється в `1`, щоб запобігти генерації `SIGHUP` при зміні стану ліній зв'язку. |
| `CRTSCTS` | Апаратне керування потоком RTS/CTS (не входить у базовий POSIX). | Вимикається. |

#### Локальні прапорці (`c_lflag`)
Керують високорівневими режимами взаємодії з користувачем:

| Прапорець | Значення за замовчуванням | Дія при увімкненому прапорці | Наслідок вимкнення для редактора |
|---|---|---|---|
| `ECHO` | Увімкнено | Локальне відлуння: кожен введений символ негайно друкується терміналом на поточній позиції курсора. | Екран не засмічується; редактор самостійно малює символи у відповідні координати буфера. |
| `ICANON` | Увімкнено | Канонічний режим: введення накопичується в рядковому буфері ядра до натискання Enter; виклик `read()` спить. | Неканонічний режим: `read()` повертає байти негайно згідно з налаштуваннями `VMIN`/`VTIME`. |
| `ISIG` | Увімкнено | Перехоплення керуючих символів `INTR` (`Ctrl+C`), `QUIT` (`Ctrl+\`), `SUSP` (`Ctrl+Z`) з генерацією сигналів `SIGINT`, `SIGQUIT`, `SIGTSTP`. | Комбінації передаються в процес як звичайні числові байти (`0x03`, `0x1C`, `0x1A`), дозволяючи призначити їх на команди редактора. |
| `IEXTEN` | Увімкнено | Розширена обробка введення POSIX (літеральне екранування `Ctrl+V` та очищення `Ctrl+O`). | Звільняє `Ctrl+V` (вставка або шістнадцятковий ввід) та `Ctrl+O` для потреб редактора. |
| `ECHOE` | Увімкнено | Візуальне стирання символу при натисканні ERASE (Backspace) у канонічному режимі. | Неактивно при вимкненому `ICANON`. |
| `ECHOK` | Увімкнено | Виведення переведення рядка після натискання KILL (`Ctrl+U`) у канонічному режимі. | Неактивно при вимкненому `ICANON`. |
| `ECHONL` | Вимкнено | Відлуння символу `\n`, навіть якщо `ECHO` вимкнено. | Вимикається обов'язково. |
| `NOFLSH` | Вимкнено | Заборона скидання черг вводу/виводу при генерації сигналів `ISIG`. | Тримається за замовчуванням. |
| `TOSTOP` | Вимкнено | Надсилання сигналу `SIGTTOU` фоновому процесу при спробі запису в термінал. | Вимикається. |

### Спеціальні керуючі символи та таймаути в масиві `c_cc`

Масив `c_cc` має фіксований розмір `NCCS` (зазвичай 32 елементи).

#### Канонічні керуючі символи (активні при `ICANON`)

| Індекс масиву | Символ за замовчуванням | Код ASCII | Сигнал / Дія ядра |
|---|---|---|---|
| `VINTR` | `Ctrl+C` | `0x03` (ETX) | Надсилає сигнал `SIGINT` усім процесам у групі переднього плану. |
| `VQUIT` | `Ctrl+\` | `0x1C` (FS) | Надсилає сигнал `SIGQUIT` з генерацією дампа пам'яті (Core Dump). |
| `VERASE` | `Backspace` / `DEL` | `0x7F` або `0x08` | Стирає попередній символ у поточному канонічному рядку. |
| `VKILL` | `Ctrl+U` | `0x15` (NAK) | Стирає весь поточний рядок до початку. |
| `VEOF` | `Ctrl+D` | `0x04` (EOT) | Сигналізує про кінець файлу (виклик `read()` повертає `0`). |
| `VEOL` | `NUL` | `0x00` | Додатковий розділювач рядка (подібно до `\n`). |
| `VEOL2` | `NUL` | `0x00` | Другий додатковий розділювач рядка. |
| `VSTART` | `Ctrl+Q` | `0x11` (DC1) | Відновлює призупинену передачу виводу (XON). |
| `VSTOP` | `Ctrl+S` | `0x13` (DC3) | Призупиняє передачу виводу (XOFF). |
| `VSUSP` | `Ctrl+Z` | `0x1A` (SUB) | Надсилає сигнал призупинення `SIGTSTP`. |
| `VREPRINT` | `Ctrl+R` | `0x12` (DC2) | Перемальовує поточний незчитаний рядок вводу. |
| `VWERASE` | `Ctrl+W` | `0x17` (ETB) | Стирає останнє введене слово. |
| `VLNEXT` | `Ctrl+V` | `0x16` (SYN) | Літеральне введення наступного символу без інтерпретації. |
| `VDISCARD`| `Ctrl+O` | `0x0F` (SI) | Перемикає режим скидання всього виводу до наступного введення. |

#### Неканонічні параметри блокування (`VMIN` та `VTIME`)

Коли прапорець `ICANON` скинуто, позиції `c_cc[VMIN]` та `c_cc[VTIME]` перестають бути кодами символів і перетворюються на числові лічильники керування блокуванням системного виклику `read(fd, buf, count)`:
- `VMIN` (діапазон `0..255`) — мінімальна кількість байтів, необхідна для розблокування `read()`.
- `VTIME` (діапазон `0..255`) — тривалість таймауту в **децисекундах** (1 одиниця = 100 мс = 0.1 с).

```
                      Матриця поведінки read() у неканонічному режимі
                      
                              VTIME == 0                 VTIME > 0
                     +--------------------------+--------------------------+
                     |  Суто блокуюче читання   |   Міжсимвольний таймер   |
                     |                          |  (Inter-byte Timeout)    |
      VMIN > 0       | read() спить, поки не    | read() чекає 1-й байт    |
                     | надійде рівно VMIN байт  | вічно; таймер VTIME рахує|
                     | або сигнал (EINTR).      | інтервал між наступними. |
                     +--------------------------+--------------------------+
                     |  Повний Polling          |   Читання з таймаутом    |
                     |  (Неблокуючий ввід)      |   (Таймаут відповіді)    |
      VMIN == 0      | read() повертає наявні   | read() чекає VTIME*100 мс|
                     | байти або 0 негайно.     | Якщо байт немає —        |
                     | Навантажує CPU на 100%.  | повертає 0.              |
                     +--------------------------+--------------------------+
```

1. **Режим 1 (`VMIN > 0, VTIME == 0`):** Блокування до накопичення `VMIN` байтів. Виклик `read()` спить доти, доки користувач не введе щонайменше `VMIN` символів. Якщо надійшов сигнал, виклик переривається з `errno = EINTR`.
2. **Режим 2 (`VMIN == 0, VTIME == 0`):** Повне неблокуюче читання. `read()` негайно повертає кількість фактично зчитаних байтів, або `0`, якщо вхідна черга порожня. Використання в нескінченному циклі без системних селекторів (`poll`/`select`) призводить до 100% завантаження одного ядра процесора.
3. **Режим 3 (`VMIN == 0, VTIME > 0`):** Читання з абсолютним таймаутом. Виклик `read()` чекає надходження хоча б одного байта протягом `VTIME * 100` мс. Якщо за цей час надійшов 1 або більше байтів, `read()` повертає їх негайно. Якщо час вичерпано, а черга порожня — повертається `0`. Стандартне значення для термінальних редакторів: `VMIN = 0, VTIME = 1` (таймаут 100 мс).
4. **Режим 4 (`VMIN > 0, VTIME > 0`):** Міжсимвольний таймаут (Inter-byte Timer). Виклик `read()` чекає надходження *першого* байта необмежено довго. Після отримання першого байта запускається таймер на `VTIME * 100` мс. Виклик повертає керування, якщо надійшло `VMIN` байтів або якщо інтервал між двома послідовними байтами перевищив `VTIME`.

## Керування геометрією термінала: `ioctl` та `struct winsize`

### Системний виклик `ioctl(TIOCGWINSZ)`
```
#include <sys/ioctl.h>
#include <unistd.h>

int ioctl(int fd, unsigned long request, ...);
```
- **Команда запиту:** `TIOCGWINSZ` (*Terminal I/O Control Get Window Size*).
- **Команда встановлення:** `TIOCSWINSZ` (*Terminal I/O Control Set Window Size*).
- **Цільова структура:**
```
struct winsize {
    unsigned short ws_row;    /* Кількість рядків у символах */
    unsigned short ws_col;    /* Кількість колонок у символах */
    unsigned short ws_xpixel; /* Горизонтальний розмір у пікселях (0, якщо не підтримується) */
    unsigned short ws_ypixel; /* Вертикальний розмір у пікселях (0, якщо не підтримується) */
};
```
- **Повертає:** `0` при успіху, `-1` при помилці.
- **Коди помилок (`errno`):**
  - `EBADF` — невалідний файловий дескриптор `fd`.
  - `ENOTTY` — операція `TIOCGWINSZ` не підтримується пристроєм (дескриптор вказує на файл або сокет).
  - `EINVAL` — некоректні параметри або дескриптор у недійсному стані.
  - `EFAULT` — вказівник на структуру `struct winsize` виходить за межі адресного простору процесу.

### Обробка сигналу `SIGWINCH`
Коли користувач змінює розмір вікна емулятора або змінює геометрію панелей у `tmux`/`screen`, ядро надсилає процесу сесії сигнал `SIGWINCH` (*Window Size Change*, числовий код `28`).
- Сигнал є асинхронним: обробник повинен лише виставляти прапорець `volatile sig_atomic_t resize_pending = 1;`.
- У головному циклі подій при піднятому прапорці викликається `ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws)`, оновлюються внутрішні змінні `screen_rows` / `screen_cols` та ініціюється перерахунок зміщень в'юпорту (`row_offset`, `col_offset`) з повним перемальовуванням екрана.

## Каталог Escape-послідовностей (ECMA-48 / ANSI / VT100 / xterm)

Усі керівні інструкції передаються як потік байтів у дескриптор `STDOUT_FILENO`. Однобайтовий символ `ESC` (`0x1B` / 27 / `\x1b`) разом із наступним байтом `[` (`0x5B`) утворює керівний префікс **CSI** (*Control Sequence Introducer*).

### Анатомія граматики CSI
`ESC [ <приватний маркер> <параметри через крапку з комою> <проміжні байти> <фінальна літера команди>`
- **Приватний маркер (Private Marker):** символ `?` (DEC Private), `>` (xterm), `=` тощо.
- **Параметри (Parameters):** одне або кілька десяткових чисел, розділених `;` (наприклад, `1;31`). Пропущений параметр вважається рівним значенню за замовчуванням (зазвичай `1` або `0`).
- **Фінальний символ (Final Byte):** байт у діапазоні `0x40..0x7E` (`@`, `A`..`Z`, `[`, `\`, `]`, `^`, `_`, `` ` ``, `a`..`z`, `{`, `|`, `}`, `~`), що однозначно визначає тип операції.

### Позиціонування та рух курсора

Усі координати екрана в протоколі ANSI є **1-індексованими**: верхній лівий кут має координати `(рядок 1, колонка 1)`.

| Послідовність | Команда ECMA-48 | Назва та параметри | Опис механізму дії |
|---|---|---|---|
| `\x1b[H` | CUP | Cursor Position (Home) | Переміщує курсор у лівий верхній кут `(1, 1)`. Еквівалентно `\x1b[1;1H`. |
| `\x1b[<r>;<c>H` | CUP | Cursor Position | Встановлює курсор на рядок `<r>` та стовпчик `<c>`. При виході за межі екрана курсор затискається на краю. |
| `\x1b[<r>;<c>f` | HVP | Horizontal & Vertical Position | Повний функціональний аналог CUP. |
| `\x1b[<n>A` | CUU | Cursor Up | Зсуває курсор на `<n>` рядків угору (за замовчуванням `1`). Зупиняється на верхньому краї екрана. |
| `\x1b[<n>B` | CUD | Cursor Down | Зсуває курсор на `<n>` рядків униз (за замовчуванням `1`). Зупиняється на нижньому краї екрана. |
| `\x1b[<n>C` | CUF | Cursor Forward (Right) | Зсуває курсор на `<n>` позицій праворуч. Зупиняється на правому краї вікна. |

| `\x1b[<n>E` | CNL | Cursor Next Line | Переміщує курсор на початок рядка на `<n>` рядків нижче. |
| `\x1b[<n>F` | CPL | Cursor Previous Line | Переміщує курсор на початок рядка на `<n>` рядків вище. |

| `\x1b[u` | RCP | Restore Cursor Position (ANSI) | Відновлює збережені координати курсора. |
| `\x1b7` | DECSC | Save Cursor & Attributes (DEC) | Зберігає координати курсора, поточний стиль SGR та стан набору символів. |
| `\x1b8` | DECRC | Restore Cursor & Attributes (DEC) | Відновлює координати, стиль та стан набору символів. |
| `\x1b[?25l` | DECTCEM | Hide Cursor | Робить текстовий курсор невидимим під час оновлення кадру. |
| `\x1b[?25h` | DECTCEM | Show Cursor | Відновлює видимість текстового курсора на активній позиції. |
| `\x1b[<n> q` | DECSCUSR | Set Cursor Style | Задає форму та режим миготіння курсора: `0` / `1` — миготливий блок, `2` — статичний блок, `3` — миготливе підкреслення, `4` — статичне підкреслення, `5` — миготлива вертикальна риска, `6` — статична вертикальна риска. |
| `\x1b[6n` | DSR | Device Status Report (CPR) | Запит звіту про поточну позицію курсора. Термінал надсилає у потік stdin процесу відповідь `\x1b[<r>;<c>R`. |

### Спеціальні режими термінала та буфери

#### 1. Альтернативний екранний буфер (Alternate Screen Buffer)
- `\x1b[?1049h` — увімкнення альтернативного екрана (стандарт xterm): зберігає поточний екран шелу та координати курсора, перемикається на альтернативний буфер і очищає його.
- `\x1b[?1049l` — вимкнення альтернативного екрана: очищає альтернативний буфер, повертає первинний буфер командного рядка та відновлює координати курсора.

#### 2. Режим безпечної вставки (Bracketed Paste Mode)
- `\x1b[?2004h` — активація режиму.
- `\x1b[?2004l` — деактивація режиму.
- **Маркери потоку stdin:** коли користувач вставляє текст із буфера обміну ОС, термінал обрамляє вставлений блок послідовностями:
  - Префікс: `\x1b[200~`
  - Суфікс: `\x1b[201~`
  Редактор сприймає всі символи між маркерами як сирий текст, не інтерпретуючи Enter як команду виконання та вимикаючи автоматичне автодоповнення відступів.

#### 3. Синхронізоване виведення (Synchronized Output / Mode 2025)
- `\x1b[?2025h` — початок атомарного кадру (Begin Synchronized Update).
- `\x1b[?2025l` — кінець атомарного кадру (End Synchronized Update).
Емулятор термінала призупиняє рендеринг пікселів на GPU під час надходження байтів між цими командами і відображає весь кадр за один прохід, повністю усуваючи артефакти вертикального тирингу (Tearing).

#### 4. Протокол розширеного відстеження миші (SGR Mouse Tracking)
- `\x1b[?1000h` / `\x1b[?1000l` — увімкнення/вимкнення базового відстеження натискань кнопок миші.
- `\x1b[?1002h` / `\x1b[?1002l` — відстеження натискань, відпускань та переміщення курсора миші при затиснутій кнопці (Cell Motion).
- `\x1b[?1006h` / `\x1b[?1006l` — розширений формат SGR: координати передаються без обмеження 223 колонок у вигляді `\x1b[<btn;col;rowM` (натискання) та `\x1b[<btn;col;rowm` (відпускання).

### Стилізація тексту та кольори (SGR — Select Graphic Rendition)

Команда встановлення графічних атрибутів має вигляд `\x1b[<параметр1>;<параметр2>;...m`.

#### Атрибути шрифту та накреслення

| Код | Дія | Код вимкнення | Дія скидання |
|---|---|---|---|
| `0` | Скидання всіх графічних атрибутів і кольорів до стандартних | — | Повний скид |
| `1` | Жирний шрифт (Bold) або підвищена яскравість | `22` | Нормальна інтенсивність (не жирний і не тьмяний) |
| `2` | Тьмяний шрифт (Faint / Dim) | `22` | Нормальна інтенсивність |
| `3` | Курсив (Italic) | `23` | Скасування курсиву |
| `4` | Підкреслення (Underline) | `24` | Скасування підкреслення |
| `5` | Повільне миготіння (Slow Blink, < 150 разів/хв) | `25` | Скасування миготіння |
| `7` | Інверсія кольорів (Reverse Video: тло стає текстом і навпаки) | `27` | Скасування інверсії |
| `8` | Прихований текст (Conceal / Hidden) | `28` | Відображення прихованого тексту |
| `9` | Закреслений текст (Crossed-out / Strikethrough) | `29` | Скасування закреслення |

#### 1. Стандартна 8/16-колірна палітра ANSI

| Колір | Основний текст (Foreground) | Яскравий текст (Bright FG) | Основне тло (Background) | Яскраве тло (Bright BG) |
|---|---|---|---|---|
| Чорний | `\x1b[30m` | `\x1b[90m` | `\x1b[40m` | `\x1b[100m` |
| Червоний | `\x1b[31m` | `\x1b[91m` | `\x1b[41m` | `\x1b[101m` |
| Зелений | `\x1b[32m` | `\x1b[92m` | `\x1b[42m` | `\x1b[102m` |
| Жовтий | `\x1b[33m` | `\x1b[93m` | `\x1b[43m` | `\x1b[103m` |
| Синій | `\x1b[34m` | `\x1b[94m` | `\x1b[44m` | `\x1b[104m` |
| Пурпурний | `\x1b[35m` | `\x1b[95m` | `\x1b[45m` | `\x1b[105m` |
| Блакитний | `\x1b[36m` | `\x1b[96m` | `\x1b[46m` | `\x1b[106m` |
| Білий | `\x1b[37m` | `\x1b[97m` | `\x1b[47m` | `\x1b[107m` |
| За замовчуванням | `\x1b[39m` | — | `\x1b[49m` | — |

#### 2. Розширена 256-колірна палітра
- Встановлення кольору тексту: `\x1b[38;5;<n>m`
- Встановлення кольору тла: `\x1b[48;5;<n>m`
- **Структура індексного простору `<n>` (`0..255`):**
  - `0..7` — стандартні кольори ANSI.
  - `8..15` — яскраві кольори ANSI.
  - `16..231` — 6×6×6 колірний куб RGB. Формула індексу: `індекс = 16 + 36*r + 6*g + b`, де `r, g, b` набувають значень від `0` до `5`.
  - `232..255` — градації сірого від темно-сірого до майже білого (24 кроки).

#### 3. Повноколірний 24-бітний режим TrueColor
- Встановлення 24-бітного кольору тексту: `\x1b[38;2;<r>;<g>;<b>m`
- Встановлення 24-бітного кольору тла: `\x1b[48;2;<r>;<g>;<b>m`
- Де `<r>`, `<g>`, `<b>` — десяткові числа в діапазоні від `0` до `255`.

| `F12` | `\x1b[24~` | `1B 5B 32 34 7E` | VT220 Key |

#### Модифікатори комбінацій (Shift, Alt, Ctrl)
Коли зі стрілками або функціональними клавішами затискаються клавіші-модифікатори, до CSI-послідовності додається параметр виду `\x1b[1;<модифікатор>A`:
- Формула модифікатора: `код = 1 + (Shift ? 1 : 0) + (Alt ? 2 : 0) + (Ctrl ? 4 : 0)`
- `2` — `Shift` (наприклад, `\x1b[1;2A` — Shift + Стрілка вгору)
- `3` — `Alt` (наприклад, `\x1b[1;3A` — Alt + Стрілка вгору)
- `4` — `Shift + Alt`
- `5` — `Ctrl` (наприклад, `\x1b[1;5C` — Ctrl + Стрілка вправо для стрибка по словах)
- `6` — `Shift + Ctrl`
- `7` — `Alt + Ctrl`
- `8` — `Shift + Alt + Ctrl`

### 3. Протокол розширеної клавіатури Kitty Keyboard Protocol (CSI u)

Класична модель клавіатурного вводу VT100/xterm страждає від чотирьох фундаментальних архітектурних недоліків:
1. **Неможливість розрізнення життєвого циклу клавіші:** програма отримує байти лише при первинному натисканні (`Press`) та під час апаратного автоповтору (`Repeat`), але ніколи не отримує сповіщення про фізичне відпускання клавіші (`Release`). Це унеможливлює реалізацію комбінацій із затисканням, точної обробки швидких акордів та ігрових елементів керування.
2. **Колізії керуючих ASCII-кодів:** через історичну спадщину терміналів 1970-х років комбінація `Ctrl+I` генерує той самий байт `0x09`, що й клавіша `Tab`; `Ctrl+M` невідрізна від `Enter` (`0x0D`); `Ctrl+[` збігається з `Escape` (`0x1B`); `Ctrl+H` — з `Backspace` (`0x08`), а `Ctrl+Space` — з `Ctrl+@` (`0x00`). Редактор позбавлений можливості призначити окремі функції на ці комбінації.
3. **Втрата модифікаторів на службових клавішах:** комбінації на кшталт `Shift+Enter`, `Ctrl+Tab`, `Ctrl+Backspace` чи `Ctrl+Shift+Z` у застарілих терміналах або повністю ігноруються, або надсилають деструктивні одиночні байти.
4. **Затримка клавіші Escape (Escape Ambiguity):** оскільки всі стрілки та функціональні клавіші починаються з префікса `\x1b`, редактор змушений запускати таймер на 50–100 мс після отримання байта `0x1B`, щоб визначити, чи це одиночний Escape, чи початок багатобайтової послідовності. Це вносить відчутну затримку в зміну режимів редактора.

Протокол **Kitty Keyboard Protocol** (розроблений Kovıd Goyal та підтримуваний сучасними емуляторами Kitty, Ghostty, WezTerm, Foot, Alacritty з розширеннями, Neovim) розв'язує ці проблеми за допомогою механізму **прогресивного розширення** (*Progressive Enhancement*) на базі послідовностей `CSI ... u`.

#### Стек режимів клавіатури: активація та відновлення

Емулятор термінала підтримує апаратний стек конфігурацій клавіатури. Це дозволяє повноекранному редактору завантажувати потрібний набір прапорців у стек під час запуску та гарантовано повертати попередню поведінку шелу після виходу одним викликом.

- **Запит підтримки протоколу та поточних прапорців:**
  Програма надсилає в `STDOUT_FILENO`: `\x1b[?u`
  Термінал відповідає у потік `stdin`: `\x1b[?<flags>u`, де `<flags>` — десяткова сума активних бітових прапорців. Якщо протягом таймауту відповідь не надійшла, термінал підтримує лише застарілий протокол VT100.
- **Завантаження режиму в стек (Push Keyboard Mode):**
  `\x1b[><flags>u` — створює новий рівень у стеку термінала та активує передану бітову маску `<flags>`.
- **Вилучення режиму зі стека (Pop Keyboard Mode):**
  `\x1b[<<count>u` — знімає зі стека `<count>` конфігурацій (за замовчуванням `1`, тобто `\x1b[<u`). Використовується в деструкторі сесії для повернення попередніх прапорців.
- **Пряме встановлення прапорців без стека:**
  `\x1b[=<flags>;<mode>u`, де параметр `<mode>` визначає дію:
  - `1` — повністю замінити поточну маску на `<flags>`;
  - `2` — увімкнути вказані біти (побітове OR: `current |= flags`);
  - `3` — вимкнути вказані біти (побітове AND NOT: `current &= ~flags`).

#### Бітові прапорці функціоналу (`flags`)

| Біт | Десяткове значення | Назва прапорця | Механізм дії |
|---|---|---|---|
| 0 | `1` (`0x01`) | Disambiguate Escape Codes | Повне усунення колізій. Клавіші `Escape` (`27`), `Enter` (`13`), `Tab` (`9`), `Backspace` (`127`) завжди кодуються як явні послідовності `\x1b[<код>u`. Одиночне натискання Escape надсилає `\x1b[27u`, усуваючи необхідність таймаутного дочитування `read()`. |
| 1 | `2` (`0x02`) | Report Event Types | Термінал надсилає окремі повідомлення для кожного типу події: натискання (`1`), автоповтор (`2`) та фізичне відпускання клавіші (`3`). |
| 2 | `4` (`0x04`) | Report Alternate Keys | Термінал передає додаткові поля: код символу зі зміщенням (`Shifted Keycode`) та код фізичної клавіші в поточній базовій латинській розкладці (`Base Layout Keycode`), дозволяючи підтримувати гарячі клавіші незалежно від системної мови вводу. |
| 3 | `8` (`0x08`) | Report All Keys as Escape Codes | Абсолютно всі натискання клавіш (включно зі звичайними літерами 'a', '1', пробілом) надсилаються як послідовності `\x1b[<код>u`, навіть якщо жоден модифікатор не затиснуто. |
| 4 | `16` (`0x10`) | Report Associated Text | Термінал додає сегмент текстового представлення у кодових точках Unicode (необхідно для коректної інтеграції з комплексними методами введення IME). |

Для повноекранного текстового редактора рекомендованою є комбінація прапорців `1 | 2 = 3` (усунення неоднозначностей + звіт про натискання/відпускання) або `1 | 2 | 4 = 7`.

#### Граматика кодування вхідних подій

Кожне повідомлення від клавіатури надходить у потік `stdin` у такому форматі:
`\x1b[ <unicode-key-code> [ : <shifted-key> [ : <base-layout-key> ] ] ; <modifiers> [ : <event-type> ] [ ; <text-codepoints> ] u`

- **Поле `<unicode-key-code>`:** десятковий код Unicode відповідного символу (наприклад, `97` для 'a', `27` для Escape) або код функціональної клавіші з таблиці розширень.
- **Поле `<event-type>` (тип події):**
  - `1` (або опущено) — `Press` (первинне натискання клавіші);
  - `2` — `Repeat` (автоповтор клавіші операційною системою);
  - `3` — `Release` (фізичне відпускання клавіші користувачем).
- **Поле `<modifiers>` (бітова маска модифікаторів):**
  Розраховується за стандартизованою формулою:
  `modifiers = 1 + (Shift ? 1 : 0) + (Alt ? 2 : 0) + (Ctrl ? 4 : 0) + (Super ? 8 : 0) + (Hyper ? 16 : 0) + (Meta ? 32 : 0) + (CapsLock ? 64 : 0) + (NumLock ? 128 : 0)`
  - Без модифікаторів: `1` (якщо поле типу події активне, записується як `1:1` для натискання або `1:3` для відпускання).
  - `Shift` = `2`
  - `Alt` (Option на macOS) = `3`
  - `Shift + Alt` = `4`
  - `Ctrl` = `5`
  - `Shift + Ctrl` = `6`
  - `Alt + Ctrl` = `7`
  - `Shift + Alt + Ctrl` = `8`
  - `Super` (Windows / Command) = `9`
  - `Super + Shift` = `10`
  - `CapsLock` додає `64`, `NumLock` додає `128`.

## Керуючі послідовності операційної системи (OSC — Operating System Command)

Послідовності класу **OSC** (*Operating System Command*) призначені для двосторонньої взаємодії програми редактора із зовнішнім оточенням емулятора термінала, системним віконним менеджером та операційною системою: встановлення заголовка вікна, маніпуляція системним буфером обміну, динамічне опитування і налаштування кольорової палітри та створення гіперпосилань.

### Граматика та термінатори послідовностей OSC

Загальний синтаксис інструкції OSC:
`ESC ] <Ps> ; <Pt> <Термінатор>`
- `ESC ]` — двобайтовий префікс `\x1b]` (`0x1B 0x5D`).
- `<Ps>` — десятковий номер команди операційної системи.
- `;` — обов'язковий розділювач коду команди та тіла параметрів.
- `<Pt>` — параметри та текстове корисне навантаження команди.
- `<Термінатор>` — завершувач керуючої послідовності:
  - `BEL` (`\x07` / `0x07` / `\a`) — традиційний ASCII-термінатор Bell, що підтримується 100% емуляторів терміналів.
  - `ST` (*String Terminator*, `\x1b\\` / `0x1B 0x5C`) — офіційний термінатор стандарту ECMA-48. Програма може відправляти будь-який із двох термінаторів, але зобов'язана коректно розпізнавати обидва варіанти у вхідних відповідях.

---

### 1. Встановлення заголовка вікна та іконки (OSC 0, OSC 2)

Використовується для індикації назви редагованого файлу, статусу модифікації буфера (`[+]` / `[Modified]`), поточної гілки Git та координат курсора в рядку заголовка вікна або у вкладці термінального мультиплексора (`tmux`, `zellij`, `wezterm`).

| Послідовність | Команда OSC | Призначення |
|---|---|---|
| `\x1b]0;<рядок_заголовка>\x07` | OSC 0 | Встановлює одночасно заголовок вікна емулятора та ім'я іконки на панелі задач. |
| `\x1b]2;<рядок_заголовка>\x07` | OSC 2 | Встановлює виключно заголовок вікна термінала. |
| `\x1b]1;<рядок_іконки>\x07` | OSC 1 | Встановлює ім'я піктограми (іконки) вікна. |

- **Приклад встановлення:**
  `write(STDOUT_FILENO, "\x1b]0;kilo — /etc/hosts [Modified]\x07", 37);`
- **Відновлення при виході:** перед завершенням роботи редактор надсилає `\x1b]0;\x07` для повернення стандартного заголовка шелу.

### 2. Робота з системним буфером обміну (OSC 52 — Clipboard Access)

Протокол **OSC 52** забезпечує уніфіковане читання та запис у буфер обміну хостової ОС (X11 Clipboard, Wayland `wl-clipboard`, macOS Pasteboard, Windows Clipboard) через звичайний термінальний потік введення-виведення. Це уможливлює повноцінний спільний буфер обміну навіть усередині віддалених SSH-сесій без налаштування прокидання X11-сокетів чи сторонніх демонів.

#### Формат команди OSC 52
`\x1b]52;<clipboard-target>;<base64-payload>\x07`

- **Параметр `<clipboard-target>` (цільова вибірка):**
  - `c` — основний системний буфер обміну (*System Clipboard*, `Ctrl+C` / `Ctrl+V`).
  - `p` — первинна вибірка X11/Wayland (*Primary Selection*, виділення мишею та вставка середньою кнопкою).
  - `s` — буфер швидкого виділення (*Secondary Selection*).
  - `q` — буфер запиту.
  - Комбінація цілей (наприклад, `cp`) — одночасний запис в основний системний буфер та первинну вибірку.

#### 1. Запис у буфер обміну (Clipboard Write)
Редактор кодує виділений фрагмент тексту в кодування **Base64** і передає послідовність у `STDOUT_FILENO`:
- Формат: `\x1b]52;c;<Base64-стрічка>\x07`
- **Приклад:** копіювання коду `int x = 42;\n`:
  1. Base64-представлення рядка: `aW50IHggPSA0MjsK`
  2. Вихідна команда: `\x1b]52;c;aW50IHggPSA0MjsK\x07`
  3. Емулятор термінала перехоплює послідовність, декодує Base64 у пам'ять і поміщає сирий текст у системний буфер ОС.

#### 2. Очищення буфера обміну (Clipboard Clear)
- Формат: `\x1b]52;c;!\x07` або передача порожнього навантаження `\x1b]52;c;\x07`.

#### 3. Зчитування з буфера обміну (Clipboard Read / Query)
- **Запит від програми:** `\x1b]52;c;?\x07`
- **Відповідь термінала у потік `stdin`:** `\x1b]52;c;<Base64-стрічка>\x07` (або `\x1b]52;c;<Base64-стрічка>\x1b\\`).
- Редактор розбирає вхідний потік, виділяє Base64-фрагмент між другою крапкою з комою та термінатором, декодує байти та вставляє результуючий текст у поточну позицію курсора буфера.

#### Політики безпеки та обмеження (Security Considerations)
- **Блокування читання:** більшість емуляторів терміналів за замовчуванням блокують запити на зчитування буфера обміну (`?`) або вимагають інтерактивного дозволу користувача, щоб шкідливі скрипти не могли викрадати конфіденційні дані (паролі, токени).
- **Обмеження довжини:** через обмеження черг TTY розмір одного Base64-пейлоада зазвичай лімітується від 100 КБ до 1 МБ.

### 3. Налаштування та опитування палітри кольорів термінала (OSC 4)

Дозволяє редактору динамічно перевизначати кольори в базовій 256-колірній палітрі термінала під власну колірну схему або опитувати встановлені кольори оточення.

- **Встановлення кольору палітри:**
  `\x1b]4;<індекс>;rgb:<rr>/<gg>/<bb>\x07`
  - `<індекс>` — індекс кольору від `0` до `255`.
  - `<rr>`, `<gg>`, `<bb>` — шістнадцяткові компоненти кольору (1, 2 або 4 шістнадцяткові цифри на канал, наприклад `rgb:ff/80/00` або `rgb:ffff/8000/0000`).
- **Опитування кольору палітри:**
  - Запит: `\x1b]4;<індекс>;?\x07`
  - Відповідь термінала у потік `stdin`: `\x1b]4;<індекс>;rgb:<rrrr>/<gggg>/<bbbb>\x1b\\` (значення нормалізуються до 16 бітів на канал у діапазоні `0000..ffff`).
- **Скидання кольору до значень теми термінала:**
  `\x1b]104;<індекс>\x07` (якщо індекс опущено — `\x1b]104\x07` — скидається вся таблиця з 256 кольорів).

---

### 4. Динамічне визначення кольорів тексту, тла та курсора (OSC 10 / OSC 11 / OSC 12)

Критично важливий механізм для автоматичного визначення світлої або темної теми операційної системи (Light vs Dark mode) та динамічного підлаштування кольорів синтаксису без вимагання ручного конфігурування користувачем.

| Послідовність запиту | Команда OSC | Призначення | Формат відповіді термінала | Послідовність скидання |
|---|---|---|---|---|
| `\x1b]10;?\x07` | OSC 10 | Запит кольору основного тексту (Foreground) | `\x1b]10;rgb:<rrrr>/<gggg>/<bbbb>\x1b\\` | `\x1b]110\x07` |
| `\x1b]11;?\x07` | OSC 11 | Запит кольору тла (Background) | `\x1b]11;rgb:<rrrr>/<gggg>/<bbbb>\x1b\\` | `\x1b]111\x07` |
| `\x1b]12;?\x07` | OSC 12 | Запит кольору курсора (Cursor Color) | `\x1b]12;rgb:<rrrr>/<gggg>/<bbbb>\x1b\\` | `\x1b]112\x07` |

- **Встановлення кольору тла:** `\x1b]11;rgb:1e/1e/1e\x07` (встановлює темно-сіре тло редактора).
- **Алгоритм детекції Dark / Light Mode за стандартом ITU-R BT.709:**
  1. Програма надсилає `\x1b]11;?\x07` та зчитує 16-бітні компоненти кольору тла `R, G, B` (`0..65535`).
  2. Обчислюється відносна яскравість (Luminance):
     `Y = 0.2126 * (R / 65535.0) + 0.7152 * (G / 65535.0) + 0.0722 * (B / 65535.0)`
  3. Якщо `Y < 0.5` — активний темний режим термінала (Dark Theme), редактор вмикає темну тему оформлення. Якщо `Y >= 0.5` — активна світла тема (Light Theme).

### 5. Інлайн-гіперпосилання (OSC 8 — Terminal Hyperlinks)

Дозволяє зв'язувати довільний текст на екрані редактора (URL-адреси у коментарях коду, посилання на документацію у виводі мовного сервера LSP або локальні шляхи до файлів) із гіперпосиланнями, які відкриваються у системному браузері за кліком `Ctrl+Click`.

- **Синтаксис відкриття посилання:**
  `\x1b]8;<параметри>;<URI>\x1b\\<відображуваний_текст>\x1b]8;;\x1b\\`
- **Параметри:** необов'язковий список пар `key=value` (наприклад, `id=link_42` для візуального об'єднання частин одного посилання при автоматичному переносі рядка).
- **Приклад використання:**
  `\x1b]8;id=std1;https://en.cppreference.com/w/cpp\x1b\\std::string_view reference\x1b]8;;\x1b\\`

## Графічні протоколи терміналів (Terminal Graphics Protocols)

Сучасні консольні редактори та файл-менеджери (Neovim з плагінами прев'ю, Helix, Yazi, Ranger) інтегрують показ повноколірних растрових зображень, архітектурних діаграм та графіків безпосередньо в символьну сітку термінала. Для цього в екосистемі Unix застосовуються два стандарти: растровий протокол **DEC Sixel** та високопродуктивний протокол прямого рендерингу **Kitty Graphics Protocol**.

---

### 1. Протокол растрової графіки DEC Sixel (`\x1bP...q`)

Протокол **Sixel** (скорочення від *Six Pixels*) розроблений Digital Equipment Corporation для апаратних терміналів VT240/VT330/VT340 і матричних принтерів. Підтримується в xterm, Foot, WezTerm, mlterm, Mintty.

#### Структура кадру DCS (Device Control String)
`ESC P [P1] ; [P2] ; [P3] q <sixel-payload> ESC \`
- `ESC P` — префікс керуючого рядка пристрою `\x1bP` (`0x1B 0x50`).
- `[P1]`, `[P2]`, `[P3]` — числові параметри конфігурації:
  - `P1` — співвідношення сторін пікселя (Pixel Aspect Ratio): `0` або `1` — 2:1 (висота вдвічі більша за ширину), `2` — 5:1, `7`, `8`, `9` — 1:1 (квадратний піксель, стандарт сучасних дисплеїв).
  - `P2` — режим тла: `0` або `2` — прозоре тло (нульові пікселі не перекривають фон термінала); `1` — непрозоре тло (заливка кольором регістру 0).
  - `P3` — горизонтальний крок сітки (Grid Size).
- `q` — фінальний ідентифікатор режиму Sixel.
- `<sixel-payload>` — тіло растрових даних та команд палітри.
- `ESC \` — термінатор `ST` (`\x1b\\` / `0x1B 0x5C`).

#### Кодування піксельних стовпчиків (Sixel Data Bytes)
Зображення розбивається по вертикалі на горизонтальні смуги висотою рівно **6 пікселів**.
Кожен байт даних кодує один вертикальний стовпчик із 6 пікселів поточної смуги:
`ASCII-код = 63 + бітова_маска` (діапазон значень від `?` (`0x3F` / 63) до `~` (`0x7E` / 126)).

```
  Біт 0 (вага 1)  -> [ Піксель 0 (верхній) ]
  Біт 1 (вага 2)  -> [ Піксель 1           ]
  Біт 2 (вага 4)  -> [ Піксель 2           ]
  Біт 3 (вага 8)  -> [ Піксель 3           ]
  Біт 4 (вага 16) -> [ Піксель 4           ]
  Біт 5 (вага 32) -> [ Піксель 5 (нижній)  ]
  Значення байта = 63 + (b0*1 + b1*2 + b2*4 + b3*8 + b4*16 + b5*32)
```

- Якщо горять усі 6 пікселів стовпчика: `63 + 63 = 126` (символ `~`).
- Якщо горить лише верхній піксель: `63 + 1 = 64` (символ `@`).
- Якщо жоден піксель не горить: `63 + 0 = 63` (символ `?`).

#### Керування палітрою, RLE та розгорткою
- **Вибір колірного регістру:** `#<номер>` (наприклад, `#1` активує колір регістру 1).
- **Визначення кольору в регістрі:** `#<номер>;<формат>;<p1>;<p2>;<p3>`
  - `<формат> = 1` — модель HLS: `<Hue: 0..360>;<Lightness: 0..100>;<Saturation: 0..100>`.
  - `<формат> = 2` — модель RGB: `<Red: 0..100>;<Green: 0..100>;<Blue: 0..100>` (у відсотках яскравості 0..100% за класичним стандартом DEC VT340).
- **RLE-компресія повторів:** `!<кількість><символ_sixel>` (наприклад, `!100~` малює суцільну смугу шириною 100 пікселів і висотою 6 пікселів).
- **Символ `$` (Carriage Return):** повертає позицію малювання на початок *поточної* 6-піксельної смуги без зсуву вниз. Застосовується для багатопрохідного накладання різних кольорів на тій самій висоті.
- **Символ `-` (Line Feed):** переводить позицію на початок *наступної* 6-піксельної смуги вниз.

#### Приклад байтового потоку Sixel
Малювання червоного прямокутника 10×6 пікселів на чорному тлі:
```
\x1bP7;1;0q#0;2;0;0;0#1;2;100;0;0#1!10~\x1b\
```
- `\x1bP7;1;0q` — ініціалізація Sixel, квадратний піксель (7), непрозоре тло (1);
- `#0;2;0;0;0` — визначення кольору тла RGB(0, 0, 0);
- `#1;2;100;0;0` — визначення кольору 1 як яскраво-червоного RGB(100%, 0%, 0%);
- `#1!10~` — вибір кольору 1 та малювання 10 стовпчиків із 6 зафарбованих пікселів;
- `\x1b\` — термінатор кадру ST.

### 2. Протокол прямої передачі піксельних буферів Kitty Graphics Protocol (`\x1b_G`)

Протокол **Kitty Graphics Protocol** спроєктований для високопродуктивної передачі великих растрових зображень безпосередньо у відеопам'ять GPU емулятора термінала. Він підтримує 24- та 32-бітний TrueColor з альфа-каналом прозорості, пряму обробку форматів PNG, апаратне масштабування на GPU, обрізку (cropping), анімації та надшвидку передачу даних через спільну пам'ять POSIX (Shared Memory).

Підтримується в Kitty, Ghostty, WezTerm, Konsole, Wayst, Neovim.

#### Структура кадру APC (Application Program Command)
`ESC _ G <керуючі_ключі_через_кому> ; <корисне_навантаження_payload> ESC \`
- `ESC _ G` — префікс APC `\x1b_G` (`0x1B 0x5F 0x47`).
- `<керуючі_ключі>` — список пар `key=value`, розділених комами.
- `;` — розділювач службових метаданих та тіла даних.
- `<корисне_навантаження_payload>` — растрові дані (закодовані в Base64 або шлях до ресурсу).
- `ESC \` — термінатор `ST` (`\x1b\\`).

#### Словник керуючих параметрів

| Ключ | Назва | Допустимі значення | Призначення |
|---|---|---|---|
| `a` | Action | `t` / `T` (дефолт), `q`, `p`, `d`, `f`, `a` | Тип операції: `t` / `T` — передати та відобразити на позиції курсора; `q` — опитування підтримки; `p` — відобразити збережене зображення за `i`; `d` — видалити зображення/розміщення; `f` — передати кадр анімації; `a` — керування анімацією. |
| `f` | Format | `24`, `32`, `100` | Формат пікселів: `24` — сирий 24-бітний RGB (3 байти/піксель); `32` — сирий 32-бітний RGBA (4 байти/піксель з альфа-каналом); `100` — стиснений бінарний потік PNG. |
| `t` | Medium | `d` (дефолт), `f`, `t`, `s` | Середовище передачі даних: `d` — прямий Base64-пейлоад у потоці; `f` — звичайний файл (payload = шлях); `t` — тимчасовий файл (термінал видаляє файл після читання); `s` — спільна пам'ять POSIX (`shm_open`). |
| `s` | Source Width | Ціле додатне число | Фізична ширина вихідного зображення в пікселях (обов'язково для `f=24` та `f=32`). |
| `v` | Source Height | Ціле додатне число | Фізична висота вихідного зображення в пікселях (обов'язково для `f=24` та `f=32`). |
| `c` | Target Columns | Ціле додатне число | Бажана ширина на екрані в кількості текстових комірок (символьних колонок). Термінал масштабує зображення на GPU. |
| `r` | Target Rows | Ціле додатне число | Бажана висота на екрані в кількості текстових рядків. |
| `x`, `y` | Crop Offset | Цілі числа | Координати X та Y лівого верхнього кута прямокутної під-області для вирізки. |
| `w`, `h` | Crop Size | Цілі числа | Ширина та висота вирізки в пікселях. |
| `i` | Image ID | `1..4294967295` | Унікальний 32-бітний числовий ідентифікатор зображення для подальшого повторного використання чи видалення. |
| `p` | Placement ID | `1..4294967295` | Унікальний ідентифікатор конкретного екземпляра розміщення на екрані. |
| `m` | More Chunks | `0` (дефолт), `1` | Прапорець фрагментації: `1` — за цим пакетом слідуватиме продовження; `0` — останній фрагмент. |
| `q` | Quietness | `0`, `1`, `2` | Рівень сповіщень: `0` — термінал повертає `OK` або `error`; `1` — надсилати лише помилки; `2` — повне придушення відповідей. |
| `o` | Compression | `z` | Додаткове стиснення: payload попередньо стиснуто алгоритмом `zlib/deflate` перед Base64-кодуванням. |

#### Фрагментована передача великих зображень (Chunked Transmission)
Якщо розмір Base64-рядка перевищує 4096 байтів, потік розбивається на частини з прапорцем `m`:
1. **Перший чанк:** передає всі метадані конфігурації та прапорець `m=1`:
   `\x1b_Ga=T,f=100,i=42,m=1;<Base64_чанк_1>\x1b\\`
2. **Проміжні чанки:** містять лише прапорець продовження `m=1`:
   `\x1b_Gm=1;<Base64_чанк_2>\x1b\\`
3. **Фінальний чанк:** завершує передачу кадру з прапорцем `m=0`:
   `\x1b_Gm=0;<Base64_чанк_N>\x1b\\`

#### Запит підтримки протоколу терміналом
1. Програма надсилає тестовий запит: `\x1b_Gi=1,a=q;\x1b\\`
2. Термінал відповідає у потік stdin: `\x1b_Gi=1;OK\x1b\\` (протокол підтримується) або повертає опис помилки `\x1b_Gi=1;error:...\x1b\\`.

#### Команди видалення графіки
- `\x1b_Ga=d,d=a\x1b\\` — видалити абсолютно всі відображені графічні об'єкти на екрані.
- `\x1b_Ga=d,d=i,i=42\x1b\\` — видалити зображення з ідентифікатором `i = 42`.
- `\x1b_Ga=d,d=c\x1b\\` — видалити графіку, що перекриває поточну позицію курсора.

## Еталонний системний контракт викликів (C та C++)

Повний приклад надійної конфігурації raw mode з перевіркою кодів помилок, отриманням розміру екрана через `TIOCGWINSZ` з резервом на `CPR`, активацією розширеного протоколу клавіатури Kitty (`CSI u`), функціями взаємодії з заголовком вікна та системним буфером обміну через OSC, а також універсальним парсером клавіш:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <termios.h>
#include <sys/ioctl.h>
#include <errno.h>

enum EditorKey {
    KEY_NONE = 0,
    KEY_CHAR,
    KEY_ARROW_UP = 1000,
    KEY_ARROW_DOWN,
    KEY_ARROW_RIGHT,
    KEY_ARROW_LEFT,
    KEY_PAGE_UP,
    KEY_PAGE_DOWN,
    KEY_HOME,
    KEY_END,
    KEY_DELETE,
    KEY_ESCAPE,
    KEY_ENTER,
    KEY_TAB,
    KEY_BACKSPACE
};

struct KeyPressEvent {
    int key;
    int ch;
    int modifiers;
    int event_type; /* 1 = Press, 2 = Repeat, 3 = Release */
};

static struct termios orig_termios;
static int raw_mode_active = 0;
static int kitty_proto_active = 0;

void disable_raw_mode(void) {
    if (kitty_proto_active) {
        /* Pop Kitty keyboard mode */
        write(STDOUT_FILENO, "\x1b[<u", 4);
        kitty_proto_active = 0;
    }
    if (raw_mode_active) {
        tcsetattr(STDIN_FILENO, TCSAFLUSH, &orig_termios);
        raw_mode_active = 0;
    }
}

int enable_raw_mode(void) {
    if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) {
        return -1;
    }
    atexit(disable_raw_mode);

    struct termios raw = orig_termios;
    raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON);
    raw.c_oflag &= ~(OPOST);
    raw.c_cflag |= (CS8);
    raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG);
    raw.c_cc[VMIN] = 0;
    raw.c_cc[VTIME] = 1;

    if (tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw) == -1) {
        return -1;
    }
    raw_mode_active = 1;

    /* Push Kitty keyboard mode: Disambiguate (1) + Event Types (2) = 3 */
    if (write(STDOUT_FILENO, "\x1b[>3u", 5) == 5) {
        kitty_proto_active = 1;
    }
    return 0;
}

void set_window_title(const char *title) {
    if (!title) return;
    write(STDOUT_FILENO, "\x1b]0;", 4);
    write(STDOUT_FILENO, title, strlen(title));
    write(STDOUT_FILENO, "\x07", 1);
}

void clipboard_copy_osc52(const char *base64_text) {
    if (!base64_text) return;
    write(STDOUT_FILENO, "\x1b]52;c;", 7);
    write(STDOUT_FILENO, base64_text, strlen(base64_text));
    write(STDOUT_FILENO, "\x07", 1);
}

int get_window_size(int *rows, int *cols) {
    struct winsize ws;
    if (ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws) == 0 && ws.ws_col != 0) {
        *cols = ws.ws_col;
        *rows = ws.ws_row;
        return 0;
    }

    /* Резервний протокольний запит через CPR (Cursor Position Report) */
    if (write(STDOUT_FILENO, "\x1b[999C\x1b[999B\x1b[6n", 16) != 16) {
        return -1;
    }

    char buf[32];
    unsigned int i = 0;
    while (i < sizeof(buf) - 1) {
        if (read(STDIN_FILENO, &buf[i], 1) != 1) break;
        if (buf[i] == 'R') break;
        i++;
    }
    buf[i] = '\0';

    if (buf[0] != '\x1b' || buf[1] != '[') return -1;
    if (sscanf(&buf[2], "%d;%d", rows, cols) != 2) return -1;
    return 0;
}

int editor_read_key(struct KeyPressEvent *event) {
    event->key = KEY_NONE;
    event->ch = 0;
    event->modifiers = 1;
    event->event_type = 1;

    char c;
    int nread;
    while ((nread = read(STDIN_FILENO, &c, 1)) != 1) {
        if (nread == -1 && errno != EAGAIN && errno != EINTR) {
            return -1;
        }
        if (nread == 0) return KEY_NONE;
    }

    if (c == '\x1b') {
        char seq[32];
        if (read(STDIN_FILENO, &seq[0], 1) != 1) {
            event->key = KEY_ESCAPE;
            event->ch = '\x1b';
            return KEY_ESCAPE;
        }

        if (seq[0] == '[') {
            int idx = 1;
            while (idx < (int)sizeof(seq) - 1) {
                if (read(STDIN_FILENO, &seq[idx], 1) != 1) break;
                if ((seq[idx] >= 'A' && seq[idx] <= 'Z') ||
                    (seq[idx] >= 'a' && seq[idx] <= 'z') ||
                    seq[idx] == '~') {
                    idx++;
                    break;
                }
                idx++;
            }
            seq[idx] = '\0';

            /* Kitty Keyboard Protocol: розбір послідовностей CSI ... u */
            if (seq[idx - 1] == 'u') {
                int keycode = 0;
                int mods = 1;
                int ev_type = 1;
                if (sscanf(&seq[1], "%d;%d:%d", &keycode, &mods, &ev_type) >= 1 ||
                    sscanf(&seq[1], "%d;%d", &keycode, &mods) >= 1 ||
                    sscanf(&seq[1], "%d", &keycode) >= 1) {
                    event->modifiers = mods;
                    event->event_type = ev_type;
                    if (keycode == 27) { event->key = KEY_ESCAPE; return KEY_ESCAPE; }
                    if (keycode == 13) { event->key = KEY_ENTER; return KEY_ENTER; }
                    if (keycode == 9)  { event->key = KEY_TAB; return KEY_TAB; }
                    if (keycode == 127 || keycode == 8) { event->key = KEY_BACKSPACE; return KEY_BACKSPACE; }
                    event->key = KEY_CHAR;
                    event->ch = keycode;
                    return KEY_CHAR;
                }
            }

            /* Застарілі послідовності VT100 / xterm */
            if (seq[1] >= '0' && seq[1] <= '9') {
                if (seq[idx - 1] == '~') {
                    switch (seq[1]) {
                        case '1': case '7': event->key = KEY_HOME; return KEY_HOME;
                        case '3': event->key = KEY_DELETE; return KEY_DELETE;
                        case '4': case '8': event->key = KEY_END; return KEY_END;
                        case '5': event->key = KEY_PAGE_UP; return KEY_PAGE_UP;
                        case '6': event->key = KEY_PAGE_DOWN; return KEY_PAGE_DOWN;
                    }
                }
            } else {
                switch (seq[1]) {
                    case 'A': event->key = KEY_ARROW_UP; return KEY_ARROW_UP;
                    case 'B': event->key = KEY_ARROW_DOWN; return KEY_ARROW_DOWN;
                    case 'C': event->key = KEY_ARROW_RIGHT; return KEY_ARROW_RIGHT;
                    case 'D': event->key = KEY_ARROW_LEFT; return KEY_ARROW_LEFT;
                    case 'H': event->key = KEY_HOME; return KEY_HOME;
                    case 'F': event->key = KEY_END; return KEY_END;
                }
            }
        } else if (seq[0] == 'O') {
            if (read(STDIN_FILENO, &seq[1], 1) == 1) {
                switch (seq[1]) {
                    case 'H': event->key = KEY_HOME; return KEY_HOME;
                    case 'F': event->key = KEY_END; return KEY_END;
                }
            }
        }
        event->key = KEY_ESCAPE;
        event->ch = '\x1b';
        return KEY_ESCAPE;
    }

    event->key = KEY_CHAR;
    event->ch = (unsigned char)c;
    return KEY_CHAR;
}
```

```cpp
#include <iostream>

#include <tuple>
#include <system_error>
#include <unistd.h>
#include <termios.h>
#include <sys/ioctl.h>
#include <cerrno>

enum class EditorKey {
    None = 0,
    Char,
    ArrowUp = 1000,
    ArrowDown,
    ArrowRight,
    ArrowLeft,
    PageUp,
    PageDown,
    Home,
    End,
    Delete,
    Escape,
    Enter,
    Tab,
    Backspace
};

struct KeyInput {
    EditorKey key{EditorKey::None};
    int codepoint{0};
    int modifiers{1};
    int event_type{1}; // 1 = Press, 2 = Repeat, 3 = Release
};

class TerminalSession {
public:
    TerminalSession() {
        if (tcgetattr(STDIN_FILENO, &orig_termios_) == -1) {
            throw std::system_error(errno, std::generic_category(), "tcgetattr failed");
        }

        termios raw = orig_termios_;
        raw.c_iflag &= ~(BRKINT | ICRNL | INPCK | ISTRIP | IXON);
        raw.c_oflag &= ~(OPOST);
        raw.c_cflag |= (CS8);
        raw.c_lflag &= ~(ECHO | ICANON | IEXTEN | ISIG);
        raw.c_cc[VMIN] = 0;
        raw.c_cc[VTIME] = 1;

        if (tcsetattr(STDIN_FILENO, TCSAFLUSH, &raw) == -1) {
            throw std::system_error(errno, std::generic_category(), "tcsetattr failed");
        }
        is_active_ = true;

        // Push Kitty keyboard mode: Disambiguate (1) + Event Types (2) = 3
        if (write(STDOUT_FILENO, "\x1b[>3u", 5) == 5) {
            kitty_active_ = true;
        }
    }

    ~TerminalSession() noexcept {
        if (kitty_active_) {
            write(STDOUT_FILENO, "\x1b[<u", 4);
        }
        if (is_active_) {
            tcsetattr(STDIN_FILENO, TCSAFLUSH, &orig_termios_);
        }
    }

    TerminalSession(const TerminalSession&) = delete;
    TerminalSession& operator=(const TerminalSession&) = delete;
    TerminalSession(TerminalSession&&) noexcept = default;
    TerminalSession& operator=(TerminalSession&&) noexcept = default;

    void set_title(std::string_view title) const {
        std::string cmd = "\x1b]0;";
        cmd.append(title);
        cmd.push_back('\x07');
        write(STDOUT_FILENO, cmd.data(), cmd.size());
    }

    void copy_to_clipboard(std::string_view base64_payload) const {
        std::string cmd = "\x1b]52;c;";
        cmd.append(base64_payload);
        cmd.push_back('\x07');
        write(STDOUT_FILENO, cmd.data(), cmd.size());
    }

    [[nodiscard]] std::pair<int, int> get_window_size() const {
        winsize ws{};
        if (ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws) == 0 && ws.ws_col != 0) {
            return {ws.ws_row, ws.ws_col};
        }

        if (write(STDOUT_FILENO, "\x1b[999C\x1b[999B\x1b[6n", 16) != 16) {
            throw std::runtime_error("Failed to query cursor position report");
        }

        std::string response;
        char ch{};
        while (read(STDIN_FILENO, &ch, 1) == 1) {
            if (ch == 'R') break;
            response += ch;
        }

        int rows = 0, cols = 0;
        if (response.size() < 2 || response[0] != '\x1b' || response[1] != '[') {
            throw std::runtime_error("Invalid CPR response");
        }
        if (sscanf(&response[2], "%d;%d", &rows, &cols) != 2) {
            throw std::runtime_error("Failed to parse CPR response");
        }
        return {rows, cols};
    }

    [[nodiscard]] KeyInput read_key() const {
        KeyInput result{};
        char c{};
        ssize_t nread = 0;
        while ((nread = read(STDIN_FILENO, &c, 1)) != 1) {
            if (nread == -1 && errno != EAGAIN && errno != EINTR) {
                throw std::system_error(errno, std::generic_category(), "read failed");
            }
            if (nread == 0) return result;
        }

        if (c == '\x1b') {
            std::array<char, 32> seq{};
            if (read(STDIN_FILENO, &seq[0], 1) != 1) {
                result.key = EditorKey::Escape;
                result.codepoint = '\x1b';
                return result;
            }

            if (seq[0] == '[') {
                size_t idx = 1;
                while (idx < seq.size() - 1) {
                    if (read(STDIN_FILENO, &seq[idx], 1) != 1) break;
                    if ((seq[idx] >= 'A' && seq[idx] <= 'Z') ||
                        (seq[idx] >= 'a' && seq[idx] <= 'z') ||
                        seq[idx] == '~') {
                        idx++;
                        break;
                    }
                    idx++;
                }
                seq[idx] = '\0';

                // Kitty Keyboard Protocol (CSI ... u)
                if (idx > 1 && seq[idx - 1] == 'u') {
                    int keycode = 0, mods = 1, ev_type = 1;
                    if (sscanf(&seq[1], "%d;%d:%d", &keycode, &mods, &ev_type) >= 1 ||
                        sscanf(&seq[1], "%d;%d", &keycode, &mods) >= 1 ||
                        sscanf(&seq[1], "%d", &keycode) >= 1) {
                        result.modifiers = mods;
                        result.event_type = ev_type;
                        if (keycode == 27) { result.key = EditorKey::Escape; return result; }
                        if (keycode == 13) { result.key = EditorKey::Enter; return result; }
                        if (keycode == 9)  { result.key = EditorKey::Tab; return result; }
                        if (keycode == 127 || keycode == 8) { result.key = EditorKey::Backspace; return result; }
                        result.key = EditorKey::Char;
                        result.codepoint = keycode;
                        return result;
                    }
                }

                // Застарілі послідовності VT100 / xterm
                if (seq[1] >= '0' && seq[1] <= '9') {
                    if (seq[idx - 1] == '~') {
                        switch (seq[1]) {
                            case '1': case '7': result.key = EditorKey::Home; return result;
                            case '3': result.key = EditorKey::Delete; return result;
                            case '4': case '8': result.key = EditorKey::End; return result;
                            case '5': result.key = EditorKey::PageUp; return result;
                            case '6': result.key = EditorKey::PageDown; return result;
                        }
                    }
                } else {
                    switch (seq[1]) {
                        case 'A': result.key = EditorKey::ArrowUp; return result;
                        case 'B': result.key = EditorKey::ArrowDown; return result;
                        case 'C': result.key = EditorKey::ArrowRight; return result;
                        case 'D': result.key = EditorKey::ArrowLeft; return result;
                        case 'H': result.key = EditorKey::Home; return result;
                        case 'F': result.key = EditorKey::End; return result;
                    }
                }
            } else if (seq[0] == 'O') {
                if (read(STDIN_FILENO, &seq[1], 1) == 1) {
                    switch (seq[1]) {
                        case 'H': result.key = EditorKey::Home; return result;
                        case 'F': result.key = EditorKey::End; return result;
                    }
                }
            }
            result.key = EditorKey::Escape;
            result.codepoint = '\x1b';
            return result;
        }

        result.key = EditorKey::Char;
        result.codepoint = static_cast<unsigned char>(c);
        return result;
    }

private:
    termios orig_termios_{};
    bool is_active_{false};
    bool kitty_active_{false};
};
```
