# 📋 Інтерфейс ioctl для управління субтомами, знімками та клонуванням екстентів

Взаємодія програм користувацького простору з підсистемою Btrfs здійснюється через системний виклик `ioctl(2)` над відкритим файловим дескриптором директорії або файлу всередині монтованої файлової системи. Заголовкові файли `<linux/btrfs.h>` та `<linux/fs.h>` визначають константи викликів, прапорці, структури даних та специфічні бінарні коди для маніпуляції субтомами, знімками, квотовими групами (qgroups) та екстентами даних.

## Таблиця системних викликів ioctl Btrfs

Нижче наведено повний перелік керуючих команд `ioctl`, які використовують утиліти `btrfs-progs`, менеджери контейнерів (Docker, Podman, systemd-nspawn) та системні засоби створення резервних копій:

| Код ioctl | Структура аргументу | Опис операції та призначення |
| :--- | :--- | :--- |
| `BTRFS_IOC_SUBVOL_CREATE` | `struct btrfs_ioctl_vol_args` | Створення нового порожнього субтому у вказаній директорії |
| `BTRFS_IOC_SNAP_CREATE` | `struct btrfs_ioctl_vol_args` | Застарілий виклик створення знімка субтому (без прапорців) |
| `BTRFS_IOC_SNAP_CREATE_V2` | `struct btrfs_ioctl_vol_args_v2` | Сучасний розширений виклик створення знімка (підтримує Read-Only та qgroups) |
| `BTRFS_IOC_SNAP_DESTROY` | `struct btrfs_ioctl_vol_args` | Видалення субтому або знімка з B-дерева коренів |
| `BTRFS_IOC_SNAP_DESTROY_V2` | `struct btrfs_ioctl_vol_args_v2` | Асинхронне або специфічне за ID видалення субтому |
| `BTRFS_IOC_SUBVOL_GETFLAGS` | `__u64` | Отримання атрибутів та прапорців субтому |
| `BTRFS_IOC_SUBVOL_SETFLAGS` | `__u64` | Встановлення або скидання прапорців субтому (наприклад, `BTRFS_SUBVOL_RDONLY`) |
| `BTRFS_IOC_SEND` | `struct btrfs_ioctl_send_args` | Ініціалізація генерації бінарного потоку інкрементальної реплікації |
| `BTRFS_IOC_TREE_SEARCH_V2` | `struct btrfs_ioctl_search_args_v2` | Інспектування та обхід елементів B-дерев із користувацького простору |
| `FICLONE` | `int src_fd` | VFS ioctl: Copy-on-Write клонування всіх екстентів джерела в цільовий файл |
| `FICLONERANGE` | `struct file_clone_range` | VFS ioctl: Часткове клонування вирівняного за блоками діапазону екстентів |

## Детальний опис структур даних

### 1. Базова структура `btrfs_ioctl_vol_args`

Використовується викликами `BTRFS_IOC_SUBVOL_CREATE` та `BTRFS_IOC_SNAP_DESTROY`. Файловий дескриптор, над яким виконується `ioctl(2)`, повинен вказувати на батьківську директорію, всередині якої створюється або з якої вилучається субтом.

```c
// Заголовковий файл <linux/btrfs.h>
struct btrfs_ioctl_vol_args {
    __s64 fd;                           // FD вихідного субтому (тільки для застарілого BTRFS_IOC_SNAP_CREATE)
    char name[BTRFS_PATH_NAME_MAX + 1]; // Ім'я субтому, який створюють або видаляють (до 4087 символів)
};
```

Поле `fd` ігнорується при виконанні `BTRFS_IOC_SUBVOL_CREATE`. Поле `name` містить лише відносне ім'я нового субтому у батьківському каталозі (без шляхів із `/`). При виконанні видалення `BTRFS_IOC_SNAP_DESTROY` ядро вилучає запис про цей субтом із батьківської директорії та маркує відповідне B-дерево як видалене для фонової очистки потоком `btrfs-cleaner`.

### 2. Розширена структура `btrfs_ioctl_vol_args_v2`

Використовується викликом `BTRFS_IOC_SNAP_CREATE_V2` для атомарного задання режимів доступу та успадкування обмежень дискових квот.

```c
struct btrfs_ioctl_vol_args_v2 {
    __s64 fd;                         // Відкритий файловий дескриптор джерельного субтому
    __u64 transid;                    // Сюди ядро повертає номер транзакції створення
    __u64 flags;                      // Бітова маска прапорців створення
    union {
        struct {
            __u64 size;                                  // Розмір масиву qgroups у структурі
            struct btrfs_qgroup_inherit *qgroup_inherit; // Вказівник на структуру успадкування квот
        };
        __u64 unused[4];
    };
    union {
        char name[BTRFS_SUBVOL_NAME_MAX + 1]; // Ім'я нового субтому у батьківському каталозі
        __u64 devid;                          // ID пристрою (операції з пристроями)
        __u64 subvolid;                       // ID субтому для BTRFS_IOC_SNAP_DESTROY_V2
    };
};
```

#### Бітові прапорці для поля `flags`:
- `BTRFS_SUBVOL_CREATE_ASYNC` (`1ULL << 0`): Повертати керування негайно після додавання запису в пам'ять, не чекаючи фіксації транзакції на диск. Підтримку вилучено в ядрі 5.7 — від нього ioctl із цим бітом повертає `EOPNOTSUPP`.
- `BTRFS_SUBVOL_RDONLY` (`1ULL << 1`): Створити новий знімок у режимі «лише для читання». Зміна файлів у такому знімку блокуватиметься ядром на рівні VFS.
- `BTRFS_SUBVOL_QGROUP_INHERIT` (`1ULL << 2`): Вказує ядру Linux застосувати налаштування qgroup із поля `qgroup_inherit`.
- `BTRFS_SUBVOL_SPEC_BY_ID` (`1ULL << 4`): Використовується викликом `BTRFS_IOC_SNAP_DESTROY_V2` для вказання субтому за його 64-бітним numeric `subvolid`, а не за текстом імені в `name`. Біт `1ULL << 3` зайнятий прапорцем `BTRFS_DEVICE_SPEC_BY_ID`, який те саме робить для пристроїв.

### 3. Успадкування квот `struct btrfs_qgroup_inherit`

Коли при створенні субтому або знімка ввімкнено прапорець `BTRFS_SUBVOL_QGROUP_INHERIT`, ядро зчитує конфігурацію обмежень дискового простору:

```c
struct btrfs_qgroup_inherit {
    __u64 flags;                // Прапорці успадкування квот
    __u64 num_qgroups;          // Кількість батьківських qgroups у масиві
    __u64 num_ref_copies;       // Кількість квотових копій посилань
    __u64 num_excl_copies;      // Кількість квотових копій ексклюзивного простору
    struct btrfs_qgroup_limit lim; // Загальні обмеження (rfer/excl limits)
    __u64 qgroups[];            // Масив ідентифікаторів qgroups (Object IDs)
};
```

### 4. Управління режимним прапором `BTRFS_IOC_SUBVOL_SETFLAGS`

Переключення субтому між режимами Read-Write та Read-Only виконується системними викликами читання та запису прапорців над відкритим дескриптором самого субтому:

```c
__u64 flags = 0;

// Отримання поточних прапорців
if (ioctl(subvol_fd, BTRFS_IOC_SUBVOL_GETFLAGS, &flags) < 0) {
    perror("BTRFS_IOC_SUBVOL_GETFLAGS failed");
}

// Встановлення прапора Read-Only
flags |= BTRFS_SUBVOL_RDONLY;
if (ioctl(subvol_fd, BTRFS_IOC_SUBVOL_SETFLAGS, &flags) < 0) {
    perror("BTRFS_IOC_SUBVOL_SETFLAGS failed");
}
```

### 5. Структура інкрементальної реплікації `btrfs_ioctl_send_args`

Забезпечує роботу команди `btrfs send` для порівняння двох B-дерев та створення бінарного потоку змін.

```c
struct btrfs_ioctl_send_args {
    __s64 send_fd;          // Файловий дескриптор (пайп або сокет) для запису бінарного потоку
    __u64 clone_sources_cnt;// Кількість додаткових знімків-джерел для пошуку клонованих екстентів
    __u64 *clone_sources;   // Масив uint64_t з Root IDs субтомів-джерел
    __u64 parent_root;      // Root ID базового батьківського знімка (parent snapshot)
    __u64 flags;            // Прапорці відправки (наприклад, BTRFS_SEND_FLAG_NO_FILE_DATA)
    __u64 reserved[4];      // Резерв ядра для майбутніх розширень
};
```

При виконанні `BTRFS_IOC_SEND` ядро обходить B-дерево поточного субтому та порівнює його з B-деревом `parent_root`. Згенеровані інструкції кодування бінарного потоку записуються безпосередньо у `send_fd`.

## Специфікація VFS ioctls для клонування екстентів (Reflinks)

Два узагальнені системні виклики VFS розроблені спеціально для CoW-файлових систем і визначені у заголовковому файлі `<linux/fs.h>`.

### 1. Повне клонування `FICLONE`

```c
// dest_fd повинен бути відкритий з правом запису (O_WRONLY або O_RDWR)
// src_fd повинен бути відкритий з правом читання (O_RDONLY або O_RDWR)
int result = ioctl(dest_fd, FICLONE, src_fd);
```

При успішному виконанні запис `EXTENT_DATA` цільового файлу налаштовується на фізичні екстенти джерела, а лічильник посилань `refs` у `EXTENT_TREE` збільшується.

### 2. Часткове клонування `FICLONERANGE`

Дозволяє скопіювати лише певний фрагмент файлу без зачіпання решти даних.

```c
struct file_clone_range {
    __s64 src_fd;       // Файловий дескриптор джерела
    __u64 src_offset;   // Зсув у джерелі (повинен бути вирівняний по межі 4096 байтів)
    __u64 src_length;   // Довжина діапазону у байтах (0 означає "до кінця файлу")
    __u64 dest_offset;  // Зсув у цільовому файлі (вирівняний по 4096 байтів)
};

int result = ioctl(dest_fd, FICLONERANGE, &range);
```

Якщо `src_offset` або `dest_offset` не вирівняні по розміру блоку диска (зазвичай `4096` байтів), виклик поверне помилку `EINVAL`.

## Простеження операцій ядра через Tracepoints та sysfs

Для моніторингу та інспектування маніпуляцій із субтомами підсистема ядра Linux Btrfs експортує точку простеження (tracepoints) та структури у каталозі `sysfs`:

### Точки простеження `tracepoints` ядра Linux:
- `btrfs:btrfs_subvolume_create`: Викликається ядром у момент додавання нового вузла `btrfs_root_item` в `ROOT_TREE`.
- `btrfs:btrfs_snapshot_create`: Фіксує створення знімка із вихідного субтому з його UUID та згенерованими прапорцями.
- `btrfs:btrfs_cow_block`: Фіксує кожне виділення нового дискового блоку при хвилеподібному CoW-оновленні шляху дерева.

```bash
# Моніторинг створення субтомів та знімків у реальному часі через tracepoints
sudo trace-cmd record -e btrfs:btrfs_subvolume_create -e btrfs:btrfs_snapshot_create
```

### Інтерфейси `sysfs` у `/sys/fs/btrfs/`:
Кожен монтований том Btrfs представляється каталогом у `/sys/fs/btrfs/<UUID>/`:
- `/sys/fs/btrfs/<UUID>/allocation/data/bytes_used`: Загальний обсяг задіяного дискового простору для даних.
- `/sys/fs/btrfs/<UUID>/allocation/metadata/bytes_used`: Обсяг простору, зайнятий вузлами B-дерев метаданих.
- `/sys/fs/btrfs/<UUID>/generation`: Поточний глобальний номер генерації транзакцій файлової системи.

## Діагностика та коди помилок `errno`

При відмові системних викликів `ioctl` функція повертає `-1`, а глобальна змінна `errno` містить конкретну причину помилки:

- `EXDEV` (Invalid cross-device link): Виникає при спробі виконати `FICLONE` або `BTRFS_IOC_SNAP_CREATE_V2` між двома різними точками монтування або різними файловими системами.
- `EEXIST` (File exists): Спроба створити субтом або знімок із ім'ям, яке вже присутнє в даній батьківській директорії.
- `EROFS` (Read-only file system): Виклик модифікації файлів або створення субтому всередині знімка з прапорцем `BTRFS_SUBVOL_RDONLY`.
- `ENOSPC` (No space left on device): Неможливо виділити нові вузли B-дерева метаданих у `ROOT_TREE` або `EXTENT_TREE`.
- `EPERM` / `EACCES` (Operation not permitted): Спроба видалити субтом без прав власника чи `CAP_SYS_ADMIN` (том не змонтовано з опцією `user_subvol_rm_allowed`) або змінити дефолтний субтом без `CAP_SYS_ADMIN`. Створення субтому чи знімка привілеїв не потребує — досить права запису в батьківський каталог.
- `EINVAL` (Invalid argument): Передано невирівняні зсуви в `FICLONERANGE` або некоректні ідентифікатори у `btrfs_ioctl_vol_args_v2`.
