# 🔌 Архітектурне порівняння систем доповнення Bash та Zsh

Незважаючи на спільне історичне коріння в сімействі оболонок Bourne shell та використання термінальної бібліотеки редагування рядка, механізми автодоповнення в GNU Bash та Zsh базуються на принципово відмінних архітектурних парадигмах. Bash використовує пласку рядкову модель генерації списків з делегуванням форматування бібліотеці Readline, тоді як Zsh розгортає повноцінну підсистему контекстно-керованого синтаксичного аналізу `compsys`, інтегровану з власним редактором рядка ZLE (Zsh Line Editor).

Історично ранні версії Zsh використовували вбудовану команду `compctl`, яка за концепцією була схожою на `complete` у Bash. Проте починаючи з версії Zsh 4.0 розробники повністю відмовилися від цієї моделі на користь нової модульної підсистеми `compsys` (Completion System), побудованої на багаторівневому автоматі станів та декларативних специфікаціях.

## 1. Порівняння архітектурних моделей

| Критерій | Підхід GNU Bash (`complete` / Readline) | Підхід Z Shell (`zshcompsys` / ZLE) |
| :--- | :--- | :--- |
| **Фундаментальна парадигма** | Генерація одновимірного списку слів (flat string array). Повернення масиву `COMPREPLY`. | Обчислення контекстного стану та генерація типізованих об'єктів з метаданими (tags, groups, descriptions). |
| **Розбиття рядка на слова** | Механічне розбиття за статичним набором символів `COMP_WORDBREAKS`. | Повноцінний лексичний аналіз із врахуванням синтаксису лапок, дужок та конвеєрів безпосередньо рушієм ZLE. |
| **Опис граматики утиліт** | Ручний імперативний розбір у циклах `for`/`case` над масивом `COMP_WORDS`. | Декларативний синтаксис через функцію `_arguments` та автоматичний автомат станів (`->state`). |
| **Підтримка метаданих** | Відсутня. Readline отримує лише текстові значення підстановки. | Повна. Кожен елемент може містити підпис-опис (description), тег групи та власну палітру кольорів. |
| **Візуальний інтерфейс** | Статичний текстовий стовпчик або сітка варіантів. Прокрутка через внутрішній пейджер. | Інтерактивне меню (`menu-select`) з двовимірною навігацією стрілками клавіатури та пошуком на льоту. |
| **Автозавантаження правил** | Динамічний пошук файлу за назвою команди у системних каталогах `/usr/share/bash-completion`. | Автоматичне виявлення метаданих `#compdef` у каталогах масиву `$fpath` при ініціалізації `compinit`. |

## 2. Імперативний розбір проти декларативних специфікацій

Головна відмінність для розробника полягає у складності опису граматики опцій. У Bash кожне розгалуження вимагає написання коду перевірки попередніх токенів. Якщо прапорець приймає аргумент (наприклад, `-o output.txt`), сценарій Bash має вручну відстежувати, чи є попередній індекс `COMP_CWORD-1` цим прапорцем, чи користувач уже почав вводити наступний позиційний параметр.

У Zsh функція `_arguments` дозволяє описати повний контракт команди єдиним декларативним виразом:

:::tabs
```bash
# Bash: ручна перевірка контексту через індексацію слів
_mycmd_bash() {
    local cur prev
    cur="${COMP_WORDS[COMP_CWORD]}"
    prev="${COMP_WORDS[COMP_CWORD-1]}"

    case "$prev" in
        -o|--output)
            COMPREPLY=( $(compgen -f -- "$cur") )
            return 0
            ;;
        -l|--level)
            COMPREPLY=( $(compgen -W "debug info warn error" -- "$cur") )
            return 0
            ;;
    esac

    if [[ "$cur" == -* ]]; then
        COMPREPLY=( $(compgen -W "-o --output -l --level -h --help" -- "$cur") )
    fi
}
complete -F _mycmd_bash mycmd
```
```zsh
# Zsh: декларативний опис синтаксису через _arguments
#compdef mycmd

_mycmd_zsh() {
    _arguments -s -S \
        '(-h --help)'{-h,--help}'[Показати довідку]' \
        '(-o --output)'{-o,--output}'[Шлях до файлу звіту]:файл виводу:_files' \
        '(-l --level)'{-l,--level}'[Рівень логування]:рівень:(debug info warn error)' \
        '*:вхідні файли:_files -g "*.log"'
}
_mycmd_zsh "$@"
```
:::

Специфікація `_arguments` у Zsh одночасно визначає:
- Взаємне виключення опцій: рядок `'(-h --help)'` забороняє пропонувати коротку опцію `-h`, якщо вже введено довгу `--help`.
- Зв'язування опції з типом її аргументу: `:файл виводу:_files` вказує, що після `-o` автоматично запускається генератор файлів, а в терміналі відображається підказка `файл виводу`.
- Обробку залишкових позиційних аргументів: `'*:вхідні файли:_files -g "*.log"'` фільтрує всі подальші аргументи за розширенням `.log`.

## 3. Контекстна модель та механізм комплекторів (Completers)

У системі `compsys` виконання автодоповнення не зводиться до виклику однієї функції. Zsh пропускає введений рядок через ланцюжок так званих **комплекторів** (completer functions), які задаються змінною стилю:

```zsh
zstyle ':completion:*' completer _expand _complete _correct _approximate
```

Кожен комплектор виконує спеціалізовану трансформацію контексту:
1. `_expand`: Здійснює розкриття регулярних виразів glob, змінних середовища та числових діапазонів безпосередньо у рядку введення ще до аналізу команд.
2. `_complete`: Головний генератор точних збігів, який викликає специфічні сценарії команд (`_git`, `_docker`, `_systemctl`).
3. `_correct`: Виправляє друкарські помилки у назвах команд та опцій, пропонуючи варіант заміни у разі невеликої відстані Левенштейна.
4. `_approximate`: Нечітке (fuzzy) автодоповнення. Якщо точних збігів за введеним префіксом не знайдено, комплектор дозволяє наявність 1–2 помилкових символів та генерує список найближчих відповідників.

Bash не має вбудованої підтримки ланцюжків комплекторів: для реалізації нечіткого пошуку розробник змушений вручну писати алгоритми розрахунку відстані редагування на чистому Bash, що критично сповільнює відгук термінала.

## 4. Ієрархія контекстів zstyle та керування метаданими

На відміну від плаского масиву `COMPREPLY` у Bash, підсистема `compsys` передає результати разом із метаданими. Будь-який запит на автодоповнення формує ієрархічний контекстний рядок:

```text
:completion:<function>:<completer>:<command>:<argument>:<tag>
```

Наприклад, запит на доповнення опцій команди `ssh` розгортається у контекст `:completion::complete:ssh:options:flags`. Завдяки цьому користувач може налаштувати поведінку будь-якого елемента системи за допомогою команди `zstyle`:

```zsh
# Налаштування формату підписів для різних груп варіантів у Zsh
zstyle ':completion:*:descriptions' format '%F{yellow}-- %d --%f'
zstyle ':completion:*:corrections' format '%F{red}!- %d (помилок: %e) -!%f'
zstyle ':completion:*' group-name ''
zstyle ':completion:*:messages' format '%F{purple} %d %f'
zstyle ':completion:*:warnings' format '%F{red}Немає збігів для: %d%f'

# Визначення порядку відображення груп (спочатку локальні хости, потім користувачі)
zstyle ':completion:*:*:ssh:*' tag-order 'hosts users'
```

При доповненні складної команди (наприклад, `ssh <Tab>`) Zsh одночасно групує варіанти за джерелами:
- Конфігураційні хости з `~/.ssh/config`;
- Імена комп'ютерів із `/etc/hosts`;
- Користувачі системи.

У Bash такий розподіл неможливий: функція `complete` передає єдиний масив рядків, і Readline виводить їх суцільним списком, де перемішані системні облікові записи та імена серверів.

## 5. Інтерактивне меню ZLE проти пейджера Readline

Бібліотека GNU Readline при подвійному натисканні Tab друкує текстовий список варіантів під поточним командним рядком. Якщо варіантів більше, ніж висота вікна, Readline виводить діалог `--More--`.

Редактор Zsh Line Editor підтримує модуль `zsh/complist`, який активує повноцінне інтерактивне псевдографічне меню:

```zsh
# Увімкнення вибору елементів стрілками з підсвічуванням
zstyle ':completion:*' menu select=2
```

При натисканні Tab курсор переходить у сітку варіантів. Користувач переміщується між варіантами стрілками клавіатури `Left`/`Right`/`Up`/`Down`, поточний вибраний елемент підсвічується інверсним кольором або ANSI-палітрою, а рядок команди у верхній частині екрана оновлюється в реальному часі.

## 6. Продуктивність та модель завантаження

Обидві системи стикаються з проблемою часу запуску (startup time), якщо у системі встановлено сотні скриптів доповнення:
- **Bash**: Застосовує відкладене завантаження (dynamic loading) на рівні базового сценарію `/usr/share/bash-completion/bash_completion`. При першому введенні незнайомої команди спрацьовує обробник за замовчуванням `complete -D`, який шукає файл `/usr/share/bash-completion/completions/<cmd>`, зчитує його через `source` та повторно викликає доповнення.
- **Zsh**: Використовує механізм компільованих дампів `compdump`. При запуску `compinit` сканує заголовки `#compdef` у всіх каталогах `$fpath` і зберігає мапінг команд на функції у файлі `~/.zcompdump`. Завдяки цьому старт нової інтерактивної сесії займає менше 10–20 мілісекунд навіть при наявності понад 1000 функцій доповнення.
