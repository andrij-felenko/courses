# 📋 Вбудовані механізми програмованого доповнення Bash

Інтерфейс програмованого доповнення оболонки GNU Bash реалізовано через трійку вбудованих команд (`complete`, `compgen`, `compopt`), спеціальний набір змінних оточення з префіксом `COMP_*` та угоду про повернення результатів через масив `COMPREPLY`. Цей інтерфейс зв'язує низькорівневий цикл обробки клавіші Tab бібліотеки Readline із функціями простору користувача.

На рівні джерельного коду Bash (файли `pcomplete.c` та `pcomplete.h`) кожна зареєстрована специфікація зберігається у структурі `COMPSPEC`. Ця структура містить бітові маски дій, покажчики на списки слів, регулярні вирази фільтрації, ім'я викликаної функції та бітові прапорці поведінки Readline. Коли користувач натискає Tab, інтерпретатор шукає `COMPSPEC` для поточної команди й передає вказані параметри у виконавчий рушій.

## 1. Команда реєстрації обробників complete

Команда `complete` реєструє правила генерації варіантів для конкретної утиліти, псевдоніма або шаблону команди. Вона визначає, яку функцію, список або системний генератор викликатиме оболонка, коли курсор перебуває в позиції аргументу відповідної команди.

```text
complete [-abcdefgjksuv] [-o comp-option] [-DEI] [-A action] [-G globpat] 
         [-W wordlist] [-F function] [-C command] [-X filterpat] 
         [-P prefix] [-S suffix] [name ...]
complete -pr [-D] [-E] [-I] [name ...]
```

### Основні прапорці генераторів та джерел даних

| Прапорець | Джерело генерації варіантів | Опис та системне джерело |
| :--- | :--- | :--- |
| `-a` | Псевдоніми (alias) | Список зареєстрованих аліасів поточної сесії |
| `-b` | Вбудовані команди (builtins) | Внутрішні команди оболонки (`cd`, `echo`, `read` тощо) |
| `-c` | Усі доступні команди | Об'єднання аліасів, функцій, вбудованих команд та бінарників у `PATH` |
| `-d` | Каталоги | Тільки каталоги файлової системи |
| `-e` | Експортовані змінні | Змінні оточення, позначені атрибутом `export` |
| `-f` | Файли | Усі файли та каталоги файлової системи |
| `-j` | Завдання оболонки (jobs) | Ідентифікатори фонових та зупинених процесів (`%1`, `%+`) |
| `-k` | Зарезервовані слова | Ключові слова синтаксису (`if`, `then`, `while`, `case`) |
| `-s` | Служби (services) | Назви служб із системної бази `/etc/services` |
| `-u` | Користувачі | Імена облікових записів із бази NSS (`/etc/passwd`, LDAP, SSSD) |
| `-v` | Усі змінні | Будь-які змінні оболонки (як експортовані, так і локальні) |
| `-A action` | Іменована дія | Дія зі списку стандартних дій (наприклад, `-A hostname`, `-A stopped`) |
| `-G globpat` | Шаблон імен файлів | Розкриття шляхів за шаблоном підстановки glob (наприклад, `*.tar.gz`) |
| `-W wordlist` | Список слів | Рядок слів, розділених пропусками або значенням змінної `IFS` |
| `-F function` | Функція оболонки | Виклик функції Bash для обчислення масиву `COMPREPLY` |
| `-C command` | Зовнішня команда | Виконання зовнішньої програми у підоболонці для генерації списку |

### Прапорці режимів та спеціальних реєстрацій

Команда `complete` надає службові прапорці для визначення обробників широкого охоплення, які діють за межами індивідуальних імен утиліт:

| Прапорець | Призначення |
| :--- | :--- |
| `-D` | Реєстрація генератора за замовчуванням (Default). Викликається для будь-якої команди, яка не має індивідуального правила. Використовується системним завантажувачем `bash-completion`. |
| `-E` | Реєстрація генератора для порожнього рядка (Empty line). Спрацьовує при спробі доповнення на рядку, де не введено жодного символу. |
| `-I` | Реєстрація генератора для початкового слова команди (Initial command word). Обробляє доповнення найпершого слова рядка замість стандартного пошуку команд у `PATH`. |
| `-p [name]` | Друк поточних правил доповнення у форматі, придатному для повторного імпорту в Bash. |
| `-r [name]` | Видалення правила доповнення для вказаної команди або для всіх команд, якщо аргумент відсутній. |

### Опції поведінки обробника (-o comp-option)

Прапорець `-o` керує низькорівневими прапорцями обробки результатів у бібліотеці Readline. Ці прапорці безпосередньо мапуються на глобальні змінні стану Readline:

| Опція `-o` | Змінна Readline / Механізм | Поведінка Readline |
| :--- | :--- | :--- |
| `bashdefault` | Резервний обробник Bash | Якщо функція або генератор не повернули жодного варіанта, виконати стандартне доповнення Bash (файли, команди, змінні). |
| `default` | `rl_filename_completion_function` | Якщо збігів немає, застосувати стандартний механізм Readline (доповнення імен файлів через системний виклик `readdir()`). |
| `dirnames` | Фільтрація каталогів | Якщо згенерований список збігів порожній, виконати доповнення лише назвами каталогів файлової системи. |
| `filenames` | `rl_filename_completion_desired` | Повідомити Readline, що згенеровані варіанти є шляхами до файлів. Readline автоматично додасть слеш `/` до каталогів і екранує спеціальні символи. |
| `noquote` | `rl_filename_quoting_desired = 0` | Заборонити Readline автоматично екранувати лапками або зворотними слешами спеціальні символи у сформованих варіантах. |
| `nosort` | Відключення `qsort` | Заборонити алфавітне сортування варіантів; відображати елементи у точному порядку їх генерації обробником. |
| `nospace` | `rl_completion_suppress_append = 1` | Заборонити Readline автоматично додавати кінцевий пропуск після підстановки єдиного унікального збігу в кінець слова. |
| `plusdirs` | Об'єднання результатів | Спочатку обчислити збіги за правилом генератора, після чого додати до результату імена підкаталогів поточного каталогу. |

## 2. Команда генерації варіантів compgen

Вбудована команда `compgen` є обчислювальним рушієм фільтрації. Вона приймає ті самі прапорці генерації джерел, що й `complete`, але замість реєстрації правила негайно обчислює список варіантів, фільтрує їх за переданим префіксом і виводить результат у стандартний потік виводу (по одному варіанту на рядок).

```text
compgen [-abcdefgjksuv] [-o comp-option] [-A action] [-G globpat] 
        [-W wordlist] [-F function] [-C command] [-X filterpat] 
        [-P prefix] [-S suffix] [-- word]
```

### Внутрішній механізм роботи compgen

Коли `compgen` отримує запит, інтерпретатор виконує наступну послідовність дій:
1. Залежно від вказаного прапорця (`-u`, `-v`, `-f`, `-W`) формується первинний масив рядків. Для `-W` рядок розбивається на окремі слова за символами змінної `IFS` (або пропусками, якщо `IFS` не встановлена).
2. Якщо вказано останній аргумент `-- word`, `compgen` ітерується по масиву та відбирає лише ті елементи, які починаються з префікса `word` (порівняння рядків з фіксованою довжиною префікса).
3. Якщо задано шаблон фільтрації виключень `-X filterpat`, відібрані рядки зіставляються з патерном через функцію `fnmatch()`. Збіги видаляються зі списку (або залишаються, якщо патерн інвертовано знаком оклику `!`).
4. До кожного відібраного рядка додаються префікс `-P` та суфікс `-S`, якщо вони були вказані.
5. Результат виводиться у стандартний потік виводу, де кожен елемент розділено символом переходу на новий рядок `\n`.

### Практичні сценарії фільтрації compgen

```bash
# Фільтрація по списку слів за префіксом "st"
compgen -W "start status stop restart reload" -- "st"
# Вивід:
# start
# status
# stop

# Пошук активних користувачів на літеру "r"
compgen -u -- "r"
# Вивід:
# root
# rpc

# Пошук змінних оточення, що починаються з "LC_"
compgen -v -- "LC_"
# Вивід:
# LC_ALL
# LC_CTYPE
# LC_MESSAGES

# Доповнення файлів з фільтрацією виключень: залишаємо лише файли C/C++
compgen -f -X '!*.@(c|cpp|cc|h|hpp)' -- "src/m"
```

## 3. Команда динамічного налаштування compopt

Команда `compopt` призначена для динамічної зміни параметрів генерації (`-o comp-option`) безпосередньо під час виконання функції доповнення. Вона дозволяє сценарію вмикати або вимикати прапорці залежно від контексту поточного аргументу.

```text
compopt [-o comp-option] [+o comp-option] [-D] [-E] [-I] [name ...]
```

### Синтаксис прапорців

- `-o comp-option`: Увімкнути вказану опцію для поточної операції доповнення.
- `+o comp-option`: Вимкнути вказану опцію для поточної операції доповнення.

### Приклад контекстного перемикання опцій

Під час написання комплішена для прапорців виду `--key=value` поведінка має змінюватися залежно від того, з якого боку від знака `=` знаходиться курсор:

```bash
_custom_kv_complete() {
    local cur="${COMP_WORDS[COMP_CWORD]}"
    if [[ "$cur" == *=* ]]; then
        # Праворуч від '=': доповнюємо шляхи до файлів, блокуємо зайвий пропуск
        compopt -o filenames -o nospace
        COMPREPLY=( $(compgen -f -- "${cur#*=}") )
    else
        # Ліворуч від '=': пропонуємо назви ключів із додаванням знака '='
        compopt -o nospace
        COMPREPLY=( $(compgen -W "host= port= timeout= cert=" -- "$cur") )
    fi
}
```

## 4. Контекстні змінні середовища оболонки

Під час виклику функції доповнення, зареєстрованої через `complete -F function`, Bash ініціалізує ряд спеціальних змінних, які описують повний контекст термінального буфера:

### Таблиця змінних COMP_*

| Змінна | Тип | Опис та призначення |
| :--- | :--- | :--- |
| `COMP_WORDS` | Масив (array) | Масив окремих слів у поточному командному рядку, розбитих за символами `COMP_WORDBREAKS`. Елемент `COMP_WORDS[0]` містить ім'я самої команди. |
| `COMP_CWORD` | Ціле число (int) | Індекс у масиві `COMP_WORDS`, що вказує на слово, на якому зараз розташований курсор користувача. |
| `COMP_LINE` | Рядок (string) | Повний сирий текст поточного командного рядка, введений користувачем до натискання Tab. |
| `COMP_POINT` | Ціле число (int) | Позиція курсора у байтах від початку рядка `COMP_LINE` у мить натискання Tab. |
| `COMP_KEY` | Ціле число (int) | ASCII-код клавіші, яка викликала операцію доповнення (для клавіші Tab значення дорівнює `9`). |
| `COMP_TYPE` | Ціле число (int) | Числовий код типу операції доповнення, що виконується в Readline. |
| `COMP_WORDBREAKS` | Рядок (string) | Набір символів, які Readline вважає межами між словами. Типове значення: ` \t\n"'><=;|&(:`. |
| `COMPREPLY` | Масив (array) | Масив результатів, який функція доповнення зобов'язана заповнити. Bash передає елементи цього масиву назад у Readline. |

### Числові значення змінної COMP_TYPE

Змінна `COMP_TYPE` дозволяє функції адаптувати генерацію варіантів залежно від того, як саме користувач викликав доповнення:

| Значення | Символ / Константа | Режим виклику |
| :--- | :--- | :--- |
| `9` | `TAB` | Звичайне автодоповнення за першим натисканням Tab. |
| `63` | `?` | Повторне натискання Tab для відображення повного списку варіантів. |
| `33` | `!` | Доповнення після невдалої спроби знайти збіг за префіксом. |
| `64` | `@` | Спеціальне доповнення для виклику списку можливих команд без підстановки. |
| `37` | `%` | Меню-доповнення (почерговий перебір варіантів у рядку). |

### Байти проти символів у COMP_POINT

Змінна `COMP_POINT` містить абсолютне зміщення курсора у байтах. У сучасних UTF-8 терміналах кириличні символи, ієрогліфи або емодзі займають від 2 до 4 байтів. 
Якщо рядок містить багатобайтові символи, позиція курсора у символах (символьний індекс) відрізнятиметься від байтового індексу `COMP_POINT`. Тому при маніпуляціях із рядком через зрізи `${COMP_LINE:0:COMP_POINT}` слід враховувати налаштування локалі або використовувати прямий розбір слів через масив `COMP_WORDS`.

## 5. Допоміжні функції бібліотеки bash-completion

У стандартному середовищі Linux пакунок `bash-completion` надає стандартизовану бібліотеку функцій, які нівелюють вади базового парсингу слів у Bash та спрощують обробку складних аргументів:

### `_init_completion [-n exclude_chars] [-s]`

Ініціалізує стандартизовані змінні `cur` (поточне слово), `prev` (попереднє слово), `words` (масив слів без хибного розбиття двокрапками) та `cword` (індекс поточного слова).
Прапорець `-n exclude_chars` вказує, які символи слід ігнорувати як роздільники слів під час формування контексту. Прапорець `-s` вмикає спрощений режим для команд із короткими однолітерними прапорцями.

```bash
_mytool() {
    local cur prev words cword
    _init_completion -n ":=" || return

    case "$prev" in
        --config)
            _filedir "yaml|json"
            return
            ;;
        --port)
            COMPREPLY=( $(compgen -W "80 443 8080 8443" -- "$cur") )
            return
            ;;
    esac
}
```

### `_get_comp_words_by_ref [-n exclude_chars] [-c cur] [-p prev] [-w words] [-i cword]`

Витягує посилання на слова командного рядка, виключаючи вказані символи (наприклад, двокрапку `:` чи знак `=`) зі списку роздільників слів. Це запобігає розриву таких параметрів, як `--opt=val` або `localhost:8080`, на окремі елементи масиву `COMP_WORDS`.

### `_filedir [-d] [extension_pattern]`

Стандартизований генератор доповнення файлів і каталогів. На відміну від сирого `compgen -f`, функція `_filedir` коректно обробляє екранування спеціальних символів, шляхи з пропусками, розкриття тильди `~` та підтримує фільтрацію розширень через регулярні вирази (наприклад, `_filedir '@(mp3|flac|ogg)'`). Прапорець `-d` обмежує вивід лише каталогами.

### `__ltrim_colon_completions <prefix_word>`

Видаляє префікс до двокрапки з усіх елементів масиву `COMPREPLY`. Необхідна у випадках, коли змінна `COMP_WORDBREAKS` містить символ `:`, через що Readline при вставці результату вважає двокрапку початком нового слова і помилково дублює ліву частину рядка.

## 6. Налагодження функцій автодоповнення

Оскільки стандартний потік виводу функції автодоповнення перехоплюється Readline для формування підказок, використання звичайного `echo` або `printf` усередині функції доповнення призводить до спотворення інтерфейсу командного рядка.

Для безпечного налагодження та трасування стану змінних застосовують перенаправлення діагностичних повідомлень в окремий файл або сусідній термінал TTY:

```bash
_debug_completion() {
    local log_file="/tmp/bash_completion_debug.log"
    {
        echo "=== $(date) ==="
        echo "COMP_LINE:  '$COMP_LINE'"
        echo "COMP_POINT: $COMP_POINT"
        echo "COMP_CWORD: $COMP_CWORD"
        echo "COMP_WORDS: ${COMP_WORDS[*]}"
        echo "cur:        '$cur'"
        echo "prev:       '$prev'"
    } >> "$log_file"
}
```

Іншим ефективним методом є тимчасова інспекція зареєстрованих обробників через `complete -p <command>`, що дозволяє перевірити, чи правильний скрипт було завантажено динамічним завантажувачем.
