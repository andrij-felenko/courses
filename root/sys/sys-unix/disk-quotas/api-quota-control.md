# 📋 quotactl(): контракт керування квотами

Усе керування квотами — увімкнення обліку на файловій системі, читання рахунку, виставлення меж, обхід усіх власників — робить один системний виклик `quotactl()`. Тут зібрано його контракт: як кодується команда, що лежить у структурах і, найголовніше, **у яких одиницях** — бо сусідні поля тієї самої структури міряють місце по-різному, і саме на цьому помиляються найчастіше.

## Два виклики

```c
#include <sys/quota.h>

int quotactl(int cmd, const char *special, int id, caddr_t addr);
int quotactl_fd(int fd, int cmd, int id, void *addr);   /* ядро 5.14+, glibc 2.36+ */
```

`special` — шлях до **блокового пристрою** (`/dev/sda1`), а не до точки монтування; точка монтування дає `ENOTBLK`. Через це старий виклик безсилий там, де пристрою немає взагалі — tmpfs, мережеві та накладені файлові системи. Тому в ядрі 5.14 з'явився `quotactl_fd()`: він бере дескриптор будь-якого файлу чи каталогу на потрібній файловій системі (годиться й відкритий з `O_PATH`). Плата за зручність одна: його `Q_QUOTAON` ігнорує `addr` та `id`, тож придатний лише там, де файли квот — приховані системні inode.

## Слово команди

```c
#define SUBCMDSHIFT 8
#define SUBCMDMASK  0x00ff
#define QCMD(cmd, type)  (((cmd) << SUBCMDSHIFT) | ((type) & SUBCMDMASK))

#define USRQUOTA 0
#define GRPQUOTA 1
#define PRJQUOTA 2
```

Перший аргумент — не команда, а команда разом із типом рахунку: старші біти кажуть, що робити, молодший байт — за чиїм рахунком.

![Схема кодування першого аргументу quotactl(): угорі підпис виклику, ліворуч картка «підкоманда» з шістнадцятковими значеннями Q_GETQUOTA, Q_SETQUOTA і Q_XGETQUOTA, праворуч картка «тип рахунку» зі значеннями USRQUOTA 0, GRPQUOTA 1, PRJQUOTA 2, від обох стрілки вниз до картки QCMD із формулою (підкоманда << 8) | (тип & 0xff) і двома прикладами обчислених значень](img/qcmd-encoding.svg)

*Той самий тип підставляють і до звичайних команд `Q_*`, і до XFS-івських `Q_X*`.*

## Команди VFS

| команда | що робить | `id` | `addr` | повноваження |
|---|---|---|---|---|
| `Q_QUOTAON` `0x800002` | вмикає облік і примус | номер формату | шлях до файлу квот | `CAP_SYS_ADMIN` |
| `Q_QUOTAOFF` `0x800003` | вимикає | — | — | `CAP_SYS_ADMIN` |
| `Q_GETQUOTA` `0x800007` | межі й ужиток одного рахунку | uid / gid / projid | `struct dqblk` | свій — вільно, чужий — `CAP_SYS_ADMIN` |
| `Q_GETNEXTQUOTA` `0x800009` (4.6+) | перший наявний рахунок із номером ≥ `id` | звідки шукати | `struct nextdqblk` | те саме |
| `Q_SETQUOTA` `0x800008` | виставляє межі, ужиток, строки | номер рахунку | `struct dqblk` + маска | `CAP_SYS_ADMIN` |
| `Q_GETINFO` `0x800005` | пільгові строки й прапорці | — | `struct dqinfo` | — |
| `Q_SETINFO` `0x800006` | те саме на запис | — | `struct dqinfo` + маска | `CAP_SYS_ADMIN` |
| `Q_GETFMT` `0x800004` | чинний формат файлів квот | — | буфер на 4 байти | — |
| `Q_SYNC` `0x800001` | скидає рахунки на носій | — | — | — |

Формати для `Q_QUOTAON`: `QFMT_VFS_OLD` (1) — первісний; `QFMT_VFS_V0` (2) — 32-бітові номери, межі до 2⁴² байтів; `QFMT_VFS_V1` (4) — межі до 2⁶³−1 байтів і стільки ж inode.

`Q_GETNEXTQUOTA` виглядає дрібницею, але без нього перелічити всіх, у кого є рахунок, можна тільки перебором усіх можливих номерів від 0 до 2³²−1. Саме тому звіт по великій файловій системі колись коштував так дорого.

## struct dqblk і одиниці

```c
struct dqblk {                 /* у <linux/quota.h> та сама розкладка зветься if_dqblk */
    uint64_t dqb_bhardlimit;   /* блоки по 1024 байти */
    uint64_t dqb_bsoftlimit;   /* блоки по 1024 байти */
    uint64_t dqb_curspace;     /* БАЙТИ */
    uint64_t dqb_ihardlimit;   /* штук inode */
    uint64_t dqb_isoftlimit;   /* штук inode */
    uint64_t dqb_curinodes;    /* штук inode */
    uint64_t dqb_btime;        /* момент, коли спливе пільговий строк за блоками */
    uint64_t dqb_itime;        /* те саме за inode */
    uint32_t dqb_valid;        /* маска QIF_* */
};
```

Пастка тут одна, зате чіпка: **межі задані в блоках по 1024 байти, а зайняте місце — просто в байтах**. Порівнювати їх напряму не можна:

```
скільки лишилося (КіБ) = dqb_bhardlimit − dqb_curspace / 1024
```

І «блок» у цій структурі не має нічого спільного з блоком файлової системи — він завжди кілобайт, хоч у ext4 блок типово 4 КіБ.

Друга тонкість — час. `dqb_btime` і `dqb_itime` — не тривалість, а **момент**: секунди від епохи, коли пільговий строк спливе. Нуль означає, що м'яку межу не перейдено.

Маска `dqb_valid` каже, які поля брати до уваги:

| константа | значення | поля |
|---|---|---|
| `QIF_BLIMITS` | 1 | `dqb_bhardlimit`, `dqb_bsoftlimit` |
| `QIF_SPACE` | 2 | `dqb_curspace` |
| `QIF_ILIMITS` | 4 | `dqb_ihardlimit`, `dqb_isoftlimit` |
| `QIF_INODES` | 8 | `dqb_curinodes` |
| `QIF_BTIME` | 16 | `dqb_btime` |
| `QIF_ITIME` | 32 | `dqb_itime` |
| `QIF_LIMITS` · `QIF_USAGE` · `QIF_TIMES` · `QIF_ALL` | — | попарні об'єднання й усе разом |

Читаючи (`Q_GETQUOTA`), маску заповнює ядро. Записуючи (`Q_SETQUOTA`), її ставите ви — і це єдиний спосіб змінити межу, не зачепивши лічильника ужитку. Дозвіл писати в `dqb_curspace` тут не примха: саме ним інструмент перевірки повертає лічильник до дійсності після збою.

## Пільговий строк: struct dqinfo

```c
struct dqinfo {
    uint64_t dqi_bgrace;   /* секунди; типово 604800 — сім діб */
    uint64_t dqi_igrace;   /* секунди */
    uint32_t dqi_flags;    /* DQF_ROOT_SQUASH = 1<<0 · DQF_SYS_FILE = 1<<16 */
    uint32_t dqi_valid;    /* IIF_BGRACE 1 · IIF_IGRACE 2 · IIF_FLAGS 4 */
};
```

Ось де тривалість справді тривалість — на противагу `dqb_btime`. Строк один на всю файлову систему; окремому рахунку можна лише пересунути момент його кінця, записавши `dqb_btime` з маскою `QIF_BTIME`. Прапорець `DQF_SYS_FILE` у відповіді `Q_GETINFO` — ознака, що файли квот приховані від каталогу й живуть системними inode.

## Окремий набір для XFS

XFS ніколи не жила за схемою «файл квот у корені», тож має власні команди — `Q_XQUOTAON`, `Q_XQUOTAOFF`, `Q_XGETQUOTA`, `Q_XGETNEXTQUOTA` (4.6+), `Q_XSETQLIM`, `Q_XGETQSTAT`, `Q_XGETQSTATV`, `Q_XQUOTARM` — з кодами `XQM_CMD(x) = ('X' << 8) + x`. Замість `dqblk` вони беруть `struct fs_disk_quota`.

Головне про неї — знову одиниці: і межі (`d_blk_hardlimit`, `d_blk_softlimit`), і ужиток (`d_bcount`) міряються **базовими блоками по 512 байтів**. Число, перенесене з VFS-структури без перерахунку, дасть удвічі меншу межу, ніж хотіли. Поле `d_fieldmask` грає роль `dqb_valid`, тільки з константами `FS_DQ_BSOFT`, `FS_DQ_BHARD`, `FS_DQ_ISOFT`, `FS_DQ_IHARD`, `FS_DQ_BTIMER` і подібними; `d_flags` каже, який це тип рахунку (`XFS_USER_QUOTA`, `XFS_GROUP_QUOTA`, `XFS_PROJ_QUOTA`); `d_itimer` і `d_btimer` — нуль, поки м'яку межу не перейдено, інакше момент кінця строку. Поля `d_rtb_*` стосуються realtime-підтому — окремої ділянки XFS для потоків із гарантованою швидкістю; на звичайній файловій системі вони нулі.

Відмінність є і в самому житті обліку: в XFS **облік вмикається лише під час монтування**, і вимкнути його на змонтованій системі не можна. `Q_XQUOTAON` перемикає тільки примус меж — облік має вже йти. Для кореневої файлової системи параметри тому й доводиться передавати через `rootflags=` у командному рядку ядра.

## Повноваження

Речі три, і плутати їх не варто:

- **своє прочитати** — без жодних повноважень;
- **будь-яка зміна** (`Q_SETQUOTA`, `Q_QUOTAON`/`Q_QUOTAOFF`, `Q_SETINFO`, `Q_XSETQLIM`…) і **чуже прочитати** — `CAP_SYS_ADMIN`, інакше `EPERM`;
- **переступити жорстку межу під час запису** — `CAP_SYS_RESOURCE`; це вже не про `quotactl()`, а про те, чому службі не треба вимикати квоти, щоб дописати свій журнал.

Обидві назви — з набору [окремих дозволів, на які розібрано повноваження root](root:sys-unix/capabilities): процес може мати `CAP_SYS_RESOURCE` і не мати `CAP_SYS_ADMIN`.

Помилки, які трапляються найчастіше: `ENOSYS` — ядро зібране без `CONFIG_QUOTA`; `ESRCH` — квоти на цій файловій системі не ввімкнені або такого рахунку немає; `EBUSY` — `Q_QUOTAON` уже виконано; `ERANGE` — межа не влазить у чинний формат; `ENOTBLK` — у `special` не блоковий пристрій.

## Як облік вмикають

Сам виклик нічого не ввімкне на файловій системі, яка про квоти не знає: спершу її треба [змонтувати з відповідними параметрами](root:sys-unix/mount-model) або дати їй потрібну властивість.

| випадок | що зробити |
|---|---|
| ext4, зовнішні файли квот | `mount -o usrquota,grpquota`, файли `aquota.user`/`aquota.group` у корені тому, далі `quotacheck` і `quotaon` |
| те саме, але через журнал | `-o usrjquota=aquota.user,grpjquota=aquota.group,jqfmt=vfsv1` — правка рахунку стає частиною транзакції |
| ext4, вбудовані квоти | `tune2fs -O quota` (тонше — `tune2fs -Q usrquota,grpquota,prjquota`): файли квот стають прихованими системними inode, вмикаються самі при монтуванні, звіряються `e2fsck` |
| проєктні квоти в ext4 | додатково властивість `project` і параметр `prjquota` |
| XFS | `mount -o uquota,gquota,pquota`; для обліку без примусу — `uqnoenforce` тощо |

## Інструменти

| програма | роль |
|---|---|
| `quotaon` / `quotaoff` | `Q_QUOTAON` / `Q_QUOTAOFF` — вмикає й вимикає примус |
| `quotacheck` | повний обхід усіх inode і перезапис файлів квот, коли лічильник розійшовся з дійсністю |
| `quota` | `Q_GETQUOTA` для одного номера — «скільки в мене лишилося» |
| `repquota` | звіт по всіх рахунках тому: `Q_GETNEXTQUOTA` там, де він є |
| `edquota` | `Q_GETQUOTA` → текстовий редактор → `Q_SETQUOTA` |
| `setquota` | те саме без редактора, межі аргументами — для скриптів |
| `warnquota` | обхід рахунків і листи тим, хто перейшов м'яку межу |
| `xfs_quota` | увесь набір `Q_X*` в одній оболонці з власними командами |

## Мінімальний робочий виклик

Прочитати власний рахунок і показати, скільки лишилося, — єдина дія, для якої не потрібно жодних повноважень:

```c
#define _GNU_SOURCE
#include <sys/quota.h>
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    struct dqblk d;

    if (quotactl(QCMD(Q_GETQUOTA, USRQUOTA), "/dev/sda1",
                 getuid(), (caddr_t)&d) < 0) {
        perror("quotactl");          /* ESRCH — квоти тут не ввімкнені */
        return 1;
    }

    printf("ужито %llu КіБ, м'яка межа %llu КіБ, жорстка %llu КіБ\n",
           (unsigned long long)(d.dqb_curspace / 1024),   /* байти → КіБ */
           (unsigned long long)d.dqb_bsoftlimit,          /* уже в КіБ */
           (unsigned long long)d.dqb_bhardlimit);
    return 0;
}
```

А ось запис: важить не лише нове число, а й маска — без неї виклик перепише ще й лічильник ужитку нулями зі свіжозаведеної структури.

```c
struct dqblk d = { 0 };

d.dqb_bsoftlimit = 4ULL * 1024 * 1024;   /* 4 ГіБ у блоках по 1024 Б */
d.dqb_bhardlimit = 5ULL * 1024 * 1024;   /* 5 ГіБ */
d.dqb_valid      = QIF_BLIMITS;          /* чіпаємо ЛИШЕ межі блоків */

quotactl(QCMD(Q_SETQUOTA, GRPQUOTA), "/dev/sda1", 200, (caddr_t)&d);
```
