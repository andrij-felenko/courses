# 📋 Довідник API: BPF Iterators та BPF User Ring Buffer

Цей довідник містить систематичний опис інтерфейсів програмування, внутрішніх структур даних ядра Linux, сигнатур викликів допоміжних функцій BPF (kernel helpers) та функцій користувацької бібліотеки `libbpf` для роботи з програмованими ітераторами `bpf_iter` та кільцевим буфером користувача `BPF_MAP_TYPE_USER_RINGBUF`.

---

## 1. Контексти та структури BPF Iterators (`bpf_iter`)

При виконанні BPF-програми типу `BPF_PROG_TYPE_TRACING` з секцією `SEC("iter/<target>")`, ядро підготує та передасть у програму вказівник на відповідну структуру контексту. Кожен тип ітератора оперує власним типом контексту, що надає прочитальний доступ до внутрішніх полів ядерних об'єктів.

### 1.1 Загальна мета-структура `struct bpf_iter_meta`

Структура `bpf_iter_meta` є першим обов'язковим полем у всіх спеціалізованих контекстах ітераторів. Вона надає метаінформацію про поточний стан обходу колекції та вказівник на послідовний файл VFS.

```c
struct bpf_iter_meta {
    struct seq_file *seq; /* Вказівник на послідовний файл підсистеми VFS */
    __u64 session_id;     /* Унікальний ідентифікатор сесії ітерації */
    __u64 seq_num;        /* Монотонний номер поточного кроку ітерації (починається з 0) */
};
```

Поле `seq` використовується для передачі у помічники форматування `bpf_seq_printf()` та `bpf_seq_write()`. Поле `session_id` залишається незмінним протягом усього циклу читання файла від `open()` до `release()`. Поле `seq_num` збільшується на одиницю при кожному успішному виклику BPF-програми.

### 1.2 Контекст ітератора процесів (`iter/task`)

Ітератор процесів використовується для обходу всіх елементів глобального списку задач ядра Linux (`struct task_struct`).

```c
struct bpf_iter__task {
    struct bpf_iter_meta *meta; /* Загальна метаінформація сесії */
    struct task_struct *task;   /* Вказівник на поточний процес у ядрі */
};
```

Вказівник `task` посилається на поточну структуру `task_struct`. У випадку, коли ядро досягає кінця списку процесів, воно викликає BPF-програму востаннє, передаючи `task == NULL`. Перевірка `if (task == NULL)` є обов'язковою у кожній програмі `iter/task` для запобігання розіменуванню нульового вказівника та сигналізації про завершення збору даних.

### 1.3 Контекст ітератора файлових дескрипторів (`iter/task_file`)

Ітератор файлових дескрипторів дозволяє проаналізувати всі відкриті файли у таблиці файлових дескрипторів конкретного процесу або всіх процесів системи.

```c
struct bpf_iter__task_file {
    struct bpf_iter_meta *meta; /* Загальна метаінформація */
    struct task_struct *task;   /* Процес-власник файлового дескриптора */
    __u32 fd;                   /* Числовий індекс файлового дескриптора */
    struct file *file;          /* Вказівник на структуру file ядра */
};
```

Поле `fd` містить цілочисельний дескриптор (наприклад, 0 для stdin, 1 для stdout), а поле `file` посилається на внутрішню структуру ядра `struct file`, що описує відкритий іннод, прапорці доступу та поточну позицію у файлі.

### 1.4 Контекст ітератора TCP-сокетів (`iter/tcp`)

Спеціалізований ітератор мережевої підсистеми для обходу таблиць активних сокетів протоколу TCP.

```c
struct bpf_iter__tcp {
    struct bpf_iter_meta *meta;     /* Загальна метаінформація */
    struct tcp_sock *conn_tcp;      /* Вказівник на структуру TCP-сокета ядра */
    __u32 socket_cur_skmem;         /* Обсяг виділеної сокету оперативної пам'яті */
};
```

Вказівник `conn_tcp` надає повний доступ до полів `struct tcp_sock`, включаючи стан з'єднання (`sk_state`), IP-адреси та порти джерела/призначення, розміри вікон віртуального передавання та статистику ретрансмісій.

### 1.5 Контекст ітератора елементів мап BPF (`iter/bpf_map_elem`)

Ітератор елементів мап BPF дозволяє послідовно обійти всі записи у будь-якій мапі BPF (Hash, Array, LRTU) без необхідності робити системні виклики `bpf_map_get_next_key()`.

```c
struct bpf_iter__bpf_map_elem {
    struct bpf_iter_meta *meta; /* Загальна метаінформація */
    struct bpf_map *map;        /* Цільова мапа BPF */
    void *key;                  /* Вказівник на ключ поточного елемента */
    void *value;                /* Вказівник на значення поточного елемента */
};
```

Поля `key` та `value` надають прямі прочитальні вказівники на пам'ять елемента всередині ядра, що дозволяє BPF-програмі виконувати аналіз складних мап великого розміру за один прохід.

## 2. Помічники ядра (Kernel Helpers) для BPF Iterators

Для формування виводу BPF-ітератора у буфер підсистеми `seq_file` використовуються спеціалізовані помічники ядра BPF.

### 2.1 Функція `bpf_seq_printf`

Виконує відформатований запис текстового рядка у буфер `seq_file`.

```c
long bpf_seq_printf(struct seq_file *m, const char *fmt, __u32 fmt_size, 
                   const void *data, __u32 data_len);
```

- **`m`**: Вказівник на структуру `seq_file`, отриманий з початкового поля `meta->seq` контексту ітератора.
- **`fmt`**: Вказівник на статичний рядок форматування (аналог специфікаторів `printf`).
- **`fmt_size`**: Загальний розмір рядка форматування в байтах, включаючи завершальний нульовий символ `\0`.
- **`data`**: Вказівник на упакований масив аргументів форматування.
- **`data_len`**: Розмір масиву аргументів у байтах.
- **Повертає**: `0` у разі успішного запису. У випадку переповнення поточного сторінкового буфера повертає від'ємний код `-EOVERFLOW`, що змушує підсистему `seq_file` автоматично подвоїти розмір буфера і повторити спробу.

### 2.2 Функція `bpf_seq_write`

Здійснює прямий запис сирих бінарних даних у буфер `seq_file` без текстового перетворення ASCII.

```c
long bpf_seq_write(struct seq_file *m, const void *data, __u32 len);
```

- **`m`**: Вказівник на об'єкт `seq_file`.
- **`data`**: Вказівник на буфер у пам'яті ядра з бінарними даними.
- **`len`**: Точна кількість байтів для запису.
- **Повертає**: `0` при успіху або від'ємний код помилки. Ця функція є значно продуктивнішою за `bpf_seq_printf()`, оскільки вона повністю оминає виклики форматування рядків.

## 3. Конфігурація та параметризація BPF Iterators у libbpf

Для обмеження області обходу BPF-ітератора (наприклад, ітерація лише по сокетах конкретного PID або елементах конкретної cgroup) бібліотека `libbpf` використовує об'єднання `union bpf_iter_link_info`.

```c
union bpf_iter_link_info {
    struct {
        __u32 map_fd;        /* Файловий дескриптор мапи для iter/bpf_map_elem */
    } map;
    struct {
        enum bpf_cgroup_iter_order order; /* Порядок обходу: BPF_CGROUP_ITER_ASC / DESC */
        __u32 cgroup_fd;                  /* Файловий дескриптор цільової cgroup */
        __u64 cgroup_id;                  /* Унікальний числовий ID cgroup у ядрі */
    } cgroup;
    struct {
        __u32 pid;                        /* Цільовий PID для iter/task або iter/task_file */
    } task;
};
```

Створення та прикріплення ітератора здійснюється через виклик `bpf_program__attach_iter()` з передачею структури опцій `struct bpf_iter_attach_opts`.

```c
struct bpf_iter_attach_opts {
    size_t sz;                           /* Розмір структури для сумісності ABI */
    union bpf_iter_link_info *link_info; /* Вказівник на масив параметрів обходу */
    __u32 link_info_len;                 /* Кількість елементів у масиві link_info */
};
```

## 4. API BPF User Ring Buffer (`BPF_MAP_TYPE_USER_RINGBUF`)

Мапа `BPF_MAP_TYPE_USER_RINGBUF` реалізує кільцевий буфер типу single-producer (користувацький простір) / single-consumer (BPF-програма в ядрі).

### 4.1 Оголошення мапи у BPF-коді

```c
struct {
    __uint(type, BPF_MAP_TYPE_USER_RINGBUF);
    __uint(max_entries, 1024 * 1024); /* Розмір буфера (кратний PAGE_SIZE) */
} user_ringbuf_map SEC(".maps");
```

Поле `max_entries` задає загальний обсяг кільцевого буфера у байтах. Значення має бути ступенем двійки та кратним розміру сторінки пам'яті процесора (PAGE_SIZE, зазвичай 4096 байтів).

### 4.2 Помічник ядра `bpf_user_ringbuf_drain`

Зчитує всі накопичені записи з кільця `USER_RINGBUF` та передає кожен запис у callback-функцію BPF.

```c
long bpf_user_ringbuf_drain(struct bpf_map *map, 
                            void *callback_fn, 
                            void *callback_ctx, 
                            __u64 flags);
```

- **`map`**: Вказівник на оголошену мапу `BPF_MAP_TYPE_USER_RINGBUF`.
- **`callback_fn`**: Вказівник на BPF-функцію з сигнатурою `int (*cb)(struct bpf_dynptr *dynptr, void *ctx)`.
- **`callback_ctx`**: Довільний вказівник на контекст, що передається у кожний виклик callback.
- **`flags`**: Прапорці сповіщення. `BPF_RB_NO_WAKEUP` забороняє надсилання сповіщення користувачу про вивільнення слотів; `BPF_RB_FORCE_WAKEUP` примусово сповіщає користувача.
- **Повертає**: Кількість успішно оброблених записів або від'ємне значення `errno`.

## 5. Механізм Dynamic Pointers (`bpf_dynptr`)

Для безпечного зчитування записів довільної довжини з кільцевого буфера верифікатор eBPF вимагає використання обгортки `struct bpf_dynptr`.

### 5.1 Читання даних з `bpf_dynptr`

```c
long bpf_dynptr_read(void *dst, __u32 len, const struct bpf_dynptr *ptr, 
                     __u32 offset, __u64 flags);
```

- **`dst`**: Вказівник на локальний буфер у пам'яті BPF-програми (на стеку або в мапі).
- **`len`**: Кількість байтів для копіювання.
- **`ptr`**: Вказівник на `struct bpf_dynptr`, отриманий у callback-функції.
- **`offset`**: Зміщення у байтах від початку запису в `dynptr`.
- **`flags`**: Зарезервовані прапорці (передавати 0).
- **Повертає**: `0` при успішному зчитуванні або `-EINVAL` при виході за межі фактичного розміру запису.

### 5.2 Прямий доступ до пам'яті `bpf_dynptr_data`

```c
void *bpf_dynptr_data(const struct bpf_dynptr *ptr, __u32 offset, __u32 len);
```

Отримує прямий вказівник на область пам'яті у буфері без додаткового копіювання. Повертає `NULL`, якщо верифікатор BPF не може статично перевірити межі доступу на довжину `len`.

## 6. Інтерфейси користувацького простору libbpf (`user_ring_buffer`)

Бібліотека `libbpf` ховає складність атомарних інструкцій та синхронізації пам'яті за зручним C-інтерфейсом.

### 6.1 Створення буфера `user_ring_buffer__new`

```c
struct user_ring_buffer *
user_ring_buffer__new(int map_fd, const struct user_ring_buffer_opts *opts);
```

Ініціалізує користувацьку структуру кільцевого буфера та відображає пам'ять мапи `map_fd` у віртуальний простір за допомогою `mmap()`. Повертає вказівник на об'єкт або `NULL` при помилці.

### 6.2 Резервування слота `user_ring_buffer__reserve`

```c
void *user_ring_buffer__reserve(struct user_ring_buffer *rb, __u32 size);
```

Атомарно резервує `size` байтів у буфері **без виконання системного виклику**. Повертає вказівник на пам'ять або `NULL`, якщо буфер переповнений.

### 6.3 Публікація даних `user_ring_buffer__submit`

```c
void user_ring_buffer__submit(struct user_ring_buffer *rb, void *sample);
```

Фіксує зарезервований слот `sample` та оновлює вказівник `producer_pos` із релізним бар'єром пам'яті (`smp_store_release`), роблячи дані доступними для ядра.

### 6.4 Скасування зарезервованого слота `user_ring_buffer__discard`

```c
void user_ring_buffer__discard(struct user_ring_buffer *rb, void *sample);
```

Скасовує резервування слота `sample` та вивільняє пам'ять назад у кільцевий буфер без публікації запису в ядро.

### 6.5 Звільнення ресурсів `user_ring_buffer__free`

```c
void user_ring_buffer__free(struct user_ring_buffer *rb);
```

Відвідображає сторінки пам'яті (`munmap`) та звільняє внутрішні структури даних `libbpf`.
