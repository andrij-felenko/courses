# 📋 Довідник предикатів find та параметрів xargs

Системний інтерфейс утиліт `find` та `xargs` поєднує мову виразів предикатної логіки для фільтрації метаданих файлової системи з низькорівневим механізмом керування системними викликами `execve`, буферами пам'яті та пулами паралельних процесів. Кожен предикат у виразі `find` виступає функцією зворотного виклику над структурою метаданих `struct stat`, а прапорці `xargs` регулюють розміщення масивів вказівників у віртуальному адресному просторі створюваних процесів.

---

## Глобальні опції утиліти `find` та поведінка VFS

Глобальні опції впливають на базовий алгоритм обходу дерева файлової системи, керуючи розв'язанням шляхів та переходом між точками монтування. Вони мають зазначатися перед списком стартових шляхів або безпосередньо перед першим логічним виразом перевірки.

| Опція | Призначення | Поведінка щодо системних викликів |
|---|---|---|
| `-P` | Фізичний обхід (за замовчуванням) | Символьні посилання не розіменовуються; викликається виключно `lstat()` |
| `-L` | Логічний обхід | Розіменовує всі символьні посилання; для отримання цілі викликається `stat()` |
| `-H` | Гібридний обхід | Розіменовує символьні посилання лише у списку вихідних аргументів командного рядка |
| `-mount`, `-xdev` | Обмеження однією FS | Не переходити в каталоги на інших змонтованих файлових системах (перевірка `st_dev`) |
| `-depth` | Постфіксний обхід (DFS) | Спочатку обробляти вміст каталогу, а потім сам каталог (обов'язково для `-delete`) |
| `-maxdepth N` | Максимальна глибина | Не занурюватися глибше `N` рівнів каталогів відносно стартової точки |
| `-mindepth N` | Мінімальна глибина | Не застосовувати тести та дії на рівнях менше `N` (1 = ігнорувати стартові шляхи) |
| `-ignore_readdir_race` | Ігнорування гонитви | Не повертати помилку, якщо файл зник між викликами `getdents64()` та `stat()` |

Під час використання логічного обходу `-L` утиліта `find` автоматично активує алгоритм виявлення циклів у структурі каталогів. Якщо символьне посилання вказує на батьківський каталог або створює замкнене кільце, `find` відстежує унікальні пари `(st_dev, st_ino)` у внутрішній хеш-таблиці. При повторній зустрічі того самого індексного дескриптора на поточному шляху обхід гілки негайно переривається з виведенням попередження про виявлену циклічність, що захищає процес від нескінченної рекурсії та переповнення стеку.

## Предикати перевірки метаданих індексного вузла

Предикати виконують зіставлення полів структури `struct stat` або імені запису в каталозі з критеріями користувача і повертають булеве значення `true` або `false`.

### 1. Тип вузла файлової системи (`-type`)

Предикат перевіряє значення бітової маски файлового режиму `st_mode` або поле `d_type` у структурі запису каталогу `linux_dirent64`. Якщо файлова система підтримує повернення типу безпосередньо через `getdents64()`, утиліта `find` уникає звернення до `stat()`, суттєво прискорюючи фільтрацію.

| Значення прапорця | Тип об'єкта в POSIX | Макрос перевірки маски `st_mode` |
|---|---|---|
| `-type f` | Звичайний файл (Regular file) | `S_ISREG(st_mode)` |
| `-type d` | Каталог (Directory) | `S_ISDIR(st_mode)` |
| `-type l` | Символьне посилання (Symbolic link) | `S_ISLNK(st_mode)` |
| `-type s` | Сокет домену Unix (UNIX domain socket) | `S_ISSOCK(st_mode)` |
| `-type p` | Іменований канал (FIFO / Named pipe) | `S_ISFIFO(st_mode)` |
| `-type b` | Блоковий пристрій (Block device) | `S_ISBLK(st_mode)` |
| `-type c` | Символьний пристрій (Character device) | `S_ISCHR(st_mode)` |

### 2. Шаблони імен та регулярні вирази

- **`-name "pattern"`** — зіставлення базового імені файлу за стандартними правилами розгортання масок оболонки (`*`, `?`, `[...]`). Пошук виконується виключно над іменем запису, без урахування шляху каталогу.
- **`-iname "pattern"`** — нечутливе до регістру зіставлення базового імені файлу (наприклад, `-iname "*.JPG"` відповідає як `file.jpg`, так і `photo.JPG`).
- **`-path "pattern"`** — перевірка повного відносного шляху до файлу. Символ `/` розглядається як звичайний символ у шаблоні, тому шаблон `*/test/*` успішно фільтрує всі вкладені каталоги з назвою `test`.
- **`-regex "pattern"`** — перевірка всього шляху за регулярним виразом. Тип синтаксису регулярних виразів може бути змінений глобальною опцією `-regextype` (наприклад, `posix-extended`, `posix-egrep`, `emacs`).

### 3. Часові мітки та математика інтервалів

Ядро Linux зберігає три основні часові мітки для кожного файлу: час останнього доступу (`atime`), час модифікації вмісту (`mtime`) та час зміни метаданих або прав доступу (`ctime`). Під час обчислення предикатів `-mtime`, `-atime` та `-ctime` утиліта `find` розраховує вік файлу у 24-годинних інтервалах відносно поточної системної дати:

```
N = ⌊(current_time - file_timestamp) / 86400⌋
```

- **`-mtime N`** — модифікація відбулася в інтервалі від `N*24` до `(N+1)*24` годин тому (дробова частина ділення відкидається).
- **`-mtime -N`** — модифікація відбулася менше ніж `N*24` годин тому (суворо останні `N` діб).
- **`-mtime +N`** — модифікація відбулася більше ніж `(N+1)*24` годин тому (файл старіший за `N` повних діб).
- **`-daystart`** — модифікатор, що змушує вимірювати часові інтервали від початку поточної доби (00:00 сьогодні), а не від точного моменту запуску команди.
- **`-mmin [+/-]N`, `-amin`, `-cmin`** — високоточна фільтрація за часовими інтервалами у хвилинах.
- **`-newer ref_file`** — повертає `true`, якщо час модифікації поточного файлу є новішим за часову мітку референтного файлу `ref_file`.

Варто враховувати поведінку опцій монтування Linux: якщо файлова система змонтована з опцією `relatime` (стандарт для Linux з версії 2.6.30) або `noatime`, ядро оновлює значення `atime` лише тоді, коли попередній час доступу є старішим за `mtime` чи `ctime`, або якщо з моменту останнього оновлення минуло більше 24 годин. Це оптимізує кількість операцій запису на диск, але робить фільтрацію за `-atime` приблизною.

### 4. Розмір файлу (`-size`)

Предикат перевіряє значення поля `st_size` структури метаданих. Якщо одиниця виміру не вказана явно, розмір інтерпретується в 512-байтових блоках.

| Суфікс | Одиниця виміру | Точний розмір у байтах |
|---|---|---|
| `c` | Байт (Characters) | 1 байт |
| `w` | Двобайтове слово (Words) | 2 байти |
| `b` | Блок файлової системи | 512 байтів (значення за замовчуванням) |
| `k` | Кілобайт (Kibibytes) | 1024 байти |
| `M` | Мегабайт (Mebibytes) | 1 048 576 байтів (1024² ) |
| `G` | Гігабайт (Gibibytes) | 1 073 741 824 байти (1024³ ) |

Під час порівняння без знака (наприклад, `-size 10M`) `find` округлює фактичний розмір файлу вгору до найближчої цілої одиниці зазначеного розміру. Таким чином, критерію `-size 10M` відповідають усі файли з розміром від 9 437 185 до 10 485 760 байтів (інтервал `(9M, 10M]`). Знаки `+` та `-` позначають суворе перевищення або менший розмір.

### 5. Права доступу (`-perm`) та біти безпеки

Предикат `-perm` аналізує молодші 12 бітів поля `st_mode`, що містять стандартні права читання, запису та виконання (`rwx`) для власника, групи та інших користувачів, а також спеціальні біти SUID (`04000`), SGID (`02000`) та Sticky bit (`01000`).

- **`-perm 0644`** — точний збіг режиму доступу. Усі біти прав мають точно відповідати вісімковому значенню `0644`. Наявність будь-якого додаткового біта (наприклад, виконання `0755`) дає `false`.
- **`-perm -0644`** — перевірка підмножини бітів. Усі біти маски `0644` обов'язково повинні бути встановлені (`(st_mode & 0644) == 0644`), тоді як стан решти бітів ігнорується (файл з правами `0755` успішно пройде перевірку).
- **`-perm /0644`** (або застарілий запис `+0644`) — перевірка будь-якого біта. Повертає `true`, якщо хоча б один із зазначених у масці бітів встановлено у файлі (`(st_mode & 0644) != 0`).

## Логічні оператори та обчислення за короткою схемою

Усі предикати у виразі утворюють логічне дерево (AST), яке обчислюється зліва направо за правилом короткого замикання (short-circuit evaluation). Це означає, що обчислення виразу припиняється, щойно підсумковий результат стає однозначно визначеним.

1. **`!` або `-not`** — логічне заперечення (найвищий пріоритет). Змінює результат наступного предиката на протилежний.
2. **`-a`, `-and`** (або неявне зіставлення через пробіл) — логічне «І». Якщо лівий операнд повертає `false`, правий предикат взагалі не викликається.
3. **`-o`, `-or`** — логічне «АБО». Якщо лівий операнд повертає `true`, правий предикат ігнорується.
4. **`\( ... \)`** — примусова зміна пріоритету операторів за допомогою дужок. Дужки обов'язково екрануються зворотним слешем `\(` або беруться в лапки, щоб запобігти їх інтерпретації оболонкою як підкоманд (subshells).

## Предикати-дії (Actions)

Дії — це специфічні предикати, які виконують побічні ефекти (вивід на екран, видалення, запуск зовнішнього процесу).

| Дія | Опис поведінки | Код повернення |
|---|---|---|
| `-print` | Виводить шлях до файлу у стандартний вивід, завершуючи символом `\n` | Завжди `true` |
| `-print0` | Виводить повний шлях, завершуючи його байтом `\0` (ASCII NUL) | Завжди `true` |
| `-delete` | Видаляє поточний файл або порожній каталог через `unlinkat()` | `true` при успіху, `false` при помилці |
| `-ls` | Виводить детальні метадані об'єкта у форматі команди `ls -dils` | Завжди `true` |
| `-exec cmd {} \;` | Викликає `cmd` окремо для кожного файлу; замінює `{}` на поточний шлях | `true`, якщо процес завершився з кодом 0 |
| `-exec cmd {} +` | Пакетує знайдені шляхи в максимально довгий список аргументів для `cmd` | Завжди `true` |
| `-execdir cmd {} \;` | Переходить у каталог знайденого файлу і виконує команду відносно `./file` | `true`, якщо процес завершився з кодом 0 |

Дія `-execdir` є безпечною альтернативою `-exec`. Вона захищає систему від атак класу Time-of-Check to Time-of-Use (TOCTOU), переходячи безпосередньо у цільовий каталог за допомогою дескриптора каталогу перед викликом команди, що унеможливлює підміну компонентів шляху під час роботи зовнішнього процесу.

## Параметри утиліти `xargs`

Утиліта `xargs` зчитує елементи зі стандартного входу, формує масив вказівників `argv[]` та виконує системний виклик `execve()`.

| Параметр | Повна назва | Призначення та вплив на пам'ять |
|---|---|---|
| `-0` | `--null` | Використовувати байт `\0` як розділювач; вимикає обробку лапок, слешів та пробілів |
| `-d delim` | `--delimiter=delim` | Встановити довільний одинарний символ як розділювач вхідного потоку |
| `-n N` | `--max-args=N` | Передавати не більше `N` аргументів у кожен окремий запуск програми |
| `-s N` | `--max-chars=N` | Обмежити сумарний розмір рядка аргументів та оточення `N` байтами |
| `-L N` | `--max-lines=N` | Зчитувати не більше `N` непорожніх рядків для формування одного виклику |
| `-I str` | `--replace=str` | Підставляти аргумент замість маркера `str` у довільне місце команди (вмикає `-n 1`) |
| `-P N` | `--max-procs=N` | Запускати до `N` паралельних процесів (`-P 0` — необмежений пул воркерів) |
| `-r` | `--no-run-if-empty` | Не викликати цільову команду, якщо стандартний вхід не містить жодного елемента |
| `-p` | `--interactive` | Запитувати інтерактивне підтвердження користувача перед кожним запуском |
| `-t` | `--verbose` | Друкувати сформований командний рядок у `stderr` перед системним викликом |
| `-a file` | `--arg-file=file` | Зчитувати аргументи із зазначеного файлу замість стандартного входу |

## Коди виходу (Exit Codes) `xargs`

Стандарт POSIX та реалізація GNU `xargs` визначають точну семантику статусів завершення утиліти для контролю результатів виконання в скриптах автоматизації.

| Код виходу | Значення за стандартом POSIX | Технічна першопричина |
|---|---|---|
| `0` | Успіх (Success) | Усі запущені дочірні процеси успішно завершилися з кодом 0 |
| `1–125` | Помилка програми | Хоча б один запущений процес повернув ненульовий код помилки |
| `123` | Часткова помилка | Один або кілька запусків повернули код від 1 до 125 у режимі пулу процесів |
| `124` | Перевищення часу | Виконання команди було примусово перервано через таймаут |
| `125` | Внутрішній збій `xargs` | Помилка виділення динамічної пам'яті або некоректні параметри виклику |
| `126` | Неможливо виконати | Програму знайдено у файловій системі, але відсутні права на запуск (`EACCES`) |
| `127` | Команду не знайдено | Цільовий виконуваний файл не знайдено у каталогах змінної `PATH` (`ENOENT`) |
| `255` | Фатальна зупинка | Дочірній процес завершився зі статусом 255 або був аварійно вбитий сигналом |
