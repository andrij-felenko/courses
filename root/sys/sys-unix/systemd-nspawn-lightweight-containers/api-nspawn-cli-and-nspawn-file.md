# 📋 Інтерфейс та конфігурація systemd-nspawn: параметри CLI, файли .nspawn та D-Bus

Інструмент `systemd-nspawn` надає розробникам та системним адміністраторам три рівні управління контейнерним середовищем: інтерактивний інтерфейс командного рядка (CLI) для оперативного запуску, декларативні файли конфігурації `.nspawn` для постійного визначення параметрів контейнера, та низькорівневий програмний інтерфейс D-Bus через службовий демон `systemd-machined`.

---

### 1. Детальний розбір параметрів командного рядка systemd-nspawn

Команди утиліти `systemd-nspawn` вимагають привілеїв суперкористувача (`root`) для створення ядерних просторів імен, мапування пристроїв та налаштування мережевих стеків. Ключові прапорці командного рядка групуються за п'ятьма Основними функціональними напрямками.

#### Визначення кореня файлової системи та режимів запуску
- `-D, --directory=PATH`: Вказує абсолютний або відносний шлях до директорії на хості, який виконуватиме роль кореневої файлової системи (`rootfs`) контейнера. Утиліта виконує перевірку наявності базових директорій `/usr`, `/etc` та `/proc`.
- `-i, --image=PATH`: Шлях до файлу дискового образу у форматі RAW або qcow2, який містить таблицю розділів GPT або MBR. При використанні цього прапорця `systemd-nspawn` автоматично підключає образ через loop-пристрій ядра, аналізує специфікацію Discoverable Partitions Specification (DPS) та монтує кореневий та системні розділи.
- `-x, --ephemeral`: Активує режим одноразового знімка файлової системи. Інструмент створює тимчасову шар-надбудову OverlayFS (або btrfs subvolume, якщо корінь розташований на btrfs). Усі зміни, згенеровані усередині контейнера під час його роботи, повністю скидаються після завершення процесів.
- `-b, --boot`: Переключає режим роботи з виконання окремої команди на повноцінний запуск системного менеджера ініціалізації. Утиліта шукає двійковий файл `/usr/lib/systemd/systemd` або `/sbin/init` усередині `rootfs` і передає йому управління як PID 1 ізольованого контейнера.

#### Монтування точок та оверлейних шарів
- `--bind=HOSTPATH[:CONTAINERPATH[:OPTIONS]]`: Виконує мотування директорії з хостової системи усередину контейнера у режимі читання та запису. Опції дозволяють вказувати рекурсивне мотування або ID-mapped прив'язку прав.
- `--bind-ro=HOSTPATH[:CONTAINERPATH]`: Виконує безпечне мотування хостової директорії у режимі тільки для читання (`read-only`), захищаючи файли хоста від модифікації усередині контейнера.
- `--overlay=HOSTPATH1:HOSTPATH2:...:CONTAINERPATH`: Компонує декілька нижніх директорій хоста у єдине об'єднане оверлейне мотування усередині контейнера за допомогою драйвера OverlayFS ядра Linux.

#### Мережева конфігурація та ізоляція трафіку
- `--private-network`: Створює ізольований мережевий простір імен (`CLONE_NEWNET`). Усередині контейнера за замовчуванням залишається доступним лише петльовий інтерфейс `lo`, а всі сокети та поррти хоста стають повністю недоступними.
- `-n, --network-veth`: Автоматично створює пару віртуальних Ethernet-інтерфейсів (`veth`). На хості створюється мережевий інтерфейс з префіксом `ve-<name>`, а всередині контейнера з'являється інтерфейс `host0`.
- `--network-bridge=BRIDGE`: Підключає хостову частину віртуальної пари `ve-<name>` до вказаного мережевого мосту (наприклад, `br0`), інтегруючи контейнер у фізичну або віртуальну L2-мережу.
- `--port=[PROTOCOL:]HOSTPORT[:CONTAINERPORT]`: Налаштовує перенаправлення мережевих портів між хостовою системою та контейнером (вимагає активації `--private-network` або `--network-veth`).

#### Безпека, User Namespace та привілеї
- `-U, --private-users=pick|auto|UID:COUNT`: Вмикає простір імен користувачів (`CLONE_NEWUSER`). Значення `pick` змушує `systemd-machined` автоматично виділити вільний діапазон із 65536 ідентифікаторів UID/GID у базі хоста (починаючи з UID 524288).
- `--private-users-chown`: Автоматично змінює власників файлів та директорій усередині `rootfs` на виділений діапазон UID/GID під час першого запуску контейнера.
- `--capability=CAP1,CAP2`: Додає вказані ядерні можливості (capabilities) до Bounding Set контейнера.
- `--drop-capability=CAP1,CAP2`: Вилучає вказані привілеї з Bounding Set контейнера, забороняючи їх використання навіть суперкористувачем root.

### 2. Декларативна конфігурація у файлах .nspawn

Для відмови від довгих командних рядків інструмент підтримує конфігураційні файли з розширенням `.nspawn`. Вони розміщуються у директорії `/etc/systemd/nspawn/<name>.nspawn` або поруч із директорією файлової системи контейнера.

```ini
[Exec]
Boot=yes
ProcessTwo=no
Environment=NODE_ENV=production DB_HOST=127.0.0.1
User=root
Capability=CAP_NET_BIND_SERVICE CAP_NET_ADMIN
DropCapability=CAP_SYS_RAWIO CAP_SYS_MODULE
LimitCPU=4
LimitMEMORY=2G

[Files]
PrivateUsers=pick
Bind=/var/log/app-container:/var/log/app
BindReadOnly=/etc/ssl/certs:/etc/ssl/certs:idmap
TemporaryFileSystem=/tmp:size=512M

[Network]
Private=yes
VirtualEthernet=yes
Bridge=br0
Port=tcp:8080:80
Port=tcp:8443:443
```

#### Детальний опис секцій конфігурації:
- **`[Exec]`**: Визначає правила виконання PID 1, передачу змінних оточення у контейнер, обмеження ресурсів cgroups v2 (`LimitCPU`, `LimitMEMORY`) та керування привілеями ядра.
- **`[Files]`**: Задає конфігурацію файлових монтувань, використання оверлейних шарів, активацію унікальних діапазонів UID/GID у User namespace та створення тимчасових дисків у RAM (`tmpfs`).
- **`[Network]`**: Регулює мережеву топологію контейнера, підключення до хостових мостів та правила маршрутизації портів.

### 3. Програмний D-Bus інтерфейс служби systemd-machined

Центральний демон реєстрації контейнерів та віртуальних машин `systemd-machined` публікує шинний інтерфейс `org.freedesktop.machine1` у системній шині D-Bus хоста за адресою об'єкта `/org/freedesktop/machine1`.

#### Основні методи системної шини (D-Bus Methods)

| Метод D-Bus | Вхідний тип | Опис функціонального контракту |
| :--- | :--- | :--- |
| `CreateMachine` | `(s s s s u s)` | Створює та реєструє новий контейнерний контекст у підсистемі cgroups `machine.slice`. |
| `GetMachine` | `(s)` | Повертає унікальний об'єктний шлях D-Bus для зареєстрованого контейнера за його іменем. |
| `TerminateMachine` | `(s)` | Надсилає сигнал примусового завершення процесів (`SIGTERM`/`SIGKILL`) усім об'єктам контейнера. |
| `OpenMachinePTY` | `(s)` | Відкриває та повертає файловий дескриптор pseudo-terminal (PTY) для інтерактивного керування. |
| `BindMountMachine` | `(s s s b b)` | Здійснює мотування директорії з хостової системи у файловий простір працюючого контейнера на льоту. |

#### Основні сигнали подій D-Bus (D-Bus Signals)
- `MachineNew(s name, o path)`: Випромінюється службою під час успішного запуску та реєстрації нового контейнера.
- `MachineRemoved(s name, o path)`: Випромінюється під час зупинення контейнера та вилучення його cgroup scope з системного дерева ресурсів.
