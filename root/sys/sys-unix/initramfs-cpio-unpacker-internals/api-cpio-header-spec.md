# 📋 Специфікація заголовка cpio newc та вирівнювання кадрів

Цей довідник надає повну специфікацію двобічного двійкового формату кадрів `newc` (відомого як SVR4 Portable Format без перевірки CRC), який ядро Linux використовує як основний потоковий контейнер для початкової файлової системи `initramfs`. Специфікація розкриває бітову структуру заголовка, текстове ASCII-кодування полів, маски режимів файлів, математичні правила вирівнювання за межами 4 байтів та алгоритми обробки специфічних типів VFS-вузлів.

Основною метою розробників специфікації `newc` було усунення залежності від порядку байтів (англ. *endianness*) процесорної архітектури. Усі числові значення всередині заголовка представлені у вигляді 8-значних шістнадцяткових ASCII-рядків. Це дозволяє ядерному розпаковувачу розбирати архів однаководієво на архітектурах Big-Endian (s390x, SPARC) та Little-Endian (x86_64, ARM64, RISC-V) без застосування апаратно-залежних макросів byte-swap (`ntohl` або `bswap32`).

### Двійкова форма та представлення в мовах програмування

Фіксована частина заголовка кожного кадру має розмір точно **110 байтів**. Вона передує текстовому шляху файлу та його бінарному навантаженню.

:::tabs
```c
/* cpio_newc_header.h — Специфікація заголовка мовою C */
#include <stdint.h>

struct cpio_newc_header {
    char c_magic[6];     /* Магічний маркер: "070701" (без CRC) або "070702" (з CRC) */
    char c_ino[8];       /* Номер іноди джерела у hex ASCII */
    char c_mode[8];      /* Тип файлу та права доступу у hex ASCII */
    char c_uid[8];       /* Ідентифікатор користувача-власника (UID) у hex ASCII */
    char c_gid[8];       /* Ідентифікатор групи-власника (GID) у hex ASCII */
    char c_nlink[8];     /* Кількість посилань на іноду у hex ASCII */
    char c_mtime[8];     /* Штамп часу модифікації POSIX timestamp у hex ASCII */
    char c_filesize[8];  /* Розмір бінарних даних файлу в байтах у hex ASCII */
    char c_maj[8];       /* Major номер пристрою носія іноди у hex ASCII */
    char c_min[8];       /* Minor номер пристрою носія іноди у hex ASCII */
    char c_rmaj[8];      /* Major номер спеціального пристрою у hex ASCII */
    char c_rmin[8];      /* Minor номер спеціального пристрою у hex ASCII */
    char c_namesize[8];  /* Довжина шляху файлу з урахуванням NUL-байта у hex ASCII */
    char c_chksum[8];    /* Контрольна сума ("00000000" для 070701) у hex ASCII */
};
```
```cpp
// cpio_newc_header.hpp — Ідіоматична специфікація заголовка мовою C++20
#include <array>
#include <cstdint>
#include <string_view>

namespace cpio {

struct alignas(1) Header {
    std::array<char, 6>  magic;     // "070701" або "070702"
    std::array<char, 8>  ino;       // Hex ASCII номер іноди
    std::array<char, 8>  mode;      // Hex ASCII тип і права доступу
    std::array<char, 8>  uid;       // Hex ASCII User ID
    std::array<char, 8>  gid;       // Hex ASCII Group ID
    std::array<char, 8>  nlink;     // Hex ASCII лічильник посилань
    std::array<char, 8>  mtime;     // Hex ASCII час модифікації
    std::array<char, 8>  filesize;  // Hex ASCII розмір даних у байтах
    std::array<char, 8>  maj;       // Hex ASCII Major dev іноди
    std::array<char, 8>  min;       // Hex ASCII Minor dev іноди
    std::array<char, 8>  rmaj;      // Hex ASCII Major dev пристрою
    std::array<char, 8>  rmin;      // Hex ASCII Minor dev пристрою
    std::array<char, 8>  namesize;  // Hex ASCII довжина шляху з '\0'
    std::array<char, 8>  chksum;    // Hex ASCII CRC32 або 0
};

static_assert(sizeof(Header) == 110, "Заголовок CPIO newc мусить бути точно 110 байтів");

} // namespace cpio
```

### Детальний аналіз полів заголовка

Кожне поле структури займає строго фіксовану позицію та довжину. Значення розкодовуються шляхом інтерпретації 8 шістнадцяткових символів як 32-бітного беззнакового цілого числа (`uint32_t`).

1. **`c_magic` (зсув 0, 6 байтів):**
   Приймає одне з двох фіксованих значень: `"070701"` для стандартного `newc` без контрольної суми або `"070702"` для версії `crc`. Якщо перші 6 байтів не збігаються з цими значеннями, парсер ядра зупиняє обробку з помилкою формату.

2. **`c_ino` (зсув 6, 8 байтів):**
   Номер іноди вихідної файлової системи. Це поле є критичним для відновлення жорстких посилань (англ. *hard links*). Коли декілька файлів в архіві мають однаковий номер `c_ino` та лічильник `c_nlink > 1`, перший файл розпаковується повністю, а для наступних файлів з тим самим `c_ino` (у яких `c_filesize == 0`) ядро створює жорстке посилання через виклик `sys_link()`.

3. **`c_mode` (зсув 14, 8 байтів):**
   Об'єднує тип файлу VFS та біти прав доступу (POSIX `st_mode`). Старші біти визначають тип об'єкта, а молодші 12 бітів — права доступу `read`, `write`, `execute` для власника, групи та інших користувачів, а також спеціальні біти `SUID` (`04000`), `SGID` (`02000`) та `Sticky Bit` (`01000`).

4. **`c_uid` та `c_gid` (зсуви 22 та 30, по 8 байтів):**
   Числові ідентифікатори користувача та групи власника файлу. Під час розпакування в `rootfs` ядро призначає вказані UID/GID створеному об'єкту VFS.

5. **`c_nlink` (зсув 38, 8 байтів):**
   Кількість жорстких посилань, які вказують на цю іноду. Для звичайних поодиноких файлів це значення дорівнює `1`.

6. **`c_mtime` (зсув 46, 8 байтів):**
   Час останньої модифікації файлу в секундах від початку епохи POSIX (1 січня 1970 року, 00:00:00 UTC).

7. **`c_filesize` (зсув 54, 8 байтів):**
   Довжина файлового навантаження у байтах, яка слідує після вирівняного імені файлу. Для каталогів, пристроїв, FIFO-каналів та повторних жорстких посилань це поле дорівнює `0`. Для символьних посилань `c_filesize` містить довжину рядка шляху цілі, на яку вказує посилання.

8. **`c_maj` та `c_min` (зсуви 62 та 70, по 8 байтів):**
   Старший та молодший номери пристрою файлової системи, на якій існував файл під час створення архіву.

9. **`c_rmaj` та `c_rmin` (зсуви 78 та 86, по 8 байтів):**
   Старший (Major) та молодший (Minor) номери пристрою для спеціальних файлів символьних (`S_IFCHR`) та блокових (`S_IFBLK`) пристроїв. Для звичайних файлів та каталогів ці поля містять `0`. Під час розпакування ядро передає ці номери у внутрішній виклик `sys_mknod()` для автоматичного формування вузлів пристроїв у `/dev`.

10. **`c_namesize` (зсув 94, 8 байтів):**
    Точна довжина текстового шляху файлу в байтах, включаючи завершальний нульовий символ (`\0`). Наприклад, для шляху `init` значення `c_namesize` дорівнює `5` (`"init\0"`).

11. **`c_chksum` (зсув 102, 8 байтів):**
    Контрольна сума вмісту. Для формату `"070701"` це поле ігнорується й записується як `"00000000"`. Для формату `"070702"` містить 32-бітну суму всіх байтів файлового навантаження.

### Бітові маски полів c_mode (POSIX file types)

Тип файлу розкодовується шляхом застосування вісімкової маски `c_mode & 0170000`:

| Вісімкова маска | Символьний константа | Тип вузла VFS | Поведінка ядерного розпаковувача |
|---|---|---|---|
| `0100000` | `S_IFREG` | Regular File | Створює новий файл через `sys_open()`, записує `c_filesize` байтів у сторінковий кеш. |
| `0040000` | `S_IFDIR` | Directory | Створює каталог через `sys_mkdir()`. Поле `c_filesize` дорівнює `0`. |
| `0120000` | `S_IFLNK` | Symbolic Link | Створює символьне посилання `sys_symlink()`. Ціль зчитується з секції даних. |
| `0020000` | `S_IFCHR` | Character Device | Створює вузол символьного пристрою `sys_mknod()` з номерами `c_rmaj`/`c_rmin`. |
| `0060000` | `S_IFBLK` | Block Device | Створює вузол блокового пристрою `sys_mknod()` з номерами `c_rmaj`/`c_rmin`. |
| `0010000` | `S_IFIFO` | FIFO Pipe | Створює іменований канал через `sys_mknod()`. |
| `0140000` | `S_IFSOCK` | UNIX Socket | Створює локальний сокет у файловій системі. |

### Правила вирівнювання кадрів (4-Byte Alignment Math)

Формат `newc` вимагає, щоб кожен елемент архіву — заголовок, ім'я файлу та файлові дані — починався за адресою у пам'яті, кратною 4 байтам (`offset % 4 == 0`).

1. **Вирівнювання імені файлу:**
   Шлях файлу розміщується одразу після 110-байтового заголовка. Оскільки число 110 ділиться на 4 із остачею 2 (`110 % 4 == 2`), після імені додається така кількість нульових байтів:
   ```
   pad_name = (4 - ((110 + namesize) % 4)) % 4
   ```
   Або у побітовій арифметиці для систем з 2-комплементом:
   ```
   padded_namesize = (110 + namesize + 3) & ~3 - 110
   ```

2. **Вирівнювання бінарних даних:**
   Секція бінарних даних файлу починається одразу після вирівняного імені. Після закінчення даних файлу довжиною `filesize` також додається падінг:
   ```
   pad_data = (4 - (filesize % 4)) % 4
   ```

Зсув початку наступного заголовка `cpio_newc_header` обчислюється як:
```
next_header_offset = current_offset + 110 + namesize + pad_name + filesize + pad_data
```

### Маркер кінця архіву (TRAILER!!!)

Парсер ядра вважає поточний потік `cpio` завершеним, коли зустрічає заголовок кадру зі спеціальним ім'ям:
- `c_namesize` дорівнює `11` (`"0000000B"` у hex ASCII), що відповідає рядку `"TRAILER!!!"` з NUL-байтом.
- `c_filesize` дорівнює `0` (`"00000000"`).

Після виявлення markers `"TRAILER!!!"` ядро припиняє розпакування поточного архіву. Якщо в загальному буфері пам'яті, переданому завантажувачем, залишаються дані, ядро вирівнює поточний зсув до найближчої межі 512 байтів і перевіряє наявність наступного склеєного архіву `cpio` або сигнатури декомпресора (`gzip`, `zstd`, `xz`).
