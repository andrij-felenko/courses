# Повна специфікація прапорців stty, полів termios та керуючих кодів VT100

Діагностика, низькорівнева конфігурація та програмне відновлення термінального середовища в операційних системах сімейства Unix вимагають точного знання двійкового контракту (ABI) між простором користувача та ядром. Цей довідник надає повний інженерний опис архітектури підсистеми TTY ядра Linux, внутрішнього влаштування лінійної дисципліни `N_TTY`, кільцевих буферів та flip-буферів, побітової відповідності між параметрами утиліти `stty` та масками структури `struct termios` / `struct termios2`, алгоритмів неканонічного читання (`VMIN`/`VTIME`), протоколу асинхронно-сигнальної безпеки (`SIGINT`, `SIGTSTP`, `SIGCONT`, `SIGWINCH`), специфікації керуючих escape-послідовностей стандарту DEC VT100 / ANSI X3.64, сучасних розширень емуляторів (TrueColor, SGR-1006, Bracketed Paste, Mode 2026, Sixel, Kitty Graphics, iTerm2), а також методів низькорівневого аудиту через `strace`, `/proc` та `gdb`.

## Архітектура підсистеми TTY ядра Linux та потік даних

Термінальна підсистема ядра Linux є модульним конвеєром обробки потоків байтів між процесами простору користувача та апаратними інтерфейсами або псевдотерміналами. Вона побудована на трирівневій моделі абстракції:

1. **Рівень VFS та TTY Core (`drivers/tty/tty_io.c`):** Надає стандартні файлові операції (`open`, `read`, `write`, `ioctl`, `poll`) для символьних пристроїв `/dev/tty`, `/dev/ttyN` (віртуальні консолі) та `/dev/pts/N` (псевдотермінали). Керує структурами `struct tty_struct`, обліком сесій, контрольними терміналами процесів та блокуваннями.
2. **Рівень лінійної дисципліни (Line Discipline, `drivers/tty/n_tty.c`):** Реалізує протокольну обробку потоку байтів. Стандартна дисципліна `N_TTY` (номер 0, структура `struct tty_ldisc`) виконує канонічну буферизацію рядків, локальне відлуння (`ECHO`), генерацію асинхронних сигналів (`ISIG`), нормалізацію переведення рядків (`ICRNL`, `ONLCR`) та програмне керування потоком (XON/XOFF).
3. **Рівень апаратних та віртуальних драйверів:** 
   - `drivers/tty/serial/serial_core.c` — фізичні UART/RS-232/RS-485 інтерфейси.
   - `drivers/tty/vt/vt.c` — драйвер віртуальних текстових консолей Linux (VGA / Framebuffer).
   - `drivers/tty/pty.c` — драйвер псевдотерміналів (PTY), що зв'язує графічні емулятори терміналів (`xterm`, `alacritty`, `kitty`, `tmux`) через пару Master/Slave.


### Кільцеві буфери n_tty_data та захист від переповнення (Watermarks)

Внутрішній стан дисципліни `N_TTY` інкапсульовано у структурі `struct n_tty_data`:

- **Кільцевий буфер вводу `read_buf`:** Має фіксований розмір `N_TTY_BUF_SIZE` (4096 байтів). Вказівники `read_head` (куди записує драйвер) та `read_tail` (звідки читає процес) рухаються за модулем 4096. Якщо активний канонічний режим (`ICANON`), показчик `line_start` фіксує початок поточного незавершеного рядка.
- **Буфер відлуння `echo_buf`:** Кільцевий буфер розміром 4096 байтів, що зберігає байти, призначені для повернення у вихідний потік термінала. Керується індексами `echo_head`, `echo_tail` та `echo_commit`.
- **Порогові рівні контролю потоку (Watermarks):**
  - **High Watermark (`TTY_THRESHOLD_THROTTLE`):** Коли кількість вільних байтів у `read_buf` падає нижче критичного порогу (зазвичай 128 або 256 байтів), лінійна дисципліна викликає `tty_throttle()`. Якщо увімкнено `IXOFF`, драйвер генерує у зворотний бік байт `VSTOP` (`Ctrl+S`); якщо увімкнено `CRTSCTS`, опускається апаратна лінія RTS; якщо увімкнено `IMAXBEL`, надсилається звуковий сигнал `\a` (`0x07`).
  - **Low Watermark (`TTY_THRESHOLD_UNTHROTTLE`):** Коли процес простору користувача вичитує байти через `read()` і вільне місце в `read_buf` перевищує поріг відновлення, ядро викликає `tty_unthrottle()`, надсилаючи байт `VSTART` (`Ctrl+Q`) або піднімаючи сигнал RTS.

### Подвійна буферизація: Flip-буфери ядра (tty_buffer)

Для запобігання втраті вхідних байтів під час обробки апаратних переривань UART або високонавантаженого виводу емулятора, ядро Linux використовує механізм подвійної буферизації — **Flip-буфери** (`struct tty_buffer` у `drivers/tty/tty_buffer.c`):

1. Обробник переривання (ISR) апаратного порту або виклик `pty_write()` записує байти безпосередньо у поточний активний `tty_buffer` за допомогою функцій `tty_insert_flip_char()` або `tty_insert_flip_string()`. Ця операція є неблокуючою і виконується в атомарному контексті.
2. Після додавання даних викликається `tty_flip_buffer_push()`, яка ставить у системну чергу ядра завдання відкладеної обробки (workqueue `flush_to_ldisc`).
3. Ядровий потік у контексті процесу забирає накопичений flip-буфер і передає його у лінійну дисципліну викликом `n_tty_receive_buf2()`, де виконується побайтова фільтрація `c_iflag` та розбір керуючих сигналів `c_lflag`.

### Взаємодія з емуляторами терміналів (PTY) та віртуальними консолями (VT)

- **Псевдотермінали (PTY):** Складаються з пари пристроїв: Master (`/dev/ptmx`, дескриптор належить графічному емулятору або SSH-демону) та Slave (`/dev/pts/N`, відкривається оболонкою `bash`). Коли емулятор записує байти клавіатури у Master, функція `pty_write()` перенаправляє їх у flip-буфер Slave-пристрою. Коли програма виконує `write()` у Slave, дисципліна `N_TTY` обробляє вихідні прапорці `c_oflag` і записує результат у буфер Master, звідки емулятор вичитує дані через `read()` для рендерингу гліфів.
- **Віртуальна консоль ядра (`vt.c`):** Текстовий термінал ядра Linux перехоплює скан-коди клавіатури через підсистему `input`, конвертує їх у символи відповідно до таблиць `loadkeys`, пропускає через `N_TTY` і відправляє вихідний потік у внутрішній драйвер консолі `con_write()`, який безпосередньо змінює відеопам'ять VGA або фреймбуфера DRM/KMS.

### Пакетний режим псевдотерміналів (PTY Packet Mode: TIOCPKT) та керуючі події

При взаємодії двох процесів простору користувача через псевдотермінал (наприклад, графічного емулятора або SSH-демона з командною оболонкою) звичайний потік байтів через дескриптор Master не передає позасмугові (out-of-band) зміни стану лінії. Якщо програма на боці Slave скидає вхідні чи вихідні черги викликом `tcflush()`, призупиняє вивід комбінацією `Ctrl+S` (`c_cc[VSTOP]`) або змінює параметри `termios`, ведучий процес (Master) не має стандартного способу дізнатися про це, продовжуючи передавати застарілі мережеві пакети.

Для вирішення цієї проблеми операційні системи Unix надають **пакетний режим псевдотермінала (PTY Packet Mode)**:

1. **Активація пакетного режиму:**
   Пакетний режим активується виключно на дескрипторі ведучого пристрою (`master_fd`, відкритий через `/dev/ptmx`) за допомогою системного виклику `ioctl`:
   ```c
   int mode = 1;
   if (ioctl(master_fd, TIOCPKT, &mode) < 0) {
       perror("ioctl(TIOCPKT)");
   }
   ```
   Передача значення `mode = 0` вимикає пакетний режим, повертаючи дескриптор до прозорої трансляції сирого потоку даних.

2. **Протокол кадрування пакетів при виклику `read()`:**
   Після активації `TIOCPKT` кожен системний виклик `read(master_fd, buf, count)` повертає сформований пакет, у якому **найперший байт (`buf[0]`) завжди є байтом стану (Packet Control Byte)**:
   - **Пакет даних (`buf[0] == TIOCPKT_DATA` / `0x00`):** Якщо перший байт дорівнює нулю, решта прочитаних байтів від індексу `1` до `bytes_read - 1` є дійсним корисним навантаженням (вихідними даними процесу Slave).
   - **Пакет керівної події (`buf[0] != 0`):** Якщо перший байт містить ненульову бітову маску, системний виклик `read()` повертає рівно **один байт** (`bytes_read == 1`). Цей байт кодує асинхронні події, що відбулися в лінійній дисципліні веденого пристрою.

3. **Специфікація бітових масок керуючих подій TIOCPKT:**

| Константа ядра | Значення (Hex) | Бітова маска | Системна подія веденого термінала (Slave) | Необхідна дія ведучого процесу (Master / SSH) |
|---|---|---|---|---|
| `TIOCPKT_DATA` | `0x00` | `0` | Звичайний пакет корисних даних. | Обробити та відобразити байти `buf[1 .. bytes_read-1]`. |
| `TIOCPKT_FLUSHREAD` | `0x01` | `1 << 0` | Вхідну чергу веденого термінала (`read_buf`) очищено через `tcflush(fd, TCIFLUSH)` або `TCIOFLUSH`. | Негайно відкинути всі накопичені вхідні байти в мережевому сокеті/буфері передачі до клієнта. |
| `TIOCPKT_FLUSHWRITE` | `0x02` | `1 << 1` | Вихідну чергу веденого термінала очищено через `tcflush(fd, TCOFLUSH)` або `TCIOFLUSH`. | Очистити локальні буфери рендерингу та черги очікування виводу. |
| `TIOCPKT_STOP` | `0x04` | `1 << 2` | Вивід термінала зупинено (отримано `VSTOP` / `Ctrl+S` або виклик `tcflow(fd, TCOOFF)`). | Призупинити читання нових даних із процесу або передачу виводу на монітор. |
| `TIOCPKT_START` | `0x08` | `1 << 3` | Вивід термінала поновлено (отримано `VSTART` / `Ctrl+Q` або виклик `tcflow(fd, TCOON)`). | Відновити надсилання вихідних даних. |
| `TIOCPKT_NOSTOP` | `0x10` | `1 << 4` | Символи керування потоком `VSTART`/`VSTOP` відрізняються від стандартних `^Q`/`^S`, або `IXON` вимкнено. | Перемкнути режим контролю потоку на віддаленому клієнті. |
| `TIOCPKT_DOSTOP` | `0x20` | `1 << 5` | Символи `VSTART`/`VSTOP` відновлено до стандартних `^Q`/`^S`, а прапорець `IXON` увімкнено. | Відновити стандартний режим програмного керування потоком XON/XOFF. |
| `TIOCPKT_IOCTL` | `0x40` | `1 << 6` | Розширення ядра Linux (за активного `TIOCPKT_IOCTL`): стан `struct termios` на стороні Slave було змінено. | Перечитати параметри `termios` веденого пристрою для синхронізації емулятора. |

4. **Інженерна схема обробки кадру в Master-циклі:**
   ```c
   char packet_buf[4096];
   ssize_t n = read(master_fd, packet_buf, sizeof(packet_buf));
   if (n > 0) {
       unsigned char control_byte = (unsigned char)packet_buf[0];
       if (control_byte == TIOCPKT_DATA) {
           /* Обробка корисних даних виводу: n - 1 байтів */
           handle_terminal_output(packet_buf + 1, n - 1);
       } else {
           /* Обробка керуючих прапорців лінії */
           if (control_byte & TIOCPKT_FLUSHREAD) {
               flush_network_rx_buffer();
           }
           if (control_byte & TIOCPKT_FLUSHWRITE) {
               flush_network_tx_buffer();
           }
           if (control_byte & TIOCPKT_STOP) {
               pause_data_transmission();
           }
           if (control_byte & TIOCPKT_START) {
               resume_data_transmission();
           }
       }
   }
   ```

### Буферизація та динаміка черг PTY при високошвидкісних потоках

Коли консольна програма генерує безперервний масивний потік текстового виводу (наприклад, утиліта `yes`, компіляція великого проєкту, читання дампу бази даних або `cat /dev/urandom`), продуктивність конвеєра PTY лімітується розміром буферів ядра та швидкістю їх вичитування емулятором.

1. **Ємність буферів підсистеми PTY в ядрі Linux:**
   - Буферизація між Master та Slave здійснюється через ядрові flip-буфери `struct tty_buffer`. Драйвер `drivers/tty/pty.c` виділяє пам'ять сторінковими блоками `PAGE_SIZE` (4096 байтів).
   - Сумарний ліміт черги накопичення за замовчуванням становить `TTY_BUFFER_PAGE_LIMIT` (зазвичай 64 КБ на чергу).
   - Коли цей ліміт вичерпується, функція `tty_insert_flip_string()` перестає приймати нові байти, і виклик `write()` у дескриптор Slave блокується на рівні ядра (або повертає помилку `EAGAIN`, якщо дескриптор переведено в режим `O_NONBLOCK`).

2. **Захист від дедлоків (PTY Deadlock Condition):**
   - *Сценарій виникнення блокування:* Програма простору користувача виконує одночасне читання та запис у псевдотермінал в одному синхронному потоці. Якщо вихідний буфер PTY заповнюється до ліміту 64 КБ, черговий виклик `write()` блокує потік. Якщо в цей самий момент ведучий процес (Master) чекає від веденого процесу підтвердження або відповіді на ввід, виникає нерозв'язний дедлок: ведений процес заблокований у `write()`, а ведучий — у `read()`.
   - *Інженерне рішення:* Завжди використовувати асинхронне мультиплексування (`epoll` / `kqueue` / `poll`) з прапорцем `O_NONBLOCK` або розділяти читання та запис між незалежними системними потоками виконання.

3. **Моніторинг заповненості черг через ioctl:**
   - Кількість байтів, доступних для читання без блокування:
     ```c
     int bytes_available;
     ioctl(master_fd, FIONREAD, &bytes_available);
     ```
   - Кількість байтів, що очікують передачі у вихідній черзі:
     ```c
     int bytes_queued;
     ioctl(master_fd, TIOCOUTQ, &bytes_queued);
     ```

## Системний інтерфейс ABI: структури termios та termios2

Інтерфейс термінальної підсистеми стандартизовано в POSIX.1 (IEEE Std 1003.1). Заголовок `<termios.h>` оголошує структуру `struct termios`, яка інкапсулює стан лінійної дисципліни ядра (драйвер `N_TTY`) для кожного символьного пристрою TTY або псевдотермінала (`/dev/pts/N`):

```c
typedef unsigned int  tcflag_t;
typedef unsigned char cc_t;
typedef unsigned int  speed_t;

#define NCCS 32 /* Розмір масиву спецсимволів у Linux (у BSD/macOS — 20) */

struct termios {
    tcflag_t c_iflag;      /* Вхідні режими (Input Modes) */
    tcflag_t c_oflag;      /* Вихідні режими (Output Modes) */
    tcflag_t c_cflag;      /* Керуючі режими лінії (Control Modes) */
    tcflag_t c_lflag;      /* Локальні режими дисципліни (Local Modes) */
    cc_t     c_line;       /* Номер лінійної дисципліни (0 = N_TTY) */
    cc_t     c_cc[NCCS];   /* Масив спеціальних керуючих символів */
    speed_t  c_ispeed;     /* Швидкість вхідного потоку в бодах */
    speed_t  c_ospeed;     /* Швидкість вихідного потоку в бодах */
};
```

### Розширена структура Linux: struct termios2 та довільні бодрейти

У стандартній структурі POSIX `struct termios` швидкість передачі задається через бітове поле `CBAUD` у `c_cflag` за допомогою дискретних констант (`B9600`, `B115200` тощо). Це унеможливлює роботу з довільними апаратними швидкостями (наприклад, 31250 бод для протоколу MIDI, 250000 бод для DMX512 або нестандартні швидкості мікроконтролерів).

Операційна система Linux надає низькорівневе розширення ядра через структуру `struct termios2`, визначену в системному заголовку `<asm/termbits.h>`:

```c
struct termios2 {
    tcflag_t c_iflag;      /* Вхідні режими */
    tcflag_t c_oflag;      /* Вихідні режими */
    tcflag_t c_cflag;      /* Керуючі режими (підтримує прапорець BOTHER) */
    tcflag_t c_lflag;      /* Локальні режими */
    cc_t     c_line;       /* Номер лінійної дисципліни */
    cc_t     c_cc[NCCS];   /* Спеціальні керуючі символи */
    speed_t  c_ispeed;     /* Пряма числова швидкість прийому в бодах */
    speed_t  c_ospeed;     /* Пряма числова швидкість передачі в бодах */
};
```

Для роботи зі структурою `struct termios2` використовуються спеціальні коди запитів системного виклику `ioctl`:
- `TCGETS2` (`_IOR('T', 0x2A, struct termios2)`): Зчитує параметри термінала безпосередньо в `struct termios2`.
- `TCSETS2` (`_IOW('T', 0x2B, struct termios2)`): Застосовує нові параметри негайно (аналог `TCSANOW`).
- `TCSETSW2` (`_IOW('T', 0x2C, struct termios2)`): Застосовує параметри після передачі вихідної черги (аналог `TCSADRAIN`).
- `TCSETSF2` (`_IOW('T', 0x2D, struct termios2)`): Застосовує параметри після передачі виводу та очищення черги вводу (аналог `TCSAFLUSH`).

Щоб встановити нестандартну швидкість (наприклад, 250000 бод), у полі `c_cflag` очищають маску `CBAUD`, виставляють біт `BOTHER` (`0x00001000` / `0010000`) та записують числове значення прямо в поля `c_ispeed` і `c_ospeed`:

```c
struct termios2 t2;
ioctl(fd, TCGETS2, &t2);
t2.c_cflag &= ~CBAUD;
t2.c_cflag |= BOTHER;
t2.c_ispeed = 250000;
t2.c_ospeed = 250000;
ioctl(fd, TCSETS2, &t2);
```

## Системні виклики та функції керування терміналом

Стандарт POSIX.1 визначає набір функцій обгортки над системним викликом `ioctl`, які забезпечують переносне керування термінальним дескриптором.

### Функції конфігурації атрибутів

#### `int tcgetattr(int fd, struct termios *termios_p)`
- **Призначення:** Зчитує поточні параметри лінійної дисципліни, асоційовані з відкритим дескриптором `fd`, і зберігає їх за вказівником `termios_p`.
- **Системний виклик ядра:** `ioctl(fd, TCGETS, termios_p)`.
- **Повертуване значення:** `0` у разі успіху; `-1` у разі помилки із встановленням `errno`.
- **Попередні умови:** `fd` має бути відкритим файловим дескриптором, що вказує на термінальний пристрій (перевіряється функцією `isatty(fd)`).

#### `int tcsetattr(int fd, int optional_actions, const struct termios *termios_p)`
- **Призначення:** Записує конфігурацію зі структури `*termios_p` у лінійну дисципліну термінала.
- **Параметр `optional_actions`:**
  - `TCSANOW` (ioctl `TCSETS`): Зміни набувають чинності негайно. Єдиний безпечний варіант для обробників асинхронних сигналів (`SIGINT`, `SIGTERM`), оскільки не блокується, якщо вивід термінала було призупинено за протоколом XOFF (`Ctrl+S`).
  - `TCSADRAIN` (ioctl `TCSETSW`): Зміни набувають чинності після того, як увесь вивід, записаний у `fd`, буде передано на термінал. Стандартний вибір утиліти `stty` для запобігання пошкодженню тексту в процесі передачі.
  - `TCSAFLUSH` (ioctl `TCSETSF`): Зміни набувають чинності після завершення передачі виводу, а всі накопичені вхідні байти, які ще не були прочитані програмою, безповоротно відкидаються. Обов'язковий при перемиканні в сирий режим або перед запитом пароля, щоб усунути випадково набрані користувачем символи.
- **Пастка стандарту POSIX (Partial Success):** Стандарт POSIX вимагає повернення `0`, якщо вдалося застосувати *хоча б частину* запитаних змін (наприклад, якщо змінено швидкість, але не підтримано прапорець парності). Надійний код зобов'язаний після `tcsetattr()` викликати `tcgetattr()` та перевірити, чи всі критичні біти справді встановилися.

### Функції керування лінією та буферами

#### `int tcsendbreak(int fd, int duration)`
- **Призначення:** Генерує стан розриву зв'язку (BREAK) на послідовній лінії шляхом передачі безперервного потоку нульових бітів.
- **Системний виклик ядра:** `ioctl(fd, TCSBRK, 0)` або `ioctl(fd, TCSBRKP, duration)`.
- **Параметр `duration`:** За стандартом POSIX значення `0` надсилає розрив тривалістю від 0.25 до 0.5 секунди. Ненульове значення в Linux інтерпретується як тривалість у десятих частках секунди.

#### `int tcdrain(int fd)`
- **Призначення:** Призупиняє виконання викликаючого потоку до повного спустошення черги передачі виводу (усі байти фізично відправлено на лінію або вичитано емулятором).
- **Системний виклик ядра:** `ioctl(fd, TCSBRK, 1)`.

#### `int tcflush(int fd, int queue_selector)`
- **Призначення:** Примусово очищає вказані внутрішні черги лінійної дисципліни:
  - `TCIFLUSH` (значення `0`): Очищає чергу отриманих, але ще не прочитаних вхідних байтів.
  - `TCOFLUSH` (значення `1`): Очищає чергу записаних, але ще не переданих вихідних байтів.
  - `TCIOFLUSH` (значення `2`): Одночасно очищає обидві черги (вводу і виводу).
- **Системний виклик ядра:** `ioctl(fd, TCFLSH, queue_selector)`.

#### `int tcflow(int fd, int action)`
- **Призначення:** Керує програмним потоком передачі даних на терміналі:
  - `TCOOFF` (значення `0`): Призупиняє передачу вихідних даних (аналог отримання `VSTOP` / `0x13`).
  - `TCOON` (значення `1`): Поновлює призупинену передачу вихідних даних (аналог отримання `VSTART` / `0x11`).
  - `TCIOFF` (значення `2`): Передає на лінію байт `STOP` (`c_cc[VSTOP]`, `Ctrl+S`), вимагаючи від віддаленого вузла зупинити передачу.
  - `TCION` (значення `3`): Передає на лінію байт `START` (`c_cc[VSTART]`, `Ctrl+Q`), дозволяючи віддаленому вузлу поновити передачу.
- **Системний виклик ядра:** `ioctl(fd, TCXONC, action)`.

### Функції маніпуляції швидкістю передачі

- `speed_t cfgetispeed(const struct termios *termios_p)`: Повертає константу вхідної швидкості з переданої структури.
- `speed_t cfgetospeed(const struct termios *termios_p)`: Повертає константу вихідної швидкості з переданої структури.
- `int cfsetispeed(struct termios *termios_p, speed_t speed)`: Встановлює константу швидкості прийому в структурі.
- `int cfsetospeed(struct termios *termios_p, speed_t speed)`: Встановлює константу швидкості передачі в структурі. Встановлення швидкості `B0` змушує драйвер скинути сигнал DTR (покласти слухавку модема).
- `int cfsetspeed(struct termios *termios_p, speed_t speed)`: Розширення BSD/glibc для одночасного встановлення вхідної та вихідної швидкостей.
- `void cfmakeraw(struct termios *termios_p)`: Розширення BSD/glibc, що вимикає всі рівні обробки введення, виведення та локальних сигналів, налаштовуючи структуру на сирий 8-бітний потік.

### Керування розміром вікна та групами процесів через ioctl

| Код ioctl | Тип аргументу | Опис системної операції |
|---|---|---|
| `TIOCGWINSZ` | `struct winsize *` | Зчитує геометрію вікна термінала (`ws_row`, `ws_col`, `ws_xpixel`, `ws_ypixel`). |
| `TIOCSWINSZ` | `const struct winsize *` | Встановлює розмір вікна та автоматично надсилає сигнал `SIGWINCH` передній групі процесів. |
| `TIOCGPGRP` | `pid_t *` | Отримує ідентифікатор групи процесів переднього плану (Foreground Process Group ID). |
| `TIOCSPGRP` | `const pid_t *` | Призначає групу процесів переднього плану для керування терміналом. |
| `TIOCSCTTY` | `int` (`0` або `1`) | Робить термінал контрольним для викликаючого сесійного лідера (`setsid()`). |
| `TIOCNOTTY` | `void` | Від'єднує викликаючий процес від його поточного контрольного термінала. |

### Коди системних помилок (errno)

- `EBADF`: Дескриптор `fd` не є відкритим файловим дескриптором.
- `ENOTTY`: Файловий дескриптор вказує на файл, пайп, сокет або каталог, які не підтримують операції термінального введення-виведення.
- `EINVAL`: Передано недійсний аргумент (невідомий селектор черги, помилковий модифікатор `optional_actions` або непідтримуване значення швидкості).
- `EINTR`: Виклик було перервано обробником асинхронного сигналу до завершення операції `ioctl`.
- `EFAULT`: Вказівник на структуру `termios` вказує на недоступну область адресного простору процесу.
- `EIO`: Процес фонової групи спробував виконати читання або запис у термінал, який було від'єднано або переведено в недійсний стан.

### Механіка та крайові випадки обробки c_iflag

1. **Пріоритет обробки стану BREAK:**
   - Якщо `IGNBRK = 1`: лінійна дисципліна повністю ігнорує розрив лінії.
   - Якщо `IGNBRK = 0` та `BRKINT = 1`: драйвер очищає черги вводу-виводу (`TCIOFLUSH`) та генерує сигнал `SIGINT` передній групі процесів термінала.
   - Якщо `IGNBRK = 0` та `BRKINT = 0`: якщо `PARMRK = 1`, розрив лінії транслюється у трибайтну послідовність `\377 \0 \0`; якщо `PARMRK = 0`, розрив читається програмою як одиночний нульовий байт `\0` (`0x00`).

2. **Пріоритет нормалізації переведення рядків на вводі:**
   - Послідовність перевірки вхідного байта `0x0D` (`\r`): спершу перевіряється `IGNCR` — якщо активний, байт негайно знищується; якщо ні, перевіряється `ICRNL` — якщо активний, байт замінюється на `0x0A` (`\n`).
   - Послідовність перевірки вхідного байта `0x0A` (`\n`): якщо активний `INLCR`, байт замінюється на `0x0D` (`\r`).

3. **Протокол маркування помилок парності (PARMRK):**
   - Якщо `INPCK = 1`, `IGNPAR = 0` та `PARMRK = 1`, помилковий байт `X` замінюється в потоці на послідовність трьох байтів: `0xFF 0x00 X`.
   - Якщо `ISTRIP = 0`, валідний байт даних `0xFF` замінюється на `0xFF 0xFF`, щоб відрізнити дійсні дані від префікса помилки.

### Внутрішня механіка лінійної дисципліни N_TTY для c_lflag

1. **Генерація сигналів через `n_tty_receive_signal_char()`:**
   Коли у вхідному потоці з'являється байт, що збігається з `c_cc[VINTR]` (`^C`), `c_cc[VQUIT]` (`^\`) або `c_cc[VSUSP]` (`^Z`), дисципліна перевіряє біт `ISIG`:
   - Якщо `ISIG` активний: драйвер перериває накопичення буфера, якщо прапорець `NOFLSH` вимкнено — виконує `n_tty_flush_buffers()` для негайного очищення вхідної та вихідної черг, знаходить сесійну групу процесів переднього плану через `tty->pgrp` і надсилає груповий сигнал за допомогою функції ядра `kill_pgrp(tty->pgrp, sig, 1)`.
   - Якщо `ISIG` знято: вхідний байт сприймається як звичайні дані і записується у `read_buf`.

2. **Канонічне редагування рядків (Line Editing State Machine):**
   У режимі `ICANON` показчик `line_start` фіксує початок поточного рядка в кільцевому буфері `read_buf`. Коли надходить байт `VERASE` (Backspace):
   - Якщо `IUTF8` активний: ядро сканує байти назад від `read_head` до знаходження стартового байта UTF-8 (байта, в якого два старших біти не дорівнюють `10xxxxxx`), стираючи весь багатобайтовий символ цілком.
   - Якщо `ECHOE` активний: у буфер відлуння `echo_buf` надсилається трибайтна послідовність `\b \b` (Cursor Left, Space, Cursor Left).
   - Коли надходить байт `VKILL` (`^U`), за активного `ECHOKE` ядро генерує стільки пар `\b \b`, скільки символів містив поточний рядок від `line_start` до `read_head`.

3. **Керування фоновим доступом та блокуванням (Job Control):**
   Коли фоновий процес намагається виконати запис `write()` у дескриптор TTY, функція ядра `tty_check_change()` звіряє `task_pgrp(current)` із `tty->pgrp`:
   - Якщо `TOSTOP` активний і процес не ігнорує та не блокує сигнал `SIGTTOU`, ядро надсилає `SIGTTOU` групі процесу, що переводить її в стан `TASK_STOPPED`.
   - Якщо `TOSTOP` вимкнено (типово у `stty sane`), фоновий `write()` успішно записує дані у вихідний буфер без генерації сигналів.

### Матриця чотирьох квадрантів неканонічного читання (VMIN та VTIME)

Коли канонічний режим вимкнено (`c_lflag & ICANON == 0`), спеціальні символи `VEOF`, `VEOL`, `VERASE`, `VKILL` перестають оброблятися ядром. Поведінка системного виклику `read(fd, buf, count)` повністю визначається значеннями двох параметрів: `c_cc[VMIN]` та `c_cc[VTIME]`.

```
                    VTIME == 0                      VTIME > 0
          ┌─────────────────────────────┬─────────────────────────────┐
          │ Квадрант 1: Блокуюче        │ Квадрант 3: Міжсимвольний   │
VMIN > 0  │ читання                     │ таймер (Inter-byte)         │
          │ Блокується до отримання     │ Перший байт без тайм-ауту,  │
          │ щонайменше VMIN байтів.     │ наступні — з таймером VTIME.│
          ├─────────────────────────────┼─────────────────────────────┤
          │ Квадрант 4: Повний Polling  │ Квадрант 2: Чистий тайм-аут │
VMIN == 0 │ Неблокуюче опитування.      │ Таймер запускається одразу. │
          │ Повертає 0 негайно,         │ Повертає 0 після завершення │
          │ якщо черга вводу порожня.   │ інтервалу VTIME * 0.1 с.    │
          └─────────────────────────────┴─────────────────────────────┘
```

| Конфігурація | Стан таймера та блокування | Поведінка виклику read() | Сфера інженерного застосування |
|---|---|---|---|
| **VMIN > 0, VTIME == 0** | Чисте блокування за кількістю байтів. Таймер вимкнено. | Виклик `read()` блокує процес на невизначений термін, доки в буфер не надійде щонайменше `VMIN` байтів. Повертає кількість реально прочитаних байтів (від `VMIN` до `count`). Значення `0` ніколи не повертається. | Класичний сирий режим (`cfmakeraw`), посимвольне читання команд у редакторах (`VMIN = 1, VTIME = 0`). |
| **VMIN == 0, VTIME > 0** | Чистий тайм-аут. Таймер запускається негайно в момент виклику. | Таймер зворотного відліку з дискретністю 0.1 с (`VTIME * 100 мс`) стартує при вході в `read()`. Якщо до завершення часу надійшов хоча б 1 байт, `read()` негайно повертає всі накопичені дані. Якщо час сплив без надходження даних, `read()` повертає `0` (фіксація тайм-ауту). | Опитування зовнішніх датчиків, очікування відповіді AT-модема з гарантованим поверненням керування. |
| **VMIN > 0, VTIME > 0** | Міжсимвольний таймер (Inter-byte Timer). | Виклик `read()` блокується до надходження **першого байта**. Щойно перший байт отримано, ядро запускає міжсимвольний таймер тривалістю `VTIME * 0.1 с`. Кожен наступний байт скидає та перезапускає таймер. `read()` повертає керування, якщо: (1) накопичено `VMIN` байтів; або (2) пауза між двома послідовними байтами перевищила `VTIME`. | Прийом пакетів змінного розміру за протоколами UART/RS-485 (виявлення кінця кадру за тайм-аутом тиші). |
| **VMIN == 0, VTIME == 0** | Повне неблокуюче опитування (Polling). | Виклик `read()` повертає керування негайно. Якщо у черзі ядра є доступні байти, повертається їхня кількість (до розміру `count`). Якщо буфер вводу порожній, виклик негайно повертає `0`. | Швидке опитування термінала всередині високочастотних ігрових циклів або графічних рушіїв без використання `select()`/`poll()`. |

У внутрішній реалізації ядра Linux таймер розраховується в системних квантах часу `jiffies` через константу частоти `HZ` як `timeout = VTIME * HZ / 10`. Процес переводиться в стан сну `TASK_INTERRUPTIBLE` у черзі очікування `tty->read_wait`. Коли черговий flip-буфер виштовхується в лінійну дисципліну, виклик `wake_up_interruptible(&tty->read_wait)` пробуджує процес для перевірки виконання умов `VMIN` або спливання тайм-ауту.

## Мультиплексування введення-виведення та неблокуючий режим termios (O_NONBLOCK, epoll, poll, kqueue)

Сучасні термінальні програми, сервери віддаленого доступу (OpenSSH, Mosh), мультиплексори вікон (`tmux`, `screen`, `zellij`) та реактивні TUI-рушії обробляють десятки джерел подій (користувацький ввід, таймери, мережеві сокети, дескриптори дочірніх процесів) в одному системному потоці за допомогою механізмів мультиплексування I/O (`epoll` у Linux, `kqueue` у BSD/macOS, POSIX `poll`/`ppoll`).

### Пріоритет O_NONBLOCK над параметрами VMIN та VTIME

Переведення термінального файлового дескриптора в неблокуючий режим здійснюється через системний виклик `fcntl`:

```c
int flags = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, flags | O_NONBLOCK);
```

Стандарт POSIX.1 чітко специфікує співвідношення між прапорцем статусу відкритого файлового опису `O_NONBLOCK` (рівень VFS) та конфігурацією лінійної дисципліни `VMIN`/`VTIME` (рівень `struct termios`):

1. **Безумовне скасування блокування:** Прапорець `O_NONBLOCK` має абсолютний пріоритет над будь-якими ненульовими значеннями `VMIN` та `VTIME`.
2. **Семантика виклику `read()` при порожньому буфері:**
   - Якщо в черзі `read_buf` лінійної дисципліни немає даних, виклик `read(fd, buf, count)` не переводить процес у стан сну ядра і не запускає таймери `VTIME`. Він негайно повертає значення `-1`, а системна змінна `errno` встановлюється в `EAGAIN` (або `EWOULDBLOCK`).
3. **Семантика виклику `read()` при наявності даних:**
   - Якщо у буфері є хоча б один байт (навіть якщо загальна кількість менша за `VMIN`), ядро копіює всі наявні байти у буфер простору користувача (до максимального розміру `count`) і негайно повертає кількість реально прочитаних байтів. Процес ніколи не чекає накопичення повного обсягу `VMIN`.

| Стан буфера ядра | Конфігурація VMIN / VTIME | Поведінка read() без O_NONBLOCK | Поведінка read() з O_NONBLOCK |
|---|---|---|---|
| **Порожній** | `VMIN > 0, VTIME == 0` | Блокується до накопичення `VMIN` байтів. | Повертає `-1` (`errno = EAGAIN`) негайно. |
| **Порожній** | `VMIN == 0, VTIME > 0` | Блокується до тайм-ауту або першого байта. | Повертає `-1` (`errno = EAGAIN`) негайно; таймер не стартує. |
| **Порожній** | `VMIN > 0, VTIME > 0` | Блокується до надходження 1-го байта. | Повертає `-1` (`errno = EAGAIN`) негайно. |
| **Є N байтів (N < VMIN)** | `VMIN > 0, VTIME == 0` | Блокується до прибуття ще `VMIN - N` байтів. | Повертає `N` байтів негайно; блокування відсутнє. |
| **Є N байтів** | Будь-яка комбінація | Повертає `min(N, count)` згідно з правилами квадранта. | Повертає `min(N, count)` негайно. |

### Обробка термінальних подій у механізмах poll, epoll та kqueue

Термінальні дескриптори TTY та псевдотермінали PTY транслюють внутрішні зміни стану ядра у стандартні системні маски подій:

1. **Маска подій для poll / epoll (Linux) та kqueue (BSD):**
   - `POLLIN` / `EPOLLIN` / `EVFILT_READ`:
     - Для підсистеми TTY/Slave: у канонічному режимі (`ICANON`) доступний щонайменше один повний рядок (завершений `\n`, `EOF` або `EOL`); у неканонічному режимі (`-icanon`) у буфері є хоча б один байт вхідних даних.
     - Для PTY Master: у вихідному буфері веденого пристрою з'явилися дані для емулятора (або сформовано пакет події `TIOCPKT`).
   - `POLLOUT` / `EPOLLOUT` / `EVFILT_WRITE`:
     - Вільне місце у вихідному буфері TTY/PTY перевищує поріг відновлення (`TTY_THRESHOLD_UNTHROTTLE`). Системний виклик `write()` гарантовано прийме щонайменше частину байтів без блокування.
   - `POLLHUP` / `EPOLLHUP` / `EV_EOF`:
     - Відбулося від'єднання (Hangup) термінального каналу. Для PTY Master подія `POLLHUP` генерується, коли ведений процес закрив останній відкритий дескриптор `/dev/pts/N` (наприклад, оболонка завершилася). Подальші виклики `read()` з майстер-дескриптора повертають `0` (EOF) або помилку `EIO`.
   - `POLLERR` / `EPOLLERR`:
     - Виникла апаратна помилка послідовної лінії або порушення протоколу керування сесією.

2. **Особливості Edge-Triggered режиму (`EPOLLET`):**
   - У режимі `EPOLLET` ядро надсилає сповіщення лише в момент **зміни стану** (наприклад, при переході буфера від 0 байтів до ненульової кількості).
   - *Інженерний патерн повного спустошення (Draining Loop):* Обробник події зобов'язаний вичитувати дані у циклі `while` до отримання помилки `EAGAIN`:
     ```c
     while (1) {
         ssize_t n = read(tty_fd, buf, sizeof(buf));
         if (n > 0) {
             process_input_chunk(buf, n);
         } else if (n < 0) {
             if (errno == EAGAIN || errno == EWOULDBLOCK) {
                 break; /* Усі наявні в буфері ядра байти вичитано */
             }
             if (errno == EINTR) {
                 continue; /* Системний виклик перервано сигналом */
             }
             handle_read_error(errno);
             break;
         } else {
             handle_eof(); /* n == 0: отримано кінець файлу */
             break;
         }
     }
     ```
   - Якщо застосунок вичитає лише частину байтів (наприклад, один фіксований буфер) і вийде з обробника, `epoll_wait()` більше ніколи не розбудить процес для залишкових байтів, що призведе до повного зависання вводу.

### Несумісність блокуючих операцій termios з Event Loop та патерни асинхронного дренажу

1. **Пастка викликів `tcdrain()` та `tcsetattr(TCSADRAIN)`:**
   - Системний виклик `tcdrain(fd)` (або модифікатор `TCSADRAIN` у `tcsetattr`) блокує викликаючий потік ядра доти, доки апаратний трансивер UART або черга PTY повністю не передасть усі накопичені байти.
   - На повільних послідовних лініях (наприклад, швидкість 9600 бод передає 1 байт приблизно за 1.04 мс) вивід 4 КБ тексту блокує процес на **4.2 секунди**.
   - Виклик `tcdrain()` у головному потоці реактивного циклу подій (Event Loop) повністю паралізує обробку всіх мережевих сокетів, інтерфейсних таймерів та користувацьких сигналів на цей час.

2. **Патерн асинхронного дренажу черги:**
   Щоб уникнути блокування основного потоку при зміні параметрів термінала або закритті з'єднання:
   - Застосунок інспектує кількість непереданих байтів у вихідному буфері ядра за допомогою `ioctl(fd, TIOCOUTQ, &pending_bytes)`.
   - Якщо `pending_bytes > 0`, дескриптор реєструється в `epoll` з маскою `EPOLLOUT`.
   - Нові дані не записуються; програма продовжує обслуговувати інші клієнтські події.
   - Щойно лічильник `TIOCOUTQ` падає до `0` або надходить фінальна подія готовності запису, викликається неблокуючий перемикач `tcsetattr(fd, TCSANOW, &new_termios)` без затримки виконання.

## Механіка руйнування стану та виникнення «зламаного терміналу»

Явище «зламаного терміналу» (Broken Terminal) виникає внаслідок розриву синхронізації між прикладним процесом, лінійною дисципліною ядра та кінцевим автоматом емулятора термінала.

### Причини збереження пошкодженого стану

1. **Життєвий цикл структури termios у пам'яті ядра:** Коли інтерактивна програма (текстовий редактор, пейджер або TUI-додаток) конфігурує сирий режим, вона викликає `tcsetattr()`, модифікуючи екземпляр `struct termios` усередині структури `struct tty_struct` пристрою псевдотермінала `/dev/pts/N`. Якщо процес завершується аварійно (внаслідок сигналів `SIGSEGV`, `SIGABRT`, `SIGBUS` або неперехоплюваного вбивства `kill -9`), системний виклик ядра `do_exit()` звільняє пам'ять процесу (`mm_struct`) та закриває його дескриптори (`files_struct`). Проте пристрій `/dev/pts/N` залишається відкритим батьківською командною оболонкою (`bash`, `zsh`), тому ядро не скидає прапорці `termios` автоматично.
2. **Автономність кінцевого автомата емулятора:** Емулятор термінала (`xterm`, `alacritty`, `kitty`) функціонує як незалежний процес на боці `/dev/ptmx`. Він не отримує сигналів операційної системи про аварійну загибель клієнтської програми. Якщо програма встигла надіслати escape-послідовність перемикання кодової сторінки на DEC Line Drawing (`\033(0` / `SO`), приховання курсора (`\033[?25l`), активації Alternate Screen Buffer (`\033[?1049h`), захоплення подій миші (`\033[?1000h`), увімкнення обрамленої вставки (`\033[?2004h`) або початку синхронізованого кадру (`\033[?2026h`), внутрішні регістри парсера емулятора залишаються в цьому стані назавжди, доки не надійде явна послідовність скидання.

### Побітовий аналіз симптомів руйнування

| Симптом поломки | Скинутий або встановлений прапорець | Фізичний механізм дефекту в ядрі / емуляторі | Метод усунення |
|---|---|---|---|
| **«Сліпий термінал» (Blind Input)** | Знято `ECHO` (`c_lflag`) | Лінійна дисципліна `N_TTY` припиняє копіювати вхідні байти у вихідний буфер `echo_buf`. Натискання клавіш зчитуються оболонкою, але не відображаються на моніторі. | `stty echo` або `stty sane` |
| **«Ефект сходів» (Staircase Effect)** | Знято `ONLCR` або `OPOST` (`c_oflag`) | Символ переведення рядка `\n` (`0x0A`) більше не розгортається у пару `\r\n` (`0x0D 0x0A`). Емулятор зміщує курсор вниз, не повертаючи його до нульової колонки. | `stty onlcr opost` |
| **Втрата рядкового редагування** | Знято `ICANON` (`c_lflag`) | Вимкнено канонічний буфер `read_buf`. Натискання Backspace надсилає код `0x7F` або `0x08`, який друкується як `^?`/`^H` замість видалення символу. | `stty icanon` або `stty sane` |
| **Блокування клавіші Enter** | Знято `ICRNL` (`c_iflag`) | Клавіша Enter фізично надсилає байт `0x0D` (`CR`). Без `ICRNL` ядро не замінює його на `0x0A` (`NL`). Оболонка чекає на `\n` і блокує виконання команд. | Введення **`Ctrl+J`** (байт `0x0A` в обхід драйвера) та `stty icrnl` |
| **Втрата сигнальних клавіш** | Знято `ISIG` (`c_lflag`) | Байти `0x03` (`Ctrl+C`), `0x1C` (`Ctrl+\`) та `0x1A` (`Ctrl+Z`) передаються як сирі дані замість генерації сигналів `SIGINT`, `SIGQUIT` та `SIGTSTP`. | `stty isig` |
| **Шрифтова псевдографіка** | Встановлено активний набір G1 (`SO` / `0x0E`) | Емулятор перемикає активну таблицю на DEC Special Graphics: латинські літери від `a` до `z` замінюються на кутики й рамки (`date` -> `␍▒├␊`). | Послідовність `\033(B\017` (US-ASCII + Shift-In) |
| **Завислий альтернативний екран** | Встановлено режим `\033[?1049h` | Емулятор залишається у відрізаному повноекранному буфері без доступу до історії прокрутки. | Послідовність `\033[?1049l` |
| **Невидимий курсор** | Встановлено режим `\033[?25l` | Регістр `DECTCEM` емулятора приховує текстовий курсор. | Послідовність `\033[?25h` |
| **Сміття від миші та вставки** | Режими `\033[?1000h` / `\033[?2004h` | Рух мишею та вставка тексту генерують коди `^[[<0;45;12M` або `\033[200~` у командний рядок. | Послідовності `\033[?1000l` / `\033[?2004l` |
| **Зависання рендерингу кадру** | Встановлено режим `\033[?2026h` | Емулятор чекає завершення синхронного блоку й не відображає вивід на екран. | Послідовність `\033[?2026l` |

## Протокол асинхронно-сигнальної безпеки та обробки сигналів у застосунках

Консольні програми, що переводять термінал у сирий режим, зобов'язані реалізувати строгий протокол обробки асинхронних сигналів для запобігання дедлокам та збереження працездатності батьківської оболонки.

### 1. Перехоплення сигналів завершення (SIGINT, SIGTERM, SIGHUP, SIGQUIT)

- **Вимоги стандарту POSIX (Async-Signal-Safe):** Сигнальний обробник перериває виконання процесу в довільний момент часу. Всередині обробника категорично заборонено викликати функції виділення динамічної пам'яті (`malloc`, `free`), операції з потоками введення-виведення (`printf`, `std::cout`, `syslog`), або функції завершення `exit()`, оскільки вони використовують нереентерабельні м'ютекси.
- **Дозволені системні виклики:** `tcsetattr()`, `tcgetattr()`, `write()`, `sigaction()`, `sigprocmask()`, `raise()`, `_exit()`.
- **Застосування `TCSANOW` проти `TCSADRAIN`:** В обробниках сигналів дозволено використовувати виключно дію `TCSANOW`. Якщо користувач перед натисканням `Ctrl+C` натиснув `Ctrl+S` (зупинка передачі за протоколом XOFF), черга передачі ніколи не спустошиться, і виклик `tcsetattr(fd, TCSADRAIN, ...)` спричинить вічне взаємне блокування процесу всередині обробника сигналу.
- **Патерн коректного завершення через самогубство (Signal Resend):** Якщо процес завершується через `_exit(1)`, батьківська оболонка сприймає це як штатно завершений процес (`WIFEXITED == true`), що спотворює статус умовних конвеєрів (наприклад, `make && ./app`). Надійний обробник відновлює стан термінала, скидає диспозицію сигналу на `SIG_DFL`, розблоковує сигнал через `sigprocmask()` та викликає `raise(signo)`:

```c
static struct termios g_orig_termios;
static volatile sig_atomic_t g_is_raw = 0;

void fatal_signal_handler(int signo) {
    int saved_errno = errno;

    if (g_is_raw) {
        /* 1. Негайне відновлення налаштувань ядра */
        tcsetattr(STDIN_FILENO, TCSANOW, &g_orig_termios);
        /* 2. Скидання графічних режимів емулятора: показ курсора та очищення стилів */
        const char reset_seq[] = "\033[?25h\033[0m\033(B\017\033[?2004l\033[?1000l\033[?1006l\033[?2026l";
        (void)write(STDOUT_FILENO, reset_seq, sizeof(reset_seq) - 1);
        g_is_raw = 0;
    }

    /* 3. Скидання диспозиції сигналу на системну дію за замовчуванням */
    struct sigaction sa;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sa.sa_handler = SIG_DFL;
    sigaction(signo, &sa, NULL);

    /* 4. Зняття блокування сигналу в поточній масці процесу */
    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, signo);
    sigprocmask(SIG_UNBLOCK, &set, NULL);

    /* 5. Повторна генерація сигналу самому собі для коректного waitpid() */
    raise(signo);

    errno = saved_errno;
}
```

### 2. Протокол керування завданнями (Job Control: SIGTSTP та SIGCONT)

Коли користувач натискає комбінацію `Ctrl+Z`, лінійна дисципліна надсилає процесу сигнал `SIGTSTP`. Якщо програма не перехопить цей сигнал, ядро призупинить процес безпосередньо у сирому режимі, залишивши оболонку зі зламаним терміналом.

**Покроковий протокол обробки `SIGTSTP` та `SIGCONT`:**
1. **Призупинення (`SIGTSTP`):**
   - Тимчасово відновити вихідний канонічний стан термінала: `tcsetattr(STDIN_FILENO, TCSANOW, &g_orig_termios)`.
   - Зробити курсор видимим: `write(STDOUT_FILENO, "\033[?25h", 6)`.
   - Встановити обробник `SIGTSTP` у стан `SIG_DFL`.
   - Зняти блокування сигналу `SIGTSTP` через `sigprocmask(SIG_UNBLOCK, ...)`.
   - Викликати `raise(SIGTSTP)` — ядро переводить процес у стан `TASK_STOPPED` та надсилає батьківській оболонці сигнал `SIGCHLD`. Оболонка отримує контроль над чистим терміналом.
2. **Поновлення роботи (`SIGCONT`):**
   - Коли користувач вводить команду `fg`, ядро надсилає процесу сигнал `SIGCONT`.
   - Виконання процесу поновлюється безпосередньо після інструкції `raise(SIGTSTP)`.
   - Обробник перереєстровує власну функцію для майбутніх `SIGTSTP`.
   - Програма повторно переводить термінал у сирий режим: `tcsetattr(STDIN_FILENO, TCSADRAIN, &g_raw_termios)`.
   - Приховує курсор `write(STDOUT_FILENO, "\033[?25l", 6)` та перемальовує TUI-інтерфейс.

### 3. Обробка зміни розміру вікна (SIGWINCH) та системні виклики (EINTR)

- **Зчитування геометрії:** При зміні розміру вікна емулятор надсилає сигнал `SIGWINCH`. Обробник сигналу виставляє атомарний прапорець `volatile sig_atomic_t g_resized = 1;`. Основний цикл програми перевіряє цей прапорець та зчитує нові розміри викликом `ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws)`.
- **Переривання повільних системних викликів (`EINTR`):** Блокуючий системний виклик `read(STDIN_FILENO, ...)` переривається сигналом `SIGWINCH` і повертає `-1` зі значенням `errno == EINTR`. Надійний цикл опитування повинен коректно опрацьовувати цю ситуацію:

```c
char c;
ssize_t n;
while (g_running) {
    n = read(STDIN_FILENO, &c, 1);
    if (n < 0) {
        if (errno == EINTR) {
            /* Системний виклик було перервано сигналом (наприклад, SIGWINCH) */
            if (g_resized) {
                handle_window_resize();
                g_resized = 0;
            }
            continue;
        }
        break; /* Реальна системна помилка введення */
    }
    /* Обробка прочитаного байта */
}
```

### 4. Фонове читання та запис (SIGTTIN / SIGTTOU)

- **Фонове читання:** Спроба будь-якого фонового процесу виконати `read()` з дескриптора керівного термінала змушує ядро надіслати процесу сигнал `SIGTTIN`, що переводить його в стан зупинки `TASK_STOPPED`.
- **Фоновий запис:** Якщо у `c_lflag` активний прапорець `TOSTOP`, будь-яка спроба фонового процесу виконати `write()` у термінал породжує сигнал `SIGTTOU`, блокуючи процес. Якщо `TOSTOP` вимкнено (значення за замовчуванням у `sane`), фоновий вивід вільно друкується на екран, змішуючись із виводом переднього плану.

## Побітовий розбір команд та профілів stty

### Профіль stty sane

Команда `stty sane` приводить структуру `struct termios` до безпечного, гарантовано працездатного стандартного стану, скидаючи специфічні налаштування прикладних програм:

```c
void make_sane(struct termios *t) {
    /* 1. Вхідні прапорці c_iflag: */
    t->c_iflag |= (BRKINT | ICRNL | IMAXBEL);
    #ifdef IUTF8
    t->c_iflag |= IUTF8;
    #endif
    t->c_iflag &= ~(IGNBRK | INLCR | IGNCR | IUCLC |
                    IXOFF | IXANY | IGNPAR | PARMRK | INPCK | ISTRIP);
    /* IXON зберігається увімкненим */

    /* 2. Вихідні прапорці c_oflag: */
    t->c_oflag |= (OPOST | ONLCR);
    t->c_oflag &= ~(OLCUC | OCRNL | ONOCR | ONLRET | OFILL | OFDEL |
                    NLDLY | CRDLY | TABDLY | BSDLY | VTDLY | FFDLY);

    /* 3. Керуючі прапорці c_cflag: */
    t->c_cflag |= (CREAD | CS8 | CLOCAL);
    t->c_cflag &= ~(PARENB | PARODD | CSTOPB | CRTSCTS);

    /* 4. Локальні прапорці c_lflag: */
    t->c_lflag |= (ISIG | ICANON | IEXTEN | ECHO | ECHOE | ECHOK | ECHOCTL | ECHOKE);
    t->c_lflag &= ~(ECHONL | NOFLSH | TOSTOP | ECHOPRT | XCASE);

    /* 5. Відновлення базових значень спецсимволів c_cc: */
    t->c_cc[VINTR]    = 0x03; /* ^C */
    t->c_cc[VQUIT]    = 0x1C; /* ^\ */
    t->c_cc[VERASE]   = 0x7F; /* ^? (DEL) */
    t->c_cc[VKILL]    = 0x15; /* ^U */
    t->c_cc[VEOF]     = 0x04; /* ^D */
    t->c_cc[VSTART]   = 0x11; /* ^Q */
    t->c_cc[VSTOP]    = 0x13; /* ^S */
    t->c_cc[VSUSP]    = 0x1A; /* ^Z */
    t->c_cc[VREPRINT] = 0x12; /* ^R */
    t->c_cc[VWERASE]  = 0x17; /* ^W */
    t->c_cc[VLNEXT]   = 0x16; /* ^V */
    t->c_cc[VDISCARD] = 0x0F; /* ^O */
    t->c_cc[VEOL]     = 0x00; /* _POSIX_VDISABLE */
    t->c_cc[VEOL2]    = 0x00; /* _POSIX_VDISABLE */
    t->c_cc[VMIN]     = 1;
    t->c_cc[VTIME]    = 0;
}
```

### Профіль stty raw та системна функція cfmakeraw

Режим `stty raw` (еквівалент функції `cfmakeraw(&t)`) повністю вимикає будь-яку обробку байтів ядром, перетворюючи лінійну дисципліну на прозорий канал передачі сирих двійкових даних:

```c
void cfmakeraw(struct termios *t) {
    /* Вимкнення всіх модифікацій вхідного потоку:
     * - відключає обробку BREAK (IGNBRK/BRKINT)
     * - відключає маркування та відсікання 8-го біта (PARMRK/ISTRIP)
     * - відключає нормалізацію CR/NL (INLCR/IGNCR/ICRNL)
     * - відключає програмне керування потоком (IXON) */
    t->c_iflag &= ~(IGNBRK | BRKINT | PARMRK | ISTRIP |
                    INLCR | IGNCR | ICRNL | IXON);

    /* Повне вимкнення вихідної обробки:
     * байти write() надсилаються у термінал без змін, ONLCR не працює */
    t->c_oflag &= ~OPOST;

    /* Вимкнення локальних режимів:
     * - вимикає відлуння (ECHO/ECHONL)
     * - вимикає буферизацію рядків (ICANON)
     * - вимикає генерацію сигналів SIGINT/SIGQUIT/SIGTSTP (ISIG)
     * - вимикає розширені спецсимволи (IEXTEN) */
    t->c_lflag &= ~(ECHO | ECHONL | ICANON | ISIG | IEXTEN);

    /* Налаштування апаратного кадру: 8 бітів без парності */
    t->c_cflag &= ~(CSIZE | PARENB);
    t->c_cflag |= CS8;

    /* Переведення read() у режим очікування 1 байта без тайм-ауту */
    t->c_cc[VMIN] = 1;
    t->c_cc[VTIME] = 0;
}
```

### Профіль прихованого вводу: stty -echo

Вимкнення відлуння для безпечного введення паролів змінює виключно бітову маску `c_lflag`:

```c
void set_password_mode(int fd, struct termios *saved_t) {
    struct termios t;
    tcgetattr(fd, saved_t);
    t = *saved_t;

    /* Скидання бітів відлуння при збереженні канонічного режиму */
    t.c_lflag &= ~(ECHO | ECHOE | ECHOK | ECHONL);

    /* Застосування через TCSAFLUSH: гарантує видалення випадково введених
     * раніше байтів із вхідного буфера ядра */
    tcsetattr(fd, TCSAFLUSH, &t);
}
```

### Відновлення канонічного режиму: stty cooked (або stty -raw)

Режим `cooked` повертає термінал із сирого стану до нормального режиму обробки:
- Вмикає `c_lflag |= (ICANON | ISIG | ECHO | ECHOE | ECHOK | IEXTEN)`.
- Вмикає `c_oflag |= (OPOST | ONLCR)`.
- Вмикає `c_iflag |= (ICRNL | IXON | BRKINT)`.

## Керуючі escape-послідовності скидання емулятора (VT100 / ANSI / DEC)

Якщо порушено внутрішній стан кінцевого автомата парсера емулятора термінала, скидання прапорців `termios` не відновить відображення. Емулятор функціонує за стандартом скінченних автоматів DEC ANSI X3.64 / ECMA-48. Переходи між станами (Ground, Escape, CSI, OSC, DCS, APC) визначаються вхідними байтами. Якщо вхідний потік було перервано на середині складеної послідовності або активовано нестандартні модальні регістри, необхідно відправити у вихідний потік термінала спеціальні керуючі коди.

## Термінальні бази даних: terminfo, termcap та інтеграція з curses/ncurses

Жорстке кодування escape-послідовностей ANSI/VT100 безпосередньо у вихідному коді програм порушує переносність, оскільки різні термінали, апаратні консолі та емулятори мають відмінні набори підтримуваних функцій, коди функціональних клавіш та часові затримки. В операційних системах Unix цю проблему розв'язує рівень абстракції термінальних баз даних **terminfo** (System V) та **termcap** (Berkeley Unix), а також бібліотеки інтерфейсу користувача **curses** / **ncurses**.

### Двійковий формат та внутрішня структура файлів terminfo

База даних `terminfo` зберігає скомпільовані двійкові описи можливостей терміналів у файловій системі за ієрархічними шляхами `/usr/share/terminfo/` або `~/.terminfo/`. Файли впорядковано у підкаталоги за першим символом назви або його шістнадцятковим кодом (наприклад, `/usr/share/terminfo/x/xterm-256color` або `/usr/share/terminfo/6c/linux`).

1. **Заголовок двійкового файлу terminfo (12 байтів):**
   Структура заголовка складається з шести 16-бітних цілих чисел у форматі Little-Endian:
   - `magic` (2 байти): Магічне число формату. Значення `0432` (`0x011A` у вісімковій системі `0432`) позначає класичний 16-бітний terminfo; значення `01036` (`0x021E`) позначає розширений 32-бітний формат terminfo v2.
   - `name_size` (2 байти): Розмір секції імен термінала в байтах (рядок синонімів, розділених символом `|`, із завершальним `\0`).
   - `bool_count` (2 байти): Кількість булевих прапорців (Boolean Section).
   - `num_count` (2 байти): Кількість числових констант (Numbers Section).
   - `str_count` (2 байти): Кількість зміщень у таблиці рядків (Offsets Section).
   - `str_size` (2 байти): Загальний розмір таблиці рядкових escape-послідовностей (String Table) у байтах.

2. **Секції даних після заголовка:**
   - **Boolean Section:** Масив байтів довжиною `bool_count`. Значення `1` означає наявність можливості (наприклад, `am` — автоматичний перенос рядків, `bce` — очищення екрана кольором фону), `0` — відсутність.
   - **Numbers Section:** Масив 16-бітних (або 32-бітних) чисел зі знаком. Значення `-1` (`0xFFFF`) позначає відсутність можливості; `-2` — скасовану можливість. Тут зберігаються параметри `cols` (стовпчики), `lines` (рядки), `colors` (максимальна кількість кольорів).
   - **Offsets & String Table:** Таблиця 16-бітних індексів, що вказують на позиції рядків у пам'яті String Table. Кожен рядок завершується нульовим байтом `\0` і містить параметризовану керуючу послідовність.
   - **Extended Header:** Якщо база містить нестандартні користувацькі розширення (наприклад, прапорці TrueColor `Tc`, `RGB` або розширені підкреслення `Smulx`), заголовок дублюється для секції розширених можливостей.

### Програмний C-інтерфейс terminfo (setupterm, tigetstr, tparm, tputs)

Низькорівнева бібліотека `<term.h>` надає інтерфейс прямого доступу до бази `terminfo` без накладних витрат віконного менеджера curses:

```c
#include <curses.h>
#include <term.h>

int errret;
/* 1. Ініціалізація структури TERMINAL *cur_term за дескриптором stdout */
if (setupterm(NULL, STDOUT_FILENO, &errret) != OK) {
    /* errret: 1 = знайдено, 0 = не знайдено, -1 = база terminfo відсутня */
}

/* 2. Зчитування булевих, числових та рядкових можливостей */
int has_auto_margins = tigetflag("am");
int max_colors       = tigetnum("colors");
char *enter_alt_scr  = tigetstr("smcup"); /* \033[?1049h */
char *exit_alt_scr   = tigetstr("rmcup"); /* \033[?1049l */
char *hide_cursor    = tigetstr("civis"); /* \033[?25l */
char *show_cursor    = tigetstr("cnorm"); /* \033[?25h */
char *cursor_pos     = tigetstr("cup");   /* \033[%i%p1%d;%p2%dH */
```

1. **Параметризація послідовностей через `tparm()`:**
   Функція `char *tparm(const char *cap, ...)` приймає рядок можливості та до 9 числових/рядкових параметрів, розгортаючи їх за допомогою внутрішнього стек-орієнтованого інтерпретатора керуючих кодів:
   - `%p1` .. `%p9`: Заштовхує у стек значення аргументу номер N.
   - `%d`: Виштовхує число зі стека і друкує його як десяткове.
   - `%i`: Інкрементує перші два параметри на 1 (трансляція 0-індексованих координат C у 1-індексовані координати ANSI).
   - *Приклад виклику:* `tparm(cursor_pos, 4, 9)` транслює шаблон `\033[%i%p1%d;%p2%dH` у рядок `\033[5;10H`.

2. **Вивід із розрахунком часових затримок через `tputs()`:**
   Функція `int tputs(const char *str, int affcnt, int (*putc_func)(int))` відправляє рядок на термінал через користувацьку функцію зворотного виклику `putc_func`:
   - Якщо escape-послідовність містить специфікатор затримки (наприклад, `$<50>` означає паузу 50 мс для механіки каретки), `tputs()` звіряє вихідну швидкість `ospeed` у `termios` і вставляє у вихідний потік точну кількість символів заповнення `NUL` або `DEL` (згідно з прапорцями `OFILL`/`OFDEL` у `c_oflag`) або виконує системний `usleep()`.

### Керування станом termios у бібліотеці ncurses

Бібліотека `ncurses` інкапсулює подвійний стан термінальної підсистеми для запобігання пошкодженню термінала при переходах між повноекранним графічним інтерфейсом та виконанням команд оболонки:

1. **Два еталонні стани:**
   - **Shell Mode:** Стан структури `termios`, який термінал мав у момент запуску програми (канонічний режим, активне відлуння `echo`, стандартні сигнали).
   - **Program Mode (Prog Mode):** Стан `termios`, оптимізований для TUI-інтерфейсу (неканонічний режим `cbreak()` або `raw()`, вимкнене відлуння `noecho()`, вимкнена нормалізація переведення рядків `nonl()`, перехоплення функціональних клавіш `keypad(stdscr, TRUE)`).

2. **Функції життєвого циклу termios у ncurses:**
   - `def_shell_mode()`: Зберігає поточний стан `termios` у внутрішній статичній структурі як еталонний Shell Mode.
   - `def_prog_mode()`: Фіксує поточний стан `termios` як еталонний Program Mode.
   - `reset_shell_mode()`: Відновлює Shell Mode (викликається перед запуском зовнішніх утиліт через `system()`, `fork()`/`execve()` або тимчасовим виходом в CLI).
   - `reset_prog_mode()`: Повторно застосовує Program Mode при поверненні в TUI після виконання зовнішньої команди.
   - `savetty()` та `resetty()`: Стек тимчасового збереження та відновлення налаштувань `termios` безпосередньо прикладним кодом.

### Компіляція, декомпіляція та аудит: утиліти infocmp і tic

Для інспекції, налагодження та розширення термінальних баз даних використовуються системні утиліти пакета `ncurses-bin`:

1. **Компілятор описів `tic` (Terminfo Compiler):**
   - Компілює текстовий файл визначення термінала у двійковий формат terminfo:
     ```bash
     # Компіляція з підтримкою нестандартних розширених прапорців (-x)
     tic -x -o ~/.terminfo custom-terminal.info
     ```
   - Прапорець `-x` є обов'язковим для збереження сучасних 24-бітних розширень TrueColor (`set_a_foreground`, `set_a_background`, `Tc`, `RGB`).

2. **Декомпілятор та компаратор `infocmp` (Terminfo Comparator & Decompiler):**
   - **Декомпіляція активного термінала у вихідний код:**
     ```bash
     infocmp $TERM
     ```
     Виводить повний перелік булевих, числових та рядкових можливостей термінала у текстовому форматі.
   - **Побітове порівняння двох термінальних описів:**
     ```bash
     infocmp -d xterm-256color alacritty
     ```
     Прапорець `-d` знаходить усі відмінності між двома базами (корисно для пошуку причин, чому комбінації клавіш чи кольори працюють в одному емуляторі, але ламаються в іншому).
   - **Експорт у формат termcap:**
     ```bash
     infocmp -C $TERM
     ```
     Транслює сучасний опис terminfo у застарілий формат `/etc/termcap` з дволітерними назвами полів для сумісності зі старим софтом.
   - **Генерація статичного C-коду (Embedded Terminfo):**
     ```bash
     infocmp -E xterm-256color
     ```
     Генерує C-структуру з масивом констант для прямого вбудовування термінального опису в бінарний файл без залежності від наявності файлів у `/usr/share/terminfo/`.

## Розширені протоколи сучасних емуляторів терміналів

Сучасні термінальні програми виходять далеко за межі базового стандарту VT100. Вони використовують розширені протоколи кодування кольорів, обробки взаємодії з мишею та безпечного введення тексту через буфер обміну.

### 24-бітний колір TrueColor та розширена колірна модель SGR

Колірна підсистема термінала еволюціонувала від базових 8/16 системних кольорів ANSI (`\033[30m`..`\033[37m`, `\033[90m`..`\033[97m`) до повноколірного 24-бітного прямого простору RGB (16.7 мільйонів кольорів).

1. **Індексована 256-колірна палітра xterm:**
   - Формат виклику: `\033[38;5;Nm` (передній план) та `\033[48;5;Nm` (фон), де `N ∈ [0, 255]`.
   - Карта розподілу індексів:
     - `0 .. 15`: Стандартні системні та яскраві кольори ANSI.
     - `16 .. 231`: Колірний куб 6x6x6. Розрахунок індексу: `Index = 16 + 36·R + 6·G + B`, де компоненти `R, G, B ∈ [0, 5]`. Відповідні рівні яскравості каналів у RGB: `[0, 95, 135, 175, 215, 255]`.
     - `232 .. 255`: Шкала сірого з 24 градацій (без чорного та білого). Розрахунок індексу: `Index = 232 + N`, де `N ∈ [0, 23]`. Рівень яскравості каналу: `Y = 8 + 10·N` (від `0x08` до `0xEE`).

2. **Прямий 24-бітний колір TrueColor (Direct RGB):**
   - **Специфікація SGR:**
     - Передній план (Foreground): `\033[38;2;R;G;Bm`
     - Фон (Background): `\033[48;2;R;G;Bm`
     - Колір лінії підкреслення (Underline Color, SGR 58): `\033[58;2;R;G;Bm` (скидання кольору лінії підкреслення: `\033[59m`).
     - Розширені стилі підкреслення (SGR 4): `\033[4:1m` (одинарне), `\033[4:2m` (подвійне), `\033[4:3m` (хвилясте / curly), `\033[4:4m` (пунктирне / dotted), `\033[4:5m` (штрихове / dashed), вимкнення `\033[4:0m` або `\033[24m`.
   - **Дилема розділювачів (Стандарт ITU T.416 проти сумісності де-факто):**
     - За стандартом ITU-T T.416 / ISO/IEC 8613-6 параметри кольору є субаргументами параметра 38/48 і повинні розділятися двокрапками: `CSI 38 : 2 : [ColorSpace] : R : G : B m`. Якщо колірний простір опущено, двокрапки ставляться поспіль: `\033[38:2::255:128:0m`.
     - Проте рання реалізація в утилітах та парсерах емуляторів закріпила використання крапки з комою: `\033[38;2;255;128;0m`. Сучасні рушії емуляції (`alacritty`, `kitty`, `wezterm`, `foot`, `iterm2`) підтримують обидва варіанти, проте код із двокрапками забезпечує коректну роботу вкладених атрибутів стилю.

3. **Механізми виявлення підтримки TrueColor:**
   - **Змінні середовища:** Застосунки перевіряють змінну `COLORTERM=truecolor` або `COLORTERM=24bit`.
   - **База terminfo:** Перевірка можливості `Tc` або наявності розширеного рядка `setaf`/`setab` із послідовністю `38;2;%p1%d;%p2%d;%p3%dm`.
   - **Термінальні запити можливостей:** Відправка послідовності `\033P+q544e\033\` (XTGETTCAP для capability `TN` / Terminal Name) або запит розширених атрибутів пристрою DA2 (`\033[>c`).

### Розширені протоколи відстеження подій миші (SGR-1006 Mouse Tracking)

Для реалізації повноцінного графічного інтерфейсу TUI (виділення тексту, навігація у файлових менеджерах, кліки у меню) термінал перехоплює події миші та транслює їх у вихідний потік PTY.

1. **Режими перехоплення подій:**
   - `\033[?9h` / `\033[?9l`: X10 Compatibility Mode — повідомляє лише про натискання лівої кнопки, без відпускання та модифікаторів.
   - `\033[?1000h` / `\033[?1000l`: VT200 Normal Tracking — повідомляє про натискання та відпускання кнопок.
   - `\033[?1002h` / `\033[?1002l`: Button-Event Tracking — фіксує натискання, відпускання та переміщення миші за затиснутої кнопки (Drag & Drop).
   - `\033[?1003h` / `\033[?1003l`: Any-Event Tracking — надсилає координати при будь-якому переміщенні миші (Hover), генеруючи інтенсивний потік даних.
   - `\033[?1004h` / `\033[?1004l`: Focus Tracking — надсилає `\033[I` при отриманні вікном фокусу та `\033[O` при втраті.

2. **Еволюція форматів кодування та протокол SGR-1006:**
   - **Застарілий формат Xterm (Normal):** Послідовність `\033[M Cb Cx Cy`, де `Cb = button + 32`, `Cx = col + 32`, `Cy = row + 32`.
     - *Критичне обмеження 223 стовпчиків:* Оскільки значення зберігається в одному байті (`0..255`), максимальна координата дорівнює `255 - 32 = 223`. Якщо вікно ширше ніж 223 стовпчики, координати переповнюються й генерують сміття.
     - *Конфлікт із UTF-8:* Байти координат у діапазоні `128..255` руйнують вхідний UTF-8 парсер ядра (`IUTF8`).
   - **Протокол розширеного режиму SGR (SGR-1006, `\033[?1006h`):** Сучасний стандарт, що усуває обмеження координат шляхом передачі десяткових чисел:
     - Формат події натискання / переміщення: `\033[<Btn;Px;Py;M`
     - Формат події відпускання кнопки: `\033[<Btn;Px;Py;m`
     - `Px` та `Py`: 1-індексовані десяткові координати стовпчика та рядка довільної величини.

3. **Розкодування бітового поля `Btn` у протоколі SGR-1006:**
   - **Біти 0..1 (Код кнопки):** `0` = Ліва кнопка, `1` = Середня (колесо), `2` = Права кнопка.
   - **Біт 2 (`+4`):** Затиснуто клавішу `Shift`.
   - **Біт 3 (`+8`):** Затиснуто клавішу `Meta` / `Alt`.
   - **Біт 4 (`+16`):** Затиснуто клавішу `Ctrl`.
   - **Біт 5 (`+32`):** Подія переміщення миші (Mouse Motion / Drag).
   - **Біти 6..7:** Події колеса прокрутки та розширених кнопок:
     - `64`: Прокрутка колеса вгору (Wheel Up).
     - `65`: Прокрутка колеса вниз (Wheel Down).
     - `66`: Горизонтальна прокрутка вліво (Tilt Left).
     - `67`: Горизонтальна прокрутка вправо (Tilt Right).
     - `128 .. 131`: Додаткові апаратні кнопки миші (Button 8..11).

### Протокол безпечної вставки тексту (Bracketed Paste Mode)

1. **Захист від атак підміни вводу (Pastejacking):**
   - Якщо користувач копіює текст із вебсторінки або журналу, зловмисний фрагмент може містити невидимі символи переведення рядка `\n` або `\r` (наприклад, рядок вигляду `rm -rf / \n`).
   - У стандартному режимі командна оболонка (`bash`, `zsh`) сприймає кожен байт `\n` як негайну команду завершення вводу й виконує системний виклик `execve()` до того, як людина встигне перевірити вміст буфера обміну.

2. **Специфікація режиму Bracketed Paste (`\033[?2004h`):**
   - Увімкнення режиму: `\033[?2004h`
   - Вимкнення режиму: `\033[?2004l`
   - Коли режим активний, графічний емулятор термінала при вставці з буфера обміну огортає вставлений блок байтів спеціальними маркерами:
     - Префікс початку вставки: `\033[200~` (`0x1B 0x5B 0x32 0x30 0x30 0x7E`)
     - Суфікс кінця вставки: `\033[201~` (`0x1B 0x5B 0x32 0x30 0x31 0x7E`)

3. **Поведінка застосунків та дефект завислого стану:**
   - Редактори рядків (`readline`, `zsh-line-editor`, `neovim`) при отриманні маркера `\033[200~` тимчасово блокують автоматичне виконання команд. Усі внутрішні символи `\n` та `\r` трактуються як літеральний текст або замінюються візуальними відступами. Текст виконується лише після того, як користувач перегляне його та натисне клавішу Enter.
   - Якщо застосунок увімкнув `\033[?2004h` і впав без відновлення режиму, будь-яка спроба вставити текст у термінал призводить до того, що оболонка друкує символи `^[[200~` перед вставленим рядком і `^[[201~` після нього. Для лікування відправляють послідовність вимкнення: `printf '\033[?2004l'`.

## Синхронізація кадрів та термінальні графічні протоколи

Сучасний графічний вивід у терміналах вимагає координації частоти кадрів для запобігання розривам зображення (tearing) та спеціалізованих протоколів передачі піксельних растрових даних безпосередньо у відеопам'ять.

### Синхронне оновлення термінала та атомарний рендеринг (Synchronous Output Mode 2026)

Складні інтерфейси TUI (`neovim`, `btop`, `lazygit`) оновлюють десятки фрагментів екрана за один кадр, генеруючи велику кількість послідовностей переміщення курсора `\033[y;xH` та SGR кольорів.

1. **Проблема розриву кадру (Tearing та Flicker):**
   - Вихідний потік розбивається на окремі пакети через буферизацію каналу TCP/SSH або 4096-байтні чанки псевдотермінала `/dev/ptmx`.
   - Емулятор термінала вичитує неповний блок даних і виконує проміжний рендеринг частини вікна. Користувач бачить візуальне мерехтіння або каскадний розрив тексту на межах блоків.

2. **Специфікація DEC Private Mode 2026:**
   - **Початок атомарного блоку (Begin Synchronized Update):** `\033[?2026h`
     Емулятор термінала повністю призупиняє перемальовування видимого вікна. Усі наступні операції виводу направляються у внутрішній тіньовий буфер (off-screen backbuffer).
   - **Кінець атомарного блоку (End Synchronized Update):** `\033[?2026l`
     Емулятор виконує атомарну підміну буферів (Blit / Swap Buffers) і синхронізує відображення з кадровою розгорткою монітора (VSync, 60/120 Гц).

3. **Захисний тайм-аут (Guard Timeout):**
   - Якщо програма зависла або загинула всередині блоку між `2026h` та `2026l`, екран термінала залишився б заблокованим назавжди.
   - Емулятори реалізують апаратний/програмний таймер безпеки тривалістю від 100 до 500 мс. Якщо за цей час не надходить закриваючий код `\033[?2026l`, режим автоматично скидається, а накопичений буфер негайно відображається.

4. **Запит підтримки (Mode Query):**
   - Запит стану: `\033[?2026$p` (DECRQM).
   - Відповідь емулятора (DECRPM): `\033[?2026;1$y` (режим активний), `\033[?2026;2$y` (режим скинуто / підтримується), `\033[?2026;0$y` (не підтримується).

### Протокол растрової графіки Sixel (DEC VT240/VT330)

Протокол Sixel розроблено корпорацією DEC для виводу графіки на термінали серій VT240/VT330 та матричні принтери.

1. **Формат керуючої послідовності:**
   - Початок послідовності DCS (Device Control String): `\033P [p1;p2;p3] q [sixel-data] \033\`
   - `p1`: Співвідношення сторін пікселя (Pixel Aspect Ratio), типово `7` або `9`.
   - `p2`: Режим очищення фону (`0` або `1` — очистити фон поточним кольором, `2` — зберегти прозорий фон).
   - `p3`: Горизонтальний крок сітки.
   - Завершувач рядка керування (ST — String Terminator): `\033\` (HEX `0x1B 0x5C` або байт `0x9C`).

2. **Кодування пікселів у смугах Sixel:**
   - Базовою одиницею є вертикальний стовпчик шириною 1 піксель і висотою 6 пікселів (Six Pixels = Sixel).
   - Кожен стовпчик кодується одним друкованим ASCII-символом у діапазоні від `?` (`0x3F` / 63) до `~` (`0x7E` / 126).
   - Значення символу обчислюється додаванням зміщення `0x3F` до 6-бітної бітової маски пікселів:
     - Біт 0 (`вага 1`): Верхній піксель стовпчика.
     - Біт 1 (`вага 2`): Другий піксель зверху.
     - Біт 2 (`вага 4`): Третій піксель зверху.
     - Біт 3 (`вага 8`): Четвертий піксель зверху.
     - Біт 4 (`вага 16`): П'ятий піксель зверху.
     - Біт 5 (`вага 32`): Нижній (шостий) піксель стовпчика.
     - Підсумковий код: `Char = 0x3F + Bitmask`. Наприклад, код `?` (`0x3F + 0`) означає 6 порожніх пікселів; код `~` (`0x3F + 63`) означає 6 суцільних зафарбованих пікселів.

3. **Службові оператори керування:**
   - `#P`: Вибір активного слота палітри (індекс `P ∈ [0, 255]`).
   - `#P;2;R;G;B`: Визначення кольору слота `P` у системі RGB (значення каналів у відсотках `0..100` або шкалі `0..255`).
   - `$`: Повернення каретки (CR) — повертає позицію малювання в початок поточної 6-піксельної смуги для накладання точок іншого кольору.
   - `-`: Переведення рядка (LF) — переміщує активну позицію на 6 пікселів вниз на нову графічну смугу.
   - `!count!char`: Стиснення RLE (Run-Length Encoding) — повторює стовпчик `char` кількість разів `count` (наприклад, `!80~` малює суцільну лінію шириною 80 пікселів).

### Високопродуктивний протокол прямої графіки Kitty (KGP)

Протокол Kitty Graphics Protocol базується на керівних послідовностях APC (Application Program Command) і спроєктований для передачі повноколірних 24/32-бітних растрових зображень з апаратним прискоренням на GPU.

1. **Формат керівної команди APC:**
   `\033_G [control-keys] ; [payload] \033\`

2. **Словник параметрів керування (`control-keys` у форматі `ключ=значення,ключ=значення`):**
   - `a` (Дія / Action):
     - `a=t`: Передати та відобразити зображення (Transmit & Display, типове значення).
     - `a=T`: Передати, відобразити та зберегти в кеші пам'яті емулятора.
     - `a=p`: Розмістити раніше збережене зображення за його ідентифікатором `i`.
     - `a=d`: Видалити зображення з пам'яті емулятора (за `i`, координатами чи всі).
     - `a=q`: Запитати статус підтримки протоколу.
   - `f` (Формат піксельних даних):
     - `f=24`: 24-бітний прямий RGB (3 байти на піксель).
     - `f=32`: 32-бітний RGBA (4 байти на піксель з альфа-каналом прозорості).
     - `f=100`: Стиснений двійковий потік формату PNG (емулятор самостійно декомпресує зображення).
   - `s` та `v` (Розміри в пікселях): `s=width`, `v=height`.
   - `i` (Ідентифікатор зображення): Унікальне 32-бітне число `image_id` для подальшого перевикористання без повторної передачі байтів через PTY.
   - `p` (Ідентифікатор розміщення): `placement_id` для керування декількома екземплярами одного зображення.
   - `m` (Пакетна передача / Chunking):
     - `m=1`: Дані не завершено, наступний чанк передається в наступному APC-пакеті (дозволяє передавати масивні текстури блоками по 4096 байтів).
     - `m=0`: Фінальний блок передачі.
   - `t` (Канал передачі / Transmission Medium):
     - `t=d`: Пряме корисне навантаження в Base64 у тілі команди.
     - `t=f`: Звичайний файл на диску (емулятор читає файл напряму).
     - `t=t`: Тимчасовий файл (емулятор зчитує файл і автоматично видаляє його).
     - `t=s`: Розділювана пам'ять POSIX Shared Memory (`shm_open()` + `mmap()`). Забезпечує нульовий оверхед копіювання (Zero-Copy) при трансляції високочастотного відеопотоку 60 FPS.
   - `c` та `r` (Геометрія в сітці): Ширина `c` та висота `r` у символьних клітинках.
   - `X` та `Y` (Субпіксельне зміщення): Зсув усередині першої комірки в пікселях.
   - `z` (Z-індекс шару): `z < 0` — зображення рендериться під текстом (фоновий шар), `z >= 0` — зображення перекриває символи тексту.

### Протокол вбудованих зображень iTerm2 (OSC 1337)

Протокол iTerm2 передає растрові файли (PNG, JPEG, GIF) через escape-послідовності OSC (Operating System Command).

1. **Специфікація послідовності:**
   `\033]1337;File=[arguments]:[base64-data]\007` (або завершувач ST `\033\`).

2. **Параметри аргументів (`arguments` через крапку з комою `;`):**
   - `inline=1`: Відобразити зображення безпосередньо у поточному місці курсора. Якщо `inline=0`, файл завантажується як вкладення без малювання.
   - `name=<base64-string>`: Закодоване у Base64 ім'я файлу (для збереження користувачем).
   - `size=<bytes>`: Точний розмір файлу в байтах.
   - `width=<value>` та `height=<value>`:
     - `auto`: Автоматичний розмір згідно з оригінальною роздільною здатністю файлу.
     - `N`: Фіксована ширина/висота у символьних знакомісцях.
     - `Npx`: Точний розмір у пікселях екрана.
     - `N%`: Відсоток від поточної ширини або висоти вікна термінала.
   - `preserveAspectRatio=1` (або `0`): Збереження вихідних пропорцій сторін при примусовому масштабуванні.

## Діагностика, низькорівневе трасування та інструменти аудиту termios

Для виявлення причин руйнування термінального сеансу, відстеження системних викликів `ioctl` та інспекції стану `termios` у працюючих процесах застосовуються системні інструменти Linux: `strace`, віртуальна файлова система `/proc` та відлагоджувач `gdb`.

### Трасування системних викликів ioctl через strace

Утиліта `strace` дозволяє перехоплювати всі термінальні керуючі запити між простором користувача та ядром.

1. **Команди запуску аудиту:**
   - Трасування ioctl активного процесу за його PID:
     ```bash
     strace -e trace=ioctl -p <PID>
     ```
   - Детальне розгортання структур termios із часовими мітками:
     ```bash
     strace -v -s 256 -T -tt -e trace=ioctl <команда>
     ```

2. **Інтерпретація виводу системних викликів:**
   - **Читання стану (TCGETS):**
     ```
     ioctl(0, TCGETS, {c_iflags=0x4500, c_oflags=0x5, c_cflags=0xbf, c_lflags=0x8a3b, c_line=0, c_cc="\x03\x1c\x7f\x15\x04..."}) = 0
     ```
     У виводі фіксуються поточні числові маски прапорців:
     - `c_lflags & 0x0008` — стан `ECHO` (якщо відсутній біт 3, термінал «сліпий»).
     - `c_lflags & 0x0002` — стан `ICANON` (якщо відсутній біт 1, вимкнено буферизацію рядків).
     - `c_oflags & 0x0004` — стан `ONLCR` (якщо відсутній біт 2, виникає «ефект сходів»).
     - `c_iflags & 0x0100` — стан `ICRNL` (якщо відсутній біт 8, блокується клавіша Enter).
   - **Запис конфігурації (TCSETSW / TCSETSF):**
     ```
     ioctl(0, TCSETSW, {B38400 -opost -isig -icanon -echo ...}) = 0
     ```
   - **Діагностика дедлоку виклику `TCSETSW`:**
     Якщо процес блокується на виклику `ioctl(0, TCSETSW, ...)` і не повертає керування, це означає, що термінал перебуває у стані призупиненого виводу XOFF (`Ctrl+S`) або вихідна черга не вичитується емулятором через переповнення буфера PTY.
   - **Зчитування геометрії вікна:**
     ```
     ioctl(1, TIOCGWINSZ, {ws_row=45, ws_col=172, ws_xpixel=0, ws_ypixel=0}) = 0
     ```

### Інспекція дескрипторів та структури termios через віртуальну файлову систему /proc

Файлова система `/proc` надає прямий доступ до інформації ядра про файлові дескриптори, сесії та контрольні термінали процесів.

1. **Перевірка відкритих дескрипторів процесу:**
   ```bash
   $ ls -l /proc/<PID>/fd/
   lrwx------ 1 user user 64 Aug 29 12:00 0 -> /dev/pts/4
   lrwx------ 1 user user 64 Aug 29 12:00 1 -> /dev/pts/4
   lrwx------ 1 user user 64 Aug 29 12:00 2 -> /dev/pts/4
   ```
   Символьне посилання вказує на точний файл псевдотермінала `/dev/pts/N`, до якого підключено процес.

2. **Перевірка файлових статусів та блокувань у `/proc/<PID>/fdinfo/<FD>`:**
   ```bash
   $ cat /proc/<PID>/fdinfo/0
   pos:    0
   flags:  0100002
   mnt_id: 25
   ino:    7
   ```
   Поле `flags` кодує вісімкову маску прапорців відкриття файлу (`O_RDWR = 02`, `O_NONBLOCK = 04000`). Якщо встановлено біт `O_NONBLOCK`, системний виклик `read()` повертає помилку `EAGAIN` замість блокування за правилами `VMIN`/`VTIME`.

3. **Декодування контрольного термінала з `/proc/<PID>/stat`:**
   Файл `/proc/<PID>/stat` містить параметри процесу в одному рядку:
   - **Поле 7 (`tty_nr`):** Десятковий номер пристрою керівного термінала (controlling TTY `dev_t`).
     - *Формула розкодування `tty_nr` у номери Major та Minor ядра Linux:*
       ```
       Major = (tty_nr >> 8) & 0xFF;
       Minor = (tty_nr & 0xFF) | ((tty_nr >> 12) & 0xFFF00);
       ```
       Для пристроїв `/dev/pts/N` номер `Major` дорівнює `136`, а `Minor` точно дорівнює номеру `N`. Якщо значення `tty_nr == 0`, процес повністю від'єднано від керівного термінала (фоновий демон).
   - **Поле 8 (`tpgid`):** Ідентифікатор групи процесів переднього плану (Foreground Process Group ID). Якщо `tpgid != getpgrp()`, процес є фоновим і спроба читання з термінала призведе до надсилання сигналу `SIGTTIN`.

4. **Системні лічильники драйверів ядра:**
   - `/proc/tty/ldiscs`: Перелік зареєстрованих у ядрі лінійних дисциплін (`0 = N_TTY`, `1 = SLIP`, `2 = MOUSE`, `3 = PPP`).
   - `/proc/tty/driver/serial`: Апаратна статистика послідовних портів UART: лічильники переданих (`tx`) та прийнятих (`rx`) байтів, лічильники апаратних помилок кадрування (`fe`), помилок парності (`pe`), переповнення буфера FIFO (`oe`), а також стан ліній CTS, DSR, CD, RTS.

### Низькорівневий аудит та відновлення termios у живому процесі через gdb

Якщо консольний застосунок завис у сирому режимі або залишив термінал зламаним, відлагоджувач `gdb` дозволяє приєднатися до процесу на льоту, проінспектувати поля `termios` та викликати системні функції відновлення без перезапуску програми.

1. **Приєднання до процесу:**
   ```bash
   $ gdb -p <PID>
   ```

2. **Зчитування поточної структури termios через стек процесу:**
   Оскільки відлагоджувач може викликати системні функції у контексті цільового процесу, виділяється тимчасовий буфер на вершині стека (`$sp - 128`):
   ```gdb
   (gdb) call (int)tcgetattr(0, (struct termios*)($sp - 128))
   (gdb) set $t = (struct termios*)($sp - 128)
   (gdb) print *$t
   (gdb) print/x $t->c_iflag
   (gdb) print/x $t->c_oflag
   (gdb) print/x $t->c_cflag
   (gdb) print/x $t->c_lflag
   (gdb) print (char)$t->c_cc[0]@32
   ```

3. **Аналіз пошкоджених бітових масок:**
   - Перевірка відлуння: `print/x ($t->c_lflag & 0x0008)` (якщо `0x0`, прапорець `ECHO` вимкнено).
   - Перевірка канонічного вводу: `print/x ($t->c_lflag & 0x0002)` (якщо `0x0`, прапорець `ICANON` вимкнено).
   - Перевірка переведення рядків: `print/x ($t->c_oflag & 0x0004)` (якщо `0x0`, прапорець `ONLCR` вимкнено).

4. **Модифікація та відновлення стану termios на льоту:**
   ```gdb
   # 1. Відновлення локальних прапорців (ICANON | ECHO | ECHOE | ECHOK | ISIG):
   (gdb) set $t->c_lflag |= 0x003B

   # 2. Відновлення вихідної нормалізації (OPOST | ONLCR):
   (gdb) set $t->c_oflag |= 0x0005

   # 3. Відновлення нормалізації входу Enter (ICRNL | BRKINT):
   (gdb) set $t->c_iflag |= 0x0102

   # 4. Застосування модифікованої структури негайно (TCSANOW = 0):
   (gdb) call (int)tcsetattr(0, 0, $t)

   # 5. Скидання графічних режимів емулятора (показ курсора, скидання кольорів, SGR-1006, Mode 2026):
   (gdb) call (int)write(1, "\033[?25h\033[0m\033(B\017\033[?2004l\033[?1000l\033[?1006l\033[?2026l", 45)

   # 6. Від'єднання від процесу:
   (gdb) detach
   (gdb) quit
   ```

Після виконання цих команд процес поновлює виконання, а керівний термінал миттєво повертається до повністю функціонального та безпечного канонічного стану.
