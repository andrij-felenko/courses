# ⚙️ Надійний менеджер сирого режиму TTY: обробка сигналів, Job Control та RAII

Будь-яка консольна програма, що перемикає термінал у сирий режим (raw mode) для посимвольного вводу або побудови інтерфейсу TUI, бере на себе повну відповідальність за стан системної дисципліни лінії та внутрішніх регістрів емулятора. Якщо процес завершиться аварійно, буде перерваний асинхронним сигналом або тимчасово призупинений користувачем через комбінацію `Ctrl+Z`, термінал залишиться у спотвореному стані для батьківської оболонки.

Коли повнотекстовий редактор (`vim`, `nano`), утиліта перегляду журналів (`less`), інтерактивний відлагоджувач (`gdb`) або власна TUI-програма конфігурує термінал під посимвольне опрацювання введення, вона модифікує два незалежні рівні системи: структуру `termios` у пам'яті ядра та стан кінцевого автомата емулятора термінала. Якщо процес завершується штатно, він повертає вихідні налаштування. Проте у разі аварійного сигналу (`SIGINT`, `SIGTERM`, `SIGSEGV`), примусового закриття сесії (`SIGHUP`) чи переведення у фоновий режим комбінацією `Ctrl+Z` (`SIGTSTP`), операційна система звільняє ресурси процесу, але не торкається стану лінії, залишаючи користувача зі «зламаним терміналом».

Нижче наведено повний інженерний аналіз підсистем термінала, механізми захисту від руйнування стану, протокол апаратно-програмної реанімації та готові виробничі реалізації мовами C та C++.

## Подвійний контур руйнування стану: ядро та емулятор

Термінальний сеанс Unix складається з двох автономних підсистем зі збереженням стану. Руйнування будь-якої з них робить взаємодію з командною оболонкою неможливою:

```
[ Користувач / Клавіатура ]
            │
            ▼
┌────────────────────────────────────────────────────────┐
│ 1. Контур ядра: Лінійна дисципліна N_TTY (struct termios)│
│    • c_iflag : ICRNL, IXON, BRKINT, IUTF8              │
│    • c_oflag : OPOST, ONLCR (запобігання сходам)        │
│    • c_lflag : ICANON, ECHO, ECHOE, ECHOK, ISIG, IEXTEN│
│    • c_cc    : VMIN, VTIME, VERASE, VKILL, VINTR       │
└────────────────────────────────────────────────────────┘
            │
            ▼
┌────────────────────────────────────────────────────────┐
│ 2. Контур емулятора: Кінцевий автомат DEC VT100 / ANSI │
│    • Екранні буфери: Main Buffer vs Alternate Screen   │
│    • Курсор: DECTCEM (видимість \033[?25h/l), позиція  │
│    • Таблиці символів: G0/G1 Charset (US-ASCII vs DEC) │
│    • Графічні атрибути: SGR (кольори, жирність, інверс)│
│    • Розширені режими: Mouse Tracking, Bracketed Paste │
└────────────────────────────────────────────────────────┘
```

### Контур 1: Лінійна дисципліна ядра (struct termios)

Ядро Linux зберігає параметри псевдотермінала у внутрішній структурі `struct tty_struct`, яка закріплена за пристроєм `/dev/pts/N`. Коли програма викликає функцію `cfmakeraw()` або вручну модифікує бітові маски `termios`, вона змінює поведінку підсистеми `N_TTY`:

1. **Локальні режими (`c_lflag`):**
   - `ICANON` (канонічний режим): ядро збирає байти у внутрішньому буфері до отримання символу переведення рядка `\n`. Натискання клавіші забою (`VERASE`, Backspace) видаляє попередній символ із буфера. Якщо `ICANON` вимкнено, кожен байт негайно передається процесу у системному виклику `read()`, а Backspace сприймається як звичайний символ `0x7F` або `0x08`.
   - `ECHO` (локальне відлуння): ядро автоматично копіює введені символи у вихідну чергу термінала. Без `ECHO` настає синдром «сліпого термінала» — клавіші натискаються, але екран залишається порожнім.
   - `ECHOE` (візуальне стирання): змушує драйвер при отриманні символу `ERASE` надсилати послідовність «забій-пробіл-забій» (`\b \b`), фізично очищаючи символ на моніторі.
   - `ECHOK` та `ECHOKE`: очищають увесь введений рядок при натисканні комбінації `Ctrl+U` (`VKILL`).
   - `ISIG` (генерація сигналів): ядро перехоплює байти `0x03` (`Ctrl+C`), `0x1C` (`Ctrl+\`) та `0x1A` (`Ctrl+Z`) і генерує відповідні сигнали `SIGINT`, `SIGQUIT` та `SIGTSTP`. Якщо `ISIG` знято, ці байти проходять як сирі дані, позбавляючи користувача можливості зупинити процес з клавіатури.
   - `IEXTEN` (розширене введення): вмикає обробку комбінацій на кшталт `Ctrl+V` (літеральне введення наступного символу) та `Ctrl+W` (видалення слова).

2. **Вхідні режими (`c_iflag`):**
   - `ICRNL`: автоматично перетворює вхідний байт повернення каретки `\r` (`0x0D`, клавіша Enter) на переведення рядка `\n` (`0x0A`). Без цього прапорця командні оболонки не розпізнають натискання Enter, оскільки чекають на символ `\n`.
   - `IXON`: вмикає програмне керування потоком (Software Flow Control). Байт `0x13` (`Ctrl+S`, `XOFF`) блокує передачу виводу, а `0x11` (`Ctrl+Q`, `XON`) поновлює її.
   - `BRKINT`: генерує сигнал `SIGINT` при фіксації стану апаратного розриву зв'язку (BREAK).
   - `ISTRIP`: обрізає 8-й біт кожного вхідного байта, що руйнує кодування UTF-8.
   - `IUTF8` (Linux): інформує драйвер про межі багатобайтових символів UTF-8, дозволяючи коректно стирати кириличні літери та символи змінної довжини одним натисканням Backspace.

3. **Вихідні режими (`c_oflag`):**
   - `OPOST`: головний перемикач вихідної обробки. Якщо його знято, байти виводу надсилаються на пристрій без модифікацій.
   - `ONLCR`: перетворює кожен вихідний символ `\n` (`0x0A`) на пару `\r\n` (`0x0D 0x0A`). Відсутність `ONLCR` породжує класичний «ефект сходів» (Staircase Effect), коли кожен наступний рядок починається у позиції завершення попереднього.

4. **Керівні символи (`c_cc`):**
   - `VMIN` та `VTIME`: у неканонічному режимі задають правила повернення системного виклику `read()`. Значення `VMIN = 1, VTIME = 0` вказує ядру блокувати виклик доти, доки не буде прочитано щонайменше 1 байт.

### Контур 2: Кінцевий автомат емулятора (DEC VT100 / ANSI)

Емулятор термінала (`xterm`, `alacritty`, `kitty`, `tmux`) функціонує як незалежний процес, що зчитує вихідний потік байтів і змінює внутрішні графічні регістри:

1. **Альтернативний екранний буфер (Alternate Screen Buffer):** Повноекранні програми надсилають послідовність `\033[?1049h` для перемикання на чистий буфер без історії прокрутки. Якщо процес вмирає без відправки `\033[?1049l`, користувач залишається у відрізаному буфері, де не працює стандартна прокрутка термінала.
2. **Видимість курсора (DECTCEM):** Щоб уникнути мерехтіння під час перемальовування інтерфейсу, TUI надсилає `\033[?25l` (приховати курсор). При аварії курсор залишається невидимим.
3. **Таблиці кодування символів (Alternate Character Set):** Коли двійковий потік (наприклад, результат `cat /bin/bash`) містить керівний символ `0x0E` (`SO`, Shift-Out) або послідовність `\033(0`, емулятор вмикає набір псевдографіки DEC VT100, замінюючи всі латинські літери рамками та кутиками. Повернення до стандарту вимагає символу `0x0F` (`SI`, Shift-In) та скидання таблиць G0/G1 через `\033(B\033)B`.
4. **Режими взаємодії з мишею та клавіатурою:** TUI-бібліотеки вмикають розширене відстеження координат миші (`\033[?1000h`, `\033[?1002h`, `\033[?1006h`) та режим обрамленої вставки (Bracketed Paste Mode `\033[?2004h`). Якщо ці режими не вимкнути, будь-який рух мишею чи вставка тексту генеруватимуть у командний рядок сміттєві послідовності вигляду `^[[<0;45;12M` або `\033[200~`.

## Механіка відновлення termios: робота з системними викликами

Процедура взаємодії з драйвером TTY вимагає точного дотримання послідовності викликів стандарту POSIX:

```
                  ┌──────────────────────┐
                  │ tcgetattr(fd, &orig) │ ──► Збереження вихідного стану
                  └──────────┬───────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
┌─────────────────────────┐       ┌─────────────────────────┐
│ Вхід у сирий режим:     │       │ Аварійне скидання:      │
│ cfmakeraw(&raw)         │       │ tcsetattr(fd, TCSANOW,  │
│ tcsetattr(fd,TCSAFLUSH, │       │           &orig)        │
│           &raw)         │       │ [Негайно, без очікування│
│ [Скидає непрочитане]    │       │  спустошення черги]     │
└─────────────────────────┘       └─────────────────────────┘
```

### Вибір режиму оновлення: TCSANOW проти TCSAFLUSH

Стандарт POSIX визначає три режими застосування структури `termios` у функції `tcsetattr(int fd, int optional_actions, const struct termios *termios_p)`:

- `TCSANOW`: зміни набувають чинності негайно. Цей режим є єдино правильним вибором для сигнальних обробників аварійного виходу (`SIGINT`, `SIGTERM`, `SIGQUIT`). Якщо вивід термінала було призупинено комбінацією `Ctrl+S` (`IXON`), черга передачі ніколи не спустошиться сама по собі. Використання будь-якого іншого режиму призведе до мертвого блокування процесу всередині обробника.
- `TCSADRAIN`: зміни застосовуються після того, як усі раніше записані у дескриптор виводу байти будуть фізично передані пристрою. Використовується для плавної зміни параметрів виводу без втрати даних.
- `TCSAFLUSH`: ядро очікує передачі записаного виводу, після чого повністю очищає та відкидає всі непрочитані байти з черги вхідних символів клавіатури. Цей режим застосовується під час перемикання у сирий режим, щоб відкинути символи, випадково набрані користувачем до старту TUI-рушія.

### Реконструкція безпечного стану з нуля (Sane Synthesis)

Якщо програма перехоплює керування у терміналі, стан якого вже було пошкоджено попереднім аварійним процесом (або якщо збережена структура `g_orig_termios` виявилася некоректною), менеджер термінала синтезує канонічну структуру `sane` з нуля за такими параметрами:

- **Маска вводу `c_iflag`:** встановлюються прапорці `ICRNL | IXON | BRKINT | IMAXBEL | IUTF8`. Вони забезпечують нормалізацію клавіші Enter, програмне керування потоком, сигнал переривання при обриві лінії, звуковий сигнал переповнення черги та облік багатобайтових меж UTF-8.
- **Маска виводу `c_oflag`:** встановлюються прапорці `OPOST | ONLCR`, що гарантує розширення символу переведення рядка `\n` до повної пари повернення каретки та переведення рядка `\r\n`.
- **Маска керування лінією `c_cflag`:** встановлюються прапорці `CS8 | CREAD | CLOCAL`, які задають 8-бітний розмір символу, активують прийом вхідних даних та переводять лінію в локальний режим без очікування модемних сигналів.
- **Маска локальних режимів `c_lflag`:** встановлюються прапорці `ICANON | ECHO | ECHOE | ECHOK | ECHOCTL | ECHOKE | ISIG | IEXTEN`. Вони повертають рядкову буферизацію, відлуння символів, візуальний забій, очищення рядка комбінацією `Ctrl+U`, сигнальні клавіші та розширені модифікатори.
- **Керівні символи масиву `c_cc`:** заповнюються стандартні коди ASCII: `VINTR = 0x03` (`Ctrl+C`), `VQUIT = 0x1C` (`Ctrl+\`), `VERASE = 0x7F` (`DEL` / Backspace), `VKILL = 0x15` (`Ctrl+U`), `VEOF = 0x04` (`Ctrl+D`), `VSTART = 0x11` (`Ctrl+Q`), `VSTOP = 0x13` (`Ctrl+S`), `VSUSP = 0x1A` (`Ctrl+Z`).

## Реанімаційний пакет послідовностей ANSI/VT100

Для ліквідації наслідків аварії у контурі емулятора термінала менеджер зобов'язаний надіслати до стандартного виводу концентрований реанімаційний пакет керівних послідовностей.

| Послідовність | Назва стандарту | Інженерне призначення |
|---|---|---|
| `\033[?1049l` | Alternate Screen Disable | Повертає термінал на головний екранний буфер з відновленням історії прокрутки. |
| `\033[?25h` | DECTCEM Cursor Enable | Робить курсор видимим для користувача. |
| `\033[0m` | SGR Reset | Скидає всі атрибути тексту: жирність, підкреслення, інверсію кольорів та кастомні палітри. |
| `\033(B\033)B` | G0/G1 US-ASCII Select | Прив'язує таблиці кодування G0 та G1 до стандартної латиниці US-ASCII. |
| `\017` (`0x0F`) | Shift-In (SI) | Перемикає активний набір символів на таблицю G0, нейтралізуючи ефект `cat binary`. |
| `\033[?1000l\033[?1002l\033[?1006l` | Disable Mouse Tracking | Вимикає передачу подій переміщення та кліків миші у вхідний потік. |
| `\033[?2004l` | Disable Bracketed Paste | Вимикає обрамлення вставленого тексту службовими префіксами. |
| `\033[?1l` | DECCKM Cursor Keys Normal | Перемикає клавіші стрілок із режиму застосунку (Application Mode) у стандартний режим ANSI. |
| `\033[r` | DECSTBM Margin Reset | Скидає обмеження вертикальних меж прокрутки на повну висоту вікна. |
| `\033[!p` | DECSTR Soft Terminal Reset | Виконує м'який апаратний ресет внутрішніх регістрів емулятора без очищення екрана. |

Об'єднаний реанімаційний рядок записується прямо у дескриптор `STDOUT_FILENO` через небуферизований системний виклик `write()`, уникаючи буферизації користувацького простору та блокувань бібліотеки введення-виведення.

## Архітектура обробки сигналів та Job Control

Керування життєвим циклом консольної програми вимагає обробки трьох категорій системних сигналів: фатальних сигналів завершення, сигналів керування завданнями та сигналів зміни геометрії вікна.

```
                  ┌────────────────────────────────────┐
                  │          СИГНАЛ ВІД ЯДРА           │
                  └─────────────────┬──────────────────┘
                                    │
         ┌──────────────────────────┼──────────────────────────┐
         ▼                          ▼                          ▼
┌──────────────────┐       ┌──────────────────┐       ┌──────────────────┐
│ Фатальні сигнали │       │   Job Control    │       │  Зміна розміру   │
│ SIGINT, SIGTERM, │       │ SIGTSTP (Ctrl+Z) │       │     SIGWINCH     │
│ SIGHUP, SIGQUIT  │       │ SIGCONT (fg)     │       │                  │
└────────┬─────────┘       └────────┬─────────┘       └────────┬─────────┘
         │                          │                          │
         ▼                          ▼                          ▼
1. tcsetattr(TCSANOW)      1. tcsetattr(sane)         1. ioctl(TIOCGWINSZ)
2. write(VT100_CLEANUP)    2. sa_handler = SIG_DFL    2. Оновлення матриці
3. sa_handler = SIG_DFL    3. sigprocmask(UNBLOCK)    3. Переривання read
4. sigprocmask(UNBLOCK)    4. raise(SIGTSTP)             (обробка EINTR)
5. raise(signo)            5. [fg] -> raw mode
```

### Асинхронно-сигнальна безпека (Async-Signal Safety)

Всередині сигнальних обробників діють суворі обмеження стандарту POSIX.1-2008. Сигнал перериває потік інструкцій у довільний момент часу. Якщо в момент отримання сигналу основний потік виконував функцію `malloc()`, `free()` або виводив дані через `printf()` чи `std::cout`, внутрішній м'ютекс купи або буфера виводу перебуває у заблокованому стані. Спроба викликати будь-яку з цих функцій з обробника сигналу спричинить дедлок самого на себе.

В обробниках дозволено викликати лише функції зі списку Async-Signal-Safe:
- `tcsetattr()` та `tcgetattr()` (пряма робота з дескриптором термінала);
- `write()` (небуферизований системний запис у дескриптор);
- `sigaction()`, `sigprocmask()`, `sigemptyset()`, `sigaddset()`;
- `raise()` та `_exit()`.

### Патерн збереження та відновлення errno

Системні виклики всередині обробника можуть змінити глобальну змінну `errno`. Якщо сигнал перервав системний виклик основного циклу (наприклад, `read()`, що завершився з кодом `EINTR`), перезапис `errno` спотворить стан програми після повернення. Кожен обробник зобов'язаний зберігати локальну копію `int saved_errno = errno;` на початку і відновлювати `errno = saved_errno;` перед виходом.

### Коректна передача коду виходу: скидання обробника та raise()

Поширена помилка — викликати `exit(1)` або `_exit(1)` всередині обробника `SIGINT` або `SIGTERM`. Якщо процес завершується через `exit()`, його батьківська оболонка отримує статус штатного завершення (`WIFEXITED(status)` повертає `true`). Це ламає ланцюжки виконання в командних оболонках: наприклад, скрипт `make && ./app` не зупиниться, а продовжить виконувати наступні команди.

Стандартизований шлях аварійного завершення:
1. Відновити стан термінала через `tcsetattr(TCSANOW)` та надіслати послідовності ANSI.
2. Скинути дію сигналу на типову (`SIG_DFL`) через виклик `sigaction()`.
3. Зняти маску блокування сигналу через `sigprocmask(SIG_UNBLOCK, ...)`.
4. Повторно згенерувати той самий сигнал самому собі через `raise(signo)`.

Ядро знищить процес стандартною дією, а батьківська оболонка зафіксує завершення від сигналу через макрос `WIFSIGNALED(status)` та отримає точний номер сигналу через `WTERMSIG(status)`.

### Механіка керування завданнями (Job Control: SIGTSTP та SIGCONT)

Коли користувач натискає `Ctrl+Z`, лінійна дисципліна надсилає сигнал `SIGTSTP`. Якщо програма просто проігнорує його, призупинення не відбудеться. Якщо програма засне без скидання термінала, оболонка `bash` прокинеться і виведе промпт у спотворений термінал.

Протокол обробки `SIGTSTP`:
1. Відновити канонічний стан `termios` та увімкнути видимість курсора.
2. Встановити обробник `SIGTSTP` у стан `SIG_DFL`.
3. Розблокувати сигнал `SIGTSTP` у масці потоку.
4. Надіслати `raise(SIGTSTP)` — ядро переведе процес у стан `TASK_STOPPED` і сповістить оболонку сигналом `SIGCHLD`.
5. Після того, як користувач виконає команду `fg`, ядро надсилає процесу сигнал `SIGCONT`. Виконання поновлюється безпосередньо після інструкції `raise()`.
6. Обробник відновлює власну адресу для наступних `SIGTSTP` і повторно перемикає термінал у сирий режим.

### Обробка SIGWINCH та переривання викликів (EINTR)

Сигнал `SIGWINCH` надходить, коли користувач змінює розмір вікна емулятора. Розмір вікна зчитується системним викликом `ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws)`. Оскільки сигнали переривають повільні системні виклики введення-виведення, системний виклик `read(STDIN_FILENO, &c, 1)` повертає `-1` зі значенням `errno == EINTR`. Менеджер перевіряє цю умову в головному циклі й поновлює опитування через `continue` замість передчасного виходу з програми.

## Детальний розбір реалізації та пасток виконання

### 1. Анатомія модуля мовою C (`safe_terminal.c`)

- **Атомарний стан `volatile sig_atomic_t g_is_raw`:** Змінна з цим типом гарантує, що операції читання та запису виконуються як неподільні апаратні інструкції, унеможливлюючи читання частково оновленого стану під час переривання сигналом. Ключове слово `volatile` забороняє компілятору кешувати значення прапорця в регістрах процесора.
- **Ідемпотентність відновлення:** Функція `restore_terminal_raw()` перевіряє прапорець `g_is_raw` перед виконанням системного виклику. Якщо термінал уже відновлено (наприклад, деструктором або попереднім сигналом), повторний виклик `tcsetattr()` пропускається, що усуває зайві системні виклики.
- **Реєстрація `atexit(on_exit_cleanup)`:** Гарантує автоматичне відновлення структури `termios` при будь-якому штатному виході з програми (через `return` у `main()` або явний виклик `exit()`).

### 2. Анатомія RAII-модуля мовою C++ (`safe_terminal.cpp`)

- **Ідіома RAII та безпека винятків:** Конструктор `TerminalGuard` перевіряє тип дескриптора (`::isatty`), зберігає поточні атрибути та застосовує сирий режим. Якщо будь-який системний виклик завершується невдачею, конструктор викидає `std::system_error` з оригінальним системним кодом помилки `errno`. Деструктор `~TerminalGuard()` позначено специфікатором `noexcept` і гарантовано викликається під час розгортання стека (Stack Unwinding).
- **Заборона копіювання та переміщення:** Конструктори та оператори копіювання й переміщення явно видалені (`= delete`). Це запобігає передачі об'єкта за значенням, що призвело б до передчасного виклику деструктора копії та скидання термінала посеред роботи програми.
- **Статичний місток `s_active_instance`:** Оскільки системний обробник сигналів стандарту POSIX повинен мати C-сигнатуру `void (*)(int)`, він не може бути нестатичним методом класу. Статичний вказівник `s_active_instance` зберігає адресу поточного живого екземпляра класу, дозволяючи обробнику викликати закритий метод `restore_raw()`.

## Покроковий протокол перевірки та тестування

Для всебічної верифікації надійності модуля рекомендується виконати п'ять контрольних сценаріїв в окремій термінальній сесії:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        МАТРИЦЯ ТЕСТУВАННЯ TTY                          │
├───────────────────┬────────────────────────────┬───────────────────────┤
│ Сценарій тесту    │ Вхідна дія                 │ Очікуваний результат  │
├───────────────────┼────────────────────────────┼───────────────────────┤
│ 1. Штатний вихід  │ Натискання клавіші 'q'     │ Прапорці echo, icanon │
│ 2. Сигнал SIGINT  │ Натискання Ctrl+C або kill │ Миттєве відновлення   │
│ 3. Job Control    │ Ctrl+Z -> fg               │ Чистий промпт -> Raw  │
│ 4. Обрив сесії    │ Закриття вкладки (SIGHUP)  │ Відсутність зависань  │
│ 5. Не-термінал    │ echo "test" | ./app        │ Помилка ENOTTY        │
└───────────────────┴────────────────────────────┴───────────────────────┘
```

1. **Тест штатного завершення:**
   Запустіть скомпільовану програму, натисніть кілька клавіш для перевірки посимвольного вводу та натисніть `q`. Виконайте перевірку конфігурації лінії:
   ```bash
   stty -a | grep -E "echo|icanon|onlcr"
   ```
   Усі три параметри мають бути присутні без префікса мінуса (`echo`, `icanon`, `onlcr`).

2. **Тест асинхронного переривання (`Ctrl+C` / `SIGINT`):**
   Запустіть програму і надішліть сигнал `SIGINT` натисканням `Ctrl+C` або з сусіднього термінала:
   ```bash
   kill -INT $(pidof safe_terminal_c)
   ```
   Програма повинна миттєво завершитися, запрошення командної оболонки має відображатися з крайнього лівого стовпчика, а набір символів на клавіатурі повинен супроводжуватися штатним відлунням.

3. **Тест підсистеми Job Control (`Ctrl+Z` -> `fg`):**
   Запустіть програму та натисніть комбінацію `Ctrl+Z`. Оболонка повинна вивести статус зупинки завдання:
   ```
   [1]+  Stopped                 ./safe_terminal_c
   ```
   Введіть команду `ls` в оболонці — введення та виведення повинні працювати без спотворень. Потім поверніть програму на передній план командою `fg` — програма повинна без збоїв відновити сирий режим і продовжити посимвольний ввід.

4. **Тест аварійного обриву сесії (`SIGHUP`):**
   Запустіть програму всередині віконного мультиплексора `tmux` або окремого вікна емулятора та примусово закрийте вікно. Перевірте через системний монітор, що процес перехопив сигнал `SIGHUP`, коректно завершився і не перетворився на завислий зомбі-процес.

5. **Тест роботи з конвеєром (Non-TTY Edge Case):**
   Спробуйте перенаправити потік у програму:
   ```bash
   echo "test" | ./safe_terminal_cpp
   ```
   Програма повинна штатно перехопити нетермінальний дескриптор, вивести повідомлення про помилку `STDIN не є терміналом` (код `ENOTTY`, Inappropriate ioctl for device) і завершитися зі статусом `EXIT_FAILURE` без генерації паніки ядра чи збоїв пам'яті.
