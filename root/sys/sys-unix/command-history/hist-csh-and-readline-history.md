# 📜 Від телетайпів 2BSD csh до GNU Readline: історія розкриття команд

Поява механізму збереження та повторного використання введених команд у терміналах Unix була зумовлена фізичними обмеженнями апаратного забезпечення кінця 1970-х років. У перших версіях Unix, розроблених у Bell Labs Кеннетом Томпсоном (Kenneth Thompson) та Деннісом Рітчі (Dennis Ritchie), користувачі взаємодіяли з комп'ютером PDP-11 через електромеханічні телетайпи Teletype Model 33 або ранні текстові дисплеї, підключені через повільні послідовні інтерфейси RS-232 зі швидкістю передачі від 110 до 300 бод (символів на секунду). Якщо інженер припускався одруківки у складному шляху файлу чи параметрі компілятора наприкінці довгого рядка, йому доводилося або стирати весь рядок символом забою, або набирати його заново від першої літери.

Оригінальна оболонка Стівена Борна (Stephen Bourne), представлена у V7 Unix (1979 рік), була спроєктована передусім як мінімалістична мова програмування для сценаріїв автоматизації. Вона працювала в канонічному режимі термінала (`ICANON`), де обробка рядка відбувалася виключно на рівні драйвера TTY ядра, а після натискання клавіші Return введений буфер передавався парсеру без збереження у пам'яті процесу для подальшого виклику. Для систем із 64 кілобайтами адресного простору на процес утримання масиву раніше виконаних рядків вважалося надмірною розкішшю, тому оболонка Борна залишалася без власної пам'яті.

```
[1978: 2BSD csh] ────────► [1984: ksh] ────────► [1989: GNU Bash / Readline] ──► [1990+: Zsh]
  Біл Джой:                 Девід Корн:             Браян Фокс:                    Пол Фалстад:
  Синтаксис «!»,            Редагування Emacs/Vi,   libhistory, libreadline,       Мітки часу,
  події та модифікатори     історія у пам'яті       файл ~/.bash_history           SHARE_HISTORY
```

Університет Каліфорнії в Берклі під керівництвом Біла Джоя (Bill Joy) обрав інший вектор розвитку. Створюючи у 1978 році C-Shell (`csh`) для дистрибутиву 2BSD Unix, Джой прагнув перетворити оболонку на зручне робоче середовище саме для інтерактивної роботи людини-оператора. Оскільки повноцінне переміщення курсора стрілками вимагало складного керування escape-послідовностями термінала, Джой запропонував алгоритм швидкої символьної підстановки перед фазою синтаксичного розбору — розкриття історії (History Expansion), що позначалося символом знака оклику `!`.

Джой реалізував у `csh` кільцевий буфер рядків, у який копіювався кожен завершений рядок введення. Спеціальний синтаксис дозволяв миттєво посилатися на ці рядки: оператор `!!` дублював попередню команду, `!$` підставляв останній аргумент, а синтаксис швидкої заміни `^old^new^` виправляв помилку друку без повторного введення всього рядка. Для маніпуляцій зі шляхами було запроваджено модифікатори `:h` (head, каталог), `:t` (tail, ім'я файлу) та `:r` (root, ім'я без суфікса розширення), які значно прискорювали циклічну збірку програм компілятором C (`cc`).

У 1984 році Девід Корн (David Korn) у Bell Labs створив KornShell (`ksh`), де поєднав строгу алгоритмічну сумісність з оболонкою Борна та концепцію інтерактивної пам'яті команд. Корн зробив наступний крок: замість виключно символьної підстановки `!` він інтегрував безпосередньо в оболонку механізми динамічного редагування рядка за стандартами редакторів Emacs (комбінації `Ctrl+P`, `Ctrl+N`, `Ctrl+R`) та Vi (клавіші `k`, `j`, `/`). Історія перестала бути просто текстовим журналом і перетворилася на динамічний список, яким можна було переміщатися візуально, повертаючи курсор у будь-яку точку попереднього виклику.

Коли у 1989 році Фонд вільного програмного забезпечення (Free Software Foundation) розпочав створення оболонки GNU Bourne-Again Shell (Bash), автор проєкту Браян Фокс (Brian Fox) вирішив відокремити інтерфейс редагування та керування історією у дві незалежні бібліотеки: `libreadline` та `libhistory`. Це інженерне рішення дозволило використовувати уніфіковану історію не лише в самій оболонці Bash, а й у будь-яких інтерактивних утилітах простору користувача (таких як `gdb`, `sqlite3`, `python` чи `bc`).

Саме у `libhistory` було впроваджено модель довготривалого збереження сесій у текстовому файлі `~/.bash_history`, механізм очищення дублікатів через `HISTCONTROL`, а згодом у версіях Bash 3.0+ — часові мітки `HISTTIMEFORMAT` у форматі коментарів з епохою Unix (Unix Epoch, стандарт POSIX.1). Команда запису отримала можливість не лише перезаписувати файл цілком через виклик `write_history()`, а й дописувати нові рядки у режимі додавання через системний виклик `open()` з прапорцем `O_APPEND`.

Подальший розвиток у 1990-х роках у оболонці Zsh під керівництвом Пола Фалстада (Paul Falstad) розширив механіку історії підтримкою багаторядкових блоків коду, функціями паралельного атомарного блокування файлу історії між десятками вікон терміналів (`SHARE_HISTORY`) та збереженням тривалості виконання кожної команди. Завдяки цьому еволюційному ланцюгу сучасні Unix-оболонки поєднують швидкість символьного розкриття 1970-х років із надійними механізмами синхронізації та безпеки сучасних багатоядерних операційних систем.
