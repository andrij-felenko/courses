# 📋 Довідник синтаксису розкриття історії та модифікаторів

Механізм розкриття історії (History Expansion) у командних оболонках Bash та Zsh виконує підстановку раніше введених слів та команд перед етапом лексичного аналізу, розділення слів і виконання системних викликів. Цей довідник містить повну специфікацію селекторів подій, селекторів слів, модифікаторів форматування та вбудованих параметрів бібліотеки GNU History.

## 1. Граматика та фази обробки рядка

Розкриття історії в інтерактивній оболонці відбувається на найпершому етапі конвеєра обробки введення — ще до того, як інтерпретатор розпізнає синтаксичні конструкції мови (цикли, умовні оператори), виконує розкриття змінних `$VAR` або видаляє лапки. Це означає, що символ знака оклику `!` розпізнається як метасимвол розкриття навіть усередині подвійних лапок `"..."`, що часто стає причиною неочікуваних синтаксичних помилок виду `bash: !": event not found`.

Єдиними конструкціями, які блокують розкриття знака оклику, є одинарні лапки `'...'` (у яких будь-які символи сприймаються буквально), екранування символом зворотного слешу `\!`, або вимкнення функції розкриття історії в оболонці за допомогою команди `set +H` (або `set +o histexpand`).

Синтаксис повного виразу розкриття історії складається з трьох послідовних компонентів:

```
!<подія>[:<селектор_слова>][:<модифікатор_1>][:<модифікатор_2>]...
```

Якщо селектор слова починається з одного зі спеціальних символів `^`, `$`, `*`, `-` або `%`, двокрапку між подією та словом можна опустити. Якщо ж вираз розкриття починається з символу `^` без знака оклику (наприклад, `^старе^нове^`), оболонка розпізнає його як коротку форму модифікації попередньої команди.

## 2. Селектори подій (Event Designators)

Селектор події визначає, з якого саме рядка кільцевого списку історії буде виконано вибірку. Якщо за знаком оклику стоїть пробіл, табуляція, символ кінця рядка або знак рівності `=`, символ `!` залишається без змін і розкриття не виконується.

| Селектор | Опис та семантика вибірки | Приклад розгортання |
|---|---|---|
| `!` | Розпочинає підстановку історії (якщо далі йде непорожній символ) | `!104` |
| `!!` | Попередня команда (повний еквівалент `!-1`) | `sudo !!` |
| `!n` | Команда з абсолютним номером рядка `n` у поточному буфері | `!42` |
| `!-n` | Команда, що була виконана `n` кроків тому | `!-2` |
| `!string` | Найновіша команда, що починається з текстового префікса `string` | `!systemctl` |
| `!?string[?]` | Найновіша команда, що містить підрядок `string` у будь-якій позиції рядка | `!?nginx?` |
| `^old^new^` | Коротка заміна: знаходить перший збіг `old` у попередній команді та замінює його на `new` (еквівалент `!!:s/old/new/`) | `^tset^test^` |
| `!#` | Увесь рядок, набраний у поточному командному рядку до поточної позиції курсора | `cp file.txt /tmp/!#:1` |

Якщо селектор не знаходить відповідного запису у буфері історії, оболонка виводить повідомлення про помилку `event not found`, повертає ненульовий статус завершення та повністю скасовує виконання введеного рядка, не передаючи його на наступні етапи синтаксичного аналізу.

## 3. Селектори слів та аргументів (Word Designators)

Селектор слів вказує, які саме позиційні аргументи з вибраної події необхідно витягти та підставити у поточний рядок. Слова визначаються за стандартними правилами розбиття рядка на лексеми за допомогою пробільних символів, з урахуванням лапок. Нульове слово (`0`) відповідає імені самої команди.

| Селектор | Опис слова у командному рядку | Приклад підстановки |
|---|---|---|
| `0` | Ім'я команди (нульовий аргумент виклику) | `!vim:0` ──► `vim` |
| `n` | Аргумент за числовим індексом `n` (`1`, `2`, `3` тощо) | `!gcc:2` ──► другий аргумент команди `gcc` |
| `^` | Перший аргумент команди (повний еквівалент індексу `1`) | `cat !^` |
| `$` | Останній аргумент вибраної команди | `cd !$` |
| `%` | Слово, що збіглося з останнім пошуковим запитом `?string?` | `vi !%` |
| `x-y` | Діапазон слів від позиційного індексу `x` до `y` включно | `tar -czf !:2-4` |
| `-y` | Скорочення для діапазону слів від початку до індексу `y` (`0-y`) | `!: -2` |
| `*` | Усі аргументи команди, крім нульового імені (еквівалент `1-$`) | `echo !*` |
| `x*` | Скорочення для діапазону від індексу `x` до останнього слова (`x-$`) | `cp !:2* /tmp/` |
| `x-` | Діапазон слів від `x` до передостаннього аргументу (`x-($-1)`) | `diff !:1-` |

Якщо числовий індекс або межа діапазону перевищує кількість фактичних слів у вибраній команді, операція завершується помилкою `bad word specifier`.

## 4. Модифікатори слів та шляхів (Modifiers)

Модифікатори додаються після селектора слова (або безпосередньо після селектора події, якщо вибирається вся команда) через послідовні символи двокрапки `:`. Вони дозволяють маніпулювати шляхами файлової системи, здійснювати контекстну заміну рядків або захищати отриманий текст від подальшого розкриття.

| Модифікатор | Дія над виділеним рядком | Приклад (для рядка `/var/log/nginx/access.log.gz`) |
|---|---|---|
| `:h` | Head: видаляє хвостовий компонент шляху, повертаючи батьківський каталог | `!$:h` ──► `/var/log/nginx` |
| `:t` | Tail: видаляє початковий шлях каталогу, повертаючи базове ім'я файлу | `!$:t` ──► `access.log.gz` |
| `:r` | Root: видаляє розширення файлу (починаючи з останньої крапки) | `!$:r` ──► `/var/log/nginx/access.log` |
| `:e` | Extension: повертає суфікс розширення файлу | `!$:e` ──► `.gz` |
| `:p` | Print: виводить підставлену команду на екран термінала без її виконання та додає її в історію | `!rm:p` ──► лише друкує команду `rm ...` |
| `:q` | Quote: бере всі виділені слова у лапки для захисту від подальшого розкриття | `!$:q` |
| `:x` | Quote words: бере кожне окреме слово вибірки в окремі лапки, розділені пробілами | `!*:x` |
| `:s/old/new/` | Substitute: замінює перше входження підрядка `old` на рядок `new` | `!!:s/v1/v2/` |
| `:gs/old/new/` | Global Substitute: замінює всі входження підрядка `old` на `new` | `!!:gs/test/prod/` |
| `:&` | Повторює попередню виконану операцію заміни `s` над новим рядком | `!$:&` |

Модифікатори можна об'єднувати у ланцюжки. Наприклад, вираз `!$:h:t` спочатку обріже ім'я файлу модифікатором `:h`, отримавши шлях до каталогу `/var/log/nginx`, а потім застосує модифікатор `:t`, виділивши ім'я кінцевої папки `nginx`.

## 5. Змінні середовища конфігурації історії

Керування внутрішніми структурами даних бібліотеки `libhistory`, лімітами виділення пам'яті процесу та форматом довготривалого збереження здійснюється через стандартні змінні середовища:

| Змінна | Тип значення | Призначення та системна поведінка |
|---|---|---|
| `HISTFILE` | Рядок (шлях) | Шлях до постійного файлу збереження історії (`~/.bash_history` за замовчуванням). Якщо змінну скинуто або встановлено у `/dev/null`, запис на диск під час виходу з сесії блокується. |
| `HISTSIZE` | Ціле число | Максимальна кількість елементів, які утримуються в динамічному масиві `the_history` в оперативній пам'яті процесу. Якщо значення дорівнює `0`, збереження історії у пам'яті вимикається. |
| `HISTFILESIZE` | Ціле число | Максимальна кількість рядків у файлі `HISTFILE`. При виході з оболонки функція `history_truncate_file()` обрізає файл до цієї межі. |
| `HISTCONTROL` | Список через `:` | Прапорці фільтрації: `ignorespace` (не зберігати рядки, що починаються з пробілу), `ignoredups` (ігнорувати послідовні дублікати), `ignoreboth` (space + dups), `erasedups` (видаляти всі попередні копії команди з пам'яті). |
| `HISTIGNORE` | Список через `:` | Шаблони `glob`, команди за якими повністю ігноруються при виклику `add_history()` (наприклад, `"ls*:bg:fg:exit:history*:[ ]*"`). |
| `HISTTIMEFORMAT` | Рядок формату `strftime` | Рядок форматування дати. Якщо встановлено, оболонка зберігає мітки часу у вигляді рядків `#<epoch>` та виводить відформатований час при виклику `history`. |
| `HISTCMD` | Ціле число | Номер історії або індекс поточної команди у буфері виконання. |

## 6. Крайові випадки та відмінності між Bash і Zsh

Хоча синтаксис знака оклику бере свій початок з 2BSD C-Shell, поведінка сучасних оболонок має суттєві відмінності при обробці складних рядків:

* **Попередній перегляд перед виконанням**: У Bash модифікатор `:p` друкує розгорнуту команду і поміщає її в кінець списку історії, дозволяючи викликати її клавішею «Стрілка вгору» без повторного набору. В оболонці Zsh опція `setopt HIST_VERIFY` змушує будь-яке розкриття знака оклику завантажуватися безпосередньо в активний буфер редагування рядка замість його негайного виконання.
* **Символ знака оклику в лапках**: Bash розкриває `!` у подвійних лапках, якщо він не захищений зворотним слешем `\!`. В оболонці Zsh розкриття всередині подвійних лапок за замовчуванням вимкнено, якщо не активовано сумісність через `setopt BANG_HIST` та відповідні режими емуляції.
* **Підстановки з розділювачами**: У модифікаторі заміни `:s/old/new/` як розділювач можна використовувати будь-який символ, а не лише скісну риску (наприклад, `!!:s#http://#https://#` позбавляє від необхідності екранувати слеші в адресах URL).
* **Ізоляція підінтерпретаторів**: Команди, запущені у підоболонці `(cmd)`, не мають прямого доступу до зміни масиву `the_history` батьківського процесу через копіювання адресного простору при системному виклику `fork()`.

## 7. Інтерфейс вбудованої команди history

Вбудована команда `history` надає безпосередній доступ до функцій бібліотеки `libhistory` з простору сценаріїв оболонки:

```bash
history [-c] [-d offset] [n]
history -a [-w] [-r] [-n] [filename]
history -ps arg [arg...]
```

* `-c`: Викликає функцію `clear_history()`, повністю очищаючи динамічний список історії в оперативній пам'яті поточного процесу.
* `-d offset`: Видаляє запис історії за вказаним числовим індексом `offset`. У сучасних версіях Bash підтримуються від'ємні зміщення для відліку з кінця списку.
* `-a`: Викликає `append_history()`, дописуючи нові команди, виконані у поточній сесії з моменту запуску, у файл `HISTFILE` без перезапису старого вмісту.
* `-n`: Зчитує з файлу історії лише ті рядки, які були записані іншими паралельними процесами з моменту останнього зчитування.
* `-r`: Перечитує весь вміст файлу `HISTFILE` та додає його до поточного списку історії в пам'яті процесу.
* `-w`: Повністю записує поточний стан списку пам'яті у файл історії, перезаписуючи існуючий файл.
* `-p arg ...`: Виконує розкриття історії над переданими рядками аргументів та виводить результат у стандартний вивід без збереження команди у пам'яті.
* `-s arg ...`: Додає передані рядки як єдиний запис у кінець буфера історії без їхнього фактичного запуску на виконання.
