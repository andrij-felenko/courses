# 📋 Довідник синтаксису розкриття історії та модифікаторів

Механізм розкриття історії (англ. *History Expansion*) у командних оболонках Unix (GNU Bash, Zsh, csh, tcsh) виконує контекстну текстову підстановку раніше введених команд, окремих позиційних слів та файлових шляхів на етапі попереднього опрацювання вхідного рядка перед лексичним аналізом, розділенням слів, підстановкою змінних та запуском процесів.

Цей документ містить повну нормативну специфікацію синтаксису розкриття за метасимволом `!`, селекторів подій, селекторів слів, модифікаторів трансформації рядків, параметрів і змінних середовища керування історією, опцій оболонки `shopt` та `setopt`, архітектури розширеної історії Zsh, паралельної роботи в сесіях tmux/screen із блокуванням файлів, індексації розширених метаданих, вбудованих утиліт `history` і `fc` (стандарт POSIX IEEE 1003.1), функцій бібліотеки GNU Readline, інтеграцій сучасних рушіїв пошуку `fzf` та `atuin`, протоколу збереження конфіденційних даних і специфікації C-API бібліотеки `libhistory`.

## 1. Граматика та фази обробки рядка

Розкриття історії в інтерактивній оболонці виконується на **найпершому етапі** конвеєра обробки вхідного рядка (REPL-циклу). Оболонка сканує вхідний потік символів до розкриття псевдонімів (alias expansion), фігурних дужок (brace expansion), тильди (tilde expansion), підстановки параметрів і змінних `$VAR`, виконання вкладених команд `$(...)`, арифметичних операцій `$((...))`, розбиття на слова (word splitting), розкриття імен файлів (pathname expansion / globbing) та фінального видалення лапок (quote removal).

```
Вхідний потік символів (TTY / stdin)
  │
  ▼
[ 1. History Expansion (! та ^) ] ──► Підстановка записів, селекція слів, модифікатори
  │
  ▼
[ 2. Alias Expansion ] ─────────────► Розкриття псевдонімів команд
  │
  ▼
[ 3. Shell Expansions ] ────────────► Brace {a,b}, Tilde ~, Parameter $VAR, Command $(), Arithmetic $(())
  │
  ▼
[ 4. Word Splitting ] ──────────────► Розбиття на поля за символами $IFS
  │
  ▼
[ 5. Pathname Expansion ] ──────────► Globbing (*, ?, [...])
  │
  ▼
[ 6. Quote Removal ] ───────────────► Зняття захисних лапок '...' та "..."
  │
  ▼
[ 7. Redirection & Execution ] ─────► Налаштування дескрипторів файлів та виклик execve()
```

### Загальна структура виразу розкриття

Повний вираз розкриття історії складається з трьох послідовних компонентів:

```
!<подія>[:<селектор_слова>][:<модифікатор_1>][:<модифікатор_2>]...
```

1. **Селектор події (Event Designator)**: обов'язковий початковий елемент (починається з `!` або `^`), що обирає конкретний рядок із буфера пам'яті `the_history` або збереженого журналу.
2. **Селектор слова (Word Designator)**: необов'язковий компонент, що витягує конкретний позиційний аргумент або діапазон слів із вибраного рядка події. Відокремлюється двокрапкою `:`. Двокрапку можна опустити, якщо селектор слова починається з символів `^`, `$`, `*`, `-` або `%`.
3. **Ланцюжок модифікаторів (Modifiers)**: один або кілька необов'язкових операторів строкової трансформації (обрізання шляхів каталогу, вилучення розширення, контекстна заміна, взяття в лапки, тестовий друк). Кожен модифікатор відокремлюється окремою двокрапкою `:` і застосовується послідовно зліва направо.

### Керуючі символи: змінна HISTCHARS

Символи, що активують механізм розкриття історії, визначаються значенням змінної середовища `HISTCHARS`:

```bash
HISTCHARS="!^#"
```

* **Перший символ** (за замовчуванням `!`, *bang*) — запускає загальне розкриття подій та слів.
* **Другий символ** (за замовчуванням `^`, *caret*) — запускає коротку контекстну заміну в безпосередньо попередній команді (`^old^new^`).
* **Третій символ** (за замовчуванням `#`, *hash*) — позначає початок коментаря в інтерактивному рядку, коли зустрічається як перший символ слова (коментар запобігає виконанню залишку рядка).

Якщо змінній `HISTCHARS` присвоєно значення з одного символу, цей символ стає символом розкриття подій, а символи заміни та коментаря деактивуються. Якщо змінна порожня, розкриття історії вимикається.

### Правила екранування та блокування розкриття

Символ `!` розпізнається лексичним аналізатором як метасимвол розкриття навіть усередині **подвійних лапок** `"..."`. Це класична пастка, що призводить до аварійної зупинки інтерпретації рядка:

```bash
$ echo "Hello World!"
bash: !": event not found
```

Механізм розкриття історії блокується або ігнорує символ `!` за таких суворих умов:

1. **Одинарні лапки `'...'`**: будь-які символи всередині одинарних лапок (strong quoting) сприймаються суто буквально. Вираз `echo 'Hello World!'` не активує розкриття історії.
2. **Зворотний слеш `\!`**: екранує знак оклику. Під час зняття екранування зворотний слеш видаляється, залишаючи літеральний символ `!`.
3. **Символи-розділювачі після `!`**: якщо безпосередньо за знаком оклику стоїть символ пробілу, табуляції `\t`, нового рядка `\n`, повернення каретки `\r`, знак рівності `=`, відкриваюча кругла дужка `(` або нульовий байт `\0`, знак оклику не розглядається як префікс події та передається наступним фазам парсера без змін (наприклад, вираз `if [ ! -f file ]` виконується без помилок).
4. **Конструкція `$!`**: комбінація знака долара та знака оклику інтерпретується як спеціальний параметр оболонки (PID останнього фонового процесу) і не активує розкриття історії.
5. **Вимкнення опції оболонки**: розкриття історії можна повністю вимкнути для поточної сесії командою `set +H` або `set +o histexpand` у Bash (повторне увімкнення — `set -H` або `set -o histexpand`), або `unsetopt BANG_HIST` у Zsh. У неінтерактивних сценаріях (shell scripts) розкриття історії за замовчуванням завжди вимкнено.
6. **Особливість подвійних лапок у Zsh**: на відміну від Bash, Zsh за замовчуванням не розкриває знак оклику всередині подвійних лапок `"..."`, якщо не встановлено опцію сумісності `setopt CSH_JUNKIE_HISTORY`.

### Внутрішній алгоритм парсингу лінійного буфера історії (GNU Readline / Bash)

Розбір виразів розкриття реалізовано у функції `history_expand()` бібліотеки `libhistory` (файл вихідного коду `histexpand.c`). Парсер функціонує як детермінований скінченний автомат (FSM), що виконує посимвольне сканування вхідного буфера з динамічним виділенням результуючого рядка.

```
Вхідний рядок (line)
  │
  ├─► [ Стан: NORMAL_TEXT ] ──────────► Копіювання символів у вихідний буфер
  │      │
  │      ├─► зустріли '\'' ──────────► [ Стан: IN_SINGLE_QUOTE ] (ігнорувати '!' до закриття)
  │      ├─► зустріли '\"' ──────────► [ Стан: IN_DOUBLE_QUOTE ] (Bash: '!' активний)
  │      ├─► зустріли '\\' ──────────► [ Стан: ESCAPED_CHAR ] (пропуск наступного байта)
  │      └─► зустріли '!'  ──────────► [ Стан: CHECK_BANG_DELIM ]
  │                                           │
  │                  ┌────────────────────────┴────────────────────────┐
  │                  ▼                                                 ▼
  │          [ Розділювач / Пробіл ]                           [ Початок виразу ]
  │                  │                                                 │
  │                  ▼                                                 ▼
  │        (Літеральний '!')                                 [ Стан: PARSE_EVENT ]
  │                                                                    │
  │                                                                    ▼
  │                                                     [ Пошук у the_history[] ]
  │                                                                    │
  │                                                                    ▼
  │                                                     [ Токенізація: history_tokenize() ]
  │                                                                    │
  │                                                                    ▼
  │                                                     [ Стан: PARSE_WORD_DESIGNATOR ]
  │                                                                    │
  │                                                                    ▼
  │                                                     [ Стан: EXECUTE_MODIFIERS (:s, :h, :t) ]
  │                                                                    │
  │                                                                    ▼
  └─────────────────────────────────────────────────────► Злиття: префікс + підстановка + суфікс
```

#### Стани автомата парсера history_expand()

1. `STATE_NORMAL`: початковий стан. Символи копіюються у вихідний буфер без змін. Якщо перший символ рядка збігається з `HISTCHARS[1]` (`^`), активується режим швидкої заміни `^old^new^`.
2. `STATE_IN_SINGLE_QUOTE`: активується символом одинарної лапки `'`. Будь-які метасимволи, включаючи `!`, пропускаються дослівно до зустрічі наступної одинарної лапки без зворотного екранування.
3. `STATE_IN_DOUBLE_QUOTE`: активується символом подвійної лапки `"`. У Bash символ `!` продовжує розпізнаватися як тригер розкриття, якщо за ним не слідує екрануючий слеш `\` або розділювач. У Zsh цей стан блокує розкриття за замовчуванням.
4. `STATE_CHECK_BANG`: перевіряє символ, що слідує безпосередньо за `!`. Якщо це пробіл, `\t`, `\n`, `\r`, `=`, `(`, `$` або `\0`, автомат повертає символ `!` у вихідний потік як літеральний текст і повертається до `STATE_NORMAL`.
5. `STATE_PARSE_EVENT`: розпізнає та обчислює селектор події:
   * Числові цифри `[0-9]` — витягує абсолютний номер запису та викликає `history_get(event_num)`.
   * Знак мінус `-` та цифри — обчислює відносне зміщення `history_length - offset`.
   * Знак `!` — обирає попередній запис `history_get(history_length - 1)`.
   * Знак `?` — запускає підрядковий пошук `history_search(sub, -1)`.
   * Знак `#` — підставляє поточний сформований вихідний буфер до позиції курсора.
   * Рядок символів — запускає префіксний пошук `history_search_prefix(string, -1)`.
6. `STATE_TOKENIZE_EVENT`: вибраний рядок події розбивається на масив лексем функцією `history_tokenize(entry->line)`. Токенізатор враховує лапки `'...'` та `"..."`, зберігаючи аргументи з пробілами як неподільні слова, та формує масив покажчиків `char **words`.
7. `STATE_PARSE_WORD`: після двокрапки `:` зчитує селектор слова (`0`, `N`, `^`, `$`, `*`, `N-M`, `N*`, `N-`, `:%`). Виконує перевірку меж індексів: якщо `N >= word_count`, функція перериває виконання з кодом помилки `bad word specifier`. Формує підрядок із вибраних слів.
8. `STATE_EXECUTE_MODIFIERS`: у циклі обробляє ланцюжок модифікаторів через двокрапку `:`. Для файлових модифікаторів (`:h`, `:t`, `:r`, `:e`) сканує покажчики на розділювачі `/` та `.`. Для модифікатора заміни `:s` зчитує довільний розділювач, парсить шаблони `old` та `new`, обробляє метасимвол `&` та виконує заміну підрядків у виділеному динамічному буфері.
9. `STATE_ASSEMBLY`: результуючий модифікований підрядок вставляється замість вихідного виразу розкриття, після чого парсер продовжує аналіз залишкового суфікса вхідного рядка.

## 2. Селектори подій (Event Designators)

Селектор події вказує, який саме рядок із кільцевого буфера або журналу історії обирається для підстановки. Якщо зазначену подію не знайдено, оболонка перериває обробку командного рядка, виводить у потік `stderr` діагностичне повідомлення `bash: !...: event not found` і повертає статус завершення `1` без передачі команди ядру.

| Селектор | Назва та алгоритм вибірки | Приклад виклику | Результат розкриття |
|---|---|---|---|
| `!` | Базовий префікс розкриття історії | `!104` | Команда під номером 104 |
| `!!` | Попередня виконана команда (синонім `!-1`) | `sudo !!` | `sudo <попередня_команда>` |
| `!N` | Команда за абсолютним номером рядка `N` у списку `history` | `!42` | Команда під індексом 42 |
| `!-N` | Команда, виконана `N` кроків тому (відносне зміщення назад) | `!-3` | Команда, що була виконана 3 кроки тому |
| `!string` | Найновіша команда, що **починається** з підрядка `string` | `!systemctl` | Останній виклик `systemctl restart nginx` |
| `!?string[?]` | Найновіша команда, що **містить** підрядок `string` у будь-якому місці | `!?docker?` | Останній виклик `docker compose up -d` |
| `!#` | Весь поточний рядок, набраний до цього моменту (до позиції курсора) | `cp file.txt !#:1.bak` | `cp file.txt file.txt.bak` |
| `^old^new^` | Швидка заміна першого збігу `old` на `new` у **попередній** команді | `^grpe^grep^` | Виправляє помилку у слові попередньої команди |

### Поведінкові нюанси селекторів подій

* **Завершальний знак `?` у `!?string?`**: якщо за пошуковим виразом не слідують селектори слів або модифікатори, кінцевий знак `?` можна опустити (`!?nginx`). Якщо ж необхідно додати селектор слова або модифікатор (наприклад, витягти останній аргумент), знак `?` є обов'язковим розділювачем: `!?docker?:$`.
* **Селектор `!#`**: використовується для посилання на аргументи, введені на початку того ж самого рядка. Наприклад, у виразі `tar -czf archive.tar.gz -C /data . && scp archive.tar.gz remote: && rm !#:2` токен `!#:2` розкривається в `archive.tar.gz` (другий аргумент поточного рядка).
* **Специфіка `^old^new^`**: форма швидкої заміни є скороченням від `!!:s/old/new/`. Кінцевий символ `^` необов'язковий, якщо за ним не слідують додаткові модифікатори.

## 3. Селектори слів та аргументів (Word Designators)

Селектор слова відокремлюється від селектора події двокрапкою `:` і визначає, які саме позиційні аргументи (лексеми) витягуються з рядка події.

Токенізація на слова виконується за правилами лексичного аналізу оболонки: пробільні символи (пробіли та табуляції) розглядаються як розділювачі, але аргументи, взяті в лапки `"arg with space"` або `'arg with space'`, сприймаються як одне неподільне слово.

| Селектор | Позиція аргументу у вибраній події | Приклад виклику | Значення при вихідній команді `git commit -m "initial commit"` |
|---|---|---|---|
| `0` | Нульове слово (назва виконуваної утиліти / команди) | `!git:0` | `git` |
| `N` | `N`-й позиційний аргумент (індексація починається з 0) | `!!:1` | `commit` |
| `^` | Перший аргумент команди (синонім `:1`) | `!echo:^` | Перший аргумент останньої команди `echo` |
| `$` | Останній аргумент команди | `ls -la !!:$` | `"initial commit"` (останній аргумент попередньої команди) |
| `%` | Слово, що збіглося з останнім пошуковим патерном `?string?` | `!?config?:%` | Слово, у якому знайдено підрядок `config` |
| `N-M` | Діапазон аргументів від позиції `N` до позиції `M` включно | `!!:1-2` | `commit -m` |
| `N*` | Усі аргументи від `N`-го до останнього (синонім `N-$`) | `!!:1*` | `commit -m "initial commit"` |
| `*` | Усі аргументи, крім нульового (синонім `1-*` або `1-$`) | `sudo !!:*` | `commit -m "initial commit"` |
| `N-` | Діапазон від `N`-го аргументу до передостаннього (еквівалент `N-(N_last-1)`) | `!!:1-` | `commit -m` |
| `-` | Аргументи від 0-го до передостаннього (синонім `0-`) | `!!:-` | `git commit -m` |

### Граничні випадки селекторів слів

1. **Команди без аргументів**: якщо попередня команда містила лише нульове слово (наприклад, `clear`), спроба розкрити `!!:1` або `!!:$` повертає помилку `bash: !!:1: bad word specifier`.
2. **Селектор `*` для однослівних команд**: якщо команда складається лише з імені утиліти (`pwd`), селектор `!!:*` розкривається в порожній рядок (без генерації помилки).
3. **Опущення двокрапки**: двокрапка перед селектором слова є обов'язковою для числових індексів (`!104:2`), але може опускатися для символьних позначень:
   * `!$` — останній аргумент попередньої команди (синонім `!!:$`).
   * `!^` — перший аргумент попередньої команди (синонім `!!:^`).
   * `!*` — усі аргументи попередньої команди (синонім `!!:*`).
   * `!-2:$` — останній аргумент команди, виконаної 2 кроки тому.

## 4. Модифікатори перетворення рядків (Modifiers)

Модифікатори додаються після селектора події або селектора слова через двокрапку `:`. Вони дозволяють маніпулювати шляхами файлової системи, виконувати контекстну заміну тексту, екранувати лапками та контролювати виконання.

| Модифікатор | Офіційна назва | Дія над рядком | Приклад аргументу | Результат трансформації |
|---|---|---|---|---|
| `:h` | Head | Видаляє завершальний компонент шляху файлу, повертаючи каталог (аналог утиліти `dirname`). | `/etc/nginx/nginx.conf` | `/etc/nginx` |
| `:t` | Tail | Видаляє всі початкові компоненти шляху, залишаючи базове ім'я файлу (аналог `basename`). | `/etc/nginx/nginx.conf` | `nginx.conf` |
| `:r` | Root | Видаляє суфікс розширення файлу формату `.xxx`, залишаючи базовий корінь імені. | `archive.tar.gz` | `archive.tar` |
| `:e` | Extension | Видаляє все, крім суфікса розширення файлу (включаючи крапку). | `archive.tar.gz` | `.gz` |
| `:p` | Print | Виконує розкриття виразу, друкує результуючу команду в термінал, але **не виконує її** і додає в історію як найновіший запис. | `!systemctl:p` | Друкує команду для візуальної перевірки |
| `:q` | Quote | Бере виділені слова в лапки, захищаючи всі метасимволи та пробіли від подальшого розбиття на поля оболонкою. | `hello world` | `'hello world'` |
| `:x` | eXecute quote | Розбиває виділені слова на окремі токені за пробілами, та бере кожне слово в лапки окремо. | `hello world` | `'hello' 'world'` |
| `:s/old/new/` | Substitute | Замінює **перший** знайдений підрядок `old` на рядок `new` у вибраному тексті. | `echo "test 1 test 2"` | `echo "prod 1 test 2"` |
| `:gs/old/new/` або `:s/old/new/:g` | Global Substitute | Замінює **всі** входження підрядка `old` на рядок `new` у всьому виразі. | `echo "test 1 test 2"` | `echo "prod 1 prod 2"` |
| `:&&` | Repeat substitute | Повторює попередню операцію заміни `:s` над новою цільовою подією. | `!105:&` | Застосовує останній шаблон заміни до рядка 105 |
| `:g&` | Global repeat | Повторює попередню заміну глобально (`global repeat`) над усім рядком. | `!$:g&` | Глобальна повторна заміна в останньому аргументі |
| `:u` *(лише Zsh)* | Uppercase | Перетворює всі символи виділеного рядка у верхній регістр. | `readme.md` | `README.MD` |
| `:l` *(лише Zsh)* | Lowercase | Перетворює всі символи виділеного рядка у нижній регістр. | `CONFIG.TXT` | `config.txt` |
| `:a` *(лише Zsh)* | Absolute path | Перетворює відносний шлях в абсолютний, обчислюючи поточний `$PWD` (без розв'язання symlink). | `./src/main.c` | `/home/user/project/src/main.c` |
| `:A` *(лише Zsh)* | Canonical realpath | Перетворює шлях в абсолютний канонічний із розкриттям усіх символічних посилань (`realpath`). | `/var/mail` | `/var/spool/mail` |
| `:c` *(лише Zsh)* | Command path | Шукає повний шлях до виконуваного файлу команди у системній змінній `$PATH` (аналог `which`). | `ls` | `/bin/ls` |

### Специфікація модифікатора заміни :s

Синтаксис оператора заміни:

```
:s<розділювач><old><розділювач><new>[<розділювач>]
```

1. **Довільний розділювач**: як розділювач можна використовувати будь-який символ, що не входить до підрядків `old` та `new` (наприклад, `:s#old#new#` або `:s@old@new@`). Це критично для заміни файлових шляхів, щоб уникнути конфліктів із прямим слешем `/`.
2. **Спеціальний метасимвол `&` у блоці `new`**: символ `&` у підрядку `new` автоматично розгортається у точний текст, який збігся з `old`:
   ```bash
   $ tar -czf release.tar data/
   $ !!:s/release/&-2026-08/
   # Розкривається в: tar -czf release-2026-08.tar data/
   ```
3. **Порожній шаблон `old`**: якщо блок `old` залишено порожнім (`:s//new/`), підсистема використовує попередній успішно застосований шаблон заміни або рядок із селектора пошуку події `!?string?`.
4. **Екранування розділювача**: якщо розділювач повинен входити до складу `old` або `new`, він екранується зворотним слешем: `:s/\/var\/log/\/tmp/`.

### Ланцюжки модифікаторів

Модифікатори можна комбінувати послідовно через двокрапку. Вони виконуються зліва направо:

```bash
$ tar -czf /var/backup/database-dump.tar.gz /var/lib/mysql
$ cd !$:h
# Результат: cd /var/backup

$ echo !-2:$:t:r:r
# Отримуємо чисте ім'я дампу без шляхів та подвійних розширених суфіксів .gz та .tar:
# !-2:$      -> /var/backup/database-dump.tar.gz
# :t         -> database-dump.tar.gz
# :r         -> database-dump.tar
# :r         -> database-dump
# Результат: echo database-dump
```

## 5. Системні змінні керування історією Bash

GNU Bash надає набір змінних середовища та внутрішніх змінних оболонки, які керують ємністю буферів, форматом серіалізації на диск, фільтрацією дублікатів та безпекою.

| Змінна Bash | Тип даних | Значення за замовчуванням | Опис призначення та механізм дії |
|---|---|---|---|
| `HISTFILE` | Рядок (шлях) | `~/.bash_history` | Абсолютний або відносний шлях до файлу постійного збереження журналу історії на диску. Якщо змінну скинуто (`unset HISTFILE`), історія сесії не зберігається на диск при закритті. |
| `HISTSIZE` | Ціле число | `500` (або `1000`) | Максимальна кількість команд, що зберігаються в оперативній пам'яті активного процесу оболонки (розмір кільцевого буфера `the_history`). При `HISTSIZE=0` запис у пам'ять блокується. При від'ємному значенні — ємність пам'яті необмежена. |
| `HISTFILESIZE` | Ціле число | `500` (або `2000`) | Максимальна кількість рядків у файлі `HISTFILE` на диску. Під час виходу з оболонки файл обрізається до цього ліміту (видаляються найстаріші записи). При `HISTFILESIZE=0` файл обнуляється. Від'ємне значення знімає ліміт. |
| `HISTCONTROL` | Рядок (прапорці через `:`) | `""` (не встановлено) | Керує фільтрацією запису команд у пам'ять та видаленням дублікатів. Можливі значення: `ignorespace`, `ignoredups`, `ignoreboth`, `erasedups`. |
| `HISTIGNORE` | Рядок (патерни через `:`) | `""` (не встановлено) | Двокрапковий список glob-шаблонів команд, які **ніколи не додаються** в історію. Перевірка здійснюється через функцію `fnmatch(3)`. |
| `HISTTIMEFORMAT` | Рядок формату `strftime` | `NULL` (не встановлено) | Задає формат дати й часу для виводу команди `history`. Якщо змінна встановлена, у файл `~/.bash_history` перед кожною командою записується рядок коментаря `#<epoch_timestamp>`. |
| `HISTCHARS` | Рядок (2 або 3 символи) | `"!^#"` | Задає керуючі символи: 1) розкриття історії (`!`), 2) швидка заміна (`^`), 3) коментар (`#`). |

### Режими прапорця HISTCONTROL

Значення `HISTCONTROL` конфігурується комбінацією ключових слів, розділених двокрапкою:

* **`ignorespace`**: команди, що починаються з одного або кількох символів пробілу або табуляції, не додаються до списку історії процесу.
* **`ignoredups`**: команда не зберігається, якщо вона повністю ідентична **безпосередньо попередній** виконаній команді.
* **`ignoreboth`**: скорочення, що активує одночасно `ignorespace` та `ignoredups`.
* **`erasedups`**: перед додаванням нового рядка в історію оболонка виконує повне сканування всього масиву пам'яті й видаляє **всі попередні екземпляри** цієї ж команди з історії, гарантуючи сувору унікальність кожного запису.

```bash
# Еталонне налаштування HISTCONTROL у ~/.bashrc
export HISTCONTROL="ignoreboth:erasedups"
```

### Синтаксис масок HISTIGNORE

Змінна `HISTIGNORE` містить перелік glob-патернів. Спеціальний символ `&` усередині маски позначає збіг із попередньою командою (аналог `ignoredups`):

```bash
# Ігнорувати: дублікати (&), базові навігаційні команди, виклики історії та фонові команди
export HISTIGNORE="&:ls:[bf]g:exit:quit:clear:history:history -c:pwd:date"

# Ігнорувати будь-яку команду, що починається з пробілу, або команди з секретами
export HISTIGNORE="[ ]*:export *TOKEN*:export *KEY*:*PASSWORD*:vault *:mysql *-p*"
```

### Опції ядра оболонки (shopt) для керування історією

Налаштування підсистеми історії в Bash реалізовано через вбудовану команду `shopt`:

```bash
# Перевірка поточного стану опції
shopt <опція>

# Увімкнення опції
shopt -s <опція>

# Вимкнення опції
shopt -u <опція>
```

| Опція shopt | Рекомендований стан | Опис поведінки ядра Bash |
|---|---|---|
| `histappend` | `shopt -s histappend` | Під час закриття сесії дописує нові рядки в кінець файлу `HISTFILE` (режим `O_APPEND`), замість повного перезапису файлу вмістом пам'яті процесу. Запобігає затиранню історії паралельних сесій. |
| `histreedit` | `shopt -s histreedit` | Якщо розкриття історії (`!`) зазнало невдачі (наприклад, `event not found`), рядок не скидається, а повертається в буфер Readline для виправлення користувачем. |
| `histverify` | `shopt -s histverify` | Після успішного розкриття історії рядок не виконується негайно ядром, а завантажується в буфер редагування Readline для попереднього перегляду та підтвердження натисканням Enter. |
| `cmdhist` | `shopt -s cmdhist` | Багаторядкові команди (наприклад, цикли `for ... done` або блоки `if`) зберігаються в історії як єдиний логічний запис зі збереженням крапок з комою. |
| `lithist` | `shopt -s lithist` | Працює лише разом із `cmdhist`. Зберігає багаторядкові команди з реальними символами перенесення рядка `\n` замість заміни їх на `;`. |

## 6. Архітектура та підсистема розширеної історії Zsh

Zsh має потужнішу підсистему історії, що підтримує мікросекундну точність тривалості виконання команд, блокування файлів для багатопроцесорної синхронізації та внутрішнє байтове кодування.

### Параметри розміру: HISTSIZE проти SAVEHIST

У Zsh керування розміром буферів розділено між двома змінними:

* `HISTSIZE`: максимальна кількість рядків у внутрішньому списку активного процесу Zsh.
* `SAVEHIST`: максимальна кількість записів, які записуються у файл `HISTFILE`. Якщо `SAVEHIST=0`, файл історії не оновлюється при закритті сесії.

### Специфікація формату .zsh_history (Extended History)

Коли в Zsh увімкнено опцію `EXTENDED_HISTORY` (`setopt EXTENDED_HISTORY`), кожен запис у файлі `~/.zsh_history` серіалізується у строгому структурованому форматі з фіксацією мітки часу початку та загальної тривалості виконання команди:

```
: <epoch_start>:<elapsed_seconds>;<command_string>
```

#### Анатомія полів запису

```
: 1724589600:12;docker build -t app:v1.0 .
│ │          │ │ └───────────────────────── Текст виконаної команди
│ │          │ └─────────────────────────── Розділювач метаданих та команди (;)
│ │          └───────────────────────────── Тривалість виконання команди в секундах (12 с)
│ └──────────────────────────────────────── Час запуску: Unix Epoch у секундах (1724589600)
└────────────────────────────────────────── Маркер розширеного формату Zsh (: )
```

1. **Маркер формату (`: `)**: перші два байти рядка — двокрапка та пробіл (`0x3A 0x20`). Парсер Zsh розпізнає їх як початок розширеного запису. Якщо двокрапки немає, рядок трактується як класичний запис без міток часу.
2. **Поле `<epoch_start>`**: десяткове ціле число без знаку, що представляє секунди від початку епохи Unix (1 січня 1970 року, виклик `gettimeofday()` або `clock_gettime(CLOCK_REALTIME)`).
3. **Розділювач полів (`:`)**: двокрапка, що відокремлює час старту від тривалості.
4. **Поле `<elapsed_seconds>`**: десяткове ціле число секунд, витрачених процесом на виконання команди (`t_end - t_start`). Для вбудованих команд оболонки або швидких викликів це поле дорівнює `0`.
5. **Розділювач команди (`;`)**: крапка з комою, після якої слідує повний символьний рядок команди.
6. **Метабайтове кодування (Zsh Metafication)**: якщо текст команди містить байти з кодами `>= 0x80` (наприклад, символи UTF-8) або спеціальні керуючі байти (зокрема нульовий байт `\0` чи символ нового рядка `\n`), Zsh під час збереження перетворює їх за схемою метафікації. Перед кожним таким байтом записується метабайт-маркер `0x83` (Meta), а сам цільовий байт інвертується виключним «АБО» з маскою `0x20` (`byte ^ 0x20`). Під час зчитування файлу парсер розпізнає `0x83`, відновлює оригінальний байт операцією `unmetafy()` та гарантує цілісність багатобайтових рядків.

### Опції ядра Zsh (setopt) для історії

Конфігурація підсистеми історії в Zsh виконується за допомогою вбудованої команди `setopt` (або `unsetopt` для вимкнення):

| Опція Zsh | Опис механізму та системна дія |
|---|---|
| `EXTENDED_HISTORY` | Зберігає записи у форматі `: <epoch>:<elapsed>;<cmd>`, фіксуючи час початку та тривалість виконання. |
| `INC_APPEND_HISTORY` | Записує кожну команду у файл `HISTFILE` негайно в момент її введення (до виконання). Поле тривалості записується як `0`. |
| `INC_APPEND_HISTORY_TIME` | Записує команду у файл `HISTFILE` негайно після завершення її виконання, записуючи точну фактичну тривалість `elapsed_seconds`. |
| `SHARE_HISTORY` | Організує спільну історію реального часу між усіма паралельними процесами Zsh. Імпортує нові записи з файлу перед кожним запрошенням і експортує виконані команди. Використовує блокування `fcntl(F_SETLK)` для захисту від стану гонитви. |
| `HIST_IGNORE_ALL_DUPS` | Якщо нова команда дублює старішу команду в історії, старий запис видаляється з пам'яті, залишаючи лише найновіший екземпляр. |
| `HIST_IGNORE_DUPS` | Не зберігає команду, якщо вона повністю збігається з безпосередньо попереднім рядком (аналог `ignoredups` у Bash). |
| `HIST_SAVE_NO_DUPS` | Під час запису буфера пам'яті у файл на диску ігнорує старіші дублікати, записуючи кожну команду лише один раз. |
| `HIST_EXPIRE_DUPS_FIRST` | Коли пам'ять історії `HISTSIZE` заповнена, першими витісняються та видаляються дублікати рядків, а не найстаріші унікальні записи. |
| `HIST_FIND_NO_DUPS` | Під час навігації стрілками чи пошуку `Ctrl+R` не показує дублікати рядків, навіть якщо вони присутні в історії. |
| `HIST_IGNORE_SPACE` | Рядки, що починаються з пробілу, не потрапляють до історії (аналог `HISTCONTROL=ignorespace`). |
| `HIST_NO_STORE` | Видаляє самі команди виклику історії (`history`, `fc -l`) зі списку історії. |
| `HIST_REDUCE_BLANKS` | Видаляє зайві незначащі пробіли всередині команди перед її додаванням в історію. |
| `HIST_VERIFY` | Після розкриття історії (`!`, `^`) не виконує команду негайно, а завантажує розкритий текст у рядок введення ZLE. |
| `BANG_HIST` | Вмикає розкриття історії за символом `!` (увімкнено за замовчуванням). Вимкнення — `unsetopt BANG_HIST`. |

### Еталонна конфігурація ~/.zshrc

```zsh
# Шлях та місткість історії
HISTFILE="$HOME/.zsh_history"
HISTSIZE=50000
SAVEHIST=50000

# Розширений формат та атомарна синхронізація
setopt EXTENDED_HISTORY          # Запис : <epoch>:<elapsed>;<cmd>
setopt INC_APPEND_HISTORY_TIME   # Дописування після виконання з фіксацією тривалості
setopt SHARE_HISTORY             # Атомарне злиття паралельних терміналів

# Дедуплікація та чистота журналу
setopt HIST_IGNORE_ALL_DUPS      # Видалення старих дублікатів
setopt HIST_SAVE_NO_DUPS         # У файлі зберігати тільки унікальні записи
setopt HIST_EXPIRE_DUPS_FIRST    # Першими витісняти дублікати
setopt HIST_REDUCE_BLANKS        # Стискати повторювані пробіли

# Безпека та верифікація
setopt HIST_IGNORE_SPACE         # Лідируючий пробіл приховує команду
setopt HIST_VERIFY               # Попередній перегляд після розкриття !
setopt HIST_NO_STORE             # Не зберігати команди перегляду history
```

## 7. Паралельні термінали, сесії tmux/screen та блокування файлів історії

Під час одночасної роботи кількох термінальних вікон, SSH-сесій або панелей мультиплексорів (`tmux`, `screen`) виникає класична проблема стану гонитви (Race Condition) за спільний файл історії на диску.

### Проблема перезапису «Last-Close-Wins»

Якщо в Bash не активовано опцію `shopt -s histappend` (поведінка за замовчуванням у стандартних збірках), підсистема історії функціонує за моделлю повного перезапису:

```
[ Термінал A (tmux pane 0) ] ── t0: Читає 1000 рядків ──► Виконує 50 команд ──► t2: exit ──► open(O_TRUNC) ──► 1050 рядків
[ Термінал B (tmux pane 1) ] ── t0: Читає 1000 рядків ──► Виконує 10 команд ──► t3: exit ──► open(O_TRUNC) ──► 1010 рядків
                                                                                    ▲
                                                    (Усі 50 команд із Термінала A повністю знищено!)
```

1. **Фаза старту `t0`**: обидві сесії зчитують файл `~/.bash_history` у власні масиви `the_history` у віртуальній пам'яті.
2. **Фаза виконання `t1`**: користувач вводить 50 команд у терміналі A і 10 команд у терміналі B. Кожна оболонка модифікує виключно свій локальний буфер у купі процесу.
3. **Фаза закриття `t2` (Термінал A)**: процес A завершується і викликає `write_history()`. Файл відкривається із прапорцем `O_WRONLY|O_CREAT|O_TRUNC`, і туди записуються 1050 команд.
4. **Фаза закриття `t3` (Термінал B)**: процес B завершується пізніше. Він відкриває той самий файл із прапорцем `O_TRUNC`, повністю стирає вміст диска і записує свої 1010 команд. Усі 50 команд із сесії A безповоротно втрачаються.

### Семантика режиму дописування (O_APPEND) та атомарність VFS

Увімкнення `shopt -s histappend` перемикає виклик `write_history()` на функцію `append_history()`, яка відкриває файл із прапорцем `O_APPEND`:

```
int fd = open(histfile, O_WRONLY | O_CREAT | O_APPEND, 0600);
```

За стандартом POSIX, для файлів, відкритих із прапорцем `O_APPEND`, зміщення файлу автоматично встановлюється на кінець перед кожним системним викликом `write(2)`. На рівні віртуальної файлової системи ядра Linux (VFS) операція позиціонування та запису є атомарною для блоків, розмір яких не перевищує розмір сторінки пам'яті (4096 байтів). Однак якщо запис містить велику багаторядкову команду або кілька процесів одночасно скидають буфери без блокування, байти окремих рядків можуть перемішатися (Interleaving).

### Механізми файлового блокування: fcntl проти flock

Для запобігання стану гонитви та пошкодженню файлу розширені оболонки використовують механізми консультативного блокування (Advisory File Locking).

```
Оболонка (Zsh / Bash sync)
  │
  ├─► open(HISTFILE, O_RDWR) ────────► Отримання файлового дескриптора fd
  │
  ├─► fcntl(fd, F_SETLK, &fl) ───────► Спроба взяття ексклюзивного блокування (F_WRLCK)
  │      │
  │      ├─► Успіх (0) ──────────────► Зчитування дельти ──► Дописування нової команди ──► fcntl(F_UNLCK)
  │      │
  │      └─► Зайнято (EAGAIN/EACCES) ─► Retry loop з експоненційним backoff (usleep)
```

#### Архітектура блокування у Zsh (SHARE_HISTORY)

У Zsh механізм `SHARE_HISTORY` виконує атомарну транзакцію перед виведенням кожного рядка запрошення `PS1` та після завершення кожної команди:

1. **Захоплення блокування**: Zsh викликає системний виклик `fcntl(fd, F_SETLK, &fl)`, де структура `struct flock` налаштована на блокування всього файлу:
   ```
   struct flock fl;
   fl.l_type = F_WRLCK;     /* Ексклюзивне блокування запису */
   fl.l_whence = SEEK_SET;
   fl.l_start = 0;
   fl.l_len = 0;            /* Блокування до кінця файлу */
   ```
2. **Зчитування нових записів**: процес перевіряє поточний розмір файлу через `fstat(fd)` або зміщення `lseek(fd, last_read_offset, SEEK_SET)`. Якщо з моменту останнього читання інші сесії додали команди, вони зчитуються та інтегруються у локальний буфер ZLE.
3. **Атомарне дописування**: нова щойно виконана команда серіалізується та записується в кінець файлу.
4. **Вивільнення блокування**: блокування скидається викликом `fl.l_type = F_UNLCK; fcntl(fd, F_SETLK, &fl);`.

#### Конкуренція за блокування та обробка збоїв (Stale Locks)

* **Коди помилок `EAGAIN` та `EACCES`**: якщо інший процес оболонки утримує блокування, неблокуючий виклик `fcntl(F_SETLK)` миттєво повертає помилку. Оболонка виконує серію повторних спроб (retry loop) із короткою паузою (від 1 до 10 мс) перед тим, як відмовитися від операції або повідомити користувача.
* **Автоматичне вивільнення ядром**: блокування `fcntl` прив'язані до системної таблиці відкритих файлів процесу. Якщо процес оболонки або сесія tmux раптово гине (наприклад, аварійне закриття SSH, переривання зв'язку або сигнал `kill -9`), ядро Linux автоматично звільняє всі дескрипторні блокування під час виконання процедури `do_exit()`, запобігаючи вічному зависанню інших сесій.
* **Допоміжні lock-файли**: у старих версіях або сторонніх утилітах створення блокування через створення файлу `~/.zsh_history.LOCK` (`open(O_CREAT|O_EXCL)`) могло призводити до утворення «завислих» замків (stale lockfiles) при збоях живлення. Сучасний Zsh перевіряє вік lock-файлу та валідність PID процесу через `kill(lock_pid, 0)`: якщо процес-власник більше не існує в таблиці процесів (`errno == ESRCH`), застарілий lock-файл примусово видаляється викликом `unlink()`.

### Стратегії організації історії у спільних облікових записах

У виробничих середовищах, де кілька інженерів мають доступ до спільного облікового запису (наприклад, `root` або службовий користувач `deploy`), використання єдиного файлу `~/.bash_history` призводить до змішування контекстів та неможливості точного аудиту.

#### 1. Пастка успадкування прав при sudo -s

Виконання команди `sudo -s` або `sudo bash` зберігає змінну середовища `$HOME` звичайної сесії користувача (`/home/user`). У результаті суперкористувач `root` створює або оновлює файл `/home/user/.bash_history` з правами власника `root:root` та маскою доступу `0600`. Коли інженер виходить назад у звичайну оболонку, процес більше не має прав на запис у власний файл історії, що викликає системну помилку `bash: /home/user/.bash_history: Permission denied`.

* **Нормативне вирішення**: використовувати команду `sudo -i` або `sudo su -`, яка повністю скидає контекст оточення, встановлює `HOME=/root` та спрямовує збереження команд у захищений журнал `/root/.bash_history`.

#### 2. Ізольоване журналювання окремих сесій (Per-Session Logs)

Для детермінованого розмежування паралельних сесій у конфігурації `~/.bashrc` налаштовують динамічний шлях до файлу історії, прив'язаний до ідентифікатора термінала, номера панелі `tmux` та PID процесу:

```bash
# Створення каталогу для сесійних логів
mkdir -p "$HOME/.logs/shell_history/$(date +%Y-%m)"

# Формування унікального імені файлу для кожної сесії / панелі tmux
_session_tty=$(tty 2>/dev/null | tr '/' '_' | sed 's/^_dev_//')
_session_pane="${TMUX_PANE:+tmux_${TMUX_PANE}_}"
export HISTFILE="$HOME/.logs/shell_history/$(date +%Y-%m)/hist_${_session_pane}${_session_tty}_$$.log"

# Запис у режимі дописування
shopt -s histappend
export HISTSIZE=50000
export HISTFILESIZE=100000
```

## 8. Індексація та збереження розширених метаданих команд у сучасних оболонках

Класичний формат історії Unix зберігає лише чистий символьний рядок команди, що втрачає критично важливий контекст її виконання. Сучасні оболонки та спеціалізовані підсистеми аудиту фіксують розширені набори метаданих.

### Специфікація полів метаданих

#### 1. Часові шкали: Астрономічний час проти Монотонного таймера

Для фіксації моменту запуску та тривалості виконання процесу використовуються дві різні шкали часу:
* **Абсолютний астрономічний час (Wall-Clock Time)**: отримується через системний виклик `clock_gettime(CLOCK_REALTIME)` або `gettimeofday()`. Представляє секунди або наносекунди від початку Unix Epoch (1 січня 1970 року). Використовується для індексації в календарі, але є вразливим до стрибків системного годинника при синхронізації через протокол NTP або зміні часових поясів.
* **Монотонний таймер тривалості (Monotonic Clock)**: вимірюється через `clock_gettime(CLOCK_MONOTONIC)` або `CLOCK_MONOTONIC_RAW`. Цей лічильник монотонно зростає від моменту завантаження системи й ніколи не повертається назад. Тривалість виконання команди обчислюється виключно за монотонним таймером: `duration = t_end_monotonic - t_start_monotonic`, що унеможливлює появу від'ємної тривалості при NTP-корекціях.

#### 2. Код завершення процесу та декодування сигналів

Після завершення дочірнього процесу оболонка зчитує статус через системний виклик `waitpid(pid, &wstatus, 0)` та декодує його за стандартом POSIX:
* `WIFEXITED(wstatus)`: процес завершився самостійно через виклик `exit(n)`. Код повернення витягується макросом `WEXITSTATUS(wstatus)` (діапазон `0–255`).
* `WIFSIGNALED(wstatus)`: процес було аварійно вбито сигналом ядра. За конвенцією Unix, оболонка встановлює змінну `$?` у значення `128 + WTERMSIG(wstatus)`:
  * `130` (`128 + 2`) — завершено сигналом переривання `SIGINT` (`Ctrl+C`).
  * `137` (`128 + 9`) — примусово знищено сигналом `SIGKILL` (Out-of-Memory Killer або `kill -9`).
  * `139` (`128 + 11`) — помилка сегментації пам'яті `SIGSEGV` (Null pointer dereference).
  * `143` (`128 + 15`) — завершено сигналом `SIGTERM`.
* Спеціальні коди помилок оболонки: `126` — файл знайдено, але він не має прав на виконання (`Permission denied`); `127` — команду або виконуваний файл не знайдено в каталогах змінної `$PATH`.

#### 3. Контекст робочого каталогу (CWD)

Оболонка фіксує каталог, у якому було запущено команду:
* **Логічний шлях (`$PWD`)**: зберігає шлях з урахуванням символічних посилань (symlinks).
* **Канонічний фізичний шлях**: отримується системним викликом `getcwd(2)` або функцією `realpath(3)` ядра Linux, розкриваючи всі проміжні symlinks у реальні каталоги файлової системи.

Збереження робочого каталогу дозволяє реалізувати контекстний пошук історії («показати лише ті команди, які запускалися всередині цього репозиторію»).

#### 4. Сесійні ідентифікатори та контекст оточення

Для точної ідентифікації джерела виклику сучасні рушії фіксують:
* **Session GUID**: унікальний ідентифікатор сесії (UUIDv4 або UUIDv7), що генерується процесом оболонки під час старту.
* **Ідентифікатор мультиплексора**: значення змінних `$TMUX_PANE` (наприклад, `%0`, `%3`), `$WINDOW` у screen або `$ZELLIJ_PANE_ID`.
* **Мережевий контекст SSH**: значення змінних `$SSH_CONNECTION` (`<клієнт_IP> <клієнт_порт> <сервер_IP> <сервер_порт>`) та `$SSH_TTY`.
* **Ідентифікатор сесії аудиту Linux (Audit Session ID)**: системний номер сесії PAM із файлу `/proc/self/sessionid` або змінної `$XDG_SESSION_ID`.

### Порівняльна таблиця форматів збереження метаданих

| Оболонка / Підсистема | Формат сховища на диску | Збережені поля метаданих | Механізм кодування |
|---|---|---|---|
| **GNU Bash (`HISTTIMEFORMAT`)** | Текстовий файл `~/.bash_history` (2 рядки на запис) | Час початку (`Unix Epoch`). | Рядок коментаря `#<epoch>`, за яким слідує текст команди. |
| **Zsh (`EXTENDED_HISTORY`)** | Текстовий файл `~/.zsh_history` (1 рядок на запис) | Час початку (`Epoch`), тривалість (`секунди`). | Префікс `: <epoch>:<duration>;` + Zsh-метафікація (`0x83`). |
| **Fish Shell** | YAML-подібний файл `~/.local/share/fish/fish_history` | Текст команди, час (`Epoch`), робочі каталоги (`paths`). | Блоки структурованого тексту `- cmd: ...\n  when: ...\n  paths: ...`. |
| **Atuin** | Реляційна база SQLite `~/.local/share/atuin/history.db` | UUIDv7, час (`наносекунди`), тривалість (`нс`), код `$?`, команда, `cwd`, `session`, `hostname`, `user`. | Бінарні B-Tree індекси SQLite + шифрування E2EE (XChaCha20). |
| **Linux Auditd (`pam_tty_audit`)** | Системний бінарний лог `/var/log/audit/audit.log` | `auid`, `uid`, `euid`, `tty`, `comm`, `exe`, `cwd`, повний масив `argv[]`, `exit_code`. | Незмінні події ядра `type=SYSCALL`, `type=EXECVE`, `type=TTY`. |

## 9. Інтерфейс вбудованої команди history (GNU Bash)

Вбудована команда `history` надає прямий інтерфейс до маніпуляції оперативним масивом `the_history` у віртуальній пам'яті процесу та синхронізації з постійним файлом `HISTFILE`.

### Синопсис виклику

```bash
history [n]
history -c
history -d offset
history -d start-end
history -a [filename]
history -n [filename]
history -r [filename]
history -w [filename]
history -p arg [arg...]
history -s arg [arg...]
```

### Специфікація прапорців

| Прапорець / Аргумент | Призначення | Семантика виконання та системні виклики |
|---|---|---|
| `n` (число) | Display last `n` | Виводить останні `n` записів історії з їхніми числовими номерами та мітками часу (якщо встановлено `HISTTIMEFORMAT`). |
| `-c` | Clear memory | Викликає внутрішню функцію `clear_history()`, повністю звільняючи пам'ять масиву `the_history` поточної сесії. Файл на диску не змінюється до виклику `history -w`. |
| `-d offset` | Delete entry | Видаляє запис за числовим індексом `offset`. Якщо зміщення від'ємне (наприклад, `history -d -1` у Bash 5.0+), відлік ведеться з кінця списку (видалення останньої виконаної команди). |
| `-d start-end` | Delete range | У версіях Bash 5.0+ видаляє діапазон записів від індексу `start` до `end` включно. |
| `-a [filename]` | Append unwritten | Викликає функцію `append_history()`, дописуючи команди поточної сесії, виконані з моменту запуску або попереднього `history -a`, у вказаний файл (за замовчуванням `HISTFILE`). |
| `-n [filename]` | Read new entries | Зчитує з файлу історії тільки ті рядки, які були додані іншими паралельними процесами з моменту останнього читання. |
| `-r [filename]` | Read all entries | Зчитує весь вміст вказаного файлу історії та додає його в кінець активного буфера пам'яті процесу. |
| `-w [filename]` | Write all entries | Повністю перезаписує вказаний файл історії поточним вмістом оперативної пам'яті процесу (`open(O_TRUNC)`). |
| `-p arg [arg...]` | Perform expansion | Виконує розкриття історії над переданими рядками аргументів та виводить результат у стандартний потік виводу `stdout` без додавання команди до буфера пам'яті та без її виконання. |
| `-s arg [arg...]` | Store fake entry | Додає передані аргументи як єдиний запис у кінець оперативного списку історії без їх виконання. |

### Рецепти синхронізації паралельних сесій через PROMPT_COMMAND

#### Модель 1: Інкрементальне дописування та зчитування нових рядків

```bash
# Додати у ~/.bashrc:
shopt -s histappend
export HISTSIZE=50000
export HISTFILESIZE=100000
export HISTCONTROL="ignoreboth:erasedups"
export PROMPT_COMMAND="history -a; history -n; ${PROMPT_COMMAND:-}"
```

1. `history -a`: визначає кількість нових команд з моменту попереднього виклику, відкриває `HISTFILE` системним викликом `open(O_WRONLY|O_APPEND)` і дописує лише дельту.
2. `history -n`: перевіряє поточний розмір файлу на диску, зчитує системним викликом `read()` рядки, додані сусідніми терміналами, та додає їх у кінець списку `the_history`.

#### Модель 2: Повна синхронізація зі скиданням буфера

```bash
# Додати у ~/.bashrc:
shopt -s histappend
export HISTSIZE=50000
export HISTFILESIZE=100000
export HISTCONTROL="ignoreboth:erasedups"
export PROMPT_COMMAND="history -a; history -c; history -r; ${PROMPT_COMMAND:-}"
```

Перед виведенням кожного рядка `PS1` поточні команди зберігаються (`history -a`), локальний буфер звільняється (`history -c`), і весь дисковий файл перечитується заново (`history -r`), гарантуючи абсолютно однаковий хронологічний порядок у всіх терміналах.

## 10. Стандарт POSIX: утиліта fc (Fix Commands)

У стандарті POSIX (IEEE Std 1003.1 / The Open Group Base Specifications) взаємодія з історією формалізована через утиліту `fc` (*Fix Commands*). Усі POSIX-сумісні оболонки зобов'язані надавати цю команду як вбудовану.

### Синопсис виклику (POSIX)

```bash
fc [-r] [-e editor] [first [last]]
fc -l [-n] [-r] [first [last]]
fc -s [old=new] [first]
```

### Специфікація прапорців та режимів

| Режим / Прапорець | Офіційна назва POSIX | Семантика виконання |
|---|---|---|
| `-e editor` | Edit and execute | Відкриває вибраний діапазон команд у текстовому редакторі `editor`. Після збереження та закриття файлу редактором із кодом `0` оболонка негайно виконує кожну відредаговану команду послідовно. |
| `-l` | List | Режим лістингу: виводить вибрані команди у стандартний потік виводу `stdout` замість виклику редактора (поводиться як утиліта `history`). |
| `-n` | Suppress numbers | Пригнічує виведення номерів рядків у режимі списку `-l`. |
| `-r` | Reverse | Змінює порядок команд на протилежний (від найновіших до найстаріших). |
| `-s [old=new]` | Re-execute | Повторно виконує команду без відкриття редактора, опціонально замінюючи перший збіг підрядка `old` на `new`. |

### Правила визначення аргументів first та last

Аргументи `first` та `last` задають межі діапазону команд і можуть бути задані в трьох форматах:

1. **Додатне число**: абсолютний номер рядка в журналі історії (наприклад, `fc -l 100 120` виводить рядки з 100 по 120).
2. **Від'ємне число**: відносне зміщення від поточної команди назад (наприклад, `fc -l -10` виводить останні 10 команд).
3. **Текстовий рядок**: обирає найновішу команду, яка починається з цього рядка (наприклад, `fc -s git` повторить останній виклик `git`).

**Правила заповнення пропущених аргументів:**
* Якщо аргумент `last` опущено в режимі `-l`, за замовчуванням вибирається найновіша виконана команда.
* Якщо аргумент `last` опущено в режимі редагування `-e`, значенням `last` стає значення `first` (редагування рівно однієї команди).
* Якщо не вказано жодного аргументу (`first` і `last` опущені):
  * У режимі редагування обирається безпосередньо попередня команда (зміщення `-1`).
  * У режимі лістингу `-l` виводяться останні 16 команд.

### Ієрархія вибору текстового редактора

Якщо прапорець `-e` не вказано, утиліта `fc` визначає редактор за таким суворим пріоритетом:

```
Значення змінної середовища $FCEDIT
        │
        ▼ (якщо порожньо або не встановлено)
Значення змінної середовища $EDITOR
        │
        ▼ (якщо порожньо або не встановлено)
Системний редактор за замовчуванням (ed або vi)
```

### Статуси завершення утиліти fc

* `0`: успішний вивід списку в режимі `-l` або успішне завершення виконаних команд.
* `>0`: помилка відкриття редактора, некоректні межі діапазону або статус завершення останньої запущеної після редагування команди.

## 11. Інтерактивне розкриття та функції GNU Readline

Бібліотека GNU Readline надає інтерфейс для навігації історією безпосередньо в рядку введення без застосування символів розкриття `!`.

| Комбінація клавіш | Функція Readline | Дія в рядку редагування |
|---|---|---|
| `Ctrl+R` | `reverse-search-history` | Запускає зворотний інкрементальний пошук підрядка від найновіших команд до найстаріших. Повторне натискання `Ctrl+R` переходить до наступного збігу. |
| `Ctrl+S` | `forward-search-history` | Запускає прямий інкрементальний пошук уперед до новіших записів. |
| `Alt+.` або `Alt+_` | `yank-last-arg` | Вставляє останній аргумент попередньої команди в позицію курсора. Повторне натискання перебирає аргументи старіших команд. З числовим аргументом (`Alt+2 Alt+.`) вставляє аргумент із зазначеним індексом. |
| `Ctrl+P` (або `Up`) | `previous-history` | Переміщується на один рядок назад у списку історії. |
| `Ctrl+N` (або `Down`) | `next-history` | Переміщується на один рядок уперед у списку історії. |
| `Alt+<` | `beginning-of-history` | Миттєво переходить до найпершого (найстарішого) запису в буфері. |
| `Alt+>` | `end-of-history` | Переходить до кінця історії (до порожнього рядка поточного введення). |
| `Alt+P` | `non-incremental-reverse-search-history` | Неінкрементальний пошук назад: очікує повного введення рядка та натискання Enter. |
| `Alt+N` | `non-incremental-forward-search-history` | Неінкрементальний пошук уперед. |
| `Ctrl+Alt+Y` | `yank-nth-arg` | Вставляє перший аргумент (індекс `1`) попередньої команди. Із числовим префіксом вставляє `n`-й аргумент. |
| `Alt+^` | `history-expand-line` | Виконує розкриття історії в поточному рядку та замінює його на розкритий результат без натискання Enter. |
| `Space` (з `magic-space`) | `magic-space` | Виконує миттєве розкриття історії при натисканні пробілу. |

### Конфігурація ~/.inputrc та магічний пробіл

Для автоматичного розкриття виразів `!$` або `!!` під час введення пробілу без виконання команди налаштовують файл `~/.inputrc`:

```
# Автоматичне розкриття історії при натисканні пробілу
Space: magic-space

# Пошук в історії за початком уже набраного рядка (стрілки вгору/вниз)
"\e[A": history-search-backward
"\e[B": history-search-forward

# Ігнорування регістру при автодоповненні та пошуку
set completion-ignore-case on

# Ліміт записів Readline
set history-size 10000
```

### Розблокування Ctrl+S (усунення блокування XOFF/XON)

У більшості терміналів емулятор перехоплює комбінацію `Ctrl+S` як команду програмного призупинення виводу TTY (`XOFF`), що викликає ілюзію повного зависання вікна. Для відновлення передачі сигналу необхідно натиснути `Ctrl+Q` (`XON`).

Щоб комбінація `Ctrl+S` вільно викликала функцію `forward-search-history` у Readline, контроль потоку вимикають у файлі `~/.bashrc`:

```bash
stty -ixon
```

## 12. Інтеграція сучасних інструментів пошуку (fzf та Atuin)

Стандартний пошук `Ctrl+R` у Readline виконує лише точний послідовний пошук підрядків. Сучасні інструменти інтегруються в термінальний REPL-цикл для забезпечення нечіткого (fuzzy) або структурованого реляційного пошуку з синхронізацією.

### Інтеграція fzf (Fuzzy Finder History Search)

Утиліта `fzf` реалізує інтерактивний вибір рядків на основі алгоритму нечіткого пошуку за відстанню Левенштейна та ваговими коефіцієнтами збігу символів.

```
┌───────────────────────────────────────────────────────────────────────────┐
│ > git checkout                                                            │
│  2048  2026-08-25 10:14  git checkout -b feature/auth-v2                  │
│  2049  2026-08-25 11:20  git checkout main                                │
│  2050  2026-08-25 14:02  git checkout -b fix/history-expansion-leak       │
│ > 3/2050 ──────────────────────────────────────────────────────────────── │
└───────────────────────────────────────────────────────────────────────────┘
```

#### Контракт інтеграції в GNU Bash

Інтеграція в Bash базується на команді `bind -x`, яка зв'язує комбінацію клавіш із виконанням користувацької функції оболонки, що маніпулює внутрішніми змінними Readline `READLINE_LINE` та `READLINE_POINT`:

```bash
# Функція перехоплення Ctrl+R у Bash
__fzf_history_custom() {
    local selected_cmd
    # Витягуємо історію, пропускаємо номери рядків, фільтруємо через fzf
    selected_cmd=$(HISTTIMEFORMAT= history | fzf \
        --height 40% \
        --reverse \
        --tac \
        --tiebreak=index \
        --query "${READLINE_LINE}" \
        --bind "ctrl-r:toggle-sort" \
        | sed -E 's/^[ ]*[0-9]+[ ]*//')

    local ret=$?
    if [ $ret -eq 0 ] && [ -n "$selected_cmd" ]; then
        READLINE_LINE="$selected_cmd"
        READLINE_POINT=${#READLINE_LINE}
    fi
}

# Реєстрація хука на Ctrl+R
bind -x '"\C-r": __fzf_history_custom'
```

* **`READLINE_LINE`**: містить поточний текстовий вміст рядка вводу Readline. Призначення нового значення перезаписує буфер редагування.
* **`READLINE_POINT`**: ціле число, що задає позицію курсора (встановлення в довжину рядка переміщує курсор у кінець команди).
* **Коди повернення `fzf`**:
  * `0`: елемент успішно вибрано натисканням клавіші Enter.
  * `1`: збігів не знайдено за заданим фільтром.
  * `130`: скасовано користувачем (натискання Esc або `Ctrl+C`).

#### Контракт інтеграції в Zsh (ZLE Widget)

У Zsh інтеграція реалізується через власну систему віджетів Zsh Line Editor (ZLE):

```zsh
# Віджет ZLE для Zsh
fzf-history-widget() {
    local selected_cmd
    setopt localoptions noglobsubst noposixbuiltins pipefail no_aliases 2> /dev/null
    
    selected_cmd=$(fc -rl 1 | fzf \
        --height 40% \
        --reverse \
        --tac \
        --tiebreak=index \
        --query "${BUFFER}" \
        | sed -E 's/^[ ]*[0-9]+[ ]*//')
        
    local ret=$?
    if [ $ret -eq 0 ] && [ -n "$selected_cmd" ]; then
        BUFFER="$selected_cmd"
        CURSOR=$#BUFFER
    fi
    zle reset-prompt
}

zle -N fzf-history-widget
bindkey '^R' fzf-history-widget
```

* `BUFFER`: спеціальна змінна ZLE, що містить повний текст рядка.
* `CURSOR`: позиція курсора в символах від початку буфера.
* `zle reset-prompt`: примусово перемальовує запрошення `PS1` після завершення віджета `fzf`.

### Atuin: реляційна база SQLite та протокол E2EE-синхронізації

Утиліта **Atuin** замінює лінійні текстові файли `~/.bash_history` та `~/.zsh_history` структурованою базою даних SQLite (`~/.local/share/atuin/history.db`), зберігаючи повний контекст виконання кожної команди.

```
[ REPL / Командний рядок ]
  │
  ├─► preexec хук ──► Запис (t0, cwd, session_id, command)
  │                      │
  │   [ Виконання процесу: exit_code = $? ]
  │                      │
  │   └─► precmd хук  ──► Обчислення duration = t1 - t0 ──► SQLite history.db
                                                           │
                                                           ▼ (фоновий sync)
                                                   [ E2EE XChaCha20 ]
                                                           │
                                                           ▼ (HTTPS REST)
                                                   [ Atuin Sync Server ]
```

#### Схема реляційної таблиці SQLite (таблиця history)

```sql
CREATE TABLE IF NOT EXISTS history (
    id TEXT PRIMARY KEY,          -- UUIDv7 (унікальний ідентифікатор запису)
    timestamp INTEGER NOT NULL,   -- Час запуску в наносекундах Unix Epoch
    duration INTEGER NOT NULL,    -- Тривалість виконання процесу в наносекундах
    exit INTEGER NOT NULL,        -- Код повернення процесу ($?)
    command TEXT NOT NULL,        -- Повний текст виконаної команди
    cwd TEXT NOT NULL,            -- Абсолютний робочий каталог у момент запуску
    session TEXT NOT NULL,        -- UUID поточної термінальної сесії
    hostname TEXT NOT NULL,       -- Мережеве ім'я хоста (FQDN / hostname)
    user TEXT NOT NULL            -- Системний обліковий запис ($USER / UID)
);

CREATE INDEX IF NOT EXISTS idx_history_timestamp ON history(timestamp);
CREATE INDEX IF NOT EXISTS idx_history_cwd ON history(cwd);
CREATE INDEX IF NOT EXISTS idx_history_command ON history(command);
```

#### Життєвий цикл хуків Atuin

1. **Фаза перед виконанням (`preexec`)**:
   Оболонка викликає хук `atuin history start "<command>"`. Фіксується початковий таймстемп `t0` через `clock_gettime(CLOCK_MONOTONIC)` або `date +%s%N`, поточний робочий каталог `cwd` (`getcwd(2)`) та генерується унікальний ідентифікатор запису `id`.
2. **Фаза після виконання (`precmd` / `PROMPT_COMMAND`)**:
   Оболонка викликає хук `atuin history end $?`. Фіксується фінальний статус завершення `$?`, обчислюється `duration = t1 - t0`, і виконується транзакційний виклик `INSERT INTO history` через локальний SQLite IPC-драйвер або UNIX-сокет демона.

#### Протокол наскрізного шифрування (E2EE) та синхронізації

Синхронізація між комп'ютерами здійснюється за моделлю Zero-Knowledge:
* **Алгоритм шифрування**: XChaCha20-Poly1305 (256-бітний ключ, 192-бітний нонс).
* **Деривація ключа**: Argon2id з пароля користувача та 256-бітного локального ключа відновлення (`key`).
* **Формат корисного навантаження**: відкритий текст команд ніколи не передається мережею. На сервер синхронізації (Atuin Sync Server) відправляються виключно бінарні шифротексти (Encrypted Envelopes) з монотонними лічильниками версій для дельта-синхронізації.

#### Режими контекстного пошуку Atuin

Atuin підтримує контекстну фільтрацію вибірки прапорцем `--filter-mode`:

| Режим фільтрації | Область вибірки команд |
|---|---|
| `directory` (`--filter-mode directory`) | Лише команди, виконані в поточному каталозі `cwd`. |
| `session` (`--filter-mode session`) | Лише команди поточної відкритої вкладки/сесії термінала. |
| `host` (`--filter-mode host`) | Команди з усіх сесій поточного комп'ютера. |
| `global` (`--filter-mode global`) | Усі команди з усіх синхронізованих хостів та сесій користувача. |

## 13. Протокол захисту та збереження конфіденційних даних

Журнали історії команд є критичним вектором атак локального підвищення привілеїв (Privilege Escalation) та компрометації облікових записів. Відкритим текстом в історію часто потрапляють паролі баз даних (`mysql -p`), токени аутентифікації (`curl -H "Authorization: Bearer ..."`), секретні ключі хмарних провайдерів (`export AWS_SECRET_ACCESS_KEY=...`) або приватні ключі SSH.

### Нормативний протокол запобігання збереженню секретів

#### 1. Правило лідируючого пробілу (Lead Space Protocol)

Найпростіший детермінований спосіб виконати команду без запису в журнал — почати рядок з одного символу пробілу або табуляції:

```bash
# У Bash (потрібно HISTCONTROL=ignorespace або ignoreboth):
$  export VAULT_TOKEN="s.1234567890abcdef"

# У Zsh (потрібно setopt HIST_IGNORE_SPACE):
%  curl -H "X-Vault-Token: s.1234567890abcdef" https://vault.internal/v1/secret
```

* **Механізм**: оболонка перевіряє перший символ рядка. Якщо це пробіл `0x20` чи табуляція `0x09`, виклик внутрішньої функції `add_history()` пропускається, команда виконується процесом, але ніколи не потрапляє ні в буфер пам'яті, ні у файл на диску.

#### 2. Захисні маски HISTIGNORE

У конфігураційному файлі `~/.bashrc` задаються регулярні патерни для автоматичного відсікання потенційно небезпечних викликів:

```bash
export HISTIGNORE="[ ]*:export *TOKEN*:export *KEY*:export *PASS*:*PASSWORD*:*SECRET*:vault *:openssl *:mysql *-p*:psql *password*:curl *-H *Auth*:history -c:history -d*"
```

* Будь-яка команда, що збігається з glob-шаблоном через системну функцію `fnmatch(3)`, відкидається на рівні ядра оболонки.

#### 3. Ефемерний режим сесії (Zero-Trace Session)

Для проведення чутливих робіт на виробничих серверах запис історії повністю відключається на час сесії:

```bash
# Метод А: Скидання файлу історії (не створює записів на диску при виході)
unset HISTFILE

# Метод Б: Перенаправлення файлу історії в псевдопристрій
export HISTFILE=/dev/null

# Метод В: Тимчасове призупинення запису в буфер пам'яті
set +o history          # Вимкнути запис
dangerous_operation_with_secrets
set -o history          # Відновити запис
```

#### 4. Обмеження прав доступу на рівні файлової системи (POSIX DAC)

Файли історії повинні бути захищені від читання іншими локальними користувачами та непривілейованими процесами:

```bash
# Суворі права доступу: лише власник (read/write)
chmod 600 ~/.bash_history ~/.zsh_history ~/.local/share/atuin/history.db 2>/dev/null || true

# Захист від видалення та скорочення (Append-Only атрибут ext4/xfs)
sudo chattr +a ~/.bash_history
```

* Прапорець `chattr +a` дозволяє процесам лише дописувати нові рядки (`O_APPEND`), блокуючи системні виклики скорочення `ftruncate()` або перезапису `O_TRUNC`, що унеможливлює непомітне затирання слідів зловмисником.

#### 5. Ізоляція сесій sudo

Виконання `sudo -s` успадковує середовище звичайної сесії з `HOME=/home/user`. У результаті команди суперкористувача записуються у файл `~/.bash_history` звичайного користувача від імені `root:root` (права `0600`), що призводить до блокування запису (`Permission denied`) після повернення у звичайний сеанс.

* **Безпечний вхід**: слід використовувати `sudo -i` або `sudo su -`, що скидає `HOME=/root` та спрямовує історію root у захищений файл `/root/.bash_history`.

### Протокол екстреного вилучення скомпрометованих записів

Якщо конфіденційні дані помилково потрапили в командний рядок, їх необхідно негайно видалити з обох шарів (пам'яті та диска):

1. **Визначення позиції**: виклик `history | tail -n 10` знаходить точний номер скомпрометованого рядка (наприклад, `10542`).
2. **Видалення з пам'яті процесу**:
   ```bash
   history -d 10542       # Видалення за номером
   # Або видалення останньої команди у Bash 5.0+:
   history -d -1
   ```
3. **Примусова синхронізація на диск**:
   ```bash
   history -w             # Перезапис файлу HISTFILE актуальним буфером пам'яті
   ```
4. **Гарантоване знищення (Secure Erase)**:
   Якщо файл історії містить масивний витік або його потрібно повністю знищити:
   ```bash
   history -c             # Очищення ОЗП
   shred -u -z -n 3 ~/.bash_history  # 3-прохідне затирання псевдовипадковими байтами
   ```

### Межа захисту: історія проти ядра ОС

Приховування команди з файлу історії не приховує її від процесів моніторингу під час виконання:
* Коли програма запускається системним викликом `execve(2)`, масив аргументів `argv[]` копіюється в адресний простір нового процесу і стає доступним у псевдофайловій системі ядра `/proc/[pid]/cmdline` для будь-якого користувача через утиліти `ps aux`, `top`, `htop`.
* **Невідхильний аудит ядра**: підсистема ядра Linux `auditd` перехоплює системні виклики `sys_enter_execve` та `sys_enter_execveat`, фіксуючи повні масиви аргументів незалежно від налаштувань `HISTCONTROL` чи `HISTIGNORE`.
* **Модуль PAM**: `pam_tty_audit` реєструє всі натискання клавіш безпосередньо на рівні термінального драйвера TTY.

## 14. C-API бібліотеки GNU History (libhistory)

Бібліотека GNU History (`libhistory.so`, заголовочний файл `<readline/history.h>`) надає низькорівневий інтерфейс мовою C для керування списками історії, серіалізації файлів та алгоритмічного розкриття рядків у сторонніх C/C++ програмах.

### Структури даних C-API

```
/* Окремий запис історії в купі */
typedef void *histdata_t;

typedef struct _hist_entry {
    char *line;          /* Текстовий рядок команди (ASCII/UTF-8) */
    char *timestamp;     /* Символьне представлення мітки часу або NULL */
    histdata_t data;     /* Довільні контекстні дані користувача */
} HIST_ENTRY;

/* Стан підсистеми історії */
typedef struct _history_state {
    HIST_ENTRY **entries; /* Динамічний масив покажчиків на записи */
    int offset;           /* Поточна позиція ітератора */
    int length;           /* Поточна кількість елементів у масиві */
    int size;             /* Виділена ємність масиву (capacity) */
    int flags;            /* Внутрішні прапорці стану */
} HISTORY_STATE;
```

```cpp
// Приклад використання GNU History API мовою C++
#include <iostream>
#include <string>
#include <memory>
#include <stdexcept>
#include <readline/history.h>

class HistoryManager {
public:
    HistoryManager() {
        using_history();
    }

    ~HistoryManager() {
        clear_history();
    }

    void add(const std::string& cmd) {
        add_history(cmd.c_str());
    }

    std::string expand(const std::string& expr) {
        char* raw_output = nullptr;
        int status = history_expand(const_cast<char*>(expr.c_str()), &raw_output);
        
        if (status < 0) {
            if (raw_output) {
                std::string err_msg(raw_output);
                free(raw_output);
                throw std::runtime_error("Синтаксична помилка: " + err_msg);
            }
            throw std::runtime_error("Помилка розкриття історії");
        }

        std::string result(raw_output ? raw_output : expr);
        free(raw_output);
        return result;
    }

    void saveToFile(const std::string& filepath) {
        if (write_history(filepath.c_str()) != 0) {
            throw std::runtime_error("Не вдалося зберегти історію у файл: " + filepath);
        }
    }
};

int main() {
    try {
        HistoryManager hist;
        hist.add("tar -czf backup.tar.gz /var/data");
        hist.add("sha256sum backup.tar.gz");

        std::string test_expr = "ls -lh !sha256sum:$";
        std::cout << "Вхідний вираз:  " << test_expr << "\n";
        std::cout << "Розкритий рядок: " << hist.expand(test_expr) << "\n";

        hist.saveToFile("/tmp/test_cpp_history.log");
    } catch (const std::exception& ex) {
        std::cerr << "Виняток: " << ex.what() << "\n";
        return 1;
    }
    return 0;
}
```
