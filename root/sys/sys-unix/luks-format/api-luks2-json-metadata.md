# 📋 Специфікація JSON-метаданих та об'єктів формату LUKS2

Метадані формату LUKS2 зберігаються у відкритому вигляді безпосередньо за 4-кілобайтним бінарним заголовком `luks2_hdr_disk`. Вони являють собою валідний текстовий документ JSON у кодуванні UTF-8, доповнений нульовими байтами (`0x00`) до повного розміру службової зони метаданих (за замовчуванням 4 МіБ мінус 4 КіБ = 4 190 208 байтів). Метадані формують зв'язний орієнтований граф, у якому об'єкти посилаються один на одного за числовими або рядковими ідентифікаторами.

## Загальна топологія документа

Кореневий JSON-документ містить п'ять обов'язкових та опціональних словників:

```json
{
  "keyslots": {},
  "tokens": {},
  "segments": {},
  "digests": {},
  "config": {}
}
```

```
┌───────────────────────────────────────────────────────────┐
│                       JSON METADATA                       │
│                                                           │
│  ┌──────────────┐         ┌─────────────┐                 │
│  │   tokens     │────────▶│  keyslots   │                 │
│  │ (tpm2/fido2) │         │ (Argon2id)  │                 │
│  └──────────────┘         └──────┬──────┘                 │
│                                  │                        │
│                                  ▼                        │
│                           ┌─────────────┐                 │
│                           │   digests   │                 │
│                           │  (PBKDF2)   │                 │
│                           └──────┬──────┘                 │
│                                  │                        │
│                                  ▼                        │
│                           ┌─────────────┐                 │
│                           │  segments   │                 │
│                           │(dm-crypt/XTS│                 │
│                           └─────────────┘                 │
└───────────────────────────────────────────────────────────┘
```

## 1. Об'єкт `keyslots` (Слоти ключів)

Словник `keyslots` містить перелік замкових шпарин, пронумерованих рядковими ключами (`"0"`, `"1"`, ...). Кожен слот описує параметри автентифікації, алгоритм розтягування пароля та фізичне розташування зашифрованої копії головного ключа тому (Master Key).

### Поля слота типу `luks2`

| Поле | Тип | Опис та допустимі значення |
| :--- | :--- | :--- |
| `type` | String | Тип слота: `"luks2"` (стандартний слот) або `"reencrypt"` (слот онлайн-перешифрування). |
| `key_size` | Integer | Розмір ключа розшифрування шпарини (VKDK) у байтах (`64` для AES-XTS-512). |
| `priority` | Integer | Пріоритет перебору слота під час відкриття тома (`0` — вимкнено, `1` — нормальний, `2` — високий). |
| `af` | Object | Конфігурація алгоритму розщеплення інформації AFSplit. |
| `area` | Object | Фізичні параметри бінарного зберігання смуг на диску. |
| `kdf` | Object | Параметри функції розтягування пароля (Key Derivation Function). |

### Вкладений об'єкт `af` (Anti-Forensic Splitter)

```json
"af": {
  "type": "luks1",
  "stripes": 4000,
  "hash": "sha256"
}
```

* `type` (String) — алгоритм розщеплення (завжди `"luks1"`, що відповідає дифузійному розщепленню Клеменса Фрувірта).
* `stripes` (Integer) — кількість смуг розщеплення (за замовчуванням `4000`).
* `hash` (String) — криптографічна геш-функція дифузії (`"sha256"`, `"sha512"`).

### Вкладений об'єкт `area` (Розмітка області шпарини)

```json
"area": {
  "type": "raw",
  "offset": "32768",
  "size": "262144",
  "encryption": "aes-xts-plain64",
  "key_size": 64
}
```

* `type` (String) — тип області збереження (завжди `"raw"`).
* `offset` (String) — абсолютний зсув початку бінарних смуг від початку диска в байтах (рядковий формат 64-бітного числа).
* `size` (String) — розмір області смуг у байтах (`stripes * key_size`, наприклад `4000 * 64 = 256000` з вирівнюванням до 262144 байтів / 256 КіБ).
* `encryption` (String) — шифр підсистеми `dm-crypt`, яким зашифровано смуги шпарини на диску (зазвичай `"aes-xts-plain64"` або `"aes-cbc-essiv:sha256"`).
* `key_size` (Integer) — розмір ключа шифрування області в байтах.

### Вкладений об'єкт `kdf` (Параметри Argon2 / PBKDF2)

```json
"kdf": {
  "type": "argon2id",
  "time": 4,
  "memory": 1048576,
  "cpus": 4,
  "salt": "u8+3F...k=",
  "hash": "sha256"
}
```

* `type` (String) — тип функції формування ключа: `"argon2id"` (гібридний режим за замовчуванням), `"argon2i"` (режим із захистом від сторонніх каналів) або `"pbkdf2"` (класичний обчислювальний режим сумісності).
* `time` (Integer) — кількість проходів за часом (ітерацій).
* `memory` (Integer) — обсяг оперативної пам'яті в кілобайтах (наприклад, `1048576` = 1 ГБ).
* `cpus` (Integer) — кількість паралельних потоків обчислення.
* `salt` (String) — криптографічна сіль у кодуванні Base64 (мінімум 16 байтів).
* `hash` (String) — базова геш-функція для PBKDF2 або внутрішніх перетворень Argon2.

## 2. Спеціальний слот `reencrypt` (Онлайн-перешифрування)

Під час виконання операції онлайн-перешифрування тома без зупинки вводу-виводу у словнику `keyslots` створюється динамічний об'єкт типу `"reencrypt"`.

```json
"reencrypt": {
  "mode": "reencrypt",
  "direction": "forward",
  "resilience": "journal",
  "hash": "sha256",
  "alignment": 4096,
  "device_size": "10737418240",
  "progress": "41943040"
}
```

* `mode` (String) — режим перешифрування: `"reencrypt"` (зміна ключа), `"encrypt"` (первинне шифрування відкритого тома) або `"decrypt"` (розшифрування).
* `direction` (String) — напрямок руху зміщення (`"forward"` від початку до кінця, або `"backward"`).
* `resilience` (String) — метод захисту від збоїв живлення: `"journal"` (транзакційний журнал на диску), `"checksum"` або `"none"`.
* `progress` (String) — поточне зміщення в байтах, до якого дані вже перешифровано новим Master Key.

## 3. Об'єкт `digests` (Контрольні дайджести)

Словник `digests` забезпечує миттєву перевірку правильності відновленого Master Key без необхідності розшифровувати та монтувати весь розділ файлової системи.

```json
"digests": {
  "0": {
    "type": "pbkdf2",
    "keyslots": ["0", "1"],
    "segments": ["0"],
    "salt": "vG9...A==",
    "digest": "pW7...8=",
    "iterations": 125000,
    "hash": "sha256"
  }
}
```

* `type` (String) — алгоритм гешування дайджесту (завжди `"pbkdf2"`).
* `keyslots` (Array of Strings) — масив ідентифікаторів слотів ключів, які захищають цей Master Key.
* `segments` (Array of Strings) — масив сегментів даних, які розшифровуються цим Master Key.
* `salt` (String) — випадкова сіль у кодуванні Base64.
* `digest` (String) — контрольний геш від Master Key у кодуванні Base64.
* `iterations` (Integer) — кількість ітерацій PBKDF2 для обчислення дайджесту.
* `hash` (String) — алгоритм гешування (`"sha256"` або `"sha512"`).

## 4. Об'єкт `segments` (Сегменти даних)

Словник `segments` описує розташування, межі та криптографічні параметри розшифрування корисного навантаження (користувацьких даних) на блоковому пристрої.

```json
"segments": {
  "0": {
    "type": "crypt",
    "offset": "16777216",
    "size": "dynamic",
    "iv_tweak": "0",
    "encryption": "aes-xts-plain64",
    "sector_size": 4096,
    "flags": [],
    "integrity": {
      "type": "hmac",
      "journal_encryption": "none",
      "journal_integrity": "none"
    }
  }
}
```

* `type` (String) — тип сегмента: `"crypt"` (зашифрований том dm-crypt) або `"linear"` (лінійне наскрізне відображення).
* `offset` (String) — зсув початку зашифрованих даних від нульового сектора носія в байтах (наприклад, `"16777216"` = 16 МіБ).
* `size` (String) — довжина сегмента в байтах або ключове слово `"dynamic"` (сегмент займає весь доступний залишок простору до кінця розділу).
* `iv_tweak` (String) — початкове зміщення для лічильника вектора ініціалізації секторів.
* `encryption` (String) — криптографічна специфікація ядра Linux (`"aes-xts-plain64"`, `"aes-cbc-essiv:sha256"` або специфікація AEAD).
* `sector_size` (Integer) — розмір логічного сектора криптографічного перетворення в байтах (`512`, `1024`, `2048`, `4096`).
* `flags` (Array of Strings) — додаткові прапорці сегмента (наприклад, `["backup-final-metadata"]` під час зміни розміру або перешифрування).
* `integrity` (Object, опціонально) — конфігурація шару `dm-integrity` (містить тип контролю цілісності, розмір тегу на сектор, параметри шифрування журналу).

## 5. Об'єкт `tokens` (Апаратні токени та плагіни)

Словник `tokens` містить описи зовнішніх механізмів автентифікації, прив'язаних до конкретних слотів ключів.

### Токен TPM2 (`systemd-tpm2`)

```json
"tokens": {
  "0": {
    "type": "systemd-tpm2",
    "keyslots": ["1"],
    "tpm2-blob": "h7F...9A=",
    "tpm2-policy-hash": "a4b...2f=",
    "tpm2-pcr-mask": 133,
    "tpm2-pcr-bank": "sha256",
    "tpm2-primary-alg": "ecc"
  }
}
```

* `type` (String) — тип токена: `"systemd-tpm2"`.
* `keyslots` (Array of Strings) — перелік слотів ключів, які можуть бути розблоковані цим токеном.
* `tpm2-blob` (String) — запечатаний апаратним ключем TPM2 бінарний секрет у кодуванні Base64.
* `tpm2-pcr-mask` (Integer / Array) — бітова маска або список номерів регістрів PCR, до поточного стану яких прив'язане розпечатування (наприклад, `0` для BIOS/Firmware + `7` для Secure Boot).

### Токен FIDO2 (`systemd-fido2`)

```json
"tokens": {
  "1": {
    "type": "systemd-fido2",
    "keyslots": ["2"],
    "fido2-credential": "m9K...==",
    "fido2-salt": "q1W...==",
    "fido2-rp": "io.systemd.cryptsetup",
    "fido2-clientPin-required": true,
    "fido2-up-required": true
  }
}
```

* `fido2-credential` (String) — ідентифікатор облікового запису апаратного ключа FIDO2.
* `fido2-salt` (String) — криптографічна сіль для розширення `hmac-secret`.
* `fido2-clientPin-required` (Boolean) — вимога введення локального PIN-коду ключа.
* `fido2-up-required` (Boolean) — вимога підтвердження фізичної присутності користувача (дотик до сенсора ключа).

### Токен смарткарт PKCS#11 (`systemd-pkcs11`)

```json
"tokens": {
  "2": {
    "type": "systemd-pkcs11",
    "keyslots": ["3"],
    "pkcs11-uri": "pkcs11:model=PKCS%2315;manufacturer=Yubico;serial=123456",
    "pkcs11-key": "a9B...=="
  }
}
```

* `pkcs11-uri` (String) — уніфікований ідентифікатор ресурсу URI за стандартом RFC 7512 для пошуку відкритого ключа та сертифіката на смарткарті.
* `pkcs11-key` (String) — зашифрований асиметричним відкритим ключем токена RSA/ECC симетричний секрет розблокування шпарини.

## 6. Об'єкт `config` (Системна конфігурація)

Словник `config` визначає загальні параметри форматування тома та вимоги до підтримки версій рушія `cryptsetup`.

```json
"config": {
  "json_size": "4190208",
  "keyslots_size": "12582912",
  "flags": [],
  "requirements": [
    "online-reencrypt-v2"
  ]
}
```

* `json_size` (String) — розмір області пам'яті, зарезервованої під JSON-метадані (у байтах).
* `keyslots_size` (String) — розмір бінарної області носія, зарезервованої під смуги слотів ключів (у байтах).
* `flags` (Array of Strings) — інформаційні прапорці стану метаданих.
* `requirements` (Array of Strings) — обов'язкові розширення драйвера, без підтримки яких монтування заборонено (наприклад, `"online-reencrypt-v2"` блокує відкриття застарілими версіями `libcryptsetup`, щоб уникнути пошкодження тома під час міграції).

## 7. Правила валідації та обробка помилок

Під час читання JSON-метаданих парсер `libcryptsetup` виконує обов'язкові перевірки цілісності та структури:

1. **Контроль розміру документа:** документ не повинен перевищувати значення `json_size`. Усі байти після закриваючої фігурної дужки `}` аж до кінця виділеної області зобов'язані бути занулені (`0x00`).
2. **Перехресна цілісність посилань (Referential Integrity):** кожен ідентифікатор слота в масивах `digests[].keyslots` зобов'язаний існувати у словнику `keyslots`. Будь-яке посилання на неіснуючий сегмент або слот викликає критичну помилку монтування.
3. **Невідомі обов'язкові вимоги:** якщо масив `requirements` містить рядок, не підтримуваний поточною версією ядра або бібліотеки, операція відкриття тома негайно блокується з повідомленням про несумісність версій для захисту даних від пошкодження.
