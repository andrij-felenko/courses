# 📋 Довідник вбудованих функцій, системних змінних та інтерфейсу AWK

Мова AWK надає фіксований набір вбудованих спеціальних змінних для керування станом парсера, системні функції для обробки рядків, виконання чисельних обчислень і бітових операцій, механізми взаємодії з процесами операційної системи, а також прапорці командного рядка для конфігурації середовища виконання. Цей довідник описує стандартний інтерфейс POSIX.1-2008 / POSIX.1-2024 AWK із детальним описом семантики поведінки, крайових випадків, внутрішніх інваріантів, низькорівневої моделі типізації, організації пам'яті та розширень інтерпретатора GNU AWK (`gawk`).

---

## 1. Спеціальні системні змінні

Вбудовані змінні автоматично ініціалізуються інтерпретатором під час запуску програми та оновлюються на кожному кроці циклу обробки записів. Будь-яку з цих змінних можна зчитувати у виразах та змінювати вручну для динамічного керування парсером.

### 1.1 Стандартні системні змінні POSIX

| Змінна | Тип | Значення за замовчуванням | Призначення, семантика та ефекти модифікації |
|---|---|---|---|
| `$0` | Рядок | `""` | Повний вміст поточного вхідного запису (включно з внутрішніми роздільниками, але без кінцевого `RS`). Пряма зміна `$0` призводить до негайного перепарсингу запису на поля `$1..$NF` за поточним правилом `FS`. |
| `$1` .. `$NF` | Рядок / Число | `""` | Позиційні поля поточного запису, виділені за правилами `FS`. Модифікація будь-якого поля `$i` (або створення нового поля `$k` де `k > NF`) призводить до автоматичної перебудови `$0` шляхом конкатенації всіх полів від `$1` до `$NF` через роздільник `OFS`. Звернення до `$i` при `i > NF` повертає порожній рядок `""`. Адресація підтримує довільні вирази: `$(NF-1)`, `$(i+1)`, `$$1` (непряма адресація). |
| `ARGC` | Ціле число | — | Кількість позиційних аргументів командного рядка, переданих інтерпретатору (включно з іменем самої утиліти `awk` на індексі `0`). |
| `ARGV` | Масив | — | 0-індексований масив аргументів командного рядка з ключами від `0` до `ARGC - 1`. Елементи масиву можна зчитувати, змінювати або видаляти (`ARGV[i] = ""`) у блоці `BEGIN` для динамічного керування списком файлів. Аргументи формату `var=value` сприймаються як динамічні присвоєння змінних безпосередньо перед відкриттям відповідного файлу. |
| `CONVFMT` | Рядок | `"%.6g"` | Формат неявного перетворення чисел із плаваючою комою у рядки під час конкатенації (`str = num ""`) або створення ключів масивів (`arr[num]`). Не впливає на інструкцію `print` (для якої діє `OFMT`). |
| `ENVIRON` | Масив | — | Асоціативний масив змінних середовища поточного процесу (наприклад, `ENVIRON["USER"]`, `ENVIRON["PATH"]`). Зміна значень у масиві в `gawk` експортується дочірнім процесам, запущеним через `system()` або конвеєри введення-виведення. |
| `FILENAME` | Рядок | `""` | Ім'я поточного вхідного файлу, з якого зчитуються записи. У блоці `BEGIN` містить порожній рядок `""`. Під час читання зі стандартного вводу містить `"-"` або `""` залежно від реалізації. |
| `FNR` | Ціле число | `0` | Порядковий номер поточного запису у поточному відкритому вхідному файлі. Скидається в `1` під час переходу до першого запису кожного наступного файлу зі списку аргументів. |
| `FS` | Рядок / Regex | `" "` (пробіл) | **Field Separator:** роздільник полів. Визначає правила розбиття `$0` на поля `$1..$NF`. Підтримує три режими роботи: пробіл (група пробілів/табуляцій), одиночний символ (строгий поділ) або регулярний вираз. |
| `NF` | Ціле число | `0` | **Number of Fields:** кількість полів у поточному записі `$0`. Зміна `NF` впливає на склад полів: `NF = 2` обрізає всі поля після другого, а `NF = 10` створює порожні поля від `$3` до `$10` з відповідною регенерацією `$0`. |
| `NR` | Ціле число | `0` | **Number of Records:** глобальний лічильник прочитаних записів від моменту старту програми через усі оброблені вхідні файли. |
| `OFMT` | Рядок | `"%.6g"` | Формат виводу чисел із плаваючою комою за допомогою простої інструкції `print`. Не застосовується у викликах `printf` або `sprintf`. |
| `OFS` | Рядок | `" "` (пробіл) | **Output Field Separator:** роздільник полів під час виводу через `print expr1, expr2` та під час регенерації `$0` після модифікації позиційних полів `$i`. |
| `ORS` | Рядок | `"\n"` | **Output Record Separator:** роздільник записів під час виводу інструкцією `print`. Додається автоматично в кінець кожного друкованого рядка. |
| `RLENGTH` | Ціле число | `-1` | Довжина у символах знайденого фрагмента після виклику функції `match()`. Якщо збігу не знайдено — встановлюється у `-1`. |
| `RSTART` | Ціле число | `0` | Початкова 1-індексована позиція першого символу знайденого фрагмента після виклику `match()`. Якщо збігу не знайдено — встановлюється у `0`. |
| `RS` | Рядок / Regex | `"\n"` | **Record Separator:** роздільник вхідних записів. У стандарті POSIX — один символ. При `RS = ""` вмикається режим абзаців (paragraph mode). У `gawk` може містити регулярний вираз довільної складності. |
| `SUBSEP` | Рядок | `"\034"` (ASCII 0x1C) | **Subscript Separator:** невидимий роздільник, який використовується для конкатенації індексів у багатовимірних масивах виду `arr[i, j]` (фактично формує одновимірний ключ `i SUBSEP j`). |

### 1.2 Розширення системних змінних GNU AWK (Gawk)

| Змінна | Тип | Значення за замовчуванням | Призначення та семантика у `gawk` |
|---|---|---|---|
| `ARGIND` | Ціле число | `0` | Порядковий індекс поточного оброблюваного файлу в масиві аргументів `ARGV`. Дозволяє однозначно ідентифікувати файл навіть за наявності повторюваних імен у списку аргументів (`FILENAME == ARGV[ARGIND]`). |
| `BINMODE` | Ціле число | `0` | Режим бінарного вводу/виводу для платформ, що розрізняють текстові та бінарні файли (Windows/DOS): `1` — читання без трансляції `\r\n`, `2` — бінарний запис, `3` — бінарне читання та запис. |
| `ERRNO` | Рядок | `""` | Текстовий опис системної помилки (`strerror(errno)`) після невдалого виклику `getline`, збою команди `close()`, помилки відкриття файлу/каналу або операцій із мережевими сокетами. |
| `FIELDWIDTHS` | Рядок | `""` | Пробіло-розділений список фіксованих ширин колонок (наприклад, `"4 2 2 10"` або `"8 4:4 12"` із пропуском колонок). Вмикає режим позиційного розбору записів фіксованої ширини, повністю ігноруючи `FS`. |
| `FPAT` | Рядок / Regex | `""` | **Field Pattern:** регулярний вираз, що описує структуру самого вмісту полів (а не роздільників між ними). Застосовується для парсингу структурованого тексту на кшталт CSV: `FPAT = "([^,]+)|(\"[^\"]+\")"`. Має вищий пріоритет над `FS`. |
| `FUNCTAB` | Масив | — | Асоціативний масив, ключами якого є імена всіх вбудованих та визначених користувачем функцій програми. Дозволяє перевіряти існування функцій або здійснювати непрямі виклики через змінні. |
| `IGNORECASE` | Ціле число | `0` | При ненульовому значенні (`1`) вмикає регістронезалежний режим для всіх регулярних виразів, операторів `~` та `!~`, правил розбиття `FS`, `RS`, `FPAT` та функцій `sub`, `gsub`, `gensub`, `match`, `split`, `patsplit`. |
| `LINT` | Ціле число / Рядок | `0` | Керування динамічним виводом попереджень lint під час виконання: `0` — вимкнено, `1` — динамічні попередження про підозрілі конструкції (неініціалізовані змінні, сумнівні перетворення), `"fatal"` або `2` — перетворення попереджень lint на фатальні помилки. |
| `PREC` | Ціле число | `53` | Рівень точності в бітах для арифметики довільної точності (MPFR), коли `gawk` запущено з прапорцем `-M` / `--bignum`. |
| `PROCINFO` | Масив | — | Спеціальний асоціативний масив метаданих середовища та стану процесу (PID, UID, версія, стан сокетів, режим сортування масивів `PROCINFO["sorted_in"]`). |
| `ROUNDMODE` | Рядок | `"N"` | Режим округлення для MPFR у режимі `-M`: `"N"` (до найближчого), `"Z"` (до нуля), `"U"` (до плюс нескінченності), `"D"` (до мінус нескінченності). |
| `RT` | Рядок | `""` | **Record Terminator:** фактична послідовність символів вхідного потоку, що збіглася з роздільником записів `RS` (особливо актуально, коли `RS` задано регулярним виразом). |
| `SYMTAB` | Масив | — | Асоціативний масив усіх глобальних змінних та масивів програми (ключ — ім'я змінної у вигляді рядка). Дозволяє динамічно зчитувати та модифікувати змінні за їхніми текстовими назвами (`SYMTAB["FS"] = ","`). |
| `TEXTDOMAIN` | Рядок | `"messages"` | Текстовий домен для локалізації повідомлень за допомогою GNU `gettext`. Використовується рядковими функціями інтернаціоналізації. |

### 1.3 Поглиблений аналіз семантики та крайових випадків

#### Режими розбиття полів через `FS`
Механізм розбиття поточного запису `$0` на позиційні поля `$1..$NF` визначається значенням змінної `FS`:

1. **Одиночний пробіл (`FS = " "`):**
   - Спеціальний режим за замовчуванням у стандарті POSIX AWK.
   - Роздільником вважається будь-яка неперервна послідовність пробілів та знаків табуляції (`[ \t]+`).
   - Будь-які ведучі та кінцеві пробіли або табуляції запису `$0` автоматично відтинаються інтерпретатором і не утворюють порожніх полів на початку (`$1`) чи в кінці (`$NF`).
2. **Одиночний непробільний символ (`FS = ","` або `FS = ":"`):**
   - Розбиття здійснюється строго за кожним окремим входженням вказаного символу.
   - Дві коми поспіль (`",,"`) породжують порожнє поле `""`.
   - Символ роздільника на початку запису утворює порожнє поле `$1 = ""`, а роздільник наприкінці запису утворює порожнє поле `$NF = ""`.
   - Пробіли навколо роздільника не видаляються і входять до складу відповідних полів.
3. **Регулярний вираз (`FS = "[,\t:]+"` або `FS = " +"`):**
   - Поля розділяються будь-яким непорожнім текстовим фрагментом, що відповідає вказаному регулярному виразу.
   - Якщо регулярний вираз збігається з текстом на початку або в кінці запису, інтерпретатор створює порожні поля `$1 = ""` або `$NF = ""`.
4. **Строгий поділ по одиночних пробілах:**
   - Для того щоб відключити спеціальний режим відтинання пробілів і розбивати текст строго по одиночних символах пробілу, використовується регулярний вираз із квадратними дужками: `FS = "[ ]"`.

#### Позиційний розбір та виділення вмісту (`FIELDWIDTHS` і `FPAT` у Gawk)

GNU AWK надає два спеціалізовані механізми виділення полів, які повністю замінюють собою дію `FS`, коли структура вхідних даних не спирається на прості символи-роздільники:

##### 1. Специфікація розбору фіксованої ширини (`FIELDWIDTHS`)

Змінна `FIELDWIDTHS` задає рядок позиційних правил розбиття вхідного запису на поля фіксованої довжини. Вона призначена для обробки вивантажень реляційних СУБД, журналів фіксованого формату, банківських реєстрів та мейнфрейм-потоків (COBOL copybook layouts, ASCII/EBCDIC fixed-width extracts).

###### Граматика та синтаксис специфікатора:
Рядок `FIELDWIDTHS` складається з елементів, розділених пробілами:
- **`N` (ціле додатне число):** виділяє поле довжиною рівно `N` символів або байтів.
- **`skip:len`:** перед виділенням поля довжиною `len` пропускає `skip` символів у вхідному потоці. Пропущені символи не потрапляють у жодну позиційну змінну `$i` і не збільшують лічильник `NF`.
- **`*` (зірочка на останній позиції):** призначає останньому полю `$NF` весь нерозібраний залишок поточного запису `$0`.

```awk
# Приклад конфігурації складного змішаного розбору:
# $1: перші 8 символів
# пропуск 4 символів, після чого $2: наступні 10 символів
# $3: наступні 6 символів
# $4: весь залишок рядка до кінця запису
BEGIN { FIELDWIDTHS = "8 4:10 6 *" }
```

###### Внутрішній стан та пріоритет вибору парсера:
- Присвоєння непустого значення `FIELDWIDTHS` негайно перемикає рушій парсингу GNU AWK у позиційний режим. Значення `PROCINFO["FS"]` набуває рядка `"FIELDWIDTHS"`, а змінні `FS` та `FPAT` тимчасово деактивуються.
- Якщо згодом у коді виконується явне присвоєння `FS` або `FPAT`, змінна `FIELDWIDTHS` автоматично скидається в порожній рядок `""`, а `PROCINFO["FS"]` оновлюється відповідно до `"FS"` або `"FPAT"`.
- Якщо рядок запису `$0` коротший за суму всіх ширин у `FIELDWIDTHS`, інтерпретатор виділяє стільки полів, на скільки вистачило фактичної довжини рядка. Останнє частково покрите поле отримує наявні байти, а для наступних полів повертається порожній рядок `""`, при цьому `NF` встановлюється за фактично сформованими полями.

###### Багатобайтовий UTF-8 проти однобайтового режиму (`gawk -b`):
- За замовчуванням у сучасних Linux-системах зі встановленою UTF-8 локаллю (`LC_ALL=uk_UA.UTF-8` або `en_US.UTF-8`) інтерпретатор `gawk` вимірює ширину колонок у **логічних Unicode-символах** (`wchar_t`), викликаючи системну функцію `mbrtowc(3)` для кожного символу вхідного буфера.
- Для мейнфрейм-вивантажень та банківських файлів, закодованих у фіксованій однобайтовій сітці (наприклад, перетворений EBCDIC IBM 1047 / CP037, ISO 8859-1, Windows-1251 або двійкові пакети), зміщення полів строго прив'язані до **фізичних байтів**, а не UTF-8 символів. Наявність кирилиці або спецсимволів у UTF-8 зміщує всі наступні позиційні поля через варіативну довжину символів (2–4 байти на кодову точку).
- **Інженерне правило:** під час обробки фіксованих транзакційних файлів обов'язково запускайте Gawk з прапорцем байтового режиму `-b` (`--characters-as-bytes`) або встановлюйте `LC_ALL=C`. Це вимикає валідацію багатобайтових послідовностей, гарантує строгу побайтову адресацію зміщень і прискорює парсинг у 3–4 рази:
  ```bash
  LC_ALL=C gawk -b -f parse_mainframe.awk transactions_fixed.dat
  ```

###### Банківські та мейнфрейм-вивантаження (COBOL/EBCDIC Fixed Records):
У фінансових та облікових системах типи даних часто мають специфічне кодування:
1. **Текстові поля (`PIC X(n)`):** доповнюються пробілами праворуч (`"INV-10940  "`).
2. **Числові поля без знака (`PIC 9(n)`):** доповнюються нулями ліворуч (`"000045000"`).
3. **Фіксована крапка (`PIC 9(7)V99`):** у файлі зберігається 9 цифр без символу крапки (`"000045099"` = `450.99 грн`). Для перетворення у дійсне число виконується арифметичне ділення: `$amount = $raw / 100`.
4. **Знакові поля з кінцевим знаком (Trailing Sign / Signed Decimal, `PIC S9(7)V99 SIGN TRAILING`):** знак розташовується в останньому байті колонки (`"00045000+"` або `"00012050-"`).
5. **Кредитові/дебетові суфікси:** значення супроводжуються дволітерними маркерами `CR` (кредит, від'ємний баланс) або `DB` (дебет): `" 14500.25CR"`.

```awk
# worked_example: Повний конвеєр розбору 80-байтового мейнфрейм-реєстру транзакцій
# Формат запису (80 байтів):
# [01-10] (10 симв): Номер рахунку (Account ID)
# [11-18] (8 симв):  Дата транзакції YYYYMMDD
# [19-22] (4 симв):  Код валюти ISO 4217 (UAH , USD )
# [23-34] (12 симв): Сума з неявною комою PIC S9(10)V99 з кінцевим знаком (+/-)
# [35-36] (2 симв):  Пропуск службового заголовка
# [37-46] (10 симв): Код операції (Mcc code)
# [47-80] (34 симв): Опис транзакції

BEGIN {

    FIELDWIDTHS = "10 8 4 12 2:10 *"
    OFS = "\t"
    total_uah = 0
}

function trim(str) {
    gsub(/^[ \t]+|[ \t]+$/, "", str)
    return str
}

function parse_signed_amount(raw_str,    len, sign, num_part, val) {

    len = length(raw_str)
    sign = substr(raw_str, len, 1)
    num_part = substr(raw_str, 1, len - 1)
    
    val = (num_part + 0) / 100
    if (sign == "-") {
        val = -val
    }
    return val
}

{

    currency = trim($3)

    mcc_code = trim($5)
    desc     = trim($6)

    if (currency == "UAH") {
        total_uah += amount
    }

    printf "%-10s | %s | %3s | %12.2f | %-10s | %s\n", \
           acc_id, tx_date, currency, amount, mcc_code, desc
}

END {
    print "-------------------------------------------------------------------------------"
    printf "Підсумковий баланс UAH: %.2f\n", total_uah
```

##### 2. Специфікація розбору структурованого тексту за шаблоном полів (`FPAT`)

Змінна `FPAT` (Field Pattern) визначає регулярний вираз, що описує лексичну структуру **вмісту самого поля**, а не роздільників між полями.

###### Принцип роботи лексичного сканера `FPAT`:
- Під час розбиття запису `$0` інтерпретатор послідовно зіставляє регулярний вираз `FPAT` із текстом запису зліва направо.
- Кожен непорожній збіг шаблону утворює чергове позиційне поле: перший збіг стає `$1`, другий — `$2`, і так далі до `$NF`.
- Текст між збігами розглядається як роздільники й ігнорується (якщо не використовується функція `patsplit()`, яка зберігає їх у масиві `seps`).
- Встановлення `FPAT` встановлює `PROCINFO["FS"] = "FPAT"` та вимикає `FS` і `FIELDWIDTHS`.

###### Граматика RFC 4180 CSV:
Стандарт RFC 4180 визначає дві форми полів у форматі CSV:
1. **Просте поле:** послідовність будь-яких символів, крім коми, лапок та переводу рядка: `[^,\r\n]+`.
2. **Екрановане поле в подвійних лапках:** починається і закінчується подвійними лапками `"..."`, може містити всередині коми, пробіли, символи переходу рядка, а також подвоєні лапки `""` як екранування символу `"`. Регулярний вираз: `\"([^\"]|\"\")*\"`.

###### Канонічний вираз FPAT для CSV:
```awk
BEGIN {
    FPAT = "([^,]+)|(\"([^\"]|\"\")*\")"
}
```

###### Критичні крайові випадки та пастки `FPAT`:

1. **Порожні поля між суміжними комами (`"alpha,,gamma"`):**
   - **Проблема:** Регулярний вираз `[^,]+` вимагає наявності щонайменше одного символу (`+`). Якщо у вхідному рядку зустрічаються дві коми поспіль (`",,"`), сканер `FPAT` не знаходить збігу між ними і пропускає порожню позицію.
   - **Наслідок:** Запис `"10,,Developer"` створює лише два поля: `$1 = "10"`, `$2 = "Developer"`, `NF = 2`. Позиція третього поля зміщується на другу, що руйнує відповідність колонок схемі таблиці!
   - **Розв'язання:** Для повного контролю порожніх полів використовують функцію `patsplit()` із масивом роздільників `seps` або застосовують повнофункціональну бібліотеку `@load "csv"`.

2. **Вкладені символи переходу рядка (`\n` / `\r\n`) всередині лапок:**
   - **Проблема:** Стандартний цикл AWK ділить вхідний потік на записи за символом `RS = "\n"`. Якщо поле в лапках містить перехід рядка (наприклад, багаторядковий коментар у базі даних), рядок розривається посередині комірки:
     ```csv
     101,"Київ, вул. Хрещатик
     будинок 1, офіс 42",Active
     ```
     Інтерпретатор сприймає це як два поламані незалежні записи: перший рядок не має закриваючої лапки, а другий не має початкової.
   - **Розв'язання через багаторядковий `RS` та парність лапок:**
     Встановлення спеціального режиму накопичення рядків через `getline` до відновлення парності лапок.

###### Функція зняття лапок та розпакування екранування (Unquoting):
Коли поле зчитане через `FPAT`, воно зберігає обрамляючі подвійні лапки та внутрішні подвоєння `""`. Для очищення даних застосовують нормалізатор:

```awk
function csv_unquote(val) {
    if (val ~ /^".*"$/) {
        val = substr(val, 2, length(val) - 2) # Відтинаємо початкову і кінцеву лапки
        gsub(/""/, "\"", val)                 # Замінюємо подвійні лапки на одинарні
    }
    return val
}
```

```awk
# worked_example: Повнофункціональний стійкий потоковий парсер складних CSV-файлів
# Підтримує: коми в лапках, екрановані подвійні лапки "", багаторядкові поля з переходом \n

BEGIN {
    FPAT = "([^,]+)|(\"([^\"]|\"\")*\")"
    OFS = " | "
}

# Допоміжна функція перевірки балансу подвійних лапок у буфері
function is_quote_balanced(str,    tmp) {
    tmp = str
    # Рахуємо кількість символів подвійних лапок
    return (gsub(/"/, "&", tmp) % 2 == 0)
}

function normalize_csv_field(f) {
    if (f ~ /^".*"$/) {
        f = substr(f, 2, length(f) - 2)
        gsub(/""/, "\"", f)
    }
    return f
}

{
    record_buffer = $0

    # Якщо кількість лапок непарна — запис містить перехід рядка всередині лапок.
    # Дочитуємо наступні рядки з потоку до закриття лапок:
    while (!is_quote_balanced(record_buffer)) {
        if ((getline next_line) <= 0) {
            # Досягнуто EOF при незакритих лапках — пошкоджений файл
            print "ПОМИЛКА: Незбалансовані лапки на рядку " NR > "/dev/stderr"
            break
        }
        record_buffer = record_buffer "\n" next_line
    }

    # Перепарсимо зібраний багаторядковий запис через patsplit
    n_fields = patsplit(record_buffer, fields, FPAT)

    printf "Запис #%d (полів: %d):\n", ++rec_count, n_fields
    for (i = 1; i <= n_fields; i++) {
        clean_val = normalize_csv_field(fields[i])
        # Замінюємо внутрішні \n на пробіл для компактного відображення звіту
        gsub(/\n/, "\\n", clean_val)
        printf "  [$%d] = %s\n", i, clean_val
    }
}
```

#### Режим абзаців (`RS = ""`) та робота з `RT`
1. **Режим абзаців (`RS = ""`):**
   - Записи розділяються одним або кількома послідовними порожніми рядками (`\n\n+`).
   - Будь-які ведучі порожні рядки на початку файлу автоматично відкидаються.
   - Якщо `FS` має стандартне значення `" "` (пробіл), символ переходу на новий рядок `\n` автоматично додається до списку роздільників полів разом із пробілом і табуляцією (`[ \t\n]+`). Кожен рядок всередині абзацу автоматично розбивається на окремі поля.
2. **Роздільник записів як регулярний вираз у Gawk:**
   - У `gawk` змінній `RS` можна присвоїти регулярний вираз: `RS = "\r?\n|;;"`.
   - Змінна `RT` автоматично отримує фактичний текст роздільника, який відокремив поточний запис від наступного. Це дозволяє точно реконструювати вхідний потік байт у байт:
     ```awk
     { printf "%s%s", $0, RT }
     ```

#### Багатовимірні масиви та `SUBSEP`
Стандарт POSIX AWK реалізує асоціативні масиви як пласкі одновимірні хеш-таблиці з рядковими ключами. Синтаксис багатовимірної індексації є синтаксичним цукром:
- Вираз `arr[i, j, k]` автоматично перетворюється на звернення за єдиним спільним рядковим ключем:
  ```
  key = i SUBSEP j SUBSEP k
  ```
- Значення `SUBSEP` за замовчуванням дорівнює `"\034"` (ASCII Unit Separator, 0x1C). Цей байт практично ніколи не зустрічається у друкованому тексті, що виключає колізії ключів.
- Перевірка наявності ключа виконується через оператор `in`:
  ```awk
  if ((i, j) in arr) {
      print arr[i, j]
  }
  ```

#### Повний опис структури метамасиву `PROCINFO` у Gawk та інтроспекція середовища

Масив `PROCINFO` у GNU AWK є багаторівневою структурою метаданих, що надає програмі прямий доступ до системного оточення, параметрів процесу, внутрішнього стану парсера, таблиці ідентифікаторів та підсистем чисельних обчислень.

##### 1. Ідентифікатори процесу, платформи та версії API
```awk
PROCINFO["pid"]          # PID поточного процесу awk (getpid(2))
PROCINFO["ppid"]         # PID батьківського процесу (getppid(2))
PROCINFO["pgrpid"]       # ID групи процесів поточного процесу (getpgrp(2))
PROCINFO["uid"]          # Реальний ідентифікатор користувача (getuid(2))
```

##### 2. Сирі аргументи командного рядка (`PROCINFO["argv"]`)
На відміну від масиву `ARGV`, який містить лише позиційні імена файлів та динамічні присвоєння `var=val` після того, як інтерпретатор відсіяв власні прапорці запуску (`-F`, `-v`, `-f`, `-M`), масив `PROCINFO["argv"]` зберігає повний оригінальний вектор аргументів процесу в тому вигляді, в якому його було передано ядром ОС через системний виклик `execve(2)`:
```awk
# Якщо запуск виконано як: gawk -F: -v DEBUG=1 -f script.awk input.txt
BEGIN {
    # ARGV містить лише: ARGV[0]="gawk", ARGV[1]="input.txt"
    # PROCINFO["argv"] містить повний зліпок переданих параметрів:
    for (i = 0; i in PROCINFO["argv"]; i++) {
        print "argv[" i "] =", PROCINFO["argv"][i]
    }
    # Виведе:
    # argv[0] = gawk
    # argv[1] = -F:
    # argv[2] = -v
    # argv[3] = DEBUG=1
    # argv[4] = -f
    # argv[5] = script.awk
    # argv[6] = input.txt
}
```

##### 3. Інтроспекція таблиці символів (`PROCINFO["identifiers"]`)
Масив `PROCINFO["identifiers"]` надає повний зліпок глобальної таблиці імен програми, зіставляючи кожному відомому ідентифікатору його поточний статус типізації:
- `"untyped"` — змінна була згадана в коді або списку параметрів функцій, але ще не отримала ані скалярного значення, ані статусу асоціативного масиву (неініціалізована комірка).
- `"scalar"` — глобальна або користувацька змінна, що містить скалярне значення (число, рядок або числовий рядок `strnum`).
- `"array"` — змінна, ініціалізована як асоціативний масив.
- `"builtin"` — вбудована стандартна функція інтерпретатора (`length`, `substr`, `split` тощо).
- `"user"` — функція користувача, оголошена через ключове слово `function`.
- `"extension"` — нативна C/C++ функція, завантажена динамічно через директиву `@load` або прапорець `-l`.

```awk
# Приклад динамічного аналізу середовища виконання:
function custom_calc(x, y,   local_tmp) {
    return x * y + 42
}

BEGIN {
    global_var = 100
    global_arr["key"] = "val"
    
    for (id in PROCINFO["identifiers"]) {
        type = PROCINFO["identifiers"][id]
        if (type ~ /^(user|extension|array)$/) {
            printf "Ідентифікатор: %-20s | Тип: %s\n", id, type
        }
    }
}
```

##### 4. Метадані чисельної підсистеми MPFR/GMP (`PROCINFO["mpfr_version"]`, `PROCINFO["prec_max"]`)
Коли `gawk` скомпільовано з підтримкою розширеної арифметики та запущено з прапорцем `-M` / `--bignum`, у масиві `PROCINFO` з'являються атрибути підсистем GNU MPFR та GNU GMP:
```awk
PROCINFO["mpfr_version"] # Текстовий рядок версії бібліотеки MPFR (наприклад, "4.2.1")
PROCINFO["gmp_version"]  # Текстовий рядок версії бібліотеки GMP (наприклад, "6.3.0")
PROCINFO["prec_max"]     # Максимальна підтримувана точність мантиси в бітах (MPFR_PREC_MAX)
PROCINFO["prec_min"]     # Мінімальна допустима точність у бітах (зазвичай 2)
```
Ці змінні визначають граничні межі, які можна призначати системній змінній `PREC` (за замовчуванням `53` біти для стандартної подвійної точності IEEE 754).

##### 5. Керування порядком обходу масивів у циклі `for (key in arr)`
```awk
PROCINFO["sorted_in"]
```
Допустимі стандартні значення для `PROCINFO["sorted_in"]`:
- `"@val_num_asc"` / `"@val_num_desc"` — сортування за числовими значеннями елементів (висхідний / спадний порядок).
- `"@val_str_asc"` / `"@val_str_desc"` — сортування за рядковими значеннями елементів (лексикографічно).
- `"@val_type_asc"` / `"@val_type_desc"` — сортування за типом значення (число, рядок, масив, регулярний вираз).
- `"@ind_num_asc"` / `"@ind_num_desc"` — сортування за числовими значеннями ключів / індексів.
- `"@ind_str_asc"` / `"@ind_str_desc"` — сортування за рядковими значеннями ключів (лексикографічно).
- `"@unsorted"` — обхід у сирому внутрішньому порядку хеш-таблиці (максимальна швидкодія).
- `name` — ім'я користувацької функції порівняння виду `function cmp_func(idx1, val1, idx2, val2)`.

##### 6. Спеціальні атрибути вводу/виводу, таймаути та псевдотермінали
- `PROCINFO[input_file, "READ_TIMEOUT"]` — таймаут операції читання у мілісекундах для сокетів, іменованих каналів (FIFO) та терміналів. Якщо за вказаний час даних не надійшло, `getline` повертає помилку `-1`, а `ERRNO` встановлюється в `"ETIMEDOUT"`.
- `PROCINFO[input_file, "RETRY"]` — якщо встановлено у `1`, тимчасові помилки `EAGAIN` / `EWOULDBLOCK` / `EINTR` не переривають виконання, а спричиняють автоматичний повтор читання.
- `PROCINFO[command, "pty"]` — якщо встановлено у `1` перед відкриттям двонаправленого каналу `command |& getline`, взаємодія з підпроцесом здійснюється через емульований псевдотермінал (`/dev/pts/*`), що змушує підпроцеси (наприклад, `ssh` або `sudo`) працювати в режимі інтерактивного термінала без блокової буферизації.

#### Масив `ARGV` та відкладені присвоєння
- Елементи `ARGV[1]..ARGV[ARGC-1]` можуть містити імена файлів або присвоєння вигляду `var=value`.
- Якщо аргумент має форму `var=val`, AWK не відкриває файл із такою назвою, а присвоює змінній `var` значення `val` безпосередньо в момент досягнення цього аргументу в списку обробки (після завершення попереднього файлу і перед початком наступного).
- Присвоєння `ARGV[i] = ""` у блоці `BEGIN` вилучає відповідний файл зі списку обробки без зсуву інших індексів.

#### Інтернаціоналізація та `TEXTDOMAIN`
GNU AWK підтримує механізм перекладу рядків через бібліотеку `gettext`:
- `TEXTDOMAIN` визначає ім'я домену повідомлень (каталогу перекладів).
- Рядки, позначені символом підкреслення перед лапками `_"Текст для перекладу"`, автоматично транслюються за поточною локаллю `LC_MESSAGES`.
- Функція `bindtextdomain(dir [, domain])` задає шлях до каталогів `.mo` файлів локалізації.

## 2. Низькорівнева типізація, структура `NODE`/`CELL` та правила порівняння

Мова AWK використовує динамічну модель типізації, побудовану довкола концепції подвійного стану (dual-state value representation). Змінні не мають фіксованого статичного типу, проте кожне значення зберігає метадані про походження, чинну рядкову форму та кешоване чисельне представлення.

### 2.1 Внутрішнє представлення даних (`NODE` / `CELL`)

У кодових базах основних інтерпретаторів AWK кожна змінна, позиційне поле `$i`, аргумент функції та константа описуються універсальною C-структурою:

```c
/* GNU AWK (gawk): struct exp_node (скорочено NODE) */
typedef struct exp_node {
    union {
        struct {
            union {
                char *sp;               /* Покажчик на виділений рядковий буфер */
                struct exp_node *rnode; /* Вузол дерева для непрямих посилань */
            } l;
            size_t slen;                /* Довжина рядка в байтах */
            AWKNUM numbr;               /* 64-бітний double (IEEE 754) або MPFR */
        } val;
    } sub;
    unsigned short flags;               /* Бітові прапорці стану та походження */
    unsigned char type;                 /* Node_val, Node_var, Node_array_ref */
    unsigned long valref;               /* Лічильник посилань для копіювання за записом (CoW) */
} NODE;

/* Fast AWK (mawk): CELL */
typedef struct cell {
    short type;                         /* C_NOINIT, C_STR, C_NUM, C_STRNUM, C_MBSTRN */
    char *ptr;                          /* Покажчик на рядок у буфері або купі */
    size_t len;                         /* Довжина рядка */
    double dval;                        /* Кешоване чисельне значення double */
} CELL;
```

```
                   Внутрішня комірка значення AWK (NODE / CELL)
    ┌────────────────────────────────────────────────────────────────────────┐
    │ Прапорці стану: [ NUMBER | STRING | NUMCUR | STRCUR | USER_INPUT ]     │
    ├────────────────────────────────────┬───────────────────────────────────┤
    │ Числове кешоване поле:             │ Покажчик на текстовий буфер:      │
    │ AWKNUM numbr = 4521.000000;        │ char *sp -> "4521\0"              │
    │ (кешує результат strtod())         │ size_t slen = 4;                  │
    └────────────────────────────────────┴───────────────────────────────────┘
```

Головні бітові прапорці стану в `NODE.flags`:
- **`NUMBER`**: значення було створене як числовий літерал або як результат арифметичної операції.
- **`STRING`**: значення було створене як рядковий літерал або результат рядкової операції (конкатенація, `substr`, `sprintf`).
- **`NUMCUR` (Numeric Current)**: числове поле `numbr` є валідним і синхронізованим з поточним значенням.
- **`STRCUR` (String Current)**: рядковий буфер `sp` та довжина `slen` містять актуальний текст.
- **`USER_INPUT` / `NUMSTR`**: значення отримане безпосередньо з вхідного потоку (запис `$0`, поле `$1..$NF`, результат `getline` або аргумент `ARGV`). Це значення є «числовим рядком» (strnum): воно зчитувалося як текст, але якщо його синтаксис відповідає формату числа, воно бере участь у чисельних порівняннях без явної конвертації.
- **`MALLOC`**: пам'ять під рядок `sp` виділена в купі (`malloc`) і підлягає звільненню під час мутації або видалення змінної.

### 2.2 Двоїсті стани (Dual-State) та кешування типів

Під час виконання програми AWK мінімізує накладні витрати на повторний парсинг рядків за допомогою лінивої синхронізації прапорців:

1. **Читання вхідного поля:**
   Коли рядок зчитується у `$1`, утворюється вузол із прапорцями `USER_INPUT | STRCUR`. Поле `numbr` не ініціалізується, а функція `strtod()` не викликається.
2. **Перше використання в арифметиці (`total += $1`):**
   Інтерпретатор перевіряє прапорець `NUMCUR`. Оскільки його немає, викликається парсер `strtod()`. Отримане значення записується в `numbr`, а до прапорців додається `NUMCUR`. Тепер вузол перебуває у двоїстому стані: і `STRCUR`, і `NUMCUR` активні одночасно.
3. **Наступні арифметичні виклики:**
   Інтерпретатор читає `numbr` безпосередньо з регістрів процесора за `O(1)` без виклику системних бібліотек конвертації.
4. **Рядкова мутація (`$1 = $1 "_suffix"`):**
   Виділяється новий буфер пам'яті, записується новий текст, встановлюється `STRCUR`, а прапорці `NUMCUR` та `USER_INPUT` скидаються.

### 2.3 Семантика неявного та примусового приведення типів

Приведення типів відбувається автоматично відповідно до оператора, у виразі якого бере участь операнд:

```awk
# Ідіоматичні примусові перетворення:
num = str + 0   # Арифметичний контекст: форсує парсинг рядка у число
str = num ""    # Контекст конкатенації: форсує приведення числа до рядка
```

#### Правила перетворення «Рядок -> Число»:
- Рядок сканується зліва направо за правилами функції `strtod(3)`.
- Будь-які ведучі пробіли ігноруються.
- Сприймаються знаки `+`/`-`, десяткова крапка та експонента (`1.25e-3`).
- Якщо рядок починається з нечислових символів (наприклад, `"error 404"`), числовий еквівалент дорівнює `0`.
- Якщо рядок містить число з наступним текстом (наприклад, `"100MB"`), чисельне значення дорівнює `100`, а залишок рядка відкидається.
- У `gawk` без прапорця `--posix` шістнадцяткові рядки `"0x1F"` розпізнаються автоматично лише у виклику `strtonum()`, але не під час операції `+ 0` (де вони парсяться як `0`).

#### Правила перетворення «Число -> Рядок»:
- Якщо перетворення відбувається під час конкатенації (`num ""`) або створення індексу масиву (`arr[num]`), число форматується згідно зі специфікатором системної змінної **`CONVFMT`** (за замовчуванням `"%.6g"`).
- Якщо вивід здійснюється оператором `print num`, число форматується згідно зі змінною **`OFMT`** (за замовчуванням `"%.6g"`).
- Виклики `printf` та `sprintf` повністю ігнорують `CONVFMT` та `OFMT`, використовуючи виключно переданий рядок формату.

### 2.4 Числові рядки (`strnum` / `NUMSTR`) та повна матриця правил порівняння

Найбільш критичною частиною стандарту POSIX AWK є семантика операторів порівняння (`==`, `!=`, `<`, `<=`, `>`, `>=`). Тип порівняння (числове проти лексикографічного) визначається не поточним вмістом, а **походженням (provenance)** операндів.

Операнди поділяються на три категорії:
1. **Число (`Number`):** числовий літерал (`42`, `3.14`) або результат арифметичного виразу (`a + b`, `sqrt(x)`).
2. **Числовий рядок (`Numeric String` / `strnum`):** немодифікований вхідний рядок (`$1`, `$0`, результат `getline`, елемент `ARGV`), синтаксичний аналіз якого дає валідне число за граматикою POSIX.
3. **Рядок (`String`):** рядковий літерал у лапках (`"42"`), результат конкатенації (`a ""`) або результат функцій `substr`, `sprintf`, `tolower`.

#### Матриця правил порівняння POSIX.1-2024 / GNU AWK

| Тип операнда 1 | Тип операнда 2 | Режим порівняння | Алгоритм виконання та конвертації |
|---|---|---|---|
| **Число** | **Число** | **Числове** | `num1 == num2`, `num1 < num2` за правилами IEEE 754. |
| **Число** | **Числовий рядок (`strnum`)** | **Числове** | `strnum` використовує чисельне значення; виконується числове порівняння. |
| **Числовий рядок (`strnum`)** | **Числовий рядок (`strnum`)** | **Числове** | Обидва рядки парсяться як числа; чисельне порівняння (`"010" == "10"` повертає `1`). |
| **Рядок** | **Рядок** | **Рядкове** | Побайтове порівняння (`strcmp`) або згідно з поточною локаллю `LC_COLLATE` (`strcoll`). |
| **Числовий рядок (`strnum`)** | **Рядок** | **Рядкове** | `strnum` розглядається як сирий рядок; лексикографічне порівняння. |
| **Число** | **Рядок** | **Рядкове (POSIX)** | **Критична пастка POSIX:** Число конвертується у рядок через `CONVFMT`, після чого виконується рядкове порівняння! |
| **Неініціалізована змінна** | **Число** | **Числове** | Неініціалізоване значення розглядається як числовий `0`. |
| **Неініціалізована змінна** | **Рядок** | **Рядкове** | Неініціалізоване значення розглядається як порожній рядок `""`. |
| **Неініціалізована змінна** | **Неініціалізована змінна** | **Числове/Рядкове** | Обидва операнди рівні між собою (`0 == 0` та `"" == ""` повертають `1`). |

```awk
# Ілюстрація пастки порівняння (Число проти Рядка):
BEGIN {
    CONVFMT = "%.6g"
    
    # 1. Порівняння Числа з Рядком:
    n = 3
    s = "12"
    if (s < n) {
        # n (число 3) перетворюється у рядок "3".
        # Виконується рядкове порівняння: "12" < "3" -> ІСТИНА (оскільки '1' < '3')!
        print "Рядкове порівняння: \"12\" менше за 3"
    }

    # 2. Порівняння Числового рядка (strnum) з Числом:
    # Нехай у файлі стоїть рядок "12", прочитаний у $1:
    # ($1 < 3) виконає числове порівняння: 12 < 3 -> ХИБНІСТЬ.
}
```

## 3. Внутрішній устрій асоціативних масивів та керування пам'яттю

Асоціативні масиви в AWK реалізовані як динамічні хеш-таблиці з прямим ланцюжком вирішення колізій (separate chaining). Вони здатні зберігати довільні рядкові та числові ключі без попереднього оголошення розміру.

### 3.1 Хеш-таблиця, ланцюжки колізій та алгоритми рехешування

Хеш-таблиця складається з масиву покажчиків на відра (bucket array) та вузлів елементів:

```c
/* Структура вузла хеш-таблиці в gawk / mawk */
typedef struct hash_node {
    struct hash_node *next;  /* Покажчик на наступний вузол у ланцюжку колізій */
    NODE *name;              /* Ключ елемента (структура NODE або рядок) */
    NODE *value;             /* Значення елемента масиву */
    size_t hash_code;        /* Кешоване 32/64-бітне значення хешу ключа */
} HASHNODE;

typedef struct awk_array {
    HASHNODE **buckets;      /* Динамічний масив покажчиків на ланцюжки */
    size_t size;             /* Поточна кількість відер (розмір масиву buckets) */
    size_t count;            /* Загальна кількість збережених елементів */
    size_t threshold;        /* Ліміт елементів до запуску рехешування */
} AWK_ARRAY;
```

```
                 Організація хеш-таблиці асоціативного масиву
    buckets:
    ┌──────────┐
    │ [0] ptr  │ ───► [ HashNode: key="db", val=120 ] ───► NULL
    ├──────────┤
    │ [1] NULL │
    ├──────────┤
    │ [2] ptr  │ ───► [ HashNode: key="web", val=400 ] ───► [ HashNode: key="api", val=350 ] ──► NULL
    ├──────────┤
    │   ...    │
    ├──────────┤
    │ [N] ptr  │ ───► NULL
    └──────────┘
```

#### Алгоритми хешування:
1. **GNU AWK:** використовує модифікований хеш Пітера Вайнбергера (PJW / ElfHash) або алгоритм Fowler-Noll-Vo (FNV-1a), що забезпечує рівномірний розподіл рядкових ключів по відрах за мінімальної кількості бітових інструкцій.
2. **MAWK:** використовує швидкий мультиплікативний хеш Бреннана над блоками байтів ключа.

#### Механізм динамічного рехешування (Rehashing):
1. **Початковий розмір:** нова хеш-таблиця ініціалізується невеликим масивом відер (13, 17 або 32 відра залежно від рушія).
2. **Коефіцієнт завантаження (Load Factor):** інтерпретатор обчислює відношення `load_factor = count / size`. Поріг рехешування зазвичай становить `1.5`–`2.0`.
3. **Процедура рехешування:**
   - Виділяється новий масив покажчиків удвічі більшого розміру (або наступне просте число).
   - Інтерпретатор проходить по всіх наявних відрах старого масиву.
   - Для кожного вузла `HASHNODE` обчислюється новий індекс: `new_idx = hash_code % new_size` (або `hash_code & (new_size - 1)` для розмірів степеня двійки).
   - Вузли перелінковуються в нові однозв'язні списки без копіювання рядків чи виділення нових структур `HASHNODE`.
   - Старий масив покажчиків звільняється викликом `free()`.
   - Це забезпечує амортизовану складність вставки та пошуку `O(1)`.

### 3.2 Семантика видалення елементів (`delete`) та очищення пам'яті

Інструкція `delete` використовується для видалення одного елемента або повного очищення масиву.

#### 1. Видалення одного елемента `delete arr[k]`:
- Інтерпретатор обчислює хеш ключа `k` і знаходить відповідне відро.
- Проходить ланцюжком колізій, відстежуючи попередній вузол (`prev`), доки не знайде збіг за довжиною `slen` та побайтовим порівнянням `memcmp(node->name, k)`.
- Вилучає вузол `node` зі списку: `prev->next = node->next`.
- Зменшує лічильники посилань ключа та значення (`unref(node->name)`, `unref(node->value)`). Якщо лічильник стає `0`, пам'ять у купі негайно звільняється.
- Вузол `HASHNODE` повертається у пул вільних вузлів інтерпретатора або звільняється.
- Декрементується лічильник елементів `count--`.
- *Примітка:* видалення елемента не зменшує розмір масиву відер `buckets` (пам'ять під покажчики таблиці зберігається).

#### 2. Повне видалення масиву `delete arr` (POSIX.1-2008 / Gawk):
- Інтерпретатор послідовно обходить усі відра таблиці.
- Звільняє всі вузли `HASHNODE`, їхні рядкові ключі та асоційовані значення.
- Скидає лічильник елементів `count = 0`.
- У `gawk` масив відер стискається назад до початкового мінімального розміру, повністю запобігаючи витокам пам'яті під час циклічної обробки великих пакетів даних.

### 3.3 Побічні ефекти автоініціалізації при читанні та оптимізація перевірок існування (`in`)

У мові AWK звичайне читання неіснуючого елемента призводить до **автоініціалізації (auto-vivification)**:

```awk
# Небезпечний патерн (породжує витік пам'яті та спотворення стану):
if (arr[key] == "") {
    # Звернення arr[key] автоматично створює новий елемент arr[key] = ""
    # у хеш-таблиці, виділяючи HASHNODE та рядок ключа в купі!
}

# Коректний патерн перевірки без створення вузла:
if (key in arr) {
    # Оператор 'in' виконує чистий пошук у хеш-таблиці.
    # Якщо ключ відсутній, структура таблиці залишається незмінною.
}
```

Використання оператора `in` запобігає неконтрольованому зростанню хеш-таблиці, захищає від хибних результатів функції `length(arr)` та запобігає потраплянню порожніх ключів у цикли `for (k in arr)`.

## 4. Вбудовані рядкові функції

Усі рядкові функції в AWK базуються на **1-індексації**: перший символ будь-якого рядка має індекс `1`, а не `0`. Якщо функції передається позиція `0`, стандарти POSIX та Gawk автоматично коригують її до `1`.

### `asort(source [, dest [, how]]) -> int` *(Gawk)*
Сортує значення елементів асоціативного масиву `source`.
- **Параметри:**
  - `source` — вихідний асоціативний масив.
  - `dest` *(необов'язковий)* — цільовий масив для запису результатів. Якщо вказано, `source` залишається незмінним, а відсортовані значення записуються в `dest` із числовими індексами `1, 2, ..., N`. Якщо `dest` опущено, сортування відбувається за місцем у `source`, при цьому всі старі ключі замінюються на числові індекси `1..N`.
  - `how` *(необов'язковий)* — правило порівняння (наприклад, `"@val_num_asc"`, `"@val_str_desc"` або ім'я користувацької функції порівняння). За замовчуванням діє поточне значення `PROCINFO["sorted_in"]`.
- **Повертає:** ціле число `N` — загальну кількість елементів у відсортованому масиві.
- **Крайові випадки:** якщо `source` порожній, повертає `0`, а `dest` залишається порожнім.
- **Приклад:**
  ```awk
  data["web"] = 400
  data["db"] = 120
  data["api"] = 350
  n = asort(data, sorted, "@val_num_asc")
  for (i = 1; i <= n; i++) print i, sorted[i]
  ```

---

### `asorti(source [, dest [, how]]) -> int` *(Gawk)*
Сортує **ключі (індекси)** асоціативного масиву `source`.
- **Параметри:**
  - `source` — вихідний асоціативний масив, ключі якого необхідно відсортувати.
  - `dest` *(необов'язковий)* — цільовий масив, у який записуються відсортовані ключі як значення з індексами `dest[1]..dest[N]`. Якщо опущено, модифікується вихідний масив `source`.
  - `how` *(необов'язковий)* — правило порівняння ключів (`"@ind_str_asc"`, `"@ind_num_desc"` тощо).
- **Повертає:** ціле число `N` — кількість знайдених ключів.
- **Приклад:**
  ```awk
  counts["192.168.1.1"] = 10
  counts["10.0.0.1"] = 55
  n = asorti(counts, ip_list, "@ind_str_asc")
  for (i = 1; i <= n; i++) print ip_list[i], counts[ip_list[i]]
  ```

---

### `gensub(regex, replacement, how [, target]) -> string` *(Gawk)*
Універсальна неруйнівна функція заміни регулярного виразу з підтримкою груп захоплення та вибіркової заміни конкретного входження.
- **Параметри:**
  - `regex` — регулярний вираз або рядок шаблону пошуку.
  - `replacement` — рядок підстановки. Підтримує збережені групи захоплення `\\1` .. `\\9` (текст відповідної пари круглих дужок у `regex`), а також `&` або `\\0` (весь знайдений фрагмент).
  - `how` — область застосування заміни:
    - `"g"` або `"G"` — глобальна заміна всіх знайдених входжень.
    - Додатне число `N` (`1`, `2`, `3`...) — заміна **виключно N-го** знайденого збігу зліва направо.
  - `target` *(необов'язковий)* — вхідний рядок. Якщо опущено, використовується копія поточного запису `$0`.
- **Повертає:** новий сформований рядок. Вихідний рядок `target` **не змінюється**.
- **Приклад:**
  ```awk
  # Перестановка компонентів дати з YYYY-MM-DD у DD.MM.YYYY
  clean = gensub(/^([0-9]{4})-([0-9]{2})-([0-9]{2})$/, "\\3.\\2.\\1", "g", "2026-08-29")
  # Заміна лише 2-го входження пробілу на кому
  row = gensub(/ /, ",", 2, "alpha beta gamma delta") # -> "alpha beta,gamma delta"
  ```

---

### `gsub(regex, replacement [, target]) -> int`
Виконує глобальну заміну всіх входжень регулярного виразу `regex` на текст `replacement` у цільовому рядку `target`.
- **Параметри:**
  - `regex` — регулярний вираз для пошуку.
  - `replacement` — текст заміни. Символ `&` розгортається у знайдений фрагмент. Для літерального символу `&` використовується екранування `\\&`.
  - `target` *(необов'язковий)* — змінна, над якою здійснюється заміна. Модифікується **за місцем (in-place)**. Якщо `target` опущено, модифікується `$0` (що призводить до негайної регенерації полів `$1..$NF`).
- **Повертає:** ціле число — кількість виконаних замін (або `0`, якщо збігів не знайдено).
- **Приклад:**
  ```awk
  text = "foo-10 bar-20 baz-30"
  count = gsub(/[0-9]+/, "[&]", text)
  # text стає "foo-[10] bar-[20] baz-[30]", count = 3
  ```

---

### `index(s, substr) -> int`
Виконує прямий пошук першого входження підрядка `substr` у рядку `s`.
- **Параметри:**
  - `s` — базовий рядок.
  - `substr` — шуканий підрядок (трактується буквально, без регулярних виразів).
- **Повертає:** 1-індексовану позицію першого символу знайденого збігу. Якщо підрядок відсутній — повертає `0`.
- **Крайові випадки:** якщо `substr` є порожнім рядком `""`, функція повертає `1`.
- **Приклад:**
  ```awk
  pos = index("user@domain.com", "@") # pos = 5
  ```

---

### `length([target]) -> int`
Обчислює кількість символів у рядку або кількість елементів у масиві.
- **Параметри:**
  - `target` *(необов'язковий)* — рядок, масив або вираз. Якщо аргумент опущено, повертає `length($0)`.
- **Семантика:**
  - Для рядків повертає кількість символів (враховуючи багатобайтові символи UTF-8 у сучасних локалях). При запуску `gawk -b` повертає кількість сирих байтів.
  - У GNU AWK, якщо як аргумент передано ім'я асоціативного масиву (`length(array)`), функція повертає кількість елементів у ньому.
- **Приклад:**
  ```awk
  len = length("Привіт") # len = 6 (символів)
  ```

---

### `match(s, regex [, array]) -> int`
Перевіряє наявність збігу регулярного виразу `regex` усередині рядка `s` та зберігає інформацію про координати знайденого фрагмента.
- **Параметри:**
  - `s` — вхідний рядок для пошуку.
  - `regex` — регулярний вираз.
  - `array` *(необов'язковий, POSIX.1-2008 та Gawk)* — масив для запису захоплених круглими дужками підгруп.
- **Побічні ефекти:**
  - Встановлює системну змінну `RSTART` у 1-індексовану початкову позицію першого збігу (або `0` у разі відсутності).
  - Встановлює системну змінну `RLENGTH` у довжину знайденого збігу в символах (або `-1` у разі відсутності).
  - Якщо передано масив `array`, він заповнюється елементами:
    - `array[0]` — повний текст усього знайденого збігу.
    - `array[i]` — текст, захоплений i-ю групою дужок `(...)`.
    - `array[i, "start"]` — початкова позиція i-ї групи в рядку `s`.
    - `array[i, "length"]` — довжина i-ї групи в символах.
- **Повертає:** значення змінної `RSTART` (ціле число `>= 0`).
- **Приклад:**
  ```awk
  line = "HTTP/1.1 404 Not Found"
  if (match(line, /HTTP\/[0-9.]+ ([0-9]{3}) (.+)/, m)) {
      status_code = m[1] # "404"
      status_text = m[2] # "Not Found"
  }
  ```

---

### `patsplit(s, array [, regex [, seps]]) -> int` *(Gawk)*
Розбиває рядок `s` на елементи масиву `array`, виділяючи фрагменти, що відповідають шаблону вмісту `regex`.
- **Параметри:**
  - `s` — вхідний рядок для парсингу.
  - `array` — цільовий масив для знайдених полів (`array[1]..array[N]`).
  - `regex` *(необов'язковий)* — регулярний вираз вмісту поля. Якщо опущено, береться поточне значення `FPAT`.
  - `seps` *(необов'язковий)* — масив для збереження проміжних роздільників: `seps[0]` містить текст до першого поля, `seps[i]` — текст між полем `i` та `i+1`, `seps[N]` — залишок після останнього поля.
- **Повертає:** кількість знайдених елементів `N`.
- **Приклад:**
  ```awk
  csv = "10,\"Smith, John\",Developer"
  n = patsplit(csv, fields, /([^,]+)|("[^"]+")/, seps)
  # fields[1] = "10", fields[2] = "\"Smith, John\"", fields[3] = "Developer"
  ```

---

### `split(s, array [, fieldsep [, seps]]) -> int`
Розбиває вхідний рядок `s` на елементи та зберігає їх у масиві `array` з числовими індексами `array[1]..array[N]`.
- **Параметри:**
  - `s` — вхідний рядок. Якщо `s == ""`, повертає `0`, а масив залишається порожнім.
  - `array` — цільовий масив. Будь-який попередній вміст масиву повністю видаляється перед розбиттям.
  - `fieldsep` *(необов'язковий)* — роздільник полів (одиночний символ або регулярний вираз). Якщо опущено, використовується поточне значення `FS`.
  - `seps` *(необов'язковий, Gawk)* — масив, у який записуються фактичні рядки-роздільники, що відокремлювали відповідні елементи.
- **Повертає:** ціле число `N` — загальну кількість сформованих елементів.
- **Приклад:**
  ```awk
  n = split("root:x:0:0:root:/root:/bin/bash", u, ":")
  print "Користувач:", u[1], "Оболонка:", u[7]
  ```

---

### `sprintf(format, expr1, expr2, ...) -> string`
Форматує передані аргументи за специфікаторами рядка `format` безпосередньо у вихідний рядок (аналог системної функції `snprintf(3)`).
- **Специфікатори типу даних:**
  - `%s` — рядок символів.
  - `%c` — один символ (якщо аргумент число — виводить ASCII/Unicode символ за кодом; якщо рядок — виводить його перший символ).
  - `%d`, `%i` — десяткове знакове ціле число.
  - `%u` — десяткове беззнакове ціле число.
  - `%o` — вісімкове ціле число.
  - `%x`, `%X` — шістнадцяткове ціле число (у нижньому або верхньому регістрі).
  - `%f`, `%F` — число з плаваючою комою у фіксованому форматі `[-]ddd.ddd`.
  - `%e`, `%E` — експоненційна форма представлення `[-]d.ddde[+-]dd`.
  - `%g`, `%G` — автоматичний вибір найбільш компактного формату між `%f` та `%e`.
  - `%a`, `%A` *(Gawk)* — шістнадцяткове число з плаваючою комою виду `[-]0xh.hhhhp[+-]d`.
- **Прапорці форматування:**
  - `-` — вирівнювання значення по лівому краю всередині виділеного поля.
  - `+` — обов'язковий вивід знака (`+` або `-`) для числових типів.
  - *(пробіл)* — додавання ведучого пробілу для додатних чисел.
  - `0` — заповнення виділеної ширини ведучими нулями замість пробілів.
  - `#` — альтернативна форма: додає префікси `0` для вісімкових та `0x`/`0X` для шістнадцяткових чисел, гарантує наявність крапки для `%f`/`%g`.
  - `'` *(Gawk)* — додавання локалезалежних роздільників тисяч (наприклад, ком або пробілів у числових групах).
- **Позиційні специфікатори:**
  - Підтримує синтаксис `%N$` для явного вказування порядкового номера аргументу (корисно під час локалізації рядків):
    ```awk
    msg = sprintf("%2$s має %1$d нових повідомлень", 5, "Олександр")
    ```
- **Повертає:** сформований відформатований рядок.

---

### `strtonum(target) -> number` *(Gawk)*
Виконує синтаксичний аналіз текстового рядка `target` та повертає його чисельне значення.
- **Розпізнавані формати:**
  - Десяткові числа: `"123"`, `"-45.67"`, `"1.5e-3"`.
  - Шістнадцяткові числа з префіксом `0x` або `0X`: `"0xFF"` -> `255`.
  - Вісімкові числа з ведучим нулем `0`: `"0755"` -> `493`.
- **Крайові випадки:** якщо рядок не містить валідного числового представлення, функція повертає `0`.
- **Приклад:**
  ```awk
  mode = strtonum("0644") # mode = 420
  mask = strtonum("0x80") # mask = 128
  ```

---

### `sub(regex, replacement [, target]) -> int`
Знаходить **перше** зліва входження регулярного виразу `regex` у цільовому рядку `target` і замінює його на текст `replacement`.
- **Параметри:**
  - `regex` — регулярний вираз пошуку.
  - `replacement` — текст заміни (символ `&` розгортається у весь знайдений фрагмент, `\\&` дає літеральний символ).
  - `target` *(необов'язковий)* — змінна, що модифікується **за місцем**. Якщо опущено, модифікується `$0`.
- **Повертає:** `1`, якщо заміну було успішно виконано, або `0`, якщо збіг відсутній.
- **Приклад:**
  ```awk
  path = "/var/log/syslog"
  sub(/^\/var/, "/srv", path) # path стає "/srv/log/syslog"
  ```

---

### `substr(s, start [, length]) -> string`
Вирізає та повертає підрядок із рядка `s`, починаючи з 1-індексованої позиції `start`.
- **Параметри:**
  - `s` — вихідний рядок.
  - `start` — початкова позиція (1-індексація). Якщо `start < 1`, значення автоматично приводиться до `1`.
  - `length` *(необов'язковий)* — кількість символів для вирізання. Якщо параметр опущено або `start + length > length(s)`, повертаються всі символи до кінця рядка `s`.
- **Крайові випадки:** якщо `start > length(s)` або `length <= 0`, повертає порожній рядок `""`.
- **Приклад:**
  ```awk
  tag = substr("[ERROR] Disk full", 2, 5) # tag = "ERROR"
  ```

---

### `tolower(s) -> string` та `toupper(s) -> string`
Перетворюють усі літери вхідного рядка `s` відповідно у нижній або верхній регістр.
- **Семантика:** перетворення виконується з урахуванням поточної системної локалі `LC_CTYPE`.
- **Повертає:** новий рядок із трансформованим регістром.
- **Приклад:**
  ```awk
  low = tolower("STANDALONE_MODE") # "standalone_mode"
  up  = toupper("kernel panic")     # "KERNEL PANIC"
  ```

## 5. Математичні та бітові функції

AWK виконує всі чисельні розрахунки за стандартом IEEE 754 у форматі чисел із плаваючою комою подвійної точності (64-бітний `double`, 53 біти точності мантиси).

### 5.1 Стандартні математичні функції POSIX

| Функція | Сигнатура | Призначення, математична поведінка та крайові випадки |
|---|---|---|
| `atan2(y, x)` | `atan2(y, x) -> float` | Обчислює арктангенс частки `y / x` у радіанах у діапазоні `[-π, π]`. Враховує знаки обох аргументів для точного визначення квадранта. Якщо обидва аргументи дорівнюють `0`, повертає `0`. |
| `cos(x)` | `cos(x) -> float` | Обчислює тригонометричний косинус кута `x`, заданого в радіанах. |
| `sin(x)` | `sin(x) -> float` | Обчислює тригонометричний синус кута `x`, заданого в радіанах. |
| `exp(x)` | `exp(x) -> float` | Обчислює експоненту числа `x` (`e^x`). У разі переповнення повертає `+Inf` або генерує помилку. |
| `int(x)` | `int(x) -> int` | Відтинає дробову частину числа `x`, округлюючи його в бік нуля (`int(3.9) = 3`, `int(-3.9) = -3`). Не виконує математичного округлення до найближчого цілого. |
| `log(x)` | `log(x) -> float` | Обчислює натуральний логарифм за основою `e` для `x > 0`. Якщо `x <= 0`, повертає `-Inf` або `NaN` із генерацією попередження чи помилки. |
| `rand()` | `rand() -> float` | Генерує псевдовипадкове число з рівномірним розподілом у напіввідкритому інтервалі `[0.0, 1.0)`. Без виклику `srand()` послідовність чисел ідентична при кожному запуску. |
| `sqrt(x)` | `sqrt(x) -> float` | Обчислює квадратний корінь для `x >= 0`. При `x < 0` повертає `NaN` або породжує помилку часу виконання. |
| `srand([seed])` | `srand(seed) -> int` | Ініціалізує генератор псевдовипадкових чисел початковим значенням `seed`. Якщо `seed` опущено, використовується поточний системний час епохи Unix. Повертає попереднє значення зерна генератора. |

```awk
# Ідіоматична генерація випадкового цілого числа в діапазоні [min, max]:
function random_range(min, max) {
    return min + int(rand() * (max - min + 1))
}

BEGIN {
    srand() # Ініціалізація генератора поточним часом
    print "Випадкове число [1..100]:", random_range(1, 100)
}
```

### 5.2 Бітові операції GNU AWK (Gawk)

Усі бітові функції `gawk` приводять вхідні чисельні аргументи до беззнакових цілих чисел фіксованої ширини (64-бітних `uint64_t`) перед виконанням побітових перетворень:

| Функція | Сигнатура | Опис операції та бітовий еквівалент |
|---|---|---|
| `and(v1, v2 [, ...])` | `and(v1, v2, ...) -> int` | Побітове І (Bitwise AND): виконує послідовну побітову кон'юнкцію над двома або більше аргументами (`v1 & v2 & ...`). |
| `or(v1, v2 [, ...])` | `or(v1, v2, ...) -> int` | Побітове АБО (Bitwise OR): виконує побітову диз'юнкцію над двома або більше аргументами (`v1 \| v2 \| ...`). |
| `xor(v1, v2 [, ...])` | `xor(v1, v2, ...) -> int` | Побітове виключне АБО (Bitwise XOR): виконує операцію XOR над двома або більше аргументами (`v1 ^ v2 ^ ...`). |
| `compl(x)` | `compl(x) -> int` | Побітове заперечення (Bitwise NOT): інвертує всі біти 64-бітного цілого числа (`~x`). |
| `lshift(x, count)` | `lshift(x, count) -> int` | Логічний зсув ліворуч: зсуває біти числа `x` на `count` позицій ліворуч (`x << count`). Звільнені позиції праворуч заповнюються нулями. |
| `rshift(x, count)` | `rshift(x, count) -> int` | Логічний зсув праворуч: зсуває біти числа `x` на `count` позицій праворуч (`x >> count`). Звільнені позиції ліворуч заповнюються нулями. |

```awk
# Приклад маніпуляції бітовими масками прапорців:
BEGIN {
    FLAG_READ    = 1 # 0001
    FLAG_WRITE   = 2 # 0010
    FLAG_EXEC    = 4 # 0100

    perms = or(FLAG_READ, FLAG_EXEC) # 0101 (5)
    
    # Перевірка наявності прапорця FLAG_WRITE
    if (and(perms, FLAG_WRITE)) {
        print "Запис дозволено"
    } else {
        print "Лише читання та виконання"
    }
}
```

## 6. Функції часу та дати

Стандарт POSIX не регламентує функцій роботи з часом в AWK. Усі наведені нижче часові інтерфейси є стандартом GNU AWK (також підтримуються `mawk` нових версій):

### `systime() -> int` *(Gawk)*
Повертає поточний системний час у вигляді цілої кількості секунд, що минули з початку епохи Unix (1 січня 1970 року 00:00:00 UTC).
- **Повертає:** 64-бітний цілочисельний timestamp (наприклад, `1787999800`).

---

### `mktime(datespec [, utcflag]) -> int` *(Gawk)*
Перетворює рядок специфікації дати й часу у цілочисельний Unix timestamp.
- **Параметри:**
  - `datespec` — рядок формату `"YYYY MM DD HH MM SS [DST]"`, де:
    - `YYYY` — 4-значний рік (наприклад, `2026`).
    - `MM` — номер місяця (`01` .. `12`).
    - `DD` — день місяця (`01` .. `31`).
    - `HH` — години (`00` .. `23`).
    - `MM` — хвилини (`00` .. `59`).
    - `SS` — секунди (`00` .. `59`).
    - `DST` *(необов'язковий)* — статус літнього часу: `1` (діє літній час), `0` (не діє), `-1` (визначити автоматично з системної бази часових поясів).
  - `utcflag` *(необов'язковий)* — якщо ненульовий, рядок інтерпретується за шкалою UTC замість локального часового поясу системи.
- **Повертає:** ціле число секунд від початку епохи Unix або `-1` у разі некоректного формату дати.
- **Приклад:**
  ```awk
  ts = mktime("2026 08 29 16 00 00", 1) # Timestamp для 16:00:00 UTC
  ```

---

### `strftime([format [, timestamp [, utcflag]]]) -> string` *(Gawk)*
Форматує числовий timestamp у структурований текстовий рядок згідно зі специфікаторами системної бібліотеки `strftime(3)`.
- **Параметри:**
  - `format` *(необов'язковий)* — рядок форматування. Якщо опущено, використовується значення за замовчуванням `PROCINFO["strftime"]` (еквівалент формату утиліти `date`).
  - `timestamp` *(необов'язковий)* — чисельний час епохи Unix. Якщо опущено, використовується результат виклику `systime()`.
  - `utcflag` *(необов'язковий)* — якщо ненульовий, час форматується за зоною UTC замість локального часового поясу.
- **Основні специфікатори формату:**
  - `%Y` — 4-значний рік (`2026`).
  - `%m` — місяць двома цифрами (`01` .. `12`).
  - `%d` — день місяця двома цифрами (`01` .. `31`).
  - `%H` — години у 24-годинному форматі (`00` .. `23`).
  - `%I` — години у 12-годинному форматі (`01` .. `12`).
  - `%p` — індикатор до/після полудня (`AM` або `PM`).
  - `%M` — хвилини (`00` .. `59`).
  - `%S` — секунди (`00` .. `59`).
  - `%F` — повна дата ISO 8601, еквівалент `%Y-%m-%d`.
  - `%T` — 24-годинний час, еквівалент `%H:%M:%S`.
  - `%s` — кількість секунд з початку епохи Unix.
  - `%u` — день тижня як число (`1` = Понеділок .. `7` = Неділя).
  - `%w` — день тижня (`0` = Неділя .. `6` = Субота).
  - `%j` — порядковий день року (`001` .. `366`).
  - `%z` — числовий зсув часового поясу (`+0300`).
  - `%Z` — буквена назва часового поясу (`EEST`, `UTC`).
- **Повертає:** сформований текстовий рядок дати й часу.

## 7. Керування потоком виконання, системне I/O, буферизація та підпроцеси

### 7.1 Керуючі інструкції життєвого циклу

| Інструкція | Допустимий контекст | Семантика виконання |
|---|---|---|
| `next` | Головний цикл обробки | Негайно припиняє виконання правил над **поточним записом** і переходить до зчитування та обробки наступного запису з вхідного потоку. Заборонено викликати всередині блоків `BEGIN` та `END`. |
| `nextfile` | Головний цикл / `BEGINFILE` | Негайно зупиняє читання **поточного вхідного файлу**, закриває його дескриптор і переходить до першого запису **наступного файлу** з масиву `ARGV`. Якщо поточний файл був останнім у списку, керування передається блоку `END`. Стандарт POSIX.1-2024 та GNU AWK. |
| `exit [code]` | Будь-який блок програми | Зупиняє виконання головного циклу обробки і негайно передає керування блоку `END`. Якщо `exit` викликано всередині самого блоку `END`, процес негайно завершується з кодом повернення `code` (за замовчуванням `0`). |

### 7.2 Повна специфікація викликів `getline`

Інструкція `getline` є низькорівневим засобом неблокуючого або потокового читання записів, що повертає статус виконання:
- `1` — успішне зчитування нового запису.
- `0` — досягнуто кінця вхідного потоку або файлу (`EOF`).
- `-1` — критична помилка введення-виведення (у `gawk` опис записується в `ERRNO`).

| Варіант виклику | Джерело даних | Цільове сховище | Вплив на `$0` та поля `$1..$NF` | Вплив на лічильники `NR` та `FNR` |
|---|---|---|---|---|
| **`getline`** | Поточний вхідний потік | `$0` | **Оновлює** `$0`, перераховує поля `$1..$NF` та `NF` | **Інкрементує** обидва лічильники (`NR++`, `FNR++`) |
| **`getline var`** | Поточний вхідний потік | Змінна `var` | **Не змінює** ні `$0`, ні `$1..$NF`, ні `NF` | **Інкрементує** обидва лічильники (`NR++`, `FNR++`) |
| **`getline < "file"`** | Зовнішній файл `"file"` | `$0` | **Оновлює** `$0`, перераховує поля `$1..$NF` та `NF` | **Не змінює** лічильники `NR` та `FNR` |
| **`getline var < "file"`** | Зовнішній файл `"file"` | Змінна `var` | **Не змінює** ні `$0`, ні `$1..$NF`, ні `NF` | **Не змінює** лічильники `NR` та `FNR` |
| **`"cmd" \| getline`** | Вивід конвеєра команди `"cmd"` | `$0` | **Оновлює** `$0`, перераховує поля `$1..$NF` та `NF` | **Не змінює** лічильники `NR` та `FNR` |
| **`"cmd" \| getline var`** | Вивід конвеєра команди `"cmd"` | Змінна `var` | **Не змінює** ні `$0`, ні `$1..$NF`, ні `NF` | **Не змінює** лічильники `NR` та `FNR` |
| **`"cmd" \|& getline var`** | Двонаправлений сокет/процес *(Gawk)* | Змінна `var` | **Не змінює** ні `$0`, ні `$1..$NF`, ні `NF` | **Не змінює** лічильники `NR` та `FNR` |

> ⚠️ **Критичний пріоритет операторів:**
> Оператори введення `<` та каналу `|` мають нижчий пріоритет за оператори порівняння. Неправильний вираз `while (getline line < "file" > 0)` розбирається парсером як `while (getline line < ("file" > 0))`. **Завжди беріть виклик у дужки:**
> ```awk
> while ((getline line < "/etc/hosts") > 0) {
>     print "Прочитано:", line
> }
> close("/etc/hosts")
> ```

### 7.3 Буферизація stdio, скидання через `fflush()` та інтерактивні потоки

Усі операції введення-виведення в інтерпретаторах AWK спираються на стандартну бібліотеку C (`stdio`). Режим буферизації вихідних потоків визначається типом приймача:

1. **Повна буферизація (Block Buffering, `_IOFBF`):**
   - Вмикається автоматично, коли `stdout` або перенаправлення `print > "file"` спрямовані у файл на диску або у міжпроцесний конвеєр (`print | "cmd"`).
   - Розмір системного буфера зазвичай становить 4096, 8192 або 65536 байтів (`BUFSIZ`).
   - Дані фізично не передаються ядру ОС доти, доки буфер не заповниться повністю або програма не завершить роботу.
2. **Порядкова буферизація (Line Buffering, `_IOLBF`):**
   - Діє, коли `stdout` підключено до інтерактивного термінала TTY (`isatty(STDOUT_FILENO) == 1`).
   - Кожен символ нового рядка `\n` (включно зі стандартним `ORS`) ініціює скидання буфера в термінал.
3. **Відсутність буферизації (Unbuffered, `_IONBF`):**
   - Застосовується для стандартного потоку помилок `/dev/stderr`.

#### Проблема зависання потокових конвеєрів (Pipeline Stalling):
Якщо AWK працює як проміжна ланка у потоковому конвеєрі реального часу:
```bash
tail -f /var/log/nginx/access.log | awk '/404/ { print $1, $7 }' | logger -t nginx_errors
```
Оскільки вивід `awk` спрямовано в конвеєр до `logger`, вмикається повна блокова буферизація. Повідомлення не з'являться у системному журналі доти, доки обсяг виявлених помилок 404 не досягне 4–8 КБ.

#### Функція примусового скидання буферів `fflush()`:
```awk
# Синтаксис виклику fflush():
fflush()            # Скидає буфер стандартного виводу (stdout)
fflush("")          # Скидає буфери ВСІХ відкритих файлів, конвеєрів та сокетів
fflush("file.log")  # Скидає буфер конкретного файлу
fflush("grep 404")  # Скидає буфер каналу запису у підпроцес
```

```awk
# Ідіоматичне потокове логування в реальному часі без затримок буферизації:
/ERROR/ {
    print strftime("[%Y-%m-%d %H:%M:%S]"), $0 > "/var/log/alerts.log"
    fflush("/var/log/alerts.log")
}
```

### 7.4 Керування файловими дескрипторами та конвеєрами (`close`, `system`)

Інтерпретатор AWK веде внутрішню таблицю відкритих файлів та процесів (Redirection Table).

#### `close(target [, how]) -> int`
Закриває файловий дескриптор, конвеєр або сокет, асоційований з рядковим ідентифікатором `target`.

- **Життєвий цикл файлів:**
  - Якщо файл було прочитано через `getline < "file"` до стану `EOF`, подальші виклики повертатимуть `0`. Щоб перечитати файл спочатку, необхідно явно виконати `close("file")`.
  - Якщо у циклі відкривається багато унікальних файлів (`print $0 > ("out_" $1 ".txt")`), операційна система вичерпає ліміт відкритих дескрипторів (`EMFILE` / `ulimit -n`), якщо їх не закривати своєчасно через `close()`.
- **Життєвий цикл конвеєрів (`print | "cmd"`):**
  - Виклик `close("cmd")` закриває записуючий кінець каналу (надсилає `EOF` дочірньому процесу).
  - Інтерпретатор викликає системний виклик `waitpid(pid, &status, 0)` для очищення процесу-зомбі та очікує завершення дочірньої програми.
  - Повертає код завершення дочірнього процесу (exit status).
- **Двонаправлені канали `gawk` (`|&`):**
  - Параметр `how = "to"` закриває канал запису, сигналізуючи віддаленому серверу про завершення передачі запиту, залишаючи канал читання відкритим для отримання відповіді.
  - Параметр `how = "from"` закриває вхідний потік сокета.

#### `system(command) -> int`
Виконує команду `command` через системну оболонку `/bin/sh -c`.
- Призупиняє виконання AWK до завершення команди.
- Повертає статус завершення: у `gawk` повертається нормалізований код виходу (0–255), або від'ємне число у разі помилки виклику `fork`/`exec`.

### 7.5 Обробка сигналів POSIX (`SIGPIPE`, `SIGINT`), таблиця відкритих процесів та коди завершення

Взаємодія AWK із процесами операційної системи підпорядковується стандартам POSIX:

#### 1. Обробка сигналу зламаного каналу `SIGPIPE`:
Коли вивід AWK спрямовано в утиліту, що закриває читання раніше (наприклад, `awk '{print}' large.log | head -n 5`):
- Коли `head` зчитує 5 рядків і завершує роботу, операційна система закриває дескриптор читання каналу.
- Наступна операція запису генерує системний сигнал `SIGPIPE`.
- За замовчуванням у Unix цей сигнал аварійно вбиває процес. Стандартні інтерпретатори AWK встановлюють обробник або ігнорують `SIGPIPE` на дескрипторах перенаправлення, перехоплюючи системну помилку `EPIPE`. Інтерпретатор коректно закриває відкриті файли, скидає таблиці та завершує роботу з нульовим або нормалізованим кодом виходу без створення аварійних дампів.

#### 2. Обробка сигналів переривання `SIGINT` та `SIGQUIT`:
- Під час виконання функції `system(command)` інтерпретатор AWK тимчасово блокує та ігнорує сигнали `SIGINT` і `SIGQUIT` у батьківському процесі (вимога стандарту POSIX `system(3)`), делегуючи обробку сигналів запущеному підпроцесу.
- Якщо користувач натискає `Ctrl+C`, сигнал отримує дочірній процес; після його завершення AWK перевіряє код виходу й приймає рішення щодо продовження або виходу.
- При отриманні `SIGINT` безпосередньо процесом AWK, інтерпретатор перериває головний цикл обробки, викликає блок `END` (якщо налаштовано відповідний режим) та повертає статус `128 + SIGINT` (130).

### 7.6 Мережева взаємодія та спеціальні файли у GNU AWK

GNU AWK надає вбудовану підтримку мережевих TCP/UDP з'єднань через спеціальний синтаксис шляхів та оператор двонаправленого каналу `|&`:

```
/inet/tcp/lport/rhost/rport
/inet/udp/lport/rhost/rport
/inet4/tcp/lport/rhost/rport
/inet6/tcp/lport/rhost/rport
```

- `lport` — локальний порт для прив'язки (`0` для автоматичного вибору ядром).
- `rhost` — ім'я віддаленого вузла або IP-адреса.
- `rport` — порт віддаленого сервісу або його назва з `/etc/services` (наприклад, `80` або `http`).

```awk
# Приклад HTTP GET-запиту безпосередньо з AWK через TCP-сокет:
BEGIN {
    service = "/inet/tcp/0/example.com/80"
    
    # Відправка HTTP-запиту у двонаправлений канал
    print "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n" |& service
    
    # Зчитування HTTP-відповіді
    while ((service |& getline response) > 0) {
        print response
    }
    
    # Закриття сокета
    close(service)
}
```

Також підтримуються спеціальні системні шляхи:
- `/dev/stdin`, `/dev/stdout`, `/dev/stderr` — стандартні потоки процесу.
- `/dev/fd/N` — прямий доступ до відкритого файлового дескриптора з номером `N`.

## 8. Параметри командного рядка (CLI) та конфігурація середовища

Виклик інтерпретатора AWK здійснюється за базовими схемами:

```bash
awk [options] 'program_text' [file ...]
awk [options] -f program_file [file ...]
```

### 8.1 Стандартні опції POSIX

| Опція | Призначення та семантика |
|---|---|
| **`-F fsvalue`** | Встановлює початкове значення системного роздільника полів `FS`. Еквівалентно виконанню інструкції `BEGIN { FS = "fsvalue" }`. Може приймати одиночний символ, спеціальну послідовність (`-F'\t'`) або регулярний вираз (`-F'[,:]'`). |
| **`-v var=value`** | Присвоює змінній `var` вказане значення `value` **до** виконання будь-якого блоку `BEGIN`. Це єдиний спосіб передати конфігураційні параметри, які мають бути доступні безпосередньо під час ініціалізації середовища. Кожна змінна вимагає окремого прапорця `-v`. |
| **`-f scriptfile`** | Зчитує вихідний код програми з файлу `scriptfile`. Дозволяється багаторазове вказування прапорця `-f` для підключення сторонніх бібліотек та модулів. |

---

### 8.2 Розширені опції GNU AWK (Gawk)

| Опція | Довгий еквівалент | Призначення та поведінка |
|---|---|---|
| **`-e 'text'`** | `--source 'text'` | Дозволяє поєднувати програмний текст із командного рядка разом із бібліотечними файлами, підключеними через `-f`. |
| **`-E file`** | `--exec file` | Зчитує код із файлу `file`, при цьому вимикає подальший розбір прапорців CLI, передаючи всі наступні аргументи безпосередньо в масив `ARGV`. Використовується в shebang-скриптах: `#!/usr/bin/gawk -E`. |
| **`-b`** | `--characters-as-bytes` | Трактує всі вхідні байти як окремі 8-бітні символи, повністю вимикаючи парсинг багатобайтових послідовностей UTF-8. Суттєво прискорює обробку великих обсягів ASCII та бінарних даних. |
| **`-M`** | `--bignum` | Вмикає режим довільної точності для цілих чисел і чисел із плаваючою комою за допомогою бібліотек GNU MPFR та GNU GMP. |
| **`-P`** | `--posix` | Вмикає режим суворої сумісності з POSIX: вимикає всі розширення GNU (`gensub`, `FPAT`, `FIELDWIDTHS`, мережеві сокети, нерегулярні масиви). |
| **`-c`** | `--traditional` | Вмикає сумісність з історичним оригінальним Unix AWK (Bell Labs awk). |
| **`-d[file]`** | `--dump-variables[=file]` | Записує відсортований дамп усіх глобальних змінних, їхніх типів та фінальних значень у файл (за замовчуванням `awkvars.out`). |
| **`-p[file]`** | `--profile[=file]` | Вмикає режим профілювання виконання. Генерує детальний звіт із підрахунком кількості викликів кожного блоку та рядка програми. |
| **`-S`** | `--sandbox` | Режим пісочниці: забороняє виклики `system()`, відкриття міжпроцесних конвеєрів (`print | "cmd"`, `"cmd" | getline`) та роботу з мережевими сокетами. |

| **`-l lib`** | `--load lib` | Динамічно завантажує спільну C-бібліотеку розширення (shared library `.so` або `.dll`) через системний виклик `dlopen(3)`. |

| **`-V`** | `--version` | Виводить інформацію про версію інтерпретатора (`GNU Awk`, `mawk`, `bwk`), авторів та ліцензію, після чого процес завершується. |

## 9. C/C++ API динамічних розширень Gawk (Dynamic Extensions API)

GNU AWK починаючи з версії 4.1 надає уніфікований інтерфейс C API для підключення динамічних бібліотек (`.so` у Linux/BSD, `.dylib` у macOS, `.dll` у Windows). Це дозволяє розширювати стандартну бібліотеку AWK нативними системними викликами, взаємодіяти з низькорівневими структурами пам'яті, використовувати сторонні бібліотеки C/C++ та виконувати критичні за швидкодією ділянки коду зі швидкістю скомпільованого двійкового файлу.

### 9.1 Архітектура завантаження та протокол рукостискання (Handshake)

Динамічне розширення підключається у скрипті AWK за допомогою інструкції `@load "назва_модуля"` або через прапорець командного рядка `-l назва_модуля` (`--load`). Пошук файлу здійснюється за шляхами змінної оточення `AWKLIBPATH` (за замовчуванням `/usr/local/lib/gawk:/usr/lib/gawk`), а завантаження виконується системним викликом `dlopen(3)`.

Точкою входу в кожну бібліотеку розширення є обов'язкова C-функція ініціалізації:

```c
int dl_load(const gawk_api_t *const api_p, awk_ext_id_t id);
```

#### Послідовність ініціалізації:
1. Інтерпретатор передає покажчик `api_p` на структуру `gawk_api_t`, яка містить таблицю адрес усіх доступних функцій API ядра Gawk, а також дескриптор розширення `id`.
2. Бібліотека зобов'язана здійснити валідацію версії:
   - `api_p->major_version == GAWK_API_MAJOR_VERSION` (гарантія бінарної сумісності структур).
   - `api_p->minor_version >= GAWK_API_MINOR_VERSION` (наявність необхідних точок входу).
   Якщо версії не сумісні, функція повертає `0`, і завантаження негайно переривається з фатальною помилкою.
3. Бібліотека викликає `api_p->api_add_ext_func()` для реєстрації кожної нової функції в таблиці символів AWK.
4. За успішної реєстрації `dl_load` повертає `1`.

### 9.2 Структури даних, значення `awk_value_t` та дескриптор `awk_ext_func_t`

#### 1. Дескриптор функції розширення (`awk_ext_func_t`):
```c
typedef struct awk_ext_func {
    const char *name;                      /* Назва функції в AWK (наприклад "fnv1a_64") */
    awk_value_t *(*function)(int num_actual_args,
                             awk_value_t *result,
                             struct awk_ext_func *flags); /* Покажчик на реалізацію */
    size_t max_expected_args;              /* Максимальна кількість аргументів */
    size_t min_required_args;              /* Мінімальна обов'язкова кількість аргументів */
    awk_bool_t suppress_lint;              /* Прапорець вимкнення lint-попереджень */
    void *data;                            /* Вказівник на довільні контекстні дані модуля */
} awk_ext_func_t;
```

#### 2. Дискриміноване об'єднання типів `awk_value_t`:
Будь-який аргумент, повернене значення, змінна або елемент масиву передається через уніфікований контейнер `awk_value_t`:

```c
typedef enum {
    AWK_UNDEFINED = 0,
    AWK_NUMBER,       /* Число double або MPFR */
    AWK_STRING,       /* Текстовий рядок: char *str, size_t len */
    AWK_STRNUM,       /* Числовий рядок */
    AWK_REGEX,        /* Регулярний вираз */
    AWK_ARRAY,        /* Дескриптор асоціативного масиву (cookie) */
    AWK_SCALAR,       /* Посилання на скалярну змінну */
    AWK_VALUE_COOKIE  /* Непрозорий дескриптор значення */
} awk_valtype_t;

typedef struct awk_string {
    char *str;
    size_t len;
} awk_string_t;

typedef struct awk_value {
    awk_valtype_t val_type;
    union {
        AWKNUM num_value;
        awk_string_t str_value;
        awk_regex_t regex_value;
        awk_array_t array_cookie;
        awk_scalar_t scalar_cookie;
        awk_value_cookie_t value_cookie;
    };
} awk_value_t;
```

### 9.3 Макроси API та функції взаємодії з інтерпретатором

Заголовочний файл `<gawkapi.h>` надає макроси для доступу до підсистем інтерпретатора:

| Макрос / Функція API | Призначення та поведінка |
|---|---|
| `get_argument(count, desired_type, &val)` | Зчитує `count`-й позиційний аргумент (0-індексація) із приведенням до типу `desired_type` (`AWK_STRING`, `AWK_NUMBER`, `AWK_UNDEFINED`). Повертає `awk_bool_t` (`1` — успіх, `0` — помилка). |
| `make_number(num, &result)` | Записує число `double num` у структуру `result` і встановлює тип `AWK_NUMBER`. Повертає `&result`. |
| `make_const_string(str, len, &result)` | Прив'язує рядковий літерал до `result` без дублювання пам'яті (буфер не повинен модифікуватися або вивільнятися бібліотекою). |
| `make_malloced_string(str, len, &result)` | Передає динамічний буфер `str`, виділений через `malloc()`, у володіння AWK. Інтерпретатор самостійно викличе `free()`, коли змінна буде перезаписана чи знищена. |
| `make_null_string(&result)` | Встановлює `result` у порожній рядок `""`. |
| `update_ERRNO_string(str)` | Записує рядок помилки `str` безпосередньо у спеціальну системну змінну `ERRNO` в середовищі AWK. |
| `update_ERRNO_int(err_code)` | Конвертує числовий код помилки `errno` у текст через `strerror(errno)` та оновлює змінну `ERRNO`. |
| `warning(format, ...)` | Друкує попередження у потік `stderr` за стандартним форматом діагностики AWK. |
| `fatal(format, ...)` | Виводить повідомлення про критичний збій та негайно аварійно завершує роботу інтерпретатора. |
| `sym_lookup(name, type, &val)` | Знаходить глобальну змінну або масив у таблиці символів за назвою `name`. |
| `sym_update(name, &val)` | Створює або перезаписує глобальну змінну в таблиці символів AWK. |
| `create_array()` | Створює новий асоціативний масив AWK і повертає його дескриптор `awk_array_t`. |
| `set_array_element(arr, idx, &val)` | Записує значення `val` у масив `arr` за індексом `idx` (`awk_value_t`). |
| `get_array_element(arr, idx, type, &res)` | Зчитує елемент масиву за вказаним індексом. |

### 9.4 Приклад реалізації модуля динамічного розширення на C та C++

Реалізуємо високопродуктивний модуль `fast_tools`, що додає до AWK дві функції:
1. `monotonic_time_ns()` — вимірює монотонний час операційної системи в наносекундах (`clock_gettime(CLOCK_MONOTONIC)`), запобігаючи спотворенням від стрибків NTP.
2. `fnv1a_64(str)` — обчислює 64-бітний некриптографічний хеш Fowler–Noll–Vo (FNV-1a) над переданим рядком на рівні регістрів CPU.

:::tabs
```c
/* fast_tools.c — Реалізація модуля розширення мовою C */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <errno.h>
#include <stdint.h>
#include <gawkapi.h>

static const gawk_api_t *api;
static awk_ext_id_t ext_id;
static const char *ext_version = "fast_tools: 1.0.0";

#define FNV_OFFSET_BASIS_64 14695981039346656037ULL
#define FNV_PRIME_64        1099511628211ULL

/* 1. Отримання монотонного системного часу в наносекундах */
static awk_value_t *do_monotonic_time_ns(int nargs, awk_value_t *result, struct awk_ext_func *flags)
{
    struct timespec ts;
    if (clock_gettime(CLOCK_MONOTONIC, &ts) != 0) {
        update_ERRNO_int(errno);
        return make_number(-1.0, result);
    }

    double ns = (double)ts.tv_sec * 1e9 + (double)ts.tv_nsec;
    return make_number(ns, result);
}

/* 2. Обчислення 64-бітного некриптографічного хешу FNV-1a */
static awk_value_t *do_fnv1a_64(int nargs, awk_value_t *result, struct awk_ext_func *flags)
{
    awk_value_t str_arg;
    if (!get_argument(0, AWK_STRING, &str_arg)) {
        update_ERRNO_string("fnv1a_64: очікується рядковий аргумент");
        return make_null_string(result);
    }

    const uint8_t *data = (const uint8_t *)str_arg.str_value.str;
    size_t len = str_arg.str_value.len;
    uint64_t hash = FNV_OFFSET_BASIS_64;

    for (size_t i = 0; i < len; i++) {
        hash ^= data[i];
        hash *= FNV_PRIME_64;
    }

    /* Виділяємо буфер під шістнадцятковий рядок "0x..." */
    char *buf = (char *)malloc(19);
    if (!buf) {
        update_ERRNO_int(ENOMEM);
        return make_null_string(result);
    }
    snprintf(buf, 19, "0x%016llx", (unsigned long long)hash);

    return make_malloced_string(buf, strlen(buf), result);
}

/* Таблиця функцій для реєстрації в AWK */
static awk_ext_func_t func_table[] = {
    { "monotonic_time_ns", do_monotonic_time_ns, 0, 0, awk_false, NULL },
    { "fnv1a_64",           do_fnv1a_64,           1, 1, awk_false, NULL },
};

/* Точка входу динамічного модуля */
int dl_load(const gawk_api_t *const api_p, awk_ext_id_t id)
{
    api = api_p;
    ext_id = id;

    if (api->major_version != GAWK_API_MAJOR_VERSION ||
        api->minor_version < GAWK_API_MINOR_VERSION) {
        fprintf(stderr, "fast_tools: несумісна версія Gawk API (%d.%d)\n",
                api->major_version, api->minor_version);
        return 0;
    }

    size_t num_funcs = sizeof(func_table) / sizeof(func_table[0]);
    for (size_t i = 0; i < num_funcs; i++) {
        if (!api->api_add_ext_func(ext_id, NULL, &func_table[i])) {
            warning("fast_tools: не вдалося зареєструвати функцію %s", func_table[i].name);
            return 0;
        }
    }

    api->api_register_ext_version(ext_id, ext_version);
    return 1;
}
```

```cpp
// fast_tools.cpp — Реалізація мовою C++ з RAII, std::string_view та безпечними типами
#include <chrono>
#include <string_view>
#include <cstdio>
#include <cstdint>
#include <cstring>
#include <cstdlib>
#include <cerrno>
#include <gawkapi.h>

namespace fast_tools {

static const gawk_api_t *api = nullptr;
static awk_ext_id_t ext_id;
static constexpr std::string_view EXT_VERSION = "fast_tools_cpp: 1.0.0";

constexpr uint64_t FNV_OFFSET_BASIS = 14695981039346656037ULL;
constexpr uint64_t FNV_PRIME        = 1099511628211ULL;

[[nodiscard]] constexpr uint64_t compute_fnv1a(std::string_view sv) noexcept
{
    uint64_t hash = FNV_OFFSET_BASIS;
    for (char c : sv) {
        hash ^= static_cast<uint8_t>(c);
        hash *= FNV_PRIME;
    }
    return hash;
}

awk_value_t *monotonic_time_ns_impl(int, awk_value_t *result, struct awk_ext_func *) noexcept
{
    try {
        const auto now = std::chrono::steady_clock::now();
        const auto ns = std::chrono::duration_cast<std::chrono::nanoseconds>(now.time_since_epoch()).count();
        return make_number(static_cast<double>(ns), result);
    } catch (...) {
        api->api_update_ERRNO_string(ext_id, "monotonic_time_ns: помилка таймера");
        return make_number(-1.0, result);
    }
}

awk_value_t *fnv1a_64_impl(int, awk_value_t *result, struct awk_ext_func *) noexcept
{
    awk_value_t str_arg;
    if (!api->api_get_argument(ext_id, 0, AWK_STRING, &str_arg)) {
        api->api_update_ERRNO_string(ext_id, "fnv1a_64: невалідний рядковий аргумент");
        return make_null_string(result);
    }

    const std::string_view input(str_arg.str_value.str, str_arg.str_value.len);
    const uint64_t hash = compute_fnv1a(input);

    char *buf = static_cast<char *>(std::malloc(19));
    if (!buf) {
        api->api_update_ERRNO_int(ext_id, ENOMEM);
        return make_null_string(result);
    }
    std::snprintf(buf, 19, "0x%016llx", static_cast<unsigned long long>(hash));

    return make_malloced_string(buf, std::strlen(buf), result);
}

} // namespace fast_tools

extern "C" {

static awk_ext_func_t func_table[] = {
    { "monotonic_time_ns", fast_tools::monotonic_time_ns_impl, 0, 0, awk_false, nullptr },
    { "fnv1a_64",           fast_tools::fnv1a_64_impl,           1, 1, awk_false, nullptr },
};

int dl_load(const gawk_api_t *const api_p, awk_ext_id_t id)
{
    fast_tools::api = api_p;
    fast_tools::ext_id = id;

    if (api_p->major_version != GAWK_API_MAJOR_VERSION ||
        api_p->minor_version < GAWK_API_MINOR_VERSION) {
        return 0;
    }

    for (const auto &func : func_table) {
        if (!api_p->api_add_ext_func(id, nullptr, const_cast<awk_ext_func_t *>(&func))) {
            return 0;
        }
    }

    api_p->api_register_ext_version(id, fast_tools::EXT_VERSION.data());
    return 1;
}

} // extern "C"
```

### 9.5 Екосистема бібліотек `gawkextlib`

Проєкт **`gawkextlib`** є офіційною інфраструктурою GNU AWK, що надає набір модулів розширення для типових завдань:

1. **`gawk-json` (`@load "json"`):**
   - Надає функції двосторонньої конвертації: `json::from_json(json_str, target_array)` та `json::to_json(source_array)`.

2. **`gawk-xml` (`@load "xml"`):**
   - Потоковий SAX/DOM парсер XML-документів на базі бібліотеки Expat.
   - Дозволяє обробляти гігабайтні XML-потоки без виділення пам'яті під повне DOM-дерево.
3. **`gawk-pgsql` (`@load "pgsql"`):**
   - Клієнтський інтерфейс до СУБД PostgreSQL (`libpq`).
   - Дозволяє виконувати SQL-запити, керувати транзакціями та вивантажувати результати вибірок безпосередньо в масиви AWK.
4. **`gawk-csv` (`@load "csv"`):**
   - Парсер формату CSV за стандартом RFC 4180 на базі `libcsv`.
   - Коректно обробляє вкладені символи переходу рядка `\n` всередині лапок, екрановані коми та спецсимволи, усуваючи обмеження регулярних виразів `FPAT`.
5. **`gawk-select` (`@load "select"`):**
   - Інтерфейс системного виклику `select(2)` для мультиплексування введення/виведення над множиною відкритих файлових дескрипторів, конвеєрів та мережевих сокетів без блокування потоку.

## 10. Патерни обробки реляційних даних та оптимізація з'єднань (Relational Joins) на великих обсягах

Мова AWK є високоефективним потоковим рушієм реляційної алгебри для роботи з текстовими таблицями (TSV, CSV, PSV). Завдяки вбудованим асоціативним хеш-таблицям з амортизованим часом доступу `O(1)` інтерпретатор дозволяє реалізовувати операції з'єднання (`INNER JOIN`, `LEFT OUTER JOIN`, `FULL OUTER JOIN`, `SEMI JOIN`, `ANTI JOIN`) як над даними, що повністю вміщуються в оперативну пам'ять (In-Memory Hash Join), так і над масивами від 10 до 100+ мільйонів рядків, що значно перевищують обсяг доступної RAM (Grace / Partitioned Hash Join та Sort-Merge Join).

### 10.1 Внутрішня ціна пам'яті та межі масштабування таблиць

При виборі стратегії з'єднання необхідно враховувати фізичні накладні витрати пам'яті інтерпретатора. Кожен елемент асоціативного масиву AWK зберігає:
- Вузол хеш-таблиці `HASHNODE` (24–32 байти).
- Структуру ключа `NODE` (32–40 байтів) + виділений рядок ключа в купі (`malloc`).
- Структуру значення `NODE` (32–40 байтів) + виділений рядок значення.
- Частку покажчика у масиві відер `buckets` (~8 байтів).

```
   Накладні витрати пам'яті на 1 запис у масиві AWK ≈ 140–220 байтів
```

Для таблиці розміром:
- **1 000 000 записів:** споживання RAM ≈ 150–220 МБ (повністю комфортно в пам'яті).
- **10 000 000 записів:** споживання RAM ≈ 1.5–2.2 ГБ (вимагає контролю пам'яті).
- **100 000 000 записів:** споживання RAM ≈ 15–22 ГБ (небезпека вичерпання RAM, виклику OOM Killer або деградації через swap thrashing).

### 10.2 Хеш-з'єднання в оперативній пам'яті (In-Memory Hash Join)

Застосовується у випадках, коли менша з двох таблиць (Relation `R`, таблиця розмірностей / довідник) повністю вміщується в оперативну пам'ять, а більша таблиця (Relation `S`, таблиця фактів) потоково транслюється з диска або конвеєра.

#### Алгоритм складається з двох фаз:
1. **Фаза побудови (Build Phase):** файл `R` зчитується першим; ключ з'єднання записується як індекс асоціативного масиву, а значення або повний рядок — як вміст комірки.
2. **Фаза зондування (Probe Phase):** файл `S` зчитується рядок за рядком; для кожного запису ключ витягується і перевіряється в масиві через оператор `in`. У разі збігу генерується з'єднаний рядок.

#### 1. Класичний `INNER JOIN` та `LEFT OUTER JOIN`:

```awk
# inner_join.awk: З'єднання orders.tsv (Факт, $2=user_id) з users.tsv (Довідник, $1=user_id)
# Запуск: awk -F'\t' -v OFS='\t' -f inner_join.awk users.tsv orders.tsv

NR == FNR {
    # ФАЗА ПОБУДОВИ (Build Phase) над першим файлом (users.tsv)
    # Зберігаємо ім'я та email користувача: users[user_id] = name "\t" email
    user_data[$1] = $2 OFS $3
    next
}

{
    # ФАЗА ЗОНДУВАННЯ (Probe Phase) над другим файлом (orders.tsv)
    user_id = $2
    order_id = $1
    amount = $3

    if (user_id in user_data) {
        # INNER JOIN: знайдено збіг у таблиці розмірностей
        print order_id, user_id, user_data[user_id], amount
    } else {
        # LEFT JOIN (якщо розкоментувати): вивід із NULL значеннями
        # print order_id, user_id, "NULL", "NULL", amount
    }
}
```

#### 2. `FULL OUTER JOIN` з відстеженням використаних ключів:

```awk
# full_outer_join.awk: З'єднання двох таблиць із виводом непарних рядків з обох сторін
# Запуск: awk -F'\t' -v OFS='\t' -f full_outer_join.awk left_table.tsv right_table.tsv

NR == FNR {
    # Збереження лівої таблиці
    left_data[$1] = $2
    next
}

{
    # Обробка правої таблиці
    right_key = $1
    right_val = $2
    
    if (right_key in left_data) {
        print right_key, left_data[right_key], right_val
        matched_keys[right_key] = 1
    } else {
        # Рядок є лише в правій таблиці
        print right_key, "NULL", right_val
    }
}

END {
    # Вивід рядків, які були лише в лівій таблиці й не знайшли пари в правій
    for (k in left_data) {
        if (!(k in matched_keys)) {
            print k, left_data[k], "NULL"
        }
    }
}
```

#### 3. Складені ключі з'єднання (Composite Join Keys):
Коли з'єднання здійснюється за кількома полями одночасно (наприклад, `tenant_id` та `user_id`), використовується роздільник `SUBSEP`:

```awk
# З'єднання за двома колонками: ($1, $2)
NR == FNR {
    dim_data[$1, $2] = $3
    next
}

($2, $3) in dim_data {
    print $1, $2, $3, dim_data[$2, $3], $4
}
```

### 10.3 Секціоноване хеш-з'єднання (Grace / Partitioned Hash Join) для обсягів 10–100 млн рядків

Коли **обидва** набори даних є масивними (наприклад, `events.tsv` на 50 млн рядків і `transactions.tsv` на 50 млн рядків, сумарний розмір 30–60 ГБ), побудова повної хеш-таблиці в RAM призводить до аварійного завершення процесу через Out-Of-Memory.

**Секціоноване хеш-з'єднання (Partitioned Hash Join)** розв'язує цю задачу методом «розділяй і володарюй» (Divide and Conquer), гарантуючи константне споживання пам'яті незалежно від загального розміру вхідних файлів.

```
                      Схема Grace / Partitioned Hash Join
     Файл R (100 млн)                       Файл S (100 млн)
            │                                      │
    ┌───────┴───────┐                      ┌───────┴───────┐
    │ Hash-партиції │ (hash % K)           │ Hash-партиції │ (hash % K)
    └───────┬───────┘                      └───────┬───────┘
            │                                      │
      R_00, R_01 ... R_{K-1}                 S_00, S_01 ... S_{K-1}
            │                                      │
            └───────────────────┬──────────────────┘
                                │
                      Попарний In-Memory Join
                      для кожної пари (R_i, S_i):
                      1. Build hash(R_i) в RAM (легко вміщується!)
                      2. Probe S_i рядок за рядком
                      3. Очистити пам'ять delete hash(R_i)
```

#### Фаза 1: Хеш-розбиття потоків на диск (Partitioning Script)

```awk
# partition.awk: Розбиття великого файлу на K партицій за хешем ключа
# Запуск: awk -F'\t' -v K=64 -v PREFIX="part_r" -f partition.awk big_relation_r.tsv

function fnv1a_bucket(key, k_buckets,    len, h, i) {
    len = length(key)
    h = 2166136261  # 32-бітний FNV-1a offset basis
    for (i = 1; i <= len; i++) {
        h = xor(h, ord_map[substr(key, i, 1)])
        h = and(h * 16777619, 4294967295) # FNV prime & 32-bit mask
    }
    return h % k_buckets
}

BEGIN {
    # Ініціалізація ASCII таблиці для швидкого отримання кодів символів
    for (i = 0; i < 256; i++) {
        ord_map[sprintf("%c", i)] = i
    }
    if (!K) K = 64
}

{
    join_key = $1
    bucket = fnv1a_bucket(join_key, K)
    out_file = sprintf("%s_%02d.tsv", PREFIX, bucket)
    
    print $0 > out_file
}
```

#### Фаза 2: Попарне з'єднання відповідних партицій (Join Execution Script)

Оскільки детерміністична хеш-функція гарантує, що записи з однаковими ключами потрапляють виключно у партиції з однаковими номерами `i` (`part_r_05.tsv` та `part_s_05.tsv`), ми з'єднуємо партиції попарно:

```bash
#!/usr/bin/env bash
# run_grace_join.sh: Оркестрація масштабованого Grace Hash Join
set -euo pipefail

K=64
REL_R="dataset_r_50M.tsv"
REL_S="dataset_s_50M.tsv"
RESULT="final_joined.tsv"

rm -f part_r_*.tsv part_s_*.tsv "$RESULT"

# 1. Паралельне або послідовне розбиття обох відношень
gawk -F'\t' -v K="$K" -v PREFIX="part_r" -f partition.awk "$REL_R"
gawk -F'\t' -v K="$K" -v PREFIX="part_s" -f partition.awk "$REL_S"

# 2. Почерговий In-Memory Join кожної пари партицій
for ((i=0; i<K; i++)); do
    f_r=$(printf "part_r_%02d.tsv" "$i")
    f_s=$(printf "part_s_%02d.tsv" "$i")

    if [[ -f "$f_r" && -f "$f_s" ]]; then
        gawk -F'\t' -v OFS='\t' '
            NR == FNR {
                # Кожна партиція займає лише ~1/64 від загального обсягу (легко вміщується в RAM)
                r_data[$1] = $2
                next
            }
            $1 in r_data {
                print $1, r_data[$1], $2
            }
        ' "$f_r" "$f_s" >> "$RESULT"
    fi
    # Видаляємо оброблені партиції для збереження дискового простору
    rm -f "$f_r" "$f_s"
done
```

### 10.4 Потокове з'єднання сортуванням і злиттям (Stream-Sorted Merge Join)

Якщо вхідні дані вже впорядковані за ключем з'єднання (або можуть бути попередньо відсортовані утилітою `sort -t$'\t' -k1,1`), з'єднання двох файлів довільного розміру (навіть 1 терабайт) виконується **в один потоковий прохід із константним споживанням пам'яті `O(1)`**.

#### Алгоритм роботи з двома покажчиками:
Інтерпретатор AWK читає обидва файли синхронно: один потік через стандартний конвеєр, а другий — через команду `getline < file`. Порівнюються поточні ключі `key_R` та `key_S`:
- `key_R < key_S`: потік `R` зсувається вперед.
- `key_R > key_S`: потік `S` зсувається вперед викликом `getline`.
- `key_R == key_S`: генерується з'єднаний рядок.

```awk
# sort_merge_join.awk: Потокове злиття двох попередньо відсортованих TSV файлів
# Використання: awk -F'\t' -v OFS='\t' -v FILE_S="sorted_s.tsv" -f sort_merge_join.awk sorted_r.tsv

BEGIN {
    # Читаємо перший запис із другого файлу FILE_S
    if ((getline line_s < FILE_S) <= 0) {
        has_s = 0
    } else {
        has_s = 1
        split(line_s, f_s, FS)
        key_s = f_s[1]
        val_s = f_s[2]
    }
}

{
    # Поточний рядок із першого файлу (sorted_r.tsv)
    key_r = $1
    val_r = $2

    # Просуваємо другий файл уперед, доки key_s < key_r
    while (has_s && key_s < key_r) {
        if ((getline line_s < FILE_S) <= 0) {
            has_s = 0
            break
        }
        split(line_s, f_s, FS)
        key_s = f_s[1]
        val_s = f_s[2]
    }

    # Якщо ключі збіглися — виводимо результат
    if (has_s && key_s == key_r) {
        print key_r, val_r, val_s
    }
}

END {
    close(FILE_S)
}
```

#### Обробка кардинальності «Багато до Багатьох» (`N:M` Duplicate Keys) у Merge Join:
Якщо ключ з'єднання містить повтори в обох файлах, алгоритм використовує локальний масив для буферизації рядків з однаковими ключами без повного завантаження таблиці в RAM.

### 10.5 Блокове вкладене циклічне з'єднання (Block Nested Loop Join) для нееквівалентних умов

Коли умова з'єднання не є рівністю (Non-Equi Join) — наприклад, пошук потрапляння часової мітки події в інтервал сесії (`event.ts >= session.start && event.ts <= session.end`) чи перевірка діапазонів чисел — хешування непридатне.

Наївний Nested Loop Join перечитує файл `S` повністю для кожного рядка `R`, виконуючи `|R|` повних сканувань файлу. **Block Nested Loop Join** зчитує з `R` блок розміром `B` записів у буфер пам'яті і сканує файл `S` один раз для всього блоку, скорочуючи дискове читання у `B` разів:

```awk
# block_nested_loop_range_join.awk: З'єднання подій з інтервалами сесій
# Запуск: awk -F'\t' -v OFS='\t' -v SESSIONS_FILE="sessions.tsv" -v BLOCK_SIZE=50000 -f block_nested_loop_range_join.awk events.tsv

function flush_block(    e_idx, s_line, s_fields, s_user, s_start, s_end, s_id) {
    if (block_count == 0) return

    # Скануємо файл сесій один раз для всього накопиченого блоку подій
    while ((getline s_line < SESSIONS_FILE) > 0) {
        split(s_line, s_fields, FS)
        s_user  = s_fields[1]
        s_start = s_fields[2] + 0
        s_end   = s_fields[3] + 0
        s_id    = s_fields[4]

        # Перевіряємо всі події в поточному блоці
        for (e_idx = 1; e_idx <= block_count; e_idx++) {
            if (ev_user[e_idx] == s_user) {
                ts = ev_ts[e_idx]
                if (ts >= s_start && ts <= s_end) {
                    print ev_id[e_idx], ev_user[e_idx], ts, s_id, s_fields[5]
                }
            }
        }
    }
    close(SESSIONS_FILE) # Перемотуємо файл сесій на початок

    # Очищуємо блок
    block_count = 0
    delete ev_id
    delete ev_user
    delete ev_ts
}

BEGIN {
    if (!BLOCK_SIZE) BLOCK_SIZE = 50000
    block_count = 0
}

{
    # Накопичуємо блок подій
    block_count++
    ev_id[block_count]   = $1
    ev_user[block_count] = $2
    ev_ts[block_count]   = $3 + 0

    if (block_count >= BLOCK_SIZE) {
        flush_block()
    }
}

END {
    flush_block()
}
```

### 10.6 Зведена інженерна матриця вибору алгоритму з'єднання

| Алгоритм | Часова складність | Просторова складність (RAM) | Дисковий I/O оверхед | Максимальний обсяг даних | Підтримувані типи зв'язків | Допустимі предикати |
|---|---|---|---|---|---|---|
| **In-Memory Hash Join** | `O(|R| + |S|)` | `O(|R|)` (уся таблиця `R` у RAM) | `0` (чистий потоковий прохід) | Менша таблиця `|R| ≤ 5–10 млн` рядків | `1:1`, `1:N`, `N:M` | Тільки рівність (`Equi-Join`, `$1 == $2`) |
| **Grace / Partitioned Hash Join** | `O(|R| + |S|)` (з коефіцієнтом розбиття) | `O(|R| / K)` (розмір однієї партиції) | Запис і читання `2 · (|R| + |S|)` байтів партицій | Необмежений (`10–100+ млн` рядків, 100+ ГБ) | `1:1`, `1:N`, `N:M` | Тільки рівність (`Equi-Join`) |
| **Stream Sort-Merge Join** | `O(|R| + |S|)` (без урахування сортування) | `O(1)` (константний розмір буфера) | Залежить від зовнішнього `sort` | Необмежений (терабайти даних) | `1:1`, `1:N`, `N:M` (з буфером дублікатів) | Тільки рівність (`Equi-Join`, `<`, `==`, `>`) |
| **Block Nested Loop Join** | `O(|R| + (|R|/B) · |S|)` | `O(B)` (фіксований розмір блоку) | `(|R| / B)` повторних читань файлу `S` | Середні та великі обсяги при фільтрації | `1:1`, `1:N`, `N:M` | Довільні нерівності (`>=`, `<=`, `!=`, regex, діапазони) |

## 11. Порівняльний аналіз архітектури та оптимізацій рушіїв AWK: Gawk, Mawk та Nawk

Екосистема Unix містить три основні реалізації мови AWK, кожна з яких оптимізована під різні архітектурні цілі: гнучкість та функціональне багатство (`gawk`), максимальна швидкість потокової обробки (`mawk`) та мінімалістична компактність еталонного стандарту (`nawk` / `bwk`).

```
          Архітектурні моделі інтерпретаторів AWK

  [ GNU AWK (Gawk) ]        [ Fast AWK (Mawk) ]        [ One True AWK (Nawk/bwk) ]
 ┌───────────────────┐     ┌───────────────────┐      ┌───────────────────────────┐
 │ Вихідний код AWK  │     │ Вихідний код AWK  │      │ Вихідний код AWK          │
 └─────────┬─────────┘     └─────────┬─────────┘      └─────────────┬─────────────┘
           │ (Bison AST)             │ (Bison AST)                  │ (Yacc AST)
           ▼                         ▼                              ▼
 ┌───────────────────┐     ┌───────────────────┐      ┌───────────────────────────┐
 │ Bytecode Compiler │     │ Bytecode Compiler │      │   AST Tree-Walk Engine    │
 └─────────┬─────────┘     └─────────┬─────────┘      │   (execute(Node *tree))   │
           │ (Opcode Array)          │ (DFA Opcodes)  └─────────────┬─────────────┘
           ▼                         ▼                              │
 ┌───────────────────┐     ┌───────────────────┐                    │

   MPFR / Shared Libs ]      Zero-Copy Strings ]        Мінімальний бінарник <200KB]
```

### 11.1 Архітектурні моделі виконання

#### 1. GNU AWK (`gawk`): Стек-орієнтована віртуальна машина байт-коду (Bytecode VM)
- **Модель трансляції:** Починаючи з версії 4.0, `gawk` відмовився від класичного прямого виконання AST на користь двофазного конвеєра: граматика Bison будує проміжне дерево розбору, яке транслюється компілятором байт-коду в лінійний масив інструкцій `INSTRUCTION` (`Op_push`, `Op_field_spec`, `Op_store_var`, `Op_jmp`, `Op_match_rec` тощо).
- **Віртуальна машина:** Виконання здійснюється у внутрішньому циклі диспетчеризації `r_interpret()`. Операнди передаються через системний стек значень, де кожна комірка представлена структурою `NODE`.
- **Керування пам'яттю та CoW:** Використовує підрахунок посилань (Reference Counting) та стратегію копіювання за записом (Copy-on-Write) для рядків і асоціативних масивів.
- **Особливості:** Повна підтримка стандартів POSIX.1-2008/2024 та великий набір розширень: довільна точність MPFR/GMP (`-M`), регулярні вирази з підтримкою Unicode-властивостей, динамічні C/C++ плагіни (`@load`), відлагоджувач `--debug` та профайлер `--profile`.
- **Накладні витрати:** Розгалужений диспетчер інструкцій, постійна валідація багатобайтових послідовностей UTF-8 (`mbrtowc`) та важка структура вузла роблять `gawk` повільнішим за `mawk` на чисельних та посимвольних циклах.

#### 2. Fast AWK (`mawk`): Спеціалізований байт-код автомат та нуль-копіювальний I/O
- **Модель трансляції:** Розроблений Майком Бреннаном (Mike Brennan). Транслює код AWK у компактний оптимізований байт-код із мінімальною кількістю переходів.
- **Рушій регулярних виразів:** Містить власний високоефективний алгоритм компіляції детермінованих скінченних автоматів (DFA). Регулярні вирази транслюються безпосередньо у плоскі таблиці переходів станів, уникаючи рекурсивного повернення (backtracking).
- **Пряма буферизація вводу-виводу:** `mawk` повністю обходить стандартні бібліотечні виклики libc `stdio` (`fgets(3)`, `fgetc(3)`), які здійснюють надлишкове блокування м'ютексів та подвійне копіювання. Замість цього `mawk` читає дані безпосередньо системними викликами `read(2)` у великі кільцеві буфери розміром 64–128 КБ.
- **Нуль-копіювальні поля (Zero-Copy):** Структура `CELL` (24–32 байти) містить прямий покажчик `ptr` на байти всередині кільцевого буфера читання. Поки поле не модифікується, інтерпретатор не виділяє пам'ять у купі через `malloc()`.
- **Продуктивність:** Найшвидший інтерпретатор AWK у світі. На задачах агрегації та фільтрації гігабайтних текстових масивів демонструє пропускну здатність 1.2–2.0 ГБ/с, випереджаючи `gawk` у 3–8 разів.
- **Обмеження:** Орієнтований на однобайтові кодування (ASCII/ISO-8859), не підтримує GNU-розширень (`FIELDWIDTHS`, `FPAT`, `@load`, багатовимірні масиви як об'єкти) та довільну точність.

#### 3. One True AWK (`nawk` / `bwk`): Прямий інтерпретатор дерева розбору (AST Tree-Walk)
- **Модель трансляції:** Створений Браяном Керніганом (Bell Labs) як еталонна реалізація «нового AWK» (New AWK). Не транслює програму в байт-код.
- **Механізм виконання:** Парсер Yacc генерує дерево абстрактного синтаксису зі структур `Node`. Двигун виконання обходить це дерево рекурсивним викликом функції `execute(Node *n)`, яка містить розгалуження `switch (n->nobj)` за типами вузлів (`PROGRAM`, `PAREN`, `CAT`, `ASSIGN`, `SPLIT` тощо).
- **Компактність та стабільність:** Розмір двійкового файлу становить лише 150–200 КБ, відсутні будь-які зовнішні бібліотечні залежності. Є стандартним системним інтерпретатором у FreeBSD, OpenBSD, NetBSD, macOS та Solaris.
- **Продуктивність:** Рекурсивний обхід дерева вузлів генерує велику кількість викликів функцій C, глибокий стек та спричиняє часті промахи кешу процесора (pointer chasing). На тривалих чисельних розрахунках `nawk` значно поступається `mawk` і `gawk`. Проте завдяки відсутності фази компіляції байт-коду та ініціалізації великих структур, затримка старту (Startup Latency) становить менше 0.5 мс, що робить його ідеальним для мільйонів коротких однорядкових викликів у скриптах ініціалізації ОС.

### 11.2 Порівняльна матриця характеристик рушіїв

| Характеристика | GNU AWK (`gawk` 5.3+) | Fast AWK (`mawk` 1.3.4+) | One True AWK (`nawk` / `bwk`) |
|---|---|---|---|
| **Архітектура виконання** | Стек-орієнтована VM байт-коду | Швидка VM з кастомним байт-кодом | Рекурсивний обхід AST дерева (`execute()`) |
| **Проміжне представлення** | Лінійний масив `INSTRUCTION` | Опкоди та DFA таблиці | Дерево вказівників на структури `Node` |
| **Розмір комірки значення** | `NODE` (48–64 байти, CoW refcount) | `CELL` (24–32 байти, inlined data) | `Cell` / `Node` (32–48 байтів) |
| **Рушій Regular Expressions** | GNU Regex (DFA + NFA, multibyte) | Brennan DFA (прямі таблиці станів) | Kernighan Regex (DFA/NFA) |
| **Система введення/виведення** | C `stdio` (`FILE*`, `BUFSIZ`, `fflush`) | Прямий `read(2)` у 64–128 КБ кільцеві буфери | C `stdio` (`FILE*`, `fgets`) |
| **Підтримка UTF-8 / локалей** | Повна (символьна адресація `mbrtowc`) | Однобайтова (Raw Byte / ASCII) | Однобайтова / базова локаль |
| **Пропускна здатність (I/O throughput)** | Помірна (250–500 МБ/с; до 1 ГБ/с з `-b`) | Екстремальна (1.2–2.2 ГБ/с) | Помірна (200–400 МБ/с) |
| **Затримка запуску (Startup latency)** | ~3.5–8.0 мс | ~1.0–2.0 мс | < 0.5 мс |
| **Арифметика довільної точності** | Так (`-M` через MPFR/GMP) | Ні (лише IEEE 754 double) | Ні (лише IEEE 754 double) |
| **Розширення (FIELDWIDTHS, FPAT)** | Так | Ні | Ні |
| **Динамічні C-модулі (`@load`)** | Так (Gawk Extension API) | Ні | Ні |
| **Справжні багатовимірні масиви** | Так (`arr[i][j]`) | Ні (лише емуляція через `SUBSEP`) | Ні (лише емуляція через `SUBSEP`) |

### 11.3 Інженерні оптимізації швидкодії AWK у високонавантажених конвеєрах

Під час обробки сотень гігабайтів логів або потоків у режимі реального часу оптимізація структури скрипту дозволяє підвищити пропускну здатність у 3–10 разів без зміни мови програмування.

#### 1. Форсування 8-бітного однобайтового режиму (`LC_ALL=C` та `gawk -b`)
За замовчуванням у UTF-8 локалях `gawk` змушений валідувати кожен вхідний байт через функцію `mbrtowc(3)` для коректного визначення меж Unicode-символів. Це створює колосальні накладні витрати CPU. Встановлення змінної середовища `LC_ALL=C` або передача прапорця `-b` перемикає парсер у пряму побайтову обробку, прискорюючи фільтрацію у 3–4 рази:
```bash
# Повільно (багатобайтова валідація UTF-8):
gawk -F',' '$1 ~ /^ERROR/ { print $2 }' massive_access.log

# Швидко (побайтовий режим ASCII/Raw-bytes):
LC_ALL=C gawk -b -F',' '$1 ~ /^ERROR/ { print $2 }' massive_access.log
```

#### 2. Усунення зайвого розбиття полів (Lazy Field Splitting)
Інтерпретатори AWK не розбивають запис `$0` на поля `$1..$NF` доти, доки в поточному правилі не відбудеться явного звернення до будь-якої позиційної змінної `$i` або системної змінної `NF`.
- Якщо рядок відкидається на рівні умови `$0`, функція `split_fields()` взагалі не викликається:
```awk
# Оптимально: фільтрація за $0 перед зверненням до полів
# Рядки, що не містять "POST", відсікаються без парсингу полів!
/POST/ && $9 == "500" { error_count++ }

# Неоптимально: рушій вимушений розбити ВСІ рядки на поля
$6 == "POST" && $9 == "500" { error_count++ }
```

#### 3. Вимкнення сортування при обході масивів
За замовчуванням GNU AWK може виконувати внутрішнє сортування ключів або виділяти тимчасові буфери індексів. Явне встановлення несортованого обходу усуває накладні витрати на виклики `qsort`:
```awk
BEGIN {
    PROCINFO["sorted_in"] = "@unsorted"
}
```

#### 4. Статичні літерали регулярних виразів проти динамічних рядків
- Регулярні вирази, задані літералами `/pattern/`, компілюються у DFA-автомат **один раз** під час завантаження скрипту.
- Використання рядкових змінних у виразах зіставлення `$0 ~ dynamic_str` змушує інтерпретатор щоразу перевіряти, чи змінився рядок, та ініціювати повторну компіляцію автомата регулярного виразу на кожному записі.
```awk
# Швидко (DFA скомпільовано один раз під час старту):
$1 ~ /^[0-9]{4}-[0-9]{2}-[0-9]{2}$/

# Повільно (потенційна рекомпіляція шаблону на кожному рядку):
pat = "^[0-9]{4}-[0-9]{2}-[0-9]{2}$"
$1 ~ pat
```

#### 5. Атомарне очищення масивів замість циклічного видалення
Видалення всіх елементів масиву в циклі `for (k in arr) delete arr[k]` виконує `N` пошуків у хеш-таблиці та `N` модифікацій ланцюжків колізій. Інструкція `delete arr` звільняє всі відра і вузли за один прямий прохід пам'яті:
```awk
# Швидко (атомарне очищення структури хеш-таблиці):
delete cache_map

# Повільно (O(N) ітерацій з пошуком та розлінковуванням):
for (k in cache_map) {
    delete cache_map[k]
}
```

#### 6. Мінімізація конкатенацій та модифікацій `$0`
Будь-яка зміна позиційного поля (наприклад, `$1 = $1`) встановлює внутрішній прапорець невалідності `$0`, що змушує рушій виконувати повторне виділення буфера пам'яті та конкатенацію всіх полів через `OFS` під час наступного виклику `print $0`. Форматуйте вивід через кому `print $1, $2, $3` або `printf`, уникаючи примусової перебудови всього вхідного запису.
