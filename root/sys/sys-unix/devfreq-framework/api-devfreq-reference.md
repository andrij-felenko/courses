# 📋 Довідник інтерфейсів devfreq: структури ядра та інтерфейс sysfs

Підсистема devfreq надає два рівні програмних інтерфейсів: внутрішній програмний інтерфейс ядра (Kernel API) для розробників драйверів периферійних пристроїв та алгоритмів регуляторів, а також стандартизований інтерфейс файлової системи `sysfs` для моніторингу, діагностики та конфігурації з простору користувача.

---

### 1. Головні структури даних ядра Linux (`<linux/devfreq.h>`)

#### Структура `struct devfreq_dev_profile`
Визначає апаратні характеристики та функції зворотного виклику конкретного драйвера пристрою:

```c
struct devfreq_dev_profile {
    unsigned long initial_freq;
    unsigned int polling_ms;
    int (*target)(struct device *dev, unsigned long *freq, u32 flags);
    int (*get_dev_status)(struct device *dev, struct devfreq_dev_status *stat);
    int (*get_cur_freq)(struct device *dev, unsigned long *freq);
    void (*exit)(struct device *dev);
    unsigned long *freq_table;
    unsigned int max_state;
    bool is_cooling;
};
```

* `initial_freq`: Початкова тактова частота пристрою в герцах (Гц), яка встановлюється під час завантаження ядра або ініціалізації драйвера.
* `polling_ms`: Базовий період опитування лічильників навантаження в мілісекундах. Якщо значення дорівнює нулю, ядро devfreq вважає, що пристрій використовує подієво-орієнтовану модель (наприклад, через переривання) і не запускає періодичний таймер моніторингу.
* `target()`: Головна функція перемикання робочого стану. Вона приймає покажчик на запитану цільову частоту `freq` та набір прапорців `flags` (наприклад, `DEVFREQ_FLAG_LEAST_UPPER_BOUND`). Драйвер знаходить відповідну точку OPP, застосовує напругу й тактовий сигнал, після чого записує у `*freq` фактично досягнуту частоту. Повертає 0 у разі успіху або негативний код помилки (`-EINVAL`, `-EBUSY`, `-EIO`).
* `get_dev_status()`: Функція опитування поточного навантаження. Заповнює поля структури `struct devfreq_dev_status`. Викликається ядром devfreq перед кожною оцінкою цільової частоти регулятором.
* `get_cur_freq()`: Опціональний виклик для прямого зчитування поточної апаратної частоти з регістрів тактового генератора. Використовується, якщо частота може змінюватися апаратними автоматами або сторонніми механізмами без відома ядра devfreq.
* `exit()`: Опціональна функція вивільнення специфічних апаратних ресурсів під час видалення екземпляра devfreq.
* `freq_table` та `max_state`: Статичний масив підтримуваних частот та кількість елементів у ньому (використовується для застарілих драйверів, які не інтегровані з Device Tree та OPP Framework).
* `is_cooling`: Булевий прапорець, який сигналізує ядру про необхідність автоматичної реєстрації цього екземпляра devfreq як охолоджувального пристрою (Thermal Cooling Device) у підсистемі контролю температури.

#### Структура `struct devfreq_dev_status`
Містить статистичні дані навантаження пристрою за останній період моніторингу:

```c
struct devfreq_dev_status {
    unsigned long total_time;
    unsigned long busy_time;
    unsigned long current_frequency;
    void *private_data;
};
```

* `total_time`: Загальна тривалість інтервалу спостереження. Може вимірюватися в апаратних тактах шини, мікросекундах або внутрішніх одиницях лічильника.
* `busy_time`: Час, протягом якого апаратний блок фактично виконував обчислення або передавав дані шиною. Обов'язкова умова коректності: `busy_time <= total_time`.
* `current_frequency`: Поточна робоча частота пристрою на момент зчитування лічильників.
* `private_data`: Необов'язковий покажчик на додаткові специфічні дані пристрою, які можуть використовуватися спеціалізованими регуляторами (наприклад, показники черг DMA чи температура кристала).

#### Внутрішнє представлення пристрою в ядрі (`struct devfreq`)
Кожен зареєстрований пристрій представляється в ядрі екземпляром `struct devfreq`. Головними полями цієї структури є:
* `dev`: Базовий об'єкт `struct device`, прив'язаний до файлової системи `sysfs`.
* `profile`: Покажчик на структуру `struct devfreq_dev_profile`, надану драйвером.
* `governor`: Покажчик на поточний активний регулятор `struct devfreq_governor`.
* `previous_freq`: Попередня робоча частота, яка використовується для підрахунку переходів і сповіщення підлеглих пристроїв.
* `lock`: Головний м'ютекс блокування екземпляра, що синхронізує операції перемикання регуляторів, оновлення параметрів sysfs та виконання черги моніторингу.
* `work`: Структура відкладеної черги `delayed_work`, яка відповідає за періодичне викликання циклу опитування навантаження.
* `trans_stat`: Внутрішня таблиця переходів між частотами та накопичувальний лічильник часу перебування в кожному стані.

#### Життєвий цикл регулятора (`struct devfreq_governor`)

Кожен регулятор реалізує функцію обробки подій `event_handler(struct devfreq *df, unsigned int event, void *data)`. Ядро надсилає регулятору такі стандартні події:

```c
#define DEVFREQ_GOV_START               1
#define DEVFREQ_GOV_STOP                2
#define DEVFREQ_GOV_UPDATE_INTERVAL     3
#define DEVFREQ_GOV_SUSPEND             4
#define DEVFREQ_GOV_RESUME              5
```

* `DEVFREQ_GOV_START`: Ініціалізація внутрішніх структур регулятора, налаштування порогових значень та запуск робочої черги моніторингу через `devfreq_monitor_start()`.
* `DEVFREQ_GOV_STOP`: Зупинка робочої черги моніторингу через `devfreq_monitor_stop()` та звільнення пам'яті регулятора перед вивантаженням драйвера або перемиканням на інший алгоритм.
* `DEVFREQ_GOV_UPDATE_INTERVAL`: Сигнал про зміну періоду опитування через запис у `polling_interval` із простору користувача. Регулятор переналаштовує таймер відкладеної черги.
* `DEVFREQ_GOV_SUSPEND`: Призупинення моніторингу перед переходом системи в режим сну (System Suspend). Робоча черга скасовується, щоб уникнути пробудження процесора.
* `DEVFREQ_GOV_RESUME`: Відновлення регулярного моніторингу після виходу системи зі стану сну (System Resume).

### 2. Ключові функції ядра для драйверів пристроїв

| Сигнатура функції | Призначення та поведінка |
| :--- | :--- |
| `struct devfreq *devm_devfreq_add_device(struct device *dev, struct devfreq_dev_profile *profile, const char *gov_name, void *data)` | Створює, реєструє та ініціалізує керований екземпляр devfreq для пристрою `dev`. Автоматично прив'язує його до життєвого циклу драйвера (devres). Приймає ім'я початкового регулятора `gov_name`. Повертає покажчик на `struct devfreq` або помилку в форматі `ERR_PTR`. |
| `int devfreq_remove_device(struct devfreq *df)` | Примусово видаляє екземпляр devfreq, зупиняє активний регулятор і видаляє записи з `sysfs` (використовується для не-devres викликів). |
| `struct dev_pm_opp *devfreq_recommended_opp(struct device *dev, unsigned long *freq, u32 flags)` | Здійснює пошук у зареєстрованій таблиці OPP найближчої частоти, що задовольняє запит `freq` з урахуванням обмежень `min_freq`, `max_freq` та температурного тротлінгу. Записує знайдене значення у `*freq`. |
| `void devfreq_monitor_start(struct devfreq *df)` | Запускає таймер відкладеної черги `delayed_work` для періодичного опитування лічильників пристрою. |
| `void devfreq_monitor_stop(struct devfreq *df)` | Зупиняє та скасовує заплановані завдання відкладеної черги моніторингу. |
| `int devfreq_update_status(struct devfreq *df, unsigned long freq)` | Оновлює внутрішню статистику перебування пристрою в поточному стані та реєструє перехід на нову частоту `freq` у матриці `trans_stat`. |
| `int devfreq_add_governor(struct devfreq_governor *governor)` | Реєструє новий алгоритм регулятора в глобальному реєстрі ядра Linux. Дозволяє підключати кастомні регулятори як модулі ядра. |
| `int devfreq_remove_governor(struct devfreq_governor *governor)` | Видаляє регулятор із глобального списку за умови, що жоден активний пристрій його не використовує. |

#### Механізм ланцюжків сповіщень (Notifier Chains)
Підсистема devfreq надає механізм підписки на події перемикання частоти через функцію `devfreq_register_notifier()`. Клієнтські драйвери можуть отримувати два типи сповіщень:
* `DEVFREQ_PRECHANGE`: надсилається безпосередньо перед перемиканням частоти пристрою. Використовується для завчасного підняття напруги або підготовки шин.
* `DEVFREQ_POSTCHANGE`: надсилається відразу після успішного встановлення нової робочої точки. На цій події базується робота регулятора `passive` для підлеглих шин і кешів.

#### Обробка апаратних помилок та відмов PMIC
Якщо під час виконання функції `target()` перетворювач напруги або тактовий генератор повертає код помилки (наприклад, тайм-аут стабілізації напруги `-ETIMEDOUT` або перевантаження лінії живлення `-EBUSY`), ядро devfreq скасовує перехід. Поточна робоча частота залишається незмінною, а помилка логується в кільцевий буфер ядра `dmesg`. На наступному кроці таймера регулятор повторює спробу розрахунку та адаптації стану.

### 3. Інтерфейс файлової системи Sysfs (`/sys/class/devfreq/<dev>/`)

Для кожного зареєстрованого в системі devfreq-пристрою створюється каталог у `/sys/class/devfreq/<dev>/`, який містить такі атрибути:

| Атрибут | Права | Тип даних | Опис та семантика використання |
| :--- | :---: | :---: | :--- |
| `cur_freq` | `r--` | `unsigned long` | Поточна робоча частота пристрою в герцах (Гц). Зчитується з кешованого стану ядра або через апаратний виклик `get_cur_freq()`. |
| `target_freq` | `r--` | `unsigned long` | Остання цільова частота в герцах, яку активний регулятор запросив у драйвера. |
| `governor` | `rw-` | `string` | Назва поточного регулятора (наприклад, `simple_ondemand`, `passive`, `performance`). Запис назви іншого регулятора у цей файл миттєво зупиняє старий алгоритм і запускає новий. Потрібні права `CAP_SYS_ADMIN`. |
| `available_governors` | `r--` | `string` | Перелік усіх скомпільованих у ядрі регуляторів, які підтримуються цим пристроєм, розділених пробілами. |
| `available_frequencies` | `r--` | `string` | Список усіх дискретних робочих частот (у Гц), доступних для пристрою згідно з його OPP-таблицею, відсортований від меншої до більшої. |
| `min_freq` | `rw-` | `unsigned long` | Нижня допустима межа частоти в герцах. Регулятор не може опустити частоту нижче цього значення. Дозволяє користувачеві встановлювати гарантовану мінімальну продуктивність. |
| `max_freq` | `rw-` | `unsigned long` | Верхня допустима межа частоти в герцах. Використовується для штучного обмеження продуктивності або термічного захисту. |
| `polling_interval` | `rw-` | `unsigned int` | Період опитування лічильників у мілісекундах. Зміна значення перезапускає таймер робочої черги. |
| `trans_stat` | `r--` | `table` | Повна матриця переходів між усіма частотами та сумарний час у мілісекундах, проведений у кожній робочій точці від моменту завантаження. |
| `load` | `r--` | `string` | Останній виміряний відсоток навантаження пристрою у форматі `busy_time / total_time (load%)`. |
| `timer` | `rw-` | `string` | Тип системного таймера для робочої черги: `delayed_work` (звичайний таймер) або `deferrable_timer` (відкладений таймер, що не будить процесор зі сну). |

#### Асинхронний моніторинг через `poll()` та `epoll()`
Файлова система `sysfs` підтримує механізм сповіщень `sysfs_notify()`. Програми простору користувача (наприклад, системні монітори або ігрові рушії) можуть відкрити дескриптор файлу `cur_freq` або `governor` і заблокуватися у виклику `poll()` або `epoll()`. Коли ядро виконує перемикання робочої точки, виклик `poll()` миттєво розблоковується з подією `POLLPRI` / `POLLERR`, дозволяючи додатку реагувати на зміну стану без неперервного ресурсомісткого циклу активного опитування (*busy-polling*).

### 4. Практичний приклад: утиліта моніторингу devfreq-пристрою

Програма для простору користувача відкриває каталог пристрою в `sysfs`, зчитує поточну тактову частоту, вираховує її значення в мегагерцах та виводить детальний звіт матриці переходів:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

int main(int argc, char *argv[]) {
    const char *dev_name = (argc > 1) ? argv[1] : "10040000.bus-controller";
    char path[256];
    char buffer[512];
    FILE *f;

    snprintf(path, sizeof(path), "/sys/class/devfreq/%s/cur_freq", dev_name);
    f = fopen(path, "r");
    if (!f) {
        perror("Не вдалося відкрити cur_freq");
        return 1;
    }

    if (fgets(buffer, sizeof(buffer), f)) {
        unsigned long long freq = strtoull(buffer, NULL, 10);
        printf("Пристрій: %s\nПоточна частота: %.2f МГц\n", dev_name, (double)freq / 1e6);
    }
    fclose(f);

    snprintf(path, sizeof(path), "/sys/class/devfreq/%s/trans_stat", dev_name);
    f = fopen(path, "r");
    if (f) {
        printf("\n--- Статистика переходів частот ---\n");
        while (fgets(buffer, sizeof(buffer), f)) {
            printf("%s", buffer);
        }
        fclose(f);
    }

    return 0;
}
```
```cpp
#include <iostream>
#include <fstream>
#include <string>
#include <filesystem>
#include <iomanip>

namespace fs = std::filesystem;

int main(int argc, char* argv[]) {
    std::string dev_name = (argc > 1) ? argv[1] : "10040000.bus-controller";
    fs::path base_path = fs::path("/sys/class/devfreq") / dev_name;

    fs::path cur_freq_file = base_path / "cur_freq";
    std::ifstream cur_file(cur_freq_file);
    if (!cur_file.is_open()) {
        std::cerr << "Помилка відкриття " << cur_freq_file << std::endl;
        return 1;
    }

    unsigned long long freq = 0;
    if (cur_file >> freq) {
        std::cout << "Пристрій: " << dev_name << "\n"
                  << "Поточна частота: " << std::fixed << std::setprecision(2)
                  << (static_cast<double>(freq) / 1e6) << " МГц\n";
    }

    fs::path trans_stat_file = base_path / "trans_stat";
    std::ifstream trans_file(trans_stat_file);
    if (trans_file.is_open()) {
        std::cout << "\n--- Статистика переходів частот ---\n";
        std::string line;
        while (std::getline(trans_file, line)) {
            std::cout << line << "\n";
        }
    }

    return 0;
}
```
