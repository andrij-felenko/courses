# 📋 Інтерфейс kstat та параметри ядра для налаштування ARC і ZIL

Комплексна підсистема кешування ARC (Adaptive Replacement Cache) та журнал синхронного запису ZIL (ZFS Intent Log) у ZFS on Linux надають системному адміністратору та розробнику два основних канали спостереження й керування. Першим є псевдофайлова система `/proc/spl/kstat/zfs/` для отримання телеметрії та лічильників продуктивності в реальному часі. Другим каналом виступають параметри модуля ядра `/sys/module/zfs/parameters/` для тонкого налаштування поведінки пам'яті, а також властивості датасетів ZFS.

## 1. Лічильники псевдофайлу /proc/spl/kstat/zfs/arcstats

Файл `/proc/spl/kstat/zfs/arcstats` експортує понад 80 метрик роботи ARC у форматі `kstat` (структура даних із Solaris, перенесена в Linux шаром сумісності SPL — Solaris Porting Layer). Формат виводу містить заголовок `name type data` з подальшими рядками вигляду `<name> <type> <value>`.

Для аналізу стану оперативної пам'яті ядро ZFS оновлює ці лічильники атомарно при кожній операції читання, витіснення або зміни розміру кешу.

### Основні лічильники розміру та балансу ARC

Підсистема ARC динамічно виділяє та вивільняє пам'ять залежно від навантаження. Для спостереження за стелею та поточним обсягом кешу використовуються такі ключові лічильники:

| Лічильник | Тип | Опис та одиниці вимірювання |
|---|---|---|
| `size` | 4 (uint64) | Поточний загальний розмір ARC у пам'яті (байти) |
| `c` | 4 (uint64) | Цільовий (максимально допустимий у поточних умовах) розмір ARC `c` (байти) |
| `c_min` | 4 (uint64) | Мінімально припустима межа стискання ARC `c_min` (байти) |
| `c_max` | 4 (uint64) | Абсолютний максимум ємності ARC `c_max` (байти) |
| `p` | 4 (uint64) | Адаптивна цільова вага списку MRU у байтах; в OpenZFS від 2.2 цього лічильника вже немає |
| `arc_meta_used` | 4 (uint64) | Загальний обсяг пам'яті, зайнятий метаданими (dnodes, dentries, indirect blocks) |
| `arc_meta_limit` | 4 (uint64) | Поточний верхній поріг пам'яті під метадані |
| `arc_meta_max` | 4 (uint64) | Піковий історичний розмір пам'яті під метадані |
| `arc_dnode_used` | 4 (uint64) | Обсяг пам'яті, зайнятий кешованими dnode-структурами файлів |
| `anon_size` | 4 (uint64) | Розмір анонімних (ще не прив'язаних до конкретного списку) даних |
| `mru_size` | 4 (uint64) | Розмір активного списку блоків MRU (Most Recently Used) |
| `mfu_size` | 4 (uint64) | Розмір активного списку блоків MFU (Most Frequently Used) |

Коли показник `size` наближається до межі `c`, підсистема витіснення починає звільняти сторінки пам'яті згідно з пропорціями списків MRU та MFU. Якщо величина `p` висока, перевага надається збереженню нещодавно зчитаних даних, тоді як при малій `p` кеш утримує записи з високою частотою звернення. Показник `arc_meta_used` демонструє тиск з боку файлової структури — якщо значення досягає `arc_meta_limit`, ZFS примусово витісняє метадані каталогів та dnode-записи. Ця пара лічильників належить епосі до OpenZFS 2.2: у 2.2 адаптацію ARC переписано, окремої межі метаданих і лічильника `p` більше немає, а баланс даних і метаданих задає один параметр `zfs_arc_meta_balance`.

### Лічильники влучань та промахів (Hits / Misses)

Для оцінки ефективності кешування системний інженер обчислює відсоток влучань на основі агрегованих та деталізованих метрик доступу:

| Лічильник | Опис | Формула аналізу |
|---|---|---|
| `hits` | Загальна кількість влучань у кеш ARC | `hits / (hits + misses)` = Hit Ratio |
| `misses` | Загальна кількість промахів повз ARC | Читання з фізичного диска |
| `demand_data_hits` | Влучання при прямих запитах даних додатками | Високий показник свідчить про ефективність для IO |
| `demand_data_misses` | Промахи при прямих запитах даних | Призводить до блокуючого читання з пулу |
| `demand_metadata_hits` | Влучання при зчитуванні метаданих файлової системи | Прискорює `stat()`, `ls`, обхід каталогів |
| `demand_metadata_misses` | Промахи метаданих | Спричиняє читання дзеркальних метаблоків |
| `prefetch_data_hits` | Влучання при попередньому зчитуванні (Prefetch) | Успішне вгадування послідовних читань |
| `prefetch_data_misses` | Промахи prefetch-алгоритму | Марно витрачений I/O пропускної здатності |
| `mru_hits` | Влучання у список нещодавно використаних блоків | Свідчить про перевагу нових, щойно прочитаних даних |
| `mfu_hits` | Влучання у список часто використовуваних блоків | Свідчить про наявність гарячого ядра даних |
| `mru_ghost_hits` | Влучання в метадані витіснених MRU-блоків B₁ | Змушує ARC збільшувати `p` на користь MRU |
| `mfu_ghost_hits` | Влучання в метадані витіснених MFU-блоків B₂ | Змушує ARC зменшувати `p` на користь MFU |

Співвідношення `mru_ghost_hits` та `mfu_ghost_hits` показує роботу адаптивного зворотного зв'язку. Часто влучання в B₁ сигналізують про потребу збільшити цільовий розмір `p`, щоб запобігти передчасному витісненню нових блоків.

## 2. Параметри модуля ядра /sys/module/zfs/parameters/

Параметри модуля `zfs` дозволяють змінювати ліміти кешування та синхронного запису. Для зміни параметра в реальному часі використовується команда `echo <val> > /sys/module/zfs/parameters/<param>`, або файл конфігурації `/etc/modprobe.d/zfs.conf` для персистентного збереження при перезавантаженні системи.

### Параметри керування обсягом пам'яті ARC

Модуль ZFS надає гнучкі важелі обмеження споживання оперативної пам'яті для запобігання конфліктам із системами віртуалізації та базам даних:

```
zfs_arc_max (uint64)
```
- **Опис**: Максимальний розмір ARC у байтах. 
- **Значення за замовчуванням**: `0` (автоматично розраховується як 50% фізичної RAM системи).
- **Приклад**: `echo 34359738368 > /sys/module/zfs/parameters/zfs_arc_max` (обмеження до 32 ГБ).
- **Вплив**: Обмеження `zfs_arc_max` необхідно встановлювати на серверах з віртуалізацією KVM або контейнерами, де Linux-процеси потребують гарантованого обсягу неподіленої оперативної пам'яті.

```
zfs_arc_min (uint64)
```
- **Опис**: Мінімальний розмір ARC у байтах, нижче якого ядро Linux Shrinker не може стиснути ARC під тиском пам'яті.
- **Значення за замовчуванням**: `0` (автоматично 1/32 від фізичної RAM або 64 МБ).
- **Приклад використання**: Встановлення високого значення `zfs_arc_min` на виділених файлових серверах запобігає надмірному витісненню кешу під час короткочасних сплесків виділення пам'яті утилітами користувача.

```
zfs_arc_sys_free (uint64)
```
- **Опис**: Запас вільної оперативної пам'яті у системі (у байтах), який ZFS зобов'язана залишати для потреб ядра Linux та процесів користувача перед тим, як стискати ARC.
- **Значення за замовчуванням**: `0` (автоматично `allmem / 64`).

```
zfs_arc_meta_limit_percent (uint)
```
- **Опис**: Максимальний відсоток від `zfs_arc_max`, який дозволено займати метаданим (dnodes, dentries). Параметр чинний до OpenZFS 2.2; від 2.2 його прибрано разом з рештою метаданих-важелів, а замість нього діє `zfs_arc_meta_balance` (за замовчуванням `500`) — що більше значення, то охочіше ARC тримає метадані.
- **Значення за замовчуванням**: `75` (до 75% ARC може займатися метаданими).

```
zfs_compressed_arc_enabled (int)
```
- **Опис**: Прапорець активації збереження блоків у стиснутому стані всередині ARC.
- **Значення за замовчуванням**: `1` (включено). `0` — вимикає compressed ARC (блок розпаковується при вході у кеш).

### Параметри підсистеми ZIL та SLOG

Налаштування журналювання впливають на затримку синхронних операцій та ресурсомісткість накопичувачів:

```
zfs_immediate_write_sz (long)
```
- **Опис**: Пороговий розмір блоку (у байтах), до якого синхронні записи вивантажуються безпосередньо в ZIL (SLOG). Якщо розмір запису перевищує цей поріг, ZIL записує лише покажчик на блок, а самі дані залишаються в ARC до скидання TXG.
- **Значення за замовчуванням**: `32768` (32 КБ).

```
zil_slog_bulk (ulong)
```
- **Опис**: Поріг у байтах на один commit журналу: доки записи в SLOG менші за нього, вони йдуть із синхронним пріоритетом (мінімальна затримка); більші — з асинхронним, щоб один активний писар не забив пристрій.
- **Значення за замовчуванням**: залежить від версії OpenZFS — `786432` (768 КБ) у ранніх, `67108864` (64 МБ) у сучасних. Старіша назва цього важеля — `zil_slog_limit`.

```
zfs_nocacheflush (int)
```
- **Опис**: Прапорець ігнорування команд витирання кешу диска (Cache Flush / CACHE_FLUSH / FUA) при скиданні ZIL.
- **Значення за замовчуванням**: `0` (безпечний режим, Cache Flush виконується). `1` — ризикований режим (прискорює записи, але загрожує втратою даних при вимкненні живлення без джерела безперебійного живлення).

## 3. Властивості датасетів ZFS (Dataset Properties)

Налаштування ZIL та ARC можна конфігурувати індивідуально для кожного датасету або ZVOL за допомогою команди `zfs set`. Це дозволяє гнучко розділяти ресурси між високопродуктивними базами даних та статичними архівами.

### Властивість `sync`
Визначає семантику обробки синхронних записів додатка (`fsync`, `O_SYNC`):

- `sync=standard` (за замовчуванням): Синхронні записи прямують через ZIL/SLOG, асинхронні буферизуються в TXG.
- `sync=always`: Усі записи (включно зі звичайним `write()`) примусово обробляються як синхронні через ZIL. Забезпечує максимальний рівень захисту, але знижує швидкість.
- `sync=disabled`: ZIL повністю ігнорується. Синхронні виклики `fsync()` повертають успіх негайно, а дані чекають на скидання TXG у RAM. **Максимальна швидкість, але ризик втрати останніх 5 секунд даних при збої живлення.**

### Властивість `logbias`
Визначає оптимізаційну стратегію ZIL під тип накопичувача:

- `logbias=latency` (за замовчуванням): Оптимізація під найменшу затримку. Малі та середні записи копіюються в ZIL/SLOG на окремому швидкому NVMe-диску.
- `logbias=throughput`: Оптимізація під пропускну здатність. ZIL відмовляється від виділення окремих блоків у SLOG для великих записів і виділяє блоки безпосередньо в основному пулі, зменшуючи подвійний запис.

### Властивість `primarycache` та `secondarycache`
Контролюють рівні кешування для об'єкта:

- `primarycache=all|metadata|none`: Що кешувати в ARC в RAM (усе, лише метадані, або нічого).
- `secondarycache=all|metadata|none`: Що відправляти у SSD-кеш L2ARC при витісненні з ARC.

Наприклад, для датасету з тимчасовими файлами або збірковими артефактами доцільно встановити `zfs set sync=disabled pool/scratch` та `zfs set primarycache=metadata pool/scratch`, що суттєво зекономить ресурс кешу RAM для основної СУБД.
