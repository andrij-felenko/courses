# 📋 Інтерфейс бібліотеки GNU Readline та конфігурація inputrc

Бібліотека GNU Readline надає два взаємопов'язані інтерфейси: програмний C-інтерфейс (API) для вбудовування інтерактивного редактора в прикладні процеси та декларативну мову конфігурації `~/.inputrc` для налаштування поведінки клавіш і змінних кінцевим користувачем.

Заголовні файли бібліотеки розташовані в каталозі `readline/`:

```c
#include <readline/readline.h>
#include <readline/history.h>
```

Для лінкування використовують прапорець `-lreadline` (і за потреби `-lhistory` та `-lncurses` або `-ltinfo` для низькорівневих термінальних можливостей terminfo).

## 1. Синхронний інтерфейс зчитування

Базовий режим роботи призначений для лінійних консольних утиліт, де головний потік виконання блокується доти, доки користувач не натисне клавішу Enter або не завершить введення комбінацією `Ctrl+D` на порожньому рядку.

```c
char *readline(const char *prompt);
```

Функція `readline` виконує чітку послідовність низькорівневих операцій:
1. Зберігає поточні налаштування структури `termios` дескриптора стандартного введення `stdin` (дескриптор `0`) через системний виклик `tcgetattr()`.
2. Перемикає термінал у неблокуючий сирий режим (англ. *raw mode*): скидає біти канонічної обробки (`ICANON`), локального відлуння символів (`ECHO`), розширеної обробки (`IEXTEN`) і налаштовує параметри `c_cc[VMIN] = 1, c_cc[VTIME] = 0`. Сигнали генерування переривань (`ISIG`) залишаються активними або обробляються бібліотекою.
3. Виводить рядок запрошення `prompt` на термінал через системний виклик `write(1, ...)`.
4. Входить у внутрішній цикл зчитування байтів через `read(0, ...)`, посимвольної диспетчеризації послідовностей клавіш та екранного перемальовування.
5. При отриманні символу нового рядка (`\n` або `\r`) викликає `tcsetattr()`, відновлюючи початковий збережений стан `termios`, переводить курсор на новий рядок і повертає покажчик на динамічно виділений через `malloc()` C-рядок без кінцевого символу переведення рядка.
6. При отриманні кінця файлу (`EOF` / `Ctrl+D`) на порожньому рядку відновлює термінал і повертає `NULL`.

Пам'ять, виділену під повернутий рядок, викликач зобов'язаний самостійно звільнити системним викликом `free()`.

```c
void add_history(const char *string);
```

Додає переданий рядок у кінець внутрішнього списку історії команд процесу. Якщо рядок порожній або дублює попередній, додавати його зазвичай не рекомендується, щоб не засмічувати навігацію історією.

### Керування персистентною історією

```c
int read_history(const char *filename);
int write_history(const char *filename);
int append_history(int nelements, const char *filename);
int history_truncate_file(const char *filename, int nlines);
```

Функції взаємодії з диском повертають `0` у разі успіху або код системної помилки `errno`. Якщо параметр `filename` дорівнює `NULL`, бібліотека намагається прочитати значення змінної середовища `HISTFILE` або використовує стандартний файл `~/.history`. Функція `append_history` записує лише останні `nelements` записів, що мінімізує операції введення-виведення при частих збереженнях сеансу.

## 2. Стан редактора рядка (внутрішні змінні)

Під час виконання операцій редагування та всередині користувацьких функцій зворотного виклику повний стан поточного рядка доступний через глобальні змінні бібліотеки:

| Змінна | Тип | Призначення |
|---|---|---|
| `rl_line_buffer` | `char *` | Текстовий буфер поточного рядка. Завжди завершується нульовим байтом `\0`. |
| `rl_point` | `int` | Поточна позиція курсора в буфері `rl_line_buffer` (байтовий індекс від `0` до `rl_end`). |
| `rl_end` | `int` | Загальна кількість байтів у поточному буфері `rl_line_buffer`. |
| `rl_mark` | `int` | Позиція мітки виділення тексту для операцій копіювання та вирізання регіонів (між `rl_mark` і `rl_point`). |
| `rl_prompt` | `char *` | Поточний рядок запрошення, переданий у `readline()`. |
| `rl_readline_name` | `const char *` | Рядкове ім'я поточної програми (наприклад, `"bash"`, `"gdb"`, `"python"`), що використовується в умовних блоках `$if` у файлі `.inputrc`. |
| `rl_editing_mode` | `int` | Поточний активний режим редагування: `1` для Emacs (`EMACS_EDITING_MODE`), `0` для Vi (`VI_EDITING_MODE`). |
| `rl_erase_empty_line` | `int` | Якщо встановлено в `1`, порожній рядок запрошення повністю стирається з екрана при отриманні сигналу `EOF`. |

## 3. Точки перехоплення та хуки (Hook Functions)

Readline містить набір вказівників на функції, за допомогою яких прикладний застосунок може вбудовувати власну логіку на різних етапах життєвого циклу рядка:

```c
typedef int rl_hook_func_t(void);

rl_hook_func_t *rl_startup_hook;
rl_hook_func_t *rl_pre_input_hook;
rl_hook_func_t *rl_event_hook;
rl_hook_func_t *rl_signal_event_hook;
rl_hook_func_t *rl_input_available_hook;
rl_cpvfunc_t  *rl_prep_term_function;
rl_vintfunc_t *rl_deprep_term_function;
```

- `rl_startup_hook`: викликається безпосередньо перед виведенням промпта, але після ініціалізації термінала. Дозволяє змінити початковий стан або прив'язки клавіш для поточного виклику.
- `rl_pre_input_hook`: викликається після друку промпта, але до зчитування першого символу від користувача.
- `rl_event_hook`: періодично викликається під час очікування введення від користувача, коли у дескрипторі `0` немає готових даних. Дозволяє фоновим потокам або графічним інтерфейсам оновлювати стан без блокування.
- `rl_signal_event_hook`: викликається під час отримання сигналів (`SIGINT`, `SIGWINCH`), надаючи можливість виконати безпечну очистку ресурсів.

## 4. Асинхронний інтерфейс зворотних викликів (Callback API)

Для програм із власним циклом подій (англ. *event loop* на основі системних викликів `poll()`, `epoll()`, `select()` або бібліотеки `libuv`), де блокування потоку на синхронному виклику `readline()` неприпустиме, бібліотека надає неблокуючий інтерфейс.

```c
typedef void rl_vcpfunc_t(char *line);

void rl_callback_handler_install(const char *prompt, rl_vcpfunc_t *lhandler);
void rl_callback_read_char(void);
void rl_callback_handler_remove(void);
```

Механізм роботи колбек-інтерфейсу складається з трьох частин:
- `rl_callback_handler_install`: ініціалізує структури Readline, перемикає `termios` у сирий режим, друкує запрошення `prompt` і реєструє функцію зворотного виклику `lhandler`. Ця функція буде викликана рівно один раз, коли користувач завершить редагування рядка натисканням Enter.
- `rl_callback_read_char`: зчитує доступні байти з дескриптора `stdin`, оновлює внутрішній стан буфера `rl_line_buffer` та викликає перемальовування. Цю функцію викликають щоразу, коли мультиплексор введення-виведення (`poll()`) повідомляє про подію готовності читання (`POLLIN`) на дескрипторі `0`.
- `rl_callback_handler_remove`: відновлює термінал у початковий канонічний режим, стирає незавершений рядок з екрана та звільняє зареєстрований обробник. Викликається перед завершенням програми або перед тимчасовою передачею термінала іншій утиліті.

## 5. Керування дисплеєм та перемальовуванням

Дисплейний рушій Readline мінімізує кількість байтів, що надсилаються терміналу під час редагування:

```c
void rl_redisplay(void);
void rl_forced_update_display(void);
void rl_reset_line_state(void);
void rl_cleanup_after_signal(void);
void rl_free_line_state(void);
void rl_resize_terminal(void);
```

Внутрішня робота `rl_redisplay()` базується на збереженні двох структур: попереднього видимого стану рядка на екрані та нового стану буфера. Рушій обчислює найдовший спільний префікс і суфікс, визначає точні координати курсора на сітці термінала через функцію `wcwidth()` для кожного символу UTF-8, і генерує лише необхідні керівні послідовності переміщення курсора (`\e[C`, `\e[D`), видалення символів (`\e[K`) або додавання нових знаків.

Функція `rl_resize_terminal` запитує нові геометричні параметри вікна термінала (кількість рядків і стовпчиків) через виклик `ioctl(0, TIOCGWINSZ, &ws)` і перераховує точки перенесення довгих рядків. Її необхідно викликати під час отримання сигналу зміни розміру вікна `SIGWINCH`.

## 6. Таблиці прив'язок клавіш (Keymaps) та вбудовані функції

Кожне натискання клавіші транслюється через активну таблицю прив'язок. Тип `Keymap` являє собою масив із 256 елементів типу `KEYMAP_ENTRY`. Кожен елемент може містити або прямий покажчик на функцію обробки команди `rl_command_func_t`, або посилання на дочірню таблицю (підмапу) для багатобайтних префіксних послідовностей (після `ESC`, `Ctrl+X` тощо).

```c
typedef int rl_command_func_t(int count, int key);

int rl_bind_key(int key, rl_command_func_t *function);
int rl_bind_keyseq(const char *seq, rl_command_func_t *function);
int rl_generic_bind(int type, const char *seq, char *data, Keymap map);
int rl_parse_and_bind(char *line);
int rl_read_init_file(const char *filename);
Keymap rl_get_keymap(void);
void rl_set_keymap(Keymap map);
Keymap rl_get_keymap_by_name(const char *name);
```

Стандартні іменовані таблиці прив'язок:
- `emacs` (або `emacs-standard`) — основна таблиця безмодального режиму Emacs;
- `emacs-meta` — таблиця для послідовностей, що починаються з префікса `ESC` або клавіші `Alt`;
- `emacs-ctlx` — таблиця для послідовностей після префікса `Ctrl+X`;
- `vi` (або `vi-insert`) — режим вставки тексту у стилі Vi;
- `vi-command` (або `vi-movement`) — командний нормальний режим навігації та операторів у стилі Vi.

## 7. Інтерфейс автодоповнення слів (Completion API)

Для реалізації контекстного доповнення команд, параметрів чи шляхів Readline надає гнучку систему диспетчеризації:

```c
typedef char *rl_compentry_func_t(const char *text, int state);
typedef char **rl_completion_func_t(const char *text, int start, int end);

rl_completion_func_t *rl_attempted_completion_function;
char **rl_completion_matches(const char *text, rl_compentry_func_t *entry_func);
char *rl_filename_completion_function(const char *text, int state);
```

Коли користувач натискає клавішу Tab, Readline викликає функцію, зареєстровану в `rl_attempted_completion_function`. Вона отримує префікс слова `text`, а також позиції початку й кінця цього слова в загальному буфері `[start, end]`. Це дозволяє перевірити, чи є слово першим у рядку (команда), чи стоїть після певного прапорця (аргумент).

Якщо користувацький диспетчер повертає `NULL`, Readline застосовує стандартне файлове автодоповнення `rl_filename_completion_function`.

Генератор `entry_func` викликається ітеративно для одного й того самого пошуку:
- При першому виклику передається `state == 0`: генератор ініціалізує внутрішні структури чи курсори пошуку та повертає перший знайдений результат у вигляді динамічного рядка `char*`, виділеного через `malloc()`.
- При наступних викликах передається `state != 0`: генератор повертає наступний знайдений збіг.
- Коли всі варіанти вичерпано, генератор повертає `NULL`.

Функція-обгортка `rl_completion_matches` агрегує всі виклики генератора у фінальний динамічний масив `char**`, де нульовий елемент містить найдовший спільний префікс усіх знайдених збігів, подальші елементи — повні варіанти слів, а список завершується покажчиком `NULL`.

## 8. Конфігураційний файл inputrc

При запуску будь-яка програма, що використовує GNU Readline, шукає конфігураційний файл у такій пріоритетній послідовності:
1. Шлях, явно вказаний у змінній середовища `INPUTRC`.
2. Файл `~/.inputrc` у домашньому каталозі поточного користувача.
3. Загальносистемний файл конфігурації `/etc/inputrc`.

### Синтаксичні правила файлу

1. **Коментарі:** порожні рядки або рядки, першим непробільним символом яких є `#`.
2. **Встановлення внутрішніх змінних:** `set <ім'я-змінної> <значення>`.
3. **Прив'язка послідовності до функції:** `"<послідовність>": <ім'я-функції>`.
4. **Клавіатурні макроси:** `"<послідовність>": "<рядок-підстановки>"`.
5. **Умовні директиви та включення:** `$if ...`, `$else`, `$endif`, `$include <шлях>`.

### Спеціальні позначення керівних клавіш

| Позначення | Значення | Приклад запису |
|---|---|---|
| `\C-` або `\C-x` | Утримування клавіші Control | `\C-a` (Ctrl+A), `\C-r` (Ctrl+R) |
| `\M-` або `\M-x` | Утримування клавіші Meta / Alt | `\M-f` (Alt+F), `\M-b` (Alt+B) |
| `\e` | Керівний символ Escape (`0x1B`) | `\e[A` (Стрілка вгору), `\e[3~` (Delete) |
| `\\` | Зворотний слеш | `\\` |
| `\"` | Подвійні лапки всередині рядка | `\"` |
| `\'` | Одинарні лапки всередині рядка | `\'` |
| `\t` | Символ табуляції (`0x09`) | `\t` |

### Довідник змінних inputrc

| Змінна | Значення за замовчуванням | Допустимі значення | Опис поведінки |
|---|---|---|---|
| `bell-style` | `audible` | `none`, `visible`, `audible` | Спосіб сповіщення про помилку або межу буфера: вимкнено, візуальне миготіння екрана або звуковий сигнал термінала. |
| `colored-stats` | `off` | `on`, `off` | Підсвічування кольором типів файлів у списку варіантів доповнення за правилами змінної `LS_COLORS`. |

### Умовні блоки та директиви

Readline дозволяє застосовувати налаштування вибірково за допомогою директиви `$if`:

```ini
# 1. Фільтрація за іменем програми
$if Bash
    # Налаштування, специфічні лише для оболонки Bash
    set show-all-if-ambiguous on
    set colored-stats on
$endif

$if Python
    # Налаштування для інтерактивного REPL Python
    set editing-mode emacs
$endif

# 2. Фільтрація за активним режимом редагування
$if mode=vi
    set show-mode-in-prompt on
    set vi-ins-mode-string \1\e[6 q\2
    set vi-cmd-mode-string \1\e[2 q\2
    
    # Прив'язки для нормального режиму Vi
    set keymap vi-command
    "ciw": "diwbbla"
$endif

# 3. Фільтрація за типом термінала
$if term=xterm-256color
    "\e[1;5C": forward-word
    "\e[1;5D": backward-word
$endif

# 4. Підключення зовнішнього файлу
$include /etc/inputrc
```

Спеціальні маркери `\1` та `\2` у рядках `vi-ins-mode-string` та `vi-cmd-mode-string` еквівалентні константам `RL_PROMPT_START_IGNORE` (`\001`) та `RL_PROMPT_END_IGNORE` (`\002`): вони сигналізують дисплейному рушію Readline, що вкладена керівна послідовність зміни форми курсора не займає фізичного місця на екрані й не повинна впливати на розрахунок позиції курсора.
