# 📋 Релокації та внутрішні структури PLT і GOT

Цей довідник містить повний перелік низькорівневих структур даних стандарту System V ELF, типізованих релокацій ABI, тегів секції `.dynamic` та байти-опкоди процедурних трамплінів PLT для архітектур x86-64 та ARM64 (AArch64). Довідник призначений для розробників системного програмного забезпечення, бінарних аналізаторів, компіляторів та інструментів зворотного інжинірингу.

---

## 1. Концепція та внутрішня розмітка секцій GOT у пам'яті

Глобальна таблиця зміщень (*Global Offset Table — GOT*) є центральним інструментом забезпечення позиційно-незалежного коду (PIC/PIE). У будь-якому бінарному виконуваному файлі або динамічній бібліотеці формату ELF таблица GOT розділена на дві суміжні секції у завантажуваних сегментах пам'яті:

1. **Секція `.got`:** Призначена для збереження віртуальних адрес глобальних та статичних змінних, які імпортуються з інших об'єктних файлів або завантажених динамічних бібліотек. Комірки у цій секції обчислюються й заповнюються динамічним завантажувачем негайно під час запуску програми в рамках первинної обробки релокацій (load-time relocations).
2. **Секція `.got.plt`:** Призначена виключно для обслуговування викликів функцій через процедурні трампліни PLT. Вона підтримує механізм відкладеного зв'язування (*lazy binding*), тобто комірки заповнюються адресами функцій у момент їх першого фактичного виконання. У разі збірки бінарного файла із прапорцями Full RELRO секція `.got.plt` заповнюється на старті й переводиться в режим *Read-Only*.

### Таблиця зарезервованих елементів `.got.plt` (System V AMD64 ABI)

Згідно зі специфікацією System V AMD64 ABI, перші три 64-бітні комірки секції `.got.plt` (розміром по 8 байтів кожна) мають фіксоване службове призначення й зарезервовані для внутрішніх потреб динамічного завантажувача `ld-linux.so`:

| Зсув у `.got.plt` | Поле / Константа | Опис вмісту та призначення | Доступний режим |
| :--- | :--- | :--- | :--- |
| `0x00` (`GOT[0]`) | `_DYNAMIC` | Віртуальна адреса початку секції `.dynamic` даного об'єкта | Read-Only після завантаження |
| `0x08` (`GOT[1]`) | `link_map` | Вказівник на внутрішню структуру `struct link_map` завантажувача (`ld-linux.so`) | Заповнюється `ld-linux.so` при збіранні |
| `0x10` (`GOT[2]`) | `resolver` | Віртуальна адреса функції-резолвера `_dl_runtime_resolve` | Заповнюється `ld-linux.so` при збіранні |
| `0x18` (`GOT[3]`) | `GOT[foo]` | Адреса першого імпортованого символу (на старті вказує на `foo@plt + 6`) | Перезаписується під час резолвінгу |
| `0x20` (`GOT[4]`) | `GOT[bar]` | Адреса другого імпортованого символу | Перезаписується під час резолвінгу |

Кожна наступна комірка, починаючи з `GOT[3]`, відповідає одній зовнішній функції, яка викликається програмою через трамплін у секції `.plt`.

## 2. Структури даних релокацій ELF (`Elf64_Rela`, `Elf64_Rel` та `Elf64_Sym`)

Усі імпортовані та експортовані символи описуються у бінарному файлі спеціальними таблицями ELF. Для опису дій, які завантажувач повинен виконати з комірками GOT, використовуються структури релокацій `Elf64_Rela` (для архітектур із явним доданком, таких як x86-64 та ARM64) або `Elf64_Rel` (для архітектур без явного доданка).

Імена символів, їхні типи та віртуальні адреси зберігаються у таблиці динамічних символів `.dynsym` у вигляді масиву структур `Elf64_Sym`.

:::tabs

@tab C
```c
#include <stdint.h>

// 64-бітна структура релокації з доданком (Rela)
typedef struct {
    uint64_t r_offset; // Віртуальна адреса (або зсув у GOT), куди записується результат
    uint64_t r_info;   // Індекс символу у .dynsym (верхні 32 біти) + тип релокації (нижні 32 біти)
    int64_t  r_addend; // Фіксований доданок (addend), що додається до обчисленого значення
} Elf64_Rela;

// 64-бітна структура релокації без доданка (Rel)
typedef struct {
    uint64_t r_offset; // Віртуальна адреса запису у GOT
    uint64_t r_info;   // Індекс символу та тип релокації
} Elf64_Rel;

// 64-бітний запис символу у таблиці .dynsym
typedef struct {
    uint32_t st_name;  // Зсув у таблиці рядків .dynstr до імені символу
    uint8_t  st_info;  // Тип символу (STT_FUNC, STT_OBJECT) та зв'язування (STB_GLOBAL)
    uint8_t  st_other; // Видимість символу (STV_DEFAULT, STV_HIDDEN)
    uint16_t st_shndx; // Індекс секції, де визначено символ (SHN_UNDEF для імпортованих)
    uint64_t st_value; // Віртуальна адреса символу або 0
    uint64_t st_size;  // Розмір об'єкта в байтах
} Elf64_Sym;
```

@tab C++
```cpp
#include <cstdint>

// 64-бітна структура релокації з доданком (Rela)
struct Elf64_Rela {
    std::uint64_t r_offset; // Віртуальна адреса (або зсув у GOT), куди записується результат
    std::uint64_t r_info;   // Індекс символу у .dynsym (верхні 32 біти) + тип релокації (нижні 32 біти)
    std::int64_t  r_addend; // Фіксований доданок (addend), що додається до обчисленого значення
};

// 64-бітна структура релокації без доданка (Rel)
struct Elf64_Rel {
    std::uint64_t r_offset; // Віртуальна адреса запису у GOT
    std::uint64_t r_info;   // Індекс символу та тип релокації
};

// 64-бітний запис символу у таблиці .dynsym
struct Elf64_Sym {
    std::uint32_t st_name;  // Зсув у таблиці рядків .dynstr до імені символу
    std::uint8_t  st_info;  // Тип символу (STT_FUNC, STT_OBJECT) та зв'язування (STB_GLOBAL)
    std::uint8_t  st_other; // Видимість символу (STV_DEFAULT, STV_HIDDEN)
    std::uint16_t st_shndx; // Індекс секції, де визначено символ (SHN_UNDEF для імпортованих)
    std::uint64_t st_value; // Віртуальна адреса символу або 0
    std::uint64_t st_size;  // Розмір об'єкта в байтах
};
```

### Пояснення полів релокаційних структур

Поле `r_offset` відіграє вирішальну роль під час динамічного зв'язування. У виконуваних файлах та спільних бібліотеках це поле містить віртуальну адресу комірки пам'яті (у секції `.got` або `.got.plt`), куди динамічний завантажувач повинен записати обчислену віртуальну адресу символу. У переміщуваних об'єктних файлах (`.o`) це значення показує зсув відносно початку відповідної секції.

Поле `r_info` об'єднує два логічних атрибути ради економії обсягу пам'яті у таблицях ELF. Верхні 32 біти містять 0-базовий індекс символу у таблиці `.dynsym`. За цим індексом завантажувач знаходить структуру `Elf64_Sym`, витягує зсув `st_name` і знаходить у таблиці рядків `.dynstr` текстове ім'я символу (наприклад, `"printf"` чи `"malloc"`). Нижні 32 біти поля `r_info` містять числовий код типу релокації (наприклад, `R_X86_64_JUMP_SLOT` або `R_X86_64_GLOB_DAT`), який вказує завантажувачу математичну формулу для обчислення фінальної адреси.

Поле `r_addend` містить значення фіксованого доданка, яке додається до віртуальної адреси символу під час обчислення остаточного результату. Для більшості процедурних релокацій функцій у PLT значення доданка дорівнює `0`.

### Макроси маніпуляції полем `r_info`

Для розпакування та пакування полів `r_info` специфікація System V ELF надає стандартні макроси та помічники.

:::tabs

@tab C
```c
#include <stdint.h>

// Отримання індексу символу з поля r_info
#define ELF64_R_SYM(i)    ((uint32_t)((i) >> 32))

// Отримання типу релокації з поля r_info
#define ELF64_R_TYPE(i)   ((uint32_t)((i) & 0xffffffffL))

// Утворення значення r_info з індексу символу s та типу t
#define ELF64_R_INFO(s,t) ((((uint64_t)(s)) << 32) + ((uint32_t)(t)))
```

@tab C++
```cpp
#include <cstdint>

// Ідіоматичні inline-функції C++ для маніпуляцій r_info
constexpr std::uint32_t get_elf64_r_sym(std::uint64_t info) noexcept {
    return static_cast<std::uint32_t>(info >> 32);
}

constexpr std::uint32_t get_elf64_r_type(std::uint64_t info) noexcept {
    return static_cast<std::uint32_t>(info & 0xffffffffL);
}

constexpr std::uint64_t make_elf64_r_info(std::uint32_t sym, std::uint32_t type) noexcept {
    return (static_cast<std::uint64_t>(sym) << 32) + type;
}
```

## 3. Таблиця кодів релокацій ABI (x86-64 та ARM64)

Під час резолвів символів динамічний завантажувач аналізує код релокації й застосовує відповідну математичну формулу обчислення адреси.

У таблицях нижче використовуються стандартні специфіковані позначення System V ABI:
- **`S`**: Віртуальна адреса символу після виконання пошуку в завантажених об'єктах `.so`.
- **`A`**: Значення доданка `r_addend` із запису релокації `Elf64_Rela`.
- **`P`**: Віртуальна адреса самого запису релокації (`r_offset`).
- **`B`**: Базова адреса завантаження позиційно-незалежного об'єкта в пам'ять (Base load address).
- **`GOT`**: Віртуальна адреса початку глобальної таблиці зміщень `.got`.

### Коди релокацій для архітектури x86-64 (AMD64 System V ABI)

| Назва релокації | Код (HEX / DEC) | Формула обчислення | Опис та цільове застосування |
| :--- | :--- | :--- | :--- |
| `R_X86_64_NONE` | `0x00` (`0`) | *Немає* | Ігнорується завантажувачем (заглушка) |
| `R_X86_64_64` | `0x01` (`1`) | `S + A` | Пряма 64-бітна абсолютна адреса у секції даних |
| `R_X86_64_PC32` | `0x02` (`2`) | `S + A - P` | 32-бітна відносна адресація відносно `%rip` |
| `R_X86_64_GOT32` | `0x03` (`3`) | `G + A` | 32-бітна адреса запису у GOT відносно початку GOT |
| `R_X86_64_PLT32` | `0x04` (`4`) | `L + A - P` | 32-бітний відносний перехід на трамплін PLT (`L`) |
| `R_X86_64_GLOB_DAT`| `0x06` (`6`) | `S` | Заповнення `.got` адресою глобальної змінної |
| `R_X86_64_JUMP_SLOT`| `0x07` (`7`) | `S` | Заповнення `.got.plt` адресою процедурного виклику |
| `R_X86_64_RELATIVE`| `0x08` (`8`) | `B + A` | Релокація зсуву бази для PIE-файлів у `.got` / `.data` |
| `R_X86_64_GOTPCREL`| `0x09` (`9`) | `GOT + S + A - P` | `%rip`-відносне звернення до комірки GOT |
| `R_X86_64_DTPMOD64`| `0x10` (`16`) | `Module ID` | Ідентифікатор модуля для Thread-Local Storage (TLS) |
| `R_X86_64_DTPOFF64`| `0x11` (`17`) | `TLS Offset` | Зсув змінної у блоці пам'яті TLS модуля |
| `R_X86_64_TPOFF64` | `0x12` (`18`) | `Static TLS` | Зсув у статичному блоці пам'яті потоку |
| `R_X86_64_IRELATIVE`|`0x25` (`37`) | `indirect(B+A)`| Динамічний виклик GNU Indirect Function (IFUNC) |

### Детальний аналіз спеціальних типів релокацій x86-64

1. **`R_X86_64_JUMP_SLOT`:** Основний тип релокацій для PLT. Компонувальник створює такий запис у секції `.rela.plt` для кожного виклику зовнішньої функції. Динамічний завантажувач використовує цей запис під час Lazy Binding або Full RELRO для перезапису відповідної комірки `.got.plt` адресою `S`.
2. **`R_X86_64_GLOB_DAT`:** Використовується для зв'язування глобальних змінних у секції `.got`. Завантажувач обчислює адресу змінної та записує її в GOT під час завантаження програми.
3. **`R_X86_64_RELATIVE`:** Критично важлива релокація для позиційно-незалежних виконуваних файлів (PIE). Оскільки програма завантажується за випадковою базовою адресою `B` через ASLR, завантажувач додає базову адресу до зсуву `A` і записує результат у пам'яті.
4. **`R_X86_64_IRELATIVE`:** Використовується для механізму **GNU Indirect Functions (IFUNC)**. IFUNC дозволяє бібліотекам (наприклад, `glibc`) вибирати оптимізовану реалізацію функції (AVX2, AVX-512, SSE4.2) під час запуску програми залежно від можливостей поточного процесора. Для релокацій `IRELATIVE` адреса у GOT обчислюється шляхом виконання функції-селектора, адреса якої записана у початковому бінарному файлі.

### Коди релокацій для архітектури ARM64 (AArch64 ELF ABI)

| Назва релокації | Код (HEX / DEC) | Формула обчислення | Опис та цільове застосування |
| :--- | :--- | :--- | :--- |
| `R_AARCH64_NONE` | `0x000` (`0`) | *Немає* | Порожня релокація |
| `R_AARCH64_ABS64` | `0x101` (`257`) | `S + A` | Пряма 64-бітна адреса ARM64 |
| `R_AARCH64_PREL32` | `0x105` (`261`) | `S + A - P` | 32-бітна відносна адреса відносно PC ARM64 |
| `R_AARCH64_GLOB_DAT`| `0x401` (`1025`)| `S` | Заповнення GOT адресою глобальної змінної ARM64 |
| `R_AARCH64_JUMP_SLOT`|`0x402` (`1026`)| `S` | Заповнення `.got.plt` адресою функції ARM64 |
| `R_AARCH64_RELATIVE`| `0x403` (`1027`)| `B + A` | Динамічне коригування базової адреси ARM64 |
| `R_AARCH64_IRELATIVE`|`0x404` (`1028`)| `indirect(B+A)`| Оптимізований виклик IFUNC на архітектурі ARM64 |

## 4. Специфікація динамічних тегів секції `.dynamic`

Секція `.dynamic` є головним орієнтиром для динамічного завантажувача. Вона завантажується в пам'ять як частина сегмента `PT_DYNAMIC` і описується масивом структур `Elf64_Dyn`:

:::tabs

@tab C
```c
#include <stdint.h>

typedef struct {
    int64_t d_tag; // Тег елемента динамічної секції (константа DT_)
    union {
        uint64_t d_val; // Числове значення або розмір
        uint64_t d_ptr; // Віртуальна адреса в пам'яті
    } d_un;
} Elf64_Dyn;
```

@tab C++
```cpp
#include <cstdint>

struct Elf64_Dyn {
    std::int64_t d_tag; // Тег елемента динамічної секції (константа DT_)
    union {
        std::uint64_t d_val; // Числове значення або розмір
        std::uint64_t d_ptr; // Віртуальна адреса в пам'яті
    } d_un;
};
```

:::

### Повний довідник ключових тегів динамічної секції

| Назва тегу | Числовий код | Значення `d_un` | Призначення для завантажувача |
| :--- | :--- | :--- | :--- |
| `DT_NULL` | `0` | `0` | Маркер завершення масиву елементів `.dynamic` |
| `DT_NEEDED` | `1` | `d_val` (strtab offset)| Зсув імені необхідної спільній бібліотеки (наприклад, `libc.so.6`) |
| `DT_PLTRELSZ` | `2` | `d_val` (bytes) | Загальний розмір таблиці релокацій PLT (`.rela.plt`) у байтах |
| `DT_PLTGOT` | `3` | `d_ptr` (address)| Віртуальна адреса початку секції `.got.plt` (або `.got`) |
| `DT_HASH` | `4` | `d_ptr` (address)| Віртуальна адреса класичної хеш-таблиці System V |
| `DT_STRTAB` | `5` | `d_ptr` (address)| Віртуальна адреса таблиці рядків імпортів `.dynstr` |
| `DT_SYMTAB` | `6` | `d_ptr` (address)| Віртуальна адреса таблиці динамічних символів `.dynsym` |
| `DT_RELA` | `7` | `d_ptr` (address)| Віртуальна адреса головної таблиці релокацій `.rela.dyn` |
| `DT_RELASZ` | `8` | `d_val` (bytes) | Загальний розмір головної таблиці релокацій `.rela.dyn` |
| `DT_RELAENT` | `9` | `d_val` (bytes) | Розмір одного запису релокації (24 байти для `Elf64_Rela`) |
| `DT_STRSZ` | `10` | `d_val` (bytes) | Загальний розмір таблиці рядків `.dynstr` у байтах |
| `DT_SYMENT` | `11` | `d_val` (bytes) | Розмір одного запису символу (24 байти для `Elf64_Sym`) |
| `DT_INIT` | `12` | `d_ptr` (address)| Адреса функції ініціалізації модуля (`_init`) |

## 5. Байти-опкоди та машинні інструкції трамплінів PLT

Низькорівневе виконання викликів у PLT спирається на суворо регламентовані послідовності інструкцій процесора.

### 1. Архітектура x86-64: Стандартна PLT (без IBT)

Кожен запис у секції `.plt` вирівняний по межі 16 байтів.

```assembly
; Службовий нульовий трамплін PLT0 (розмір 16 байтів)
.plt:
  41000: ff 35 02 20 00 00    push   QWORD PTR [rip+0x2002] # GOT[1] (link_map)
  41006: ff 25 04 20 00 00    jmp    QWORD PTR [rip+0x2004] # GOT[2] (resolver)
  4100c: 0f 1f 40 00          nopl   0x0(%rax)              # Вирівнювання

; Персональний трамплін foo@plt (розмір 16 байтів)
foo@plt:
  41010: ff 25 02 20 00 00    jmp    QWORD PTR [rip+0x2002] # Перехід за GOT[foo]
  41016: 68 00 00 00 00       push   0x0                    # reloc_arg (індекс 0)
  4101b: e9 e0 ff ff ff       jmp    41000 <.plt>           # Перехід на PLT0
```

### 2. Архітектура x86-64: Захищена секція `.plt.sec` (Intel CET IBT)

З використанням прапорців Intel CET на початку кожного трампліну розміщується 4-байтова інструкція `endbr64` (`f3 0f 1e fa`):

```assembly
foo@plt.sec:
  42000: f3 0f 1e fa          endbr64                       # Інструкція підтвердження переходу
  42004: ff 25 fa 1f 00 00    jmp    QWORD PTR [rip+0x1ffa] # Прямий стрибок через GOT
  4200a: 66 0f 1f 44 00 00    nop    WORD PTR [rax+rax*1+0x0]
```

### 3. Архітектура ARM64 (AArch64): Стандартна PLT

На ARM64 кожен трамплін займає 16 або 32 байти та використовує регістри `x16` і `x17`:

```assembly
foo@plt:
  10040: 90000010     adrp   x16, 10000 <got_page>     ; Обчислення старшої сторінки GOT
  10044: f9400211     ldr    x17, [x16, #8]            ; Зчитування адреси з GOT[foo]
  10048: 91002210     add    x16, x16, #8              ; Обчислення адреси комірки GOT
  1004c: d61f0220     br     x17                       ; Стрибок за адресою у x17
```
