# 📋 Інтерфейси ZNS у ядрі Linux та налаштування f2fs

Цей довідник містить докладний опис системних інтерфейсів ядра Linux, утиліт командного рядка, параметрів кешування й sysfs, прапорців форматування `mkfs.f2fs` та викликів `ioctl`, необхідних для низькорівневого адміністрування та розробки програмного забезпечення під зоновані накопичувачі ZNS.

---

## 1. Параметри sysfs блочного шару ядра Linux

Підсистема блочних пристроїв ядра Linux експортує метрики та апаратні обмеження зонованого накопичувача через файлову систему `sysfs` за шляхом `/sys/block/<device>/queue/`. Ці параметри зчитуються ядром під час ініціалізації NVMe-драйвера із системних структур даних `NVMe Identify Controller` та `NVMe Identify Namespace`.

### Основні атрибути зонування
- `/sys/block/<device>/queue/zoned` (`string`):
  Визначає режим підтримки зонування блочним шаром.
  - `none`: звичайний пристрій із довільним доступом (Conventional Block Device).
  - `host-managed`: суворий зонований пристрій (NVMe ZNS або SAS ZBC). Перезапис на місці заборонений, запис дозволено лише в позицію покажчика запису (Write Pointer).
  - `host-aware`: застарілий режим для SMR-дисків, де послідовний запис є рекомендованим, але не суворо обов'язковим.

- `/sys/block/<device>/queue/chunk_sectors` (`integer`):
  Розмір однієї зони накопичувача, виражений у кількості 512-байтових секторів. Для апаратної зони розміром 256 МіБ значення в sysfs становить `524288` секторів (розмір у байтах: `524288 × 512 = 268435456`).

- `/sys/block/<device>/queue/zone_append_max_bytes` (`integer`):
  Граничний розмір одного запиту атомарного додавання `Zone Append` у байтах, який спроможна прийняти апаратура контролера. Зазвичай це значення становить від 64 КіБ (65536 байтів) до 512 КіБ (524288 байтів). Якщо програма або файлова система надсилає `bio` з командою `REQ_OP_ZONE_APPEND`, більший за цей ліміт, блочний шар ядра Linux розбиває запит на кілька окремих операцій.

- `/sys/block/<device>/queue/max_open_zones` (`integer`):
  Максимально дозволена кількість зон, які можуть одночасно перебувати в стані `Explicitly Open` або `Implicitly Open`. Число `0` означає відсутність апаратних обмежень. Якщо система перевищує цей ліміт, контролер повертає системну помилку `NVME_SC_ZONE_TOO_MANY_OPEN`.

- `/sys/block/<device>/queue/max_active_zones` (`integer`):
  Максимальна кількість активних зон (відкриті зони + закриті зони, покажчик запису яких є більшим за початок зони, `WP > Start LBA`). Апаратне обмеження зумовлене обсягом внутрішньої оперативної пам'яті SRAM/DRAM на контролері SSD, необхідної для відстеження покажчиків запису.

## 2. Утиліта blkzone: інспекція та керування зонами

Утиліта `blkzone` із пакета `util-linux` взаємодіє напряму з підсистемою ядра через виклики `ioctl` блочного пристрою. Вона дозволяє адмініструвати стан покажчиків запису без виклику вищих шарів файлової системи.

### Отримання звіту про зони (blkzone report)
Команда зчитує масив структур `struct blk_zone` із ядра й виводить поточний стан кожної зони:
```bash
blkzone report -o 0 -c 16 /dev/nvme0n1
```
- `-o, --offset`: початковий сектор LBA, з якого починати звіт.
- `-c, --count`: кількість зон для відображення у звіті.

Приклад виводу утиліти (поля скорочено — точний набір і формат залежать від версії `util-linux`):
```text
  start: 0x000000000, len: 0x080000, cap: 0x080000, wptr: 0x000000000, cond: 0x1, type: 0x2
  start: 0x00080000, len: 0x080000, cap: 0x080000, wptr: 0x00084000, cond: 0x2, type: 0x2
```
Де `cond: 0x1` відповідає стану `EMPTY`, а `cond: 0x2` — стану `IMPLICIT OPEN` із частково просунутим покажчиком `wptr` (`0x3` означав би `EXPLICIT OPEN`, тобто зону, відкриту явною командою хоста).

### Скидання покажчика запису (blkzone reset)
Примусово надсилає команду `REQ_OP_ZONE_RESET` на накопичувач, обнуляючи покажчик запису:
```bash
# Скидання конкретної зони за сектором початку
blkzone reset -o 524288 -l 524288 /dev/nvme0n1

# Скидання покажчиків запису для УСІХ зон накопичувача (повне очищення)
blkzone reset /dev/nvme0n1
```
- `-l, --length`: довжина ділянки в секторах. Повинна відповідати розміру однієї або кількох зон.

### Зміна стану зон (close та finish)
```bash
# Примусове закриття зони (перехід зі стану Open у Closed)
blkzone close -o 524288 -l 524288 /dev/nvme0n1

# Позначення зони як повністю заповненої (перехід у стан FULL, WP = End LBA)
blkzone finish -o 524288 -l 524288 /dev/nvme0n1
```
Операція `finish` примусово переводить частково заповнену зону в стан `FULL`, звільняючи апаратний ресурс відкритої зони. Решта ємності такої зони лишається невикористаною доти, доки зону не скинуть командою `Zone Reset`, — тому `finish` доречний тоді, коли зону вже не планують дописувати, а ліміт `max_open_zones` потрібен під інші потоки.

## 3. Прапорці форматування mkfs.f2fs для ZNS

Створення файлової системи f2fs на зонованому накопичувачі виконується спеціалізованою утилітою `mkfs.f2fs`. Під час форматування утиліта зчитує геометрію зонування через `ioctl(BLKGETZONESZ)` (розмір зони в секторах), `ioctl(BLKGETNRZONES)` (кількість зон) та `ioctl(BLKREPORTZONE)`, щоб вирівняти внутрішні секції f2fs по апаратних межах ZNS.

### Команди форматування
```bash
# Однодискове форматування зонованого накопичувача
mkfs.f2fs -m /dev/nvme0n1

# Багатодискове форматування: метадані на звичайному SSD (nvme0n1), дані на ZNS (nvme1n1)
mkfs.f2fs -m -c /dev/nvme1n1 /dev/nvme0n1
```

### Детальний опис прапорців mkfs.f2fs
Довгих (подвійний дефіс) форм у `mkfs.f2fs` немає — утиліта розбирає лише однолітерні прапорці.

- `-m`:
  **Обов'язковий прапорець для ZNS.** Вмикає ознаку зонованого блочного пристрою в суперблоці f2fs. Розмір апаратної зони має бути кратним розміру сегмента f2fs (2 МіБ), і секція вирівнюється по межі зони: для зони 256 МіБ утиліта робить секцію рівною 128 сегментам.
  Однодискова команда (перша з наведених вище) спрацює лише тоді, коли на початку пристрою є конвенційні (незоновані) зони під область метаданих — так буває на host-managed SMR-дисках і на емуляторі `null_blk`. Простір назв NVMe ZNS складається з самих послідовних зон, тому для нього потрібен другий, звичайний пристрій, поданий через `-c`.

- `-c <пристрій>`:
  Додає ще один блочний пристрій до тому («build f2fs with this device additionally»). Головним лишається пристрій, названий **останнім, позиційним** аргументом, — саме на ньому мають бути суперблок і метадані, тож на зонованій конфігурації позиційним іде звичайний SSD (`/dev/nvme0n1`), а через `-c` подається накопичувач ZNS (`/dev/nvme1n1`) під блоки даних користувачів.

- `-z <число>`:
  Кількість **секцій в одній зоні f2fs** (зона f2fs складається з секцій). За замовчуванням `1`. Парний до нього `-s` задає кількість сегментів у секції.

- `-q`:
  Режим без виводу службових повідомлень.

## 4. Опції монтування f2fs на ZNS

При монтуванні зонованого розділу ядро Linux перевіряє наявність прапорця зонованого режиму в суперблоці та вмикає специфічні механізми керування логом.

```bash
mount -t f2fs -o mode=lfs,discard,active_logs=6 /dev/nvme0n1 /mnt/zns
```

### Таблиця параметрів монтування f2fs
| Параметр | Значення для ZNS | Технічний механізм |
| :--- | :--- | :--- |
| `mode=lfs` | **Обов'язково** | Вимикає перезапис блоків на місці (In-Place Update). Усі нові дані та метадані записуються виключно послідовно в кінець відкритих зон. |
| `discard` | Рекомендовано | Дозволяє f2fs автоматично надсилати команду `REQ_OP_ZONE_RESET` контролеру ZNS у момент, коли під час збирання сміття (GC) із зони виселено останні дійсні блоки. |
| `active_logs=6` | За замовчуванням | Вказує f2fs підтримувати паралельно 6 відкритих зон для розподілу даних за ступенем гарячості (Hot/Warm/Cold Data та Hot/Warm/Cold Node). |
| `fsync_mode=posix` | За замовчуванням | Полегшений режим: `fsync()` синхронізує лише сам файл, як того мінімально вимагає POSIX. Строгу семантику (як в ext4, XFS, btrfs) вмикає `fsync_mode=strict`, а `nobarrier` додатково не надсилає команду скидання кешу для неатомарних файлів. |
| `alloc_mode=default` | За замовчуванням | Політика розподілу блоків. `default` — звичайний розподіл f2fs; `reuse` дозволяє повторно вживати застарілі блоки, що на зонованому пристрої суперечить послідовному запису. |

## 5. Системний ioctl інтерфейс ядра Linux (uapi/linux/blkzoned.h)

Для низькорівневого програмування системних утиліт, баз даних або файлових систем ядро Linux надає набір команд `ioctl`, визначених у заголовному файлі `<linux/blkzoned.h>`.

### Основні команди ioctl
```c
#include <sys/ioctl.h>
#include <linux/blkzoned.h>

// 1. Запит звіту про стан зон пристрою
// int ret = ioctl(fd, BLKREPORTZONE, struct blk_zone_report *rep);

// 2. Скидання покажчика запису для діапазону секторів (BLKRESETZONE)
// int ret = ioctl(fd, BLKRESETZONE, struct blk_zone_range *range);

// 3. Явне відкриття зон (BLKOPENZONE)
// int ret = ioctl(fd, BLKOPENZONE, struct blk_zone_range *range);

// 4. Явне закриття зон (BLKCLOSEZONE)
// int ret = ioctl(fd, BLKCLOSEZONE, struct blk_zone_range *range);

// 5. Завершення заповнення зон (BLKFINISHZONE)
// int ret = ioctl(fd, BLKFINISHZONE, struct blk_zone_range *range);
```

### Структури даних ядра Linux
Запит `BLKREPORTZONE` заповнює зарезервований буфер масивом структур `struct blk_zone`:

```c
struct blk_zone_report {
    __u64   sector;         // Початковий сектор для запиту звіту
    __u32   nr_zones;       // Вхід: розмір масиву; Вихід: повернута кількість зон
    __u32   flags;          // Додаткові прапорці запиту
    struct blk_zone zones[]; // Гнучкий масив структур опису зон
};

struct blk_zone {
    __u64   start;          // Початковий сектор зони в LBA
    __u64   len;            // Довжина зони у секторах (наприклад, 524288)
    __u64   wp;             // Поточна позиція покажчика запису (Write Pointer)
    __u8    type;           // Тип зони (BLK_ZONE_TYPE_SEQWRITE_REQ)
    __u8    cond;           // Стан зони (EMPTY, IMP_OPEN, EXP_OPEN, CLOSED, READONLY, FULL, OFFLINE)
    __u8    non_seq;        // Зона обслуговується ресурсом непослідовного запису
    __u8    reset;          // Контролер радить скинути цю зону
    __u8    resv[4];
    __u64   capacity;       // Корисна ємність зони в секторах (може бути меншою за len)
    __u8    reserved[24];   // Резерв під майбутні розширення стандарту
};

struct blk_zone_range {
    __u64   sector;         // Початковий сектор зони для керування
    __u64   nr_sectors;     // Кількість секторів (має бути кратною chunk_sectors)
};
```

Ці інтерфейси утворюють контракт між підсистемою блочного вводу-виводу ядра Linux та розробниками системного програмного забезпечення, забезпечуючи точний контроль над станом апаратних зон ZNS.
