# Контролери Cgroups v2: ліміти ресурсів

Уніфікована ієрархія Cgroups v2 організовує процеси, але фактичне управління ресурсами виконують **контролери** (процесор, пам'ять, ввід-вивід, кількість процесів). Вони активуються на потрібних вузлах дерева і створюють файли інтерфейсу, через які ядро отримує команди.

## Основні контролери та ліміти

- **Процесор (cpu)**
  - `cpu.weight`: пропорційна частка процесорного часу (чим більша вага, тим більше часу отримує група під навантаженням).
  - `cpu.max`: жорсткий ліміт (наприклад, `50000 100000` означає 50% одного ядра).

- **Пам'ять (memory)**
  - `memory.max`: жорстке обмеження обсягу пам'яті. При перевищенні ядро може вбити процес (OOM-killer).
  - `memory.pressure`: метрика (через PSI), що показує, як довго процеси чекають на вільну пам'ять, дозволяючи реагувати на перевантаження до виклику OOM-killer.

- **Ввід-вивід (io)**
  - `io.weight`: вага для доступу до диска.
  - `io.max`: жорсткі обмеження IOPS або BPS (швидкості читання/запису) для конкретних пристроїв.

- **Процеси (pids)**
  - `pids.max`: максимальна кількість завдань у групі. Слугує базовим захистом від fork-бомб (коли ліміт вичерпано, `fork` повертає `EAGAIN`).

Ця система дозволяє прозоро й передбачувано обмежувати споживання ресурсів, уникаючи суперечностей, неминучих у першій версії з її незалежними ієрархіями.
