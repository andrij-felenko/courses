# 📋 Довідник структур та системних інтерфейсів <elf.h>

Заголовочний файл `<elf.h>` надає стандартні визначення типів даних, системних структур, розширень та констант для роботи з бінарними файлами формату ELF у системному програмуванні на C та C++. У 64-бітних операційних системах Linux стандартом є використання типів із префіксом `Elf64_`, тоді як для 32-бітних архітектур застосовуються типи `Elf32_`.

Операційна система Linux гарантує бінарну сумісність заголовків ELF у користувацькому просторі та просторі ядра через відповідні специфікації System V Application Binary Interface (ABI).

---

## 1. Базові типи даних ELF (64-бітна специфікація)

Усі поля структур ELF мають суворо фіксований розмір у байтах, який не залежить від компілятора, опцій вирівнювання чи розрядності хост-системи, на якій виконується аналіз:

| Тип ELF | Розмір (байти) | Вирівнювання (байти) | Опис та семантичне призначення |
| :--- | :--- | :--- | :--- |
| `Elf64_Addr` | 8 | 8 | Незнакова адреса віртуальної пам'яті у 64-бітному просторі |
| `Elf64_Off` | 8 | 8 | Незнаковий зсув усередині бінарного файлу (в байтах від початку) |
| `Elf64_Half` | 2 | 2 | Незнакове 16-бітне ціле число (для лічильників та прапорців) |
| `Elf64_Word` | 4 | 4 | Незнакове 32-бітне ціле число (для типів та розмірів) |
| `Elf64_Sword` | 4 | 4 | Знакове 32-бітне ціле число (для знаковими зсувів) |
| `Elf64_Xword` | 8 | 8 | Незнакове 64-бітне ціле число (для великих розмірів та прапорів) |
| `Elf64_Sxword` | 8 | 8 | Знакове 64-бітне ціле число (для знаковими зсувів у 64-бітах) |

## 2. Заголовок ELF: Структура `Elf64_Ehdr`

Заголовок ELF розташований на самому початку файлу (зсув `0`) і має фіксований розмір рівно 64 байти для 64-бітних об'єктів. Він містить глобальний паспорт файлу та вказує точні файлові зсуви на таблиці програмних заголовків та заголовків секцій.

:::tabs
```c
typedef struct {
    unsigned char e_ident[16]; /* Магічні байти та ідентифікатори архітектури */
    Elf64_Half    e_type;      /* Тип бінарного ELF-файлу */
    Elf64_Half    e_machine;   /* Апаратна архітектура цільового процесора */
    Elf64_Word    e_version;   /* Версія формату (завжди EV_CURRENT = 1) */
    Elf64_Addr    e_entry;     /* Віртуальна адреса початкової точки входу */
    Elf64_Off     e_phoff;     /* Зсув таблиці програмних заголовків у файлі */
    Elf64_Off     e_shoff;     /* Зсув таблиці заголовків секцій у файлі */
    Elf64_Word    e_flags;     /* Прапорці, специфічні для конкретної архітектури */
    Elf64_Half    e_ehsize;    /* Розмір цього заголовка ELF (64 байти) */
    Elf64_Half    e_phentsize; /* Розмір одного елемента в таблиці PHT (56 байтів) */
    Elf64_Half    e_phnum;     /* Кількість елементів у таблиці PHT */
    Elf64_Half    e_shentsize; /* Розмір одного елемента в таблиці SHT (64 байти) */
    Elf64_Half    e_shnum;     /* Кількість елементів у таблиці SHT */
    Elf64_Half    e_shstrndx;  /* Індекс секції, яка містить таблицю рядків імен секцій */
} Elf64_Ehdr;
```
```cpp
// Ідіоматичне C++20 представлення заголовка ELF
struct Elf64_Ehdr {
    std::array<unsigned char, 16> e_ident; // Магічні байти та ідентифікатори
    Elf64_Half    e_type;      // Тип об'єкта (ET_EXEC, ET_DYN)
    Elf64_Half    e_machine;   // Архітектура (EM_X86_64, EM_AARCH64)
    Elf64_Word    e_version;   // Версія специфікації
    Elf64_Addr    e_entry;     // Точка входу
    Elf64_Off     e_phoff;     // Зсув PHT
    Elf64_Off     e_shoff;     // Зсув SHT
    Elf64_Word    e_flags;     // Прапорці архітектури
    Elf64_Half    e_ehsize;    // Розмір заголовка
    Elf64_Half    e_phentsize; // Розмір запису PHT
    Elf64_Half    e_phnum;     // Кількість записів PHT
    Elf64_Half    e_shentsize; // Розмір запису SHT
    Elf64_Half    e_shnum;     // Кількість записів SHT
    Elf64_Half    e_shstrndx;  // Індекс таблиці імен секцій
};
```
:::

### Масив ідентифікації `e_ident` та його константи

Перші 16 байтів масиву `e_ident` призначені для первинної верифікації бінарного файлу завантажувачем ядра або аналітичними інструментами.

- **`EI_MAG0`..`EI_MAG3` (індекси 0..3):** Магічне число ELF. Повинно дорівнювати послідовності `0x7F`, `'E'`, `'L'`, `'F'` (байтові константи `ELFMAG0`..`ELFMAG3` або макрос `ELFMAG`).
- **`EI_CLASS` (індекс 4):** Клас розрядності архітектури:
  - `ELFCLASSNONE` (`0`) — недійсний клас.
  - `ELFCLASS32` (`1`) — 32-бітна архітектура.
  - `ELFCLASS64` (`2`) — 64-бітна архітектура.
- **`EI_DATA` (індекс 5):** Порядок байтів (Endianness) для багатобайтових полів:
  - `ELFDATANONE` (`0`) — недійсне кодування.
  - `ELFDATA2LSB` (`1`) — Little-Endian (прямий порядок: x86, x86-64, ARM Little-Endian, RISC-V).
  - `ELFDATA2MSB` (`2`) — Big-Endian (зворотний порядок: PowerPC, SPARC, System/390).
- **`EI_VERSION` (індекс 6):** Версія специфікації ELF. Повинно дорівнювати `EV_CURRENT` (`1`).
- **`EI_OSABI` (індекс 7):** Операційна система та системний розширюваний ABI:
  - `ELFOSABI_SYSV` або `ELFOSABI_NONE` (`0`) — UNIX System V ABI.
  - `ELFOSABI_HPUX` (`1`) — HP-UX.
  - `ELFOSABI_NETBSD` (`2`) — NetBSD.
  - `ELFOSABI_GNU` / `ELFOSABI_LINUX` (`3`) — GNU/Linux із системними розширеннями.
  - `ELFOSABI_SOLARIS` (`6`) — Oracle Solaris.
  - `ELFOSABI_FREEBSD` (`9`) — FreeBSD.
  - `ELFOSABI_ARM` (`97`) — Апаратна архітектура ARM.
  - `ELFOSABI_STANDALONE` (`255`) — Автономні вбудовані системи (Bare-metal).
- **`EI_ABIVERSION` (індекс 8):** Версія конкретного ABI цільової системи.
- **`EI_PAD` (індекси 9..15):** Зарезервовані байти вирівнювання (обнуляються).

### Типи файлів `e_type`

Поле `e_type` позначає базове функціональне призначення ELF-об'єкта:

- **`ET_NONE` (`0`):** Невизначений або невідомий тип файлу.
- **`ET_REL` (`1`):** Переміщуваний об'єктний файл (`.o`). Створюється компілятором і містить релокаційні поправки для подальшого збирання компонувальником.
- **`ET_EXEC` (`2`):** Статично зкомпонований виконуваний файл. Містить фіксовані адреси віртуальної пам'яті та не вимагає динамічного завантажувача.
- **`ET_DYN` (`3`):** Спільний об'єкт (`.so`) або виконуваний файл із підтримкою позиційно-незалежного коду (PIE). Завантажується за довільною базовою адресою у віртуальній пам'яті.
- **`ET_CORE` (`4`):** Дамп оперативної пам'яті (Core Dump). Зберігається ядром Linux при аварійному завершенні процесу (SIGSEGV, SIGABRT) і містить регістри та сторінки пам'яті.

### Апаратні платформи `e_machine`

Поле `e_machine` визначає набор інструкцій (ISA), під який скомпільовано бінарний код:

- `EM_386` (`3`) — Intel 80386 та сумісні 32-бітні процесори.
- `EM_MIPS` (`8`) — MIPS Architecture.
- `EM_PPC` (`20`) — PowerPC (32-bit).
- `EM_PPC64` (`21`) — PowerPC (64-bit).
- `EM_ARM` (`40`) — ARM (32-bit).
- `EM_IA_64` (`50`) — Intel Itanium Architecture.
- `EM_X86_64` (`62`) — AMD/Intel x86-64 (AMD64 / EM64T).
- `EM_AARCH64` (`183`) — ARM 64-bit (ARMv8-A / ARMv9-A).
- `EM_RISCV` (`243`) — RISC-V (32-bit / 64-bit / 128-bit).

## 3. Таблиця програмних заголовків: Структура `Elf64_Phdr`

Програмні заголовки описують сегменти бінарного файлу. Вони використовуються ядром операційної системи та динамічним завантажувачем під час створення віртуального адресного простору процесу.

:::tabs
```c
typedef struct {
    Elf64_Word  p_type;   /* Тип сегмента */
    Elf64_Word  p_flags;  /* Прапорці прав доступу до сегмента (PF_R, PF_W, PF_X) */
    Elf64_Off   p_offset; /* Зсув початку сегмента від початку файлу у байтах */
    Elf64_Addr  p_vaddr;  /* Віртуальна адреса сегмента в пам'яті процесу */
    Elf64_Addr  p_paddr;  /* Фізична адреса (у сучасних OS з вик. VMM не використовується) */
    Elf64_Xword p_filesz; /* Розмір даних сегмента, що знаходяться у файлі (у байтах) */
    Elf64_Xword p_memsz;  /* Загальний розмір сегмента в оперативній пам'яті (у байтах) */
    Elf64_Xword p_align;  /* Вимоги до сторінкового вирівнювання (степінь двійки) */
} Elf64_Phdr;
```
```cpp
// Ідіоматична C++ структура елемента PHT
struct Elf64_Phdr {
    Elf64_Word  p_type;   // Тип сегмента (PT_LOAD, PT_INTERP, etc.)
    Elf64_Word  p_flags;  // Прапорці доступу (PF_R | PF_W | PF_X)
    Elf64_Off   p_offset; // Зсув у файлі
    Elf64_Addr  p_vaddr;  // Віртуальна адреса
    Elf64_Addr  p_paddr;  // Фізична адреса
    Elf64_Xword p_filesz; // Розмір у файлі
    Elf64_Xword p_memsz;  // Розмір у пам'яті
    Elf64_Xword p_align;  // Вирівнювання
};
```
:::

### Константи типів сегментів `p_type`

- **`PT_NULL` (`0`):** Невикористовуваний або розформований елемент таблиці.
- **`PT_LOAD` (`1`):** Завантажуваний сегмент. Ядро відображає `p_filesz` байтів із файлу у пам'яті за адресою `p_vaddr`, а решту `p_memsz - p_filesz` обнуляє (сегмент даних та `.bss`).
- **`PT_DYNAMIC` (`2`):** Вказує на масив метаданих динамічного зв'язування (структури `Elf64_Dyn`).
- **`PT_INTERP` (`3`):** Містить шлях до інтерпретатора/завантажувача (рядок з нульовим завершенням, наприклад `/lib64/ld-linux-x86-64.so.2`).
- **`PT_NOTE` (`4`):** Вказує на системні примітки (версія ABI, Build-ID, примітки ядра).
- **`PT_SHLIB` (`5`):** Зарезервовано (не застосовується у Linux).
- **`PT_PHDR` (`6`):** Визначає розташування та розмір самої таблиці PHT у пам'яті.
- **`PT_TLS` (`7`):** Описує шаблон ініціалізації локальних даних потоку (Thread-Local Storage).
- **`PT_GNU_EH_FRAME` (`0x6474e550`):** Вказує на таблицю індексування для швидкої обробки винятків C++ (`.eh_frame_hdr`).
- **`PT_GNU_STACK` (`0x6474e551`):** Визначає атрибути захисту стеку процесу (відсутність `PF_X` вмикає захист NX).
- **`PT_GNU_RELRO` (`0x6474e552`):** Описує область пам'яті, яка після завершення релокацій переводиться завантажувачем у режим `PROT_READ`.

### Прапорці прав доступу `p_flags`

- **`PF_X` (`1`):** Дозвіл на виконання інструкцій (`PROT_EXEC`).
- **`PF_W` (`2`):** Дозвіл на запис у пам'ять (`PROT_WRITE`).
- **`PF_R` (`4`):** Дозвіл на читання з пам'яті (`PROT_READ`).

## 4. Таблиця заголовків секцій: Структура `Elf64_Shdr`

Таблиця заголовків секцій описує секції файлу, які використовуються статичним компонувальником для об'єднання об'єктних файлів, зв'язування символів та релокації.

:::tabs
```c
typedef struct {
    Elf64_Word  sh_name;      /* Зсув імені секції в таблиці рядків .shstrtab */
    Elf64_Word  sh_type;      /* Тип вмісту та внутрішня семантика секції */
    Elf64_Xword sh_flags;     /* Атрибути та прапорці доступу під час виконання */
    Elf64_Addr  sh_addr;      /* Віртуальна адреса секції під час виконання */
    Elf64_Off   sh_offset;    /* Зсув секції від початку файлу у байтах */
    Elf64_Xword sh_size;      /* Загальний розмір секції у байтах */
    Elf64_Word  sh_link;      /* Індекс пов'язаної секції в SHT */
    Elf64_Word  sh_info;      /* Додаткова системна інформація */
    Elf64_Xword sh_addralign; /* Вимоги до вирівнювання адреси секції */
    Elf64_Xword sh_entsize;   /* Розмір одного запису, якщо секція містить таблицю */
} Elf64_Shdr;
```
```cpp
// Ідіоматична C++ структура елемента SHT
struct Elf64_Shdr {
    Elf64_Word  sh_name;      // Зсув імені в .shstrtab
    Elf64_Word  sh_type;      // Тип секції (SHT_PROGBITS, SHT_NOBITS)
    Elf64_Xword sh_flags;     // Прапорці атрибутів (SHF_WRITE | SHF_ALLOC)
    Elf64_Addr  sh_addr;      // Віртуальна адреса
    Elf64_Off   sh_offset;    // Зсув у файлі
    Elf64_Xword sh_size;      // Розмір секції
    Elf64_Word  sh_link;      // Пов'язана секція
    Elf64_Word  sh_info;      // Додаткова інформація
    Elf64_Xword sh_addralign; // Вирівнювання
    Elf64_Xword sh_entsize;   // Розмір запису
};
```
:::

### Константи типів секцій `sh_type`

- **`SHT_NULL` (`0`):** Заголовок секції неактивний.
- **`SHT_PROGBITS` (`1`):** Секція містить дані програми (машинний код `.text`, константи `.rodata`, ініціалізовані змінні `.data`).
- **`SHT_SYMTAB` (`2`):** Повна таблиця символів для статичного компонування та налагодження.
- **`SHT_STRTAB` (`3`):** Таблиця рядків (символьні імена секцій, змінних та функцій).
- **`SHT_RELA` (`4`):** Записи релокацій із явним доданком (`Elf64_Rela`).
- **`SHT_HASH` (`5`):** Хеш-таблиця символів для динамічного пошуку.
- **`SHT_DYNAMIC` (`6`):** Секція метаданих динамічного зв'язування.
- **`SHT_NOTE` (`7`):** Системна примітка або метадані збірки.
- **`SHT_NOBITS` (`8`):** Секція не займає місця у файлі (наприклад, `.bss`). Розмір задається полем `sh_size`.
- **`SHT_REL` (`9`):** Записи релокацій без явного доданка (`Elf64_Rel`).
- **`SHT_DYNSYM` (`11`):** Мінімальна таблиця символів для динамічного зв'язування під час виконання.
- **`SHT_INIT_ARRAY` (`14`):** Масив вказівників на конструктори (`__attribute__((constructor))`).
- **`SHT_FINI_ARRAY` (`15`):** Масив вказівників на деструктори.
- **`SHT_GNU_HASH` (`0x6ffffff6`):** Оптимізована хеш-таблиця GNU для виключно швидкого розв'язання символів.

### Прапорці атрибутів секцій `sh_flags`

- **`SHF_WRITE` (`0x1`):** Секція повинна бути доступною для запису в пам'яті (`.data`, `.bss`).
- **`SHF_ALLOC` (`0x2`):** Секція займає оперативну пам'ять під час виконання процесів.
- **`SHF_EXECINSTR` (`0x4`):** Секція містить виконувані машинні інструкції (`.text`).
- **`SHF_MERGE` (`0x10`):** Дані секції можуть бути об'єднані компонувальником для усунення дублікатів.
- **`SHF_STRINGS` (`0x20`):** Секція складається з рядків із нульовим завершенням.
- **`SHF_TLS` (`0x400`):** Секція належить до даних потоку (Thread-Local Storage).

## 5. Таблиця символів: Структура `Elf64_Sym`

Кожен запис у секціях `.symtab` або `.dynsym` описується структурою `Elf64_Sym`:

:::tabs
```c
typedef struct {
    Elf64_Word    st_name;  /* Зсув імені символу у відповідній таблиці рядків */
    unsigned char st_info;  /* Тип символу та його атрибут зв'язування (Binding) */
    unsigned char st_other; /* Атрибут видимості символу (Visibility) */
    Elf64_Half    st_shndx; /* Індекс секції в SHT, де визначено даний символ */
    Elf64_Addr    st_value; /* Віртуальна адреса або значення символу */
    Elf64_Xword   st_size;  /* Розмір символу в байтах (наприклад, розмір функції) */
} Elf64_Sym;
```
```cpp
// Ідіоматична C++ структура опису символу
struct Elf64_Sym {
    Elf64_Word    st_name;  // Зсув імені в .strtab/.dynstr
    unsigned char st_info;  // Тип та зв'язування (STB_GLOBAL, STT_FUNC)
    unsigned char st_other; // Видимість
    Elf64_Half    st_shndx; // Індекс секції в SHT
    Elf64_Addr    st_value; // Віртуальна адреса
    Elf64_Xword   st_size;  // Розмір символу
};
```
:::

Для аналізу поля `st_info` застосовуються стандартні макроси:

- **`ELF64_ST_BIND(st_info)` (Зв'язування):**
  - `STB_LOCAL` (`0`) — Локальний символ (видимий лише в межах поточного об'єктного файлу).
  - `STB_GLOBAL` (`1`) — Глобальний символ (видимий для всіх об'єктних файлів під час компонування).
  - `STB_WEAK` (`2`) — Слабий символ (може бути перевизначений глобальним символом із тим самим ім'ям).
- **`ELF64_ST_TYPE(st_info)` (Тип):**
  - `STT_NOTYPE` (`0`) — Тип символу не визначено.
  - `STT_OBJECT` (`1`) — Символ посилається на об'єкт даних (змінна, структура, масив).
  - `STT_FUNC` (`2`) — Символ посилається на виконувану функцію або точку входу.
  - `STT_SECTION` (`3`) — Символ пов'язаний із секцією.
  - `STT_FILE` (`4`) — Ім'я сирцевого файлу компіляції.
  - `STT_TLS` (`5`) — Символ локальних даних потоку.

## 6. Таблиця динамічного зв'язування: Структура `Elf64_Dyn`

Секція `.dynamic` (сегмент `PT_DYNAMIC`) складається з масиву елементів `Elf64_Dyn`, які контролюють роботу динамічного завантажувача:

:::tabs
```c
typedef struct {
    Elf64_Sxword d_tag; /* Тег динамічного запису */
    union {
        Elf64_Xword d_val; /* Цілочисельне значення або розмір */
        Elf64_Addr  d_ptr; /* Віртуальна адреса у пам'яті */
    } d_un;
} Elf64_Dyn;
```
```cpp
// Ідіоматична C++ структура динамічного тегу
struct Elf64_Dyn {
    Elf64_Sxword d_tag; // Динамічний тег (DT_NEEDED, DT_SYMTAB)
    union {
        Elf64_Xword d_val; // Розмір чи значення
        Elf64_Addr  d_ptr; // Віртуальна адреса
    } d_un;
};
```
:::

Основні значення `d_tag`:

- **`DT_NULL` (`0`):** Маркер кінця динамічної таблиці.
- **`DT_NEEDED` (`1`):** Зсув у `.dynstr` імені залежної спільної бібліотеки (наприклад, `libc.so.6`).
- **`DT_PLTRELSZ` (`2`):** Загальний розмір релокаційних записів PLT.
- **`DT_PLTGOT` (`3`):** Адреса, пов'язана з глобальною таблицею зсувів (GOT / PLT).
- **`DT_HASH` (`5`):** Адреса стандартної хеш-таблиці символів.
- **`DT_STRTAB` (`5`):** Адреса таблиці рядків `.dynstr`.
- **`DT_SYMTAB` (`6`):** Адреса таблиці динамічних символів `.dynsym`.
- **`DT_RELA` (`7`):** Адреса таблиці релокацій `.rela.dyn`.
- **`DT_RELASZ` (`8`):** Загальний розмір таблиці `.rela.dyn` у байтах.
- **`DT_RELAENT` (`9`):** Розмір одного запису в таблиці релокацій.
- **`DT_INIT` (`12`):** Адреса функції ініціалізації модуля.
- **`DT_FINI` (`13`):** Адреса функції завершення модуля.
- **`DT_SONAME` (`14`):** Внутрішнє ім'я спільної бібліотеки (SONAME).
- **`DT_RUNPATH` (`29`):** Шляхи пошуку спільних бібліотек під час виконання.

## 7. Структури релокацій: `Elf64_Rela` та `Elf64_Rel`

Записи релокації описують, як саме компонувальник або динамічний завантажувач модифікують вміст коду та даних під час налаштування адрес.

:::tabs
```c
typedef struct {
    Elf64_Addr   r_offset; /* Віртуальна адреса або зсув, що підлягає модифікації */
    Elf64_Xword  r_info;   /* Індекс символу у таблиці та тип релокації */
    Elf64_Sxword r_addend; /* Явний доданок (Explicit Addend) */
} Elf64_Rela;

typedef struct {
    Elf64_Addr  r_offset;  /* Віртуальна адреса або зсув, що підлягає модифікації */
    Elf64_Xword r_info;    /* Індекс символу у таблиці та тип релокації */
} Elf64_Rel;
```
```cpp
// Ідіоматична C++ структура запису релокацій з явним доданком
struct Elf64_Rela {
    Elf64_Addr   r_offset; // Адреса модифікації
    Elf64_Xword  r_info;   // Індекс символу та тип релокації
    Elf64_Sxword r_addend; // Явний доданок
};

struct Elf64_Rel {
    Elf64_Addr  r_offset;  // Адреса модифікації
    Elf64_Xword r_info;    // Індекс символу та тип релокації
};
```
:::

Для маніпуляцій із полем `r_info` використовуються макроси:
- `ELF64_R_SYM(info)` — витягує індекс символу з вищих 32 бітів.
- `ELF64_R_TYPE(info)` — витягує тип релокації з нижчих 32 бітів.

Найважливіші типи релокацій для архітектури x86-64:
- `R_X86_64_NONE` (`0`) — Релокація відсутня.
- `R_X86_64_64` (`1`) — Пряме 64-бітне значення символу (`S + A`).
- `R_X86_64_PC32` (`2`) — 32-бітне відносне адресування відносно Лічильника Команд (`S + A - P`).
- `R_X86_64_GOT32` (`3`) — 32-бітний зсув у таблиці GOT.
- `R_X86_64_PLT32` (`4`) — 32-бітна адреса вхідної точки у таблиці PLT.
- `R_X86_64_GLOB_DAT` (`6`) — Запис у GOT для глобального символу.
- `R_X86_64_JUMP_SLOT` (`7`) — Запис у GOT/PLT для процедурних викликів.
- `R_X86_64_RELATIVE` (`8`) — Базова релокація відносно адреси завантаження бінарного файлу (`B + A`).
