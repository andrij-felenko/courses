# 📋 Мережевий інтерфейс Netlink та параметри sysctl для MPTCP

Підсистема Багатошляхового TCP у ядрі Linux надає розширений програмний інтерфейс керування та діагностики. Оскільки традиційні сокетні виклики POSIX не передбачали маніпуляцій декількома мережевими інтерфейсами для одного транспортного з'єднання, розробники ядра Linux використали механізм **Generic Netlink (genl)** для зв'язку між простором користувача та підсистемою MPTCP.

У цій довідковій вставці систематизовано специфікацію Generic Netlink сімейства `"mptcp"`, структуру повідомлень та атрибутів, події мультикаст-груп, координаційні параметри `sysctl`, а також синтаксис CLI-утиліти `ip mptcp` та налаштування демона `mptcpd`.

---

## 1. Специфікація Generic Netlink сімейства "mptcp"

Протокол Generic Netlink виступає гнучкою надбудовою над базовим сокетом `AF_NETLINK` (із типом `NETLINK_GENERIC`). Він дозволяє ядру реєструвати динамічні сімейства команд із власним набором атрибутів та мультикаст-груп.

Підсистема MPTCP реєструє у ядрі сімейство з наступними константами:
- **Ім'я сімейства (Family Name):** `"mptcp"` (визначено макросом `MPTCP_PM_NAME`).
- **Версія протоколу (Version):** `1` (визначено макросом `MPTCP_PM_VER`).
- **Мультикаст-група сповіщень:** `"events"` (`MPTCP_PM_EV_GRP_NAME`).

Кожне повідомлення Generic Netlink складається з базового заголовка Netlink (`struct nlmsghdr`), заголовка Generic Netlink (`struct genlmsghdr`) та послідовності вкладених атрибутів у форматі `TLV` (Type-Length-Value).

### 1.1 Команди управління (Netlink Commands)

Управлінські запити від надсилаються від прикладного процесу (наприклад, utility `ip mptcp` або сервісу `mptcpd`) до ядра Linux у формі повідомлень з відповідним номером команди у полі `cmd` заголовка `struct genlmsghdr`.

#### Перелік команд ядра Linux:

- **`MPTCP_PM_CMD_ADD_ADDR` (`1`):** 
  Створює новий локальний ендпоінт (адресну точку) у внутрішній таблиці ядерного Path Manager. Приймає вкладений атрибут `MPTCP_PM_ATTR_ADDR`, який містить IP-адресу, порт, ідентифікатор адреси (`Address ID`) та бітові прапори (наприклад, `signal` або `subflow`). При створенні адреси з прапором `signal`, ядро готує опцію `ADD_ADDR` для передачі віддаленому вузлу.

- **`MPTCP_PM_CMD_DEL_ADDR` (`2`):** 
  Видаляє існуючий ендпоінт із таблиці Path Manager за його `Address ID` або конкретною IP-адресою. Якщо з цим ендпоінтом були пов'язані активні підпотоки, ядро надсилає сигнал `RM_ADDR` і закриває відповідні сокети.

- **`MPTCP_PM_CMD_GET_ADDR` (`3`):** 
  Запитує в ядра детальні характеристики конкретного ендпоінта за його ідентифікатором.

- **`MPTCP_PM_CMD_FLUSH_ADDRS` (`4`):** 
  Повністю очищає всі зареєстровані локальні ендпоінти MPTCP в системі.

- **`MPTCP_PM_CMD_SET_LIMITS` (`5`):** 
  Встановлює системні ліміти ядра на максимальну кількість дозволених підпотоків та прийнятих адрес `ADD_ADDR` для MPTCP-з'єднань.

- **`MPTCP_PM_CMD_GET_LIMITS` (`6`):** 
  Повертає поточні глобальні обмеження ядра (відповідає значенням атрибутів `MPTCP_PM_ATTR_SUBFLOWS` та `MPTCP_PM_ATTR_ADD_ADDR_ACCEPTED`).

- **`MPTCP_PM_CMD_SET_FLAGS` (`7`):** 
  Динамічно змінює прапори для вже існуючої адреси без її видалення (наприклад, дозволяє на льоту перетворити звичайний ендпоінт на резервний `backup`).

- **`MPTCP_PM_CMD_ANNOUNCE` (`8`):** 
  Використовується виключно в режимі `userspace PM`. Дозволяє зовнішньому демону наказати ядру надіслати опцію `ADD_ADDR` для конкретного сокета, вказаного його унікальним токеном (`MPTCP_PM_ATTR_TOKEN`).

- **`MPTCP_PM_CMD_REMOVE` (`9`):** 
  Використовується в режимі `userspace PM` для примусового відправлення сигналу видалення адреси `RM_ADDR` для конкретного токена.

- **`MPTCP_PM_CMD_SUBFLOW_CREATE` (`10`):** 
  Команда користувацького менеджера шляхів, яка наказує ядру негайно ініціювати новий вихідний підпотік `MP_JOIN` з вказаного локального ендпоінта до вказаної віддаленої IP-адреси.

- **`MPTCP_PM_CMD_SUBFLOW_DESTROY` (`11`):** 
  Примусово розриває та знищує конкретний підпотік для вказаного MPTCP-сокета.

### 1.2 Події ядра (Netlink Events)

Для реалізації моніторингу та зовнішнього управління, ядро Linux транслює події про зміну стану MPTCP-з'єднань у мультикаст-групу `"events"`. Прикладні програми підписуються на цю групу через системний виклик `nl_subscribe()` або сокетний виклик `bind()`.

#### Опис подій ядра:

- **`MPTCP_EVENT_CREATED` (`1`):** 
  Викликається в момент створення нового мета-сокета `IPPROTO_MPTCP` (до початку мережевого рукостискання). Повідомлення містить згенерований токен з'єднання, вихідну та призначену IP-адресу й номери портів.

- **`MPTCP_EVENT_ESTABLISHED` (`2`):** 
  Генерується після успішного завершення 3-way handshake первинного підпотоку (`MP_CAPABLE`). Інформує, яка саме сторона виступає сервером (`SERVER_SIDE`), а яка — клієнтом.

- **`MPTCP_EVENT_CLOSED` (`3`):** 
  Сповіщає про повне закриття MPTCP-мета-сокета та звільнення пов'язаних із ним системних ресурсів.

- **`MPTCP_EVENT_ANNOUNCED` (`4`):** 
  Викликається при отриманні від віддаленого вузла TCP-опції `ADD_ADDR`. Повідомлення містить новий `Address ID`, додану IP-адресу та номер порту.

- **`MPTCP_EVENT_REMOVED` (`5`):** 
  Викликається при отриманні опції `RM_ADDR` про скасування віддаленої адреси.

- **`MPTCP_EVENT_SUB_ESTABLISHED` (`6`):** 
  Інформує про успішне приєднання додаткового підпотоку (`MP_JOIN`). Містить локальний та віддалений `Address ID`, а також конкретну пара IP-адрес та портів нового підпотоку.

- **`MPTCP_EVENT_SUB_CLOSED` (`7`):** 
  Сповіщає про розрив або закриття одного з підпотоків. Мета-сокет при цьому продовжує функціонувати на інших підпотоках.

- **`MPTCP_EVENT_SUB_PRIO` (`8`):** 
  Інформує про зміну прапора резервування підпотоку внаслідок отримання або надсилання опції `MP_PRIO`.

### 1.3 Атрибути та прапори ендпоінтів

Дані в повідомленнях Generic Netlink кодуються у вигляді дерева вкладених атрибутів `nlattr`. Головним контейнером для опису мережевої адреси є атрибут `MPTCP_PM_ATTR_ADDR` (`NLA_NESTED`).

#### Структура вкладеного атрибута `MPTCP_PM_ATTR_ADDR`:

1. `MPTCP_ATTR_FAMILY` (`u16`): Мережеве сімейство адрес (`AF_INET` для IPv4 або `AF_INET6` для IPv6).
2. `MPTCP_ATTR_ADDR4` (`u32`): 32-бітна адреса IPv4 у мережевому порядку байтів (Big-Endian).
3. `MPTCP_ATTR_ADDR6` (`raw`): 128-бітна адреса IPv6 (масив із 16 байт).
4. `MPTCP_ATTR_PORT` (`u16`): Номер TCP-порту. Якщо вказано `0`, ядро використовує стандартний порт первинного з'єднання.
5. `MPTCP_ATTR_TOKEN` (`u32`): Унікальний 32-бітний токен MPTCP-з'єднання.
6. `MPTCP_ATTR_LOC_ID` (`u8`): Локальний ідентифікатор адреси (`Address ID` у діапазоні від `0` до `255`).
7. `MPTCP_ATTR_FLAGS` (`u32`): Бітова маска поведінки ендпоінта.

#### Значення бітових прапорів (`MPTCP_ATTR_FLAGS`):

- **`MPTCP_PM_ADDR_FLAG_SIGNAL` (`0x01`):** 
  Оголошувати дану адресу віддаленому вузлу за допомогою опції `ADD_ADDR`. Локальне ядро не створює вихідний підпотік самостійно, а очікує, що віддалена сторона ініціює `MP_JOIN` до цієї адреси.

- **`MPTCP_PM_ADDR_FLAG_SUBFLOW` (`0x02`):** 
  Наказує локальному ядрові самостійно ініціювати вихідне з'єднання `MP_JOIN` з цього ендпоінта до віддаленої адреси сервера.

- **`MPTCP_PM_ADDR_FLAG_BACKUP` (`0x04`):** 
  Позначає ендпоінт як резервний (передає опцію `MP_PRIO`). Трафік через цей підпотік спрямовуватиметься лише тоді, коли всі основні підпотоки недоступні або зазнають важких втрат пакетів.

- **`MPTCP_PM_ADDR_FLAG_FULLMESH` (`0x08`):** 
  Наказує створювати окремі підпотоки до всіх відомих IP-адрес віддаленого вузла, формуючи повнозв'язану сітку з'єднань.

- **`MPTCP_PM_ADDR_FLAG_IMPLICIT` (`0x10`):** 
  Автоматично сформований ядром ендпоінт, виявлений безпосередньо з параметрів сокета без явного додавання користувачем.

## 2. Параметри ядра Linux у /proc/sys/net/mptcp/

Тюнінг глобальної поведінки MPTCP виконується через файл-систему `procfs` у каталозі `/proc/sys/net/mptcp/`. Налаштування можна змінювати на льоту командою `sysctl -w` або зберігати у файлі `/etc/sysctl.d/99-mptcp.conf`.

### Детальний опис параметрів `sysctl`:

- **`net.mptcp.enabled` (integer, default: `1`):**
  Головний системний перемикач підтримки MPTCP у ядрі.
  - `1`: Дозволити створення сокетів `IPPROTO_MPTCP` та обробку MPTCP-опцій у TCP-заголовках.
  - `0`: Повністю вимкнути MPTCP. Спроба виклику `socket(..., IPPROTO_MPTCP)` повертатиме помилку `EPROTONOSUPPORT`, а вхідні опції MPTCP ігноруватимуться.

- **`net.mptcp.pm_type` (integer, default: `0`):**
  Визначає архітектуру Path Manager для нових сокетів.
  - `0` (`in-kernel PM`): Управління підпотоками виконується ядром Linux на основі правил, заданих через `ip mptcp endpoint`.
  - `1` (`userspace PM`): Управління передається зовнішньому демону `mptcpd` через Netlink.

- **`net.mptcp.add_addr_accepted_limit` (integer, default: `2`):**
  Максимальна кількість опцій `ADD_ADDR`, яку локальне ядро погоджується прийняти від віддаленого вузла в межах одного MPTCP-з'єднання. Обмеження захищає систему від DoS-атак переповнення пам'яті фальшивими адресами.

- **`net.mptcp.subflows_limit` (integer, default: `2`):**
  Максимальна кількість додаткових підпотоків (`MP_JOIN`), яку ядро дозволяє створити чи прийняти для одного MPTCP-з'єднання (на додачу до первинного підпотоку).

- **`net.mptcp.stale_loss_cnt` (integer, default: `4`):**
  Кількість послідовних ретрансмісій (втрат пакетів) на підпотоці, після яких ядро позначає підпотік як "застарілий" (`stale`). Планувальник тимчасово зупиняє відправку нових даних у цей підпотік до відновлення зв'язку.

- **`net.mptcp.checksum_enabled` (integer, default: `0`):**
  Перемикач розрахунку 16-бітної контрольної суми в опціях DSS. Вмикання (`1`) підвищує захист від пошкодження даних middlebox-пристроями, але створює незначне додаткове навантаження на процесор.

- **`net.mptcp.allow_join_initial_addr_port` (integer, default: `1`):**
  Дозволяє створювати нові підпотоки `MP_JOIN`, що спрямовані на ту саму комбінацію IP-адреси та порту, що й початковий підпотік.

## 3. Синтаксис CLI-інструменту ip mptcp

Керування ендпоінтами та лімітами MPTCP у сучасних дистрибутивах Linux виконується за допомогою утиліти `ip mptcp` з пакета `iproute2`.

### 3.1 Управління ендпоінтами (`ip mptcp endpoint`)

Перегляд зареєстрованих ендпоінтів:
```bash
ip mptcp endpoint show
```

Оголошення адреси віддаленому вузлу (сигнал `ADD_ADDR`):
```bash
ip mptcp endpoint add 192.168.1.100 dev eth0 signal
```

Створення ендпоінта для активного відкриття підпотоків (`MP_JOIN`):
```bash
ip mptcp endpoint add 10.0.2.15 dev wlan0 subflow
```

Призначення ендпоінта резервним каналом (`backup`):
```bash
ip mptcp endpoint add 172.16.0.5 dev wwan0 subflow backup
```

Додавання ендпоінта з явним ідентифікатором адреси та сіткою `fullmesh`:
```bash
ip mptcp endpoint add 192.168.1.100 id 1 signal fullmesh
```

Видалення ендпоінта за ID або IP-адресою:
```bash
ip mptcp endpoint del id 1
ip mptcp endpoint del 10.0.2.15
```

Очищення всіх ендпоінтів:
```bash
ip mptcp endpoint flush
```

---

### 3.2 Налаштування системних лімітів (`ip mptcp limits`)

Перегляд поточних обмежень:
```bash
ip mptcp limits show
```

Зміна лімітів прийнятих адрес та підпотоків:
```bash
ip mptcp limits set add_addr_accepted 4 subflows 4
```

---

### 3.3 Моніторинг подій у реальному часі (`ip mptcp monitor`)

Запуск утиліти в режимі безперервного відстеження подій ядра:
```bash
ip mptcp monitor
```

Приклад виводу логу подій під час підключення клієнта:
```text
[CREATED] token=3a8f1b12 rem_id=0 loc_id=0 saddr=192.168.1.50 daddr=93.184.216.34 sport=42100 dport=443
[ESTABLISHED] token=3a8f1b12 rem_id=0 loc_id=0 saddr=192.168.1.50 daddr=93.184.216.34 sport=42100 dport=443
[SF_ESTABLISHED] token=3a8f1b12 rem_id=0 loc_id=2 saddr=10.0.2.15 daddr=93.184.216.34 sport=58912 dport=443 backup=0
```

## 4. Конфігурація юзерспейсного демона mptcpd

Демон `mptcpd` реалізує функціональність користувацького менеджера шляхів (`userspace PM`). Він працює у тлі й відстежує зміни мережевих інтерфейсів через `rtnetlink`, автоматично формуючи Netlink-команди для ядра.

Файл конфігурації знаходиться за шляхом `/etc/mptcpd/mptcpd.conf`:

```ini
[mptcpd]
# Вибір плагіна розшуку та керування шляхами
path-manager=default

# Автоматично створювати підпотоки при появі нових мережевих інтерфейсів
auto-subflows=true

# Автоматично оголошувати нові IP-адреси віддаленим вузлам через ADD_ADDR
track-addresses=true

# Прапори за замовчуванням для нових інтерфейсів
default-flags=subflow,signal

# Налаштування журналювання (stderr, sys_log)
log-destination=sys_log
log-level=info
```

Демон `mptcpd` надає C-бібліотеку `libmptcpd`, що дозволяє розробникам створювати власні плагіни оркестрації підпотоків для спеціалізованих маршрутизаторів та пристроїв 5G N3IWF.
