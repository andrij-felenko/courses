# 📋 Довідник розділів, макросів розмітки та конвенцій man

Довідник фіксує технічні специфікації, структуру розділів, синтаксичні контракти макропакетів `man(7)` та `mdoc(7)`, низькорівневі регістри й умовні вирази рушія `roff`, синтаксис препроцесорів `tbl(1)`, `eqn(1)`, `pic(1)`, конвенції локалізації та стандарти кодування, правила оформлення секції безпеки `ATTRIBUTES`, а також формати конфігурації генераторів документації.

---

## 1. Класифікація розділів та ієрархія інтерфейсів

Стандартна ієрархія сторінок довідки розподіляє документацію на дев'ять нумерованих розділів відповідно до рівня абстракції в операційній системі.

### Основні розділи (1–9)

```
   ┌─────────────────────────────────────────────────────────────────────────┐
   │                  КЛАСИФІКАЦІЯ РОЗДІЛІВ СИСТЕМИ MAN                      │
   ├──────┬──────────────────────────────────────────┬───────────────────────┤
   │ Сек. │ Призначення та тип сутності              │ Типові приклади       │
   ├──────┼──────────────────────────────────────────┼───────────────────────┤
   │  1   │ Команди користувача та утиліти CLI       │ ls, grep, bash, tar   │
   │  2   │ Прямі системні виклики ядра              │ read, write, open, mmap│
   │  3   │ Бібліотечні функції C / glibc / POSIX    │ printf, malloc, fopen │
   │  4   │ Спеціальні файли та пристрої (/dev)      │ null, tty, random, sd │
   │  5   │ Формати файлів конфігурацій та таблиць   │ passwd, fstab, elf    │
   │  6   │ Ігри, демо-програми та заставки          │ fortune, cowsay       │
   │  7   │ Огляди підсистем, конвенції та стандарти │ ip, tcp, pthreads, man│
   │  8   │ Системне адміністрування та демони       │ systemd, mount, sshd  │
   │  9   │ Внутрішні функції та інтерфейси ядра     │ VFS API, sk_buff (BSD)│
   └──────┴──────────────────────────────────────────┴───────────────────────┘
```

1. **Розділ 1 — Команди простору користувача (`User Commands`)**:
   - Утиліти командного рядка, виконувані бінарні файли, скрипти оболонки та компілятори, доступні непривілейованим користувачам.
   - Специфікація: обов'язкова наявність секцій `SYNOPSIS`, `OPTIONS` та опису кодів завершення процесу в `EXIT STATUS`.
   - Приклади: `ls(1)`, `grep(1)`, `find(1)`, `git(1)`, `tar(1)`.

2. **Розділ 2 — Системні виклики ядра (`System Calls`)**:
   - Прямі програмні точки входу в простір ядра Linux/Unix, що ініціюються процесором через інструкцію `syscall` (x86-64), `sysenter` (x86-32) або програмне переривання `svc` (ARM).
   - Специфікація: опис поведінки бінарного інтерфейсу ядра (ABI), правила взаємодії з таблицею дескрипторів, встановлення маски помилки `errno`, атомарність операцій, поведінка при перериванні сигналами (`EINTR`).
   - Приклади: `open(2)`, `read(2)`, `write(2)`, `mmap(2)`, `epoll_create1(2)`, `clone(2)`.

3. **Розділ 3 — Бібліотечні виклики (`Library Calls`)**:
   - Функції стандартної бібліотеки C (`glibc`, `musl`), обгортки системних викликів, математичні алгоритми (`libm`), бібліотеки потоків (`libpthread`), криптографічні рушії (`libcrypto`, `libssl`) та мережеві бібліотеки (`libcurl`).
   - Специфікація: сигнатури мови C, директиви `#include`, макроси тестування функціональності (`_GNU_SOURCE`, `_POSIX_C_SOURCE`), повертані значення, коди помилок та матриця безпеки `ATTRIBUTES` (`MT-Safe`, `AS-Safe`, `AC-Safe`).
   - Приклади: `printf(3)`, `malloc(3)`, `qsort(3)`, `dlopen(3)`, `pthread_create(3)`, `fopen(3)`.

4. **Розділ 4 — Спеціальні файли пристроїв (`Special Files / Devices`)**:
   - Вузли файлової системи в каталозі `/dev`, псевдопристрої ядра, сокети IPC, інтерфейси драйверів блокових та символьних пристроїв.
   - Специфікація: мажорні та мінорні номери пристроїв, специфічні запити системного виклику `ioctl(2)`, формат бінарних пакетів та поведінка при читанні/записі.
   - Приклади: `null(4)`, `zero(4)`, `random(4)`, `urandom(4)`, `tty(4)`, `console(4)`, `loop(4)`, `sd(4)`.

5. **Розділ 5 — Формати файлів та системні угоди (`File Formats`)**:
   - Структури текстових і бінарних конфігураційних файлів, системні таблиці ідентифікації, формати виконуваних файлів, дампів пам'яті та метаданих файлових систем.
   - Специфікація: граматика конфігураційних директив, формати полів, допустимі кодування, символи екранування, структури бінарних заголовків у форматі C.
   - Приклади: `passwd(5)`, `shadow(5)`, `fstab(5)`, `hosts(5)`, `crontab(5)`, `elf(5)`, `core(5)`, `systemd.unit(5)`.

6. **Розділ 6 — Ігри та візуальні програми (`Games and Demos`)**:
   - Інтерактивні консольні ігри, генератори тексту, анімації та скрінсейвери термінала.
   - Приклади: `fortune(6)`, `cowsay(6)`, `tetris(6)`, `factor(6)`.

7. **Розділ 7 — Огляди, конвенції та стандарти (`Overview, Conventions, Miscellaneous`)**:
   - Концептуальні огляди підсистем ядра, стандарти оформлення макропакетів (`man(7)`, `mdoc(7)`), мережеві протоколи, специфікації POSIX, моделі роботи з сигналами, сокетами, потоками та просторами імен.
   - Специфікація: загальна архітектура підсистеми, діаграми потоків даних, алгоритмічні конвенції, системні обмеження.
   - Приклади: `ip(7)`, `tcp(7)`, `udp(7)`, `unix(7)`, `socket(7)`, `signal(7)`, `pthreads(7)`, `epoll(7)`, `namespaces(7)`, `cgroups(7)`, `standards(7)`.

8. **Розділ 8 — Системне адміністрування та сервіси (`System Administration / Daemons`)**:
   - Команди керування операційною системою, призначені виключно або переважно для суперкористувача (`root`), системні демони, фонові служби та утиліти ініціалізації.
   - Специфікація: взаємодія з підсистемою init, права доступу (`CAP_SYS_ADMIN`), конфігураційні сокети, реакція на сигнали (`SIGHUP` для перечитування конфігурації).
   - Приклади: `systemd(8)`, `mount(8)`, `iptables(8)`, `fdisk(8)`, `sshd(8)`, `ip(8)`, `sysctl(8)`, `modprobe(8)`.

9. **Розділ 9 — Внутрішні процедури ядра (`Kernel Routines`)**:
   - Внутрішні API та структури ядра операційної системи, інтерфейси драйверів пристроїв, розподільники пам'яті ядра (`kmalloc`), механізми синхронізації (`spinlocks`).
   - Специфікація: активно підтримується в BSD-системах (FreeBSD, OpenBSD, NetBSD) та Illumos. У Linux документація ядра традиційно поширюється у форматі Sphinx/RST у сирцях ядра, проте системні макроси розпізнають цей розділ.

### Спеціалізовані та додаткові підрозділи

Для точної диференціації та запобігання колізіям імен використовуються буквені суфікси до номерів розділів:

- **Розділ `0p`**: Офіційні специфікації заголовкових файлів мови C стандарту POSIX.1 (IEEE Std 1003.1). Наприклад, `unistd.h(0p)`, `sys/socket.h(0p)`, `fcntl.h(0p)`.
- **Розділ `1p`**: Специфікації стандартних команд та утиліт стандарту POSIX.1. Наприклад, `sh(1p)`, `awk(1p)`, `sed(1p)`.
- **Розділ `3p`**: Офіційні специфікації бібліотечних функцій стандарту POSIX.1. Наприклад, `read(3p)`, `fork(3p)`, `pthread_mutex_lock(3p)`.
- **Розділ `3pm`**: Сторінки довідки модулів мови Perl (Perl Module). Наприклад, `CPAN(3pm)`, `Data::Dumper(3pm)`.
- **Розділ `3am`**: Документація модулів розширення інтерпретатора GNU Awk. Наприклад, `filefuncs(3am)`, `time(3am)`.
- **Розділи `1ssl`, `3ssl`, `5ssl`, `7ssl`**: Документація утиліт, API та конфігураційних файлів проекту OpenSSL / LibreSSL. Наприклад, `openssl-req(1ssl)`, `EVP_EncryptInit(3ssl)`, `x509v3_config(5ssl)`.
- **Розділи `3tcl`, `3tk`**: Функції бібліотек Tcl та інтерфейсного каркаса Tk.
- **Розділи `3ncurses`, `3form`, `3menu`**: Функції бібліотеки управління екранними формами ncurses.
- **Розділи `7d`, `9e`, `9f`, `9s`**: Розділи операційних систем сімейства Solaris/Illumos та BSD для структур даних драйверів (`9s`) та точок входу драйверів (`9e`).

## 2. Стандартна послідовність та вимоги до секцій документа

Стандарти POSIX та проект Linux `man-pages` вимагають суворого дотримання порядку слідування заголовків першого рівня (`.SH` або `.Sh`).

```
   ┌──────┬───────────────────────┬───────────────────────────────┐
   │  №   │ Назва секції          │ Призначення                   │
   ├──────┼───────────────────────┼───────────────────────────────┤
   │   1  │ NAME                  │ Назва та однорядковий опис    │
   │   2  │ LIBRARY               │ Назва бібліотеки (mdoc 2, 3)  │
   │   3  │ SYNOPSIS              │ Формальний контракт виклику   │
   │   4  │ CONFIGURATION         │ Параметри пристрою (4, 9)     │
   │   5  │ DESCRIPTION           │ Розгорнутий технічний опис    │
   │   6  │ OPTIONS               │ Прапорці командного рядка (1,8)│
   │   7  │ EXIT STATUS           │ Коди повернення процесу (1, 8)│
   │   8  │ RETURN VALUE          │ Результат функції (2, 3)      │
   │   9  │ ERRORS                │ Коди помилок errno (2, 3)     │
   │  10  │ ENVIRONMENT           │ Змінні оточення процесу       │
   │  11  │ FILES                 │ Конфігураційні шляхи          │
   │  12  │ ATTRIBUTES            │ Таблиця потокобезпеки C       │
   │  13  │ VERSIONS              │ Історія появи в ядрі / glibc  │
   │  14  │ STANDARDS             │ POSIX, ISO C, Linux-specific  │
   │  15  │ HISTORY               │ Генеалогія інтерфейсу         │
   │  16  │ NOTES                 │ Архітектурні нюанси           │
   │  17  │ CAVEATS / BUGS        │ Обмеження та дефекти          │
   │  18  │ EXAMPLES              │ Код або сценарії запуску      │
   │  19  │ AUTHORS / COLOPHON    │ Джерело пакету, супровідники  │
   │  20  │ SEE ALSO              │ Пов'язані сторінки довідки    │
   └──────┴───────────────────────┴───────────────────────────────┘
```

### Специфікація обов'язкових та додаткових секцій

1. **`NAME` (обов'язкова для всіх розділів)**:
   - Складається з єдиного рядка: список імен об'єктів через кому з пробілом, дефіс (`\-`), оточений одинарними пробілами, і стислий опис без крапки наприкінці.
   - Специфікований формат: `name, name2 \- short description of purpose`.
   - Критичність: утиліти `mandb` та `makewhatis` парсять цей рядок для генерації бази пошуку `whatis` та `apropos`. Порушення формату (відсутність дефіса, зайвий перенос рядка, спецсимволи шрифту в імені) призводить до випадання сторінки з пошукових індексів системи.
2. **`LIBRARY` (для розділів 2 та 3 у конвенції `mdoc`)**:
   - Вказує символічне ім'я та прапорець лінкування бібліотеки (наприклад, `.Lb libc`, `.Lb libpthread`, `.Lb libcrypto`).
3. **`SYNOPSIS` (обов'язкова для розділів 1, 2, 3, 8)**:
   - Для утиліт розділів 1 та 8: наводить повний синтаксис виклику з переліком підкоманд, опцій та позиційних параметрів.
   - Для викликів розділів 2 та 3: наводить директиви препроцесора `#include`, необхідні макроси тестування функціональності (`_GNU_SOURCE`), типи повернення, точні імена функцій та типи параметрів із кваліфікаторами `const` і `restrict`.
4. **`DESCRIPTION` (обов'язкова для всіх розділів)**:
   - Розгорнутий технічний опис функціоналу. Роз'яснює кожен прапорець, описує стан внутрішніх буферів, послідовність обробки запиту, побічні ефекти та зміну структур даних.
5. **`OPTIONS` (для розділів 1 та 8)**:
   - Алфавітний опис усіх прапорців командного рядка. Кожна опція описується через тегований параграф (`.TP` у `man` або `.It Fl` у `mdoc`), де зазначено як короткі (`-f`), так і довгі (`--file`) варіанти, їхні значення за замовчуванням та взаємовиключні обмеження.
6. **`EXIT STATUS` (для розділів 1 та 8)**:
   - Перелік числових кодів завершення процесу:
     - `0`: успішне завершення;
     - `1`: загальна помилка виконання або помилка вхідних даних;
     - `2`: синтаксична помилка командного рядка або невалідний прапорець;
     - `126`: команду знайдено, але файл не є виконуваним;
     - `127`: команду не знайдено у каталогах змінної `PATH`;
     - `128 + N`: процес завершено отриманням фатального сигналу номер `N` (наприклад, `137` = `128 + 9` при `SIGKILL`).
7. **`RETURN VALUE` (обов'язкова для розділів 2 та 3)**:
   - Чітко фіксує значення, яке повертає функція у разі успішного виконання: невід'ємне ціле число (дескриптор, кількість байтів), ненульовий вказівник або `0`.
   - Визначає значення помилки: `-1` для системних викликів, `NULL` для алокаторів, `EOF` для потокового вводу-виводу.
   - Фіксує, чи вимагає виклик попереднього обнулення `errno = 0` (актуально для функцій типу `getpriority(2)` або `strtol(3)`, де `-1` є легітимним успішним результатом).
8. **`ERRORS` (обов'язкова для розділів 2 та 3)**:
   - Алфавітний перелік усіх символьних констант `errno`, які може встановити цей виклик (`EACCES`, `EAGAIN`, `EBADF`, `EFAULT`, `EINTR`, `EINVAL`, `ENOMEM`, `ENOENT`, `EPERM`, `EPIPE`, `ERANGE`, `ETIMEDOUT`, `EWOULDBLOCK`). Для кожного коду наводиться вичерпний опис системної причини його виникнення.
9. **`ENVIRONMENT`**:
   - Перелік змінних середовища (`LANG`, `LC_ALL`, `PATH`, `TMPDIR`, `LD_PRELOAD`, `HOME`, `POSIXLY_CORRECT`), що модифікують поведінку програми, із зазначенням стандартних значень.
10. **`FILES`**:
    - Абсолютні шляхи до системних файлів конфігурації, сокетів IPC, баз даних або логів, які програма читає чи створює (`/etc/hosts`, `/var/run/utmp`, `~/.config/app/config.toml`).
11. **`ATTRIBUTES` (для розділу 3)**:
    - Стандартизована таблиця безпеки виконання в багатопотокових програмах та обробниках сигналів (`MT-Safe`, `AS-Safe`, `AC-Safe`).
12. **`VERSIONS` (для розділів 2 та 3)**:
    - Версія ядра Linux, у якій системний виклик став доступним, та версія бібліотеки `glibc`, починаючи з якої виклик отримав повноцінну обгортку C.
13. **`STANDARDS` (або `CONFORMING TO`)**:
    - Посилання на офіційні стандарти: POSIX.1-2001, POSIX.1-2008, POSIX.1-2024, ISO C99, C11, C17, C23, 4.3BSD, System V Release 4 (SVr4), або позначка `Linux-specific` чи `GNU extension`.
14. **`NOTES`**:
    - Архітектурні особливості реалізації, поведінка при виклику `fork(2)` чи `pthread_create(3)`, 32-бітні та 64-бітні розширення (`_FILE_OFFSET_BITS=64`, `time_t`).
15. **`CAVEATS` та `BUGS`**:
    - Відомі обмеження, дефекти реалізації, випадки невідповідності стандарту або крайові умови, де поведінка відхиляється від очікуваної.
16. **`EXAMPLE` / `EXAMPLES`**:
    - Повний мінімальний самодостатній приклад програми мовою C або скрипту оболонки, готовий до компіляції та запуску.
17. **`AUTHORS` / `COLOPHON`**:
    - Інформація про авторів програми, URL сирцевого репозиторію та інструкція щодо надсилання патчів до проекту `man-pages`.
18. **`SEE ALSO`**:
    - Список пов'язаних за змістом сторінок довідки через кому в алфавітному порядку із зазначенням номерів розділів у дужках у форматі `.BR name (sec)` або `.Xr name sec` (наприклад, `fcntl(2)`, `open(2)`, `socket(7)`).

## 3. Граматика та синтаксис секції SYNOPSIS

Секція `SYNOPSIS` є формальною специфікацією контракту виклику. Вона спирається на розширену форму Бекуса — Наура (EBNF) та конвенції командного рядка POSIX.

### Синтаксичні лексеми для утиліт командного рядка (Розділи 1 та 8)

```
   ┌─────────────────────────────────────────────────────────────┐
   │             СИНТАКСИЧНІ ЛЕКСЕМИ РОЗДІЛУ SYNOPSIS            │
   ├──────────────────┬─────────────────┬────────────────────────┤
   │ Елемент          │ Накреслення     │ Значення               │
   ├──────────────────┼─────────────────┼────────────────────────┤
   │ program_name     │ Жирний (bold)   │ Дослівна назва команди │
   │ -f, --flag       │ Жирний (bold)   │ Дослівний прапорець    │
   │ sub_command      │ Жирний (bold)   │ Дослівна підкоманда    │
   │ FILE, VAR, NUM   │ Курсив (italic) │ Заповнювач аргументу   │
   │ [ item ]         │ Звичайний       │ Опційний елемент       │
   │ { a | b }        │ Звичайний       │ Взаємовиключний вибір  │
   │ item...          │ Звичайний       │ Повторення 1+ разів    │
   │ [item...]        │ Звичайний       │ Повторення 0+ разів    │
   │ --               │ Жирний (bold)   │ Кінець обробки опцій   │
   │ -                │ Жирний (bold)   │ Позначення stdin/stdout│
   └──────────────────┴─────────────────┴────────────────────────┘
```

Правила синтаксичного зв'язування параметрів опцій:
- Якщо аргумент обов'язковий: `.BI \-o " " file` або `.BI \-\-output= file` рендериться як **`-o`** *file* або **`--output=`**_file_.
- Якщо аргумент опційний: `[\fB\-f\fR[\fINUM\fR]]` або `[\fB\-\-color\fR[=\fIWHEN\fR]]`.

### Синтаксичні лексеми для інтерфейсів мови C (Розділи 2 та 3)

Сигнатура C у секції `SYNOPSIS` зобов'язана точно передавати вимоги компіляції та лінкування:

```groff
.nf
.B #include <fcntl.h>
.B #include <unistd.h>
.PP
.BI "int open(const char *" pathname ", int " flags ");"
.BI "int open(const char *" pathname ", int " flags ", mode_t " mode ");"
.PP
.BI "ssize_t read(int " fd ", void " buf "[." count "], size_t " count ");"
.fi
```

Вимоги до макросів тестування функціональності (*Feature Test Macros*):
```groff
/* Feature Test Macro Requirements for glibc: */
#define _GNU_SOURCE         /* See feature_test_macros(7) */
#define _POSIX_C_SOURCE 200809L
#define _XOPEN_SOURCE 700
```

## 4. Реєстр структурних та візуальних макросів пакету man(7)

Пакет `man(7)` є класичним набором макросів UNIX System V та Seventh Edition Unix (V7), орієнтованим на пряме візуальне форматування.

### Пролог та колонтитули

- **`.TH TITLE SECTION [DATE [SOURCE [MANUAL]]]`**:
  - `TITLE`: Назва сторінки у верхньому регістрі (наприклад, `READ`, `SYSTEMD`);
  - `SECTION`: Номер розділу та підрозділу (`1`, `2`, `3p`, `8`);
  - `DATE`: Дата останньої зміни у форматі `YYYY-MM-DD` або `Month Year`;
  - `SOURCE`: Джерело/пакет програми (наприклад, `Linux man-pages 6.9.1`, `GNU coreutils 9.5`);
  - `MANUAL`: Загальна назва книги довідника (наприклад, `Linux Programmer's Manual`, `System Administration Commands`).

### Секції та абзаци

- **`.SH [НАЗВА]`**: Заголовок секції першого рівня (*Section Heading*). Рендериться жирним шрифтом без відступу.
- **`.SS [НАЗВА]`**: Підзаголовок другого рівня (*Subsection Heading*). Рендериться з невеликим лівим відступом.
- **`.P` / `.PP` / `.LP`**: Початок нового стандартного параграфа з вертикальним відступом.
- **`.TP [відступ]`**: Тегований параграф (*Tagged Paragraph*). Наступний фізичний рядок є тегом (рендериться з нульовим відступом), а рядки після нього — тілом опису з відступом за замовчуванням (7n) або вказаним числовим значенням.
- **`.IP [маркер [відступ]]`**: Параграф з індивідуальним відступом та опційним маркером списку (булет або цифра).
- **`.HP [відступ]`**: Параграф із висячим відступом (*Hanging Paragraph*). Перший рядок починається з краю, всі наступні зміщені вправо.
- **`.RS [відступ]` / `.RE [рівень]`**: Зсув лівого поля вправо (*Relative Start*) та повернення попереднього рівня відступу (*Relative End*).

### Шрифтові та чергувальні макроси

- **`.B [текст...]`**: Встановлює жирний шрифт (*Bold*) для всіх переданих слів.
- **`.I [текст...]`**: Встановлює курсивне накреслення (*Italic* / *Underline*).
- **`.SM [текст...]`**: Зменшує розмір шрифту (*Small*).
- **`.SB [текст...]`**: Зменшений жирний шрифт (*Small Bold*).
- **`.BR b_word r_word ...`**: Чергує жирний (*Bold*) та звичайний романський (*Roman*) шрифт. Стандарт для посилань виду `.BR read (2)`.
- **`.BI b_word i_word ...`**: Чергує жирний шрифт і курсив. Стандарт для опцій із параметрами: `.BI -f " FILE"`.
- **`.IB i_word b_word ...`**: Чергує курсив і жирний шрифт.
- **`.IR i_word r_word ...`**: Чергує курсив і звичайний шрифт: `.IR count );`.
- **`.RB r_word b_word ...`**: Чергує звичайний шрифт і жирний.
- **`.RI r_word i_word ...`**: Чергує звичайний шрифт і курсив.

### Блоки коду, форматування та екранування

- **`.EX` / `.EE`**: Блок прикладу (*Example Start* / *Example End*). Вимикає вирівнювання і перенос слів (`.nf`), встановлює моноширинний шрифт константного розміру, а макрос `.EE` відновлює звичайний режим (`.fi`).
- **`.nf` / `.fi`**: Базові директиви roff: *no-fill* (вимкнути автоперенос і злиття рядків) та *fill* (увімкнути нормальну верстку абзацу).
- **`.\"`**: Коментар. Усе, що йде після `.\"` до кінця фізичного рядка, ігнорується форматерами.
- **Керуючі спецсимволи roff**:
  - `\-`: Справжній типографічний мінус / дефіс (ASCII 0x2D). Використовується для всіх прапорців командного рядка (`\-v`), запобігаючи автоматичній заміні форматерами на Unicode hyphen чи довге тире;
  - `\e`: Друк зворотного слеша `\`;
  - `\(aq`: Нейтральний одинарний апостроф `'` (ASCII 0x27) без перетворення на відкриваючу типографічну лапку;
  - `\(dq`: Нейтральні подвійні лапки `"`;
  - `\ `: Нерозривний фіксований пробіл;
  - `\&`: Символ нульової ширини (*zero-width space*). Запобігає інтерпретації крапки `.` або апострофа `'` на початку рядка як команди roff;
  - `\(bu`: Маркер маркованого списку (*bullet*);
  - `\(em`: Довге тире (*em-dash*);
  - `\fB`, `\fI`, `\fR`, `\fP`: Інлайн-перемикання шрифтів (Bold, Italic, Roman, Previous);
  - `\c`: З'єднання рядків без внесення додаткового пробілу чи розриву (*continuation*).

## 5. Низькорівневий синтаксис roff: умови, регістри та змінні

Для побудови адаптивної верстки, сумісної одночасно з різними драйверами виводу (термінал `nroff`, графічний друк `troff` / `groff`, транслятор `mandoc`), мова roff надає повноцінний апарат числових регістрів, рядкових змінних, умовних переходів та макроозначень.

### Числові регістри (Number Registers)

Числові регістри зберігають цілочисельні значення та використовуються для розрахунку відступів, лічильників, розмірів шрифтів та перевірки стану форматера.

- **`.nr REG [+-]VAL [STEP]`**:
  - Присвоює числовому регістру `REG` значення `VAL`.
  - Якщо перед значенням стоїть знак `+` або `-`, поточне значення регістру збільшується або зменшується на `VAL` (`.nr my_indent +2n`).
  - Опційний третій аргумент `STEP` задає крок автоінкременту/автодекременту.
- **Синтаксис інтерполяції регістрів у тексті**:
  - `\nx`: значення односимвольного регістру `x`;
  - `\n(xx`: значення двосимвольного регістру `xx`;
  - `\n[NAME]`: значення багатосимвольного регістру `NAME` (розширення GNU roff / Heirloom);
  - `\n+[REG]` / `\n-[REG]`: автоінкремент або автодекремент регістру на крок `STEP` із поверненням нового значення.
- **`.rr REG`**: Видалення (скидання) числового регістру `REG`.

#### Реєстр системних вбудованих регістрів roff

```
   ┌───────────────────┬─────────────────────────────────────────────────────────┐
   │ Регістр           │ Семантичне значення та стан форматера                   │
   ├───────────────────┼─────────────────────────────────────────────────────────┤
   │ \n(.g             │ 1 у середовищі GNU roff (groff); невизначений / 0       │
   │                   │ у класичному AT&T troff, heirloom troff та mandoc       │
   │ \n(.T             │ 1, якщо задано вивідний пристрій (\*[.T] повертає назву)│
   │ \n(.m             │ Ім'я поточного завантаженого макропакета (an, doc)      │
   │ \n(.A             │ 1 у groff при роботі генератора ASCII/термінального коду│
   │ \n(.C             │ 1, якщо увімкнено режим сумісності з AT&T troff (-C)   │
   │ \n(.f             │ Числовий індекс поточного шрифту (1=R, 2=I, 3=B, 4=BI)  │
   │ \n(.s             │ Поточний розмір шрифту в типографічних пунктах (кегль)  │
   │ \n(.v             │ Поточний інтерліньяж (vertical spacing / leading)       │
   │ \n(.l             │ Поточна ширина рядка виводу (line length, замовч. 78n)  │
   │ \n(.i             │ Поточний рівень лівого відступу (indentation)           │
   │ \n(.u             │ 1, якщо увімкнено вирівнювання за обома краями (fill)   │
   │ \n(.j             │ Режим вирівнювання: 0=ragged, 1=right, 3=both, 5=center │
   │ \n(.d             │ Поточна вертикальна позиція у диверсії                  │
   │ \n(.t             │ Відстань до найближчої пастки сторінки (trap)           │
   │ \n(.z             │ Ім'я поточної активної диверсії                         │
   │ \n(.c / \n(c.     │ Номер поточного фізичного вхідного рядка                │
   │ \n(.F             │ Ім'я поточного вхідного файлу                           │
   │ \n(%              │ Номер поточної сторінки виводу                          │
   │ \n($              │ Кількість позиційних аргументів, переданих макросу      │
   │ \n(yr             │ Поточний рік мінус 1900 (наприклад, 126 для 2026 року)  │
   │ \n(mo             │ Поточний місяць року (1–12)                             │
   │ \n(dy             │ Поточний день місяця (1–31)                             │
   │ \n(dw             │ День тижня (1 = неділя, 2 = понеділок ... 7 = субота)   │
   │ \n(.H             │ Горизонтальна роздільна здатність базових одиниць       │
   │ \n(.V             │ Вертикальна роздільна здатність базових одиниць         │
   └───────────────────┴─────────────────────────────────────────────────────────┘
```

### Умовні конструкції: `.if`, `.ie`, `.el`

Оператори розгалуження керують умовним виконанням команд і підстановкою фрагментів розмітки залежно від вивідного пристрою або версії форматера.

- **`.if COND ACTION`**: Односторонній умовний оператор. Якщо умова `COND` істинна, виконується інструкція `ACTION`.
- **`.ie COND TRUE_ACTION`** та **`.el FALSE_ACTION`**: Двосторонній умовний оператор (*if-then-else*). Макрос `.ie` (*if-else*) обробляє позитивну гілку, а наступний пов'язаний макрос `.el` (*else*) — негативну гілку.
- **Групування багаторядкових блоків дій (`\{` та `\}`)**:
  - Відкриваюча дужка `\{` зобов'язана стояти в кінці рядка після зворотного слеша `\`.
  - Закриваюча дужка `\}` зобов'язана починатися з нового рядка після крапки `.` або управляючого апострофа:
  ```groff
  .ie \n(.g \{\
  .  \" Код, специфічний для GNU roff
  .  fam C
  .  ps -1
  .\}
  .el \{\
  .  \" Код для класичного troff / mandoc
  .  ft CW
  .\}
  ```

#### Специфікація вбудованих умовних предикатів

1. **Тип цільового пристрою виводу**:
   - `t`: Істинно, якщо документ компілюється для друкарського пристрою високої роздільної здатності (*typesetter* / PostScript / PDF / `troff`).
   - `n`: Істинно, якщо документ компілюється для моноширинного термінала чи лінійного принтера (`nroff` / `grotty`).
2. **Паритет сторінки**:
   - `e`: Істинно на парних сторінках (*even page*).
   - `o`: Істинно на непарних сторінках (*odd page*).
3. **Визначеність макросів, рядків та регістрів**:
   - `d NAME`: Істинно, якщо макрос, рядок чи диверсія `NAME` визначені в середовищі.
   - `r REG`: Істинно, якщо числовий регістр `REG` існує та ініціалізований.
   - `c CH`: Істинно, якщо символ або гліф `CH` доступний у поточному завантаженому шрифті.
4. **Порівняння рядків**:
   - `'STR1'STR2'`: Істинно, якщо текстові рядки `STR1` та `STR2` після інтерполяції змінних посимвольно ідентичні. Як обмежувачі замість апострофа дозволено використовувати будь-який унікальний символ, відсутній усередині рядків (наприклад, `!STR1!STR2!`).
5. **Розширені перевірки GNU roff**:
   - `\B'EXPR'`: Істинно, якщо вираз всередині обмежувачів є синтаксично валідним числовим виразом.
   - `\A'STR'`: Істинно, якщо рядок містить виключно валідні символи ідентифікаторів roff (літери, цифри, підкреслення).
   - `\V'ENV_VAR'`: Інтерполює значення системної змінної середовища операційної системи.
6. **Числові умови та логічні оператори**:
   - Будь-який числовий вираз `EXPR > 0` трактується як істина.
   - Оператори порівняння: `==` (або `=`), `!=`, `<`, `>`, `<=`, `>=`.
   - Логічні зв'язки: `&` (кон'юнкція / AND), `:` (диз'юнкція / OR), ведучий `!` (заперечення / NOT).
   - Приклад комплексної перевірки детектора GNU roff:
     ```groff
     .if !\n(.g .tm Попередження: компіляція вимагає середовища GNU groff!
     .if \n(.g&'\*[.T]'utf8' .tm Форматування для термінала з кодуванням UTF-8
     ```

### Рядкові змінні, макроозначення та аліаси

- **`.ds NAME STRING`**: Оголошення рядкової змінної `NAME`. Інтерполюється як `\*[NAME]`, `\*(xx` або `\*x`.
- **`.as NAME STRING`**: Дописування рядка `STRING` у кінець існуючої рядкової змінної `NAME` (*append string*).
- **`.de NAME [END_MACRO]`**: Визначення власного макросу `NAME`. Тіло макросу записується з наступних рядків і завершується директивою `..` (або `.END_MACRO` за умови явного завдання мітки завершення).
  - Позиційні аргументи всередині макросу інтерполюються як `\\$1`, `\\$2`, ..., `\\$9`.
  - Змінна `\\$*` інтерполює всі передані аргументи через пробіл.
  - Змінна `\\$@` інтерполює аргументи з індивідуальним взяттям у лапки.
- **`.am NAME [END_MACRO]`**: Дописування інструкцій у кінець існуючого макросу (*append macro*).
- **`.als NEW_NAME OLD_NAME`**: Створення синоніму (аліасу) для макросу, рядка або диверсії.
- **`.rn OLD_NAME NEW_NAME`**: Перейменування макросу або рядка.
- **`.rm NAME`**: Повне видалення визначення макросу чи рядка з пам'яті форматера.
- **`.do CMD`**: Виконання команди `CMD` у просторі імен GNU groff навіть за умови активації режиму сумісності з класичним troff (`-C`).

## 6. Реєстр семантичних макросів пакету mdoc(7)

Пакет `mdoc(7)` (розроблений для BSD) спирається на семантичну типізацію сутностей: замість інструкцій накреслення вказується природа кожного токена.

### Пролог документа

- **`.Dd Month Day, Year`**: Дата останньої ревізії документа (наприклад, `.Dd August 29, 2026`).
- **`.Dt TITLE SECTION [ARCH]`**: Заголовок сторінки у верхньому регістрі, номер розділу та необов'язкова цільова архітектура (наприклад, `.Dt READ 2`, `.Dt OPEN 2 amd64`).
- **`.Os [SYSTEM [VERSION]]`**: Операційна система (наприклад, `.Os OpenBSD 7.5`, `.Os FreeBSD 14.0`, `.Os Linux`).

### Структурні секції

- **`.Sh SECTION`**: Секція першого рівня (`.Sh NAME`, `.Sh LIBRARY`, `.Sh SYNOPSIS`, `.Sh DESCRIPTION`, `.Sh ERRORS`, `.Sh SEE ALSO`).
- **`.Ss SUBSECTION`**: Підсекція другого рівня.

### Семантичні макроси інтерфейсу командного рядка

- **`.Nm [ім'я]`**: Ім'я утиліти або команди. Якщо викликано в секції `NAME`, фіксує головне ім'я документа; якщо викликано пізніше без аргументів, автоматично вставляє зафіксоване ім'я.
- **`.Nd summary`**: Короткий опис у секції `NAME` (рендериться після тире).
- **`.Fl flag`**: Прапорець опції командного рядка. Автоматично додає ведучий дефіс (`.Fl l` рендериться як `-l`). Допускає комбінування та ланцюжки: `.Fl a Fl b` або `.Fl abc`.
- **`.Ar [arg...]`**: Змінний аргумент користувача (рендериться курсивом). Якщо викликано без аргументів, підставляє стандартне `file ...`.
- **`.Cm command`**: Інтерактивна команда, підкоманда або модифікатор (`.Cm commit`, `.Cm status`).
- **`.Op args...`**: Обгортає всі аргументи у квадратні дужки, позначаючи необов'язковість (`.Op Fl v Ar file` → `[-v file]`).
- **`.Oo` / `.Oc`**: Багаторядковий блок опційності (*Option Open* / *Option Close*).
- **`.Ic command`**: Внутрішня інтерактивна команда оболонки (`.Ic cd`, `.Ic exit`).

### Семантичні макроси мови C та API

- **`.Ft type`**: Тип даних або тип результату функції C (`.Ft ssize_t`).
- **`.Fn name [arg ...]`**: Оголошення або виклик функції C (`.Fn read "int fd" "void *buf" "size_t count"`).
- **`.Fo name` / `.Fc`**: Багаторядкове оголошення складної сигнатури функції (*Function Open* / *Function Close*). Аргументи всередині блоку позначаються макросом `.Fa`.
- **`.Fa argument`**: Окремий параметр функції всередині блоку `.Fo`/`.Fc` або в тексті опису.
- **`.Va variable`**: Змінна програми або поле структури (`.Va errno`, `.Va tv_sec`).
- **`.Vt type`**: Оголошення типу даних або структури (`.Vt struct stat`, `.Vt size_t`).
- **`.Er ERROR`**: Символьний код системної помилки `errno` (`.Er EINTR`, `.Er EBADF`, `.Er ENOMEM`).
- **`.Dv CONSTANT`**: Константа препроцесора, макрос або бітова маска (`.Dv O_NONBLOCK`, `.Dv NULL`, `.Dv AF_INET`).
- **`.In header.h`**: Заголовковий файл мови C (у `SYNOPSIS` автоматично генерує `#include <header.h>`).
- **`.Fd "#define ..."`**: Пряма директива препроцесора.
- **`.Lb library`**: Символічне ім'я системної бібліотеки в секції `LIBRARY` (`.Lb libc`, `.Lb libpthread`).

### Системні сутності та гіперпосилання

- **`.Pa path`**: Шлях до файлу або каталогу в файловій системі (`.Pa /etc/passwd`, `.Pa /dev/null`).
- **`.Ev VARIABLE`**: Змінна середовища (`.Ev PATH`, `.Ev MANPATH`, `.Ev LC_ALL`).
- **`.Xr name section`**: Крос-посилання на іншу сторінку довідки (`.Xr write 2`). Автоматично формує зв'язку `write(2)`.
- **`.Lk url [link_text]`**: Гіперпосилання URL.
- **`.Mt email`**: Адреса електронної пошти.
- **`.Ms name`**: Математичний символ або оператор.
- **`.An author`**: Ім'я автора в секції `AUTHORS`.
- **`.Cd config`**: Директива конфігурації ядра (для розділів 4 та 9).
- **`.Sy symbol`**: Символічний текст, що виділяється жирним накресленням.

### Блоки виводу та списки mdoc

- **`.Bd` / `.Ed`**: Блок буквального або форматованого відображення (*Block Display* / *End Display*).
  - Режими:
    - `-literal`: моноширинний шрифт без перенесення слів (ідеально для коду C);
    - `-ragged`: текст без вирівнювання правого краю;
    - `-filled`: стандартний вирівняний абзац;
    - `-unfilled`: збереження розривів рядків зі стандартним шрифтом;
    - `-offset indent`: зсув блоку вправо (`-offset indent`, `-offset 4n`).
- **`.Dl`**: Однорядковий буквальний лістинг із відступом (*Display Literal*).
- **`.Bl` / `.El`**: Блок списку (*Block List* / *End List*).
  - Специфікатори списків:
    - `-tag -width Ds`: тегований список (аналог `.TP`), де опція `-width` задає зразок ширини тегу (`Ds` — 6 символів, або текстовий шаблон `-width "--output=FILE"`);
    - `-bullet`: маркований список;
    - `-enum`: автоматично нумерований список;
    - `-column "col1" "col2"`: табличний багатостовпчиковий список;
    - `-dash` / `-hyphen`: список із тире;
    - `-item`: параграфи з відступом без маркерів;
    - `-compact`: придушення додаткових вертикальних інтервалів між елементами.
- **`.It`**: Елемент списку всередині блоку `.Bl`.

### Правила синтаксичного аналізу розділових знаків у mdoc

Макроси в `mdoc` поділяються на *callable* (можуть бути викликані як аргументи інших макросів) та *parsed* (парсять свої аргументи). Якщо останнім аргументом макросу є розділовий знак (`.`, `,`, `;`, `:`, `(`, `)`, `[`, `]`, `?`, `!`), парсер `mdoc` автоматично приєднує його до попереднього слова без пробілу:

```groff
.Xr read 2 ,
.Xr write 2 ,
.Xr close 2 .
```
Рендериться як: `read(2), write(2), close(2).`

## 8. Специфікація препроцесорів roff: tbl, eqn, pic

Препроцесори `roff` трансформують спеціалізовані блоки розмітки у низькорівневі інструкції позиціонування та графічні примітиви до основного проходу форматера.

```
   Вхідний .roff файл
         │
         ▼
   ┌───────────┐
   │ preconv   │  Трансляція кодувань (UTF-8 → \[uXXXX])
   └─────┬─────┘
         │
         ▼
   ┌───────────┐
   │   pic     │  Векторна графіка (.PS / .PE)
   └─────┬─────┘
         │
         ▼
   ┌───────────┐
   │   tbl     │  Таблиці та матриці (.TS / .TE)
   └─────┬─────┘
         │
         ▼
   ┌───────────┐
   │   eqn     │  Математичні формули (.EQ / .EN)
   └─────┬─────┘
         │
         ▼
   ┌───────────┐
   │   troff   │  Верстка та генерація проміжного коду
   └─────┬─────┘
         │
         ▼
   ┌───────────┐
   │  grotty   │  Драйвер терміналу (ANSI escape codes)
   └───────────┘
```

### 1. Препроцесор таблиць tbl(1)

Препроцесор `tbl` компілює таблиці зі складними правилами вирівнювання, багаторядковими текстовими блоками та координатними сітками.

#### Структура блоку tbl

```groff
.TS
опція_1 опція_2;
специфікація_формату_рядок_1
специфікація_формату_рядок_2.
дані	клітинки	розділені_табуляцією
ще_дані	T{
Багаторядковий текстовий блок
T}	значення
.TE
```

#### Глобальні опції (Global Options)

Рядок опцій слідує одразу за макросом `.TS` і обов'язково завершується крапкою з комою `;`:
- **`center`**: Центрувати всю таблицю по ширині вивідного аркуша / термінала;
- **`expand`**: Рівномірно розтягнути ширину колонок на всю доступну ширину рядка (`\n(.l`);
- **`box`**: Оточити таблицю одинарною зовнішньою рамкою;
- **`doublebox`**: Оточити таблицю подвійною зовнішньою рамкою;
- **`allbox`**: Побудувати одинарну рамку навколо кожної окремої клітинки таблиці;
- **`tab(c)`**: Встановити символ `c` як роздільник стовпчиків у вхідних даних (за замовчуванням символ табуляції `\t`);
- **`linesize(n)`**: Встановити товщину ліній рамки у `n` пунктів;
- **`delim(xy)`**: Встановити символи `x` та `y` як обмежувачі формул препроцесора `eqn` всередині клітинок;
- **`nokeep`**: Вимкнути автоматичне утримання таблиці на одній сторінці (дозволяє розрив сторінки);
- **`nospaces`**: Ігнорувати ведучі та замикаючі пробіли навколо даних клітинок.

#### Специфікація форматного рядка (Format Specification)

Форматний рядок визначає тип вирівнювання кожної шпальти. Останній рядок формату обов'язково завершується крапкою `.`. Якщо кількість рядків даних перевищує кількість форматних рядків, останній форматний рядок застосовується до всіх наступних рядків автоматично.

##### Ключові літери вирівнювання шпальт:
- **`l` / `L`**: Вирівнювання по лівому краю (*Left-aligned*);
- **`r` / `R`**: Вирівнювання по правому краю (*Right-aligned*);
- **`c` / `C`**: Центрування тексту в шпальті (*Centered*);
- **`n` / `N`**: Числове вирівнювання (*Numeric*). Числа вирівнюються за позицією десяткової крапки чи коми;
- **`a` / `A`**: Алфавітне підвирівнювання. Найдовший рядок центрується, решта вирівнюється за його лівим краєм;
- **`s` / `S`**: Горизонтальне об'єднання (*Span*). Клітинка розширюється на місце сусідньої шпальти зліва;
- **`^`**: Вертикальне об'єднання (*Vertical span*). Клітинка об'єднується з клітинкою з рядка вище;
- **`_`** або **`-`**: Горизонтальна одинарна лінія всередині клітинки;
- **`=`**: Горизонтальна подвійна лінія всередині клітинки;
- **`|`**: Вертикальна одинарна розділова лінія між шпальтами;
- **`||`**: Вертикальна подвійна розділова лінія між шпальтами.

##### Модифікатори параметрів шпальт:
- **`f` / `B` / `I` / `R` / `CW`**: Встановлення накреслення шрифту для стовпчика (наприклад, `cB` — центрування жирним);
- **`p+n` / `p-n` / `m+n` / `m-n`**: Зміна розміру шрифту (кегля) для стовпчика;
- **`v+n` / `v-n`**: Зміна інтерліньяжу для стовпчика;
- **`w(N)`**: Фіксація мінімальної ширини шпальти (наприклад, `lw(2.5i)` або `lw(20n)`);
- **`e` / `E`**: Рівна ширина (*Equal width*). Усі шпальти з модифікатором `e` отримають однакову максимальну ширину;
- **`u` / `U`**: Підкреслення тексту в клітинках шпальти;
- **`z` / `Z`**: Нульова ширина при розрахунку загальної геометрії таблиці;
- **`d` / `D`**: Вертикальне вирівнювання текстового блоку по нижньому краю клітинки (*bottom align*);
- **Числові інтервали (1–9)**: Додатковий горизонтальний проміжок між шпальтами (наприклад, `c3 c5 r.` задає 3 пробіли після першої та 5 після другої колонки).

#### Синтаксис даних та блоків тексту

- **Стовпчики даних**: Розділяються символом табуляції `\t` (або символом із `tab(c)`).
- **Багаторядкові текстові блоки (`T{` ... `T}`)**:
  ```groff
  Функція	T{
  Розгорнутий опис алгоритму, який займає
  декілька рядків і автоматично форматується
  за шириною стовпчика.
  T}	MT-Safe
  ```
- **Горизонтальні розділові лінії в даних**:
  - `_`: Одинарна лінія на всю ширину таблиці;
  - `=`: Подвійна лінія на всю ширину таблиці;
  - `\_`: Одинарна лінія лише в межах поточної клітинки;
  - `\=`: Подвійна лінія лише в межах поточної клітинки.
- **Спеціальні маркери клітинок**:
  - `\^`: Вертикальне продовження клітинки зверху;
  - `\Rx`: Заповнення клітинки повторюваним символом `x`.
- **Зміна формату посеред таблиці (`.T&`)**:
  Дозволяє змінити правила форматування для наступних рядків даних без закриття блоку `.TE`:
  ```groff
  .TS
  center box;
  cB cB cB.
  Код	Статус	Опис
  _
  .T&
  n l l.
  200	OK	Успішний запит
  404	Not Found	Ресурс відсутній
  .TE
  ```

### 2. Препроцесор математичних виразів eqn(1)

Препроцесор `eqn` компілює математичні формули, інтеграли, матриці та дроби у векторну графіку або термінальні текстові наближення.

#### Оголошення роздільників та інлайн-математика

- **Блок формули**: Виділяється макросами `.EQ [мітка]` та `.EN`. Опційна мітка вирівнюється по правому краю сторінки.
- **Інлайн-розділювачі**: Оголошуються директивою `delim $$` (або `delim @@`, вимикаються через `delim off`), що дозволяє вставляти формули безпосередньо в абзаци:
  ```groff
  .EQ
  delim $$
  .EN
  Складність алгоритму оцінюється як $O(N log N)$.
  ```
- **Макроси визначень**:
  ```groff
  define sqr 'sup 2'
  tdefine sqr 'sup 2'  \" Визначення виключно для troff
  ndefine sqr '^2'     \" Визначення виключно для nroff
  ```

#### Реєстр синтаксичних операторів eqn

```
   ┌───────────────────────────┬───────────────────────────────┬───────────────────────────┐
   │ Синтаксис eqn             │ Призначення                   │ Приклад рендерингу        │
   ├───────────────────────────┼───────────────────────────────┼───────────────────────────┤
   │ a over b                  │ Звичайний дріб                │ a / b                     │
   │ sqrt x                    │ Квадратний корінь             │ √x                        │
   │ a sub i                   │ Нижній індекс (subscript)     │ aᵢ                        │
   │ a sup 2                   │ Верхній індекс (superscript)  │ a²                        │
   │ a sub i sup 2             │ Одночасний індекс і степінь   │ aᵢ²                       │
   │ sum from {i=0} to n       │ Сума з межами                 │ ∑ᵢ₌₀ⁿ                     │
   │ int from 0 to inf         │ Інтеграл з межами             │ ∫₀^∞                      │
   │ prod from 1 to k          │ Добуток з межами              │ ∏₁^k                      │
```

### 3. Препроцесор векторної графіки pic(1)

Препроцесор `pic` трансформує описову геометрію блоків, стрілок, кіл та з'єднань у векторні фігури мови `troff` або ASCII-схеми.

#### Структура блоку pic

```groff
.PS [ширина [висота]]
scale = 2.54  \" Масштабування: одиниці вимірювання в сантиметрах
box "User Space"
arrow "syscall" above
box "Kernel Space"
.PE
```

#### Базові графічні примітиви

- **`box [текст...]`**: Прямокутник. Атрибути: `wid n` (ширина), `ht n` (висота), `rad n` (радіус скруглення кутів), `dashed [n]`, `dotted [n]`, `fill [n]` (рівень сірої заливки від 0.0 до 1.0), `invis` (невидимий).
- **`circle [текст...]`**: Коло. Атрибути: `rad n` (радіус), `diam n` (діаметр).
- **`ellipse [текст...]`**: Еліпс. Атрибути: `wid n` (горизонтальна вісь), `ht n` (вертикальна вісь).
- **`arc [текст...]`**: Дуга кола. Атрибути: `rad n`, `cw` (за годинниковою стрілкою), `ccw` (проти годинникової стрілки), `from point to point`.
- **`line [текст...]`**: Пряма лінія. Атрибути: `from point to point`, `right n`, `left n`, `up n`, `down n`, `thick n` (товщина лінії), `chop [n]` (обрізання кінців).
- **`arrow [текст...]`**: Лінія зі стрілкою на кінці. Атрибути: `<-`, `->`, `<->`, `wid n` (ширина наконечника), `ht n` (довжина наконечника).
- **`spline [текст...]`**: Згладжена крива лінія (сплайн) через опорні точки.
- **`move [n]`**: Невидиме переміщення поточної точки малювання у вказаному напрямку.
- **`"Текст"`**: Розміщення текстового напису. Атрибути вирівнювання: `ljust` (по лівому краю), `rjust` (по правому краю), `above`, `below`.
- **`[ ... ]`**: Композитний блок. Групує декілька фігур у єдиний ізольований складений об'єкт із власною системою координат.

#### Геометричні прив'язки (Compass Anchors) та відносне позиціонування

Кожен графічний об'єкт у `pic` має стандартизовані прив'язні точки компаса:
- `.c` (Center / центр);
- `.n`, `.s`, `.e`, `.w` (North, South, East, West — верх, низ, праворуч, ліворуч);
- `.ne`, `.se`, `.nw`, `.sw` (Кутові точки фігури);
- `.start`, `.end` (Початкова та кінцева точка лінії чи стрілки).

##### Посилання на створені об'єкти:
- За міткою: `Proc: box "Process"`; `arrow from Proc.e to Net.w`;
- За порядком створення: `last box`, `2nd last circle`, `1st line`;
- Позиціонування за якорем: `box with .nw at last box.se + (0.5, -0.2)`.

#### Приклад діаграми системного виклику в pic

```groff
.PS
boxwid = 1.6; boxht = 0.6; circlerad = 0.3
U: box "User Process" "\fI(read(2))\fR"
arrow "syscall" above "trap" below from U.s down 0.5
K: box "Kernel VFS" "\fI(sys_read)\fR"
arrow "lookup" above from K.e right 0.8
D: box "Device Driver" "\fI(ext4_file_read)\fR"
arrow from D.s down 0.5
H: box "Hardware" "Storage Controller"
.PE
```

## 10. Локалізація man-сторінок та конвенції кодування

Підсистема локалізації довідки забезпечує відображення сторінок рідною мовою користувача з урахуванням мовних конвенцій, правил сортування та коректного кодування символів.

### Ієрархія каталогів та файлова структура локалізації

Локалізовані сторінки розміщуються у підкаталогах системного сховища `/usr/share/man/` (або `/usr/local/share/man/`), назви яких відповідають стандарту мовних тегів POSIX / ISO:

```
/usr/share/man/
├── man1/                    # Системна англійська мова за замовчуванням (C / POSIX)
│   ├── ls.1.gz
│   └── read.2.gz
├── uk/                      # Загальна українська локаль (без прив'язки до кодування)
│   ├── man1/
│   │   └── ls.1.gz
│   └── man2/
├── uk_UA/                   # Мова та територія (Україна)
│   └── man1/
├── uk_UA.UTF-8/             # Повна канонічна назва локалі з явним кодуванням
│   ├── man1/
│   │   └── ls.1.gz
│   └── man5/
├── de/                      # Німецька локаль
├── fr.UTF-8/                # Французька локаль
└── ja/                      # Японська локаль
```

#### Алгоритм резолюції мовних каталогів утилітою man

Під час запиту сторінки `man <name>` утиліта формує ланцюжок пошуку каталогів відповідно до встановлених змінних середовища:
1. `/usr/share/man/<ll_CC.encoding>/manN/<name>.N` (наприклад, `/usr/share/man/uk_UA.UTF-8/man1/ls.1.gz`);
2. `/usr/share/man/<ll_CC>/manN/<name>.N` (наприклад, `/usr/share/man/uk_UA/man1/ls.1.gz`);
3. `/usr/share/man/<ll>/manN/<name>.N` (наприклад, `/usr/share/man/uk/man1/ls.1.gz`);
4. `/usr/share/man/manN/<name>.N` (канонічна версія сторінки за замовчуванням).

### Кодування символів: сучасний стандарт UTF-8 проти застарілих наборів

1. **Історичний спадок (Legacy Encodings)**:
   - До впровадження стандарту Unicode різні мовні групи використовували однобайтові та багатобайтові незалежні кодування:
     - Західна Європа: `ISO-8859-1` (Latin-1), `ISO-8859-15`;
     - Центральна та Східна Європа: `ISO-8859-2` (Latin-2);
     - Кирилиця: `KOI8-U` (Україна), `KOI8-R` (Cyrillic), `ISO-8859-5`, `Windows-1251`;
     - Східна Азія: `EUC-JP`, `Shift-JIS` (Японія), `EUC-KR` (Корея), `Big5`, `GB2312` (Китай).
   - *Проблема застарілих кодувань у roff*: Рушій `troff` історично проектувався під 7-бітний ASCII. Символи з 8-м встановленим бітом або багатобайтові UTF-8 послідовності сприймалися форматерами як розділові керуючі байти, викликаючи артефакти верстки, розрив слів та некоректний підрахунок довжини рядка (`\n(.l`).

2. **Сучасна уніфікація UTF-8**:
   - Усі сучасні дистрибутиви Linux (Debian, Ubuntu, Fedora, Arch, Alpine) та системи BSD вимагають збереження сирцевих man-файлів виключно у кодуванні **UTF-8 без BOM** (*Byte Order Mark*).

### Конвеєр перекодування та препроцесор preconv(1)

Для прозорої трансляції UTF-8 та національних кодувань у внутрішні безпечні сутності `roff` використовується препроцесор `preconv(1)`:

- `preconv` сканує вхідний файл і замінює всі не-ASCII гліфи на 4-значні шістнадцяткові escaped-сутності groff виду `\[uXXXX]`. Наприклад:
  - Літера `і` (U+0456) транслюється у `\[u0456]`;
  - Літера `ї` (U+0457) транслюється у `\[u0457]`;
  - Літера `є` (U+0454) транслюється у `\[u0454]`;
  - Літера `ґ` (U+0491) транслюється у `\[u0491]`.
- **Автовизначення кодування в preconv**:
  1. Заголовок Emacs/Vim у першому або другому рядку файлу:
     ```groff
     .\" -*- mode: troff; coding: utf-8 -*-
     ```
  2. Перший рядок директиви препроцесорів `roff`:
     ```groff
     '\" t k
     ```
     (Літера `k` наказує системі автоматично викликати `preconv`, літера `t` — `tbl`).
  3. Якщо явна вказівка відсутня, `preconv` використовує поточну локаль системи або перевіряє валідність потоку UTF-8 за допомогою бібліотеки `uchardet`.

### Керування локалізацією через змінні оточення та виклики

1. **Ієрархія системних змінних середовища**:
   - `LANGUAGE`: Має найвищий пріоритет. Дозволяє задати список мов через двокрапку: `export LANGUAGE="uk:de:en"`;
   - `LC_ALL`: Перевизначає всі інші налаштування категорії локалей;
   - `LC_MESSAGES`: Визначає мову системних повідомлень та пошуку сторінок довідки;
   - `LANG`: Базова системна локаль за замовчуванням (`export LANG=uk_UA.UTF-8`).

2. **Примусовий вибір локалі через прапорці команди `man`**:
   ```bash
   # Відкрити сторінку українською мовою:
   man -L uk_UA.UTF-8 ls
   man -L uk 1 ls

   # Відкрити оригінальну сторінку англійською мовою (C locale):
   man -L C 2 open
   man -L POSIX 3 printf
   ```

## 11. Специфікація сучасних генераторів man-сторінок

На практиці більшість сторінок створюється у високорівневих розмітках (Markdown, AsciiDoc, YAML) і транслюється в `roff` на етапі збірки проекту.

### 1. Генератор ronn / ronn-ng (формат Markdown)

#### Синтаксис файлу .ronn

```markdown
myutil(1) -- короткий однорядковий опис
=======================================

## SYNOPSIS

`myutil` [<опції>...] <файл>

## DESCRIPTION

**myutil** обробляє вхідні потоки даних з високою швидкодією.

## OPTIONS

* `-f`, `--file`=<ШЛЯХ>:
  Шлях до цільового файлу конфігурації.
* `-v`, `--verbose`:
  Увімкнути докладний режим виводу в stderr.

## SEE ALSO

grep(1), awk(1)
```

#### Вимоги до синтаксису ronn
- Перший рядок обов'язково має вигляд `name(sec) -- summary`.
- Заголовки `## SECTION` автоматично транслюються в `.SH SECTION`.
- Списки з тегами `* `-f`, `--file`:` автоматично транслюються в `.TP` та `.BI`.
- Посилання `name(sec)` автоматично транслюються в `.BR name (sec)`.
- Команда компіляції: `ronn --roff --manual="User Manual" myutil.1.ronn`.

---

### 2. Генератор Pandoc (компілятор man-pages)

#### Синтаксис документу Pandoc із YAML-метаданими

```yaml
---
title: MYTOOL
section: 1
header: Інструкція користувача
footer: MyTool 2.4.0
date: Серпень 2026
author:
  - Розробник Проекту <dev@example.com>
---

# NAME

mytool - утиліта фільтрації системних подій

# SYNOPSIS

`mytool` [**-v**] [**-c** *config*] *input_file*

# DESCRIPTION

Розгорнутий технічний опис функціоналу утиліти.

# OPTIONS

`-c` *FILE*, `--config`=*FILE*
: Вказати шлях до файлу конфігурації.

`-v`, `--verbose`
: Докладне логування діагностичних повідомлень.

# SEE ALSO

`systemd(8)`, `journalctl(1)`
```

#### Команда компіляції Pandoc

```bash
pandoc -s -f markdown -t man mytool.md -o mytool.1
```

### 4. Генератор help2man (автоматичний екстрактор)

Утиліта `help2man` генерує канонічну сторінку man(7) на основі стандартизованого виводу програми при виклику з прапорцями `--help` та `--version`.

#### Виклик та прапорці help2man

```bash
help2man --no-info \
         --name="утиліта аналізу логів" \
```

Файл `.h2m` дозволяє додати додаткові секції, які відсутні у виводі `--help`:

```
[NAME]

[DESCRIPTION]

.B myutil -f /var/log/app.bin -v

[SEE ALSO]
syslog(3), journalctl(1)
```

## 12. Конфігурація середовища, індексація та утиліти діагностики

### Системні змінні середовища

- **`MANPATH`**: Двокрапковий список базових каталогів пошуку (наприклад, `/usr/share/man:/usr/local/share/man`). Якщо змінна починається або закінчується двокрапкою, системні шляхи за замовчуванням автоматично додаються у відповідну позицію.
- **`MANPAGER`** / **`PAGER`**: Програма перегляду виводу. Стандартне значення: `less -s -R`.
- **`MANWIDTH`**: Фіксована ширина форматування тексту в колонках (наприклад, `export MANWIDTH=100`).
- **`MANOPT`**: Аргументи командного рядка, які автоматично підставляються перед кожним викликом `man`.
- **`MANSECT`**: Список розділів для послідовного пошуку (за замовчуванням: `1:1p:8:2:3:3p:4:5:6:7:9:0p:tcl:n:l:p:o`).

### Конфігураційний файл /etc/manpath.config

Файл `/etc/manpath.config` (у BSD `/etc/man.conf`) регламентує системні правила мапування:
- **`MANDATORY_MANPATH /usr/share/man`**: Базовий обов'язковий каталог;
- **`MANPATH_MAP /usr/bin /usr/share/man`**: Зв'язування шляхів виконуваних файлів із відповідними каталогами документації;
- **`MANDB_MAP /usr/share/man /var/cache/man/index.db`**: Розташування бінарного індексу кешу бази даних;
- **`SECTION_LIST 1 1p 8 2 3 3p 4 5 6 7 9 0p`**: Порядок пошуку за розділами.

### Утиліти визначення розташування файлів

- **`man -w [name]`**: Друкує абсолютний шлях до файлу сторінки довідки замість її відображення на екрані.
- **`man -w`** (без аргументів): Виводить повний перелік активних каталогів пошуку `MANPATH`.
- **`man -W [name]`**: Аналогічно до `-w`, але виводить лише перший знайдений шлях без попередньої обробки.
- **`whereis -m [name]`**: Знаходить усі файли довідки для вказаного імені у системних каталогах.

### Утиліти індексації: mandb та makewhatis

- **`mandb` (Linux / GNU man-db)**:
  - Сканує каталоги `MANPATH`, читає секції `NAME`, витягує імена утиліт та короткі описи й записує їх у бінарну базу даних GDBM/Berkeley DB (`/var/cache/man/index.db`).
  - Прапорці: `mandb -c` (повне перестворення індексу з нуля), `mandb -u` (інкрементне оновлення кешу), `mandb -q` (тихий режим).
- **`makewhatis` (BSD / mandoc)**:
  - Компілює текстовий індекс `whatis` або базу пошуку SQLite (`mandoc.db`) у кожному каталозі дерева man.

### Утиліти пошуку: apropos та whatis

- **`whatis [name...]`** (еквівалент `man -f`):
  - Виконує точний пошук за ім'ям команди в базі даних індексів і виводить однорядковий опис із секції `NAME`:
  ```bash
  $ whatis read
  read (2)             - read from a file descriptor
  read (1p)            - read a line from standard input
  read (3p)            - read from a file
  ```
- **`apropos [pattern...]`** (еквівалент `man -k`):
  - Здійснює повнотекстовий пошук регулярного виразу серед усіх імен та описів бази `mandb`:
  ```bash
  $ apropos "socket"
  accept (2)           - accept a connection on a socket
  bind (2)             - bind a name to a socket
  socket (2)           - create an endpoint for communication
  socket (7)           - Linux socket interface
  ```

### Статичний аналіз та аудит через mandoc -Tlint

Утиліта `mandoc` має вбудований суворий лінтер структури документа:

```bash
mandoc -Tlint myutil.1
```

#### Рівні строгості повідомлень linter'а
1. **FATAL**: Критична помилка структури (файл неможливо розпарсити);
2. **ERROR**: Грубе порушення синтаксису (незакритий блок `.Bl`, невідомий макрос);
3. **WARNING**: Порушення стандартів верстки (відсутність `.Sh AUTHORS`, невірний порядок секцій);
4. **UNSUPP**: Використання конструкцій, не підтримуваних стандартом `mdoc`/`man`;
5. **STYLE**: Стилістичні зауваження (зайві пробіли, відсутність екранування мінусів `\-`).

#### Команда автоматичної перевірки в CI/CD

```bash
# Перевірка синтаксису через mandoc (повертає ненульовий код при помилках)
mandoc -Tlint -Werror myutil.1

# Перевірка через GNU groff з максимальним рівнем діагностики
groff -Wall -Tutf8 -mandoc myutil.1 > /dev/null
```

### Компіляція, конвертація та конвеєри groff

1. **Термінальний перегляд із підтримкою UTF-8**:
   ```bash
   groff -Wall -Tutf8 -mandoc myutil.1 | less -R
   ```
2. **Очищення від керуючих послідовностей (Plain Text / ASCII)**:
   ```bash
   groff -Tutf8 -mandoc myutil.1 | col -b > myutil.txt
   ```
3. **Генерація PostScript для поліграфічного друку**:
   ```bash
   groff -Tps -mandoc myutil.1 > myutil.ps
   ```
4. **Пряма компіляція у формат PDF**:
   ```bash
   groff -Tpdf -mandoc myutil.1 > myutil.pdf
   ```
5. **Генерація веб-сторінки HTML**:
   ```bash
   groff -Thtml -mandoc myutil.1 > myutil.html
   # або через mandoc:
   mandoc -Thtml -O style=man.css myutil.1 > myutil.html
   ```
6. **Експорт у формат Markdown**:
   ```bash
   mandoc -Tmarkdown myutil.1 > myutil.md
   ```
7. **Повний конвеєр із запуском усіх препроцесорів**:
   ```bash
   preconv myutil.1 | tbl | eqn | pic | groff -Tutf8 -man
   # або еквівалентний короткий виклик groff:
   groff -k -t -e -p -Tutf8 -man myutil.1
   ```
