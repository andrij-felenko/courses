# 📋 Довідник розділів, макросів розмітки та конвенцій man

Сторінки довідки Unix/Linux підпорядковуються суворим правилам структурування, синтаксичної розмітки, класифікації інтерфейсів та специфікації потокобезпечності. Цей довідник містить вичерпний опис класичних та розширених розділів, правила побудови обов'язкових секцій, порівняльну специфікацію макросів пакетів `man(7)` та `mdoc(7)`, а також матрицю кодів безпеки таблиці `ATTRIBUTES`.

## 1. Класифікація розділів та ієрархія інтерфейсів

Стандартний ієрархічний розподіл інформації за нумерованими розділами (*sections*) визначає категорію, системний рівень та контекст використання кожної сутності. Номер розділу дозволяє розрізняти однойменні команди, виклики ядра та бібліотечні абстракції.

### Основні розділи (1–8)

- **Розділ 1: Команди користувача та утиліти оболонки (`user commands`)**. Описує автономні виконувані програми, утиліти термінала, вбудовані команди командних інтерпретаторів, фільтри та компілятори, які запускаються звичайними користувачами в сесіях командного рядка (наприклад, `ls(1)`, `grep(1)`, `bash(1)`, `tar(1)`, `gcc(1)`).
- **Розділ 2: Системні виклики ядра (`system calls`)**. Документує інтерфейс переходу процесора між кільцями захисту (Ring 3 → Ring 0). Ці виклики виконуються ядром операційної системи, оперують дескрипторами, процесами, пам'яттю та апаратними ресурсами і сигналізують про помилку поверненням значення `-1` зі встановленням глобальної змінної `errno` (наприклад, `open(2)`, `read(2)`, `mmap(2)`, `fork(2)`, `epoll_create1(2)`).
- **Розділ 3: Бібліотечні функції C (`library functions`)**. Описує функції стандартної бібліотеки мови C (`glibc`, `musl`) та системних бібліотек (`libpthread`, `libcrypto`, `libm`, `libz`), що виконуються суто у просторі користувача. Вони реалізують буферизований ввід-вивід, математичні розрахунки, структури даних та високорівневі мережеві абстракції (наприклад, `printf(3)`, `malloc(3)`, `pthread_create(3)`, `dlopen(3)`, `qsort(3)`).
- **Розділ 4: Спеціальні файли пристроїв (`special files /dev`)**. Описує віртуальні та апаратні вузли файлової системи, розташовані в каталозі `/dev`. Тут документується семантика читання, запису та специфічні керуючі виклики `ioctl` для драйверів терміналів, генераторів випадкових чисел, нульових приймачів та накопичувачів (наприклад, `null(4)`, `zero(4)`, `random(4)`, `urandom(4)`, `tty(4)`, `loop(4)`).
- **Розділ 5: Формати конфігураційних файлів та протоколів (`file formats`)**. Специфікує синтаксис статичних файлів конфігурації операційної системи, системних таблиць, баз даних та бінарних структур заголовків файлів (наприклад, `/etc/passwd` у `passwd(5)`, `/etc/shadow` у `shadow(5)`, `/etc/fstab` у `fstab(5)`, `crontab(5)`, `elf(5)`).
- **Розділ 6: Ігри та заставки (`games`)**. Історичний розділ, де зібрані описи консольних ігор, демонстраційних графічних ефектів, генераторів випадкових цитат та розважальних утиліт (наприклад, `fortune(6)`, `factor(6)`, `tetris(6)`).
- **Розділ 7: Оглядові статті, стандарти та протоколи (`miscellaneous and conventions`)**. Містить концептуальні описи підсистем операційної системи, мережевих стеків, конвенцій кодування та стандартів POSIX/Linux. Тут роз'яснюються механізми доставки сигналів `signal(7)`, мережеві протоколи `ip(7)`, `tcp(7)`, `unix(7)`, модель очікування подій `epoll(7)` та конвенції верстки документації `man-pages(7)`.
- **Розділ 8: Утиліти системного адміністрування (`system administration`)**. Документує фонові демони, системні сервіси та утиліти керування платформою, які вимагають привілеїв суперкористувача (`root`) або спеціальних системних можливостей (*capabilities*), такі як `systemd(8)`, `mount(8)`, `iptables(8)`, `fsck(8)`, `useradd(8)`.

### Спеціалізовані та додаткові підрозділи

- **Підрозділ `0` / `0p`**: Описує стандартні заголовкові файли мови C відповідно до специфікацій POSIX (`stdio.h(0p)`, `unistd.h(0p)`, `fcntl.h(0p)`, `signal.h(0p)`).
- **Підрозділи `1p` та `3p`**: Містять офіційні специфікації стандарту The Open Group / IEEE POSIX 1003.1, описуючи стандартизовану переносну поведінку функцій та утиліт окремо від специфічних розширень ядра Linux чи бібліотеки GNU C (наприклад, `read(3p)` проти `read(2)`).
- **Підрозділ `9`**: Документує внутрішні інтерфейси та підсистеми ядра Linux або BSD, призначені для авторів драйверів пристроїв і завантажуваних модулів ядра.
- **Підрозділи `l` (`local`) та `n` (`new`)**: Історичні розділи для локально зібраного програмного забезпечення або нових розширень середовища Tcl/Tk.

## 2. Стандартна послідовність та вимоги до секцій документа

Згідно зі стандартом `man-pages(7)`, кожна сторінка довідки повинна містити канонічний набір заголовків першого рівня (`.SH` у `man` або `.Sh` у `mdoc`), розташованих у строго визначеній послідовності. Це забезпечує передбачуваність навігації та коректну роботу інструментів автоматичного парсингу.

### Обов'язкові секції

1. **`NAME`**: Найважливіша секція для пошукової системи. Містить ім'я об'єкта, список усіх його синонімів або споріднених функцій через кому, дефіс та стислий однорядковий опис без крапки наприкінці. Рядок аналізується утилітами `mandb` та `makewhatis` для генерації індексу `whatis`.
2. **`SYNOPSIS`**: Формальний конспект виклику. Для утиліт розділів 1 та 8 наводить шаблон прапорців та аргументів; для функцій розділів 2 та 3 — директиви препроцесора `#include`, необхідні макроси `_GNU_SOURCE` чи `_POSIX_C_SOURCE`, типи повернення, імена та типи аргументів із кваліфікаторами `const` та `restrict`.
3. **`DESCRIPTION`**: Розгорнутий технічний опис функціоналу. Детально роз'яснює кожен прапорець, описує стан внутрішніх буферів, послідовність обробки запиту та зміну структур даних.
4. **`RETURN VALUE`**: Обов'язкова для розділів 2 та 3. Чітко визначає, яке саме числове значення чи вказівник повертається у разі успішного завершення операції, яке значення сигналізує про помилку (типово `-1` або `NULL`), та чи вимагає виклик попереднього скидання `errno = 0`.
5. **`ERRORS`**: Обов'язкова для розділів 2 та 3. Містить алфавітний список усіх можливих числових кодів `errno` (`EINTR`, `EAGAIN`, `EBADF`, `EFAULT`, `EINVAL`, `ENOMEM`, `EPERM`) із детальним описом конкретних системних умов, за яких кожен код виникає.
6. **`CONFORMING TO` (або `STANDARDS`)**: Фіксує відповідність офіційним стандартам: POSIX.1-2001, POSIX.1-2008, ISO C99, C11, System V Release 4 (SVr4), 4.3BSD або вказує на специфічність інтерфейсу для Linux чи GNU.
7. **`SEE ALSO`**: Список пов'язаних за змістом сторінок довідки із зазначенням номерів розділів (наприклад, `open(2)`, `write(2)`, `fcntl(2)`).

### Додаткові та рекомендовані секції

- **`ENVIRONMENT`**: Перелік змінних середовища (`LANG`, `PATH`, `TMPDIR`, `LD_PRELOAD`), що впливають на поведінку програми чи бібліотеки під час виконання.
- **`FILES`**: Абсолютні шляхи до системних файлів конфігурації, баз даних, логів або сокетів, які читає або створює програма (наприклад, `/etc/hosts`, `/var/run/utmp`).
- **`ATTRIBUTES`**: Стандартизована таблиця безпеки виконання для багатопотокових програм та обробників сигналів (`MT-Safe`, `AS-Safe`, `AC-Safe`).
- **`VERSIONS`**: Історія появи системного виклику в ядрі Linux та версія бібліотеки `glibc`, починаючи з якої виклик отримав повноцінну обгортку.
- **`NOTES`**: Архітектурні нюанси, відмінності між реалізаціями на різних процесорних архітектурах, особливості взаємодії з потоками чи форком.
- **`CAVEATS` та `BUGS`**: Документовані обмеження архітектури, відомі дефекти або крайові умови, де поведінка відхиляється від очікуваної.
- **`EXAMPLE`**: Повний мінімальний самодостатній приклад програми мовою C або скрипту оболонки, готовий до компіляції та запуску.

## 3. Специфікація макросів розмітки

Сторінки довідки верстаються за допомогою двох взаємодоповнюючих макропакетів: презентаційного `man(7)` та семантичного `mdoc(7)`.

### Традиційний пакет макросів `man(7)`

Макроси `man(7)` визначають візуальне представлення тексту:
- **`.TH TITLE SECTION DATE SOURCE MANUAL`**: Головний заголовок сторінки. Задає ім'я документа, номер розділу, дату останньої модифікації, джерело пакету та назву загального посібника в колонтитулах.
- **`.SH [НАЗВА]`**: Заголовок секції першого рівня (`NAME`, `SYNOPSIS`, `DESCRIPTION`).
- **`.SS [НАЗВА]`**: Підзаголовок другого рівня всередині секції.
- **`.TP [відступ]`**: Параграф із тегом (*tagged paragraph*). Наступний за директивою рядок стає заголовком (наприклад, прапорцем опції), а подальший текст зміщується вправо як опис.
- **`.PP` / `.P` / `.LP`**: Початок нового звичайного абзацу тексту.
- **`.B [текст]`**: Встановлює жирне накреслення (*Bold*) для всього рядка або першого аргументу.
- **`.I [текст]`**: Встановлює курсивне накреслення (*Italic* / *Underline*) для позначення змінних користувача.
- **`.BR b_word r_word ...`**: Чергує жирний та звичайний шрифт для кожного наступного слова без пробілів між ними (стандартний прийом для оформлення посилань виду `read(2)`).
- **`.IR i_word r_word ...`**: Чергує курсив та звичайний шрифт.
- **`.BI b_word i_word ...`**: Чергує жирний шрифт і курсив (для опцій із параметрами, наприклад `-f` *FILE*).
- **`.RS [відступ]` / `.RE`**: Зсуває ліве поле верстки вправо (*Relative Start*) та повертає його назад (*Relative End*).

### Семантичний пакет макросів `mdoc(7)`

Макроси `mdoc(7)` описують зміст та призначення сутностей:
- **`.Dd DATE` / `.Dt TITLE SECTION` / `.Os SYSTEM`**: Заголовок документа, розділ та назва операційної системи.
- **`.Sh SECTION` / `.Ss SUBSECTION`**: Структурні секції та підсекції.
- **`.Nm [ім'я]`**: Позначає ім'я утиліти або модуля. Автоматично пам'ятає головне ім'я, вказане в секції `NAME`.
- **`.Fl flag`**: Позначає прапорець опції командного рядка (автоматично додає дефіс перед літерою).
- **`.Ar arg`**: Позначає змінний аргумент користувача (рендериться курсивом).
- **`.Op ...`**: Обгортає вміст у квадратні дужки, позначаючи опційність блоку.
- **`.Ft type`**: Тип даних або тип повернення функції C (наприклад, `ssize_t`).
- **`.Fn name args...`**: Сигнатура виклику функції C зі списком параметрів.
- **`.Fa arg`**: Окремий параметр функції або структура даних.
- **`.Er ERROR`**: Символьний код системної помилки `errno` (наприклад, `EINTR`).
- **`.Dv CONSTANT`**: Константа препроцесора, макрос або бітова маска (наприклад, `O_NONBLOCK`).
- **`.Xr name section`**: Семантичне перехресне посилання на іншу сторінку довідки (наприклад, `.Xr write 2`).

## 4. Матриця безпеки середовища виконання ATTRIBUTES

У секції `ATTRIBUTES` сторінок довідки функцій бібліотеки C наводиться таблиця відповідності стандарту безпеки POSIX.1-2008 та проєкту GNU C Library. Ця таблиця регулює правила використання функцій у складних архітектурах із паралельними потоками та асинхронними обробниками.

### Категорії безпеки виконання

- **`MT-Safe` (Multi-Thread Safe)**: Функція гарантує коректність роботи при паралельному виклику з довільної кількості потоків процесу. Вона не використовує несинхронізований спільний стан пам'яті та захищає власні внутрішні структури примітивами блокування.
- **`MT-Unsafe` (Multi-Thread Unsafe)**: Одночасний виклик функції з декількох потоків призводить до пошкодження пам'яті або стану гонитви (*race condition*). Використання вимагає обов'язкової зовнішньої синхронізації м'ютексом.
- **`AS-Safe` (Async-Signal Safe)**: Функцію можна безпечно викликати всередині обробника системного сигналу (`signal handler`). Вона є реентрантною і не захоплює м'ютекси, які міг захопити перерваний потік.
- **`AS-Unsafe` (Async-Signal Unsafe)**: Виклик функції з обробника сигналу суворо заборонений, оскільки може спричинити взаємне блокування (*deadlock*) або руйнування структур пам'яті (типовий приклад — `printf` та `malloc`).
- **`AC-Safe` (Async-Cancel Safe)**: Функція коректно вивільняє ресурси у разі асинхронного переривання потоку механізмом `pthread_cancel`.
- **`AC-Unsafe` (Async-Cancel Unsafe)**: Асинхронне скасування потоку під час виконання цієї функції призведе до витоку пам'яті, залишених заблокованими замків або незакритих файлових дескрипторів.

### Специфікатори застережень у таблиці `ATTRIBUTES`

Якщо функція має статус `MT-Unsafe`, поруч із міткою наводиться конкретна причина небезпеки:
- **`race:object`**: функція використовує статичний неізольований буфер пам'яті (наприклад, `race:strtok` для `strtok` або `race:asctime` для `asctime`). Рішення — використання реентрантної версії із суфіксом `_r` (`strtok_r`).
- **`env`**: функція зчитує або модифікує глобальний масив змінних середовища процесу (`environ`), що створює стан гонитви з функціями `setenv` та `putenv`.
- **`locale`**: функція використовує глобальний стан мовної локалі процесу без ізоляції в об'єкт `locale_t`.
- **`sig`**: функція модифікує глобальну таблицю сигнальних диспозицій процесу.
- **`lock`**: функція захоплює внутрішній замок блокування, переривання якого обробником сигналу загрожує дедлоком.

## 5. Конфігурація середовища та валідація сторінок

Утиліти відображення та пошуку сторінок `man` керуються набором системних змінних середовища та конфігураційних файлів:

- **`MANPATH`**: Список каталогів для пошуку файлів сторінок довідки, розділений двокрапками. Якщо змінна починається або закінчується двокрапкою, до неї автоматично додаються стандартні системні каталоги `/usr/share/man`.
- **`MANPAGER`** та **`PAGER`**: Команда переглядача тексту. Рекомендоване значення для повноцінного відображення кольорів та стилів — `less -R`.
- **`MANWIDTH`**: Фіксує ширину стовпчика форматування у символах (наприклад, `export MANWIDTH=100`), що запобігає надмірному розтягуванню рядків на широкоформатних моніторах.
- **`/etc/manpath.config`**: Центральний конфігураційний файл, що визначає обов'язкові шляхи `MANDATORY_MANPATH`, відповідність бінарних каталогів каталогам довідки `MANPATH_MAP` та порядок сканування секцій `SECTION_LIST`.

### Інструменти перевірки та валідації якості (Linting)

Під час розробки власних сторінок довідки для програм та бібліотек автори використовують такі інструменти компіляції та аудиту розмітки:

1. **Валідація через `mandoc`**:
   ```bash
   mandoc -Tlint myprogram.1
   ```
   Утиліта будує синтаксичне дерево документу і перевіряє структурну коректність макросів, баланс відкриваючих і закриваючих блоків та валідність секції `NAME`.
2. **Перевірка компіляції через `groff`**:
   ```bash
   groff -Wall -Tutf8 -mandoc myprogram.1 > /dev/null
   ```
