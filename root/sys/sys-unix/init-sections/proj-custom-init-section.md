# ⚙️ Реалізація одноразових секцій пам'яті в C та C++

Механізм одноразових секцій ініціалізації (`__init`) можна успішно відтворити не лише у внутрішній архітектурі ядра операційної системи, а й у високонавантажених системних користувацьких програмах, демонах або вбудованих прошивках без ОС (bare-metal firmware). Для цього використовуються спеціальні атрибути розміщення секцій компіляторів GCC та Clang, автоматично згенеровані символи системного компонувальника (linker) для визначення точних меж секції у віртуальному адресному просторі, а також системні виклики управління сторінковою пам'ятью POSIX (`mprotect` та `munmap`). Нижче розвертається повна реалізація самоочисного блоку ініціалізації мовами C та C++.

## 1. Архітектурна концепція користувацької init-секції

Під час стандартної компіляції програми машинний код усіх функцій за замовчуванням потрапляє у виділену секцію `.text`, а глобальні та статичні змінні — у секції `.data` (для ініціалізованих даних) або `.bss` (для нульових даних). Щоб відокремити початковий код завантаження від основного постійного коду програми, застосовується наступний інженерний алгоритм:

1. **Примусова компоновка секції**: За допомогою атрибута `__attribute__((section(".my_init")))` у мові C або стандартизованого атрибута `[[gnu::section("my_init")]]` у мові C++20 ми змушуємо компілятор поміщати машинний код і конфігураційні константи початкового налаштування в окрему спеціальну секцію ELF-файлу з ім'ям `my_init`.
2. **Автоматична генерація символів компонувальника**: Системний компонувальник GNU `ld` або LLVM `lld` під час створення фінального виконуваного бінарного файлу автоматично формує два глобальні символи: `__start_my_init` та `__stop_my_init`. Ці символи позначають відповідно початкову та кінцеву віртуальні адреси виділеної секції в оперативній пам'яті процесу.
3. **Строге сторінкове вирівнювання (Page Alignment)**: Підсистема віртуальної пам'яті ядра Linux оперує адресами виключно на рівні сторінок пам'яті (за замовчуванням 4096 байтів для архітектур x86_64 та ARM64). Викликати системні операції видалення пам'яті для довільних байтових зміщень неможливо. Тому секція `my_init` повинна бути вирівняна на межу сторінки за допомогою атрибута `aligned(4096)`.
4. **Апаратний демонтаж пам'яті**: Після виконання всіх початкових процедур конфігурування спеціальна функція самоочищення обчислює точні межі сторінок і викликає системний виклик `munmap()`. Це призводить до видалення відповідних сторінок із таблиці сторінок процесу (Page Table Entries, PTE) та повернення фізичних кадрів пам'яті до загального пулу операційної системи.

## 2. Повна реалізація: Вкладки C та C++

Нижче наведено ідіоматичні реалізації самоочисного блоку ініціалізації для мов C та C++. У версії для C++ використовується принцип RAII (Resource Acquisition Is Initialization), який гарантує автоматичний демонтаж пам'яті при виході з області видимості конфігураційного блоку.

:::tabs
```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/mman.h>
#include <stdint.h>

/* Оголошення зовнішніх символів лінкера для меж секції my_init */
extern char __start_my_init[];
extern char __stop_my_init[];

/* Макрос для розміщення коду та даних у секції my_init із вирівнюванням */
#define __my_init __attribute__((section("my_init"), aligned(4096)))

/* Дані ініціалізації, які зберігаються у спеціальній секції */
static const char init_msg[] __my_init = "Початкове конфігурування системи та перевірка обладнання...";

/* Функція ініціалізації, яка виконує початкове налаштування */
static void __my_init run_early_setup(void)
{
    printf("[INIT] %s\n", init_msg);
    printf("[INIT] Виконано розпакування початкових структур даних.\n");
}

/* Механізм самоочищення пам'яті ініціалізації */
static void purge_init_sections(void)
{
    uintptr_t start = (uintptr_t)__start_my_init;
    uintptr_t end = (uintptr_t)__stop_my_init;
    size_t page_size = sysconf(_SC_PAGESIZE);

    /* Вирівнюємо початок вниз, а кінець вгору до меж сторінок */
    uintptr_t page_start = start & ~(page_size - 1);
    uintptr_t page_end = (end + page_size - 1) & ~(page_size - 1);
    size_t len = page_end - page_start;

    printf("[SYSTEM] Звільнення init-пам'яті: %lu байтів (початок: %p)...\n",
           (unsigned long)len, (void *)page_start);

    /* Демонтаж сторінок з адресного простору процесу */
    if (munmap((void *)page_start, len) == 0) {
        printf("[SYSTEM] Init-пам'ять успішно звільнена та повернута ОС.\n");
    } else {
        perror("[ERROR] Системний виклик munmap не вдався");
    }
}

int main(void)
{
    /* Етап 1: Виконання ініціалізації */
    run_early_setup();

    /* Етап 2: Звільнення пам'яті секції */
    purge_init_sections();

    /* Етап 3: Робочий цикл системи */
    printf("[MAIN] Основний робочий цикл запущено. Init-код більше недоступний.\n");
    return 0;
}
```
```cpp
#include <iostream>
#include <span>
#include <cstdint>
#include <unistd.h>
#include <sys/mman.h>

// Оголошення зовнішніх символів компонувальника GCC/Clang
extern "C" {
    extern char __start_my_init[];
    extern char __stop_my_init[];
}

// Використання стандартних атрибутів C++20 з розширеннями GNU
#define MY_INIT [[gnu::section("my_init"), gnu::aligned(4096)]]

MY_INIT const char init_payload[] = "C++ Init Payload Structure Configuration";

MY_INIT void execute_cpp_init() {
    std::cout << "[INIT C++] Виконання ранньої ініціалізації: " << init_payload << std::endl;
}

// RAII-обгортка для автоматичного контролю життєвого циклу секції ініціалізації
class InitSectionPurger {
public:
    InitSectionPurger(void* start, void* end) noexcept
        : start_(reinterpret_cast<uintptr_t>(start)),
          end_(reinterpret_cast<uintptr_t>(end)) {}

    ~InitSectionPurger() {
        const size_t page_size = static_cast<size_t>(sysconf(_SC_PAGESIZE));
        const uintptr_t page_start = start_ & ~(page_size - 1);
        const uintptr_t page_end = (end_ + page_size - 1) & ~(page_size - 1);
        const size_t len = page_end - page_start;

        if (len > 0 && munmap(reinterpret_cast<void*>(page_start), len) == 0) {
            std::cout << "[RAII Purger] Секція init-пам'яті (" << len 
                      << " байтів) успішно деалокована." << std::endl;
        }
    }

    // Заборона копіювання для збереження семантики унікального володіння
    InitSectionPurger(const InitSectionPurger&) = delete;
    InitSectionPurger& operator=(const InitSectionPurger&) = delete;

private:
    uintptr_t start_;
    uintptr_t end_;
};

int main() {
    {
        // Контекст ініціалізації: RAII-об'єкт автоматично демонтує пам'ять при виході
        InitSectionPurger purger(__start_my_init, __stop_my_init);
        execute_cpp_init();
    }

    std::cout << "[MAIN] Програма працює у штатному режимі користувацького простору." << std::endl;
    return 0;
}
```

## 3. Збирання, компіляція та аналіз ELF-бінарника

Для збирання та перевірки наведеного коду використовується стандартний інструментарій GCC або Clang у операційній системі Linux.

```bash
# Збирання C-версії програми
gcc -O2 -Wall main.c -o custom_init_c

# Збирання C++20 версії програми
g++ -O2 -std=c++20 -Wall main.cpp -o custom_init_cpp
```

Після компіляції можна дослідити таблицю секцій ELF-файлу за допомогою системної утиліти `readelf`:

```bash
readelf -S custom_init_c | grep my_init
```

Результат виконання команди відобразить наявність окремої секції `my_init`, її точний розмір та віртуальну адресу, яка буде вирівняна на межу 4096 байтів (`0x1000`).

## 4. Детальний математично-логічний розрахунок меж сторінок

При роботі із системними викликами віртуальної пам'яті критично важливо правильно виконувати бітові операції вирівнювання адрес. Нехай адреса початку секції `__start_my_init` дорівнює `start`, а адреса кінця `__stop_my_init` дорівнює `end`. Розмір сторінки системи `PAGE_SIZE` зазвичай є степенем двійки ($2^{12} = 4096$).

Формула вирівнювання початкової адреси вниз до межі сторінки:
```
page_start = start & ~(PAGE_SIZE - 1)
```
Для `PAGE_SIZE = 4096` (`0x1000`) маска `~(PAGE_SIZE - 1)` дорівнює `0xFFFFF000` на 32-бітних або `0xFFFFFFFFFFFFF000` на 64-бітних системах. Ця операція обнуляє молодші 12 бітів адреси, повертаючи точний початок сторінки, у якій лежить символ.

Формула вирівнювання кінцевої адреси вгору до найближчої межі сторінки:
```
page_end = (end + PAGE_SIZE - 1) & ~(PAGE_SIZE - 1)
```
Ця операція гарантує, що якщо секція `my_init` закінчується хоча б на 1 байт усередині наступної сторінки, `page_end` охопить цю сторінку повністю. Отриманий розмір `len = page_end - page_start` гарантовано буде кратним 4096 байтам, що є необхідною умовою для коректної роботи `munmap()`.

## 5. Альтернативний захист через mprotect

Замість повного демонтажу сторінок за допомогою `munmap()`, у деяких архітектурах застосовується системний виклик `mprotect()` із прапорцем `PROT_NONE`:

```c
mprotect((void *)page_start, len, PROT_NONE);
```

Перевагою використання `PROT_NONE` є те, що сторінки залишаються зарезервованими в адресному просторі процесу, але будь-яка спроба читання, запису чи виконання коду за цими адресами негайно викликає апаратне виключення MMU й надсилання сигналу `SIGSEGV`. Це запобігає повторному перевиділенню тих самих віртуальних адрес під інші потреби програми, роблячи діагностику помилок виклику init-коду більш однозначною.

## 6. Глибокі механізми, крайові випадки та пастки

### 6.1. Вирівнювання за межами сторінки (Page Alignment Requirement)
Операційна система керує віртуальною пам'яттю через сторінкові таблиці (PTE). Виклик системного функціоналу `munmap(addr, length)` вимагає, щоб початкова адреса `addr` була кратною системному розміру сторінки `PAGE_SIZE`. Якщо адреса секції `my_init` не вирівняна на 4096 байтів, виклик `munmap()` спробує вирівняти адресу вниз, що може призвести до демонтажу сусідніх сторінок з постійним кодом `.text`. Саме тому додавання `aligned(4096)` до кожної змінної та функції в цій секції є обов'язковою умовою для безпечного вилучення.

### 6.2. Специфіка об'єднання константних рядків (`-fmerge-constants`)
Під час компіляції з прапорцями оптимізації (`-O2` або `-O3`) компілятор може автоматично перемістити рядкові літерали (наприклад, `"Початкове конфігурування..."`) у загальну константну секцію `.rodata` для усунення дублікатів рядків у бінарнику. У такому разі функція з секції `my_init` звертатиметься до даних у `.rodata`. Якщо рядковий літерал має залишатися всередині `my_init` і бути знищеним разом із нею, його слід явно оголосити як масив констант із атрибутом `__my_init`.

### 6.3. Оптимізації усунення незвертального коду (`-fno-toplevel-reorder`)
При агресивних оптимізаціях компілятор може перевпорядковувати функції або вбудовувати їх (inlining). Якщо функція з секції `my_init` буде вбудована (inlined) у функцію `main()`, частина коду ініціалізації потрапить до постійної секції `.text`, а виклик `munmap()` видалить лише порожній каркас. Щоб запобігти цьому, до `__my_init` можна додати атрибут `noinline` (`__attribute__((noinline))`).

### 6.4. Апаратна діагностика спроб звернення після очищення (Use-After-Free)
Якщо після виконання `purge_init_sections()` програма спробує викликати `run_early_setup()`, операційна система негайно згенерує сигнал `SIGSEGV` (Segmentation Fault). На відміну від звичайного помилкового звернення до пам'яті у динамічній купі (heap), демонтаж сторінки через `munmap()` гарантує апаратний перехоплювач доступу на рівні MMU процесора, що робить цей підхід винятково надійним інструментом системної розробки.
