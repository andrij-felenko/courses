# 📋 Інтерфейси керування RSS та RETA: C-структури, ioctl та Netlink

Конфігурація механізмів Receive Side Scaling (RSS), Indirection Tables (RETA), Flow Hashing, прив'язки переривань та сокетного масштабування у ядрі Linux виконується через два основних програмних інтерфейси: класичний системний виклик `ioctl()` із заголовочного файла `<linux/ethtool.h>` та сучасний уніфікований протокол **Netlink (generic netlink ethtool)**. Крім того, підсистема ядра надає віртуальні файлові контролери у псевдофайлових системах `/proc` та `/sys`.

Цей довідник містить повний та точний опис структур даних C, констант, Netlink-атрибутів, параметрів CLI-утиліти `ethtool`, а також шляхів у `/sys` та `/proc`.

---

## 1. Класичний ioctl-інтерфейс (`<linux/ethtool.h>`)

Традиційна взаємодія з драйвером мережевого адаптера виконується через сокет за допомогою системного виклику `ioctl(fd, SIOCETHTOOL, &ifr)`. У цій виклику `ifr.ifr_name` містить назву мережевого інтерфейсу у вигляді нуль-термінованого рядка (наприклад, `"eth0"`), а `ifr.ifr_data` є вказівником на відповідну C-структуру ethtool.

Вся обробка викликів ioctl виконується у ядрі підсистемою `net/ethtool/ioctl.c`. Кожен виклик модифікації параметрів вимагає наявності привілеїв `CAP_NET_ADMIN` у поточному просторі імен мережі (Network Namespace).

### Структура `struct ethtool_rxfh_indir` (Застарілий інтерфейс RETA)

Використовувалася у ранніх версіях ядра Linux (до версії 3.14) для читання та зміни виключно таблиці непрямої адресації RETA. Ця структура є застарілою, оскільки вона не підтримує налаштування ключа хешування, вибір хеш-функції та роботу з множинними RSS-контекстами.

```c
struct ethtool_rxfh_indir {
    __u32   cmd;        /* ETHTOOL_GRXFHINDIR або ETHTOOL_SRXFHINDIR */
    __u32   size;       /* Кількість елементів у масиві ring_index[] */
    __u32   ring_index[0]; /* Гнучкий масив індексів черг Rx */
};
```

- `cmd`: Ідентифікатор команди. `ETHTOOL_GRXFHINDIR` слугує для читання RETA (Get RX flow hash indirection table), а `ETHTOOL_SRXFHINDIR` — для її запису (Set RX flow hash indirection table).
- `size`: При запиті `ETHTOOL_GRXFHINDIR` приймає розмір масиву, виділеного у просторі користувача. Після повернення з виклику ядро записує у це поле реальну кількість комірок у RETA (наприклад, 128, 256 або 512). При записі `ETHTOOL_SRXFHINDIR` це поле має чітко відповідати апаратному розміру RETA.
- `ring_index`: Гнучкий масив (Flexible Array Member), у який драйвер мережевої карти копіює номери апаратних черг прийому для кожної комірки RETA.

### Структура `struct ethtool_rxfh` (Універсальний ioctl-інтерфейс RSS)

Починаючи з ядра Linux 3.14, утиліта ethtool використовує розширену структуру `struct ethtool_rxfh`. Вона дозволяє одночасно читати та змінювати таблицю RETA, секретний хеш-ключ, вибирати алгоритм хешування та вказувати ідентифікатор RSS-контексту.

```c
struct ethtool_rxfh {
    __u32   cmd;            /* ETHTOOL_GRXFHINDIR ВАМ / ETHTOOL_SRXFHINDIR */
    __u32   rss_context;    /* Ідентифікатор RSS-контексту (0 = дефолтний) */
    __u32   indir_size;     /* Кількість елементів u32 у таблиці RETA */
    __u32   key_size;       /* Розмір секретного хеш-ключа у байтах */
    __u8    hfunc;          /* Бітова маска вибору хеш-функції */
    __u8    rsvd8[3];       /* Резервні байти для вирівнювання структури */
    __u32   rsvd32;         /* Резервне поле для майбутніх розширень */
    __u32   rss_config[0];  /* Суміщений бінарний буфер RETA та HKEY */
};
```

#### Деталі буфера `rss_config`:
Пам'ять під `rss_config` виділяється одним суцільним блоком у просторі користувача:
- Перші `indir_size * sizeof(__u32)` байтів займають індекси черг RETA.
- Наступні `key_size * sizeof(__u8)` байтів займають байти секретного ключа RSS.

#### Прапорці вибору хеш-функції (`hfunc`):

- `ETH_RSS_HASH_TOP` (`0x01`): Хеш Тепліца (Toeplitz Hash). Стандарт де-факто для більшості апаратних адаптерів Intel, Mellanox та Broadcom.
- `ETH_RSS_HASH_XOR` (`0x02`): Простий XOR-хеш по полях n-tuple. Використовується для спрощеного або симетричного хешування.
- `ETH_RSS_HASH_CRC32` (`0x04`): Апаратно прискорений алгоритм обчислення контрольної суми CRC32.

### Команди ioctl для налаштування Flow Hashing (`ethtool_rxnfc`)

Для вибору полів пакетів (n-tuple), які беруть участь в обчисленні хешу для конкретного мережевого протоколу (TCP, UDP, SCTP), використовуються команди `ETHTOOL_GRXFH` та `ETHTOOL_SRXFH`.

```c
struct ethtool_rxnfc {
    __u32   cmd;            /* ETHTOOL_GRXFH або ETHTOOL_SRXFH */
    __u32   flow_type;      /* Тип мережевого потоку (TCP_V4_FLOW і т.д.) */
    __u64   data;           /* Бітова маска полів хешування (RXH_*) */
    __u32   fs;             /* Структура правила класифікатора Flow Director */
    __u32   rule_cnt;       /* Кількість активних правил у драйвері */
    __u32   rule_locs[0];   /* Масив індексів правил */
};
```

#### Значення бітової маски полів хешування `data` (`RXH_*`):

- `RXH_L2DA` (`1 << 1`): Враховувати MAC-адресу призначення Ethernet-кадра.
- `RXH_VLAN` (`1 << 2`): Враховувати тег 802.1Q VLAN.
- `RXH_L3_PROTO` (`1 << 3`): Враховувати тип протоколу L3 (IP protocol ID).
- `RXH_IP_SRC` (`1 << 4`): Враховувати IP-адресу джерела (Source IPv4/IPv6).
- `RXH_IP_DST` (`1 << 5`): Враховувати IP-адресу призначення (Destination IPv4/IPv6).
- `RXH_L4_SOCKET` (`1 << 6`): Враховувати порти джерела та призначення L4 (Source & Destination Ports).
- `RXH_DISCARD` (`1 << 31`): Скинути конфігурацію хешування для даного протоколу.

## 2. Інтерфейс Netlink (`ETHTOOL_MSG_RSS_*`)

У сучасних версіях ядра Linux (починаючи з версії 5.6) підсистему ethtool було переведено на архітектуру **Generic Netlink** (`GENL_NAMSIZ` = `"ethtool"`). Цей протокол усунув обмеження ioctl, забезпечив асинхронні сповіщення (Multicast Notifications) та дозволив гнучко передавати лише потрібні атрибути конфігурації у форматі TLV (Type-Length-Value).

Код обробки Netlink RSS розташовано у файлі ядра `net/ethtool/rss.c`.

### Основні типи командних повідомлень Netlink:

- `ETHTOOL_MSG_RSS_GET` (`18`): Запит конфігурації RSS від простору користувача до ядра.
- `ETHTOOL_MSG_RSS_SET` (`19`): Команда модифікації параметрів RSS від простору користувача до ядра.
- `ETHTOOL_MSG_RSS_ACT` (`20`): Сповіщення від ядра про зміну налаштувань RSS іншими процесами.

### Дерево атрибутів Netlink (`ETHTOOL_A_RSS_*`):

```c
enum {
    ETHTOOL_A_RSS_UNSPEC,
    ETHTOOL_A_RSS_HEADER,       /* Вкладений заголовок (ETHTOOL_A_HEADER_*) */
    ETHTOOL_A_RSS_CONTEXT,      /* u32: Ідентифікатор RSS-контексту */
    ETHTOOL_A_RSS_HFUNC,        /* u32: Хеш-функція (ETH_RSS_HASH_*) */
    ETHTOOL_A_RSS_INDIR,        /* Binary/Array: Масив u32 комірок RETA */
    ETHTOOL_A_RSS_HKEY,         /* Binary: Байтовий масив секретного ключа */
    __ETHTOOL_A_RSS_CNT,
    ETHTOOL_A_RSS_MAX = (__ETHTOOL_A_RSS_CNT - 1)
};
```

## 3. Інтерфейси псевдофайлових систем `/sys` та `/proc`

### Керування програмним масштабуванням (RPS / RFS) у `/sys`

Для кожного мережевого інтерфейсу та кожної його апаратної Rx-черги ядро Linux створює каталог у псевдофайловій системі `/sys/class/net/<iface>/queues/rx-<N>/`:

1. **`rps_cpus`** (Read/Write, Hexadecimal Bitmask):
   - Шістнадцяткова бітова маска ядер CPU, які залучаються до обробки трафіку з даної черги `rx-N` у режимі Receive Packet Steering (RPS).
   - Приклад: `echo "f" > /sys/class/net/eth0/queues/rx-0/rps_cpus` дозволяє обробку трафіку черги 0 на ядрах CPU 0–3.

2. **`rps_flow_cnt`** (Read/Write, Integer):
   - Максимальна кількість активних мережевих потоків, які відстежує підсистема Receive Flow Steering (RFS) для даної конкретної черги `rx-N`.
   - Приклад: `echo 4096 > /sys/class/net/eth0/queues/rx-0/rps_flow_cnt`.

3. **`xps_cpus`** (Read/Write, Hexadecimal Bitmask):
   - Розташований у `/sys/class/net/<iface>/queues/tx-<N>/xps_cpus`. Задає бітову маску ядер CPU для Transmit Packet Steering (XPS), що забезпечує прив'язку черг передачі Tx до тих самих ядер CPU, де виконується застосунок.

4. **Глобальні сумарні ліміти RFS**:
   - `/proc/sys/net/core/rps_sock_flow_entries`: Загальний системний ліміт сокетних потоків RFS для всіх черг у системі (наприклад, `32768`).

### Керування прив'язкою переривань (SMP Affinity) у `/proc`

Для кожної апаратної черги прийому, яка має свій вектор MSI-X переривань (номер `IRQ` з файлу `/proc/interrupts`), ядро створює віртуальний каталог у `/proc/irq/<IRQ>/`:

1. **`/proc/irq/<IRQ>/smp_affinity`** (Read/Write, Hex Bitmask):
   - Бітова маска ядер CPU, які мають право обробляти це переривання.
   - Приклад: `echo "00000001" > /proc/irq/124/smp_affinity` (прив meже IRQ 124 до ядра CPU 0).

2. **`/proc/irq/<IRQ>/smp_affinity_list`** (Read/Write, String):
   - Зручний для людини текстовий список ядер CPU.
   - Приклад: `echo "0-3" > /proc/irq/124/smp_affinity_list` (дозволяє обробку IRQ 124 на ядрах CPU 0, 1, 2 та 3).

## 4. Швидкий довідник команд `ethtool` для CLI

Нижче наведено основні команди системного адміністрування для перегляду та керування параметрами RSS, RETA та Flow Hashing з консолі:

```bash
# 1. Перегляд поточної конфігурації апаратних черг (Channels)
ethtool -l eth0

# 2. Зміна кількості комбінованих черг прийому/передачі (Combined Rx/Tx)
sudo ethtool -L eth0 combined 8

# 3. Перегляд таблиці RETA, секретного ключа RSS та активної хеш-функції
ethtool -x eth0

# 4. Встановлення рівномірного розподілу комірок RETA між 8 чергами
sudo ethtool -X eth0 equal 8

# 5. Встановлення зваженого розподілу ваг RETA (Черга 0 вимкнена, Черга 1: 50%, Черги 2 і 3: по 25%)
sudo ethtool -X eth0 weight 0 2 1 1

# 6. Перегляд полів хешування (n-tuple) для протоколу TCP v4
ethtool -n eth0 rx-flow-hash tcp4

# 7. Увімкнення повного 4-tuple хешування для UDP v4 (Src IP, Dst IP, Src Port, Dst Port)
sudo ethtool -N eth0 rx-flow-hash udp4 sdfn
```
