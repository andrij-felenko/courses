# 🧮 Математичні властивості акумулятора PCR та алгоритм Extend

Цей математичний аналіз описує фундаментальні криптографічні властивості операції `Extend` в регістрах Platform Configuration Registers (PCR) та математичний алгоритм відтворення журналу подій (Event Log Replay). Він пояснює, чому регістр PCR працює як незворотний акумулятор стану і чому спроба підробити послідовність завантаження вимагає вирішення математично нерозв'язної задачі пошуку прообразу хеш-функції.

Криптографічний захист виміряного завантаження спирається на те, що апаратний модуль не намагається аналізувати внутрішню семантику або структуру завантажуваних файлів. Замість цього він застосовує строгі математичні перетворення, які перетворюють будь-яку довільну послідовність виконаних бінарних блоків на один підсумковий криптографічний вектор.

## Математичне означення операції Extend

Регістр PCR є апаратним комірчастим регістром фіксованої довжини, що відповідає розміру виходу обраної cryptographic hash function `H` (наприклад, 256 біт для SHA-256).

Позначимо значення регістра PCR на кроці `t` як `PCR[t]`. При ввімкненні живлення (Power-On Reset) або скиданні чипа TPM регістр ініціалізується нульовим вектором (або вектором з усіх одиниць для спеціальних регістрів):

```
PCR[0] = 0x00000000...00  (N нульових байтів)
```

Операція оновлення `TPM2_Extend`, яка приймає вхідний дайджест виміряного блоку даних `D[t]`, описується криптографічною рекурентною формулою:

```
PCR[t] = H( PCR[t-1] || D[t] )
```

де:
- `||` — операція послідовного зліплювання байтових масивів (конкатенація);
- `D[t]` — хеш вимірюваного компонента, де `D[t] = H(Data[t])`;
- `H(x)` — криптографічно стійка однонапрямлена хеш-функція (SHA-256, SHA-384).

## Фундаментальні алгебраїчні властивості

### 1. Некомутативність (Order Sensitivity) та лавинний ефект

Операція `Extend` є **строго залежною від порядку виконання**. Для двох довільних вимірювань `D[1]` та `D[2]` результатом послідовності `(D[1], D[2])` є:

```
PCR[1] = H( PCR[0] || D[1] )
PCR[2] = H( PCR[1] || D[2] ) = H( H( PCR[0] || D[1] ) || D[2] )
```

Якщо поміняти порядок вимірювань місцями `(D[2], D[1])`:

```
PCR'[1] = H( PCR[0] || D[2] )
PCR'[2] = H( PCR'[1] || D[1] ) = H( H( PCR[0] || D[2] ) || D[1] )
```

Оскільки конкатенація не є комутативною (`A || B ≠ B || A`) і криптографічна функція `H` проявляє лавинний ефект (Avalanche Effect, коли зміна навіть одного біта на вході змінює в середньому 50% бітів на виході псевдовипадковим чином), з високою ймовірністю:

```
H( H( PCR[0] || D[1] ) || D[2] ) ≠ H( H( PCR[0] || D[2] ) || D[1] )
```

**Практичний наслідок**: Якщо зловмисник спробує спочатку завантажити шкідливе ядро, а потім підсунути законне ядро, або змінити порядок виконання модулів UEFI, фінальне значення регістра PCR буде абсолютно іншим. Порядок подій криптографічно зафіксовано.

### 2. Стійкість до пошуку другого прообразу (Second Pre-image Resistance)

Нехай зловмисник хоче підмінити компонент `Data[k]` на зловмисний `Data'[k]`, але зберегти фінальне значення регістра `PCR[N]` незмінним, щоб TPM видав запечений ключ.

Щоб підміна залишилася непоміченою на наступних кроках, зловмиснику потрібно знайти таке значення `D'[k] = H(Data'[k])`, щоб:

```
H( PCR[k-1] || D'[k] ) = H( PCR[k-1] || D[k] )
```

Це вимагає знаходження колізії або другого прообразу для криптографічної хеш-функції `H`. Для SHA-256 складність цього пошуку становить `2^256` операцій (або `2^128` за парадоксом днів народження для пошуку довільної колізії), що є фізично неможливим на сучасному та перспективному обчислювальному обладнанні.

### 3. Незворотність стану (One-Way Accumulator)

Зчитуючи поточне значення `PCR[t]`, неможливо математично "відмотати" стан назад до `PCR[t-1]` або вилучити з нього конкретне вимірювання `D[t]`.

Спроба виразити `PCR[t-1]` через `PCR[t]` вимагає обернення функції `H`:

```
PCR[t-1] = H⁻¹( PCR[t] ) \ D[t]
```

Оскільки `H⁻¹` не існує за означенням криптографічної хеш-функції, простір користувача або ядро не мають жодних криптографічних засобів для видалення записів з PCR без повного апаратного скидання чипа TPM.

## Математика обчислення політик довіри TPM2_PolicyPCR

Коли об'єкт у TPM 2.0 (наприклад, ключ шифрування LUKS2) запечатується під певний стан PCR, TPM створює так зване **дайджест-дерево політики** (`policyDigest`).

Операція розпечатування вимагає створення сесії авторизації (Policy Session). Внутрішній стан дайджесту політики `PolicyDigest[k]` оновлюється командою `TPM2_PolicyPCR` за наступною формулою:

```
PolicyDigest[k] = H( PolicyDigest[k-1] || TPM_CC_PolicyPCR || pcrSelection || expectedPcrDigest )
```

де:
- `TPM_CC_PolicyPCR` — 32-бітний код інструкції команди політики (`0x0000017E`);
- `pcrSelection` — бітова структура, що описує перелік вибраних регістрів PCR;
- `expectedPcrDigest` — хеш конкатенації очікуваних значень обраних регістрів PCR: `H( PCR[idx1] || PCR[idx2] || ... )`.

Під час виклику цієї команди чип TPM 2.0 прочитує дійсні апаратні регістри `PCR[idx1], PCR[idx2]`, обчислює їхній поточний дайджест і порівнює його з `expectedPcrDigest`. Якщо поточний стан збігається, TPM модифікує внутрішній `PolicyDigest` сесії. Якщо наприкінці сесії `PolicyDigest` збігається із запеченим у об'єкті хешем — ключ розпечатується.

## Математична структура твердження TPM2_Quote та зв'язок із Nonce

Для віддаленої атестації чип TPM виконує математичне підписання поточного стану обраних регістрів PCR за допомогою власного апаратного ключа атестації (Attestation Key, AK).

Щоб віддалений сервер переконався, що знімок PCR згенеровано саме зараз, а не записано заздалегідь під час попереднього успішного завантаження (захист від атак повторного відтворення Replay Attacks), використовується одноразове випадкове число **Nonce**.

Математична форма підпису командою `TPM2_Quote` описується формулою:

```
Quote_Digest = H( TPMS_ATTEST_HEADER || H( PCR_Select_Mask || Composite_PCR_Digest ) || Nonce )
Signature = Sign_AK_Private( Quote_Digest )
```

де:
- `Composite_PCR_Digest` — це хеш конкатенації всіх обраних регістрів PCR: `H( PCR[a] || PCR[b] || ... || PCR[z] )`;
- `PCR_Select_Mask` — бітова маска, яка вказує, які саме регістри PCR вимірювалися;
- `Nonce` — псевдовипадкова послідовність (зазвичай 256 біт), згенерована сервером-чекером;
- `Sign_AK_Private` — алгоритм цифрового підпису (RSA-2048 або ECDSA P-256) приватною частиною ключа AK.

Оскільки `Nonce` входить під загальний дайджест підпису `Quote_Digest`, підробити підпис чи використати старий Quote для іншого запиту математично неможливо.

## Математичний алгоритм відтворення журналу подій (Log Replay)

Оскільки регістр PCR зберігає лише один фінальний дайджест `PCR[N]`, перевірка цілісності системи вимагає алгоритму відтворення (Replay Verification) на основі журналу подій `L = [e[1], e[2], ..., e[N]]`.

Кожен запис журналу `e[i]` містить заявлений дайджест `e[i].digest` та метадані події `e[i].event_data`.

### Покроковий алгоритм перевірки:

```
[Крок 1: Ініціалізація локального акумулятора]
R = 0x00000000...00  (масив з N нульових байтів)

[Крок 2: Ітеративне відтворення кожної події журналу]
Для кожного запису e[i] від i = 1 до N:
    1. Перевірка дайджесту події (якщо лог містить сирі дані):
       assert e[i].digest == H( e[i].event_data )
    
    2. Симуляція апаратної операції Extend:
       R = H( R || e[i].digest )

[Крок 3: Апаратне зіставлення з TPM]
TPM_PCR = TPM2_ReadPCR( pcr_index )

Якщо R == TPM_PCR:
    Висновок: Журнал подій цілісний та автентичний.
Інакше:
    Висновок: Журнал підроблено або систему скомпрометовано.
```

Якщо перевірка на Кроці 3 повертає рівність `R == TPM_PCR`, математично доведено, що журнал подій `L` описує точну послідовність і вміст усіх компонентів, завантажених системою з моменту ввімкнення живлення.
