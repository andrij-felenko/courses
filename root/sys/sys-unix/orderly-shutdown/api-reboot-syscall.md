# Системний виклик `reboot(2)`: магія чисел

Під капотом усі команди вимкнення та перезавантаження в Linux зрештою зводяться до одного системного виклику — `reboot(2)`. Сирий виклик до ядра має дуже специфічну сигнатуру, розроблену для захисту від випадкового виклику:

```c
/* сирий системний виклик, як його бачить ядро */
int reboot(int magic, int magic2, int cmd, void *arg);

/* обгортка glibc: магічні числа вона підставляє сама */
int reboot(int cmd);
```

Саме тому в коді на C зазвичай видно однослівне `reboot(RB_POWER_OFF)` — магію туди вже вписала бібліотека.

Щоб виклик вдався, потрібно передати два "магічних" числа (magic numbers). Ці числа є даниною історії Лінуса Торвальдса та його родини.

- `magic` **завжди** повинен дорівнювати `LINUX_REBOOT_MAGIC1` (`0xfee1dead`).
- `magic2` може бути одним із чотирьох значень. Наприклад, `672274793` (`LINUX_REBOOT_MAGIC2`), що в шістнадцятковій системі дорівнює `0x28121969` (28 грудня 1969 року — дата народження Лінуса Торвальдса). Решта три представляють дати народження його доньок:

```
LINUX_REBOOT_MAGIC2   = 672274793  = 0x28121969  → 28.12.1969
LINUX_REBOOT_MAGIC2A  =  85072278  = 0x05121996  → 05.12.1996
LINUX_REBOOT_MAGIC2B  = 369367448  = 0x16041998  → 16.04.1998
LINUX_REBOOT_MAGIC2C  = 537993216  = 0x20112000  → 20.11.2000
```

Лише якщо обидва числа правильні, ядро перейде до виконання команди `cmd`, такої як `LINUX_REBOOT_CMD_POWER_OFF` (вимкнення) або `LINUX_REBOOT_CMD_RESTART` (перезавантаження). Це гарантує, що випадковий стрибок пам'яті в простір ядра не призведе до випадкового вимкнення сервера.
