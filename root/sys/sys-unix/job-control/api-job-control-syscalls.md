# 📋 Системні виклики та термінальні інтерфейси керування завданнями

Цей довідник описує повний набір системних викликів POSIX, прапорців термінала та сигнальної семантики, що забезпечують тристоронній арбітраж груп процесів над управляючим терміналом у системі Unix. Матеріал структуровано за категоріями: управління ідентифікаторами процесів та сеансів, передача володіння терміналом, розширена конфігурація дисципліни лінії N_TTY, точна сигнальна дисципліна ядра та моніторинг стану нащадків через `waitpid`.

---

## 1. Системні виклики ідентифікаторів груп та сеансів

Перегрупування процесів та ізоляція сеансів є основою для побудови моделей керування завданнями. Системні виклики `setpgid`, `getpgid`, `getpgrp` та `setsid` регулюють приналежність процесів до контейнерів виконання.

```c
#include <unistd.h>
#include <sys/types.h>

int setpgid(pid_t pid, pid_t pgid);
pid_t getpgid(pid_t pid);
pid_t getpgrp(void);
pid_t setsid(void);
```

### setpgid

Призначає ідентифікатор групи процесів `pgid` для процесу з номером `pid`.

- **Параметри та їхні спеціальні значення:**
  - `pid`: Ідентифікатор цільового процесу. Якщо `pid == 0`, виклик застосовується до поточного викликаючого процесу (`getpid()`).
  - `pgid`: Новий ідентифікатор групи процесів. Якщо `pgid == 0`, значення PGID встановлюється рівним PID вказаного процесу (`pid`), створюючи нову групу процесів, де процес `pid` стає її лідером.
- **Правила поведінки та внутрішні обмеження ядра Linux:**
  - Процес може змінити PGID лише собі або своїм прямим нащадкам (`forked children`).
  - Процес не має права змінювати PGID нащадка після того, як той виконав системний виклик `execve()`. Спроба викликати `setpgid` після `execve()` повертає помилку `EACCES`.
  - Усі процеси, що об'єднуються у групу `pgid`, повинні належати до одного й того самого сеансу (`Session`). Спроба об'єднати процеси з різних сеансів повертає `EPERM`.
  - Процес-лідер сеансу (`Session Leader`) не має права змінювати свій PGID. Його PGID назавжди залишається рівним його PID.
- **Коди повернення та помилки (`errno`):**
  - `0`: Успішне створення або приєднання до групи процесів.
  - `-1`: Помилка з оновленням `errno`:
    - `EACCES`: Спроба змінити PGID нащадка, який уже викликав `execve()`.
    - `EINVAL`: Некоректне значення `pgid` (менше нуля).
    - `EPERM`: Спроба перемістити процес у групу з іншого сеансу, або спроба змінити PGID лідера сеансу, або спроба створити групу у чужому сеансі.
    - `ESRCH`: Процес з вказаним `pid` не існує у системній таблиці процесів.

### getpgid та getpgrp

- `pid_t getpgid(pid_t pid)`: Повертає ідентифікатор групи процесів (PGID) для процесу `pid`. Якщо `pid == 0`, повертає PGID поточного викликаючого процесу. При виникненні помилки (наприклад, процес `pid` не знайдено) повертає `(pid_t)-1` та встановлює `errno = ESRCH`.
- `pid_t getpgrp(void)`: Повертає PGID поточного викликаючого процесу. Відповідно до стандарту POSIX.1-2001 виклик не приймає аргументів і еквівалентний `getpgid(0)`.

### setsid

Створює новий сеанс і нову групу процесів, якщо викликаючий процес не є лідером групи процесів.

- **Семантика виконання:**
  - Викликаючий процес стає лідером нового сеансу (`Session Leader`) та лідером нової групи процесів.
  - SID новоствореного сеансу та PGID нової групи процесів встановлюються рівними PID викликаючого процесу.
  - Викликаючий процес втрачає зв'язок з управляючим терміналом (`Controlling Terminal`). Будь-який відкритий дескриптор TTY втрачає свій статус управляючого.
- **Помилки та обмеження:**
  - `EPERM`: Помилка виникає, якщо викликаючий процес уже є лідером групи процесів (`getpid() == getpgid(0)`). Щоб гарантовано викликати `setsid()`, програма повинна виконати `fork()`, завершити батьківський процес, і викликати `setsid()` у нащадку.

## 2. Інтерфейси арбітражу управляючого термінала

Передача права переднього плану (`Foreground`) для читання та запису з термінала здійснюється за допомогою викликів `tcsetpgrp`, `tcgetpgrp` та `tcgetsid`.

```c
#include <unistd.h>
#include <termios.h>

int tcsetpgrp(int fd, pid_t pgrp);
pid_t tcgetpgrp(int fd);
pid_t tcgetsid(int fd);
```

### tcsetpgrp

Встановлює групу процесів `pgrp` як групу переднього плану (`Foreground Process Group`) для управляючого термінала, пов'язаного з файловим дескриптором `fd`.

- **Параметри та умови:**
  - `fd`: Файловий дескриптор відкритого управляючого термінала (зазвичай `STDIN_FILENO` або дескриптор, отриманий через `open("/dev/tty", O_RDWR)`).
  - `pgrp`: Ідентифікатор групи процесів, яка стає фокусною групою термінала.
- **Умови успішного виконання:**
  - Група процесів `pgrp` повинна належати до того ж сеансу, що й викликаючий процес.
  - Файловий дескриптор `fd` повинен описувати управляючий термінал викликаючого сеансу.
- **Сигнальні побічні ефекти:**
  - Якщо `tcsetpgrp()` викликається процесом, що належить до **фонової** групи процесів, і сигнал `SIGTTOU` не заблоковано у сигнальній масці і не ігнорується, ядро надсилає сигнал `SIGTTOU` усій фоновій групі процесів. Це призупиняє викликаючий процес до його повернення на передній план.
- **Коди помилок (`errno`):**
  - `EBADF`: `fd` не є дійсним файловим дескриптором.
  - `EINVAL`: `pgrp` має некоректне або від'ємне значення.
  - `ENOTTY`: Процес не має управляючого термінала, або `fd` описує файл/сокет, який не є TTY.
  - `EPERM`: Група `pgrp` не належить до сеансу викликаючого процесу.

### tcgetpgrp

Повертає PGID фокусної (`Foreground`) групи процесів для термінала `fd`.

- **Повернене значення:**
  - Повертає PGID фокусної групи процесів (значення більше 1).
  - Якщо термінал наразі не має групи переднього плану, повертає значення більше 1, яке не збігається з жодною існуючою групою, або повертає `-1` з встановленням `errno = ENOTTY`.

### tcgetsid

Повертає ідентифікатор сеансу (SID), пов'язаного з управляючим терміналом `fd`.

- Повертає SID сеансу або `-1` при помилці (`ENOTTY`, якщо `fd` не є управляючим терміналом).

## 3. Конфігурація termios та дисципліна лінії N_TTY

Управління генерацією сигналів з клавіатури та блокуванням фонового виводу здійснюється через структуру `struct termios`.

```c
#include <termios.h>

int tcgetattr(int fd, struct termios *termios_p);
int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);
```

### Структура struct termios

```c
struct termios {
    tcflag_t c_iflag;      /* Прапорці вхідного режиму */
    tcflag_t c_oflag;      /* Прапорці вихідного режиму */
    tcflag_t c_cflag;      /* Прапорці керування лінією */
    tcflag_t c_lflag;      /* Прапорці локального режиму */
    cc_t      c_line;       /* Дисципліна лінії */
    cc_t      c_cc[NCCS];   /* Масив управляючих символів */
    speed_t   c_ispeed;     /* Вхідна швидкість передачі */
    speed_t   c_ospeed;     /* Вихідна швидкість передачі */
};
```

### Параметр optional_actions для tcsetattr

| Дія | Опис та семантика |
|---|---|
| `TCSANOW` | Зміни атрибутів термінала застосовуються негайно. |
| `TCSADRAIN` | Зміни застосовуються після того, як усі записані у `fd` байти будуть фізично передані на пристрій. Рекомендовано при зміні вихідних параметрів. |
| `TCSAFLUSH` | Зміни застосовуються після передачі всіх вихідних даних, при цьому всі накопичені незчитані вхідні байти у буфері прийому відкидаються. |

### Ключові прапорці локального режиму (`c_lflag`)

| Прапорець | Опис | Вплив на керування завданнями |
|---|---|---|
| `ISIG` | Вмикає розпізнавання управляючих символів. | При отриманні `VINTR`, `VQUIT`, `VSUSP` або `VDSUSP` драйвер генерує відповідні сигнали для foreground PGID. Якщо прапорець скинуто, `Ctrl+C` та `Ctrl+Z` передаються у програму як звичайні байти. |
| `TOSTOP` | Забороняє фоновий вивід на екран. | Якщо увімкнено, спроба фонового процесу виконати `write()` на термінал викликає надсилання сигналу `SIGTTOU` усій фоновій групі. |
| `ICANON` | Канонічний режим вводу. | Вхідні байти збираються буфером порядково до символу нового рядка `\n`. |
| `ECHO` | Автоматичне ехо символів. | Вхідні символи автоматично виводяться на екран термінала. |

### Масив управляючих символів `c_cc`

| Спецсимвол | Індекс масиву | Типове значення | Згенерований сигнал | Опис |
|---|---|---|---|---|
| `VINTR` | `c_cc[VINTR]` | `0x03` (`Ctrl+C`) | `SIGINT` | Переривання виконання процесу переднього плану. |
| `VQUIT` | `c_cc[VQUIT]` | `0x1C` (`Ctrl+\`) | `SIGQUIT` | Аварійне завершення процесу з дампами пам'яті (`core dump`). |
| `VSUSP` | `c_cc[VSUSP]` | `0x1A` (`Ctrl+Z`) | `SIGTSTP` | Призупинення виконання передньопланового завдання. |
| `VDSUSP` | `c_cc[VDSUSP]` | `0x19` (`Ctrl+Y`) | `SIGDSUSP` | Призупинення завдання у момент читання з термінала (BSD). |
| `VSTART` | `c_cc[VSTART]` | `0x11` (`Ctrl+Q`) | Немає (XON) | Відновлення виводу на термінал після паузи. |
| `VSTOP` | `c_cc[VSTOP]` | `0x13` (`Ctrl+S`) | Немає (XOFF) | Призупинення виводу на термінал. |

## 4. Сигнали керування завданнями та сигнальна дисципліна ядра

Сигнали керування завданнями обробляються ядром Linux за спеціальною семантикою. Деякі сигнали неможливо перехопити, а сигнал `SIGCONT` має властивість скидати невиконані сигнали зупинки.

| Сигнал | Номер (x86_64) | Типова дія ядра | Можливість перехоплення | Опис та вплив на стан процесу |
|---|---|---|---|---|
| `SIGINT` | 2 | Завершення (Term) | Так | Завершує процес або викликає обробник. |
| `SIGQUIT` | 3 | Завершення + Core | Так | Завершує процес із створенням знімка пам'яті. |
| `SIGTSTP` | 20 | Зупинка (Stop) | Так | Переводить процес у стан `TASK_STOPPED`. Генерується з клавіатури (`Ctrl+Z`). |
| `SIGSTOP` | 19 | Зупинка (Stop) | **Ні** | Атомарно зупиняє процес. Управлювачі не можуть його заблокувати чи перехопити. |
| `SIGCONT` | 18 | Продовження (Cont) | Так | Пробуджує процес зі стану `TASK_STOPPED` у `TASK_RUNNING`. Очищує невиконані сигнали зупинки. |
| `SIGTTIN` | 21 | Зупинка (Stop) | Так | Надсилається фоновому процесу при спробі `read()` з TTY. |
| `SIGTTOU` | 22 | Зупинка (Stop) | Так | Надсилається фоновому процесу при спробі `write()` з TTY (при `TOSTOP=1`) або при `tcsetattr()`. |
| `SIGHUP` | 1 | Завершення (Term) | Так | Надсилається при втраті носія термінала або закритті сеансу. |

### Взаємодія сигналів SIGCONT та сигналів зупинки

Ядро Linux підтримує інваріант взаємного виключення між `SIGCONT` та сигналами зупинки (`SIGSTOP`, `SIGTSTP`, `SIGTTIN`, `SIGTTOU`):

1. **Коли ядро надсилає `SIGCONT` процесу:**
   - Усі невиконані (`pending`) сигнали зупинки (`SIGSTOP`, `SIGTSTP`, `SIGTTIN`, `SIGTTOU`) для цього процесу негайно **видаляються** з черги сигналів процесу.
   - Процес переводиться зі стану `TASK_STOPPED` у стан `TASK_RUNNING` і додається до черги планувальника.
   - Якщо для `SIGCONT` встановлено користувацький обробник, він викликається після відновлення виконання.
2. **Коли ядро надсилає будь-який сигнал зупинки (`SIGSTOP`, `SIGTSTP`, `SIGTTIN`, `SIGTTOU`):**
   - Невиконаний сигнал `SIGCONT` у черзі процесу атомарно **видаляється**.

## 5. Моніторинг стану нащадків через waitpid

Оболонка відстежує зміну стану процесів у завданнях за допомогою розширених прапорців `waitpid`.

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t waitpid(pid_t pid, int *wstatus, int options);
```

### Прапорці аргументу options

- `WUNTRACED`: Повертає статус також для тих процесів-нащадків, які були **зупинені** (наприклад, через `SIGTSTP`, `SIGTTIN`, `SIGTTOU` або `SIGSTOP`), але чий новий статус ще не був прочитаний оболонкою.
- `WCONTINUED`: Повертає статус для зупинених нащадків, які були **відновлені** надсиланням сигналу `SIGCONT`.
- `WNOHANG`: Неблокуючий режим: негайно повертає 0, якщо жоден нащадок не змінив свій стан.

### Макроси аналізу значення wstatus

| Макрос | Значення та умови повернення |
|---|---|
| `WIFEXITED(status)` | Повертає true, якщо нащадок завершився штатно (через `exit()` або `return` з `main`). |
| `WEXITSTATUS(status)` | Повертає код повернення (нижні 8 біт), якщо `WIFEXITED` є true. |
| `WIFSIGNALED(status)` | Повертає true, якщо нащадок був неперехоплено вбитий сигналом (`SIGINT`, `SIGKILL` тощо). |
| `WTERMSIG(status)` | Повертає номер сигналу, який спричинив загибель процесу. |
| `WIFSTOPPED(status)` | Повертає true, якщо нащадок перейшов у стан **зупинено** (`TASK_STOPPED`). |
| `WSTOPSIG(status)` | Повертає номер сигналу, який зупинив процес (`SIGTSTP`, `SIGTTIN`, `SIGTTOU` тощо). |
| `WIFCONTINUED(status)` | Повертає true, якщо процес було відновлено сигналом `SIGCONT`. |

## 6. Низькорівневий ioctl-інтерфейс TTY

Системні виклики `tcsetpgrp` та `tcgetpgrp` у Лінукс реалізовані як зручні обгортки над системним викликом `ioctl` для файлового дескриптора термінала.

```c
#include <sys/ioctl.h>

int ioctl(int fd, unsigned long request, ...);
```

### Запити ioctl керування завданнями

- `TIOCSPGRP` (аргумент `const pid_t *pgrp`): Встановити фокусну групу процесів переднього плану (еквівалент `tcsetpgrp`).
- `TIOCGPGRP` (аргумент `pid_t *pgrp`): Отримати ідентифікатор фокусної групи процесів переднього плану (еквівалент `tcgetpgrp`).
- `TIOCGSID` (аргумент `pid_t *sid`): Отримати ідентифікатор сеансу, якому належить термінал `fd`.
- `TIOCNOTTY`: Від'єднати викликаючий процес від його управляючого термінала (історичний метод створення демонів у BSD до появи `setsid`).
