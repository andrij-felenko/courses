# 📋 Довідник інтерфейсів seqlock у ядрі Linux

Послідовні замки у ядрі Linux розділені на два фундаментальні рівні абстракції: чисті лічильники послідовності (`seqcount_t`) та повноцінні автономні примітиви блокування з вбудованим спін-замком (`seqlock_t`). Перша категорія застосовується тоді, коли захист письменника від інших письменників вже вибудувано зовнішніми механізмами ядра (наприклад, окремим м'ютексом або спін-замком), а друга надає повністю самодостатній примітив синхронізації.

---

## 1. Архітектурні типи даних та структури

### `seqcount_t` — базовий лічильник послідовності

Це мінімалістична структура, що зберігає лише 32-бітне беззнакове ціле число `sequence`. Цей тип використовують у тих підсистемах ядра, які вже мають власний замок для письменників (наприклад, `spinlock_t` або `struct mutex`). Додавання другого спін-замка всередину seqlock було б надлишковим витрачанням пам'яті та дорогоцінних тактів процесора.

```c
typedef struct seqcount {
    unsigned sequence;
#ifdef CONFIG_DEBUG_LOCK_ALLOC
    struct lockdep_map dep_map;
#endif
} seqcount_t;
```

Коли у конфігурації ядра увімкнено відлагоджувальний режим `CONFIG_DEBUG_LOCK_ALLOC`, структура розширюється полем відстеження Lockdep (`dep_map`), яке фіксує стеки викликів та приналежність до системних контекстів виконання.

### Асоційовані типи `seqcount` для динамічного аналізу Lockdep

Для того щоб підсистема динамічного аналізу коректності блокувань Lockdep мала змогу перевіряти, яким саме замком захищається письменник, у сучасних версіях ядра Linux введено спеціалізовані асоційовані типи лічильників:

- **`seqcount_spinlock_t`:** Лічильник послідовності, прив'язаний до об'єкта `spinlock_t`. Використовується за замовчуванням у більшості стандартних структур ядра.
- **`seqcount_raw_spinlock_t`:** Лічильник, прив'язаний до примітиву `raw_spinlock_t`. Використовується у низькорівневих обробниках переривань та у системному ядрі реального часу `PREEMPT_RT`, де звичайні спін-замки перетворені на м'ютекси із засинанням.
- **`seqcount_mutex_t`:** Лічильник, прив'язаний до стандартного м'ютекса ядра `struct mutex`. Дозволяє потіку-письменнику виконувати тривалі операції або засинати у критичній секції запису, але вимагає спеціального реагування з боку читачів для запобігання нескінченного спінінгу.
- **`seqcount_rwlock_t`:** Лічильник, прив'язаний до зчитувально-письменницького замка `rwlock_t` — для підсистем, де письменників кілька й вони вже впорядковані таким замком.

Асоційовані типи дозволяють інструментарію Lockdep здійснювати статичний та динамічний контроль: якщо розробник спробує викликати `write_seqcount_begin()` без попереднього захоплення відповідного прив'язаного замка, ядро надрукує детальний звіт про помилку.

### `seqlock_t` — автономний послідовний замок

Структура `seqlock_t` є повним самодостатнім примітивом, який об'єднує всередині себе `seqcount_spinlock_t` та класичний спін-замок `spinlock_t`.

```c
typedef struct {
    seqcount_spinlock_t seqcount;
    spinlock_t lock;
} seqlock_t;
```

Цей тип застосовується тоді, коли захищається окрема автономна структура даних, що не має власного зовнішнього замка.

## 3. Інтерфейси письменника (Writer APIs)

Операції письменника вимагають обов'язкового виключного доступу. Функції для `seqlock_t` автоматично виконують дві дії: захоплюють внутрішній спін-замок та збільшують лічильник послідовності `sequence`.

### Сигнатури та вибір контексту для `seqlock_t`

:::code api-kernel-seqlocks/c/syhnatury-ta-vybir.h

Правило суворого вибору варіанта для письменника:
- Якщо читач може викликатися з обробника апаратного переривання (`hardirq`), письменник зобов'язаний використовувати **`write_seqlock_irqsave()`**, щоб не припуститися взаємного блокування на одному процесорному ядрі.
- Якщо читач викликається з контексту тасклета або м'якого переривання (`softirq`), письменник використовує **`write_seqlock_bh()`**, вимикаючи нижні половини.
- Якщо читач і письменник працюють виключно у контексті процесів, достатньо використовувати **`write_seqlock()`**.

### Сигнатури для `seqcount_t` (Зовнішнє блокування)

Якщо письменник захищений зовнішнім м'ютексом або спін-замком, він викликає безпосередні операції зміни лічильника:

## 6. Діагностика Lockdep, асерти та розшифровка помилок

При включенні параметра конфігурації ядра `CONFIG_PROVE_LOCKING` підсистема Lockdep здійснює суворий контроль за дотриманням правил користування seqlock:

1. **Макрос перевірки захоплення замка:** У коді письменника можна використовувати макрос `lockdep_assert_held(&sl->lock)`, який друкує попередження зі стеком викликів у `dmesg`, якщо спін-замок не було захоплено перед модифікацією `seqcount`.
2. **Запис без прив'язаного замка:** Якщо потік викликає `write_seqcount_begin()` на асоційованому `seqcount_spinlock_t`, а спін-замка через `spin_lock()` не захопив, спрацьовує вбудована перевірка прив'язаного замка й ядро друкує попередження зі стеком. Це означає, що розробник порушив контракт і залишив небезпеку паралельного запису іншим письменником.
3. **Помилка контексту переривань:** Якщо той самий `seqlock_t` пишуть з обробника апаратного переривання, а десь у контексті процесу той-таки замок беруть звичайним `write_seqlock()` без вимкнення переривань, Lockdep позначить клас замка як `HARDIRQ-safe`, побачить `HARDIRQ-unsafe` захоплення й видасть звіт із заголовком виду `WARNING: HARDIRQ-safe -> HARDIRQ-unsafe lock order detected` — ще до того, як переривання справді вклиниться. Підказка звіту одна: письменник у контексті процесу повинен перейти на `write_seqlock_irqsave()`.
   Важлива межа цього інструмента: **читача seqlock Lockdep не бачить взагалі**. Читач нічого не захоплює, тож у `current->held_locks` не з'являється жодного запису — і класичний глухий кут «письменник у контексті процесу проти читача в обробнику переривання» не діагностується автоматично. Це правило доводиться тримати в голові й перевіряти очима.
4. **Виявлення непарності при виході:** Якщо розробник припустився помилки у відгалуженні коду і забув викликати `write_sequnlock()`, Lockdep при поверненні із системного виклику зафіксує незвільнений замок у списку `current->held_locks` і надрукує попередження про витік замка.
