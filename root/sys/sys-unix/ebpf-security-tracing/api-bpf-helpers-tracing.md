# 📋 Інтерфейси та допоміжні функції BPF для моніторингу безпеки

Під час розробки eBPF-програм для моніторингу та аудиту безпеки ядро Linux надає спеціальний набір допоміжних функцій (BPF Helper Functions). Ці функції дозволяють безпечно зчитувати контекст системних процесів, аналізувати структури пам'яті ядра та користувацького простору, а також передавати сформовані події у простір користувача.

Нижче наведено систематичний довідник ключових API ядра, які використовуються у програмах типів `BPF_PROG_TYPE_KPROBE`, `BPF_PROG_TYPE_TRACEPOINT`, `BPF_PROG_TYPE_TRACING` (fentry/fexit) та `BPF_PROG_TYPE_LSM`.

---

## 1. Функції отримання контексту процесу та ідентифікаторів

### `bpf_get_current_pid_tgid`

Отримує ідентифікатор потоку (Thread ID) та ідентифікатор групи потоків (Process ID) потоку, у контексті якого виконується BPF-програма.

```c
u64 bpf_get_current_pid_tgid(void);
```

- **Значення повернення:** 64-бітне ціле число. Старші 32 біти містять Process ID (`tgid`), молодші 32 біти — Thread ID (`pid`).
- **Вилучення PID та TID:**
  ```c
  u64 pid_tgid = bpf_get_current_pid_tgid();
  u32 pid = pid_tgid >> 32;   // Реальний PID у просторі користувача
  u32 tid = (u32)pid_tgid;    // TID (потік)
  ```

---

### `bpf_get_current_uid_gid`

Повертає реальні (не ефективні) ідентифікатори користувача (UID) та групи (GID) поточного процесу, перелічені у початковому просторі імен користувачів `init_user_ns`.

```c
u64 bpf_get_current_uid_gid(void);
```

- **Значення повернення:** 64-бітне ціле число. Молодші 32 біти містять `uid`, старші 32 біти — `gid`.
- **Вилучення UID та GID:**
  ```c
  u64 uid_gid = bpf_get_current_uid_gid();
  u32 uid = (u32)uid_gid;
  u32 gid = uid_gid >> 32;
  ```

---

### `bpf_get_current_comm`

Зчитує назву виконуваного файла поточного процесу (поле `comm` зі структури `struct task_struct`).

```c
long bpf_get_current_comm(void *buf, u32 size_of_buf);
```

- **Аргументи:**
  - `buf`: вказівник на буфер пам'яті (мінімальний рекомендований розмір 16 байт).
  - `size_of_buf`: розмір буфера (зазвичай `TASK_COMM_LEN`, що дорівнює 16).
- **Значення повернення:** `0` при успіху, або від'ємний код помилки.
- **Примітка безпеки:** Назва `comm` не є надійним критерієм ідентифікації процесу, оскільки процес може змінити її через `prctl(PR_SET_NAME)`.

---

### `bpf_get_current_cgroup_id`

Повертає унікальний 64-бітний ідентифікатор v2 cgroup, до якої належить поточний процес.

```c
u64 bpf_get_current_cgroup_id(void);
```

- **Використання в безпеці:** Ключова функція для сортування й прив'язки подій аудиту до конкретних контейнерів Docker або Kubernetes Pods у хмарних середовищах.

---

## 2. Функції безпечного читання пам'яті

Оскільки BPF-програма виконується у ядрі, пряме розіменування довільних вказівників пам'яті заборонене верифікатором. Для зчитування даних використовуються спеціалізовані функції групи `bpf_probe_read`.

### `bpf_probe_read_user_str`

Зчитує рядок із завершальним нульовим байтом (null-terminated string) із простору користувача у буфер BPF-програми.

```c
long bpf_probe_read_user_str(void *dst, u32 size, const void *unsafe_ptr);
```

- **Аргументи:**
  - `dst`: буфер BPF-програми (на стеку або в BPF-мапі).
  - `size`: максимальний розмір зчитування.
  - `unsafe_ptr`: вказівник на пам'ять простору користувача (наприклад, шлях до файла в аргументах `execve`).
- **Значення повернення:** Довжина зчитаного рядка (включаючи нульовий байт) при успіху, або від'ємний код помилки (наприклад, `-EFAULT`).

---

### `bpf_probe_read_kernel_str`

Аналогічна функція для безпечного зчитування рядка з пам'яті ядра Linux (наприклад, із полів структури `struct path` або `struct dentry`).

```c
long bpf_probe_read_kernel_str(void *dst, u32 size, const void *unsafe_ptr);
```

---

## 3. Інтерфейси передачі подій через BPF Ring Buffer

З версії ядра Linux 5.8 для передачі подій аудиту у простір користувача використовується BPF Ring Buffer API.

### `bpf_ringbuf_reserve`

Зарезервує ділянку пам'яті у кільцевому буфері під структуру події безпеки.

```c
void *bpf_ringbuf_reserve(void *ringbuf, u64 size, u64 flags);
```

- **Аргументи:**
  - `ringbuf`: вказівник на мапу типу `BPF_MAP_TYPE_RINGBUF`.
  - `size`: розмір структури події у байтах.
  - `flags`: прапори (зазвичай `0`).
- **Значення повернення:** Вказівник на виділену ділянку у спільній пам'яті, або `NULL`, якщо буфер переповнений.
- **Обов'язкове правило:** Верифікатор вимагає обов'язкової перевірки поверненого вказівника на `NULL` перед записом даних.

---

### `bpf_ringbuf_submit`

Фіксує заповнену структуру події та робить її доступною для читання демоном у просторі користувача.

```c
void bpf_ringbuf_submit(void *data, u64 flags);
```

- **Аргументи:**
  - `data`: вказівник, отриманий з `bpf_ringbuf_reserve`.
  - `flags`: прапори сповіщення (наприклад, `BPF_RB_NO_WAKEUP` для запобігання зайвим перериванням).

---

### `bpf_ringbuf_discard`

Скасовує зарезервовану ділянку пам'яті у кільцевому буфері без передачі події у простір користувача (наприклад, якщо фільтрація BPF визначила подію як безпечну).

```c
void bpf_ringbuf_discard(void *data, u64 flags);
```

---

## 4. Інтерфейси активного впливу та реагування на загрози

### `bpf_send_signal`

Надсилає POSIX-сигнал поточному процесу, який викликав критичну подію безпеки.

```c
long bpf_send_signal(u32 sig);
```

- **Аргументи:** `sig` — номер сигналу (наприклад, `SIGKILL` = 9 або `SIGSTOP` = 19).
- **Використання в безпеці:** Дозволяє BPF-програмі негайно термінувати процес при виявленні несанкціонованої аномалії (наприклад, при спробі ін'єкції коду або аварійній зміні UID).

---

### `bpf_override_return`

Змінює значення повернення системного виклику ядра, спричиняючи його дострокове завершення з кодом помилки.

```c
long bpf_override_return(struct pt_regs *regs, unsigned long rc);
```

- **Аргументи:**
  - `regs`: вказівник на регістри процесора.
  - `rc`: код помилки, який отримує додаток у просторі користувача (наприклад, `-EPERM`).
- **Обмеження:** Функція доступна лише для системних викликів, які явним чином позначені у ядрі макросом `ALLOW_ERROR_INJECTION()`, і вимагає привілей `CAP_SYS_ADMIN`.
