# 📋 API визначення термінала й керування машинністю виводу

При проєктуванні системних утиліт, демонів та консольних інструментів в операційних системах сімейства Unix та Linux виникає потреба динамічно адаптувати формат виводу до контексту виклику. Інтерактивний користувач очікує кольорові символи ANSI, форматовані таблиці з вирівнюванням по ширині екрана, скорочені одиниці вимірювання (кілобайти, мегабайти) та інтерактивні прогрес-бари. Навпаки, автоматизований скрипт, фоновий сервіс або наступна ланка конвеєра (`pipeline`) вимагають детермінованого, строго типізованого потоку даних без оформлювального сміття — табуляційних розділювачів (TSV), сирих числових значень у байтах або валідних документів JSON.

Цей довідник містить вичерпний опис системних викликів ядра Linux, функцій стандартної бібліотеки C (libc), структур даних `termios`, керуючих команд `ioctl`, стандартів змінних середовища та параметрів командного рядка для реалізації надійного машинного виводу.

## 1. Системні виклики та низькорівнева взаємодія з драйвером TTY

Головним критерієм вибору між людським та машинним режимом є перевірка того, чи підключений файловий дескриптор до пристрою термінала. У стандарті POSIX.1-2008 та ядрі Linux цей механізм реалізовано через сімейство викликів керування терміналом.

:::tabs
```c
/* Сигнатури інтерфейсів термінала мовою C */
#include <unistd.h>
#include <termios.h>
#include <sys/ioctl.h>

int isatty(int fd);
char *ttyname(int fd);
int ttyname_r(int fd, char *buf, size_t buflen);
int tcgetattr(int fd, struct termios *termios_p);
int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);
int ioctl(int fd, unsigned long request, ...);
```
```cpp
// C++ оголошення інтерфейсів термінала у просторі імен POSIX
#include <unistd.h>
#include <termios.h>
#include <sys/ioctl.h>

extern "C" {
int isatty(int fd);
char *ttyname(int fd);
int ttyname_r(int fd, char *buf, size_t buflen);
int tcgetattr(int fd, struct termios *termios_p);
int tcsetattr(int fd, int optional_actions, const struct termios *termios_p);
int ioctl(int fd, unsigned long request, ...);
}
```
:::

### Детальна специфікація функцій

#### `isatty`
Функція `isatty(int fd)` перевіряє, чи асоційований відкритий файловий дескриптор `fd` з активним символьним пристроєм термінала (псевдотерміналом `/dev/pts/N`, віртуальною консоллю `/dev/ttyN` або апаратним послідовним портом `/dev/ttyS*`).
- **Повертане значення**: повертає `1`, якщо дескриптор вказує на TTY; повертає `0`, якщо дескриптор вказує на регулярний файл, анонімний канал (`pipe`), сокет, блок або якщо дескриптор є недійсним.
- **Коди помилок у `errno`**:
  - `ENOTTY` (`25`): дескриптор вказує на об'єкт файлової системи, який не є терміналом. Це штатна ситуація при перенаправленні виводу в канал `cmd | grep` або у файл `cmd > out.txt`.
  - `EBADF` (`9`): переданий аргумент `fd` не є відкритим файловим дескриптором у таблиці дескрипторів поточного процесу.

#### `ttyname` та `ttyname_r`
Функції повертають нуль-термінований рядок з абсолютним шляхом до спеціального файлу пристрою у каталозі `/dev` (наприклад, `/dev/pts/4`).
- `ttyname(fd)` використовує внутрішній статичний буфер libc і не є потокобезпечною.
- `ttyname_r(fd, buf, buflen)` є реентерабельною: записує результат у буфер `buf` розміром `buflen`. Повертає `0` при успіху або додатний код помилки (`ERANGE`, якщо розмір буфера недостатній для запису повного шляху).

#### `tcgetattr` та `tcsetattr`
Функція `tcgetattr(fd, termios_p)` отримує конфігураційну структуру `termios`, що описує стан термінального драйвера ядра (режими луни, канонічну обробку рядків, керування потоком). Функція `tcsetattr` дозволяє змінювати параметри роботи термінала. Якщо `fd` не є терміналом, виклики повертають `-1` та встановлюють `errno = ENOTTY`.

## 2. Реалізація isatty() всередині libc та поведінка ядра

У вихідному коді стандартних бібліотек C (glibc, musl) функція `isatty()` не має власного виділеного системного виклику ядра. Вона реалізується як тонка обгортка над системним викликом `ioctl` із командою запиту параметрів термінала:

:::tabs
```c
/* Типова реалізація isatty() у бібліотеці musl libc */
#include <termios.h>
#include <sys/ioctl.h>

int isatty(int fd) {
    struct termios t;
    return ioctl(fd, TCGETS, &t) == 0;
}
```
```cpp
// C++ еквівалент низькорівневої перевірки через ioctl
#include <termios.h>
#include <sys/ioctl.h>

[[nodiscard]] bool check_isatty(int fd) noexcept {
    struct termios t{};
    return ioctl(fd, TCGETS, &t) == 0;
}
```
:::

### Маршрутизація запиту в ядрі Linux

1. Програма у просторі користувача викликає `ioctl(fd, TCGETS, &t)`.
2. Ядро Linux переходить у режим супервізора через інструкцію `syscall` та потрапляє до підсистеми VFS (файл `fs/ioctl.c`, функція `do_vfs_ioctl()`).
3. Ядро знаходить структуру `struct file`, відповідну номеру дескриптора `fd`, та викликає обробник файлових операцій `file->f_op->unlocked_ioctl()`.
4. Якщо файл є анонімним каналом (`pipefs`), регулярним файлом (`ext4`, `btrfs`) або сокетом (`sockfs`), таблиця операцій не містить обробника термінальних команд. Драйвер повертає значення помилки `-ENOTTY`.
5. Якщо файл є пристроєм TTY (`drivers/tty/tty_io.c`), функція `tty_ioctl()` розпізнає команду `TCGETS`, копіює параметри термінальної лінії зі структури `tty_struct` у буфер користувача та повертає `0` (успіх).

```
[Простір користувача: isatty(1)]
       │
       ▼
[libc: ioctl(1, TCGETS, &termios)]
       │ (syscall)
       ▼
[Ядро Linux: VFS do_vfs_ioctl()]
       │
       ├─────────────────────────────────────────┐
       ▼                                         ▼
[Файл TTY: drivers/tty/tty_io.c]       [Файл Pipe / ext4 / socket]
       │                                         │
       ├─► Копіює struct termios                 └─► Повертає -ENOTTY
       ▼                                         ▼
[Результат ioctl: 0 (Успіх)]           [Результат ioctl: -1, errno=ENOTTY]
       │                                         │
       ▼                                         ▼
[isatty() повертає 1 (true)]           [isatty() повертає 0 (false)]
```

## 3. Керуючі структури та команди ioctl для TTY

Підсистема терміналів Linux використовує низку керуючих кодів `ioctl` для налаштування розмірів екрана, опитування активної групи процесів та модифікації режимів вводу/виводу.

### Таблиця команд ioctl термінальної підсистеми

| Команда ioctl | Тип аргументу | Призначення |
|---|---|---|
| `TCGETS` | `struct termios *` | Отримання поточної структури конфігурації термінала. Базовий маркер наявності TTY. |
| `TCSETS` | `const struct termios *` | Негайне застосування нових параметрів термінала. |
| `TCSETSW` | `const struct termios *` | Застосування параметрів після того, як увесь виведений буфер буде передано на пристрій. |
| `TCSETSF` | `const struct termios *` | Застосування параметрів після очищення невичитаного вхідного буфера та вивантаження виводу. |
| `TIOCGWINSZ` | `struct winsize *` | Отримання поточної геометрії вікна термінала (кількість рядків, колонок та пікселів). |
| `TIOCSWINSZ` | `const struct winsize *` | Встановлення розмірів вікна (зазвичай викликається емулятором термінала при зміні розміру вікна або отриманні сигналу `SIGWINCH`). |
| `TIOCGPGRP` | `pid_t *` | Отримання ідентифікатора групи процесів переднього плану (Foreground Process Group ID, PGID) для керування завданнями (`job control`). |
| `TIOCSPGRP` | `const pid_t *` | Призначення групи процесів переднього плану для керуючого термінала. |

### Структура `struct winsize`

Для форматування людського табличного виводу під ширину екрана та запобігання потворному переносу рядків утиліти зчитують структуру `winsize`:

:::tabs
```c
#include <sys/ioctl.h>

/* Структура геометрії вікна в C */
struct winsize {
    unsigned short ws_row;    /* Кількість рядків на екрані (у знакомісцях) */
    unsigned short ws_col;    /* Кількість колонок на екрані (у знакомісцях) */
    unsigned short ws_xpixel; /* Горизонтальна роздільна здатність у пікселях */
    unsigned short ws_ypixel; /* Вертикальна роздільна здатність у пікселях */
};
```
```cpp
#include <sys/ioctl.h>

// Структура геометрії вікна в C++
struct winsize {
    unsigned short ws_row;    // Кількість рядків на екрані (у знакомісцях)
    unsigned short ws_col;    // Кількість колонок на екрані (у знакомісцях)
    unsigned short ws_xpixel; // Горизонтальна роздільна здатність у пікселях
    unsigned short ws_ypixel; // Вертикальна роздільна здатність у пікселях
};
```

## 4. Матриця перевірки дескрипторів та контексти виконання

Програма під час запуску в Unix-оточенні має три стандартні потоки, кожен з яких може бути перенаправлений незалежно від інших. Інженерний аналіз вимагає розрізнення комбінацій дескрипторів:

| Сценарій виклику | `isatty(0)` (STDIN) | `isatty(1)` (STDOUT) | `isatty(2)` (STDERR) | Оптимальна стратегія поведінки |
|---|---|---|---|---|
| Прямий запуск користувачем у шеллі (`mytool`) | `1` (true) | `1` (true) | `1` (true) | Повний інтерактивний режим: ANSI-кольори, таблиці, пейджер при довгому виводі, живий прогрес-бар. |
| Вивід у пайп (`mytool \| grep foo`) | `1` (true) | `0` (false) | `1` (true) | Машинний STDOUT (TSV або JSON без кольору); прогрес або діагностика помилок у STDERR з кольором. |
| Запуск у конвеєрі фільтрації (`cat file \| mytool`) | `0` (false) | `1` (true) | `1` (true) | Пакетна обробка вхідних даних; результат виводиться людині у термінал з кольоровим оформленням. |
| Повний неінтерактивний режим (`cron`, CI/CD, `systemd`) | `0` (false) | `0` (false) | `0` (false) | Строгий машинний вивід: вимкнено всі анімації `\r`, вимкнено кольори, логування з часовими мітками. |
| Перенаправлення виводу у файл (`mytool > log.txt`) | `1` (true) | `0` (false) | `1` (true) | STDOUT пишеться блоками без escape-послідовностей; помилки йдуть на екран оператора. |

## 5. Стандарти змінних середовища для керування виводом

Існує усталений набір змінних середовища, які дозволяють користувачам та системам оркестрації перевизначати автоматичну поведінку детекції термінала.

### Специфікація змінних

1. **`NO_COLOR`** (специфікація [no-color.org](https://no-color.org)):
   - Якщо змінна `NO_COLOR` присутня в таблиці оточення процесу і її значення не є порожнім рядком (`getenv("NO_COLOR") != NULL && getenv("NO_COLOR")[0] != '\0'`), програма **зобов'язана вимкнути будь-які ANSI escape-послідовності кольорів**, незалежно від значення `isatty()`.
   - Не залежить від числових значень: `NO_COLOR=1`, `NO_COLOR=0`, `NO_COLOR=false` — усі варіанти вимикають колір (крім повної відсутності змінної або пустого рядка `NO_COLOR=""`).

2. **`CLICOLOR` та `CLICOLOR_FORCE`** (специфікація BSD/CLIColor):
   - `CLICOLOR=0`: забороняє використання кольору.
   - `CLICOLOR=1`: дозволяє використання кольору за умови, що `isatty(STDOUT_FILENO)` повертає істину.
   - `CLICOLOR_FORCE=1`: примусово вмикає кольоровий вивід навіть тоді, коли STDOUT перенаправлено у канал (`pipe`) або файл (`isatty() == 0`). Ця змінна використовується в системах CI/CD (наприклад, GitHub Actions, GitLab CI), які зберігають колір у збережених веб-логах.
   - Пріоритет: `NO_COLOR` має абсолютний найвищий пріоритет над `CLICOLOR_FORCE`.

3. **`TERM`** (специфікація Terminfo):
   - Якщо `TERM=dumb`, термінал вважається таким, що не підтримує керування курсором, зміну кольорів та очищення екрана. Утиліти мають вимикати кольори та анімації.

4. **`COLUMNS` та `LINES`** (стандарт POSIX Shell):
   - Явно задають розміри вікна у символах, перекриваючи значення системного виклику `ioctl(TIOCGWINSZ)`. Необхідні для генерації стабільних звітів фіксованої ширини.

### Еталонна функція визначення активності кольорів

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

int should_enable_color(int fd) {
    /* 1. Стандарт NO_COLOR: найвищий пріоритет */
    const char *no_color = getenv("NO_COLOR");
    if (no_color != NULL && no_color[0] != '\0') {
        return 0;
    }

    /* 2. Примусове увімкнення кольорів для CI/CD логів */
    const char *clicolor_force = getenv("CLICOLOR_FORCE");
    if (clicolor_force != NULL && strcmp(clicolor_force, "0") != 0) {
        return 1;
    }

    /* 3. Перевірка примітивного термінала dumb */
    const char *term = getenv("TERM");
    if (term != NULL && strcmp(term, "dumb") == 0) {
        return 0;
    }

    /* 4. Заборона через CLICOLOR=0 */
    const char *clicolor = getenv("CLICOLOR");
    if (clicolor != NULL && strcmp(clicolor, "0") == 0) {
        return 0;
    }

    /* 5. Автоматичне визначення TTY */
    return isatty(fd);
}
```
```cpp
#include <cstdlib>
#include <cstring>
#include <string_view>
#include <unistd.h>

[[nodiscard]] bool should_enable_color(int fd) noexcept {
    // 1. Стандарт NO_COLOR: найвищий пріоритет
    if (const char *no_color = std::getenv("NO_COLOR"); no_color != nullptr && no_color[0] != '\0') {
        return false;
    }

    // 2. Примусове увімкнення кольорів для CI/CD логів
    if (const char *force = std::getenv("CLICOLOR_FORCE"); force != nullptr && std::string_view(force) != "0") {
        return true;
    }

    // 3. Перевірка примітивного термінала dumb
    if (const char *term = std::getenv("TERM"); term != nullptr && std::string_view(term) == "dumb") {
        return false;
    }

    // 4. Заборона через CLICOLOR=0
    if (const char *clicolor = std::getenv("CLICOLOR"); clicolor != nullptr && std::string_view(clicolor) == "0") {
        return false;
    }

    // 5. Автоматичне визначення TTY
    return isatty(fd) == 1;
}
```
:::

## 6. Зведена таблиця інтерфейсів системних утиліт Linux

Для автоматизації адміністрування сучасні інструменти надають спеціалізовані прапорці, що перемикають формат із людського на машинний.

| Категорія | Утиліта | Людський дефолт | Машинний прапорець | Формат машинного виводу |
|---|---|---|---|---|
| **Дискова підсистема** | `lsblk` | Дерево `├─`, одиниці `4.2G` | `-J` / `--json` | Структурований JSON з вкладеними об'єктами |
| | `lsblk` | Дерево `├─`, одиниці `4.2G` | `-b` / `--bytes` | Точні розміри у байтах як цілі числа |
| | `lsblk` | Дерево `├─` | `-r` / `--raw` | Пари `KEY="VALUE"` без псевдографіки |
| | `df` | Одиниці `1K-blocks` | `-B1` / `--block-size=1` | Сирі байти без заокруглень |
| **Мережа** | `ip address` | Текст із відступами, маски `/24` | `-j` / `-json` | JSON-масив інтерфейсів та конфігурацій |
| | `ip route` | Багаторядкові записи маршрутів | `-j -p` | Форматований JSON для автоматичного розбору |
| **Процеси** | `ps` | Таблиця з динамічною шириною | `-h` / `--no-headers` | Вивід рядків без шапки колонок |
| | `ps` | Дефолтні колонки системи | `-o pid,ppid,vsz,comm=` | Фіксований порядок полів, придушення заголовка |
| **Контроль версій** | `git status` | Кольоровий статус, підказки | `--porcelain=v1` | Стабільний машиночитаний плоский формат |
| | `git status` | Кольоровий статус, підказки | `--porcelain=v2 -z` | Розширений формат із NUL-розділювачами |
| | `git log` | Форматоване дерево комітів | `--format='%H%x09%an%x09%s'` | TSV-потік хешів, авторів та повідомлень |
| **Контейнеризація** | `docker ps` | Вирівняна пробілами таблиця | `--format '{{.ID}}\t{{.Image}}'` | Табуляційні значення через Go-шаблони |
| | `docker inspect` | Довільний JSON контейнера | `--format '{{json .NetworkSettings}}'` | Виділений JSON-фрагмент налаштувань |
| **Файлова система** | `find` | Список рядків, розділених `\n` | `-print0` | NUL-розділений потік (`\0`) для `xargs -0` |
| | `du` | Людські розміри `-h` | `-b` / `--bytes` | Точний розмір файлів у байтах |
