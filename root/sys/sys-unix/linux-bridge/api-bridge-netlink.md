# 📋 Довідник інтерфейсів Netlink та sysfs для Linux Bridge

Довідник параметрів ядра, атрибутів повідомлень RTNETLINK та вузлів віртуальної файлової системи sysfs, необхідних для програмного налаштування, моніторингу та діагностики комутатора Linux Bridge.

Програмний комутатор Linux Bridge надає ядру та простору користувача багаторівневий інтерфейс керування. Основним і найбільш продуктивним механізмом конфігурації є протокол RTNETLINK (сімейство сокетів `AF_NETLINK` із типом `NETLINK_ROUTE`). На відміну від застарілих блокувальних системних викликів `ioctl`, протокол Netlink забезпечує асинхронну передачу бінарних структурованих повідомлень, підтримку транзакцій, детальну нотифікацію про події через мультикаст-групи та сумісність із багатопотоковими сервісами оркестрації. Паралельно з Netlink ядро експортує дерево параметрів у віртуальній файловій системі `sysfs` для швидкої діагностики та налаштування через сценарії командного інтерпретатора.

## 1. RTNETLINK: Керування мостом (Link Layer)

Створення, модифікація параметрів та видалення моста здійснюються через сокети `AF_NETLINK` за допомогою системних повідомлень `RTM_NEWLINK`, `RTM_SETLINK` та `RTM_DELLINK`. Повідомлення містить стандартний заголовок `struct ifinfomsg`, після якого у буфері розміщуються вкладені структури атрибутів `struct rtattr`.

Для ініціалізації віртуального пристрою моста заголовок `IFLA_LINKINFO` містить обов'язковий під-атрибут `IFLA_INFO_KIND` зі строковим значенням `"bridge"`. Специфічні для комутатора конфігураційні параметри упаковуються у вкладений блок атрибутів `IFLA_INFO_DATA`. Ядро розбирає цей блок функцією `br_changelink()` у файлі `net/bridge/br_netlink.c`.

### Атрибути конфігурації моста (`IFLA_BR_*`)

Під час створення чи зміни конфігурації моста у контейнері `IFLA_INFO_DATA` використовуються такі константи:

| Атрибут (`IFLA_BR_*`) | Тип даних | Опис та внутрішня семантика ядра |
| :--- | :--- | :--- |
| `IFLA_BR_FORWARD_DELAY` | `__u32` | Затримка переходу між проміжними станами порту STP (Listening -> Learning -> Forwarding). Задається у сотих долях секунди (clock ticks). Значення за замовчуванням становить 1500 (15 секунд). Мінімально допустиме значення — 200 (2 секунди). |
| `IFLA_BR_HELLO_TIME` | `__u32` | Інтервал між генерацією періодичних конфігураційних кадрів BPDU кореневим комутатором. Задається у сотих долях секунди (за замовчуванням 200, тобто 2 секунди). |
| `IFLA_BR_MAX_AGE` | `__u32` | Максимальний час збереження конфігурації BPDU до фіксації втрати зв'язку з кореневим мостом (за замовчуванням 2000, тобто 20 секунд). |
| `IFLA_BR_AGEING_TIME` | `__u32` | Час життя динамічно вивчених записів у таблиці комутації FDB у сотих долях секунди (за замовчуванням 30000, тобто 300 секунд). Після завершення цього інтервалу збирач сміття видаляє запис. |
| `IFLA_BR_STP_STATE` | `__u32` | Режим роботи підсистеми Spanning Tree: `0` — протокол повністю вимкнено (усі порти одразу переходять у Forwarding); `1` — активний вбудований ядровий STP 802.1D; `2` — обробку BPDU делеговано демону простору користувача (RSTP/MSTP). |
| `IFLA_BR_VLAN_FILTERING` | `__u8` | Активація перевірки та ізоляції кадрів за мітками 802.1Q: `0` — міст працює у прозорому режимі без перевірки тегів; `1` — активна фільтрація за таблицею VLAN. |
| `IFLA_BR_VLAN_PROTOCOL` | `__u16` | Вибір стандарту тегування кадрів: `ETH_P_8021Q` (`0x8100` для звичайних клієнтських C-VLAN) або `ETH_P_8021AD` (`0x88A8` для провайдерських S-VLAN / QinQ). |
| `IFLA_BR_GROUP_FWD_MASK` | `__u16` | 16-бітна маска дозволу пересилання зарезервованих Link-Local групових MAC-адрес IEEE 802.1D (`01:80:C2:00:00:0X`). Дозволяє пропускати протоколи LLDP, LACP або 802.1X крізь міст. |
| `IFLA_BR_MCAST_SNOOPING` | `__u8` | Управління функцією IGMP/MLD Snooping: `1` — увімкнено відстеження багатоадресних груп і фільтрацію за MDB; `0` — багатоадресний трафік реплікується на всі порти як широкомовний. |
| `IFLA_BR_MCAST_QUERIER` | `__u8` | Дозвіл мосту генерувати власні періодичні запити IGMP/MLD General Query за відсутності виділеного апаратного мультикаст-маршрутизатора в сегменті. |

## 2. RTNETLINK: Налаштування портів моста (Port Layer)

Приєднання фізичного або віртуального інтерфейсу до моста виконується через повідомлення `RTM_SETLINK` встановленням атрибута `IFLA_MASTER`, що вказує на числовий індекс інтерфейсу моста (`ifindex`). Видалення інтерфейсу зі складу комутатора виконується відправкою `IFLA_MASTER` зі значенням 0.

Специфічні властивості конкретного порту передаються всередині вкладеного контейнера `IFLA_PROTINFO`. Обробку цих атрибутів у ядрі виконує функція `br_setport()`.

| Атрибут (`IFLA_BRPORT_*`) | Тип даних | Опис та функціональне призначення |
| :--- | :--- | :--- |
| `IFLA_BRPORT_STATE` | `__u8` | Примусова зміна стану STP для даного порту: `BR_STATE_DISABLED` (0), `BR_STATE_LISTENING` (1), `BR_STATE_LEARNING` (2), `BR_STATE_FORWARDING` (3), `BR_STATE_BLOCKING` (4). Застосовується зовнішніми демонами RSTP. |
| `IFLA_BRPORT_PRIORITY` | `__u16` | Пріоритет порту в розрахунках STP (від 0 до 63, значення за замовчуванням — 32). Впливає на вибір Root Port при наявності кількох рівнозначних лінків. |
| `IFLA_BRPORT_COST` | `__u32` | Вартість шляху (Path Cost) для алгоритму Spanning Tree. За замовчуванням ядро вираховує її автоматично на основі швидкості лінка (наприклад, 4 для 1 Gbps, 2 для 10 Gbps). |
| `IFLA_BRPORT_MODE` | `__u8` | Режим Hairpin (Reflective Relay): `1` — дозволяє відправку кадру назад у той самий порт, з якого його було отримано; `0` — забороняє петлю (стандартна поведінка комутатора). |
| `IFLA_BRPORT_GUARD` | `__u8` | Механізм захисту BPDU Guard: `1` — порт автоматично переводиться у стан `DISABLED` у разі отримання хоча б одного кадру BPDU, захищаючи мережу від несанкціонованих комутаторів. |
| `IFLA_BRPORT_PROTECT` | `__u8` | Механізм Root Guard: `1` — забороняє даному порту ставати кореневим портом (Root Port). Якщо підключений пристрій оголошує себе новим Root Bridge, порт блокується. |
| `IFLA_BRPORT_LEARNING` | `__u8` | Дозвіл автоматичного вивчення MAC-адрес: `1` — оновлювати таблицю FDB на основі адрес відправників у вхідних кадрах; `0` — заборонити динамічне навчання (для портів із фіксованими MAC). |
| `IFLA_BRPORT_UNICAST_FLOOD` | `__u8` | Розсилка невідомого індивідуального трафіку (Unknown Unicast Flood): `1` — реплікувати невідомі кадри на цей порт; `0` — скидати трафік, якщо адреси немає в FDB. |
| `IFLA_BRPORT_MCAST_FLOOD` | `__u8` | Розсилка невідомого багатоадресного трафіку при відсутності активних підписок у таблиці MDB (`1` — дозволено; `0` — заборонено). |
| `IFLA_BRPORT_BCAST_FLOOD` | `__u8` | Розсилка широкомовного трафіку (`FF:FF:FF:FF:FF:FF`) на цей порт (`1` — дозволено; `0` — заблоковано). |
| `IFLA_BRPORT_ISOLATED` | `__u8` | Ізоляція портів (Private VLAN): порти з цим прапорцем не можуть обмінюватися L2-трафіком між собою, але зберігають зв'язок із неізольованими портами шлюзу. |

## 3. Таблиця FDB (Neighbor Netlink API)

Операції читання, створення та очищення записів у таблиці комутації FDB реалізовано через сокети `AF_NETLINK` із сімейством адресації сусідів `AF_BRIDGE`. Для взаємодії використовуються типи повідомлень `RTM_NEWNEIGH`, `RTM_DELNEIGH` та `RTM_GETNEIGH`.

Повідомлення складається з фіксованого бінарного заголовка `struct ndmsg`, за яким слідує ланцюжок атрибутів `struct rtattr`.

### Поля заголовка `struct ndmsg`

- `ndm_family` (`__u8`): обов'язково встановлюється у значення `AF_BRIDGE`;
- `ndm_ifindex` (`__s32`): числовий індекс порту комутатора, до якого прив'язаний MAC (або індекс моста для локальних записів);
- `ndm_state` (`__u16`): стан запису сусіда. Для постійних статичних записів моста використовується прапорець `NUD_PERMANENT` (`0x80`), для динамічно досяжних — `NUD_REACHABLE` (`0x02`), для записів без перевірки ARP — `NUD_NOARP` (`0x40`);
- `ndm_flags` (`__u8`): прапорці розміщення запису. `NTF_MASTER` вказує ядру внести запис у таблицю FDB батьківського моста; `NTF_SELF` вносить запис безпосередньо в таблицю підпорядкованого драйвера NIC або Switchdev; `NTF_EXT_LEARNED` сигналізує, що запис вивчено зовнішнім SDN-контролером.

### Атрибути повідомлень FDB (`NDA_*`)

| Атрибут | Тип даних | Опис та використання |
| :--- | :--- | :--- |
| `NDA_LLADDR` | 6 байтів | Апаратна канальна адреса Ethernet (MAC-адреса хоста у бінарному форматі). |
| `NDA_VLAN` | `__u16` | Ідентифікатор VLAN ID, до якого прив'язано даний MAC-запис у FDB (1..4094). |
| `NDA_MASTER` | `__u32` | Індекс батьківського інтерфейсу моста (`ifindex` Master-пристрою). |
| `NDA_DST` | `in_addr` / `in6_addr` | IP-адреса віддаленої точки тунелювання VTEP при використанні FDB разом із віртуальними інтерфейсами VXLAN або Geneve. |
| `NDA_PORT` | `__be16` | UDP-порт віддаленого тунелю (за замовчуванням 4789 для VXLAN). |
| `NDA_VNI` | `__u32` | Номер віртуального мережевого сегмента VXLAN Network Identifier (VNI). |

## 4. Конфігурація VLAN Filtering (`IFLA_AF_SPEC`)

Налаштування членства портів у віртуальних мережах виконується повідомленням `RTM_SETLINK` із передачею атрибута `IFLA_AF_SPEC`. Всередині цього атрибута вкладаються бінарні блоки `IFLA_BRIDGE_VLAN_INFO`, кожен із яких містить структуру `struct bridge_vlan_info`.

Поле `flags` структури визначає режим обробки кадрів на канальному рівні:

- `BRIDGE_VLAN_INFO_PVID` (`0x0002`): призначає вказаний VID як Port VLAN ID. Усі нетеговані вхідні кадри на цьому порту автоматично отримують цей внутрішній ідентифікатор VLAN.
- `BRIDGE_VLAN_INFO_UNTAGGED` (`0x0004`): активує зняття 4-байтного тегу 802.1Q при виході кадру з порту (режим Access Port). Якщо прапорець не встановлено, кадри виходять із заголовком VLAN (режим Trunk Port).
- `BRIDGE_VLAN_INFO_RANGE_BEGIN` (`0x0008`) та `BRIDGE_VLAN_INFO_RANGE_END` (`0x0010`): дозволяють оголошувати діапазони VLAN в одному запиті (наприклад, дозволити VLAN від 100 до 200 на магістральному порту).

## 5. Мультикаст-групи та асинхронні події Netlink

Для відстеження змін у топології комутатора, динамічного вивчення нових MAC-адрес або міграції віртуальних машин системні демони можуть підписуватися на асинхронні мультикаст-групи ядра:

1. **`RTNLGRP_LINK`**: генерує сповіщення `RTM_NEWLINK` / `RTM_DELLINK` при зміні стану лінка портів або зміні конфігураційних прапорців моста (`stp_state`, `vlan_filtering`);
2. **`RTNLGRP_NEIGH`**: сповіщає про створення нових записів у FDB при надходженні трафіку від раніше невідомих MAC-адрес, оновлення порту прив'язки хоста або видалення застарілих записів таймером застарівання;
3. **`RTNLGRP_BRVLAN`**: транслює оновлення таблиці членства портів у віртуальних локальних мережах.

Підписка на ці події здійснюється бітовою маскою поля `nl_groups` у структурі `struct sockaddr_nl` під час виклику `bind()`.

### Коди помилок ядра при конфігурації моста

При некоректних параметрах Netlink-запитів ядро повертає стандартизовані коди помилок у структурі `struct nlmsgerr`:
- **`EINVAL`**: неприпустиме значення параметра (наприклад, `vlan_id > 4094`, невідомий протокол тегування або некоректні таймери STP);
- **`EBUSY`**: спроба змінити параметри, які вимагають попереднього відключення порту, або спроба додати інтерфейс, який уже підпорядкований іншому мосту чи bonding-мастеру;
- **`EEXIST`**: спроба додати існуючий статичний запис у FDB або дублюючий VLAN без встановлення прапорця `NLM_F_REPLACE`;
- **`ENODEV`**: вказаний у запиті числовий `ifindex` не існує в системі;
- **`EOPNOTSUPP`**: дія не підтримується апаратним драйвером (наприклад, запит на offload функції, відсутньої в чіпі ASIC).

## 6. Вузли sysfs та параметри ядра (sysctl)

Файлова система `sysfs` надає людиночитабельний інтерфейс для моніторингу та швидкого налаштування окремих параметрів моста без використання бінарних сокетів Netlink.

### Параметри моста: `/sys/class/net/<brname>/bridge/`

- `ageing_time`: поточний час застарівання записів у FDB у таймерних тіках (clock ticks). Читання повертає значення в секундах або jiffies;
- `bridge_id`: 8-байтний ідентифікатор моста у шістнадцятковому форматі, сформований із 2-байтного пріоритету STP та 6-байтної базової MAC-адреси;
- `stp_state`: поточний числовий режим Spanning Tree (`0`, `1` або `2`);
- `vlan_filtering`: стан механізму фільтрації тегів 802.1Q (`0` — вимкнено, `1` — увімкнено);
- `group_fwd_mask`: бітова маска пропуску зарезервованих link-local групових адрес;
- `root_port`: номер порту комутатора, через який проходить найкоротший шлях до кореневого моста STP;
- `root_path_cost`: сумарна вартість шляху до кореневого моста за метрикою 802.1D.

### Параметри портів: `/sys/class/net/<brname>/brif/<portname>/`

- `hairpin_mode`: бінарний прапорець дозволу відправки кадру назад у вхідний порт (`0` або `1`);
- `learning`: прапорець динамічного вивчення MAC-адрес з трафіку цього порту;
- `unicast_flood`, `multicast_flood`, `broadcast_flood`: окремі перемикачі розсилки невідомих потоків;
- `isolated`: прапорець ізоляції порту на канальному рівні;
- `state`: числовий код поточного стану порту в алгоритмі STP (`0` — Disabled, `1` — Listening, `2` — Learning, `3` — Forwarding, `4` — Blocking).

### Системні перемикачі модуля `br_netfilter` (`sysctl`)

Коли модуль `br_netfilter` завантажено в пам'ять ядра, системні параметри фільтрації стають доступними через дерево `sysctl` у каталозі `net/bridge/`:

| Змінна sysctl | Значення за замовчуванням | Вплив на проходження пакетів |
| :--- | :---: | :--- |
| `net.bridge.bridge-nf-call-iptables` | `1` | Пропускати транзитні L2 IPv4-пакети через ланцюги `iptables` (PREROUTING, FORWARD, POSTROUTING). Значення `0` повністю вимикає втручання L3-файрволу в комутацію. |
| `net.bridge.bridge-nf-call-ip6tables` | `1` | Аналогічно перехоплює транзитні IPv6-пакети моста для обробки правилами `ip6tables`. |
| `net.bridge.bridge-nf-call-arptables` | `1` | Дозволяє фільтрувати транзитні кадри протоколу ARP через таблиці утиліти `arptables`. |
| `net.bridge.bridge-nf-filter-vlan-tagged` | `0` | Вмикає перевірку правил файрволу над VLAN-тегованими кадрами моста з автоматичним розбором заголовка 802.1Q. |
| `net.bridge.bridge-nf-pass-vlan-input-dev` | `0` | Примусово передає у правила Netfilter ім'я віртуального VLAN-інтерфейсу замість імені фізичного моста. |
