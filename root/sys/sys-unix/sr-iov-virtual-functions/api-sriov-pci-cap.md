# 📋 Регістри PCI Express SR-IOV Extended Capability та sysfs-інтерфейс Linux

Цей довідник описує низькорівневу структуру регістрів розширеної спроможності PCI Express SR-IOV Extended Capability (ID `0x0010`), програмний інтерфейс ядра Linux у псевдофайловій системі sysfs, виклики Netlink `rtnetlink` та функції драйверного API ядра Linux.

## 1. Специфікація апаратних регістрів SR-IOV Extended Capability

Згідно зі специфікацією PCI-SIG SR-IOV, кожен Physical Function (PF) з підтримкою віртуалізації містить у своєму розширеному конфігураційному просторі (PCIe Extended Configuration Space, зсув ≥ `0x100`) структуру із заголовочним ідентифікатором Extended Capability ID `0x0010`.

Конфігураційний простір доступний для читання та запису операційній системі хоста через системні виклики або утиліту `lspci -vvv -s <BDF>`.

| Зсув (Offset) | Поле | Розмір | Атрибут | Опис та семантика |
|---|---|---|---|---|
| `0x00` | Extended Cap Header | 32 біти | RO | Cap ID (`0x0010`), версія структури (зазвичай `1`) та зміщення до наступного розширення PCIe Cap. |
| `0x04` | SR-IOV Capabilities | 32 біти | RO | Прапори апаратної підтримки чипа. Біт 0: `VF Migration Capable`; біт 1: `ARI Capable` (підтримка 256 функцій). |
| `0x08` | SR-IOV Control | 16 бітів | RW | Регістр керування. Біт 0: `VF Enable` (1 = включити декодування адрес масиву VF); біт 1: `VF Migration Enable`. |
| `0x0A` | SR-IOV Status | 16 бітів | RO/RW1C | Регістр стану. Біт 0: `VF Migration Status` (1 = відбулася подія міграції VF). |
| `0x0C` | InitialVFs | 16 бітів | RO | Кількість VF, які апаратно доступні одразу після скидання пристрою (Initial state). |
| `0x0E` | TotalVFs | 16 бітів | RO | Максимальна кількість VF, яку здатний підтримувати даний PF за специфікацією чипа. |
| `0x10` | NumVFs | 16 бітів | RW | Кількість активованих на даний момент VF (записується операційною системою хоста). |
| `0x12` | Function Dependency Link | 8 бітів | RO | Номер PF, з якою ця PF ділить спільні апаратні ресурси: залежні функції вмикають і вимикають SR-IOV разом. |
| `0x14` | VF Offset | 16 бітів | RO | Зсув у номерах BDF від PF до найпершої віртуальної функції (`VF 0`). |
| `0x16` | VF Stride | 16 бітів | RO | Крок (відстань) між номерами BDF для наступних віртуальних функцій (`VF n+1`). |
| `0x1A` | VF Device ID | 16 бітів | RO | Ідентифікатор пристрою (PCI Device ID), який бачитиме гостьова ОС для кожної VF. |
| `0x1C` | Supported Page Sizes | 32 біти | RO | Бітова маска розмірів сторінок пам'яті, які підтримує контролер: біт `n` означає сторінку 2^(n+12) байтів, тобто відлік починається з 4 КіБ. |
| `0x20` | System Page Size | 32 біти | RW | Поточний розмір сторінки пам'яті, вибраний системним драйвером хоста (за замовчуванням 4 КіБ). |
| `0x24`..`0x38` | VF BAR0 .. VF BAR5 | 6 × 32 біти | RO/RW | Таблиця регістрів базових адрес (BAR) для масиву VF. Кожен VF BAR визначає сукупний розмір пам'яті для всіх VF. |

### Формула обчислення адреси BDF (Bus/Device/Function)

Кожна віртуальна функція отримує власний ідентифікатор адреси на шині PCI Express. Якщо PF має адресу `Bus:Dev.Func`, то адреса `n`-ї віртуальної функції (`n` від `0` до `NumVFs-1`) розраховується як:

```
BDF(VF_n) = BDF(PF) + VF_Offset + (n × VF_Stride)
```

Приклад: PF перебуває на адресі `0000:03:00.0`, тобто його Routing ID дорівнює `0x0300` (шина 3 — біти 15:8, пристрій 0 — біти 7:3, функція 0 — біти 2:0). Якщо `VF_Offset = 16` (тобто `0x10`), а `VF_Stride = 1`, то `VF 0` дістає Routing ID `0x0310` — це BDF `0000:03:02.0`, `VF 1` — `0000:03:02.1`, і так далі.

## 2. Системний інтерфейс sysfs ядра Linux

Ядро Linux експортує атрибути SR-IOV у директорії PCI-пристрою `/sys/bus/pci/devices/<domain>:<bus>:<dev>.<func>/`.

```
/sys/bus/pci/devices/0000:03:00.0/
├── sriov_totalvfs          (r--)  # Максимальна кількість VF (значення з TotalVFs)
├── sriov_numvfs            (rw-)  # Поточна кількість активних VF (значення з NumVFs)
├── sriov_offset            (r--)  # Зсув BDF для першої VF (значення з VF Offset)
├── sriov_stride            (r--)  # Крок BDF між сусідніми VF (значення з VF Stride)
├── sriov_vf_device         (r--)  # PCI Device ID для віртуальних функцій
├── sriov_drivers_autoprobe (rw-)  # Прапор авто-прив'язки драйвера (1 = так, 0 = ні)
├── virtfn0                 (r--)  # Символьне посилання на директорію VF 0
├── virtfn1                 (r--)  # Символьне посилання на директорію VF 1
└── virtfnN                 (r--)  # Символьне посилання на директорію VF N
```

### Семантика запису в `sriov_numvfs`:

1. **Зміна з 0 на N (`N > 0`):** 
   - Драйвер PF через виклик ядра `pci_enable_sriov()` зчитує регістри `VF Offset`, `VF Stride` та `VF BARs`.
   - Ядро перевіряє наявність вільних адрес у просторі PCI-ресурсів (MMIO space) для покриття сукупного розміру всіх `VF BAR`.
   - Виділяються BDF-адреси на шині PCIe, створюються структури `struct pci_dev` для кожної VF та додаються відповідні символьні посилання `virtfn<N>` у sysfs.
   - Якщо `sriov_drivers_autoprobe == 1`, ядро шукає відповідний драйвер (наприклад, `iavf` або `mlx5_core`) та автоматично прив'язує його до створених VF.

2. **Зміна з N на 0:**
   - Викликається функція ядра `pci_disable_sriov()`.
   - Якщо пристрої VF в цей момент прокинуті у працюючу віртуальну машину, драйвер PF бачить це за `pci_vfs_assigned()` і відмовляє: запис у `sriov_numvfs` завершується помилкою (конкретний код залежить від драйвера — `-EBUSY` чи `-EINVAL`), а в журналі ядра з'являється попередження про призначені ВМ функції.
   - Якщо пристрої вільні, ядро відв'язує драйвери, знищує пристрої `struct pci_dev` та звільняє виділені ресурси MMIO.

3. **Зміна з N на M (`M ≠ 0` та `M ≠ N`):**
   - Ядро не дозволяє змінювати кількість уже ввімкнених VF на льоту: масив спершу треба скинути до 0.
   - Спроба записати `M`, поки `NumVFs > 0`, повертає `-EBUSY` (Device or resource busy) і залишає в журналі ядра попередження на кшталт «VFs already enabled. Disable them first».

## 3. Інтерфейс Netlink (`rtnetlink`) для налаштування параметрів VF

Для керування віртуальними функціями мережевих карт ядро надає розширення Netlink-повідомлень `RTM_NEWLINK` / `RTM_SETLINK` із вкладеним атрибутом `IFLA_VFINFO_LIST`. У консолі ці параметри керуються утилітою `ip link`:

```bash
ip link set dev <pf_interface> vf <vf_index> \
    [ mac <mac_addr> ] \
    [ vlan <vlan_id> [ qos <priority> ] [ proto <802.1Q|802.1ad> ] ] \
    [ rate <max_tx_rate_mbps> ] \
    [ min_tx_rate <min_tx_rate_mbps> ] \
    [ spoofchk <on|off> ] \
    [ trust <on|off> ] \
    [ state <auto|enable|disable> ]
```

### Повний перелік атрибутів структури `IFLA_VF_INFO`:

- **`IFLA_VF_MAC` (`mac <mac_addr>`):**
  Жорстко фіксує MAC-адресу VF у прошивці eSwitch. При спробі гостя змінити MAC-адресу програмно прошивка відхиляє зміну.
- **`IFLA_VF_VLAN` (`vlan <vlan_id>`):**
  Визначає режим Port VLAN. Включає VLAN ID (1–4095), коефіцієнт пріоритету QoS 802.1p (0–7) та протокол (802.1Q або 802.1ad QinQ).
- **`IFLA_VF_TX_RATE` (`rate` / `min_tx_rate`):**
  Встановлює обмеження пропускної здатності відправки (Tx Bandwidth Shaping) у мегабітах за секунду (Mbps). `max_tx_rate` обмежує пікову швидкість, `min_tx_rate` гарантує мінімальну смугу (QoS Reservation).
- **`IFLA_VF_SPOOFCHK` (`spoofchk <on|off>`):**
  Вмикає апаратну перевірку Anti-Spoofing. Якщо VF надсилає кадр із вихідною MAC-адресою або IP-адресою, що не відповідає призначеній, eSwitch скидає такий пакет (Drop) та виставляє лічильник помилок у PF.
- **`IFLA_VF_TRUST` (`trust <on|off>`):**
  Дозволяє VF вмикати нерозбірливе приймання (Promiscuous mode) або додавати нові мультикаст-групи. За замовчуванням `off` для захисту від перехоплення сусіднього трафіку.
- **`IFLA_VF_LINK_STATE` (`state <auto|enable|disable>`):**
  Керує віртуальним станом лінка для VF. `auto` — стан лінка відповідає фізичному порту; `enable` — лінк завжди UP (навіть якщо кабель відключено); `disable` — лінк завжди DOWN (для ізоляції ВМ).
- **`IFLA_VF_STATS`:**
  Контейнер системних лічильників трафіку для конкретної VF (передані/прийняті пакети, байти, скинуті кадри та помилки Anti-Spoofing).

## 4. Драйверне API ядра Linux (Kernel C API)

Для розробників драйверів мережевих карт ядро Linux надає набір функцій у заголовках `<linux/pci.h>` та `<linux/netdevice.h>`:

- **`int pci_enable_sriov(struct pci_dev *dev, int nr_virtfn)`:**
  Низькорівнева функція ядра, яка ініціалізує регістри SR-IOV Extended Capability, включає біт `VF Enable` у конфігураційному просторі та виділяє ресурси PCIe.
- **`void pci_disable_sriov(struct pci_dev *dev)`:**
  Вимикає біт `VF Enable` та звільняє виділені ресурси віртуальних функцій.
- **`int pci_vfs_assigned(struct pci_dev *dev)`:**
  Повертає кількість VF даного PF, які в даний момент прокинуті у віртуальні машини через `vfio-pci` або KVM. Якщо повертається значення `> 0`, драйвер не повинен вимикати SR-IOV.
- **Колбек `.sriov_configure(struct pci_dev *dev, int num_vfs)`:**
  Елемент структури `struct pci_driver`. Ядро викликає цей колбек, коли користувач записує значення у файл `sriov_numvfs` у sysfs. Драйвер повинен обробити запит, перевірити апаратні ліміти та викликати `pci_enable_sriov()` або `pci_disable_sriov()`.
