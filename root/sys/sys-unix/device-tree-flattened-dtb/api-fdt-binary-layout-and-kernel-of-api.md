# 📋 Бінарна структура FDT та довідник API ядра Linux (Open Firmware)

Цей довідник описує точну специфікацію бінарного заголовка Flattened Device Tree (`struct fdt_header`), розташування блоків і керуючих токенів у бінарному блобі `.dtb`, а також наводить вичерпну сигнатурну таблицю та опис внутрішніх механізмів API ядра Linux з префіксом `of_*` для пошуку вузлів, зчитування властивостей, вилучення ресурсів пам'яті (MMIO), переривань (IRQ) та сигналів GPIO.

## 1. Детальна специфікація бінарного заголовка FDT (`struct fdt_header`)

Будь-який бінарний файл `.dtb` починається з заголовка фіксованого розміру 40 байтів (згідно зі специфікацією версії 17). Заголовок вирівнюється в пам'яті за межею 8 байтів (64 біти). Усі цілочисельні поля заголовка та внутрішніх блоків зберігаються строго у порядку **Big-Endian** (Network Byte Order, де старший байт розташований за меншою фізичною адресою).

```c
struct fdt_header {
    uint32_t magic;             /* 0xd00dfeed (FDT_MAGIC) */
    uint32_t totalsize;         /* Загальний розмір бінарного DTB у байтах */
    uint32_t off_dt_struct;     /* Зсув у байтах до блоку структур (dt_struct) */
    uint32_t off_dt_strings;    /* Зсув у байтах до блоку рядків (dt_strings) */
    uint32_t off_mem_rsvmap;    /* Зсув до таблиці зарезервованої пам'яті */
    uint32_t version;           /* Версія специфікації FDT (наразі 17) */
    uint32_t last_comp_version; /* Найменша сумісна версія (зазвичай 16) */
    uint32_t boot_cpuid_phys;   /* Фізичний ID ядра CPU для первинного завантаження */
    uint32_t size_dt_strings;   /* Розмір блоку рядків у байтах */
    uint32_t size_dt_struct;    /* Розмір блоку структур у байтах */
};
```

Поле `magic` містить фіксовану константу `0xd00dfeed`. Під час раннього завантаження ядро Linux виконує швидку перевірку перших 4 байтів за адресою, переданою в регістрах CPU. Якщо значення `magic` після виклику `be32_to_cpu()` збігається з `0xd00dfeed`, ядро визнає передану область пам'яті коректним блобом FDT. Якщо сигнатура ламається (наприклад, через помилку завантажувача або пошкодження пам'яті), ядро зупиняє процес завантаження з повідомленням `Invalid device tree blob header`.

Поле `boot_cpuid_phys` вказує апаратний фізичний ідентифікатор процесорного ядра (Hardware Thread / Hart ID), яке виконує початковий запуск системи. У багатоядерних системах (SMP) це дозволяє ядру визначати, яке саме ядро виконує фазу `setup_arch()`, і тримати інші ядра у стані очікування (Spin-Table або PSCI loop) до моменту їхньої віддаленої активації.

### 1.1. Секція зарезервованої пам'яті (`off_mem_rsvmap`)

За зсувом `off_mem_rsvmap` розташовано масив елементів `struct fdt_reserve_entry`. Цей блок призначений для інформування операційної системи про фізичні області DRAM, які зайняті прошивками системного рівня (наприклад, ARM Trusted Firmware TF-A, OpenSBI на RISC-V, графічними буферами framebuffer або самим образом DTB) і які заборонено виділяти під підсистему сторінкової пам'яті ядра (`memblock`).

```c
struct fdt_reserve_entry {
    uint64_t address; /* Початкова фізична адреса зарезервованого регіону (Big-Endian) */
    uint64_t size;    /* Довжина зарезервованого регіону у байтах (Big-Endian) */
};
```

Кожен запис займає 16 байтів (двоє 64-бітних чисел). Масив не має фіксованого поля кількості елементів, а завершується спеціальним термінальним записом, у якому обидва поля дорівнюють нулю (`address = 0`, `size = 0`). Під час сканування `early_init_dt_scan()` ядро ітерується по масиву до першого нульового запису і автоматично додає кожен регіон у списки виключень розподілювача `memblock_reserve()`.

## 2. Формат керуючих токенів та структура блоку `dt_struct`

Блок `dt_struct` містить безпосередній опис ієрархії деревних вузлів та їхніх властивостей. Дані записані у вигляді послідовності 32-бітних токенів (Big-Endian). Усі токени, назви вузлів та корисні навантаження властивостей обов'язково вирівнюються в пам'яті за межею **4 байти (32 біти)**. Якщо довжина рядка або масиву не кратна 4, вона доповнюється нульовими байтами (`\0`).

| Токен | Символьна назва | Значення (HEX) | Структура даних після токена у бінарному потоці |
| :--- | :--- | :--- | :--- |
| `FDT_BEGIN_NODE` | Початок вузла | `0x00000001` | Нуль-термінований ASCII-рядок із назвою вузла (наприклад, `"serial@101f1000\0"`). Далі додаються нульові байти padding до межі 4 байти. Для кореневого вузла рядок містить лише один нульовий байт (`"\0"`). |
| `FDT_END_NODE` | Кінець вузла | `0x00000002` | Сигналізує про закриття поточного вузла. Додаткових даних у потоці немає. Дозволяє парсеру підніматися на один рівень вгору по стеку вкладеності ієрархії. |
| `FDT_PROP` | Оголошення властивості | `0x00000003` | Заголовкова структура `struct fdt_property` (8 байтів), за якою слідує байтовий масив значення властивості довжиною `len` байтів та вирівнювання до 4 байтів. |
| `FDT_NOP` | Порожня операція | `0x00000004` | 4-байтовий заповнювач. Пропускається парсером без дій. Використовується завантажувачами для швидкого видалення вузлів або властивостей прямо в пам'яті без потреби переміщення великих блоків даних. |
| `FDT_END` | Кінець структури | `0x00000009` | Фінальний маркер завершення блоку `dt_struct`. Обов'язково присутній у кожному валідному файлі DTB. |

### 2.1. Анатомія токена властивості (`struct fdt_property`)

Коли парсер знаходить токен `FDT_PROP` (`0x00000003`), наступні 8 байтів інтерпретуються як заголовок властивості:

```c
struct fdt_property {
    uint32_t len;     /* Довжина сирих даних властивості у байтах (Big-Endian) */
    uint32_t nameoff; /* Зсув назви властивості у блоці dt_strings (Big-Endian) */
    /* uint8_t data[len];  Сирі байти значення властивості (вирівняно до 4 байтів) */
};
```

Зсув `nameoff` вказує на точну позицію символьного рядка назви властивості (наприклад, `"compatible"`, `"reg"`, `"interrupts"`) відносно базової адреси блоку рядків `off_dt_strings`. Завдяки цьому всі однакові назви властивостей у вихідному коді (які повторюються сотні разів) у бінарному файлі зберігаються в одному екземплярі у блоці `dt_strings`, а структури містять лише 4-байтні зсуви.

Обчислення фактичного зсуву в буфері пам'яті для читання значення властивості виконується за формулою:

```
data_ptr = struct_ptr + sizeof(struct fdt_property);
next_token_ptr = data_ptr + align4(len);
```

де `align4(val)` обчислюється як `(val + 3) & ~3U`.

## 3. Довідник API ядра Linux (Open Firmware `of_*`)

Усі функції для взаємодії з розгорнутим деревом пристроїв у пам'яті ядра оголошені в системному заголовочному файлі `<linux/of.h>`. Вони працюють із динамічними структурою `struct device_node`.

### 3.1. Функції пошуку та обходу вузлів дерева

Ці функції використовуються для знаходження конкретних пристроїв у дереві під час ініціалізації драйверів.

```c
struct device_node *of_find_compatible_node(struct device_node *from,
                                             const char *type,
                                             const char *compat);
```
- **Опис:** Шукає вузол у дереві, у якого властивість `compatible` містить рядок `compat`.
- **Аргументи:** `from` — вузол, з якого починати пошук (або `NULL` для пошуку з кореня); `type` — опціональне значення `device_type` (або `NULL`); `compat` — рядок сумісності (наприклад, `"arm,pl011"`).
- **Повертає:** Вказівник на знайдений `struct device_node` з автоматично збільшеним лічильником посилань (`kref`), або `NULL` якщо вузол не знайдено.
- **Особливості:** Обов'язково вимагає виклику `of_node_put()` після завершення використання знайденого вузла.

```c
struct device_node *of_find_node_by_path(const char *path);
```
- **Опис:** Шукає вузол за його абсолютним шляхом у дереві (наприклад, `"/soc/serial@101f1000"`). також підтримує псевдоніми (aliases), визначені у вузлі `/aliases` (наприклад, `"serial0"`).
- **Повертає:** Вказівник на вузол або `NULL`.

```c
struct device_node *of_get_next_child(const struct device_node *node,
                                       struct device_node *prev);
```
- **Опис:** Ітератор для послідовного обходу всіх дочірніх вузлів даного батьківського вузла `node`.
- **Аргументи:** `node` — батьківський вузол; `prev` — попередній дочірній вузол (або `NULL` на першій ітерації).
- **Особливості:** Автоматично зменшує лічильник посилань для `prev` та збільшує для поверненого наступного вузла.

### 3.2. Функції читання числових та рядкових властивостей

```c
int of_property_read_u32(const struct device_node *np,
                         const char *propname,
                         u32 *out_value);
```
- **Опис:** Зчитує одиночне 32-бітне число з властивості `propname` вузла `np`. Автоматично виконує конвертацію ендіаннесу з Big-Endian у формат хостового CPU (`be32_to_cpu`).
- **Повертає:** `0` при успіху, `-EINVAL` якщо властивості не існує, `-EOVERFLOW` якщо розмір властивості менший за 4 байти.

```c
int of_property_read_u32_array(const struct device_node *np,
                               const char *propname,
                               u32 *out_values,
                               size_t sz);
```
- **Опис:** Зчитує масив із `sz` елементів 32-бітних чисел із властивості `propname`.
- **Повертає:** `0` при успіху або від'ємний код помилки.

```c
int of_property_read_string(const struct device_node *np,
                            const char *propname,
                            const char **out_string);
```
- **Опис:** Витягує вказівник на null-термінований ASCII-рядок із властивості `propname`.
- **Повертає:** `0` при успіху або від'ємний код помилки.

```c
bool of_property_read_bool(const struct device_node *np,
                           const char *propname);
```
- **Опис:** Перевіряє наявність булевої властивості-прапорця (наприклад, `"dma-coherent"` або `"promiscuous"`), яка не має значення, а її присутність сама по собі означає `true`.
- **Повертає:** `true` якщо властивість присутня у вузлі, `false` якщо відсутня.

### 3.3. Функції трансляції та вилучення апаратних ресурсів

```c
int of_address_to_resource(struct device_node *dev,
                           int index,
                           struct resource *r);
```
- **Опис:** Зчитує `index`-ний кортеж із властивості `reg` вузла `dev`, парсить кількість комірок з урахуванням батьківських `#address-cells` та `#size-cells`, виконує трансляцію фізичних адрес через властивості `ranges` усіх вищих шин та заповнює стандартну структуру ядра `struct resource` (з прапорцями `IORESOURCE_MEM`).
- **Повертає:** `0` у разі успішної трансляції або від'ємний код помилки.

```c
void __iomap *of_iomap(struct device_node *np, int index);
```
- **Опис:** Зручна високорівнева функція-обгортка. Автоматично викликає `of_address_to_resource()` для `index`-ного регістру `reg`, а потім виконує системний виклик `ioremap()` для відображення фізичних MMIO адрес пристрою у віртуальний адресний простір ядра.
- **Повертає:** Віртуальний вказівник `void __iomap *` або `NULL` при помилці.

```c
unsigned int irq_of_parse_and_map(struct device_node *dev, int index);
```
- **Опис:** Зчитує `index`-ний запис із властивості `interrupts` вузла `dev`, знаходить відповідний контролер переривань через властивість `interrupt-parent` (або вище по дереву) та мапить апаратний номер переривання на системний віртуальний номер IRQ у домені переривань ядра (`irq_domain`).
- **Повертає:** Системний номер переривання Linux IRQ (значення > 0) або `0` у разі помилки.

```c
struct gpio_desc *gpiod_get_optional(struct device *dev,
                                      const char *con_id,
                                      enum gpiod_flags flags);
```
- **Опис:** Автоматично шукає у Device Tree вузла пристрою властивість вида `<con_id>-gpios` (наприклад, `"reset-gpios"` чи `"enable-gpios"`), транслятором визначає відповідний GPIO-контролер, запитує вивід у підсистеми gpiolib та налаштовує його початковий напрямок (вхід/вихід) згідно з аргументом `flags`.
- **Повертає:** Вказівник на `struct gpio_desc *` або `NULL` якщо опціональний GPIO відсутній у дереві.

## 4. Дисципліна керування пам'яттю та Reference Counting

Структура `struct device_node` бере участь у системі автоматичного обліку посилань ядра через механізм `kref`. 

Кожен виклик функцій пошуку (таких як `of_find_compatible_node()`, `of_find_node_by_path()`, `of_get_parent()`) збільшує лічильник посилань поверненого вузла. Якщо драйвер отримує вказівник на вузол і не зменшує лічильник після завершення роботи, відповідний вузол і всі пов'язані з ним властивості назавжди залишаються в оперативній пам'яті ядра, що призводить до витоків пам'яті (Memory Leaks).

Обов'язкове звільнення посилання виконується викликом:

```c
void of_node_put(struct device_node *node);
```

Майкроси макро-ітераторів (такі як `for_each_child_of_node(parent, child)`) автоматично викликають `of_node_put(child)` на кожному кроці циклу. Однак, якщо розробник виконує достроковий вихід із циклу через `return` або `break`, він зобов'язаний вручну викликати `of_node_put(child)` перед виходом.
