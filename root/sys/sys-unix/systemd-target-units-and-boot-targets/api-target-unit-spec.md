# 📋 Специфікація директив target-юнітів та інтерфейс управління systemctl

Ця довідкова вставка містить детальну специфікацію конфігураційних директив секцій `[Unit]` та `[Install]` для цільових юнітів, розширенну матрицю відповідності стандартних системних таргетів системі SysVinit, опис структур D-Bus інтерфейсу та довідник команд утиліти `systemctl` для управління станами системи.

---

## Конфігураційні директиви target-юнітів

Цільовий юніт (`.target`) описується у синтаксисі INI-подібних файлів конфігурації systemd. Оскільки target-юніти виконують роль чистих вузлів групування у графі залежностей і не запускають безпосередніх бінарних процесів у просторі користувача, вони зазвичай позбавлені секції `[Service]` та командних ключів на кшталт `ExecStart=`. Головне семантичне навантаження target-юніта зосереджено в секціях `[Unit]` та `[Install]`.

### Конфігураційні ключі секції [Unit]

Секція `[Unit]` відповідає за загальні метадані юніта, оголошення ребер спрямованого ациклічного графа (DAG) та визначення правил ізоляції станів:

#### 1. Директиви метаданих
- `Description=`: Текстовий рядок, що містить короткий опис призначення цільового таргета. Цей опис відображається у системних логах `journalctl`, при виведенні статусу утилітою `systemctl status`, а також під час візуального оформлення етапу завантаження в консолі.
- `Documentation=`: Список URI-посилань на документацію, пов'язану з даним таргетом. Підтримуються схеми `man:name(section)`, `file:/path`, `http://` або `https://`.

#### 2. Директиви формування залежностей
- `Wants=`: Оголошує м'яку залежність. Усі юніти, вказані в цьому списку, автоматично додаються до транзакції завантаження під час активації даного таргета. Помилка активації або раптовий збій одного з залежних юнітів не призводить до зупинки або збою самого цільового таргета.
- `Requires=`: Оголошує жорстку залежність. Якщо цільовий таргет активовано, усі юніти зі списку `Requires=` обов'язково додаються до транзакції. Помилка активації або зупинка будь-якого із залежних юнітів спричиняє автоматичну зупинку самого цільового таргета.
- `BindsTo=`: Оголошує сильну залежність зв'язування. За семантикою схожа на `Requires=`, але додатково відстежує життєвий цикл залежних юнітів у реальному часі. Якщо залежний юніт несподівано зникає (наприклад, відбувається відключення фізичного мережевого пристрою або відмонтування накопичувача), таргет-юніт негайно переходить у неактивний стан.
- `Requisite=`: Оголошує передумову активації. На відміну від `Requires=`, дана директива не додає вказані юніти до транзакції запуску, а лише перевіряє їх поточний стан. Якщо хоча б один юніт зі списку `Requisite=` не є активним у момент виклику таргета, активація таргета негайно скасовується з помилкою.
- `Conflicts=`: Оголошує негативну залежність (несумісність станів). При активації цільового таргета системний менеджер PID 1 автоматично формує транзакційні роботи зупинки (`JOB_STOP`) для всіх юнітів, перелічених у ключі `Conflicts=`.

#### 3. Директиви часового впорядкування
- `Before=`: Вказує правило послідовності. Поточний цільовий таргет має повністю завершити свій етап активації до того, як розпочнеться запуск юнітів, перелічених у даному списку.
- `After=`: Вказує правило послідовності. Поточний цільовий таргет розпочне процедуру активації лише після того, як вказані у списку юніти успішно завершать свій запуск.

#### 4. Директиви ізоляції та автоматичного припинення
- `AllowIsolate=`: Приймає булеве значення (`yes` або `no`). Якщо встановлено `yes`, даний таргет дозволяє виконання процедури ізоляції стану за допомогою команди `systemctl isolate <target>`. За замовчуванням значення дорівнює `no` для запобігання випадковій ізоляції пасивних точок синхронізації.
- `IgnoreOnIsolate=`: Приймає булеве значення (`yes` або `no`). Якщо встановлено `yes`, даний юніт буде повністю ігноруватися алгоритмом зупинки під час виконання ізоляції інших таргетів. Використовується для захисту критичних системних демонів (`systemd-journald`, `dbus`, root mounts).
- `StopWhenUnneeded=`: Приймає булеве значення (`yes` або `no`). Якщо встановлено `yes`, PID 1 автоматично зупиняє даний таргет у момент, коли у системі не залишається жодного іншого активного юніта, що залежить від нього.

### Конфігураційні ключі секції [Install]

Секція `[Install]` містить інструкції для утиліти `systemctl` щодо створення та видалення символьних посилань під час виконання команд `systemctl enable` та `systemctl disable`. Ця секція повністю ігнорується системним менеджером PID 1 під час безпосереднього завантаження графа!

- `WantedBy=`: Вказує назву цільового таргета, до якого має бути прив'язаний даний юніт. Виконання `systemctl enable` створює символьне посилання у каталозі `/etc/systemd/system/<target>.wants/`.
- `RequiredBy=`: Вказує назву цільового таргета для жорсткої прив'язки. Виконання `systemctl enable` створює символьне посилання у каталозі `/etc/systemd/system/<target>.requires/`.
- `Alias=`: Список додаткових імен (синонімів), під якими даний юніт повинен бути доступний у системі. Виконання `enable` створює відповідні символьні посилання.

## Матриця стандартних системних target-юнітів

Операційна система systemd визначає стандартизований набір спеціальних цільових юнітів (`man systemd.special(7)`), які формують базову архітектуру завантаження Linux.

| Target-юніт | Сумісний SysV Alias | Функціональне призначення та склад залежностей | Дозвіл AllowIsolate |
| :--- | :--- | :--- | :--- |
| `sysinit.target` | — | Рання ініціалізація системи: монтування `/proc`, `/sys`, `/dev`, запуск `udev`, `sysctl`, LVM, RAID, swap. | `no` |
| `basic.target` | — | Базовий стан системи: запуск сокетів (`sockets.target`), таймерів (`timers.target`), шляхів (`paths.target`). | `no` |
| `multi-user.target` | `runlevel3.target` | Повноцінний консольний режим: мережеві служби, SSH, TTY, cron, авторизація користувачів. | `yes` |
| `graphical.target` | `runlevel5.target` | Графічний режим: включає `multi-user.target` та запуск дисплейного менеджера (GDM/SDDM). | `yes` |
| `rescue.target` | `runlevel1.target` | Режим однокористувацького відновлення: монтування дисків та виклик `sulogin`. | `yes` |
| `emergency.target` | — | Екстрений режим: мінімальна консоль відновлення при критичних помилках монтування. | `yes` |
| `poweroff.target` | `runlevel0.target` | Корректне завершення роботи та вимкнення живлення обладнання. | `yes` |
| `reboot.target` | `runlevel6.target` | Перезавантаження операційної системи через ядро. | `yes` |
| `kexec.target` | — | Швидке перезавантаження операційної системи в нове ядро без проходження POST BIOS. | `yes` |
| `network.target` | — | Пасивна точка синхронізації: мережевий стек ініціалізовано (IP може бути відсутнім). | `no` |
| `network-online.target` | — | Активна точка синхронізації: мережеве з'єднання повністю піднято (IP отримано, маршрут є). | `no` |
| `remote-fs.target` | — | Точка синхронізації віддалених мережевих файлових систем (NFS, CIFS, iSCSI). | `no` |
| `time-sync.target` | — | Точка синхронізації системного часу (NTP, `systemd-timesyncd`, chrony). | `no` |

## Інтерфейс командного рядка systemctl

Утиліта `systemctl` надає повний комплекс команд для аналізу, переключення та управління цільовими юнітами.

### 1. Управління ізоляцією та переключенням станів

Команда `isolate` здійснює транзакційну зміну поточного операційного стану системи:

```bash
# Переключення у багатокористувацький консольний режим
systemctl isolate multi-user.target

# Переключення у повноцінний графічний режим
systemctl isolate graphical.target

# Переключення у режим однокористувацького відновлення
systemctl isolate rescue.target

# Екстрене виклики режимів аварійного відновлення
systemctl isolate emergency.target
```

### 2. Управління таргетом за замовчуванням (Default Target)

Таргет за замовчуванням визначає, у який саме стан переходить система після завершення етапу ініціалізації:

```bash
# Перевірка поточного таргета за замовчуванням (зчитує /etc/systemd/system/default.target)
systemctl get-default

# Встановлення графічного режиму за замовчуванням
systemctl set-default graphical.target

# Встановлення консольного режиму за замовчуванням
systemctl set-default multi-user.target
```

### 3. Аналіз залежностей та інспекція станів

Для налагодження та аналізу складних графів залежностей використовуються наступні команди:

```bash
# Перелік усіх активних цільових юнітів у пам'яті PID 1
systemctl list-units --type=target

# Перелік усіх встановлених таргетів (включаючи неактивні)
systemctl list-unit-files --type=target

# Відображення прямого дерева залежностей для вказаного таргета
systemctl list-dependencies multi-user.target

# Відображення зворотного дерева залежностей (хто залежить від цього таргета)
systemctl list-dependencies --reverse network.target
```

## Параметри командного рядка ядра (Kernel Boot Options)

Параметри завантажувального таргета можна передавати безпосередньо через командний рядок ядра під час конфігурації завантажувачів (GRUB 2, systemd-boot, EFISTUB):

- `systemd.unit=multi-user.target`: Примусове завантаження системи у консольний режим.
- `systemd.unit=graphical.target`: Примусове завантаження у графічний режим.
- `systemd.unit=emergency.target`: Негайний виклик екстреної консолі при старті.
- `1`, `s`, `S`, `single`: Короткі псевдоніми SysV, які автоматично транслюються у `rescue.target`.
- `3`: Короткий псевдонім SysV, що транслюється у `multi-user.target`.
- `5`: Короткий псевдонім SysV, що транслюється у `graphical.target`.

## Опис D-Bus API системного менеджера для target-юнітів

Управління target-юнітами на програмному рівні здійснюється через міжпроцесний зв'язок D-Bus:

- **Bus Name**: `org.freedesktop.systemd1`
- **Object Path**: `/org/freedesktop/systemd1`
- **Interface**: `org.freedesktop.systemd1.Manager`

### Ключові методи D-Bus Manager:

1. `StartUnit(in STRING name, in STRING mode, out OBJECT_PATH job)`
   Запускає вказаний юніт. Якщо параметр `mode` дорівнює `"isolate"`, виконує операцію ізоляції стану. Повертає шлях об'єкта D-Bus для створеної транзакційної роботи (`Job`).
2. `GetUnit(in STRING name, out OBJECT_PATH unit)`
   Повертає D-Bus об'єкт вказаного юніта для зчитування його властивостей.
3. `SetDefaultTarget(in STRING name, in BOOLEAN force, out ARRAY of (STRING, STRING, STRING) changes)`
   Змінює символьне посилання `default.target` на новий таргет.

### Ключові властивості D-Bus Unit (Interface `org.freedesktop.systemd1.Unit`):

- `ActiveState` (`s`): Поточний стан юніта (`active`, `reloading`, `inactive`, `failed`).
- `SubState` (`s`): Деталізований субстан (для таргетів зазвичай `active` або `dead`).
- `CanIsolate` (`b`): Значення прапорця `AllowIsolate=`.
- `Id` (`s`): Канонічне ім'я юніта.
