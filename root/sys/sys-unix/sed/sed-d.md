Коли системний адміністратор або бекенд-інженер стикається з необхідністю відредагувати файл журналу розміром 80 гігабайтів на сервері з 4 гігабайтами оперативної пам'яті, звичайний інтерактивний текстовий редактор (такий як `vim`, `nano` чи `emacs`) зазнає аварійної зупинки. Інтерактивні редактори вимагають повного завантаження документу або побудови складних внутрішніх структур у пам'яті (gap buffers, мотузкових структур rope або зв'язних списків рядків) для забезпечення довільного позиціонування курсора (random access). Запуск `vim access.log` на такому обсязі негайно активує механізм ядра Linux OOM Killer (Out-Of-Memory Killer), який примусово знищує процес редактора через вичерпання пулу сторінок оперативної пам'яті.

Аналогічний провал виникає при спробі вбудувати редагування в середину неперервного конвеєра Unix між двома мережевими процесами: `tcpdump -l | editor | logger`. Інтерактивний редактор не вміє працювати з потоком, у якого немає фіксованого кінця (EOF), оскільки чекає на завершення вводу перед відображенням інтерфейсу.

Потоковий редактор `sed` (Stream Editor) розв'язує обидві проблеми шляхом повної відмови від концепції довільного доступу до файлу. Замість того, щоб тримати документ у пам'яті, `sed` перетворює процес редагування на лінійну фабрику: він зчитує вхідний потік строго по одному рядку, поміщає його в мініатюрний буфер фіксованого розміру, виконує над ним послідовність заздалегідь скомпільованих інструкцій і негайно виштовхує результат у вихідний потік. Просторова складність обробки залишається константною `O(1)` відносно розміру файлу, що дозволяє безперешкодно трансформувати терабайти інформації з мінімальним споживанням RAM.

Детальний аналіз історичного шляху від інтерактивного редактора Кена Томпсона `ed` до створення потокового автомата Лі Макмегоном наведено у матеріалі [📜 Від редактора ed до потокового фільтра sed: народження потокового редагування](root:sys-unix/sed/hist-sed-evolution.md).

## Парадигма потокового редагування

Класичний редактор орієнтований на стан документа: користувач переміщує курсор у просторі двох вимірів (рядок і стовпець), робить правки та зберігає стан на диск. Потоковий редактор орієнтований на подію проходження байтів: документ є одновимірною послідовністю символів, яка рухається крізь нерухомий набір правил трансформації.

```
Вхідний потік ──> [ Зчитування рядка ] ──> [ Трансформація ] ──> [ Вихідний потік ]
     (stdin)           (без повернення)      (список правил)          (stdout)
```

Ця модель породжує три фундаментальні властивості:

1. **Однопрохідність (One-pass processing):** `sed` читає байти виключно вперед. Він не може за замовчуванням повернутися до попереднього рядка, якщо той уже був оброблений та виведений у stdout. Уся логіка, що вимагає озирання назад або заглядання наперед, має реалізовуватися через явне утримання рядків у спеціальних внутрішніх регістрах.
2. **Неінтерактивність (Batch execution):** Користувач не взаємодіє з процесом під час виконання. Усі інструкції — адреси фільтрації, підстановки регулярних виразів, команди видалення та злиття — формулюються у вигляді декларативного сценарію до початку обробки.
3. **Безшовна інтеграція в конвеєр (Pipeline Composability):** Оскільки `sed` використовує стандартний ввід (дескриптор `0`) як джерело та стандартний вивід (дескриптор `1`) як приймач, він виступає ідеальним перетворювачем між різнорідними процесами операційної системи.

## Внутрішня модель виконання: Pattern Space та Hold Space

Робота `sed` організована навколо неперервного життєвого циклу (Execution Cycle), який керується двома внутрішніми буферами пам'яті у просторі користувача:

- **Pattern Space (простір шаблону):** Основний робочий буфер процесу. Саме сюди ядро `sed` поміщає черговий рядок тексту для виконання трансформацій. Будь-які команди пошуку, заміни, транслітерації чи друку за замовчуванням застосовуються виключно до вмісту Pattern Space.
- **Hold Space (допоміжний простір / регістр утримання):** Резервний буфер збереження. Він не очищається між циклами зчитування рядків і виконує роль енергонезалежної пам'яті. Інженер може скопіювати туди вміст Pattern Space, накопичити кілька рядків або поміняти буфери місцями для виконання нелінійних операцій (реверс файлу, пошук багаторядкових блоків, накопичення контексту).

### Фази головного циклу обробки

Перед тим, як зчитати перший байт вхідного потоку, інтерпретатор `sed` виконує фазу попередньої компіляції сценарію. Текстові інструкції розбираються у внутрішнє абстрактне синтаксичне дерево (AST), де всі регулярні вирази трансформуються у скомпільовані структури скінченних автоматів `regex_t`, а мітки переходів перетворюються на прямі покажчики на інструкції. Якщо сценарій містить синтаксичну помилку, процес завершує роботу негайно з ненульовим кодом, не чіпаючи вхідні дані.

Після успішної ініціалізації для кожного рядка вхідного потоку виконується суворо фіксована послідовність кроків:

1. **Зчитування (Read & Strip):** Редактор вичитує символи з вхідного дескриптора аж до першого символу нового рядка `\n` (або до кінця потоку EOF).
2. **Відсікання кінцевого роздільника:** Символ `\n` видаляється з вхідного тексту. У Pattern Space потрапляє чистий рядок без кінцевого байта переводу каретки. Це критично важливо: символ `$` у регулярних виразах `sed` відповідає кінцю рядка саме тому, що `\n` не присутній у буфері під час обробки.
3. **Виконання командного ланцюжка:** Інтерпретатор перебирає скомпільований список інструкцій сценарію від першої до останньої. Для кожної команди перевіряється, чи відповідає поточний стан (номер рядка або регулярний вираз) заданій адресі. Якщо адреса збігається, команда виконується над Pattern Space, модифікуючи його вміст "на льоту". Наступна команда списку бачить уже модифікований рядок.
4. **Автоматичний друк (Auto-print):** Якщо виконання дійшло до кінця списку команд і в процесі не було викликано команду явного видалення `d`, `sed` автоматично відправляє вміст Pattern Space у стандартний вивід і дописує наприкінці символ `\n`.
5. **Очищення та перезапуск:** Вміст Pattern Space скидається, після чого цикл повторюється для наступного рядка потоку.

### Поведінка прапорця тихого режиму (`-n`)

Якщо `sed` запущено з ключем `-n` (`--quiet` або `--silent`), поведінка кроку 4 змінюється: автоматичний друк вимикається. Редактор нічого не виводить у stdout, доки в тілі сценарію не спрацює явна інструкція друку `p` (print), `P` або прапорець `p` у команді заміни `s///p`. Цей режим перетворює `sed` на розширений аналог `grep`, де виводяться лише ті рядки, що зазнали конкретної селективної мутації.

## Адресація команд: вибірковість обробки рядків

Сила `sed` полягає в тому, що кожна команда може виконуватися не безумовно над усім файлом, а строго за адресою (предикатом). Специфікація адреси вказується безпосередньо перед буквою команди:

```text
[адреса1[,адреса2]]команда[аргументи]
```

Якщо адреса відсутня, команда виконується для абсолютно кожного рядка вхідного потоку.

### 1. Адресація за абсолютними номерами рядків

`sed` підтримує внутрішній лічильник зчитаних рядків, починаючи з одиниці:

- `5d` — видалити виключно 5-й рядок файлу.
- `1,10p` — застосувати команду друку до рядків з 1-го по 10-й включно.
- `$d` — метасимвол `$` в адресному полі позначає останній рядок вхідного потоку (видалити фінальний рядок).

У GNU sed доступне розширення крокової адресації у форматі `first~step`:

```bash
sed -n '1~2p' data.txt   # Вивести всі непарні рядки (1, 3, 5, 7...)
sed -n '0~2p' data.txt   # Вивести всі парні рядки (2, 4, 6, 8...)
```

Крім того, GNU sed підтримує спеціальну адресу `0`, яка дозволена виключно як початкова адреса числового діапазону (наприклад, `0,/^$/d` видаляє всі рядки від початку файлу до першого порожнього рядка включно, навіть якщо перший рядок уже є порожнім). У стандарті POSIX адреса 0 вважається синтаксичною помилкою.

### 2. Адресація за регулярними виразами (Pattern Matching)

Адреса може бути регулярним виразом, обмеженим косими рисками `/шаблон/`:

```bash
sed '/^#/d' config.conf          # Видалити всі рядки з коментарями (що починаються на #)
sed -n '/CRITICAL/p' server.log  # Надрукувати лише рядки, що містять слово CRITICAL
```

Якщо шаблон містить косі риски (наприклад, шляхи у файловій системі `/var/log/syslog`), для уникнення громіздкого екранування `\/var\/log\/syslog` `sed` дозволяє перевизначити роздільник за допомогою синтаксису `\%шаблон%`:

```bash
sed '\%/var/log/%d' paths.txt
```

### 3. Діапазони адрес та механіка тригера (Trigger Flip-Flop)

Діапазон, заданий двома регулярними виразами `/BEGIN/,/END/`, працює за принципом тригера зі станом (finite-state machine):

```
                       Збіг /BEGIN/ (Тригер = ON)
Вхідний потік ────────────────────▼─────────────────────
[поза діапазоном]             [активна зона дій]
──────────────────────────────────▲─────────────────────
                       Збіг /END/ (Тригер = OFF)
```

1. Стан тригера спочатку вимкнений (`OFF`).
2. Коли `sed` зустрічає рядок, що містить `/BEGIN/`, тригер перемикається у стан `ON`, і команда виконується над цим рядком.
3. Усі наступні рядки автоматично вважаються такими, що потрапляють у діапазон, і команда застосовується до кожного з них.
4. Коли `sed` доходить до рядка зі збігом `/END/`, команда виконується над ним востаннє, після чого тригер перемикається в стан `OFF`.

**Крайові випадки поведінки діапазонів:**
- Якщо шаблон `/END/` збігається в тому ж самому рядку, де вперше знайдено `/BEGIN/`, діапазон **не закривається** на цьому рядку: `sed` почне шукати `/END/` лише у наступних рядках, оскільки закриття перевіряється на наступній ітерації.
- Якщо шаблон `/END/` взагалі не зустрінеться у файлі після відкриття тригера, дія команди пошириться до самого кінця потоку (до сигналу EOF).

### 4. Інверсія предикатів (`!`) та групування блоків `{}`

Символ оклику `!`, розміщений після адреси, інвертує умову виконання:

```bash
sed '/^\[DATABASE\]/!d' app.ini    # Видалити все, крім рядка із заголовком секції
```

Для застосування цілого пакета дій до однієї адреси використовується групування фігурними дужками `{ ... }`:

```bash
sed -n '/^ERROR/,/^END/ {
    s/password=[^ ]*/password=REDACTED/g
    s/token=[^ ]*/token=REDACTED/g
    p
}' service.log
```

Повний довідковий перелік адресних модифікаторів та керуючих структур наведено у матеріалі [📋 Повний довідник команд, адрес та прапорців потокового редактора sed](root:sys-unix/sed/api-sed-command-reference.md).

## Команда заміни `s/regex/replacement/flags`

Команда підстановки `s` є найбільш часто використовуваною операцією `sed`. Її синтаксична структура має вигляд:

```text
[адреса]s/регулярний_вираз/рядок_заміни/[прапорці]
```

### Довільні роздільники

Перший символ, що стоїть після літери `s`, автоматично стає роздільником полів команди. Замість традиційного `/` можна обрати будь-який друкований символ:

```bash
# Нечитабельний варіант із «синдромом похилої риски» (leaning toothpick syndrome):
sed 's/\/usr\/local\/bin/\/opt\/bin/g' script.sh

# Ідіоматичний варіант з роздільником | або #:
sed 's|/usr/local/bin|/opt/bin|g' script.sh
sed 's#/usr/local/bin#/opt/bin#g' script.sh
```

### Спеціальні метасимволи поля заміни

У полі `рядок_заміни` звичайні символи інтерпретуються буквально, за винятком двох конструкцій:

1. **Символ амперсанда (`&`):** Підставляє **весь фрагмент тексту**, який фактично збігся з регулярним виразом.
   ```bash
   echo "порт: 8080" | sed 's/[0-9]\+/(&)/'
   # Результат: порт: (8080)
   ```
2. **Зворотні посилання (Backreferences `\1`..`\9`):** Посилаються на підгрупи, захоплені круглими дужками в регулярному виразі. У базовому синтаксисі (BRE) дужки екрануються `\(...\)`, у розширеному (ERE, прапорець `-E`) використовуються звичайні `(...)`.
   ```bash
   # Перестановка порядку слів у форматі ключ=значення:
   echo "timeout = 30" | sed -E 's/^([a-z]+) = ([0-9]+)/\1: \2s/'
   # Результат: timeout: 30s
   ```

### Прапорці виконання заміни

| Прапорець | Призначення | Приклад та поведінка |
|---|---|---|
| `g` (global) | Замінити всі входження шаблону в межах поточного рядка. Без `g` замінюється лише перший знайдений збіг. | `s/foo/bar/g` |
| `ЧИСЛО` (1..N) | Замінити виключно `N`-е входження шаблону в рядку, пропустивши всі попередні. | `s/foo/bar/2` (замінить лише друге слово foo) |
| `p` (print) | Якщо заміна відбулася успішно, негайно відправити модифікований рядок у stdout. Зазвичай комбінується з `sed -n`. | `sed -n 's/ERR_\([0-9]\+\)/ERROR \1/p' log.txt` |
| `I` або `i` | Виконувати зіставлення регулярного виразу без урахування регістру символів (case-insensitive). | `s/warning/ALERT/Ig` |
| `w файл` | У разі успішної заміни записати отриманий рядок у вказаний файл на диску. | `s/admin/root/gw /tmp/replaced_users.txt` |
| `e` (execute) | Розширення GNU sed: виконати вміст Pattern Space як команду системної оболонки `/bin/sh` і вставити результат. | `s/^ls (.*)/ls -la \1/e` |

Слід пам'ятати про ризики безпеки при використанні прапорця `e`: якщо вхідний текст надходить від ненадійних клієнтів (наприклад, заголовки HTTP або імена користувачів), підстановка може призвести до довільного виконання команд у системі (Arbitrary Code Execution).

## Маніпуляція потоком: базові команди

Окрім підстановки `s`, `sed` надає набір низькорівневих команд для модифікації потоку рядків:

### Видалення та керування циклом (`d` та `q`)

- `d` (Delete): Негайно очищає Pattern Space, перериває виконання командного списку для поточного рядка та переходить до зчитування наступного рядка вхідного потоку. Автоматичний друк для цього рядка не викликається.
- `q` (Quit): Негайно виводить поточний рядок (якщо не задано `-n`) і завершує процес `sed`. Використовується для оптимізації швидкодії, коли обробляти решту файлу немає сенсу (наприклад, `sed '100q' large_file.txt` еквівалентно швидкому `head -n 100`, але без марного читання гігабайтів залишкового тексту).

### Вставка, додавання та заміна (`i\`, `a\`, `c\`)

- `i\` (Insert): Вставляє рядок тексту перед поточним рядком. Текст відправляється безпосередньо у вихідний потік.
- `a\` (Append): Реєструє рядок для додавання після виведення поточного Pattern Space.
- `c\` (Change): Замінює весь поточний рядок (або весь блок рядків, якщо вказано діапазон) новим текстом і негайно починає новий цикл.

```bash
sed '/\[mysqld\]/a\max_connections = 500' /etc/my.cnf
```

### Робота з файлами (`r` та `w`)

- `r файл` (Read): Зчитує вміст зовнішнього файлу і додає його у вихідний потік після поточного рядка. Якщо файл не знайдено, помилка не генерується.
- `w файл` (Write): Записує поточний вміст Pattern Space у зовнішній файл на диску. Якщо файл не існував, він створюється; якщо існував — перезаписується на початку роботи `sed`.

## Просунуте програмування: Hold Space, багаторядковий режим та переходи

Базових операцій з одним рядком достатньо для примітивної фільтрації. Проте для розв'язання складних інженерних задач (об'єднання логів стек-трейсу Java, видалення багаторядкових XML-коментарів, реверс порядку рядків) `sed` перетворюється на повноцінну машину станів.

![Операції взаємодії між Pattern Space та Hold Space](/root/sys/sys-unix/sed/img/sed-hold-pattern-exchange.svg)
*Операції копіювання, додавання та обміну даними між регістрами Pattern Space та Hold Space.*

### Команди маніпуляції Hold Space

| Команда | Назва операції | Вплив на стан пам'яті |
|---|---|---|
| `h` | Hold (копіювання) | Перезаписує Hold Space поточним вмістом Pattern Space: `Hold = Pattern`. |
| `H` | Hold Append (додавання) | Додає символ `\n` та вміст Pattern Space до кінця Hold Space: `Hold = Hold + '\n' + Pattern`. |
| `g` | Get (відновлення) | Перезаписує Pattern Space вмістом Hold Space: `Pattern = Hold`. |
| `G` | Get Append (злиття) | Додає символ `\n` та вміст Hold Space до кінця Pattern Space: `Pattern = Pattern + '\n' + Hold`. |
| `x` | Exchange (обмін) | Атомарно міняє місцями вміст двох буферів: `swap(Pattern, Hold)`. |

### Приклад: Реалізація утиліти `tac` (реверс рядків файлу)

Класична демонстрація сили Hold Space — розгортання всього вхідного файлу у зворотному порядку за допомогою трисимвольного сценарію `1!G;h;$p`:

```bash
sed -n '1!G;h;$p' input.txt
```

Покрокова трасування цього алгоритму:
1. `1!G`: Для всіх рядків, крім першого (`1!`), додати поточний Hold Space до Pattern Space через `\n`. На першому рядку в Hold Space нічого немає, тому дія пропускається. На другому рядку в Pattern Space утворюється комбінація `Рядок_2\nРядок_1`.
2. `h`: Зберегти поточний накопичений інвертований стек з Pattern Space назад у Hold Space.
3. `$p`: Коли `sed` доходить до останнього рядка файлу (`$`), весь накопичений зворотний текст друкується у вихідний потік.

### Багаторядкові команди: `N`, `D`, `P`

Стандартна команда `s/foo\nbar/baz/` у `sed` не спрацює за звичайних умов, оскільки `\n` відсікається на етапі читання. Для роботи з патернами, що перетинають межу рядків, використовується трійка багаторядкових інструкцій:

- `N` (Next multiline): Зчитує наступний рядок із вхідного потоку і додає його через `\n` до поточного Pattern Space. Тепер Pattern Space містить два фізичні рядки.
- `P` (Print multiline): Друкує лише першу частину Pattern Space до першого знайденого символу `\n`.
- `D` (Delete multiline): Видаляє з Pattern Space фрагмент тексту від початку до першого знайденого `\n`, після чого **перезапускає цикл сценарію спочатку над залишком буфера без зчитування нового рядка**.

Комбінація `N;D` створює алгоритм ковзного вікна (sliding window) розміром у 2 рядки. Розглянемо приклад обробки трьох рядків тексту `A`, `B`, `C`:

```text
Крок 1: Зчитано 'A' в Pattern Space.
        Виконано N: Pattern Space містить 'A\nB'.
        Виконано P: Надруковано 'A'.
        Виконано D: 'A\n' видалено, в Pattern Space залишився 'B'.
Крок 2: Цикл перезапущено без читання.
        Виконано N: Дочитано 'C', Pattern Space містить 'B\nC'.
        Виконано P: Надруковано 'B'.
        Виконано D: 'B\n' видалено, в Pattern Space залишився 'C'.
```

Цей цикл дозволяє ефективно аналізувати взаємозв'язки між суміжними рядками у нескінченних потоках.

### Керування потоком виконання: мітки `:label`, переходи `b` та `t`

`sed` підтримує безумовні та умовні переходи між командами, що робить його тьюрінг-повною мовою програмування:

- `:label` — оголошення точки переходу в сценарії.
- `b label` (Branch) — безумовний перехід на `:label`. Якщо мітку не вказано, керування переходить у кінець сценарію (завершує поточний цикл над цим рядком).
- `t label` (Test on success) — умовний перехід на `:label`. Стрибок виконується **лише за умови**, що хоча б одна попередня команда підстановки `s///` виконала успішну заміну з моменту зчитування рядка або попереднього виклику `t`.
- `T label` (Test on failure, GNU) — умовний перехід за невдачі: стрибок виконується, якщо жодна заміна `s///` не відбулася.

```bash
# Алгоритм видалення всіх HTML-тегів включно з тими, що розбиті на кілька рядків:
sed -E ':loop
    s/<[^>]*>//g
    /<[^>]*$/{
        N
        b loop
    }' document.html
```

Повний вихідний код роботизованого емулятора циклу `sed` з підтримкою багаторядкових команд на мовах C та C++ наведено у матеріалі [⚙️ Реалізація спрощеного потокового редактора на C та C++](root:sys-unix/sed/proj-stream-editor-emulator.md).

## Редагування на місці (`sed -i`): архітектура та системні пастки

Прапорець `-i` (`--in-place`) створює ілюзію того, що `sed` безпосередньо перезаписує сектори файлу на диску. Насправді файлові системи Unix (ext4, XFS, Btrfs) не підтримують довільну вставку чи видалення байтів усередині файлу без повного перезапису його залишку.

![Механізм оновлення inode при виконанні sed -i](/root/sys/sys-unix/sed/img/sed-inplace-inodes.svg)
*Механіка роботи sed -i: створення тимчасового файлу з новим номером Inode та системний виклик rename.*

### Системний алгоритм `sed -i`

Коли виконується команда `sed -i 's/foo/bar/' config.conf`, процес здійснює такі системні виклики:

1. **Створення тимчасового файлу:** `sed` відкриває новий анонімний тимчасовий файл у тому ж каталозі, де лежить цільовий файл (наприклад, через функцію `mkstemp()` створюється `.sedXXXXXX`). Створення файлу саме в тому ж каталозі є критичним для того, щоб наступний системний виклик `rename` гарантовано відбувався в межах однієї файлової системи (інакше виклик поверне помилку `EXDEV` — Invalid cross-device link).
2. **Перенаправлення виводу:** Потік модифікованих рядків записується в цей тимчасовий файл.
3. **Копіювання метаданих:** `sed` намагається скопіювати права доступу (`chmod`), власника (`chown`) та мітки часу зі старого файлу на новий.
4. **Атомарне перейменування:** Викликається системний виклик `rename(".sedXXXXXX", "config.conf")`.

### Критичні інженерні наслідки та типові аварії

Цей механізм має чотири серйозні підводні камені, які часто призводять до збоїв у продакшн-середовищах:

#### 1. Зміна номера Inode та розрив Hard Links

Оскільки системний виклик `rename` просто замінює запис у каталозі новим індексним дескриптором (inode), старий файл фізично залишається на диску, якщо на нього посилався жорсткий лінк (Hard link). Зв'язок між жорсткими посиланнями назавжди розривається: один файл містить нові дані, інший — старі.

#### 2. Знищення символічних посилань (Symlinks)

Якщо файл конфігурації є символічним посиланням (наприклад, утиліта `systemd` або Docker контейнери монтують `/etc/app/config.json -> /var/run/secrets/config.json`), стандартний `sed -i` **видаляє симлінк** і створює на його місці звичайний регулярний файл! Оригінальний цільовий файл залишається незмінним, а контейнер чи служба втрачає зв'язок із джерелом конфігурації.

*Виправлення:* Використовувати прапорець `--follow-symlinks`:
```bash
sed -i --follow-symlinks 's/DEBUG=true/DEBUG=false/' /etc/app/config.json
```

#### 3. Втрата прав доступу, POSIX ACLs та атрибутів безпеки

Якщо користувач запускає `sed -i` під звичайним обліковим записом, новий файл створюється з поточною маскою створення файлів `umask`. Розширені атрибути файлової системи (`xattr`), списки контролю доступу (POSIX ACLs) та контексти SELinux можуть бути безповоротно скинуті або замінені на дефолтні.

#### 4. Несумісність синтаксису GNU sed та BSD/macOS sed

У системі macOS (BSD sed) прапорець `-i` вимагає обов'язкового зазначення суфікса резервної копії як окремого аргументу:

```bash
# Працює в Linux (GNU sed), але падає з помилкою в macOS (BSD sed):
sed -i 's/a/b/' file.txt

# Працює в macOS, створюючи файл file.txt і видаляючи бекап:
sed -i '' 's/a/b/' file.txt

# Переносний синтаксис для обох операційних систем:
sed -i.bak 's/a/b/' file.txt && rm file.txt.bak
```

## Продуктивність, оптимізації та межі застосування

### Вплив змінної середовища `LC_ALL=C`

За замовчуванням у сучасних Linux-дистрибутивах встановлено локаль UTF-8 (наприклад, `uk_UA.UTF-8` або `en_US.UTF-8`). При виконанні регулярних виразів з діапазонами символів (`[a-z]`, `[0-9]`, `.*`) рушій `sed` змушений декодувати багатобайтові послідовності та враховувати складні правила колізії (collation rules).

Якщо обробляється суто ASCII-текст (наприклад, системні логи Nginx або дампи бінарних ідентифікаторів), встановлення `LC_ALL=C` перемикає `sed` на побайтову обробку без декодування UTF-8, що дає прискорення обробки в 5–10 разів:

```bash
# Повільно на великих файлах:
sed 's/[0-9]\+/ID/g' access.log > /dev/null

# У 7 разів швидше:
LC_ALL=C sed 's/[0-9]\+/ID/g' access.log > /dev/null
```

### Коли обирати sed, а коли переходити на awk чи мови загального призначення

Потоковий редактор `sed` є неперевершеним інструментом для швидкої підстановки та однопрохідної фільтрації. Проте намагання реалізувати на `sed` складну бізнес-логіку з арифметичними підрахунками або асоціативними масивами перетворює код на непідтримуваний набір нечитабельних мнемонік (`h;x;s/.../.../;x;G`).

```
                              Складність задачі
───────────────────────────────────────────────────────────────────────────►
Заміна підрядків       Колонки, поля,         Складні структури даних,
Фільтрація рядків      математика,            JSON, робота з мережею,
Редагування на місці   підрахунок сум         валідація схем
      ▼                      ▼                      ▼
    [ sed ]               [ awk ]            [ Python / Go / Rust ]
```

- **`sed` обирають, коли:** Потрібно замінити текст за регулярним виразом, вирізати фіксований діапазон рядків або виконати просту маніпуляцію над цілим рядком у конвеєрі.
- **`awk` обирають, коли:** З'являється робота з окремими стовпцями (полями `$1, $2`), необхідність підсумовування чисел, агрегації статистики або фільтрації за числовими порогами.
- **Python / Go / C++ обирають, коли:** Потрібно розбирати структуровані формати (JSON, YAML, Protobuf), звертатися до зовнішніх API чи баз даних або обробляти складні багатовимірні структури даних.
