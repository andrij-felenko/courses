# 📋 Повний довідник команд, адрес та прапорців потокового редактора sed

Потоковий редактор `sed` (Stream Editor) — це детермінований неінтерактивний текстовий процесор, що застосовує скомпільований набір інструкцій до кожного рядка вхідного байтового потоку. Редактор функціонує за моделлю лінійного конвеєра з двома внутрішніми регістрами пам'яті: основним робочим буфером `Pattern Space` та допоміжним буфером збереження стану `Hold Space`.

Нижче наведено системну специфікацію внутрішньої архітектури пам'яті буферів, фаз головного життєвого циклу виконання, потоку керування, синтаксису виклику, параметрів командного рядка, системної взаємодії з файловими системами при in-place редагуванні (`-i`), буферизації I/O та міжпроцесних сигналів конвеєрів (`SIGPIPE`, `-u`, ранній вихід через `q`), обробки двійкових даних та null-термінованих записів (`-z`), внутрішньої архітектури рушія регулярних виразів (DFA/NFA) та впливу локалей, формату адресних предикатів, повного реєстру команд, прапорців підстановки, побудови циклічних автоматів, комплексних інженерних рецептів рефакторингу вихідного коду C/C++, оптимізацій продуктивності на великих даних у порівнянні з `awk` та `perl`, кодів виходу та матриці міжплатформної сумісності стандартів POSIX.1-2017/2024, GNU sed та BSD sed.

## Низькорівнева архітектура пам'яті: Pattern Space та Hold Space

У просторі користувача процес `sed` оперує двома основними динамічними структурами даних. Обидва регістри представляють собою неперервні байтові масиви на купі (heap), що динамічно масштабуються через системний розподільник пам'яті (`malloc`/`realloc`):

```text
                   ┌────────────────────────────────────────────────────────┐
   Вхідний потік ──►  Pattern Space (Робочий буфер: char *active_buf)       ├──► Вихідний потік
      (stdin)      │  - динамічний розмір: pattern_len, pattern_cap         │      (stdout)
                   │  - інваріант: нуль-термінатор '\0' на позиції len      │
                   └───────────▲────────────────────────────────┬───────────┘
                               │        h / H (копіювання /     │
                         g / G │               додавання)       │
                   (відновлення│                                │
                    / злиття)  │        x (нуль-копійний swap)  │
                               │                                │
                   ┌───────────┴────────────────────────────────▼───────────┐
                   │  Hold Space (Регістр утримання: char *hold_buf)        │
                   │  - зберігає байти між циклами читання потоку           │
                   │  - динамічний розмір: hold_len, hold_cap               │
                   └────────────────────────────────────────────────────────┘
```

### Інваріанти пам'яті та стратегія виділення

1. **Інваріант нульового байта (`\0`):** На позиції `buf->data[buf->len]` завжди зберігається нульовий байт `\0`. Це забезпечує пряму передачу покажчика `pattern_space.data` у виклики `regexec()`, `fputs()`, `puts()` та системний виклик `write()` без створення тимчасових копій.
2. **Геометричне масштабування:** При копіюванні або конкатенації нова місткість обчислюється з запасом (коефіцієнт росту `1.5x` або вирівнювання за блоком у 64/128 байтів), що гарантує амортизовану константну складність `O(1)` для операцій нарощування буфера.
3. **Відсутність статичних обмежень:** На відміну від історичних версій Unix V7 (де розмір буфера був зафіксований на рівні 4000 байтів), сучасні реалізації GNU sed та BSD sed масштабують буфери до меж доступного віртуального адресного простору процесу.

### Механіка команд роботи з регістрами на рівні покажчиків та байтів

Взаємодія між `Pattern Space` та `Hold Space` реалізується через набір низькорівневих операцій:

- **`h` (Hold Copy):** Повний перезапис Hold Space вмістом Pattern Space. Якщо `pattern_space.len + 1 > hold_space.cap`, виконується `realloc(hold_space.data, new_cap)`. Потім здійснюється пряме побайтове копіювання `memcpy(hold_space.data, pattern_space.data, pattern_space.len + 1)` та встановлення `hold_space.len = pattern_space.len`.
- **`H` (Hold Append):** Конкатенація з роздільником `\n`. Запитуваний розмір становить `needed = hold_space.len + 1 + pattern_space.len + 1`. Після перевірки ємності на позицію `hold_space.data[hold_space.len]` записується байт `\n` (ASCII `0x0A`), слідом через `memcpy` додається вміст Pattern Space, і ставиться кінцевий `\0`.
  - *Крайовий випадок POSIX:* На старті процесу `Hold Space` вважається порожнім рядком нульової довжини. Перший виклик команди `H` формує в `Hold Space` послідовність `\n<вміст_першого_рядка>`. Для запобігання початковому порожньому рядку застосовують ідіому `1h; 1!H`.
- **`g` (Get Copy):** Повний перезапис Pattern Space вмістом Hold Space. Пам'ять `pattern_space` перевиділяється за потреби, дані переносяться викликом `memcpy`, а довжина оновлюється: `pattern_space.len = hold_space.len`.
- **`G` (Get Append):** Приєднання Hold Space до Pattern Space через символ `\n`. Байт `\n` додається на позицію `pattern_space.len`, після чого копіюється корисне навантаження Hold Space.
- **`x` (Exchange):** Нуль-копійний обмін дескрипторами. Здійснюється swap трьох пар полів (`data`, `len`, `cap`) між структурами `pattern_space` та `hold_space`. Складність операції є строго константною `O(1)`, оскільки виділення пам'яті на купі та копіювання байтів відсутні.
- **`z` (Zap, GNU sed):** Швидке очищення робочого буфера. Встановлює `pattern_space.len = 0` та `pattern_space.data[0] = '\0'`. Виділена ємність `cap` залишається без змін, що запобігає зайвим накладним витратам на наступні виділення пам'яті.

## Внутрішній конвеєр обробки та життєвий цикл виконання

Потоковий редактор функціонує за строгим детермінованим циклом обробки (Execution Cycle). Кожен цикл відповідає обробці однієї порції вхідних даних (за замовчуванням — одного рядка):

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 1. Зчитування байтів до '\n' або EOF (read / getline)                  │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 2. Відсікання кінцевого роздільника '\n' -> Pattern Space             │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 3. Оцінка адресних предикатів (номер рядка, regex_t, flip-flop стан)   │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 4. Послідовне виконання командного ланцюжка (ip = 0 .. N)             │
 └──────────────────┬──────────────────────────────────┬──────────────────┘
                    │                                  │
      (команда d)   │                    (команда D)   │ (якщо є '\n')
                    ▼                                  ▼
 ┌─────────────────────────────┐        ┌─────────────────────────────────┐
 │ Очистити Pattern Space,     │        │ Видалити до першого '\n',       │
 │ скинути прапорець виводу,   │        │ перезапустити виконання з ip = 0│
 │ почати новий цикл з читання │        │ БЕЗ зчитування нового рядка     │
 └─────────────────────────────┘        └─────────────────────────────────┘
                    │
                    ▼ (звичайне завершення ланцюжка)
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 5. Автоматичний друк (Auto-print): якщо не активний -n і не було d/D,  │
 │    записати Pattern Space + '\n' у дескриптор stdout                   │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 6. Скидання відкладених черг виводу: скинути буфер команди a (append)  │
 │    та вивести вміст файлів за командою r (read file) у stdout          │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 7. Очищення Pattern Space та перехід до кроку 1 для наступного рядка   │
 └────────────────────────────────────────────────────────────────────────┘
```

### Деталізація фаз конвеєра

1. **Фаза читання та вилучення роздільника:** `sed` зчитує потік із поточного файлового дескриптора до появи символу `\n` (або `\0` при використанні прапорця `-z`). Кінцевий символ переводу рядка видаляється. Робочий буфер `Pattern Space` містить виключно чистий корисний текст рядка. Завдяки цьому символ `$` у регулярних виразах зіставляється з останнім символом тексту, а не з символом нового рядка.
2. **Фаза виконання інструкцій:** Покажчик інструкцій `ip` (Instruction Pointer) послідовно проходить скомпільований масив команд. Для кожної інструкції перевіряється адресний фільтр. Якщо адреса збігається, команда модифікує `Pattern Space` безпосередньо. Будь-яка наступна інструкція працює над уже модифікованим рядком.
3. **Фаза автоматичного виведення (Auto-print):** Якщо виконання досягло кінця командного списку без виклику команд `d` чи `D`, і процес не запущено з прапорцем `-n`, інтерпретатор автоматично відправляє весь вміст `Pattern Space` у вихідний потік `stdout` разом із символом перенесення рядка `\n`.
4. **Фаза відкладеного введення/виведення (Deferred Queues):** Команди вставки тексту `a` (append) та зчитування файлу `r` (read file) не змінюють `Pattern Space` і не виводять дані негайно. Вони реєструють текст або дескриптор у внутрішній черзі виводу. Запис цих черг у `stdout` відбувається строго після завершення кроку автоматичного виведення або безпосередньо перед виконанням чергової команди зчитування рядка `n`/`N`.

### Механіка керування потоком: порівняльний аналіз команд `d` проти `D` та `n` проти `N`

Розуміння точної поведінки команд на межах потоку є ключовим для побудови багаторядкових конвеєрів:

| Критерій порівняння | `d` (Delete All) | `D` (Delete First Line) |
|---|---|---|
| **Обсяг видалення з буфера** | Повністю очищає весь вміст `Pattern Space` (`len = 0`). | Видаляє текст від початку буфера до першого роздільника `\n` включно. |
| **Поведінка, якщо `\n` відсутній** | Очищає буфер, перериває скрипт, читає наступний рядок. | Повністю очищає буфер, перериває скрипт, читає наступний рядок (ідентично `d`). |
| **Поведінка, якщо `\n` присутній** | Повністю очищає весь багаторядковий буфер. | Видаляє перший підрядок. **Перезапускає скрипт з найпершої команди (`ip = 0`) над залишком буфера БЕЗ зчитування нового рядка з входу!** |
| **Автоматичний друк** | Заборонений. | Заборонений для видаленої частини; залишок буфера підлягає обробці. |

| Критерій порівняння | `n` (Next Line) | `N` (Next Multiline Append) |
|---|---|---|
| **Дія над поточним буфером** | Друкує `Pattern Space` у `stdout` (якщо не `-n`), після чого повністю його очищає. | Зберігає поточний вміст `Pattern Space` без друку. |
| **Дія з новим рядком** | Зчитує наступний рядок із входу і поміщає його в `Pattern Space` як єдиний вміст. | Зчитує наступний рядок і **додає його до кінця поточного буфера через роздільник `\n`**. |
| **Покажчик інструкцій (`ip`)** | Продовжує виконання з **наступної команди** після `n`. | Продовжує виконання з **наступної команди** після `N`. |
| **Лічильник номерів рядків** | Збільшується на `1`. | Збільшується на `1`. |
| **Поведінка при досягненні EOF** | Процес негайно завершує роботу. | **POSIX:** друкує `Pattern Space` (якщо не `-n`) і виходить; **GNU:** виходить без виводу буфера. |

## Синтаксис виклику та опції командного рядка

Програма `sed` приймає інструкції безпосередньо з аргументів командного рядка або зчитує їх із зовнішнього файлу сценарію.

```text
# Одиночний вираз трансформації:
sed [ОПЦІЇ] 'СЦЕНАРІЙ' [ВХІДНІ_ФАЙЛИ...]

# Ланцюжок послідовних виразів:
sed [ОПЦІЇ] -e 'СЦЕНАРІЙ_1' -e 'СЦЕНАРІЙ_2' ... [ВХІДНІ_ФАЙЛИ...]

# Виконання сценарію із зовнішнього файлу:
sed [ОПЦІЇ] -f файл_сценарію.sed [ВХІДНІ_ФАЙЛИ...]

# Комбінований виклик (файли сценаріїв разом з інлайн-інструкціями):
sed [ОПЦІЇ] -f base_rules.sed -e 's/DEBUG/INFO/g' [ВХІДНІ_ФАЙЛИ...]
```

Якщо перелік `ВХІДНІ_ФАЙЛИ` не задано або як ім'я файлу передано дефіс `-`, `sed` зчитує дані зі стандартного вхідного потоку (`stdin`, файловий дескриптор `0`). Якщо передано кілька файлів, `sed` за замовчуванням обробляє їх як єдиний безперервний потік (конкатенацію), зберігаючи наскрізну нумерацію рядків.

### Реєстр опцій командного рядка

| Опція | Довгий еквівалент GNU | Стандарт / Реалізація | Опис та системна дія |
|---|---|---|---|
| `-n` | `--quiet`, `--silent` | POSIX, GNU, BSD | Вимикає автоматичне виведення (auto-print) `Pattern Space` у `stdout` наприкінці кожного циклу. Вивід відбувається лише за явними командами `p`, `P` або прапорцем `p` команди `s///p`. Якщо скрипт починається з `#n` у першому рядку, режим `-n` вмикається автоматично. |
| `-e СКРИПТ` | `--expression=СКРИПТ` | POSIX, GNU, BSD | Додає інструкції зазначеного рядка до черги виконання. Дозволяє передавати кілька незалежних блоків команд, які інтерпретуються в порядку їх передачі. Інструкції всередині рядка розділяються крапкою з комою `;` або символом `\n`. |
| `-f ФАЙЛ` | `--file=ФАЙЛ` | POSIX, GNU, BSD | Зчитує інструкції з файлу `ФАЙЛ`. Команди у файлі розділяються символами нового рядка `\n` або крапкою з комою `;`. Порожні рядки та рядки, що починаються з `#`, ігноруються як коментарі (за винятком спеціального маркера `#n` на початку файлу). |
| `-i[СУФ]` | `--in-place[=СУФ]` | GNU, BSD (різний синтаксис) | Редагування файлів на місці. `sed` створює тимчасовий файл у тому ж каталозі, записує в нього результат трансформації, копіює права доступу (`chmod`/`chown`) і викликає `rename()` для атомарної заміни. У GNU sed суфікс бекапу необов'язковий і пишеться разом (`-i.bak`), у BSD sed суфікс є обов'язковим окремим аргументом (`-i ''` для відмови від бекапу). |
| `-E`, `-r` | `--regexp-extended` | POSIX (лише `-E`), GNU, BSD | Вмикає режим розширених регулярних виразів (ERE). Метасимволи `+`, `?`, `|`, `(`, `)`, `{`, `}` трактуються як оператори без зворотного слеша `\`. Прапорець `-r` є застарілим синонімом GNU; `-E` закріплено у POSIX.1-2024. |
| `-s` | `--separate` | GNU sed | Обробляє кожен вхідний файл як повністю незалежний потік. Лічильник номерів рядків `1..$` та стани тригерів адресних діапазонів `/BEGIN/,/END/` автоматично скидаються на початку кожного нового файлу. |
| `-z` | `--null-data`, `--zero-terminated` | GNU sed | Змінює роздільник записів з `\n` (ASCII `0x0A`) на нульовий байт NUL (`\0`, ASCII `0x00`). Дозволяє безпечно обробляти списки файлів від `find -print0`, `grep -Z` або xargs-сумісні потоки. |
| `-u` | `--unbuffered` | GNU, BSD | Перемикає буферизацію вводу та виводу у мінімальний режим. Дані зчитуються з дескриптора дрібними порціями й негайно виштовхуються у `stdout` через `fflush()`, що необхідно при обробці потоків реального часу (наприклад, `tail -f log | sed -u ...`). |
| `-b` | `--binary` | GNU sed | Відкриває вхідні та вихідні файли в бінарному режимі (запобігає автоматичній трансляції байтів `CR/LF` у `LF` на платформах Windows/DOS). На POSIX-системах опція ігнорується. |
| `--posix` | — | GNU sed | Примусово вимикає всі специфічні розширення GNU sed (такі як `first~step`, `0,/re/`, `addr,+N`, `addr,~N`, `T`, `Q`, `z`, `\L`, `\U`, прапорець `e`), забезпечуючи сувору відповідність специфікації IEEE Std 1003.1. |
| `--follow-symlinks` | — | GNU sed | Використовується разом із `-i`. При роботі з символічним посиланням `sed` за замовчуванням замінює сам симлінк на звичайний файл. Ця опція примушує слідувати за посиланням і модифікувати безпосередньо цільовий файл. |
| `--sandbox` | — | GNU sed | Режим безпеки (пісочниця). Забороняє виконання зовнішніх команд (команда та прапорець `e`), а також блокує відкриття довільних файлів на читання/запис командами `r`, `R`, `w`, `W`. |
| `--help`, `--version` | — | GNU sed | Виводить довідку використання або версію програми та завершує процес із кодом `0`. |

## Системне оточення та інженерна механіка in-place редагування (-i)

Опція in-place редагування (`-i` / `--in-place`) створює ілюзію прямої зміни файлу на накопичувачі. Однак у потоковій однопрохідній моделі відкриття файлу для прямого перезапису через `open(O_TRUNC)` або позиціонування `lseek(fd, 0, SEEK_SET)` є фізично неприпустимим: затирання перших байтів файлу призвело б до безповоротної втрати наступних рядків ще до того, як `sed` встигне їх вичитати.

З цієї причини `sed` реалізує **транзакційну заміну файлу через тіньовий буфер файлової системи**.

```text
До редагування:
  Каталог (dentry) "app.conf"  ──► Inode #10425 (старі блоки даних на диску)
  Hard link "app.conf.bak"     ──► Inode #10425

У процесі виконання sed -i:
  1. mkstemp("sedXXXXXX")      ──► Inode #88912 (у тому ж каталозі)
  2. fchmod / fchown / xattr  ──► копіювання метаданих з Inode #10425 на #88912
  3. fsetfilecon (SELinux)    ──► перенесення мітки безпеки на Inode #88912
  4. Потоковий запис даних     ──► наповнення Inode #88912
  5. rename("sedXXXXXX", "app.conf") ──► атомарна підміна запису в dentry

Після виклику rename(2):
  Каталог "app.conf"           ──► Inode #88912 (новий вміст)
  Hard link "app.conf.bak"     ──► Inode #10425 (старий незмінений вміст) [РОЗРИВ ЗВ'ЯЗКУ!]
```

### 1. Алгоритм взаємодії з файловими системами та створення `sedXXXXXX`

1. **Генерація унікального імені тимчасового файлу:** Процес `sed` викликає `mkstemp(3)` або `open(O_CREAT | O_EXCL | O_RDWR, 0600)` для створення тимчасового файлу за шаблоном `sedXXXXXX` (або `sed<PID><hash>`).
2. **Локалізація в тому самому каталозі:** Тимчасовий файл створюється **виключно в тому ж каталозі**, де лежить цільовий файл, а не у спільному системному каталозі `/tmp`.
   - *Причина обмеження VFS:* Системний виклик `rename(2)` є строго локальним для суперблока файлової системи (VFS mount point). Якщо розмістити тимчасовий файл у `/tmp` (який часто змонтовано як незалежний `tmpfs` або окремий розділ диска), виклик `rename()` зазнає аварійної зупинки з помилкою `EXDEV` (*Invalid cross-device link*), що вимагало б неатомарного копіювання даних через пам'ять ядра.

### 2. Атомарна підміна inode проти перезапису "на місці"

Виклик `rename("sedXXXXXX", "target.conf")` атомарно переприв'язує запис каталогу (directory entry, dentry) до нового ідентифікатора `inode`. При цьому старий `inode` відв'язується (unlinked). Це призводить до трьох фундаментальних системних наслідків:

- **Розрив жорстких посилань (Hard Links):** Якщо файл мав кілька жорстких посилань (`link("app.conf", "app_link.conf")`), вони посилалися на спільний `inode #10425`. Після виконання `sed -i` ім'я `app.conf` вказує на новий `inode #88912`, тоді як `app_link.conf` продовжує вказувати на старий `inode #10425` зі старими даними. Зв'язок між іменами розривається.
- **Поведінка з символічними посиланнями (Symlinks):** За замовчуванням `sed -i symlink.conf` видаляє сам симлінк у каталозі та створює на його місці новий регулярний файл. Цільовий файл залишається незмінним.
  - *Рішення GNU sed:* Прапорець `--follow-symlinks` примушує `sed` розгорнути ланцюжок посилань через `realpath(3)`, визначити реальний каталог цільового файлу, створити тимчасовий файл поруч із ціллю і замінити саме цільовий файл, зберігши вхідний symlink неушкодженим.
- **Розсинхронізація з відкритими дескрипторами процесів (`tail -f`, сервери логів):** Якщо сторонній процес (наприклад, демон `nginx` або утиліта `tail -f`) тримає відкритим дескриптор `open("app.log", O_RDWR)`, системний виклик `rename()` не закриває його. Старий `inode` залишається живим у пам'яті ядра, поки лічильник відкритих дескрипторів не стане `0`. Демон продовжує писати байти у старий безіменний `inode`, а користувач бачить новий `inode`, створений `sed`. Нові рядки логу перестають надходити у файл, спричиняючи приховану аварію моніторингу.

### 3. Збереження прав доступу POSIX, розширених атрибутів (xattr) та контекстів SELinux

Щоб новий файл не втратив системних властивостей оригіналу, `sed` виконує комплексний перенос метаданих:

- **POSIX Permissions (`fchmod`):** Перед записом `sed` отримує структуру `struct stat` вихідного файлу викликом `fstat(orig_fd, &st)`. Новий тимчасовий файл одразу отримує вихідні біти режиму доступу через `fchmod(temp_fd, st.st_mode)` (включно зі спеціальними бітами `SUID`/`SGID`/`Sticky`, якщо це дозволено поточному процесу).
- **Власник та група (`fchown`):** `sed` намагається відтворити користувача та групу викликом `fchown(temp_fd, st.st_uid, st.st_gid)`. Якщо процес виконується звичайним користувачем без привілею `CAP_CHOWN`, виклик повертає помилку `EPERM`. У цьому випадку `sed` ігнорує збій, внаслідок чого власником відредагованого файлу стає користувач, що запустив команду.
- **Розширені атрибути (xattr & ACLs):** GNU sed вичитує розширені атрибути просторів `user.*` та списки контролю доступу POSIX ACLs (`system.posix_acl_access`) через `flistxattr(2)` / `fgetxattr(2)` та встановлює їх на новий дескриптор через `fsetxattr(2)`.
- **Контексти безпеки SELinux (`libselinux`):** При створенні нового файлу через `mkstemp()` підсистема безпеки ядра Linux автоматично призначає йому контекст за замовчуванням для батьківського каталогу (правило Type Transition). Наприклад, у каталозі `/etc` файл отримає тип `etc_t`. Якщо цільовий файл мав спеціальний тип (наприклад, `shadow_t` для `/etc/shadow` або `named_conf_t` для конфігурації DNS-сервера), звичайна заміна файлу призведе до блокування сервісів через відмови SELinux (AVC denials). GNU sed викликає `fgetfilecon(orig_fd, &scon)` і явно відновлює вихідний контекст безпеки викликом `fsetfilecon(temp_fd, scon)` до виклику `rename()`.

### 5. Порівняльний аналіз семантики GNU sed проти BSD sed `-i`

| Характеристика операції | GNU sed (Linux) | BSD sed (macOS / FreeBSD) |
|---|---|---|

| **Створення резервної копії** | Створює hard link або копіює оригінал перед `rename()` | Робить `rename("file", "file.bak")`, потім `rename("temp", "file")` |

## Взаємодія sed із системними пайплайнами: буферизація I/O, сигнали та оптимізація потоку

У класичній моделі Unix-конвеєра (Unix Pipeline) процеси зв'язуються між собою анонімними каналами ядра (Anonymous Pipes). Процес `sed` виступає проміжною ланкою конвеєра, зчитуючи дані з дескриптора `stdin` (fd 0) та записуючи результат у дескриптор `stdout` (fd 1). Для забезпечення високої пропускної здатності та передбачуваної поведінки в реальному часі необхідно враховувати взаємодію між рівнем буферизації користувацького простору (C Runtime Stdio), кільцевими буферами ядра та системними сигналами IPC.

```text
               ┌──────────────────────────────────────────────────────────┐
               │ Ядро Linux: VFS Pipe Buffer (Кільцевий буфер 64 KB)      │
               └────────────────────────────┬─────────────────────────────┘
                                            │ read(2)
                                            ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ Простір користувача: Процес sed                                         │
│                                                                         │
│  Вхідний потік (stdin) ──► Внутрішній буфер glibc (_IOFBF: 4KB / 8KB)   │
│                                           │                             │
│                                           ▼                             │
│                           Pattern Space / Hold Space                    │
│                                           │                             │
│                                           ▼                             │
│  Вихідний потік (stdout) ◄─ Буфер виводу glibc (fflush при -u / _IONBF) │
└───────────────────────────────────────────┬─────────────────────────────┘
                                            │ write(2)
                                            ▼
               ┌──────────────────────────────────────────────────────────┐
               │ Ядро Linux: Downstream Pipe / Споживач (SIGPIPE при EOF) │
               └──────────────────────────────────────────────────────────┘
```

### 1. Системна буферизація вводу/виводу: glibc stdio проти прапорця -u

Стандартна бібліотека C (`glibc`, `musl`, `FreeBSD libc`) керує потоками введення/виведення через дескриптори типу `FILE *`. Стандарт ISO C та специфікація POSIX.1 визначають три режими буферизації для потоку `stdout` (налаштовуються викликом `setvbuf(3)`):

1. **Повна блокова буферизація (`_IOFBF` — Full Buffering):** Дані акумулюються у внутрішньому масиві пам'яті процесу розміром `BUFSIZ` (зазвичай 4096 або 8192 байти, або розмір блоку файлової системи `st_blksize`). Фізичний системний виклик `write(1, ...)` ініціюється ядром `glibc` виключно тоді, коли буфер заповнюється на всі 100%, або при виклику `fflush(stdout)`.
   - *Дефолтне правило POSIX:* Якщо дескриптор `stdout` вказує на регулярний файл на диску або на анонімний канал `pipe(2)` (`isatty(1) == 0`), потік автоматично ініціалізується в режимі `_IOFBF`.
2. **Лінійна буферизація (`_IOLBF` — Line Buffering):** Буфер скидається у системний виклик `write()` при кожній появі символу нового рядка `\n` або при вичерпанні ліміту пам'яті.
   - *Дефолтне правило POSIX:* Потік перемикається в режим `_IOLBF` автоматично, лише якщо дескриптор підключено до інтерактивного термінала або псевдотермінала (`isatty(1) == 1`).
3. **Небуферизований режим (`_IONBF` — No Buffering):** Будь-який запис негайно транслюється в прямий системний виклик `write(2)`. За замовчуванням застосовується для дескриптора помилок `stderr` (fd 2).

#### Проблема блокування конвеєрів реального часу (Pipeline Stalling)

Розглянемо типовий діагностичний конвеєр для моніторингу подій у реальному часі:

```bash
# Моніторинг відмов авторизації через конвеєр:
tail -f /var/log/auth.log | sed '/Failed password/p' | tee failed_auth.log
```

У цій конфігурації вивід `sed` підключено до входу утиліти `tee` через міжпроцесний pipe. Оскільки дескриптор не є терміналом (`isatty == 0`), бібліотека `glibc` всередині процесу `sed` перемикає `stdout` у режим `_IOFBF` (8192 байти). 

Якщо на сервері відбувається 2–3 невдалі спроби входу на хвилину (розмір рядка близько 120 байтів), процесу `sed` знадобиться згенерувати понад 65 рядків, щоб заповнити буфер обсягом 8 KB. Як наслідок, оператор системи не побачить жодного рядка у `failed_auth.log` протягом 20–30 хвилин. Створюється ілюзія зависання конвеєра або відсутності подій.

#### Інженерна механіка прапорця `-u` / `--unbuffered`

Прапорець `-u` (доступний у GNU sed та BSD sed) розв'язує проблему затримки:

- **На рівні виводу:** `sed` або явно конфігурує дескриптор викликом `setvbuf(stdout, NULL, _IONBF, 0)`, або викликає системну підпрограму `fflush(stdout)` після кожного кроку автоматичного друку (auto-print) чи виконання явних команд виведення (`p`, `P`, `w`).
- **На рівні вводу:** `sed` вимикає жадібне попереднє зчитування великих блоків, зчитуючи з дескриптора `stdin` мінімально необхідні порції байтів (посимвольно або дрібними сегментами через `read(0, buf, 1)` / `getc()`).

```bash
# Виправлений конвеєр із нульовою затримкою (Zero Latency Streaming):
tail -f /var/log/auth.log | sed -u -n '/Failed password/p' | tee failed_auth.log
```

#### Компроміс: Затримка проти пропускної здатності (Latency vs Throughput Tradeoff)

Вимкнення буферизації має високу системну ціну:
- На статичних масивах даних розміром 10–50 GB запуск `sed -u` призводить до генерації мільйонів окремих системних викликів `write(1, line, len)` замість оптимізованих блокових записів по 8192 або 65536 байтів.
- Кожен системний виклик спричиняє перехід процесора між простором користувача та простором ядра (Ring 3 -> Ring 0), скидання конвеєра інструкцій CPU та оновлення системних структур VFS.
- Загальна швидкість обробки файлу на накопичувачі падає у 3–6 разів (з 1150 MB/s до 180–250 MB/s).

*Інженерне правило:* Прапорець `-u` слід використовувати **виключно** для неперервних потоків реального часу (`tail -f`, `tcpdump`, сенсорні дані, логи сокетів). Для статичних файлів та пакетних перетворень використання `-u` є грубою антиоптимізацією.

### 2. Обробка сигналу SIGPIPE та семантика обірваних каналів (Broken Pipe)

Міжпроцесний канал POSIX функціонує за принципом односпрямованої черги FIFO в пам'яті ядра. Коли процес на читальному кінці каналу (Downstream Consumer, наприклад `head -n 10`) завершує свою роботу, він закриває відповідний файловий дескриптор `close(pipe_read_fd)`.

У ядрі операційної системи лічильник відкритих дескрипторів читання для даного каналу стає рівним нулю.

```text
               ┌────────────────┐  Закриття дескриптора   ┌────────────────┐
               │ sed (Writer)   │ ────── read fd = 0 ────►│ head (Reader)  │
               └───────┬────────┘                         │ (Вихід exit 0) │
                       │                                  └────────────────┘
                       │ write(2)
                       ▼
          ┌───────────────────────────┐
          │ Ядро Linux: VFS Pipe      │
          │ Лічильник читачів = 0     │
          └────────────┬──────────────┘
                       │
                       ▼ Генерація сигналу
               ┌────────────────┐
               │ SIGPIPE (13)   │ ──► Негайне аварійне завершення процесу sed
               │                │     (Код виходу bash: 128 + 13 = 141)
               └────────────────┘
```

#### Системний ланцюжок генерації SIGPIPE:

1. Наступна спроба процесу `sed` записати чергову порцію даних у `stdout` через системний виклик `write(1, buf, len)` фіксується ядром як спроба запису в "обірваний канал" (Broken Pipe).
2. Ядро генерує та надсилає процесу `sed` сигнал `SIGPIPE` (системний сигнал 13).
3. **Реакція за замовчуванням (`SIG_DFL`):** Процес негайно завершує роботу. Операційна система звільняє всі сторінки пам'яті та дескриптори процесу.
4. **Коди завершення в оболонці:** Оболонка `bash` (або `zsh`) інтерпретує завершення від сигналу за формулою `128 + номер_сигналу`. Для `SIGPIPE` код повернення становить `128 + 13 = 141`.
5. **Вплив на CI/CD та скрипти автоматизації:** Якщо у скрипті активовано прапорець суворого контролю помилок `set -e` або `set -o pipefail`, завершення `sed` із кодом `141` розцінюється інтерпретатором як критичний збій конвеєра, що перериває виконання сценарію розгортання:
   ```bash
   set -o pipefail
   # Конвеєр впаде з помилкою exit code 141, оскільки head закриє pipe раніше за sed:
   cat 10GB_access.log | sed 's/foo/bar/g' | head -n 5
   ```
6. **Обробка з маскуванням сигналу:** Якщо процес `sed` ігнорує сигнал через `signal(SIGPIPE, SIG_IGN)`, виклик `write()` не перериває виконання сигналом, а повертає статус `-1`, встановлюючи змінну помилки `errno = EPIPE`. Редактор `sed` обробляє `EPIPE` як штатне завершення введення/виведення і завершує головний цикл.

### 3. Ранній вихід: команди q/Q проти пасивного сканування потоку

Поширеною помилкою при вибірці перших `N` рядків є використання пасивного фільтра друку:

```bash
# Пасивна фільтрація (Неоптимально!):
sed -n '1,100p' 100GB_database.dump
```

#### Порівняльний аналіз механізмів виконання:

| Критерій | Пасивний фільтр: `sed -n '1,100p'` | Ранній вихід: `sed '100q'` |
|---|---|---|
| **Поведінка після 100-го рядка** | Продовжує читати всі залишковий 100 GB масив до кінця файлу (`EOF`). | Негайно викликає системний `exit(0)` на 100-му рядку. |
| **Алгоритмічна складність за часом** | Строго `O(N)`, де `N` — повна кількість рядків у вхідному потоці. | Строго `O(K)`, де `K` — кількість запитуваних рядків (константа). |
| **I/O навантаження на диск** | Повне вичитування всіх 100 GB даних через пам'ять ядра. | Зчитування лише перших кількох кілобайтів файлу. |
| **Вплив на upstream producer у pipe** | Процес-виробник (`zcat`, `mysqldump`) виконується на 100% до кінця. | Процес-виробник отримує `SIGPIPE` на 101-му рядку і зупиняється миттєво. |

#### Каскадна оптимізація пайплайнів через SIGPIPE

Коли виконується команда `zcat huge_compressed_log.gz | sed '100q'`, відбувається наступне:
1. `sed` зчитує 100 рядків, відправляє їх у `stdout` і завершує процес викликом `exit(0)`.
2. Закриття процесу `sed` автоматично закриває його вхідний дескриптор `stdin` (читальний кінець каналу від `zcat`).
3. Утиліта `zcat` намагається записати 101-й розпакований рядок у канал, негайно отримує сигнал `SIGPIPE` від ядра і припиняє декомпресію.
4. Весь конвеєр зупиняється менш ніж за 5 мілісекунд, заощаджуючи десятки гігабайтів дискового вводу/виводу та гігагерци процесорного часу.

#### Семантичні відмінності команд `q` та `Q`

- **`q [код]` (Quit, POSIX):** Друкує поточний вміст `Pattern Space` (якщо не активовано опцію `-n`), скидає відкладені черги команд `a` та `r`, після чого негайно завершує процес з опціональним числовим кодом завершення `0..255` (за замовчуванням `0`).
- **`Q [код]` (Quiet Quit, розширення GNU sed):** Завершує процес негайно **без виведення поточного Pattern Space** і без виконання відкладених черг.

```bash
# Друк перших 10 рядків (q надрукує 10-й рядок і вийде):
sed '10q' input.txt

# Друк рядків до появи першої помилки (рядок з ERROR не друкується завдяки Q):
sed '/^ERROR/Q' server.log
```

## Обробка двійкових даних та null-термінованих записів (-z / --null-data)

У традиційній моделі Unix стандартним роздільником записів текстового потоку є символ переводу рядка `\n` (ASCII `0x0A`, LF). Однак у системних інтерфейсах POSIX VFS єдиними двома байтами, забороненими до використання в іменах файлів та шляхах, є прямий слеш `/` (ASCII `0x2F`, роздільник каталогів) та нульовий байт NUL (`\0`, ASCII `0x00`, термінатор рядків у C).

Усі інші байти — пробіли, табуляції, лапки, керуючі escape-послідовності та навіть сам символ нового рядка `\n` — є абсолютно легальними символами в іменах файлів.

```text
Ім'я файлу на диску: "audit_log\n2026-08-29.csv" (один файл з '\n' всередині назви)

Стандартний sed (розбиття по '\n'):
  Запис 1: "audit_log"           ──► xargs rm ──► Спроба видалити "audit_log" (ПОМИЛКА / ВТРАТА ДАНИХ)
  Запис 2: "2026-08-29.csv"      ──► xargs rm ──► Спроба видалити "2026-08-29.csv" (ПОМИЛКА)

GNU sed з опцією -z (розбиття по '\0'):
  Запис 1: "audit_log\n2026-08-29.csv\0" ──► xargs -0 rm ──► Безпечне точне видалення цільового файлу
```

### 1. Анатомія опції -z (--null-data у GNU sed)

Опція `-z` (`--null-data`, `--zero-terminated`) докорінно трансформує модель виконання головного життєвого циклу `sed`:

1. **Зміна термінатора записів:** Замість байта `0x0A` (`\n`) системна підпрограма зчитування потоку використовує як роздільник нульовий байт `0x00` (`\0`).
2. **Вміст `Pattern Space`:** Робочий буфер завантажує порцію байтів від попереднього `\0` до наступного `\0`. Будь-які символи `\n` всередині цієї порції трактуються як звичайні текстові байти корисного навантаження.
3. **Метасимволи регулярних виразів при активному `-z`:**
   - `^` — зіставляється з початком NUL-термінованого запису (позиція безпосередньо після попереднього `\0` або старт потоку).
   - `$` — зіставляється з кінцем NUL-термінованого запису (позиція безпосередньо перед кінцевим `\0`).
   - `.` — оператор будь-якого символу збігається з абсолютно будь-яким байтом, **включаючи символ `\n`** (але не збігається з кінцевим `\0`).
   - `\n` — зіставляється з літеральним байтом переводу рядка всередині поточного NUL-запису.
4. **Виведення (`stdout`):** Команди автоматичного друку (auto-print), явні команди `p`, `P` та прапорець `p` завершують виведений буфер нульовим байтом `\0` замість `\n`.

### 2. Інженерні сценарії інтеграції у системні конвеєри

#### Сценарій 1: Пакетна безпечна нормалізація файлів через `find -print0` та `xargs -0`

При автоматизованій обробці файлових сховищ користувачів або системних звалищ імен файли можуть містити небажані символи, пробіли та спеціальні знаки. Комбінація `find -print0 | sed -z | xargs -0` гарантує 100% захист від ін'єкцій аргументів:

```bash
# Масове перейменування файлів з заміною пробілів на підкреслення:
find /var/uploads -type f -name "* *" -print0 | \
    sed -z -e 'p' -e 's/ /_/g' | \
    xargs -0 -n 2 mv
```

*Механіка виконання:*
1. `find -print0` генерує потік шляхів, де кожен шлях завершується байтом `\0`.
2. `sed -z` виконує два вирази `-e`:
   - `p` — друкує оригінальний шлях + `\0`.
   - `s/ /_/g` — змінює пробіли на `_` у `Pattern Space` і друкує модифікований шлях + `\0` наприкінці циклу.
3. `xargs -0 -n 2 mv` вичитує по два NUL-терміновані аргументи за раз і виконує атомарну команду `mv "оригінальний шлях" "модифікований_шлях"`.

#### Сценарій 2: Парсинг виводу Git у двійковому режимі (`git status -z`)

У Git-хуках (Git Pre-commit Hooks) стандартний вивід `git status` або `git diff --name-only` екранує нелатинські назви та шляхи з пробілами у вісімкові послідовності в лапках (`"\321\202\320\265\321\201\321\202.txt"`). Прапорець `-z` примушує Git виводити сирі немодифіковані байти UTF-8 із роздільником `\0`.

Формат виводу `git status -z`:
- Звичайні зміни: `XY PATH\0` (де `XY` — двобайтовий статусний код, наприклад `M `, `A `, `??`).
- Перейменовані файли: `R  ORIG_PATH\0NEW_PATH\0`.

```bash
# Вибірка всіх модифікованих або доданих файлів C/C++ для запуску clang-format:
git status -z | \
    sed -z -n 's/^[ MADRCU]\{2\} //p' | \
    sed -z -n '/\.\(cpp\|hpp\|cc\|c\|h\)$/p' | \
    xargs -0 -r clang-format -i
```

*Механіка:*
1. Перший `sed -z` відсікає двосимвольний префікс статусу Git `^[ MADRCU]{2} ` та виводить очищений шлях з нуль-термінатором.
2. Другий `sed -z` фільтрує лише файли з розширеннями вихідного коду C/C++.
3. `xargs -0 -r clang-format -i` форматує файли на місці без ризику збою на шляхах з пробілами чи апострофами.

#### Сценарій 3: Конвеєри з `grep -Z` / `grep -z`

```bash
# Знайти всі файли, що містять паролі або токени, та змінити їхні права доступу на 0600:
grep -lZ -r "PRIVATE_KEY" /etc/ssl/ | \
    sed -z 's/\.tmp$//' | \
    xargs -0 -r chmod 0600
```

### 3. Обробка бінарних даних та hex-модифікації байтів

GNU sed підтримує шістнадцятковий запис байтів у регулярних виразах та полях заміни через синтаксис `\xNN` (де `NN` — два шістнадцяткові символи `00..FF`).

У комбінації з прапорцем `-z` це перетворює `sed` на швидкісний потоковий редактор двійкових файлів (Binary Patching Tool):

```bash
# Патчинг заголовка виконуваного файлу ELF (заміна сигнатури або шляху до інтерпретатора):
sed -z -i 's|/lib64/ld-linux-x86-64.so.2|/opt/glibc/lib/ld-linux.so.2\x00\x00\x00\x00|g' custom_app
```

#### Відмінність між опціями `-z` та `-b` у GNU sed

- **`-z` (`--null-data`):** Змінює логічний термінатор записів процесора з `\n` на `\0`. Працює на всіх POSIX-системах.
- **`-b` (`--binary`):** Специфічний прапорець для систем Windows/DOS. Відкриває файли в двійковому режимі введення/виведення, блокуючи автоматичне перетворення рантаймом MSVCRT послідовності `CR/LF` (`0x0D 0x0A`) у поодинокий байт `LF` (`0x0A`). На Linux та BSD системах прапорець `-b` ігнорується, оскільки POSIX VFS не виконує трансляції кінців рядків.

#### Портативність: BSD sed проти GNU sed

Реалізація BSD sed (macOS, FreeBSD) **не підтримує** прапорець `-z`. Для забезпечення переносимості скриптів у багатоплатформних проектах застосовують перевірку наявності `gsed` або еквівалентний однорядковик на `perl`:

```bash
# Кросплатформна заміна NUL-потоку (Працює на Linux, macOS та FreeBSD):
if command -v gsed >/dev/null 2>&1; then
    gsed -z 's/\.old$/\.bak/'
else
    perl -0 -pe 's/\.old\z/\.bak/'
fi
```

## Модель адресації та автомати станів

Кожна інструкція `sed` може мати префікс адреси, який визначає умову її активації:

```text
[адреса1[,адреса2]][!]команда[аргументи]
```

Якщо адресу не вказано, команда виконується безумовно для кожного зчитаного рядка вхідного потоку.

### 1. Одиночні адреси рядків

- **`N` (десяткове число):** Застосовується строго до рядка з абсолютним номером `N` (1-indexed). Внутрішній лічильник рядків починається з `1` і зростає наскрізно через усі передані файли (якщо не вказано `-s`).
- **`$` (знак долара):** Адресує фінальний рядок вхідного потоку (подія настання EOF для останнього файлу у списку або для потоку `stdin`). При використанні опції GNU sed `-s` метасимвол `$` адресує останній рядок кожного окремого файлу.
- **`/шаблон/`:** Контекстна адреса. Застосовується до будь-якого рядка, чий поточний вміст `Pattern Space` відповідає базовому (BRE) або розширеному (ERE, прапорець `-E`) регулярному виразу.
- **`\%шаблон%` або `\cшаблонc`:** Дозволяє замінити стандартний роздільник `/` на будь-який інший одиночний символ `c` (окрім `\` та `\n`). Зручно для регулярних виразів, що оперують шляхами до файлів або URL (наприклад, `\%/var/log/%d` або `\_https://_p`).

### 2. Розширення адресації GNU sed

- **`first~step` (крокова адресація):** Обирає кожен `step`-й рядок, починаючи з рядка `first`. Застосовується формула номерів рядків: `first + k * step` для цілих `k >= 0`.
  - `1~2` — усі непарні рядки (1, 3, 5, 7, ...).
  - `0~2` або `2~2` — усі парні рядки (2, 4, 6, 8, ...).
  - `5~10` — рядки 5, 15, 25, 35, ...
- **`0` (нульова адреса):** Дозволена виключно як перша адреса діапазону `0,/шаблон/`. Дозволяє закрити діапазон на першому ж рядку, якщо він містить збіг із шаблоном (на відміну від `1,/шаблон/`, де діапазон залишається відкритим до наступного рядка зі збігом). У POSIX та BSD sed адреса `0` вважається синтаксичною помилкою.
- **`адреса,+N` (відносний числовий діапазон):** Активується на рядку, що відповідає `адресі`, і діє для наступних `N` рядків після нього (разом `N + 1` рядок). Наприклад, `/^START/,+4d` видаляє рядок з маркером і наступні 4 рядки.
- **`адреса,~N` (вирівнювання за кратністю):** Активується на рядку, що відповідає `адресі`, і продовжує діяти доти, доки абсолютний номер рядка не стане кратним числу `N` (`line_number % N == 0`). Якщо рядок активації вже кратний `N`, дія триває до наступного числа, кратного `N`.

### 3. Діапазонна адресація `addr1,addr2` (Flip-Flop State Machine)

Діапазон, сформований двома адресами через кому, керується внутрішнім тригером активного стану (двопозиційним перемикачем зі станами `OFF` та `ON`):

```text
            Збіг addr1 (стан -> ON)
Вхід ───────────────▼───────────────────────────
[неактивно]      [активна зона виконання дій]
─────────────────────────────────▲──────────────
            Збіг addr2 (стан -> OFF)
```

1. **Ініціалізація:** На старті обробки стан тригера встановлено в `OFF`.
2. **Вхід у діапазон:** Коли рядок відповідає критерію `addr1`, стан перемикається в `ON`, і команда виконується над цим рядком.
3. **Утримання стану:** Для всіх наступних рядків, поки тригер перебуває в стані `ON`, команда виконується безумовно.
4. **Вихід із діапазону:**
   - Якщо `addr2` є регулярним виразом `/шаблон/`, перевірка збігу з `addr2` починається **лише з наступного рядка** після рядка активації. Якщо той самий перший рядок містить і `addr1`, і `addr2`, діапазон **не закривається** на ньому, а продовжує діяти до наступного збігу `addr2`.
   - Якщо `addr2` є фіксованим номером рядка `M`, і номер рядка відкриття `>= M`, діапазон закривається негайно на поточному рядку (команда виконується рівно один раз).
   - Коли знайдено рядок, що відповідає `addr2`, команда виконується над цим рядком востаннє, після чого тригер скидається в стан `OFF`.
5. **Незакритий діапазон:** Якщо умова `addr2` жодного разу не виконалася до кінця потоку, тригер залишається в стані `ON` до сигналу `EOF`, застосовуючи дію до всіх залишкових рядків.
6. **Повторна активація:** Після переходу тригера в стан `OFF` черговий рядок зі збігом `addr1` знову перемикає стан у `ON`, відкриваючи наступний блок дій.

### 4. Модифікатор заперечення адреси (`!`) та групування блоків `{ ... }`

- **Інверсія (`!`):** Розміщується безпосередньо після адреси або діапазону. Змушує виконувати команду для всіх рядків, які **НЕ** потрапили під критерій адресації:
  ```bash
  sed -n '1,10!p' input.txt      # Друкувати рядки з 11-го до кінця файлу
  sed '/^ERROR/!d' app.log       # Видалити все, крім рядків з помилками
  sed '/^BEGIN/,/^END/!s/foo/bar/g' data.txt # Заміна поза межами блоку
  ```
- **Блокове групування `{ ... }`:** Дозволяє прив'язати цілий список команд до однієї адреси або діапазону, а також підтримує довільну глибину вкладеності:
  ```bash
  sed -n '/^BEGIN/,/^END/ {
      s/foo/bar/g
      s/baz/qux/g
      p
  }' data.txt
  ```
  *Примітка сумісності:* У стандарті POSIX та BSD sed закривальна дужка `}` обов'язково повинна передуватися символом нового рядка `\n` або крапкою з комою `;`, а в деяких старих реалізаціях BSD sed має розташовуватись на окремому рядку.

## Рушій регулярних виразів: компіляція, бектрекінг та вплив локалей

Регулярні вирази у `sed` обробляються спеціалізованим рушієм, який поєднує швидку фільтрацію детермінованим автоматом з покроковим розбором груп захоплення.

```text
Вхідний рядок (Pattern Space)
             │
             ▼
┌───────────────────────────┐
│ GNU Fast DFA Engine       │ ── (Немає збігу) ──► Швидке відкидання (O(N), 0 бектрекінгу)
│ (таблиця переходів 256 B) │
└────────────┬──────────────┘
             │ (Є потенційний збіг або зворотні посилання \1..\9)
             ▼
┌───────────────────────────┐
│ GNU NFA / Regex Matcher   │ ──► Точне виділення груп regmatch_t (rm_so, rm_eo)
│ (покроковий бектрекінг)   │
└───────────────────────────┘
```

### 1. Архітектура та оптимізація компіляції шаблонів regex у GNU sed

GNU sed використовує двоетапну гібридну архітектуру зіставлення:

1. **Фаза статичної попередньої компіляції:** Під час розбору командного рядка або файлу сценарію всі регулярні вирази з адресних предикатів (`/шаблон/`) та інструкцій підстановки (`s/шаблон/заміна/`) компілюються один раз викликами `dfacomp()` (бібліотека `gnulib/dfa.c`) та системної підпрограми `regcomp()`. У головному циклі обробки рядків компіляція не повторюється.
2. **Швидкий фільтр DFA (Deterministic Finite Automaton):** Для кожного рядка `Pattern Space` спочатку застосовується детермінований скінченний автомат DFA. Автомат будує компактні таблиці переходів (256 байтів на стан), що дозволяє сканувати вхідні байти за суворий лінійний час `O(N)` без використання системного стека та без бектрекінгу. Якщо DFA показує, що рядок не містить збігу, рядок негайно відкидається за мінімальну кількість тактів CPU.
3. **Точний розбір NFA (Non-deterministic Finite Automaton):** Якщо DFA сигналізує про наявність збігу або якщо у виразі використовуються зворотні посилання (`\1`..`\9`), виконання передається підсистемі NFA (`regexec.c`). NFA виконує покрокове зіставлення і заповнює масив структур `regmatch_t` зі зміщеннями початку (`rm_so`) та кінця (`rm_eo`) для кожного підвиразу.

### 2. Відмінності BRE проти ERE та ціна зворотних посилань (`\1`..`\9`)

- **BRE (Basic Regular Expressions, дефолт POSIX):** Керівні оператори групування та повторення вимагають екранування зворотним слешем: `\(...\)` для груп захоплення, `\{m,n\}` для квантифікаторів діапазону, `\+` (GNU) для одного або більше входжень, `\?` (GNU) для опціональності, `\|` (GNU) для логічного "АБО". Без слеша ці символи трактуються як звичайні літерали.
- **ERE (Extended Regular Expressions, опція `-E`):** Метасимволи `( )`, `{m,n}`, `+`, `?`, `|` діють як оператори за замовчуванням, а для пошуку літералів їх слід екранувати: `\+`, `\(`, `\|`.

| Операція | Синтаксис BRE (sed за замовчуванням) | Синтаксис ERE (`sed -E`) |
|---|---|---|
| Захоплення групи | `\(pattern\)` | `(pattern)` |
| Літеральні круглі дужки | `(pattern)` | `\(pattern\)` |
| Квантифікатор 1 або більше | `\+` (розширення GNU) | `+` (стандарт POSIX) |
| Квантифікатор 0 або 1 | `\?` (розширення GNU) | `?` (стандарт POSIX) |
| Діапазон повторень | `\{2,5\}` | `{2,5}` |
| Логічна альтернація (OR) | `foo\|bar` (розширення GNU) | `foo|bar` (стандарт POSIX) |
| Зворотні посилання | `\1` .. `\9` | `\1` .. `\9` (розширення GNU) |

#### Системна ціна зворотних посилань (Backreferences)

Зворотні посилання `\1`..`\9` дозволяють перевіряти повторюваність раніше захопленого тексту (наприклад, `s/\b([a-zA-Z]+) \1\b/\1/g` для видалення подвоєних слів).

З погляду теорії формальних мов, наявність зворотних посилань виводить мову за межі класу регулярних граматик: мова повторів `L = {w w | w ∈ Σ*}` не є контекстно-вільною, а задача її розпізнавання стає **NP-повною**.

DFA принципово не здатен зберігати динамічний стан раніше зіставленого підрядка. Тому, щойно компілятор `sed` виявляє у шаблоні конструкцію `\1`, оптимізація швидкого DFA-фільтра повністю вимикається. Увесь пошук виконується виключно NFA-рушієм з повним перебором станів, що призводить до падіння швидкості обробки в десятки разів.

При використанні складних вкладених квантифікаторів або неоднозначних жадібних операторів на невдалих збігах виникає лавиноподібне зростання варіантів розгалуження:

Якщо на вхід подати рядок виду `xxxxxxxxxxxxxxxxxxxxxxxxxxxx!`, що містить довгу послідовність символів `x` без фінального символу `y`, рушій NFA намагатиметься перевірити всі можливі комбінації розбиття послідовності між зовнішнім та внутрішнім квантифікаторами `+`. Кількість варіантів обчислюється як `O(2ⁿ)`, що викликає 100% завантаження одного ядра процесора та зависання обробки на багато хвилин.

#### Інженерні правила запобігання бектрекінгу:
1. **Відмова від неспецифічних жадібних виразів `.*`:** Замість виразу `s/.*://` (який сканує рядок до самого кінця і потім відкочується назад) слід використовувати негативні класи символів: `s/[^:]*://`.
2. **Явні початкові прив'язки `^`:** Прив'язка до початку рядка блокує спроби рушія перезапускати пошук з кожного наступного байтового зміщення `1..len`.
3. **Усунення перекриття в альтернаціях:** Замість `(a|ab)` слід писати `ab?` або впорядковувати гілки від найбільш специфічної до загальної.

### 4. Вплив системних локалей (`LC_COLLATE`, `LC_CTYPE`, `LC_ALL`) на діапазони символів

Поведінка діапазонів символів у квадратних дужках `[a-z]` та `[A-Z]` безпосередньо залежить від системних змінних середовища:

```bash
# Перевірка поточних налаштувань локалі:
locale
```

- **Стандартне середовище ASCII (`LC_ALL=C` або `POSIX`):** Діапазон `[a-z]` будується строго за двійковими ASCII-кодами байтів від `0x61` (`a`) до `0x7A` (`z`). Він містить рівно 26 малих літер латинського алфавіту.
- **Локалізовані середовища UTF-8 (`en_US.UTF-8`, `uk_UA.UTF-8` тощо):** Змінна `LC_COLLATE` вмикає правила сортування національних абеток (Collation Sequence). У багатьох європейських локалях символи впорядковуються за парами ваг: `a, A, b, B, c, C, ..., y, Y, z, Z`.
  - *Пастка великих літер:* У локалі `en_US.UTF-8` діапазон `[a-z]` охоплює послідовність від `a` до `z`, яка включає великі літери `A, B, C, ..., Y` (усі великі, окрім фінальної `Z`!). Як наслідок, команда `sed 's/[a-z]//g'` несподівано видаляє великі літери, ламаючи роботу сценаріїв.
  - *Пастка кирилиці:* Діапазон `[а-я]` у середовищі `uk_UA.UTF-8` часто пропускає літери `є`, `і`, `ї`, `ґ`, оскільки їхні кодові позиції та правила зіставлення в бібліотеці `glibc` розташовані за межами основного діапазону.

#### Стандартизовані класи символів POSIX

Для забезпечення переносимості та детермінізму стандарт POSIX закріплює спеціальні символьні класи:

| Клас POSIX | Еквівалент у `LC_ALL=C` | Опис класу символів |
|---|---|---|
| `[[:lower:]]` | `[a-z]` | Малі літери поточного кодування |
| `[[:upper:]]` | `[A-Z]` | Великі літери поточного кодування |
| `[[:alpha:]]` | `[a-zA-Z]` | Будь-які алфавітні символи (малі та великі) |
| `[[:digit:]]` | `[0-9]` | Десяткові цифри `0`–`9` |
| `[[:alnum:]]` | `[a-zA-Z0-9]` | Алфавітно-цифрові символи |
| `[[:blank:]]` | `[ \t]` | Горизонтальні пробільні символи (пробіл та табуляція) |
| `[[:space:]]` | `[ \t\r\n\v\f]` | Усі пробільні символи включно з перенесенням рядка |
| `[[:cntrl:]]` | `[\x00-\x1F\x7F]` | Недруковані керівні символи |
| `[[:graph:]]` | `[\x21-\x7E]` | Усі друковані символи, крім пробілу |
| `[[:print:]]` | `[\x20-\x7E]` | Усі друковані символи включно з пробілом |
| `[[:punct:]]` | `[!\"#$%&'()*+,-./:;<=>?@[\]^_`{|}~]` | Символи пунктуації та спеціальні знаки |
| `[[:xdigit:]]` | `[0-9a-fA-F]` | Шістнадцяткові цифри |

```bash
# Правильний переносимий запис видалення малих літер:
sed 's/[[:lower:]]//g' input.txt

# Швидкісний детермінований виклик у продакшн-середовищі:
LC_ALL=C sed 's/[a-z]//g' input.txt
```

## Повний реєстр команд sed

### 1. Базові команди заміни та транслітерації тексту

#### `s/регулярний_вираз/рядок_заміни/[прапорці]` (Substitute)

Шукає збіг із регулярним виразом у межах `Pattern Space` і замінює знайдену ділянку текстом із поля `рядок_заміни`. Роздільником полів виступає будь-який одиночний символ, наступний безпосередньо за літерою `s`.

**Спеціальні керівні конструкції в полі `рядок_заміни`:**
- `&` — підставляє весь фрагмент тексту, що збігся з регулярним виразом.
- `\1` .. `\9` — зворотні посилання на текст, захоплений відповідною парою круглих дужок `\(...\)` (у BRE) або `(...)` (у ERE).
- `\L` (GNU sed) — переводить усі наступні символи заміни у нижній регістр до появи `\E` або `\U`.
- `\l` (GNU sed) — переводить рівно один наступний символ у нижній регістр.
- `\U` (GNU sed) — переводить усі наступні символи заміни у верхній регістр до появи `\E` або `\L`.
- `\u` (GNU sed) — переводить рівно один наступний символ у верхній регістр.
- `\E` (GNU sed) — завершує дію перетворення регістру, розпочату `\L` або `\U`.
- `\\` — вставляє літеральний символ зворотної косої риски `\`.
- `\&` — вставляє літеральний символ амперсанда `&`.
- `\n` — вставляє символ переводу рядка (ASCII `0x0A`).

**Реєстр прапорців команди `s///`:**

| Прапорець | Стандарт / Реалізація | Призначення та системна поведінка |
|---|---|---|
| `g` (global) | POSIX, GNU, BSD | Виконує заміну для **всіх** неперетинних входжень шаблону в межах `Pattern Space`. Без `g` замінюється лише перше входження. |
| `ЧИСЛО` (1..N) | POSIX, GNU, BSD | Замінює виключно `N`-е за рахунком входження регулярного виразу в рядку (діапазон `1..512` за POSIX, без обмеження в GNU sed). |
| `ЧИСЛОg` | GNU sed | Починає заміну з `N`-го входження і продовжує змінювати всі наступні збіги до кінця рядка (наприклад, `2g`). |
| `p` (print) | POSIX, GNU, BSD | Якщо в буфері відбулася хоча б одна успішна підстановка, вміст `Pattern Space` негайно дублюється у вихідний потік `stdout`. Часто використовується у комбінації `sed -n 's/.../.../p'`. |
| `w ФАЙЛ` | POSIX, GNU, BSD | У разі успішної заміни записує поточний вміст `Pattern Space` у вказаний файл `ФАЙЛ`. Файл відкривається (і обнуляється) один раз при ініціалізації процесу `sed`. |
| `W ФАЙЛ` | GNU sed | У разі успішної заміни записує у файл `ФАЙЛ` лише перший рядок `Pattern Space` (від початку до першого символу `\n`). |
| `I` або `i` | GNU, BSD (FreeBSD/macOS) | Виконує зіставлення регулярного виразу без урахування регістру символів (case-insensitive). |
| `M` або `m` | GNU sed | Багаторядковий режим (Multiline). Змінює дію метасимволів `^` та `$`: `^` зіставляється з початком буфера та позицією одразу після кожного внутрішнього `\n`, а `$` — з кінцем буфера та позицією безпосередньо перед кожним внутрішнім `\n`. |
| `e` | GNU sed | Режим виконання (Execute). Виконує модифікований вміст `Pattern Space` як команду оболонки `/bin/sh` і замінює вміст `Pattern Space` результатом її стандартного виводу (без кінцевого `\n`). Несе ризики довільного виконання коду при обробці неперевірених даних. |

#### `y/символи_джерела/символи_призначення/` (Transliterate)

Виконує посимвольну трансляцію за таблицею відповідності (аналог утиліти `tr`). Кожен символ із першого набору замінюється на відповідний за індексом символ із другого набору. Обидва набори зобов'язані мати строго однакову довжину в байтах. Роздільником виступає будь-який символ, наступний за `y`.

```bash
sed 'y/abcdef/ABCDEF/' input.txt   # Транслює символи a-f у відповідні A-F
```

### 2. Команди виведення та видалення

- **`p` (Print):** Копіює весь поточний вміст `Pattern Space` у стандартний вивід `stdout`. Не модифікує буфери і не перериває виконання командного ланцюжка.
- **`P` (Print First Line):** Виводить у `stdout` фрагмент `Pattern Space` від початку до першого знайденого роздільника `\n`. Якщо внутрішніх переходів рядка немає, дія повністю еквівалентна `p`.
- **`d` (Delete):** Повністю очищає вміст `Pattern Space`, негайно перериває виконання команд для поточного рядка і розпочинає новий цикл зі зчитування наступного рядка з входу. Автоматичний друк наприкінці циклу блокується.
- **`D` (Delete First Line):** Видаляє з `Pattern Space` текст від початку до першого символу `\n` включно.
  - Якщо в буфері залишився текст після `\n`, `sed` негайно **перезапускає виконання сценарію з найпершої інструкції над залишком буфера без зчитування нового рядка з вхідного потоку**.
  - Якщо буфер не містив `\n` або став порожнім, ініціюється звичайний новий цикл зі зчитуванням чергового рядка.
- **`q [КОД]` (Quit):** Негайно завершує виконання процесу `sed`. Перед виходом виводить вміст `Pattern Space` у `stdout` (якщо не активний режим `-n`). Опціонально повертає операційній системі числовий код завершення `КОД` (за замовчуванням `0`, діапазон `0..255`).
- **`Q [КОД]` (Quiet Quit, GNU sed):** Негайно завершує виконання процесу `sed` без виведення поточного `Pattern Space` у вихідний потік. Опціонально повертає вказаний числовий код виходу `КОД`.

---

### 3. Команди модифікації тексту (Insert, Append, Change)

- **`i\ ТЕКСТ` або `i ТЕКСТ` (Insert):** Виводить зазначений текст у стандартний вихідний потік безпосередньо перед тим, як буде виведено поточний рядок `Pattern Space` (або перед виконанням чергової команди зчитування). Не змінює вміст `Pattern Space`.
- **`a\ ТЕКСТ` або `a ТЕКСТ` (Append):** Ставить зазначений текст у внутрішню чергу відкладеного виведення. Текст буде відправлено у `stdout` після завершення обробки поточного рядка (після кроку auto-print) або перед виконанням чергової команди зчитування `n`/`N`.
- **`c\ ТЕКСТ` або `c ТЕКСТ` (Change):** Замінює адресований рядок новим текстом.
  - Якщо команду `c` застосовано до одиночної адреси, текст виводиться у `stdout`, поточний `Pattern Space` очищається, і редактор негайно переходить до нового циклу зчитування.
  - Якщо команду `c` застосовано до діапазону адрес `addr1,addr2`, текст виводиться **рівно один раз** після досягнення кінця діапазону (`addr2`), а всі рядки всередині діапазону видаляються без індивідуального друку.

*Синтаксична відмінність:* У стандарті POSIX та BSD sed команди `a`, `i`, `c` вимагають обов'язкового зворотного слеша та фізичного перенесення рядка:
```bash
# Синтаксис POSIX / BSD:
sed 'i\
Це перший рядок вставки
' file.txt

# Синтаксис GNU sed (підтримує однорядковий запис):
sed 'i Це перший рядок вставки' file.txt
```

---

### 4. Буферні регістри: Pattern Space та Hold Space

| Команда | Мнемоніка | Формальна операція над буферами | Опис системної дії |
|---|---|---|---|
| `h` | Hold | `Hold = Pattern` | Копіює поточний `Pattern Space` у допоміжний регістр `Hold Space`, повністю перезаписуючи його попередній вміст. |
| `H` | Hold Append | `Hold = Hold + '\n' + Pattern` | Додає символ нового рядка `\n` та поточний вміст `Pattern Space` до кінця наявного тексту в `Hold Space`. Якщо `Hold Space` був порожнім, першим байтом стане `\n`. |
| `g` | Get | `Pattern = Hold` | Перезаписує робочий `Pattern Space` вмістом допоміжного регістра `Hold Space`. Попередній вміст `Pattern Space` втрачається. |
| `G` | Get Append | `Pattern = Pattern + '\n' + Hold` | Додає символ `\n` та вміст `Hold Space` до кінця поточного рядка в `Pattern Space`. |
| `x` | Exchange | `swap(Pattern, Hold)` | Атомарно міняє місцями вміст `Pattern Space` та `Hold Space`. |
| `z` | Zap (GNU sed) | `Pattern = ""` | Очищає `Pattern Space`, роблячи його порожнім рядком нульової довжини. На відміну від `d`, виконання наступних інструкцій у ланцюжку продовжується. |

---

### 5. Багаторядкові команди та керування потоком вводу

- **`n` (Next Line):** Якщо не увімкнено тихий режим `-n`, виводить поточний `Pattern Space` у `stdout`. Потім очищає буфер, вичитує наступний рядок із входу в `Pattern Space` і продовжує виконання командного списку з наступної за `n` інструкції. Якщо вхідний потік вичерпано (EOF), процес завершує роботу.
- **`N` (Next Multiline Append):** Зчитує наступний рядок із входу і додає його до кінця поточного вмісту `Pattern Space` через роздільник `\n`. Внутрішній лічильник номерів рядків збільшується на одиницю.
  - *Поведінка на EOF:* Якщо під час виконання `N` досягнуто кінця вхідного потоку, стандарт POSIX вимагає вивести поточний `Pattern Space` (якщо не активний `-n`) і завершити процес. У GNU sed за замовчуванням редактор негайно завершує виконання без виведення залишку буфера (поведінку POSIX можна увімкнути прапорцем `--posix` або змінною середовища `POSIXLY_CORRECT`).

---

### 6. Керування розгалуженнями та мітки

- **`:МІТКА` (Label):** Оголошує іменовану точку переходу в коді сценарію. Ім'я мітки може складатись із літер, цифр та символів підкреслення (довжина до 8 символів у ранніх реалізаціях Unix sed, необмежена в сучасних GNU та BSD sed).
- **`b [МІТКА]` (Branch):** Здійснює безумовний перехід на інструкцію `:МІТКА`. Якщо ім'я мітки опущено, перехід здійснюється в самий кінець списку команд (що завершує поточний цикл обробки над рядком і переходить до кроку auto-print).
- **`t [МІТКА]` (Test on Success):** Умовний перехід за успішною підстановкою. Здійснює перехід на `:МІТКА` виключно тоді, коли з моменту останнього зчитування вхідного рядка (командами циклу, `n` або `N`) або з моменту виконання попередньої команди `t`/`T` хоча б одна інструкція `s///` здійснила успішну заміну. Виклик `t` скидає внутрішній булевий прапорець успішності підстановки в стан `false`.
- **`T [МІТКА]` (Test on Failure, GNU sed):** Умовний перехід за невдачею. Здійснює перехід на `:МІТКА`, якщо жодна підстановка `s///` не була успішною з моменту зчитування рядка або останнього тестування `t`/`T`. Виклик команди скидає прапорець успішності підстановки.

---

### 7. Допоміжні команди, файлове введення/виведення та діагностика

- **`=` (Line Number):** Друкує поточний абсолютний номер рядка у стандартний вивід у вигляді окремого текстового рядка з кінцевим `\n`, що передує виводу `Pattern Space`.
- **`l [ШИРИНА]` (List):** Виводить вміст `Pattern Space` у візуально недвозначній (unambiguous) формі.
  - Недруковані керівні символи відображаються у вигляді стандартних escape-послідовностей C: `\a` (0x07), `\b` (0x08), `\t` (0x09), `\n` (0x0A), `\v` (0x0B), `\f` (0x0C), `\r` (0x0D), або як тризначні вісімкові коди `\ooo` (наприклад, `\000` для NUL).
  - Фізичний кінець рядка маркується символом `$`.
  - Довгі рядки розбиваються на відрізки із символом `\` на кінці. Опціональний числовий параметр `ШИРИНА` (розширення GNU sed) задає колонку перенесення (за замовчуванням `70`, значення `0` повністю вимикає розбиття).
- **`r ФАЙЛ` (Read File):** Ставить у чергу виведення повний вміст зовнішнього файлу `ФАЙЛ`. Вміст буде зчитано і додано до вихідного потоку після виведення поточного рядка або при виконанні чергової команди `n`. Якщо файл не існує або недоступний для читання, дія мовчки ігнорується без аварійної зупинки.
- **`R ФАЙЛ` (Read Line, GNU sed):** Зчитує рівно один рядок із зовнішнього файлу `ФАЙЛ` за один виклик і ставить його в чергу виведення. При кожному наступному спрацьовуванні зчитується черговий рядок аж до вичерпання файлу.
- **`w ФАЙЛ` (Write File):** Записує поточний вміст `Pattern Space` у вказаний файл на диску. Файл відкривається для запису один раз на старті програми (перезаписуючи наявний файл) і наповнюється в процесі роботи.
- **`W ФАЙЛ` (Write First Line, GNU sed):** Записує у зовнішній файл `ФАЙЛ` виключно перший рядок `Pattern Space` (від початку до першого роздільника `\n`).
- **`e [КОМАНДА]` (Execute, GNU sed):** Виконує зазначену системну команду через `/bin/sh` і відправляє результат її виводу безпосередньо у `stdout`. Якщо параметр `КОМАНДА` не передано, `sed` виконує сам вміст `Pattern Space` як команду оболонки і замінює `Pattern Space` отриманим виводом.
- **`F` (File Name, GNU sed):** Друкує ім'я поточного вхідного файлу, що обробляється у даний момент, окремим рядком у `stdout`.
- **`v [ВЕРСІЯ]` (Version Check, GNU sed):** Перевіряє версію GNU sed. Якщо версія середовища нижча за вказану `ВЕРСІЮ` або програма виконується не під GNU sed, виконання сценарію негайно аварійно припиняється з кодом помилки.
- **`#` (Comment):** Позначає коментар. Усе від `#` до кінця фізичного рядка ігнорується інтерпретатором.
  - *Спеціальний випадок `#n`:* Якщо найпершими двома символами всього сценарію є рядок `#n`, `sed` автоматично вмикає тихий режим (еквівалентно передачі прапорця `-n` у командному рядку).

## Побудова складних циклічних алгоритмів та скінченних автоматів

Поєднання двох регістрів пам'яті (`Pattern Space` та `Hold Space`), багаторядкових команд (`N`, `P`, `D`) та умовних переходів (`t`, `T`, `b`) робить командну мову `sed` повною за Тьюрінгом. Нижче наведено формальні специфікації та інженерні патерни проектування складних потокових автоматів.

### 1. Багаторядковий конвеєр ковзного вікна (`N;P;D`)

Патерн `N;P;D` дозволяє організувати потокову обробку вікна фіксованого розміру (наприклад, 2 рядки) над нескінченним вхідним потоком з просторовою складністю `O(1)`.

```text
Вхідний потік: [ L1 ] [ L2 ] [ L3 ] [ L4 ] ...
                     ▲
                     │
Крок 1 (Старт):      Pattern Space = "L1"
                     Виклик N      -> Pattern Space = "L1\nL2"
                     Обробка вікна -> [Перевірка умов над парою L1 та L2]
                     Виклик P      -> stdout <── "L1"
                     Виклик D      -> Pattern Space = "L2" (цикл перезапускається без читання!)

Крок 2 (Ітерація):   Pattern Space = "L2"
                     Виклик N      -> Pattern Space = "L2\nL3"
                     Обробка вікна -> [Перевірка умов над парою L2 та L3]
                     Виклик P      -> stdout <── "L2"
                     Виклик D      -> Pattern Space = "L3" (цикл перезапускається без читання!)
```

### 2. Сортування рядків у пам'яті sed (Bubble Sort у регістрах)

Сортування списку рядків у межах одного проходу реалізується за алгоритмом бульбашкового сортування (Bubble Sort). Усі рядки акумулюються в одному буфері через символ `\n`, після чого циклічний автомат виконує попарне порівняння та перестановку сусідніх елементів доти, доки за один повний прохід не припиняться операції обміну.

#### Специфікація алгоритму сортування

1. **Фаза акумуляції:** Усі вхідні рядки збираються в `Hold Space` за допомогою `1h; 1!H`.
2. **Фаза ініціалізації сортування:** На останньому рядку (`$`) вміст `Hold Space` витягується в `Pattern Space` командою `g`.
3. **Фаза проходу сортування (`:sort_loop`):**
   - Автомат шукає два сусідні рядки `A\nB`.
   - За допомогою лексикографічного порівняння або перевірки таблиці трансляції, якщо `A > B`, вони міняються місцями: `s/^\(.*\)\n\(.*\)$/\2\n\1/`.
   - Команда `t sort_loop` перезапускає сканування, якщо відбулася перестановка.
4. **Фаза виведення:** Коли жодної перестановки не відбулося (брудний біт `subst_success == false`), відсортований буфер виводиться у `stdout`.

### 3. Скінченні автомати та довільна десяткова арифметика

Оскільки `sed` не має вбудованого арифметичного співпроцесора, обчислення виконуються через табличні автомати підстановки (Lookup Tables) та циклічне перенесення розрядів (Carry Propagation).

#### Автомат інкрементування довільного невід'ємного десяткового числа

1. Замінює молодшу цифру за таблицею переходу: `0->1, 1->2, ..., 8->9`.
2. Якщо молодша цифра `9`, вона перетворюється на `0`, а прапорець переносу зсувається вліво на наступний розряд.
3. Якщо всі розряди були `9` (наприклад, `999`), на початок дописується `1` (`1000`).

## Комплексні інженерні рецепти рефакторингу вихідного коду C/C++ та системних скриптів

У промисловій розробці рефакторинг масштабних кодових баз (тисячі файлів, мільйони рядків) вимагає автоматизованих, детермінованих та ідемпотентних інструментів трансформації. Нижче наведено розбір складних багаторядкових автоматів `sed` для вирішення реальних завдань супроводу проектів на C, C++ та Bash.

### 1. Автоматизоване оновлення та стандартизація ліцензійних заголовків

#### Інженерна постановка задачі:
У кодовій базі проекту необхідно видалити старі різнорідні ліцензійні коментарі на початку файлів (наприклад, застарілі блоки 2012–2018 років) та вставити стандартизований заголовок SPDX (`// SPDX-License-Identifier: Apache-2.0`) разом з актуальним копірайтом.

#### Системні вимоги надійності:
1. **Збереження Shebang:** Якщо файл є скриптом і містить у першому рядку маркер `#!/bin/bash` або `#!/usr/bin/env python3`, заголовок має вставлятися **після** shebang-рядка.
2. **Видалення старих коментарів:** Блоки коментарів C-стилю (`/* ... */`) або C++-стилю (`// ...`) на початку файлу мають повністю видалятися без пошкодження наступного коду.
3. **Ідемпотентність:** Якщо файл уже містить актуальний рядок `SPDX-License-Identifier`, скрипт не повинен вносити повторних змін.

#### Покрокова діагностика роботи автомата:
1. **Фаза детекції:** Регулярний вираз `/net_send_packet[[:space:]]*\(/` фіксує рядок із початком виклику.

## Продуктивність та оптимізація: sed проти awk та perl на великих обсягах даних

При обробці багатогігабайтних файлів журналів (log files) та масивів даних вибір інструмента потокової обробки визначається пропускною здатністю I/O, накладними витратами на виділення пам'яті та моделлю парсингу записів.

### 1. Внутрішній I/O конвеєр sed: буферизація, нуль-копіювання та амортизація пам'яті

Висока продуктивність `sed` базується на трьох системних принципах:

1. **Блокова буферизація вводу:** `sed` зчитує дані з файлового дескриптора великими блоками розміром `BUFSIZ` (зазвичай 8192 або 65536 байтів) за допомогою низькорівневих викликів `read(2)` / `fread(3)`. Рядки виділяються безпосередньо у внутрішньому буфері введення без проміжних копіювань.
2. **Амортизоване перевикористання пам'яті (Zero Allocation Hot Loop):** Буфери `Pattern Space` та `Hold Space` динамічно зростають на купі (`realloc`) лише до максимальної довжини найдовшого рядка у потоці. Після досягнення необхідного розміру пам'ять ніколи не повертається операційній системі під час виконання: той самий блок пам'яті багаторазово перезаписується новими байтами. При середньому розмірі рядка логу 200–500 байтів `sed` виконує виділення пам'яті лише один-два рази на старті процесу, після чого працює з нульовими накладними витратами на алокатор.
3. **Відсутність парсингу полів:** На відміну від `awk`, який при зчитуванні кожного рядка розбирає текст на поля `$1, $2, ..., $NF` та створює масив покажчиків, `sed` сприймає рядок як монолітний масив байтів. Це виключає зайві цикли CPU та промахи кешу L1/L2.

### 2. Порівняльний аналіз швидкодії: sed проти awk та perl на потоках логів

Для оцінки ефективності розглядаються три типові інженерні сценарії на файлі обсягом 10 GB:

```text
Сценарій 1: Потокова заміна або фільтрація тексту (s/foo/bar/g або /ERROR/p)
  sed (LC_ALL=C):  ██████████████████████████████ 1150 MB/s (RSS: ~2.5 MB)
  mawk (LC_ALL=C): ██████████████████████████     980 MB/s  (RSS: ~3.5 MB)
  perl (LC_ALL=C): ████████████████████           800 MB/s  (RSS: ~18.0 MB)
  gawk (LC_ALL=C): ████████████                   480 MB/s  (RSS: ~9.0 MB)

Сценарій 2: Стовпчикова вибірка (print $1, $4 де $4 > 500)
  mawk:            ██████████████████████████     950 MB/s  (Лінійний O(N) прохід)
  gawk:            ████████████                   450 MB/s  (Нативний парсинг колонок)
  perl:            ████████████████████           780 MB/s  (split за запитом)
  sed:             █                              45 MB/s   (Повільна емуляція через regex \1)

Сценарій 3: Асоціативна агрегація та підрахунок (uniq -c / count[$1]++)
  mawk / gawk:     ██████████████████████████     750 MB/s  (Нативні хеш-таблиці O(N))
  perl:            ████████████████████████       700 MB/s  (Нативні хеші O(N))
  sed:             (Не застосовується: O(N^2) деградація при емуляції в Hold Space)
```

1. **Проста потокова заміна та фільтрація:** `sed` демонструє максимальну пропускну здатність (часто впираючись у швидкість читання накопичувача NVMe) з мінімальним використанням оперативної пам'яті (RSS < 4 MB).
2. **Стовпчикова обробка та робота з полями:** Утиліти `mawk` та `gawk` перемагають `sed`, оскільки для виділення окремої колонки в `sed` необхідно конструювати складні регулярні вирази з групуванням `\1`..`\9`, що вимикає швидкий DFA-фільтр.
3. **Агрегація, частотний аналіз та асоціативні масиви:** `awk` та `perl` виконують групування за константний час `O(N)` завдяки вбудованим хеш-таблицям (`count[$1]++`). У `sed` спроба реалізувати підрахунок через текстові підстановки в `Hold Space` перетворює алгоритм на квадратичну складність `O(N²)`, що робить обробку гігабайтних обсягів практично неможливою.

### 3. Вплив змінної середовища `LC_ALL=C` на пропускну здатність конвеєра

У сучасному дистрибутиві Linux за замовчуванням встановлено локаль UTF-8 (наприклад, `LANG=uk_UA.UTF-8` або `en_US.UTF-8`). Запуск `sed` у середовищі UTF-8 призводить до падіння швидкості у 4–10 разів через необхідність побайтової валідації багатобайтових послідовностей функціями `mbrtowc(3)` / `wcscoll(3)` та перевірки таблиць властивостей символів Юнікоду.

```bash
# Тест пропускної здатності в середовищі UTF-8:
$ time sed 's/foo/bar/g' 10GB_access.log > /dev/null
real    0m48.12s (~210 MB/s)

# Тест із примусовим вимкненням багатобайтової валідації:
$ time LC_ALL=C sed 's/foo/bar/g' 10GB_access.log > /dev/null
real    0m8.74s  (~1150 MB/s — прискорення у 5.5 разів!)
```

У режимі `LC_ALL=C` кожен байт інтерпретується як окремий символ (0..255). Таблиця переходів DFA (256 байтів) повністю поміщається в найшвидший кеш першого рівня процесора (L1 Data Cache, 32–48 KB), усуваючи промахи пам'яті.

### 4. Зведена таблиця архітектурних характеристик та меж застосування

| Критерій порівняння | GNU sed | Fast awk (`mawk`) | GNU awk (`gawk`) | Perl 5 |
|---|---|---|---|---|
| **Модель виконання** | Однопрохідний скінченний автомат (DFA/NFA) | Стекова байткод VM з нульовим overhead | Інтерпретатор байткоду AST з VM | Компілятор байткоду + VM з JIT Regex |
| **Споживання пам'яті (RSS)** | **~1.5 – 4 MB** (строго константно) | ~2 – 6 MB | ~5 – 15 MB | ~10 – 30 MB |
| **Пропускна здатність заміни (`LC_ALL=C`)** | **~1100 – 1200 MB/s** | ~950 – 1050 MB/s | ~450 – 550 MB/s | ~750 – 850 MB/s |
| **Накладні витрати парсингу полів** | Відсутні (монолітний буфер) | Відкладені (Lazy splitting) | Повні ($1..$NF на кожному рядку) | За запитом (`split`) |
| **Підтримка нативних типів даних** | Відсутня (лише текст) | Числа з плаваючою комою, рядки, хеші | Числа, рядки, багатовимірні масиви | Усі структури даних, посилання, об'єкти |
| **Час ініціалізації процесу** | **< 1 ms** | < 1 ms | ~2–4 ms | ~5–12 ms |
| **Оптимальна ніша застосування** | Швидкісне потокове очищення, in-place редагування конфігів, видалення діапазонів | Стовпчикова обробка гігабайтних TSV/CSV, швидкісна фільтрація | Комплексна аналітика даних, зведені таблиці, кастомні роздільники | Складний синтаксичний аналіз, взаємодія з API, бінарні формати |

## Зведена матриця сумісності: POSIX vs GNU sed vs BSD sed

Таблиця фіксує підтримуваність опцій, команд та синтаксичних розширень між специфікаціями POSIX.1-2017/2024, реалізацією GNU sed (Linux) та реалізацією BSD sed (macOS, FreeBSD, OpenBSD).

| Можливість / Синтаксис | POSIX.1 (IEEE Std 1003.1) | GNU sed (Linux) | BSD sed (macOS / FreeBSD) | Примітки та відмінності реалізацій |
|---|---|---|---|---|
| Прапорець `-n` / маркер `#n` | Так | Так | Так | Повна відповідність на всіх платформах. |
| Прапорець `-E` (ERE) | Так (з POSIX.1-2024) | Так | Так | У старих версіях GNU sed використовувався `-r`. |
| Прапорець `-i` (in-place) | Ні | Так (`-i` або `-i.bak`) | Так (`-i ''` або `-i .bak`) | **Критична несумісність:** у BSD суфікс є обов'язковим окремим аргументом (`-i ''`), у GNU — необов'язковим приєднаним (`-i`). |
| Опція `--follow-symlinks` | Ні | Так | Ні | Збереження структури символічних посилань при in-place редагуванні. |
| Прапорець `-s` (separate) | Ні | Так | Ні | Ізоляція лічильників рядків та станів тригерів між файлами. |
| Прапорець `-z` (null-data) | Ні | Так | Ні | Обробка записів, розділених нульовим байтом `\0`. |
| Прапорець `-u` (unbuffered) | Ні | Так | Так | Мінімізація буферизації потоків вводу/виводу. |
| Крокова адресація `first~step` | Ні | Так (`1~2`) | Ні | У BSD sed генерує синтаксичну помилку. |
| Нульова адреса `0,/шаблон/` | Ні | Так | Ні | Дозволяє збіг на рядку 1; у POSIX/BSD `0` є помилкою. |
| Відносні адреси `addr,+N`, `addr,~N` | Ні | Так | Ні | Діапазон відносних рядків та вирівнювання за кратністю. |
| Підстановка: перетворення `\L`, `\U`, `\E` | Ні | Так | Ні | Регістрові конверсії в полі заміни `s///`. |
| Прапорець підстановки `M` / `m` | Ні | Так | Ні | Багаторядкове зіставлення `^` та `$` навколо `\n`. |
| Прапорець підстановки `I` / `i` | Ні | Так | Так (FreeBSD/macOS) | Нечутливість до регістру символів. |
| Прапорець / команда `e` | Ні | Так | Ні | Виконання команд оболонки `/bin/sh`. |
| Команда `T` (Branch on Failure) | Ні | Так | Ні | Умовний перехід, якщо жодна заміна `s///` не вдалася. |
| Команди `Q`, `z` | Ні | Так | Ні | `Q` — тихий вихід; `z` — очищення буфера без зупинки. |
| Команди `R`, `W` | Ні | Так | Ні | Порядкове читання з файлу та запис першого рядка. |
| Команди `F`, `v` | Ні | Так | Ні | Друк імені файлу та перевірка версії. |
| Однорядковий запис `a`, `i`, `c` | Ні | Так (`i text`) | Ні (потрібен `\` + `\n`) | BSD вимагає екранованого переносу рядка. |
| Поведінка `N` на EOF | Друкує Pattern Space | Без виводу (якщо не `--posix`) | Без виводу | Відмінність поведінки завершення на фінальному рядку. |
| Точка з комою перед `}` | Обов'язкова (або `\n`) | Необов'язкова | Обов'язкова (або `\n`) | Синтаксис закриття блоків `{ ... }`. |

## Системні коди повернення (Exit Codes)

| Код виходу | Категорія завершення | Опис та системні причини |
|---|---|---|
| `0` | Успіх (`EXIT_SUCCESS`) | Вхідний потік повністю та успішно оброблено, або виконано команду завершення `q 0` / `Q 0`. |
| `1` | Синтаксична помилка | Передано некоректний сценарій sed (непарні фігурні дужки `{}`, невідома команда, неправильно оформлена адреса, помилка компіляції регулярного виразу `regcomp()`). |
| `2` | Помилка введення/виведення (I/O) | Не вдалося відкрити або зчитати вхідний файл на накопичувачі, сталася помилка доступу до файлу для запису в командах `w`/`W`, або виникла помилка `rename()` під час виконання `sed -i`. |
| `N` | Специфічний код користувача | Довільний цілочисельний код повернення в діапазоні `0..255`, явно переданий командами `q N` або `Q N`. |
