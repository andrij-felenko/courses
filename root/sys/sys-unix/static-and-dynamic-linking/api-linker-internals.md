# 📋 Інтерфейс та структури динамічного лінкування

Ця довідкова вставка містить вичерпний опис бінарних структур ELF, системних API-функцій стандарту POSIX (`<dlfcn.h>`), алгоритмів обходу залежностей та змінних середовища, які керують поведінкою динамічного завантажувача `ld.so` у системному середовищі Linux.

## Бінарний інтерфейс секції .dynamic та структури ELF

Під час створення динамічно злінкованого бінарного файла компонувальник `ld` додає до нього спеціальний сегмент `PT_DYNAMIC`. У файловій системі та в пам'яті цьому сегменту відповідає секція `.dynamic`. 

Секція `.dynamic` являє собою масив елементів структури `Elf64_Dyn` (або `Elf32_Dyn` для 32-бітних архітектур). Масив завершується елементом з ідентифікатором тегу `DT_NULL`.

```c
typedef struct {
    Elf64_Sxword d_tag;   /* Ідентифікатор типу запису (тег) */
    union {
        Elf64_Xword d_val; /* Цілочисельне значення або розмір */
        Elf64_Addr  d_ptr; /* Віртуальна адреса в пам'яті */
    } d_un;
} Elf64_Dyn;
```

Кожен запис секції `.dynamic` задає конкретний параметр, необхідний динамічному завантажувачу `ld.so` для налаштування адресного простору процесу під час запуску.

### Вичерпна специфікація тегів секції .dynamic

| Тег (d_tag) | Тип поля | Призначення та поведінка динамічного завантажувача |
| :--- | :--- | :--- |
| `DT_NULL` | `d_val` | Завершує масив елементів секції `.dynamic`. Завантажувач припиняє парсинг при зустрічі цього тегу. |
| `DT_NEEDED` | `d_val` | Задає байтове зміщення в таблиці рядків (`.dynstr`), яке вказує на ім'я необхідної спільновживаної бібліотеки (наприклад, `libc.so.6`). Секція може містити безліч записів `DT_NEEDED`. |
| `DT_PLTGOT` | `d_ptr` | Зберігає віртуальну адресу, пов'язану з таблицями PLT та GOT (на x86_64 вказує на початок секції `.got.plt`). |
| `DT_HASH` | `d_ptr` | Віртуальна адреса класичної таблиці хешів символів у форматі System V (SYSV Hash Table). |
| `DT_GNU_HASH` | `d_ptr` | Віртуальна адреса оптимізованої хеш-таблиці символів GNU (GNU Hash Table), яка використовує фільтр Блума (Bloom filter) і прискорює пошук символів на 50%. |
| `DT_STRTAB` | `d_ptr` | Віртуальна адреса таблиці рядків динамічних символів (`.dynstr`). Містить Null-terminated рядки з іменами всіх функцій і змінних. |
| `DT_SYMTAB` | `d_ptr` | Віртуальна адреса таблиці динамічних символів (`.dynsym`), що містить масив структур `Elf64_Sym`. |
| `DT_STRSZ` | `d_val` | Загальний розмір таблиці рядків динамічних символів (`.dynstr`) у байтах. |
| `DT_SYMENT` | `d_val` | Розмір одного запису в таблиці динамічних символів `Elf64_Sym` у байтах (зазвичай 24 байти на x86_64). |
| `DT_INIT` | `d_ptr` | Віртуальна адреса застарілої функції ініціалізації модуля (викликається до `main`). |
| `DT_FINI` | `d_ptr` | Віртуальна адреса застарілої функції деініціалізації модуля (викликається після `exit`). |
| `DT_INIT_ARRAY` | `d_ptr` | Віртуальна адреса масиву вказівників на функції-конструктори (`.init_array`). Використовується для ініціалізації глобальних об'єктів C++. |
| `DT_INIT_ARRAYSZ`| `d_val` | Загальний розмір масиву функцій-конструкторів `.init_array` у байтах. |
| `DT_FINI_ARRAY` | `d_ptr` | Віртуальна адреса масиву вказівників на функції-деструктори (`.fini_array`). |
| `DT_FINI_ARRAYSZ`| `d_val` | Загальний розмір масиву функцій-деструкторів `.fini_array` у байтах. |
| `DT_RPATH` | `d_val` | Зміщення в `.dynstr`, що задає застарілий hardcoded шлях пошуку бібліотек. Має низький пріоритет. |
| `DT_RUNPATH` | `d_val` | Зміщення в `.dynstr`, що задає сучасний hardcoded шлях пошуку бібліотек (задається прапорцем `-Wl,-rpath`). Перевизначає `DT_RPATH`. |
| `DT_RELA` | `d_ptr` | Віртуальна адреса таблиці релокацій з явним аддендом (`.rela.dyn` або `.rela.plt`). |
| `DT_RELASZ` | `d_val` | Загальний розмір таблиці релокацій `DT_RELA` у байтах. |
| `DT_RELAENT` | `d_val` | Розмір одного запису релокації `Elf64_Rela` у байтах (зазвичай 24 байти). |
| `DT_FLAGS_1` | `d_val` | Бітова маска спеціальних прапорців завантажувача (наприклад, `DF_1_NOW` для миттєвого зв'язування або `DF_1_PIE` для позиційно-незалежного виконуваного файла). |

## Програмний інтерфейс POSIX dlfcn (libdl)

Для реалізації систем динамічних плагінів, розширень та завантаження модулів під час виконання (Run-time Dynamic Loading) стандарт POSIX визнає інтерфейс `<dlfcn.h>`. 

У сучасній системі `glibc` (починаючи з версії 2.34) функції `dlopen`, `dlsym`, `dlclose`, `dlerror` вбудовано безпосередньо у головну системну бібліотеку `libc.so`. У старіших Linux-системах для використання цих функцій вимагається лінкування з прапорцем `-ldl`.

### 1. Системний виклик dlopen

```c
void *dlopen(const char *filename, int flags);
```

Функція `dlopen` відкриває файл динамічної бібліотеки, відображає її сегменти у віртуальний адресний простір викликаючого процесу, виконує необхідні релокації та повертає непрозорий дескриптор (handle).

- **Параметр `filename`:** Відносний або абсолютний шлях до файлу `.so`. Якщо передано лише ім'я файла (без символу `/`), динамічний завантажувач виконує пошук за стандартним алгоритмом. Якщо передано `NULL`, `dlopen` повертає дескриптор головного виконуваного бінарника програми.
- **Параметр `flags`:** Бітова комбінація прапорців режиму зв'язування.

#### Обов'язкові прапорці режимів (має бути вказано рівно один з двох):

- `RTLD_LAZY`: **Відкладене лінкування (Lazy Binding).** Виклики функцій не релокуються під час роботи `dlopen`. Релокація інструкцій відбувається динамічно лише в момент першого фізичного виклику кожної конкретної функції через PLT-трамплін. Це забезпечує миттєве повернення з `dlopen`.
- `RTLD_NOW`: **Негайне лінкування (Immediate Binding).** Під час виконання `dlopen` завантажувач негайно вирішує абсолютно всі необов'язкові та обов'язкові посилання на функції та змінні у завантажуваній бібліотеці. Якщо хоча б один символ не вдається вирішити, `dlopen` повертає помилку `NULL`.

#### Додаткові прапорці керування (можна комбінувати за допомогою побітового OR `|`):

- `RTLD_GLOBAL`: Експортує всі символи завантажуваної бібліотеки у глобальний простір імен процесу. Ці символи стають доступними для вирішення залежностей у згодом завантажуваних бібліотеках.
- `RTLD_LOCAL`: **(Режим за замовчуванням)** Символи завантажуваної бібліотеки залишаються приватними для цього дескриптора і не використовуються для вирішення зовнішніх символів в інших модулях.
- `RTLD_NODELETE`: Забороняє вивантаження коду бібліотеки з оперативної пам'яті при наступному виклику `dlclose()`. Якщо бібліотека згодом відкриється знову через `dlopen`, її стани статичних змінних зберігаються.
- `RTLD_NOLOAD`: Перевіряє, чи завантажена бібліотека вже у віртуальний адресний простір процесу. Якщо бібліотека завантажена, повертає її наявний дескриптор; якщо ні — повертає `NULL` без завантаження файла з диска.
- `RTLD_DEEPBIND`: Змушує завантажувач при вирішенні символів усередині цієї бібліотеки віддавати перевагу власним внутрішнім символам бібліотеки перед глобальними символами з такими ж іменами, які вже існують у програмі.

### 2. Системний виклик dlsym

```c
void *dlsym(void *handle, const char *symbol);
```

Приймає дескриптор завантаженої бібліотеки `handle` та ім'я символу `symbol` (у стилі C, null-terminated string) і повертає точну віртуальну адресу цього символу (функції або глобальної змінної) в пам'яті.

#### Спеціальні псевдо-дескриптори для dlsym:

- `RTLD_DEFAULT`: Шукає символ у глобальному просторі імен процесу за стандартним порядком завантаження (починаючи з головного бінарника, потім по всіх завантажених `.so` бібліотеках).
- `RTLD_NEXT`: Шукає наступне входження символу в бібліотеках, які були завантажені *після* поточної бібліотеки. Це основний інструмент для реалізації перехоплення функцій (function hooking) у бібліотеках `LD_PRELOAD`.

### 3. Системний виклик dlclose

```c
int dlclose(void *handle);
```

Зменшує внутрішній лічильник посилань (reference count) завантаженої динамічної бібліотеки. Якщо лічильник посилань досягає нуля, динамічний завантажувач викликає деструктори з секції `.fini_array` даної бібліотеки, вивантажує її сторінки з пам'яті за допомогою `munmap()` і видаляє дескриптор.

### 4. Системний виклик dlerror

```c
char *dlerror(void);
```

Повертає текстовий рядок з описом останньої помилки, яка сталася під час виконання функцій `dlopen`, `dlsym` або `dlclose`. Якщо помилок не було від моменту останнього виклику, повертає `NULL`. 

> ⚠️ **Важлива особливість:** Функція `dlerror()` є деструктивною для стану помилки. Вона повертає покажчик на внутрішній буфер і одразу скидає його значення в `NULL`. Повторний послідовний виклик `dlerror()` гарантовано поверне `NULL`.

### 5. Системна структура та функція dladdr

```c
#define _GNU_SOURCE
#include <dlfcn.h>

typedef struct {
    const char *dli_fname; /* Шлях до .so файла або бінарника, що містить адресу */
    void       *dli_fbase; /* Базова адреса завантаження модуля в пам'ять (mmap base) */
    const char *dli_sname; /* Ім'я найближчого символу (функції), що передує адресі */
    void       *dli_saddr; /* Точна віртуальна адреса початку цього символу */
} Dl_info;

int dladdr(const void *addr, Dl_info *info);
```

Функція `dladdr` виконує зворотне відображення (інтроспекцію): за довільною віртуальною адресою в пам'яті `addr` вона визначає, якому саме бінарному модулю належить ця адреса, де розташований цей модуль у RAM та назву найближчого експортованого символу.

## Змінні середовища динамічного завантажувача (ld.so)

Динамічний завантажувач Linux (`ld-linux.so`) аналізує низку спеціальних змінних оточення під час старту будь-якого динамічного процесу.

> 🔒 **Безпека SUID/SGID та Capabilities:** Якщо бінарний файл має встановлені прапорці `SUID` або `SGID` (наприклад, `/usr/bin/passwd` або `/usr/bin/sudo`), або якщо процес володіє підвищеними Linux capabilities, завантажувач `ld.so` з міркувань безпеки **повністю ігнорує** змінні `LD_PRELOAD`, `LD_LIBRARY_PATH` та `LD_AUDIT`. Це запобігає локальному підвищенню привілеїв шляхом підміни системних функцій у привілейованих процесах.

### Повна довідкова таблиця змінних ld.so

| Змінна середовища | Опис, призначення та механізм дії |
| :--- | :--- |
| `LD_PRELOAD` | Список бібліотек (через двоеточіє або пробіл), які завантажуються **найпершими**, до відкриття всіх інших бібліотек та `libc.so`. Дозволяє перехоплювати та замінювати будь-які системні функції.<br>Приклад: `LD_PRELOAD=/usr/lib/libmimalloc.so ./my_app` |
| `LD_LIBRARY_PATH` | Список додаткових каталогів (через двоеточіє), де завантажувач шукає файли `.so` під час запуску програми. Перевизначає системні шляхи за замовчуванням.<br>Приклад: `LD_LIBRARY_PATH=/opt/custom_lib ./my_app` |
| `LD_BIND_NOW` | Якщо встановлено значення `1`, змушує `ld.so` виконати негайну релокацію всіх функцій у PLT під час старту програми (повністю вимикає lazy binding). |
| `LD_DEBUG` | Вмикає вивід детальних логів діагностики завантажувача в `stderr`. Можливі значення: `libs` (пошук файлів), `reloc` (процес релокації), `symbols` (вирішення символів), `bindings`, `versions`, `all`.<br>Приклад: `LD_DEBUG=libs ./my_app` |
| `LD_DEBUG_OUTPUT` | Задає префікс шляху файла для запису логів `LD_DEBUG` замість стандартного виводу в `stderr`. |
| `LD_SHOW_AUXV` | Якщо встановлено значення `1`, завантажувач перед запуском програми виводить у `stdout` весь вміст вектора Auxiliary Vector, переданого ядром Linux. |
| `LD_AUDIT` | Список бібліотек розширеного аудиту (з підтримкою API `rtld-audit`), які перехоплюють події завантаження бібліотек, викликів PLT та релокацій на рівні ядра завантажувача. |
| `LD_DYNAMIC_WEAK` | Якщо встановлено значення `1`, дозволяє слабким символам (weak symbols) з пізніше завантажених бібліотек замінювати раніше визначені слабкі символи. |

## Порядок пошуку динамічних бібліотек у файловій системі Linux

Коли динамічний завантажувач бачить запис залежності `DT_NEEDED` (наприклад, `libssl.so.3`), він виконує пошук файла у файловій системі Linux у такому **суворо визначеному порядку пріоритетів**:

1. **Каталоги з `DT_RPATH`:** Задаються в заголовочному блоці бінарника під час компіляції (за умови, що в бінарнику відсутній тег `DT_RUNPATH`).
2. **Каталоги зі змінної середовища `LD_LIBRARY_PATH`:** Перераховані користувачем у списку розділених двокрапкою шляхів (ігнорується для SUID-бінарників).
3. **Каталоги з `DT_RUNPATH`:** Сучасний спосіб задання шляхів пошуку у заголовочному блоці бінарника (задається через `-Wl,-rpath`). Якщо присутній `DT_RUNPATH`, запис `DT_RPATH` повністю ігнорується.
4. **Кеш динамічного завантажувача `/etc/ld.so.cache`:** Швидкий бінарний індекс усіх доступних системних бібліотек. Цей кеш ґенерується системною утилітою `ldconfig` на основі конфігураційного файла `/etc/ld.so.conf` та його підкаталогу `/etc/ld.so.conf.d/*.conf`.
5. **Стандартний системний каталог `/lib64`** (або `/lib` для 32-бітних систем).
6. **Стандартний системний каталог `/usr/lib64`** (або `/usr/lib`).

Якщо після перевірки всіх зазначених джерел файл динамічної бібліотеки не знайдено у файловій системі, завантажувач `ld.so` припиняє запуск процесу і виводить у консоль стандартну системну помилку:
`error while loading shared libraries: libssl.so.3: cannot open shared object file: No such file or directory`.
