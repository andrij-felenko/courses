# 📋 Інтерфейси керування буферизацією: stdio, stdbuf та прапорці утиліт

Конвеєри Unix передають дані між процесами через байтові канали ядра (`pipe`), проте фактична затримка передачі даних визначається не ядром, а механізмами буферизації стандартної бібліотеки мови C (`libc stdio`) та рушіями конкретних утиліт. Якщо процес не налаштований на миттєве скидання буфера після кожного рядка, конвеєр накопичує від 4 КіБ до 64 КіБ даних перед передачею наступній ланці, створюючи тривалі паузи в режимі реального часу.

Нижче наведено структурований довідник системних викликів, функцій бібліотеки `libc`, внутрішніх структур керування дескрипторами, змінних оточення утиліти `stdbuf` та вбудованих прапорців класичних фільтрів для повного контролю затримок вводу-виводу.

## Внутрішня структура буферизації `FILE*` у стандартній бібліотеці C

Усі операції високорівневого потокового введення-виведення в бібліотеці `glibc` спираються на внутрішню структуру керування файловими потоками `struct _IO_FILE` (оголошену в системному заголовку `stdio.h` та реалізовану в модулях `libio`). Ця структура містить набір вказівників пам'яті, що визначають активне вікно буфера:

- `_IO_read_ptr` та `_IO_read_end`: позначають поточну позицію читання та кінець заповнених даних у буфері вводу.
- `_IO_write_base`, `_IO_write_ptr` та `_IO_write_end`: визначають межі буфера виводу. Нові дані дописуються у позицію `_IO_write_ptr`. Щойно `_IO_write_ptr` досягає `_IO_write_end`, бібліотека викликає внутрішню функцію `__overflow()`, яка скидає накопичені байти в ядро системним викликом `write(2)`.
- `_IO_buf_base` та `_IO_buf_end`: позначають фізичні межі всієї виділеної області пам'яті під буфер потоку.

Керування цими вказівниками здійснюється системною функцією `setvbuf(3)`.

### Сигнатура та константи режимів

:::tabs
```c
#include <stdio.h>

/*
 * stream: вказівник на відкритий потік (stdin, stdout, stderr або FILE*)
 * buf:    буфер виділений користувачем (або NULL для автовиділення libc)
 * mode:   режим буферизації (_IONBF, _IOLBF, _IOFBF)
 * size:   розмір буфера в байтах
 */
int setvbuf(FILE *stream, char *buf, int mode, size_t size);
```
```cpp
#include <cstdio>
#include <iostream>
#include <memory>
#include <vector>

// У C++ керування буферизацією потоків stdio здійснюється через std::setvbuf,
// а для потоків iostream — через синхронізацію та прив'язку потоків.
void configure_stream_buffering(std::FILE* stream, int mode, std::size_t size) {
    if (std::setvbuf(stream, nullptr, mode, size) != 0) {
        std::perror("setvbuf failed");
    }
}
```
:::

| Режим | Числове значення (glibc) | Опис поведінки | Типове застосування |
|---|---|---|---|
| `_IONBF` | `2` (*No Buffering*) | Дані скидаються системним викликом `write(2)` негайно на кожен байт або запис. | Потік помилок `stderr`. |
| `_IOLBF` | `1` (*Line Buffering*) | Буфер скидається у разі запису символу `\n` (`0x0A`) або коли буфер заповнюється повністю. | Потік `stdout`, якщо підключено інтерактивний термінал (`isatty(1) == 1`). |
| `_IOFBF` | `0` (*Full Buffering*) | Дані накопичуються до досягнення розміру `size` (зазвичай 4096 або 65536 байтів) або до явного виклику `fflush()` / закриття дескриптора `fclose()`. | Потоки `stdin` та `stdout`, спрямовані у файл або конвеєр (`pipe`). |

### Життєвий цикл запису в режимах `_IOLBF` та `_IOFBF`

Коли програма викликає функцію форматованого виводу `printf("Повідомлення\n")`, бібліотека виконує такі кроки:

1. **Копіювання у буфер користувача**: Символи копіюються за адресою `_IO_write_ptr`, і вказівник зсувається вперед на кількість записаних байтів.
2. **Перевірка умов скидання (Flush Check)**:
   - У режимі `_IOLBF` сканер перевіряє наявність байта `0x0A` (`\n`) серед щойно записаних даних. Якщо символ знайдено, функція `_IO_do_write()` негайно здійснює системний виклик `write(fileno(fp), _IO_write_base, _IO_write_ptr - _IO_write_base)` і скидає вказівник `_IO_write_ptr` на початок `_IO_write_base`.
   - У режимі `_IOFBF` символ `\n` ігнорується, і запис триває доти, доки `_IO_write_ptr == _IO_write_end`. Лише після вичерпання виділеного обсягу пам'яті викликається `write(2)` на весь розмір блоку.

### Правила ініціалізації за замовчуванням у glibc

Під час запуску програми середовище виконання C налаштовує дескриптори за такими правилами:
1. `stderr` завжди ініціалізується в режимі `_IONBF`, що гарантує негайну доставку аварійних повідомлень навіть у разі раптового збою програми.
2. Якщо виклик `isatty(fileno(stream))` повертає `1` (дескриптор вказує на пристрій термінала), потік налаштовується як `_IOLBF` з розміром буфера 1024 байти.
3. Якщо виклик `isatty(fileno(stream))` повертає `0` (потік перенаправлено у файл, сокет або анонімний канал pipe), потік налаштовується як `_IOFBF` з розміром буфера, що відповідає розміру блоку файлової системи `st_blksize` з виклику `fstat(2)` (зазвичай 4096 байтів).

## Керування розміром каналу ядра `pipe`

Ядро Linux виділяє для кожного каналу міжпроцесної взаємодії кільцевий буфер сторінок пам'яті (`struct pipe_inode_info`). Запис у канал здійснюється атомарно, якщо обсяг порції даних не перевищує константу `PIPE_BUF` (4096 байтів на Linux). Якщо обсяг запису більший, ядро може чергувати байти від різних паралельних процесів-постачальників.

### Системний інтерфейс `fcntl(2)`

:::tabs
```c
#define _GNU_SOURCE
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int set_pipe_capacity(int pipe_fd, int capacity_bytes) {
    // Встановлення нового розміру кільцевого буфера ядра
    int actual_size = fcntl(pipe_fd, F_SETPIPE_SZ, capacity_bytes);
    if (actual_size == -1) {
        perror("fcntl F_SETPIPE_SZ");
        return -1;
    }
    return actual_size;
}
```
```cpp
#define _GNU_SOURCE
#include <fcntl.h>
#include <unistd.h>
#include <system_error>
#include <iostream>

int set_pipe_capacity(int pipe_fd, int capacity_bytes) {
    int actual_size = fcntl(pipe_fd, F_SETPIPE_SZ, capacity_bytes);
    if (actual_size == -1) {
        throw std::system_error(errno, std::generic_category(), "fcntl F_SETPIPE_SZ failed");
    }
    return actual_size;
}
```
:::

- **Стандартний розмір**: 16 сторінок пам'яті ядра = 65 536 байтів (64 КіБ на архітектурі x86-64).
- **Мінімальний розмір**: 1 сторінка (4096 байтів).
- **Системний ліміт для непривілейованих процесів**: файл `/proc/sys/fs/pipe-max-size` (за замовчуванням 1 048 576 байтів = 1 МіБ). Значення можна збільшити за наявності привілею `CAP_SYS_RESOURCE`.

## Утиліта `stdbuf`: механізм `LD_PRELOAD` та ін'єкція середовища

Утиліта `stdbuf` модифікує поведінку буферизації динамічно скомпільованих програм без зміни їхнього вихідного коду шляхом попереднього завантаження бібліотеки `libstdbuf.so`.

### Синтаксис виклику

```bash
stdbuf [ОПЦІЇ] КОМАНДА [АРГУМЕНТИ...]
```

### Параметри конфігурації потоків

| Опція | Змінна оточення | Допустимі значення | Опис дії |
|---|---|---|---|
| `-i`, `--input` | `_STDBUF_I` | `L`, `0`, `N` (число) | Налаштовує буферизацію стандартного вводу `stdin`. |
| `-o`, `--output` | `_STDBUF_O` | `L`, `0`, `N` (число) | Налаштовує буферизацію стандартного виводу `stdout`. |
| `-e`, `--error` | `_STDBUF_E` | `L`, `0`, `N` (число) | Налаштовує буферизацію стандартного потоку помилок `stderr`. |

### Формат суфіксів розміру для `N`

- `0` — режим без буферизації (`_IONBF`).
- `L` — порядковий режим (`_IOLBF`), доступний тільки для потоків виводу.
- `B` — множник 1 (байти).
- `K` або `KiB` — множник 1024 (кібібайти).
- `M` або `MiB` — множник 1024 × 1024 (мебібайти).

### Внутрішня реалізація `libstdbuf.so`

Бібліотека містить конструктор із атрибутом `__attribute__((constructor))`, який автоматично викликається динамічним лінкером під час ініціалізації процесу до передачі керування функції `main()`:

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>

static void __attribute__((constructor)) init_stdbuf(void) {
    const char *out_mode = getenv("_STDBUF_O");
    if (out_mode) {
        if (out_mode[0] == '0') {
            setvbuf(stdout, NULL, _IONBF, 0);
        } else if (out_mode[0] == 'L') {
            setvbuf(stdout, NULL, _IOLBF, 0);
        } else {
            size_t sz = strtoul(out_mode, NULL, 10);
            if (sz > 0) setvbuf(stdout, NULL, _IOFBF, sz);
        }
    }
}
```
```cpp
#include <cstdio>
#include <cstdlib>
#include <string_view>

namespace {
    struct StreamBufferInitializer {
        StreamBufferInitializer() noexcept {
            if (const char* out_mode = std::getenv("_STDBUF_O")) {
                std::string_view mode{out_mode};
                if (mode == "0") {
                    std::setvbuf(stdout, nullptr, _IONBF, 0);
                } else if (mode == "L") {
                    std::setvbuf(stdout, nullptr, _IOLBF, 0);
                } else {
                    char* end = nullptr;
                    unsigned long sz = std::strtoul(out_mode, &end, 10);
                    if (sz > 0) {
                        std::setvbuf(stdout, nullptr, _IOFBF, sz);
                    }
                }
            }
        }
    };

    // Статичний об'єкт ініціалізується до виклику main()
    const StreamBufferInitializer g_stream_initializer;
}
```
:::

### Обмеження застосування `stdbuf`

1. **Статично скомпільовані бінарні файли**: Якщо програма зібрана без підтримки динамічного лінкера (`-static` або мовами Go/Rust без `cgo`), механізм `LD_PRELOAD` не працює, і `stdbuf` не зможе змінити режим буферизації.
2. **Програми з явним повторним викликом `setvbuf`**: Якщо всередині функції `main()` програма явно викликає `setvbuf()` або `setbuf()`, це перезапише налаштування, задані `libstdbuf.so` на етапі конструктора.
3. **Пряме використання системних викликів `read/write`**: Якщо утиліта працює через сирі файлові дескриптори `int fd` в обхід обгортки `FILE*`, функції `stdio` не беруть участі в обробці даних.

## Вбудовані прапорці буферизації класичних утиліт

Якщо `stdbuf` не може бути застосований, керування здійснюється спеціалізованими прапорцями, вбудованими безпосередньо в кожну утиліту.

### Зведена таблиця фільтрів

| Утиліта | Прапорець / Команда | Механізм дії | Приклад використання |
|---|---|---|---|
| **grep** | `--line-buffered` | Викликає `fflush(stdout)` після кожного рядка, що збігся з шаблоном. | `tail -f app.log \| grep --line-buffered "ERROR"` |
| **sed** | `-u`, `--unbuffered` | Зчитує мінімальні порції зі `stdin` і негайно скидає `stdout` після кожної заміни `p` або `s///`. | `tail -f app.log \| sed -u 's/foo/bar/g'` |
| **awk (gawk)** | `-W interactive` | Переводить потік виводу в небуферизований або порядковий режим. | `tail -f app.log \| gawk -W interactive '{print $1}'` |
| **awk (POSIX)** | `fflush()` | Явний виклик функції `fflush()` або `fflush(stdout)` у тілі дії правила. | `awk '{print $1; fflush()}'` |
| **sort** | `-S, --buffer-size=SIZE` | Обмежує розмір оперативної пам'яті для сортування перед скиданням на диск (temp files). | `sort -S 2G -T /tmp/sort_work/ input.txt` |
| **sort** | `--parallel=N` | Кількість паралельних потоків виконання сортування. | `sort --parallel=8 input.txt` |
| **sort** | `LC_ALL=C` | Вимикає Unicode-солінг та колізії, порівнює байти за ASCII-кодами (`0x00-0xFF`). | `LC_ALL=C sort -k1,1 input.txt` |

## Робота з псевдотерміналами: утиліта `unbuffer`

Для програм, які жорстко перевіряють `isatty()` і відмовляються змінювати буферизацію через бібліотечні виклики або прапорці, використовується утиліта `unbuffer` (з пакету `expect`):

```bash
# unbuffer створює пару дескрипторів псевдотерміналу (/dev/pts/X),
# змушуючи downstream-процес вважати, що він працює з фізичним терміналом
unbuffer some_interactive_binary | grep "STATUS"
```

### Механізм роботи псевдотермінала (PTY)

1. Утиліта `unbuffer` викликає системний виклик `posix_openpt(2)` або `openpty(3)` для створення пари ведучого (*master*) та веденого (*slave*) псевдотерміналів.
2. Процес цільової програми запускається із перенаправленням стандартних дескрипторів `0`, `1`, `2` на ведений пристрій `/dev/pts/N`.
3. Коли цільова програма викликає `isatty(1)`, ядро повертає `1`, оскільки `/dev/pts/N` є повноцінним термінальним пристроєм.
4. Програма автоматично вмикає порядковий буфер `_IOLBF`. Утиліта `unbuffer` зчитує байти з ведучого кінця PTY і перенаправляє їх у стандартний конвеєр.

Накладна ціна `unbuffer`: створення додаткового процесу інтерпретатора `expect`, виділення PTY-дескрипторів ядра та додатковий шар емуляції термінальної дисципліни рядків (`termios` з прапорцями `ICANON`, `ECHO`, `ONLCR`).
