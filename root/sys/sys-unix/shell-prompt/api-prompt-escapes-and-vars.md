# 📋 Довідник змінних запрошення та керівних послідовностей оболонки

Цей довідник містить повну специфікацію системних змінних керування запрошеннями (`PS1`–`PS4`, `PROMPT_COMMAND`, `PROMPT_DIRTRIM`), таблицю керівних послідовностей GNU Bash, константи бібліотеки GNU Readline для маркування невидимих символів, а також зіставлення стандартів POSIX, Bash та Zsh.

## Системні змінні запрошення

У командних оболонках сімейства Unix стан та поведінка інтерфейсу командного рядка визначаються набором спеціальних змінних середовища та внутрішніх змінних оболонки. Кожна змінна відповідає за окрему фазу життєвого циклу інтерпретатора.

| Змінна | Призначення | Область застосування | Значення за замовчуванням |
|---|---|---|---|
| `PS1` | Первинне командне запрошення (Primary Prompt) | Інтерактивний режим REPL, готовність до прийому нової команди | `\s-\v\$ ` (Bash) або `$ ` (POSIX sh) |
| `PS2` | Вторинне командне запрошення (Secondary Prompt) | Багаторядкове введення, незавершені лапки, конвеєри, блоки `if`/`while`/`for` | `> ` |
| `PS3` | Запрошення інтерактивного меню | Вбудована конструкція `select name in words; do ... done` | `#? ` |
| `PS4` | Префікс рядка трасування виконання | Режим налагодження `set -x` (`set -o xtrace`) у сценаріях та оболонці | `+ ` (перший символ множиться на рівень вкладеності `$SHLVL`) |
| `PROMPT_COMMAND` | Команда або масив команд, що виконуються перед виводом `PS1` | Опитування зовнішнього стану, фіксація історії, встановлення заголовка вікна | Не встановлено (починаючи з Bash 5.1 підтримує тип `array`) |
| `PROMPT_DIRTRIM` | Кількість кінцевих каталогів, що зберігаються під час розгортання `\w` і `\W` | Скорочення занадто довгих шляхів у глибині файлової системи | `0` або порожньо (не обрізати; значення `>0` вставляє трикрапку `.../`) |

### Детальний механізм функціонування кожної змінної

Змінна `PS1` розгортається інтерпретатором щоразу, коли завершується виконання попередньої команди або конвеєра і потік керування повертається до головного циклу читання рядка. Розгортання відбувається у кілька послідовних кроків: спершу Bash замінює бекслеш-послідовності (`\u`, `\h`, `\w`), після цього виконує параметричні підстановки (`${VAR}`), арифметичні обчислення (`$((...))`) та підстановки команд (`$(...)`), якщо вони були захищені одинарними лапками під час визначення.

Змінна `PS2` активується синтаксичним аналізатором під час розпізнавання незавершених граматичних конструкцій. Якщо лексичний сканер виявляє відкриту лапку, незакритий конвеєр чи керівний блок, він призупиняє парсинг і звертається до користувача через `PS2`. У `PS2` розгортаються ті самі бекслеш-послідовності, що й у `PS1`, проте динамічні команди зазвичай туди не включають заради збереження візуальної стабільності при багаторядковому введенні.

Змінна `PS3` обслуговує вбудовану інструкцію створення текстових інтерфейсів `select`. Коли інтерпретатор обробляє список аргументів, він генерує нумерований список варіантів у стандартний потік помилок, після чого друкує вміст `PS3` і зчитує вибір користувача у спеціальну внутрішню змінну `REPLY`.

Змінна `PS4` відіграє роль маркера трасування. Під час роботи `set -x` кожен рядок трасування передується значенням `PS4`. Якщо перший символ `PS4` є плюсом `+`, оболонка автоматично дублює його відповідно до рівня вкладеності поточної підоболонки, що дозволяє візуально розрізняти команди головного процесу та вкладених блоків.

## Керівні послідовності Bash у рядках запрошення

Під час формування значення змінних `PS1`, `PS2` та `PS4` командний інтерпретатор GNU Bash здійснює розгортання спеціальних послідовностей, що починаються із символу зворотного слеша `\`.

| Послідовність | Опис розгортання | Системне джерело / Приклад результату |
|---|---|---|
| `\u` | Ім'я поточного користувача | Виклик `getpwuid(geteuid())` -> `alex` |
| `\h` | Коротке ім'я хоста до першої крапки `.` | Виклик `gethostname()` -> `srv-prod` |
| `\H` | Повне доменне ім'я хоста (FQDN) | Виклик `gethostname()` -> `srv-prod.dc1.internal` |
| `\w` | Повний поточний робочий каталог із заміною `$HOME` на `~` | Виклик `getcwd()` або читання `$PWD` -> `~/projects/courses` |
| `\W` | Базове ім'я поточного робочого каталогу (basename) | Остання ланка шляху (для кореня `/` або `~`) -> `courses` |
| `\$` | Символ `#`, якщо ефективний UID дорівнює `0` (`root`), або `$` для інших | Перевірка `geteuid() == 0` -> `$` або `#` |
| `\!` | Номер поточної команди в історії команд | Лічильник внутрішньої історії `history_number` -> `1042` |
| `\#` | Порядковий номер команди в поточному сеансі оболонки | Лічильник команд поточної сесії -> `42` |
| `\j` | Кількість завдань, керованих оболонкою в даний момент | Кількість елементів у таблиці завдань (`jobs -p`) -> `2` |
| `\l` | Базове ім'я термінального пристрою введення | Наприклад, `pts/3` або `tty1` (відкидає префікс `/dev/`) |
| `\s` | Назва виконуваного файлу оболонки | Значення `basename($0)` -> `bash` |
| `\v` | Версія GNU Bash у скороченому форматі | Наприклад, `5.2` |
| `\V` | Повна версія GNU Bash із рівнем латок (patchlevel) | Наприклад, `5.2.21(1)-release` |
| `\d` | Дата у форматі «День_тижня Місяць Число» | Англійською: `Tue Aug 25` |
| `\t` | Поточний час у 24-годинному форматі `ГГ:ХХ:СС` | Наприклад, `14:30:15` |
| `\T` | Поточний час у 12-годинному форматі `ГГ:ХХ:СС` | Наприклад, `02:30:15` |
| `\@` | Поточний час у 12-годинному форматі `ГГ:ХХ am/pm` | Наприклад, `02:30 pm` |
| `\A` | Поточний час у 24-годинному форматі `ГГ:ХХ` | Наприклад, `14:30` |
| `\D{format}` | Дата і час згідно з форматом POSIX `strftime(3)` | Наприклад, `\D{%Y-%m-%d %H:%M:%S}` -> `2026-08-25 14:30:15` |
| `\n` | Символ переходу на новий рядок (LF, `0x0A`) | Створює багаторядковий промпт |
| `\r` | Символ повернення каретки (CR, `0x0D`) | Переміщує курсор у початок рядка |
| `\e` або `\033` | Керівний символ Escape (ESC, `0x1B`) | Початок керівних послідовностей ANSI CSI |
| `\a` | Символ звукового сигналу / дзвінка (BEL, `0x07`) | Подача звукового сигналу або завершення послідовності OSC |
| `\\` | Літеральний символ зворотного слеша | Виводить `\` |
| `\[` | Початок послідовності недрукованих символів | Маркер для GNU Readline: нульова ширина на екрані (`0x01`) |
| `\]` | Кінець послідовності недрукованих символів | Маркер для GNU Readline: відновлення підрахунку ширини (`0x02`) |

### Внутрішні механізми розгортання бекслеш-символів

Розгортання бекслеш-послідовностей реалізовано у вихідному коді Bash всередині функції `decode_prompt_char()`. На відміну від запуску зовнішніх програм або функцій, обробка кожного символу виконується як пряма операція над пам'яттю.

Для послідовності `\u` інтерпретатор звертається до кешованого значення структури `passwd`, отриманої під час старту через системну функцію `getpwuid()`. Якщо користувач увійшов під обліковим записом `root` або підвищив привілеї через `setuid`, `\u` негайно відобразить актуальне ім'я суперкористувача.

Для послідовностей `\w` та `\W` оболонка виконує нормалізацію рядка шляху. Вона порівнює початкові байти поточного робочого каталогу з вмістом змінної `$HOME`. Якщо збіг знайдено, префікс замінюється символом тільди `~`. Якщо активовано змінну `PROMPT_DIRTRIM`, внутрішній алгоритм сканує шлях праворуч наліво, відраховує задану кількість косих рис `/` і відсікає всі проміжні сегменти, підставляючи трикрапку.

## Маркери недрукованих послідовностей Readline

Бібліотека GNU Readline використовує спеціальні однобайтові маркери для розмежування видимих символів тексту та невидимих керуючих байтів термінала.

:::tabs
@tab C
```c
/* Константи заголовочного файлу <readline/readline.h> */
#define RL_PROMPT_START_IGNORE  '\001'  /* Байт 0x01 (SOH) - відповідає \[ у Bash */
#define RL_PROMPT_END_IGNORE    '\002'  /* Байт 0x02 (STX) - відповідає \] у Bash */
```
@tab C++
```cpp
#include <string_view>

// Константи протоколу GNU Readline для маркування недрукованих керівних послідовностей
namespace readline {
    inline constexpr char prompt_start_ignore = '\001'; // Відповідає \[ у Bash
    inline constexpr char prompt_end_ignore   = '\002'; // Відповідає \] у Bash
    inline constexpr std::string_view prompt_start_ignore_sv{"\001", 1};
    inline constexpr std::string_view prompt_end_ignore_sv{"\002", 1};
}
```
:::

Коли Bash обробляє рядок `PS1`, він замінює кожне входження `\[` на байт `\001`, а кожне входження `\]` на байт `\002`. Функція `rl_expand_prompt()` парсить цей потік байтів, тимчасово вилучаючи всі байти між `\001` і `\002` під час розрахунку змінних `prompt_visible_length` та `prompt_physical_chars`. Це гарантує, що розрахунок меж рядків у терміналі буде математично точним.

### Особливості розширеної колірної палітри 256 та 24-біт TrueColor

Стандарт ANSI CSI SGR дозволяє керувати не лише базовими 8 або 16 кольорами, але й розширеними колірними просторами. Формат `38;5;N` задає колір символів із таблиці 256 кольорів xterm, де значення від 0 до 15 відповідають стандартним системним відтінкам, від 16 до 231 формують тривимірний колірний куб 6x6x6, а значення від 232 до 255 задають 24 градації сірого кольору.

Формат `38;2;R;G;B` забезпечує пряму передачу 24-бітного значення RGB, дозволяючи відображати понад 16 мільйонів колірних відтінків. Більшість сучасних графічних терміналів (Alacritty, Kitty, WezTerm, iTerm2, GNOME Terminal) повністю підтримують TrueColor, проте для сумісності зі старими терміналами рекомендується перевіряти наявність змінної середовища `COLORTERM=truecolor` або `COLORTERM=24bit`.

## Зіставлення поведінки в POSIX sh, Bash та Zsh

Різні командні оболонки суттєво відрізняються за рівнем підтримки керуючих послідовностей та механізмами розширення рядків запрошення.

| Можливість | POSIX sh (dash, busybox sh) | GNU Bash | Zsh |
|---|---|---|---|
| Змінні запрошення | Лише `PS1`, `PS2`, `PS4` | `PS1`, `PS2`, `PS3`, `PS4` | `PROMPT` / `PS1`, `PROMPT2` / `PS2`, `PROMPT3` / `PS3`, `PROMPT4` / `PS4`, `RPROMPT` / `RPS1` |
| Праве запрошення | Відсутнє | Відсутнє (можливе лише через складні трюки з `tput` та `\r`) | Нативна підтримка змінної `RPROMPT` |
| Розгортання параметрів | Лише `$VAR`, `${VAR}` та `$(cmd)` | Бекслеш-коди (`\u`, `\w`) + розширення параметрів | Специфікатори з відсотком (`%n`, `%~`, `%#`) |
| Ім'я користувача | Немає послідовності (використовують `$USER` або `$(whoami)`) | `\u` | `%n` |
| Робочий каталог | Немає послідовності (використовують `$PWD` або `$(pwd)`) | `\w` (повний), `\W` (базовий) | `%~` (з `~`), `%d` (абсолютний), `%1~` (останній сегмент) |
| Символ привілеїв | Немає послідовності (вимагає ручної перевірки `$UID` або `id -u`) | `\$` (`#` для root, `$` для користувача) | `%#` (`#` для root, `%` для користувача) |
| Маркери невидимих байтів | Не підтримуються (немає Readline) | `\[` та `\]` | `%{` та `%}` або атрибути `%F{color}...%f` |
| Передвиконавчий хук | Відсутній | `PROMPT_COMMAND` (рядок або масив) | Функція-хук `precmd()` або масив `precmd_functions` |
| Трасування `PS4` | Виводить `$PS4` перед командою (дефолт: `+ `) | Розгортає `\w`, `$LINENO`, `$BASH_SOURCE`, `$FUNCNAME` | Розгортає `%N` (файл), `%i` (рядок), `%_` (блок коду) |

### Специфіка стандарту POSIX та переносність

Стандарт POSIX.1-2017 (IEEE Std 1003.1) вимагає підтримки лише змінних `PS1`, `PS2` та `PS4`. У стандартній оболонці POSIX (наприклад, `dash` у дистрибутивах Debian/Ubuntu або `sh` у FreeBSD) бекслеш-послідовності не розгортаються. Будь-який зворотний слеш виводиться буквально, або призводить до синтаксичної помилки.

Для створення переносного промпту, який працюватиме в суто POSIX-сумісних оболонках, розробники використовують динамічне розгортання стандартних змінних середовища:

```sh
# Переносний POSIX-промпт без використання розширень Bash
USER_NAME="${USER:-$(id -un 2>/dev/null || echo user)}"
PS1='${USER_NAME}@$(uname -n):${PWD} $ '
```

Такий підхід гарантує працездатність у мінімалістичних середовищах відновлення (rescue mode), образах initramfs та вбудованих системах на базі BusyBox.

## Спеціальні послідовності трасування для PS4 у Bash

Змінна `PS4` використовується для діагностики сценаріїв при виклику `set -x` або запуску `bash -x script.sh`. У ній доступні системні змінні середовища Bash:

```bash
# Розширене форматування PS4 для професійного налагодження:
export PS4='+ [${BASH_SOURCE[0]##*/}:${LINENO}] ${FUNCNAME[0]:+${FUNCNAME[0]}(): }'
```

- `${BASH_SOURCE[0]##*/}` — ім'я поточного файлу сценарію без повного шляху;
- `${LINENO}` — номер поточного виконуваного рядка в коді;
- `${FUNCNAME[0]}` — ім'я поточної функції (якщо команда виконується всередині функції);
- Перший символ `+` у `PS4` автоматично повторюється оболонкою відповідно до рівня вкладеності підоболонок (`$SHLVL` або `subshell level`).
