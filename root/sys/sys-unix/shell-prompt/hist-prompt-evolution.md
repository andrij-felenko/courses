# 📜 Еволюція командного запрошення в Unix: від % до асинхронних генераторів

У перших версіях Unix на телетайпах Teletype Model 33 кожен надрукований символ коштував механічного ресурсу та часу передачі на швидкості 110 бод, тому командне запрошення складалося з єдиного символу `%` або `@`. З переходом на відеотермінали, появою розгалужених файлових систем, систем контролю версій та контейнеризації коротке запрошення еволюціонувало від статичного префікса до складної динамічної підсистеми з власними мовами форматування, асинхронними процесами та скомпільованими бінарними генераторами.

## Епоха телетайпів і Thompson Shell (1971)

У найперших версіях Research Unix для PDP-11 командний інтерпретатор Кема Томпсона (`/bin/sh`, відомий як Thompson shell) не мав жодної конфігурації інтерфейсу. Термінал користувача був електромеханічним телетайпом, де виведення тексту фізично вибивалося молоточками по паперовій стрічці. У цих умовах будь-яке зайве слово в інтерфейсі створювало акустичний шум, витрачало папір і сповільнювало роботу.

Запрошенням за замовчуванням у Thompson shell був одиничний символ `%` для звичайного користувача та `#` для системного адміністратора (користувача `root`). Оболонка не надавала змінних для зміни цього символу: код виводу запрошення містив жорстко зашитий системний виклик `write(2, "% ", 2)`. Якщо користувач переходив у підкаталог за допомогою команди `chdir`, оболонка ніяк не відображала поточне розташування — дізнатися свій каталог можна було лише явним викликом зовнішньої утиліти `pwd`.

Символ `#` для суперкористувача було обрано через його візуальну вагу: він сигналізував про роботу з найвищими привілеями, де помилка в команді могла призвести до незворотного пошкодження файлової системи. Ця домовленість стала фундаментальним стандартом Unix, який зберігся в усіх наступних оболонках.

## Bourne Shell та народження ієрархії PS1/PS2 (1979)

У сьомій редакції Research Unix (Version 7 Unix) Стівен Борн представив повністю переписану оболонку — Bourne shell (`sh`). Вона принесла повноцінну мову програмування зі змінними, циклами та функціями, а також вперше ввела параметризовані змінні запрошення: `PS1` (Prompt String 1) та `PS2` (Prompt String 2).

Борн розділив введення на два концептуальні стани:
- `PS1` виводився, коли оболонка перебувала у стані готовності до прийому нового первинного виразу (за замовчуванням `$ ` для користувача і `# ` для `root`).
- `PS2` виводився, коли введений рядок був синтаксично незавершеним — наприклад, користувач відкрив лапку, не закрив блок `if ... then`, або поставив зворотний слеш `\` наприкінці рядка для продовження (за замовчуванням `> `).

У Bourne shell значення `PS1` та `PS2` були статичними рядками. Якщо користувач записував `PS1="myhost$ "`, оболонка буквально виводила цей текст. Механізму автоматичної підстановки імені комп'ютера чи поточного каталогу всередині `PS1` не існувало, оскільки оболонка не здійснювала параметричного розкриття над рядком запрошення під час кожного виводу.

## C Shell та інтерактивна революція Білла Джоя (1978–1980-ті)

У середовищі BSD Білл Джой створив C Shell (`csh`), орієнтований саме на зручність щоденної інтерактивної роботи людини за терміналом. На відміну від мінімалістичного Bourne shell, `csh` запропонував історію команд та механізм швидких підстановок через знак оклику `!`.

Для підтримки цієї функціональності Джой ввів спеціальні керуючі послідовності в змінну `prompt`:
- `!`: автоматично підставляв номер поточної команди в історії. Завдяки цьому користувач міг бачити `[42] %` і швидко повторювати попередні команди за допомогою конструкцій на кшталт `!40` або `!-2`.
- `%/` або `$cwd`: відображали поточний робочий каталог.
- `%m`: відображав коротке ім'я вузла (hostname).

Це був перший крок до перетворення запрошення на джерело системного контексту. Проте в `csh` розширення запрошення здійснювалося спеціальним внутрішнім кодом парсера, а не загальним механізмом змінних, що створювало труднощі для тонкого налаштування.

## Korn Shell і динамічне виконання (1983)

Девід Корн в AT&T Bell Labs розробив Korn shell (`ksh`), поєднавши сумісність із синтаксисом Bourne shell та інтерактивні можливості `csh`. Корн здійснив архітектурний прорив: він зробив так, що рядок `PS1` перед виведенням на екран проходив стандартну фазу підстановки параметрів, арифметичних операцій та підстановки команд (`parameter expansion`, `command substitution`).

Це дозволило вбудовувати в запрошення системні змінні:
```ksh
PS1='$PWD $ '
```
Оскільки змінна `$PWD` автоматично оновлювалася вбудованою командою `cd`, користувачі `ksh` вперше отримали динамічний шлях у запрошенні без запуску зовнішніх процесів.

Крім того, Корн додав змінні `PS3` (запрошення для циклу створення інтерактивних текстових меню `select`) та `PS4` (префікс для трасування виконання сценаріїв при увімкненому режимі `set -x`). Завдяки цьому діагностика сценаріїв отримала структуроване візуальне виділення.

## GNU Bash та керування бібліотекою Readline (1989–2000-ні)

Браян Фокс та Чет Рамі в рамках проекту GNU створили Bash (Bourne Again Shell), інтегрувавши в нього бібліотеку редагування командного рядка GNU Readline. Це породило як широкі можливості форматування, так і нові інженерні проблеми розрахунку позиції курсора.

Bash стандартизував багатий набір бекслеш-послідовностей:
- `\u` — ім'я поточного користувача через `getpwuid(geteuid())`;
- `\h` / `\H` — коротке та повне ім'я вузла через `gethostname()`;
- `\w` / `\W` — повний робочий каталог із заміною домашньої теки на `~` або лише базова назва каталогу;
- `\t`, `\T`, `\@`, `\d` — різні формати поточного системного часу.

З масовим поширенням кольорових емуляторів терміналів стандарту ANSI (VT100, xterm) розробники почали розфарбовувати запрошення за допомогою керуючих кодів `\033[32m` (зелений колір) або `\033[1;31m` (жирний червоний). Це негайно призвело до критичного бага: бібліотека Readline рахувала байти ANSI-кодів як реальні друковані символи на екрані. Коли користувач викликав довгу команду з історії або натискав `Backspace`, курсор перескакував у неправильні позиції, а текст накладався сам на себе.

Для вирішення цієї проблеми Чет Рамі ввів спеціальні маркери:
- `\[` (байт `0x01` у внутрішньому представленні Readline `RL_PROMPT_START_IGNORE`);
- `\]` (байт `0x02` у внутрішньому представленні Readline `RL_PROMPT_END_IGNORE`).

Readline фільтрував послідовності між цими маркерами під час розрахунку видимих знакомісць, передаючи самі байти на термінал без спотворень.

Також у Bash 2.0 було впроваджено змінну `PROMPT_COMMAND` — команду або функцію, яку оболонка виконує перед кожним виведенням `PS1`. Це відкрило шлях до складних обчислень системного стану безпосередньо перед відображенням запрошення.

## Zsh: двосторонній вивід та асинхронні воркери (1990–2010-ті)

Пауль Фальстад створив Zsh, запропонувавши фундаментально нову концепцію — двостороннє запрошення `PROMPT` (ліворуч) та `RPROMPT` (праворуч). Правий промпт автоматично зникав, коли введення користувача наближалося до правого краю вікна, що дозволило виносити другорядну інформацію (час виконання, системний час, код виходу) за межі основного робочого простору.

З поширенням Git на початку 2010-х стандартним очікуванням інженера стало відображення поточної гілки та стану робочого дерева (`dirty`/`clean`) прямо в запрошенні. Проте виконання команди `git status` у великих репозиторіях (з сотнями тисяч файлів або на мережевих NFS-дисках) займало від кількох сотень мілісекунд до десятків секунд. Якщо цей виклик стояв у `PROMPT_COMMAND` або розширенні `PS1`, оболонка зависала на кожне натискання клавіші `Enter`.

Спільнота Zsh вирішила цю проблему за допомогою модуля `zsh/zpty` та асинхронних фонових воркерів (бібліотека `zsh-async`, тема `Pure`, рушій `Powerlevel10k`). Оболонка миттєво відмальовувала базове запрошення, паралельно запускала фоновий процес опитування файлової системи через `fork()`, і після отримання сигналу `SIGUSR1` або готовності дескриптора каналу безшовно домальовувала статус Git за допомогою перемальовування через ZLE (Zsh Line Editor).

## Сучасність: компільовані генератори та протоколи терміналів (2020-ті)

Спроби перетворити сценарії налаштування оболонки на монструозні фреймворки (Oh-My-Bash, Oh-My-Zsh) призвели до «кризи затримок»: час запуску оболонки та відмальовки промпту досягав 200–500 мс, що сприймалося людиною як суттєве гальмування.

Сучасним стандартом стали скомпільовані бінарні генератори, написані на системних мовах програмування:
- **Starship** (мова Rust): один бінарний файл, що зчитує системні змінні, файли оточення (`.git/HEAD`, `Cargo.toml`, `pyproject.toml`, `package.json`) та конфігурацію, віддаючи готовий розфарбований рядок промпту за 2–5 мілісекунд.
- **Powerlevel10k** (мова C + Zsh bytecode): кешує стан git-статусу у пам'яті демона та здійснює миттєвий асинхронний рендеринг.

Крім того, сучасні емулятори терміналів (Alacritty, Kitty, WezTerm, iTerm2, Windows Terminal) інтегрували протокол інтеграції з оболонкою (OSC 133 / FinalTerm Protocol). За допомогою спеціальних послідовностей у промпті (`OSC 133 ; A ST` — початок промпту, `OSC 133 ; B ST` — початок команди, `OSC 133 ; D ; <code > ST` — код завершення) термінал точно знає, де закінчується системне запрошення і починається вивід програми. Це дозволяє здійснювати швидку навігацію між виконаними командами, копіювати вивід окремої команди в буфер обміну та автоматично підсвічувати невдалі виклики в інтерфейсі термінала.
