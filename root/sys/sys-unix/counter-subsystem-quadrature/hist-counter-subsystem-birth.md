# 📜 Історія створення підсистеми Counter у ядрі Linux

Підсистема лічильників ядра Linux пройшла шлях від роззосередженого хаосу в підсистемах Industrial I/O (IIO) та input до створення впорядкованого фреймворку, здатного працювати із сучасними високошвидкісними робототехнічними комплексами.

## Проблема роздрібнених драйверів (до 2018 року)

До появи підсистеми Counter у ядрі Linux не існувало єдиного місця для драйверів апаратних лічильників імпульсів, таймерних накопичувачів та квадратурних енкодерів. Інженери, які розробляли драйвери для спецпроцесорів або SoC (наприклад, STM32, TI AM335x, Intel Quadrature Counter, Microchip Flexcom), були змушені обирати між кількома невідповідними підсистемами:

1. **Підсистема Industrial I/O (IIO)**: призначена першочергово для аналогово-цифрових перетворювачів (АЦП), цифро-аналогових перетворювачів (ЦАП), акселерометрів та датчиків температури. IIO моделює дані як безперервний потік вибірок аналогових величин у фізичних одиницях (вольти, паскалі, g). Квадратурний енкодер у IIO виглядав як "канал позиції", але IIO не мав абстракцій для синаптичного зв'язку фаз A/B, індексного скидання (Index Z) чи апаратних функцій X1/X2/X4.
2. **Підсистема введення (Input Subsystem)**: розроблена для клавіатур, мишей та джойстиків. Деякі драйвери енкодерів реєструвалися як пристрої `evdev` й генерували події `REL_WHEEL` або `REL_DIAL` при кожному кліку енкодера. Це працювало для коліщатка миші або ручки гучності аудіоплеєра, але при обертанні промислового мотора зі швидкістю 5000 обертів на хвилину підсистема `input` заповнювала чергу мільйонами подій, перевантажуючи демон `udev` та систему обробки подій X11/Wayland.
3. **Власні символьні пристрої (`drivers/misc/`)**: розробники створювали приватні драйвери з унікальним набором системних викликів `ioctl` та власними структурами у `/sys/internal/`. Це унеможливлювало створення універсального ПЗ для промислової автоматизації: кожен новий контролер вимагав переписування користувацького коду.

## Поява Counter Subsystem у ядрі Linux 5.2

У 2018 році розробник Вільям Брейтіт Ґрей (William Breathitt Gray) запропонував концептуально нову архітектуру. Замість спроб втиснути лічильники в існуючі підсистеми, він спроектував граф-подібну модель, яка описує апаратні лічильники через чіткі фізичні та логічні компоненти: `Signal` (вхідний електричний сигнал), `Synapse` (зв'язок сигналу з лічильником), `Count` (акумулятор значень), `Function` (математичний режим декодування) та `Extension` (додаткові налаштування пристрою).

Перші серії патчів викликали бурхливе обговорення у поштовій розсилці `linux-kernel`. Спільнота розробників ядра спочатку вагалася, чи потрібна окрема підсистема для порівняно вузького класу пристроїв. Однак Вільям Брейтіт Ґрей надав переконливі докази: поява тисяч робототехнічних систем на базі Linux, маніпуляторів ЧПУ та безпілотних апаратів вимагала єдиного стандартного драйверного контракту.

Після кількох ітерацій рецензування підсистему **Counter Subsystem** було офіційно включено до основного дерева ядра Linux у версії **5.2** (липень 2019 року).

## Велике переписання та події високої швидкості у ядрі 5.15

Початкова реалізація Counter subsystem спиралася виключно на текстовий інтерфейс `sysfs`. Користувацькі програми читали позицію енкодера через файли `/sys/bus/counter/devices/counterX/countY/count`.

Для базових задач (наприклад, підрахунок літрів води у лічильнику витрати) читання через sysfs було достатнім. Однак для систем керування рухом у реальному часі виявилися серйозні обмеження:

- **Форматування тексту**: конвертація бінарних 64-бітних регістрів у ASCII-рядки в ядрі та зворотний парсинг `strtoull()` у просторі користувача створювали марне навантаження на ЦПУ.
- **Відсутність міток часу**: при опитуванні sysfs програма не знала точного моменту часу, коли саме лічильник досяг певного значення або коли відбулося скидання по індексному каналу Z.
- **Низька швидкість подій**: sysfs не давав змоги ефективно чекати на події переповнення (overflow) або зміни напрямку обертання через виклики `poll()`.

У ядрі **Linux 5.15** (листопад 2021 року) Вільям Брейтіт Ґрей здійснив масштабну реструктуризацію підсистеми. У ядро було додано символьний пристрій `/dev/counterX` та бінарний ABI подій (Counter Events). Завдяки кільцевому буферу подій у ядрі та структурі `counter_event` із 64-бітною міткою часу `CLOCK_MONOTONIC`, користувацький простір отримав можливість підписуватися на апаратні події з наносекундною точністю та мінімальними накладними витратами.
