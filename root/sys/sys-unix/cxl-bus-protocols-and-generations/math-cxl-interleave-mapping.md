# 🧮 Математична модель інтерлівінгу та затримок CXL

Математична модель міжз'єднання CXL охоплює два ключові аспекти: апаратний перерахунок системних фізичних адрес (System Physical Address, SPA) у фізичні адреси пристрою (Device Physical Address, DPA) через механізм чергування (interleaving) та ймовірнісну модель затримок доступу при комутації пам'яті.

## 1. Математика апаратного інтерлівінгу (HDM Interleaving)

Для досягнення максимальної пропускної здатності хост-контролер пам'яті CXL об'єднує декілька контролерів (Root Ports) або пристроїв пам'яті (Type 3 Endpoints) у єдиний неперервний адресний простір — CXL Region. Базовою одиницею стрибка є гранулярність інтерлівінгу (Interleave Granularity, `G`), яка в специфікаціях CXL може становити 256 байтів, 512 байтів, 1 KB, 2 KB, 4 KB, 8 KB або 16 KB.

Нехай задано такі змінні:
- `SPA` — системна фізична адреса (64-бітне ціле число);
- `N` — кількість каналів чергування (`N ∈ {1, 2, 3, 4, 6, 8, 12, 16}`);
- `G` — розмір стрибка в байтах (`G = 2ᵍ`, наприклад, для `G = 256 B` маємо `g = 8`);
- `Target_Index` — індекс вихідного порту або пристрою, куди спрямовується транзакція.

### Покрокове математичне виведення target-індексу для канонічного випадку (N = 2ⁿ)

У канонічному випадку, коли кількість цільових пристроїв є степенем двійки (`N = 2ⁿ`), номер цільового порту визначається витягуванням бітів адреси безпосередньо над границею гранулярності.

Математична послідовність дій та виведення:

```
SPA_block
= SPA >> g                            [Крок 1: усунення молодших бітів всередині блока]

Target_Index 
= SPA_block mod N                     [Крок 2: обчислення залишкового індексу за модулем N]
= (SPA >> g) mod N                    [підстановка SPA_block]
= (SPA >> g) & (N - 1)                [Крок 3: апаратна оптимізація при N = 2ⁿ через побітове AND]
```

Адреса в межах конкретного пристрою (DPA) розраховується шляхом вилучення інтерлівованих бітів і зміщення залишку старших бітів праворуч на `n` позицій:

```
Offset_in_block
= SPA & (G - 1)                       [Крок 1: збереження внутрішнього зсуву у блоці]

High_address_shifted
= SPA >> (g + n)                      [Крок 2: зсув старшої частини адреси над бітами інтерлівінгу]

DPA_Offset
= Offset_in_block + (High_address_shifted << g)   [Крок 3: збирання підсумкової адреси DPA]
= (SPA & (G - 1)) + ((SPA >> (g + n)) << g)       [підстановка виразів]
```

### Спеціальний випадок інтерлівінгу для не-двійкової кількості каналів (N = 3, 6, 12)

У специфікації CXL 3.0 впроваджено підтримку не-двійкового чергування на 3, 6 та 12 каналів для оптимального використання триканальних контролерів пам'яті DRAM у сучасних процесорах.

Оскільки для `N = 3` операція побітового `AND` неможлива, апаратний декодер застосовує оптимізоване множення на фіксовану зворотну величину (Reciprocal Multiplication):

```
Target_Index_3
= (SPA >> g) - 3 · ((SPA >> g) · M >> 32)   [де M = 0x55555556 — константа ділення на 3]
```

### Докладний чисельний приклад розрахунку

Розглянемо систему із чотирма розширювачами пам'яті CXL Type 3 (`N = 4`, тобто `n = 2`). Задано гранулярність інтерлівінгу `G = 256` байтів (`g = 8`). Процесор виконує читання за системною фізичною адресою `SPA = 0x100045A0`.

Переведемо системну адресу у двійкову форму:
`SPA = 0001 0000 0000 0000 0100 0101 1010 0000₂`

Виконаємо розрахунок target-індексу та DPA-зсуву за кроками у код-блоці:

```
SPA >> 8
= 0x100045                            [вилучено 8 молодших бітів 0xA0]

Target_Index
= 0x100045 & (4 - 1)
= 0x100045 & 0x3
= 1                                   [транзакція спрямовується на ціль з індексом 1]

High_address_shifted
= 0x100045A0 >> (8 + 2)
= 0x40011                             [зсув старшої частини]

DPA_Offset
= (0x100045A0 & 0xFF) + (0x40011 << 8)
= 0xA0 + 0x4001100
= 0x40011A0                           [локальний зсув на пристрої DPA]
```

У результаті транзакція читання з адресою `0x100045A0` буде перенаправлена на пристрій з індексом 1 (другий за порядком у списку цілей) за локальним зсувом `0x40011A0`.

### XOR-інтерлівінг для запобігання конфліктам банків памʼяті (CXL 3.0)

У складних багатопроцесорних системах при виконанні алгоритмів векторного множення матриць або обробки зображень звернення до пам'яті часто відбуваються з постійним кроком (Stride), кратним степеню двійки (наприклад, 4 KB або 64 KB). При класичному лінійному мапуванні це призводить до того, що всі транзакції потрапляють на один і той самий контролер, створюючи затор.

Для розв'язання цієї проблеми в CXL 3.0 впроваджено XOR-побітове змішування вищих бітів адреси:

```
High_bits
= SPA >> (g + n)                      [визначення XOR маски з вищих бітів адреси]

Target_Index_XOR
= ((SPA >> g) ^ High_bits) & (N - 1)  [обчислення індексу з використанням операції XOR]
```

Завдяки операції XOR сусідні рядки матриць псевдовипадково розподіляються по різних вихідних портах, гарантуючи рівномірне навантаження шини.

## 2. Ймовірнісна модель затримок доступу та черг (M/D/1 Queueing Model)

Загальна затримка доступу процесора до CXL-пам'яті у складній комутованій топології (Switched Fabric) є випадковою величиною, яка складається з фіксованого апаратного часу проходження сигналів та змінного часу очікування в чергах арбітражу.

### Рівняння балансу затримок

```
Latency_total
= Latency_core + Latency_root_port + Latency_phy + Latency_switch + Latency_media + W_queue [сума складових]
```

Компоненти затримки:
- `Latency_core`: час генерації інструкції та пошуку в кеші L3 CPU (~15–20 нс).
- `Latency_root_port`: затримка упаковки в CXL Flit на Root Port (~25–30 нс).
- `Latency_phy`: фізична затримка трансиверів SerDes PCIe 5.0/6.0 (~15–20 нс).
- `Latency_switch`: затримка комутації CXL Switch (~70–100 нс).
- `Latency_media`: затримка контролера пристрою та вибірки з осередків DRAM (~50–60 нс).
- `W_queue`: середня затримка в черзі арбітра ARB/MUX.

### Обчислення затримки черги за моделлю M/D/1

Арбітр ARB/MUX на CXL-комутаторі обробляє пакети фіксованого розміру (Flit size = 68B у CXL 2.0 або 256B у CXL 3.0). Це дозволяє застосувати модель теорії масового обслуговування `M/D/1` (Пуассонівський вхідний потік запитів, детермінований час обслуговування, один канал):

```
ρ
= λ / μ                               [коефіцієнт завантаження лінку ρ]

W_queue
= ρ / (2 · μ · (1 - ρ))                [середня затримка очікування в черзі W_queue]
```

Де:
- `λ` — інтенсивність надходження запитів читання/запису від процесорів (пакетів/нс);
- `μ` — максимальна пропускна здатність ARB/MUX шини (пакетів/нс);
- `ρ` — коефіцієнт утилізації шини (`0 ≤ ρ < 1`).

Аналіз залежності затримки від навантаження:
- При низькому навантаженні (`ρ = 0.2` або 20%): `W_queue = 0.2 / (2 · μ · 0.8) = 0.125 / μ` (затримка мінімальна).
- При середньому навантаженні (`ρ = 0.5` або 50%): `W_queue = 0.5 / (2 · μ · 0.5) = 0.5 / μ`.
- При високому навантаженні (`ρ = 0.9` або 90%): `W_queue = 0.9 / (2 · μ · 0.1) = 4.5 / μ` (зростання у 36 разів порівняно з ρ=0.2!).

Математична модель показує, що при наближенні завантаження лінку CXL до 90% затримка в черзі стає панівною складовою, перевищуючи апаратну затримку DRAM. Саме тому в специфікації CXL 2.0+ впроваджено апаратні телеметричні лічильники QoS (Quality of Service) для динамічного обмеження пропускної здатності (Throttling) некритичних потоків даних.
