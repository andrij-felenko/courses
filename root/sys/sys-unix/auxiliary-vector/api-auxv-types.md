# 📋 Довідник типів та ключів допоміжного вектора ELF (AT_*)

Цей довідник надає вичерпну специфікацію бінарних структур даних `Elf32_auxv_t` та `Elf64_auxv_t`, числових констант `AT_*` (Auxiliary Type), розшифровку масок апаратних можливостей процесора (`AT_HWCAP`, `AT_HWCAP2`), а також специфіку системних C/C++ API (`getauxval`, `getauxval2`) та бінарного псевдофайла `/proc/<pid>/auxv` у середовищах Linux та POSIX-подібних операційних систем.

---

## 1. Бінарне представлення та геометрія записів

Допоміжний вектор передається ядром операційної системи як послідовний масив структур фіксованого розміру у пам'яті стека процесу. У залежності від розрядності цільової архітектури використовуються відповідні визначення типів із системного заголовного файла `<elf.h>` або `<sys/auxv.h>`.

### Структура `Elf32_auxv_t` (32-бітні системи)

Розмір одного запису становить 8 байтів (4 байти на тип і 4 байти на значення або вказівник). Записи у масиві розташовані послідовно без проміжних байтів вирівнювання.

```c
typedef struct {
    uint32_t a_type;              /* Числовий ідентифікатор типу запису (ключ AT_*) */
    union {
        uint32_t a_val;           /* Цілочисельне значення або маска прапорців */
        void    *a_ptr;           /* 32-бітний віртуальний вказівник у пам'яті */
        void  (*a_fcn)(void);     /* Вказівник на функціональний елемент */
    } a_un;
} Elf32_auxv_t;
```

### Структура `Elf64_auxv_t` (64-бітні системи)

Розмір одного запису становить 16 байтів. Перші 8 байтів займає 64-бітне ціле число `a_type`, наступні 8 байтів — об'єднання `a_un` (`a_val` або `a_ptr`). Вирівнювання структури у пам'яті становить 8 байтів.

```c
typedef struct {
    uint64_t a_type;              /* Числовий ідентифікатор типу запису (ключ AT_*) */
    union {
        uint64_t a_val;           /* 64-бітне цілочисельне значення або маска */
        void    *a_ptr;           /* 64-бітний віртуальний вказівник у пам'яті */
        void  (*a_fcn)(void);     /* Вказівник на функціональний елемент */
    } a_un;
} Elf64_auxv_t;
```

## 2. Повна специфікація констант векторів (`AT_*`)

Нижче наведено вичерпний опис усіх стандартизованих типів допоміжного вектора на основі заголовкових файлів ядра Linux `<uapi/linux/auxvec.h>` та специфікацій System V ELF ABI.

### `AT_NULL` (Значення `0`)
Термінатор масиву. Вказує на кінець допоміжного вектора. Зчитування вектора лінкером або рантаймом зупиняється на першому записі з `a_type == 0`. Поле `a_val` у цьому записі також дорівнює `0`.

### `AT_IGNORE` (Значення `1`)
Пропущений або недійсний запис. Використовується ядром або динамічним завантажувачем для нейтралізації елемента вектора у пам'яті без потреби виконання дорогої операції зсуву всього масиву.

### `AT_EXECFD` (Значення `2`)
Файловий дескриптор відкритого виконуваного файла. Передається ядром у рідкісних випадках, коли виконуваний файл відкривається ядром до створення процесу (наприклад, при використанні бінарних інтерпретаторів `binfmt_misc`). Якщо файл завантажено звичайно через шлях, значення дорівнює `0`.

### `AT_PHDR` (Значення `3`)
Віртуальна адреса початку таблиці заголовків програми (`Program Header Table`, `Elf64_Phdr`) основного виконуваного файла у пам'яті. За цією адресою динамічний завантажувач `ld-linux.so` виявляє завантажені сегменти, шукає сегмент `PT_DYNAMIC`, таблиці релокацій та вимоги до залежних бібліотек (`DT_NEEDED`).

### `AT_PHENT` (Значення `4`)
Розмір одного запису в таблиці заголовків програми у байтах. Для 64-бітних ELF-файлів цей розмір становить 56 байтів (`sizeof(Elf64_Phdr)`), для 32-бітних — 32 байти (`sizeof(Elf32_Phdr)`).

### `AT_PHNUM` (Значення `5`)
Кількість елементів (сегментів) у таблиці заголовків програми. Дозволяє завантажувачу коректно обійти весь масив заголовків без виходу за його межі.

### `AT_PAGESZ` (Значення `6`)
Розмір системної сторінки віртуальної пам'яті у байтах. На архітектурах x86_64 та ARM64 стандартний розмір становить `4096` байтів (4 KiB), проте на деяких конфігураціях ARM64 чи PowerPC це значення може дорівнювати `16384` (16 KiB) або `65536` (64 KiB). Використовується менеджерами пам'яті (`malloc`, `mmap`) для вирівнювання блоків.

### `AT_BASE` (Значення `7`)
Базова віртуальна адреса завантаження інтерпретатора ELF (динамічного завантажувача `ld-linux.so`). Якщо програма є статично зкомпільованим бінарним файлом без динамічного лінкера, ядро записує сюди значення `0`.

### `AT_FLAGS` (Значення `8`)
Процесорні прапорці запуску. Історичний атрибут специфікації System V ABI. У сучасних версіях ядра Linux цей вектор майже завжди містить значення `0`.

### `AT_ENTRY` (Значення `9`)
Віртуальна адреса точці входу (`entry point`) основного виконуваного файла (початок функції `_start`). Для динамічно зв'язаних програм ядро передає керування динамічному лінкеру, і лінкер після завершення ініціалізації зчитує `AT_ENTRY` та здійснює безумовний перехід за цією адресою.

### `AT_NOTELF` (Значення `10`)
Ненульове значення, якщо виконуваний файл не відповідає формату ELF. Використовувалося під час перехідного періоду від формату `a.out` до `ELF`. У сучасних Linux-системах дорівнює `0`.

### `AT_UID` (Значення `11`)
Реальний ідентифікатор користувача (`Real UID`), який ініціював системний виклик `execve`.

### `AT_EUID` (Значення `12`)
Ефективний ідентифікатор користувача (`Effective UID`). Якщо виконуваний файл має біт `setuid`, значення `AT_EUID` відрізняється від `AT_UID` і відображає ID власника файла.

### `AT_GID` (Значення `13`)
Реальний ідентифікатор групи користувача (`Real GID`).

### `AT_EGID` (Значення `14`)
Ефективний ідентифікатор групи користувача (`Effective GID`). Відображає привілеї групи при активному біті `setgid`.

### `AT_PLATFORM` (Значення `15`)
Вказівник на рядок символів (ASCIIZ у інформаційному блоці на стеку), який описує назву апаратної платформи процесора (наприклад, `"x86_64"`, `"i686"`, `"aarch64"`).

### `AT_HWCAP` (Значення `16`)
Бітова маска апаратних можливостей процесора. Дозволяє системній бібліотеці визначити наявність векторних розширень та спеціалізованих інструкцій CPU.

### `AT_CLKTCK` (Значення `17`)
Частота системного таймера у системних тиках за секунду (зазвичай `100`). Використовується функцією `times(2)` та утилітами моніторингу процесів для перерахунку системного часу.

### `AT_FPUCW` (Значення `18`)
Початкове керуюче слово математичного співпроцесора FPU (x87 control word), встановлене ядром при старті процесу.

### `AT_DCACHEBSIZE` / `AT_ICACHEBSIZE` / `AT_UCACHEBSIZE` (Значення `19`, `20`, `21`)
Розміри рядків кеш-пам'яті L1 (кеш даних, кеш інструкцій та об'єднаний кеш) у байтах. Застосовуються на архітектурах PowerPC та ARM для оптимізації інструкцій очищення кешу.

### `AT_SECURE` (Значення `23`)
Прапорець захищеного режиму виконання. Ядро встановлює `AT_SECURE = 1`, якщо процес запущено привілейованим файлом (`setuid`/`setgid`) або файл має розширені атрибути `capabilities`. Динамічний лінкер, побачивши `AT_SECURE = 1`, повністю блокує виконання підтягування сторонніх бібліотек через змінні середовища `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`.

### `AT_BASE_PLATFORM` (Значення `24`)
Вказівник на рядок реальної базової платформи при використанні режимів емуляції або сумісності (наприклад, запуск 32-бітного бінарника на 64-бітному ядрі x86_64).

### `AT_RANDOM` (Значення `25`)
Вказівник на блок із 16 байтів якісних криптографічних випадкових даних, згенерованих ядром при виклику `execve`. Використовується glibc для ініціалізації **канарейок стека (`__stack_chk_guard`)** та захисту хеш-таблиць від атак типу Hash DoS.

### `AT_HWCAP2` (Значення `26`)
Друга 64-бітна маска розширених апаратних можливостей процесора для нових векторних наборів (наприклад, SVE2, BTI, MTE на ARM64).

### `AT_EXECFN` (Значення `31`)
Вказівник на рядок символів із шляхом до виконуваного файла, як він був переданий ядру при виклику `execve`.

### `AT_SYSINFO_EHDR` (Значення `33`)
Базова віртуальна адреса ELF-заголовка **vDSO (virtual dynamic shared object)** у пам'яті процесу. Дозволяє користувацькому простору виконувати швидкі системні виклики часу без перемикання контексту ядра.

### `AT_MINSIGSTKSZ` (Значення `51`)
Мінімальний необхідний розмір альтернативного стека сигналів (`sigaltstack`), розрахований ядром з урахуванням розміру векторних регістрів (AVX-512, SVE).

## 3. Деталізація бітів `AT_HWCAP` та `AT_HWCAP2`

Апаратні прапорці дозволяють високонавантаженим обчислювальним бібліотекам виявляти підтримувані розширення CPU під час виконання без виклику заборонених інструкцій.

### Архітектура x86_64 (`<asm/hwcap.h>`)

| Маска / Біт | Константа | Опис апаратного розширення |
| :--- | :--- | :--- |
| `1 << 0` | `HWCAP_X86_FPU` | Наявність математичного співпроцесора x87 |
| `1 << 4` | `HWCAP_X86_TSC` | Наявність лічильника тактів `RDTSC` |
| `1 << 23` | `HWCAP_X86_MMX` | Векторний набір інструкцій MMX |
| `1 << 25` | `HWCAP_X86_SSE` | Розширення Streaming SIMD Extensions (SSE) |
| `1 << 26` | `HWCAP_X86_SSE2` | Набір інструкцій SSE2 |
| `1 << 28` | `HWCAP_X86_HT` | Подвійна потоковість Hyper-Threading |

### Архітектура ARM64 / AArch64 (`<asm/hwcap.h>`)

На архітектурі ARM64 маски `AT_HWCAP` та `AT_HWCAP2` є основним безпечним інструментом визначення можливостей процесора.

#### `AT_HWCAP` (ARM64):
- `HWCAP_FP` (`1 << 0`): Апаратна плаваюча крапка (Floating Point).
- `HWCAP_ASIMD` (`1 << 1`): Розширений векторний набір Advanced SIMD (NEON).
- `HWCAP_AES` (`1 << 3`): Апаратне прискорення симетричного шифрування AES.
- `HWCAP_SHA1` (`1 << 5`) / `HWCAP_SHA2` (`1 << 6`): Інструкції прискорення хешування SHA.
- `HWCAP_CRC32` (`1 << 7`): Обчислення контрольних сум CRC32.
- `HWCAP_ATOMICS` (`1 << 8`): Атомарні інструкції LSE (`LDADD`, `CAS`).
- `HWCAP_SVE` (`1 << 22`): Векторні інструкції Scalable Vector Extension.

#### `AT_HWCAP2` (ARM64):
- `HWCAP2_SVE2` (`1 << 1`): Друге покоління Scalable Vector Extension.
- `HWCAP2_BTI` (`1 << 17`): Захист цілісності потоку виконання Branch Target Identification.
- `HWCAP2_MTE` (`1 << 18`): Апаратне тегування пам'яті Memory Tagging Extension.

## 4. Специфікація C/C++ API (`getauxval`, `getauxval2`)

Системні бібліотеки (glibc починаючи з версії 2.16, musl, bionic) надають стандартизований C-інтерфейс доступу до вектора.

### Специфікація `getauxval(3)`

```c
#include <sys/auxv.h>

unsigned long getauxval(unsigned long type);
```

#### Поведінка та контракт:
1. Функція повертає значення поля `a_val` або `a_ptr` для заданого `type`.
2. Якщо ключ відсутній у допоміжному векторі, функція повертає `0` та встановлює `errno = ENOENT`.
3. Оскільки повернуте значення `0` може бути легітимним вмістом ключа (наприклад, `AT_SECURE = 0`), для надійної перевірки слід обнуляти `errno` перед викликом:

:::tabs
```c
#include <sys/auxv.h>
#include <stdio.h>
#include <errno.h>

void safe_get_auxv(void) {
    errno = 0;
    unsigned long val = getauxval(AT_SECURE);
    int err = errno;

    if (val == 0 && err == ENOENT) {
        printf("Ключ AT_SECURE відсутній у auxv\n");
    } else {
        printf("Значення AT_SECURE: %lu\n", val);
    }
}
```
```cpp
#include <sys/auxv.h>
#include <iostream>
#include <cerrno>

void safe_get_auxv_cpp() {
    errno = 0;
    const unsigned long val = ::getauxval(AT_SECURE);
    const int err = errno;

    if (val == 0 && err == ENOENT) {
        std::cout << "Ключ AT_SECURE відсутній у auxv\n";
    } else {
        std::cout << "Значення AT_SECURE: " << val << "\n";
    }
}
```
:::

### Специфікація `getauxval2(3)` (glibc 2.38+)

У нових версіях glibc додано розширену функцію `getauxval2()`, яка приймає додатковий параметр замовчуваного значення, усуваючи невизначеність із `errno`.

## 5. Доступ та структура `/proc/<pid>/auxv`

Ядро Linux експортує бінарний масив допоміжного вектора через псевдофайл `/proc/<pid>/auxv`.

- Для читання власного вектора використовується шлях `/proc/self/auxv`.
- Читання вектора іншого процесу вимагає відповідних привілей доступу (перевірка `PTRACE_MODE_READ_REALCREDS`).
- Файл містить послідовність бінарних структур `Elf64_auxv_t` або `Elf32_auxv_t` до термінатора `AT_NULL` включно. Загальний розмір файла у байтах завжди кратний розміру структури (16 байтів для 64-бітних систем).
