# 📋 Довідник прапорців та змінних інтроспекції Bash

Цей довідник містить повний систематичний опис опцій інтерпретатора, вбудованих змінних інтроспекції та спеціальних сигналів пасток, які використовуються для налагодження, трасування, профілювання й діагностики сценаріїв у командних оболонках стандарту POSIX `sh` та розширеному середовищі GNU `bash`.

Командні оболонки Unix надають багаторівневий інтерфейс діагностики, що охоплює як статичні прапорці конфігурації поведінки парсера та виконавця, так і динамічні масиви віддзеркалення внутрішнього стану середовища виконання. Розуміння точної семантики цих інструментів, їхніх обмежень і взаємодії з процесною моделлю операційної системи є обов'язковою умовою створення стійких системних сценаріїв.

## 1. Прапорці оболонки для діагностики та трасування

Опції інтерпретатора можуть задаватися при запуску процесу через аргументи командного рядка (наприклад, `bash -x script.sh`) або змінюватися динамічно в процесі виконання через вбудовану команду `set`. За традицією Unix прапорець із дефісом `-` вмикає відповідний режим, тоді як прапорець зі знаком плюс `+` вимикає його.

```bash
# Приклад динамічного перемикання режимів у коді
set -o xtrace    # Увімкнути трасування (еквівалентно set -x)
set +o xtrace    # Вимкнути трасування (еквівалентно set +x)
```

### 1.1. Базові діагностичні опції POSIX

Наступні прапорці стандартизовані специфікацією POSIX.2 (IEEE Std 1003.1) і підтримуються всіма сумісними оболонками (`dash`, `ash`, `ksh`, `zsh`, `bash`):

- **`-x` (`xtrace`):** режим покрокового трасування інструкцій. Після того як оболонка виконала всі фази розгортання (підстановку параметрів, розкриття арифметичних виразів, заміну команд, розбиття на слова та розгортання масок шляхів), але безпосередньо перед передачею сформованого масиву `argv[]` системному виклику `execve(2)` або внутрішньому обробнику функції, рядок команди виводиться в діагностичний потік. Перед кожною інструкцією виводиться розгорнутий префікс `PS4`.
- **`-v` (`verbose`):** режим протоколювання вхідного потоку. Інтерпретатор виводить кожен прочитаний рядок сценарію в його сирому, немодифікованому вигляді безпосередньо в момент зчитування з файлу або стандартного вводу, до застосування будь-яких підстановок або розгортань. Цей режим дозволяє відстежувати прогрес синтаксичного аналізу багаторядкових конструкцій.
- **`-n` (`noexec`):** режим пасивної синтаксичної перевірки. Інтерпретатор читає команди, виконує лексичний і синтаксичний аналіз, будує внутрішнє дерево інструкцій, але повністю блокує стадію виконання. Усі системні виклики та розгортання змінних ігноруються. Якщо вхідний потік є інтерактивним терміналом, прапорець автоматично ігнорується оболонкою для запобігання блокуванню сеансу користувача.
- **`-u` (`nounset`):** режим суворого контролю ініціалізації змінних. При спробі звернення до змінної, якій не було присвоєно значення (за винятком спеціальних параметрів `$@` та `$*`), неінтерактивна оболонка виводить повідомлення про помилку у потік `stderr` і негайно перериває виконання сценарію з ненульовим статусом виходу. Це запобігає випадковому знищенню даних при операціях на кшталт `rm -rf "${UNSET_VAR}/cache"`.
- **`-e` (`errexit`):** режим негайної зупинки при збоях. Якщо будь-яка проста команда завершується з кодом повернення, відмінним від нуля (`$? != 0`), оболонка негайно припиняє виконання сценарію. За стандартом POSIX дія `set -e` пригнічується, якщо збійна команда є частиною перевірки умов у конструкціях `if`, `while`, `until`, або є лівим операндом логічних операторів `&&` чи `||`, або перед нею стоїть оператор логічного заперечення `!`.

### 1.2. Розширені опції GNU Bash

Для подолання відомих обмежень стандарту POSIX оболонка GNU Bash вводить спеціалізовані розширення:

- **`-o pipefail`:** модифікує логіку обчислення коду повернення конвеєра процесів. За замовчуванням конвеєр `cmd1 | cmd2 | cmd3` повертає статус виходу крайньої правої команди (`cmd3`), навіть якщо `cmd1` завершилася аварійно з критичною помилкою. Режим `pipefail` повертає код виходу останньої (крайньої правої) команди в конвеєрі, яка зазнала невдачі з ненульовим статусом. Якщо всі команди завершилися успішно, повертається `0`.
- **`-T` (`functrace`):** вмикає автоматичне успадкування пасток сигналів `DEBUG` та `RETURN` усіма функціями, підоболонками та процесами заміщення (`<(...)`). Без активації `-T` пастка `DEBUG`, зареєстрована на рівні головного скрипту, перестає викликатися всередині користувацьких функцій.
- **`-E` (`errtrace`):** вмикає примусове успадкування пастки сигналу `ERR` функціями, підоболонками та блоками підстановки команд `$(...)`. Без прапорця `-E` аварійний обробник пастки `ERR` не викликається, якщо збій стався всередині вкладеної функції.
- **`shopt -s extdebug`:** розширений режим налагодження Bash. Вмикає поведінку, необхідну для побудови повноцінних відлагоджувачів:
  1. Забезпечує збереження історії аргументів виклику функцій у масивах `BASH_ARGC` та `BASH_ARGV`;
  2. Дозволяє функції-обробнику пастки `DEBUG` повертати спеціальний статус `2`, який наказує інтерпретатору пропустити виконання поточної команди;
  3. Вмикає відстеження викликів перед входом у тіло функцій і підключених через `source` файлів.
- **`shopt -s inherit_errexit`:** починаючи з Bash 4.4, змушує підстановки команд `$(...)` успадковувати прапорець `set -e`. За замовчуванням у режимі сумісності підоболонка `$(failing_command)` скидає стан `errexit`, що може призводити до непомітного ігнорування збоїв під час ініціалізації змінних.

## 2. Вбудовані змінні інтроспекції та стану процесу

GNU Bash надає розробнику набір спеціальних системних змінних, які автоматично оновлюються ядром інтерпретатора на кожному кроці виконання.

### 2.1. Змінні контексту та часових позначок

- **`PS4` (Prompt String 4):** рядок префіксу, що виводиться перед кожною інструкцією в режимі `set -x`. За замовчуванням дорівнює `+ `. Якщо перший символ змінної є символом плюс, він автоматично мультиплікується інтерпретатором для відображення глибини вкладеності підоболонок (`+`, `++`, `+++`). Значення `PS4` піддається повному динамічному розгортанню змінних і виклику функцій перед кожним друком рядка трасування.
- **`LINENO`:** числове значення, що вказує поточний номер рядка у виконуваному файлі або функції. Значення є локальним для кожного підключеного сценарію.
- **`EPOCHREALTIME`:** дробове число з плаваючою комою (починаючи з Bash 5.0), що представляє системний час у форматі `секунди.мікросекунди` з початку епохи Unix (1970-01-01 00:00:00 UTC). Дозволяє вимірювати тривалість окремих команд без виклику зовнішніх утиліт.
- **`EPOCHSECONDS`:** цілочисельний системний час у секундах з початку епохи Unix (Bash 5.0+).
- **`BASH_COMMAND`:** рядкова змінна, що містить текст поточної команди, яка виконується в даний момент (під час обробки пастки `DEBUG`), або текст інструкції, збій якої призвів до спрацьовування пастки `ERR`.
- **`BASH_SUBSHELL`:** лічильник рівня вкладеності підоболонок. Дорівнює `0` у головному процесі, збільшується на `1` при кожному вході в блок у круглих дужках `(...)`, підстановку `$(...)` або асинхронний фоновий процес `&`.
- **`BASHPID`:** реальний числовий ідентифікатор поточного процесу операційної системи (PID). На відміну від спеціального параметра `$$`, який зберігає постійне значення PID кореневої оболонки навіть всередині підоболонок, `BASHPID` коректно відображає новий PID після кожного системного виклику `fork()`.
- **`BASH_XTRACEFD`:** ціле число, що позначає відкритий файловий дескриптор, у який інтерпретатор спрямовує вивід трасування `set -x`. Якщо змінна не встановлена або містить неприпустиме значення, вивід надходить у стандартний потік помилок `stderr` (дескриптор 2).

### 2.2. Масиви стека викликів та їхнє індексування

Для аналізу ієрархії викликів підпрограм Bash підтримує три паралельні індексовані масиви. Розуміння зв'язку між їхніми індексами є критичним для побудови коректних стек-трейсів:

- **`${FUNCNAME[@]}`:** список імен функцій у поточному стеку викликів. Елемент `FUNCNAME[0]` завжди містить ім'я поточної активної функції. Елемент `FUNCNAME[1]` містить ім'я функції, яка її викликала, і так далі до дна стека, де останній елемент дорівнює `main` або імені сценарію.
- **`${BASH_SOURCE[@]}`:** список шляхів до файлів вихідного коду. `BASH_SOURCE[0]` вказує на файл, де фізично розташована поточна інструкція, тоді як `BASH_SOURCE[1]` вказує на файл, звідки було здійснено виклик функції `FUNCNAME[0]`.
- **`${BASH_LINENO[@]}`:** масив номерів рядків, де відбулися відповідні виклики. Зверніть увагу на зсув індексації: `BASH_LINENO[0]` містить номер рядка у файлі `BASH_SOURCE[1]`, де було викликано `FUNCNAME[0]`. Загальне правило: виклик функції `FUNCNAME[i]` відбувся у файлі `BASH_SOURCE[i+1]` на рядку `BASH_LINENO[i]`.

## 3. Спеціальні події та псевдосигнали механізму `trap`

Вбудована команда `trap` стандарту POSIX призначена для перехоплення асинхронних сигналів операційної системи (`SIGINT`, `SIGTERM`, `SIGHUP`). Оболонка Bash розширює цей механізм, вводячи псевдосигнали для перехоплення внутрішніх подій життєвого циклу програми.

### 3.1. Пастка `DEBUG`

Обробник, зареєстрований для події `DEBUG`, виконується інтерпретатором безпосередньо перед кожною простою командою, викликом функції, тілом циклу або складеною умовою:

```bash
trap 'echo "Наступна команда: ${BASH_COMMAND}"' DEBUG
```

Особливості функціонування `DEBUG`:
- Якщо всередині сценарію увімкнено `shopt -s extdebug`, повернення статусу `2` з обробника наказує інтерпретатору пропустити виконання наступної команди;
- Повернення статусу `1` у режимі `extdebug` всередині функції перериває її виконання й повертає управління викликачу;
- Пастка не виконується всередині інших пасток, що запобігає нескінченній взаємній рекурсії.

### 3.2. Пастка `ERR`

Подія `ERR` виникає щоразу, коли проста команда повертає статус виходу, відмінний від нуля (`$? != 0`). 

Умови блокування пастки `ERR`:
- Пастка не викликається, якщо збій стався у виразі перевірки умови операторів `if`, `while`, `until`;
- Пастка не викликається для команд, що стоять ліворуч від операторів `&&` або `||` (наприклад, у виразі `grep pattern file || true` пастка `ERR` не спрацює при відсутності збігів у `grep`);
- Пастка не викликається, якщо перед командою стоїть оператор заперечення `!`.

### 3.3. Пастка `RETURN`

Подія `RETURN` виникає щоразу, коли завершується виконання функції або зовнішнього файлу, завантаженого за допомогою вбудованої команди `source` (або `.`). Вона дозволяє організувати вимірювання часу виконання окремих модулів або виконувати гарантоване скидання локальних змінних середовища.

### 3.4. Пастка `EXIT` (сигнал 0)

Подія `EXIT` гарантовано виконується під час завершення роботи оболонки за будь-яких обставин: явного виклику `exit`, досягнення кінця файлу сценарію або аварійного переривання за прапорцем `set -e`. Це стандартне місце для гарантованого видалення тимчасових файлів, закриття файлових дескрипторів та зняття файлових блокувань `flock`.
