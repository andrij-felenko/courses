# 📋 Системні виклики та інтерфейси політик пам'яті Linux

Управління політиками розміщення та міграції сторінок у ядрі Linux спирається на сімейство спеціалізованих системних викликів. Заголовний файл ядра `<linux/mempolicy.h>` та бібліотека простору користувача `<numaif.h>` (разом із високорівневою `<numa.h>` з пакета `numactl-devel` / `libnuma-dev`) визначають типи, режими, маски вузлів і числові коди прапорців.

Нижче наведено точні контракти викликів, структуру бітових масок вузлів, прапорці поведінки, внутрішні механізми ядра та коди помилок.

## Системні виклики ядра (UAPI)

```c
#define _GNU_SOURCE
#include <numaif.h>
#include <unistd.h>
#include <sys/syscall.h>

/* Встановлення політики за замовчуванням для поточного потоку */
long set_mempolicy(int mode, const unsigned long *nodemask, unsigned long maxnode);

/* Прив'язка політики пам'яті до конкретного віртуального діапазону [addr, addr + len) */
long mbind(void *addr, unsigned long len, int mode,
           const unsigned long *nodemask, unsigned long maxnode, unsigned int flags);

/* Отримання поточної політики процесу або інформації про вузол конкретної адреси */
long get_mempolicy(int *mode, unsigned long *nodemask, unsigned long maxnode,

/* Пакетна міграція сторінок процесу з одного набору вузлів на інший */

/* Встановлення «домашнього вузла» для діапазону пам'яті (Linux 5.17+) */
```

```cpp
#include <unistd.h>
#include <sys/syscall.h>
#include <cstdint>
#include <span>
#include <expected>
#include <system_error>

namespace numa {

enum class Mode : int {
    Default       = 0,
    Bind          = 1,
    Interleave    = 2,
    Preferred     = 3,
    Local         = 4,
    PreferredMany = 5
};

/* Безпечна C++ обгортка для встановлення політики пам'яті діапазону */
[[nodiscard]] inline std::expected<void, std::error_code> bind_range(
    std::span<std::byte> buffer,
    Mode mode,
    const unsigned long* nodemask,
    unsigned long maxnode,
    unsigned int flags) noexcept
{
    long ret = ::mbind(buffer.data(), buffer.size(),
                       static_cast<int>(mode), nodemask, maxnode, flags);
    if (ret != 0) {
        return std::unexpected(std::error_code(errno, std::generic_category()));
    }
    return {};
}

} // namespace numa
```

## Внутрішній життєвий цикл політик пам'яті в ядрі

Коли процес викликає будь-який системний виклик сімейства політик пам'яті, ядро Linux створює внутрішню структуру `struct mempolicy`. Ця структура містить числовий код режиму, прапорці поведінки, маску вузлів `nodemask_t` та лічильник посилань `refcnt`.

### Як ядро розв'язує політику під час виділення сторінки

Під час обробки сторінкового збою (page fault) ядро виконує пошук діючої політики за суворою ієрархічною схемою у функції `get_vma_policy()`:

1. **Перевірка VMA:** Спочатку перевіряється дескриптор `vm_area_struct` віртуальної адреси, на якій стався збій. Якщо для цього діапазону раніше викликався `mbind()`, поле `vma->vm_policy` містить покажчик на власну політику діапазону. Вона має абсолютний пріоритет.
2. **Перевірка файлової системи (shmem / hugetlbfs):** Якщо VMA належить спільній пам'яті (shared memory, `tmpfs`, `hugetlbfs`), політика може бути закріплена за самим файловим inode або суперблоком (`vma->vm_ops->get_policy()`).
3. **Перевірка потоку (Task Policy):** Якщо діапазон не має власної політики, ядро звертається до поля `current->mempolicy` у дескрипторі поточного потоку `task_struct`, встановленого через `set_mempolicy()`.
4. **Системне значення за замовчуванням (Default Policy):** Якщо потік не має власної політики (`current->mempolicy == NULL`), застосовується системна політика за замовчуванням — виділення на локальному вузлі того CPU, на якому в даний момент виконується потік.

При створенні нових потоків через `clone()` із прапорцем `CLONE_VM` (стандартні потоки POSIX `pthread`) новий потік успадковує покажчик на політику батьківського завдання зі збільшенням лічильника посилань `mpol_get()`.

## Режими політики (`mode`)

Константа `mode` передається першим аргументом у `set_mempolicy()` або третім у `mbind()`. Вона визначає базовий алгоритм розміщення фізичних кадрів.

| Константа | Значення | Опис поведінки ядра |
|---|:---:|---|
| `MPOL_DEFAULT` | `0` | Скидає політику діапазону чи потоку до системної (виділення на локальному вузлі CPU, що виконує виклик). Аргумент `nodemask` має бути `NULL`, а `maxnode` дорівнювати `0`. |
| `MPOL_BIND` | `1` | Суворе виділення виключно на вузлах, зазначених у бітовій масці `nodemask`. Якщо на всіх вказаних вузлах вичерпано пам'ять, розподільник повертає `-ENOMEM`, не зачіпаючи інші вузли системи. |
| `MPOL_INTERLEAVE` | `2` | Циклічне чергування виділення сторінок (round-robin) між вузлами з маски `nodemask`. Для виклику `mbind()` номер вузла вираховується від зміщення сторінки в межах VMA. |
| `MPOL_PREFERRED` | `3` | Бажане виділення на одному конкретному вузлі (перший встановлений біт у `nodemask`). Якщо на цьому вузлі виникає дефіцит пам'яті, ядро плавно переходить до сусідніх вузлів згідно з таблицею відстаней SLIT. Якщо `nodemask` порожня, бажаним вважається локальний вузол поточного CPU. |
| `MPOL_LOCAL` | `4` | Явно вимагає виділяти пам'ять на тому вузлі, де на момент виділення виконується потік. На відміну від `MPOL_DEFAULT`, не наслідує політику батьківського процесу. Доступно починаючи з Linux 3.8. |
| `MPOL_PREFERRED_MANY` | `5` | Розширення `MPOL_PREFERRED` для множини вузлів: ядро намагається задовольнити виділення на будь-якому з вузлів маски `nodemask`, і лише за браку пам'яті на всіх них переходить до інших вузлів системи. Додано в Linux 5.15. |

### Прапорці модифікації режиму (бітові маски у верхніх бітах `mode`)

Прапорці об'єднуються з базовим режимом через побітове «АБО» (`mode | MPOL_F_...`):

- **`MPOL_F_STATIC_NODES` (`1 << 15`):** біти у масці `nodemask` відповідають абсолютним фізичним ідентифікаторам NUMA-вузлів системи. Якщо процес переміщується між різними контрольними групами `cpuset` (наприклад, оркестратором контейнерів), маска не змінюється. Якщо після зміни `cpuset` жоден із вузлів маски не входить до списку дозволених для процесу, спроби виділення пам'яті зазнають невдачі з помилкою `-ENOMEM`.
- **`MPOL_F_RELATIVE_NODES` (`1 << 14`):** біти у масці `nodemask` інтерпретуються відносно списку вузлів, дозволених для поточного процесу в `cpuset`. Біт 0 позначає перший дозволений вузол, біт 1 — другий тощо. Коли `cpuset` змінює конфігурацію доступних вузлів, ядро автоматично перераховує фізичні вузли для цієї політики.
- **`MPOL_F_NUMA_BALANCING` (`1 << 13`):** використовується разом із `MPOL_BIND` для явного ввімкнення або вимкнення автоматичного балансування (Auto-NUMA) для конкретного діапазону адрес (Linux 5.12+).

## Прапорці міграції `mbind()` (`flags`)

Аргумент `flags` у виклику `mbind()` керує тим, що робити з віртуальними сторінками в діапазоні `[addr, addr + len)`, для яких уже виділено фізичні кадри (наприклад, через попередній запис або відображення файлу).

:::tabs
```c
#define MPOL_MF_STRICT   (1 << 0) /* Повернути EIO, якщо існуючі сторінки не відповідають політиці */
#define MPOL_MF_MOVE     (1 << 1) /* Мігрувати сторінки, що порушують нову політику, на вказані вузли */
#define MPOL_MF_MOVE_ALL (1 << 2) /* Мігрувати всі сторінки, включно зі спільними (потрібен CAP_SYS_ADMIN) */
```
```cpp
enum class MoveFlags : unsigned int {
    Strict  = (1U << 0), /* Повернути EIO, якщо сторінки не відповідають політиці */
    Move    = (1U << 1), /* Мігрувати сторінки, що порушують нову політику */
    MoveAll = (1U << 2)  /* Мігрувати всі сторінки, включно зі спільними (CAP_SYS_ADMIN) */
};
```

### Детальна поведінка комбінацій прапорців

Коли викликається `mbind()`, ядро виконує розбиття VMA-структур (`split_vma()`), якщо переданий діапазон адрес не збігається з існуючими межами алокацій процесу. Потім, залежно від прапорців, виконуються такі дії:

1. **`flags = 0` (Лише майбутні виділення):** Політика встановлюється в дескриптор VMA. Ядро не перевіряє таблиці сторінок. Фізичні кадри, які вже існують під цими адресами, залишаються на своїх вихідних вузлах. Нові сторінки, до яких процес торкнеться вперше після виклику, виділятимуться за новою політикою.
2. **`flags = MPOL_MF_MOVE` (М'яка міграція):** Ядро запускає функцію `queue_pages_range()`, яка обходить таблиці сторінок (PGD -> P4D -> PUD -> PMD -> PTE). Для кожної сторінки, яка знаходиться не на тому вузлі, що вимагається політикою, вона ізолюється зі списків LRU і передається підсистемі міграції `migrate_pages()`. Якщо окремі сторінки тимчасово заблоковані драйверами для прямого доступу пам'яті (DMA через `pin_user_pages()`), ядро пропускає їх і продовжує обробку інших сторінок без повернення помилки.
3. **`flags = MPOL_MF_STRICT | MPOL_MF_MOVE` (Сувора міграція з валідацією):** Ядро вимагає, щоб **усі 100% сторінок** діапазону лежали на дозволених вузлах. Якщо хоча б одну сторінку не вдалося мігрувати (наприклад, через активний DMA або брак пам'яті на цільовому вузлі), системний виклик негайно переривається і повертає помилку `-EIO`.
4. **`flags = MPOL_MF_MOVE_ALL` (Міграція спільних сторінок):** Звичайний `MPOL_MF_MOVE` переміщує лише сторінки, які належать виключно поточному процесу (анонімна приватна пам'ять). Якщо діапазон містить спільні сторінки (`MAP_SHARED`), які одночасно відображені в таблиці інших процесів, їхнє переміщення дозволяється тільки за наявності прав суперкористувача `CAP_SYS_ADMIN` та встановленого прапорця `MPOL_MF_MOVE_ALL`.

## Прапорці запиту `get_mempolicy()` (`flags`)

Системний виклик `get_mempolicy()` працює у двох принципово різних режимах залежно від прапорців:

- **`flags = 0` (Політика процесу):** запитує поточну політику процесу або потоку. Записує код режиму в `*mode` та бітову маску дозволених вузлів у `nodemask`.
- **`MPOL_F_NODE` (`1 << 0`):** повертає в `*mode` числовий ідентифікатор NUMA-вузла (Node ID), на якому фактично розміщено фізичну сторінку за адресою `addr` (якщо вказано `MPOL_F_ADDR`), або наступний вузол для виділення в режимі `MPOL_INTERLEAVE`.
- **`MPOL_F_ADDR` (`1 << 1`):** вимагає повернути політику, прив'язану до конкретної віртуальної адреси `addr` (встановлену через `mbind()`), а не загальну політику процесу.
- **`MPOL_F_MEMS_ALLOWED` (`1 << 2`):** повертає у `nodemask` бітову маску всіх вузлів, виділення пам'яті на яких дозволено поточному процесу його контекстом `cpuset`.

## Системний виклик `set_mempolicy_home_node()` (Linux 5.17+)

Починаючи з ядра Linux 5.17, для підтримки гетерогенних систем і багаторівневої пам'яті CXL було додано системний виклик `set_mempolicy_home_node()`:

:::tabs
```c
long set_mempolicy_home_node(unsigned long start, unsigned long len,
                            unsigned long home_node, unsigned long flags);
```
```cpp
[[nodiscard]] inline std::expected<void, std::error_code> set_home_node(
    std::span<std::byte> buffer,
    unsigned long home_node,
    unsigned long flags = 0) noexcept
{
    long ret = ::set_mempolicy_home_node(
        reinterpret_cast<unsigned long>(buffer.data()),
        buffer.size(), home_node, flags);
    if (ret != 0) {
        return std::unexpected(std::error_code(errno, std::generic_category()));
    }
    return {};
}
```
:::

Цей виклик дозволяє вказати «домашній вузол» (`home_node`) для діапазону VMA, для якого вже встановлено політику `MPOL_BIND` або `MPOL_PREFERRED_MANY`. 

Призначення домашнього вузла:
- Коли пам'ять виділяється з пулу кількох дозволених вузлів, розподільник віддає безумовний перший пріоритет домашньому вузлу.
- Механізм автоматичного балансування Auto-NUMA використовує домашній вузол як цільову точку міграції при виникненні hinting fault, що критично для систем із повільними CXL-вузлами та швидкими сокетами процесора.

## Системний виклик `migrate_pages()` проти `move_pages()`

Ядро надає два різні механізми примусової міграції сторінок між NUMA-вузлами:

1. **`migrate_pages(pid, maxnode, old_nodes, new_nodes)`:**
   - Працює над **усім адресним простором** процесу з ідентифікатором `pid`.
   - Приймає дві бітові маски: маску вихідних вузлів `old_nodes` та маску цільових вузлів `new_nodes`.
   - Ядро знаходить усі фізичні кадри процесу, що лежать на вузлах із `old_nodes`, і переносить їх на вузли з `new_nodes` (відповідно 1-в-1 або за порядком).
   - Застосовується системними утилітами (`numactl --migrate`) та демонами оркестрації віртуальних машин для перенесення процесу на інший сокет.
2. **`move_pages(pid, count, pages, nodes, status, flags)`:**
   - Працює з **посторінковим вектором**: дозволяє передати масив довільних віртуальних адрес `pages` та масив конкретних цільових вузлів `nodes` для кожної сторінки індивідуально.
   - Масив `status` повертає результат міграції для кожного окремого кадру (успіх або код помилки).
   - Якщо аргумент `nodes` передано як `NULL`, системний виклик не переміщує сторінки, а лише заповнює масив `status` поточними номерами вузлів, де лежать відповідні фізичні сторінки (інспекція розташування).

## Структура бітової маски вузлів (`nodemask_t` та `struct bitmask`)

На рівні системного виклику ядра бітова маска — це масив цілих чисел типу `unsigned long`. Аргумент `maxnode` вказує максимальну кількість бітів у масці (плюс 1).

У просторі користувача бібліотека `libnuma` надає зручну структуру `struct bitmask` та допоміжні функції для маніпуляцій:

:::tabs
```c
#include <numa.h>
#include <stdio.h>

void setup_node_mask(void) {
    /* Виділення маски потрібного розміру для поточної системи */
    struct bitmask *nodes = numa_allocate_nodemask();

    /* Встановлення бітів вузлів 0 та 1 */
    numa_bitmask_setbit(nodes, 0);
    numa_bitmask_setbit(nodes, 1);

    /* Перевірка біта */
    if (numa_bitmask_isbitset(nodes, 0)) {
        printf("Node 0 active in mask\n");
    }

    /* Звільнення структури */
    numa_free_nodemask(nodes);
}
```
```cpp
#include <numa.h>
#include <memory>
#include <iostream>

struct BitmaskDeleter {
    void operator()(struct bitmask* bm) const noexcept {
        if (bm) {
            numa_free_nodemask(bm);
        }
    }
};

using UniqueBitmask = std::unique_ptr<struct bitmask, BitmaskDeleter>;

inline UniqueBitmask make_node_mask(std::initializer_list<unsigned int> node_ids) {
    UniqueBitmask mask(numa_allocate_nodemask());
    if (!mask) {
        throw std::bad_alloc();
    }
    for (unsigned int node : node_ids) {
        numa_bitmask_setbit(mask.get(), node);
    }
    return mask;
}
```

## Високорівневі функції `libnuma`

Для більшості прикладних програм ручний виклик `syscall(__NR_mbind)` або `syscall(__NR_set_mempolicy)` не потрібен — значно надійніше використовувати функції бібліотеки `libnuma`:

| Функція `libnuma` | Призначення |
|---|---|
| `numa_available()` | Перевіряє, чи система підтримує NUMA і чи доступний інтерфейс ядра (повертає `-1`, якщо ні). |
| `numa_max_node()` | Повертає максимальний доступний ідентифікатор NUMA-вузла в системі. |
| `numa_alloc_onnode(size, node)` | Виділяє пам'ять обсягом `size` через `mmap` та встановлює для неї політику `MPOL_BIND` на вказаному вузлі. |
| `numa_alloc_local(size)` | Виділяє сторінки на локальному вузлі того процесора, що викликав функцію. |
| `numa_alloc_interleaved(size)` | Виділяє пам'ять із чергуванням сторінок на всіх доступних вузлах системи (`MPOL_INTERLEAVE`). |
| `numa_free(start, size)` | Звільняє буфер, виділений будь-якою з функцій `numa_alloc_*` (через `munmap`). |
| `numa_set_membind(mask)` | Встановлює для всього потоку політику суворого виділення пам'яті на вузлах із `mask`. |
| `numa_set_interleave_mask(mask)` | Вмикає для потоку режим чергування пам'яті на вузлах із `mask`. |
| `numa_run_on_node(node)` | Прив'язує планувальник процесора (affinity) для поточного потоку до всіх CPU вказаного вузла. |

## Коди помилок системних викликів

| Код помилки | Типові причини виникнення |
|---|---|
| `EFAULT` | Неприпустима віртуальна адреса або діапазон адрес `[addr, addr + len)` виходить за межі адресного простору процесу; недійсний покажчик на `nodemask` чи `mode`. |
| `EINVAL` | Невідомий код `mode` або неприпустимі прапорці; передано непустий `nodemask` для `MPOL_DEFAULT`; значення `maxnode` перевищує підтримуваний ліміт ядра (`PAGE_SIZE * 8`); адреса `addr` не вирівняна по межі сторінки (`PAGE_SIZE`) у виклику `mbind()`. |
| `ENOMEM` | Недостатньо пам'яті в ядрі для створення внутрішніх структур політики; або виділення сторінки в режимі `MPOL_BIND` провалилося, бо на зазначених вузлах вичерпано всі вільні кадри. |
| `EPERM` | Спроба використати `MPOL_MF_MOVE_ALL` без привілеїв `CAP_SYS_ADMIN`; спроба змінити політику чи викликати `migrate_pages()` для чужого процесу без прав відлагодження/керування. |
| `EIO` | Вказано прапорець `MPOL_MF_STRICT`, і в діапазоні пам'яті виявлено сторінки, що лежать на заборонених вузлах або не можуть бути перенесені (наприклад, сторінки, захоплені пристроями вводу-виводу). |
| `ESRCH` | Процес із зазначеним `pid` не існує (у виклику `migrate_pages()`). |
| `ENODEV` | Жоден із вузлів, вказаних у `nodemask`, не містить оперативної пам'яті або не доступний процесу через обмеження `cpuset`. |
