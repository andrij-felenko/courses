# 📋 Конвенції роздільників та системні формати записів Unix

У системному середовищі Unix та Linux текстові інтерфейси спираються на набір усталених конвенцій щодо розділення записів (Record Separators) та полів (Field Delimiters). Відсутність єдиної бінарної схеми на рівні ядра компенсується суворим дотриманням семантики символів-розділювачів у системних конфігураційних файлах, інтерфейсах віртуальних файлових систем (`/proc`, `/sys`), системних викликах та потоках міжпроцесної взаємодії.

Коли операційна система позбавлена глобального реєстру типів, надійність обробки залежить виключно від домовленостей між програмами. Якщо формат припускає наявність довільного тексту всередині поля, вибір роздільника стає питанням безпеки та цілісності даних. Неправильно обраний або неперевірений роздільник призводить до вразливостей типу розщеплення слів (word splitting) та ін'єкцій аргументів у командних конвеєрах.

## 1. Роздільники записів (Record Separators)

Запис є неподільною логічною одиницею інформації: окремим рядком конфігураційної таблиці, подією системного журналу, обліковим записом користувача або шляхом до файлу у файловій системі. Утиліти обробки потоків оперують двома основними символами завершення запису:

| Символ | Код ASCII / Hex | Призначення | Утиліти з підтримкою |
|---|---|---|---|
| **`\n` (Line Feed)** | `10` / `0x0A` | Стандартний роздільник рядкових записів для людей та скриптів. Позначає кінець логічного запису в текстових файлах та конвеєрах. | Усі стандартні утиліти POSIX (`grep`, `sed`, `awk`, `head`, `tail`, `wc`, `sort`). |
| **`\0` (NUL Byte)** | `0` / `0x00` | Абсолютно надійний роздільник записів довільного вмісту. Забезпечує коректну передачу шляхів, що містять пробіли, лапки та символи переносу рядка. | `find -print0`, `xargs -0`, `sort -z`, `grep -z`, `cut -z`, `read -d ''`, `parallel -0`. |

Символ `\n` забезпечує читабельність та природну інтеграцію з терміналом: людина може переглядати потік за допомогою `cat` або `less`, а утиліти можуть зчитувати записи буферизовано, виділяючи пам'ять лише під один рядок. Проте стандарт POSIX дозволяє використовувати будь-які байти, крім `0x00` та слеша `/` (`0x2F`), у назвах файлів та каталогів. Це означає, що ім'я файлу в Linux може легально містити символ переносу рядка `\n`.

Якщо потік імен файлів розділяється символом `\n`, файл із назвою `backup\nrm -rf /` буде розірваний утилітою-отримувачем на два незалежні записи. Це створює катастрофічну вразливість в автоматизованих сценаріях адміністрування. Саме тому для передачі шляхів у сучасних конвеєрах стандартом де-факто є нульовий байт `\0`. Оскільки байт `0x00` є термінатором рядків мови C і фізично заборонений у шляхах POSIX на рівні ядра, він утворює абсолютно надійну межу між записами довільної довжини та структури.

### Інтерфейси нульового байта в ядрі Linux

Ядро Linux використовує байт `0x00` як штатний роздільник параметрів у псевдофайлах процесів віртуальної файлової системи `procfs`:

- **`/proc/[pid]/cmdline`** — повний список аргументів командного рядка процесу (`argv`), розділених байтом `\0`. Останній аргумент також завершується нульовим байтом. Якщо процес є потоком ядра (kernel thread), цей файл порожній.
- **`/proc/[pid]/environ`** — масив змінних оточення процесу у форматі `KEY=VALUE`, розділених байтом `\0`.
- **`/proc/[pid]/auxv`** — двійковий допоміжний вектор (auxiliary vector), що передається динамічним завантажувачем `ld.so`.

```bash
# Читання аргументів процесу без пошкодження через пробіли
tr '\0' '\n' < /proc/$$/cmdline

# Порядковий вивід змінних оточення активного процесу
tr '\0' '\n' < /proc/$$/environ
```

## 2. Роздільники полів (Field Delimiters)

Поле є окремим атрибутом або значенням всередині одного логічного запису. Залежно від вимог до даних, компактності та читабельності, системні інтерфейси використовують три моделі розбиття на поля.

### Двокрапка (`:`) — фіксовані системні реєстри

Двокрапка застосовується у файлах з фіксованою кількістю полів, де значення можуть містити довільні пробіли (наприклад, повне ім'я користувача чи коментар), але гарантовано не містять символу `:`.

| Файл | Кількість полів | Схема запису | Призначення полів |
|---|---|---|---|
| `/etc/passwd` | 7 | `name:pwd:UID:GID:GECOS:home:shell` | 1. Логін; 2. Заповнювач пароля (`x`); 3. Числовий UID; 4. Числовий GID; 5. Коментар GECOS; 6. Домашній каталог; 7. Шлях до командної оболонки. |
| `/etc/group` | 4 | `group:pwd:GID:user_list` | 1. Назва групи; 2. Пароль групи; 3. Числовий GID; 4. Список користувачів через кому. |
| `/etc/shadow` | 9 | `name:hash:last:min:max:warn:inact:exp:flag` | 1. Логін; 2. Хеш пароля; 3. День останньої зміни; 4. Мін. днів до зміни; 5. Макс. днів; 6. Попередження; 7. Неактивність; 8. Термін дії; 9. Резерв. |
| Змінна `$PATH` | Змінна | `dir1:dir2:dir3...` | Список каталогів для пошуку виконуваних файлів. Порожній елемент (`::` або на початку/кінці) означає поточний каталог `.`. |

Правила синтаксису:
- Порожнє поле позначається двома двокрапками поспіль (`::`).
- Символ `:` всередині значення суворо заборонений (наприклад, системна утиліта `usermod` повертає помилку при спробі вставити двокрапку в поле опису користувача GECOS).
- Останнє поле запису завершується символом нового рядка `\n`.

### Табуляція (`\t`) — формат TSV (Tab-Separated Values)

Символ табуляції (`0x09`, `\t`) є машино-орієнтованим стандартом делімітації в утилітах текстової обробки:

- Утиліти `cut` та `paste` використовують `\t` як роздільник стовпців за замовчуванням (`-d $'\t'`).
- Значення полів можуть містити одиничні або багаторазові пробіли, які не призводять до зсуву чи спотворення сусідніх колонок.
- Кожен символ табуляції позначає рівно одну межу поля (два символи `\t\t` означають одне порожнє поле між ними, тоді як пробіли часто об'єднуються).

### Пробільні символи (Whitespace) — таблиці конфігурацій та вивід утиліт

Послідовність з одного або кількох пробілів та знаків табуляції розглядається як єдиний роздільник полів.

| Файл / Вивід | Кількість колонок | Опис формату | Особливості парсингу |
|---|---|---|---|
| `/etc/fstab` | 6 | `fs_spec fs_file fs_vfstype fs_mntops fs_freq fs_passno` | Пробіли та табуляції в точках монтування (`fs_file`) замінюються вісімковим кодом `\040` (наприклад, `/media/My\040Drive`). |
| `/proc/mounts` | 6 | Аналогічно `/etc/fstab` | Генерується ядром динамічно через підсистему `seq_file`. Віддзеркалює активні монтування `struct mount`. |
| `/proc/loadavg` | 5 | `load1 load5 load15 runnable/total last_pid` | Три середні завантаження за 1, 5, 15 хв, дріб активних задач до загальних, PID останнього створеного процесу. |
| `ps -ef` / `ps aux` | Змінна | `UID PID PPID C STIME TTY TIME CMD` | Остання колонка (`CMD` або `COMMAND`) містить повний командний рядок з пробілами, тому читається до кінця рядка `\n`. |
| `/etc/hosts` | 2+ | `ip_address canonical_hostname [aliases...]` | Перше поле — IP-адреса, друге — канонічне ім'я хоста, наступні поля через пробіли — псевдоніми. |
| `/etc/resolv.conf`| 2 | `directive value` | Директиви типу `nameserver 1.1.1.1` або `search domain.local`. |

## 3. Прапори стандартних утиліт POSIX для налаштування роздільників

| Утиліта | Прапор роздільника полів | Прапор нульового роздільника (`\0`) | Приклад застосування |
|---|---|---|---|
| `cut` | `-d 'delim'` | `-z` (GNU) | `cut -d: -f1,7 /etc/passwd` |
| `awk` | `-F 'delim'` або `FS="delim"` | `-v RS='\0'` / `-v ORS='\0'` | `awk -F: '$3 >= 1000 {print $1}' /etc/passwd` |
| `sort` | `-t 'delim'` | `-z` (GNU) | `sort -t: -k3,3n /etc/passwd` |
| `paste` | `-d 'delim'` | `-z` (GNU) | `paste -d, names.txt emails.txt` |
| `join` | `-t 'delim'` | `-z` (GNU) | `join -t: -1 4 -2 3 /etc/passwd /etc/group` |
| `xargs` | `-d 'delim'` | `-0` (POSIX / GNU) | `find /var/log -type f -print0 \| xargs -0 rm -f` |
| `grep` | — | `-z` (GNU) | `grep -z "pattern" file_with_nulls` |
| `column` | `-s 'delim'` (вхідний роздільник) | `-z` (GNU) | `column -t -s: /etc/passwd` |

## 4. Семантика внутрішнього роздільника полів оболонки (`$IFS`)

У командних оболонках POSIX (sh, dash, bash) розбиття потоку на слова (Word Splitting) та розбір полів у вбудованій команді `read` контролюються спеціальною змінною оточення `IFS` (Internal Field Separator).

За замовчуванням змінна `IFS` містить три символи: пробіл, табуляцію та перенос рядка:
```bash
IFS=$' \t\n'
```

### Відмінність між пробільними та непробільними роздільниками:

1. **Пробільні роздільники (`IFS whitespace` — пробіл, `\t`, `\n`):**
   - Провідні (leading) та завершальні (trailing) пробільні символи автоматично відкидаються синтаксичним аналізатором.
   - Будь-яка неперервна послідовність з кількох пробільних символів поспіль об'єднується в один неподільний роздільник. Порожні поля між ними не утворюються.
2. **Непробільні роздільники (наприклад, `IFS=":"` або `IFS=","`):**
   - Кожен окремий символ роздільника створює чітку межу поля.
   - Послідовність двох символів роздільника поспіль (`::`) обов'язково породжує порожнє поле нульової довжини (`""`).
   - Роздільники на початку або наприкінці рядка створюють порожні поля на першій та останній позиціях списку.

```bash
# Надійний шаблон безпечного порядкового читання /etc/passwd у скриптах
while IFS=: read -r username password uid gid gecos homedir usershell || [ -n "$username" ]; do
    if [ "$uid" -ge 1000 ] && [ "$usershell" != "/usr/sbin/nologin" ]; then
        printf "Користувач: %-15s UID: %-5d Домашній каталог: %s\n" "$username" "$uid" "$homedir"
    fi
done < /etc/passwd
```

## 5. Обробка багатобайтових кодувань (UTF-8 проти ASCII)

При роботі з текстовими інтерфейсами важливо враховувати різницю між байтами та символами:

- Утиліти `cut -b 1-10` оперують фізичними байтами, що може призвести до розриву багатобайтового символу UTF-8 (наприклад, кирилична літера `д` займає 2 байти `0xD0 0xB4`).
- Утиліти `cut -c 1-10` або вирази `awk` з увімкненою локаллю UTF-8 оперують логічними символами (Unicode code points), декодуючи послідовність байтів відповідно до налаштувань `LC_CTYPE`.
- У системному програмуванні для надійності розбору конфігураційних файлів та імен системних служб завжди рекомендується використовувати байт-орієнтовані алгоритми в локалі `LC_ALL=C`, де кожен байт розглядається як ізольований елемент без потреби у складному юнікод-декодуванні.

## 6. Програмний інтерфейс C та C++ для читання системних записів

Стандартна бібліотека C надає функції для безпечного синтаксичного розбору табличних файлів без ручної маніпуляції рядками. Відповідні інтерфейси реалізують автоматичне пропускання коментарів, обробку вісімкових кодів екранування та виділення структур у пам'яті.

:::tabs
```c
#define _GNU_SOURCE
#include <pwd.h>
#include <stdio.h>
#include <mntent.h>
#include <string.h>

// Порядкова ітерація через /etc/passwd за допомогою POSIX getpwent()
void print_regular_users(void) {
    struct passwd *pw;
    setpwent(); // Перемотування файлу облікових записів на початок
    while ((pw = getpwent()) != NULL) {
        if (pw->pw_uid >= 1000) {
            printf("Користувач: %s, UID: %u, Оболонка: %s\n",
                   pw->pw_name, (unsigned int)pw->pw_uid, pw->pw_shell);
        }
    }
    endpwent(); // Закриття файлового дескриптора
}

// Порядкове читання монтувань ядра через mntent
void list_ext4_mounts(void) {
    FILE *fp = setmntent("/proc/mounts", "r");
    if (!fp) return;

    struct mntent *ent;
    while ((ent = getmntent(fp)) != NULL) {
        if (strcmp(ent->mnt_type, "ext4") == 0) {
            printf("Пристрій: %s -> Точка монтування: %s\n",
                   ent->mnt_fsname, ent->mnt_dir);
        }
    }
    endmntent(fp);
}
```
```cpp
#include <iostream>
#include <fstream>
#include <string>
#include <string_view>
#include <vector>
#include <pwd.h>
#include <mntent.h>

// Ідіоматична обгортка RAII для дескриптора mntent
class MountTableReader {
public:
    explicit MountTableReader(const char* path) 
        : fp_(setmntent(path, "r")) {}

    ~MountTableReader() {
        if (fp_) {
            endmntent(fp_);
        }
    }

    bool is_open() const noexcept { return fp_ != nullptr; }

    void print_fs_type(std::string_view target_type) {
        if (!fp_) return;
        struct mntent ent{};
        char buffer[4096];
        while (getmntent_r(fp_, &ent, buffer, sizeof(buffer)) != nullptr) {
            if (target_type == ent.mnt_type) {
                std::cout << "Пристрій: " << ent.mnt_fsname
                          << " -> Точка монтування: " << ent.mnt_dir << '\n';
            }
        }
    }

private:
    FILE* fp_{nullptr};
};

void print_regular_users_cpp() {
    setpwent();
    while (const auto* pw = getpwent()) {
        if (pw->pw_uid >= 1000) {
            std::cout << "Користувач: " << pw->pw_name 
                      << ", UID: " << pw->pw_uid 
                      << ", Оболонка: " << pw->pw_shell << '\n';
        }
    }
    endpwent();
}
```
:::

Використання потокобезпечних функцій `libc` (`getpwent_r`, `getmntent_r`, `getgrent_r`) або обгорток RAII гарантує коректну обробку коментарів, порожніх рядків, вісімкових екранувань та відповідність стандартам POSIX без витоків дескрипторів пам'яті.
