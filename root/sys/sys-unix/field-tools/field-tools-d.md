Коли системний конвеєр обробляє гігабайти журналів вебсервера, списки відкритих дескрипторів із `/proc` чи таблиці користувачів із `/etc/passwd`, потік байтів майже завжди має внутрішню структуру: послідовність рядків-записів, розбитих на окремі колонки роздільниками на зразок двокрапки, коми чи табуляції. Якщо для простої вибірки третього стовпця або порівняння двох списків ідентифікаторів щоразу викликати важкі інтерпретатори на зразок Python, Perl чи навіть універсальну мову `awk`, конвеєр витрачає левову частку процесорних тактів на ініціалізацію віртуальної машини, динамічне виділення пам'яті під абстрактні синтаксичні дерева та парсинг складних граматик. На великих обсягах даних накладні витрати на інтерпретацію одного рядка починають перевищувати пропускну здатність системного каналу вводу-виводу.

Операційні системи родини Unix розв'язують цю проблему через набір спеціалізованих потокових фільтрів із пакета coreutils: `cut`, `paste`, `join`, `comm` та `tr`. Кожен із цих інструментів сфокусований на єдиній вузькій операції над стовпцями чи символами, скомпільований у машинний код і спроєктований так, щоб обробляти потік зі швидкістю лінійного читання пам'яті. Вони оперують фіксованими системними буферами, уникають динамічної алокації рядків у купі та використовують прямі табличні підстановки.

Однак вузька спеціалізація накладає жорсткі інженерні обмеження: робота лише з односимвольними роздільниками, чутливість до повторюваних пробілів, відсутність регулярних виразів та сувора вимога однакового попереднього сортування даних для реляційних операцій. Розуміння внутрішнього механізму цих утиліт, їхньої взаємодії та граничних випадків дозволяє будувати гранично швидкі й надійні конвеєри обробки структурованого тексту.

## 1. Спеціалізовані фільтри стовпців проти універсальних інтерпретаторів

Архітектурний принцип Unix стверджує: програма повинна робити одну річ, але робити її бездоганно, приймаючи текстовий потік на стандартний вхід і віддаючи результат на стандартний вихід. Табличні операції в конвеєрах природно розпадаються на кілька фундаментальних примітивів:
1. **Вертикальний зріз** (проєкція в реляційній термінології): вибір фіксованих колонок або діапазонів байтів із кожного рядка — за це відповідає `cut` (від англ. *to cut* — різати).
2. **Горизонтальне злиття** (склеювання): об'єднання кількох незалежних потоків рядок у рядок бік-о-бік або серіалізація послідовності — завдання утиліти `paste` (від англ. *to paste* — вставляти/склеювати).
3. **Реляційне з'єднання** (екві-з'єднання, *equi-join*): злиття двох файлів за спільним ключовим полем у лінійному часі без завантаження всієї таблиці в оперативну пам'ять — цим займається `join`.
4. **Операції над множинами**: обчислення перетину, симетричної та відносної різниці двох впорядкованих списків — функція `comm` (від англ. *common* — спільний).
5. **Посимвольна нормалізація**: заміна байтів за фіксованою таблицею, видалення службових символів та стискання дублікатів — зона відповідальності `tr` (від англ. *translate* — транслювати).

Коли задачу можна вирішити за допомогою цих утиліт, запуск інтерпретатора `awk` чи скрипту на Python є надлишковим. Розглянемо різницю у внутрішній організації:

```
[Потік stdin] ──► [Системний буфер read()] ──► [Прямий сканер memchr()/таблиця] ──► [Буфер write()] ──► [stdout]
                               (Модель cut / tr / paste: нуль динамічних алокацій)

[Потік stdin] ──► [Лексичний аналізатор] ──► [Парсер AST] ──► [Хеш-таблиці полів $1..$N] ──► [Інтерпретатор]
                               (Модель awk / perl / python: оверхед на кожен рядок)
```

Утиліти `cut` і `tr` читають дані великими блоками (зазвичай 32 або 64 КіБ) через системний виклик `read` або буферизований потік C-бібліотеки `fread`. Для пошуку роздільника `cut` використовує векторні інструкції пошуку байта (функцію `memchr`, оптимізовану через AVX2/SSE2 на сучасних процесорах). Знайдені зміщення одразу передаються у вихідний буфер без створення проміжних об'єктів рядків у пам'яті. Крім того, утиліти GNU coreutils використовують неблоковані версії функцій введення-виведення C-бібліотеки (`getc_unlocked`, `putc_unlocked` та `fread_unlocked`), що повністю усуває накладні витрати на взяття м'ютексів потокової безпеки (thread-safety mutex) на кожен символ.

Натомість `awk` під час читання кожного рядка мусить динамічно розбити рядок на масив полів, створити змінні `$1`, `$2`, ..., `$NF`, оновити лічильники `NR` та `FNR`, перевірити умови шаблонів і лише потім виконати дію друку `print`. Якщо вхідний файл містить 50 мільйонів рядків, різниця у часі виконання між конвеєром `cut -d: -f1,3` та командою `awk -F: '{print $1":"$3}'` становить від 3 до 7 разів на користь `cut`, при споживанні пам'яті менше 1 МіБ проти десятків мегабайтів у важких середовищах.

| Утиліта | Призначення | Вимога до впорядкованості | Складність за часом | Споживання RAM | Обмеження |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `cut` | Вибірка полів / байтів | Не потрібна | `O(N)` | `O(1)` (буфер I/O) | Лише 1 байт роздільника; не стискає пробіли |
| `paste` | Горизонтальне злиття | Не потрібна | `O(N)` | `O(1)` | Рівняє файли за номерами рядків |
| `join` | Реляційний JOIN за ключем | **Обов'язкове сортування** | `O(N + M)` | `O(1)` | Однаковий `LC_ALL=C`; ключ в обох файлах |
| `comm` | Порівняння списків (множини) | **Обов'язкове сортування** | `O(N + M)` | `O(1)` | Тільки повні рядки; однаковий порядок |
| `tr` | Побайтова заміна / видалення | Не потрібна | `O(N)` | `O(1)` (256 байт) | Працює **виключно** через `stdin` |

## 2. Утиліта `cut`: вибірка полів, символів та байтів

Утиліта `cut` призначена для вилучення вертикальних колонок із кожного рядка вхідного текстового потоку. Її поведінка визначається вибором режиму адресації: за байтами (`-b`), за символами (`-c`) або за роздільником полів (`-f`).

### Режими адресації та синтаксис діапазонів

Діапазони вибірки вказуються як список номерів або інтервалів через кому:
- `N`: рівно `N`-те поле, символ або байт (нумерація завжди починається з одиниці, `1-based`).
- `N-M`: діапазон від `N` до `M` включно.
- `N-`: від `N` і до кінця поточного рядка.
- `-M`: від початку рядка і до `M` включно.
- `N,M,K`: перелік окремих індексів.

Прапорець `--complement` інвертує вибірку: `cut` друкує всі поля або байти, крім тих, що потрапили у вказаний діапазон.

```bash
# Вибірка першого та третього полів із конфігурації облікових записів
cut -d: -f1,3 /etc/passwd

# Вибірка всіх полів, окрім другого (хешу пароля)
cut -d: -f2 --complement /etc/passwd

# Вибірка перших 10 байтів кожного рядка
cut -b 1-10 /var/log/syslog
```

### Зміна вихідного роздільника (`--output-delimiter`) та нульові термінатори (`-z`)

За замовчуванням `cut` зберігає той самий роздільник у вихідному потоці, що був вказаний у параметрі `-d`. Якщо на вході поля розділялися двокрапкою, то й на виході між обраними колонками стоятиме двокрапка. GNU coreutils додає прапорець `--output-delimiter=STRING`, що дозволяє трансформувати роздільник на льоту без додаткових викликів `sed` чи `tr`:

```bash
# Перетворення формату passwd (:) у формат CSV (,)
cut -d: -f1,3,7 --output-delimiter=',' /etc/passwd
# Вивід: root,0,/bin/bash
```

Для надійної обробки шляхів до файлів, що можуть містити пробіли або символи переносу рядка, у GNU coreutils передбачено прапорець `-z` (`--zero-terminated`). У цьому режимі `cut` сприймає нульовий байт `\0` (NUL-термінатор) як кінець запису замість `\n`. Це дозволяє бездоганно комбінувати `cut` із виводом `find -print0`, `git status -z` або `grep -Z`:

```bash
# Безпечна вибірка першого поля з потоку з NUL-розділеними рядками
find . -maxdepth 2 -type f -printf "%u\t%p\0" | cut -z -f2 | xargs -0 ls -l
```

### Різниця між байтовим (`-b`) та символьним (`-c`) режимами

У ранніх версіях Unix, розрахованих на однобайтну таблицю ASCII, символи та байти були тотожними поняттями: 1 символ = 1 байт. З переходом сучасних операційних систем на кодування UTF-8 ця тотожність зникла: один символ (кодова позиція Юнікоду) може займати від 1 до 4 байтів.

- Прапорець `-b` (*bytes*) здійснює сліпе різання за абсолютними зміщеннями байтів у пам'яті без огляду на кодування. Якщо зріз `-b 1-3` потрапить посередині двобайтового або трибайтового символу UTF-8 (наприклад, кириличної літери `Ф`, яка кодується двома байтами `0xD0 0xA4`), на стандартний вихід піде обірвана послідовність байтів, що призведе до появи символів заміни на екрані термінала.
- Прапорець `-c` (*characters*) змушує `cut` декодувати потік за допомогою багатобайтових функцій C-бібліотеки (`mbrtowc` або внутрішніх декодерів UTF-8). Утиліта відраховує зміщення в логічних символах, коректно зберігаючи цілісність багатобайтових послідовностей.

> 🔧 **Навіщо це в реальній практиці:** якщо ви парсите бінарні протоколи, мережеві дампи або файли з гарантованим ASCII (наприклад, заголовки HTTP чи дамп пам'яті), прапорець `-b` працює швидше, оскільки уникає декодування таблиць UTF-8. Якщо ж дані містять локалізовані імена користувачів, повідомлення про помилки чи довільний текст, обов'язково використовуйте `-c` або режим полів `-f`.

### Прапорець `-s` та пастка рядків без роздільника

За замовчуванням, якщо утиліта `cut -d: -f1,2` зустрічає рядок, у якому роздільник `:` взагалі відсутній, вона **друкує цей рядок повністю**. Це типова поведінка POSIX, покликана зберігати коментарі та порожні рядки, але в конвеєрах обробки структурованих даних це нерідко стає джерелом прихованих аварій: рядок-заголовок чи випадковий службовий текст проходить крізь `cut` у незмінному вигляді й ламає наступні ланки конвеєра.

Щоб примусити `cut` ігнорувати рядки без роздільника, застосовують прапорець `-s` (`--only-delimited`):

```bash
# Без -s: заголовок пройде на вихід
printf "USER:ID\n# Коментар без двокрапок\nroot:0\n" | cut -d: -f1
# Вивід:
# USER
# # Коментар без двокрапок
# root

# З прапорцем -s: рядок без роздільника відкидається
printf "USER:ID\n# Коментар без двокрапок\nroot:0\n" | cut -d: -s -f1
# Вивід:
# USER
# root
```

### Фундаментальні обмеження `cut`

Утиліта `cut` має кілька жорстких конструктивних обмежень:
1. **Роздільником може бути лише один-єдиний байт.** Не можна вказати двосимвольний роздільник на зразок `-d '::'` або регулярний вираз. Спроба передати більше одного символа завершиться фатальною помилкою `cut: the delimiter must be a single character`.
2. **Відсутність автоматичного стискання пробілів.** Якщо таблиця відформатована шпальтами змінної ширини з кількома пробілами (як у виводі команд `ps`, `df -h` чи `ls -l`), команда `cut -d' ' -f2` вважатиме кожен пробіл окремим роздільником. Якщо між першим і другим словом стоїть чотири пробіли, `cut` побачить три порожні поля, і ви отримаєте порожній вивід замість очікуваного значення.
3. **Фіксований порядок виводу полів.** Команда `cut -d: -f3,1` виведе поля у вихідному порядку їх розташування в рядку (`1:3`), а не в порядку запиту (`3:1`). `cut` не вміє переставляти стовпці місцями.

Щоб застосувати `cut` до виводу команд із довільною кількістю пробілів, потік попередньо нормалізують за допомогою `tr -s ' '` (стискання повторів), як показано нижче:

```bash
# Отримання PID та імені команди з виводу ps aux:
# 1. tr -s ' ' згортає послідовності пробілів в один
# 2. cut вибирає друге (PID) та одинадцяте (команда) поля
ps aux | tr -s ' ' | cut -d' ' -f2,11
```

## 3. Утиліта `paste`: горизонтальне злиття та трансформація потоків

Якщо `cut` ділить один потік на кілька колонок по вертикалі, то утиліта `paste` виконує зворотну операцію: вона з'єднує рядки з кількох файлів або дескрипторів горизонтально, склеюючи їх через заданий роздільник.

### Паралельне злиття файлів бік-о-бік

За замовчуванням `paste` відкриває всі передані файли одночасно, вичитує по одному рядку з кожного файлу і записує їх у вихідний потік через символ табуляції `\t`:

```bash
# Створення тестових файлів
printf "host1\nhost2\nhost3\n" > hosts.txt
printf "192.168.1.10\n192.168.1.11\n192.168.1.12\n" > ips.txt

# Горизонтальне склеювання через кому
paste -d, hosts.txt ips.txt
# Вивід:
# host1,192.168.1.10
# host2,192.168.1.11
# host3,192.168.1.12
```

Якщо один із файлів коротший за інший, `paste` продовжує читати довший файл, підставляючи порожні поля для вичерпаного джерела, доки не дійдуть кінця всі файли.

### Циклічне чергування роздільників

Прапорець `-d` підтримує не лише один символ, а цілий рядок роздільників. Утиліта застосовує їх **циклічно** (*round-robin*) зліва направо між сусідніми стовпцями:

```bash
# Задаємо послідовність роздільників: ":" між 1 і 2 файлом, "\t" між 2 і 3
paste -d ':\t' file1.txt file2.txt file3.txt
```

Якщо роздільників менше, ніж стовпців мінус один, після використання останнього символу черга роздільників повертається до першого.

### Серіалізація рядків у єдиний рядок (`-s`)

Прапорець `-s` (`--serial`) перемикає `paste` з паралельного читання файлів на послідовне: утиліта зчитує весь перший файл і склеює всі його рядки в один горизонтальний рядок через вказаний роздільник, потім переходить до наступного файлу.

Це класичний інженерний спосіб перетворити список елементів, розділених символом нового рядка, у рядок для списків аргументів або SQL-запитів:

```bash
# Перетворення стовпця PID у список через кому: 1234,5678,9101
pgrep nginx | paste -sd, -

# Генерація списку для SQL IN (...):
printf "'alpha'\n'beta'\n'gamma'\n" | paste -sd, -
# Вивід: 'alpha','beta','gamma'
```

### Трюк із кількома дефісами (`paste - - -`) для групування потоку

Один із найпотужніших та найелегантніших патернів у Unix-конвеєрах — використання кількох дефісів `-` як аргументів для `paste`. За угодою POSIX символ `-` позначає стандартний вхід `stdin` (дескриптор `0`).

Коли `paste` отримує команду `paste - - -`, вона відкриває три логічних джерела, але **всі три джерела посилаються на один і той самий дескриптор файлу `stdin`**. У процесі формування першого вихідного рядка `paste`:
1. Читає перший рядок зі `stdin` для першої колонки (перший дефіс).
2. Читає наступний рядок із **того ж самого** `stdin` для другої колонки (другий дефіс).
3. Читає третій рядок із **того самого** `stdin` для третьої колонки (третій дефіс).
4. Виводить рядок `кол1\tкол2\tкол3\n` і повторює цикл.

```bash
# Перетворення лінійного списку значень у таблицю з 3 колонок:
seq 1 9 | paste - - -
# Вивід:
# 1	2	3
# 4	5	6
# 7	8	9

# Перетворення пар «ключ - значення» у двоколонковий CSV:
# Вхід: рядок 1 - назва метрики, рядок 2 - значення
printf "cpu_usage\n45.2\nmem_free\n1024\nload_avg\n1.15\n" | paste -d: - -
# Вивід:
# cpu_usage:45.2
# mem_free:1024
# load_avg:1.15
```

Ця операція виконується за один лінійний прохід без накопичення даних у проміжних масивах і без циклів оболонки `while read`, забезпечуючи максимальну швидкість групування.

## 4. Утиліта `join`: потокова реляційна алгебра над текстом

Утиліта `join` реалізує фундаментальну операцію реляційної алгебри — з'єднання двох відношень за спільним значенням атрибута (екві-з'єднання, аналог оператора `JOIN` у мові SQL). На відміну від реляційних баз даних, які можуть створювати хеш-таблиці в оперативній пам'яті (Hash Join) або індекси на диску, `join` працює за класичним потоковим алгоритмом **злиття двох вказівників** (*Two-Pointer Merge Join*).

![Реляційне з'єднання двох відсортованих текстових потоків за спільним ключем за допомогою join](/root/sys/sys-unix/field-tools/img/join-relational-logic.svg)
*Потоковий двовказівниковий алгоритм з'єднання утиліти join: внутрішнє з'єднання, зовнішнє збереження непарних ключів та анти-з'єднання.*

### Алгоритм роботи та вимога `LC_ALL=C`

Алгоритм `join` спирається на жорсткий інваріант: **обидва вхідні файли мають бути заздалегідь відсортовані за ключовим полем відповідно до одних і тих самих правил порівняння**.

Працюючи з відсортованими потоками `File1` та `File2`, утиліта тримає в пам'яті лише по одному поточному рядку з кожного джерела:
1. Порівнюються ключі поточних рядків: `key1` та `key2`.
2. Якщо `key1 == key2`: знайдено збіг. `join` формує об'єднаний рядок (за замовчуванням: спільний ключ, потім залишок рядка 1, потім залишок рядка 2) і читає наступні рядки з однаковими ключами.
3. Якщо `key1 < key2`: оскільки файл 2 відсортований, ключ `key1` уже гарантовано ніколи не з'явиться далі у файлі 2. Утиліта пропускає рядок із файлу 1 і читає з нього наступний рядок.
4. Якщо `key1 > key2`: утиліта пропускає рядок із файлу 2 і читає з нього наступний.

Складність такого алгоритму за часом становить строго `O(N + M)` (де `N` і `M` — кількості рядків у файлах), а за пам'яттю — строго `O(1)`. Це дозволяє з'єднувати файли розміром сотні гігабайтів на машині з мінімальним обсягом RAM.

> ⚠️ **Критична вимога коллації та пастка діапазонів ключів sort:**
> 1. Сортування файлів за допомогою `sort` та їх подальше з'єднання через `join` **мусять виконуватися в одній і тій самій локалі**, бажано з `LC_ALL=C`. Якщо сортування виконати в локалі `en_US.UTF-8`, а `join` викликати з `LC_ALL=C`, алгоритм двох вказівників при першій же розбіжності вважатиме потік несортованим і **мовчазно пропустить** валідні збіги або завершиться аварійно з повідомленням `join: input is not in sorted order`.
> 2. При сортуванні ключа завжди вказуйте кінець поля: `sort -k1,1`, а **не** `sort -k1`. Прапорець `-k1` без другого числа означає сортування від першого поля **і до кінця рядка**, що спотворює порядок ключів при різній довжині решти колонок!

```bash
# Правильний шаблон підготовки та з'єднання:
export LC_ALL=C
sort -k1,1 -t, users.csv -o users.sorted.csv
sort -k1,1 -t, orders.csv -o orders.sorted.csv
join -t, -1 1 -2 1 users.sorted.csv orders.sorted.csv
```

### Режими з'єднання: Inner, Outer та Anti-Join

За замовчуванням `join` виконує **внутрішнє з'єднання** (*Inner Join*): на вихід потрапляють лише ті записи, для яких ключ знайдено в обох файлах одночасно.

Для зміни типу з'єднання використовуються такі параметри:
- `-a 1`: **Left Outer Join** — окрім спільних записів, виводити також усі рядки з першого файлу, які не знайшли пари в другому.
- `-a 2`: **Right Outer Join** — додатково виводити всі непарні рядки з другого файлу.
- `-a 1 -a 2`: **Full Outer Join** — виводити всі рядки з обох файлів незалежно від наявності пари.
- `-v 1`: **Left Anti-Join** — виводити **виключно** ті рядки з першого файлу, які **не мають пари** у другому (дуже зручно для пошуку втрачених або застарілих облікових записів).
- `-v 2`: **Right Anti-Join** — виводити виключно непарні рядки з другого файлу.

### Керування форматом виводу (`-o`), заміна пропущених полів (`-e`) та заголовки

Якщо виконується зовнішнє з'єднання (`-a 1`), у рядках, які не мали пари у файлі 2, поля другого файлу будуть відсутні. Щоб результат залишався валідною таблицею однакової ширини, використовують прапорець `-e STRING` (заміна відсутніх полів на заданий рядок) разом із явною специфікацією колонок через `-o`:

```bash
# users.txt (ID, Ім'я)
# 101 John
# 102 Alice
# 103 Bob

# departments.txt (ID, Відділ)
# 101 Engineering
# 103 Marketing

# Left Join із заміною відсутніх відділів на 'NONE':
join -1 1 -2 1 -a 1 -e 'NONE' -o 1.1,1.2,2.2 users.txt departments.txt
# Вивід:
# 101 John Engineering
# 102 Alice NONE
# 103 Bob Marketing
```

Формат специфікатора `-o`: `ФАЙЛ.ПОЛЕ` через кому (наприклад, `1.1` — перше поле першого файлу, `2.2` — друге поле другого файлу). Ключове слово `-o auto` в GNU coreutils автоматично розширює кількість колонок до максимальної для даного рядка.

Крім того, GNU-версія утиліти підтримує прапорець `--header`, який змушує `join` сприймати перший рядок кожного файлу як назви колонок: ці рядки з'єднуються одразу без перевірки порядку сортування і виводяться як шапка підсумкової таблиці.

## 5. Утиліта `comm`: операції над множинами у впорядкованих послідовностях

Утиліта `comm` порівнює два попередньо відсортовані файли рядок за рядком і представляє результат у вигляді трьох паралельних стовпців, розділених символами табуляції:
- **Колонка 1** (без відступу): рядки, що існують **тільки в першому файлі** (`File1 \ File2`).
- **Колонка 2** (відступ один `\t`): рядки, що існують **тільки в другому файлі** (`File2 \ File1`).
- **Колонка 3** (відступ два `\t\t`): рядки, що є **спільними для обох файлів** (`File1 ∩ File2`).

![Модель стовпців та матриця придушення утиліти comm для операцій над множинами](/root/sys/sys-unix/field-tools/img/comm-set-operations.svg)
*Відображення трьох стандартних колонок comm на теоретико-множинні операції перетину, різниці та симетричної різниці.*

### Матриця вимкнення стовпців (`-1`, `-2`, `-3`)

Головна сила `comm` розкривається через прапорці **придушення стовпців**. Прапорці `-1`, `-2`, `-3` приховують відповідні колонки у виводі. Комбінуючи їх, ми отримуємо будь-яку теоретико-множинну операцію над списками:

```
┌────────────────────────────────────────┬────────────────────────────────┐
│ Множинна операція                      │ Команда comm                   │
├────────────────────────────────────────┼────────────────────────────────┤
│ Перетин (A ∩ B)                        │ comm -12 fileA fileB           │
│ Різниця (A \ B) — елементи лише в A    │ comm -23 fileA fileB           │
│ Різниця (B \ A) — елементи лише в B    │ comm -13 fileA fileB           │
│ Симетрична різниця (A △ B)             │ comm -3 fileA fileB            │
│ Усі записи з розподілом по 3 стовпцях  │ comm fileA fileB               │
└────────────────────────────────────────┴────────────────────────────────┘
```

> 🔧 **Практичний приклад: аудитування встановлених пакетів.**
> Припустимо, у вас є еталонний список пакетів `base-packages.txt` і поточний список встановлених пакетів на сервері `current-packages.txt`. Обидва списки відсортовані.

```bash
# Знайти пакети, встановлені понад еталон (є в current, немає в base):
comm -13 base-packages.txt current-packages.txt

# Знайти видалені базові пакети (були в base, зникли в current):
comm -23 base-packages.txt current-packages.txt

# Знайти пакети, що точно відповідають еталону:
comm -12 base-packages.txt current-packages.txt
```

### Підсумкова статистика (`--total`) та одноразові конвеєри через Process Substitution

Сучасні версії `comm` у GNU coreutils містять прапорець `--total`, який після виводу даних друкує підсумковий четвертий рядок із кількістю рядків у кожній із трьох категорій.

Щоб не створювати проміжні тимчасові файли на диску при порівнянні виводу динамічних команд, застосовують підстановку процесів оболонки (*process substitution*) `<(...)`:

```bash
# Порівняння списків модулів ядра на двох серверах на льоту:
comm -3 <(ssh srv1 lsmod | cut -d' ' -f1 | LC_ALL=C sort) \
        <(ssh srv2 lsmod | cut -d' ' -f1 | LC_ALL=C sort)
```

Як і `join`, `comm` вимагає суворого однакового сортування вхідних потоків (`LC_ALL=C sort`). Якщо рядок у файлі з'явиться не в лексикографічному порядку, `comm` видасть попередження і не зможе коректно знайти спільні елементи далі по тексту.

## 6. Утиліта `tr`: посимвольна таблична трансляція та потокова нормалізація

На відміну від решти фільтрів coreutils, утиліта `tr` (*translate*) володіє унікальною властивістю: **вона взагалі не приймає імена файлів як аргументи командного рядка**. `tr` спроєктована виключно як чистий потоковий фільтр, що читає стандартний вхід `stdin` (дескриптор 0) і записує результат у стандартний вихід `stdout` (дескриптор 1).

### Внутрішній механізм: пряма таблиця відображення

Всередині `tr` влаштована як гранично оптимізована 256-елементна таблиця перекодування (`unsigned char map[256]`). На етапі ініціалізації аргументи `SET1` та `SET2` транслюються в прямі індекси масиву:

```
map[0x00] = 0x00
...
map['a']  = 'A'   (0x61 -> 0x41)
map['b']  = 'B'   (0x62 -> 0x42)
...
map[0xFF] = 0xFF
```

Після ініціалізації таблиці гарячий цикл обробки даних являє собою безрозгалужену пряму підстановку з вхідного буфера у вихідний:

:::tabs
```c
/* Гарячий цикл табличної трансляції байтів на C */
#include <unistd.h>
#include <stddef.h>

#define BUF_SIZE 65536

void fast_tr_loop(const unsigned char map[256]) {
    unsigned char in_buf[BUF_SIZE];
    unsigned char out_buf[BUF_SIZE];
    ssize_t n_read;

    while ((n_read = read(0, in_buf, BUF_SIZE)) > 0) {
        for (ssize_t i = 0; i < n_read; ++i) {
            out_buf[i] = map[in_buf[i]];
        }
        write(1, out_buf, (size_t)n_read);
    }
}
```
```cpp
// Гарячий цикл табличної трансляції байтів на C++20
#include <array>
#include <vector>
#include <iostream>
#include <span>
#include <unistd.h>

constexpr size_t BUF_SIZE = 65536;

void fast_tr_loop_cpp(const std::array<unsigned char, 256>& map) {
    std::vector<unsigned char> in_buf(BUF_SIZE);
    std::vector<unsigned char> out_buf(BUF_SIZE);
    ssize_t n_read = 0;

    while ((n_read = ::read(0, in_buf.data(), in_buf.size())) > 0) {
        std::span<const unsigned char> in_span(in_buf.data(), static_cast<size_t>(n_read));
        std::span<unsigned char> out_span(out_buf.data(), static_cast<size_t>(n_read));

        for (size_t i = 0; i < in_span.size(); ++i) {
            out_span[i] = map[in_span[i]];
        }
        ::write(1, out_span.data(), out_span.size());
    }
}
```
:::

Оскільки тут відсутні розгалуження `if` або `switch` у розрахунку на окремий байт, процесорний конвеєр інструкцій працює без зривів передбачення переходів (*branch mispredictions*), забезпечуючи швидкість обробки на рівні кількох гігабайтів за секунду.

![Внутрішня архітектура побайтової трансляції та фільтрації утиліти tr](/root/sys/sys-unix/field-tools/img/tr-byte-lookup-table.svg)
*Обробка вхідного потоку stdin через пряму 256-елементну таблицю відображення без розгалужень у гарячому циклі.*

### Режими роботи: трансляція, видалення, стискання, доповнення

1. **Трансляція (заміна 1-в-1):** `tr SET1 SET2`
   Кожен символ із множини `SET1` замінюється на відповідний за індексом символ із `SET2`. Якщо `SET2` коротший за `SET1`, у стандарті POSIX останній символ `SET2` дублюється до досягнення довжини `SET1`.

   ```bash
   # Перетворення латинських літер у верхній регістр
   cat input.txt | tr 'a-z' 'A-Z'
   # Або з використанням POSIX-класів символів:
   cat input.txt | tr '[:lower:]' '[:upper:]'
   ```

2. **Видалення символів (`-d` / `--delete`):** `tr -d SET1`
   Усі байти, що входять до `SET1`, пропускаються і не потрапляють у вихідний потік.

   ```bash
   # Видалення повернень каретки Windows (CRLF -> LF)
   tr -d '\r' < windows_file.txt > unix_file.txt

   # Видалення всіх нечислових символів
   echo "Phone: +38 (044) 123-45-67" | tr -d ' ()+-'
   # Вивід: 380441234567
   ```

3. **Стискання повторів (`-s` / `--squeeze-repeats`):** `tr -s SET1`
   Послідовності однакових символів із множини `SET1`, що йдуть підряд, замінюються на один екземпляр цього символу.

   ```bash
   # Стискання множинних пробілів в один
   echo "alpha     beta   gamma" | tr -s ' '
   # Вивід: alpha beta gamma

   # Видалення порожніх рядків (стискання кількох \n в один)
   printf "line1\n\n\n\nline2\n" | tr -s '\n'
   # Вивід:
   # line1
   # line2
   ```

4. **Доповнення множини (`-c` / `-C` / `--complement`):**
   Прапорець `-c` інвертує множину `SET1`, застосовуючи дію до всіх байтів, окрім зазначених.

   ```bash
   # Залишити в тексті ТІЛЬКИ друковані літери та цифри, видаливши решту:
   tr -cd '[:alnum:]\n' < dirty_log.txt

   # Замінити всі неалфавітні символи на символ нового рядка (отримання списку слів):
   tr -cs '[:alpha:]' '\n' < article.txt
   ```

## 7. Інженерний розбір: системна реалізація потокового з'єднання

Щоб наочно продемонструвати внутрішній механізм потокових фільтрів, розглянемо повноцінну реалізацію власної версії алгоритму злиття двох впорядкованих текстових потоків (спрощений аналог `join` для двох файлів із роздільником табуляції) мовами C та C++.

Обидві реалізації демонструють принцип нульового повторного сканування: дані зчитуються блоками через буферизовані потоки, порівнюються на льоту та записуються у вихідний потік без побудови індексів і без завантаження файлів у пам'ять.

```c
/* fast_stream_join.c — Потокове реляційне з'єднання двох відсортованих списків */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define DELIM '\t'

int main(int argc, char *argv[]) {
    if (argc < 3) {
        fprintf(stderr, "Використання: %s file1.tsv file2.tsv\n", argv[0]);
        return EXIT_FAILURE;
    }

    FILE *f1 = fopen(argv[1], "re");
    FILE *f2 = fopen(argv[2], "re");
    if (!f1 || !f2) {
        perror("Помилка відкриття файлів");
        if (f1) fclose(f1);
        if (f2) fclose(f2);
        return EXIT_FAILURE;
    }

    char *line1 = NULL, *line2 = NULL;
    size_t cap1 = 0, cap2 = 0;
    ssize_t len1 = 0, len2 = 0;

    /* Зчитування перших рядків */
    len1 = getline(&line1, &cap1, f1);
    len2 = getline(&line2, &cap2, f2);

    /* Двовказівниковий марш O(N + M) */
    while (len1 > 0 && len2 > 0) {
        /* Прибираємо символ переносу рядка */
        if (line1[len1 - 1] == '\n') line1[--len1] = '\0';
        if (line2[len2 - 1] == '\n') line2[--len2] = '\0';

        /* Копії рядків для виділення ключів без пошкодження вихідного тексту */
        char key1_buf[256], key2_buf[256];
        char *d1 = memchr(line1, DELIM, len1);
        char *d2 = memchr(line2, DELIM, len2);

        size_t k1_len = d1 ? (size_t)(d1 - line1) : (size_t)len1;
        size_t k2_len = d2 ? (size_t)(d2 - line2) : (size_t)len2;

        snprintf(key1_buf, sizeof(key1_buf), "%.*s", (int)k1_len, line1);
        snprintf(key2_buf, sizeof(key2_buf), "%.*s", (int)k2_len, line2);

        int cmp = strcmp(key1_buf, key2_buf);
        if (cmp == 0) {
            /* Спільний ключ: виводимо ключ, залишок файлу 1, залишок файлу 2 */
            const char *val1 = d1 ? d1 + 1 : "";
            const char *val2 = d2 ? d2 + 1 : "";
            printf("%s\t%s\t%s\n", key1_buf, val1, val2);

            len1 = getline(&line1, &cap1, f1);
            len2 = getline(&line2, &cap2, f2);
        } else if (cmp < 0) {
            /* Ключ 1 менший — просуваємо файл 1 */
            len1 = getline(&line1, &cap1, f1);
        } else {
            /* Ключ 2 менший — просуваємо файл 2 */
            len2 = getline(&line2, &cap2, f2);
        }
    }

    free(line1);
    free(line2);
    fclose(f1);
    fclose(f2);
    return EXIT_SUCCESS;
}
```

```cpp
// fast_stream_join.cpp — Ідіоматичне реляційне з'єднання на C++20
#include <iostream>
#include <fstream>
#include <string>
#include <string_view>
#include <memory>
#include <system_error>

constexpr char DELIM = '\t';

struct Record {
    std::string line;
    std::string_view key;
    std::string_view value;

    static Record parse(std::string raw_line) {
        Record rec;
        rec.line = std::move(raw_line);
        std::string_view sv(rec.line);
        
        auto pos = sv.find(DELIM);
        if (pos == std::string_view::npos) {
            rec.key = sv;
            rec.value = {};
        } else {
            rec.key = sv.substr(0, pos);
            rec.value = sv.substr(pos + 1);
        }
        return rec;
    }
};

int main(int argc, char *argv[]) {
    if (argc < 3) {
        std::cerr << "Використання: " << argv[0] << " file1.tsv file2.tsv\n";
        return 1;
    }

    // Прискорення стандартного I/O потоків C++
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);

    std::ifstream stream1(argv[1]);
    std::ifstream stream2(argv[2]);

    if (!stream1 || !stream2) {
        std::cerr << "Помилка відкриття файлів для зчитування\n";
        return 1;
    }

    std::string raw1, raw2;
    bool has1 = static_cast<bool>(std::getline(stream1, raw1));
    bool has2 = static_cast<bool>(std::getline(stream2, raw2));

    while (has1 && has2) {
        auto rec1 = Record::parse(raw1);
        auto rec2 = Record::parse(raw2);

        if (rec1.key == rec2.key) {
            // Ключі збіглися: прямий запис у stdout без проміжних алокацій
            std::cout << rec1.key << DELIM << rec1.value << DELIM << rec2.value << '\n';
            has1 = static_cast<bool>(std::getline(stream1, raw1));
            has2 = static_cast<bool>(std::getline(stream2, raw2));
        } else if (rec1.key < rec2.key) {
            has1 = static_cast<bool>(std::getline(stream1, raw1));
        } else {
            has2 = static_cast<bool>(std::getline(stream2, raw2));
        }
    }

    return 0;
}
```

## 8. Практичні пастки, правила безпеки та зведена матриця

Під час побудови виробничих конвеєрів із використанням утиліт полів найчастіше трапляються чотири типи типових помилок:

### 1. Несумісність правил локалі між `sort`, `join` та `comm`
Якщо дані сортуються за замовчуванням у сучасних Linux-дистрибутивах (де зазвичай активна локаль `en_US.UTF-8` або `uk_UA.UTF-8`), правила сортування визначаються складними правилами мовної коллації Unicode. Символи пунктуації, пробіли та регістр можуть ігноруватися або групуватися за правилами природної мови.

Утиліти `join` та `comm` під час перевірки впорядкованості виконують побайтове порівняння через функцію `strcoll()` або пряме `strcmp()`. Якщо порядок у файлі не відповідає очікуванням `join`, виникає тиха втрата даних.

**Правило безпеки:** Усі конвеєри, що використовують `sort`, `join` та `comm`, завжди повинні явно фіксувати байтове сортування через змінну середовища `LC_ALL=C`:
```bash
# Безпечний патерн конвеєра:
LC_ALL=C join -t$'\t' <(LC_ALL=C sort -k1,1 f1.tsv) <(LC_ALL=C sort -k1,1 f2.tsv)
```

### 2. Порожні поля проти відсутніх роздільників у `cut`
При обробці файлів формату CSV чи TSV слід чітко розрізняти:
- Порожнє значення поля: `alpha,,gamma` (два роздільники поруч). `cut -d, -f2` поверне порожній рядок (довжина 0), але коректно змістить покажчик на третє поле.
- Послідовності пробілів: `alpha   gamma`. `cut -d' ' -f2` поверне порожній рядок (перший пробіл з послідовності), а поле `gamma` опиниться на позиції `-f4` або `-f5`.

Якщо дані містять змінну кількість роздільників-пробілів, завжди використовуйте попереднє стискання через `tr -s ' '` або переходьте на `awk`.

### 3. Багатобайтові роздільники та кодування UTF-8 у `tr`
Утиліта `tr` у більшості реалізацій (зокрема в GNU coreutils до останніх версій) працює **суто побайтово**.
Спроба виконати трансляцію кириличних літер:
```bash
# ПОМИЛКА: tr працюватиме з окремими байтами UTF-8, руйнуючи кодування
echo "привіт" | tr 'а-я' 'А-Я'
```
призведе до повного спотворення тексту, оскільки діапазон `'а-я'` буде інтерпретовано як послідовність шістнадцяткових байтів `0xD0..0xD1`, які переплутаються між собою.

**Правило безпеки:** Для конвертації регістру та заміни не-ASCII символів Юнікоду використовуйте `sed`, `awk` або системні інструменти з підтримкою ICU/UTF-8. `tr` призначений виключно для однобайтних символів ASCII (коди 0x00–0x7F) та видалення бінарних байтів на зразок `\r`, `\0`, `\t`.

### 4. Наскрізний приклад: аналіз аномальних з'єднань у системних журналах

Розглянемо практичну системну задачу: потрібно виявити IP-адреси з підозрілою активністю у файлі журналу вебсервера `access.log`, витягнути їхні країни з геобази `geoip.csv` та перевірити, чи є ці IP-адреси в білому списку адміністраторів `whitelist.txt`.

Комплексний конвеєр, що поєднує всі розглянуті утиліти, виглядає так:

```bash
#!/bin/sh
export LC_ALL=C

# 1. Витягуємо IP-адреси з журналу, рахуємо кількість запитів і сортуємо за IP:
# tr -s ' ' стискає пробіли -> cut бере першу колонку (IP) -> sort | uniq -c рахує частоту
cut -d' ' -f1 access.log | LC_ALL=C sort | uniq -c | tr -s ' ' | sed 's/^ //' | cut -d' ' -f1,2 > ip_counts.txt
# Формат ip_counts.txt: КІЛЬКІСТЬ IP

# 2. Формуємо файл IP -> КІЛЬКІСТЬ, відсортований за IP:
cut -d' ' -f2,1 --output-delimiter=',' ip_counts.txt | LC_ALL=C sort -t, -k1,1 > ip_by_key.csv

# 3. З'єднуємо з таблицею країн geoip.csv (IP,COUNTRY) через join:
# Результат: IP,КІЛЬКІСТЬ,COUNTRY
join -t, -1 1 -2 1 -o 1.1,1.2,2.2 ip_by_key.csv <(LC_ALL=C sort -t, -k1,1 geoip.csv) > ip_with_geo.csv

# 4. Знаходимо всі IP, яких НЕМАЄ в білому списку whitelist.txt, за допомогою comm:
# comm -23 вибирає елементи, присутні тільки в першому файлі
comm -23 <(cut -d, -f1 ip_with_geo.csv | LC_ALL=C sort) \
         <(LC_ALL=C sort whitelist.txt) > suspicious_ips.txt

# 5. Серіалізуємо список підозрілих IP в один рядок для виклику блокування iptables:
BLOCKED_LIST=$(paste -sd, suspicious_ips.txt)
echo "Підозрілі адреси для блокування: ${BLOCKED_LIST}"
```

### 5. Зведена матриця вибору інструментів

Нижче наведено практичний орієнтир для вибору оптимального фільтра залежно від структури вхідних даних та цільової операції:

| Завдання | Оптимальний інструмент | Чому саме він |
| :--- | :--- | :--- |
| Витягнути фіксовану колонку за сталим роздільником (наприклад, `:`) | `cut -d: -fN` | Найшвидший I/O, нуль накладних витрат на парсинг |
| Витягнути колонку з виводу системних утиліт (`ps`, `df`, `ls`) | `tr -s ' ' \| cut -d' ' -fN` | Стискання пробілів + швидкий зріз |
| Об'єднати два файли однакової довжини по рядках | `paste -d, f1 f2` | Паралельне горизонтальне читання за один прохід |
| Розбити один довгий стовпчик на N колонок | `paste - - -` | Групування з одного fd stdin без проміжних масивів |
| Об'єднати два списки за спільним ID | `LC_ALL=C join -t, f1 f2` | Лінійний час `O(N+M)`, пам'ять `O(1)` для гігабайтних файлів |
| Знайти, які рядки додалися або зникли між двома конфігами | `LC_ALL=C comm -3 f1 f2` | Швидке обчислення симетричної різниці без хешування |
| Знайти точний перетин двох списків хешів чи IP-адрес | `LC_ALL=C comm -12 f1 f2` | Ефективне потокове обчислення перетину множин |
| Очистити файл від Windows CRLF або недрукованих байтів | `tr -d '\r'` або `tr -cd '[:print:]\n'` | Пряма таблична фільтрація 256 байтів на швидкості пам'яті |
| Складна логіка: нерівні пробіли, обчислення суми, фільтрація за regex | `awk` | Повноцінна мова з підтримкою регулярних виразів та арифметики |
