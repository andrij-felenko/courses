# 📋 Довідник символів vDSO, типів AUXV та полів vvar

У цьому довіднику зібрано вичерпну технічну специфікацію інтерфейсу vDSO: константи допоміжного вектора (Auxiliary Vector), перелік експортованих символів для різних апаратних архітектур, структуру даних сторінки `vvar`, специфікацію версіонування символів у форматі ELF, а також параметри ядра Linux для керування vDSO.

## Сполучення ядра та простору користувача: Auxiliary Vector (auxv)

Під час системного виклику `execve` ядро Linux готує віртуальний адресний простір для нового процесу. Перш ніж передати керування динамічному лінкеру або точці входу програми (`_start`), ядро копіює на стек процесу спеціальну структуру — Auxiliary Vector (допоміжний вектор). Допоміжний вектор є масивом пар елементів типу `Elf64_auxv_t`, де кожен елемент складається з ключа `a_type` та значення `a_un.a_val`.

Допоміжний вектор виступає первинним джерелом ініціалізаційних даних для динамічного завантажувача `ld-linux.so`. Саме через `auxv` лінкер дізнається про наявність та розташування vDSO у пам'яті.

## Експортовані символи vDSO за апаратними архітектурами

Бінарний образ vDSO є повноцінною розділюваною бібліотекою ELF і містить секцію динамічних символів `.dynsym`, а також таблицю версій символів `.gnu.version`. Назва об'єкта vDSO у полі `DT_SONAME` зазвичай має вигляд `linux-vdso.so.1` (або `linux-gate.so.1` на 32-бітних системах x86).

### 1. Архітектура x86_64 (AMD64 / Intel 64)

- `__vdso_clock_gettime`: Головна функція обчислення точного системного часу для годинників `CLOCK_REALTIME`, `CLOCK_MONOTONIC`, `CLOCK_BOOTTIME`, `CLOCK_TAI`, `CLOCK_MONOTONIC_RAW`.
- `__vdso_gettimeofday`: Отримання астрономічного часу в секундах та мікросекундах (структура `struct timeval`).
- `__vdso_time`: Отримання системного часу в секундах від початку Епохи Unix (1 січня 1970 року).
- `__vdso_getcpu`: Визначення номера поточного процесорного ядра (CPU ID) та ідентифікатора NUMA-вузла без виконання системного виклику.
- `__vdso_clock_getres`: Отримання роздільної здатності конкретного системного годинника у наносекундах.
- `__vdso_getrandom`: Криптографічно стійка генерація випадкових чисел у просторі користувача без виконання системного виклику через алгоритм ChaCha20 (додано у ядрі Linux 6.11).
- `__vdso_sgx_enter_enclave`: Спеціалізована точка входу для роботи з апаратними анклавами безпеки Intel SGX (Software Guard Extensions).

### 2. Архітектура i386 (32-bit x86)

- `__kernel_vsyscall`: Швидка точка входу для системних викликів. Автоматично вибирає найшвидший апаратний інструкційний перехід (`sysenter`, `syscall` або старе переривання `int 0x80`) залежно від моделі процесора.
- `__vdso_clock_gettime`: 32-бітна реалізація читання системного часу.
- `__vdso_gettimeofday`: 32-бітна реалізація застарілого API `gettimeofday`.
- `__vdso_clock_gettime64`: Новий 64-бітний інсталяційний символ для 32-бітних систем, покликаний розв'язати проблему 2038 року (Y2038 problem) шляхом передачі 64-бітних значень секунд у `struct __timespec64`.
- `__vdso_clock_getres`: Читання роздільної здатності таймера на 32-бітних системах.

### 3. Архітектура ARM64 (AArch64)

- `__kernel_clock_gettime`: Зчитування системного часу через апаратний лічильник `cntvct_el0`.
- `__kernel_gettimeofday`: Версія `gettimeofday` для 64-бітних процесорів ARM.
- `__kernel_clock_getres`: Читання роздільної здатності системного годинника ARM.
- `__kernel_rt_sigreturn`: Обробник повернення з обробника сигналів (Signal Trampoline), який забезпечує відновлення маски сигналів та контексту регістрів після завершення виконання обробника сигналу користувача.

### 4. Архітектура RISC-V (RV64)

- `__vdso_clock_gettime`: Читання системного часу через апаратний регістр `rdtime`.
- `__vdso_gettimeofday`: Отримання астрономічного часу на архітектурі RISC-V.
- `__vdso_clock_getres`: Зчитування роздільної здатності годинника.
- `__vdso_getcpu`: Визначення ідентифікатора апаратного потоку RISC-V (HART ID — Hardware Thread).
- `__vdso_flush_icache`: Синхронізація інструкційного кешу процесора після динамічного генерації коду у пам'яті (JIT-компілятори V8, JVM, LuaJIT).

## Внутрішня структура даних сторінки vvar (vdso_data)

Сторінка пам'яті `vvar` відображається у простір користувача з правами **Тільки для читання (`r--p`)**. Вона містить масив структур `vdso_data`, у яких ядро Linux зберігає актуальні параметри синхронізації часу.

Нижче наведено розбір полів вихідної структури `struct vdso_data` з вихідного коду ядра Linux (`include/vdso/datapage.h`):

:::tabs
```c
/* Вихідна структура з заголовка ядра Linux include/vdso/datapage.h */
struct vdso_timestamp {
    uint64_t sec;       /* Секунди поточного часу */
    uint64_t nsec;      /* Наносекунди поточного часу */
};

struct vdso_data {
    uint32_t seq;       /* 32-бітний лічильник послідовності Seqlock */
    int32_t  clock_mode;/* Апаратний режим годинника (VDSO_CLOCKMODE_*) */
    uint64_t cycle_last;/* Значення TSC/таймера під час останнього тику ядра */
    uint64_t mask;      /* Битмаска розрядності апаратного лічильника */
    uint32_t mult;      /* Множник для переведення тактів у наносекунди */
    uint32_t shift;     /* Зсув праворуч для нормування множення */
    
    struct vdso_timestamp basetime[CS_BASES]; /* Масив базового часу для різних годинників */
    
    int32_t  tz_minuteswest; /* Зсув часового поясу у хвилинах на захід від Гринвіча */
    int32_t  tz_dsttime;     /* Прапорець літнього часу (DST) */
    
    uint32_t hrtimer_res;    /* Роздільна здатність системного таймера високої точності */
    uint32_t __unused;       /* Поле вирівнювання структури у пам'яті */
};
```

#include <array>

    std::uint64_t nsec;  // Наносекунди поточного часу

    std::uint64_t cycle_last; // Значення TSC під час тику ядра

### Деталізація режимів апаратного годинника (`clock_mode`)

Поле `clock_mode` визначає, яким саме чином vDSO має зчитувати апаратний лічильник процесора. Якщо ядро виявляє проблеми з апаратним забігом таймерів, воно змінює це поле, змушуючи vDSO робити фолбек на системний виклик.

- `VDSO_CLOCKMODE_NONE` (`0`): Апаратний таймер у просторі користувача недоступний або непридатний для використання. vDSO негайно здійснює відкат на системний виклик `syscall`.
- `VDSO_CLOCKMODE_TSC` (`1`): Використовується апаратний лічильник тактів процесора x86 (інструкції `rdtsc` / `rdtscp`).
- `VDSO_CLOCKMODE_PVCLOCK` (`2`): Використовується паравіртуалізований годинник гіпервізора KVM (KVM PV clock), де значення тактів зчитуються з додатково відображеної сторінки віртуалізації.
- `VDSO_CLOCKMODE_HVCLOCK` (`3`): Використовується паравіртуалізований годинник гіпервізора Microsoft Hyper-V.
- `VDSO_CLOCKMODE_ARCHTIMER` (`4`): Використовується системний лічильник архітектури ARM64 (регістр `cntvct_el0`).

## Специфікація версіонування символів ELF у vDSO

Для забезпечення сумісності із бінарними файлами, зібраними 10–20 років тому, vDSO використовує стандартний механізм версіонування символів ELF (GNU Symbol Versioning). При динамічному зв'язуванні лінкер `ld-linux.so` шукає не просто ім'я символу, а комбінацію імені символу та тегу версії.

Приклади тегів версій символів vDSO:
- `LINUX_2.6`: Базовий тег версії для перших систем із підтримкою vDSO на архітектурах x86_64 та i386.
- `LINUX_2.6.39`: Тег розширення для додаткових системних викликів.
- `LINUX_6.11`: Сучасний тег версії для новенького символу `__vdso_getrandom`.

Дерево залежностей версій описується у секціях `.gnu.version` та `.gnu.version_d` бінарного файлу vDSO. Якщо програма вимагає версію символу `__vdso_clock_gettime@@LINUX_2.6`, ядро гарантує збереження стабільного ABI цієї функції незалежно від оновлень версії ядра Linux.

## Параметри командного рядка ядра для керування vDSO та vsyscall

Адміністратори та системні розробники можуть змінювати поведінку vDSO та застарілого vsyscall під час завантаження ядра Linux за допомогою спеціальних параметрів у загрузчику (GRUB2 / systemd-boot):

### 1. Параметр `vdso`

- `vdso=1` (за замовчуванням): Увімкнути відображення vDSO у простір пам'яті кожного нового процесу.
- `vdso=0`: Вимкнути мапування vDSO (доступно лише на деяких 32-бітних архітектурах та спеціалізованих збірках ядра). Усі виклики C-бібліотеки починають примусово здійснювати класичний системний виклик `syscall`.

### 2. Параметр `vsyscall`

- `vsyscall=none`: Повністю вимкнути сторінку `vsyscall` за адресою `0xffffffffff600000`. Зчитування цієї адреси спричиняє `SIGSEGV`. Покращує безпеку системи.
- `vsyscall=emulate` (за замовчуванням у багатьох дистрибутивах): Ядро прибирає права на виконання зі сторінки `vsyscall`. При спробі виконання коду відбувається апаратний трап, який перехоплюється ядром і симулює повернення значення.
- `vsyscall=xonly`: Дозволяє виконання коду за фіксованою адресою, але забороняє читання (Memory Read Protect).

## Особливості трасування та інспекції: vDSO проти strace / ptrace

Оскільки функції vDSO виконуються повністю у просторі користувача без системних викликів, традиційна утиліта трасування системних викликів `strace` **не бачить** виклики `clock_gettime()` або `gettimeofday()`, якщо вони пройшли через vDSO.

Особливості діагностики:
- **Поведінка `strace`**: При запуску `strace ./app` ви не побачите рядків `clock_gettime(...)`, бо перехоплювач `ptrace` спрацьовує лише на виклик інструкції `syscall`.
- **Аналіз через eBPF / uprobes**: Для відстеження викликів vDSO використовуються утиліти eBPF (`bpftrace`), які встановлюють пользовательські зонди (uprobes) безпосередньо на функції відображеної у пам'ять бібліотеки `linux-vdso.so.1`.
