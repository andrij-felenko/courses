# 📋 Довідник позиційних параметрів та утиліти getopts

Цей довідник містить повну нормативну специфікацію спеціальних змінних командної оболонки POSIX для роботи з аргументами, правила розгортання параметрів, сигнатури вбудованих команд `shift` і `set`, а також вичерпний опис інтерфейсу, внутрішніх змінних стану та кодів повернення вбудованого аналізатора `getopts` разом із системним еквівалентом C/C++.

## 1. Спеціальні та позиційні змінні оболонки

Усі змінні позиційних параметрів та службового стану встановлюються інтерпретатором під час ініціалізації середовища або виклику функцій. Вони є частиною базового синтаксису стандарту IEEE Std 1003.1 (POSIX.1-2017 / POSIX.1-2024, розділ «Shell Command Language»).

| Змінна / Конструкція | Тип значення | Опис та механізм розгортання |
| :--- | :--- | :--- |
| `$0` | Рядок | Ім'я сценарію або назва виклику оболонки (значення першого елемента `argv[0]`). Не змінюється командою `shift`. Якщо скрипт виконується як сеанс входу (login shell), перший символ дорівнює `-` (наприклад `-sh`). |
| `$1` .. `$9` | Рядок | Позиційні параметри з першого по дев'ятий. Доступні без фігурних дужок. Якщо параметр не передано, розгортається у порожній рядок (якщо не активовано режим `set -u`). |
| `${10}` .. `${N}` | Рядок | Позиційні параметри з індексом 10 і більше. **Обов'язково** вимагають фігурних дужок; запис `$10` без дужок розгортається у значення `$1` та літеральний символ `'0'`. |
| `$#` | Ціле число | Кількість поточних позиційних параметрів (не враховуючи `$0`). При виклику `shift` зменшується. Якщо аргументи відсутні, `$# == 0`. |
| `$*` | Список слів | Розгортається у `$1 $2 $3 ...`. Без лапок підпадає під розбиття на поля (`IFS`) та розкриття імен шляхів (globbing). |
| `"$*"` | Окремий рядок | Розгортається в один суцільний рядок `"$1c$2c$3..."`, де `c` — перший символ змінної `IFS` (за замовчуванням пробіл). Якщо `IFS` порожня (`IFS=""`), аргументи зливаються без роздільників. |
| `$@` | Список слів | Розгортається у `$1 $2 $3 ...`. Без лапок підпадає під розбиття на поля (`IFS`) та розкриття шляхів. |
| `"$@"` | Масив слів | Розгортається у `"$1" "$2" "$3" ...`. Зберігає точні межі кожного аргументу, включаючи внутрішні пробіли та символи нового рядка. Якщо `$# == 0`, розгортається у нуль слів (нічого). |
| `$$` | Ціле число | Ідентифікатор процесу (PID) поточної оболонки. У підоболонках `( )` зберігає PID батьківської оболонки. |
| `$?` | Ціле число | Код завершення останньої виконаної перед цим команди або конвеєра (`0`–`255`). `0` означає успіх, значення `>0` — помилку. |
| `$!` | Ціле число | PID останнього асинхронного (фонового) процесу, запущеного за допомогою оператора `&`. |
| `$-` | Рядок | Поточні прапорці конфігурації оболонки (наприклад `hB` або `eux`), активовані через `set` або параметри запуску інтерпретатора. |
| `$_` | Рядок | Останній аргумент попередньої виконаної команди (у більшості розширених оболонок). |

### Правила взаємодії з роздільником полів (IFS)

Змінна `IFS` (Internal Field Separator) визначає символи, які інтерпретатор використовує для розбиття на слова після виконання розкриття параметрів:

Значення за замовчуванням складається з трьох символів: пробіл, знак табуляції та символ нового рядка. Символи пробілу, табуляції та переходу рядка класифікуються як пробільні роздільники IFS (IFS whitespace characters). Будь-які інші символи (наприклад двокрапка, кома чи крапка з комою) вважаються непробільними роздільниками (non-whitespace delimiters).

Розкриття `"$*"` бере виключно перший байт значення змінної `IFS`. Якщо змінна `IFS` містить значення `":, \t"`, першим символом є двокрапка `:`, і аргументи `a`, `b`, `c` перетворяться на рядок `"a:b:c"`. Якщо значення `IFS` повністю очищене (`IFS=""`), розбиття на поля вимикається для всієї оболонки, а розгортання `"$*"` склеює всі елементи в один монолітний текстовий блок без проміжних знаків. Якщо ж змінну `IFS` було видалено через виклик `unset IFS`, стандарт POSIX вимагає від інтерпретатора відновити поведінку за замовчуванням, ніби змінна містить пробіл, табуляцію та новий рядок.

## 2. Команди маніпуляції позиційними параметрами

### Команда shift

```sh
shift [n]
```

Вбудована команда `shift` виконує зсув масиву позиційних параметрів ліворуч на вказану кількість позицій `n`.

Якщо цілочисельний параметр `n` не вказано користувачем, інтерпретатор автоматично застосовує одиничний зсув `n=1`. Під час виконання операції параметр `$1` безповоротно перезаписується значенням колишнього `$(1 + n)`, параметр `$2` отримує значення `$(2 + n)` і так далі. Загальний лічильник кількості позиційних аргументів `$#` декрементується рівно на число `n`.

Змінна `$0`, яка зберігає назву виклику сценарію або програми, ніколи не змінюється командою `shift`. Число `n` зобов'язане бути невід'ємним цілим значенням у діапазоні від нуля до поточного значення лічильника `$#`.

Коди завершення команди `shift`:
- `0`: операцію зсуву виконано успішно.
- `>0`: сталася помилка виконання (якщо значення `n < 0` або `n > $#`).

У неінтерактивному режимі виконання стандартної оболонки POSIX команда `shift` класифікується як спеціальна вбудована утиліта (Special Built-in Utility). Це означає, що будь-яка помилка виконання команди `shift` (зокрема спроба зсунути більше елементів, ніж містить стек) призводить до негайного аварійного завершення роботи всього процесу сценарію з ненульовим статусом виходу.

### Команда set --

```sh
set -- [arg ...]
```

Вбудована команда `set` з маркером подвійного дефіса повністю замінює поточний активний масив позиційних параметрів новим списком аргументів `arg ...`.

Роздільник `--` є обов'язковим захисним елементом синтаксису. Він однозначно сигналізує лексичному аналізатору про завершення списку внутрішніх опцій команди `set` (таких як `-e`, `-u`, `-x` чи `-o pipefail`). Завдяки цьому перший елемент нового списку `arg`, навіть якщо він починається з дефіса (наприклад `-filename.tar.gz`), інтерпретується суто як значення першого позиційного параметра `$1`, а не як прапорець конфігурації оболонки.

Якщо команду `set --` викликано без жодного наступного аргументу, інтерпретатор повністю очищує поточний позиційний масив і встановлює значення лічильника кількості аргументів `$# = 0`. Змінна `$0` при цьому залишається незмінною.

## 3. Специфікація інтерфейсу утиліти getopts

Вбудована команда POSIX `getopts` виконує синтаксичний аналіз коротких опцій командного рядка відповідно до стандартних правил POSIX Utility Syntax Guidelines (керівні принципи 3–10).

### Сигнатура виклику

```sh
getopts optstring name [arg ...]
```

Аргумент `optstring` є рядком специфікації, який визначає набір дозволених односимвольних прапорців та правила очікування обов'язкових значень.

Параметр `name` вказує ім'я змінної оболонки, куди `getopts` записує знайдений символ опції на кожній успішній ітерації циклу або символ помилки при некоректному введенні.

Необов'язковий масив `arg ...` дозволяє передати довільний список рядків для розбору. Якщо цей масив опущено, утиліта `getopts` за замовчуванням виконує послідовний синтаксичний аналіз поточного масиву позиційних параметрів сценарію або функції `"$@"`.

### Синтаксис рядка специфікації (optstring)

| Елемент синтаксису | Приклад | Поведінка |
| :--- | :--- | :--- |
| Одиночний символ | `"v"` | Опція `-v` є прапорцем і не приймає значення аргументу. |
| Символ із двокрапкою | `"f:"` | Опція `-f` вимагає обов'язкового аргументу (значення записується в `OPTARG`). Приймає форми `-f file` та `-ffile`. |
| Провідна двокрапка | `":f:v"` | Вмикає **тихий режим** (Silent Mode). Придушує стандартні системні повідомлення про помилки та змінює логіку змінних `name` і `OPTARG`. |

### Внутрішні змінні стану getopts

Утиліта `getopts` керується трьома глобальними змінними стану, які автоматично оновлюються між викликами:

Змінна `OPTIND` (Option Index) зберігає числовий індекс наступного елемента у вхідному масиві аргументів, який буде зчитано інтерпретатором. Під час старту сценарію інтерпретатор встановлює `OPTIND=1`. Коли опції згруповано в один кластер (наприклад `-vxf`), утиліта по черзі витягує символи з одного слова, використовуючи внутрішнє посимвольне зміщення, і збільшує значення `OPTIND` лише після повного вичерпання літер у поточному слові.

Змінна `OPTARG` (Option Argument) містить текстове значення аргументу, якщо знайдена опція вимагала обов'язкового значення. Якщо ж опція є простим прапорцем, змінна `OPTARG` скидається в невизначений стан або залишається порожньою. У тихому режимі обробки помилок змінна `OPTARG` зберігає символ невідомої опції або прапорця, для якого не було надано аргументу.

Змінна `OPTERR` (Option Error) є числовим перемикачем (`1` або `0`), що визначає, чи повинен інтерпретатор автоматично друкувати діагностичні повідомлення про синтаксичні помилки у стандартний потік помилок `stderr`. За замовчуванням `OPTERR=1`.

## 4. Матриця поведінки та обробки помилок getopts

| Стан обробки | Багатослівний режим (`"f:v"`) | Тихий режим (`":f:v"`) |
| :--- | :--- | :--- |
| **Знайдено коректну опцію без аргументу** (`-v`) | `name="v"`, `OPTARG` не змінюється | `name="v"`, `OPTARG` не змінюється |
| **Знайдено опцію з аргументом** (`-f out.txt`) | `name="f"`, `OPTARG="out.txt"` | `name="f"`, `OPTARG="out.txt"` |
| **Знайдено невідому опцію** (`-z`) | `name="?"`, `OPTARG` скидається, друк помилки в `stderr` | `name="?"`, `OPTARG="z"`, вивід у `stderr` відсутній |
| **Пропущено обов'язковий аргумент** (`-f` у кінці) | `name="?"`, `OPTARG` скидається, друк помилки в `stderr` | `name=":"`, `OPTARG="f"`, вивід у `stderr` відсутній |
| **Досягнуто кінця опцій** (перший не-опціональний аргумент або `--`) | Повертає код `>0` (хибність), завершуючи цикл | Повертає код `>0` (хибність), завершуючи цикл |

### Правила завершення розбору опцій

Команда `getopts` зупиняє свою роботу та повертає статус виходу `1` за таких умов:
1. Повністю вичерпано всі елементи масиву позиційних параметрів (`OPTIND > $#`).
2. Зустрінуто перший позиційний аргумент, який не починається з дефіса `-` (наприклад, звичайне ім'я файлу).
3. Зустрінуто спеціальний маркер кінця опцій `--`. При цьому `getopts` самостійно збільшує `OPTIND` на одиницю, зміщуючи покажчик на наступний операнд.
4. Зустрінуто одиночний символ дефіса `-`. За конвенцією POSIX одиночний дефіс позначає стандартне введення `stdin` і трактується як звичайний позиційний операнд, а не опція.

### Поведінка getopts у функціях оболонки та реентрабельність

Оскільки змінна `OPTIND` є глобальною для всього процесу інтерпретатора, багаторазовий виклик функції з синтаксичним розбором `getopts` вимагає обов'язкового ручного скидання стану. Якщо функція завершила роботу, значення `OPTIND` залишиться більшим за одиницю. При повторному виклику цієї самої або іншої функції аналізатор `getopts` одразу поверне хибність, вважаючи масив аргументів вичерпаним.

Для забезпечення реентрабельності функція зобов'язана виконувати локалізацію та ініціалізацію індексу:

```sh
parse_helper() {
    # Скидання індексу для коректного старту вбудованого парсера
    OPTIND=1
    while getopts "ab:" opt; do
        case "$opt" in
            a) echo "Прапорець a" ;;
            b) echo "Значення b: $OPTARG" ;;
        esac
    done
    shift "$((OPTIND - 1))"
}
```

## 5. Порівняння системних інтерфейсів парсингу

У системному програмуванні POSIX / C / C++ прямим аналогом утиліти `getopts` виступає бібліотечний інтерфейс `getopt()` та розширення GNU `getopt_long()` з заголовка `<getopt.h>`.

:::tabs
```c
/* Оголошення інтерфейсу getopt_long у C */
#include <getopt.h>

struct option {
    const char *name;    /* Назва довгої опції, наприклад "file" */
    int         has_arg; /* no_argument (0), required_argument (1), optional_argument (2) */
    int        *flag;    /* Якщо NULL, getopt_long повертає val; інакше записує val у *flag */
    int         val;     /* Значення повернення або значення для запису в *flag */
};

extern char *optarg;
extern int optind, opterr, optopt;

int getopt_long(int argc, char *const argv[],
                const char *optstring,
                const struct option *longopts, int *longindex);
```
```cpp
// C++ оголошення інтерфейсу getopt_long у системному просторі
#include <cstddef>
#include <getopt.h>

namespace posix_cli {
    using OptionStruct = ::option;
    
    inline int parse_options(int argc, char *const argv[],
                             const char *optstring,
                             const OptionStruct *longopts,
                             int *longindex) noexcept {
        return ::getopt_long(argc, argv, optstring, longopts, longindex);
    }
}
```
:::

### Зіставлення змінних оболонки та змінних бібліотеки C

| Змінна Shell (`getopts`) | Змінна C/C++ (`<getopt.h>`) | Функціональне призначення |
| :--- | :--- | :--- |
| `OPTIND` | `optind` | Індекс наступного елемента в масиві аргументів `argv`. |
| `OPTARG` | `optarg` | Вказівник на рядок аргументу поточної опції. |
| `OPTERR` | `opterr` | Прапорець дозволу стандартного виводу помилок у `stderr`. |
| `$opt` (значення при помилці) | `optopt` | Символ невідомої опції або опції з відсутнім аргументом. |
| `optstring` (провідна `:`) | `optstring` (провідна `:`) | Вмикання тихого режиму обробки без автоматичного друку у `stderr`. |

Бібліотека C підтримує також розширення `optional_argument` (значення `2` у полі `has_arg`), коли параметр опції може бути опущений. У такому разі значення розпізнається лише тоді, коли воно передане в тому самому слові (наприклад `--color=always` або `-calways`), тоді як у POSIX `getopts` необов'язкові аргументи для прапорців не підтримуються граматикою.
