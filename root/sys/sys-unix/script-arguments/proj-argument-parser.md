# ⚙️ Практикум: Створення надійного парсера аргументів командного рядка

У цьому практикумі розглядається проектування та побудова надійного, переносного синтаксичного аналізатора аргументів командного рядка, який коректно обробляє короткі прапорці, обов'язкові значення, довгі опції GNU (`--long`), відокремлювач позиційних операндів `--`, підкоманди та повідомлення про помилки.

## 1. Архітектурні вимоги до парсера командного рядка

Надійний синтаксичний аналізатор командного рядка в Unix-системах повинен суворо дотримуватися стандартів POSIX Utility Syntax Guidelines (керівні принципи 3–10) та загальноприйнятих конвенцій GNU:

Короткі прапорці повинні підтримувати як роздільне введення (`-h`, `-v`, `-f`), так і кластеризацію (комбінація `-f -v` еквівалентна запису `-fv`). Опції з обов'язковими значеннями повинні однаково коректно приймати значення, передані як наступним окремим словом (`-o FILE`), так і злитно без пробілу (`-oFILE`).

Довгі опції формату GNU мають забезпечувати роботу повних найменувань (`--help`, `--version`, `--force`). Якщо довга опція вимагає обов'язкового аргументу, синтаксичний аналізатор зобов'язаний однаково успішно обробляти два альтернативні формати введення: розділений пробілом `--output FILE` та запис через знак рівності `--output=FILE`.

Маркер завершення опцій `--` є критично важливим для захисту від некоректних або ворожих вхідних даних. Будь-який аргумент після окремо розташованого маркера `--` повинен сприйматися суто як позиційний операнд (ім'я файлу, цільовий шлях або пошуковий запис), навіть якщо цей аргумент починається з дефіса (наприклад `-strange-file.txt` або `--hidden-data`).

Збереження цілісності рядків та меж операндів вимагає повної відмови від неекранованих розширень змінних. Позиційні операнди у реальних файлових системах часто містять пробіли, символи табуляції, лапки або знаки нового рядка. Парсер зобов'язаний зберегти масив позиційних операндів у первинному вигляді без додаткового розбиття на слова (word splitting) та без випадкового розкриття файлових шаблонів (pathname globbing).

Діагностика синтаксичних помилок повинна бути чіткою та інформативною. Якщо користувач передав невідомий прапорець або забув вказати обов'язкове значення аргументу, утиліта повинна вивести зрозуміле повідомлення у стандартний потік помилок `stderr` і завершитися зі стандартним кодом повернення `2` (код синтаксичної помилки CLI за стандартом POSIX/GNU), уникаючи виконання основної логіки програми.

## 2. Реалізація чистим стандартом POSIX Shell

У чистому POSIX `sh` вбудована утиліта `getopts` не вміє самостійно обробляти довгі опції на кшталт `--output`. Тому нижче наведено переносний автомат станів, реалізований за допомогою циклу `while [ $# -gt 0 ]` та блоку зіставлення шаблонів `case "$1" in`.

```sh
#!/bin/sh
set -eu

PROGNAME="${0##*/}"
VERSION="1.4.0"

usage() {
    cat <<EOF
Використання: $PROGNAME [ОПЦІЇ] [ФАЙЛ ...]

Опції:
  -h, --help            Показати цю довідку й вийти
  -v, --version         Показати версію програми
  -o, --output FILE     Вказати шлях до файлу виводу
  -f, --force           Перезаписувати існуючий файл без запиту
  --                    Завершення списку опцій

Приклад:
  $PROGNAME -f -o /tmp/out.bin "Звіт за 2026.pdf" input2.dat
EOF
}

# Значення параметрів за замовчуванням
OUTPUT_FILE=""
FORCE_FLAG=0

# Основний цикл синтаксичного аналізу аргументів
while [ $# -gt 0 ]; do
    case "$1" in
        -h|--help)
            usage
            exit 0
            ;;
        -v|--version)
            printf "%s %s\n" "$PROGNAME" "$VERSION"
            exit 0
            ;;
        -f|--force)
            FORCE_FLAG=1
            shift
            ;;
        -o|--output)
            # Обробка формату з окремим словом: -o FILE або --output FILE
            if [ $# -lt 2 ]; then
                printf "%s: Помилка: опція '%s' вимагає значення файлу\n" "$PROGNAME" "$1" >&2
                exit 2
            fi
            OUTPUT_FILE="$2"
            shift 2
            ;;
        --output=*)
            # Обробка формату зі знаком рівності: --output=FILE
            OUTPUT_FILE="${1#*=}"
            if [ -z "$OUTPUT_FILE" ]; then
                printf "%s: Помилка: значення для '--output' не може бути порожнім\n" "$PROGNAME" >&2
                exit 2
            fi
            shift
            ;;
        -o*)
            # Обробка злитого короткого формату: -oFILE
            OUTPUT_FILE="${1#-o}"
            shift
            ;;
        --)
            # Маркер завершення опцій: відкидаємо сам дефіс і виходимо з циклу
            shift
            break
            ;;
        -*)
            printf "%s: Помилка: невідома опція '%s'\n" "$PROGNAME" "$1" >&2
            printf "Спробуйте '%s --help' для отримання довідки.\n" "$PROGNAME" >&2
            exit 2
            ;;
        *)
            # Перший аргумент без провідного дефіса є позиційним операндом
            break
            ;;
    esac
done

# Валідація обов'язкових параметрів
if [ -z "$OUTPUT_FILE" ]; then
    printf "%s: Помилка: обов'язкова опція '-o/--output' не вказана\n" "$PROGNAME" >&2
    exit 2
fi

printf "Режим виконання:\n"
printf "  Цільовий файл: [%s]\n" "$OUTPUT_FILE"
printf "  Прапорець Force: %d\n" "$FORCE_FLAG"
printf "  Кількість залишкових позиційних операндів: %d\n" "$#"

# Ітерація за залишковими операндами з повним збереженням пробілів
for file_arg in "$@"; do
    printf "  -> Обробка операнда: [%s]\n" "$file_arg"
done
```

### Покроковий розбір логіки автомата станів

Синтаксичний аналізатор використовує кілька ключових конструкцій стандарту POSIX:

Конструкція `${1#*=}` виконує швидке видалення найкоротшого префікса, що відповідає шаблону `*=`. Якщо перший аргумент дорівнює `--output=/var/log/app.log`, ця підстановка миттєво повертає `/var/log/app.log` без запуску зовнішніх утиліт на кшталт `sed` або `awk`. Це забезпечує максимальну швидкодію обробки параметрів у циклах.

Конструкція `${1#-o}` за тим самим принципом відсікає префікс `-o`, коректно витягуючи значення зі злитих коротких прапорців на кшталт `-ooutput.dat`.

Команда `shift 2` застосовується тоді, коли опція та її значення передані двома окремими позиційними параметрами (наприклад `$1="-o"` та `$2="file.txt"`). Вона атомарно вилучає обидва елементи зі стека позиційних параметрів, пересуваючи покажчик на наступний нерозібраний аргумент.

Маркер `--` перехоплюється спеціальною гілкою, яка виконує одинарний `shift` (відкидаючи сам маркер) та негайно викликає оператор `break`, гарантуючи, що жоден з наступних аргументів більше не потрапить під перевірку прапорців.

Обробка помилок із кодом виходу `2` відповідає конвенціям GNU/POSIX для синтаксичних збоїв командного рядка. Код `1` зазвичай резервується для загальних операційних збоїв (наприклад, файл не знайдено), тоді як код `2` однозначно вказує користувачеві чи скрипту викликачу на некоректні параметри виклику.

## 3. Патерн диспетчеризації підкоманд (Subcommands Dispatching)

Багато сучасних системних інструментів (таких як `git`, `docker`, `ip` або `systemctl`) використовують дворівневу структуру виклику: глобальні прапорці передують назві підкоманди, після якої слідують специфічні опції цієї підкоманди.

Для реалізації цієї архітектури в POSIX Shell парсер розділяють на два послідовні етапи:
1. **Перший прохід**: вилучення глобальних прапорців (наприклад `-v` або `--config`) доти, доки не зустрінеться перший позиційний аргумент (назва підкоманди).
2. **Диспетчеризація**: вилучення назви підкоманди через `SUBCOMMAND="$1"; shift` та виклик відповідної внутрішньої функції обробника, якій передаються всі залишкові параметри `"$@"`.

```sh
# Зразок дворівневого парсера підкоманд
handle_deploy() {
    OPTIND=1
    TARGET_ENV="staging"
    while getopts "e:" opt; do
        case "$opt" in
            e) TARGET_ENV="$OPTARG" ;;
            *) return 2 ;;
        esac
    done
    shift "$((OPTIND - 1))"
    printf "Розгортання у середовище: %s, файли: %s\n" "$TARGET_ENV" "$*"
}

case "${1:-}" in
    deploy)
        shift
        handle_deploy "$@"
        ;;
    status)
        shift
        printf "Статус системи: OK\n"
        ;;
    *)
        printf "Помилка: невідома підкоманда '%s'\n" "${1:-}" >&2
        exit 2
        ;;
esac
```

## 4. Реалізація на Bash з поєднанням getopts та довгих опцій

У сценаріях, розрахованих суто на середовище Bash, розробники можуть поєднувати високу швидкість вбудованого аналізатора `getopts` для коротких опцій із власною перевіркою довгих прапорців:

```bash
#!/usr/bin/env bash
set -euo pipefail

PROGNAME="${0##*/}"
OUTPUT_FILE=""
FORCE=0

while [ $# -gt 0 ]; do
    case "$1" in
        --help)
            printf "Використання: %s [ОПЦІЇ] [ФАЙЛ ...]\n" "$PROGNAME"
            exit 0
            ;;
        --output=*)
            OUTPUT_FILE="${1#*=}"
            shift
            ;;
        --output)
            [[ $# -ge 2 ]] || { printf "Помилка: --output вимагає аргументу\n" >&2; exit 2; }
            OUTPUT_FILE="$2"
            shift 2
            ;;
        --force)
            FORCE=1
            shift
            ;;
        --)
            shift
            break
            ;;
        --*)
            printf "Помилка: невідома довга опція '%s'\n" "$1" >&2
            exit 2
            ;;
        -*)
            # Обробка коротких прапорців через getopts
            OPTIND=1
            while getopts ":hfo:v" opt "$1"; do
                case "$opt" in
                    h) printf "Довідка %s\n" "$PROGNAME"; exit 0 ;;
                    f) FORCE=1 ;;
                    o) 
                        if [[ -n "$OPTARG" ]]; then
                            OUTPUT_FILE="$OPTARG"
                        fi
                        ;;
                    :)
                        # Якщо аргумент йде наступним словом у командному рядку
                        [[ $# -ge 2 ]] || { printf "Помилка: -o вимагає аргументу\n" >&2; exit 2; }
                        OUTPUT_FILE="$2"
                        shift
                        ;;
                    \?) printf "Помилка: невідомий прапорець '-%s'\n" "$OPTARG" >&2; exit 2 ;;
                esac
            done
            shift
            ;;
        *)
            break
            ;;
    esac
done
```

## 5. Системний вимір: реалізація мовами C та C++

Для системних демонів, мікросервісів та утиліт ядра той самий контракт розбору параметрів реалізується за допомогою функції `getopt_long()` у мові C та типобезпечної конфігураційної структури в ідіоматичному C++20.

У мові C розбір базується на структурі `struct option` та глобальних змінних бібліотеки glibc (`optind`, `optarg`, `opterr`). У C++20 ми позбавляємося сирих покажчиків, застосовуючи `std::string_view` для посилань на рядки без виділення динамічної пам'яті в купі (heap allocation) та контейнер `std::vector` для збереження залишкових позиційних операндів.

```c
/* Реалізація CLI-парсера мовою C за допомогою POSIX getopt_long */
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <getopt.h>

typedef struct {
    const char *output_file;
    bool force;
} Config;

static void print_usage(const char *progname) {
    printf("Використання: %s [ОПЦІЇ] [ФАЙЛ ...]\n"
           "  -h, --help            Показати довідку\n"
           "  -v, --version         Показати версію\n"
           "  -o, --output FILE     Файл виводу\n"
           "  -f, --force           Примусовий перезапис\n",
           progname);
}

int main(int argc, char *argv[]) {
    Config cfg = { .output_file = NULL, .force = false };

    static struct option long_options[] = {
        {"help",    no_argument,       NULL, 'h'},
        {"version", no_argument,       NULL, 'v'},
        {"output",  required_argument, NULL, 'o'},
        {"force",   no_argument,       NULL, 'f'},
        {NULL,      0,                 NULL, 0}
    };

    int opt;
    while ((opt = getopt_long(argc, argv, "hvo:f", long_options, NULL)) != -1) {
        switch (opt) {
        case 'h':
            print_usage(argv[0]);
            return 0;
        case 'v':
            puts("cli_parser 1.4.0");
            return 0;
        case 'o':
            cfg.output_file = optarg;
            break;
        case 'f':
            cfg.force = true;
            break;
        case '?':
            /* getopt_long уже надрукував повідомлення про помилку в stderr */
            return 2;
        default:
            return 2;
        }
    }

    if (cfg.output_file == NULL) {
        fprintf(stderr, "%s: Помилка: опція -o/--output є обов'язковою\n", argv[0]);
        return 2;
    }

    printf("Вивід: %s, Force: %s\n", cfg.output_file, cfg.force ? "true" : "false");
    printf("Кількість позиційних файлів: %d\n", argc - optind);

    for (int i = optind; i < argc; ++i) {
        printf("  -> Операнд: [%s]\n", argv[i]);
    }

    return 0;
}
```

```cpp
// Ідіоматична реалізація CLI-парсера мовою C++20 з використанням std::string_view
#include <iostream>
#include <string_view>
#include <vector>
#include <optional>
#include <cstdlib>
#include <getopt.h>

struct ProgramConfig {
    std::string_view output_file;
    bool force{false};
    std::vector<std::string_view> positional_files;
};

static void print_usage(std::string_view progname) {
    std::cout << "Використання: " << progname << " [ОПЦІЇ] [ФАЙЛ ...]\n"
              << "  -h, --help            Показати довідку\n"
              << "  -v, --version         Показати версію\n"
              << "  -o, --output FILE     Файл виводу\n"
              << "  -f, --force           Примусовий перезапис\n";
}

int main(int argc, char *argv[]) {
    static const struct option long_options[] = {
        {"help",    no_argument,       nullptr, 'h'},
        {"version", no_argument,       nullptr, 'v'},
        {"output",  required_argument, nullptr, 'o'},
        {"force",   no_argument,       nullptr, 'f'},
        {nullptr,   0,                 nullptr, 0}
    };

    ProgramConfig config;
    int opt;

    while ((opt = ::getopt_long(argc, argv, "hvo:f", long_options, nullptr)) != -1) {
        switch (opt) {
        case 'h':
            print_usage(argv[0]);
            return 0;
        case 'v':
            std::cout << "cli_parser_cpp 1.4.0\n";
            return 0;
        case 'o':
            config.output_file = optarg;
            break;
        case 'f':
            config.force = true;
            break;
        case '?':
            return 2;
        default:
            return 2;
        }
    }

    if (config.output_file.empty()) {
        std::cerr << argv[0] << ": Помилка: опція -o/--output є обов'язковою\n";
        return 2;
    }

    for (int i = optind; i < argc; ++i) {
        config.positional_files.emplace_back(argv[i]);
    }

    std::cout << "Вивід: " << config.output_file << ", Force: " << std::boolalpha << config.force << "\n";
    std::cout << "Кількість позиційних файлів: " << config.positional_files.size() << "\n";

    for (const auto &file : config.positional_files) {
        std::cout << "  -> Операнд: [" << file << "]\n";
    }

    return 0;
}
```

## 6. Тестовий набір валідації граничних випадків

Для всебічної верифікації створеного синтаксичного аналізатора рекомендується автоматизований набір тестів, що покриває типові пастки командного рядка:

| Номер тесту | Командний рядок виклику | Очікуваний результат | Перевірка граничного випадку |
| :--- | :--- | :--- | :--- |
| **Тест 1** | `./parser -f -o out.bin file1.txt` | Успіх (`rc=0`), `force=1`, `output="out.bin"`, 1 операнд | Базові короткі опції з операндом. |
| **Тест 2** | `./parser --output="/tmp/my file.bin" "data 1.csv" "data 2.csv"` | Успіх (`rc=0`), збережено пробіли у шляху та файлах | Збереження пробілів у довгій опції та операндах. |
| **Тест 3** | `./parser --force --output=result.dat -- -weird-file.txt` | Успіх (`rc=0`), 1 операнд `"-weird-file.txt"` | Захист маркером `--` від сприйняття файлу як опції. |
| **Тест 4** | `./parser -o` (без наступного слова) | Помилка (`rc=2`), повідомлення про відсутність аргументу | Відсутній обов'язковий аргумент короткої опції. |
| **Тест 5** | `./parser --invalid-flag` | Помилка (`rc=2`), повідомлення про невідому опцію | Обробка невідомих довгих опцій. |
| **Тест 6** | `./parser -f -o "" file.txt` | Помилка (`rc=2`), повідомлення про порожній аргумент | Перевірка передачі порожнього рядка як шляху файлу. |

Регулярне проходження цього набору тестів гарантує повну сумісність парсера з конвеєрами CI/CD, системними службами systemd та інтерактивними терміналами Unix.
