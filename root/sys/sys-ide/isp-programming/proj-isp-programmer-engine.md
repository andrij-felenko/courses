# ⚙️ Програмний рушій емулятора ISP-програматора з валідацією сигнатур

Внутрішньосхемне програмування мікроконтролерів вимагає надійного мосту між програмним інструментарієм на комп'ютері розробника та апаратними лініями цільового кристала. При розробці вбудованого програмного забезпечення, налагодженні утиліт прошивки (таких як `avrdude`) або побудові автоматизованих конвеєрів тестування Hardware-in-the-Loop (HIL) виникає гостра потреба у віртуальному емуляторі програматора. Такий програмний рушій емулює повноцінний пристрій стандарту STK500 v2, віртуалізує фізичну пам'ять мікроконтролера (Flash, EEPROM, Fuses, Lock Bits), відтворює логіку посторінкового запису з урахуванням високовольтних затримок та забезпечує сувору валідацію ідентифікаційних сигнатур і часових обмежень тактової частоти `f_ISP < f_CPU / 4`.

Створення власного рушія емулятора дозволяє досконало зрозуміти кожен біт протоколу обміну, дослідити поведінку системи при виникненні апаратних збоїв та побудувати надійний симулятор для автоматичного тестування вбудованого коду в середовищах неперервної інтеграції (CI/CD) без підключення фізичних плат.

### Архітектура системи та віртуальна модель мікроконтролера

Програмний комплекс емулятора будується за модульним принципом із чітким розділенням зон відповідальності. Вся система функціонує як детерміністичний скінченний автомат, що приймає потік байтів від хоста (наприклад, через віртуальний послідовний порт або сокет TCP), розпізнає двійкові кадри протоколу, перевіряє цілісність даних за допомогою контрольної суми, модифікує внутрішній стан віртуального мікроконтролера та генерує синхронні пакети відповідей.

```
Архітектура програмного рушія емулятора:
┌────────────────────────────────────────────────────────────────────────┐
│                   Хост-клієнт (avrdude / IDE / Тестовий стенд)          │
└────────────────────────────────────────────────────────────────────────┘
                                    ▲
                                    │ Пакетний протокол STK500 v2 (UART/Stream)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                      Stk500Engine / Диспетчер команд                   │
│  - Декодування заголовка [0x1B] [SEQ] [SIZE] [0x0E] [PAYLOAD] [XOR]     │
│  - Перевірка параметрів частоти (f_ISP <= f_CPU / 4)                   │
│  - Маршрутизація команд (Sign-On, ProgMode, ChipErase, Flash, Fuses)   │
└────────────────────────────────────────────────────────────────────────┘
                                    ▲
                                    │ Керування станами та шиною пам'яті
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                     VirtualMCU / Модель пам'яті кристала               │
│  - Масив Flash (32 КБ, 256 сторінок по 128 байтів)                    │
│  - Буфер сторінки SRAM (Page Buffer 64 слова)                          │
│  - Енергонезалежна EEPROM (1 КБ)                                       │
│  - Регістри Fuses (Low, High, Ext) та Lock Bits                        │
│  - Валідація заводської сигнатури (0x1E 0x95 0x0F)                    │
│  - Апаратне блокування доступу при активних Lock Bits                  │
└────────────────────────────────────────────────────────────────────────┘
```

#### Рівні абстракції програмного комплексу:

1. **Рівень віртуального кремнію (Virtual MCU State):**
   Цей модуль моделює внутрішні ресурси мікроконтролера ATmega328P. Він містить повний масив пам'яті програм Flash обсягом 32768 байтів (розбитий на 256 сторінок по 128 байтів кожна), масив енергонезалежної пам'яті даних EEPROM обсягом 1024 байти, регістри конфігураційних бітів Fuses (`Low`, `High`, `Extended`), регістр захисту Lock Bits та статичні байти заводської сигнатури (`0x1E 0x95 0x0F`).
   Модель чіпа також відтворює внутрішній стан апаратного скидання: мікроконтролер може перебувати або у звичайному робочому стані (`Running`), або у стані захоплення шини програмування (`In Programming Mode`). Будь-які спроби прочитати або записати пам'ять Flash без попереднього успішного виконання команди входу в режим ISP апаратно відхиляються.

2. **Рівень протоколу зв'язку (STK500v2 Framing & Parser):**
   Реалізує потоковий синтаксичний аналізатор бінарних пакетів стандарту Atmel STK500 v2. Парсер обробляє байти по черзі в міру їх надходження з комунікаційного каналу. Він виділяє початковий маркер кадру `0x1B`, фіксує інкрементний номер послідовності `Sequence Number`, зчитує 16-бітне поле довжини корисного навантаження, перевіряє наявність обов'язкового розділового токена `0x0E`, акумулює байти корисних даних у внутрішній буфер та здійснює побайтову верифікацію контрольної суми XOR.

3. **Рівень диспетчеризації команд (Command Dispatcher Engine):**
   Отримує перевірене корисне навантаження кадру, декодує код операції та маршрутизує його до відповідного обробника. Диспетчер відповідає за інтерпретацію команд високого рівня (`CMD_SIGN_ON`, `CMD_SET_PARAMETER`, `CMD_ENTER_PROGMODE_ISP`, `CMD_LOAD_ADDRESS`, `CMD_PROGRAM_FLASH_ISP`, `CMD_READ_FLASH_ISP`, `CMD_CHIP_ERASE_ISP`, `CMD_SPI_MULTI`). Він взаємодіє з віртуальним мікроконтролером, здійснює трансляцію 16-бітних адрес слів у байтові адреси, контролює стан бітів захисту Lock Bits та пакує вихідні дані у формат двійкової відповіді з кодами статусів `STATUS_CMD_OK`, `STATUS_CMD_FAILED` або `STATUS_CMD_UNKNOWN`.

### Моделювання фізичної пам'яті та адресація

Критичною особливістю архітектури AVR є те, що пам'ять програм Flash адресується у **16-бітних машинних словах** (*Words*), тоді як протоколи передачі даних на комп'ютері оперують **байтами** (*Bytes*).

У мікроконтролері ATmega328P загальний обсяг Flash становить 32 КБ (32768 байтів), що відповідає 16384 словам (адреси слів від `0x0000` до `0x3FFF`). Кожне слово складається з двох байтів: молодшого (*Low Byte*) та старшого (*High Byte*).

```
Організація адресації пам'яті Flash:
Байтова адреса:     0x0000   0x0001   0x0002   0x0003   ...   0x7FFE   0x7FFF
                     ┌────────┬────────┬────────┬────────┬     ┬────────┬────────┐
Вміст Flash:         │ Low[0] │ High[0]│ Low[1] │ High[1]│ ... │Low[N]  │High[N] │
                     └────────┴────────┴────────┴────────┴     ┴────────┴────────┘
Адреса слова (Word): └────── Word 0 ───┘└────── Word 1 ───┘     └──── Word 16383 ──┘
```

Коли утиліта `avrdude` передає команду встановлення адреси `CMD_LOAD_ADDRESS`, вона надсилає 32-бітне число, що задає саме **адресу слова**. Емулятор зобов'язаний виконати перетворення адреси слів у фізичне зміщення байтового масиву:

```
Physical_Byte_Offset = (Word_Address & 0x7FFFFFFF) * 2
```

Старший розряд адреси `0x80000000` використовується протоколом STK500 v2 як службовий прапорець автоматичного інкременту адреси. Якщо цей біт встановлено, після кожного запису або читання блоку пам'яті внутрішній покажчик адреси автоматично зміщується вперед на кількість переданих байтів.

#### Організація сторінок Flash та буферизація
Flash-пам'ять ATmega328P розбита на 256 сторінок по 128 байтів (64 слова на сторінку). Фізичний запис комірок Flash не може виконуватися довільними поодинокими байтами: запис завжди здійснюється цілими сторінками за допомогою проміжного апаратного буфера сторінки (*Page Buffer*).

Емулятор точно відтворює цю двоетапну процедуру:
1. Під час надходження команди `CMD_PROGRAM_FLASH_ISP` передані байти спочатку завантажуються у проміжний буфер;
2. Емулятор перевіряє, чи не заблокована пам'ять захисними бітами Lock Bits. Якщо біт `LB2` або `LB1` запрограмований у `0` (Mode 2 або Mode 3), модифікація Flash забороняється, і команда повертає статус помилки `STATUS_CMD_FAILED`;
3. Якщо запис дозволено, дані з буфера фіксуються у фізичний масив Flash за поточною адресою сторінки, імітуючи завершення циклу роботи внутрішнього помпового перетворювача напруги Charge Pump.

#### Енергонезалежні регістри Fuses та захисні біти Lock Bits
Окрему увагу в структурі пам'яті приділено регістрам конфігурації. У моделі емулятора реалізовано:
* `fuse_low`: біти вибору джерела тактування та дільника `CKDIV8` (заводське значення `0x62` задає роботу від внутрішнього RC-генератора 8 МГц із дільником на 8, тобто результуючу частоту 1 МГц);
* `fuse_high`: біти керування інтерфейсом SPI (`SPIEN = 0`), збереженням EEPROM при стиранні (`EESAVE`) та вектором скидання (`BOOTRST`);
* `fuse_ext`: вибір порогу спрацьовування аналогового детектора просідання напруги Brown-out Detector (`BODLEVEL`);
* `lock_bits`: біти захисту пам'яті від читання та запису. Значення `0xFF` відповідає відкритому стану (Mode 1), `0xFE` — забороні подальшого запису (Mode 2), а `0xFC` — повній забороні як запису, так і верифікації (Mode 3).

### Фізична організація та алгоритми захисту сигнатур мікроконтролерів

Кожен оригінальний кристал сімейства AVR містить у постійній заводській пам'яті три байти незмінної сигнатури (*Device Signature*), які зчитуються через низькорівневі команди ISP (`0x30 0x00 [0..2] 0x00`).

```
Структура ідентифікаційної сигнатури AVR:
┌─────────────────┬───────────────────────────────┬──────────────────────────────────┐
│ Позиція         │ Значення в ATmega328P        │ Семантичне призначення          │
├─────────────────┼───────────────────────────────┼──────────────────────────────────┤
│ Байт 0 (Sig 0)  │ 0x1E                          │ Ідентифікатор виробника (Atmel)  │
│ Байт 1 (Sig 1)  │ 0x95                          │ Обсяг Flash (0x95 = 32 КБ)       │
│ Байт 2 (Sig 2)  │ 0x0F                          │ Модель кристала (ATmega328P)     │
└─────────────────┴───────────────────────────────┴──────────────────────────────────┘
```

#### Таблиця сигнатур популярних мікроконтролерів:
* **ATmega328P:** `0x1E 0x95 0x0F` (сторінка Flash 128 байтів, 32 КБ Flash);
* **ATmega328PB:** `0x1E 0x95 0x14` (розширена версія з додатковими таймерами);
* **ATmega2560:** `0x1E 0x98 0x01` (сторінка Flash 256 байтів, 256 КБ Flash);
* **ATmega32U4:** `0x1E 0x95 0x87` (апаратний USB-контролер, 32 КБ Flash);
* **ATtiny85:** `0x1E 0x93 0x0B` (сторінка Flash 64 байти, 8 КБ Flash);
* **ATtiny13A:** `0x1E 0x90 0x07` (сторінка Flash 32 байти, 1 КБ Flash).

Утиліта `avrdude` перед початком будь-якої операції запису обов'язково порівнює вичитану сигнатуру з параметрами конфігураційного файлу `avrdude.conf`. Якщо сигнатура не збігається (наприклад, через спробу прошити ATmega2560 конфігурацією ATmega328P), утиліта аварійно припиняє роботу. Це захищає схему від фатального пошкодження: прошивка для іншого чіпа має інші вектори переривань та інші розміри сторінок Flash, через що запис спотворив би код програми.

### Детальний аналіз енергонезалежної пам'яті EEPROM та фьюза EESAVE

Окрім пам'яті програм Flash, модель емулятора містить повноцінний масив енергонезалежної пам'яті даних EEPROM обсягом 1024 байти (для ATmega328P). На відміну від Flash, EEPROM підтримує як посторінковий, так і побайтовий довільний доступ.

У реальному мікроконтролері тривалість високовольтного запису одного байта або сторінки EEPROM становить `t_WD_EEPROM ≈ 3.6 мс`. Емулятор моделює цей процес під час обробки команд `CMD_PROGRAM_EEPROM_ISP` (`0x15`) та `CMD_READ_EEPROM_ISP` (`0x16`).

#### Логіка збереження даних при повному стиранні (EEPROM Preserve Fuse):
Найважливішим аспектом взаємодії EEPROM з конфігурацією кристала є біт `EESAVE` (розряд 3 регістра `High Fuse`):
1. **`EESAVE = 1` (Стерто / Заводський стан за замовчуванням):** при виконанні команди повного стирання `CMD_CHIP_ERASE_ISP` очищаються одночасно як масив Flash, так і весь масив EEPROM (усі байти заповнюються значенням `0xFF`);
2. **`EESAVE = 0` (Запрограмовано):** при виконанні `CMD_CHIP_ERASE_ISP` очищається виключно пам'ять Flash та скидаються біти захисту Lock Bits, тоді як весь вміст пам'яті EEPROM залишається абсолютно недоторканим.

Ця функція є життєво необхідною у серійному виробництві: вона дозволяє інженеру оновлювати двійковий код програми по ISP без ризику втрати індивідуальних калібрувальних коефіцієнтів сенсорів, мережевих налаштувань, журналів подій та криптографічних ключів, раніше збережених в EEPROM.

### Детальний розбір пакетного протоколу STK500 v2

Протокол STK500 v2 розроблено для забезпечення абсолютної надійності при передачі двійкових блоків прошивки поверх неідеальних каналів зв'язку (RS-232, емульований USB-UART). На відміну від текстових або ASCII-протоколів, бінарний формат STK500 v2 захищений суворим кадруванням та обов'язковою контрольною сумою.

```
Структура двійкового кадру STK500 v2:
Позиція:    Байт 0     Байт 1       Байт 2       Байт 3     Байт 4      Байти 5 .. 5+N-1     Байт 5+N
Поле:    ┌──────────┬───────────┬────────────┬────────────┬─────────┬──────────────────────┬──────────┐
         │  START   │  SEQ_NUM  │ MSG_SIZE_H │ MSG_SIZE_L │  TOKEN  │   PAYLOAD (N байт)   │ CHECKSUM │
         │   0x1B   │  (0..255) │ (High Byte)│ (Low Byte) │  0x0E   │ [CMD] [PARAMS/DATA]  │  (XOR)   │
         └──────────┴───────────┴────────────┴────────────┴─────────┴──────────────────────┴──────────┘
```

#### Поля заголовка кадру:
* **`START` (`0x1B` / ASCII ESC):** фіксований початковий маркер. Дозволяє приймальному автомату виявити початок нового пакета навіть після втрати синхронізації або збою зв'язку;
* **`SEQ_NUM` (Sequence Number):** 8-бітний лічильник послідовності пакетів (від 0 до 255). Клієнт збільшує це поле на одиницю для кожного нового запиту, а емулятор зобов'язаний повернути той самий номер у пакеті відповіді. Це захищає від обробки запізнілих або дубльованих пакетів;
* **`MSG_SIZE_H` та `MSG_SIZE_L`:** 16-бітне ціле число без знаку у форматі Big-Endian, що визначає точну довжину корисного навантаження `PAYLOAD` у байтах (розмір поля від 1 до 512 байтів);
* **`TOKEN` (`0x0E`):** фіксований розділовий маркер між заголовком та початком даних, який служить додатковим рубежем перевірки правильності структури кадру;
* **`PAYLOAD`:** корисні дані команди (код операції та його аргументи) або відповіді (код підтвердження, статус виконання та вичитані байти);
* **`CHECKSUM`:** 8-бітний контрольний байт, що обчислюється як побайтова операція XOR (виключальне АБО) від найпершого байта `START` до останнього байта корисного навантаження включно:

```
CHECKSUM = START ⊕ SEQ_NUM ⊕ MSG_SIZE_H ⊕ MSG_SIZE_L ⊕ TOKEN ⊕ PAYLOAD[0] ⊕ PAYLOAD[1] ⊕ ... ⊕ PAYLOAD[N-1]
```

Якщо обчислена на стороні емулятора контрольна сума не збігається зі значенням у кінці кадру, пакет негайно відкидається як пошкоджений, а автомат переходить у стан очікування наступного маркеру `0x1B`.

#### Скінченний автомат потокового парсера пакетів:
Обробка байтів виконується послідовно через наступні стани автомата:
1. `STK_STATE_IDLE`: очікування початкового байта `0x1B`. Будь-яке інше сміття на лінії ігнорується;
2. `STK_STATE_SEQ`: прийом номера послідовності `seq_num` та ініціалізація акумулятора контрольної суми;
3. `STK_STATE_SIZE_H`: прийом старшого байта розміру повідомлення;
4. `STK_STATE_SIZE_L`: прийом молодшого байта розміру повідомлення, розрахунок сумарної довжини `msg_size` та перевірка на перевищення ємності буфера;
5. `STK_STATE_TOKEN`: перевірка наявності маркера `0x0E`. Якщо токен не збігається, автомат негайно повертається в стан очікування `IDLE`;
6. `STK_STATE_PAYLOAD`: циклічний прийом `msg_size` байтів корисного навантаження в буфер із побітовим накопиченням XOR;
7. `STK_STATE_CHECKSUM`: прийом байта контрольної суми та звірка з акумулятором. При збігу прапорець готовності пакета виставляється в `true`, і викликається диспетчер команд.

### Детальна специфікація команд диспетчера STK500 v2

Диспетчер команд емулятора підтримує повний набір операцій протоколу Atmel STK500 v2. Кожна команда виконується атомарно з поверненням структурованого коду статусу.

```
Таблиця підтримуваних команд протоколу STK500 v2:
┌──────┬────────────────────────┬────────────────────────────────────────────────────────┐
│ Код  │ Назва команди          │ Фізична дія в емуляторі                                │
├──────┼────────────────────────┼────────────────────────────────────────────────────────┤
│ 0x01 │ CMD_SIGN_ON            │ Перевірка зв'язку та повернення рядка "AVRISP_2"       │
│ 0x02 │ CMD_SET_PARAMETER      │ Встановлення тривалості SCK (PARAM_SCK_DURATION)       │
│ 0x03 │ CMD_GET_PARAMETER      │ Читання версії HW/SW, напруги живлення VTARGET         │
│ 0x06 │ CMD_LOAD_ADDRESS       │ Встановлення 32-бітної адреси Flash/EEPROM у словах    │
│ 0x10 │ CMD_ENTER_PROGMODE_ISP │ Перевірка f_ISP <= f_CPU/4 та захоплення шини ISP      │
│ 0x11 │ CMD_LEAVE_PROGMODE_ISP │ Зняття сигналу RESET та запуск виконання програми      │
│ 0x12 │ CMD_CHIP_ERASE_ISP     │ Повне стирання Flash, EEPROM (за EESAVE) і Lock Bits   │
│ 0x13 │ CMD_PROGRAM_FLASH_ISP  │ Запис блоку 128 байтів у Flash з контролем Lock Bits   │
│ 0x14 │ CMD_READ_FLASH_ISP     │ Зчитування блоку Flash (маскування 0xFF при Mode 3)    │
│ 0x15 │ CMD_PROGRAM_EEPROM_ISP │ Посторінковий запис в енергонезалежну EEPROM           │
│ 0x16 │ CMD_READ_EEPROM_ISP    │ Читання пам'яті EEPROM                                 │
│ 0x17 │ CMD_PROGRAM_FUSE_ISP   │ Запис конфігураційних байтів Low/High/Extended Fuses   │
│ 0x18 │ CMD_READ_FUSE_ISP      │ Зчитування байтів Fuses                                │
│ 0x1D │ CMD_SPI_MULTI          │ Низькорівневий міст для 4-байтних SPI-команд (0x30...) │
└──────┴────────────────────────┴────────────────────────────────────────────────────────┘
```

#### Коди статусів відповідей (Response Status Codes):
* `STATUS_CMD_OK` (`0x00`): команду успішно виконано без помилок;
* `STATUS_CMD_TOUT` (`0x80`): таймаут очікування сигналу готовності від мікроконтролера;
* `STATUS_CMD_RDY_BSY_TOUT` (`0x81`): перевищено час очікування завершення високовольтного запису сторінки;
* `STATUS_CMD_FAILED` (`0xC0`): помилка виконання операції (спроба запису при активному захисті Lock Bits, невірна адреса, або перевищення частоти `f_ISP`);
* `STATUS_CMD_UNKNOWN` (`0xC9`): запитуваний код операції не підтримується емулятором.

### Емуляція низькорівневих команд шини SPI (`CMD_SPI_MULTI`)

Особливе місце в протоколі STK500 v2 займає команда `CMD_SPI_MULTI` (`0x1D`). Вона дозволяє хосту обійти високорівневі абстракції програматора та виконати пряму 4-байтну послідовну транзакцію низькорівневого інтерфейсу SPI безпосередньо на ніжках кристала.

Утиліта `avrdude` використовує команду `CMD_SPI_MULTI` для виконання наступних критичних операцій:
* **Зчитування заводської сигнатури чіпа:** відправка 4-байтної команди `0x30 0x00 [0..2] 0x00` та отримання у 4-му байті відповіді байтів ідентифікатора (`0x1E`, `0x95`, `0x0F`);
* **Зчитування конфігураційних бітів Fuses:** команди `0x58 0x00 0x00 0x00` (Low Fuse), `0x58 0x08 0x00 0x00` (High Fuse) та `0x50 0x08 0x00 0x00` (Extended Fuse);
* **Зчитування та запис бітів захисту Lock Bits:** команда читання `0x58 0x00 0x00 0x00` та команда запису `0xAC 0xE0 0x00 [Data]`.

```
Формат пакета CMD_SPI_MULTI:
Запит:  [0x1D] [NumTx] [NumRx] [RxStartAddr] [TxData[0] .. TxData[NumTx-1]]
              │       │          │
              │       │          └─ Позиція першого байта у відповіді (типово 3 або 4)
              │       └──────────── Кількість байтів для повернення хосту (типово 1)
              └──────────────────── Кількість переданих байтів SPI (типово 4)

Відповідь: [0x1D] [STATUS_CMD_OK] [RxData[0] .. RxData[NumRx-1]] [STATUS_CMD_OK]
```

Емулятор містить спеціалізований внутрішній декодер, який перехоплює 4-байтні транзакції всередині `CMD_SPI_MULTI`, аналізує код операції низького рівня та формує апаратну відповідь віртуального мікроконтролера. Якщо запитується читання сигнатури, емулятор підставляє значення констант `MCU_SIG_BYTE0..2`; якщо запитується модифікація Lock Bits, новий байт накладається побітовою операцією `AND` на поточний стан регістра, забезпечуючи фізичну інверсну логіку Flash-комірок (біти можна скидати з `1` в `0`, але неможливо встановити назад в `1` без повної операції `Chip Erase`).

### Емуляція апаратних обмежень частоти (f_ISP < f_CPU / 4)

Як детально обґрунтовано в теоретичній статті, внутрішня цифрова логіка ISP мікроконтролера AVR здійснює дискретизацію сигналу `SCK` за допомогою системних тактів процесорного ядра `f_CPU`. Для надійної фіксації стану лінії напівперіод сигналу `SCK` повинен тривати щонайменше два системних такти ядра, що накладає фундаментальне фізичне обмеження:

```
f_ISP < f_CPU / 4
```

У реальних програматорах тривалість такту `SCK` налаштовується командою `CMD_SET_PARAMETER` з ідентифікатором параметра `PARAM_SCK_DURATION` (`0x98`).

Емулятор моделює цю апаратну поведінку:
* При ініціалізації віртуальний мікроконтролер має базову частоту тактування `f_CPU = 1.0 МГц` (заводський внутрішній RC-генератор 8 МГц із дільником `CKDIV8`);
* Якщо хост встановлює значення параметра `PARAM_SCK_DURATION`, яке відповідає частоті програмування `f_ISP > 250 кГц` (наприклад, 500 кГц або 1.5 МГц), спроба входу в режим програмування командою `CMD_ENTER_PROGMODE_ISP` завершується аварійним статусом `STATUS_CMD_FAILED`;
* Тільки коли хост обирає безпечну частоту (наприклад, `f_ISP = 125 кГц`), емулятор підтверджує успішний вхід у режим ISP, повністю відтворюючи діагностику реального фізичного кремнію.

### Часові діаграми та мікросекундні таймінги SPI-транзакцій ISP

Фізична взаємодія програматора з цільовим кристалом підпорядковується суворим часовим діаграмам інтерфейсу послідовного програмування. Порушення будь-якого з наведених параметрів призводить до збою десеріалізації бітів або пошкодження даних у внутрішньому буфері сторінки:

1. **Тривалість імпульсу скидання (t_RST / Reset Pulse Width):**
   Перед ініціалізацією режиму ISP лінія `RESET` притискається до низького логічного рівня на час не менше 20 мс (або щонайменше 2 · 10⁶ тактів ядра `f_CPU`). Це гарантує завершення всіх внутрішніх перехідних процесів стабілізатора напруги живлення, переведення всіх ліній введення-виведення мікроконтролера у стан високого імпедансу (High-Z) та готовність внутрішнього зсувного регістра ISP до прийому синхроімпульсів.

2. **Тривалість напівперіодів тактового сигналу (t_SCK_LOW та t_SCK_HIGH):**
   Внутрішня логіка синхронізації AVR здійснює стробування сигналу `SCK` по системному тактовому генератору `f_CPU`. Кожен напівперіод сигналу тактування повинен тривати щонайменше 2 системні такти процесорного ядра:
   ```
   t_SCK_LOW >= 2 / f_CPU
   t_SCK_HIGH >= 2 / f_CPU
   T_SCK = t_SCK_LOW + t_SCK_HIGH >= 4 / f_CPU
   ```
   Для мікроконтролера, що працює на базовій заводській частоті 1.0 МГц, мінімальна тривалість `t_SCK_LOW` та `t_SCK_HIGH` становить 2.0 мкс, що обмежує сумарний період `T_SCK >= 4.0 мкс` (максимальна частота `f_ISP <= 250 кГц`).

3. **Міжбайтова затримка десеріалізації (t_BYTE_DELAY):**
   При передачі 4-байтних інструкцій низького рівня (наприклад, `0xAC 0x53 0x00 0x00` для команди `Programming Enable`) між завершенням 8-го такту попереднього байта і 1-м тактом наступного байта програматор повинен витримувати паузу `t_BYTE_DELAY >= 2 / f_CPU` (не менше 2 мкс при частоті 1 МГц). Цей інтервал необхідний вбудованому апаратному автомату чіпа для переносу байта з приймального зсувного регістра у внутрішній командний регістр та підготовки байта-відповіді у вихідний зсувний регістр лінії `MISO`.

4. **Час утримання та встановлення даних (t_SETUP та t_HOLD):**
   Дані на лінії `MOSI` повинні бути стабільно виставлені щонайменше за `t_SETUP >= 10 нс` до наростаючого фронту `SCK` та утримуватися щонайменше `t_HOLD >= 10 нс` після спадного фронту. Зі свого боку, мікроконтролер формує дійсний біт на лінії `MISO` з максимальною затримкою поширення `t_VALID <= 15 нс` після спадного фронту тактового сигналу.

5. **Час самопрограмування пам'яті (t_WD_FLASH та t_WD_EEPROM):**
   Апаратний цикл фіксації даних із проміжного буфера сторінки у фізичні плаваючі затвори комірок пам'яті Flash триває `t_WD_FLASH ≈ 4.5 мс`. Запис сторінки або окремого байта EEPROM вимагає `t_WD_EEPROM ≈ 3.6 мс`. Програматор зобов'язаний витримувати ці затримки перед відправкою наступної адреси або опитувати прапорець завершення запису методом Data Polling.

### Діагностика збоїв синхронізації та обробка аномалій 0x00 / 0xFF при дефектах чіпа

При взаємодії з фізичним або емульованим мікроконтролером найчастішими симптомами апаратних збоїв шини програмування є зчитування однорідних сигнатурних послідовностей `0x00 0x00 0x00` або `0xFF 0xFF 0xFF` замість очікуваних заводських байтів виробника (`0x1E 0x95 0x0F`). Програмний рушій емулятора та утиліти прошивки здійснюють структурний аналіз цих помилок:

#### 1. Синдром «Суцільних нулів» (`0x00 0x00 0x00`):
* **Фізична природа дефекту:** лінія передачі даних від чіпа `MISO` постійно утримується на низькому логічному рівні 0V (GND).
* **Типові апаратні причини:**
  - Коротке замикання лінії `MISO` на загальну шину `GND` або між сусідніми виводами друкованої плати;
  - Повна відсутність напруги живлення `VTARGET` на виводах `VCC` / `AVCC` мікроконтролера або перевантаження внутрішнього лінійного стабілізатора;
  - Перевернутий на 180 градусів роз'єм кабелю ISP, внаслідок чого сигнальні лінії контактують із землею;
  - Фізичний пробій вихідного каскаду виводу `MISO` (пошкодження захисних ESD-діодів високовольтним статичним розрядом).
* **Реакція програмного рушія:** якщо емулятор у режимі інжектування несправностей повертає сигнатуру `0x00 0x00 0x00`, диспетчер команд фіксує статус помилки `STATUS_CMD_FAILED` та генерує діагностичне повідомлення про коротке замикання шини або відсутність цільового живлення.

#### 2. Синдром «Суцільних одиниць» (`0xFF 0xFF 0xFF`):
* **Фізична природа дефекту:** лінія `MISO` залишається у стані високого логічного рівня (+5V або +3.3V) через зовнішній резистор підтяжки (Pull-up) або стан високого імпедансу лінії при читанні логічної одиниці вхідним буфером програматора.
* **Типові апаратні причини:**
  - Фізичний обрив провідника лінії `MISO`, `MOSI` або `SCK` у шлейфі програматора;
  - Обрив лінії `RESET` (мікроконтролер не скидається і продовжує виконувати основний код, ігноруючи тактування ISP);
  - Блокування тактового генератора: конфігураційні біти Fuses помилково налаштовані на роботу від зовнішнього кварцового резонатора (`CKSEL[3:0] = 1111`), який фізично відсутній на налагоджувальній платі, або вивід скидання вимкнено фьюзом `RSTDISBL = 0`;
  - Перевищення допустимої частоти програмування `f_ISP > f_CPU / 4`, через що вхідний зсувний регістр чіпа не встигає зафіксувати байти команди `Programming Enable`.
* **Реакція програмного рушія:** рушій STK500 v2 відхиляє операцію з кодом помилки `STATUS_CMD_TOUT` або `STATUS_CMD_FAILED`, ініціюючи процедуру відновлення зв'язку.

#### 3. Алгоритм відновлення синхронізації та відкату частоти (Auto-Recovery):
При виявленні недійсної сигнатури сучасні прошивальні конвеєри та емулятори виконують покроковий алгоритм аварійного відновлення:
1. **Зняття та повторне накладання апаратного скидання:** лінія `RESET` піднімається у високий рівень на 50 мс, після чого знову притискається до нуля для перезапуску внутрішнього кінцевого автомата ISP;
2. **Ступінчасте зниження тактової частоти SCK:** швидкість послідовного інтерфейсу знижується до мінімально можливої (наприклад, параметр `PARAM_SCK_DURATION` збільшується для переходу на частоту `f_ISP = 32 кГц` або `8 кГц`). Це дозволяє відновити зв'язок із мікроконтролерами, тактованими від низькочастотного Watchdog-генератора 128 кГц або у режимі глибокого сну;
3. **Подача зовнішнього аварійного тактового сигналу:** генерація меандру частотою 1–8 МГц на вивід `XTAL1` для оживлення кристалів із некоректно записаними бітами джерела тактування `CKSEL`.

### Відновлення синхронізації та захист від спотворень потоку

При роботі емулятора через послідовні канали зв'язку існує ймовірність втрати окремих байтів або появи перешкод. Особливу небезпеку становлять «хибні маркери»: наприклад, байт `0x1B` може законно зустрічатися всередині бінарного образу Flash-прошивки (як опкод машинної інструкції).

Скінченний автомат емулятора реалізує двобар'єрний захист від хибної синхронізації:
1. **Перевірка розділового токена `0x0E`:** навіть якщо випадковий байт `0x1B` був помилково сприйнятий за початок кадру, автомат перевірить наявність обов'язкового байта `TOKEN = 0x0E` у суворо визначеній 5-й позиції кадру. Якщо у двійкових даних на цій позиції стоїть інше число, стан негайно скидається в `IDLE`;
2. **Контрольна сума XOR:** якщо навіть токен випадково збігся, побайтова перевірка контрольної суми в кінці пакета з імовірністю 255/256 ≈ 99.6% виявить порушення структури та відкине некоректний блок даних.

### Калібрування внутрішнього RC-генератора та дрейф частоти

У реальних мікроконтролерах частота внутрішнього RC-генератора калібрується на заводі записом початкового значення у спеціальний байт `OSCCAL`. При зміні температури навколишнього середовища або коливаннях напруги живлення частота може змінюватися на ±10%.

Емулятор підтримує моделювання температурного дрейфу:
* При зміні параметра напруги `PARAM_VTARGET` емулятор може масштабувати ефективну частоту ядра `simulated_cpu_hz`;
* Якщо занижена напруга живлення зміщує частоту ядра нижче 500 кГц, межа `f_ISP < f_CPU / 4` автоматично знижується до 125 кГц, що дозволяє виявляти маргінальні таймінги при тестуванні низьковольтних пристроїв із батарейним живленням.

### Вплив фізичної довжини кабелю та паразитної ємності на сигнал SCK

При переході від віртуального емулятора до реального заліза критичним фактором стає хвильовий імпеданс з'єднувального шлейфа. Типовий плоский 6- або 10-жильний шлейф ISP довжиною понад 20–30 см має власну паразитну ємність `C ≈ 40–80 пФ` та індуктивність `L ≈ 200–400 нГн`.

При високих швидкостях передачі (`f_ISP > 1 МГц`) круті фронти тактового сигналу `SCK` (`t_rise < 5 нс`) збуджують у довгому шлейфі паразитні високочастотні коливання — **дзвін (Ringing)** та зворотні викиди амплітуди. Якщо амплітуда дзвону перевищує поріг логічного перемикання `V_IH / V_IL`, мікроконтролер фіксує два такти замість одного, руйнуючи 8-бітне вирівнювання байтів у зсувному регістрі.

Емулятор дозволяє відтворювати ці сценарії у симуляціях Hardware-in-the-Loop, додаючи випадкові зсуви фази до потоку байтів та перевіряючи здатність прошивального ПЗ відновлювати кадрову синхронізацію після поодиноких збоїв тактування.

---

### Інжектування дефектів та стрес-тестування у стендах HIL

У виробничих та сертифікаційних лабораторіях емулятор використовується як генератор аномалій (*Fault Injection Engine*) для перевірки стійкості хостового ПЗ:
1. **Симуляція пошкодження бітів шини (Bit-Flipping):** програмне спотворення 1 біта у випадковому пакеті Flash для перевірки реакції `avrdude` на помилку верифікації;
2. **Симуляція зносу комірок пам'яті (Flash Wear-Out):** імітація «залипання» окремих бітів у нуль після багаторазового перезапису;
3. **Симуляція аварійного скидання живлення (Power-Cut Recovery):** раптове розірвання з'єднання посеред запису сторінки та перевірка алгоритмів відновлення прошивки після неповного циклу запису.

---

### Порівняльний аналіз архітектури C99 та C++20

Програмні рушії реалізовані двома мовами з дотриманням фундаментальних парадигм кожної з них:

1. **Реалізація на C99:**
   * Спроектована для прямої інтеграції у вбудовані системи з жорсткими обмеженнями ресурсів (наприклад, для створення перехідників USB-ISP на базі малопотужних мікроконтролерів);
   * **Повна відсутність динамічного виділення пам'яті (Zero Dynamic Memory Allocation):** усі буфери розміщені статично всередині структур `virtual_mcu_t` та `stk500_engine_t`, що виключає ризик фрагментації купи або аварійного вичерпання RAM;
   * Явний процедурний інтерфейс із передачею контексту через вказівники та строгою типізацією стандартними заголовками `<stdint.h>` і `<stdbool.h>`.

2. **Реалізація на C++20:**
   * Оптимізована для високопродуктивних симуляторів, серверних HIL-стендів та тестових фреймворків;
   * **Безпечна робота з пам'яттю та зрізами даних:** використання `std::span` та `std::array` гарантує відсутність виходу за межі масивів та усуває накладні витрати на зайве копіювання байтів;
   * Строга типізація команд і параметрів за допомогою типізованих переліків `enum class`;
   * Сучасна обробка результатів та помилок через `std::expected` і `std::optional`, що дозволяє позбутися глобальних прапорців стану;
   * Використання стандартних алгоритмів `<numeric>` (`std::accumulate` для розрахунку контрольної суми XOR) та інкапсуляція бізнес-логіки у класи `VirtualMcu` та `Stk500Engine`.

```c
/* ============================================================================
 * Програмний рушій емулятора ISP-програматора STK500v2 (Стандарт C99)
 * ============================================================================ */

#include <stdint.h>
#include <stdbool.h>
#include <string.h>
#include <stdio.h>

#define STK_MESSAGE_START           0x1B
#define STK_TOKEN                   0x0E

/* Коди команд протоколу STK500 v2 */
#define CMD_SIGN_ON                 0x01
#define CMD_SET_PARAMETER           0x02
#define CMD_GET_PARAMETER           0x03
#define CMD_LOAD_ADDRESS            0x06
#define CMD_ENTER_PROGMODE_ISP      0x10
#define CMD_LEAVE_PROGMODE_ISP      0x11
#define CMD_CHIP_ERASE_ISP          0x12
#define CMD_PROGRAM_FLASH_ISP       0x13
#define CMD_READ_FLASH_ISP          0x14
#define CMD_PROGRAM_EEPROM_ISP      0x15
#define CMD_READ_EEPROM_ISP         0x16
#define CMD_PROGRAM_FUSE_ISP        0x17
#define CMD_READ_FUSE_ISP           0x18
#define CMD_SPI_MULTI               0x1D

/* Коди параметрів програматора */
#define PARAM_BUILD_NUMBER_LOW      0x80
#define PARAM_BUILD_NUMBER_HIGH     0x81
#define PARAM_HW_VER                0x90
#define PARAM_SW_MAJOR              0x91
#define PARAM_SW_MINOR              0x92
#define PARAM_VTARGET               0x94
#define PARAM_SCK_DURATION          0x98

/* Коди статусів відповіді STK500 v2 */
#define STATUS_CMD_OK               0x00
#define STATUS_CMD_TOUT             0x80
#define STATUS_CMD_RDY_BSY_TOUT     0x81
#define STATUS_CMD_SET_PARAM_MISSING 0x82
#define STATUS_CMD_FAILED           0xC0
#define STATUS_CMD_UNKNOWN          0xC9

/* Константи конфігурації мікроконтролера ATmega328P */
#define MCU_FLASH_SIZE              32768U
#define MCU_PAGE_SIZE               128U
#define MCU_PAGE_COUNT              (MCU_FLASH_SIZE / MCU_PAGE_SIZE)
#define MCU_EEPROM_SIZE             1024U
#define MCU_SIG_BYTE0               0x1EU
#define MCU_SIG_BYTE1               0x95U
#define MCU_SIG_BYTE2               0x0FU

#define BUFFER_MAX_SIZE             512U

/* ── Віртуальна модель мікроконтролера ─────────────────────────────────────── */

typedef struct {
    uint8_t flash[MCU_FLASH_SIZE];
    uint8_t eeprom[MCU_EEPROM_SIZE];
    uint8_t page_buffer[MCU_PAGE_SIZE];
    uint8_t fuse_low;
    uint8_t fuse_high;
    uint8_t fuse_ext;
    uint8_t lock_bits;
    uint32_t current_address_bytes;
    bool in_programming_mode;
    bool page_buffer_dirty;
    uint32_t simulated_cpu_hz;
    uint32_t current_isp_hz;
} virtual_mcu_t;

void mcu_init(virtual_mcu_t *mcu) {
    if (!mcu) return;
    memset(mcu->flash, 0xFF, sizeof(mcu->flash));
    memset(mcu->eeprom, 0xFF, sizeof(mcu->eeprom));
    memset(mcu->page_buffer, 0xFF, sizeof(mcu->page_buffer));
    mcu->fuse_low = 0x62;   /* Заводський стан: 8 МГц internal RC + CKDIV8 (1 МГц) */
    mcu->fuse_high = 0xD9;  /* Заводський стан: SPIEN увімкнено, BOD вимкнено */
    mcu->fuse_ext = 0xFF;
    mcu->lock_bits = 0xFF;  /* Mode 1: Захист відсутній */
    mcu->current_address_bytes = 0;
    mcu->in_programming_mode = false;
    mcu->page_buffer_dirty = false;
    mcu->simulated_cpu_hz = 1000000UL; /* 1.0 МГц */
    mcu->current_isp_hz = 125000UL;    /* 125 кГц (безпечно: < f_CPU / 4) */
}

/* Повне стирання кристала */
void mcu_chip_erase(virtual_mcu_t *mcu) {
    if (!mcu) return;
    memset(mcu->flash, 0xFF, sizeof(mcu->flash));
    /* Якщо фьюз EESAVE (біт 3 fuse_high) не запрограмований (тобто 1), стираємо EEPROM */
    if ((mcu->fuse_high & 0x08) != 0) {
        memset(mcu->eeprom, 0xFF, sizeof(mcu->eeprom));
    }
    memset(mcu->page_buffer, 0xFF, sizeof(mcu->page_buffer));
    mcu->lock_bits = 0xFF; /* Скидання бітів захисту */
    mcu->page_buffer_dirty = false;
}

/* ── Структура та стан рушія програматора ─────────────────────────────────── */

typedef struct {
    virtual_mcu_t mcu;
    uint8_t seq_number;
    uint8_t sck_duration_param;
    uint8_t rx_buffer[BUFFER_MAX_SIZE];
    uint16_t rx_index;
    uint16_t rx_msg_size;
    uint8_t tx_buffer[BUFFER_MAX_SIZE];
    uint16_t tx_size;
} stk500_engine_t;

void stk_engine_init(stk500_engine_t *engine) {
    if (!engine) return;
    mcu_init(&engine->mcu);
    engine->seq_number = 0;
    engine->sck_duration_param = 8; /* Типовий параметр затримки SCK */
    engine->rx_index = 0;
    engine->rx_msg_size = 0;
    engine->tx_size = 0;
}

/* Обчислення контрольної суми XOR */
static uint8_t calculate_checksum(const uint8_t *data, uint16_t length) {
    uint8_t checksum = 0;
    for (uint16_t i = 0; i < length; ++i) {
        checksum ^= data[i];
    }
    return checksum;
}

/* Формування двійкового пакету відповіді STK500 v2 */
static void build_response(stk500_engine_t *engine, const uint8_t *payload, uint16_t payload_len) {
    if (!engine || !payload) return;
    
    engine->tx_buffer[0] = STK_MESSAGE_START;
    engine->tx_buffer[1] = engine->seq_number;
    engine->tx_buffer[2] = (uint8_t)((payload_len >> 8) & 0xFF);
    engine->tx_buffer[3] = (uint8_t)(payload_len & 0xFF);
    engine->tx_buffer[4] = STK_TOKEN;
    
    memcpy(&engine->tx_buffer[5], payload, payload_len);
    
    uint16_t total_before_crc = 5 + payload_len;
    engine->tx_buffer[total_before_crc] = calculate_checksum(engine->tx_buffer, total_before_crc);
    engine->tx_size = total_before_crc + 1;
}

/* ── Диспетчеризація команд протоколу ─────────────────────────────────────── */

void stk_process_command(stk500_engine_t *engine, const uint8_t *payload, uint16_t payload_len) {
    if (!engine || !payload || payload_len == 0) return;
    
    uint8_t cmd = payload[0];
    uint8_t resp_payload[BUFFER_MAX_SIZE];
    uint16_t resp_len = 0;
    
    switch (cmd) {
        case CMD_SIGN_ON: {
            resp_payload[0] = CMD_SIGN_ON;
            resp_payload[1] = STATUS_CMD_OK;
            const char *sig_str = "AVRISP_2";
            uint8_t sig_len = (uint8_t)strlen(sig_str);
            resp_payload[2] = sig_len;
            memcpy(&resp_payload[3], sig_str, sig_len);
            resp_len = 3 + sig_len;
            break;
        }
        
        case CMD_SET_PARAMETER: {
            resp_payload[0] = CMD_SET_PARAMETER;
            if (payload_len >= 3) {
                uint8_t param = payload[1];
                uint8_t val = payload[2];
                if (param == PARAM_SCK_DURATION) {
                    engine->sck_duration_param = val;
                    /* Розрахунок частоти: f_ISP = 1 / (SCK_DURATION * 1e-6) */
                    uint32_t calculated_hz = (val > 0) ? (1000000UL / val) : 2000000UL;
                    engine->mcu.current_isp_hz = calculated_hz;
                }
                resp_payload[1] = STATUS_CMD_OK;
            } else {
                resp_payload[1] = STATUS_CMD_FAILED;
            }
            resp_len = 2;
            break;
        }
        
        case CMD_GET_PARAMETER: {
            resp_payload[0] = CMD_GET_PARAMETER;
            resp_payload[1] = STATUS_CMD_OK;
            uint8_t param = (payload_len >= 2) ? payload[1] : 0;
            switch (param) {
                case PARAM_HW_VER:            resp_payload[2] = 0x02; break;
                case PARAM_SW_MAJOR:          resp_payload[2] = 0x02; break;
                case PARAM_SW_MINOR:          resp_payload[2] = 0x0A; break;
                case PARAM_VTARGET:           resp_payload[2] = 50;   break; /* 5.0V */
                case PARAM_SCK_DURATION:      resp_payload[2] = engine->sck_duration_param; break;
                default:                      resp_payload[2] = 0x00; break;
            }
            resp_len = 3;
            break;
        }
        
        case CMD_LOAD_ADDRESS: {
            resp_payload[0] = CMD_LOAD_ADDRESS;
            if (payload_len >= 5) {
                /* Адреса передається в 16-бітних словах (Big-Endian) */
                uint32_t word_addr = ((uint32_t)payload[1] << 24) |
                                     ((uint32_t)payload[2] << 16) |
                                     ((uint32_t)payload[3] << 8)  |
                                     ((uint32_t)payload[4]);
                /* Очищаємо прапорець автоінкременту (старший біт) та переводимо в байти */
                word_addr &= 0x7FFFFFFFUL;
                engine->mcu.current_address_bytes = word_addr * 2;
                resp_payload[1] = STATUS_CMD_OK;
            } else {
                resp_payload[1] = STATUS_CMD_FAILED;
            }
            resp_len = 2;
            break;
        }
        
        case CMD_ENTER_PROGMODE_ISP: {
            resp_payload[0] = CMD_ENTER_PROGMODE_ISP;
            /* Перевірка обмеження f_ISP < f_CPU / 4 */
            if (engine->mcu.current_isp_hz > (engine->mcu.simulated_cpu_hz / 4)) {
                /* Помилка частоти: кристал не встигає дискретизувати SCK */
                resp_payload[1] = STATUS_CMD_FAILED;
                engine->mcu.in_programming_mode = false;
            } else {
                engine->mcu.in_programming_mode = true;
                resp_payload[1] = STATUS_CMD_OK;
            }
            resp_len = 2;
            break;
        }
        
        case CMD_LEAVE_PROGMODE_ISP: {
            resp_payload[0] = CMD_LEAVE_PROGMODE_ISP;
            engine->mcu.in_programming_mode = false;
            resp_payload[1] = STATUS_CMD_OK;
            resp_len = 2;
            break;
        }
        
        case CMD_CHIP_ERASE_ISP: {
            resp_payload[0] = CMD_CHIP_ERASE_ISP;
            if (engine->mcu.in_programming_mode) {
                mcu_chip_erase(&engine->mcu);
                resp_payload[1] = STATUS_CMD_OK;
            } else {
                resp_payload[1] = STATUS_CMD_FAILED;
            }
            resp_len = 2;
            break;
        }
        
        case CMD_PROGRAM_FLASH_ISP: {
            resp_payload[0] = CMD_PROGRAM_FLASH_ISP;
            if (!engine->mcu.in_programming_mode) {
                resp_payload[1] = STATUS_CMD_FAILED;
                resp_len = 2;
                break;
            }
            /* Перевірка Lock Bits (Mode 2/3 забороняють запис) */
            if ((engine->mcu.lock_bits & 0x02) == 0) {
                resp_payload[1] = STATUS_CMD_FAILED; /* Захист від запису активний */
                resp_len = 2;
                break;
            }
            
            if (payload_len >= 10) {
                uint16_t num_bytes = ((uint16_t)payload[1] << 8) | payload[2];
                const uint8_t *data_ptr = &payload[10];
                
                if (engine->mcu.current_address_bytes + num_bytes <= MCU_FLASH_SIZE) {
                    memcpy(&engine->mcu.flash[engine->mcu.current_address_bytes], data_ptr, num_bytes);
                    engine->mcu.current_address_bytes += num_bytes;
                    resp_payload[1] = STATUS_CMD_OK;
                } else {
                    resp_payload[1] = STATUS_CMD_FAILED;
                }
            } else {
                resp_payload[1] = STATUS_CMD_FAILED;
            }
            resp_len = 2;
            break;
        }
        
        case CMD_READ_FLASH_ISP: {
            resp_payload[0] = CMD_READ_FLASH_ISP;
            if (!engine->mcu.in_programming_mode) {
                resp_payload[1] = STATUS_CMD_FAILED;
                resp_len = 2;
                break;
            }
            
            if (payload_len >= 3) {
                uint16_t num_bytes = ((uint16_t)payload[1] << 8) | payload[2];
                resp_payload[1] = STATUS_CMD_OK;
                
                /* Перевірка Lock Bits Mode 3 (заборона читання) */
                if ((engine->mcu.lock_bits & 0x01) == 0 && (engine->mcu.lock_bits & 0x02) == 0) {
                    /* Захищений стан: повертаємо 0xFF замість коду */
                    memset(&resp_payload[2], 0xFF, num_bytes);
                } else {
                    if (engine->mcu.current_address_bytes + num_bytes <= MCU_FLASH_SIZE) {
                        memcpy(&resp_payload[2], &engine->mcu.flash[engine->mcu.current_address_bytes], num_bytes);
                        engine->mcu.current_address_bytes += num_bytes;
                    } else {
                        memset(&resp_payload[2], 0xFF, num_bytes);
                    }
                }
                resp_payload[2 + num_bytes] = STATUS_CMD_OK;
                resp_len = 3 + num_bytes;
            } else {
                resp_payload[1] = STATUS_CMD_FAILED;
                resp_len = 2;
            }
            break;
        }
        
        case CMD_SPI_MULTI: {
            resp_payload[0] = CMD_SPI_MULTI;
            if (!engine->mcu.in_programming_mode) {
                resp_payload[1] = STATUS_CMD_FAILED;
                resp_len = 2;
                break;
            }
            
            if (payload_len >= 8) {
                uint8_t num_tx = payload[1];
                uint8_t num_rx = payload[2];
                uint8_t rx_start = payload[3];
                const uint8_t *tx_data = &payload[4];
                
                resp_payload[1] = STATUS_CMD_OK;
                uint8_t rx_buffer[4] = {0, 0, 0, 0};
                
                /* Розпізнавання низькорівневих 4-байтних команд ISP */
                if (num_tx >= 4) {
                    uint8_t op = tx_data[0];
                    if (op == 0x30) {
                        /* Read Signature: 0x30 0x00 [Addr 0..2] 0x00 */
                        uint8_t addr = tx_data[2];
                        if (addr == 0) rx_buffer[3] = MCU_SIG_BYTE0;
                        else if (addr == 1) rx_buffer[3] = MCU_SIG_BYTE1;
                        else if (addr == 2) rx_buffer[3] = MCU_SIG_BYTE2;
                    } else if (op == 0x58 && tx_data[1] == 0x00) {
                        /* Read Low Fuse */
                        rx_buffer[3] = engine->mcu.fuse_low;
                    } else if (op == 0x58 && tx_data[1] == 0x08) {
                        /* Read High Fuse */
                        rx_buffer[3] = engine->mcu.fuse_high;
                    } else if (op == 0x50 && tx_data[1] == 0x08) {
                        /* Read Ext Fuse */
                        rx_buffer[3] = engine->mcu.fuse_ext;
                    } else if (op == 0x58 && tx_data[1] == 0x00) {
                        /* Read Lock Bits */
                        rx_buffer[3] = engine->mcu.lock_bits;
                    } else if (op == 0xAC && tx_data[1] == 0xE0) {
                        /* Write Lock Bits: 0xAC 0xE0 0x00 [Data] */
                        engine->mcu.lock_bits &= tx_data[3]; /* Біти можна лише скидати в 0 */
                    }
                }
                
                memcpy(&resp_payload[2], &rx_buffer[rx_start], num_rx);
                resp_payload[2 + num_rx] = STATUS_CMD_OK;
                resp_len = 3 + num_rx;
            } else {
                resp_payload[1] = STATUS_CMD_FAILED;
                resp_len = 2;
            }
            break;
        }
        
        default: {
            resp_payload[0] = cmd;
            resp_payload[1] = STATUS_CMD_UNKNOWN;
            resp_len = 2;
            break;
        }
    }
    
    build_response(engine, resp_payload, resp_len);
}

    /* Тест 2: Налаштування безпечної швидкості SCK */

    uint8_t set_param_cmd[] = {CMD_SET_PARAMETER, PARAM_SCK_DURATION, 8};
    stk_process_command(&engine, set_param_cmd, sizeof(set_param_cmd));
    printf("    -> УСПІХ: Встановлено частоту f_ISP = %lu Гц.\n", (unsigned long)engine.mcu.current_isp_hz);
```

```cpp
// ============================================================================
// Програмний рушій емулятора ISP-програматора STK500v2 (Стандарт C++20)
// ============================================================================

#include <cstdint>
#include <array>
#include <vector>
#include <span>
#include <string>
#include <string_view>
#include <algorithm>
#include <iostream>
#include <expected>
#include <numeric>

namespace stk500 {

inline constexpr std::uint8_t MessageStart = 0x1B;
inline constexpr std::uint8_t TokenMarker  = 0x0E;

enum class Command : std::uint8_t {
    SignOn            = 0x01,
    SetParameter      = 0x02,
    GetParameter      = 0x03,
    LoadAddress       = 0x06,
    EnterProgModeIsp  = 0x10,
    LeaveProgModeIsp  = 0x11,
    ChipEraseIsp      = 0x12,
    ProgramFlashIsp   = 0x13,
    ReadFlashIsp      = 0x14,
    ProgramEepromIsp  = 0x15,
    ReadEepromIsp     = 0x16,
    ProgramFuseIsp    = 0x17,
    ReadFuseIsp       = 0x18,
    SpiMulti          = 0x1D
};

enum class Status : std::uint8_t {
    Ok                = 0x00,
    Timeout           = 0x80,
    Failed            = 0xC0,
    Unknown           = 0xC9
};

enum class Parameter : std::uint8_t {
    HwVersion         = 0x90,
    SwMajor           = 0x91,
    SwMinor           = 0x92,
    VTarget           = 0x94,
    SckDuration       = 0x98
};

// ── Віртуальна модель мікроконтролера ───────────────────────────────────────

class VirtualMcu {
public:
    static constexpr std::size_t FlashSize  = 32768;
    static constexpr std::size_t PageSize   = 128;
    static constexpr std::size_t EepromSize = 1024;
    static constexpr std::array<std::uint8_t, 3> Signature{0x1E, 0x95, 0x0F}; // ATmega328P

    VirtualMcu() noexcept {
        reset();
    }

    void reset() noexcept {
        flash_.fill(0xFF);
        eeprom_.fill(0xFF);
        fuse_low_ = 0x62;
        fuse_high_ = 0xD9;
        fuse_ext_ = 0xFF;
        lock_bits_ = 0xFF;
        current_byte_address_ = 0;
        in_prog_mode_ = false;
        cpu_hz_ = 1'000'000;
        isp_hz_ = 125'000;
    }

    void chip_erase() noexcept {
        flash_.fill(0xFF);
        if ((fuse_high_ & 0x08) != 0) { // Якщо EESAVE не встановлено
            eeprom_.fill(0xFF);
        }
        lock_bits_ = 0xFF; // Скидання захисту
    }

    [[nodiscard]] bool enter_prog_mode() noexcept {
        // Перевірка обмеження f_ISP <= f_CPU / 4
        if (isp_hz_ > (cpu_hz_ / 4)) {
            in_prog_mode_ = false;
            return false;
        }
        in_prog_mode_ = true;
        return true;
    }

    void leave_prog_mode() noexcept {
        in_prog_mode_ = false;
    }

    [[nodiscard]] bool in_prog_mode() const noexcept { return in_prog_mode_; }

    void set_address(std::uint32_t byte_addr) noexcept {
        current_byte_address_ = byte_addr;
    }

    [[nodiscard]] std::uint32_t current_address() const noexcept {
        return current_byte_address_;
    }

    [[nodiscard]] bool program_flash_page(std::span<const std::uint8_t> data) noexcept {
        if (!in_prog_mode_ || (lock_bits_ & 0x02) == 0) {
            return false; // Захист від запису
        }
        if (current_byte_address_ + data.size() > FlashSize) {
            return false;
        }
        std::copy(data.begin(), data.end(), flash_.begin() + current_byte_address_);
        current_byte_address_ += static_cast<std::uint32_t>(data.size());
        return true;
    }

    [[nodiscard]] std::vector<std::uint8_t> read_flash(std::size_t length) noexcept {
        std::vector<std::uint8_t> result(length, 0xFF);
        if (!in_prog_mode_) {
            return result;
        }
        // Захист Lock Bits Mode 3
        if ((lock_bits_ & 0x03) == 0) {
            return result; // Повертаємо 0xFF
        }

        if (current_byte_address_ + length <= FlashSize) {
            std::copy_n(flash_.begin() + current_byte_address_, length, result.begin());
            current_byte_address_ += static_cast<std::uint32_t>(length);
        }
        return result;
    }

    void set_isp_frequency(std::uint32_t hz) noexcept { isp_hz_ = hz; }
    [[nodiscard]] std::uint32_t isp_frequency() const noexcept { return isp_hz_; }

    [[nodiscard]] std::uint8_t fuse_low() const noexcept { return fuse_low_; }
    [[nodiscard]] std::uint8_t fuse_high() const noexcept { return fuse_high_; }
    [[nodiscard]] std::uint8_t fuse_ext() const noexcept { return fuse_ext_; }
    [[nodiscard]] std::uint8_t lock_bits() const noexcept { return lock_bits_; }

    void apply_lock_bits(std::uint8_t bits) noexcept {
        lock_bits_ &= bits; // Тільки скидання в нуль
    }

private:
    std::array<std::uint8_t, FlashSize> flash_{};
    std::array<std::uint8_t, EepromSize> eeprom_{};
    std::uint8_t fuse_low_{0x62};
    std::uint8_t fuse_high_{0xD9};
    std::uint8_t fuse_ext_{0xFF};
    std::uint8_t lock_bits_{0xFF};
    std::uint32_t current_byte_address_{0};
    bool in_prog_mode_{false};
    std::uint32_t cpu_hz_{1'000'000};
    std::uint32_t isp_hz_{125'000};
};

// ── Рушій емулятора STK500v2 ───────────────────────────────────────────────

class Stk500Engine {
public:
    Stk500Engine() noexcept = default;

    [[nodiscard]] VirtualMcu& mcu() noexcept { return mcu_; }
    [[nodiscard]] const VirtualMcu& mcu() const noexcept { return mcu_; }

    [[nodiscard]] std::vector<std::uint8_t> process_command(std::span<const std::uint8_t> payload) {
        if (payload.empty()) {
            return build_frame(std::array<std::uint8_t, 2>{0x00, static_cast<std::uint8_t>(Status::Failed)});
        }

        const auto cmd = static_cast<Command>(payload[0]);
        std::vector<std::uint8_t> resp;

        switch (cmd) {
            case Command::SignOn: {
                resp.push_back(static_cast<std::uint8_t>(Command::SignOn));
                resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                constexpr std::string_view name = "AVRISP_2";
                resp.push_back(static_cast<std::uint8_t>(name.size()));
                resp.insert(resp.end(), name.begin(), name.end());
                break;
            }

            case Command::SetParameter: {
                resp.push_back(static_cast<std::uint8_t>(Command::SetParameter));
                if (payload.size() >= 3) {
                    const auto param = static_cast<Parameter>(payload[1]);
                    const std::uint8_t val = payload[2];
                    if (param == Parameter::SckDuration) {
                        sck_duration_ = val;
                        const std::uint32_t hz = (val > 0) ? (1'000'000u / val) : 2'000'000u;
                        mcu_.set_isp_frequency(hz);
                    }
                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                } else {
                    resp.push_back(static_cast<std::uint8_t>(Status::Failed));
                }
                break;
            }

            case Command::GetParameter: {
                resp.push_back(static_cast<std::uint8_t>(Command::GetParameter));
                resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                const auto param = (payload.size() >= 2) ? static_cast<Parameter>(payload[1]) : Parameter::HwVersion;
                switch (param) {
                    case Parameter::HwVersion:   resp.push_back(0x02); break;
                    case Parameter::SwMajor:     resp.push_back(0x02); break;
                    case Parameter::SwMinor:     resp.push_back(0x0A); break;
                    case Parameter::VTarget:     resp.push_back(50);   break;
                    case Parameter::SckDuration: resp.push_back(sck_duration_); break;
                    default:                     resp.push_back(0x00); break;
                }
                break;
            }

            case Command::LoadAddress: {
                resp.push_back(static_cast<std::uint8_t>(Command::LoadAddress));
                if (payload.size() >= 5) {
                    const std::uint32_t word_addr = ((static_cast<std::uint32_t>(payload[1]) << 24) |
                                                     (static_cast<std::uint32_t>(payload[2]) << 16) |
                                                     (static_cast<std::uint32_t>(payload[3]) << 8)  |
                                                     (static_cast<std::uint32_t>(payload[4]))) & 0x7FFFFFFF;
                    mcu_.set_address(word_addr * 2);
                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                } else {
                    resp.push_back(static_cast<std::uint8_t>(Status::Failed));
                }
                break;
            }

            case Command::EnterProgModeIsp: {
                resp.push_back(static_cast<std::uint8_t>(Command::EnterProgModeIsp));
                const bool ok = mcu_.enter_prog_mode();
                resp.push_back(static_cast<std::uint8_t>(ok ? Status::Ok : Status::Failed));
                break;
            }

            case Command::LeaveProgModeIsp: {
                resp.push_back(static_cast<std::uint8_t>(Command::LeaveProgModeIsp));
                mcu_.leave_prog_mode();
                resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                break;
            }

            case Command::ChipEraseIsp: {
                resp.push_back(static_cast<std::uint8_t>(Command::ChipEraseIsp));
                if (mcu_.in_prog_mode()) {
                    mcu_.chip_erase();
                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                } else {
                    resp.push_back(static_cast<std::uint8_t>(Status::Failed));
                }
                break;
            }

            case Command::ProgramFlashIsp: {
                resp.push_back(static_cast<std::uint8_t>(Command::ProgramFlashIsp));
                if (payload.size() >= 10) {
                    const std::size_t num_bytes = (static_cast<std::size_t>(payload[1]) << 8) | payload[2];
                    const auto data_slice = payload.subspan(10, num_bytes);
                    const bool ok = mcu_.program_flash_page(data_slice);
                    resp.push_back(static_cast<std::uint8_t>(ok ? Status::Ok : Status::Failed));
                } else {
                    resp.push_back(static_cast<std::uint8_t>(Status::Failed));
                }
                break;
            }

            case Command::ReadFlashIsp: {
                resp.push_back(static_cast<std::uint8_t>(Command::ReadFlashIsp));
                if (payload.size() >= 3) {
                    const std::size_t num_bytes = (static_cast<std::size_t>(payload[1]) << 8) | payload[2];
                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                    const auto read_data = mcu_.read_flash(num_bytes);
                    resp.insert(resp.end(), read_data.begin(), read_data.end());
                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                } else {
                    resp.push_back(static_cast<std::uint8_t>(Status::Failed));
                }
                break;
            }

            case Command::SpiMulti: {
                resp.push_back(static_cast<std::uint8_t>(Command::SpiMulti));
                if (payload.size() >= 8 && mcu_.in_prog_mode()) {
                    const std::uint8_t num_tx = payload[1];
                    const std::uint8_t num_rx = payload[2];
                    const std::uint8_t rx_start = payload[3];
                    const auto tx_data = payload.subspan(4, num_tx);

                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                    std::array<std::uint8_t, 4> rx_buf{0, 0, 0, 0};

                    if (tx_data.size() >= 4) {
                        const std::uint8_t op = tx_data[0];
                        if (op == 0x30) { // Read Signature
                            const std::uint8_t addr = tx_data[2];
                            if (addr < VirtualMcu::Signature.size()) {
                                rx_buf[3] = VirtualMcu::Signature[addr];
                            }
                        } else if (op == 0x58 && tx_data[1] == 0x00) {
                            rx_buf[3] = mcu_.fuse_low();
                        } else if (op == 0x58 && tx_data[1] == 0x08) {
                            rx_buf[3] = mcu_.fuse_high();
                        } else if (op == 0x50 && tx_data[1] == 0x08) {
                            rx_buf[3] = mcu_.fuse_ext();
                        } else if (op == 0xAC && tx_data[1] == 0xE0) {
                            mcu_.apply_lock_bits(tx_data[3]);
                        }
                    }

                    for (std::uint8_t i = 0; i < num_rx; ++i) {
                        resp.push_back(rx_buf[rx_start + i]);
                    }
                    resp.push_back(static_cast<std::uint8_t>(Status::Ok));
                } else {
                    resp.push_back(static_cast<std::uint8_t>(Status::Failed));
                }
                break;
            }

            default:
                resp.push_back(static_cast<std::uint8_t>(cmd));
                resp.push_back(static_cast<std::uint8_t>(Status::Unknown));
                break;
        }

        return build_frame(resp);
    }

private:
    [[nodiscard]] std::vector<std::uint8_t> build_frame(std::span<const std::uint8_t> payload) {
        std::vector<std::uint8_t> frame;
        frame.reserve(6 + payload.size());

        frame.push_back(MessageStart);
        frame.push_back(seq_num_++);
        frame.push_back(static_cast<std::uint8_t>((payload.size() >> 8) & 0xFF));
        frame.push_back(static_cast<std::uint8_t>(payload.size() & 0xFF));
        frame.push_back(TokenMarker);

        frame.insert(frame.end(), payload.begin(), payload.end());

        const std::uint8_t checksum = std::accumulate(frame.begin(), frame.end(), static_cast<std::uint8_t>(0),
                                                      [](std::uint8_t acc, std::uint8_t b) { return acc ^ b; });
        frame.push_back(checksum);
        return frame;
    }

    VirtualMcu mcu_{};
    std::uint8_t seq_num_{0};
    std::uint8_t sck_duration_{8};
};

} // namespace stk500
```

### Покроковий розбір інтеграційного тестового стенду

Вбудована функція `main()` демонструє повний життєвий цикл роботи програматора від першого опитування до завершення прошивки та зняття сигналу скидання. Розгляньмо фізичний та протокольний зміст кожного з 8 етапів тестування:

1. **Етап 1: Ідентифікація програматора (`CMD_SIGN_ON`)**
   Тест надсилає 1-байтну команду `0x01`. Емулятор формує відповідь із статусом `STATUS_CMD_OK` (`0x00`) та повертає текстовий рядок `AVRISP_2` довжиною 8 байтів. Це підтверджує готовність комунікаційного мосту до прийому команд конфігурації.
2. **Етап 2: Налаштування тривалості такту (`CMD_SET_PARAMETER`)**
   Тест встановлює параметр `PARAM_SCK_DURATION = 8`, що задає тривалість напівперіоду тактів шини ISP. Емулятор розраховує відповідну частоту `f_ISP = 125 кГц`. Оскільки це значення є нижчим за граничну безпечну межу `f_CPU / 4 = 250 кГц`, емулятор фіксує безпечний режим тактування.
3. **Етап 3: Захоплення мікроконтролера в режим ISP (`CMD_ENTER_PROGMODE_ISP`)**
   Тест передає розширений пакет конфігурації скидання разом із 4-байтною командою `0xAC 0x53 0x00 0x00`. Емулятор перевіряє поточну частоту шини, встановлює внутрішній прапорець `in_programming_mode = true` та повертає код підтвердження `0x00`.
4. **Етап 4: Зчитування та валідація сигнатури кристала (`CMD_SPI_MULTI`)**
   Тест виконує три послідовні низькорівневі транзакції `0x30 0x00 [0..2] 0x00`. Емулятор зчитує статичні байти дескриптора `0x1E`, `0x95`, `0x0F` та повертає їх хосту. Тестовий стенд звіряє вичитані байти з еталоном ATmega328P і лише за умови повного збігу дозволяє перехід до наступного кроку.
5. **Етап 5: Повне стирання кристала (`CMD_CHIP_ERASE_ISP`)**
   Тест ініціює операцію повного очищення кристала. Емулятор заповнює масив Flash байтами `0xFF`, стирає EEPROM та повертає регістр Lock Bits у відкритий стан `0xFF` (Mode 1).
6. **Етап 6: Посторінковий запис образу прошивки (`CMD_LOAD_ADDRESS` + `CMD_PROGRAM_FLASH_ISP`)**
   Тест встановлює початкову адресу `0x0000` та передає сторінку обсягом 128 байтів із тестовим числовим патерном. Емулятор перевіряє права доступу за Lock Bits і переносить дані у відповідний сегмент віртуального масиву Flash.
7. **Етап 7: Посторінкова верифікація пам'яті (`CMD_READ_FLASH_ISP`)**
   Тест скидає адресу в `0x0000` та вичитує назад записані 128 байтів. Стенд здійснює побайтове порівняння оригіналу з вичитаними даними, підтверджуючи 100% цілісність запису.
8. **Етап 8: Вихід із режиму програмування (`CMD_LEAVE_PROGMODE_ISP`)**
   Тест знімає режим ISP. Емулятор скидає прапорець `in_programming_mode = false`, симулюючи перехід сигналу `RESET` у високий рівень (+5V) та передачу керування щойно записаній прошивці.

### Інструкція з розгортання та інтеграції в тестові стенди HIL

Для використання розробленого рушія в реальних конвеєрах тестування та інтеграції з утилітою `avrdude` виконуються наступні кроки:

#### 1. Компіляція та збірка
Компіляція здійснюється будь-яким стандартним компілятором C/C++:

```bash
# Збірка версії C99
gcc -std=c99 -Wall -Wextra -O2 stk500_emulator.c -o stk500_emulator

# Збірка версії C++20
g++ -std=c++20 -Wall -Wextra -O2 stk500_emulator.cpp -o stk500_emulator_cpp
```

#### 2. Створення віртуального COM-порту в Linux
Для з'єднання емулятора з `avrdude` створюється пара зв'язаних віртуальних псевдотерміналів за допомогою утиліти `socat`:

```bash
# Створення зв'язаної пари віртуальних портів
socat -d -d pty,raw,echo=0,link=/tmp/vcom_emu pty,raw,echo=0,link=/tmp/vcom_client
```

Емулятор підключається до порту `/tmp/vcom_emu`, а утиліта прошивки викликається до клієнтського кінця:

```bash
# Запуск прошивки через avrdude до віртуального емулятора
avrdude -c stk500v2 -p m328p -P /tmp/vcom_client -b 115200 -U flash:w:firmware.hex:i
```

У результаті `avrdude` зв'язується з рушієм емулятора, вичитує сигнатуру `0x1E 0x95 0x0F`, проводить посторінковий запис файлу прошивки та виконує верифікацію без фізичного підключення будь-яких апаратних плат.

### Автоматизація тестування в пайплайнах GitHub Actions

Завдяки повній відсутності зовнішніх залежностей емулятор легко вбудовується у файли конфігурації безперервної інтеграції CI/CD:

```yaml
# Приклад кроку CI для автоматичного тестування прошивки
name: Firmware Flashing Verification
on: [push, pull_request]

jobs:
  test-flashing:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Build Firmware and Emulator
        run: |
          sudo apt-get update && sudo apt-get install -y avrdude gcc-avr avr-libc socat
          avr-gcc -mmcu=atmega328p -Os -o main.elf main.c
          avr-objcopy -O ihex -R .eeprom main.elf firmware.hex
          gcc -std=c99 -O2 stk500_emulator.c -o stk500_emulator
      - name: Run Virtual Flashing Test
        run: |
          socat -d -d pty,raw,echo=0,link=/tmp/vcom_emu pty,raw,echo=0,link=/tmp/vcom_client &
          sleep 1
          ./stk500_emulator /tmp/vcom_emu &
          sleep 1
          avrdude -c stk500v2 -p m328p -P /tmp/vcom_client -b 115200 -U flash:w:firmware.hex:i
```

Такий підхід гарантує, що кожна зміна у коді проекту проходить повну перевірку сумісності з реальними інструментами програмування ще до етапу масового тиражування на платах.

### Порівняння зі спеціалізованими симуляторами (Simavr, Simulavr)

При проектуванні автоматизованих конвеєрів тестування розробники часто обирають між повними симуляторами інструкцій ядра (наприклад, `simavr` або `simulavr`) та спеціалізованими емуляторами протоколів програмування (на кшталт розробленого STK500v2 Engine).

1. **Швидкодія та споживання пам'яті:** повні емулятори інструкцій ядра емулюють кожен машинний такт процесора, регістри вводу-виводу, АЦП та таймери, що вимагає значних обчислювальних ресурсів процесора хоста. Розроблений емулятор протоколу ISP зосереджений виключно на інтерфейсі прошивки та пам'яті, виконуючи запис образу 32 КБ за частки мілісекунди з нульовим споживанням додаткової RAM;
2. **Ізольоване тестування утиліт розгортання:** якщо мета тесту полягає у верифікації виробничих скриптів прошивки, конфігурації бітів Fuses або калібрувальних таблиць EEPROM, емулятор протоколу забезпечує 100% сумісність з `avrdude` без необхідності запуску коду самої прошивки;
3. **Легкість інжектування несправностей:** модифікувати декілька рядків коду в нашому емуляторі для симуляції збою пам'яті чи нестабільності частоти `f_ISP` у рази простіше, ніж переналаштовувати складне ядро симулятора процесорних інструкцій.

### Крайові випадки, захист від переповнень та обробка аномалій

Надійність роботи емулятора у промислових середовищах забезпечується обробкою повного спектра позаштатних ситуацій:

1. **Захист від переповнення адресного простору:** якщо клієнт намагається записати блок даних, розмір якого перевищує межу 32 КБ Flash, або передає некоректну адресу через `CMD_LOAD_ADDRESS`, диспетчер блокує вихід за межі масиву та повертає статус помилки `STATUS_CMD_FAILED`;
2. **Обробка асинхронного пошкодження пакетів:** якщо вхідний двійковий потік містить сміття або випадкові байти `0x1B` всередині корисного навантаження, скінченний автомат завдяки перевірці розділового токена `0x0E` та суворому розрахунку контрольної суми XOR безпечно відкидає пошкоджений кадр і автоматично синхронізується на наступному дійсному пакеті;
3. **Емуляція захищеного стану при блокуванні Lock Bits:** при спробі прочитати Flash або EEPROM чіпа, заблокованого у Mode 3, емулятор не перериває з'єднання аварійно, а точно імітує поведінку фізичного кремнію AVR, повертаючи масив суцільних байтів `0xFF`;
4. **Розширення адресації для великих чіпів (Flash > 64 КБ):** при масштабуванні моделі до ATmega2560 (256 КБ Flash) адреса слів перевищує 16 біт. У реальному протоколі STK500 v2 для цього використовується команда `CMD_LOAD_EXT_ADDRESS`, яка встановлює розширений байт адреси сегмента (*Extended Segment Address*). Рушій може бути легко доповнений підтримкою 3-байтних фізичних покажчиків;
5. **Моделювання аналогового скидання при просіданні живлення (Brown-Out Detection):** якщо вхідна напруга `PARAM_VTARGET` падає нижче порогу, заданого бітами `BODLEVEL` у регістрі `fuse_ext` (наприклад, нижче 2.7V або 4.3V), емулятор переводить модель у стан апаратного блокування, симулюючи спрацьовування внутрішнього компаратора BOD та запобігаючи спотворенню пам'яті.
