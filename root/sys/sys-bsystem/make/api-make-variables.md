# 📋 Довідник змінних, автоматичних підстановок і функцій GNU Make

Утиліта GNU Make містить великий набір вбудованих змінних, автоматичних макросів, спеціальних цілей та функцій перетворення тексту. Разом вони утворюють повноцінний внутрішній інтерфейс для розрахунку графа залежностей, маніпуляцій шляхами до файлів і формування командних рядків компілятора. Коли виникає потреба витягнути каталог зі складного шляху, профільтрувати список об'єктних файлів, отримати перелік пререквізитів без дублікатів чи гарантувати коректне видалення пошкоджених артефактів після збою, звертаються до цих стандартних конструкцій.

Цей довідник містить систематичний опис синтаксису, поведінки та семантичних тонкощів кожної категорії вбудованих інструментів GNU Make.

## 1. Автоматичні змінні (Automatic Variables)

Автоматичні змінні обчислюються утилітою `make` індивідуально для кожного правила у **фазі виконання** (Execute Phase) безпосередньо перед запуском рядків відповідного рецепта. Їхні значення динамічно генеруються на основі імені поточної цілі та списку її пререквізитів, які зіставилися з цим правилом.

Спроба звернутися до автоматичної змінної поза межами рецепта (наприклад, у правій частині негайного присвоєння `:=` чи в заголовку правила) поверне порожній рядок, оскільки у фазі читання конкретна ціль ще не обробляється.

| Змінна | Опис значення | Фаза доступності |
|---|---|---|
| `$@` | Ім'я цілі (*target*), яка зараз виконується. Якщо ціль є членом архіву бібліотеки, це ім'я самого архіву. | Рецепт у фазі 2 |
| `$%` | Ім'я члена архіву, якщо ціль має вигляд `lib.a(member.o)`. Порожнє для звичайних файлових цілей. | Рецепт у фазі 2 |
| `$<` | Ім'я **першого** пререквізиту правила (*first prerequisite*). Якщо правило шаблонне (`%.o: %.c`), це вихідний файл. | Рецепт у фазі 2 |
| `$^` | Імена **всіх** пререквізитів через пробіл із **видаленням дублікатів**. Порядок відповідає оголошенню. | Рецепт у фазі 2 |
| `$+` | Імена **всіх** пререквізитів через пробіл зі **збереженням повторів**. | Рецепт у фазі 2 |
| `$?` | Імена лише тих пререквізитів, чий час зміни (`mtime`) **новіший** за ціль, або тих, яких фізично немає на диску. | Рецепт у фазі 2 |
| `$*` | Основа (*stem*) шаблонного правила — частина імені, яка збіглася зі знаком відсотка `%`. | Рецепт у фазі 2 |
| `$(@D)` | Каталог цілі без завершального слеша (еквівалент виклику `$(patsubst %/,%,$(dir $@))`). Якщо ціль лежить у поточному каталозі, повертає `.`. | Рецепт у фазі 2 |
| `$(@F)` | Ім'я файлу цілі без шляху каталогу (еквівалент виклику `$(notdir $@)`). | Рецепт у фазі 2 |
| `$(<D)` | Каталог першого пререквізиту без завершального слеша. | Рецепт у фазі 2 |
| `$(<F)` | Ім'я файлу першого пререквізиту без шляху каталогу. | Рецепт у фазі 2 |
| `$(^D)` | Список каталогів усіх пререквізитів через пробіл без завершальних слешів. | Рецепт у фазі 2 |
| `$(^F)` | Список імен файлів усіх пререквізитів без шляхів каталогів. | Рецепт у фазі 2 |

### Тонкощі поведінки та приклади

Розгляньмо, як саме формуються значення автоматичних змінних на типових сценаріях збірки:

```make
# Шаблонне правило компіляції об'єктного файлу у вихідний каталог build/
build/%.o: src/%.c include/%.h
	@mkdir -p $(@D)
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

# Лінкування виконуваного бінарного файлу
bin/app: build/main.o build/parser.o build/lexer.o
	@mkdir -p $(@D)
	$(CC) $(LDFLAGS) $^ $(LDLIBS) -o $@
```

У наведеному фрагменті:
- Під час складання об'єкта `build/parser.o`: змінна `$@` містить точний рядок `build/parser.o`, модифікатор `$(@D)` повертає каталог `build`, перший пререквізит `$<` вказує на `src/parser.c`, а основа `$*` містить рядок `parser`.
- Під час лінкування `bin/app`: автоматична змінна `$^` об'єднує всі об'єктні модулі `build/main.o build/parser.o build/lexer.o` в єдиний список. Якщо якийсь об'єкт помилково вказано двічі в списку залежностей, `$^` автоматично відкине копію, запобігаючи помилкам повторного визначення символів у лінкері.
- Змінна `$+` навпаки, зберігає повтори. Це буває необхідно під час роботи зі статичними архівами на старих версіях лінкера GNU `ld`, коли дві бібліотеки мають циклічні посилання одна на одну і вимагають подвійного зазначення у командному рядку.

## 2. Стандартні змінні та конвенції тулчейну

GNU Make має великий набір зумовлених змінних (*implicit variables*), які використовуються у вбудованих неявних правилах трансляції мов C, C++, Fortran, асемблера тощо. Дотримання загальноприйнятих назв цих змінних забезпечує взаємозамінність тулчейнів і коректну інтеграцію з мета-системами збірки (Autotools, CMake).

### Виконавчі програми компіляторів та системних утиліт

Ці змінні визначають, які саме бінарні файли утиліта Make викликатиме для виконання типових операцій:

| Змінна | Типове значення | Семантичне призначення |
|---|---|---|
| `CC` | `cc` (або `gcc`) | Драйвер компілятора мови C |
| `CXX` | `g++` | Драйвер компілятора мови C++ |
| `CPP` | `$(CC) -E` | Препроцесор мови C для генерації розгорнутого коду |
| `AS` | `as` | Асемблер для трансляції асемблерних інструкцій |
| `AR` | `ar` | Архіватор бібліотечних об'єктних файлів |
| `ARFLAGS` | `rv` | Ключі командного рядка для архіватора `ar` (заміна зі звітом) |
| `LD` | `ld` | Системний лінкер (компонувальник) |
| `RM` | `rm -f` | Утиліта примусового видалення файлів без зупинки через відсутність |
| `SHELL` | `/bin/sh` | Командна оболонка, яку Make викликає для виконання кожного рядка рецепта |
| `MAKE` | Шлях до поточного бінарника make | Змінна для безпечного рекурсивного виклику підпорядкованих Makefile |

### Прапорці компіляції, оптимізації та компонування

Прапорці компіляції розділяються за рівнями конвеєра збірки. Змішування прапорців компілятора з прапорцями препроцесора чи бібліотеками компонування є грубим порушенням структури Makefile.

| Змінна | Призначення в конвеєрі | Приклад рекомендованого значення |
|---|---|---|
| `CPPFLAGS` | Прапорці препроцесора C та C++ (шляхи пошуку заголовків `-I`, визначення макросів `-D`) | `-Iinclude -D_GNU_SOURCE -DNDEBUG` |
| `CFLAGS` | Прапорці трансляції мови C (стандарт мови, попередження, генерація налагоджувальних символів) | `-std=c17 -O2 -Wall -Wextra -pedantic -g` |
| `CXXFLAGS` | Прапорці трансляції мови C++ (версія стандарту ISO C++, керування RTTI та винятками) | `-std=c++20 -O3 -Wall -Wextra -Wshadow` |
| `ASFLAGS` | Прапорці асемблера для обробки асемблерних файлів | `-g -Wa,--warn` |
| `LDFLAGS` | Загальні прапорці лінкування (шляхи пошуку бібліотек `-L`, прапорці підсистеми, опції `-Wl,...`) | `-L/usr/local/lib -Wl,-rpath,/opt/app/lib` |
| `LDLIBS` | Перелік бібліотек для передачі лінкеру (прапорці `-l...`) | `-lm -lpthread -lssl -lcrypto` |

### Важливість порядку аргументів під час лінкування

Позиція змінних у рядку лінкування критично впливає на результат збірки:

```make
# ПРАВИЛЬНО: LDFLAGS стоїть ДО об'єктів, LDLIBS — строго ПІСЛЯ об'єктів
$(TARGET): $(OBJS)
	$(CC) $(LDFLAGS) $^ $(LDLIBS) -o $@

# НЕПРАВИЛЬНО: LDLIBS стоїть перед об'єктами (викличе помилку undefined reference)
$(TARGET): $(OBJS)
	$(CC) $(LDLIBS) $(LDFLAGS) $^ -o $@
```

Це правило обумовлене однопрохідною моделлю класичного компонувальника `ld`: коли компонувальник зустрічає прапорець бібліотеки `-lm` на початку рядка, він бачить, що жоден символ із math-бібліотеки ще не потрібен (адже об'єктні файли `$^` стоять пізніше), і викидає бібліотеку з розгляду. Коли далі зчитується `main.o` з викликом функції `sqrt()`, символ лишається нерозв'язаним.

## 3. Спеціальні керуючі цілі (Special Built-in Targets)

Спеціальні цілі починаються з символу крапки і записуються великими літерами. Вони не створюють файлів на файловій системі, а керують внутрішньою логікою планувальника завдань GNU Make, оптимізують паралелізм та забезпечують цілісність збірки.

| Спеціальна ціль | Механізм впливу на процес збірки |
|---|---|
| `.PHONY` | Оголошує свої пререквізити абстрактними діями. Make ніколи не зіставляє їх із файлами на диску і завжди безумовно виконує відповідні команди. |
| `.DELETE_ON_ERROR` | Наказує Make автоматично видаляти ціль, якщо команда її рецепта завершилася аварійно з ненульовим кодом або була перервана сигналом операційної системи. |
| `.PRECIOUS` | Захищає вказані цілі та проміжні файли від видалення у разі аварійного переривання збірки (наприклад, сигналу `SIGINT` при натисканні `Ctrl+C`). |
| `.INTERMEDIATE` | Позначає проміжні ланки ланцюга неявних правил; такі файли автоматично видаляються після успішного завершення загального ланцюжка збірки. |
| `.SECONDARY` | Працює аналогічно до `.INTERMEDIATE`, але **забороняє** автоматичне видалення проміжних файлів після збірки, запобігаючи їхньому повторному перезбиранню. |
| `.ONESHELL` | Вказує Make передавати весь багаторядковий блок рецепта цілі єдиному екземпляру командної оболонки, зберігаючи стан змінних і робочого каталогу між рядками. |
| `.SILENT` | Придушує стандартний друк (відлуння) виконуваних команд у термінал для зазначених цілей (аналог префікса `@` для кожного рядка). |
| `.NOTPARALLEL` | Примусово вимикає багатопотоковий режим (`-j`) для всього файлу або для списку зазначених цілей, змушуючи виконувати їх послідовно. |
| `.SUFFIXES` | Очищає або перевизначає список розширень, що підтримуються застарілими суфіксними правилами. Запис `.SUFFIXES:` без параметрів вимикає всі вбудовані суфікси. |
| `.SECONDEXPANSION:` | Вмикає додатковий другий прохід розгортання змінних у пререквізитах для всіх наступних правил файлу безпосередньо перед обходом цілі. |
| `.EXPORT_ALL_VARIABLES:` | Автоматично експортує всі змінні Makefile у змінні оточення для кожного дочірнього процесу командної оболонки. |

### Механіка вторинного розгортання (`.SECONDEXPANSION:`)

Звичайна модель Make розгортає пререквізити правила негайно у фазі читання. Через це неможливо використати автоматичну змінну `$@` у списку залежностей, бо сама ціль ще не відома. 

Директива `.SECONDEXPANSION:` дозволяє відкласти розгортання пререквізитів до другої фази. Щоб захистити змінні від першого проходу розгортання, перед знаком долара ставлять другий `$$`:

```make
.SECONDEXPANSION:

# Пререквізит обчислюється індивідуально для кожної цілі
# Для build/parser.o шукається src/parser.c
# Для build/lib/math.o шукається src/lib/math.c
build/%.o: src/$$(patsubst build/%,%,$$*).c
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) -c $< -o $@
```

У цьому прикладі під час другого проходу `$$*` розгортається у стебло конкретної цілі, дозволяючи будувати складні правила відображення каталогів без написання громіздких явних списків.

## 4. Пошук файлів через VPATH та vpath

Коли вихідні файли проекту рознесені по багатьох підкаталогах (`src/`, `src/net/`, `src/crypto/`), а об'єктні файли складаються в єдину папку `build/`, Make потребує механізму пошуку джерел.

Для цього існують дві форми директиви пошуку:

1. **Глобальна змінна `VPATH`:** містить список каталогів, розділених двокрапками (або пробілами), де Make шукає будь-які пререквізити, не знайдені в поточному каталозі.
   ```make
   VPATH = src:src/net:src/crypto
   ```
2. **Вибіркова директива `vpath` (малими літерами):** прив'язує конкретний шаблон розширень файлів до конкретних каталогів.
   ```make
   # Шукати файли .c у підкаталогах src/net та src/crypto
   vpath %.c src/net src/crypto
   # Шукати заголовки .h у каталозі include
   vpath %.h include
   ```

### Як VPATH взаємодіє з автоматичними змінними

Коли Make знаходить пререквізит за допомогою `vpath`, автоматична змінна `$<` отримує **повний відносний шлях** до знайденого файлу (наприклад, `src/net/socket.c`), тоді як у правилі було зазначено просто `socket.c`. 

Це вимагає суворого використання автоматичної змінної `$<` у рецепті: якщо замість `$<` написати жорстке ім'я `socket.c`, компілятор шукатиме його в поточному каталозі й збірка зазнає невдачі.

## 5. Префікси рядків рецепта: керування виконанням команд

Кожен рядок командного блоку рецепта може мати спеціальні односимвольні префікси, які модифікують стандартну поведінку оболонки:

| Префікс | Ефект під час виконання |
|---|---|
| `@` | **Придушення відлуння:** Make не друкує текст команди в термінал перед її запуском. Використовується для викликів `echo` та створення каталогів: `@mkdir -p $(@D)`. |
| `-` | **Ігнорування помилок:** Якщо команда повертає ненульовий код помилки, Make ігнорує її й продовжує виконання наступних рядків рецепта замість зупинки: `-rm -f *.o`. |
| `+` | **Примусове виконання у сухому режимі:** Команда виконується навіть тоді, коли Make запущено з прапорцем `-n` (`--dry-run`). Необхідно для рекурсивних викликів `$(MAKE)`, щоб Make міг побудувати дерево підпорядкованих процесів. |

Префікси можна комбінувати на початку одного рядка (наприклад, `@+$(MAKE) -C subdir` одночасно придушує друк команди та гарантує її виконання під час аналізу сухого прогону).

## 7. Прапорці запуску та діагностика графа GNU Make

У процесі налагодження складних Makefile незамінними стають спеціальні параметри командного рядка утиліти Make:

- `make -n` (або `--dry-run`, `--just-print`) — симулює процес збірки: виводить у термінал усі команди, які були б запущені, але не виконує їх насправді.
- `make -d` (або `--debug=a`) — вмикає повний діагностичний протокол: видруковує інформацію про кожен вузол графа, перевірку `mtime`, неявні ланцюги правил та причину прийняття рішення щодо кожного файлу.
- `make --trace` — виводить точне правило, номер рядка у Makefile та команду, яка ініціювала виконання кожної поточної дії.
- `make -p` (або `--print-data-base`) — видруковує повну внутрішню базу даних Make: усі зумовлені та визначені користувачем правила, змінні, значення суфіксів і каталоги пошуку `VPATH`.
- `make -j<N>` (або `--jobs=<N>`) — задає максимальну кількість паралельних процесів компіляції, активуючи системний протокол Jobserver для керування навантаженням.
- `make -k` (або `--keep-going`) — продовжує збірку незалежних гілок графа залежностей навіть у разі виникнення помилки в одній із цілей, виявляючи всі можливі дефекти за один прогін.
