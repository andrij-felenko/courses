Досягнення бінарної відтворюваності вимагає точного конфігурування кожного інструмента в ланцюгу трансляції: препроцесора, компілятора, компонувальника, архіватора статичних бібліотек та утиліт пакування результуючих дистрибутивів. За замовчуванням більшість системних утиліт зчитують стан операційної системи хоста й вшивають у вихідні двійкові файли поточний системний час, абсолютні шляхи до каталогів на диску, числові ідентифікатори користувачів або випадкові маркери збірки.

Щоб усунути ці витоки, кожен рівень конвеєра повинен отримати набір прапорців нормалізації та працювати в санітизованому середовищі. Нижче наведено детальний опис контрактів, синтаксису прапорців, змінних оточення та поведінки інструментів.

## Специфікація стандарту SOURCE_DATE_EPOCH

Змінна середовища `SOURCE_DATE_EPOCH` є стандартом консорціуму Reproducible Builds, покликаним замінити звернення до системного таймера `time(NULL)` на детерміністичну часову позначку.

### Формат і правила валідації

Значення змінної — це десяткове ціле невід'ємне число в кодуванні ASCII, яке визначає кількість секунд, що минули з 1 січня 1970 року 00:00:00 UTC (епоха Unix).

Будь-які провідні пробіли, символи кінця рядка, дробові частини або літери вважаються помилкою формату. Якщо змінна містить некоректне значення або порожній рядок, сумісні інструменти зобов'язані завершити роботу з помилкою або проігнорувати її з попередженням у журналі.

```sh
# Отримання дати останнього коміту у репозиторії Git
export SOURCE_DATE_EPOCH=$(git log -1 --format=%ct)

# Отримання дати у репозиторії Mercurial
export SOURCE_DATE_EPOCH=$(hg log -r . --template '{date}\n' | cut -d. -f1)

# Встановлення фіксованого значення за відсутності системи контролю версій
export SOURCE_DATE_EPOCH=${SOURCE_DATE_EPOCH:-1700000000}
```

### Механізм обробки в інструментах трансляції

Коли змінна `SOURCE_DATE_EPOCH` присутня в адресному просторі процесу, системні компілятори та генератори документації змінюють внутрішню поведінку:

1. **Компілятори C/C++ (GCC починаючи з 7.0, Clang починаючи з 4.0)**. Препроцесор перехоплює макроси `__DATE__`, `__TIME__` та `__TIMESTAMP__`. Замість виклику функції `time()` чи `gettimeofday()` препроцесор перетворює число із `SOURCE_DATE_EPOCH` за допомогою функції `gmtime()` у формат UTC і генерує фіксовані рядкові літерали вигляду `"Jan 01 1970"` та `"00:00:00"`.
2. **Компілятор Rust (`rustc`)**. Прапорець за замовчуванням зчитує `SOURCE_DATE_EPOCH` для формування метаданих крейтів та налагоджувальних заголовків.
3. **Байткод Python (`py_compile`)**. Починаючи з версії Python 3.7, компілятор байткоду записує значення `SOURCE_DATE_EPOCH` у поле часової позначки заголовка файлів `.pyc`, забезпечуючи однакові бінарні образи модулів.
4. **Генератори документації (Doxygen, Sphinx, Texinfo)**. Утиліти замінюють часові позначки в колонтитулах та метаданих генерованих HTML- або PDF-сторінок на вказане значення.
5. **Системи збірки (CMake, Meson)**. Функція `string(TIMESTAMP ...)` у CMake починаючи з версії 3.8 повертає форматовану дату з `SOURCE_DATE_EPOCH`, якщо змінна визначена.

## Прапорці компіляторів GCC та Clang

Компілятори GCC та Clang надають спеціальні прапорці заміни префіксів шляхів (англ. *prefix mapping*), які дають змогу збирати проєкт у довільному каталозі без ризику зашити шлях цього каталогу у вихідний бінарний файл.

### Механізм заміни префіксів шляхів

Шляхи до файлів проникають у бінарний артефакт через три незалежні канали: макрос препроцесора `__FILE__`, системний макрос перевірки тверджень `assert()` та секції налагоджувального формату DWARF (`.debug_info`, `.debug_line`).

```sh
# Універсальне правило заміни префіксів (GCC >= 8, Clang >= 10)
-ffile-prefix-map=/home/builder/workspace/myproject=.
-ffile-prefix-map=$PWD=.

# Спеціалізована заміна префіксів для налагоджувальних секцій DWARF
-fdebug-prefix-map=/home/builder/workspace/myproject=/usr/src/debug

# Спеціалізована заміна префіксів для макросів препроцесора (__FILE__, __BASE_FILE__)
-fmacro-prefix-map=/home/builder/workspace/myproject=.

# Заміна шляхів у файлах профілювання gcov (.gcno, .gcda)
-fprofile-prefix-map=/home/builder/workspace/myproject=.
```

Принцип роботи прапорця полягає у лексичній заміні рядка на стадії розбору шляхів: якщо абсолютний шлях до файлу починається з рядка `OLD`, ця префіксна частина замінюється на рядок `NEW`.

Якщо в командному рядку задано кілька прапорців `-ffile-prefix-map`, компілятор застосовує їх у порядку від найдовшого префікса до найкоротшого. Завдяки цьому можна задати специфічні правила для вкладених залежностей та загальне правило для кореневої теки проєкту.

При крос-компіляції зі стороннім системним каталогом sysroot часто комбінують два правила: перше нормалізує шлях до сирців проєкту, а друге — шлях до системних заголовків цільової платформи:

```sh
-ffile-prefix-map=/home/builder/workspace/myproject=.
-ffile-prefix-map=/opt/toolchains/arm-linux-gnueabihf/sysroot=/usr/include
```

### Керування оптимізацією на стадії лінкування (LTO / ThinLTO)

Під час використання глобальної міжмодульної оптимізації (Link-Time Optimization, LTO) компілятор зберігає внутрішнє проміжне представлення (GIMPLE у GCC, LLVM Bitcode у Clang) в об'єктних файлах, а остаточна генерація машинного коду відбувається під час лінкування.

У режимі ThinLTO генерація коду розподіляється між кількома паралельними потоками. Якщо кількість потоків не зафіксована або потоки завершують роботу в довільному порядку, розбиття функцій на модулі може різнитися через стан планувальника задач операційної системи.

Для забезпечення детермінізму LTO використовують такі прапорці:

```sh
# Фіксація кількості паралельних потоків кодогенерації в Clang/LLD
-flto=thin -Wl,--thinlto-jobs=4

# Вимкнення недетерміністичного автовизначення кількості ядер у GCC
-flto=4 -flto-partition=1to1
```

Опція `-flto-partition=1to1` у GCC змушує компілятор призначати кожній вхідній одиниці трансляції рівно один внутрішній розділ LTO, що усуває евристичне динамічне балансування навантаження між ядрами.

### Керування метаданими та налагоджувальною інформацією DWARF

Формат DWARF зберігає інформацію про назву робочого каталогу компіляції в атрибуті `DW_AT_comp_dir` секції `.debug_info`. Прапорець `-fdebug-prefix-map` гарантує, що значення `DW_AT_comp_dir` стане відносним шляхом або фіксованим канонічним рядком (наприклад, `/usr/src/debug`).

Для повного усунення сторонніх маркерів компіляції використовують такі додаткові прапорці:

- `-fno-ident` — вимикає генерацію секції `.comment` у форматі ELF, куди компілятор за замовчуванням записує назву та точну версію компілятора (наприклад, `GCC: (Debian 12.2.0-14) 12.2.0`). Якщо двоє розробників використовують різні мінорні версії дистрибутивних збірок GCC, секція `.comment` призведе до бінарної розбіжності.
- `-gno-record-gcc-switches` — забороняє компілятору записувати повний рядок прапорців командного рядка в атрибут `DW_AT_producer` секції DWARF. Це запобігає витоку локальних шляхів, переданих через прапорці `-I` або `-L`.
- `-fno-guess-branch-probability` — відключає внутрішні евристики компілятора щодо ймовірності переходів у розгалуженнях, які можуть залежати від псевдовипадкових генераторів при оптимізації без профілю.

### Ручне перевизначення макросів часу для застарілих компіляторів

У старих версіях компіляторів (GCC < 7.0 або Clang < 4.0), які не підтримують стандарт `SOURCE_DATE_EPOCH`, спроба перевизначити макроси `__DATE__` та `__TIME__` через аргумент командного рядка `-D` викликає помилку компіляції через конфлікт із вбудованими ключовими словами. Для обходу цієї заборони використовують прапорець придушення попереджень:

```sh
gcc -Wno-builtin-macro-redefined \
    -D__DATE__="\"Jan 01 1970\"" \
    -D__TIME__="\"00:00:00\"" \
    -D__TIMESTAMP__="\"Thu Jan 01 00:00:00 1970\"" \
    -c main.c -o main.o
```

## Прапорці компілятора та лінкера MSVC (Windows)

Середовище Microsoft Visual C++ генерує виконувані файли у форматі Portable Executable (PE/COFF) та окремі файли налагоджувальних символів Program Database (PDB). Обидва формати містять кілька специфічних джерел недетермінізму.

### Опції лінкера link.exe

1. `/Brepro` — ключовий прапорець детермінізму в екосистемі Microsoft. За замовчуванням заголовок `IMAGE_FILE_HEADER` файлу PE містить 32-бітне поле `TimeDateStamp`, куди записується поточний системний час у форматі POSIX. Крім того, аналогічна часова позначка записується в заголовок таблиці налагодження `IMAGE_DEBUG_DIRECTORY`. Прапорець `/Brepro` змушує компонувальник `link.exe` записувати в ці поля детерміністичний криптографічний геш вмісту скомпільованого коду замість реального часу.
2. `/PDBALTPATH:%_PDB%` — за замовчуванням компонувальник записує в секцію `.rdata` виконуваного образу структуру типу `CodeView` (запис `RSDS`), яка містить повний абсолютний шлях до файлу символів на диску розробника (наприклад, `C:\Users\builder\source\app.pdb`). Опція `/PDBALTPATH:%_PDB%` замінює абсолютний шлях на відносне ім'я файлу `app.pdb`.
3. `/DEBUG:FULL` — створює повну детерміністичну структуру налагоджувальних даних без використання тимчасових інкрементальних таблиць компонування (Incremental Linking).

### Опції компілятора cl.exe

1. `/experimental:deterministic` — прапорець компілятора `cl.exe`, який активує внутрішній детерміністичний режим генерації коду. Він стабілізує порядок оптимізаційних проходів, порядок злиття ідентичних функцій (Identical COMDAT Folding, ICF) та усуває недетермінізм розподілу функцій між різними потоками компіляції.
2. `/pathmap:OLD=NEW` — офіційний аналог прапорця `-ffile-prefix-map` у сучасних версіях MSVC (починаючи з Visual Studio 2019 версії 16.6). Замінює абсолютні шляхи до файлів вихідного коду в налагоджувальних записах PDB та макросі `__FILE__`.

```bat
:: Компіляція одиниці трансляції
cl.exe /c /O2 /experimental:deterministic /pathmap:%CD%=. main.cpp /Fo:main.obj

:: Детерміністичне лінкування виконуваного образу
link.exe /Brepro /DEBUG:FULL /PDBALTPATH:%_PDB% main.obj /OUT:app.exe
```

## Прапорці компіляторів Rust (rustc) та Go

Сучасні системні мови програмування Rust та Go містять власні вбудовані механізми нормалізації шляхів і контролю за детермінізмом артефактів.

### Компілятор Rust (rustc / Cargo)

Компілятор Rust записує шляхи до вихідних крейтів у секції DWARF та у панічні повідомлення про помилки (макрос `panic!`). Для нормалізації шляхів використовують прапорець `--remap-path-prefix`:

```sh
# Перевизначення шляхів у Cargo через змінну RUSTFLAGS
export RUSTFLAGS="--remap-path-prefix=$PWD=."

# Додаткове налаштування детерміністичного лінкування в Linux
export RUSTFLAGS="$RUSTFLAGS -C link-arg=-Wl,--build-id=sha1"
```

У конфігураційному файлі `Cargo.toml` для релізного профілю рекомендується фіксувати глобальну оптимізацію ThinLTO або FatLTO (`lto = "fat"`), а також вимикати інкрементальну компіляцію (`incremental = false`), оскільки проміжний кеш інкрементальних модулів rustc може вносити недетермінізм у порядок злиття секцій.

### Компілятор Go (go build)

Утиліта збірки `go build` за замовчуванням записує повні шляхи файлової системи хоста у бінарний файл для коректного виведення стектрейсів під час збоїв, а також зберігає метадані контролю версій Git.

```sh
# Повна санітизація бінарника Go
go build -trimpath -buildvcs=false -ldflags="-s -w -buildid=" -o app .
```

Значення прапорців:
- `-trimpath` — видаляє всі абсолютні шляхи до файлів із бінарного файлу, замінюючи їх на назви імпортованих пакетів модулів.
- `-buildvcs=false` — забороняє компілятору зчитувати статус репозиторіїв Git (хеш коміту, статус наявності локальних правок та дату).
- `-ldflags="-buildid="` — запобігає запису псевдовипадкового внутрішнього ідентифікатора збірки Go.

## Прапорці компонувальників GNU ld, Gold, LLVM lld та mold

Під час об'єднання об'єктних файлів у фінальний виконуваний образ компонувальник створює унікальний ідентифікатор складання (Build ID) та впорядковує секції пам'яті.

### Генерація ідентифікатора Build ID

Секція `.note.gnu.build-id` містить 20-байтний числовий масив, що ідентифікує бінарний файл для систем налагодження (GDB, debuginfod). За замовчуванням деякі лінкери генерують цей ідентифікатор на основі псевдовипадкових чисел або системного часу.

```sh
# Генерація детерміністичного SHA-1 гешу від усього бінарного вмісту вихідних секцій
ld --build-id=sha1 ...

# Генерація швидкого детерміністичного деревоподібного гешу MD5
ld --build-id=tree ...

# Ручне задання фіксованого ідентифікатора у шістнадцятковому вигляді
ld --build-id=0xabcdef0123456789abcdef0123456789abcdef01 ...
```

### Впорядкування секцій та символів

Якщо об'єктні файли мають однакові назви секцій (наприклад, `.text.hot`, `.rodata.str1.1`) або глобальні неініціалізовані змінні (Common symbols), компонувальник GNU `ld` розміщує їх у порядку надходження в командному рядку.

Для забезпечення стабільного розміщення використовують прапорці:
- `--sort-common` — примусово сортує спільні символи за розміром вирівнювання, а в межах однакового розміру — за алфавітом назв символів.
- `--sort-section=name` — сортує однойменні вхідні секції за назвою перед розміщенням у вихідному сегменті ELF.

Компонувальники `lld` (проєкт LLVM) та `mold` за замовчуванням реалізують детерміністичні алгоритми: за фіксованого порядку аргументів командного рядка вони гарантують ідентичний бінарний результат незалежно від кількості виділених ядер процесора.

## Архіватори: GNU ar, tar, zip, gzip

Утиліти створення архівів відповідають за пакування проміжних об'єктних файлів у статичні бібліотеки `.a` та формування кінцевих файлів дистрибутивів (`.tar.gz`, `.zip`).

### Створення детерміністичних бібліотек .a (GNU ar / llvm-ar)

Стандартний заголовок `ar_hdr` формату архіву Unix містить 60 байтів ASCII-тексту, з яких 16 байтів відведено під поле `ar_date` (час модифікації файлу), по 6 байтів — під `ar_uid` та `ar_gid`, а 8 байтів — під права доступу `ar_mode`.

```sh
# Створення архіву в детерміністичному режимі (прапорець 'D')
ar Drcs libcore.a alpha.o beta.o gamma.o

# Оновлення таблиці символів архіву ranlib у детерміністичному режимі
ranlib -D libcore.a

# Примусове занулення дат для всього інструментарію binutils
export ZERO_AR_DATE=1
```

У детерміністичному режимі (`D`) архіватор записує константні значення:
- `ar_date = "0               "` (відповідає епосі Unix);
- `ar_uid  = "0     "`;
- `ar_gid  = "0     "`;
- `ar_mode = "100644  "`.

### Створення детерміністичних тарболів (GNU tar)

Утиліта `tar` записує метадані файлів безпосередньо з хостової файлової системи. Для отримання відтворюваного архіву необхідно явно перевизначити всі метадані:

```sh
tar --sort=name \
    --mtime="@$SOURCE_DATE_EPOCH" \
    --owner=0 \
    --group=0 \
    --numeric-owner \
    --pax-option=exthdr.name=%d/PaxHeaders/%f,delete=atime,delete=ctime \
    --mode='u=rwX,go=rX' \
    -cf release.tar ./bin ./include
```

Параметри команди:
- `--sort=name` — сортує файли за алфавітом, запобігаючи впливу порядку читання каталогу `readdir()`.
- `--mtime="@$SOURCE_DATE_EPOCH"` — замінює реальний час зміни всіх файлів на фіксовану дату коміту.
- `--owner=0 --group=0 --numeric-owner` — встановлює власника `root:root` (UID 0, GID 0) замість локального користувача.
- `--pax-option=delete=atime,delete=ctime` — видаляє розширені заголовки POSIX PAX, що містять час останнього доступу та зміни інода.
- `--mode='u=rwX,go=rX'` — нормалізує маску прав доступу, усуваючи вплив системної `umask`.

### Стиснення без збереження метаданих: gzip та zip

Утиліта `gzip` записує в байти 4–7 заголовка вихідного файлу `.gz` поточний 32-бітний час стиснення та прапорець операційної системи. Прапорець `-n` (`--no-name`) повністю вимикає запис часу та оригінального імені файлу:

```sh
# Детерміністичне стиснення потоку даних
gzip -n -9 < release.tar > release.tar.gz

# Створення відтворюваного ZIP-архіву
find . -type f | LC_ALL=C sort | zip -X -q -@ release.zip
```

Прапорець `-X` (`--no-extra`) в утиліті `zip` вимикає збереження додаткових атрибутів хостової файлової системи (розширених часових позначок NTFS/Unix та числових UID/GID).

## Детерміністичні контейнери OCI та Docker BuildKit

Під час збирання образів контейнерів через `docker build` кожен шар образу являє собою стиснений тарбол. За замовчуванням `docker build` записує в шари поточний системний час виконання кожної інструкції `RUN` або `COPY`.

Для досягнення бінарної відтворюваності образів Docker використовують рушій BuildKit із передачею `SOURCE_DATE_EPOCH`:

```sh
# Увімкнення BuildKit і передача фіксованої часової позначки шарів
export DOCKER_BUILDKIT=1
export SOURCE_DATE_EPOCH=$(git log -1 --format=%ct)

docker build \
    --build-arg SOURCE_DATE_EPOCH="$SOURCE_DATE_EPOCH" \
    --output type=oci,dest=image.tar \
    -t myapp:release .
```

Рушій BuildKit автоматично замінює часові позначки модифікації файлів у всіх шарах на значення `SOURCE_DATE_EPOCH` і формує ідентичний криптографічний маніфест образу OCI.

## Автоматизоване тестування через утиліту reprotest

Для верифікації правильності налаштування прапорців розробники використовують утиліту `reprotest`, яка автоматизує запуск подвійної збірки з навмисним внесенням варіацій середовища:

```sh
# Запуск автоматизованого тестування відтворюваності проєкту
reprotest --variations=all 'cmake --build build' build/app
```

Утиліта `reprotest` автоматично змінює:
- системний час (зсув на 398 днів вперед);
- часовий пояс (UTC проти GMT-14);
- системну локаль (`C` проти `fr_CH.UTF-8`);
- маску прав створення файлів `umask` (`0022` проти `0002`);
- імена хостів і доменів (через системні виклики `sethostname`);
- порядок файлів у каталозі (через підміну бібліотеки `disorderfs` FUSE);
- кількість доступних процесорних ядер (через `taskset`).

Якщо після всіх цих мутацій геші вихідних бінарних файлів збігаються, конфігурацію прапорців детермінізму вважають повною та надійною.

## Повний скрипт санітизації оточення

Перед запуском будь-якої детерміністичної збірки середовище виконання процесу повинно бути очищене за допомогою такого базового скрипта:

```sh
#!/usr/bin/env bash
set -euo pipefail

# 1. Примусове встановлення канонічної локалі для передбачуваного сортування рядків
export LC_ALL=C.UTF-8
export LANG=C.UTF-8
export LC_COLLATE=C

# 2. Фіксація часового поясу в нульовий меридіан
export TZ=UTC

# 3. Нормалізація маски створення файлів
umask 0022

# 4. Встановлення фіксованого часу коміту для компіляторів та архіваторів
export SOURCE_DATE_EPOCH=$(git log -1 --format=%ct 2>/dev/null || echo 1700000000)

# 5. Примусовий детермінізм для GNU binutils
export ZERO_AR_DATE=1

# 6. Очищення шляхів пошуку бінарних файлів від локальних каталогів користувача
export PATH="/usr/bin:/bin:/usr/local/bin"

# 7. Видалення небезпечних змінних середовища
unset LD_PRELOAD
unset LD_LIBRARY_PATH
unset C_INCLUDE_PATH
unset CPLUS_INCLUDE_PATH
unset TMPDIR

# 8. Запуск збірки
cmake --preset release
cmake --build --preset release
```

## Інтеграція в CMakeLists.txt та Meson

Для того щоб проєкт автоматично застосовував прапорці детермінізму під час генерації та компіляції, у файли конфігурації систем збірки вбудовують спеціальні правила.

### Приклад для CMakeLists.txt

```cmake
# Перевірка та конфігурація компіляторів GCC і Clang
if(CMAKE_C_COMPILER_ID MATCHES "GNU|Clang")
    # Перетворення абсолютних шляхів на відносні
    add_compile_options(
        -ffile-prefix-map=${CMAKE_SOURCE_DIR}=.
        -ffile-prefix-map=${CMAKE_BINARY_DIR}=.
        -fno-ident
        -gno-record-gcc-switches
    )
    # Детерміністичний Build ID для компонувальника
    add_link_options("-Wl,--build-id=sha1")
endif()

# Налаштування для середовища MSVC на Windows
if(MSVC)
    add_compile_options(/experimental:deterministic "/pathmap:${CMAKE_SOURCE_DIR}=.")
    add_link_options(/Brepro "/PDBALTPATH:%_PDB%")
endif()

# Детерміністичний виклик архіватора статичних бібліотек
set(CMAKE_C_ARCHIVE_CREATE "<CMAKE_AR> Dqc <TARGET> <LINK_FLAGS> <OBJECTS>")
set(CMAKE_C_ARCHIVE_APPEND "<CMAKE_AR> Dq  <TARGET> <LINK_FLAGS> <OBJECTS>")
set(CMAKE_C_ARCHIVE_FINISH "<CMAKE_RANLIB> -D <TARGET>")

set(CMAKE_CXX_ARCHIVE_CREATE "<CMAKE_AR> Dqc <TARGET> <LINK_FLAGS> <OBJECTS>")
set(CMAKE_CXX_ARCHIVE_APPEND "<CMAKE_AR> Dq  <TARGET> <LINK_FLAGS> <OBJECTS>")
set(CMAKE_CXX_ARCHIVE_FINISH "<CMAKE_RANLIB> -D <TARGET>")
```

### Приклад для Meson (meson.build)

У системі збірки Meson прапорці детермінізму можна задати безпосередньо у виклику проєкту або через файл cross/native файлу профілю:

```meson
project('myproject', 'c', 'cpp',
  version : '1.0.0',
  default_options : [
    'c_std=c11',
    'cpp_std=c++20',
    'b_ndebug=if-release'
  ]
)

# Автоматичне додавання прапорців для компіляторів GCC та Clang
cc = meson.get_compiler('c')
if cc.get_id() in ['gcc', 'clang']
  add_project_arguments(
    cc.get_supported_arguments([
      '-ffile-prefix-map=' + meson.current_source_dir() + '=. ',
      '-fno-ident'
    ]),
    language : ['c', 'cpp']
  )
  add_project_link_arguments(
    cc.get_supported_link_arguments(['-Wl,--build-id=sha1']),
    language : ['c', 'cpp']
  )
endif()
```
