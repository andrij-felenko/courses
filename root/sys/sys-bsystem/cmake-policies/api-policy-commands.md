# 📋 Довідник команд і змінних керування політиками

Інтерфейс керування політиками CMake надає набір вбудованих директив для встановлення глобальних версійних меж, точкового перемикання окремих правил, інспекції їхнього стану та безпечного ізолювання областей видимості.

## 1. cmake_minimum_required

Оголошує мінімально необхідну версію CMake для збірки проєкту та встановлює базовий рівень політик для поточного каталогу та його піддерев.

```cmake
cmake_minimum_required(VERSION <min>[...<max>] [FATAL_ERROR])
```

### Параметри та семантика

| Параметр | Тип | Опис та правила поведінки |
| :--- | :--- | :--- |
| `VERSION <min>` | Рядок версії (`X.Y.Z`) | Обов'язкова нижня версійна межа. Якщо запущений бінарник CMake має версію, нижчу за `<min>`, процес конфігурації негайно припиняється з фатальною помилкою. Одночасно всі політики, запроваджені до версії `<min>` включно, автоматично встановлюються у стан `NEW`. |
| `...<max>` | Рядок версії (`X.Y.Z`) | *(Опційно, з'явився у CMake 3.12)* Верхня версійна межа діапазону. Якщо версія запущеного CMake перевищує `<min>`, інструмент активує стан `NEW` для всіх політик аж до версії `<max>` (або до поточної версії бінарника, якщо вона менша за `<max>`). Усі політики, введені після `<max>`, залишаються у стані за замовчуванням (`UNSET` / `OLD`). |
| `FATAL_ERROR` | Ключове слово | Застарілий прапорець часів CMake 2.4. У версіях CMake 2.6+ повністю ігнорується, оскільки будь-яка невідповідність мінімальної версії завжди завершується фатальною помилкою. Зберігається виключно заради сумісності зі стародавніми скриптами. |

### Правила розміщення та область дії

- **Позиція в проєкті:** Виклик `cmake_minimum_required` повинен стояти найпершим виконуваним рядком у кореневому файлі `CMakeLists.txt`, обов'язково перед викликом директиви `project()`. Це критично, оскільки сама команда `project()` залежить від багатьох політик (наприклад, `CMP0048` для розбору версії та `CMP0025` для ідентифікації компілятора AppleClang).
- **Поведінка у підкаталогах:** Якщо `cmake_minimum_required` викликається всередині підкаталогу, підключеного через `add_subdirectory()`, команда оновлює набір політик **виключно для цього підкаталогу** та його дочірніх областей. Після завершення обробки підкаталогу батьківський стек політик залишається незмінним.
- **Встановлення системної змінної:** Успішний виклик директиви записує значення версії у глобальну внутрішню змінну `CMAKE_MINIMUM_REQUIRED_VERSION`.

## 2. cmake_policy

Універсальна команда для точкового перемикання окремих політик, масового оновлення версійного зрізу та маніпуляцій зі стеком областей видимості.

### Режим cmake_policy(VERSION ...)

Оновлює набір активних політик до вказаної версії без примусової перевірки версії самого бінарника CMake.

```cmake
cmake_policy(VERSION <min>[...<max>])
```

На відміну від `cmake_minimum_required`, ця команда не перериває конфігурацію помилкою, якщо поточний інтерпретатор CMake старіший за вказану версію (якщо сам синтаксис підтримується). Вона використовується всередині користувацьких макросів, системних модулів або допоміжних скриптів, коли необхідно тимчасово підняти версійний зріз політик для певної ділянки коду без зміни загальних вимог проєкту.

### Режим cmake_policy(SET ...)

Явно призначає стан `OLD` або `NEW` для конкретної політики за її числовим ідентифікатором.

```cmake
cmake_policy(SET CMPxxxx OLD|NEW)
```

| Значення стану | Вплив на виконання та діагностику |
| :--- | :--- |
| `OLD` | Вмикає застарілу поведінку CMake для політики `CMPxxxx`. Використовується виключно як тимчасовий засіб збереження працездатності легасі-коду. Якщо політику визнано застарілою, виклик генерує `CMake Deprecation Warning`. Якщо підтримку політики видалено з ядра (наприклад, у CMake 4.0+), виклик призводить до фатальної помилки. |
| `NEW` | Активує сучасну виправлену поведінку для політики `CMPxxxx`. Повністю вимикає авторські попередження (dev warnings), пов'язані з цим правилом. |

**Крайові випадки та захист:** Якщо команда викликається з ідентифікатором політики, який невідомий поточному бінарнику CMake (наприклад, спроба встановити політику майбутньої версії на старій системі), CMake зупиняє виконання з помилкою `cmake_policy given unknown policy`. Щоб уникнути збоїв, виклик завжди захищають умовою:

```cmake
if(POLICY CMP0144)
  cmake_policy(SET CMP0144 NEW)
endif()
```

### Режим cmake_policy(GET ...)

Зчитує поточний встановлений стан конкретної політики у вказану змінну.

```cmake
cmake_policy(GET CMPxxxx <variable>)
```

Команда записує у змінну `<variable>` одне з трьох стандартних рядкових значень:
- `OLD` — для політики явно активовано застарілий режим;
- `NEW` — для політики явно активовано сучасний режим;
- `UNSET` — політику не було явно налаштовано (у цьому стані CMake застосовує стару поведінку та виводить авторське попередження під час першого зіткнення).

Якщо передано неіснуючий ідентифікатор політики, змінній призначається порожній рядок `""`.

### Режими cmake_policy(PUSH) та cmake_policy(POP)

Керують стеком станів політик для забезпечення ізоляції модулів і запобігання витоку локальних змін у глобальний контекст.

```cmake
cmake_policy(PUSH)
# ... локальні модифікації станів політик ...
cmake_policy(POP)
```

- `cmake_policy(PUSH)`: створює новий шар на вершині внутрішнього стека політик і виконує повне копіювання поточного стану всіх правил.
- `cmake_policy(POP)`: знімає верхній шар зі стека, повертаючи стан усіх політик до моменту відповідного виклику `PUSH`.

**Вимоги до балансування:** Виклики `PUSH` та `POP` повинні бути строго парними в межах одного файлу або функції. Спроба виконати `POP` на порожньому стеку призводить до фатальної помилки інтерпретатора `cmake_policy POP without matching PUSH`. Якщо файл завершується із незакритим `PUSH`, CMake видає попередження про розбалансування стека.

## 3. Команда block(SCOPE_FOR POLICIES)

Починаючи з версії CMake 3.25, у мові з'явилася директива `block()`, яка забезпечує структуроване автоматичне керування стеком політик без необхідності вручну стежити за парністю `PUSH` та `POP`.

```cmake
block(SCOPE_FOR POLICIES [PROPAGATE <var1> ...])
  cmake_policy(SET CMP0077 NEW)
  cmake_policy(SET CMP0144 NEW)
  # ... ізольовані дії ...
endblock()
```

| Опція блоку | Опис поведінки |
| :--- | :--- |
| `SCOPE_FOR POLICIES` | Створює ізольовану область видимості виключно для політик CMake. Звичайні змінні продовжують модифікуватися у поточному контексті. Після завершення `endblock()` усі зміни політик автоматично скасовуються. |
| `SCOPE_FOR VARIABLES POLICIES` | Створює повну комбіновану ізоляцію: як для змінних, так і для політик. Будь-які змінні та налаштування політик, створені всередині блоку, не виходять за його межі, якщо вони явно не перераховані в списку `PROPAGATE`. |
| `PROPAGATE <var...>` | Дозволяє безпечно прокинути перелічені змінні зсередини ізольованого блоку в зовнішню область видимості викликача. |

Команда `block()` гарантує коректне відновлення стека політик навіть тоді, коли всередині блоку спрацьовує достроковий вихід через команду `return()`.

## 4. Взаємодія з командою include() та прапорець NO_POLICY_SCOPE

За замовчуванням команда `include(file.cmake)` створює неявний рівень стека політик (еквівалентний автоматичному виклику `cmake_policy(PUSH)` перед включенням та `cmake_policy(POP)` після завершення файлу). Це захищає викликача від випадкової зміни його налаштувань увімкненим файлом.

Якщо модуль спеціально призначений для глобального налаштування середовища і повинен змінювати політики викликача, команда `include` викликається з модифікатором `NO_POLICY_SCOPE`:

```cmake
include(ConfigureProjectPolicies.cmake NO_POLICY_SCOPE)
```

У цьому режимі всі виклики `cmake_policy(SET ...)` або `cmake_minimum_required`, виконані всередині включеного файлу, безпосередньо впливають на поточну область видимості викликача.

## 5. Системні змінні керування політиками

CMake надає спеціальні службові змінні для зовнішнього конфігурування політик через командний рядок або файли ініціалізації тулчейнів без прямого редагування вихідних текстів `CMakeLists.txt`.

### CMAKE_POLICY_DEFAULT_CMPxxxx

Перевизначає поведінку за замовчуванням для політики `CMPxxxx` у всіх областях і підпроєктах, де вона перебуває у стані `UNSET`.

```bash
# Примусове застосування нової логіки опцій у сторонніх залежностях:
cmake -B build -DCMAKE_POLICY_DEFAULT_CMP0077=NEW
```

Ця змінна застосовується лише тоді, коли сам підпроєкт не виконав явного виклику `cmake_policy(SET CMPxxxx ...)`. Вона є головним інструментом системних інтеграторів і пакетних менеджерів для виправлення поведінки застарілих бібліотек без внесення патчів у їхні вихідні тексти.

### CMAKE_POLICY_WARNING_CMPxxxx

Керує виведенням діагностичних повідомлень інтерпретатора для окремої політики `CMPxxxx`.

| Значення змінної | Результат |
| :--- | :--- |
| `OLD` або `OFF` | Пригнічує виведення попереджень про використання поведінки за замовчуванням (`UNSET`) або застарілість режиму `OLD`. |
| `FATAL` або `ERROR` | Підвищує діагностичні попередження за цією політикою до рівня фатальної помилки збірки, негайно зупиняючи процес конфігурації. |

Використовується в скриптах неперервної інтеграції (CI) для суворої перевірки кодової бази на відсутність застарілих або неоднозначних викликів.

## 6. Логічні оператори та перевірка наявності політик

Для безпечної підтримки різних версій CMake у єдиній кодовій базі мова підтримує спеціальний предикат `POLICY` всередині умовних виразів `if()`:

```cmake
# Перевірка реєстрації політики в поточному бінарнику:
if(POLICY CMP0144)
  cmake_policy(SET CMP0144 NEW)
else()
  # Альтернативна обробка для старих версій CMake:
  if(DEFINED OPENSSL_ROOT AND NOT DEFINED OpenSSL_ROOT)
    set(OpenSSL_ROOT "${OPENSSL_ROOT}")
  endif()
endif()
```

Предикат `if(POLICY CMPxxxx)` оцінюється як істинний виключно тоді, коли інструмент CMake, що виконує конфігурацію, містить внутрішній опис правила `CMPxxxx`. Якщо CMake старіший за версію, де з'явилася ця політика, блок `else` дозволяє емулювати потрібну логіку вручну без виникнення синтаксичних помилок.
