# 📋 Змінні CMake тулчейну Android NDK

Ця довідкова специфікація містить повний перелік, механізми обробки, внутрішні прапорці трансляції та крайові випадки конфігураційних змінних, які інтерпретує файл тулчейна `$NDK/build/cmake/android.toolchain.cmake` під час налаштування крос-компіляції проєктів C та C++ у середовищі Android Gradle Plugin (AGP) або автономного виклику CMake.

## Таблиця головних змінних платформи та архітектури

| Змінна CMake | Тип даних | Значення за замовчуванням | Допустимі значення |
|---|---|---|---|
| `ANDROID_ABI` | Рядок | `arm64-v8a` (або значення з AGP `ndk.abiFilters`) | `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64` |
| `ANDROID_PLATFORM` | Рядок / Число | `android-21` (або `minSdkVersion` з AGP) | `android-<N>`, `android-latest`, або число `<N>` |
| `ANDROID_STL` | Рядок | `c++_static` | `c++_static`, `c++_shared`, `none`, `system` |
| `ANDROID_PIE` | Булеве | `ON` (завжди увімкнено для API ≥ 16) | `ON`, `OFF` |
| `ANDROID_ARM_MODE` | Рядок | `thumb` (для `armeabi-v7a`) | `thumb`, `arm` |
| `ANDROID_ARM_NEON` | Булеве | `ON` (з NDK r21 для `armeabi-v7a`) | `ON`, `OFF` |
| `ANDROID_ALLOW_UNDEFINED_SYMBOLS` | Булеве | `OFF` | `ON`, `OFF` |
| `ANDROID_CPP_FEATURES` | Список | Порожньо | `rtti`, `exceptions`, `no-rtti`, `no-exceptions` |
| `ANDROID_CCACHE` | Шлях | Порожньо | Абсолютний шлях до бінарника `ccache` |

---

## 1. `ANDROID_ABI`

Задає цільову двійкову архітектуру набору інструкцій процесора (Application Binary Interface).

### Семантика та прапорці компілятора
Змінна безпосередньо транслюється тулчейном у цільовий тріплет LLVM Clang (`--target=<arch>-linux-android<API>`):
* `arm64-v8a`: генерує 64-бітний машинний код AArch64 (ARMv8-A). Тріплет `aarch64-linux-android<API>`. Регістровий виклик AAPCS64, обов'язкова апаратна підтримка векторних інструкцій NEON і 64-бітних покажчиків. Розмір сторінки віртуальної пам'яті за замовчуванням становить 4 КБ, проте починаючи з NDK r27 підтримується вирівнювання на 16 КБ.
* `armeabi-v7a`: генерує 32-бітний машинний код ARMv7-A з набором інструкцій Thumb-2 (`-march=armv7-a -mthumb`). Тріплет `armv7a-linux-androideabi<API>`.
* `x86`: генерує 32-бітний машинний код IA-32 з підтримкою MMX, SSE, SSE2, SSE3 та SSSE3. Тріплет `i686-linux-android<API>`.
* `x86_64`: генерує 64-бітний машинний код x86-64 з підтримкою SSE4.2 та інструкцій POPCNT. Тріплет `x86_64-linux-android<API>`.

### Практичні обмеження та пастки
* Застарілі архітектури `armeabi` (ARMv5), `mips` та `mips64` було повністю видалено в NDK r17. Якщо передати `ANDROID_ABI=armeabi`, тулчейн перериває генерацію файлів збірки аварійною помилкою.
* Якщо у виклику CMake прапорець `ANDROID_ABI` не задано явно і конфігурація виконується поза Gradle, тулчейн обирає перше значення з внутрішнього пріоритетного списку (зазвичай `arm64-v8a`).

## 2. `ANDROID_PLATFORM` (також відома як `ANDROID_NATIVE_API_LEVEL`)

Вказує мінімальний рівень API платформи Android (`minSdkVersion`), з яким компонується бінарний модуль.

### Формат запису
Підтримуються як повні назви `android-21`, `android-34`, так і чисті цілочисельні номери `21`, `34`. Крім того, значення `android-latest` автоматично обирає найвищий рівень API, доступний у каталозі `platforms/` поточного NDK. Якщо передано значення, нижче за мінімально підтримуване цим випуском NDK (наприклад, `android-16` у сучасному NDK), тулчейн автоматично підвищує його до найменшого чинного рівня (наприклад, `android-21`).

### Вплив на компілятор і лінкер
1. **Макрос препроцесора:** встановлює `-D__ANDROID_API__=<N>`. Заголовки Bionic libc використовують цей макрос для умовного приховування або відкриття функцій через атрибути виду `__INTRODUCED_IN(21)`.
2. **Тріплет виклику Clang:** суфікс версії додається до назви компілятора чи параметра `--target`, змушуючи Clang виставляти відповідний рівень ABI.
3. **Пошук заглушок компонування:** додає до шляхів пошуку лінкера каталог системних заглушок `sysroot/usr/lib/<triple>/<N>/libc.so`. Спроба використати символ, доданий у пізнішому API (наприклад, `getrandom()` з API 28 при виборі `ANDROID_PLATFORM=21`), спричиняє помилку компонування `undefined reference to 'getrandom'`.

## 3. `ANDROID_STL`

Визначає реалізацію стандартної бібліотеки C++ та спосіб її зв'язування з виконуваними модулями чи спільними бібліотеками `.so`.

### Варіанти та прапорці лінкера
* `c++_static`: статична бібліотека `libc++_static.a` та `libc++abi.a` вшиваються безпосередньо в результуючий бінарник `.so`. Не вимагає додаткових залежностей під час завантаження в пам'ять. Безпечно виключно за умови наявності рівно однієї бібліотеки C++ у всьому процесі застосунку.
* `c++_shared`: динамічна бібліотека `libc++_shared.so` зв'язується через запис `DT_NEEDED`. Дозволяє кільком спільним модулям проєкту спільно використовувати єдиний екземпляр рантайму C++, стан RTTI, перехоплювачі винятків та системні алокатори пам'яті.
* `none`: стандартна бібліотека C++ не підключається. Дозволено компілювати файли `.cpp`, але будь-яке звернення до символів простору назв `std::` призведе до помилки нерозв'язаних символів. Корисно для мінімалістичних модулів мовою C або спеціалізованих ядерних драйверів.
* `system`: застарілий мінімальний C++ рантайм Bionic (`libstdc++.so`), який містить лише базові оператори `new` та `delete` без підтримки STL, винятків чи RTTI. Застосовується виключно в застарілому системному коді AOSP.

## 4. `ANDROID_ARM_MODE` та `ANDROID_ARM_NEON`

Керують специфічними режимами генерації коду мікропроцесорної архітектури ARM для 32-бітного ABI `armeabi-v7a`.

### `ANDROID_ARM_MODE`
* `thumb` (за замовчуванням): компілює код у 16/32-бітний змішаний режим інструкцій Thumb-2 (`-mthumb`). Забезпечує на 25–35% менший розмір машинного коду порівняно з чистим 32-бітним режимом ARM при незначній втраті пікової швидкодії у щільних циклах.
* `arm`: вмикає класичний 32-бітний набір інструкцій ARM (`-marm`). Використовується, коли критичний низькорівневий ассемблерний код або обчислювальні блоки вимагають прямого доступу до умовного виконання всіх інструкцій.

### `ANDROID_ARM_NEON`
* `ON` (за замовчуванням з NDK r21): активує розширення SIMD векторних операцій ARM Advanced SIMD (NEON) шляхом додавання прапорця `-mfpu=neon`. Компілятор автоматично векторизує цикли з плаваючою комою одинарної точності та цілочисельними векторами.
* `OFF`: обмежує модуль інструкціями плаваючої коми VFPv3-D16 (лише 16 регістрів FPU, векторний рушій NEON вимкнено).

## 5. `ANDROID_ALLOW_UNDEFINED_SYMBOLS`

Керує поведінкою компонувальника `lld` щодо символів, які не вдалося розв'язати на етапі збірки спільної бібліотеки `.so`.

### Семантика
* `OFF` (за замовчуванням): тулчейн додає до командного рядка компонувальника прапорець `-Wl,-z,defs` (або `--no-undefined`). Будь-який нерозв'язаний виклик функції чи доступ до зовнішньої змінної вважається критичною помилкою збірки. Це захищає розробника від створення пошкоджених `.so` файлів, які неминуче впадуть у рантаймі при виклику `dlopen()`.
* `ON`: прапорець `-Wl,-z,defs` вимикається. Дозволяє створювати спільні бібліотеки, чиї символи будуть знайдені лише в момент завантаження в адресний простір головного процесу іншою вже завантаженою бібліотекою (наприклад, у плагінних архітектурах).

## 6. `ANDROID_CPP_FEATURES` та `ANDROID_PIE`

### `ANDROID_CPP_FEATURES`
Дозволяє глобально активувати або вимикати ключові можливості мови C++:
* `rtti` / `no-rtti`: додає прапорці `-frtti` або `-fno-rtti`. Вимкнення RTTI зменшує розмір таблиць віртуальних методів (`vtable`), але забороняє використання `dynamic_cast` та `typeid`.
* `exceptions` / `no-exceptions`: додає прапорці `-fexceptions` або `-fno-exceptions`. За замовчуванням у NDK обробку винятків увімкнено; вимкнення прибирає таблиці розгортання стека (`.eh_frame`), що скорочує розмір двійкового коду на 10–15%.

### `ANDROID_PIE` (Position Independent Executables)
* `ON` (за замовчуванням для всіх підтримуваних версій Android): додає прапорець `-fPIE -pie` під час збірки виконуваних файлів. Починаючи з Android 5.0 (API 21), системний динамічний лінкер відмовляється запускати двійкові файли без прапорця PIE заради забезпечення рандомізації адресного простору (ASLR).

## 7. `ANDROID_CCACHE`

Вказує абсолютний шлях до утиліти кешування компіляції `ccache`.

### Механізм інтеграції
Якщо змінну задано, тулчейн автоматично встановлює властивості CMake `CMAKE_C_COMPILER_LAUNCHER` та `CMAKE_CXX_COMPILER_LAUNCHER`. Це дозволяє суттєво прискорити повторні інкрементальні збірки за рахунок повторного використання об'єктних файлів без необхідності ручного редагування викликів компілятора в кожному тарґеті.

## 8. Приклади конфігурації через Gradle та CLI

### Конфігурація через `build.gradle.kts`
```kotlin
android {
    defaultConfig {
        ndk {
            abiFilters.addAll(listOf("arm64-v8a", "armeabi-v7a", "x86_64"))
        }
        externalNativeBuild {
            cmake {
                arguments(
                    "-DANDROID_STL=c++_shared",
                    "-DANDROID_ARM_NEON=ON",
                    "-DANDROID_ARM_MODE=thumb",
                    "-DANDROID_ALLOW_UNDEFINED_SYMBOLS=OFF"
                )
                cFlags("-O3", "-fvisibility=hidden")
                cppFlags("-std=c++20", "-fexceptions", "-frtti")
            }
        }
    }
    externalNativeBuild {
        cmake {
            path = file("src/main/cpp/CMakeLists.txt")
            version = "3.22.1"
        }
    }
}
```

### Автономний виклик CMake з командного рядка
```bash
cmake -B build-android-arm64 -S . \
  -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK_HOME/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-29 \
  -DANDROID_STL=c++_shared \
  -DCMAKE_BUILD_TYPE=Release
```
