# 📋 Довідник інтерфейсу portfile: функції та структура маніфестів vcpkg

Цей довідник містить повну технічну специфікацію функцій-хелперів `portfile.cmake`, опис поведінки системних змінних тріплетів та структурні вимоги до файлів маніфестів `vcpkg.json` і конфігурації `vcpkg-configuration.json`.

---

## 1. Специфікація маніфесту vcpkg.json

Файл `vcpkg.json` є основним декларативним описом порту в репозиторії або залежностей у споживчому проєкті. Формат файлу є суворо типізованим JSON-документом.

| Поле | Тип | Обов'язкове | Опис |
| :--- | :--- | :---: | :--- |
| `name` | String | Так | Унікальний ідентифікатор пакета у форматі lowercase kebab-case (наприклад, `fast-telemetry`). Заборонено використовувати великі літери, підкреслення або спеціальні символи. |
| `version` | String | Ні* | Семантична версія у вільному форматі. Використовується для проєктів із нестандартною нумерацією випусків. |
| `version-semver` | String | Ні* | Строга версія за специфікацією SemVer 2.0.0 (`MAJOR.MINOR.PATCH`). Дозволяє коректне автоматичне порівняння версій. |
| `version-date` | String | Ні* | Календарна версія у форматі `YYYY-MM-DD` (з опціональним суфіксом ревізії `.PATCH`). Типова для бібліотек без номерних релізів. |
| `version-string` | String | Ні* | Неструктурований текстовий рядок для застарілих портів або специфічних зрізів коду. |
| `port-version` | Integer | Ні | Номер ревізії порту vcpkg (за замовчуванням `0`). Інкрементується при зміні рецепта або латок без зміни версії сирців. |
| `description` | String / Array | Ні | Стислий опис функціонального призначення бібліотеки. Може бути масивом рядків для багаторядкового виводу. |
| `homepage` | String | Ні | URL офіційної вебсторінки або репозиторію проєкту. |
| `license` | String | Ні | SPDX-ідентифікатор ліцензії (наприклад, `MIT`, `Apache-2.0`, `BSD-3-Clause`, `LGPL-3.0-or-later`). |
| `dependencies` | Array | Ні | Список прямих залежностей (рядки або об'єкти з детальними обмеженнями та компонентами). |
| `features` | Object | Ні | Опис додаткових компонентів (можливостей) порту, які можуть бути увімкнені споживачем. |
| `default-features` | Array | Ні | Список можливостей, які активуються автоматично, якщо споживач явно не вимкнув їх. |
| `builtin-baseline` | String | Ні | 40-символьний Git-хеш комміту vcpkg для фіксації базового зрізу версій у споживчому маніфесті. |
| `overrides` | Array | Ні | Масив жорстких перевизначень версій для розв'язання конфліктів у кореневому проєкті. |

*\* Примітка: Пакет мусить містити рівно одне з полів версії (`version`, `version-semver`, `version-date` або `version-string`).*

### Структура об'єкта залежності у списку dependencies

Кожен елемент масиву `dependencies` може бути простим рядком з іменем порту або розширеним JSON-об'єктом, що задає умови та обмеження:

```json
{
  "name": "boost-asio",
  "version>=": "1.82.0",
  "default-features": false,
  "features": [ "ssl" ],
  "platform": "windows & !arm",
  "host": false
}
```

- `version>=` — мінімально прийнятна версія для алгоритму Minimal Version Selection (MVS). Рушій гарантує, що обрана версія буде не нижчою за вказану.
- `default-features: false` — вимикає базовий набір компонентів залежності, залишаючи лише мінімальне ядро або явно вказані фічі.
- `features` — масив додаткових компонентів порту, які мають бути скомпільовані разом із цією залежністю.
- `platform` — вираз на базі логічних операторів (`!`, `&`, `|`) та ідентифікаторів платформи (`windows`, `linux`, `osx`, `android`, `x86`, `x64`, `arm64`, `static`, `wasm32`), який визначає, чи активна ця залежність у поточному тріплеті.
- `host: true` — вказує рушію збірки скомпілювати цей пакет для середовища компілятора (Host Triplet), а не для цільової системи (Target Triplet). Це є обов'язковим для генераторів коду (наприклад, `protobuf` для отримання утиліти `protoc`).

## 2. Специфікація конфігурації vcpkg-configuration.json

Файл `vcpkg-configuration.json` використовується для реєстрації зовнішніх або приватних реєстрів портів, налаштування базових ревізій та вказівки шляхів до локальних оверлеїв.

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `default-registry` | Object | Визначає головний реєстр портів. За замовчуванням це вбудований репозиторій `microsoft/vcpkg`. |
| `registries` | Array | Список додаткових Git або файлових реєстрів, які обслуговують власні набори портів для корпоративних пакетів. |
| `overlay-ports` | Array | Масив відносних або абсолютних шляхів до каталогів користувацьких оверлей-портів. |
| `overlay-triplets` | Array | Масив відносних або абсолютних шляхів до каталогів користувацьких оверлей-тріплетів. |

### Приклад конфігурації з приватним корпоративним Git-реєстром

```json
{
  "$schema": "https://raw.githubusercontent.com/microsoft/vcpkg-tool/main/docs/vcpkg-configuration.schema.json",
  "default-registry": {
    "kind": "builtin",
    "baseline": "d3509a2d326f59fa05f4e1f7a1f59265f24ec4d9"
  },
  "registries": [
    {
      "kind": "git",
      "repository": "https://gitlab.company.internal/cpp/vcpkg-registry.git",
      "baseline": "a1b2c3d4e5f60718293a4b5c6d7e8f9012345678",
      "packages": [ "corp-crypto", "corp-telemetry", "fast-telemetry" ]
    }
  ],
  "overlay-ports": [ "./custom-ports" ],
  "overlay-triplets": [ "./custom-triplets" ]
}
```

## 3. Допоміжні функції отримання вихідного коду

### vcpkg_from_github()
Завантажує архів вихідного коду із зазначеного репозиторію GitHub, перевіряє криптографічну цілісність за хешем SHA-512, розпаковує архів в ізольований каталог `buildtrees/<port>/src/` та застосовує латки.

```cmake
vcpkg_from_github(
    OUT_SOURCE_PATH <variable>
    REPO <owner/repository>
    REF <git-tag-or-commit>
    SHA512 <checksum>
    [HEAD_REF <branch>]
    [PATCHES <patch1.patch> <patch2.patch>...]
)
```

- `OUT_SOURCE_PATH` — ім'я вихідної змінної CMake, куди записується абсолютний шлях до каталогу з розпакованим кодом.
- `REPO` — шлях до репозиторію на GitHub у форматі `організація/назва_репозиторію`.
- `REF` — тег версії або конкретний 40-символьний хеш комміту.
- `SHA512` — 128-символьний шістнадцятковий хеш SHA-512 архіву. При невідповідності хешу виконання переривається з повідомленням про помилку.
- `HEAD_REF` — ім'я гілки за замовчуванням (наприклад, `main` або `master`), яка використовується при складанні з прапорцем `--head`.
- `PATCHES` — список відносних шляхів до `.patch` файлів, які vcpkg накладає на вихідний код у порядку їх переліку перед початком етапу конфігурації.

### vcpkg_from_git()
Клонує вихідний код із довільного Git-репозиторію (зокрема закритих корпоративних серверів через протоколи HTTPS або SSH).

```cmake
vcpkg_from_git(
    OUT_SOURCE_PATH <variable>
    URL <git-url>
    REF <git-tag-or-commit>
    [FETCH_SUBMODULES]
    [PATCHES <patch1.patch>...]
)
```

- `URL` — повна адреса репозиторію.
- `FETCH_SUBMODULES` — прапорець, що вказує рекурсивно ініціалізувати та завантажувати всі вкладені сабмодулі Git.

### vcpkg_download_distfile()
Завантажує довільний файл чи архів за списком дзеркал (URL) у централізований каталог `downloads/` із верифікацією хешу.

```cmake
vcpkg_download_distfile(
    <out-var>
    URLS <url1> [<url2>...]
    FILENAME <name-in-downloads>
    SHA512 <checksum>
    [ALWAYS_REDOWNLOAD]
)
```

## 4. Допоміжні функції конфігурації та компіляції

### vcpkg_cmake_configure()
Створює конфігурацію CMake та готує дерево збірки для генератора Ninja на основі параметрів тріплета.

```cmake
vcpkg_cmake_configure(
    SOURCE_PATH <path>
    [OPTIONS <opt1> <opt2>...]
    [OPTIONS_RELEASE <opt1>...]
    [OPTIONS_DEBUG <opt1>...]
    [MAYBE_UNUSED_VARIABLES <var1>...]
    [LOGFILE_BASE <name>]
)
```

- `SOURCE_PATH` — абсолютний шлях до каталогу вихідних кодів проєкту.
- `OPTIONS` — прапорці конфігурації CMake (наприклад, `-DBUILD_SHARED_LIBS=OFF`, `-DENABLE_TESTING=OFF`), які передаються як для релізної, так і для налагоджувальної конфігурацій.
- `OPTIONS_RELEASE` — прапорці, що застосовуються виключно під час генерації Release збірки.
- `OPTIONS_DEBUG` — прапорці, що застосовуються виключно під час генерації Debug збірки.
- `MAYBE_UNUSED_VARIABLES` — перелік змінних, для яких вимикається попередження CMake про невикористані опції конфігурації.
- `LOGFILE_BASE` — префікс імен журналів конфігурації в каталозі `buildtrees/<port>/`.

### vcpkg_cmake_install()
Запускає компіляцію та інсталяцію проєкту в буферний каталог `packages/<port>_<triplet>/`.

```cmake
vcpkg_cmake_install(
    [ADD_BIN_TO_PATH]
    [DISABLE_PARALLEL]
)
```

- Виконує дві послідовні збірки: оптимізовану Release (встановлюється в корінь `${CURRENT_PACKAGES_DIR}`) та Debug (встановлюється у підкаталог `${CURRENT_PACKAGES_DIR}/debug/`).
- `ADD_BIN_TO_PATH` — тимчасово додає каталоги `bin/` зібраних залежностей до системної змінної `PATH`, що необхідно для запуску щойно скомпільованих інструментів під час інсталяції.
- `DISABLE_PARALLEL` — примусово запускає однопотокову збірку для застарілих бібліотек, чиї скрипти збірки мають стан гонитви за файли.

### vcpkg_check_features()
Автоматично перетворює активні компоненти (features) порту у відповідні визначення змінних CMake.

```cmake
vcpkg_check_features(
    OUT_FEATURE_OPTIONS <variable>
    [PREFIX <prefix>]
    FEATURES
        <feature-name> <CMAKE_VARIABLE_NAME>
        ...
)
```

Якщо компонент активний, змінній присвоюється значення `ON`, інакше — `OFF`. Отриманий список прапорців передається безпосередньо в секцію `OPTIONS` виклику `vcpkg_cmake_configure()`.

## 5. Допоміжні функції нормалізації та лінтування

### vcpkg_cmake_config_fixup()
Переносить файли конфігурації CMake (`*Config.cmake`, `*-config.cmake`, `*Targets.cmake`) зі специфічних підкаталогів бібліотеки в канонічний каталог `share/<package>/` та нормалізує шляхи `PACKAGE_PREFIX_DIR`.

```cmake
vcpkg_cmake_config_fixup(
    [PACKAGE_NAME <name>]
    [CONFIG_PATH <relative-path>]
    [DO_NOT_DELETE_EMPTY_CONFIG_DIR]
)
```

- `PACKAGE_NAME` — назва пакета для команди `find_package(<name> CONFIG)`. Якщо не вказано, використовується ім'я поточного порту.
- `CONFIG_PATH` — початкове розташування конфігураційних файлів відносно каталогу інсталяції (наприклад, `lib/cmake/fast-telemetry` або `share/cmake/fast-telemetry`).
- `DO_NOT_DELETE_EMPTY_CONFIG_DIR` — запобігає видаленню початкового каталогу конфігів після перенесення файлів.

### vcpkg_fixup_pkgconfig()
Нормалізує файли `*.pc` у каталогах `lib/pkgconfig` та `debug/lib/pkgconfig`, виправляючи префікси шляхів та видаляючи системні залежності хоста.

```cmake
vcpkg_fixup_pkgconfig(
    [RELEASE_FILES <file1>...]
    [DEBUG_FILES <file1>...]
    [SYSTEM_PACKAGES <pkg1>...]
    [SYSTEM_LIBRARIES <lib1>...]
)
```

### vcpkg_install_copyright()
Копіює один або декілька ліцензійних файлів бібліотеки у фінальний файл `share/<port>/copyright`.

```cmake
vcpkg_install_copyright(
    FILE_LIST <license_file1> [<license_file2>...]
    [COMMENT <text>]
)
```

- Є обов'язковою функцією для кожного порту. Якщо виклик пропущено, лінтер vcpkg відхиляє збірку порту як дефектну.

### vcpkg_copy_pdbs()
Автоматично знаходить файли налагоджувальної інформації `.pdb` компілятора MSVC у каталогах збірки та копіює їх у каталоги `bin/` та `debug/bin/` поруч із відповідними `.dll` та `.exe`.

```cmake
vcpkg_copy_pdbs()
```

## 6. Системні змінні конфігурації тріплетів

Файли тріплетів (`triplets/<triplet>.cmake`) керують параметрами трансляції та зв'язування за допомогою наступних системних змінних:

| Змінна | Можливі значення | Опис поведінки |
| :--- | :--- | :--- |
| `VCPKG_TARGET_ARCHITECTURE` | `x64`, `x86`, `arm`, `arm64`, `wasm32`, `arm64ec` | Цільова апаратна архітектура процесора. |
| `VCPKG_CRT_LINKAGE` | `dynamic`, `static` | Модель зв'язування рантайму C (на Windows визначає прапорці `/MD` чи `/MT`). |
| `VCPKG_LIBRARY_LINKAGE` | `dynamic`, `static` | Визначає, чи компілюються бібліотеки як спільні (`.so`/`.dll`/`.dylib`), чи як статичні архіви (`.a`/`.lib`). |
| `VCPKG_CMAKE_SYSTEM_NAME` | `WindowsStore`, `Linux`, `Darwin`, `Android`, `iOS`, `Emscripten` | Цільова операційна система для крос-компіляції (залишається порожньою для Desktop Windows). |
| `VCPKG_CHAINLOAD_TOOLCHAIN_FILE` | Шлях до файлу | Шлях до зовнішнього файлу тулчейна (наприклад, тулчейна крос-компілятора або Android NDK), який завантажується після ініціалізації vcpkg. |
| `VCPKG_C_FLAGS` | Рядок прапорців | Додаткові прапорці компілятора мови C для обох конфігурацій. |
| `VCPKG_CXX_FLAGS` | Рядок прапорців | Додаткові прапорці компілятора мови C++ для обох конфігурацій. |
| `VCPKG_LINKER_FLAGS` | Рядок прапорців | Додаткові прапорці компонувальника (лінкеру). |
| `VCPKG_BUILD_TYPE` | `release` | Якщо вказано, vcpkg компілює виключно релізну конфігурацію, повністю пропускаючи фазу збірки Debug. |

## 7. Змінні інтеграції з системою збірки CMake

При підключенні файлу `scripts/buildsystems/vcpkg.cmake` поведінка інтеграції може додатково налаштовуватися через аргументи командного рядка CMake:

- `VCPKG_TARGET_TRIPLET` — явна вказівка тріплета для цільових бібліотек (за замовчуванням визначається автоматично за хостовою ОС).
- `VCPKG_HOST_TRIPLET` — вказівка тріплета для збірки хостових генераторів коду при крос-компіляції.
- `VCPKG_MANIFEST_MODE` — примусове увімкнення (`ON`) або вимкнення (`OFF`) маніфестного режиму. За замовчуванням активується автоматично при виявленні `vcpkg.json` у корені проєкту.
- `VCPKG_MANIFEST_INSTALL` — якщо встановлено в `ON` (типово), CMake автоматично відновлює та компілює всі залежності на фазі конфігурації.
- `VCPKG_APPLOCAL_DEPS` — для платформи Windows вмикає автоматичне копіювання необхідних `.dll` файлів у вихідний каталог поруч із виконуваним файлом.
