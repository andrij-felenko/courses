# 📋 Довідник прапорців компіляторів C++: GCC, Clang, MSVC

Точне налаштування параметрів компіляції для трійки провідних інструментаріїв — GNU Compiler Collection (GCC), LLVM/Clang та Microsoft Visual C++ (MSVC) — є обов'язковою умовою для забезпечення переносимості сирцевого коду, дотримання вимог стандарту ISO/IEC 14882 та запобігання прихованим дефектам. Різні компілятори використовують відмінні правила іменування прапорців, мають власні застарілі режими поблажливості (англ. *permissive modes*) та типово вмикають розширення, які не є частиною офіційного стандарту C++.

У цьому довіднику зведено всі ключові прапорці вибору діалекту мови, керування суворістю відповідності стандарту, активації рівнів попереджень і діагностики, налаштування оптимізацій і перевірок пам'яті, вибору стандартної бібліотеки та інспекції внутрішніх макросів препроцесора.

## 1. Прапорці вибору діалекту стандарту

Для ввімкнення підтримки конкретної версії стандарту кожен компілятор надає відповідний перемикач командного рядка. У GCC та Clang прапорці `-std=c++XX` активують суворий режим стандарту ISO, тоді як прапорці `-std=gnu++XX` активують стандарт із розширеннями GNU C/C++ (типовий режим у GCC/Clang). У MSVC прапорці починаються з косої риски `/std:c++XX`.

| Стандарт C++ | GCC (ISO) | GCC / Clang (GNU розширення) | Clang (ISO) | MSVC (Visual Studio) | Мітка чернетки (Draft Alias) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **C++98 / C++03** | `-std=c++98` | `-std=gnu++98` | `-std=c++98` | *(Базовий режим)* | — |
| **C++11** | `-std=c++11` | `-std=gnu++11` | `-std=c++11` | *(Підтримується без окремого прапорця)* | `-std=c++0x`, `-std=gnu++0x` |
| **C++14** | `-std=c++14` | `-std=gnu++14` | `-std=c++14` | `/std:c++14` *(Типово у VS 2015–2019)* | `-std=c++1y`, `-std=gnu++1y` |
| **C++17** | `-std=c++17` | `-std=gnu++17` | `-std=c++17` | `/std:c++17` *(Типово з VS 2022 v17.0)* | `-std=c++1z`, `-std=gnu++1z` |
| **C++20** | `-std=c++20` | `-std=gnu++20` | `-std=c++20` | `/std:c++20` | `-std=c++2a`, `-std=gnu++2a` |
| **C++23** | `-std=c++23` | `-std=gnu++23` | `-std=c++23` | `/std:c++23` *(Починаючи з VS 2022 v17.6+)* | `-std=c++2b`, `-std=gnu++2b` |
| **C++26 (Чернетка)**| `-std=c++26` | `-std=gnu++26` | `-std=c++26` | `/std:c++latest` | `-std=c++2c`, `-std=gnu++2c` |

### Особливості поведінки перемикачів діалектів

1. **Типові значення без явного вказання прапорця:**
   - **GCC:** починаючи з версії GCC 6.1 типовим діалектом за замовчуванням є `-std=gnu++14`. Починаючи з версії GCC 11.1 типовим стандартом за замовчуванням став `-std=gnu++17`. Зверніть увагу: за замовчуванням GCC завжди використовує режим розширень GNU (`gnu++`), а не чистий ISO C++.
   - **Clang:** синхронізований з GCC; починаючи з Clang 6.0 типово використовує `-std=gnu++14`, а починаючи з Clang 16.0 — `-std=gnu++17`.
   - **MSVC:** тривалий час використовував за замовчуванням режим `/std:c++14`. У Visual Studio 2022 версії 17.0+ типовим є стандарт `/std:c++17`.

2. **Прапорець `/std:c++latest` у MSVC:**
   - Вмикає всі реалізовані на поточний момент можливості робочої чернетки майбутнього стандарту C++ (наразі C++26), а також експериментальні доповнення до стандартної бібліотеки MSVC STL.
   - Автоматично активує суворий режим відповідності `/permissive-`.
   - Не гарантує стабільності ABI між мінорними оновленнями компілятора `cl.exe`. Цей прапорець призначений виключно для експериментів з новими можливостями та раннього тестування, але не для стабільних релізів бібліотек з фіксованим двійковим інтерфейсом.

3. **Анатомія відмінностей між `-std=c++XX` та `-std=gnu++XX`:**
   Режим розширень GNU дозволяє використання синтаксичних конструкцій, запозичених із мови C або створених спеціально для оптимізації низькорівневих системних компонентів ядра Linux:
   - **Масиви змінної довжини (Variable Length Arrays, VLA):** виділення масивів динамічного розміру на стеку `int arr[n];` усередині функцій. У чистому C++ масиви на стеку зобов'язані мати константний розмір часу компіляції (`constexpr`), а для динамічного виділення призначені `std::vector` або `std::unique_ptr<int[]>`.
   - **Вирази-блоки (Statement Expressions):** складні складені конструкції виду `({ int x = calc(); x > 0 ? x : 0; })`, які повертають значення останнього виразу. Вони не підтримуються стандартом ISO C++ і викликають помилку синтаксичного розбору в інших компіляторах.
   - **Нестандартні ключові слова й атрибути:** пряме використання `typeof(...)`, `__alignof__(...)`, `__attribute__((aligned(16)))` замість стандартних операторів `decltype(...)`, `alignof(...)` та `alignas(16)`.
   - **Порожні або безрозмірні структури:** `struct Empty {};` у C-контекстах має розмір 0 байтів у GNU C, тоді як стандарт C++ строго вимагає, щоб будь-який повний тип об'єкта займав щонайменше 1 байт для забезпечення унікальності покажчиків.

Використання `-std=gnu++XX` призводить до того, що сирцевий код, успішно скомпільований на машині з GCC, зазнає аварійної зупинки під час спроби компіляції через MSVC або Clang у режимі чистого стандарту.

## 2. Прапорці суворої відповідності стандарту (Conformance & Conformance Switching)

Стандарт C++ забороняє певні конструкції, які історично підтримувалися компіляторами як розширення вендорів. Щоб змусити компілятор суворо слідувати ISO/IEC 14882, застосовують спеціалізовані прапорці відповідності.

### GCC та Clang: вимкнення розширень і педантична діагностика

```bash
# Примусове відхилення нестандартних розширень ISO C++
g++ -std=c++20 -pedantic-errors main.cpp

# Попередження про всі розширення без переривання збірки
clang++ -std=c++20 -Wpedantic main.cpp
```

- `-pedantic` (або еквівалентний йому `-Wpedantic`): активує діагностику та формує попередження для всіх конструкцій, які не відповідають суворому стандарту ISO C++ (наприклад, використання масивів змінної довжини VLA, порожніх структур або нестандартних виразів-блоків `({ ... })`).
- `-pedantic-errors`: підвищує серйозність усіх попереджень `-pedantic` до статусу критичних помилок компіляції (Error), повністю блокуючи генерацію об'єктного файлу при використанні вендорних розширень. Це найефективніший спосіб гарантувати, що в код не просочаться GNU-розширення.
- `-fno-gnu-keywords`: вимикає розпізнавання спеціальних ключових слів GNU (`typeof`, `__alignof__` тощо) у режимі суворого стандарту, дозволяючи використовувати ці імена як звичайні ідентифікатори змінних чи функцій.
- `-fstrict-enums`: змушує компілятор оптимізувати операції на основі точного діапазону значень перелічень `enum`, вважаючи будь-які інші значення невизначеною поведінкою (Undefined Behavior).
- `-fno-permissive`: забороняє застарілі відхилення від стандарту C++, такі як неявне приведення вказівників або використання імен функцій без попереднього оголошення.

### MSVC: двофазний пошук імен та прапорці `/Zc`

Історично компілятор MSVC (`cl.exe`) використовував однофазний спрощений розбір шаблонів: усі імена всередині шаблону розв'язувалися лише в момент інстанціації. Стандарт ISO C++ вимагає **двофазного пошуку імен** (англ. *Two-Phase Name Lookup*):
1. **Фаза 1 (визначення шаблону):** компілятор перевіряє синтаксис та розв'язує всі незалежні імена (англ. *non-dependent names*). Якщо незалежне ім'я містить друкарську помилку чи не оголошене в поточній області, компілятор зобов'язаний видати помилку одразу, навіть якщо цей шаблон ніколи не інстанціюється в програмі.
2. **Фаза 2 (інстанціація шаблону):** компілятор підставляє конкретні типи-аргументи та виконує пошук залежних імен (англ. *dependent names*) через механізм ADL.

Увімкнення прапорця `/permissive-` активує двофазний пошук імен у MSVC і вимагає обов'язкового використання ключових слів `typename` та `template` для залежних типів і функцій (наприклад, `typename T::iterator` або `obj.template get<int>()`).

Зведена таблиця спеціалізованих прапорців конформантності MSVC:

| Прапорець MSVC | Призначення та нормативна поведінка | Стан за замовчуванням |
| :--- | :--- | :--- |
| **/permissive-** | Вмикає стандартну сумісність: двофазний пошук імен у шаблонах (*Two-phase name lookup*), суворі вимоги до `typename`/`template`, заборону неявних приведень типів покажчиків на функції та альтернативні операторні токени (`and`, `or`, `not`). | **Увімкнено** при `/std:c++20`, `/std:c++latest`; вимкнено при `/std:c++14` |
| **/Zc:__cplusplus** | Змушує макрос `__cplusplus` повертати реальну дату стандарту (наприклад, `202002L` для C++20 замість застарілого значення `199711L`). | **Вимкнено** (вимагає явного додавання у командний рядок збірки) |
| **/Zc:preprocessor** | Активує новий стандартний препроцесор ISO C/C++, який правильно підтримує макроси зі змінною кількістю аргументів, токен `__VA_OPT__`, кому перед порожнім списком та рекурсивне розгортання токенів. | **Вимкнено** (традиційний препроцесор активний за замовчуванням) |
| **/Zc:lambda** | Активує новий синтаксичний аналізатор лямбда-виразів з підтримкою правильного захоплення вкладених типів, узагальнених шаблонів лямбд та розширеного пошуку імен. | **Увімкнено** за замовчуванням у Visual Studio 2019 v16.8+ |
| **/Zc:inline** | Видаляє невикористані вбудовані функції (*unreferenced inline functions*) з об'єктного коду, зменшуючи розмір двійкових файлів та прискорюючи компонування. | **Увімкнено** за замовчуванням |
| **/Zc:throwingNew** | Повідомляє компілятору, що оператор `operator new` викидає виняток `std::bad_alloc` при невдачі, що дозволяє оптимізатору опускати перевірку результату виділення пам'яті на `nullptr`. | **Вимкнено** |
| **/Zc:rvalueCast** | Забороняє приведення типів до неконстантного lvalue-посилання для rvalue-виразів відповідно до стандарту C++11. | **Увімкнено** за замовчуванням |
| **/Zc:strictStrings** | Забороняє неявне приведення рядкових літералів типу `const char[]` до неконстантного покажчика `char*`. | **Увімкнено** при `/permissive-` |
| **/Zc:templateScope** | Вмикає суворі правила видимості параметрів шаблонів згідно з вимогами стандарту C++20. | **Увімкнено** у нових версіях VS 2022 |
| **/Zc:ternary** | Застосовує правила C++11 до тернарного умовного оператора `?:` щодо приведення типів аргументів. | **Увімкнено** при `/permissive-` |
| **/Zc:enumTypes** | Забезпечує точне дотримання базових типів перелічень `enum` та операцій з їхніми значеннями. | **Увімкнено** у VS 2022 v17.4+ |
| **/Zc:hiddenFriend** | Забезпечує правильну видимість функцій «прихованих друзів» (*hidden friends*) виключно через ADL. | **Увімкнено** при `/permissive-` |
| **/utf-8** | Встановлює кодування UTF-8 і для сирцевих файлів (*Source Character Set*), і для рядкових літералів у бінарнику (*Execution Character Set*). | **Вимкнено** (типово використовується локаль Windows ANSI) |

### Чому новий препроцесор MSVC (`/Zc:preprocessor`) критичний

Традиційний препроцесор MSVC містив грубу помилку в обробці макросів зі змінною кількістю аргументів `__VA_ARGS__`: при передачі списку аргументів в інший вкладений макрос MSVC склеював усі аргументи в один єдиний строковий токен. Це повністю ламало роботу метапрограмних бібліотек на зразок `Boost.Preprocessor` і унеможливлювало використання нового токена C++20 `__VA_OPT__(,)` для видалення зайвої коми перед порожнім списком аргументів. Прапорець `/Zc:preprocessor` повністю замінює застарілий рушій на строгий аналізатор стандарту ISO C99 / C++20.

## 3. Діагностика, попередження та суворість (Warnings and Diagnostic Severity)

Для запобігання помилкам часу виконання та підтримки найвищої якості кодової бази проєкти використовують набори прапорців суворої діагностики.

### Рівні попереджень та прапорці діагностики у GCC / Clang

```bash
# Базовий рекомендований набір суворої діагностики для GCC / Clang
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -Wnon-virtual-dtor -Wold-style-cast -Wconversion -Wsign-conversion -Wnull-dereference -Woverloaded-virtual -Wduplicated-cond -Wduplicated-branches -Wlogical-op -Wzero-as-null-pointer-constant -Werror main.cpp
```

- `-Wall`: вмикає широкий базовий набір попереджень щодо підозрілих конструкцій (неініціалізовані змінні, пропущені гілки `switch`, переповнення констант, небезпечні операції присвоєння в умовах).
- `-Wextra` (історична назва `-W`): додає додаткові важливі попередження, які не увійшли до `-Wall` (порівняння знакових і беззнакових цілих чисел, невикористані параметри функцій, порожні тіла циклів, пропущені ініціалізатори у структурах).
- `-Wpedantic`: попереджає про будь-які відхилення від синтаксису ISO C++.
- `-Werror`: перетворює всі попередження на фатальні помилки компіляції. Це запобігає накопиченню технічного боргу в командній розробці.
- `-Werror=NAME`: перетворює конкретне попередження (наприклад, `-Werror=return-type` або `-Werror=uninitialized`) на фатальну помилку, залишаючи решту попереджень інформативними.
- `-Wshadow`: попереджає, коли локальна змінна затінює іншу змінну, параметр функції або поле класу у зовнішній області видимості. Затінювання полів класу конструкторами є однією з найпоширеніших причин прихованих логічних помилок.
- `-Wnon-virtual-dtor`: попереджає, якщо клас містить віртуальні функції, але його деструктор не оголошено віртуальним. Знищення поліморфного об'єкта через покажчик на базовий клас без віртуального деструктора призводить до невизначеної поведінки та витоку ресурсів похідного класу.
- `-Wold-style-cast`: виявляє використання С-подібного приведення типів `(Type)val` замість явних C++ операторів `static_cast`, `reinterpret_cast` або `const_cast`. С-приведення небезпечне тим, що може непомітно зняти константність або виконати небезпечне реінтерпретування пам'яті.
- `-Wconversion` та `-Wsign-conversion`: виявляють неявні звужувальні перетворення типів (наприклад, приведення 64-бітного `size_t` до 32-бітного `int` або змішування знакових і беззнакових чисел зі зміною значення).
- `-Wnull-dereference`: попереджає про гарантоване або високоімовірне розіменування нульового покажчика на основі статичного аналізу потоку керування.
- `-Woverloaded-virtual`: попереджає, якщо функція у похідному класі приховує віртуальну функцію базового класу замість її перевизначення через незначну розбіжність у сигнатурі.
- `-Wduplicated-cond` (GCC): виявляє повторення ідентичних логічних умов у ланцюжках `if (...) else if (...)`.
- `-Wduplicated-branches` (GCC): виявляє наявність абсолютно однакового коду в різних гілках розгалуження `if/else`.
- `-Wlogical-op` (GCC): попереджає про підозріле використання логічних операторів `&&` та `||` там, де ймовірно очікувалися побітові операції `&` або `|`.
- `-Wzero-as-null-pointer-constant`: попереджає про використання числового літерала `0` або макроса `NULL` замість стандартизованого ключового слова `nullptr`.

### Рівні попереджень та прапорці діагностики у MSVC

```cmd
:: Базовий рекомендований набір діагностики для MSVC
cl.exe /std:c++20 /permissive- /W4 /WX /Zc:__cplusplus /Zc:preprocessor /utf-8 /external:anglebrackets /external:W0 main.cpp
```

- `/W0`: повністю вимикає всі попередження компілятора.
- `/W1`: відображає лише критичні попередження високої важливості (наприклад, явні синтаксичні конфлікти).
- `/W2`: додає діагностику конструкцій, що можуть призвести до проблем із пам'яттю чи логікою.
- `/W3`: стандартний виробничий рівень для розробки корпоративних додатків під Windows.
- `/W4`: рекомендований рівень суворої діагностики для сучасного коду C++. Включає глибокі перевірки неініціалізованих змінних, невикористаних формальних параметрів та втрати точності даних при приведенні типів.
- `/Wall`: вмикає абсолютно всі наявні попередження компілятора, включно з тими, що за замовчуванням вимкнені через надмірну шумовитість або невідповідність стандартним системним заголовкам Windows SDK. У реальній розробці цей режим вимагає обов'язкового вибіркового вимкнення сотень попереджень через директиви `#pragma warning(disable: ...)`.
- `/WX`: перетворює всі попередження на фатальні помилки компіляції (прямий аналог `-Werror` у GCC/Clang).
- `/weNNNN`: перетворює конкретне попередження номер `NNNN` на фатальну помилку (наприклад, `/we4715` для неповернення значення з усіх гілок функції).
- `/wdNNNN`: пригнічує та вимикає повідомлення про попередження номер `NNNN` (наприклад, `/wd4100` для ігнорування невикористаних параметрів у функціях зворотного виклику або `/wd4251` для попереджень експорту шаблонів DLL).
- `/external:anglebrackets /external:W0`: надзвичайно важливий прапорець MSVC, який пригнічує діагностику попереджень у зовнішніх системних заголовках (що підключаються через кутові дужки `#include <...>`), застосовуючи сувору політику `/W4 /WX` виключно до сирцевих файлів поточного проєкту.

## 4. Прапорці стандартної бібліотеки, безпеки та середовища виконання

На платформах Unix/Linux та macOS компілятор Clang може взаємодіяти з різними реалізаціями стандартної бібліотеки STL: LLVM `libc++` або GNU `libstdc++`.

### Вибір стандартної бібліотеки у Clang

- `-stdlib=libc++`: вказує компілятору Clang використовувати реалізацію стандартної бібліотеки LLVM libc++ та бібліотеку розгортання стека `libc++abi`. Це типовий вибір на macOS та FreeBSD.
- `-stdlib=libstdc++`: вказує компілятору Clang використовувати стандартну бібліотеку GNU libstdc++ від проєкту GCC. Це типовий вибір у більшості дистрибутивів Linux (Ubuntu, Debian, Fedora, RHEL).

```bash
# Збірка Clang з використанням LLVM libc++ на Linux
clang++ -std=c++20 -stdlib=libc++ -lc++ -lc++abi main.cpp
```

### Прапорці захисту STL та безпеки пам'яті

Сучасні версії бібліотек підтримують внутрішні механізми перевірки меж ітераторів та інваріантів:
- **GNU libstdc++:** `-D_GLIBCXX_ASSERTIONS` активує швидкі перевірки виходу за межі діапазону в `std::vector::operator[]`, `std::string_view` та розіменування `std::optional` без суттєвої деградації швидкодії. Повний налагоджувальний режим `-D_GLIBCXX_DEBUG` змінює макет типів контейнерів і несумісний по ABI з релізними бінарниками.
- **LLVM libc++:** прапорець `-D_LIBCPP_HARDENING_MODE=_LIBCPP_HARDENING_MODE_FAST` або `_EXTENSIVE` вмикає перевірки меж та запобігання експлуатації вразливостей пам'яті.

### Вибір середовища виконання (C/C++ Runtime Library) у MSVC

Компілятор MSVC вимагає узгодженого вибору версії рантайму C/C++ Runtime (CRT) для всіх модулів проєкту:

| Прапорець MSVC | Тип середовища виконання | Багатопотоковість | Налагоджувальна версія (Debug) | Макрос препроцесора |
| :--- | :--- | :--- | :--- | :--- |
| **/MD** | Динамічна бібліотека DLL (MSVCPRT.LIB / MSVCRT.DLL) | Так | Ні | `_MT`, `_DLL` |
| **/MDd** | Динамічна бібліотека DLL (Налагодження) | Так | Так | `_DEBUG`, `_MT`, `_DLL` |
| **/MT** | Статична лінковка (LIBCPMT.LIB / LIBCMT.LIB) | Так | Ні | `_MT` |
| **/MTd** | Статична лінковка (Налагодження) | Так | Так | `_DEBUG`, `_MT` |

> ⚠️ **Важливе правило компонування MSVC:** ніколи не змішуйте статичні бібліотеки, скомпільовані з `/MT`, з модулями, зібраними з `/MD`. Це призведе до конфлікту символів лінкера (`LNK2005`), подвійної ініціалізації середовища виконання та краху при звільненні пам'яті (`std::free` або `delete`) між різними копіями купи (Heap).

## 5. Інспекція макросів препроцесора та перевірка стану компілятора

Щоб точно перевірити, які саме макроси конфігурації стандарту активні при заданих прапорцях, використовують спеціальні режими роботи препроцесора.

### Отримання повного дампу вбудованих макросів

:::tabs
```bash
# Дамп усіх макросів у GCC для C++20
g++ -std=c++20 -dM -E -x c++ /dev/null | grep -E "(__cplusplus|__cpp_)"
```
```bash
# Дамп усіх макросів у Clang для C++23
clang++ -std=c++23 -dM -E -x c++ /dev/null | grep -E "(__cplusplus|__cpp_)"
```
```cmd
:: Перевірка значення макросів у MSVC через препроцесор
cl.exe /std:c++20 /Zc:__cplusplus /E /d1PP test.cpp
```
:::

### Ключові макроси ідентифікації компілятора та стандарту

- `__cplusplus`: числове значення стандарту ISO C++ у форматі `YYYYMML`:
  - `199711L` — C++98 / C++03;
  - `201103L` — C++11;
  - `201402L` — C++14;
  - `201703L` — C++17;
  - `202002L` — C++20;
  - `202302L` — C++23;
  - `202600L` або вище — C++26 (робоча чернетка).
- `_MSVC_LANG`: специфічний макрос MSVC, який завжди відображає активний прапорець стандарту (`/std:c++14` -> `201402L`, `/std:c++17` -> `201703L`, `/std:c++20` -> `202002L`, `/std:c++latest` -> значення понад `202302L`), незалежно від наявності прапорця `/Zc:__cplusplus`.
- `__GNUC__`, `__GNUC_MINOR__`, `__GNUC_PATCHLEVEL__`: версія компілятора GCC (також визначаються Clang для сумісності).
- `__clang__`, `__clang_major__`, `__clang_minor__`, `__clang_patchlevel__`: точна версія транслятора Clang.
- `_MSC_VER`: номер версії компілятора MSVC (наприклад, `1930` для Visual Studio 2022 v17.0, `1940` для Visual Studio 2022 v17.10).

## 6. Зведена таблиця відповідності суворих прапорців у CMake

Сучасна система збірки CMake абстрагує специфічні прапорці компіляторів за допомогою властивостей цілей (*Target Properties*):

| Вимога стандарту та якості | Властивість CMake або команда | Еквівалент GCC/Clang | Еквівалент MSVC |
| :--- | :--- | :--- | :--- |
| Встановити стандарт C++20 | `set_target_properties(tgt PROPERTIES CXX_STANDARD 20)` | `-std=c++20` або `-std=gnu++20` | `/std:c++20` |
| Вимагати точний стандарт (без відкату) | `set_target_properties(tgt PROPERTIES CXX_STANDARD_REQUIRED ON)` | Помилка конфігурації, якщо стандарт не підтримується | Помилка конфігурації, якщо стандарт не підтримується |
| Вимкнути вендорні розширення (Суворий ISO) | `set_target_properties(tgt PROPERTIES CXX_EXTENSIONS OFF)` | `-std=c++20` (замість `-std=gnu++20`) | `/permissive-` |
| Увімкнути суворі попередження | `target_compile_options(tgt PRIVATE $<$<CXX_COMPILER_ID:GNU,Clang>:-Wall -Wextra -Wpedantic> $<$<CXX_COMPILER_ID:MSVC>:/W4>)` | `-Wall -Wextra -Wpedantic` | `/W4` |
| Перетворити попередження на помилки | `set_target_properties(tgt PROPERTIES COMPILE_WARNING_AS_ERROR ON)` *(CMake 3.24+)* | `-Werror` | `/WX` |
| Новий препроцесор ISO для MSVC | `target_compile_options(tgt PRIVATE $<$<CXX_COMPILER_ID:MSVC>:/Zc:preprocessor /Zc:__cplusplus>)` | *(За замовчуванням)* | `/Zc:preprocessor /Zc:__cplusplus` |
| UTF-8 кодування для MSVC | `target_compile_options(tgt PRIVATE $<$<CXX_COMPILER_ID:MSVC>:/utf-8>)` | *(За замовчуванням)* | `/utf-8` |
