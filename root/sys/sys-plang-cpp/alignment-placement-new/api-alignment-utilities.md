# 📋 Довідник утиліт вирівнювання пам'яті та розміщувального new

Коли програма виходить за межі автоматичного виділення об'єктів і бере керування пам'яттю у власні руки, вона зобов'язана дотримуватися суворих апаратних та мовних контрактів. Будь-яка помилка в розрахунку адреси, недостатнє вирівнювання сирого буфера або неправильний виклик деструктора призводить до важковловимих збоїв: від деградації швидкодії та падіння конвеєра на x86 до аварійного завершення процесу сигналом `SIGBUS` на архітектурах ARM і RISC-V. Цей довідник містить вичерпний опис стандартних мовних засобів C++, операторів, функцій і констант, призначених для контролю вирівнювання даних та ініціалізації об'єктів у попередньо виділених буферах.

## Мовні оператори: alignof та alignas

Контроль вирівнювання на рівні синтаксису мови введено у стандарті C++11 через ключові слова `alignof` та `alignas`. Вони замінили розрізнені компіляторні розширення минулого (`__attribute__((aligned(N)))` у GCC/Clang та `__declspec(align(N))` у MSVC) єдиним стандартизованим інтерфейсом.

### Оператор alignof

Оператор `alignof` повертає вимогу вирівнювання заданого типу в байтах. Значення завжди є цілочисельною константою часу компіляції типу `std::size_t` і обов'язково дорівнює додатньому степеню двійки (`1`, `2`, `4`, `8`, `16`, `32`, `64` тощо).

```cpp
#include <cstddef>
#include <iostream>

struct PacketHeader {
    char flag;       // 1 байт
    int id;          // 4 байти
    double weight;   // 8 байтів
};

static_assert(alignof(char) == 1);
static_assert(alignof(int) == 4);
static_assert(alignof(double) == 8);
static_assert(alignof(PacketHeader) == 8); // визначається найбільшим членом
```

#### Правила обчислення alignof

| Цільовий тип | Значення `alignof` | Примітка |
| :--- | :--- | :--- |
| Фундаментальний тип (`char`, `int`, `double`...) | Природне вирівнювання архітектури | Зазвичай дорівнює `sizeof(T)`, крім деяких 32-бітних платформ для 64-бітних чисел |
| Масив `T[N]` | `alignof(T)` | Вирівнювання масиву завжди збігається з вирівнюванням його базового елемента |
| Структура / Клас | Найбільше значення `alignof` серед усіх нестатичних членів | За відсутності явного специфікатора `alignas` |
| Посилання `T&` | `alignof(T)` | Посилання має вимогу вирівнювання типу, на який воно посилається |
| Неповний тип (`incomplete type`) | Помилка компіляції | Не можна запитувати `alignof` для неоголошеної структури `struct Node;` |

### Специфікатор alignas

Специфікатор `alignas` установлює вимогу вирівнювання для оголошення змінної, поля структури або визначення типу. Він приймає або константний вираз, що обчислюється у ступінь двійки, або тип, чиє вирівнювання слід запозичити.

```cpp
// 1. Примусове вирівнювання окремої змінної
alignas(16) float vector4[4];

// 2. Використання типу як аргументу
alignas(double) char raw_buffer[sizeof(double)];

// 3. Вирівнювання поля структури
struct Node {
    char tag;
    alignas(64) int counter; // розміщує counter на початку 64-байтної кеш-лінії
};

// 4. Вирівнювання цілого типу
struct alignas(32) AVXData {
    float values[8];
};
```

#### Обмеження та правила специфікатора alignas

1. **Заборона послаблення:** Специфікатор `alignas` не може задати вирівнювання, менше за природне вирівнювання типу. Запис `alignas(2) int x;` на платформі, де `alignof(int) == 4`, є некоректним і призводить до помилки компіляції (`error: alignment of 'x' is less than the natural alignment of type 'int'`). Послаблення вирівнювання в C++ можливе лише через нестандартні компіляторні директиви пакування (`#pragma pack(push, 1)` або `__attribute__((packed))`), які знімають внутрішній відступ (padding), але роблять пряме взяття покажчика на поле потенційним джерелом UB.
2. **Лише степені двійки:** Значення вирівнювання обов'язково має бути додатним степенем двійки (`1`, `2`, `4`, `8`...). Значення на зразок `alignas(3)` чи `alignas(10)` викликають помилку трансляції.
3. **Об'єднання кількох alignas:** Якщо до одного оголошення застосовано кілька специфікаторів `alignas`, компілятор обирає найбільш суворе (найбільше) значення:
   ```cpp
   alignas(8) alignas(32) int x; // підсумкове вирівнювання буде 32
   ```
4. **Вирівнювання та масиви:** Якщо тип `T` оголошено зі специфікатором `alignas(N)`, то кожен елемент масиву `T arr[M]` буде вирівняний по межі `N`. Для забезпечення цієї гарантії компілятор автоматично збільшує `sizeof(T)` до найближчого кратного `N` за рахунок додавання хвостового вирівнювального заповнення (tail padding).

## Фундаментальне вирівнювання: std::max_align_t

Заголовок `<cstddef>` визначає псевдонім типу `std::max_align_t`. Це тривіальний скалярний тип (зазвичай еквівалентний найдовшому фундаментальному типу платформи, як-от `long double` або подвійне машинне слово), чия вимога вирівнювання є максимальною серед усіх скалярних типів за відсутності специфікаторів надмірного вирівнювання.

```cpp
#include <cstddef>

constexpr std::size_t max_alignment = alignof(std::max_align_t);
```

### Контракт std::max_align_t

- **Гарантія стандартних алокаторів:** Системні функції виділення динамічної пам'яті `std::malloc`, `std::calloc`, `std::realloc`, а також звичайні глобальні оператори `::operator new` гарантують, що адреса поверненого блоку пам'яті завжди вирівняна щонайменше за модулем `alignof(std::max_align_t)`.
- **Типові значення:** На переважній більшості сучасних систем (x86-64, ARM64, RISC-V 64) `alignof(std::max_align_t)` дорівнює `16` байтам (або `8` байтам на 32-бітних x86/ARM32).
- **Призначення:** Якщо ви пишете власний універсальний алокатор або пул пам'яті, кожен виділений фрагмент для невідомого заздалегідь типу має вирівнюватися за `alignof(std::max_align_t)`. Будь-який скалярний фундаментальний тип мови гарантовано розміщується у такому сховищі без порушення апаратних вимог.

## Пошук вирівняної ділянки: std::align

Функція `std::align` оголошена в заголовку `<memory>` і призначена для обчислення адреси всередині наданого буфера, яка задовольняє вказані вимоги до розміру та вирівнювання.

### Сигнатура

```cpp
#include <memory>

void* align(
    std::size_t alignment,
    std::size_t size,
    void*& ptr,
    std::size_t& space
) noexcept;
```

### Параметри функції

| Параметр | Тип | Опис та семантика |
| :--- | :--- | :--- |
| `alignment` | `std::size_t` | Необхідне вирівнювання в байтах. Обов'язково має бути додатним ступенем двійки. |
| `size` | `std::size_t` | Розмір у байтах об'єкта або блоку даних, який планується розмістити. |
| `ptr` | `void*&` | Посилання на вказівник початку вільної області буфера. У разі успіху функція **модифікує** цей вказівник, записуючи в нього першу вирівняну адресу. |
| `space` | `std::size_t&` | Посилання на розмір доступного вільного місця в буфері. У разі успіху функція **зменшує** це значення на кількість байтів, витрачених на вирівнювальний відступ (padding). |

### Повернене значення та алгоритм

Математично функція перевіряє, на скільки байтів слід збільшити поточну адресу `uintptr_t(ptr)`, щоб вона ділилася на `alignment` без залишку:

```
offset = (alignment - (uintptr_t(ptr) % alignment)) % alignment
```

Або через бітову маску (оскільки `alignment` є степенем двійки):

```
aligned_address = (uintptr_t(ptr) + alignment - 1) & ~(alignment - 1)
offset = aligned_address - uintptr_t(ptr)
```

- **Успіх:** Якщо у буфері залишається достатньо байтів для заповнення відступу та самого об'єкта (`size + offset <= space`), функція оновлює вхідні змінні:
  ```
  ptr = reinterpret_cast<void*>(aligned_address);
  space -= offset;
  ```
  і повертає оновлений вказівник `ptr`.
- **Невдача:** Якщо вільного місця недостатньо (`size + offset > space`), функція повертає `nullptr`, а значення змінних `ptr` та `space` залишаються **повністю незмінними**.

### Приклад застосування std::align

```cpp
#include <memory>
#include <cstddef>
#include <cstdint>
#include <iostream>

struct SensorData {
    double timestamp;  // alignof = 8, sizeof = 8
    float values[3];   // 12 байтів + 4 байти padding -> sizeof = 24
};

int main() {
    alignas(std::max_align_t) std::byte storage[256];
    
    void* current_ptr = storage + 3; // навмисно беремо невирівняну адресу (+3 байти від початку)
    std::size_t free_space = sizeof(storage) - 3;
    
    void* aligned_ptr = std::align(
        alignof(SensorData),
        sizeof(SensorData),
        current_ptr,
        free_space
    );
    
    if (aligned_ptr != nullptr) {
        // current_ptr тепер зсунутий на найближчу адресу, кратну 8 (додано 5 байтів padding)
        // free_space зменшено на розмір доданого padding (на 5 байтів)
        SensorData* sensor = ::new (aligned_ptr) SensorData{100.5, {1.0f, 2.0f, 3.0f}};
        
        std::cout << "Об'єкт успішно розміщено за адресою: " << sensor << "\n";
        
        // Звільнення об'єкта
        sensor->~SensorData();
    }
}
```

## Надмірне вирівнювання та std::align_val_t (C++17)

До стандарту C++17 типи, вирівнювання яких перевищувало `alignof(std::max_align_t)` (так звані *over-aligned types*, наприклад, векторні 32-байтні типи AVX `alignas(32)` або 64-байтні структури під кеш-лінію `alignas(64)`), не підтримувалися стандартним оператором `new`. Виклик `new OverAlignedType` повертав адресу з вирівнюванням лише до `alignof(std::max_align_t)`, що викликало апаратні збої інструкцій SIMD.

У C++17 додано переліковий тип `std::align_val_t` у заголовку `<new>` та відповідні перевантаження операторів виділення пам'яті.

### Визначення типу

```cpp
namespace std {
    enum class align_val_t : std::size_t {};
}
```

### Перевантаження операторів пам'яті у стандартній бібліотеці

```cpp
void* operator new(std::size_t count, std::align_val_t al);
void* operator new[](std::size_t count, std::align_val_t al);

void operator delete(void* ptr, std::align_val_t al) noexcept;
void operator delete[](void* ptr, std::align_val_t al) noexcept;

void operator delete(void* ptr, std::size_t sz, std::align_val_t al) noexcept;
void operator delete[](void* ptr, std::size_t sz, std::align_val_t al) noexcept;
```

Компілятор C++17 і новіших стандартів автоматично генерує виклики цих операторів, коли створюється або видаляється об'єкт із типом `alignof(T) > alignof(std::max_align_t)`:

```cpp
struct alignas(64) CacheAlignedBlock {
    int counter;
    char payload[60];
};

// Компілятор C++17 транслює цей рядок у:
// operator new(sizeof(CacheAlignedBlock), std::align_val_t(64))
CacheAlignedBlock* p = new CacheAlignedBlock();

// Транслюється у:
// operator delete(p, sizeof(CacheAlignedBlock), std::align_val_t(64))
delete p;
```

Під капотом реалізації стандартної бібліотеки транслюють ці виклики у системні функції ОС із підтримкою явного вирівнювання: `posix_memalign` або `aligned_alloc` на POSIX-сумісних системах (Linux, macOS) та `_aligned_malloc` / `_aligned_free` на Windows.

## Підказка компілятору: std::assume_aligned (C++20)

У високоефективних чисельних алгоритмах компілятор часто не може довести за контекстом, що переданий через параметри сирий вказівник має спеціальне вирівнювання (наприклад, 32 або 64 байти для векторних інструкцій AVX-512 чи ARM NEON). Через це оптимізатор змушений генерувати повільніші непідрівняні інструкції завантаження (`vmovups`) замість швидких вирівняних (`vmovaps`).

Функція `std::assume_aligned` з заголовка `<memory>` слугує явною декларацією контракту вирівнювання для оптимізатора.

### Сигнатура

```cpp
#include <memory>

template<std::size_t N, typename T>
[[nodiscard]] constexpr T* assume_aligned(T* ptr) noexcept;
```

### Контракт і правила застосування

1. **Шаблонний параметр `N`:** Обов'язково має бути додатним степенем двійки.
2. **Прекондиція:** Вказівник `ptr` на момент виклику зобов'язаний реально вказувати на адресу, кратну `N`.
3. **Порушення контракту:** Якщо функцію викликано над адресою, яка не є кратною `N`, це породжує **невизначену поведінку (Undefined Behavior)**. Компілятор оптимізує подальший код під припущення вирівняності, що призводить до апаратних падінь або генерації некоректного машинного коду.

```cpp
#include <memory>
#include <numeric>
#include <span>

void process_floats_avx(float* raw_data, std::size_t count) {
    // Повідомляємо компілятору, що raw_data гарантовано вирівняний по межі 64 байтів
    float* aligned_data = std::assume_aligned<64>(raw_data);
    
    // Компілятор може безпечно розгорнути цикл у векторні інструкції vmovaps
    for (std::size_t i = 0; i < count; ++i) {
        aligned_data[i] *= 2.0f;
    }
}
```

## Багатопотокові константи вирівнювання (C++17)

Заголовок `<new>` визначає дві платформозалежні константи для керування просторовою локальністю та запобігання конфліктам кешів процесора в паралельних програмах.

```cpp
#include <new>

namespace std {
#ifdef __cpp_lib_hardware_interference_size
    constexpr std::size_t hardware_destructive_interference_size = /* implementation-defined */;
    constexpr std::size_t hardware_constructive_interference_size = /* implementation-defined */;
#endif
}
```

### Призначення констант

| Константа | Сенс і типове значення | Застосування |
| :--- | :--- | :--- |
| `hardware_destructive_interference_size` | Мінімальний інтервал у байтах між двома об'єктами, що гарантує відсутність взаємної інвалідації кешів при одночасному записі з різних ядер (типово `64` байти на x86/ARM). | Використовується як аргумент `alignas(...)` для ліквідації явища **False Sharing** (хибного розділення кеш-ліній). |
| `hardware_constructive_interference_size` | Максимальний розмір безперервної ділянки пам'яті в байтах, для якої гарантується потрапляння у спільну кеш-лінію при спільному читанні. | Використовується для групування даних, які вигідно завантажувати в кеш процесора однією операцією. |

### Приклад усунення False Sharing

```cpp
#include <new>
#include <atomic>
#include <thread>

struct ThreadMetrics {
    // Кожен лічильник розміщується у власній незалежній кеш-лінії
    alignas(std::hardware_destructive_interference_size) std::atomic<uint64_t> writes{0};
    alignas(std::hardware_destructive_interference_size) std::atomic<uint64_t> reads{0};
};
```

## Розміщувальний new та розміщувальний delete

Спеціальні неалокуючі форми операторів `operator new` та `operator delete` оголошені в стандартному заголовку `<new>`. Їхня задача — надати мовний механізм виклику конструктора на заданій адресі без звернення до купового алокатора.

### Сигнатури стандартних функцій

```cpp
#include <new>

// 1. Для одиничного об'єкта
void* operator new(std::size_t size, void* ptr) noexcept;

// 2. Для масиву об'єктів
void* operator new[](std::size_t size, void* ptr) noexcept;

// 3. Відповідні розміщувальні оператори delete
void operator delete(void* ptr, void* place) noexcept;
void operator delete[](void* ptr, void* place) noexcept;
```

### Реалізація та семантика

Реалізація стандартного розміщувального `operator new` у рантаймі є тривіальною:

```cpp
void* operator new(std::size_t, void* ptr) noexcept {
    return ptr; // не виконує жодного виділення пам'яті
}
```

Вираз розміщувального new `new (ptr) T(args...)` виконує два послідовні кроки:
1. Кличе функцію `operator new(sizeof(T), ptr)`, яка просто повертає `ptr`.
2. Компілятор генерує прямий виклик конструктора `T::T(args...)`, передаючи повернутий вказівник як неявний `this`.

### Семантика розміщувального delete

Розміщувальний оператор `operator delete(void* ptr, void* place)` **ніколи не викликається користувачем вручну**. Вираз на зразок `delete (ptr) p;` є синтаксично некоректним і не компілюється.

Єдине призначення розміщувального `operator delete` — це **автоматична аварійна обробка винятків у конструкторі**. Якщо під час виконання виразу:
```cpp
T* obj = new (storage_ptr) T(arg1, arg2);
```
конструктор `T::T` кидає виняток, середовище виконання автоматично шукає парний оператор видалення `operator delete(void*, void*)` і викликає його перед тим, як виняток полетить далі по стеку. Оскільки оператор є пустим, пам'ять не пошкоджується. Якби відповідного розміщувального `operator delete` не існувало, компілятор видавав би помилку або попередження про неможливість парного відкату.

## Відмивання вказівників: std::launder (C++17)

При повторному використанні буфера пам'яті (коли старий об'єкт знищено деструктором, а на його місці через розміщувальний new створено новий об'єкт) оптимізатор компілятора спирається на правила псевдонімів типу (Type-Based Alias Analysis) та припущення незмінності `const`-даних.

Якщо об'єкт містить константні поля (`const`) або поля-посилання, компілятор має право кешувати значення цих полів у регістрах процесора на весь час видимості старого вказівника. Створення нового об'єкта за тією самою адресою призводить до ситуації, коли старий вказівник читає застаріле константне значення з регістра, ігноруючи нові байти в пам'яті.

Функція `std::launder` із заголовка `<new>` розриває оптимізаційні ланцюжки компілятора та змушує його заново перечитати дійсний стан пам'яті.

### Сигнатура

```cpp
#include <new>

template<typename T>
[[nodiscard]] constexpr T* launder(T* ptr) noexcept;
```

### Правила застосування std::launder

`std::launder(ptr)` необхідний у трьох випадках, якщо новий об'єкт побудовано на місці старого:
1. Клас має хоча б один нестатичний член із модифікатором `const`.
2. Клас має хоча б один нестатичний член, що є посиланням (`T&`).
3. Новий об'єкт має інший динамічний тип або створений усередині поліморфної ієрархії без оновлення оригінального покажчика.

```cpp
#include <new>
#include <cstdint>

struct ImmutableConfig {
    const int port;
    const char protocol;
};

void update_storage(ImmutableConfig* cfg) {
    // 1. Завершуємо час життя старого об'єкта
    cfg->~ImmutableConfig();
    
    // 2. Створюємо новий об'єкт на тому самому місці з новими const-значеннями
    ImmutableConfig* new_cfg = new (cfg) ImmutableConfig{8080, 'U'};
    
    // ПРЯМЕ використання старого cfg->port — це UB, бо компілятор пам'ятає старий const int
    // Правильний доступ:
    ImmutableConfig* valid_ptr = std::launder(cfg);
    // Тепер valid_ptr->port гарантовано поверне 8080
}
```
