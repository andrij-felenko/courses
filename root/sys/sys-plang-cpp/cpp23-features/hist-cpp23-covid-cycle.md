# 📜 Історія стандарту C++23: пандемічний цикл WG21 і порятунок ядра мови

Розуміння обставин створення стандарту C++23 (офіційно опублікованого ISO як ISO/IEC 14882:2024) необхідне кожному системному інженеру, оскільки саме надзвичайні умови 2020–2023 років визначили характер релізу: перехід від гігантських мовних експериментів до точкового ремонту найболючіших місць синтаксису ядра та масивного доповнення стандартної бібліотеки STL.

У лютому 2020 року на пленарному засіданні комітету ISO/IEC JTC1/SC22/WG21 у Празі було тріумфально завершено роботу над C++20 — наймасштабнішим оновленням мови за попереднє десятиліття, яке принесло концептуальні революції: концептури, модулі, корутини та діапазони (Ranges). Делегати роз'їжджалися з Праги з амбітним планом на наступний трирічний цикл C++23. У центрі уваги стояли фундаментальні розширення: повноцінна статична рефлексія (Static Reflection), синтаксис контрактного програмування (Contracts), зіставлення зі зразком (Pattern Matching) та асинхронна архітектура виконання на основі відправників та отримувачів (Senders/Receivers, std::execution).

Однак уже за три тижні після празького засідання світ охопила пандемія COVID-19. Міжнародні подорожі припинилися, а всі заплановані очні засідання WG21 — у Варні, Нью-Йорку, Коні й далі за календарем — було скасовано. Комітет опинився перед загрозою повної зупинки стандартизаційного процесу.

## Криза пропускної здатності віртуальних зустрічей

Очна зустріч комітету WG21 — це тижневий марафон, де 250–300 фахівців працюють одночасно в десятці паралельних залів з 8:30 до 22:00, проводячи неформальні вечірні обговорення в коридорах і готельних лобі. Саме під час таких неформальних переговорів зазвичай узгоджувалися компроміси між авторами конкуруючих пропозицій і знімалися блокуючі заперечення національних делегацій.

Перехід у дистанційний режим Zoom-конференцій продемонстрував жорсткі фізичні та когнітивні обмеження:

1. **Проблема часових поясів:** Учасники комітету перебували в діапазоні від Токіо (UTC+9) і Сіднея (UTC+10) до Каліфорнії (UTC-8). Віртуальні зустрічі доводилося обмежувати вузькими сесіями по 2–3 години, що зменшило ефективний час колективного обговорення в 6–8 разів порівняно з очними тижнями.
2. **Неможливість консенсусу щодо складних концепцій:** Масштабні пропозиції, такі як контракти чи рефлексія, вимагали глибокого багатогодинного консенсусного аналізу десятків взаємопов'язаних крайових випадків. У форматі віртуальних дзвінків на 80+ учасників дискусії тонули в монологах і не приводили до узгоджених рішень.
3. **Психологічна втома:** Зустрічі на вихідних та у пізні нічні години призвели до вигорання ключових редакторів стандарту та авторів паперів.

У червні 2020 року керівництво WG21 ухвалило стратегічне рішення щодо тріажу (англ. *triage* — медичне сортування поранених). Було оголошено принцип: **«Завершити те, що розпочато в C++20, полагодити ядро мови й наповнити STL готовими компонентами»**. Усі експериментальні мовні монстри (рефлексія, контракти, pattern matching, networking на базі ASIO) були офіційно відкладені до циклу C++26.

## Боротьба за Deducing this: порятунок синтаксису методів

Головним проривом ядра мови в C++23 стала пропозиція **P0847 (Deducing this)**, підготовлена авторським колективом у складі Ґашпера Ажмана (Gašper Ažman), Сая Бренда (Sy Brand), Бена Діна (Ben Deane) та Баррі Ревзіна (Barry Revzin).

Ідея явного зазначення параметра об'єкта обговорювалася в комітеті ще з 2017 року, однак саме в пандемійний період вона стала критично важливою. Автори мови зіткнулися з проблемою: розвиток C++20 Ranges вимагав написання адаптерів і представлень, методи яких (`operator[]`, `begin()`, `front()`) потребували чотирьох майже ідентичних перевантажень для збереження семантики константності та lvalue/rvalue посилань:

```cpp
// Класичне пекло дублювання до C++23
struct Container {
    auto& operator[](size_t i) &       { return data_[i]; }
    const auto& operator[](size_t i) const& { return data_[i]; }
    auto&& operator[](size_t i) &&      { return std::move(data_[i]); }
    const auto&& operator[](size_t i) const&& { return std::move(data_[i]); }
private:
    std::vector<int> data_;
};
```

Це дублювання призводило до роздування кодової бази стандартної бібліотеки, збільшувало час парсингу та створювало ґрунт для помилок, коли одне з чотирьох перевантажень забували або реалізовували неточно. Крім того, шаблонний патерн CRTP (Curiously Recurring Template Pattern), винайдений Джеймсом Копліном (James Coplien) у 1995 році, змушував розробників використовувати складне шаблонне успадкування та небезпечний `static_cast<Derived*>(this)` для досягнення статичного поліморфізму.

У дистанційних сесіях робочої групи з еволюції мови (EWG) навколо Deducing this точилися гострі дискусії щодо синтаксису: чи використовувати ключове слово `this` як специфікатор першого параметра (`this Self&& self`), чи запроваджувати новий синтаксичний маркер. Перемогла пропозиція `this Type name`, оскільки вона не вводила нових ключових слів, була абсолютно однозначною для парсера і природно розширювала правила виведення типів функціональних шаблонів на нестатичні функції-члени. У лютому 2022 року папір P0847R7 було остаточно прийнято до робочої чернетки стандарту.

## Восьмирічний шлях std::mdspan: спадщина національних лабораторій

Якщо Deducing this став головною мовною інновацією, то головною архітектурною подією стандартної бібліотеки стало прийняття **`std::mdspan` (папір P0009)**.

Історія цього компонента розпочалася задовго до C++23 — у 2014 році, коли дослідники Ліверморської національної лабораторії Лоуренса (LLNL) та Національних лабораторій Сандія (Sandia National Laboratories) на чолі з Крістіаном Троттом (Christian Trott), Девідом Голлманом (David Hollman) та Марком Гогером (Mark Hoemmen) розробляли бібліотеку Kokkos для високопродуктивних суперкомп'ютерних обчислень.

Сучасні суперкомп'ютерні симуляції (квантова хромодинаміка, гідродинаміка, астрофізика) оперують багатовимірними тензорами на гетерогенних прискорювачах (GPU NVIDIA, AMD, Intel). У мовах C і C++ не існувало стандартного способу передати у функцію 3D- чи 4D-матрицю без втрати інформації про розмірність або без прихованих витрат на покажчики другого порядку (`double**`).

Розробка `std::mdspan` пройшла через 18 ревізій паперу P0009. Ключовою інженерною знахідкою авторів став розподіл обов'язків на три ортогональні політики:
- **`extents`** — статичні або динамічні розміри вимірів тензора;
- **`layout_mapping`** — математичний закон перетворення багатовимірного індексу `(i, j, k)` у лінійне зміщення в пам'яті (C-порядок `layout_right`, Fortran-порядок `layout_left` або довільний крок `layout_stride`);
- **`accessor`** — спосіб безпосереднього розіменування покажчика (що дозволяє працювати з атомною пам'яттю, пам'яттю графічного процесора чи блоками з обмеженим доступом).

Завдяки відокремленню виду від володіння пам'яттю, `std::mdspan` став нульовою за накладними витратами абстракцією, яку суперкомп'ютерний комерційний сектор очікував майже десятиліття.

## std::expected: завершення десятилітньої саги обробки помилок

Папір **P0323 (`std::expected`)**, поданий Вісенте Боті (Vicente J. Botet Escriba) та Саєм Брендом (Sy Brand), пройшов шлях тривалістю понад вісім років — перші варіанти обговорювалися ще під час формування C++14 у 2013 році під впливом типів `Result` у Rust та `Either` у Haskell.

Головним каменем спотикання у комітеті були філософські суперечки між двома таборами:
1. **Прихильники традиційних винятків (Exceptions):** Стверджували, що винятки є канонічним механізмом C++, а впровадження типу помилки як значення розколе екосистему на два несумісні стилі програмування.
2. **Практики систем реального часу та ембеддед-розробки:** Вказували на те, що в ігрових рушіях, ядрах ОС, аерокосмічній техніці та фінансових торгових системах винятки заборонені прапорцем `-fno-exceptions` через непередбачуваність часу розкручування стека (stack unwinding) і накладні витрати на таблиці винятків (DWARF `.eh_frame`).

У пандемійний період компроміс було досягнуто: `std::expected` було стандартизовано не як повну заміну винятків, а як словниковий тип для **очікуваних, відновлюваних збоїв бізнес-логіки** (невірний формат вхідного файлу, мережевий таймаут, відхилений парсинг). Додавання монадичних методів (`and_then`, `transform`, `or_else`) для `std::optional` (папір P0798) та `std::expected` перетворило C++23 на потужну платформу функціонального конвеєрного програмування.

## std::print та std::generator: швидкість і лінивість

Двома фінальними подарунками стандартної бібліотеки стали:
- **`std::print` / `std::println` (папір P2093, Віктор Звєрович / Victor Zverovich):** Робота над заміною архаїчного `std::cout` розпочалася у C++20 з бібліотеки `std::format`. Проте `std::format` лише створював рядок у пам'яті, залишаючи операцію виводу на повільний `std::cout`, що супроводжувалося викликами локалей, блокуваннями потоків та зайвими алокаціями. Папір P2093 інтегрував прямий системний вивід у термінал через POSIX `write()` та Windows Unicode Console API, забезпечивши типобезпеку, що перевершує `printf`, при меншому часі виконання.
- **`std::generator` (папір P2502, Кейсі Картер, Льюїс Бейкер, Корентен Жабо):** У C++20 було стандартизовано корутини, проте комітет не надав жодного готового корутинного типу в STL, змушуючи кожного інженера власноруч писати 100+ рядків обв'язки `promise_type`. `std::generator` заповнив цю прогалину, забезпечивши безшовну взаємодію корутин із конвеєрами `std::ranges`.

## Фінал: затвердження в Коні та публікація ISO/IEC 14882:2024

У листопаді 2022 року на засіданні в місті Коні (Кона, Гаваї, США) комітет WG21 провів першу за три роки очну сесію. На цій зустрічі було остаточно зафіксовано текст чернетки Committee Draft (CD) та оголошено мораторій на нові функції (Feature Freeze).

Протягом 2023 року відбувалися процедури офіційного балотування національних комітетів ISO (DIS Ballot), виправлення редакторських неточностей та узгодження фінального тексту нормативного стандарту. У жовтні 2024 року Міжнародна організація зі стандартизації офіційно опублікувала підсумковий документ під назвою **ISO/IEC 14882:2024 Information technology — Programming languages — C++**.

Стандарт C++23 увійшов в історію як зразок інженерної зрілості та прагматизму. Попри глобальні потрясіння та повну зміну робочого формату, комітет зміг усунути системні недоліки попередніх стандартів, зробити мову значно приємнішою для щоденного використання та підготувати міцний фундамент для наступного великого стрибка — C++26.
