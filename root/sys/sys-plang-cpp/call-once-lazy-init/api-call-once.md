# 📋 Довідник API: std::call_once та std::once_flag

У стандартній бібліотеці C++ заголовок `<mutex>` визначає структуру стану `std::once_flag` та шаблонну функцію `std::call_once`. Разом вони утворюють стандартний високоефективний інтерфейс для гарантовано одноразового, потокобезпечного виконання довільних функціональних об'єктів у багатопотоковому середовищі.

Цей довідник містить вичерпну технічну специфікацію типів, сигнатур, вимог до параметрів шаблонів, правил перенаправлення аргументів, гарантій виняткової безпеки та відношень впорядкування пам'яті відповідно до стандартів ISO/IEC 14882 (C++11, C++14, C++17, C++20 та C++23).

---

## 1. Специфікація структури std::once_flag

Тип `std::once_flag` є непрозорим об'єктом синхронізації (англ. *synchronization token*), який інкапсулює внутрішній стан процесу ініціалізації асоційованого ресурсу.

### Формальне оголошення типу:

```cpp
namespace std {
    struct once_flag {
        // Конструктор за замовчуванням (constexpr)
        constexpr once_flag() noexcept;

        // Копіювання суворо заборонено
        once_flag(const once_flag&) = delete;
        once_flag& operator=(const once_flag&) = delete;

        // Переміщення суворо заборонено
        once_flag(once_flag&&) = delete;
        once_flag& operator=(once_flag&&) = delete;

        // Тривіальний деструктор
        ~once_flag() = default;
    };
}
```

### Детальний опис спеціальних методів-членів:

1. **`constexpr once_flag() noexcept`**:
   - Ініціалізує об'єкт прапорця у вихідному неініціалізованому стані.
   - Позначений як `constexpr`, що гарантує виконання нульової (статичної) ініціалізації для об'єктів зі статичною або просторовою тривалістю життя (Static/Thread Storage Duration) ще на етапі компіляції або завантаження двійкового модуля.
   - Це запобігає виникненню невизначеного порядку глобальної ініціалізації (Static Initialization Order Fiasco) до запуску функції `main()`.

2. **Видалені конструктори та оператори копіювання/переміщення (`= delete`)**:
   - Об'єкт `std::once_flag` фізично прив'язаний до своєї адреси в оперативній пам'яті.
   - Спроба скопіювати або перемістити прапорець порушила б роботу внутрішніх атомарних вказівників, черг очікування ядра операційної системи (futex) та унеможливила б узгодженість стану між різними нитками виконання.

3. **`~once_flag() = default`**:
   - Деструктор є тривіальним. Він не здійснює виділення або звільнення динамічної пам'яті на купі.
   - **Увага**: знищення об'єкта `std::once_flag`, поки інший потік все ще виконує `std::call_once` з цим прапорцем, є невизначеною поведінкою (Undefined Behavior). Час життя прапорця повинен строго перекривати час життя всіх операцій, що його використовують.

### Розміщення у пам'яті та тривалість життя:

| Спосіб розміщення | Приклад оголошення | Опис поведінки та рекомендації |
| :--- | :--- | :--- |
| **Static / Global** | `static std::once_flag g_flag;` | Живе протягом усього часу роботи процесу. Використовується для глобальних сервісів, логерів, реєстрів драйверів. |
| **Member (Поле класу)** | `class Client { std::once_flag init_flag_; };` | Живе разом із конкретним екземпляром класу. Забезпечує незалежну ліниву ініціалізацію для кожного створеного об'єкта. |
| **Local Static** | `void fn() { static std::once_flag local_flag; }` | Ініціалізується при першому проході. Дозволяє інкапсулювати одноразову логіку всередині конкретної функції. |
| **Dynamic (На купі)** | `auto p = std::make_unique<Resource>();` | Створюється динамічно у складі складних структур даних. Знищується разом із батьківським контейнером. |
| **Automatic (На стеку)** | `void fn() { std::once_flag stack_flag; }` | ⚠️ **Антипатерн**: локальний прапорець знищується при виході з функції, призводячи до повторної ініціалізації щоразу! |

## 2. Специфікація функції std::call_once

Шаблонна функція `std::call_once` координує одноразове виконання переданого функціонального об'єкта через спільний прапорець `std::once_flag`.

### Сигнатура шаблону (C++11 / C++14 / C++17 / C++20):

```cpp
template<class Callable, class... Args>
void call_once(std::once_flag& flag, Callable&& f, Args&&... args);
```

### Концептуальні обмеження типів (C++20 Concepts):

```cpp
template<class Callable, class... Args>
requires std::invocable<std::decay_t<Callable>, std::decay_t<Args>...>
void call_once(std::once_flag& flag, Callable&& f, Args&&... args);
```

### Опис параметрів:
- **`flag` (`std::once_flag&`)**: посилання на екземпляр прапорця, що координує синхронізацію.
  - Якщо один і той самий об'єкт `flag` передається у кілька різних викликів `call_once` із **різними** функціями `f1`, `f2`, `f3`, виконана буде **лише одна** функція — та, виклик якої першим успішно завершиться без винятку.
  - Усі наступні виклики з іншими функціями, але тим самим прапорцем, просто проігнорують свої аргументи і миттєво повернуть керування.
- **`f` (`Callable&&`)**: цільовий функціональний об'єкт. Може бути звичайною функцією, покажчиком на функцію, лямбда-виразом, функтором або покажчиком на метод/поле класу.
- **`args...` (`Args&&...`)**: список аргументів, які передаються у викликану функцію `f`.

### Повертане значення:
`void` — функція нічого не повертає. Результати ініціалізації передаються через захоплення за посиланням у лямбдах, мутацію стану об'єкта або збереження даних у спільних вказівниках.

## 3. Семантика виклику та правила передачі аргументів

Виклик цільового об'єкта всередині `std::call_once` здійснюється за правилами узагальненого виклику `std::invoke` (C++17) або його семантичного еквівалента:

```
INVOKE(decay_copy(std::forward<Callable>(f)), decay_copy(std::forward<Args>(args))...)
```

### 1. Механізм Decay-Copy (Копіювання зі згасанням типів)
Стандарт вимагає, щоб функція `f` та всі її аргументи `args...` були спершу скопійовані або переміщені у внутрішній буфер виклику (англ. *decay-copied*).
- Масиви перетворюються на вказівники на перший елемент (`T[]` → `T*`).
- Функції перетворюються на вказівники на функції (`void()` → `void(*)()`).
- Посилання та константність верхнього рівня відкидаються (`const int&` → `int`).

### 2. Передача аргументів за неконстантним посиланням (`T&`)
Через механізм *decay-copy* пряма передача змінної у функцію, яка очікує неконстантне посилання, призведе до помилки компіляції (компілятор намагатиметься зв'язати rvalue тимчасового об'єкта з lvalue-посиланням) або до модифікації тимчасової копії.

Щоб передати справжнє посилання на зовнішній об'єкт, необхідно явно використовувати обгортку `std::ref` або `std::cref`:

```cpp
#include <mutex>
#include <functional>
#include <string>
#include <vector>

void fill_hardware_ids(std::vector<int>& ids, std::string& status) {
    ids.push_back(101);
    ids.push_back(102);
    status = "READY";
}

void configure(std::once_flag& flag, std::vector<int>& out_ids, std::string& out_status) {
    // ❌ Помилка: std::call_once(flag, fill_hardware_ids, out_ids, out_status);
    
    // ✅ Правильно: загортаємо в std::ref
    std::call_once(flag, fill_hardware_ids, std::ref(out_ids), std::ref(out_status));
}
```

### 3. Передача об'єктів лише для переміщення (Move-Only Types)
Аргументи, які підтримують лише семантику переміщення (наприклад, `std::unique_ptr`), передаються за допомогою `std::move`:

```cpp
#include <mutex>
#include <memory>

struct SessionContext {
    int auth_level;
};

void setup_session(std::unique_ptr<SessionContext> ctx) {
    // Володіння контекстом переходить сюди
}

void initialize(std::once_flag& flag, std::unique_ptr<SessionContext> ctx) {
    std::call_once(flag, setup_session, std::move(ctx));
}
```

### 4. Виклик методів класу
Якщо першим аргументом передається покажчик на метод класу, другим аргументом обов'язково повинен бути вказівник або посилання на об'єкт, для якого цей метод викликається:

```cpp
struct NetworkSocket {
    std::once_flag open_flag_;

    void open_connection(const std::string& ip, int port);

    void connect() {
        std::call_once(open_flag_, &NetworkSocket::open_connection, this, "192.168.1.1", 8080);
    }
};
```

## 4. Гарантії безпеки винятків (Exception Guarantees)

Робота `std::call_once` базується на суворій моделі виняткової безпеки:

1. **Транзакційне скидання стану**:
   - Якщо виконання функції `f` завершується викиданням винятку, стан `std::once_flag` **не фіксується як завершений (Done)**.
   - Внутрішній стан прапорця повертається у вихідний стан неініціалізованості.
2. **Прокидання винятку**:
   - Виняток перехоплюється механізмом `call_once`, стек розгортається (деструктори локальних об'єктів гарантовано викликаються), і виняток ретранслюється назовні у потік, що виконував ініціалізацію.
3. **Пробудження та вибір нового лідера**:
   - Усі інші нитки, заблоковані в очікуванні на цьому прапорці, розблоковуються.
   - Один із розблокованих потоків (або наступний потік, що викличе `std::call_once`) обирається як новий лідер і виконує свою функцію ініціалізації.
4. **Виняток `std::system_error`**:
   - Якщо операційна система не може виділити ресурси синхронізації або фіксує внутрішній збій ядра (наприклад, помилку системного виклику `futex`), `std::call_once` генерує виняток типу `std::system_error`.
5. **Рекурсивне звернення (Deadlock)**:
   - Якщо функція `f` всередині свого тіла повторно викликає `std::call_once` з тим самим об'єктом `once_flag`, це призводить до взаємного блокування (Deadlock). Сучасні реалізації стандартної бібліотеки виявляють такий рекурсивний виклик у тому самому потоці і генерують `std::system_error` з кодом `std::errc::resource_deadlock_would_occur`.

## 5. Впорядкування пам'яті та формальні гарантії (Happens-Before)

Специфікація ISO/IEC 14882 §33.4.6.3 встановлює точний контракт синхронізації пам'яті:

- Усі операції запису в пам'ять (Side Effects), здійснені всередині функції `f` потоком-лідером, синхронізуються за семантикою **Release** перед успішним завершенням виклику `call_once`.
- Будь-яке повернення з `std::call_once` у будь-якому іншому потоці виконує зчитування прапорця за семантикою **Acquire**.
- **Наслідок**: успішне виконання `f` **happens-before** («відбувається раніше, ніж») повернення з будь-якого виклику `call_once` із цим самим прапорцем. Це гарантує повну безпеку читання ініціалізованого об'єкта без необхідності встановлення явних бар'єрів пам'яті або захоплення додаткових замків.

## 6. Порівняльна таблиця примітивів одноразової ініціалізації

| Характеристика | `std::call_once` (C++11) | `pthread_once` (POSIX C) | `InitOnceExecuteOnce` (Win32) | `call_once` (C11 `<threads.h>`) |
| :--- | :--- | :--- | :--- | :--- |
| **Заголовний файл** | `<mutex>` | `<pthread.h>` | `<windows.h>` | `<threads.h>` |
| **Тип прапорця** | `std::once_flag` | `pthread_once_t` | `INIT_ONCE` | `once_flag` |
| **Ініціалізатор прапорця** | `constexpr` конструктор | `PTHREAD_ONCE_INIT` | `INIT_ONCE_STATIC_INIT` | `ONCE_FLAG_INIT` |
| **Сигнатура функції** | Довільний `Callable` | `void (*)(void)` | `BOOL (CALLBACK*)(...)` | `void (*)(void)` |
| **Передача контексту** | Лямбди, захоплення, аргументи | Тільки глобальні змінні | Через параметр `PVOID` | Тільки глобальні змінні |
| **Обробка C++ винятків** | Повне скидання стану | Undefined Behavior | Через повернення `FALSE` | Відсутня (мова C) |
| **Швидкий шлях (Fast Path)** | 1 атомарний Acquire-load | Залежить від libc | Interlocked-біт у користувачі | 1 атомарний Acquire-load |
| **Використання в класах** | Звичайне поле екземпляра | Складно (немає `this`) | Потребує ручного касту `PVOID` | Складно (немає класів) |

## 7. Приклади використання для типових сценаріїв

:::tabs
```cpp
#include <mutex>
#include <iostream>
#include <string>
#include <vector>
#include <memory>

class HardwareSensorCluster {
private:
    struct CalibrationProfile {
        std::vector<double> gains;
        std::string firmware_version;
    };

    std::unique_ptr<CalibrationProfile> profile_;
    std::once_flag calibration_flag_;

    void load_profile_from_eeprom(const std::string& chip_serial) {
        std::cout << "Зчитування калібрувального профілю для чіпа " << chip_serial << "...\n";
        auto p = std::make_unique<CalibrationProfile>();
        p->gains = {1.024, 0.998, 1.005};
        p->firmware_version = "v2.4.1";
        profile_ = std::move(p);
    }

public:
    HardwareSensorCluster() = default;

    void read_sensor(int channel) {
        // Лінива ініціалізація з передачею методу та аргументів
        std::call_once(calibration_flag_, &HardwareSensorCluster::load_profile_from_eeprom, 
                       this, "CHIP-XYZ-9876");

        std::cout << "Канал " << channel << " з коефіцієнтом: " 
                  << profile_->gains[channel % profile_->gains.size()] << "\n";
    }
};
```
```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    double gains[3];
    char firmware_version[16];
} CalibrationProfileC;

static CalibrationProfileC* g_profile = NULL;
static pthread_once_t g_calib_flag = PTHREAD_ONCE_INIT;

static void load_profile_eeprom_c(void) {
    printf("Зчитування калібрувального профілю (POSIX C)...\n");
    g_profile = (CalibrationProfileC*)malloc(sizeof(CalibrationProfileC));
    if (g_profile) {
        g_profile->gains[0] = 1.024;
        g_profile->gains[1] = 0.998;
        g_profile->gains[2] = 1.005;
        strncpy(g_profile->firmware_version, "v2.4.1", 15);
    }
}

void read_sensor_c(int channel) {
    pthread_once(&g_calib_flag, load_profile_eeprom_c);
    if (g_profile) {
        printf("Канал %d з коефіцієнтом: %f\n", channel, g_profile->gains[channel % 3]);
    }
}
```
