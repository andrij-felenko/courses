# 📋 Довідник API std::optional: сигнатури, методи та гарантії

Інтерфейс `std::optional<T>` надає строгий контракт управління опціональним станом без динамічної пам'яті, де кожна операція має чіткі гарантії винятків, складності та тривіальності. Цей довідник систематизує повну поверхню API типу `std::optional`, його допоміжні класи, конструктори, модифікатори, оператори розгортання, монадичні операції C++23 та специфічні метапрограмувальні трейти.

## Вкладені типи, маркер порожнечі та допоміжні структури

Шаблон `std::optional<T>` визначено в заголовочному файлі `<optional>` у просторі назв `std`. Тип `T` мусить задовольняти базовим вимогам `Destructible` (тобто мати доступний та коректний деструктор). Стандарт забороняє створювати `std::optional` для масивів, типів `std::nullopt_t` та `std::in_place_t`. До стандарту C++26 спеціалізація `std::optional<T&>` є некоректною і викликає помилку компіляції під час аналізу `static_assert`, оскільки семантика присвоєння для посилань виникає з фундаментального розходження між перезв'язуванням посилання та модифікацією цільового об'єкта.

```cpp
namespace std {
    // Основний шаблон класу
    template <class T>
    class optional;

    // Маркер порожнього стану
    struct nullopt_t {
        explicit constexpr nullopt_t(int) {}
    };
    inline constexpr nullopt_t nullopt{0};

    // Виняток при некоректному доступі
    class bad_optional_access : public std::exception {
    public:
        bad_optional_access() noexcept;
        virtual const char* what() const noexcept override;
    };
}
```

Конструкція `std::nullopt_t` розроблена як унікальний теговий тип, що не дозволяє неплідне неявне зведення з типів `nullptr_t` або звичайних цілочисельних нулів. Передача `std::nullopt` у будь-яку функцію, яка приймає `std::optional<T>`, явно сигналізує про створення або скидання об'єкта до порожнього стану. Виняток `std::bad_optional_access` успадковується безпосередньо від `std::exception` і кидається лише при виклику методу `.value()` над об'єктом, у якого прапорець `has_value()` дорівнює `false`.

## Конструктори та деструктор: механіка ініціалізації та тривіальність

Конструктори `std::optional` розроблені так, щоб гарантувати ліниву ініціалізацію та збереження тривіальності операцій, якщо вихідний тип `T` підтримує тривіальні спецчлени. Це дозволяє компілятору оптимізувати передачу `std::optional<T>` через процесорні регістри за аналогією до простих C-структур.

| Сигнатура конструктора | Опис механізму | Гарантія винятків | Складність |
| :--- | :--- | :--- | :--- |
| `constexpr optional() noexcept;` | Створює порожній `optional` (`has_value() == false`). Конструктор `T` не викликається. | `noexcept` | `O(1)` |
| `constexpr optional(nullopt_t) noexcept;` | Еквівалент конструктора за замовчуванням. Створює порожній стан. | `noexcept` | `O(1)` |
| `constexpr optional(const optional& rhs);` | Копіює `rhs`. Якщо `rhs.has_value()`, виконується placement new копіювання `T(*rhs)`. | Залежить від `T(const T&)` | `O(1)` |
| `constexpr optional(optional&& rhs) noexcept(...);` | Переміщує `rhs`. Якщо `rhs.has_value()`, виконується placement new `T(std::move(*rhs))`. | `noexcept(is_nothrow_move_constructible_v<T>)` | `O(1)` |
| `constexpr optional(const T& value);` | Створює заповнений `optional`, копіюючи `value` у внутрішній буфер. | Залежить від `T(const T&)` | `O(1)` |
| `constexpr optional(T&& value);` | Створює заповнений `optional`, переміщуючи `value` у внутрішній буфер. | `noexcept(is_nothrow_move_constructible_v<T>)` | `O(1)` |
| `template<class... Args><br>explicit constexpr optional(in_place_t, Args&&... args);` | Конструює об'єкт `T` безпосередньо у внутрішньому буфері, передаючи `args...`. | Залежить від `T(Args...)` | `O(1)` |
| `template<class U, class... Args><br>explicit constexpr optional(in_place_t, initializer_list<U> il, Args&&... args);` | Конструює об'єкт `T` у внутрішньому буфері з `initializer_list`. | Залежить від `T(il, Args...)` | `O(1)` |
| `~optional();` | Якщо `has_value() == true`, викликає деструктор `val.~T()`. Якщо `T` тривіальний, деструктор є тривіальним `default`. | `noexcept` | `O(1)` |

При використанні конструктора `optional(const optional& rhs)` відбувається умовна ініціалізація: якщо об'єкт `rhs` був порожнім, новий об'єкт також створюється порожнім без виклику будь-яких методів `T`. Якщо ж `rhs` був заповнений, новий об'єкт викликає конструктор копіювання `T::T(const T&)` через розміщувальний виклик `placement new` безпосередньо у внутрішньому буфері `storage`.

Окремо слід виділити гарантію семантики переміщення. Переміщення `std::optional` (наприклад, виклики `optional(optional&& rhs)` або `rhs = std::move(lhs)`) **НЕ робить джерело `rhs` порожнім**. Об'єкт-джерело `rhs` залишається заповненим (`has_value() == true`), проте усередині нього міститься екземпляр `T`, який перебуває у правомірному, але невизначеному стані після переміщення (moved-from state). Це відповідає загальним правилам семантики переміщення у C++: переміщення змінює вміст ресурсу, але не змінює стан самого контейнера. Щоб скинути джерело у порожній стан, необхідно явно викликати `rhs.reset()` або виконувати присвоєння `rhs = std::nullopt`.

Тег `std::in_place` є критично важливим для продуктивності інструментом. Без `std::in_place` виклик `std::optional<BigType> opt(BigType(a, b, c))` змушений спочатку сконструювати тимчасовий об'єкт `BigType` на стеку, а потім перемістити його у буфер `optional`. Використання конструктора `std::optional<BigType> opt(std::in_place, a, b, c)` передає аргументи `a, b, c` через ідеальне передавання (`std::forward`) безпосередньо конструктору `BigType` усередині внутрішньої пам'яті `optional`, повністю усуваючи створення тимчасових об'єктів.

## Методи спостереження та перевірки стану: гарантії продуктивності та винятків

Для перевірки наявності значення та доступу до нього `std::optional` надає розробнику два фундаментально різних сімейства методів: захищені (з перевіркою стану) та незахищені (з нульовими накладними витратами).

```cpp
// 1. Перевірка наявності значення
constexpr bool has_value() const noexcept;
constexpr explicit operator bool() const noexcept;

// 2. Розгортання без перевірки (Unchecked Access — швидкий доступ, O(1), noexcept)
constexpr const T& operator*() const& noexcept;
constexpr T& operator*() & noexcept;
constexpr const T&& operator*() const&& noexcept;
constexpr T&& operator*() && noexcept;

constexpr const T* operator->() const noexcept;
constexpr T* operator->() noexcept;

// 3. Розгортання з перевіркою (Checked Access — кидає bad_optional_access)
constexpr const T& value() const&;
constexpr T& value() &;
constexpr const T&& value() const&&;
constexpr T&& value() &&;

// 4. Безпечне розгортання із дефолтом
template <class U>
constexpr T value_or(U&& default_value) const&;

template <class U>
constexpr T value_or(U&& default_value) &&;
```

### Детальний аналіз гарантій доступу

1. **Незахищене розгортання (`operator*` та `operator->`)**:
   Ці оператори розроблені для максимальної продуктивності у гарячих циклах та критичних до швидкості алгоритмах. Вони не здійснюють жодних перевірок прапорця `has_value()` і відмічені специфікатором `noexcept`. Компілятор транслює виклик `*opt` у звичайне розіменування адреси внутрішнього буфера `storage`, що займає нуль додаткових тактів процесора. Проте виклик `*opt` або `opt->field` над порожнім `std::optional` призводить до **неокресленої поведінки (Undefined Behavior)**, що може спричинити збій адресації (`Segmentation Fault`) або вичитування сміття з пам'яті. Використовувати незахищені оператори дозволяється лише після перевірки `if (opt.has_value())` або у контекстах, де відсутність значення виключена логікою програми.

2. **Захищене розгортання (`.value()`)**:
   Метод `.value()` перед поверненням посилання виконує явну умовну перевірку `if (!has_value())`. Якщо об'єкт виявляється порожнім, метод кидає виняток `std::bad_optional_access`. Це гарантує безпеку виконання на межах системних модулів або при обробці зовнішніх даних, де порожній стан є ознакою невалідного введення. Накладні витрати методу полягають у створенні однієї умовної гілки переходів у машинному коді та генерації таблиці розкрутки стека для винятку.

3. **Безумовна підстановка запасного значення (`.value_or()`)**:
   Метод `.value_or(default_value)` повертає значення внутрішнього об'єкта, якщо `has_value() == true`. Якщо об'єкт порожній, метод конструює та повертає екземпляр `T`, створений із переданого `default_value`. Метод перевантажений для lvalue та rvalue посилань: якщо сам `optional` є rvalue-об'єктом (`std::move(opt).value_or(...)`), його внутрішній вміст буде переміщено, а не скопійовано.

## Модифікатори стану та керування ресурсом

Модифікатори дозволяють динамічно змінювати стан `optional`, замінювати збережений об'єкт, повторно конструювати його на місці або повертати пам'ять у порожній стан.

```cpp
// Скидання стану у порожній (виклик деструктора T.~T() якщо заповнений)
void reset() noexcept;

// Конструювання об'єкта на місці (inplace construction)
template <class... Args>
T& emplace(Args&&... args);

template <class U, class... Args>
T& emplace(std::initializer_list<U> il, Args&&... args);

// Присвоєння
optional& operator=(nullopt_t) noexcept;
optional& operator=(const optional& rhs);
optional& operator=(optional&& rhs) noexcept(...);

template <class U = T>
optional& operator=(U&& rhs);

// Обмін вмістом
void swap(optional& rhs) noexcept(...);
```

Анатомія роботи модифікатора `emplace(args...)` є наступною: якщо `std::optional` на момент виклику вже містив заповнений об'єкт, метод спочатку викликає його деструктор `val.~T()`, знищуючи старий вміст. Після цього у тому ж самому внутрішньому буфері викликається placement new `::new (address) T(std::forward<Args>(args)...)`. Метод повертає посилання `T&` на новостворений об'єкт. Це гарантує, що адреса буфера усередині `optional` залишається незмінною, а нові ресурси конструюються без додаткових виділень пам'яті у купі.

Метод `reset()` переводить об'єкт у порожній стан (`has_value() == false`). Якщо об'єкт містив значення, виконується виклик деструктора `val.~T()`. Якщо тип `T` є тривіально деструктовним, прапорець просто скидається у `false`, а код деструктора повністю оптимізується компілятором.

Операція `swap(rhs)` має складну логіку для забезпечення максимальної безпеки винятків:
- Якщо обидва об'єкти заповнені, викликається нечленська функція `using std::swap; swap(**this, *rhs)`.
- Якщо один об'єкт заповнений, а інший порожній, заповнений об'єкт переміщується у буфер порожнього через конструктор переміщення, після чого заповнений об'єкт скидається через `reset()`.
- Якщо обидва об'єкти порожні, операція `swap` гарантовано не виконує жодних дій і завершується за `O(1)`.

## Монадичні операції C++23: специфікація та ланцюгові обчислення

Додані у стандарту C++23 (згідно з прийнятою пропозицією P0798R8), монадичні оператори дозволяють будувати декларативні конвеєри обробки без використання вкладених умовних гілок `if (opt.has_value())`.

```cpp
// 1. and_then: связує функції, що повертають std::optional<U>
template <class F>
constexpr auto and_then(F&& f) &;

template <class F>
constexpr auto and_then(F&& f) const&;

template <class F>
constexpr auto and_then(F&& f) &&;

template <class F>
constexpr auto and_then(F&& f) const&&;

// 2. transform: застосовує трансформацію T -> U та повертає std::optional<U>
template <class F>
constexpr auto transform(F&& f) &;

template <class F>
constexpr auto transform(F&& f) const&;

template <class F>
constexpr auto transform(F&& f) &&;

template <class F>
constexpr auto transform(F&& f) const&&;

// 3. or_else: надає альтернативне джерело std::optional<T>, якщо поточний порожній
template <class F>
constexpr optional or_else(F&& f) const&;

template <class F>
constexpr optional or_else(F&& f) &&;
```

### Формальна специфікація поведінки монадичних методів

1. **`and_then(f)` (операція monadic bind / flatMap)**:
   - Приймає функцію або лямбда-вираз `f`, який приймає вміст `T` (за посиланням або значенням) і повертає об'єкт типу `std::optional<U>` для деякого типу `U`.
   - Якщо поточний `optional` заповнений (`has_value() == true`), повертає результат безпосереднього виклику `std::invoke(std::forward<F>(f), **this)`.
   - Якщо поточний `optional` порожній (`has_value() == false`), обчислення функції `f` коротко замикається (не виконується), і метод миттєво повертає порожній `std::optional<U>(std::nullopt)`.

2. **`transform(f)` (операція monadic map)**:
   - Приймає функцію `f`, яка приймає вміст `T` і повертає звичайне значення типу `U` (де `U` не є `std::nullopt_t` або `std::in_place_t`).
   - Якщо поточний `optional` заповнений (`has_value() == true`), повертає новий заповнений об'єкт `std::optional<U>(std::in_place, std::invoke(std::forward<F>(f), **this))`.
   - Якщо поточний `optional` порожній, повертає порожній `std::optional<U>(std::nullopt)`.

3. **`or_else(f)` (операція відновлення / fallback)**:
   - Приймає функцію `f` без аргументів (`()`), яка повинна повертати об'єкт того ж типу `std::optional<T>`.
   - Якщо поточний `optional` заповнений, метод повертає поточний `*this` без виклику функції `f`.
   - Якщо поточний `optional` порожній, метод викликає `f()` і повертає її результат, дозволяючи спробувати альтернативне джерело даних або відновити стан після помилки.

## Операції порівняння та хешування

`std::optional` підтримує повний набір операторів порівняння (`==`, `!=`, `<`, `<=`, `>`, `>=`), забезпечуючи коректну роботу у відсортованих контейнерах `std::set` та `std::map`.

### Семантика порівняння

- При порівнянні двох `optional`: порожній об'єкт вважається **суворо меншим** за будь-який заповнений об'єкт. Два порожніх об'єкти вважаються рівними між собою (`nullopt == nullopt` завжди повертає `true`). Якщо обидва об'єкти заповнені, результат дорівнює порівнянню їхніх внутрішніх значень `*lhs op *rhs`.
- При порівнянні `optional` з `nullopt`: `opt == nullopt` дорівнює `!opt.has_value()`.
- При порівнянні `optional` зі значенням `T`: якщо `optional` заповнений, порівнюються `*opt op value`; якщо `optional` порожній, порівняння з `T` повертає `false` (за винятком `!=`).

### Хешування через std::hash

```cpp
namespace std {
    template <class T>
    struct hash<optional<T>> {
        size_t operator()(const optional<T>& opt) const {
            return opt.has_value() ? std::hash<T>{}(*opt) : 0;
        }
    };
}
```

Спеціалізація `std::hash<std::optional<T>>` є доступною тоді і тільки тоді, коли визначена спеціалізація `std::hash<remove_const_t<T>>`. Якщо `optional` є заповненим, його хеш-код дорівнює хешу збереженого значення `*opt`. Якщо `optional` є порожнім, його хеш-код дорівнює `0`. Це дозволяє безпосередньо використовувати `std::optional<T>` як ключі у хеш-таблицях `std::unordered_map` та `std::unordered_set`.
