# 📋 Матриця нововведень C++20: мовні конструкції, бібліотеки та макроси SD-6

Стандарт C++20 ввів розгалужену систему макросів тестування можливостей (Feature-testing macros) відповідно до рекомендацій ISO/IEC Standing Document 6 (SD-6), затвердив шістнадцять нових заголовків стандартної бібліотеки та встановив точні програмні інтерфейси для нових мовних механізмів, що забезпечує переносність коду між різними трансляторами.

На відміну від попередніх версій стандарту, де розробники змушені були визначати доступність мовних засобів за допомогою нестандартних препроцесорних директив перевірки версій компіляторів (таких як `__GNUC__`, `__clang_major__` або `_MSC_VER`), стандарт C++20 формалізував механізм гранулярної перевірки конкретних нововведень. Це дозволяє створювати кросплатформні кодові бази, які адаптивно використовують найновіші мовні та бібліотечні розширення на компіляторах із неповною або експериментальною підтримкою стандарту, зберігаючи працездатні резервні гілки реалізації для консервативних промислових середовищ.

## 1. Система макросів тестування мовних можливостей (SD-6)

Макроси перевірки мовних можливостей визначаються компілятором автоматично при увімкненні відповідного прапорця стандарту (`-std=c++20` для GCC і Clang, `/std:c++20` або `/std:c++latest` для MSVC). Значенням кожного макроса є ціле беззнакове число у форматі дати `РРРРММL`, що відповідає року та місяцю, коли відповідна робоча пропозиція була офіційно прийнята на пленарному засіданні комітету WG21.

Якщо транслятор не реалізував певну мовну конструкцію або реалізував її за старішою чорновою специфікацією, значення макроса або взагалі не визначається препроцесором, або містить старішу дату. Це забезпечує надійний механізм умовної компіляції без виникнення хибних спрацьовувань.

| Макрос | Значення C++20 | Опис підтримуваної можливості |
| :--- | :--- | :--- |
| `__cpp_concepts` | `201907L` | Концепти, вирази `requires`, обмеження шаблонів |
| `__cpp_modules` | `201907L` | Підтримка іменованих модулів (`export module`, `import`) |
| `__cpp_impl_coroutine` | `201902L` | Мовна підтримка корутин (`co_await`, `co_yield`, `co_return`) |
| `__cpp_impl_three_way_comparison` | `201907L` | Тристороннє порівняння (`operator<=>`) та переписані кандидати |
| `__cpp_consteval` | `201811L` | Негайні функції `consteval`, обчислювані виключно під час компіляції |
| `__cpp_constinit` | `201907L` | Гарантована статична ініціалізація змінних без константності |
| `__cpp_constexpr` | `201907L` | Динамічна алокація (`new`/`delete`), віртуальні функції та `try-catch` у `constexpr` |

| `__cpp_aggregate_paren_init` | `201902L` | Ініціалізація агрегатів круглими дужками `T(a, b)` |
| `__cpp_using_enum` | `201907L` | Оголошення `using enum Type;` для введення елементів у поточну область |

| `__cpp_generic_lambdas` | `201707L` | Явні шаблонні параметри для лямбда-виразів (`[]<typename T>(T x){}`) |
| `__cpp_conditional_explicit` | `201806L` | Умовний специфікатор `explicit(bool-expr)` для конструкторів |

### Детальний розбір семантики ключових мовних макросів

1. **Концепти та обмеження (`__cpp_concepts >= 201907L`):**
   Цей макрос сигналізує про повну відповідність компілятора специфікації концептів ISO C++20. Він гарантує підтримку ключових слів `concept` та `requires`, можливість накладання обмежень на класи, методи та функції, а також коректну реалізацію правил логічного поглинання (Subsumption Rules). Якщо концепт `B` логічно вимагає виконання концепту `A`, компілятор однозначно обирає перевантаження з `B` як більш спеціалізоване без виникнення неоднозначностей.

2. **Модулі та бінарні інтерфейси (`__cpp_modules >= 201907L`):**
   Макрос засвідчує, що транслятор підтримує синтаксис `export module`, `import`, поділ на модульні розділи (Module Partitions) та приватні фрагменти реалізації `module :private`. Крім того, він гарантує повну ізоляцію препроцесора: макроси, оголошені всередині модуля, не експортуються назовні.

3. **Корутини на рівні ядра транслятора (`__cpp_impl_coroutine >= 201902L`):**
   Цей макрос визначається компілятором, коли активовано генерацію скінченних автоматів для функцій, що містять оператори `co_await`, `co_yield` або `co_return`. Він свідчить про наявність підтримки трансформації фрейму корутини та оптимізації елімінації виділення пам'яті (HALO).

4. **Тристороннє порівняння (`__cpp_impl_three_way_comparison >= 201907L`):**
   Макрос вмикає підтримку оператора `<=>` та механізм синтезу переписаних (Rewritten) і перевернутих (Reversed) кандидатів під час розв'язання перевантажень. Компілятор автоматично синтезує вирази `!=`, `<`, `<=`, `>`, `>=` на основі `operator<=>` та `operator==`.

5. **Розширення constexpr-обчислень (`__cpp_constexpr >= 201907L` та `__cpp_constexpr_dynamic_alloc`):**
   Показник повної підтримки перехідного динамічного виділення пам'яті (`constexpr new`/`delete`), стандартних класів `std::vector` і `std::string` у контексті обчислення константних виразів, а також підтримки віртуальних функцій і блоків обробки винятків `try-catch`.

6. **Іменовані переліки (`__cpp_using_enum >= 201907L`):**
   Дозволяє конструкцію `using enum Color;`, яка робить усі елементи строго типізованого переліку (`enum class`) доступними в поточній області видимості без потреби багаторазового зазначення префікса `Color::`. Це особливо корисно у виразах `switch`, скорочуючи шум у коді без втрати типобезпеки.

7. **Окремий тип для UTF-8 (`__cpp_char8_t >= 201811L`):**
   Введення окремого фундаментального типу `char8_t` для рядкових літералів `u8"..."`. У C++17 такі літерали повертали масив звичайних `char`, що призводило до випадкового змішування рядків UTF-8 з локальними однобайтовими кодуваннями ASCII або Windows-1251. У C++20 тип `char8_t` є несумісним зі звичайним `char` без явного перетворення, що унеможливлює помилки змішування кодувань на етапі компіляції.

## 2. Нові заголовки стандартної бібліотеки та макроси бібліотечного тестування

Бібліотечні макроси тестування мають стандартизований префікс `__cpp_lib_` і стають доступними для препроцесора після включення відповідного функціонального заголовка або спеціального заголовка `<version>`. Заголовок `<version>` є мінімалістичним і містить виключно макроси без підключення важких тіл функцій та оголошень класів, що робить його оптимальним для глобальних конфігураційних файлів проєкту.

| Заголовок | Макрос бібліотечного тестування | Призначення |
| :--- | :--- | :--- |
| `<concepts>` | `__cpp_lib_concepts` (`202002L`) | Базові концептуальні предикати (`std::same_as`, `std::integral` тощо) |
| `<coroutine>` | `__cpp_lib_coroutine` (`201902L`) | Інтерфейси корутин: `std::coroutine_handle`, `std::noop_coroutine` |
| `<ranges>` | `__cpp_lib_ranges` (`202110L`) | Бібліотека діапазонів, види `std::views`, точки кастомізації |
| `<compare>` | `__cpp_lib_three_way_comparison` (`201907L`) | Класи категорій порядку (`std::strong_ordering`) та утиліти |
| `<format>` | `__cpp_lib_format` (`202110L`) | Типобезпечне форматування рядків `std::format`, `std::formatter` |
| `<span>` | `__cpp_lib_span` (`202002L`) | Невласницьке суцільне представлення послідовностей пам'яті |
| `<jthread>` | `__cpp_lib_jthread` (`201911L`) | Потік із автоприєднанням та токеном скасування |
| `<stop_token>` | `__cpp_lib_jthread` (`201911L`) | Кооперативне переривання потоків (`std::stop_token`, `std::stop_source`) |
| `<latch>` | `__cpp_lib_latch` (`201907L`) | Одноразовий бар'єр зворотного відліку для синхронізації |
| `<barrier>` | `__cpp_lib_barrier` (`201907L`) | Багаторазовий фазовий бар'єр із функцією завершення кроку |
| `<semaphore>` | `__cpp_lib_semaphore` (`201907L`) | Лічильний (`std::counting_semaphore`) та двійковий семафори |
| `<bit>` | `__cpp_lib_bitops` (`201907L`), `__cpp_lib_bit_cast` (`201806L`) | Низькорівневі маніпуляції бітами, підрахунок одиниць, безпечний каст |
| `<numbers>` | `__cpp_lib_math_constants` (`201907L`) | Математичні константи компіляції (`std::numbers::pi`, `std::numbers::e`) |
| `<source_location>` | `__cpp_lib_source_location` (`201907L`) | Метадані місця у вихідному коді замість макросів `__FILE__`, `__LINE__` |
| `<version>` | — | Централізований заголовок для включення всіх макросів тестування |
| `<syncstream>` | `__cpp_lib_syncbuf` (`201803L`) | Потокобезпечний вивід у спільні потоки `std::osyncstream` |

### Додаткові спеціалізовані заголовки C++20

1. **Заголовок `<source_location>`:**
   Вводить структуру `std::source_location`, яка автоматично захоплює ім'я поточного файлу, номер рядка, номер стовпця та ім'я функції за допомогою статичного виклику `std::source_location::current()`. Використовується як значення за замовчуванням у параметрах логувальних функцій, замінюючи застарілі препроцесорні макроси `__FILE__` та `__LINE__`.

2. **Заголовок `<numbers>`:**
   Містить математичні константи підвищеної точності у просторі імен `std::numbers` (`pi_v<T>`, `e_v<T>`, `sqrt2_v<T>`, `ln2_v<T>` тощо), параметризовані типом із плаваючою комою (`float`, `double`, `long double`), що усуває потребу у використанні непереносних макросів POSIX `M_PI`.

3. **Заголовок `<syncstream>`:**
   Надає класи `std::osyncstream` та `std::basic_syncbuf`, які буферизують вивід у консоль або файл і атомарно скидають його в базовий потік при знищенні об'єкта. Це гарантує відсутність перемішування рядків під час одночасного логування з багатьох паралельних потоків без використання явних м'ютексів.

4. **Атомарні вказівники та числа з плаваючою комою:**
   Стандарт C++20 додав повноцінну спеціалізацію `std::atomic<std::shared_ptr<T>>` та `std::atomic<std::weak_ptr<T>>` у заголовок `<memory>`, що дозволило реалізовувати безпечні безблокувальні структури даних без необхідності використання застарілих глобальних функцій `std::atomic_load`. Крім того, тип `std::atomic<float>` та `std::atomic<double>` отримав підтримку атомарних арифметичних операцій `fetch_add` та `fetch_sub`.

5. **Зручні утиліти контейнерів (`erase_if`, `starts_with`, `ssize`):**
   Бібліотека отримала глобальні вільні функції видалення `std::erase` та `std::erase_if` для всіх стандартних контейнерів, замінюючи громіздку ідіому Erase-Remove (`vec.erase(std::remove(...), vec.end())`). Рядки `std::string` та `std::string_view` отримали прямі методи `starts_with` та `ends_with`, а для безпечної роботи зі знаковими індексами масивів введено функцію `std::ssize()`.

## 3. Специфікація інтерфейсу std::span

Шаблон `std::span<T, Extent>` реалізує концепцію невласницького представлення неперервної послідовності елементів. Він інкапсулює пару значень: покажчик на перший елемент масиву та його довжину.

Параметр шаблону `Extent` визначає розмірність масиву:
- **Динамічний розмір (`Extent == std::dynamic_extent`):** розмір зберігається як поле класу (займає 16 байтів на 64-бітній архітектурі: 8 байтів покажчик + 8 байтів розмір).
- **Статичний розмір (`Extent != std::dynamic_extent`):** розмір зафіксовано на етапі компіляції. Об'єкт `std::span` займає рівно 8 байтів (лише один сирий покажчик), а всі операції перевірки меж оптимізуються компілятором без збереження додаткового лічильника в пам'яті.

```cpp
namespace std {
    inline constexpr size_t dynamic_extent = numeric_limits<size_t>::max();

    template<typename ElementType, size_t Extent = dynamic_extent>
    class span {
    public:
        using element_type     = ElementType;
        using value_type       = remove_cv_t<ElementType>;
        using size_type        = size_t;
        using difference_type  = ptrdiff_t;
        using pointer          = ElementType*;
        using const_pointer    = const ElementType*;
        using reference        = ElementType&;
        using const_reference  = const ElementType&;
        using iterator         = /* contiguous iterator */;

        static constexpr size_t extent = Extent;

        // Конструктори
        constexpr span() noexcept;
        constexpr span(pointer ptr, size_type count);
        constexpr span(pointer first, pointer last);
        template<size_t N>
        constexpr span(element_type (&arr)[N]) noexcept;
        template<typename Container>
        constexpr span(Container& cont);

        // Доступ до елементів
        constexpr reference front() const;
        constexpr reference back() const;
        constexpr reference operator[](size_type idx) const;
        constexpr pointer data() const noexcept;

        // Розмір та стан
        constexpr size_type size() const noexcept;
        constexpr size_type size_bytes() const noexcept;
        [[nodiscard]] constexpr bool empty() const noexcept;

        // Піддіапазони
        template<size_t Count>
        constexpr span<element_type, Count> first() const;
        constexpr span<element_type, dynamic_extent> first(size_type count) const;

        template<size_t Count>
        constexpr span<element_type, Count> last() const;
        constexpr span<element_type, dynamic_extent> last(size_type count) const;

        template<size_t Offset, size_t Count = dynamic_extent>
        constexpr auto subspan() const;
        constexpr span<element_type, dynamic_extent>
        subspan(size_type offset, size_type count = dynamic_extent) const;
    };
}
```

### Інваріанти та правила безпеки для `std::span`

1. **Константність представлення проти константності даних:** Якщо `span` оголошено як `const std::span<int>`, константним є саме представлення (не можна змінити покажчик або розмір), але елементи масиву `int` можна вільно змінювати. Для створення доступу «тільки для читання» слід використовувати `std::span<const int>`.
2. **Відсутність неявного копіювання буфера:** Конструктори та оператори копіювання `std::span` мають гарантовану складність `O(1)` і ніколи не виділяють пам'ять у купі.
3. **Метод `size_bytes()`:** повертає точний розмір займаної пам'яті в байтах (`size() * sizeof(element_type)`), що суттєво спрощує передачу структурованих буферів у системні виклики введення-виведення на зразок `read`, `write`, `recv`, `send` без ручного обчислення добутку.
4. **Робота з піддіапазонами (`subspan`, `first`, `last`):** виклики створення піддіапазонів зі статичними шаблонними параметрами повертають статичні `std::span<T, N>`, що гарантує збереження нульової вартості абстракції без виділення пам'яті під лічильники.

## 4. Контракти примітивів синхронізації

Спеціалізовані класи синхронізації C++20 спроектовані для заміни важких об'єктів `std::mutex` та `std::condition_variable` у сценаріях фазової координації паралельних потоків обчислень.

### Клас std::latch (заголовок `<latch>`)

`std::latch` — це одноразовий лічильник зворотного відліку. Після того як значення лічильника досягає нуля, об'єкт переходить у сигнальний стан назавжди і не може бути скинутий до початкового значення.

Головні операції:
- `count_down(n)`: атомарно зменшує лічильник на `n` без блокування викликаючого потоку. Якщо лічильник стає рівним нулю, усі заблоковані в очікуванні потоки миттєво розблоковуються.
- `wait()`: блокує виконання потоку, доки лічильник не досягне нуля. Якщо лічильник уже дорівнює нулю на момент виклику, метод повертає керування негайно без переходу в режим сну.
- `arrive_and_wait(n)`: еквівалентно атомарному виклику `count_down(n)` з наступним викликом `wait()`.
- `try_wait()`: неблокуюча перевірка, чи досяг лічильник нуля.

### Клас std::barrier (заголовок `<barrier>`)

`std::barrier` — це багаторазовий фазовий бар'єр для групи потоків. Коли всі зареєстровані потоки досягають бар'єра, викликається необов'язковий функціональний об'єкт `CompletionFunction`, після чого фаза оновлюється, а лічильник автоматично повертається до початкового значення для наступного циклу.

Методи керування:
- `arrive(n)`: фіксує прибуття потоку та повертає маркер фази `arrival_token`. Потік не блокується і може продовжувати виконання іншої роботи до явного виклику `wait()`.
- `wait(token)`: очікує завершення фази, зафіксованої маркером `token`.
- `arrive_and_wait()`: стандартний синхронний виклик очікування завершення поточної фази всіма учасниками.
- `arrive_and_drop()`: зменшує очікувану кількість потоків для наступних фаз на одиницю і завершує поточну фазу для даного потоку. Використовується, коли потік виходить з паралельної секції або завершує свою участь у пулі.

### Клас std::counting_semaphore (заголовок `<semaphore>`)

`std::counting_semaphore` моделює класичний семафор Едсгера Дейкстри. Він підтримує внутрішній атомарний лічильник ресурсів:
- `acquire()`: зменшує лічильник на одиницю; якщо лічильник дорівнює нулю, потік блокується до появи вільного ресурсу.
- `release(n)`: збільшує лічильник на `n` та розблоковує відповідну кількість очікуючих потоків.
- `try_acquire()`: неблокуюча спроба зменшити лічильник (повертає `true` у разі успіху та `false`, якщо ресурс зайнято).
- `try_acquire_for(duration)` та `try_acquire_until(time_point)`: спроба захоплення ресурсу із заданим часовим обмеженням.

Якщо параметр шаблону `LeastMaxValue` дорівнює `1`, використовується стандартизований псевдонім `std::binary_semaphore`, оптимізований транслятором як швидкий прапорець повідомлення між двома потоками.

## 5. Низькорівнева бітова арифметика заголовка `<bit>`

Функції заголовка `<bit>` призначені для системного програмування, драйверів пристроїв, мережевих протоколів, криптографії та телеметрії. Усі вони оголошені зі специфікаторами `constexpr` та `noexcept` і транслюються компілятором у відповідні апаратні інструкції сучасних процесорів архітектур x86-64 та ARM64.

| Сигнатура функції | Апаратне відображення x86 | Опис дії |
| :--- | :--- | :--- |
| `std::bit_cast<To>(From from)` | `mov` / reinterpretation | Безпечне побітове перетворення типу без UB та порушення Strict Aliasing |
| `std::has_single_bit(T x)` | `test` + `blsr` | Перевіряє, чи є число точним степенем двійки (`x != 0 && (x & (x - 1)) == 0`) |
| `std::bit_ceil(T x)` | `lzcnt` + `shl` | Знаходить найменший степінь двійки, не менший за `x` |
| `std::bit_floor(T x)` | `lzcnt` + `shl` | Знаходить найбільший степінь двійки, не більший за `x` |
| `std::bit_width(T x)` | `lzcnt` + `sub` | Кількість бітів, необхідних для двійкового представлення `x` |
| `std::rotl(T x, int s)` | `rol` | Циклічний зсув бітів ліворуч (по колу) |
| `std::rotr(T x, int s)` | `ror` | Циклічний зсув бітів праворуч (по колу) |
| `std::countl_zero(T x)` | `lzcnt` / `bsr` | Підрахунок поспіль нульових бітів, починаючи від старшого розряду |
| `std::countl_one(T x)` | `not` + `lzcnt` | Підрахунок поспіль одиничних бітів, починаючи від старшого розряду |
| `std::countr_zero(T x)` | `tzcnt` / `bsf` | Підрахунок поспіль нульових бітів, починаючи від молодшого розряду |
| `std::countr_one(T x)` | `not` + `tzcnt` | Підрахунок поспіль одиничних бітів, починаючи від молодшого розряду |
| `std::popcount(T x)` | `popcnt` | Загальна кількість одиничних бітів у двійковому значенні |

### Особливості std::bit_cast проти memcpy та reinterpret_cast

До стандарту C++20 спроба перетворити бітове представлення одного типу в інший (наприклад, інтерпретувати біти числа з плаваючою комою `float` як ціле `uint32_t`) через покажчики `reinterpret_cast` або через неактивне поле `union` формально породжувала невизначену поведінку (Undefined Behavior) згідно з правилом суворого аліасингу (Strict Aliasing Rule).

Єдиним легальним стандартизованим способом був виклик функції низькорівневого копіювання `std::memcpy`. Функція `std::bit_cast<To>(From)` повністю вирішує цю проблему:
- Вона здійснює сувору перевірку рівності розмірів типів `sizeof(To) == sizeof(From)` на етапі компіляції;
- Вона вимагає, щоб обидва типи були тривіально копійованими (`std::is_trivially_copyable_v<To>` та `std::is_trivially_copyable_v<From>`);
- Вона дозволена для обчислень під час компіляції всередині виразів `constexpr`, чого `std::memcpy` робити не може.

## 6. Календарна модель заголовка `<chrono>`

Бібліотека `<chrono>` C++20 запровадила повну систему типів для роботи з григоріанським календарем та часовими зонами міжнародної бази IANA. Система побудована на строгій типізації, яка чітко розмежовує поняття дня, місяця, року та комбінованих календарних структур:

```cpp
namespace std::chrono {
    class day;
    class month;
    class year;
    class weekday;
    class year_month;
    class year_month_day;
    class sys_days;
    class zoned_time;
}
```

Головні властивості календарної системи:
1. **Інтуїтивний синтаксис конструкторів:** оператор ділення `/` перевантажено для створення об'єктів дат у довільному загальноприйнятому порядку: `рік / місяць / день`, `день / місяць / рік` або `місяць / день / рік`.
2. **Перевірка валідності (`.ok()`):** створення об'єкта дати не викликає винятків і не генерує помилок. Для перевірки реальності дня (наприклад, чи існує 29 лютого в заданому році) викликається константний метод `date.ok()`.
3. **Конвертація в абсолютний час (`sys_days`):** тип `sys_days` є спеціалізацією `time_point` з точністю до одного дня, що дозволяє миттєво перетворювати календарні дати в мілісекунди від початку епохи Unix Epoch і виконувати точну часову арифметику.
4. **Підтримка часових зон (`zoned_time`):** автоматично враховує переходи на літній/зимовий час, високосні секунди та географічні зсуви за офіційною базою даних таймзон IANA.

## 7. Прапорці компіляторів для роботи з C++20

Для активації повної підтримки стандарту C++20 у сучасних системах збірки (CMake, Meson, Make) використовуються такі параметри трансляції:

1. **GCC (починаючи з версії 10.1, повна підтримка у GCC 11–13):**
   - Флаг стандарту: `-std=c++20` (або експериментальний `-std=c++2a` для старіших релізів).
   - Підтримка модулів: вимагає прапорця `-fmodules-ts` та компіляції попередніх інтерфейсів модуля у бінарний кеш gcm.
2. **Clang / LLVM (починаючи з версії 10.0, стабільна підтримка в Clang 13–16):**
   - Флаг стандарту: `-std=c++20`.
   - Бібліотека: вимагає прапорця `-stdlib=libc++` для доступу до найновіших компонентів `<format>` та `<ranges>`.
   - Модулі: ключі `-fmodules` та предкомпільовані модульні файли `.pcm`.
3. **Microsoft Visual C++ (MSVC 2019 версії 16.11 та MSVC 2022 версії 17.0+):**
   - Флаг стандарту: `/std:c++20` (суворий стандарт) або `/std:c++latest` (усі доступні можливості).
   - Сумісність препроцесора: обов'язковий флаг `/Zc:preprocessor` для коректної обробки вариативних макросів та алгоритмів форматування рядків.
   - Модулі: ключ `/interface` для компіляції інтерфейсів `.ixx` та створення файлів `.ifc`.

Ця повна довідкова матриця дозволяє системним інженерам проектувати надійні, оптимізовані та кросплатформні архітектури програмного забезпечення відповідно до всіх вимог стандарту ISO/IEC 14882:2020.
