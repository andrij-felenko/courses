# 📋 Довідник макросів тестування можливостей мови та бібліотеки

Повний довідник макросів тестування можливостей мови C++, операторів препроцесора та компонентів стандартної бібліотеки визначає числові сигнатури, мінімальні дати прийняття WG21 і правила умовного зондування синтаксичних та бібліотечних засобів.

Усі макроси тестування можливостей стандартизовані комітетом ISO C++ для забезпечення передбачуваної кросплатформної сумісності сирцевого коду. На відміну від застарілої практики перевірки номерів релізів окремих трансляторів чи використання булевих прапорців, система стандартизованих макросів спирається на точні числові дати прийняття рішень робочою групою WG21. Довідник детально описує механіку роботи операторів препроцесора, перелік макросів ядра компілятора (`__cpp_*`), макроси компонентів стандартної бібліотеки (`__cpp_lib_*`), правила версійності атрибутів через `__has_cpp_attribute`, а також контракт автономного заголовка `<version>`.

## 1. Оператори препроцесора для зондування середовища

Оператори препроцесора обчислюються транслятором безпосередньо під час аналізу директив умовної компіляції (`#if`, `#elif`) на четвертій фазі трансляції вихідного коду C++. Вони запобігають фатальним помилкам парсера у випадках, коли компілятор намагається відкрити відсутній файл або опрацювати невідомий синтаксичний атрибут.

### 1.1. Зондування наявності заголовків: `__has_include`

Оператор `__has_include` перевіряє доступність файлу в системних або користувацьких директоріях пошуку інклудів компілятора без виникнення критичної помилки переривання збірки.

```cpp
#if __has_include(<header-name>)
#if __has_include("header-name")
```

#### Семантика та правила обчислення:
- **Тип результату**: вираз обчислюється у цілочисельне значення `1` (якщо вказаний файл успішно знайдено в шляхах компілятора та він відкривається для читання) або `0` (якщо файл відсутній чи недоступний).
- **Синтаксичні форми**: підтримуються кутові дужки `<...>` для системних заголовків стандартної бібліотеки та подвійні лапки `"..."` для локальних заголовків проєкту.
- **Стандарт появи**: офіційно стандартизовано в C++17 (папір P0061R1), хоча більшість компіляторів підтримували його раніше у режимі сумісності з документом SD-6.
- **Ліниве обчислення в препроцесорі**: оператор `__has_include` можна комбінувати з іншими умовами через логічні оператори `&&` та `||`. Якщо попередня умова в ланцюжку `&&` обчислюється як хибна (`0`), компілятор не виконує пошук файлу на диску.

### 1.2. Зондування підтримки атрибутів: `__has_cpp_attribute`

Оператор `__has_cpp_attribute` перевіряє, чи розпізнає транслятор стандартний синтаксичний атрибут у подвійних квадратних дужках `[[attribute]]` або специфічний для вендора атрибут виду `[[vendor::attribute]]`.

```cpp
#if __has_cpp_attribute(attribute-token)
#if __has_cpp_attribute(vendor::attribute-token)
```

#### Семантика та правила обчислення:
- **Тип результату**: повертає ціле число `0`, якщо атрибут не підтримується даною версією компілятора, або дату формату `YYYYMML`, яка відповідає стандарту, що затвердив цей атрибут.
- **Стандарт появи**: C++20 (папір P0941R2).
- **Обробка вендорних просторів імен**: якщо оператор опитує вендорний атрибут на кшталт `gnu::always_inline` чи `clang::trivial_abi`, а компілятор належить іншій родині (наприклад, MSVC), вираз повертає `0` без генерації синтаксичної помилки чи попередження.

#### Повний перелік стандартних атрибутів мови C++:

| Атрибут | Версія макросу | Стандарт | Призначення та семантика |
| :--- | :--- | :--- | :--- |

## 2. Макроси ядра мови C++ (__cpp_*)

Макроси ядра вбудовані безпосередньо у внутрішній препроцесор компілятора. Вони сигналізують про підтримку нових ключових слів, конструкцій граматики та правил системи типів. Їхня наявність та значення не залежать від підключення будь-яких заголовків стандартної бібліотеки.

### 2.1. Конвенції та формат значень ядра

Усі макроси ядра починаються з префікса `__cpp_`, за яким слідує уніфікована назва синтаксичної можливості у форматі `snake_case`. Значення кожного макросу являє собою константу цілого типу `long` у форматі `YYYYMML`. Якщо компілятор не підтримує відповідну можливість, макрос залишається невизначеним (undefined).

Перевірка підтримки можливості завжди повинна здійснюватися через порівняння `>=` з відповідною стандартизованою датою, а не через просту перевірку існування `#ifdef`:

```cpp
#if defined(__cpp_concepts) && __cpp_concepts >= 201907L
    // Використання повноцінних концепцій C++20
#endif
```

### 2.3. Покрокова історія поправок `__cpp_constexpr`

Константні вирази зазнали найбільшої кількості ітеративних розширень в історії C++. Кожне числове значення макросу відкриває нові можливості для компілятора:

1. `200704L` (C++11): дозволяє функції з єдиним виразом `return`, константні конструктори та константи примітивних літеральних типів.
2. `201304L` (C++14): знімає заборону на локальні змінні, цикли `for`/`while`, умовні оператори `if` та мутацію локальних об'єктів у тілі функції.
3. `201603L` (C++17): дозволяє створювати та викликати лямбда-вирази всередині константних виразів, а також визначати умовні блоки `if constexpr`.
4. `201907L` (C++20): додає підтримку віртуальних викликів методів, блоків обробки винятків `try`/`catch` (за умови, що виняток не викидається в runtime), а також динамічне виділення пам'яті через `std::allocator`.
5. `202002L` (C++20 Defect Report): уточнює правила тривіального копіювання об'єктів union у константному контексті.
6. `202110L` (C++23): дозволяє оголошення нелітеральних типів, статичних локальних змінних та міток `goto`, якщо відповідна гілка коду не виконується в режимі compile-time.
7. `202211L` (C++23): дозволяє використання `static constexpr` локальних змінних у constexpr-функціях для кешування проміжних обчислень.
8. `202306L` (C++26): послаблює обмеження на перетворення нетипізованих покажчиків `void*` у constexpr-обчисленнях.

## 3. Макроси стандартної бібліотеки (__cpp_lib_*)

Бібліотечні макроси мають префікс `__cpp_lib_` і сигналізують про реалізацію конкретних класів, функцій, трейтів або алгоритмів у стандартній бібліотеці STL. На відміну від макросів ядра, бібліотечні макроси стають доступними лише після підключення спеціального заголовка `<version>` або відповідного функціонального заголовка (наприклад, `<optional>`, `<span>`, `<expected>`).

## 4. Специфікація та правила використання заголовка <version>

Заголовок `<version>` є спеціалізованим нормативним заголовком стандартної бібліотеки, починаючи зі стандарту ISO/IEC 14882:2020 (C++20).

### 4.1. Архітектурні гарантії стандарту щодо <version>
1. **Підтримка автономних середовищ (Freestanding)**: специфікація ISO C++ зобов'язує постачальників компіляторів надавати заголовок `<version>` як у повноцінному оточенні з операційною системою (Hosted), так і в автономному режимі прошивок мікроконтролерів (Freestanding). У freestanding-режимі цей заголовок визначає лише ті макроси `__cpp_lib_*`, компоненти яких не вимагають динамічної купи чи системних викликів ядра ОС.
2. **Нульове забруднення простору імен**: підключення заголовка `<version>` не імпортує жодних типів, класів, функцій чи шаблонів у простір імен `std`. Він містить виключно визначення директив `#define` для макросів препроцесора.
3. **Мінімальний час компіляції**: заголовок не містить складних шаблонів, не вимагає інклуду інших файлів STL і складається виключно з константних директив препроцесора. Час його обробки компілятором становить частки мікросекунди, що робить його ідеальним для включення у спільні конфігураційні заголовки проєктів.

### 4.2. Канонічний патерн безпечного підключення

Оскільки заголовок `<version>` фізично відсутній у застарілих компіляторах стандартів C++11, C++14 та ранніх релізах C++17, надійний кроскомпіляторний код повинен підключати його виключно за допомогою захисного зондування через оператор `__has_include`:

```cpp
#if defined(__has_include)
    #if __has_include(<version>)
        #include <version>
    #endif
#endif
```

Цей каскадний патерн гарантує, що старі транслятори безпечно оминуть директиву підключення без генерації фатальної помилки відсутності файлу, тоді як сучасні компілятори C++20/C++23/C++26 отримають повну таблицю макросів для умовного вибору між рідним синтаксисом та бібліотечними поліфілами.
