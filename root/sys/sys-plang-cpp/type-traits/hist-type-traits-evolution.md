# 📜 Історія та паперовий слід інтроспекції типів у C++

Метапрограмування на шаблонах у мові C++ не розроблялося як планова підсистема заздалегідь: воно з'явилося як несподіване відкриття. У 1994 році під час засідання комітету зі стандартизації ISO C++ німецький фізик-інформатик Ервін Унру (Erwin Unruh) продемонстрував незвичний код. Його програма не містила жодної викликуваної функції у розділі виконання, але змушувала компілятор обчислювати прості числа прямо в процесі синтаксичного аналізу і виводити їх як довгий список помилок збірки. Це відкриття довело, що система шаблонів C++ є повною за Тюрінгом (англ. *Turing-complete*).

Проте для практичного розроблення реального програмного забезпечення метапрограмування кінця 1990-х років залишалося вкрай небезпечним і важким інструментом. Головною перешкодою була відсутність інтроспекції типів: розробники не мали жодного вбудованого способу дізнатися під час компіляції, чи є параметр шаблону `T` цілим числом, чи містить він конструктор копіювання, чи є вказівником або чи безпечно застосувати до нього копіювання сирих байтів через `std::memcpy`.

Стандартна бібліотека шаблонів (STL), створена Олександром Степановим і Менґ Лі (Meng Lee) у лабораторії HP, частково розв'язувала цю проблему за допомогою механізму ітераторних тегів (`std::iterator_traits`). Схема Степанова дозволяла алгоритмам на кшталт `std::advance` або `std::distance` відрізнити ітератор довільного доступу (`random_access_iterator_tag`) від послідовного вхідного ітератора (`input_iterator_tag`) і вибрати швидке відгалуження за допомогою перевантаження функцій. Але цей підхід вимагав явного оголошення вкладених типів `iterator_category` усередині кожного класу ітератора і виявлявся повністю безсилим для базових вбудованих типів мови (`int*`, `double*`) та звичайних користувацьких структур.

## Ера Loki та революція Андрі Александреску (2001)

Справжній перелом у сприйнятті метапрограмування стався у 2001 році після виходу книги Андрі Александреску (Andrei Alexandrescu) *«Modern C++ Design: Generic Programming and Design Patterns Applied»* та випуску його супровідної бібліотеки **Loki**. Александреску формалізував та довів до досконалості поняття **Type Traits** (риси або характеристики типів).

У бібліотеці Loki Александреску продемонстрував, як за допомогою комбінації часткової спеціалізації шаблонів та рекурсивного розбору типів можна опитувати базові кваліфікатори мови. Клас-метафункція `Loki::TypeTraits<T>` містив набір констант переліків:

```cpp
// Концептуальна схема з бібліотеки Loki (2001 рік)
template <typename T>
struct TypeTraits {
    enum { isPointer = false };
    enum { isReference = false };
    enum { isConst = false };
    typedef T ParameterType;
};

// Часткова спеціалізація для вказівників
template <typename T>
struct TypeTraits<T*> {
    enum { isPointer = true };
    enum { isReference = false };
    enum { isConst = false };
    typedef T* ParameterType;
};
```

Александреску також запропонував дві фундаментальні ідіоми:
1. **IntToType** (шаблон, що перетворює цілочислове значення або булевий прапор унікальним типом під час компіляції) — прообраз сучасного `std::integral_constant`.
2. **Tag Dispatching** (відправлення за тегом), коли функція-обгортка передає об'єкт `IntToType<isPointer>` у приватне перевантаження, дозволяючи компіляторові вибирати потрібний алгоритм без витрат часу на перевірки під час виконання.

Схема Александреску мала суттєві обмеження тих часів. Оскільки мова ще не мала ключового слова `constexpr`, значення поверталися через нетипізовані константи `enum`. Крім того, комбінація кваліфікаторів `const volatile` вимагала написання десятків ручних спеціалізацій, а тогочасні компілятори (GCC 2.95, Visual C++ 6.0) часто падали у segmentation fault під час збірки складних меташаблонів.

## Еволюція Boost.TypeTraits та поява Boost.MPL (2002-2003)

Незалежно від розробок Александреску, у межах спільноти Boost сформувалася робоча група під керівництвом Джона Маддока (John Maddock), Стіва Клірі (Steve Cleary), Олексія Германова (Alexei Gourtovoy) та Девіда Абрагамса (Dave Abrahams). Вони створили бібліотеку **Boost.TypeTraits**, яка систематизувала всі можливі типи мови C++ у строгу математичну класифікацію.

Одночасно з цим Олексій Германов та Девід Абрагамс розробили бібліотеку **Boost.MPL** (Template Metaprogramming Library). У Boost.MPL трейти стали фундаментальними обчислювальними атомами. Метафункції опитування типів перестали повертати сирі значення `enum`, а почали повертати унікальні класи-типи `mpl::bool_<true>` та `mpl::bool_<false>`. Це дозволило передавати результати одного трейту у списки типів `mpl::vector` та застосовувати до них вищопорядок метафункції `mpl::transform` та `mpl::filter` безпосередньо під час компіляції.

Розробники Boost розділили метафункції на чотири фундаментальні категорії:
- **Первинні категорії типів** (чи є тип вказівником, цілим числом, плаваючою крапкою, масивом, функцією, об'єднанням чи класом);
- **Складені категорії** (арифметичні типи, скалярні типи, посилання);
- **Властивості типів** (тривіальність конструювання, наявність віртуального деструктора, сумісність із C-layout);
- **Трансформації типів** (зняття const/volatile, видалення посилань, додавання вказівників).

У травні 2003 року Джон Маддок, Дженнаро Прота (Gennaro Prota) та Бредлі Вайт (Bradley White) подали до комітету ISO C++ офіційний документ **N1424** (*«A Proposal to Add Type Traits to the Standard Library»*). Цей документ увійшов до технічного звіту C++ Technical Report 1 (TR1) і став прямим попередником сучасного заголовочного файла `<type_traits>`.

Під час підготовки TR1 виявилася фундаментальна проблема: **певну інформацію про типи неможливо добути засобами самої мови C++**. Наприклад, жодна комбінація шаблонів не може відрізнити порожній `struct` від порожнього `union`, чи перевірити, чи має клас тривіальний конструктор копіювання, якщо компілятор не надасть спеціальної підказки.

Це змусило розробників провідних компіляторів (GCC, Clang, MSVC) створити вбудовані компіляторні інтринсики (англ. *compiler intrinsics*) — спеціальні розширення мови на кшталт `__is_enum(T)`, `__is_union(T)`, `__is_trivially_copyable(T)`, `__is_base_of(Base, Derived)`. Стандартна бібліотека `<type_traits>` донині є високорівневою обгорткою над цими інтринсиками компілятора.

## Офіційний стандарт C++11: унікальний тип integral_constant та SFINAE

У стандарту C++11 заголовочний файл `<type_traits>` став офіційною частиною ядра стандартної бібліотеки. Для уніфікації повернення значень комітет затвердив базовий шаблон `std::integral_constant<T, v>`:

```cpp
template<class T, T v>
struct integral_constant {
    static constexpr T value = v;
    using value_type = T;
    using type = integral_constant;
    constexpr operator value_type() const noexcept { return value; }
    constexpr value_type operator()() const noexcept { return value; }
};

using true_type  = integral_constant<bool, true>;
using false_type = integral_constant<bool, false>;
```

Уніфікація через `true_type` та `false_type` дозволила легко поєднувати метафункції з механізмами SFINAE (Substitution Failure Is Not An Error) та метафункцією `std::enable_if`. З появою ключового слова `constexpr` усі обчислення типів нарешті отримали строгу типізацію та гарантію виконання під час збірки проєкту.

## Ера зручного синтаксису: C++14, C++17 та C++20

Хоча C++11 надав потужний інструментарій інтроспекції, синтаксис використання трейтів залишався надзвичайно важким для читання. Для кожної трансформації розробники змушені були писати префікс `typename` та вкладений тип `::type`, а для кожної перевірки — вкладену константу `::value`:

```cpp
// Важкий синтаксис C++11:
typename std::remove_reference<T>::type clean_x;
bool check = std::is_same<T, int>::value;
```

У C++14 завдяки пропозиції Вальтера Брауна (Walter E. Brown, документ **N3655**) комітет ввів шаблони псевдонімів із суфіксом `_t`:
```cpp
// Зручний синтаксис C++14:
std::remove_reference_t<T> clean_x;
```

У C++17 за пропозицією Алісдера Мередіта (Alisdair Meredith, документ **P0006R0**) були додані змінні-шаблони із суфіксом `_v`:
```cpp
// Зручний синтаксис C++17:
bool check = std::is_same_v<T, int>;
```

Тоді ж у C++17 з'явилися компіляторні логічні оператори `std::conjunction`, `std::disjunction` та `std::negation`, які забезпечили короткі замикання (short-circuit evaluation) під час інстанціювання шаблонів, що усунуло каскадні помилки збірки при аналізі складних умов.

У C++20 із появою **концептів** (Concepts) та синтаксичного виразу `requires` метафункції з `<type_traits>` отримали нове життя. Вони стали прямою основою для заголовочного файла `<concepts>` та стандартних концептів (`std::derived_from<Derived, Base>`, `std::same_as<T, U>`, `std::convertible_to<From, To>`). Завдяки цьому метапрограмування остаточно трансформувалося з важких синтаксичних трюків SFINAE на прозору, декларативну частину граматики мови C++.
