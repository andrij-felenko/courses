# 📋 Довідник заголовочного файла <type_traits>

Заголовочний файл `<type_traits>` є фундаментальним інструментальним довідником метапрограмувального арсеналу стандартної бібліотеки C++. Він містить понад 90 стандартних шаблонів для класифікації, опитування, перевірки відносин та трансформації типів під час компіляції. Всі предикатні метафункції перевірки успадковуються від уніфікованого базового шаблону `std::integral_constant<bool, B>` і надають статичну константу `::value` (типу `bool`), вкладений тип `::type` (який вказує на сам клас `integral_constant`), а також реалізують constexpr-оператор приведення `operator bool()` та оператор виклику `operator()()`.

Нижче наведено детальний довідник усіх категорій метафункцій стандартної бібліотеки C++ із вичерпним розбором їхньої внутрішньої семантики, крайових випадків та компіляторних гарантій.

## 1. Первинні категорії типів (Primary Type Categories)

Первинні категорії є фундаментальними взаємовиключними атомами (англ. *mutually exclusive primary categories*): будь-який тип у мові C++ належить **рівно до однієї** з чотирнадцяти первинних категорій. Перевірка двох різних первинних категорій для одного й того самого типу ніколи не може дати `true` одночасно.

| Метафункція (C++11) | Помічник `_v` (C++17) | Умова істинності (`true_type`) |
| :--- | :--- | :--- |
| `is_void<T>` | `is_void_v<T>` | `T` є типом `void` (з урахуванням cv-кваліфікаторів `const`/`volatile`) |
| `is_null_pointer<T>` | `is_null_pointer_v<T>` | `T` є типом `std::nullptr_t` (тип виразу `nullptr`) |
| `is_integral<T>` | `is_integral_v<T>` | `T` є базовим цілочисловим типом (`bool`, `char`, `int`, `long`, `char16_t` тощо) |
| `is_floating_point<T>` | `is_floating_point_v<T>` | `T` є типом із плаваючою крапкою (`float`, `double`, `long double`) |
| `is_array<T>` | `is_array_v<T>` | `T` є масивом відомого або невідомого розміру (наприклад, `int[5]` або `int[]`) |
| `is_pointer<T>` | `is_pointer_v<T>` | `T` є вказівником на об'єкт або функцію (включаючи `void*`, але НЕ вказівники на члени) |
| `is_lvalue_reference<T>` | `is_lvalue_reference_v<T>` | `T` є посиланням на lvalue (`U&`) |
| `is_rvalue_reference<T>` | `is_rvalue_reference_v<T>` | `T` є посиланням на rvalue (`U&&`) |
| `is_member_object_pointer<T>` | `is_member_object_pointer_v<T>` | `T` є вказівником на поле даних класу (`Data Class::*`) |
| `is_member_function_pointer<T>`| `is_member_function_pointer_v<T>`| `T` є вказівником на метод класу (`Ret (Class::*)(Args...)`) |
| `is_enum<T>` | `is_enum_v<T>` | `T` є переліком (`enum` або `enum class`) |
| `is_union<T>` | `is_union_v<T>` | `T` є об'єднанням (`union`) |
| `is_class<T>` | `is_class_v<T>` | `T` є структурою або класом (`struct` / `class`, але не `union`) |
| `is_function<T>` | `is_function_v<T>` | `T` є типом функції (наприклад, `void(int)`, але не вказівником на функцію) |

### Семантичні особливості первинних категорій

1. **Кваліфікатори `const` та `volatile`:** Кожна з первинних метафункцій повністю ігнорує топові кваліфікатори `const` та `volatile`. Вирази `std::is_integral_v<const int>` та `std::is_integral_v<volatile int>` однаково повертають `true`, бо топовий кваліфікатор модифікує об'єкт, а не його первинну категорію.
2. **Розмежування вказівників:** Метафункція `std::is_pointer` повертає `true` лише для звичайних вказівників на об'єкти чи функції (наприклад, `int*`, `void(*)()`). Вказівники на члени класів (`int Class::*` або `void (Class::*)()`) належать до окремих категорій `is_member_object_pointer` та `is_member_function_pointer`, і для них `std::is_pointer` повертає `false`.
3. **Розмежування типів функцій:** Тип сигнатури функції `void(int)` належить до категорії `is_function`. Проте тип вказівника на функцію `void(*)(int)` належить до категорії `is_pointer`.

## 2. Складені категорії типів (Composite Type Categories)

Складені категорії є логічними комбінаціями первинних категорій. Вони розроблені для того, щоб метапрограмісти не писали розлогі ланцюжки булевих операторів при побудові узагальнених обмежень.

| Метафункція (C++11) | Помічник `_v` (C++17) | Формула обчислення (Композиція) |
| :--- | :--- | :--- |
| `is_reference<T>` | `is_reference_v<T>` | `is_lvalue_reference<T> \|\| is_rvalue_reference<T>` |
| `is_arithmetic<T>` | `is_arithmetic_v<T>` | `is_integral<T> \|\| is_floating_point<T>` |
| `is_fundamental<T>` | `is_fundamental_v<T>` | `is_arithmetic<T> \|\| is_void<T> \|\| is_null_pointer<T>` |
| `is_object<T>` | `is_object_v<T>` | `!is_function<T> && !is_reference<T> && !is_void<T>` |
| `is_scalar<T>` | `is_scalar_v<T>` | `is_arithmetic<T> \|\| is_enum<T> \|\| is_pointer<T> \|\| is_member_pointer<T> \|\| is_null_pointer<T>` |
| `is_compound<T>` | `is_compound_v<T>` | `!is_fundamental<T>` (будь-який складений тип) |
| `is_member_pointer<T>` | `is_member_pointer_v<T>` | `is_member_object_pointer<T> \|\| is_member_function_pointer<T>` |

### Важливі юридичні деталі складених категорій

Категорія `is_object` відіграє фундаментальну роль при написанні низькорівневих менеджерів пам'яті та алокаторів. У мові C++ об'єктом (англ. *object*) називається ділянка пам'яті, яка має розмір, вирівнювання та тривалість зберігання. Тому `is_object` повертає `true` для всіх арифметичних типів, вказівників, масивів, структур та об'єднань, але повертає `false` для типів `void`, посилань (`T&`, `T&&`) та сигнатур функцій (`void()`), оскільки останні три не займають окремого місця в пам'яті за правилами C++.

Категорія `is_scalar` описує атомарні типи даних, які можна завантажувати у регістри процесора безпосередньо. Скалярні типи підтримують оператори порівняння, не мають конструкторів чи деструкторів і є повністю тривіальними під час передачі у функції.

## 3. Властивості типів (Type Properties)

Властивості типів описують кваліфікатори, розташування полів об'єкта в пам'яті, сумісність із мовою C, а також конструктивну поведінку при створенні, копіюванні чи знищенні об'єктів.

| Метафункція | Помічник `_v` | Опис перевірки |
| :--- | :--- | :--- |
| `is_const<T>` | `is_const_v<T>` | Перевіряє, чи є тип `const` (для посилань повертає `false`, бо `const` відноситься до об'єкта під посиланням) |
| `is_volatile<T>` | `is_volatile_v<T>` | Перевіряє, чи кваліфікований тип як `volatile` |
| `is_trivial<T>` | `is_trivial_v<T>` | Перевіряє, чи є тип тривіальним (має тривіальний конструктор по замовчуванню та є тривіально копійованим) |
| `is_trivially_copyable<T>`| `is_trivially_copyable_v<T>`| Дозволяє безпечне використання `std::memcpy` та `std::memmove` під час копіювання байтів пам'яті |
| `is_standard_layout<T>` | `is_standard_layout_v<T>` | Перевіряє сумісність розташування полів класу з мовою C (C-compatible memory layout) |
| `is_pod<T>` | `is_pod_v<T>` | *Deprecated у C++20.* Перевіряв, чи є тип Plain Old Data (`is_trivial && is_standard_layout`) |
| `is_empty<T>` | `is_empty_v<T>` | Перевіряє, чи є тип порожнім класом без даних-членів та віртуальних функцій (підходить під Empty Base Optimization) |
| `is_polymorphic<T>` | `is_polymorphic_v<T>` | Перевіряє наявність хоча б однієї віртуальної функції або віртуального успадкування у класі |
| `is_abstract<T>` | `is_abstract_v<T>` | Перевіряє наявність чисто віртуальних функцій (`pure virtual`) |
| `is_final<T>` | `is_final_v<T>` | Перевіряє, чи оголошено клас із ключовим словом `final` (C++14) |
| `is_signed<T>` | `is_signed_v<T>` | Перевіряє, чи є арифметичний тип знаковим |
| `is_unsigned<T>` | `is_unsigned_v<T>` | Перевіряє, чи є арифметичний тип беззнаковим |
| `is_bounded_array<T>` | `is_bounded_array_v<T>` | Перевіряє, чи є тип масивом із явно вказаним розміром `N` (C++20) |
| `is_unbounded_array<T>` | `is_unbounded_array_v<T>` | Перевіряє, чи є тип масивом із невизначеним розміром `T[]` (C++20) |

### Глибокий розбір гарантій тривіальності та Standard Layout

- **`is_trivially_copyable`:** Клас є тривіально копійованим, якщо всі його конструктори копіювання та переміщення, а також оператори присвоєння є тривіальними (або видаленими), і він має тривіальний деструктор. Для таких типів мова C++ дає офіційну гарантію: їхній стан можна зберегти у файл або передати по мережі через `std::memcpy`, а потім відновити байт у байт без виклику конструкторів.
- **`is_standard_layout`:** Клас має стандартне розташування (Standard Layout), якщо:
  1. Він не має віртуальних функцій та віртуальних базових класів;
  2. Усі нестатичні поля даних мають однаковий специфікатор доступу (`public`, `protected` або `private`);
  3. Усі нестатичні поля оголошені у самому класі або в одного з його предків, але не в обох одночасно;
  4. Жоден із базових класів не має полів того ж типу, що й перший елемент похідного класу (для забезпечення унікальності адрес).

Дотримання виразів `is_standard_layout` та `is_trivially_copyable` є обов'язковим при розробці системних ABI-інтерфейсів між C та C++.

## 4. Відносини між типами (Type Relationships)

Метафункції цієї групи приймають два або більше аргументів-типів і досліджують їхні взаємні ієрархічні зв'язки, сумісність типів та синтаксичну можливість конструювання чи присвоєння.

| Метафункція | Помічник `_v` | Сигнатура та умова істинності |
| :--- | :--- | :--- |
| `is_same<T, U>` | `is_same_v<T, U>` | `true`, якщо типи `T` та `U` тотожно рівні (включаючи збіг всіх `const`/`volatile` кваліфікаторів) |
| `is_base_of<Base, Derived>` | `is_base_of_v<Base, Derived>` | `true`, якщо `Base` є базовим класом для `Derived` (або вони є одним і тим самим класом) |
| `is_convertible<From, To>` | `is_convertible_v<From, To>` | `true`, якщо вираз `std::declval<From>()` можна неявно перетворити на тип `To` |
| `is_nothrow_convertible<F, T>`| `is_nothrow_convertible_v` | `true`, якщо неявне перетворення з `F` у `T` є `noexcept` (C++20) |
| `is_constructible<T, Args...>`| `is_constructible_v` | `true`, якщо об'єкт типу `T` можна сконструювати з аргументами `Args...` (`T(declval<Args>()...)`) |
| `is_trivially_constructible<T, Args...>` | `is_trivially_constructible_v` | `true`, якщо конструювання `T(Args...)` є тривіальним (не виконує додаткового коду) |
| `is_nothrow_constructible<T, Args...>` | `is_nothrow_constructible_v` | `true`, якщо конструювання `T(Args...)` позначено кваліфікатором `noexcept` |
| `is_assignable<To, From>` | `is_assignable_v` | `true`, якщо вираз `std::declval<To>() = std::declval<From>()` є синтаксично валідним |

### Тонкощі відношень is_base_of vs is_convertible

Існує важлива практична відмінність між `std::is_base_of<Base, Derived>` та `std::is_convertible<Derived*, Base*>`.

Метафункція `is_base_of` аналізує сам факт оголошення ієрархії класів. Вона повертає `true`, навіть якщо `Base` є `private` або `protected` базовим класом для `Derived`. Натомість `is_convertible` перевіряє неявне перетворення вказівників. Якщо успадкування є приватним (`private Base`), перетворити `Derived*` на `Base*` поза межами класу неможливо, тож `is_convertible` поверне `false`.

## 5. Трансформації та модифікатори типів (Type Transformations)

На відміну від булевих предикатів, метафункції трансформації модифікують вхідний тип `T` і повертають новий тип через вкладений псевдонім `::type` (або через шаблони псевдонімів із суфіксом `_t` починаючи з C++14).

| Метафункція (C++11) | Помічник `_t` (C++14) | Правило трансформації типу |
| :--- | :--- | :--- |
| `remove_const<T>` | `remove_const_t<T>` | Видаляє верхній кваліфікатор `const` (з `const int` робить `int`; з `const int*` не міняє нічого, бо const під вказівником) |
| `remove_volatile<T>` | `remove_volatile_t<T>` | Видаляє верхній кваліфікатор `volatile` |
| `remove_cv<T>` | `remove_cv_t<T>` | Видаляє обидва кваліфікатори `const` та `volatile` |
| `add_const<T>` | `add_const_t<T>` | Додає кваліфікатор `const` до типу `T` |
| `remove_reference<T>` | `remove_reference_t<T>` | Видаляє lvalue або rvalue посилання (з `int&` та `int&&` робить `int`) |
| `add_lvalue_reference<T>`| `add_lvalue_reference_t<T>`| Перетворює `T` на `T&` із застосуванням правил згортання посилань (з `void` залишає `void`) |
| `add_rvalue_reference<T>`| `add_rvalue_reference_t<T>`| Перетворює `T` на `T&&` із застосуванням правил згортання посилань |
| `remove_pointer<T>` | `remove_pointer_t<T>` | Видаляє один рівень вказівника (з `int*` робить `int`; з `int**` робить `int*`) |
| `add_pointer<T>` | `add_pointer_t<T>` | Перетворює `T` на `std::remove_reference_t<T>*` |
| `make_signed<T>` | `make_signed_t<T>` | Перетворює цілочисловий або enum-тип на відповідний знаковий цілочисловий тип |
| `make_unsigned<T>` | `make_unsigned_t<T>` | Перетворює цілочисловий або enum-тип на відповідний беззнаковий цілочисловий тип |
| `remove_extent<T>` | `remove_extent_t<T>` | Видаляє першу розмірність масиву (з `int[5][10]` робить `int[10]`) |
| `remove_all_extents<T>`| `remove_all_extents_t<T>`| Видаляє всі розмірності масиву (з `int[5][10]` робить `int`) |
| `decay<T>` | `decay_t<T>` | Застосовує правила розпаду типу: знімає посилання, перетворює масиви й функції на вказівники, видаляє cv-кваліфікатори |
| `underlying_type<T>` | `underlying_type_t<T>` | Повертає базовий цілочисловий тип для переліку `enum` або `enum class` |
| `remove_cvref<T>` | `remove_cvref_t<T>` | Видаляє одночасно посилання та cv-кваліфікатори (комбінація `remove_cv_t<remove_reference_t<T>>`, C++20) |

### Механіка згортання посилань (Reference Collapsing Rules)

При застосуванні `add_lvalue_reference` та `add_rvalue_reference` метафункції дотримуються чотирьох фундаментальних правил згортання посилань:
1. `T& &`   → `T&`
2. `T& &&`  → `T&`
3. `T&& &`  → `T&`
4. `T&& &&` → `T&&`

Якщо вхідний тип `T` є `void`, додавання посилань не викликає помилки компіляції, а мовчки повертає `void`, оскільки посилань на `void` у мові C++ не існує.

## 6. Виклик функціональних об'єктів (Invocation Traits)

Спеціалізована група метафункцій призначена для аналізу викликів функцій, лямбда-виразів, вказівників на методи та довільних функторів через узагальнений механізм `std::invoke`.

Сдислові метафункції аналізу викликів включають:
- `std::is_invocable<F, Args...>` — повертає `true`, якщо об'єкт `F` можна викликати з набором аргументів `Args...` за правилами `std::invoke`.
- `std::is_invocable_r<R, F, Args...>` — перевіряє, чи є виклик синтаксично валідним і чи можна тип повернення неявно перетворити на тип `R`.
- `std::is_nothrow_invocable<F, Args...>` — гарантує, що виклик об'єкта `F` із аргументами `Args...` позначено кваліфікатором `noexcept`.
- `std::invoke_result<F, Args...>` — обчислює тип результату виклику `F(Args...)`. Вона замінила застарілий шаблон `std::result_of`, який був вилучений у стандарту C++20 через важкий синтаксис.

```cpp
// Приклад визначення типу результату виклику у C++17:
using ReturnType = std::invoke_result_t<MyCallable, int, double>;
```

## 7. Компіляторні логічні помічники (Logical Operator Traits)

У C++17 введено стандартизовані метафункції для виконання булевої логіки над пакетами параметрів шаблонів із важливою гарантією: **підтримкою короткого замикання (short-circuit evaluation)** під час компіляції.

Основними логічними метафункціями є:
- `std::conjunction<B1, ..., Bn>` — обчислює логічне І (`&&`). Процес обчислення послідовно аналізує предикати `B1`, `B2` і зупиняється на першому предикаті, що повернув `false`. Усі наступні шаблони у пакеті навіть не інстанціюються компілятором, що запобігає помилкам збірки у невикористовуваних гілках.
- `std::disjunction<B1, ..., Bn>` — обчислює логічне АБО (`||`). Зупиняється на першому предикаті, що повернув `true`, і скасовує подальше інстанціювання.
- `std::negation<B>` — повертає логічне заперечення `!B::value` як шаблон `std::bool_constant`.

```cpp
// Перевірка, що всі типи у варіативному пакеті є цілочисловими (C++17):
template<typename... Ts>
inline constexpr bool all_integrals_v = std::conjunction_v<std::is_integral<Ts>...>;
```

Використання `std::conjunction` та `std::disjunction` замість звичайних операторів `&&` і `||` суттєво прискорює час збірки великих проєктів, оскільки компілятор не витрачає ресурси на розбір невикористовуваних спеціалізацій типів.
