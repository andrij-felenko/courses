# 📋 Інтерфейси синхронізації: std::shared_mutex, std::shared_lock та POSIX pthread_rwlock

Цей довідник описує повну поверхню програмування для роздільного блокування читання й запису в мовах C++ (стандарти C++14 та C++17) та C (стандарт POSIX.1-2001). Зазначено точні сигнатури функцій, типи параметрів, часову складність, вимоги до обробки винятків, системні коди помилок, модель пам'яті та гарантії потокобезпечності.

## 1. Концепції C++ та заголовок <shared_mutex>

Стандарт C++17 визначає формальні вимоги до методів примітивів блокування через поняття іменних вимог (Named Requirements):
- **`BasicLockable`**: вимагає наявності методів `lock()` та `unlock()`, які забезпечують базове взаємне виключення для єдиного потоку.
- **`Lockable`**: розширює `BasicLockable` неблокуючим методом `try_lock()`, що повертає булевий результат спроби захоплення ресурсу.
- **`SharedLockable`**: вимагає наявності сумісних операцій `lock_shared()`, `unlock_shared()` та `try_lock_shared()`, які дозволяють множинним потокам одночасно перебувати в критичній секції читання.
- **`SharedMutex`**: вимога, яка об'єднує властивості `Lockable` та `SharedLockable`. Класи `std::shared_mutex` та `std::shared_timed_mutex` відповідають вимозі `SharedMutex`.

Усі типи, концепції та допоміжні RAII-обгортки роздільного блокування оголошено у стандартному заголовковому файлі `<shared_mutex>`.

## 2. Клас std::shared_mutex (C++17)

Клас `std::shared_mutex` реалізує примітив синхронізації з підтримкою двох рівнів доступу: монопольного (для потоків запису) та сумісного (для потоків читання). У мові C++17 він не надає методів обмеження часу очікування, що дозволяє реалізувати його з мінімальними накладними витратами пам'яті (зазвичай 4 або 8 байтів).

### Оголошення класу
```cpp
namespace std {
    class shared_mutex {
    public:
        shared_mutex();
        ~shared_mutex();

        shared_mutex(const shared_mutex&) = delete;
        shared_mutex& operator=(const shared_mutex&) = delete;

        // Монопольний режим (Exclusive Access / Writer)
        void lock();
        bool try_lock();
        void unlock();

        // Сумісний режим (Shared Access / Reader)
        void lock_shared();
        bool try_lock_shared();
        void unlock_shared();

        // Отримання системного дескриптора (опційно у деяких реалізаціях)
        using native_handle_type = /* системно-залежний тип */;
        native_handle_type native_handle();
    };
}
```

### Конструктори та деструктор

#### `shared_mutex()`
Створює та ініціалізує новий об'єкт м'ютекса у вільному (незахопленому) стані.
- **Передумови**: відсутні.
- **Післяумови**: м'ютекс готовий до заблокування будь-яким потоком як у сумісному, так і в монопольному режимі. Внутрішні атомарні лічильники встановлюються у стан нульового читання й відсутності запису.
- **Винятки**: викидає виняток типу `std::system_error`, якщо операційній системі не вдалося виділити необхідні системні ресурси або структури ядра. Код помилки відповідає `std::errc::resource_unavailable_try_again` або `std::errc::operation_not_permitted`.
- **Складність**: постійна часова складність `O(1)`.

#### `~shared_mutex()`
Знищує об'єкт `std::shared_mutex` та звільняє виділені під нього системні ресурси.
- **Передумови**: об'єкт м'ютекса **мусить перебувати у вільному стані**. Знищення м'ютекса, який заблоковано хоча б одним потоком (у сумісному чи монопольному режимі), спричиняє неозначену поведінку (Undefined Behavior). Якщо у черзі є потоки, що чекають на розблокування, знищення об'єкта також є недійсним.
- **Гарантія винятків**: деструктор оголошено як `noexcept` і він ніколи не викидає винятків.

### Операції монопольного блокування (Exclusive Access / Writer)

#### `void lock()`
Захоплює м'ютекс у монопольному режимі. Якщо м'ютекс на даний момент утримується іншим потоком у монопольному режимі або хоча б одним потоком у сумісному режимі, поточний потік зупиняє виконання та переходить у стан очікування (занурюється у системний сплячий режим через виклик ядра).
- **Передумови**: поточний потік виконання не повинен вже утримувати цей м'ютекс у жодному з режимів. Клас `std::shared_mutex` не є рекурсивним, тому спроба повторного захоплення тим самим потоком викликає нездоланний глухий кут (Deadlock) або примусовий збій системи.
- **Післяумови**: поточний потік є єдиним власником м'ютекса. Жоден інший потік не може увійти до критичної секції читання або запису. Операція забезпечує семантику впорядкування пам'яті Acquire (`std::memory_order_acquire`), гарантуючи, що всі наступні читання й записи в поточній нитці побачать зміни, зроблені попередніми власниками замка.
- **Складність**: `O(1)` при відсутності контенції (виконується швидка атомарна інструкція CAS у просторі користувача). Під час контенції час залежить від тривалості перебування інших потоків у критичній секції та алгоритму планивальника ОС.
- **Винятки**: викидає `std::system_error` у разі виявлення системної помилки (наприклад, якщо система підтримує перевірку глухих кутів і повертає код `std::errc::resource_deadlock_would_occur`).

#### `bool try_lock()`
Робіть спробу захопити м'ютекс у монопольному режимі без блокування поточного потоку.
- **Повертає**: значення `true`, якщо м'ютекс був вільний і успішно захоплений потоком у монопольному режимі. Повертає `false`, якщо м'ютекс заблоковано іншим потоком у сумісному або монопольному режимі.
- **Складність**: завжди виконається за постійний час `O(1)` без виклику системного планивальника.
- **Винятки**: не викидає винятків (`noexcept`).

#### `void unlock()`
Звільняє монопольне блокування м'ютекса, повертаючи його у вільний стан або передаючи право володіння наступному потокові з черги очікування.
- **Передумови**: поточний потік виконання зобов'язаний володіти м'ютексом у монопольному режимі (після успішного виклику `lock()` або `try_lock()`). Виклик `unlock()` на незахопленому м'ютексі або з потоку, який не володіє замком, викликає неозначену поведінку.
- **Післяумови**: монопольне блокування знято. Операція забезпечує семантику впорядкування пам'яті Release (`std::memory_order_release`), гарантуючи скидання модифікованих даних із кешів процесора до виходу з критичної секції. Якщо в черзі чекали читачі, вони переходять у стан сумісного володіння; якщо чекав письменник — йому передається монопольне право.
- **Складність**: `O(1)`. Здійснює системний виклик розблокування (`FUTEX_WAKE` у Linux чи `WakeSRWLockExclusive` у Windows) лише за наявності блокованих потоків.
- **Винятки**: не викидає винятків (`noexcept`).

### Операції сумісного блокування (Shared Access / Reader)

#### `void lock_shared()`
Захоплює м'ютекс у сумісному режимі (для читання). Кілька потоків можуть одночасно успішно виконати `lock_shared()` та паралельно перебувати у критичній секції. Якщо м'ютекс заблоковано у монопольному режимі або в черзі є очікуючий письменник (за залежності від політики пріоритету реалізації), потік блокується до звільнення ресурсу.
- **Передумови**: поточний потік не повинен вже утримувати цей м'ютекс у монопольному режимі. Рекурсивний виклик `lock_shared()` тим самим потоком не гарантується стандартом і може призводити до глухого кута на реалізаціях із пріоритетом письменників.
- **Післяумови**: лічильник сумісних користувачів м'ютекса збільшено на одиницю. Потік має право читати спільні дані під захистом прапорця Acquire.
- **Складність**: `O(1)` при відсутності контенції записи (виконується атомарне додавання `fetch_add`).
- **Винятки**: викидає `std::system_error` у разі системного збою.

#### `bool try_lock_shared()`
Виконує неблокуючу спробу захопити м'ютекс у сумісному режимі.
- **Повертає**: `true`, якщо сумісне блокування успішно встановлено; `false`, якщо ресурс заблоковано на запис або якщо вхідна черга призупинила прийом новіших читачів.
- **Складність**: `O(1)`.
- **Винятки**: не викидає винятків (`noexcept`).

#### `void unlock_shared()`
Зменшує лічильник сумісних читачів на одиницю та звільняє сумісний замок із семантикою Release.
- **Передумови**: поточний потік зобов'язаний утримувати сумісний замок (після `lock_shared()` або `try_lock_shared()`).
- **Післяумови**: якщо лічильник читачів падає до нуля й у черзі є очікуючий письменник, системний планивальник збуджує потік запису.
- **Складність**: `O(1)`.
- **Винятки**: не викидає винятків (`noexcept`).

## 3. Клас std::shared_timed_mutex (C++14)

Клас `std::shared_timed_mutex` розширює інтерфейс `std::shared_mutex` чотирма додатковими шаблонними методами для обмеження часу очікування замка.

### Оголошення додаткових методів
```cpp
namespace std {
    class shared_timed_mutex {
    public:
        // Базові методи lock(), try_lock(), unlock(), lock_shared(), try_lock_shared(), unlock_shared()

        // Блокування на запис із граничним часом
        template <class Rep, class Period>
        bool try_lock_for(const std::chrono::duration<Rep, Period>& timeout_duration);

        template <class Clock, class Duration>
        bool try_lock_until(const std::chrono::time_point<Clock, Duration>& timeout_time);

        // Блокування на читання з граничним часом
        template <class Rep, class Period>
        bool try_lock_shared_for(const std::chrono::duration<Rep, Period>& timeout_duration);

        template <class Clock, class Duration>
        bool try_lock_shared_until(const std::chrono::time_point<Clock, Duration>& timeout_time);
    };
}
```

### Деталі специфікації часових методів

#### `try_lock_for(timeout_duration)` / `try_lock_shared_for(timeout_duration)`
Призупиняє виконання поточного потоку до успішного захоплення м'ютекса у відповідному режимі або до закінчення відносного часового інтервалу `timeout_duration`.
- **Параметри**: `timeout_duration` — об'єкт `std::chrono::duration`, що задає тривалість очікування.
- **Повертає**: `true`, якщо замок успішно отримано до закінчення інтервалу; `false`, якщо час вичерпано.
- **Складність**: блокування залежить від системного таймера ядра (наприклад, `FUTEX_WAIT_BITSET` у Linux із прапорцем відносного часу).

#### `try_lock_until(timeout_time)` / `try_lock_shared_until(timeout_time)`
Призупиняє виконання потоку до досягнення абсолютного моменту часу `timeout_time`.
- **Параметри**: `timeout_time` — об'єкт `std::chrono::time_point`, що вказує точний момент системного або монотонного годинника.
- **Особливість**: якщо параметр прив'язано до `std::chrono::system_clock`, ручне переведення системного часу користувачем або службою NTP може призвести до передчасного розблокування або збільшення часу очікування. Для стабільності рекомендовано вживати `std::chrono::steady_clock`.

## 4. Шаблонний клас std::shared_lock<Mutex> (C++14)

Клас `std::shared_lock` реалізує паттерн RAII (Resource Acquisition Is Initialization) для безпечного сумісного блокування. Він виключає витоки замків при виході з функції через оператор `return` або при прокиданні винятків (Exception Safety).

### Конструктори та їх стратегії блокування

```cpp
namespace std {
    template <class Mutex>
    class shared_lock {
    public:
        using mutex_type = Mutex;

        // 1. Порожній конструктор
        shared_lock() noexcept : pm(nullptr), owns(false) {}

        // 2. Стандартне сумісне блокування (захоплює lock_shared)
        explicit shared_lock(mutex_type& m) 
            : pm(std::addressof(m)), owns(true) { m.lock_shared(); }

        // 3. Відкладене блокування (без виклику lock_shared)
        shared_lock(mutex_type& m, defer_lock_t) noexcept 
            : pm(std::addressof(m)), owns(false) {}

        // 4. Спроба блокування без зупинки потоку
        shared_lock(mutex_type& m, try_to_lock_t) 
            : pm(std::addressof(m)), owns(m.try_lock_shared()) {}

        // 5. Перебрання вже захопленого замка
        shared_lock(mutex_type& m, adopt_lock_t) 
            : pm(std::addressof(m)), owns(true) {}

        // 6. Конструктори з часовими інтервалами
        template <class Rep, class Period>
        shared_lock(mutex_type& m, const chrono::duration<Rep, Period>& timeout_duration)
            : pm(std::addressof(m)), owns(m.try_lock_shared_for(timeout_duration)) {}

        template <class Clock, class Duration>
        shared_lock(mutex_type& m, const chrono::time_point<Clock, Duration>& timeout_time)
            : pm(std::addressof(m)), owns(m.try_lock_shared_until(timeout_time)) {}

        // Деструктор
        ~shared_lock() {
            if (owns) pm->unlock_shared();
        }

        // Оператори переміщення
        shared_lock(shared_lock&& u) noexcept 
            : pm(u.pm), owns(u.owns) { u.pm = nullptr; u.owns = false; }

        shared_lock& operator=(shared_lock&& u) noexcept {
            if (owns) pm->unlock_shared();
            pm = u.pm; owns = u.owns;
            u.pm = nullptr; u.owns = false;
            return *this;
        }

        // Заборона копіювання
        shared_lock(const shared_lock&) = delete;
        shared_lock& operator=(const shared_lock&) = delete;
    };
}
```

### Методи управління станом `std::shared_lock`

- `void lock()`: примусово викликає `pm->lock_shared()`. Змінює `owns_lock()` на `true`. Викидає `std::system_error` з кодом `operation_not_permitted`, якщо `pm == nullptr`, або з кодом `resource_deadlock_would_occur`, якщо замок уже належить цьому об'єкту.
- `bool try_lock()`: викликає `pm->try_lock_shared()` і оновлює стан прапорця володіння.
- `void unlock()`: викликає `pm->unlock_shared()` і скидає прапорець володіння `owns` у `false`.
- `mutex_type* release() noexcept`: відплітає об'єкт від м'ютекса без виклику `unlock_shared()`. Повертає вказівник на м'ютекс і скидає внутрішній стан у порожній. Передає відповідальність за розблокування розробнику.
- `mutex_type* mutex() const noexcept`: повертає вказівник на пов'язаний об'єкт м'ютекса.
- `bool owns_lock() const noexcept`: повертає `true`, якщо об'єкт наразі володіє сумісним замком.
- `explicit operator bool() const noexcept`: еквівалент виклику `owns_lock()`.

### Гарантії безпеки винятків при розгортанні стеку
Об'єкт `std::shared_lock` забезпечує строгу гарантію безпеки винятків (Strong Exception Guarantee). Якщо користувацька функція усередині критичної секції читання прокидає виняток, механізм розгортання стеку C++ (Stack Unwinding) автоматично викликає деструктор `~shared_lock()`. Деструктор перевіряє прапорець `owns` і коректно зменшує лічильник читачів через `unlock_shared()`. Це унеможливлює виникнення витоку читацьких блокувань та виключає вічне заблокування очікуючих потоків запису.

Конструктори `std::shared_lock`, які приймають м'ютекс за посиланням без додаткових прапорців, гарантують, що при викиданні винятку усередині `lock_shared()` сам об'єкт `std::shared_lock` не вважається створеним і його деструктор не викликається повторно.

## 5. Системна реалізація та інтеграція з ОС

У системній архітектурі Linux та Windows примітив `std::shared_mutex` відображається безпосередньо на оптимізовані системні виклики ядра.

### 5.1. Linux: futex та атомарний стан (libstdc++ / libc++)
У бібліотеці `libstdc++` (GCC) клас `std::shared_mutex` реалізовано як 32-бітове атомарне ціле число у просторі користувача, яке розділено на дві бітові маски:
1. **Лічильник читачів (Bits 0–29)**: утримує поточну кількість активних сумісних потоків.
2. **Прапорець очікування письменника (Bit 30)**: сигналізує про наявність у черзі принаймні одного потоку, що викликав `lock()`.
3. **Прапорець монопольного володіння (Bit 31)**: вказує, що м'ютекс повністю заблоковано для запису.

Коли контенція відсутня, виклики `lock_shared()` та `unlock_shared()` виконують виключно інструкцію `lock xadd` у пам'яті без звернення до ядра Linux. Лише у разі виявлення встановленого прапорця запису потік виконує системний виклик `sys_futex()` з описовим кодом `FUTEX_WAIT_PRIVATE`.

### 5.2. Windows: SRWLOCK (Slim Reader/Writer Lock)
На платформі Windows реалізація MSVC `std::shared_mutex` є тонкою обгорткою над системним примітивом ядра Windows `SRWLOCK` (Slim Reader/Writer Lock):
- **Розмір об'єкта**: дорівнює розміру одного системного вказівника (`uintptr_t`, 8 байтів на x64).
- **Системні функції**: `AcquireSRWLockShared()`, `ReleaseSRWLockShared()`, `AcquireSRWLockExclusive()`, `ReleaseSRWLockExclusive()`.
- **Характеристика**: примітив `SRWLOCK` не виділяє дескрипторів ядра (Handles) і не вимагає виклику системних деструкторів, що робить його створення та знищення абсолютно безкоштовним з точки зору ОС.

## 6. Порівняльна матриця стандартних RAII-обгортак C++

Система типів C++ надає чотири базові класи для керування життям м'ютексів. Таблиця нижче підсумовує відмінності в їхньому призначенні та можливостях:

| Характеристика | `std::lock_guard` | `std::scoped_lock` | `std::unique_lock` | `std::shared_lock` |
| :--- | :--- | :--- | :--- | :--- |
| **Стандарт мови** | C++11 | C++17 | C++11 | C++14 |
| **Необхідна концепція** | `BasicLockable` | `BasicLockable`... | `BasicLockable` | `SharedLockable` |
| **Режим блокування** | Монопольний | Монопольний | Монопольний | Сумісний (читання) |
| **Підтримка кількох м'ютексів** | Ні | Так (без deadlock) | Ні | Ні |
| **Операції переміщення (Move)** | Ні | Ні | Так | Так |
| **Ручне керування (`unlock`)** | Ні | Ні | Так | Так |
| **Підтримка `defer_lock`** | Ні | Ні | Так | Так |
| **Розмір об'єкта в пам'яті** | 1 вказівник | N вказівників | 1 вказівник + `bool` | 1 вказівник + `bool` |

## 7. Системний C API: POSIX pthread_rwlock_t (<pthread.h>)

У системному програмуванні на мові C для Unix-подібних операційних систем використовується стандартний тип `pthread_rwlock_t` та функціональна поверхня бібліотеки `libpthread`.

### Функції ініціалізації та руйнування

:::tabs
```c
#include <pthread.h>

// Статична ініціалізація
pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

// Динамічна ініціалізація та знищення
int pthread_rwlock_init(pthread_rwlock_t *restrict rwlock, 
                        const pthread_rwlockattr_t *restrict attr);
int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);
```
```cpp
#include <shared_mutex>

// Статичне або автоматичне створення в C++
std::shared_mutex mtx; // Автоматична ініціалізація конструктором
// Деструктор ~shared_mutex() виконується автоматично при виході з області видимості
```
:::

- `pthread_rwlock_init`: ініціалізує структура замка з атрибутами `attr`. Якщо `attr == NULL`, застосовуються системні атрибути за замовчуванням. Повертає `0` при успіху або код помилки (`EAGAIN`, `ENOMEM`, `EPERM`).
- `pthread_rwlock_destroy`: звільняє системні ресурси. Повертає `EBUSY`, якщо замок перебуває у заблокованому стані.

### Операції сумісного блокування (Читання)

:::tabs
```c
#include <pthread.h>

int pthread_rwlock_rdlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_tryrdlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_timedrdlock(pthread_rwlock_t *restrict rwlock, 
                               const struct timespec *restrict abs_timeout);
```
```cpp
#include <shared_mutex>
#include <chrono>

std::shared_timed_mutex mtx;

mtx.lock_shared();
bool success = mtx.try_lock_shared();
bool timed_success = mtx.try_lock_shared_for(std::chrono::milliseconds(100));
```
:::

- `pthread_rwlock_rdlock`: переводить потік у стан очікування, якщо замок утримується на запис. Повертає `0` при успіху, `EAGAIN` при досягненні максимальної кількості читацьких замків, або `EDEADLK` при виявленні глухого кута.
- `pthread_rwlock_tryrdlock`: повертає `EBUSY` негайно, якщо замок не можна захопити без блокування.

### Операції монопольного блокування (Запис)

:::tabs
```c
#include <pthread.h>

int pthread_rwlock_wrlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_trywrlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_timedwrlock(pthread_rwlock_t *restrict rwlock, 
                               const struct timespec *restrict abs_timeout);
```
```cpp
#include <shared_mutex>
#include <chrono>

std::shared_timed_mutex mtx;

mtx.lock();
bool success = mtx.try_lock();
bool timed_success = mtx.try_lock_for(std::chrono::milliseconds(100));
```
:::

- `pthread_rwlock_wrlock`: блокує потік до виходу всіх читачів і письменників. Повертає `0` при успіху або `EDEADLK`.

### Звільнення блокування

:::tabs
```c
#include <pthread.h>

// Звільнення будь-якого виду блокування
int pthread_rwlock_unlock(pthread_rwlock_t *rwlock);
```
```cpp
#include <shared_mutex>

std::shared_mutex mtx;

mtx.unlock_shared(); // Звільнення сумісного читацького замка
mtx.unlock();        // Звільнення монопольного письменницького замка
```
:::

- `pthread_rwlock_unlock`: універсальна функція звільнення замка. Повертає `0` при успіху або `EPERM`, якщо потік не володів цим замком.

### Коди помилок системних функцій POSIX
Системні функції сімейства `pthread_rwlock` не встановлюють глобальну змінну `errno`, а повертають значення коду помилки безпосередньо як результат виконання:
- `0`: успішне виконання операції.
- `EBUSY`: спроба захопити замок функціями `tryrdlock` або `trywrlock` завершилася невдачею, оскільки ресурс заблоковано іншим потоком.
- `ETIMEDOUT`: вичерпано граничний абсолютний час очікування у функціях `timedrdlock` або `timedwrlock`.
- `EDEADLK`: системний виклик виявив, що поточний потік уже володіє цим замком і повторне очікування створить взаємний глухий кут.
- `EAGAIN`: перевищено максимально припустиму кількість паралельних читацьких блокувань для даного об'єкта.

### Управління політикою пріоритету (Розширення GNU/Linux)

Для керування чергою читачів і письменників у системній бібліотеці `glibc` надається нестандартний атрибут `pthread_rwlockattr_setkind_np`:

:::tabs
```c
#define _GNU_SOURCE
#include <pthread.h>

int pthread_rwlockattr_init(pthread_rwlockattr_t *attr);
int pthread_rwlockattr_setkind_np(pthread_rwlockattr_t *attr, int pref);
int pthread_rwlockattr_destroy(pthread_rwlockattr_t *attr);
```
```cpp
#include <shared_mutex>

// У стандарті C++17 політика пріоритету є Implementation-Defined.
// На Linux glibc за замовчуванням застосовує фазово-справедливий алгоритм (Phase-Fair RWLock).
std::shared_mutex mtx;
```
:::

Можливі прапорці значення `pref`:
1. `PTHREAD_RWLOCK_PREFER_READER_NP`: надає пріоритет читачам. Письменники чекають, доки вхідний потік читачів повністю не вичерпається.
2. `PTHREAD_RWLOCK_PREFER_WRITER_NP`: розглядається як рекомендація надання пріоритету письменникам.
3. `PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP`: надає суворий пріоритет письменникам за умови, що читачі не виконують рекурсивних блокувань. Як тільки письменник заходить у чергу, нові читачі блокуються негайно.
