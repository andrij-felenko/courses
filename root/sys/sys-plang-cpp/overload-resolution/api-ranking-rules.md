# 📋 Мірила добору: розряди перетворень і порядок правил-розсудників

Це довідник для звірки: у які розряди мова розкладає неявні перетворення, з чого складається послідовність перетворень і в якому саме порядку компілятор застосовує правила, коли розряди виявилися рівними. Формулювання звірені з чинним проєктом стандарту — розділи `[conv]`, `[over.ics.scs]`, `[over.ics.rank]`, `[over.ics.user]`, `[over.match.best]`.

## Будова стандартної послідовності

Стандартна послідовність — не довільний ланцюжок кроків, а чотири впорядковані комірки, кожну з яких заповнюють щонайбільше один раз:

```
[1] перетворення             [2] підвищення АБО         [3] перетворення     [4] узгодження
    самого виразу                перетворення               покажчика            cv
    ─────────────────            ─────────────────          на функцію           ────────────
    lvalue → rvalue              рівно ОДНЕ з двох          noexcept-функція     T* → const T*
    масив → покажчик             стовпців таблиці           → звичайна
    функція → покажчик           нижче
```

Порядок жорсткий, назад дороги немає. Комірки `[2]` взаємно виключні: одне підвищення **або** одне перетворення, ніколи два поспіль. Тому `char` → `long double` — це один крок (дробово-цілочислове перетворення), а не «спершу підвищення до `int`, потім перетворення в `double`». Комірка `[3]` існує окремо з C++17, відколи [`noexcept`](root:sys-plang-cpp/noexcept) став частиною типу функції: покажчик на функцію з обіцянкою не кидати вільно перетворюється на покажчик без неї, назад — ні.

## Таблиця розрядів

| Перетворення | Категорія | Розряд |
|---|---|---|
| перетворень не потрібно | тотожність | **точний збіг** |
| lvalue → rvalue (читання значення) | перетворення виразу | **точний збіг** |
| масив → покажчик на перший елемент | перетворення виразу | **точний збіг** |
| функція → покажчик на функцію | перетворення виразу | **точний збіг** |
| узгодження cv (`T*` → `const T*`) | узгодження кваліфікації | **точний збіг** |
| покажчик на `noexcept`-функцію → на звичайну | узгодження кваліфікації | **точний збіг** |
| цілочислове підвищення | підвищення | **підвищення** |
| дробове підвищення (`float` → `double`) | підвищення | **підвищення** |
| цілочислове перетворення (`long` → `short`) | перетворення | **перетворення** |
| дробове перетворення (`double` → `float`) | перетворення | **перетворення** |
| дробово-цілочислове (`int` ↔ `double`) | перетворення | **перетворення** |
| покажчикове (`D*` → `B*`, `T*` → `void*`, `nullptr` → `T*`) | перетворення | **перетворення** |
| покажчик на член (`B::*` → `D::*`) | перетворення | **перетворення** |
| булеве (будь-що → `bool`) | перетворення | **перетворення** |

```
розряд(послідовності) = НАЙГІРШИЙ розряд серед її кроків
точний збіг  ‹  підвищення  ‹  перетворення        (ліворуч — краще)
```

Що саме мова вважає підвищенням, вирішено не смаком, а сумісністю з C. [Цілочислове підвищення](root:sf-lang/integer-promotion) — це `bool`, `char`, `signed char`, `unsigned char`, `short`, `unsigned short`, `char8_t`, `char16_t`, `char32_t`, `wchar_t`, бітове поле й **незакрите** перерахування (`enum` без `class`) → `int`, а якщо `int` не вміщає всіх значень джерела — `unsigned int`. Дробове підвищення в мові рівно одне: `float` → `double`. Усе інше в межах арифметики — уже перетворення, хай навіть без утрати точності.

## Три родини послідовностей і списочна ініціалізація

| Родина | Із чого складається | Місце в порядку |
|---|---|---|
| стандартна | чотири комірки вище (можливо, порожні) | найкраща |
| користувацька | стандартна послідовність → **один** виклик конструктора або оператора приведення → стандартна послідовність | гірша за **будь-яку** стандартну |
| багатокрапка | аргумент потрапив у `...` | найгірша |
| списочна | аргумент записано як `{…}`; розряд береться з поелементних перетворень | окремі правила, див. нижче |

Ключове обмеження користувацької родини записано в `[class.conv]`/4: щонайбільше одне користувацьке перетворення застосовується неявно до одного значення. Тому ланцюжок «рядковий літерал → `std::string` → ваш `Widget`» не збереться ніколи, скільки б конструкторів ви не написали.

Дві користувацькі послідовності порівнюються **лише тоді**, коли в них той самий конструктор чи той самий оператор приведення (або та сама сукупна ініціалізація) — тоді виграє та, у якої краща **друга** стандартна послідовність. Різні користувацькі перетворення між собою незрівнянні: два різні шляхи однакові за рангом, і це прямий шлях до неоднозначності.

## Тонші правила всередині «краща послідовність» — `[over.ics.rank]`

Ці правила ще не про кандидатів, а про **одну позицію** вектора: вони уточнюють, коли S1 краща за S2. Саме сюди, всупереч поширеній думці, належать усі мірила зв'язування посилань — а не до переліку розсудників наступного розділу.

| Умова | Хто виграє |
|---|---|
| S1 — власна підпослідовність S2 (тотожність вважають підпослідовністю будь-якої іншої) | S1 |
| розряд S1 кращий за розряд S2 | S1 |
| обидві — зв'язування посилань; S1 зв'язує rvalue-посилання з rvalue, S2 — lvalue-посилання | S1 |
| обидві зв'язують посилання на той самий тип, але ціль S2 сильніше cv-кваліфікована | S1 (менш константна) |
| обидві відрізняються лише узгодженням cv | та, що додає менше |
| обидві мають розряд «перетворення», але S2 перетворює покажчик, покажчик на член або `nullptr_t` у `bool` | S1 |
| `B` походить від `A`: `B*` → `A*` проти `B*` → `void*` | ближчий шлях, `B*` → `A*` |
| `C` → `B` → `A`: `C*` → `B*` проти `C*` → `A*` (те саме для посилань і значень) | коротший підйом ієрархією |
| підвищення перерахування з **закріпленим** базовим типом до цього типу проти підвищення до просунутого | до закріпленого типу |
| списочна: L1 дає `std::initializer_list<X>`, L2 — ні | L1, **сильніше за всі решту правил** |

Останній рядок — не звичайний розсудник, а перебивна карта: `std::vector<int> v{3, 1}` дає вектор із двох елементів, а не з трьох одиниць, саме тому ([форми ініціалізації](root:sys-plang-cpp/initialization-forms)).

Мірила зв'язування посилань вимагають розрізняти категорію значення виразу — чи є в нього місце в пам'яті і чи можна забрати його нутрощі ([категорії значень](root:sys-plang-cpp/value-categories), [правила зв'язування](root:sys-plang-cpp/references-binding)).

## Порядок правил-розсудників — `[over.match.best]`

Передумова для всіх пунктів: послідовність F1 **не гірша за F2 для всіх аргументів**. Далі правила перебирають строго згори вниз, і перше, що спрацювало, вирішує все.

| № | Правило | Типовий випадок |
|---|---|---|
| 1 | хоч для одного аргументу послідовність F1 строго краща | щоденна робота добору |
| 2 | контекст — ініціалізація користувацьким перетворенням, і від **результату** F1 до цілі веде краща стандартна послідовність | вибір між кількома `operator T()` |
| 3 | контекст — пряме зв'язування посилання на функцію через оператор приведення; F1 повертає посилання тієї самої категорії, що й ціль | рідкісна екзотика |
| 4 | F1 — **не** спеціалізація шаблона, F2 — спеціалізація | «звичайна функція б'є шаблон» |
| 5 | обидві — спеціалізації, і шаблон F1 **спеціальніший** | [часткове впорядкування шаблонів](root:sys-plang-cpp/specialization-overload) |
| 6 | обидва нешаблонні, і F1 **обмеженіший** (C++20) | [концепти](root:sys-plang-cpp/concepts-constraints) різної вимогливості |
| 7 | F1 — конструктор класу `D`, F2 — конструктор бази `B`, і типи параметрів у них однакові | успадковані конструктори через `using B::B;` |
| 8 | F2 — **переписаний** кандидат, F1 — ні | `a < b` проти переписаного `(a <=> b) < 0` |
| 9 | обидва переписані, і F2 — синтезований кандидат із **переставленими** операндами, F1 — ні | `b == a` як заміна `a == b` |
| 10 | тільки для CTAD: F2 породжено з успадкованих конструкторів бази, F1 — ні | `std::vector v{1, 2}` |
| 11 | F1 породжено з підказки виведення, F2 — ні | явна `deduction guide` |
| 12 | F1 — копіювальний кандидат виведення, F2 — ні | `std::vector v2{v1}` дає копію, не вектор векторів |
| 13 | F1 породжено з нешаблонного конструктора, F2 — з шаблонного | останній запобіжник CTAD |

Пункти 8–9 з'явилися в C++20 разом із переписуванням операторів порівняння: компілятор має право сам скласти `a < b` з `(a <=> b) < 0`, а `a == b` — з `b == a`, і такі синтезовані кандидати навмисне поставлено **нижче** за написані вами ([тричленне порівняння](root:sys-plang-cpp/three-way-comparison)). Пункти 10–13 працюють лише всередині виведення аргументів шаблона класу і на звичайні виклики не впливають.

## Неявний параметр об'єкта

Нестатичний метод бере участь у доборі так, ніби має додатковий нульовий параметр:

| Оголошення методу | Тип неявного параметра |
|---|---|
| `void f();` | `X&` |
| `void f() const;` | `const X&` |
| `void f() &;` | `X&` |
| `void f() &&;` | `X&&` |
| `static void f();` | збігається з будь-яким об'єктом (аргумент відкидають) |

Дві особливості цього параметра варто пам'ятати. До нього **не застосовують користувацьких перетворень** — об'єкт зберігає свою тотожність. І метод без ref-кваліфікатора приймає rvalue навіть без `const`, але на розряд це не впливає.

## Що в доборі не бере участі

| Що не враховують | Наслідок |
|---|---|
| тип повернення | `int g(); double g();` — не перевантаження, а помилка повторного оголошення (виняток — контекст пункту 2 вище) |
| тіло функції | добору вистачає оголошення; визначення може бути в іншій одиниці трансляції |
| права доступу | приватний метод — повноцінний кандидат; доступ перевіряють **після** перемоги |
| `noexcept` на самій функції | `void f() noexcept;` і `void f();` — те саме оголошення, а не пара перевантажень |
| типові значення параметрів | не частина сигнатури; впливають лише на діапазон допустимої кількості аргументів |
| імена параметрів | `f(int count)` і `f(int n)` — та сама функція |
| верхньорівневі cv на параметрі-значенні | `f(int)` ≡ `f(const int)` |
| масив і функція в типі параметра | `f(int[10])` ≡ `f(int*)`, `f(int())` ≡ `f(int(*)())` |
| псевдоніми типів | `using Size = std::size_t;` дає той самий тип, а не новий |
| `constexpr`, `consteval`, `inline`, `virtual` | перевантажень не розрізняють |

Один виняток із рядка про `noexcept` заслуговує окремої згадки: у **типі параметра** обіцянка не кидати цілком розрізняльна, бо `void(*)() noexcept` і `void(*)()` — різні типи.

```cpp
void call(void (*f)());            // (1)
void call(void (*f)() noexcept);   // (2) — законне перевантаження

void quiet() noexcept;
call(quiet);    // (2): тотожність б'є перетворення покажчика на функцію
```

Обидві послідовності мають розряд «точний збіг», тож розсудило перше правило з таблиці `[over.ics.rank]`: тотожність є підпослідовністю будь-якої іншої послідовності.
