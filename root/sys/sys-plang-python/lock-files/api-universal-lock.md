# 📋 Специфікація універсального lock-файлу та інтерфейс синхронізації

<preknowlist>
- [pyproject.toml і метадані](root:sys-plang-python/pyproject-toml) — структура маніфесту проєкту та декларація залежностей.
- [sdist, wheel і бінарні колеса](root:sys-plang-python/wheels-and-sdist) — теги сумісності платформ і двійкові дистрибутиви.
- [pip і джерела пакетів](root:sys-plang-python/pip-install) — протокол індексів пакетів Simple Repository API.
</preknowlist>

Універсальний lock-файл (Universal Lock File) — це машинно-орієнтований документ у форматі TOML, що фіксує детерміноване розв'язання повного транзитивного графа залежностей для всіх цільових операційних систем (Linux, macOS, Windows), архітектур CPU (x86_64, aarch64, armv7) та версій інтерпретатора Python. На відміну від застарілих плоских файлів `requirements.txt`, універсальний замок містить повну топологію дерева зв'язків, специфікатори маркерів середовища за стандартом PEP 508, правила зіставлення платформних тегів коліс (PEP 425 / PEP 600), механізми прямого посилання на репозиторії Git (PEP 610), а також таблицю криптографічних хешів (SHA-256 / BLAKE3) для кожного скомпільованого двійкового колеса (`wheel`) та вихідного архіву (`sdist`).

Нижче наведено формальну специфікацію схеми універсального замка (на основі стандарту `uv.lock` та чернетки PEP 751), правила обчислення маркерів середовища, алгоритм валідації тегів коліс, внутрішній життєвий цикл узгодження файлової системи та повний опис інтерфейсу синхронізації віртуального простору.

## 1. Схема TOML-документа універсального замка

Документ блокування складається з двох основних секцій: кореневої таблиці глобальних метаданих проєкту та масиву таблиць `[[package]]`, що описують кожен зафіксований пакунок.

```
+-------------------------------------------------------------------------+
|                        СТРУКТУРА ФАЙЛУ-ЗАМКА                            |
+-------------------------------------------------------------------------+
| [Кореневі метадані]                                                     |
| • version = 1                                                           |
| • manifest-hash = "blake3:9a8f..." (Хеш pyproject.toml)                 |
| • requires-python = ">=3.10"                                            |
+-------------------------------------------------------------------------+
| [[package]] (fastapi 0.110.0)                                           |
| • source = { registry = "https://pypi.org/simple" }                     |
| • dependencies = [ { name = "pydantic", marker = "..." } ]              |
| • wheels = [ { file = "...", hash = "sha256:4a8e..." } ]                |
+-------------------------------------------------------------------------+
| [[package]] (pydantic 2.6.4)                                            |
| • wheels = [                                                            |
|     { file = "...cp312-manylinux_x86_64.whl", hash = "sha256:7b1c..." },|
|     { file = "...cp312-macosx_arm64.whl", hash = "sha256:9f8a..." }    |
|   ]                                                                     |
+-------------------------------------------------------------------------+
```

### 1.1. Коренева таблиця метаданих

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `version` | ціле число | Так | Мажорна версія формату файлу блокування (наприклад, `1`). |
| `revision` | ціле число | Так | Ревізія структури всередині поточної версії для зворотно сумісних розширень. |
| `manifest-hash` | рядок | Так | Криптографічний хеш (BLAKE3 або SHA-256) вхідного маніфесту `pyproject.toml`. Дозволяє миттєво визначити, чи змінювалися вихідні вимоги, без опитування віддаленого репозиторію. |
| `requires-python` | рядок | Ні | Глобальне обмеження підтримуваних версій інтерпретатора Python згідно з PEP 440 (наприклад, `>=3.10, <3.14`). |

### 1.2. Специфікація таблиці пакета `[[package]]`

Кожна залежність у транзитивному замиканні описується окремою секцією `[[package]]`:

```toml
version = 1
revision = 1
manifest-hash = "blake3:9a8f2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b"
requires-python = ">=3.10"

[[package]]
name = "fastapi"
version = "0.110.0"
source = { registry = "https://pypi.org/simple" }
dependencies = [
    { name = "pydantic", marker = "python_version >= '3.10'" },
    { name = "starlette" },
    { name = "typing-extensions", marker = "python_version < '3.11'" }
]
sdist = { url = "https://files.pythonhosted.org/packages/.../fastapi-0.110.0.tar.gz", hash = "sha256:7c9e1b2a3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a", size = 56420 }
wheels = [
    { url = "https://files.pythonhosted.org/packages/.../fastapi-0.110.0-py3-none-any.whl", hash = "sha256:4a8e912b7f30c1d2e3f4a5b6c7d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6", size = 92100 }
]

[[package]]
name = "uvloop"
version = "0.19.0"
source = { registry = "https://pypi.org/simple" }
sdist = { url = "https://files.pythonhosted.org/packages/.../uvloop-0.19.0.tar.gz", hash = "sha256:3a1b2c4d5e6f...", size = 2300000 }
wheels = [
    { file = "uvloop-0.19.0-cp312-cp312-manylinux_2_17_x86_64.whl", hash = "sha256:8f7e6d5c4b3a...", size = 4100000 },
    { file = "uvloop-0.19.0-cp312-cp312-macosx_11_0_arm64.whl", hash = "sha256:9b8a7c6d5e4f...", size = 3900000 }
]
```

### 1.3. Опис полів сутності `[[package]]`

- `name` *(рядок, обов'язкове)*: нормалізоване ім'я пакета за стандартом PEP 503 (усі символи зведені до нижнього регістру, крапки й підкреслення замінені на дефіси).
- `version` *(рядок, обов'язкове)*: точний канонічний номер версії відповідно до PEP 440.
- `source` *(таблиця, обов'язкове)*: джерело походження артефакту. Може набувати одного з трьох значень:
  - `{ registry = "URL" }` — стандартний пакет із віддаленого індексу PyPI або приватного сховища (Artifactory, Nexus).
  - `{ git = "URL", commit = "FULL_HASH" }` — версія, зібрана безпосередньо з конкретного коміту Git-репозиторію згідно з PEP 610.
  - `{ path = "RELATIVE_PATH", editable = true }` — локальний пакет у режимі розробки (Editable Install) або компонент монорепозиторію (Workspace Member).
- `dependencies` *(масив таблиць, опціональне)*: прямі транзитивні вимоги пакета. Кожен елемент містить поле `name` та необов'язкове поле `marker`, що задає умову активації залежності за стандартом PEP 508.
- `sdist` *(таблиця, опціональне)*: метадані вихідного архіву (`.tar.gz`). Включає посилання на завантаження `url` або ім'я файлу `file`, розмір у байтах `size` та обов'язковий криптографічний хеш `hash = "sha256:..."`.
- `wheels` *(масив таблиць, опціональне)*: перелік попередньо скомпільованих бінарних коліс для різних платформ і ABI.

## 2. Оцінка маркерів середовища (Environment Markers)

Під час інсталяції або синхронізації середовища менеджер пакетів здійснює оцінку булевих виразів маркерів у пам'яті процесу без запитів до віддалених серверів.

Синтаксис маркерів регулюється стандартом PEP 508. Дозволені логічні оператори:
- Порівняння версій та рядків: `==`, `!=`, `<`, `<=`, `>`, `>=`, `===`.
- Входження у підрядок або список: `in`, `not in`.
- Логічні зв'язки: `and`, `or`, а також круглі дужки `( )` для групування пріоритетів.

Таблиця стандартних змінних середовища для розрахунку маркерів:

| Маркер PEP 508 | Приклад значення | Системне джерело у CPython |
|---|---|---|
| `os_name` | `'posix'`, `'nt'`, `'java'` | `os.name` |
| `sys_platform` | `'linux'`, `'darwin'`, `'win32'` | `sys.platform` |
| `platform_machine` | `'x86_64'`, `'arm64'`, `'aarch64'` | `platform.machine()` |
| `platform_python_implementation` | `'CPython'`, `'PyPy'`, `'GraalPy'` | `platform.python_implementation()` |
| `python_version` | `'3.12'` | `f"{sys.version_info.major}.{sys.version_info.minor}"` |
| `python_full_version` | `'3.12.3'` | `platform.python_version()` |
| `implementation_name` | `'cpython'`, `'pypy'` | `sys.implementation.name` |
| `extra` | `'test'`, `'docs'`, `'benchmark'` | Активна опціональна група залежностей маніфесту |

### Приклад складного виразу маркера:

```text
sys_platform == 'linux' and platform_machine == 'x86_64' and (python_version >= '3.11' or extra == 'speedups')
```

Якщо під час аналізу активного середовища вираз маркера обчислюється як `False`, менеджер пакетів повністю виключає цю залежність і не здійснює пошук відповідних коліс на диску чи в кеші.

## 3. Алгоритм підбору коліс (Wheel Tag Matching)

Коли пакет ідентифіковано як активний, інсталятор зіставляє теги файлів `.whl` із поточним оточенням за стандартом PEP 425:

```text
{distribution}-{version}(-{build_tag})?-{python_tag}-{abi_tag}-{platform_tag}.whl
```

Приклад зіставлення для `uvloop-0.19.0-cp312-cp312-manylinux_2_17_x86_64.whl`:
1. `python_tag = cp312`: відповідає версії інтерпретатора CPython 3.12.
2. `abi_tag = cp312`: вимагає бінарний інтерфейс CPython 3.12 без режиму Py_LIMITED_API (`abi3`).
3. `platform_tag = manylinux_2_17_x86_64`: сумісний з Linux-системами на базі `glibc >= 2.17` згідно зі специфікацією PEP 600.

Якщо доступні кілька сумісних коліс (наприклад, універсальне `py3-none-any` та специфічне `cp312-cp312-manylinux`), інсталятор віддає пріоритет найбільш спеціалізованому бінарному збиранню з максимальним рейтингом сумісності.

## 4. Прямі посилання та залежності Git (PEP 610)

Сучасний lock-файл підтримує точну фіксацію залежностей, отриманих безпосередньо з систем контролю версій Git, Mercurial або локальних шляхів монорепозиторію (Direct URL Data according to PEP 610):

```toml
[[package]]
name = "custom-auth"
version = "1.2.0"
source = { git = "https://github.com/company/custom-auth.git", commit = "d3b07384d113edec49eaa6238ad5ff00" }
dependencies = [
    { name = "cryptography" }
]
```

Фіксація повного 40-символьного SHA-1 / SHA-256 хешу коміту гарантує, що навіть якщо автор гілки оновить тег або перепише історію Git через `git push --force`, середовище збірки залишиться захищеним і незмінним.

## 5. Внутрішній життєвий цикл синхронізації файлової системи

Процедура синхронізації (Synchronization Lifecycle) складається з чотирьох строго детермінованих фаз:
1. **Зчитування каталогу `.dist-info`:** менеджер сканує каталог `site-packages` цільового віртуального середовища, парсить файли `METADATA`, `INSTALLER` та `RECORD` для кожного встановленого пакета і будує карту поточного фізичного стану.
2. **Обчислення дифу (Diff Computation):** порівнюються дві множини — `LockedPackages(Env)` (пакети з lock-файлу, що задовольняють маркери поточної платформи) та `InstalledPackages` (фактично наявні на диску). Формуються три списки дій: `Install`, `Update` та `Prune`.
3. **Атомарне видалення (Pruning):** усі файли, перелічені у файлах `RECORD` пакетів зі списку `Prune`, атомарно видаляються з файлової системи, очищаючи простір `site-packages` від застарілих бібліотек.
4. **Матеріалізація артефактів (Materialization):** відсутні пакети створюються через жорсткі посилання (Hardlinks) або посилання з копіюванням при записі (Reflinks) із глобального контентно-адресованого кешу користувача, після чого оновлюється підсумковий маніфест середовища.

## 6. Інтерфейс синхронізації та семантика прапорців CLI

Сучасні менеджери пакетів відокремлюють процедуру розв'язання графа (Resolution) від процедури фізичного приведення середовища до цільового стану (Synchronization).

```
+-------------------------------------------------------------------------+
|                        РЕЖИМИ ВИКОНАННЯ СИНХРОНІЗАЦІЇ                   |
+--------------------+----------------------------------------------------+
| Прапорець CLI      | Алгоритмічна семантика                             |
+--------------------+----------------------------------------------------+
| uv sync            | Зчитує pyproject.toml. Якщо маніфест новіший за    |
|                    | lock-файл, оновлює uv.lock через SAT і розгортає.  |
+--------------------+----------------------------------------------------+
| uv sync --locked   | Перевіряє manifest-hash у lock-файлі. Якщо замок   |
|                    | не відповідає pyproject.toml, зупиняє роботу       |
|                    | з кодом помилки. Не оновлює файл блокування.       |
+--------------------+----------------------------------------------------+
| uv sync --frozen   | Повністю ігнорує pyproject.toml і встановлює       |
|                    | точний зріз із uv.lock. Обов'язковий для CI/CD.    |
+--------------------+----------------------------------------------------+
```

### 6.1. Прапорці тонкого налаштування середовища

Менеджер `uv` надає додаткові параметри керування складом встановлюваних бібліотек:
- `--no-install-project`: встановлює виключно сторонні бібліотеки-залежності, не монтуючи сам поточний проєкт у віртуальне середовище (критично для оптимізації шарів Docker-образу).
- `--no-dev`: виключає секції залежностей для розробки (`[dependency-groups.dev]`), залишаючи лише виробничий контур (Production Runtime).
- `--all-extras`: примусово активує всі опціональні групи залежностей, оголошені в секції `[project.optional-dependencies]`.
- `--dry-run`: виводить повний план операцій додавання, оновлення та видалення файлів без модифікації файлової системи.

### 6.2. Порівняльна таблиця CLI-команд сучасних менеджерів

| Інженерна дія | `uv` | `Poetry` | `PDM` | `pip-tools` | `Pipenv` |
|---|---|---|---|---|---|
| **Генерація / Оновлення замка** | `uv lock` | `poetry lock` | `pdm lock` | `pip-compile` | `pipenv lock` |
| **Повна синхронізація venv** | `uv sync` | `poetry install --sync` | `pdm sync` | `pip-sync` | `pipenv sync` |
| **Суворий режим CI/CD** | `uv sync --frozen` | `poetry install --no-root --frozen` | `pdm sync --frozen` | `pip install --require-hashes` | `pipenv sync --deploy` |
| **Додавання нової залежності** | `uv add <pkg>` | `poetry add <pkg>` | `pdm add <pkg>` | Редагування `.in` + compile | `pipenv install <pkg>` |
| **Оновлення окремого пакета** | `uv lock --upgrade-package <pkg>` | `poetry update <pkg>` | `pdm update <pkg>` | `pip-compile --upgrade-package <pkg>` | `pipenv update <pkg>` |
| **Експорт у сумісний requirements** | `uv export -o req.txt` | `poetry export -f req.txt` | `pdm export -o req.txt` | Готовий `requirements.txt` | `pipenv requirements` |
