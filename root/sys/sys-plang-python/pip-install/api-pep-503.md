# 📋 Специфікація Simple Repository API: PEP 503 та PEP 691

Специфікація Simple Repository API є фундаментальним мережевим протоколом взаємодії між клієнтськими менеджерами встановлення пакунків (як-от `pip`, `uv`, `poetry` чи `pdm`) та серверами індексів (PyPI, Nexus, JFrog Artifactory, devpi або приватні S3-шлюзи). Цей документ регламентує структуру ендпоінтів, правила нормалізації назв проектів, механізми виявлення сумісних релізів, протокол узгодження вмісту через заголовки HTTP та формат передачі криптографічних контрольних сум для верифікації цілісності двійкових файлів.

---

## 1. Традиційний HTML-інтерфейс: PEP 503

Стандарт [PEP 503](https://peps.python.org/pep-0503/), розроблений Дональдом Стаффтом у 2015 році, формалізував мінімальний веб-інтерфейс на основі статичних або динамічно згенерованих HTML-сторінок. Головною метою стандарту було усунення хаотичного веб-скрейпінгу, який застосовувався у ранніх версіях `easy_install`.

### Нормалізація імен проєктів

Сервер репозиторію та клієнт зобов'язані приводити будь-яку назву проекту до єдиного канонічного вигляду за наступним правилом: усі літери переводяться в нижній регістр, а будь-які неперервні послідовності крапок, знаків підкреслення або дефісів замінюються на один символ дефісу `-`.

```python
import re

def normalize_project_name(name: str) -> str:
    return re.sub(r"[-_.]+", "-", name).lower()
```

Згідно з цим правилом, такі варіанти запису, як `My.Super_Package`, `my-super-package`, `my_super_package` та `MY...SUPER___PACKAGE`, є абсолютно ідентичними та вказують на один і той самий ресурс індексу: `my-super-package`.

### Структура ендпоінтів

Індекс Simple API організовано у вигляді двоетапного ієрархічного дерева URL:

1. **Кореневий індекс усіх проектів (`/simple/`):**
   Повертає повний перелік усіх зареєстрованих у репозиторії проектів. Сервер повинен повертати валідний документ HTML5:
   ```html
   <!DOCTYPE html>
   <html>
     <head>
       <meta name="pypi:repository-version" content="1.0">
       <title>Simple Index</title>
     </head>
     <body>
       <a href="/simple/flask/">flask</a>
       <a href="/simple/requests/">requests</a>
       <a href="/simple/urllib3/">urllib3</a>
     </body>
   </html>
   ```
   Порядок посилань не регламентується, проте рекомендується сортування за алфавітом. Усі посилання в кореневому списку повинні містити виключно нормалізовані імена.

2. **Індекс релізів конкретного проекту (`/simple/<project>/`):**
   Повертає список доступних для завантаження файлів дистрибутивів (`.whl`, `.tar.gz`, `.zip`):
   ```html
   <!DOCTYPE html>
   <html>
     <head>
       <meta name="pypi:repository-version" content="1.0">
       <title>Links for requests</title>
     </head>
     <body>
       <h1>Links for requests</h1>
       <a href="../../packages/requests-2.31.0-py3-none-any.whl#sha256=942c5a758f98d790eaed1a29cb6eefc7ffb0d1cf7af05c3dce7f496104d74e9e"
          data-requires-python="&gt;=3.7"
          data-dist-info-metadata="sha256=58b73a7d5ebf91b7ab19a3b98c56e3b5e4ffad5f4019a84a6b2c2c0119b48c66">
          requests-2.31.0-py3-none-any.whl
       </a>
       <a href="../../packages/requests-2.31.0.tar.gz#sha256=8a86644d6dbf82540d87997509db823910e9233446543bea01787f46c38860b8"
          data-requires-python="&gt;=3.7"
          data-yanked="Виявлено критичну регресію сесій у релізі">
          requests-2.31.0.tar.gz
       </a>
     </body>
   </html>
   ```

### Деталізація атрибутів посилань

- **Криптографічний хеш у фрагменті URL (`href="url#<hash_name>=<digest>"`):**
  Фрагмент URL містить контрольний дайджест файлу. Стандарт підтримує алгоритми `sha256`, `sha384`, `sha512` (використання застарілих `md5` та `sha1` заборонено сучасними специфікаціями). Наявність хешу дозволяє клієнту валідувати файл під час потокового завантаження без виконання додаткових запитів.
- **Специфікатор версії Python (`data-requires-python`):**
  Містить рядок сумісності згідно з PEP 440 (наприклад, `>=3.8, <3.12`). Якщо поточний інтерпретатор не відповідає вказаному предикату, клієнт `pip` зобов'язаний проігнорувати цей файл ще на етапі аналізу індексу, уникаючи зайвого завантаження непрацездатного коду.
- **Окремі метадані Core Metadata (`data-dist-info-metadata` / PEP 658):**
  Вказує, що сервер надає прямий доступ до файлу метаданих `.dist-info/METADATA` за адресою `<wheel-url>.metadata`. Значення атрибута може бути булевим (`true`) або містити хеш-суму файлу метаданих (`sha256=<hash>`). Завдяки цьому резолвер витягує інформацію про залежності, завантажуючи лише 2–5 КБ метаданих замість повного бінарного колеса розміром 50–500 МБ.
- **Відкликання релізу (`data-yanked` / PEP 592):**
  Атрибут свідчить про те, що автор пакета відкликав цей конкретний артефакт. Якщо значенням атрибута є непорожній рядок, він інтерпретується як текстова причина відкликання (наприклад, критична вразливість безпеки). Клієнт зобов'язаний відкинути цей файл під час автоматичного підбору версій, за винятком випадків, коли користувач явно зафіксував саме цю версію у своїх вимогах (`requests==2.31.0`).
- **Цифровий підпис GPG (`data-gpg-sig`):**
  Булевий атрибут, що вказує на наявність від'єднаного підпису за адресою `<file-url>.asc`. Вважається застарілим механізмом на користь прозорих криптографічних підписів Sigstore.

## 2. Сучасний JSON-інтерфейс: PEP 691 та PEP 700

Стандарт [PEP 691](https://peps.python.org/pep-0691/), прийнятий у 2022 році, стандартизував передачу даних індексу у форматі JSON, а стандарт [PEP 700](https://peps.python.org/pep-0700/) розширив його додатковими полями метаданих розміру та часу публікації.

### Протокол узгодження вмісту (Content Negotiation)

Клієнт ініціює запит до індексу, передаючи пріоритет підтримуваних MIME-типів у заголовку `Accept`:

```http
GET /simple/requests/ HTTP/1.1
Host: pypi.org
Accept: application/vnd.pypi.simple.v1+json, application/vnd.pypi.simple.v1+html;q=0.2, text/html;q=0.01
```

Сервер аналізує заголовок:
1. Якщо сервер підтримує JSON API, він повертає відповідь із заголовком `Content-Type: application/vnd.pypi.simple.v1+json`.
2. Якщо сервер підтримує лише HTML, він повертає `Content-Type: application/vnd.pypi.simple.v1+html` або стандартний `text/html`.

### Схема відповіді проекту (PEP 691 / PEP 700)

```json
{
  "meta": {
    "api-version": "1.1",
    "_last-serial": 18239012
  },
  "name": "requests",
  "files": [
    {
      "filename": "requests-2.31.0-py3-none-any.whl",
      "url": "https://files.pythonhosted.org/packages/70/8e/requests-2.31.0-py3-none-any.whl",
      "hashes": {
        "sha256": "942c5a758f98d790eaed1a29cb6eefc7ffb0d1cf7af05c3dce7f496104d74e9e",
        "blake2b": "20b22a628867a53696fb942c5a758f98d790eaed1a29cb6eefc7ffb0d1cf7af0"
      },
      "requires-python": ">=3.7",
      "core-metadata": {
        "sha256": "58b73a7d5ebf91b7ab19a3b98c56e3b5e4ffad5f4019a84a6b2c2c0119b48c66"
      },
      "yanked": false,
      "size": 62650,
      "upload-time": "2023-05-22T14:32:10.123456Z"
    },
    {
      "filename": "requests-2.31.0.tar.gz",
      "url": "https://files.pythonhosted.org/packages/c3/3e/requests-2.31.0.tar.gz",
      "hashes": {
        "sha256": "8a86644d6dbf82540d87997509db823910e9233446543bea01787f46c38860b8"
      },
      "requires-python": ">=3.7",
      "core-metadata": false,
      "yanked": "Знайдено критичну регресію",
      "size": 109520,
      "upload-time": "2023-05-22T14:30:00.000000Z"
    }
  ]
}
```

### Довідник полів об'єкта файлу в JSON API

- `filename` (*рядок, обов'язкове*): точне ім'я файлу дистрибутива.
- `url` (*рядок, обов'язкове*): абсолютний або відносний URL для завантаження файлу.
- `hashes` (*словник, обов'язкове*): асоціативний масив імен криптографічних алгоритмів та відповідних контрольних дайджестів у шістнадцятковому форматі (`hex`).
- `requires-python` (*рядок | null*): специфікатор версій Python (еквівалент `data-requires-python`).
- `core-metadata` (*словник | булеве значення | null*): об'єкт із хешами окремого файлу метаданих за адресою `<url>.metadata` або `false`, якщо метадані недоступні окремо.
- `yanked` (*булеве значення | рядок*): прапорець або текстова причина відкликання релізу.
- `size` (*ціле число, PEP 700*): точний розмір файлу в байтах.
- `upload-time` (*рядок у форматі ISO 8601, PEP 700*): позначка точного часу завантаження артефакту на сервер.

## 3. Інваріанти клієнта, кешування та обробка помилок HTTP

Під час реалізації серверів та клієнтів Simple Repository API мають виконуватися наступні обов'язкові технічні вимоги:

1. **Кешування HTTP (RFC 7234):**
   Сервери повинні супроводжувати відповіді індексу заголовками `ETag` (наприклад, хеш поточного стану проекту) або `Last-Modified`. Клієнт при повторному опитуванні ендпоінта зобов'язаний надсилати заголовки `If-None-Match` або `If-Modified-Since`. Отримання коду статусу `304 Not Modified` дозволяє миттєво використати локальний кеш списку релізів без передачі даних тіла відповіді.
2. **Обробка перенаправлень (Redirects):**
   Якщо клієнт надсилає запит на адресу без кінцевого слеша (наприклад, `/simple/requests`), сервер має повернути постійне перенаправлення `301 Moved Permanently` або `308 Permanent Redirect` на канонічну адресу `/simple/requests/`. Клієнт повинен прозоро слідувати перенаправленню зі збереженням заголовка `Accept`.
3. **Коди помилок:**
   - `404 Not Found`: пакет не зареєстрований у репозиторії.
   - `410 Gone`: проект або реліз було повністю вилучено з міркувань безпеки чи за рішенням модераторів.
   - `401 Unauthorized` / `403 Forbidden`: вимагається автентифікація через HTTP Basic Auth або Bearer Token (актуально для приватних корпоративних сховищ).
