# 📋 Конфігурація джерел pip та безпека ланцюга постачання

Конфігураційна підсистема менеджера пакунків `pip` визначає маршрутизацію мережевих запитів, політику використання локального кешу, криптографічну перевірку цілісності завантажених файлів, поведінку ізольованого збирання та налаштування безпеки з'єднання. Неправильне налаштування джерел або нерозуміння пріоритетів пошуку є однією з найпоширеніших причин компрометації програмних систем через атаки на ланцюг постачання (Supply Chain Attacks).

Цей довідник містить повний опис ієрархії конфігураційних рівнів, таблицю відповідності параметрів CLI, змінних оточення та конфігураційних файлів, а також перевірені архітектурні шаблони для захисту корпоративних середовищ.

---

## 1. Ієрархія рівнів конфігурації та правила перекриття

`pip` зчитує конфігураційні параметри з кількох джерел. Значення, визначені на вищому рівні ієрархії, повністю перекривають або розширюють значення, отримані з нижчих рівнів:

```
[1. Системний рівень] -> [2. Користувацький рівень] -> [3. Рівень venv] -> [4. Змінні оточення] -> [5. Прапорці CLI]
      (Найнижчий)                                                                                (Найвищий пріоритет)
```

### Фізичне розташування файлів конфігурації за операційними системами

| Рівень | POSIX / Linux | macOS | Windows |
|---|---|---|---|
| **1. Системний (Global)** | `/etc/pip.conf` або `/etc/xdg/pip/pip.conf` | `/Library/Application Support/pip/pip.conf` | `C:\ProgramData\pip\pip.ini` |
| **2. Користувацький (User)** | `~/.config/pip/pip.conf` або `~/.pip/pip.conf` | `~/Library/Application Support/pip/pip.conf` | `%APPDATA%\pip\pip.ini` |
| **3. Віртуальне оточення (Site)** | `$VIRTUAL_ENV/pip.conf` | `$VIRTUAL_ENV/pip.conf` | `%VIRTUAL_ENV%\pip.ini` |

Якщо системні змінні середовища `XDG_CONFIG_DIRS` або `XDG_CONFIG_HOME` перевизначені в операційній системі Linux, `pip` автоматично використовує вказані ними шляхи для пошуку конфігураційних файлів.

### Правила трансляції змінних середовища

Будь-який параметр конфігурації можна задати через змінну оточення процесу. Назва змінної формується шляхом додавання префікса `PIP_`, заміни дефісів на підкреслення та переведення всього рядка у верхній регістр:
- Опція CLI `--index-url` відповідає змінній `PIP_INDEX_URL`.
- Опція CLI `--extra-index-url` відповідає змінній `PIP_EXTRA_INDEX_URL`.
- Булевий прапорець `--no-index` активується через `PIP_NO_INDEX=1` або `PIP_NO_INDEX=true`.
- Опція `--require-hashes` активується через `PIP_REQUIRE_HASHES=1`.
- Спискові опції (наприклад, `--trusted-host` або `--find-links`) приймають значення, розділені пробілами: `PIP_TRUSTED_HOST="host1.corp host2.corp"`.

## 2. Структура секцій конфігураційного файлу

Конфігураційні файли `pip.conf` та `pip.ini` використовують стандартний синтаксис INI-файлів. Параметри групуються за підкомандами або діють глобально:

```ini
[global]
timeout = 45
index-url = https://artifactory.internal.corp/artifactory/api/pypi/pypi-virtual/simple
trusted-host = artifactory.internal.corp
no-cache-dir = false
retries = 3

[install]
require-hashes = true
no-build-isolation = false
prefer-binary = true
use-pep517 = true
upgrade-strategy = only-if-needed

[list]
format = columns

[wheel]
wheel-dir = /opt/vendor/wheels
```

Якщо параметр розміщено у секції `[global]`, він застосовується до кожної підкоманди (`install`, `wheel`, `download`, `list`). Параметри у спеціалізованих секціях (наприклад, `[install]`) діють виключно під час виклику відповідної підкоманди, перевизначаючи глобальні налаштування.

## 3. Детальний довідник ключових параметрів

### Маршрутизація та джерела пакетів

- **`index-url` (`--index-url <url>` / `PIP_INDEX_URL`):**
  Задає базову URL-адресу репозиторію Simple API. За замовчуванням: `https://pypi.org/simple`. Ця директива є ексклюзивною: вона повністю замінює публічний PyPI на вказаний сервер.
- **`extra-index-url` (`--extra-index-url <url>` / `PIP_EXTRA_INDEX_URL`):**
  Додає додаткову URL-адресу індексу, що опитується паралельно з основним.
  > ⚠️ **Критичне застереження безпеки:** `pip` опитує всі індекси одночасно без фіксованого пріоритету черги і обирає найвищу знайдену версію пакета. Це робить систему вразливою до атаки **Dependency Confusion**.
- **`find-links` (`--find-links <url|path>` / `PIP_FIND_LINKS`):**
  Вказує локальний каталог файлової системи або просту HTML-сторінку з прямими посиланнями на архіви `.whl` та `.tar.gz`. На відміну від `index-url`, джерело `find-links` не вимагає ієрархічної структури каталогів `/simple/<project>/`.
- **`no-index` (`--no-index` / `PIP_NO_INDEX`):**
  Повністю блокує будь-які мережеві звернення до репозиторіїв Simple API. Вимагає обов'язкової наявності локальних джерел через `find-links`.

### Безпека, криптографія та мережеві з'єднання

- **`require-hashes` (`--require-hashes` / `PIP_REQUIRE_HASHES`):**
  Вмикає обов'язковий режим верифікації криптографічних контрольних сум (Hash-checking Mode). Вимагає, щоб кожен запис у файлі `requirements.txt` супроводжувався директивою `--hash=sha256:...`. Автоматичне завантаження неоголошених транзитивних залежностей повністю блокується.
- **`trusted-host` (`--trusted-host <hostname>` / `PIP_TRUSTED_HOST`):**
  Додає хост до списку довірених, дозволяючи завантаження пакетів через незахищений протокол HTTP або через HTTPS із приватними самопідписаними сертифікатами без перевірки ланцюжка довіри CA.
- **`cert` (`--cert <path>` / `PIP_CERT`):**
  Вказує шлях до користувацького файлу кореневих сертифікатів у форматі PEM (CA Bundle) для валідації SSL/TLS з'єднань із внутрішніми корпоративними серверами.
- **`client-cert` (`--client-cert <path>` / `PIP_CLIENT_CERT`):**
  Шлях до клієнтського SSL-сертифіката (та опціонального закритого ключа) для двосторонньої TLS-автентифікації (mTLS).
- **`proxy` (`--proxy <[user:passwd@]proxy.server:port>` / `PIP_PROXY`):**
  Задає мережевий проксі-сервер для HTTP та HTTPS з'єднань.

### Збирання, компіляція та оновлення залежностей

- **`no-build-isolation` (`--no-build-isolation` / `PIP_NO_BUILD_ISOLATION`):**
  Вимикає створення ізольованого віртуального середовища під час збирання пакетів із вихідних кодів (PEP 517 / PEP 518). `pip` виконує бекенд збирання у поточному середовищі, використовуючи вже встановлені інструменти (наприклад, системний `setuptools` або `cython`).
- **`prefer-binary` (`--prefer-binary` / `PIP_PREFER_BINARY`):**
  Змушує резолвер надавати перевагу старішій версії готового двійкового колеса (`wheel`), якщо найновіша доступна версія пакета опублікована лише у вигляді вихідного архіву (`sdist`).
- **`upgrade-strategy` (`--upgrade-strategy <eager|only-if-needed>` / `PIP_UPGRADE_STRATEGY`):**
  Визначає стратегію оновлення залежностей під час виклику `pip install --upgrade`:
  - `only-if-needed` (за замовчуванням): оновлює залежність лише у випадку, якщо її поточна встановлена версія не відповідає новим вимогам оновлюваного пакета.
  - `eager`: примусово оновлює всі прямі та транзитивні залежності до максимально можливих версій.
- **`dry-run` (`--dry-run`):**
  Виконує повний цикл роботи резолвера, завантаження метаданих та перевірки конфліктів без фізичної зміни файлів на диску, виводячи підсумковий план дій.
- **`only-binary` (`--only-binary <all|package_name>` / `PIP_ONLY_BINARY`):**
  Забороняє збирання пакетів із вихідних кодів, вимагаючи наявності виключно готових коліс `.whl`.
- **`no-binary` (`--no-binary <all|package_name>` / `PIP_NO_BINARY`):**
  Примушує `pip` ігнорувати скомпільовані колеса й завжди збирати пакет із вихідного дистрибутива `sdist`.
- **`break-system-packages` (`--break-system-packages` / `PIP_BREAK_SYSTEM_PACKAGES`):**
  Ігнорує системний маркер [PEP 668](https://peps.python.org/pep-0668/) (`EXTERNALLY-MANAGED`), дозволяючи примусове встановлення або оновлення пакетів у системному каталозі Linux.
  > ⚠️ **Попередження:** Використання цієї опції несе ризик пошкодження системного менеджера пакунків операційної системи (`apt`, `dnf`, `pacman`). Рекомендується використовувати віртуальні середовища замість прапорця перекриття.
- **`config-settings` (`--config-settings <KEY=VALUE>`):**
  Передає довільні параметри конфігурації безпосередньо бекенду збирання PEP 517 (наприклад, прапорці компілятора для `meson-python` або `maturin`).

## 4. Практичні конфігураційні патерни

### Патерн 1: Корпоративний проксі-репозиторій (Захист від Dependency Confusion)

Щоб унеможливити підміну приватних внутрішніх пакетів публічними версіями-двійниками з PyPI, у корпоративному контурі налаштовується єдиний віртуальний репозиторій Nexus або Artifactory. Всі клієнти конфігуруються виключно через директиву `index-url`:

```ini
# /etc/pip.conf або $VIRTUAL_ENV/pip.conf
[global]
index-url = https://nexus.corp.internal/repository/pypi-all/simple
cert = /etc/ssl/certs/corp-internal-ca.pem
timeout = 30
# extra-index-url ЗАБОРОНЕНО використовувати
```

### Патерн 2: Повністю автономний ізольований контур (Air-Gapped / Offline)

У виробничих середовищах військового призначення, критичної інфраструктури або банківських дата-центрів доступ до зовнішньої мережі заблоковано на рівні фаєрволу. Інсталяція виконується з попередньо перевіреного локального сховища:

```ini
[global]
no-index = true
find-links = /opt/vendor/wheels
no-cache-dir = true

[install]
require-hashes = true
only-binary = :all:
```

Команда запуску інсталяції:

```bash
pip install --no-index --find-links=/opt/vendor/wheels -r /opt/app/requirements.txt
```

### Патерн 3: Суворе закріплення в CI/CD пайплайнах

Для забезпечення абсолютної детермінованості складання Docker-образів у CI/CD рекомендується передавати параметри через системні змінні оточення в `Dockerfile`:

```dockerfile
ENV PIP_NO_CACHE_DIR=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1 \
    PIP_REQUIRE_HASHES=1

RUN pip install -r requirements.lock
```

## 5. Діагностика, керування конфігурацією та аудит кешу

Для перевірки ефективної конфігурації, інспекції кешу та пошуку конфліктних параметрів `pip` надає вбудовану підсистему діагностики:

```bash
# Вивести всі активні параметри з зазначенням файлу, де їх визначено
pip config list -v

# Отримати поточне значення конкретного параметра
pip config get global.index-url

# Встановити нове значення в конфігураційний файл поточного віртуального середовища
pip config --site set global.index-url https://artifactory.corp/simple

# Переглянути статистику локального кешу пакетів
pip cache info

# Повністю очистити кеш коліс та HTTP-відповідей
pip cache purge

# Вивести повний діагностичний звіт про системні шляхи, CA-сертифікати та теги коліс
pip debug
```

Виклик `pip debug` є найшвидшим способом отримати вичерпний список підтримуваних тегів платформи (`Compatible tags`) для поточної версії CPython, що дозволяє миттєво з'ясувати причину відхилення скомпільованого двійкового колеса.
