# 📋 Програмний інтерфейс модуля runpy та функції запуску C API

Модуль стандартної бібліотеки `runpy` та пов'язаний набір низькорівневих функцій CPython C API надають програмний контроль над процесами пошуку завантажувачів, ізоляції просторів імен та запуску байткоду в контексті головної точки входу `__main__`. На відміну від звичайної інструкції `import`, яка завжди виконує модуль під його власним канонічним ім'ям та кешує результат у глобальній таблиці `sys.modules`, ці інтерфейси дозволяють динамічно конфігурувати метадані виконання (`__name__`, `__package__`, `__spec__`) та керувати ступенем модифікації системного стану інтерпретатора.

## 1. Програмний інтерфейс модуля стандартної бібліотеки `runpy`

Модуль `runpy` реалізує внутрішню логіку прапорця командного рядка `-m` та функції запуску файлів за довільними шляхами без їхнього постійного додавання до реєстру імпортованих пакунків.

### 1.1. Функція `runpy.run_module`

```python
def run_module(
    mod_name: str,
    init_globals: dict[str, object] | None = None,
    run_name: str | None = None,
    alter_sys: bool = False
) -> dict[str, object]: ...
```

Функція знаходить модуль у системних шляхах `sys.path` за допомогою стандартного ланцюга пошуку `sys.meta_path`, отримує його скомпільований об'єкт коду `PyCodeObject` і виконує його у виділеному словнику глобальних змінних.

#### Параметри та їхня системна дія:

1. `mod_name` (`str`, обов'язковий):
   Повне кваліфіковане ім'я модуля (наприклад, `'http.server'` або `'app.services.worker'`). Якщо зазначене ім'я посилається на пакет (каталог, що містить `__init__.py`), функція автоматично перевіряє наявність внутрішнього підмодуля `mod_name.__main__`. Якщо такий файл знайдено, виконується саме він, а якщо ні — генерується виняток `ImportError`.
2. `init_globals` (`dict[str, object] | None`, за замовчуванням `None`):
   Словник, значення якого копіюються в глобальний простір імен модуля перед виконанням першого байткод-опокоду. Це дозволяє передавати вхідні змінні, мок-об'єкти або конфігураційні параметри безпосередньо в глобальний контекст цільового скрипту.
3. `run_name` (`str | None`, за замовчуванням `None`):
   Рядкове значення, яке записується в атрибут `__name__` виконуваного модуля. Якщо передано `None`, поведінка залежить від прапорця `alter_sys`: при `alter_sys=False` встановлюється значення `mod_name`, а при `alter_sys=True` атрибут примусово отримує значення `'__main__'`.
4. `alter_sys` (`bool`, за замовчуванням `False`):
   Керує ступенем мутації глобального стану віртуальної машини:
   - Якщо `False` (безпечний режим для виклику з коду бібліотеки), функція не зачіпає системні структури: модуль `sys.modules['__main__']` залишається незмінним, `sys.argv[0]` не модифікується, а всі створені змінні повертаються лише у вихідному словнику.
   - Якщо `True` (режим повної емуляції CLI), функція замінює словник `sys.modules['__main__'].__dict__` на простір імен запущеного модуля та оновлює `sys.argv[0]`, записуючи туди фізичний шлях до знайденого файлу.

#### Повертане значення та винятки:
- **Повертає:** результуючий словник `dict[str, object]`, що представляє фінальний стан глобального простору імен (`globals()`) після завершення виконання модуля.
- **Винятки:**
  - `ImportError`: модуль не вдалося знайти в жодному з каталогів `sys.path`, або пакет не містить обов'язкового файлу `__main__.py`.
  - Будь-які винятки часу виконання (`RuntimeError`, `ValueError`, `SystemExit` тощо), згенеровані кодом самого модуля під час роботи. Винятки не приховуються і прокидаються у викликальний стек.

### 1.2. Функція `runpy.run_path`

```python
def run_path(
    path_name: str | os.PathLike[str],
    init_globals: dict[str, object] | None = None,
    run_name: str | None = None
) -> dict[str, object]: ...
```

Функція виконує вихідний код Python, переданий як фізичний шлях у файловій системі операційної системи.

#### Типи підтримуваних цілей `path_name`:
1. **Звичайний вихідний файл (`.py`):** зчитується, компілюється в об'єкт коду і виконується.
2. **Скомпільований байткод (`.pyc`):** розпаковується з формату маршалінгу і виконується безпосередньо.
3. **Каталог файлової системи:** функція тимчасово монтує шлях каталогу в `sys.path[0]`, знаходить у ньому файл `__main__.py` і виконує його.
4. **ZIP-архів або zipapp (`.zip`, `.pyz`):** підключає механізм `zipimport`, додає архів до `sys.path[0]` і запускає кореневий `__main__.py`.

#### Особливості модифікації шляхів пошуку:
На час виконання цільового файлу або архіву функція `run_path` вносить тимчасові зміни в `sys.path[0]`:
- Для окремого файлу записується каталог цього файлу (`os.path.dirname(path_name)`).
- Для каталогу чи ZIP-архіву записується повний шлях до самого каталогу/архіву.
- Після завершення роботи функції (навіть у разі виникнення аварійного винятку завдяки блоку `finally`) початкове значення `sys.path[0]` гарантовано відновлюється.

## 2. Інтерфейс запуску CPython C API

Для системних застосунків, які вбудовують інтерпретатор Python (Game Engines, системні сервіси, бази даних), мова C надає багаторівневий набір функцій ініціалізації та виконання.

### 2.1. Функції запуску коду C API

| Сигнатура функції C API | Рівень ініціалізації | Обробка помилок і повернене значення | Семантика та системна дія |
| :--- | :--- | :--- | :--- |
| `int PyRun_SimpleFileExFlags(FILE *fp, const char *filename, int closeit, PyCompilerFlags *flags)` | Вимагає попереднього виклику `Py_Initialize()` | Повертає `0` при успіху, `-1` у разі виникнення необробленого винятку | Зчитує потік файлу `fp`, компілює його як головний скрипт і виконує в словнику `sys.modules['__main__']`. Якщо `closeit != 0`, автоматично закриває дескриптор `fp` після зчитування. |
| `int PyRun_SimpleStringFlags(const char *command, PyCompilerFlags *flags)` | Вимагає попереднього виклику `Py_Initialize()` | Повертає `0` при успіху, `-1` при винятку | Виконує рядок вихідного коду `command` у контексті модуля `__main__`. Зручно для виконання швидких скриптів ініціалізації. |
| `PyObject* PyRun_StringFlags(const char *str, int start, PyObject *globals, PyObject *locals, PyCompilerFlags *flags)` | Повна ініціалізація CPython | Повертає новий вказівник `PyObject*` з результатом виразу або `NULL` при збої | Низькорівневе виконання рядка в явно переданих словниках `globals` та `locals`. Параметр `start` визначає граматику: `Py_file_input` (послідовність інструкцій), `Py_eval_input` (окремий вираз), `Py_single_input` (інтерактивна команда). |
| `int Py_RunMain(void)` | Працює в межах архітектури `PyConfig` (PEP 587) | Повертає цілочисельний код завершення процесу (`0..255`) | Головна точка входу runtime CPython. Зчитує налаштування полів `run_filename`, `run_module` або `run_command` з конфігурації `PyConfig`, виконує відповідну точку входу та коректно очищає ресурси середовища. |

### 2.2. Конфігурація структури `PyConfig` (Python 3.8+, PEP 587)

Сучасний C API стандартизує конфігурацію точки входу через поля структури `PyConfig`. Усі рядкові поля використовують формат широких символів `wchar_t*`:

```c
typedef struct {
    int parse_argv;            /* 1 = парсити аргументи командного рядка CLI */
    wchar_t *run_command;      /* Команда для запуску (аналог прапорця -c) */
    wchar_t *run_module;       /* Модуль для запуску через runpy (аналог -m) */
    wchar_t *run_filename;     /* Шлях до файлу, каталогу або zipapp */
    
    PyConfig_Argv argv;        /* Список аргументів для заповнення sys.argv */
    PyConfig_Argv orig_argv;   /* Оригінальні аргументи операційної системи */
    /* ... додаткові поля шляхів та алокаторів пам'яті ... */
} PyConfig;
```

#### Взаємовиключність та пріоритетність режимів запуску в `PyConfig`:
1. **`run_command`:** якщо поле заповнено (наприклад, `L"import sys; print(sys.version)"`), CPython ігнорує файлову систему і виконує рядок коду. Атрибут `sys.argv[0]` встановлюється в рядок `"-c"`.
2. **`run_module`:** інтерпретатор ініціалізує середовище, додає поточний робочий каталог до `sys.path[0]` та викликає внутрішню функцію `runpy._run_module_as_main()`. Атрибут `__name__` встановлюється в `'__main__'`, а `__package__` заповнюється іменем батьківського вузла.
3. **`run_filename`:** інтерпретатор відкриває переданий шлях. Якщо шлях є каталогом або ZIP-архівом, виконується пошук `__main__.py`; якщо файлом — код виконується безпосередньо, а каталог файлу записується в `sys.path[0]`.

## 3. Маніпуляція простором імен `__main__` через C API

Під час вбудовування інтерпретатора виникає потреба програмно зчитувати або записувати змінні в модуль `__main__` без виконання зовнішніх файлів.

### Функції доступу до простору імен:
- `PyObject* PyImport_AddModule(const char *name)`: повертає об'єкт модуля з таблиці `sys.modules`. Якщо модуль ще не створено, функція алокує новий `PyModuleObject`, реєструє його в `sys.modules` та повертає вказівник. Для головного модуля викликається як `PyImport_AddModule("__main__")`.
- `PyObject* PyModule_GetDict(PyObject *module)`: повертає внутрішній словник простору імен модуля (`module.__dict__`).

### Інваріанти безпеки роботи з пам'яттю та потоками:
1. **Запозичені посилання (Borrowed References):** функція `PyModule_GetDict()` повертає запозичене посилання на словник модуля. Заборонено викликати `Py_DECREF()` для отриманого словника, оскільки це призведе до передчасного знищення таблиці символів модуля та краху віртуальної машини при наступній операції запису.
2. **Глобальне блокування інтерпретатора (GIL):** будь-які виклики функцій `PyRun_*`, `PyImport_*` та операції зі словником `PyDict_*` дозволені виключно після захоплення GIL поточним системним потоком через виклик `PyGILState_Ensure()`. Після завершення роботи блокування звільняється викликом `PyGILState_Release()`.
3. **Обробка та очищення помилок:** якщо функція виконання повертає `-1` або `NULL`, інтерпретатор встановлює внутрішній індикатор винятку. Хост-програма зобов'язана або роздрукувати виняток через `PyErr_Print()`, або перехопити та очистити його викликом `PyErr_Clear()`, інакше наступний виклик C API завершиться непередбачуваною аварією через залишковий стан помилки.
