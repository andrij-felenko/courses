# Специфікація API мостів між асинхронним циклом та пулами виконання

Інтерфейси взаємодії між однопотоковим циклом подій `asyncio` та пулами системних потоків і процесів регламентують правила передачі завдань, збереження контексту виконання та потокобезпечної передачі результатів. Цей довідник містить точні сигнатури, опис параметрів, вимоги до безпеки потоків (*thread-safety*), поведінку контекстних змінних та семантику винятків для всіх компонентів моста.

## 1. Функції делегування завдань у пули виконання

### `asyncio.to_thread(func, /, *args, **kwargs)`

Функція високого рівня для асинхронного виконання блокувальної функції в окремому потоці (з'явилася у Python 3.9).

| Параметр / Атрибут | Тип | Опис |
|---|---|---|
| `func` | `Callable[..., T]` | Синхронна функція або об'єкт, що викликається. Позиційний аргумент. |
| `*args` | `Any` | Позиційні аргументи, що передаються у `func`. |
| `**kwargs` | `Any` | Іменовані аргументи, що передаються у `func`. |
| **Повертає** | `Coroutine[Any, Any, T]` | Корутина, результат очікування якої (`await`) повертає значення `T`. |
| **Контекст** | `contextvars` | **Автоматично копіює** поточний контекст (`contextvars.copy_context().run()`). |
| **Пул** | `Executor` | Використовує дефолтний `ThreadPoolExecutor` поточного циклу подій. |
| **Помилки** | `Exception` | Якщо `func` викидає виняток, він перехоплюється та повторно підіймається у точці `await`. |

#### Механізм роботи та життєвий цикл

Виклик `asyncio.to_thread()` виконує такі послідовні системні кроки:

1. **Захоплення контексту:** Отримує поточний екземпляр `contextvars.Context` через `contextvars.copy_context()`. Це гарантує, що значення локальних контекстних змінних (наприклад, ідентифікатори запитів `request_id` або поточний стан транзакції), встановлені в асинхронній задачі, будуть доступні всередині синхронної функції у фоновому потоці.
2. **Отримання циклу та пулу:** Звертається до `asyncio.get_running_loop()` і запитує дефолтний пул потоків `_default_executor`. Якщо дефолтний пул ще не було створено, інтерпретатор ініціалізує новий екземпляр `concurrent.futures.ThreadPoolExecutor`.
3. **Делегування виклику:** Передає обгортку `context.run(func, *args, **kwargs)` до методу `loop.run_in_executor(None, ...)`.
4. **Створення `Future`:** Повертає асинхронний об'єкт очікування. Коли системний потік завершує роботу, результат або згенерований виняток передається назад у головний потік циклу подій.

#### Обмеження скасування (Cancellation)

Якщо корутину, яка очікує завершення `asyncio.to_thread()`, скасовано через `task.cancel()`, об'єкт `asyncio.Future` переходить у стан скасування і генерує `asyncio.CancelledError` у точці `await`. Проте **системний потік операційної системи продовжить виконувати функцію `func` до кінця**. Операційні системи POSIX та Windows не дозволяють безпечно примусово переривати довільні системні потоки без ризику пошкодження пам'яті інтерпретатора CPython.

```python
import asyncio
import time

def blocking_disk_operation(filename: str, retry_count: int = 3) -> int:
    time.sleep(0.5)
    return len(filename) * retry_count

async def handle_request():
    # Безпечне винесення виклику без зупинки циклу подій
    result = await asyncio.to_thread(blocking_disk_operation, "report.pdf", retry_count=5)
    print(f"Обчислено розмір: {result}")
```

### `loop.run_in_executor(executor, func, *args)`

Низькорівневий метод екземпляра циклу подій `AbstractEventLoop` для запуску синхронної функції у вказаному пулі потоків або процесів.

| Параметр / Атрибут | Тип | Опис |
|---|---|---|
| `executor` | `Optional[concurrent.futures.Executor]` | Екземпляр `ThreadPoolExecutor`, `ProcessPoolExecutor` або `None`. Якщо `None`, використовується дефолтний пул. |
| `func` | `Callable[..., T]` | Синхронна функція для виконання. |
| `*args` | `Any` | Позиційні аргументи функції `func`. **Іменовані аргументи (`kwargs`) не підтримуються.** |
| **Повертає** | `asyncio.Future[T]` | Об'єкт майбутнього результату `asyncio`, готовий для `await`. |
| **Контекст** | `contextvars` | **Не копіює** контекст автоматично. Потрібне ручне обгортання. |
| **Помилки** | `Exception` | Винятки з `func` зберігаються у `Future` і викидаються при виконанні `await`. |

#### Відмінності між `ThreadPoolExecutor` та `ProcessPoolExecutor`

1. **При виклику з `ThreadPoolExecutor`:** Функція виконується у системному потоці в тому самому адресному просторі процесу. Дозволено передавати будь-які об'єкти Python за посиланням. Накладні витрати на виклик становлять одиниці мікросекунд. Проте байткод Python залишається обмеженим спільним замком GIL.
2. **При виклику з `ProcessPoolExecutor`:** Функція та всі її позиційні аргументи повинні підтримувати серіалізацію модулем `pickle`. Інтерпретатор серіалізує дані, відправляє їх через канали IPC до дочірнього процесу, де вони десеріалізуються та виконуються на власному ядрі процесора з окремим GIL. Накладні витрати на один виклик становлять сотні мікросекунд або мілісекунди залежно від обсягу даних.

```python
import asyncio
from concurrent.futures import ProcessPoolExecutor

def heavy_number_crunching(base: int, exponent: int) -> int:
    return pow(base, exponent, 1_000_000_007)

async def compute():
    loop = asyncio.get_running_loop()
    with ProcessPoolExecutor(max_workers=4) as pool:
        # Виклик процесу для обходу обмежень GIL
        val = await loop.run_in_executor(pool, heavy_number_crunching, 1234567, 9876543)
        print(f"Результат розрахунку: {val}")
```

### `loop.set_default_executor(executor)` та `loop.shutdown_default_executor()`

Керування життєвим циклом глобального пулу потоків для активного циклу подій.

- `loop.set_default_executor(executor)`: Замінює стандартний екземпляр `ThreadPoolExecutor` власним пулом із налаштованою кількістю потоків `max_workers` та кастомним префіксом імен `thread_name_prefix`.
- `await loop.shutdown_default_executor()` (Python 3.9+): Асинхронно очікує завершення всіх потоків дефолтного пулу під час зупинки циклу подій, запобігаючи втраті даних або аварійному завершенню програми.

## 2. Міжпотокова сигналізація та зворотні виклики

### `loop.call_soon_threadsafe(callback, *args, context=None)`

Планує виконання функції `callback` на наступній ітерації циклу подій. Це єдиний базовий метод класу `BaseEventLoop`, який дозволено безпечно викликати з будь-якого стороннього системного потоку.

| Параметр / Атрибут | Тип | Опис |
|---|---|---|
| `callback` | `Callable[..., Any]` | Функція, яка буде викликана в **головному потоці** циклу подій. |
| `*args` | `Any` | Аргументи, що передаються у `callback`. |
| `context` | `Optional[contextvars.Context]` | Контекст виконання (за замовчуванням створюється копія поточного). |
| **Повертає** | `asyncio.Handle` | Дескриптор запланованого виклику для можливого скасування. |
| **Thread-Safety** | **Так** | Повністю безпечний для виклику з паралельних потоків ОС. |

#### Механізм виходу селектора зі стану блокування

Коли цикл подій не має активних задач, він перебуває у стані очікування всередині системного виклику опитування дескрипторів (`epoll_wait`, `kevent` або `select`). Якщо інший системний потік просто додасть функцію у список `_ready`, цикл подій не дізнається про це до завершення поточного системного таймауту.

Для негайного пробудження циклу метод `call_soon_threadsafe()` використовує системний канал сповіщення (*Self-Pipe* або пару підключених сокетів `socket.socketpair()`):

1. Захоплює внутрішній м'ютекс `self._thread_safe_lock`.
2. Додає створений екземпляр `Handle` до списку запланованих викликів.
3. Записує один контрольний байт `b"\x00"` у записуючий кінець сокета або каналу `self._csock`.
4. Селектор операційної системи в головному потоці миттєво фіксує подію читання на читаючому сокеті `self._ssock`, перериває очікування `epoll_wait()` і переходить до виконання черги `_ready`.

### `asyncio.run_coroutine_threadsafe(coro, loop)`

Відправляє корутину `coro` на виконання в активний цикл подій `loop` із довільного зовнішнього системного потоку.

| Параметр / Атрибут | Тип | Опис |
|---|---|---|
| `coro` | `Coroutine[Any, Any, T]` | Об'єкт корутини, який має виконатися в потоці циклу `loop`. |
| `loop` | `AbstractEventLoop` | Цільовий активний цикл подій. |
| **Повертає** | `concurrent.futures.Future[T]` | Синхронний об'єкт майбутнього результату. |
| **Thread-Safety** | **Так** | Потокобезпечний метод для моста між потоками. |

#### Правила застосування та небезпека взаємного блокування (Deadlock)

Метод `asyncio.run_coroutine_threadsafe()` створює задачу `asyncio.Task` у цільовому циклі та повертає синхронний екземпляр `concurrent.futures.Future`. Зовнішній потік може заблокуватися на виклику `future.result(timeout=5.0)` до моменту, поки корутина не поверне значення.

**Критична помилка:** Ніколи не викликайте `future.result()` у тому самому системному потоці, де запущено цикл подій `loop`. Оскільки потік циклу подій буде заблокований очікуванням результату `Future`, він не зможе виконати жодної ітерації `_run_once()`, корутина ніколи не виконається, і програма потрапить у стан мертвого блокування (*deadlock*).

```python
import asyncio
import threading
import time

def sync_worker_thread(loop: asyncio.AbstractEventLoop):
    time.sleep(1.0)
    
    async def async_database_insert(record_id: int) -> str:
        await asyncio.sleep(0.1)  # Імітація асинхронного запиту
        return f"OK_{record_id}"

    # Безпечний запуск корутини з фонового потоку
    future = asyncio.run_coroutine_threadsafe(async_database_insert(42), loop)
    # Очікування відповіді з таймаутом
    result = future.result(timeout=2.0)
    print(f"Синхронний потік отримав результат: {result}")
```

### `asyncio.wrap_future(future, *, loop=None)`

Адаптує сторонній екземпляр `concurrent.futures.Future` (отриманий від довільного пулу потоків чи процесів) для використання в асинхронному коді через `await`.

| Параметр / Атрибут | Тип | Опис |
|---|---|---|
| `future` | `concurrent.futures.Future[T]` | Синхронний об'єкт майбутнього результату. |
| `loop` | `Optional[AbstractEventLoop]` | Цільовий цикл подій (за замовчуванням `asyncio.get_running_loop()`). |
| **Повертає** | `asyncio.Future[T]` | Асинхронний об'єкт Future. |

#### Механізм передачі результату

Метод реєструє функцію зворотного виклику на синхронному об'єкті через `future.add_done_callback()`. Коли робочий потік встановлює результат, цей колбек за допомогою `loop.call_soon_threadsafe()` переносить результат або виняток в об'єкт `asyncio.Future`, пробуджуючи корутину, яка чекає на `await`.

## 3. Порівняльний аналіз черг: asyncio.Queue проти queue.Queue

| Характеристика | `asyncio.Queue` | `queue.Queue` | `multiprocessing.Queue` |
|---|---|---|---|
| **Цільове середовище** | Єдиний потік Event Loop | Багатопотоковість ОС | Окремі процеси ОС |
| **Безпека потоків** | **Ні** (лише в межах Loop) | **Так** (`threading.Lock`) | **Так** (пайпи ОС + семафори) |
| **Читання даних** | `await q.get()` | `q.get(block=True)` | `q.get(block=True)` |
| **Запис даних** | `await q.put(item)` | `q.put(item, block=True)` | `q.put(item, block=True)` |
| **Запис із потоку в Loop** | `loop.call_soon_threadsafe(q.put_nowait, x)` | Прямий `q.put(x)` | Прямий `q.put(x)` |
| **Читання з корутини** | Прямий `await q.get()` | `await asyncio.to_thread(q.get)` | `await asyncio.to_thread(q.get)` |
| **Накладні витрати** | Мінімальні (~100 нс) | Низькі (~1 мкс) | Високі (~100 мкс через `pickle`) |

#### Вибір черги за типом архітектури

1. **В межах виключно асинхронного коду:** Використовуйте `asyncio.Queue`. Вона забезпечує максимальну швидкодію без накладних витрат на захоплення системних м'ютексів.
2. **Для передачі завдань пулу фонових потоків:** Використовуйте `queue.Queue`. Корутина записує дані через `await asyncio.to_thread(sync_q.put, item)`, а робочі потоки споживають їх через блокувальний `sync_q.get()`.
3. **Для передачі результатів із фонових потоків у цикл:** Використовуйте `asyncio.Queue`, наповнюючи її через виклик `loop.call_soon_threadsafe(async_q.put_nowait, item)`.
