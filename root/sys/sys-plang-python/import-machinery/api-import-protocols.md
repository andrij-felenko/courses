# 📋 Протоколи імпорту importlib та C-API

Підсистема імпорту CPython побудована на чітко специфікованих об'єктно-орієнтованих протоколах модуля `importlib` та наборі низькорівневих C-функцій. Цей довідник містить повний опис сигнатур, атрибутів, поведінкових контрактів та правил керування пам'яттю для розробників власних знахідників, завантажувачів та C/C++ розширень.

## 1. Специфікація модуля: об'єкт ModuleSpec

Клас `importlib.machinery.ModuleSpec` містить повні метадані, необхідні інтерпретатору для створення та завантаження модуля. Він виступає сполучною ланкою між фазою виявлення ресурсу та фазою його завантаження в пам'ять.

```python
class importlib.machinery.ModuleSpec(
    name: str,
    loader: Loader | None,
    *,
    origin: str | None = None,
    loader_state: Any = None,
    is_package: bool | None = None
)
```

При створенні екземпляра `ModuleSpec` інтерпретатор автоматично обчислює значення допоміжних властивостей. Зокрема, якщо прапорець `is_package` явно передано як `True`, поле `submodule_search_locations` ініціалізується порожнім списком, якщо воно не було задане окремо. Якщо ж передано `False`, це поле залишається рівним `None`.

| Атрибут | Тип | Опис та семантика |
|---|---|---|
| `name` | `str` | Повна кваліфікована назва модуля (наприклад, `os.path` чи `urllib.request`). |
| `loader` | `Loader \| None` | Екземпляр завантажувача, що відповідає за виконання коду модуля. Для просторових пакунків без коду може бути `_NamespaceLoader` або `None`. |
| `origin` | `str \| None` | Рядок, що вказує на фізичне джерело коду (шлях до файлу `.py`/`.so`, рядок `built-in`, `frozen` або URL). Для просторових пакунків дорівнює `None`. |
| `submodule_search_locations` | `list[str] \| None` | Список шляхів для пошуку дочірніх підмодулів. Якщо модуль є пакунком — містить список рядків (ініціалізує атрибут модуля `__path__`). Для звичайних модулів-файлів має значення `None`. |
| `loader_state` | `Any` | Довільний контейнер додаткових даних, специфічних для завантажувача (наприклад, відкритий дескриптор zip-архіву). |
| `cached` | `str \| None` | Шлях до скомпільованого файлу байткоду `.pyc`. Якщо модуль не кешується на диску — `None`. |
| `parent` | `str \| None` | Назва батьківського пакунка (наприклад, для `a.b.c` значенням буде `a.b`). Для модулів верхнього рівня — порожній рядок `""`. |
| `has_location` | `bool` | Прапорець, що показує, чи вказує `origin` на реальне фізичне місцезнаходження у файловій системі. |

## 2. Протоколи знахідників (Finders)

Знахідники відповідають виключно за виявлення модуля та генерацію об'єкта `ModuleSpec`. Їхнім контрактом заборонено створювати об'єкти модулів, виконувати сторонній код чи модифікувати словник `sys.modules`.

### `importlib.abc.MetaPathFinder`

Базовий абстрактний клас для знахідників найвищого пріоритету, зареєстрованих у системному списку `sys.meta_path`. Інтерпретатор послідовно викликає метод `find_spec` кожного зареєстрованого знахідника доти, доки один із них не поверне об'єкт `ModuleSpec`. Якщо знахідник не може знайти модуль, він зобов'язаний повернути `None`. Збудження винятків дозволяється лише у випадках фатальних системних збоїв або пошкодження структури сховища.

```python
class importlib.abc.MetaPathFinder:
    def find_spec(
        self,
        fullname: str,
        path: Sequence[str] | None,
        target: types.ModuleType | None = None
    ) -> ModuleSpec | None:
        """Шукає специфікацію модуля.
        
        Параметри:
          fullname: повна кваліфікована назва модуля.
          path: None для модулів верхнього рівня або значення __path__ 
                батьківського пакунка при імпорті підмодуля.
          target: існуючий модуль (передається лише під час перезавантаження reload()).
        """
        ...

    def invalidate_caches(self) -> None:
        """Скидає внутрішні кеші знахідника (викликається importlib.invalidate_caches())."""
        ...
```

Метод `invalidate_caches()` є обов'язковим для знахідників, які кешують стан файлової системи (наприклад, список файлів у каталогах). Виклик цієї функції гарантує, що новостворені файли на диску будуть коректно виявлені без перезапуску процесу інтерпретатора.

### `importlib.abc.PathEntryFinder`

Протокол для знахідників, прив'язаних до конкретного запису у списку шляхів (елемента `sys.path` або списку `pkg.__path__`). Вони створюються фабричними функціями, зареєстрованими у `sys.path_hooks`. Кожен екземпляр `PathEntryFinder` інкапсулює логіку пошуку лише в межах одного конкретного каталогу чи архіву.

```python
class importlib.abc.PathEntryFinder:
    def find_spec(
        self,
        fullname: str,
        target: types.ModuleType | None = None
    ) -> ModuleSpec | None:
        """Шукає специфікацію модуля в межах закріпленого каталогу/шляху."""
        ...

    def invalidate_caches(self) -> None:
        """Очищає кеш файлових дескрипторів або списків файлів каталогу."""
        ...
```

## 3. Протокол завантажувачів (Loaders)

Завантажувачі відповідають за створення екземпляра модуля та виконання його коду всередині простору імен. Стандарт PEP 451 вимагає чіткого розділення цих двох операцій.

### `importlib.abc.Loader`

```python
class importlib.abc.Loader:
    def create_module(self, spec: ModuleSpec) -> types.ModuleType | None:
        """Алокує новий об'єкт модуля.
        
        Повертає новий types.ModuleType або None. Якщо повернено None,
        CPython створює стандартний модуль types.ModuleType(spec.name).
        """
        return None

    def exec_module(self, module: types.ModuleType) -> None:
        """Виконує код модуля у просторі імен module.__dict__.
        
        Обов'язковий метод за стандартом PEP 451. Усі винятки,
        викинуті цим методом, призводять до відкату та видалення
        модуля з sys.modules.
        """
        ...

    def load_module(self, fullname: str) -> types.ModuleType:
        """Застарілий метод епохи PEP 302.
        
        У сучасному коді не реалізується; за замовчуванням емулюється
        через виклики create_module() та exec_module().
        """
        ...
```

Метод `create_module()` викликається інтерпретатором першим. Більшість завантажувачів повертають `None`, дозволяючи CPython виконати стандартну алокацію об'єкта `types.ModuleType` та заповнити службові атрибути (`__name__`, `__spec__`, `__loader__`, `__file__`, `__path__`). Власна реалізація `create_module` потрібна лише у специфічних випадках, наприклад, при завантаженні C-розширень або поверненні спеціальних проксі-об'єктів.

Метод `exec_module()` викликається після того, як новостворений модуль уже зареєстровано у словнику `sys.modules`. Це критично важливо для підтримки взаємних і циклічних імпортів. Завантажувач не повинен повертати значень із `exec_module`. Якщо під час виконання виникає необроблений виняток, ядро CPython гарантує видалення модуля з `sys.modules`, відновлюючи консистентний стан середовища.

### Додаткові методи інтроспекції та читання ресурсів

Для повної інтеграції з підсистемами налагодження, профілювання та пакункових ресурсів завантажувач може реалізовувати додаткові інтерфейси:

| Метод | Сигнатура | Призначення |
|---|---|---|
| `get_source` | `get_source(fullname: str) -> str \| None` | Повертає вихідний текст модуля у вигляді рядка або `None`, якщо модуль бінарний. |
| `get_code` | `get_code(fullname: str) -> types.CodeType \| None` | Повертає скомпільований об'єкт байткоду `PyCodeObject`. |
| `get_data` | `get_data(path: str) -> bytes` | Читає довільні бінарні байти за вказаним шляхом (використовується для пакункових ресурсів). |
| `is_package` | `is_package(fullname: str) -> bool` | Повертає `True`, якщо модуль є пакунком. |

## 4. Стандартні системні знахідники та завантажувачі CPython

У стандартній конфігурації CPython список `sys.meta_path` містить три базові знахідники, які реалізують завантаження всіх типів підтримуваних модулів:

| Клас | Модуль | Призначення |
|---|---|---|
| `BuiltinImporter` | `_frozen_importlib` | Знахідник і завантажувач статично скомпільованих C-модулів (`sys`, `builtins`). |
| `FrozenImporter` | `_frozen_importlib` | Знахідник і завантажувач замороженого байткоду ядра CPython. |
| `PathFinder` | `_frozen_importlib_external` | Знахідник верхнього рівня у `sys.meta_path`, що делегує пошук записів у `sys.path`. |
| `FileFinder` | `_frozen_importlib_external` | Реалізація `PathEntryFinder` для фізичних каталогів файлової системи. |
| `SourceFileLoader` | `_frozen_importlib_external` | Завантажувач вихідних файлів `.py`, відповідає за компіляцію та запис `.pyc`. |
| `SourcelessFileLoader` | `_frozen_importlib_external` | Завантажувач готових файлів байткоду `.pyc` без наявності вихідного `.py`. |
| `ExtensionFileLoader` | `_frozen_importlib_external` | Завантажувач бінарних динамічних бібліотек C/C++ (`.so`, `.pyd`). |
| `_NamespaceLoader` | `_frozen_importlib_external` | Фіктивний завантажувач для просторових пакунків PEP 420 (не виконує коду). |

## 5. Довідник функцій C-API підсистеми імпорту

Низькорівневий інтерфейс ядра CPython для взаємодії з імпортом із програм мовами C та C++. Усі функції вимагають наявності захопленого глобального блокування інтерпретатора (GIL) та валідного потокового стану `PyThreadState`.

### `PyImport_ImportModule`

:::tabs
```c
PyObject* PyImport_ImportModule(const char *name);
```
```cpp
// C++20 сигнатура RAII-обгортки
ScopedPyObject import_module(std::string_view name);
```
:::

Функція виконує спрощений імпорт модуля за його текстовою назвою, аналогічно виклику `__import__(name)` на рівні Python. Вона повертає нове посилання (*New reference*) на завантажений об'єкт модуля або `NULL` у разі виникнення помилки. У разі невдачі функція встановлює виняток `ModuleNotFoundError` або відповідний виняток ініціалізації. Викликаючий код зобов'язаний звільнити отримане посилання через `Py_DECREF()` після завершення використання модуля.

---

### `PyImport_ImportModuleLevelObject`

:::tabs
```c
PyObject* PyImport_ImportModuleLevelObject(
    PyObject *name,
    PyObject *globals,
    PyObject *locals,
    PyObject *fromlist,
    int level
);
```
```cpp
ScopedPyObject import_module_level(
    PyObject *name,
    PyObject *globals,
    PyObject *locals,
    PyObject *fromlist,
    int level
);
```
:::

Це фундаментальна функція C-API, яка реалізує виконання інструкції байткоду `IMPORT_NAME`. Вона приймає повний набір контекстних параметрів:

- `name`: рядок `PyUnicode` із назвою модуля.
- `globals`: словник глобальних змінних поточного кадру виклику (використовується для вилучення атрибутів `__package__` та `__spec__`).
- `locals`: словник локальних змінних (у сучасному CPython здебільшого ігнорується).
- `fromlist`: кортеж рядків імен об'єктів, що імпортуються (наприклад, `("foo", "bar")` для конструкції `from pkg import foo, bar`).
- `level`: ціле число, що визначає тип імпорту: `0` для абсолютного пошуку або додатне число `1, 2...`, яке позначає кількість крапок у відносному імпорті.

Функція повертає нове посилання на модуль або верхній пакунок (залежно від вмісту `fromlist`) чи `NULL` у разі збою.

---

### `PyImport_GetModuleDict`

:::tabs
```c
PyObject* PyImport_GetModuleDict(void);
```
```cpp
// Повертає запозичене посилання (Borrowed reference) на словник sys.modules
PyObject* get_module_dict() noexcept;
```
:::

Повертає глобальний словник кешу `sys.modules`. Повернене значення є запозиченим посиланням (*Borrowed reference*), тому лічильник посилань словника не збільшується. Функція ніколи не повертає `NULL`, за винятком випадків грубого пошкодження внутрішніх структур під час зупинки інтерпретатора. Модифікація цього словника напряму дозволяє втручатися в системний кеш імпорту.

---

### `PyImport_GetModule`

:::tabs
```c
PyObject* PyImport_GetModule(PyObject *name);
```
```cpp
ScopedPyObject get_module(PyObject *name);
```
:::

Безпечно видобуває модуль зі словника `sys.modules` за його об'єктом назви `PyUnicode`. На відміну від `PyImport_GetModuleDict()`, ця функція повертає нове посилання (*New reference*), що запобігає стану гонитви в багатопотокових середовищах, коли інший потік може видалити модуль зі словника під час читання. Якщо модуль не знайдено, функція повертає `NULL` без встановлення винятку.

---

### `PyImport_AddModule`

:::tabs
```c
PyObject* PyImport_AddModule(const char *name);
```
```cpp
// Повертає запозичене посилання на існуючий або новостворений модуль
PyObject* add_module(std::string_view name);
```
:::

Перевіряє наявність модуля з назвою `name` у словнику `sys.modules`. Якщо модуль знайдено, функція повертає запозичене посилання на нього. Якщо модуль відсутній, вона створює новий порожній екземпляр `types.ModuleType`, додає його до `sys.modules` та повертає запозичене посилання. Функція широко використовується у C-розширеннях для поступового заповнення нового простору імен константами та функціями.

---

### `PyImport_ExecCodeModule`

:::tabs
```c
PyObject* PyImport_ExecCodeModule(const char *name, PyObject *co);
```
```cpp
ScopedPyObject exec_code_module(std::string_view name, PyObject *co);
```
:::

Створює новий модуль із вказаним ім'ям `name`, атомарно додає його до `sys.modules` та виконує переданий скомпільований об'єкт байткоду `PyCodeObject *co` у просторі імен модуля. Повертає нове посилання на створений модуль або `NULL`, якщо виконання байткоду призвело до винятку.

---

### `PyImport_AppendInittab` та `PyImport_ExtendInittab`

:::tabs
```c
int PyImport_AppendInittab(const char *name, PyObject* (*initfunc)(void));
int PyImport_ExtendInittab(struct _inittab *newtab);
```
```cpp
int append_inittab(std::string_view name, PyObject* (*initfunc)(void)) noexcept;
int extend_inittab(struct _inittab *newtab) noexcept;
```
:::

Ці функції використовуються для статичної реєстрації користувацьких C-модулів у глобальній таблиці ініціалізації середовища `_PyImport_Inittab`. Реєстрація повинна відбуватися строго *до* виклику функції `Py_Initialize()`. Після ініціалізації інтерпретатора стандартний `BuiltinImporter` зможе знаходити та імпортувати зареєстровані модулі через звичайний вираз `import <name>`. Функції повертають `0` у разі успішної реєстрації або `-1` при виникненні помилки алокації системної пам'яті.
