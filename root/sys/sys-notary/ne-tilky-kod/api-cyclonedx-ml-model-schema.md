# 📋 Специфікація метаданих CycloneDX 1.6 та SPDX 3.0 для не-кодових компонентів

У стандартах Software Bill of Materials (SBOM) нового покоління — **CycloneDX 1.6** та **SPDX 3.0** — впроваджено першокласну підтримку не-кодових цифрових артефактів. На відміну від застарілих схем, які розглядали будь-який компонент виключно як вихідний код бібліотеки або двійковий файл пакунка, сучасні специфікації містять детальний понятійний апарат для опису моделей машинного навчання, навчальних датасетів, шрифтових ресурсів та закритих вендорських драйверів.

Цей довідник описує ключові поля, типи даних, семантику зв'язків та схеми валідації для документування не-кодових компонентів у складі програмно-апаратних комплексів.

## CycloneDX 1.6: Компонент типу `machine-learning-model`

У стандарті CycloneDX 1.6 для нейромереж та ML-артефактів використовується тип компонента `machine-learning-model` з обов'язковим об'єктом `modelCard`. Модельна картка (англ. *Model Card*) забезпечує повну прозорість щодо призначення нейромережі, архітектурних параметрів, кількісних метрик точності, обмежень застосування та юридичного походження навчальних даних.

### Поля опису навчальних датасетів (`datasets`)

Кожен навчальний датасет, на якому тренувалася модель, фіксується окремим об'єктом у маніфесті. Це дає змогу відстежувати юридичне походження та виявляти несанкціоноване використання даних із комерційними обмеженнями:

| Поле JSON | Тип | Обов'язкове | Опис призначення та семантика |
|---|---|---|---|
| `type` | String | Так | Тип набору даних: `dataset` або посилання через `ref`. |
| `name` | String | Так | Офіційна назва датасету (наприклад, `BearingFailureDataset-2025`). |
| `contents.url` | String | Ні | URI постійного зберігання (Zenodo, Hugging Face Hub, DVC, AWS S3). |
| `governance.licenses` | Array | Так | Повний ліцензійний ідентифікатор SPDX (наприклад, `CC-BY-4.0` або `CDLA-Permissive-2.0`). |
| `governance.sensitiveData` | Array | Ні | Маркування конфіденційності (наприклад, `non-personal`, `anonymized-telemetry`, `proprietary-lab`). |
| `governance.owners` | Array | Ні | Перелік юридичних осіб — власників майнових прав на дані. |

Об'єкт `governance` відіграє вирішальну роль у проведенні комплаєнс-аудиту. Якщо поле `governance.licenses` містить ідентифікатор `CC-BY-NC-4.0`, це означає, що ваги моделі скомпрометовані некомерційним статусом вихідних даних. Поле `sensitiveData` дозволяє аудиторам перевірити, чи не використовувалися під час навчання персональні дані або медична таємниця без належної згоди суб'єктів.

## CycloneDX 1.6: Компонент типу `data` для вбудованих шрифтів

Шрифтові ресурси у форматі TrueType/OpenType або растрові C-масиви гліфів описуються як компоненти даних (`type: "data"` або `type: "file"`). Головна мета опису — зафіксувати назву гарнітури, наявність прав на вшивання у ROM та дотримання правил модифікації:

```json
{
  "type": "data",
  "bom-ref": "font-roboto-embedded-rom-0x08040000",
  "name": "Roboto-Bold",
  "version": "2.138",
  "description": "Векторний TrueType шрифт для графічного дисплея панелі керування",
  "licenses": [
    {
      "license": {
        "id": "Apache-2.0",
        "url": "https://spdx.org/licenses/Apache-2.0.html"
      }
    }
  ],
  "properties": [
    {
      "name": "font:family",
      "value": "Roboto"
    },
    {
      "name": "font:weight",
      "value": "700"
    },
    {
      "name": "font:format",
      "value": "TrueType (.ttf)"
    },
    {
      "name": "font:target-rendering-engine",
      "value": "FreeType-2.13 / LVGL-v9"
    },
    {
      "name": "font:embedding-license-type",
      "value": "ROM-Embedded-Full"
    },
    {
      "name": "font:reserved-font-name",
      "value": "Roboto"
    }
  ],
  "hashes": [
    {
      "alg": "SHA-256",
      "content": "8f434346648f6b96df89dda901c5176b10a6d83961dd3c1ac88b59b2dc327aa4"
    }
  ]
}
```

Властивість `font:embedding-license-type` документує юридичну підставу присутності шрифту у прошивці:
- `OFL-Free-ROM`: вільне вбудовування під ліцензією SIL OFL 1.1 із дотриманням застереження про зарезервовану назву.
- `Commercial-OEM-Royalty`: комерційний контракт із виробником шрифту, за яким сплачуються роялті за кожен виготовлений апаратний пристрій.
- `Bitmap-Raster-Only`: ліцензійний дозвіл на використання виключно згенерованих растрових бітових матриць без поширення самого векторного файлу.

## CycloneDX 1.6: Компонент типу `device-driver` для вендорських блобів

Закриті об'єктні файли та статичні архіви HAL описуються типом `device-driver` або `library`. У властивостях фіксуються апаратні обмеження та статус ліцензійного дозволу:

| Властивість `properties` | Опис значення | Приклад значення |
|---|---|---|
| `vendor:silicon-target` | Дозволена родина мікроконтролерів | `STM32F4xx / Nordic nRF52840` |
| `vendor:license-grant` | Тип ліцензійного дозволу | `Production-Redistributable / Evaluation-Only` |
| `vendor:nda-required` | Вимога конфіденційності | `true / false` |
| `vendor:redistribution-allowed` | Право субліцензування замовникам | `true` |
| `vendor:crypto-export-class` | Клас експортного контролю криптографії | `ECCN-5D002 / Mass-Market` |

Якщо вендорський блоб має властивість `vendor:license-grant` зі значенням `Evaluation-Only`, система неперервної інтеграції зобов'язана зупинити випуск прошивки у виробництво, оскільки тестова ліцензія забороняє серійне поширення коду третім особам.

## SPDX 3.0: Профіль `AI` та класи `AIModelPackage` і `DatasetPackage`

У специфікації SPDX 3.0 запроваджено окремий логічний профіль **AI (Artificial Intelligence Profile)**. На відміну від плоских списків компонентів, SPDX 3.0 будує орієнтований граф об'єктів інтелектуальної власності, де моделі машинного навчання та їхні навчальні вибірки є повноправними сутностями.

### Ключові класи моделі даних SPDX 3.0:

1. **`AIModelPackage`:** спадкоємець базового класу `Package`, який представляє конкретний артефакт нейромережі.
   - `informationModality`: тип вхідних сигналів (`sensor`, `audio`, `image`, `timeseries`).
   - `energyConsumption`: середнє енергоспоживання під час виконання одного інференсу на цільовому мікроконтролері (у мікроджоулях).
   - `hardwareLimitation`: мінімальні вимоги до розміру пам'яті SRAM та Flash, а також наявність блоку плаваючої коми (FPU) або векторних інструкцій ARM Helium/DSP.
   - `hyperparameters`: словник гіперпараметрів навчання (швидкість навчання, оптимізатор, кількість епох, розмір батчу).

2. **`DatasetPackage`:** описує юридичне походження, повноту та склад навчальної вибірки.
   - `datasetType`: походження даних (`synthetic`, `measured`, `annotated`).
   - `dataCollectionProcess`: опис методології збору (наприклад, стендові випробування електродвигунів у лабораторних умовах).
   - `knownBiases`: задокументовані систематичні похибки або обмеження вибірки (наприклад, дані зібрано лише при кімнатній температурі).

3. **Відношення `trainedOn` та `hasModelWeight`:**
   - Зв'язок `AIModelPackage --[trainedOn]--> DatasetPackage` фіксує юридичну залежність скомпільованої моделі від конкретного набору даних.
   - Якщо `DatasetPackage` має ліцензію `CC-BY-NC-4.0`, автоматичний валідатор політик блокує комерційний випуск пов'язаного `AIModelPackage`.
   - Зв'язок `AIModelPackage --[hasModelWeight]--> Artifact` пов'язує логічну модель із конкретною двійковою секцією пам'яті у файлі ELF або дампі Flash.

## Правила валідації та інтеграція у збірку

Під час автоматизованого аудиту збірки інструмент перевірки відповідності (Compliance Policy Engine) застосовує такі обов'язкові інваріанти:

1. **Інваріант цілісності ваг (Weight Integrity Invariant):** SHA-256 хеш секції ваг у скомпільованій прошивці повинен суворо збігатися з хешем у записі `AIModelPackage` в SBOM. Будь-яка невідповідність свідчить про несанкціоновану підміну моделі або помилку компонування під час збирання образу.
2. **Інваріант комерційної чистоти (Commercial Cleanliness Invariant):** наявність ліцензії `CC-BY-NC` у будь-якому елементі графа залежностей `trainedOn` вважається критичною помилкою збірки (Critical Policy Violation).
3. **Інваріант шрифтового права (Font Embedding Rights Invariant):** якщо шрифт марковано комерційною ліцензією, властивість `font:embedding-license-type` повинна містити верифікований номер комерційного OEM-контракту з правовласником. У разі використання SIL OFL перевіряється обов'язкова наявність декларації `font:reserved-font-name`.
4. **Інваріант дистрибуції вендорських блобів (Vendor Redistribution Invariant):** компоненти типу `device-driver` зі значенням `vendor:license-grant == Evaluation-Only` блокують фінальну генерацію виробничого релізу прошивки.
5. **Інваріант експортного контролю (Export Compliance Invariant):** якщо компонент містить криптографічні примітиви з довжиною ключа понад 56 біт для симетричних або 512 біт для асиметричних шифрів, поле `vendor:crypto-export-class` повинно містити дійсний номер класифікації експортного контролю (ECCN).

Ці правила гарантують, що підсумковий документ SBOM є не просто пасивним звітом, а дієвим інструментом технічного контролю якості та юридичної безпеки пристрою.
