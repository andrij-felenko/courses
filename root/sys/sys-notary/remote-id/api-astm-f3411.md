# 📋 Специфікація двійкового протоколу ASTM F3411 та Open Drone ID

Стандарти ASTM F3411-19 / F3411-22a та гармонізований європейський регламент ASD-STAN prEN 4709-002 визначають відкритий канальний двійковий протокол для трансляції ідентифікаційних, навігаційних та системних даних безпілотних повітряних суден. Протокол оптимізовано для передачі в неліцензованому радіоефірі з жорсткими обмеженнями на розмір корисного навантаження (PDU), високим рівнем завад та одностороннім характером зв'язку (англ. *unidirectional broadcast*).

Базовою атомарною одиницею протоколу є фіксований **25-байтний двійковий блок**. Цей розмір обрано для того, щоб повідомлення гарантовано вміщувалося в єдиний рекламний пакет застарілого протоколу Bluetooth 4.2 Legacy Advertising (максимальний розмір корисного поля AD Structure якого становить 28 байтів, включно з 3 байтами заголовків сервісу). У сучасних фізичних середовищах Bluetooth 5 та Wi-Fi ці 25-байтні блоки агрегуються в єдиний масив за допомогою контейнера `Message Pack`.

---

### 1. Загальний заголовок повідомлення (Message Header)

Кожне 25-байтне повідомлення обов'язково починається з однобайтового поля `Header` (зсув 0):

```
Бітова структура байта 0:
+-------------------------------+-------------------------------+
|  Біти 7 .. 4                  |  Біти 3 .. 0                  |
|  Message Type (Тип повідомл.) |  Protocol Version (Версія)    |
+-------------------------------+-------------------------------+
```

- **Message Type (4 біти):**
  - `0x0` — Basic ID (Ідентифікатор безпілотного судна);
  - `0x1` — Location / Vector (Просторові координати, висота та вектор швидкості);
  - `0x2` — Authentication (Фрагменти цифрового криптографічного підпису);
  - `0x3` — Self-ID (Текстовий опис цілі або спеціального статусу польоту);
  - `0x4` — System Data (Координати оператора, висота точки зльоту та параметри зони);
  - `0x5` — Operator Location (Специфічні розширені координати пункту керування);
  - `0xF` — Message Pack (Контейнер об'єднання декількох повідомлень).
- **Protocol Version (4 біти):**
  - `0x0` — ASTM F3411-19 (початкова версія стандарту 2019 року);
  - `0x1` — ASTM F3411-22a та ASD-STAN prEN 4709-002 (діюча редакція стандарту).

### 2. Повідомлення 0x0: Basic ID (Ідентифікатор борту)

Повідомлення Basic ID транслює постійний або динамічний ідентифікатор безпілотника. За потреби передачі кількох ідентифікаторів (наприклад, заводського серійного номера виробника та реєстраційного коду цивільної авіаційної адміністрації) дрон транслює два окремих повідомлення Basic ID з різними типами `ID Type`.

| Зсув (байти) | Розмір | Назва поля | Тип даних | Призначення, діапазон та спеціальні значення |
|---|---|---|---|---|
| `0` | 1 байт | `Header` | `uint8_t` | Старші 4 біти: `0x0`, молодші 4 біти: `0x1` (версія 2) |
| `1` | 1 байт | `ID & UA Type` | `uint8_t` | Старші 4 біти: `ID Type`, молодші 4 біти: `UA Type` |
| `2 .. 21` | 20 байтів | `UAS ID` | `uint8_t[20]` | ASCII-рядок ідентифікатора або бінарний UUID |
| `22 .. 24` | 3 байти | `Reserved` | `uint8_t[3]` | Зарезервовано регулятором (заповнюється нулями `0x00`) |

#### Специфікація типів ідентифікатора (ID Type):
- `0` — None (Тип не визначено);
- `1` — Serial Number (Фізичний серійний номер виробника за стандартом ANSI/CTA-2063-A);
- `2` — CAA Registration ID (Офіційний номер реєстрації, виданий авіаційною владою держави);
- `3` — UTM Assigned UUID (Універсальний унікальний ідентифікатор, наданий сервісом UTM);
- `4` — Specific Session ID (Динамічний псевдонім польоту, що генерується для збереження приватності).

#### Класифікація типів літального апарата (UA Type):
- `0` — None / Undeclared (Не вказано або невизначений клас);
- `1` — Aeroplane (Класичний літак із нерухомим крилом);
- `2` — Helicopter (Однороторний гелікоптер із автоматом перекосу);
- `3` — Gyroplane (Автожир із вільнообертовим несучим гвинтом);
- `4` — Hybrid Lift (VTOL літак з комбінованою силовою установкою вертикального зльоту);
- `5` — Ornithopter (Махокрилий літальний апарат);
- `6` — Glider (Планер без власної рушійної установки);
- `7` — Kite (Керований повітряний змій);
- `8` — Free Balloon (Вільний некерований аеростат);
- `9` — Airship (Керований дирижабль);
- `10` — Free Fall / Parachute (Парашутна або скидна рятувальна система);
- `11` — Rocket (Ракета на твердопаливному чи рідинному двигуні);
- `12` — Tethered Powered Aircraft (Прив'язний дрон із живленням по кабелю);
- `13` — Ground Obstacle (Стаціонарна або рухома наземна навігаційна перешкода);
- `14` — Other (Інший нестандартний тип апарата);
- `15` — Hybrid Multirotor / Multirotor (Класичний багатороторний коптер — квадро-, гекса-, октокоптер).

### 3. Повідомлення 0x1: Location / Vector (Місцезнаходження та вектор руху)

Повідомлення транслюється з обов'язковою періодичністю не рідше ніж 1 раз на секунду (1 Гц) і містить просторово-часовий стан апарата у тривимірному просторі.

| Зсув | Розмір | Назва поля | Тип | Формули кодування та спеціальні значення |
|---|---|---|---|---|
| `0` | 1 Б | `Header` | `uint8_t` | Старші 4 біти: `0x1`, молодші 4 біти: `0x1` |
| `1` | 1 Б | `Status & Flags` | `uint8_t` | Біти 7..4: `Status`, біт 3: `EW Direction`, біти 2..0: `Height Ref` |
| `2` | 1 Б | `Direction` | `uint8_t` | Курс відносно півночі: `0 .. 359` градусів (`361` = невідомо) |
| `3` | 1 Б | `Speed Horizontal` | `uint8_t` | Горизонтальна швидкість: крок `0.25 м/с` (0..62.5 м/с) або `0.75 м/с` |
| `4` | 1 Б | `Speed Vertical` | `int8_t` | Вертикальна швидкість: крок `0.5 м/с` (`+` підйом, `-` спуск) |
| `5 .. 8` | 4 Б | `Latitude` | `int32_t` | Географічна широта: `grad · 10 000 000` (little-endian) |
| `9 .. 12` | 4 Б | `Longitude` | `int32_t` | Географічна довгота: `grad · 10 000 000` (little-endian) |
| `13 .. 14`| 2 Б | `Altitude Geodetic` | `uint16_t`| Геодезична висота WGS84: `(h_m + 1000) / 0.5` |
| `15 .. 16`| 2 Б | `Altitude Pressure` | `uint16_t`| Барометрична висота: `(h_baro_m + 1000) / 0.5` |
| `17 .. 18`| 2 Б | `Height AGL` | `uint16_t`| Висота над землею (Above Ground Level): `(h_agl + 1000) / 0.5` |
| `19` | 1 Б | `Horiz & Vert Acc` | `uint8_t` | Старші 4 біти: `HAcc` (0..13), молодші 4 біти: `VAcc` (0..13) |
| `20` | 1 Б | `Baro & Speed Acc` | `uint8_t` | Старші 4 біти: `BaroAcc`, молодші 4 біти: `SpeedAcc` |
| `21 .. 22`| 2 Б | `Timestamp` | `uint16_t`| Десяті частки секунди поточної години: `0 .. 35999` (крок 100 мс) |
| `23` | 1 Б | `Time & Adv Acc` | `uint8_t` | Старші 4 біти: `TimeAcc`, молодші 4 біти: `AdvInterval` |
| `24` | 1 Б | `Reserved` | `uint8_t` | Зарезервовано (`0x00`) |

#### Правила математичного кодування навігаційних параметрів:
1. **Географічні координати:** Кодуються у знакових 32-бітних цілих числах з фіксованою комою. Значення `0x7FFFFFFF` позначає відсутність даних або невалідний GPS-fix.
```
Lat_encoded = (int32_t)round(Latitude_deg * 10000000.0)
Lon_encoded = (int32_t)round(Longitude_deg * 10000000.0)
```
2. **Висота над еліпсоїдом (WGS84 HAE):** Для уникнення від'ємних чисел у випадках польотів у западинах (наприклад, район Мертвого моря) застосовується зміщення на 1000 метрів. Крок дискретизації становить 0.5 метра. Значення `0xFFFF` означає невідому висоту.
```
Alt_encoded = (uint16_t)round((Altitude_m + 1000.0) / 0.5)
```
3. **Часова мітка (Timestamp):** Визначає час створення навігаційного виміру всередині поточної астрономічної години UTC з дискретністю 0.1 с (100 мс). При переході через межу години лічильник скидається в 0.
```
Time_encoded = (Minute * 60 + Second) * 10 + (Milliseconds / 100)
```

### 4. Повідомлення 0x4: System Data (Дані оператора та місії)

Повідомлення транслює наземні параметри керування: розташування пункту дистанційного пілотування (GCS) або вихідної точки зльоту (Home Point), географічні межі зони операції та клас безпеки.

| Зсув | Розмір | Назва поля | Тип | Опис та правила квантування |
|---|---|---|---|---|
| `0` | 1 Б | `Header` | `uint8_t` | Старші 4 біти: `0x4`, молодші 4 біти: `0x1` |
| `1` | 1 Б | `Flags` | `uint8_t` | Біти 1..0: `Operator Loc Type`, біти 7..2: `Classification Type` |
| `2 .. 5` | 4 Б | `Operator Lat` | `int32_t` | Географічна широта оператора: `grad · 10 000 000` |
| `6 .. 9` | 4 Б | `Operator Lon` | `int32_t` | Географічна довгота оператора: `grad · 10 000 000` |
| `10 .. 11`| 2 Б | `Area Count` | `uint16_t`| Кількість апаратів, що одночасно виконують групову місію |
| `12` | 1 Б | `Area Radius` | `uint8_t` | Радіус зони операції: крок `10 метрів` (діапазон 0..2540 м) |
| `13 .. 14`| 2 Б | `Area Ceiling` | `uint16_t`| Верхня вертикальна межа зони: `(alt_m + 1000) / 0.5` |
| `15 .. 16`| 2 Б | `Area Floor` | `uint16_t`| Нижня вертикальна межа зони: `(alt_m + 1000) / 0.5` |
| `17` | 1 Б | `Category / Class`| `uint8_t` | Старші 4 біти: категорія ризику, молодші 4 біти: клас C0..C6 |
| `18 .. 19`| 2 Б | `Operator Altitude`|`uint16_t`| Геодезична висота пілота WGS84: `(alt_m + 1000) / 0.5` |
| `20 .. 23`| 4 Б | `System Timestamp` | `uint32_t`| Абсолютний час системи (UTC Unix Timestamp у секундах) |
| `24` | 1 Б | `Reserved` | `uint8_t` | Заповнюється нулем (`0x00`) |

### 5. Повідомлення 0x2: Authentication (Цифровий підпис)

Використовується для запобігання підробці навігаційного ефіру шляхом передачі фрагментованого криптографічного підпису ECDSA NIST P-256 або Ed25519.

| Зсув | Розмір | Назва поля | Тип | Опис поля для сторінки 0 та сторінок 1..N |
|---|---|---|---|---|
| `0` | 1 Б | `Header` | `uint8_t` | Старші 4 біти: `0x2`, молодші 4 біти: `0x1` |
| `1` | 1 Б | `Auth Type & Page` | `uint8_t` | Старші 4 біти: `Auth Type` (1=ECDSA, 2=Ed25519), молодші: `Page (0..15)` |
| `2` | 1 Б | `Last Page & Length`| `uint8_t` | Старші 4 біти: `Last Page Index` (типово 3), молодші: довжина сторінки 0 |
| `3 .. 6` | 4 Б | `Timestamp` | `uint32_t`| UTC час генерації підпису (секунди від епохи 01.01.2019) |
| `7 .. 23` | 17 Б | `Auth Data (Page 0)`| `uint8_t[17]`| Перші 17 байтів криптографічного підпису |
| `1 .. 23` | 23 Б | `Auth Data (Page N)`| `uint8_t[23]`| На сторінках від 1 до N поля `Timestamp` немає, всі 23 байти займає підпис |

### 6. Повідомлення 0xF: Message Pack (Агрегація)

Контейнер `Message Pack` дозволяє об'єднувати до 9 окремих 25-байтних повідомлень в єдиний монолітний масив для передачі в протоколах Bluetooth 5 та Wi-Fi.

```
Формат Message Pack (0xF):
+--------------------+--------------------+--------------------+----------------------------------------+
| Байт 0             | Байт 1             | Байт 2             | Байти 3 .. 3 + (N * 25) - 1            |
| Заголовок (0xF1)   | Розмір Msg (0x19)  | Кількість Msg (N)  | Масив упакованих повідомлень 0 .. N-1  |
+--------------------+--------------------+--------------------+----------------------------------------+
```

Типовий пакет мовлення містить 3 вкладених повідомлення (`N = 3`): Basic ID (25B) + Location (25B) + System Data (25B). Загальна довжина блоку становить: `3 + (3 * 25) = 78 байтів`.

---

### 7. Транспортні константи та радіозаголовки

1. **Bluetooth Low Energy:**
   - Поле `AD Type`: `0x16` (Service Data — 16-bit UUID);
   - Зареєстрований UUID ASTM: `0xFFFA` (передається як `0xFA, 0xFF`);
   - Загальний розмір пакета Legacy AD PDU: `3 байти Flags` + `4 байти Service Header` + `25 байтів ODID` = 32 байти.

2. **Wi-Fi 802.11 Vendor Specific Information Element:**
   - Поле `Element ID`: `221` (`0xDD`);
   - Довжина `Length`: `4 + розмір Message Pack` (наприклад, `4 + 78 = 82 байти` / `0x52`);
   - Поле `OUI`: `0xFA, 0x0B, 0xBC` (Wi-Fi Alliance allocated for Remote ID);
   - Поле `OUI Type`: `0x0D` (Open Drone ID Application Subtype).
