# 📋 Структури дескрипторів USB Device Descriptor та полів Bluetooth EIR

Для конфігурації мікроконтролера, низькорівневої розробки USB-прошивки чи формування широкомовних радіопакетів Bluetooth розробник зобов'язаний точно розмістити офіційні ідентифікатори (VID, PID, OUI, SIG Company ID) у стандартизованих двійкових структурах даних. Помилка у зміщенні байта, невірний порядок байтів (endianness) чи некоректний прапорець класу призводять до збою ініціалізації пристрою в операційній системі, відмови завантаження драйвера або блокування пакетів у радіоефірі.

У цій довідковій специфікації наведено двійкові структури, зміщення полів, правила формування бітових масок та інваріанти валідації для дескрипторів USB Device Descriptor, дескрипторів бінарних об'єктів BOS, розширених дескрипторів Microsoft OS 2.0, а також пакетів Bluetooth Low Energy Advertising Data та Extended Inquiry Response (EIR).

---

### 1. Дескриптор пристрою USB (Device Descriptor)

Дескриптор пристрою передається хосту у відповідь на стандартний запит керування `GET_DESCRIPTOR` із типом `0x01` на нульовій кінцевій точці (Endpoint 0). Цей блок даних має фіксовану довжину 18 байтів і визначає глобальні характеристики фізичного пристрою.

```
Структура USB Device Descriptor (USB 2.0 / USB 3.2 Specification):
+--------+------+----------+-------------------+---------------------------------------------------------+
| Зсув   | Байт | Тип      | Назва поля        | Опис та значення                                        |
+--------+------+----------+-------------------+---------------------------------------------------------+
| 0x00   | 1    | uint8_t  | bLength           | Розмір дескриптора у байтах (завжди 0x12 = 18).         |
| 0x01   | 1    | uint8_t  | bDescriptorType   | Тип дескриптора (0x01 = DEVICE).                        |
| 0x02   | 2    | uint16_t | bcdUSB            | Версія специфікації USB у двійково-десятковому форматі: |
|        |      |          |                   | 0x0200 = USB 2.0, 0x0210 = USB 2.1 (BOS), 0x0320 = 3.2. |
| 0x04   | 1    | uint8_t  | bDeviceClass      | Клас пристрою (0x00 = дивитися дескриптор інтерфейсу,   |
|        |      |          |                   | 0x02 = CDC, 0xEF = Miscellaneous Multi-function).       |
| 0x05   | 1    | uint8_t  | bDeviceSubClass   | Підклас пристрою (0x00 або 0x02 для IAD).               |
| 0x06   | 1    | uint8_t  | bDeviceProtocol   | Протокол пристрою (0x00 або 0x01 для IAD).              |
| 0x07   | 1    | uint8_t  | bMaxPacketSize0   | Максимальний розмір пакета Endpoint 0 (8, 16, 32, 64,   |
|        |      |          |                   | або 9 = 512 байтів у SuperSpeed).                       |
| 0x08   | 2    | uint16_t | idVendor          | 16-бітний Vendor ID, призначений USB-IF (little-endian).|
| 0x0A   | 2    | uint16_t | idProduct         | 16-бітний Product ID, призначений виробником (LE).      |
| 0x0C   | 2    | uint16_t | bcdDevice         | Номер ревізії виробу в BCD (наприклад, 0x0100 = v1.0.0).|
| 0x0E   | 1    | uint8_t  | iManufacturer     | Індекс рядкового дескриптора назви виробника (0 = нема).|
| 0x0F   | 1    | uint8_t  | iProduct          | Індекс рядкового дескриптора назви продукту (0 = нема). |
| 0x10   | 1    | uint8_t  | iSerialNumber     | Індекс рядкового дескриптора серійного номера (0 = нема)|
| 0x11   | 1    | uint8_t  | bNumConfigurations| Кількість підтримуваних конфігурацій (зазвичай 1).      |
+--------+------+----------+-------------------+---------------------------------------------------------+
```

#### Семантика та інваріанти полів ідентифікації
1. **`idVendor` (зсув 0x08, 16 бітів):** Числове значення, офіційно присвоєне консорціумом USB-IF. Операційні системи використовують це поле для побудови рядка апаратного ідентифікатора (Hardware ID). Заборонено використовувати значення `0x0000` та `0xFFFF`.
2. **`idProduct` (зсув 0x0A, 16 бітів):** Внутрішній ідентифікатор конкретної моделі виробу. Обирається інженером у межах діапазону `0x0000..0xFFFF`. Різні апаратні ревізії з несумісними протоколами повинні мати відмінні значення Product ID.
3. **`bcdDevice` (зсув 0x0C, 16 бітів):** Ревізія прошивки у двійково-десятковому форматі (Binary Coded Decimal). Значення `0x0102` інтерпретується операційною системою як версія `1.02`. Диспетчер пристроїв використовує це поле для визначення пріоритету оновлення драйверів.
4. **`bDeviceClass`, `bDeviceSubClass`, `bDeviceProtocol`:** Якщо пристрій реалізує складену функціональність (Composite Device, наприклад, віртуальний COM-порт CDC + клавіатура HID), поле `bDeviceClass` встановлюється в `0xEF` (Miscellaneous), `bDeviceSubClass` в `0x02`, а `bDeviceProtocol` в `0x01`. Це вказує стеку ОС на використання дескрипторів асоціації інтерфейсів (Interface Association Descriptor, IAD).

#### Порядок байтів (Endianness)
Усі 16-бітні поля (`bcdUSB`, `idVendor`, `idProduct`, `bcdDevice`) передаються лініями D+/D− шини USB у порядку **Little-Endian** (молодший байт за меншим зсувом, старший за більшим).

Якщо компанії призначено Vendor ID `0x1209`, а Product ID обрано `0x0042`, байти в пам'яті мікроконтролера розташовуються так:
```
Зсув 0x08: 0x09  (idVendor LSB)
Зсув 0x09: 0x12  (idVendor MSB)
Зсув 0x0A: 0x42  (idProduct LSB)
Зсув 0x0B: 0x00  (idProduct MSB)
```

### 2. Дескриптор сховища бінарних об'єктів (BOS) та дескриптори Microsoft OS 2.0

Починаючи зі специфікації USB 2.1 (зі значенням `bcdUSB = 0x0210`), хост запитує дескриптор BOS (`GET_DESCRIPTOR`, тип `0x0F`). Він слугує кореневим контейнером для розширень платформи (Device Capabilities).

```
Структура BOS Header Descriptor:
+--------+------+----------+-------------------+---------------------------------------------------------+
| Зсув   | Байт | Тип      | Назва поля        | Опис та значення                                        |
+--------+------+----------+-------------------+---------------------------------------------------------+
| 0x00   | 1    | uint8_t  | bLength           | Розмір заголовка (0x05 = 5 байтів).                     |
| 0x01   | 1    | uint8_t  | bDescriptorType   | Тип дескриптора (0x0F = BOS).                           |
| 0x02   | 2    | uint16_t | wTotalLength      | Сумарна довжина BOS та всіх capability-блоків (LE).     |
| 0x04   | 1    | uint8_t  | bNumDeviceCaps    | Кількість блоків Capability у складі дескриптора.       |
+--------+------+----------+-------------------+---------------------------------------------------------+
```

#### Автоматичне монтування драйверів WinUSB через Microsoft OS 2.0 Descriptors
Щоб пристрій без стандартного USB-класу (vendor-specific) автоматично монтувався в ОС Windows без встановлення сторонніх файлів `.inf` та без проходження дорогої сертифікації WHQL, у дескриптор BOS додається блок Platform Capability з UUID Microsoft OS 2.0 (`D8DD60DF-4589-4CC7-9CD2-659D9E648A9F`).

```
Структура Microsoft OS 2.0 Platform Capability у складі BOS:
+--------+------+----------+-------------------+---------------------------------------------------------+
| Зсув   | Байт | Тип      | Назва поля        | Опис та значення                                        |
+--------+------+----------+-------------------+---------------------------------------------------------+
| 0x00   | 1    | uint8_t  | bLength           | Розмір дескриптора capability (0x1C = 28 байтів).       |
| 0x01   | 1    | uint8_t  | bDescriptorType   | 0x10 (DEVICE CAPABILITY).                               |
| 0x02   | 1    | uint8_t  | bDevCapabilityType| 0x05 (PLATFORM).                                        |
| 0x03   | 1    | uint8_t  | bReserved         | 0x00.                                                   |
| 0x04   | 16   | uint8_t  | PlatformCapability| UUID: DF 60 DD D8 89 45 C7 4C 9C D2 65 9D 9E 64 8A 9F   |
|        |      |          | UUID              |                                                         |
| 0x14   | 4    | uint32_t | dwWindowsVersion  | Мінімальна версія Windows (0x06030000 = Windows 8.1+).  |
| 0x18   | 2    | uint16_t | wMSOSDescriptorSet| Загальна довжина набору дескрипторів MS OS 2.0.         |
|        |      |          | TotalLength       |                                                         |
| 0x1A   | 1    | uint8_t  | bMS_VendorCode    | Спеціальний код команди vendor control transfer.        |
| 0x1B   | 1    | uint8_t  | bAltEnumCode      | Код альтернативної нумерації (0x00).                    |
+--------+------+----------+-------------------+---------------------------------------------------------+
```

Коли Windows виявляє цей блок у BOS, вона надсилає пристрою вендорний запит із кодом `bMS_VendorCode` і зчитує дескриптор сумісності `Compatible ID Descriptor`, де вказано рядок `WINUSB\0\0`. Операційна система автоматично прив'язує універсальний драйвер `WinUSB.sys`, надаючи користувацькому застосунку прямий доступ до передачі даних через бібліотеку `libusb`.

### 3. Bluetooth Advertising Data (AD) та Extended Inquiry Response (EIR)

У протоколах Bluetooth Low Energy (BLE) та Bluetooth Classic широкомовна інформація транслюється без встановлення з'єднання у вигляді ланцюжка інформаційних блоків формату **LTV (Length-Type-Value)**.

```
Структура елемента LTV:
[ 1 байт: Length (N+1) ] [ 1 байт: AD Type ] [ N байтів: AD Data (Value) ]
```

```
Поширені типи AD Type (Core Specification Supplement, CSS):
+---------+-----------------------------------+----------------------------------------------------------+
| AD Type | Назва типу                        | Призначення та структура корисного навантаження          |
+---------+-----------------------------------+----------------------------------------------------------+
| 0x01    | Flags                             | Бітові прапори: LE General Discoverable (0x02),          |
|         |                                   | BR/EDR Not Supported (0x04). Типове значення: 0x06.      |
| 0x08    | Shortened Local Name              | Скорочена назва пристрою в кодуванні UTF-8.              |
| 0x09    | Complete Local Name               | Повна назва пристрою в кодуванні UTF-8.                  |
| 0x02    | Incomplete List of 16-bit UUIDs   | Неповний список 16-бітних сервісів GATT.                 |
| 0x03    | Complete List of 16-bit UUIDs     | Повний список підтримуваних стандартних сервісів GATT.   |
| 0x16    | Service Data - 16-bit UUID        | Дані сервісу: 2 байти UUID (LE) + корисні дані датчика.  |
| 0xFF    | Manufacturer Specific Data        | Специфічні дані виробника: 2 байти SIG Company ID + дані.|
+---------+-----------------------------------+----------------------------------------------------------+
```

#### Формат поля Manufacturer Specific Data (AD Type 0xFF)
Поле `0xFF` використовується для пропрієтарних маяків, телеметрії та ідентифікації обладнання. Перші два байти корисного навантаження обов'язково містять 16-бітний **Company Identifier Code (Company ID)**, виданий Bluetooth SIG:

```
Формат пакета Manufacturer Specific Data (AD Type 0xFF):
Зсув 0: [ Length = N + 3 ]
Зсув 1: [ AD Type = 0xFF ]
Зсув 2: [ Company ID LSB ]  (16-бітний код Bluetooth SIG у форматі Little-Endian)
Зсув 3: [ Company ID MSB ]
Зсув 4..N+3: [ Пропрієтарні дані виробника (до 27 байтів у BLE 4.x або 251 у BLE 5.x) ]
```

```
Приклади офіційних 16-бітних Bluetooth SIG Company Identifier Codes:
0x004C: Apple, Inc. (використовується для кадрів iBeacon та AirDrop)
0x0059: Nordic Semiconductor ASA
0x0075: Samsung Electronics Co. Ltd.
0x0006: Microsoft Corporation
0x0030: STMicroelectronics
0x02E5: Espressif Systems (Shanghai) Co., Ltd.
0xFFFF: Reserved for internal testing (суворо заборонено для комерційних виробів)
```

### 4. Бітова анатомія адрес IEEE EUI-48 та правила інверсії в IPv6

Адреса канального рівня (MAC-адреса) складається з 6 байтів (48 бітів). У текстовому вигляді адреса записується шістнадцятковими октетами, розділеними двокрапками (`AA:BB:CC:DD:EE:FF`).

```
Анатомія першого байта адреси EUI-48 (Octet 0):
+------+------+------+------+------+------+------+------+
| b7   | b6   | b5   | b4   | b3   | b2   | b1   | b0   |
+------+------+------+------+------+------+------+------+
|             Біти префікса OUI           | U/L  | I/G  |
+------+------+------+------+------+------+------+------+
```

- **Біт 0 (I/G — Individual/Group, маска `0x01`):**
  * `b0 = 0`: Individual (Unicast) — адресний пакет призначений одному фізичному мережевому адаптеру;
  * `b0 = 1`: Group (Multicast / Broadcast) — групова розсилка або широкомовний кадр (наприклад, широкомовний `FF:FF:FF:FF:FF:FF` або мультимедійний IPv4 Multicast `01:00:5E:00:00:01`).
- **Біт 1 (U/L — Universal/Local, маска `0x02`):**
  * `b1 = 0`: Universal (Universally Administered Address, UAA) — адреса є глобально унікальною і походить з офіційного пулу IEEE OUI виробника;
  * `b1 = 1`: Local (Locally Administered Address, LAA) — адреса згенерована локальним програмним забезпеченням (наприклад, механізмом MAC Randomization у смартфонах або гіпервізором віртуальних машин).

#### Правила генерації IPv6 Interface Identifier (Modified EUI-64)
При автоконфігурації без збереження стану (IPv6 SLAAC, RFC 4291) 48-бітна MAC-адреса перетворюється на 64-бітний ідентифікатор інтерфейсу:
1. Адреса EUI-48 розділяється на два 3-байтні блоки: OUI (`AA:BB:CC`) та ідентифікатор пристрою (`DD:EE:FF`);
2. Посередині вставляється фіксований 16-бітний шаблон `0xFFFE`, утворюючи 64-бітне значення `AA:BB:CC:FF:FE:DD:EE:FF`;
3. Біт `U/L` у першому байті **інвертується** (`b1 = b1 ^ 0x02`). Якщо апаратна адреса була глобальною (`U/L = 0`), у модифікованому форматі EUI-64 біт стає `1`, вказуючи на універсальну область видимості ідентифікатора IPv6.

### 5. Інтерфейси інспекції в середовищі Linux

Для перевірки коректності дескрипторів та адрес у ядрі Linux використовуються стандартні віртуальні файлові системи `sysfs` та утиліти діагностики:
- Перегляд дескрипторів підключених USB-пристроїв:
  `cat /sys/bus/usb/devices/1-1/idVendor`
  `cat /sys/bus/usb/devices/1-1/idProduct`
- Отримання апаратної MAC-адреси мережевого адаптера:
  `cat /sys/class/net/eth0/address`
- Зчитування постійної адреси з пам'яті OTP/EEPROM в обхід локальної зміни:
  `ethtool -P eth0`
- Перевірка широкомовних параметрів Bluetooth та Company ID:
  `hciconfig hci0 leadv`
