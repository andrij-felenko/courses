# 🧮 Математична точність координат: чому float32 не підходить для навігації

Під час передачі польотних завдань кожна точка маршруту містить географічну широту, довготу й висоту. На перший погляд, стандартного 32-бітного дробового числа з рухомою комою (англ. *single-precision floating-point*, `float`) має вистачати для будь-яких інженерних розрахунків. Проте в супутниковій навігації спроба зберегти географічні координати у форматі `float` призводить до раптової втрати точності на величину до двох метрів. З'ясуймо математичну природу цього обмеження, виведімо просторову роздільну здатність сітки на поверхні земного еліпсоїда WGS 84, проаналізуємо катастрофічне скасування розрядів при розрахунку дистанцій і азимутів, деформацію меж геозон та доведемо, чому цілочислова фіксована кома з масштабом `10⁻⁷` є оптимальним інженерним розв'язком.

## Геометрична модель і довжина дуги на еліпсоїді WGS 84

Для опису положення апарата в просторі міжнародна геодезична система WGS 84 (англ. *World Geodetic System 1984*) задає форму Землі як сплюснутий еліпсоїд обертання з такими параметрами:

```
a = 6 378 137.0 м               [велика піввісь еліпсоїда, радіус екватора]
b = 6 356 752.314245 м          [мала піввісь еліпсоїда, полярний радіус]
f = (a - b) / a                 [геодезичне стиснення Землі]
  = 1 / 298.257223563
e² = 2·f - f²                   [квадрат першого ексцентриситету]
   ≈ 0.00669437999014
```

Через сплюснутість планети радіус кривизни поверхні залежить від географічної широти `φ`. Радіус кривизни меридіанного перерізу `M(φ)` (який визначає лінійну довжину дуги широти) описується формулою:

```
M(φ) = a · (1 - e²) / (1 - e² · sin²(φ))^(3/2)
```

Обчислимо довжину дуги одного кутового градуса широти вздовж меридіана на екваторі (`φ = 0°`) та на полюсі (`φ = 90°`):

```
M(0°) = a · (1 - e²)
      = 6 378 137.0 · (1 - 0.00669438)   [підстановка нульової широти]
      = 6 335 439.33 м                   [радіус кривизни на екваторі]

l_lat(0°) = 2 · π · M(0°) / 360
          = 2 · 3.1415926535 · 6 335 439.33 / 360  [довжина дуги одного градуса]
          = 110 574.27 м                 [довжина градуса широти на екваторі]
```

На полюсі (`φ = 90°`):

```
M(90°) = a / sqrt(1 - e²)
       = 6 378 137.0 / sqrt(1 - 0.00669438)  [підстановка максимальної широти]
       = 6 399 593.63 м                  [радіус кривизни біля полюса]

l_lat(90°) = 2 · π · M(90°) / 360
           = 2 · 3.1415926535 · 6 399 593.63 / 360  [довжина дуги одного градуса]
           = 111 693.86 м                [довжина градуса широти на полюсі]
```

Для сферичного наближення із середнім радіусом Землі `R = 6 371 000 м` довжина одного градуса широти приймається рівною:

```
l_lat = 2 · π · R / 360
      = 2 · 3.1415926535 · 6 371 000 / 360  [довжина дуги на середній сфері]
      = 111 194.93 м ≈ 111.195 км
```

Для географічної довготи відстань між сусідніми меридіанами визначається радіусом паралелі, тобто залежить від широти `φ` і радіуса кривизни першого вертикалу `N(φ)`:

```
N(φ) = a / sqrt(1 - e² · sin²(φ))
l_lon(φ) = 2 · π · N(φ) · cos(φ) / 360
```

На екваторі (`φ = 0°`, `N(0°) = a`):

```
l_lon(0°) = 2 · π · 6 378 137.0 / 360    [довжина градуса довготи на екваторі]
          = 111 319.49 м ≈ 111.32 км
```

У помірних широтах, наприклад, для Києва (`φ ≈ 50.45°`, `cos(50.45°) ≈ 0.63674`):

```
l_lon(50.45°) ≈ 111 319.49 · 0.63674 м   [масштабування косинусом широти]
              ≈ 70 881.7 м ≈ 70.88 км на один градус довготи
```

Кутова похибка дискретизації `Δθ` перетворюється на лінійне зміщення точки `Δs` на місцевості:

```
Δs_lat(φ) = Δθ · l_lat(φ)
Δs_lon(φ) = Δθ · l_lon(φ)
```

## Анатомія розрядної сітки IEEE 754 Single Precision

Стандарт IEEE 754 визначає 32-бітне число з рухомою комою як сукупність трьох двійкових полів:

```
+---+--------+-----------------------+
| S | E (8)  |        M (23)         |
+---+--------+-----------------------+
| 1 | 8 біт  |        23 біти        |
+---+--------+-----------------------+
```

Де:
- `S` — знаковий біт (0 — додатне число, 1 — від'ємне);
- `E` — зміщений порядок (експонента), 8 бітів (зсув `+127`, реальний порядок `E_real = E - 127`);
- `M` — дробова частина мантиси, 23 явно збережених біти.

Оскільки для всіх нормалізованих чисел провідний біт мантиси перед двійковою комою завжди дорівнює одиниці (`1.b₂₂b₂₁...b₀`), реальна розрядність мантиси складає `p = 24 біти`.

Значення нормалізованого числа обчислюється за формулою:

```
V = (-1)^S · (1 + M / 2²³) · 2^(E - 127)
```

Відстань між двома найближчими представленими двійковими числами називається одиницею в останньому розряді (англ. *unit in the last place*, ULP). Для числа з реальним порядком `E_real` величина ULP дорівнює:

```
ULP(V) = 2^(E_real - 23)
```

### Дискретизація довготи при використанні float32

Географічна довгота змінюється в діапазоні від `-180.0°` до `+180.0°`. Знайдемо крок квантування сітки `ULP` для різних географічних зон:

**1. Діапазон від 0° до 1° (Гринвіч, Лондон, Західна Африка):**
Порядок лежить у межах `2⁰ ≤ |λ| < 2¹`, тобто `E_real = 0`.

```
ULP = 2^(0 - 23)
    = 2⁻²³                               [дискретність мантиси]
    ≈ 1.19209 · 10⁻⁷ градуса
```

Лінійна похибка сітки на екваторі:

```
Δs = 1.19209 · 10⁻⁷ · 111 319.49 м       [множення ULP на довжину екватора]
   = 0.01327 м ≈ 1.33 см
```

Біля нульового меридіана 32-бітний `float` дає роздільну здатність близько 1.3 см. Проте зі зростанням кута порядок числа збільшується на одиницю при кожному переході через ступінь двійки (`2°, 4°, 8°, 16°, 32°, 64°, 128°`), а разом із ним експоненційно зростає крок просторової сітки.

**2. Діапазон від 64° до 128° (значна частина Євразії, Казахстан, Індія, Китай, Індійський океан):**
Тут `2⁶ ≤ |λ| < 2⁷`, тобто порядок `E_real = 6`.

```
ULP = 2^(6 - 23)
    = 2⁻¹⁷                               [зсув експоненти на 6 бітів]
    = 1 / 131 072 градуса
    ≈ 7.62939 · 10⁻⁶ градуса
```

Лінійна похибка сітки на екваторі:

```
Δs = 7.62939 · 10⁻⁶ · 111 319.49 м       [множення на довжину екватора]
   = 0.8493 м ≈ 85 см
```

Крок координатної сітки досягає 85 сантиметрів.

**3. Діапазон від 128° до 180° (Східна Азія, Японія, Австралія, Тихий океан, західне узбережжя США):**
Тут `2⁷ ≤ |λ| ≤ 180`, тобто порядок `E_real = 7`.

```
ULP = 2^(7 - 23)
    = 2⁻¹⁶                               [зсув експоненти на 7 бітів]
    = 1 / 65 536 градуса
    ≈ 1.52588 · 10⁻⁵ градуса
```

Обчислимо лінійну похибку сітки на екваторі:

```
Δs = 1.52588 · 10⁻⁵ · 111 319.49 м       [перемноження ULP та довжини дуги]
   = 1.6986 м ≈ 1.70 м
```

Крок сітки становить `1.70 метра` на екваторі й до `2.4 метра` вздовж діагоналі координатної клітинки. Якщо оператор планує місію і задає координату поворотного пункту, наприклад, `150.1234567°`, формат `float32` фізично не здатний зберегти це число й округлює його до найближчого вузла сітки:

```
Задане значення довготи:   150.12345670°
Найближче менше у float:   150.12344360°
Найближче більше у float:  150.12345886°
Різниця між вузлами:         0.00001526° ≈ 1.70 м на місцевості
```

Для автономного літального апарата це спричиняє прямі навігаційні дефекти:
- Спроба посадки на платформу розміром `1 × 1 м` стає неможливою, оскільки координата центру платформи провалюється між двома вузлами сітки.
- Коридор безпечної геозони шириною `5 м` втрачає понад `30%` своєї ширини лише через похибку квантування чисел.
- Навігаційний контролер із високоточним приймачем RTK GNSS (що має апаратну похибку вимірювань `1–2 см`) отримує від польотного завдання штучний шум позиціювання величиною до двох метрів.

## Альтернатива: цілочислова фіксована кома 10⁻⁷ градуса

Щоб подолати ваду рухомої коми без подвоєння обсягу переданих даних (переходу на 64-бітний `double`), протокол місій MAVLink перейшов на цілочислове представлення з фіксованою комою (англ. *fixed-point arithmetic*).

Широта й довгота множаться на коефіцієнт масштабування `10⁷` (`10 000 000`) і упаковуються в 32-бітне знакове ціле число `int32_t`:

```
coord_int = round(coord_degrees · 10 000 000)
```

Перевіримо, чи вміщуються всі можливі координати Землі в діапазон `int32_t`.

### Діапазон значень

32-бітне знакове ціле в додатковому коді має межі:

```
INT32_MIN = -2 147 483 648
INT32_MAX = +2 147 483 647
```

Діапазон географічних координат:
- Широта `φ ∈ [-90.0°, +90.0°]`:
  `[-900 000 000, +900 000 000]`.
- Довгота `λ ∈ [-180.0°, +180.0°]`:
  `[-1 800 000 000, +1 800 000 000]`.

Максимальне абсолютне значення `1 800 000 000` менше за `INT32_MAX = 2 147 483 647`. Запас розрядності складає:

```
Запас = (2 147 483 647 - 1 800 000 000) / 2 147 483 647
      = 347 483 647 / 2 147 483 647      [віднімання максимального значення координат]
      ≈ 16.18%                           [частка вільного діапазону int32]
```

Жодного переповнення розрядної сітки не виникає за будь-яких валідних координат.

### Просторова роздільна здатність

Один крок молодшого розряду в представленні з фіксованою комою становить строго фіксовану кутову величину:

```
Δθ_int = 1 / 10 000 000 градуса
       = 10⁻⁷ градуса                    [кутова дискретність одного розряду]
       = 0.0000001°                      [десятковий вигляд]
```

Обчислимо лінійну роздільну здатність по широті на меридіані еліпсоїда WGS 84:

```
Δs_lat = 10⁻⁷ · 111 194.93 м
       = 0.0111195 м                     [множення на довжину градуса меридіана]
       ≈ 1.11 см                         [округлення до сотих сантиметра]
```

Лінійна роздільна здатність по довготі на екваторі:

```
Δs_lon(0°) = 10⁻⁷ · 111 319.49 м
           = 0.0111319 м                 [множення на довжину екваторіального градуса]
           ≈ 1.11 см                     [сантиметрова точність на екваторі]
```

Лінійна роздільна здатність по довготі на широті 50° (Київ, Харків, Львів):

```
Δs_lon(50°) = 10⁻⁷ · 111 319.49 · cos(50°) м
            ≈ 10⁻⁷ · 111 319.49 · 0.642788 м  [підстановка cos(50°)]
            ≈ 0.007155 м                      [проміжне значення]
            ≈ 0.72 см                         [округлення до сотих сантиметра]
```

Крок координатної сітки `int32` становить строго `≤ 1.11 см` у будь-якій точці земної кулі. На відміну від `float32`, де дискретність стрибає від 1.3 см до 1.7 м залежно від довготи, фіксована кома забезпечує повністю однорідну сантиметрову роздільну здатність.

## Катастрофічне скасування при розрахунку дистанцій та азимутів

Ще небезпечнішим наслідком використання `float32` у навігаційних алгоритмах є явище катастрофічного скасування значущих цифр (англ. *catastrophic cancellation*) при відніманні двох близьких географічних координат.

### Розрахунок ортодромічної відстані (формула гаверсинусів)

Відстань між двома точками `(φ₁, λ₁)` та `(φ₂, λ₂)` на сфері описується формулою гаверсинусів:

```
hav(d / R) = hav(Δφ) + cos(φ₁) · cos(φ₂) · hav(Δλ)
```

Де `hav(θ) = sin²(θ / 2)`. Відстань `d` обчислюється як:

```
d = 2 · R · asin(sqrt(sin²(Δφ / 2) + cos(φ₁) · cos(φ₂) · sin²(Δλ / 2)))
```

Коли безпілотник летить до чергової точки маршруту, розташованої на відстані `5 м`, кутова різниця довготи на екваторі складає:

```
Δλ = 5 м / 111 319.49 м/град
   ≈ 0.000044916°
```

Якщо базові довготи точок знаходяться в діапазоні `128°…180°`, їхні значення у форматі `float32` зберігаються з кроком `ULP = 0.00001526°`. Різниця двох таких чисел `Δλ_float = λ₂_float - λ₁_float` може набувати лише дискретних значень, кратних `ULP`:

```
Можливі значення Δλ_float:
  2 · ULP = 0.00003052°  →  3.40 м  (заниження на 32%)
  3 · ULP = 0.00004578°  →  5.10 м  (помилка 2%)
  4 · ULP = 0.00006104°  →  6.79 м  (завищення на 36%)
```

Квантування призводить до того, що розрахункова відстань між точками стрибає з кроком `1.7 метра`, спричиняючи різкі ривки в розрахунку необхідної швидкості та гальмування в навігаційному регуляторі автопілота.

### Розрахунок навігаційного азимута (помилка курсу)

Початковий азимут `θ` (кутовий напрямок руху від точки 1 до точки 2) обчислюється через арктангенс двох аргументів:

```
y = sin(Δλ) · cos(φ₂)
x = cos(φ₁) · sin(φ₂) - sin(φ₁) · cos(φ₂) · cos(Δλ)
θ = atan2(y, x)
```

Розгляньмо політ суворо на північ (`Δλ = 0`, `Δφ = 0.000045° ≈ 5 м`). Теоретичний азимут руху дорівнює `0.0°` (істинна північ).

Якщо через похибку квантування довгота другої точки отримала зміщення лише на один `ULP` (`Δλ_err = 0.00001526°`):

```
y_err = sin(0.00001526° · π / 180) · cos(0°)
      ≈ 2.663 · 10⁻⁷                     [помилкове східне зміщення]

x_true = sin(0.000045° · π / 180)
       ≈ 7.854 · 10⁻⁷                    [істинне північне зміщення]

θ_calc = atan2(2.663 · 10⁻⁷, 7.854 · 10⁻⁷)
       = atan2(0.339, 1.0)
       ≈ 0.327 рад ≈ 18.7°               [спотворений розрахунковий курс]
```

Похибка квантування довготи призводить до спотворення розрахункового курсу на `18.7 градуса`! Для відстані між точками в `2 метри` спотворення азимута досягає `40°…50°`. Автопілот намагається повернути ніс апарата в бік хибного вузла сітки, спричиняючи різкі коливання по осі рискання (англ. *yaw oscillation*) при проходженні вейпоінтів.

## Деформація меж геозон і хибні спрацьовування периметра

Польотні місії часто містять обмеження безпеки у вигляді полігональних геозон (англ. *geofence*), за межі яких апарату заборонено вилітати. Перевірка знаходження точки всередині полігона виконується алгоритмом пускання променя (англ. *Ray-Casting Algorithm*):

1. З поточної точки апарата `P(x, y)` проводиться нескінченний горизонтальний промінь уздовж осі довготи.
2. Підраховується кількість перетинів променя з відрізками ребер полігона `E_i = (V_i, V_{i+1})`.
3. Непарна кількість перетинів свідчить про знаходження всередині зони, парна — за її межами.

Умова перетину променя з ребром між вершинами `(x₁, y₁)` та `(x₂, y₂)` на широті апарата `y`:

```
x_intersect = x₁ + (y - y₁) · (x₂ - x₁) / (y₂ - y₁)
```

Якщо координати вершин `V_i` квантуються з кроком до `1.7 м`, межі полігона зміщуються, а нахили ребер зазнають деформації:

```
Кутове відхилення нормалі:
tan(α_err) ≈ Δ_quant / |V₂ - V₁|
```

Для короткого ребра геозони довжиною `10 м` кут нахилу межі може спотворитися на `atan(1.7 / 10) ≈ 9.6°`. Це призводить до двох небезпечних наслідків:
1. **Хибне спрацьовування (False Alarm):** апарат, який летить на відстані півтора метра від законної межі всередині дозволеної зони, через квантування розпізнається як порушник. Автопілот раптово активує аварійний режим (англ. *Geofence Breach Failsafe*), зупиняє виконання місії та переходить до екстреного примусового повернення на базу (RTL).
2. **Прорив периметра (Undetected Breach):** апарат вилітає за межі реальної фізичної перешкоди (будівлі, зони аеропорту), але через спотворену в пам'яті межу автопілот вважає, що все ще знаходиться в безпечній зоні.

## Кумулятивне накопичення похибок при обчисленні маршруту

Розгляньмо, як похибка дискретизації позначається на обчисленні повної довжини полігонального маршруту (наприклад, місії аерофотознімання поля зі 150 проходами й поворотними точками).

Нехай координати поворотних точок `W_i = (x_i, y_i)` квантуються із випадковою похибкою `ε_i`, розподіленою рівномірно в інтервалі `[-Δ/2, +Δ/2]`. Дисперсія похибки положення кожної окремої точки становить:

```
Var(ε) = Δ² / 12                         [дисперсія рівномірного розподілу]
```

При оцінці загальної довжини маршруту з `N` відрізків похибки положення сусідніх вершин додаються. Для `N = 150` точок середньоквадратичне відхилення положення вузлів маршруту складає:

```
σ_N = sqrt(N) · sqrt(Var(ε))
    = sqrt(N) · Δ / sqrt(12)
```

Для формату `float32` при довготі понад 128° (`Δ ≈ 1.70 м`):

```
σ_float = sqrt(150) · 1.70 / sqrt(12)
        = 12.247 · 1.70 / 3.4641         [підстановка кількості точок і кроку]
        = 20.82 / 3.4641
        ≈ 6.01 м                         [сумарне середньоквадратичне відхилення]
```

Для формату `int32` (`Δ = 0.0111 м`):

```
σ_int = sqrt(150) · 0.0111 / sqrt(12)
      = 12.247 · 0.0111 / 3.4641         [підстановка параметрів fixed-point]
      = 0.1359 / 3.4641
      ≈ 0.0392 м ≈ 3.9 см                [сумарне середньоквадратичне відхилення]
```

При використанні `float32` межі маршруту й розрахунковий кілометраж відхиляються на шість метрів, тоді як цілочислова фіксована кома тримає кумулятивну похибку в межах чотирьох сантиметрів.

## Чому висота Z лишається у форматі float32

У повідомленні `MISSION_ITEM_INT` координати широти `x` та довготи `y` передаються як `int32_t`, тоді як висота `z` передається як стандартний 32-бітний `float`. На перший погляд, це здається непослідовним, проте математика величин повністю виправдовує такий поділ.

Висота точки польоту вимірюється не в кутових градусах із перевідним коефіцієнтом `111 319 м/град`, а безпосередньо в метрах відносно точки старту або рівня моря. Типовий діапазон висот автономних безпілотників лежить у межах від `-500 м` до `+15 000 м`.

Обчислимо крок дискретизації `ULP` для висоти `z = 1000 м` (`2⁹ ≤ 1000 < 2¹⁰`, `E_real = 9`):

```
ULP_z(1000 м) = 2^(9 - 23)
              = 2⁻¹⁴                     [зсув порядку експоненти]
              = 1 / 16 384 м
              ≈ 0.000061 м = 0.061 мм    [субміліметрова дискретність]
```

Навіть на висоті польоту пасажирського лайнера `z = 10 000 м` (`2¹³ ≤ 10 000 < 2¹⁴`, `E_real = 13`):

```
ULP_z(10 000 м) = 2^(13 - 23)
                = 2⁻¹⁰                   [зсув порядку для 10 км]
                = 1 / 1024 м
                ≈ 0.000976 м ≈ 0.98 мм   [дискретність менше одного міліметра]
```

Оскільки для висоти `float32` забезпечує субміліметрову дискретність у всьому діапазоні атмосфери Землі, передавати її цілим числом немає математичної потреби.

## Перехід до локальної тангенціальної площини (NED та ENU)

Навігаційні регулятори автопілота (наприклад, фільтр Калмана EKF3 в ArduPilot або ECL EKF у PX4) виконують розрахунки стабілізації не в криволінійних географічних координатах, а в локальній прямокутній системі координат NED (англ. *North-East-Down*, «Північ-Схід-Вниз») або ENU (англ. *East-North-Up*, «Схід-Північ-Вгору»).

Локальна тангенціальна площина прив'язується до початкової точки місії (англ. *Home position*) або локального початку відліку `(φ₀, λ₀, h₀)`.

Перетворення географічних координат точки `(φ, λ)` у плоскі метричні координати `(x_N, y_E)` на еліпсоїді WGS 84 виконується через різниці кутів:

```
Δφ = φ - φ₀
Δλ = λ - λ₀
```

Метричні зміщення на північ `x_N` та на схід `y_E` обчислюються як:

```
x_N = Δφ · M(φ₀) · (π / 180)
y_E = Δλ · N(φ₀) · cos(φ₀) · (π / 180)
```

Де:
- `M(φ₀)` — радіус кривизни меридіана на широті початку відліку;
- `N(φ₀)` — радіус кривизни першого вертикалу;
- множник `π / 180` переводить градуси в радіани.

Якщо координати `(φ, λ)` та `(φ₀, λ₀)` зберігаються як 32-бітні цілі числа `int32_t` із коефіцієнтом `10⁷` (`φ_int = φ · 10⁷`), то різниця обчислюється як точне цілочислове віднімання:

```
Δφ_int = φ_int - φ₀_int          [абсолютно точна різниця в одиницях 10⁻⁷ deg]
Δλ_int = λ_int - λ₀_int
```

Перехід до метрів у рухомій комі подвійної точності (`double`) виконується за один крок:

```
x_N = (double)Δφ_int · (1e-7 · (π / 180.0) · M(φ₀))
y_E = (double)Δλ_int · (1e-7 · (π / 180.0) · N(φ₀) · cos(φ₀))
```

Оскільки константи `k_lat = 1e-7 · (π / 180.0) · M(φ₀)` та `k_lon = 1e-7 · (π / 180.0) · N(φ₀) · cos(φ₀)` обчислюються автопілотом один раз під час фіксації точки старту (англ. *EKF origin*), проекція будь-якої точки маршруту в локальний метр потребує лише двох операцій множення:

```
x_N = (double)Δφ_int · k_lat
y_E = (double)Δλ_int · k_lon
```

Завдяки цьому автопілот уникає тригонометричних викликів `sin()` і `cos()` на кожному такті польотного контролера (400 Гц), зберігаючи сантиметрову точність положення всіх вейпоінтів місії.

## Програмне перетворення без накопичення похибок

При написанні коду взаємодії між модулями зв'язку та математичним ядром автопілота важливо уникати випадкового проміжного зведення до `float32`.

Якщо виконати перетворення:

:::tabs
```cpp
// ПОМИЛКА: проміжний тип float спотворює точність перед множенням
double raw_deg = 150.12345678;
int32_t bad_coord = static_cast<int32_t>(static_cast<float>(raw_deg) * 1e7f);
```
```c
// ПОМИЛКА: проміжний тип float спотворює точність перед множенням
double raw_deg = 150.12345678;
int32_t bad_coord = (int32_t)((float)raw_deg * 1e7f);
```
:::

То координата спотвориться ще на етапі приведення до `float`. Правильне перетворення виконується через 64-бітну арифметику з рухомою комою (`double`) або безпосередній цілочисловий розбір текстового рядка NMEA/JSON:

:::tabs
```cpp
#include <cmath>
#include <cstdint>

// ПРАВИЛЬНО: збереження точності через double
double raw_deg = 150.12345678;
int32_t good_coord = static_cast<int32_t>(std::round(raw_deg * 10000000.0));

// Зворотне перетворення для відображення оператору
double restored_deg = static_cast<double>(good_coord) * 1e-7;
```
```c
#include <math.h>
#include <stdint.h>

// ПРАВИЛЬНО: збереження точності через double
double raw_deg = 150.12345678;
int32_t good_coord = (int32_t)round(raw_deg * 10000000.0);

// Зворотне перетворення для відображення оператору
double restored_deg = (double)good_coord * 1e-7;
```
:::

Вибір `int32_t` з фіксованою комою `10⁻⁷` градуса забезпечує оптимальний баланс: мінімальний 4-байтовий розмір поля в каналі зв'язку, абсолютну детермінованість цілочислової сітки та сантиметрову точність позиціонування літального апарата в будь-якій точці планети.
