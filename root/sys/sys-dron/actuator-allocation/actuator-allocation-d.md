Коли восьмимоторний октокоптер масою 15 кг потрапляє в порив вітру зі швидкістю 18 м/с, регулятор кутової орієнтації миттєво обчислює необхідний відновлювальний момент крену `M_x = 4.2 Н·м` та додаткову вертикальну тягу `F_z = 180 Н`. Регулятор не знає, скільки в апарата гвинтів, під якими кутами нахилені їхні осі, які мотори крутяться за годинниковою стрілкою, а які проти, і чи не перегрівся один із силових ключів. Він оперує абстрактними фізичними величинами — узагальненими силами й моментами. Завдання перекласти ці чотири абстрактні числа на мову восьми конкретних сигналів шпаруватості PWM або пакетів DShot для регуляторів швидкості бере на себе підсистема **розподілу керування** (англ. *control allocation*, від лат. *allocare* — «виділяти, призначати»).

Якщо на звичайному симетричному квадрокоптері зв'язок між моментами та моторами описується жорсткою таблицею знаків `±1`, то будь-яке ускладнення конструкції — асиметрична рама «Deadcat», гексакоптер, октокоптер із нахиленими моторами, літак із V-подібним оперенням, безхвостка з елевонами чи конвертоплан із поворотними балками — перетворює просте змішування на задачу лінійної оптимізації в умовах геометричних та фізичних обмежень приводів.

## Віртуальне керування проти фізичних приводів

Архітектура сучасного польотного контролера суворо розділяє дві концептуальні площини: динаміку руху центру мас і кінематику виконавчих органів. Каскадні регулятори положення та орієнтації формують так званий **вектор віртуального керування** `τ` (грец. *tau*), що містить сумарну силу та головні моменти сил у зв'язаній системі координат апарата:

```
τ = [F_z, M_x, M_y, M_z]ᵀ
```

У повній шестивимірній постановці для апаратів із керованим вектором тяги (наприклад, мультироторів із поворотними моторами чи підводних апаратів) цей вектор розширюється до шести компонентів `τ = [F_x, F_y, F_z, M_x, M_y, M_z]ᵀ`. Для класичних дронів та літаків компоненти сил у горизонтальній площині `F_x, F_y` створюються непрямо — шляхом нахилу корпусу (створення кутів крену й тангажу), тому розмірність вектора віртуальних зусиль становить `n = 4`.

З іншого боку системи розташований **вектор фізичних приводів** `u`:

```
u = [u₁, u₂, ..., u_m]ᵀ,    де u_i ∈ [u_min, i, u_max, i]
```

Розмірність `m` визначається кількістю незалежних моторів, сервомашинок, елеронів, рулів висоти чи закрилків. Для кожного привода сигнал `u_i` нормалізується: для безколекторних моторів це зазвичай безрозмірний діапазон `[0.0, 1.0]` (від повної зупинки до максимального газу), а для сервоприводів аеродинамічних рулів — `[-1.0, +1.0]` (відхилення від нейтралі в крайні положення).

![Конвеєр розподілу керування](/root/sys/sys-dron/actuator-allocation/img/allocation-pipeline.svg)
*Конвеєр розподілу керування: контури стабілізації видають вектор узагальнених зусиль τ, алокатор транслює їх через псевдообернену матрицю B⁺ у фізичні сигнали u, а блок десатурації коригує команди при виході приводів на апаратне насичення.*

Пряма задача динаміки зв'язує команди приводів `u` зі створюваними силами та моментами `τ` через лінійне матричне рівняння:

```
τ = B · u
```

Матриця `B` розмірністю `n × m` називається **матрицею ефективності керування** (англ. *control effectiveness matrix*) або **матрицею мікшування** (англ. *mixer matrix*). Кожен `i`-й стовпчик матриці `B` показує одиничний відгук апарата: які саме сили та моменти породжує одиничний сигнал `u_i = 1.0` на `i`-му приводі.

Задача розподілу керування полягає у розв'язанні оберненої задачі: знайти такий вектор фізичних сигналів `u`, який задовольняє рівність `B · u = τ` і водночас не виходить за допустимі межі `u_min ≤ u ≤ u_max`.

## Фізика формування матриці ефективності B

Щоб побудувати матрицю `B`, польотний контролер спирається на просторову геометрію рами та аеродинамічні параметри кожного окремого виконавчого органа.

Розглянемо ротор із порядковим номером `i`. Його розташування відносно центру мас дрона задається радіус-вектором у системі координат FRD (Forward-Right-Down — ніс уперед, праве крило праворуч, вісь Z униз):

```
r_i = [x_i, y_i, z_i]ᵀ  (у метрах)
```

Орієнтація осі обертання гвинта задається одиничним вектором тяги `n_i = [n_x,i, n_y,i, n_z,i]ᵀ`. Для звичайного плаского колінеарного мультикоптера тяга спрямована строго вгору вздовж від'ємної осі Z, тому `n_i = [0, 0, -1]ᵀ`. Якщо ж мотор встановлено з конструктивним нахилом для покращення реакції на рискання чи горизонтального прискорення без нахилу корпусу, вектор `n_i` містить ненульові проєкції на осі X та Y.

![Зв'язок геометрії ротора з матрицею ефективності](/root/sys/sys-dron/actuator-allocation/img/geometry-to-effectiveness.svg)
*Геометричні витоки стовпчика матриці ефективності B: просторове положення ротора r_i, вектор спрямування тяги n_i та реактивний крутний момент Q_i утворюють результуючі проєкції сил і моментів у зв'язаній системі координат.*

При подачі керівного сигналу `u_i` ротор створює вектор сили тяги:

```
F_i = c_t,i · u_i · n_i
```

де `c_t,i` — коефіцієнт тяги привода (у ньютонах на одиницю сигналу).

Окрім сили тяги, обертання гвинта у в'язкому повітрі породжує аеродинамічний опір лопатей, що створює реактивний момент, спрямований протилежно напрямку обертання ротора:

```
Q_i = d_i · c_m,i · u_i · n_i
```

де `d_i = +1` для гвинтів, що обертаються проти годинникової стрілки (CCW), і `d_i = -1` для гвинтів за годинниковою стрілкою (CW); `c_m,i` — коефіцієнт реактивного крутного моменту (у ньютон-метрах на одиницю сигналу).

Сумарний момент сили відносно центру мас, створюваний `i`-м ротором, дорівнює сумі моменту від сили тяги (обчислюваного через [векторний добуток](root:math-algebra/cross-product) плеча на силу) та власного реактивного моменту:

```
M_i = (r_i × F_i) + Q_i
```

Розкриваючи векторний добуток `r_i × n_i` за правилом визначника:

```
r_i × n_i = [
  y_i · n_z,i - z_i · n_y,i,
  z_i · n_x,i - x_i · n_z,i,
  x_i · n_y,i - y_i · n_x,i
]ᵀ
```

Збираючи проєкції сили на вісь Z та моменти навколо осей X, Y, Z, отримуємо `i`-й стовпчик матриці ефективності `b_i ∈ ℝ⁴`:

```
b_i = [
  -c_t,i · n_z,i,                                            [F_z: вертикальна тяга]
   c_t,i · (y_i·n_z,i - z_i·n_y,i) + d_i·c_m,i·n_x,i,        [M_x: момент крену (Roll)]
   c_t,i · (z_i·n_x,i - x_i·n_z,i) + d_i·c_m,i·n_y,i,        [M_y: момент тангажу (Pitch)]
   c_t,i · (x_i·n_y,i - y_i·n_x,i) + d_i·c_m,i·n_z,i         [M_z: момент рискання (Yaw)]
]
```

Для аеродинамічних поверхонь літаків (елеронів, рулів висоти, рулів напрямку) створення сили базується не на обертах гвинта, а на відхиленні площини в набігаючому потоці. Ефективність такої поверхні пропорційна швидкісному напору `q = 1/2 · ρ · V²`:

```
b_aero, j = q · S_j · [ c_L,j, c_l,j, c_m,j, c_n,j ]ᵀ
```

де `S_j` — площа кермової поверхні, а `c_l, c_m, c_n` — безрозмірні коефіцієнти аеродинамічної похідної ефективності відхилення. Завдяки єдиній матричній формі `τ = B · u` польотний контролер однаково працює як із роторами, так і з сервоприводами літакових поверхонь.

## Розв'язання задачі: псевдообернення Мура–Пенроуза

Розмірність простору приводів `m` визначає математичну категорію задачі розподілу керування:

1. **Квадратна система (`m = n = 4`):** класичний 4-роторний дрон. Матриця `B` квадратна `4 × 4`. Якщо мотори не розташовані колінеарно на одній прямій, матриця `B` є невиродженою (`det(B) ≠ 0`), і існує єдиний точний розв'язок: `u = B⁻¹ · τ`.
2. **Недовизначена система з надлишковістю (`m > n`):** гексакоптери (`m = 6`), октокоптери (`m = 8`), літаки з флаперонами та роздільними рулями. Кількість приводів більша за кількість ступенів свободи. Рівняння `B · u = τ` має нескінченну кількість розв'язків.
3. **Перевизначена система (`m < n`):** трикоптер без сервоприводу хвостового мотора чи апарат із відмовою приводів. Керувати всіма чотирма осями незалежно фізично неможливо.

![Порівняння конфігурацій алокації](/root/sys/sys-dron/actuator-allocation/img/multirotor-vs-fixedwing-mixing.svg)
*Порівняння схем алокації: квадратний мікшер Quad-X дає єдиний розв'язок без резервування; надлишковий алокатор Hexa-X мінімізує енергетичну норму та зберігає керованість при відмові мотора; алокатор літака поєднує неоднорідні сервоприводи.*

У випадку надлишковості (`m > n`) постає питання: який саме з нескінченної множини допустимих векторів `u` обрати? Критерієм вибору є мінімізація втрат електричної енергії на активному опорі обмоток моторів та напівпровідникових ключів ESC. Теплові втрати Джоуля–Ленца пропорційні квадрату струму: `P_loss ∝ I² ∝ u²`.

Тому формулюється задача мінімізації квадратичної норми вектора керування:

```
min J(u) = 1/2 · ||u||₂² = 1/2 · (u₁² + u₂² + ... + u_m²)
за умови: B · u = τ
```

Розв'язання цієї оптимізаційної задачі методом невизначених множників Лагранжа приводить до використання правої **псевдооберненої матриці Мура–Пенроуза** `B⁺` (англ. *Moore-Penrose pseudoinverse*):

```
B⁺ = Bᵀ · (B · Bᵀ)⁻¹
u = B⁺ · τ
```

Повний математичний вивід методу Лагранжа, оптимізація зі зваженою матрицею витрат `W` (Weighted Least Squares), нуль-просторові проєкції та чисельний аналіз сингулярного розкладу наведено у вставці [псевдообернена матриця Мура–Пенроуза та метод найменших квадратів](root:sys-dron/actuator-allocation/math-pseudoinverse-mixer.md).

> 🔧 **Навіщо це.** Головна перевага псевдообернення полягає в автоматичній відмовостійкості. Якщо на гексакоптері виходить з ладу один із моторів (наприклад, згорів силовий ключ MOSFET), польотному контролеру не потрібно мати заздалегідь написані аварійні таблиці мікшування. Прошивка просто викреслює стовпчик аварійного мотора з матриці `B` і миттєво перераховує `B⁺` для п'яти решти моторів. Навантаження автоматично та оптимально розподіляється між вцілілими приводами, дозволяючи зберегти стабілізацію та здійснити безаварійну посадку.

## Просторово нахилені мотори та повноприводні (6-DoF) мультиротори

Звичайні пласкі мультикоптери є неповноприводними (англ. *underactuated*): вони мають 6 просторових ступенів свободи (3 лінійні координати `X, Y, Z` та 3 кути орієнтації `Roll, Pitch, Yaw`), але лише 4 незалежні вектори керування `τ = [F_z, M_x, M_y, M_z]ᵀ`. Щоб прискоритися вперед уздовж осі X, класичний дрон змушений нахилити корпус на кут тангажу, що неминуче відхиляє напрямок камер і сенсорів корисного навантаження.

Для подолання цього обмеження застосовуються схеми з **просторово нахиленими моторами** (англ. *canted / tilted rotors*) або повноприводні мультиротори (англ. *fully actuated omnidirectional drones*). У такій конфігурації осі моторів відхилені від вертикалі на фіксований кут (зазвичай `α = 20°..35°`) у тангенціальному або радіальному напрямках.

Кожен мотор починає створювати не лише вертикальну силу `F_z`, але й прямі горизонтальні сили `F_x` та `F_y`:

```
n_i = [ sin(α)·cos(ψ_i), sin(α)·sin(ψ_i), -cos(α) ]ᵀ
```

де `ψ_i` — азимутальний кут розташування балки мотора.

Матриця ефективності `B` стає повною матрицею `6 × 6` (для гексакоптера) або `6 × 8` (для октокоптера):

```
[ F_x ]   [ b₁₁  b₁₂  ...  b₁₆ ]   [ u₁ ]
[ F_y ]   [ b₂₁  b₂₂  ...  b₂₆ ]   [ u₂ ]
[ F_z ] = [ b₃₁  b₃₂  ...  b₃₆ ] · [ u₃ ]
[ M_x ]   [ b₄₁  b₄₂  ...  b₄₆ ]   [ u₄ ]
[ M_y ]   [ b₅₁  b₅₂  ...  b₅₆ ]   [ u₅ ]
[ M_z ]   [ b₆₁  b₆₂  ...  b₆₆ ]   [ u₆ ]
```

Оскільки ранг матриці `B` дорівнює 6 (`rank(B) = 6`), система стає повністю керованою (англ. *fully actuated*): польотний контролер може незалежно задавати бічне прискорення `F_y` або поздовжнє `F_x` при абсолютно нульових кутах крену й тангажу (`M_x = 0, M_y = 0`). Дрон може зависати в повітрі під будь-яким кутом до горизонту (наприклад, строго вертикально боком біля фасаду будівлі).

Ціною повноприводності є енергетичні втрати (косинусний штраф): оскільки вертикальна складова тяги зменшується пропорційно `cos(α)`, для утримання висоти мотори споживають на `1 / cos(α) - 1` (близько 15–22%) більше енергії. Алокатор на базі матриці `B⁺` автоматично знаходить баланс між створенням необхідних бічних сил та підтриманням вертикальної тяги.

## Типові топології та карти мікшування

Розглянемо, як матриця `B` та її псевдообернена матриця `B⁺` виглядають для найпоширеніших аеродинамічних схем.

### 1. Симетричний квадрокоптер Quad-X

Чотири мотори розташовані по кутах квадрата з плечем `L`, мотори 1 і 4 обертаються CCW (`d = +1`), мотори 2 і 3 — CW (`d = -1`).

Матриця прямої ефективності `B`:

```
B = [
  [  c_t,       c_t,       c_t,       c_t     ],    [F_z]
  [  c_t·L_y,   c_t·L_y,  -c_t·L_y,  -c_t·L_y ],    [M_x]
  [ -c_t·L_x,   c_t·L_x,  -c_t·L_x,   c_t·L_x ],    [M_y]
  [  c_m,      -c_m,      -c_m,       c_m     ]     [M_z]
]
```

Обернена матриця `B⁻¹` після нормування на відповідні коефіцієнти набуває класичного вигляду:

```
        F_z      M_x      M_y      M_z
u₁  = [ 0.25,   0.25,   -0.25,    0.25 ]
u₂  = [ 0.25,   0.25,    0.25,   -0.25 ]
u₃  = [ 0.25,  -0.25,   -0.25,   -0.25 ]
u₄  = [ 0.25,  -0.25,    0.25,    0.25 ]
```

### 2. Літакове V-подібне оперення (V-Tail)

У V-подібному оперенні два керма, розташовані під кутом `γ` до горизонталі (зазвичай `γ = 40°..45°`), замінюють класичні рулі висоти й напрямку. Відхилення лівого керма `δ_L` та правого `δ_R` одночасно створюють моменти тангажу `M_y` та рискання `M_z`.

Матриця ефективності хвостової групи:

```
[ M_y ]   [  c_elev · cos(γ),   c_elev · cos(γ) ]   [ δ_L ]
[ M_z ] = [ -c_rud  · sin(γ),   c_rud  · sin(γ) ] · [ δ_R ]
```

Обернення цієї матриці дає алгоритм мікшування V-Tail:
* Для створення чистого тангажу (ніс угору) обидва рулі відхиляються вгору (`δ_L > 0, δ_R > 0`);
* Для створення чистого рискання (ніс праворуч) ліве кермо відхиляється вниз, а праве — вгору (`δ_L < 0, δ_R > 0`).

### 3. Літаюче крило з елевонами (Elevons)

У безхвостих літаках типу «літаюче крило» дві кермові площини на задній кромці крила виконують спільну роль елеронів (крен) та рулів висоти (тангаж):

```
[ M_x ]   [  c_ail,  -c_ail ]   [ δ_left  ]
[ M_y ] = [  c_elv,   c_elv ] · [ δ_right ]
```

Обернена матриця розподілу формує команди елевонів:

```
δ_left  = 0.5 · ( M_y / c_elv + M_x / c_ail )
δ_right = 0.5 · ( M_y / c_elv - M_x / c_ail )
```

Синхронний рух створює тангаж, протифазний рух — крен.

### 4. Конвертоплани VTOL: динамічне змішування перехідних режимів

Апарати вертикального зльоту та посадки типу VTOL (англ. *Vertical Take-Off and Landing* — наприклад, QuadPlane або Tilt-Rotor) мають два принципово різні набори виконавчих органів: підйомні ротори для режиму висіння та аеродинамічні рулі з тяговим пропелером для швидкісного горизонтального польоту.

Під час перехідного режиму (англ. *transition*), коли апарат розганяється від швидкості висіння `V = 0` до швидкості звалювання крила `V_stall`, ефективність аеродинамічних поверхонь плавно зростає зі швидкісним напором `q = 1/2 · ρ · V²`.

Матриця ефективності `B(V)` у перехідному режимі стає функцією повітряної швидкості `V_air`:

```
B(V_air) = [ B_rotors,  w(V_air) · B_aero ]
```

де вагова функція переходу `w(V_air)` плавно змінюється від `0` (при висінні) до `1` (при досягненні крейсерської швидкості):

```
w(V_air) = clamp( (V_air - V_trans_start) / (V_trans_end - V_trans_start), 0.0, 1.0 )
```

Алокатор на базі псевдооберненої матриці `B⁺(V_air)` автоматично передає керувальні моменти від підйомних моторів до елеронів і рулів висоти в міру зростання швидкості, унеможливлюючи провали по висоті чи ривки за орієнтацією.

## Насичення приводів та драбина десатурації

У реальному польоті фізичні можливості приводів обмежені: мотор не може створити тягу понад `u_max = 1.0` (100% потужності) або менше `u_min = 0.0` (гвинт не може обертатися у зворотний бік). Коли регулятори вимагають одночасно високої загальної тяги для набору висоти (`F_z = 0.9`) і значного моменту для швидкого крену (`M_x = 0.3`), лінійне множення `u = B⁺ · τ` вимагає від навантажених моторів потужності `0.9 + 0.3 = 1.2`.

Виникає явище **насичення приводів** (англ. *actuator saturation*).

Наївний підхід — індивідуальне апаратне обмеження кожного сигналу функцією затискання `u_i = clamp(u_i, 0, 1)` — є **критичною помилкою проєктування польотного контролера**.

Розглянемо наслідок індивідуального затискання на квадрокоптері:
* Мотори правого борту `u₁, u₂` мали видати `1.2`, але їх зрізало до `1.0`;
* Мотори лівого борту `u₃, u₄` отримали `0.9 - 0.3 = 0.6` і не досягли насичення;
* Фактичний перепад тяги склав `1.0 - 0.6 = 0.4` замість необхідного `1.2 - 0.6 = 0.6`;
* Створений момент крену виявився на 33% меншим за розрахунковий;
* Не менш небезпечно: спотворився баланс реактивних моментів рискання `M_z`, викликавши паразитичний доворот по курсу.

У результаті апарат втрачає розрахункову кутову динаміку, контур стабілізації починає відставати за фазою, накопичує інтегральну помилку (I-windup) і зривається у некероване перекидання.

![Драбина пріоритетів десатурації](/root/sys/sys-dron/actuator-allocation/img/desaturation-priority-ladder.svg)
*Драбина десатурації: ієрархія збереження керованості. Першочергово захищаються моменти крену й тангажу; дефіцит запасу приводів компенсується стисненням моменту рискання та зсувом спільного рівня тяги.*

Щоб запобігти катастрофічній втраті стійкості, застосовується алгоритм **пріоритетної десатурації** (англ. *priority desaturation*), що базується на суворій ієрархії збереження ступенів свободи:

1. **Пріоритет 1: Крен і Тангаж (Roll & Pitch).** Збереження просторової орієнтації має найвищий пріоритет. Якщо дрон не зможе компенсувати нахил, він перекинеться за частки секунди;
2. **Пріоритет 2: Рискання (Yaw).** Рискання має вторинний пріоритет. Помилка курсу в кілька градусів не веде до аварії;
3. **Пріоритет 3: Загальна тяга (Thrust).** Спільний рівень газу має найнижчий пріоритет. Втрата кількох метрів висоти є прийнятною платою за збереження орієнтації та керованості.

### Алгоритм десатурації реалізується у чотири кроки:

**Крок 1: Зсув середнього рівня тяги (Shift Desaturation).**
Якщо максимальна команда перевищує стелю `max(u) > 1.0`, весь вектор команд опускається на величину перевантаження `Δ = max(u) - 1.0`:

```
u_i = u_i - Δ    для всіх i ∈ [1..m]
```

Усі різниці між моторами (а отже, 100% моментів крену, тангажу та рискання) зберігаються повністю. Знижується лише середня тяга — дрон на мить просідає по висоті, але бездоганно виконує маневр ухилення.

Аналогічно, якщо `min(u) < 0.0`, вектор піднімається вгору: `u_i = u_i - min(u)`.

**Крок 2: Масштабування моменту рискання (Yaw Desaturation).**
Якщо після зсуву діапазон між максимальним і мінімальним мотором все одно перевищує допустимий коридор `(max(u) - min(u)) > 1.0`, геометричного запасу приводів не вистачає для реалізації всіх трьох моментів.

Обчислюється динамічний запас, зайнятий креном і тангажем:

```
u_rp,max = max |u_roll,i + u_pitch,i|
```

Доступний залишок під момент рискання становить `headroom = 0.5 - u_rp,max`. Якщо цей залишок менший за необхідний внесок рискання `u_yaw,max`, момент рискання масштабується коефіцієнтом:

```
k_yaw = clamp(headroom / u_yaw,max, 0.0, 1.0)
u_i = u_thrust,i + u_rp,i + k_yaw · u_yaw,i
```

**Крок 3: Масштабування вектора моменту крену й тангажу (Roll/Pitch Dynamic Scaling).**
У найбільш екстремальній ситуації, коли навіть `u_rp,max > 0.5`, сумарний момент `[M_x, M_y]ᵀ` масштабується єдиним скалярним коефіцієнтом:

```
k_rp = 0.5 / u_rp,max
u_i = 0.5 + k_rp · (u_roll,i + u_pitch,i)
```

Масштабування саме вектора `[M_x, M_y]ᵀ` як цілісної сутності гарантує, що апарат нахилятиметься строго у правильному просторовому напрямку, нехай і з меншим кутовим прискоренням.

## Аналіз реального польотного логу: простеження насичення

Розглянемо числовий зріз польотного логу (формату ULog), зафіксованого під час виконання різкого віражу квадрокоптера на високій швидкості.

У момент часу `t = 14.320 с` апарат здійснює вертикальний набір висоти з базовою тягою `F_z = 0.85`. Пілот різко відхиляє стік крену праворуч, породжуючи запит на момент `M_x = 0.30`, а зовнішній вихор викликає збурення по курсу, що змушує регулятор рискання додати команду `M_z = 0.15`.

Простежимо роботу алокатора крок за кроком:

```
1. Необмежений лінійний розклад u_raw = B⁺ · τ:
   u₁ = 0.85 + 0.30 + 0.00 + 0.15 = 1.30  (перевантаження +30%)
   u₂ = 0.85 + 0.30 - 0.00 - 0.15 = 1.00
   u₃ = 0.85 - 0.30 + 0.00 - 0.15 = 0.40
   u₄ = 0.85 - 0.30 - 0.00 + 0.15 = 0.70

2. Зсув середньої тяги (Thrust Shift):
   max(u) = 1.30  →  shift = 1.30 - 1.00 = 0.30
   u_shifted = u_raw - 0.30:
   u₁ = 1.00
   u₂ = 0.70
   u₃ = 0.10
   u₄ = 0.40
   Результат: max(u) = 1.00, min(u) = 0.10. Усі мотори помістилися в коридор 0..1!
   Момент крену збережено: (1.00 + 0.70) - (0.10 + 0.40) = 1.70 - 0.50 = 1.20 (еквівалентно M_x = 0.30).
   Момент рискання збережено: (1.00 + 0.40) - (0.70 + 0.10) = 1.40 - 0.80 = 0.60 (еквівалентно M_z = 0.15).
   Тяга тимчасово знизилася з 0.85 до 0.55.
```

У наступний момент часу `t = 14.325 с` запит на крен зростає до `M_x = 0.45` при тій самій тязі `0.85` та рисканні `0.15`:

```
1. Необмежений розклад u_raw:
   u₁ = 0.85 + 0.45 + 0.15 = 1.45
   u₂ = 0.85 + 0.45 - 0.15 = 1.15
   u₃ = 0.85 - 0.45 - 0.15 = 0.25
   u₄ = 0.85 - 0.45 + 0.15 = 0.55

2. Зсув тяги: shift = 1.45 - 1.00 = 0.45:
   u₁ = 1.00
   u₂ = 0.70
   u₃ = -0.20  (пробиття нижньої межі!)
   u₄ = 0.10
   Розмах: 1.00 - (-0.20) = 1.20 > 1.00. Простий зсув не рятує.

3. Активація десатурації рискання (Yaw Desaturation):
   Внесок крену u_rp = 0.45.
   Доступний запас під рискання: headroom = 0.50 - 0.45 = 0.05.
   Коефіцієнт стиснення рискання: k_yaw = 0.05 / 0.15 = 0.333.
   Перерахований розклад:
   u₁ = 0.85 + 0.45 + (0.15 · 0.333) = 1.35
   u₂ = 0.85 + 0.45 - (0.15 · 0.333) = 1.25
   u₃ = 0.85 - 0.45 - (0.15 · 0.333) = 0.35
   u₄ = 0.85 - 0.45 + (0.15 · 0.333) = 0.45

4. Зсув тяги після стиснення рискання: shift = 1.35 - 1.00 = 0.35:
   u₁ = 1.00
   u₂ = 0.90
   u₃ = 0.00
   u₄ = 0.10
   Результат: 100% моменту крену збережено, дрон бездоганно втримав орієнтацію!
```

```c
#include <stdint.h>
#include <stdbool.h>

#define NUM_ACTUATORS 4

typedef struct {
    float b_inv[NUM_ACTUATORS][4]; /* Псевдообернена матриця: рядки - мотори, стовпчики - [F_z, M_x, M_y, M_z] */
} mixer_config_t;

/* Обчислення виходів на ESC у діапазоні 0.0..1.0 з пріоритетною десатурацією */
void control_allocation_step(const mixer_config_t *cfg, 
                             float thrust, float roll, float pitch, float yaw,
                             float u_out[NUM_ACTUATORS])
{
    float u_thrust[NUM_ACTUATORS];
    float u_rp[NUM_ACTUATORS];
    float u_yaw[NUM_ACTUATORS];
    float u[NUM_ACTUATORS];

    /* 1. Роздільне проектування компонентів через псевдообернену матрицю */
    for (int i = 0; i < NUM_ACTUATORS; ++i) {
        u_thrust[i] = cfg->b_inv[i][0] * thrust;
        u_rp[i]     = cfg->b_inv[i][1] * roll + cfg->b_inv[i][2] * pitch;
        u_yaw[i]    = cfg->b_inv[i][3] * yaw;
        u[i]        = u_thrust[i] + u_rp[i] + u_yaw[i];
    }

    /* 2. Пошук екстремумів */
    float min_u = u[0], max_u = u[0];
    for (int i = 1; i < NUM_ACTUATORS; ++i) {
        if (u[i] < min_u) min_u = u[i];
        if (u[i] > max_u) max_u = u[i];
    }

    /* 3. Десатурація зсувом середньої тяги (Thrust Shift) */
    if (max_u > 1.0f) {
        float shift = max_u - 1.0f;
        for (int i = 0; i < NUM_ACTUATORS; ++i) u[i] -= shift;
        min_u -= shift;
        max_u = 1.0f;
    }
    if (min_u < 0.0f) {
        float shift = -min_u;
        for (int i = 0; i < NUM_ACTUATORS; ++i) u[i] += shift;
        max_u += shift;
        min_u = 0.0f;
    }

    /* 4. Якщо розмах перевищує 1.0, жертвуємо моментом рискання */
    if (max_u > 1.0f) {
        float max_rp = 0.0f;
        float max_y = 0.0f;
        for (int i = 0; i < NUM_ACTUATORS; ++i) {
            float abs_rp = u_rp[i] < 0.0f ? -u_rp[i] : u_rp[i];
            float abs_y  = u_yaw[i] < 0.0f ? -u_yaw[i] : u_yaw[i];
            if (abs_rp > max_rp) max_rp = abs_rp;
            if (abs_y > max_y) max_y = abs_y;
        }

        float yaw_margin = 0.5f - max_rp;
        if (yaw_margin < 0.0f) yaw_margin = 0.0f;

        float k_yaw = 1.0f;
        if (max_y > 1e-4f && max_y > yaw_margin) {
            k_yaw = yaw_margin / max_y;
        }

        /* Перерахунок команд з ослабленим рисканням */
        for (int i = 0; i < NUM_ACTUATORS; ++i) {
            u[i] = u_thrust[i] + u_rp[i] + u_yaw[i] * k_yaw;
        }

        /* Повторний зсув */
        max_u = u[0];
        for (int i = 1; i < NUM_ACTUATORS; ++i) {
            if (u[i] > max_u) max_u = u[i];
        }
        if (max_u > 1.0f) {
            float shift = max_u - 1.0f;
            for (int i = 0; i < NUM_ACTUATORS; ++i) u[i] -= shift;
        }
    }

    /* 5. Фінальний апаратний запобіжник [0.0, 1.0] */
    for (int i = 0; i < NUM_ACTUATORS; ++i) {
        if (u[i] < 0.0f) u[i] = 0.0f;
        if (u[i] > 1.0f) u[i] = 1.0f;
        u_out[i] = u[i];
    }
}
```

```cpp
#include <array>
#include <span>
#include <algorithm>
#include <cmath>

namespace drone::control {

template <std::size_t NumActuators = 4>
class ControlAllocator {
public:
    struct Config {
        // Рядки - приводи, стовпчики - [F_z, M_x, M_y, M_z]
        std::array<std::array<float, 4>, NumActuators> bPseudoInv{};
    };

    explicit constexpr ControlAllocator(const Config& config) noexcept : config_(config) {}

    [[nodiscard]] std::array<float, NumActuators> allocate(float thrust, float roll, float pitch, float yaw) const noexcept {
        std::array<float, NumActuators> uThrust{};
        std::array<float, NumActuators> uRollPitch{};
        std::array<float, NumActuators> uYaw{};
        std::array<float, NumActuators> u{};

        // 1. Проектування векторів
        for (std::size_t i = 0; i < NumActuators; ++i) {
            uThrust[i]    = config_.bPseudoInv[i][0] * thrust;
            uRollPitch[i] = config_.bPseudoInv[i][1] * roll + config_.bPseudoInv[i][2] * pitch;
            uYaw[i]       = config_.bPseudoInv[i][3] * yaw;
            u[i]          = uThrust[i] + uRollPitch[i] + uYaw[i];
        }

        // 2. Пошук меж
        auto [minIt, maxIt] = std::minmax_element(u.begin(), u.end());
        float minVal = *minIt;
        float maxVal = *maxIt;

        // 3. Зсув тяги (Thrust Shift)
        if (maxVal > 1.0f) {
            const float shift = maxVal - 1.0f;
            for (auto& val : u) val -= shift;
            minVal -= shift;
            maxVal = 1.0f;
        }
        if (minVal < 0.0f) {
            const float shift = -minVal;
            for (auto& val : u) val += shift;
            maxVal += shift;
            minVal = 0.0f;
        }

        // 4. Стиснення моменту рискання при дефіциті діапазону
        if (maxVal > 1.0f) {
            float maxRp = 0.0f;
            float maxYaw = 0.0f;
            for (std::size_t i = 0; i < NumActuators; ++i) {
                maxRp  = std::max(maxRp, std::abs(uRollPitch[i]));
                maxYaw = std::max(maxYaw, std::abs(uYaw[i]));
            }

            const float yawMargin = std::max(0.0f, 0.5f - maxRp);
            const float kYaw = (maxYaw > 1e-4f && maxYaw > yawMargin) ? (yawMargin / maxYaw) : 1.0f;

            for (std::size_t i = 0; i < NumActuators; ++i) {
                u[i] = uThrust[i] + uRollPitch[i] + uYaw[i] * kYaw;
            }

            auto [newMinIt, newMaxIt] = std::minmax_element(u.begin(), u.end());
            if (*newMaxIt > 1.0f) {
                const float shift = *newMaxIt - 1.0f;
                for (auto& val : u) val -= shift;
            }
        }

        // 5. Затискання в апаратні межі [0.0, 1.0]
        std::array<float, NumActuators> uOut{};
        for (std::size_t i = 0; i < NumActuators; ++i) {
            uOut[i] = std::clamp(u[i], 0.0f, 1.0f);
        }
        return uOut;
    }

private:
    Config config_;
};

} // namespace drone::control
```

## Практичні пастки, нелінійності та калібрування

Під час інтеграції модуля розподілу керування у реальні польотні системи інженер стикається з низкою неідеальностей фізичного світу:

1. **Квадратична нелінійність статичної тяги:**
   Матриця `B` передбачає лінійну залежність сили від сигналу `F_i = c_t · u_i`. Проте фізична тяга гвинта пропорційна квадрату частоти обертання `T ∝ ω²`, а частота обертання безколекторного мотора при керуванні напругою (через шпаруватість PWM) лінійна відносно напруги лише в першому наближенні. Без компенсації цієї нелінійності ефективність мікшера в зоні малого газу (наприклад, 20%) у 2–3 рази нижча, ніж у зоні повного газу (80%), що призводить до млявої реакції на малій тязі та виникнення автоколивань на високій. Для усунення ефекту на виході алокатора застосовується поліноміальна лінеаризація:
   ```
   u_pwm = (1.0 - k_lin) · u + k_lin · u²
   ```
   де `k_lin ∈ [0.5, 0.8]` — емпіричний коефіцієнт кривини тяги, що калібрується на динамометричному стенді.

2. **Асиметрія смуги пропускання приводів:**
   У змішаних схемах (літаки, VTOL-конвертоплани) мотори змінюють тягу за 5–15 мс, а сервоприводи рулів повертаються зі швидкістю не більше 60° за 80–150 мс. Якщо спрямувати високочастотні коригувальні імпульси контуру PID на повільні сервоприводи, вони ввійдуть у фазове відставання (Rate Limiting Saturation), викликаючи розгойдування літака. Матриця розподілу розбивається на швидку підматрицю для моторів та фільтровану низькочастотну підматрицю для сервоприводів.

3. **Гіроскопічна прецесія нахилених роторів:**
   На апаратах із просторово нахиленими моторами зміна обертів масивного гвинта створює гіроскопічний момент прецесії: `M_gyro = I_prop · (ω_prop × Ω_body)`. При агресивному маневруванні цей момент додає паразитичний перехресний зв'язок між креном і тангажем, який алокатор може компенсувати додаванням динамічних поправок у вектор `τ`.
