Автономний складський дрон масою чотири кілограми залітає крізь вантажний шлюз усередину закритого ангара зі сталевими стелажами та залізобетонним перекриттям. Сигнали супутникової навігації GNSS миттєво згасають на 35–45 дБ, приймач втрачає супроводження фази несучої, а спроба навігації за рівнем потужності радіосигналу (RSSI) точок доступу Wi-Fi чи маяків Bluetooth Low Energy призводить до хаотичних стрибків розрахованих координат на 3–8 метрів через багатопроменеву інтерференцію стоячих хвиль. Якщо автопілот спиратиметься лише на інтегрування показів бортових акселерометрів і гіроскопів (IMU), дрейф нульового рівня датчиків уже за 20 секунд польоту накопичить похибку понад два метри, що призведе до неминучого зіткнення зі стелажем.

Для надійного утримання позиції та виконання автономних місій у закритих приміщеннях, підземних тунелях та промислових цехах автопілоту необхідне локальне джерело абсолютних просторових вимірювань із сантиметровою точністю та частотою оновлення не менше 20–50 Гц. Єдиною радіотехнологією, здатною забезпечити таку точність в умовах насиченого металом і бетоном середовища, є надширокосмуговий зв'язок (Ultra-Wideband, UWB).

Замість модуляції неперервної синусоїдальної несучої UWB передає субнаносекундні радіоімпульси у смузі понад 500 МГц. Завдяки цьому приймач отримує можливість зафіксувати точний момент прибуття прямого променя з роздільною здатністю в десятки пікосекунд і фізично відокремити його від відбитих від стін радіовідлунь.

## Фізика надкоротких імпульсів UWB

Класичні бездротові інтерфейси (Wi-Fi, Bluetooth, ZigBee) є вузькосмуговими системами: вони випромінюють радіосигнал у відносно вузькій смузі частот (від 1–2 МГц у BLE до 20–80 МГц у Wi-Fi). Тривалість одного інформаційного радіосимволу у таких протоколах становить від 50 наносекунд до кількох мікросекунд. Оскільки за 50 нс електромагнітна хвиля долає відстань у 15 метрів, прямий промінь від передавача та відбиті від підлоги, стелі й стін відлуння накладаються одне на одне в часі. Фази цих променів додаються векторно, формуючи глибокі інтерференційні провали (релеївське та райсівське завмирання), через що амплітуда сигналу флуктує на 20–30 дБ при зміщенні антени всього на кілька сантиметрів, роблячи вимірювання дистанції за потужністю RSSI абсолютно непридатним для прецизійного позиціонування.

Надширокосмугові системи базуються на фундаментальному співвідношенні невизначеності між часовою та частотною областями: чим коротшим є радіоімпульс у часі, тим ширший спектр він займає. Згідно зі стандартами IEEE 802.15.4a та IEEE 802.15.4z, сигнал класифікується як UWB, якщо його абсолютна смуга пропускання на рівні −10 дБ становить не менше 500 МГц, або відносна смуга частот перевищує 20%:

```
B = f_high − f_low ≥ 500 МГц
η = 2 · (f_high − f_low) / (f_high + f_low) ≥ 0.20
```

У популярних трансиверах для безпілотників (Decawave / Qorvo DW1000 та DW3000) передавач формує радіоімпульси тривалістю `T_p ≈ 1.5–2.0 нс` на центральних частотах від 3.5 до 8.0 ГГц (найпоширеніші канали — Channel 5 на частоті 3993.6 МГц зі смугою 499.2 МГц та Channel 9 на частоті 7987.2 МГц зі смугою 499.2 МГц).

```
┌─────────────────────────────────────────────────────────────────────────┐
│              ПОРІВНЯННЯ РАДІОСИГНАЛІВ У ЧАСОВІЙ ОБЛАСТІ                 │
│                                                                         │
│  Вузькосмуговий (Wi-Fi/BLE): тривалий пакет, накладання відлунь        │
│  ─────────────────────────────────────────────────────────────────────  │
│      Прямий LOS:     /\    /\    /\    /\    /\    /\    /\             │
│                     /  \  /  \  /  \  /  \  /  \  /  \  /  \            │
│      Відбитий MP:       \  /  \  /  \  /  \  /  \  /  \  /  \           │
│      (інтерференція руйнує фазу, похибка дальності ±3–10 м)             │
│                                                                         │
│  UWB (IEEE 802.15.4z): субнаносекундний імпульс, часове розділення     │
│  ─────────────────────────────────────────────────────────────────────  │
│      Прямий LOS:   _/\_ (2 нс)                                          │
│      Відбитий MP:               _/\_ (затримка 10 нс = 3 метри)         │
│      (імпульси розділені в часі, прямий фронт фіксується за 15.65 пс)   │
└─────────────────────────────────────────────────────────────────────────┘
```

Часова роздільна здатність радіоканалу `Δt_res` обернено пропорційна ширині смуги `B`:

```
Δt_res ≈ 1 / B = 1 / (499.2 · 10⁶ Гц) ≈ 2.003 наносекунди
```

У просторі часовому інтервалу у дві наносекунди відповідає фізична дистанція:

```
Δd_res = c · Δt_res = (299 792 458 м/с) · (2.003 · 10⁻⁹ с) ≈ 0.60 метра
```

Якщо відбитий від стіни промінь пройшов шлях хоча б на 60 сантиметрів довший за прямий промінь прямої видимості (Line-of-Sight, LOS), він надходить на антену приймача **після** повного завершення прямого імпульсу. Вони не змішуються і не спотворюють амплітуду один одного: приймач бачить у радіоефірі чітку послідовність розділених у часі піків.

### Спектральна маска FCC та енергетика імпульсу

Оскільки надширокосмуговий сигнал займає гігагерцові смуги частот, де вже працюють ліцензовані радіолокаційні, супутникові та стільникові служби, регуляторні органи (FCC у США, ETSI в Європі) встановили жорстке обмеження на максимальну спектральну густину еквівалентної ізотропно-випромінюваної потужності (EIRP): не більше `−41.3 дБм/МГц` (що відповідає мізерній потужності `75 нВт/МГц`).

Загальна потужність випромінювання UWB-трансивера у всій смузі 500 МГц становить менше 0.5 мілівата (−3 дБм), що на два-три порядки менше за потужність стандартного передавача Wi-Fi (100–200 мВт). Для звичайних радіоприймачів UWB-випромінювання виглядає як незначне підвищення теплового шумового фону ефіру. Щоб упевнено детектувати такі слабкі імпульси під рівнем шумів, трансивер передає кадр із псевдовипадковою кодовою послідовністю преамбули (від 64 до 4096 імпульсів), накопичуючи когерентну енергію за допомогою апаратного корелятора.

### Структура кадру IEEE 802.15.4z та захищена послідовність STS

Сучасні трансивери стандарту IEEE 802.15.4z (наприклад, DW3000 та Apple U1) використовують фізичний рівень високої швидкості імпульсів (HRP UWB). Кадр містить чотири обов'язкові сегменти:
1. **Синхронізаційна преамбула (SHR)**: складається з послідовності імпульсів коду Тернарної Гаусса-Манчестера (Ternary sequences) довжиною 16, 64, 128 або 1024 символи. Вона дозволяє приймачу виявити наявність сигналу та налаштувати автоматичне регулювання підсилення (AGC).
2. **Розділювач початку кадру (SFD, Start-of-Frame Delimiter)**: фіксована 8- або 64-бітна комбінація, точний момент закінчення якої є реперною точкою апаратного таймстемпінгу.
3. **Криптографічна послідовність таймстемпінгу (STS, Scrambled Timestamp Sequence)**: псевдовипадковий бітовий потік, сформований криптографічним генератором на базі симетричного шифрування AES-128. На відміну від відкритої преамбули, STS неможливо завчасно передбачити чи згенерувати зловмисником. Це захищає автопілот від атак випередження (Distance Reduction Attack / Preamble Injection), коли сторонній передавач транслює копію преамбули раніше, щоб змусити дрон повірити, що він знаходиться ближче до анкера.
4. **Заголовок PHY (PHR) та корисні дані (Payload)**: передаються за допомогою комбінованої модуляції BPM-BPSK (Burst Position Modulation з двійковою фазовою маніпуляцією) зі швидкостями 850 кбіт/с або 6.81 Мбіт/с.

### Апаратний таймстемпінг (Timestamping) з пікосекундною роздільною здатністю

Для перетворення часу прольоту (Time-of-Flight, ToF) у метричну дальність чіп трансивера фіксує моменти передачі й прийому кадрів за допомогою внутрішнього надвисокочастотного цифрового лічильника.

У чіпах архітектури DW1000 / DW3000 тактовий генератор синтезатора частоти множить опорну частоту на 128 відносно частоти дискретизації 499.2 МГц, формуючи системну тактову частоту таймстемпінгу:

```
f_sys = 128 · 499.2 МГц = 63.8976 ГГц
```

Цьому відповідає елементарний крок лічильника часу (1 LSB):

```
T_tick = 1 / f_sys = 1 / 63 897 600 000 Гц ≈ 15.65104167 пікосекунди
```

Один такт апаратного таймстемпа у просторі відповідає фізичній відстані:

```
d_tick = c · T_tick = (299 792 458 м/с) · (15.65104 · 10⁻¹² с) ≈ 4.692 міліметра
```

Коли аналоговий радіочастотний тракт детектує перший пік преамбули (First Path), апаратний блок захвату миттєво копіює 40-бітний системний таймстемп у регістр `RX_TIME`. Це дозволяє уникнути будь-яких програмних затримок операційної системи мікроконтролера або черг переривань.

## Протоколи двостороннього вимірювання дальності (Two-Way Ranging)

Якщо на борту супутника GNSS встановлено надточні атомні цезієві або рубідієві стандарти частоти, синхронізовані з точністю до наносекунд, то на мобільному дроні та стаціонарних анкерах стоять звичайні кварцові резонатори вартістю кілька центів. Два незалежні годинники, не з'єднані дротом, не мають спільної точки відліку часу. Тому виміряти дальність простим одноразовим випромінюванням імпульсу від анкера до тега неможливо: приймач не знає, у який саме абсолютний момент часу передавач відправив кадр.

Для вимірювання дистанції застосовують протокол двостороннього обміну повідомленнями (Two-Way Ranging, TWR), де час прольоту розраховується за круговою затримкою повернення радіовідповіді.

### Односторонній проліт (Single-Sided TWR) та катастрофічний вплив дрейфу кварцу

У найпростішій схемі Single-Sided TWR (SS-TWR) беруть участь два повідомлення:
1. Дрон (Tag) відправляє пакет `Poll` у локальний момент часу `t₁` і вмикає таймер очікування.
2. Анкер (Anchor) приймає `Poll` у момент `t₂`, витримує фіксовану апаратну паузу обробки `T_reply` і відправляє кадр `Response` у момент `t₃`. У тіло кадру анкер записує тривалість своєї паузи `T_reply = t₃ − t₂`.
3. Дрон приймає `Response` у момент `t₄` і обчислює час кругового обігу `T_round = t₄ − t₁`.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    ХРОНОМЕТРАЖ ПРОТОКОЛУ SS-TWR                         │
│                                                                         │
│   Дрон (Tag)                                            Анкер (Anchor)  │
│       │                                                       │         │
│   t₁  ●───[ 1. Poll ]────────────────────────────────────────>●  t₂     │
│       │   \                                                   │         │
│       │    \── ToF                                            │         │
│       │                                                       │ │       │
│       │                                                       │ │T_reply│
│       │                                                       │ │       │
│   t₄  ●<──[ 2. Response (t₃ - t₂) ]───────────────────────────●  t₃     │
│       │   /                                                             │
│       │  /── ToF                                                        │
│       ▼                                                                 │
│   T_round = t₄ - t₁                                                     │
│   ToF = ½ · (T_round - T_reply)                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

Ідеальна формула оцінки часу польоту:

```
ToF = ½ · (T_round − T_reply)
```

Проблема полягає в тому, що інтервал `T_round` вимірюється за тактовим генератором дрона `f_tag`, а інтервал `T_reply` — за генератором анкера `f_anchor`. Якщо кварц дрона поспішає на `+10 ppm` (відхилення `+10 · 10⁻⁶`), а кварц анкера відстає на `−10 ppm`, відносна різниця частот становить `e_drift = 20 ppm`.

Як детально доведено у вставці [Компенсація частотного дрейфу кварцових генераторів у DS-TWR](root:sys-dron/uwb-dalnist-po-nanosekundakh-dlia-pozytsionuvannia/math-ds-twr-clock-drift.md), похибка вимірювання часу польоту в протоколі SS-TWR прямо пропорційна тривалості паузи обробки `T_reply`:

```
ΔToF_SS ≈ ½ · T_reply · e_drift
```

Типовий час апаратної обробки та перемикання радіотракту з прийому на передачу в трансивері становить `T_reply = 1.0 мс` (1000 мкс). Обчислимо похибку дальності при різниці частот генераторів усього у 20 ppm:

```
ΔToF_SS = ½ · (1.0 · 10⁻³ с) · (20 · 10⁻⁶) = 10 · 10⁻⁹ с = 10 наносекунд
Δd_SS = c · ΔToF_SS = (3 · 10⁸ м/с) · (10 · 10⁻⁹ с) = 3.0 метри!
```

Похибка у три метри через звичайний температурний дрейф кварцу повністю нівелює наносекундну точність UWB-імпульсів.

### Симетричний подвійний проліт (Double-Sided TWR)

Для усунення впливу нестабільності генераторів протокол Double-Sided TWR (DS-TWR) додає третє повідомлення `Final`, створюючи два пов'язані зустрічні цикли вимірювання кругового часу.

Послідовність кадрів DS-TWR:
1. **Poll**: дрон передає у момент `t₁`, анкер приймає у момент `t₂`.
2. **Response**: анкер відповідає у момент `t₃`, дрон приймає у момент `t₄`.
3. **Final**: дрон відправляє фінальний кадр у момент `t₅`, анкер приймає у момент `t₆`.

Фіксуються чотири часові інтервали:
- На стороні дрона: перший раунд `T_round1 = t₄ − t₁` та пауза реакції `T_reply2 = t₅ − t₄`;
- На стороні анкера: пауза реакції `T_reply1 = t₃ − t₂` та другий раунд `T_round2 = t₆ − t₃`.

![Протоколи вимірювання дальності: односторонній (SS-TWR) та подвійний (DS-TWR)](/root/sys/sys-dron/uwb-dalnist-po-nanosekundakh-dlia-pozytsionuvannia/img/twr-ranging-protocols.svg)
*Часові діаграми протоколів SS-TWR та DS-TWR із взаємною компенсацією дрейфу тактових генераторів.*

Оцінка часу польоту ToF обчислюється за формулою:

```
ToF_DS = (T_round1 · T_round2 − T_reply1 · T_reply2) / (T_round1 + T_round2 + T_reply1 + T_reply2)
```

Завдяки перехресному множенню та додаванню раундів лінійні похибки частотного дрейфу `e_drift` взаємно скорочуються. Залишкова похибка масштабується не мілісекундною паузою `T_reply`, а виключно самим наносекундним часом прольоту `ToF`:

```
ΔToF_DS ≈ ToF · ½ · (e_tag + e_anchor)
```

Для відстані 30 метрів (`ToF = 100 нс`) та дрейфу 20 ppm залишкова часова похибка становить:

```
ΔToF_DS = 100 нс · (20 · 10⁻⁶) = 2.0 · 10⁻¹² с = 2.0 пікосекунди
Δd_DS = c · (2.0 · 10⁻¹² с) = 0.6 міліметра
```

Перехід до симетричного DS-TWR стискає похибку від дрейфу кварцових генераторів із трьох метрів до часток міліметра, роблячи точність системи обмеженою лише тепловим шумом радіотракту.

## Різниця часу прибуття (Time Difference of Arrival — TDoA)

Протокол DS-TWR вимагає активного двостороннього діалогу між дроном і кожним анкером: на одне вимірювання дальності витрачається 3 радіокадри. Якщо в приміщенні встановлено 6 анкерів, один повний цикл навігації дрона потребує передачі `6 × 3 = 18` пакетів. Якщо в зоні польотів одночасно перебуває 10 дронів з частотою опитування 25 Гц, ефір мусить пропускати `10 × 25 × 18 = 4500` пакетів за секунду, що призводить до катастрофічних колізій і колапсу пропускної здатності каналу.

Для обслуговування великої кількості безпілотників у спільній зоні польотів застосовують навігацію за різницею часу прибуття (Time Difference of Arrival, TDoA).

### Геометрія гіперболічного позиціонування

У системі TDoA ролі пристроїв змінюються: дрон (Tag) нікого не опитує і не чекає відповідей. Він лише періодично випромінює в ефір короткий широкомовний радіоімпульс (кадр `Blink` тривалістю всього 100–150 мікросекунд).

Стаціонарні анкери `A₁, A₂, A₃, ..., A_N`, розташовані у відомих точках із координатами `(x_i, y_i, z_i)`, приймають цей імпульс і фіксують точні часові мітки прийому `t₁, t₂, t₃, ..., t_N`.

Різниця часів прийому між парою анкерів `A_i` та `A_j` визначає різницю відстаней від дрона до цих двох анкерів:

```
Δd_ij = d_i − d_j = c · (t_i − t_j)
```

Геометричним місцем точок у 3D-просторі, для яких абсолютна різниця відстаней до двох фіксованих фокусів (анкерів) є постійною величиною `Δd_ij = const`, є **двопорожнинний гіперболоїд обертання**.

```
√[(x − x_i)² + (y − y_i)² + (z − z_i)²] − √[(x − x_j)² + (y − y_j)² + (z − z_j)²] = c · (t_i − t_j)
```

Маючи мережу з `N` анкерів, система формує `N − 1` незалежних нелінійних гіперболічних рівнянь. Перетин трьох або більше гіперболоїдів від чотирьох анкерів дає однозначну просторову точку `(x, y, z)` місцезнаходження дрона.

![Геометрія навігації: сферична трилатерація проти гіперболічної TDoA](/root/sys/sys-dron/uwb-dalnist-po-nanosekundakh-dlia-pozytsionuvannia/img/trilateration-vs-tdoa.svg)
*Порівняння сферичної трилатерації ToF (активне опитування кожного анкера) та гіперболічної навігації TDoA (пасивне слухання широкомовного маяка).*

### Синхронізація опорних анкерів

Головним інженерним викликом TDoA є необхідність жорсткої субнаносекундної синхронізації годинників між усіма анкерами інфраструктури:
- Похибка синхронізації між двома анкерами у `0.1 наносекунди` призводить до зміщення гіперболи на `3 сантиметри`.
- Похибка у `1 наносекунду` зміщує положення на `30 сантиметрів`.

Існує два методи синхронізації опорної мережі:

1. **Дротова синхронізація (Wired Clock Distribution / PTP)**:
   Всі анкери з'єднуються екранованим кабелем (кручена пара категорії Cat6/Cat7 або оптоволокно), через який від єдиного тактового генератора роздається сигнал опорної частоти (10 МГц) і синхроімпульс початку секунди (PPS), або використовується протокол White Rabbit (розширення IEEE 1588 PTP). Це забезпечує точність синхронізації краще ніж 50 пікосекунд, але вимагає прокладання сотень метрів кабелю по об'єкту.

2. **Бездротова синхронізація через радіоефір (Wireless Clock Calibration)**:
   Один з анкерів призначається майстром (Master Anchor) і щосекунди транслює в ефір синхронізувальні кадри `Sync Beacon`. Інші анкери фіксують точний момент прибуття цього маяка і, знаючи точні фіксовані відстані між анкерами, програмно обчислюють і компенсують зсув та фазовий дрейф своїх локальних таймерів за допомогою фільтра Калмана або алгоритму поліноміальної екстраполяції.

| Характеристика | Двосторонній ToF (DS-TWR) | Різниця прибуття (TDoA) |
|---|---|---|
| Роль дрона | Активний трансивер (передає й приймає) | Передавач імпульсів Blink (або пасивний слухач) |
| Кількість дронів у зоні | Обмежена (5–15 апаратів при 20 Гц) | **Необмежена** (сотні й тисячі дронів) |
| Енергоспоживання дрона | Високе (тривалий час увімкненого приймача) | **Мізерне** (передавач активний < 1% часу) |
| Синхронізація анкерів | **Не потрібна** (кожен замір самодостатній) | **Критично необхідна** (< 0.5 нс між анкерами) |
| Складність розгортання | Проста (достатньо розставити анкери) | Висока (калібрування або дротова лінія) |
| Обчислення координат | Може виконуватися на борту дрона | Обчислюється центральним сервером або бортом |

## Геометричний фактор зниження точності (GDOP) у 3D просторі

Точність визначення 3D-координат дрона визначається не лише точністю дальномірних замірів `σ_range`, а й просторовою геометрією взаємного розташування анкерів та апарата. Цей зв'язок кількісно описується матрицею геометричного фактора зниження точності (Geometric Dilution of Precision, GDOP).

Нехай дрон знаходиться у точці `r = (x, y, z)ᵀ`, а анкери — у точках `r_i = (x_i, y_i, z_i)ᵀ`. Одиничний вектор напрямку від дрона до `i`-го анкера дорівнює:

```
u_i = (r_i − r) / ||r_i − r|| = [ (x_i − x)/d_i,  (y_i − y)/d_i,  (z_i − z)/d_i ]
```

Матриця геометрії системи `G` розміром `N × 3` для трилатерації ToF формується з рядків векторів напрямку:

```
G = [ u₁ᵀ;  u₂ᵀ;  u₃ᵀ;  ...;  u_Nᵀ ]
```

Коваріаційна матриця похибки просторових координат `P_pos` визначається виразом:

```
P_pos = (Gᵀ · G)⁻¹ · σ_range²
```

Коефіцієнти геометричного зниження точності для горизонтальної (HDOP) та вертикальної (VDOP) площин:

```
HDOP = √[ (Gᵀ · G)⁻¹₁₁ + (Gᵀ · G)⁻¹₂₂ ]
VDOP = √[ (Gᵀ · G)⁻¹₃₃ ]
3D-GDOP = √(HDOP² + VDOP²)
```

### Проблема планарного розташування анкерів на стелі

Найпоширенішою інженерною помилкою при монтажі UWB-системи в цехах є закріплення всіх анкерів на одній висоті (наприклад, під стелею на балках перекриття на рівні `z = 6.0 м`).

Якщо всі анкери лежать в одній горизонтальній площині `z_i = Z_const`, третій стовпець матриці `G` складається з компонент `(Z_const − z)/d_i`, які для всіх анкерів мають однаковий знак і близькі значення. Матриця `Gᵀ · G` стає майже виродженою (ill-conditioned), визначник наближається до нуля, а діагональний елемент `(Gᵀ · G)⁻¹₃₃` зростає до 20–50.

У результаті, при горизонтальній похибці позиціонування `σ_hor = HDOP · σ_range ≈ 1.5 · 5 см = 7.5 см`, вертикальна похибка злітає до:

```
σ_vert = VDOP · σ_range ≈ 35 · 5 см = 175 сантиметрів!
```

Автопілот, намагаючись утримати висоту за UWB за планарного розташування анкерів, зазнає автоколивань за віссю Z і може вдарити дрон об підлогу або стелю.

Щоб мінімізувати GDOP у 3D:
1. Анкери розміщують на різних висотах: чергують точки монтажу (наприклад, чотири анкери на висоті 1.5–2.0 м і чотири на висоті 5.0–7.0 м), утворюючи об'ємний тетраедр або прямокутний паралелепіпед.
2. Для каналу висоти в автопілоті пріоритет віддають лазерному дальноміру (LIDAR) або ультразвуковому сонару, тоді як UWB використовується переважно для корекції горизонтальних осей X та Y.

## Перешкоди прямої видимості (NLOS) та діагностика каналу CIR

В ідеальному порожньому ангарі радіосигнал між анкером і дроном поширюється по прямій лінії зі швидкістю світла в повітрі `c ≈ 299 700 км/с`. Проте на реальному складі шлях сигналу постійно перекривається колонами, перегородками, вантажами на піддонах або самим корпусом дрона. Такий режим називається Non-Line-of-Sight (NLOS).

### Фізика спотворення сигналу в матеріалах перешкод

Коли електромагнітна хвиля проходить крізь стіну з діелектрика (бетон, цегла, гіпсокартон, деревина), її швидкість падає пропорційно квадратному кореню з відносної діелектричної проникності матеріалу `ε_r`:

```
v = c / √ε_r
```

| Матеріал перешкоди | Діелектрична проникність `ε_r` | Затухання на 4 ГГц (дБ/см) | Додаткова затримка на 10 см товщини |
|---|---|---|---|
| Сухий гіпсокартон | 2.2–2.6 | 0.1–0.3 | **0.19 нс (5.7 см)** |
| Червона цегла | 4.0–5.5 | 0.8–1.5 | **0.37 нс (11.1 см)** |
| Монолітний залізобетон | 6.5–9.0 | 2.5–5.0 | **0.55 нс (16.5 см)** |
| Скло звичайне | 5.0–7.0 | 0.5–1.0 | **0.45 нс (13.5 см)** |
| Тіло людини (вода + тканини) | 45–55 | 10–15 | **2.05 нс (61.5 см)** |

Додаткова затримка часу прольоту `Δt_wall`, спричинена проходженням стіни товщиною `d_wall`, становить:

```
Δt_wall = (d_wall / c) · (√ε_r − 1)
```

Якщо дрон опитує анкер крізь бетонну колону товщиною 30 см (`ε_r = 8.0`):

```
Δt_wall = (0.30 м / 3 · 10⁸ м/с) · (√8.0 − 1) ≈ (1.0 · 10⁻⁹ с) · (2.828 − 1) = 1.83 нс
Δd_bias = c · Δt_wall = (3 · 10⁸ м/с) · (1.83 · 10⁻⁹ с) ≈ +0.55 метра
```

Навіть якщо сигнал пройшов крізь стіну без відбиття, виміряна відстань буде штучно завищена на 55 сантиметрів через оптичне уповільнення хвилі в діелектрику.

У разі повного екранування металевим стелажем (Hard NLOS) прямий промінь поглинається повністю (затухання > 40 дБ), і приймач взагалі не фіксує прямий імпульс, а сприймає за перший сигнал відлуння, що відбилося від протилежної стіни чи підлоги, обійшовши перешкоду довшим шляхом. Це викликає стрибок виміряної дальності на 1.5–4.0 метри.

### Тіньове екранування конструкцією безпілотника (Body Shadowing)

Корпус дрона сам по собі є потужною перешкодою для частот 4–8 ГГц:
- Силовий акумулятор LiPo (масивні свинцево-алюмінієві пластини та рідкий електроліт) повністю блокує радіохвилі, створюючи тіньову зону з затуханням понад 30 дБ.
- Вуглепластикова рама (Carbon Fiber) є електропровідним матеріалом і відбиває до 90% потужності UWB-імпульсу.
- Мідні полігони силової плати PDB та безколекторні мотори створюють додаткові локальні відбиття.

Якщо UWB-антена встановлена на нижній площині рами або посередині між променями, при нахилах дрона під час маневрів (кути крену `φ` і тангажу `θ` до 25–35 градусів) лінія прямої видимості на стельові анкери перекривається власною батареєю.

Для усунення ефекту тіньового екранування на професійних безпілотниках застосовують:
1. Винесення антени на окрему непровідну щоглу (аналогічно компасу та GNSS) або закріплення на кінці одного з променів.
2. Конфігурацію з двома рознесеними UWB-антенами на протилежних кінцях рами, перемикання між якими виконується за допомогою високочастотного RF-комутатора (SPDT) або двох синхронізованих трансиверів.

### Детектування NLOS за імпульсною характеристикою каналу (CIR)

Щоб запобігти збоям навігаційного фільтра EKF через потрапляння спотворених замірів, сучасні UWB-трансивери надають апаратну діагностику імпульсної характеристики радіоканалу (Channel Impulse Response, CIR).

Під час прийому преамбули цифровий корелятор чипа формує в пам'яті масив накопиченої амплітуди радіоімпульсу з кроком ~1 нс (в DW1000 це масив з 1016 комплексних відліків `I/Q` в регістрі `ACC_MEM`).

```
┌─────────────────────────────────────────────────────────────────────────┐
│              ПРОФІЛЬ CIR: ПРЯМА ВИДИМІСТЬ (LOS) ПРОТИ NLOS              │
│                                                                         │
│  1. Line-of-Sight (LOS):                                                │
│  Амплітуда                                                              │
│     ▲          Перший пік (First Path) = Найпотужніший                  │
│     │            █                                                      │
│     │            █                                                      │
│     │            █    ▄                                                 │
│     │            █    █   ▄                                             │
│     │     ░░░░   █    █   █   ▄   ░░░  (Шумовий поріг)                  │
│     └─────┴──────┴────┴───┴───┴───┴────────► Час (відліки)              │
│            FPP ≈ RXP (різниця < 6 дБ) -> Замір ДОСТОВІРНИЙ              │
│                                                                         │
│  2. Non-Line-of-Sight (NLOS: бетонна стіна):                           │
│  Амплітуда                                                              │
│     ▲          Ослаблений FP       Потужне відлуння (Multipath)         │
│     │                                  █                                │
│     │                                  █   ▄                            │
│     │            ▄                     █   █   ▄                        │
│     │     ░░░░   █   ░░░░░░░░░░░░░░░   █   █   █    (Шумовий поріг)     │
│     └─────┴──────┴─────────────────────┴───┴───┴───► Час (відліки)      │
│            RXP >> FPP (різниця > 10 дБ) -> Замір ЗАВИЩЕНИЙ (NLOS!)      │
└─────────────────────────────────────────────────────────────────────────┘
```

![Діагностика каналу CIR: детектування прямої видимості LOS та перешкод NLOS](/root/sys/sys-dron/uwb-dalnist-po-nanosekundakh-dlia-pozytsionuvannia/img/cir-los-vs-nlos.svg)
*Аналіз профілю імпульсної характеристики каналу CIR: співвідношення потужності першого променя та сумарної енергії радіосигналу.*

Трансивер автоматично розраховує дві фундаментальні енергетичні характеристики:
1. **Потужність першого променя (First Path Power, FPP)**: енергія сигналу в перших трьох відліках біля точки виявлення фронту імпульсу (`FP_AMPL1`, `FP_AMPL2`, `FP_AMPL3`):

```
FPP = 10 · log₁₀( [F₁² + F₂² + F₃²] / N² ) − A
```

2. **Сумарна прийнята потужність сигналу (Receive Signal Power, RXP)**: інтегральна енергія всього каналу за час прийому кадру (`CIR_PWR`):

```
RXP = 10 · log₁₀( [C · 2¹⁷] / N² ) − A
```
*(де `N` — кількість накопичених символів преамбули `RXPACC`, `A = 121.74` для частоти повторення імпульсів PRF 64 МГц).*

Критерій класифікації каналу:
- Якщо `RXP − FPP < 6.0 дБ`, прямий промінь не зазнав суттєвого поглинання, перешкод на лінії прямої видимості немає (чистий **LOS**). Замір вважається достовірним з дисперсією `σ² ≈ (0.05 м)²`.
- Якщо `6.0 дБ ≤ RXP − FPP ≤ 10.0 дБ`, прямий промінь частково ослаблений матеріалом перешкоди (м'який NLOS). Замір зміщений на +10–40 см; фільтр Калмана мусить збільшити матрицю коваріації шуму вимірювання `R_uwb` у 5–10 разів.
- Якщо `RXP − FPP > 10.0 дБ`, прямий промінь заблоковано, а сигнал прийшов відбитим шляхом (Hard NLOS). Замір містить неконтрольовану похибку понад 1 метр і повинен бути **повністю відкинутий** алгоритмом Outlier Rejection автопілота.

## Інтеграція UWB у навігаційний стек автопілота

```c
#include <math.h>

typedef struct {
    uint16_t anchor_id;
    float    distance_m;
    float    variance_m2;
    bool     valid;

/* Обробка сирого вимірювання та динамічне масштабування коваріації шуму */
uwb_range_measurement_t process_uwb_range(uint16_t anchor_id, float raw_dist_m,
                                          float fpp_dbm, float rxp_dbm) {
    uwb_range_measurement_t meas = {
        .anchor_id = anchor_id,
        .distance_m = raw_dist_m,
        .variance_m2 = 0.0025f, /* Базова дисперсія LOS: (5 см)^2 */
        .valid = false
    };

    /* Базова перевірка фізичних меж приміщення */
    if (raw_dist_m < 0.1f || raw_dist_m > 80.0f) {
        return meas;
    }

    float nlos_diff = rxp_dbm - fpp_dbm;

    if (nlos_diff > 10.0f) {
        /* Hard NLOS: сигнал заблоковано, відкидаємо замір */
        meas.valid = false;
        return meas;
    } else if (nlos_diff > 6.0f) {
        /* Soft NLOS: сигнал ослаблено, збільшуємо дисперсію для EKF у 16 разів */
        meas.variance_m2 = 0.0400f; /* (20 см)^2 */
        meas.valid = true;
    } else {
        /* Чистий LOS */
        meas.variance_m2 = 0.0025f;
        meas.valid = true;
    }

    return meas;
}
```

```cpp
#include <cstdint>
#include <optional>
#include <algorithm>

namespace navigation {

struct RangeMeasurement {
    uint16_t anchor_id{0};
    float    distance_m{0.0f};
    float    variance_m2{0.0025f}; // Базова дисперсія (5 см)^2
};

class UwbMeasurementFilter {
public:
    static constexpr float MinValidDistanceM = 0.1f;
    static constexpr float MaxValidDistanceM = 80.0f;
    static constexpr float NlosRejectThresholdDb = 10.0f;
    static constexpr float NlosWarnThresholdDb   = 6.0f;

    [[nodiscard]] static std::optional<RangeMeasurement> process(
        uint16_t anchor_id, float raw_dist_m, float fpp_dbm, float rxp_dbm) noexcept {

        if (raw_dist_m < MinValidDistanceM || raw_dist_m > MaxValidDistanceM) {
            return std::nullopt;
        }

        const float nlos_diff = rxp_dbm - fpp_dbm;

        if (nlos_diff > NlosRejectThresholdDb) {
            // Hard NLOS: повністю відкидаємо хибний замір
            return std::nullopt;
        }

        float variance = 0.0025f; // (5 см)^2 для прямої видимості LOS
        if (nlos_diff > NlosWarnThresholdDb) {
            // Soft NLOS: збільшуємо невизначеність для фільтра Калмана
            variance = 0.0400f;   // (20 см)^2
        }

        return RangeMeasurement{
            .anchor_id   = anchor_id,
            .distance_m  = raw_dist_m,
            .variance_m2 = variance
        };
    }
};

} // namespace navigation
```

### Комплексування UWB у 24-станційному розширеному фільтрі Калмана (EKF3)

Автопілоти PX4 та ArduPilot не використовують чисту трилатерацію у реальному часі: алгебраїчний розв'язок системи нелінійних рівнянь чутливий до одиничних викидів і дає стрибки швидкості при втраті одного з анкерів.

Замість цього застосовується централізоване злиття даних у 24-станційному розширеному фільтрі Калмана (EKF3):
1. **Прогноз стану (Predict step, 200–400 Гц)**: висока частота опитування тривісного акселерометра та гіроскопа інтегрує вектор швидкості та положення дрона, формуючи плавну високочастотну траєкторію.
2. **Корекція псевдодальності (Update step, 20–50 Гц)**: кожне нове вимірювання дальності `d_i` до анкера `A_i = (x_i, y_i, z_i)` розглядається як одновимірне спостереження.

Фільтр обчислює очікувану дальність `h_i(x)` від поточного оціненого положення дрона `(x, y, z)` до анкера:

```
h_i(x) = √[(x − x_i)² + (y − y_i)² + (z − z_i)²]
```

Нев'язка інновації (Innovation):

```
y_innov = d_i − h_i(x)
```

Вектор спостереження (якобіан `H_i`):

```
H_i = [ (x − x_i)/h_i(x),  (y − y_i)/h_i(x),  (z − z_i)/h_i(x),  0, ..., 0 ]
```

Коваріація інновації `S_i = H_i · P · H_iᵀ + R_i`, де `R_i` — дисперсія шуму UWB-вимірювача (яка динамічно збільшується при детектуванні NLOS).

Якщо нев'язка `|y_innov| > 3 · √S_i` (правило трьох сигм), фільтр класифікує замір як аномальний викид (Outlier) і відкидає його, запобігаючи різким ривкам керування.

Комплексування UWB з оптичним потоком (Optical Flow) та лазерним лідаром висоти дозволяє дрону продовжувати впевнений політ навіть у разі тимчасового перекриття трьох із чотирьох анкерів масивними металевими конструкціями цеху.

> 🔧 **Навіщо це.**
>
> 1. **Автономна інспекція складів та логістичних терміналів**: квадрокоптер зі сканером штрих-кодів літає вузькими проходами між 12-метровими стелажами без ризику зачепити полиці; точність позиціонування становить 3–7 см при швидкості руху до 3 м/с.
> 2. **Шоу дронів у закритих аренах**: десятки мікрокоптерів виконують складні синхронні фігури пілотажу з мінімальною дистанцією між апаратами у 40 см без взаємних зіткнень завдяки єдиній системі координат TDoA.
> 3. **Посадка на рухому платформу без GNSS**: посадковий майданчик автономного катера або всюдихода обладнується трьома анкерами UWB; дрон вимірює вектор відносної дальності до кожного кута платформи й здійснює прецизійне приземлення навіть під час хитавиці.
