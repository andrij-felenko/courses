# Алгоритм геозони

<preknowlist>
- [Геозона (geofence) в автопілоті](root:sys-dron/geofence) — загальне призначення та концепція віртуальних меж польоту.
- [Належність точки багатокутнику](root:sf-algorithms/point-in-polygon) — математичний принцип пускання променя та парності перетинів.
- [Відстань великого кола](root:math-geometry/great-circle-distance) — сферична геометрія та переведення кутових координат у метри.
- [Безпечний відмов (failsafe)](root:sys-dron/failsafe) — реакції автопілота на аварійні стани та порушення меж.
</preknowlist>

Швидкісний безпілотник рухається на швидкості 20 м/с (72 км/год) у напрямку закритої зони зі складною ламаною межею. За такої швидкості кожна секунда зволікання обчислювача означає 20 метрів пройденої відстані, а безпечне гальмування апарата з допустимим перевантаженням `2.5 м/с²` вимагає 8 секунд часу та 80 метрів гальмівного шляху. Якщо автопілот перевірятиме лише факт поточного перетину віртуального паркану, дрон неминуче вилетить углиб закритого простору майже на сотню метрів до повної зупинки. Якщо ж алгоритм перевірки багатокутника виконуватиме тригонометричні перетворення з плаваючою комою для кожного ребра на кожному кроці польотного циклу, 32-бітний мікроконтролер польотного контролера вичерпає процесорний бюджет основного контуру стабілізації.

Алгоритм геозонування (англ. *geofencing algorithm*, від грец. *γεω-* — земля та англ. *fence* — огорожа) розв'язує задачу гарантованого просторового стримування безпілотного апарата. Він поєднує математичний апарат обчислювальної геометрії, оптимізовані структури просторового відсікання, цілочисельну арифметику фіксованої коми для мікроконтролерів без апаратного FPU подвійної точності та кінематичне прогнозування траєкторії для своєчасного увімкнення гальмівних процедур.

> 🔧 **Навіщо це.** Статичне поняття геозони описує лише кордон на карті, але реальний автопілот має справу з динамічним об'єктом, що володіє масою, швидкістю та обмеженою тягооснащеністю. Надійний алгоритм геозони виконує дві взаємопов'язані функції: обчислює миттєвий топологічний стан (всередині чи зовні) за частки мікросекунди без перевантаження процесора та формує випереджальний сигнал тривоги задовго до фізичного перетину стіни, запобігаючи аварійним інцидентам.

### Геометричні моделі просторових меж

Повітряний простір, у якому виконується місія, описується двома базовими геометричними примітивами: циліндрами та полігональними призмами.

**Циліндрична геозона** задається координатами центру в горизонтальній площині `(lat_0, lon_0)`, радіусом `R` у метрах, а також діапазоном висот `[alt_min, alt_max]` відносно точки старту (Home) або середнього рівня моря (AMSL). Для перевірки знаходження поточної точки `(lat, lon, alt)` усередині циліндра обчислюється горизонтальна відстань `d_h`.

#### Геодезичні наближення та похибки обчислення відстані

На масштабах польотної зони типового безпілотника (радіус польоту до 20–50 км від точки зльоту) кривина поверхні Землі в межах робочої ділянки дозволяє використовувати плоску еквідистантну циліндричну проєкцію (англ. *Equirectangular approximation*) замість важких сферичних формул гаверсинусів або геодезичних рівнянь Вінсенті:

```
dx = (lon - lon_0) · (π ÷ 180) · R_earth · cos(lat_avg)
dy = (lat - lat_0) · (π ÷ 180) · R_earth
d_h² = dx² + dy²
```

Порівняння обчислювальної ціни та похибок різних моделей на мікроконтролері ARM Cortex-M4 дає наочний інженерний компроміс:

1. **Модель Вінсенті (еліпсоїд WGS84):** вимагає 8–15 ітерацій із багаторазовим обчисленням тригонометричних функцій `sin()`, `cos()`, `atan2()`. Час виконання становить понад 2500 тактів CPU, забезпечуючи субміліметрову точність, яка є надлишковою для польотного контролера з точністю GPS-приймача `1.5...3.0 м`.
2. **Формула гаверсинусів (сферична модель):** вимагає обчислення 4 тригонометричних функцій та одного квадратного кореня (~350 тактів CPU).
3. **Еквідистантна проєкція:** вимагає лише одного обчислення косинуса `cos(lat_avg)`, яке обчислюється один раз при зміні базису, та двох множень у внутрішньому циклі (~12 тактів CPU). На відстані 10 км від центру на широті 50° відносна похибка відстані порівняно з еліпсоїдом Вінсенті становить менше `0.02%` (менше 2 метрів), що повністю перекривається дисперсією супутникових вимірювань.

Перевірка належності циліндру зводиться до порівняння квадрата горизонтальної відстані з квадратом радіуса та перевірки вертикального коридору:

```
(d_h² ≤ R²) ∧ (alt_min ≤ alt ≤ alt_max)
```

Такий підхід повністю усуває повільну операцію добування квадратного кореня `sqrt()` з внутрішнього циклу.

**Полігональна геозона (Polygon Geofence)** формується впорядкованою послідовністю з `N` вершин `V_0, V_1, ..., V_{N-1}` у площині географічних координат. Вершини з'єднуються прямолінійними відрізками, утворюючи замкнений багатокутник (де останнє ребро з'єднує `V_{N-1}` з `V_0`), який екструдується по вертикалі між висотами `alt_min` та `alt_max`.

На відміну від циліндра, полігон дозволяє повторювати довільні контури кадастрових ділянок, русел річок, коридорів інфраструктурних об'єктів або заборонених секторів аеропортів. Полігони можуть бути неопуклими (увігнутими) та містити гострі внутрішні кути, що робить неможливим простий радіальний контроль і вимагає повноцінного аналізу перетину площини.

#### Тривимірний рельєф та геозони слідування за поверхнею (Terrain-Following)

У гірській або пересіченій місцевості абсолютні обмеження висоти AMSL (`alt_min`, `alt_max`) створюють небезпеку: апарат може зіткнутися зі схилом пагорба, формально перебуваючи всередині вертикального коридору геозони. Для вирішення цієї проблеми польотні стеки підтримують геозони з прив'язкою до поверхні землі (AGL — Above Ground Level).

Поточна висота апарата над рельєфом обчислюється шляхом запиту висоти земної поверхні `h_terrain(lat, lon)` з цифрової моделі рельєфу (DEM / SRTM):

```
alt_agl = alt_amsl - h_terrain(lat, lon)
```

Вертикальна перевірка модифікується відповідно до висоти над поверхнею:

```
alt_min_agl ≤ alt_agl ≤ alt_max_agl
```

Це перетворює плоску призму на тривимірний деформований об'єм, що огинає топографію місцевості та запобігає зіткненням із рельєфом при збереженні бічних полігональних меж.

### Булева композиція зон: Keep-In та Keep-Out

Реальний польотний план містить не одну область, а сукупність взаємопов'язаних дозволених і заборонених просторів. Автопілоти PX4 та ArduPilot класифікують кожну просторову область за її функціональним призначенням:

1. **Зони дозволеного польоту (Keep-In або Inclusion Zones):** обсяги простору, всередині яких апарату дозволено здійснювати маневри. Якщо в польотному завданні сконфігуровано кілька зон Keep-In, вони об'єднуються за правилом логічного «АБО» (диз'юнкція): апарат може перебувати в будь-якій із них.
2. **Зони заборони польоту (Keep-Out або Exclusion Zones):** обсяги простору, куди апарату залітати категорично заборонено (вежі зв'язку, лінії електропередач, промислові підприємства, будівлі). Зони заборони діють за правилом логічного заперечення: апарат не повинен перетинати жодну з них.

![Композиція геозон Keep-In та Keep-Out з AABB](/root/sys/sys-dron/geofence-algorithm/img/inclusion-exclusion-composite.svg)
*Композиція дозволеного простору: дрон зобов'язаний перебувати всередині хоча б однієї зони Keep-In та одночасно поза всіма зонами Keep-Out. Зовнішній прямокутник AABB забезпечує попереднє відсікання зон за O(1).*

Математично умова перебування апарата в легітимному просторі виражається булевою функцією:

```
Valid(P) = (Count(KeepIn) = 0 ∨ (∃ i: P ∈ KeepIn[i])) ∧ (∀ j: P ∉ KeepOut[j])
```

Якщо в польотному контролері не задано жодної зони Keep-In, за замовчуванням дозволеним вважається весь світ, за винятком явно оголошених зон Keep-Out. Якщо ж визначено хоча б один впускний полігон, вихід за його межі миттєво генерує сигнал тривоги, навіть якщо дрон не наблизився до жодної зони Keep-Out.

#### Дворівнева просторова фільтрація через AABB

Перевірка довільного багатокутника з `N` вершинами вимагає проходу по всіх його ребрах. Коли в системі завантажено десятки полігонів, поцикловий перебір кожного ребра створює неприпустиме навантаження на процесор. Для оптимізації застосовують **габаритні контейнери, вирівняні по осях (Axis-Aligned Bounding Box, AABB)**.

Під час завантаження геозони для кожного полігона обчислюються мінімальні та максимальні координати його вершин:

```
min_x = min(V_0.x, V_1.x, ..., V_{N-1}.x)
max_x = max(V_0.x, V_1.x, ..., V_{N-1}.x)
min_y = min(V_0.y, V_1.y, ..., V_{N-1}.y)
max_y = max(V_0.y, V_1.y, ..., V_{N-1}.y)
```

Перевірка точки `P = (P.x, P.y)` починається з швидкого тесту AABB, що вимагає лише чотирьох скалярних порівнянь:

```
In_AABB(P) = (P.x ≥ min_x) ∧ (P.x ≤ max_x) ∧ (P.y ≥ min_y) ∧ (P.y ≤ max_y)
```

Якщо умова `In_AABB(P)` хибна:
- Для зони **Keep-Out** алгоритм миттєво повертає `false` (точка гарантовано поза зоною заборони, порушення немає) без обробки ребер.
- Для зони **Keep-In** алгоритм знає, що точка поза цією зоною впуску, заощаджуючи час на повному геометричному аналізі.

Тільки якщо точка потрапляє всередину габаритного прямокутника `AABB`, викликається точний алгоритм перевірки належності полігону.

#### Просторова сітка (Spatial Grid Indexing) для масивів зон

Коли кількість заборонених зон досягає кількох десятків (наприклад, у міських умовах або під час інспекції промислових зон із багатьма щоглами й опорами), послідовна перевірка навіть легких AABB починає відбирати помітний час. У таких випадках застосовують **рівномірну просторову сітку (Spatial Hash Grid)**.

Робоча ділянка розбивається на квадратні комірки розміром `S_cell` (наприклад, 500×500 м). Кожна полігональна зона чи циліндр асоціюється лише з тими комірками, габарити яких перетинаються з її AABB. Під час польоту дрон обчислює індекси своєї поточної комірки за одну операцію ділення:

```
cell_x = (P.x - Origin.x) ÷ S_cell
cell_y = (P.y - Origin.y) ÷ S_cell
```

Замість перевірки всіх `M` зон у системі, перевіряються лише 1–3 зони, зареєстровані в поточній комірці `(cell_x, cell_y)`, що перетворює складність вибірки активних зон із `O(M)` на `O(1)`.

### Алгоритм променя (Ray-Casting) та обчислювальна геометрія на MCU

Для визначення належності точки довільному полігону на площині в обчислювальній геометрії існують два класичних підходи: алгоритм підрахунку числа обертів (англ. *Winding Number Algorithm*) та алгоритм пускання променя (англ. *Ray-Casting Algorithm / Even-Odd Rule*).

Алгоритм числа обертів інтегрує кутові зміщення точки відносно кожного ребра:

```
W = (1 ÷ 2π) · ∑ θ_i
```

Точка лежить всередині, якщо сумарне число повних обертів `W ≠ 0`. Проте обчислення суми кутів на мікроконтролері вимагає викликів арктангенса `atan2()` або покрокової класифікації квадрантів для кожного ребра, що у 5–8 разів повільніше за пускання променя.

Алгоритм пускання променя спирається на теорему Жордана про замкнену криву: з досліджуваної точки `P = (P.x, P.y)` у додатному напрямку горизонтальної осі `+X` (де `y = P.y`, `x ≥ P.x`) випускається напівпряма. Алгоритм підраховує кількість її перетинів зі сторонами багатокутника.

![Алгоритм пускання променя та обробка ребер полігона](/root/sys/sys-dron/geofence-algorithm/img/ray-casting-edges.svg)
*Принцип пускання променя: для внутрішньої точки P_in кількість перетинів ребер непарна (k = 3), для зовнішньої точки P_out — парна (k = 2). Напіввідкриті інтервали по осі Y виключають подвійний підрахунок вершин.*

Кожен перетин межі змінює топологічний стан: перехід ззовні всередину або зсередини назовні. Отже:
- **Непарна кількість перетинів (`k % 2 == 1`):** точка лежить **всередині** багатокутника;
- **Парна кількість перетинів (`k % 2 == 0`):** точка лежить **зовні** багатокутника.

Важливою властивістю правила парності є його **інваріантність до орієнтації обходу вершин**: алгоритм працює однаково коректно як при нумерації вершин за годинниковою стрілкою (CW), так і проти годинникової стрілки (CCW), що усуває потребу у валідації знака площі при завантаженні місії.

#### Самоперетини та валідація простих багатокутників

Правило парності передбачає, що контур полігона є **простим** (жордановим), тобто ребра не перетинаються між собою. Якщо оператор під час планування місії помилково створює контур із самоперетином (наприклад, у формі «вісімки»), правило Even-Odd розділить внутрішній простір на зони з різною парністю: центральна область виявиться топологічно «зовнішньою», що створить невидиму дірку всередині зони впуску.

Тому перед завантаженням геозони на борт наземна станція (QGC) або передпольотний валідатор прошивки перевіряє полігон на відсутність самоперетинів за алгоритмом Бентлі-Оттманна (Bentley-Ottmann) або попарною перевіркою відрізків за `O(N²)`, відхиляючи некоректні контури до старту місії.

#### Математика перетину відрізка променем

Розглянемо ребро полігона, утворене парою вершин `A = (A.x, A.y)` та `B = (B.x, B.y)`. Горизонтальний промінь `y = P.y` перетинає пряму, що проходить через `AB`, у точці з абсцисою `x_int`. 

Рівняння прямої через дві точки має вигляд:

```
(x - A.x) ÷ (B.x - A.x) = (y - A.y) ÷ (B.y - A.y)
```

Підставивши `y = P.y`, знаходимо координату перетину `x_int`:

```
x_int - A.x = (P.y - A.y) · (B.x - A.x) ÷ (B.y - A.y)
x_int = A.x + (P.y - A.y) · (B.x - A.x) ÷ (B.y - A.y)
```

Промінь спрямований управо від точки `P`, тому перетин зараховується лише тоді, коли точка перетину лежить праворуч від `P.x`, тобто `x_int > P.x`.

#### Обробка крайових випадків та сингулярностей

Наївна реалізація алгоритму променя ламається на трьох класичних геодезичних крайових випадках:
1. **Промінь проходить точно через вершину:** якщо вершина належить двом ребрам, промінь може перетнути обидва відрізки в одній точці, подвоївши лічильник і давши хибний висновок про парність.
2. **Горизонтальне ребро (`A.y == B.y`):** знаменник `(B.y - A.y)` перетворюється на нуль, викликаючи апаратний виняток ділення на нуль або переповнення `NaN`.
3. **Промінь збігається з горизонтальною стороною:** промінь накладається на ребро на всій його довжині.

Для бездоганного розв'язання цих проблем застосовують концепцію **напіввідкритих вертикальних інтервалів**. Ребро вважається активним для перевірки тоді й тільки тоді, коли координата `P.y` потрапляє в напіввідкритий діапазон висот ребра:

```
Condition_Y = (A.y ≤ P.y < B.y) ∨ (B.y ≤ P.y < A.y)
```

Таке формулювання дає фундаментальні математичні інваріанти:
- **Усунення подвійного рахунку вершин:** Якщо промінь проходить через вершину `V_i`, то для ребра, що закінчується у `V_i`, умова `y < V_i.y` буде хибною (верхня межа виключена), а для ребра, що починається у `V_i`, умова `V_i.y ≤ y` буде істинною (нижня межа включена). Вершина зараховується **рівно один раз**.
- **Автоматичне відсікання горизонтальних ребер:** Для горизонтального відрізка `A.y == B.y`. Умова `(A.y ≤ P.y < A.y)` є тотожно хибною за будь-яких значень `P.y`. Горизонтальні ребра ігноруються миттєво, усуваючи будь-яку можливість ділення на нуль.

#### Цілочисельна оптимізація під мікроконтролери (Fixed-Point Math)

Більшість польотних контролерів базуються на мікроконтролерах із 32-бітною архітектурою (наприклад, STM32F4/F7/H7 на ядрі ARM Cortex-M). Операції ділення чисел із плаваючою комою одинарної точності виконуються за 14–20 тактів, а подвійної точності на Cortex-M4 емулюються програмно сотнями тактів. Крім того, накопичення похибок заокруглення `float32` на великих географічних координатах призводить до тремтіння меж на сантиметрових відстанях.

Для усунення цих недоліків координати `WGS84` масштабують у цілі числа фіксованої коми: `lat_e7 = lat · 10⁷` та `lon_e7 = lon · 10⁷`. При цьому дискретність становить `10⁻⁷` градуса (близько 1.11 см), що покриває будь-які потреби навігації без втрати точності.

Перетворимо умову `P.x < x_int` так, щоб виключити операцію ділення:

```
P.x < A.x + (P.y - A.y) · (B.x - A.x) ÷ (B.y - A.y)
P.x - A.x < (P.y - A.y) · (B.x - A.x) ÷ (B.y - A.y)
```

Знак нерівності при множенні на `(B.y - A.y)` залежить від напрямку ребра:
1. Якщо ребро спрямоване **вгору** (`B.y > A.y`), різниця `(B.y - A.y) > 0`:
   ```
   (P.x - A.x) · (B.y - A.y) < (P.y - A.y) · (B.x - A.x)
   (P.x - A.x) · (B.y - A.y) - (P.y - A.y) · (B.x - A.x) < 0
   ```
2. Якщо ребро спрямоване **вниз** (`B.y < A.y`), різниця `(B.y - A.y) < 0`. Множення на від'ємне число перевертає знак нерівності:
   ```
   (P.x - A.x) · (B.y - A.y) > (P.y - A.y) · (B.x - A.x)
   (P.x - A.x) · (B.y - A.y) - (P.y - A.y) · (B.x - A.x) > 0
   ```

Вираз `(P.x - A.x) · (B.y - A.y) - (P.y - A.y) · (B.x - A.x)` є z-компонентою 2D-векторного (псевдоскалярного) добутку векторів `(P - A)` та `(B - A)`: він визначає, з якого боку від орієнтованої прямої `AB` лежить точка `P`. 

При відніманні двох `int32_t` різниця вміщується в діапазон `[-2·10⁹, 2·10⁹]`. Їхній добуток може досягати `4·10¹⁸`, що перевищує 32 біти, тому множення обов'язково виконується в 64-бітному типі `int64_t`. На процесорах ARM Cortex-M4/M7 інструкція `SMLAL` або `SMULL` виконує 32×32 -> 64-бітне множення за один такт.

:::tabs
```c
// Оптимізована функція перевірки належності точки полігону на цілих числах.
// Повертає true, якщо точка (px, py) всередині полігона.
// Координати задані у форматі int32_t (градуси * 1e7).

bool point_in_polygon_fixed(int32_t px, int32_t py,
                            const int32_t vx[], const int32_t vy[],
                            uint8_t n) {
    bool inside = false;
    uint8_t j = n - 1;

    for (uint8_t i = 0; i < n; i++) {
        // Перевірка напіввідкритого вертикального інтервалу
        if ((vy[i] <= py && py < vy[j]) || (vy[j] <= py && py < vy[i])) {
            // Векторний добуток без ділення
            int64_t cross = (int64_t)(px - vx[i]) * (int64_t)(vy[j] - vy[i]) -
                            (int64_t)(py - vy[i]) * (int64_t)(vx[j] - vx[i]);

            if (vy[i] < vy[j]) {
                // Ребро спрямоване вгору: перетин праворуч, якщо cross < 0
                if (cross < 0) inside = !inside;
            } else {
                // Ребро спрямоване вниз: перетин праворуч, якщо cross > 0
                if (cross > 0) inside = !inside;
            }
        }
        j = i;
    }
    return inside;
}
```

```cpp
// Ідіоматична C++20 версія алгоритму перевірки належності точки полігону.
// Використовує std::span для безпечного доступу та constexpr для обчислень.

#include <span>
#include <cstdint>

namespace drone::geometry {

struct Point2D {
    std::int32_t x{0};
    std::int32_t y{0};
};

[[nodiscard]] constexpr bool is_point_in_polygon(Point2D p,
                                                 std::span<const Point2D> polygon) noexcept {
    const std::size_t n = polygon.size();
    if (n < 3) [[unlikely]] {
        return false;
    }

    bool inside = false;
    std::size_t j = n - 1;

    for (std::size_t i = 0; i < n; ++i) {
        const auto& vi = polygon[i];
        const auto& vj = polygon[j];

        if ((vi.y <= p.y && p.y < vj.y) || (vj.y <= p.y && p.y < vi.y)) {
            const std::int64_t cross = static_cast<std::int64_t>(p.x - vi.x) * (vj.y - vi.y) -
                                       static_cast<std::int64_t>(p.y - vi.y) * (vj.x - vi.x);

            if (vi.y < vj.y) {
                if (cross < 0) {
                    inside = !inside;
                }
            } else {
                if (cross > 0) {
                    inside = !inside;
                }
            }
        }
        j = i;
    }
    return inside;
}

} // namespace drone::geometry
```

### Кінематичне прогнозування порушення (Predictive Geofence Breach)

Миттєва перевірка координат відповідає лише на питання «чи перебуває апарат у межах прямо зараз». Проте якщо апарат летить зі швидкістю `V`, фізичні закони динаміки вимагають скінченного часу на зупинку.

![Динамічне прогнозування порушення: швидкість, затримка та гальмівний шлях](/root/sys/sys-dron/geofence-algorithm/img/predictive-breach-braking.svg)
*Динаміка зупинки: повна дистанція зупинки D_stop складається зі шляху затримки реакції d_react та гальмівного шляху d_brake. Якщо прогнозована точка P_pred виходить за межу, автопілот ініціює маневр ухилення заздалегідь.*

#### Фізика гальмування мультикоптерів проти літаків

Механіка утримання кордону істотно відрізняється залежно від аеродинамічної схеми апарата:

- **Мультикоптери (роторні безпілотники):** для уповільнення коптер нахиляє корпус назад на кут тангажу `θ`, створюючи горизонтальну складову тяги проти вектора руху. Граничне гальмівне прискорення визначається гравітацією та максимальним кутом нахилу:
  ```
  a_max = g · tan(θ_max)
  ```
  При типовому куті `θ_max = 30°` теоретичне прискорення сягає `9.81 · tan(30°) ≈ 5.66 м/с²`. Проте обмеження кутової швидкості стабілізації (Slew Rate) та обмеження на ривок (Jerk, похідна від прискорення `da/dt`) обмежують реальне гальмування величинами `2.0...3.5 м/с²`.
- **Літаки (фіксоване крило):** літак не здатний зависнути на місці, оскільки його повітряна швидкість не може опускатися нижче швидкості звалювання `V_stall`. Єдиним способом уникнути виходу за межу для літака є виконання координованого віражу з кутом крену `φ_max`. Мінімальний радіус розвороту літака становить:
  ```
  R_turn = V² ÷ (g · tan(φ_max))
  ```
  Для літака, що летить на швидкості `25 м/с` із граничним креном `φ_max = 45°`, радіус віражу дорівнює `25² / (9.81 · 1.0) ≈ 63.7 м`. Щоб літак зміг розвернутися на 180° і не пробити межу, ширина буферної смуги геозони повинна перевищувати діаметр розвороту: `Margin_plane ≥ 2 · R_turn ≈ 130 м`.

#### Динамічне розширення буфера за коваріацією EKF

Точність визначення положення не є абсолютною і змінюється під час польоту через зміну геометричного фактора DOP, багатопроменевість сигналу GNSS або роботу в умовах завад. Розширений фільтр Калмана (EKF) видає оцінку стандартного відхилення горизонтальної позиції `σ_pos`.

Для гарантування надійності статичний запас безпеки динамічно адаптується за правилом трьох сигм (`3σ`, 99.7% довірчий інтервал):

```
Margin_dynamic = Margin_base + 3 · σ_pos
```

Якщо дисперсія GPS зростає з `0.6 м` до `4.0 м` (наприклад, у міському каньйоні), буферна смуга автоматично розширюється на `10.2 м`, запобігаючи помилковому входу в небезпечну зону при зашумлених вимірюваннях.

Процес екстреного гальмування коптера складається з двох послідовних фаз:

1. **Фаза латентності системи (`t_delay`):** період часу між моментом наближення до межі та формуванням фізичного гальмівного прискорення двигунами. Вона включає затримку фільтрації EKF (20–100 мс), період опитування алгоритму геозони (20–100 мс), затримку каналу зв'язку та час перевороту/нахилу апарата (Attitude Slew Rate) для створення протитяги (200–500 мс). Сумарна затримка становить `t_delay ≈ 0.3...0.6 с`. Протягом цього часу апарат продовжує летіти з поточною швидкістю:
   ```
   d_react = |V| · t_delay
   ```
2. **Фаза активного уповільнення (`a_max`):** гальмування з максимально допустимим для поточної конструкції прискоренням `a_max`. Гальмівний шлях визначається кінематичною формулою:
   ```
   d_brake = |V|² ÷ (2 · a_max)
   ```

Повний динамічний дистанційний поріг зупинки `D_stop` дорівнює сумі цих величин плюс адаптований запас безпеки `Margin_dynamic`:

```
D_stop = |V| · t_delay + |V|² ÷ (2 · a_max) + Margin_dynamic
```

#### Розрахунок точки випередження (Lookahead Point)

Найпростіший спосіб прогнозування полягає в перевірці не поточної точки `P`, а екстрапольованої точки передбачуваної зупинки `P_pred`:

```
P_pred = P + (V ÷ |V|) · D_stop
```

Якщо точка `P_pred` виходить за межі впускного полігону або входить у заборонений циліндр, автопілот фіксує стан **прогнозованого порушення (Predictive Breach)** та негайно переводить контур навігації в режим екстреного гальмування.

#### Обчислення часу до перетину (Time-To-Breach, TTB) та відстані до ребер

Для більш плавного керування швидкістю автопілот розраховує точний час до перетину межі (Time-To-Breach, TTB). Для цього обчислюється відстань від поточної точки `P` до кожного відрізка `AB` полігона.

Вектор ребра `e = B - A`, вектор від початку ребра до точки `w = P - A`. Параметр проєкції `u` точки `P` на пряму `AB`:

```
u = (w · e) ÷ |e|² = ((P.x - A.x) · (B.x - A.x) + (P.y - A.y) · (B.y - A.y)) ÷ ((B.x - A.x)² + (B.y - A.y)²)
```

Параметр `u` обмежується діапазоном `[0, 1]` для знаходження найближчої точки `Q` на відрізку:

```
u_clamped = max(0, min(1, u))
Q = A + u_clamped · e
```

Відстань від апарата до ребра становить `dist = |P - Q|`. Якщо вектор швидкості `V` спрямований у бік ребра, проєкція швидкості на нормаль до ребра дорівнює:

```
v_perp = (V · (Q - P)) ÷ |Q - P|
```

Час до зіткнення з цією ділянкою межі визначається як:

```
TTB = dist ÷ v_perp    [для v_perp > 0]
```

Якщо мінімальний `TTB` серед усіх ребер падає нижче критичного порогу `T_crit = t_delay + |V| / a_max`, апарат негайно починає гальмування.

### Скінченний автомат геозонування та ескалація Failsafe

Обробка геозони реалізується у вигляді скінченного автомата (FSM — Finite State Machine), інтегрованого в підсистему [безпечного відмову (failsafe)](root:sys-dron/failsafe).

![Скінченний автомат стану та ієрархія захисних дій](/root/sys/sys-dron/geofence-algorithm/img/geofence-state-machine.svg)
*Стани автомата геозонування: переходи між SAFE, WARNING та BREACH з викликом відповідних ступенів захисту failsafe.*

Автомат підтримує три стани:

1. **`GEOFENCE_SAFE` (Штатний стан):** дрон знаходиться всередині дозволеного простору, прогнозована точка `P_pred` вільна від перешкод, `TTB` перевищує поріг попередження `T_warn` (типово 3–5 с). Польотний стек виконує поточну місію або команди оператора без обмежень.
2. **`GEOFENCE_WARNING` (Попередження):** дрон наблизився до смуги запасу або `TTB ≤ T_warn`. Автопілот надсилає статусний пакет MAVLink `STATUSTEXT` на наземну станцію керування (GCS) та активує функцію **динамічного обмеження швидкості**: вектор швидкості у напрямку межі штучно обмежується пропорційно залишковій відстані, не дозволяючи розігнатися в бік стіни.
3. **`GEOFENCE_BREACH` (Порушення межі):** точка `P` перетнула межу або `TTB ≤ T_crit` (пробиття неминуче без екстрених дій). Автопілот повністю перехоплює керування у ручного режиму або планувальника місії та активує заздалегідь налаштовану захисну дію (Breach Action).

#### Драбина захисних реакцій (Breach Actions)

Залежно від конфігурації параметрів апарата (у ArduPilot параметр `FENCE_ACTION`, у PX4 `GF_ACTION`) виконується одна з дій за ієрархією:

- **1. Hold / Brake (Зупинка на місці):** найпростіша дія для мультикоптерів — скинути горизонтальну швидкість до нуля та перейти в режим зависання (Loiter/Hold), очікуючи втручання пілота.
- **2. Smart-RTL (Повернення чистим треком):** апарат повертається назад точно по власному раніше пройденому безпечному шляху, уникаючи потрапляння в зони Keep-Out, повз які він щойно пролетів.
- **3. RTL (Return to Launch):** набір безпечної висоти повернення та політ по прямій до точки зльоту (Home). Якщо на прямій траєкторії повернення лежить зона Keep-Out, сучасні автопілоти будують обхідний шлях за алгоритмом A* або Dijkstra.
- **4. Emergency Land (Аварійна посадка):** вертикальний спуск на місці з контрольованою швидкістю при дефіциті заряду батареї або відмові навігації.
- **5. Flight Termination (Примусове припинення польоту):** відсічка живлення моторів та викид рятувального парашута, якщо дрон перетнув зовнішній критичний бар'єр полігона льотних випробувань.

### Багатопотокова синхронізація та Double-Buffering при завантаженні місії

У реальних польотних контролерах завантаження геозони здійснюється під час польоту через радіоканал MAVLink. Процес завантаження складається з десятків окремих транзакцій `MISSION_ITEM_INT` і триває від кількох сотих долі секунди до кількох секунд.

Якщо навігаційний потік (виконується на частоті 100 Гц у RTOS) читатиме масив вершин, який у цей самий момент перезаписується низькопріоритетним потоком телеметрії (MAVLink task), виникає критичний стан гонитви (Race Condition). Обчислювач може зчитати незамкнений багатокутник із нульовими координатами або змішаний набір вершин, що спричинить хибне спрацьовування failsafe та раптову аварійну зупинку моторів.

Для усунення цієї небезпеки без блокування швидкого навігаційного контуру м'ютексами застосовують **шаблон подвійної буферизації з атомарною підміною вказівника (Lock-Free Double Buffering)**:

1. Рушій утримує два екземпляри структури геозони: `active_engine` (використовується лише для читання навігаційним потоком) та `staging_engine` (використовується для збирання пакетів MAVLink).
2. Потік телеметрії завантажує вершини у `staging_engine`, перевіряє цілісність, замкненість контурів та обчислює AABB.
3. Після перевірки виконується атомарне перемикання вказівника активного екземпляра за одну машинну інструкцію з бар'єром пам'яті (Memory Barrier), що усуває будь-які затримки та забезпечує абсолютну цілісність даних.

### Повна реалізація рушія геозонування на C та C++

Нижче наведено самодостатній виробничий модуль вбудованого геозонування, що містить підтримку циліндричних та полігональних зон, дворівневу фільтрацію AABB, цілочисельний Ray-Casting та кінематичний розрахунок гальмівного упередження.

Повний перелік структур даних, констант пам'яті та часових оцінок описано у вставці [довідка API бібліотеки геозонування](root:sys-dron/geofence-algorithm/api-geofence.md).

```c
// geofence_engine.c — Виробничий модуль геозонування на C99 для польотних контролерів.
// Без динамічного виділення пам'яті (Zero-Heap Allocation).

#include <stdint.h>
#include <stdbool.h>
#include <math.h>

#define MAX_POLY_VERTICES 16
#define MAX_POLYGONS     8
#define MAX_CYLINDERS    8

typedef struct {
    int32_t lat_e7;
    int32_t lon_e7;
    float   alt_m;
} GeoPoint;

typedef struct {
    int32_t min_lat;
    int32_t max_lat;
    int32_t min_lon;
    int32_t max_lon;
} BoundingBoxAABB;

typedef struct {
    GeoPoint       vertices[MAX_POLY_VERTICES];
    uint8_t        count;
    bool           is_keep_in;
    float          alt_min;
    float          alt_max;
    BoundingBoxAABB aabb;
    bool           active;
} PolygonFence;

typedef struct {
    GeoPoint center;
    float    radius_m;
    float    alt_min;
    float    alt_max;
    bool     is_keep_in;
    bool     active;
} CylinderFence;

typedef struct {
    PolygonFence  polygons[MAX_POLYGONS];
    CylinderFence cylinders[MAX_CYLINDERS];
    uint8_t       poly_count;
    uint8_t       cyl_count;
    float         max_braking_accel; // м/с²
    float         latency_sec;       // с
    float         static_margin_m;   // м
} GeofenceEngine;

// Оновлення AABB габаритів полігона
static void update_polygon_aabb(PolygonFence *poly) {
    if (poly->count == 0) return;
    poly->aabb.min_lat = poly->vertices[0].lat_e7;
    poly->aabb.max_lat = poly->vertices[0].lat_e7;
    poly->aabb.min_lon = poly->vertices[0].lon_e7;
    poly->aabb.max_lon = poly->vertices[0].lon_e7;

    for (uint8_t i = 1; i < poly->count; i++) {
        if (poly->vertices[i].lat_e7 < poly->aabb.min_lat) poly->aabb.min_lat = poly->vertices[i].lat_e7;
        if (poly->vertices[i].lat_e7 > poly->aabb.max_lat) poly->aabb.max_lat = poly->vertices[i].lat_e7;
        if (poly->vertices[i].lon_e7 < poly->aabb.min_lon) poly->aabb.min_lon = poly->vertices[i].lon_e7;
        if (poly->vertices[i].lon_e7 > poly->aabb.max_lon) poly->aabb.max_lon = poly->vertices[i].lon_e7;
    }
}

// Цілочисельний Ray-Casting
static bool is_point_in_polygon_fast(int32_t lat, int32_t lon, const PolygonFence *poly) {
    // Рівень 1: AABB фільтр O(1)
    if (lat < poly->aabb.min_lat || lat > poly->aabb.max_lat ||
        lon < poly->aabb.min_lon || lon > poly->aabb.max_lon) {
        return false;
    }

    // Рівень 2: Перевірка перетинів ребер O(N)
    bool inside = false;
    uint8_t j = poly->count - 1;

    for (uint8_t i = 0; i < poly->count; i++) {
        int32_t yi = poly->vertices[i].lat_e7;
        int32_t xi = poly->vertices[i].lon_e7;
        int32_t yj = poly->vertices[j].lat_e7;
        int32_t xj = poly->vertices[j].lon_e7;

        if ((yi <= lat && lat < yj) || (yj <= lat && lat < yi)) {
            int64_t cross = (int64_t)(lon - xi) * (int64_t)(yj - yi) -
                            (int64_t)(lat - yi) * (int64_t)(xj - xi);

            if (yi < yj) {
                if (cross < 0) inside = !inside;
            } else {
                if (cross > 0) inside = !inside;
            }
        }
        j = i;
    }
    return inside;
}

// Перевірка циліндричної зони
static bool is_point_in_cylinder(const GeoPoint *p, const CylinderFence *cyl) {
    if (p->alt_m < cyl->alt_min || p->alt_m > cyl->alt_max) return false;

    // Відстань у площині через еквідистантну проєкцію
    float lat_rad = (float)cyl->center.lat_e7 * 1e-7f * (3.14159265f / 180.0f);
    float d_lat_m = (float)(p->lat_e7 - cyl->center.lat_e7) * 1e-7f * 111319.5f;
    float d_lon_m = (float)(p->lon_e7 - cyl->center.lon_e7) * 1e-7f * 111319.5f * cosf(lat_rad);

    return (d_lat_m * d_lat_m + d_lon_m * d_lon_m) <= (cyl->radius_m * cyl->radius_m);
}

// Повна перевірка належності дозволеному простору
bool geofence_check_point(const GeofenceEngine *engine, const GeoPoint *p) {
    bool has_keep_in = false;
    bool inside_keep_in = false;

    // 1. Перевірка полігонів
    for (uint8_t i = 0; i < engine->poly_count; i++) {
        if (!engine->polygons[i].active) continue;

        bool alt_ok = (p->alt_m >= engine->polygons[i].alt_min &&
                       p->alt_m <= engine->polygons[i].alt_max);

        bool in_poly_2d = is_point_in_polygon_fast(p->lat_e7, p->lon_e7, &engine->polygons[i]);
        bool inside_3d = alt_ok && in_poly_2d;

        if (engine->polygons[i].is_keep_in) {
            has_keep_in = true;
            if (inside_3d) inside_keep_in = true;
        } else {
            // Зона Keep-Out: вхід заборонено!
            if (inside_3d) return false;
        }
    }

    // 2. Перевірка циліндрів
    for (uint8_t i = 0; i < engine->cyl_count; i++) {
        if (!engine->cylinders[i].active) continue;

        bool in_cyl = is_point_in_cylinder(p, &engine->cylinders[i]);
        if (engine->cylinders[i].is_keep_in) {
            has_keep_in = true;
            if (in_cyl) inside_keep_in = true;
        } else {
            if (in_cyl) return false;
        }
    }

    if (has_keep_in && !inside_keep_in) return false;
    return true;
}

// Кінематична перевірка з гальмівним упередженням
bool geofence_predictive_check(const GeofenceEngine *engine,
                               const GeoPoint *p,
                               float vx_mps, float vy_mps, float vz_mps) {
    // 1. Перевірка поточної позиції
    if (!geofence_check_point(engine, p)) return false;

    float speed = sqrtf(vx_mps * vx_mps + vy_mps * vy_mps + vz_mps * vz_mps);
    if (speed < 0.1f) return true; // Дрон практично стоїть на місці

    // 2. Обчислення гальмівного шляху D_stop
    float d_stop = speed * engine->latency_sec +
                   (speed * speed) / (2.0f * engine->max_braking_accel) +
                   engine->static_margin_m;

    // 3. Розрахунок точки упередження P_pred
    float lookahead_ratio = d_stop / speed;
    float d_north_m = vx_mps * lookahead_ratio;
    float d_east_m  = vy_mps * lookahead_ratio;
    float d_alt_m   = vz_mps * lookahead_ratio;

    GeoPoint p_pred;
    p_pred.lat_e7 = p->lat_e7 + (int32_t)(d_north_m * (1e7f / 111319.5f));
    float lat_rad = (float)p->lat_e7 * 1e-7f * (3.14159265f / 180.0f);
    p_pred.lon_e7 = p->lon_e7 + (int32_t)(d_east_m * (1e7f / (111319.5f * cosf(lat_rad))));
    p_pred.alt_m  = p->alt_m + d_alt_m;

    // 4. Перевірка валідності точки упередження
    return geofence_check_point(engine, &p_pred);
}
```

```cpp
// geofence_engine.hpp — Сучасний C++20 модуль геозонування.
// Використовує строгу типізацію, constexpr та std::span.

#pragma once
#include <cstdint>
#include <span>
#include <array>
#include <cmath>
#include <numbers>

namespace drone::geofence {

struct GeoPoint {
    std::int32_t lat_e7{0};
    std::int32_t lon_e7{0};
    float        alt_m{0.0f};
};

struct VelocityNed {
    float vx{0.0f};
    float vy{0.0f};
    float vz{0.0f};

    [[nodiscard]] float speed() const noexcept {
        return std::sqrt(vx * vx + vy * vy + vz * vz);
    }
};

struct BoundingBoxAABB {
    std::int32_t min_lat{0};
    std::int32_t max_lat{0};
    std::int32_t min_lon{0};
    std::int32_t max_lon{0};

    [[nodiscard]] constexpr bool contains(std::int32_t lat, std::int32_t lon) const noexcept {
        return lat >= min_lat && lat <= max_lat && lon >= min_lon && lon <= max_lon;
    }
};

enum class ZoneType : std::uint8_t {
    KeepIn,
    KeepOut
};

inline constexpr std::size_t MaxPolygonVertices = 16;
inline constexpr std::size_t MaxPolygons        = 8;
inline constexpr std::size_t MaxCylinders       = 8;

struct PolygonFence {
    std::array<GeoPoint, MaxPolygonVertices> vertices{};
    std::uint8_t                            count{0};
    ZoneType                                type{ZoneType::KeepIn};
    float                                   alt_min{0.0f};
    float                                   alt_max{120.0f};
    BoundingBoxAABB                         aabb{};
    bool                                    active{true};

    void update_aabb() noexcept {
        if (count == 0) return;
        aabb.min_lat = aabb.max_lat = vertices[0].lat_e7;
        aabb.min_lon = aabb.max_lon = vertices[0].lon_e7;

        for (std::size_t i = 1; i < count; ++i) {
            aabb.min_lat = std::min(aabb.min_lat, vertices[i].lat_e7);
            aabb.max_lat = std::max(aabb.max_lat, vertices[i].lat_e7);
            aabb.min_lon = std::min(aabb.min_lon, vertices[i].lon_e7);
            aabb.max_lon = std::max(aabb.max_lon, vertices[i].lon_e7);
        }
    }
};

struct CylinderFence {
    GeoPoint center{};
    float    radius_m{100.0f};
    float    alt_min{0.0f};
    float    alt_max{120.0f};
    ZoneType type{ZoneType::KeepIn};
    bool     active{true};
};

class GeofenceEngine {
public:
    struct Config {
        float max_braking_accel_mps2{2.5f};
        float system_latency_s{0.3f};
        float static_margin_m{5.0f};
    };

    explicit constexpr GeofenceEngine(Config cfg = {}) noexcept : config_{cfg} {}

    [[nodiscard]] bool check_containment(const GeoPoint& p) const noexcept {
        bool has_keep_in = false;
        bool inside_keep_in = false;

        // Перевірка полігональних зон
        for (std::size_t i = 0; i < poly_count_; ++i) {
            const auto& poly = polygons_[i];
            if (!poly.active) continue;

            const bool alt_ok = (p.alt_m >= poly.alt_min && p.alt_m <= poly.alt_max);
            const bool in_poly = alt_ok && is_inside_polygon(p.lat_e7, p.lon_e7, poly);

            if (poly.type == ZoneType::KeepIn) {
                has_keep_in = true;
                if (in_poly) inside_keep_in = true;
            } else {
                if (in_poly) return false; // Порушення Keep-Out
            }
        }

        // Перевірка циліндричних зон
        for (std::size_t i = 0; i < cyl_count_; ++i) {
            const auto& cyl = cylinders_[i];
            if (!cyl.active) continue;

            const bool in_cyl = is_inside_cylinder(p, cyl);
            if (cyl.type == ZoneType::KeepIn) {
                has_keep_in = true;
                if (in_cyl) inside_keep_in = true;
            } else {
                if (in_cyl) return false; // Порушення Keep-Out
            }
        }

        return !has_keep_in || inside_keep_in;
    }

    [[nodiscard]] bool predict_breach(const GeoPoint& p, const VelocityNed& vel) const noexcept {
        if (!check_containment(p)) return false;

        const float spd = vel.speed();
        if (spd < 0.1f) return true;

        const float d_stop = spd * config_.system_latency_s +
                             (spd * spd) / (2.0f * config_.max_braking_accel_mps2) +
                             config_.static_margin_m;

        const float dt = d_stop / spd;
        const float d_north = vel.vx * dt;
        const float d_east  = vel.vy * dt;
        const float d_alt   = vel.vz * dt;

        GeoPoint p_pred;
        p_pred.lat_e7 = p.lat_e7 + static_cast<std::int32_t>(d_north * (1e7f / 111319.5f));
        const float lat_rad = static_cast<float>(p.lat_e7) * 1e-7f * (std::numbers::pi_v<float> / 180.0f);
        p_pred.lon_e7 = p.lon_e7 + static_cast<std::int32_t>(d_east * (1e7f / (111319.5f * std::cos(lat_rad))));
        p_pred.alt_m  = p.alt_m + d_alt;

        return check_containment(p_pred);
    }

    bool add_polygon(PolygonFence poly) noexcept {
        if (poly_count_ >= MaxPolygons) return false;
        poly.update_aabb();
        polygons_[poly_count_++] = poly;
        return true;
    }

    bool add_cylinder(const CylinderFence& cyl) noexcept {
        if (cyl_count_ >= MaxCylinders) return false;
        cylinders_[cyl_count_++] = cyl;
        return true;
    }

private:
    [[nodiscard]] static bool is_inside_polygon(std::int32_t lat, std::int32_t lon,
                                                const PolygonFence& poly) noexcept {
        if (!poly.aabb.contains(lat, lon)) return false;

        bool inside = false;
        std::size_t j = poly.count - 1;

        for (std::size_t i = 0; i < poly.count; ++i) {
            const std::int32_t yi = poly.vertices[i].lat_e7;
            const std::int32_t xi = poly.vertices[i].lon_e7;
            const std::int32_t yj = poly.vertices[j].lat_e7;
            const std::int32_t xj = poly.vertices[j].lon_e7;

            if ((yi <= lat && lat < yj) || (yj <= lat && lat < yi)) {
                const std::int64_t cross = static_cast<std::int64_t>(lon - xi) * (yj - yi) -
                                           static_cast<std::int64_t>(lat - yi) * (xj - xi);

                if (yi < yj) {
                    if (cross < 0) inside = !inside;
                } else {
                    if (cross > 0) inside = !inside;
                }
            }
            j = i;
        }
        return inside;
    }

    [[nodiscard]] static bool is_inside_cylinder(const GeoPoint& p,
                                                 const CylinderFence& cyl) noexcept {
        if (p.alt_m < cyl.alt_min || p.alt_m > cyl.alt_max) return false;

        const float lat_rad = static_cast<float>(cyl.center.lat_e7) * 1e-7f * (std::numbers::pi_v<float> / 180.0f);
        const float d_lat_m = static_cast<float>(p.lat_e7 - cyl.center.lat_e7) * 1e-7f * 111319.5f;
        const float d_lon_m = static_cast<float>(p.lon_e7 - cyl.center.lon_e7) * 1e-7f * 111319.5f * std::cos(lat_rad);

        return (d_lat_m * d_lat_m + d_lon_m * d_lon_m) <= (cyl.radius_m * cyl.radius_m);
    }

    Config                                      config_{};
    std::array<PolygonFence, MaxPolygons>       polygons_{};
    std::array<CylinderFence, MaxCylinders>     cylinders_{};
    std::size_t                                 poly_count_{0};
    std::size_t                                 cyl_count_{0};
};

} // namespace drone::geofence
```

### Підсумковий синтез архітектури

Стійкість та надійність системи геозонування досягається за рахунок суворого узгодження трьох компонентів:

1. **Цілісність вхідних навігаційних даних:** геозона спирається на достовірність фільтра оцінки стану [GNSS та ІВБ](root:sys-dron/gnss-i-ivb-razom). При деградації супутникового фіксу або виявленні супутникового глушіння автопілот переходить у спеціальний аварійний режим до того, як геозона почне видавати хибні спрацьовування.
2. **Детерміновані обчислення без блокувань:** цілочисельний Ray-Casting із захистом від сингулярностей та попередня фільтрація AABB гарантують сталий час обробки порядку одиниць мікросекунд, що дозволяє виконувати перевірку геозони в кожному циклі навігаційного контролера.
3. **Випереджальна кінематична безпека:** завдяки розрахунку гальмівного шляху та часу до перетину межі (TTB) автопілот усуває вплив інерції, забезпечуючи фізичне перебування апарата в межах дозволеного коридору за будь-яких польотних швидкостей.
