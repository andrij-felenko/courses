# Кінематична велосипедна модель

<preknowlist>
- [Кермо ровера](root:sys-dron/rover-steering) — диференційна та Аккерманова схеми, неголономна в'язь коліс.
- [Кутова швидкість](root:ph-mechanics/angular-velocity) — вектор і скаляр обертання твердого тіла навколо миттєвого центру.
- [Тверде тіло](root:ph-mechanics/rigid-body) — рух плоского твердого тіла, розклад на поступальний та обертальний рухи.
- [Кути Ейлера](root:math-geometry/euler-angles) — орієнтація та курс (yaw/heading) у двовимірній та тривимірній площинах.
</preknowlist>

Автономний колісний робот масою дві тонни з базою два з половиною метри на швидкості сорок кілометрів на годину входить у крутий поворот. Якщо польотний контролер чи бортовий комп'ютер уявить цей апарат матеріальною точкою, якій можна довільно задати миттєву швидкість у декартових осях `(ẋ, ẏ)`, машина зійде з траєкторії в перший же метр: автомобіль не має бічних реактивних двигунів і не вміє миттєво зсуватися вбік. Рух народжується виключно коченням коліс по твердій поверхні, де кожна вісь має власну орієнтацію. З іншого боку, якщо спробувати врахувати в алгоритмі реального часу всі чотири підвіски, диференціал, індивідуальні деформації кожної шини та поперечний перерозподіл навантаження на кузов, розв'язання задачі планування траєкторії вимагатиме важких матричних обчислень, що не встигатимуть у такт керування десять мікросекунд.

Кінематична велосипедна модель (англ. *kinematic bicycle model*, або *single-track model*) усуває цю проблему. Вона редукує складне чотириколісне шасі до елегантної двоколісної конструкції на поздовжній осі симетрії, залишаючи в рівняннях руху лише те, що принципово формує геометрію: відстань між осями, орієнтацію кузова та кут вивороту керованого колеса.

## Від чотирьох коліс до двох: зведення вздовж осі симетрії

Реальний автомобільний робот або ровер із класичною кермовою трапецією Аккермана спирається на чотири колеса: два задніх несучих і два передніх керованих. Коли такий апарат повертає, внутрішнє до центру повороту колесо котиться по дузі меншого радіуса, ніж зовнішнє. Щоб обидва передні колеса котилися чисто, без паразитного бічного зсуву та вищання гуми, кермова трапеція вивертає внутрішнє колесо на більший кут `δ_i`, а зовнішнє — на менший кут `δ_o`.

Ця різниця кутів критична для механічної конструкції тяг і шарнірів, але для планування траєкторії всього апарата на мапі вона створює зайву розмірність. Якщо ширина колії `W` помітно менша за радіус повороту `R` (`W ≪ R`), а бічне прискорення не перевищує порогу зчеплення шин, ліве й праве колеса кожної осі можна подумки стиснути вздовж поперечної лінії й замінити одним віртуальним колесом, розташованим строго на поздовжній осі симетрії.

![Зведення чотириколісного шасі до велосипедної моделі](/root/sys/sys-dron/bicycle-kinematic-model/img/bicycle-reduction.svg)
*Зведення чотириколісного шасі Аккермана до еквівалентної велосипедної моделі. Ліворуч — реальна геометрія з різними кутами вивороту лівого й правого коліс. Праворуч — одне віртуальне кероване колесо спереду під усередненим кутом δ та одне некероване ззаду на відстані бази L.*

Отримана схема має лише два колеса:
1. **Заднє віртуальне колесо:** зафіксоване вздовж поздовжньої осі корпусу. Воно може котитися тільки вперед або назад у напрямку поточного курсу `θ`.
2. **Переднє віртуальне колесо:** розташоване на відстані колісної бази `L` (англ. *wheelbase*) попереду заднього. Воно здатне повертатися навколо вертикальної осі на кут керма `δ` (англ. *steering angle*).

Кут `δ` пов'язаний із реальними кутами коліс Аккермана точним аналітичним співвідношенням через середнє арифметичне котангенсів:

```
cot(δ) = (cot(δ_i) + cot(δ_o)) / 2
```

При малих кутах вивороту це співвідношення перетворюється на звичайне середнє значення `δ ≈ (δ_i + δ_o) / 2`. Математичне зведення шасі до велосипедної схеми дає змогу повністю описати конфігурацію всього корпусу всього трьома змінними стану на площині замість десятка координат окремих важелів підвіски.

## Системи координат та матричні перетворення руху

Для строгого математичного опису кінематики введемо дві системи координат на площині:

1. **Глобальна інерціальна система відліку** `I = (X_I, Y_I)`: нерухома система координат карти (наприклад, східно-північна сітка ENU або топоцентрична система місії). Позиція робота в ній визначається декартовими координатами `(x, y)`.
2. **Локальна система координат корпусу** `B = (X_B, Y_B)` (англ. *Body frame*): рухома система, жорстко зв'язана з кузовом робота. Її початок поміщається в обрану опорну точку (центр задньої осі або центр мас), вісь `X_B` спрямована вперед вздовж поздовжньої осі симетрії машини, а вісь `Y_B` — ліворуч перпендикулярно до кузова.

Кут між віссю `X_I` та віссю `X_B` визначає **орієнтацію або курс робота** `θ` (англ. *heading* або *yaw angle*).

Будь-який вектор швидкості `v_B = [u, v_lat]ᵀ`, виміряний у зв'язаних осях робота (де `u` — поздовжня швидкість вперед, а `v_lat` — бічна швидкість ковзання ліворуч), перераховується у вектор швидкості у світовій системі координат `v_I = [ẋ, ẏ]ᵀ` через стандартну матрицю плоского повороту `R(θ)`:

```
[ẋ]   [cos(θ)  −sin(θ)] [   u  ]
[ẏ] = [sin(θ)   cos(θ)] [ v_lat]
```

Особливість кінематики колісного шасі полягає в тому, що величина `v_lat` у точці задньої осі тотожно дорівнює нулю завдяки силам тертя кочення шин.

## Неголономне обмеження: чому колесо не ковзає вбік

Ключова фізична властивість колеса полягає в анізотропії його взаємодії з ґрунтом чи асфальтом. У поздовжньому напрямку колесо вільно котиться навколо власної осі обертання майже без опору. У поперечному ж напрямку протектор шини чіпляється за мікронерівності поверхні, створюючи силу тертя спокою. За помірних швидкостей ця сила повністю унеможливлює миттєвий рух поперек площини обертання.

У механіці таке обмеження, накладене не на самі просторові координати, а на складові швидкості, називається **неголономною в'яззю** (від грец. *hólos* — «цілий» + *nómos* — «закон»; закон, який неможливо інтегрувати до алгебраїчного зв'язку між координатами).

![Неголономне кінематичне обмеження та розклад швидкостей](/root/sys/sys-dron/bicycle-kinematic-model/img/nonholonomic-constraints.svg)
*Неголономна в'язь кочення коліс. Миттєва бічна швидкість кожного колеса дорівнює нулю (рух боком заборонено). У світовій системі координат поздовжня швидкість корпусу v розкладається на проекції ẋ та ẏ відповідно до поточного кута курсу θ та кута зсуву швидкості β.*

Сформулюємо цю умову аналітично для заднього колеса. Нехай точка контакту заднього колеса має координати `(x_r, y_r)` у нерухомій системі відліку, а кузов розвернутий на кут курсу `θ`. Вектор швидкості задньої осі `(ẋ_r, ẏ_r)` мусить бути строго паралельним до поздовжньої осі робота. Це означає, що проекція швидкості на нормаль до площини колеса дорівнює нулю:

```
−ẋ_r · sin(θ) + ẏ_r · cos(θ) = 0
```

Це рівняння Пфаффа (диференціальна форма першого порядку). У матричному вигляді в'язь записується як `A(q) · q̇ = 0`, де `q = [x_r, y_r, θ]ᵀ`:

```
[−sin(θ)   cos(θ)   0] · [ẋ_r, ẏ_r, θ̇]ᵀ = 0
```

Його принципова особливість полягає в тому, що матрицю `A(q)` неможливо проінтегрувати й звести до вигляду `f(x_r, y_r, θ) = 0`. Робот не обмежений перебуванням на якійсь конкретній лінії чи площині: він може відвідати будь-яку точку `(x, y)` карти з будь-яким кутом `θ`. Проте в кожен фіксований момент часу вектор його миттєвої швидкості належить лише двовимірному підпростору, породженому дозволеними векторними полями.

Наслідок цього фундаментальний:
- **У просторі миттєвих швидкостей** система має лише 2 ступені вільності (можна задавати поздовжню лінійну швидкість `v` та швидкість зміни кута керма `δ̇`). Прямий бічний рух неможливий.
- **У просторі конфігурацій** робот має всі 3 ступені вільності `(x, y, θ)`. Завдяки дужкам Лі (комутації векторних полів руху вперед та повороту керма) послідовність маневрів уперед-назад дозволяє генерувати результуючий бічний зсув (як під час паралельного паркування між автомобілями).

Для переднього керованого колеса діє аналогічна неголономна в'язь, але площина його кочення розвернута відносно курсу на кут `δ`:

```
−ẋ_f · sin(θ + δ) + ẏ_f · cos(θ + δ) = 0
```

Поєднання цих двох неголономних обмежень для переднього і заднього коліс повністю однозначно диктує геометрію руху всього шасі.

## Геометрія миттєвого центру обертання (ICR)

Оскільки кожне колесо може рухатися лише вздовж власної поздовжньої осі, вектор швидкості кожної точки контакту спрямований строго по дотичній до траєкторії її кочення. За теоремою кінематики твердого тіла (теорема Ейлера-Шаля), будь-який плоский рух у кожен момент часу можна подати як чисте обертання навколо єдиної точки — **миттєвого центру обертання** (МЦО, англ. *Instantaneous Center of Rotation*, або *ICR*).

Щоб знайти положення МЦО, достатньо провести перпендикуляри до векторів швидкостей двох різних точок тіла:
1. Перпендикуляр до вектора швидкості заднього колеса лежить на продовженні осі заднього моста.
2. Перпендикуляр до вектора швидкості переднього колеса проходить через центр переднього колеса під кутом `δ` до поперечної осі.

![Геометрія повороту та миттєвий центр обертання (ICR)](/root/sys/sys-dron/bicycle-kinematic-model/img/icr-geometry.svg)
*Геометрична побудова миттєвого центру обертання (МЦО). Перетин перпендикулярів до заднього та переднього коліс визначає радіуси R_r, R_cg та R_f. Усе тверде тіло обертається навколо МЦО зі спільною кутовою швидкістю ω = θ̇.*

Перетин цих двох перпендикулярів утворює прямокутний трикутник з вершинами в МЦО, центрі задньої осі та центрі передньої осі.

З прямокутного трикутника знаходимо радіус повороту задньої осі `R_r`:

```
R_r = L / tan(δ)
```

де:
- `L` — колісна база (відстань між осями), метри;
- `δ` — кут повороту переднього колеса, радіани;
- `R_r` — радіус кривини траєкторії заднього колеса, метри.

Кривина траєкторії `κ` (англ. *curvature*) є величиною, оберненою до радіуса:

```
κ = 1 / R_r = tan(δ) / L
```

З цієї формули чітко видно взаємозв'язок: коли кермо стоїть прямо (`δ = 0`), тангенс дорівнює нулю, радіус прямує до нескінченності, а кривина дорівнює нулю — апарат рухається по прямій. Що більший кут вивороту `δ`, то менший радіус і крутіший поворот.

Гіпотенуза трикутника визначає радіус повороту переднього колеса `R_f`:

```
R_f = L / sin(δ)
```

Повне покрокове виведення всіх геометричних співвідношень та тригонометричних тотожностей наведено у вставці [Геометричне виведення кінематичних рівнянь велосипедної моделі](root:sys-dron/bicycle-kinematic-model/math-bicycle-derivation.md).

Оскільки все шасі є абсолютно твердим тілом, кутова швидкість обертання кузова навколо власного МЦО однакова для всіх його точок:

```
ω = θ̇ = v_r / R_r = (v_r / L) · tan(δ)
```

Це найпростіший зв'язок між лінійною швидкістю заднього колеса, кутом керма та кутовою швидкістю розвороту корпусу.

## Розподіл кута зсуву швидкості вздовж колісної бази

Уздовж поздовжньої осі робота лінійна швидкість кожної точки відрізняється як за модулем, так і за напрямком. Розглянемо довільну точку `P(s)`, розташовану на поздовжній осі на відстані `s` попереду заднього моста (де `0 ≤ s ≤ L`).

Відстань від точки `P(s)` до МЦО дорівнює:

```
R(s) = √(R_r² + s²) = √((L / tan(δ))² + s²)
```

Кут `β(s)` між вектором швидкості точки `P(s)` та поздовжньою віссю кузова (локальний кут зсуву швидкості) знаходиться з прямокутного трикутника:

```
tan(β(s)) = s / R_r = (s / L) · tan(δ)
β(s) = arctan((s / L) · tan(δ))
```

Розглянемо три характерні перерізи вздовж осі шасі:
1. **Задня вісь (`s = 0`):** `tan(β) = 0 ⟹ β = 0`. Вектор швидкості спрямований строго по осі кузова.
2. **Центр мас (`s = l_r`):** `tan(β) = (l_r / L) · tan(δ)`. Вектор швидкості відхилений на проміжний кут ковзання `β_cg`.
3. **Передня вісь (`s = L`):** `tan(β) = (L / L) · tan(δ) = tan(δ) ⟹ β = δ`. Вектор швидкості спрямований строго під кутом вивороту керма.

Модуль лінійної швидкості в точці `P(s)` пов'язаний зі швидкістю задньої осі через відношення радіусів:

```
v(s) = ω · R(s) = v_r · √(1 + (s / L)² · tan²(δ)) = v_r / cos(β(s))
```

Цей аналітичний розподіл показує: що далі точка розташована від задньої осі вперед, то вища її лінійна швидкість під час повороту і то сильніше вектор її руху спрямований убік.

## Диференціальні рівняння стану відносно трьох опорних точок

У системах автоматичного керування та навігації стан робота необхідно описувати у вигляді системи звичайних диференціальних рівнянь (ЗДУ):

```
q̇ = f(q, u)
```

де `q = [x, y, θ]ᵀ` — вектор стану робота у світовій системі координат, а `u = [v, δ]ᵀ` — вектор керуючих впливів (лінійна швидкість і кут керма).

Вигляд цих рівнянь залежить від того, яку саме фізичну точку шасі обрано за початок рухомої системи відліку. В інженерній практиці використовують три точки: центр задньої осі, центр мас ($CG$) та центр передньої осі.

### 1. Центр задньої осі

Центр задньої осі є найпопулярнішим вибором для алгоритмів геометричного слідування за траєкторією (наприклад, [навігації Pure Pursuit](root:sys-dron/pure-pursuit-navigation)). У цій точці вектор швидкості завжди колінеарний поздовжній осі кузова (`β = 0`):

```
ẋ_r = v_r · cos(θ)
ẏ_r = v_r · sin(θ)
θ̇   = (v_r / L) · tan(δ)
```

Перевага такого вибору — максимальна математична простота: у рівняннях швидкості `ẋ` та `ẏ` відсутні тригонометричні функції від кута керма `δ`, що спрощує побудову аналітичних розв'язків та диференціювання.

### 2. Центр мас (Center of Mass, CoM)

У системах оцінки стану за даними інерційних модулів (IMU) та супутникових приймачів (GNSS) датчики зазвичай встановлюють поблизу центру мас апарата. Крім того, динамічні контролери (Model Predictive Control) розраховують сили саме відносно центру мас.

Нехай центр мас розташований на відстані `l_r` попереду задньої осі та на відстані `l_f` позаду передньої осі (`L = l_f + l_r`).

Вектор абсолютної швидкості центру мас утворює з віссю `X` світової системи координат сумарний кут `θ + β`. Відповідно, диференціальні рівняння руху набувають вигляду:

```
ẋ = v · cos(θ + β)
ẏ = v · sin(θ + β)
θ̇ = (v / L) · tan(δ) · cos(β)
```

де кут зсуву `β` обчислюється як:

```
β = arctan((l_r / (l_f + l_r)) · tan(δ))
```

Кутову швидкість `θ̇` можна також записати через `sin(β)`:

```
θ̇ = (v / l_r) · sin(β)
```

Цей вираз показує: щойно переднє колесо повертається на кут `δ`, у центрі мас миттєво виникає кут зсуву `β`, і робот починає одночасно зміщуватись убік та обертатися за курсом.

### 3. Центр передньої осі

Якщо точка спостереження обрана на передньому керованому колесі (що використовується в алгоритмі керування Стенлі — *Stanley Controller*), вектор швидкості `v_f` спрямований під кутом `δ` до поздовжньої осі кузова (тобто під кутом `θ + δ` до світової осі `X`):

```
ẋ_f = v_f · cos(θ + δ)
ẏ_f = v_f · sin(θ + δ)
θ̇   = (v_f / L) · sin(δ)
```

Швидкість переднього колеса пов'язана зі швидкістю заднього колеса як `v_f = v_r / cos(δ)`.

| Опорна точка | Зсув швидкості відносно корпусу | Поступальний рух (ẋ, ẏ) | Швидкість курсу θ̇ | Типове застосування |
| :--- | :--- | :--- | :--- | :--- |
| **Задня вісь** | `0` | `v_r · cos(θ)`, `v_r · sin(θ)` | `(v_r / L) · tan(δ)` | Pure Pursuit, базова одометрія |
| **Центр мас** | `β = arctan((l_r/L)·tan δ)` | `v · cos(θ + β)`, `v · sin(θ + β)` | `(v / L) · tan(δ) · cos(β)` | Фільтри EKF, злиття IMU/GNSS, MPC |
| **Передня вісь** | `δ` | `v_f · cos(θ + δ)`, `v_f · sin(θ + δ)` | `(v_f / L) · sin(δ)` | Stanley Controller |

## Інверсна кінематика та розрахунок керування для планувальника

У задачах слідування за криволінійним шляхом (планування за сплайнами чи лініями Дубінса) планувальник верхнього рівня видає бажану кривину траєкторії `κ(s)` та лінійну швидкість `v(s)` у кожній точці шляху.

Задача інверсної кінематики полягає в однозначному знаходженні кута керма `δ`, який забезпечить задану кривину:

```
κ = tan(δ) / L
tan(δ) = L · κ
δ = arctan(L · κ)
```

Оскільки реальний кермовий привід має конструктивне обмеження на максимальний кут вивороту `|δ| ≤ δ_max`, із кінематики безпосередньо випливає мінімальний радіус повороту машини:

```
R_min = L / tan(δ_max)
κ_max = tan(δ_max) / L
```

Це обмеження `κ ≤ κ_max` є жорстким геометричним фільтром: будь-який генератор траєкторій (Dubins curves, Reeds-Shepp paths, поліноми Безьє) зобов'язаний будувати криві з кривиною, що не перевищує `κ_max`, інакше робот фізично не зможе вписатися в поворот.

## Порівняння: велосипедна модель проти диференційного приводу

Наземні роботи будуються за двома основними кінематичними схемами: диференційною (двоколісний або гусеничний привід) та автомобільною (велосипедною). Їхні фундаментальні відмінності визначають вибір платформи під конкретні задачі:

1. **Мінімальний радіус повороту:**
   - *Диференційне кермо:* `R_min = 0`. Апарат може обертатися навколо свого геометричного центру на місці шляхом обертання бортів у протилежні боки.
   - *Велосипедна модель:* `R_min > 0`. Апарат не може обертатися на місці; для розвороту на 180 градусів у вузькому коридорі потрібен багатоточковий маневр (триточковий розворот уперед-назад).
2. **Енергоефективність і знос на швидкості:**
   - *Диференційне кермо:* при збільшенні швидкості розворот вимагає значного поперечного проковзування шин (skid steering), що призводить до високих втрат енергії, зносу гуми та непередбачуваності через нерівності ґрунту.
   - *Велосипедна модель:* колеса котяться чисто по своїх дугах без бокового тертя, забезпечуючи високий ККД та стабільність на швидкостях понад 20–50 км/год.
3. **Кількість моторів і сервоприводів:**
   - *Диференційне кермо:* 2 тягові двигуни (по одному на борт), кермові сервоприводи відсутні.
   - *Велосипедна модель:* 1 тяговий двигун (через диференціал або задній привід) + 1 високоточний сервопривід керма.

## Сингулярності, реверс та особливості динаміки розімкненого контуру

Під час аналізу кінематичних рівнянь необхідно виділити три особливі режими роботи:

1. **Граничний кут вивороту (`δ → ±90°`):**
   При `δ = ±π/2` тангенс прямує до нескінченності, а радіус задньої осі `R_r → 0`. У цьому теоретичному стані МЦО падає безпосередньо в центр задньої осі: заднє колесо зупиняється на місці, а переднє колесо описує коло радіуса `L` навколо нього. У реальних автомобілях кут обмежений упорами рейки на рівні `δ_max ≈ 30°...45°`.
2. **Нульова швидкість (`v = 0`):**
   При повній зупинці всі похідні координат `(ẋ, ẏ, θ̇)` стають рівними нулю незалежно від положення керма `δ`. Поворот керма на місці не змінює орієнтації кузова в кінематичній моделі (на відміну від диференційного приводу, здатного крутитися на місці).
3. **Рух заднім ходом (`v < 0`):**
   Коли знак швидкості стає від'ємним (`v < 0`), рівняння кінематики залишаються формально незмінними, але поведінка системи кардинально трансформується. При русі вперед некерована задня вісь стабілізує траєкторію (візок слідує за тягачем). При русі назад задня вісь штовхає передню: навіть мінімальне початкове відхилення курсу викликає прогресуюче закручування кузова (ефект «складання ножиць»). Розімкнений контур руху заднім ходом є асимптотично нестійким і вимагає постійної активної корекції кермом зі зворотним знаком зв'язку.

## Динаміка похибок відстеження траєкторії (Tracking Error Dynamics)

Для побудови зворотного зв'язку в автопілоті розглянемо відхилення робота від заданої опорної траєкторії. Нехай найближча точка на траєкторії має кривину `κ_ref`, а стан робота описується двома похибками:
- `e_y` — поперечна відстань від опорної точки на шляху до задньої осі робота (помилка зсуву);
- `e_ψ = θ − θ_ref` — кутова помилка курсу відносно дотичної до траєкторії.

Диференціюючи похибки за часом, отримуємо нелінійні рівняння динаміки похибок:

```
ė_y = v · sin(e_ψ)
ė_ψ = θ̇ − θ̇_ref = (v / L) · tan(δ) − v · κ_ref
```

При малих кутових помилках (`sin(e_ψ) ≈ e_ψ` та `tan(δ) ≈ δ`) система лінеаризується:

```
ė_y = v · e_ψ
ė_ψ = (v / L) · δ − v · κ_ref
```

Це дозволяє синтезувати лінійний пропорційно-диференціальний (PD) або лінійно-квадратичний (LQR) регулятор:

```
δ_cmd = L · κ_ref − k_p · e_y − k_d · e_ψ
```

де перший доданок `L · κ_ref` — це пряме керування за кривиною (англ. *feedforward*), а доданки `- k_p · e_y - k_d · e_ψ` — коригуючий зворотний зв'язок (англ. *feedback*).

## Межі застосовності: перехід від кінематики до динаміки

Головне допущення кінематичної моделі велосипеда — **ідеальне кочення коліс без бічного ковзання**. Це означає, що кут між площиною обертання колеса та вектором його фактичного руху (кут ковзання шини, англ. *tire slip angle* `α`) вважається рівним нулю.

У реальному світі, коли машина рухається по колу радіуса `R` зі швидкістю `v`, на неї діє доцентрове прискорення:

```
a_y = v² / R = (v² / L) · tan(δ)
```

Щоб утримати кузов на цій траєкторії, шини повинні створити поперечну силу зчеплення `F_y = m · a_y`. Ця сила виникає внаслідок пружної деформації гумового протектора в плямі контакту з дорогою. При цьому колесо починає рухатися під невеликим кутом ковзання `α` до площини диска:

```
F_y = C_α · α
```

де `C_α` — кутова жорсткість шини (англ. *cornering stiffness*).

Поки доцентрове прискорення мале (`a_y < 0.3 · g`, або приблизно `a_y < 3 м/с²`), кути деформації шин не перевищують 1–2 градусів. У цьому режимі кінематична модель забезпечує високу точність відтворення траєкторії за мінімальної обчислювальної складності.

Коли ж швидкість зростає або маневр стає занадто різким (`a_y > 0.4 · g`), деформація шин стає домінуючим фактором:
- виникає недостатня або надлишкова повертаність (англ. *understeer / oversteer*);
- реальний радіус повороту стає значно більшим за чисто геометричний `R = L / tan(δ)`;
- кінематична модель починає сильно занижувати бічне зміщення робота.

За таких умов необхідно переходити до **динамічної моделі велосипеда** (англ. *dynamic bicycle model*), яка включає масу кузова `m`, момент інерції навколо вертикальної осі `I_z` та нелінійні моделі тертя шин (наприклад, магічну формулу Пасейки, англ. *Pacejka Magic Formula*).

> 🔧 **Навіщо це.** Кінематична модель — основна робоча конячка автопілотів міських роботів, логістичних візків, тракторів та автомобілів на швидкостях до 30–50 км/год. Вона використовується в стеках навігації ROS 2 (Nav2), Autoware, Baidu Apollo та в прошивках ArduPilot Rover і PX4. Розуміння меж її застосовності рятує розробника від фатальної помилки: намагатися керувати швидкісним безпілотником на трасі чистою кінематикою.

## Чисельне інтегрування та одометрія на борту

На борту польотного контролера чи мікрокомп'ютера рівняння руху функціонують у дискретному часі з фіксованим тактом `dt` (зазвичай від 10 до 50 мілісекунд).

Нехай на кроці `k` відомі виміряна швидкість `v_k` та кут керма `δ_k`. Необхідно оновити вектор оцінки позиції `(x_{k+1}, y_{k+1}, θ_{k+1})`.

![Порівняння схем чисельного інтегрування кінематики](/root/sys/sys-dron/bicycle-kinematic-model/img/integration-comparison.svg)
*Порівняння методів чисельного інтегрування кінематики. При значному кроці часу dt метод Ейлера накопичує систематичну лінійну похибку, дрейфуючи назовні повороту. Інтегрування круговою дугою та метод Рунге-Кутти (RK4) точно слідують кривині траєкторії.*

Для дискретного інтегрування застосовують три основні методи:

### 1. Метод прямого Ейлера (Forward Euler)
Найпростіший підхід, що апроксимує рух дотичним відрізком:

```
θ_{k+1} = θ_k + (v_k / L) · tan(δ_k) · dt
x_{k+1} = x_k + v_k · cos(θ_k) · dt
y_{k+1} = y_k + v_k · sin(θ_k) · dt
```

Похибка методу має порядок `O(dt)`. На поворотах такий інтегратор завжди «вистрілює» назовні істинної дуги, оскільки вважає курс постійним протягом усього інтервалу `dt`.

### 2. Метод точної кругової дуги (Exact Arc Integration)
Якщо припустити, що протягом інтервалу `dt` швидкість `v` та кут `δ` залишаються незмінними, апарат рухається по ідеальній дузі кола радіуса `R = v / ω` зі зміною курсу `Δθ = ω · dt`. Інтегруючи диференціали явно, отримуємо:

```
Δx = (v / ω) · (sin(θ + Δθ) − sin(θ))
Δy = (v / ω) · (cos(θ) − cos(θ + Δθ))
```

Ця схема дає нульову методичну похибку за постійних керуючих впливів і є стандартом для обчислення одометрії за енкодерами коліс.

### 3. Метод Рунге-Кутти 4-го порядку (RK4)
Застосовується в симуляторах та предикторах траєкторій, де кут керма та прискорення змінюються плавно з обмеженими похідними `δ̇` та `a`. Похибка зменшується до `O(dt⁴)`.

Повний вихідний код модуля інтегратора та симулятора траєкторій із реалізацією всіх трьох методів подано у вставці [Кінематичний симулятор та інтегратор позиції на C та C++](root:sys-dron/bicycle-kinematic-model/proj-bicycle-simulator.md).

## Керування кінематичною моделлю: такт інтегратора на C та C++

Нижче наведено практичний код одного такту інтегратора кінематичної моделі велосипеда для центру мас робота з автоматичним вибором методу інтегрування та обмеженням діапазону керма.

```c
#include <math.h>

/* Геометрія платформи */
typedef struct {
    double L;   /* Повна колісна база, м */
    double lr;  /* Відстань від задньої осі до CoM, м */
} ChassisGeometry;

/* Стан робота на площині */
typedef struct {
    double x;     /* Позиція X, м */
    double y;     /* Позиція Y, м */
    double theta; /* Курс, рад */
} Pose2D;

/* Один такт інтегрування позиції методом точної дуги */
void bicycle_integrate_step(
    Pose2D *pose,
    double v,
    double delta,
    double dt,
    const ChassisGeometry *geom)
{
    /* 1. Розрахунок кута зсуву швидкості beta */
    double beta = atan((geom->lr / geom->L) * tan(delta));

    /* 2. Розрахунок кутової швидкості обертання omega */
    double omega = (v / geom->L) * tan(delta) * cos(beta);
    double dtheta = omega * dt;

    /* 3. Оновлення координат залежно від наявності кривини */
    if (fabs(omega) > 1e-5) {
        double R = v / omega;
        double heading_start = pose->theta + beta;
        double heading_end = heading_start + dtheta;

        pose->x += R * (sin(heading_end) - sin(heading_start));
        pose->y += R * (cos(heading_start) - cos(heading_end));
    } else {
        /* Рух по прямій */
        double heading = pose->theta + beta;
        pose->x += v * cos(heading) * dt;
        pose->y += v * sin(heading) * dt;
    }

    pose->theta += dtheta;

    /* Нормалізація кута до діапазону [-pi, pi] */
    while (pose->theta > M_PI)  pose->theta -= 2.0 * M_PI;
    while (pose->theta < -M_PI) pose->theta += 2.0 * M_PI;
}
```
```cpp
#include <cmath>
#include <numbers>

namespace kinematics {

struct ChassisGeometry {
    double wheelbase{2.5}; // Повна колісна база L, м
    double rear_to_cg{1.2}; // Відстань від задньої осі до центру мас, м
};

struct Pose2D {
    double x{0.0};
    double y{0.0};
    double theta{0.0};
};

class KinematicIntegrator {
public:
    explicit constexpr KinematicIntegrator(ChassisGeometry geom) noexcept
        : geom_{geom} {}

    void step(Pose2D& pose, double v, double delta, double dt) const noexcept {
        const double beta = std::atan((geom_.rear_to_cg / geom_.wheelbase) * std::tan(delta));
        const double omega = (v / geom_.wheelbase) * std::tan(delta) * std::cos(beta);
        const double dtheta = omega * dt;

        if (std::abs(omega) > 1e-5) {
            const double R = v / omega;
            const double heading_start = pose.theta + beta;
            const double heading_end = heading_start + dtheta;

            pose.x += R * (std::sin(heading_end) - std::sin(heading_start));
            pose.y += R * (std::cos(heading_start) - std::cos(heading_end));
        } else {
            const double heading = pose.theta + beta;
            pose.x += v * std::cos(heading) * dt;
            pose.y += v * std::sin(heading) * dt;
        }

        pose.theta = normalize_angle(pose.theta + dtheta);
    }

private:
    ChassisGeometry geom_;

    [[nodiscard]] static double normalize_angle(double angle) noexcept {
        while (angle > std::numbers::pi)  angle -= 2.0 * std::numbers::pi;
        while (angle < -std::numbers::pi) angle += 2.0 * std::numbers::pi;
        return angle;
    }
};

} // namespace kinematics
```
