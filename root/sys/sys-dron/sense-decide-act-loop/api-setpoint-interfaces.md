# 📋 Специфікація інтерфейсів сетпоінтів Offboard

Інтерфейс зовнішнього керування (Offboard) визначає двійковий протокольний контракт між високорівневим бортовим комп'ютером (Companion Computer) та польотним контролером (Flight Controller Unit, FCU). Стек автопілота підтримує два основних стандарти взаємодії: телеметрійний протокол MAVLink v2 для передачі команд через послідовні інтерфейси UART або мережеві UDP/IP сокети, та протокол Micro-XRCE-DDS (uORB) для прямої публікації повідомлень у вузли ROS 2 без проміжної серіалізації.

## 1. MAVLink Повідомлення #84: SET_POSITION_TARGET_LOCAL_NED

Повідомлення `SET_POSITION_TARGET_LOCAL_NED` є основним універсальним засобом передачі просторових завдань у тривимірній системі координат. Воно підтримує одночасне або роздільне керування просторовим положенням, лінійною швидкістю, вектором прискорення, а також кутом курсу (yaw) та швидкістю його зміни (yaw rate).

Коли бортовий комп'ютер формує просторову траєкторію, він пакує миттєві координати цільової точки разом із похідними (швидкістю та прискоренням). Якщо передаються лише координати, внутрішній контур швидкості FCU змушений обчислювати похідну чисельно, що при частоті 20–50 Гц породжує східчасті стрибки похибки. Передача векторів швидкості та прискорення дозволяє автопілоту використовувати прямий зв'язок Feed-Forward, згладжуючи рух апарата між окремими пакетами.

### Бітова маска type_mask для конфігурації контурів

Поле `type_mask` використовує інвертовану логіку (маска ігнорування): встановлення біта в значення `1` наказує каскадному регулятору автопілота **ігнорувати** відповідне поле пакету, тоді як значення `0` активує відповідний контур стеження.

| Біт | Шістнадцяткове значення | Символічна назва | Функціональне призначення |
| :--- | :--- | :--- | :--- |
| `0` | `0x0001` | `POSITION_IGNORE_X` | Ігнорувати цільову координату `x` |
| `1` | `0x0002` | `POSITION_IGNORE_Y` | Ігнорувати цільову координату `y` |
| `2` | `0x0004` | `POSITION_IGNORE_Z` | Ігнорувати цільову координату `z` |
| `3` | `0x0008` | `VELOCITY_IGNORE_VX` | Ігнорувати лінійну швидкість `vx` |
| `4` | `0x0010` | `VELOCITY_IGNORE_VY` | Ігнорувати лінійну швидкість `vy` |
| `5` | `0x0020` | `VELOCITY_IGNORE_VZ` | Ігнорувати лінійну швидкість `vz` |
| `6` | `0x0040` | `ACCEL_IGNORE_AFX` | Ігнорувати лінійне прискорення `afx` |
| `7` | `0x0080` | `ACCEL_IGNORE_AFY` | Ігнорувати лінійне прискорення `afy` |
| `8` | `0x0100` | `ACCEL_IGNORE_AFZ` | Ігнорувати лінійне прискорення `afz` |
| `9` | `0x0200` | `FORCE_SETPOINT` | Трактувати поля `afx, afy, afz` як сили у Ньютонах |
| `10` | `0x0400` | `YAW_IGNORE` | Ігнорувати цільовий кут курсу `yaw` |
| `11` | `0x0800` | `YAW_RATE_IGNORE` | Ігнорувати швидкість курсу `yaw_rate` |

#### Стандартні конфігурації бітових масок:
- **Керування виключно позицією та абсолютним курсом (Position + Yaw)**:
  `type_mask = 0b0000_1011_1111_1000 = 0x0BF8`. Автопілот самостійно генерує внутрішній профіль швидкості для досягнення заданої просторової точки.
- **Керування вектором швидкості та швидкістю рискання (Velocity + Yaw Rate)**:
  `type_mask = 0b0000_0111_1100_0111 = 0x07C7`. Цей режим є основним для алгоритмів візуального переслідування рухомих цілей та реактивного обльоту динамічних перешкод за даними глибинних камер.
- **Повний комбінований режим прямого зв'язку Feed-Forward (Pos + Vel + Accel + Yaw)**:
  `type_mask = 0b0000_1000_0000_0000 = 0x0800`. Передаються всі складові траєкторії. Контур позиції використовує швидкість та прискорення як випереджальне керування, усуваючи фазове запізнення регулятора та забезпечуючи максимальну точність руху вздовж криволінійних сплайнів.

### Підтримувані системи координат (coordinate_frame)

Вибір системи координат визначає, як польотний контролер інтерпретує числа у полях позиції та швидкості:

1. `MAV_FRAME_LOCAL_NED` (значення 1): локальна система координат з фіксованим початком відліку в точці ініціалізації навігаційного фільтра EKF2 (вісь X спрямована на північ, Y — на схід, Z — вертикально вниз). Це стандартна система для глобальної автономної навігації.
2. `MAV_FRAME_LOCAL_OFFSET_NED` (значення 7): локальна система координат зі зміщенням відносно поточної позиції апарата. Координати трактуються як дельта від поточного положення, зафіксованого в момент прийому пакета.
3. `MAV_FRAME_BODY_NED` (значення 8): тілофіксована система координат (вісь X спрямована за носом апарата, Y — вздовж правого крила, Z — перпендикулярно днищу вниз). Команда швидкості `vx = 3.0` у цьому фреймі спрямовує апарат уперед за вектором носа незалежно від його компасного курсу.
4. `MAV_FRAME_BODY_OFFSET_NED` (значення 9): відносні просторові кроки у тілофіксованій системі координат.

## 2. MAVLink Повідомлення #82: SET_ATTITUDE_TARGET

Повідомлення `SET_ATTITUDE_TARGET` застосовується в задачах високодинамічного маневрування (наприклад, аеробатика або швидкісне проходження траси за моделлю Time-Optimal Trajectory), де бортовий комп'ютер бере на себе повний розрахунок кутової динаміки та транслює на автопілот безпосередній кватерніон просторової орієнтації або цільові кутові швидкості разом із колективною тягою.

У цьому режимі вимикаються контури регулювання просторового положення та лінійної швидкості польотного контролера. Автопілот виконує виключно стабілізацію кутового положення (через контур орієнтації на частоті 250–500 Гц) або безпосереднє відпрацювання кутових швидкостей (через контур кутових швидкостей на частоті 400–1000 Гц).

### Двійкова структура корисного навантаження (39 байтів)

| Зсув (байти) | Поле | Тип | Одиниці | Опис |
| :--- | :--- | :--- | :--- | :--- |
| `0..3` | `time_boot_ms` | `uint32_t` | мс | Час від старту автопілота |
| `4..19` | `q` | `float[4]` | одиничний кватерніон | Цільова просторова орієнтація `[w, x, y, z]` у системі NED |
| `20..23` | `body_roll_rate` | `float` | рад/с | Цільова кутова швидкість крену у зв'язаній системі |
| `24..27` | `body_pitch_rate`| `float` | рад/с | Цільова кутова швидкість тангажу у зв'язаній системі |
| `28..31` | `body_yaw_rate`  | `float` | рад/с | Цільова кутова швидкість рискання у зв'язаній системі |
| `32..35` | `thrust` | `float` | `[0.0, 1.0]` | Нормована колективна тяга пропелерів |
| `36` | `target_system` | `uint8_t` | ID | Системний ідентифікатор автопілота |
| `37` | `target_component` | `uint8_t` | ID | Компонентний ідентифікатор автопілота |
| `38` | `type_mask` | `uint8_t` | бітова маска | Маска вибору між кватерніоном та кутовими швидкостями |

### Бітова маска type_mask для SET_ATTITUDE_TARGET

| Біт | Значення | Призначення |
| :--- | :--- | :--- |
| `0` | `0x01` | Ігнорувати кутову швидкість крену `body_roll_rate` |
| `1` | `0x02` | Ігнорувати кутову швидкість тангажу `body_pitch_rate` |
| `2` | `0x04` | Ігнорувати кутову швидкість рискання `body_yaw_rate` |
| `6` | `0x40` | Ігнорувати нормалізовану тягу `thrust` |
| `7` | `0x80` | Ігнорувати кватерніон орієнтації `q` |

> **Вимога до кватерніона:** Кватерніон орієнтації `q` обов'язково повинен бути нормалізованим до одиничної довжини: `w² + x² + y² + z² = 1.0`. Передача ненормалізованого кватерніона або наявність у ньому значень `NaN`/`Inf` призводить до миттєвого відхилення команди внутрішнім фільтром автопілота та аварійного перемикання у стабілізований режим.

## 3. Керуючі команди MAVLink для ініціалізації та переходів режимів

Для активації контуру зовнішнього керування бортовий комп'ютер використовує протокол команд `COMMAND_LONG` (#76) або `COMMAND_INT` (#75). Відправка команд супроводжується обов'язковим очікуванням пакета підтвердження `COMMAND_ACK` (#77).

### Команда MAV_CMD_DO_SET_MODE (#176)

Використовується для переведення автопілота в режим `OFFBOARD` після встановлення попереднього стабільного потоку сетпоінтів.

| Параметр | Значення для PX4 | Опис |
| :--- | :--- | :--- |
| `param1` | `MAV_MODE_FLAG_CUSTOM_MODE_ENABLED` (значення 1) | Прапорець активації спеціального режиму виробника |
| `param2` | `PX4_CUSTOM_MAIN_MODE_OFFBOARD` (значення 6) | Головний кастомний режим автопілота PX4 (Offboard) |
| `param3` | `0` | Додатковий підрежим (Sub-mode, зарезервовано) |
| `param4..7`| `0.0` | Не використовуються (заповнюються нулями) |

### Коди результатів підтвердження COMMAND_ACK

Автопілот відповідає на команду `COMMAND_LONG` пакетом `COMMAND_ACK`, що містить поле `result`:
- `MAV_RESULT_ACCEPTED` (0): команду прийнято, режим Offboard успішно активовано.
- `MAV_RESULT_TEMPORARILY_REJECTED` (1): тимчасова відмова. Виникає, якщо бортовий комп'ютер надіслав команду переходу до того, як автопілот отримав достатню кількість сетпоінтів (менше ніж 500 мс активного потоку).
- `MAV_RESULT_DENIED` (2): відмова. Автопілот не має валідної оцінки локальної позиції від фільтра EKF2 (відсутній фікс GNSS, немає оптичного потоку або втрачено VIO-одометрію).
- `MAV_RESULT_UNSUPPORTED` (3): команда не підтримується поточною прошивкою.
- `MAV_RESULT_FAILED` (4): внутрішня помилка виконання команди.

## 4. Синхронізація часу між компаньйоном та автопілотом

Для коректного зіставлення телеметрії, високоточного керування сплайнами та компенсації транспортних затримок годинники бортового комп'ютера та мікроконтролера автопілота повинні бути жорстко синхронізовані. 

У протоколі MAVLink для цього використовується повідомлення `TIMESYNC` (#111). Бортовий комп'ютер періодично (з частотою 1–5 Гц) надсилає пакет `TIMESYNC`, де поле `tc1` містить поточний час компаньйона в наносекундах, а `ts1 = 0`. Автопілот негайно повертає цей пакет, заповнюючи `ts1` власним монотонним часом.

Отримавши відповідь, бортовий комп'ютер обчислює кругову затримку передачі (Round-Trip Time, RTT) та зсув годинників:

```
RTT = (t_recv - t_send)
offset = t_fcu - (t_send + RTT / 2)
```

Отримане значення `offset` згладжується через фільтр ковзного середнього або фільтр Калмана. Усі часові мітки в повідомленнях `SET_POSITION_TARGET_LOCAL_NED` та `trajectory_setpoint` обов'язково переводяться в шкалу часу автопілота перед відправкою у порт.

## 5. Micro-XRCE-DDS / ROS 2 Інтерфейси uORB

У сучасних версіях стека PX4 взаємодія виконується через апаратний міст Micro-XRCE-DDS, який транслює внутрішні uORB-структури ядра RTOS у стандартні топіки ROS 2 без протокольних накладних витрат MAVLink.

### Топік: /fmu/in/offboard_control_mode

Повідомлення `px4_msgs/msg/OffboardControlMode` сигналізує автопілоту, які саме фізичні контури керування активує зовнішній вузол. Якщо це повідомлення перестає публікуватися, автопілот фіксує аварійний таймаут втрати зв'язку.

```
# px4_msgs/msg/OffboardControlMode.msg
uint64 timestamp             # Монотонний системний час у мікросекундах (FCU clock)

bool position                # Активація контуру позиції (Position Loop)
bool velocity                # Активація контуру швидкості (Velocity Loop)
bool acceleration            # Активація контуру прискорення (Acceleration Loop)
bool attitude                # Активація контуру просторової орієнтації
bool body_rate               # Активація контуру кутових швидкостей
bool thrust_and_torque       # Пряма подача вектора тяги та керівних моментів
bool direct_actuator         # Пряме керування вихідними каналами PWM/DShot
```

### Топік: /fmu/in/trajectory_setpoint

Повідомлення `px4_msgs/msg/TrajectorySetpoint` передає параметри траєкторії безпосередньо у внутрішній контур стабілізації траєкторії польотного контролера.

```
# px4_msgs/msg/TrajectorySetpoint.msg
uint64 timestamp             # Час у мікросекундах

float32[3] position          # Координати [x, y, z] у системі NED (метри)
float32[3] velocity          # Лінійні швидкості [vx, vy, vz] у системі NED (м/с)
float32[3] acceleration      # Лінійні прискорення [ax, ay, az] (м/с²)
float32[3] jerk              # Похідна прискорення по часу (м/с³, ривок)

float32 yaw                  # Цільовий кут курсу (радіани, [-π, +π])
float32 yawspeed             # Цільова кутова швидкість обертання по курсу (рад/с)
```

> **Конвенція передачі неактивних полів (NaN Convention):**
> Якщо окрема просторова вісь або фізична величина не контролюється зовнішнім вузлом (наприклад, задається швидкість по осі X і Y, але висота Z фіксується внутрішнім барометричним утриманням), відповідне поле масиву заповнюється значенням `NAN` (`std::numeric_limits<float>::quiet_NaN()`). Регулятор польотного контролера автоматично вимикає обчислення похибки для полів зі значенням `NAN`.

### Топік зворотного зв'язку: /fmu/out/vehicle_local_position

Повідомлення `px4_msgs/msg/VehicleLocalPosition` повертає високочастотну оцінку поточного просторового стану апарата, розраховану фільтром EKF2 на основі комплексування IMU, барометра, оптичного потоку та GNSS/VIO.

```
# px4_msgs/msg/VehicleLocalPosition.msg
uint64 timestamp             # Час оцінки стану (мікросекунди)

bool xy_valid                # Валідність горизонтальної позиції
bool z_valid                 # Валідність вертикальної висоти
bool v_xy_valid              # Валідність горизонтальної швидкості
bool v_z_valid               # Валідність вертикальної швидкості

float32 x                    # Поточна координата X у NED (метри)
float32 y                    # Поточна координата Y у NED (метри)
float32 z                    # Поточна координата Z у NED (метри)

float32 vx                   # Поточна лінійна швидкість Vx (м/с)
float32 vy                   # Поточна лінійна швидкість Vy (м/с)
float32 vz                   # Поточна лінійна швидкість Vz (м/с)

float32 ax                   # Оцінене лінійне прискорення Ax (м/с²)

float32 heading              # Поточний кут курсу (радіани)
float32 ref_lat              # Географічна широта початку локального відліку (градуси)

float32 ref_alt              # Висота точки ініціалізації над WGS-84 (метри)
```
