# 📋 Структура й двійковий інтерфейс HEARTBEAT

Цей довідник містить вичерпний двійковий та програмний опис повідомлення `HEARTBEAT` (числовий ідентифікатор `ID 0`) протоколу MAVLink версій v1.0 та v2.0. Документ призначений для системних програмістів, розробників вбудованого програмного забезпечення польотних контролерів (на базі RTOS NuttX, FreeRTOS або bare-metal архітектур), авторів модулів супутніх комп'ютерів (Companion Computer) та розробників наземних станцій керування (GCS). Тут розібрано точне розташування полів у пам'яті, правила вирівнювання, перерахування кодів платформ і станів, алгоритми обчислення контрольної суми `CRC_EXTRA` та ідіоматичні функції пакування й розпакування мовами C та C++.

---

## Протокольний профіль та двійкові характеристики

Повідомлення `HEARTBEAT` є базовим повідомленням простору `common.xml` і слугує відправною точкою для встановлення каналу зв'язку. Будь-який парсер MAVLink починає валідацію потоку саме з розпізнавання нульового ідентифікатора.

Повний кадр повідомлення на фізичному рівні передачі (UART, SPI, UDP або TCP) має фіксовану довжину, яка залежить від версії протоколу:

* **У протоколі MAVLink v1.0:** Загальний розмір кадру становить рівно 17 байтів. Кадр складається зі стартового маркера `STX = 0xFE` (1 байт), поля довжини корисних даних `LEN = 9` (1 байт), лічильника послідовності `SEQ` (1 байт), системного номера `SYS` (1 байт), номера компонента `COMP` (1 байт), однобайтового типу повідомлення `MSG ID = 0` (1 байт), корисного навантаження (9 байтів) та контрольної суми `CRC` (2 байти).
* **У протоколі MAVLink v2.0:** Загальний розмір базового кадру без криптографічного підпису становить 21 байт. Кадр містить стартовий маркер `STX = 0xFD` (1 байт), поле довжини `LEN = 9` (1 байт), прапорці несумісності `INC FLAGS` (1 байт), прапорці сумісності `CMP FLAGS` (1 байт), лічильник `SEQ` (1 байт), адреси `SYS` (1 байт) та `COMP` (1 байт), трибайтний ідентифікатор повідомлення `MSG ID = 0x000000` (3 байти), корисне навантаження (9 байтів) та контрольну суму `CRC` (2 байти). Якщо увімкнено автентифікацію пакета, наприкінці кадру додається 13-байтовий блок підпису (Signature).

Контрольна сума кадру розраховується за алгоритмом CRC-16-MCRF4XX (поліном `0x1021`, початкове значення `0xFFFF`) з обов'язковим додаванням одного байта константи сумісності `CRC_EXTRA = 50` (`0x32`). Якщо визначення повідомлення в XML-файлі генератора відрізняється хоча б одним полем або типом даних, обчислений байт `CRC_EXTRA` буде іншим, контрольна сума не зійдеться, і приймач автоматично відкине несумісний кадр.

## Бінарна карта зміщень та вирівнювання пам'яті

Корисне навантаження повідомлення `HEARTBEAT` має фіксований розмір **9 байтів**. Усі багатобайтові цілі числа передаються в каналі зв'язку виключно у форматі **Little-Endian** (найменш значущий байт розташований за найменшим зміщенням у буфері).

Генератор коду MAVLink автоматично сортує поля в двійковій структурі за принципом спадання розміру типів: спершу розташовуються 4-байтові поля (`uint32_t`), потім 2-байтові (`uint16_t`), і наприкінці — однобайтові (`uint8_t`, `int8_t`, `char`). Завдяки такому сортуванню досягається природне вирівнювання даних у пам'яті 32-бітних процесорів (ARM Cortex-M4/M7): чотирибайтне число `custom_mode` починається з нульового зміщення, що повністю виключає виникнення апаратних винятків невирівняного доступу (англ. *Alignment Fault*) та не потребує заповнення паразитними байтами (англ. *Padding Bytes*).

Побайтова структура корисних даних у буфері:

* **Зсув 0x00..0x03 (4 байти): `custom_mode` (тип `uint32_t`).** Специфічний для конкретного автопілота бінарний код режиму польоту. Формат інтерпретації повністю визначається полем `autopilot`.
* **Зсув 0x04 (1 байт): `type` (тип `uint8_t`).** Тип транспортного засобу або функціонального вузла з перерахування `MAV_TYPE`.
* **Зсув 0x05 (1 байт): `autopilot` (тип `uint8_t`).** Архітектура польотного контролера та стек прошивки з перерахування `MAV_AUTOPILOT`.
* **Зсув 0x06 (1 байт): `base_mode` (тип `uint8_t`).** Стандартизована бітова маска базових режимів керування та стану безпеки з перерахування `MAV_MODE_FLAG`.
* **Зсув 0x07 (1 байт): `system_status` (тип `uint8_t`).** Фаза життєвого циклу бортової системи з перерахування `MAV_STATE`.
* **Зсув 0x08 (1 байт): `mavlink_version` (тип `uint8_t`).** Версія бібліотеки протоколу (для актуальних генераторів MAVLink значення за замовчуванням дорівнює `3`).

## Детальний опис перерахування типів компонентів (MAV_TYPE)

Поле `type` дозволяє приймальній стороні ідентифікувати фізичні можливості та аеродинамічну модель вузла без запиту додаткових параметрів. Наземна станція використовує цей тип для завантаження відповідних піктограм, розрахунку просторових зон безпеки та валідації надісланих оператором команд.

Коди типів апаратів з перерахування `MAV_TYPE`:

* **`0 — MAV_TYPE_GENERIC`:** Універсальний або невизначений пристрій. Застосовується для тестових стендів або розробницьких плат без специфічної кінематики.
* **`1 — MAV_TYPE_FIXED_WING`:** Літак класичної схеми або «літаюче крило» (Fixed Wing). Має мінімальну швидкість звалювання, не здатний зависати на місці без вітру, керується елеронами, кермом висоти та тягою маршового двигуна.
* **`2 — MAV_TYPE_QUADROTOR`:** Чотирироторний мультикоптер (схеми розташування двигунів X, +, H). Керування здійснюється диференціальною зміною тяги гвинтів.
* **`3 — MAV_TYPE_COAXIAL`:** Мультикоптер або вертоліт зі співвісними гвинтами зустрічного обертання.
* **`4 — MAV_TYPE_HELICOPTER`:** Однороторний вертоліт класичної схеми з автоматом перекосу та хвостовим компенсуючим гвинтом.
* **`5 — MAV_TYPE_ANTENNA_TRACKER`:** Наземна поворотна станція стеження. Обчислює азимут і кут піднесення на безпілотник за його GPS-координатами та орієнтує вузькоспрямовану антену.
* **`6 — MAV_TYPE_GCS`:** Наземна станція керування (комп'ютер або планшет оператора). Наявність цього типу вказує автопілоту на присутність активного командного пульта.
* **`7 — MAV_TYPE_AIRSHIP`:** Керований дирижабль (аеростат із силовими установками).
* **`8 — MAV_TYPE_FREE_BALLOON`:** Некерована повітряна куля або стратосферний зонд.
* **`9 — MAV_TYPE_ROCKET`:** Балістична або геофізична ракета.
* **`10 — MAV_TYPE_GROUND_ROVER`:** Наземний колісний, гусеничний або крокуючий роботизований комплекс.
* **`11 — MAV_TYPE_SURFACE_BOAT`:** Надводний катер, безекіпажний човен або гідрографічний дрон.
* **`12 — MAV_TYPE_SUBMARINE`:** Підводний телекерований або автономний апарат (ROV/AUV).
* **`13 — MAV_TYPE_HEXAROTOR`:** Шестироторний мультикоптер. Забезпечує часткову відмовостійкість при виході з ладу одного двигуна.
* **`14 — MAV_TYPE_OCTOROTOR`:** Восьмироторний мультикоптер важкого класу.
* **`15 — MAV_TYPE_TRICOPTER`:** Трироторний мультикоптер із сервоприводом відхилення хвостового мотора для компенсації реактивного моменту.
* **`16 — MAV_TYPE_FLAPPING_WING`:** Орнітоптер (літальний апарат із махаючими крилами).
* **`17 — MAV_TYPE_KITE`:** Прив'язний кайтовий літальний апарат.
* **`18 — MAV_TYPE_ONBOARD_CONTROLLER`:** Супутній комп'ютер (Companion Computer, наприклад Nvidia Jetson або Raspberry Pi), що виконує завдання комп'ютерного зору, SLAM-навігації чи зв'язку через мобільні мережі 4G/5G.
* **`19 — MAV_TYPE_VTOL_DUALROTOR`:** Апарат вертикального зльоту та посадки з двома поворотними роторами (Tilt-rotor).
* **`20 — MAV_TYPE_VTOL_QUADROTOR`:** Гібридний літак вертикального зльоту (QuadPlane), обладнаний чотирма підйомними моторами для зависання та окремим штовхаючим двигуном для горизонтального польоту.
* **`21 — MAV_TYPE_VTOL_TILTROTOR`:** Конвертоплан із трьома або чотирма поворотними мотогондолами.
* **`26 — MAV_TYPE_GIMBAL`:** Дво- або триосьовий стабілізований безколекторний підвіс оптичної системи.
* **`27 — MAV_TYPE_ADSB`:** Приймач/передавач авіаційного спостереження ADS-B (Automatic Dependent Surveillance-Broadcast).
* **`30 — MAV_TYPE_CAMERA`:** Автономна корисна оптична або тепловізійна камера.
* **`31 — MAV_TYPE_CHARGING_STATION`:** Автоматизована наземна зарядна станція або роботизований ангар базування дронів.

## Детальний опис стеків автопілотів (MAV_AUTOPILOT)

Поле `autopilot` інформує операторську станцію про те, який саме стек керування виконує обчислення на польотному контролері. Це критично, оскільки одна й та сама високорівнева дія (наприклад, перемикання в режим повернення додому) у різних прошивках вимагає надсилання різних числових значень у полі `custom_mode` або відмінних параметрів команди `MAV_CMD_DO_SET_MODE`.

Значення перерахування `MAV_AUTOPILOT`:

* **`0 — MAV_AUTOPILOT_GENERIC`:** Базовий MAVLink-сумісний автопілот. Підтримує виключно стандартизовані команди `MAV_CMD` без розширених діалектів.
* **`3 — MAV_AUTOPILOT_ARDUPILOTMEGA`:** Прошивки сімейства ArduPilot (ArduCopter, ArduPlane, ArduRover, ArduSub, AntennaTracker). Використовують діалект `ardupilotmega.xml`.
* **`4 — MAV_AUTOPILOT_OPENPILOT`:** Прошивки OpenPilot, LibrePilot та Taulabs.
* **`12 — MAV_AUTOPILOT_PX4`:** Прошивка PX4 Autopilot (Pixhawk, PX4 FMU). Використовує власну модульну систему uORB і діалект `common.xml` з розширеннями PX4.
* **`13 — MAV_AUTOPILOT_SMACCMPILOT`:** Формально верифікована система керування SMACCMPilot на базі захищеної мови Ivory/Tower.
* **`14 — MAV_AUTOPILOT_AUTOQUAD`:** Високопродуктивний автономний польотний контролер AutoQuad з динамічною компенсацією нелінійностей регуляторів.

## Бітова маска базових режимів (MAV_MODE_FLAG)

Поле `base_mode` є 8-бітовою бітовою маскою (типу `uint8_t`), де кожен окремий біт сигналізує про ввімкнення або вимкнення певного контуру керування чи стану безпеки.

Призначення кожного біта:

* **Біт 7 (`0x80 — MAV_MODE_FLAG_SAFETY_ARMED`):** Прапорець активації силової частини. Значення `1` свідчить про те, що автопілот пройшов усі передпольотні перевірки (Pre-arm Checks), зняв апаратне блокування виходів ШІМ/DShot і подав напругу на силові ключі регуляторів швидкості ESC. Гвинти можуть почати обертання будь-якої миті. Якщо біт дорівнює `0` (`DISARMED`), виконавча система заблокована, і випадковий рух стіків пульта не викличе запуск моторів.
* **Біт 6 (`0x40 — MAV_MODE_FLAG_MANUAL_INPUT_ENABLED`):** Прапорець ручного пілотування. Вказує, що польотний контролер зчитує вхідні канали від пульта радіокерування RC (SBUS, CRSF, PPM) або джойстика наземної станції та безпосередньо транслює їх у команди виконавчим приводам.
* **Біт 5 (`0x20 — MAV_MODE_FLAG_HIL_ENABLED`):** Прапорець апаратно-програмного моделювання (Hardware-in-the-Loop). Активується під час тестування польотного контролера на лабораторному стенді, коли він підключений до симулятора (AirSim, Gazebo, jMAVSim). Фізичні мотори при цьому вимкнені, а сенсорні дані надходять через мережу.
* **Біт 4 (`0x10 — MAV_MODE_FLAG_STABILIZE_ENABLED`):** Прапорець активної стабілізації. Означає, що в контурі керування задіяні PID-регулятори кутової швидкості та кутів орієнтації (Roll, Pitch, Yaw). Контролер автоматично утримує дрон у горизонтальному положенні при відпусканні стіків керування.
* **Біт 3 (`0x08 — MAV_MODE_FLAG_GUIDED_ENABLED`):** Режим зовнішнього ведення (Guided). Автопілот виконує політ, орієнтуючись на координатні цілі, вектори швидкості або кутові прискорення, які надсилаються в реальному часі через інтерфейсні повідомлення `SET_POSITION_TARGET_LOCAL_NED` чи `SET_ATTITUDE_TARGET` від супутнього комп'ютера або станції GCS.
* **Біт 2 (`0x04 — MAV_MODE_FLAG_AUTO_ENABLED`):** Повністю автономний режим навігації. Контролер керується заздалегідь завантаженою місією з енергонезалежної пам'яті (Flash/EEPROM), самостійно виконуючи зліт, проходження маршрутних точок, фотографування, скидання вантажу та повернення.
* **Біт 1 (`0x02 — MAV_MODE_FLAG_TEST_ENABLED`):** Інженерний або стендовий режим тестування окремих підсистем (перевірка обертання моторів на мінімальних обертах, тестування сервоприводів).
* **Біт 0 (`0x01 — MAV_MODE_FLAG_CUSTOM_MODE_ENABLED`):** Прапорець валідності кастомного режиму. Інформує парсер про те, що поле `custom_mode` заповнено чинними даними і має бути розшифровано за специфікацією відповідного автопілота.

## Детальний опис станів життєвого циклу (MAV_STATE)

Поле `system_status` відображає поточну сходинку кінцевого автомата операційної системи та системи безпеки:

* **`0 — MAV_STATE_UNINIT`:** Неініціалізований стан. Вказує на виконання початкового коду апаратного завантажувача або фазу скидання процесора.
* **`1 — MAV_STATE_BOOT`:** Завантаження операційної системи реального часу, створення системних потоків, ініціалізація шин опитування сенсорів (I2C, SPI, CAN) та конфігурація каналів DMA.
* **`2 — MAV_STATE_CALIBRATING`:** Виконання калібрування сенсорів: вимірювання нульових зміщень гіроскопів, статичного тиску барометра, пошук супутників GPS та очікування сходження фільтра Калмана (EKF). У цьому стані будь-яка команда армінгу відхиляється.
* **`3 — MAV_STATE_STANDBY`:** Режим очікування. Усі сенсори функціонують, фільтр орієнтації стабільний, навігація зафіксована, мотори знеструмлені (`DISARMED`). Система очікує на команду старту.
* **`4 — MAV_STATE_ACTIVE`:** Активний стан. Мотори заармовані (`ARMED`), виконавча система подає робочі струми на обмотки двигунів, апарат виконує зліт або активний політ.
* **`5 — MAV_STATE_CRITICAL`:** Стан критичної відмови. Виникає при втраті супутників під час польоту в режимі позиціювання, просіданні напруги батареї нижче аварійного порогу, перегріві процесора або втраті зв'язку з пультом керування. Система автоматично вмикає аварійні алгоритми повернення або керованого спуску.
* **`6 — MAV_STATE_EMERGENCY`:** Аварійний стан найвищого пріоритету. Вказує на повну втрату просторового контролю, відмову двигуна на мультикоптері, перекидання в повітрі або некероване падіння. Вимагає негайного блокування моторів для мінімізації наслідків удару.
* **`7 — MAV_STATE_POWEROFF`:** Процедура завершення роботи бортового комп'ютера, скидання дискових кешів логування на SD-карту та безпечне знеструмлення.

## Внутрішня структура custom_mode для PX4 та ArduPilot

Поле `custom_mode` займає 4 байти (32 біти), але його внутрішня бітова структура кардинально різниться між провідними стеками керування.

### 1. Формат custom_mode у прошивці PX4

У прошивці PX4 Autopilot 32-бітне число формується об'єднанням головного режиму (`main_mode`) та підрежиму (`sub_mode`):

```
Біти:     [31..24]          [23..16]         [15..8]          [7..0]
Вміст:    Зарезервовано     main_mode        sub_mode         Зарезервовано
```

Для отримання головного режиму виконується бітовий зсув: `main_mode = (custom_mode >> 16) & 0xFF`.

Значення `main_mode` у PX4:
* `1 — MANUAL`: Ручне пілотування без стабілізації.
* `2 — ALTCTL`: Автоматичне утримання висоти за барометром.
* `3 — POSCTL`: Автоматичне утримання горизонтальної позиції та висоти.
* `4 — AUTO`: Автономний режим, де конкретна дія визначається байтом `sub_mode`:
  * `sub_mode = 1`: `AUTO_READY` (очікування старту).
  * `sub_mode = 2`: `AUTO_TAKEOFF` (автоматичний вертикальний зліт).
  * `sub_mode = 3`: `AUTO_LOITER` (зависання над точкою).
  * `sub_mode = 4`: `AUTO_MISSION` (політ за маршрутом).
  * `sub_mode = 5`: `AUTO_RTL` (повернення на точку старту).
  * `sub_mode = 6`: `AUTO_LAND` (автоматична посадка).
  * `sub_mode = 8`: `AUTO_PRECLAND` (прецизійна оптична посадка).
* `5 — ACRO`: Акробатичний політ з прямим контролем кутових швидкостей.
* `6 — OFFBOARD`: Керування за зовнішніми потоковими векторними завданнями від бортового комп'ютера.
* `7 — STABILIZED`: Стабілізація кутів крену й тангажу.

### 2. Формат custom_mode у прошивці ArduPilot (ArduCopter)

В ArduPilot поле `custom_mode` представляє пряме цілочисельне значення перерахування режимів конкретного типу платформи:

* `0 — STABILIZE`: Стабілізація горизонту з прямим керуванням газом.
* `1 — ACRO`: Керування кутовими швидкостями гіроскопа.
* `2 — ALT_HOLD`: Утримання висоти за барометром з ручним керуванням креном/тангажем.
* `3 — AUTO`: Автономний політ за завантаженим маршрутом місії.
* `4 — GUIDED`: Політ у задані координати або слідування за цільовим вектором швидкості.
* `5 — LOITER`: Високоточне утримання позиції за супутниками GPS.
* `6 — RTL`: Автоматичне повернення на точку зльоту (Return to Launch).
* `7 — CIRCLE`: Автоматичний політ по колу заданого радіуса навколо точки.
* `9 — LAND`: Автоматична вертикальна посадка з контрольованою швидкістю зниження.
* `11 — DRIFT`: Напівавтономне пілотування з автоматичним узгодженням повороту по курсу.
* `13 — SPORT`: Спортивний режим зі збільшеними лімітами кутів нахилу.
* `14 — FLIP`: Автоматичне виконання перевороту на 360 градусів.
* `15 — AUTOTUNE`: Автоматичне налаштування коефіцієнтів PID-регуляторів у повітрі.
* `16 — POSHOLD`: Утримання позиції з природним ручним керуванням нахилами.
* `17 — BRAKE`: Екстрене гальмування та перехід у зависання.
* `21 — SMART_RTL`: Повернення назад точно за раніше пройденою траєкторією польоту.

## Особливості поведінки кодеків MAVLink v1 та MAVLink v2

У протоколі MAVLink v2 реалізовано оптимізацію обрізання кінцевих нульових байтів (англ. *Zero-Byte Truncation*): якщо наприкінці корисного навантаження розташовані нульові байти, кодек відкидає їх перед відправкою кадру, відповідно зменшуючи поле довжини `LEN`.

Проте для повідомлення `HEARTBEAT` обрізання кінцевих нулів практично ніколи не застосовується, оскільки останнє поле структури (`mavlink_version`, зсув 8) містить ненульове число `3`. Відповідно, довжина корисних даних `HEARTBEAT` на фізичному рівні передачі завжди становить повні **9 байтів**.

## Програмний інтерфейс пакування та розпакування на C та C++

Нижче наведено зразки кодування та декодування повідомлення `HEARTBEAT` з використанням низькорівневих бітових операцій та сучасних стандартів мов програмування:

```c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

// Бінарна структура корисного навантаження HEARTBEAT
typedef struct __attribute__((__packed__)) {
    uint32_t custom_mode;
    uint8_t  type;
    uint8_t  autopilot;
    uint8_t  base_mode;
    uint8_t  system_status;
    uint8_t  mavlink_version;
} mavlink_heartbeat_payload_t;

// Функція ручної серіалізації в буфер (Little-Endian)
void pack_heartbeat(uint8_t* buffer, uint32_t custom_mode, uint8_t type,
                    uint8_t autopilot, uint8_t base_mode,
                    uint8_t system_status, uint8_t mavlink_version) {
    // 1. Серіалізація custom_mode (uint32_t) у Little-Endian
    buffer[0] = (uint8_t)(custom_mode & 0xFF);
    buffer[1] = (uint8_t)((custom_mode >> 8) & 0xFF);
    buffer[2] = (uint8_t)((custom_mode >> 16) & 0xFF);
    buffer[3] = (uint8_t)((custom_mode >> 24) & 0xFF);

    // 2. Серіалізація однобайтних полів
    buffer[4] = type;
    buffer[5] = autopilot;
    buffer[6] = base_mode;
    buffer[7] = system_status;
    buffer[8] = mavlink_version;
}

// Функція ручної десеріалізації з буфера
void unpack_heartbeat(const uint8_t* buffer, mavlink_heartbeat_payload_t* out) {
    out->custom_mode = (uint32_t)buffer[0] |
                       ((uint32_t)buffer[1] << 8) |
                       ((uint32_t)buffer[2] << 16) |
                       ((uint32_t)buffer[3] << 24);

    out->type            = buffer[4];
    out->autopilot       = buffer[5];
    out->base_mode       = buffer[6];
    out->system_status   = buffer[7];
    out->mavlink_version = buffer[8];
}
```

```cpp
#include <iostream>
#include <cstdint>
#include <span>
#include <optional>
#include <string_view>

namespace mavlink {

struct HeartbeatData {
    uint32_t custom_mode{0};
    uint8_t  type{0};
    uint8_t  autopilot{0};
    uint8_t  base_mode{0};
    uint8_t  system_status{0};
    uint8_t  mavlink_version{3};

    [[nodiscard]] constexpr bool is_armed() const noexcept {
        return (base_mode & 0x80) != 0;
    }

    [[nodiscard]] constexpr bool is_manual_input_enabled() const noexcept {
        return (base_mode & 0x40) != 0;
    }

    [[nodiscard]] constexpr bool is_stabilize_enabled() const noexcept {
        return (base_mode & 0x10) != 0;
    }

    [[nodiscard]] constexpr bool is_guided_enabled() const noexcept {
        return (base_mode & 0x08) != 0;
    }

    [[nodiscard]] constexpr bool is_auto_enabled() const noexcept {
        return (base_mode & 0x04) != 0;
    }

    [[nodiscard]] constexpr bool is_custom_mode_valid() const noexcept {
        return (base_mode & 0x01) != 0;
    }

    [[nodiscard]] static std::optional<HeartbeatData> deserialize(std::span<const uint8_t> buffer) noexcept {
        if (buffer.size() < 9) {
            return std::nullopt;
        }

        HeartbeatData data;
        data.custom_mode = static_cast<uint32_t>(buffer[0]) |
                          (static_cast<uint32_t>(buffer[1]) << 8) |
                          (static_cast<uint32_t>(buffer[2]) << 16) |
                          (static_cast<uint32_t>(buffer[3]) << 24);

        data.type            = buffer[4];
        data.autopilot       = buffer[5];
        data.base_mode       = buffer[6];
        data.system_status   = buffer[7];
        data.mavlink_version = buffer[8];

        return data;
    }

    void serialize_into(std::span<uint8_t, 9> buffer) const noexcept {
        buffer[0] = static_cast<uint8_t>(custom_mode & 0xFF);
        buffer[1] = static_cast<uint8_t>((custom_mode >> 8) & 0xFF);
        buffer[2] = static_cast<uint8_t>((custom_mode >> 16) & 0xFF);
        buffer[3] = static_cast<uint8_t>((custom_mode >> 24) & 0xFF);

        buffer[4] = type;
        buffer[5] = autopilot;
        buffer[6] = base_mode;
        buffer[7] = system_status;
        buffer[8] = mavlink_version;
    }
};

} // namespace mavlink
```
