# 📋 Специфікація мікросервісу Message Interval та груп MAV_DATA_STREAM

Цей документ містить вичерпний інженерний довідник протоколу MAVLink щодо структур даних, числових констант, бінарного форматування кадрів та протокольних послідовностей, призначених для конфігурації частот генерації потоків телеметрії та діагностики стану радіоліній зв'язку.

---

### 1. Архітектура та протокольний життєвий цикл Message Interval Protocol

Сучасний протокол MAVLink v2 стандартизує керування потоками через спеціалізований мікросервіс інтервалів повідомлень (*Message Interval Protocol*). На відміну від монолітного керування групами, цей мікросервіс забезпечує атомарний, точковий контроль періоду генерації кожного окремого типу повідомлення за його числовим 24-бітним ідентифікатором `Message ID`.

Життєвий цикл узгодження частот між наземною станцією керування (GCS) та польотним контролером (Autopilot) складається з послідовності чітко регламентованих фаз:

Перша фаза — **з'ясування можливостей автопілота (Capability Discovery)**. Під час встановлення зв'язку наземна станція запитує інформацію про підтримувані протоколи за допомогою універсальної команди `MAV_CMD_REQUEST_AUTOPILOT_CAPABILITIES`. Польотний контролер відповідає системним повідомленням `AUTOPILOT_VERSION` (#148), де бітовий прапорець `MAV_PROTOCOL_CAPABILITY_MESSAGE_INTERVALS` (біт 7 у 64-бітному масиві `capabilities`) підтверджує апаратну та програмну підтримку точкового мікросервісу. Якщо цей біт встановлено в одиницю, наземна станція повністю блокує відправку застарілих пакетів `REQUEST_DATA_STREAM` і переходить на команди `MAV_CMD_SET_MESSAGE_INTERVAL`.

Друга фаза — **конфігурація індивідуального потоку (Stream Configuration)**. Станція формує команду `MAV_CMD_SET_MESSAGE_INTERVAL` (#511), запаковану в загальний контейнер виконання команд `COMMAND_LONG` (#76) або `COMMAND_INT` (#75). У параметрах команди вказується числовий номер цільового повідомлення та бажаний період у мікросекундах.

Третя фаза — **підтвердження та обробка (Acknowledgment)**. Польотний контролер перевіряє коректність отриманого ідентифікатора, наявність датчика в системі та доступність ресурсів планувальника, після чого повертає пакет `COMMAND_ACK` (#77) із кодом результату `MAV_RESULT`.

Четверта фаза — **верифікація встановленого стану (State Verification)**. За потреби перевірки або синхронізації інтерфейсу станція надсилає діагностичний запит `MAV_CMD_GET_MESSAGE_INTERVAL` (#512) і отримує точне значення поточного інтервалу у звіті `MESSAGE_INTERVAL` (#299).

```
+-------------------------------------------------------------------------------+
|                      MAV_CMD_SET_MESSAGE_INTERVAL (#511)                      |
+-------+-------------------------+---------------------------------------------+
| Номер | Назва поля              | Опис, тип даних та інженерні обмеження      |
+-------+-------------------------+---------------------------------------------+
| param1| Message ID              | Числовий ідентифікатор повідомлення MAVLink |
|       |                         | (діапазон 0 .. 16777215, тип uint32).       |
| param2| Interval (мікросекунди) | Бажаний період між відправками (тип float): |
|       |                         |  > 0 : період у мкс (наприклад, 20000 = 50 Гц)|
|       |                         |    0 : скинути на заводський дефолт прошивки|
|       |                         |   -1 : повністю вимкнути трансляцію (0 Гц)  |
| param3| Зарезервовано           | 0.0 (не використовується у поточному стані) |
| param4| Зарезервовано           | 0.0 (не використовується у поточному стані) |
| param5| Зарезервовано           | 0.0 (не використовується у поточному стані) |
| param6| Зарезервовано           | 0.0 (не використовується у поточному стані) |
| param7| Response Target         | Адресація та маршрутизація вихідного потоку:|
|       |                         |  0 = стандартний вихідний потік (broadcast) |
|       |                         |  1 = надсилати лише запитувачу (targeted)   |
|       |                         |  2 = виділений інтерфейс / апаратний лінк   |
+-------+-------------------------+---------------------------------------------+
```

#### Інженерні особливості обробки параметрів команди #511

Використання мікросекунд замість цілих значень Герців вирішує фундаментальну проблему дискретизації низьких і дробових частот. У класичному форматі Герців неможливо задати частоту 0.5 Гц (один звіт на дві секунди) або 0.2 Гц (один звіт на п'ять секунд), оскільки ціле число `0` означало вимкнення або дефолт. Завдання періоду в мікросекундах знімає це обмеження:
- Період `5000000` мкс відповідає частоті `1 / 5.0 = 0.2` Гц (ідеально для повільних звітів про стан накопичувача пам'яті або температуру платформи).
- Період `1000000` мкс відповідає частоті 1.0 Гц (стандартний пульс зв'язку HEARTBEAT).
- Період `100000` мкс відповідає частоті 10.0 Гц (динаміка польоту та координати GPS).
- Період `20000` мкс відповідає частоті 50.0 Гц (швидкий штучний горизонт для ручного керування).

Поведінка параметра `param2` при спеціальних значеннях строго регламентована специфікацією MAVLink. Якщо передано значення `0.0`, внутрішній планувальник польотного контролера не вимикає генерацію, а відновлює частоту за замовчуванням, закладену в енергонезалежних параметрах автопілота (наприклад, параметрами `SR1_*` в ArduPilot або значеннями за замовчуванням модуля `mavlink_stream` у PX4). Якщо передано значення `-1.0`, обробник черги негайно вилучає дане повідомлення з циклу активного опитування, і його генерація повністю припиняється.

Параметр `param7` визначає логіку маршрутизації потоку. У складних безпілотних комплексах польотний контролер має декілька фізичних каналів зв'язку: порт `TELEM1` для основного радіомодема, порт `TELEM2` для додаткового термінала супутникового зв'язку та USB-порт або Ethernet для бортового комп'ютера компаньйона. Значення `0` транслює повідомлення у стандартний вихідний потік порту. Значення `1` спрямовує згенеровані пакети виключно до того порту, через який надійшла команда `COMMAND_LONG`, що запобігає засміченню інших вузьких каналів небажаним швидким трафіком.

```
+-------------------------------------------------------------------------------+
|                      MAV_CMD_GET_MESSAGE_INTERVAL (#512)                      |
+-------+-------------------------+---------------------------------------------+
| Номер | Назва поля              | Опис та допустимі значення                  |
+-------+-------------------------+---------------------------------------------+
| param1| Message ID              | Числовий ID повідомлення, що запитується    |
| param2| Зарезервовано           | 0.0                                         |
| param3| Зарезервовано           | 0.0                                         |
| param4| Зарезервовано           | 0.0                                         |
| param5| Зарезервовано           | 0.0                                         |
| param6| Зарезервовано           | 0.0                                         |
| param7| Зарезервовано           | 0.0                                         |
+-------+-------------------------+---------------------------------------------+
```

### 2. Повідомлення стану інтервалу MESSAGE_INTERVAL (#299)

Повідомлення `MESSAGE_INTERVAL` є офіційним структурним звітом польотного контролера про поточний період передачі конкретного повідомлення. Воно транслюється у відповідь на запит `MAV_CMD_GET_MESSAGE_INTERVAL` або асинхронно при зміні налаштувань.

```
+-------------------------------------------------------------------------------+
|                    Повідомлення MESSAGE_INTERVAL (ID #299)                    |
+---------+-------------+-----------+-------------------------------------------+
| Зсув (B)| Поле        | Тип даних | Призначення та діапазон значень           |
+---------+-------------+-----------+-------------------------------------------+
| 0..3    | interval_us | int32_t   | Встановлений період передачі в мкс:       |
|         |             |           |   > 0 : період у мкс (наприклад, 100000)  |
|         |             |           |    -1 : трансляцію повідомлення вимкнено  |
|         |             |           |     0 : потік керується внутрішньою чергою|
| 4..5    | message_id  | uint16_t  | Числовий ідентифікатор MAVLink-повідомлення|
+---------+-------------+-----------+-------------------------------------------+
Загальний розмір корисного навантаження (Payload): 6 байтів.
```

Наземна станція використовує значення `interval_us` для відображення реальної частоти телеметрії в інтерфейсі користувача та перевірки того, чи підтвердив автопілот запитану конфігурацію.

Повідомлення `MESSAGE_INTERVAL` упаковується відповідно до стандартного порядку вирівнювання полів MAVLink (від найбільшого типу даних до найменшого): спочатку йде 4-байтне знакове ціле `interval_us` (int32_t), після чого слідує 2-байтне беззнакове ціле `message_id` (uint16_t). Це виключає появу неконтрольованих байтів вирівнювання (*padding bytes*) під час передачі по мережі.

### 3. Результати обробки та коди підтвердження COMMAND_ACK (#77)

Під час отримання команди налаштування частоти польотний контролер перевіряє можливість виділення смуги пропускання та повертає повідомлення `COMMAND_ACK`.

```
+-------+----------------------------------+------------------------------------+
| Код   | Константа переліку MAV_RESULT    | Технічна інтерпретація результату  |
+-------+----------------------------------+------------------------------------+
| 0     | MAV_RESULT_ACCEPTED              | Інтервал успішно змінено у черзі   |
| 1     | MAV_RESULT_TEMPORARILY_REJECTED  | Відхилено через дефіцит пам'яті/MCU|
| 2     | MAV_RESULT_DENIED                | Заборонено поточною конфігурацією  |
| 3     | MAV_RESULT_UNSUPPORTED           | Прошивка не підтримує цей MessageID|
| 4     | MAV_RESULT_FAILED                | Внутрішня помилка диспетчера черг  |
| 5     | MAV_RESULT_IN_PROGRESS           | Команда виконується асинхронно     |
| 6     | MAV_RESULT_CANCELLED             | Скасовано пріоритетнішим процесом  |
+-------+----------------------------------+------------------------------------+
```

Коли контролер відповідає кодом `MAV_RESULT_ACCEPTED`, наземна станція може вважати новий інтервал чинним і очікувати надходження пакетів із заданою періодичністю.

Якщо контролер повертає `MAV_RESULT_TEMPORARILY_REJECTED`, це сигналізує про тимчасове перевантаження черги планувальника завдань (наприклад, під час ініціалізації розширеного фільтра Калмана EKF або калібрування компаса). У цьому випадку станція повторює команду через фіксований таймаут (типово 500–1000 мс).

Відповідь `MAV_RESULT_UNSUPPORTED` означає, що автопілот скомпільовано без модуля підтримки відповідного датчика (наприклад, запитано повідомлення оптичного потоку `OPTICAL_FLOW` на платі, де драйвер камери відсутній у збірці прошивки). Отримавши такий код, станція зобов'язана припинити спроби активації потоку, щоб не навантажувати радіоканал марними запитами.

### 4. Застарілий стандарт MAVLink v1: REQUEST_DATA_STREAM (#66)

У першій версії протоколу керування потоками базувалося на відправці бінарного кадру `REQUEST_DATA_STREAM` (#66). Станція обирала ідентифікатор категорії зі списку `MAV_DATA_STREAM` і передавала бажану частоту у вигляді цілого числа Герців.

```
+-------------------------------------------------------------------------------+
|                   Повідомлення REQUEST_DATA_STREAM (ID #66)                   |
+---------+-------------------+-----------+-------------------------------------+
| Зсув (B)| Поле              | Тип даних | Призначення та діапазон             |
+---------+-------------------+-----------+-------------------------------------+
| 0..1    | req_message_rate  | uint16_t  | Бажана частота відправки в Герцах   |
| 2       | target_system     | uint8_t   | Системний ID апарата (Target SysID) |
| 3       | target_component  | uint8_t   | Компонентний ID (типово 1 для MCU)  |
| 4       | req_stream_id     | uint8_t   | Ідентифікатор групи MAV_DATA_STREAM |
| 5       | start_stop        | uint8_t   | 1 = активувати потік, 0 = вимкнути  |
+---------+-------------------+-----------+-------------------------------------+
Загальний розмір корисного навантаження (Payload): 6 байтів.
```

#### Детальний опис груп переліку `MAV_DATA_STREAM`

Груповий механізм об'єднував повідомлення за функціональними напрямками. Головна проблема полягала в тому, що зміна частоти групи змінювала частоту всіх включених до неї повідомлень одночасно.

+-----+-------------------------------+-----------------------------------------+
| 0   | MAV_DATA_STREAM_ALL           | Усі активовані потоки автопілота        |
| 1   | MAV_DATA_STREAM_RAW_SENSORS   | RAW_IMU (#27), SCALED_IMU2 (#116),      |
|     |                               | SCALED_PRESSURE (#29), SENSOR_OFFSETS   |
| 2   | MAV_DATA_STREAM_EXTENDED_STAT | SYS_STATUS (#1), POWER_STATUS (#125),   |
|     |                               | MEMINFO (#152), GPS_RAW_INT (#24)       |
| 3   | MAV_DATA_STREAM_RC_CHANNELS   | RC_CHANNELS (#65), RC_CHANNELS_RAW (#35)|
|     |                               | SERVO_OUTPUT_RAW (#36)                  |
| 4   | MAV_DATA_STREAM_RAW_CONTROLLER| ATTITUDE_CONTROLLER_OUTPUT (#60),       |
|     |                               | POSITION_CONTROLLER_OUTPUT (#61)        |

Приклад конфлікту в групі `EXTRA1`: повідомлення `ATTITUDE` містить 28 байтів і необхідне для стабілізації штучного горизонту на високій частоті (30–50 Гц). Водночас повідомлення `AHRS` (#163) містить оцінки матриці орієнтації спрямування, а `SIMSTATE` (#164) — стан математичної моделі симулятора. Включення групи `EXTRA1` на 50 Гц змушувало контролер генерувати всі три повідомлення, створюючи сумарний потік понад 4.5 кБ/с, що призводило до миттєвого забивання каналів 57600 бод.

### 5. Діагностика фізичного радіоканалу: RADIO_STATUS (#109)

Повідомлення `RADIO_STATUS` формується безпосередньо апаратними модемами серії SiK Telemetry (чипи Silicon Labs Si1000/Si1060), RFD900 та сумісними бездротовими мостами. Прошивка модема вимірює рівні сигналів і стан внутрішніх буферів та самостійно вставляє пакети `RADIO_STATUS` у потік UART у напрямку автопілота й наземної станції з фіксованою частотою 1–2 Гц.

```
+-------------------------------------------------------------------------------+
|                     Повідомлення RADIO_STATUS (ID #109)                       |
+---------+-----------+-----------+---------------------------------------------+
| Зсув (B)| Поле      | Тип даних | Призначення та інженерна шкала              |
+---------+-----------+-----------+---------------------------------------------+
| 0..1    | rxerrors  | uint16_t  | Кількість пакетів із некоригованими CRC     |
| 2..3    | fixed     | uint16_t  | Кількість пакетів, виправлених кодом Голея  |
| 4       | rssi      | uint8_t   | Рівень сигналу локального приймача (RSSI)   |
|         |           |           | Розрахунок у дБм: P_dBm = (rssi / 1.9) - 127|
| 5       | remrssi   | uint8_t   | Рівень сигналу віддаленого приймача в дБм   |
| 6       | txbuf     | uint8_t   | Заповненість апаратного FIFO передавача (%):|
|         |           |           |   0 = буфер порожній, 100 = повне переповн. |
| 7       | noise     | uint8_t   | Рівень фонового шуму ефіру локально (дБм)   |
| 8       | remnoise  | uint8_t   | Рівень фонового шуму ефіру на стороні БПЛА  |
+---------+-----------+-----------+---------------------------------------------+
Загальний розмір корисного навантаження (Payload): 9 байтів.
```

#### Розрахунок метрик якості радіозв'язку

Значення полів `rssi`, `remrssi`, `noise` та `remnoise` передаються у безрозмірних дискретних одиницях від 0 до 255. Для переводу цих значень у фізичні децибел-мілівати (дБм) застосовується лінійна апроксимаційна формула:
`P_dBm = (raw_value / 1.9) - 127`.

Наприклад:
- Значення `rssi = 133` відповідає рівню потужності: `(133 / 1.9) - 127 = 70 - 127 = -57` дБм (відмінний рівень зв'язку на близькій дистанції).
- Значення `rssi = 70` відповідає рівню потужності: `(70 / 1.9) - 127 = 36.8 - 127 = -90.2` дБм (межа чутливості приймача, початок втрати пакетів).
- Значення `noise = 40` відповідає рівню фонового шуму: `(40 / 1.9) - 127 = 21 - 127 = -106` дБм.

Відношення сигнал/шум (*Signal-to-Noise Ratio, SNR*) визначається як різниця між корисним сигналом та рівнем шуму: `SNR = RSSI_dBm - Noise_dBm`. Якщо запас SNR падає нижче 10–12 дБ, імовірність спотворення окремих байтів зростає експоненційно, що призводить до зростання лічильника `rxerrors`.

Показник `txbuf` відображає відсоток заповненості циклічного вихідного буфера модема. Якщо вхідний потік від контролера становить 4000 байт/с, а пропускна здатність радіоефіру через завади знизилася до 2000 байт/с, значення `txbuf` зростає зі швидкістю 20% на секунду. Досягнення `txbuf = 100%` означає настання апаратного переповнення (Buffer Overflow), під час якого модем скидає всі нові байти, спотворюючи кадри MAVLink.

### 6. Довідкова таблиця ідентифікаторів MAVLink Message ID

У таблиці наведено параметри основних повідомлень, що використовуються для конфігурації потоків у безпілотних авіаційних комплексах:

#### Правила пріоритезації повідомлень у диспетчері черг
1. **Критичний пріоритет (Non-droppable):** Повідомлення `HEARTBEAT` (#0), `COMMAND_ACK` (#77), `RADIO_STATUS` (#109) та відповіді на зміну параметрів `PARAM_VALUE` (#22). Вони ніколи не відкидаються диспетчером черг автопілота й мають найвищий пріоритет у черзі відправки UART.
2. **Високий пріоритет (High Rate Dynamic):** Повідомлення просторової орієнтації `ATTITUDE` (#30) та розширеного стану `VFR_HUD` (#74). Вони транслюються з максимальною частотою за сприятливих умов і троттляться першими під час деградації каналу.
3. **Середній пріоритет (Navigation State):** Повідомлення `GLOBAL_POSITION_INT` (#33), `LOCAL_POSITION_NED` (#32) та `ALTITUDE` (#141). Їхня частота підтримується в межах 5–10 Гц для забезпечення коректної роботи навігаційних алгоритмів наземної станції.
4. **Низький пріоритет (Housekeeping & Sensors):** Повідомлення `SYS_STATUS` (#1), `BATTERY_STATUS` (#147), `RAW_IMU` (#27). Ці пакети передаються з низькою частотою (0.5–2 Гц), а сирі дані сенсорів активуються виключно під час калібрування на землі.
