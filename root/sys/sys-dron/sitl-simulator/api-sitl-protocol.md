# 📋 Протоколи та формати обміну даними симуляції SITL і HITL

Взаємодія між польотним автопілотом і зовнішнім симулятором фізики базується на суворо специфікованих бінарних і текстових мережевих контрактах. Помилка в системі координат, одиницях вимірювання (наприклад, передача градусів замість радіанів) або масштабуванні значень призводить до некоректної оцінки орієнтації [фільтром Калмана EKF](root:com-signal/kalman-ekf) та миттєвої дестабілізації апарата.

Цей довідник містить повні технічні специфікації трьох головних протоколів взаємодії: текстового протоколу ArduPilot JSON/UDP, бінарних пакетів MAVLink HIL (PX4) та інтерфейсу Google Protocol Buffers симулятора Gazebo.

## 1. Текстовий протокол ArduPilot SITL JSON через UDP

Для підключення зовнішніх середовищ моделювання (AirSim, Gazebo, користувацьких моделей на Python, Rust чи C++) в автопілоті ArduPilot передбачено відкритий текстовий протокол на базі формату JSON, що передається через датаграми UDP. Перевагою цього протоколу є його прозорість: розробник може перехоплювати пакети стандартними утилітами налагодження мережі на кшталт `tcpdump` або Wireshark і читати значення телеметрії без додаткових декодерів.

Обмін організовано через пару локальних UDP-портів:
- **Вхідний порт 9002 (Автопілот слухає):** симулятор фізики надсилає повний кадр стану сенсорного комплексу з частотою 200–400 Гц.
- **Вихідний порт 9003 (Автопілот відправляє):** автопілот транслює команди керування актуаторами у форматі JSON у відповідь на кожен отриманий кадр сенсорів.

### Механізм синхронізації та послідовність обміну

Протокол реалізує жорстку покрокову схему Lockstep:
1. Симулятор фізики формує JSON-пакет зі знімком поточного стану світу та міткою часу `timestamp` і відправляє його на порт `9002`.
2. Після відправки симулятор призупиняє інтегрування фізики й переходить у стан блокуючого очікування на сокеті порту `9003`.
3. Автопілот приймає пакет, оновлює свій внутрішній симуляційний час, виконує такт контуру керування (оцінка стану EKF, регулятори стабілізації, мікшер) і формує пакет-відповідь із масивом тривалостей імпульсів ШІМ `pwm`.
4. Автопілот відправляє сформовану відповідь на порт `9003`.
5. Симулятор отримує відповідь, перевіряє контрольну суму `magic`, прикладає тягу до гвинтів і виконує один крок чисельного інтегрування на інтервал `Δt`.

### Формат вхідного пакета сенсорів (Симулятор → ArduPilot)

Симулятор формує JSON-об'єкт із поточним модельним часом, вектором кутових швидкостей, прискорень, координатами та параметрами атмосфери:

```json
{
  "timestamp": 12.45025,
  "imu": {
    "gyro": [0.0012, -0.0008, 0.0031],
    "accel_body": [0.05, -0.12, -9.81]
  },
  "position": [10.5, -4.2, -50.0],
  "velocity": [1.2, 0.4, -0.1],
  "attitude": [0.01, -0.02, 1.57],
  "quaternion": [0.999, 0.005, -0.01, 0.0],
  "baro": {
    "pressure_pa": 100720.5,
    "temperature_c": 21.5
  },
  "rng": [12.4],
  "wind": [2.0, 0.5, 0.0]
}
```

### Детальна специфікація полів JSON-пакета сенсорів

Кожне поле вхідного JSON-пакета має суворо фіксований фізичний зміст та розмірність:

- `timestamp` (`float64`, секунди): монотонний симуляційний час, що відлічується від моменту запуску віртуального світу. Використовується автопілотом як єдине джерело системного часу.
- `imu.gyro` (`float64[3]`, радіани на секунду): тривимірний вектор кутової швидкості обертання твердого тіла `[p, q, r]` у зв'язаній системі координат Body (де вісь X спрямована на ніс апарата, Y — на праве крило, Z — крізь днище вниз).
- `imu.accel_body` (`float64[3]`, метри на секунду в квадраті): вектор питомої сили (уявного прискорення) `[a_x, a_y, a_z]` у системі координат Body. У нерухомому горизонтальному стані на землі сенсор фіксує реакцію опори вгору, тому значення по осі Z дорівнює `-9.80665` м/с².
- `position` (`float64[3]`, метри): вектор положення літального апарата в навігаційній системі відліку NED `[North, East, Down]` відносно вихідної точки старту (Home Position).
- `velocity` (`float64[3]`, метри на секунду): вектор лінійної швидкості польоту в системі координат NED `[v_x, v_y, v_z]`.
- `attitude` (`float64[3]`, радіани): кути орієнтації Ейлера `[roll, pitch, yaw]`, розраховані в послідовності авіаційних поворотів Z-Y-X.
- `quaternion` (`float64[4]`, безрозмірний): нормований кватерніон орієнтації `[q_w, q_x, q_y, q_z]`, що задає поворот із системи координат Body у систему NED.
- `baro.pressure_pa` (`float64`, Паскалі): статичний абсолютний тиск повітря на поточній барометричній висоті польоту.
- `baro.temperature_c` (`float64`, градуси Цельсія): температура повітря в зоні розташування барометричного датчика.
- `rng` (`float64[N]`, метри): масив вимірів лазерного оптичного далекоміра (лідара) або сонара, спрямованого вертикально вниз.
- `wind` (`float64[3]`, метри на секунду): вектор швидкості вітру в системі координат NED, що використовується для обчислення повітряної швидкості.

### Формат вихідного пакета актуаторів (ArduPilot → Симулятор)

Автопілот у відповідь на кожен отриманий кадр сенсорів формує JSON-пакет зі значеннями вихідних сигналів мікшера:

```json
{
  "timestamp": 12.45025,
  "magic": 18458,
  "pwm": [1520, 1480, 1500, 1500, 1000, 1000, 1000, 1000]
}
```

- `magic`: цілочисельний маркер валідності `0x481A` (`18458` у десятковому записі). Якщо симулятор отримує пакет із невірним значенням `magic`, кадр ігнорується як пошкоджений.
- `pwm`: масив цілих чисел довжиною від 8 до 16 елементів, що задають шпаруватість сигналу керування ШІМ у мікросекундах. Значення 1000 мкс відповідає нульовій тязі двигуна, 1500 мкс — нейтральному положенню сервопривода, 2000 мкс — максимальній 100% потужності.

## 2. Бінарний протокол MAVLink HIL (PX4 та ArduPilot)

Для високоефективного обміну в режимі реального часу та стендів апаратного моделювання (HITL) застосовується бінарний протокол [MAVLink](root:sys-dron/mavlink-packet). Бінарні повідомлення мінімізують накладні витрати на серіалізацію, мають жорсткий контроль цілісності CRC-16-MCRF4XX та гарантують точне збереження розрядності чисел із рухомою комою IEEE 754.

### Структура кадру `HIL_SENSOR` (Message ID #107)

Повідомлення `HIL_SENSOR` містить повний комплекс показників інерційних сенсорів, барометра та магнітометра в одному компактному 64-байтовому бінарному пакеті.

:::tabs
```cpp
#include <cstdint>
#include <array>

// Оголошення структури кадру HIL_SENSOR у стилі сучасного C++
struct alignas(8) HilSensorMessage {
    uint64_t time_usec{0};           // Монотонний час симуляції у мікросекундах
    float xacc{0.0f};                // Акселерометр X (м/с²) у Body Frame
    float yacc{0.0f};                // Акселерометр Y (м/с²) у Body Frame
    float zacc{0.0f};                // Акселерометр Z (м/с²) у Body Frame
    float xgyro{0.0f};               // Гіроскоп X (рад/с) навколо осі Roll
    float ygyro{0.0f};               // Гіроскоп Y (рад/с) навколо осі Pitch
    float zgyro{0.0f};               // Гіроскоп Z (рад/с) навколо осі Yaw
    float xmag{0.0f};                // Магнітометр X (Гаус)
    float ymag{0.0f};                // Магнітометр Y (Гаус)
    float zmag{0.0f};                // Магнітометр Z (Гаус)
    float abs_pressure{0.0f};        // Абсолютний тиск (гПа / мілібари)
    float diff_pressure{0.0f};       // Диференційний тиск трубки Піто (гПа)
    float pressure_alt{0.0f};        // Розрахована барометрична висота (метри)
    float temperature{0.0f};         // Температура сенсорного модуля (°C)
    uint32_t fields_updated{0};      // Бітова маска оновлених сенсорів
    uint8_t id{0};                   // Ідентифікатор комплексу сенсорів
};
```
```c
#include <stdint.h>

/* Оголошення структури кадру HIL_SENSOR мовою C */
typedef struct __mavlink_hil_sensor_t {
    uint64_t time_usec;        /* Монотонний час симуляції у мікросекундах */
    float xacc;                /* Акселерометр X (м/с²) у Body Frame */
    float yacc;                /* Акселерометр Y (м/с²) у Body Frame */
    float zacc;                /* Акселерометр Z (м/с²) у Body Frame */
    float xgyro;               /* Гіроскоп X (рад/с) навколо осі Roll */
    float ygyro;               /* Гіроскоп Y (рад/с) навколо осі Pitch */
    float zgyro;               /* Гіроскоп Z (рад/с) навколо осі Yaw */
    float xmag;                /* Магнітометр X (Гаус) */
    float ymag;                /* Магнітометр Y (Гаус) */
    float zmag;                /* Магнітометр Z (Гаус) */
    float abs_pressure;        /* Абсолютний барометричний тиск (гПа / мілібари) */
    float diff_pressure;       /* Диференційний тиск трубки Піто (гПа) */
    float pressure_alt;        /* Розрахована барометрична висота (метри) */
    float temperature;         /* Температура сенсорного модуля (°C) */
    uint32_t fields_updated;   /* Бітова маска оновлених сенсорів у поточному кадрі */
    uint8_t id;                /* Ідентифікатор комплексу сенсорів (0 для основного блоку) */
} mavlink_hil_sensor_t;
```
:::

### Бітова маска оновлення каналів `fields_updated`

Бітова маска дозволяє симулятору передавати сенсорні дані з різною фізичною частотою дискретизації в межах єдиного типу повідомлення:
- `0x0001` (`IMU_ACCEL_X`): містить нове значення лінійного прискорення по осі X;
- `0x0002` (`IMU_ACCEL_Y`): містить нове значення лінійного прискорення по осі Y;
- `0x0004` (`IMU_ACCEL_Z`): містить нове значення лінійного прискорення по осі Z;
- `0x0008` (`IMU_GYRO_X`): містить нову кутову швидкість навколо осі крену Roll;
- `0x0010` (`IMU_GYRO_Y`): містить нову кутову швидкість навколо осі тангажу Pitch;
- `0x0020` (`IMU_GYRO_Z`): містить нову кутову швидкість навколо осі рискання Yaw;
- `0x0040` (`MAG_X`): містить оновлену напруженість магнітного поля по осі X;
- `0x0080` (`MAG_Y`): містить оновлену напруженість магнітного поля по осі Y;
- `0x0100` (`MAG_Z`): містить оновлену напруженість магнітного поля по осі Z;
- `0x0200` (`BARO_ABS`): містить оновлений статичний атмосферний тиск;
- `0x0400` (`BARO_DIFF`): містить показник диференційного тиску датчика повітряної швидкості;
- `0x0800` (`BARO_TEMP`): містить оновлену температуру середовища;
- `0x1FFF` (`ALL_UPDATED`): прапорець комплексного оновлення всіх вимірювальних каналів одночасно.

### Структура кадру `HIL_ACTUATOR_CONTROLS` (Message ID #93)

Автопілот транслює команди керування актуаторами у нормалізованому діапазоні з плаваючою комою:

:::tabs
```cpp
#include <cstdint>
#include <array>

// Оголошення структури актуаторів у стилі сучасного C++
struct alignas(8) HilActuatorControlsMessage {
    uint64_t time_usec{0};           // Часова мітка автопілота (мкс)
    uint64_t flags{0};               // Прапорці конфігурації режиму
    std::array<float, 16> controls{};// Нормалізовані керуючі сигнали
    uint8_t mode{0};                 // Стан озброєння системи (MAV_MODE_FLAG)
};
```
```c
#include <stdint.h>

/* Оголошення структури актуаторів мовою C */
typedef struct __mavlink_hil_actuator_controls_t {
    uint64_t time_usec;        /* Часова мітка автопілота (мкс) */
    uint64_t flags;            /* Прапорці конфігурації режиму симуляції */
    float controls[16];        /* Нормалізовані керуючі сигнали [-1.0 .. +1.0] або [0.0 .. 1.0] */
    uint8_t mode;              /* Поточний стан озброєння системи (MAV_MODE_FLAG) */
} mavlink_hil_actuator_controls_t;
```
:::

Поле `controls` містить до 16 каналів керування. Для мультироторних систем сигнали `controls[0..3]` представляють нормалізовану тягу кожного з чотирьох двигунів у діапазоні `[0.0, 1.0]`. Для літаків класичної схеми канали відображають кути відхилення елеронів, керма висоти, керма напрямку (діапазон `[-1.0, +1.0]`) та тягу маршового двигуна `[0.0, 1.0]`.

## 3. Протокол Gazebo / Ignition Transport (Protobuf)

Симулятори робототехніки нового покоління Gazebo використовують шину Google Protocol Buffers для міжпроцесорного обміну топіками через спільну пам'ять або сокети IPC:

### Топік керування актуаторами `/gazebo/command/motor_speed`

Повідомлення `gz.msgs.Actuators` передає цільові кутові швидкості обертання або нормалізовані значення тяги двигунів:

```protobuf
syntax = "proto3";
package gz.msgs;

message Actuators {
  Header header = 1;
  repeated double position = 2;   // Кутове положення сервоприводів у радіанах
  repeated double velocity = 3;   // Кутова швидкість моторів у радіанах на секунду
  repeated double normalized = 4; // Нормалізована тяга двигунів у діапазоні [0.0, 1.0]
}
```

### Топік синхронізації часу `/world/default/clock`

Повідомлення `gz.msgs.Clock` транслює монотонний час віртуального світу з наносекундною точністю:

```protobuf
syntax = "proto3";
package gz.msgs;

message Clock {
  Header header = 1;
  int64 sim_sec = 2;  // Секунди симуляційного часу
  int32 sim_nsec = 3; // Наносекунди симуляційного часу
}
```

Автопілот підписується на цей топік і виконує дискретні ітерації контуру керування строго у відповідь на оновлення віртуального годинника, що гарантує абсолютну детермінованість [SITL-симуляції](root:sys-dron/sitl-simulator).
