Автономний квадрокоптер масою `1.8 кг` виконує політ між деревами густого лісу зі швидкістю `12 м/с` (`43.2 км/год`). Бортова стереокамера з робочою дистанцією `8 м` та кутом огляду `85°` фіксує раптову появу тонкої сухої гілки товщиною `3 см` безпосередньо за вектором руху. Відстань до зіткнення становить рівно `7.2 м`, що за поточної швидкості залишає системі рівно `600 мс` до фізичного удару.

Якщо бортовий планувальник реагує за наївною схемою «виявив колізію — миттєво екстрено загальмуй», апарат неминуче розбивається. За максимального доступного кута тангажу `θ_max = 45°` граничне гальмівне прискорення мультикоптера обмежене проєкцією гравітації та тяги: `a_max = g · tan(45°) ≈ 9.81 м/с²`. Чистий гальмівний шлях без урахування затримок становить:

```
S_stop = v² / (2 · a_max)
       = 12² / (2 · 9.81)
       = 144 / 19.62
       = 7.34 м                 [гальмівний шлях перевищує запас дистанції 7.2 м]
```

Додавши сюди апаратну затримку стереокамери (`30 мс`), час інтеграції хмари точок у воксельну сітку (`20 мс`) та час розвороту корпусу безпілотника за кутової швидкості `ω_pitch = 300 °/с` (`150 мс`), сумарна дистанція до повної зупинки сягає `9.74 м`. Зупинитися перед перешкодою фізично неможливо. Єдиний порятунок — негайне динамічне перепланування траєкторії в обхід перешкоди без скидання поступальної швидкості, де на зміну напрямку польоту на `1.5 м` убік потрібно значно менше бічного прискорення, ніж на повну зупинку.

Друга критична помилка полягає у спробі запустити класичний алгоритм пошуку шляху (наприклад, A* чи RRT) безпосередньо з миттєвої виміряної точки `p(t_now)` з нульовою або довільною початковою швидкістю. Поки бортовий комп'ютер розраховує новий просторовий шлях протягом `t_plan = 40 мс`, дрон пролітає `0.48 м`. Спроба виконати нову траєкторію, розраховану від старої точки, породжує миттєвий стрибок позиційної помилки для автопілота, колосальний сплеск цільового прискорення, насичення моторів на максимальних обертах, зрив кутової орієнтації та миттєву аварію.

Динамічне перепланування на ходу (Dynamic Replanning) вирішує задачу генерації нового безаварійного маршруту в умовах карти, яка постійно змінюється, суворо узгоджуючи математику пошуку з фізичною інерцією тіла та ненульовим часом роботи самого обчислювача.

## Диференціальна площинність та фізика кінодинамічних обмежень

Рух безпілотного апарата у фізичному просторі описується вектором стану у світовій системі координат `W = {x_W, y_W, z_W}`: положенням центру мас `p(t) = [x(t), y(t), z(t)]ᵀ` та орієнтацією зв'язаної системи координат `B = {x_B, y_B, z_B}`, заданою матрицею обертання `R(t) ∈ SO(3)`.

Послідовні похідні вектора положення за часом мають прямий фізичний зміст:

```
v(t) = ṗ(t) = dp/dt           [лінійна швидкість]
a(t) = p̈(t) = d²p/dt²         [лінійне прискорення]
j(t) = p⃛(t) = d³p/dt³         [ривок або jerk]
s(t) = p⁽⁴⁾(t) = d⁴p/dt⁴      [снеп або snap]
```

Для мультикоптера справедлива фундаментальна властивість **диференціальної площинності** (Differential Flatness). Всі 12 змінних стану (3 координати позиції, 3 компоненти лінійної швидкості, 3 кути орієнтації, 3 кутові швидкості) та 4 керуючі сигнали моторів однозначно виражаються через 4 плоскі виходи (Flat Outputs) та їхні похідні:

```
σ(t) = [x(t), y(t), z(t), ψ(t)]ᵀ
```

де `ψ(t)` — кут курсу (yaw).

Зв'язок між вектором лінійного прискорення та просторовою орієнтацією визначається другим законом Ньютона:

```
m · a(t) = T(t) · z_B - m · g · z_W
```

де `m` — маса апарата, `g = 9.81 м/с²` — прискорення вільного падіння, `T(t)` — сумарна скалярна тяга чотирьох пропелерів, а `z_B` — одиничний вектор вертикальної осі апарата, спрямований перпендикулярно до площини рами вгору.

З цього рівняння вектор тяги та вертикальна вісь дрона знаходяться аналітично:

```
F_total = m · (a(t) + g · z_W)
T(t) = ‖F_total‖ = m · ‖a(t) + g · z_W‖
z_B = F_total / ‖F_total‖ = (a(t) + g · z_W) / ‖a(t) + g · z_W‖
```

Щоб повністю визначити матрицю орієнтації `R = [x_B, y_B, z_B]`, задається напрямок носової частини дрона через проміжний вектор `x_C = [cos(ψ), sin(ψ), 0]ᵀ`. Поперечна вісь `y_B` та поздовжня вісь `x_B` обчислюються через векторні добутки:

```
y_B = (z_B × x_C) / ‖z_B × x_C‖
x_B = y_B × z_B
```

Диференціюючи вираз для `z_B` за часом, отримуємо зв'язок між кутовою швидкістю `ω` та ривком `j(t) = p⃛(t)`:

```
h_ω = (m / T) · (j(t) - (z_Bᵀ · j(t)) · z_B)
ω_x = -h_ωᵀ · y_B
ω_y = h_ωᵀ · x_B
ω_z = ψ̇ · z_Wᵀ · z_B
```

Диференціюючи ще раз, кутове прискорення `α = ω̇` виражається через четверту похідну позиції — **снеп** `s(t) = p⁽⁴⁾(t)`.

З цієї математичної моделі випливає фізична сутність обмежень гладкості:

```
Похідна траєкторії    Фізичний ефект на апарат             Наслідок розриву при переплануванні
Позиція p(t)          Координата в просторі                Миттєва просторова телепортація
Швидкість v(t)        Кінетична енергія та імпульс         Нескінченна сила F = m · Δv / Δt
Прискорення a(t)      Кути нахилу (roll/pitch) та тяга     Стрибок кутів орієнтації, насичення тяги
Ривок j(t)            Кутова швидкість обертання ω         Стрибок струмів на ESC, удар по моторах
Снеп s(t)             Кутове прискорення рами α            Зрив потоку з лопатей, крутильні вібрації
```

Траєкторія називається **кінодинамічно сумісною** (Kinodynamic Feasible), якщо вона одночасно задовольняє дві умови:
1. `p(t) ∈ C_free` для всіх `t ∈ [0, T]` (геометрична відсутність зіткнень з урахуванням конфігураційного габариту дрона).
2. Кінематичні характеристики не перевищують фізичних можливостей приводів:

```
‖v(t)‖ ≤ v_max                 [максимальна швидкість]
‖a(t)‖ ≤ a_max                 [максимальне прискорення]
‖j(t)‖ ≤ j_max                 [максимальний ривок]
f_min ≤ ‖a(t) + g · z_W‖ ≤ f_max  [діапазон сумарної питомої тяги моторів]
```

## Механізм склеювання траєкторій у точці випередження

Коли бортова система картографування фіксує нову перешкоду в момент часу `t_now`, алгоритм перепланування не має права вважати дрон нерухомим чи зупиняти обчислення. Планувальник виконується як асинхронний процес у реальному часі й має фіксований або обмежений зверху бюджет часу `t_plan`.

Якщо розрахунок нової траєкторії триває від моменту `t_now` до `t_now + t_plan`, то в момент готовності результату дрон фізично перебуватиме вже в точці `p(t_now + t_plan)`. Якщо розпочати нову траєкторію від точки `p(t_now)`, виникає фатальний фазовий зсув: автопілот спробує повернути апарат назад у точку, де той був `40 мс` тому.

Правильний механізм полягає у **склеюванні траєкторії в точці випередження** (Trajectory Stitching). Планувальник прогнозує рух дрона за *старою, вже затвердженою траєкторією* `σ_old(t)` на часовий інтервал `t_plan` уперед:

```
t_stitch = t_now + t_plan
```

Стан склеювання `S_stitch` у момент `t_stitch` обчислюється аналітичним розрахунком старої траєкторії:

```
p_stitch = σ_old(t_stitch)
v_stitch = σ̇_old(t_stitch)
a_stitch = σ̈_old(t_stitch)
```

Нова траєкторія `σ_new(τ)`, де локальний час `τ = t - t_stitch ≥ 0`, оптимізується з жорсткими початковими крайовими умовами:

```
σ_new(0) = p_stitch
σ̇_new(0) = v_stitch
σ̈_new(0) = a_stitch
```

Поки алгоритм перепланування працює в окремому потоці, контур виконання автопілота безперервно відпрацьовує стару траєкторію `σ_old(t)` на інтервалі `t ∈ [t_now, t_stitch]`. Рівно в момент `t_stitch` автопілот безшовно перемикає джерело цільових уставок зі `σ_old` на `σ_new`. Оскільки позиція, швидкість і вектор прискорення в точці стику тотожно рівні, регулятори моторів не відчувають жодного стрибка.

![Фізичний простір та профілі неперервності при склеюванні траєкторії](/root/sys/sys-dron/pereplanuvannia-na-khodu/img/kinodynamic-stitching.svg)
*Принцип кінодинамічного склеювання траєкторій: розрахунок починається з випередженням на час t_plan, а крайові умови C² забезпечують гладкість профілів позиції, швидкості й прискорення без стрибків тяги.*

Якщо час обчислення `t_plan` коливається від кадру до кадру, у системі задається консервативна верхня оцінка `t_plan_max` (наприклад, `30 мс`). Якщо оптимізатор завершив роботу раніше (за `12 мс`), результат буферизується й активується точно в запланований момент `t_now + t_plan_max`.

## Алгоритми швидкого локального оновлення

Коли карта довкілля змінюється лише локально (наприклад, у полі зору з'явився стовп або інший дрон), перераховувати повний глобальний маршрут від старту до фінішу довжиною кілька кілометрів — марнотратство обчислювальних ресурсів. Сучасні бортові автопілоти застосовують дворівневу схему: швидкий дискретний фронтенд для знаходження топології обходу та неперервний оптимізаційний бекенд для формування плавного кінодинамічного сплайна.

### Інкрементний граф: алгоритм D* Lite

У класичному пошуку A* поява навіть однієї перешкоди на маршруті вимагає повного очищення черги з пріоритетом і побудови дерева шляхів з нуля зі складністю `O(N · log N)`. На 3D-сітках розміром `200 × 200 × 50` вокселів це займає понад `100 мс`.

Алгоритм **D\* Lite** розв'язує цю задачу інкрементно: він зберігає попереднє дерево пошуку й при зміні вартостей окремих ребер графа оновлює лише ті вершини, на які безпосередньо вплинули зміни.

D* Lite веде пошук у зворотному напрямку: від глобальної цілі `s_goal` до поточного положення `s_start`. Для кожної вершини графа `s` підтримуються дві оцінки вартості:
- `g(s)` — поточна оцінка найкоротшої відстані від `s` до `s_goal`;
- `rhs(s)` — одношаговий погляд уперед (one-step lookahead cost), який обчислюється через сусідні вершини:

```
rhs(s) = 0,                               якщо s = s_goal
rhs(s) = min [s' ∈ Succ(s)] (c(s, s') + g(s')),  якщо s ≠ s_goal
```

Вершина називається **локально узгодженою** (Locally Consistent), якщо `g(s) = rhs(s)`. Якщо вартість переходу `c(u, v)` зростає до нескінченності через появу перешкоди, вершини `u` та `v` стають неузгодженими (`g(u) ≠ rhs(u)`) і поміщаються у чергу з пріоритетом `U`.

Ключ пріоритету в черзі є парою значень `k(s) = [k₁(s); k₂(s)]`:

```
k₁(s) = min(g(s), rhs(s)) + h(s_start, s) + k_m
k₂(s) = min(g(s), rhs(s))
```

де `h(s_start, s)` — евристична відстань до поточного положення дрона, а `k_m` — кумулятивний модифікатор евристики (Key Modifier). Коли дрон переміщується з позиції `s_prev` у `s_start`, замість повного перерахунку пріоритетів усіх вершин у черзі модифікатор просто збільшується на пройдену відстань:

```
k_m = k_m + h(s_prev, s_start)
```

Під час процедури `UpdateVertex(u)` алгоритм перевіряє лише локальних сусідів зміненої комірки:

1. Якщо `u ≠ s_goal`, перераховується значення `rhs(u) = min [s' ∈ Succ(u)] (c(u, s') + g(s'))`.
2. Якщо `u` перебуває в черзі `U`, вона видаляється з черги.
3. Якщо `g(u) ≠ rhs(u)`, вершина `u` знову вставляється в `U` з оновленим ключем `k(u)`.

Основна функція `ComputeShortestPath()` витягує вершини з черги `U`, доки найменший ключ у черзі менший за ключ поточної позиції дрона `k(s_start)` або поточна позиція залишається неузгодженою `g(s_start) ≠ rhs(s_start)`:

- Якщо для вилученої вершини `u` значення `g(u) > rhs(u)` (переузгоджена вершина, вартість зменшилася), встановлюється `g(u) = rhs(u)`, і всі попередники `s ∈ Pred(u)` оновлюються через `UpdateVertex(s)`.
- Якщо `g(u) < rhs(u)` (недоузгоджена вершина, вартість зросла через перешкоду), значення скидається `g(u) = ∞`, після чого оновлюються сама вершина `u` та всі її попередники.

Завдяки зворотній орієнтації пошуку та збереженню коректних `g`-значень для більшої частини простору, час реакції D* Lite на зміну карти становить лише `0.8–2.5 мс`, що на два порядки швидше за перезапуск A*.

### Кінодинамічний пошук у просторі станів (Kinodynamic A*)

Альтернативою D* Lite на регулярній сітці є **Kinodynamic A\*** — дискретний пошук, де вузлами графа є не геометричні клітинки, а вектори стану `x = [p, v]ᵀ`. Рух між вузлами генерується інтегруванням дискретних імпульсів керування (Motion Primitives) — фіксованих векторів прискорення `u ∈ U = {-a_max, 0, a_max}³` протягом кванту часу `τ` (наприклад, `0.2 с`).

Траєкторія кожного примітиву знаходиться аналітичним інтегруванням:

```
p(t) = p₀ + v₀·t + 0.5·u·t²
v(t) = v₀ + u·t
```

Оскільки всі згенеровані примітиви автоматично задовольняють диференціальні обмеження за прискоренням та швидкістю, знайдений шлях складається з кусочно-квадратичних сегментів без розривів швидкості (`C¹`). Kinodynamic A* використовує евристичну функцію Понтрягіна — точний мінімальний час польоту у фазовому просторі з урахуванням `a_max`, що забезпечує швидке відсікання неперспективних гілок.

### Локальна деформація B-сплайнів у полях ESDF

Дискретний шлях від D* Lite або Kinodynamic A* слугує початковою ініціалізацією для бекенд-оптимізатора. Для перетворення ламаної лінії на кінодинамічно гладку траєкторію використовують однорідні **B-сплайни** (B-splines).

B-сплайн порядку `p_b` (степеня `p_b - 1`, типово кубічний `p_b = 4` або квінтичний `p_b = 6`) однозначно задається вектором із `N + 1` контрольних точок `Q = {Q₀, Q₁, ..., Q_N}` та вузловим вектором часу `t = [t₀, t₁, ..., t_M]`:

```
p(t) = ∑ [i=0..N] Q_i · B_{i, p_b}(t)
```

де `B_{i, p_b}(t)` — базисні поліноми Блама-де Бора. Для рівномірного B-сплайна вузловий вектор має сталий крок `Δt = t_{i+1} - t_i`.

B-сплайни володіють трьома вирішальними властивостями для перепланування на ходу:

1. **Властивість опуклої оболонки (Convex Hull Property):** будь-який сегмент кривої для часу `t ∈ [t_i, t_{i+1})` суворо лежить всередині опуклої оболонки відповідних `p_b` контрольних точок `{Q_{i-p_b+1}, ..., Q_i}`. Якщо опукла оболонка контрольних точок вільна від перешкод, уся неперервна траєкторія гарантовано вільна від колізій.
2. **Локальність носія (Local Support):** зміна положення однієї контрольної точки `Q_i` деформує криву лише на часовому інтервалі `[t_i, t_{i+p_b})`. Якщо нова перешкода перекриває середину траєкторії, оптимізатор переміщує лише 3–4 сусідні контрольні точки, не зачіпаючи точку стартового склеювання `Q₀, Q₁, Q₂` та фінішну ділянку.
3. **Аналітичні похідні:** похідна B-сплайна є іншим B-сплайном нижчого порядку, а його контрольні точки обчислюються елементарним відніманням:

```
V_i = p_b · (Q_{i+1} - Q_i) / (t_{i+p_b+1} - t_{i+1}) = (p_b / Δt) · (Q_{i+1} - Q_i)
A_i = (p_b - 1) · (V_{i+1} - V_i) / Δt = (p_b · (p_b - 1) / Δt²) · (Q_{i+2} - 2·Q_{i+1} + Q_i)
J_i = (p_b - 2) · (A_{i+1} - A_i) / Δt = (p_b · (p_b - 1) · (p_b - 2) / Δt³) · (Q_{i+3} - 3·Q_{i+2} + 3·Q_{i+1} - Q_i)
```

Для деформації траєкторії простір представляється у вигляді знакових евклідових полів відстаней (Euclidean Signed Distance Field, ESDF). Кожен воксель карти містить відстань `d(x)` до найближчої фізичної перешкоди та градієнтний вектор `∇d(x)`, спрямований від перешкоди у вільний простір.

Оптимізація контрольних точок B-сплайна формулюється як мінімізація зваженої суми функцій вартості:

```
min [Q] J_total = λ_smooth · J_smooth + λ_obs · J_obs + λ_dyn · J_dyn
```

де компоненти вартості визначаються наступним чином:

- **Гладкість (Smoothness):** мінімізація інтегралу квадрата прискорення або ривка через скінченні різниці контрольних точок:
  `J_smooth = ∑ [i] ‖A_i‖²`
  Градієнт гладкості є строго лінійним: `∂J_smooth / ∂Q_i = 2 · M_smooth · Q`.
- **Безпека від перешкод (Obstacle Avoidance):** квадратичний або кубічний штраф за наближення до перешкоди ближче безпечної дистанції `d_safe`:
  `J_obs = ∑ [i] c(d(Q_i))`, де `c(d) = (d - d_safe)²`, якщо `d < d_safe`, і `0` інакше.
  Градієнт виштовхування контрольної точки обчислюється напряму через поле відстаней:
  `∂J_obs / ∂Q_i = -2 · (d(Q_i) - d_safe) · ∇d(Q_i)`
  Для точок між центрами вокселів значення `d(Q_i)` та `∇d(Q_i)` отримуються трилінійною інтерполяцією 8 сусідніх вокселів ESDF.
- **Кінодинамічні обмеження (Feasibility):** штраф за перевищення лімітів швидкості й прискорення:
  `J_dyn = ∑ [i] max(0, ‖V_i‖² - v_max²)² + ∑ [i] max(0, ‖A_i‖² - a_max²)²`

Оскільки градієнт цільової функції `∇_Q J_total` обчислюється аналітично без чисельного диференціювання, задача розв'язується квазіньютонівським методом L-BFGS (Limited-memory Broyden–Fletcher–Goldfarb–Shanno) за `3–8 мс`.

### Мінімізація поліномів (Minimum Snap QP)

Альтернативним підходом до бекенд-оптимізації є подання траєкторії у вигляді кусочно-поліноміальної функції з `M` сегментів. На кожному інтервалі часу `t ∈ [0, T_k]` координата описується поліномом степеня `N = 7` (для мінімізації снепу) або `N = 5` (для мінімізації ривка):

```
p_k(t) = c_{k,0} + c_{k,1}·t + c_{k,2}·t² + ... + c_{k,N}·tᴺ = ∑ [j=0..N] c_{k,j} · tʲ
```

Цільова функція мінімізує сумарний інтеграл квадрата похідної (сніпу або ривка):

```
J_snap = ∑ [k=1..M] ∫ [0..T_k] ‖p_k⁽⁴⁾(t)‖² dt = cᵀ · H · c
```

де `c = [c₁, c₂, ..., c_M]ᵀ` — сукупний вектор усіх коефіцієнтів розмірності `M · (N + 1) · 3`, а `H` — блочно-діагональна матриця Гессе. Для одного сегмента тривалістю `T_k` елементи матриці `Q_k` обчислюються інтегруванням добутків похідних базисних мономів:

```
Q_k[r, c] = 2 · (r·(r-1)·(r-2)·(r-3)) · (c·(c-1)·(c-2)·(c-3)) / (r + c - 7) · T_k^{r + c - 7},   якщо r, c ≥ 4
Q_k[r, c] = 0,                                                                                    якщо r < 4 або c < 4
```

При переплануванні на ходу на коефіцієнти накладаються лінійні обмеження у формі матричного рівняння `A · c = b`:

1. **Крайові умови склеювання на старті (`k = 1, t = 0`):**
   `p₁(0) = p_stitch`, `ṗ₁(0) = v_stitch`, `p̈₁(0) = a_stitch`, `p⃛₁(0) = j_stitch`.
2. **Неперервність на внутрішніх стиках сегментів (`t = T_k` для сегмента `k` і `t = 0` для `k+1`):**
   `p_k(T_k) = p_{k+1}(0)`
   `ṗ_k(T_k) = ṗ_{k+1}(0)`
   `p̈_k(T_k) = p̈_{k+1}(0)`
   `p⃛_k(T_k) = p⃛_{k+1}(0)`
3. **Кінцеві умови в точці повернення на безпечний маршрут (`k = M, t = T_M`):**
   `p_M(T_M) = p_goal`, `ṗ_M(T_M) = v_goal`, `p̈_M(T_M) = a_goal`.

Якщо проміжні шляхові точки задані жорстко, система має єдиний замкнений розв'язок:

```
c* = A⁻¹ · b
```

Оскільки матриця `A` є розрідженою та блочно-діагональною, розв'язання через LU-факторизацію або метод прогонки займає менше `0.5 мс`.

Якщо ж перешкода вимагає відхилення траєкторії всередині безпечного опуклого коридору (Safe Flight Corridor, SFC), проміжні координати задаються не точками, а нерівностями багатогранників:

```
C_k · p_k(t) ≤ d_k,   ∀ t ∈ [0, T_k]
```

У цьому випадку задача розв'язується стандартним розв'язувачем квадратичного програмування (наприклад, OSQP або qpOASES) за `2–5 мс`.

### Оптимізація часового профілю сегментів (Time Allocation)

При кусочно-поліноміальній оптимізації фіксований вектор тривалостей сегментів `T = [T₁, T₂, ..., T_M]ᵀ` часто призводить до нерівномірного навантаження на приводи: короткі за довжиною просторові сегменти вимагають колосальних прискорень, тоді як на довгих ділянках дрон летить надто повільно.

Повна оптимізація траєкторії включає як просторові коефіцієнти `c`, так і вектор тривалостей `T`:

```
min [c, T] J(c, T) = J_snap(c, T) + ρ_T · ∑ [k=1..M] T_k
```

де `ρ_T > 0` — коефіцієнт штрафу за загальний час польоту.

Градієнт цільової функції за тривалістю окремого сегмента `T_k` обчислюється аналітично через теорему про диференціювання функціоналу зі змінними межами:

```
∂J / ∂T_k = -c_kᵀ · (∂Q_k / ∂T_k) · c_k + ρ_T + λᵀ · (∂A / ∂T_k) · c
```

де `λ` — вектор множників Лагранжа для обмежень неперервності.

Градієнтний спуск за вектором часу `T` виконується на верхньому рівні ітерацій: на кожному кроці за фіксованого `T` розв'язується лінійна система `A(T) · c = b`, після чого вектор `T` оновлюється у напрямку антиградієнта `-∇_T J`. Це забезпечує плавний і рівномірний розподіл прискорень уздовж усієї траєкторії.

### Генерація безпечного коридору польоту (Safe Flight Corridor)

Один із найнадійніших методів гарантування безаварійності полягає у побудові **безпечного коридору польоту** (Safe Flight Corridor, SFC). Замість перевірки колізій для мільйонів точок неперервної траєкторії простір навколо дискретного шляху розбивається на послідовність взаємно перекритих опуклих багатогранників (Convex Polyhedra) `P_k = { x ∈ ℝ³ : A_k · x ≤ b_k }`.

Кожен багатогранник будується методом розширення еліпсоїда (Ellipsoid Expansion):

1. Відрізок між двома сусідніми шляховими точками `w_k` та `w_{k+1}` береться як головна вісь початкового еліпсоїда.
2. Еліпсоїд рівномірно роздувається в усіх напрямках у воксельній карті, доки його поверхня не торкнеться першої зайнятої точки перешкоди `p_obs`.
3. У точці дотику генерується гіперплощина, дотична до еліпсоїда, яка відсікає півпростір із перешкодою: `n_iᵀ · (x - p_obs) ≥ 0`.
4. Процес повторюється для всіх точок дотику, формуючи опуклий багатогранник `P_k`, що гарантовано містить лише вільний простір `P_k ⊂ C_free`.

Ключова перевага коридору SFC у поєднанні з B-сплайнами полягає у властивості опуклої оболонки: **якщо всі контрольні точки B-сплайна `Q_i` сегмента належать багатограннику `P_k`, то вся неперервна крива `p(t)` суворо лежить всередині `P_k`**. Це перетворює складну нелінійну задачу уникнення колізій на тривіальні лінійні обмеження-нерівності для оптимізатора.

## Динамічні рухомі перешкоди та конуси швидкостей

Якщо перешкода не є статичною (наприклад, зустрічний або перехресний дрон, птах чи рухомий навантажувач), карта відстаней ESDF застаріває швидше, ніж завершується цикл планування. У цьому випадку перепланування переноситься у **просторово-часовий простір** (Space-Time Configuration Space, `ℝ³ × ℝ`).

Для рухомої перешкоди з поточною позицією `p_obs` та постійною або екстрапольованою швидкістю `v_obs` заборонений простір визначається концепцією **конуса швидкостей** (Velocity Obstacle, VO):

```
VO_{A|B}(v_obs) = { v_A ∈ ℝ³ : ∃ t > 0, p_A + (v_A - v_obs) · t ∈ B ⊕ (-A) }
```

Якщо вектор відносної швидкості `v_rel = v_A - v_obs` потрапляє всередину конуса `VO`, зіткнення через час `t` неминуче.

Алгоритм **оптимального взаємного ухилення** (Optimal Reciprocal Collision Avoidance, ORCA) розподіляє відповідальність за маневр між двома рухомими агентами порівну: кожен апарат змінює свою швидкість щонайменше на половину необхідного вектора ухилення `u`:

```
v_A^{new} ∈ ORCA_{A|B} = { v ∈ ℝ³ : (v - (v_A^{opt} + 0.5 · u))ᵀ · n ≥ 0 }
```

де `n` — нормаль до межі конуса `VO` у точці найближчого виходу.

У бортовому оптимізаторі нерівності ORCA інтегруються безпосередньо у квадратичну програму як лінійні обмеження на вектор швидкості в точці склеювання та контрольні точки перших сегментів B-сплайна: `nᵀ · V_i ≥ nᵀ · (v_A + 0.5 · u)`.

## Архітектурний конвеєр перепланування та бортовий інтерфейс

Для надійної роботи на борту безпілотника модулі автономії об'єднуються у трирівневий конвеєр, розподілений між комп'ютером-компаньйоном (Companion Computer, наприклад NVIDIA Jetson Orin або Raspberry Pi 5) та польотним контролером (Flight Controller, наприклад STM32H7 з прошивкою PX4 або ArduPilot).

```
Частота       Модуль конвеєра                   Призначення
20–50 Гц      Картографування (ESDF/OctoMap)    Інтеграція хмар точок, очищення рухомих шумів
10–30 Гц      Планувальник (D* / B-Spline QP)   Асинхронний розрахунок кінодинамічної траєкторії
250–500 Гц    Генератор уставок (Tracker)       Розрахунок миттєвих [p, v, a, yaw] для автопілота
```

Зв'язок між комп'ютером-компаньйоном та автопілотом реалізується через високошвидкісний UART-інтерфейс (`921600 baud` або Ethernet) за протоколом MAVLink. Замість передачі дискретних шляхових точок компаньйон генерує потік повідомлень `SET_POSITION_TARGET_LOCAL_NED` (ID `#84`), де вказуються погоджені вектори позиції, швидкості, прискорення та кута курсу.

Бітова маска `type_mask` повідомлення `#84` налаштовується наступним чином:
- `POSITION_TARGET_TYPEMASK_VX_IGNORE = 0` (швидкість активна);
- `POSITION_TARGET_TYPEMASK_AX_IGNORE = 0` (прискорення активне, прямий зв'язок Feedforward);
- `POSITION_TARGET_TYPEMASK_YAW_RATE_IGNORE = 0` (швидкість рискання активна).

Одночасна передача прискорення `a_target` дозволяє контуру орієнтації автопілота негайно розраховувати необхідний кут нахилу дрона, не очікуючи виникнення позиційної помилки в PID-регуляторі. Завдяки цьому дрон входить у маневр ухилення з нульовим часовим відставанням.

У системі POSIX на комп'ютері-компаньйоні потоки виконуються з різними пріоритетами планувальника ядра Linux:
- **Потік картографування:** `SCHED_OTHER`, `nice = -10` (обробка лідара та ESDF);
- **Потік оптимізації:** `SCHED_FIFO`, пріоритет `80` (D* Lite та B-spline QP);
- **Потік генератора уставок:** `SCHED_FIFO`, пріоритет `95` (строгий жорсткий реальний час `400 Гц` для відправки MAVLink).

У разі апаратного збою компаньйона або зависання процесу планувальника автопілот відстежує таймаут надходження уставок (`watchdog timeout = 100 мс`). Якщо черговий пакет не надійшов, автопілот автоматично перемикається в режим автономного гальмування (Braking Failsafe) та зависання в точці за даними власної інерційної системи.

Повний алгоритмічний розбір модульної архітектури, структур даних та практичну реалізацію наведено у [модулі kinodynamic-перепланування траєкторій](root:sys-dron/pereplanuvannia-na-khodu/proj-kinodynamic-replanner.md).

## Порівняння підходів до локального перепланування

Вибір математичного апарату для бортового планувальника визначається доступною обчислювальною потужністю, динамікою перешкод та швидкістю польоту:

```
Критерій порівняння      D* Lite               B-Spline ESDF            Minimum Snap QP
Клас гладкості           C⁰ (дискретні ребра)  C² / C³ (неперервний)    C² / C³ (аналітичний)
Час обчислення           0.8–2.5 мс            3.0–8.0 мс               0.5–3.0 мс
Робота в ESDF-полях      Ні (лише сітка)       Так (градієнтний спуск)  Через коридор SFC
Локальні мінімуми        Глобально оптимальний Чутливий до пасток       Вільний у межах SFC
Кінодинамічні обмеження  Через дискретні стани Через функцію штрафу     Строгі QP-обмеження
```

На практиці найкращі результати демонструє гібридна схема: дискретний алгоритм (D* Lite або Kinodynamic A*) генерує початковий безаварійний скелет у глобальній воксельній сітці, після чого B-сплайн або поліноміальний QP-оптимізатор згладжує криву за `2–4 мс` з обов'язковим C²-склеюванням у точці `t_stitch`.

## Програмне зшивання квінтичного сплайна траєкторії

Розглянемо практичну реалізацію аналітичного розв'язувача для аварійного зшивання ділянки маневру ухилення тривалістю `T`. Необхідно побудувати одновимірний поліном 5-го степеня `p(t) = c₀ + c₁·t + c₂·t² + c₃·t³ + c₄·t⁴ + c₅·t⁵`, що забезпечує точне склеювання `C²` між початковим станом `(p₀, v₀, a₀)` при `t = 0` та цільовим станом `(p₁, v₁, a₁)` при `t = T`.

Запишемо рівняння для похідних полінома:

```
p(t)  = c₀ + c₁·t + c₂·t² + c₃·t³ + c₄·t⁴ + c₅·t⁵
ṗ(t)  = c₁ + 2·c₂·t + 3·c₃·t² + 4·c₄·t³ + 5·c₅·t⁴
p̈(t)  = 2·c₂ + 6·c₃·t + 12·c₄·t² + 20·c₅·t³
```

Підставляючи граничні умови при `t = 0`:

```
c₀ = p₀
c₁ = v₀
c₂ = a₀ / 2
```

Для знаходження трьох старших коефіцієнтів `c₃, c₄, c₅` підставимо умови при `t = T`. Введемо дельти положення, швидкості та прискорення:

```
Δp = p₁ - (p₀ + v₀·T + 0.5·a₀·T²)
Δv = v₁ - (v₀ + a₀·T)
Δa = a₁ - a₀
```

Розв'язуючи систему лінійних рівнянь `3 × 3` аналітично відносно `c₃, c₄, c₅`:

```
c₃ = (10·Δp - 4·Δv·T + 0.5·Δa·T²) / T³
c₄ = (-15·Δp + 7·Δv·T - Δa·T²) / T⁴
c₅ = (6·Δp - 3·Δv·T + 0.5·Δa·T²) / T⁵
```

Нижче наведено реалізацію генератора квінтичного сегмента з автоматичною перевіркою кінодинамічних лімітів та часовим масштабуванням:

:::tabs
```c
#include <stdbool.h>
#include <math.h>

typedef struct {
    double p0, v0, a0;  /* Стан склеювання при t = 0 */
    double p1, v1, a1;  /* Цільовий стан при t = T */
    double T;           /* Тривалість маневру */
    double c[6];        /* Коефіцієнти полінома: c[0] + c[1]*t + ... + c[5]*t^5 */
} QuinticSegment;

typedef struct {
    double pos;
    double vel;
    double acc;
    double jerk;
} TrajectoryPoint;

/* Розрахунок аналітичних коефіцієнтів C²-стику */
void quintic_solve(QuinticSegment *seg) {
    double T = seg->T;
    double T2 = T * T;
    double T3 = T2 * T;
    double T4 = T3 * T;
    double T5 = T4 * T;

    seg->c[0] = seg->p0;
    seg->c[1] = seg->v0;
    seg->c[2] = 0.5 * seg->a0;

    double dp = seg->p1 - (seg->p0 + seg->v0 * T + 0.5 * seg->a0 * T2);
    double dv = seg->v1 - (seg->v0 + seg->a0 * T);
    double da = seg->a1 - seg->a0;

    seg->c[3] = (10.0 * dp - 4.0 * dv * T + 0.5 * da * T2) / T3;
    seg->c[4] = (-15.0 * dp + 7.0 * dv * T - da * T2) / T4;
    seg->c[5] = (6.0 * dp - 3.0 * dv * T + 0.5 * da * T2) / T5;
}

/* Обчислення миттєвих уставок для контуру стабілізації */
TrajectoryPoint quintic_eval(const QuinticSegment *seg, double t) {
    if (t < 0.0) t = 0.0;
    if (t > seg->T) t = seg->T;

    double t2 = t * t;
    double t3 = t2 * t;
    double t4 = t3 * t;
    double t5 = t4 * t;

    TrajectoryPoint pt;
    pt.pos = seg->c[0] + seg->c[1]*t + seg->c[2]*t2 + seg->c[3]*t3 + seg->c[4]*t4 + seg->c[5]*t5;
    pt.vel = seg->c[1] + 2.0*seg->c[2]*t + 3.0*seg->c[3]*t2 + 4.0*seg->c[4]*t3 + 5.0*seg->c[5]*t4;
    pt.acc = 2.0*seg->c[2] + 6.0*seg->c[3]*t + 12.0*seg->c[4]*t2 + 20.0*seg->c[5]*t3;
    pt.jerk = 6.0*seg->c[3] + 24.0*seg->c[4]*t + 60.0*seg->c[5]*t2;
    return pt;
}

/* Перевірка лімітів та ітеративна корекція тривалості T */
bool quintic_rescale_time(QuinticSegment *seg, double v_max, double a_max, int max_iter) {
    for (int iter = 0; iter < max_iter; ++iter) {
        quintic_solve(seg);

        double max_v = 0.0;
        double max_a = 0.0;
        const int samples = 20;

        for (int i = 0; i <= samples; ++i) {
            double t = (seg->T * i) / samples;
            TrajectoryPoint pt = quintic_eval(seg, t);
            if (fabs(pt.vel) > max_v) max_v = fabs(pt.vel);
            if (fabs(pt.acc) > max_a) max_a = fabs(pt.acc);
        }

        if (max_v <= v_max && max_a <= a_max) {
            return true; /* Траєкторія кінодинамічно допустима */
        }

        double scale_v = max_v / v_max;
        double scale_a = sqrt(max_a / a_max);
        double scale = (scale_v > scale_a) ? scale_v : scale_a;
        if (scale < 1.05) scale = 1.05;

        seg->T *= scale; /* Розтягуємо час для зниження пікових навантажень */
    }
    return false;
}
```

```cpp
#include <array>
#include <cmath>
#include <algorithm>
#include <span>

struct TrajectoryPoint {
    double pos{0.0};
    double vel{0.0};
    double acc{0.0};
    double jerk{0.0};
};

class QuinticSegment {
public:
    constexpr QuinticSegment(double p0, double v0, double a0,
                             double p1, double v1, double a1,
                             double duration) noexcept
        : p0_(p0), v0_(v0), a0_(a0), p1_(p1), v1_(v1), a1_(a1), duration_(duration) {
        solve();
    }

    void solve() noexcept {
        const double t1 = duration_;
        const double t2 = t1 * t1;
        const double t3 = t2 * t1;
        const double t4 = t3 * t1;
        const double t5 = t4 * t1;

        c_[0] = p0_;
        c_[1] = v0_;
        c_[2] = 0.5 * a0_;

        const double dp = p1_ - (p0_ + v0_ * t1 + 0.5 * a0_ * t2);
        const double dv = v1_ - (v0_ + a0_ * t1);
        const double da = a1_ - a0_;

        c_[3] = (10.0 * dp - 4.0 * dv * t1 + 0.5 * da * t2) / t3;
        c_[4] = (-15.0 * dp + 7.0 * dv * t1 - da * t2) / t4;
        c_[5] = (6.0 * dp - 3.0 * dv * t1 + 0.5 * da * t2) / t5;
    }

    [[nodiscard]] TrajectoryPoint evaluate(double t) const noexcept {
        const double clamped_t = std::clamp(t, 0.0, duration_);
        const double t2 = clamped_t * clamped_t;
        const double t3 = t2 * clamped_t;
        const double t4 = t3 * clamped_t;
        const double t5 = t4 * clamped_t;

        return {
            .pos = c_[0] + c_[1]*clamped_t + c_[2]*t2 + c_[3]*t3 + c_[4]*t4 + c_[5]*t5,
            .vel = c_[1] + 2.0*c_[2]*clamped_t + 3.0*c_[3]*t2 + 4.0*c_[4]*t3 + 5.0*c_[5]*t4,
            .acc = 2.0*c_[2] + 6.0*c_[3]*clamped_t + 12.0*c_[4]*t2 + 20.0*c_[5]*t3,
            .jerk = 6.0*c_[3] + 24.0*c_[4]*clamped_t + 60.0*c_[5]*t2
        };
    }

    bool scale_duration_if_needed(double v_max, double a_max, int max_iterations = 10) noexcept {
        for (int iter = 0; iter < max_iterations; ++iter) {
            solve();
            double max_v = 0.0;
            double max_a = 0.0;
            constexpr int kSamples = 20;

            for (int i = 0; i <= kSamples; ++i) {
                const double t = (duration_ * i) / kSamples;
                const auto pt = evaluate(t);
                max_v = std::max(max_v, std::abs(pt.vel));
                max_a = std::max(max_a, std::abs(pt.acc));
            }

            if (max_v <= v_max && max_a <= a_max) {
                return true;
            }

            const double scale_v = max_v / v_max;
            const double scale_a = std::sqrt(max_a / a_max);
            const double scale = std::max({scale_v, scale_a, 1.05});
            duration_ *= scale;
        }
        return false;
    }

    [[nodiscard]] double duration() const noexcept { return duration_; }
    [[nodiscard]] std::span<const double, 6> coefficients() const noexcept { return c_; }

private:
    double p0_, v0_, a0_;
    double p1_, v1_, a1_;
    double duration_;
    std::array<double, 6> c_{};
};
```

## Інженерні пастки перепланування на ходу

Під час проектування та польотних випробувань систем динамічного перепланування інженери регулярно стикаються з критичними відмовами:

1. **Пастка застарілої карти (Stale Map Latency):** Якщо конвеєр обробки лідара має затримку `80 мс`, а планувальник рахує ще `30 мс`, то траєкторія будується на основі перешкод, де дрон знаходився `110 мс` тому. На швидкості `15 м/с` це дає просторову помилку `1.65 м`. Лікування: жорстка часова синхронізація через PTP/hardware triggers та екстраполяція позицій перешкод через поточний вектор швидкості БПЛА.
2. **Пастка локального мінімуму в U-подібних пастках:** Градієнтні методи деформації B-сплайнів не можуть самостійно вийти з увігнутої стіни чи глухого кута коридору, оскільки сили відштовхування затискають контрольні точки всередині. Лікування: обов'язкове використання глобального топологічного фронтенду (D* Lite або Kinodynamic A*), який прокладає шлях крізь інший гомотопічний клас, перш ніж запускати локальний оптимізатор.
3. **Ефект голодування горизонту (Horizon Starvation):** Якщо локальний планувальник будує траєкторію на короткий горизонт `T = 1.0 с` заради економії CPU, дрон може увійти у зону високої швидкості, де наприкінці горизонту немає фізично можливої траєкторії для гальмування чи маневру. Лікування: підтримка кінцевої безпечної зони зупинки (Emergency Braking Trajectory) на кожній ітерації планування.
4. **Насичення моторів при боковому вітрі:** Сильний вітровий порив `6 м/с` забирає до `30%` запасу тяги двигунів на компенсацію зносу. Якщо планувальник вимагає граничного бічного прискорення `a_max`, сумарний вектор тяги виходить за межі фізичних можливостей гвинтів. Лікування: динамічне заниження допустимих лімітів `a_max` та `v_max` у планувальнику на основі поточної оцінки вітру від розширеного фільтра Калмана (EKF).
