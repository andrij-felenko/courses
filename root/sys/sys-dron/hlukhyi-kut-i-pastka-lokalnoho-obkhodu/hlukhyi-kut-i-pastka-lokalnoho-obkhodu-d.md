Коли дрон прямує до цільової точки у міській забудові чи промисловому ангарі, найшвидший спосіб оминати раптові перешкоди — реактивне відштовхування: сенсор виявляє стіну, обчислювач генерує вектор ухилення в протилежний бік, а вектор тяги до цілі підсумовується з ним на кожному такті польотного контролера. Ця схема бездоганно працює з поодинокими стовпами, деревами чи плоскими фасадами. Проте варто апарату влетіти у внутрішній двір у формі літери U, заглиблення між цехами чи глухий кут паркану, як вектор тяги продовжує непереборно тягнути дрон уперед крізь перешкоду до цілі, а вектори відштовхування від стін із трьох боків спрямовуються назад і всередину.

У певній точці всередині увігнутості ці протилежні сили зрівнюють одна одну до нуля: результуюче прискорення зникає, просторова швидкість падає до нуля, і багатороторний апарат зависає на місці, витрачаючи сотні ват потужності акумулятора на безплідне утримання точки. Якщо ж дискретність оновлення сенсорів або шум далекомірів постійно зміщують рівновагу, замість повного зависання виникає інший руйнівний режим — автоколивання (маятниковий рух або граничний цикл): безпілотник із частотою кілька герц шарпається вперед-назад і вліво-вправо між стінами, перевантажуючи виконавчі механізми та швидко вичерпуючи енергоресурс борту.

Проблема полягає в тому, що локальні реактивні алгоритми оцінюють довкілля лише у радіусі дії своїх сенсорів і не мають уявлення про топологію простору за межами поля зору. Для виходу з такої ситуації системі автономності потрібні окремі механізми: математичний детектор відсутності прогресу, що відрізняє справжній тупик від штатного гальмування, та набір активних стратегій виходу — від руху вздовж контуру перешкоди й відкату по історії траєкторії до набору висоти та примусового виклику глобального планувальника.

## Анатомія локального мінімуму: чому реактивне планування потрапляє в пастку

Більшість класичних локальних планувальників реального часу (зокрема штучні потенціальні поля — англ. *Artificial Potential Fields, APF*, методи динамічного вікна — англ. *Dynamic Window Approach, DWA* та гістограми векторного поля — англ. *Vector Field Histogram, VFH*) зводять задачу оминання до задачі локальної градієнтної оптимізації.

У концепції потенціальних полів цільова точка генерує притягальний потенціал `U_att(p)`, що монотонно зростає з віддаленням від цілі, а кожна виявлена перешкода створює навколо себе відштовхувальний потенціал `U_rep(p)`, що прямує до нескінченності при наближенні до її поверхні:

```
U_total(p) = U_att(p) + ∑ U_rep,i(p)
```

Бажана швидкість або сила керування формується рухом уздовж антиградієнта сумарного потенціалу:

```
F_total(p) = -∇U_total(p) = F_att(p) + ∑ F_rep,i(p)
```

де квадратичний притягальний потенціал та його сила задаються відстанню до цільової точки `p_goal`:

```
U_att(p) = 0.5 · k_att · ||p - p_goal||²
F_att(p) = -k_att · (p - p_goal)
```

Відштовхувальне поле `i`-ї перешкоди діє лише в межах радіуса впливу `d_0` від її найближчої точки:

```
U_rep,i(p) = 0.5 · k_rep · (1/d_i(p) - 1/d_0)²    [якщо d_i(p) ≤ d_0]
U_rep,i(p) = 0                                     [якщо d_i(p) > d_0]
```

Градієнт цього поля створює відштовхувальну силу, спрямовану вздовж нормалі від поверхні:

```
F_rep,i(p) = k_rep · (1/d_i(p) - 1/d_0) · (1/d_i(p)²) · ∇d_i(p)
```

### Чисельний розрахунок сил у типовій пастці

Розглянемо квадрокоптер масою `m = 1.8` кг, що летить зі швидкістю `v = 3.0` м/с до цілі `p_goal = [30.0, 0.0, 5.0]ᵀ`.

На шляху розташована U-подібна перешкода з дном у точці `x = 15.0` м та бічними стінками на `y = ±4.0` м. Нехай параметри потенціалу дорівнюють `k_att = 1.2` Н/м, `k_rep = 25.0` Н·м, радіус впливу стін `d_0 = 3.0` м.

Коли дрон влітає всередину кишені у точку `p = [13.0, 0.0, 5.0]ᵀ`:
1. Відстань до цілі становить `||p - p_goal|| = 17.0` м. Сила притягання спрямована вперед вздовж осі `X`:

```
F_att_x = 1.2 · 17.0 = 20.4 Н
```

2. Відстань до дна кишені становить `d_bottom = 2.0` м. Відштовхувальна сила від дна спрямована назад вздовж осі `X`:

```
F_rep_bottom_x = -25.0 · (1/2.0 - 1/3.0) · (1/4.0) = -25.0 · 0.1667 · 0.25 = -1.04 Н
```

3. У міру просування вперед дрон наближається до дна до відстані `d_bottom = 0.58` м. У цій точці:

```
F_rep_bottom_x = -25.0 · (1/0.58 - 1/3.0) · (1/0.58²) ≈ -20.4 Н
```

Результуюча поздовжня сила повністю обнуляється:

```
F_total_x = F_att_x + F_rep_bottom_x = 20.4 - 20.4 = 0.0 Н
```

Поперечні сили від бічних стінок `y = 4.0` та `y = -4.0` взаємно компенсуються через симетрію `F_rep_left_y + F_rep_right_y = 0`. Дрон опиняється в абсолютному динамічному глухому куті на відстані 58 см від бетонної стіни.

### Геометричний колапс сил

Коли перешкода має увігнуту геометрію (U-подібний фасад, тупиковий коридор або заглиблення між трьома контейнерами), виникає принциповий дефект градієнтного спуску:

1. **Точка локального мінімуму (локальна пастка).** Якщо ціль розташована позаду перешкоди, вектор `F_att` спрямований углиб увігнутості. Дно та бічні стінки перешкоди генерують відштовхувальні вектори `F_rep`, спрямовані назустріч `F_att` та назустріч один одному.
2. **Занулення сумарного градієнта.** У певній точці `p_trap` векторна сума збігається:

```
F_total(p_trap) = -∇U_total(p_trap) = 0,    при цьому p_trap ≠ p_goal
```

Оскільки градієнт дорівнює нулю, антиградієнтний спуск вважає, що оптимальний стан досягнуто. Польотний контролер скидає задану швидкість до нуля: апарат «застрягає» (англ. *deadlock*) у фальшивій рівновазі.

3. **Сідлові точки та нестійкість.** Якщо точка занулення сил є сідловою точкою потенціалу, найменше збурення від пориву вітру або шуму лідара виводить дрон із рівноваги ліворуч або праворуч. Проте, змістившись убік, апарат наближається до однієї зі стінок, отримує потужний відштовхувальний імпульс назад, повертається до центру, за інерцією пролітає його, відштовхується від протилежної стінки й входить у стійкий автоколивальний режим.

### Гармонічні потенціальні функції та чому вони дорогі на борту

У теоретичній робототехніці відомий математичний спосіб повністю ліквідувати локальні мінімуми в аналітичних потенціальних полях — використання гармонічних функцій (англ. *Harmonic Potential Fields*). Гармонічна функція задовольняє рівнянню Лапласа:

```
∇²U(p) = ∂²U/∂x² + ∂²U/∂y² + ∂²U/∂z² = 0
```

За принципом максимуму Діріхле для гармонічних функцій, такий потенціал не може мати строгих локальних мінімумів або максимумів усередині вільного простору: усі екстремуми розташовані виключно на межах області (на стінках перешкод потенціал дорівнює 1, у цільовій точці — 0).

Проте розв'язання рівняння Лапласа в реальному часі на бортовому мікроконтролері вимагає розв'язання системи лінійних рівнянь або чисельної релаксації методом скінченних різниць на тривимірній сітці (англ. *Successive Over-Relaxation, SOR*). При розмірі локальної карти `100 × 100 × 50` вокселів кожна ітерація релаксації потребує мільйонів операцій із рухомою комою, що робить цей підхід надто ресурсномістким для вбудованих польотних процесорів із тактовою частотою 200–480 МГц. Через це легкі комерційні автопілоти змушені використовувати прості квадратичні або експоненційні поля у парі з детекторами тупиків.

### Динамічна нестійкість та фазове запізнення в контурі керування

Окрім чисто геометричної рівноваги сил, у реальних безпілотниках виникає додатковий фізичний ефект — автоколивання через часову затримку в сенсорно-моторному контурі.

Кожен сенсор (лідар, стереокамера чи сонар) має затримку опитування та фільтрації `τ_delay` (зазвичай 30–80 мс від моменту фізичного відбиття променя до публікації точки у топіку автопілота). Коли дрон рухається до стіни зі швидкістю `v`, обчислювач формує відштовхувальну силу `F_rep(t)`, яка насправді відповідає положенню апарата у момент часу `t - τ_delay`:

```
m · p̈(t) + c · ṗ(t) = F_att(p(t)) + F_rep(p(t - τ_delay))
```

Розклавши запізнілий аргумент у ряд Тейлора `p(t - τ_delay) ≈ p(t) - τ_delay · ṗ(t)`, отримуємо лінеаризоване рівняння збуреного руху вздовж нормалі до стіни:

```
m · p̈(t) + (c - τ_delay · k_rep_grad) · ṗ(t) + (k_att + k_rep_grad) · p(t) = 0
```

де `k_rep_grad = ∂F_rep / ∂p` — крутість градієнта відштовхування біля стіни.

Якщо коефіцієнт відштовхування стіни або затримка сенсора занадто великі, ефективний коефіцієнт демпфування `(c - τ_delay · k_rep_grad)` стає від'ємним. Замість асимптотичного сповільнення система втрачає дисипативність і перетворюється на автогенератор незатухаючих коливань: дрон розгойдується всередині кишені зі зростаючою амплітудою, доки не вріжеться у фасад або не перейде у захисне аварійне відключення.

### Пастки методів простору швидкостей: DWA, VFH та Bug

Проблема локальних мінімумів притаманна не лише штучним потенціальним полям, а й іншим реактивним алгоритмам:

- **Підхід динамічного вікна (Dynamic Window Approach, DWA).** Алгоритм шукає допустимі дуги руху в просторі швидкостей `(v, ω)`, максимізуючи цільову функцію виду `G(v, ω) = α · heading + β · dist + γ · velocity`. Всередині U-подібної кишені функція має два симетричні локальні максимуми (поворот ліворуч уздовж лівої стінки або поворот праворуч уздовж правої). Через дискретність оцінки лідара на кожному такті (кожні 20–50 мс) переможець змінюється між лівою та правою дугою, змушуючи дрон безупинно перекладати рулі без реального просування вперед.
- **Гістограми векторного поля (Vector Field Histogram, VFH/VFH+).** Алгоритм перетворює карту зайнятості на полярну гістограму щільності перешкод і обирає найширший сектор із низькою щільністю, найближчий до азимуту цілі. Всередині кишені сектор, спрямований на ціль, заблокований дном кишені. Вільні бічні сектори ведуть у тупикові бічні кути. Увійшовши у бічний кут, алгоритм бачить, що сектор закрився, розвертається до протилежного кута і потрапляє у нескінченний цикл перебіжок.
- **Еластичні часові стрічки (Timed Elastic Band, TEB).** Алгоритм оптимізує послідовність просторово-часових конфігурацій за допомогою нелінійної оптимізації g2o. Всередині глибоких увігнутостей деформація стрічки блокується потенціальним бар'єром стін: якщо початкова ініціалізація потрапила всередину U-кишені, оптимізатор не може перестрибнути через бар'єр нескінченної вартості до альтернативного топологічного класу шляху (іншого гомотопічного класу `H-signature`) без явного глобального перезапуску.
- **Геометричні евристики Bug (Bug1, Bug2, TangentBug).** Хоча алгоритми Bug мають доведену властивість повноти (англ. *completeness*), їхня практична поведінка в складному лабіринті будівель є неефективною. Bug1 обходить повний периметр об'єкта перед тим, як полетіти до цілі, витрачаючи до 70% енергії батареї на зайвий кілометраж: довжина шляху оцінюється як `L ≤ L_direct + 1.5 · ∑ P_i`, де `P_i` — периметр `i`-ї перешкоди. Bug2 перетинає пряму лінію «старт—ціль» (m-line) і може багаторазово заходити в сусідні увігнуті закутки: верхня межа довжини становить `L ≤ L_direct + 0.5 · ∑ N_i · P_i`, де `N_i` — кількість перетинів лінії контуром перешкоди. На складних промислових спорудах із гребінчастою геометрією Bug2 вироджується у тривале блукання.

### Топологічні діаграми Вороного як захист від локальних мінімумів

Фундаментальною альтернативою реактивним полям є побудова узагальненої діаграми Вороного (англ. *Generalized Voronoi Diagram, GVD*). Діаграма Вороного розбиває простір на ребра, що проходять рівновіддалено від усіх навколишніх перешкод:

```
GVD = { p ∈ C_free : ∃ p_1, p_2 ∈ C_obs, p_1 ≠ p_2, ||p - p_1|| = ||p - p_2|| = dist(p, C_obs) }
```

Рух уздовж ребер GVD максимізує кліренс до стін і топологічно унеможливлює потрапляння всередину увігнутих кишень, якщо ціль розташована за межами перешкоди. Проте на відміну від локальних полів, GVD вимагає повної глобальної карти та значних обчислювальних ресурсів для тривимірної тріангуляції Делоне. Тому на борту легких БПЛА використовують гібридну схему: реактивний контролер веде апарат доти, доки детектор не зафіксує тупик, після чого ініціюється побудова топологічного скелета.

### Топологічні особливості 3D-простору та орієнтації

На відміну від наземних колісних платформ, для безпілотника простір конфігурацій є повнорозмірним `SE(3) = ℝ³ × SO(3)`.

У тривимірному просторі виникають унікальні типи локальних мінімумів:
1. **Нависаючі конструкції (Overhang Traps):** козирки дахів, кабельні естакади та мостові крани утворюють кишені, закриті зверху і з боків. Спроба виконати набір висоти всередині такої пастки без наявності верхнього далекоміра призводить до зіткнення з перекриттям.
2. **Пастки спрямованих сенсорів (Sensor Field-of-View Traps):** якщо дрон обладнано фронтальною стереокамерою з кутом огляду 90°, під час виконання розвороту вбік для обходу стіни перешкода виходить із поля зору камери. Обчислювач вважає, що передній простір очистився, повертає дрон назад до цілі й знову натикається на ту саму стіну. Виникає оптичний граничний цикл.
3. **Дзеркальне відбиття ультразвуку (Specular Reflection):** у кутах 90° акустичні хвилі сонарів відбиваються від першої стіни до другої й повертаються назад із подвійною затримкою. Сенсор повідомляє про дистанцію 4 метри замість реальних 2 метрів, через що автопілот влітає глибше в кут, ніж дозволяють безпечні ліміти.

## Розпізнавання глухого кута: як автопілот фіксує пастку

Щоб вчасно активувати процедуру порятунку, бортовий комп'ютер має виявити пастку ще до того, як вичерпається запас батареї.

Звичайна перевірка швидкості за модулем `||v|| < v_min` непридатна: дрон може законно зупинитися для зависання над проміжною точкою маршруту, під час очікування оператора або під час боротьби з сильним зустрічним вітром на відкритому просторі. Детектор глухого кута повинен враховувати просторовий напрямок руху, динаміку наближення до цілі та витрату керуючих зусиль.

```
                    ┌─────────────────────────┐
                    │    Поточний стан БПЛА   │
                    │   p(t), v(t), u_cmd(t)  │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │ Проекція швидкості на   │
                    │ напрямок цілі: v_prog   │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
     ┌───────────────────────┐       ┌───────────────────────┐
     │  Інтеграл наближення  │       │  Радіус дисперсії та  │
     │ I_prog(T) < δ_thresh  │       │ L_path / R_disp > 4.0 │
     └───────────┬───────────┘       └───────────┬───────────┘
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
                     ┌───────────────────────┐
                     │ Тяга активна:         │
                     │ ||u_cmd|| > u_min     │
                     └───────────┬────────────┘
                                 │
                                 ▼
                     ┌───────────────────────┐
                     │ ПАСТКУ ЗАФІКСОВАНО    │
                     │  (Stuck Confirmed)    │
                     └───────────────────────┘
```

### 1. Проекція швидкості та інтеграл наближення до цілі

Головною кінематичною метрикою є миттєва швидкість скорочення евклідової відстані до цільової точки `p_goal`.

Нехай поточне положення апарата є `p(t) ∈ ℝ³`, а вектор поточної швидкості — `v(t) = dp/dt`. Одиничний вектор прямої видимості на ціль:

```
e_goal(t) = (p_goal - p(t)) / ||p_goal - p(t)||
```

Миттєва швидкість прогресу `v_prog(t)` визначається як скалярний добуток вектора швидкості на одиничний вектор цілі:

```
v_prog(t) = v(t) · e_goal(t)
```

Якщо `v_prog(t) > 0`, апарат реально наближається до мети; якщо `v_prog(t) ≤ 0`, апарат або стоїть на місці, або рухається перпендикулярно, або віддаляється від цілі.

Для захисту від короткочасних шумів оцінювача стану обчислюється інтеграл корисного наближення на ковзному часовому вікні тривалістю `T` (зазвичай `T = 3.0…5.0` с):

```
I_prog(t, T) = ∫ max(0, v_prog(τ)) dτ    [інтегрування від τ = t - T до τ = t]
```

Якщо інтеграл корисного наближення за вікно `T` не перевищує порогової величини `δ_thresh` (наприклад, `δ_thresh = 0.2` м):

```
I_prog(t, T) < δ_thresh
```

і при цьому регулятор положення видає активну команду руху вперед `||u_cmd(t)|| > u_min` (тобто автопілот намагається летіти, а не виконує штатне зависання), реєструється перша ознака глухого кута.

### 2. Метрика просторової дисперсії та детекція автоколивань

Для виявлення коливальних пасток (коли швидкість `||v||` велика, але дрон кидається між стінами) обчислюються дві величини за вікно `T`:
1. Повна довжина пройденої просторової траєкторії:

```
L_path(t, T) = ∫ ||v(τ)|| dτ    [інтегрування від τ = t - T до τ = t]
```

2. Радіус дисперсії відносно середнього геометричного положення `p_mean`:

```
p_mean(t, T) = (1 / T) · ∫ p(τ) dτ
R_disp(t, T) = max ||p(τ) - p_mean(t, T)||    [для τ ∈ [t - T, t]]
```

У нормальному прямолінійному польоті зі швидкістю 3 м/с за час `T = 3` с довжина шляху `L_path ≈ 9` м, а радіус дисперсії `R_disp ≈ 4.5` м (відношення `L_path / R_disp ≈ 2.0`).

Якщо ж дрон застряг у коливальному циклі всередині кишені:
- Пройдений шлях залишається великим: `L_path > 4.0` м;
- Радіус зміщення залишається малим: `R_disp < 1.0` м;
- Відношення виродження перевищує критичний поріг:

```
L_path(t, T) / max(R_disp(t, T), 0.1) > 4.0
```

Це однозначно сигналізує про наявність стійкого граничного циклу.

### 3. Детектор зміни знака кутової швидкості (Zero-Crossing Rate)

Під час автоколивань у вузькому коридорі або кишені автопілот постійно перекладає кут рискання або крен. Швидкість зміни курсу `ψ̇(t)` здійснює високочастотні коливання навколо нуля.

Кількість переходів через нуль (англ. *Zero-Crossing Count, ZCC*) похідної курсу за вікно `T`:

```
ZCC(ψ̇, T) = ∑ [1, якщо sign(ψ̇(t_k)) ≠ sign(ψ̇(t_{k-1}))]
```

Якщо за 3 секунди кількість змін знака перевищує `ZCC ≥ 6` при радіусі дисперсії `R_disp < 1.5` м, бортовий контролер фіксує перехід у режим нестійких автоколивань.

### 4. Просторове хешування відвіданих вокселів

Додатковим незалежним індикатором слугує дискретний воксельний лічильник відвідувань. Простір розбивається на комірки розміром `Δr = 0.5` м. Бортовий алгоритм записує індекси зайнятих комірок у кільцевий буфер або хеш-таблицю. Якщо протягом вікна часу кількість входжень у вже відвідані вокселі перевищує 80% від загальної кількості відліків при відсутності скорочення дистанції до фінішу, фіксується потрапляння в замкнену топологічну пастку.

## Стратегії виходу з пастки

Після того як детектор підтвердив перебування в глухому куті, локальний реактивний контролер вимикається, і керування передається одній з відновлювальних стратегій. Вибір конкретної стратегії залежить від доступних сенсорів, розмірності простору та обмежень карти.

![Огляд стратегій виходу з глухого кута](/root/sys/sys-dron/hlukhyi-kut-i-pastka-lokalnoho-obkhodu/img/escape-strategies-overview.svg)
*Три стратегії виходу з увігнутої пастки: відкат назад по збережених точках, контурний обхід периметра та вертикальний набір висоти*

### 1. Відкат по історії траєкторії (Breadcrumb Backtracking)

Найбільш надійний та обчислювально легкий спосіб вибратися з кишені — повернутися тим самим безпечним коридором, через який дрон щойно потрапив усередину.

```
                    ┌─────────────────────────┐
                    │    Фіксація тупика      │
                    │    p_trap у точці p(t)  │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │  Вилучення вейпоінтів   │
                    │  з буфера крихт (FIFO)  │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │ Рух у реверсному        │
                    │ порядку до p_k          │
                    │ де dist(p_k, p_trap)>L  │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │ Досягнуто чистої зони:  │
                    │ виклик глобального A*   │
                    └─────────────────────────┘
```

**Механізм роботи:**
1. Під час штатного польоту автопілот безперервно записує координати `p(t)` у кільцевий буфер «хлібних крихт» (англ. *breadcrumb buffer*). Нова точка додається до буфера лише за умови, що евклідова відстань від попередньої збереженої точки перевищує `d_step` (наприклад, `d_step = 0.5` м). Це виключає захаращення буфера точками під час зависання.
2. При виявленні пастки точка входу в тупик позначається як `p_trap`.
3. Контролер формує реверсний маршрут, послідовно обираючи точки з буфера від кінця до початку: `p_{N}, p_{N-1}, p_{N-2}, …`.
4. Дрон рухається назад у зворотному напрямку, доки не віддалиться від точки пастки на безпечну відстань `L_backtrack` (зазвичай `L_backtrack = 3.0…6.0` м) або доки лідар не покаже відкриття бічного простору.
5. Зворотний рух виконується на зниженій швидкості (1.0…1.5 м/с) з орієнтацією курсу за вектором руху або задом наперед, якщо задня півсфера прикрита далекомірами.

Головна перевага відкату полягає в тому, що коридор повернення гарантовано вільний від статичних перешкод, адже дрон щойно безаварійно пролетів ним уперед.

### 2. Обхід контуру перешкоди (Wall-Following / Bug2)

Якщо відкат назад неможливий (наприклад, позаду рухається інший об'єкт або коридор заблоковано), застосовується маневр контурного обходу.

**Механізм формування вектора:**
1. За даними лідара або ультразвукових сенсорів визначається вектор нормалі `n_wall` до найближчої ділянки стіни.
2. Одиничний вектор дотичної до стіни `t_wall` обчислюється векторним добутком нормалі на вертикальний вектор осі `Z` (`e_z = [0, 0, 1]ᵀ`):

```
t_wall = n_wall × e_z    [для лівостороннього обходу]
t_wall = e_z × n_wall    [для правостороннього обходу]
```

3. Команда швидкості формується суперпозицією двох компонентів: руху вздовж дотичної `v_tangent` та корекції дистанції до стіни `v_dist`:

```
v_cmd = v_nominal · t_wall + k_dist · (d_current - d_desired) · n_wall
```

де `d_desired` — бажана відстань безпечного супроводу стіни (наприклад, 1.5 м), а `k_dist` — коефіцієнт пропорційного утримання дистанції.

**Умова виходу з режиму обходу (Leave Condition):**
Апарат продовжує слідувати вздовж периметра стіни доти, доки не буде виконано умову алгоритму Bug2:
- Дрон перетинає базову лінію між початковою точкою місії та фінішем (пряму `m-line`);
- Відстань від поточної точки до цілі `||p(t) - p_goal||` строго менша за відстань, яка була в момент потрапляння в пастку `||p_trap - p_goal|| - ε_margin`.

Після виконання цієї умови контурний обхід завершується, і автопілот повертається до прямого руху на ціль.

### 3. Вертикальний набір висоти (3D Altitude Escape)

На відміну від наземних колісних роботів, обмежених площиною `SE(2)`, безпілотні літальні апарати мають третій просторовий ступінь вільності `Z`.

У реальних умовах більшість штучних пасток (паркани, одноповерхові склади, будівельні паркани, контейнери, насипи) мають скінченну висоту `H_obs`. Локальний мінімум існує виключно як двовимірний переріз простору перешкод.

**Алгоритм 3D-маневру:**
1. Оцінюється наявність вільного простору зверху за допомогою верхнього далекоміра або 3D-лідара.
2. Якщо стеля вільна, поточні координати площини `(X, Y)` фіксуються, і видається команда вертикального набору висоти на величину:

```
Δz_escape = H_obs + H_margin
```

де `H_margin` — гарантований запас висоти над верхньою кромкою перешкоди (зазвичай 2.0…3.0 м).
3. Після виходу на безпечний висотний ешелон двовимірна кишеня перетворюється на плоску поверхню під дроном, локальний мінімум зникає, і апарат продовжує прямий рух до цільової точки на новій висоті.

### 4. Глобальне перепланування (Global Replanning)

Коли дрон успішно вийшов із зони безпосереднього заклинювання (завдяки відкату або контурному руху), повертатися до попереднього локального плану не можна: реактивний алгоритм знову потягне апарат у ту саму кишеню.

Необхідно оновити карту та запустити глобальний алгоритм планування:
1. Виявлене заглиблення штучно маркується у глобальній сітці вартостей (англ. *Global Costmap* / *OctoMap*) як область із максимальною вартістю (англ. *Lethal Obstacle* / інфляція вартості).
2. Запускається топологічний або графовий планувальник (A*, Jump Point Search, D* Lite або RRT*), який враховує всю накопичену форму перешкоди.
3. Глобальний планувальник прокладає макрошлях в обхід усієї структури будівлі, і локальний контролер отримує нову серію проміжних вейпоінтів, що оминають пастку заздалегідь.

## Архітектура автомата станів та інтеграція в дерево поведінки

Для безшовної взаємодії між штатним польотом та аварійними підпрограмами порятунку навігаційний стек організовується у вигляді скінченного автомата станів (англ. *Finite State Machine, FSM*) або піддерева поведінки (англ. *Behavior Tree*).

```
                        ┌─────────────────────────┐
                        │       NAVIGATING        │
                        │    (Штатний політ)      │
                        └────────────┬────────────┘
                                     │ Stuck detected
                                     ▼
                        ┌─────────────────────────┐
                        │     STUCK_CONFIRMED     │
                        │  (Зупинка, аналіз 3D)   │
                        └──────┬───────┬───────┬──┘
                               │       │       │
             Верх вільний      │       │       │ Немає крихт
             ┌─────────────────┘       │       └────────────────┐
             ▼                         ▼                        ▼
  ┌─────────────────────┐   ┌─────────────────────┐   ┌─────────────────────┐
  │   VERTICAL_ESCAPE   │   │  BACKTRACK_HISTORY  │   │    WALL_FOLLOWING   │
  │   (Набір висоти)    │   │  (Відкат за FIFO)   │   │   (Обхід контуру)   │
  └──────────┬──────────┘   └──────────┬──────────┘   └──────────┬──────────┘
             │                         │                         │
             │ Висота досягнута        │ Відкат завершено        │ Умова виходу Bug2
             └─────────────────┬───────┴─────────────────────────┘
                               ▼
                    ┌─────────────────────────┐
                    │      REPLAN_GLOBAL      │
                    │   (Оновлення Costmap)   │
                    └────────────┬────────────┘
                                 │ Новий шлях знайдено
                                 ▼
                    ┌─────────────────────────┐
                    │       NAVIGATING        │
                    │   (Продовження місії)   │
                    └─────────────────────────┘
```

Для запобігання хибним спрацьовуванням та частим перемиканням режимів (англ. *flapping*) автомат використовує два таймери гістерезису:
- **Таймер підтвердження тупика (`t_stuck_confirm = 2.5` с):** умови браку прогресу мають безперервно виконуватися протягом усього інтервалу;
- **Таймер блокування повторного входу (`t_cooldown = 5.0` с):** після успішного виходу з пастки та глобального перепланування детектор блокує нове спрацьовування на час розгону, щоб уникнути помилкового тривожного сигналу під час зміни курсу.

### Інтеграція з польотними стеками PX4 та ArduPilot

У реальних польотних стеках взаємодія між локальним обходом перешкод та аварійним відновленням спирається на стандартизовані MAVLink-повідомлення та параметри конфігурації:
- **Повідомлення `OBSTACLE_DISTANCE`:** бортовий компаньйон-комп'ютер передає у польотний контролер 72-секторну або 36-променеву карту відстаней у площині обертання дрона.
- **Параметри PX4 Collision Prevention:** параметри `CP_DIST` (мінімальна дистанція зупинки) та `MPC_COL_PREV_D` (радіус зони уповільнення) обмежують швидкість наближення. Коли дрон зупиняється на дистанції `CP_DIST`, стан застрягання фіксується внутрішнім таймером `NAV_GPS_TAKEOFF`.
- **Параметри ArduPilot Object Avoidance:** параметри `OA_TYPE = 2` (Dijkstra/Bendyruler) та `OA_LOOKAHEAD` (горизонт передбачення) намагаються обійти кути перешкоди заздалегідь. Якщо параметр `OA_BR_TYPE = 1` не знаходить вільного проходу, автопілот переходить у стан зависання `BRAKE`, очікуючи команди від вищого рівня автономності.

### Політика безпеки та багаторівневий Failsafe

Якщо виконання первинного маневру порятунку не привело до відновлення прогресу або якщо вихідний коридор виявився заблокованим динамічною перешкодою, система застосовує ступеневу ескалацію безпеки:
1. **Рівень 1 (Кінематичний відкат):** реверс на 4.5 м по крихтах FIFO.
2. **Рівень 2 (Контурне огинання або набір висоти):** слідування вздовж периметра до перетину лінії m-line або підйом на 3 м угору.
3. **Рівень 3 (Глобальне перепланування з інфляцією):** очищення локального кешу та прокладання обхідного макромаршруту графовим планувальником.
4. **Рівень 4 (Аварійний Failsafe):** якщо після 3 спроб за час `t_timeout > 30.0` с дрон залишається заблокованим, активується режим аварійного повернення додому (RTL) на максимальному безпечному ешелоні (наприклад, 50 м) або екстрена керована посадка на відкритому п'ятачку.

#include <stdbool.h>
#include <stdint.h>
#include <math.h>
#include <string.h>

#define BREADCRUMB_CAPACITY 128
#define PROGRESS_WINDOW_SIZE 50

typedef struct {
    float x;
    float y;
    float z;
} Vector3f;

typedef enum {
    NAV_STATE_NORMAL = 0,
    NAV_STATE_STUCK_DETECTED,
    NAV_STATE_BACKTRACKING,
    NAV_STATE_REPLAN_TRIGGERED
} NavEscapeState;

typedef struct {
    Vector3f buffer[BREADCRUMB_CAPACITY];
    uint16_t head;
    uint16_t count;
    float min_dist_sq;
} BreadcrumbTracker;

typedef struct {
    float progress_history[PROGRESS_WINDOW_SIZE];
    uint8_t window_idx;
    uint8_t window_filled;
    float window_dt;
    float progress_threshold;
    float max_dispersion_ratio;
    
    BreadcrumbTracker crumbs;
    NavEscapeState state;
    uint16_t backtrack_target_idx;
    float backtrack_dist_accum;
    float backtrack_required_dist;
    float cooldown_timer;
} LocalMinimaEscapeDetector;

static inline float vec3_dist_sq(const Vector3f* a, const Vector3f* b) {
    float dx = a->x - b->x;
    float dy = a->y - b->y;
    float dz = a->z - b->z;
    return dx * dx + dy * dy + dz * dz;
}

static inline float vec3_dist(const Vector3f* a, const Vector3f* b) {
    return sqrtf(vec3_dist_sq(a, b));
}

void escape_detector_init(LocalMinimaEscapeDetector* det, float dt) {
    memset(det, 0, sizeof(LocalMinimaEscapeDetector));
    det->window_dt = dt;
    det->progress_threshold = 0.25f;       /* мінімум 25 см прогресу за вікно */
    det->max_dispersion_ratio = 4.0f;       /* поріг детекції коливань */
    det->crumbs.min_dist_sq = 0.25f;       /* запис крихти кожні 0.5 м */
    det->backtrack_required_dist = 4.0f;    /* відкат на 4 метри назад */
    det->state = NAV_STATE_NORMAL;
}

void breadcrumb_push(BreadcrumbTracker* bt, const Vector3f* pos) {
    if (bt->count > 0) {
        uint16_t last_idx = (bt->head + BREADCRUMB_CAPACITY - 1) % BREADCRUMB_CAPACITY;
        if (vec3_dist_sq(&bt->buffer[last_idx], pos) < bt->min_dist_sq) {
            return;
        }
    }
    bt->buffer[bt->head] = *pos;
    bt->head = (bt->head + 1) % BREADCRUMB_CAPACITY;
    if (bt->count < BREADCRUMB_CAPACITY) {
        bt->count++;
    }
}

bool escape_detector_update(LocalMinimaEscapeDetector* det,
                            const Vector3f* cur_pos,
                            const Vector3f* cur_vel,
                            const Vector3f* goal_pos,
                            bool active_thrust,
                            Vector3f* out_setpoint) {
    if (det->cooldown_timer > 0.0f) {
        det->cooldown_timer -= det->window_dt;
    }

    if (det->state == NAV_STATE_NORMAL) {
        breadcrumb_push(&det->crumbs, cur_pos);

        /* 1. Розрахунок проекції швидкості на промінь до цілі */
        float to_goal_x = goal_pos->x - cur_pos->x;
        float to_goal_y = goal_pos->y - cur_pos->y;
        float to_goal_z = goal_pos->z - cur_pos->z;
        float dist_goal = sqrtf(to_goal_x * to_goal_x + to_goal_y * to_goal_y + to_goal_z * to_goal_z);

        float v_prog = 0.0f;
        if (dist_goal > 0.001f) {
            v_prog = (cur_vel->x * to_goal_x + cur_vel->y * to_goal_y + cur_vel->z * to_goal_z) / dist_goal;
        }

        det->progress_history[det->window_idx] = (v_prog > 0.0f) ? (v_prog * det->window_dt) : 0.0f;
        det->window_idx = (det->window_idx + 1) % PROGRESS_WINDOW_SIZE;
        if (det->window_idx == 0) {
            det->window_filled = 1;
        }

        /* 2. Аналіз накопиченого корисного прогресу */
        if (det->window_filled && det->cooldown_timer <= 0.0f && active_thrust) {
            float total_prog = 0.0f;
            for (int i = 0; i < PROGRESS_WINDOW_SIZE; ++i) {
                total_prog += det->progress_history[i];
            }

            if (total_prog < det->progress_threshold && det->crumbs.count > 4) {
                det->state = NAV_STATE_STUCK_DETECTED;
                det->backtrack_dist_accum = 0.0f;
                det->backtrack_target_idx = (det->crumbs.head + BREADCRUMB_CAPACITY - 1) % BREADCRUMB_CAPACITY;
            }
        }
        return false;
    }

    if (det->state == NAV_STATE_STUCK_DETECTED || det->state == NAV_STATE_BACKTRACKING) {
        det->state = NAV_STATE_BACKTRACKING;

        if (det->crumbs.count == 0) {
            det->state = NAV_STATE_REPLAN_TRIGGERED;
            return true;
        }

        Vector3f target_wp = det->crumbs.buffer[det->backtrack_target_idx];
        *out_setpoint = target_wp;

        float dist_to_wp = vec3_dist(cur_pos, &target_wp);
        if (dist_to_wp < 0.6f) {
            det->backtrack_dist_accum += dist_to_wp;
            if (det->crumbs.count > 1) {
                det->backtrack_target_idx = (det->backtrack_target_idx + BREADCRUMB_CAPACITY - 1) % BREADCRUMB_CAPACITY;
                det->crumbs.count--;
            } else {
                det->crumbs.count = 0;
            }
        }

        if (det->backtrack_dist_accum >= det->backtrack_required_dist || det->crumbs.count == 0) {
            det->state = NAV_STATE_REPLAN_TRIGGERED;
            det->cooldown_timer = 5.0f;
            return true;
        }
    }

    return false;
}

#include <array>
#include <cmath>
#include <cstdint>
#include <optional>
#include <span>

struct Vector3f {
    float x{0.0F};
    float y{0.0F};
    float z{0.0F};

    [[nodiscard]] constexpr float dist_sq(const Vector3f& other) const noexcept {
        const float dx = x - other.x;
        const float dy = y - other.y;
        const float dz = z - other.z;
        return (dx * dx) + (dy * dy) + (dz * dz);
    }

    [[nodiscard]] float dist(const Vector3f& other) const noexcept {
        return std::sqrt(dist_sq(other));
    }
};

enum class NavEscapeState : uint8_t {
    Normal = 0,
    StuckDetected,
    Backtracking,
    ReplanTriggered
};

template <size_t Capacity>
class BreadcrumbTracker {
public:
    explicit constexpr BreadcrumbTracker(float min_step = 0.5F) noexcept
        : min_dist_sq_(min_step * min_step) {}

    void push(const Vector3f& pos) noexcept {
        if (count_ > 0) {
            const size_t last_idx = (head_ + Capacity - 1) % Capacity;
            if (buffer_[last_idx].dist_sq(pos) < min_dist_sq_) {
                return;
            }
        }
        buffer_[head_] = pos;
        head_ = (head_ + 1) % Capacity;
        if (count_ < Capacity) {
            ++count_;
        }
    }

    [[nodiscard]] size_t count() const noexcept { return count_; }
    [[nodiscard]] size_t head() const noexcept { return head_; }

    [[nodiscard]] std::optional<Vector3f> pop_back(size_t& current_idx) noexcept {
        if (count_ == 0) {
            return std::nullopt;
        }
        const Vector3f pt = buffer_[current_idx];
        current_idx = (current_idx + Capacity - 1) % Capacity;
        --count_;
        return pt;
    }

    [[nodiscard]] const Vector3f& at(size_t idx) const noexcept {
        return buffer_[idx % Capacity];
    }

private:
    std::array<Vector3f, Capacity> buffer_{};
    size_t head_{0};
    size_t count_{0};
    float min_dist_sq_{0.25F};
};

class LocalMinimaEscapeDetector {
public:
    static constexpr size_t kHistoryWindow = 50;
    static constexpr size_t kCrumbCapacity = 128;

    explicit LocalMinimaEscapeDetector(float dt) noexcept
        : window_dt_(dt) {}

    bool update(const Vector3f& cur_pos,
                const Vector3f& cur_vel,
                const Vector3f& goal_pos,
                bool active_thrust,
                Vector3f& out_setpoint) noexcept {
        if (cooldown_timer_ > 0.0F) {
            cooldown_timer_ -= window_dt_;
        }

        if (state_ == NavEscapeState::Normal) {
            crumbs_.push(cur_pos);

            const Vector3f to_goal{goal_pos.x - cur_pos.x, goal_pos.y - cur_pos.y, goal_pos.z - cur_pos.z};
            const float dist_goal = std::sqrt(to_goal.x * to_goal.x + to_goal.y * to_goal.y + to_goal.z * to_goal.z);

            float v_prog = 0.0F;
            if (dist_goal > 1e-3F) {
                v_prog = (cur_vel.x * to_goal.x + cur_vel.y * to_goal.y + cur_vel.z * to_goal.z) / dist_goal;
            }

            progress_history_[window_idx_] = (v_prog > 0.0F) ? (v_prog * window_dt_) : 0.0F;
            window_idx_ = (window_idx_ + 1) % kHistoryWindow;
            if (window_idx_ == 0) {
                window_filled_ = true;
            }

            if (window_filled_ && cooldown_timer_ <= 0.0F && active_thrust) {
                float total_prog = 0.0F;
                for (const float step : progress_history_) {
                    total_prog += step;
                }

                if (total_prog < progress_threshold_ && crumbs_.count() > 4) {
                    state_ = NavEscapeState::StuckDetected;
                    backtrack_dist_accum_ = 0.0F;
                    backtrack_target_idx_ = (crumbs_.head() + kCrumbCapacity - 1) % kCrumbCapacity;
                }
            }
            return false;
        }

        if (state_ == NavEscapeState::StuckDetected || state_ == NavEscapeState::Backtracking) {
            state_ = NavEscapeState::Backtracking;

            if (crumbs_.count() == 0) {
                state_ = NavEscapeState::ReplanTriggered;
                return true;
            }

            const Vector3f target_wp = crumbs_.at(backtrack_target_idx_);
            out_setpoint = target_wp;

            const float dist_to_wp = cur_pos.dist(target_wp);
            if (dist_to_wp < 0.6F) {
                backtrack_dist_accum_ += dist_to_wp;
                if (crumbs_.count() > 1) {
                    backtrack_target_idx_ = (backtrack_target_idx_ + kCrumbCapacity - 1) % kCrumbCapacity;
                }
                auto popped = crumbs_.pop_back(backtrack_target_idx_);
                (void)popped;
            }

            if (backtrack_dist_accum_ >= backtrack_required_dist_ || crumbs_.count() == 0) {
                state_ = NavEscapeState::ReplanTriggered;
                cooldown_timer_ = 5.0F;
                return true;
            }
        }

        return false;
    }

    [[nodiscard]] NavEscapeState state() const noexcept { return state_; }
    void reset_to_normal() noexcept { state_ = NavEscapeState::Normal; }

private:
    float window_dt_{0.02F};
    float progress_threshold_{0.25F};
    float backtrack_required_dist_{4.0F};
    float cooldown_timer_{0.0F};

    std::array<float, kHistoryWindow> progress_history_{};
    size_t window_idx_{0};
    bool window_filled_{false};

    BreadcrumbTracker<kCrumbCapacity> crumbs_{0.5F};
    NavEscapeState state_{NavEscapeState::Normal};
    size_t backtrack_target_idx_{0};
    float backtrack_dist_accum_{0.0F};
};
