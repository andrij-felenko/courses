</preknowlist>

Коли інженерна команда розробляє лінійку автономних безпілотних платформ — мультикоптер спостереження для міських умов, далекомагістральне розвідувальне крило, важкий вантажний VTOL-конвертоплан для міжбазової логістики, колісний ровер для патрулювання периметра та підводний апарат для огляду гідротехнічних споруд, — найперша інтуїтивна спроба полягає у створенні окремої спеціалізованої прошивки під кожен тип планера. Літаку потрібні алгоритми тримання глісади, автокоординація віражу кермом напрямку та управління тягою маршового двигуна; коптеру — кілогерцовий ПІД-регулятор кутових швидкостей із розкладкою на чотири симетричні мотори; конвертоплану — складна нелінійна кінематика нахилу мотогондол; роверу — диференціальне керування швидкістю бортів; а підводному апарату — стабілізація глибини за гідростатичним тиском.

Такий підхід швидко заводить інженерію в глухий кут комбінаторного множення дефектів. Понад 80% кодової бази будь-якого автономного робота взагалі не залежать від форми його рами чи середовища руху. Опитування первинних інерційних давачів по шині SPI на частоті 8 кГц, смугова та режекторна цифрова фільтрація вібраційного шуму, зведення спостережень у 24-вимірному розширеному фільтрі Калмана (EKF), диспетчеризація пакетів телеметрії MAVLink, запис високочастотних польотних логів на карту пам'яті, планування просторових місій за геодезичними точками та безпекова логіка аварійних повернень при відмові зв'язку (failsafe) є абсолютно ідентичними для літака, коптера, конвертоплана, ровера й підводного човна. Якщо кожен тип платформи живе у власному форку прошивки, будь-яке виправлення математичної похибки в матрицях коваріації навігаційного фільтра чи оптимізація драйвера магнітометра вимагає ручного перенесення в п'ять різних репозиторіїв та п'ятикратного повторення циклу випробувань.

Сучасні автопілоти промислового рівня (зокрема PX4 Autopilot та ArduPilot) вирішують цю проблему через впровадження уніфікованої модульної архітектури **«один стек — багато тіл»** (англ. *one stack — many airframes*). Уся система розбивається на чітку ієрархію функціональних шарів: верхні контури навігації, оцінювання стану та стабілізації оперують абстрактними фізичними силами й моментами, повністю абстрагуючись від конструкції рами, а вся специфіка конкретного планера інкапсулюється в єдиному ізольованому шарі — підсистемі **розподілу керування (Control Allocation & Mixing)**.

## Чотирирівневий конвеєр абстракції від планера

Уніфікований польотний стек побудований як строго детермінований конвеєр обробки інформації, розділений на чотири функціональні рівні з фіксованими інтерфейсними контрактами між ними.

![Уніфікована архітектура польотного стека](/root/sys/sys-dron/one-stack-many-bodies/img/architecture-layers.svg)
*Архітектурний конвеєр польотного стека: від уніфікованих шарів первинної обробки давачів, EKF та регуляторів до планерно-залежного розподілу керування.*

### 1. Рівень первинної обробки давачів (Sensor Processing)

На найнижчому рівні драйвери апаратних шин (SPI, I2C, UART, CAN/DroneCAN) опитують первинні бортові сенсори з різними детермінованими періодами. Гіроскопи та акселерометри (IMU) опитуються на частотах від 1 до 8 кГц; барометричний висотомір — на частотах 50–100 Гц; тривісний магнітометр (компас) — на частотах 50–100 Гц; супутниковий приймач GNSS — на частотах 5–10 Гц; давач диференціального тиску (трубка Піто) — на частоті 50 Гц; а лазерні чи оптичні далекоміри — на частотах 20–50 Гц.

Цей шар виконує критичну первинну математичну підготовку сигналів:
- усуває статичні та температурні зміщення нульового рівня (gyro/accel bias);
- застосовує калібрувальні матриці масштабних коефіцієнтів і неколінеарності осей;
- здійснює компенсацію магнітних девіацій від силових струмів акумулятора (hard-iron та soft-iron компенсація);
- фільтрує механічні вібрації від обертання моторів за допомогою цифрових фільтрів низьких частот другого порядку (Butterworth) та динамічних адаптивних режекторних фільтрів (Notch Filters), частота яких у реальному часі підлаштовується під швидкість обертання кожного пропелера за даними ESC-телеметрії (RPM feedback).

Первинні сенсори не знають форми планера: вони вимірюють сирі кінематичні величини (кутову швидкість, лінійне прискорення, тиск, напруженість магнітного поля) у власній конструктивній системі координат сенсорного модуля.

### 2. Рівень оцінювання навігаційного стану (State Estimation)

Серцем навігаційного ядра є [розширений фільтр Калмана (EKF2 / EKF3)](root:sys-dron/px4-architecture). Фільтр підтримує 24-вимірний вектор стану, що повністю описує просторовий рух твердого тіла:
- тривимірне положення `[X, Y, Z]` у географічній системі координат NED (North-East-Down);
- вектор лінійної швидкості `[V_n, V_e, V_d]`;
- просторову орієнтацію апарата у формі [одиничного кватерніона `q = [q0, q1, q2, q3]`](root:sys-dron/quaternion-attitude-control);
- тривимірні вектори зсуву нулів гіроскопів (gyro bias) та акселерометрів (accel bias);
- вектор швидкості горизонтального вітру `[W_n, W_e]`;
- просторові компоненти магнітного поля Землі та локальні бортові магнітні аномалії.

Оцінювач стану працює з математичною моделлю твердого тіла, масою `m` і тензором інерції `J`. Йому байдуже, чи створюється підйомна сила гвинтами, чи крилом: фільтр лише зважує передбачення кінематичної моделі проти свіжих спостережень давачів відповідно до їхніх матриць коваріації шумів.

### 3. Рівень траєкторного планування та навігації (Guidance & Navigation)

Модулі автономної навігації зіставляють поточну оцінку стану з польотною місією (маршрутними точками, коридорами геофенсингу, областями автоматичного картографування чи траєкторіями заходу на посадку). Використовуючи геометричні алгоритми наведення ([навігацію pure pursuit](root:sys-dron/pure-pursuit-navigation) або векторне ведення L1/NPFG), модуль обчислює необхідну просторову траєкторію та транслює її в бажаний вектор лінійного прискорення `a_des` або бажаний вектор швидкості `v_des`.

### 4. Рівень каскадних регуляторів орієнтації (Attitude & Rate Control)

Зовнішній контур стабілізації орієнтації обчислює просторову похибку між поточною орієнтацією та цільовим положенням, формуючи бажаний вектор кутової швидкості `ω_des = [p_des, q_des, r_des]ᵀ`.

Внутрішній контур регулювання кутових швидкостей працює з найвищим пріоритетом реального часу на частотах 400–1000 Гц. Швидкісний ПІД-регулятор порівнює `ω_des` із виміряною гіроскопом кутовою швидкістю `ω` та формує **узагальнений вектор віртуальних зусиль (wrench)** у зв'язаній системі координат FRD (Forward-Right-Down):

```
τ_sp = [F_x, F_y, F_z, M_x, M_y, M_z]ᵀ
```

де `F_x, F_y, F_z` — необхідні головні сили (Ньютони), а `M_x, M_y, M_z` — відновлювальні моменти сил навколо осей крену (Roll), тангажу (Pitch) та рискання (Yaw) (Н·м).

Вектор `τ_sp` є строгою **інтерфейсною межею абстракції**. Усі рівні вище цієї лінії нічого не знають про кількість моторів, кути нахилу балок чи площу елеронів. Уся специфіка механіки конкретної рами інкапсульована нижче — у підсистемі **розподілу керування (Control Allocation)** та апаратних драйверах приводів.

## Фізика та механіка різних планерів

Щоб зрозуміти, як єдиний інтерфейс `τ_sp` обслуговує кардинально відмінні апарати, порівняємо фізичні механізми створення сил і моментів на основних класах безпілотних платформ.

![Фізичні механізми створення сил і моментів](/root/sys/sys-dron/one-stack-many-bodies/img/airframe-physics-comparison.svg)
*Порівняння фізики чотирьох класів планерів: пряма тяга роторів, аеродинамічні сили крила, роздільна тяга QuadPlane та векторизація тяги поворотних гондол.*

### Мультиротори (Multi-Rotor)

Мультикоптер спирається на пряме векторне керування тягою кількох фіксованих пропелерів. Сумарна сила тяги спрямована строго вздовж від'ємної вертикальної осі Z планера:

```
F_z = -Σ T_i,    де T_i = c_t,i · Ω_i²
```

де `c_t,i` — коефіцієнт тяги пропелера, а `Ω_i` — кутова швидкість обертання `i`-го ротора.

Моменти крену `M_x` та тангажу `M_y` створюються диференціальною зміною тяги між протилежними моторами через геометричні плечі їхнього вильоту `r_i = [x_i, y_i, z_i]ᵀ` від центру мас. Момент рискання `M_z` створюється не силами тяги, а [реактивним крутним моментом](root:ph-mechanics/torque) аеродинамічного опору обертання лопатей:

```
M_z = Σ (d_i · c_m,i · Ω_i²)
```

де `d_i = +1` для гвинтів, що обертаються проти годинникової стрілки (CCW), і `d_i = -1` для гвинтів за годинниковою стрілкою (CW), а `c_m,i` — коефіцієнт реактивного моменту.

Мультиротор статично нестійкий: без безперервної стабілізації з частотою щонайменше 400 Гц він миттєво втрачає орієнтацію й перевертається. Горизонтальні сили `F_x, F_y` не можуть генеруватися прямо: щоб летіти вперед або вбік, коптер змушений нахиляти весь свій корпус, проєктуючи вектор тяги `F_z` на горизонт.

### Літаки класичної схеми (Fixed-Wing)

Класичний літак створює підйомну силу виключно за рахунок обтікання нерухомого профілю крила повітряним потоком з індикаторною швидкістю `V_ias`:

```
L = 0.5 · ρ · V_ias² · S · C_L(α)
```

де `ρ` — густина повітря, `S` — площа крила, а `C_L(α)` — коефіцієнт підйомної сили при поточному куті атаки `α`.

Керуючі моменти сил генеруються аеродинамічними рульовими поверхнями:
- **Елерони (Ailerons, `δ_a`):** диференціально змінюють підйомну силу лівого та правого напівкрил, створюючи момент крену `M_x`.
- **Кермо висоти (Elevator, `δ_e`):** змінює силу на горизонтальному стабілізаторі хвоста, створюючи момент тангажу `M_y`.
- **Кермо напрямку (Rudder, `δ_r`):** створює бічну аеродинамічну силу на кілі, формуючи момент рискання `M_z`.
- **Маршовий двигун (Pusher / Puller):** створює поздовжню тягу вперед `F_x`.

Ефективність усіх рульових поверхонь строго пропорційна швидкісному напору `q = 0.5 · ρ · V_ias²`. На низькій швидкості літак втрачає керованість, а нижче швидкості звалювання `V_stall` настає повний зрив потоку з крила. Літак не здатний зависати на місці, а будь-який розворот вимагає узгодженого створення крену та підтягування керма висоти для компенсації втрати вертикальної проєкції підйомної сили (координований віраж).

### Апарати вертикального зльоту та посадки (VTOL)

VTOL-конфігурації об'єднують переваги зависання мультикоптера та швидкісного енергоефективного польоту літака:

1. **QuadPlane (Separate Lift + Thrust / SLT):** Схема з роздільними рушіями. До літакового планера додаються поздовжні балки з 4 незалежними вертикальними моторами плюс один маршовий штовхаючий або тягнучий двигун. На зльоті та посадці літак поводиться як чистий квадрокоптер; у крейсерському польоті 4 підйомні мотори повністю зупиняються, а рух забезпечується крилом і маршовим мотором. Перевага — простота керування та відсутність рухомих поворотних вузлів. Недолік — постійна мертва вага та паразитний лобовий опір непрацюючих роторів у крейсерському польоті, що забирає 20–30% дальності.
2. **Tailsitter (посадка на хвіст):** Апарат не має окремих моторів для зависання. На старті він стоїть вертикально на хвостовому оперенні, спрямовуючи тягу двигунів у зеніт. Після набору висоти літак нахиляє ніс на 90° вперед, переходячи в горизонтальний політ. Перевага — мінімальна конструктивна маса. Недоліки — висока вразливість до бічного вітру на зависанні (величезне крило працює як вітрило) та необхідність безангулярного кватерніонного перерахунку орієнтації при зміні тангажу на 90°. На зависанні елевони працюють виключно за рахунок обдування від пропелерів (propwash), тому ефективна швидкість потоку на рулях визначається швидкістю струменя гвинта `V_eff ≈ sqrt(V_ias² + 2·T / (ρ·A))`, а не швидкістю руху апарата.
3. **Tilt-Rotor / Tilt-Wing (поворотні гвинти або крила):** Мотогондоли або крило разом із моторами повертаються потужними сервоприводами на кут `θ_tilt ∈ [0°, 90°]`. При `θ_tilt = 90°` тяга спрямована вертикально (зависання); при `θ_tilt = 0°` — горизонтально (літак). Усі мотори беруть участь у створенні підйомної сили на зльоті та забезпечують рух уперед у крейсерському режимі. Плата за це — висока механічна складність поворотних шарнірів, гіроскопічна прецесія пропелерів при швидкому нахилі (`M_gyro = I_prop · (ω_tilt × Ω)`) та сильна нелінійна міжкоординатна зв'язаність у перехідній фазі.

### Наземні, надводні та підводні платформи

Та сама архітектура без змін інтегрує інші типи рухомих роботів:
- **Колісний ровер (Rover) / Човен (Boat):** Двовимірний рух на площині. Для гусеничного чи диференціального колісного шасі (Skid-Steer) вектор керування містить лише поздовжню силу `F_x = F_left + F_right` та момент розвороту `M_z = (F_left - F_right) · d/2`. Для схеми з кермовим приводом Аккермана керування розпадається на швидкість маршового мотора та кут повороту коліс.
- **Підводний апарат (ROV / Submarine / AUV):** Шестивимірний рух (6-DOF) у водному середовищі. Використовується просторовий комплекс із 6–8 векторних водонепроникних рушіїв (трастерів). Шар розподілу компенсує статичну плавучість корпусу, враховує пасивний відновлювальний момент метацентричної висоти `M_restoring = m · g · GM · sin(φ)`, квадратичний гідродинамічний опір та велику приєднану масу води, яка збільшує ефективну інерцію апарата у 1.5–2 рази.

## Динаміка перехідного режиму VTOL (Transition Phase)

Найбільш витонченим завданням уніфікованого польотного стека є управління перехідним режимом (Transition Phase) гібридних літальних апаратів.

![Динаміка перехідного режиму VTOL](/root/sys/sys-dron/one-stack-many-bodies/img/vtol-transition-dynamics.svg)
*Динаміка прямого переходу VTOL: квадратичний перерозподіл ваги між підйомними моторами T_hover та крилом L(V) забезпечує незмінну висоту.*

### Прямий перехід (Forward Transition: Hover → Fixed-Wing)

Прямий перехід виконується у чотири строго узгоджені фази:

1. **Фаза ініціації та розгону (`0 ≤ V_ias < V_min`):** Апарат зависає на заданій висоті переходу (зазвичай 30–50 м). Автопілот активує маршовий двигун на 60–80% потужності (для QuadPlane) або починає плавний нахил мотогондол на перші 15–20° (для Tilt-Rotor). Повітряна швидкість починає лінійно наростати. Підйомні мотори несуть 100% ваги літака та здійснюють повну кутову стабілізацію за всіма трьома осями.
2. **Фаза динамічного квадратичного блендингу (`V_min ≤ V_ias ≤ V_trans`):** У міру розгону швидкісний напір `q = 0.5 · ρ · V_ias²` зростає. Крило починає генерувати підйомну силу `L(V_ias)`. Одночасно зростає ефективність елеронів, керма висоти й напрямку. Шар розподілу керування обчислює безрозмірний ваговий коефіцієнт літакового режиму `w_fw(V_ias)`:

```
w_fw(V_ias) = (V_ias² - V_min²) / (V_trans² - V_min²)
```

Тяга підйомних моторів примусово зменшується за комплементарним законом:

```
T_hover(V_ias) = m · g · (1.0 - w_fw(V_ias))
```

Оскільки підйомна сила крила росте пропорційно квадрату швидкості, сума сил `T_hover(V_ias) + L(V_ias)` залишається абсолютно незмінною і точно дорівнює повній вазі апарата `m · g`. Апарат утримує горизонтальну траєкторію без просідання чи здирання носа. Повний математичний розбір динаміки та профілювання тангажу наведено у вставці [математичний розбір перехідних кривих та вагового блендингу](root:sys-dron/one-stack-many-bodies/math-vtol-transition-blending.md).
3. **Фаза підтвердження швидкості (`V_ias ≥ V_trans`):** Швидкість досягає безпечного порогу `V_trans = 1.2 · V_stall`. Контролер запускає таймер підтвердження стабільності (зазвичай 1.5–2.0 секунди), перевіряючи, що швидкість не падає через випадкові пориви зустрічного вітру.
4. **Знеструмлення роторів:** Підйомні мотори повністю вимикаються, а їхні пропелери складаються потоком. Керування орієнтацією на 100% передається на аеродинамічні рулі. Літак переходить у повноцінний крейсерський режим.

### Зворотний перехід (Back-Transition: Fixed-Wing → Hover)

Зворотний перехід перед посадкою є найбільш критичним за часом процесом:

1. **Гальмування планера:** Маршова тяга скидається в нуль. Літак виконує невелике кабельрування (підйом носа на `+5° .. +10°` тангажу) для створення аеродинамічного гальмування та гасіння горизонтальної кінетичної енергії.
2. **Випереджальна розкрутка підйомних моторів:** Доки повітряна швидкість не опустилася нижче порогу звалювання (`V_ias ≈ 1.2 · V_stall`), підйомні мотори вмикаються на холості оберти (idle speed), виходячи на робочу готовність за час розкрутки `t_spinup ≈ 0.3 .. 0.5 с`.
3. **Зворотний блендинг:** У міру сповільнення ротори плавно нарощують тягу від 0% до 100%, компенсуючи зникаючу підйомну силу крила. Коли `V_ias < V_min`, літак остаточно зависає на місці та переходить у режим вертикальної посадки.

### Захисна логіка відмов у перехідному режимі

У реальних польотах перехідний режим стикається з критичними зовнішніми факторами:
- **Засмічення або обмерзання трубки Піто:** Якщо давач повітряної швидкості відмовляє, виміряна швидкість може зависнути на нулі. Фільтр EKF безперервно порівнює покази трубки Піто з різницею супутникової шляхової швидкості (GNSS ground speed) та розрахункового вітру. При виявленні аномалії автопілот відкидає давач і перемикається на синтетичну повітряну швидкість (Synthetic Airspeed).
- **Таймаут переходу (Transition Timeout):** Якщо через сильний зустрічний вітер або дефіцит тяги апарат не може досягти `V_trans` за встановлений таймаут (зазвичай 15–25 секунд), стек припиняє перехід і повертає апарат у безпечне зависання на роторах.
- **Аеродинамічний скос потоку від роторів (Downwash):** Під час переходу струмені від передніх підйомних гвинтів обдувають крило та хвостовий стабілізатор, змінюючи ефективний кут атаки хвоста `α_tail = α - ε(V, T)`. Це породжує додатковий пікіруючий момент, який автопілот випереджально компенсує програмним тримуванням керма висоти.

## Матриці мікшування та узагальнена матриця геометрії актуаторів

Математичним ядром уніфікованого розподілу керування є матриця ефективності приводів (Control Effectiveness Matrix).

![Узагальнена матриця ефективності та десатурація](/root/sys/sys-dron/one-stack-many-bodies/img/dynamic-allocation-matrix.svg)
*Структура геометричної матриці ефективності B(θ, V) та каскадна драбина десатурації при виході приводів на апаратні обмеження.*

Прямий зв'язок між вектором фізичних приводів `u = [u₁, u₂, ..., u_m]ᵀ` (де `u_i ∈ [0, 1]` для моторів та `u_j ∈ [-1, +1]` для сервоприводів) та вектором віртуальних зусиль `τ` описується лінійним рівнянням:

```
τ = B · u
```

Матриця ефективності `B ∈ ℝ^(n × m)` формується динамічно з просторової геометрії кожного виконавчого органа:

1. **Ротори зависання:** `i`-й стовпчик визначається радіус-вектором `r_i = [x_i, y_i, z_i]ᵀ` від центру мас, одиничним вектором тяги `n_i` та коефіцієнтом реактивного моменту:

```
b_rotor,i = [
    n_x,i,
    n_y,i,
    n_z,i,
    y_i · n_z,i - z_i · n_y,i,
    z_i · n_x,i - x_i · n_z,i,
    x_i · n_y,i - y_i · n_x,i + d_i · (c_m / c_t) · n_z,i
]ᵀ · c_t,i · (1.0 - w_fw)
```

2. **Поворотні мотори (Tilt-Rotor):** Вектор спрямування тяги `n_i(θ)` залежить від поточного кута нахилу мотогондоли `θ`:

```
n_i(θ) = [sin(θ), 0, -cos(θ)]ᵀ
```

При зміні кута `θ` тяга і моменти неперервно перерозподіляються між поздовжньою віссю X та вертикальною віссю Z.

3. **Аеродинамічні рулі:** Створюють моменти сил, пропорційні динамічному напору повітряного потоку `q`:

```
b_surface,j = [
    0,
    0,
    0,
    c_roll,j · q,
    c_pitch,j · q,
    c_yaw,j · q
]ᵀ
```

### Лінеаризація статичної кривої тяги моторів

Зв'язок між електричним сигналом шпаруватості ШІМ чи пакетом DShot і реальною статичною тягою безколекторного мотора є нелінійним. Через аеродинаміку пропелера сила тяги росте пропорційно квадрату обертів:

```
T(u) = u^κ,    де κ ∈ [1.5, 2.0]
```

Якщо передати нелінійний сигнал безпосередньо на мотор, ефективний коефіцієнт підсилення контуру стабілізації плаватиме залежно від поточної тяги зависання. Тому перед видачею сигналу на ESC шар мікшування виконує обернену лінеаризацію:

```
u_pwm = (1.0 - c_expo) · u + c_expo · sqrt(u)
```

де `c_expo` — коефіцієнт експоненти тяги (`THR_MDL_FAC` у PX4 або `MOT_THST_EXPO` в ArduPilot). Це гарантує ідеальну лінійність відгуку по всій шкалі газу.

### Псевдообернення Мура-Пенроуза та пріоритетна десатурація

Оскільки кількість приводів `m` зазвичай перевищує кількість ступенів вільності `n = 4` чи `n = 6` (надлишкова система актуаторів), точний єдиний розв'язок відсутній. У загальній постановці задача розподілу керування зводиться до квадратичного програмування з обмеженнями:

```
min_u ( 0.5 · ||B · u - τ_sp||_Q² + 0.5 · ||u||_R² )
при обмеженнях: u_min ≤ u ≤ u_max
```

де `Q` — діагональна матриця вагових штрафів за нев'язку моментів і сил по окремих осях, а `R` — матриця енергетичної вартості сигналів керування.

Для виконання в мікросекундному циклі мікроконтролера розв'язок знаходиться через зважене псевдообернення:

```
u_raw = B⁺ · τ_sp = W⁻¹ · Bᵀ · (B · W⁻¹ · Bᵀ)⁻¹ · τ_sp
```

де `W` — діагональна матриця вагових коефіцієнтів енергетичної вартості приводів.

Якщо окремі компоненти вектора `u_raw` виходять за фізичні межі `[u_min, u_max]` (наприклад, мотор вимагає 120% тяги при сильному пориві вітру), просте арифметичне обрізання (`clipping`) кожного каналу окремо руйнує баланс моментів і призводить до зриву стабілізації. Стек застосовує жорстку **драбину пріоритетів десатурації (Saturation Priority Ladder)**:

1. **Пріоритет 1 (Стабілізація кутової орієнтації Roll / Pitch):** Збереження просторового положення є абсолютним життєвим пріоритетом. Якщо мотори входять у насичення при виправленні крену чи тангажу, автопілот автоматично знижує загальну вертикальну тягу, вивільняючи динамічний діапазон для моментів `M_x, M_y`.
2. **Пріоритет 2 (Вертикальна тяга / Утримання висоти F_z):** Збереження висоти важливіше за швидкість переміщення.
3. **Пріоритет 3 (Курс / Рискання M_z):** За дефіциту тяги автопілот тимчасово жертвує точністю утримання курсу, дозволяючи невеликий дрейф заради збереження орієнтації.
4. **Пріоритет 4 (Маршове прискорення F_x):** При перевантаженні силової установки маршова тяга літака чи ровера знижується в останню чергу.

## Уніфікований конфігуратор та мікшер на C та C++

Практична реалізація підсистеми розподілу базується на чистому обчислювальному ядрі без побічних ефектів, оптимізованому для виконання в жорсткому циклі реального часу RTOS (NuttX / FreeRTOS).

Детальний робочий проект із повним набором тестів та підтримкою мультикоптерів, літаків, QuadPlane, Tilt-Rotor і колісних роверів наведено у вставці [модульний рушій уніфікованого мікшування](root:sys-dron/one-stack-many-bodies/proj-unified-flight-mixer.md).

Нижче показано ключовий інтерфейсний контракт уніфікованого конфігуратора та обчислювача на мовах C та ідіоматичному C++.

=== C++
```cpp
#include <array>
#include <span>
#include <cmath>
#include <algorithm>

namespace flight_stack {

enum class AirframeClass : uint8_t {
    MultirotorX4,
    FixedWingConventional,
    VtolQuadplane,
    VtolTiltrotor,
    RoverSkidSteer
};

struct WrenchCommand {
    float fx{0.0f}, fy{0.0f}, fz{0.0f};
    float mx{0.0f}, my{0.0f}, mz{0.0f};
};

struct AirframeState {
    float v_ias{0.0f};
    float tilt_angle{0.0f};
    float dynamic_pressure{0.0f};
};

struct ActuatorChannel {
    uint8_t output_channel{0};
    std::array<float, 3> pos{0.0f, 0.0f, 0.0f};
    std::array<float, 3> dir{0.0f, 0.0f, -1.0f};
    float c_thrust{1.0f};
    float c_torque{0.0f};
    float min_limit{0.0f};
    float max_limit{1.0f};
};

class UniversalControlAllocator {
public:
    static constexpr size_t max_channels = 16;

    static void allocate(AirframeClass airframe,
                         const AirframeState& state,
                         const WrenchCommand& wrench,
                         std::span<const ActuatorChannel> actuators,
                         std::span<float> out_commands) noexcept {
        const size_t n = std::min(actuators.size(), out_commands.size());

        for (size_t i = 0; i < n; ++i) {
            const auto& act = actuators[i];
            float raw_cmd = 0.0f;

            // Базовий розподіл сил і моментів з урахуванням геометрії
            raw_cmd += -wrench.fz * (-act.dir[2]);
            raw_cmd += wrench.mx * act.pos[1];
            raw_cmd += wrench.my * (-act.pos[0]);
            raw_cmd += wrench.mz * act.c_torque;

            // Пріоритетна десатурація
            out_commands[i] = std::clamp(raw_cmd, act.min_limit, act.max_limit);
        }
    }
};

} // namespace flight_stack
```

Додавання нової екзотичної конфігурації планера (наприклад, трикоптера з поворотним хвостовим сервоприводом, конвертоплана з трьома поворотними гондолами чи октокоптера з асиметричним V-подібним розташуванням балок) зводиться до створення простого конфігураційного масиву дескрипторів `ActuatorChannel` без необхідності вносити зміни до навігаційних алгоритмів, оцінювачів стану чи протоколів телеметрії.
