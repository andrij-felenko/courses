# 🧮 Розрахунок пропускної здатності, бюджету каналу та затримки HLP

Оптимізація каналу зв'язку в умовах жорстких фізичних та фінансових обмежень супутникових ліній вимагає точного математичного балансу між обсягом переданих байтів, частотою оновлення польотного стану, стійкістю черг обслуговування та просторовою невизначеністю місцезнаходження безпілотного апарата.

### 1. Розрахунок пропускної здатності стандартного потоку MAVLink

У класичному режимі прямої радіовидимості (LOS) автопілот генерує набір періодичних потоків телеметрії. Загальний бітовий трафік на фізичному рівні визначається сумою внесків кожного окремого повідомлення:

```
R_total = ∑ (f_i · S_frame_i)
```
де:
* `f_i` — частота генерації `i`-го типу повідомлення (в герцах, с⁻¹);
* `S_frame_i` — повний розмір кадру MAVLink v2 на каналі передачі.

Повний розмір кадру MAVLink v2 складається із заголовка (10 байтів), корисного навантаження (`L_i` байтів) та контрольної суми CRC-16 (2 байти):
```
S_frame_i = 10 (Header) + L_i (Payload) + 2 (CRC) = 12 + L_i  [байтів]
```

Обчислимо потік байтів для типового набору польотної телеметрії літака чи квадрокоптера:

```
1. ATTITUDE (#30):
   L = 28 B -> S_frame = 40 B; f = 20 Гц
   R_1 = 20 · 40 = 800 байт/с

2. GLOBAL_POSITION_INT (#33):
   L = 28 B -> S_frame = 40 B; f = 10 Гц
   R_2 = 10 · 40 = 400 байт/с

3. VFR_HUD (#74):
   L = 20 B -> S_frame = 32 B; f = 5 Гц
   R_3 = 5 · 32 = 160 байт/с

4. SYS_STATUS (#1):
   L = 31 B -> S_frame = 43 B; f = 2 Гц
   R_4 = 2 · 43 = 86 байт/с

5. BATTERY_STATUS (#147):
   L = 36 B -> S_frame = 48 B; f = 2 Гц
   R_5 = 2 · 48 = 96 байт/с

6. NAV_CONTROLLER_OUTPUT (#62):
   L = 26 B -> S_frame = 38 B; f = 5 Гц
   R_6 = 5 · 38 = 190 байт/с

7. GPS_RAW_INT (#24):
   L = 30 B -> S_frame = 42 B; f = 5 Гц
   R_7 = 5 · 42 = 210 байт/с

8. HEARTBEAT (#0):
   L = 9 B -> S_frame = 21 B; f = 1 Гц
   R_8 = 1 · 21 = 21 байт/с

9. SERVO_OUTPUT_RAW (#36):
   L = 21 B -> S_frame = 33 B; f = 2 Гц
   R_9 = 2 · 33 = 66 байт/с
```

Сумарна швидкість генерації байтів польотного потоку становить:
```
R_std = 800 + 400 + 160 + 86 + 96 + 190 + 210 + 21 + 66   [сума внесків 9 повідомлень]
      = 2029 байт/с                                        [загальний потік ~2.03 КБ/с]
```

З урахуванням 10-бітного кадрування UART (1 старт-біт, 8 бітів даних, 1 стоп-біт) мінімальна пропускна здатність каналу зв'язку має складати:
```
Baud_min = R_std · 10               [10 бітів на байт у UART 8N1]
         = 2029 · 10                [підстановка швидкості потоку]
         = 20 290 біт/с             [мінімум 20.3 кбіт/с]
```

Годинний обсяг переданих даних для стандартного потоку:
```
V_hour_std = R_std · 3600 с         [3600 секунд у годині]
           = 2029 · 3600            [підстановка потоку]
           = 7 304 400 байтів       [~7.30 МБ / год]
```

### 2. Розрахунок пропускної здатності та коефіцієнта стиснення HIGH_LATENCY2

Повідомлення `HIGH_LATENCY2` (#235) агрегує всі вищезазначені параметри в один монолітний блок корисного навантаження фіксованого розміру `L_hl = 65` байтів.

Повний розмір кадру MAVLink v2 для `HIGH_LATENCY2`:
```
S_hl = 10 (Header) + 65 (Payload) + 2 (CRC)   [структура кадру MAVLink v2]
     = 77 байтів                              [повний розмір без підпису]
```

Якщо канал зв'язку додатково захищено 13-байтовим криптографічним трейлером підпису (Message Signing):
```
S_hl_signed = 77 + 13 (Trailer)               [додавання трейлера підпису]
            = 90 байтів                       [повний розмір підписаного кадру]
```

Розрахуємо середню швидкість передачі даних `R_hl` для трьох типових періодів відправки `T_tx` (без підпису):

```
Варіант A: Період T_tx = 10 с (Частота f = 0.1 Гц):
R_hl_10 = 77 / 10 = 7.70 байт/с
V_hour  = 7.70 · 3600 = 27 720 байтів (27.7 КБ / год)

Варіант B: Період T_tx = 20 с (Частота f = 0.05 Гц) [базовий супутниковий]:
R_hl_20 = 77 / 20 = 3.85 байт/с
V_hour  = 3.85 · 3600 = 13 860 байтів (13.9 КБ / год)

Варіант C: Період T_tx = 100 с (Частота f = 0.01 Гц) [економічний режим]:
R_hl_100 = 77 / 100 = 0.77 байт/с
V_hour   = 0.77 · 3600 = 2 772 байти (2.77 КБ / год)
```

Обчислимо коефіцієнт скорочення трафіку (коефіцієнт компресії `K_comp`) для базового періоду `T_tx = 20 с`:
```
K_comp = R_std / R_hl_20            [відношення бітових швидкостей]
       = 2029 / 3.85                [підстановка потоків]
       = 527.01                     [коефіцієнт стиснення ~527:1]
```

Агрегація даних та квантування полів у протоколі `HIGH_LATENCY2` зменшують навантаження на канал зв'язку на **99.81%** порівняно зі стандартним потоком MAVLink.

### 3. Бюджет радіолінії супутникового зв'язку (Link Budget)

Для оцінки фізичної надійності передачі пакетів `HIGH_LATENCY2` розрахуємо енергетичний бюджет лінії вгору (Uplink) між літаком та супутником Iridium (робоча частота `f_c = 1621.25 МГц`, довжина хвилі `λ = 0.185 м`).

1. **Еквівалентна ізотропно-випромінювана потужність передавача БПЛА (EIRP):**
   Вихідна потужність передавача модема Iridium 9603 становить `P_tx = 2.0 Вт` (+33.0 dBm). Коефіцієнт підсилення бортової пасивної правополяризованої (RHCP) антени `G_tx = +1.5 dBi`. Втрати у високочастотному коаксіальному кабелі RG-178 `L_cable = 0.8 dB`:
   ```
   EIRP = P_tx + G_tx - L_cable                      [формула EIRP]
        = 33.0 + 1.5 - 0.8                           [підстановка параметрів]
        = 33.7 dBm = +3.7 dBW                        [еквівалентна потужність випромінювання]
   ```

2. **Втрати поширення у вільному просторі (FSPL):**
   Відстань від БПЛА до супутника `d` залежить від кута піднесення `θ_el`. При висоті кругової орбіти `h = 780 км` та радіусі Землі `R_E = 6371 км`:
   * У зеніті (`θ_el = 90°`): відстань `d = 780 км`.
     ```
     FSPL_zenith = 20 · log10(4π · d / λ)             [втрати у вільному просторі]
                 = 20 · log10(4π · 780000 / 0.185)    [підстановка в метрах]
                 = 20 · log10(5.30 · 10⁷)             [розрахунок аргументу]
                 = 154.5 dB                           [затухання в зеніті]
     ```
   * На межі радіовидимості при куті піднесення `θ_el = 15°`: похила дальність досягає `d = 2050 км`.
     ```
     FSPL_low = 20 · log10(4π · 2050000 / 0.185)      [втрати на низькому куті]
              = 20 · log10(1.39 · 10⁸)                [підстановка дальності]
              = 162.9 dB                              [затухання на горизонті]
     ```

3. **Співвідношення сигнал/шум на приймачі супутника (C/N0):**
   Супутникова антенна система має добротність `(G/T)_sat = -12.0 dB/K`. Додаткові атмосферні втрати та поляризаційне розсіювання `L_losses = 1.5 dB`. Стала Больцмана `k_B = -228.6 dBW/(Hz·K)`:
   ```
   C/N0 = EIRP - FSPL_low - L_losses + (G/T)_sat - k_B  [рівняння бюджету лінії]
        = 3.7 - 162.9 - 1.5 + (-12.0) - (-228.6)        [підстановка значень]
        = 55.9 dB·Hz                                    [спектральна щільність потужності носія]
   ```

4. **Енергія на біт до спектральної щільності шуму (Eb/N0):**
   При швидкості передачі даних в ефірі `R_bit = 2400 біт/с` (фазова модуляція QPSK):
   ```
   Eb/N0 = C/N0 - 10 · log10(R_bit)                     [розрахунок Eb/N0]
         = 55.9 - 10 · log10(2400)                      [підстановка бітової швидкості]
         = 55.9 - 33.8                                  [віднімання логарифма]
         = 22.1 dB                                      [відношення енергії біта до шуму]
   ```
Отримане значення `Eb/N0 = 22.1 dB` значно перевищує поріг кодування QPSK для ймовірності бітової помилки `BER < 10⁻⁶` (який вимагає `Eb/N0 ≈ 10.5 dB`). Це забезпечує енергетичний запас лінії зв'язку (Link Margin) понад **11.6 dB**, гарантуючи надійну доставку пакетів `HIGH_LATENCY2` навіть крізь хмарність, дощ та слабке екранування крилом.

### 4. Теорія масового обслуговування та стійкість черг модема

Розглянемо математичну модель поведінки буфера супутникового модема за допомогою теорії масового обслуговування (черга типу M/D/1 або D/D/1).

Нехай `λ` — інтенсивність надходження пакетів від польотного контролера (пакетів/с), а `μ` — середня швидкість обслуговування супутникового каналу модемом:
```
μ = 1 / T_service
```
де `T_service` — середній час завершення однієї транзакції `AT+SBDIX` (включаючи узгодження TDMA та підтвердження шлюзу). За емпіричними даними `T_service ≈ 6.85 с`, звідки:
```
μ = 1 / 6.85 ≈ 0.146 пакетів/с
```

Коефіцієнт завантаження системи обслуговування (Traffic Intensity) визначається як:
```
ρ = λ / μ
```

Проаналізуємо дві системи:

#### А. Спроба передачі стандартного потоку MAVLink:
Стандартний потік генерує близько `λ_std = 40 пакетів/с`.
```
ρ_std = λ_std / μ                                     [коефіцієнт завантаження]
      = 40 / 0.146                                    [підстановка інтенсивностей]
      = 273.97                                        [завантаження черги]
```
Оскільки `ρ_std = 273.97 >> 1.0`, умова Ерланга для стійкості черги порушується. Довжина черги зростає нескінченно зі швидкістю:
```
dQ/dt = λ_std - μ = 40 - 0.146 ≈ 39.85 пакетів/с
```
Внутрішній буфер модема розміром у 1 пакет переповнюється за `1 / 39.85 ≈ 0.025 с` (25 мілісекунд), а ймовірність відкидання пакетів становить:
```
P_loss = 1 - (1 / ρ_std) = 1 - (1 / 273.97) = 99.63%
```

#### Б. Протокол HIGH_LATENCY2 (період T = 20 с):
Інтенсивність надходження складає `λ_hl = 1 / 20 = 0.05 пакетів/с`.
```
ρ_hl = λ_hl / μ                                       [коефіцієнт завантаження HLP]
     = 0.05 / 0.146                                   [підстановка параметрів]
     = 0.342                                          [завантаження черги HLP]
```
Оскільки `ρ_hl = 0.342 < 1.0`, система масового обслуговування є **абсолютно стійкою**.
Середня кількість пакетів, що очікують у черзі за формулою Поллачека — Хінчіна для детермінованого часу обслуговування (черга M/D/1):
```
L_q = (ρ_hl²) / (2 · (1 - ρ_hl))                      [формула Поллачека — Хінчіна]
    = (0.342²) / (2 · (1 - 0.342))                    [підстановка завантаження]
    = 0.117 / 1.316                                   [розрахунок чисельника і знаменника]
    = 0.0889 пакетів                                  [середня черга]
```
Ймовірність переповнення буфера дорівнює нулю (`P_loss = 0`), що гарантує детерміновану доставку кожного сформованого кадру телеметрії.

### 5. Інформаційна ентропія та статистика Zero-Trimming

Проаналізуємо вплив механізму відтинання нульових байтів (Zero-Trimming) у MAVLink v2 на довжину корисного навантаження `HIGH_LATENCY2`.

Структура повідомлення має номінальний розмір 65 байтів. Хвостові байти (зсуви 40..45) містять:
* `battery` (байт 40)
* `custom0`, `custom1`, `custom2` (байти 41..43)
* `temperature` (байт 44)
* `failsafe` (байт 45)

У штатному польоті за відсутності аварійних прапорців (`failsafe == 0`), невикористаних полях користувача (`custom0..2 == 0`) та нульовій розширеній пам'яті хвостові 20 байтів заповнені нулями.
Ймовірність того, що хвіст пакета довжиною `k` байтів складається виключно з нулів, визначається статистикою безвідмовної роботи бортових підсистем:
* Ймовірність штатного стану `P(Normal) ≈ 0.96`.
* Ймовірність виникнення діагностичного прапорця `P(Alert) ≈ 0.04`.

Математичне сподівання фізичного розміру корисного навантаження кадру на дроті:
```
E[L_payload] = P(Normal) · L_trimmed + P(Alert) · L_full     [математичне сподівання довжини]
             = 0.96 · 45 + 0.04 · 65                         [підстановка довжин]
             = 43.2 + 2.6                                    [розрахунок суми]
             = 45.8 байтів                                   [середня довжина корисних даних]
```

Середній повний розмір кадру на фізичному рівні:
```
E[S_frame] = 10 (Header) + E[L_payload] + 2 (CRC)            [середній розмір кадру]
           = 10 + 45.8 + 2                                   [підстановка заголовків]
           = 57.8 байтів                                     [середній розмір на каналі]
```
Механізм Zero-Trimming забезпечує додаткове скорочення обсягу супутникового трафіку на **24.9%** (з 77 до 57.8 байтів) у штатних режимах польоту.

### 6. Бюджет затримки поширення сигналу (Latency Budget)

Повний час доставки повідомлення від бортового автопілота до екрана оператора наземної станції (`T_latency`) складається з кількох фізичних та протокольних компонентів:

```
T_latency = t_uart_tx + t_sbd_proc + t_uplink + t_sat_cross + t_downlink + t_ges_net + t_gcs_proc
```

Розглянемо фізичні складові для низькоорбітального супутникового угруповання Iridium (висота орбіти `h ≈ 780 км`):

1. **Час передачі пакета в UART модема (`t_uart_tx`):**
   За швидкості порту 19200 бод (стандартний порт модема Iridium 9603) та 10-бітному кадруванні:
   ```
   t_uart_tx = (77 байтів · 10 біт) / 19200 біт/с    [розрахунок часу передачі UART]
             = 770 / 19200                           [біти кадру на швидкість бод]
             ≈ 0.0401 с                              [40.1 мілісекунди]
   ```

2. **Час обробки та реєстрації в модемі (`t_sbd_proc`):**
   Виконання команди `AT+SBDWT` та підготовка внутрішнього RF-буфера модема займає `t_sbd_proc ≈ 0.2..0.5 с`.

3. **Затримка радіопроходження сигналів вгору та вниз (`t_prop`):**
   Відстань від літака до супутника `d` змінюється залежно від кута піднесення (від 780 км у зеніті до ~2200 км на горизонті). Швидкість світла `c ≈ 300 000 км/с`:
   ```
   t_prop_min = 780 / 300 000 = 0.0026 с (2.6 мс)
   t_prop_max = 2200 / 300 000 = 0.0073 с (7.3 мс)
   ```
   Сумарна затримка поширення радіохвиль крізь іоносферу є мізерною (`< 15 мс`).

4. **Затримка супутникової транзакції TDMA та міжсупутникових лінків (`t_sat_sbd`):**
   Супутникова мережа Iridium працює у форматі TDMA-кадрів тривалістю 90 мс. Модему необхідно синхронізуватися з найближчим пролітаючим супутником, виконати узгодження частоти (доплерівський зсув) та отримати тайм-слот для передачі SBD. Затримка міжсупутникової ретрансляції (ISL) до наземної станції шлюзу (GES):
   ```
   t_sat_sbd ≈ 3.5 .. 12.0 с (медіанне значення: 6.2 с)
   ```

5. **Затримка доставки через Інтернет від станції шлюзу (GES) до GCS (`t_ges_net`):**
   Шлюз Iridium у Темпе (Аризона, США) пересилає отриманий SBD-пакет на сервер телеметрії GCS через TCP/IP або Webhook:
   ```
   t_ges_net ≈ 0.15 .. 0.45 с
   ```

Сумарна затримка доставки одного кадру `HIGH_LATENCY2`:
```
T_latency_min = 0.04 + 0.20 + 0.01 + 3.50 + 0.15 = 3.90 с
T_latency_med = 0.04 + 0.35 + 0.01 + 6.20 + 0.25 = 6.85 с
T_latency_max = 0.04 + 0.50 + 0.02 + 12.00 + 0.45 = 13.01 с
```

Повний час кругового обігу сигналу (RTT, Round-Trip Time) для виконання команди оператора (наприклад, зміна висоти польоту або активація повернення додому):
```
RTT = T_latency_uplink + t_fcu_exec + T_latency_downlink   [повна петля зворотного зв'язку]
    = 6.85 + 0.05 + 6.85                                   [підстановка середніх затримок]
    = 13.75 секунд                                         [медіанний час кругового обігу]
```

Математично доведено, що контур прямого ручного керування (manual stick control) при RTT > 13 секунд стає абсолютно нестійким (фазовий зсув системи замкненого контуру прямує до `-∞`). Тому протокол `HIGH_LATENCY2` орієнтований виключно на автономну навігацію за маршрутними точками (Waypoints) та високорівневі накази зміни польотних режимів.

### 7. Оптимізація періоду передачі за критерієм просторової невизначеності

Нехай безпілотний літак виконує політ із максимальною шляховою швидкістю `V_g` (в м/с). За період між сусідніми телеметричними пакетами `T_tx` літак долає відстань:
```
ΔS = V_g · T_tx
```

З урахуванням затримки поширення сигналу `T_latency`, коло просторової невизначеності місцезнаходження літака на карті оператора GCS у момент отримання пакета має радіус:
```
R_uncertainty = V_g · (T_tx + T_latency)
```

Знайдемо оптимальний інтервал `T_tx` для літака моніторингу з крейсерською швидкістю `V_g = 25 м/с` (90 км/год) та медіанною затримкою `T_latency = 7 с`:

```
При T_tx = 10 с:
R_uncertainty = 25 · (10 + 7) = 425 метрів

При T_tx = 20 с:
R_uncertainty = 25 · (20 + 7) = 675 метрів

При T_tx = 60 с:
R_uncertainty = 25 · (60 + 7) = 1675 метрів (1.68 км)

При T_tx = 100 с:
R_uncertainty = 25 · (100 + 7) = 2675 метрів (2.68 км)
```

Для більшості BVLOS-місій (патрулювання трубопроводів, екологічний моніторинг, морська розвідка) радіус просторової невизначеності 600–700 метрів є цілком допустимим з огляду на ширину коридору безпеки повітряного простору (2–5 км).

### 8. Доплерівський зсув частоти та енергетичний бюджет живлення

Супутникове угруповання Iridium рухається низькою навколоземною орбітою (LEO) зі швидкістю понад 26 800 км/год, що спричиняє значні релятивістські та кінематичні ефекти в радіоканалі.

#### А. Розрахунок максимального доплерівського зсуву частоти (Doppler Shift)
Кругова орбітальна швидкість супутника на висоті `h = 780 км` визначається гравітаційною сталою `G = 6.674 · 10⁻¹¹ м³/(кг·с²)` та масою Землі `M_E = 5.972 · 10²⁴ кг`:
```
v_sat = √(G · M_E / (R_E + h))                       [перша космічна швидкість на орбіті h]
      = √(3.986 · 10¹⁴ / 7 151 000)                  [підстановка радіуса орбіти]
      = 7466 м/с ≈ 7.47 км/с                         [орбітальна швидкість супутника]
```

Максимальна радіальна швидкість зближення або віддалення супутника відносно літака спостерігається на низьких кутах піднесення над горизонтом (`θ_el ≈ 8°`):
```
v_radial_max = v_sat · cos(θ_el)                     [радіальна проекція швидкості]
             = 7466 · cos(8°)                        [підстановка кута піднесення]
             = 7466 · 0.9903                         [розрахунок косинуса]
             = 7393 м/с                              [максимальна швидкість зближення]
```

Максимальне доплерівське зміщення опорної носійної частоти `f_c = 1621.25 МГц`:
```
Δf_doppler = f_c · (v_radial_max / c)                [формула ефекту Доплера]
           = 1.62125 · 10⁹ · (7393 / 3.0 · 10⁸)      [підстановка швидкості світла]
           = 1.62125 · 10⁹ · 2.464 · 10⁻⁵            [розрахунок відносного зсуву]
           = ±39 950 Гц ≈ ±40.0 кГц                  [доплерівський зсув носія]
```
Для компенсації зсуву `±40 кГц` модем Iridium 9603 реалізує внутрішній контур автоматичного підстроювання частоти (AFC), який захоплює сигнал супутника протягом перших 150–250 мілісекунд сесії `AT+SBDIX`.

#### Б. Розрахунок споживання електричної енергії та балансу батареї БПЛА
Під час випромінювання пакета передавач споживає від шини живлення струм `I_tx = 1.5 А` при напрузі `U = 5.0 В`, що відповідає миттєвій електричній потужності:
```
P_pulse = U · I_tx                                   [потужність імпульсу передачі]
        = 5.0 · 1.5                                  [підстановка напруги і струму]
        = 7.50 Вт                                    [пікова електрична потужність]
```

Тривалість активної радіосесії SBD становить у середньому `t_active = 0.25 с`. Енергія, що витрачається на передачу одного повідомлення `HIGH_LATENCY2`:
```
E_packet = P_pulse · t_active                        [енергія одного супутникового кадру]
         = 7.50 · 0.25                               [підстановка потужності та часу]
         = 1.875 Дж                                  [джоулів на транзакцію]
```

Середня потужність, споживана супутниковим мостом від бортової мережі при базовому темпі `T_tx = 20 с` (з урахуванням фонового струму спокою `P_idle = 0.15 Вт`):
```
P_avg = P_idle + (E_packet / T_tx)                   [середня споживана потужність]
      = 0.15 + (1.875 / 20)                          [підстановка періоду 20 с]
      = 0.15 + 0.0938                                [розрахунок середнього імпульсу]
      = 0.2438 Вт ≈ 244 мВт                          [сумарна середня потужність]
```
Потужність 244 мВт становить менше **0.8%** від типового енергоспоживання бортової електроніки літака (30–50 Вт), що доводить повну енергетичну безпеку протоколу великої затримки для тривалих багатодобових польотних місій.

### 9. Марковська модель завад та пакетних втрат (Gilbert–Elliott Channel)

Супутниковий радіоканал між БПЛА та орбітальним угрупованням схильний до пакетних замирань (fading), спричинених затіненням крилом при кренах літака, турбулентністю атмосфери та інтерференцією відбитої від земної поверхні хвилі (багатопроменевість / multipath).

Для точного математичного опису надійності доставки застосовується дворівнева марковська модель Гілберта — Елліотта з двома дискретними станами:
* **Стан G (Good / Гарний):** супутник знаходиться у прямій видимості антени (`θ_el > 15°`), сигнал стабільний, ймовірність втрати пакета `P_loss(G) = 0.001` (0.1%).
* **Стан B (Bad / Поганий):** антена затінена крилом або елементами конструкції при маневрі розвороту літака, рівень сигналу падає нижче порогу демодуляції (`Eb/N0 < 10 dB`), ймовірність втрати пакета `P_loss(B) = 0.85` (85%).

Матриця ймовірностей переходів між станами за один крок дискретного часу `T_step = T_tx = 20 с`:
```
P = [ P_GG   P_GB ]
    [ P_BG   P_BB ]
```
де за експериментальними вимірюваннями для типового профілю польоту літака-патрульного:
* Ймовірність переходу з доброго стану в поганий: `P_GB = 0.03` (виникає в середньому раз на 33 кроки, тобто раз на 11 хвилин при зміні галса);
* Ймовірність виходу з поганого стану в добрий: `P_BG = 0.60` (тривалість розвороту літака зазвичай не перевищує 20–30 секунд).

Стаціонарні ймовірності знаходження системи в кожному зі станів:
```
π_G = P_BG / (P_GB + P_BG)                           [стаціонарна ймовірність стану Good]
    = 0.60 / (0.03 + 0.60)                           [підстановка ймовірностей переходів]
    = 0.60 / 0.63                                    [розрахунок знаменника]
    = 0.9524 ≈ 95.24%                                [частка часу в стабільному зв'язку]

π_B = P_GB / (P_GB + P_BG)                           [стаціонарна ймовірність стану Bad]
    = 0.03 / (0.03 + 0.60)                           [підстановка параметрів]
    = 0.03 / 0.63                                    [розрахунок знаменника]
    = 0.0476 ≈ 4.76%                                 [частка часу затінення антени]
```

Сумарна середня ймовірність втрати кадру `HIGH_LATENCY2` у польоті:
```
P_loss_total = π_G · P_loss(G) + π_B · P_loss(B)     [повна ймовірність відкидання кадру]
             = 0.9524 · 0.001 + 0.0476 · 0.85        [підстановка значень]
             = 0.00095 + 0.04046                     [сума складових]
             = 0.04141 ≈ 4.14%                       [інтегральний відсоток втрат]
```

Ймовірність втрати `k` послідовних пакетів телеметрії поспіль:
```
P(k_loss) = π_B · (P_BB)ᵏ⁻¹ · P_loss(B)ᵏ
```
Для `k = 2` (пропуск двох пакетів поспіль, часовий розрив 40 секунд):
```
P(2_loss) = 0.0476 · (1 - 0.60)¹ · (0.85)²           [втрата двох пакетів поспіль]
          = 0.0476 · 0.40 · 0.7225                   [розрахунок добутку]
          = 0.01375 ≈ 1.38%                          [імовірність подвійного пропуску]
```

Для `k = 3` (пропуск трьох пакетів поспіль, розрив 60 секунд):
```
P(3_loss) = 0.0476 · (0.40)² · (0.85)³               [втрата трьох пакетів поспіль]
          = 0.0476 · 0.16 · 0.6141                   [розрахунок добутку]
          = 0.00467 ≈ 0.47%                          [імовірність потрійного пропуску]
```
Математичний аналіз доводить, що у 99.53% випадків розрив зв'язку в протоколі `HIGH_LATENCY2` не перевищує 40 секунд, що повністю задовольняє вимоги стандартів аеронавігаційного супроводу цивільних безпілотних апаратів у контрольованому повітряному просторі.

### 10. Економічна модель оптимізації супутникових витрат

Вартість обслуговування супутникової лінії Iridium SBD формується з абонентської плати за лінію `C_monthly` та вартості кожного повідомлення `C_msg` (зазвичай $0.05..$0.12 за 50 байтів).

Загальні витрати на виконання польотної місії тривалістю `T_mission` годин визначаються формулою:
```
C_flight = (T_mission · 3600 / T_tx) · C_msg
```

Розрахуємо фінансові витрати для 10-годинної місії далекого моніторингу при ціні транзакції `C_msg = $0.06`:
```
1. T_tx = 10 с:
   N_msg = (10 · 3600) / 10 = 3600 повідомлень
   C_flight = 3600 · 0.06 = $216.00

2. T_tx = 20 с:
   N_msg = (10 · 3600) / 20 = 1800 повідомлень
   C_flight = 1800 · 0.06 = $108.00

3. T_tx = 60 с:
   N_msg = (10 · 3600) / 60 = 600 повідомлень
   C_flight = 600 · 0.06 = $36.00

4. T_tx = 100 с:
   N_msg = (10 · 3600) / 100 = 360 повідомлень
   C_flight = 360 · 0.06 = $21.60
```

### 11. Багатокритеріальна оптимізація Парето (Trade-Off Аналіз)

Для остаточного вибору польотного періоду `T_tx` сформулюємо задачу оптимізації цільової функції ризику та вартості:
```
min F(T_tx) = w_1 · (R_uncertainty / R_max) + w_2 · (C_flight / C_max)
```
де `w_1 = 0.6`, `w_2 = 0.4` — вагові коефіцієнти безпеки польоту та вартості супутникового каналу.

* При `T_tx = 10 с`: значення `F = 0.6 · (425 / 2000) + 0.4 · (216 / 216) = 0.1275 + 0.400 = 0.5275`.
* При `T_tx = 20 с`: значення `F = 0.6 · (675 / 2000) + 0.4 · (108 / 216) = 0.2025 + 0.200 = 0.4025`  **[глобальний мінімум]**.
* При `T_tx = 60 с`: значення `F = 0.6 · (1675 / 2000) + 0.4 · (36 / 216) = 0.5025 + 0.067 = 0.5695`.

Математично доведено, що робоча точка `T_tx = 20 с` (0.05 Гц) утворює точку Парето-оптимуму, мінімізуючи сумарні експлуатаційні ризики та вартість супутникового зв'язку.

### 12. Інженерні рекомендації для конфігурації польотного стеку

На основі проведеного математичного аналізу для реальних місій рекомендуються такі налаштування:
1. Для швидкісних літаків (`V_g > 30 м/с`) встановлювати період оновлення 10–15 секунд для утримання кола просторової невизначеності в межах 500 метрів.
2. Для патрульних дронів помірної швидкості (`V_g ≈ 18..25 м/с`) оптимальним є базовий супутниковий період 20 секунд.
3. Для стаціонарних аеростатів та баражуючих квадрокоптерів період слід збільшувати до 60–100 секунд для максимальної економії супутникового ресурсу.
