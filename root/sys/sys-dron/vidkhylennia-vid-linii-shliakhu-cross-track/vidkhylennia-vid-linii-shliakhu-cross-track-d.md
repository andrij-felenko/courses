# Відхилення від лінії шляху (cross-track)

<preknowlist>
- [Скалярний добуток](root:math-algebra/dot-product) — проєкція вектора на напрям, ортогональність та поздовжній зсув.
- [Векторний добуток](root:math-algebra/cross-product) — псевдоскалярний 2D-добуток, знак бічного відхилення та орієнтація.
- [Навігація pure pursuit](root:sys-dron/pure-pursuit-navigation) — відстеження цільової точки на траєкторії через дугу постійної кривини.
</preknowlist>

Безпілотний літак виконує аерофотознімання за маршрутом між точками `W_A = (0, 0)` та `W_B = (1000, 0)` метрів на швидкості 18 м/с. З правого борту дме постійний вітер зі швидкістю 6 м/с. Якщо автопілот просто спрямовує ніс літака на фінальну точку `W_B`, бічний потік безперервно зносить апарат ліворуч. До середини відрізка дрон зміщується на 75 метрів від заданої осі, а траєкторія перетворюється на вигнуту дугу погоні. Смуга перекриття кадрів зривається, а в умовах польоту у вузькому безпечному коридорі між висотними перешкодами чи зонами обмеження польотів таке відхилення призводить до аварії.

Наведення безпосередньо на кінцеву точку працює лише в ідеальному штилі й на прямій видимості. Щойно з'являється вітер, початкове зміщення або ламана траєкторія з десятків поворотів, навігаційній системі потрібен інструмент, який у реальному часі розділяє рух на дві незалежні складові: просування вперед уздовж коридору та бічне зміщення від заданої лінії.

> 🔧 **Навіщо це.** Похибка відхилення від лінії шляху (Cross-Track Error) — це фундаментальна метрика для систем автоматичного пілотування літаків, коптерів, крил, безекіпажних катерів та наземних роботів. На ній тримаються алгоритми утримання коридору польоту в PX4 та ArduPilot, обхід зон заборони польотів (geofence), точне проходження сільськогосподарських рядків та навігація в умовах сильного бокового зносу.

## Геометрія коридору: чому наведення на точку спотворює шлях

Коли літальний апарат летить від точки `W_A` до `W_B`, його положення відносно відрізка неможливо адекватно описати однією лише відстанню до точки призначення. Якщо дрон змістився вбік на 50 метрів, але прямує носом на `W_B`, вектор його швидкості не повертає дрон назад на лінію, а лише веде до фінішу під кутом. Що ближче апарат підлітає до `W_B`, то крутішим стає цей кут, провокуючи різкий фінальний доворот і проскакування точки.

Правильний підхід полягає в переведенні поточної позиції апарата `p` у локальну систему координат самого відрізка шляху (так званий фрейм шляху або координатну систему Френе–Серре). У цій системі простір розщеплюється на дві взаємно перпендикулярні осі:

1. **Поздовжня вісь (along-track):** спрямована вздовж прямої `W_A → W_B`. Вона показує пройдений шлях від початку відрізка `s` та визначає, чи не проскочив апарат цільову точку.
2. **Поперечна вісь (cross-track):** спрямована строго перпендикулярно до лінії шляху. Вона вимірює бічне зміщення `e_ct` зі знаком: плюс — відхилення праворуч від лінії, мінус — відхилення ліворуч.

![Геометрія похибки cross-track](/root/sys/sys-dron/vidkhylennia-vid-linii-shliakhu-cross-track/img/cross-track-geometry.svg)
*Векторний розклад положення апарата p відносно відрізка маршруту W_A → W_B. Проєкція вектора a на дотичний вектор t̂ задає пройдену відстань s (along-track), а векторний добуток із t̂ визначає величину та знак бічного відхилення e_ct (cross-track).*

Знаючи обидві ці величини, автопілот розв'язує дві окремі підзадачі: поздовжній автомат перемикає точки маршруту, коли `s` досягає довжини відрізка, а поперечний контур керування формує курс або крен для ліквідації `e_ct`.

## Локальна система координат: перехід від WGS-84 до площини

Супутникові приймачі GNSS видають координати у геодезичній системі WGS-84 у вигляді географічної широти `lat`, довготи `lon` та еліпсоїдної висоти `alt`. Безпосередній розрахунок векторних добутків у градусах неможливий через кривину Землі та нерівність довжини градуса широти й довготи.

Перед початком навігаційних обчислень координати точок місії `W_A`, `W_B` та поточної позиції `p` переводять у локальну дотичну метричну площину (Local Tangent Plane / фрейм NED — North-East-Down) відносно опорної точки `(lat_0, lon_0)`.

Для площі польотів у радіусі до 30–50 км використовується проєкція пласкої Землі (Flat Earth projection):

```
R_earth ≈ 6371000.0                           [середній радіус Землі у метрах]
x_ned = (lat − lat_0) · (π / 180.0) · R_earth [північна координата X у метрах]
y_ned = (lon − lon_0) · (π / 180.0) · R_earth · cos(lat_0 · π / 180.0)   [східна координата Y]
```

Отримані метричні координати `(x_ned, y_ned)` утворюють стандартний двовимірний простір, у якому векторна алгебра виконується строго й без спотворень масштабів.

## Векторний розрахунок: псевдоскалярний добуток і знак відхилення

Нехай початкова точка відрізка має координати `W_A = (x_A, y_A)`, кінцева — `W_B = (x_B, y_B)`, а поточні координати апарата за даними комплексованого навігаційного фільтра Калмана — `p = (p_x, p_y)`.

Визначимо вектор відрізка шляху `b` та вектор зміщення апарата від початку відрізка `a`:

```
b = W_B − W_A = (x_B − x_A,  y_B − y_A)       [вектор лінії шляху]
a = p − W_A   = (p_x − x_A,  p_y − y_A)       [вектор від початку до апарата]
```

Довжина сегмента шляху `L_AB` обчислюється через евклідову норму вектора `b`:

```
L_AB = ||b|| = √( (x_B − x_A)² + (y_B − y_A)² )   [повна довжина відрізка]
```

Одиничний дотичний вектор лінії шляху `t̂` (орт напрямку) дорівнює:

```
t̂ = b / L_AB = ( (x_B − x_A) / L_AB,  (y_B − y_A) / L_AB ) = (t_x, t_y)   [дотичний одиничний вектор]
```

Щоб знайти відстань від точки `p` до прямої, розглянемо паралелограм, побудований на векторах `a` та `b`. Його площа обчислюється двома способами: як модуль двовимірного псевдоскалярного (косого) добутку `a × b`, і як добуток довжини основи `||b||` на висоту, яка і є шуканою відстанню `|e_ct|`.

Прирівнюючи ці два вирази, дістаємо аналітичну формулу поперечного відхилення `e_ct`:

```
e_ct = (a_x · b_y − a_y · b_x) / ||b||
     = ( (p_x − x_A)(y_B − y_A) − (p_y − y_A)(x_B − x_A) ) / L_AB   [поперечна похибка cross-track]
```

Через компоненти одиничного дотичного вектора `t̂ = (t_x, t_y)` розрахунок зводиться до двох множень:

```
e_ct = a_x · t_y − a_y · t_x                  [обчислення через орт напрямку]
```

Алгебраїчний знак величини `e_ct` визначає сторону відхилення за правилом правої руки:
- `e_ct > 0`: апарат зміщений праворуч від напрямку руху `W_A → W_B` (для повернення на лінію потрібен лівий поворот);
- `e_ct < 0`: апарат зміщений ліворуч від напрямку руху (потрібен правильний доворот праворуч);
- `e_ct = 0`: апарат знаходиться строго на осьовій лінії заданого відрізка.

## Поздовжня відстань (along-track) та проєкція на відрізок

Поздовжня відстань `s` показує, яку дистанцію вздовж осьової лінії вже подолав апарат відносно точки `W_A`. Геометрично це скалярна проєкція вектора `a` на одиничний дотичний вектор `t̂`:

```
s = a · t̂
  = a_x · t_x + a_y · t_y                     [скалярний добуток]
  = ( (p_x − x_A)(x_B − x_A) + (p_y − y_A)(y_B − y_A) ) / L_AB   [поздовжня координата]
```

Нормалізований прогрес проходження відрізка `u` виражається часткою від повної довжини:

```
u = s / L_AB
  = ( (p_x − x_A)(x_B − x_A) + (p_y − y_A)(y_B − y_A) ) / (L_AB)²   [параметр прогресу]
```

Точка ортогональної проєкції `p_proj` на осьову лінію маршруту визначається як:

```
p_proj = W_A + s · t̂ = W_A + u · b            [координати точки проєкції]
```

Параметр `u` розбиває траєкторію на три характерні робочі зони:
1. `u < 0` (`s < 0`): дрон знаходиться позаду початкової точки `W_A`. Така ситуація виникає під час виходу на перший відрізок місії або після різкого маневру ухилення. Автопілот повинен утримувати вектор наведення в напрямку відрізка, уникаючи розвороту назад.
2. `0 ≤ u ≤ 1` (`0 ≤ s ≤ L_AB`): дрон летить уздовж поточного відрізка. Це штатна зона регулювання, де працює основний контур ліквідації `e_ct`.
3. `u > 1` (`s > L_AB`): дрон перетнув площину нормалі, що проходить через фінішну точку `W_B`. У цей момент сегмент вважається виконаним, і логіка місії має негайно переключити цільовий відрізок на наступний (`W_B → W_C`).

> 🧮 Повне математичне виведення формул проєкцій, розбір тригонометричних тотожностей та строгий аналіз динаміки контуру зібрані у вставці [Виведення похибки відхилення та стійкості LOS](root:sys-dron/vidkhylennia-vid-linii-shliakhu-cross-track/math-cross-track-derivation.md).

## Алгоритм віртуальної цілі: Carrot Chaser

Знаючи точку проєкції `p_proj` та величину відхилення `e_ct`, навігаційна система має згенерувати команду на рульові органи. Найпростіший спосіб повернути апарат на лінію — створити рухому віртуальну точку-ціль на лінії шляху попереду апарата. Цей алгоритм історично отримав назву **Carrot Chaser** («гонитва за морквиною», за аналогією з віслюком, що біжить за закріпленою на вудці морквою).

Точка «морквини» `p_carrot` обчислюється шляхом зміщення від точки проєкції `p_proj` вперед за напрямком руху на фіксовану відстань випередження `Δ` (lookahead distance):

```
p_carrot = p_proj + Δ · t̂ = W_A + (s + Δ) · t̂   [координати рухомої цілі]
```

Бажаний шляховий курс літака `χ_cmd` обчислюється як прямий азимут від поточної позиції дрона `p` на точку `p_carrot`:

```
χ_cmd = atan2( y_carrot − p_y,  x_carrot − p_x )   [командний курс на морквину]
```

![Carrot Chaser проти Pure Pursuit](/root/sys/sys-dron/vidkhylennia-vid-linii-shliakhu-cross-track/img/carrot-vs-pure-pursuit.svg)
*Принципова відмінність двох підходів до цілевказівки. Ліворуч: Carrot Chaser генерує рухому точку на фіксованій відстані Δ попереду проєкції та вимагає лише розрахунку азимута. Праворуч: Pure Pursuit шукає перетин кола радіуса L_d з лінією та безпосередньо розраховує кривину дуги повороту κ.*

Поведінка апарата під керуванням Carrot Chaser повністю залежить від вибору величини `Δ`:
- **Мале `Δ` (близьке випередження):** кут наведення стає майже перпендикулярним до лінії шляху. Апарат агресивно намагається повернутися на вісь, але через інерцію та обмежену швидкість розвороту перелітає лінію (overshoot), починаючи коливатися з наростаючою або незгасаючою амплітудою.
- **Велике `Δ` (далеке випередження):** апарат плавно і повільно наближається до лінії під дуже гострим кутом, долаючи значну поздовжню відстань до повного вирівнювання.

Головне обмеження Carrot Chaser: алгоритм видає лише кут напрямку на точку `χ_cmd`, не враховуючи поточну швидкість літака, обмеження по куту крену та допустимий радіус віражу.

## Геометричний алгоритм Pure Pursuit: розрахунок кривини

На відміну від Carrot Chaser, класичний метод [чистої погоні (Pure Pursuit)](root:sys-dron/pure-pursuit-navigation) будує геометричну траєкторію у вигляді дуги кола постійного радіуса `R`, яка виходить із поточної точки під поточним курсом апарата і влучає в точку перетину лінії шляху з колом радіуса `L_d` (lookahead distance).

Нехай `η` — кут між вектором поточної швидкості дрона та вектором на цільову точку перетину на лінії шляху. Тоді необхідна кривина траєкторії `κ` обчислюється за формулою:

```
κ = 1 / R = (2 · sin(η)) / L_d                [кривина траєкторії pure pursuit]
```

Для літаків та крилатих безпілотників кривина `κ` миттєво переводиться в команду поперечного нормального прискорення `a_y` та відповідний кут крену `ϕ_cmd`:

```
a_y,cmd = v² · κ = (2 · v² · sin(η)) / L_d    [командне бічне прискорення]
ϕ_cmd   = atan( a_y,cmd / g ) = atan( (v² · κ) / g )   [командний крен для скоординованого віражу]
```

де `g ≈ 9.81` м/с² — прискорення вільного падіння, `v` — дійсна шляхова швидкість.

Цей закон автоматично масштабує інтенсивність розвороту залежно від швидкості польоту: на високій швидкості за тієї самої геометрії потрібен менший кут кривини, що захищає планер від перевантажень.

## Алгоритм прямої видимості (Line-of-Sight LOS) та векторне поле

Найпоширенішим і математично обґрунтованим стандартом ведення безпілотників по лінії є закон наведення прямої видимості (**Line-of-Sight, LOS Guidance**). Він створює плавне векторне поле напрямків, де бажаний курс є функцією базового азимута відрізка `χ_F` та величини бічного зміщення `e_ct`.

Базовий азимут лінії відрізка:

```
χ_F = atan2( y_B − y_A,  x_B − x_A )          [орієнтація відрізка у світі]
```

Кут корекції входу на лінію `χ_cross` обчислюється через арктангенс відношення похибки `e_ct` до дистанції випередження `Δ_los`:

```
χ_cross = atan( −e_ct / Δ_los )               [кут входу на лінію]
χ_cmd   = χ_F + χ_cross = χ_F − atan( e_ct / Δ_los )   [закон наведення LOS]
```

![Векторне поле наведення LOS](/root/sys/sys-dron/vidkhylennia-vid-linii-shliakhu-cross-track/img/los-vector-field.svg)
*Векторне поле наведення прямої видимості (Line-of-Sight). Стрілки показують заданий напрямок швидкості в кожній точці простору. Вдалині від лінії кут наближається до максимального кута захоплення, а поблизу осі експоненційно зливається з базовим напрямком шляху χ_F.*

Властивості векторного поля LOS:
1. **На великій відстані від лінії (`|e_ct| ≫ Δ_los`):** дріб `e_ct / Δ_los` стає великим, а `atan` наближається до граничного кута `±90°`. Дрон прямує до лінії шляху практично під прямим кутом, швидко скорочуючи боковий розрив. На практиці цей кут програмно обмежують величиною `χ_max ≈ 45°..60°`, щоб зберегти рух у напрямку цілі.
2. **Поблизу осі (`|e_ct| ≪ Δ_los`):** кут наближається до нуля за лінійним законом `χ_cross ≈ −e_ct / Δ_los`. Швидкість зменшення похибки стає строго пропорційною самій похибці:

```
ė_ct = −v · sin( atan( e_ct / Δ_los ) ) ≈ −(v / Δ_los) · e_ct   [лінеаризована динаміка]
```

Розв'язок цього диференціального рівняння описує плавне експоненційне затухання відхилення `e_ct(t) = e_ct(0) · exp(−t / τ)` зі сталою часу:

```
τ = Δ_los / v                                 [стала часу збіжності]
```

Стала часу `τ` визначає темп повернення на лінію: якщо літак летить на швидкості `v = 20` м/с із параметром `Δ_los = 40` м, стала часу становить `τ = 2.0` секунди. Через час `3 · τ = 6` секунд початкове відхилення зменшується на 95%.

## Порівняння основних алгоритмів ведення по лінії

В інженерній практиці автономних літальних апаратів застосовують чотири базові сімейства алгоритмів. Їхні властивості, обчислювальна складність та чутливість до збурень суттєво відрізняються:

| Алгоритм | Вихідна команда | Головний параметр | Стійкість до вітру | Поведінка при великих відхиленнях |
|---|---|---|---|---|
| **Carrot Chaser** | Курс на точку `χ_cmd` | Відстань `Δ` | Низька (постійне зміщення) | Агресивний вихід, можливі коливання |
| **Pure Pursuit** | Кривина `κ` (радіус `R`) | Радіус кола `L_d` | Середня (без інтегратора) | Гладка дуга віражу без перевантажень |
| **LOS Guidance** | Шляховий курс `χ_cmd` | Випередження `Δ_los` | Висока (з інтегратором ILOS) | Асимптотичне експоненційне зближення |
| **L1 Controller** | Бічне прискорення `a_y` | Період `T_L1` (або `L_1`) | Дуже висока (демпфований рух) | Нелінійне насичення за креном |

Сучасні автопілоти (зокрема PX4 та ArduPilot Plane) використовують модифікації законів LOS та L1 Nonlinear Guidance завдяки їхній гарантованій стійкості за Ляпуновим та легкій інтеграції з контуром компенсації зносу вітром.

## Боковий вітер та інтегральна компенсація (ILOS)

При польоті в атмосфері вектор швидкості літака відносно повітря (air velocity) та вектор швидкості відносно землі (ground velocity) різняться на вектор швидкості вітру `v_wind`. 

Якщо на дрон діє постійний боковий вітер `v_w`, літак змушений летіти під кутом зносу (кутом усунення дрейфу / crab angle `β_w`):

```
sin(β_w) ≈ v_w / v                            [кут зносу вітром]
```

Якщо використовувати класичний закон LOS без інтегратора, виникає статична рівновага: літак повертає ніс проти вітру лише за рахунок кута корекції `χ_cross`, який виникає внаслідок наявності бокового відхилення. Тобто апарат продовжує політ паралельно лінії шляху, але з постійною ненульовою статичною похибкою `e_ct,ss`:

```
e_ct,ss = Δ_los · tan(β_w) ≈ Δ_los · (v_w / v) [статична похибка без інтегратора]
```

За вітру 6 м/с, швидкості літака 18 м/с та `Δ_los = 36` м статичне зміщення становить `36 · (6 / 18) = 12` метрів. Дрон летітиме паралельно лінії, зсунувшись на 12 метрів з підвітряного боку.

Для повної ліквідації статичної похибки вводиться інтегральний закон **ILOS (Integral Line-of-Sight)**. До поточного відхилення додається інтеграл накопиченої похибки:

```
e_ct,eff = e_ct + k_i · ∫ e_ct dt             [ефективна похибка з інтегратором]
χ_cmd    = χ_F − atan( e_ct,eff / Δ_los )     [закон наведення ILOS]
```

Інтегратор накопичує зміщення, доки `e_ct` не стане строго рівним нулю. Щоб уникнути накопичення надлишкового інтеграла під час різких розворотів або тривалого виходу на лінію (явище windup), інтегральну суму обов'язково обмежують жорстким порогом (anti-windup clamping):

```
|∫ e_ct dt| ≤ I_max                           [захист від насичення інтегратора]
```

## Перемикання сегментів місії та крайові випадки

Навігаційний автомат переходу між послідовними точками маршруту `W_0 → W_1 → W_2 → ...` повинен надійно фіксувати момент завершення поточного відрізка. Існують два взаємодоповнюючі критерії перемикання:

1. **Радіус досягнення точки (acceptance radius `R_acc`):** коли пряма евклідова відстань від поточної позиції `p` до цільової точки `W_B` стає меншою за заданий радіус `||p − W_B|| ≤ R_acc`.
2. **Перетин площини бісектриси (нормалі):** коли поздовжня пройдена відстань перевищує повну довжину сегмента `s ≥ L_AB` (або параметр прогресу `u ≥ 1.0`).

Перевірка перетину нормалі є критично важливою: якщо через сильний вітер або великий радіус віражу дрон пролітає повз точку `W_B` на відстані `R_acc + 2` метри, він ніколи не влучить у коло радіуса `R_acc`. Без перевірки умови `s ≥ L_AB` літак увійде в нескінченний розворот (циркуляцію) навколо пропущеної точки замість переходу до наступного етапу місії.

### Захист від вироджених випадків у коді

Під час реалізації алгоритму необхідно враховувати критичні крайові умови:
- **Нульова довжина сегмента (`L_AB < 1e-6`):** якщо дві послідовні точки місії мають однакові координати, ділення на `L_AB` призведе до появи `NaN` та зависання системи керування. Такий відрізок має негайно пропускатися автопілотом.
- **Розрив фази кута курсу на межі `±π`:** обчислення різниці кутів курсу завжди має пропускатися через функцію нормалізації `wrap_to_pi(angle)`, інакше при переході через північний азимут (0° / 360°) різниця між курсом 359° та 1° складе 358° замість правильних 2°.
- **Адаптація дистанції випередження до швидкості:** для збереження стійкості на різних режимах польоту параметр `Δ_los` масштабують пропорційно швидкості `Δ_los = clamp(v · k_t, Δ_min, Δ_max)`, де `k_t` — базовий часовий горизонт випередження (зазвичай 2.0–3.5 секунди).

#include <math.h>
#include <stdbool.h>

#ifndef M_PI
#define M_PI 3.14159265358979323846
#endif

typedef struct {
    double x;
    double y;
} vec2_d;

typedef struct {
    double lookahead_dist; /* Базове випередження Delta_los [м] */
    double lookahead_time; /* Коефіцієнт часу Delta = v * k_t [с] */
    double min_lookahead;  /* Мінімальне випередження [м] */
    double max_lookahead;  /* Максимальне випередження [м] */
    double ki;             /* Коефіцієнт інтегратора вітру [1/с] */
    double int_limit;      /* Поріг інтегратора [м*с] */
    double max_cross_ang;  /* Максимальний кут захоплення лінії [рад] */
} crosstrack_cfg_t;

typedef struct {
    double ect;            /* Поперечна похибка e_ct зі знаком [м] */
    double along_track;    /* Поздовжня пройдена відстань s [м] */
    double progress;       /* Параметр відрізка u in [0, 1] */
    vec2_d proj_pt;        /* Точка ортогональної проєкції p_proj [м] */
    double course_cmd;     /* Командний шляховий курс chi_cmd [рад] */
    double curvature_cmd;  /* Бажана кривина траєкторії kappa [1/м] */
} crosstrack_out_t;

static inline double math_wrap_pi(double rad) {
    while (rad > M_PI) rad -= 2.0 * M_PI;
    while (rad < -M_PI) rad += 2.0 * M_PI;
    return rad;
}

static inline double math_clamp(double v, double min_v, double max_v) {
    if (v < min_v) return min_v;
    if (v > max_v) return max_v;
    return v;
}

bool calculate_crosstrack_guidance(vec2_d pos,
                                   vec2_d wa,
                                   vec2_d wb,
                                   double ground_speed,
                                   double dt,
                                   const crosstrack_cfg_t *cfg,
                                   double *integrator_state,
                                   crosstrack_out_t *out) {
    /* 1. Вектор відрізка b = WB - WA */
    double bx = wb.x - wa.x;
    double by = wb.y - wa.y;
    double seg_len = sqrt(bx * bx + by * by);

    if (seg_len < 1e-6) {
        return false; /* Некоректний сегмент нульової довжини */
    }

    /* 2. Одиничний дотичний вектор t̂ = b / seg_len */
    double tx = bx / seg_len;
    double ty = by / seg_len;

    /* 3. Вектор положення від початку a = pos - WA */
    double ax = pos.x - wa.x;
    double ay = pos.y - wa.y;

    /* 4. Поперечна похибка e_ct через 2D-векторний добуток a × t̂ */
    double ect = ax * ty - ay * tx;

    /* 5. Поздовжня пройдена відстань s = a · t̂ */
    double s = ax * tx + ay * ty;
    double u = s / seg_len;

    /* 6. Координати точки проєкції */
    vec2_d proj = { wa.x + s * tx, wa.y + s * ty };

    /* 7. Адаптивна дистанція прямої видимості */
    double delta_los = ground_speed * cfg->lookahead_time;
    if (delta_los < cfg->lookahead_dist) {
        delta_los = cfg->lookahead_dist;
    }
    delta_los = math_clamp(delta_los, cfg->min_lookahead, cfg->max_lookahead);

    /* 8. Інтегрування похибки для компенсації вітру (ILOS) */
    if (integrator_state != NULL && dt > 0.0) {
        *integrator_state += ect * dt;
        *integrator_state = math_clamp(*integrator_state, -cfg->int_limit, cfg->int_limit);
    }
    double int_val = (integrator_state != NULL) ? *integrator_state : 0.0;
    double ect_eff = ect + cfg->ki * int_val;

    /* 9. Розрахунок кута корекції та командного курсу */
    double chi_f = atan2(by, bx);
    double chi_cross = atan(-ect_eff / delta_los);
    chi_cross = math_clamp(chi_cross, -cfg->max_cross_ang, cfg->max_cross_ang);

    double chi_cmd = math_wrap_pi(chi_f + chi_cross);
    double kappa = 2.0 * sin(chi_cross) / delta_los;

    /* 10. Запис результатів */
    out->ect = ect;
    out->along_track = s;
    out->progress = u;
    out->proj_pt = proj;
    out->course_cmd = chi_cmd;
    out->curvature_cmd = kappa;

    return true;
}

#include <cmath>
#include <numbers>
#include <algorithm>
#include <optional>

struct Vec2d {
    double x{0.0};
    double y{0.0};

    [[nodiscard]] constexpr Vec2d operator+(const Vec2d& o) const noexcept { return { x + o.x, y + o.y }; }
    [[nodiscard]] constexpr Vec2d operator-(const Vec2d& o) const noexcept { return { x - o.x, y - o.y }; }
    [[nodiscard]] constexpr Vec2d operator*(double s) const noexcept { return { x * s, y * s }; }
    [[nodiscard]] constexpr double dot(const Vec2d& o) const noexcept { return x * o.x + y * o.y; }
    [[nodiscard]] constexpr double cross(const Vec2d& o) const noexcept { return x * o.y - y * o.x; }
    [[nodiscard]] double norm() const noexcept { return std::hypot(x, y); }
};

struct CrossTrackConfig {
    double lookahead_dist{35.0};
    double lookahead_time{2.5};
    double min_lookahead{20.0};
    double max_lookahead{120.0};
    double ki{0.03};
    double int_limit{50.0};
    double max_cross_ang{55.0 * std::numbers::pi / 180.0};
};

struct CrossTrackOutput {
    double ect{0.0};
    double along_track{0.0};
    double progress{0.0};
    Vec2d proj_pt{};
    double course_cmd{0.0};
    double curvature_cmd{0.0};
};

class CrossTrackGuidance {
public:
    explicit CrossTrackGuidance(CrossTrackConfig cfg) : cfg_(cfg) {}

    void reset_integrator() noexcept {
        integrator_state_ = 0.0;
    }

    [[nodiscard]] std::optional<CrossTrackOutput> calculate(Vec2d pos,
                                                           Vec2d wa,
                                                           Vec2d wb,
                                                           double ground_speed,
                                                           double dt) noexcept {
        const Vec2d b = wb - wa;
        const double seg_len = b.norm();

        if (seg_len < 1e-6) {
            return std::nullopt;
        }

        const Vec2d t_hat = b * (1.0 / seg_len);
        const Vec2d a = pos - wa;

        /* 1. Поперечна похибка e_ct = a × t̂ */
        const double ect = a.cross(b) / seg_len;

        /* 2. Поздовжня відстань s = a · t̂ */
        const double s = a.dot(t_hat);
        const double u = s / seg_len;
        const Vec2d proj = wa + t_hat * s;

        /* 3. Адаптивне випередження */
        const double delta_los = std::clamp(std::max(cfg_.lookahead_dist, ground_speed * cfg_.lookahead_time),
                                            cfg_.min_lookahead,
                                            cfg_.max_lookahead);

        /* 4. Інтегратор похибки (ILOS) */
        if (dt > 0.0) {
            integrator_state_ = std::clamp(integrator_state_ + ect * dt,
                                           -cfg_.int_limit,
                                           cfg_.int_limit);
        }
        const double ect_eff = ect + cfg_.ki * integrator_state_;

        /* 5. Розрахунок кутів */
        const double chi_f = std::atan2(b.y, b.x);
        const double chi_cross = std::clamp(std::atan(-ect_eff / delta_los),
                                            -cfg_.max_cross_ang,
                                            cfg_.max_cross_ang);

        const double chi_cmd = wrap_pi(chi_f + chi_cross);
        const double kappa = 2.0 * std::sin(chi_cross) / delta_los;

        return CrossTrackOutput{ ect, s, u, proj, chi_cmd, kappa };
    }

private:
    static double wrap_pi(double rad) noexcept {
        while (rad > std::numbers::pi) rad -= 2.0 * std::numbers::pi;
        while (rad < -std::numbers::pi) rad += 2.0 * std::numbers::pi;
        return rad;
    }

    CrossTrackConfig cfg_;
    double integrator_state_{0.0};
};

## Архітектурне місце алгоритму в автопілотах

В ієрархії бортового програмного забезпечення (такого як PX4 Autopilot або ArduPilot) алгоритм обчислення відхилення від лінії шляху займає ключове місце у зовнішньому контурі горизонтальної навігації:

```
[ Менеджер місії (Waypoints) ]
            │
            ▼
[ Модуль відхилення (Cross-Track & LOS) ] ───► e_ct, along-track s, chi_cmd, kappa
            │
            ▼
[ Контур бічного керування (L1 / TECS / Lateral Controller) ] ───► Roll / Yaw rate
            │
            ▼
[ Внутрішній контур орієнтації (Attitude PID / Rate Loop) ] ───► Сервоприводи / Елерони
```

Модуль Cross-Track бере з плану місії координати поточної та наступної точок, отримує від фільтра Калмана (EKF) оцінку поточної позиції й шляхової швидкості та перетворює геометрію лінії у єдину команду — бажаний курс `χ_cmd` або бажану кривину `κ`. Нижчі контури керування кутами крену й рискання реалізують цю команду на рівні виконавчих приводів, повністю абстрагуючись від складності геометрії маршруту.
