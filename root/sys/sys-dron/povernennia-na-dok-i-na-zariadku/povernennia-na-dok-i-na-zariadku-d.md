# Повернення на док і на зарядку: стикування, центрування та контроль живлення

<preknowlist>
- [Безпечний відмов (failsafe)](root:sys-dron/failsafe) — виявлення втрати зв'язку та запуск рятувальних процедур
- [Повернення додому](root:sys-dron/povernennia-dodomu) — фази набору висоти, маршового транзиту та енергетичний бюджет
- [RTK на практиці](root:sys-dron/rtk-na-praktytsi) — подвійні різниці фаз несучої, стан Fixed та сантиметрова точність
- [Низька батарея](root:sys-dron/nyzka-batareia) — розрахунок залишкової ємності, просідання напруги під навантаженням та пороги повернення
- [Автопосадка](root:sys-dron/avtoposadka) — фінальне зниження, детект торкання землі та вимкнення моторів
</preknowlist>

Коли безпілотний апарат завершує автономний моніторинговий політ за сорок кілометрів від оператора, стандартна процедура повернення додому за координатами супутникової навігації лише виводить дрон у загальний район розташування бази. Навіть дводіапазонний приймач супутникових сигналів у режимі RTK Fixed із теоретичною похибкою два сантиметри не гарантує безпомилкового потрапляння шасі в контактну групу зарядного майданчика. Багатопроменеве перевідбиття радіохвиль від металевих стулок захисного купола станції, пориви приземного вітру зі швидкістю до десяти метрів на секунду та теплові деформації конструкції створюють сумарне відхилення у 10–25 сантиметрів. Якщо важкий квадрокоптер опуститься повз приймальні воронки або стане на пружні клеми з перекосом у п'ять градусів за курсом, силові контакти не замкнуться, захисний дах заклинить лопаті пропелерів, а спроба подати зарядний струм силою п'ятнадцять ампер через брудний перехідний опір спричинить електричну дугу й займання акумуляторного відсіку.

Повноцінна концепція автономного дрона в захисному контейнері (*Drone-in-a-Box*, DiaB) потребує багатоланцюгової взаємозв'язаної системи: від переходу з глобальної радіонавігації на локальне оптичне та інфрачервоне наведення до механічного затискання шасі, чотирипровідної діагностики контактної пари та цифрового протоколу керування зарядом акумулятора.

![Ієрархічні ешелони наближення, позиціонування та стикування з док-станцією](/root/sys/sys-dron/povernennia-na-dok-i-na-zariadku/img/docking-approach-phases-and-sensors.svg)
*Чотири послідовні фази наближення дрона до автоматизованої док-станції: транзит за супутниковими поправками RTK, оптичне наведення на вкладені маркери AprilTag та інфрачервоний маяк, механічне самоцентрування у напрямних воронках і замикання силового електричного контуру.*

### Фізична піраміда наближення: від супутника до контактного майданчика

Помилка просторового позиціонування під час посадки мусить зменшуватися значно швидше, ніж скорочується дистанція між апаратом і поверхнею станції. Якщо на висоті п'ятдесяти метрів похибка у пів метра є цілком прийнятною, то на висоті двадцяти сантиметрів допустиме відхилення не повинно перевищувати трьох міліметрів. Жоден окремий клас датчиків не здатний покрити такий динамічний діапазон точності й дальності одночасно.

Система керування розділяє простір наближення на три просторові ешелони:

1. **Макронавігація (від 1000 м до 15 м над станцією):** автопілот веде дрон за вектором шляхової швидкості, використовуючи дводіапазонний модуль RTK-GNSS. Базова станція поправок інтегрована безпосередньо в раму дока або підключена через локальну мережу за протоколом RTCM v3. Позиція апарата розраховується з точністю 10–20 см.
2. **Мезонавігація (від 15 м до 0.5 м над платформою):** на бортовому комп'ютері активується спрямована вниз курсова камера та інфрачервоний оптичний сенсор. Алгоритми комп'ютерного зору знаходять реперні маркери (AprilTag, ArUco) або виявляють модульований ІЧ-маяк, розташований у центрі посадкового лотка. Точність розрахунку просторового вектора зміщення становить 1–2 см за горизонталлю та менше одного градуса за кутом рискання (Yaw).
3. **Мікронавігація та механічне центрування (від 0.5 м до повного контакту):** після торкання посадкових напрямних електродвигуни негайно роззброюються (*disarm*), а кінематична геометрія воронки або рухомі сервоприводні лапи примусово центрують апарат, усуваючи залишкові відхилення до величини менше 1.0 мм.

Такий розподіл гарантує, що відмова або тимчасове засліплення одного контуру наведення перехоплюється попереднім ешелоном стабілізації.

```
+-------------------------------------------------------------------------+
|                  ІЄРАРХІЯ СЕНСОРІВ ТА ТОЧНОСТІ DiaB                     |
+-------------------------------------------------------------------------+
|  Ешелон      | Датчики / Канал      | Дальність | Точність | Помилка Yaw|
|--------------+----------------------+-----------+----------+------------|
|  Макро       | RTK-GNSS (L1/L2)     | 1000–15 м | 10–20 см | 2.0–5.0°   |
|  Мезо        | AprilTag / IR-Beacon | 15–0.5 м  | 1–2 см   | 0.3–0.8°   |
|  Мікро       | Лідар / Воронки      | 0.5–0.0 м | 1–3 мм   | < 0.2°     |
|  Фіксація    | Крокові лапи / Реле  | 0 мм      | ±0.5 мм  | ±0.1°      |
+-------------------------------------------------------------------------+
```

### Грубе супутникове наведення: RTK та динамічна база

На етапі транзиту дрон розраховує траєкторію виходу на точку очікування (*Holding Point*). Ця точка розташовується строго на осі підходу до док-станції на висоті 15–20 метрів над верхнім зрізом захисного люка. Вихід у точку очікування здійснюється з обов'язковим урахуванням вектора приземного вітру: апарат заходить на станцію носом проти вітру, що мінімізує крени та стабілізує кут огляду бортової камери.

Цільова просторова точка очікування в локальній системі координат NED обчислюється як:

```
P_holding = P_dock + [0, 0, -H_hold]^T   [точка очікування над доком у системі NED]
```

Для передачі диференційних поправок RTCM від базового GNSS-приймача дока до безпілотника застосовується стек MAVLink із повідомленнями `GPS_RTCM_DATA`:

```
┌─────────────────┐  RTCM3 поправки   ┌─────────────────┐  MAVLink GPS_RTCM_DATA  ┌─────────────────┐
│ GNSS Base (Dock)│──────────────────→│ Dock Controller │────────────────────────→│ UAV Autopilot   │
└─────────────────┘   UART / 115200   └─────────────────┘     Wi-Fi / 5.8 GHz     └─────────────────┘
```

Якщо док-станція встановлена на мобільній платформі (наприклад, палубі судна або кузові автомобіля), використовується режим *Moving Baseline RTK*. У цьому режимі базова станція передає не статичні координати, а сирі фазові спостереження несучої в реальному часі. Бортовий приймач безпосередньо обчислює вектор відносної дальності між рухомим дроном і рухомою платформою, усуваючи похибки, викликані качкою судна чи рухом транспортного засобу.

Проте за 15 метрів до майданчика виникає фундаментальне фізичне обмеження супутникової навігації: металеві стінки захисного боксу, радіопрозорий пластиковий купол і навколишні інженерні споруди створюють потужний ефект багатопроменевості (*multipath*). Фазові вимірювання починають флуктувати, статус RTK Fixed може короткочасно деградувати до RTK Float із похибкою до 50 см. Тому на висоті п'ятнадцяти метрів автопілот беззастережно передає пріоритет контуру візуального наведення.

### Оптичне та інфрачервоне прецизійне наведення

Для візуального захоплення цілі на посадковій плиті встановлюється контрастний двовимірний матричний маркер. Найвищу стабільність детекції в умовах зміни освітленості та часткового розмиття рухом демонструють маркери сімейства **AprilTag 36h11** та словники **ArUco**.

Головна оптична проблема посадки дрона полягає у зміні масштабу. З висоти п'ятнадцяти метрів маркер розміром 10×10 см займає на матриці камери площу всього кілька пікселів і не може бути розпізнаний через недостатню роздільну здатність. Якщо ж встановити маркер розміром 80×80 см, то під час зниження до висоти пів метра він повністю вийде за межі поля зору камери (*Field of View*, FOV).

Для подолання цієї дилеми застосовують систему **вкладених маркерів** (*Nested Tags*):

```
┌─────────────────────────────────────────────────────────┐
│  Великий маркер Tag ID: 0 (800 × 800 мм)                │
│  Робоча зона: висота від 20 м до 3.5 м                  │
│                                                         │
│         ┌─────────────────────────────────────┐         │
│         │  Середній маркер Tag ID: 1 (200 мм) │         │
│         │  Робоча зона: від 4.0 м до 0.8 м    │         │
│         │                                     │         │
│         │       ┌─────────────────────┐       │         │
│         │       │ Малий Tag ID: 2     │       │         │
│         │       │ (50 мм, 0.9–0.1 м)  │       │         │
│         │       └─────────────────────┘       │         │
│         └─────────────────────────────────────┘         │
└─────────────────────────────────────────────────────────┘
```

Бортовий комп'ютер захоплює відеопотік із частотою 30–60 кадрів на секунду, виконує бінаризацію за адаптивним порогом, виділяє чотирикутні контури та розв'язує задачу Perspective-n-Point (PnP). Алгоритм PnP обчислює вектор відносного положення `T = [t_x, t_y, t_z]^T` та матрицю повороту `R` у системі координат камери на основі відомих фізичних розмірів кутів маркера та матриці внутрішніх параметрів камери `K`:

```
K = ⎡ f_x   0   c_x ⎤
    ⎢  0   f_y  c_y ⎥   [матриця внутрішніх параметрів оптичної камери]
    ⎣  0    0    1  ⎦
```

```
s · ⎡ u ⎤   ⎡ r_11  r_12  r_13  t_x ⎤   ⎡ X_tag ⎤
    ⎢ v ⎥ = ⎢ r_21  r_22  r_23  t_y ⎥ · ⎢ Y_tag ⎥   [проекційне PnP-перетворення]
    ⎣ 1 ⎦   ⎣ r_31  r_32  r_33  t_z ⎦   ⎢ Z_tag ⎥
                                        ⎣   1   ⎦
```

Для пласких маркерів класичні алгоритми PnP страждають від проблеми двозначності оцінки нахилу (*Planar Pose Ambiguity*), коли дзеркально відбита поза дає майже ідентичну проекцію на площину матриці. Для усунення цього артефакту застосовують спеціалізовані методи оптимізації (IPPE — *Infinitesimal Plane-based Pose Estimation*), які обчислюють обидва аналітичні розв'язки й обирають фізично коректний на основі попереднього вектора швидкості від фільтра Калмана.

Отриманий вектор відносного зміщення трансформується з оптичної системи координат камери в систему координат зв'язаного базису дрона (*Body Frame*), а потім передається польотному контролеру через повідомлення MAVLink `LANDING_TARGET`:

:::tabs


#### Інфрачервоне наведення (Active IR Beacons)

В умовах нічного польоту, щільного туману, дощу або прямого засвічення низьким сонцем оптичні маркери втрачають контрастність. Для гарантованої всепогодності майданчик док-станції оснащують активним **інфрачервоним маяком**.

Маяк складається з матриці надяскравих ІЧ-світлодіодів із довжиною хвилі 850 або 940 нм, які випромінюють імпульсний сигнал, модульований несівною частотою 38 кГц (за стандартом IR-LOCK). На борту дрона встановлюється сенсор із вузькосмуговим оптичним фільтром, який пропускає виключно випромінювання заданого спектра і відсікає денне сонячне світло. Датчик апаратно детектує центр плями випромінювання на частоті 50 Гц і видає кутові відхилення автопілоту, дозволяючи виконувати спуск у повній темряві без демаскувального видимого підсвічування.

### Комплексування вимірювань у розширеному фільтрі Калмана (EKF)

Сирі візуальні координати від камери мають дві неприємні властивості: часову затримку обробки кадрів (*latency*) величиною 30–80 мс та шум дискретизації піксельної сітки. Якщо подати ці координати безпосередньо в контур регулятора положення, дрон почне розгойдуватися над мішенню через фазовий зсув сигналу зворотного зв'язку.

Для згладжування та компенсації затримки на бортовому комп'ютері функціонує розширений фільтр Калмана (EKF). Вектор стану фільтра описує відносне тривимірне положення та швидкість мішені в системі координат дока:

```
x_k = [ p_x, p_y, p_z, v_x, v_y, v_z, psi_dock ]^T   [вектор стану EKF посадки]
```

Динамічна модель перерахунку базується на показниках бортового інерційного блоку IMU (кутові швидкості `ω` та лінійні прискорення `a`):

```
p_(k+1) = p_k + v_k · Δt + 0.5 · (R_body^dock · a_imu - g) · Δt^2   [прогноз положення]
v_(k+1) = v_k + (R_body^dock · a_imu - g) · Δt                     [прогноз швидкості]
```

Коли від оптичного модуля надходить новий кадр із міткою часу `t_frame`, фільтр відкочує свій стан у буфер спостережень на величину затримки кадру `Δt_lag = t_now - t_frame`, виконує корекцію матриці коваріацій за PnP-виміром і повторно інтегрує стан до поточного моменту часу `t_now`. Це усуває запізнювання та видає автопілоту гладкі векторні уставки швидкості без фазового відставання.

### Динаміка спуску, вітрові збурення та критерії відходу на друге коло

Під час зниження док-станція створює специфічний аеродинамічний бар'єр: відкриті стулки люка та стінки боксу утворюють аеродинамічну яму. Приземний вітер, набігаючи на край контейнера, зривається у вихори, формуючи низхідні та висхідні струмені з локальною турбулентністю.

Автопілот адаптує коефіцієнти зворотного зв'язку регулятора положення залежно від висоти `h`:

```
K_p_xy(h) = K_p_base · (1.0 + α_gain / (h + h_offset))   [динамічне посилення чутливості]
```

При наближенні до поверхні пропорційний коефіцієнт зростає, змушуючи контур стабілізації швидше парирувати бічні зсуви. Одночасно обмежується інтегральна складова регулятора, щоб уникнути накопичення помилки (*integrator windup*) під час потрапляння шасі на похилі стінки воронки.

```
       [ ЗНИЖЕННЯ h < 1.5 м ]
                 │
      ┌──────────┴──────────┐
      │  Перевірка умов     │
      │  безпеки спуску     │
      └──────────┬──────────┘
                 │
  ┌──────────────┴───────────────────────────────┐
  │ Помилка горизонталі e_xy > 15 см?            │
  │ Швидкість спуску v_z > 0.5 м/с?              │─── ТАК ──→ [ СКАСУВАННЯ ПОСАДКИ (Go-Around) ]
  │ Втрата оптичного маркеру > 200 мс?           │             Підйом на h = 10 м, новий захід
  │ Кут нахилу платформи > 8°?                   │
  └──────────────┬───────────────────────────────┘
                 │ НІ (Все в нормі)
                 ▼
     [ ТОРКАННЯ ВОРОНКИ ТА DISARM ]
```

Якщо під час фінального зниження (на висоті менше півтора метра) бічний порив вітру зміщує апарат більше ніж на 15 см від оптичного центру або оптичний маркер зникає з кадру довше ніж на 200 мс, алгоритм негайно ініціює процедуру відходу на друге коло (*Go-Around*). Мотори форсуються на повну тягу набору висоти, дрон повертається на ешелон очікування 10–15 метрів і повторює спробу наближення за оновленим вітровим вектором.

### Механічне позиціонування та вирівнювання осей

Коли дрон опускається нижче двадцяти сантиметрів, виникає складне явище — **екранний ефект землі** (*Ground Effect*) та турбулентна рециркуляція повітряних потоків, відбитих від стінок посадкового відсіку дока. Повітряні вихори штовхають апарат убік, намагаючись скинути його з центру платформи. Контур керування вже не встигає компенсувати ці високочастотні мікропориви.

Тому фінальне стикування покладається на пасивну або активну механіку.

```
       Дрон знижується              Торкання воронки            Центрування у гнізді
       
          ┌───────┐                    ┌───────┐                    ┌───────┐
          │  UAV  │                    │  UAV  │                    │  UAV  │
          └──┬─┬──┘                    └──┬─┬──┘                    └──┬─┬──┘
             │ │                          │ │                          │ │   
             ▼ ▼                          ▼ ▼                          │ │   
        \         /                  \   │     /                  \    │ │    /
         \       /      ────→         \  ▼    /      ────→         \   │ │   / 
          \  ○  /                      \  ○  /                      \───○───/  
           └───┘                        └───┘                        └─────┘   
       Напрямна воронка              Ковзання конуса              Силовий контакт
```

У сучасних автоматизованих станціях застосовують три типи механічного позиціонування:

1. **Пасивні конічні напрямні (Guiding Funnels):** кінці посадкових опор дрона закінчуються конічними або сферичними штифтами з низьким коефіцієнтом тертя (фторопласт, поліформальдегід або полірована неіржавна сталь). На платформі змонтовано чотири воронкоподібні заглиблення з кутом нахилу стінок 30–45°. Під час опускання штифти потрапляють на похилу поверхню і під власною вагою апарата зісковзують до центру, де розташована контактна група.
2. **Активні центруючі штанги (Robotic Clamping Arms):** платформа виконана у вигляді пласкої плити. Після того, як автопілот глушить мотори, контролер док-станції вмикає два лінійні крокові приводи з паралельними планками. Планки рухаються назустріч одна одній по осі X, зміщуючи лижі дрона в центр, а потім друга пара планок стискає шасі по осі Y. Одночасно планки примусово розвертають апарат за кутом Yaw, орієнтуючи корпус із точністю до десятих часток міліметра.
3. **Захисний купол (Clamshell Mechanism):** стулки док-станції мають форму сферичного або двосхилого купола. Привід закривання оснащений струмовим захистом від защемлення: якщо пропелер дрона не зупинився в горизонтальному положенні або став у зоні перекриття, контролер фіксує стрибок струму двигуна люка, негайно зупиняє рух, відводить стулку назад і подає сигнал сервоприводу довороту гвинтів.

### Електричний інтерфейс та конструкція контактної пари

Надійне передавання зарядного струму 10–30 А через відкриті контакти на вулиці — одне з найскладніших інженерних завдань у системах DiaB. Контактні майданчики зазнають впливу пилу, піску, дощової води з розчиненими солями та конденсату.

Застосовують дві базові схеми контактних вузлів:

* **Концентричні кругові доріжки:** на посадковій плиті розміщено кілька ізольованих латунних кілець із гальванічним золоченням товщиною не менше 3–5 мкм. На шасі дрона встановлено підпружинені струмознімачі (кулькові плунжери або щітки). Така конструкція забезпечує електричний контакт при довільному куті посадки за азимутом (Yaw invariant), проте кільця схильні до накопичення снігу та бруду.
* **Штирові пружні клеми (Pogo-Pins) з дренажними каналами:** контакти висуваються крізь захисні ущільнення лише після посадки та фіксації дрона. Усередині контактного гнізда передбачено нагрівальний елемент потужністю 30–50 Вт, який розтоплює лід і випаровує вологу перед початком сеансу заряджання.

### Схема комутації та силова електроніка

Електрична топологія зарядного вузла містить захисні ключі як на боці наземної станції, так і на борту безпілотника.

![Принципова схема комутації, діагностики та захисту заряду](/root/sys/sys-dron/povernennia-na-dok-i-na-zariadku/img/dock-charging-circuit-and-state-machine.svg)
*Принципова електрична схема док-станції та безпілотника: вимірювальний зонд Кельвіна, силове реле комутації, зворотний ідеальний діод, захисні TVS-супресори та шина обміну даними BMS.*

Станція містить такі обов'язкові вузли силового захисту:
* **Ідеальний діод (Active Reverse-Polarity MOSFET):** захищає силове джерело станції та акумулятор дрона від зустрічного струму при помилковому підключенні або випадковому короткому замиканні. На відміну від діодів Шотткі з падінням 0.5 В, польовий N-канальний транзистор із відкритим каналом 1.5 мОм розсіює менше 1 Вт тепла при струмі 25 А.
* **TVS-супресори та розрядники (Transient Voltage Suppressors):** поглинають імпульсні викиди перенапруги, викликані індуктивністю довгих кабелів живлення під час комутації великих струмів.
* **Швидкодіючий електронний запобіжник (e-Fuse):** апаратний компаратор струмового шунта вимикає сигнал керування затворів силіконових ключів за час менше 2.5 мікросекунд у разі виникнення короткого замикання.

### Протокол безпечного заряджання: від зондування до реле

Подача напруги 24–50 В на відкриті контакти без попередньої перевірки категорично неприпустима. Пряме замикання клем призведе до оплавлення металу, а наявність крапель води спричинить бурхливу електрохімічну корозію та закорочення.

Процес заряджання регламентується жорстким послідовним протоколом безпеки.

```
       [ ТОРКАННЯ І ЗАХВАТ ]
                 │
                 ▼
    ┌─────────────────────────┐
    │  1. Зондування Кельвіна │
    │  I_probe = 200 мА       │
    └────────────┬────────────┘
                 │
        R_contact < 40 мОм? ───── НІ ──→ [ ВІДМОВА: Повторний затиск / продув ]
                 │ ТАК
                 ▼
    ┌─────────────────────────┐
    │  2. Перевірка полярності│
    │  та опитування BMS      │
    └────────────┬────────────┘
                 │
        CAN Handshake OK?   ───── НІ ──→ [ ВІДМОВА: Блокування живлення ]
                 │ ТАК
                 ▼
    ┌─────────────────────────┐
    │  3. Pre-charge Softstart│
    │  Плавне заряджання ємності
    └────────────┬────────────┘

```

#### Фаза 1: 4-провідне вимірювання перехідного опору (Kelvin Sensing)

Перед увімкненням потужного джерела станція підключає до контактних пар вимірювальний мікрострумовий генератор `I_probe = 200 мА`. За окремими сигнальними лініями (*Sense Lines*) високоточний 16-бітний АЦП зчитує падіння напруги безпосередньо на точці торкання клем:

```
R_contact = ΔU_sense / I_probe   [визначення перехідного опору контакту]
```

Якщо `R_contact > 40 мОм`, протокол забороняє перехід до силової фази. При робочому струмі `I = 20 А` опір усього 100 мОм призвів би до локального тепловиділення потужністю:

```
P_loss = I^2 · R_contact = 20^2 · 0.1 = 40 Вт   [потужність теплових втрат на клемах]
```

Виділення сорока ват на площі у два квадратні міліметри за лічені секунди розплавить пластиковий тримач контакту і спалить пружину струмознімача. При виявленні завищеного опору контролер дока активує циклічне стискання лап позиціонування або імпульсний електропневматичний клапан обдування контактів сухим повітрям під тиском 6 бар.

#### Фаза 2: Цифровий Handshake та опитування BMS

По паралельній шині передачі даних (CAN / DroneCAN або оптичному оптрону) станція встановлює зв'язок із бортовою системою керування батареєю (*Battery Management System*, BMS).

Док зчитує паспортні та поточні параметри батарейного пакета:
* поточну напругу кожної комірки (Cell Voltages `V_1 ... V_n`);
* температуру батареї за трьома точковими NTC-термісторами всередині паку;
* максимальний дозволений струм заряду для поточної температури акумулятора.

Якщо напруга хоча б однієї комірки опустилася нижче критичного порогу глибокого розряду (наприклад, менше 3.0 В для LiPo) або температура перевищує 45 °C, стандартний режим швидкого заряду блокується. Станція переходить у режим попереднього регенераційного заряду струмом 0.1 C або очікує охолодження комірок.

#### Фаза 3: Плавний пуск (Soft-Start Pre-Charge)

Вхідні ланцюги живлення сучасних польотних контролерів і регуляторів швидкості (ESC) містять конденсаторні батареї значної ємності (сумарно 2000–5000 мкФ) для фільтрації високочастотних перешкод від моторів.

Якщо миттєво замкнути силове реле, струм заряджання розряджених конденсаторів (*Inrush Current*) досягає 150–200 А протягом кількох мікросекунд. Це створює мікродугу між контактами та поступово руйнує золоте напилення.

Щоб запобігти стрибку, силова плата дока містить допоміжний передзарядний ключ із потужним резистором опором 10–20 Ом. Контролер відкриває передзарядний MOSFET на 150 мс, вирівнює потенціали між джерелом і шиною дрона, і лише після досягнення `ΔU < 0.5 В` замикає головне електромеханічне реле або силове MOSFET-сховище.

#### Фаза 4: CC/CV керування та тепловий захист

Заряджання здійснюється за двостадійним алгоритмом:
1. **Стадія постійного струму (Constant Current, CC):** струм утримується на рівні 1.0–2.0 C (наприклад, 15 А для батареї 10 А·год). Напруга батареї лінійно зростає.
2. **Стадія постійної напруги (Constant Voltage, CV):** після досягнення позначки 4.20 В на комірку (або 25.2 В для 6S паку) джерело фіксує напругу з точністю до ±5 мВ, а струм плавно спадає до величини відсікання (0.05 C).

Під час усього циклу контролер док-станції перевіряє безпеку кожні 50 мілісекунд. Алгоритм негайно скидає силове реле при виникненні будь-якої з подій:
* перевищення температури будь-якої комірки `T_cell > 50 °C`;
* різке зростання перехідного опору під час заряду (рух корпусу від вітру);
* обрив телеметрії BMS по шині CAN довше ніж на 200 мс;
* перекіс напруг між сусідніми комірками `ΔV_cell > 50 мВ`.

Детальний алгоритм контролера стикування, розрахунку PnP-вектора наведення та обробки телеметрії живлення реалізовано у проекті [Контролер прецизійного стикування](root:sys-dron/povernennia-na-dok-i-na-zariadku/proj-docking-controller.md).

### Протоколи телеметрії та балансування комірок

Під час заряду станція постійно отримує оновлення стану акумулятора через повідомлення стандарту DroneCAN `uavcan.equipment.power.BatteryInfo`:

```
┌─────────────────────────────────────────────────────────┐
│ uavcan.equipment.power.BatteryInfo                      │
├─────────────────────────────────────────────────────────┤
│ uint8_t  battery_id              = 0                    │
│ float32  voltage                 = 24.85 V              │
│ float32  current                 = +12.40 A             │
│ float32  temperature             = 312.15 K (+39.0 °C)  │
│ float32  state_of_charge_pct     = 84.5 %               │
│ float16  voltage_cell[6]         = [4.14, 4.15, 4.13,   │
│                                     4.14, 4.15, 4.14] V │
└─────────────────────────────────────────────────────────┘
```

Якщо різниця напруг між окремими банками перевищує `ΔV > 15 мВ`, вмикається вбудований балансувальний контур. Застосовують дві схеми балансування:
1. **Пасивне резистивне балансування:** паралельно кожній комірці через транзисторний ключ підключається навантажувальний резистор 39 Ом. При виявленні комірки з випереджальною напругою ключ відкривається, розсіюючи надлишковий струм близько 100 мА у вигляді тепла і дозволяючи іншим банкам підтягнутися до єдиного рівня.
2. **Активне індуктивне балансування:** надлишковий заряд перекачується з найбільш зарядженої комірки в найменш заряджену за допомогою мініатюрних дроселів і синхронних перетворювачів із ККД понад 90%, що запобігає зайвому нагріванню батарейного блоку всередині закритого корпусу.

Станція також виконує розрахунок внутрішнього динамічного опору комірок (DCIR):

```
R_int = (V_open_circuit - V_loaded) / I_charge   [внутрішній імпеданс комірки]
```

Зростання внутрішнього опору понад 15 мОм на комірку свідчить про хімічну деградацію акумулятора (утворення дендритів). Контролер автоматично формує діагностичне попередження для наземного оператора про необхідність регламентної заміни батарейного паку.

### Кліматичні фактори та підготовка до вильоту

Експлуатація систем DiaB у реальних польових умовах вимагає врахування екстремальних температурних режимів:

* **Зимовий режим (температура нижче 0 °C):** літієві акумулятори категорично заборонено заряджати високим струмом при температурі електроліту нижче 5 °C через ризик утворення металевого літієвого осаду на аноді (*Lithium Plating*), що призводить до внутрішнього короткого замикання. Док-станція вмикає внутрішній термобокс або нагрівальні мати навколо батарейного відсіку, доводить температуру паку до +15 °C і лише після цього починає заряджання.
* **Літній перегрів (температура понад 35 °C):** після інтенсивного польоту акумулятор прибуває з температурою 45–50 °C. Заряджання такого акумулятора без охолодження викликає деградацію катодного матеріалу. Станція активує турбінні вентилятори примусового охолодження посадкового лотка, збиваючи температуру до безпечних 30 °C.
* **Передпольотна перевірка (Pre-flight Handshake):** після завершення заряду до 100% контролер дока перевіряє стан батареї, запитує у польотного контролера статус ініціалізації датчиків, відмикає затискні лапи, відкриває захисний купол і подає команду зльоту лише після отримання підтвердження про чистий повітряний простір над станцією.

### Програмна реалізація діагностики контакту та захисту

Наведені нижче програмні модулі демонструють алгоритм чотирипровідної діагностики контактної пари, перевірки полярності напруги, розрахунку перехідного опору та безпечної комутації силового реле.

:::tabs
```c

#define MAX_BATTERY_VOLTAGE_MV               25500
#define MAX_CELL_TEMPERATURE_C               45.0f

typedef enum {
    DOCK_CONTACT_OPEN = 0,
    DOCK_CONTACT_PROBING,
    DOCK_CONTACT_POLARITY_FAULT,
    DOCK_CONTACT_HIGH_RESISTANCE,
    DOCK_CONTACT_COMM_TIMEOUT,
    DOCK_CONTACT_READY_TO_CHARGE,
    DOCK_CONTACT_CHARGING_ACTIVE,
    DOCK_CONTACT_THERMAL_FAULT
} dock_contact_state_t;

typedef struct {
    float sense_voltage_drop_mv;
    float probe_current_ma;
    float calculated_resistance_mohm;
    uint32_t battery_voltage_mv;
    float max_cell_temp_c;
    bool reverse_polarity_detected;
    bool bms_heartbeat_alive;
} dock_telemetry_t;

typedef struct {
    dock_contact_state_t state;
    uint32_t state_entry_time_ms;
    uint8_t retry_count;
} dock_charge_controller_t;

void dock_charge_controller_init(dock_charge_controller_t *ctrl) {
    if (!ctrl) return;
    ctrl->state = DOCK_CONTACT_OPEN;
    ctrl->state_entry_time_ms = 0;
    ctrl->retry_count = 0;
}

dock_contact_state_t dock_evaluate_contact_health(
    dock_charge_controller_t *ctrl,
    const dock_telemetry_t *telem,
    uint32_t current_time_ms)
{
    if (!ctrl || !telem) return DOCK_CONTACT_OPEN;

    switch (ctrl->state) {
    case DOCK_CONTACT_OPEN:
        if (telem->probe_current_ma > 50.0f) {
            ctrl->state = DOCK_CONTACT_PROBING;
            ctrl->state_entry_time_ms = current_time_ms;
        }
        break;

    case DOCK_CONTACT_PROBING:
        if (telem->reverse_polarity_detected) {
            ctrl->state = DOCK_CONTACT_POLARITY_FAULT;
            break;
        }

        if (telem->probe_current_ma > 10.0f) {
            float r_mohm = (telem->sense_voltage_drop_mv / telem->probe_current_ma) * 1000.0f;
            if (r_mohm > MAX_ALLOWED_CONTACT_RESISTANCE_MOHM) {
                ctrl->state = DOCK_CONTACT_HIGH_RESISTANCE;
                break;
            }
        }

        if (!telem->bms_heartbeat_alive) {
            if (current_time_ms - ctrl->state_entry_time_ms > 1000) {
                ctrl->state = DOCK_CONTACT_COMM_TIMEOUT;
            }
            break;
        }

        if (telem->battery_voltage_mv < MIN_BATTERY_VOLTAGE_MV ||
            telem->battery_voltage_mv > MAX_BATTERY_VOLTAGE_MV) {
            ctrl->state = DOCK_CONTACT_POLARITY_FAULT;
            break;
        }

        if (telem->max_cell_temp_c > MAX_CELL_TEMPERATURE_C) {
            ctrl->state = DOCK_CONTACT_THERMAL_FAULT;
            break;
        }

        ctrl->state = DOCK_CONTACT_READY_TO_CHARGE;
        break;

    case DOCK_CONTACT_READY_TO_CHARGE:
        /* Готовий до комутації реле через soft-start */
        break;

    case DOCK_CONTACT_CHARGING_ACTIVE:
        if (telem->max_cell_temp_c > MAX_CELL_TEMPERATURE_C ||
            !telem->bms_heartbeat_alive) {
            ctrl->state = DOCK_CONTACT_THERMAL_FAULT;
        }
        break;

    default:
        break;
    }

    return ctrl->state;
}
```

```cpp
// ContactDiagnostics.hpp
#pragma once
#include <cstdint>
#include <optional>
#include <span>
#include <chrono>

namespace DroneDock {

enum class ContactState : uint8_t {
    Open,
    Probing,
    PolarityFault,
    HighResistance,
    CommTimeout,
    ReadyToCharge,
    ChargingActive,
    ThermalFault
};

struct DiagnosticTelemetry {
    float senseVoltageDropMv{0.0F};
    float probeCurrentMa{0.0F};
    float calculatedResistanceMohm{0.0F};
    uint32_t batteryVoltageMv{0};
    float maxCellTempC{0.0F};
    bool reversePolarityDetected{false};
    bool bmsHeartbeatAlive{false};
};

class DockChargeController {
public:
    static constexpr float MaxAllowedResistanceMohm{40.0F};
    static constexpr uint32_t MinBatteryVoltageMv{18000};
    static constexpr uint32_t MaxBatteryVoltageMv{25500};
    static constexpr float MaxCellTemperatureC{45.0F};
    static constexpr std::chrono::milliseconds CommTimeoutLimit{1000};

    constexpr DockChargeController() = default;

    [[nodiscard]] ContactState getState() const noexcept { return currentState_; }

    ContactState update(const DiagnosticTelemetry& telem,
                        std::chrono::milliseconds currentTime) noexcept
    {
        switch (currentState_) {
        case ContactState::Open:
            if (telem.probeCurrentMa > 50.0F) {
                currentState_ = ContactState::Probing;
                stateEntryTime_ = currentTime;
            }
            break;

        case ContactState::Probing:
            if (telem.reversePolarityDetected) {
                currentState_ = ContactState::PolarityFault;
                break;
            }

            if (telem.probeCurrentMa > 10.0F) {
                const float rMohm = (telem.senseVoltageDropMv / telem.probeCurrentMa) * 1000.0F;
                if (rMohm > MaxAllowedResistanceMohm) {
                    currentState_ = ContactState::HighResistance;
                    break;
                }
            }

            if (!telem.bmsHeartbeatAlive) {
                if (currentTime - stateEntryTime_ > CommTimeoutLimit) {
                    currentState_ = ContactState::CommTimeout;
                }
                break;
            }

            if (telem.batteryVoltageMv < MinBatteryVoltageMv ||
                telem.batteryVoltageMv > MaxBatteryVoltageMv) {
                currentState_ = ContactState::PolarityFault;
                break;
            }

            if (telem.maxCellTempC > MaxCellTemperatureC) {
                currentState_ = ContactState::ThermalFault;
                break;
            }

            currentState_ = ContactState::ReadyToCharge;
            break;

        case ContactState::ReadyToCharge:
            // Очікування сигналу запуску від планувальника заряду
            break;

        case ContactState::ChargingActive:
            if (telem.maxCellTempC > MaxCellTemperatureC || !telem.bmsHeartbeatAlive) {
                currentState_ = ContactState::ThermalFault;
            }
            break;

        case ContactState::PolarityFault:
        case ContactState::HighResistance:
        case ContactState::CommTimeout:
        case ContactState::ThermalFault:
            // Стан аварійної ізоляції контактів
            break;
        }

        return currentState_;
    }

    void setChargingActive() noexcept {
        if (currentState_ == ContactState::ReadyToCharge) {
            currentState_ = ContactState::ChargingActive;
        }
    }

    void reset() noexcept {
        currentState_ = ContactState::Open;
        stateEntryTime_ = std::chrono::milliseconds{0};
    }

private:
    ContactState currentState_{ContactState::Open};
    std::chrono::milliseconds stateEntryTime_{0};
};

} // namespace DroneDock
```

### Підсумкова архітектура та інтеграція в автономний цикл

Надійне функціонування комплексу Drone-in-a-Box досягається за рахунок суворого узгодження просторових і фізичних обмежень на кожному кроці посадкового циклу. Жоден рівень не починає роботу без підтвердження успішного завершення попереднього:

1. Супутниковий навігатор RTK забезпечує доставку апарата у вікно видимості оптичних сенсорів розміром 3×3 метри.
2. Алгоритм PnP детекції візуальних ідентифікаторів усуває зсуви вітру та динамічні похибки, приводячи дрон у стул посадкових воронок із точністю до сантиметра.
3. Кінематика механічного затискача трансформує кінетичну енергію посадки у прецизійне центрування клем.
4. Чотирипровідна схема Кельвіна та цифрове рукостискання з BMS запобігають подачі сили в ненадійний або перегрітий контактний вузол.

Завдяки цьому повна автоматизація зльоту, виконання місії, прецизійного стикування та заряджання перетворює безпілотний апарат на повністю самодостатній всепогодний робототехнічний вузол.
