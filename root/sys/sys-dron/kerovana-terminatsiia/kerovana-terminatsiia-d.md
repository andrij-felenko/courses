# Керована термінація: коли правильна дія — впасти

<preknowlist>
- [Безпечний відмов (failsafe)](root:sys-dron/failsafe) — концепція переходу системи в безпечний стан при аварійних подіях та рівні реагування.
- [Геозона (geofence) в автопілоті](root:sys-dron/geofence) — визначення дозволених просторових меж польоту та виявлення їх порушення.
- [Політний контролер](root:sys-dron/flight-controller) — апаратна архітектура автопілота, керування приводами й системні шини.
- [Парашут: опір і швидкість спуску](root:sys-dron/parashut) — аеродинаміка гальмування куполом, імпульсний викид та розсіювання кінетичної енергії.
- [Спільна фільтрація GNSS та ІНС](root:sys-dron/gnss-i-ivb-razom) — оцінка просторового вектора стану та коваріацій у розширеному фільтрі Калмана (EKF).
</preknowlist>

Важкий безпілотник злітною масою 25 кг виконує автономний моніторинговий політ на швидкості 120 км/год уздовж промислового коридору, розташованого за два кілометри від межі глісади міжнародного аеропорту та густонаселеного житлового масиву. На двадцятій хвилині місії стається подвійна апаратна відмова: імпульсний перетворювач живлення на платі розподілу (PDB) зазнає теплового пробою й видає в 5-вольтову шину високовольтні завади, які намертво блокують головний процесор автопілота в апаратному виключенні HardFault. Одночасно з цим сервопривід елерона заклинює в крайньому положенні під кутом 25°. Оскільки планувальник операційної системи реального часу завис, таймери генерації ШІМ-сигналів лишаються зафіксованими в останньому активному стані. Дрон не переходить у стандартний режим повернення додому (RTL), не вирівнює крен і починає стрімко набирати швидкість у пологій спіралі зі зниженням, несучи у напрямку цивільних об'єктів понад 180 кілоджоулів сумарної кінетичної та хімічної енергії.

У такій ситуації класичний програмний failsafe повністю мертвий. Продовжувати політ або сподіватися на диво означає гарантувати катастрофічне зіткнення з пілотованим літаком або наземними спорудами. В авіаційній безпеці діє непорушна ієрархія пріоритетів: життя людей на землі та безпека екіпажів у повітряному просторі стоять нескінченно вище за збереження конструкції самого безпілотника. Коли апарат виходить з-під контролю, єдиною правильною, математично детермінованою дією є **примусове припинення польоту (Flight Termination)** — негайне вимкнення тяги та кероване скидання дрона в межах заздалегідь визначеної зони безпеки.

> 🔧 **Навіщо це.** Система припинення польоту (Flight Termination System, FTS) є обов'язковою вимогою авіаційних регуляторів (FAA Part 107 Waiver, регламенти EASA SORA для категорій Specific та Certified, стандарт ASTM F3322-18) для польотів поза прямою видимістю (BVLOS) та над людьми. Вона гарантує, що за будь-якої критичної відмови головного автопілота апарат не вилетить за межі виділеного повітряного об'єму (Containment Area), знижуючи інтегральний ризик для третіх осіб до рівня менше `10⁻⁶` катастрофічних подій на годину польоту.

### Межа між штатним Failsafe та аварійною термінацією

Щоб зрозуміти необхідність виділеного механізму термінації, слід чітко розмежувати поняття безпечного відмову (*failsafe*) та аварійного припинення польоту (*termination*). 

Штатний захисний алгоритм автопілота розраховує на те, що базовий контур керування залишається функціональним. Якщо зникає радіозв'язок із пультом або супутниковий сигнал GNSS, автопілот має справні гіроскопи, живий процесор і робочі мотори. Він може виконати зависання, розвернутися за курсом компаса, здійснити плавне гальмування чи зайти на автоматичну посадку. Failsafe — це збереження керованості за рахунок зміни траєкторії або польотного режиму.

Аварійна термінація вмикається тоді, коли передумова про працездатність контуру керування порушена. Якщо зруйновано механіку одного з променів, заклинило кермові поверхні, спалахнув силовий акумулятор або зависло ядро автопілота, будь-яка спроба продовжувати стабілізацію лише подовжує неконтрольовану балістичну траєкторію розльоту уламків. Термінація — це фізичне знищення підйомної сили та тяги апарата для того, щоб зупинити його горизонтальний поступ і локалізувати точку падіння.

```
Штатний політ    ──► Відмова зв'язку / GNSS  ──► Failsafe (RTL / Land / Loiter)
                                                       │
                                      Відмова контуру керування / вихід за межі
                                                       ▼
                                             FTS: Миттєва термінація
                                             • Знеструмлення моторів (Motor Kill)
                                             • Викид парашута / гальмівних щитків
                                             • Падіння в буферній зоні
```

Цей механізм отримав назву **система припинення польоту (Flight Termination System, скорочено FTS**; від англ. *flight* — політ, *termination* — припинення, завершення, *system* — система). Цей термін прийшов із ракетобудування та полігонних випробувань, де дистанційний підрив або глушіння двигунів ракети є єдиним засобом захисту стартового комплексу від некерованого відхилення ракети-носія.

### Нормативна база та оцінка ризиків (SORA M2 та ASTM F3322)

Міжнародні авіаційні правила підходять до систем припинення польоту через методологію оцінки сукупного ризику операцій (Specific Operations Risk Assessment, SORA), розроблену об'єднаною владою з регулювання безпілотних систем JARUS та прийняту європейським агентством EASA:

1. **Клас наземного ризику (Ground Risk Class, GRC):** базовий ризик визначається кінетичною енергією дрона, його габаритами та щільністю населення в зоні польоту. Безпечний сертифікований FTS знижує підсумковий GRC на 1 чи 2 рівні (M2 Mitigation — зменшення наслідків удару).
2. **Вимоги до стійкості (Robustness Level):**
   - **Низька стійкість (Low Robustness):** комерційні модулі без суворої ізоляції живлення, допустимі лише для операцій над безлюдною закритою територією.
   - **Середня та висока стійкість (Medium / High Robustness):** повна апаратна незалежність FTS від автопілота, ізольоване джерело енергії, захищений радіоканал на виділеній частоті та розрахункова ймовірність відмови на вимогу (Probability of Failure on Demand, PFD) не більше `10⁻⁴`.
3. **Стандарт ASTM F3322-18:** визначає обов'язкові льотні випробування систем аварійного порятунку: мінімум 45 успішних скидів у різних конфігураціях аварій (повна втрата живлення, зависання автопілота, некерований штопор, ручне глушіння) без жодної відмови.

### Критерії та сценарії застосування: матриця тригерів

Рішення про аварійне припинення польоту не може ухвалюватися випадково. Передчасна активація призводить до втрати дорогого апарата й корисного навантаження, тоді як запізніла активація робить падіння некерованим. Тому FTS спирається на жорстко верифіковану матрицю з чотирьох незалежних критеріїв спрацьовування.

![Критерії спрацьовування та часова діаграма аварійної термінації](/root/sys/sys-dron/kerovana-terminatsiia/img/fts-decision-and-timing.svg)
*Чотири незалежні тригери аварійного стану та поетапна часова шкала виконання термінації від вимкнення двигунів до приземлення з безпечною швидкістю.*

#### 1. Порушення невідкличної межі утримання (Hard Geofence Breach)

Усі місії плануються всередині тривимірного дозволеного геопростору. Проте в системі безпеки визначають дві концентричні межі:
- **М'яка геозона (Soft Geofence):** у разі її перетину головний автопілот вмикає повернення додому або зависання.
- **Жорстка межа термінації (Hard Containment Boundary):** лінія, за якою починається заборонений простір або зона ризику для людей.

Якщо апарат перетинає лінію жорсткої межі на швидкості `V_ground`, до моменту вильоту в критичну зону залишається буферна відстань `d_margin`. Час, доступний для ухвалення рішення (`t_contain`), визначається відношенням дистанції до швидкості:

```
t_contain = d_margin / V_ground      [час до вильоту за межі безпечного коридору]
```

Якщо за час `t_contain` дрон не повернувся всередину зони, FTS виконує термінацію. При цьому розраховується сумарний радіус зони падіння `R_impact`, який враховує балістичний вибіг уламків та вітрове знесення купола:

```
t_fall = √( (2 · h) / g )            [тривалість балістичної фази вільного падіння]
d_ballistic = V_ground · t_fall      [горизонтальний шлях за час падіння]
d_wind = V_wind · (h / V_term)       [вітрове знесення купола під час спуску]
R_impact = d_ballistic + d_wind      [радіус зони гарантованого падіння]
```

де:
- `h` — поточна висота польоту над рельєфом, м;
- `g = 9.80665 м/с²` — прискорення вільного падіння;
- `V_ground` — горизонтальна швидкість у момент активації, м/с;
- `V_wind` — швидкість бокового вітру, м/с;
- `V_term` — усталена швидкість зниження на парашуті, м/с.

#### 2. Некероване обертання та зрив у штопор (Tumbling / High-Rate Spin)

Коли мультиротор втрачає один із гвинтів або літак зривається у плаский штопор, кутова швидкість обертання довкола осей різко зростає. Аеродинамічні сили більше не компенсують вагу, а інерційні датчики входять у насичення.

Критерій зриву фіксується за модулем вектора кутової швидкості `ω = (ω_x, ω_y, ω_z)` за даними гіроскопів:

```
|ω| = √( ω_x² + ω_y² + ω_z² )      [повна кутова швидкість обертання апарата]
```

Якщо величина `|ω|` перевищує критичний поріг `ω_crit` (зазвичай `400–500 °/с` для важких платформ) і утримується понад час фільтрації `T_dwell = 300–500 мс`, стан класифікується як некерований штопор. Часова затримка `T_dwell` необхідна, щоб відсіяти короткочасні сплески від поривів турбулентного вітру чи різких маневрів ухилення.

Одночасно з цим FTS аналізує модуль вектора повної перевантаження за даними тривісного акселерометра:

```
|a| = √( a_x² + a_y² + a_z² )      [модуль вектору сумарного прискорення]
```

Якщо `|a| < 0.25 g` упродовж `T_dwell`, апарат перебуває у вільному падінні (невагомість через відсутність підйомної сили). Поєднання високої кутової швидкості `|ω| > 450 °/с` та низького перевантаження `|a| < 0.25 g` дає 100% математичну достовірність катастрофічного зриву в штопор, унеможливлюючи хибне спрацьовування під час планових перевантажень.

#### 3. Повна розбіжність фільтра станів EKF (Sensor Fusion Divergence)

Головний навігаційний фільтр автопілота (Extended Kalman Filter, EKF) безперервно оцінює стан системи та обчислює матрицю коваріацій похибок. Якщо через супутникове глушіння (GNSS Jamming), магнітні аномалії або збій акселерометрів інноваційні нев'язки вимірювань перевищують допустимі межі, нормалізований індикатор розбіжності (innovation test ratio) стрімко зростає:

```
Ratio_innov = (y_k - ŷ_k)² / S_k > 5.0      [перевищення порогу правдоподібності EKF]
```

де `y_k - ŷ_k` — нев'язка вимірювання, а `S_k` — дисперсія інновації. Коли розбіжність одночасно охоплює оцінки швидкості, висоти та курсу, автопілот стає повністю сліпим. Він не здатний визначити вектор свого руху і може розігнати апарат у землю на повній тязі. За відсутності достовірних оцінок просторового положення впродовж заданого інтервалу (наприклад, понад 3–5 секунд на критичній ділянці) ініціюється термінація.

#### 4. Пряма загроза людям та екстрена ручна команда (Manual Override)

Незалежно від автоматичних алгоритмів, оператор або офіцер безпеки полігону (Range Safety Officer, RSO) повинен мати можливість у будь-яку частку секунди примусово зупинити політ. Ручна команда передається по виділеному захищеному радіоканалу, оминаючи всі польотні режими та програмні фільтри автопілота.

### Фізичні механізми термінації

Термінація — це не просто абстрактна зміна прапорця в пам'яті контролера. Це конкретна фізична дія над бортовими виконавчими механізмами, спрямована на якнайшвидше гасіння швидкості й розсіювання енергії.

```
                                  ┌──► 1. Миттєвий Motor Kill (0 мс)
                                  │       • Зняття ШІМ / DShot
                                  │       • Відсікання силового eFuse
                                  │
Ініціація аварійної термінації ───┼──► 2. Балістичний парашут (60–100 мс)
                                  │       • Піропатрон / виштовхувач
                                  │       • Гасіння швидкості: V < 4 м/с
                                  │
                                  └──► 3. Аеродинамічний штопор (літаки)
                                          • Розкриття інтерцепторів
                                          • Відхилення керма в упор
```

#### 1. Миттєве відсікання тяги силової установки (Motor Kill / In-Flight Disarm)

Найперший і безумовний крок термінації — зняття напруги або керуючого сигналу з регуляторів обертів двигунів (ESC). 

Чому недостатньо просто надіслати повідомлення `MAV_CMD_COMPONENT_ARM_DISARM` по шині MAVLink? Якщо процесор автопілота завис або завис мікроконтролер самого регулятора швидкості (ESC), програмна команда буде проігнорована. Ба більше, під час сильних вібрацій або збоїв зв'язку польотний контролер може продовжувати видавати імпульси ШІМ або цифрові фрейми DShot із високим шпаруватістю.

Справжня система FTS реалізує апаратне переривання:
- **Апаратне притягування ліній керування (Pull-Down Clamping):** швидкодіючі аналогові ключі або буфери з відкритим колектором миттєво закорочують сигнальні лінії ШІМ/DShot на землю (`GND`), змушуючи ESC розпізнати втрату сигналу та заглушити ключі інвертора за час менше `1–2 мс`.
- **Силове знеструмлення (High-Side eFuse / Solid-State Disconnect):** потужні польові транзистори (MOSFET) у розриві силової шини живлення ESC розмикають ланцюг, знеструмлюючи двигуни навіть за умови повного виходу з ладу керуючої електроніки регуляторів.

При миттєвому розмиканні ланцюга зі струмом понад `100–200 А` виникає потужний індуктивний викид напруги `U_spike = -L · (di/dt)`. Для захисту силових ключів FTS обов'язково встановлюються швидкодіючі супресори (TVS-діоди) та демпфуючі RC-ланцюжки (snubbers), що поглинають енергію магнітного поля дротів живлення.

#### 2. Балістичний викид парашута піропатроном

Для мультироторів та апаратів вертикального зльоту відсікання моторів переводить дрон у режим вільного падіння. Щоб знизити енергію удару об землю до безпечних значень, FTS активує рятувальний парашут.

У процесі термінації критично витримати жорстку мікросекундну послідовність:
1. **`T = 0 мс`:** Спрацьовує апаратний Motor Kill. Струм на мотори переривається.
2. **`T = 50–80 мс`:** Затримка зупинки обертання пропелерів. Якщо викинути парашутний пакет крізь пропелери, що обертаються зі швидкістю 6000 об/хв, стропи купола будуть миттєво перерубані карбоновими лопатями або намотані на вали моторів.
3. **`T = 80–100 мс`:** Подається струмовий імпульс на піропатрон (Squib) або електромагнітний замок пружинного тубуса. Купол вистрілюється зі швидкістю понад 20 м/с убік від корпусу апарата.
4. **`T = 300–500 мс`:** Повне наповнення купола та перехід на стаціонарну швидкість спуску `V_term ≤ 3.5–4.0 м/с`.

Кінетична енергія зіткнення при цьому спадає від руйнівних кілоджоулів до величин менше 80 Дж:

```
E_k = 0.5 · m · V_term²      [кінетична енергія контакту з поверхнею]
```

Для апарата масою `m = 10 кг` при швидкості `V_term = 3.8 м/с`:

```
E_k = 0.5 · 10 · (3.8)²
    = 0.5 · 10 · 14.44
    = 72.2 Дж              [нижче порогу важких травм за стандартом EASA SORA]
```

#### 3. Аеродинамічні гальма та контрольоване введення в штопор

На швидкісних безпілотних літаках крилатої схеми (Fixed-Wing) масою 50–100 кг встановлення великогабаритного парашута не завжди можливе через обмеження за масою та об'ємом фюзеляжу. Якщо такий літак зазнає відмови, він перетворюється на планер з аеродинамічною якістю `L/D = 12–18`, здатний пролетіти по прямій понад 15–20 кілометрів і впасти далеко за межами полігону.

Механізм термінації літака без парашута полягає в примусовому руйнуванні аеродинамічної якості:
- **Миттєве розкриття інтерцепторів та гальмівних щитків (Airbrakes / Spoilers):** зрив ламінарного обтікання крила, зниження підйомної сили на 70–80% та зростання лобового опору в 4–6 разів.
- **Асиметричне відхилення кермових поверхонь у крайні положення:** елерони відхиляються на повний кут в один бік, а кермо напрямку (Rudder) — у протилежний, одночасно кермо висоти береться повністю «на себе». Це насильно вводить літак у крутий, компактний штопор (Flat Spin) або пікірування з великим ковзанням.
- **Наслідок:** горизонтальна швидкість падає майже до нуля, літак спускається суворо вертикально у межах вузького циліндра безпеки радіусом 100–200 метрів, не маючи змоги вилетіти у захищену зону.

### Апаратна незалежність FTS: архітектура ізоляції

Головна інженерна вимога до будь-якої системи термінації формулюється в авіаційних стандартах DO-254 / DO-178C як **усунення єдиної точки відмови (Single Point of Failure elimination)**.

Якщо FTS є просто підпрограмою всередині прошивки головного автопілота, що працює на тому ж мікроконтролері й живиться від того ж джерела 5V, вона абсолютно марна: збій ядра CPU або короткозамикання в шині живлення знищує FTS разом з автопілотом.

![Апаратна архітектура незалежної системи припинення польоту (FTS)](/root/sys/sys-dron/kerovana-terminatsiia/img/fts-hardware-architecture.svg)
*Повна ізоляція доменів: незалежний мікроконтролер FTS, резервний радіоканал 868 МГц, автономна батарея LiFePO4 та бар'єр гальванічної розв'язки ліній керування.*

Справжня сертифікована FTS будується як повністю автономний пристрій у власному екранованому корпусі:

1. **Виділений вторинний мікроконтролер (Secondary MCU):** компактний надійний чип (наприклад, STM32G0 або RP2040), прошивка якого виконує виключно одну задачу — моніторинг безпеки, декодування команд термінації та керування виконавчими ключами. Жодних складних RTOS, мережевих стеків чи важких бібліотек — детермінований код на C з гарантованим часом реакції `< 1 мс`.
2. **Власний резервний радіоканал (868 / 433 / 915 МГц):** автономний трансивер (наприклад, на базі модулів LoRa/SX1262 або вузькосмугового FSK-модема), що працює на іншій частоті, ніж основний канал керування дроном (2.4 ГГц або 5.8 ГГц). Навіть якщо головний радіолінк придушений потужною завадою чи РЕБ, резервний низькочастотний лінк FTS зберігає зв'язок на дистанціях у десятки кілометрів.
3. **Автономне джерело живлення:** незалежний акумулятор (LiFePO4 2S або літій-тіонілхлоридний елемент `Li-SOCl₂`) у поєднанні з блоком суперконденсаторів ємністю 5–10 Фарад. FTS здатна функціонувати та гарантовано підірвати піропатрон упродовж щонайменше 45–60 хвилин після повного руйнування головного акумулятора дрона.
4. **Гальванічна розв'язка (Optoisolation):** усі зв'язки між головним автопілотом і модулем FTS проходять крізь цифрові оптоізолятори з напругою пробою не менше `2.5 кВ`. Згоряння силової частини автопілота чи коротке замикання на PDB фізично не може пошкодити плату FTS.
5. **Двоконтурний захисний інтерлок (Dual-Switch Hardware Interlock):** ланцюг запалювання піропатрона містить два послідовно ввімкнені ключі (MOSFET верхнього та нижнього плеча), керовані різними виводами мікроконтролера. Для спрацьовування необхідно одночасно замкнути обидва ключі за чітко заданим часовим шаблоном. Будь-який хаотичний сигнал під час увімкнення живлення чи перезавантаження чипа не здатний відкрити обидва ключі одночасно.

### Фізика резервного радіоканалу: чому саме 868 / 433 МГц

Для гарантованого проходження команди термінації в екстремальних умовах вибір діапазону частот є фундаментальним інженерним рішенням.

Основний телеметричний лінк автопілота зазвичай працює на частотах 2.4 ГГц або 5.8 ГГц, передаючи широкосмугове відео та високочастотний потік MAVLink. Проте сигнал 2.4 ГГц має високе згасання у вільному просторі (Free Space Path Loss, FSPL) та практично повністю поглинається вологою рослинністю, спорудами та тілом фюзеляжу, якщо дрон увійшов у неконтрольований крен і екранує антену вуглепластиковою декою:

```
FSPL(дБ) = 20 · log10(d) + 20 · log10(f) + 32.44      [згасання радіосигналу на відстані]
```

де `d` — відстань у кілометрах, `f` — частота в мегагерцах.

Порівняймо згасання сигналу на дистанції `d = 10 км`:
- На частоті `f = 2400 МГц`: `FSPL ≈ 120 дБ`.
- На частоті `f = 868 МГц`: `FSPL ≈ 111.2 дБ` (перевага за потужністю майже в 9 разів).
- На частоті `f = 433 МГц`: `FSPL ≈ 105.2 дБ` (перевага за потужністю у 30 разів).

Низькі субгігагерцові частоти (433/868 МГц) забезпечують відмінне дифракційне огинання перешкод (рефракція навколо пагорбів та будівель) та глибоке проникнення крізь турбулентні вихлопи або задимлення. Використання модуляції LoRa з коефіцієнтом розширення спектра `SF = 10..12` дозволяє приймати пакети FTS при співвідношенні сигнал/шум `SNR = -20 дБ` (глибоко під рівнем теплового шуму приймача), гарантуючи доставку команди термінації навіть в умовах навмисних радіозавад.

### Схемотехніка ланцюга активації піропатрона (Firing Circuit)

Піропатрон рятувальної системи (Squib) являє собою низькоомний нагрівальний місток з опором `R_bridge ≈ 1.0–2.0 Ом`, який для надійного запалювання потребує струму амплітудою `I_fire = 1.5–3.0 А` впродовж `t_pulse = 20–50 мс`.

Під час проектування ланцюга запалювання вирішуються три критичні схемотехнічні задачі:
1. **Ємнісний накопичувач енергії (Capacitive Discharge Unit):** навіть якщо внутрішній опір резервної батареї зріс через мороз (`-20 °C`), енергія накопичується в електролітичному танталовому конденсаторі ємністю `C_fire = 2200–4700 мкФ`, заряженому до напруги 12V. Запас енергії в конденсаторі:

```
E_cap = 0.5 · C_fire · (V_start² - V_end²)      [енергія розряду в запалювальний місток]
```

Для `C = 3300 мкФ`, `V_start = 12 В` та `V_end = 4 В`:

```
E_cap = 0.5 · 0.0033 · (144 - 16)
      = 0.5 · 0.0033 · 128
      = 0.211 Дж              [достатньо для гарантованого підриву мікропіропатрона 0.05 Дж]
```

2. **Апаратний тест цілісності містка (Continuity Sense):** перед вильотом і безперервно під час польоту мікроконтролер FTS зобов'язаний контролювати, чи не обірвано провід піропатрона. Тестовий струм обмежується прецизійним резистором `R_sense = 2.2 кОм`:

```
I_test = V_ref / R_sense = 3.3 / 2200 ≈ 1.5 мА      [струм значно нижчий за поріг спрацьовування 50 мА]
```

Падіння напруги на містку зчитується АЦП мікроконтролера. Якщо `V_adc ≈ 0 В` — місток цілий; якщо `V_adc ≈ V_ref` — обрив ланцюга (Parachute Squib Disconnected), що негайно блокує Arming дрона на землі.

### Наземне тестування, чека безпеки та Built-In Self-Test (BITE)

Передпольотне обслуговування апарата з бойовим піропатроном або зведеною пружиною на борту несе пряму небезпеку для інженерів та операторів. Випадкове спрацьовування системи на столі чи в руках може завдати важких травм.

Для безпечної експлуатації FTS впроваджує комплекс багаторівневих запобіжників:

1. **Фізична чека безпеки (Remove Before Flight Pin):** механічний розмикач зі штифтом та яскраво-червоним вимпелом. Поки штифт вставлений у гніздо, ланцюг живлення запалювача фізично закорочений на масу через низькоомний резистор, а шина високої напруги накопичувача повністю розімкнена. Жоден програмний чи апаратний збій контролера не здатен подати струм на піропатрон. Штифт виймається безпосередньо перед зльотом після завершення всіх передстартових перевірок.
2. **Вбудоване самотестування (Built-In Self-Test, BITE):** під час увімкнення живлення FTS здійснює автоматичний чеклист:
   - Перевірка опорної напруги автономного акумулятора та суперконденсатора (`V_cap ≥ 11.8 В`).
   - Перевірка цілісності нитки розжарення запалювача парашута через мікрострумовий сенсор.
   - Тестування зв'язку по шині SPI з власним тривісним датчиком IMU та радіотрансивером 868 МГц.
   - Звірка та узгодження стартового номера пакета (Sequence Number Sync) із пультом оператора.
   - Якщо хоча б один тест не пройдено, FTS утримує лінію готовності `READY_OUT` на рівні нуля, що апаратно блокує взведення (Arming) головного автопілота.
3. **Режим холостого тестування (Dry Run / Test Mode):** дає змогу операторам перевірити весь ланцюг проходження команд без фізичного відстрілу парашута. У цьому режимі замість піропатрона підключається світлодіодний індикатор або еквівалент навантаження, а відсікання моторів імітується зняттям ШІМ-сигналів на стенді.

### Захищений протокол керування та блокування випадкового спрацювання

Система термінації має дві діаметрально протилежні загрози:
- **Помилка I роду (хибне спрацьовування):** випадкова термінація під час нормального польоту через шум в ефірі чи програмний баґ. Це призводить до аварії справного апарата.
- **Помилка II роду (відмова спрацьовування):** нездатність перервати політ під час реальної катастрофи через втрату пакета чи зависання логіки.

Щоб звести ймовірність помилок обох типів до мінімуму, протокол зв'язку FTS проєктується за жорсткими військово-авіаційними стандартами безпеки.

#### 1. Двостадійне взведення (Two-Stage Arming Sequence)

Команда термінації ніколи не надсилається одним пакетом. Оператор або наземна станція виконує двостадійну послідовність:
1. **Команда `ARM_TERMINATION` (Взвести систему):** переводить модуль FTS зі стану `SAFE` у стан `ARMED`. Відкривається часове вікно підтвердження тривалістю `T_window = 1000–3000 мс`.
2. **Команда `EXECUTE_TERMINATION` (Виконати термінацію):** якщо ця команда надходить усередині активного вікна `T_window`, FTS миттєво активує Motor Kill та викид парашута. Якщо вікно спливло, а підтвердження не надійшло, система автоматично скидається назад у безпечний стан `SAFE`.

#### 2. Захист від атак повторного відтворення (Anti-Replay Counter)

У кожному фреймі передається монотонно зростаючий 32-бітний лічильник послідовності `sequence_number` та мітка часу. Бортовий приймач FTS відкидає будь-який пакет, номер якого менший або дорівнює останньому прийнятому значенню. Зловмисник не може перехопити команду з ефіру й відтворити її пізніше для несанкціонованого знищення дрона.

#### 3. Криптографічна автентифікація (HMAC / AES-CMAC)

Кожен пакет термінації містить 64-бітний або 128-бітний імітовставку (MAC), обчислений за алгоритмом HMAC-SHA256 або AES-CMAC з використанням попередньо розподіленого секретного ключа (Pre-Shared Key), прошитого в захищену пам'ять модуля перед вильотом. Пакет із невалідною контрольною сумою чи невірним MAC-підписом відкидається на рівні апаратного переривання радіомодуля.

### Програмна реалізація протоколу FTS та FSM безпеки

Розгляньмо еталонну реалізацію ядра обробки команд та автомата станів безпеки системи Flight Termination System мовами C та C++.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define FTS_MAGIC_HEADER        0x5AA5F751U
#define FTS_ARM_WINDOW_MS       2500U
#define FTS_MIN_ARM_TIME_MS     100U

typedef enum {
    FTS_STATE_SAFE = 0,
    FTS_STATE_ARMED,
    FTS_STATE_TRIGGERED,
    FTS_STATE_LATCHED_KILL
} fts_state_t;

typedef enum {
    FTS_CMD_NONE = 0x00,
    FTS_CMD_ARM  = 0xA5,
    FTS_CMD_KILL = 0x5A,
    FTS_CMD_PING = 0x55
} fts_cmd_type_t;

typedef struct __attribute__((packed)) {
    uint32_t magic;
    uint32_t seq_num;
    uint32_t timestamp_ms;
    uint8_t  command;
    uint8_t  reserved[3];
    uint32_t auth_token;
    uint32_t crc32;
} fts_packet_t;

typedef struct {
    fts_state_t state;
    uint32_t    last_seq;
    uint32_t    arm_timestamp_ms;
    uint32_t    auth_secret_key;
    bool        hardware_motor_kill_active;
    bool        squib_fired;
} fts_controller_t;

/* Простий CRC32 (IEEE 802.3) */
static uint32_t calculate_crc32(const uint8_t *data, size_t len) {
    uint32_t crc = 0xFFFFFFFFU;
    for (size_t i = 0; i < len; ++i) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; ++j) {
            crc = (crc >> 1) ^ (0xEDB88320U & (-(int32_t)(crc & 1U)));
        }
    }
    return ~crc;
}

/* Обчислення автентифікаційного токена */
static uint32_t compute_auth_token(const fts_packet_t *pkt, uint32_t key) {
    uint32_t hash = key ^ pkt->magic ^ pkt->seq_num ^ pkt->timestamp_ms ^ (uint32_t)pkt->command;
    hash = ((hash << 13) | (hash >> 19)) * 0x5BD1E995U;
    return hash ^ (hash >> 15);
}

void fts_init(fts_controller_t *fts, uint32_t secret_key) {
    memset(fts, 0, sizeof(fts_controller_t));
    fts->state = FTS_STATE_SAFE;
    fts->auth_secret_key = secret_key;
    fts->hardware_motor_kill_active = false;
    fts->squib_fired = false;
}

/* Апаратні дії термінації */
static void hw_execute_motor_kill(void) {
    /* Апаратне замикання ліній DShot на GND та відсікання живлення ESC */
}

static void hw_fire_pyro_squib(void) {
    /* Двоконтурна подача струму на запалювач парашута */
}

bool fts_process_packet(fts_controller_t *fts, const uint8_t *buffer, size_t len, uint32_t current_time_ms) {
    if (len < sizeof(fts_packet_t)) {
        return false;
    }

    const fts_packet_t *pkt = (const fts_packet_t *)buffer;

    /* 1. Перевірка магічного заголовка */
    if (pkt->magic != FTS_MAGIC_HEADER) {
        return false;
    }

    /* 2. Перевірка контрольної суми CRC32 */
    uint32_t calc_crc = calculate_crc32(buffer, sizeof(fts_packet_t) - sizeof(uint32_t));
    if (calc_crc != pkt->crc32) {
        return false;
    }

    /* 3. Захист від повтору: номер пакета мусить строго зростати */
    if (pkt->seq_num <= fts->last_seq) {
        return false;
    }

    /* 4. Перевірка криптографічного токена */
    if (compute_auth_token(pkt, fts->auth_secret_key) != pkt->auth_token) {
        return false;
    }

    fts->last_seq = pkt->seq_num;

    /* 5. Автомат станів безпеки */
    switch (fts->state) {
        case FTS_STATE_SAFE:
            if (pkt->command == FTS_CMD_ARM) {
                fts->state = FTS_STATE_ARMED;
                fts->arm_timestamp_ms = current_time_ms;
            }
            break;

        case FTS_STATE_ARMED:
            if (pkt->command == FTS_CMD_KILL) {
                uint32_t delta = current_time_ms - fts->arm_timestamp_ms;
                if (delta >= FTS_MIN_ARM_TIME_MS && delta <= FTS_ARM_WINDOW_MS) {
                    fts->state = FTS_STATE_TRIGGERED;
                    hw_execute_motor_kill();
                    fts->hardware_motor_kill_active = true;
                    hw_fire_pyro_squib();
                    fts->squib_fired = true;
                    fts->state = FTS_STATE_LATCHED_KILL;
                } else {
                    /* Вихід за межі часового вікна — скидання в SAFE */
                    fts->state = FTS_STATE_SAFE;
                }
            } else if (pkt->command == FTS_CMD_ARM) {
                /* Оновлення таймера взведення */
                fts->arm_timestamp_ms = current_time_ms;
            }
            break;

        case FTS_STATE_TRIGGERED:
        case FTS_STATE_LATCHED_KILL:
            /* Після активації система заблокована до повного знеструмлення */
            hw_execute_motor_kill();
            break;
    }

    return true;
}

void fts_update_periodic(fts_controller_t *fts, uint32_t current_time_ms) {
    if (fts->state == FTS_STATE_ARMED) {
        if (current_time_ms - fts->arm_timestamp_ms > FTS_ARM_WINDOW_MS) {
            fts->state = FTS_STATE_SAFE;
        }
    }
}
```

```cpp
#include <cstdint>
#include <cstddef>
#include <array>
#include <span>
#include <expected>

namespace fts {

inline constexpr uint32_t MagicHeader    = 0x5AA5F751U;
inline constexpr uint32_t ArmWindowMs    = 2500U;
inline constexpr uint32_t MinArmTimeMs   = 100U;

enum class State : uint8_t {
    Safe = 0,
    Armed,
    Triggered,
    LatchedKill
};

enum class Command : uint8_t {
    None = 0x00,
    Arm  = 0xA5,
    Kill = 0x5A,
    Ping = 0x55
};

enum class ParseError {
    BufferTooSmall,
    InvalidMagic,
    ChecksumMismatch,
    SequenceReplay,
    AuthenticationFailed,
    WindowExpired
};

struct [[gnu::packed]] PacketHeader {
    uint32_t magic;
    uint32_t seq_num;
    uint32_t timestamp_ms;
    Command  command;
    uint8_t  reserved[3];
    uint32_t auth_token;
    uint32_t crc32;
};

class HardwareInterlock {
public:
    static void executeMotorKill() noexcept {
        /* Апаратне замикання ліній DShot на GND та відсікання eFuse */
    }

    static void firePyrotechnicSquib() noexcept {
        /* Двоконтурний імпульс активації парашута */
    }
};

class Controller {
public:
    explicit constexpr Controller(uint32_t secret_key) noexcept
        : secretKey_(secret_key) {}

    [[nodiscard]] std::expected<void, ParseError> processPacket(
        std::span<const uint8_t> buffer,
        uint32_t currentTimeMs) noexcept
    {
        if (buffer.size() < sizeof(PacketHeader)) {
            return std::unexpected(ParseError::BufferTooSmall);
        }

        const auto& pkt = *reinterpret_cast<const PacketHeader*>(buffer.data());

        if (pkt.magic != MagicHeader) {
            return std::unexpected(ParseError::InvalidMagic);
        }

        const uint32_t calcCrc = computeCrc32(buffer.first(sizeof(PacketHeader) - sizeof(uint32_t)));
        if (calcCrc != pkt.crc32) {
            return std::unexpected(ParseError::ChecksumMismatch);
        }

        if (pkt.seq_num <= lastSeq_) {
            return std::unexpected(ParseError::SequenceReplay);
        }

        if (computeToken(pkt, secretKey_) != pkt.auth_token) {
            return std::unexpected(ParseError::AuthenticationFailed);
        }

        lastSeq_ = pkt.seq_num;
        applyCommand(pkt.command, currentTimeMs);
        return {};
    }

    void updatePeriodic(uint32_t currentTimeMs) noexcept {
        if (state_ == State::Armed) {
            if (currentTimeMs - armTimestampMs_ > ArmWindowMs) {
                state_ = State::Safe;
            }
        }
    }

    [[nodiscard]] State getState() const noexcept { return state_; }
    [[nodiscard]] bool isLatched() const noexcept { return state_ == State::LatchedKill; }

private:
    void applyCommand(Command cmd, uint32_t currentTimeMs) noexcept {
        switch (state_) {
            case State::Safe:
                if (cmd == Command::Arm) {
                    state_ = State::Armed;
                    armTimestampMs_ = currentTimeMs;
                }
                break;

            case State::Armed:
                if (cmd == Command::Kill) {
                    const uint32_t delta = currentTimeMs - armTimestampMs_;
                    if (delta >= MinArmTimeMs && delta <= ArmWindowMs) {
                        state_ = State::Triggered;
                        HardwareInterlock::executeMotorKill();
                        HardwareInterlock::firePyrotechnicSquib();
                        state_ = State::LatchedKill;
                    } else {
                        state_ = State::Safe;
                    }
                } else if (cmd == Command::Arm) {
                    armTimestampMs_ = currentTimeMs;
                }
                break;

            case State::Triggered:
            case State::LatchedKill:
                HardwareInterlock::executeMotorKill();
                break;
        }
    }

    static uint32_t computeCrc32(std::span<const uint8_t> data) noexcept {
        uint32_t crc = 0xFFFFFFFFU;
        for (uint8_t byte : data) {
            crc ^= byte;
            for (uint8_t j = 0; j < 8; ++j) {
                crc = (crc >> 1) ^ (0xEDB88320U & (-(int32_t)(crc & 1U)));
            }
        }
        return ~crc;
    }

    static uint32_t computeToken(const PacketHeader& pkt, uint32_t key) noexcept {
        uint32_t hash = key ^ pkt.magic ^ pkt.seq_num ^ pkt.timestamp_ms ^ static_cast<uint32_t>(pkt.command);
        hash = ((hash << 13) | (hash >> 19)) * 0x5BD1E995U;
        return hash ^ (hash >> 15);
    }

    State    state_{State::Safe};
    uint32_t lastSeq_{0};
    uint32_t armTimestampMs_{0};
    uint32_t secretKey_{0};
};

} // namespace fts
```

### Підсумок: інженерна ціна усвідомленої втрати

Усі системи безпеки в авіації будуються на принципі мінімізації загальної шкоди. Аварійна термінація — це інженерний інструмент останньої надії. Коли відмовляють сенсори, руйнується механіка чи зависає операційна система, зберегти дрон уже неможливо. Єдиний вибір, який залишається в інженера — вирішити, куди і як саме впаде некерована маса.

Керована термінація гарантує, що замість неконтрольованого падіння на житловий квартал зі швидкістю понад 130 км/год, апарат миттєво знеструмлюється й спускається на куполі в межах дозволеного сектора з безпечною швидкістю менше 4 м/с. Правильна дія у безнадійній аварії — вчасно та гарантовано впасти.
