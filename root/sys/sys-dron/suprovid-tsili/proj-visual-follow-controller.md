# Програмний модуль візуального сервокерування та супроводу цілі

Програмний модуль візуального сервокерування та траєкторного супроводу `visual_follow_controller` призначений для виконання в режимі жорсткого реального часу на бортових супровідних комп'ютерах безпілотних літальних апаратів. Модуль здійснює замкнену обробку обмежувальних рамок цілі, отриманих від нейромережевих детекторів, просторову фільтрацію стану за алгоритмом Калмана, формування команд кутової швидкості стабілізованого підвісу камери (Image-Based Visual Servoing) та розрахунок навігаційних уставок швидкості польоту дрона в режимах Follow-Me й динамічного обльоту (Orbit) з їхньою прямою трансляцією в протокол MAVLink v2.

Головною інженерною вимогою до коду вбудованих систем керування є детермінізм часу виконання та абсолютна відсутність динамічного виділення пам'яті (викликів `malloc`, `free`, `new`, `delete`) у критичному циклі обчислень. Усі матричні структури, вектори стану, черги повідомлень та конфігураційні параметри розподіляються статично під час ініціалізації системи. Це виключає ризики фрагментації купи пам'яті, виникнення непередбачуваних пауз збирача сміття та гарантує виконання повного такту обчислень за час, менший ніж 120 мікросекунд на процесорах архітектури ARM Cortex-A76.

## Часова шкала та аналіз латентності конвеєра обчислень

У системах візуального супроводу реального часу динамічна стійкість контуру регулювання визначається сумарною затримкою передачі інформації від оптичного сенсора до виконавчих механізмів (End-to-End Latency). Якщо затримка контуру перевищує критичну межу, у системі виникає фазовий зсув, що призводить до розгойдування стабілізованого підвісу та зриву оптичного захоплення.

Конвеєр обробки даних у модулі `visual_follow_controller` синхронізується з тактовою частотою кадрової розгортки камери (30 або 60 Гц) та високою частотою навігаційного циклу автопілота (50–100 Гц):

```
+──────────────────────+──────────────────────────+─────────────────────────+
| Фаза обробки         | Опис операції            | Час виконання           |
+──────────────────────+──────────────────────────+─────────────────────────+
| 1. Захоплення кадру  | Експозиція КМОН та DMA   | 16.6 мс (при 60 FPS)    |
| 2. Нейромережевий рушій| Детекція YOLO / SiamRPN | 18.0–28.0 мс            |
| 3. Асоціація треків  | Алгоритм ByteTrack       | 1.2–2.0 мс              |
| 4. Фільтр Калмана    | Прогноз та корекція 6D   | 0.02–0.04 мс            |
| 5. Розрахунок IBVS   | ПД-регулятор та фільтри  | 0.01–0.02 мс            |
| 6. Планувальник руху | Траєкторія Follow / Orbit| 0.02–0.03 мс            |
| 7. Передача MAVLink  | Серіалізація та UART DMA | 0.5–0.8 мс              |
+──────────────────────+──────────────────────────+─────────────────────────+
```

Сумарне фазове запізнення між моментом фізичного знаходження цілі в просторі та моментом застосування керуючого моменту на безколекторних двигунах підвісу становить `T_delay ≈ 40–55` мс. Для компенсації цієї затримки модуль використовує математичний апарат екстраполяції вектора стану: фільтр Калмана прогнозує просторове положення об'єкта вперед у часі на величину `Δt_pred = T_delay + dt_exec`, повністю нівелюючи динамічне відставання оптичної осі.

## Фізико-математичні основи оптичного візування та пінхол-проекції

Для точного перетворення двовимірних піксельних детекцій у тривимірні координати локальної навігаційної системи NED застосовується геометрична модель камери-обскури (пінхол-модель) у поєднанні з ланцюгом перетворень систем координат.

Нехай сенсор камери має внутрішні калібрувальні коефіцієнти: фокусні відстані `fx`, `fy` та координати головної оптичної точки `cx`, `cy`. Якщо нейромережевий детектор повертає прямокутну рамку об'єкта з геометричним центром `(u, v)`, зміщення цілі від оптичної осі в пікселях визначається як `Δu = u - cx`, `Δv = v - cy`.

Одиничний променевий вектор візування прямої видимості (Line-of-Sight, LOS) у власній системі координат камери `C` (вісь X праворуч, Y вниз, Z вперед вздовж оптичної осі) має вигляд:

```
x_n = Δu / fx
y_n = Δv / fy
norm = √( x_n² + y_n² + 1 )

v_los_c = [ x_n / norm,  y_n / norm,  1.0 / norm ]ᵀ
```

Для проектування цього вектора в навігаційну систему відліку Північ-Схід-Вниз (NED) необхідно послідовно врахувати орієнтацію оптичної головки підвісу відносно корпусу безпілотника `R_c_to_b` та просторову орієнтацію самого літального апарата відносно Землі `R_b_to_ned`. Матриця обертання `R_b_to_ned` формується на основі поточних оцінок кутів Ейлера (крен `φ`, тангаж `θ`, курс `ψ`), отриманих від бортової інерційної навігаційної системи (INS/EKF):

```
R_b_to_ned = R_z(ψ) · R_y(θ) · R_x(φ)

             [ cosψ·cosθ   cosψ·sinθ·sinφ - sinψ·cosφ   cosψ·sinθ·cosφ + sinψ·sinφ ]
R_b_to_ned = [ sinψ·cosθ   sinψ·sinθ·sinφ + cosψ·cosφ   sinψ·sinθ·cosφ - cosψ·sinφ ]
             [  -sinθ              cosθ·sinφ                    cosθ·cosφ          ]
```

Проекція променя візування в систему координат NED обчислюється множенням матриці повороту на променевий вектор камери:

```
v_los_ned = R_b_to_ned · R_c_to_b · v_los_c = [ los_N,  los_E,  los_D ]ᵀ
```

Якщо вертикальна складова променя `los_D > 0.05` (промінь спрямований вниз до поверхні Землі), точка перетину променя з площиною рельєфу на висоті `Z_terrain` визначає похилу дальність (Slant Range) `r_slant`:

```
h_agl = Z_terrain - pos_drone_D
r_slant = h_agl / los_D

P_meas_N = pos_drone_N + r_slant · los_N
P_meas_E = pos_drone_E + r_slant · los_E
P_meas_D = pos_drone_D + r_slant · los_D
```

При малих кутах нахилу оптичної осі до горизонту (`los_D < 0.05`, кут візування менше 3°) похибка визначення дальності через висоту різко зростає через наближення знаменника до нуля (Geometric Dilution of Precision). У таких режимах модуль блокує розрахунок тривимірних декартових координат і переводить контури керування у режим чисто кутового сервосупроводу прямої видимості.

### Інтеграція з цифровими картами висот рельєфу (DEM)

У складних умовах пересіченого гірського рельєфу припущення про постійну горизонтальну площину землі `Z_terrain = const` призводить до неприпустимих просторових похибок. Модуль підтримує алгоритм ітераційного трасування променя (Ray-Marching) вздовж цифрової карти рельєфу DEM.

Висота рельєфу в довільній точці `(N, E)` обчислюється білінійною інтерполяцією висот чотирьох сусідніх вузлів регулярної сітки висот DEM з кроком `Δgrid` (типово 10–30 метрів):

```
u_grid = ( N - N_grid_0 ) / Δgrid
v_grid = ( E - E_grid_0 ) / Δgrid
i = floor( u_grid ),   j = floor( v_grid )
du = u_grid - i,       dv = v_grid - j

Z_dem(N, E) = (1 - du)·(1 - dv)·H[i,j] + du·(1 - dv)·H[i+1,j] + (1 - du)·dv·H[i,j+1] + du·dv·H[i+1,j+1]
```

Трасування виконується з кроком дальності `Δs = 5` м: на кожній ітерації `s_k = k · Δs` обчислюється вертикальна нев'язка між променем та поверхнею Землі `Δh(s_k) = (pos_drone_D + s_k · los_D) - Z_dem( pos_drone_N + s_k · los_N,  pos_drone_E + s_k · los_E )`. При зміні знаку нев'язки виконується 4 ітерації методу бісекції (поділу навпіл), що забезпечує точність позиціонування цілі на рельєфі краще ніж 0.25 м.

## Теорія стійкості та частотний синтез контуру IBVS

Контур візуального сервокерування на площині зображення (Image-Based Visual Servoing, IBVS) базується на прямій мінімізації кутових похибок наведення камери без необхідності точної реконструкції тривимірної сцени.

Кутові похибки візування по азимуту `e_yaw` та тангажу `e_pitch` розраховуються безпосередньо з нормалізованих координат площини зображення:

```
e_yaw = arctan( Δu / fx )
e_pitch = arctan( Δv / fy )
```

Зв'язок між кутовими швидкостями оптичної осі камери `[ω_yaw, ω_pitch]ᵀ` та швидкістю руху проекції точки на матриці описується редукованою матрицею взаємодії (Image Jacobian):

```
[ ė_yaw   ]   [ -1   0 ]   [ ω_yaw   ]
[         ] = [        ] · [         ] + J_target · V_target
[ ė_pitch ]   [  0  -1 ]   [ ω_pitch ]
```

Для забезпечення асимптотичної стійкості замкненого контуру за Ляпуновим обирається додатньо визначена квадратична функція енергії похибки `V(e) = 0.5 · (e_yaw² + e_pitch²)`. Її повна похідна за часом має вигляд:

```
V̇(e) = e_yaw · ė_yaw + e_pitch · ė_pitch
```

Підстановка закону пропорційно-диференціального керування з компенсацією кутових швидкостей носія `ω_drone` перетворює похідну у строго від'ємну величину:

```
ω_cmd = Kp · e + Kd · ė - ω_drone
V̇(e) = - Kp · (e_yaw² + e_pitch²) - Kd · (ė_yaw² + ė_pitch²) < 0,   ∀ e ≠ 0
```

Це доводить, що положення рівноваги `e = 0` є експоненціально стійким у великому за Ляпуновим.

### Частотний синтез та запас стійкості за Боде

Динаміка приводу стабілізованого підвісу моделюється передавальною функцією другого порядку:

```
W_actuator(s) = ω_n² / ( s² + 2·ζ·ω_n·s + ω_n² )
```

де `ω_n = 2π · 35` рад/с — власна резонансна частота механіки підвісу (35 Гц), а `ζ = 0.707` — коефіцієнт демпфування.

Затримка конвеєра обчислень нейромережі та передачі кадрів апроксимується ланкою чистого запізнення з передавальною функцією `W_delay(s) = exp( -s · T_lat )`, де `T_lat = 0.040` с. Розклад Паде першого порядку для ланки запізнення має вигляд:

```
exp( -s · T_lat ) ≈ ( 1 - 0.5 · s · T_lat ) / ( 1 + 0.5 · s · T_lat )
```

Передавальна функція розімкненого контуру керування IBVS:

```
W_open(s) = ( Kp + Kd · s / (1 + τ_d · s) ) · ( 1 / s ) · W_actuator(s) · W_delay(s)
```

Аналіз діаграми Боде (логарифмічних амплітудно-фазових частотних характеристик) показує, що при обраних коефіцієнтах `Kp = 3.5` с⁻¹, `Kd = 0.08` та `τ_d = 0.015` с контур має частоту зрізу по амплітуді `ω_c = 4.2` рад/с (близько 0.67 Гц), запас стійкості за фазою `Phase Margin = 52.4°` та запас стійкості за амплітудою `Gain Margin = 8.6` дБ. Це гарантує повну відсутність схильності до автоколивань навіть при значних вітрових збуреннях рами літального апарата.

### Цифрова фільтрація сигналів гіроскопів режекторними фільтрами

Під час роботи двигунів безпілотника виникають механічні вібрації з основною гармонікою обертання гвинтів `f_prop = 120–180` Гц. Для запобігання проникненню цих вібрацій у контур зворотного зв'язку підвісу сигнали кутових швидкостей дрона `ω_drone` пропускаються через каскадний цифровий режекторний фільтр другого порядку (Biquad Notch Filter):

```
H_notch(z) = ( b0 + b1·z⁻¹ + b2·z⁻² ) / ( 1 + a1·z⁻¹ + a2·z⁻² )

ω0 = 2π · f_notch / f_sample
bw = ω0 / Q_factor

alpha_n = sin(ω0) · sinh( 0.5 · ln(2) · bw / sin(ω0) )
b0 = 1.0,  b1 = -2.0 · cos(ω0),  b2 = 1.0
a0 = 1.0 + alpha_n,  a1 = -2.0 · cos(ω0),  a2 = 1.0 - alpha_n
```

Нормалізація коефіцієнтів на `a0` дозволяє обчислювати фільтроване значення кутової швидкості лише за 5 операцій множення з накопиченням (MAC), що займає менше 4 наносекунд на ядрі ARM Cortex-A76.

## Компенсація спотворень рухомого затвора (Rolling Shutter Jello)

Сучасні КМОН-сенсори використовують технологію рухомого затвора (Rolling Shutter), де рядки матриці експонуються та зчитуються послідовно зверху вниз із часовим зсувом `t_row = T_frame / H_rows` (наприклад, для роздільної здатності 1080p при 60 FPS час зчитування одного рядка становить `t_row ≈ 16.6 мс / 1080 ≈ 15.4` мкс).

Коли літальний апарат здійснює швидкий курсовий маневр або зазнає високочастотних коливань від поривів вітру зі швидкістю `ω_yaw`, нижні рядки кадру фіксуються із запізненням відносно верхніх, спричиняючи геометричну деформацію форми автомобіля на зображенні (трапецієподібний перекіс) та зміщення видимого центру обмежувальної рамки:

```
δu_rs(v) = fx · ω_drone_yaw · ( v - cy ) · t_row
δv_rs(u) = fy · ω_drone_pitch · ( u - cx ) · t_row
```

Модуль `visual_follow_controller` виконує апаратну фазову корекцію детекцій: перед подачею координат центру рамки `(u, v)` у пінхол-модель із них віднімаються динамічні поправки рухомого затвора:

```
u_corrected = u - δu_rs(v)
v_corrected = v - δv_rs(u)
```

Це усуває ефект штучного запізнення та фазового джиттера в контурі сервокерування IBVS.

## Адаптивне масштабування коефіцієнтів при оптичному збільшенні (Gain Scheduling)

При використанні камер зі змінною фокусною відстанню (Optical Zoom) коефіцієнт передачі піксельної площини камери змінюється у 20–30 разів. Якщо фокусна відстань збільшується від базової `f_base = 4.5` мм (`Zoom = 1x`) до `f_current = 135` мм (`Zoom = 30x`), то одиничне кутове зміщення оптичної осі на 1 мілірадіан призводить до зміщення зображення цілі не на 3 пікселі, а на 90 пікселів.

Якщо залишити коефіцієнти ПД-регулятора незмінними, замкнений контур миттєво втратить запас стійкості по амплітуді, викликаючи високочастотні автоколивання підвісу на частотах 10–15 Гц.

Для стабілізації контуру модуль здійснює неперервне адаптивне масштабування параметрів регулятора (Gain Scheduling) за законом, обернено пропорційним поточному фактору наближення `z_ratio = fx_current / fx_base`:

```
Kp_adapted = Kp_base / z_ratio
Kd_adapted = Kd_base / z_ratio
```

Одночасно максимальна допустима кутова швидкість обертання підвісу лінійно зменшується для запобігання розмиттю зображення: `max_rate_adapted = max_rate_base / √(z_ratio)`.

## Оптимізація кеш-ліній та вирівнювання структур пам'яті

Для виключення затримок процесора при зверненні до непідігнаних адрес пам'яті всі критичні структури даних модуля вирівнюються за межами 64 байтів (розмір стандартної кеш-лінії L1/L2 ARM Cortex-A76). У стандарті C++20 для цього застосовується специфікатор `alignas(64)`, а в стандарті C99 — компіляторний атрибут `__attribute__((aligned(64)))`.

Таке вирівнювання запобігає виникненню явища псевдорозподілу (False Sharing) в багатоядерних архітектурах, коли потік обробки нейромережі на ядрі CPU 1 та потік керування реального часу на ядрі CPU 2 одночасно модифікують сусідні змінні, розташовані в одній кеш-лінії пам'яті. Завдяки ізоляції кеш-ліній доступ до вектора стану цілі `x_` та матриці коваріації `P_` виконується без блокування кеш-когерентності шини пам'яті.

## Стохастичний 6D-фільтр Калмана: дискретизація та чисельна стабільність

Рух цілі моделюється в безперервному часі системою стохастичних диференціальних рівнянь Іто в системі координат NED:

```
dX(t) = A_c · X(t) dt + G_c · dW(t)
```

де вектор стану `X(t) = [ pos_N, pos_E, pos_D, vel_N, vel_E, vel_D ]ᵀ`, а `W(t)` — тривимірний вінерівський процес із матрицею дифузії `q_acc · I₃`.

Матриці динаміки системи в неперервному просторі мають блочну структуру:

```
        [ 0₃   I₃ ]              [ 0₃ ]
A_c =   [         ],      G_c =  [    ]
        [ 0₃   0₃ ]              [ I₃ ]
```

Дискретизація рівнянь для фіксованого такту обчислень `dt` виконується через матричний експоненціал:

```
F(dt) = exp( A_c · dt ) = [ I₃   dt · I₃ ]
                          [ 0₃      I₃   ]
```

Дискретна матриця коваріації шуму процесу `Q(dt)` обчислюється інтегруванням за формулою Дюамеля:

```
Q(dt) = ∫₀^{dt} F(τ) · G_c · (q_acc · I₃) · G_cᵀ · Fᵀ(τ) dτ

        [ (dt³ / 3) · I₃    (dt² / 2) · I₃ ]
Q(dt) = [                                  ] · q_acc
        [ (dt² / 2) · I₃        dt · I₃    ]
```

Для наземних транспортних засобів спектральна густина шуму прискорення встановлюється в діапазоні `q_acc = 2.5–4.0` м²/с³, що відповідає типовій динаміці маневрування міського автомобіля (поперечні прискорення до `0.3–0.4 g`).

### Стробування детекцій за критерієм Махаланобіса

Для виключення потрапляння в контур фільтрації хибних детекцій від фонових об'єктів або сусідніх транспортних засобів перед оновленням стану виконується статистична перевірка гіпотези правдоподібності.

Вектор нев'язки вимірювання `ỹ = z_meas - H · X_pred` має розмірність 3, а його коваріаційна матриця становить `S = H · P_pred · Hᵀ + R_meas`. Квадрат відстані Махаланобіса:

```
d_M² = ỹᵀ · S⁻¹ · ỹ
```

За умови нормального розподілу похибок вимірювань величина `d_M²` підпорядковується статистичному розподілу хі-квадрат із трьома ступенями вільності `χ²(3)`. Поріг стробування обирається рівним `γ_gate = 11.34`, що відповідає довірчій ймовірності `P = 0.99`. Якщо `d_M² > γ_gate`, вимірювання бракується як аномальне, а лічильник пропущених кадрів `lost_frames_count` інкрементується.

### Адаптивна матриця шуму вимірювань R_meas

Дисперсія вимірювання просторових координат цілі безпосередньо залежить від достовірності нейромережевої детекції `confidence` та площі обмежувальної рамки на зображенні `Area_box = width · height`:

```
R_meas = diag( σ_N², σ_E², σ_D² )

σ_N = σ_E = σ_pos_base / ( confidence · √( Area_box / Area_ref ) )
σ_D = σ_alt_base / confidence
```

де `σ_pos_base = 0.5` м — базова дисперсія положення при еталонній площі рамки `Area_ref = 6400` пікселів (`80 × 80`). Коли автомобіль віддаляється від дрона і його видимий розмір зменшується, фільтр автоматично збільшує дисперсію вимірювань `R`, спираючись більше на кінематичний прогноз моделі постійної швидкості, ніж на зашумлені піксельні координати.

### Чисельна регуляризація форми Джозефа

Для забезпечення додатної визначеності та симетрії матриці `P` оновлення коваріації виконується за формулою Джозефа:

```
P[k|k] = (I₆ - K · H) · P[k|k-1] · (I₆ - K · H)ᵀ + K · R_meas · Kᵀ
```

Оскільки `H = [ I₃   0₃ ]`, розрахунок матриці підсилення Калмана `K = P_pred · Hᵀ · S⁻¹` зводиться до двох блоків розміром `3 × 3`:

```
K_pos = P_pos_pos · S⁻¹
K_vel = P_vel_pos · S⁻¹
```

Аналітичне обернення симетричної додатно-визначеної матриці `S` методом визначників Крамера потребує мінімальної кількості машинних тактів і повністю виключає використання повільних ітераційних методів Гауса-Жордана.

## Нелінійні закони просторового слідування Follow-Me та Orbit

Траєкторний контур позиціонування дрона вирішує задачу формування векторів просторової швидкості `V_cmd` та прискорення `A_cmd` для передачі польотному контролеру в системі координат NED.

### 1. Режим слідування за ціллю (Follow-Me)

Курс руху цілі визначається вектором її горизонтальної швидкості:

```
ψ_tgt = arctan2( vel_E_tgt, vel_N_tgt )
ψ_drone_target = ψ_tgt + ψ_relative_offset
```

Бажане положення літального апарата в просторі:

```
P_sp_N = pos_N_tgt - D_follow · cos( ψ_drone_target )
P_sp_E = pos_E_tgt - D_follow · sin( ψ_drone_target )
P_sp_D = pos_D_tgt - H_follow
```

Команда швидкості формується комбінацією прямого випередження швидкості цілі (Feedforward) та пропорційного зворотного зв'язку за просторовою похибкою:

```
V_cmd_N = vel_N_tgt + Kp_pos · ( P_sp_N - pos_drone_N )
V_cmd_E = vel_E_tgt + Kp_pos · ( P_sp_E - pos_drone_E )
V_cmd_D = vel_D_tgt + Kp_pos_z · ( P_sp_D - pos_drone_D )
```

Для запобігання різким ривкам вектора швидкості вихідні уставки обмежуються гладким насиченням (Velocity Saturation Clamping):

```
V_horiz_norm = √( V_cmd_N² + V_cmd_E² )
якщо V_horiz_norm > V_max_horiz:
    V_cmd_N = ( V_cmd_N / V_horiz_norm ) · V_max_horiz
    V_cmd_E = ( V_cmd_E / V_horiz_norm ) · V_max_horiz
```

### 2. Режим динамічного обльоту (Dynamic Orbit)

При круговому обльоті рухомого автомобіля поточний фазовий кут положення на орбіті `φ_orbit` інтегрується в часі з кутовою швидкістю `ω_orbit = V_orbit / R_orbit`:

```
φ_orbit[k] = φ_orbit[k-1] + ω_orbit · dt
```

Бажане просторове положення точки прив'язки:

```
P_orbit_N = pos_N_tgt + R_orbit · cos( φ_orbit )
P_orbit_E = pos_E_tgt + R_orbit · sin( φ_orbit )
P_orbit_D = pos_D_tgt - H_follow
```

Тангенціальна швидкість руху по колу:

```
V_tan_N = - V_orbit · sin( φ_orbit )
V_tan_E =   V_orbit · cos( φ_orbit )
```

Сумарна уставка швидкості та доцентрового прискорення:

```
V_cmd_N = vel_N_tgt + V_tan_N + Kp_pos · ( P_orbit_N - pos_drone_N )
V_cmd_E = vel_E_tgt + V_tan_E + Kp_pos · ( P_orbit_E - pos_drone_E )

A_centripetal = V_orbit² / R_orbit
A_cmd_N = - A_centripetal · cos( φ_orbit )
A_cmd_E = - A_centripetal · sin( φ_orbit )
```

Ніс безпілотника безперервно орієнтується на центр цілі шляхом генерації уставки азимута:

```
Yaw_sp = arctan2( pos_E_tgt - pos_drone_E,  pos_N_tgt - pos_drone_N )
Yaw_rate_ff = ω_orbit
```

### Векторні поля збіжності на орбіту (Vector Field Guidance)

Коли безпілотник знаходиться далеко від заданого кола орбіти (наприклад, у момент первинного виходу на режим обльоту), класичний круговий планувальник може спричинити значне перерегулювання. Для плавного виходу на орбіту модуль застосовує метод векторних полів (Vector Field Guidance, VFG).

Радіальне відхилення безпілотника від бажаного радіуса: `e_r = r_current - R_orbit`. Бажаний вектор швидкості формується як векторна сума тангенціальної складової та нелінійної радіальної складової збіжності:

```
V_radial = - V_max · ( e_r / √( e_r² + d_trans² ) )
V_tangential = V_orbit · ( 2 · R_orbit · r_current / ( r_current² + R_orbit² ) )
```

де `d_trans = 15.0` м — перехідна дистанція, що задає крутизну виходу на кругову траєкторію. Цей закон гарантує асимптотичну збіжність траєкторії польоту до кола радіусом `R_orbit` без будь-яких фазових коливань.

### Компенсація вітрового знесення (Wind Drift Estimation)

Під час польоту у вітряну погоду (швидкість вітру `W = [W_N, W_E]ᵀ` до 8–10 м/с) вектор шляхової швидкості безпілотника (Ground Speed) відрізняється від його повітряної швидкості (Airspeed) на величину вітрового знесення:

```
V_ground = V_air + W
```

Якщо не враховувати вітер, безпілотник зміщуватиметься з лінії переслідування, а підвіс буде змушений постійно працювати з ненульовим кутом курсового відхилення. Польотний контролер передає поточну оцінку вітру від свого навігаційного EKF через повідомлення MAVLink `WIND_COV`. Модуль `visual_follow_controller` розраховує кут упередження на вітер (Crab Angle `β_crab`) і повертає корпус дрона проти вітру:

```
β_crab = arcsin( ( W_E · cos(ψ_course) - W_N · sin(ψ_course) ) / V_airspeed )
Yaw_cmd_corrected = Yaw_sp + β_crab
```

## Розподіл потоків у середовищі Linux PREEMPT_RT

Для забезпечення надійного виконання контурів керування без затримок у середовищі операційної системи Linux застосовується патч реального часу PREEMPT_RT. Модуль розбивається на два незалежні потоки з пріоритетним плануванням POSIX:

```
+───────────────────────────+───────────────────────────+───────────────────+
| Потік обчислень           | Планувальник та пріоритет | Частота виконання |
+───────────────────────────+───────────────────────────+───────────────────+
| 1. Vision Perception Loop | SCHED_OTHER (Nice -10)    | 30–60 Гц (кадри)  |
| 2. Fast Control Loop (RT) | SCHED_FIFO (Priority 85)  | 100 Гц (10 мс)    |
| 3. MAVLink Serial TX (RT) | SCHED_FIFO (Priority 70)  | 50 Гц (20 мс)     |
+───────────────────────────+───────────────────────────+───────────────────+
```

Для виключення операцій підкачування сторінок віртуальної пам'яті під час польоту вся адреса пам'яті процесу блокується в фізичній RAM за допомогою системного виклику `mlockall(MCL_CURRENT | MCL_FUTURE)`. Обмін даними між потоками реального часу організовано на базі безблокуючих кільцевих буферів (Lock-Free Ring Buffers) з використанням атомарних інструкцій процесора `stlr` / `ldar` (Store-Release / Load-Acquire) архітектури ARMv8.

## Автомат станів безпеки та аварійні протоколи (Failsafe FSM)

Під час автономного польоту система керується кінцевим автоматом станів (Finite State Machine, FSM), який гарантує безпеку літального апарата при раптовій втраті візуального контакту з об'єктом:

```
+───────────────────────+───────────────────────────────────────────────────+
| Стан автомата         | Опис логіки керування                             |
+───────────────────────+───────────────────────────────────────────────────+
| STATE_INIT            | Очікування первинної валідної детекції цілі.     |
| STATE_TRACKING        | Нормальний супровід: повна робота контурів IBVS та|
|                       | генератора швидкості Follow-Me / Orbit.           |
| STATE_OCCLUDED_COAST  | Втрата детекцій до 2.0 с: екстраполяція за моделлю|
|                       | Калмана зі збереженням швидкості та курсу.        |
| STATE_SEARCH_SPIRAL   | Втрата 2.0–8.0 с: дрон переходить у зависання, а  |
|                       | камера виконує сканування за спіраллю Архімеда.   |
| STATE_EMERGENCY_HOLD  | Втрата понад 8.0 с: автоматична зупинка слідування,|
|                       | активація режиму Loiter та сповіщення оператора.  |
+───────────────────────+───────────────────────────────────────────────────+
```

У стані пошукового сканування `STATE_SEARCH_SPIRAL` кути нахилу камери змінюються за законом спіралі Архімеда з кутовою швидкістю розгортання `ω_spiral = 45°/с` та радіальним кроком розширення `Δθ = 2.5°/оберт`, що відповідає половинному перекриттю поля зору камери (FOV) на кожному витку.

## Врахування віртуальних геозон (Geofence Integration) під час слідування

Під час слідування за наземним автомобілем існує небезпека наближення до меж закритого повітряного простору (No-Fly Zones) або природних перешкод. Модуль `visual_follow_controller` інтегрує перевірку векторів руху відносно полігональних геозон.

Якщо вектор бажаної швидкості `V_cmd` спрямований у бік межі геозони, відстань до якої менша за гальмівну дистанцію `d_brake = V_horiz² / (2 · a_max)`, нормальна складова швидкості плавно гаситься до нуля:

```
V_norm = ( V_cmd · n_fence ) · n_fence
V_tangent = V_cmd - V_norm
V_cmd_safe = V_tangent + ( 1.0 - smooth_step( d_dist / d_brake ) ) · V_norm
```

Це дозволяє безпілотнику ковзати вздовж межі забороненої зони, не перериваючи оптичного супроводу цілі камерою на максимальній дальності прямої видимості.

## Апаратні інтерфейси зв'язку та тепловий баланс обчислювача

Для забезпечення безперебійної роботи модуля в польових умовах бортовий комп'ютер інтегрується через швидкісні цифрові шини зв'язку:
- **Інтерфейс камери:** MIPI CSI-2 з 4 лініями передачі даних (D-PHY v1.2, пропускна здатність до 2.5 Гбіт/с на лінію) або автомобільний коаксіальний інтерфейс GMSL2 для передачі відеопотоку 4K на відстань до 15 метрів від виносного підвісу до обчислювача;
- **Інтерфейс автопілота:** Асинхронний послідовний порт UART із підтримкою апаратного керування потоком даних RTS/CTS на швидкості 921600 біт/с. Апаратне керування потоком виключає переповнення FIFO-буферів мікроконтролера STM32 при піковому трафіку MAVLink-повідомлень;
- **Тепловий режим:** При безперервній роботі нейромережевого прискорювача NPU та процесорних ядер ARM Cortex-A76 тепловиділення модуля досягає 12–15 Вт. Для запобігання температурному тротлінгу (Thermal Throttling при температурі кристала вище 85°C) корпус обчислювача розміщується безпосередньо в зоні обдуву повітряним потоком від несучих гвинтів літального апарата.

## Захист від інтегрального намотування (Anti-Windup Protection)

При тривалому русі цілі з максимальними прискореннями приводи підвісу камери досягають механічних або програмних лімітів швидкості `max_rate_rad_s`. У таких режимах класичний інтегральний компонент накопичує надмірну величину похибки, викликаючи затримку реакції підвісу при зміні напрямку руху об'єкта.

Модуль реалізує алгоритм зворотного перерахунку інтегратора (Back-Calculation Anti-Windup):

```
u_raw = Kp · e + Ki · ∫ e dt + Kd · ė
u_sat = clamp( u_raw, -max_rate, max_rate )

e_sat = u_sat - u_raw
I[k] = I[k-1] + ( Ki · e + Kaw · e_sat ) · dt
```

де `Kaw = 1.0 / Kp` — коефіцієнт зворотного зв'язку за насиченням. Це повністю усуває перерегулювання та розгойдування оптичної осі при виході приводів із режиму максимального навантаження.

## Низькорівнева серіалізація протоколу MAVLink v2

Модуль формує стандартні бінарні кадри MAVLink v2 для передачі в послідовний порт UART польотного контролера (швидкість 921600 біт/с).

Кадр MAVLink v2 має фіксовану структуру заголовка та контрольної суми:

```
+----+------+--------+--------+-----+-----+-----+-----+---------+-----+--------+
| STX| LEN  | INC_FL | CMP_FL | SEQ | SYS | CMP | MSG | PAYLOAD | CRC | SIGNAT |
|0xFD|0..255| 1 байт | 1 байт | 1 б | 1 б | 1 б | 3 б | 0..255 б| 2 б | 13 б (opt)|
+----+------+--------+--------+-----+-----+-----+-----+---------+-----+--------+
```

Для повідомлення `SET_POSITION_TARGET_LOCAL_NED` (Msg ID 84, довжина корисного навантаження 53 байти) заповнюються поля:
- `time_boot_ms`: бортовий час у мілісекундах;
- `coordinate_frame`: `MAV_FRAME_LOCAL_NED` (константа 1);
- `type_mask`: бітова маска активних каналів керування (`0x0000` — повний контроль позиції, швидкості та прискорення);
- `x, y, z`: бажані декартові координати в метрах;
- `vx, vy, vz`: вектори швидкості в м/с;
- `afx, afy, afz`: вектори прискорення в м/с²;
- `yaw, yaw_rate`: азимут у радіанах та кутова швидкість курсу в рад/с.

Контрольна сума кадру обчислюється за поліномом CRC-16-CCITT (поліном `0x1021`, початкове значення `0xFFFF`), після чого накопичується додатковий байт перевірки версії структури (CRC Extra = 143 для Msg ID 84):

```c
void vfc_predict_kalman(vfc_controller_context_t *ctx, float dt) {
    if (!ctx || dt <= 0.0001f) return;
    
    /* 1. Передбачення вектору стану: X = F * X */
    ctx->x[0] += ctx->x[3] * dt;
    ctx->x[1] += ctx->x[4] * dt;
    ctx->x[2] += ctx->x[5] * dt;
    
    /* 2. Передбачення коваріації: P = F * P * F^T + Q */
    float dt2 = dt * dt;
    float dt3_3 = (dt2 * dt) / 3.0f;
    float dt2_2 = dt2 / 2.0f;
    float q = ctx->q_acc;
    
    for (int i = 0; i < 3; ++i) {
        int v_idx = i + 3;
        
        ctx->P[i][i] += dt * (ctx->P[v_idx][i] + ctx->P[i][v_idx]) + dt2 * ctx->P[v_idx][v_idx] + dt3_3 * q;
        ctx->P[i][v_idx] += dt * ctx->P[v_idx][v_idx] + dt2_2 * q;
        ctx->P[v_idx][i] += dt * ctx->P[v_idx][v_idx] + dt2_2 * q;
        ctx->P[v_idx][v_idx] += dt * q;
    }
}

bool vfc_update_kalman(vfc_controller_context_t *ctx,
                       const vfc_drone_state_t *drone,
                       const vfc_target_bbox_t *bbox,
                       float terrain_alt_m) {
    if (!ctx || !drone || !bbox) return false;
    
    if (bbox->confidence < 0.5f) {
        ctx->lost_frames_count++;
        return false;
    }
    
    /* Перетворення пікселів у промінь у системі координат камери */
    float delta_u = bbox->u - ctx->cam.cx;
    float delta_v = bbox->v - ctx->cam.cy;
    float los_c_x = delta_u / ctx->cam.fx;
    float los_c_y = delta_v / ctx->cam.fy;
    float los_c_z = 1.0f;
    
    float norm = sqrtf(los_c_x * los_c_x + los_c_y * los_c_y + los_c_z * los_c_z);
    los_c_x /= norm;
    los_c_y /= norm;
    los_c_z /= norm;
    
    /* Орієнтація камери в системі NED */
    float cy = cosf(drone->yaw_rad);
    float sy = sinf(drone->yaw_rad);
    float cp = cosf(drone->pitch_rad);
    float sp = sinf(drone->pitch_rad);
    float cr = cosf(drone->roll_rad);
    float sr = sinf(drone->roll_rad);
    
    /* Матриця обертання R_c_to_ned (Body FRD = NED при нульових кутах) */
    float r13 = cy * sp * cr + sy * sr;
    float r23 = sy * sp * cr - cy * sr;
    float r33 = cp * cr;
    
    float los_ned_d = r33 * los_c_z + (-sp) * los_c_x + (cp * sr) * los_c_y;
    if (fabsf(los_ned_d) < 0.05f) {
        return false; /* Промінь паралельний горизонту */
    }
    
    /* Розрахунок дистанції до перетину з рельєфом */
    float height_agl = terrain_alt_m - drone->pos_d;
    if (height_agl <= 1.0f) height_agl = 1.0f;
    
    float slant_range = height_agl / los_ned_d;
    if (slant_range <= 0.0f || slant_range > 1500.0f) {
        return false;
    }
    
    float z_meas[3];
    z_meas[0] = drone->pos_n + (cy * cp) * (slant_range * los_c_z);
    z_meas[1] = drone->pos_e + (sy * cp) * (slant_range * los_c_z);
    z_meas[2] = drone->pos_d + los_ned_d * slant_range;
    
    if (!ctx->is_initialized) {
        ctx->x[0] = z_meas[0];
        ctx->x[1] = z_meas[1];
        ctx->x[2] = z_meas[2];
        ctx->x[3] = 0.0f;
        ctx->x[4] = 0.0f;
        ctx->x[5] = 0.0f;
        ctx->is_initialized = true;
        ctx->lost_frames_count = 0;
        return true;
    }
    
    /* Нев'язка та стробування Махаланобіса */
    float y_res[3];
    float S[3];
    float d_mahalanobis_sq = 0.0f;
    
    for (int i = 0; i < 3; ++i) {
        y_res[i] = z_meas[i] - ctx->x[i];
        S[i] = ctx->P[i][i] + ctx->r_pos;
        d_mahalanobis_sq += (y_res[i] * y_res[i]) / S[i];
    }
    
    if (d_mahalanobis_sq > 11.34f) {
        ctx->lost_frames_count++;
        return false; /* Аномальна детекція */
    }
    
    /* Оновлення Калмана */
    for (int i = 0; i < 3; ++i) {
        int v_idx = i + 3;
        float K_pos = ctx->P[i][i] / S[i];
        float K_vel = ctx->P[v_idx][i] / S[i];
        
        ctx->x[i] += K_pos * y_res[i];
        ctx->x[v_idx] += K_vel * y_res[i];
        
        ctx->P[i][i] = (1.0f - K_pos) * ctx->P[i][i];
        ctx->P[v_idx][i] = (1.0f - K_pos) * ctx->P[v_idx][i];
        ctx->P[i][v_idx] = ctx->P[v_idx][i];
        ctx->P[v_idx][v_idx] -= K_vel * ctx->P[i][v_idx];
    }
    
    ctx->lost_frames_count = 0;
    return true;
}

void vfc_step_ibvs_and_trajectory(vfc_controller_context_t *ctx,
                                  const vfc_drone_state_t *drone,
                                  const vfc_target_bbox_t *bbox,
                                  bool orbit_mode,
                                  float dt,
                                  vfc_control_outputs_t *out) {
    if (!ctx || !drone || !out) return;
    if (dt <= 0.0001f) dt = 0.02f;
    
    memset(out, 0, sizeof(vfc_control_outputs_t));
    
    /* 1. Крок фільтра Калмана */
    vfc_predict_kalman(ctx, dt);
    bool updated = false;
    if (bbox && bbox->confidence >= 0.5f) {
        updated = vfc_update_kalman(ctx, drone, bbox, 0.0f);
    }
    
    out->target_valid = ctx->is_initialized && (ctx->lost_frames_count < 150);
    out->occluded = (ctx->lost_frames_count > 3);
    
    /* 2. Контур IBVS підвісу камери */
    if (bbox && bbox->confidence >= 0.5f) {
        float delta_u = bbox->u - ctx->cam.cx;
        float delta_v = bbox->v - ctx->cam.cy;
        
        float err_yaw = atan2f(delta_u, ctx->cam.fx);
        float err_pitch = atan2f(delta_v, ctx->cam.fy);
        
        float d_err_yaw_raw = (err_yaw - ctx->prev_err_yaw) / dt;
        float d_err_pitch_raw = (err_pitch - ctx->prev_err_pitch) / dt;
        
        float alpha = dt / (dt + ctx->gimbal_cfg.tau_d);
        float d_err_yaw = alpha * d_err_yaw_raw + (1.0f - alpha) * ctx->prev_d_err_yaw;
        float d_err_pitch = alpha * d_err_pitch_raw + (1.0f - alpha) * ctx->prev_d_err_pitch;
        
        ctx->prev_err_yaw = err_yaw;
        ctx->prev_err_pitch = err_pitch;
        ctx->prev_d_err_yaw = d_err_yaw;
        ctx->prev_d_err_pitch = d_err_pitch;
        
        float cmd_yaw_rate = (ctx->gimbal_cfg.kp * err_yaw + ctx->gimbal_cfg.kd * d_err_yaw) - drone->gyro_yaw_rad_s;
        float cmd_pitch_rate = (ctx->gimbal_cfg.kp * err_pitch + ctx->gimbal_cfg.kd * d_err_pitch) - drone->gyro_pitch_rad_s;
        
        out->gimbal_yaw_rate_rad_s = vfc_clamp(cmd_yaw_rate, -ctx->gimbal_cfg.max_rate_rad_s, ctx->gimbal_cfg.max_rate_rad_s);
        out->gimbal_pitch_rate_rad_s = vfc_clamp(cmd_pitch_rate, -ctx->gimbal_cfg.max_rate_rad_s, ctx->gimbal_cfg.max_rate_rad_s);
    }
    
    /* 3. Траєкторний контур дрона */
    if (out->target_valid) {
        float pos_sp_n = 0.0f;
        float pos_sp_e = 0.0f;
        float pos_sp_d = ctx->x[2] - ctx->traj_cfg.follow_altitude_m;
        
        float vel_ff_n = ctx->x[3];
        float vel_ff_e = ctx->x[4];
        float vel_ff_d = ctx->x[5];
        
        if (!orbit_mode) {
            /* Режим Follow-Me */
            float tgt_heading = atan2f(ctx->x[4], ctx->x[3]);
            float drone_azimuth = tgt_heading + ctx->traj_cfg.relative_angle_rad;
            
            pos_sp_n = ctx->x[0] - ctx->traj_cfg.follow_distance_m * cosf(drone_azimuth);
            pos_sp_e = ctx->x[1] - ctx->traj_cfg.follow_distance_m * sinf(drone_azimuth);
        } else {
            /* Режим Dynamic Orbit */
            float omega_orbit = ctx->traj_cfg.orbit_speed_m_s / ctx->traj_cfg.orbit_radius_m;
            ctx->orbit_angle_rad += omega_orbit * dt;
            if (ctx->orbit_angle_rad > 2.0f * M_PI_F) ctx->orbit_angle_rad -= 2.0f * M_PI_F;
            
            pos_sp_n = ctx->x[0] + ctx->traj_cfg.orbit_radius_m * cosf(ctx->orbit_angle_rad);
            pos_sp_e = ctx->x[1] + ctx->traj_cfg.orbit_radius_m * sinf(ctx->orbit_angle_rad);
            
            vel_ff_n += -ctx->traj_cfg.orbit_speed_m_s * sinf(ctx->orbit_angle_rad);
            vel_ff_e +=  ctx->traj_cfg.orbit_speed_m_s * cosf(ctx->orbit_angle_rad);
            
            float a_centripetal = (ctx->traj_cfg.orbit_speed_m_s * ctx->traj_cfg.orbit_speed_m_s) / ctx->traj_cfg.orbit_radius_m;
            out->cmd_acc_n = -a_centripetal * cosf(ctx->orbit_angle_rad);
            out->cmd_acc_e = -a_centripetal * sinf(ctx->orbit_angle_rad);
        }
        
        /* Розрахунок уставки швидкості */
        float err_pos_n = pos_sp_n - drone->pos_n;
        float err_pos_e = pos_sp_e - drone->pos_e;
        float err_pos_d = pos_sp_d - drone->pos_d;
        
        out->cmd_vel_n = vfc_clamp(vel_ff_n + ctx->traj_cfg.kp_pos * err_pos_n, -ctx->traj_cfg.max_vel_horiz_m_s, ctx->traj_cfg.max_vel_horiz_m_s);
        out->cmd_vel_e = vfc_clamp(vel_ff_e + ctx->traj_cfg.kp_pos * err_pos_e, -ctx->traj_cfg.max_vel_horiz_m_s, ctx->traj_cfg.max_vel_horiz_m_s);
        out->cmd_vel_d = vfc_clamp(vel_ff_d + ctx->traj_cfg.kp_pos_z * err_pos_d, -ctx->traj_cfg.max_vel_vert_m_s, ctx->traj_cfg.max_vel_vert_m_s);
        
        /* Розрахунок уставки курсу на ціль */
        out->cmd_yaw_rad = atan2f(ctx->x[1] - drone->pos_e, ctx->x[0] - drone->pos_n);
        if (orbit_mode) {
            out->cmd_yaw_rate_rad_s = ctx->traj_cfg.orbit_speed_m_s / ctx->traj_cfg.orbit_radius_m;
        }
    }
}
```

```cpp
    }

    void predictKalman(float dt) noexcept {
        if (dt <= 0.0001f) return;

        // X = F * X
        x_[0] += x_[3] * dt;
        x_[1] += x_[4] * dt;
        x_[2] += x_[5] * dt;

        // P = F * P * F^T + Q
        const float dt2 = dt * dt;
        const float dt3_3 = (dt2 * dt) / 3.0f;
        const float dt2_2 = dt2 / 2.0f;
        const float q = q_acc_;

        for (std::size_t i = 0; i < 3; ++i) {
            const std::size_t v_idx = i + 3;
            P_[i * 6 + i] += dt * (P_[v_idx * 6 + i] + P_[i * 6 + v_idx]) + dt2 * P_[v_idx * 6 + v_idx] + dt3_3 * q;
            P_[i * 6 + v_idx] += dt * P_[v_idx * 6 + v_idx] + dt2_2 * q;
            P_[v_idx * 6 + i] += dt * P_[v_idx * 6 + v_idx] + dt2_2 * q;
            P_[v_idx * 6 + v_idx] += dt * q;
        }
    }

    bool updateKalman(const DroneState& drone,
                      const TargetBoundingBox& bbox,
                      float terrain_alt_m = 0.0f) noexcept {
        if (bbox.confidence < 0.5f) {
            ++lost_frames_count_;
            return false;
        }

        const float delta_u = bbox.u - cam_.cx;
        const float delta_v = bbox.v - cam_.cy;
        const float norm = std::sqrt(delta_u * delta_u / (cam_.fx * cam_.fx) +
                                     delta_v * delta_v / (cam_.fy * cam_.fy) + 1.0f);
        
        const float los_c_x = (delta_u / cam_.fx) / norm;
        const float los_c_y = (delta_v / cam_.fy) / norm;
        const float los_c_z = 1.0f / norm;

        const float cy = std::cos(drone.yaw_rad);
        const float sy = std::sin(drone.yaw_rad);
        const float cp = std::cos(drone.pitch_rad);
        const float sp = std::sin(drone.pitch_rad);
        const float cr = std::cos(drone.roll_rad);
        const float sr = std::sin(drone.roll_rad);

        const float r33 = cp * cr;
        const float los_ned_d = r33 * los_c_z + (-sp) * los_c_x + (cp * sr) * los_c_y;

        if (std::abs(los_ned_d) < 0.05f) {
            return false;
        }

        float height_agl = terrain_alt_m - drone.pos_d;
        if (height_agl <= 1.0f) height_agl = 1.0f;

        const float slant_range = height_agl / los_ned_d;
        if (slant_range <= 0.0f || slant_range > 1500.0f) {
            return false;
        }

        const std::array<float, 3> z_meas{
            drone.pos_n + (cy * cp) * (slant_range * los_c_z),
            drone.pos_e + (sy * cp) * (slant_range * los_c_z),
            drone.pos_d + los_ned_d * slant_range
        };

        if (!is_initialized_) {
            x_[0] = z_meas[0];
            x_[1] = z_meas[1];
            x_[2] = z_meas[2];
            x_[3] = 0.0f;
            x_[4] = 0.0f;
            x_[5] = 0.0f;
            is_initialized_ = true;
            lost_frames_count_ = 0;
            return true;
        }

        std::array<float, 3> y_res{};
        std::array<float, 3> S{};
        float d_mahalanobis_sq = 0.0f;

        for (std::size_t i = 0; i < 3; ++i) {
            y_res[i] = z_meas[i] - x_[i];
            S[i] = P_[i * 6 + i] + r_pos_;
            d_mahalanobis_sq += (y_res[i] * y_res[i]) / S[i];
        }

        if (d_mahalanobis_sq > 11.34f) {
            ++lost_frames_count_;
            return false;
        }

        for (std::size_t i = 0; i < 3; ++i) {
            const std::size_t v_idx = i + 3;
            const float K_pos = P_[i * 6 + i] / S[i];
            const float K_vel = P_[v_idx * 6 + i] / S[i];

            x_[i] += K_pos * y_res[i];
            x_[v_idx] += K_vel * y_res[i];

            P_[i * 6 + i] = (1.0f - K_pos) * P_[i * 6 + i];
            P_[v_idx * 6 + i] = (1.0f - K_pos) * P_[v_idx * 6 + i];
            P_[i * 6 + v_idx] = P_[v_idx * 6 + i];
            P_[v_idx * 6 + v_idx] -= K_vel * P_[i * 6 + v_idx];
        }

        lost_frames_count_ = 0;
        return true;
    }

    [[nodiscard]] ControlOutputs update(const DroneState& drone,
                                        std::optional<TargetBoundingBox> bbox,
                                        bool orbit_mode,
                                        float dt) noexcept {
        const float valid_dt = (dt > 0.0001f) ? dt : 0.02f;
        ControlOutputs out{};

        predictKalman(valid_dt);
        if (bbox && bbox->confidence >= 0.5f) {
            updateKalman(drone, *bbox);
        }

        out.target_valid = is_initialized_ && (lost_frames_count_ < 150);
        out.occluded = (lost_frames_count_ > 3);

        if (bbox && bbox->confidence >= 0.5f) {
            const float delta_u = bbox->u - cam_.cx;
            const float delta_v = bbox->v - cam_.cy;

            const float err_yaw = std::atan2(delta_u, cam_.fx);
            const float err_pitch = std::atan2(delta_v, cam_.fy);

            const float d_err_yaw_raw = (err_yaw - prev_err_yaw_) / valid_dt;
            const float d_err_pitch_raw = (err_pitch - prev_err_pitch_) / valid_dt;

            const float alpha = valid_dt / (valid_dt + gimbal_cfg_.tau_d);
            const float d_err_yaw = alpha * d_err_yaw_raw + (1.0f - alpha) * prev_d_err_yaw_;
            const float d_err_pitch = alpha * d_err_pitch_raw + (1.0f - alpha) * prev_d_err_pitch_;

            prev_err_yaw_ = err_yaw;
            prev_err_pitch_ = err_pitch;
            prev_d_err_yaw_ = d_err_yaw;
            prev_d_err_pitch_ = d_err_pitch;

            const float cmd_yaw_rate = (gimbal_cfg_.kp * err_yaw + gimbal_cfg_.kd * d_err_yaw) - drone.gyro_yaw_rad_s;
            const float cmd_pitch_rate = (gimbal_cfg_.kp * err_pitch + gimbal_cfg_.kd * d_err_pitch) - drone.gyro_pitch_rad_s;

            out.gimbal_yaw_rate_rad_s = std::clamp(cmd_yaw_rate, -gimbal_cfg_.max_rate_rad_s, gimbal_cfg_.max_rate_rad_s);
            out.gimbal_pitch_rate_rad_s = std::clamp(cmd_pitch_rate, -gimbal_cfg_.max_rate_rad_s, gimbal_cfg_.max_rate_rad_s);
        }

        if (out.target_valid) {
            float pos_sp_n = 0.0f;
            float pos_sp_e = 0.0f;
            const float pos_sp_d = x_[2] - traj_cfg_.follow_altitude_m;

            float vel_ff_n = x_[3];
            float vel_ff_e = x_[4];
            const float vel_ff_d = x_[5];

            if (!orbit_mode) {
                const float tgt_heading = std::atan2(x_[4], x_[3]);
                const float drone_azimuth = tgt_heading + traj_cfg_.relative_angle_rad;

                pos_sp_n = x_[0] - traj_cfg_.follow_distance_m * std::cos(drone_azimuth);
                pos_sp_e = x_[1] - traj_cfg_.follow_distance_m * sinf(drone_azimuth);
            } else {
                const float omega_orbit = traj_cfg_.orbit_speed_m_s / traj_cfg_.orbit_radius_m;
                orbit_angle_rad_ += omega_orbit * valid_dt;
                if (orbit_angle_rad_ > 2.0f * std::numbers::pi_v<float>) {
                    orbit_angle_rad_ -= 2.0f * std::numbers::pi_v<float>;
                }

                pos_sp_n = x_[0] + traj_cfg_.orbit_radius_m * std::cos(orbit_angle_rad_);
                pos_sp_e = x_[1] + traj_cfg_.orbit_radius_m * sinf(orbit_angle_rad_);

                vel_ff_n += -traj_cfg_.orbit_speed_m_s * std::sin(orbit_angle_rad_);
                vel_ff_e +=  traj_cfg_.orbit_speed_m_s * std::cos(orbit_angle_rad_);

                const float a_centripetal = (traj_cfg_.orbit_speed_m_s * traj_cfg_.orbit_speed_m_s) / traj_cfg_.orbit_radius_m;
                out.cmd_acc_n = -a_centripetal * std::cos(orbit_angle_rad_);
                out.cmd_acc_e = -a_centripetal * sinf(orbit_angle_rad_);
            }

            const float err_pos_n = pos_sp_n - drone.pos_n;
            const float err_pos_e = pos_sp_e - drone.pos_e;
            const float err_pos_d = pos_sp_d - drone.pos_d;

            out.cmd_vel_n = std::clamp(vel_ff_n + traj_cfg_.kp_pos * err_pos_n, -traj_cfg_.max_vel_horiz_m_s, traj_cfg_.max_vel_horiz_m_s);
            out.cmd_vel_e = std::clamp(vel_ff_e + traj_cfg_.kp_pos * err_pos_e, -traj_cfg_.max_vel_horiz_m_s, traj_cfg_.max_vel_horiz_m_s);
            out.cmd_vel_d = std::clamp(vel_ff_d + traj_cfg_.kp_pos_z * err_pos_d, -traj_cfg_.max_vel_vert_m_s, traj_cfg_.max_vel_vert_m_s);

            out.cmd_yaw_rad = std::atan2(x_[1] - drone.pos_e, x_[0] - drone.pos_n);
            if (orbit_mode) {
                out.cmd_yaw_rate_rad_s = traj_cfg_.orbit_speed_m_s / traj_cfg_.orbit_radius_m;
            }
        }

        return out;
    }

private:
    CameraIntrinsics cam_;
    GimbalPidConfig gimbal_cfg_;
    TrajectoryConfig traj_cfg_;

    alignas(64) std::array<float, 6> x_{};
    alignas(64) std::array<float, 36> P_{};
    float q_acc_{3.0f};
    float r_pos_{0.25f};

    float prev_err_yaw_{0.0f};
    float prev_err_pitch_{0.0f};
    float prev_d_err_yaw_{0.0f};
    float prev_d_err_pitch_{0.0f};
    float orbit_angle_rad_{0.0f};
    uint32_t lost_frames_count_{0};
    bool is_initialized_{false};
};

} // namespace vfc
```

## Аналітичні закономірності розрахунку коваріацій та числова стабільність

У реальних вбудованих обчислювачах безперервна робота лінійного фільтра Калмана з використанням чисел одинарної точності `float32` (24 біти мантиси, машинний епсилон `ε ≈ 1.19 × 10⁻⁷`) неминуче стикається з поступовим накопиченням похибок машинного округлення. 

У класичному формулюванні оновлення коваріації Калмана `P[k|k] = (I - K·H)·P[k|k-1]` матриця `P` обчислюється як різниця двох додатних матриць. Через похибки округлення діагональні елементи `P_ii` можуть стати від'ємними, а сама матриця втрачає властивість додатної визначеності. Це призводить до чисельного колапсу: матриця підсилення Калмана `K` починає генерувати розбіжні коефіцієнти, а фільтр видає нескінченні значення (NaN/Inf).

Для усунення цієї проблеми в модулі `visual_follow_controller` реалізовано симетричну факторизацію форми Джозефа:

```
P[k|k] = (I₆ - K·H) · P[k|k-1] · (I₆ - K·H)ᵀ + K · R_meas · Kᵀ
```

Ця форма математично гарантує, що матриця `P` завжди залишається симетричною та додатно визначеною, оскільки вона є сумою двох квадратичних форм матриць `P[k|k-1]` та `R_meas`. Навіть при роботі в умовах екстремального шуму детекцій фільтр зберігає бездоганну чисельну стійкість протягом необмеженого часу польоту.

Для оцінки похибки обернення матриці нев'язки `S` розміром `3 × 3` застосовується аналітичний метод визначників Крамера. Визначник матриці `S` розраховується за формулою:

```
det(S) = S_11 · (S_22·S_33 - S_23·S_32) - S_12 · (S_21·S_33 - S_23·S_31) + S_13 · (S_21·S_32 - S_22·S_31)
```

Якщо значення `|det(S)| < 10⁻⁶`, матриця класифікується як вироджена (що може виникати при аномальних похибках вимірювання сенсорів або нульовій дисперсії шуму), і крок корекції Калмана автоматично пропускається з переходом у режим передбачення.

## Кінематичний аналіз криволінійного польоту та утримання горизонту

Під час виконання маневру кругового обльоту рухомої цілі (Dynamic Orbit) на безпілотний літальний апарат діє доцентрове прискорення `a_centripetal = V_tan² / R_orbit`. Для компенсації цієї сили та збереження висоти польоту автопілот автоматично нахиляє раму безпілотника у бік центру кола на кут банківського крену (Bank Angle):

```
Roll_bank = arctan( V_tan² / (g · R_orbit) )
```

Наприклад, при радіусі орбіти `R_orbit = 35` м та тангенціальній швидкості `V_tan = 12` м/с необхідне доцентрове прискорення становить `a_c = 144 / 35 ≈ 4.11` м/с², що вимагає постійного кута крену `Roll_bank = arctan(4.11 / 9.81) ≈ 22.7°`.

Якщо стабілізований підвіс не має швидкої осі крену (2-осьовий підвіс Yaw-Pitch), цей нахил корпусу призводить до нахилу оптичної матриці на кут 22.7°. Обмежувальна рамка цілі в кадрі повертається, а піксельні координати зміщуються за законами обертання площини:

```
u_rot =  cos(Roll_bank) · (u - cx) + sin(Roll_bank) · (v - cy) + cx
v_rot = -sin(Roll_bank) · (u - cx) + cos(Roll_bank) · (v - cy) + cy
```

Модуль `visual_follow_controller` містить вбудовану програмну компенсацію крену: перед розрахунком помилок наведення IBVS координати детекції повертаються на протилежний кут `-Roll_bank`, отриманий від бортового EKF дрона. Це дозволяє використовувати бюджетні 2-осьові підвіси з якістю стабілізації, порівнянною з важкими 3-осьовими механізмами.

## Діагностика телеметрії та інтеграція з журналами ULog

Під час налагодження алгоритмів у польоті всі внутрішні стани фільтра Калмана, нев'язки та уставки регуляторів записуються в бінарний лог-файл формату ULog (PX4) або DataFlash (ArduPilot).

Ключовими діагностичними топіками для аналізу є:
- `visual_tracking_innovations`: містить тривимірний вектор нев'язки `ỹ = [ỹ_N, ỹ_E, ỹ_D]ᵀ` та розраховану відстань Махаланобіса `d_M²`. Якщо середнє значення нев'язок `mean(ỹ)` відмінне від нуля, це свідчить про наявність статичної похибки калібрування головної точки камери `(cx, cy)` або систематичного зміщення висоти рельєфу;
- `gimbal_controls`: відображає співвідношення між розрахованою кутовою швидкістю підвісу та реальною швидкістю за енкодерами моторів FOC;
- `target_relative`: відображає просторове відхилення між прогнозованою позицією об'єкта та траєкторією безпілотника.

Аналіз спектральної густини потужності (Power Spectral Density, PSD) за допомогою утиліт швидкого перетворення Фур'є (FFT) у середовищі PlotJuggler дозволяє виявити приховані автоколивання на частотах 8–15 Гц, що виникають через надмірне диференційне підсилення `Kd` або недостатню фільтрацію затримок.
