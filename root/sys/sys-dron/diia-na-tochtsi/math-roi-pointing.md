# 🧮 Розрахунок кутів наведення підвісу на точку інтересу (ROI)

Управління оптичним підвісом під час автономного польоту вимагає неперервного перерахунку просторових векторів: камера має дивитися на нерухомий або рухомий наземний орієнтир попри те, що безпілотник постійно змінює кути крену, тангажу та курсу під дією вітрових збурень і маневрів траєкторії. Цей розрахунок визначає точні кути тангажу (`Pitch`) та азимуту (`Yaw`) підвісу у світовій та зв'язаній системах координат з урахуванням геометричного плеча виносу вузла кріплення (`lever arm`), а також виводить формули прямого випередження за кутовою швидкістю (`feedforward`).

---

### Системи координат та вхідні вектори

Для однозначного опису просторової геометрії візування вводяться три ортогональні праві системи координат:
1. **Земна навігаційна система `NED` (North-East-Down):** початок у точці старту або поточному нулі локальної навігації. Вісь `X_N` напрямлена на північ, `Y_E` — на схід, `Z_D` — вертикально вниз за вектором гравітації.
2. **Зв'язана система координат носія `Body Frame` (`B`):** початок у центрі мас безпілотника. Вісь `X_B` спрямована вперед уздовж поздовжньої осі фюзеляжу, `Y_B` — праворуч за правим крилом або променем, `Z_B` — вниз крізь днище.
3. **Система координат основи підвісу `Gimbal Mount Frame` (`G_0`):** жорстко прив'язана до монтажного майданчика вібророзв'язки на корпусі дрона.

Вхідними даними навігаційного фільтра є:
- Поточне просторове положення центру мас БПЛА в системі `NED`: `P_uav = [X_u, Y_u, Z_u]ᵀ`.
- Вектор лінійної швидкості БПЛА в системі `NED`: `V_uav = [V_x, V_y, V_z]ᵀ`.
- Кватерніон орієнтації корпусу БПЛА відносно земної системи `NED`: `q_b^ned = [q_w, q_x, q_y, q_z]ᵀ`.
- Вектор просторового виносу підвісу відносно центру мас у зв'язаній системі `Body`: `r_mount^b = [r_x, r_y, r_z]ᵀ`.
- Координати цільової точки інтересу в системі `NED`: `P_target = [X_t, Y_t, Z_t]ᵀ`.

### Геодезична прив'язка та перетворення WGS-84 у локальний кадр NED

Цільова точка інтересу в польотному завданні зазвичай задається глобальними географічними координатами: широтою `φ_t`, довготою `λ_t` та абсолютною висотою `h_t` над еліпсоїдом WGS-84. Для переходу в локальну декартову систему координат `NED` з початком у точці `(φ_0, λ_0, h_0)` використовується геодезична проекція на базі радіусів кривини еліпсоїда:

```
R_N = a / √(1 - e² · sin²(φ_0))                    [радіус кривини першого вертикала]
R_M = a · (1 - e²) / (1 - e² · sin²(φ_0))^{1.5}    [радіус кривини меридіана]

де a = 6378137.0 м — велика піввісь еліпсоїда WGS-84, e² = 0.00669437999014 — квадрат ексцентриситету.

X_t = (φ_t - φ_0) · (R_M + h_0)
Y_t = (λ_t - λ_0) · (R_N + h_0) · cos(φ_0)
Z_t = -(h_t - h_0)
```

На тактичних дистанціях прямої видимості (до 10 км) похибка цієї локальної проекції не перевищує 0.05 м, що значно менше похибки побутових GNSS-приймачів.

### Матриця просторової орієнтації носія

Перетворення довільного вектора зі зв'язаної системи `Body` у земну `NED` виконується матрицею напрямних косинусів `R_b^ned`, що розраховується за компонентами кватерніона орієнтації:

```
R_b^ned =
[ 1 - 2·(q_y² + q_z²),   2·(q_x·q_y - q_w·q_z), 2·(q_x·q_z + q_w·q_y) ]
[ 2·(q_x·q_y + q_w·q_z), 1 - 2·(q_x² + q_z²),   2·(q_y·q_z - q_w·q_x) ]
[ 2·(q_x·q_z - q_w·q_y), 2·(q_y·q_z + q_w·q_x), 1 - 2·(q_x² + q_y²) ]
```

### Вектор візування цілі з урахуванням плеча виносу

Положення оптичного центру камери `P_cam` у світовій системі `NED` визначається сумою позиції центру мас носія та повернутого вектора виносу кронштейна:

```
P_cam = P_uav + R_b^ned · r_mount^b
```

Вектор прямого візування від камери до наземної цілі `ΔP^ned` в системі `NED`:

```
ΔP^ned = P_target - P_cam
       = [ ΔX_ned ]   [ X_t - (X_u + (R_b^ned · r_mount^b)_x) ]
       = [ ΔY_ned ] = [ Y_t - (Y_u + (R_b^ned · r_mount^b)_y) ]
       = [ ΔZ_ned ]   [ Z_t - (Z_u + (R_b^ned · r_mount^b)_z) ]
```

Горизонтальна відстань між оптичною віссю камери та цільовою точкою на площині `N-E`:

```
d_xy = √(ΔX_ned² + ΔY_ned²)
```

Повна просторова дальність до об'єкта в тривимірному просторі:

```
D_3d = √(ΔX_ned² + ΔY_ned² + ΔZ_ned²)
     = √(d_xy² + ΔZ_ned²)
```

### Розрахунок кутів наведення у світовій системі (World Frame)

Якщо стабілізований підвіс працює в режимі світової стабілізації (`Earth Frame Tracking`), бортові контролери приводів підвісу орієнтуються безпосередньо на абсолютні кути відносно площини горизонту та географічного півночі:

```
θ_pitch_world = atan2(-ΔZ_ned, d_xy)             [кут тангажу відносно площини горизонту]
Ψ_yaw_world   = atan2(ΔY_ned, ΔX_ned)             [абсолютний азимут візування на північ]
```

Знак мінус перед `ΔZ_ned` зумовлений тим, що в навігаційній системі `NED` вісь `Z` спрямована вниз. Коли ціль розташована нижче літального апарата (`Z_t > Z_cam`, тобто `ΔZ_ned > 0`), кут тангажу нахилу камери вниз є від'ємним (`θ_pitch < 0`).

---

### Перетворення вектора візування у зв'язану систему корпусу

Якщо підвіс приймає уставки кутів відносно корпусу безпілотника (`Body-Relative Frame`), вектор візування трансформується у зв'язану систему за допомогою транспонованої матриці повороту `(R_b^ned)ᵀ`:

```
ΔP^body = (R_b^ned)ᵀ · ΔP^ned
        = [ ΔX_b, ΔY_b, ΔZ_b ]ᵀ
```

Послідовний розрахунок проекцій вектора візування на осі літального апарата та визначення кутів:

```
ΔX_b = (R_b^ned)₁₁·ΔX_ned + (R_b^ned)₂₁·ΔY_ned + (R_b^ned)₃₁·ΔZ_ned    [проекція на поздовжню вісь X_body]
ΔY_b = (R_b^ned)₁₂·ΔX_ned + (R_b^ned)₂₂·ΔY_ned + (R_b^ned)₃₂·ΔZ_ned    [проекція на поперечну вісь Y_body]
ΔZ_b = (R_b^ned)₁₃·ΔX_ned + (R_b^ned)₂₃·ΔY_ned + (R_b^ned)₃₃·ΔZ_ned    [проекція на вертикальну вісь Z_body]

d_xy_b = √(ΔX_b² + ΔY_b²)                                               [горизонтальна проекція в площині корпусу]

θ_pitch_body = atan2(-ΔZ_b, d_xy_b)                                     [кутова уставка тангажу відносно носія]
Ψ_yaw_body   = atan2(ΔY_b, ΔX_b)                                         [кутова уставка рискання відносно носія]
```

### Пряме випередження за кутовими швидкостями (Feedforward Rate Control)

Коли безпілотник летить на високій швидкості повз наземний орієнтир, звичайний пропорційний регулятор положення підвісу дає динамічну похибку відставання. Для компенсації фазового запізнення обчислюються теоретичні кутові швидкості зміни лінії візування шляхом диференціювання рівнянь наведення за часом.

Похідна вектора візування нерухомої цілі відносно камери дорівнює вектору лінійної швидкості дрона з протилежним знаком:

```
d(ΔP^ned)/dt = -V_uav = [ -V_x, -V_y, -V_z ]ᵀ
```

Диференціюючи вирази для кутів тангажу та азимуту, отримуємо аналітичні формули кутових швидкостей випередження:

```
ω_yaw_ff = d(Ψ_yaw)/dt
         = (ΔX_ned · (-V_y) - ΔY_ned · (-V_x)) / (ΔX_ned² + ΔY_ned²)                    [диференціювання atan2(ΔY, ΔX)]
         = (ΔY_ned · V_x - ΔX_ned · V_y) / (d_xy²)                                      [підстановка d_xy² та розкриття дужок]

ω_pitch_ff = d(θ_pitch)/dt
           = (d_xy · V_z - (-ΔZ_ned) · (d(d_xy)/dt)) / (D_3d²)                          [диференціювання atan2(-ΔZ, d_xy)]
           = (d_xy · V_z + ΔZ_ned · ((ΔX_ned·(-V_x) + ΔY_ned·(-V_y)) / d_xy)) / (D_3d²) [ланцюгове правило для d(d_xy)/dt]
           = (d_xy² · V_z - ΔZ_ned · (ΔX_ned · V_x + ΔY_ned · V_y)) / (d_xy · D_3d²)    [зведення дробів до спільного знаменника]
```

Ці розраховані швидкості `ω_yaw_ff` та `ω_pitch_ff` передаються безпосередньо в контур швидкості драйверів моторів підвісу як випереджувальний сигнал `Feedforward Setpoint`, зменшуючи статичну похибку стеження майже до нуля.

### Числовий приклад розрахунку наведення

Розглянемо політ розвідувального дрона над заданим районом:
- Поточні координати БПЛА: `P_uav = [100.0, 200.0, -150.0]ᵀ` м (висота польоту 150 м над точкою старту).
- Швидкість польоту БПЛА: `V_uav = [15.0, 5.0, 0.0]ᵀ` м/с (політ на північний схід).
- Координати цілі: `P_target = [250.0, 320.0, 0.0]ᵀ` м.
- Кронштейн підвісу винесено вперед: `r_mount^b = [0.25, 0.0, 0.08]ᵀ` м.
- Дрон летить за курсом `Ψ = 45°` без крену та тангажу (`q = [cos(22.5°), 0, 0, sin(22.5°)]ᵀ = [0.9239, 0, 0, 0.3827]ᵀ`).

1. **Розрахунок вектора виносу в NED:**
```
r_mount^ned = R_b^ned · r_mount^b
            = [ 0.25 · cos(45°), 0.25 · sin(45°), 0.08 ]ᵀ
            = [ 0.177, 0.177, 0.080 ]ᵀ м
```

2. **Положення камери:**
```
P_cam = [ 100.0 + 0.177, 200.0 + 0.177, -150.0 + 0.080 ]ᵀ
      = [ 100.177, 200.177, -149.920 ]ᵀ м
```

3. **Вектор візування цілі:**
```
ΔP^ned = [ 250.0 - 100.177, 320.0 - 200.177, 0.0 - (-149.920) ]ᵀ
       = [ 149.823, 119.823, 149.920 ]ᵀ м
```

4. **Дальність та кути візування:**
```
d_xy = √(149.823² + 119.823²) = √(22446.9 + 14357.6) = √36804.5 = 191.845 м
D_3d = √(191.845² + 149.920²) = √(36804.5 + 22476.0) = √59280.5 = 243.476 м

θ_pitch_world = atan2(-149.920, 191.845) = -37.99°  (нахил камери вниз на 38 градусів)
Ψ_yaw_world   = atan2(119.823, 149.823) = +38.65°   (азимут 38.65 градусів на північний схід)
```

5. **Розрахунок швидкостей випередження:**
```
ω_yaw_ff = (119.823 · 15.0 - 149.823 · 5.0) / (36804.5)                                [підстановка числових значень]
         = (1797.345 - 749.115) / 36804.5                                               [обчислення добутків у чисельнику]
         = 1048.230 / 36804.5                                                           [обчислення різниці]
         = +0.02848 рад/с                                                               [ділення чисельника на знаменник]
         = +1.63°/с                                                                     [переведення радіанів у градуси за секунду]

ω_pitch_ff = (36804.5 · 0.0 - 149.920 · (149.823 · 15.0 + 119.823 · 5.0)) / (191.845 · 59280.5) [підстановка числових значень]
           = -149.920 · (2247.345 + 599.115) / (11372667.0)                             [спрощення дужок та знаменника]
           = -149.920 · 2846.460 / 11372667.0                                           [сума в дужках чисельника]
           = -426741.3 / 11372667.0                                                     [добуток у чисельнику]
           = -0.03752 рад/с                                                             [ділення]
           = -2.15°/с                                                                   [переведення в градуси за секунду]
```

### Особливі точки та усунення сингулярності надиру

Коли дрон пролітає безпосередньо над ціллю, вектор візування спрямований вертикально вниз (`d_xy → 0`, `ΔZ_ned ≈ D_3d`). У точці надиру (`θ_pitch = -90°`) виникає кінематична сингулярність (gimbal lock): кут азимуту `Ψ_yaw` стає невизначеним (`atan2(0, 0)`), що за наївної реалізації призводить до хаотичного розкручування підвісу за віссю рискання.

Для запобігання зриву стабілізації вводиться радіальна зона гарантованого утримання (`R_nadir_deadband` = 1.5–2.0 м):

```
if d_xy < R_nadir_deadband:
    θ_pitch = -89.5°                                [обмеження тангажу перед сингулярністю]
    Ψ_yaw   = Ψ_yaw_previous                        [заморожування азимуту до виходу з зони]
```

### Фільтрація кутової швидкості та розгортання фази азимуту

При переході кута азимуту через межу `±180°` пряма різниця уставок породжує стрибок у `360°`. Контролер підвісу обчислює найкоротшу кутову дугу розвороту через функцію розгортання фази:

```
ΔΨ = Ψ_target - Ψ_current
ΔΨ_wrapped = ΔΨ - 360° · round(ΔΨ / 360°)           [зведення кутової похибки до інтервалу [-180°, +180°]]
```

Для запобігання зриву крокових або безколекторних двигунів підвісу через надмірні динамічні прискорення розрахована швидкість перекидання обмежується темпом наростання (`Slew Rate Limiter`):

```
ω_max = 60.0°/с                                     [максимальна кутова швидкість приводу]
Δt    = t_k - t_{k-1}                               [період оновлення контуру наведення]

Δθ_cmd = clamp(θ_target - θ_current, -ω_max · Δt, +ω_max · Δt)
θ_filtered = θ_current + Δθ_cmd
```
