# ⚙️ Покроковий розбір: як заплутаний рахунок тане хід за ходом

У статті ми бачили короткий смак: зібгану петлю рахунку розсікли двома ходами й лишили зелений слід між ними. Тут — повний прохід, і не заради краси кінцевого стану, а заради **відчуття кроку**. Мета розбору не «подивись, яким охайним став код», а «подивись, яким дрібним був кожен рух і як щоразу трос тримав». Наприкінці один хід навмисне почервоніє — щоб побачити трос у дії, а не лише на словах.

Ось функція, гірша за ту, зі статті, — така, яку реально знаходиш у чужому сервісі рахунків. Місячний рахунок за спожиту енергію: кілька лічильників, тарифи, надлишкова ставка понад ліміт, бонусні кіловати активним побутовим клієнтам, друк. Усе — в одній петлі, з іменами, що бурмочуть:

:::tabs
```ts
type Tariff = "day" | "night" | "business";
interface Line { meter: string; tariff: Tariff; kWh: number; }
interface Account { customer: string; active: boolean; lines: Line[]; }

function statement(acc: Account): string {
  let ta = 0;                    // total amount, у копійках
  let vc = 0;                    // volume credits — бонусні кВт·год
  let out = `Рахунок — ${acc.customer}\n`;

  for (const l of acc.lines) {
    // ціна рядка за тарифом
    let a = 0;
    if (l.tariff === "day") {
      a = l.kWh * 250;
      if (l.kWh > 100) a += (l.kWh - 100) * 30;
    } else if (l.tariff === "night") {
      a = l.kWh * 120;
    } else if (l.tariff === "business") {
      a = l.kWh * 300;
      if (l.kWh > 500) a += (l.kWh - 500) * 40;
    } else {
      throw new Error(`невідомий тариф: ${l.tariff}`);
    }

    // бонусні кВт·год — лише активним і не бізнесу
    if (acc.active) {
      if (l.tariff !== "business") {
        vc += Math.max(l.kWh - 200, 0);
        if (l.tariff === "night") vc += Math.floor(l.kWh / 500);
      }
    }

    out += `  ${l.meter}: ${l.kWh} кВт·год — ${(a / 100).toFixed(2)} грн\n`;
    ta += a;
  }

  out += `Разом: ${(ta / 100).toFixed(2)} грн\n`;
  out += `Бонусні кіловати: ${vc}\n`;
  return out;
}
```

:::

Понад два десятки рядків, і в них злиплося все: тариф рахується поряд із бонусами, які рахуються поряд із друком; імена `ta`, `vc`, `a`, `l` мовчать про суть; вкладений `if` усередині `if` для бонусів; одна петля тягне **дві** різні суми водночас. Кожна з цих дрібниць — окремий запах, і кожна лікується окремим названим ходом каталогу. Ми пройдемо ланцюг: винести функцію, перейменувати, винести змінну, знову винести функцію, замінити вкладений if охоронними реченнями, розділити цикл, замінити temp запитом. Сім ходів — і жоден сам собою не страшний.

## Ідея: кожен хід — це названа заміна форми, а не переписування

Уся дисципліна тримається на одному: **хід не змінює поведінки**. «Винести функцію» переставляє шматок обчислення під ім'я — той самий вхід дає той самий вихід. «Перейменувати» через інструмент оновлює всі посилання розом. Кожен рух — така сама рівність форм, як розкладання виразу на множники: інший запис, те саме значення. А раз поведінка стала — між ходами лежить **оракул**, із яким звіряєшся: прогнав тести, зелено — форма змінилась, значення ні, йдемо далі.

Тому першим ділом — сітка. Функція повертає рядок; найпростіший, найчесніший тест над таким кодом — **золотий зразок** (golden master): зафіксувати цілий вихід на певному вході й після кожного ходу звіряти байт у байт. Це різновид [характеризаційного тесту](root:progarch/characterization-tests) — коли над ділянкою тестів нема, спершу накидаєш сітку поверх наявної поведінки, ще не знаючи, «правильна» вона чи ні; важливо лише, що після ходу вона **та сама**.

:::tabs

Числа тут справжні, звірмо руками, щоб далі довіряти зеленому:

```
Кухня  (day, 150):  150·250 = 37500;  150>100 → +(150−100)·30 = +1500  → 39000  → 390.00
Бойлер (night, 320): 320·120 = 38400;  надлишку night не має           → 38400  → 384.00
Гараж  (day, 80):   80·250 = 20000;   80>100 хибно, надлишку нема       → 20000  → 200.00
Разом:  39000 + 38400 + 20000 = 97400  → 974.00
Бонуси: Кухня max(150−200,0)=0 · Бойлер max(320−200,0)=120 + ⌊320/500⌋=0 · Гараж max(80−200,0)=0  → 120
```

Зелено. Далі кожен хід — і після кожного цей самий тест крутиться знову. Загальну картину руху — щоразу зелено, з одним червоним і відкотом — тримай перед очима:

## Хід 1 — винести функцію `amountFor`

Найгустіший вузол — обчислення ціни рядка за тарифом. Витягуємо його (Extract Function): дивимось, що фрагмент **читає** (`l`) — це стане параметром; що він **лишає по собі** (`a`) — це стане поверненням. Копіюємо тіло під новим ім'ям, компілюємо, і аж тоді замінюємо оригінал викликом.

```ts
function amountFor(l: Line): number {
  let a = 0;
  if (l.tariff === "day") {
    a = l.kWh * 250;
    if (l.kWh > 100) a += (l.kWh - 100) * 30;
  } else if (l.tariff === "night") {
    a = l.kWh * 120;
  } else if (l.tariff === "business") {
    a = l.kWh * 300;
    if (l.kWh > 500) a += (l.kWh - 500) * 40;
  } else {
    throw new Error(`невідомий тариф: ${l.tariff}`);
  }
  return a;
}

// у statement блок тарифу зник, лишився виклик:
    const a = amountFor(l);
// тести: зелено
```

Це рівно той хід, який сучасне середовище виконує **автоматично** — виділив блок, «Extract Function», дав ім'я. І тут варто довіритися інструменту, а не пальцям: автоматичне винесення само розбереться з параметрами й поверненням і не проґавить жодного посилання. Ми показуємо тіло руками лише щоб було видно, що саме відбувається.

## Хід 2 — перейменувати те, що бурмоче

Функція вийшла, але всередині досі `a` і `l`. Ім'я, яке бреше чи мовчить, — окремий запах, і лікує його окремий хід: перейменувати (Rename). Через інструмент — щоб усі згадки оновилися разом. `l` → `line`, `a` → `result` (усталена назва для змінної-накопичувача, яку функція зрештою поверне):

```ts
function amountFor(line: Line): number {
  let result = 0;
  if (line.tariff === "day") {
    result = line.kWh * 250;
    if (line.kWh > 100) result += (line.kWh - 100) * 30;
  } else if (line.tariff === "night") {
    result = line.kWh * 120;
  } else if (line.tariff === "business") {
    result = line.kWh * 300;
    if (line.kWh > 500) result += (line.kWh - 500) * 40;
  } else {
    throw new Error(`невідомий тариф: ${line.tariff}`);
  }
  return result;
}
// у statement: for (const line of acc.lines) { … amountFor(line) … }
// тести: зелено
```

Перейменування здається косметикою, та це найдешевший і найцінніший хід каталогу: нуль ризику (інструмент гарантує), а код починає казати правду. Кожне наступне читання цієї функції тепер коротше на здогад «а що таке `a`?».

## Хід 3 — винести змінну, щоб намір проступив

Придивись до гілки `day`: `line.kWh * 250` — це базова ціна, а `(line.kWh - 100) * 30` — надбавка за надлишок. Числа стоять голі, роль їхня в голові автора, не в коді. Винести змінну (Extract Variable) — дати підвиразу ім'я, не чіпаючи потоку керування:

```ts
  if (line.tariff === "day") {
    const base = line.kWh * 250;
    const surcharge = line.kWh > 100 ? (line.kWh - 100) * 30 : 0;
    result = base + surcharge;
  }
// (симетрично напрошується і в гілці business — той самий base + surcharge)
// тести: зелено
```

Тепер із коду видно **структуру** тарифу — «база плюс надбавка за надлишок», — а не лише арифметику. Ім'я `surcharge` пояснює, чому там оте `> 100`: це поріг, за яким вмикається надбавка. Один погляд замість розшифровування.

## Хід 4 — винести функцію `creditsFor`

Бонусні кіловати — окрема справа, що причепилася до петлі рахунку. Витягуємо її так само, як `amountFor`, але вона читає і рядок, і рахунок (чи активний, чи не бізнес), тож параметрів два:

```ts
function creditsFor(account: Account, line: Line): number {
  let credits = 0;
  if (account.active) {
    if (line.tariff !== "business") {
      credits += Math.max(line.kWh - 200, 0);
      if (line.tariff === "night") credits += Math.floor(line.kWh / 500);
    }
  }
  return credits;
}

// у statement:  vc += creditsFor(acc, line);
// тести: зелено
```

Функція вийшла, але всередині лишився той вкладений `if` усередині `if` — сходинка вправо, що ховає справжню роботу в найглибшому відступі. Це готує наступний хід.

## Хід 5 — охоронні речення замість вкладеного if

Перед тим як чіпати умову — переконайся, що обидві її **хибні** гілки під тестами. Золотий зразок ловить лише активного побутового клієнта (бонуси нараховуються); неактивний і бізнес — поза ним. Тож перед перебудовою докидаємо два дрібні тести, щоб сітка ловила саме те, що ми зараз рухаємо:

```ts
test("бонусів нема неактивному", () => {
  const off: Account = { customer: "X", active: false,
    lines: [{ meter: "M", tariff: "night", kWh: 900 }] };
  expect(statement(off)).toContain("Бонусні кіловати: 0");
});
test("бонусів нема бізнесу", () => {
  const biz: Account = { customer: "ТОВ", active: true,
    lines: [{ meter: "Піч", tariff: "business", kWh: 900 }] };
  expect(statement(biz)).toContain("Бонусні кіловати: 0");
});
// обидва — зелено (закріпили поведінку ДО перебудови умови)
```

Тепер перебудова. Вкладені `if` тут — ланцюг воріт: «активний І не бізнес — тоді рахуй». Кожні ворота обертаємо на **охоронне речення** (guard clause) — ранній вихід на хибі, — і глибокий відступ розпростується, а справжня робота лягає останньою, без відступу:

:::tabs
```ts
function creditsFor(account: Account, line: Line): number {
  if (!account.active) return 0;              // ворота 1 → ранній вихід
  if (line.tariff === "business") return 0;   // ворота 2 → ранній вихід
  let credits = Math.max(line.kWh - 200, 0);  // справжня робота — без відступу
  if (line.tariff === "night") credits += Math.floor(line.kWh / 500);
  return credits;
}
// тести: зелено (усі чотири)
```
```py
def credits_for(account: Account, line: Line) -> int:
    if not account.active:
        return 0                                   # ворота 1 → ранній вихід
    if line.tariff == "business":
        return 0                                   # ворота 2 → ранній вихід
    credits = max(line.kwh - 200, 0)               # справжня робота — без відступу
    if line.tariff == "night":
        credits += line.kwh // 500
    return credits
```
:::

Порівняй форму. Було: щоб дістатися до розрахунку, око спускалося двома вкладеннями вглиб, тримаючи в голові «ми всередині active, ми всередині не-business». Стало: два коротких «якщо ось це — то нуль» згори, а далі спокійний головний випадок. Охоронне речення каже «оце — виняток, обробили й вийшли», лишаючи тіло функції для того, заради чого вона є.

## Хід 6 — розділити цикл

Головна петля досі тягне **дві** незалежні суми: рахунок (`ta` + друк) і бонуси (`vc`). Одна петля — дві справи, і саме через це ні з рахунком, ні з бонусами не можна повестися окремо. Розділяємо цикл (Split Loop) — та сама послідовність рядків, але кожна петля робить **одне**:

```ts
  let ta = 0;
  let vc = 0;

  for (const line of acc.lines) {                 // петля 1: рахунок і друк
    const a = amountFor(line);
    out += `  ${line.meter}: ${line.kWh} кВт·год — ${(a / 100).toFixed(2)} грн\n`;
    ta += a;
  }
  for (const line of acc.lines) {                 // петля 2: лише бонуси
    vc += creditsFor(acc, line);
  }
// тести: зелено
```

Око одразу спотикається: «ми ж тепер ходимо списком двічі!» — і рука тягнеться відкотити. Стримайся. По-перше, на будь-якому реальному рахунку ця «зайва» петля непомітна, а передчасна оптимізація тут — золочення без потреби. По-друге, і головне: розділення — не самоціль, а **під'їзд**. Поки обидві суми росли в одній петлі, жодну не витягнеш окремо; тепер, коли кожна має власну петлю, кожна за один крок стає власним запитом. Якщо колись ці два проходи справді муляли б швидкодією, їх завжди можна злити назад — теж ходом, що зберігає поведінку. Форма слухняна в обидва боки.

## Хід 7 — замінити temp запитом

`ta` і `vc` — тимчасові (temp): значення, заморожене в одній точці й доступне лише тут. Кожне тепер обчислює власна петля, тож кожне перетворюємо на **запит** (Replace Temp with Query) — функцію, що рахує це на вимогу й кличеться звідусіль:

```ts
function totalAmount(account: Account): number {
  let total = 0;
  for (const line of account.lines) total += amountFor(line);
  return total;
}
function totalCredits(account: Account): number {
  let credits = 0;
  for (const line of account.lines) credits += creditsFor(account, line);
  return credits;
}
// тести: зелено
```

Чому це безпечно й чому взагалі варте ходу — в одному слові: запит **чистий**. Він читає стан і нічого не міняє, тож звати його можна будь-коли й скільки завгодно разів, і відповідь та сама — рівно та [властивість чистої функції](topic:sf-apps/pure-functions-side-effects), на якій тримається довіра до нього. Якби `totalCredits` попутно щось записував, замінити ним temp було б не можна: два виклики дали б різне. Саме тому хід п'ятий (охоронні речення) і четвертий (винесення) готували ґрунт — вони лишили `creditsFor` чистим.

Тепер `statement` скидає обидва temp і осідає до самого свого призначення — форматування:

:::tabs
```ts
function statement(acc: Account): string {
  let out = `Рахунок — ${acc.customer}\n`;
  for (const line of acc.lines) {
    out += `  ${line.meter}: ${line.kWh} кВт·год — ${(amountFor(line) / 100).toFixed(2)} грн\n`;
  }
  out += `Разом: ${(totalAmount(acc) / 100).toFixed(2)} грн\n`;
  out += `Бонусні кіловати: ${totalCredits(acc)}\n`;
  return out;
}
// тести: зелено
```
```py
def statement(acc: Account) -> str:
    out = f"Рахунок — {acc.customer}\n"
    for line in acc.lines:
        out += f"  {line.meter}: {line.kwh} кВт·год — {amount_for(line) / 100:.2f} грн\n"
    out += f"Разом: {total_amount(acc) / 100:.2f} грн\n"
    out += f"Бонусні кіловати: {total_credits(acc)}\n"
    return out
```
:::

Шість рядків замість двадцяти чотирьох. Зібгана петля розкладена на названі шматки: `amountFor` знає тарифи, `creditsFor` знає правила бонусів, `totalAmount`/`totalCredits` підсумовують, `statement` лише малює. Жоден крок не був хоробрим — хоробрість зайва, коли кожен рух дрібний і відкотний. І звідси видно головне: охайний кінець — **побічний** продукт. Що ми справді робили — тримали ритм «зелено → крихітна зміна → зелено», а форма впорядкувалася сама.

## Хід, що почервонів, — і трос у дії

Тепер жива демонстрація. Зелена смуга п'янить, і рука тягнеться «дочистити». `Math.max(line.kWh - 200, 0)` у `creditsFor` муляє — навіщо той `max`? «Та в нас усі споживають більше як 200, від'ємним воно не буває». Прибираємо — «спрощення»:

```ts
function creditsFor(account: Account, line: Line): number {
  if (!account.active) return 0;
  if (line.tariff === "business") return 0;
  let credits = line.kWh - 200;               // ← прибрали Math.max(..., 0)
  if (line.tariff === "night") credits += Math.floor(line.kWh / 500);
  return credits;
}
```

Прогін тестів — **червоно**:

```
✗ statement — золотий зразок

  Expected:  "…Бонусні кіловати: 120\n"
  Received:  "…Бонусні кіловати: -50\n"
```

Порахуймо, що сталося. Без `max` від'ємні доданки більше не зрізаються нулем:

```
Кухня  (day, 150):  150 − 200 = −50    (було 0)
Бойлер (night, 320): 320 − 200 = 120   (без змін, додатне)
Гараж  (day, 80):   80 − 200 = −120    (було 0)
Разом бонусів:  −50 + 120 − 120 = −50   (замість 120)
```

І ось де окуповується вся дисципліна. Тест почервонів **однозначно**: ми були в капелюсі рефакторингу, нічого не додавали — отже, останній крихітний крок зламав поведінку, і винен саме він, шукати нема де. А оскільки на кожному зеленому був коміт, [відкіт — одна команда](topic:sf-release/version-control): `git restore` цього файлу — і ми знову на зеленому, за кілька секунд, без розслідування.

Урок — рівно той, що в статті про два капелюхи. Прибрати `max` не було рефакторингом: воно **змінило видиму поведінку** (клієнти з обсягом менше 200 кВт·год почали діставати від'ємні бонуси). Це зміна поведінки, перевдягнена в рефакторинг, і тест упіймав її на першому ж прогоні. Якби ми справді хотіли нового правила бонусів — то окрема зміна, під іншим капелюхом, зі своїм тестом, що спершу червоний, потім зелений. А тут `max` виявився несучим, «спрощення» — просто хибним, і чесний хід — лишити код таким, яким його зробив хід сьомий.

> 🔧 **Навіщо це.** Червоний тест тут — не прикра завада, а сам трос, що смикнув. Він відповів на єдине питання, яке має значення посеред рефакторингу: «я щось зламав?» — миттєво, точно вказавши на останній крок. Без цієї відповіді «спрощення» поїхало б у прод, і від'ємні бонуси спливли б не тут, а через місяць у чужому рахунку. Уся вартість дрібного кроку в тому, що відстань від помилки до сигналу — один прогін, а відстань від сигналу до чистого стану — одна команда відкату.

## Складність і пастки

**Збити ходи в купу — втратити однозначність.** Найбільша спокуса — зробити винесення, перейменування й охоронні речення одним махом і закомітити разом. Поки все зелено, наче й дарма морочитись дрібними кроками. Але щойно наприкінці спалахне червоне — сигнал стає **двозначним**: котрий із трьох ходів зламав? Ти вертаєшся до того самого розслідування в копиці, від якого дрібний крок і рятує. Один хід — один прогін — один коміт тримає кожне червоне з єдиним підозрюваним. Дисципліна не в тому, щоб ходи були маленькі заради естетики, а в тому, щоб **відстань до винуватця** завжди лишалася нульовою.

**«Дружнє спрощення», що тихо змінює поведінку.** Історія з `max` — не випадковість, а ціла родина помилок: `saveOrder()`, який заразом «підправив» валідацію; перейменування, що «до купи» виправило дрібний баг; зрізаний `Math.floor`, бо «однаково ціле». Перевірка одна й гостра: **рефакторинг ніколи не міняє жодного виходу**. Якщо після «причісування» бодай один тест мусив змінити очікуване значення — це була не перестановка форми, а зміна поведінки, і їй місце в окремому коміті зі своїм тестом. Тест каже правду; коли він червоніє на «косметиці» — червоніє насправді про підмінений капелюх.

**Рефакторинг без сітки — це не хоробрість, а азарт.** Прибери золотий зразок — і червоний хід сьомий-з-половиною доїхав би до прода нечутно: від'ємні бонуси, тиха поломка, скарга через місяць. Тут і видно, чому [надійна сітка](topic:sf-apps/testability-tactics) — передумова, а не оздоба: трос тримає рівно настільки, наскільки міцний шар, на якому висить. Над ділянкою без тестів рефакторити наосліп не можна — спершу накидаєш [характеризаційну сітку](root:progarch/characterization-tests) поверх наявної поведінки, і аж тоді чіпаєш форму.

**Страх «зайвого проходу» вбиває хід шостий.** Розділений цикл лякає видимою марнотратністю — «ми ж ходимо двічі!» — і його кортить пропустити. Але поки дві суми ростуть в одній петлі, жодну не витягнеш запитом; розділення — не витрата, а сходинка, без якої немає ходу сьомого. А якщо ті два проходи колись справді муляли б швидкодією, їх злиття назад — теж хід зі збереженням поведінки, під сіткою. Не жертвуй зрозумілістю передчасній оптимізації там, де вимірювання ще нічого не сказало.

**Золочення того, чого ніхто не чіпатиме.** Останнє: увесь цей ланцюг вартий заходу, лише коли `statement` **треба міняти** — додати тариф, новий формат, іншу знижку. Причісувати функцію в мертвому кутку, куди роками ніхто не зазирне, — змарнований час: краси додав, ризик і години витратив, користі нуль. Рефакторинг — слуга зміни, а не самоціль: спершу зроби зміну легкою (оцим ланцюгом ходів), тоді зроби легку зміну. Немає зміни на обрії — немає й приводу для ланцюга.
