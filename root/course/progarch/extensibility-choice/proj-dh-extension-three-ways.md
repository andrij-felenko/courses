# ⚙️ Одна дія DH трьома моделями — правилом, плагіном, вебхуком

Драбину ми накреслили в загальному: конфіг дає дані, правило — логіку обмеженим словником, плагін — код у твоєму процесі, «поза процесом» — код за стіною. Драбина показує напрямки — а ціну на дотик дає лише код, що лягає на диск і запускається. Тож візьмімо **одну-єдину** дію Digital Homes і зберімо її **тричі**: декларативним правилом, плагіном у процесі, вихідним вебхуком. Та сама потреба щоразу — а ми поміряємо на кожній три речі: **радіус ураження** (що буде, коли розширення зависне, кине виняток або виявиться зловмисним), **затримку на гарячому шляху** (наносекунди прямого виклику проти мілісекунд мережевого оберту) і **хто коли деплоїть** (дані миттєво, з ядром чи за графіком постачальника).

Одразу пуант, щоб тримати його весь розбір: код усіх трьох майже однаковий за обсягом, а ось рахунок за нього різниться не на відсотки, а на **порядки** — і саме число робить драбину, яку ми малювали на словах, беззаперечною.

## Задача — одна дія, зафіксована точно

Візьмімо нестандартну реакцію, якої в DH нема з коробки: **коли давач руху в коридорі спрацьовує вночі, а дім у режимі «нікого немає» — блимнути світлом у коридорі тричі й штовхнути власнику сповіщення на телефон.** «Нічний вартовий»: не вбудована поведінка, а саме той різновид прохання, під яке й потрібна розширюваність.

Щоб порівняння було чесним, прибиваємо цвяхами все, крім самої моделі. Тригер **один** — подія руху, і вона тече **гарячим шляхом**: давачі в домі стріляють десятки разів за хвилину, і кожен постріл проходить через ту саму точку. Ефект **один** — блимнути й сповістити. Скелет хаба **один**: подія й невеликий контекст із рівно тими можливостями, які дія сміє чіпати.

```ts
type MotionEvent = {
  sensor: string;   // "hallway-pir"
  room: string;     // "коридор"
  at: number;       // Unix-час, мілісекунди
};

// контекст — вузька поверхня: лише те, що дія має право робити
interface HubContext {
  home: { mode: "home" | "away" | "night" };
  light: { blink(room: string, times: number): void };
  notify: { push(text: string): void };
}
```

Хаб — на Node/TypeScript, тож і плагін, і рушій правил, і відправник вебхука живуть тією самою мовою. Це не дрібниця: якби правило я написав на Python, плагін на C++, а вебхук на Go, то й не розібрав би, звідки взялася різниця — від моделі чи від мови. Прибиваємо мову — тоді все, що побачимо, належить **моделі** й нічому більше. Міняється лише одне: **де** біжить логіка дії і **чим** стримано її силу.

![Три горизонтальні доріжки з однієї події руху ліворуч. Верхня — обмежений рушій (обхід дерева + пальне), стримано межею словника, радіус: тільки твої дієслова. Середня — плагін у процесі хаба, нічим не стримано, радіус: весь хаб (зависання, виняток, крадіжка токена). Нижня — хаб штовхає подію чужому адаптеру крізь стіну, стримано таймаутом та ізоляцією, радіус: за стіною, чужий збій дорівнює твоєму таймауту.](img/action-three-lanes.svg)

*Та сама подія руху годує всі три доріжки — різне лише те, де біжить логіка й чим стримано її силу. Плагін не стримано нічим, тож його біда розходиться по всьому хабу; правило тримає словник, вебхук — стіна.*

## Модель перша — декларативне правило в обмеженому рушії

Користувач пише свою дію як **дані**, а не як код:

```yaml
when: motion.detected
if:   time.hour < 6 and home.mode == "away"
then:
  - light.blink: { room: "коридор", times: 3 }
  - notify.push: { text: "Рух у коридорі, коли нікого немає" }
```

Це не програма — це запис у структурі, яку хаб читає й виконує сам. Уся сила й уся безпека тут — у тому, що рушій розуміє лише **скінченний словник** дієслів. Умову хаб тримає розібраним деревцем, а виконує його **власним обходом**, і ось у цьому обході — головний трюк:

```ts
type Cond =
  | { op: "and" | "or"; l: Cond; r: Cond }
  | { op: "==" | "<";   l: Cond; r: Cond }
  | { op: "var"; name: string }        // "time.hour", "home.mode"
  | { op: "lit"; value: string | number };

class FuelOut extends Error {}

function evalCond(n: Cond, env: Record<string, unknown>, fuel: { left: number }): unknown {
  if (--fuel.left <= 0) throw new FuelOut();   // КОЖЕН вузол коштує одиницю пального
  switch (n.op) {
    case "lit": return n.value;
    case "var": return env[n.name];
    case "and": return evalCond(n.l, env, fuel) && evalCond(n.r, env, fuel);
    case "or":  return evalCond(n.l, env, fuel) || evalCond(n.r, env, fuel);
    case "==":  return evalCond(n.l, env, fuel) === evalCond(n.r, env, fuel);
    case "<":   return (evalCond(n.l, env, fuel) as number) < (evalCond(n.r, env, fuel) as number);
  }
}
```

Той рядок `if (--fuel.left <= 0) throw` — і є **обмежене обчислення**. На кожен тригер рушій наливає правилу фіксовану порцію **пального** (скажімо, 10 000 одиниць), і кожен обчислений вузол дерева спалює одну. Скінчилося пальне — обчислення обривається, крапка. Це та сама ідея, що «пальне» (англ. *gas*) в обмежених віртуальних машинах чи лічильник інструкцій у пісочниці мови сценаріїв: ти не довіряєш чужій логіці не витрачати твій час — ти **міряєш** її витрату й уриваєш, коли вона переступила стелю.

Тепер драйвер, що зводить усе докупи — закритий словник дій, ізоляція збою й межа каскаду:

```ts
// СЛОВНИК дій — закритий. Чого тут нема, того правило висловити НЕ МОЖЕ
const ACTIONS: Record<string, (args: any, ctx: HubContext) => void> = {
  "light.blink": (a, ctx) => ctx.light.blink(a.room, a.times),
  "notify.push": (a, ctx) => ctx.notify.push(a.text),
};

const MAX_CASCADE = 4;

function runRule(rule: Rule, ev: MotionEvent, ctx: HubContext, depth = 0): void {
  if (depth > MAX_CASCADE) { log.warn("каскад правил задовгий — обрив"); return; }
  const env = {
    "time.hour":  new Date(ev.at).getHours(),
    "home.mode":  ctx.home.mode,
    "event.room": ev.room,
  };
  const fuel = { left: 10_000 };                 // стеля обчислення на один тригер
  let pass = false;
  try {
    pass = Boolean(evalCond(rule.cond, env, fuel));
  } catch (e) {
    if (e instanceof FuelOut) { log.warn("правило обірвано: скінчилося пальне"); return; }
    log.warn("умова правила кинула виняток", e); return;   // навіть кривий вузол не валить хаб
  }
  if (!pass) return;
  for (const step of rule.then) {
    const run = ACTIONS[step.action];
    if (!run) continue;                          // невідоме дієслово — тихо ігноруємо
    try { run(step.args, ctx); }
    catch (e) { log.warn(`дія ${step.action} впала`, e); }  // один крок упав — решта живе
  }
}
```

Придивімося, **чому** таке правило безпечно виконувати мільйони разів від незнайомих людей — і чому воно не може зациклитися. Тут працюють два різні замки. Перший — **сам словник**: у мові нема дієслова «повторюй» чи «крутись, доки», тож окреме правило й не має чим висловити нескінченний цикл; його умова — скінченне дерево, обхід якого завершується вже за побудовою. Але цей замок стереже лише поодиноке правило. Справжній цикл ховається деінде — у **каскаді**: правило A блимає світлом, блимання породжує подію, подія будить правило B, а те знову смикає A. Ось де народжується вічна петля, якої в жодному окремому правилі не видно. Її ловить `MAX_CASCADE` — межа глибини, за якою ланцюг обривають. А пальне лишається **третім** замком, найширшим: воно кладе стелю на **вартість** одного тригера незалежно від того, звідки взялася робота — з монструозно глибокої умови, з майбутнього дієслова, яке ти колись додаси й недооціниш, чи з того самого каскаду. Словник забороняє петлю **на письмі**, каскадна межа рве її **між правилами**, а пальне страхує від усього, що ці двоє проґавлять. Разом вони роблять «чужа логіка на гарячому шляху» безпечним **за побудовою**, а не за обіцянкою автора поводитися чемно.

> 🔧 **Навіщо це.** Метроване виконання — не академічна прикраса, а те, чим реальні платформи автоматизації відрізняють «користувач написав погане правило» від «користувач поклав хаб». Без пального одне неоковирне правило (глибоко вкладена умова, ненавмисний каскад) з'їдає гарячий шлях, і разом з ним застигають усі давачі в домі — рівно та аварія, від якої розширюваність мала б захистити. Стеля на вартість тригера коштує один `if` на вузол; її відсутність коштує нічного дзвінка з бойового дому.

**Радіус ураження.** Найгірше, що може зробити правило, — це **легальна, але дратівлива** комбінація твоїх дієслів: блимнути світлом серед ночі, надіслати зайве сповіщення. Воно фізично не може прочитати токен хаба, відкрити файл чи закрутити процесор — таких слів у мові просто нема, а спробу з'їсти час уриває пальне. Безпека тут не з перевірок і не з довіри — вона з **межі виразності**.

**Затримка.** Обхід дерева — це інтерпретація, і вона повільніша за прямий машинний виклик: десятки-сотні вузлів по кілька наносекунд кожен — разом мікросекунди. Дорожче за плагін, але це все ще **локально**: жодного системного виклику, жодної мережі.

**Деплой.** Правило — це рядок даних. Користувач зберігає його — і воно живе **тієї ж миті**. Ніякого перезбирання хаба, ніякого релізу, ніякого оновлення прошивки в домах. Дані розгортаються миттєво, бо це не код.

## Модель друга — плагін у процесі

Тепер протилежний кут: та сама дія, але **справжнім кодом** у процесі хаба. Розширення реалізує інтерфейс дії й біжить прямим викликом на кожному русі:

```ts
interface ActionPlugin {
  readonly kind: string;
  onMotion(ev: MotionEvent, ctx: HubContext): void;   // біжить У процесі хаба, на гарячому шляху
}

class NightWatchPlugin implements ActionPlugin {
  readonly kind = "night-watch";
  onMotion(ev: MotionEvent, ctx: HubContext): void {
    const hour = new Date(ev.at).getHours();
    if (hour < 6 && ctx.home.mode === "away") {
      ctx.light.blink(ev.room, 3);
      ctx.notify.push(`Рух у ${ev.room}, коли нікого немає`);
    }
  }
}
```

Хаб на гарячому шляху кличе плагін **прямо** — жодного посередника, жодної інтерпретації:

```ts
for (const p of plugins) {
  try { p.onMotion(ev, ctx); }
  catch (e) { log.error(`плагін ${p.kind} кинув виняток`, e); }   // виняток ловимо…
}
```

Обгортка `try/catch` виглядає так, ніби вона все стримує. Не все. Ось ті самі три біди, якими чужий код у твоєму процесі ділиться з тобою:

```ts
onMotion(ev, ctx) {
  while (true) {}                                   // ЗАВИСАННЯ: подієвий цикл Node став — хаб мертвий
  throw new Error("boom");                          // ВИНЯТОК: без обгортки забирає обробник події
  const t = fs.readFileSync("/etc/dh/hub.token");   // КРАДІЖКА: ті самі права, що й у хаба
}
```

Ось найгостріший, найтихіший урок цієї моделі. `try/catch` навколо виклику справді ловить `throw` — виняток не пробиває обробник далі. Але з `while (true)` він **не може вдіяти нічого**: синхронний нескінченний цикл у JavaScript не переривається зсередини, а Node — однопотоковий, тож поки той цикл крутиться, **жоден** інший давач не опитується, жоден таймер не спрацьовує, жоден вебхук не відправляється. Хаб не «повільний» — він **мертвий**, і весь дім застиг. І що найважливіше: **таймаут у процесі тебе не рятує**. Немає способу поставити будильник, який перерве гарячий цикл на тому самому потоці, — будильник теж стоїть у черзі за ним. Урвати чужий код можна лише винісши його на **інший** потік (worker) або за **стіну** процесу. Ось звідки росте модель третя: не з любові до мережі, а з того, що всередині одного потоку зависання нічим не спинити.

**Радіус ураження.** Весь хаб. Зависання кладе дім, необроблений виняток може забрати процес, а `readFileSync` дістає токен хаба до хмари — бо в чужого коду поруч із твоїм рівно ті самі права, що й у тебе. Стримати вже нічим — саме тому такий плагін пишуть **свої** або ретельно перевірені, а не хто завгодно.

**Затримка.** Найменша з трьох. Прямий виклик методу в V8 — це одиниці-десятки наносекунд накладних (поряд із захопленням м'ютекса чи зверненням до пам'яті), а далі вже тіло дії робить свою роботу. Швидше не буває: ти платиш рівно за корисну роботу й майже нічого — за диспетчеризацію.

**Деплой.** Плагін вкомпільований у хаб. Щоб змінити дію, ти перезбираєш і випускаєш **нову версію хаба**, і вона доходить до домів тоді, коли вони оновляться — на **твоєму** релізному потязі. Виправлення їде з ядром, а не окремо.

## Модель третя — вихідний вебхук

Третій шлях виносить код дії **за стіну**: хаб на подію руху штовхає HTTP-запит зовнішньому сервісу — адаптеру «нічного вартового» від стороннього бренду, — а вже той вирішує й діє на своєму боці. Уся тонкість збирається у **відправнику**: він мусить пережити мертвого одержувача, не зависнувши на ньому, і не дати одному трупу застопорити розсилку решті.

:::tabs
```ts
type Subscriber = { url: string; secret: string };

async function postWithTimeout(url: string, body: unknown, ms: number): Promise<void> {
  const ctl = new AbortController();
  const timer = setTimeout(() => ctl.abort(), ms);    // мертвий одержувач не висить вічно
  try {
    const res = await fetch(url, {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify(body),
      signal: ctl.signal,
    });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
  } finally {
    clearTimeout(timer);
  }
}

async function dispatch(subs: Subscriber[], ev: MotionEvent): Promise<void> {
  // назовні йде ЛИШЕ те, що ми свідомо поклали — ні токена, ні нутрощів
  const payload = { type: "motion.detected", room: ev.room, at: ev.at };
  const results = await Promise.allSettled(
    subs.map((s) => postWithTimeout(s.url, payload, 800)),
  );
  results.forEach((r, i) => {
    if (r.status === "rejected")
      log.warn(`вебхук ${subs[i].url} впав:`, r.reason);   // один мертвий — решта доставлена
  });
}
```
```go
type Subscriber struct{ URL, Secret string }

func dispatch(subs []Subscriber, ev MotionEvent) {
    payload, _ := json.Marshal(map[string]any{             // лише свідомо обраний вміст
        "type": "motion.detected", "room": ev.Room, "at": ev.At,
    })
    var wg sync.WaitGroup
    for _, s := range subs {
        wg.Add(1)
        go func(s Subscriber) {                            // кожен одержувач — окрема горутина
            defer wg.Done()
            ctx, cancel := context.WithTimeout(context.Background(), 800*time.Millisecond)
            defer cancel()
            req, _ := http.NewRequestWithContext(ctx, "POST", s.URL, bytes.NewReader(payload))
            req.Header.Set("content-type", "application/json")
            res, err := http.DefaultClient.Do(req)
            if err != nil {                                // таймаут чи мертвий вузол — падає ЛИШЕ цей
                log.Printf("вебхук %s впав: %v", s.URL, err)
                return
            }
            res.Body.Close()
        }(s)
    }
    wg.Wait()                                              // збій одного не чіпає інших
}
```
:::

Дві мови — той самий задум, показаний двома ідіомами ізоляції. У TypeScript стіну тримають `AbortController` (свій таймаут на кожен запит) і `Promise.allSettled` — він чекає на **всі** запити, але кожен розв'язується **окремо**: мертвий одержувач відпадає власним таймаутом, не торкнувшись сусідів. Це ключова відмінність від `Promise.all`, який завалив би **всю** пачку на першій же відмові. У Go ту саму ізоляцію дає горутина-на-одержувача з `context.WithTimeout`: кожен постріл несе свій дедлайн, а `WaitGroup` збирає всіх у кінці — падіння одного лишається в його горутині. Обидва кажуть одне: **таймаут на кожного плюс збій кожного окремо** — ось що не дає одному трупу заморозити фан-аут.

І ще один хід, без якого вебхук отруїв би гарячий шлях: розсилка йде **поза** ним. Гарячий шлях лише кладе подію в чергу й вертається за наносекунди; окремий насос спорожняє чергу у своєму темпі, і мілісекунди мережі вже нікого не блокують.

```ts
// гарячий шлях НЕ чекає на мережу — кладе подію й вертається (~наносекунди)
function onMotion(ev: MotionEvent) { outbox.push(ev); }

// окремий насос розсилає у своєму темпі, поза гарячим шляхом
setInterval(() => { const ev = outbox.shift(); if (ev) dispatch(subscribers, ev); }, 0);
```

> 🔧 **Навіщо це.** «Мертвий одержувач не стопорить решту» — це не дрібна оптимізація, а різниця між ізольованим збоєм і каскадним. Один завислий партнерський сервіс без таймаута й ізоляції затягує в себе потік розсилки, черга подій росте, пам'ять пухне — і чужий труп валить твій фан-аут цілком. `allSettled` замість `all`, таймаут на кожен запит, розсилка поза гарячим шляхом — три рядки, що перетворюють «його аварія = моя аварія» на «його аварія = мій рядок у лог».

**Радіус ураження.** Замкнений по той бік стіни. Зависання одержувача обертається **твоїм таймаутом** — 800 мс, і ти пішов далі. Його падіння лишається в його коробці. А зловмисність? Він бачить **лише той вміст, який ти свідомо поклав** у payload — `{type, room, at}`, — ні токена, ні пам'яті, ні файлів хаба. Це і є [найменші привілеї на практиці — дати рівно стільки, скільки треба на роботу, і ні краплі більше](topic:programming/least-privilege): за стіною чужий код дістає не «все, що має хаб», а рівно три поля, які ти йому надіслав.

**Затримка.** Мережевий оберт — від ~0.5 мс у тій самій мережі до ~150 мс через океан, тобто в десятки тисяч разів більше за прямий виклик. Але — і це головне — вона **поза гарячим шляхом**: це «час до реакції», а не «час, поки хаб застиг». На гарячому шляху ти платиш лише наносекунди за `outbox.push`.

**Деплой.** Адаптер живе в коробці постачальника. Він випускає оновлення **за власним графіком** — ти не міняєш нічого, не перезбираєш хаб, навіть не знаєш про його реліз. Ціна цієї свободи — контракт вебхука, який замерз тієї миті, коли перший партнер на нього сперся.

Дві пастки, що приходять зі стіною, варто назвати відразу. Таймаут означає **повторні спроби**, а повтор означає, що та сама подія руху може прилетіти одержувачу **двічі**; тому доставку роблять «щонайменше раз», а одержувача змушують бути [ідемпотентним — щоб повтор тієї самої події не наробив подвійної роботи](topic:programming/idempotency). І якщо одержувач мертвий не мить, а годину, безглуздо гатити в нього кожну подію лише щоб зібрати таймаут; тут ставлять [запобіжник, що після низки поспіль відмов перестає стукати в мертвий вузол і пропускає його, доки той не ожив](topic:programming/circuit-breaker-pattern).

## Три рахунки поруч — ось де драбина стає числом

Спинімося й покладімо три виміри поряд, бо саме контраст — уся сіль кроку. Почнімо із затримки, бо вона найяскравіша. Опертися є на що: канонічний список «затримок, які має знати кожен програміст» (його зібрав Джефф Дін на давнішій таблиці Пітера Норвіга; статус — усталені інженерні орієнтири на порядок величини, не замір конкретної машини) дає звернення до пам'яті ≈ 100 нс, захоплення м'ютекса ≈ 25 нс, оберт у тому самому центрі даних ≈ 0.5 мс, а пакет Каліфорнія → Нідерланди → Каліфорнія ≈ 150 мс. Прикладімо це до наших трьох моделей:

```
Плагін у процесі  — прямий виклик         ~50 нс            × 1          (на гарячому шляху)
Правило в рушії   — обхід дерева + пальне  ~5 000 нс         × ~100       (на гарячому шляху)
Вебхук, та сама мережа — оберт по LAN      ~500 000 нс       × ~10 000    (поза гарячим шляхом)
Вебхук, інший континент — оберт крізь світ  ~150 000 000 нс   × ~3 000 000  (поза гарячим шляхом)
```

Від прямого виклику до заокеанського оберту — приблизно **шість-сім порядків**. Але число саме по собі бреше, якщо не сказати, **де** його сплачують: наносекунди плагіна й мікросекунди правила — це час, поки гарячий шлях **застиг** і чекає; мілісекунди вебхука — час до реакції **осторонь**, поки хаб уже побіг далі. Тому правильне питання не «що швидше», а «що блокує гарячий шлях»: правило й плагін блокують (і мусять бути дешеві), вебхук — ні (і тому може дозволити собі мережу).

![Логарифмічна лінійка затримок від однієї наносекунди до секунди з позначками на кожній декаді. Чотири маркери: плагін у процесі — прямий виклик, близько 50 наносекунд; правило в рушії — обхід дерева, близько 5 мікросекунд; вебхук у тій самій мережі, близько 0.5 мілісекунди; вебхук на інший континент, близько 150 мілісекунд. Дужка над крайніми маркерами підписана «приблизно 6–7 порядків різниці».](img/hotpath-latency-scale.svg)

*На логарифмічній шкалі провалля видно тілом: між прямим викликом і мережевим обертом лежать шість-сім порядків. Плагін і правило платять час на гарячому шляху, вебхук — осторонь нього.*

Радіус ураження йде **не** слідом за швидкістю, і в цьому вся мораль. Найшвидша модель — плагін — має **найширший** радіус: її зависання, виняток чи крадіжка розходяться по всьому хабу, бо силу не стримано нічим, крім довіри. Найповільніша — вебхук — має **найвужчий** радіус із «повного коду»: чужа біда впирається в стіну, а зловмисність бачить лише три поля payload. А правило, дешеве й локальне, тримає радіус **межею словника**: гіршого за легальну комбінацію твоїх дієслів воно не висловить. Швидкість купуєш близькістю до ядра, а безпеку — стримуванням; і ці дві валюти течуть **у різні боки**.

І третій вимір — деплой — розводить моделі ще однією віссю. Правило — дані, тож воно живе **миттєво**, без релізу. Плагін їде **з ядром**, на твоєму релізному потязі. Вебхук деплоїть **чужий**, за графіком, якого ти не контролюєш. Та сама потреба — а «коли зміна доходить до дому» відрізняється від секунд до тижнів.

## Складність і пастки

Три моделі — три різні набори граблів, і кожні ростуть із того самого кореня, що й перевага.

**Правило: словник тисне на виразність.** Уся безпека тримається на тому, що словник **закритий** — а отже, чого в ньому нема, того користувач і не висловить. Настане день, коли комусь забракне саме того дієслова, якого ти не поклав, і спокуса «додати ще одне слово в мову» тягтиме розширювати словник, аж поки він тихо не перетвориться на повноцінну мову програмування з усіма її небезпеками. Друга грабля — **пальне як число**: постав стелю занизько — і чесні складні правила обриваються серед білого дня; зависоко — і захист провисає. І третя, найтихіша: кожне нове дієслово, яке ти додав, **замерзає** назавжди, щойно перший користувач на нього сперся, — вузький словник тому не лише безпечніший, а й дешевший в утриманні роками.

**Плагін: близькість, за яку платиш усім хабом.** Найгостріше ми вже бачили — синхронне зависання, якого не спинити таймаутом у процесі. Поряд ідуть сусіди: витік пам'яті в плагіні стає витоком хаба; повільний плагін на гарячому шляху крадькома підвищує затримку **кожного** показання в домі; а `try/catch` присипляє пильність, бо ловить винятки й тим створює ілюзію, ніби він ловить і зависання. Плагін пишуть свої не тому, що чужі гірші програмісти, а тому, що всередині одного процесу **немає** механізму стримати чужу біду — лишається тільки довіряти.

**Вебхук: стіна коштує частковою відмовою.** Мережа приносить свій оброк, і його легко недооцінити. Доставка «щонайменше раз» вимагає ідемпотентного одержувача — інакше повтор після таймаута зробить дію двічі (дві нічні тривоги замість однієї). Мертвий партнер без запобіжника перетворює кожну подію на 800 мс марного чекання. А `Promise.all` замість `allSettled` — однорядкова помилка, що повертає тобі рівно ту каскадну відмову, від якої стіна мала б захистити. Стіна ловить чужу аварію — але тільки якщо відправник написаний так, наче по той бік стіни **завжди** хтось мертвий.

## Потреба → модель → рахунок

Складімо все в одну таблицю — не «яка модель найкраща», а **під яку потребу який рахунок**:

| Потреба (хто пише × скільки влади) | Модель | Радіус ураження | Затримка на гарячому шляху | Хто коли деплоїть |
|---|---|---|---|---|
| Незнайомий користувач, композиція примітивів | **Декларативне правило** | Межа словника — не спинить хаб, не вкраде токен | ~мкс, локально (блокує) | Дані — **миттєво**, без релізу |
| Наш код, повна влада, кожне показання | **Плагін у процесі** | **Весь хаб**: зависання · виняток · крадіжка | ~нс, найшвидше (блокує) | **З ядром** — на нашому релізі |
| Чужий напівдовірений бренд, справжній код | **Вихідний вебхук** | За стіною: чужий збій = твій таймаут; видно лише payload | ~мс, але **поза** гарячим шляхом | За **графіком постачальника** |

Ось де пуант, з якого ми починали, лягає в руки доказом. Дія була **одна** — нічний вартовий, блимнути й сповістити, — а рахунок за неї виявився не однаковий і навіть не схожий: радіус ураження стрибає від «межі словника» до «всього хаба», затримка — на шість порядків, а мить, коли зміна доходить до дому, — від секунд до тижнів. Драбину розширюваності не видно, поки говориш про неї словами; вона проступає тілом, щойно та сама потреба, зібрана трьома моделями, виставляє тобі три геть різні рахунки. І вибирати щабель означає читати саме цей рахунок — не «яку технологію ми любимо», а «кому ми віримо, скільки виразності треба і чию аварію готові оплатити».
