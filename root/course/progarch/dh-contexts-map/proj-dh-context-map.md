# ⚙️ Уся мапа DH в одному файлі: ворота, картинка й легенда з тих самих даних

Ми домовилися, що довідник не сміє брехати з часом, і назвали ліки: тримати мапу не картинкою, а **виконуваним артефактом**. Загальний механізм цього вже розкладено до кісток окремо — [карта контекстів як код](book:programming/context-mapping/proj-context-map-as-code.md): три множини (контексти, оголошені ребра, знайдені в коді ребра), одне порівняння `знайдені − оголошені`, ненульовий код виходу на різниці. Те, що треба знати перед цим кроком: перевірка сканує реальні `import`-и, зводить їх у граф ребер «звідки → куди» і валить збірку, щойно в коді проступила стрілка, якої нема в оголошенні. Механізм там; **тут — сам артефакт Digital Homes**.

І DH піднімає планку цілком конкретно. У навчальному прикладі загальної статті — чотири іграшкові контексти й одна заборона «назад». У нас — **дев'ять справжніх світів плюс дві спільні вершини** (шина подій і ядро ідентифікаторів), **сім різних видів зв'язку**, двобічне партнерство хаб-твін, опублікована мова замість прямих ребер, свідомо відрізане відео й крихітне спільне ядро. Записати все це чесно — то вже пів роботи. Але справжня причина винести артефакт окремо інша: ми хочемо, щоб **та сама структура даних** одночасно (1) стерегла збірку, (2) **малювала** картинку з попереднього кроку й (3) **друкувала** ту таблицю-довідник. Одне джерело — троє споживачів. Тоді розійтися не може вже не одна пара «код ↔ схема», а весь трикутник: ворота, картинка й легенда народжені з одного файлу й рухаються разом.

> 🔧 **Навіщо це.** Малюнок і таблицю в попередньому кроці ми накреслили руками — і рівно тому вони почнуть старіти першого ж місяця. Зробити їх **виходом** однієї структури — значить купити неможливість не однієї брехні, а двох одразу: «цієї стрілки нема на мапі» **і** «картинка не збігається з правилами». Обидві фізично не трапляються, коли картинку ніхто не малює руками, а генерує машина з того самого джерела, що й ворота.

*Один файл-мапа, з якого машина читає тричі: як ворота (валить заборонене ребро), як картинку (та сама схема) і як легенду (той самий довідник рядками). Зміниш ребро в даних — зрушаться всі троє; жодному нема куди розійтися.*

## Уся мапа — одна структура даних

Почнімо з джерела. Ось повна мапа DH як дані — виконуваний двійник тієї таблиці, яку ми читали рядками. Кожен контекст знає свій **корінь у коді** й, головне, свою `published` — єдину поверхню, яку йому дозволено показувати назовні. Домені ребра (партнерство, замовник-постачальник) стоять у `allow`; універсальні вершини, що їх сміють читати всі (ідентичність, шина подій, ядро ідентифікаторів), позначені `open`, а свій вид зв'язку носять поруч.

:::tabs
```ts
// map.ts — ЄДИНЕ джерело правди про межі DH. З нього живуть і ворота, і картинка, і легенда.
type Kind =
  | "partnership"         // рівні, релізяться разом (двобічне)
  | "customer-supplier"   // верховий диктує модель, низовий має голос
  | "conformist"          // приймаємо чужу мову як є
  | "published-language"  // нейтральна подія у спільній шині
  | "shared-kernel"       // крихітне спільне ядро
  | "separate-ways"       // свідомо без стику
  | "acl";                // антикорупційний шар до чужого (за межами репо)

interface Context {
  root: string;                    // де контекст живе у файловій системі
  pub: string;                     // ЄДИНА поверхня, видима іншим контекстам
  allow: Record<string, Kind>;     // кого цей контекст сміє ІМПОРТУВАТИ (доменні ребра)
  open?: boolean;                  // його pub сміють читати ВСІ (ідентичність, шина, ядро)
  kind?: Kind;                     // вид зв'язку для open-вершини
  isolated?: boolean;              // окремі шляхи: у нього не сміє входити НІХТО
}

// Увага: allow — це напрямок ІМПОРТУ (хто кого тягне), а НЕ напрямок течії з таблиці.
// Замовник (низовий) імпортує постачальника (верхового) — тож ребро в даних
// протилежне стрілці на картинці. Про цю пастку — окремо наприкінці.
export const MAP: Record<string, Context> = {
  hub:           { root: "src/hub",           pub: "src/hub/published",
                   allow: { twin: "partnership" } },
  twin:          { root: "src/twin",          pub: "src/twin/published",
                   allow: { hub: "partnership", control: "customer-supplier" } },
  control:       { root: "src/control",       pub: "src/control/published",
                   allow: {} },                       // ядро моделі: імпортує НІКОГО, лише публікує
  automations:   { root: "src/automations",   pub: "src/automations/published",
                   allow: { twin: "customer-supplier" } },
  billing:       { root: "src/billing",       pub: "src/billing/published",
                   allow: { control: "customer-supplier" } },   // споживає published control, не домен
  telemetry:     { root: "src/telemetry",     pub: "src/telemetry/published",
                   allow: {} },                       // годується лише з шини подій (open нижче)
  notifications: { root: "src/notifications", pub: "src/notifications/published",
                   allow: {} },
  video:         { root: "src/video",         pub: "src/video/published",
                   allow: {}, isolated: true },       // окремі шляхи: тільки ідентичність
  identity:      { root: "src/identity",      pub: "src/identity/published",
                   allow: {}, open: true, kind: "conformist" },
  events:        { root: "src/events",        pub: "src/events",            // уся шина — опубл. мова
                   allow: {}, open: true, kind: "published-language" },
  ids:           { root: "src/shared/ids",    pub: "src/shared/ids",        // усе ядро — самі типи
                   allow: {}, open: true, kind: "shared-kernel" },
};
```

Придивись, що ця структура кодує з попереднього кроку без жодного слова прози. Партнерство хаб-твін — симетричне: обидва тримають одне одного в `allow`, бо петлю синхронізації міняють разом. `control` імпортує **нікого**: ядро дому лише диктує модель і публікує факти, а само не залежить від периферії — це видно рядком `allow: {}`. Відео позначене `isolated`: у нього не сміє входити ніхто, крім спільних вершин. А ідентичність, шина й ядро — `open` для всіх, кожна зі своїм видом зв'язку. Це не документація про мапу; це **сама мапа**, яку далі читатиме машина.

Але тут DH вимагає тонкості, якої в іграшковому прикладі не було, — і саме вона робить наскрізний приклад цікавим. Замало сказати «білінгу можна знати про керування». Бо `control→billing` — це замовник-постачальник, і білінг **справді** має право споживати факти керування. Питання не в тім, **чи** можна перетнути межу, а **куди саме** ти в неї заходиш. Кожен контекст показує світу лише свою `published`-поверхню — нейтральні факти, події, порти — і ховає `domain` з живими агрегатами, [багатою моделлю `Lock` та інваріантами](root:progarch/dh-data-model). Дозволене ребро пускає тебе **лише в `published`** сусіда й ніколи — у його нутрощі. Тому правило воріт двошарове:

```
дозволено(a → b, ціль) ⟺ пара(a → b) оголошена  ∧  ціль ∈ b.published
```

Перший кон'юнкт — «чи взагалі можна до b». Другий — «і тільки в його опубліковану поверхню». Саме об другий розбивається наскрізний приклад: `billing` імпортує `control/domain/Device`. Пара `billing→control` оголошена (замовник-постачальник) — перший кон'юнкт істинний. А от `Device` лежить у `control/domain`, не в `control/published` — другий кон'юнкт хибний, і ребро летить у порушення. Наївна перевірка, що знає тільки «дозволено/ні» на рівні контекстів, це ребро **пропустила б**, бо пара ж легальна. DH-ворота — ні.

## Ворота: фітнес-функція, що валить збірку

Такий тест — це **фітнес-функція** в тому сенсі, який Нейл Форд, Ребекка Парсонз і Патрік Куа ввели в «Building Evolutionary Architectures» (O'Reilly, 2017): виконуваний вимір, що стереже архітектурну властивість, поки код змінюється. Термін вони позичили з еволюційних обчислень, де фітнес-функція оцінює, наскільки особина пасує до середовища. Наша властивість проста: жодне ребро в коді не сміє суперечити мапі. Ось вирок над одним ребром і драйвер, що проганяє його по всіх знайдених імпортах:

:::tabs
```ts
// ownerOf(шлях) -> контекст за найдовшим коренем і сам сканер import-ів —
// ті самі, що в загальній перевірці; тут лише DH-вирок поверх знайдених ребер.
function verdict(from: string, to: string, target: string): string | null {
  if (from === to) return null;                 // всередині контексту — вільно
  const dst = MAP[to];
  if (!dst) return null;                         // зовнішній пакет — окрема перевірка (див. пастки)
  const pairOk = dst.open || to in MAP[from].allow;
  if (!pairOk) return `неоголошене ребро ${from} → ${to}`;
  if (!target.startsWith(dst.pub))
    return `${from} тягне НУТРОЩІ ${to}: ${target} (дозволено лише ${dst.pub})`;
  return null;
}

type Imp = { fromFile: string; target: string };   // джерело ребра — сканер import-ів

function audit(imports: Imp[], ownerOf: (p: string) => string | null): string[] {
  const bad: string[] = [];
  for (const { fromFile, target } of imports) {
    const from = ownerOf(fromFile), to = ownerOf(target);
    if (from === null || to === null) continue;      // поза мапою — не наша межа
    const v = verdict(from, to, target);
    if (v) bad.push(v);
    // структурні контракти поверх пер-ребра:
    if (MAP[to]?.isolated && from !== to) bad.push(`окремі шляхи порушено: ${from} → ${to}`);
    if ((from === "events" || from === "ids") && to !== from)
      bad.push(`${from} має бути листком, а тягне ${to}`);
  }
  return bad;
}

export function main(imports: Imp[], ownerOf: (p: string) => string | null): number {
  const bad = audit(imports, ownerOf);
  if (bad.length === 0) { console.log("мапа DH тримається"); return 0; }
  console.error("АРХІТЕКТУРНІ ПОРУШЕННЯ DH:");
  for (const b of bad) console.error("  " + b);
  return 1;                                          // exit 1 → крок CI червоний → merge заблоковано
}
```
```py
# owner_of(шлях) -> контекст за найдовшим коренем і сам сканер import-ів —
# ті самі, що в загальній перевірці; тут лише DH-вирок поверх знайдених ребер.
def verdict(frm, to, target):
    if frm == to:
        return None                              # всередині контексту — вільно
    dst = MAP.get(to)
    if dst is None:
        return None                              # зовнішній пакет — окрема перевірка (див. пастки)
    pair_ok = dst.get("open") or to in MAP[frm]["allow"]
    if not pair_ok:
        return f"неоголошене ребро {frm} → {to}"
    if not target.startswith(dst["pub"]):
        return f"{frm} тягне НУТРОЩІ {to}: {target} (лише {dst['pub']})"
    return None

def audit(imports, owner_of):                     # imports: [(файл-джерело, ціль-модуль), …]
    bad = []
    for from_file, target in imports:
        frm, to = owner_of(from_file), owner_of(target)
        if frm is None or to is None:
            continue                              # поза мапою — не наша межа
        v = verdict(frm, to, target)
        if v:
            bad.append(v)
        if MAP.get(to, {}).get("isolated") and frm != to:  # окремі шляхи: у video не входить ніхто ЗЗОВНІ
            bad.append(f"окремі шляхи порушено: {frm} → {to}")
        if frm in ("events", "ids") and to != frm:  # шина й ядро мусять бути листками
            bad.append(f"{frm} має бути листком, а тягне {to}")
    return bad

def main(imports, owner_of):
    bad = audit(imports, owner_of)
    if not bad:
        print("мапа DH тримається")
        return 0
    print("АРХІТЕКТУРНІ ПОРУШЕННЯ DH:")
    for b in bad:
        print("  " + b)
    return 1                                       # exit 1 → крок CI червоний → merge заблоковано
```
:::

Драйвер бере знайдені сканером ребра й проганяє кожне крізь `verdict` плюс два **структурні контракти**, яких пер-ребро мало: `isolated` стереже окремі шляхи відео (в нього не сміє входити ніхто), а перевірка листка не дає шині подій чи ядру ідентифікаторів раптом потягти чийсь контекст. Ці два — прямі DH-двійники того, що в промислових інструментах звуть «independence» та «forbidden» контрактами (`import-linter` у Python має обидва: перший забороняє будь-які імпорти між множинами модулів навіть опосередковано, другий — щоб один набір не імпортувався іншим).

Тепер наскрізний приклад у роботі. Хтось у білінгу під дедлайн дописав `import { Device } from "../control/domain/device"` — «щоб швидше дістати можливості пристрою». Рев'ю проґавило, юніт-тести зелені. На збірці ворота кажуть:

```
АРХІТЕКТУРНІ ПОРУШЕННЯ DH:
  billing тягне НУТРОЩІ control: src/control/domain/device (дозволено лише src/control/published)
```

і процес виходить із кодом `1` — крок CI червоний, merge заблоковано. Прибираєш заборонений імпорт (береш факт із `control/published`, як і належить замовнику) — і та сама перевірка каже `мапа DH тримається` з кодом `0`. Стіна спрацювала до того, як білінг устиг припнутися до живого агрегата керування й почати ламатися щоразу, коли той агрегат еволюціонує.

![Ліворуч коробка «Білінг»; праворуч область «Керування (control)» з двома поверхнями — угорі жовта published/DeviceRegistered, унизу domain/Device; зелена стрілка від білінга дозволено входить у published, а червона пунктирна впирається в товсту стіну перед domain з позначкою ✗ і підписом «збірка червона»](/root/course/progarch/dh-contexts-map/img/published-wall.svg)

*Ребро billing→control оголошене — та лише в опубліковану поверхню. Читати `control/published/DeviceRegistered` можна; тягнути `control/domain/Device` — ні, бо це нутрощі сусіда. Пара легальна, а конкретний імпорт — порушення.*

Куди це чіпляється — тривіально, бо `main` уже повертає правильний код виходу: крок у CI (`node arch.mjs` чи `python -m arch`), який на ненульовому виході валить увесь конвеєр. Важлива лише одна дисципліна: **не робити перевірку необов'язковою**. Крок, який пише порушення, але завершується нулем через чиєсь «поки що» `|| true`, — це знову мапа-музей, тільки дорожча: ілюзія контролю без контролю.

## Та сама картинка — з тих самих даних

Ось де DH-артефакт іде далі за загальну перевірку. Та зупиняється на текстовому вироку. А ми хочемо, щоб **картинка** з попереднього кроку теж народжувалася з `MAP`, — тоді вона фізично не зможе розійтися ні з воротами, ні з правдою. Це і є diagram-as-code: не малюєш стрілки рукою, а **обходиш ті самі дані** й друкуєш вузли та підписані ребра:

```py
# draw.py — SVG-мапа DH з ТИХ САМИХ даних, що й ворота. Ребра беремо з MAP, не з голови.
import math

SHORT = {"partnership": "партн.", "customer-supplier": "зам.-пост.",
         "conformist": "конф.", "published-language": "оп. мова",
         "shared-kernel": "ядро", "separate-ways": "окр. шляхи", "acl": "ACL"}

def draw(path):
    names = list(MAP)
    cx, cy, R = 430, 300, 250
    pos = {n: (cx + R * math.cos(-math.pi / 2 + 2 * math.pi * i / len(names)),
               cy + R * math.sin(-math.pi / 2 + 2 * math.pi * i / len(names)))
           for i, n in enumerate(names)}
    p = ['<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 860 620">']
    for n, meta in MAP.items():                       # ← ребра лише з даних
        for to, kind in meta["allow"].items():
            (x1, y1), (x2, y2) = pos[n], pos[to]
            p.append('<line x1="%.0f" y1="%.0f" x2="%.0f" y2="%.0f" stroke="#333"/>'
                     % (x1, y1, x2, y2))
            p.append('<text x="%.0f" y="%.0f" font-size="10" text-anchor="middle">%s</text>'
                     % ((x1 + x2) / 2, (y1 + y2) / 2, SHORT[kind]))
    for n, (x, y) in pos.items():
        p.append('<circle cx="%.0f" cy="%.0f" r="34" fill="#eef" stroke="#333"/>' % (x, y))
        p.append('<text x="%.0f" y="%.0f" font-size="11" text-anchor="middle">%s</text>'
                 % (x, y, n))
    p.append("</svg>")
    open(path, "w", encoding="utf-8").write("\n".join(p))
```

Розкладка тут навмисно дурна — вузли по колу; краса картинки не мета. Мета — **походження стрілок**. Кожне ребро на малюнку взяте з `meta["allow"]`, а не набране пальцями. Додав у `MAP` нове ребро — на картинці **сам собою** з'явився штрих із правильним підписом. Забув додати ребро, але дописав імпорт — ворота почервоніли. Намалювати мапу, на якій бракує оголошеного ребра, тепер неможливо, бо ти її взагалі не малюєш: обидва документи, картинка й вирок, приколоті до `MAP` з двох боків, і жодному нема куди відповзти.

Це не саморобна екзотика. Промислові інструменти вже вміють обидва боки з одного джерела: `dependency-cruiser` тим самим проходом по імпортах і **валить збірку** на забороненому правилі, і малює граф — `depcruise src --output-type dot | dot -Tsvg > map.svg` дає картинку рівно з того коду, який щойно перевірив. Той самий принцип, лиш готовий: одні дані — і ворота, і зображення.

І третій споживач напрошується безкоштовно. Раз `MAP` знає всі ребра з видами зв'язку, з нього так само друкується **та таблиця-довідник** рядками — не набрана в редакторі, а породжена, тож завжди актуальна. Обійди `MAP`, для кожного ребра виведи рядок `from → to | вид | що це каже`, для `open`-вершин — рядок «усі → identity/events/ids». Таблиця, картинка й ворота — троє нащадків одного файлу.

## Складність і пастки

Наївний артефакт вище стереже головне, але між «працює на моєму дереві» й «на нього можна покластися» лежить кілька DH-специфічних грабель. Кожну варто знати в обличчя.

**Напрямок стрілки — не напрямок імпорту.** Це найпідступніше, бо тихо **перевертає** сенс. На картинці стрілка `control → billing` означає течію: зміна керування змушує білінг наздоганяти. А в коді залежність протилежна — це **білінг** імпортує керування (замовник тягне постачальника). Тому в `MAP` ребро стоїть у `billing.allow`, не в `control.allow`. Переплутаєш — і ворота почнуть вимагати, щоб постачальник імпортував замовника, тобто стерегтимуть архітектуру задом наперед, пропускаючи справжні порушення. Наш `control` з порожнім `allow` — саме тому порожній: він нікого не імпортує, хоч на картинці з нього виходять дві стрілки течії. До речі, це дає безкоштовну перевірку: якщо `control` раптом почав щось імпортувати з периферії — ядро дому потекло назовні, і це вже саме по собі порушення.

**Опублікована мова — не пряме ребро між контекстами.** Коли замок замкнувся, керування не дзвонить телеметрії — воно кладе подію в **шину**. Тому в даних `telemetry.allow` порожній: телеметрія імпортує не керування, а `events` — нейтральну вершину, спільну для всіх. Спокуса змоделювати це як `control → telemetry` хибна: такого імпорту в коді нема й не має бути, а справжнє ребро — `telemetry → events`. Шина — окремий вузол саме тому, що [не належить ні продюсеру, ні споживачам](root:progarch/dh-data-model), і кожен тримається за неї, а не за нутрощі сусіда.

**Партнерство — це дозволений цикл, не помилка.** Спокусливо додати контракт «жодних циклів у графі» — і він одразу засвітить `hub ↔ twin` як заборонену петлю. Але цей цикл **легальний**: партнерство і є двобічна залежність рівних, що релізяться разом. Мораль: не забороняй усі цикли гамузом; партнерство легітимізує рівно одну петлю на стик, і вона має бути **оголошена** обома `allow`, а не заборонена скопом.

**Окремі шляхи треба стерегти активно.** Відсутність ребра **невидима** для перевірки по знайдених ребрах: якщо відео тихо ні з ким не зв'язане, воріт це не обходить. Але щойно хтось додасть `video → billing` «щоб показувати камери в рахунку», наївна перевірка змовчить — адже вона лише звіряє *наявні* ребра з дозволеними, а поява нового заборонена хіба явним правилом. Тому ізоляцію треба **стверджувати**: прапорець `isolated` каже воротам активно валити будь-яке вхідне ребро у відео. Це та сама думка, що independence-контракт у `import-linter`: свідома **не**-залежність вартує рядка коду, інакше вона вивітриться.

**Спільне ядро тримай крихітним цифрою, а не совістю.** `ids` пускаємо всім — і це правильно: `DeviceId`, `HomeId` мають бути одні на всіх. Але цей виняток найнебезпечніший, бо надто зручний: у «спільне» починає стікати все підряд, і за півроку ядро розпухає в другу грудку багна, тільки узаконену. Ліки — додатковий гейт, що рахує файли (чи рядки) у `src/shared/ids` і валить збірку, коли ядро переросло стелю; хай машина нагадує про межу числом, а не сподіванням на дисципліну. І пильнуй, щоб у «спільне» не заповз цілий `Device`: ядро — це самі типи-ідентифікатори, а не жива модель.

**Зовнішній світ живе поза графом контекстів.** Вендорські SDK, платіжний і пуш-провайдери сидять у `node_modules`, не в `src/`, тож `ownerOf` поверне на них `null`, і `verdict` їх пропустить. Але ACL до них — теж правило мапи, лише іншого крою: не «контекст → контекст», а «**лише** хаб сміє імпортувати вендорський SDK, лише білінг — платіжний, лише сповіщення — пуш». Це окремий білий список «хто сміє тягти цей зовнішній пакет», який кладеться поряд і перевіряється так само різницею множин. А зв'язки, що йдуть **повз** код узагалі — спільна таблиця, черга, — статичний сканер не бачить: тут його чесно доповнює [людський огляд і журнал рішень](book:programming/context-mapping/proj-context-map-as-code.md), як розписано в загальній статті про сліпі зони інструмента.

## Що лишається в руках

Мапа DH перестала бути картинкою, що старіє. Дев'ять світів, дві спільні вершини й усі дозволені ребра з видами зв'язку живуть в одному файлі `MAP`, а машина читає його **тричі**: як фітнес-функцію, що валить збірку двошаровим вироком «пара оголошена ∧ ціль у published» і ловить навіть тонке `billing → control/domain/Device`; як SVG-мапу, де кожен штрих родом із даних, тож картинка не може загубити оголошене ребро; і як таблицю-довідник, породжену, а не набрану. Троє нащадків одного джерела рухаються разом — розійтися нема куди ні наявності стрілки, ні її природі, ні зображенню.

Пастки окреслюють, де артефакт міцний, а де потребує руки поряд: напрямок імпорту протилежний течії (не переплутай і не перевернеш ворота), опублікована мова — це ребро до шини, а не між контекстами, партнерство — легальний цикл, окремі шляхи й крихкість ядра треба **стверджувати** числом і прапорцем, а зовнішній світ і не-кодові канали лишаються за окремим білим списком та оглядом.

Головне, що ти забираєш: цей файл — те місце, куди курс повертатиметься. Коли постане питання, [чи різати хмару DH на окремі сервіси й чи витримає стик мережу](root:progarch/context-as-service-candidate), новий шов оголошується тут — і ворота, картинка й легенда зрушуються одним рухом, разом. Довідник, який фізично не може збрехати, — це не краса, а рівно та гарантія, якої найбільше бракує системі, що переживе не одну нараду.
