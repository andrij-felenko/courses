# Курс «Архітектура програм» (slug: progarch) — проєкт з лінзи «Викладач»

**Повна назва:** «Архітектура програм: від одного файлу до мільйонів користувачів»
**Тип:** guide (послідовний курс, схема v5: modules → chapters → steps)
**Пререквізит:** модуль «Вхід у програмування» курсу embedded або еквівалент — читач ВМІЄ писати код (функції, цикли, структури даних рівня «знаю, що таке хеш-мапа»). Синтаксису не вчимо.
**Обсяг:** 250 кроків · 10 модулів (21–29 кроків кожен) · 56 розділів (5–6 на модуль).
**Дуга:** принципи коду → класичні патерни → архітектура застосунку → дані → паралельність → мережа/API → розподілені системи → високе навантаження → надійність → експлуатація.

## 1. Дидактична рама

### 1.1 Наскрізний проєкт: сервіс «Квиток»

Сервіс продажу квитків на події. Обраний навмисно: у ньому природно живуть УСІ болі курсу, і кожен модуль його розвиває:

| Версія | Модуль | Що стається з «Квитком» |
|---|---|---|
| v0 — один файл | М1 | працює, але страшно міняти → біль модульності |
| v1 — модулі | М1 | розрізаний на модулі, з тестами |
| v2 — патерни | М2 | доречні патерни (стратегія цін, спостерігач сповіщень) |
| v3 — шари | М3 | домен окремо від UI і сховища; автомат станів замовлення |
| v4 — база даних | М4 | SQL, транзакція на «останній квиток» |
| v5 — багатопотоковий | М5 | гонка за квиток у НАШОМУ коді; пул воркерів |
| v6 — HTTP-API | М6 | клієнти по мережі; таймаути, ретраї, ідемпотентність |
| v7 — кілька вузлів | М7 | реплікація, шардинг за подіями, outbox |
| v8 — під піком | М8 | кеш афіші, зала очікування на старті продажу |
| v9 — незламний | М9 | запобіжник довкола платіжки, навчальні аварії |
| v10 — в експлуатації | М10 | метрики, конвеєр деплою, розбір інциденту |

Драматургія: «гонка за останній квиток» (М4→М5→М7) і «старт продажу на топ-концерт» (М8) — два наскрізні конфлікти, до яких курс повертається по спіралі.

### 1.2 Мотивація на вході («який біль розвʼязуємо»)

Кожен модуль відкривається болем із «Квитка» або живим кейсом компанії (рядок «Біль» нижче в кожному модулі — це перший абзац вступного кроку модуля).

### 1.3 Спіраль повторення

- **Гонки:** транзакція БД як щит (М4) → механіка гонки в коді (М5) → гонка між вузлами, кворум (М7) → гонка мільйона людей за квитки (М8).
- **Черга:** черга-структура (М5) → черга повідомлень (М6) → черга як амортизатор піка + теорія черг (М8).
- **Кеш:** кеш процесора (ref у М5-вступі) → кеш даних застосунку (М4) → кеш-сервер, CDN (М8).
- **Таймаути/повтори:** мережеві основи (М6) → бюджети часу і запобіжники (М9).
- **Інтерфейс/контракт:** функція-модуль (М1) → патерни (М2) → порти й адаптери (М3) → API сервісу (М6) → межі мікросервісів (М7).
- **Embedded-місток** (для читачів після embedded): scheduler, priority-inversion, watchdog, MQTT — знайомі атоми в новому контексті серверів.

### 1.4 Рівні сходинки

Жоден крок не вживає невведеного поняття (перевірку пререквізитів між модулями див. §5). Усі нові book-атоми — самодостатні (читаються без курсу), а кумулятивність несуть own-кроки.

- М2 (патерни) ← інтерфейси, залежності, інверсія залежностей (М1).
- М3 (DI, шари) ← інверсія залежностей (М1), фабрика/стратегія (М2).
- М4 (транзакції) вводить гонку ЛИШЕ як явище, щит — транзакція; механіку розкриває М5 (свідома спіраль, у тексті кроку 4.5.21 — форвард-посилання «зазирнемо під капот у наступному модулі»).
- М5 (черга-структура) ← вводиться в тому ж розділі до producer-consumer.
- М6 (серіалізація в API) ← М4.1; (проксі як патерн віддаленості) ← М2.3.
- М7 (реплікація/шардинг) ← БД (М4), мережа/таймаути/ідемпотентність (М6); консистентне хешування ← хеш-мапа з пререквізиту курсу + нагадування в самому атомі.
- М8 (черги/Літтл) ← producer-consumer (М5), брокер (М6); (репліки читання) ← М7.2; (CDN) ← кешування 8.3 і DNS (М6.1).
- М9 (запобіжник) ← таймаути/ретраї (М6), перцентилі (М8); (failover) ← вибори лідера (М7).
- М10 (канарки за метрикою) ← метрики (10.1) і SLO (М9); (автоскейл) ← балансувальник (М8).

## 6. Самоперевірка розділів («розділ = одна мета?»)

Кожен із 56 розділів має мету-однорядник у дужках при назві (див. вище). Контрольні сумніви й ухвали:
- 1.5 «Щоденні інструменти якості» — git+тести+ревʼю+аналіз = одна мета «страхувальні сітки щодня»; рефакторинг винесено окремо (1.6 — практика зміни, не інструмент).
- 3.6 «Рішення і їхній слід» — ADR + вибір технологій + межі монолита = одна мета «як ухвалювати і фіксувати рішення».
- 8.3 «Кешування» — 7 кроків, найбільший розділ курсу, але мета одна (не рахувати двічі); різати на «локальний/розподілений» штучно.
- 9.5 «Стійкість до зловмисника» — безпека свідомо в модулі надійності: та сама мета «система працює попри вороже середовище»; повний курс безпеки — поза скоупом progarch.
- Кейси гігантів (8.6) — окремий розділ-синтез, а не розкидані по темах: мета «скласти інструменти в цілісні живі системи».

## 7. Ризики та відкриті питання

1. **68 нових book-атомів** — велика черга письма понад 133 own-статті курсу. Пом'якшення: 28 ref-ів уже done — перші два модулі читабельні швидко; nb-атоми М2 (патерни) незалежні один від одного — добре лягають у батч-письмо.
2. **Дублікати в індексі** (adaptive-bitrate у двох книгах, wear-leveling тощо) — для кейсу YouTube інлайн-реф на communications/networks/adaptive-bitrate; при письмі перевірити, чи не зливати.
3. **programming/services vs programming/systems** — межа: systems = усередині однієї машини/процесу; services = компоненти між процесами й машинами. Зафіксувати в scope секцій при створенні.
4. **Мова термінів** — вживано: патерн, кеш, шардинг, реплікація, консенсус, балансувальник, запобіжник (circuit breaker), перебірки (bulkhead), зала очікування, фікус-душитель (strangler fig), викочування (rollout). Перекладні пари даються один раз при введенні терміна.
5. **Кейси компаній** — усі історичні твердження (Ticketmaster 2022, GitLab 2017, Dapper 2010, AWS 2006, «указ Безоса») у hist-вставках писати з перевіркою джерел за AUTHORING §7; цифри на кшталт «девʼять девʼяток AXD301» подавати як заяву-легенду з застереженням.
6. **Час/наступність:** курс не залежить від інших guide-ів; embedded-містки (watchdog, priority-inversion, MQTT, scheduler) — це ref-и на book-атоми, доступні будь-кому.
