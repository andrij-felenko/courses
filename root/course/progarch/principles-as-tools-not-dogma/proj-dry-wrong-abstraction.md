# ⚙️ Розчеплення хибної абстракції: цикл на коді Digital Homes

У хабі Digital Homes два місця шлють власнику сповіщення — про рух в охоронюваній зоні й про пристрій, що зник зі зв'язку. Ми щойно бачили, як спокуса «не повторюватися» злила їх в один метод, а перша ж пара розбіжних вимог перетворила той метод на кашу з `if (kind === …)`. Тепер зробімо руками те, що на словах звучить просто, а наважується мало хто: **вийдемо з хибної абстракції назад** — і на її місці зведемо правильну. Не на папері, а робочим кодом, крок за кроком: злиття → каша → розчеплення → чесний винос уже по справжній осі. А наприкінці зміримо результат тим, що не лестить, — тестами до й після.

Розворот цей описала інженерка Сенді Метц в есеї «The Wrong Abstraction» (опублікований 20 січня 2016; саму ідею вона винесла раніше — у доповіді «All the Little Things» на RailsConf 2014). Її формула варта, щоб висіти над столом: **дублювання набагато дешевше за хибну абстракцію**. Чому — стане видно, коли ми пройдемо цикл до кінця й порахуємо, що коштувало більше.

Щоб код читався як код, а не як натяк, домовмося про кілька готових помічників хаба — далі ми лише ними користуємось:

```
time(at)         → "14:07"               sendVia(ch, text)      → шле каналом ch ∈ {sms, push}
sinceMin(at)     → хвилин минуло від at   scheduleRepeat(t, chs) → повторює, доки не підтвердять
ZONE_RISK[zone]  → базовий бал зони 0…3   isNight(now)           → чи зараз ніч
```

## Ідея: найкоротший шлях уперед — назад

Інстинкт, коли метод обріс прапорцями, — патчити далі: ще один `if`, ще один параметр, ще одна гілка під новий випадок. Кожен такий патч дешевий поодинці й катастрофічний у сумі — саме так хибна абстракція й набирає масу, доки її не стане страшно чіпати. Метц пропонує протилежний, майже єретичний рух. Її дослівна порада — **«the fastest way forward is back»**, найкоротший шлях уперед лежить назад. Не добудовувати абстракцію, а **розібрати** її, повернути дублювання, яке колись поспіхом прибрали, — і аж тоді, коли справжні шви проступлять на очах, абстрагувати заново, уже по правильній осі.

Конкретно есей дає три кроки виходу, і ми пройдемо кожен на живому коді:

1. **Поверни дублювання** — вклей тіло абстракції назад у кожен виклик (inline).
2. **У кожному виклику лиши свою підмножину** — параметри, з якими сюди заходили, кажуть, яка гілка тут справжня.
3. **Викинь зайве** — усе, що не потрібне цьому конкретному викликові, видали.

Що заважає це зробити — не техніка, а психологія: злитий метод *працює*, у нього вкладено працю, і рука не піднімається його ламати. Це [пастка втрачених витрат](book:programming/tradeoff-analysis) (sunk cost) — коли рішення женуть не майбутньою користю, а вже витраченим. Метц називає її прямо й радить одне: не дай минулим витратам вести. Гроші, вкладені в хибну абстракцію, уже витрачені; єдине питання — скільки коштуватиме тримати її далі.

## Як здорове DRY стає хибною абстракцією

Почнімо з невинного стану. Дві функції, кожна робить своє, і на око вони справді близнюки — обидві складають рядок із назви й часу та шлють власнику:

:::tabs
```ts
function notifyMotion(ev: MotionEvent): void {
  const text = `Рух у зоні «${ev.zone}» о ${time(ev.at)}`;
  sendVia("push", text);
}
function notifyOffline(ev: OfflineEvent): void {
  const text = `Пристрій «${ev.device}» офлайн о ${time(ev.at)}`;
  sendVia("push", text);
}
```
```py
def notify_motion(ev: MotionEvent) -> None:
    text = f"Рух у зоні «{ev.zone}» о {time(ev.at)}"
    send_via("push", text)

def notify_offline(ev: OfflineEvent) -> None:
    text = f"Пристрій «{ev.device}» офлайн о {time(ev.at)}"
    send_via("push", text)
```
:::

Рука тягнеться злити: та сама форма, той самий `sendVia("push", …)` — навіщо двічі? Виносимо у `notify(kind, …)` із шаблоном за `kind`. [DRY](book:programming/dry-kiss-yagni) задоволено, дублювання нема. І тут важливо зупинитися на тому, що саме ми щойно зробили: ми зшили дві функції на підставі того, що **збіглася їхня видима форма** — довжина рядка, виклик каналу. Ми не питали, чи це одне знання. А воно не одне — просто ще не встигло розійтися.

Розходиться воно з першою реальною вимогою. Служба безпеки хоче, щоб тривога руху **ескалувалася**: не тихий пуш, а SMS *і* пуш, повторювати, доки власник не підтвердить, і дописати рівень небезпеки зони. Офлайн, навпаки, лишається тихим одноразовим пушем, зате з рядком «останній зв'язок N хвилин тому». Дві вимоги до двох різних гілок лягають у **спільний** метод. А трохи згодом приходить третій випадок — «батарея сідає», — і кожна розвилка обростає ще одним рукавом. Ось до чого доходить `notify` кілька вимог по тому:

:::tabs
```ts
type Kind = "motion" | "offline" | "lowbat";

// метод відростив ще й параметр zone і третій kind
function notify(kind: Kind, subject: string, zone: string, at: number): void {
  // 1) тіло тексту — розвилка на kind
  let text: string;
  if (kind === "motion")        text = `Рух у зоні «${zone}» о ${time(at)}`;
  else if (kind === "offline")  text = `Пристрій «${subject}» офлайн о ${time(at)}`;
  else                          text = `Батарея «${subject}» сідає`;

  // 2) хвіст тексту — знову розвилка на kind
  if (kind === "motion")   text += ` — небезпека ${ZONE_RISK[zone] ?? 0}`;
  if (kind === "offline")  text += ` — останній зв'язок ${sinceMin(at)} хв тому`;

  // 3) канали — розвилка
  const channels = kind === "motion" ? ["sms", "push"] : ["push"];

  // 4) повтор — розвилка
  const repeat = kind === "motion";

  for (const ch of channels) sendVia(ch, text);
  if (repeat) scheduleRepeat(text, channels);
}
```
```py
Kind = Literal["motion", "offline", "lowbat"]

# метод відростив ще й параметр zone і третій kind
def notify(kind: Kind, subject: str, zone: str, at: float) -> None:
    # 1) тіло тексту — розвилка на kind
    if kind == "motion":
        text = f"Рух у зоні «{zone}» о {time(at)}"
    elif kind == "offline":
        text = f"Пристрій «{subject}» офлайн о {time(at)}"
    else:
        text = f"Батарея «{subject}» сідає"

    # 2) хвіст тексту — знову розвилка на kind
    if kind == "motion":
        text += f" — небезпека {ZONE_RISK.get(zone, 0)}"
    if kind == "offline":
        text += f" — останній зв'язок {since_min(at)} хв тому"

    # 3) канали — розвилка
    channels = ["sms", "push"] if kind == "motion" else ["push"]

    # 4) повтор — розвилка
    repeat = kind == "motion"

    for ch in channels:
        send_via(ch, text)
    if repeat:
        schedule_repeat(text, channels)
```
:::

Придивись до сигнатури — вона вже зраджує біду. Виклики змушені передавати заглушки в параметри, яких їхня гілка не торкається:

```ts
notify("motion",  "",        ev.zone, ev.at);   // subject не потрібен — тичемо ""
notify("offline", ev.device, ev.zone, ev.at);   // zone тут висить «про запас»
```

Метод має **чотири** незалежні розвилки на `kind`, і жодна з гілок motion не поділяє логіки з гілкою offline — вони ділять лише кістяк «скласти рядок і надіслати», той самий випадковий збіг форми, за який ми й ухопилися. Це і є хибна абстракція в повній красі: спільним зробили те, що спільним лише *здавалося*. Гірше — вона підняла [зчеплення](book:programming/coupling-cohesion) там, де його не було: тепер кожна нова вимога до тривоги фізично лягає в той самий метод, що й офлайн, і не даси собі ради з однією гілкою, не боячись зачепити другу.

Це видно навіть у тесті. Спробуй закріпити просту вимогу — «офлайн шле рівно один тихий пуш, без SMS і без повторів»:

:::tabs
```ts
test("offline: один тихий пуш, без SMS і повторів", () => {
  const bus = spyBus();                            // підміняє sendVia / scheduleRepeat
  notify("offline", "Камера-1", "передпокій", T);  // сигнатура motion-подібна
  expect(bus.push).toHaveBeenCalledTimes(1);
  expect(bus.sms).not.toHaveBeenCalled();
  expect(bus.repeat).not.toHaveBeenCalled();
});
```
```py
def test_offline_one_silent_push():
    bus = spy_bus()                                  # підміняє send_via / schedule_repeat
    notify("offline", "Камера-1", "передпокій", T)   # сигнатура motion-подібна
    assert bus.push == 1
    assert bus.sms == 0
    assert bus.repeat == 0
```
:::

Тест ніби нескладний, а насправді хисткий. Щоб пояснити офлайн, ти будуєш `motion`-подібну сигнатуру й простягаєш `zone`, який офлайн для каналів не читає. Три `expect` стережуть поведінку, що живе в **спільних** розвилках: варто комусь докрутити тривогу — додати їй третій канал, змінити умову `repeat` — і зміна впаде в **той самий** метод, поряд із гілкою offline. Тест захищає не одиницю, а вузол; він зелений сьогодні й може почервоніти від правки, яка офлайн навіть не мала на увазі. Ось операційна ціна хибної абстракції: страх правити тривогу без переогляду офлайн, вшитий у самі тести.

## Крок назад: inline, викинути, розчепити

Тепер — розворот. Пройдемо три кроки Метц буквально.

**Крок 1 — inline.** Вклеюємо тіло `notify` назад у кожен виклик. На мить коду стане *більше*, і це нормально: ми навмисне повертаємо дублювання, щоб побачити, що з нього справжнє.

**Крок 2 — лишити свою підмножину.** У виклику з тривоги `kind` завжди `"motion"` — отже, всі `if (kind === "offline")` та `else` тут мертві. У виклику з офлайну навпаки. Параметр, з яким заходили, вирішує, яка гілка справжня.

**Крок 3 — викинути.** Мертві гілки видаляємо. Лишається три прямі функції, кожна без жодного `if (kind)`:

:::tabs
```ts
function notifyMotion(ev: MotionEvent): void {
  const text = `Рух у зоні «${ev.zone}» о ${time(ev.at)} — небезпека ${ZONE_RISK[ev.zone] ?? 0}`;
  sendVia("sms", text);
  sendVia("push", text);
  scheduleRepeat(text, ["sms", "push"]);       // доки власник не підтвердить
}

function notifyOffline(ev: OfflineEvent): void {
  const text =
    `Пристрій «${ev.device}» офлайн о ${time(ev.at)} — останній зв'язок ${sinceMin(ev.at)} хв тому`;
  sendVia("push", text);                        // тихий одноразовий
}
```
```py
def notify_motion(ev: MotionEvent) -> None:
    text = f"Рух у зоні «{ev.zone}» о {time(ev.at)} — небезпека {ZONE_RISK.get(ev.zone, 0)}"
    send_via("sms", text)
    send_via("push", text)
    schedule_repeat(text, ["sms", "push"])       # доки власник не підтвердить

def notify_offline(ev: OfflineEvent) -> None:
    text = (f"Пристрій «{ev.device}» офлайн о {time(ev.at)} "
            f"— останній зв'язок {since_min(ev.at)} хв тому")
    send_via("push", text)                        # тихий одноразовий
```
:::

Подивись, що сталося. Кожна функція тепер читається згори вниз без жодної розвилки; тривогу можна правити, навіть не знаючи, що офлайн існує; сигнатури беруть рівно свій тип події — жодних заглушок. Ми не «втратили» абстракцію — ми викинули *неправильну*. Зчеплення між двома сповіщеннями впало до нуля: у них більше немає спільного тіла, яке можна ненароком зламати.

> 🔧 **Навіщо це.** Ось звідки формула «дублювання дешевше за хибну абстракцію» бере свою правду. Дублікат ти бачиш очима й правиш за хвилину; хибна ж абстракція збирає навколо себе умовну логіку роками, і кожен, хто її торкається, платить податок страху. Повернути дублювання — операція на пів години й повністю зворотна. Тому коли вагаєшся, «злити чи лишити», помиляйся в бік дублювання: з двох копій завжди можна зробити абстракцію, коли вісь проступить, а з хибної абстракції вибиратися доводиться крізь оцей самий розворот.

## Справжня вісь: формула небезпеки, не форма рядка

Розворот дав чистоту, але не сказав головного: а *що ж* тут справді спільне? Форма рядка була хибною віссю. Справжня ховалася в іншому місці — і проступила рівно тоді, коли ми прибрали фальшиву й дали вимогам говорити.

Приходить нова вимога, і вона все змінює: офлайн-пристрій **у небезпечній зоні** (камера в сейф-кімнаті, датчик на дверях) — сам по собі подія; хтось міг перерізати зв'язок. Такий офлайн має не мовчати, а ескалувати, як тривога. Ще одне рішення того ж хаба: озброюючи зону на ніч, для небезпечних зон вимагати друге підтвердження. І от у трьох різних місцях коду постає **одне й те саме питання — «наскільки небезпечна ця зона»**, і кожен розробник відповідає на нього по-своєму, локально:

```ts
// у notifyMotion — сирий бал, ніч не врахована:
text += ` — небезпека ${ZONE_RISK[ev.zone] ?? 0}`;
// у notifyOffline — поріг «двійка й вище»:
if ((ZONE_RISK[ev.zone] ?? 0) >= 2) escalate();
// в armZone — захардкоджений список зон:
if (["спальня", "сейф-кімната"].includes(zone)) requireSecondConfirm(zone);
```

Три копії однієї ідеї, записані трьома різними виразами. Сьогодні вони дають однаковий присуд — і саме тому здаються безпечними. Але це та сама сила, від якої застерігає DRY по-справжньому: **продубльоване знання з часом розходиться**. Перевірмо це на конкретному майбутньому.

**Умова: бізнес додає правило «вночі — на щабель небезпечніше». Подія: рух уночі у спальні (база зони 2).**

```
дадуть правку в notifyMotion  → небезпека 2 + 1 = 3   ✔ побачив ніч
про notifyOffline забули       → поріг лишився на сирих 2, ескалації вночі нема   ✘
про armZone забули             → список зон ночі взагалі не знає   ✘

фактична небезпека вночі = 3, а система в двох місцях із трьох діє на 2
```

Одна зміна формули — і три «однакові» копії розсинхронізувалися тихо, без жодної помилки компілятора. Це не гіпотеза «а раптом»: щойно бізнес змінює формулу — а він її змінює, — копії розходяться. Ось де справжня спільна вісь: не форма рядка, а **формула небезпеки зони**, яку бізнес володіє й міняє як одне ціле.

![Ліворуч — хибна вісь: notifyMotion і notifyOffline тягнуться в один метод notify(kind, …), спільний лише на око, а гілки не діляться. Праворуч — справжня вісь: три різні дії (тривога руху, офлайн-пристрій, озброєння зони) спираються на одну формулу dangerLevel(zone), яку бізнес міняє як одне ціле.](/root/course/progarch/principles-as-tools-not-dogma/img/true-vs-false-axis.svg)

*Зливати треба не те, що на око схоже (рядок), а те, за чим стоїть одна сила (формула небезпеки). Три чесні користувачі однієї формули — це та абстракція, яку варто винести; два випадково схожі рядки — ні.*

Тепер виносимо — уже по правильній осі. Одна функція, єдине джерело правди про небезпеку зони (та сама, що в чорновику мигцем звалася `riskOf`):

:::tabs
```ts
// одна формула небезпеки — єдине місце, де живе це знання
export function dangerLevel(zone: string, now = Date.now()): number {
  const base = ZONE_RISK[zone] ?? 0;
  return isNight(now) ? base + 1 : base;         // ← правило ночі тепер в ОДНОМУ місці
}

// три користувачі кличуть ту саму формулу:
// notifyMotion:
text += ` — небезпека ${dangerLevel(ev.zone)}`;
// notifyOffline:
const channels = dangerLevel(ev.zone) >= 2 ? ["sms", "push"] : ["push"];
// armZone:
if (dangerLevel(zone) >= 2) requireSecondConfirm(zone);
```
```py
# одна формула небезпеки — єдине місце, де живе це знання
def danger_level(zone: str, now: float | None = None) -> int:
    base = ZONE_RISK.get(zone, 0)
    return base + 1 if is_night(now) else base    # ← правило ночі тепер в ОДНОМУ місці

# три користувачі кличуть ту саму формулу:
# notify_motion:
text += f" — небезпека {danger_level(ev.zone)}"
# notify_offline:
channels = ["sms", "push"] if danger_level(ev.zone) >= 2 else ["push"]
# arm_zone:
if danger_level(zone) >= 2:
    require_second_confirm(zone)
```
:::

Тепер правило ночі — а завтра свята, а післязавтра «зона на ремонті» — лягає в **одне** місце, і всі троє бачать його разом. Знання перестало розходитися, бо перестало бути продубльованим. Це та сама операція «винести спільне», що на початку дала хибний `notify`, — але цього разу спільне *справжнє*: не збіг форми, а одна сила, яку три різні дії чесно поділяють.

Порахуймо перевагу тестами. Раніше офлайн доводилося перевіряти крізь `kind`-тунель, а спільна поведінка сиділа в розвилках. Тепер кожна функція тестується прямо, а вся спільна логіка небезпеки закривається **одним** чистим тестом формули — на всіх трьох користувачів одразу:

:::tabs
```ts
test("офлайн у безпечній зоні — один тихий пуш", () => {
  const bus = spyBus();
  notifyOffline({ device: "Камера-1", zone: "двір", at: T });
  expect(bus.push).toHaveBeenCalledTimes(1);
  expect(bus.sms).not.toHaveBeenCalled();
});

// уся спільна логіка — в одному чистому тесті формули, без каналів і подій:
test.each([["двір", 0], ["спальня", 2], ["сейф-кімната", 3]])(
  "dangerLevel(%s) удень = %i", (zone, lvl) =>
    expect(dangerLevel(zone as string, NOON)).toBe(lvl),
);
test("вночі формула піднімає на щабель", () =>
  expect(dangerLevel("спальня", MIDNIGHT)).toBe(3));
```
```py
def test_offline_safe_zone_one_push():
    bus = spy_bus()
    notify_offline(OfflineEvent(device="Камера-1", zone="двір", at=T))
    assert bus.push == 1
    assert bus.sms == 0

# уся спільна логіка — в одному чистому тесті формули, без каналів і подій:
@pytest.mark.parametrize("zone, lvl", [("двір", 0), ("спальня", 2), ("сейф-кімната", 3)])
def test_danger_level_day(zone, lvl):
    assert danger_level(zone, NOON) == lvl

def test_danger_level_night_bumps():
    assert danger_level("спальня", MIDNIGHT) == 3
```
:::

Різниця не косметична. Тест офлайну більше не знає про тривогу й не залежить від неї; тест формули — чиста функція без каналів, подій і моків, і саме він тепер стереже правило ночі за всіх трьох. Зміниш формулу — впаде **один** тест, і ти точно знаєш, що це та зміна. Ось як виглядає абстракція, винесена по силі: вона *звужує* поверхню зламу, а не розширює її, як хибна.

> 🔧 **Навіщо це.** Звідси проста дисципліна, що вберігає від передчасного злиття, — **правило трьох**: побачив дублікат — не абстрагуй; побачив другий — терпи; аж на третьому виноси. Мартін Фаулер закріпив його в книжці «Refactoring» (1999) з посиланням на Дона Робертса: «перший раз просто роби; удруге скривися, але продублюй; утретє — рефактор». Річ не в магії числа три, а в тому, що два збіги ще не кажуть, *що саме* спільне, — форму рядка вони підказали хибно. Три справжні користувачі формули небезпеки показали вісь однозначно. Правило трьох — це не «полічи до трьох», а «дочекайся, доки кількість покаже, яка вісь реальна».

## Складність і пастки

Цикл виглядає чистим на папері, та в реальному коді на кожному кроці чатує спокуса зіскочити. Ось де тонко.

**Розворот виглядає як регрес — і його блокують на рев'ю.** Крок «повернути дублювання» тимчасово *збільшує* код і додає повторів; рецензент, навчений гасла «прибирай дублювання», щиро попросить «а давай залишимо спільний метод». Тому inline треба називати вголос як **навмисний** маневр, а не недогляд: «повертаю дублювання, щоб проступила справжня вісь, — це крок 1 з трьох, кінцевий стан буде чистіший». Без цієї рамки найкорисніший крок циклу гине першим.

**Не абстрагуй одразу наступну схожість.** Тільки-но ти розчепив хибне й відчув смак чистоти, око чіпляється за *інший* збіг — обидві функції ж кличуть `sendVia`, обидві звуть `time(at)`. Стоп. Це знову форма. Спитай ту саму річ, що вивела на формулу небезпеки: за цим збігом стоїть одна сила, яку бізнес міняє як одне ціле, — чи просто дві функції випадково вживають той самий примітив? `sendVia` спільний як *інструмент*, а не як *знання*; виносити тут нема чого. Розворот лікує хибну абстракцію, але сам не імунний до неї — наступна може вирости на першому ж кроці назад.

**Inline мусить бути повний.** Небезпечний проміжний стан — коли ти вклеїв тіло у два виклики, а третій ще кличе старий `notify`, і старий метод живе паралельно з новими функціями. Тепер поведінка розмазана по обох, і зміна в одному місці мовчки розходиться з іншим — та сама хвороба, тільки під час лікування. Розворот роби до кінця однією зміною: або всі виклики inline, або жоден; проміжного «наполовину» тримати не можна.

**Не кожен `if` — привід розчіплювати.** Дзеркальна помилка теж коштує: сплющити абстракцію, яка насправді *правильна*. Тест простий і той самий — на осі. Якщо розвилки форкають на **тип/дискримінатор** (`kind`, `type`, `isX`), а гілки не поділяють логіки — це майже завжди хибна абстракція, злита по формі, і її треба розчепити. Якщо ж параметр — чесна вісь **однієї** зв'язної операції (`retries`, `timeout`, `locale`), а тіло справді спільне — це нормальна параметризація, чіпати нема чого. `notify(kind)` форкав на тип, гілки не ділилися нічим — розчеплюємо. `dangerLevel(zone, now)` бере параметри однієї формули — лишаємо.

**Винос по силі може перетнути модулі — тоді думай про транзакцію знання.** Коли формула небезпеки переїжджає у власний модуль, три користувачі стають від нього залежні. Це правильно, але накладає обов'язок: міняти формулу тепер треба **сумісно** — стара й нова поведінка мають узгоджуватися між усіма трьома за один випуск, інакше ти повернеш ту саму розсинхронізацію, тільки вже між версіями. Єдине джерело правди економить на дублюванні знання рівно доти, доки ти справді тримаєш його єдиним і викочуєш як одне ціле.

Отже, що заробив цей цикл. Ми взяли метод, у який було *страшно* зазирати, і розібрали його на функції, кожну з яких видно наскрізь; знайшли справжню спільну силу, яка ховалася повз хибну; і замкнули правило небезпеки в одному місці, де його стереже один тест. Ціну ми теж тепер бачимо очима: вхід у хибну абстракцію коштував пів години на «злиймо близнюків», а вихід — цілого розвороту через inline, чистку й повторний винос. Саме цю нерівність і стискає формула Метц. Дублювання ти платиш дрібними монетами й бачиш кожну; хибну абстракцію — роками страху правити, і рахунок приходить тоді, коли платити найдорожче.
