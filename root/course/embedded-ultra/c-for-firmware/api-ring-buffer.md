# 📋 Інтерфейс статичного кільцевого буфера телеметрії

Цей довідник визначає програмний контракт, типи даних, вимоги до вирівнювання, математичні інваріанти, часову складність та правила безпечного доступу при роботі зі статичним кільцевим буфером у схемі «один виробник — один споживач» (Single-Producer Single-Consumer, SPSC) для вбудованих систем на мовах C та C++.

### Призначення та архітектурний контекст

У системах керування реального часу та бортовій телеметрії швидкість надходження інформації з фізичних інтерфейсів (UART, SPI, I2C, CAN) часто перевищує швидкість або регулярність її обробки головним алгоритмом. Апаратний обробник переривання (ISR) зобов'язаний зафіксувати вхідний байт за мінімальну кількість тактів процесора і негайно повернути керування, не виконуючи важких обчислень, розбору структури чи розрахунку контрольних сум.

Статичний кільцевий буфер виконує роль асинхронного моста між швидким апаратним перериванням та фоновим циклом обробки `super-loop`. Модуль гарантує повну відсутність динамічного виділення пам'яті (`malloc`/`free`), фіксований час виконання кожної операції `O(1)` та коректну роботу без взаємних блокувань і відключення переривань за умови дотримання контракту SPSC.

Буфер вирішує фундаментальну проблему розриву швидкостей: передавач може надсилати дані пачками (bursts) на високій швидкості, тоді як основний процесор може бути зайнятий періодичним розрахунком фільтра Калмана або записом журналу на Flash-носій. Накопичуючись у кільцевому масиві, байти безпечно чекають своєї черги на розбір без ризику втрати інформації.

### Математичний інваріант степеня двійки

Класична реалізація кільцевого буфера вимагає операції взяття залишку від ділення для повернення індексу на початок масиву після досягнення кінця: `next_index = (current_index + 1) % CAPACITY`.

На 32-бітних мікроконтролерах без апаратного дільника (наприклад, архітектура ARM Cortex-M0/M0+) інструкція ділення відсутня на рівні кремнію. Компілятор змушений генерувати виклик бібліотечної підпрограми програмної емуляції `__aeabi_uidiv`, яка виконує від 40 до 120 тактів процесора і використовує регістри загального призначення. Навіть на ядрах Cortex-M3/M4/M7, де присутня інструкція `UDIV`, операція займає від 2 до 12 тактів і не має фіксованого часу завершення.

Даний інтерфейс вимагає, щоб розмір буфера `CAPACITY` був строго цілим степенем двійки: `CAPACITY = 2^N`, де `N >= 1`. Для будь-якого числа `2^N` двійкове представлення складається з одиниці та `N` нулів, а число `MASK = CAPACITY - 1` складається рівно з `N` одиниць у молодших розрядах.

Математично доведено, що операція побітового множення `index & MASK` дає результат, абсолютно тотожний `index % CAPACITY` для будь-якого додатного цілого числа:

```
CAPACITY = 256  ->  Двійкове: 00000001 00000000
MASK     = 255  ->  Двійкове: 00000000 11111111

Якщо index = 255: (255 + 1) & 255 = 256 & 255 = 0 (миттєве повернення на початок)
```

Операція побітового `AND` транслюється в єдину процесорну інструкцію `ANDS` або `AND`, яка виконується рівно за **1 такт процесора** на будь-якому ядрі ARM, AVR чи RISC-V, забезпечуючи абсолютний детермінізм часу виконання в обробнику переривання.

### Специфікація полів структури даних

Пам'ять під структуру буфера виділяється статично у глобальній області (`.bss` або `.data`) або як статичне поле класу.

| Поле структури | Тип | Модифікатор | Опис призначення |
| :--- | :--- | :--- | :--- |
| `buffer` | `uint8_t[CAPACITY]` | — | Фізичний масив зберігання байтів даних у пам'яті SRAM. |
| `head` | `uint16_t` / `size_t` | `volatile` | Індекс запису (голова). Вказує на комірку, куди буде записано наступний новий байт. Модифікується **виключно виробником**. |
| `tail` | `uint16_t` / `size_t` | `volatile` | Індекс читання (хвіст). Вказує на найстаріший невичитаний байт. Модифікується **виключно споживачем**. |

### Зведена таблиця методів інтерфейсу

| Функція (C API) | Метод (C++ API) | Часова складність | Дозволено в ISR | Опис поведінки |
| :--- | :--- | :--- | :--- | :--- |
| `ring_buffer_init` | `clear()` | O(1) | Тільки до увімкнення переривань | Встановлює індекси `head = 0` та `tail = 0`. |
| `ring_buffer_put` | `push(item)` | O(1) [1 такт] | Так (Виробник) | Записує байт у буфер. Якщо буфер повний, повертає `false` без модифікації пам'яті. |
| `ring_buffer_get` | `pop()` | O(1) [1 такт] | Так (Споживач) | Вичитує байт і просуває `tail`. Якщо буфер порожній, повертає `false` / `std::nullopt`. |
| `ring_buffer_is_empty` | `empty()` | O(1) | Так (Обидва) | Повертає `true`, якщо `head == tail`. |
| `ring_buffer_is_full` | `full()` | O(1) | Так (Обидва) | Повертає `true`, якщо `((head + 1) & MASK) == tail`. |
| `ring_buffer_available` | `size()` | O(1) | Так (Обидва) | Обчислює кількість доступних байтів за формулою `(head - tail) & MASK`. |

### Специфікація заголовків та програмний код

:::tabs
```c
#ifndef STATIC_RING_BUFFER_H
#define STATIC_RING_BUFFER_H

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#ifdef __cplusplus
extern "C" {
#endif

// Конфігурація розміру буфера телеметрії (мусить бути 2^N)
#define RING_BUF_CAPACITY 256U
#define RING_BUF_MASK     (RING_BUF_CAPACITY - 1U)

_Static_assert((RING_BUF_CAPACITY & RING_BUF_MASK) == 0,
               "RING_BUF_CAPACITY must be a power of two!");

typedef struct {
    uint8_t buffer[RING_BUF_CAPACITY];
    volatile uint16_t head;
    volatile uint16_t tail;
} RingBuffer;

/**
 * @brief Ініціалізує кільцевий буфер перед початком роботи.
 * @param rb Покажчик на структуру буфера.
 */
void ring_buffer_init(RingBuffer *rb);

/**
 * @brief Додає байт у буфер. Безпечно для виклику з ISR виробника.
 * @param rb Покажчик на структуру буфера.
 * @param byte Значення байта.
 * @return true — байт збережено; false — буфер переповнено (дані відкинуто).
 */
bool ring_buffer_put(RingBuffer *rb, uint8_t byte);

/**
 * @brief Вичитує байт із буфера. Безпечно для виклику зі споживача.
 * @param rb Покажчик на структуру буфера.
 * @param byte Покажчик на вихідну змінну для збереження байта.
 * @return true — байт успішно вичитано; false — буфер порожній.
 */
bool ring_buffer_get(RingBuffer *rb, uint8_t *byte);

/**
 * @brief Перевіряє, чи буфер не містить даних.
 */
bool ring_buffer_is_empty(const RingBuffer *rb);

/**
 * @brief Перевіряє, чи заповнений буфер повністю.
 */
bool ring_buffer_is_full(const RingBuffer *rb);

/**
 * @brief Повертає поточну кількість байтів, готових до читання.
 */
uint16_t ring_buffer_available(const RingBuffer *rb);

#ifdef __cplusplus
}
#endif

#endif // STATIC_RING_BUFFER_H
```
```cpp
#ifndef STATIC_RING_BUFFER_HPP
#define STATIC_RING_BUFFER_HPP

#include <cstdint>
#include <cstddef>
#include <array>
#include <optional>
#include <span>

template <typename T, size_t Capacity>
class StaticRingBuffer {
    static_assert((Capacity > 1) && ((Capacity & (Capacity - 1)) == 0),
                  "Capacity must be a power of two greater than 1!");
public:
    using value_type = T;
    using size_type  = size_t;

    constexpr StaticRingBuffer() noexcept = default;

    /**
     * @brief Скидає індекси буфера до початкового стану.
     */
    void clear() noexcept {
        head_ = 0;
        tail_ = 0;
    }

    /**
     * @brief Додає елемент у буфер без блокування переривань.
     * @return true у разі успіху, false якщо буфер заповнений.
     */
    bool push(const T& item) noexcept {
        const size_type next_head = (head_ + 1U) & mask_;
        if (next_head == tail_) {
            return false;
        }
        buffer_[head_] = item;
        head_ = next_head;
        return true;
    }

    /**
     * @brief Вилучає елемент із буфера.
     * @return std::optional з елементом або std::nullopt, якщо буфер порожній.
     */
    [[nodiscard]] std::optional<T> pop() noexcept {
        if (empty()) {
            return std::nullopt;
        }
        T item = buffer_[tail_];
        tail_ = (tail_ + 1U) & mask_;
        return item;
    }

    [[nodiscard]] bool empty() const noexcept {
        return head_ == tail_;
    }

    [[nodiscard]] bool full() const noexcept {
        return ((head_ + 1U) & mask_) == tail_;
    }

    [[nodiscard]] size_type size() const noexcept {
        return (head_ - tail_) & mask_;
    }

    [[nodiscard]] constexpr size_type capacity() const noexcept {
        return Capacity - 1U; // Одна комірка резервується для розрізнення full/empty
    }

private:
    static constexpr size_type mask_ = Capacity - 1U;
    std::array<T, Capacity> buffer_{};
    volatile size_type head_{0};
    volatile size_type tail_{0};
};

#endif // STATIC_RING_BUFFER_HPP
```

### Правила безпеки та інваріанти паралелізму SPSC

Для коректної роботи без блокувань розробник зобов'язаний гарантувати дотримання чотирьох непорушних інваріантів:

1. **Суворе розділення ролей (Single-Producer Single-Consumer):**
   * Тільки одна сутність у системі (наприклад, переривання `USART1_IRQHandler`) має право викликати функцію запису `ring_buffer_put` / `push`.
   * Тільки одна сутність (наприклад, функція розбору телеметрії в `main()`) має право викликати функцію читання `ring_buffer_get` / `pop`.
   * Якщо в системі виникає потреба писати в буфер із кількох різних переривань або кількох потоків RTOS, ця структура **не підходить без додаткових м'ютексів чи вимкнення переривань**.

2. **Резервна комірка та корисна місткість:**
   * Буфер розміром `Capacity` здатний зберігати щонайбільше `Capacity - 1` елементів.
   * Коли `head == tail`, буфер вважається повністю порожнім.
   * Коли `((head + 1) & MASK) == tail`, буфер вважається повністю заповненим. Якби ми дозволили записати останній вільний елемент, `head` зрівнявся б із `tail`, і програма не змогла б відрізнити повний буфер від абсолютно порожнього.

3. **Атомарність оновлення індексів:**
   * Тип змінних `head` та `tail` обрано як `uint16_t` (або `uint32_t`), що гарантує оновлення індексу рівно за одну атомарну інструкцію запису процесора (`STRH` або `STR` в архітектурі ARM). Процесор не може бути перерваний посеред запису такого числа.
   * Оскільки виробник лише читає `tail`, а споживач лише читає `head`, навіть якщо переривання вклиниться в момент читання індексу, воно побачить або старе коректне значення, або нове коректне значення. Спотворення стану неможливе.

4. **Кеш-когерентність на ядрах Cortex-M7:**
   * Якщо мікроконтролер має увімкнений кеш даних (D-Cache), буфер обміну з апаратним модулем DMA повинен розташовуватися в некешованій області пам'яті (налаштованій через MPU) або вимагає явної інвалідації ліній кешу після читання/запису.
   * У системах зі складним конвеєром перед оновленням покажчика `head` рекомендується вставляти бар'єр пам'яті компілятора (`__asm__ volatile("" ::: "memory")`), щоб гарантувати, що запис байта в масив фізично передує оновленню індексу для споживача.

### Аналіз ресурсів та продуктивності

Використання статичного кільцевого буфера накладає мінімальні накладні витрати на систему:
* **Пам'ять SRAM:** Точно `CAPACITY + 4` байти (для 256-байтового буфера на 32-бітному ядрі це становить 260 байтів у секції `.bss`).
* **Пам'ять Flash:** Увесь скомпільований код функцій ініціалізації, запису та читання займає менше 120 байтів у секції `.text`.
* **Час виконання:** Операція запису байта в перериванні триває близько 6–8 машинних тактів (менше 100 наносекунд при тактовій частоті 72 МГц), що повністю виключає затримку обробки наступних апаратних подій.
* **Детермінізм:** Час виконання кожної функції суворо фіксований і не залежить від кількості накопичених даних у буфері, що є обов'язковою вимогою стандартів функціональної безпеки.
