# 📋 Регістрова карта та контракти бітових полів GPIO й базового таймера

Низькорівневе програмування периферії базується на строгому знанні адресної карти та функціонального призначення кожного біта в апаратних регістрах. Кожен апаратний модуль має власний набір регістрів, розташованих із фіксованими зміщеннями від базової адреси модуля на системній шині APB або AHB. Нижче наведено повну технічну специфікацію регістрових блоків порту виводу загального призначення (GPIO) та базового апаратного таймера (на базі мікроконтролерів архітектури ARM Cortex-M).

## Карта регістрів модуля GPIO (Базова адреса: 0x40020000 для Port A)

Модуль GPIO займає блок із десяти регістрів розрядністю 32 біти кожен, розміщених із фіксованим кроком у 4 байти (32 біти). Всі регістри підтримують 32-бітний атомарний доступ. Спроба виконання 8-бітного або 16-бітного запису на шині APB може призводити до невизначеної поведінки або апаратного винятку шини залежно від реалізації конкретного чипа.

| Зміщення (Offset) | Назва регістра | Опис регістра | Доступ | Значення після скидання |
|---|---|---|---|---|
| `+0x00` | `MODER` | Режим роботи виводів (In/Out/Alternate/Analog) | RW | `0xA8000000` (PA15–PA13 JTAG) |
| `+0x04` | `OTYPER` | Тип виходу (Push-Pull / Open-Drain) | RW | `0x00000000` |
| `+0x08` | `OSPEEDR` | Швидкість наростання фронту вихідного сигналу | RW | `0x00000000` |
| `+0x0C` | `PUPDR` | Керування внутрішніми підтяжками Pull-Up / Pull-Down | RW | `0x64000000` |
| `+0x10` | `IDR` | Регістр вхідних даних фізичних ліній | RO | Стан виводів кристала |
| `+0x14` | `ODR` | Регістр вихідних засувок даних | RW | `0x00000000` |
| `+0x18` | `BSRR` | Атомарне встановлення та скидання бітів | WO | `0x00000000` |
| `+0x1C` | `LCKR` | Регістр апаратного блокування конфігурації | RW | `0x00000000` |
| `+0x20` | `AFRL` | Вибір альтернативної функції для пінів 0–7 | RW | `0x00000000` |
| `+0x24` | `AFRH` | Вибір альтернативної функції для пінів 8–15 | RW | `0x00000000` |

### Деталізація бітових полів регістра GPIOx_MODER

Регістр `MODER` визначає базовий режим роботи кожного з 16 виводів порту. Регістр виділяє рівно 2 біти на кожен фізичний пін (`MODER[2y+1 : 2y]`, де `y` — номер піна від 0 до 15).

Кожна двобітна комбінація задає наступну конфігурацію:
* `00` — **Режим цифрового входу (Input mode)**. Вихідні польові транзистори повністю закриті й перебувають у високоімпедансному стані (Hi-Z). Вхідний тригер Шмітта підключений до лінії, його вихід фіксується у відповідному біті регістра `IDR` на кожному такті шини APB.
* `01` — **Режим цифрового виходу загального призначення (General purpose output mode)**. Вихідний драйвер активний і керується вмістом засувки регістра `ODR`. Вхідний тригер Шмітта залишається активним, тому читання регістра `IDR` повертає реальний електричний стан на ніжці.
* `10` — **Режим альтернативної функції (Alternate function mode)**. Керування ніжкою передається спеціалізованому периферійному модулю (передавачу UART, тактовій лінії SPI, каналу ШІМ таймера). Конкретна периферія вибирається записами у регістри `AFRL` та `AFRH`.
* `11` — **Аналоговий режим (Analog mode)**. Вхідний тригер Шмітта повністю знеструмлюється для усунення паразитного наскрізного струму при проходженні вхідного сигналу через зону невизначеної напруги. Вивід напряму з'єднується з внутрішнім мультиплексором АЦП чи ЦАП.

### Деталізація бітових полів регістра GPIOx_OTYPER (Output Type)

Регістр конфігурує схемотехніку вихідного каскаду для кожного виводу (1 біт на пін у позиціях `[15:0]`; старші біти `[31:16]` зарезервовані):
* Біт `0` — **Двотактний вихід (Push-Pull)**. Працюють обидва комплементарні транзистори: верхній P-MOSFET підтягує вивід до напруги живлення `VDD`, а нижній N-MOSFET притискає до землі `VSS`. Забезпечує симетричні та швидкі фронти наростання й спаду сигналу.
* Біт `1` — **Відкритий стік (Open-Drain)**. Верхній P-MOSFET апаратно відімкнений. Логічна «1» переводить вивід у плаваючий стан (Hi-Z), а логічний «0» відкриває нижній N-MOSFET на землю. Режим обов'язковий для шин із багатьма передавачами (наприклад, шина I²C) та для узгодження логічних рівнів за наявності зовнішнього підтягуючого резистора.

### Деталізація бітових полів регістра GPIOx_BSRR (Bit Set/Reset Register)

Регістр `BSRR` розроблений виключно для атомарного керування станом вихідних засувок без необхідності виконання операцій читання–модифікації–запису (RMW). Регістр є односпрямованим (лише для запису):

* Молодша половина `[15:0]` — **BSy (Bit Set y)**:
  * Запис `1` у біт `y`: встановлює біт `y` регістра `ODR` у логічну `1` (на виводі з'являється високий рівень).
  * Запис `0` у біт `y`: не виконує жодної дії над апаратним тригером.
* Старша половина `[31:16]` — **BRy (Bit Reset y)**:
  * Запис `1` у біт `y + 16`: скидає біт `y` регістра `ODR` у логічний `0` (на виводі з'являється низький рівень).
  * Запис `0` у біт `y + 16`: не виконує жодної дії над апаратним тригером.
* Якщо у програмному коді через помилку одночасно записано `1` в обидва біти `BSy` і `BRy` одного й того самого виводу, апаратний пріоритет має операція встановлення `BSy`.

## Карта регістрів базового таймера (Базова адреса: 0x40001000 для TIM6)

Базові таймери (наприклад, TIM6 та TIM7) є 16-бітними лічильниками, призначеними для точного вимірювання часових інтервалів, періодичного виклику переривань та апаратного запуску перетворень ЦАП без навантаження процесора.

| Зміщення | Назва | Опис регістра | Доступ | Розрядність |
|---|---|---|---|---|
| `+0x00` | `CR1` | Регістр керування 1 (Control Register 1) | RW | 16 бітів |
| `+0x04` | `CR2` | Регістр керування 2 (керування тригером TRGO) | RW | 16 бітів |
| `+0x0C` | `DIER` | Дозвіл переривань та запитів DMA | RW | 16 бітів |
| `+0x10` | `SR` | Регістр статусу (Status Register) | `rc_w0` / `rc_w1` | 16 бітів |
| `+0x14` | `EGR` | Регістр примусової генерації подій (Event Generation) | WO | 16 бітів |
| `+0x24` | `CNT` | Поточне значення лічильника (Counter) | RW | 16 бітів |
| `+0x28` | `PSC` | Дільник частоти (Prescaler) | RW | 16 бітів |
| `+0x2C` | `ARR` | Регістр автоперезавантаження (Auto-Reload Register) | RW | 16 бітів |

### Бітові прапорці регістра керування TIMx_CR1

Регістр `CR1` визначає базовий життєвий цикл таймера та його реакцію на переповнення:
* Біт `0` — **`CEN` (Counter Enable)**:
  * `0`: Рахунок зупинено. Лічильник `CNT` зберігає свій поточний стан, але не інкрементується.
  * `1`: Лічильник увімкнено. Кожен тактовий імпульс після дільника `PSC` збільшує значення `CNT` на одиницю.
* Біт `1` — **`UDIS` (Update Disable)**:
  * `0`: Генерація подій оновлення (Update Event, UEV) дозволена. Подія виникає при переповненні лічильника або записі в регістр `EGR`.
  * `1`: Події оновлення заборонені. Тіньові регістри не оновлюються, що дозволяє безпечно змінювати кілька пов'язаних параметрів таймера.
* Біт `2` — **`URS` (Update Request Source)**:
  * `0`: Будь-яка подія (переповнення лічильника, скидання або програмний запис у `EGR`) генерує запит на переривання чи DMA.
  * `1`: Лише фізичне переповнення лічильника `CNT` генерує запит на переривання, що запобігає хибним спрацьовуванням переривання під час первинної ініціалізації.
* Біт `3` — **`OPM` (One-Pulse Mode)**:
  * `0`: Таймер працює в неперервному циклічному режимі.
  * `1`: Однократний режим: при виникненні першої ж події оновлення біт `CEN` автоматично скидається в `0` апаратурою.
* Біт `7` — **`ARPE` (Auto-Reload Preload Enable)**:
  * `0`: Запис нового числа в регістр `ARR` негайно змінює активну межу рахунку.
  * `1`: Регістр `ARR` буферизується через тіньовий регістр. Нове значення набуває чинності лише після завершення поточного циклу рахунку.

### Регістр статусу TIMx_SR та обробка прапорців

* Біт `0` — **`UIF` (Update Interrupt Flag)**:
  * Апаратно встановлюється в `1`, коли значення лічильника `CNT` досягає порогу `ARR` і скидається в `0`.
  * Якщо в регістрі `DIER` виставлено біт `UIE` (Update Interrupt Enable), встановлення `UIF` негайно активує лінію переривання таймера в контролері переривань NVIC.
  * Для скидання прапорця програмний код записує `0` або виконує читання залежно від моделі регістра.
