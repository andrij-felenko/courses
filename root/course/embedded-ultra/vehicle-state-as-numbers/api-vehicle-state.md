# 📋 Інтерфейс та структури даних навігаційного стану апарата

Довідник інтерфейсу модуля стану визначає бінарне розміщення структур у пам'яті, конвенції одиниць вимірювання, числові інваріанти та прототипи функцій оцінювача стану. Цей модуль є ядром навігаційного стека польотного контролера і взаємодіє з драйверами сенсорів IMU/GNSS та виконавчими регуляторами мотора.

Архітектура інтерфейсу базується на принципі суворої типізації, відсутності прихованого стану всередині бібліотеки та гарантії потокобезпеки під час обміну даними між перериваннями апаратних таймерів і низькопріоритетними задачами операційної системи.

Модуль надає прямий інтерфейс для швидких контурів стабілізації, де кожна наносекунда затримки впливає на стійкість польоту. Усі функції API спроектовані як реентрабельні (Reentrant) чисті процедури, що не мають статичних буферів і приймають покажчики на структури явно.

### Життєвий цикл стану апарата

Обчислювальний конвеєр польотного контролера переводить навігаційний стан через декілька дискретних фаз готовності:
1. **Неініціалізований стан (Uninitialized)**: пам'ять структури скинута в нуль, орієнтація заповнена одиничним кватерніоном `[1, 0, 0, 0]`, прапорці валідності сенсорів скинуті.
2. **Калібрування на землі (Calibrating)**: протягом перших 2–5 секунд після подачі живлення дрон стоїть нерухомо; алгоритм накопичує вибірку кутових швидкостей для оцінки зміщення нуля гіроскопа `b_g` та вирівнює вектор орієнтації за статичним вектором сили тяжіння `g`.
3. **Готовність орієнтації (Attitude Valid)**: гіроскопи відкалібровані, кватерніон `q` коректно відображає нахил корпусу відносно горизонту; дозволено запуск моторів у ручних режимах стабілізації (Acro/Angle).
4. **Повна навігаційна готовність (Navigation Ready)**: отримано стабільні координати від супутникового модуля GNSS та барометра, дрейф швидкостей усунуто; автопілот дозволяє автономні місії та повернення додому.

### Вимоги до когерентності пам'яті для DMA та кешу (Cortex-M7 / Cortex-A)

На високопродуктивних мікроконтролерах із розділеними кешами інструкцій та даних (I-Cache та D-Cache, наприклад STM32H7, i.MX RT) апаратний контролер DMA записує байти з SPI-шини сенсорів безпосередньо в оперативну пам'ять (AXI SRAM), оминаючи кеш процесора. Якщо структура стану розміщена у звичайній пам'яті з увімкненим Write-Back кешуванням, процесор зчитуватиме застарілі значення з D-Cache замість щойно прийнятих сенсорних вимірів.

Для забезпечення повної апаратної узгодженості даних без накладних витрат на регулярну програмну інвалідацію кешу (`SCB_InvalidateDCache_by_Addr`), структури буферів сенсорів та вектор стану розміщують у спеціальній некешованій області пам'яті. Ця область налаштовується через блок захисту пам'яті MPU (Memory Protection Unit) як `Non-Cacheable, Normal Memory` або виділяється у внутрішній пам'яті DTCM (Data Tightly-Coupled Memory), яка фізично підключена безпосередньо до ядра процесора без проміжних кеш-буферів.

### Конвенції координат та одиниць вимірювання

Усі фізичні величини у структурі стану строго виражаються в міжнародній системі одиниць SI та кутових радіанах:

| Параметр | Позначення | Система координат | Одиниці | Діапазон |
|---|---|---|---|---|
| Позиція X/Y | `p_N, p_E` | Earth NED | метри (`m`) | `[-100000.0, 100000.0]` |
| Висота Z | `p_D` | Earth NED (`p_D = -h`) | метри (`m`) | `[-10000.0, 1000.0]` |
| Лінійна швидкість | `v_N, v_E, v_D` | Earth NED | м/с (`m/s`) | `[-150.0, 150.0]` |
| Орієнтація | `q_w, q_x, q_y, q_z` | Body -> NED | безрозмірний | `q_w² + q_x² + q_y² + q_z² = 1` |
| Кутова швидкість | `p, q, r` | Body Frame | рад/с (`rad/s`) | `[-35.0, 35.0]` (до 2000 °/с) |
| Перевантаження | `a_x, a_y, a_z` | Body Frame | м/с² (`m/s²`) | `[-160.0, 160.0]` (до 16g) |
| Зміщення гіроскопа | `b_gx, b_gy, b_gz` | Body Frame | рад/с (`rad/s`) | `[-0.2, 0.2]` |
| Зміщення акселерометра | `b_ax, b_ay, b_az` | Body Frame | м/с² (`m/s²`) | `[-2.0, 2.0]` |

### Числові та фізичні інваріанти структури

Для гарантування математичної стійкості навігаційного фільтра всі поля структури стану зобов'язані задовольняти суворим системним інваріантам під час кожного такту оновлення:
* **Інваріант унітарності кватерніона**: евклідова норма кватерніона орієнтації повинна задовольняти умову `|q_w² + q_x² + q_y² + q_z² - 1.0| < 1e-3`. Якщо внаслідок накопичення похибок дискретизації норма відхиляється від одиниці більше ніж на `0.1%`, викликається примусова перенормалізація або фіксується внутрішнє попередження оцінювача.
* **Інваріант фізичної реалістичності динаміки**: модуль швидкості не може перевищувати конструктивну межу апарата `|v_ned| < 150.0 м/с`, а виміряне перевантаження має перебувати в межах шкали акселерометра `|a_b| < 160.0 м/с²`. Вихід за ці межі свідчить про апаратну відмову сенсора або удар планера.
* **Узгодженість базисів**: вектор орієнтації пов'язує праву зв'язану систему координат корпусу Body (FRD: Forward — X вперед, Right — Y праворуч, Down — Z вниз) із локальною геодезичною системою Earth NED (North — X на північ, East — Y на схід, Down — Z до центру Землі).

### Потокобезпека та lock-free читання

Оскільки оновлення стану виконується всередині високопріоритетного переривання таймера або драйвера SPI IMU (1000 Гц), а зчитування стану здійснюється низькопріоритетними задачами навігації (100 Гц) та телеметрії (20–50 Гц), прямий доступ до пам'яті структури без синхронізації призведе до розриву даних (Torn Read), коли частина полів оновлена, а частина належить попередньому кроку.

Для забезпечення детерміністичної роботи без використання важких блокувань (Mutex) у прошивках застосовують механізм **Seqlock** (Sequence Lock) або подвійну буферизацію (Double Buffering):

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    volatile uint32_t sequence;
    vehicle_state_t   state;
} seqlock_vehicle_state_t;

// Читання стану у фоновому потоці телеметрії
bool vehicle_state_read_atomic(const seqlock_vehicle_state_t *seq, vehicle_state_t *out) {
    uint32_t s1, s2;
    uint32_t retries = 0;
    do {
        s1 = seq->sequence;
        if (s1 & 1) { // Запис у процесі (непарне число)
            continue;
        }
        *out = seq->state;
        s2 = seq->sequence;
        retries++;
        if (retries > 10) return false;
    } while (s1 != s2 || (s1 & 1));
    return true;
}
```
```cpp
#include <cstdint>
#include <atomic>
#include <optional>

struct SeqlockVehicleState {
    std::atomic<uint32_t> sequence{0};
    VehicleState          state{};

    // Атомарне зчитування стану без блокування потоку
    [[nodiscard]] std::optional<VehicleState> read_atomic() const noexcept {
        for (uint32_t retries = 0; retries < 10; ++retries) {
            const uint32_t s1 = sequence.load(std::memory_order_acquire);
            if (s1 & 1U) {
                continue; // Запис у процесі
            }
            const VehicleState snapshot = state;
            const uint32_t s2 = sequence.load(std::memory_order_acquire);
            if (s1 == s2 && !(s1 & 1U)) {
                return snapshot;
            }
        }
        return std::nullopt; // Перевищено кількість спроб через високу активність запису
    }
};
```

### Діагностика та обробка виняткових станів

Для контролю коректності оцінки навігаційного стану модуль підтримує бітову маску прапорців діагностики:
* `STATUS_FLAG_ATTITUDE_CONVERGED` (біт 0): вектор орієнтації зійшовся за статичним вектором гравітації, коваріація оцінки кута опустилася нижче порогового значення 0.05 рад.
* `STATUS_FLAG_VELOCITY_VALID` (біт 1): швидкість підтверджена даними GNSS або оптичного потоку, що унеможливлює неконтрольований розгін інтегратора.
* `STATUS_FLAG_POSITION_VALID` (біт 2): координати зафіксовані з горизонтальною похибкою менше 2.5 м (3D-Fix із показником HDOP < 2.0).
* `STATUS_FLAG_SENSOR_TIMEOUT` (біт 3): сторожовий таймер зафіксував пропуск вибірки з шини SPI IMU тривалістю понад 5 мілісекунд.
* `STATUS_FLAG_IMU_CLIPPING` (біт 4): виявлено насичення шкали вимірювання акселерометра чи гіроскопа внаслідок сильного удару або вібрацій рами.
* `STATUS_FLAG_DEGRADED_MODE` (біт 5): перехід оцінювача в автономний режим числення координат за одометрією (Dead Reckoning) при втраті супутників.
* `STATUS_FLAG_NAN_DETECTED` (біт 6): виявлено некоректне значення `NaN` або `Inf` у полях стану.

У разі підняття прапорця `STATUS_FLAG_NAN_DETECTED` алгоритм негайно блокує видачу вихідних сигналів на мотори, повертає дефолтний кватерніон `[1, 0, 0, 0]` та ініціює процедуру безпечного аварійного спуску (Failsafe Landing).

### Крайові випадки при нормалізації кватерніона

Обчислення евклідової норми кватерніона `norm = sqrtf(w² + x² + y² + z²)` містить приховану загрозу генерації апаратних винятків ділення на нуль:
* **Нульовий вектор стану**: якщо через збій живлення або помилку ініціалізації всі 4 компоненти кватерніона виявляються нульовими, сума квадратів дорівнює строго `0.0f`. Пряме ділення `1.0f / sqrtf(0.0f)` на апаратному FPU Cortex-M4 генерує значення `+Inf`, яке під час наступного кроку множення перетворюється на руйнівний `NaN`.
* **Захисний поріг відсікання**: умова `if (norm_sq < 1e-12f)` надійно перехоплює як чистий нуль, так і надмалі денормалізовані числа, повертаючи нейтральний одиничний кватерніон `[1, 0, 0, 0]`.
* **Переповнення розрядної сітки**: у разі виникнення значень компонентів, що перевищують `1e19f`, сума квадратів переповнює діапазон `float` у `+Inf`. Захисна перевірка гарантує повернення дефолтної орієнтації без зависання алгоритму.

### Часові мітки та синхронізація

Кожна структура стану обов'язково супроводжується монотонною часовою міткою `timestamp_us` (64-бітне ціле число мікросекунд від моменту старту системи):
* **Захист від переповнення**: 32-бітний мілісекундний таймер переповнюється через 49.7 діб, а 32-бітний мікросекундний лічильник — уже через 71.5 хвилини. Використання `uint64_t` усуває проблему розриву шкали часу під час тривалих польотів.
* **Компенсація затримки сенсорів (Group Delay)**: цифрові фільтри всередині мікросхеми IMU вносять затримку вибірки 1.5–3.0 мс. Оцінювач стану використовує точну дельту часу `dt` між фізичним моментом вимірювання та поточним тактом інтегрування для ретроспективної корекції вектора стану.

### Контракти безпеки функцій C API

#### `void vehicle_state_init(vehicle_state_t *state)`
* **Призначення**: ініціалізація структури стану нульовими векторами та одиничним кватерніоном `[1, 0, 0, 0]`.
* **Передумови**: покажчик `state != NULL`.
* **Післяумови**: кватерніон орієнтації строго нормований, усі швидкості та зміщення дорівнюють нулю.
* **Часова складність**: `O(1)`, 22 операції запису.

#### `quat_t quat_normalize(quat_t q)`
* **Призначення**: відновлення одиничної норми кватерніона `|q| = 1`.
* **Математичний контракт**: якщо `|q|² < 10⁻¹²`, повертає дефолтний кватерніон `[1, 0, 0, 0]`.
* **Обчислювальні витрати**: 4 множення, 3 додавання, 1 квадратний корінь `sqrtf`, 4 множення на обернену норму.

#### `quat_t quat_integrate_rk2(quat_t q, vec3_t omega, float dt)`
* **Призначення**: чисельне інтегрування орієнтації методом Рунге-Кутти 2-го порядку.
* **Вхідні параметри та контракти**:
  * `q`: поточна орієнтація (має бути нормованим кватерніоном).
  * `omega`: вектор кутової швидкості (рад/с, не містить `NaN` чи `Inf`).
  * `dt`: часовий інтервал інтегрування (секунди, `0.0f < dt < 0.1f`).
* **Похибка дискретизації**: `O(dt²)`.

#### `vec3_t quat_rotate_body_to_ned(quat_t q, vec3_t v)`
* **Призначення**: поворот вектора `v` зі зв'язаної системи координат `B` у земну систему `NED` через формулу Родрігеса.
* **Обчислювальні витрати**: 15 множень, 10 додавань, 0 викликів тригонометричних функцій.

#### `euler_t quat_to_euler_angles(quat_t q)`
* **Призначення**: видобування кутів Ейлера Тейта-Браяна (Roll, Pitch, Yaw) для телеметрії.
* **Гарантія безпеки**: обов'язкове внутрішнє відтинання `clamp(sin_pitch, -1.0f, 1.0f)` для гарантування відсутності `NaN`.

### Серіалізація стану для протоколів телеметрії MAVLink

Структура стану `vehicle_state_t` є джерелом даних для стандартних протоколів телеметрії (MAVLink v2, MSP, UAVCAN). При пакуванні повідомлення `ATTITUDE` (повідомлення ID #30) та `LOCAL_POSITION_NED` (повідомлення ID #32) виконується приведення типів та масштабування:
* `roll`, `pitch`, `yaw`: передаються як 32-бітні числа `float` у радіанах.
* `x`, `y`, `z`: локальні координати NED у метрах.
* `vx`, `vy`, `vz`: лінійні швидкості в метрах за секунду.
* Часова мітка `time_boot_ms`: 32-бітне ціле без знаку (мілісекунди від старту таймера мікроконтролера).

Завдяки прямій відповідності системи координат NED стандарту MAVLink, автопілот уникає проміжних поворотних перетворень перед відправкою пакетів по радіомодему або UART.
