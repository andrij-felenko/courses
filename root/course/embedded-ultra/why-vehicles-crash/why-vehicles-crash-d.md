- [Failsafe](root:sys-dron/failsafe) — принципи побудови аварійних режимів автопілота при втраті радіозв'язку та відмові навігації.
</preknowlist>

Квадрокоптер масою 2.4 кг виконує різкий розворот на швидкості 22 м/с. На третьому силовому плечі транзисторний міст регулятора швидкості зазнає збою детекції фази, через що обертове магнітне поле статора розсинхронізується з ротором двигуна. Тяга третього пропелера миттєво зникає. За 15 мілісекунд кутова швидкість обертання рами за креном досягає 380 градусів на секунду. Пропорційно-диференціальний регулятор польотного контролера намагається компенсувати катастрофічний крен і видає команду максимального струму на діагональний мотор. Струм батареї стрибає з 35 А до 110 А. Внутрішній опір підсистеми живлення `R_int = 32 мОм` створює миттєве просідання напруги `ΔV = I · R_int = 3.52 В`. Імпульсний стабілізатор 5 В переходить у режим зриву стабілізації, напруга живлення мікроконтролера опускається нижче 2.7 В, і вбудований детектор напруги виконує апаратне перезавантаження процесора. Апарат падає на землю за некерованою балістичною траєкторією задовго до того, як мікроконтролер завершить ініціалізацію тактової частоти.

Цей сценарій демонструє фундаментальну природу аварій складних безпілотних систем: падіння майже ніколи не є наслідком ізольованого виходу з ладу одного компонента. Воно розгортається як стрімкий каскадний процес, у якому первинне збурення в одному фізичному домені перевантажує суміжні підсистеми, викликає ланцюгову реакцію насичення сигналів і завершується повною втратою керованості.

## Механічний та аеродинамічний домен: межі міцності та динаміки

Механічна конструкція безпілотного апарата є першою лінією взаємодії з навколишнім середовищем. Будь-яке порушення геометрії або цілісності рушіїв генерує сили, здатні миттєво вивести систему за межі діапазону регулювання.

### Руйнування та зрив лопатей гвинта

Повітряний гвинт обертається з частотою від 5 000 до 35 000 обертів на хвилину. На кінці лопаті діаметром 10 дюймів лінійна швидкість сягає `v = ω · r ≈ 230 м/с`, що становить близько 0.7 швидкості звуку. Відцентрова сила, яка діє на масу лопаті всього 4 грами на радіусі 100 мм при 20 000 об/хв, розраховується за формулою:

```
F_c
= m · ω² · r                          [формула: відцентрова сила обертання]
= 0.004 кг · (20000 · 2π / 60)² · 0.1 м [підстановка параметрів лопаті]
= 0.004 · (2094.4)² · 0.1              [розрахунок кутової швидкості]
≈ 1754 Н (еквівалент 178 кгс)          [статичне розривне навантаження]
```

Мікротріщина у пластику або втомне розшарування вуглепластику призводить до миттєвого відриву лопаті. Наслідки мають подвійний характер:
1. **Миттєве зникнення аеродинамічної тяги:** Підйомна сила плеча падає до нуля за час менше одного оберту (менше 3 мс).
2. **Величезний динамічний дисбаланс:** Залишок другої лопаті створює радіальну вібраційну силу понад 1700 Н, яка передається на підшипники двигуна та карбоновий промінь. Вібрація з частотою обертання зрізає кріпильні гвинти, вносить непереборний шум у кристали сенсорів та призводить до механічного руйнування рами за лічені частки секунди.

### Гіроскопічна прецесія та згинальні моменти вала мотора

Коли безпілотний апарат виконує різкий маневр за курсом (*Yaw*) з кутовою швидкістю `Ω = 800 град/с ≈ 14 рад/с`, швидкообертовий пропелер із моментом інерції `I_prop ≈ 2.5 · 10⁻⁵ кг·м²` та швидкістю обертання `ω = 2200 рад/с` починає поводитися як класичний гіроскоп.

Виникає гіроскопічний момент прецесії, спрямований перпендикулярно до осі обертання:

```
M_gyro
= I_prop · ω · Ω                       [формула гіроскопічного моменту]
= (2.5 · 10⁻⁵ кг·м²) · 2200 рад/с · 14 рад/с [підстановка параметрів гвинта]
≈ 0.77 Н·м                             [згинальний момент на валу мотора]
```

Для тонкого сталевого вала двигуна діаметром 3–4 мм із плечем 15 мм такий момент створює радіальну силу згину понад 50 Н. Це призводить до пружної мікродеформації колокола ротора, через що постійні неодимові магніти торкаються статора (*rotor rub*). Тертя металу об метал викликає миттєвий локальний перегрів, заклинювання підшипників та електричне замикання обмоток.

### Режим вихрового кільця (Vortex Ring State)

При стрімкому вертикальному зниженні зі швидкістю `v_z > 0.7 · v_induced` (де `v_induced` — індукована швидкість потоку крізь площину гвинта) виникає небезпечне аеродинамічне явище — **режим вихрового кільця** (*Vortex Ring State*, VRS).

Пропелер потрапляє у власний спутний струмінь повітря, що рухається вниз. Замість формування спрямованого відкидання маси повітря навколо лопатей утворюється замкнений тороїдальний вихор. У цьому режимі:
* Ефективна тяга гвинта стохастично коливається з амплітудою до ±40%.
* Апарат зазнає неконтрольованого розгойдування (*wobble of death*).
* Намагання пілота чи автопілота зупинити падіння простим збільшенням тяги лише посилює циркуляцію вихору, збільшуючи швидкість падіння.

Єдиним виходом із VRS є надання апарату горизонтальної швидкості для виходу з власного спутного потоку.

### Зрив синхронізації безколекторних регуляторів (ESC Desync)

В авіаційних безколекторних двигунах постійного струму (BLDC) обертове магнітне поле формується електронним регулятором швидкості (ESC, *Electronic Speed Controller*). Безсенсорні регулятори визначають положення магнітів ротора за наведеною протиелектрорушійною силою (проти-ЕРС, *Back-EMF*) на відключеній у цей момент обмотці статора.

Коли польотний контролер видає команду різкого наростання тяги (стрибок шпаруватості ШІМ від 20% до 100% за 1 мс), виникає явище **десинхронізації** (*desynchronization*, від латинського *de-* — роз'єднання, та грецького *synchronos* — одночасний):
* Висока швидкість зміни струму `di/dt` створює тривалий сплеск струму розмагнічування через індуктивність обмотки `L · (di/dt)`.
* Цей індуктивний викид засліплює аналоговий компаратор нульового перетину напруги (*zero-crossing detector*).
* Прошивка регулятора пропускає фазовий перехід і вмикає чергову пару силових транзисторів невчасно — коли магнітне поле статора протидіє руху ротора.

Замість обертання двигун зазнає потужного електромагнітного гальмування, струм зростає до рівня короткого замикання, силові ключі розігріваються, а ефективна тяга падає до нуля. Детальний аналіз напівпровідникового моста та методів боротьби з цим явищем наведено у вставці [Регулятори швидкості BLDC: комутація та desync](root:embedded-ultra/why-vehicles-crash/comp-bldc-esc-telemetry.md).

## Електричний та енергетичний домен: шини живлення та перехідні процеси

Електрична мережа безпілотного апарата є високодинамічним середовищем із паразитними індуктивностями, різкими стрибками споживання та високовольтними шумами комутації.

```
       +BAT (25.2 В) ────[Головний силовий кабель L_wire]────┬───── До силових ESC (100 А)
                                                              │
                                                     [Buck-стабілізатор 5 В]
                                                              │
                                                     [LDO-регулятор 3.3 В]
                                                              │
                                                     [MCU: ядро і FLASH]
```

### Динамічне просідання напруги (Battery Sag)

Літій-полімерна (LiPo) або літій-іонна батарея не є ідеальним джерелом напруги. Її реальна поведінка описується еквівалентною схемою з електрорушійною силою `E_cell` та внутрішнім активним опором `R_int`.

Напруга на клемах батареї під навантаженням розраховується як:

```
V_term(t)
= E_cell(SOC) - I(t) · R_int - L_wire · (dI/dt)  [напруга під навантаженням]
```

Де:
* `E_cell(SOC)` — напруга розімкненого кола, що залежить від ступеня заряду (*State of Charge*).
* `I(t) · R_int` — статичне падіння напруги на внутрішньому хімічному опорі комірок та контактних з'єднаннях.
* `L_wire · (dI/dt)` — динамічне індуктивне падіння напруги на силових кабелях від акумулятора до розподільчої плати.

Коли акумулятор розряджений на 80%, його опір `R_int` зростає у 2–3 рази через збіднення електроліту. При маневрі ухилення або боротьбі з поривом вітру сумарний струм чотирьох або восьми моторів може досягати 120 А. Якщо `R_int = 40 мОм`, падіння напруги на самій батареї становить:

```
ΔV_sag
= 120 А · 0.040 Ом                    [розрахунок падіння напруги]
= 4.80 В                              [глибина просідання силової шини]
```

Для 4S LiPo батареї з номінальною напругою 14.8 В (3.7 В на банку) миттєва напруга просідає до `14.8 - 4.8 = 10.0 В` (2.5 В на банку), що викликає лавинний перехід лінійних або імпульсних стабілізаторів у режим відмови.

### Апаратне скидання MCU (Brownout Reset)

Мікроконтролер польотного контролера живиться напругою 3.3 В через каскад вторинних перетворювачів. Коли вхідна напруга 5V-стабілізатора падає нижче його мінімальної робочої межі (*dropout voltage*), напруга 3.3V шини починає стрімко знижуватися.

У мікроконтролерах вбудовано спеціальний апаратний блок моніторингу напруги — **детектор просідання** (англ. *Brownout Detector*, BOD, або *Brownout Reset*, BOR; назва походить від англійського *brownout* — часткове падіння напруги в електромережі, коли лампи розжарювання світять тьмяним коричневим світлом).

```
3.3 В ────┐
          │  [Нормальна робота ядра]
2.7 В ────┼───────────────────────── [Поріг спрацьовування BOR Level 3]
          │  \                      /
          │   \── [Скидання MCU] ──/
0.0 В ────┴───────────────────────────────────────────> Час
```

Якщо напруга опускається нижче апаратного порогу (наприклад, 2.7 В у лінійці STM32), логічні елементи Flash-пам'яті та регістрів починають видавати непередбачувані бітові помилки. Щоб запобігти виконанню сміттєвих інструкцій, схема BOR примусово затягує процесор у стан апаратного скидання. Спроба відновлення займає від 15 до 50 мілісекунд (заряд ємностей, стабілізація тактового генератора HSE, виконання системного завантажувача). Для апарата, що перебуває в повітрі, 50 мс без активного контуру стабілізації означає невідворотне перекидання.

### Індуктивні викиди та зсув потенціалу землі (Ground Bounce)

Довгі дроти від акумулятора до регуляторів швидкості мають розподілену індуктивність `L_wire ≈ 1 мкГн/м`. При високочастотній ШІМ-комутації транзисторів зі швидкістю зміни струму `dI/dt = 50 А / 100 нс = 5 · 10⁸ А/с` на шині виникають паразитні імпульси самоіндукції:

```
V_spike
= L_wire · (dI/dt)                     [формула індуктивного викиду]
= 10⁻⁶ Гн · (5 · 10⁸ А/с)              [підстановка параметрів]
= 500 В                                [теоретичний пік напруги комутації]
```

Реальні супресори (TVS-діоди) та керамічні конденсатори зрізають цей пік, проте залишковий імпульс амплітудою 35–50 В пробиває ізоляцію слаботочних інтерфейсів. Крім того, протікання зворотного силового струму через спільну мідну площину викликає явище **зсуву потенціалу землі** (*Ground Bounce*). Сигнальна земля сенсора опиняється під потенціалом +0.8 В відносно землі мікроконтролера, що призводить до спотворення логічних рівнів шин SPI та UART і породжує фатальні помилки контрольних сум або зависання транзакцій.

### Теплове старіння конденсаторів та пульсації струму (Ripple Current)

Електролітичні конденсатори, встановлені паралельно вхідній лінії ESC, виконують роль локальних резервуарів енергії, що згладжують високочастотні імпульси струму споживання.

Через конденсатор щомиті протікає високочастотний змінний струм пульсацій `I_ripple = 15–30 А RMS`. Теплові втрати всередині конденсатора визначаються його еквівалентним послідовним опором (ESR, *Equivalent Series Resistance*):

```
P_loss = I_ripple² · ESR
```

Якщо на платі встановлено звичайні загальнопромислові конденсатори з високим `ESR ≈ 150 мОм` замість спеціалізованих низькоімпедансних (*Low-ESR* із `ESR < 15 мОм`), потужність розсіювання сягає 3–5 Вт на один невеликий корпус. Рідкий електроліт закипає, гумовий ущільнювач висихає за кілька десятків польотів, після чого ефективна ємність падає у 10 разів, а амплітуда комутаційних викидів на шині живлення зростає до рівня пробою вхідних стабілізаторів польотного контролера.

## Сенсорний домен: спотворення реальності

Польотний контролер не «бачить» фізичний простір безпосередньо. Він спирається на модель стану, що формується розширеним фільтром Калмана (EKF, *Extended Kalman Filter*) на основі вимірів інерційного вимірювального модуля (IMU, *Inertial Measurement Unit*), магнітометра, барометра та приймача супутникової навігації (GNSS). Спотворення сенсорних даних призводить до того, що математично коректний регулятор упевнено спрямовує апарат у землю.

### Вібраційне насичення та асиметричний кліпінг (IMU Clipping)

Мікроелектромеханічний акселерометр (MEMS) складається з кремнієвої чутливої маси на пружних мікропідвісах. Прискорення зсуває масу, змінюючи ємність вимірювальних гребінчастих конденсаторів.

Більшість авіаційних сенсорів налаштовуються на вимірювальний діапазон `±16g`. Якщо механічні коливання рами від пошкодженого пропелера перевищують цей поріг, рухома маса фізично вдаряється в обмежувачі ходу або вихідний підсилювач АЦП сенсора досягає максимального розрядного числа.

![](/root/course/embedded-ultra/why-vehicles-crash/img/imu-vibration-clipping.svg)
*Механізм виникнення фатальної похибки орієнтації через асиметричний зріз вібраційного шуму (Clipping): симетрична вібрація після обмеження перетворюється на хибну постійну складову прискорення.*

Коливання у просторі рідко бувають ідеально симетричними. Через постійний вплив сили тяжіння 1g або аеродинамічного навантаження додатні піки вібрації обрізаються сильніше, ніж від'ємні. Виникає явище **асиметричного кліпінгу** (від англійського *clipping* — обрізання вершин сигналу, та латинського *saturatio* — переповнення, насичення).

Наслідок для алгоритму фільтрації:
1. Високочастотний вібраційний шум після асиметричного зрізу детекторується як постійне зміщення нульового рівня (*rectified DC bias*).
2. Інтегратор EKF сприймає це зміщення як реальне лінійне прискорення апарата, наприклад `a_y = -3.2 м/с²`.
3. Щоб зрівноважити уявне прискорення, фільтр робить висновок, що апарат нахилений за креном на кут `θ = arcsin(3.2 / 9.81) ≈ 19°`.
4. Система автопілота намагається вирівняти дрон і створює протилежний реальний крен на 19 градусів, переходячи в некероване бокове ковзання з подальшим зіткненням із перешкодою.

### Акустичний резонанс чутливих елементів гіроскопа

Мікромеханічний гіроскоп вимірює кутову швидкість за силою Коріоліса, що діє на кремнієву масу, яка примусово вібрує на власній резонансній частоті (зазвичай у діапазоні від 18 до 28 кГц).

Якщо акустичні гармоніки від кінчиків високошвидкісних лопатей або комутаційний писк силових транзисторів ESC збігаються з резонансною частотою внутрішньої камери гіроскопа, звукова хвиля проникає крізь металевий корпус сенсора. Відбувається акустичне збудження вимірювальних балок: вихідні дані кутової швидкості або раптово застигають на фіксованій константі (*gyro freeze*), або починають генерувати максимальне числове значення шкали (`±2000 deg/s`). Алгоритм орієнтації миттєво втрачає азимут.

### Електромагнітні наводки на магнітометр (Toilet-Bowling)

Магнітометр вимірює вектор магнітного поля Землі, напруженість якого становить від 30 до 60 мікротесла (`0.3–0.6 Гауса`).

За законом Біо-Савара-Лапласа постійний струм `I = 60 А`, що протікає по силовому кабелю на відстані `r = 50 мм` від компаса, створює власне паразитне магнітне поле:

```
B_noise
= (μ₀ · I) / (2π · r)                 [формула напруженості поля провідника]
= (4π · 10⁻⁷ · 60) / (2π · 0.05)      [підстановка фізичних констант]
= (2 · 10⁻⁷ · 60) / 0.05
= 2.4 · 10⁻⁴ Тл = 240 мкТл            [магнітне поле шуму]
```

Паразитне поле у 4–8 разів перевищує корисний сигнал геомагнітного поля Землі. Коли пілот збільшує тягу, вектор магнітної індукції раптово повертається на десятки градусів.

Алгоритм розрахунку курсу (*Yaw estimator*) фіксує уявний поворот носа апарата. Система навігації намагається повернути апарат назад, що призводить до розбіжності між координатами GPS та показами компаса. Виникає класичний дефект автопілота — **ефект унітазної вирви** (*toilet-bowling*): дрон починає літати колами по спіралі з наростаючим радіусом та кутовою швидкістю, доки не перекинеться або не вріжеться в землю.

### Спотворення висоти барометра динамічним тиском Бернуллі

Барометричний датчик висоти вимірює статичний атмосферний тиск повітря всередині корпусу апарата. Згідно з законом Бернуллі, повний тиск у рухомому потоці газу складається зі статичного тиску `P_stat` та динамічного швидкісного напору `q`:

```
P_total = P_stat + 0.5 · ρ · v²
```

Коли апарат летить уперед зі швидкістю `v = 25 м/с`, повітряний потік, що огинає фюзеляж, створює зону локального розрідження (падіння статичного тиску) біля вентиляційних отворів:

```
ΔP_bernoulli
= 0.5 · 1.225 кг/м³ · (25 м/с)²       [розрахунок динамічного тиску]
≈ 383 Па                              [глибина перепаду тиску]
```

Оскільки зміна тиску на 12 Па біля поверхні Землі відповідає зміні висоти приблизно на 1 метр, барометр фіксує уявний підйом апарата на висоту:

```
Δh_error
= 383 Па / 12 Па/м                    [перерахунок тиску у висоту]
≈ 31.9 м                              [хибна висота барометра]
```

Автопілот вважає, що дрон самовільно піднявся на 32 метри вище заданого ешелону. Регулятор висоти скидає тягу двигунів до мінімуму, спрямовуючи апарат у пікірування на повній горизонтальній швидкості.

## Програмний домен: детермінізм реального часу та пастки паралелізму

Програмне забезпечення польотного контролера функціонує в умовах твердого реального часу (*Hard Real-Time*). Пропуск дедлайну розрахунку контуру стабілізації еквівалентний повній відмові апаратної частини.

### Апаратне захоплення шини I2C (SDA Lockup)

Шина I2C широко використовується для опитування допоміжних датчиків: барометра, магнітометра, зовнішніх світлодіодів. Протокол базується на лініях із відкритим колектором (Open-Drain), підтягнутих до напруги живлення резисторами.

![](/root/course/embedded-ultra/why-vehicles-crash/img/i2c-bus-lockup.svg)
*Механізм апаратного зависання лінії SDA веденим сенсором при збої ведучого та покроковий алгоритм розблокування шини імпульсами SCL.*

Сценарій фатального блокування шини:
1. Ведучий (MCU) зчитує байт із веденого датчика. Датчик передає біт логічного нуля і примусово притискає лінію `SDA` до землі (0 В).
2. У цей момент мікроконтролер зазнає короткочасного скидання від просідання живлення, переривання або внутрішнього збою тактування.
3. Після рестарту мікроконтролер ініціалізує свій апаратний блок I2C. Периферійний модуль перевіряє стан шини: лінія `SDA` затиснута в нуль веденим пристроєм, який досі чекає тактового імпульсу `SCL` для завершення свого байта.
4. Апаратний контролер I2C вважає, що шина зайнята іншим ведучим (*Master Arbitration Lost*), і зависає в нескінченному циклі очікування звільнення лінії. Польотний стек блокується на стадії завантаження або втрачає навігаційні сенсори прямо в польоті.

### Інверсія пріоритетів та дедлоки в RTOS

У багатозадачних операційних системах реального часу (FreeRTOS, NuttX) критичні задачі розбито за пріоритетами:
* **Task A (Високий пріоритет):** Розрахунок кутових швидкостей та видача команд на мотори (частота 1000 Гц, дедлайн 1 мс).
* **Task B (Середній пріоритет):** Обробка протоколу зв'язку MAVLink та логування (частота 50 Гц).
* **Task C (Низький пріоритет):** Запис логу польоту на SD-карту через спільну шину SPI (частота 10 Гц).

Коли низькопріоритетна задача `Task C` захоплює м'ютекс доступу до шини SPI і в цей момент витісняється задачею `Task B`, виникає стан **інверсії пріоритетів** (*Priority Inversion*, від латинського *prior* — перший, вищий, та *inversio* — перевертання).

```
Task A (Rate Loop)    ────[Потребує SPI]───XXXXX [Заблоковано м'ютексом!] ─────────> КРАХ
                              ▲
Task B (Комунікація)   ───────┼────────────██████████████████████████████──────────> Працює
                              ▼
Task C (SD-Card)      ──████ [Утримує м'ютекс SPI] ────────────────────────────────> Витіснено B
```

Високопріоритетна задача `Task A` намагається звернутися до сенсора на тій самій шині, блокується на м'ютексі й чекає задачу `Task C`. Проте задача `Task C` не може виконатися, тому що процесор зайнятий середньою задачею `Task B`. Контур стабілізації пропускає дедлайн, мотори не отримують оновлення тяги, і апарат втрачає орієнтацію.

Для вирішення цієї проблеми операційна система зобов'язана підтримувати **протокол успадкування пріоритетів** (*Priority Inheritance Protocol*): у момент, коли `Task A` блокується на м'ютексі, пріоритет `Task C` тимчасово підвищується до рівня `Task A`, що унеможливлює її витіснення задачею `Task B` і забезпечує швидке звільнення критичного ресурсу.

### Анатомія фатального збою HardFault в ARM Cortex-M

Аварійний виняток `HardFault` є останньою лінією зупинки процесора при виявленні невідновних помилок пам'яті або команд.

Основні причини падіння ядра в польоті:
1. **Розіменування нульового вказівника (*Null Pointer Dereference*):** Спроба запису телеметрії за неініціалізованою адресою `0x00000000` при вичерпанні пулу динамічної пам'яті (*Heap Exhaustion*).
2. **Невирівняний доступ до пам'яті (*Unaligned Memory Access*):** Пряме перетворення байтового буфера пакета вказівником `(uint32_t*)&buffer[i]` при активованому біті `UNALIGN_TRP` у регістрі конфігурації ядра `CCR`.
3. **Переповнення стека задачі (*Stack Overflow*):** Виклик вкладених математичних функцій розрахунку навігації перевищує розмір виділеного стека (наприклад, 2048 байт), стираючи сусідні структури TCB (Task Control Block) операційної системи.

Історичний досвід системних відмов через переповнення та порушення детермінізму детально висвітлено у вставці [Уроки космічних катастроф](root:embedded-ultra/why-vehicles-crash/hist-ariane-and-apollo.md).

## Побудова системи аварійного захисту (Failsafe)

Стійкість безпілотного апарата досягається не надією на відсутність збоїв, а проектуванням архітектури, здатної детерміновано виявляти відмови та переводити систему в безпечний стан деградації.

Термін **фейлсейф** (*failsafe*) утворено поєднанням англійських слів *fail* (відмовляти, ламатися, що сходить до латинського *fallere* — обманювати, хибити) та *safe* (безпечний, збережений).

![](/root/course/embedded-ultra/why-vehicles-crash/img/failsafe-state-machine.svg)
*Ієрархічний кінцевий автомат Failsafe: багаторівнева градація аварійних реакцій залежно від глибини відмови сенсорів, живлення та радіоканалу.*

### Ієрархія захисних механізмів

Система захисту польотного контролера організована у вигляді багаторівневого фільтра реакцій:

1. **Рівень 1: Алгоритмічна компенсація та десатурація (Degraded Mode):**
   * *Захист інтегратора (Anti-Windup):* Якщо один із моторів досяг 100% тяги через фізичне пошкодження гвинта, інтегральна складова PID-регулятора заморожується, запобігаючи неконтрольованому накопиченню помилки (*I-term saturation*).
   * *Десатурація мікшера моторів (*Mixer Desaturation*):* При перевищенні діапазону тяги (сума `Throttle + Roll + Pitch > 1.0`) система автоматично зменшує спільну вертикальну тягу, зберігаючи пропорційність керуючих моментів стабілізації. Стабільність кутової орієнтації завжди має вищий пріоритет над утриманням висоти.
   * *Перемикання сенсорних каналів (EKF Lane Switching):* Польотний стек запускає паралельно 2–3 екземпляри фільтра Калмана з різними джерелами IMU. При асиметричному кліпінгу або збої одного сенсора система за 10 мс перемикає активний контур на резервний EKF.
2. **Рівень 2: Автономна навігація повернення (RTH / RTL):**
   * При втраті радіоканалу керування (*RC Loss*) довше ніж на 1.5 секунди автопілот фіксує координати точки старту, піднімається на безпечну висоту запобігання зіткненням із рельєфом (наприклад, 50 метрів) і виконує процедуру повернення додому (*Return-To-Home*).
3. **Рівень 3: Контрольований аварійний спуск (Emergency Descent):**
   * При падінні напруги батареї нижче критичного порогу (наприклад, `3.3 В` на банку під навантаженням) або за повної відмови супутникової навігації в режимі RTH автопілот переходить у режим вертикального спуску з фіксованою швидкістю `1.5 м/с` за барометром чи оптичним сенсором до повного торкання землі.
4. **Рівень 4: Аварійне глушіння та балістичний парашут (Critical Termination):**
   * Якщо кут нахилу апарата за креном або тангажем перевищує 75–80 градусів (стан некерованого перекидання) або виявлено відрив мотора, польотний контролер негайно вимикає приводи (*Disarm*), щоб запобігти пожежі, та викидає піротехнічний або пружинний рятувальний парашут.

### Сторожові таймери та безпечний цикл обслуговування

Основою програмної живучості є **сторожовий таймер** (*Watchdog timer*):

* **Незалежний сторож (IWDG, *Independent Watchdog*):** Апаратний лічильник зі своїм власним ізольованим низькочастотним генератором (RC-коло 32–40 кГц). Якщо ядро процесора зависає у дедлоку, таймер дораховує до нуля і генерує повне апаратне скидання чипа.
* **Віконний сторож (WWDG, *Window Watchdog*):** Спрацьовує не лише при затримці скидання, а й при занадто ранньому скиданні, що дозволяє ловити збої тактування основного кварцового генератора.
* **Супервізор завдань (Task Watchdog):** У FreeRTOS кожна задача зобов'язана виставити свій біт життєздатності в глобальному реєстрі. Апаратний сторож годується тільки тоді, коли всі без винятку задачі підтвердили виконання своїх дедлайнів.

Нижче наведено практичну реалізацію модуля перевірки здоров'я польотного стека, процедури апаратного вивільнення шини I2C та оновлення стану Failsafe-автомата на мовах C та C++.

```c
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    FAIL_MODE_NONE = 0,
    FAIL_MODE_SENSOR_DEGRADED,
    FAIL_MODE_RTH,
    FAIL_MODE_LAND,
    FAIL_MODE_TERMINATE
} failsafe_mode_t;

typedef struct {
    uint32_t last_rc_tick_ms;
    uint32_t last_imu_tick_ms;
    float vbat_volts;
    float tilt_roll_deg;
    float tilt_pitch_deg;
    bool gps_valid;
} flight_telemetry_t;

/* Процедура вивільнення заблокованої лінії SDA 9 тактами SCL */
bool i2c_bus_recover_sda(void (*scl_pin_set)(bool level),
                         bool (*sda_pin_read)(void),
                         void (*delay_fn)(uint32_t us)) {
    /* 1. Генеруємо до 9 імпульсів на лінії SCL */
    for (uint8_t i = 0; i < 9; ++i) {
        if (sda_pin_read()) {
            break; /* Ведений пристрій відпустив лінію SDA у High-Z */
        }
        scl_pin_set(false);
        delay_fn(5);
        scl_pin_set(true);
        delay_fn(5);
    }
    return sda_pin_read();
}

/* Оцінка стану безпеки та перемикання аварійного режиму */
failsafe_mode_t failsafe_evaluate_state(const flight_telemetry_t *telem, uint32_t now_ms) {
    const uint32_t rc_dt = now_ms - telem->last_rc_tick_ms;
    const uint32_t imu_dt = now_ms - telem->last_imu_tick_ms;

    /* 1. Фатальні умови: перекидання понад 75 градусів або відмова IMU */
    if (imu_dt > 40 || telem->tilt_roll_deg > 75.0f || telem->tilt_roll_deg < -75.0f ||
        telem->tilt_pitch_deg > 75.0f || telem->tilt_pitch_deg < -75.0f) {
        return FAIL_MODE_TERMINATE;
    }

    /* 2. Критичне падіння напруги живлення */
    if (telem->vbat_volts < 13.2f) { /* Поріг 3.3 В на банку для 4S */
        return FAIL_MODE_LAND;
    }

    /* 3. Втрата зв'язку керування RC */
    if (rc_dt > 1500) {
        return telem->gps_valid ? FAIL_MODE_RTH : FAIL_MODE_LAND;
    }

    return FAIL_MODE_NONE;
}
```

```cpp
#include <cstdint>
#include <functional>

enum class FailsafeMode : uint8_t {
    None = 0,
    SensorDegraded,
    ReturnToHome,
    EmergencyLand,
    CriticalTerminate
};

struct FlightTelemetry {
    uint32_t last_rc_tick_ms{0};
    uint32_t last_imu_tick_ms{0};
    float vbat_volts{16.8f};
    float tilt_roll_deg{0.0f};
    float tilt_pitch_deg{0.0f};
    bool gps_valid{true};
};

class FailsafeController {
public:
    static constexpr uint32_t kRcTimeoutMs = 1500;
    static constexpr uint32_t kImuTimeoutMs = 40;
    static constexpr float kCriticalVoltage4S = 13.2f;
    static constexpr float kMaxTiltAngleDeg = 75.0f;

    [[nodiscard]] FailsafeMode evaluate(const FlightTelemetry& telem, uint32_t now_ms) const noexcept {
        const uint32_t rc_dt = now_ms - telem.last_rc_tick_ms;
        const uint32_t imu_dt = now_ms - telem.last_imu_tick_ms;

        // 1. Негайне аварійне глушіння при перекиданні або втраті датчиків кута
        if (imu_dt > kImuTimeoutMs ||
            telem.tilt_roll_deg > kMaxTiltAngleDeg || telem.tilt_roll_deg < -kMaxTiltAngleDeg ||
            telem.tilt_pitch_deg > kMaxTiltAngleDeg || telem.tilt_pitch_deg < -kMaxTiltAngleDeg) {
            return FailsafeMode::CriticalTerminate;
        }

        // 2. Критичний розряд батареї
        if (telem.vbat_volts < kCriticalVoltage4S) {
            return FailsafeMode::EmergencyLand;
        }

        // 3. Втрата радіоканалу зв'язку
        if (rc_dt > kRcTimeoutMs) {
            return telem.gps_valid ? FailsafeMode::ReturnToHome : FailsafeMode::EmergencyLand;
        }

        return FailsafeMode::None;
    }

    // Апаратне відновлення шини I2C
    static bool recover_i2c_bus(const std::function<void(bool)>& scl_set,
                               const std::function<bool()>& sda_read,
                               const std::function<void(uint32_t)>& delay_fn) noexcept {
        for (uint8_t i = 0; i < 9; ++i) {
            if (sda_read()) {
                return true; // Лінія SDA вільна
            }
            scl_set(false);
            delay_fn(5);
            scl_set(true);
            delay_fn(5);
        }
        return sda_read();
    }
};
```
