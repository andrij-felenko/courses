# ⚙️ Відновлення зв'язку з заблокованим мікроконтролером (SWD Unbricking)

Цей практикум містить покроковий інженерний розбір аварійного відновлення доступу до мікроконтролера через апаратний інтерфейс SWD (Serial Wire Debug). Він призначений для ситуацій, коли некоректна прошивка перепризначила системні виводи `PA13` (SWDIO) чи `PA14` (SWCLK) під загальний GPIO, перевела ядро процесора в режим глибокого енергозбереження (Deep Sleep) одразу після зняття скидання або активувала захист пам'яті.

---

### Проблема: механізм апаратного блокування налагоджувача

Під час розробки вбудованих систем розробник нерідко стикається з ситуацією, коли після чергового прошивання плати налагоджувач (ST-Link, J-Link, Black Magic Probe або CMSIS-DAP) раптово перестає бачити мікроконтролер. Спроба підключитися через утиліти `openocd`, `st-flash` або інтерфейс GDB завершується помилкою опитування шини налагодження:

```text
Error: init mode failed (unable to connect to the target)
Error: target voltage is 3.28V, but DAP communication failed
Error: No device found on SWD bus (DPIDR read failed: 0x00000000).
```

Цей стан називається апаратним замиканням доступу (від англійського *debugger lockout* або *bricking*). Основні причини, через які чип перетворюється на «цеглину»:

1. **Захоплення виводів у коді ініціалізації:** функція `GPIO_Init()` викликає конфігурацію виводів `PA13` або `PA14` на режим виходу (`GPIO_Mode_OUT`) або змінює стан регістрів мультиплексора `AFIO` / `MODER`, відключаючи вхідні буфери блоку DAP (Debug Access Port).
2. **Миттєве відключення тактування (Sleep Lockout):** прошивка переводить мікроконтролер у режим `STOP` чи `STANDBY` через 10–50 мікросекунд після старту. Оскільки у глибокому сні внутрішній генератор тактування ядра та системної шини APB знеструмлюється, блок налагодження втрачає синхронізацію і не може відповісти на запити відлагоджувача.
3. **Збійне дерево тактування (Clock Tree Failure):** прошивка вмикає блок помножувача частоти PLL на неприпустимо високі коефіцієнти множення або вибирає зовнішній кварц HSE, який фізично не запаяний на платі. Процесор миттєво падає в обробник помилки `HardFault_Handler` або зависає в нескінченному очікуванні готовності генератора.
4. **Блокування через захист зчитування (RDP Level 1):** випадкова або помилкова активація бітів Option Bytes, яка блокує доступ налагоджувача до внутрішньої пам'яті SRAM та Flash.

### Метод 1: Апаратне перехоплення при скиданні (Connect Under Reset)

Найбільш надійний та стандартний спосіб відновлення — використання апаратної лінії скидання `NRST` разом із протоколом векторного перехоплення (Vector Catch).

#### Фізичний принцип та робота регістрів DAP

Коли на лінію `NRST` мікроконтролера подано низький логічний рівень (0 В), процесорне ядро ARM Cortex-M та вся периферія утримуються в стані скидання. У цьому стані всі виводи GPIO переведені в режим плаваючого входу або системної альтернативної функції `AF0`, а виводи `PA13` (SWDIO) та `PA14` (SWCLK) апаратно підключені до внутрішнього порту доступу налагодження (Debug Port, DP).

Програматор виконує наступну послідовність дій:
1. Примусово притискає лінію `NRST` до землі за допомогою внутрішнього відкритого колектора.
2. Відправляє у лінію `SWCLK`/`SWDIO` послідовність перемикання інтерфейсів (JTAG-to-SWD Switching Sequence: щонайменше 50 одиничних бітів, 16-бітний код `0xE79E`, ще 50 одиничних бітів та 8 нульових бітів паузи).
3. Зчитує регістр ідентифікації `DPIDR` (Debug Port Identification Register). Для Cortex-M4 значення повинно дорівнювати `0x2BA01477`.
4. Записує біт `C_DEBUGEN` (активація відладки) та біт `C_HALT` (запит зупинки ядра) у системний регістр керування налагодженням `DHCSR` (Debug Halting Control and Status Register, адреса `0xE000EDF0`).
5. Встановлює біт `VC_CORERESET` (векторне перехоплення скидання) у регістрі `DEMCR` (Debug Exception and Monitor Control Register, адреса `0xE000EDFC`).
6. Відпускає апаратну лінію `NRST`.

Оскільки у регістрі `DEMCR` було активовано біт `VC_CORERESET`, ядро процесора після виходу зі стану скидання зупиняється **до виконання першої інструкції** з нульової адреси Flash-пам'яті (до виклику `Reset_Handler`). Збійна прошивка не встигає виконатися, і налагоджувач отримує повний контроль над контролером пам'яті.

#### Конфігураційний скрипт для OpenOCD

Створіть у робочій теці файл конфігурації `openocd_recover.cfg`:

```text
# 1. Вибір апаратного адаптера
source [find interface/stlink.cfg]

# 2. Вибір протоколу передачі даних
transport select hla_swd

# 3. Вибір цільового мікроконтролера
source [find target/stm32f4x.cfg]

# 4. ГОЛОВНЕ НАЛАШТУВАННЯ: Утримання апаратного скидання під час підключення
# connect_assert_srst змушує адаптер тримати NRST = 0 до повної ініціалізації DAP
reset_config srst_only srst_nogate connect_assert_srst

# 5. Зниження частоти тактування SWD до 500 кГц для надійного захоплення
adapter speed 500

init
targets

# 6. Зупинка ядра, повне стирання flash-пам'яті та завершення роботи
reset halt
stm32f4x mass_erase 0
reset halt
shutdown
```

Запуск аварійного відновлення з консолі:

```bash
openocd -f openocd_recover.cfg
```

Після завершення виконання команди вся користувацька пам'ять Flash буде стерта (заповнена байтами `0xFF`), і мікроконтролер перейде у чистий заводський стан.

### Метод 2: Апаратна пастка системного завантажувача (Bootloader Trap)

Якщо на вашій друкованій платі лінія `NRST` не була виведена на роз'єм програмування (або мікроконтролер запаяний у мініатюрному корпусі без доступу до скидання), метод *Connect Under Reset* застосувати неможливо. У такому разі використовується вивід конфігурації джерела завантаження — `BOOT0`.

```
┌─────────────────────────┐          +3.3V (VDD)
│                         │             ▲
│                         │             │
│                         │            [R1: 4.7 кОм]
│      STM32 MCU          │             │
│                         ├─────────────┴─────[Джампер / Кнопка RECOVER]
│        BOOT0            │
│                         ├─────────────┬─────[R2: 10 кОм]
│                         │             │
└─────────────────────────┘             ▼
                                       GND (0V)
```

#### Покроковий алгоритм відновлення:
1. Повністю знеструмте пристрій.
2. Встановіть тимчасову перемичку між піном `BOOT0` та шиною живлення +3.3 В (подайте високий логічний рівень).
3. Подайте живлення на плату.
4. Внутрішня апаратна логіка виявить рівень логічної одиниці на виводі `BOOT0` у момент старту. Процесор проігнорує вміст Flash-пам'яті та передасть керування у захищену область системної пам'яті (System ROM), де знаходиться заводський завантажувач від виробника (ST System Bootloader).
5. Заводський завантажувач містить код для зв'язку через USART/USB, ніколи не вимикає лінії SWD і не використовує режими сну.
6. Підключіть програматор і виконайте повне стирання пам'яті за допомогою утиліти `st-flash` або STM32CubeProgrammer:
   ```bash
   st-flash erase
   ```
7. Зніміть живлення, поверніть перемичку `BOOT0` у положення логічного нуля (підтяжка до GND) і ввімкніть живлення. Контролер готовий до звичайного програмування.

### Метод 3: Програмний захисний інтервал у прошивці (Startup Safety Guard)

Найкращий спосіб боротьби з блокуванням — запобігти йому на рівні архітектури прошивки. Під час розробки коду, що взаємодіє з режимами енергозбереження або модифікує регістри виводів `PA13`/`PA14`, у функцію `main()` обов'язково додається захисна пауза.

:::tabs
```c
#include "stm32f4xx.h"
#include <stdbool.h>

/**
 * @brief Апаратний захисний інтервал перед виконанням небезпечної ініціалізації.
 * Дає налагоджувачу 2 секунди для перехоплення контролю над ядром.
 */
static void debug_startup_guard(void) {
    // Вмикаємо тактування порту кнопки (наприклад, PA0)
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    GPIOA->MODER &= ~(0x3U << (0 * 2)); // Вхід
    GPIOA->PUPDR |=  (0x2U << (0 * 2)); // Підтяжка вниз (Pull-down)

    // Якщо кнопка затиснута під час увімкнення — зависаємо в безпечному циклі
    if ((GPIOA->IDR & (1U << 0)) != 0) {
        while (true) {
            __NOP(); // Дозволяє відлагоджувачу підключитися в будь-який момент
        }
    }

    // Захисна затримка на 2000 мс при стандартній частоті тактування 16 МГц (HSI)
    for (volatile uint32_t i = 0; i < 2000000UL; ++i) {
        __NOP();
    }
}

int main(void) {
    // ВИКЛИКАТИ ПЕРШИМ РЯДКОМ У MAIN!
    debug_startup_guard();

    // Далі йде потенційно небезпечний код перепризначення виводів або переходу в сон:
    // enter_stop_mode();
    
    while (1) {
    }
}
```
```cpp
#include "stm32f4xx.h"
#include <cstdint>

namespace mcu::debug {

/**
 * @brief Клас захисту інтерфейсу налагодження на етапі старту (Zero-overhead guard).
 */
class SafetyBarrier {
public:
    static void apply_boot_guard(uint32_t loop_count = 2'000'000U) noexcept {
        // Дозволяємо тактування порту користувацької кнопки для екстреного входу в цикл
        RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
        GPIOA->MODER &= ~(0x3U << (0 * 2)); // Вхід PA0

        // Якщо кнопка утримується під час подачі живлення — блокуємо перехід у сон
        if ((GPIOA->IDR & (1U << 0)) != 0) {
            while (true) {
                asm volatile("nop");
            }
        }

        // Програмний інтервал затримки для підключення OpenOCD/ST-Link
        for (volatile uint32_t i = 0; i < loop_count; ++i) {
            asm volatile("nop");
        }
    }
};

} // namespace mcu::debug

int main() {
    // Захисний бар'єр гарантує збереження доступу до ядра під час розробки
    mcu::debug::SafetyBarrier::apply_boot_guard();

    // Робоча ініціалізація периферії
    
    while (true) {
    }
}
```

### Крайові випадки та пастки розблокування

1. **Невідповідність рівнів напруги (VREF):** якщо цільова плата живиться від 1.8 В, а програматор ST-Link V2 має фіксовані рівні 3.3 В, вхідний каскад SWDIO може не розпізнавати логічні рівні. Для низьковольтних плат слід використовувати відлагоджувачі з окремим входом `VREF / VAPP` (наприклад, J-Link або ST-Link V3).
2. **Паразитна ємність на лініях SWD:** встановлення конденсаторів фільтрації або супресорів із ємністю понад 30 пФ на лінії `PA13`/`PA14` завалює фронти тактового сигналу `SWCLK`. Для стабільної роботи на лініях програмування не повинно бути жодних додаткових ємностей.
3. **Захист пам'яті RDP Level 2:** якщо в регістрах Option Bytes було активовано максимальний рівень захисту (RDP Level 2), апаратний блок DAP деактивується на рівні кремнієвих масок назавжди. Мікроконтролер у стані RDP Level 2 неможливо розблокувати жодним програмним чи апаратним методом — чип підлягає лише фізичній заміні на платі.
