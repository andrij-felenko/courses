# Від ручки до команди: осі, мертва зона, криві, експонента

<preknowlist>
- [Аналого-цифровий перетворювач](root:hw-analog/adc) — дискретизація та квантування напруги сенсорів стіка у цифровий код.
- [Потенціометр](root:hw-components/potentiometer) — резистивний дільник напруги як первинний перетворювач механічного кута.
- [Датчик Холла](root:hw-sensing/hall-sensor) — безконтактне вимірювання напруженості магнітного поля при нахилі ручки.
- [RC-сигнал: PWM, PPM і S.BUS](root:sys-dron/rc-signal-protocol) — традиційні протоколи передачі каналів керування через радіолінк.
- [Протокол CRSF](root:sys-dron/crsf-protocol) — сучасний цифровий пакетний протокол обміну між пультом та польотним контролером.
</preknowlist>

Коли оператор відпускає ручку керування на пульті, дві сталеві пружини карданного підвісу повертають її назад до центру. З точки зору математики в цей момент вхідний сигнал має стати ідеальним нулем. На реальному апараті цього не відбувається ніколи: механічне тертя в шарнірах, залишковий люфт пружини та мікровольтні коливання опорної напруги напівпровідникового давача залишають ручку на відліку, наприклад, 2038 замість теоретичного 2048 на 12-бітному АЦП. Якщо перетворити цей сирий вихід безпосередньо на команду кутової швидкості для PID-регулятора, дрон або роботизована платформа навіть без дотику людини почне безперервно повертатися навколо своєї осі зі швидкістю 3–5°/с, повільно дрейфувати вбік, а мотори на столі грітимуться від паразитичного мікротремтіння.

Між механічним рухом пальця оператора та уставкою швидкості для контурів стабілізації лежить багатоланковий алгоритмічний конвеєр. Кожен його крок вирішує власну фізичну або фізіологічну проблему: виправляє асиметрію підвісу, відсікає апаратний дрейф, формує нелінійну криву чутливості для високоточного прицілювання та згладжує сходинки радіопакетів.

![Схема повного конвеєра перетворення даних стіка: від первинного вимірювання напруги датчиків до згладженої уставки кутової швидкості для контуру керування](/root/course/embedded/vid-ruchky-do-komandy/img/stick-pipeline.svg)
*Повний конвеєр обробки стіка. Сирий сигнал давача оцифровується АЦП, калібрується за трьома точками, проходить неперервну мертву зону, формується нелінійною кривою експоненти, масштабується моделлю кутових швидкостей і згладжується низькочастотним фільтром перед подачею в PID-контур.*

## Сирий вхід стіка: фізика давачів та оцифрування

Механічний модуль стіка пульта (gimbal) складається з двох ортогональних осей обертання, кожна з яких закріплена на кулькових підшипниках і з'єднана з первинним вимірювальним перетворювачем кута. У сучасній апаратурі керування застосовують два принципово різні типи давачів положення: резистивні потенціометри та магнітні сенсори Холла.

### Потенціометричні підвіси

У потенціометричному підвісі вісь ручки механічно обертає ковзний контакт (повзунок) по дугоподібній доріжці з резистивного вуглецевого або металокерамічного композиту. Крайні виводи доріжки підключені до шини живлення та землі (наприклад, 3.3 В та 0 В), перетворюючи кут повороту на лінійний дільник напруги.

Головна перевага класичного потенціометра — простота та пряма пропорційність вихідної напруги положенню вала. Проте в умовах інтенсивної експлуатації проявляються критичні фізичні обмеження:
1. **Механічний знос резистивного шару:** постійне тертя повзунка стирає резистивний шар у найчастіше використовуваній зоні — навколо центру. Вже після 50–100 годин роботи в центрі виникає мікроскопічна яма, через яку опір втрачає монотонність.
2. **Контактний шум (шурхіт):** мікрочастинки пилу та окисли металу спричиняють короткочасні мікророзриви контакту під час руху ручки, що породжує сплески напруги амплітудою в десятки мілівольтів.
3. **Температурний дрейф опору:** зміна температури навколишнього середовища змінює повний опір доріжки та контактний опір повзунка, зсуваючи напругу центральної точки на 1–2%.

### Підвіси на датчиках Холла

У безконтактних підвісах на рухомій осі закріплений мініатюрний неодимовий магніт, а на нерухомій платі навпроти нього встановлений лінійний [датчик Холла](root:hw-sensing/hall-sensor). При відхиленні ручки змінюється кут падіння вектора магнітної індукції на чутливий напівпровідниковий кристал сенсора, що змінює вихідну ЕРС Холла.

Повна відсутність механічного тертя забезпечує підвісам на датчиках Холла практично необмежений ресурс (мільйони циклів) і повну відсутність контактного шуму. Проте обробка магнітного сигналу потребує врахування таких нюансів:
1. **Геометрична нелінійність:** напруженість магнітного поля спадає нелінійно з відстанню, а перпендикулярна складова вектора магнітної індукції пропорційна синусу кута нахилу. На кутах відхилення понад ±20° виникає помітна нелінійність характеристик, яку необхідно вирівнювати програмно.
2. **Чутливість до опорної напруги:** аналогові сенсори Холла є раціометричними — їхній вихід пропорційний напрузі живлення. Будь-які пульсації шини живлення мікроконтролера передаються безпосередньо у виміряний кут.
3. **Температурний зсув нуля:** напівпровідникові структури мають температурний дрейф напруги зміщення (offset drift), через що нульова точка зміщується при нагріванні пульта на сонці або охолодженні на морозі.

### Схемотехніка вхідного тракту та дискретизація АЦП

Аналогова напруга з давача не може подаватися безпосередньо на вхідний мультиплексор [АЦП](root:hw-analog/adc). Пульт дистанційного керування містить потужний високочастотний передавач (від 100 мВт до 1 Вт на частотах 868 МГц або 2.4 ГГц). Довгі дроти від підвісів до головної плати працюють як антени, вловлюючи високочастотне електромагнітне поле.

Для придушення наведень безпосередньо біля виводів мікроконтролера встановлюють пасивний RC-фільтр низьких частот:
- Послідовний резистор номіналом 1–2.2 кОм;
- Керамічний конденсатор ємністю 10–47 нФ на землю (частота зрізу порядку 3–5 кГц).

Такий фільтр повністю відсікає радіочастотний шум, але не створює відчутної затримки для механічного руху руки (постійна часу τ = RC ≈ 30 мкс).

Для оцифрування застосовують АЦП послідовного наближення (SAR ADC) з розрядністю 10 біт (1024 рівні) або 12 біт (4096 рівнів). При напрузі живлення 3.3 В крок квантування 12-бітного АЦП становить:

```
ΔV = 3.3 В / 4096 ≈ 0.806 мВ
```

Оскільки повний кутовий діапазон ходу ручки становить зазвичай лише ±25° (загалом 50°), переміщення стіка на 1° створює зміну сигналу приблизно на 82 відліки АЦП. Завдяки цьому роздільна здатність перевищує 0.012° на відлік, що значно тонше за поріг тактильної чутливості людської руки.

Проте тепловий шум вхідних кіл, перехідні процеси при комутації каналів АЦП та цифрові наведення від радіопередавача створюють високочастотний джитер молодших 2–3 розрядів. Якщо прочитати значення нерухомого стіка 100 разів поспіль, значення коливатиметься у межах ±4–8 відліків LSB. Залишати цей шум без фільтрації неприпустимо, оскільки цифрові протоколи передачі передаватимуть мікрозміни у кожному радіопакеті.

## Калібрування та нормалізація вхідного сигналу

Сирий цифровий код з АЦП залежить від конкретного екземпляра давача, механічної посадки магнітів та пружності повертаючих пружин. Наприклад, для осі крену крайній лівий упор може видавати код 312, центральне положення — 2065, а крайній правий упор — 3890.

Завдання нормалізації полягає у перетворенні сирого коду у безрозмірну величину:

```
x ∈ [-1.0, +1.0]
```

де `x = -1.0` відповідає повному лівому відхиленню, `x = 0.0` — точному центру, а `x = +1.0` — повному правому відхиленню.

### Чому не можна застосовувати просте лінійне масштабування

Типова помилка початківця — спроба нормалізувати сигнал через єдине лінійне перетворення:

```
x = (raw - 2048) / 2048
```

Такий підхід руйнує керування з двох причин:
1. **Асиметрія плечей:** відстань від центру до лівого упору (`2065 - 312 = 1753`) майже ніколи не дорівнює відстані від центру до правого упору (`3890 - 2065 = 1825`). Використання однакового знаменника призведе до того, що в один бік ручка не доходитиме до 100%, а в інший бік виходитиме за межі одиниці задовго до механічного упору.
2. **Зсув нуля:** фіксоване віднімання числа 2048 при реальному центрі 2065 створить постійну похибку `x = +0.0083` у стані спокою, викликаючи безперервний паразитичний поворот апарата.

### Триточкове кусочно-лінійне калібрування

Для коректної нормалізації підвіс калібрують за трьома опорними точками:
- `raw_min`: мінімальний зафіксований код при крайньому відхиленні вліво/вниз;
- `raw_center`: код, зафіксований у спокої при вільному положенні стіка;
- `raw_max`: максимальний зафіксований код при крайньому відхиленні вправо/вгору.

Діапазон ділиться центром на два незалежні напівінтервали. Якщо поточне значення `raw` більше або дорівнює `raw_center`, воно масштабується за правим плечем; якщо менше — за лівим:

```
якщо raw ≥ raw_center:
    x = (raw - raw_center) / (raw_max - raw_center)
інакше:
    x = (raw - raw_center) / (raw_center - raw_min)
```

Після обчислення результат жорстко обмежується (clamping) діапазоном `[-1.0, +1.0]`. Це гарантує, що при будь-яких температурних змінах нормалізований сигнал ніколи не вийде за допустимі межі:

```
x = max(-1.0, min(1.0, x))
```

## Мертва зона (Deadband): математика збереження неперервності

Навіть після ідеального триточкового калібрування ручка керування має фізичний гістерезис повернення. Якщо відхилити ручку праворуч і плавно відпустити, пружина поверне її, наприклад, у точку з нормалізованим значенням `x = +0.012`. Якщо ж відхилити ліворуч і відпустити — ручка зупиниться в точці `x = -0.009`.

Цей діапазон невизначеності (зазвичай 1–3% від повного ходу) називають механічною мертвою зоною. Якщо польотний контролер реагуватиме на ці відхилення, оператор буде змушений постійно «ловити» апарат мікрорухами руки.

### Катастрофа наївного відсікання порогу

Найпростіший спосіб усунення шуму в нулі — обнулення всіх значень, менших за поріг `db` (наприклад, `db = 0.04`):

```
if (abs(x) < db) {
    y = 0.0;
} else {
    y = x;
}
```

Такий алгоритм містить критичний дефект — **розрив першого роду (стрибок функції)** на межі мертвої зони.

![Порівняння передавальних функцій мертвої зони: наївне обнулення зі стрибком розриву проти плавного ремасштабування без стрибків](/root/course/embedded/vid-ruchky-do-komandy/img/deadband-curves.svg)
*Мертва зона: наївне відсікання (ліворуч) створює стрибок розриву величиною db у момент подолання порогу. Плавне ремасштабування (праворуч) забезпечує неперервність C⁰ — сигнал плавно зростає від нуля відразу за межею мертвої зони.*

Розглянемо, що відбувається, коли оператор плавно веде стік від центру праворуч:
- Поки `x` змінюється від 0.00 до 0.039, вихід `y` дорівнює строго 0.00.
- Щойно `x` досягає 0.040, вихід `y` миттєво стрибає з 0.00 на 0.040.

Цей стрибок означає нескінченно велику похідну сигналу в часі:

```
dy/dt → ∞
```

Диференціальна ланка PID-регулятора (`D-term`) реагує на миттєву зміну сигналу потужним ударом струму в мотори. Апарат здригається під час кожної спроби зробити плавний старт маневру.

### Плавне лінійне масштабування (C⁰-неперервність)

Щоб уникнути стрибка, мертва зона повинна не просто відсікати сигнал, а плавно розтягувати залишок робочого діапазону від 0.0 до 1.0.

Математична передавальна функція неперервної мертвої зони для додатного напівінтервалу має вигляд:

```
y = 0,                        якщо 0 ≤ x ≤ db
y = (x - db) / (1.0 - db),    якщо db < x ≤ 1.0
```

З урахуванням знака для всього діапазону `x ∈ [-1.0, +1.0]`:

```
y = sgn(x) · max(0.0, (|x| - db) / (1.0 - db))
```

Перевіримо поведінку функції на межі:
- При `x = db`: `y = (db - db) / (1.0 - db) = 0.0`.
- При `x = 1.0`: `y = (1.0 - db) / (1.0 - db) = 1.0`.

Функція є строго неперервною (належить до класу C⁰). Вихід із мертвої зони відбувається абсолютно безшовно, від нульового значення, без жодного стрибка та без паразитних сплесків диференціальної складової.

### Мертва зона крайніх упорів (Endpoint Deadband)

Аналогічна проблема існує і на крайніх межах ходу стіка. Через потрапляння пилу в карданний підвіс, температурне розширення пластикового корпусу або стиснення обмежувальних демпферів ручка може фізично не доходити до відкаліброваного значення `raw_max` на кілька десятих міліметра. Якщо мертва зона на кінцях відсутня, оператор не зможе видати 100% потужності або досягти максимальної кутової швидкості при повному упорі пальця.

Для вирішення цієї проблеми вводять кінцеву мертву зону `db_end` (зазвичай 1–2%). Робочий діапазон стіка стискається між `db_center` та `(1.0 - db_end)`:

```
якщо |x| ≤ db_center:
    y = 0.0
інакше якщо |x| ≥ (1.0 - db_end):
    y = sgn(x) · 1.0
інакше:
    y = sgn(x) · (|x| - db_center) / (1.0 - db_center - db_end)
```

Детальний математичний аналіз поведінки похідних та кривини передавальних функцій наведено у вставці [Математика кривих стіка](root:embedded/vid-ruchky-do-komandy/math-rates-derivation.md).

## Експоненційні криві (RC Expo): баланс точності та динаміки

У ручних режимах пілотування виникає фундаментальне протиріччя між двома завданнями:
1. **Прецизійне прицілювання та утримання траєкторії:** проліт у вузькі ворота, утримання лінії горизонту чи наведення камери вимагають дуже м'якого відгуку на мікрорухи пальця біля центру стіка (мала чутливість).
2. **Різкі акробатичні маневри:** виконання фліпів, ролів та швидких розворотів на 180° потребує екстремально високої кутової швидкості (до 800–1200°/с) при повному відхиленні стіка.

Якщо зв'язок між положенням стіка та кутовою швидкістю зробити строго лінійним (`ω = 1000 · x`), то відхилення пальця всього на 1 мм (близько 4% ходу) викликатиме обертання зі швидкістю 40°/с. За таких налаштувань пілот не зможе летіти по прямій лінії, оскільки природний тремор руки призводитиме до постійного хитання апарата.

### Математична модель кубічної експоненти

Для розв'язання цього конфлікту застосовують експоненційне вигинання характеристичної кривої (RC Expo). Класична формула поліноміальної експоненти являє собою зважену комбінацію лінійної та кубічної складових:

```
y = x · (1.0 - expo) + x³ · expo
```

де `expo ∈ [0.0, 1.0]` — коефіцієнт експоненти.

![Графіки кубічної експоненти при різних значеннях параметра expo від 0.0 до 0.85](/root/course/embedded/vid-ruchky-do-komandy/img/expo-curvature.svg)
*Кубічна експонента формує нелінійну криву передачі. Біля центру графік стає пологішим, забезпечуючи високу точність мікроманеврів, а на краю круто піднімається до одиниці, зберігаючи максимальний динамічний діапазон.*

Розглянемо властивості цієї функції:
- **Збереження граничних точок:** при `x = 0` маємо `y = 0`; при `x = 1` маємо `y = 1 · (1 - expo) + 1 · expo = 1`. Максимальний розмах сигналу залишається незмінним.
- **Непарність:** функція симетрична відносно нуля (`y(-x) = -y(x)`), що забезпечує ідентичну поведінку вліво і вправо.
- **Крутизна біля центру:** перша похідна функції в нулі дорівнює:
```
dy/dx |_{x=0} = 1.0 - expo
```
При `expo = 0.6` чутливість біля нуля зменшується на 60% порівняно з лінійною. Хід ручки біля центру стає у 2.5 раза «м'якшим».
- **Крутизна на краю діапазону:** перша похідна при повному відхиленні (`x = 1`) становить:
```
dy/dx |_{x=1} = (1.0 - expo) + 3.0 · expo = 1.0 + 2.0 · expo
```
При `expo = 0.6` крутизна на упорі зростає до 2.20. Завдяки цьому рух ручки в останніх 20% ходу викликає стрімке наростання кутової швидкості.

## Системи обчислення кутових швидкостей (Rate Models)

Положення стіка після проходження мертвої зони та експоненти — це безрозмірний коефіцієнт `y ∈ [-1.0, +1.0]`. Польотний контролер повинен перетворити його у фізичну величину: цільову кутову швидкість `ω_target` у градусах за секунду (`deg/s`) для акробатичного режиму (Acro/Rate) або цільовий кут нахилу `θ_target` у градусах для режиму автостабілізації (Angle).

В історії розробки автопілотів сформувалися три головні системи розрахунку швидкостей: **Betaflight SuperRate**, **Actual Rates** та **QuickRates**.

![Порівняння кривих кутової швидкості трьох моделей: лінійної, Betaflight SuperRate та Actual Rates](/root/course/embedded/vid-ruchky-do-komandy/img/rate-models-comparison.svg)
*Порівняння моделей Rates. Betaflight SuperRate використовує гіперболічну асимптоту для різкого зльоту швидкості на краю. Actual Rates забезпечує пряме незалежне задання швидкості в центрі (Center Rate) та на упорі (Max Rate).*

### 1. Betaflight SuperRate (Legacy Rates)

Історично перша популярна модель з відкритих прошивок MultiWii та ранніх версій Betaflight. Вона використовує раціональну функцію з гіперболічним знаменником:

```
x_exp = x · (1.0 - rc_expo) + x³ · rc_expo
ω = (200.0 · rc_rate · x_exp) / (1.0 - |x| · super_rate)
```

де:
- `rc_rate`: базовий лінійний коефіцієнт чутливості;
- `rc_expo`: коефіцієнт кубічної експоненти;
- `super_rate`: коефіцієнт нелінійного підсилення країв (зазвичай 0.60–0.80).

**Механізм дії:** Знаменник `(1.0 - |x| · super_rate)` зменшується при віддаленні стіка від центру. Якщо `super_rate = 0.75`, то при `x = 1.0` знаменник дорівнює `1.0 - 0.75 = 0.25`, що збільшує швидкість на краю у 4 рази.

**Головний недолік:** Всі три параметри тісно переплетені між собою. Зміна `rc_rate` одночасно змінює і чутливість біля центру, і максимальну швидкість обертання на краю. Налаштування вимагало тривалого підбору значень за таблицями.

### 2. Actual Rates (Betaflight 4.3+, ExpressLRS, EdgeTX)

Сучасний інженерний стандарт, у якому всі параметри мають пряму фізичну розмірність і повністю ізольовані один від одного:
1. `Center_Rate` — бажана крутизна відгуку біля центру (`deg/s` на одиницю ходу);
2. `Max_Rate` — точна максимальна кутова швидкість при повному відхиленні стіка (`deg/s`);
3. `Expo` — коефіцієнт пом'якшення перехідної зони (`0.0 .. 1.0`).

Формула Actual Rates використовує поліном 5-го порядку для забезпечення бездоганної плавності:

```
x_curve = x · (1.0 - expo) + x⁵ · expo
ω = x · Center_Rate + (Max_Rate - Center_Rate) · x_curve
```

**Переваги моделі Actual Rates:**
- Максимальна швидкість **завжди фіксована**: якщо задано `Max_Rate = 850 deg/s`, апарат буде робити оберт рівно зі швидкістю 850°/с на упорі, незалежно від налаштувань експоненти чи центру.
- Чутливість у центрі налаштовується прямо в градусах за секунду: значення `Center_Rate = 200 deg/s` означає, що при відхиленні стіка на 10% швидкість складе рівно 20°/с.

### Практичні профілі налаштувань для різних завдань

Завдяки ізольованості параметрів в `Actual Rates` легко будувати спеціалізовані профілі керування:

1. **FPV Freestyle (вільний політ, акробатика):**
   - `Center_Rate = 200 deg/s` (м'який центр для плавної плавності камери);
   - `Max_Rate = 850–1000 deg/s` (блискавичні фліпи та роли);
   - `Expo = 0.58–0.65` (глибока крива переходу).
2. **Drone Racing (спортивні гонки по трасі):**
   - `Center_Rate = 350–450 deg/s` (висока лінійність і швидка реакція на корекцію воріт);
   - `Max_Rate = 550–700 deg/s` (помірна максимальна швидкість для запобігання зриву траєкторії);
   - `Expo = 0.30–0.40` (майже пряма лінія відгуку).
3. **Cinematic / Long-Range (плавна кінозйомка):**
   - `Center_Rate = 80–120 deg/s` (надзвичайна стабільність горизонту);
   - `Max_Rate = 250–350 deg/s` (повна відсутність різких ривків навіть при ударі стіка об упор);
   - `Expo = 0.70–0.80` (максимальне пом'якшення перехідних режимів).

## Згладжування сигналу та усунення джитера (RC Smoothing)

Остання критична ланка конвеєра — це усунення дискретності радіоканалу.

Сучасні цифрові радіопротоколи ([CRSF](root:sys-dron/crsf-protocol), ExpressLRS, TBS Tracer) передають пакети керування з фіксованою частотою: 50 Гц, 150 Гц, 250 Гц, 500 Гц або 1000 Гц. Водночас внутрішній контур стабілізації польотного контролера (PID-loop) виконує розрахунки на значно вищій частоті — зазвичай 4000 Гц або 8000 Гц (період циклу Δt = 125 мкс).

Якщо між двома радіопакетами, що надходять кожні 4 мс (при 250 Гц), польотний контролер виконує 32 цикли PID, то протягом цих 32 циклів уставка залишається абсолютно незмінною, а потім миттєво стрибає на нове значення сходинкою.

```
Радіопакети (250 Гц):  ───[Пакет 1]───────────────────────[Пакет 2]───
Уставка PID (без фільтра): ────|________________________________|─────── (сходинка)
Похідна d(Set)/dt:     ────────▲ (величезний сплеск)────────────▲───────
```

При диференціюванні східчастого сигналу для розрахунку складової D_setpoint виникають дельта-подібні сплески. Мотори починають видавати високочастотний писк, швидко перегріваються через паразитні струми, а акумулятор втрачає ємність на марний нагрів обмоток.

### Низькочастотний фільтр PT1 (Low-Pass Filter)

Для усунення сходинок сигнал уставки пропускають крізь фільтр низьких частот першого порядку (PT1):

```
y[n] = y[n-1] + α · (x[n] - y[n-1])
```

де коефіцієнт фільтрації `α` обчислюється через частоту зрізу `f_cutoff` (зазвичай 40–60 Гц) та реальний період виклику `dt`:

```
RC = 1.0 / (2 · π · f_cutoff)
α  = dt / (RC + dt)
```

Фільтр PT1 перетворює сходинки радіопакетів на гладку неперервну траєкторію, повністю прибираючи високочастотні сплески диференціального контуру при мінімальній затримці (фазовий зсув складає всього 1.5–3 мс).

### Адаптивне згладжування та Feedforward

У сучасних прошивках RC Smoothing будується за адаптивною схемою: польотний контролер вимірює реальний інтервал надходження пакетів (RX packet interval jitter) і динамічно підлаштовує частоту зрізу `f_cutoff` фільтра. Якщо зв'язок стабільний (1000 Гц), частота зрізу піднімається до 80–100 Гц для мінімізації затримки; якщо лінк переходить у далекобійний режим 50 Гц, частота зрізу автоматично опускається до 20–25 Гц, захищаючи силові ключі від перевантаження.

```c
#include <stdint.h>
#include <stdbool.h>
#include <math.h>

/* Параметри калібрування та мертвої зони для однієї осі */
typedef struct {
    float raw_min;         /* Мінімальний відлік АЦП (наприклад, 1000.0f) */
    float raw_center;      /* Відлік спокою в центрі (наприклад, 1500.0f) */
    float raw_max;         /* Максимальний відлік АЦП (наприклад, 2000.0f) */
    float deadband_center; /* Мертва зона центру [0.0 .. 0.15], наприклад 0.04f */
    float deadband_end;    /* Мертва зона упору [0.0 .. 0.10], наприклад 0.02f */
} stick_geometry_t;

/* Налаштування моделі швидкостей Actual Rates */
typedef struct {
    float center_rate;     /* Чутливість біля нуля (deg/s), наприклад 200.0f */
    float max_rate;        /* Максимальна швидкість (deg/s), наприклад 850.0f */
    float expo;            /* Експонента [0.0 .. 1.0], наприклад 0.55f */
} stick_rates_t;

/* Стан фільтра згладжування PT1 */
typedef struct {
    float state;           /* Поточний згладжений вихід */
    float cutoff_hz;       /* Частота зрізу (Гц), наприклад 45.0f */
} stick_filter_t;

/* Обробка одного відліку осі: повертає цільову кутову швидкість у deg/s */
float process_stick_axis(const stick_geometry_t *geom,
                         const stick_rates_t *rates,
                         stick_filter_t *filt,
                         float raw_input,
                         float dt_sec)
{
    /* 1. Триточкова нормалізація в діапазон [-1.0 .. +1.0] */
    float norm = 0.0f;
    if (raw_input >= geom->raw_center) {
        float span = geom->raw_max - geom->raw_center;
        norm = (span > 1e-3f) ? (raw_input - geom->raw_center) / span : 0.0f;
    } else {
        float span = geom->raw_center - geom->raw_min;
        norm = (span > 1e-3f) ? (raw_input - geom->raw_center) / span : 0.0f;
    }
    if (norm > 1.0f) norm = 1.0f;
    if (norm < -1.0f) norm = -1.0f;

    /* 2. Плавне ремасштабування мертвої зони без розривів */
    float sign = (norm >= 0.0f) ? 1.0f : -1.0f;
    float abs_x = fabsf(norm);
    float active_x = 0.0f;

    if (abs_x > geom->deadband_center) {
        if (abs_x >= (1.0f - geom->deadband_end)) {
            active_x = 1.0f;
        } else {
            float range = 1.0f - geom->deadband_center - geom->deadband_end;
            active_x = (range > 1e-3f) ? (abs_x - geom->deadband_center) / range : 0.0f;
        }
    }
    float stick_pos = sign * active_x;

    /* 3. Модель Actual Rates з кубічно-степеневою експонентою */
    float x = fabsf(stick_pos);
    float x5 = x * x * x * x * x;
    float curve = x * (1.0f - rates->expo) + x5 * rates->expo;
    float raw_rate = sign * (x * rates->center_rate + (rates->max_rate - rates->center_rate) * curve);

    /* 4. Низькочастотна фільтрація PT1 */
    if (dt_sec > 0.0f && filt->cutoff_hz > 0.0f) {
        float rc = 1.0f / (2.0f * 3.14159265f * filt->cutoff_hz);
        float alpha = dt_sec / (rc + dt_sec);
        if (alpha > 1.0f) alpha = 1.0f;
        filt->state += alpha * (raw_rate - filt->state);
    } else {
        filt->state = raw_rate;
    }

    return filt->state;
}
```

```cpp
#include <cmath>
#include <algorithm>
#include <numbers>

namespace flight_control {

struct StickGeometry {
    float raw_min{1000.0f};
    float raw_center{1500.0f};
    float raw_max{2000.0f};
    float deadband_center{0.04f}; // 4% мертва зона в центрі
    float deadband_end{0.02f};    // 2% мертва зона на упорі
};

struct ActualRates {
    float center_rate{200.0f};    // deg/s навколо нуля
    float max_rate{850.0f};       // deg/s на крайньому упорі
    float expo{0.55f};            // коефіцієнт пом'якшення [0..1]
};

class AxisProcessor {
public:
    constexpr AxisProcessor(StickGeometry geom, ActualRates rates, float cutoff_hz = 45.0f) noexcept
        : geom_{geom}, rates_{rates}, cutoff_hz_{cutoff_hz} {}

    [[nodiscard]] float process(float raw_input, float dt_sec) noexcept {
        const float norm = normalize(raw_input);
        const float active_stick = apply_deadband(norm);
        const float target_rate = calculate_rate(active_stick);
        return apply_pt1_filter(target_rate, dt_sec);
    }

    void reset() noexcept { filter_state_ = 0.0f; }
    [[nodiscard]] float current_rate() const noexcept { return filter_state_; }

private:
    [[nodiscard]] float normalize(float raw) const noexcept {
        float norm = 0.0f;
        if (raw >= geom_.raw_center) {
            const float span = geom_.raw_max - geom_.raw_center;
            norm = (span > 1e-3f) ? (raw - geom_.raw_center) / span : 0.0f;
        } else {
            const float span = geom_.raw_center - geom_.raw_min;
            norm = (span > 1e-3f) ? (raw - geom_.raw_center) / span : 0.0f;
        }
        return std::clamp(norm, -1.0f, 1.0f);
    }

    [[nodiscard]] float apply_deadband(float norm) const noexcept {
        const float abs_x = std::abs(norm);
        if (abs_x <= geom_.deadband_center) {
            return 0.0f;
        }
        if (abs_x >= (1.0f - geom_.deadband_end)) {
            return std::copysign(1.0f, norm);
        }
        const float range = 1.0f - geom_.deadband_center - geom_.deadband_end;
        if (range < 1e-3f) {
            return 0.0f;
        }
        return std::copysign((abs_x - geom_.deadband_center) / range, norm);
    }

    [[nodiscard]] float calculate_rate(float stick_pos) const noexcept {
        const float x = std::abs(stick_pos);
        const float x5 = x * x * x * x * x;
        const float curve = x * (1.0f - rates_.expo) + x5 * rates_.expo;
        const float rate = x * rates_.center_rate + (rates_.max_rate - rates_.center_rate) * curve;
        return std::copysign(rate, stick_pos);
    }

    [[nodiscard]] float apply_pt1_filter(float target, float dt_sec) noexcept {
        if (dt_sec <= 0.0f || cutoff_hz_ <= 0.0f) {
            filter_state_ = target;
            return filter_state_;
        }
        constexpr float two_pi = 2.0f * std::numbers::pi_v<float>;
        const float rc = 1.0f / (two_pi * cutoff_hz_);
        const float alpha = std::clamp(dt_sec / (rc + dt_sec), 0.0f, 1.0f);
        filter_state_ += alpha * (target - filter_state_);
        return filter_state_;
    }

    StickGeometry geom_;
    ActualRates rates_;
    float cutoff_hz_{45.0f};
    float filter_state_{0.0f};
};

} // namespace flight_control
```

## Інженерний підсумок

Перетворення сигналу стіка керування — це послідовне вирішення конфліктів між фізикою апаратної частини та ергономікою людського керування:
1. **Апаратний шар (АЦП та давачі):** вирішує проблему шуму квантування та розкиду напруг опорних джерел через роздільне триточкове калібрування лівого та правого напівінтервалів та апаратну RC-фільтрацію наведень.
2. **Геометричний шар (Мертва зона та експонента):** ліквідує механічний гістерезис пружин та фізіологічний тремор пальця. Плавне лінійне масштабування забезпечує C⁰-неперервність без ударів по диференційному контуру, а кубічна експонента ізолює прецизійний мікроконтроль від швидких поворотів на упорах.
3. **Динамічний шар (Rates та RC Smoothing):** переводить геометричне положення у фізичні одиниці обертання (`deg/s`) через модель Actual Rates та усуває часовий джитер сходинок радіопакетів за допомогою низькочастотного фільтра PT1.

Коректно побудований конвеєр гарантує, що контур стабілізації отримує математично гладку, фізично детерміновану та передбачувану уставку без паразитних сплесків та нагріву силових приводів.
