# ⚙️ Тепловий регулятор заряду: від кількох NTC до машини станів

У темі ми вже зустріли скелет захисту — функцію `charge_limit_ma()`, що за температурою найгарячішої комірки повертає дозволений струм заряду. Вона показала ідею foldback в одному рядку лінійної арифметики. Але між тією навчальною функцією й кодом, який не соромно поставити в живий пакет, лежить ціла прірва дрібних, але злих питань. Звідки взагалі береться та `t_c10`? Як із напруги на NTC дістати градуси? Що буде, коли давач обірветься посеред заряду? Чому проста лінійна функція змусить реле клацати десять разів на секунду на самому порозі? І як вплести сюди заборону заряду на морозі, та ще й опційний підігрів?

Тут ми розгорнемо `charge_limit_ma()` у **повний робочий модуль** теплового регулятора заряду. Підемо знизу вгору, як іде сам сигнал: спершу прочитаємо NTC через АЦП і перетворимо опір на температуру, тоді відфільтруємо шум і виберемо найгарячішу комірку, потім зробимо foldback стійким до «дзвону» через гістерезис, і нарешті оберемо все це в скінченну машину станів, яка веде пакет крізь мороз, нормальну роботу, перегрів і відмову давача. Кожен крок — з реальним кодом прошивки й з пасткою, яку він закриває.

![Шлях сигналу від кількох NTC через АЦП, фільтр і перетворення в градуси до вибору максимуму й foldback, що дає дозволений струм](/root/course/embedded/battery-pack-thermal/img/signal-chain.svg)
*Сигнал іде ланцюжком окремих перетворень: опір NTC → напруга на дільнику → код АЦП → відфільтроване значення → температура в °C → максимум по всіх давачах → дозволений струм. Кожна ланка — окрема функція, а рішення завжди ухвалюємо за найгарячішою коміркою, не за середньою.*

### Задача

Сформулюймо її чесно й повністю, бо саме повнота тут — половина роботи. Нам треба прошивка, яка:

- читає **кілька** NTC-термісторів (по одному на групу комірок), кожен через свій канал АЦП;
- перетворює виміряне на **температуру в градусах**, попри те що NTC різко нелінійний;
- **фільтрує** шум АЦП і відсіює очевидну маячню (давач закоротило, обірвало);
- бере **максимум** температур — бо керувати треба за найгарячішою коміркою;
- плавно **зрізає** струм заряду в гарячій зоні (foldback) і **не дозволяє** «дзвону» на порозі;
- **забороняє** заряд на морозі (нижче 0 °C літій незворотно псується дендритами), а якщо є нагрівач — вмикає **підігрів**;
- за будь-якої **відмови давача** падає в безпечний стан, а не керує за брехливим числом.

Це вже не «формула струму», а маленька підсистема з пам'яттю стану. І писати її треба так, наче від неї залежить пакет вартістю як пів пристрою, — бо так і є.

### Ідея

Розкладемо задачу на шари, кожен з яких нічого не знає про сусідів, крім свого входу й виходу. Знизу — **сире залізо**: АЦП дає код, ми тлумачимо його як опір, опір — як температуру. Над ним — **гігієна даних**: усереднення проти шуму, перевірка на абсурд проти відмови. Ще вище — **звід**: з багатьох температур робимо одну, що нас цікавить, — максимум. І на вершині — **рішення**: скінченна машина станів, що дивиться на цю одну температуру й веде політику заряду.

Чому саме так, а не однією великою функцією «прочитав і вирішив»? Бо кожен шар має власні пастки, які найлегше закрити окремо. Перетворення опору на градуси — це чиста математика, її хочеться написати раз і перевірити таблицею. Фільтрація — це боротьба з фізикою АЦП, вона однакова для будь-якого давача. А машина станів — це логіка безпеки, і її треба тримати настільки простою й оглядовою, щоб у ній не лишилося місця для прихованого «а що, як…». Змішаєш усе докупи — і не доведеш, що в гарячій гілці нема дірки.

Серце рішення — та сама ідея foldback, що в темі, але з двома суттєвими доповненнями. Перше: **гістерезис** — поріг «вмикання» захисту й поріг «вимикання» рознесені, щоб дрібне тремтіння температури біля межі не перемикало стан туди-сюди. Друге: **окрема холодна гілка** — мороз вимагає не зрізання струму, а повної заборони заряду (і, можливо, підігріву), тож це інший стан, а не просто «струм = 0».

![Профіль дозволеного струму від температури: повний у вікні 0..35°, лінійне зрізання 35..45°, нуль за межами; гарячий поріг має гістерезис — відновлення лише на 42°](/root/course/embedded/battery-pack-thermal/img/foldback-hyst.svg)
*Дозволений струм як функція температури найгарячішої комірки. У вікні 0..35 °C — повний струм; від 35 до 45 °C — лінійне зрізання до нуля; нижче 0 °C і вище 45 °C — заряд заборонено. Гарячий поріг із гістерезисом: зрізавши струм на 45°, повертаємо повний лише коли комірка охолоне до 42°, інакше система «дзвенить» на самій межі.*

## Шар 1: від коду АЦП до градусів

Почнімо з найнижчого. NTC увімкнено звичайним дільником напруги: від живлення йде постійний резистор Rₚ, від його низу до землі — NTC, а точку між ними читає АЦП. Коли NTC нагрівається, його опір падає, напруга в точці змінюється, АЦП бачить інший код. Перше завдання — з коду дістати **опір** NTC.

Нехай АЦП 12-бітний (коди 0…4095) і вимірює відносно того ж живлення, що й живить дільник. Тоді живлення скорочується — і це велике полегшення, бо нам байдуже точне значення Vcc:

```
Дільник: Vadc = Vcc · R_ntc / (R_pull + R_ntc)
Код АЦП: code = 4095 · Vadc / Vcc = 4095 · R_ntc / (R_pull + R_ntc)

Звідси опір NTC:
  R_ntc = R_pull · code / (4095 − code)
```

```c
#include <stdint.h>

#define ADC_MAX     4095        // 12-бітний АЦП
#define R_PULL_OHM  10000       // верхнє плече дільника, Ом

#define OHM_OPEN   (-1)         // обрив давача (опір «нескінченний»)
#define OHM_SHORT  (-2)         // коротке замикання давача (опір нульовий)

// Код АЦП → опір NTC в омах. У нашому дільнику NTC стоїть знизу до землі,
// тож фізика крайніх кодів однозначна:
//   code = ADC_MAX  →  Vadc = Vcc  →  опір NTC «нескінченний»  →  ОБРИВ;
//   code = 0        →  Vadc = 0    →  опір NTC нульовий         →  КЗ.
int32_t adc_to_ohm(uint16_t code) {
    if (code >= ADC_MAX)  return OHM_OPEN;       // прилипло до Vcc → обрив
    if (code == 0)        return OHM_SHORT;      // прилипло до нуля → КЗ
    return (int32_t)R_PULL_OHM * code / (ADC_MAX - code);
}
```

Зверніть увагу: ще тут, у найнижчій функції, ми ловимо **дві відмови залізом** — обрив і коротке замикання давача. Логіка проста, якщо твердо триматися схеми: NTC у нас знизу дільника, до землі. Обірвався NTC — його гілка зникла, верхній резистор тягне точку вимірювання вгору до Vcc, АЦП бачить майже максимальний код. Закоротився — точка падає на землю, код майже нульовий. Справний давач у робочому діапазоні **ніколи** не дає крайнього коду (його опір лежить між сотнями ом і сотнею кілоом, тобто Vadc завжди десь усередині), тож обидва краї — це гарантований сигнал біди, а не реальна температура. Повертаємо для них окремі мітки `OHM_OPEN` / `OHM_SHORT`, щоб вищі шари відрізнили відмову давача від справжнього виміру. (Якби NTC стояв зверху дільника, краї помінялися б місцями — тому орієнтацію треба прив'язувати до конкретної схеми, а не запам'ятовувати «нуль = КЗ».)

Тепер головне перетворення: **опір → температура**. NTC жорстко нелінійний, прямої формули «помножити на коефіцієнт» тут немає. Є два усталені шляхи.

**Перший — рівняння Стейнгарта-Гарта.** Це найточніша аналітична модель опір-температура для NTC; її 1968 року вивели американські океанографи **Джон С. Стейнгарт і Стенлі Р. Гарт** (це усталений факт — рівняння носить їхні імена й опубліковане в *Deep-Sea Research* саме того року). Виглядає так:

```
1/T = A + B·ln(R) + C·(ln R)³        T — у кельвінах, R — опір NTC
```

Коефіцієнти A, B, C виробник або дає в даташиті, або їх рахують із трьох вимірів опору при трьох температурах (бажано рознесених щонайменше на 10°). Модель тримає точність близько ±0.15 °C у діапазоні −50…+150 °C — більш ніж досить.

**Другий — спрощене β-рівняння** (англ. *B-parameter equation*), окремий випадок попереднього з одним коефіцієнтом β:

```
1/T = 1/T₀ + (1/β)·ln(R/R₀)          T₀ = 298.15 K (25°C), R₀ — опір при 25°C
```

Воно потребує лише двох чисел із даташита (β і R₀) і дає точність порядку ±5 °C на повному діапазоні — для теплового захисту цього зазвичай вистачає, бо нам важлива не абсолютна точність, а правильне спрацювання на порогах у вузькому вікні навколо кімнатної температури.

Але обидва рівняння тягнуть `log()` і ділення з плаваючою комою — а ми домовилися не пускати float у гарячий шлях прошивки. Тому в реальному регуляторі роблять третє: **таблицю опір→температура** з лінійною інтерполяцією між вузлами. Таблицю рахують один раз (хоч тим самим Стейнгартом-Гартом на ПК), зашивають у flash, а в рантаймі лишається пошук і множення-ділення цілими. Так ми дістаємо точність аналітичної моделі за ціну кількох цілих операцій:

```c
// Вузли таблиці опір→температура для конкретного NTC (напр. 10 кОм, β≈3950).
// Опір спадає з температурою, тож таблиця впорядкована за спаданням опору.
// Температура — в десятих градуса Цельсія (щоб не тягнути float).
typedef struct { int32_t ohm; int16_t t_c10; } ntc_point_t;

static const ntc_point_t NTC_TAB[] = {
    { 96358, -200 },  // -20.0 °C
    { 55046, -100 },  // -10.0 °C
    { 32554,    0 },  //   0.0 °C
    { 19873,  100 },  //  10.0 °C
    { 12488,  200 },  //  20.0 °C
    { 10000,  250 },  //  25.0 °C  (опорна точка)
    {  8059,  300 },  //  30.0 °C
    {  5327,  400 },  //  40.0 °C
    {  3603,  500 },  //  50.0 °C
    {  2488,  600 },  //  60.0 °C
    {  1751,  700 },  //  70.0 °C
};
#define NTC_TAB_N  (int)(sizeof(NTC_TAB) / sizeof(NTC_TAB[0]))

// Опір (Ом) → температура (десяті °C) лінійною інтерполяцією за таблицею.
// Повертає INT16_MIN як ознаку «поза таблицею / неможливе значення».
int16_t ohm_to_c10(int32_t ohm) {
    if (ohm <= 0) return INT16_MIN;                  // КЗ або хибний нуль

    // вище за найбільший опір у таблиці — холодніше за нижній край
    if (ohm >= NTC_TAB[0].ohm)            return NTC_TAB[0].t_c10;
    // нижче за найменший опір — гарячіше за верхній край
    if (ohm <= NTC_TAB[NTC_TAB_N - 1].ohm) return NTC_TAB[NTC_TAB_N - 1].t_c10;

    // знайти сусідні вузли, між якими лежить опір (таблиця спадна за опором)
    for (int i = 0; i < NTC_TAB_N - 1; i++) {
        int32_t r_hi = NTC_TAB[i].ohm;       // більший опір (холодніше)
        int32_t r_lo = NTC_TAB[i + 1].ohm;   // менший опір (гарячіше)
        if (ohm <= r_hi && ohm >= r_lo) {
            int32_t t_hi = NTC_TAB[i].t_c10;     // нижча температура
            int32_t t_lo = NTC_TAB[i + 1].t_c10; // вища температура
            // лінійна інтерполяція: чим ближче опір до r_lo, тим гарячіше
            int32_t span_r = r_hi - r_lo;
            int32_t span_t = t_lo - t_hi;
            return (int16_t)(t_hi + (r_hi - ohm) * span_t / span_r);
        }
    }
    return INT16_MIN;   // сюди не дійти, але хай компілятор спить спокійно
}
```

> 🔧 **Навіщо це.** Таблиця замість формули — не лінь, а інженерне рішення. Вона прибирає float із гарячого шляху (на дрібному МК без FPU кожен `log()` коштує сотні тактів), робить поведінку **детермінованою** за часом (пошук завжди обмежений довжиною таблиці), і дозволяє підкрутити криву під конкретний екземпляр давача, просто замінивши вузли. Той самий прийом — заздалегідь порахована таблиця замість дорогої функції в рантаймі — повертатиметься скрізь у прошивці, де точність потрібна, а часу й коми немає.

## Шар 2: фільтрація шуму й самонагрів давача

Сирий код АЦП **тремтить**. Останні один-два біти 12-бітного перетворювача майже завжди шумлять — від наведень, від брижів живлення, від самої природи перетворення. Якщо годувати foldback сирим значенням, дозволений струм смикатиметься на кожному вимірі навіть за стабільної температури. Лікуємо це усередненням, але не абияким.

Найпростіше — **середнє по кількох вимірах**. Беремо N зчитувань поспіль, додаємо, ділимо. Це гасить випадковий шум у √N разів: чотири виміри — удвічі тихіше, шістнадцять — учетверо. Дешево й зрозуміло. Але середнє має ваду: один **викид** (різкий збій, наведення від силового ключа) тягне результат за собою. Тому для значення, від якого залежить безпека, краще **медіана** — серединний елемент відсортованої вибірки. Медіана повністю ігнорує поодинокі викиди: хоч один вимір стрибне до стелі, на серединний елемент це не вплине.

```c
// Медіана з невеликої вибірки кодів АЦП (стійка до поодиноких викидів).
// Сортування вставками — для 5–9 елементів це швидше за будь-яку «розумну» сортувалку.
uint16_t adc_median(uint16_t *buf, int n) {
    for (int i = 1; i < n; i++) {
        uint16_t key = buf[i];
        int j = i - 1;
        while (j >= 0 && buf[j] > key) { buf[j + 1] = buf[j]; j--; }
        buf[j + 1] = key;
    }
    return buf[n / 2];          // серединний елемент відсортованого масиву
}
```

Часто роблять обидва: спершу медіана з невеликої вибірки (вбиває викиди), тоді ще й **експоненційне згладжування** в часі (вбиває дрижання між циклами). Експоненційний фільтр — це один рядок і одна змінна стану: нове згладжене значення тягнеться до свіжого виміру на частку α.

```c
// Експоненційне згладжування в часі: state += (sample - state) >> SHIFT.
// SHIFT=3 означає α≈1/8 — повільний, спокійний фільтр; менший SHIFT — жвавіший.
// Працюємо з цілими; зсув замість ділення тримає це дешевим.
#define EMA_SHIFT  3
int32_t ema_step(int32_t state, int32_t sample) {
    return state + ((sample - state) >> EMA_SHIFT);
}
```

Тепер про підступнішу пастку — **самонагрів NTC**. Через термістор тече вимірювальний струм (бо на ньому ж падає напруга, яку ми читаємо), а будь-який струм на опорі виділяє тепло Джоуля. NTC гріє сам себе — і показує температуру **вищу за справжню**. Скільки саме — задає тепловий показник розсіяння давача (англ. *dissipation constant*, δ), типово близько 1–7 мВт/°C для дрібних NTC: стільки потужності треба розсіяти на давачі, щоб він нагрівся на градус понад середовище.

**Worked-приклад: на скільки NTC перегріває сам себе.** Дільник на 3.3 В, верхній резистор 10 кОм, NTC при кімнатній теж близько 10 кОм. Показник розсіяння давача δ = 2 мВт/°C.

```
Струм через дільник (обидва плеча по 10 кОм):
  I = 3.3 В / (10000 + 10000) = 0.165 мА

Потужність, розсіяна на самому NTC:
  P = I² · R = (0.000165)² · 10000 = 0.000272 Вт = 0.27 мВт

Самонагрів давача:
  ΔT = P / δ = 0.27 мВт / 2 (мВт/°C) = 0.14 °C
```

Чотирнадцять сотих градуса — дрібниця, нею можна знехтувати. Але зменшіть верхній резистор до 1 кОм заради «кращого сигналу» — струм зросте вдесятеро, потужність у сто разів, самонагрів стане понад градус і поповзе вгору на спеці, де опір NTC малий і струм ще більший. Звідси правило: **верхній резистор беруть досить великим** (десятки кілоом), щоб вимірювальний струм був мізерний, або взагалі живлять дільник **імпульсно** — вмикають живлення NTC лише на час виміру, а решту часу струм не тече зовсім. Останнє ще й економить енергію в режимі сну, що для автономного пакета важливо окремо.

> 🔧 **Навіщо це.** Самонагрів — класична пастка «виміряв і не повірив очам»: пакет холодний, а давач уперто показує на градус-два більше, і foldback зрізає струм даремно. Зрозумівши механізм (вимірювальний струм → P=I²R → ΔT = P/δ), її лікують одним рішенням на етапі схеми — великим верхнім резистором чи імпульсним живленням, — а не латками в коді. Це той випадок, коли правильна електроніка економить тонни прошивки.

## Шар 3: звід у одну температуру й перевірка на відмову

Маючи по температурі з кожного давача, зводимо їх в одну, що нас цікавить, — **максимум**. Чому максимум, а не середнє, ми вже з'ясували в темі: керувати треба за найгарячішою коміркою, бо саме вона першою дійде до небезпеки й першою почне передчасно старіти. Середнє приховало б гарячу точку за прохолодними сусідками — і ми б спокійно жарили струмом комірку, що вже за порогом.

Але перш ніж брати максимум, кожне значення треба **перевірити на справність давача**. Це найважливіша й найчастіше забута частина. Давач — фізична деталь на дроті, що йде крізь пакет; дріт перетирається, роз'єм окислюється, паяння тріскається від вібрації. Відмова давача **небезпечніша за відмову обчислень**: якщо обірваний NTC «показує» −20 °C, наївний регулятор вирішить, що пакет крижаний, і дасть повний струм заряду посеред перегріву. Тиха брехня давача гірша за явну поломку.

Тож кожне значення проганяємо крізь три сита: чи не крайній код АЦП (обрив/КЗ ми вже мітили в `adc_to_ohm`); чи опір узагалі в межах таблиці (`ohm_to_c10` вертає `INT16_MIN` за межами); і чи результат у фізично можливому вікні для цього застосунку (комірка ніяк не буде −40 чи +120 у нормі — таке значить, що давач бреше).

```c
#include <stdbool.h>

#define N_SENSORS    4              // давачів у пакеті
#define T_PLAUSIBLE_LO  (-300)      // −30.0 °C: холодніше — давач бреше
#define T_PLAUSIBLE_HI   (800)      // +80.0 °C: гарячіше — або втеча, або брехня

// Один давач: код АЦП → температура з повною перевіркою справності.
// valid=false означає «цьому давачу вірити не можна».
typedef struct { int16_t t_c10; bool valid; } reading_t;

reading_t read_sensor(uint16_t adc_code) {
    reading_t r = { .t_c10 = 0, .valid = false };

    int32_t ohm = adc_to_ohm(adc_code);
    if (ohm <= 0) return r;                       // обрив або КЗ давача

    int16_t t = ohm_to_c10(ohm);
    if (t == INT16_MIN) return r;                 // поза таблицею

    if (t < T_PLAUSIBLE_LO || t > T_PLAUSIBLE_HI) // фізично неможливо
        return r;

    r.t_c10 = t;
    r.valid = true;
    return r;
}

// Звід кількох давачів: максимум серед СПРАВНИХ. Окремо повертаємо,
// скільки давачів живі — за цим машина станів вирішить, чи можна довіряти пакету.
typedef struct { int16_t t_max_c10; int n_valid; } pack_temp_t;

pack_temp_t pack_temperature(const uint16_t *codes) {
    pack_temp_t out = { .t_max_c10 = INT16_MIN, .n_valid = 0 };
    for (int i = 0; i < N_SENSORS; i++) {
        reading_t r = read_sensor(codes[i]);
        if (!r.valid) continue;
        out.n_valid++;
        if (r.t_c10 > out.t_max_c10)
            out.t_max_c10 = r.t_c10;
    }
    return out;
}
```

Двозначна політика тут навмисна. Ми повертаємо не лише максимум, а й **скільки давачів живі**. Бо «всі чотири мовчать» і «один із чотирьох мовчить» — це різні ситуації. Якщо живий бодай один давач на групу, максимум по живих усе ще осмислений (ми просто втратили видимість частини пакета — небезпечно, але керувати ще можна обережно). А якщо не лишилося **жодного** — ми сліпі, і єдине безпечне рішення — спинити заряд, бо керувати наосліп гарячим пакетом не можна. Це рішення ухвалить машина станів; шар зводу лише чесно доповідає, що бачить.

## Шар 4: машина станів регулятора

Тепер вершина — логіка, що дивиться на `pack_temperature()` і веде політику заряду. Її природно оформити **скінченною машиною станів** (англ. *finite state machine*) — тим самим інструментом, яким [машина станів веде USB-PD-рукостискання](root:embedded/pd-sink-design/proj-pd-state-machine.md): кожен стан — це «де ми зараз», кожна подія (нова температура, відмова давача) — перехід. Чому не «великий `if`»? Бо в захисті важлива не лише поточна дія, а й **пам'ять про те, де ми були**: саме пам'ять дає гістерезис (зрізали струм — пам'ятаємо це й вертаємо повний лише після охолодження) і безпечні переходи (з аварії не вискакуємо назад миттєво).

Наші стани:

- **`COLD_WAIT`** — нижче 0 °C. Заряд заборонено. Якщо є нагрівач — гріємо; як ні — просто чекаємо тепла.
- **`CHARGE`** — робоче вікно (0…35 °C). Повний дозволений струм.
- **`FOLDBACK`** — гаряче (35…45 °C). Лінійно зрізаємо струм за нашою формулою.
- **`STOP`** — перегрів (≥45 °C) або занадто холодно без нагрівача. Струм нуль, чекаємо безпечної зони.
- **`FAULT`** — давачам вірити не можна (жоден не живий). Струм нуль, поки давачі не повернуться.

![Машина станів регулятора: головна лінія COLD_WAIT → CHARGE → FOLDBACK, перегрів веде в STOP, мороз повертає в COLD_WAIT, а відмова давача з будь-якого стану кидає у FAULT](/root/course/embedded/battery-pack-thermal/img/thermal-fsm.svg)
*Уперед нагріванням: COLD_WAIT (мороз, грій/чекай) → CHARGE (повний струм) → FOLDBACK (зрізаю) → STOP (перегрів). Назад — за охолодженням, але через гістерезисні пороги (FOLDBACK вертається в CHARGE лише нижче 33°, STOP — лише нижче 42°), щоб система не «дзвеніла». Окрема червона шина: обрив, КЗ чи абсурдне значення давача кидають у FAULT з будь-якого стану — там струм завжди нуль.*

Ключова деталь — **гістерезис на кожному порозі**. Поріг «вгору» (вмикаємо суворіший стан) і поріг «вниз» (повертаємось до м'якшого) рознесені на кілька десятих градуса. Без цього температура, що тремтить рівно на 45.0°, перемикала б STOP↔FOLDBACK на кожному вимірі — реле клацало б, струм смикався б, а в логах був би хаос. Це і є той «дзвін» (англ. *chatter*), про який попереджала тема. Гістерезис розриває петлю: щоб зайти в STOP, треба перетнути 45.0° вгору, а щоб вийти — впасти аж до 42.0°; між ними є «мертва зона», де стан не міняється.

```c
// ── Пороги (десяті °C). Кожен має пару: спрацювання / відпускання (гістерезис). ──
#define T_COLD_ENTER     0      //  0.0 °C: нижче — заряд заборонено (вхід у COLD)
#define T_COLD_EXIT     20      //  2.0 °C: вийти з COLD лише коли потеплішало (гіст.)
#define T_FOLD_ENTER   350      // 35.0 °C: вище — починаємо зрізати струм
#define T_FOLD_EXIT    330      // 33.0 °C: повертаємось до повного струму (гіст.)
#define T_STOP_ENTER   450      // 45.0 °C: вище — повна заборона
#define T_STOP_EXIT    420      // 42.0 °C: відновлюємо зрізаний заряд (гіст.)

#define I_CHARGE_MAX  4000      // повний струм заряду, мА

typedef enum { ST_COLD_WAIT, ST_CHARGE, ST_FOLDBACK, ST_STOP, ST_FAULT } therm_state_t;

// Контекст регулятора живе між викликами (пам'ять машини станів).
typedef struct {
    therm_state_t state;
    int32_t       charge_ma;   // поточний дозволений струм заряду
    bool          heater_on;   // чи увімкнено нагрівач (якщо він є)
} regulator_t;

#define HAS_HEATER  1          // 0, якщо нагрівача в пакеті немає

// Лінійне зрізання у вікні FOLD..STOP (та сама ідея, що charge_limit_ma у темі).
static int32_t foldback_ma(int16_t t_c10) {
    if (t_c10 <= T_FOLD_ENTER) return I_CHARGE_MAX;
    if (t_c10 >= T_STOP_ENTER) return 0;
    int32_t span  = T_STOP_ENTER - T_FOLD_ENTER;   // 100 десятих = 10 °C
    int32_t above = t_c10 - T_FOLD_ENTER;
    return (int32_t)I_CHARGE_MAX * (span - above) / span;
}

// Один крок машини: викликати періодично (напр. раз на 100 мс) зі свіжими кодами АЦП.
void regulator_step(regulator_t *reg, const uint16_t *adc_codes) {
    pack_temp_t pt = pack_temperature(adc_codes);

    // ── Найвищий пріоритет: жоден давач не живий → сліпі → FAULT. ──
    if (pt.n_valid == 0) {
        reg->state     = ST_FAULT;
        reg->charge_ma = 0;
        reg->heater_on = false;          // наосліп не гріємо й не заряджаємо
        return;
    }

    int16_t t = pt.t_max_c10;            // керуємо за найгарячішою живою коміркою

    switch (reg->state) {

    case ST_FAULT:
        // давачі повернулись — перезаходимо в логіку через безпечний STOP
        reg->state = ST_STOP;
        reg->charge_ma = 0;
        break;

    case ST_COLD_WAIT:
        reg->charge_ma = 0;                          // на морозі заряд заборонено
        reg->heater_on = HAS_HEATER ? true : false;  // гріємо, якщо вміємо
        if (t >= T_COLD_EXIT) {                       // потеплішало понад гіст-поріг
            reg->state     = ST_CHARGE;
            reg->heater_on = false;
        }
        break;

    case ST_CHARGE:
        reg->charge_ma = I_CHARGE_MAX;
        if (t < T_COLD_ENTER)       reg->state = ST_COLD_WAIT;   // похолодало
        else if (t >= T_FOLD_ENTER) reg->state = ST_FOLDBACK;    // нагрілося
        break;

    case ST_FOLDBACK:
        reg->charge_ma = foldback_ma(t);
        if (t >= T_STOP_ENTER)      reg->state = ST_STOP;        // перегрів
        else if (t < T_FOLD_EXIT)   reg->state = ST_CHARGE;      // охолов (гіст.)
        break;

    case ST_STOP:
        reg->charge_ma = 0;
        if (t < T_COLD_ENTER)       reg->state = ST_COLD_WAIT;   // впав у мороз
        else if (t < T_STOP_EXIT)   reg->state = ST_FOLDBACK;    // охолов (гіст.)
        break;
    }
}
```

Розберімо, чому переходи саме такі. З `CHARGE` ми йдемо вгору в `FOLDBACK` на 35.0°, але **назад** із `FOLDBACK` у `CHARGE` — лише на 33.0°: ось він, гістерезис, та сама «мертва зона» 33…35°. Так само `STOP` віддає назад у `FOLDBACK` тільки на 42.0°, хоча зайшли ми туди на 45.0°. Холодна гілка симетрична: у `COLD_WAIT` падаємо на 0.0°, а вибираємось аж на 2.0° — щоб давач, що тремтить біля нуля, не вмикав-вимикав заряд літію, для якого перетин нуля — це питання незворотного псування.

Окремо — **повернення з `FAULT`**. Коли давачі ожили, ми не стрибаємо прямо в `CHARGE` (раптом за час сліпоти пакет перегрівся?), а заходимо через `STOP` — найобережніший робочий стан, з якого наступний крок уже спокійно перерахує температуру й роздасть машину далі. Принцип «з аварії — у найбезпечніший стан, не назад туди, де були» — той самий, що в [PD-машині падіння на безпечні 5 В](root:embedded/pd-sink-design/proj-pd-state-machine.md): коли щось пішло не так, повертайся не до оптимального, а до завідомо безпечного.

## Як це зібрати докупи

Усі чотири шари сходяться в одному періодичному виклику. Десь у головному циклі чи в перериванні таймера, скажімо, раз на 100 мс, прошивка:

```c
// Глобальний контекст регулятора (пам'ять між викликами).
static regulator_t g_reg = { .state = ST_STOP, .charge_ma = 0, .heater_on = false };

// Викликати періодично (раз на ~100 мс).
void thermal_tick(void) {
    uint16_t codes[N_SENSORS];

    // 1) Зчитати кожен давач: медіана кількох вимірів проти викидів.
    for (int s = 0; s < N_SENSORS; s++) {
        uint16_t samp[5];
        for (int k = 0; k < 5; k++)
            samp[k] = adc_read(NTC_CH[s]);     // апаратне читання каналу
        codes[s] = adc_median(samp, 5);
    }

    // 2) Прокрутити машину станів (вона сама зробить шари 1–3 усередині).
    regulator_step(&g_reg, codes);

    // 3) Застосувати рішення до заліза.
    charger_set_current_ma(g_reg.charge_ma);   // задати ліміт зарядці
    heater_set(g_reg.heater_on);               // увімкнути/вимкнути нагрівач
}
```

Початковий стан — навмисно `ST_STOP`, а не `ST_CHARGE`: поки регулятор не зробив жодного виміру, він не має права дозволяти струм. Це загальний принцип безпечного старту — **прокинутись у найобережнішому стані** й послабити обмеження лише за свіжими, перевіреними даними. Перший же `thermal_tick()` прочитає температуру й переведе машину в правильний стан.

## Складність і пастки на МК

- **Керуй за максимумом, не за середнім.** На вхід рішення йде найгарячіша **жива** комірка. Середнє приховає гарячу точку за прохолодними сусідками — і ти жаритимеш струмом ту, що вже за порогом. Це найперше правило теплового захисту, і його найлегше зламати, написавши `(t1+t2+t3+t4)/4` «бо так природніше».
- **Гістерезис обов'язковий на кожному порозі.** Один поріг = «дзвін»: температура тремтить на межі, стан клацає туди-сюди, реле зношується, лог нечитабельний. Завжди розноси поріг спрацювання й відпускання на кілька десятих градуса. Без гістерезису foldback із теми перетворюється на генератор перешкод.
- **Відмова давача небезпечніша за саму спеку.** Обірваний NTC, що «показує» −20°, змусить наївний регулятор дати повний струм у перегрітий пакет. Перевіряй кожне значення трьома ситами: крайній код АЦП (обрив/КЗ), межі таблиці, фізична правдоподібність. Жоден давач не живий → струм нуль, крапка. Тиха брехня гірша за явну поломку.
- **Самонагрів NTC лікують схемою, не кодом.** Вимірювальний струм гріє давач (P=I²R, ΔT=P/δ). Малий верхній резистор «заради сигналу» дає фальшиве завищення на градуси. Бери десятки кілоом або живи дільник імпульсно — і заодно заощадиш у сні. Латати самонагрів поправкою в коді — гнатися за хвостом, бо величина пливе з температурою.
- **Float — геть із гарячого шляху.** Працюй у десятих градуса цілими; перетворення опір→°C — таблицею з інтерполяцією, а не `log()`. На МК без FPU кожне рівняння Стейнгарта-Гарта в рантаймі — це сотні зайвих тактів на кожен давач на кожному циклі.
- **Фільтруй, але знай чим.** Медіана вбиває поодинокі викиди (наведення від силового ключа), експоненційне згладжування — дрижання між циклами. Просте середнє вразливе до викидів; для значення, що керує безпекою, бери медіану бодай першим ситом.
- **З аварії — у найбезпечніший стан, не назад.** Коли давачі ожили після `FAULT`, заходь через `STOP`, а не прямо в `CHARGE`: за час сліпоти могло статися що завгодно. Перерахуй температуру з нуля й лише тоді послаблюй обмеження.
- **Прокидайся обережним.** Стартовий стан — `STOP` із нульовим струмом, поки не зроблено перший вимір. Дозвіл струму — лише за свіжими перевіреними даними, ніколи «за замовчуванням увімкнено».
- **Мороз — це не «струм нуль», це окрема гілка.** Нижче 0° літій псується дендритами незворотно; тут треба не зрізати, а **забороняти** заряд і, якщо вмієш, **гріти**. Гістерезис на нульовому порозі особливо важливий — давач, що тремтить біля нуля, не повинен пускати краплі заряду в крижану комірку.
- **Темп виклику має сенс.** Сто мілісекунд — добрий компроміс: температура комірки змінюється повільно (велика теплоємність, як ми бачили в темі), тож частіше міряти нема потреби, а рідше — ризик проґавити швидкий нагрів на сильному струмі. Прив'яжи `thermal_tick()` до надійного таймера, не до головного циклу, що може загальмувати.
