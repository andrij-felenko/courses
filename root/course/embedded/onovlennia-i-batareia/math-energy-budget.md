# 🧮 Розрахунок енергетичного бюджету та пікового струму OTA

Оновлення прошивки повітрям (англ. *Over-The-Air*, OTA) — найбільш енергоємна операція за весь час функціонування бездротового автономного пристрою. У звичайному режимі мікроконтролер споживає мікроампери у глибокому сні, прокидаючись на кілька десятків мілісекунд для зняття замірів давача. Сесія OTA триває від десятків секунд до кількох хвилин, вимагаючи безперервної роботи високочастотного радіотракту, граничної обчислювальної потужності процесора для розрахунку криптографічних підписів і живлення внутрішньої помпи заряду Flash-пам'яті. Без детального розрахунку сумарного заряду та динамічного просідання напруги на внутрішньому імпедансі батареї запуск OTA перетворюється на лотерею, де платою за промах є раптове знеструмлення посеред запису сектора.

Ця математична вставка розкладає енергетичний баланс оновлення на складові ланки: приймання радіопакетів, криптографічну перевірку, секторне стирання та запис Flash-пам'яті, а також виводить аналітичну залежність просідання напруги на клемах від температури навколишнього середовища та внутрішнього опору комірки.

### 1. Модель сумарної енергії та витрати заряду сесії OTA

Повний енергетичний бюджет сесії оновлення складається з чотирьох послідовних фізичних етапів:

```
E_total = E_rx + E_crypto + E_flash + E_boot
```

де:
- `E_rx` — енергія приймання бінарного образу через бездротовий інтерфейс;
- `E_crypto` — енергія побайтового гешування (SHA-256) та перевірки асиметричного цифрового підпису (Ed25519 або ECDSA P-256);
- `E_flash` — енергія стирання цільових секторів і посторінкового запису даних у мікросхему Flash;
- `E_boot` — енергія первинного завантаження нового образу, самодіагностики периферії та надсилання підтвердження серверу керування.

Для батарейного живлення критичною величиною є не лише абсолютна енергія у джоулях (`Дж`), а й спожитий електричний заряд у міліампер-годинах (`мА·год`), оскільки саме він безпосередньо зменшує ємність електрохімічної комірки:

```
Q_total = (I_rx · t_rx + I_crypto · t_crypto + I_flash · t_flash + I_boot · t_boot) / 3600
```

Розглянемо параметри для типового образу прошивки розміром `S = 1.5 МБ` (`1 572 864 байти`) на базі сучасного 32-бітного мікроконтролера (наприклад, ESP32-S3 або STM32WB55 з зовнішньою SPI NOR Flash).

#### Етап 1: Приймання даних через радіоканал (Wi-Fi / BLE / Cellular)

Тривалість завантаження залежить від корисної пропускної здатності протоколу передачі `R_eff` з урахуванням накладних витрат транспортного рівня (TCP/TLS або CoAP/DTLS) та повторних передач пошкоджених пакетів:

```
t_rx = S / R_eff
```

Порівняймо часові та енергетичні витрати для трьох найпоширеніших радіоінтерфейсів при середній напрузі шини живлення `V_rail = 3.3 В`:

1. **Wi-Fi 802.11 b/g/n** (швидкісний локальний канал):
   - Корисна швидкість: `R_eff = 250 КБ/с` (`2.0 Мбіт/с`);
   - Середній струм приймача (RX активний + періодичні ACK у TX): `I_rx = 130 мА`;
   - Час завантаження: `t_rx = 1536 КБ / 250 КБ/с = 6.14 с`;
   - Заряд: `Q_rx = (130 мА · 6.14 с) / 3600 ≈ 0.222 мА·год` (`0.800 Кл`);
   - Енергія: `E_rx = 3.3 В · 0.130 А · 6.14 с ≈ 2.63 Дж`.

2. **Bluetooth Low Energy 5.0 (2M PHY)**:
   - Корисна швидкість з урахуванням ATT MTU та інтервалів з'єднання: `R_eff = 45 КБ/с` (`360 Кбіт/с`);
   - Середній струм RX/TX: `I_rx = 22 мА`;
   - Час завантаження: `t_rx = 1536 КБ / 45 КБ/с = 34.13 с`;
   - Заряд: `Q_rx = (22 мА · 34.13 с) / 3600 ≈ 0.209 мА·год` (`0.751 Кл`);
   - Енергія: `E_rx = 3.3 В · 0.022 А · 34.13 с ≈ 2.48 Дж`.

3. **Cellular LTE-M (eMTC / Cat-M1)** (далекий польовий зв'язок):
   - Реальна пропускна здатність в умовах помірного покриття: `R_eff = 20 КБ/с` (`160 Кбіт/с`);
   - Середній струм модема: `I_rx = 160 мА` (з періодичними сплесками TX потужністю +23 dBm до `450 мА`);
   - Час завантаження: `t_rx = 1536 КБ / 20 КБ/с = 76.8 с`;
   - Заряд: `Q_rx = (160 мА · 76.8 с) / 3600 ≈ 3.413 мА·год` (`12.29 Кл`);
   - Енергія: `E_rx = 3.3 В · 0.160 А · 76.8 с ≈ 40.55 Дж`.

У стільникових мережах одне завантаження витрачає у 15 разів більше заряду, ніж по Wi-Fi чи BLE, через меншу швидкість та високу потужність передавача базової станції.

#### Етап 2: Криптографічна валідація образу

Перед записом образу або його активацією процесор виконує суцільне гешування SHA-256 та перевірку підпису Ed25519 для захисту від підміни та пошкодження бітів.

Обчислювальна складність SHA-256 для 1.5 МБ блоку:
- Кількість 64-байтних блоків: `N_blocks = 1 572 864 / 64 = 24 576`;
- Кількість тактів ядра ARM Cortex-M4 / RISC-V без апаратного прискорювача: приблизно 11 тактів на байт → `N_cycles = 1 572 864 · 11 ≈ 17.3 · 10⁶ тактів`;
- При тактовій частоті ядра `f_cpu = 160 МГц` час гешування: `t_sha = 17.3 · 10⁶ / 160 · 10⁶ ≈ 0.108 с`;
- Перевірка підпису Ed25519 (множення точки на еліптичній кривій Curve25519): `t_ed25519 ≈ 0.015 с`;
- Повний час активності CPU на максимальній частоті: `t_crypto ≈ 0.13 с`;
- Струм процесора при 100% навантаженні: `I_crypto = 45 мА`;
- Заряд: `Q_crypto = (45 мА · 0.13 с) / 3600 ≈ 0.0016 мА·год`;
- Енергія: `E_crypto = 3.3 В · 0.045 А · 0.13 с ≈ 0.019 Дж`.

Криптографічна верифікація вимагає мізерної частки загальної енергії (`< 0.1%`), проте створює сходинковий сплеск споживання струму.

#### Етап 3: Секторне стирання та запис Flash-пам'яті

Пам'ять типу NOR Flash вимагає попереднього стирання перед записом нових байтів. Фізично стирання виконується блоками по 64 КБ або секторами по 4 КБ шляхом подачі високої напруги (10–12 В) від внутрішньої помпи заряду для інжекції або видалення електронів із плаваючого затвора.

Параметри мікросхеми SPI Flash (наприклад, Winbond W25Q128JV):
- Розмір сектора: `4 КБ` (`4096 байтів`);
- Кількість секторів для 1.5 МБ: `N_sec = 1536 / 4 = 384 сектори`;
- Типовий час стирання сектора 4 КБ: `t_erase_sec = 45 мс` (максимальний за паспортом: `400 мс`);
- Сумарний час стирання: `t_erase = 384 · 0.045 с = 17.28 с`;
- Струм помпи заряду під час стирання: `I_erase = 20 мА`;
- Розмір сторінки запису: `256 байтів`;
- Кількість сторінок: `N_pages = 1 572 864 / 256 = 6144 сторінки`;
- Час запису сторінки (Page Program): `t_prog_page = 0.7 мс` (максимальний: `3 мс`);
- Сумарний час запису: `t_prog = 6144 · 0.0007 с = 4.30 с`;
- Струм під час програмування: `I_prog = 25 мА`;
- Струм споживання мікроконтролера, що керує шиною SPI: `I_mcu = 20 мА`.

Сумарний час та струм етапу Flash:
- Повний час операцій з пам'яттю: `t_flash = t_erase + t_prog = 17.28 + 4.30 = 21.58 с`;
- Середній струм: `I_flash = I_mcu + (I_erase · t_erase + I_prog · t_prog) / t_flash = 20 + (20 · 17.28 + 25 · 4.30) / 21.58 ≈ 41.0 мА`;
- Заряд: `Q_flash = (41.0 мА · 21.58 с) / 3600 ≈ 0.246 мА·год` (`0.885 Кл`);
- Енергія: `E_flash = 3.3 В · 0.041 А · 21.58 с ≈ 2.92 Дж`.

#### Зведений баланс енергії

Для Wi-Fi OTA загальний витрачений заряд становить:

```
Q_total = Q_rx + Q_crypto + Q_flash + Q_boot
= 0.222 + 0.0016 + 0.246 + 0.005      [підстановка розрахованих значень ланок]
≈ 0.475 мА·год                        [сумарний заряд: 1.71 Кл або 5.64 Дж]
```

Для порівняння: типовий автономний давач із середнім струмом споживання у режимі сну `I_sleep = 15 мкА`, який прокидається раз на годину на 50 мс (`I_act = 80 мА`), витрачає за добу:

```
Q_day = 24 · (15 мкА · 3599.95 с + 80 мА · 0.05 с) / 3600
= 24 · (0.0540 + 0.0040) / 3600       [обчислення заряду за 24 цикли]
≈ 0.387 мА·год/доба                   [добове споживання пристрою]
```

Одне оновлення прошивки по Wi-Fi забирає енергію, еквівалентну **1.2 доби повноцінної роботи пристрою**, а оновлення по стільниковій мережі LTE-M (`Q_total ≈ 3.66 мА·год`) спалює запас енергії за **9.5 діб автономного життя**.

### 2. Динаміка просідання напруги на внутрішньому опорі батареї

Будь-яке хімічне джерело струму моделюється як ідеальне джерело напруги розімкненого кола `OCV(SoC)` (англ. *Open Circuit Voltage*), з'єднане послідовно з еквівалентним послідовним опором `R_esr` та RC-ланцюгами поляризації.

Миттєва напруга на клемах під час сплеску струму навантаження `I_load(t)` описується рівнянням:

```
V_term(t) = OCV(SoC) - I_load(t) · R_esr(T, SOH) - V_pol(t)
```

де:
- `OCV(SoC)` — рівноважна термодинамічна ЕРС комірки, що однозначно залежить від ступеня заряду `SoC`;
- `R_esr(T, SOH)` — омічний опір електроліту, контактів та електродної маси, що експоненційно зростає при зниженні температури `T` та деградації здоров'я батареї `SOH`;
- `V_pol(t)` — напруга електрохімічної та концентраційної поляризації, що розвивається впродовж мілісекунд та секунд.

#### Температурна залежність внутрішнього опору

Іонна провідність рідкого або гелевого електроліту підпорядковується рівнянню Арреніуса. Відповідно, внутрішній опір комірки `R_esr` зростає зі зниженням абсолютної температури `T` (у Кельвінах):

```
R_esr(T) = R_0 · exp( (E_a / k_B) · (1/T - 1/T_0) )
```

де:
- `R_0` — паспортний опір при кімнатній температурі `T_0 = 298.15 K` (`+25 °C`);
- `E_a` — енергія активації іонного переносу в електроліті (типово `0.25–0.35 еВ` для Li-ion);
- `k_B` — стала Больцмана (`8.617 · 10⁻⁵ еВ/K`).

Для якісної нової комірки Li-ion 18650 ємністю 2500 мА·год:
- При `T = +25 °C`: `R_esr ≈ 0.080 Ом` (`80 мОм`);
- При `T = 0 °C` (`273.15 K`): `R_esr ≈ 0.220 Ом` (зростання у 2.75 раза);
- При `T = -15 °C` (`258.15 K`): `R_esr ≈ 0.650 Ом` (зростання у 8.1 раза).

Для старої комірки (`SOH = 70%`, напрацювання 500 циклів) опір `R_0` при кімнатній температурі вже становить `0.250 Ом`, а на морозі `0 °C` сягає `0.750 Ом`.

#### Умова виникнення аварійного Brownout Reset

Мікроконтролер живиться від батареї через імпульсний або LDO-стабілізатор з мінімальною напругою падіння `V_drop` (англ. *dropout voltage*). Скидання за низькою напругою (Brownout Reset, BOR) спрацьовує, якщо напруга на вході або виході стабілізатора падає нижче порогового значення `V_bor`:

```
V_term(t) < V_bor + V_drop
```

Під час сесії OTA виникає момент суперпозиції пікових струмів: коли радіомодуль передає підтверджувальний кадр ACK (`I_tx = 220 мА`), процесор працює на повній частоті (`I_cpu = 45 мА`), а Flash-пам'ять виконує стирання блоку (`I_flash_peak = 35 мА`). Сумарний піковий струм сягає:

```
I_peak = 220 + 45 + 35 = 300 мА = 0.300 А
```

Розрахуємо напругу на клемах батареї, розрядженої до `SoC = 30%` (`OCV ≈ 3.65 В`), для двох температурних умов:

1. **Тепла батарея (+25 °C, R_esr = 0.080 Ом)**:
   ```
   ΔV_sag = 0.300 А · 0.080 Ом = 0.024 В
   V_term = 3.65 В - 0.024 В = 3.626 В
   ```
   Запас до порогу `V_bor + V_drop = 2.70 В + 0.15 В = 2.85 В` становить `+0.776 В`. Система працює стабільно.

2. **Холодна зношена батарея (0 °C, R_esr = 0.750 Ом)**:
   ```
   ΔV_sag = 0.300 А · 0.750 Ом = 0.225 В
   ```
   З урахуванням імпедансу підвідних доріжок плати та опору контактних пружин відсіку батареї (`R_contact ≈ 0.200 Ом`), сумарний імпеданс ланцюга становить `R_loop = 0.950 Ом`:
   ```
   ΔV_sag_total = 0.300 А · 0.950 Ом = 0.285 В
   ```
   Якщо рівень заряду комірки опустився до `SoC = 15%` (`OCV ≈ 3.20 В` для LiFePO4 або `3.50 В` для Li-ion):
   ```
   V_term = 3.20 В - 0.285 В = 2.915 В
   ```
   При тривалому імпульсі струму (понад 10 мс) підключається електрохімічна поляризація `V_pol ≈ 0.150 В`:
   ```
   V_term_real = 2.915 В - 0.150 В = 2.765 В < 2.85 В
   ```
   Напруга шини пробиває поріг детектора BOR. Мікроконтролер миттєво перезавантажується під час активного імпульсу стирання сектора.

### 3. Аналітичний розрахунок безпечного порогу заряду (Safety Threshold)

Щоб гарантувати 100% завершення процесу оновлення за будь-яких умов, прошивка повинна розраховувати динамічний поріг залишкового заряду `SoC_min(T, SOH)` перед підтвердженням завантаження.

Критерій безпеки складається з двох незалежних нерівностей:

#### Критерій 1: Енергетична місткість (Energy Reserve)

Залишковий заряд батареї `Q_rem` повинен перевищувати сумарну витрату заряду сесії `Q_total` з коефіцієнтом інженерного запасу `k_margin ≥ 3.0` (на випадок повторних спроб завантаження пошкоджених пакетів):

```
Q_rem = Q_nominal · SOH · SoC ≥ k_margin · Q_total
```

Звідси мінімальний відсоток заряду за критерієм енергії:

```
SoC_energy_min = (k_margin · Q_total) / (Q_nominal · SOH)
```

Для Wi-Fi OTA (`Q_total = 0.475 мА·год`), нової батареї 2500 мА·год (`SOH = 1.0`):
```
SoC_energy_min = (3.0 · 0.475) / 2500 ≈ 0.00057 = 0.057%
```
Енергетичний критерій для ємних акумуляторів є дуже м'яким — за обсягом енергії вистачило б навіть 1% заряду.

#### Критерій 2: Запас за просіданням напруги (Voltage Sag Margin)

Критичним обмежувачем є не ємність, а напруга під піковим навантаженням. Мінімальна напруга розімкненого кола `OCV_min` повинна задовольняти умову:

```
OCV_min ≥ V_bor + V_drop + I_peak · R_loop(T, SOH) + V_pol_max + V_safety
```

де `V_safety = 0.200 В` — захисний шум-бар'єр.

Підставимо граничні параметри для зимових умов (`T = 0 °C`, `R_loop = 0.950 Ом`, `I_peak = 0.300 А`, `V_bor + V_drop = 2.85 В`, `V_pol_max = 0.150 В`):

```
OCV_min ≥ 2.85 + (0.300 · 0.950) + 0.150 + 0.200    [підстановка граничних параметрів для 0 °C]
= 2.85 + 0.285 + 0.150 + 0.200                      [множення пікового струму на імпеданс]
= 3.485 В                                           [мінімальна напруга спокою для допуску]
```

Для хімії Li-ion напрузі розімкненого кола `OCV = 3.485 В` відповідає залишковий заряд `SoC ≈ 25–30%`.
Для хімії LiFePO4 напруга `3.485 В` лежить на верхньому вигині розрядної кривої (`SoC ≈ 90%`), що робить проведення OTA на морозі від автономної LFP-батареї практично неможливим без підігріву або зовнішнього живлення.

### Підсумкова інженерна формула шлюзу допуску

Перед виконанням першого мережевого запиту OTA-клієнт обчислює безпечний поріг напруги спокою:

```
OCV_threshold(T) = V_cutoff + I_max_pulse · (R_base · 2.5^((25 - T)/20)) + V_margin
```

Якщо поточна напруга батареї у спокої `V_bat_idle < OCV_threshold(T)`, прошивка зобов'язана **заблокувати старт сесії** та повернути серверу статус відкладеного виконання із зазначенням необхідного рівня підзарядки або прогріву пристрою.
