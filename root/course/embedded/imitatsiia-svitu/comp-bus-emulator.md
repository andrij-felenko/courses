# 🔌 Апаратний емулятор сенсорних шин: архітектура FPGA, таймінги та інжекція збоїв

У закритому контурі апаратного тестування (HIL) мікроконтролер випробуваного пристрою не повинен відрізняти тестовий стенд від справжнього кремнієвого давача. Якщо вставити в прошивку програмний місток, який перехоплює виклики драйвера й підставляє симульовані числа з пам'яті, ми перевіряємо лише математику фільтра, оминаючи контролер шини, переривання, прямий доступ до пам'яті (DMA), налаштування регістрів та електричні затримки. Щоб тестувати реальний бінарний образ без жодного модифікованого рядка коду, фізичні виводи мікроконтролера (SCL, SDA, SCK, MOSI, MISO, CS, DRDY) підключають до апаратного емулятора шин.

Емулятор шин — це окремий електронний пристрій, який на фізичному та протокольному рівнях поводиться як ведений вузол (Target / Slave) цифрових інтерфейсів I2C, SPI, UART або паралельних шин, але наповнює свої внутрішні регістри даними з математичної моделі польоту чи руху.

---

## 1. Архітектурне протистояння: чому швидкий мікроконтролер програє FPGA

Перше інженерне рішення, яке спадає на думку під час побудови стенда, — взяти потужний мікроконтролер із тактовою частотою 400–500 МГц (наприклад, на ядрі ARM Cortex-M7), налаштувати його апаратний блок SPI у режим веденого (Target) і в обробнику переривань підставляти потрібні байти. На практиці така схема розбивається об часові обмеження швидких сенсорних шин.

Розглянемо фізичний сеанс читання даних з акселерометра по шині SPI на стандартній тактовій частоті 10 МГц (тривалість одного тактового імпульсу SCK становить 100 нс). Ведучий пристрій (DUT) виставляє сигнал вибору мікросхеми (CS падає в логічний нуль) і вже через 50–100 нс починає генерувати тактові імпульси SCK, одночасно надсилаючи адресу регістра по лінії MOSI (1 байт = 800 нс). У режимі читання ведений пристрій зобов'язаний виставити перший біт даних на лінію MISO або на 9-му такті SCK (одразу після завершення передачі адреси), або заздалегідь, якщо протокол передбачає потокову відповідь.

```
Часовий бюджет реакції веденого вузла SPI (10 МГц):
Спалах CS (0) ───[ 50 нс ]───> 1-й такт SCK ───[ 800 нс (адреса) ]───> 9-й такт (MISO біт 7)
Бюджет на підготовку байта відповіді: ≤ 50..100 нс
```

У мікроконтролері ланцюжок реакції виглядає так:
1. Захоплення спаду лінії CS або завершення прийому байта викликає апаратне переривання.
2. Конвеєр процесора скидає поточні інструкції, зберігає регістровий контекст у стек (на ядрі Cortex-M це займає від 12 до 26 тактів процесора).
3. Виконується пролог функції обробника, читається прапорець статусу SPI, розпізнається надіслана адреса регістра.
4. Значення вибирається з масиву та записується в передавальний буфер `SPI->DR` чи `SPI->TXDR`.

Якщо контролер працює на частоті 400 МГц, 26 тактів входу в переривання займають 65 нс. Але якщо в цей момент процесор виконував інше критичне переривання або обслуговував системний таймер, затримка входу зростає до 200–500 нс. За цей час провідний пристрій уже згенерував тактові імпульси для наступного байта й прочитав з лінії MISO нулі або сміття.

У шині I2C проблема має інший вигляд: стандарт дозволяє веденому пристрою примусово утримувати лінію SCL у нулі (механізм утримання тактового сигналу — clock stretching), щоб отримати час на підготовку байта. Але багато апаратних контролерів I2C у дешевих або старих мікроконтролерах містять помилки в кремнії (errata): тривале утримання SCL веде до зависання всього I2C-периферійного блоку ведучого в нескінченному очікуванні.

Саме тому професійні емулятори шин будують на базі програмованих логічних інтегральних схем (FPGA / ПЛІС). У ПЛІС протокольний автомат веденого вузла реалізовано повністю на апаратному рівні: дешифрація адреси й виставлення першого біта відповіді з внутрішньої блокової пам'яті (BRAM) займає від 1 до 2 тактів базового генератора ПЛІС (менше 10–20 нс), що повністю усуває джиттер і запізнення.

## 2. Структура емулятора на основі двопортової пам'яті

Ядром апаратного емулятора є масив регістрів, організований у вигляді справжньої двопортової пам'яті (Dual-Port RAM):

```
┌─────────────────────────┐                 ┌─────────────────────────┐
│     ХОСТ-СИМУЛЯТОР      │                 │    ВИПРОБУВАНИЙ DUT     │
│   (Модель середовища)   │                 │   (Штатна прошивка)     │
└────────────┬────────────┘                 └────────────┬────────────┘
             │ USB 3.0 / Ethernet                        │ Фізичні дроти шини
             ▼                                           ▼
   ┌───────────────────┐                       ┌───────────────────┐
   │ Порт A (Швидкий)  │                       │  Порт B (Сенсор)  │
   │ Запис нових даних │ ──> [ Двопортова ] <──│ Апаратні автомати │
   │ вимірів (1000 Гц) │     [ RAM регістрів]  │ I2C / SPI Slave   │
   └───────────────────┘                       └───────────────────┘
```

- **Порт A (керівний):** з'єднаний із шиною хост-симулятора (USB High Speed, Ethernet або PCIe). Математична модель польоту з кроком 1 мс розраховує фізичний стан (лінійні прискорення, кутові швидкості, магнітне поле, барометричний тиск) і записує свіжі значення у відповідні адреси віртуальних регістрів.
- **Порт B (сенсорний):** з'єднаний із фізичними виводами роз'єму DUT. Апаратні скінченні автомати емулюють внутрішній простір регістрів конкретного чипа (наприклад, регістри даних `0x3B`..`0x40` для акселерометра, регістри конфігурації, ідентифікатор `WHO_AM_I` за адресою `0x75`).

Оскільки порти A і B мають незалежні тактові домени та адресні шини, запис нових вимірів симулятором не блокує читання регістрів прошивкою мікроконтролера. Для запобігання ситуації «розірваного читання» (коли хост оновив лише старший байт 16-бітного значення осі `ACCEL_X_H`, а мікроконтролер уже зчитує молодший `ACCEL_X_L`) блок порту B реалізує тіньове замикання регістрів (shadow latching): як тільки мікроконтролер починає читання першого байта виміру, увесь блок регістрів поточної вибірки фіксується у внутрішньому буфері до моменту підняття лінії CS або надсилання умови STOP на шині I2C.

## 3. Інжекція електричних та протокольних аномалій

Головна цінність апаратного емулятора перед простим з'єднанням двох плат — здатність навмисно, керовано та відтворювано створювати збої на фізичному та канальному рівнях.

| Тип збою | Механізм емулятора | Що саме перевіряється в прошивці DUT |
|---|---|---|
| **Зависання лінії SDA в нулі (I2C Bus Lockup)** | Емулятор примусово відкриває вихідний транзистор з відкритим стоком і утримує SDA = 0V після 8-го такту. | Здатність прошивки виявити таймаут шини, згенерувати 9 тактових імпульсів на SCL для скидання веденого вузла та виконати апаратний ресет I2C-блоку. |
| **Інжекція помилки контрольної суми (CRC/Parity Error)** | Емулятор навмисно інвертує біт CRC у кінці кадру передачі (наприклад, у протоколах Sensirion чи Bosch). | Логіка відкидання некоректного пакета, повторний запит даних, реєстрація діагностичного лічильника помилок. |
| **Відмова підтвердження (I2C NACK)** | Емулятор залишає лінію SDA підтягнутою до живлення під час 9-го такту у відповідь на адресний байт або байт даних. | Обробка помилки в драйвері: відсутність зависання в блокуючому циклі `while(!I2C_CheckEvent())`, коректний вихід із кодом помилки. |
| **Обрізаний кадр SPI (Partial Frame)** | Емулятор імітує підняття лінії CS посеред передачі 16-бітного слова (наприклад, після 7-го такту SCK). | Скидання стану внутрішнього драйвера SPI, очищення приймальних буферів перед початком наступної транзакції. |
| **Плаваючий рівень напруги / шум** | Цифро-аналоговий перетворювач (ЦАП) емулятора генерує напругу логічної одиниці на межі порогу спрацьовування тригера Шмітта (наприклад, 1.8 В замість 3.3 В). | Стійкість приймача до хибних спрацьовувань та дребезгу на сигнальних лініях. |

## 4. Схема електричного сполучення та рівні сигналів

Сучасні вбудовані системи використовують давачі з напругами живлення цифрових інтерфейсів 1.2 В, 1.8 В, 2.5 В, 3.3 В та 5.0 В. Підключення емулятора з фіксованим рівнем 3.3 В до процесора з напругою введення-виведення 1.8 В призведе до пробою захисних діодів порту та фізичного виходу кристала з ладу.

Стендовий емулятор оснащують двонапрямленими трансляторами рівнів з автоматичним або керованим напрямком передачі (наприклад, на базі швидкодіючих мікросхем сімейства TXB або TXS з відкритим стоком для I2C та двотактними буферами для SPI). Опорна напруга транслятора `V_CCA` підключається до виводу живлення цифрового інтерфейсу `V_DDIO` плати DUT, завдяки чому вихідні рівні емулятора автоматично відстежують реальну напругу живлення процесора.

```
       Емулятор (ПЛІС 3.3V)           Транслятор рівнів            Плата DUT (1.8V)
      ┌────────────────────┐        ┌───────────────────┐        ┌────────────────────┐
      │                    │        │ V_CCA       V_CCB │ <───── │ V_DDIO (1.8V)      │
      │ SPI_SCK_OUT (3.3V) │ ─────> │ A1             B1 │ ─────> │ SCK_IN (1.8V)      │
      │ SPI_MOSI_OUT(3.3V) │ ─────> │ A2             B2 │ ─────> │ MOSI_IN (1.8V)     │
      │ SPI_MISO_IN (3.3V) │ <───── │ A3             B3 │ <───── │ MISO_OUT (1.8V)    │
      │ SPI_CS_OUT  (3.3V) │ ─────> │ A4             B4 │ ─────> │ CS_IN (1.8V)       │
      │                    │        │        GND        │        │                    │
      └────────────────────┘        └─────────┬─────────┘        └────────────────────┘
                                              │
                                     Спільна земля стенда
```

> 🔧 **Навіщо це в реальній розробці:**
> Емулятор шин дозволяє за одну хвилину прогнати 10 000 циклів читання давачів з різними комбінаціями збоїв: відмови шини на високих кутових швидкостях, випадання кадрів під час запису у флеш-пам'ять, залипання ліній зв'язку. Це виявляє 99% прихованих гонок та блокувань у драйверах до того, як плата буде змонтована у виріб.
