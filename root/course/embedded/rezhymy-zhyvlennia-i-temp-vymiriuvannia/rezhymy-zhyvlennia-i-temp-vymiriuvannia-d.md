Батарейка CR2032 містить близько 220 мА·год енергії. Якщо цифровий MEMS-давач тиску чи акселерометр увімкнути в безперервний режим перетворення (Continuous Mode), його внутрішній генератор, підсилювачі та АЦП споживають приблизно 2.5 мА. За такого навантаження елемент живлення розрядиться менш ніж за чотири доби (220 / 2.5 = 88 годин), навіть якщо керівний мікроконтролер взагалі не виконує власних обчислень. Водночас у багатьох задачах — від бездротових метеостанцій до автономних реєстраторів вібрацій — оновлення даних потрібне лише раз на секунду або раз на хвилину. Якщо ж перевести сенсор у режим сну зі струмом 0.5 мкА й активувати вимірювання лише на 5 мс за потреби, середнє споживання знижується у сотні разів, продовжуючи автономну роботу до кількох років.

Для побудови енергоефективного вимірювального тракту розробник повинен узгодити два протилежні фактори: темп вимірювання (від лат. *tempus* — час), який визначає динамічну точність системи, та сумарний енергетичний бюджет автономного джерела. Оптимізація досягається не просто зниженням частоти опитування, а глибоким використанням внутрішніх апаратних блоків сучасних датчиків: незалежних автоматів станів перетворення, конфігурації оверсемплінгу, цифрових фільтрів, буферів FIFO та генераторів подійних переривань.

## 1. Профілі енергоспоживання: Single-shot проти Continuous Mode

Внутрішня структура цифрового датчика складається з двох принципово різних функціональних частин: аналогового тракту (Analog Front-End, AFE) та цифрового інтерфейсного ядра. Аналоговий тракт містить джерело опорної напруги (Bandgap Reference), вимірювальні мости або ємнісні перетворювачі, підсилювачі заряду, генератор тактових імпульсів та аналого-цифровий перетворювач (АЦП). Цифрова частина містить блок керування, регістрову карту пам'яті та трансивер послідовної шини (I²C або SPI).

Основну частку струму (95–99%) споживає саме аналоговий тракт під час заряджання ємностей моста, зміщення підсилювачів та квантування сигналу в АЦП. Залежно від стану цих вузлів сучасні сенсори підтримують три базові режими живлення:

```
+-------------------------------------------------------------------------+
|                               СЕНСОР                                    |
|                                                                         |
|  +--------------------+        +------------------+     +------------+  |
|  |  Аналоговий тракт  |        |    Цифровий      |     | Інтерфейс  |  |
|  |  (AFE + АЦП + Опора)  | <----> |  автомат станів  | <-> |  I2C / SPI |  |
|  |    1.5 .. 5.0 мА   |        |   + FIFO-буфер   |     | (10..50 нА)|  |
|  +--------------------+        +------------------+     +------------+  |
|      ▲               ▲                  ▲                      ▲        |
+------|---------------|------------------|----------------------|--------+
       |               |                  |                      |
[Power-Down: ВСЕ вимкнено]  [Standby: AFE вимкнено, регістри збережено]
                                          [Active: AFE + АЦП працюють]
```

1. **Power-Down (глибокий сон):** Усі внутрішні генератори, підсилювачі та джерела зміщення вимкнені. Струм споживання становить від 10 до 100 нА. Вміст конфігураційних регістрів може втрачатися або зберігатися на мінімальному струмі витоку.
2. **Standby (режим очікування):** Аналоговий блок вимкнено, але цифрова логіка збереження регістрів та інтерфейсний блок шини залишаються заживленими. Давач здатен миттєво відповісти на запит по шині I²C/SPI. Струм споживання становить 0.1–1.0 мкА.
3. **Active Conversion (активне перетворення):** Увімкнені всі підсилювачі, опорні напруги та АЦП. Струм зростає до 1.0–5.0 мА на час від кількох сотень мікросекунд до десятків мілісекунд.

### Неперервний режим (Continuous / Normal Mode)

У неперервному режимі внутрішній таймер чипа автоматично запускає вимірювання із заданою частотою видачі даних (ODR — Output Data Rate, від англ. *output data rate* — швидкість вихідних даних). Наприклад, при ODR = 100 Гц чип кожні 10 мс прокидається, виконує вимірювання, записує результат у вихідні регістри, після чого аналогова частина переходить у внутрішній режим очікування до наступного такту.

Якщо ODR встановлено високим (наприклад, 800 Гц або 1.6 кГц у системах стабілізації польоту дронів), тривалість активної фази збігається з періодом тактування: аналоговий тракт не встигає вимикатися і споживає постійні 2–3 мА. Для пристроїв із живленням від мережі або великого акумулятора це прийнятно, оскільки забезпечує мінімальну затримку сигналу. Проте для автономних батарейних вузлів неперервний режим без потреби призводить до катастрофічного скорочення часу життя.

### Однократний режим за запитом (Single-shot / Forced Mode)

У режимі Single-shot (у деяких виробників зветься *Forced Mode*, від англ. *forced* — примусовий) давач за замовчуванням перебуває у стані Standby зі струмом менше 1 мкА. Аналоговий блок знеструмлений.

Коли мікроконтролеру потрібні свіжі дані, він відправляє по шині коротку команду запису в регістр керування, виставляючи біт запуску (наприклад, `MODE = 0b01`). Отримавши команду, цифровий автомат сенсора:
1. Вмикає джерело опорної напруги та дає час на стабілізацію аналогового тракту (100–300 мкс).
2. Запускає цикл інтегрування АЦП.
3. Записує отримані сирі байти у вихідні регістри даних.
4. Виставляє апаратний прапорець готовності або генерує імпульс на виводі DRDY (Data Ready).
5. **Автоматично переводить аналоговий тракт назад у стан Standby**, не вимагаючи додаткових команд від хоста.

![Профілі струму: Continuous проти Single-shot режиму](/root/course/embedded/rezhymy-zhyvlennia-i-temp-vymiriuvannia/img/sensor-power-profiles.svg)
*Порівняння профілів струму: неперервне перетворення з постійним струмом міліамперного рівня проти циклічного імпульсного вимірювання з мікроамперним середнім значенням.*

Розглянемо числовий приклад. Припустимо, давач вологості й температури виконує перетворення за час `t_meas = 5` мс зі струмом `I_meas = 2.0` мА. У стані Standby його струм становить `I_sleep = 0.4` мкА. Якщо пристрій опитується один раз на 10 секунд (`T_cycle = 10000` мс):

```
Q_act   = 2.0 мА · 5 мс = 10.0 мкКл
Q_sleep = 0.0004 мА · 9995 мс = 3.998 мкКл
Q_total = 10.0 + 3.998 = 13.998 мкКл

I_avg   = Q_total / 10000 мс = 0.0013998 мА ≈ 1.40 мкА
```

Середнє споживання становить лише **1.40 мкА**. Навіть із урахуванням фонового саморозряду літієвого елемента батарейка CR2032 ємністю 220 мА·год забезпечить роботу такого сенсора протягом понад 10 років.

> 🔧 **Навіщо це.**
> У бездротових сенсорних мережах (Zigbee, LoRaWAN, BLE) переважна більшість датчиків середовища (температура, тиск, вологість, якість повітря) мають фізичну сталу часу процесів у секунди або хвилини. Використання Continuous Mode для термометра — це пряма диверсія проти батареї: температура в кімнаті не змінюється 100 разів на секунду, тому запуск Single-shot вимірювання раз на 30 секунд є єдино правильним архітектурним рішенням.

## 2. Баланс між шумом та енергією: оверсемплінг та IIR-фільтрація

Здавалося б, для максимальної економії заряду слід обирати найкоротший можливий час активного перетворення. Проте швидкість вимірювання вступає в жорсткий компроміс із роздільною здатністю та шумом.

### Фізика оверсемплінгу (передискретизації)

Будь-який аналоговий первинний перетворювач генерує тепловий шум Джонсона-Найквіста та дробовий шум, а АЦП додає шум квантування. Для зниження шуму застосовують апаратний оверсемплінг (від англ. *oversampling* — надлишкова вибірка): замість одного перетворення АЦП виконує `OSR = 2^N` послідовних вибірок на високій швидкості, після чого цифровий блок обчислює середнє арифметичне (децимація, від лат. *decimatio* — вилучення частини).

Оскільки некорельований білий шум додається некогерентно (за середньоквадратичним законом), середньоквадратичне відхилення шуму `σ_noise` зменшується пропорційно квадратному кореню з коефіцієнта оверсемплінгу `OSR`:

```
σ_noise(OSR) = σ_base / √OSR
```

Кожне чотирикратне збільшення вибірок (`OSR = 4`) знижує шум у 2 рази, що еквівалентно додаванню **1 біта ефективної роздільної здатності** (ENOB — Effective Number of Bits):

```
ΔENOB = 0.5 · log₂(OSR)
```

| Конфігурація OSR | Кількість вибірок АЦП | Зниження шуму RMS | Приріст ENOB | Тривалість `t_act` | Відносна енергія `E` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **×1 (Ultra-low power)** | 1 | 1.00 (0 дБ) | 0.0 біт | 1.5 мс | **×1.0** |
| **×2 (Low power)** | 2 | 0.71 (-3 дБ) | +0.5 біт | 2.8 мс | **×1.9** |
| **×4 (Standard)** | 4 | 0.50 (-6 дБ) | +1.0 біт | 5.5 мс | **×3.7** |
| **×8 (High resolution)** | 8 | 0.35 (-9 дБ) | +1.5 біт | 10.8 мс | **×7.2** |
| **×16 (Ultra-high res)** | 16 | 0.25 (-12 дБ) | +2.0 біт | 21.5 мс | **×14.3** |

Ціною високої точності є **пряме лінійне зростання тривалості активної фази**. Якщо при OSR = ×1 давач перебуває під струмом 2 мА лише 1.5 мс, то при OSR = ×16 активна фаза триває 21.5 мс. Енергія, витрачена на один відлік (`E = V · I · t`), зростає у 14.3 раза.

![Компроміс оверсемплінгу: зниження шуму проти витрат заряду](/root/course/embedded/rezhymy-zhyvlennia-i-temp-vymiriuvannia/img/oversampling-tradeoff.svg)
*Компроміс передискретизації: шум падає пропорційно кореню з OSR, тоді як тривалість перетворення та споживана енергія зростають лінійно.*

### Внутрішня IIR-фільтрація

Щоб згладити високочастотні шумові викиди без нескінченного збільшення OSR, виробники інтегрують у цифрову частину давачів апаратний фільтр із нескінченною імпульсною характеристикою (IIR — Infinite Impulse Response, від лат. *infinitus* — нескінченний).

Він реалізує дискретний фільтр низьких частот першого порядку безпосередньо в кремнії:

```
y[n] = (1 - α) · y[n-1] + α · x[n]
```

де `x[n]` — сире значення після оверсемплінгу, `y[n]` — відфільтрований результат у вихідному регістрі, а `α = 1 / (2^k)` — коефіцієнт згладжування (типові значення коефіцієнта фільтрації чипа `k = 2, 4, 8, 16`).

Головна перевага IIR-фільтра — **він не збільшує тривалість активної фази АЦП**. Цифрове множення зі зсувом виконується за кілька тактів логіки та споживає мізерну енергію. Проте за це доводиться платити фазовою затримкою (Latency) та часом встановлення (Settling Time). При стрибкоподібній зміні вимірюваної величини вихідному значенню потрібно від 3 до 5 циклів фільтрації, щоб наблизитися до нового рівня.

Для повільних процесів (тиск атмосфери, температура) зв'язка `OSR ×4 + IIR Filter 4` дає ідеальний результат: чистий сигнал без шуму за помірного споживання. Для динамічних систем (визначення моменту удару чи кроку) IIR-фільтр вимикають або встановлюють мінімальний коефіцієнт, оскільки згладжування приховає пікові амплітуди.

## 3. Апаратний буфер FIFO та техніка пакетного зчитування (Burst Read)

Коли для застосунку потрібна висока частота опитування (наприклад, акселерометр для трекінгу активності з ODR = 100 Гц), виникає прихована енергетична пастка: споживання мікроконтролера.

Якщо мікроконтролер прокидається на кожне вимірювання за сигналом DRDY:
* 100 разів на секунду ядро виходить зі сну.
* На кожне пробудження витрачається час на розгін генератора (HSE/HSI), стабілізацію PLL та перемикання регулятора напруги (від 50 мкс до 2 мс зі струмом 10–15 мА).
* МК ініціює транзакцію по шині I²C (яка на частоті 400 кГц триває ~250 мкс).
* МК знову засинає.

У такому режимі мікроконтролер витрачає на перехідні процеси пробудження та очікування байтів по шині в десятки разів більше енергії, ніж сам давач на вимірювання.

```
Без FIFO (пробудження 100 разів/с):
МК:   |||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||  (I_avg ≈ 1.2 мА)
Сенсор: |||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||||

З FIFO на 32 кадри (пробудження 3.1 раза/с):
МК:   [сон ~1.5 мкА]                                            |BURST|  [сон...]      (I_avg ≈ 25 мкА)
Сенсор: |||||||||||||||||||||||||||||||||||||||||||||||||||||||| (пише у FIFO автономно)
```

### Принцип роботи буфера FIFO

Сучасні MEMS-чипи мають вбудовану пам'ять FIFO (First-In, First-Out, від англ. *first in, first out* — першим зайшов, першим вийшов) глибиною від 32 до 512 кадрів. Кадр містить повний набір вимірювань за один такт (наприклад, 6 байтів: осі X, Y, Z по 16 біт).

Буфер підтримує кілька апаратних режимів:
1. **Bypass Mode:** FIFO вимкнено, вихідні регістри оновлюються поточним значенням.
2. **FIFO Mode:** Буфер заповнюється до кінця і зупиняється. Подальші відліки відкидаються, доки хост не вичитає весь буфер.
3. **Stream Mode (кільцевий буфер):** Буфер заповнюється безперервно. При надходженні нового відліку найстаріший автоматично перезаписується.
4. **Stream-to-FIFO (подійний буфер):** Буфер працює як Stream, але при виникненні апаратної події (наприклад, удару) перемикається в FIFO Mode, заморожуючи передісторію та фіксуючи розвиток удару.

![FIFO-буферизація: пакетне вичитування проти частих пробуджень](/root/course/embedded/rezhymy-zhyvlennia-i-temp-vymiriuvannia/img/fifo-burst-vs-per-sample.svg)
*FIFO-буферизація: накопичення даних у внутрішній пам'яті давача дозволяє мікроконтролеру спати більшу частину часу й вичитувати відліки великими пакетами.*

### Налаштування порогу заповнення (Watermark) та Burst Read

Замість очікування повного переповнення буфера розробник конфігурує поріг заповнення — **Watermark** (рівень води, WTM). Наприклад, у буфері на 32 кадри поріг встановлюють на 28 або 32.

Алгоритм взаємодії:
1. Давач автономно працює на ODR = 100 Гц, записуючи зразки у FIFO. Мікроконтролер перебуває в режимі глибокого сну (Stop Mode) зі струмом 1.5 мкА.
2. Коли лічильник буфера досягає значення 32 (через 320 мс), давач перемикає лінію переривання INT1 у високий рівень.
3. Лінія INT1 підключена до виводу зовнішнього переривання (EXTI) мікроконтролера. МК прокидається.
4. МК активує контролер DMA та запускає пакетне зчитування (Burst Read) по швидкій шині SPI (8–10 МГц).
5. За один сеанс активності шини (з утриманням лінії Chip Select) передаються всі 192 байти (`32 кадри × 6 байтів`). На швидкості SPI 8 МГц передача триває менше **250 мікросекунд**.
6. МК обробляє пачку даних, скидає прапорець переривання і миттєво повертається в глибокий сон.

Завдяки пакетному зчитуванню коефіцієнт заповнення активної роботи мікроконтролера падає з 15–30% до менш ніж **0.2%**, що зменшує сумарне споживання системи в 10–15 разів.

## 4. Подійно-орієнтоване пробудження (Event-Driven Wakeup)

Найбільш енергоощадний режим роботи цифрового вузла — це режим, коли передача даних по шині взагалі не відбувається, доки у фізичному світі не станеться заздалегідь визначеної події.

Передача сирих потокових даних у мікроконтролер лише для того, щоб програмно перевірити «чи зрушив пристрій з місця» або «чи не перевищила температура поріг 60 °C» — груба помилка архітектури вбудованих систем. Сучасні датчики мають власні цифрові компаратори та логічні автомати, здатні детектувати події самостійно.

![Подійно-орієнтоване пробудження: ланцюг обробки від сну до реакції](/root/course/embedded/rezhymy-zhyvlennia-i-temp-vymiriuvannia/img/sensor-interrupt-fsm.svg)
*Подійно-орієнтоване пробудження: внутрішня апаратна логіка сенсора відстежує порогові умови на мікрострумах, пробуджуючи хост-контролер лише при настанні події.*

### Апаратні генератори переривань у датчиках

1. **Data Ready (DRDY):** Базове переривання. Генерується на кожен новий відлік АЦП. Застосовується лише в задачах неперервної потокової фільтрації (DSP, БПФ, орієнтація дронів).
2. **Watermark / FIFO Overrun:** Генерується при накопиченні `N` відліків або переповненні буфера.
3. **Threshold / Window Interrupt (порогове переривання):** Порівнює виміряну величину з двома регістрами — `TH_HIGH` та `TH_LOW`. Якщо значення виходить за межі «вікна», виставляється переривання. Застосовується в термостатах, давачах затоплення та контролі тиску в шинах (TPMS).
4. **Any-Motion / Wake-up (виявлення руху):** Логіка акселерометра обчислює різницю між поточним і попереднім відліками: `|a[n] - a[n-1]| > Slope_Threshold`. Якщо різниця перевищує поріг протягом `N` послідовних вибірок, фіксується рух.
5. **Free-fall (вільне падіння):** Спрацьовує, коли векторна сума всіх трьох осей акселерометра одночасно падає нижче критичного порогу: `√(ax² + ay² + az²) < 0.2g`. Використовується для аварійного паркування головок жорстких дисків або детекції падіння людини.
6. **Double-Tap / Click (подвійний дотик):** Апаратний аналізатор форми імпульсу розпізнає швидкий сплеск прискорення та повторний удар у заданому часовому вікні.

### Фіксація та очищення переривань (Interrupt Latching)

Під час налаштування переривань доступні два режими генерації імпульсу на фізичному виводі INT:
* **Pulsed (імпульсний):** Вивід переходить в активний стан на фіксований короткий час (наприклад, 50 мкс), після чого автоматично повертається у вихідний стан. Небезпека полягає в тому, що якщо мікроконтролер у цей момент перемикав тактову сітку або виходив зі сну, він може пропустити короткий фронт.
* **Latched (із засувкою):** Вивід переходить в активний стан і **залишається в ньому нескінченно довго**, доки мікроконтролер не вичитає спеціальний статусний регістр переривань по шині I²C/SPI.

Читання статусного регістру виконує дві функції: скидає апаратний фіксатор (дозволяючи наступним подіям генерувати новий фронт) та повідомляє прошивці, яка саме вісь або поріг викликали спрацьовування.

## 5. Практичний розрахунок автономності та навантаження батареї

Для повного інженерного розрахунку життєвого циклу автономного пристрою необхідно звести всі фази споживання в єдиний часовий баланс заряду.

```
                      Фаза 1                   Фаза 2               Фаза 3
                 [Активне вимірювання]    [Обробка та шина]        [Глибокий сон]
Струм:               I_meas (2.4 мА)         I_proc (4.6 мА)       I_sleep (2.0 мкА)
Тривалість:          t_meas (8.0 мс)         t_proc (4.0 мс)       t_sleep (988 мс)
```

Загальний заряд за період `T = 1` с:

```
Q_meas  = 2.40 мА · 8.0 мс   = 19.20 мкКл
Q_proc  = 4.60 мА · 4.0 мс   = 18.40 мкКл
Q_sleep = 0.002 мА · 988 мс  = 1.976 мкКл

Q_total = 19.20 + 18.40 + 1.976 = 39.576 мкКл (мА·мс)
I_avg   = 39.576 мА·мс / 1000 мс ≈ 39.58 мкА
```

### Падіння напруги на внутрішньому опорі батареї

Типовий дисковий елемент CR2032 при зниженні заряду або охолодженні збільшує свій внутрішній опір `R_int` від початкових 15 Ом до 100–150 Ом.

Під час стрибка активного струму `I_peak = 4.6` мА спад напруги на батареї складе:

```
ΔV = I_peak · R_int
   = 0.0046 А · 150 Ом = 0.69 В
```

Якщо напруга батареї під навантаженням впаде нижче порогу скидання Brown-Out Reset мікроконтролера (наприклад, 2.0 В), система перезапуститься. Щоб запобігти просіданню напруги, паралельно шині живлення встановлюють накопичувальний керамічний конденсатор `C_bulk` ємністю 47–100 мкФ.

Для докладного математичного апарату з урахуванням ефекту Пейкерта, температурного розряду та розрахунку буферних конденсаторів див. [детальний математичний розрахунок автономності та підбору буферного конденсатора](root:embedded/rezhymy-zhyvlennia-i-temp-vymiriuvannia/math-power-autonomy.md).

Для повного коду драйвера з конфігурацією переривань Watermark, DMA та переходом у режим Stop 2 див. [практична реалізація драйвера пакетного вичитування FIFO на C та C++](root:embedded/rezhymy-zhyvlennia-i-temp-vymiriuvannia/proj-burst-fifo-polling.md).

## 6. Зведена інженерна стратегія вибору режиму

Під час проектування вбудованого вузла вибір конфігурації сенсора визначається природою вхідного сигналу та жорсткістю енергетичного бюджету:

```
Яка природа сигналу?
│
├── Повільні зміни (T, вологість, барометр погоди)
│   └── Режим: Single-shot / Forced Mode
│       Частота: 1 вимірювання раз на 1–60 с
│       Фільтрація: OSR ×4 + IIR 4
│       Стратегія МК: Глибокий Stop Mode між вибірками
│
├── Неперервні динамічні коливання (вібрація, кутова швидкість БПЛА)
│   └── Режим: Continuous Mode з високим ODR (100–800 Гц)
│       Буферизація: FIFO Stream Mode (Watermark = 32)
│       Зчитування: SPI DMA Burst Read
│       Стратегія МК: Сон у проміжках між Watermark-перериваннями
│
└── Рідкісні критичні події (удар, сейсмічний поштовх, падіння, рух)
    └── Режим: Any-Motion / Threshold Interrupt
        Частота сенсора: Low-Power ODR (10–25 Гц, I_sens ≈ 2..5 мкА)
        Переривання: Latched Hardware Interrupt
        Стратегія МК: Нескінченний Deep Sleep до фізичного тригера
```

Керування темпом вимірювання та режимами живлення датчика перетворює вимірювальний вузол з ненажерливого споживача енергії на автономну систему, здатну роками функціонувати від мініатюрного дискового елемента живлення.
