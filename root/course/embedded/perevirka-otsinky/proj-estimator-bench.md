# ⚙️ Автоматизований стенд валідації та оптимізації фільтра на Python

Для об'єктивної оцінки роботи оцінювача стану вбудованої системи необхідний автономний конвеєр обробки даних, який приймає синхронізований лог випробувань, звіряє оцінку з еталонною траєкторією (Ground Truth), проводить діагностику інновацій фільтра Калмана та автоматично знаходить оптимальні параметри матриць `Q` і `R`.

Нижче розібрано архітектуру, методи обробки, автоматичну оптимізацію та повну робочу реалізацію аналітичного стенда на мові Python.

---

## 1. Архітектурні вимоги до стенда валідації

Під час розробки алгоритмів орієнтації та навігації ручний підбір параметрів «за графіком на екрані» є неприпустимим: він не дає числових гарантій стійкості й приховує фазові затримки. Автоматизований конвеєр валідації повинен задовольняти чотири інженерні вимоги:

1. **Декодування двійкових потоків без втрати точності**: читання упакованих структур фіксованого розміру, записаних бортовим логером через DMA. Текстові формати на кшталт JSON чи CSV створюють надлишкове навантаження на процесор мікроконтролера, тому запис завжди ведеться у двійковому форматі.
2. **Часове вирівнювання та інтерполяція**: зовнішня оптична система трекінгу (Vicon, OptiTrack) зазвичай працює на частотах 200–500 Гц, тоді як внутрішній цикл оцінювача може працювати на 100, 250 або 400 Гц. Стенд повинен виконувати точне ресемплювання сигналів за мітками апаратного стробу або через максимум взаємної кореляції.
3. **Комплексна статистична діагностика**: розрахунок не лише прямої похибки (RMSE), а й перевірка гіпотези білого шуму інновацій (нульове середнє, відсоток виходів за межі `±2√S`, автокореляція залишків `r_yy[m]`).
4. **Оцінка статистичної узгодженості**: розрахунок індексів NEES (похибка стану, зважена на `P`) та NIS (інновація, зважена на `S`) зі зіставленням із теоретичними квантилями розподілу хі-квадрат `χ²`.

## 2. Математика чисельного аналізу та обробки сигналів

Конвеєр спирається на набір чітких математичних критеріїв:

- **Середньоквадратична похибка (RMSE)**:
```
RMSE = √( (1 / N) · ∑_{k=1}^N (x̂[k] − x_gt[k])² )
```
RMSE є головною функцією втрат під час оптимізації, оскільки квадратичне покарання сильніше реагує на поодинокі динамічні зриви оцінки.

- **Фазовий лаг (динамічна затримка оцінки)**: обчислюється через дискретну кроскореляцію центрованих рядів `x̂` та `x_gt`. Зсув за часом, що дає максимальний коефіцієнт кореляції, визначає чисту затримку фільтра:
```
τ_lag = argmax_{m} ( (1 / N) · ∑ (x̂[k] − μ_x) · (x_gt[k + m] − μ_gt) )
```

- **Вибіркова автокореляція інновацій `r_yy[m]`**:
```
r_yy[m] = ∑_{k=1}^{N−m} (y[k] − ȳ) · (y[k+m] − ȳ)  /  ∑_{k=1}^N (y[k] − ȳ)²
```
Для ідеально білого шуму при `m ≥ 1` значення `r_yy[m]` мають перебувати у межах довірчого інтервалу `±1.96 / √N`.

- **Чисельна стійкість коваріаційних форм**:
Під час обчислення величин NEES `(eᵀ P⁻¹ e)` та NIS `(yᵀ S⁻¹ y)` для запобігання діленню на нуль або обчисленню обернених матриць для погано обумовлених коваріацій застосовують регуляризацію Тихонова: до діагональних елементів додають мале число `ε = 10⁻¹²`. У багатовимірному випадку обернення матриці замінюють на розв'язання лінійної системи через розклад Холецького `S = L · Lᵀ`, що гарантує збереження симетричності та додатної визначеності.

## 4. Автоматичний чисельний підбір гіперпараметрів (Q, R Tuning)

Для автоматизації налаштування фільтра стенд запускає оптимізатор Нелдера — Міда (симплекс-метод) або координатного спуску над простором логарифмів параметрів:

```
θ = [ log10(Q_diag[0]), ..., log10(Q_diag[n]), log10(R_diag[0]), ..., log10(R_diag[m]) ]
```

Оптимізація саме в логарифмічній шкалі є критично важливою, оскільки вона:
1. Забезпечує сувору додатність дисперсій шумів (`10^θ > 0`) без необхідності використання складних умовних обмежень.
2. Дозволяє ефективно досліджувати діапазони, що охоплюють від 6 до 10 порядків величини (наприклад, `Q` від `10⁻⁶` до `10²`).

Цільова функція (англ. *loss function*) конструюється як зважена сума трьох складових:

```
Loss(θ) = w₁ · RMSE(x̂, x_gt) + w₂ · |mean(NIS) − 1.0| + w₃ · ∑_{m=1}^M (r_yy[m])²
```

Де:
- Перший доданок мінімізує фізичну розбіжність між оцінкою та істиною.
- Другий доданок утримує масштаб інноваційного коридору відповідно до розподілу `χ²` (запобігає як самовпевненості, так і повільності).
- Третій доданок придушує часову пам'ять нев'язок, гарантуючи білість шуму та відсутність фазового запізнення.

## 5. Практичні поради та типові крайові випадки

1. **Дрейф міток часу та втрачені кадри**: якщо на борту виникає переповнення кільцевого буфера або затримка запису на SD-карту, мікроконтролер може пропустити кілька пакетів. Аналітичний скрипт повинен перевіряти дельту часу `Δt = t[k] − t[k−1]`. У разі виявлення стрибка `Δt > 1.5 · dt_nominal` відповідний інтервал слід маркувати як розрив траєкторії, а не враховувати як миттєвий динамічний ривок.
2. **Переповнення мікросекундного лічильника**: 32-бітний беззнаковий лічильник мікросекунд переповнюється кожні `2³² / 10⁶ ≈ 4294.9` секунд (~71.5 хвилин). При аналізі тривалих заїздів слід обробляти перехід через нуль `t_us < t_prev` через додавання `2³²`.
3. **Критерій оптимізації гіперпараметрів**: під час автоматичного підбору матриць `Q` і `R` не варто мінімізувати лише RMSE. Занадто сильне прагнення мінімізувати RMSE призводить до перенавчання (фільтр перетворюється на звичайний низькочастотний фільтр із великим лагом). Цільова функція обов'язково повинна містити штраф за автокореляцію залишків та відхилення середнього NIS від одиниці.
4. **Інтеграція в CI/CD конвеєр прошивки**: збережені «золоті» датасети випробувань додають до автоматичних регресійних тестів у системі неперервної інтеграції. Будь-яка зміна алгоритмів орієнтації автоматично проганяється через стенд, а збірка блокується, якщо RMSE зростає більше ніж на 5% або якщо порушується довірчий інтервал автокореляції інновацій.

## 6. Інтерпретація результатів валідації та усунення проблем

Коли скрипт обробляє реальний польотний чи дорожній лог, отримана зведена таблиця метрик дає однозначну вказівку на джерело проблем у прошивці:

| Ознака в метриках | Фізична причина | Інженерна дія у прошивці |
|---|---|---|
| `E[y] ≠ 0` (зміщене середнє) | Невірно калібрований нуль сенсора (`bias`) | Запустити статичне калібрування гіроскопа/акселерометра перед стартом |
| Вильоти за `2σ > 15%`, `NIS > 2.0` | Фільтр надмірно самовпевнений, занижений `Q` або `R` | Збільшити елементи діагоналі `Q` (шум моделі) або `R` |
| Вильоти за `2σ < 1%`, `NIS < 0.5` | Фільтр занадто боязкий, слабка довіра до вимірів | Зменшити шум вимірювання `R` або прискорити реакцію моделі |
| `r_yy[1] > 0.3` (висока автокореляція) | Не врахована динаміка приводів або вібрація рами | Додати стан затримки в модель `F` або встановити режекторний фільтр |
| Фазовий лаг `> 50 мс` при малому RMSE | Надмірне згладжування заниженим шумом процесу | Збільшити `Q`, переналаштувати пропорційні коефіцієнти PID |
| `NEES` стрімко росте в часі | Розбіжність фільтра, накопичення неспостережуваного стану | Додати періодичне абсолютне оновлення або збільшити діагональ `P_init` |
