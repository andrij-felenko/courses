# 🔌 Апаратний елемент безпеки: будова та ізоляція секретів

Якщо мікроконтролер зберігає криптографічні ключі у звичайній вбудованій Flash-пам'яті або зовнішньому чипі SPI Flash, зловмисник із доступом до лабораторного обладнання вартістю від кількох сотень доларів може зчитати ці дані за допомогою зняття дампу через шину, ін'єкції збоїв за живленням (англ. *voltage fault injection*) або підключення апаратного налагоджувача. **Апаратний елемент безпеки** (англ. *Secure Element*, SE) створюється як неприступна кремнієва фортеця: це спеціалізований супутній мікрочип, чиє єдине призначення — генерувати, зберігати та використовувати криптографічні секрети без жодної можливості вивантажити їх у відкритому вигляді назовні.

---

### Чому центральний мікроконтролер не може бути надійним сховищем

Звичайний мікроконтролер загального призначення (наприклад, базовий чип архітектури Cortex-M0/M3/M4) оптимізований під швидкодію, низьку ціну та гнучкість периферії, але позбавлений фізичного захисту кремнієвого кристала:
1. **Відкриті внутрішні шини:** шини інструкцій та даних проходять на верхніх металевих шарах кристала, де їх можна зондувати мікроголками (англ. *microprobing*).
2. **Вразливість бітів захисту (Readout Protection, RDP):** біти блокування налагоджувального інтерфейсу JTAG/SWD реалізовані як звичайні тригери конфігурації. Короткий імпульс просадки напруги живлення тривалістю кілька наносекунд під час завантаження (glitching) змушує ядро пропустити перевірку біта блокування і відкрити повний доступ до пам'яті через JTAG.
3. **Електромагнітне випромінювання та шум живлення:** при виконанні криптографічних інструкцій на звичайному ядрі кожен такт споживає різний струм залежно від оброблюваного біта (`0` чи `1`), що дозволяє відновити секрет через диференційний аналіз потужності (DPA).

Secure Element проєктується за абсолютно іншою парадигмою: процесор хоста (головний MCU) розглядається як потенційно скомпрометоване середовище, якому **заборонено знати сам секрет**. Хост має право лише надсилати запити на виконання криптографічної дії (підписати хеш, згенерувати випадкове число або виконати операцію узгодження ключа Diffie-Hellman), а вся обробка відбувається виключно всередині крипточипа.

### Внутрішня структура апаратного елемента безпеки

Сучасні елементи безпеки (як-от Microchip ATECC608B, NXP SE050, STMicroelectronics STSAFE-A110) об'єднують на єдиному фізично захищеному кристалі кілька взаємопов'язаних вузлів.

```

|  |     прискорювач     |  | (16 слотів пам'яті, |  | (Генератор на   |  |
|  |  • ECDSA (secp256r1)|  |  політики доступу,  |  |  шумі p-n       |  |
|  |  • AES-128/256-GCM  |  |  лічильники зносу)  |  |  переходу)      |  |
|  |  • SHA-256 / HMAC   |  +---------------------+  +-----------------+  |
|  +---------------------+             ▲                                  |
```

#### 1. Активна захисна сітка (Active Shield / Top Metal Mesh)
Верхній шар металізації мікросхеми вкритий суцільною сіткою провідників, якими постійно циркулює псевдовипадковий тестовий сигнал. Якщо атакуючий намагається спиляти захисний компаунд корпусу мікросхеми кислотою чи лазером, щоб дістатися до внутрішніх ліній, або просвердлити отвір для встановлення мікроголки, лінія сітки обривається або замикається на сусідню. Схема виявлення втручання миттєво фіксує порушення цілісності та за лічені наносекунди скидає заряд із конденсаторів пам'яті, стираючи всі збережені ключі (апаратне занулення — zeroization).

#### 2. Сенсори фізичного та середовищного втручання
- **Оптичні детектори:** фотодіоди на кремнії фіксують потрапляння світла при розтині непрозорого пластикового корпусу мікросхеми.
- **Детектори тактової частоти та напруги:** схеми моніторингу миттєво блокують кристал при спробах маніпуляції частотою тактування (clock glitching) або короткочасних просадках живлення (brownout injection).
- **Температурні сенсори:** фіксують спроби охолодити мікросхему рідким азотом (для сповільнення розряду комірок пам'яті SRAM) або перегріти її.

#### 3. Апаратний генератор справді випадкових чисел (TRNG)
Секретний ключ не можна згенерувати надійно без якісного джерела фізичного шуму. TRNG усередині SE базується на квантових явищах — тепловому шумі Джонсона–Найквіста в резисторах або лавинному пробої зворотно зміщеного p-n переходу. Згенерована випадковість проходить обов'язкові апаратні тести на ентропію (NIST SP 800-90B) перед тим, як потрапити до генератора пари ключів.

#### 4. Захищена енергонезалежна пам'ять (Slot Storage)
Пам'ять SE розбита на слоти (наприклад, 16 слотів в ATECC608). Для кожного слота на етапі виробництва апаратно конфігуруються індивідуальні права:
- Слот 0: Приватний ключ ECC (заборонено читати, дозволено лише викликати операцію підпису `Sign`).
- Слот 1: Публічний кореневий ключ перевірки оновлень (дозволено читати, заборонено записувати без валідного підпису виробника).
- Слот 2: Симетричний ключ AES (дозволено використовувати для апаратного шифрування, заборонено експортувати на шину).

Після завершення заводської конфігурації (етап блокування — *Locking/Freezing Zones*) конфігураційні біти спалюються назавжди. Змінити правила доступу до слотів неможливо навіть за наявності повного доступу до коду хост-контролера.

### Протокол взаємодії: як підписати дані без розкриття ключа

Розглянемо послідовність взаємної автентифікації пристрою в хмарі за протоколом mTLS:

```
Центральний MCU                     Secure Element (ATECC608)
      │                                       │
      ├──── 1. Запит генерації пари ─────────►│
      │        ключів (GenKey, Слот 0)        │ (Генерує приватний ключ d
      │                                       │  всередині слота 0. Ключ d
      │                                       │  НІКОЛИ не залишає SE!)
      │◄─── 2. Повертає відкритий ключ Q ─────┤ (Q = d · G)
      │                                       │
[ Підключення до TLS-сервера ]                │
      │                                       │
      │ (Сервер надіслав challenge:           │
      │  хеш H = SHA-256(handshake_data))     │
      │                                       │
      ├──── 3. Запит на підпис: ─────────────►│
      │        Sign(Слот 0, Хеш H)            │ (Обчислює ECDSA підпис
      │                                       │  s = k⁻¹(H + d·r) mod n
      │                                       │  всередині апаратного ядра)
      │◄─── 4. Повертає цифровий підпис (r, s)─┤
      │                                       │
[ Відправка (r, s) на сервер ]                │
```

Навіть якщо зловмисник підключить логічний аналізатор до ліній шини I2C (SDA/SCL) між мікроконтролером і Secure Element:
- Він побачить відкритий ключ `Q` (який не є секретом).
- Він побачить хеш `H` та підпис `(r, s)`.
- Він **ніколи не побачить приватний ключ `d`**, тому що цей ключ фізично не проходить через мідні доріжки плати.

### Типові інженерні помилки інтеграції

1. **Незаблоковані конфігураційні зони в серійному виробництві:**
   Якщо після запису серійних номерів та ключів інженер забув відправити команду `LockConfig` / `LockData`, Secure Element залишається в режимі розробки. Будь-яка людина з налагоджувачем може перезаписати конфігурацію або змінити права слота на читання.
2. **Відкрита передача сесійних ключів:**
   Якщо Secure Element використовується для генерації симетричного сесійного ключа AES, і цей ключ повертається в MCU у відкритому вигляді через I2C, шина стає найслабшою ланкою. Надійні архітектури використовують протокол зашифрованої сесії хоста (Host-to-SE encrypted tunnel) на основі спільного ключа зв'язування (IO Protection Key).
3. **Нехтування розв'язкою живлення біля крипточипа:**
   Якщо поблизу виводів VDD/GND елемента безпеки відсутній керамічний конденсатор ємністю 100 нФ з низьким еквівалентним послідовним опором (ESR), комутаційні шуми ядра SE проникатимуть у загальну шину живлення, створюючи передумови для сторонніх атак через аналіз споживання струму.
