# 📋 Структура записів NDEF та дескрипторів Out-of-Band

Формат обміну даними NFC (англ. *NFC Data Exchange Format*, NDEF) стандартизує двійкове представлення довільних корисних навантажень — від коротких текстових рядків до складних дескрипторів бездротової конфігурації. У цьому довіднику зведено побайтову розмітку полів заголовка NDEF-записів, таблиці кодів форматів імен типів (TNF), префіксів уніфікованих ідентифікаторів ресурсів (URI), структур системних контейнерів Capability Container (CC), регістрової карти наскрізного режиму Pass-Through, протокольних команд ISO та блоків Advertising Data (AD Data), що використовуються у протоколах спрощеного спаровування Bluetooth Low Energy (BLE) та Wi-Fi Protected Setup (WPS).

## Бітова маска байта заголовка NDEF (Record Header Byte)

Кожен NDEF-запис відкривається одним байтом конфігураційних прапорців, який визначає межі повідомлення, спосіб кодування довжини та тип корисного навантаження.

| Біт | Назва | Стан | Призначення та інженерне значення |
|---|---|---|---|
| **7** | `MB` (*Message Begin*) | `1` / `0` | **1** — перший запис у NDEF-повідомленні; **0** — проміжний або завершальний запис. Для одиночного запису виставляється в `1`. |
| **6** | `ME` (*Message End*) | `1` / `0` | **1** — останній запис у NDEF-повідомленні; **0** — після нього слідують наступні записи. Для одиночного запису виставляється в `1`. |
| **5** | `CF` (*Chunk Flag*) | `1` / `0` | **1** — фрагментований запис (корисне навантаження розбито на кілька послідовних частин); **0** — цілісний неподільний запис. |
| **4** | `SR` (*Short Record*) | `1` / `0` | **1** — поле довжини навантаження займає **1 байт** (розмір ≤ 255 байтів); **0** — поле довжини займає **4 байти** (формат Big-Endian). |
| **3** | `IL` (*ID Length Present*) | `1` / `0` | **1** — у заголовку присутні байти `ID Length` та поле `ID`; **0** — ідентифікатор запису відсутній. |
| **2..0** | `TNF` (*Type Name Format*) | 3 біти | 3-бітове поле, що визначає контекст інтерпретації поля `Type` (значення `0x00`..`0x07`). |

### Правила комбінації прапорців заголовка

- **Одиночний короткий запис (Single Short Record):** Якщо повідомлення складається з одного запису довжиною до 255 байтів без ідентифікатора ID, заголовок формується комбінацією бітів:
  `MB = 1`, `ME = 1`, `CF = 0`, `SR = 1`, `IL = 0`, що разом із відповідним значенням `TNF` утворює старший півбайт `0xD0 | TNF` (наприклад, `0xD1` для Well-Known або `0xD2` для MIME).
- **Багатозаписні повідомлення (Multi-Record Messages):** Перший запис має `MB = 1`, `ME = 0` (заголовок `0x90 | TNF`); проміжні записи мають `MB = 0`, `ME = 0` (заголовок `0x10 | TNF`); фінальний запис має `MB = 0`, `ME = 1` (заголовок `0x50 | TNF`).
- **Фрагментовані чанки (Chunked Records):** Перший чанк має `CF = 1` та оригінальний `TNF`; проміжні та кінцеві чанки мають `TNF = 0x06` (Unchanged) та нульову довжину поля типу (`Type Length = 0`).

## Коди форматів імен типів (Type Name Format, TNF)

Поле TNF вказує парсеру операційної системи, за якими правилами декодувати байти в полі `Type`.

| Значення TNF | Назва категорії | Опис та типове використання у вбудованих пристроях |
|---|---|---|
| `0x00` | **Empty** | Порожній запис. Поля `Type Length`, `Payload Length`, `ID Length` дорівнюють нулю. Використовується для скидання стану мітки. |
| `0x01` | **NFC Forum Well-Known Type** | Стандартизовані типи NFC Forum (RTD — Record Type Definition): `'U'` (URI), `'T'` (Text), `'Sp'` (Smart Poster). |
| `0x02` | **MIME Media-Type** | Типи за стандартом RFC 2046: `application/vnd.bluetooth.ep.oob`, `application/vnd.wfa.wsc`, `text/plain`, `application/json`. |
| `0x03` | **Absolute URI** | Повний абсолютний URI згідно з RFC 3986 (наприклад, `http://example.com/schema.json`). |
| `0x04` | **NFC Forum External Type** | Користувацькі та вендорні типи з власним простором імен. Наприклад, Android Application Record: `android.com:pkg`. |
| `0x05` | **Unknown** | Тип корисного навантаження невідомий; інтерпретується парсером як сирий бінарний масив (`application/octet-stream`). |
| `0x06` | **Unchanged** | Використовується виключно в проміжних та кінцевих фрагментах записів із прапорцем `CF = 1`. |
| `0x07` | **Reserved** | Зарезервовано NFC Forum для майбутніх розширень специфікації; при парсингу має викликати помилку непідтримуваного формату. |

## Структура корисного навантаження RTD Text (TNF = 0x01, Type = 'T')

Запис тексту починається зі статусного байта `Status`, після якого слідує код мови ISO/IANA (наприклад, `"en"` або `"uk"`) та власне текстовий рядок у форматі UTF-8 або UTF-16.

```
+----------------+--------------------------+------------------------------+
| Status (1 байт)| Language Code (n байтів) | Text Data (m байтів)         |
+----------------+--------------------------+------------------------------+
```

- **Біт 7 статусного байта (`Status[7]`):** `0` = кодування тексту UTF-8; `1` = кодування тексту UTF-16 (Big-Endian або Little-Endian із міткою порядку байтів BOM).
- **Біт 6 статусного байта (`Status[6]`):** Зарезервовано NFC Forum (має обов'язково дорівнювати нулю `0`).
- **Біти 5..0 статусного байта (`Status[5..0]`):** Довжина коду мови `n` у байтах (для 2-символьних кодів `"en"`, `"uk"`, `"de"` значення дорівнює `2`).

## Структури AD Data для BLE Out-of-Band (MIME: `application/vnd.bluetooth.ep.oob`)

Корисне навантаження запису BLE OOB пакується у форматі послідовності структур Advertising Data (AD structures) за специфікацією Bluetooth Core Specification (Volume 3, Part C). Кожна AD-структура складається з 1 байта довжини (`Length`), 1 байта типу (`AD Type`) та відповідних даних (`AD Data`). Загальна довжина блоку `Length` дорівнює розміру поля даних плюс один байт на сам дескриптор `AD Type`.

| AD Type (код) | Назва структури | Довжина поля даних | Формат та інженерне призначення |
|---|---|---|---|
| `0x01` | **Flags** | 1 байт | Прапорці доступності: біт 1 = LE General Discoverable, біт 2 = BR/EDR Not Supported. Стандартне значення для BLE-вузлів: `0x06`. |
| `0x08` | **Shortened Local Name** | Змінна | Скорочене ім'я пристрою у кодуванні UTF-8 (для відображення у системному діалозі підключення). |
| `0x09` | **Complete Local Name** | Змінна | Повне ім'я пристрою (наприклад, `"SmartValve-PRO-42"`). |
| `0x10` | **Security Manager TK** | 16 байтів | Тимчасовий ключ (Temporary Key) для алгоритму Legacy Pairing. Смартфон використовує його безпосередньо в протоколі SMP. |
| `0x1B` | **LE Bluetooth Device Address** | 7 байтів | 6 байтів MAC-адреси у форматі **Little-Endian** + 1 байт типу адреси (`0x00` = Public Device Address, `0x01` = Random Static Address). |
| `0x1C` | **LE Role** | 1 байт | `0x00` = Тільки Peripheral, `0x01` = Тільки Central, `0x02` = Peripheral пріоритетний, `0x03` = Central пріоритетний. |
| `0x19` | **Appearance** | 2 байти | 16-бітний код категорії пристрою за Bluetooth SIG (наприклад, `0x0340` = Heart Rate Sensor, `0x0040` = Thermometer). |
| `0x22` | **LE SC Confirmation Value** | 16 байтів | Хеш підтвердження `C_192` або `C_256` для алгоритму LE Secure Connections (криптографія на основі еліптичних кривих P-256). |
| `0x23` | **LE SC Random Value** | 16 байтів | Випадкове число `R_192` або `R_256` для алгоритму LE Secure Connections, що передається разом із хешем `0x22`. |
| `0x24` | **URI** | Змінна | Додатковий рядок URI згідно зі специфікацією Bluetooth Core v5.x. |

## Структура Wi-Fi WSC Token (MIME: `application/vnd.wfa.wsc`)

Для автоматичного підключення смартфона до точки доступу Wi-Fi корисне навантаження NDEF містить атрибути Wi-Fi Simple Configuration (WSC) у форматі TLV (Type: 2 байти big-endian, Length: 2 байти big-endian, Value):

- `0x1026` (**Network Index**): Індекс конфігурації мережі (1 байт, зазвичай `0x01`).
- `0x1045` (**SSID**): Назва бездротової мережі (до 32 байтів ASCII).
- `0x1003` (**Authentication Type**): 2 байти big-endian. `0x0001` = Open, `0x0002` = WPA-Personal, `0x0020` = WPA2-Personal, `0x0040` = WPA3-Personal (SAE).
- `0x100F` (**Encryption Type**): 2 байти big-endian. `0x0002` = WEP, `0x0004` = TKIP, `0x0008` = AES/CCMP.
- `0x1027` (**Network Key**): Пароль або Pre-Shared Key мережі (8..63 байти ASCII).
- `0x1020` (**MAC Address**): 6-байтна MAC-адреса інтерфейсу точки доступу у прямому порядку байтів.
- `0x1049` (**Vendor Extension**): Додаткові специфічні розширення постачальника обладнання.

## Структура системного блоку Capability Container (CC)

Перед початком читання або запису NDEF-повідомлення контролер зчитувача перевіряє блок Capability Container, розташований на початку адресної карти мітки:

### Capability Container для міток Type 2 (NXP NTAG, 4 байти в блоці 0x03)

```
+------------+------------+-------------------+-----------------+
| Байт 0: CC0| Байт 1: CC1| Байт 2: CC2       | Байт 3: CC3     |
| Магічний   | Версія     | Розмір пам'яті    | Права доступу   |
| 0xE1       | 0x10..0x12 | Розмір EEPROM / 8 | 0x00 (R/W)      |
+------------+------------+-------------------+-----------------+
```

- `CC0` (`0xE1`): Магічне число NFC Forum, що ідентифікує наявність NDEF-сумісної розмітки.
- `CC1` (`0x10`): Версія стандарту Type 2 Tag (старші 4 біти — мажорна версія `1`, молодші 4 біти — мінорна `0`).
- `CC2`: Розмір пам'яті, поділений на 8 байтів (наприклад, для мітки 144 байти `CC2 = 18 = 0x12`; для мітки 888 байтів `CC2 = 111 = 0x6F`).
- `CC3` (`0x00`): Біти захисту доступу (`0x00` дозволяє вільне читання та запис без пароля; `0x0F` встановлює режим Read-Only).

### Capability Container для міток Type 5 (STMicroelectronics ST25DV, 8 байтів у блоці 0x00)

```
+------------+------------+------------+------------+-------------------------+
| Байт 0     | Байт 1     | Байт 2     | Байт 3     | Байти 4..7 (опціонально)|
| Магічний   | Версія     | Код розміру| Права (R/W)| Розширений розмір пам'яті|
| 0xE1       | 0x40 (v1.0)| 0x40..0xFF | 0x00 (R/W) | 4 байти (якщо Байт 2=0) |
+------------+------------+------------+------------+-------------------------+
```

- `Байт 0` (`0xE1`): Магічний маркер специфікації Type 5 Tag.
- `Байт 1` (`0x40`): Версія протоколу Type 5 та прапорці підтримки розширених команд читання ISO 15693 (Read Multiple Blocks).
- `Байт 2`: Код об'єму пам'яті (розмір у 8-байтних блоках; значення `0x00` сигналізує про використання 4-байтного поля розширеного розміру в байтах 4..7 для пам'яті понад 2 КБ).
- `Байт 3` (`0x00`): Базові права доступу до масиву пам'яті.

## Регістрова карта наскрізного режиму (Pass-Through / Fast Transfer Mode)

Для організації двостороннього швидкісного обміну через буфер SRAM без запису в EEPROM динамічні мітки використовують набір системних регістрів сесії (Session Registers):

| Назва регістра | Адреса (NTAG I2C) | Адреса (ST25DV) | Біти та призначення |
|---|---|---|---|
| `NC_REG` / `GPO` | `0x00` | `0x0000` | Конфігурація поведінки виводу переривання: `0x01` = індикація наявності поля, `0x02` = сигнал готовності даних у буфері SRAM, `0x04` = індикація помилки зв'язку. |
| `REG_LOCK` | `0x01` | `0x0001` | Прапорець захисту конфігурації: біт 0 блокує зміну налаштувань через інтерфейс RF з боку смартфона. |
| `SRAM_MIRROR` | `0x02` | `0x2000` | Початкова адреса дзеркалювання буфера SRAM в адресному просторі мітки. |
| `PTHRU_DIR` | `0x03` | `0x0002` | Напрямок наскрізного каналу: `0` = I2C до RF (передача даних від MCU до смартфона), `1` = RF до I2C (прийом пакетів від смартфона). |
| `RF_STATUS` | `0x04` | `0x2004` | Стан радіотракту: біт 0 вказує на наявність активної сесії читання, біт 1 сигналізує про успішну автентифікацію паролем. |
| `FIFO_STATUS` | `0x05` | `0x2005` | Прапорці апаратного буфера: біт 0 (`SRAM_RF_READY`) = смартфон записав блок, біт 1 (`SRAM_I2C_READY`) = мікроконтролер записав блок для відправки. |

## Низькорівневі радіокоманди зчитування NDEF

З боку смартфона вичитування пам'яті мітки відбувається за допомогою стандартних команд канального рівня:

- **Type 2 Tag (ISO 14443-3A):**
  - Команда `READ` (`0x30` + номер блоку): Повертає рівно 16 байтів даних (4 послідовні сторінки по 4 байти). Контроль помилок забезпечується 16-бітною контрольною сумою CRC_A.
  - Команда `FAST_READ` (`0x3A` + стартовий блок + кінцевий блок): Дозволяє вичитати весь діапазон пам'яті (до 256 сторінок) в одній RF-транзакції без повторної адресації кожного сектора.
- **Type 5 Tag (ISO 15693):**
  - Команда `Read Single Block` (`0x20` + номер блоку): Повертає 4 або 8 байтів сторінки.
  - Команда `Read Multiple Blocks` (`0x23` + стартовий блок + кількість): Вичитує суцільний масив EEPROM зі швидкістю передачі до 26.48 кбіт/с (режим High Data Rate).
