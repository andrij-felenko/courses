Перший зліт власноруч зібраного безпілотника або роботизованої платформи на заводських налаштуваннях регулятора майже завжди закінчується однією з двох крайнощів: апарат або за 10–15 секунд розігріває мотори до 80°C через високочастотний дзвін D-терма, або розгойдується, як холодець, повільно дрейфує за вітром і перевертається під час спроби різкої зупинки. Універсальних коефіцієнтів PID у фізичному світі не існує: зміна діаметра та кроку гвинта на один дюйм змінює момент інерції ротора в півтора раза, жорсткість карбонового променя зміщує частоту власного механічного резонансу з 80 до 220 Гц, а просідання напруги 4S або 6S акумулятора під час різкого газу змінює крутизну тяги моторів на 30–40%.

Щоб змусити апарат утримувати задану траєкторію з міліметровою точністю за будь-яких поривів вітру й при цьому не спалити силову установку, контури автоматичного керування доводять за строгою математичною і польотною методикою. Цей процес починається з найглибшого контуру кутової швидкості, проходить крізь налаштування цифрової фільтрації шуму гіроскопа, перевіряється вбудованими алгоритмами AutoTune і завершується узгодженням зовнішніх навігаційних контурів позиції.

## Чому контури налаштовують суворо «зсередини назовні»

Будь-яка сучасна система автоматичного керування безпілотним апаратом будується за принципом **підпорядкованого каскадного регулювання** (англ. *cascaded loop control*). Система розбивається на вкладені контури, кожен з яких вирішує власну динамічну задачу на своїй частоті дискретизації.

![Ієрархія каскадних контурів керування безпілотного апарата: від зовнішньої позиції через швидкість і кутове положення до внутрішнього контуру кутової швидкості та моторів](/root/course/embedded/dovedennia-konturiv-na-vlasnomu-aparati/img/cascade-loops.svg)
*Ієрархія каскадних контурів керування. Налаштування виконують строго зсередини назовні: від найшвидшого контуру кутової швидкості (Rate, 1–8 кГц) через кутове положення (Angle) до зовнішніх навігаційних контурів лінійної швидкості (Velocity) та координат (Position).*

У цій ієрархії виділяють чотири послідовні рівні:

1. **Внутрішній контур кутової швидкості (Rate / Gyro Loop):** працює з частотою 1000–8000 Гц безпосередньо з даними гіроскопа IMU. Його завдання — забезпечити необхідне кутове прискорення і створити відновлювальний момент навколо осей Roll, Pitch і Yaw. Смуга пропускання цього контуру становить 30–60 Гц.
2. **Середній контур кутового положення (Attitude Angle Loop):** оновлюється з частотою 250–500 Гц на основі оцінки орієнтації з фільтра Калмана (EKF). Він обчислює помилку між заданим кутом нахилу (в градусах) та поточним станом, перетворюючи її на цільову кутову швидкість (у deg/s) для контуру Rate. Смуга пропускання — 5–10 Гц.
3. **Зовнішній контур лінійної швидкості (Velocity Loop):** працює з частотою 50–100 Гц за даними оптичного потоку, лідара або супутникової навігації (GNSS). Помилка за лінійною швидкістю (м/с) перераховується в необхідний кут нахилу апарата та сумарну тягу. Смуга пропускання — 2–4 Гц.
4. **Найзовнішніший контур координат (Position Loop):** оновлюється з частотою 20–50 Гц. Порівнює цільові координати місії з поточним положенням і видає завдання швидкості. Смуга пропускання — 0.5–1 Гц.

Головне правило теорії автоматичного керування вимагає: **смуга пропускання внутрішнього контуру має бути щонайменше в 4–8 разів ширшою за смугу зовнішнього контуру**.

Чому це критично? Зовнішній контур розраховує свої вихідні команди в припущенні, що внутрішній контур відпрацює їх практично миттєво і без власного перерегулювання. Якщо контур кутової швидкості (Rate) має фазову затримку 40 мс або схильний до дзвону на частоті 6 Гц, то контур кутового положення (Angle), намагаючись вирівняти апарат, почне підсилювати цей дзвін. Система потрапить у режим прогресуючого розгойдування, і стабілізація розпадеться.

Тому будь-які спроби налаштовувати утримання точки за GPS (PosHold) або вирівнювання горизонту (Angle Mode) до того, як вилизано контур кутової швидкості (Rate PID), позбавлені фізичного сенсу. Тюнінг завжди рухається від заліза й гіроскопа назовні — до навігації.

## Фізичний важіль кожного коефіцієнта (P, I, D, FF)

Коли йдеться про налаштування PID-регулятора на реальному апараті, коефіцієнти розглядають не як абстрактні множники в коді, а як конкретні фізичні сили й моменти, що протидіють інерції маси та аеродинамічному збуренню.

![Перехідні характеристики відгуку кутової швидкості на одиничну сходинку завдання для різних комбінацій коефіцієнтів PID](/root/course/embedded/dovedennia-konturiv-na-vlasnomu-aparati/img/step-response-pid.svg)
*Відгук кутової швидкості на сходинку команди (Step Response). Ідеальний баланс (критичне демпфування) забезпечує швидкий вихід на полицю без перельоту. Надлишок P або брак D викликає затяжні коливання, брак P робить керування ватним, а надлишок D вносить високочастотне тремтіння й гріє мотори.*

### Пропорційний член (P) — жорсткість та швидкість реакції

Пропорційна складова створює керівний момент `τ_p`, строго пропорційний поточній помилці між бажаною кутовою швидкістю `ω_des` та виміряною швидкістю гіроскопа `ω_act`:

```
e(t)   = ω_des(t) − ω_act(t)
τ_p(t) = K_p · e(t)
```

Фізично `P` працює як віртуальна торсіонна пружина: що сильніше апарат відхилився від заданого обертання, то сильніше мотори штовхають його назад.
- **Замалий `P`:** пружина м'яка. Апарат реагує на стіки повільно, «плаває» в повітрі, провалюється за траєкторією під час маневрів і легко збивається будь-яким поривом вітру.
- **Завеликий `P`:** пружина занадто жорстка. Система реагує на помилку настільки агресивно, що за рахунок інерції пропелерів перескакує цільове положення. Виникають низькочастотні гармонійні коливання (типово 3–10 Гц), амплітуда яких наростає за зростання швидкості польоту.

### Диференційний член (D) — штучне демпфування та гальмування

Сам по собі пропорційний регулятор не здатний зупинити апарат рівно в цілі: накопичена кінетична енергія обертання неминуче викликає переліт (overshoot). Диференційна складова вносить у контур штучне в'язке тертя, протидіючи швидкості зміни виміряної величини:

```
τ_d(t) = −K_d · (d ω_act(t) / dt)
```

Зверніть увагу: у сучасних автопілотах диференціюють саме **виміряну кутову швидкість**, а не помилку керування `e(t)`. Це запобігає виникненню так званого «диференційного удару» (англ. *derivative kick*) — нескінченно великого стрибка моменту в мить, коли пілот миттєво переміщує стік керування.
- **Замалий `D`:** бракує гідравлічного демпфування. При будь-якій різкій зміні напрямку апарат «перелітає» цільову кутову швидкість на 20–40% і робить кілька затухаючих коливань, перш ніж стабілізуватися.
- **Завеликий `D`:** надмірний опір рухові та катастрофічне підсилення шуму давача. D-терм реагує на мікровібрації мотора, змушуючи ESC смикати обмотки з частотою сотень герц.

### Інтегральний член (I) — пам'ять помилки та компенсація статичних моментів

Навіть якщо `P` і `D` налаштовані бездоганно, реальний апарат має асиметрію: акумулятор зміщений від центру ваги на 5 мм, один мотор генерує на 3% менше тяги через зношений підшипник, або набігаючий потік повітря постійно задирає ніс. Пропорційний член не може компенсувати цей постійний момент, оскільки для створення сили йому потрібна ненульова помилка.

Інтегральна складова накопичує помилку в часі:

```
τ_i(t) = K_i · ∫ e(t) dt
```

Вона повільно нарощує керівний сигнал доти, доки стала помилка не стане строго рівною нулю.
- **Замалий `I`:** апарат «пливе» за вітром, задирає ніс під час розгону і вимагає постійного тримування стіками в польоті.
- **Завеликий `I`:** інтегратор вносить фазовий зсув на 90° назад, що викликає повільне плаваюче розгойдування (0.5–2 Гц).
- **Небезпека інтегрального насичення (Windup):** якщо апарат стоїть на землі або вперся пропелером у перешкоду, помилка не зникає, і інтегратор розганяє сигнал до максимуму. У мить відриву накопичений `I`-терм миттєво перекидає дрон. Для боротьби з цим обов'язково застосовують захист від насичення (англ. *anti-windup clamping*) та вимикають інтегратор за нульового газу (airmode / ground idle logic).

### Прямий зв'язок (Feedforward / FF) — швидкість без затримки зворотного зв'язку

Класичний PID чекає, поки виникне помилка `e(t)`, щоб почати діяти. Це створює затримку реакції на дії пілота. Канал Feedforward формує випереджальний момент прямо з похідної положення стіка:

```
τ_ff(t) = K_ff · (d ω_des(t) / dt)
```

`FF` «знає», що для розгону апарата до кутової швидкості 500 deg/s потрібен стартовий імпульс тяги, і подає його на мотори ще до того, як гіроскоп зафіксує відставання. Це дозволяє досягти блискавичного відгуку без надмірного задирання `P`, зберігаючи контур стійким.

## Тракт D-терма та фільтрація шуму: ціна чистого сигналу

Найбільш вразливе місце будь-якого контуру кутової швидкості — це обчислення похідної. Згадаймо базову властивість диференціювання гармонійного коливання з амплітудою `A` та частотою `ω`:

```
d/dt [ A · sin(ω t) ] = A · ω · cos(ω t)
```

Амплітуда вихідного сигналу **лінійно множиться на частоту `ω`**. Якщо корисний сигнал маневру безпілотника лежить у діапазоні 0.5–20 Гц, то механічний шум від незбалансованого пропелера та обертання моторів зосереджений у діапазоні 150–400 Гц. Шум на частоті 300 Гц під час взяття похідної буде підсилено в 300 разів сильніше, ніж корисний рух апарата!

![Тракт формування D-складової та каскад цифрової фільтрації спектра гіроскопа](/root/course/embedded/dovedennia-konturiv-na-vlasnomu-aparati/img/dterm-noise-filter.svg)
*Тракт формування D-складової. Сирий сигнал гіроскопа проходить через каскад режекторних та низькочастотних фільтрів, які вирізають вузькі резонансні піки обертання моторів і шум лопатей, захищаючи диференціатор від самозбудження.*

Без ретельно налаштованого каскаду фільтрації диференційний член перетворює сирий сигнал гіроскопа на потужний потік високочастотного сміття, що бомбардує регулятори швидкості (ESC).

### Архітектура каскаду фільтрів польотного контролера

Сучасний польотний стек (Betaflight, ArduPilot, PX4) використовує триступеневу фільтрацію:

1. **Динамічний режекторний фільтр за RPM-телеметрією (Dynamic RPM Notch):**
   Регулятори швидкості (ESC) повертають поточну швидкість обертання кожного мотора по протоколу DShot або телеметрійній шині. Знаючи точну частоту `f_rpm = (RPM / 60) · (N_poles / 2)`, автопілот розміщує вузькі режекторні фільтри з високою добротністю (`Q ≈ 4–8`) строго на частотах першої, другої та третьої гармонік кожного пропелера. Це дозволяє вирізати 95% механічної вібрації взагалі без відчутної затримки на корисних частотах.
2. **Адаптивний режектор на основі спектрального аналізу (Dynamic FFT Notch):**
   Якщо апарат не підтримує двосторонній DShot, контролер у реальному часі рахує ковзне віконне швидке перетворення Фур'є (вікно 32–64 відліки) і автоматично налаштовує центральну частоту фільтра (center frequency) на найпотужніший виявлений пік вібрації.
3. **Статичні фільтри низьких частот (Low-Pass Filter, LPF):**
   Застосовуються фільтри першого порядку (PT1 / Exponential Moving Average) або другого порядку (Bi-quad / Butterworth) із частотою зрізу 90–150 Гц для загального придушення високочастотного шуму давача вище корисної смуги.

### Фазова затримка — плата за фільтрацію

Фільтри не бувають безкоштовними. Будь-який фільтр низьких частот другого порядку додає у контур фазову затримку (Phase Delay), яка для частоти `f` приблизно дорівнює:

```
Δt_delay ≈ 1 / (2 · π · f_cutoff)
```

Якщо зріз фільтра встановлено на 100 Гц, затримка становить приблизно 1.6–2.5 мс. Здавалося б, це мізерний час, але для контуру стабілізації з тактовою частотою 8 кГц це запізнення з'їдає 15–20° запасу за фазою (phase margin). Якщо фільтрації забагато, регулятор починає боротися з тим відхиленням, яке вже минуло — виникає низькочастотний резонанс і самозбудження контуру.

**Золоте правило доведення фільтрів:** фільтрації має бути рівно стільки, щоб мотори залишалися ледь теплими після 2 хвилин активного польоту, і ні на герц більше. Зайва фільтрація вбиває стабільність так само надійно, як і вібрація.

Для вимірювання резонансів, розрахунку перехідних процесів та оцінки залишкового шуму використовують спеціалізований [аналізатор перехідної характеристики](root:embedded/dovedennia-konturiv-na-vlasnomu-aparati/proj-pid-step-analyzer.md), який обробляє бортові масиви даних.

## Ознаки перетюну та фізична діагностика

Коли коефіцієнти підсилення або рівні шуму перевищують допустимі межі стійкості системи, безпілотник демонструє характерні симптоми, кожен з яких має чітке фізичне пояснення.

### 1. Гарячі мотори (Warm/Hot Motors)

Це головний і найбільш небезпечний симптом перетюну або браку фільтрації D-терма.
- **Фізичний механізм:** мотори постійно отримують керуючі імпульси з частотою 100–300 Гц від зашумленого D-терма. Через механічну інерцію ротора (`J`) та пропелера мотор фізично не здатний змінювати швидкість обертання з такою частотою: ротор працює як механічний фільтр низьких частот і просто гуде на місці. Проте електричний струм високої амплітуди через обмотки протікає безперервно.
- **Наслідок:** уся високочастотна електрична енергія розсіюється у вигляді тепла Джоуля на активному опорі обмоток статора:
```
P_heat = I_rms² · R_phase
```
Якщо температура статора перевищує 80–90°C, неодимові магніти (N52/N54SH) зазнають незворотного теплового розмагнічування. Мотор назавжди втрачає константу моменту `K_v`, починає споживати ще більший струм і зрештою згоряє разом з ESC.

### 2. Дзвін на різких маневрах і Propwash

Під час різкого гальмування, виходу з пікірування або виконання сходинки на 180° апарат потрапляє у власний вихровий слід (англ. *propwash*), де набігаючий потік повітря хаотично турбулентний.
- **Ознака надлишку P:** апарат робить 3–6 помітних оку коливань з частотою 5–10 Гц після завершення різкого руху стіка.
- **Ознака браку D:** один великий глибокий відскок у протилежний бік після різкої зупинки (overshoot > 20%).
- **Ознака надлишку D:** швидке зудяче дрібне тремтіння (20–40 Гц), яке чути на слух як сухий тріск моторів під час маневру.

### 3. Просідання напруги акумулятора (Battery Voltage Sag)

Паразитні мікроколивання моторів під час перетюну створюють постійні реактивні сплески струму амплітудою 30–80 А, які не виконують корисної роботи зі створення підйомної сили.
- **Фізичний прояв:** напруга акумулятора під навантаженням миттєво провалюється на 1.5–2.5 В навіть на половинному газі, час польоту скорочується на 20–30%, а роз'єми живлення (XT60/XT90) відчутно нагріваються.

## Алгоритми AutoTune: як автопілот вимірює фізику апарата

Ручне налаштування контурів вимагає значного польотного досвіду. Для автоматизації цього процесу в сучасних польотних контролерах (зокрема в ArduPilot та PX4) реалізовано алгоритми **AutoTune**.

![Послідовність імпульсних збурень алгоритму AutoTune для визначення передатної функції осі](/root/course/embedded/dovedennia-konturiv-na-vlasnomu-aparati/img/autotune-pulse-sequence.svg)
*Принцип роботи алгоритму AutoTune. Автопілот генерує серію каліброваних імпульсів (Step Doublets), вимірює транспортну затримку τ, кутове прискорення α_max та період коливань, після чого розраховує коефіцієнти під заданий запас стійкості.*

### Принцип роботи AutoTune під капотом

AutoTune не намагається «вгадувати» коефіцієнти навмання. Він проводить серію активних ідентифікаційних експериментів прямо в польоті за кожною з осей (Roll, Pitch, Yaw по черзі):

1. **Генерація тестових імпульсів (Step Doublets):**
   Автопілот переводить апарат у режим стабілізованого зависання і подає на контур кутової швидкості серію коротких знакозмінних імпульсів (наприклад, +20 deg/s протягом 100 мс, пауза 200 мс, -20 deg/s протягом 100 мс).
2. **Вимірювання відгуку об'єкта керування:**
   Бортовий комп'ютер реєструє форму відгуку гіроскопа й обчислює дві ключові динамічні характеристики:
   - **Транспортне запізнення системи `τ`:** час від подачі сигналу до початку наростання кутової швидкості (визначає сумарний лаг фільтрів, протоколу ESC та індуктивності моторів).
   - **Максимальне кутове прискорення `α_max = (dω/dt)_max`:** показник енерговооруженості та тягооснащеності осі.
3. **Ітеративний пошук критичного підсилення:**
   Алгоритм поступово нарощує коефіцієнт `P` з кроком 10–15% під час кожного наступного циклу імпульсів, поки перерегулювання відгуку `Overshoot` не досягне контрольного порогу (зазвичай 10–12%). У цей момент фіксується критичне підсилення `K_u` та період власних коливань `T_u` (модифікований метод релейної ідентифікації Астрома-Хегглунда).
4. **Розрахунок D та I складових:**
   Коефіцієнт `D` підбирається так, щоб зафіксоване перерегулювання знизилося до 0–3%. Після цього інтегральний коефіцієнт `I` встановлюється пропорційно до `P` (зазвичай `K_i ≈ K_p / (2 · T_settle)`), щоб забезпечити нульову статичну помилку без внесення фазового запізнення на робочій частоті.
5. **Встановлення запасу стійкості (Gain Margin):**
   Отримані критичні значення множаться на коефіцієнт запасу надійності (Safety Factor, зазвичай 0.6–0.7). Це гарантує, що коли акумулятор розрядиться (і напруга впаде з 25.2 В до 21.0 В), або коли апарат потрапить у холодний потік щільного повітря, контур не зірветься в автоколивання.

## Покроковий польотний регламент доведення на практиці

Якщо AutoTune недоступний (наприклад, на нестандартних FPV-платформах або спеціалізованих дронах), доведення виконують за суворим інженерним чеклистом.

### Крок 0. Механіка та базова підготовка

1. Переконайтеся, що польотний контролер встановлено на м'які силіконові демпфери, а дроти джгута не натягнуті й не передають вібрацію з рами на плату.
2. Пропелери мають бути статично й динамічно збалансовані (відсутність вібраційного розмиття на кінцях лопатей під час тесту на землі).
3. Увімкніть RPM-фільтрацію (двосторонній DShot) або виставте консервативні частоти зрізу низькочастотних фільтрів (LPF 100 Гц, D-term LPF 80 Гц).
4. Зменшіть коефіцієнти `P`, `I`, `D` на 40% від типових дефолтів. Повністю вимкніть `Feedforward` (`K_ff = 0`).

### Крок 1. Налаштування контуру кутової швидкості (Rate Roll & Pitch)

Налаштування виконують у режимі прямого керування кутовою швидкістю (Acro / Rate Mode):

1. **Підйом P:** злітаємо у спокійному зависанні. Починаємо поступово піднімати `K_p` з кроком 15–20%. Робимо швидкі поодинокі клацання стіком Roll/Pitch. Піднімаємо `P` доти, доки після різкого відпускання стіка не з'явиться швидкий дзвін (3–5 коливань). Відкочуємо `P` на 20% назад.
2. **Підбір D:** тепер після сходинки помітний одиничний плавний переліт (overshoot). Починаємо піднімати `K_d` з кроком 10%. Завдання — досягти критичного демпфування: крива кутової швидкості має миттєво підходити до нуля без відскоку.
   > ⚠️ **Контроль нагріву:** після кожних 30 секунд польоту саджаємо апарат і пальцем перевіряємо температуру всіх чотирьох моторів. Якщо мотори стають гарячими (> 50°C), негайно зменшуємо `D` на 25% або посилюємо фільтрацію гіроскопа.
3. **Налаштування I:** перевіряємо стійкість у прямолінійному польоті з набором швидкості. Якщо дрон задирає ніс або дрейфує за кутом, піднімаємо `K_i` доти, доки апарат не триматиме заданий кут нахилу, як на рейках.
4. **Додавання Feedforward:** плавно додаємо `K_ff`, спостерігаючи за співвідношенням `SetPoint` проти `Gyro` в логах. Значення `FF` вважається ідеальним, коли затримка між рухом стіка і початком обертання скорочується до 10–15 мс.

### Крок 2. Налаштування осі рискання (Yaw)

Вісь Yaw на мультироторі працює принципово інакше, ніж Roll та Pitch: момент створюється не нахилом тяги, а різницею реактивних моментів протилежних пар пропелерів.
- Крутизна керування по Yaw у 3–5 разів нижча, ніж по Roll/Pitch.
- Коефіцієнт `D` для осі Yaw зазвичай ставлять мінімальним або взагалі обнуляють (`K_d_yaw ≈ 0`), оскільки аеродинамічний опір обертанню пропелерів у площині диска забезпечує потужне природне демпфування.
- Основну роботу по Yaw виконують `P` та потужний `Feedforward`.

### Крок 3. Налаштування контуру кутового положення (Angle / Attitude)

Перемикаємося в режим горизонту (Angle Mode):
- Тут працює єдиний пропорційний коефіцієнт `P_angle` (або `Angle P`).
- Якщо `Angle P` замалий — дрон повертається в горизонт мляво й неохоче.
- Якщо `Angle P` завеликий — виникає повільне, величне розгойдування всього апарата з частотою 1–2 Гц.
- Підбираємо `Angle P` так, щоб повернення в нуль після відпускання стіка відбувалося за 0.3–0.5 с без коливань.

### Крок 4. Зовнішні контури швидкості та позиції (Velocity & Position)

Тестується в режимах утримання позиції (PosHold / Loiter / Auto):
- Налаштовуємо `Velocity PID`: перевіряємо гальмування з максимальної швидкості (15 м/с). Дрон повинен плавно задерти ніс, скинути швидкість і зупинитися без «витріщання» і перельоту точки зупинки.
- Якщо дрон перелітає точку зупинки й потім здає назад — зменшуємо `I` контуру швидкості або збільшуємо `D`.
- Якщо виникає ефект «унітазингу» (дрон починає намотувати кола все більшого радіуса навколо точки) — це свідчить про розкалібрування компаса або надмірний коефіцієнт `Position P`.

### Таблиця польотної діагностики контурів

| Симптом у польоті | Фізична причина | Інженерна дія |
|---|---|---|
| Високочастотний писк, гарячі мотори після 30 с | ВЧ шум гіроскопа потрапляє в D-терм | Знизити `K_d`, увімкнути RPM Notch / знизити зріз LPF |

## Програмна реалізація ядра каскадного регулятора

Нижче наведено практичну реалізацію циклу оновлення кутової швидкості польотного контролера. Код демонструє диференціювання за виміром (Derivative on Measurement), фільтрацію D-терма фільтром першого порядку (PT1), канал Feedforward та інтегрування з обмеженням насичення (Anti-windup).

```c
#include <stdint.h>
#include <stdbool.h>
#include <math.h>

typedef struct {
    // Коефіцієнти підсилення
    float kp;
    float ki;
    float kd;
    float kff;

    // Стан інтегратора та фільтрів
    float integrator;
    float prev_gyro;
    float prev_setpoint;
    float dterm_filtered;

    // Параметри фільтрації та обмеження
    float dterm_lpf_alpha;  // Коефіцієнт згладжування PT1
    float out_min;          // Мінімальний вихід моменту (-1.0f)
    float out_max;          // Максимальний вихід моменту (+1.0f)
    float i_limit;          // Поріг насичення інтегратора
} RatePidController;

static inline float constrain_f(float val, float min_val, float max_val) {
    if (val < min_val) return min_val;
    if (val > max_val) return max_val;
    return val;
}

// Ініціалізація структури регулятора
void rate_pid_init(RatePidController *pid, float kp, float ki, float kd, float kff,
                   float cutoff_hz, float loop_rate_hz) {
    pid->kp = kp;
    pid->ki = ki;
    pid->kd = kd;
    pid->kff = kff;

    pid->integrator = 0.0f;
    pid->prev_gyro = 0.0f;
    pid->prev_setpoint = 0.0f;
    pid->dterm_filtered = 0.0f;

    pid->out_min = -1.0f;
    pid->out_max = 1.0f;
    pid->i_limit = 0.35f; // Інтегратор не може займати більше 35% тяги

    // Розрахунок коефіцієнта PT1 фільтра: alpha = dt / (RC + dt)
    float dt = 1.0f / loop_rate_hz;
    float rc = 1.0f / (2.0f * 3.14159265f * cutoff_hz);
    pid->dterm_lpf_alpha = dt / (rc + dt);
}

// Основний крок обчислення моменту (викликається в циклі 1-8 кГц)
float rate_pid_update(RatePidController *pid, float setpoint_dps, float gyro_dps,
                      float dt, bool enable_i) {
    // 1. Помилка кутової швидкості
    float error = setpoint_dps - gyro_dps;

    // 2. Пропорційна складова
    float p_out = pid->kp * error;

    // 3. Диференційна складова (Derivative on Measurement)
    // Диференціюємо зміну виміру гіроскопа, а не помилку
    float gyro_delta = (gyro_dps - pid->prev_gyro) / dt;
    pid->prev_gyro = gyro_dps;

    float raw_dterm = -pid->kd * gyro_delta;

    // Проходження крізь PT1 низькочастотний фільтр D-терма
    pid->dterm_filtered += pid->dterm_lpf_alpha * (raw_dterm - pid->dterm_filtered);

    // 4. Прямий зв'язок (Feedforward) за швидкістю зміни стіка
    float sp_delta = (setpoint_dps - pid->prev_setpoint) / dt;
    pid->prev_setpoint = setpoint_dps;
    float ff_out = pid->kff * sp_delta;

    // 5. Інтегральна складова із захистом від насичення (Anti-Windup)
    if (enable_i) {
        pid->integrator += pid->ki * error * dt;
        pid->integrator = constrain_f(pid->integrator, -pid->i_limit, pid->i_limit);
    } else {
        // Плавне обнулення інтегратора на землі
        pid->integrator *= 0.95f;
    }

    // 6. Сумування компонентів і загальне насичення
    float total_out = p_out + pid->integrator + pid->dterm_filtered + ff_out;
    return constrain_f(total_out, pid->out_min, pid->out_max);
}
```

```cpp
#include <cmath>
#include <algorithm>
#include <numbers>

class RatePidController {
public:
    RatePidController(float kp, float ki, float kd, float kff,
                      float cutoff_hz, float loop_rate_hz)
        : kp_{kp}, ki_{ki}, kd_{kd}, kff_{kff} {
        const float dt = 1.0f / loop_rate_hz;
        const float rc = 1.0f / (2.0f * std::numbers::pi_v<float> * cutoff_hz);
        dterm_lpf_alpha_ = dt / (rc + dt);
    }

    void reset() noexcept {
        integrator_ = 0.0f;
        prev_gyro_ = 0.0f;
        prev_setpoint_ = 0.0f;
        dterm_filtered_ = 0.0f;
    }

    float update(float setpoint_dps, float gyro_dps, float dt, bool enable_i) noexcept {
        // 1. Помилка кутової швидкості
        const float error = setpoint_dps - gyro_dps;

        // 2. Пропорційна складова
        const float p_out = kp_ * error;

        // 3. Диференціювання за виміром (Derivative on Measurement)
        const float gyro_delta = (gyro_dps - prev_gyro_) / dt;
        prev_gyro_ = gyro_dps;

        const float raw_dterm = -kd_ * gyro_delta;
        dterm_filtered_ += dterm_lpf_alpha_ * (raw_dterm - dterm_filtered_);

        // 4. Прямий зв'язок Feedforward
        const float sp_delta = (setpoint_dps - prev_setpoint_) / dt;
        prev_setpoint_ = setpoint_dps;
        const float ff_out = kff_ * sp_delta;

        // 5. Інтегрування з обмеженням (Anti-Windup)
        if (enable_i) {
            integrator_ += ki_ * error * dt;
            integrator_ = std::clamp(integrator_, -i_limit_, i_limit_);
        } else {
            integrator_ *= 0.95f;
        }

        // 6. Сумарний вихідний момент на мікшер
        const float total_out = p_out + integrator_ + dterm_filtered_ + ff_out;
        return std::clamp(total_out, out_min_, out_max_);
    }

private:
    float kp_{0.0f};
    float ki_{0.0f};
    float kd_{0.0f};
    float kff_{0.0f};

    float integrator_{0.0f};
    float prev_gyro_{0.0f};
    float prev_setpoint_{0.0f};
    float dterm_filtered_{0.0f};

    float dterm_lpf_alpha_{0.1f};
    float out_min_{-1.0f};
    float out_max_{1.0f};
    float i_limit_{0.35f};
};
```

Розуміючи фізичну природу кожного коефіцієнта і дотримуючись послідовності від внутрішнього контуру гіроскопа до зовнішньої навігації, розробник отримує повністю передбачуваний, стійкий і слухняний апарат.
