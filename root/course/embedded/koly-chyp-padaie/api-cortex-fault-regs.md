# 📋 Регістри діагностики збоїв ядра ARM Cortex-M

Цей довідник містить повну структуру системних регістрів діагностики апаратних винятків (System Control Block, SCB), конфігурації співпроцесора з рухомою комою (FPU) та периферійних регістрів причин скидання для мікроконтролерів на базі архітектури ARMv7-M та ARMv8-M (ядра Cortex-M3, Cortex-M4, Cortex-M7 та Cortex-M33). Усі системні регістри ядра відображені в адресний простір керування з базовою адресою `0xE000ED00` (CMSIS-структура `SCB`).

## Регістри фіксації джерела скидання (Reset Status Registers)

Перед аналізом стану ядра після перезавантаження операційна система або стартовий код зчитує апаратний регістр скидання. Прапорці в цих регістрах є «липкими» (*sticky*): вони встановлюються відповідною апаратною схемою (супервізором живлення, сторожовим таймером чи лінією піна) і зберігають свій стан крізь процедуру перезапуску доти, доки їх не буде явно очищено записом у керівний біт.

### Регістр RCC->CSR (STM32 Family)
Базова адреса: `0x40023874` (для STM32F4) або `0x40021024` (STM32F1). Біти скидання зосереджені у старшому байті:

| Біт | Назва макросу CMSIS | Опис фізичного джерела скидання |
|:---|:---|:---|
| `31` | `RCC_CSR_LPWRRSTF` | **Low-Power Reset.** Скидання згенеровано при переході в режим Standby/Stop через невідповідну конфігурацію живлення. |
| `30` | `RCC_CSR_WWDGRSTF` | **Window Watchdog Reset.** Віконний сторожовий таймер добіг до нижньої межі або був оновлений поза дозволеним часовим вікном. |
| `29` | `RCC_CSR_IWDGRSTF` | **Independent Watchdog Reset.** Незалежний сторожовий таймер (тактований від автономного LSI) вичерпав свій таймаут через зависання коду. |
| `28` | `RCC_CSR_SFTRSTF` | **Software Reset.** Програмне скидання через запис `SYSRESETREQ` у системний регістр `SCB->AIRCR` (виклик `NVIC_SystemReset()`). |
| `27` | `RCC_CSR_PORRSTF` | **Power-On / Power-Down Reset.** Спрацювання вбудованого компаратора живлення при подачі живлення або падінні нижче порогу POR/PDR (~1.7–1.8 В). |
| `26` | `RCC_CSR_PINRSTF` | **NRST Pin Reset.** Фізичне скидання від зовнішнього сигналу низького рівня на виводі NRST (натискання кнопки або зовнішній супервізор). |
| `25` | `RCC_CSR_BORRSTF` | **Brown-Out Reset.** Спрацювання багаторівневого детектора BOR при короткочасному падінні напруги нижче обраного робочого порогу (2.1 В, 2.4 В, 2.7 В). |
| `24` | `RCC_CSR_RMVF` | **Remove Reset Flag.** Біт очищення: запис `1` у цей біт скидає всі перелічені вище прапорці `*RSTF` в нуль. |

### Регістри скидання інших мікроконтролерних родин
- **NXP LPC / i.MX RT (`SYSCON->SYSRSTSTAT`):** Біт `POR` (подача живлення), `EXTRST` (зовнішній пін), `WDT` (сторож), `BOD` (brown-out детектор), `SYSRST` (програмне скидання ядра).
- **Silicon Labs EFM32 / Gecko (`RMU->RSTCAUSE`):** Біти `PORST`, `BODUNREGRST`, `EXTRST`, `WDOGRST`, `SYSREQRST`.
- **Microchip SAM D21/E54 (`RSTC->RCAUSE`):** 8-бітний регістр з масками `RSTC_RCAUSE_POR`, `RSTC_RCAUSE_BOD12`, `RSTC_RCAUSE_BOD33`, `RSTC_RCAUSE_EXT`, `RSTC_RCAUSE_WDT`, `RSTC_RCAUSE_SYST`.

## Регістр статусу HardFault (SCB->HFSR)

Адреса: `0xE000ED2C`. Розмір: 32 біти. Скидається апаратно при Reset.
Запис одиниці в біт скидає відповідний прапорець (механізм `rc_w1` — *read / clear on write-1*).

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `31` | `DEBUGEVT` | rc_w1 | **Подія налагодження.** Встановлюється, коли HardFault викликано точкою зупину (breakpoint), тригером модуля DWT або запитом відладчика через вектор зупинки зупиненого процесора. |
| `30` | `FORCED` | rc_w1 | **Вимушена ескалація збою.** Вказує, що HardFault стався через неможливість виконати підлеглий виняток (MemManage, BusFault, UsageFault) — або тому, що його обробник вимкнено в `SHCSR`, або через виникнення збою всередині винятку однакового чи вищого пріоритету. Справжню причину слід шукати в підлеглих полях `CFSR`. |
| `29:2` | — | RO | Зарезервовано. Читається як 0. |
| `1` | `VECTBL` | rc_w1 | **Збій таблиці векторів.** Помилка вибірки адреси вектора з таблиці переривань (BusFault під час читання вектора з векторної таблиці). Вказує на пошкодження початкової адреси таблиці в регістрі `SCB->VTOR` або збій шини пам'яті Flash/RAM. |
| `0` | — | RO | Зарезервовано. Читається як 0. |

## Конфігурований регістр статусу збоїв (SCB->CFSR)

Адреса: `0xE000ED28`. Розмір: 32 біти.
Регістр `CFSR` об'єднує три окремі субрегістри, до яких можна звертатися як до одного 32-бітного слова або побайтно / попівслова:
- `SCB->CFSR` (32 біти, зсув `0x00`): Загальний доступ до всіх 32 прапорців збоїв.
- `SCB->MMFSR` (8 біт, зсув `0x00`, біти `7:0`): Memory Management Fault Status Register.
- `SCB->BFSR` (8 біт, зсув `0x01`, біти `15:8`): BusFault Status Register.
- `SCB->UFSR` (16 біт, зсув `0x02`, біти `31:16`): UsageFault Status Register.

Усі прапорці в `CFSR` мають поведінку `rc_w1` (очищення записом 1 у відповідний біт).

### 1. Субрегістр MemManage Fault (SCB->MMFSR / CFSR[7:0])

Керується блоком захисту пам'яті (MPU) та атрибутами системної карти адрес ARM.

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `7` | `MMARVALID` | rc_w1 | **Адреса MMAR валідна.** Якщо 1, регістр `SCB->MMFAR` містить точну адресу пам'яті, спроба доступу до якої спричинила збій MPU. |
| `6:5` | — | RO | Зарезервовано. |
| `4` | `MSTKERR` | rc_w1 | **Збій стекування при вході у виняток.** Апаратна спроба зберегти контекст на стек провалилася через порушення прав доступу MPU (наприклад, переповнення стека досягло захищеного бар'єра MPU). |
| `3` | `MUNSTKERR` | rc_w1 | **Збій дестекування при виході з винятку.** Спроба відновити контекст зі стека викликала порушення правил доступу MPU. |
| `2` | — | RO | Зарезервовано. |
| `1` | `DACCVIOL` | rc_w1 | **Порушення доступу до даних.** Спроба читання або запису за адресою, забороненою поточними налаштуваннями регіонів MPU (наприклад, запис у захищену від запису область або доступ непривілейованого коду до привілейованої пам'яті). |
| `0` | `IACCVIOL` | rc_w1 | **Порушення вибірки інструкцій.** Спроба вибірки та виконання інструкцій з області пам'яті, для якої в MPU встановлено атрибут eXecute-Never (XN), або з неіснуючого діапазону. |

### 2. Субрегістр BusFault (SCB->BFSR / CFSR[15:8])

Фіксує апаратні відповіді про помилку від системних шин AHB та APB (сигнал `HRESP = ERROR`).

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `7` | `BFARVALID` | rc_w1 | **Адреса BFAR валідна.** Якщо 1, регістр `SCB->BFAR` містить точну адресу пам'яті чи периферійного регістра, звертання до якого згенерувало Bus Error. |
| `6:5` | — | RO | Зарезервовано. |
| `4` | `STKERR` | rc_w1 | **Збій збереження стека.** Апаратне розміщення стекового фрейму при вході у виняток спричинило помилку шини. |
| `3` | `UNSTKERR` | rc_w1 | **Збій відновлення стека.** Відновлення контексту зі стека при виході з винятку спричинило помилку шини. |
| `2` | `IMPRECISERR` | rc_w1 | **Неточна помилка шини даних.** Збій стався під час асинхронного буферизованого запису через чергу запису ядра (Store Buffer). Збережений на стеку `PC` вказує на наступні інструкції, а не на сам рядок винного запису! `BFARVALID` завжди 0 при неточних помилках. |
| `1` | `PRECISERR` | rc_w1 | **Точна помилка шини даних.** Збій стався при синхронній операції читання або небуферизованого запису. Збережений на стеку `PC` вказує на точну інструкцію, що спричинила помилку. Якщо `BFARVALID=1`, адреса знаходиться в `SCB->BFAR`. |
| `0` | `IBUSERR` | rc_w1 | **Помилка шини при вибірці інструкції.** Процесор не зміг отримати інструкцію з пам'яті (Flash/RAM) через збій контролера шини або спробу вибірки з незамапованої адреси. |

### 3. Субрегістр UsageFault (SCB->UFSR / CFSR[31:16])

Відображає помилки логіки ядра, невалідні інструкції та порушення формату операндів.

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `9` | `DIVBYZERO` | rc_w1 | **Ділення на нуль.** Відбулася спроба виконання інструкцій `SDIV` або `UDIV` з дільником 0. Генерується лише за умови, що в `SCB->CCR` встановлено біт `DIV_0_TRP`. |
| `8` | `UNALIGNED` | rc_w1 | **Невирівняний доступ до пам'яті.** Виник непідтримуваний або заборонений невирівняний доступ. Генерується завжди для `LDRD`, `STRD`, `LDM`, `STM`, а для звичайних `LDR`/`STR` — за умови увімкненого біта `UNALIGN_TRP` у `SCB->CCR`. |
| `7:4` | — | RO | Зарезервовано. |
| `3` | `NOCP` | rc_w1 | **Спроба доступу до невизначеного або вимкненого співпроцесора.** Найчастіше — виконання інструкції FPU при вимкненому блоці плаваючої крапки в регістрі `SCB->CPACR` (біти CP10/CP11). |
| `2` | `INVPC` | rc_w1 | **Невалідний стан PC при завантаженні.** Спроба завантаження невалідної адреси або невалідне значення `EXC_RETURN` при виході з обробника переривання. |
| `1` | `INVSTATE` | rc_w1 | **Невалідний стан виконання (Invalid State).** Спроба виконати інструкцію при скинутому біті Thumb (`xPSR.T = 0`) або виклик функції за парною адресою через покажчик (втрата молодшого біта 0). |
| `0` | `UNDEFINSTR` | rc_w1 | **Невідома інструкція.** Процесор зустрів недійсний код операції (нерозпізнаний опкод). Свідчить про пошкодження коду у Flash, затирання пам'яті програм або стрибок на ділянку даних / затертий стек. |

## Адресні регістри збоїв (SCB->MMFAR та SCB->BFAR)

### SCB->MMFAR (MemManage Fault Address Register)
- Базова адреса: `0xE000ED34`. Розмір: 32 біти. Доступ: RW.
- Містить 32-бітну адресу пам'яті, яка спричинила збій MemManage.
- **Правило перевірки достовірності:** Значення в MMFAR є дійсним виключно у випадку, коли біт `SCB->CFSR.MMFSR.MMARVALID == 1`. Якщо цей біт дорівнює нулю, вміст регістра не оновлювався і містить сміття від попередніх подій.

### SCB->BFAR (BusFault Address Register)
- Базова адреса: `0xE000ED38`. Розмір: 32 біти. Доступ: RW.
- Містить 32-бітну адресу пам'яті або периферійного регістра, транзакція на шині до якого згенерувала сигнал помилки.
- **Правило перевірки достовірності:** Значення в BFAR дійсне виключно за умови `SCB->CFSR.BFSR.BFARVALID == 1`. При неточних помилках шини (`IMPRECISERR = 1`) конвеєр ядра та буфер запису втрачають зв'язок між виконаною інструкцією та адресою в пам'яті, тому `BFARVALID` завжди скинутий у 0.

## Керування системними обробниками (SCB->SHCSR)

Адреса: `0xE000ED24`. Розмір: 32 біти. Доступ: RW.
Дозволяє увімкнути роздільну обробку винятків замість їхнього автоматичного скидання в загальний HardFault, а також контролювати активний стан обробників:

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `18` | `USGFAULTENA` | RW | **1** = Увімкнути окремий обробник `UsageFault_Handler`. **0** = Ескалація збоїв UsageFault у HardFault. |
| `17` | `BUSFAULTENA` | RW | **1** = Увімкнути окремий обробник `BusFault_Handler`. **0** = Ескалація збоїв BusFault у HardFault. |
| `16` | `MEMFAULTENA` | RW | **1** = Увімкнути окремий обробник `MemManage_Handler`. **0** = Ескалація збоїв MemManage у HardFault. |
| `15` | `SVCALLPENDED`| RW | Прапорець очікування виконання системного виклику SVC. |
| `14` | `BUSFAULTPENDED` | RW | Прапорець очікування обробки винятку BusFault. |
| `13` | `MEMFAULTPENDED` | RW | Прапорець очікування обробки винятку MemManage. |
| `12` | `USGFAULTPENDED` | RW | Прапорець очікування обробки винятку UsageFault. |
| `11` | `SYSTICKACT` | RW | 1 = Обробник таймера SysTick виконується в даний момент. |
| `10` | `PENDSVACT` | RW | 1 = Обробник перемикання контексту PendSV активний. |
| `8` | `MONITORACT` | RW | 1 = Обробник Debug Monitor активний. |
| `7` | `SVCALLACT` | RW | 1 = Обробник SVCall активний. |
| `3` | `USGFAULTACT` | RW | 1 = Обробник UsageFault активний. |
| `1` | `BUSFAULTACT` | RW | 1 = Обробник BusFault активний. |
| `0` | `MEMFAULTACT` | RW | 1 = Обробник MemManage активний. |

## Конфігурація ядра та апаратні пастки (SCB->CCR)

Адреса: `0xE000ED14`. Розмір: 32 біти. Доступ: RW.
Задає поведінку конвеєра інструкцій та правила генерації апаратних пасток:

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `9` | `STKALIGN` | RW | **Вирівнювання стека на 8 байтів при вході у виняток.** За стандартом ARMv7-M / ARMv8-M повинен бути встановлений у 1 для забезпечення вимог стандарту AAPCS (вирівнювання 64-бітних типів `double` і `uint64_t`). |
| `8` | `BFHFNMIGN` | RW | Якщо 1, збої шини (BusFault) ігноруються під час виконання HardFault і NMI. |
| `4` | `DIV_0_TRP` | RW | **Генерація винятку при діленні на нуль.** Якщо 1, виконання `SDIV` або `UDIV` з дільником 0 генерує `UsageFault: DIVBYZERO`. Якщо 0, процесор повертає частку 0 без збою. |
| `3` | `UNALIGN_TRP` | RW | **Генерація винятку при невирівняному доступі.** Якщо 1, будь-який невирівняний доступ за інструкціями `LDR`/`STR`/`LDRH`/`STRH` негайно генерує `UsageFault: UNALIGNED`. |
| `0` | `NONBASETHRDENA`| RW | Дозволяє повернення у Thread Mode без скидання активного рівня пріоритету обробника. |

## Керування FPU та лінивим збереженням контексту (SCB->CPACR та FPU->FPCCR)

Для мікроконтролерів із апаратним блоком плаваючої крапки (Cortex-M4F, Cortex-M7, Cortex-M33F) взаємодія зі співпроцесорами регулюється регістром `SCB->CPACR` (`0xE000ED88`):
- Біти `23:20` (`CP10` та `CP11`): Контроль доступу до FPU. Значення `0b11` (Full Access) для обох бітових полів є обов'язковим перед виконанням будь-якої інструкції з плаваючою крапкою. Спроба виконати асемблерну інструкцію `VADD`, `VLDR` тощо при закритому доступі миттєво генерує `UsageFault: NOCP`.

Регістр `FPU->FPCCR` (`0xE000EF34` — Floating-Point Context Control Register) визначає автоматичне збереження 16 додаткових регістрів плаваючої крапки (`S0`–`S15`) та регістра стану `FPSCR`:
- Біт `31` (`ASPEN` — Auto Stacking Enable): Дозволяє ядру автоматично резервувати місце під FPU-контекст при виникненні винятку.
- Біт `30` (`LSPEN` — Lazy Stacking Enable): Вмикає оптимізацію відкладеного збереження. Місце на стеку виділяється, але фізичний запис значень регістрів `S0`–`S15` відкладається до моменту, коли сам обробник переривання вперше спробує використати інструкцію з плаваючою крапкою. Якщо обробник не користується FPU, запис у пам'ять не виконується взагалі, що зменшує латентність переривань із 26 тактів до 12.
- Біт `0` (`LSPACT` — Lazy Stacking Active): Вказує, що відкладене збереження перебуває в активному стані.

## Керування буферизацією шини (SCB->ACTLR)

Адреса: `0xE000E008`. Розмір: 32 біти. Доступ: RW (доступний тільки в привілейованому режимі ядра).

| Біт | Назва | Доступ | Опис призначення |
|:---|:---|:---:|:---|
| `1` | `DISDEFWBUF` | RW | **Вимкнення буфера запису (Store Buffer).** Якщо 1, усі операції запису виконуються суворо синхронно (без буферизації). Усі помилки шини при записі стають **точними** (`PRECISERR = 1`, `BFARVALID = 1`), що дозволяє під час налагодження визначити точний рядок коду і адресу збійного запису, ціною незначного зниження швидкодії шини. |

## Значення регістра LR при вході у виняток (Коди EXC_RETURN)

При передачі керування в обробник винятку апаратна логіка записує в регістр `LR` (R14) спеціальний псевдоадресний код повернення `EXC_RETURN`, біти якого кодують стан ядра перед аварією:

| Біт | Значення = 0 | Значення = 1 | Інженерне значення при діагностиці |
|:---|:---|:---|:---|
| `4` | Збережено розширений кадр FPU (26 слів) | Збережено базовий кадр (8 слів) | Визначає розмір збереженого стек-фрейму для коректного зсуву покажчиків. |
| `3` | Повернення в режим обробника (Handler Mode) | Повернення в базовий режим потоку (Thread Mode) | Показує, чи збій стався у звичайній програмі (Thread), чи всередині переривання (Handler). |
| `2` | Використовувався головний стек (MSP) | Використовувався стек процесу / задачі (PSP) | **Критично для вилучення дампу:** вказує, з якого регістра (`MSP` чи `PSP`) знімати кадр аварії! |
| `0` | Зарезервовано (ARMv7-M) | 1 (ARMv7-M) | Базовий маркер формату коду повернення. |

Типові числові магічні константи `EXC_RETURN`:
- `0xFFFFFFF9` — повернення в Thread Mode з використанням головного стека `MSP`, базовий 8-слівний фрейм.
- `0xFFFFFFFD` — повернення в Thread Mode з використанням стека задачі `PSP`, базовий 8-слівний фрейм (типовий випадок збою RTOS-задачі).
- `0xFFFFFFF1` — повернення в Handler Mode (збій стався всередині іншого переривання).
- `0xFFFFFFE9` / `0xFFFFFFED` — аналогічні стани для ядра з активним розширеним фреймом блоку FPU.

## Програмна ініціалізація діагностичного середовища

Для забезпечення максимальної інформативності діагностики під час розробки рекомендується налаштувати регістри SCB на ранньому етапі завантаження прошивки:

:::tabs
```c
void Fault_Diagnostics_Init(void) {
    // 1. Увімкнути роздільні обробники винятків у SHCSR
    SCB->SHCSR |= SCB_SHCSR_MEMFAULTENA_Msk |
                  SCB_SHCSR_BUSFAULTENA_Msk |
                  SCB_SHCSR_USGFAULTENA_Msk;

    // 2. Увімкнути пастки помилок ділення на нуль і невирівняного доступу
    SCB->CCR |= SCB_CCR_DIV_0_TRP_Msk |
                SCB_CCR_UNALIGN_TRP_Msk;

    #ifdef DEBUG
    // 3. Вимкнути буферизацію запису шини для точної локалізації BusFault
    SCB->ACTLR |= SCB_ACTLR_DISDEFWBUF_Msk;
    #endif
}
```
