# 📜 Вразливість WPS і атака Pixie Dust: як зламали кнопку на роутері

Коли у 2006 році консорціум Wi-Fi Alliance представив стандарт Wi-Fi Protected Setup (WPS), мета виглядала бездоганною: позбавити звичайного користувача потреби вручну вводити довгі 64-символьні шістнадцяткові ключі WPA2 на пристроях без повноцінної клавіатури — принтерах, бездротових фоторамках і перших датчиках розумного дому. Замість складного пароля пропонувалися два прості шляхи: фізичне натискання кнопки на корпусі роутера (Push Button Configuration, PBC) або введення короткого 8-значного цифрового PIN-коду, надрукованого на наліпці знизу маршрутизатора. Проте вже за кілька років саме цей протокол став однією з найгучніших катастроф у безпеці бездротових мереж.

Головна концептуальна помилка полягала у способі валідації PIN-коду. Вісім десяткових цифр у теорії дають простір у `10⁸ = 100 000 000` комбінацій. Для перебору такого масиву через бездротові запити з обмеженою швидкістю роутера знадобилися б роки неперервних атак, що робило б онлайновий злам непрактичним. Але автори протоколу WPS 1.0 заклали в архітектуру фатальне спрощення, яке у грудні 2011 року оприлюднив австрійський дослідник безпеки Стефан Фібок (Stefan Viehböck), а незалежно від нього — Крейг Геффнер (Craig Heffner).

```
Повний PIN (8 цифр): [ D1 D2 D3 D4 ] [ D5 D6 D7 ] [ C8 ]
                      Перша половина   Друга половина  Контрольна сума
                      10 000 спроб     1 000 спроб     (детермінована)
```

Протокол автентифікації розбивав перевірку PIN-коду на два незалежні послідовні кроки в рамках обміну повідомленнями EAP-WSC (Extensible Authentication Protocol — Wi-Fi Simple Configuration):

```
Клієнт                             Точка доступу (Роутер)
  |                                        |
  | -------- M1 (Enrollee Nonce) --------> |
  | <------- M2 (Registrar Nonce) -------- |
  | -------- M3 (Hash перших 4 цифр) ----> |
  | <------- M4 (EAP-NACK або OK) -------- | [Помилка? Перша половина хибна!]
  | -------- M5 (Hash наступних 3 цифр) -> |
  | <------- M6 (EAP-NACK або OK) -------- | [Помилка? Друга половина хибна!]
  | -------- M7 -------------------------> |
  | <------- M8 (Передача WPA-ключа) ----- |
```

Якщо перші 4 цифри виявлялися хибними, роутер негайно обривав сесію на кроці M4 негативною відповіддю EAP-NACK. Клієнту не потрібно було вгадувати другі 4 цифри: йому достатньо було перебрати лише першу половину (`10⁴ = 10 000` варіантів). Як тільки роутер відповідав успіхом і надсилав повідомлення M4, перша четвірка вважалася підтвердженою.

Для другої частини лишалося перевірити лише 3 цифри (`10³ = 1 000` комбінацій), оскільки восьма цифра була простою контрольною сумою за алгоритмом Луна (Luhn checksum) від попередніх семи і обчислювалася наперед.

Замість 100 мільйонів комбінацій складність атаки впала до:

```
N = 10⁴ + 10³ = 10 000 + 1 000 = 11 000 спроб
```

Створена утиліта `reaver` дозволяла звичайному ноутбуку перевірити всі 11 000 комбінацій за 4–10 годин ефірного опитування, після чого роутер слухняно віддавав справжній пароль від WPA2-мережі незалежно від його складності.

Виробники маршрутизаторів спробували захиститися латками: запровадили блокування WPS після 3–5 невдалих спроб на певний тайм-аут (Lockout). Здавалося, що атака сповільнилася до неприйнятних тижнів. Проте у жовтні 2014 року швейцарський криптограф Домінік Бонгар (Dominique Bongard) на конференції BruCON завдав WPS остаточного удару, презентувавши атаку **Pixie Dust**.

Бонгар дослідив прошивки популярних чипсетів Broadcom, Ralink, MediaTek і Realtek, на яких базувалися мільйони домашніх роутерів. Для захисту гешів PIN-коду у повідомленнях M3 (`E-Hash1`) та M5 (`E-Hash2`) роутер використовував криптографічні випадкові числа — одноразові значення (англ. *nonce*): `E-Nonce`, `PKE`, `PKR`, а також секретні змінні `E-S1` та `E-S2`.

```
E-Hash1 = HMAC-SHA256(AuthKey, E-S1 || PIN1 || PKE || PKR)
E-Hash2 = HMAC-SHA256(AuthKey, E-S2 || PIN2 || PKE || PKR)
```

Згідно з криптографічними стандартами, ці випадкові послідовності мали генеруватися апаратним джерелом ентропії або криптографічно стійким генератором псевдовипадкових чисел (CSPRNG). Натомість розробники прошивок для економії пам'яті й тактів процесора викликали звичайну функцію `rand()` із бібліотеки C.

У чипсетах Ralink значення псевдовипадкового генератора взагалі ініціалізувалося нулем (`seed = 0`) при кожному старті демона WPS, або залежало лише від системного часу з точністю до секунди (Unix timestamp). У чипсетах Broadcom та Realtek генератор використовував стан таймера процесора з дуже вузьким вікном невизначеності між генерацією `E-Nonce` та `E-S1`.

Отримавши від роутера всього **один** сеанс обміну (повідомлення M1–M3), атакуючий знав публічні `E-Nonce` та `PKR`. Оскільки генератор випадкових чисел був передбачуваним, атакуючий міг відновити внутрішній стан PRNG роутера, миттєво обчислити секретні `E-S1` та `E-S2`, а потім **в офлайні на власному комп'ютері** перебрати всі 10 000 варіантів `PIN1` і 1 000 варіантів `PIN2` за частки секунди.

Атака Pixie Dust не потребувала тисяч бездротових запитів і не викликала спрацювання захисних тайм-аутів роутера. Потрібен був лише один пакет M3 з ефіру, після чого ключ WPA2 вираховувався на процесорі смартфона чи ноутбука менш ніж за 100 мілісекунд.

Удар виявився фатальним для репутації технології. Виправлення вимагало повної заміни драйверів та архітектури генерації ключів на мільйонах уже проданих і необслуговуваних пристроїв. У результаті мобільні операційні системи (починаючи з Android 9 та всіх версій iOS) повністю вирізали клієнтську підтримку WPS з системного Wi-Fi стека, а виробники побутової електроніки й промислових IoT-модулів перейшли на захищені протоколи локального провізіонування через BLE та SoftAP з автентифікацією Curve25519.
