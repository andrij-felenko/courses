Нова ревізія телеметричного шлюзу лежить на лабораторному столі й поводиться непередбачувано: приблизно через сорок секунд після старту пристрій хаотично перезавантажується або намертво заклинює шину опитування сенсорів. На платі розпаяно сорок сім мікросхем і пасивних модулів, у репозиторії лежить триста свіжих комітів від чотирьох інженерів, а в коді працює десяток асинхронних задач під керуванням операційної системи реального часу. Спроба вгадати винуватця інтуїтивно — замінити підозрілий конденсатор, підкрутити пару таймаутів у драйвері SPI, змінити пріоритет переривання — спалює робочі дні без жодного поступу, бо простір можливих помилок зростає комбінаторно.

Коли система складається з десятків взаємопов'язаних вузлів, будь-яка одинична відмова маскується під лавину вторинних симптомів. Просадка живлення на п'ятдесят мілівольт викликає збій тактування інтерфейсу SPI; збій інтерфейсу повертає сміттєві дані в буфер драйвера; сміттєві дані переповнюють чергу повідомлень RTOS; переповнена черга призводить до спрацювання сторожового таймера. Інженер, який дивиться лише на кінцевий звіт посмертного дампу пам'яті або на завислий дисплей, бачить наслідок четвертого порядку й намагається лікувати симптом замість першопричини.

Єдиний інженерний порятунок від комбінаторного вибуху — **метод звуження**, або **половинний поділ** (бісекція, дихотомія). Це дисциплінована стратегія локалізації дефектів, яка кожним вимірюванням, схемотехнічним розривом або програмною модифікацією відсікає рівно половину простору підозр. Замість лінійного перебору тисячі компонентів і рядків коду бісекція гарантовано знаходить першопричину збою всього за десять послідовних кроків.

## Математична основа бісекції: чому логарифм перемагає хаос

Пошук несправності в інженерній системі — це процес послідовного усунення невизначеності. Якщо на платі або в прошивці є N потенційних джерел дефекту (вузлів схеми, мікросхем, функцій або ревізій у системі контролю версій), початковий обсяг невизначеності описується ентропією Шеннона H(X).

Коли всі вузли мають однакову апріорну ймовірність виходу з ладу, початкова невизначеність дорівнює log₂(N) бітів. Кожен діагностичний тест, який ділить простір підозрюваних елементів на дві рівні частини й відповідає «дефект у першій половині» або «дефект у другій половині», приносить рівно 1.00 біт нової інформації:

```text
H_початкова = log2(1000) ≈ 9.966 бітів         [початкова невизначеність для 1000 точок]
I_кроку     = - (0.5 * log2(0.5) + 0.5 * log2(0.5))
            = 1.000 біт                        [максимальний інформаційний виграш за 1 тест]
Кількість   = ⌈log2(1000)⌉ = 10 кроків         [гарантована кількість перевірок]
```

![Дерево дихотомічного пошуку: зменшення простору підозр з 1000 компонентів до одного дефекту за 10 кроків половинного поділу](/root/course/embedded/zvuzhennia/img/bisection-tree.svg)
*Дерево половинного поділу: кожен крок відкидає 50% підозрюваного простору й генерує рівно один біт інформації. Лінійний перебір у найгіршому разі потребує тисячі перевірок, тоді як бісекція досягає одиночного дефекту рівно за десять кроків.*

Якщо інженер вибірково перевіряє випадковий підозрілий компонент (один із тисячі), поділ відбувається у співвідношенні 1 до 999. Інформаційний виграш такого тесту становить мізерні 0.011 біта: якщо компонент виявився справним, простір підозр зменшився лише на 0.1%, і 99.9% невизначеності лишилися незмінними. Лінійний перебір вимагає в середньому п'ятисот перевірок, що перетворює налагодження складної плати на нескінченну рутину.

Логарифмічна основа половинного поділу дає фундаментальну перевагу: подвоєння складності системи (наприклад, перехід від 500 рядків коду до 1000 або подвоєння кількості чипів на платі) додає рівно **один** додатковий крок вимірювання. При лінійному переборі подвоєння складності означає подвоєння часу пошуку.

### Асиметрія ціни та ймовірностей

У реальному залізі симетричний поділ 50/50 стикається з двома фізичними обмеженнями:
1. **Різна апріорна надійність:** танталовий або електролітичний конденсатор у колі вторинного живлення або симетричний драйвер двигуна відмовляють у десятки разів частіше, ніж пасивний прецизійний резистор 0402. Якщо ймовірність відмови силового ключа становить 70%, а решти компонентів разом — 30%, перший діагностичний тест зобов'язаний ізолювати саме цей силовий ключ. Це зменшує ентропію системи набагато швидше, ніж геометричний поділ кількості деталей навпіл.
2. **Різна вартість тесту:** підключити щуп осцилографа до контрольної точки на платі займає 10 секунд, а демонтувати багатовивідну мікросхему в корпусі BGA чи QFN феном — 30 хвилин із серйозним ризиком термічного пошкодження сусідніх компонентів і відриву контактних майданчиків.

Коли витрати на проведення тестів різняться, оптимальна стратегія полягає в максимізації питомої інформаційної віддачі: вибирається той розріз схеми, який дає найбільшу кількість бітів інформації на витрачену секунду часу (ΔH / C). Спочатку виконуються всі дешеві неруйнівні перевірки з високим показником інформаційної віддачі (вимірювання напруг, аналіз форми сигналів, опитування регістрів), навіть якщо вони відсікають простір у пропорції 80/20, і лише після цього застосовуються дорогі операції паяння чи рефакторингу. Повне математичне виведення ентропійного розрізу та оптимального балансу вартості наведено в [математичній вставці про ентропію та вартість пошуку](root:embedded/zvuzhennia/math-entropy-search.md).

## Половинний поділ у схемотехніці: розрив ланцюгів та ізоляція каскадів

Головна перешкода під час пошуку апаратного дефекту — монолітність електричних кіл. Якщо шина живлення 3.3 В або цифрова шина I2C коротить на землю (GND), низький опір фіксується мультиметром на кожному виводі живлення всіх сорока мікросхем плати. Спроба навмання здувати мікросхеми феном руйнує текстоліт і вносить нові дефекти паяння.

Проєктування під діагностику (*Design for Testability*) вимагає закладати в топологію друкованої плати апаратні точки половинного розриву ще на етапі трасування:
- **Нульові резистори (Zero-Ohm Jumpers / R0):** резистори типорозміру 0603/0805, що стоять у розривах ліній живлення окремих функціональних доменів. Вони дозволяють зняти живлення з периферійного каскаду простим дотиком паяльника без різання міді.
- **Паяльні містки (Solder Bridges / SB):** контактні майданчики на платі, з'єднані краплею припою або тонкою мідною перемичкою, яку можна розімкнути опліткою для збору припою за кілька секунд.
- **Фільтрувальні дроселі (Ferrite Beads):** індуктивні елементи живлення аналогових каскадів, зняття яких повністю знеструмлює вузол без пошкодження доріжок.
- **Тестові майданчики (Test Pads):** відкриті контактні точки для щупів осцилографа та логічного аналізатора, розташовані до і після ключових буферів та комутаторів.

![Апаратний поділ шини живлення та інтерфейсів за допомогою нульових резисторів і паяльних перемичок](/root/course/embedded/zvuzhennia/img/hw-isolation-bus.svg)
*Схема апаратної бісекції: нульовий резистор R_ZERO та паяльний місток JP_I2C ділять плату на дві автономні половини. Розрив центральної перемички миттєво доводить, у якій саме групі компонентів виникло коротке замикання або блокування шини.*

### Локалізація короткого замикання на шині живлення

Коли на лінії 3.3 В виявлено коротке замикання, розмикання центрального нульового резистора R_ZERO ділить плату на дві ізольовані зони: Групу A з мікроконтролером та сенсорами й Групу B з радіомодулем і пам'яттю. Якщо коротке замикання лишилося на боці Групи B, мікроконтролер у Групі A стає повністю працездатним і виключається з підозри за одну дію.

Якщо розірвати лінію перемичкою неможливо (наприклад, внутрішній суцільний шар полігону живлення в багатошаровій платі), застосовують спеціалізовані вимірювальні методи половинного поділу:
1. **Подача обмеженого струму від лабораторного джерела:** лабораторний блок живлення переводять у режим стабілізації струму (Constant Current, CC), встановлюють обмеження струму 1.0–1.5 А та напругу 0.8–1.0 В. Напруга вибирається суворо нижче порогу відмикання p-n переходів кремнієвих кристалів (0.6–0.7 В на діод), щоб струм ішов суворо через фізичне замикання, а не живив мікросхеми через захисні структури.
2. **Тепловізійний поділ:** пробитий керамічний конденсатор або мікросхема з внутрішнім пробоєм перетворює енергію струму на тепло за законом Джоуля–Ленца (P = I² · R_кз). Тепловізор або спиртовий індикатор (крапля ізопропілового спирту на платі випаровується найшвидше над дефектним місцем) локалізує нагрів до 40–60 °C за лічені секунди.
3. **Чотирипровідний мілівольтметр (метод Кельвіна):** вимірювання мікровольтового спаду напруги вздовж мідного полігону живлення. Струм тече від джерела живлення безпосередньо до точки короткого замикання. Оскільки мідна доріжка має питомий опір близько 0.5 мОм на сантиметр (для стандартної фольги 35 мкм шириною 1 мм), струм 1 А створює спад напруги приблизно 0.5 мВ на кожен сантиметр довжини. Переміщення щупа високочутливого мілівольтметра вздовж лінії чітко вказує напрямок руху струму: точка з найнижчим потенціалом напруги відповідає фізичному місцю замикання.

### Пастка паразитного живлення (Phantom Powering)

При апаратному знеструмленні частини плати інженери часто потрапляють у небезпечну пастку: лінію живлення VCC відключено (розривом нульового резистора), але сигнальні лінії цифрових інтерфейсів (I2C SDA/SCL, SPI MOSI/CS, UART TX) залишаються під'єднаними до працюючого мікроконтролера.

Майже кожна інтегральна мікросхема містить внутрішні захисні діоди від статичної електрики (ESD Clamping Diodes), увімкнені між кожним сигнальним входом і внутрішньою шиною VCC чипа. Коли на сигнальний вхід приходить високий логічний рівень 3.3 В від працюючого мікроконтролера, струм протікає через верхній захисний діод прямо у знеструмлену шину живлення відключеного модуля. В результаті:
- Знеструмлена мікросхема частково «оживає» на паразитній напрузі 2.6–2.8 В (3.3 В мінус спад 0.6 В на діоді), переходячи в непередбачуваний хаотичний стан (*Brownout state*).
- Внутрішні захисні діоди перегріваються й деградують, оскільки вони не розраховані на постійний струм живлення всього чипа.
- Сигнальна лінія просідає по напрузі, створюючи хибне враження, що мікроконтролер несправний або закорочений.

Правило апаратного поділу вимагає: **ізолювати вузол слід разом із сигнальними лініями**. Якщо розривається лінія живлення VCC, виводи підтяжки шин даних або буфери комутації повинні бути переведені в стан високого імпедансу (High-Z) або фізично від'єднані.

### Ізоляція аналогових кіл та петель зворотного зв'язку

Аналогові каскади підсилювачів та імпульсні перетворювачі напруги містять петлі зворотного зв'язку (*Feedback Loops*). Якщо вихідний каскад замикається на вхід через дільник напруги, розривати коло навмання категорично заборонено.

Якщо розімкнути лінію зворотного зв'язку в імпульсному понижувальному перетворювачі (*Buck Converter*), контролер сприйме нульову напругу на вході Feedback як аварійну просадку й відкриє силовий MOSFET на 100% шпаруватості. Це призведе до миттєвого викиду максимальної вхідної напруги на вихід і вигорання всієї підключеної низьковольтної периферії.

Бісекція аналогового каскаду виконується за принципом **підміни сигналу** (*Half-Circuit Injection*):
1. Сигнальний вхід каскаду від'єднується від попереднього блоку (наприклад, вихід сенсора від входу операційного підсилювача).
2. На вхід подається фіксований калібрований сигнал від зовнішнього лабораторного генератора або джерела напруги.
3. Якщо вихід підсилювача формує правильний відгук — аналоговий каскад і його петля корекції повністю справні; дефект локалізовано в першій половині тракту (у сенсорі чи первинному фільтрі).

### Локалізація температурних збоїв (Freeze Spray та термофен)

Окремий клас важких апаратних несправностей виникає лише в обмеженому діапазоні температур: генерація тактового кварцу зривається при нагріванні до +50 °C, або PLL застрягає в нестійкому стані при охолодженні нижче 0 °C.

Половинний поділ плати за температурою:
1. **Накриття половини плати теплоізолятором:** половина друкованої плати екранується шматком термостійкого силікону або картону.
2. **Точковий термовплив:** на відкриту половину спрямовується потік гарячого повітря термофена (+60 °C) або струмінь охолоджувального аерозолю (*Freeze Spray*, -50 °C).
3. **Локалізація зони:** якщо відмова виникає лише при нагріванні правої половини — винуватець локалізований у межах 50% площі плати. Повторне зональне розпилення на окремі чіпи знаходить термочутливий кристал або тріснутий SMD-конденсатор за 3–4 кроки.

## Програмна бісекція: локалізація регресій, RTOS-потоків та переривань

Програмні дефекти вбудованих систем часто маскуються під апаратні збої: система зависає через псування стеку, взаємне блокування м'ютексів або надмірну латентність обробника переривань. Половинний поділ застосовується на трьох рівнях прошивки: в історії репозиторію, в архітектурних шарах коду та між паралельними задачами RTOS.

![Покрокова бісекційна ізоляція архітектурних шарів прошивки та RTOS-потоків](/root/course/embedded/zvuzhennia/img/firmware-bisection-flow.svg)
*Бісекція прошивки: заміна апаратних драйверів на стабільні заглушки (Stubs) та покрокове відключення 50% задач RTOS дозволяє ізолювати програмну помилку пам'яті від апаратного дефекту.*

### Бісекція історії коду через git bisect

Коли реліз прошивки v2.0 працював стабільно, а у версії v2.3 з'явилося спонтанне падіння, ручний аналіз трьохсот комітів займає тижні. Команда `git bisect` автоматизує половинний поділ історії репозиторію:

```bash
# 1. Запуск процедури бісекції
git bisect start
git bisect bad                 # Поточна версія (v2.3) містить дефект
git bisect good v2.0            # Остання відома стабільна версія (v2.0)

# Git автоматично перемикає робоче дерево на середній коміт (крок 1 із 8)
# Компілюємо, прошиваємо плату, перевіряємо працездатність:
git bisect good                # Якщо дефекту немає (помилку внесено пізніше)
# або
git bisect bad                 # Якщо система падає (помилка вже є тут)

# Автоматизація через скрипт автоматичного тестування:
git bisect run ./scripts/automated_hil_test.sh
```

Для повної автоматизації тестування скрипт `automated_hil_test.sh` повинен повертати чіткі коди завершення:
- `0` — коміт справний (*good*).
- `1` (або будь-яке число 1–124, 126–255) — у коміті виявлено збій (*bad*).
- `125` — коміт неможливо протестувати (наприклад, через помилку синтаксису чи незавершену зміну заголовка); Git автоматично виконає `git bisect skip` і вибере сусідній коміт.

За 8–9 ітерацій `git bisect` безпомилково вказує на єдиний коміт, який зламав систему, заощаджуючи десятки годин ручної роботи.

### Ізоляція задач RTOS та бінарне маскування переривань

Коли багатозадачна система на базі FreeRTOS або Zephyr спонтанно зависає, йде в HardFault або перезапускається сторожовим таймером, підозра падає на спільне використання пам'яті, гонки станів (*Race Conditions*) або взаємне блокування (*Deadlock*).

Половинний поділ задач RTOS (*Task Exclusion Bisection*):
1. **Призупинення половини потоків:** у функції ініціалізації вимикається створення або викликається `vTaskSuspend()` для половини непринципових задач (наприклад, задачі мережевого логування, анімації дисплея та фонової телеметрії).
2. **Оцінка поведінки:** якщо система продовжує зависати — винуватець у запущеній половині (керування двигунами або сенсорний опитувач). Якщо збій зник — дефект спричинено однією з відключених задач (або взаємодією між ними).
3. **Поділ підозрілої групи:** повторення процедури для відключеної групи локалізує дефектну задачу за 3–4 цикли перевірки.

Бісекція переривань у контролері NVIC:
Глобальне вимкнення переривань (`__disable_irq()`) дає надто грубий результат: система перестає працювати взагалі. Бісекційне маскування полягає у вибірковому відключенні половини векторів переривань через регістри маскування NVIC (`NVIC_DisableIRQ(EXTI0_IRQn)`, `NVIC_DisableIRQ(TIM3_IRQn)`).

Якщо після вимкнення таймерних переривань система стабілізується, підозра звужується до таймерного обробника:
- Чи не затягує ISR виконання довгими обчисленнями, блокуючи інші потоки?
- Чи скидається апаратний прапорець переривання в регістрі статусу периферійного модуля (наприклад, `TIMx->SR &= ~TIM_SR_UIF`)? Якщо прапорець не скинуто, процесор після виходу з обробника миттєво входить у нього знову, намертво блокуючи виконання фонового коду.

### Ізоляція пам'яті через апаратний захист MPU

Коли дефект викликаний «диким» покажчиком (*Wild Pointer*), який записує сміття у випадкову адресу пам'яті, падіння стається набагато пізніше за сам запис — у момент, коли інша задача намагається прочитати зіпсовану структуру.

Половинний поділ пам'яті через блок захисту пам'яті (Memory Protection Unit, MPU):
1. Простір оперативної пам'яті ділиться MPU на два регіони з різними правами доступу (наприклад, Регіон 1: `Read-Only` для статичних структур драйверів, Регіон 2: `Read-Write` для динамічних буферів).
2. Якщо задача виконує некоректний запис у захищений Регіон 1, процесор миттєво генерує виняток `MemManage Fault`.
3. Апаратний регістр `MMFAR` (*MemManage Fault Address Register*) фіксує точну фізичну адресу, куди відбулася спроба несанкціонованого запису, а лічильник команд `PC` у стековому кадрі вказує на точний рядок коду винуватця. Невизначеність усувається за одне спрацювання захисту.

## Матриця діагностичного виключення гіпотез: залізо проти коду

Найбільш енерговитратний конфлікт під час налагодження вбудованих пристроїв — розмежування апаратних і програмних симптомів. Програмісти стверджують, що просідає живлення або шумить шина SPI; схемотехніки наполягають, що в прошивці переповнюється буфер або застряє таймаут.

Матриця діагностичного виключення розриває це замкнене коло: кожен симптом ділиться на два ортогональні тести, один із яких перевіряє суто фізичні параметри сигналу, а другий — логічну цілісність програмного стану.

![Матриця перехресного діагностичного виключення гіпотез між апаратною та програмною частинами](/root/course/embedded/zvuzhennia/img/diagnostic-matrix.svg)
*Матриця діагностичного виключення: перевірка фізичних рівнів і стаб-ізоляція коду дозволяють однозначно розчепити апаратні та програмні першопричини відмови.*

### Практична таблиця розчеплення симптомів

| Симптом відмови | Апаратний тест (HW Probe) | Програмний тест (SW Probe) | Критерій розмежування (Бісекційний висновок) |
| :--- | :--- | :--- | :--- |
| **Шина I2C зависає наглухо** | Вимірювання напруги на лініях SDA/SCL осцилографом; розрив перемички ділить шину навпіл | Генерація 9 імпульсів SCL у режимі GPIO Open-Drain (*Bus Recovery*) | Якщо лінія 0 В без чипів — коротке замикання на платі; якщо відновилася після 9 тактів — зависання логіки веденого чипа |
| **HardFault раз на 2 години** | Моніторинг лінії VCC осцилографом у режимі тригера на спад (*Pulse Width / Undershoot*) | Увімкнення MPU (захист нульової сторінки) та перевірка сторожової мітки стеку | Якщо в момент збою напруга падає нижче порогу BOD — просадка живлення; якщо регістр CFSR вказує `UNALIGNED`/`PRECISERR` — гонка покажчиків |
| **Биті байти в кадрах SPI** | Аналіз форми сигналу SCK/MISO на осцилографі (перевірка дзвону, завалу фронтів) | Заміна живого сенсора на масив фіксованих даних у пам'яті (*Mock Injection*) | Якщо на осцилограмі є дзвін або затягнутий rise-time — брак узгодження лінії; якщо зі стабом помилка лишилася — гонка індексів буфера DMA |

### Чотири правила діагностичної дисципліни

1. **Фіксація базового стану (Baseline):** перед будь-якою зміною схеми або коду записується точний стан: версія коміту, напруга живлення, струм споживання та точний симптом помилки.
2. **Один крок — одна зміна (One variable at a time):** категорично заборонено одночасно підпаювати конденсатор і правити код ініціалізації. Якщо змінити дві речі разом, неможливо визначити, яка з них вплинула на результат.
3. **Незмінність робочого інструменту:** щуп осцилографа, лабораторне джерело живлення та з'єднувальні дроти мають власну ємність та індуктивність. Додавання щупа 10 пФ на кварцовий резонатор або довгих дротів живлення може тимчасово замаскувати або навпаки спровокувати збій (класичний ефект спостерігача — *Heisenbug*).
4. **Документування виключеної половини:** кожен завершений тест фіксує висновок у вигляді відкинутої зони простору підозр. Відкинута половина вважається перевіреною й не переглядається без нових виміряних фактів.

## Програмний кондуктор бісекційної самодіагностики на C та C++

Для автоматизації половинного поділу в пристрій вбудовують автономний діагностичний кондуктор (*Built-in Diagnostic Conductor*). Він виконує покрокове сходження від базових апаратних регістрів до високорівневих інтерфейсів, зупиняючись на першому зламаному модулі.

Нижче наведено модульну реалізацію діагностичного кондуктора мовою C з ідіоматичною об'єктно-орієнтованою реалізацією на сучасному C++ у перемикачі вкладок. Повна версія кондуктора з процедурами відновлення ліній I2C та аварійною телеметрією розібрана в [проєкті діагностичного тестового кондуктора](root:embedded/zvuzhennia/proj-bisection-conductor.md).

```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

/* Результати виконання діагностичних ступенів */
typedef enum {
    DIAG_STATUS_PASS = 0,
    DIAG_STATUS_FAIL_SILICON,
    DIAG_STATUS_FAIL_BUS,
    DIAG_STATUS_FAIL_TIMEOUT
} diag_status_t;

/* Опис окремого бісекційного кроку */
typedef struct {
    const char *step_name;
    diag_status_t (*test_fn)(void);
} diag_step_t;

/* Рівень 0: Перевірка ALU та сторожової мітки стеку */
static diag_status_t test_cpu_alu(void) {
    volatile uint32_t val = 0xAA55AA55;
    if ((val ^ 0xFFFFFFFF) != 0x55AA55AA) {
        return DIAG_STATUS_FAIL_SILICON;
    }
    return DIAG_STATUS_PASS;
}

/* Рівень 1: Перевірка фізичних ліній шини до запуску периферії */
static diag_status_t test_bus_lines_physical(void) {
    /* Читання рівнів GPIO ліній SDA/SCL. Імітація: лінії підтягнуті до 3.3 В */
    volatile bool sda_high = true;
    volatile bool scl_high = true;

    if (!sda_high || !scl_high) {
        return DIAG_STATUS_FAIL_BUS; /* Лінія затиснута в 0: КЗ або завислий чип */
    }
    return DIAG_STATUS_PASS;
}

/* Рівень 2: Опитування сенсора з жорстким апаратним таймаутом */
static diag_status_t test_sensor_ping(void) {
    uint32_t timeout = 5000;
    volatile uint8_t dev_id = 0x00;

    while (timeout > 0) {
        timeout--;
        dev_id = 0x68; /* Емуляція успішної відповіді сенсора */
        if (dev_id == 0x68) {
            return DIAG_STATUS_PASS;
        }
    }
    return DIAG_STATUS_FAIL_TIMEOUT;
}

/* Таблиця послідовності сходів довіри */
static const diag_step_t CONDUCTOR_STEPS[] = {
    { "CPU ALU & Core",    test_cpu_alu },
    { "Bus Physical Pins", test_bus_lines_physical },
    { "Sensor ID Ping",    test_sensor_ping }
};

/* Головний виконавець бісекційної діагностики */
int bisection_run_suite(void) {
    const size_t count = sizeof(CONDUCTOR_STEPS) / sizeof(CONDUCTOR_STEPS[0]);

    for (size_t i = 0; i < count; ++i) {
        diag_status_t res = CONDUCTOR_STEPS[i].test_fn();
        if (res != DIAG_STATUS_PASS) {
            return (int)(i + 1); /* Повертає номер першого зламаного рівня */
        }
    }
    return 0; /* Усі ізольовані підсистеми справні */
}
```
```cpp
#include <cstdint>
#include <cstddef>
#include <span>
#include <string_view>
#include <array>

namespace diag {

enum class Status : uint8_t {
    Pass = 0,
    FailSilicon,
    FailBus,
    FailTimeout
};

struct Step {
    std::string_view name;
    Status (*test)();
};

class Conductor {
public:
    static Status testCpuAlu() noexcept {
        constexpr uint32_t pattern = 0xAA55AA55UL;
        volatile uint32_t val = pattern;
        if ((val ^ 0xFFFFFFFFUL) != 0x55AA55AAUL) {
            return Status::FailSilicon;
        }
        return Status::Pass;
    }

    static Status testBusPhysical() noexcept {
        volatile bool sda_high = true;
        volatile bool scl_high = true;

        if (!sda_high || !scl_high) {
            return Status::FailBus;
        }
        return Status::Pass;
    }

    static Status testSensorPing() noexcept {
        uint32_t timeout = 5000;
        volatile uint8_t dev_id = 0x00;

        while (timeout > 0) {
            --timeout;
            dev_id = 0x68;
            if (dev_id == 0x68) {
                return Status::Pass;
            }
        }
        return Status::FailTimeout;
    }

    static size_t run(std::span<const Step> steps) noexcept {
        for (size_t idx = 0; idx < steps.size(); ++idx) {
            if (steps[idx].test() != Status::Pass) {
                return idx + 1; // Номер кроку, який локалізував дефект
            }
        }
        return 0; // Всі підсистеми успішно пройшли самодіагностику
    }
};

constexpr std::array<Step, 3> Steps{{
    { "CPU ALU & Core",    &Conductor::testCpuAlu },
    { "Bus Physical Pins", &Conductor::testBusPhysical },
    { "Sensor ID Ping",    &Conductor::testSensorPing }
}};

} // namespace diag

extern "C" int bisection_run_suite_cpp() {
    return static_cast<int>(diag::Conductor::run(diag::Steps));
}
```

## Підсумок: дисципліна звуження як спосіб мислення

Половинний поділ — це не просто окремий прийом діагностики, а базовий закон збереження інженерного ресурсу. У складній системі, де апаратна частина переплетена з прошивкою, інтуїція без математичного алгоритму гарантовано заходить у глухий кут.

Успішна локалізація будь-якої складної відмови тримається на трьох непорушних опорах:
1. **Топологічна готовність плати:** нульові резистори, тестові перемички та паяльні містки дозволяють розривати монолітні шини на автономні блоки без пошкодження доріжок.
2. **Логарифмічна швидкість бісекції:** кожна перевірка зменшує простір підозр удвічі, зводячи тисячу потенційних дефектів до одного точного вузла за десять кроків.
3. **Дисципліна виключення:** змінювати строго одну змінну за крок, спиратися на виміряні числа й відкидати перевірену половину простору безповоротно.
