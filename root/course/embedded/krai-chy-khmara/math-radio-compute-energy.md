# 🧮 Енергетичний баланс: обчислення на кремнії MCU проти передачі в радіоефір

Ця вставка містить строгий фізичний та математичний розрахунок витрат енергії на виконання обчислювальних інструкцій процесорним ядром мікроконтролера у порівнянні з витратами радіотракту на передачу даних в ефір. Без цього кількісного балансу неможливо спроєктувати автономний вузол Інтернету речей (IoT), здатний пропрацювати кілька років від одного гальванічного елемента живлення.

---

## 1. Фізична модель споживання процесорного ядра

Енергія, яку споживає цифровий мікроконтролер на базі комплементарної структури метал-оксид-напівпровідник (КМОН / CMOS) під час виконання коду, складається з двох компонентів: динамічного перемикання ємностей затворів транзисторів і статичного струму витоку.

Динамічна енергія одного тактового циклу ядра залежить від напруги живлення `V_dd` та еквівалентної комутованої ємності кристала `C_eff`:

```
E_cycle = C_eff · V_dd²
```

Повна енергія `E_compute`, необхідна для виконання алгоритму обсягом у `N_cycles` тактових циклів процесора при робочій частоті `f_cpu` та активному струмі споживання `I_active`:

```
E_compute
= P_active · t_exec               [потужність на час виконання]
= (V_dd · I_active) · (N_cycles ÷ f_cpu)
= (V_dd · I_active ÷ f_cpu) · N_cycles
= E_per_cycle · N_cycles         [де E_per_cycle — енергія одного такту]
```

### Розрахунок для мікроконтролера ARM Cortex-M4

Розглянемо типовий енергоефективний мікроконтролер загального призначення (наприклад, серії STM32L4 або nRF52840 на ядрі ARM Cortex-M4 з плаваючою комою FPU):
- Напруга живлення ядра: `V_dd = 3.3 В`;
- Струм споживання в активному режимі: `I_active = 8.4 мА` (0.0084 А) при частоті `f_cpu = 80 МГц` (80 · 10⁶ Гц);
- Питоме споживання ядра: `105 мкА / МГц`.

Енергія одного тактового циклу:

```
E_per_cycle
= 3.3 В · 0.0084 А ÷ (80 · 10⁶ Гц)
= 0.02772 Вт ÷ (80 · 10⁶ Гц)
= 3.465 · 10⁻¹⁰ Дж
= 346.5 пДж                     [пікоджоулів на такт]
```

Більшість базових арифметичних та логічних інструкцій ядра Cortex-M4 (додавання, віднімання, побітові зсуви, множення з накопиченням `MLA`) виконуються за 1 такт завдяки конвеєрній архітектурі.

### Енергія локального математичного аналізу

Обчислимо енергію, необхідну для виконання комплексного статистичного аналізу та фільтрації пакета вибірок датчика (1024 значення):

1. **Потоковий фільтр Велфорда (Welford)**: обчислення біжучого середнього та дисперсії для 1024 точок потребує близько 18 інструкцій на вибірку (включно із завантаженням з пам'яті):
```
N_cycles_welford = 1024 · 18 = 18 432 такти
E_welford = 18 432 · 346.5 пДж ≈ 6.39 · 10⁻⁶ Дж = 6.39 мкДж
```

2. **Швидке перетворення Фур'є (Radix-4 RFFT на 1024 комплексні точки)** з використанням оптимізованої бібліотеки CMSIS-DSP:
```
N_cycles_fft ≈ 32 000 тактів
E_fft = 32 000 · 346.5 пДж ≈ 1.11 · 10⁻⁵ Дж = 11.1 мкДж
```

## 2. Фізична модель споживання радіотракту

Енергія передачі радіопакета `E_radio` визначається напругою живлення трансивера `V_dd`, струмом споживання підсилювача потужності (PA) `I_tx`, часом перебування в ефірі (Time-on-Air, `t_toa`), а також накладними витратами на стабілізацію кварцового генератора, PLL-синтезатора частоти та преамбулу кадру:

```
E_radio = V_dd · I_tx · t_toa + E_startup
```

Розглянемо витрати енергії для різних радіотехнологій при передачі фіксованого корисного навантаження (1 кБ = 1024 байти сирих даних датчика).

### Варіант А: Bluetooth Low Energy (BLE 5.0, 2 Мбіт/с)
- Вихідна потужність передавача: `0 dBm` (1 мВт);
- Струм передачі: `I_tx = 5.0 мА` при `V_dd = 3.3 В`;
- Корисна швидкість каналу з урахуванням службових заголовків L2CAP / ATT: `~1.4 Мбіт/с` (175 кБ/с);
- Час передачі 1024 байтів: `t_toa = 1024 ÷ 175 000 ≈ 5.85 мс`;
- Енергія запуску PLL та калібрування: `E_startup ≈ 2.5 мкДж`.

```
E_ble
= 3.3 В · 0.005 А · 0.00585 с + 2.5 мкДж
= 9.65 · 10⁻⁵ Дж + 2.5 мкДж
≈ 99.0 мкДж                     [мікроджоулів на 1 кБ]
```

### Варіант Б: LoRaWAN (868 МГц, SF7, ширина смуги 125 кГц)
- Вихідна потужність передавача: `+14 dBm` (25 мВт);
- Струм передачі чіпа SX1262: `I_tx = 45 мА` при `V_dd = 3.3 В`;
- Максимальний розмір корисного навантаження одного пакета на SF7: `222 байти`;
- Для передачі 1024 байтів потрібно розбити дані на 5 пакетів;
- Час передачі одного пакета (Time-on-Air на SF7): `~62 мс`;
- Сумарний час випромінювання: `t_toa = 5 · 62 мс = 310 мс`.

```
E_lora
= 3.3 В · 0.045 А · 0.310 с
= 0.0460 Дж
= 46 035 мкДж ≈ 46.0 мДж        [міліджоулів на 1 кБ]
```

### Варіант В: Стільниковий зв'язок LTE Cat-M1 / NB-IoT
- Вихідна потужність передавача: `+23 dBm` (200 мВт);
- Середній струм під час передачі пакета: `I_tx = 220 мА` при `V_dd = 3.6 В`;
- Час синхронізації з базовою станцією, процедура випадкового доступу (RACH), підтвердження RRC та передача 1 кБ: `t_active ≈ 1.8 с`.

```
E_cellular
= 3.6 В · 0.220 А · 1.8 с
= 1.425 Дж                      [джоулів на сесію передачі]
= 1 425 000 мкДж
```

## 3. Коефіцієнт обчислювальної переваги

Співвідношення енергії передачі сирих даних до енергії їх попередньої обробки на кристалі визначає **коефіцієнт обчислювальної переваги** (`K_gain`):

```
K_gain = E_radio(Raw_Data) ÷ (E_compute(Filter) + E_radio(Summary))
```

Порівняємо два підходи для 1024 вибірок (1 кБ):
1. **Підхід 1 (Наївний)**: Передача всіх 1024 байтів сирого сигналу в хмару через LoRaWAN.
2. **Підхід 2 (Край)**: Обчислення спектра (FFT), визначення переважаючої гармоніки й відправка лише 8 байтів зведення (частота, амплітуда, прапорець аномалії).

```
Енергія наївної передачі:
E_naive = E_lora(1024 Б) = 46 035 мкДж

Енергія бортової обробки та відправки зведення:
E_edge
= E_fft(1024) + E_lora(8 Б)
= 11.1 мкДж + (3.3 В · 0.045 А · 0.041 с)
= 11.1 мкДж + 6088.5 мкДж
≈ 6099.6 мкДж

Коефіцієнт виграшу:
K_gain
= 46 035 ÷ 6099.6
≈ 7.55                          [у 7.5 разів менше енергії]
```

Якщо ж алгоритм на місці з'ясовує, що сигнал лежить у межах норми і передавати дані взагалі не потрібно (режим винятків / Exception-based telemetry), виграш стає абсолютним:

```
K_gain_silent
= 46 035 мкДж ÷ 11.1 мкДж
≈ 4147 разів
```

Локальне обчислення потребує в **4147 разів менше енергії**, ніж одна радіопередача.

## 4. Розрахунок терміну служби автономного джерела живлення

Розглянемо автономний промисловий датчик вібрації, який опитує акселерометр раз на 10 секунд (8640 вимірювань на добу) і живиться від літієвої батареї типу Li-SOCl2 (типорозмір AA, `3.6 В`, номінальна ємність `2400 мА·год` = `8.64 Вт·год` = `31 104 Дж`).

Врахуємо деградацію ємності через саморозряд (1% на рік) та коефіцієнт корисної дії перетворювача живлення `η = 0.85`. Корисна доступна енергія батареї:

```
E_battery = 31 104 Дж · 0.85 = 26 438 Дж
```

Струм вузла у глибокому сні (Deep Sleep): `I_sleep = 2.5 мкА`, що за добу дає фонові витрати:
```
E_sleep_day = 3.6 В · (2.5 · 10⁻⁶ А) · 86 400 с ≈ 0.777 Дж / добу
```

### Сценарій 1: Передача кожного вимірювання (LoRaWAN)
Кожні 10 секунд передається пакет. За добу виконується 8640 передач:
```
E_radio_day = 8640 · 0.046 Дж = 397.44 Дж / добу
E_total_day = 397.44 + 0.777 ≈ 398.22 Дж / добу
```

Термін служби батареї:
```
T_life_1 = 26 438 Дж ÷ 398.22 Дж/добу ≈ 66.4 доби (менше 2.5 місяців)
```

### Сценарій 2: Бортова фільтрація та відправка аномалій
MCU прокидається кожні 10 секунд, знімає 1024 точки через DMA, рахує статистику (11.1 мкДж). Передача в ефір відбувається лише у разі виявлення аномалії або як контрольний пульс (Heartbeat) 1 раз на 4 години (6 разів на добу):

```
E_compute_day = 8640 · (11.1 · 10⁻⁶ Дж) ≈ 0.096 Дж / добу
E_radio_day = 6 · 0.006 Дж ≈ 0.036 Дж / добу
E_total_day = 0.096 + 0.036 + 0.777 ≈ 0.909 Дж / добу
```

Термін служби батареї:
```
T_life_2
= 26 438 Дж ÷ 0.909 Дж/добу
≈ 29 084 доби
≈ 79.6 років                   [обмежено лише хімічним саморозрядом батареї: 10–15 років]
```

Цей розрахунок доводить, що перенесення первинної математичної обробки на мікроконтролер перетворює пристрій із нежиттєздатної системи з постійною заміною елементів живлення на надійний промисловий датчик із десятирічним терміном автономної експлуатації.
