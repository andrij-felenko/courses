# ⚙️ Наскрізний конвеєр обробки сигналу на мікроконтролері

<preknowlist>
- [Мікроконтролер: що всередині](root:hw-arch/mcu-blocks) — внутрішня структура MCU, апаратні таймери та переривання.
- [Логічні рівні як діапазони](root:hw-digital/logic-levels-as-ranges) — фізична природа дискретних та аналогових сигналів напруги.
</preknowlist>

У вбудованих системах автоматичного керування більшість задач зводяться до безперервного циклу: зчитати аналоговий сигнал із сенсора, відфільтрувати високочастотні завади, обчислити помилку регулювання та сформувати керівний імпульс ШІМ для силового ключа навантаження. Коли такий конвеєр реалізують на бюджетних мікроконтролерах (наприклад, на базі ядер ARM Cortex-M0+ або RISC-V), інженер стикається з двома жорсткими обмеженнями: **відсутністю апаратного модуля обчислень із плаваючою комою (FPU)** та **забороною на динамічне виділення пам'яті** (`malloc`/`free` або `new`/`delete`).

Програмна емуляція чисел `float` через бібліотечні підпрограми роздуває розмір бінарного коду у Flash на 4–8 КБ і сповільнює кожну операцію додавання чи множення з одного такту процесора до 50–120 тактів. У свою чергу, динамічне виділення пам'яті в циклі реального часу за лічені години призводить до фрагментації оперативної пам'яті (SRAM) і раптового аварійного зупинення контролера.

Розглянемо повну реалізацію надійного конвеєра обробки сигналу на основі цілочисельної арифметики з фіксованою комою та статично розміщеними структурами даних.

### Архітектура конвеєра: від відліку до ШІМ

Конвеєр складається з чотирьох послідовних стадій, які викликаються з детермінованим періодом квантування часу `dt` (наприклад, рівно кожні 10 мс за перериванням апаратного таймера):

```
+---------------+     +-----------------------+     +--------------------+     +-------------------+
|  1. Зчитування|     | 2. Цифрова фільтрація |     | 3. ПІД-регулятор   |     | 4. Генерація ШІМ  |
|  АЦП (12 біт) | --> |    (EMA-фільтр)       | --> |    (Anti-Windup)   | --> |    (Таймер 16 біт)|
|  0..4095      |     |    V_filt = EMA(V_raw)|     |    U = P + I + D   |     |    CCR = 0..65535 |
+---------------+     +-----------------------+     +--------------------+     +-------------------+
```

#### 1. Зчитування та квантування аналогового входу
На вході мікроконтролера працює 12-бітний АЦП послідовного наближення (SAR ADC). При стабільній опорній напрузі `V_ref = 3300 мВ` сирий числовий код у діапазоні `0..4095` переводиться у фізичні мілівольти за формулою:
```
V_mv = (raw_adc · 3300) / 4095
```
Щоб запобігти 32-бітному цілочисельному переповненню під час множення, використовується проміжне приведення до типу `uint32_t`: максимальне значення чисельника становить `4095 · 3300 = 13 513 500`, що гарантовано вміщується у 32-бітний регістр (максимум `4 294 967 295`).

#### 2. Цифрова фільтрація завад (EMA-фільтр)
Реальний аналоговий сигнал завжди містить високочастотний шум від перемикання сусідніх цифрових шин і силових ключів. Класичний фільтр ковзного середнього (Moving Average) вимагає виділення кільцевого буфера в пам'яті для зберігання останніх `N` відліків і обчислення суми.

Набагато ефективнішим для мікроконтролера є **експоненційний фільтр ковзного середнього** (EMA, англ. *Exponential Moving Average*), який являє собою рекурсивний цифровий фільтр низьких частот першого порядку. Він зберігає лише одну змінну стану й описується різницевим рівнянням:
```
y[k] = y[k-1] + α · (x[k] - y[k-1])
```
де `x[k]` — новий вхідний відлік, `y[k-1]` — попереднє згладжене значення, а `α` — коефіцієнт згладжування (`0 < α ≤ 1`).

Якщо обрати коефіцієнт `α` у вигляді ступеня двійки `α = 1 / 2^k` (наприклад, при `k = 3` маємо `α = 1/8 = 0.125`), операція множення замінюється надшвидким апаратним зсувом бітів вправо:
```
y[k] = y[k-1] + ((x[k] - y[k-1]) >> 3)
```
Така операція виконується процесором ARM Cortex-M або RISC-V за один машинний такт без використання апаратного дільника.

#### 3. Дискретний ПІД-регулятор із фіксованою комою
Керівний сигнал формується класичним законом пропорційно-інтегрально-диференціального регулювання:
```
u(t) = Kp · e(t) + Ki · ∫ e(τ) dτ + Kd · (de(t) / dt)
```
де `e(t) = Setpoint - Measured` — помилка регулювання (відхилення уставки від виміряного значення).

У цілочисельній реалізації коефіцієнти `Kp`, `Ki`, `Kd` масштабуються у формат із фіксованою комою `Q8.8` (множаться на `256 = 2^8` на етапі конфігурації). Після множення на помилку результат ділиться на 256 за допомогою зсуву вправо `>> 8`:

```
P_term = (Kp_q8 · error) >> 8
I_term = (Ki_q8 · integral_accum) >> 8
D_term = (Kd_q8 · (error - prev_error)) >> 8
```

##### Захист від інтегрального насичення (Anti-Windup)
Якщо виконавчий механізм фізично досяг свого максимуму (наприклад, нагрівач увімкнено на 100% потужності або клапан повністю відкрито), а температура все ще нижча за уставку, помилка `error` залишається позитивною. Без захисту інтегральна сума `integral_accum` продовжуватиме необмежено зростати, накопичуючи гігантське значення.

Коли температура нарешті досягне уставки, регулятор не зможе вчасно вимкнути нагрівач, оскільки розрядка величезного інтегратора вимагатиме тривалого часу від'ємної помилки. Це явище називають **інтегральним насиченням** (*Integral Windup*). Воно призводить до катастрофічного перерегулювання.

Для запобігання насиченню інтегратора в коді застосовується динамічне обмеження (*clamping*): якщо інтегральна складова перевищує максимальну вихідну межу `out_max`, інтегратор примусово фіксується на граничному рівні й припиняє накопичення.

#### 4. Масштабування виходу під апаратний таймер ШІМ
Сумарне керуюче значення `output = P_term + I_term + D_term` обмежується діапазоном `0..out_max` і записується в регістр порівняння захоплення апаратного таймера (наприклад, 16-бітний регістр `TIMx->CCR1` з діапазоном значень `0..65535`).

### Повна програмна реалізація: C та ідіоматичний C++

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define ADC_MAX_CODE       4095U
#define ADC_VREF_MV        3300U
#define PWM_MAX_DUTY       65535U

/* Структура стану ПІД-регулятора */
typedef struct {
    int32_t kp;              /* Пропорційний коефіцієнт у форматі Q8 (Kp * 256) */
    int32_t ki;              /* Інтегральний коефіцієнт у форматі Q8 (Ki * 256) */
    int32_t kd;              /* Диференційний коефіцієнт у форматі Q8 (Kd * 256) */
    int32_t integral_accum;  /* Накопичена інтегральна сума */
    int32_t prev_error;      /* Помилка регулювання на попередньому кроці */
    int32_t out_min;         /* Нижня межа керуючого сигналу */
    int32_t out_max;         /* Верхня межа керуючого сигналу */
} PidController;

/* Структура стану експоненційного фільтра EMA */
typedef struct {
    int32_t filtered_val;    /* Поточне згладжене значення */
    uint8_t shift_k;         /* Коефіцієнт згладжування: alpha = 1 / (2^shift_k) */
    bool initialized;        /* Прапорець первинної ініціалізації */
} EmaFilter;

/* Ініціалізація фільтра */
void ema_filter_init(EmaFilter *filter, uint8_t shift_k) {
    filter->filtered_val = 0;
    filter->shift_k = shift_k;
    filter->initialized = false;
}

/* Оновлення стану фільтра новим відліком */
int32_t ema_filter_update(EmaFilter *filter, int32_t new_val) {
    if (!filter->initialized) {
        filter->filtered_val = new_val;
        filter->initialized = true;
        return new_val;
    }
    filter->filtered_val += (new_val - filter->filtered_val) >> filter->shift_k;
    return filter->filtered_val;
}

/* Ініціалізація ПІД-регулятора */
void pid_init(PidController *pid, int32_t kp_q8, int32_t ki_q8, int32_t kd_q8,
              int32_t out_min, int32_t out_max) {
    pid->kp = kp_q8;
    pid->ki = ki_q8;
    pid->kd = kd_q8;
    pid->integral_accum = 0;
    pid->prev_error = 0;
    pid->out_min = out_min;
    pid->out_max = out_max;
}

/* Розрахунок чергового кроку ПІД-регулювання */
int32_t pid_update(PidController *pid, int32_t setpoint, int32_t measured) {
    int32_t error = setpoint - measured;

    /* Пропорційна складова: (Kp * error) / 256 */
    int32_t p_term = (pid->kp * error) >> 8;

    /* Інтегральна складова з захистом від переповнення (Anti-Windup) */
    pid->integral_accum += error;
    int32_t i_term = (pid->ki * pid->integral_accum) >> 8;

    /* Динамічне обмеження інтегратора */
    if (i_term > pid->out_max) {
        i_term = pid->out_max;
        pid->integral_accum = (pid->out_max << 8) / (pid->ki > 0 ? pid->ki : 1);
    } else if (i_term < pid->out_min) {
        i_term = pid->out_min;
        pid->integral_accum = (pid->out_min << 8) / (pid->ki > 0 ? pid->ki : 1);
    }

    /* Диференційна складова */
    int32_t derivative = error - pid->prev_error;
    int32_t d_term = (pid->kd * derivative) >> 8;
    pid->prev_error = error;

    /* Сумарний керуючий сигнал */
    int32_t output = p_term + i_term + d_term;
    if (output > pid->out_max) output = pid->out_max;
    if (output < pid->out_min) output = pid->out_min;

    return output;
}

/* Повний наскрізний конвеєр обробки сигналу */
uint16_t process_signal_pipeline(uint16_t raw_adc, uint16_t target_mv,
                                 EmaFilter *filter, PidController *pid) {
    /* 1. Масштабування відліку АЦП у мілівольти */
    uint32_t mv_unfiltered = ((uint32_t)raw_adc * ADC_VREF_MV) / ADC_MAX_CODE;

    /* 2. Цифрова фільтрація високочастотних завад */
    int32_t mv_filtered = ema_filter_update(filter, (int32_t)mv_unfiltered);

    /* 3. Обчислення керуючого сигналу ПІД-регулятором */
    int32_t control_out = pid_update(pid, (int32_t)target_mv, mv_filtered);

    /* 4. Приведення до діапазону регістра порівняння ШІМ (0..65535) */
    if (control_out < 0) control_out = 0;
    if (control_out > (int32_t)PWM_MAX_DUTY) control_out = PWM_MAX_DUTY;

    return (uint16_t)control_out;
}
```
```cpp
#include <cstdint>
#include <algorithm>

constexpr uint32_t kAdcMaxCode = 4095;
constexpr uint32_t kAdcVrefMv  = 3300;
constexpr uint16_t kPwmMaxDuty = 65535;

/* Клас експоненційного фільтра без динамічної пам'яті */
template <uint8_t ShiftK = 3>
class EmaFilter {
public:
    constexpr EmaFilter() noexcept = default;

    int32_t update(int32_t new_val) noexcept {
        if (!initialized_) {
            filtered_val_ = new_val;
            initialized_ = true;
            return new_val;
        }
        filtered_val_ += (new_val - filtered_val_) >> ShiftK;
        return filtered_val_;
    }

    [[nodiscard]] int32_t value() const noexcept { return filtered_val_; }
    void reset() noexcept { initialized_ = false; filtered_val_ = 0; }

private:
    int32_t filtered_val_{0};
    bool initialized_{false};
};

/* Клас дискретного цілочисельного ПІД-регулятора */
class PidController {
public:
    constexpr PidController(int32_t kp_q8, int32_t ki_q8, int32_t kd_q8,
                            int32_t out_min, int32_t out_max) noexcept
        : kp_(kp_q8), ki_(ki_q8), kd_(kd_q8),
          out_min_(out_min), out_max_(out_max) {}

    int32_t update(int32_t setpoint, int32_t measured) noexcept {
        const int32_t error = setpoint - measured;

        const int32_t p_term = (kp_ * error) >> 8;

        integral_accum_ += error;
        int32_t i_term = (ki_ * integral_accum_) >> 8;

        /* Захист від інтегрального насичення (Anti-Windup) */
        if (i_term > out_max_) {
            i_term = out_max_;
            integral_accum_ = (out_max_ << 8) / (ki_ > 0 ? ki_ : 1);
        } else if (i_term < out_min_) {
            i_term = out_min_;
            integral_accum_ = (out_min_ << 8) / (ki_ > 0 ? ki_ : 1);
        }

        const int32_t derivative = error - prev_error_;
        const int32_t d_term = (kd_ * derivative) >> 8;
        prev_error_ = error;

        const int32_t output = p_term + i_term + d_term;
        return std::clamp(output, out_min_, out_max_);
    }

    void reset() noexcept {
        integral_accum_ = 0;
        prev_error_ = 0;
    }

private:
    int32_t kp_;
    int32_t ki_;
    int32_t kd_;
    int32_t integral_accum_{0};
    int32_t prev_error_{0};
    int32_t out_min_;
    int32_t out_max_;
};

/* Наскрізний клас обробного конвеєра */
class SignalPipeline {
public:
    explicit SignalPipeline(PidController pid) noexcept : pid_(pid) {}

    uint16_t process(uint16_t raw_adc, uint16_t target_mv) noexcept {
        /* 1. Масштабування відліку АЦП */
        const uint32_t mv_raw = (static_cast<uint32_t>(raw_adc) * kAdcVrefMv) / kAdcMaxCode;

        /* 2. Цифрова фільтрація */
        const int32_t mv_filt = filter_.update(static_cast<int32_t>(mv_raw));

        /* 3. Розрахунок ПІД-регулятора */
        const int32_t control = pid_.update(static_cast<int32_t>(target_mv), mv_filt);

        /* 4. Формування сигналу керування ШІМ */
        const int32_t clamped_duty = std::clamp<int32_t>(control, 0, kPwmMaxDuty);
        return static_cast<uint16_t>(clamped_duty);
    }

private:
    EmaFilter<3> filter_{};
    PidController pid_;
};
```

### Апаратна інтеграція та таймерні переривання

Щоб конвеєр працював стабільно, функція `process_signal_pipeline` повинна викликатися строго за розкладом. У типовій архітектурі на базі мікроконтролера STM32 або ESP32 організація виконання будується так:

1. **Апаратний таймер (TIM2 / SysTick):** налаштовується на генерування періодичного апаратного переривання з частотою 100 Гц (`T = 10 мс`).
2. **Апаратний тригер АЦП:** таймер автоматично запускає перетворення АЦП без участі процесора (через зв'язку *Timer Trigger Out -> ADC Start*).
3. **Прямий доступ до пам'яті (DMA):** контролер DMA автоматично копіює результат вимірювання АЦП у змінну `raw_adc` в оперативній пам'яті й генерує переривання завершення передачі `DMA_TC_IRQHandler`.
4. **Обробник переривання (ISR):** викликає конвеєр обробки сигналу і безпосередньо оновлює регістр порівняння таймера ШІМ `TIM3->CCR1`.

Увесь цикл виконання конвеєра на ядрі Cortex-M0+ із тактовою частотою 48 МГц займає **менше 1.5 мікросекунди**, залишаючи 99.98% процесорного часу для виконання інших фонових завдань і протоколів зв'язку.

### Чотири класичні пастки реалізації на залізі

1. **Цілочисельне переповнення при накопиченні інтегратора.**
   Якщо коефіцієнт `Ki` малий, а помилка регулювання тримається довго, 32-бітний акумулятор `integral_accum` може переповнитися і змінити знак (з максимального позитивного `+2 147 483 647` на від'ємний `-2 147 483 648`). Це призведе до раптового вимкнення нагрівача замість максимального нагріву. Перевірка меж інтегратора на кожному кроці є обов'язковою.
2. **Джиттер періоду квантування часу (Sampling Jitter).**
   Формули дискретного інтегрування та диференціювання спираються на припущення, що крок часу `dt` є **строго незмінною константою**. Якщо викликати функцію конвеєра з головного нескінченного циклу `while(1)` із випадковими затримками від інших функцій, математичний зміст коефіцієнтів `Ki` та `Kd` руйнується, а контур регулювання починає непередбачувано коливатися й самозбуджуватися. Виклик конвеєра має здійснюватися виключно за апаратним перериванням таймера.
3. **Шум молодших розрядів АЦП (ADC Noise) і диференційна складова.**
   Реальний 12-бітний АЦП мікроконтролера через наведення від цифрових шин рідко дає ідеальні 12 біт точності (типове ефективне число розрядів ENOB становить 10–10.5 біт). Без попереднього цифрового фільтра низьких частот (EMA) диференційна складова `Kd · (error - prev_error)` багаторазово підсилюватиме високочастотне тремтіння молодших бітів, викликаючи безперервне тремтіння шпаруватості ШІМ і надлишковий нагрів силового транзистора.
4. **Імпеданс джерела сигналу та час заряду конденсатора вибірки (Sample & Hold).**
   Вхідний каскад АЦП мікроконтролера містить ключ вибірки та внутрішній конденсатор вибірки ємністю `C_sample ≈ 5–10 пФ`. Якщо внутрішній опір джерела сигналу `R_source` (наприклад, високомного резистивного дільника напруги) перевищує 10 кОм, конденсатор вибірки не встигає повністю зарядитися за короткий час вибірки АЦП `T_sample` (зазвичай 1.5–15 тактових циклів АЦП). Це призводить до заниження виміряної напруги на 5–20%. Для усунення помилки необхідно або зменшувати опір дільника, або програмно збільшувати кількість тактів вибірки в регістрі конфігурації АЦП `ADC_SMPR`, або встановлювати зовнішній буферний операційний підсилювач.
