Електронний замок із модулем зв'язку Bluetooth LE або захищений телеметричний контролер подає живлення на ядро Cortex-M4. Під час первинної ініціалізації стека безпеки прошивка викликає стандартну функцію генерації сесійного ключа або підпису повідомлення. Розробник, звиклий до настільних операційних систем, пише виклик `srand(SysTick->VAL)` або бере лінійний конгруентний генератор `rand()` зі стандартної бібліотеки C. За три мілісекунди пристрій генерує одноразовий вектор ініціалізації (nonce) для протоколу шифрування AES-GCM або випадковий скаляр `k` для створення цифрового підпису ECDSA. Для стороннього спостерігача згенеровані шістнадцяткові байти виглядають як хаотичний шум. Проте логічний аналізатор або радіоприймач нападника фіксує два сусідні сеанси зв'язку, за кілька мілісекунд обчислює точний внутрішній стан генератора і повністю відновлює довготривалий закритий ключ пристрою.

Мікроконтролер за своєю архітектурою є детермінованим автоматом. Якщо на тактовий вхід подано стабільну частоту, а живлення перебуває в межах норми, кожен такт процесора, кожна операція регістрового файлу та кожен перехід програми виконуються абсолютно повторювано. З точки зору виконання коду в кремнієвому кристалі немає жодної вбудованої невизначеності: `rand()` видає ту саму псевдовипадкову числову траєкторію за однакового початкового значення (англ. *seed*). Звідси постає фундаментальна інженерна проблема вбудованої безпеки: де детермінованій машині взяти непередбачувану фізичну ентропію (лат. *entropia*, від грец. *ἐν* — в і *троπή* — перетворення, міра невизначеності), як очистити її від систематичних спотворень і перетворити на криптографічно стійкий потік випадкових чисел.

![Конвеєр криптографічної випадковості](/root/course/embedded/zvidky-na-mikrokontroleri-braty-vypadkovist/img/entropy-pipeline.svg)
*Повний конвеєр генерації випадковості: фізичні джерела шуму проходять безперервні онлайн-тести працездатності, декореляцію та криптографічне кондиціювання в пулі ентропії для періодичного посіву CSPRNG-генератора.*

### Криптографічна ціна передбачуваної випадковості в IoT-пристроях

Алгоритмічні генератори загального призначення, такі як лінійні конгруентні генератори (англ. *Linear Congruential Generator*, LCG) чи регістри зсуву з лінійним зворотним зв'язком (англ. *Linear Feedback Shift Register*, LFSR), проектувалися виключно для статистичної рівномірності в задачах чисельного моделювання Монте-Карло. Вони не мають жодної криптографічної стійкості.

У класичному лінійному конгруентному генераторі наступний стан `X[n+1]` обчислюється за формулою:

```
X[n+1] = (a · X[n] + c) mod m
```

Якщо нападник перехоплює значення `X[n]`, йому не потрібно перебирати простір станів. Наступне число `X[n+1]` вираховується однією операцією множення і додавання. Навіть якщо розробник приховує молодші біти (англ. *truncated LCG*) і видає назовні лише старші розряди `Y[n] = X[n] >> 16`, задача відновлення повного стану `X[n]` розв'язується через редукцію базисів ґраток (алгоритм Ленстри — Ленстри — Ловаса, LLL) менш ніж за 10 мілісекунд на звичайному комп'ютері.

#### Катастрофа повтору nonce в цифрових підписах ECDSA

Найвразливішим криптографічним примітивом до якості випадковості є алгоритм цифрового підпису на еліптичних кривих (ECDSA) та алгоритм Шнорра. При створенні підпису під хешем повідомлення `h` за допомогою закритого ключа `d` обчислюється пара чисел `(r, s)`:

```
R = k · G                    [множення базової точки кривої G на скаляр k]
r = R_x mod n                [x-координата точки R за порядком підгрупи n]
s = k⁻¹ · (h + r · d) mod n  [формування другої компоненти підпису]
```

Значення `k` називається одноразовим секретним числом (англ. *ephemeral nonce*). Воно зобов'язане бути абсолютно випадковим, невідомим нападнику і ніколи не повторюватися.

Якщо прошивка мікроконтролера через слабкий генератор випадкових чисел або фіксований стан після перезавантаження використає **одне й те саме значення `k`** для підпису двох різних повідомлень із хешами `h₁` та `h₂`, підписи матимуть однакове значення координати `r`, але різні значення `s₁` та `s₂`:

```
s₁ = k⁻¹ · (h₁ + r · d) mod n
s₂ = k⁻¹ · (h₂ + r · d) mod n
```

Нападник віднімає два рівняння:

```
s₁ - s₂
= k⁻¹ · (h₁ + r · d) - k⁻¹ · (h₂ + r · d)  [розкриття різниці]
= k⁻¹ · (h₁ - h₂) mod n                   [скорочення доданка r·d]
```

Оскільки `s₁`, `s₂`, `h₁` та `h₂` відкриті, нападник миттєво обчислює секретний скаляр `k`:

```
k = (h₁ - h₂) · (s₁ - s₂)⁻¹ mod n         [знаходження одноразового nonce]
```

Маючи `k`, нападник підставляє його в перше рівняння і витягує довготривалий закритий ключ пристрою `d`:

```
s₁ · k = h₁ + r · d mod n                 [множення на k]
r · d = s₁ · k - h₁ mod n                 [перенесення хешу]
d = (s₁ · k - h₁) · r⁻¹ mod n             [повне відновлення закритого ключа]
```

Для зламу не потрібні квантові комп'ютери чи перебір `2²⁵⁶` варіантів: дві операції ділення за модулем порядку кривої повністю дискредитують кореневий сертифікат пристрою. Саме ця помилка призвела до історичного зламу системи захисту ігрової консолі Sony PlayStation 3 у 2010 році, де в алгоритмі ECDSA використовувалося константне значення `k`.

Більше того, теорема Боне — Венкатесана (англ. *Hidden Number Problem*) доводить: якщо nonce `k` не є строго рівномірним і має зміщення (наприклад, старші 4 біти з 256 завжди дорівнюють нулю через перекіс генератора), прихованого закритого ключа `d` достатньо для повного відновлення за кілька десятків підписів за допомогою методів теорії ґраток.

#### Руйнування автентичності в AEAD-шифруванні (AES-GCM)

У режимах автентифікованого шифрування з приєднаними даними (англ. *Authenticated Encryption with Associated Data*, AEAD), зокрема в AES-GCM та ChaCha20-Poly1305, повторне використання пари «ключ + nonce» (`K, N`) знищує не лише конфіденційність, а й цілісність.

Шифрування виконується в режимі лічильника CTR:

```
C₁ = P₁ ⊕ AES_K(N || 1)
C₂ = P₂ ⊕ AES_K(N || 1)
```

Якщо нападник перехоплює два шифротексти `C₁` та `C₂`, створені на одному nonce `N`, операція XOR між ними знімає гамування:

```
C₁ ⊕ C₂
= (P₁ ⊕ AES_K(N || 1)) ⊕ (P₂ ⊕ AES_K(N || 1))  [підстановка визначень]
= P₁ ⊕ P₂                                      [повне взаємне знищення маски]
```

Нападник бачить чистий XOR відкритих текстів. У протоколі AES-GCM обчислення імітовставки GHASH побудоване над полем Галуа `GF(2¹²⁸)`. Повторення nonce дозволяє скласти систему лінійних рівнянь над полем і відновити внутрішній хеш-ключ `H = AES_K(0¹²⁸)`. Маючи ключ `H`, нападник отримує можливість самостійно підробляти будь-які імітовставки для довільних підроблених пакетів без знання основного ключа `K`.

> 🔧 **Навіщо це.** У вбудованих пристроях будь-який протокол захищеного зв'язку — чи то TLS/DTLS для відправки телеметрії, WPA2/WPA3 для Wi-Fi, чи сесійні ключі оновлення прошивки OTA — повністю спирається на непередбачуваність nonce та сесійних ключів. Слабкий генератор зводить криптостійкість 256-бітного шифру до нуля.

### Апаратні джерела справжньої випадковості (TRNG) у кремнії

Єдиним способом отримати фундаментально непередбачувану послідовність чисел є пряме вимірювання стохастичних фізичних явищ на рівні атомів і носіїв заряду. Апаратний генератор справжніх випадкових чисел (англ. *True Random Number Generator*, TRNG) — це інтегрований у кристал мікроконтролера апаратний периферійний блок, що конвертує аналоговий мікроскопічний шум у бінарний потік.

У кремнієвих напівпровідникових структурах використовують три фундаментальні фізичні джерела шуму:

#### 1. Тепловий шум Джонсона — Найквіста

Тепловий шум (англ. *Johnson-Nyquist noise*) виникає внаслідок хаотичного броунівського руху вільних електронів у провідниках і напівпровідникових каналах за будь-якої температури вище абсолютного нуля (`T > 0 К`).

Спектральна густина напруги теплового шуму описується формулою Найквіста:

```
v_n = √(4 · k_B · T · R · Δf)
```

де:
- `k_B = 1.380649 × 10⁻²³ Дж/К` — стала Больцмана;
- `T` — абсолютна температура в Кельвінах;
- `R` — опір провідника або еквівалентний опір каналу транзистора в Омах;
- `Δf` — смуга пропускання вимірювального тракту в Герцах.

Для опору `R = 100 кОм` при кімнатній температурі `T = 300 К` у смузі частот `Δf = 1 МГц`:

```
v_n = √(4 · 1.380649·10⁻²³ · 300 · 100000 · 10⁶)
= √(1.65678 · 10⁻⁹)
≈ 40.7 · 10⁻⁶ В = 40.7 мкВ (RMS)  [середньоквадратична напруга шуму]
```

Ці 40 мікровольт є білим гаусовим шумом. Щоб перетворити його на логічні рівні, в апаратний TRNG інтегрують диференційний підсилювач із високим коефіцієнтом підсилення (`K_u ≈ 10⁴`), вихід якого подається на компаратор напруги.

#### 2. Дробовий та лавинний шум p-n переходу

Коли p-n перехід напівпровідникового діода зміщується у зворотному напрямку до напруги зворотної пробою (лавинний або стабілітронний пробій, англ. *avalanche breakdown*), носії заряду долають бар'єр за рахунок ударної іонізації та квантового тунелювання.

Окремі електрони, що влітають у зону сильного електричного поля, випадково ініціюють мікроскопічні струмові лавини. Оскільки момент виникнення кожної лавини квантово-механічно недетермінований, струм пробою складається з незліченної кількості випадкових пікосекундних імпульсів. Амплітуда лавинного шуму на порядок перевищує тепловий шум і досягає кількох мілівольтів, що робить його ідеальним джерелом для прецизійних апаратних TRNG.

#### 3. Фазовий джиттер кільцевих генераторів (Ring Oscillators)

У стандартних цифрових мікроконтролерах (наприклад, STM32, ESP32, nRF52) реалізувати прецизійний аналоговий підсилювач для теплового шуму буває занадто дорого за площею кристала та енергоспоживанням. Тому переважна більшість вбудованих апаратних TRNG використовує **кільцеві генератори на інверторах** (англ. *Ring Oscillator*, ROSC).

Кільцевий генератор являє собою ланцюжок із непарної кількості логічних інверторів (`N = 3, 5, 7…`), замкнений у кільце зі зворотним зв'язком.

![Апаратний TRNG: фазовий джиттер у кільцевому генераторі](/root/course/embedded/zvidky-na-mikrokontroleri-braty-vypadkovist/img/rosc-jitter.svg)
*Кільцевий генератор накопичує фазовий джиттер у кожному циклі інвертування через тепловий шум транзисторів. Семплювання сигналу D-тригером від незалежного тактового джерела захоплює справжню випадковість.*

Час перемикання одного інвертора `t_pd` визначається швидкістю перезаряду ємності затвора наступного транзистора струмом каналу. Цей струм модулюється тепловим шумом і флуктуаціями напруги живлення. В результаті тривалість кожного періоду коливань `T_k` відхиляється від ідеального середнього значення `T_0` на випадкову величину `Δt_k` (фазовий джиттер):

```
T_k = T_0 + Δt_k
```

Похибка фази є інтегралом випадкового шуму за часом. Після `k` періодів коливань загальне зміщення фази накопичується за законом випадкового блукання (англ. *random walk*):

```
σ_jitter(k) = σ_single · √k
```

де `σ_single` — середньоквадратичне відхилення джиттеру одного періоду.

Якщо на тактовий вхід D-тригера подати сигнал від стабільного джерела (наприклад, кварцового генератора HSE), а на інформаційний вхід D подати сигнал від швидкого кільцевого генератора ROSC, тригер фіксуватиме логічний стан 0 або 1 у випадкові моменти відносно фази ROSC. Коли невизначеність фази `σ_jitter(k)` перевищує період коливань ROSC (`T_ROSC`), результат кожного наступного вибіркового зчитування стає повністю непередбачуваним.

#### Захоплення метастабільності

Якщо фронт сигналу даних на вході D збігається з тактовим фронтом CLK у межах критичного інтервалу `t_setup + t_hold`, тригер входить у стан **метастабільності** (англ. *metastability*). У цей момент обидва внутрішні інвертори тригера перебувають в активній лінійній області підсилення.

Вихід із метастабільного стану в стабільний 0 або 1 відбувається за рахунок посилення мікроскопічного теплового шуму всередині транзисторів самого тригера. Час розпаду і кінцевий стан є фундаментально випадковими. Спеціалізовані апаратні схеми TRNG навмисно підлаштовують затримки за допомогою кіл фазового автопідстроювання (PLL), щоб утримувати систему на межі метастабільності та максимізувати вихід ентропії.

### Екстракція ентропії за відсутності виділеного TRNG

Що робити, якщо проект будується на бюджетному мікроконтролері без апаратного блоку TRNG (наприклад, класичні AVR ATmega328P, базові Cortex-M0 STM32F030 чи старі архітектури PIC)?

Спроба читати значення незадіяного («висячого в повітрі», англ. *floating*) аналогового виводу АЦП — найпоширеніша і найнебезпечніша ілюзія. Відкритий аналоговий пін працює як антена, що вловлює електромагнітні завади від мережі 50 Гц, імпульсних стабілізаторів живлення (DC-DC buck converter, зазвичай 1–2 МГц) та випромінювання сусідніх цифрових шин SPI/UART. Цей сигнал здається хаотичним лише людині; для нападника він є строго детермінованою періодичною синусоїдою або меандром, параметри якого легко реконструюються.

Проте за правильного інженерного підходу навіть на простому мікроконтролері можна вилучити справжню фізичну ентропію за допомогою трьох перевірених методів:

#### 1. Тепловий шум молодших розрядів АЦП (ADC LSB Noise)

Замість антени на відкритому вході, АЦП підключають до внутрішніх фізичних джерел шуму:
- Внутрішній датчик температури кристала;
- Джерело внутрішньої опорної напруги (англ. *Internal Voltage Reference*, `VREFINT` / Bandgap reference);
- Зовнішній високоомний резистивний дільник напруги (наприклад, 1 МОм), підключений до землі.

![Екстракція ентропії з дрейфу таймерів HSE та LSI](/root/course/embedded/zvidky-na-mikrokontroleri-braty-vypadkovist/img/dual-timer-jitter.svg)
*Фазовий дрейф між високостабільним кварцовим таймером HSE та релаксаційним RC-генератором LSI: старші розряди лічильника визначаються середньою частотою, а молодші біти містять чистий термодинамічний джиттер.*

Коли АЦП виконує вибірку аналогового сигналу, внутрішній конденсатор схеми вибірки та зберігання (англ. *Sample & Hold*) накопичує тепловий заряд із дисперсією напруги:

```
σ_v = √(k_B · T / C_sample)
```

Для типової ємності вибірки `C_sample = 5 пФ` при кімнатній температурі:

```
σ_v = √(1.380649·10⁻²³ · 300 / (5 · 10⁻¹²))
= √(8.28389 · 10⁻¹⁰)
≈ 28.8 · 10⁻⁶ В = 28.8 мкВ (RMS)  [тепловий шум комутатора kT/C]
```

Якщо 12-бітний АЦП працює з опорною напругою `V_ref = 3.3 В`, вага одного кванта (LSB, Least Significant Bit) становить:

```
V_LSB = 3.3 / 4096 ≈ 805.6 мкВ
```

Сам по собі тепловий шум конденсатора 28.8 мкВ менший за один квант. Проте шум вхідного аналогового буфера та опорного джерела становить від 200 до 400 мкВ. Це призводить до того, що під час багаторазового перетворення постійної напруги нульовий біт результату (а іноді й перший) хаотично перемикається між 0 та 1.

Старші 10–11 бітів містять фіксовану постійну напругу (нуль ентропії). Ентропію несе **виключно біт LSB**. Спроба використати всі 12 бітів напряму є фатальною помилкою, оскільки вони корельовані на 90%.

#### 2. Дрейф частоти та биття двох незалежних генераторів (Timer Jitter)

Будь-який сучасний мікроконтролер має принаймні два незалежні генератори тактових імпульсів:
1. **Високочастотний кварцовий генератор (HSE / PLL)**: тактує процесорне ядро та швидкі таймери (наприклад, 72–168 МГц). Кварц має високу добротність (`Q ≈ 10⁵`) і чудову температурну стабільність (похибка 10–20 ppm).
2. **Низькочастотний внутрішній RC-генератор (LSI або Watchdog RC)**: тактує сторожовий таймер та RTC (наприклад, номінально 32–40 кГц). RC-ланцюжок має низьку добротність (`Q < 10`), плаває від зміни температури на 2–5% і має значний рівень фазового шуму.

**Механізм захоплення:**
Швидкий 32-бітний апаратний таймер (наприклад, `TIM2` на STM32) налаштовується на безперервний інкремент від частоти ядра `f_fast = 168 МГц` (період лічби 5.95 нс).
Повільний RC-генератор `f_slow ≈ 32 кГц` підключається до каналу захоплення таймера (Input Capture) або генерує переривання.

За кожним фронтом повільного сигналу в регістр `TIM2->CCR1` фіксується поточне значення швидкого лічильника:

```
N_ticks = f_fast / f_slow
≈ 168000000 / 32000
= 5250 тактів              [середнє число тактів за один RC-період]
```

Оскільки фази двох генераторів не синхронізовані, а період RC-генератора тремтить через тепловий рух електронів, реальна кількість тактів у кожному вимірюванні коливається: `5248, 5253, 5249, 5251...`.

Різниця між двома послідовними захопленнями `ΔN = CCR[k] - CCR[k-1]` складається з детермінованої бази (5250) та випадкового джиттеру в молодших 1–2 бітах. Екстрагуючи молодший біт `ΔN & 0x01` на кожному періоді RC, отримують надійний потік фізичної ентропії зі швидкістю 32 000 біт/с.

#### 3. Джиттер інтервалів радіопакетів та мережевих подій

Якщо пристрій підключено до радіоканалу (Wi-Fi, Bluetooth LE, IEEE 802.15.4, LoRa) або шини CAN/Ethernet, час надходження асинхронних пакетів модулюється фізичним середовищем поширення радіохвиль, колізіями в ефірі та затримками віддаленого передавача.

Захоплення лічильника циклів ядра `DWT->CYCCNT` (на ядрах ARM Cortex-M3/M4/M7/M33) у момент виникнення переривання від радіомодуля забезпечує захоплення наносекундних флуктуацій часу прибуття кадру. Молодші байти значення лічильника додаються в накопичувальний пул ентропії.

### Кондиціювання та криптографічне відбілювання пулу ентропії

Сирий потік бітів із будь-якого фізичного джерела (чи то апаратний TRNG, АЦП чи дрейф таймерів) **ніколи не є ідеальним**. Він має дві фундаментальні вади:
1. **Зсув ймовірності (англ. *Bias*)**: ймовірність одиниці `P(1) ≠ 0.5`. Наприклад, через технологічну несиметричність CMOS-ключів `P(1) = 0.53`, а `P(0) = 0.47`.
2. **Автокореляція (англ. *Autocorrelation*)**: наступний біт статистично залежить від попереднього через паразитні ємності схеми вибірки, час відновлення аналогового компаратора або частотне затягування генераторів (англ. *injection locking*).

Використання сирого шуму безпосередньо для формування криптографічних ключів категорично заборонено стандартом NIST SP 800-90B. Сирі дані обов'язково проходять дві стадії обробки: статистичне відбілювання та криптографічне кондиціювання (англ. *whitening & conditioning*).

#### Алгоритм декореляції Джона фон Неймана

У 1951 році Джон фон Нейман запропонував простий елегантний алгоритм усунення статистичного перекосу 0/1 для незалежних вибірок.

![Алгоритм відбілювання Джона фон Неймана](/root/course/embedded/zvidky-na-mikrokontroleri-braty-vypadkovist/img/von-neumann-extractor.svg)
*Алгоритм фон Неймана розбиває сирий потік на бітові пари. Оскільки ймовірності появи пар 01 та 10 строго ідентичні, вихідний потік повністю позбавлений зміщення.*

Вхідний бітовий потік розбивається на пари сусідніх бітів `(b[2k], b[2k+1])`, які обробляються за правилом:

```
Пара 0 1 → видати біт 0
Пара 1 0 → видати біт 1
Пара 0 0 → відкинути (немає виходу)
Пара 1 1 → відкинути (немає виходу)
```

**Математичне доведення:**
Нехай ймовірність появи одиниці в сирому джерелі дорівнює `p`, а нуля `(1 - p)`. За умови незалежності бітів ймовірності появи пар становлять:

```
P(01) = (1 - p) · p
P(10) = p · (1 - p)
```

Оскільки множення дійсних чисел комутативне:

```
P(01)
= (1 - p) · p      [ймовірність пари 01]
= p · (1 - p)      [комутативність множення]
= P(10)            [ймовірність пари 10]
```

Ймовірності появи вихідного нуля та вихідної одиниці **строго рівні між собою**:

```
P(Вихід = 0)
= P(01) / (P(01) + P(10))
= P(01) / (2 · P(01))
= 0.5                      [ідеальний баланс нулів та одиниць]
```

Пропускна здатність алгоритму (ефективність екстракції `E`) залежить від початкового перекосу:

```
E = P(01) + P(10) = 2 · p · (1 - p)
```

За ідеального входу (`p = 0.5`) ефективність досягає максимуму: `E = 2 · 0.5 · 0.5 = 0.50` (викидається половина бітів). При перекосі `p = 0.7` ефективність падає до `E = 2 · 0.7 · 0.3 = 0.42`.

> [!NOTE]
> Алгоритм фон Неймана повністю ліквідує перекіс ймовірностей `P(1) ≠ P(0)`, проте він спирається на припущення про відсутність кореляції між сусідніми бітами. Якщо в джерелі присутня автокореляція (`P(b_k | b_{k-1}) ≠ P(b_k)`), фон Нейман не гарантує повної випадковості. Для захисту від автокореляції застосовують криптографічні хеш-функції.

#### Архітектура пулу ентропії (Entropy Accumulator)

Щоб надійно об'єднати ентропію з декількох різних джерел (дрейф таймерів, шум АЦП, час мережевих пакетів) і гарантувати неможливість маніпуляції з боку нападника, використовують **накопичувальний пул ентропії** (архітектура Fortuna або NIST SP 800-90A).

Пул являє собою фіксований буфер у пам'яті SRAM (наприклад, 64 байти). Додавання нової сирої вибірки `sample` виконується через криптографічну хеш-функцію:

```
Pool_State[k+1] = SHA-256(Pool_State[k] || Source_ID || Timestamp || Sample)
```

Завдяки лавиноподібному ефекту хеш-функції зміна навіть одного молодшого біта у вхідній вибірці призводить до повної псевдовипадкової перебудови всіх 256 бітів внутрішнього стану пулу. Навіть якщо нападник повністю контролює одне з джерел (наприклад, навмисно генерує мережеві пакети з фіксованим періодом), він не здатний зменшити ентропію пулу, отриману від інших фізичних джерел.

### Криптографічно стійкий генератор псевдовипадкових чисел (CSPRNG)

Фізичні джерела ентропії у вбудованих системах мають обмежену швидкість генерації — від кількох сотень біт до кількох кілобіт на секунду. Водночас криптографічним протоколам (наприклад, передача потокового відео по TLS або генерація великої кількості ключів) потрібна випадковість зі швидкістю десятки мегабайт на секунду.

Для розв'язання цієї проблеми використовують **криптографічно стійкий генератор псевдовипадкових чисел** (англ. *Cryptographically Secure Pseudo-Random Number Generator*, CSPRNG або DRBG — *Deterministic Random Bit Generator*).

CSPRNG — це детермінований алгоритм, який приймає на вхід короткий початковий блок справжньої ентропії (Seed, 256 або 384 біти) з накопичувального пулу і розгортає його в необмежену послідовність псевдовипадкових байтів, яка за поліноміальний час невідрізна від істинного білого шуму.

Головними промисловими стандартами CSPRNG є:
1. **ChaCha20-DRBG**: побудований на потоковому шифрі ChaCha20 (RFC 8439). Винятково швидкий на мікроконтролерах без апаратного прискорювача AES (потребує лише операцій додавання, циклічного зсуву та XOR — ARX);
2. **AES-CTR-DRBG**: побудований на блоковому шифрі AES-256 у режимі лічильника (NIST SP 800-90A). Ідеальний для чипів з апаратним AES (наприклад, STM32L4, ESP32, nRF52840).

#### Властивість стійкості до компрометації минулого (Backtracking Resistance)

Критична вимога до CSPRNG — **захист від компрометації минулого стану** (англ. *Forward Secrecy* або *Backtracking Resistance*). Якщо нападник у певний момент часу фізично захопить мікроконтролер, зчитає весь дамп пам'яті SRAM і дізнається поточний ключ генератора `K_current`, він **не повинен мати можливості відновити жодного байта випадковості, згенерованого до моменту зламу**.

Ця властивість досягається негайним оновленням ключа після кожного запиту випадкових даних:

```
1. Block_Out = ChaCha20_Block(Key, Nonce)
2. Stream = Truncate(Block_Out, Requested_Bytes)
3. Key_New = Truncate(ChaCha20_Block(Key, Nonce + 1), 32)  [генерація нового ключа]
4. Key = Key_New                                           [незворотне стирання старого ключа]
5. Nonce = Nonce + 2
```

Оскільки шифр ChaCha20 є односторонньою функцією, обчислити `Key_old` за відомим `Key_New` математично неможливо (складність `2²⁵⁶`).

### Статистичне тестування та валідація випадковості у прошивці

Відмова апаратного джерела ентропії (наприклад, обрив доріжки датчика, залипання виводу АЦП на шині живлення через коротке замикання, зрив генерації кварцу або температурне блокування) є катастрофічною аварією безпеки. Якщо TRNG вийде з ладу і почне видавати потік нулів, CSPRNG продовжуватиме працювати, але без оновлення ентропії, або генеруватиме передбачувані послідовності.

Стандарт **NIST SP 800-90B** вимагає обов'язкової інтеграції в прошивку **онлайн-моніторингу працездатності джерела ентропії** (англ. *Continuous Health Tests*), який працює безперервно під час функціонування пристрою.

#### 1. Тест кількості повторень (Repetition Count Test, RCT)

Тест RCT призначений для миттєвого виявлення катастрофічної відмови джерела (залипання сигналу на константному значенні).

Він відстежує, скільки разів поспіль повторюється одне й те саме значення вибірки. Якщо вибірка повторилася `C` разів, фіксується апаратна аварія (атака або деградація сенсора).

Поріг спрацьовування `C` розраховується на основі оцінки мінімальної ентропії джерела `H_min`:

```
C = 1 + ⌈ -log₂(α) / H_min ⌉
```

де `α` — допустима ймовірність хибного спрацьовування (зазвичай `α = 2⁻²⁰ ≈ 10⁻⁶` чи `2⁻⁴⁰`).

Якщо бінарне джерело має мінімальну ентропію `H_min = 0.8` біта на зразок, для `α = 2⁻²⁰`:

```
C = 1 + ⌈ 20 / 0.8 ⌉ = 1 + 25 = 26
```

Якщо 26 вибірок поспіль виявилися однаковими, джерело негайно відключається.

#### 2. Адаптивний тест пропорцій (Adaptive Proportion Test, APT)

Тест APT виявляє повільну деградацію ентропії або звуження смуги шуму.

У ковзному вікні розміром `W` вибірок (за стандартом `W = 512` або `1024`) фіксується значення першої вибірки `S_0`. Потім підраховується, скільки разів значення `S_0` зустрінеться в наступних `W - 1` вибірках. Якщо кількість збігів перевищує порогове значення `B`, тест сигналізує про деградацію генератора.

#### 3. Статистичний набір FIPS 140-2 для блоків у 20 000 бітів

Стандарт безпеки **FIPS 140-2 (§4.9.1)** регламентує перевірку якості випадкової послідовності на блоках довжиною рівно 20 000 бітів за чотирма статистичними критеріями:

1. **Тест монобітів (Monobit Frequency Test)**:
   Підраховується загальна кількість одиниць `N_1` у блоці 20 000 бітів.
   Умова успіху: `9654 < N_1 < 10346`.
2. **Тест серій (Runs Test)**:
   Серією називається безперервна послідовність однакових бітів (тільки нулі або тільки одиниці), обмежена протилежними бітами. Підраховується кількість серій довжиною 1, 2, 3, 4, 5 та 6+ бітів окремо для нулів та одиниць.
   Кількість серій кожної довжини зобов'язана потрапляти в суворо регламентований довірчий інтервал FIPS (наприклад, серій довжини 1 має бути від 2267 до 2733).
3. **Тест довгої серії (Long Run Test)**:
   У блоці 20 000 бітів **не повинно існувати жодної серії довжиною 34 біти або більше**. Поява 34 однакових бітів поспіль безумовно дискваліфікує послідовність.
4. **Покер-тест (Poker Test)**:
   Блок 20 000 бітів розбивається на 5000 4-бітних ніблів (значення від 0 до 15). Підраховується частота появи кожного з 16 можливих значень `f[i]`.
   Обчислюється статистика `χ²`:

```
X = (16 / 5000) · ∑(f[i]²) - 5000
```

Умова успіху FIPS 140-2: `1.03 < X < 57.4`.

#### Ентропія Шенона та мінімальна ентропія (Min-Entropy)

Для кількісної оцінки невизначеності випадкової величини `X` з ймовірностями значень `p₁, p₂, …, pₙ` використовують дві математичні метрики:

1. **Ентропія Шенона (інформаційна ентропія)**:

```
H(X) = - ∑ p_i · log₂(p_i)
```

Вона вимірює середню кількість інформації на символ.

2. **Мінімальна ентропія (Min-Entropy, `H_∞`)**:

```
H_∞(X) = - log₂( max(p_i) )
```

У криптографії використовують саме **мінімальну ентропію**, оскільки вона оцінює найгірший можливий випадок — ймовірність вгадування найбільш частого символу нападником. Якщо для 8-бітного АЦП одне зі значень випадає з ймовірністю `p_max = 0.25`, то `H_∞ = -log₂(0.25) = 2.0` біти ентропії на 8-бітний байт (а не 8 бітів). Відповідно, для отримання 256 бітів повноцінної ентропії необхідно накопичити не менше `256 / 2 = 128` таких байтів.

### Повна реалізація: збір ентропії, CSPRNG та онлайн-тести

Нижче наведено модульну вбудовану систему генерації випадковості. Вона містить:
1. **Збирач ентропії (Jitter & ADC Entropy Harvester)** з декорелятором фон Неймана;
2. **CSPRNG-генератор на основі ядра ChaCha20** із захистом від компрометації минулого (Backtracking Resistance);
3. **Онлайн-монітор працездатності (Health Monitor)** з тестами Repetition Count Test (RCT) та Monobit / Long Run за стандартом NIST SP 800-90B / FIPS 140-2.

/* ============================================================================
 * Вбудована криптографічна система випадковості (C99 / MCU Embedded)
 * Джерела: Timer Capture Jitter + ADC LSB + Von Neumann + ChaCha20-DRBG
 * ============================================================================ */

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <string.h>

#define CHACHA20_KEY_SIZE   32
#define CHACHA20_NONCE_SIZE 12
#define CHACHA20_BLOCK_SIZE 64
#define ENTROPY_POOL_SIZE   64

/* ── 1. Онлайн-тест працездатності ентропії (NIST SP 800-90B RCT) ─────────── */
typedef struct {
    uint8_t  last_sample;
    uint32_t repeat_count;
    uint32_t rct_cutoff;        /* Поріг відсікання однакових значень */
    uint32_t total_samples;
    uint32_t ones_count;        /* Лічильник монобітів */
    bool     health_fault;
} EntropyHealthMonitor;

static void health_monitor_init(EntropyHealthMonitor *hm, uint32_t cutoff) {
    hm->last_sample = 0xFF;
    hm->repeat_count = 0;
    hm->rct_cutoff = cutoff;    /* Зазвичай 16-32 для 8-бітних шумів */
    hm->total_samples = 0;
    hm->ones_count = 0;
    hm->health_fault = false;
}

static bool health_monitor_update(EntropyHealthMonitor *hm, uint8_t sample) {
    if (hm->health_fault) return false;

    /* Repetition Count Test (RCT) */
    if (sample == hm->last_sample) {
        hm->repeat_count++;
        if (hm->repeat_count >= hm->rct_cutoff) {
            hm->health_fault = true; /* Аварія: джерело шуму залипло! */
            return false;
        }
    } else {
        hm->last_sample = sample;
        hm->repeat_count = 1;
    }

    /* Моніторинг балансу бітів */
    for (int i = 0; i < 8; i++) {
        if ((sample >> i) & 1) hm->ones_count++;
    }
    hm->total_samples++;

    return true;
}

/* ── 2. Декорелятор Джона фон Неймана ─────────────────────────────────────── */
typedef struct {
    uint8_t bit_buffer;
    uint8_t bit_count;
    uint8_t out_byte;
    uint8_t out_bits_collected;
} VonNeumannExtractor;

static void vn_extractor_init(VonNeumannExtractor *vn) {
    vn->bit_buffer = 0;
    vn->bit_count = 0;
    vn->out_byte = 0;
    vn->out_bits_collected = 0;
}

/* Подає один сирий біт. Повертає true, якщо сформовано повноцінний вихідний байт */
static bool vn_extractor_feed_bit(VonNeumannExtractor *vn, uint8_t in_bit, uint8_t *out_byte) {
    in_bit &= 1;
    vn->bit_buffer = (vn->bit_buffer << 1) | in_bit;
    vn->bit_count++;

    if (vn->bit_count >= 2) {
        uint8_t pair = vn->bit_buffer & 0x03;
        vn->bit_count = 0;

        if (pair == 1) {        /* Пара 01 -> видати біт 0 */
            vn->out_byte = (vn->out_byte << 1);
            vn->out_bits_collected++;
        } else if (pair == 2) { /* Пара 10 -> видати біт 1 */
            vn->out_byte = (vn->out_byte << 1) | 1;
            vn->out_bits_collected++;
        }
        /* Пари 00 та 11 відкидаються */

        if (vn->out_bits_collected >= 8) {
            *out_byte = vn->out_byte;
            vn->out_byte = 0;
            vn->out_bits_collected = 0;
            return true;
        }
    }
    return false;
}

/* ── 3. Криптографічний генератор ChaCha20-DRBG ────────────────────────────── */
#define ROTL32(v, n) (((v) << (n)) | ((v) >> (32 - (n))))
#define CHACHA_QUARTERROUND(a, b, c, d) \
    a += b; d ^= a; d = ROTL32(d, 16); \
    c += d; b ^= c; b = ROTL32(b, 12); \
    a += b; d ^= a; d = ROTL32(d,  8); \
    c += d; b ^= c; b = ROTL32(b,  7);

typedef struct {
    uint32_t state[16];
    uint8_t  keystream[64];
    size_t   keystream_idx;
    uint32_t reseed_counter;
} ChaCha20_CSPRNG;

static void chacha20_block(const uint32_t in_state[16], uint8_t out[64]) {
    uint32_t x[16];
    memcpy(x, in_state, sizeof(x));

    /* 20 раундів ChaCha (10 подвійних раундів) */
    for (int i = 0; i < 10; i++) {
        /* Стовпчики */
        CHACHA_QUARTERROUND(x[0], x[4], x[ 8], x[12]);
        CHACHA_QUARTERROUND(x[1], x[5], x[ 9], x[13]);
        CHACHA_QUARTERROUND(x[2], x[6], x[10], x[14]);
        CHACHA_QUARTERROUND(x[3], x[7], x[11], x[15]);
        /* Діагоналі */
        CHACHA_QUARTERROUND(x[0], x[5], x[10], x[15]);
        CHACHA_QUARTERROUND(x[1], x[6], x[11], x[12]);
        CHACHA_QUARTERROUND(x[2], x[7], x[ 8], x[13]);
        CHACHA_QUARTERROUND(x[3], x[4], x[ 9], x[14]);
    }

    for (int i = 0; i < 16; i++) {
        uint32_t val = x[i] + in_state[i];
        out[i * 4 + 0] = (uint8_t)(val);
        out[i * 4 + 1] = (uint8_t)(val >> 8);
        out[i * 4 + 2] = (uint8_t)(val >> 16);
        out[i * 4 + 3] = (uint8_t)(val >> 24);
    }
}

static void csprng_seed(ChaCha20_CSPRNG *rng, const uint8_t seed[32]) {
    /* Константи ChaCha20 ("expand 32-byte k") */
    rng->state[0] = 0x61707865;
    rng->state[1] = 0x3320646e;
    rng->state[2] = 0x79622d32;
    rng->state[3] = 0x6b206574;

    /* 256-бітний ключ ентропії */
    for (int i = 0; i < 8; i++) {
        rng->state[4 + i] = (uint32_t)seed[i * 4 + 0]       |
                           ((uint32_t)seed[i * 4 + 1] <<  8) |
                           ((uint32_t)seed[i * 4 + 2] << 16) |
                           ((uint32_t)seed[i * 4 + 3] << 24);
    }

    /* Лічильник блоку та 96-бітний nonce */
    rng->state[12] = 0;
    rng->state[13] = 0x55AA55AA;
    rng->state[14] = 0x12345678;
    rng->state[15] = 0x9ABCDEF0;

    rng->keystream_idx = 64; /* Примусовий виклик першої генерації */
    rng->reseed_counter = 1;
}

/* Генерація випадкових байтів із захистом від компрометації минулого */
static void csprng_generate(ChaCha20_CSPRNG *rng, uint8_t *out, size_t len) {
    while (len > 0) {
        if (rng->keystream_idx >= 64) {
            chacha20_block(rng->state, rng->keystream);
            rng->state[12]++; /* Інкремент 32-бітного лічильника блоків */
            if (rng->state[12] == 0) rng->state[13]++;
            rng->keystream_idx = 0;
        }

        size_t available = 64 - rng->keystream_idx;
        size_t to_copy = (len < available) ? len : available;

        memcpy(out, &rng->keystream[rng->keystream_idx], to_copy);
        out += to_copy;
        len -= to_copy;
        rng->keystream_idx += to_copy;
    }

    /* Backtracking Resistance: негайне оновлення ключа наступним блоком */
    uint8_t next_key_block[64];
    chacha20_block(rng->state, next_key_block);
    rng->state[12]++;

    for (int i = 0; i < 8; i++) {
        rng->state[4 + i] = (uint32_t)next_key_block[i * 4 + 0]       |
                           ((uint32_t)next_key_block[i * 4 + 1] <<  8) |
                           ((uint32_t)next_key_block[i * 4 + 2] << 16) |
                           ((uint32_t)next_key_block[i * 4 + 3] << 24);
    }
    memset(next_key_block, 0, sizeof(next_key_block)); /* Очищення стеку */
    rng->keystream_idx = 64;                           /* Скидання залишкової гами */
}

// ============================================================================
// Вбудована криптографічна система випадковості (C++20 / Embedded Modern)
// Типобезпечна, без динамічної пам'яті, RAII, std::span, constexpr
// ============================================================================

#include <cstdint>
#include <cstddef>
#include <array>
#include <span>
#include <bit>
#include <algorithm>
#include <expected>

namespace embedded::crypto {

// ── 1. Онлайн-тест працездатності (NIST SP 800-90B RCT) ─────────────────────
class EntropyHealthMonitor {
public:
    explicit constexpr EntropyHealthMonitor(uint32_t cutoff = 24) noexcept
        : rct_cutoff_{cutoff} {}

    enum class Error {
        SourceStuckAtConstant,
        DegradedEntropy
    };

    [[nodiscard]] constexpr std::expected<void, Error> update(uint8_t sample) noexcept {
        if (fault_) return std::unexpected(Error::SourceStuckAtConstant);

        if (sample == last_sample_) {
            repeat_count_++;
            if (repeat_count_ >= rct_cutoff_) {
                fault_ = true;
                return std::unexpected(Error::SourceStuckAtConstant);
            }
        } else {
            last_sample_ = sample;
            repeat_count_ = 1;
        }

        ones_count_ += static_cast<uint32_t>(std::popcount(sample));
        total_samples_++;
        return {};
    }

    [[nodiscard]] constexpr bool is_healthy() const noexcept { return !fault_; }
    constexpr void reset() noexcept {
        last_sample_ = 0xFF;
        repeat_count_ = 0;
        fault_ = false;
        total_samples_ = 0;
        ones_count_ = 0;
    }

private:
    uint8_t  last_sample_{0xFF};
    uint32_t repeat_count_{0};
    uint32_t rct_cutoff_{24};
    uint32_t total_samples_{0};
    uint32_t ones_count_{0};
    bool     fault_{false};
};

// ── 2. Декорелятор Джона фон Неймана ─────────────────────────────────────────
class VonNeumannExtractor {
public:
    constexpr VonNeumannExtractor() noexcept = default;

    // Приймає один сирий біт. Якщо накопичено повний байт — повертає його.
    constexpr std::expected<uint8_t, void> feed_bit(uint8_t in_bit) noexcept {
        bit_buffer_ = (bit_buffer_ << 1) | (in_bit & 1);
        bit_count_++;

        if (bit_count_ >= 2) {
            const uint8_t pair = bit_buffer_ & 0x03;
            bit_count_ = 0;

            if (pair == 0b01) {        // Пара 01 -> біт 0
                out_byte_ = (out_byte_ << 1);
                out_bits_collected_++;
            } else if (pair == 0b10) { // Пара 10 -> біт 1
                out_byte_ = (out_byte_ << 1) | 1;
                out_bits_collected_++;
            }

            if (out_bits_collected_ >= 8) {
                const uint8_t ready_byte = out_byte_;
                out_byte_ = 0;
                out_bits_collected_ = 0;
                return ready_byte;
            }
        }
        return std::unexpected();
    }

private:
    uint8_t bit_buffer_{0};
    uint8_t bit_count_{0};
    uint8_t out_byte_{0};
    uint8_t out_bits_collected_{0};
};

// ── 3. Криптографічний генератор ChaCha20-DRBG ──────────────────────────────
class ChaCha20CSPRNG {
public:
    static constexpr size_t KeySize = 32;
    static constexpr size_t BlockSize = 64;

    explicit constexpr ChaCha20CSPRNG(std::span<const uint8_t, KeySize> seed) noexcept {
        reseed(seed);
    }

    constexpr void reseed(std::span<const uint8_t, KeySize> seed) noexcept {
        // Константи ChaCha20 ("expand 32-byte k")
        state_[0] = 0x61707865;
        state_[1] = 0x3320646e;
        state_[2] = 0x79622d32;
        state_[3] = 0x6b206574;

        for (size_t i = 0; i < 8; ++i) {
            state_[4 + i] = static_cast<uint32_t>(seed[i * 4 + 0])       |
                           (static_cast<uint32_t>(seed[i * 4 + 1]) <<  8) |
                           (static_cast<uint32_t>(seed[i * 4 + 2]) << 16) |
                           (static_cast<uint32_t>(seed[i * 4 + 3]) << 24);
        }

        state_[12] = 0;
        state_[13] = 0x55AA55AA;
        state_[14] = 0x12345678;
        state_[15] = 0x9ABCDEF0;

        keystream_idx_ = BlockSize;
    }

    void generate(std::span<uint8_t> output) noexcept {
        size_t offset = 0;
        while (offset < output.size()) {
            if (keystream_idx_ >= BlockSize) {
                generate_block(state_, keystream_);
                state_[12]++;
                if (state_[12] == 0) state_[13]++;
                keystream_idx_ = 0;
            }

            const size_t available = BlockSize - keystream_idx_;
            const size_t chunk = std::min(output.size() - offset, available);

            std::copy_n(keystream_.begin() + keystream_idx_, chunk, output.begin() + offset);
            offset += chunk;
            keystream_idx_ += chunk;
        }

        // Backtracking Resistance: оновлюємо ключ новим блоком
        std::array<uint8_t, BlockSize> next_key_block{};
        generate_block(state_, next_key_block);
        state_[12]++;

        for (size_t i = 0; i < 8; ++i) {
            state_[4 + i] = static_cast<uint32_t>(next_key_block[i * 4 + 0])       |
                           (static_cast<uint32_t>(next_key_block[i * 4 + 1]) <<  8) |
                           (static_cast<uint32_t>(next_key_block[i * 4 + 2]) << 16) |
                           (static_cast<uint32_t>(next_key_block[i * 4 + 3]) << 24);
        }
        std::fill(next_key_block.begin(), next_key_block.end(), 0);
        keystream_idx_ = BlockSize;
    }

    // Заборона копіювання для запобігання дублюванню внутрішнього стану
    ChaCha20CSPRNG(const ChaCha20CSPRNG&) = delete;
    ChaCha20CSPRNG& operator=(const ChaCha20CSPRNG&) = delete;
    ChaCha20CSPRNG(ChaCha20CSPRNG&&) noexcept = default;
    ChaCha20CSPRNG& operator=(ChaCha20CSPRNG&&) noexcept = default;

private:
    static constexpr void quarter_round(uint32_t& a, uint32_t& b, uint32_t& c, uint32_t& d) noexcept {
        a += b; d ^= a; d = std::rotl(d, 16);
        c += d; b ^= c; b = std::rotl(b, 12);
        a += b; d ^= a; d = std::rotl(d,  8);
        c += d; b ^= c; b = std::rotl(b,  7);
    }

    static void generate_block(const std::array<uint32_t, 16>& in, std::array<uint8_t, 64>& out) noexcept {
        std::array<uint32_t, 16> x = in;
        for (int i = 0; i < 10; ++i) {
            quarter_round(x[0], x[4], x[ 8], x[12]);
            quarter_round(x[1], x[5], x[ 9], x[13]);
            quarter_round(x[2], x[6], x[10], x[14]);
            quarter_round(x[3], x[7], x[11], x[15]);
            quarter_round(x[0], x[5], x[10], x[15]);
            quarter_round(x[1], x[6], x[11], x[12]);
            quarter_round(x[2], x[7], x[ 8], x[13]);
            quarter_round(x[3], x[4], x[ 9], x[14]);
        }
        for (size_t i = 0; i < 16; ++i) {
            const uint32_t val = x[i] + in[i];
            out[i * 4 + 0] = static_cast<uint8_t>(val);
            out[i * 4 + 1] = static_cast<uint8_t>(val >> 8);
            out[i * 4 + 2] = static_cast<uint8_t>(val >> 16);
            out[i * 4 + 3] = static_cast<uint8_t>(val >> 24);
        }
    }

    std::array<uint32_t, 16> state_{};
    std::array<uint8_t, 64>  keystream_{};
    size_t keystream_idx_{BlockSize};
};

} // namespace embedded::crypto

### Інженерний чеклист надійної випадковості на MCU

1. **Ніколи не використовувати `rand()` та `srand()`** для генерації криптографічних ключів, векторів ініціалізації (IV), токенів автентифікації або одноразових кодів (nonce).
2. **Апаратний TRNG — перший вибір:** якщо чип має блок TRNG (STM32 RNG, ESP32 HW RNG), увімкніть його тактування та перевіряйте статусний прапорець помилки ентропії (англ. *Seed Error Flag*, `SECS / CEIS`) на кожній ітерації зчитування.
3. **За відсутності TRNG комбінуйте щонайменше два джерела:** фазовий джиттер високочастотного таймера від повільного RC-генератора + молодші біти вибірок АЦП із внутрішнього датчика температури або опорної напруги.
4. **Обов'язкове кондиціювання через хеш-пул:** сирі біти шуму ніколи не подаються споживачам напряму. Вони відбілюються фільтром фон Неймана і хешуються (SHA-256 або ChaCha20) у пулі ентропії.
5. **Постійний онлайн-моніторинг здоров'я (Health Tests):** тест повторень (RCT) повинен негайно блокувати генерацію та переводити систему в безпечний режим у разі залипання чи відмови джерела шуму.
6. **Захист від компрометації минулого (Backtracking Resistance):** стан генератора CSPRNG оновлюється незворотним стиранням ключа одразу після видачі кожного блоку псевдовипадкових даних.
