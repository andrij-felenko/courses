# 📋 Специфікація каналів керування, діапазонів ШІМ та прапорців безпеки

Цей довідник містить повну технічну специфікацію стандартів розподілу каналів керування (Channel Mapping), фізичні рівні та швидкість послідовних інтерфейсів радіозв'язку, числові діапазони протоколів передачі радіосигналу (CRSF, SBUS, стандартний та розширений ШІМ), бітові структури упаковки радіокадрів, граничні пороги спрацьовування допоміжних каналів (AUX), таблицю вікон декодування режимів польоту та бітові прапорці блокування активації двигунів (Arming Disable Flags).

Усі польотні стеки (ArduPilot, PX4, Betaflight, INAV) спираються на стандартизовані числові діапазони в мікросекундах (`мкс`) або безрозмірних цифрових відліках шини. Невідповідність розкладки каналів передавача та приймача або неправильний поріг спрацьовування каналу безпеки призводить до повної втрати керованості апарата.

## 1. Стандарти порядку каналів керування (Channel Order)

Перші чотири канали апаратури відповідають за базові динамічні осі літального апарата. У таблиці наведено стандартні абревіатури та їхню прив'язку до протоколів і польотних стеків.

| Абревіатура | Канал 1 | Канал 2 | Канал 3 | Канал 4 | Основне середовище застосування |
|:---|:---|:---|:---|:---|:---|
| **AETR** | Крен (Aileron) | Тангаж (Elevator) | Газ (Throttle) | Рискання (Rudder) | ExpressLRS, OpenTX, EdgeTX, TBS Crossfire, FrSky, Betaflight (за замовчуванням) |
| **TAER** | Газ (Throttle) | Крен (Aileron) | Тангаж (Elevator) | Рискання (Rudder) | Spektrum DSMX/DSM2, Horizon Hobby, JR, застарілі системи Blade |
| **RETA** | Рискання (Rudder) | Тангаж (Elevator) | Газ (Throttle) | Крен (Aileron) | FlySky (i-BUS), Futaba (класичний протокол), Walkera |
| **ETAR** | Тангаж (Elevator) | Газ (Throttle) | Крен (Aileron) | Рискання (Rudder) | Multiplex, європейські планерні системи радіокерування |

У конфігураторах польотних контролерів зміна розкладки здійснюється параметром `map` (у Betaflight CLI: `map AETR1234`) або вибором відповідного переліку `RCMAP_ROLL`, `RCMAP_PITCH`, `RCMAP_THROTTLE`, `RCMAP_YAW` в ArduPilot.

## 2. Фізичні рівні, швидкості шин та електричні інтерфейси

Різні протоколи приймачів вимагають специфічної конфігурації апаратних портів UART мікроконтролера польотного контролера.

| Протокол зв'язку | Швидкість шини (Baud) | Формат кадру UART | Полярність сигналу | Тип з'єднання |
|:---|:---|:---|:---|:---|
| **SBUS (Futaba / FrSky)** | `100 000 біт/с` | `8E2` (8 біт, Even parity, 2 стоп-біти) | Інвертований (TTL Inverted) | Однопровідний односпрямований (RX) |
| **CRSF (ExpressLRS / Crossfire)** | `416 666` або `1 870 000 біт/с` | `8N1` (8 біт, No parity, 1 стоп-біт) | Прямий (Стандартний TTL) | Двопровідний дуплексний (TX + RX) |
| **i-BUS (FlySky)** | `115 200 біт/с` | `8N1` (8 біт, No parity, 1 стоп-біт) | Прямий (Стандартний TTL) | Однопровідний односпрямований (RX) |
| **FPort (FrSky)** | `115 200` або `100 000 біт/с` | `8N1` / `8E2` | Інвертований або прямий | Однопровідний напівдуплексний (Half-Duplex) |

При підключенні приймача SBUS до мікроконтролерів із фіксованими інверторами (STM32F4) необхідно використовувати виділений вхід із вбудованим апаратним транзисторним інвертором, тоді як мікроконтролери STM32F7 та STM32H7 дозволяють конфігурувати програмну інверсію полярності на будь-якому піні UART через регістр `CR2.RXINV`.

## 3. Числові діапазони цифрових протоколів та перетворення в мікросекунди

Сучасні цифрові протоколи передають значення каналів у вигляді цілочисельних відліків розрядністю 11 біт у кожному пакеті кадру.

| Параметр | Стандартний ШІМ (PWM) | Розширений ШІМ (Extended) | Цифровий CRSF (11 біт) | Цифровий SBUS (11 біт) |
|:---|:---|:---|:---|:---|
| **Мінімум (0%)** | `1000 мкс` | `988 мкс` | `172` | `172` |
| **Центр (50%)** | `1500 мкс` | `1500 мкс` | `992` | `992` |
| **Максимум (100%)** | `2000 мкс` | `2012 мкс` | `1811` | `1811` |
| **Динамічний розмах** | `1000 мкс` | `1024 мкс` | `1640 відліків` | `1640 відліків` |
| **Роздільна здатність** | ~1 мкс (аналог) | ~1 мкс (аналог) | `0.624 мкс / LSB` | `0.624 мкс / LSB` |

Формула прямого перетворення 11-бітного відліку CRSF / SBUS `Raw_val` у мікросекунди `T_us`:

```
T_us = 988 + ((Raw_val - 172) · 1024) / 1640   [лінійна інтерполяція діапазону 172..1811]
```

Зворотне перетворення мікросекунд у значення відліку протоколу:

```
Raw_val = 172 + ((T_us - 988) · 1640) / 1024   [масштабування часу в цілочисельний код]
```

## 4. Бітова структура упаковки кадрів SBUS та CRSF

У цифрових послідовних шинах 16 каналів розрядністю по 11 біт упаковані в неперервний бітовий потік без проміжних байтових меж. Загальний інформаційний обсяг 16 каналів становить:

```
16 каналів · 11 біт = 176 біт = 22 байти
```

### Структура кадру протоколу SBUS (25 байтів)
- **Байт 0:** Стартовий заголовок `0x0F`.
- **Байти 1..22:** Упаковані 16 каналів по 11 біт (LSB first).
- **Байт 23:** Прапорці стану:
  - `Bit 0:` Канал 17 (дискретний digital switch 1).
  - `Bit 1:` Канал 18 (дискретний digital switch 2).
  - `Bit 2:` Прапорець втрати кадру `Frame Lost` (1 = втрачено окремий пакет).
  - `Bit 3:` Прапорець аварії `Failsafe Active` (1 = критична втрата лінку).
- **Байт 24:** Стоповий байт `0x00` (або `0x04` у версіях Futaba S.BUS2).

### Структура кадру протоколу CRSF (RC Channels Payload, Type 0x16)
- **Байт 0:** Адреса пристрою призначення (`0xC8` для польотного контролера).
- **Байт 1:** Довжина корисного навантаження кадру (24 байти = 1 байт типу + 22 байти каналів + 1 байт CRC).
- **Байт 2:** Тип кадру `0x16` (`CRSF_FRAMETYPE_RC_CHANNELS_PACKED`).
- **Байти 3..24:** 16 каналів по 11 біт (від 172 до 1811 відліків).
- **Байт 25:** Контрольна сума CRC8 (поліном `0xD5`).

## 5. Граничні пороги та вікна допоміжних каналів (AUX Channels)

Допоміжні канали (AUX 1..AUX 12, що відповідають каналам CH5..CH16) використовуються для передачі дискретних команд перемикачів, тумблерів та селекторів.

### Пороги для 2-позиційних та 3-позиційних перемикачів

| Тип перемикача | Стан / Позиція | Номінальне значення | Діапазон спрацьовування | Гістерезис захисту |
|:---|:---|:---|:---|:---|
| **2-позиційний (SA)** | Позиція 0 (Вимкнено) | `1000 мкс` | `988...1300 мкс` | `> 1350 мкс` перехід у стан 1 |
| | Позиція 1 (Увімкнено) | `2000 мкс` | `1700...2012 мкс` | `< 1650 мкс` перехід у стан 0 |
| **3-позиційний (SC)** | Позиція 0 (Низька) | `1000 мкс` | `988...1300 мкс` | Вікно 1: `988...1300 мкс` |
| | Позиція 1 (Центральна) | `1500 мкс` | `1400...1600 мкс` | Вікно 2: `1350...1650 мкс` |
| | Позиція 2 (Висока) | `2000 мкс` | `1700...2012 мкс` | Вікно 3: `1700...2012 мкс` |

### Вікна декодування 6-позиційного перемикача режимів (Flight Modes)

У польотних контролерах під керуванням ArduPilot (параметр `FLTMODE_CH`) та PX4 6-позиційний селектор декодується за фіксованими вікнами:

| Позиція | Цільове значення | Діапазон вікна (ArduPilot / PX4) | Типовий режим польоту (Multirotor) | Поведінка системи |
|:---:|:---:|:---|:---|:---|
| **1** | `1165 мкс` | `988...1230 мкс` | `STABILIZE` | Ручний пілотаж з автостабілізацією горизонту |
| **2** | `1295 мкс` | `1231...1360 мкс` | `ALT_HOLD` | Автоматичне барометричне утримання висоти |
| **3** | `1425 мкс` | `1361...1490 мкс` | `LOITER` / `POSHOLD` | Утримання географічної координати за GNSS |
| **4** | `1555 мкс` | `1491...1620 мкс` | `AUTO` | Повністю автономне виконання польотної місії |
| **5** | `1685 мкс` | `1621...1749 мкс` | `RTL` | Автоматичне повернення на точку старту та посадка |
| **6** | `1815 мкс` | `1750...2012 мкс` | `LAND` | Вертикальне зниження та вимкнення моторів на землі |

## 6. Режими поведінки приймача при втраті радіосигналу (Failsafe Receiver Modes)

При втраті зв'язку між пультом та апаратом приймач керування переходить у захисний стан згідно з налаштованою конфігурацією:

1. **No Pulses / Cut (Рекомендований):** приймач повністю припиняє видачу кадрових імпульсів на польотний контролер або встановлює біт `Failsafe Active` у цифровому пакеті SBUS/CRSF. Польотний контролер виявляє таймаут надходження даних (`> 100 мс`) і самостійно запускає процедуру порятунку (RTL або аварійну посадку).
2. **Hold Last State (Категорично заборонений):** приймач продовжує нескінченно транслювати останні отримані значення каналів. Якщо в момент обриву лінку стік газу був на рівні 70%, а дрон летів уперед, апарат продовжить політ за вектором до повного розряду акумулятора або зіткнення.
3. **Preset Values:** приймач виставляє наперед записані значення каналів: канал газу `Throttle` скидається в значення нижче порогу виявлення (`< 950 мкс`), а канал режимів переводиться в положення `RTL`.

## 7. Бітова маска прапорців блокування запуску (Arming Disable Flags)

Якщо перемикач `ARM` переведено в активний стан, але одна з умов безпеки не виконана, польотний контролер блокує запуск двигунів і повертає бітову маску помилки (у конфігураторі Betaflight / QGroundControl відображається у рядку стану).

| Біт | Маска | Ідентифікатор прапорця | Опис причини блокування | Умова зняття блокування |
|:---:|:---:|:---|:---|:---|
| `0` | `0x0001` | `ARM_BLOCK_THROTTLE_NOT_ZERO` | Стік газу знаходиться вище мінімального порогу (`> 1050 мкс`) | Опустити стік газу в крайнє нижнє положення |
| `1` | `0x0002` | `ARM_BLOCK_FAILSAFE_ACTIVE` | Активний аварійний режим або відсутній зв'язок з пультом | Відновити надійний радіолінк або вимкнути тумблер Failsafe |
| `2` | `0x0004` | `ARM_BLOCK_PREARM_NOT_ENGAGED` | Не натиснуто кнопку попередньої авторизації (Pre-Arm) | Затиснути кнопку Pre-Arm перед перемиканням тумблера Arm |
| `3` | `0x0008` | `ARM_BLOCK_SWITCH_ACTIVE_BOOT` | Тумблер Arm був увімкнений під час подачі живлення на борт | Перевести тумблер Arm у положення Disarm для скидання захисту |
| `4` | `0x0010` | `ARM_BLOCK_CALIBRATING` | Виконується калібрування гіроскопа або барометра | Зачекати нерухомого завершення ініціалізації сенсорів (1–3 с) |
| `5` | `0x0020` | `ARM_BLOCK_TILT_ANGLE` | Кут нахилу апарата на землі перевищує допустимий ліміт (`> 25°`) | Встановити апарат на горизонтальну поверхню |
| `6` | `0x0040` | `ARM_BLOCK_NO_COMPASS_LOCK` | Магнітометр не узгоджений або зафіксовано магнітну заваду | Віддалити апарат від залізобетонних конструкцій та силових кабелів |
| `7` | `0x0080` | `ARM_BLOCK_NO_GNSS_FIX` | Режим польоту вимагає супутників, але 3D Fix відсутній | Дочекатися фіксації навігаційного рішення (HDOP < 1.5) |

## 8. Параметри конфігурації фільтрації та мертвої зони (Deadband & Smoothing)

Для виключення дрейфу нульових точок та усунення високочастотних шумів квантування радіоканалів у польотних контролерах налаштовуються параметри згладжування:

| Параметр конфігурації | Польотний стек | Рекомендоване значення | Призначення та фізичний ефект |
|:---|:---|:---|:---|
| `rc_deadband` | Betaflight / INAV | `3...5 мкс` | Зона нечутливості навколо центру 1500 мкс для осей крену й тангажу (виключає тремтіння стіка) |
| `rc_yaw_deadband` | Betaflight / INAV | `5...7 мкс` | Розширена зона нечутливості осі курсу (запобігає паразитній зміні курсу при різкому русі газом) |
| `RC_OPTIONS` (Bit 5) | ArduPilot | `0x0020` | Придушення брязкоту додаткових каналів перемикачів |
| `rc_smoothing_cutoff` | Betaflight | `30...50 Гц` | Частота зрізу біквадратного фільтра низьких частот для усунення сходинок квантування пакетів |

## 9. Логування каналів у Blackbox та телеметрії MAVLink

Для розслідування польотних інцидентів та аналізу дій оператора польотний контролер безперервно записує стан вхідного радіотракту:

1. **Журнал Blackbox (SD-карта або Flash):**
   - `rcData[0..15]`: сирі декодовані значення мікросекунд усіх каналів, отримані від приймача до застосування фільтрів та мікшерів.
   - `rcCommand[0..3]`: нормалізовані команди керування в градусах на секунду (у режимі Acro) або кутах нахилу (у режимі Angle).
   - `flightModeFlags`: бітова маска активного польотного режиму в кожен момент часу.

2. **Телеметрія MAVLink (Ground Control Station):**
   - Повідомлення `RC_CHANNELS` (`#65`): транслюється з частотою 2–10 Гц на наземну станцію; містить значення полів `chan1_raw`..`chan18_raw` у мікросекундах та рівень сигналу `rssi`.
   - Повідомлення `STATUSTEXT`: повертає текстові розшифровки причин блокування запуску (наприклад, `PreArm: Throttle below failsafe`).

Зіставлення часових міток зміни каналу `chan5_raw` (тумблер Arm) зі стрибками струму в журналі дозволяє точно встановити, чи сталася аварія через помилку пілота, чи внаслідок апаратного збою регулятора ESC.

## 10. Структури даних та розпакування каналів керування (C / C++)

Нижче наведено робочі реалізації бітового розпакування 11-бітних каналів із послідовного кадру CRSF/SBUS двома мовами програмування.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define RC_CHANNEL_MIN_US    988U
#define RC_CHANNEL_MAX_US    2012U
#define RC_CHANNEL_CENTER_US 1500U
#define RC_TOTAL_CHANNELS    16U

/* Порядок каналів керування */
typedef enum {
    RC_MAP_AETR = 0,
    RC_MAP_TAER = 1,
    RC_MAP_RETA = 2
} rc_channel_map_t;

/* Дискретні позиції перемикачів */
typedef enum {
    SWITCH_POS_LOW    = 0,
    SWITCH_POS_CENTER = 1,
    SWITCH_POS_HIGH   = 2
} switch_position_t;

/* Структура декодованого стану радіоканалу */
typedef struct {
    uint16_t raw_us;            /* Сире значення в мікросекундах */
    switch_position_t state;    /* Дискретний стан перемикача */
    bool is_valid;              /* Прапорець достовірності сигналу */
} rc_aux_channel_t;

/* Розпакування 16 11-бітних каналів з 22-байтового буфера */
void rc_unpack_11bit_channels(const uint8_t *payload, uint16_t *channels_us) {
    if (payload == NULL || channels_us == NULL) {
        return;
    }

    uint16_t raw[RC_TOTAL_CHANNELS];

    raw[0]  = (uint16_t)((payload[0]       | (payload[1] << 8))                      & 0x07FF);
    raw[1]  = (uint16_t)(((payload[1] >> 3) | (payload[2] << 5))                      & 0x07FF);
    raw[2]  = (uint16_t)(((payload[2] >> 6) | (payload[3] << 2) | (payload[4] << 10)) & 0x07FF);
    raw[3]  = (uint16_t)(((payload[4] >> 1) | (payload[5] << 7))                      & 0x07FF);
    raw[4]  = (uint16_t)(((payload[5] >> 4) | (payload[6] << 4))                      & 0x07FF);
    raw[5]  = (uint16_t)(((payload[6] >> 7) | (payload[7] << 1) | (payload[8] << 9))  & 0x07FF);
    raw[6]  = (uint16_t)(((payload[8] >> 2) | (payload[9] << 6))                      & 0x07FF);
    raw[7]  = (uint16_t)(((payload[9] >> 5) | (payload[10] << 3))                     & 0x07FF);
    raw[8]  = (uint16_t)((payload[11]      | (payload[12] << 8))                     & 0x07FF);
    raw[9]  = (uint16_t)(((payload[12] >> 3)| (payload[13] << 5))                     & 0x07FF);
    raw[10] = (uint16_t)(((payload[13] >> 6)| (payload[14] << 2)| (payload[15] << 10))& 0x07FF);
    raw[11] = (uint16_t)(((payload[15] >> 1)| (payload[16] << 7))                     & 0x07FF);
    raw[12] = (uint16_t)(((payload[16] >> 4)| (payload[17] << 4))                     & 0x07FF);
    raw[13] = (uint16_t)(((payload[17] >> 7)| (payload[18] << 1)| (payload[19] << 9)) & 0x07FF);
```
