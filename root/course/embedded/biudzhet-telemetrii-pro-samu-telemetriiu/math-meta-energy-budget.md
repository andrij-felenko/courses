# 🧮 Розрахунок енергетичного бюджету мета-телеметрії

Ця вставка містить формальні математичні моделі та покроковий розрахунок енергетичних витрат автономного вузла для різних стратегій передачі мета-телеметрії. Ми порівняємо витрати заряду батареї, середній струм споживання та тривалість автономної роботи для наївного постійного звітування, розділеного пульсу (Heartbeat), підсаджування (Piggybacking) та адаптивного сплеску при аномаліях у бездротових мережах LoRaWAN та NB-IoT.

## 1. Модель тривалості перебування в радіоефірі (Time on Air) для LoRaWAN

У бездротових протоколах низької потужності тривалість передачі пакета `T_toa` визначається довжиною преамбули, коефіцієнтом розширення спектра `SF` (Spreading Factor, від 7 до 12), смугою пропускання `BW` (зазвичай 125 кГц), швидкістю кодування `CR` (Code Rate, 4/5..4/8) та сумарним розміром корисного навантаження `PL` (Payload Length у байтах).

Тривалість одного символу модуляції:

```text
T_sym = 2^SF / BW
```

Для стандартного режиму LoRaWAN EU868 з `SF = 10` та `BW = 125 000 Гц`:

```text
T_sym = 2^10 / 125000
      = 1024 / 125000                 [піднесення 2 у степінь 10]
      = 0.008192 с                    [ділення: 8.192 мс на символ]
```

Кількість символів преамбули з урахуванням синхронізаційних символів мережі:

```text
N_preamble = 8 + 4.25
           = 12.25                    [стандартна довжина преамбули LoRa]
```

Тривалість передачі преамбули:

```text
T_preamble = N_preamble · T_sym
           = 12.25 · 0.008192         [множення кількості символів на тривалість]
           = 0.100352 с               [100.35 мс]
```

Кількість символів корисного навантаження `N_payload` для розміру кадру `PL` (у байтах) із заголовком MAC-рівня (13 байтів) та CRC (2 байти):

```text
N_payload = 8 + ceil((8·PL_total - 4·SF + 28 + 16·CRC - 20·IH) / (4·(SF - 2·DE))) · (CR + 4)
```

де `IH = 0` (явний заголовок), `DE = 1` (оптимізація низької швидкості для SF10..SF12), `CRC = 1`, `CR = 1` (4/5).

Спрощена формула для `SF10`, `BW125`, `CR 4/5`:

```text
N_payload(PL) = 8 + ceil((8·(PL + 13) - 40 + 28 + 16) / 32) · 5
              = 8 + ceil((8·PL + 108) / 32) · 5
```

Розрахуємо тривалість передачі для трьох розмірів навантаження:

1. `PL_data = 4` байти (лише корисні вимірювання сенсора):
```text
N_payload(4) = 8 + ceil((8·4 + 108) / 32) · 5
             = 8 + ceil(140 / 32) · 5          [140 / 32 = 4.375 -> ceil = 5]
             = 8 + 5 · 5                       [множення блоків кодування]
             = 33 символи                      [сумарна кількість символів тіла]

T_payload(4) = 33 · 0.008192 = 0.270336 с      [270.34 мс]

T_toa(4) = T_preamble + T_payload(4)
         = 0.100352 + 0.270336                 [додавання преамбули та тіла]
         = 0.370688 с                          [370.7 мс]
```

2. `PL_opt = 12` байтів (корисні дані 4Б + оптимізована мета-телеметрія 8Б):
```text
N_payload(12) = 8 + ceil((8·12 + 108) / 32) · 5
              = 8 + ceil(204 / 32) · 5         [204 / 32 = 6.375 -> ceil = 7]
              = 8 + 7 · 5                      [множення]
              = 43 символи

T_payload(12) = 43 · 0.008192 = 0.352256 с     [352.26 мс]

T_toa(12) = 0.100352 + 0.352256
          = 0.452608 с                         [452.6 мс]
```

3. `PL_naive = 80` байтів (корисні дані 4Б + текстовий JSON мета-телеметрії 76Б):
```text
N_payload(80) = 8 + ceil((8·80 + 108) / 32) · 5
              = 8 + ceil(748 / 32) · 5         [748 / 32 = 23.375 -> ceil = 24]
              = 8 + 24 · 5                     [множення]
              = 128 символів

T_payload(80) = 128 · 0.008192 = 1.048576 с    [1048.58 мс]

T_toa(80) = 0.100352 + 1.048576
          = 1.148928 с                         [1148.9 мс]
```

## 2. Модель енерговитрат у стільникових мережах NB-IoT

У стільникових мережах NB-IoT тривалість активності модема складається з чотирьох послідовних стадій:
1. `T_sync` — пробудження, пошук базової станції та синхронізація (при PSM становить 150–350 мс, середній струм `I_sync = 35 мА`);
2. `T_tx` — передача пакетів радіоблоками RLC/MAC (струм передавача `I_tx = 180 мА` при потужності +20 дБм);
3. `T_rx` — вікно прийому підтвердження ACK або відповіді сервера (тривалість 1.2 с, струм `I_rx = 25 мА`);
4. `T_tail` — таймер очікування переходу з активного стану RRC Connected у режим сну PSM (Inactivity Timer / RRC Release Tail, зазвичай від 6 до 20 секунд, струм спокою модема `I_tail = 12 мА`).

Енергія транзакції NB-IoT при відправці через UDP/CoAP без повторного відкриття сесії:

```text
E_nbiot = V_bat · (I_sync·T_sync + I_tx·T_tx(PL) + I_rx·T_rx + I_tail·T_tail)
```

Для пакета розміром 12 байтів (1 транспортний блок TBS):
```text
T_tx(12Б) = 0.032 с                             [32 мс радіопередачі]
E_tx_block = 3.6 В · 0.180 А · 0.032 с = 0.0207 Дж [20.7 мДж]

E_tail = 3.6 В · 0.012 А · 8.0 с
       = 0.3456 Дж                             [345.6 мДж]

E_nbiot(12Б) = 3.6·(0.035·0.25 + 0.180·0.032 + 0.025·1.2 + 0.012·8.0)
             = 3.6·(0.00875 + 0.00576 + 0.03000 + 0.09600)
             = 3.6 · 0.14051
             = 0.5058 Дж                       [505.8 мДж]
```

Для наївного JSON-пакета розміром 80 байтів через сегментацію на кілька RLC-блоків:
```text
T_tx(80Б) = 0.128 с                             [128 мс передачі]
E_nbiot(80Б) = 3.6·(0.00875 + 0.180·0.128 + 0.03000 + 0.09600)
             = 3.6·(0.00875 + 0.02304 + 0.03000 + 0.09600)
             = 3.6 · 0.15779
             = 0.5680 Дж                       [568.0 мДж]
```

При відправці через неоптимізований протокол TCP/MQTT замість UDP оверхед зростає ще сильніше через додаткові фази рукостискання SYN/ACK та закриття сокета FIN.

## 3. Енергетичний інтеграл циклу та розрахунок батареї

Сумарна енергія `E_cycle`, що витрачається вузлом за один інтервал дискретизації `T_int`, складається з чотирьох фаз:

```text
E_cycle = E_sense + E_proc + E_tx + E_sleep
```

де:
- `E_sense = V_bat · I_sense · T_sense` — опитування сенсорів (3.3 В, 5 мА протягом 20 мс = 0.33 мДж);
- `E_proc = V_bat · I_proc · T_proc` — робота процесора, підготовка кадру, розрахунок CRC (3.3 В, 8 мА протягом 10 мс = 0.264 мДж);
- `E_tx = V_bat · I_tx · T_toa` — робота радіопередавача LoRa на потужності +14 дБм (3.3 В, 45 мА);
- `E_sleep = V_bat · I_sleep · T_sleep` — глибокий сон (3.3 В, 3.5 мкА).

Обчислимо енергію радіопередачі `E_tx` для LoRaWAN:

```text
E_tx(4Б)  = 3.3 В · 0.045 А · 0.370688 с
          = 0.055047 Дж                        [55.05 мДж]

E_tx(12Б) = 3.3 В · 0.045 А · 0.452608 с
          = 0.067212 Дж                        [67.21 мДж]

E_tx(80Б) = 3.3 В · 0.045 А · 1.148928 с
          = 0.170616 Дж                        [170.62 мДж]
```

Якщо прилад надсилає дані кожні 10 хвилин (`T_int = 600` секунд):

```text
T_sleep = T_int - T_sense - T_proc - T_toa

E_sleep = 3.3 В · 0.0000035 А · 600 с
        = 0.00693 Дж                           [6.93 мДж на цикл]
```

Сумарна енергія за один цикл:
- Без мета-телеметрії (4Б): `0.33 + 0.264 + 55.05 + 6.93 = 62.57 мДж`
- З бітово-упакованою діагностикою (12Б): `0.33 + 0.264 + 67.21 + 6.93 = 74.73 мДж` (+19.4%)
- З наївною JSON мета-телеметрією (80Б): `0.33 + 0.264 + 170.62 + 6.93 = 178.14 мДж` (+184.7%)

## 4. Середній струм споживання та автономний строк служби

Середній струм споживання пристрою:

```text
I_avg = Q_cycle / T_int = (E_cycle / V_bat) / T_int
```

Розрахуємо середній струм для інтервалу `T_int = 600 с` (10 хвилин):

```text
I_avg(4Б)  = (0.06257 Дж / 3.3 В) / 600 с
           = 0.018960 Кл / 600 с               [розрахунок заряду на цикл]
           = 31.60 мкА                         [ділення на інтервал 600 с]

I_avg(12Б) = (0.07473 Дж / 3.3 В) / 600 с
           = 0.022645 Кл / 600 с               [розрахунок заряду на цикл]
           = 37.74 мкА                         [ділення на інтервал 600 с]

I_avg(80Б) = (0.17814 Дж / 3.3 В) / 600 с
           = 0.053982 Кл / 600 с               [розрахунок заряду на цикл]
           = 89.97 мкА                         [ділення на інтервал 600 с]
```

Теоретичний строк служби від літієвої батареї LiSOCl2 номінальною ємністю `C_nom = 2600 мА·год` (типорозмір AA, ER14505) з урахуванням коефіцієнта корисної віддачі ємності при імпульсному розряді `k_eff = 0.85` та щорічного саморозряду `I_self = 1 % / рік ≈ 3.0 мкА`:

```text
C_usable = C_nom · k_eff
         = 2600 мА·год · 0.85                  [врахування пасивації та просадки]
         = 2210 мА·год

I_total = I_avg + I_self
```

Розрахуємо строк служби `T_life` у роках:

```text
T_life = C_usable / (I_total · 8760 год/рік)
```

1. Базові вимірювання (4Б):
```text
I_total(4Б) = 31.60 + 3.0 = 34.60 мкА = 0.03460 мА
T_life(4Б)  = 2210 / (0.03460 · 8760)
            = 2210 / 303.096                   [річне споживання в мА·год]
            = 7.29 року                        [строк автономної роботи]
```

2. Оптимізована мета-телеметрія в кожному пакеті (12Б):
```text
I_total(12Б) = 37.74 + 3.0 = 40.74 мкА = 0.04074 мА
T_life(12Б)  = 2210 / (0.04074 · 8760)
             = 2210 / 356.882                  [річне споживання в мА·год]
             = 6.19 року                       [строк автономної роботи]
```

3. Наївна JSON мета-телеметрія в кожному пакеті (80Б):
```text
I_total(80Б) = 89.97 + 3.0 = 92.97 мкА = 0.09297 мА
T_life(80Б)  = 2210 / (0.09297 · 8760)
             = 2210 / 814.417                  [річне споживання в мА·год]
             = 2.71 року                       [строк автономної роботи]
```

4. Стратегія Piggybacking (4Б кожні 10 хв + повний кадр 12Б раз на 6 годин):
За 6 годин (36 циклів по 10 хв) передається 35 пакетів по 4Б (плюс 1 статус-байт, разом 5Б, `T_toa = 370.7 мс`) та 1 пакет повного кадру 12Б:

```text
Q_6h = 35 · Q_cycle(5Б) + 1 · Q_cycle(12Б)
     = 35 · 0.018960 + 1 · 0.022645            [сумарний заряд за 6 годин]
     = 0.663600 + 0.022645
     = 0.686245 Кл

I_avg_piggyback = 0.686245 Кл / (6 · 3600 с)
                = 0.686245 / 21600             [ділення на 21600 секунд]
                = 31.77 мкА                    [середній струм]

I_total_piggyback = 31.77 + 3.0 = 34.77 мкА
T_life_piggyback  = 2210 / (0.03477 · 8760)
                  = 2210 / 304.585             [річне споживання в мА·год]
                  = 7.25 року                  [строк автономної роботи]
```

## 5. Вплив температури та ефекту Пейкерта на корисну ємність

При імпульсному розряді хімічних елементів живлення високим струмом передавача (50–200 мА) реальна ємність батареї менша за паспортну через внутрішні поляризаційні втрати (закон Пейкерта) та пасиваційні плівки.

Залежність ефективної ємності `C_eff` від температури навколишнього середовища `T`:

```text
C_eff(T) = C_nom · k_temp(T) · (I_nom / I_pulse)^(p - 1)
```

де `p ≈ 1.05..1.15` — коефіцієнт Пейкерта для літій-тіонілхлориду, `k_temp` — температурний коефіцієнт (1.0 при +20 °C, 0.72 при −10 °C, 0.45 при −30 °C).

При короткому імпульсі передачі (98 мс для оптимізованого кадру) прогрів електроліту локальним струмом є мінімальним, а падіння напруги не досягає критичного порога. При тривалому імпульсі (1150 мс для JSON-пакета) спад напруги на внутрішньому опорі `R_int` затягується, спричиняючи передчасне вимкнення мікроконтролера задовго до повного вичерпання електрохімічної ємності.
