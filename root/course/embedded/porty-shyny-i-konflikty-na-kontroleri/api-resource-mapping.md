# 📋 Матриця периферійних ресурсів польотного контролера

Ця довідкова специфікація містить повний апаратний контракт мультиплексування виводів (GPIO Alternate Functions), таблиці каналів DMA контролерів STM32 (родини F4, F7 та H7), схеми розподілу апаратних таймерів та інтерфейс командного рядка (CLI) для конфігурації польотних прошивок.

---

## 1. Специфікація шин та периферійних інтерфейсів

Польотний контролер інтегрує датчики, приймачі та регулятори швидкості через чотири типи фізичних та логічних шин. Кожен інтерфейс має фіксовані обмеження за пропускною здатністю, затримкою та допустимим навантаженням.

| Шина / Інтерфейс | Фізичний рівень | Типова частота / швидкість | Призначення в системі | Режим передачі даних | Допустимий дедлайн |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **SPI1 (Primary)** | Full-duplex CMOS 3.3V | 10–42 МГц | Головний IMU (ICM-42688-P, BMI270) | Потоковий DMA Burst | Твердий (125 мкс при 8 кГц) |
| **SPI2 / SPI3** | Full-duplex CMOS 3.3V | 10–21 МГц | OSD (MAX7456), Flash (W25Q128), SDIO | DMA / Переривання | М'який (10–20 мс) |
| **I2C1 / I2C2** | Open-drain (Pull-up 2.2–4.7 кОм) | 400 кГц (Fast Mode) | Магнітометр (IST8310), барометр (DPS310) | Опитування за таймером | М'який (10–50 мс) |
| **UART1 (RC)** | Асинхронний NRZ / Inverted | 420–921.6 кбод (CRSF/ELRS) / 100 кбод (SBUS) | Радіоприймач керування | DMA Circular Buffer | Напівтвердий (2–4 мс) |
| **UART3 (GNSS)** | Асинхронний NRZ 3.3V | 115.2–921.6 кбод | Супутниковий модуль GNSS (UBX) | DMA / IRQ Ring Buffer | М'який (100–200 мс) |
| **UART6 (VTX)** | Асинхронний NRZ / MSP | 115.2 кбод (SmartAudio / MSP-DisplayPort) | Керування відеопередавачем | Переривання | М'який (50–100 мс) |
| **UART4 (ESC)** | Напівдуплекс (Half-duplex 1-wire) | 115.2 кбод | ESC Telemetry (KISS / BLHeli32) | Переривання | М'який (20–50 мс) |
| **CAN / FDCAN** | Диференційна пара (120 Ом) | 1 Мбіт/с (DroneCAN) | Зовнішні датчики, сервоприводи, ESC | Апаратні Mailbox FIFO | Твердий / Напівтвердий |

## 2. Апаратні регістри мультиплексування виводів (GPIO Alternate Functions)

Кожен фізичний вивід мікроконтролера STM32 комутується до внутрішньої периферії через набір 32-бітних регістрів конфігурації GPIO. Для коректної роботи швидкісних сигналів таймерів, шин SPI та портів UART прошивка налаштовує чотири обов'язкові регістри кожного порту:

1. **`GPIOx_MODER` (Mode Register):** Задає режим роботи виводу: `00` — вхід (Input), `01` — вихід загального призначення (General Purpose Output), `10` — альтернативна функція периферійного блоку (Alternate Function Mode), `11` — аналоговий режим (Analog Mode для каналів АЦП). Для таймерів, шин SPI та портів UART виставляється режим `10`.
2. **`GPIOx_AFR[0]` та `GPIOx_AFR[1]` (Alternate Function Low/High Registers):** 4-бітні поля для кожного виводу, що обирають один із 16 внутрішніх апаратних каналів (від `AF0` до `AF15`). Регістр `AFR[0]` (AFRL) керує пінами 0..7, регістр `AFR[1]` (AFRH) керує пінами 8..15.
3. **`GPIOx_OSPEEDR` (Output Speed Register):** Визначає швидкість наростання фронту сигналу (Slew Rate): `00` — низька (Low, 2 МГц), `01` — середня (Medium, 25 МГц), `10` — висока (Fast, 50 МГц), `11` — максимальна (High Speed, до 100 МГц на F4/F7/H7). Для ліній тактування SPI (SCK) та виходів DShot обов'язково встановлюється режим `11` для уникнення завалювання фронтів наносекундних імпульсів.
4. **`GPIOx_PUPDR` (Pull-up / Pull-down Register):** Внутрішні резистори підтяжки до 3.3 В або землі: `00` — без підтяжки (No Pull), `01` — підтяжка до живлення (Pull-up), `10` — підтяжка до землі (Pull-down). Для шин I2C рекомендовано зовнішні підтяжки 2.2–4.7 кОм, але внутрішній Pull-up вмикається як резервний.

### Карта альтернативних функцій STM32F4/F7

```
Код AF    Периферійне призначення
─────────────────────────────────────────────────────────────────────────────
AF0       Системні функції (MCO1, MCO2, SWD, JTAG, RTC)
```

## 3. Регістри керування та апаратні бітфілди контролера DMA

Кожен апаратний потік контролера DMA у мікроконтролерах STM32F4 та STM32F7 налаштовується через блок спеціалізованих регістрів:

1. **`DMA_SxCR` (Stream Configuration Register):**
   - Біти `CHSEL[2:0]` (27..25): вибір апаратного каналу периферійного блоку (від Channel 0 до Channel 7).
   - Біти `PL[1:0]` (17..16): пріоритет потоку арбітра шини (`00` — низький, `01` — середній, `10` — високий, `11` — дуже високий / Very High). Для шини `SPI1_RX` (Primary IMU) обов'язково призначається найвищий пріоритет `11`, для таймерів DShot — `10`, для послідовних портів — `01` або `00`.
   - Біт `CIRC` (8): циклічний режим (Circular Mode). Увімкнений для безперервного прийому пакетів RC-приймача та циклічного зчитування буферів.
   - Біти `DIR[1:0]` (7..6): напрямок передачі даних (`00` — з периферії в пам'ять / Peripheral-to-Memory для SPI RX та UART RX; `01` — з пам'яті в периферію / Memory-to-Peripheral для DShot Burst та SPI TX; `10` — з пам'яті в пам'ять / Memory-to-Memory).
   - Біти `MSIZE[1:0]` (14..13) та `PSIZE[1:0]` (12..11): ширина слова пам'яті та периферії (`00` — 8 біт / Byte, `01` — 16 біт / Half-Word, `10` — 32 біти / Word). Для пакетів DShot Burst використовується 32-бітний режим для прямого запису в регістри таймера `TIMx_DMAR`.
2. **`DMA_SxNDTR` (Number of Data Items Register):** 16-бітний лічильник елементів передачі. Декрементується апаратно після кожного успішного перенесення транзакції.
3. **`DMA_SxPAR` (Peripheral Address Register):** Базова 32-бітна фізична адреса регістра периферійного пристрою (наприклад, `&(SPI1->DR)` або `&(TIM1->DMAR)`).
4. **`DMA_SxM0AR` (Memory 0 Address Register):** Базова адреса буфера в оперативній пам'яті SRAM/DTCM.

## 4. Апаратна матриця мультиплексування DMA (STM32F405 / STM32F722)

У мікроконтролерах STM32F4 та STM32F7 запити від периферійних модулів комутуються до двох контролерів DMA (`DMA1` для периферії шини APB1, `DMA2` для APB2 та швидкісних блоків). Кожен контролер містить 8 потоків (`Stream 0..7`), а кожен потік має селектор з 8 каналів (`Channel 0..7`).

Кожен потік `DMA_Stream_x` у будь-який момент часу може обслуговувати лише **один** апаратний канал `Channel_y`. Якщо два периферійні блоки претендують на той самий потік, виникає апаратний конфлікт.

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Stream 0** | ADC1 | — | — | **SPI1_RX** | — | — | TIM1_TRIG | — |
| **Stream 1** | — | DCMI | — | — | — | USART6_RX | TIM1_CH1 | — |
| **Stream 2** | TIM8_CH1 | — | — | **SPI1_RX** | — | USART6_RX | TIM1_CH2 | — |
| **Stream 3** | — | — | — | **SPI1_TX** | — | — | TIM1_CH1 | — |
| **Stream 4** | ADC1 | — | — | — | — | — | TIM1_CH4 / TRIG | — |
| **Stream 5** | — | — | — | **SPI1_TX** | — | USART6_TX | **TIM1_UP** | — |
| **Stream 6** | TIM8_CH2 | — | — | — | — | USART6_TX | TIM1_CH3 | — |
| **Stream 7** | — | DCMI | — | — | — | USART6_RX | **TIM1_UP** | — |

| Потік DMA1 | Channel 0 | Channel 1 | Channel 2 | Channel 3 | Channel 4 | Channel 5 | Channel 6 | Channel 7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| **Stream 2** | SPI3_RX | — | — | — | UART4_RX | **USART3_TX** | TIM5_CH1 | — |
| **Stream 3** | — | — | — | **TIM3_CH4 / UP**| — | **USART3_TX** | — | — |
| **Stream 4** | SPI2_RX | — | — | — | **USART1_TX** | — | **TIM3_CH1 / TRIG** | — |
| **Stream 5** | SPI3_TX | — | — | TIM3_CH1 | **USART2_RX** | — | — | — |
| **Stream 6** | — | — | — | TIM3_CH2 / UP | **USART2_TX** | — | TIM5_UP | — |
| **Stream 7** | SPI2_TX | — | — | TIM3_CH3 | **UART4_TX** | USART3_TX | TIM5_CH4 | — |

> ⚠️ **Критичний конфлікт:** На `DMA2_Stream_5` одночасно претендують `SPI1_TX` (Channel 3) та `TIM1_UP` (Channel 6, базовий тригер DShot Burst для моторів 1–4). Якщо прошивка намагається використовувати повнодуплексний DMA для SPI1 IMU та DShot Burst на TIM1, потік `DMA2_Stream_5` блокується. Рішення: перенесення передачі `SPI1_TX` на `DMA2_Stream_3` (Channel 3), або переведення прийому `SPI1_RX` на `DMA2_Stream_0` (Channel 3), а передачі — на `DMA2_Stream_3`.

## 5. Таблиця маршрутизації DMAMUX (STM32H743 / STM32H753)

Мікроконтролери серії STM32H7 позбавлені жорсткої фіксації каналів завдяки матриці перехресних з'єднань DMAMUX1 (128 входів запитів на 16 вихідних каналів DMA). Будь-який периферійний тригер призначається довільному вільному потоку.

| Ідентифікатор тригера (Request ID) | Периферійне джерело | Призначення в польотному контролері | Рекомендований потік DMA |
| :--- | :--- | :--- | :--- |
| `0x09` | **SPI1_RX_DMA** | Зчитування вибірок головного гіроскопа | DMA1_Stream0 |
| `0x0A` | **SPI1_TX_DMA** | Запис команд/адрес до головного гіроскопа | DMA1_Stream1 |
| `0x0B` | **SPI2_RX_DMA** | Зчитування Flash Blackbox / OSD | DMA1_Stream2 |
| `0x0C` | **SPI2_TX_DMA** | Запис кадрів OSD / сторінок Flash | DMA1_Stream3 |
| `0x0F` | **TIM1_UP_DMA** | Генерація пакетів DShot для моторів 1–4 | DMA1_Stream4 |
| `0x1B` | **TIM3_UP_DMA** | Генерація пакетів DShot для моторів 5–8 | DMA1_Stream5 |
| `0x27` | **USART1_RX_DMA** | Приймач ExpressLRS / CRSF Telemetry | DMA1_Stream6 |
| `0x2D` | **USART3_RX_DMA** | Потік GNSS навігаційних повідомлень | DMA2_Stream0 |
| `0x3B` | **TIM8_UP_DMA** | Видача бітового потоку на LED Strip (WS2812B) | DMA2_Stream1 |

## 7. Інтерфейс командного рядка (CLI) для діагностики та конфігурації

У польотних прошивках родини Betaflight, Cleanflight та iNav керування прив'язкою апаратних ресурсів здійснюється через спеціалізовані команди CLI.

### 7.1. Перегляд поточної конфігурації

```text
# Перегляд прив'язки пінів до логічних функцій
resource show

# Перегляд зайнятих апаратних таймерів
timer show

# Перегляд призначених каналів та потоків DMA
dma show
```

### 7.2. Повний перелік ідентифікаторів функцій (Resource Function Identifiers)

При перепризначенні ресурсів через CLI використовуються стандартизовані ключові слова:


### 7.3. Звільнення та перепризначення ресурсів

Синтаксис команди: `resource <FUNCTION> <INDEX> <PIN> | NONE`

```text
# Звільнення піну B01 від конфліктуючого мотора
resource MOTOR 5 NONE

# Призначення піну B01 для керування адресною LED-стрічкою
resource LED_STRIP 1 B01

# Перепризначення виходу Motor 1 на альтернативний пін з підтримкою таймера
resource MOTOR 1 A08

# Фіксація змін та перезавантаження контролера
save
```

### 7.4. Ручне керування потоками DMA

Синтаксис команди: `dma <FUNCTION> <INDEX> <DMA_STREAM_ID>`

```text
# Примусове перенесення DMA тригера мотора 1 на Stream 1
dma pin A08 1

# Призначення потоку DMA для LED-стрічки
dma pin B01 0

# Збереження конфігурації
save
```
