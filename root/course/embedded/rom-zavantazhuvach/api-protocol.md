# 📋 Специфікація протоколу завантажувача ST System Memory

Фабричний ROM-завантажувач мікроконтролерів сімейства STM32 та сумісних архітектур взаємодіє із зовнішнім світом за двійковим командним протоколом фіксованого формату. Цей інтерфейс не залежить від операційної системи ПК і може бути реалізований як спеціалізованою програмою (наприклад, `stm32flash`, STM32CubeProgrammer), так і автономним драйвером на центральному мікроконтролері-майстрі чи вбудованому Linux-комп'ютері.

Нижче наведено повну двійкову специфікацію протоколу, формати команд, таймінги, правила обчислення контрольних сум, особливості фізичних шин (USART, I2C, SPI, CAN, USB DFU) та коди відповідей апаратного завантажувача.

---

## Фізичні байти квитування

Усі транзакції протоколу спираються на два однобайтові статусні коди, якими мікроконтролер підтверджує або відхиляє кожну дію хоста:

| Байт (HEX) | Назва | Опис та умова повернення |
|---|---|---|
| `0x79` | **ACK** (Acknowledge) | Успішне прийняття байта, команди, адреси чи блоку даних. Означає готовність чипа до наступного кроку транзакції. |
| `0x1F` | **NACK** (Negative Acknowledge) | Помилка: невідомий код команди, невідповідність інверсного байта (`CMD ^ ~CMD != 0xFF`), помилка контрольної суми XOR, адреса за межами доступної пам'яті, незбіг вирівнювання або спроба доступу до захищеного сектора (RDP Level 1). |

---

## Синхронізація швидкості (Autobauding для USART)

Для інтерфейсу USART хост зобов'язаний розпочати сеанс зв'язку з передачі єдиного байта ініціалізації:

```
Хост  ─── [ 0x7F ] ───►  ROM Bootloader
Хост  ◄── [ 0x79 ] ───── ROM Bootloader (ACK)
```

- **Формат кадру:** 8 бітів даних, контроль парності Even (парний), 1 стоп-біт (`8E1`). Більшість сучасних завантажувачів ST також допускають конфігурацію `8N1` (без парності) після успішного автопідлаштування, але початковий байт `0x7F` вимагає суворого дотримання таймінгів парності.
- **Діапазон швидкостей:** від 1200 до 115200 бод (на сучасних серіях STM32G4/STM32H7 — до 921600 бод).
- **Поведінка завантажувача:** таймер кристала вимірює тривалість спадного імпульсу стартового біта байта `0x7F` (перепад із високого рівня Idle у низький, після чого слідують сім одиничних бітів), обчислює коефіцієнт ділення для регістра `USART_BRR` і повертає `0x79 (ACK)`. Якщо протягом встановленого таймауту байт не розпізнано, завантажувач продовжує слухати інші інтерфейси (USB, I2C, SPI, CAN).

## Загальна структура командного кадру

Кожна команда від хоста надсилається у вигляді двобайтового пакета: сам код команди та його побітове доповнення (інверсія):

```
Кадр команди:  [ CMD ] [ ~CMD ]
де ~CMD = CMD ^ 0xFF
```

### Алгоритм валідації команди чипом:

```
1. Отримано байт B1 (CMD) та байт B2 (~CMD).
2. Якщо (B1 ^ B2) != 0xFF:
       Надіслати NACK (0x1F);
       Повернутися в стан очікування нової команди.
3. Якщо команда підтримується завантажувачем:
       Надіслати ACK (0x79);
       Перейти до прийому аргументів команди.
4. Якщо команда не підтримується або заблокована рівнем захисту RDP:
       Надіслати NACK (0x1F).
```

## Повна таблиця команд завантажувача

| Код (`CMD`) | Інверсія (`~CMD`) | Назва команди | Призначення та особливості |
|---|---|---|---|
| `0x00` | `0xFF` | **Get** | Отримати версію протоколу завантажувача та список усіх підтримуваних команд. |
| `0x01` | `0xFE` | **Get Version & Read Protection Status** | Отримати версію завантажувача та поточний стан захисту від читання (RDP). |
| `0x02` | `0xFD` | **Get ID** | Отримати 16-бітний ідентифікатор продукту (Product ID, PID кристала). |
| `0x11` | `0xEE` | **Read Memory** | Зчитати до 256 байтів із довільної адреси пам'яті (Flash, SRAM, System ROM, Option Bytes). Блокується при RDP Level 1. |
| `0x21` | `0xDE` | **Go** | Передати керування процесора за вказаною адресою (запуск прошивки у Flash або тестового коду в SRAM). |
| `0x31` | `0xCE` | **Write Memory** | Записати блок даних (від 1 до 256 байтів) за вказаною адресою Flash або SRAM. |
| `0x43` | `0xBC` | **Erase Memory** | Стандартне стирання сторінок Flash (для ранніх серій STM32F1 із нумерацією сторінок до 255). |
| `0x44` | `0xBB` | **Extended Erase Memory** | Розширене стирання Flash (підтримка 16-бітних номерів секторів, двобанкової пам'яті та кодів Mass Erase). |
| `0x63` | `0x9C` | **Write Protect** | Увімкнути захист від запису для переліку секторів Flash через Option Bytes. |
| `0x73` | `0x8C` | **Write Unprotect** | Зняти захист від запису з усіх секторів (ініціює автоматичне стирання Flash). |
| `0x82` | `0x7D` | **Readout Protect** | Увімкнути захист від зчитування (переведення в RDP Level 1). |
| `0x92` | `0x6D` | **Readout Unprotect** | Зняти захист від зчитування (переведення в RDP Level 0) з автоматичним апаратним масовим стиранням (Mass Erase). |

## Детальний формат виконання ключових команд

### 1. Команда Get (`0x00`)

Дозволяє хосту визначити версію завантажувача та підтримуваний набір опкодів:

```
Хост:         [ 0x00 ] [ 0xFF ]
Bootloader:   [ 0x79 (ACK) ]
Bootloader:   [ N ]               (Кількість наступних байтів мінус 1, зазвичай N = 11..14)
Bootloader:   [ Bootloader_Ver ]  (Наприклад, 0x22 = v2.2, 0x31 = v3.1)
Bootloader:   [ CMD_0 ]           (0x00 - Get)
Bootloader:   [ CMD_1 ]           (0x01 - Get Version)
Bootloader:   [ CMD_2 ]           (0x02 - Get ID)
              ...
Bootloader:   [ CMD_N-1 ]
Bootloader:   [ 0x79 (ACK) ]
```

---

### 2. Команда Get ID (`0x02`)

Повертає апаратний ідентифікатор сімейства чипа (Device ID), що збігається з полем `DEV_ID` у регістрі `DBGMCU_IDCODE`:

```
Хост:         [ 0x02 ] [ 0xFD ]
Bootloader:   [ 0x79 (ACK) ]
Bootloader:   [ N ]               (Кількість байтів PID мінус 1; завжди 0x01 для 2-байтового PID)
Bootloader:   [ PID_MSB ]         (Старший байт, наприклад, 0x04)
Bootloader:   [ PID_LSB ]         (Молодший байт, наприклад, 0x10 для STM32F103 Medium-Density)
Bootloader:   [ 0x79 (ACK) ]
```

*Типові ідентифікатори PID:*
- `0x0412` — STM32F10x Low-Density (до 32 КБ Flash);
- `0x0410` — STM32F10x Medium-Density (до 128 КБ Flash);
- `0x0414` — STM32F10x High-Density (до 512 КБ Flash);
- `0x0413` — STM32F405/407/415/417;
- `0x0419` — STM32F427/437/429/439;
- `0x0468` — STM32G431/G441.

---

### 3. Команда Read Memory (`0x11`)

Зчитує до 256 байтів із довільної дійсної адреси. Адреса передається 4 байтами (Big-Endian) із супроводжуючою контрольною сумою XOR:

```
Крок 1 (Запит):
Хост:         [ 0x11 ] [ 0xEE ]
Bootloader:   [ 0x79 (ACK) ]

Крок 2 (Адреса читання):
Хост:         [ ADDR_3 ] [ ADDR_2 ] [ ADDR_1 ] [ ADDR_0 ] [ XOR_CS ]
де XOR_CS = ADDR_3 ^ ADDR_2 ^ ADDR_1 ^ ADDR_0
Bootloader:   [ 0x79 (ACK) ]  (якщо адреса коректна і RDP не активний)
          або [ 0x1F (NACK) ] (якщо RDP Level 1 або адреса поза картою)

Крок 3 (Кількість байтів):
Хост:         [ N ] [ ~N ]
де N = (кількість байтів для зчитування - 1), 0 <= N <= 255. ~N = N ^ 0xFF.
Bootloader:   [ 0x79 (ACK) ]
Bootloader:   [ DATA_0 ] [ DATA_1 ] ... [ DATA_N ]
```

---

### 4. Команда Write Memory (`0x31`)

Записує від 1 до 256 байтів у Flash або SRAM. Для Flash-пам'яті адреса має бути вирівняна за межею слова або подвійного слова (2, 4 чи 8 байтів залежно від покоління ядра та контролера пам'яті), а цільовий сектор має бути попередньо стертий (`0xFF`):

```
Крок 1 (Запит):
Хост:         [ 0x31 ] [ 0xCE ]
Bootloader:   [ 0x79 (ACK) ]

Крок 2 (Цільова адреса запису):
Хост:         [ ADDR_3 ] [ ADDR_2 ] [ ADDR_1 ] [ ADDR_0 ] [ XOR_ADDR ]
де XOR_ADDR = ADDR_3 ^ ADDR_2 ^ ADDR_1 ^ ADDR_0
Bootloader:   [ 0x79 (ACK) ]

Крок 3 (Дані):
Хост:         [ N ] [ DATA_0 ] [ DATA_1 ] ... [ DATA_N ] [ XOR_DATA ]
де:
  N = кількість байтів мінус 1 (0 <= N <= 255, тобто від 1 до 256 байтів).
  XOR_DATA = N ^ DATA_0 ^ DATA_1 ^ ... ^ DATA_N
Bootloader:   [ 0x79 (ACK) ]  (після фізичного запису у Flash)
          або [ 0x1F (NACK) ] (при помилці контрольної суми або апаратному збої Flash)
```

---

### 5. Команда Extended Erase Memory (`0x44`)

Використовується в усіх сучасних мікроконтролерах із секторною або сторінковою організацією Flash. Підтримує як вибіркове стирання секторів, так і повне глобальне очищення (Global Mass Erase).

#### Режим А: Глобальне стирання (Special Mass Erase)

```
Крок 1 (Запит):
Хост:         [ 0x44 ] [ 0xBB ]
Bootloader:   [ 0x79 (ACK) ]

Крок 2 (Код масового стирання):
Хост:         [ 0xFF ] [ 0xFF ] [ 0x00 ]
де:
  0xFFFF — спеціальний 16-бітний код "Mass Erase All Banks";
  0x00 — контрольна сума: 0xFF ^ 0xFF = 0x00.
Bootloader:   [ 0x79 (ACK) ]  (надсилається ПІСЛЯ повного завершення стирання кристала)
```

*Спеціальні 16-бітні коди стирання:*
- `0xFFFF` (CS: `0x00`) — стирання всіх банків користувацької Flash;
- `0xFFFE` (CS: `0x01`) — стирання виключно Bank 1;
- `0xFFFD` (CS: `0x02`) — стирання виключно Bank 2.

#### Режим Б: Секторне стирання (Page/Sector Erase)

```
Крок 1 (Запит):
Хост:         [ 0x44 ] [ 0xBB ]
Bootloader:   [ 0x79 (ACK) ]

Крок 2 (Список секторів):
Хост:         [ N_MSB ] [ N_LSB ] [ SEC0_MSB ] [ SEC0_LSB ] ... [ SECk_MSB ] [ SECk_LSB ] [ XOR_CS ]
де:
  N = (кількість секторів для стирання - 1), 2 байти Big-Endian;
  SEC_i = 16-бітний номер сектора (0..65535);
  XOR_CS = N_MSB ^ N_LSB ^ SEC0_MSB ^ SEC0_LSB ^ ... ^ SECk_MSB ^ SECk_LSB.
Bootloader:   [ 0x79 (ACK) ] (після стирання зазначених секторів).
```

---

### 6. Команда Go (`0x21`)

Здійснює апаратний перехід (стрибок) за вказаною адресою:

```
Крок 1 (Запит):
Хост:         [ 0x21 ] [ 0xDE ]
Bootloader:   [ 0x79 (ACK) ]

Крок 2 (Адреса переходу):
Хост:         [ ADDR_3 ] [ ADDR_2 ] [ ADDR_1 ] [ ADDR_0 ] [ XOR_CS ]
де XOR_CS = ADDR_3 ^ ADDR_2 ^ ADDR_1 ^ ADDR_0
Bootloader:   [ 0x79 (ACK) ]
```

Одразу після надсилання байта `0x79 (ACK)` завантажувач деініціалізує свою периферію, завантажує значення головного покажчика стека (MSP) із комірки `ADDR` (`*(uint32_t*)ADDR`) і передає керування на вектор скидання `ADDR + 4` (`*(uint32_t*)(ADDR + 4)`).

---

### 7. Команди захисту: Readout Protect (`0x82`) та Readout Unprotect (`0x92`)

Команди керують станом бітів RDP (Read Protection) в енергонезалежних Option Bytes:

```
Readout Protect (Увімкнення RDP Level 1):
Хост:         [ 0x82 ] [ 0x7D ]
Bootloader:   [ 0x79 (ACK) ]
Bootloader:   [ 0x79 (ACK) ]  (після запису Option Bytes чип автоматично перезавантажується)

Readout Unprotect (Зняття RDP до Level 0):
Хост:         [ 0x92 ] [ 0x6D ]
Bootloader:   [ 0x79 (ACK) ]
Bootloader:   [ 0x79 (ACK) ]  (ініціюється масове апаратне стирання Flash, після чого — System Reset)
```

## Особливості реалізації на різних фізичних шинах

Командний набір залишається єдиним, проте транспортні рівні накладають власні специфічні вимоги на обмін байтами:

### 1. Послідовна шина I2C

- **Адресація на шині:** Завантажувач слухає 7-бітну апаратну адресу, зазвичай `0x52` (з бітом запису `0xA4`, з бітом читання `0xA5`) або `0x72` залежно від сімейства STM32.
- **Очікування готовності (Clock Stretching):** Коли мікроконтролер виконує фізичне стирання чи запис Flash-пам'яті, апаратний блок I2C утримує лінію `SCL` у нулі (Clock Stretching), призупиняючи хост до завершення внутрішньої операції. Якщо хост (наприклад, програмний Bit-Banging I2C) не підтримує Clock Stretching, зв'язок зірветься помилкою шини.
- **Читання відповідей:** Хост зобов'язаний згенерувати I2C START та надіслати адресу з бітом читання `(ADDR << 1) | 1`, після чого чип виставляє байти `ACK (0x79)` або `NACK (0x1F)`.

### 2. Послідовна шина SPI

- **Режим роботи:** SPI Slave, конфігурація `CPOL=0, CPHA=0` (Mode 0) або `CPOL=1, CPHA=1` (Mode 3), передача старшим бітом уперед (MSB First).
- **Вибірка чипа (NSS):** Лінія NSS має активно притискатися до землі на час кожної окремої транзакції та підніматися у високий рівень між блоками.
- **Проштовхування такту (Dummy Clocking):** Оскільки шина SPI є синхронною і тактується виключно хостом (Master), для вичитування кожного байта відповіді від завантажувача хост зобов'язаний надсилати пустий байт-заповнювач (`0x00` або `0xFF`), генеруючи тактові імпульси `SCK`.

### 3. Автомобільна та промислова шина CAN

- **Ідентифікатори кадрів:** Стандартний 11-бітний ідентифікатор (Standard ID). Хост передає кадри з ідентифікатором `0x079`, а завантажувач відповідає з ідентифікатором `0x078` (або `0x111` / `0x112` залежно від серії кристала).
- **Розмір пакета (DLC):** Довжина поля даних завжди фіксована або доповнюється до 8 байтів (`DLC = 8`).
- **Синхронізація:** Першим кадром від хоста є CAN-пакет із нульовим кодом команди або кадром ініціалізації для узгодження бітрейту (типово 125 кбіт/с, 250 кбіт/с або 500 кбіт/с).

### 4. Прямий інтерфейс USB DFU (Device Firmware Upgrade)

На чипах із вбудованим апаратним USB PHY (STM32F4, STM32F7, STM32G4 тощо) ROM-завантажувач реєструється на шині USB як стандартний DFU-пристрій класу Application-Specific (`Class 0xFE, SubClass 0x01`).

Замість прямої передачі опкодів `0x31` чи `0x44`, керування здійснюється через стандартні дескриптори керування endpoint 0:
- `DFU_DNLOAD` (wValue = BlockNum): завантаження блока прошивки в ОЗП чи Flash;
- `DFU_UPLOAD` (wValue = BlockNum): зчитування пам'яті;
- `DFU_GETSTATUS`: опитування стану скінченного автомата (стани `dfuIDLE`, `dfuDNLOAD-SYNC`, `dfuDNBUSY`, `dfuDNLOAD-IDLE`, `dfuERROR`);
- `DFU_CLRSTATUS`: скидання помилок після збою запису.

## Таймінги та критичні крайові випадки

1. **Таймаут відповіді на команду:** Завантажувач очікує прийому наступного байта аргументів не довше фіксованого вікна (від 100 мс до 1 с). Якщо хост обриває передачу посеред кадру адреси чи даних, завантажувач скидає внутрішній парсер і повертається у початковий стан очікування нового байта команди.
2. **Час стирання Flash (Flash Erase Time):** Команда Mass Erase на великих мікроконтролерах (наприклад, 2 МБ Flash у STM32F7/H7) може тривати від **2 до 15 секунд**. Хост зобов'язаний виставити таймаут очікування `ACK` для команди `0x44` не менше 20–30 секунд, не вважаючи затримку апаратним зависанням.
3. **Обмеження розміру пакета:** Максимальний розмір корисних даних для команди `0x31 (Write Memory)` становить рівно **256 байтів** (`N = 0xFF`). Передача більшої кількості призводить до переповнення внутрішнього буфера SRAM завантажувача і негайного повернення `NACK`.
4. **Вирівнювання пам'яті:** Спроба запису непарної кількості байтів у контролери з 32-бітною або 64-бітною шириною шини Flash (наприклад, STM32G0/G4/L4 з подвійним словом 64 біти) вимагає доповнення буфера байтами `0xFF` до кратності 8 байтів, інакше внутрішній контролер пам'яті генерує помилку `PGAERR` (Programming Alignment Error).
