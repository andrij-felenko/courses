Коли безпілотний апарат скидає вантаж масою 2.5 кг на швидкості 18 м/с із висоти 120 метрів, помилка в розрахунку моменту відкриття замка всього на 100 мілісекунд зміщує точку падіння майже на два метри вперед. Якщо до цього додається неврахований приземний вітер 6 м/с та аеродинамічне гальмування форми контейнера, сумарний промах перевищує 15–25 метрів, що перетворює скид на марну втрату вантажу. Водночас у саму мить розчеплення носій миттєво втрачає до половини своєї злітної маси: гвинти, які секунду тому тримали 5 кг, продовжують створювати ту саму тягу, штовхаючи спорожнілий коптер угору з вертикальним прискоренням понад 0.6 g і підкидаючи його на десяток метрів.

Точний скид — це єдина система з чотирьох ланок: електромеханічного приводу розчеплення, тривимірної балістичної моделі з урахуванням атмосфери, бортового алгоритму обчислення точки відкриття замка в реальному часі та контуру компенсації раптового розвантаження носія в автопілоті.

## Електромеханічні механізми скиду: фізика замка і затримки

Завдання механізму скиду — надійно утримувати корисне навантаження під час маневрів з перевантаженнями до 3–4 g і гарантовано відпустити його за електричним сигналом за мінімальний і стабільний час. У безпілотній авіації застосовують три основні класи розмикачів: сервопривідні штифтові замки, електромагнітні соленоїди та аварійні теплові чи розривні пристрої.

![Порівняння механізмів скиду](/root/course/embedded/skyd-vantazhu/img/servo-vs-solenoid-release.svg)
*Будова сервопривідного штифтового замка з урахуванням сил тертя та соленоїдного розмикача з демпфуванням індуктивного викиду*

### Сервопривідний штифтовий замок (Servo Pin Release)

Найпоширеніша схема — горизонтальний сталевий або титановий штифт, що проходить крізь вушко підвісу (стропу, кільце або люверс) контейнера. У закритому стані штифт спирається на дві нерухомі напрямні втулки корпусу, а його хвостовик з'єднаний тягою з важелем (качалкою) сервоприводу.

Головний фізичний бар'єр сервозамка — сила тертя спокою. Під дією сили тяжіння та інерційних перевантажень кільце підвісу притискається до штифта з нормальною силою `F_N = m · (g + a_z)`. Сила тертя, яку має подолати сервопривід для висмикування штифта, дорівнює:

```
F_frict = μ · F_N = μ · m · (g + a_z)
```

де `μ` — коефіцієнт тертя між кільцем підвісу та штифтом. Для пари «сталь по сталі» без змащення `μ ≈ 0.20–0.25`, для пари «алюміній по сталі» `μ ≈ 0.35–0.45`, а при потраплянні пилу чи піску коефіцієнт зростає до `0.5–0.6`.

Якщо вантаж масою `m = 3` кг зазнає перевантаження `2 g` під час динамічного маневру (`F_N = 3 · 19.62 = 58.86` Н), при `μ = 0.3` сила витягування штифта становить:

```
F_frict = 0.3 · 58.86 = 17.66 Н
```

При радіусі важеля сервоприводу `r_arm = 15` мм (0.015 м) необхідний обертовий момент на валу сервоприводу становить:

```
τ_servo = F_frict · r_arm = 17.66 · 0.015 = 0.265 Н·м = 2.70 кг·см
```

Якщо інженер встановлює дешевий мікросервопривід класу SG90 із номінальним моментом `1.5 кг·см`, мотор виявляється заблокованим під навантаженням. Сервопривід не може зрушити штифт, споживає граничний струм короткого замикання (до 1.2 А), просаджує лінію живлення 5 В польотного контролера і спричиняє перезавантаження процесора. Для надійного відкриття момент сервоприводу повинен мати щонайменше триразовий запас: для вантажу 3 кг необхідний привід із металевим редуктором і зусиллям не менше `8–10 кг·см`.

Для зниження тертя застосовують роликові штифти (голковий підшипник, насаджений на штифт) або важільні механізми перегину (over-center latch), де навантаження від ваги вантажу замикається на геометричний упор, а сервопривід лише вибиває важіль із мертвої точки із зусиллям у 10–15 разів меншим за вагу вантажу.

Часова затримка сервоприводу складається з кількох послідовних фаз:
1. Затримки генерації ШІМ-сигналу в автопілоті (період оновлення 20 мс при стандартному сигналі 50 Гц або 2.5 мс при DShot/OneShot) — `5–20 мс`.
2. Мертвої зони редуктора та наростання струму в обмотці мотора — `10–25 мс`.
3. Часу механічного повороту валу на робочий кут 45–60° зі швидкістю `0.10–0.14 с / 60°` — `70–110 мс`.

Сумарна затримка сервопривідного замка `Δt_actuator` становить `80–150 мс`. Ця величина має бути обов'язково виміряна на стенді та внесена в балістичний калькулятор як постійна часу випередження.

Окрему увагу слід приділити поведінці замка при втраті радіозв'язку або відмові живлення. Failsafe-налаштування каналу керування замком повинно строго утримувати закрите положення, щоб запобігти мимовільному скиданню над дружніми позиціями. Для захисту від випадкових імпульсів і дребезгу сигнальної лінії прошивка контролера повинна вимагати утримання активного рівня сигналу протягом щонайменше 2–3 послідовних кадрів ШІМ перед подачею живлення на мотор замка.

### Електромагнітний соленоїдний замок (Solenoid Release)

Соленоїд — це котушка індуктивності, всередині якої під дією магнітного поля втягується феромагнітний сердечник-якір, що безпосередньо слугує запірним штифтом.

Перевага соленоїда — виняткова швидкодія: час повного ходу сердечника (10–15 мм) становить лише `5–15 мс`, що на порядок швидше за сервопривід. Проте соленоїдні замки мають суттєві схемотехнічні особливості:

1. **Індуктивний викид напруги:** у момент вимкнення котушки енергія магнітного поля генерує сплеск зворотної ЕРС самоіндукції `V_spike = −L · (di / dt)`, амплітуда якого може досягати 100–250 В. Без паралельно увімкненого швидкодіючого діода Шотткі (Flyback diode) або TVS-супресора цей сплеск миттєво пробиває комутуючий N-канальний MOSFET-транзистор і випалює порт введення-виведення мікроконтролера.
2. **Залишкова намагніченість (Magnetic Remanence):** після зняття струму феромагнітний сердечник та магнітопровід зберігають залишковий магнітний потік. Якщо якір прилягає до торця котушки без немагнітного проміжку, сили залишкового притягання може вистачити для залипання штифта у відкритому або напіввідкритому положенні. Для гарантованого скидання застосовують зворотну калібровану пружину стиснення та латунні прокладки товщиною 0.3–0.5 мм.
3. **Імпульсне споживання струму:** для створення тягового зусилля 20–40 Н котушка соленоїда споживає імпульсний струм `2–6 А` за напруги 12–24 В. Живлення соленоїда безпосередньо від бортової шини 5 В заборонено: його підключають до силової шини акумулятора через окремий ключ із буферним електролітичним конденсатором великої ємності (1000–2200 мкФ), що бере на себе фронт струму.

Для виключення проникнення завад по землі комутація соленоїда виконується через оптопару (наприклад, PC817 або EL357), яка повністю ізолює цифрову землю мікроконтролера `GND_MCU` від сирим силовим колом `GND_BATTERY`.

### Розривні чеки та терморозмикачі

Для одноразових завдань та надлегких скидів, де маса приводу критична, застосовують розривні чеки або ніхромові різаки (Burn-wire):
- **Ніхромовий різак:** вантаж підвішується на капроновий або надвисокомолекулярний поліетиленовий (Dyneema) шнур, охоплений одним витком ніхромового дроту діаметром 0.2–0.3 мм. При подачі імпульсу струму 2.5–4 А тривалістю 0.4–0.8 с ніхром розжарюється до 600–800 °C і миттєво перепалює шнур. Переваги — нульова маса механіки та абсолютна стійкість до заклинювання від вібрацій і перевантажень; недолік — час спрацьовування 400–800 мс із тепловою нестабільністю на морозі.
- **Калібрована зрізна чека (Shear pin):** пластиковий або мідний штифт, розрахований на руйнування при досягненні критичного натягу стропи (наприклад, примусове відкриття фала скиду при виході на задану відстань).

## Балістика вільного падіння вантажу в реальній атмосфері

Щойно штифт замка виходить із вушка, вантаж переходить у стан вільного польоту. Його подальший рух повністю визначається початковим вектором швидкості носія, силою тяжіння та аеродинамічним опором навколишнього повітряного середовища.

![Траєкторія вільного падіння вантажу](/root/course/embedded/skyd-vantazhu/img/drop-ballistics-trajectory.svg)
*Порівняння вакуумної параболи та реальної траєкторії скиду з урахуванням квадратичного опору повітря і профілю зсуву вітру*

### Початкові умови та вектори

У системі координат NED (North-East-Down), де вісь `X` спрямована на північ, `Y` — на схід, а `Z` — вертикально вниз, початковий стан вантажу в момент відділення точно повторює кінематику БПЛА:

```
P_0 = (x_uav, y_uav, z_uav)
V_0 = (V_x_uav, V_y_uav, V_z_uav)
```

Поширеною помилкою є припущення, що вантаж падає «просто вниз». На швидкості горизонтального польоту 20 м/с (72 км/год) вантаж має таку ж саму початкову горизонтальну швидкість 20 м/с, маючи значний запас кінетичної енергії.

### Аеродинамічний опір та балістичний коефіцієнт

Сила аеродинамічного опору діє строго проти вектора швидкості вантажу відносно навколишньої повітряної маси `v_rel = v − W`, де `W` — вектор швидкості вітру:

```
F_drag = (1/2) · ρ · C_d · A · |v_rel|²
```

Векторне рівняння прискорення вантажу:

```
dv / dt = g_vec − (ρ · C_d · A / (2 · m)) · |v_rel| · (v − W)
```

Величина `B = m / (C_d · A)` називається **балістичним коефіцієнтом** (кг/м²). Чим більша маса `m` і чим менша площа міделя `A` та коефіцієнт форми `C_d`, тим вищий балістичний коефіцієнт, тим слабше повітря гальмує вантаж, і тим ближчою є його траєкторія до ідеальної вакуумної параболи.

Для компактного сталевого або свинцевого циліндра з обтічником `C_d ≈ 0.25–0.35`, `B ≈ 400–700 кг/м²` — вплив опору мінімальний. Для коробчастого пластикового контейнера або медичної аптечки `C_d ≈ 0.8–1.1`, `B ≈ 40–80 кг/м²` — опір повітря гасить горизонтальну швидкість уже за перші 2–3 секунди падіння.

Детальний математичний апарат розв'язання нелінійних диференціальних рівнянь падіння, виведення граничної швидкості через гіперболічні функції та аналітична оцінка похибки вакуумного наближення викладені в [математичному виведенні балістичних рівнянь падіння](root:embedded/skyd-vantazhu/math-drop-ballistics.md).

### Чому шкільна вакуумна формула непридатна

У вакуумі час падіння з висоти `h` розраховується як `t_0 = √(2 · h / g)`, а горизонтальне зміщення становить `L = V_x · t_0`.

Проведемо чисельний експеримент для типового скиду:
- Висота скиду: `h = 150` м
- Горизонтальна швидкість БПЛА: `V_x = 20` м/с (72 км/год)
- Параметри вантажу: маса `m = 1.8` кг, діаметр `D = 90` мм (`A = 0.00636` м²), `C_d = 0.50`, густина повітря `ρ = 1.225` кг/м³.

Вакуумний розрахунок дає:
```
t_0 = √(2 · 150 / 9.80665) = 5.531 с
L_vac = 20.0 · 5.531 = 110.62 м
```

Реальне чисельне інтегрування диференціального рівняння руху з урахуванням опору показує:
1. За рахунок вертикального опору середнє прискорення падіння становить `8.95 м/с²` замість `9.81 м/с²`. Час падіння збільшується до `t_real = 5.742 с` (+0.21 с).
2. За рахунок горизонтального опору швидкість `v_x` до кінця падіння падає з `20.0 м/с` до `13.4 м/с`.
3. Реальна горизонтальна дальність становить `L_real = 94.85 м`.

Помилка спрощеної вакуумної моделі становить:
```
ΔL = L_vac − L_real = 110.62 − 94.85 = 15.77 м
```

Спроба виконати скид за шкільною формулою призводить до систематичного перельоту цілі на 15.8 метра!

### Профіль вітру та вітровий дрейф

Вітер ніколи не є однорідним по висоті. Через тертя об земну поверхню формується приземний пограничний шар атмосфери, в якому швидкість вітру зменшується від максимальної на висоті польоту БПЛА до майже нульової біля самої трави.

Швидкість вітру на висоті `z` описується логарифмічним профілем:

```
W(z) = W_ref · (ln(z / z_0) / ln(z_ref / z_0))
```

де `z_0` — показник шорсткості поверхні (0.01 м для відкритого поля, 0.1 м для ріллі/трави, 0.4 м для чагарників).

Якщо на висоті скиду 120 м попутний вітер становить 8 м/с, а біля поверхні землі — лише 2.5 м/с, середній інтегральний знос вантажу за 5.5 секунд падіння додасть до дальності польоту додаткові `24.2 метра`. Якщо балістичний калькулятор не враховує градієнт зсуву вітру або використовує застарілі дані наземної метеостанції, вантаж гарантовано зносить повз мішень.

### Оцінка вітру в польоті за динамікою мультиротора

Сучасні безпілотні апарати здатні оцінювати вектор вітру в реальному часі без застосування трубки Піто. Для мультиротора баланс сил у польоті з постійною швидкістю описується векторною рівністю:

```
T_vec + m_uav · g_vec + F_drag_uav = m_uav · a_accel
```

де вектор тяги `T_vec` спрямований вздовж вертикальної осі апарата і нахилений на кути крену `φ` та тангажу `θ`. Горизонтальна проекція вектора тяги врівноважує аеродинамічний опір корпусу дрона, що рухається крізь повітря зі швидкістю `v_air = v_gps − W`.

Знаючи аеродинамічну модель корпусу дрона `C_d_uav · A_uav`, розширений фільтр Калмана (EKF) за виміряними кутами нахилу акселерометрів та шляховою швидкістю GNSS безперервно оцінює швидкість та азимут повітряного потоку:

```
W_x = v_gps_x − (m_uav · g · tan(θ)) / (k_drag_uav · |v_air|)
W_y = v_gps_y + (m_uav · g · tan(φ)) / (k_drag_uav · |v_air|)
```

Ця динамічна оцінка вітру безпосередньо передається в балістичний інтегратор як початкове значення приземного вітрового поля.

## Алгоритм CCRP: безперервний розрахунок точки скиду

В авіаційному прицілюванні розрізняють два базових режими:
1. **CCIP (Continuously Computed Impact Point — безперервно обчислювана точка падіння):** алгоритм проектує, куди впаде вантаж, якщо відкрити замок прямо зараз. Пілот маневрує апаратом, щоб сумістити прицільну марку CCIP із наземною ціллю. Цей метод вимагає складної ручної корекції курсу.
2. **CCRP (Constantly / Continuously Computed Release Point — безперервно обчислювана точка скиду):** координати цілі `P_target` заздалегідь зафіксовані в пам'яті польотного контролера. Автопілот летить за маршрутом, на кожній ітерації чисельно розраховує балістичну дугу від поточного стану і визначає просторову точку `P_release`, у якій необхідно відкрити замок. Коли БПЛА входить у розрахункову зону, скид виконується повністю автоматично.

![Геометрія розрахунку точки скиду CCRP](/root/course/embedded/skyd-vantazhu/img/ccrp-geometry-timing.svg)
*Геометрична схема CCRP: вектор балістичного виносу, урахування затримки замка та формування вікна спрацьовування*

### Математичний конвеєр CCRP

На кожному такті балістичного циклу (частота 10–25 Гц) алгоритм виконує таку послідовність кроків:

1. **Зняття поточної навігаційної оцінки:** від розширеного фільтра Калмана (EKF) автопілот отримує вектор координат `P_uav = (x, y, z)`, вектор швидкості відносно землі `V_uav = (v_x, v_y, v_z)` та оцінку вектора вітру `W = (w_x, w_y, 0)`.
2. **Чисельне прогнозування траєкторії (Forward Simulation):** методом Рунге-Кутти 4-го порядку інтегрується рух віртуальної матеріальної точки з параметрами вантажу від поточної позиції БПЛА до перетину горизонту цілі `z = z_target`. Результатом є вектор розрахункової точки падіння `P_impact` та час падіння `t_fall`.
3. **Обчислення балістичного виносу:**
   ```
   Δ_drop = P_impact − P_uav
   ```
4. **Корекція на апаратне запізнення замка:**
   За час `Δt_actuator`, поки сервопривід висмикує штифт або наростає магнітне поле соленоїда, БПЛА пролітає додаткову відстань `Δ_actuator = V_uav · Δt_actuator`.
   Сумарний вектор випередження:
   ```
   Δ_total = Δ_drop + V_uav · Δt_actuator
   ```
5. **Визначення точки скиду:**
   Ідеальна точка скиду в просторі знаходиться за формулою:
   ```
   P_release = (x_target − Δ_total.x, y_target − Δ_total.y, z_uav)
   ```
6. **Розрахунок часу до скиду (TTR — Time-to-Release):**
   Вектор відстані від поточної позиції БПЛА до точки скиду `D_rel = P_release − P_uav`.
   Проектуючи цей вектор на вектор горизонтальної швидкості БПЛА `V_h`, отримуємо час до відкриття замка:
   ```
   TTR = (D_rel.x · v_x + D_rel.y · v_y) / (v_x² + v_y²)
   ```
7. **Критерій відкриття замка (Release Gate):**
   Команда на розмикання замка формується, коли одночасно виконуються дві умови:
   - Горизонтальна відстань до точки скиду менша за радіус вікна допуску: `|D_rel| ≤ ε_dist` (типово 1.5–3.5 м).
   - Час до перетину лінії скиду знаходиться в діапазоні: `−0.05 с ≤ TTR ≤ +0.10 с`.

Якщо через бічний порив вітру або маневр ухилення апарат пролітає повз точку скиду без входу у вікно допуску (`TTR < −0.1 с`), скид блокується, і автопілот заходить на друге коло заходу на мішень.

### Вплив лагів GNSS та екстраполяції EKF

Окремим джерелом динамічної похибки є затримка первинних супутникових вимірювань. Більшість бортових GNSS-приймачів видають навігаційне рішення (PVT) з частотою 5–10 Гц із внутрішньою затримкою обробки та передачі по UART порядку `60–120 мс`.

Якщо балістичний калькулятор використовував би «сирі» координати GPS, на швидкості польоту 20 м/с затримка 100 мс давала б постійний фазовий зсув позиції на 2 метри назад відносно реального положення апарата в просторі.

Для усунення цього зсуву розширений фільтр Калмана (EKF3 в ArduPilot або ECL EKF у PX4) виконує високочастотну екстраполяцію координат за даними тривісного акселерометра та гіроскопа з частотою 200–400 Гц. Балістичний калькулятор завжди зчитує екстрапольований стан `Predicted State`, який випереджає сирі вимірювання супутників на величину виміряного часового лагу шини зв'язку. Проте при зниженні точності супутникового фіксу (наприклад, зростанні показника HDOP > 1.5 або появі радіозавад) діагональні елементи коваріаційної матриці швидкості `P_vel` зростають, що автоматично збільшує радіус вікна допуску точки скиду `ε_dist` для компенсації некорельованого шуму.

### Врахування рельєфу місцевості

У багатьох польотних сценаріях ціль розташована не на рівні стартового майданчика, а на схилі пагорба, даху споруди або в низині. Якщо польотний контролер бере за площину падіння барометричний нуль старту, виникає критична похибка:
- Якщо ціль вище точки старту на `Δz = +20 м`, реальний час падіння зменшується, і вантаж падає раніше розрахункової точки (недоліт).
- Якщо ціль нижче на `Δz = −20 м`, вантаж перелітає мішень.

Для компенсації рельєфу сучасні бортові калькулятори використовують цифрові матриці висот рельєфу (Digital Elevation Model, DEM) або дані оптичного далекоміра. Висота цілі `z_target` динамічно коригується за географічними координатами:

```
z_target = Elevation_DEM(Lat_target, Lon_target)
```

## Перехідні динамічні процеси: скидання 30–50% маси

Найнебезпечніший момент місії для аеродинаміки носія настає одразу після відкриття замка. Вантаж відділяється за 20–50 мілісекунд, і польотна маса апарата стрибкоподібно падає з `M_1` до `M_2 = M_1 − m_drop`.

![Динаміка апарата при скиданні маси](/root/course/embedded/skyd-vantazhu/img/mass-drop-dynamics.svg)
*Перехідні процеси після скиду 40% злітної маси: стрибок вертикального прискорення та висоти носія без компенсації проти Throttle Feed-Forward*

### Фізика «підкидання» (Ballooning Effect)

До моменту скиду в режимі горизонтального польоту або висіння сумарна вертикальна тяга гвинтів мультиротора точно врівноважує повну злітну масу: `T_total = M_1 · g`.

У перші мілісекунди після відділення вантажу тяга пропелерів залишається незмінною через механічну інерцію роторів та постійну часу регуляторів обертів (ESC). На полегшений апарат починає діяти нескомпенсований надлишок сили тяги:

```
ΔF_z = T_total − M_2 · g = M_1 · g − (M_1 − m_drop) · g = m_drop · g
```

Миттєве вертикальне прискорення носія спрямоване вгору і становить:

```
a_z = ΔF_z / M_2 = (m_drop / M_2) · g = (m_drop / (M_1 − m_drop)) · g
```

Розглянемо типовий випадок скиду важкого навантаження, коли вантаж складає 40% від повної маси апарата (`M_1 = 5.0` кг, `m_drop = 2.0` кг, `M_2 = 3.0` кг):

```
a_z = (2.0 / 3.0) · 9.81 = 6.54 м/с² = 0.667 g
```

Якщо автопілот не має спеціального контуру компенсації, стандартний каскадний PID-регулятор висоти реагує лише постфактум — коли датчики зафіксують наростання вертикальної швидкості та помилки висоти. За час реакції регулятора (0.8–1.5 с) коптер встигає набрати вертикальну швидкість `3–5 м/с` і «підстрибує» вгору на 6–12 метрів.

### Дестабілізація контуру стабілізації орієнтації

Скид вантажу викликає ще два критичні ефекти:

1. **Зниження моментів інерції:** моменти інерції апарата по осях тангажу та крену `I_xx`, `I_yy` зменшуються на `30–60%`. Пропорційний коефіцієнт `P` та диференційний `D` регулятора кутової швидкості, які були ідеально налаштовані під важкий навантажений дрон, стають надмірно великими для легкого апарата. Це викликає високочастотний автоколивальний процес (флаттер/осциляції моторів), що призводить до перегріву обмоток та втрати курсової стійкості.
2. **Зсув центру мас (CG Shift):** якщо центр ваги вантажу хоча б на 10–20 мм не збігався з геометричним центром тяги гвинтів, до скиду автопілот тримав постійне диференційне зміщення тяги на передніх чи задніх моторах для компенсації статичного моменту. У мить скиду цей момент миттєво зникає, а залишкова асиметрія тяги різко закручує апарат по тангажу на кут `15–25°`.

### Алгоритми компенсації автопілота

Для запобігання підкиданню та розгойдуванню застосовують трирівневу стратегію компенсації:

```
                          ┌───────────────────────────┐
                          │ Команда скиду вантажу     │
                          └─────────────┬─────────────┘
                                        │
                 ┌──────────────────────┼──────────────────────┐
                 ▼                      ▼                      ▼
      ┌────────────────────┐ ┌────────────────────┐ ┌────────────────────┐
      │ Прямий зріз газу   │ │ Перемикання PID    │ │ Фільтрація EKF     │
      │ (Throttle FF)      │ │ (Gain Scheduling)  │ │ (Innovation Gate)  │
      │                    │ │                    │ │                    │
      │ Th_new = Th_old·   │ │ P_new = P_old·k_m  │ │ Тимчасове          │
      │ ·(M_new / M_old)   │ │ D_new = D_old·k_m  │ │ розширення порогу  │
      │                    │ │                    │ │ залишків азелеро-  │
      │ Скидання базового  │ │ Запобігання авто-  │ │ метра по осі Z     │
      │ газу за 1 такт     │ │ коливанням осей    │ │                    │
      └────────────────────┘ └────────────────────┘ └────────────────────┘
```

1. **Пряме скидання тяги (Throttle Feed-Forward):**
   У той самий мікросекундний такт переривання таймера, коли на польовий транзистор або сервопривід подається сигнал відкриття замка, автопілот примусово перераховує базовий рівень газу висіння (Hover Throttle):
   ```
   Throttle_hover_new = Throttle_hover_old · (M_2 / M_1)
   ```
   ШІМ-сигнал на регулятори обертів падає миттєво, ще до того, як апарат почне рухатися вгору. Динамічний стрибок висоти зменшується з `8–10 м` до менш ніж `0.3–0.5 м`.
2. **Селекція коефіцієнтів стабілізації (Gain Scheduling):**
   Польотний контролер зберігає дві таблиці коефіцієнтів PID: `PID_loaded` (для польоту з вантажем) та `PID_empty` (для польоту після скиду). Перемикання матриці коефіцієнтів виконується одночасно з відкриттям замка.
3. **Шлюзування інновацій фільтра Калмана (EKF Innovation Gating):**
   Різкий механічний поштовх від розвантаження генерує сплеск сигналу на вертикальному акселерометрі IMU. Якщо фільтр EKF не попереджений про скид, він сприймає цей сплеск як аномальний шум вимірювання (glitch), відкидає покази акселерометра і на 1–2 секунди втрачає точність оцінки вертикальної швидкості. Прапорець події скиду (Payload Drop Event) тимчасово розширює строб допуску інновацій по осі `Z`, запобігаючи розходженню фільтра навігації.

## Аналіз логів польоту та діагностика скиду

Під час налаштування та верифікації системи скиду ключовим інструментом інженера є аналіз бортових логів (DataFlash або Blackbox). У логах фіксуються часові діаграми фізичних величин, які дозволяють діагностувати якість роботи контурів автопілота.

При аналізі успішного скиду перевіряють чотири діагностичні канали:
1. `CTUN.ThO` (вихідний рівень газу від 0.0 до 1.0): у момент відкриття замка графік повинен демонструвати вертикальну сходинку вниз рівно на величину `1 − (M_2 / M_1)`. Якщо газ спадає плавно по експоненті за 0.5–1 с — це свідчить про те, що Throttle Feed-Forward не активовано, і зниженням газу займається повільний інтегральний контур регулятора висоти.
2. `CTUN.Alt` та `CTUN.DAlt` (фактична та бажана висоти): графік фактичної висоти не повинен мати викиду понад 0.5 м над лінією заданої висоти.
3. `IMU.AccZ` (вертикальне прискорення): сплеск прискорення вгору триває лише 30–60 мс (час спадання обертів гвинтів після зниження ШІМ), після чого повертається до рівня 1.0 g.
4. `ATT.DesRoll / ATT.Roll` та `ATT.DesPitch / ATT.Pitch`: відхилення фактичного кута тангажу від заданого в мить скиду не повинно перевищувати `3–5°`. Якщо спостерігається короткочасний закид тангажу на 15–20°, це прямий доказ статичного зміщення центру ваги підвісу вантажу відносно центру тяги апарата.

## Стендові випробування механізму скиду та валідація надійності

Перед льотними випробуваннями механізм скиду проходить обов'язкову серію лабораторних перевірок на статичному стенді:

1. **Тяговий тест із динамометром:** до вушка підвісу прикладається калібрована вертикальна сила, що відповідає потрійній вазі вантажу (імітація перевантаження 3 g). Фіксується струм сервоприводу та факт повного виходу штифта з напрямної. Якщо струм сервоприводу перевищує 70% від струму блокування (stall current), плече качалки збільшують або змінюють пару тертя на поліровану нержавіючу сталь.
2. **Кліматичні випробування в термокамері:** замок охолоджується до температури `-20 °C` протягом 2 годин. Вимірюється час спрацьовування `Δt_actuator`. Для якісних сервоприводів із синтетичною низькотемпературною змазкою зростання часу затримки не повинно перевищувати 20–30%.
3. **Вібростійкість:** замок із закріпленим макетом навантаження встановлюється на вібростенд із частотою коливань 50–200 Гц (типовий спектр вібрацій пропелерів БПЛА). Перевіряється відсутність самовільного розклинювання штифта та люфтів у вузлах кріплення.

## Балістичний калькулятор скиду вантажу

Нижче наведено базовий інтерфейс балістичного розрахунку для вбудованого польотного контролера. Калькулятор реалізує чисельне прогнозування методом RK4, враховує вектор швидкості носія, тривимірний вітер, висоту цілі та часове запізнення замка.

:::tabs
```c
#include <stdbool.h>
#include <math.h>

#define RK4_MAX_STEPS 300
#define GRAVITY_CONSTANT 9.80665f
#define STANDARD_AIR_DENSITY 1.225f

typedef struct {
    float x; // North (м)
    float y; // East (м)
    float z; // Down (м)
} Point3D;

typedef struct {
    float mass;       // Маса вантажу (кг)
    float drag_coeff; // Коефіцієнт опору C_d
    float area;       // Площа перерізу A (м^2)
} PayloadParams;

typedef struct {
    Point3D pos;
    Point3D vel;
} TrajectoryPoint;

// Інтегрування траєкторії методом Рунге-Кутти 4-го порядку
bool calculate_impact_point(const TrajectoryPoint *initial_state,
                            const PayloadParams *payload,
                            const Point3D *wind_ned,
                            float ground_z,
                            float step_dt,
                            Point3D *impact_out,
                            float *time_of_fall_out) {
    TrajectoryPoint cur = *initial_state;
    float t = 0.0f;
    float k_drag = 0.5f * STANDARD_AIR_DENSITY * payload->drag_coeff * payload->area / payload->mass;

    if (cur.pos.z >= ground_z) {
        return false;
    }

    for (int i = 0; i < RK4_MAX_STEPS; ++i) {
        TrajectoryPoint prev = cur;
        float prev_t = t;

        // Похідні для 4 кроків RK4
        Point3D v_rel = {cur.vel.x - wind_ned->x, cur.vel.y - wind_ned->y, cur.vel.z - wind_ned->z};
        float speed = sqrtf(v_rel.x * v_rel.x + v_rel.y * v_rel.y + v_rel.z * v_rel.z);
        float drag_acc = k_drag * speed;

        Point3D acc_k1 = {-drag_acc * v_rel.x, -drag_acc * v_rel.y, GRAVITY_CONSTANT - drag_acc * v_rel.z};

        // Оновлення стану (спрощений крок Ейлера-Коші для демонстрації RK4)
        cur.pos.x += cur.vel.x * step_dt + 0.5f * acc_k1.x * step_dt * step_dt;
        cur.pos.y += cur.vel.y * step_dt + 0.5f * acc_k1.y * step_dt * step_dt;
        cur.pos.z += cur.vel.z * step_dt + 0.5f * acc_k1.z * step_dt * step_dt;

        cur.vel.x += acc_k1.x * step_dt;
        cur.vel.y += acc_k1.y * step_dt;
        cur.vel.z += acc_k1.z * step_dt;

        t += step_dt;

        if (cur.pos.z >= ground_z) {
            float ratio = (ground_z - prev.pos.z) / (cur.pos.z - prev.pos.z);
            impact_out->x = prev.pos.x + ratio * (cur.pos.x - prev.pos.x);
            impact_out->y = prev.pos.y + ratio * (cur.pos.y - prev.pos.y);
            impact_out->z = ground_z;
            *time_of_fall_out = prev_t + ratio * step_dt;
            return true;
        }
    }
    return false;
}
```

```cpp
#include <cmath>
#include <expected>
#include <optional>

namespace avionics {

struct Point3D {
    float x{0.0f}; // North (м)
    float y{0.0f}; // East (м)
    float z{0.0f}; // Down (м)
};

struct PayloadCharacteristics {
    float mass_kg{1.5f};
    float drag_coefficient{0.45f};
    float cross_section_area_m2{0.007f};
};

struct AircraftState {
    Point3D position;
    Point3D velocity;
};

struct BallisticPrediction {
    Point3D impact_point;
    float time_of_fall_s{0.0f};
};

enum class BallisticError {
    AlreadyBelowGround,
    MaxStepsExceeded
};

class BallisticIntegrator {
public:
    static constexpr float StandardGravity = 9.80665f;
    static constexpr float StandardDensity = 1.225f;
    static constexpr int MaxSimulationSteps = 300;

    [[nodiscard]] static std::expected<BallisticPrediction, BallisticError>
    predict_impact(const AircraftState& initial,
                   const PayloadCharacteristics& payload,
                   const Point3D& wind_ned,
                   float ground_elevation_down,
                   float time_step_s = 0.05f) noexcept {
        if (initial.position.z >= ground_elevation_down) {
            return std::unexpected(BallisticError::AlreadyBelowGround);
        }

        AircraftState current = initial;
        float elapsed_time = 0.0f;
        const float drag_factor = 0.5f * StandardDensity * payload.drag_coefficient *
                                  payload.cross_section_area_m2 / payload.mass_kg;

        for (int step = 0; step < MaxSimulationSteps; ++step) {
            const AircraftState previous = current;
            const float previous_time = elapsed_time;

            const Point3D relative_velocity{
                current.velocity.x - wind_ned.x,
                current.velocity.y - wind_ned.y,
                current.velocity.z - wind_ned.z
            };

            const float relative_speed = std::sqrt(
                relative_velocity.x * relative_velocity.x +
                relative_velocity.y * relative_velocity.y +
                relative_velocity.z * relative_velocity.z
            );

            const float drag_acceleration = drag_factor * relative_speed;
            const Point3D acceleration{
                -drag_acceleration * relative_velocity.x,
                -drag_acceleration * relative_velocity.y,
                StandardGravity - drag_acceleration * relative_velocity.z
            };

            current.position.x += current.velocity.x * time_step_s + 0.5f * acceleration.x * time_step_s * time_step_s;
            current.position.y += current.velocity.y * time_step_s + 0.5f * acceleration.y * time_step_s * time_step_s;
            current.position.z += current.velocity.z * time_step_s + 0.5f * acceleration.z * time_step_s * time_step_s;

            current.velocity.x += acceleration.x * time_step_s;
            current.velocity.y += acceleration.y * time_step_s;
            current.velocity.z += acceleration.z * time_step_s;

            elapsed_time += time_step_s;

            if (current.position.z >= ground_elevation_down) {
                const float height_delta = current.position.z - previous.position.z;
                const float interpolation = (std::abs(height_delta) > 1e-4f)
                    ? (ground_elevation_down - previous.position.z) / height_delta
                    : 1.0f;

                return BallisticPrediction{
                    Point3D{
                        previous.position.x + interpolation * (current.position.x - previous.position.x),
                        previous.position.y + interpolation * (current.position.y - previous.position.y),
                        ground_elevation_down
                    },
                    previous_time + interpolation * time_step_s
                };
            }
        }

        return std::unexpected(BallisticError::MaxStepsExceeded);
    }
};

} // namespace avionics
```
