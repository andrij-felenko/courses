# Математика експоненційного відкату та джиттеру

Коли тисячі автономних пристроїв одночасно втрачають зв'язок через перезавантаження базової станції або короткочасне зникнення живлення на вишці, спроба відновити з'єднання за фіксованим розкладом створює катастрофічну лавину запитів *(thundering herd problem)*. У стільникових мережах стандарту LTE-M та NB-IoT це призводить до миттєвого колапсу каналу випадкового доступу *(RACH, Random Access Channel)*: пристрої займають однакові часові слоти преамбул, виникають колізії, жоден пакет не доходить, а вузли повторюють спроби знову і знову, висаджуючи акумулятори за лічені години.

Щоб розвести пристрої в часі та відновити пропускну здатність мережі, використовують усічений експоненційний відкат *(Truncated Binary Exponential Backoff)* із рандомізацією часових інтервалів — джиттером *(jitter)*. Тут наведено строгий математичний розрахунок імовірності колізій, порівняння трьох ключових моделей внесення випадковості та виведення оптимальних параметрів очікування для вбудованих пристроїв.

## Модель каналу випадкового доступу (RACH) та ймовірність колізій

У стільниковій мережі процедура приєднання починається з відправки випадково обраної преамбули у доступному слоті RACH. Нехай у кожному слоті тривалістю `T_slot` доступно `M` ортогональних преамбул (типово `M = 64` для LTE або `M = 16..48` для NB-IoT). Якщо `N` пристроїв одночасно намагаються надіслати преамбулу в один і той самий слот, вибір кожним вузлом значення `m ∈ {1, 2, ..., M}` є незалежною рівномірною випадковою величиною.

Ймовірність того, що конкретний пристрій вибере унікальну преамбулу (яку не вибрав жоден із решти `N - 1` пристроїв), описується біноміальним розподілом:

```
P_single = (1 - 1/M)^(N - 1)                  [ймовірність, що інші N-1 пристроїв не обрали преамбулу]
```

Очікувана кількість успішно прийнятих преамбул `S` (пропускна здатність слота) дорівнює добутку кількості пристроїв на ймовірність успіху:

```
S(N) = N · (1 - 1/M)^(N - 1)                  [математичне сподівання успішних з'єднань за слот]
```

При великих `M` та `N` виконується класичне наближення Пуассона з параметром навантаження `G = N / M`:

```
S(G) = M · G · e^(-G)                         [наближення Пуассона для пропускної здатності Slotted ALOHA]
```

Максимум цієї функції досягається при `G = 1` (тобто коли кількість пристроїв, що претендують на слот, точно дорівнює кількості доступних преамбул `N = M`):

```
S_max = M · 1 · e^(-1) ≈ 0.368 · M            [теоретична межа ефективності каналу випадкового доступу]
```

Якщо 1000 приладів (`N = 1000`) спробують підключитися до базової станції з `M = 64` преамбулами одночасно, навантаження складе `G = 1000 / 64 ≈ 15.625`. Підставимо це значення у формулу:

```
P_success = e^(-15.625) ≈ 1.63 · 10^(-7)      [ймовірність успішного підключення без відкату]
S(1000) = 64 · 15.625 · 1.63 · 10^(-7) ≈ 0.000163 [очікувана кількість успіхів на слот]
```

Ймовірність успіху стає практично нульовою. Прилади входять у стан взаємного блокування: 99.999% енергії витрачається на передачу радіосигналів, які накладаються один на одного в ефірі й знищуються.

## Класичний двійковий експоненційний відкат

Щоб зменшити густину запитів `N(t)`, алгоритм збільшує інтервал очікування перед кожною наступною спробою `k` (де `k ∈ {0, 1, 2, ..., k_max}`). Для базового інтервалу `T_base` та максимального порогу `T_max` детерміністичний експоненційний інтервал розраховується як:

```
T(k) = min(T_max, T_base · 2^k)               [усічений двійковий експоненційний інтервал]
```

Якщо взяти `T_base = 2 с` та `T_max = 300 с`, послідовність інтервалів для перших спроб має вигляд:

```
k = 0:  T(0) = min(300, 2 · 2^0)   = 2 с      [перша спроба]
k = 1:  T(1) = min(300, 2 · 2^1)   = 4 с      [друга спроба]
k = 2:  T(2) = min(300, 2 · 2^2)   = 8 с      [третя спроба]
k = 3:  T(3) = min(300, 2 · 2^3)   = 16 с     [четверта спроба]
k = 4:  T(4) = min(300, 2 · 2^4)   = 32 с     [п'ята спроба]
k = 5:  T(5) = min(300, 2 · 2^5)   = 64 с     [шоста спроба]
k = 6:  T(6) = min(300, 2 · 2^6)   = 128 с    [сьома спроба]
k = 7:  T(7) = min(300, 2 · 2^7)   = 256 с    [восьма спроба]
k = 8:  T(8) = min(300, 2 · 2^8)   = 300 с    [вихід на насичення T_max]
```

Проте сам по собі детерміністичний відкат **не розв'язує проблему лавини**, якщо група приладів була синхронізована зовнішньою подією (наприклад, аварійним відключенням електроенергії). Усі 1000 приладів одночасно впадуть у помилку в момент `t = 0`, почекають рівно 2 секунди й одночасно атакують мережу в момент `t = 2 с`. Зазнавши невдачі, вони синхронно атакують ефір у моменти `t = 6 с` (2 + 4), `t = 14 с` (6 + 8), `t = 30 с` (14 + 16).

Колізія просто зсувається на дискретні часові інтервали. Щоб «розмазати» навантаження вздовж осі часу, необхідне додавання стохастичного шуму — джиттеру.

## Математичні моделі джиттеру

Існує три класичні стратегії внесення випадковості в експоненційний інтервал:

### 1. Повний джиттер (Full Jitter)

У цій моделі фактичний інтервал сну `t_sleep` обирається рівномірно на відрізку від 0 до розрахованої експоненційної межі `T(k)`:

```
t_sleep = U(0, T(k))                          [рівномірний розподіл від 0 до T(k)]
```

Математичне сподівання `E[t_sleep]` та дисперсія `Var(t_sleep)` для неперервного рівномірного розподілу на `[0, T(k)]` обчислюються за правилами математичної статистики:

```
E[t_sleep] = (0 + T(k)) / 2 = T(k) / 2        [середній час очікування]
Var(t_sleep) = (T(k) - 0)^2 / 12 = T(k)^2 / 12 [дисперсія розподілу]
```

Густина ймовірності відправки запиту `f(t)` на кроці `k` для групи з `N` пристроїв становить `f(t) = 1 / T(k)`. Очікувана густина запитів за одиницю часу:

```
λ(t) = N / T(k)                               [інтенсивність вхідного потоку запитів]
```

Підставивши `λ(t)` у формулу навантаження RACH `G = λ(t) · T_slot / M`, бачимо, що при збільшенні `T(k)` навантаження `G` спадає обернено пропорційно `2^k`. Вже при `k = 3` (`T(3) = 16 с`) для `N = 1000`, `T_slot = 10 мс` та `M = 64`:

```
λ = 1000 / 16 = 62.5 запитів/с                [інтенсивність потоку на 3-й спробі]
G = 62.5 · 0.010 / 64 ≈ 0.00976               [навантаження на канал преамбул]
P_success = (1 - 1/64)^(0.00976 · 64) ≈ e^(-0.00976) ≈ 0.9903 [99.03% успішних підключень]
```

Колізії повністю припиняються, а канал входить у лінійний режим високої пропускної здатності.

### 2. Рівний джиттер (Equal Jitter)

У цій моделі половина інтервалу фіксується детерміністично, а інша половина рандомізується:

```
t_sleep = T(k) / 2 + U(0, T(k) / 2)           [половина бази + рівномірний залишок]
```

Характеристики розподілу:

```
E[t_sleep] = T(k)/2 + (T(k)/2) / 2 = 0.75 · T(k) [середній час очікування]
Var(t_sleep) = (T(k) / 2)^2 / 12 = T(k)^2 / 48 [дисперсія у 4 рази менша, ніж у Full Jitter]
```

Equal Jitter гарантує мінімальну паузу між спробами `T(k)/2`, що корисно для запобігання надто швидким повторам, але створює «мертву зону» нульового трафіку на відрізку `[0, T(k)/2]`.

### 3. Декорельований джиттер (Decorrelated Jitter)

Замість прямої залежності від номера спроби `k`, кожне наступне значення розраховується рекурентно від попереднього значення сну `t_prev`:

```
t_next = min(T_max, U(T_base, 3 · t_prev))    [рекурентне масштабування попереднього сну]
```

Ця модель не потребує збереження лічильника спроб `k`, швидко збільшує розкид значень і зменшує кластеризацію приладів навіть за умов корельованих помилок.

## Порівняльний аналіз енерговитрат та часу відновлення

Розглянемо енергетичний баланс мікроконтролера та модема при виконанні `K` повторних спроб. Нехай:
- `I_active = 150 мА` — струм у режимі радіообміну та пошуку мережі;
- `I_sleep = 15 мкА = 0.015 мА` — струм у режимі глибокого сну мікроконтролера зі знеструмленим модемом;
- `t_tx = 5 с` — тривалість активної фази спроби підключення (подача живлення, AT-ініціалізація, спроба реєстрації).

Сумарна витрата енергії (у міліампер-годинах `мА·год`) на цикл відновлення з `K` спроб становить:

```
Q_total = ∑ [ (I_active · t_tx + I_sleep · t_sleep[i]) / 3600 ]  для i від 0 до K-1
```

Оскільки `I_sleep` у 10 000 разів менший за `I_active`, енергія, витрачена під час очікування у стані сну, практично нікчемна:

```
Q_sleep = (0.015 мА · 300 с) / 3600 с ≈ 0.00125 мА·год
Q_active_single = (150 мА · 5 с) / 3600 с ≈ 0.2083 мА·год [в 166 разів більше]
```

Це доводить ключовий інженерний висновок: **тривалий сон із джиттером практично безкоштовний для акумулятора**. Натомість часті безуспішні спроби підключення в умовах колізій швидко спустошують джерело живлення.

## Зведена таблиця характеристик алгоритмів

| Алгоритм | Формула `t_sleep` | Середній час `E[T]` | Дисперсія `Var(T)` | Зниження колізій | Ризик кластеризації |
|---|---|---|---|---|---|
| Фіксований інтервал | `T_fixed` | `T_fixed` | `0` | Відсутнє | Максимальний (100%) |
| Детерміністичний відкат | `min(T_max, T_0 · 2^k)` | `T(k)` | `0` | Слабке | Високий (дискретний) |
| **Full Jitter** | `U(0, min(T_max, T_0 · 2^k))` | `0.50 · T(k)` | `T(k)² / 12` | **Оптимальне** | **Мінімальний** |
| Equal Jitter | `T(k)/2 + U(0, T(k)/2)` | `0.75 · T(k)` | `T(k)² / 48` | Високе | Низький |
| Decorrelated Jitter | `min(T_max, U(T_0, 3·t_prev))` | `~1.5 · t_prev` | Висока | Дуже високе | Мінімальний |

Для автономних вбудованих пристроїв стандартом де-факто є **Full Jitter**: він забезпечує максимальну ентропію розподілу моментів виходу в ефір, мінімальний середній час очікування `E[t] = T(k)/2` та гарантує надійне відновлення мережі без участі оператора.
