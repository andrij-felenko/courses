# ⚙️ Повний інженерний чекліст вичитки принципової схеми

Вичитка принципової електричної схеми за формалізованим чеклістом — це останній бар'єр перед переходом до трасування друкованої плати, замовленням фотошаблонів і монтажем компонентів. Цей інженерний регламент систематизує ручну та автоматизовану перевірку схемотехнічних рішень за сімома ключовими функціональними доменами, запобігаючи типовим апаратним помилкам: переполюсовці танталових конденсаторів, інверсії диференційних пар, конфліктам логічних рівнів та неповному заживленню багатовивідних мікросхем.

## Регламент проведення вичитки схеми

Процедура верифікації схеми виконується двома інженерами: автором проєкту (Designer) та незалежним рецензентом (Reviewer). Автор відповідає за демонстрацію функціональних зв'язків та обґрунтування вибору номіналів, тоді як рецензент виконує аудит за принципом «не довіряй жодному маркеру без звірки з першоджерелом документації».

Перед початком ручної вичитки проєкт повинен мати нульовий баланс невиправлених помилок у звіті автоматичної перевірки електричних правил (ERC). Будь-які навмисні ігнорування правил (Exclusions / Waivers) фіксуються в журналі аудиту з вичерпним технічним обґрунтуванням.

```
+-------------------------------------------------------------------------+
|                   ЕТАПИ ВЕРИФІКАЦІЇ СХЕМИ ПЕРЕД РОЗВОДКОЮ               |
|                                                                         |
| 1. Автоматичний аудит (ERC)  --> 0 помилок, 0 неперевірених попереджень |
| 2. Аудит підсистеми живлення --> Рейки, пускові струми, зворотні діоди  |
| 3. Аудит ядра та тактування  --> Страпінг, Reset, кварц, блокувальні C  |
| 4. Аудит інтерфейсів зв'язку --> Полярність RX/TX, диференціальні пари  |
| 5. Звірка з даташитами       --> Pin 1, Exposed Pad, цокольовка роз'ємів|
| 6. Аудит тестопридатності    --> Тестові точки на шинах, ізоляція вузлів|
| 7. Фіксація в репозиторії    --> Підпис чекліста в Git (Schematic Freeze)|
+-------------------------------------------------------------------------+
```

## 1. Підсистема живлення та силові ланцюги

Підсистема живлення є фундаментом надійності всього пристрою. Помилка у виборі робочої напруги конденсатора або пропуск ланцюга захисту від зворотної полярності здатні знищити плату в перші мілісекунди після підключення джерела енергії. Під час аудиту рецензент повинен простежити кожен шлях протікання струму від вхідного клемника до виводів живлення кінцевих напівпровідникових споживачів.

Особливу увагу приділяють перевірці розрахунку теплового розсіювання лінійних стабілізаторів (LDO). Потужність, що виділяється на регуляторі, розраховується як добуток струму навантаження на різницю між вхідною та вихідною напругами. Якщо різниця напруг велика, навіть помірний струм викличе спрацьовування внутрішнього теплового захисту мікросхеми або деградацію кристала.

Також перевіряють запас за максимальною напругою для згладжувальних керамічних конденсаторів. Кераміка класу X5R/X7R страждає на виражений ефект падіння ємності під дією постійної напруги зміщення (DC Bias Effect): конденсатор номіналом 10 мкФ на робочу напругу 6.3 В при реальній напрузі 5 В може втрачати до 60–80% своєї початкової ємності, що провокує зрив стійкості імпульсного перетворювача.

| Перевірка | Параметр / Критерій | Наслідок у разі помилки | Статус |
|---|---|---|---|
| **Діапазон вхідних напруг** | Максимальна робоча та перехідна напруга на вході стабілізаторів (LDO / DC-DC) не перевищує `V_in(max)` за даташитом. | Пробій силового ключа, вихід регулятора з ладу, вигорання навантаження. | [ ] |
| **Захист від переполюсовки** | Наявність послідовного діода Шотткі, P-канального MOSFET або ідеального діодного контролера на вході живлення. | Миттєве вигорання напівпровідникових компонентів при помилці підключення кабелю. | [ ] |
| **Супресори та захист від сплесків** | TVS-діод відповідної напруги пробою (`V_BR`) та потужності на роз'ємі зовнішнього живлення. | Руйнування схеми високовольтними індуктивними викидами або ESD. | [ ] |
| **Падіння напруги на LDO** | Перепад `V_in - V_out` перевищує паспортний `V_drop` при максимальному споживаному струмі навантаження. | Просідання вихідної напруги, перехід LDO в нестабільний режим, пульсації. | [ ] |
| **Стійкість та ESR конденсаторів** | Вихідні конденсатори DC-DC і LDO відповідають вимогам до мінімальної ємності та допустимого діапазону ESR. | Самозбудження лінійного стабілізатора, генерація високочастотних коливань. | [ ] |
| **Черговість живлення (Sequencing)** | Дотримано часові затримки ввімкнення між напругами ядра (`1.1V`, `1.8V`) та периферії (`3.3V`). | Внутрішнє коротке замикання в структурі кристала, тригерний ефект (Latch-up). | [ ] |
| **Розділення аналогової та цифрової рейок** | Фільтрація ланцюгів `VDDA` / `VREF` за допомогою RC або LC-ланок (феритова намистина + кераміка). | Високий рівень цифрового шуму в АЦП/ЦАП, втрата точності вимірювань. | [ ] |

## 2. Мікроконтролер, ядро та системна обв'язка

Аудит цифрового процесорного ядра починається з перевірки топології блокувальних конденсаторів. Кожна пара виводів живлення ядра та периферії (`VDD`/`VSS`, `VDDIO`/`VSSIO`) повинна мати індивідуальний високочастотний керамічний конденсатор ємністю 100 нФ, розміщений максимально близько до відповідних виводів. Загальне правило вимагає також наявності одного-двох танталових або керамічних конденсаторів більшої ємності (4.7–10 мкФ) для компенсації низькочастотних просідань струму під час сплесків активності процесора.

Окремо перевіряють ланцюги кварцового резонатора. Кварц вимагає двох навантажувальних конденсаторів, ємність яких розраховується з урахуванням паспортної ємності навантаження резонатора та паразитної ємності монтажу плати. Неправильний вибір ємності призводить або до відхилення тактової частоти (що унеможливлює роботу інтерфейсів USB та UART), або до повного зриву коливань при низьких температурах навколишнього середовища.

Особливу небезпеку становлять піни вибору конфігурації завантаження (Strapping pins). Якщо такий пін випадково підтягнуто до невідповідного логічного рівня через внутрішні особливості підключеного зовнішнього датчика, мікроконтролер після подачі живлення замість виконання основної програми назавжди зависне в режимі системного завантажувача (ROM bootloader).

| Перевірка | Параметр / Критерій | Наслідок у разі помилки | Статус |
|---|---|---|---|
| **Блокувальні конденсатори** | Біля кожного виводу `VDD`/`VSS` передбачено керамічний конденсатор 100 нФ (найменший типорозмір) + bulk-ємність 4.7–10 мкФ на мікросхему. | Збої ядра при перемиканні GPIO, раптові перезавантаження від просідання напруги. | [ ] |
| **Ланцюг апаратного скидання (NRST)** | Зовнішній підтягувальний резистор (якщо не інтегрований у МК) та фільтрувальний конденсатор 10–100 нФ, кнопка безпосередньо замикає на GND. | Чутливість до електромагнітних завад, помилкові перезавантаження пристрою. | [ ] |
| **Конфігураційні (Strapping) піни** | Піни вибору режиму завантаження (`BOOT0`, `BOOT1`, `GPIO0`, `GPIO2`, `GPIO15`) мають однозначні апаратні підтяжки до VDD або GND. | Мікроконтролер не стартує з Flash-пам'яті або зависає в режимі програмування/ROM. | [ ] |
| **Тактовий генератор / Кварц** | Наявність навантажувальних конденсаторів `C_L`, розрахованих за формулою ємності резонатора з урахуванням паразитної ємності монтажу. | Зрив генерації, нестабільна частота, неможливість запуску PLL та інтерфейсу USB. | [ ] |
| **Налагоджувальний інтерфейс (SWD / JTAG)** | Повні лінії `SWDIO`, `SWCLK`, `GND`, `VREF`/`VDD` виведені на стандартний роз'єм або контактні майданчики. | Неможливість прошивки та налагодження першої змонтованої плати. | [ ] |
| **Незадіяні аналогові та цифрові піни** | Входи без внутрішніх підтяжок підключені до стабільних потенціалів або конфігуруються як виходи; невикористані аналогові входи підтягнуті до GND. | Підвищене споживання струму через плаваючий потенціал на CMOS-затворах. | [ ] |

## 3. Цифрові інтерфейси та узгодження логічних рівнів

Головне джерело помилок під час інтеграції мікросхем зв'язку — дзеркальна інверсія сигналів прийому та передачі. Для інтерфейсу UART передавач передавача (`TX`) повинен обов'язково підключатися до приймача приймача (`RX`). Проте в інтерфейсі SPI лінія виходу головного пристрою `MOSI` підключається до однойменного виводу `MOSI` (або `SDI`) веденого чипа. Плутанина в найменуваннях бібліотечних символів різних виробників часто призводить до з'єднання `TX` з `TX` або `MOSI` з `MISO`.

Під час узгодження різновольтних доменів (наприклад, ядра 1.8 В та сенсорів 3.3 В) недостатньо просто встановити резистивний дільник напруги. Дільник працює виключно в один бік і спотворює фронти сигналів на високих тактових частотах через паразитну ємність доріжки. Для двоспрямованих шин (I2C) необхідне використання польових MOSFET-транзисторів або спеціалізованих мікросхем трансляторів рівнів із функцією автоматичного визначення напрямку передачі даних.

| Перевірка | Параметр / Критерій | Наслідок у разі помилки | Статус |
|---|---|---|---|
| **Полярність ліній зв'язку** | Пін `TX` ведучого з'єднано з `RX` веденого (UART); `MOSI` з'єднано з `MOSI`/`SDI` (SPI); `CAN_H` до `CAN_H`, `CAN_L` до `CAN_L`. | Повна відсутність зв'язку між мікросхемами, необхідність різати доріжки на платі. | [ ] |
| **Підтяжки шини I2C** | Резистори підтяжки ліній `SDA` та `SCL` розраховані під швидкість шини (4.7 кОм для 100 кГц, 2.2 кОм для 400 кГц, 1 кОм для 1 МГц) і підключені до ПРАВИЛЬНОЇ напруги. | Завалювання фронтів сигналів, зависання шини I2C або пошкодження низьковольтного датчика. | [ ] |
| **Узгодження напруг 5V / 3.3V / 1.8V** | Наявність двоспрямованих перетворювачів логічних рівнів між доменами з різною напругою живлення. | Пробій захисних ESD-діодів вхідних пінів, паразитне живлення (Phantom Powering). | [ ] |
| **Термінація диференційних ліній** | Термінальні резистори 120 Ом на кінцях ліній шини CAN / RS-485; послідовні демпферні резистори 22–33 Ом на шинах USB (D+/D-). | Відбиття сигналів, спотворення форми імпульсів, високий рівень бітових помилок (BER). | [ ] |
| **Стан пінів при знеструмленні** | Перевірено, що при відключенні живлення плати зовнішні сигнали не подають струм на піни через верхні захисні діоди. | Неконтрольоване напівзаживлення ядра, зависання при ввімкненні, деградація кристала. | [ ] |

## 4. Бібліотечні компоненти, цокольовка та посадки

Перевірка бібліотек компонентів вимагає максимальної концентрації рецензента. Будь-який сторонній бібліотечний символ або посадкове місце розглядається як потенційно дефектний, доки кожен його вивід не буде звірено з офіційним кресленням виробника.

Під час аудиту мікросхем у корпусах QFN, DFN та BGA рецензент обов'язково перевіряє точку відліку: нумерація виводів для вигляду згори (Top View) іде проти годинникової стрілки, тоді як вигляд знизу (Bottom View) дзеркально перевертає порядок пінів. Не менш важливим є контроль нумерації контактів роз'ємів: підключення плоского шлейфа до роз'єму із прямою нумерацією замість зигзагоподібної призводить до перестановки всіх сигнальних ліній шини.

| Перевірка | Параметр / Критерій | Наслідок у разі помилки | Статус |
|---|---|---|---|
| **Звірка Pin-to-Pin за даташитом** | Номер кожного виводу в графічному символі САПР відповідає номеру виводу фізичного корпусу (SOIC, QFP, QFN, BGA). | Коротке замикання живлення на цифрові виходи, непрацездатність вузла. | [ ] |
| **Просторова орієнтація (Top vs Bottom)** | Перевірено, що нумерація виводів QFN/BGA виконана для вигляду зверху (Top View, вид крізь корпус на плату), а не дзеркально (Bottom View). | Повна дзеркальна інверсія всіх виводів мікросхеми, плату неможливо відновити. | [ ] |
| **Центральний тепловий майданчик (Exposed Pad)** | Уточнено вимогу даташиту: підключення EP до `GND`, `V-` або ізоляція від будь-яких провідників. | Коротке замикання внутрішніх вузлів кристала або перегрів мікросхеми. | [ ] |
| **Полярність танталових конденсаторів** | На схемі та у посадковому місці смуга маркування відповідає плюсовому виводу (`+`). | Вибух або спалахування танталового конденсатора під час першого ввімкнення. | [ ] |
| **Полярність діодів та стабілітронів** | Катод (смужка) спрямований у бік вищого потенціалу для блокування, або у бік катодної лінії схеми. | Коротке замикання джерела живлення через прямо зміщений діод. | [ ] |
| **Нумерація контактів багаторядних роз'ємів** | Збіг логіки нумерації: послідовна вздовж рядів чи зигзагоподібна (IDC / шлейфи). | Зсув усіх сигналів інтерфейсного кабелю на сусідні контакти. | [ ] |

## 5. Тестопридатність (DFT) та апаратне налагодження

Тестопридатність плати закладається виключно на етапі створення схеми. Якщо на схемі відсутні контрольні точки (Test Points), інженеру-досліднику доведеться підпаювати дроти безпосередньо до контактів дрібних SMD-компонентів розміру 0402 або ніжок мікросхем із кроком 0.5 мм, що створює ризик випадкового замикання сусідніх ліній та механічного відриву контактних майданчиків від текстоліту.

Кожна вторинна шина живлення повинна мати окрему контрольну точку. Для високошвидкісних сигналів поряд із сигнальним майданчиком обов'язково розміщують контакт землі `GND` під коротку коаксіальну пружинку осцилографічного щупа. Додатково на схемі передбачають послідовні резистори 0 Ом (або розімкнені перемички) для вимірювання струму споживання окремих вузлів міліамперметром під час тестування енергоефективності.

| Перевірка | Параметр / Критерій | Наслідок у разі помилки | Статус |
|---|---|---|---|
| **Тестові точки рейок живлення** | На кожній вторинній напрузі (`5V`, `3.3V`, `1.8V`, `VDDA`) встановлено окремий контрольний майданчик (Test Point). | Необхідність підпаювання тонких дротів безпосередньо до дрібних SMD-конденсаторів. | [ ] |

## Автоматизація перевірки: скрипт аудиту парності сигналів

Для запобігання ситуаціям, коли через механічну опечатку в назві мітки один із сигналів комунікаційної шини виявляється розірваним (наприклад, створено мітку `UART1_TX`, але замість парної `UART1_RX` помилково введено `UART_RX1`), розробляють допоміжні скрипти аудиту нетліста.

Нижче наведено реалізацію верифікатора парності сигналів на мовах C та C++. Утиліта аналізує список міток проєкту та сигналізує про наявність непарних виводів `TX`/`RX` або нескомпенсованих диференційних ліній `_P`/`_N`.

:::tabs
```c
/* netlist_audit.c - перевірка парності інтерфейсних сигналів у нетлісті */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdbool.h>

#define MAX_NETS 512
#define NAME_LEN 64

typedef struct {
    char name[NAME_LEN];
    bool verified;
} NetEntry;

static NetEntry g_nets[MAX_NETS];
static size_t g_net_count = 0;

void add_net(const char *name) {
    if (g_net_count >= MAX_NETS) return;
    strncpy(g_nets[g_net_count].name, name, NAME_LEN - 1);
    g_nets[g_net_count].name[NAME_LEN - 1] = '\0';
    g_nets[g_net_count].verified = false;
    g_net_count++;
}

bool find_net(const char *name) {
    for (size_t i = 0; i < g_net_count; ++i) {
        if (strcmp(g_nets[i].name, name) == 0) return true;
    }
    return false;
}

void verify_uart_and_diff_pairs(void) {
    printf("=== АУДИТ ПАРНОСТІ СИГНАЛІВ СХЕМИ ===\n");
    int issues = 0;

    for (size_t i = 0; i < g_net_count; ++i) {
        char *p = strstr(g_nets[i].name, "_TX");
        if (p && strlen(p) == 3) {
            char expected_rx[NAME_LEN];
            size_t prefix_len = (size_t)(p - g_nets[i].name);
            strncpy(expected_rx, g_nets[i].name, prefix_len);
            expected_rx[prefix_len] = '\0';
            strcat(expected_rx, "_RX");

            if (!find_net(expected_rx)) {
                printf("[ПОМИЛКА] Знайдено сигнал '%s', але відсутній парний '%s'\n",
                       g_nets[i].name, expected_rx);
                issues++;
            }
        }

        /* Перевірка диференційних пар _P та _N */
        char *dp = strstr(g_nets[i].name, "_P");
        if (dp && strlen(dp) == 2) {
            char expected_n[NAME_LEN];
            size_t prefix_len = (size_t)(dp - g_nets[i].name);
            strncpy(expected_n, g_nets[i].name, prefix_len);
            expected_n[prefix_len] = '\0';
            strcat(expected_n, "_N");

            if (!find_net(expected_n)) {
                printf("[ПОМИЛКА] Диференційна лінія '%s' не має пари '%s'\n",
                       g_nets[i].name, expected_n);
                issues++;
            }
        }
    }

    if (issues == 0) {
        printf("[OK] Усі перевірені інтерфейсні пари збігаються.\n");
    } else {
        printf("[УВАГА] Виявлено дефектів: %d. Перевірте опечатки в Net Labels!\n", issues);
    }
}

int main(void) {
    /* Симуляція завантаження міток із САПР */
    add_net("MCU_UART1_TX");
    add_net("MCU_UART1_RX");
    add_net("DEBUG_UART_TX"); /* Без пари - викличе попередження */
    add_net("USB_DP_P");
    add_net("USB_DP_N");
    add_net("CAN_P");          /* Без CAN_N - помилка */

    verify_uart_and_diff_pairs();
    return 0;
}
```

```cpp
// netlist_audit.cpp - сучасна C++ верифікація парності сигналів
#include <iostream>
#include <string>
#include <string_view>
#include <vector>
#include <unordered_set>
#include <algorithm>

class NetlistAuditor {
public:
    void add_net(std::string_view net_name) {
        nets_.emplace(net_name);
    }

    [[nodiscard]] int verify_pairs() const {
        std::cout << "=== АУДИТ ПАРНОСТІ СИГНАЛІВ СХЕМИ (C++) ===\n";
        int issues = 0;

        for (const auto& net : nets_) {
            // Перевірка TX -> RX
            if (net.ends_with("_TX")) {
                std::string expected_rx = net.substr(0, net.size() - 3) + "_RX";
                if (!nets_.contains(expected_rx)) {
                    std::cout << "[ПОМИЛКА] Знайдено сигнал '" << net
                              << "', але відсутній парний '" << expected_rx << "'\n";
                    ++issues;
                }
            }

            // Перевірка диференційних пар _P -> _N
            if (net.ends_with("_P")) {
                std::string expected_n = net.substr(0, net.size() - 2) + "_N";
                if (!nets_.contains(expected_n)) {
                    std::cout << "[ПОМИЛКА] Диференційна лінія '" << net
                              << "' не має пари '" << expected_n << "'\n";
                    ++issues;
                }
            }
        }

        if (issues == 0) {
            std::cout << "[OK] Усі інтерфейсні та диференційні пари верифіковано.\n";
        } else {
            std::cout << "[УВАГА] Виявлено дефектів: " << issues
                      << ". Перевірте опечатки в назвах міток!\n";
        }
        return issues;
    }

private:
    std::unordered_set<std::string> nets_;
};

int main() {
    NetlistAuditor auditor;
    auditor.add_net("MCU_UART1_TX");
    auditor.add_net("MCU_UART1_RX");
    auditor.add_net("DEBUG_UART_TX"); // Відсутній RX
    auditor.add_net("USB_DP_P");
    auditor.add_net("USB_DP_N");
    auditor.add_net("CAN_P");         // Відсутній CAN_N

    auditor.verify_pairs();
    return 0;
}
```
