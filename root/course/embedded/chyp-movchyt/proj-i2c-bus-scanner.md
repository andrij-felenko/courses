# ⚙️ Сканер шини I2C та процедура відновлення після зависання ліній

Коли щойно спаяна друкована плата не виходить на зв'язок із цифровим сенсором, спроба виконати повну ініціалізацію складного драйвера повертає лише таймаут або помилку шини. Першим програмним інструментом діагностики є сканер адрес: компактна підпрограма, яка послідовно перебирає всі допустимі 7-бітні адреси протоколу, надсилає адресний байт запису та фіксує наявність апаратного підтвердження (ACK) на дев'ятому такті. Якщо ж лінія даних SDA заблокована веденим пристроєм у низькому стані, скануванню обов'язково має передувати апаратна процедура виштовхування бітів (англ. *I2C Bus Clear / Recovery*).

---

### Принцип роботи сканера та виведення з глухого кута

Стандарт шини I2C виділяє для 7-бітної адресації діапазон від `0x08` до `0x77` (112 адрес). Діапазони `0x00..0x07` та `0x78..0x7F` зарезервовані для спеціальних функцій: генерального виклику (General Call), 10-бітної адресації, режиму підвищеної швидкості (High-Speed Master Code) та ідентифікації пристрою.

```
+---------------+---------------------+---------------------------------------------------------+
| Діапазон адрес| Тип адресації       | Інженерне призначення за стандартом I2C / SMBus        |
+---------------+---------------------+---------------------------------------------------------+
| 0x00 .. 0x07  | Зарезервовані       | General Call (0x00), CBUS (0x02), 10-бітний префікс     |
| 0x08 .. 0x77  | Звичайні пристрої   | Робочий простір цифрових сенсорів, пам'яті, АЦП, ЦАП    |
| 0x78 .. 0x7B  | 10-бітний префікс   | 1111 0XX для адресації розширеного адресного простору   |
| 0x7C .. 0x7F  | Спеціальні режими   | Ідентифікація виробника (Device ID), резерв             |
+---------------+---------------------+---------------------------------------------------------+
```

Для кожної адреси майстер генерує транзакцію нульової довжини: умову START, 8-бітний байт `(address << 1) | 0` (байт запису) і чекає дев'ятого такту SCL. Якщо ведений чіп присутній, заживлений і налаштований на цю адресу, він притягує лінію SDA до нуля (ACK). Отримавши ACK, майстер одразу формує умову STOP, фіксує знайдений вузол і переходить до наступної адреси.

#### Механізм зависання шини (SDA Stuck Low)
Якщо лінія SDA вже лежить у нулі до початку сканування, апаратний периферійний блок I2C переходить у стан помилки шини (Bus Busy / Arbitration Error). Найчастіша причина такого стану — перезавантаження мікроконтролера в момент, коли сенсор передавав нульовий біт даних у відповідь на попередній запит читання. Оскільки мікроконтролер перервав транзакцію і скинувся, сенсор залишається у стані очікування наступного тактового імпульсу SCL, неперервно відкриваючи свій внутрішній N-канальний польовий транзистор і притискаючи лінію SDA до землі.

Майстер після перезавантаження не може згенерувати умову START (яка вимагає перепаду SDA з 1 в 0 при високому SCL), оскільки лінія SDA вже заблокована в нулі. Апаратний периферійний контролер мікроконтролера (наприклад, блок I2C у STM32 чи ESP32) фіксує зайнятість лінії і відмовляється починати будь-яку транзакцію.

#### Послідовність апаратного відновлення (9-Clock Bus Recovery Routine)
Для розблокування шини прошивка має виконати спеціальний алгоритм до запуску апаратного периферійного модуля:
1. Виводи, призначені для I2C, конфігуруються як звичайні порти введення-виведення загального призначення (GPIO).
2. Лінія `SCL` налаштовується як вихід типу Push-Pull або Open-Drain із зовнішньою підтяжкою. Лінія `SDA` налаштовується як вхід із можливістю зчитування логічного рівня.
3. Прошивка зчитує рівень на лінії `SDA`. Якщо він високий, шина вільна і відновлення не потрібне.
4. Якщо `SDA == 0`, мікроконтролер примусово формує на лінії `SCL` дев'ять тактових імпульсів з частотою 50–100 кГц (тривалість напівперіоду 5–10 мікросекунд).
5. З кожним перепадом SCL внутрішній зсувний регістр веденого чіпа зсуває біти невідправленого байта. Максимум через 8 тактів чіп завершить передачу свого байта і на 9-му такті відпустить лінію SDA для очікування підтвердження ACK/NACK від майстра.
6. Щойно на лінії SDA фіксується високий рівень, майстер примусово формує послідовність умови STOP: опускає SDA в нуль при низькому SCL, піднімає SCL у високий рівень, а потім переводить SDA з низького рівня у високий при стабільно високому SCL.
7. Після завершення процедури піни реконфігуруються у режим альтернативної функції апаратного блоку I2C.

### Реалізація сканера та процедури відновлення

Нижче наведено модульну реалізацію відновлення шини та сканування адрес мовами C та C++.

:::tabs
```c
/* Обслуговування шини I2C: відновлення ліній та сканування адрес */
#include <stdint.h>
#include <stdbool.h>
#include <stdio.h>

/* Визначення абстрактного апаратного інтерфейсу GPIO для відновлення */
typedef struct {
    void (*set_scl_output)(void);
    void (*set_scl_level)(bool high);
    bool (*read_sda_level)(void);
    void (*set_sda_output)(void);
    void (*set_sda_level)(bool high);
    void (*restore_i2c_peripheral)(void);
    void (*delay_us)(uint32_t us);
} i2c_bus_recovery_io_t;

/* Процедура апаратного виведення веденого чіпа із затиснутого стану SDA */
bool i2c_recover_bus(const i2c_bus_recovery_io_t *io) {
    /* 1. Якщо SDA висока — шина вільна, скидання не потрібне */
    if (io->read_sda_level()) {
        return true;
    }

    /* 2. Переводимо SCL у режим GPIO виходу, SDA залишається входом */
    io->set_scl_output();
    io->set_scl_level(true);
    io->delay_us(5);

    /* 3. Тактуємо лінію SCL до 9 разів, очікуючи відпускання SDA */
    bool sda_released = false;
    for (uint8_t i = 0; i < 9; ++i) {
        io->set_scl_level(false);
        io->delay_us(5);
        io->set_scl_level(true);
        io->delay_us(5);

        if (io->read_sda_level()) {
            sda_released = true;
            break;
        }
    }

    /* Якщо ведений не відпустив лінію навіть після 9 тактів — апаратне КЗ або дефект */
    if (!sda_released) {
        io->restore_i2c_peripheral();
        return false;
    }

    /* 4. Формуємо примусову умову STOP: перехід SDA з 0 в 1 при SCL = 1 */
    io->set_sda_output();
    io->set_sda_level(false);
    io->delay_us(5);
    io->set_scl_level(true);
    io->delay_us(5);
    io->set_sda_level(true);
    io->delay_us(5);

    /* 5. Повертаємо виводи під контроль апаратного I2C блоку */
    io->restore_i2c_peripheral();
    return true;
}

/* Структура звіту сканування */
typedef struct {
    uint8_t addresses[112];
    uint8_t count;
} i2c_scan_result_t;

/* Тип функції перевірки адреси апаратним периферійним драйвером */
typedef bool (*i2c_ping_fn_t)(uint8_t addr_7bit, uint32_t timeout_ms);

/* Запуск повного циклу опитування простору адрес */
i2c_scan_result_t i2c_scan_bus(i2c_ping_fn_t ping_fn, uint32_t timeout_ms) {
    i2c_scan_result_t result = {.count = 0};

    printf("Початок сканування шини I2C (діапазон 0x08..0x77)...\r\n");

    for (uint8_t addr = 0x08; addr <= 0x77; ++addr) {
        if (ping_fn(addr, timeout_ms)) {
            result.addresses[result.count++] = addr;
            printf(" -> Знайдено пристрій за 7-бітною адресою: 0x%02X (8-бітний запис: 0x%02X)\r\n",
                   addr, (uint8_t)(addr << 1));
        }
    }

    printf("Сканування завершено. Знайдено пристроїв: %u\r\n", result.count);
    return result;
}
```

```cpp
/* Обслуговування шини I2C: сучасний C++20 з RAII та концептами */
#include <cstdint>
#include <cstdio>
#include <concepts>
#include <span>
#include <vector>
#include <optional>

/* Концепт для низькорівневих апаратних маніпуляцій лініями */
template <typename T>
concept I2CPinDriver = requires(T io, bool level, uint32_t us) {
    { io.set_scl_output() } -> std::same_as<void>;
    { io.set_scl_level(level) } -> std::same_as<void>;
    { io.read_sda_level() } -> std::same_as<bool>;
    { io.set_sda_output() } -> std::same_as<void>;
    { io.set_sda_level(level) } -> std::same_as<void>;
    { io.restore_peripheral() } -> std::same_as<void>;
    { io.delay_us(us) } -> std::same_as<void>;
};

/* Клас діагностики та обслуговування I2C шини */
template <I2CPinDriver Driver>
class I2CBusDiagnostics {
public:
    explicit I2CBusDiagnostics(Driver& driver) : driver_(driver) {}

    /* Виведення шини із зависання через 9 тактів SCL */
    [[nodiscard]] bool recover_bus() {
        if (driver_.read_sda_level()) {
            return true; /* Лінія вільна */
        }

        driver_.set_scl_output();
        driver_.set_scl_level(true);
        driver_.delay_us(5);

        bool sda_cleared = false;
        for (std::size_t i = 0; i < 9; ++i) {
            driver_.set_scl_level(false);
            driver_.delay_us(5);
            driver_.set_scl_level(true);
            driver_.delay_us(5);

            if (driver_.read_sda_level()) {
                sda_cleared = true;
                break;
            }
        }

        if (!sda_cleared) {
            driver_.restore_peripheral();
            return false; /* Апаратна несправність: SDA замкнена на GND */
        }

        /* Формування аварійного STOP сигналу */
        driver_.set_sda_output();
        driver_.set_sda_level(false);
        driver_.delay_us(5);
        driver_.set_scl_level(true);
        driver_.delay_us(5);
        driver_.set_sda_level(true);
        driver_.delay_us(5);

        driver_.restore_peripheral();
        return true;
    }

    /* Сканування простору 7-бітних адрес */
    template <typename PingCallable>
    requires std::predicate<PingCallable, std::uint8_t>
    [[nodiscard]] std::vector<std::uint8_t> scan_bus(PingCallable&& ping) {
        std::vector<std::uint8_t> found_devices;
        found_devices.reserve(8);

        std::printf("I2C Scanner: початок перебору 0x08..0x77\r\n");

        for (std::uint8_t addr = 0x08; addr <= 0x77; ++addr) {
            if (ping(addr)) {
                found_devices.push_back(addr);
                std::printf(" -> Пристрій відповідає: 7-біт: 0x%02X | 8-біт WR: 0x%02X\r\n",
                            addr, static_cast<std::uint8_t>(addr << 1));
            }
        }

        std::printf("Знайдено активних вузлів: %zu\r\n", found_devices.size());
        return found_devices;
    }

private:
    Driver& driver_;
};
```

### Аналіз та інтерпретація результатів сканування

Результати сканування дозволяють зробити однозначні інженерні висновки про стан апаратної частини:

1. **Фантомний відгук усіх адрес (знайдено 112 пристроїв):**
   Якщо сканер повідомляє про успішний ACK на кожній адресі від `0x08` до `0x77`, лінія SDA замкнена на землю або внутрішній захисний діод одного з мікроконтролерів пробитий. Оскільки лінія SDA постійно утримується в нулі, мікроконтролер на 9-му такті кожного кадру фіксує логічний нуль, сприймаючи його як валідний ACK.

2. **Повна відсутність відповідей (знайдено 0 пристроїв):**
   - Відсутнє живлення `V_DD` на веденому чіпі;
   - Відсутні або обірвані резистори підтяжки на лініях SDA та SCL (лінії постійно перебувають у стані невизначеності або нулі);
   - Лінія апаратного скидання (`nRST`) перебуває в низькому рівні;
   - Переплутані місцями лінії SDA та SCL між мікроконтролером і модулем.

3. **Незбіг виявленої адреси з очікуваною:**
   Якщо за даташитом сенсор має адресу `0x68`, а сканер виявляє пристрій за адресою `0x69`, це свідчить про зміну потенціалу на конфігураційному виводі `AD0` / `ADDR` (наприклад, підтяжка до живлення замість землі або непідключений пін, що ловить потенціал сусідньої доріжки).
