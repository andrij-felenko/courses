# Функції: даємо шматку коду ім'я

Ви вже вміли писати [цілу програму від `main()` до першого рядка на екрані](root:embedded/c-first-program), заводити [змінні різних типів](root:embedded/c-variables-types) і гнути потік [розгалуженнями та циклами](root:embedded/c-control-flow). І весь цей час ви користувалися чужими **функціями**, навіть не спиняючись над словом: `printf` друкував рядок, функція середовища смикала ніжку (`digitalWrite` в Arduino, `HAL_GPIO_WritePin` у STM32), а сам `main` — то теж функція, з якої машина стартувала. Ви кликали їх на віру, як магічні закляття: пишеш ім'я, ставиш дужки — щось відбувається. Настав час зняти магію й навчитися робити такі закляття **самому**.

Питання, з якого все виростає, просте до банальності: **навіщо** взагалі давати шматку коду ім'я? Уявіть, що ви пишете прошивку, де світлодіод має блимнути тричі — на старті, на помилці й на успіху. Без функцій ви тричі перепишете той самий десяток рядків «увімкни ніжку, зачекай, вимкни, зачекай». А тепер уявіть, що ви передумали й хочете блимати не 200 мілісекунд, а 150. Доведеться знайти **всі три** місця й виправити кожне — і, звісно, одне ви пропустите. Ось звідси й росте функція: **написати раз, назвати, а далі кликати іменем скільки завгодно разів**. Виправив в одному місці — виправилося всюди.

### Що таке функція насправді

Слово «функція» прийшло не з програмування, а з математики, і несе в собі свій корінь: латинське *functiō* — «виконання, відправлення обов'язку» (від *fungī* — «виконувати, справляти»). У математиків функцію ввів [Ґотфрід Ляйбніц ще 1673 року](root:embedded/c-functions/hist-subroutine.md), щоб позначити величину, пов'язану з точками кривої; там функція — це правило «дай мені `x`, я поверну тобі `y`». Ця математична спорідненість не випадкова: гарна функція в коді теж бере щось на вході й повертає щось на виході. Але в програмуванні слово ширше — функція це передусім **названий шматок роботи**, який можна виконати на замовлення.

Порівняння, що не бреше: функція — це як **рецепт** у кулінарній книзі. Рецепт «спекти хліб» описано **один раз**, а посилаються на нього хоч щодня. Рецепт може вимагати **складників** (борошно, вода, сіль) — це **параметри**, те, що ви передаєте функції на вхід. І рецепт дає **результат** (буханець) — це **повернене значення**, те, що функція віддає назад. Ви не переписуєте рецепт щоразу, коли печете; ви кажете «зроби за рецептом» і передаєте складники. Де аналогія трохи кульгає: кулінарний рецепт можна прочитати очима, а функцію процесор мусить **виконати** крок за кроком — але для розуміння суті рецепт — точний образ.

![Функція як рецепт: складники на вході, буханець на виході](/root/course/embedded/c-functions/img/recipe.svg)
*Функція — це рецепт, записаний один раз. Складники ліворуч — це параметри (вхід); буханець праворуч — повернене значення (вихід). Виклик функції — це не «переписати рецепт заново», а сказати «зроби за рецептом ось із цими складниками». Змінив рецепт в одному місці — і кожен, хто ним користується, отримує новий результат.*

### Будова функції в C

Розберімо функцію на частини на живому прикладі. Ось найпростіша корисна функція — вона бере два цілих числа й повертає їхню суму:

:::tabs
```c
int add(int a, int b) {
    int result = a + b;
    return result;
}
```
```cpp
int add(int a, int b) {
    int result = a + b;
    return result;
}
```
```python
def add(a, b):
    result = a + b
    return result
```
:::

Прочитаймо її зліва направо, бо кожне слово тут щось означає:

- **`int`** попереду — це **тип повернення** (*return type*): яке значення функція віддасть назад. Тут — ціле число. Якщо функція нічого не повертає (просто робить дію), тип буде `void` (лат. «порожній») — про це нижче.
- **`add`** — це **ім'я** функції. Його ви й пишете, коли хочете її покликати. Ім'я — головна цінність: воно каже, **що** функція робить, не змушуючи читати її нутрощі.
- **`(int a, int b)`** — **параметри** (*parameter*, від гр. *para* + *metron* — «побічна міра»): вхідні дані, кожен зі своїм типом і власним іменем. Усередині функції `a` і `b` — це звичайні змінні, якими можна користуватися.
- **`{ … }`** — **тіло** (*body*): власне робота, крок за кроком. Тут — порахувати суму й повернути її.
- **`return result;`** — **повернути** результат назад тому, хто кликав, і на цьому функцію завершити.

> 🔧 **Навіщо це.** Ім'я функції — це стиснута обіцянка. Коли за пів року ви (або колега) читаєте прошивку й бачите `read_temperature()`, вам не треба лізти всередину й розбирати десяток рядків роботи з давачем — ім'я вже сказало, що там діється. Добра назва економить не такти процесора, а **години людського часу** на розуміння коду. Тому називайте функції дієсловом-наміром: `read_temperature`, `set_led`, `is_button_pressed` — а не `func1` чи `do_stuff`.

### Виклик: як покликати функцію

Оголосити функцію — то ще пів справи; треба її **покликати** (*call*). Виклик — це коли ви пишете її ім'я з дужками й передаєте всередину конкретні значення:

:::tabs
```c
int main() {
    int sum = add(3, 4);   // кличемо add, передаємо 3 і 4
    printf("%d\n", sum);   // надрукує 7
    return 0;
}
```
```cpp
int main() {
    int sum = add(3, 4);        // кличемо add, передаємо 3 і 4
    std::cout << sum << '\n';   // надрукує 7
    return 0;
}
```
```python
sum = add(3, 4)   # кличемо add, передаємо 3 і 4
print(sum)        # надрукує 7
```
:::

Що тут відбувається по кроках. Виконання доходить до `add(3, 4)`; тоді воно **перестрибує** всередину функції `add`, підставивши `a = 3` і `b = 4`. Функція рахує `result = 7`, доходить до `return 7` — і **вертається назад** саме туди, звідки її покликали, принісши із собою число 7. Це число сідає у змінну `sum`. Далі виконання спокійно йде собі рядком нижче. Ключова думка: виклик — це **тимчасовий відхід** убік і **обов'язкове повернення** на те саме місце.

Значення, які ви передаєте при виклику (тут `3` і `4`), звуть **аргументами** (*argument*). Різниця тонка, але корисна: **параметр** — це ім'я-заготовка в оголошенні функції (`a`, `b`), а **аргумент** — це реальне значення, яке ви підставляєте при виклику (`3`, `4`). Параметр — порожня комірка в бланку; аргумент — те, що ви в неї вписали.

![Виклик функції: стрибок усередину і повернення назад із результатом](/root/course/embedded/c-functions/img/call-return.svg)
*Виклик — це відхід і повернення. Виконання йде згори вниз у `main`, доходить до `add(3, 4)`, стрибає всередину функції (аргументи 3 і 4 сідають у параметри a і b), там рахує й доходить до `return`. Управління повертається точно на те місце, звідки покликали, принісши результат 7. Функція завжди вертає туди, звідки її викликали, — хоч би скільки разів і звідки її кликали.*

### Аргументи копіюються: пастка, про яку мовчать

Ось перша важлива тонкість C, на якій спотикаються всі новачки. Коли ви передаєте аргумент, функція отримує **копію** значення, а не сам оригінал. Це зветься **передавання за значенням** (*pass by value*). Наслідок буває несподіваний: якщо функція міняє свій параметр, оригінал зовні **не зміниться**.

:::tabs
```c
void try_to_change(int x) {
    x = 100;              // міняємо копію всередині функції
}

int main() {
    int n = 5;
    try_to_change(n);    // передали копію 5
    printf("%d\n", n);   // надрукує 5, а не 100!
    return 0;
}
```
```cpp
void try_to_change(int x) {
    x = 100;                  // міняємо копію всередині функції
}

int main() {
    int n = 5;
    try_to_change(n);         // передали копію 5
    std::cout << n << '\n';   // надрукує 5, а не 100!
    return 0;
}
```
:::

Чому так? Бо `try_to_change` дістала **власну копію** п'ятірки у свій параметр `x`. Вона порозважалася з тією копією, поставила її на 100 — і копія загинула, щойно функція завершилася. Оригінальна змінна `n` у `main` навіть не знала, що поруч щось коїлося. Це не вада, а **захист**: функція за замовчуванням не може непомітно зіпсувати ваші дані. А коли функції **справді** треба змінити щось зовнішнє — для цього передають не саме значення, а [адресу цього значення через покажчик](root:embedded/c-pointers-intro); але це вже наступна розмова, і поки досить знати, що просте передавання **копіює**.

### `void`, `return` і функції-дії

Не кожна функція щось повертає. Дуже часто функція існує заради **дії** — блимнути світлодіодом, надіслати байт, зачекати. Такій нема чого віддавати назад, і її тип повернення — **`void`** (англ. «порожнеча»). Робота тут одна на будь-якому мікроконтролері — виставити ніжку у високий рівень, витримати паузу, повернути в низький, — а різняться лише імена функцій середовища:

:::tabs
```arduino
void blink(int times, int ms) {
    for (int i = 0; i < times; i++) {
        digitalWrite(LED, HIGH);   // ніжку у високий рівень
        delay(ms);
        digitalWrite(LED, LOW);    // і назад у низький
        delay(ms);
    }
}
```
```esp-idf
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

void blink(int times, int ms) {
    for (int i = 0; i < times; i++) {
        gpio_set_level(LED, 1);            // ніжку у високий рівень
        vTaskDelay(pdMS_TO_TICKS(ms));
        gpio_set_level(LED, 0);            // і назад у низький
        vTaskDelay(pdMS_TO_TICKS(ms));
    }
}
```
```stm32
void blink(int times, int ms) {
    for (int i = 0; i < times; i++) {
        HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);    // високий
        HAL_Delay(ms);
        HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);  // низький
        HAL_Delay(ms);
    }
}
```
:::

Ця функція нічого не повертає — вона **робить**. Кличуть її просто як окремий рядок, не сподіваючись результату: `blink(3, 150);`. Усередині `void`-функції `return;` теж можна написати (без значення) — він достроково **вискочить** із функції, якщо десь посеред роботи стало ясно, що далі робити нічого. Так `return` слугує двом цілям: у функції зі значенням він **віддає результат і виходить**, а у `void`-функції — просто **виходить**.

І зверніть увагу, як `blink` спирається на все, що ви вже знаєте: усередині неї живе [цикл `for`](root:embedded/c-control-flow), лічильник `i` — [локальна змінна типу `int`](root:embedded/c-variables-types), а запис у ніжку — та сама чужа функція середовища (`digitalWrite`, `gpio_set_level`, `HAL_GPIO_WritePin` — залежно від платформи), яку ви кликали й раніше. Функція не додає нової фізики; вона лише **пакує** знайомі шматки коду під одним іменем.

### Тепер `main` перестає бути загадкою

Пам'ятаєте, як у [першій програмі](root:embedded/c-first-program) `main` виглядав чарівним словом, з якого все починається? Тепер ви бачите його наскрізь: `main` — **звичайна функція**, просто з особливим іменем, яке [C-рантайм](book:programming/c-runtime) знає й кличе першим після старту. Її `int` на початку й `return 0;` наприкінці — не заклинання, а звичайні тип повернення і повернене значення: нуль означає «програма завершилася без помилок». В embedded, до речі, `main` часто взагалі не вертається — він крутить нескінченний цикл, бо прошивці нема куди «завершуватися»:

```c
int main() {
    setup_hardware();        // одноразові приготування
    while (1) {              // вічний цикл прошивки
        read_sensors();
        update_outputs();
    }
    return 0;                // сюди виконання ніколи не дійде
}
```

Ця будова — «налаштувати раз, тоді крутити вічно» — і є серцем майже кожної прошивки. Зверніть увагу, як `main` тут читається майже як речення людською мовою: «налаштуй залізо, тоді в циклі читай давачі й онови виходи». Кожен рядок — виклик функції з промовистим іменем, а вся марудна робота захована всередині них. Ось для чого функції насправді: вони дозволяють писати код **шарами абстракції** — верхній шар читається як задум, нижчі ховають подробиці.

### Куди зникають локальні змінні: кадр на стеку

Лишилося зрозуміти, **де** живуть змінні функції, поки вона працює, — і куди діваються потім. Кожного разу, коли функцію кличуть, під її локальні змінні й параметри виділяється маленька ділянка пам'яті — **кадр** (*stack frame*). Кадри складаються один на одного, як тарілки: покликали функцію — поклали тарілку зверху; функція завершилася — тарілку зняли, і вся її пам'ять звільнилася. Саме тому локальна змінна `result` з `add` **не існує** поза функцією: її кадр знято, тарілку прибрано.

Ця стосова дисципліна «останнім поклав — першим зняв» і є [**стек** — та сама структура пам'яті](book:programming/stack-lifo), на якій тримаються всі виклики функцій у C. Вона й пояснює, чому виклик завжди вертається **точно** туди, звідки пішов: разом із кадром на стек кладеться й **адреса повернення** — записка «куди стрибнути назад, коли скінчиш». Знімаючи кадр, машина читає ту записку й повертається за нею.

![Стек кадрів: main кличе add, кадр add лягає зверху й знімається на return](/root/course/embedded/c-functions/img/stack-frames.svg)
*Кожен виклик кладе на стек свій кадр — ділянку під локальні змінні, параметри й адресу повернення. Коли main кличе add, кадр add лягає ЗВЕРХУ на кадр main. Щойно add доходить до return, її кадр знімається — пам'ять звільняється, локальні змінні зникають, а машина за адресою повернення стрибає назад у main. Останнім поклав — першим зняв: це і є стек.*

Звідси й практичний висновок для прошивки: у мікроконтролера стек **малий** (кілька кілобайтів), тож ним не можна смітити. Величезний масив не варто заводити локальною змінною — він з'їсть увесь кадр; глибоко-вкладені або нескінченні ланцюжки викликів можуть [переповнити стек](book:programming/stack-overflow) і завалити прошивку. Але для звичайних дрібних змінних цей механізм — тихий і безкоштовний: поклав тарілку, зняв тарілку.

### Оголошення наперед: чому компілятор іноді свариться

Остання практична річ, без якої функції в реальному коді не поживеш. [Компілятор](root:embedded/c-first-program) читає файл **згори вниз** і мусить знати функцію, **перш ніж** ви її покличете. Якщо `main` кличе `add`, а `add` описано **нижче** за `main`, компілятор дійде до виклику, ще не знаючи, що таке `add`, — і насвариться.

Ліки — **прототип** (*prototype*): короткий анонс функції наперед, лише її «шапка» без тіла, що завершується крапкою з комою. Він каже компіляторові «така функція існує, ось її ім'я, входи й вихід — довіряй, тіло буде далі»:

:::tabs
```c
int add(int a, int b);   // прототип: анонс наперед, тіла ще нема

int main() {
    int s = add(2, 3);   // тепер компілятор спокійний: він знає add
    return s;
}

int add(int a, int b) {  // а ось і саме тіло, нижче
    return a + b;
}
```
```cpp
int add(int a, int b);   // прототип: анонс наперед, тіла ще нема

int main() {
    int s = add(2, 3);   // тепер компілятор спокійний: він знає add
    return s;
}

int add(int a, int b) {  // а ось і саме тіло, нижче
    return a + b;
}
```
:::

Прототип описує рівно те, що потрібно для правильного виклику: скільки аргументів, яких типів і що функція поверне. Саме прототипи збирають у **заголовкові файли** (`.h`), щоб одну функцію можна було кликати з багатьох місць проєкту, — але це вже тема [препроцесора й заголовків](root:embedded/c-preprocessor-headers), яка чекає попереду.

### Що ми маємо тепер

Функція — це названий шматок роботи: пишеш його раз, а кличеш іменем скільки завгодно, передаючи **аргументи** в **параметри** й отримуючи назад **повернене значення** (або нічого — `void`, якщо функція просто діє). Кожен виклик — це тимчасовий стрибок усередину й гарантоване повернення на місце; аргументи при цьому **копіюються**, тож функція не псує чужих даних, а її локальні змінні живуть на **стеку** рівно доти, доки вона працює. `main` виявився не магією, а звичайною функцією зі спеціальним іменем; а прототип — це ввічливий анонс, який заспокоює компілятора.

Головне ж — не механіка, а звичка мислення, яку функції прищеплюють: розбивати задачу на **названі шматки**, кожен з яких робить одну зрозумілу річ. Прошивка, зібрана з добре названих функцій, читається як опис задуму, а не як стіна коду. Далі ви побачите, як функції працюють із [масивами й рядками](root:embedded/c-arrays-strings) — і саме там уперше по-справжньому знадобиться вміння передавати у функцію не копію значення, а [адресу через покажчик](root:embedded/c-pointers-intro).
