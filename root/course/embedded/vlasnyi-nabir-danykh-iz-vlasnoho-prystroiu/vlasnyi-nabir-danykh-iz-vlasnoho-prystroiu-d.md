# Власний набір даних із власного пристрою: запис, розмітка, баланс

- [Прямий доступ до пам'яті (DMA)](root:embedded/dma-adc) — передача вибірок від периферії в оперативну пам'ять без завантаження ядра процесора.
- [Файлова система на борту (FatFS)](root:embedded/fatfs-integration) — запис блоків даних на SD-карту та буферизація секторів накопичувача.
- [Мітка часу](root:embedded/mitka-chasu) — апаратний відлік мікросекунд та прив'язка подій до єдиної монотонної шкали.
- [Автокодер](root:sf-ml/autoencoder) — архітектура нейромережі зі стисненням у вузьке горло для детекції аномалій за похибкою відновлення.
</preknowlist>

Бортова нейромережа розпізнавання вібрацій підшипника, навчена на загальнодоступному університетському датасеті, на лабораторному стенді демонструє точність 99%, але після прошивки в серійний мікроконтролер виробу відмовляє в перші ж хвилини роботи. У кращому разі вона генерує безперервні хибні тривоги на абсолютно справному двигуні, у гіршому — мовчить у момент реального механічного заклинювання валу. Причина такої поведінки криється не в архітектурі мережі чи алгоритмі оптимізації, а у фізичній невідповідності даних: чужі набори знято іншими мікросхемами сенсорів, на жорстких масивних верстатах, із відмінними опорними напругами АЦП, іншою смугою пропускання та без урахування реальних шумів силового перетворювача вашої плати.

Єдиний спосіб отримати надійний бортовий інтелект — зібрати власний набір даних безпосередньо з давачів того самого пристрою, у тому самому корпусі та в реальних експлуатаційних режимах. Цей процес вимагає розв'язання трьох суто інженерних проблем: створення апаратного логера, що не втрачає жодної вибірки на високих частотах, подолання катастрофічного дисбалансу між годинами нормальної роботи та мілісекундами аварій, а також нейтралізації дрейфу сенсорів під час коливань температури та старіння механіки.

### 1. Бортове логування: запис сирих потоків без втрат

Перше залізне правило збору навчальних даних для вбудованих систем: **на носій завжди записуються виключно сирі невідфільтровані відліки датчиків** (англ. *raw sensor readings* — прямі коди АЦП чи неперетворені 16-бітні цілі числа з регістрів SPI/I2C). Спокуса застосувати на борту фільтр низьких частот, ковзне середнє чи перевести вибірки у числа з рухомою комою (англ. *floating-point*) перед збереженням є найнебезпечнішою помилкою. 

Будь-яка цифрова фільтрація є незворотною операцією: якщо ви відфільтрували потік на частоті зрізу 500 Гц, а через місяць виявили, що ознака руйнування сепаратора підшипника ховається на частоті 1.2 кГц, весь зібраний терабайтний архів стає марним сміттям. Збір даних доведеться починати з нуля. Сирі відліки зберігають максимум фізичної інформації, дозволяючи експериментувати з будь-якими цифровими фільтрами, перетвореннями Фур'є чи вейвлетами пізніше на комп'ютері.

![Архітектура безперервного логування сенсорних даних на мікроконтролері](/root/course/embedded/vlasnyi-nabir-danykh-iz-vlasnoho-prystroiu/img/sensor-logging-pipeline.svg)
*Архітектура безперервного збору даних на мікроконтролері. Апаратні сенсори передають вибірки через DMA в оперативну пам'ять, де подвійний буфер ізолює швидкий ввід від фонового скидання на SD-карту, запобігаючи втратам пакетів під час затримок очищення Flash-пам'яті.*

#### Пастка затримок Flash-пам'яті та подвійна буферизація

Сенсорні потоки в автономній системі надходять безперервно та з високою частотою: тривісний акселерометр IMU формує вибірки на частоті 1.6–6.4 кГц, струмовий шунт через АЦП опитується на 10–50 кГц, а цифровий I2S мікрофон видає аудіопотік 16–48 кГц. 

Спроба записувати ці вибірки безпосередньо у файлову систему (наприклад, через виклики `f_write()` бібліотеки FatFS) безпосередньо в циклі опитування неминуче знищує цілісність даних. Причина криється у внутрішній будові накопичувачів Flash (SD-карток, eMMC та чіпів SPI NAND). Хоча середня швидкість запису може перевищувати десятки мегабайтів на секунду, періодично внутрішній контролер накопичувача запускає процедури стирання блоків (англ. *Block Erase*) та збирання сміття (англ. *Garbage Collection*). У цей момент лінія даних блокується на час від 10 до 250 мілісекунд.

Якщо програма виконує запис синхронно, процесорне ядро застигає в очікуванні готовності накопичувача. Внутрішні буфери FIFO самого сенсора (місткістю 16–64 вибірки) переповнюються за лічені мілісекунди, що спричиняє випадання цілих фрагментів сигналу (англ. *sample drop*). Для часових рядів випадання навіть кількох відліків спотворює спектральну щільність потужності та робить розраховані ознаки (FFT, RMS, куртозис) непридатними для навчання.

Лік проти цієї проблеми — **жорстке розділення тракту на два асинхронні шари через подвійну або кільцеву буферизацію в оперативній пам'яті (RAM)**:
1. **Апаратний збір через DMA (Direct Memory Access):** контролер прямого доступу до пам'яті забирає байти з SPI/I2S/ADC без участі ядра процесора та складає їх у заздалегідь виділений блок пам'яті `Buffer A`.
2. **Фоновий запис блоками секторів:** коли `Buffer A` наповнюється, DMA автоматично перемикається на `Buffer B`, а ядру надсилається переривання. Фонова низькопріоритетна задача операційної системи (FreeRTOS/Zephyr) забирає готовий `Buffer A` і скидає його на SD-карту великим блоком, строго кратним розміру сектора Flash (512 або 4096 байтів).

Якщо сумарний потік даних від усіх датчиків становить `50 КБ/с`, а максимальна затримка очищення SD-карти сягає `200 мс`, черга буферів у RAM повинна вміщувати щонайменше `50 КБ/с · 0.2 с = 10 КБ` даних. Для надійності виділяють 4–8 секторних буферів загальним обсягом 16–32 КБ, що повністю нівелює будь-які затримки носія.

#### Апаратні часові мітки та структура бінарного фрейму

Збереження даних у текстових форматах (CSV, JSON) на мікроконтролері суворо протипоказане: форматування тексту через `snprintf()` завантажує процесор обчисленнями ділення, роздуває обсяг носія у 3–5 разів і позбавляє датасет точної часової прив'язки.

Дані упаковуються в компактні **бінарні кадри фіксованої довжини**, кожен із яких містить обов'язкові службові поля:

```
[ Magic: 0xAA55 (2B) ] [ Stream ID (1B) ] [ Flags (1B) ] 
[ Sequence Counter (4B) ] [ Hardware Timestamp (8B) ] 
[ Payload Length (2B) ] [ Raw Sensor Data (N байт) ] [ CRC32 (4B) ]
```

Ключовими тут є два поля:
- **Апаратна мітка часу (Timestamp):** значення 32- або 64-бітного апаратного таймера високої точності (з роздільною здатністю 1 мікросекунда), а не системний лічильник `millis()`, який страждає від джитера планувальника операційної системи. Точний час дозволяє ідеально синхронізувати між собою потоки, що знімалися різними датчиками на різних фізичних шинах (наприклад, співставити стрибок струму двигуна з фазою вібраційного сплеску).
- **Наскрізний лічильник пакетів (Sequence Counter):** монотонно зростаюче ціле число `0, 1, 2, 3...`. Якщо через непередбачену апаратну затримку буфер усе ж переповнився, аналізатор датасету на комп'ютері миттєво зафіксує розрив послідовності `seq[i] != seq[i-1] + 1` і відкине пошкоджене вікно, не допустивши потрапляння фальшивих нулів чи зсувів фази в навчальну вибірку.

Повний робочий код модуля логування з подвійною буферизацією та захистом від переповнення наведено у вставці [надійний бінарний логер сенсорних потоків на C та C++](root:embedded/vlasnyi-nabir-danykh-iz-vlasnoho-prystroiu/proj-sensor-logger.md).

#### Проблема аліасингу та аналоговий вхідний тракт

Важливий аспект, про який часто забувають під час збору високочастотних сигналів (струму та вібрації), — це **ефект накладання спектрів (аліасинг)**. Теорема Котельникова-Найквіста вимагає, щоб частота дискретизації `f_s` перевищувала найвищу частоту сигналу щонайменше вдвічі. Якщо в механічній системі присутні високочастотні вібрації чи комутаційні шуми ШІМ на частоті 24 кГц, а ви опитуєте акселерометр на частоті 1.6 кГц без аналогового антиаліасингового фільтра низьких частот (RC-ланцюжка на вході АЦП чи вбудованого аналогового фільтра MEMS-чіпа), енергія шуму 24 кГц не зникне. Вона відіб'ється в робочу смугу 0..800 Гц у вигляді фальшивих низькочастотних гармонік, які неможливо відфільтрувати програмно після оцифрування.

Тому перед початком логування вбудований фільтр сенсора налаштовують на смугу `f_cutoff ≤ 0.4 · f_s`, або застосовують апаратну надлишкову вибірку (англ. *oversampling*) з подальшою цифровою децимацією.

### 2. Баланс класів: парадокс точності та методи подолання

Зібравши перші 100 годин безперервного логування з працюючого агрегату (наприклад, конвеєрного редуктора чи двигуна квадрокоптера), інженер стикається з фундаментальною статистичною властивістю реальних фізичних систем: **аномалій завжди в сотні й тисячі разів менше, ніж нормальної штатної роботи**.

Підшипник обертається абсолютно справно 99.9% усього життєвого циклу. Реальний перегрів, скол зуба шестерні чи випадіння фази статора триває лічені секунди або трапляється раз на кілька місяців. У результаті зібраний датасет містить 999 000 вибірок класу «Норма» і лише 1 000 вибірок класу «Аварія».

![Дисбаланс класів та зміна парадигми навчання](/root/course/embedded/vlasnyi-nabir-danykh-iz-vlasnoho-prystroiu/img/class-imbalance-solutions.svg)
*Проблема дисбалансу класів у сенсорних даних. Наївний класифікатор досягає 99.9% формальної точності ціною повної сліпоти до реальних аварій. Подолання вимагає переходу до керованого збурення стендів або навчання на нормі через автоенкодери та One-Class моделі.*

#### Парадокс точності (Accuracy Paradox)

Якщо на такому незбалансованому наборі навчити звичайну класифікаційну нейромережу (що мінімізує функцію втрат перехресної ентропії Cross-Entropy), відбувається катастрофа, яку важко помітити за стандартними звітами:

```
Загальна кількість прикладів: 1 000 000
Клас «Норма»:                  999 000 (99.9%)
Клас «Аварія»:                   1 000 (0.1%)

Поведінка моделі: «Завжди передбачати НОРМА»
Формальна точність (Accuracy): 999 000 / 1 000 000 = 99.9%
Повнота виявлення аварій (Recall): 0 / 1 000 = 0.0%
```

Формально алгоритм показує вражаючу точність `99.9%`, але практична цінність такого детектора дорівнює нулю: він повністю сліпий до всіх критичних інцидентів. 

Через це під час роботи з сенсорними даними мікроконтролерів метрика загальної точності (англ. *Accuracy*) **заборонена до використання як єдиний критерій**. Якість системи оцінюють виключно за метриками цільового класу аварій:
- **Влучність (Precision):** частка справжніх поломок серед усіх випадків, коли детектор підняв тривогу (захист від хибних спрацювань).
- **Повнота (Recall / Sensitivity):** частка виявлених поломок від усіх аварій, що реально сталися (захист від пропуску катастрофи).
- **F1-міра та PR-AUC:** гармонійне середнє між влучністю та повнотою та площа під кривою Precision-Recall.

#### Три інженерні стратегії розв'язання проблеми дисбалансу

Щоб навчити модель розпізнавати рідкісні події за браку реальних аварійних записів, застосовують три комплементарні підходи:

##### 1. Активний збір крайових випадків та штучні збурення
Чекати природного виходу з ладу високонадійного вузла можна роками. Замість пасивного запису інженери будують спеціальні випробувальні стенди (англ. *Hardware Test Benches*), де дефекти вносяться контрольовано та безпечно:
- **Контрольоване пошкодження деталей:** на зовнішнє кільце піддослідного підшипника мікрофрезою або електроерозією наноситься мікротріщина шириною 100–300 мкм; на крильчатку вентилятора чи пропелер наклеюється тягарець для створення дисбалансу; на обмотку статора через реле підключається шунт для імітації міжвиткового замикання.
- **Граничні режими навантаження:** робота на підвищеній швидкості, різкі гальмування з реверсом, робота за зниженої напруги живлення, створення штучного люфту кріплення.
- **Синхронізація з еталонним датчиком:** під час випробувань поряд із бортовим дешевим сенсором встановлюють прецизійний повірений п'єзоелектричний акселерометр або оптичний лазерний віброметр, що дає об'єктивну еталонну мітку істини (англ. *Ground Truth*).

##### 2. Однокласове моделювання (One-Class Classification)
Якщо природу можливих аварій неможливо передбачити заздалегідь (деталі можуть ламатися десятками різних невідомих способів), від задачі бінарної чи багатокласової класифікації повністю відмовляються. 

Замість цього застосовують алгоритми однокласової класифікації (англ. *One-Class SVM*, *Isolation Forest*), які навчаються **виключно на безпечному масиві нормальної роботи**. Алгоритм будує компактну гіперповерхню, що щільно охоплює хмару точок нормального стану. Будь-який новий вхідний вектор, що опиняється за межами цієї оболонки, автоматично класифікується як аномалія, навіть якщо такий тип несправності ніколи раніше не зустрічався.

##### 3. Детекція аномалій на базі автоенкодерів (Autoencoder Reconstruction)
Найбільш гнучкий та ефективний підхід для мікроконтролерів — використання штучної нейромережі архітектури [автокодер](root:sf-ml/autoencoder). Мережа складається з кодувальника, який стискає вектор вибірок датчика у вузький прихований простір (англ. *bottleneck*), та декодувальника, що відновлює вихідний сигнал.

```
Вхідний спектр x (128 чисел) ──► [ Кодувальник ] ──► Вузьке горло z (8 чисел) 
                                                          │
Вихідний спектр x̂ (128 чисел) ◄── [ Декодувальник ] ◄──────┘

Похибка реконструкції = MSE(x, x̂) = (1/N) · ∑ (x[i] - x̂[i])²
```

Мережу тренують лише на терабайтах здорової роботи. Завдяки вузькому горлу автокодер навчається відтворювати лише характерні гармоніки справного механізму. Коли на вхід потрапляє сигнал із новою патологічною вібрацією, мережа не здатна його реконструювати: похибка відновлення `MSE(x, x̂)` стрибкоподібно зростає. 

Перевищення заздалегідь встановленого порогу похибки сигналізує про виникнення аномалії. Детальний математичний апарат налаштування порогів та алгоритм детекції розібрано в темі про [нейромережеву діагностику вібрацій](root:embedded/vibration-anomaly-ml).

#### Порівняння моделей детекції аномалій для вбудованих систем

Вибір методу детекції аномалій визначається обчислювальними ресурсами цільового мікроконтролера:

| Метод | Потреба в RAM | Потреба у Flash | Швидкість інференсу | Здатність до генералізації |
|---|---|---|---|---|
| **One-Class SVM** | Середня (зберігання опорних векторів) | Низька (10–30 КБ) | `O(N_vectors · D)` (повільніша при великій базі) | Добре працює на простих ознаках (RMS, пік) |
| **Isolation Forest** | Висока (дерева рішень у пам'яті) | Середня (30–80 КБ) | `O(Trees · Depth)` (дуже швидка) | Чутливий до шуму у багатовимірних спектрах |
| **Повністю зв'язаний автоенкодер** | Дуже низька (2–8 КБ під активації) | Низька (15–40 КБ під квантовані ваги) | `O(W · H)` (стабільний детермінований час) | Висока точність на стиснених FFT-спектрах |
| **1D-згортковий автоенкодер (Conv1D)** | Середня (16–48 КБ) | Середня (50–150 КБ) | Помірна (потребує CMSIS-NN оптимізації) | Відмінно виділяє складні часові патерни в сирому сигналі |

Для мікроконтролерів класу ARM Cortex-M4/M7 оптимальним компромісом найчастіше є повністю зв'язаний автоенкодер, що приймає на вхід 64 або 128 смуг амплітудного спектра, розрахованого апаратним модулем FFT.

### 3. Розбіжність розподілів: чому лабораторні моделі відмовляють у полі

Навіть якщо датасет зібрано на власному пристрої та збалансовано за класами, виникає наступний бар'єр на шляху до надійного виробу — **розбіжність розподілів даних** (англ. *Data Drift* або *Covariate Shift*). Це явище, за якого статистичні характеристики вхідних сигналів змінюються в процесі реальної експлуатації, хоча фізична природа діагностованого явища залишається незмінною.

Модель, навчена в теплому сухому приміщенні лабораторії за стабільної температури `+22°C` на новому щойно зібраному прототипі, потрапляє у польові умови — і починає масово помилятися.

![Розбіжність розподілів сенсорних даних та аугментація](/root/course/embedded/vlasnyi-nabir-danykh-iz-vlasnoho-prystroiu/img/sensor-data-drift.svg)
*Розбіжність розподілів між лабораторією та польовими умовами. Зміна температури, механічний знос та електромагнітні завади виводять робочу точку за межі навчальної вибірки. Аугментація часових рядів розширює охоплення моделі ще до польових випробувань.*

#### Фізичні джерела дрейфу в апаратурі

1. **Температурний дрейф напівпровідникових та MEMS-структур:**
   Кремнієві п'єзорезистори та мікромеханічні балки ємнісних акселерометрів і гіроскопів мають виражений коефіцієнт температурного розширення. Зміна температури корпусу від `-15°C` взимку до `+60°C` біля нагрітого силового мосфета зсуває точку нульового рівня (англ. *Zero-g Offset*) на десятки одиниць LSB та змінює масштабний коефіцієнт чутливості (англ. *Sensitivity Scale Factor*). Якщо модель орієнтується на абсолютні амплітуди, температурний зсув вона сприймає як механічне пошкодження.
2. **Технологічний розкид компонентів (Unit-to-Unit Variation):**
   Два серійні пристрої, зібрані за однією схемою, не є ідентичними. Опір вимірювального шунта має допуск `±1%`, внутрішнє опорне джерело напруги АЦП мікроконтролера плаває на `±2%`, жорсткість пружин демпферів та момент затяжки кріпильних гвинтів корпусу варіюються від екземпляра до екземпляра. Модель, навчена на пристрої №1, виявляється невідкаліброваною для пристрою №2.
3. **Механічне старіння та знос:**
   У міру напрацювання мотогодин посадки підшипників набувають мікролюфтів, приводні ремені послаблюються, а мастило гусне або вимивається. Власна резонансна частота механічної конструкції плавно зміщується на кілька десятків герц.
4. **Електромагнітні наведення від силового тракту:**
   При зміні напруги акумуляторної батареї або перемиканні частоти ШІМ регуляторів обертів двигуна (ESC) змінюється спектральний склад високочастотних перешкод, що пролазять на аналогові лінії датчиків через паразитні ємності друкованої плати.

#### Аугментація сенсорних часових рядів

Щоб захистити бортову модель від дрейфу та навчити її узагальнювати фізичну сутність сигналів, застосовують спеціалізовані методи [аугментації даних](root:sf-ml/data-augmentation), адаптовані саме під одновимірні часові ряди сенсорів:

- **Дрожання та шум (Jittering / Noise Injection):**
  Додавання до сигналу гаусового шуму з нульовим середнім та стандартним відхиленням `σ = (0.01..0.05) · RMS(сигналу)`, а також випадкових одиничних імпульсних сплесків (англ. *Salt-and-Pepper noise*), що імітують комутаційні завади від перемикання реле та силових транзисторів.
- **Масштабування амплітуди (Scaling):**
  Множення всього часового вікна на випадковий коефіцієнт `α ∈ [0.85 .. 1.15]`. Це змушує модель спиратися на відносне співвідношення частот і форму спектрального профілю, а не на абсолютний рівень вібрації чи струму, який коливається залежно від навантаження.
- **Часова деформація (Time Warping / Frequency Stretching):**
  Локальне розтягування або стискання часової осі вибірки за допомогою сплайнової інтерполяції. Це імітує невелику нестабільність обертів валу двигуна (наприклад, коливання частоти обертання `±3%` під впливом зміни напруги живлення).
- **Штучний дрейф нульової лінії (Offset Drift Injection):**
  Додавання до вибірки лінійного тренду або постійної складової випадкової величини `x_aug[t] = x[t] + k · t + C`. Це позбавляє модель залежності від абсолютного зміщення нуля АЦП під час нагрівання мікросхеми.
- **Змішування середовищ (Acoustic / Sensor Mixup):**
  Додавання до чистого лабораторного запису фрагментів реального фонового шуму (наприклад, звуку вітру, гулу вентиляторів охолодження чи вібрації сусіднього компресора), записаних окремо в польових умовах.

### 4. Розмітка та віконна сегментація сенсорних потоків

Розмітка часових рядів фундаментально відрізняється від розмітки зображень: неможливо навісити мітку класу на одну окрему вибірку АЦП чи одну координату акселерометра, оскільки миттєве значення амплітуди не несе діагностичної інформації.

Одиницею аналізу в Edge ML завжди є **ковзне часове вікно** (англ. *Sliding Window*) фіксованої довжини `N` відліків (зазвичай степеня двійки для зручності швидкого перетворення Фур'є: 256, 512, 1024 або 2048 вибірок).

```
Потік вибірок:  [ s₀, s₁, s₂, s₃, s₄, s₅, s₆, s₇, s₈, s₉, s₁₀, s₁₁, ... ]
Вікно 1 (L=4):  [ s₀, s₁, s₂, s₃ ] ──────────────► Вектор ознак 1
Вікно 2 (Step=2):      [ s₂, s₃, s₄, s₅ ] ────────► Вектор ознак 2  (Перекриття 50%)
Вікно 3 (Step=2):            [ s₄, s₅, s₆, s₇ ] ──► Вектор ознак 3
```

#### Правила побудови та розмітки вікон

1. **Крок зсуву та перекриття (Stride & Overlap):**
   Вікна накладаються з перекриттям (англ. *Overlap*) від 50% до 87.5%. Це збільшує кількість навчальних прикладів без повторного збору даних і гарантує, що короткочасний аномальний сплеск не потрапить на край вікна, де його амплітуду зріже віконна функція Ханна або Хеммінга.
2. **Сесійна та синхронна розмітка за подіями:**
   Розмітка виконується не вручну вибірка за вибіркою, а на рівні сесій та журналів подій. Під час випробувань оператор або стендовий контролер фіксує точні часові інтервали:
   `[14:02:15.120 – 14:02:45.800] — Режим: Холостий хід, Стан: Норма`
   `[14:03:10.050 – 14:03:22.400] — Режим: Максимальне навантаження, Стан: Штучний перекіс фази`
   Після вивантаження бінарного логу скрипт парсингу автоматично нарізає вікна та призначає мітки на основі монотонних часових міток.
3. **Ізоляція тестових сесій від навчальних:**
   Неприпустимо перемішувати вікна з одного польоту чи одного сеансу роботи між навчальною та валідаційною вибірками. Через перекриття сусідні вікна містять майже ідентичні відліки, що створює фальшивий витік даних (англ. *Data Leakage*). **Поділ на Train/Val/Test повинен здійснюватися виключно цілими незалежними сесіями (днями, випробувальними циклами, окремими екземплярами пристроїв)**.

### 5. Практична реалізація: підготовка вхідного вікна на C та C++

Щоб модель, навчена мовою Python, видавала однакові результати на борту, математична обробка сирого буфера на пристрої має бути байт-у-байт ідентичною до коду підготовки датасету. 

Наведений нижче модуль формує вхідне нормалізоване вікно вибірок із перевіркою апаратної цілісності часових міток та відстеженням стабільності частоти дискретизації.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>
#include <math.h>

#define WINDOW_SIZE     256
#define EXPECTED_DT_US  1000  // Очікуваний період між вибірками: 1000 мкс (1 кГц)
#define DT_TOLERANCE_US 150   // Допустимий джитер таймера ±150 мкс

typedef struct {
    int16_t  raw_samples[WINDOW_SIZE];
    uint64_t timestamps[WINDOW_SIZE];
    uint32_t head_idx;
    uint32_t count;
    uint64_t last_timestamp;
    uint32_t timing_errors;
} SensorWindowCollector;

void window_collector_init(SensorWindowCollector *w) {
    w->head_idx = 0;
    w->count = 0;
    w->last_timestamp = 0;
    w->timing_errors = 0;
}

// Додавання нової вибірки з перевіркою монотонності часу
bool window_collector_push(SensorWindowCollector *w, int16_t sample, uint64_t timestamp_us) {
    if (w->last_timestamp != 0) {
        int64_t dt = (int64_t)(timestamp_us - w->last_timestamp);
        // Перевірка на пропуск вибірки або заклинювання таймера
        if (dt < (EXPECTED_DT_US - DT_TOLERANCE_US) || dt > (EXPECTED_DT_US + DT_TOLERANCE_US)) {
            w->timing_errors++;
        }
    }
    w->last_timestamp = timestamp_us;

    w->raw_samples[w->head_idx] = sample;
    w->timestamps[w->head_idx] = timestamp_us;

    w->head_idx = (w->head_idx + 1) % WINDOW_SIZE;
    if (w->count < WINDOW_SIZE) {
        w->count++;
    }

    return (w->count == WINDOW_SIZE);
}

// Експорт лінеаризованого та нормалізованого вікна для нейромережі
bool window_collector_export(const SensorWindowCollector *w, float *out_features, float scale_factor) {
    if (w->count < WINDOW_SIZE) {
        return false;
    }

    // Вичитка циклічного буфера в хронологічному порядку
    uint32_t start_idx = w->head_idx;
    for (uint32_t i = 0; i < WINDOW_SIZE; ++i) {
        uint32_t idx = (start_idx + i) % WINDOW_SIZE;
        // Переведення в одиниці фізичної величини з нормалізацією
        out_features[i] = (float)w->raw_samples[idx] * scale_factor;
    }
    return true;
}
```
```cpp
#include <cstdint>
#include <cstddef>
#include <array>
#include <span>
#include <expected>
#include <chrono>
#include <algorithm>

template <size_t WindowSize = 256, uint32_t ExpectedPeriodUs = 1000, uint32_t ToleranceUs = 150>
class SensorWindowCollector {
public:
    enum class Error {
        BufferIncomplete,
        TimingJitterExceeded
    };

    SensorWindowCollector() = default;

    // Додавання нової вибірки з контролем часового інтервалу
    bool push(int16_t sample, std::chrono::microseconds timestamp) noexcept {
        const uint64_t ts_us = static_cast<uint64_t>(timestamp.count());
        if (last_timestamp_ != 0) {
            const int64_t dt = static_cast<int64_t>(ts_us - last_timestamp_);
            if (dt < static_cast<int64_t>(ExpectedPeriodUs - ToleranceUs) ||
                dt > static_cast<int64_t>(ExpectedPeriodUs + ToleranceUs)) {
                timing_errors_++;
            }
        }
        last_timestamp_ = ts_us;

        raw_samples_[head_idx_] = sample;
        timestamps_[head_idx_] = ts_us;

        head_idx_ = (head_idx_ + 1) % WindowSize;
        if (count_ < WindowSize) {
            count_++;
        }

        return (count_ == WindowSize);
    }

    // Експорт нормалізованого вікна у вихідний буфер інференсу
    std::expected<void, Error> exportNormalized(
        std::span<float, WindowSize> output,
        float scale_factor) const noexcept 
    {
        if (count_ < WindowSize) {
            return std::unexpected(Error::BufferIncomplete);
        }

        const size_t start_idx = head_idx_;
        for (size_t i = 0; i < WindowSize; ++i) {
            const size_t idx = (start_idx + i) % WindowSize;
            output[i] = static_cast<float>(raw_samples_[idx]) * scale_factor;
        }

        return {};
    }

    [[nodiscard]] uint32_t timingErrors() const noexcept {
        return timing_errors_;
    }

    [[nodiscard]] bool isFull() const noexcept {
        return count_ == WindowSize;
    }

private:
    std::array<int16_t, WindowSize> raw_samples_{};
    std::array<uint64_t, WindowSize> timestamps_{};
    size_t head_idx_{0};
    size_t count_{0};
    uint64_t last_timestamp_{0};
    uint32_t timing_errors_{0};
};
```
