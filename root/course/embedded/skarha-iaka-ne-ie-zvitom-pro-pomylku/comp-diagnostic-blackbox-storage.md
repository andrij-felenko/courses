# Енергонезалежне сховище діагностичного журналу (Blackbox Storage)

Енергонезалежне сховище аварійного журналу («чорна скринька», англ. *diagnostic blackbox storage*) — це виділений апаратний енергонезалежний масив пам'яті (FRAM, MRAM, EEPROM або виділений сектор NOR Flash із буферизованим RTC Backup SRAM), призначений для детермінованого збереження повного діагностичного контексту (англ. *crash dump*) у момент раптового збою, апаратного зависання або аварійного знеструмлення пристрою. Без спеціалізованої апаратної організації збереження діагностики розробник залишається сліпим перед польовими відмовами: звичайний запис у Flash-пам'ять займає мілісекунди й вимагає сотень міліампер струму, через що при просіданні напруги процесор зависає до завершення запису, безповоротно спотворюючи файлову систему та втрачаючи причину перезапуску.

---

### Апаратні технології пам'яті для фіксації аварій

Вибір фізичного носія для діагностичного журналу визначається трьома критичними фізичними параметрами:
1. **Час запису одного байта/блока (`t_write`):** скільки часу мікросхема утримує шину під час фіксації транзакції.
2. **Енергоспоживання під час запису (`I_write`):** струм, необхідний для зміни стану комірки пам'яті.
3. **Ресурс циклів перезапису (Endurance):** гарантована кількість циклів запису до деградації діелектрика або магнітного переходу.

```
+-------------------+----------------+----------------+-------------------+------------------+
| Тип носія пам'яті | Час запису     | Струм запису   | Ресурс (циклів)   | Енергонезалежність|
+-------------------+----------------+----------------+-------------------+------------------+
| RTC Backup SRAM   | ~10..30 нс     | < 1 мкА        | Необмежений       | Потрібна батарея |
| FRAM (FeRAM)      | ~50..150 нс    | ~0.3..1.5 мА   | 10¹⁴ (трильйони)  | Повна фізична    |
| MRAM              | ~35..100 нс    | ~2..5 мА       | 10¹²..10¹⁴        | Повна фізична    |
| EEPROM (I2C/SPI)  | ~3..5 мс       | ~1..3 мА       | 10⁶ (мільйон)     | Повна фізична    |
| NOR Flash (SPI)   | ~0.5..3.0 мс   | ~15..35 мА     | 10⁵ (100 тисяч)   | Повна фізична    |
+-------------------+----------------+----------------+-------------------+------------------+
```

#### 1. Сегмент Backup SRAM з автономним іоністором або батареєю
Усередині багатьох мікроконтролерів (зокрема лінійок STM32F4/F7/H7, NXP LPC, ESP32) передбачено енергонезалежний блок статичної оперативної пам'яті обсягом від 2 до 4 КБ, підключений до домену живлення `V_BAT`. 
- **Фізична перевага:** запис виконується за один такт шини без затримок (нуль мілісекунд очікування сторінки).
- **Обмеження:** при повному розряді резервного джерела (або при заміні батарейки техніком) пам'ять повністю обнуляється.

#### 2. Фероелектрична пам'ять (FRAM, англ. *Ferroelectric RAM*)
FRAM використовує поляризацію кристалічної ґратки титанату цирконату свинцю (`PZT`). Зміна стану поляризації відбувається за наносекунди під дією електричного поля без тунелювання заряду крізь ізолятор.
- **Фізична перевага:** практично нескінченний ресурс (до `10¹⁴` циклів запису), миттєва готовність до запису байта без попереднього стирання сектора, низький струм запису (менше 1 мА при 20 МГц SPI).
- **Практичне застосування:** ідеальний вибір для апаратних реєстраторів швидкоплинних відмов, де snapshot системи оновлюється кожні кілька мілісекунд у фоні.

#### 3. Зовнішня SPI/QSPI NOR Flash
Найдешевший і найбільш місткий тип носія (від 4 до 128 МБ).
- **Головна пастка під час аварії:** запис вимагає попереднього стирання сектора (4 КБ), яке триває від 40 до 300 мілісекунд. Спроба записати Core Dump безпосередньо у Flash під час переривання `HardFault` за умови падіння вхідної напруги гарантовано закінчиться зависанням шини або пошкодженням сусідніх секторів.
- **Архітектурне правило:** прямий запис у NOR Flash під час аварії дозволений лише за наявності буферного накопичувального конденсатора, що гарантує час утримання живлення.

### Розрахунок накопичувального конденсатора живлення (Power-Hold-up)

Щоб процесор гарантовано встиг записати діагностичний кадр аварії (англ. *Incident Snapshot Frame*) розміром `S = 256 байтів` у зовнішнє сховище при раптовому висмикуванні кабелю або відключенні акумулятора, вхідний каскад живлення повинен містити накопичувальний конденсатор `C_hold`.

Енергія `E`, що виділяється конденсатором при розряді від робочої напруги `V_nom` до мінімальної робочої напруги мікроконтролера `V_min` (поріг скидання Brown-Out Reset, BOR):

```
E_cap = 1/2 · C_hold · (V_nom² - V_min²)
```

Необхідна енергія для виконання запису складається з енергії роботи ядра процесора та енергії інтерфейсу пам'яті протягом часу запису `t_flush`:

```
E_req = (V_avg · I_mcu + V_avg · I_mem) · t_flush
```

Розрахунок ємності для типового сценарію аварійної фіксації у SPI EEPROM проти SPI FRAM:
- `V_nom = 3.3 В`, `V_min = 2.4 В` (поріг спрацьовування BOR Level 3).
- Струм споживання системи під час аварійного запису `I_total = 20 мА = 0.020 А`.
- **Сценарій А (SPI EEPROM):** час запису сторінки `t_flush = 5 мс = 0.005 с`.
- **Сценарій Б (SPI FRAM):** час запису 256 байтів на частоті 10 МГц `t_flush = 0.25 мс = 0.00025 с`.

Розрахунок мінімальної ємності накопичувача:

```
C_hold_min = (2 · I_total · V_avg · t_flush) / (V_nom² - V_min²)

Для EEPROM (t = 5 мс):
C_hold = (2 · 0.020 · 2.85 · 0.005) / (3.3² - 2.4²)
       = 0.00057 / (10.89 - 5.76)
       = 0.00057 / 5.13 ≈ 111 мкФ

Для FRAM (t = 0.25 мс):
C_hold = (2 · 0.020 · 2.85 · 0.00025) / 5.13 ≈ 5.5 мкФ
```

Висновок: використання швидкої енергонезалежної пам'яті (FRAM/MRAM) зменшує вимоги до накопичувальної ємності плати у 20 разів, дозволяючи обійтися компактними керамічними конденсаторами типорозміру 0805 замість громіздких електролітичних ємностей.

### Топологія кільцевого буфера подій у Flash/FRAM

Діагностичне сховище організовується у вигляді кільцевого лога (англ. *ring buffer*) із подвійним індексуванням, де кожний запис захищений контрольною сумою CRC16/CRC32.

```
       СТРУКТУРА КІЛЬЦЕВОГО ЖУРНАЛУ В ЕНЕРГОНЕЗАЛЕЖНОМУ СХОВИЩІ
       
  Сектор 0 (Header)     Сектор 1 (Slot 0)     Сектор 2 (Slot 1)     Сектор N (Slot N-1)
 ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
 │ Magic: 0x54524742│  │ Timestamp: 10423 │  │ Timestamp: 10424 │  │ Timestamp: 10422 │
 │ Head Index: 0x02 │  │ Event: I2C_FAIL  │  │ Event: HARDFAULT │  │ Event: BOOT_OK   │
 │ Tail Index: 0x00 │  │ Regs: PC, LR...  │  │ Regs: PC, LR...  │  │ Regs: PC, LR...  │
 │ CRC32 Header     │  │ CRC32 Payload    │  │ CRC32 Payload    │  │ CRC32 Payload    │
 └──────────────────┘  └──────────────────┘  └──────────────────┘  └──────────────────┘
```

#### Захист від зносу та апаратна відмовостійкість:
1. **Атомарний заголовок транзакції:** перед записом тіла кадру записується маркер `STATE_IN_PROGRESS`. Після успішного запису всіх даних та перевірки CRC виставляється біт `STATE_COMMITTED`.
2. **Перевірка цілісності при старті:** якщо під час завантаження знайдено запис зі статусом `STATE_IN_PROGRESS` та невалідною CRC, система реєструє подію «Збій живлення під час аварійного запису» (англ. *Incomplete Dump on Power Loss*) і не пошкоджує попередні коректні логи.
3. **Розділення циклів:** часті логи (стан шин, температура, напруга кожні 10 секунд) спрямовуються у швидку FRAM, тоді як великі знімки пам'яті (Core Dump) фіксуються у NOR Flash лише за фактом критичної аварії.
