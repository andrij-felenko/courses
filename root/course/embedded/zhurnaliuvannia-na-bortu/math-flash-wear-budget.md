# 🧮 Розрахунок ресурсу Flash-пам'яті, зносу секторів і бюджету енергії бортового журналу

У вбудованій системі безперервний запис логів без математичного розрахунку зносу Flash-пам'яті призводить або до передчасної фізичної деградації кремнію (пробою оксиду тунелювання у комірках NOR Flash), або до несподіваного виснаження автономної батареї через часті пробудження радіомодема. Цей розрахунок виводить аналітичні моделі довговічності кільцевого буфера на секторах Flash, коефіцієнта посилення запису (Write Amplification Factor, WAF), допустимої частоти генерації подій і порівняльного балансу енергії між збереженням у Flash та передачею через бездротовий канал (NB-IoT / BLE).

## 1. Фізична модель зносу NOR Flash і термін служби кільцевого буфера

Комірка NOR Flash зберігає заряд на плаваючому затворі (Floating Gate) або у пастці заряду (Charge Trap). Операція стирання сектору переводить біти з `0` в `1` за допомогою тунелювання Фаулера-Нордгейма високою напругою (12–18 В), що створює дефекти в підзатворному діелектрику (stress-induced leakage current). Виробники мікросхем SPI Flash (наприклад, Winbond W25Q32JV або Adesto AT25FF081) гарантують ресурс стирань:

```
E_max = 100000 циклів стирання на сектор (Endurance rating)
```

Нехай для кільцевого буфера журналювання на мікроконтролері виділено область розміром `S_total` байтів, яка складається з `N_sec` фізичних секторів по `S_sec` байтів кожен:

```
S_total = N_sec · S_sec
```

Для типової області 64 КБ при розмірі сектора 4096 байтів:

```
N_sec = 64 · 1024 / 4096 = 16 секторів
```

Якщо прошивка генерує журнал із середньою швидкістю `R_byte` байтів на секунду (або `R_rec` записів на секунду із середнім розміром запису `L_rec`), то повний обіг кільцевого буфера відбувається за час `T_ring`:

```
T_ring = S_total / R_byte = (N_sec · S_sec) / (R_rec · L_rec)
```

Оскільки кільцевий буфер здійснює вирівнювання зносу (Wear Leveling) природним циклічним просуванням голови запису по всіх `N_sec` секторах, кожен окремий сектор стирається рівно один раз за час `T_ring`. Загальний термін служби буфера `T_life` до досягнення граничного зносу комірок `E_max` визначається як:

```
T_life = E_max · T_ring
       = (E_max · N_sec · S_sec) / R_byte      [множення ресурсу циклів на період обігу]
```

### Покроковий розрахунок життєвого циклу пристрою

Порівняймо два інженерних підходи до журналювання: наївний запис рядків ASCII проти бінарного токенізованого формату.

**Вхідні параметри:**
- Виділена область Flash: `S_total = 64 КБ = 65536 байтів` (`N_sec = 16`, `S_sec = 4096`).
- Ресурс стирань сектора: `E_max = 100000` циклів.
- Інтенсивність подій: 1 запис на секунду (`R_rec = 1.0 с⁻¹`).

**Варіант А (Текстовий лог ASCII, середній розмір `L_rec = 80 байтів`):**
```
R_byte = 1.0 · 80 = 80 байтів/с

T_ring = 65536 / 80 = 819.2 с ≈ 13.65 хвилин

T_life = 100000 · 819.2 с
       = 81920000 секунд
       = 948.1 доби ≈ 2.6 року
```

**Варіант Б (Двійковий токенізований лог, фіксований розмір `L_rec = 12 байтів`):**
```
R_byte = 1.0 · 12 = 12 байтів/с

T_ring = 65536 / 12 = 5461.3 с ≈ 1.52 години

T_life = 100000 · 5461.3 с
       = 546133333 секунд
       = 6321.0 діб ≈ 17.3 року
```

Токенізація знижує фізичне навантаження на кремній у `80 / 12 = 6.67` раза, переводячи ресурс Flash за межі типового 10-річного терміну служби промислового приладу.

## 2. Коефіцієнт посилення запису (Write Amplification Factor)

Коефіцієнт посилення запису `WAF` визначає відношення обсягу фізично записаних у Flash байтів до обсягу корисних прикладних даних журналу:

```
WAF = B_flash_written / B_payload_data
```

У секторному кільцевому буфері посилення запису виникає через:
1. Заголовки записів (Magic, Length, Level, Timestamp, CRC16) — `H_rec` байтів на запис;
2. Заголовок сектора (Magic, Sequence, Erase Counter, State Flags) — `H_sec` байтів на сектор;
3. Невикористаний залишок у кінці сектора (Padding), якщо наступний запис не вміщується в поточний сектор — `P_sec` байтів на сектор.

Нехай сектор вміщує `K` записів. Тоді:

```
K = ⌊(S_sec - H_sec) / (H_rec + L_payload)⌋

P_sec = (S_sec - H_sec) - K · (H_rec + L_payload)
```

Фізично записано за один сектор:

```
B_flash_written = S_sec - P_sec = H_sec + K · (H_rec + L_payload)
```

Корисний обсяг даних за сектор:

```
B_payload_data = K · L_payload
```

Тоді формулу `WAF` розгортаємо так:

```
WAF = (H_sec + K · (H_rec + L_payload)) / (K · L_payload)
    = (H_sec / (K · L_payload)) + (H_rec / L_payload) + 1    [розбиття на складові накладних витрат]
```

### Числовий приклад розрахунку WAF

**Параметри структури:**
- `S_sec = 4096 байтів`, заголовок сектора `H_sec = 16 байтів`;
- Заголовок запису `H_rec = 8 байтів` (2B Magic + 1B Len + 1B Level + 2B Mod/Seq + 2B CRC);
- Корисне навантаження токена `L_payload = 8 байтів` (4B TokenID + 4B Varargs).

Розрахунок місткості сектора:
```
Доступно під записи = 4096 - 16 = 4080 байтів
Розмір одного запису = 8 + 8 = 16 байтів
K = ⌊4080 / 16⌋ = 255 записів
Залишок P_sec = 4080 - (255 · 16) = 0 байтів

Корисні дані: B_payload = 255 · 8 = 2040 байтів
Фізичний запис: B_flash = 16 + (255 · 16) = 4096 байтів

WAF = 4096 / 2040 = 2.0078
```

Значення `WAF ≈ 2.0` показує, що для зберігання 8 байтів сирої інформації система записує 16 байтів на Flash. Це є еталонним показником для надійного структурованого логера з контролем цілісності.

## 3. Розрахунок енергетичного бюджету: Flash проти вивантаження в радіоканал

В автономних IoT-пристроях із живленням від літій-тіонілхлоридної (Li-SOCl₂) батареї ємністю `C_bat = 2400 мА·год` при напрузі `V_nom = 3.6 В` енергія є найдорожчим ресурсом.

Загальний запас енергії батареї:

```
E_total_joules = C_bat · 3600 с · V_nom / 1000
               = 2.4 А·год · 3600 с · 3.6 В = 31104 Дж
```

### Енергія локального запису на SPI Flash

Для мікросхеми Winbond W25Q32JV при `V_dd = 3.3 В`:
- Струм запису сторінки: `I_prog = 15 мА`, час запису сторінки (256 байтів): `T_prog = 0.7 мс = 0.0007 с`;
- Струм стирання сектора (4 КБ): `I_erase = 20 мА`, час стирання: `T_erase = 45 мс = 0.045 с`.

Енергія запису однієї сторінки (256 байтів):
```
E_page = V_dd · I_prog · T_prog
       = 3.3 В · 0.015 А · 0.0007 с
       = 34.65 мкДж  (0.135 мкДж на байт)
```

Енергія стирання одного сектора (4096 байтів):
```
E_erase_sec = V_dd · I_erase · T_erase
            = 3.3 В · 0.020 А · 0.045 с
            = 2.97 мДж  (0.725 мкДж на байт)
```

Повна локальна енергія збереження 1 байта логу у Flash:
```
E_flash_byte = (E_page_per_byte) + (E_erase_per_byte)
             = 0.135 мкДж + 0.725 мкДж
             = 0.860 мкДж/байт
```

Для одного 16-байтного запису:
```
E_flash_rec = 16 · 0.860 мкДж = 13.76 мкДж
```

### Енергія вивантаження через стільниковий модуль NB-IoT

Підключення та передача пачки логів через модуль Quectel BC66 (NB-IoT) за наявності встановленої RRC-сесії:
- Вихід із режиму eDRX/PSM і передача UDP/CoAP-пакета (512 байтів):
  - Піковий струм передавача (+23 dBm): `I_tx = 120 мА`, тривалість `T_tx = 350 мс`;
  - Прийом підтвердження (ACK Window): `I_rx = 30 мА`, тривалість `T_rx = 200 мс`.

Енергія сесії передачі пачки `B_batch = 512 байтів` (32 записи по 16 байтів):
```
E_tx = 3.6 В · 0.120 А · 0.350 с = 151.2 мДж
E_rx = 3.6 В · 0.030 А · 0.200 с = 21.6 мДж
E_radio_batch = 151.2 + 21.6 = 172.8 мДж

Енергія передачі 1 байта = 172.8 мДж / 512 = 337.5 мкДж/байт
Енергія передачі 1 запису = 16 · 337.5 мкДж = 5.40 мДж
```

### Порівняння витрат енергії

```
E_radio_rec / E_flash_rec = 5400 мкДж / 13.76 мкДж ≈ 392.4
```

Передача запису по радіоканалу NB-IoT коштує майже в 400 разів дорожче, ніж його локальне збереження в SPI Flash.

```
+-------------------------------------------------------------------------+
| Операція                   | Енергія на 1 запис (16B) | Частка батареї  |
+----------------------------+--------------------------+-----------------+
| Локальний запис на Flash   | 13.76 мкДж               | 0.00000004%     |
| Вивантаження пачкою NB-IoT | 5400.00 мкДж             | 0.00001736%     |
| Повне відновлення з'єднання| 45000.00 мкДж            | 0.00014467%     |
| (Cold Attach + TLS)        |                          |                 |
+-------------------------------------------------------------------------+
```

### Висновок для інженерної стратегії

1. **Буферизація обов'язкова:** Вивантажувати кожен лог-запис індивідуально в момент генерації — катастрофічно для батареї. Накопичення у Flash-буфері до повної пачки (512–1024 байти) заощаджує до 90% енергії радіотракту за рахунок амортизації витрат на встановлення сесії.
2. **Фільтрація на борту (Triage):** Оскільки запис у Flash енергетично «безкоштовний» (13.8 мкДж), збереження діагностичних подій `DEBUG/TRACE` у локальний кільцевий буфер є безпечним. Проте вивантажувати в мережу слід лише агреговані метрики та події `WARN/ERROR`, залишаючи детальні сліди у Flash для зчитування по BLE або USB під час сервісного обслуговування.
