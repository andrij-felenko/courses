Літієва дискова батарейка CR2032 має номінальну ємність близько 220 мА·год. Якщо під'єднати до неї бездротовий модуль із мікроконтролером, який у робочому стані споживає типові 25 мА, джерело живлення вичерпається всього за 8.8 години:

```
T_life = 220 мА·год / 25 мА
       = 8.8 год      [визначення автономності: ємність / активний струм]
```

Пристрій, призначений для автономного моніторингу температури на складі, контролю протікання води в колекторі чи вимірювання вібрації на опорі мосту, не може жити кілька годин: вартість заміни батареї на висоті або під землею в сотні разів перевищує вартість самого датчика. Автономна техніка зобов'язана працювати від одного елемента живлення п'ять, десять або п'ятнадцять років.

Єдиний фізичний спосіб подолати це обмеження — перестати живити вузли схеми безперервно. Якщо давачу температури потрібно лише один раз на п'ять хвилин виміряти показник і надіслати короткий радіопакет тривалістю десять мілісекунд, весь інший час (99.997% періоду) пристрій може перебувати у стані глибокого сну зі споживанням у лічені мікроампери. Це чергування активного спалаху та тривалої паузи визначає **шпаруватість** роботи пристрою.

## Шпаруватість як фундаментальний закон автономності

У радіотехніці та теорії сигналів періодичний імпульсний процес описують безрозмірним співвідношенням часу увімкненого стану до повного періоду повторення. У вітчизняній інженерній школі ця величина отримала назву **шпаруватість** (від пол. *szpara* або нім. *Sparsamkeit* — шпарина, проміжок між імпульсами; в англомовній літературі — *Duty Cycle*, або коефіцієнт заповнення).

Якщо активна фаза пристрою триває час `t_on`, а стан сну — `t_off`, повний період повторення циклу дорівнює:

```
T = t_on + t_off      [повний період як сума фази роботи й фази сну]
```

Коефіцієнт шпаруватості `D` (Duty Cycle) є відношенням активного інтервалу до повного періоду:

```
D = t_on / T
  = t_on / (t_on + t_off)      [частка часу, яку вузол перебуває в активному стані]
```

Шпаруватість змінюється від 0 (пристрій вимкнено назавжди) до 1 (пристрій працює безперервно без сну). У сучасних бездротових сенсорних вузлах (LPWAN, LoRaWAN, BLE-маяки) величина `D` становить від `0.001` (0.1%) до `0.00001` (0.001%).

Повний електричний заряд `Q_cycle`, що його пристрій витягує з джерела живлення за один період `T`, складається із заряду активного спалаху `Q_on` та заряду під час сну `Q_off`:

```
Q_cycle = Q_on + Q_off
        = I_on · t_on + I_sleep · t_off      [загальний заряд за один повний цикл]
```

Середній інтегральний струм споживання `I_avg`, який визначає темп виснаження хімічного джерела, є середнім арифметичним заряду за часом періоду:

```
I_avg = Q_cycle / T
      = (I_on · t_on + I_sleep · t_off) / T       [ділення повного заряду на тривалість періоду]
      = I_on · (t_on / T) + I_sleep · (t_off / T) [почленний поділ на доданки]
      = I_on · D + I_sleep · (1 - D)             [підстановка визначення D та (1 - D)]
```

Цей вираз — головний енергетичний закон автономної електроніки. Він демонструє, що загальне споживання пристрою не дорівнює струму передавача (50–150 мА) і не дорівнює струму сну (1–5 мкА), а є їхньою зваженою сумою, де вагами виступають частки часу `D` та `(1 - D)`. Детальне математичне дослідження цієї залежності та її граничних станів наведено в окремому розборі [математичної оптимізації шпаруватості](root:embedded/shparuvatist-roboty/math-duty-cycle-optimization.md).

> 🔧 **Навіщо це.** Шпаруватість перетворює мікроконтролер із «постійного споживача» на «генератор мікроімпульсів». Розуміння коефіцієнта заповнення дозволяє архітектору системи точно проектувати автономність: замість боротьби за зменшення струму передавача на 10% інженер збільшує інтервал сну вдвічі або скорочує час обчислень удвічі, зменшуючи інтегральне споживання на порядок.

## Декомпозиція фаз активності та сну: де ховаються мікроампери

Умовний поділ на «роботу» зі струмом `I_on` і «сон» зі струмом `I_sleep` є грубим спрощенням. На практиці активне вікно `t_on` складається з послідовності технологічних кроків, кожен з яких має власну тривалість і власний профіль струму.

![Декомпозиція фаз активності та сну](/root/course/embedded/shparuvatist-roboty/img/duty-cycle-phases.svg)
*Часова декомпозиція одного циклу шпаруватості. Активне вікно t_on складається з фаз пробудження, запуску давача, обчислень мікроконтролера та спалаху передавача. Більшу частину періоду займає фаза сну t_off зі споживанням у лічені мікроампери.*

Розгляньмо структуру активного вікна `t_on` крок за кроком:

1. **Пробудження та стабілізація тактування (`t_wu`, струм 5–15 мА, час 0.3–5 мс).** Сигнал пробудження від внутрішнього низькоспоживаючого RTC-таймера або зовнішньої ніжки переривання запускає внутрішній стабілізатор ядра мікроконтролера. Запускається високочастотний кварцовий генератор (HSE) або внутрішній RC-генератор, чекає фіксації фазового автопідстроювання частоти (PLL) та виходу живильних шин Flash-пам'яті на номінальну напругу. Допоки кварц не згенерував стабільну синусоїду заданої амплітуди, мікроконтролер не виконує корисного коду, але вже споживає міліампери. Подробиці вибору джерел тактування описано в темі про [ціну пробудження мікроконтролера](root:embedded/tsina-probudzhennia).
2. **Увімкнення та опитування давача (`t_sens`, струм 1–10 мА, час 1–20 мс).** Для збереження енергії зовнішній давач (акселерометр, газоаналізатор, давач тиску) живиться через окремий транзисторний ключ (load switch). Мікроконтролер відкриває ключ, чекає стабілізації внутрішнього АЦП давача, надсилає команду вимірювання по шині I²C або SPI та зчитує сирі байти даних.
3. **Обчислення, фільтрація та шифрування (`t_cpu`, струм 10–30 мА, час 0.5–5 мс).** Процесорне ядро (наприклад, ARM Cortex-M4 на частоті 64–80 МГц) перераховує сирі значення у фізичні величини, фільтрує шум цифровим фільтром, перевіряє порогові межі, пакує корисне навантаження та накладає криптографічний підпис (AES-128 або Speck) із підрахунком контрольної суми CRC-16/32.
4. **Робота бездротового трансивера (`t_radio`, струм 25–150 мА, час 5–60 мс).** Найбільш енергоємна частина. Радіотрансивер вмикає синтезатор частоти, калібрує ГКЧ (VCO), випромінює в ефір преамбулу, заголовок і пакет даних на потужності від +10 до +22 дБм, після чого короткочасно переходить у режим прийому (RX window) для очікування квитанції підтвердження (ACK).
5. **Завершення роботи та перехід у сон (`t_down`, струм 2–6 мА, час 0.1–0.5 мс).** Периферійні блоки вимикаються, транзисторний ключ живлення давача закривається, сигнальні лінії переводяться у високоімпедансний або низький стан для блокування паразитних витоків, і ядро виконує інструкцію входу в сон (`WFI` / `WFE`).

Спляча фаза `t_off` також не є «ідеальним нулем». У ній струм `I_sleep` формується сумою кількох джерел:

```
I_sleep = I_mcu_deep + I_ldo_q + I_sens_leak + I_pcb_leak      [структура струму спокою]
```

- `I_mcu_deep` — струм мікроконтролера в режимі глибокого сну з увімкненим RTC та збереженням вмісту оперативної пам'яті (0.5–2.5 мкА).
- `I_ldo_q` — власний струм спокою (quiescent current) лінійного або імпульсного регулятора напруги (0.8–5 мкА).
- `I_sens_leak` — струм витоку закритого ключа живлення або струм сенсора в стані Power-Down (0.05–1 мкА).
- `I_pcb_leak` — паразитні витоки через бруд на платі, захисні TVS-діоди, підтягувальні резистори та конденсатори (0.1–2 мкА). Повний алгоритм локалізації цих витоків викладено в темі про [аудит струму спокою плати](root:embedded/sleep-current-audit).

### Автономна периферія без пробудження процесорного ядра

Сучасні мікроконтролери містять апаратні механізми, які дозволяють виконувати вимірювання взагалі без пробудження енергоємного основного ядра Cortex-M:

- **Автономний фоновий режим (LPBAM у STM32U5):** контролер прямого доступу до пам'яті (LPDMA) самостійно активує АЦП або I²C, записує відліки в оперативну пам'ять і повертає шину в сон, споживаючи всього 30–50 мкА замість 10–15 мА основного ядра.
- **Програмована система подій (PPI / DPPI у Nordic nRF52/nRF54):** апаратні канали зв'язку між периферійними блоками дозволяють апаратному таймеру LPTIM запустити перетворення АЦП без участі ядра та без переривань.
- **Співпроцесори наднизького споживання (ULP-RISC-V в ESP32-C6 / ESP32-S3):** крихітне допоміжне ядро, що працює на частоті 20 МГц, періодично опитує цифрові датчики та перевіряє порогові значення, беручи лише 15–20 мкА. Основне двох'ядерне ядро прокидається лише тоді, коли виявлено аномалію.

### Числовий експеримент: як оптимізація фаз знижує струм на порядки

Уявімо бездротовий датчик тиску, що живиться від батареї ємністю 1000 мА·год.

**Випадок 1: неоптимізована прошивка (довге активне вікно).**
Мікроконтролер не використовує DMA, читає давач із повільними блокуючими затримками `delay()`, а радіомодуль довго виходить на частоту. Активний час `t_on = 50 мс` при струмі `I_on = 80 мА`. Пристрій виходить на зв'язок 1 раз на хвилину (`T = 60 с`). Струм сну через невимкнені підтяжки становить `I_sleep = 20 мкА`.

```
Q_on   = 80 мА · 0.050 с
       = 4.0 мА·с      [активний заряд за спалах]

Q_off  = 0.020 мА · 59.950 с
       = 1.199 мА·с    [заряд, витрачений під час 1 хвилини сну]

I_avg  = (4.0 + 1.199) / 60
       = 0.08665 мА
       = 86.65 мкА     [середній струм неоптимізованого вузла]

T_life = 1000 мА·год / 0.08665 мА
       = 11540 год
       ≈ 1.31 року     [автономність від батареї 1000 мА·год]
```

**Випадок 2: оптимізація коду та апаратної частини (швидкий спалах).**
Програміст прискорив опитування давача через DMA на максимальній частоті SPI, налаштував швидкий старт радіо і загнав `t_on` у `5 мс`. Струм сну почистили до `I_sleep = 3 мкА`. Період лишився тим самим (`T = 60 с`).

```
Q_on   = 80 мА · 0.005 с
       = 0.40 мА·с     [активний заряд скоротився в 10 разів]

Q_off  = 0.003 мА · 59.995 с
       = 0.180 мА·с    [заряд сну]

I_avg  = (0.40 + 0.180) / 60
       = 0.00967 мА
       = 9.67 мкА      [середній струм впав майже в 9 разів]

T_life = 1000 мА·год / 0.00967 мА
       = 103412 год
       ≈ 11.8 років    [пристрій перейшов у категорію десятирічної автономності]
```

**Випадок 3: оптимізація шпаруватості (збільшення періоду).**
Якщо технологічний процес дозволяє оновлювати дані не щохвилини, а раз на 15 хвилин (`T = 900 с`):

```
Q_on   = 0.40 мА·с
Q_off  = 0.003 мА · 899.995 с
       = 2.70 мА·с

I_avg  = (0.40 + 2.70) / 900
       = 0.00344 мА
       = 3.44 мкА      [струм впав ще майже втричі, наблизившись до струму сну]

T_life = 1000 мА·год / 0.00344 мА
       = 290697 год
       ≈ 33.1 роки     [обмежено лише саморозрядом самого хімічного елемента]
```

Скорочення активного вікна з 50 мс до 5 мс та збільшення періоду з 1 хв до 15 хв знизило середній струм з 86.65 мкА до 3.44 мкА (у 25 разів), перетворивши пристрій, що вимагав щорічного сервісу, на систему «встановив і забув».

## Регуляторні обмеження шпаруватості в радіоефірі

Шпаруватість — це не лише інструмент енергозбереження, а й суворе законодавче обмеження у безліцензійних ISM-діапазонах (868 МГц у Європі, 915 МГц у США). Європейський інститут телекомунікаційних стандартів (ETSI, стандарт EN 300 220) ділить діапазон 868 МГц на кілька піддіапазонів із жорстким лімітом часу роботи в ефірі:

| Піддіапазон EU868 | Частотний інтервал | Максимальна потужність | Ліміт шпаруватості (Duty Cycle) | Максимальний час випромінювання на годину |
|---|---|---|---|---|
| **g1 (основний LoRaWAN)** | 868.0 – 868.6 МГц | +14 дБм (25 мВт) | **1.0 %** | 36 секунд на 1 годину |
| **g2** | 868.7 – 869.2 МГц | +14 дБм (25 мВт) | **0.1 %** | 3.6 секунди на 1 годину |
| **g3 (шлюзи / висока потужність)** | 869.4 – 869.65 МГц| +27 дБм (500 мВт)| **10.0 %** | 360 секунд (6 хвилин) на 1 годину |

Стек протоколу (наприклад, LoRaWAN стек) веде ковзний облік часу в ефірі (Time-on-Air). Якщо датчик надсилає довгий пакет на повільній модуляції SF12 (тривалість пакета 1.48 секунди), один сеанс зв'язку вичерпує 4.1% усього годинного ліміту діапазону g1. Після 24 таких передач стек апаратно блокує вихід у радіоефір до початку наступного часового вікна.

## Подійний режим проти періодичного таймера: вибір архітектури датчика

Інженер, що проектує автономний вузол, стикається з компромісом між двома вимогами:
1. **Затримка доставки (Latency)** — як швидко інформація про подію в реальному світі має надійти на сервер або пульт оператора.
2. **Енергетична вартість (Energy Cost)** — скільки міліджоулів коштує кожен сеанс контролю середовища.

Існують дві діаметрально протилежні архітектури побудови сенсорних вузлів: **періодичне опитування (Periodic Polling)** та **асинхронне подійне пробудження (Asynchronous Event-Driven)**.

![Порівняння періодичного опитування та асинхронного подійного режиму](/root/course/embedded/shparuvatist-roboty/img/event-vs-polling.svg)
*Порівняння двох підходів до збору даних. При періодичному опитуванні виникає затримка доставки Latency та витрачається енергія на холості вимірювання. Подійний режим спить до моменту фізичного явища, але вимагає захисту від шторму переривань.*

### Періодичне опитування (Periodic Polling)

Пристрій налаштовує апаратний RTC-таймер або низькоспоживаючий таймер LPTIM на фіксований інтервал `T` (наприклад, 10 хвилин). Після спрацьовування таймера мікроконтролер прокидається, зчитує давач, передає пакет і знову засинає.

Сильні сторони періодичного підходу:
- **Абсолютно передбачуваний енергетичний бюджет.** Кількість сеансів зв'язку на добу фіксована (`N = 86400 / T`), тому термін служби батареї розраховується з точністю до місяця.
- **Підтвердження працездатності вузла.** Кожен регулярний пакет слугує сигналом «я живий» (heartbeat), дозволяючи базовій станції негайно виявити втрату або крадіжку датчика.

Слабкі сторони періодичного підходу:
- **Затримка реакції.** Якщо аварія (прорив труби, відкриття дверей) сталася одразу після виходу на зв'язок, інформація про неї надійде лише в наступному вікні — тобто середня затримка дорівнює `T / 2`, а максимальна — `T`.
- **Енергетична нераціональність (холості цикли).** У 99.9% випадків температура або тиск не змінюються, але радіотрансивер щоразу спалює дорогоцінний заряд акумулятора, щоб передати однакове число.

### Асинхронне подійне пробудження (Event-Driven EXTI)

Мікроконтролер перебуває у стані найглибшого сну (Standby / Deep-Sleep з вимкненим тактуванням ядра та більшості периферії). Лінія переривання мікроконтролера (EXTI, External Interrupt) під'єднана до цифрового виходу розумного сенсора (наприклад, апаратного детектора порогу акселерометра, датчика холла чи компаратора напруги).

Коли фізична величина перевищує поріг (удар, вібрація, поява магнітного поля), сенсор виставляє низький або високий логічний рівень на ніжці переривання. Це миттєво будить процесор, який формує екстрений тривожний пакет і передає його в ефір за кілька мілісекунд.

Сильні сторони подійного підходу:
- **Мінімальна затримка доставки:** від фізичної події до випромінювання пакета минає 3–10 мс.
- **Нульові витрати на передачу статичних даних:** поки нічого не відбувається, передавач не вмикається тижнями чи місяцями.

Слабкі сторони та приховані пастки:
- **Сенсор мусить постійно живитися.** Для того щоб згенерувати переривання, сам давач (акселерометр, компаратор) зобов'язаний постійно перебувати у власному режимі низькоспоживаючого моніторингу (Low-Power Measurement Mode). Сучасні MEMS-акселерометри (наприклад, LIS2DW12 або ADXL362) споживають у такому стані від 0.3 до 1.5 мкА, що додається до базового струму сну плати.
- **Небезпека шторму подій (Event Storm Trap).** Якщо датчик вібрації закріплено на обладнанні, яке несподівано перейшло в режим безперервного дрижання, або механічний контакт кнопки почав бряжчати з частотою 100 Гц, система прокидатиметься 100 разів на секунду. Коефіцієнт шпаруватості стрибне з `0.0001` до `1.0`, і батарея, розрахована на 5 років, помре за дві доби.

### Гібридна архітектура: золотий стандарт промислового IoT

Щоб об'єднати миттєву реакцію подійного режиму з надійністю та контролем періодичного, застосовують **гібридну схему**:

```
                              ┌──────────────────────────────────┐
                              │     ГІБРИДНИЙ СЕНСОРНИЙ ВУЗОЛ    │
                              └─────────────────┬────────────────┘
                                                │
                 ┌──────────────────────────────┴──────────────────────────────┐
                 ▼                                                             ▼
   [ АСИНХРОННИЙ КАНАЛ EXTI ]                                     [ ПЕРІОДИЧНИЙ RTC HEARTBEAT ]
   • Пробудження по зміні стану / порогу                          • Пробудження раз на 12 або 24 години
   • Миттєва тривожна передача (latency < 10 мс)                  • Передача напруги батареї та лічильника
   • Апаратне блокування шторму (hold-off timer)                  • Контроль наявності зв'язку з базою
```

Для захисту від шторму переривань у прошивку закладають механізм **динамічного тротлінгу (Rate Limiting)**: після передачі першої тривоги обробник вимикає зовнішнє переривання на фіксований час утримання (наприклад, на 1 хвилину) або накопичує лічильник подій у пам'яті RTC, передаючи узагальнену пачку даних пізніше.

## Точка насичення економії: коли зниження частоти більше не рятує

Поширена помилка початківців — намагатися збільшити автономність пристрою нескінченним розтягуванням періоду сну `T`: «якщо при виході на зв'язок раз на годину пристрій живе 3 роки, то раз на добу він житиме 70 років».

Фізична реальність закону шпаруватості ставить жорстку асимптотичну межу:

```
lim_{T → ∞} I_avg = lim_{T → ∞} [ (I_on · t_on) / T + I_sleep · (1 - t_on / T) ]
                  = 0 + I_sleep · (1 - 0)
                  = I_sleep      [граничне значення середнього струму при нескінченному періоді]
```

Зі збільшенням періоду `T` середній струм прямує не до нуля, а до власного струму спокою схеми `I_sleep`.

![Крива насичення закону шпаруватості](/root/course/embedded/shparuvatist-roboty/img/saturation-curve.svg)
*Крива залежності середнього струму від періоду повторення T. На початковій ділянці збільшення T стрімко зменшує струм. Після проходження точки насичення T_sat крива виходить на горизонтальне плато I_sleep, де подальше збільшення паузи дає незначний виграш у мікроамперах.*

Щоб зрозуміти, де саме закінчується ефективна оптимізація періоду, знайдемо чутливість середнього струму до зміни періоду — першу похідну функції `I_avg(T)` за `T`:

```
I_avg(T) = (I_on - I_sleep) · t_on / T + I_sleep

d(I_avg) / dT
= d/dT [ (I_on - I_sleep) · t_on · T⁻¹ + I_sleep ]  [диференціювання за періодом T]
= - (I_on - I_sleep) · t_on / T²                    [похідна степеневої функції]
```

Оскільки змінна періоду `T` стоїть у знаменнику в **квадраті** (`T²`), ефективність кожного наступного кроку збільшення періоду падає з квадратичною швидкістю. Подвоєння інтервалу зв'язку з 1 секунди до 2 секунд дає колосальний виграш, тоді як збільшення інтервалу з 1 години до 2 годин змінює інтегральний струм на мікроскопічні частки відсотка.

### Точка рівноваги та точка насичення

Введемо співвідношення між енергією, що витрачається уві сні, та енергією активного спалаху:

```
k_energy = Q_off / Q_on
         = (I_sleep · t_off) / (I_on · t_on)      [коефіцієнт енергетичного домінування фаз]
```

1. **Точка енергетичної рівноваги (`k_energy = 1`):**
   Енергія, витрачена на сон за період, точно дорівнює енергії одного сеансу зв'язку:
   ```
   I_sleep · t_off = I_on · t_on
   t_off ≈ T_eq = (I_on / I_sleep) · t_on      [період енергетичного паритету]
   ```
   До цієї точки головним ворогом автономності є активний передавач. Після цієї точки головним споживачем стає сам стан сну.

2. **Точка насичення шпаруватості (`k_energy = 9`, або T_90):**
   Період, за якого 90% усього заряду акумулятора спалюється на підтримку струму спокою `I_sleep`, і лише 10% витрачається на корисну передачу інформації:
   ```
   T_sat = 9 · (I_on / I_sleep) · t_on         [період практичного насичення закону]
   ```

Якщо для пристрою з `I_on = 60 мА`, `t_on = 10 мс` і `I_sleep = 3 мкА` порахувати точку насичення:

```
T_sat = 9 · (60000 мкА / 3 мкА) · 0.010 с
      = 9 · 20000 · 0.010 с
      = 1800 с
      = 30 хвилин      [після 30 хвилин сну 90% енергії витрачається на сам сон]
```

Збільшення періоду понад 30 хвилин (наприклад, до 6 годин або доби) збільшить теоретичний термін служби батареї лише на лічені місяці, але повністю знищить актуальність телеметрії. Якщо ж пристрій все одно не досягає цільової автономності в 10 років, боротися треба не з частотою опитування, а зі **струмом спокою `I_sleep`**: кожне зниження струму сну з 3 мкА до 1.5 мкА подвоїть термін життя системи на ділянці насичення.

## Протокольні оптимізації шпаруватості в бездротових стеках

Кожен сучасний бездротовий стандарт пропонує власні протокольні механізми адаптації шпаруватості:

### Bluetooth Low Energy: Slave Latency та Advertising Interval
У протоколі BLE периферійний пристрій узгоджує з центральним параметри з'єднання:
- `Connection Interval` (від 7.5 мс до 4.0 с): базовий крок синхронізації радіопакетів.
- `Slave Latency` (від 0 до 499): кількість послідовних з'єднувальних подій, які периферійний пристрій має право пропустити і проспати, якщо у нього немає нових даних для відправки. Завдяки Slave Latency пристрій може підтримувати логічне з'єднання зі смартфоном із номінальним інтервалом 50 мс, але фізично прокидатися раз на 2 секунди, зменшуючи енергоспоживання у 40 разів без ризику розриву сесії.

### Стільниковий зв'язок NB-IoT та LTE-M: таймери PSM та eDRX
У мережах стільникового IoT перепідключення до базової станції (процедура Attach) спалює колосальні сотні міліампер протягом 2–10 секунд. Щоб уникнути повторної реєстрації, стандарт 3GPP ввів режим енергозбереження **PSM (Power Saving Mode)**:
- Таймер `T3412` (Extended Periodic TAU, до 413 днів): інтервал періодичного підтвердження реєстрації. Мікроконтролер модему повністю вимикає приймач і передавач, утримуючи лише контекст безпеки в пам'яті (струм споживання всього 3–5 мкА).
- Таймер `T3324` (Active Time, від 2 секунд до 11 годин): короткий час після відправки пакета, коли модем залишається в ефірі для прийому можливих вхідних команд від сервера, після чого миттєво засинає на час дії таймера T3412.

## Математична модель та інженерний розрахунок автономності

Складімо інженерний розрахунок автономності з урахуванням деградації батареї, температури та характеристик шпаруватості.

### Розрахунок мінімального періоду виходу на зв'язок

**Вхідні інженерні вимоги:**
- Цільовий термін служби: `L_years = 5 років` (`43800 годин`).
- Джерело живлення: елемент Li-SOCl2 (літій-тіонілхлорид) типорозміру AA, номінальна ємність `C_nom = 2600 мА·год`.
- Коефіцієнт корисної віддачі ємності `eta_bat = 0.85` (15% втрат на саморозряд 1%/рік, імпульсне просідання напруги на внутрішньому опорі при мінусовій температурі).
- Ефективна ємність: `C_eff = 2600 · 0.85 = 2210 мА·год`.
- Струм та тривалість активної фази (LoRaWAN передача): `I_on = 40 мА = 40000 мкА`, `t_on = 30 мс = 0.030 с`.
- Виміряний струм спокою плати у глибокому сні: `I_sleep = 2.8 мкА`.

**Крок 1: Обчислення гранично допустимого середнього струму `I_avg_max`.**

```
I_avg_max = C_eff / L_hours
          = 2210 мА·год / 43800 год
          = 0.05045 мА
          = 50.45 мкА      [максимально допустимий струм для досягнення 5 років роботи]
```

**Крок 2: Знаходження мінімально допустимого періоду циклу `T_min`.**

```
I_avg = (I_on · t_on + I_sleep · (T - t_on)) / T
I_avg · T = I_on · t_on + I_sleep · T - I_sleep · t_on
T · (I_avg - I_sleep) = (I_on - I_sleep) · t_on

T_min = [ (I_on - I_sleep) · t_on ] / (I_avg_max - I_sleep)

T_min = [ (40000 мкА - 2.8 мкА) · 0.030 с ] / (50.45 мкА - 2.8 мкА)
      = [ 39997.2 · 0.030 ] / 47.65
      = 1199.916 / 47.65
      ≈ 25.18 секунди     [розрахунковий мінімальний інтервал між сеансами зв'язку]
```

**Висновок:** Щоб гарантувати 5 років роботи від одного елемента AA, пристрій LoRaWAN може виходити в ефір кожні 26 секунд. Якщо ж змінити період передачі на стандартні для LoRaWAN 10 хвилин (`T = 600 с`):

```
Q_on   = 40000 мкА · 0.030 с = 1200 мкА·с
Q_off  = 2.8 мкА · 599.97 с  = 1679.9 мкА·с
I_avg  = (1200 + 1679.9) / 600 ≈ 4.80 мкА

T_life = 2210000 мкА·год / 4.80 мкА
       = 460416 годин
       ≈ 52.5 роки (фактично обмежено терміном придатності батареї ~15–20 років).
```

### Програмний калькулятор шпаруватості та автономності

Для автоматизації розрахунку та інтеграції в утиліти конфігурації нижче наведено закінчену реалізацію моделі шпаруватості двома мовами. Програмна реалізація дозволяє розрахувати середній струм, відсоток використання енергії кожною фазою, час життя та точку насичення `T_sat`. Розширений приклад модуля з пофазною декомпозицією наведено у вставці [інженерного калькулятора шпаруватості](root:embedded/shparuvatist-roboty/proj-duty-cycle-calculator.md).

```c
#include <stdio.h>
#include <stdbool.h>

typedef struct {
    double active_current_ma;    /* струм в активному стані, мА */
    double active_time_ms;       /* тривалість активного спалаху, мс */
    double sleep_current_ua;     /* струм сну, мкА */
    double period_s;             /* період повторення циклу, с */
    double battery_capacity_mah; /* номінальна ємність батареї, мА·год */
    double battery_derating;     /* коефіцієнт корисної віддачі ємності (0.0..1.0) */
} duty_config_t;

typedef struct {
    double duty_cycle;           /* коефіцієнт заповнення D */
    double avg_current_ua;       /* середній інтегральний струм, мкА */
    double active_energy_pct;    /* частка заряду активної фази, % */
    double sleep_energy_pct;     /* частка заряду фази сну, % */
    double lifetime_years;       /* розрахунковий термін служби, років */
    double saturation_period_s;  /* період практичного насичення T_90, с */
    bool valid;
} duty_result_t;

duty_result_t calculate_duty_profile(const duty_config_t *cfg) {
    duty_result_t res = {0};
    if (!cfg || cfg->period_s <= 0.0 || cfg->active_time_ms <= 0.0) {
        return res;
    }

    double t_on_s = cfg->active_time_ms / 1000.0;
    if (t_on_s > cfg->period_s) {
        return res;
    }
    double t_off_s = cfg->period_s - t_on_s;

    /* Заряди фаз у мкА·с (мікрокулонах) */
    double i_on_ua = cfg->active_current_ma * 1000.0;
    double q_on = i_on_ua * t_on_s;
    double q_off = cfg->sleep_current_ua * t_off_s;
    double q_total = q_on + q_off;

    res.duty_cycle = t_on_s / cfg->period_s;
    res.avg_current_ua = q_total / cfg->period_s;
    res.active_energy_pct = (q_on / q_total) * 100.0;
    res.sleep_energy_pct = (q_off / q_total) * 100.0;

    double eff_cap_uah = cfg->battery_capacity_mah * cfg->battery_derating * 1000.0;
    double lifetime_hours = eff_cap_uah / res.avg_current_ua;
    res.lifetime_years = lifetime_hours / (24.0 * 365.25);

    /* Точка насичення T_90: Q_off = 9 * Q_on */
    if (cfg->sleep_current_ua > 0.0) {
        res.saturation_period_s = 9.0 * (i_on_ua / cfg->sleep_current_ua) * t_on_s;
    }

    res.valid = true;
    return res;
}

int main(void) {
    duty_config_t config = {
        .active_current_ma = 45.0,     /* 45 мА (передавач + ядро) */
        .active_time_ms = 15.0,        /* 15 мс активного вікна */
        .sleep_current_ua = 3.2,       /* 3.2 мкА струм спокою */
        .period_s = 300.0,             /* 1 передача раз на 5 хвилин */
        .battery_capacity_mah = 2400.0,/* елемент AA 2400 мА·год */
        .battery_derating = 0.85       /* 15% запас на саморозряд і мороз */
    };

    duty_result_t r = calculate_duty_profile(&config);
    if (r.valid) {
        printf("Шпаруватість D:        %.6f (%.4f%%)\n", r.duty_cycle, r.duty_cycle * 100.0);
        printf("Середній струм:        %.2f мкА\n", r.avg_current_ua);
        printf("Розподіл енергії:      Активна = %.1f%%, Сон = %.1f%%\n",
               r.active_energy_pct, r.sleep_energy_pct);
        printf("Термін автономності:   %.2f років\n", r.lifetime_years);
        printf("Точка насичення T_90:  %.0f с (%.1f хв)\n",
               r.saturation_period_s, r.saturation_period_s / 60.0);
    }
    return 0;
}
```

```cpp
using namespace std::chrono_literals;

struct DutyConfig {
    double active_current_ma{0.0};
    std::chrono::milliseconds active_time{0ms};
    double sleep_current_ua{0.0};
    std::chrono::seconds period{0s};
    double battery_capacity_mah{0.0};
    double battery_derating{0.85};
};

struct DutyMetrics {
    double duty_cycle{0.0};
    double avg_current_ua{0.0};
    double active_energy_pct{0.0};
    double sleep_energy_pct{0.0};
    double lifetime_years{0.0};
    std::chrono::seconds saturation_period{0s};
};

enum class ProfileError {
    InvalidDuration,
    ActiveExceedsPeriod,
    ZeroCapacity
};

[[nodiscard]] constexpr auto analyze_profile(const DutyConfig& cfg) noexcept 
    -> std::expected<DutyMetrics, ProfileError> 
{
    if (cfg.period <= 0s || cfg.active_time <= 0ms) {
        return std::unexpected(ProfileError::InvalidDuration);
    }

    const double t_on_s = std::chrono::duration<double>(cfg.active_time).count();
    const double period_s = std::chrono::duration<double>(cfg.period).count();

    if (t_on_s > period_s) {
        return std::unexpected(ProfileError::ActiveExceedsPeriod);
    }
    if (cfg.battery_capacity_mah <= 0.0) {
        return std::unexpected(ProfileError::ZeroCapacity);
    }

    const double t_off_s = period_s - t_on_s;
    const double i_on_ua = cfg.active_current_ma * 1000.0;
    const double q_on = i_on_ua * t_on_s;
    const double q_off = cfg.sleep_current_ua * t_off_s;
    const double q_total = q_on + q_off;

    DutyMetrics m{};
    m.duty_cycle = t_on_s / period_s;
    m.avg_current_ua = q_total / period_s;
    m.active_energy_pct = (q_on / q_total) * 100.0;
    m.sleep_energy_pct = (q_off / q_total) * 100.0;

    const double eff_cap_uah = cfg.battery_capacity_mah * cfg.battery_derating * 1000.0;
    const double lifetime_hours = eff_cap_uah / m.avg_current_ua;
    m.lifetime_years = lifetime_hours / (24.0 * 365.25);

    if (cfg.sleep_current_ua > 0.0) {
        const double sat_s = 9.0 * (i_on_ua / cfg.sleep_current_ua) * t_on_s;
        m.saturation_period = std::chrono::seconds(static_cast<long long>(sat_s));
    }

    return m;
}

} // namespace power

int main() {
    constexpr power::DutyConfig config{
        .active_current_ma = 45.0,
        .active_time = 15ms,
        .sleep_current_ua = 3.2,
        .period = 300s,
        .battery_capacity_mah = 2400.0,
        .battery_derating = 0.85
    };

    const auto result = power::analyze_profile(config);
    if (!result) {
        std::cerr << "Помилка розрахунку профілю живлення\n";
        return 1;
    }

    const auto& m = *result;
    std::cout << std::fixed << std::setprecision(2);
    std::cout << "Шпаруватість D:        " << (m.duty_cycle * 100.0) << " %\n";
    std::cout << "Середній струм:        " << m.avg_current_ua << " мкА\n";
    std::cout << "Розподіл заряду:       Активний = " << m.active_energy_pct 
              << " %, Сон = " << m.sleep_energy_pct << " %\n";
    std::cout << "Термін автономності:   " << m.lifetime_years << " років\n";
    std::cout << "Точка насичення T_90:  " << m.saturation_period.count() << " с ("
              << (m.saturation_period.count() / 60) << " хв)\n";

    return 0;
}
```

## Зведена стратегія вибору робочої точки

Оптимізація шпаруватості вбудованого пристрою будується за алгоритмом спадного пріоритету:

1. **Скорочуй тривалість активної фази `t_on`.** Перехід на максимальну тактову частоту ядра під час обчислень, використання прямого доступу до пам'яті (DMA) для шин I²C/SPI та прискорення ініціалізації радіо дають пряме лінійне скорочення активного заряду `Q_on`.
2. **Мінімізуй струм спокою `I_sleep`.** При шпаруватості менше `0.001` (інтервал понад 1 хвилину) саме струм сну починає визначати 80–95% автономності. Очищення плати від паразитних витоків через підтяжки та підбір LDO з мікроамперним `I_q` перемагають будь-яку оптимізацію коду.
3. **Обирай архітектуру за типом даних.** Для критичних до затримки подій (тривожні датчики) застосовуй асинхронні переривання EXTI із захисним тротлінгом шторму; для плавної телеметрії середовища — періодичний сон за RTC.
4. **Не розтягуй період за межу `T_sat`.** Якщо розрахунок показує, що при періоді 15 хвилин пристрій уже витрачає 90% енергії на сон, перехід на період 2 години знизить середній струм менше ніж на 0.5 мкА, але знищить оперативність системи.
