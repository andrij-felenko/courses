# 🧮 Розрахунок похибки та бюджету розсинхронізації зворотних дельт

Метод якірної реконструкції часу за зворотними дельтами дозволяє відновити астрономічний час подій без наявності абсолютного годинника на сенсорі, проте точність відновлених міток обмежена сумою похибок трьох фізичних ланок: дрейфу локального кварцового генератора, мережевого джитера радіоканалу та нестабільності серверного часу.

### Математична модель відновлення часу

Нехай точка вимірювання зафіксована локальним монотонним таймером мікроконтролера в момент `t_i`. Кадр передано в радіоефір у момент `t_tx`. Локальна відносна дельта тривалості становить:

```
Δt_i = t_tx - t_i
```

Сервер приймає пакет у момент `T_server` за власною шкалою UTC, синхронізованою за протоколом NTP або PTP. Астрономічний час відправлення кадру з урахуванням оціненої затримки поширення сигналу `t_prop` дорівнює:

```
T_anchor = T_server - t_prop
```

Тоді реконструйований час вимірювання `T_event[i]` обчислюється як:

```
T_event[i] = T_anchor - Δt_i · (1 + δ_crystal)
```

де `δ_crystal` — відносна похибка частоти бортового тактового генератора (виражена у частках від одиниці або ppm).

### Складові бюджету похибки

Сумарна абсолютна похибка відновленої мітки часу `ε_total` не перевищує суми окремих незалежних складових:

```
ε_total = ε_server + ε_jitter + ε_drift + ε_quant
```

1. **Серверна похибка синхронізації (`ε_server`):** похибка локального годинника сервера відносно істинного UTC за протоколом NTP (типово 1..10 мс для хмарних віртуальних машин, менше ніж 50 мікросекунд для локального Stratum-1 сервера з прямим підключенням до GPS-приймача).
2. **Мережева асиметрія та джитер (`ε_jitter`):** невизначеність затримки поширення сигналу в радіоканалі. Якщо повний час оберту лежить у межах `[RTT_min, RTT_max]`, похибка оцінки односторонньої затримки становить:

```
ε_jitter = (RTT_max - RTT_min) / 2
```

3. **Температурний дрейф кварцу (`ε_drift`):** накопичена похибка вимірювання інтервалу накопичення пачки `t_accum` через девіацію частоти резонатора:

```
ε_drift = t_accum · |PPM| · 10⁻⁶
```

4. **Похибка дискретизації таймера (`ε_quant`):** період одного такту апаратного лічильника `1 / f_timer` (для стандартного мілісекундного таймера `ε_quant = 1` мс).

### Температурна залежність годинникового кварцу

Для стандартного камертонного резонатора 32.768 кГц залежність частоти від температури описується параболічною функцією:

```
PPM(T) = -k · (T - T₀)²
```

де:
- `k = 0.035` ppm/°C² — параболічний коефіцієнт кристала;
- `T₀ = 25` °C — точка перегину кривої (номінальна температура);
- `T` — поточна температура навколишнього середовища (°C).

Розрахуймо максимальний дрейф частоти для вуличного датчика при температурі `T = -15` °C:

```
ΔT = T - T₀
= -15 - 25        [різниця температур від точки номіналу]
= -40 °C          [відхилення від номінальних 25 °C]

PPM(-15°C) = -0.035 · (-40)²
= -0.035 · 1600   [піднесення до квадрата]
= -56.0 ppm       [девіація частоти кварцу]
```

### Асиметрія каналу передачі та вплив на якірну мітку

Оцінка часу поширення сигналу `t_prop` зазвичай базується на половині часу оберту пакета `RTT / 2`. Проте в бездротових мережах затримка висхідного каналу (англ. *uplink*, від пристрою до сервера) часто відрізняється від затримки низхідного каналу (англ. *downlink*, від сервера до пристрою) через різницю в розмірах кадрів, схемах модуляції та чергах базових станцій.

Якщо фізична затримка передачі вгору становить `t_up`, а вниз `t_down`, похибка асиметрії виражається формулою:

```
ε_asym = |t_up - t_down| / 2
```

Для стільникових мереж LTE-M асиметрія зазвичай не перевищує 5–15 мс, тоді як у супутникових каналах геостаціонарного зв'язку вона може досягати 30–50 мс.

### Порівняльний аналіз точності для різних технологій зв'язку

Розгляньмо поведінку методу для трьох поширених радіоінтерфейсів IoT при тривалості накопичення пачки вимірювань `t_accum = 600` секунд (10 хвилин).

#### 1. Мережа LoRaWAN (Несинхронізований режим Class A)
У мережах LoRaWAN час виходу на зв'язок визначається псевдовипадковим механізмом або розкладом вузла, а затримка прийому на шлюзі має значний розкид через час обробки концентранта та завантаженість транзитного інтернет-каналу шлюзу:

- Температура середовища: -15 °C (`PPM = 56.0` ppm);
- Варіація затримки: `RTT_min = 80` мс, `RTT_max = 180` мс;
- Серверний NTP: `ε_server = 5` мс;
- Дискретизація таймера: `ε_quant = 1` мс.

Покроковий розрахунок бюджету похибки найстарішої точки в пакеті:

```
ε_drift = 600 · 56 · 10⁻⁶
= 33600 · 10⁻⁶    [множення тривалості на відносну похибку]
= 0.0336 с        [33.6 мілісекунди дрейфу за 10 хвилин]

ε_jitter = (180 - 80) / 2
= 100 / 2         [розмах варіації часу оберту]
= 50 мс           [невизначеність радіозатримки]

ε_total = ε_server + ε_jitter + ε_drift + ε_quant
= 5 + 50 + 33.6 + 1.0  [сума всіх чотирьох складових]
= 89.6 мс         [гранична похибка абсолютного часу заміру]
```

#### 2. Стільникова мережа NB-IoT / LTE-M
Стільникові модеми мають жорстко контрольовані часові слоти базової станції (eNodeB), проте затримка пробудження з режиму eDRX / PSM додає статистичний розкид:

- Температура середовища: +25 °C (`PPM = 20.0` ppm);
- Варіація затримки: `RTT_min = 40` мс, `RTT_max = 90` мс;
- Серверний NTP: `ε_server = 2` мс;
- Дискретизація таймера: `ε_quant = 1` мс.

```
ε_drift = 600 · 20 · 10⁻⁶
= 12000 · 10⁻⁶    [дрейф кварцу за кімнатної температури]
= 0.012 с         [12 мілісекунд]

ε_jitter = (90 - 40) / 2
= 50 / 2          [варіація затримки стільникового стеку]
= 25 мс           [похибка оцінки лінка]

ε_total = 2 + 25 + 12 + 1
= 40.0 мс         [сумарна похибка для NB-IoT]
```

#### 3. Локальний Bluetooth Low Energy (BLE 5.0)
При прямому зв'язку з BLE-шлюзом на відстані до 10 метрів затримка поширення радіохвиль становить частки наносекунд, а затримка стеку фіксована з точністю до інтервалу підключення:

- Температура: +25 °C (`PPM = 20.0` ppm, інтервал накопичення 60 секунд);
- Варіація затримки: `RTT_min = 7.5` мс, `RTT_max = 8.5` мс;
- Серверний PTP (IEEE 1588): `ε_server = 0.05` мс;
- Дискретизація: `ε_quant = 0.1` мс.

```
ε_drift = 60 · 20 · 10⁻⁶
= 1200 · 10⁻⁶     [дрейф за 1 хвилину]
= 0.0012 с        [1.2 мілісекунди]

ε_jitter = (8.5 - 7.5) / 2
= 1.0 / 2         [стабільний зв'язок на короткій дистанції]
= 0.5 мс          [невизначеність BLE кадру]

ε_total = 0.05 + 0.5 + 1.2 + 0.1
= 1.85 мс         [суб-мілісекундна точність відновлення часу]
```

### Вплив класу тактового генератора на час збереження точності

Якщо пристрій перебуває в глибокому офлайні протягом кількох діб, вибір апаратного тактового джерела визначає граничний час, протягом якого похибка залишається прийнятною для інженерної телеметрії:

| Клас генератора | Типова похибка (PPM) | Дрейф за 1 годину | Дрейф за 24 години | Сфера застосування |
| :--- | :--- | :--- | :--- | :--- |
| **Внутрішній RC-генератор MCU** | 10000–50000 ppm (1–5%) | 36–180 секунд | 14–72 хвилини | Тільки грубі інтервали пробудження |
| **Стандартний кварц 32.768 кГц** | 20–50 ppm | 72–180 мс | 1.7–4.3 секунди | Побутові лічильники, датчики середовища |
| **Термокомпенсований TCXO** | 0.5–2 ppm | 1.8–7.2 мс | 43–172 мс | Промислова телеметрія, вібрація, захист |
| **Опорний термостатований OCXO** | 0.01–0.1 ppm | 36–360 мкс | 0.8–8.6 мс | Базові станції, шлюзи синхронізації |

### Статистична комбінація похибок (RSS Model)

Якщо складові похибки є взаємно незалежними випадковими величинами з нульовим математичним сподіванням, замість найгіршої лінійної суми (Upper Bound) використовують середньоквадратичну оцінку (англ. *root sum squared*, RSS):

```
σ_total = √(σ_server² + σ_jitter² + σ_drift² + σ_quant²)
```

Для наведеного прикладу LoRaWAN середньоквадратична похибка становитиме близько 52 мс замість 89.6 мс, що дає 95% довірчий інтервал відновлення істинного часу заміру в межах ±100 мс.

### Висновок

Для типових інтервалів пакетної передачі від 1 до 15 хвилин навіть найдешевший кварцовий резонатор забезпечує похибку відновлення часової осі менше ніж 100 мілісекунд. Це дозволяє повністю відмовитися від наявності апаратного годинника реального часу (RTC) на сенсорних вузлах без жодної втрати якості аналізу фізичних процесів.
