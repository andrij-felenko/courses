# 📋 Інтерфейс керування радіотрансивером по SPI

Цей довідник містить вичерпну специфікацію апаратного інтерфейсу, часових діаграм, системи строб-команд, конфігураційних регістрів та протоколів обміну типового субгігагерцового та 2.4 ГГц пакетного радіотрансивера (уніфікований профіль архітектур CC1101, SX1262, nRF24L01).

У вбудованих мікропроцесорних системах радіотрансивер є інтелектуальним периферійним пристроєм, підпорядкованим мікроконтролеру. На відміну від простих давачів шини I2C чи мікросхем пам'яті, радіотрансивер містить складний автономний апаратний автомат зі строгою послідовністю переходів між режимами енергоспоживання, калібрування контурів генератора та прийому чи передачі радіосигналу. Будь-яке порушення часових інтервалів підняття виводу вибору кристала (CSN) або спроба звернення до буфера під час внутрішнього калібрування призводить до апаратного блокування шини та втрати пакетів.

## Апаратні сигнали та інтерфейс підключення

Трансивер взаємодіє з хост-мікроконтролером через синхронну чотирипровідну шину SPI та додаткові цифрові лінії керування й переривань:

| Сигнал | Напрямок | Опис призначення та електричні вимоги |
| :--- | :--- | :--- |
| `CSN` (NSS) | Вхід трансивера | Chip Select Not: активний низький рівень. Фіксує межі кожної транзакції. Повинен підтягуватися резистором 10..47 кОм до VDD для запобігання хибному вибору під час скидання МК |
| `SCK` | Вхід трансивера | Тактовий сигнал SPI (режим SPI Mode 0: CPOL = 0, CPHA = 0). Дані фіксуються за наростаючим фронтом, змінюються за спадним |
| `MOSI` | Вхід трансивера | Master Out Slave In: передача командних байтів, адрес та даних передачі від хоста до чипа |
| `MISO` | Вихід трансивера | Master In Slave Out: повернення байта статусу чіпа під час адресного циклу та вичитування регістрів / RX FIFO |
| `IRQ` / `GDO0` | Вихід трансивера | Програмована лінія апаратного переривання: повідомляє процесор про події `RX_DONE`, `TX_DONE`, досягнення порога заповнення FIFO |
| `BUSY` | Вихід трансивера | Індикатор внутрішньої зайнятості (активний високий рівень у SX1262): сигналізує про процес автокалібрування або розігріву PLL |
| `RST_N` | Вхід трансивера | Апаратний сигнал скидання (активний низький рівень). Потребує імпульсу тривалістю від 100 мкс для повного перезапуску логіки |

Шина SPI радіомодуля працює виключно в режимі SPI Mode 0 (полярність тактового сигналу CPOL = 0, фаза вибірки CPHA = 0). У стані спокою лінія SCK перебуває в логічному нулі. Коли хост опускає лінію CSN у нуль, трансивер активує свій вихідний драйвер MISO. Передача кожного біта відбувається синхронно: хост виставляє біт на лінії MOSI за спадним фронтом SCK, а трансивер фіксує його за наступним наростаючим фронтом.

## Часові діаграми та фізичні обмеження шини

Взаємодія по SPI вимагає суворого дотримання часових інтервалів між перепадами сигналів CSN та першим тактовим імпульсом SCK:

```
                     t_CS_SETUP                              t_CS_HOLD
CSN  --------\                                                        /--------
              \______________________________________________________/
                   |<- t_SCK ->|
SCK  ____________/---\___/---\___/---\___/---\___/---\___/---\___/---\________
     
MOSI --------<  Bit 7  X  Bit 6  X  Bit 5  X  ...  X  Bit 0  >----------------
     
MISO --------< Status7 X Status6 X Status5 X  ...  X Status0 >----------------
```

| Параметр | Позначення | Мінімум | Максимум | Одиниці | Інженерні примітки |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Тактова частота SPI | `f_SCK` | 0.1 | 10.0 | МГц | Робоча частота обміну при стабільному живленні |
| Час встановлення CSN | `t_CS_SETUP` | 50 | — | нс | Затримка від спаду CSN до першого наростаючого фронту SCK |
| Час утримання CSN | `t_CS_HOLD` | 50 | — | нс | Затримка від останнього спаду SCK до підйому CSN |
| Інтервал між транзакціями | `t_CS_HIGH` | 40 | — | нс | Мінімальний час неактивного високого стану CSN між командами |
| Стабілізація кварцу | `t_XOSC_STABLE` | 150 | 400 | мкс | Час виходу з режиму Deep Sleep до стабілізації генератора |
| Тривалість скидання | `t_RST_PULSE` | 100 | — | мкс | Мінімальна тривалість низького імпульсу на лінії `RST_N` |

При роботі на високих тактових частотах SPI (понад 8 МГц) паразитна ємність друкованих провідників друкованої плати (типово 10..20 пФ) може затягувати фронти MISO. Тому в низькорівневому драйвері слід перевіряти таймінги захоплення даних контролером SPI та не перевищувати граничну швидкість, рекомендовану виробником для поточної напруги живлення.

## Формат командного байта та байта статусу

Кожна транзакція SPI починається з передачі хостом однобайтного заголовка, що визначає тип операції та цільову адресу:

```
Байт команди: [ R/W | Burst | A5 | A4 | A3 | A2 | A1 | A0 ]
де:
  R/W   (біт 7): 0 = Запис (Write), 1 = Читання (Read)
  Burst (біт 6): 0 = Одиночний доступ до регістра, 1 = Пакетний режим (Burst / доступ до FIFO)
  A[5:0] (біти 5..0): 6-бітна адреса цільового регістра або опкод строб-команди (0x30..0x3D)
```

Одночасно з передачею командного байта по лінії `MOSI` радіотрансивер виставляє на лінію `MISO` **байт поточного апаратного статусу (Status Byte)**:

```
Байт статусу: [ CHIP_RDY_N | STATE_2 | STATE_1 | STATE_0 | FIFO_BYTES_AVAIL_3..0 ]
де:
  CHIP_RDY_N (біт 7): 0 = Кварцовий генератор стабільний, чип готовий; 1 = Резонатор прокидається
  STATE[2:0]  (біти 6..4): Поточний стан внутрішнього автомата радіочипа:
                 000 = IDLE (Очікування)
                 001 = RX (Активний прийом)
                 010 = TX (Активна передача)
                 011 = FSTXON (Синтезатор увімкнено та залочено)
                 100 = CALIBRATE (Виконується автокалібрування PLL)
                 101 = SETTLING (Перехідний процес встановлення частоти)
                 110 = RX_FIFO_OVERFLOW (Переповнення буфера прийому)
                 111 = TX_FIFO_UNDERFLOW (Спустошення буфера передачі)
  FIFO_BYTES[3:0] (біти 3..0): Кількість вільних байтів (у режимі TX) або прийнятих байтів (у режимі RX)
```

Перевірка біта `CHIP_RDY_N` у першому байті відповіді є найшвидшим способом діагностики готовності радіомодуля до прийому команд після пробудження зі сну. Якщо цей біт дорівнює одиниці, внутрішнє цифрове ядро ще не зафіксувало тактову частоту опорного генератора, і будь-які наступні байти конфігурації будуть проігноровані апаратурою.

## Система строб-команд керування станами (Command Strobes)

Строб-команди є однобайтними інструкціями, які не потребують передачі адреси чи додаткових аргументів. Вони безпосередньо змінюють стан внутрішнього кінцевого автомата радіоконтролера:

| Опкод (Hex) | Символічне ім'я | Дія та вплив на апаратні блоки |
| :--- | :--- | :--- |
| `0x30` | `CMD_SRES` | Програмне скидання чипа (Soft Reset). Повертає всі конфігураційні регістри до дефолтних значень і переводить чип у стан `IDLE` |
| `0x31` | `CMD_SFSTXON` | Запуск і калібрування PLL-синтезатора на робочій частоті без увімкнення вихідного каскаду PA. Скорочує час старту передачі |
| `0x32` | `CMD_SXOFF` | Зупинка основного кварцового генератора для переходу в режим ультранизького споживання (Power Down) |
| `0x33` | `CMD_SCAL` | Примусовий запуск калібрування контуру VCO та фільтрів проміжної частоти |
| `0x34` | `CMD_SRX` | Переведення радіотракту в режим активного прийому: увімкнення LNA, змішувачів, АЦП та DSP-демодулятора |
| `0x35` | `CMD_STX` | Переведення у режим передачі: запуск модуляції даних із TX FIFO та активація підсилювача потужності (PA) |
| `0x36` | `CMD_SIDLE` | Перехід у стан очікування (IDLE): вимкнення радіотракту та переведення PLL у режим низького струму |
| `0x3A` | `CMD_SFRX` | Очищення буфера прийому RX FIFO. Обов'язкова операція після виникнення помилки переповнення `RX_FIFO_OVERFLOW` |
| `0x3B` | `CMD_SFTX` | Очищення буфера передачі TX FIFO. Обов'язкова операція при відновленні після збою спустошення `TX_FIFO_UNDERFLOW` |
| `0x3D` | `CMD_SNOP` | Холоста інструкція (No Operation). Використовується хостом для читання байта статусу чипа без зміни стану |

Кожна зміна стану супроводжується внутрішніми фізичними процесами: перемиканням напруг зміщення, увімкненням малошумних стабілізаторів LDO та підстроюванням варикапів генератора керованого напругою (VCO). Спроба подати команду передачі `CMD_STX` безпосередньо зі стану сну без очікування розігріву кварцу призведе до збою синтезатора та випромінювання на хаотичній частоті.

## Карта базових конфігураційних регістрів

Регістри конфігурації визначають робочу частоту, параметри модуляції, структуру пакетного кадру та поведінку виводів переривання:

| Адреса | Ім'я регістра | Біти | Дефолт | Опис призначення та вплив на радіоканал |
| :--- | :--- | :--- | :--- | :--- |
| `0x00` | `IOCFG0` | `[5:0]` | `0x3F` | Конфігурація функції виводу `GDO0` (`0x06` = активний рівень при успішному прийомі кадру з валідним CRC) |
| `0x04` | `SYNC1` | `[7:0]` | `0xD3` | Старший байт 16-бітного синхрослова (Sync Word MSB) |
| `0x05` | `SYNC0` | `[7:0]` | `0x91` | Молодший байт 16-бітного синхрослова (Sync Word LSB) |
| `0x06` | `PKTLEN` | `[7:0]` | `0xFF` | Максимальна дозволена довжина кадру в режимі змінної довжини або фіксована довжина |
| `0x07` | `PKTCTRL1` | `[7:0]` | `0x04` | `[7:5]` Фільтрація преамбули, `[3]` Додавання статусів RSSI/LQI у кінець RX FIFO, `[1:0]` Фільтрація адрес |
| `0x08` | `PKTCTRL0` | `[7:0]` | `0x45` | `[6]` Скремблювання (Data Whitening ON/OFF), `[5:4]` Формат пакета, `[2]` Апаратний CRC ON/OFF, `[1:0]` Режим довжини |
| `0x0B` | `FSCTRL1` | `[7:0]` | `0x06` | Проміжна частота (IF Frequency) цифрового змішувача Low-IF |
| `0x0D` | `FREQ2` | `[7:0]` | `0x10` | Несуча частота `f_RF`, старший байт слова синтезатора (біти 23..16) |
| `0x0E` | `FREQ1` | `[7:0]` | `0xB1` | Несуча частота `f_RF`, середній байт слова синтезатора (біти 15..8) |
| `0x0F` | `FREQ0` | `[7:0]` | `0x3B` | Несуча частота `f_RF`, молодший байт слова синтезатора (біти 7..0) |
| `0x10` | `MDMCFG4` | `[7:0]` | `0x8C` | `[7:4]` Смуга приймального канального фільтра (Channel Filter BW), `[3:0]` Мантиса швидкості |
| `0x11` | `MDMCFG3` | `[7:0]` | `0x22` | Експонента символьної швидкості передачі даних |
| `0x12` | `MDMCFG2` | `[7:0]` | `0x02` | `[6:4]` Тип цифрової модуляції (2-FSK, GFSK, OOK), `[3]` DC Blocking, `[2:0]` Режим перевірки Sync Word |
| `0x13` | `MDMCFG1` | `[7:0]` | `0x22` | `[7]` Пряме виправлення помилок (FEC ON/OFF), `[6:4]` Довжина преамбули (2, 4, 8 або 16 байтів) |
| `0x14` | `MDMCFG0` | `[7:0]` | `0xF8` | Крок частотної сітки сусідніх каналів (Channel Spacing) |
| `0x15` | `DEVIATN` | `[7:0]` | `0x47` | Девіація частоти Δf для частотних модуляцій FSK/GFSK |
| `0x3F` | `FIFO` | `[7:0]` | — | Адресне вікно буферів FIFO (читання звертається до RX FIFO, запис — до TX FIFO) |

Розрахунок слова частоти синтезатора у регістрах `FREQ[2:0]` виконується від номінальної частоти зовнішнього опорного кварцу `f_XOSC` (типово 26 МГц) за формулою:

```
FREQ_REG = (f_RF · 2^16) / f_XOSC                  [значення 24-бітного слова частоти]
```

Наприклад, для отримання несучої частоти 868.000 МГц при кварці 26.0 МГц обчислене шістнадцяткове значення становить `0x216276`.

## Діагностичні регістри стану (Read-Only)

Ці регістри дозволяють контролювати стан ефіру, енергетичні рівні та цілісність буферів без переривання радіотракту:

| Адреса | Ім'я регістра | Опис інформації, що повертається |
| :--- | :--- | :--- |
| `0x34` | `RSSI` | Миттєвий рівень вхідної потужності: перерахунок у dBm виконується за формулою `P_in = RSSI_val / 2 - 74 dBm` |
| `0x35` | `MARCSTATE` | Розширений поточний стан головного автомата радіоконтролера (Main Radio Control State Machine) |
| `0x3A` | `PKTSTATUS` | Бітові прапорці: `[7]` Зайнятість каналу (Carrier Sense), `[6]` Детекція преамбули, `[4]` Валідність CRC |
| `0x3B` | `RXBYTES` | `[7]` Прапорець переповнення буфера `RXFIFO_OVERFLOW`, `[6:0]` Кількість доступних байтів у RX FIFO |
| `0x3C` | `TXBYTES` | `[7]` Прапорець спустошення буфера `TXFIFO_UNDERFLOW`, `[6:0]` Кількість байтів, що очікують передачі |

Регістр `MARCSTATE` є найважливішим інструментом налагодження: він повертає деталізований внутрішній код стану чипа (понад 30 підстанів, таких як `VCOON_MC`, `REGON_MC`, `MANCAL`, `BWBOOST`), що дозволяє точно встановити, на якому саме етапі завис автомат у разі апаратної аварії.

## Типові алгоритми обробки транзакцій

### Надійна відправка пакета (TX Pipeline)
1. Подати строб `CMD_SIDLE` та перевірити повернення стану `000` у байті статусу чипа;
2. Очистити можливі залишки буфера передачі стробом `CMD_SFTX`;
3. Записати сформований пакет у `FIFO` через пакетну операцію Burst Write: першим байтом передається довжина корисного навантаження N, після чого послідовно передаються N байтів даних;
4. Подати строб запуску передавача `CMD_STX`;
5. Очікувати наростаючого фронту апаратного переривання `IRQ` (початок випромінювання преамбули в ефір) та подальшого спадного фронту (завершення відправки пакета `TX_DONE`);
6. Після завершення передачі перевести трансивер у режим очікування `CMD_SIDLE` або вимкнути генератор командою `CMD_SXOFF` для економії енергії батареї.

### Надійний прийом пакета (RX Pipeline)
1. Налаштувати вивід `IOCFG0` у значення `0x06` (переривання генерується лише при повному прийомі кадру з коректною апаратною контрольною сумою);
2. Очистити буфер прийому стробом `CMD_SFRX`;
3. Подати строб увімкнення приймального тракту `CMD_SRX`;
4. За виникненням апаратного переривання на вході мікроконтролера прочитати діагностичний регістр `RXBYTES`: якщо встановлено біт 7 (`RXFIFO_OVERFLOW`), негайно виконати аварійне скидання `CMD_SFRX` і перезапустити прийом;
5. Якщо переповнення немає, вичитати по Burst SPI довжину пакета N, корисні дані та два завершальних статусних байти (RSSI та LQI);
6. Перевірити старший біт байта LQI (`CRC_OK == 1`). Якщо біт встановлено, передати корисні дані у стек обробки застосунку.

## Захист від гонок та відновлення після збоїв

У реальних вбудованих пристроях можливі збої шини через наведення імпульсних завад від електродвигунів або перехідних процесів живлення.

Для забезпечення безперебійної роботи драйвер повинен реалізовувати такі захисні механізми:
- **Таймаут очікування переривання**: якщо після подачі команди `CMD_STX` лінія `IRQ` не скинулася протягом розрахункового часу передачі кадру плюс 10 мс, драйвер зобов'язаний примусово подати строб `CMD_SIDLE`, очистити `CMD_SFTX` та зареєструвати помилку передавача;
- **Обробка переповнення буфера**: якщо мікроконтролер був заблокований тривалим критичним розділом іншого переривання і не встиг вичитати попередній пакет, прихід наступного кадру переповнює FIFO. Трансивер переходить у стан `RX_FIFO_OVERFLOW` і повністю блокує радіоприймач. Єдиний вихід — строб `CMD_SFRX` з наступним повторним увімкненням `CMD_SRX`;
- **Апаратний сторожовий перезапуск**: якщо байт статусу повертає неможливі комбінації бітів або лінія MISO зависла в логічному нулі чи одиниці, драйвер формує імпульс низького рівня на лінії `RST_N` тривалістю 1 мс і повторює повну табличну ініціалізацію регістрів.

Дотримання цієї специфікації гарантує стійкість радіотракту до апаратних колізій і забезпечує надійну роботу каналу зв'язку в автономних системах.
