Під прямим полудневим сонцем з освітленістю 100 000 люксів стандартний екран цивільного планшета чи смартфона миттєво перетворюється на непроглядне дзеркало: тонкі шрифти розміром 12 пунктів, напівпрозорі панелі та сірі піктограми повністю розчиняються у відблисках. Перші ж краплі дощу на захисному склі викликають лавину хибних спрацьовувань ємнісної сітки, хаотично перемикаючи режими польоту або скидаючи координати цілей. Спроба натиснути кнопку в тактичній рукавиці з кевларовою чи шкіряною накладкою товщиною 2 мм натикається на фізичну межу — сенсорний контролер не фіксує зміну ємності крізь шар діелектрика. А коли через холод, фізичне виснаження або вібрацію бронемашини у пальцях оператора виникає моторний тремор з амплітудою 3–5 мм, влучити в типову мобільну кнопку завширшки 7 мм стає неможливо без випадкового зачіпання сусідніх критичних перемикачів.

Польовий людино-машинний інтерфейс (англ. *Human-Machine Interface*, HMI) проєктується не за законами офісних графічних оболонок. Він спирається на оптичне узгодження коефіцієнтів заломлення шарів дисплея, алгоритми адаптивного сканування ємнісної матриці, психомоторну модель поведінки людини під адреналіновим навантаженням та жорстку геометрію однорукого хвату.

## Читабельність на прямому сонці: оптика, яскравість і контраст

Здатність людського ока розпізнати текст чи піктограму на екрані визначається не абсолютною яскравістю підсвічування, а коефіцієнтом контрастності зображення в реальних умовах довкілля (англ. *Ambient Contrast Ratio*, ACR). В офісному приміщенні з освітленістю 300–500 лк навіть скромний дисплей яскравістю 250–300 ніт забезпечує контраст понад 100:1. Проте у відкритому степу чи пустелі прямий потік сонячного світла сягає 70 000–100 000 лк, а відбите від неба та ґрунту розсіяне світло додає ще 10 000–20 000 лк.

![Оптичне склеювання дисплейного модуля проти повітряного проміжку](/root/course/embedded/ekran-u-poli/img/optical-bonding-vs-airgap.svg)
*Хід світлових променів у дисплейному модулі: повітряний проміжок створює паразитно високе відбиття сонця, тоді як оптичне склеювання клеєм LOCA/OCA усуває внутрішні відблиски.*

### Фізика відбиття Френеля та повітряний проміжок

У дешевих дисплейних модулях захисне скло (або сенсорна панель) відділене від рідкокристалічної матриці тонким шаром повітря — так званим повітряним проміжком (англ. *Air Gap*). Коли світловий промінь перетинає межу двох середовищ із різними показниками заломлення `n₁` та `n₂`, частина світлової енергії неминуче відбивається назад відповідно до рівнянь Френеля для нормального падіння:

```
R = ((n₁ - n₂) / (n₁ + n₂))²          [коефіцієнт відбиття Френеля на одній межі]
```

Показник заломлення силікатного скла становить `n_glass ≈ 1.52`, поляризаційної плівки матриці `n_polarizer ≈ 1.50`, а повітряного прошарку між ними `n_air = 1.00`. На кожній такій межі відбувається стрибок показника заломлення:

```
R_glass_air = ((1.52 - 1.00) / (1.52 + 1.00))²
= (0.52 / 2.52)²                      [обчислення відношення]
≈ 0.0426                              [відбиття 4.26 % світлового потоку]
```

У модулі з повітряним проміжком світло зустрічає три критичні межі:
1. Зовнішня поверхня захисного скла (повітря → скло): відбиття близько 4.2 %.
2. Внутрішня поверхня захисного скла (скло → повітряний проміжок): відбиття близько 4.2 %.
3. Зовнішня поверхня поляризатора TFT-матриці (повітряний проміжок → поляризатор): відбиття близько 4.0 %.

З урахуванням багаторазових внутрішніх перевипромінювань сумарне відбиття зовнішнього світла такою конструкцією становить `R_total ≈ 12–15 %`. 

Розрахуймо паразитну яскравість відблиску `L_refl`, яку побачить оператор під прямим сонцем з освітленістю `E = 100 000 лк`:

```
L_refl = E · R_total / π              [перерахунок освітленості у відбиту яскравість]
= 100000 · 0.13 / 3.14159             [підстановка сумарного відбиття 13 %]
≈ 4138 nit                            [фонова яскравість паразитного відблиску]
```

Тепер обчислимо ефективний контраст `CR` для цивільного дисплея з яскравістю підсвічування `L_white = 400 nit` та власною глибиною чорного `L_black = 0.5 nit`:

```
CR = (L_white + L_refl) / (L_black + L_refl)
= (400 + 4138) / (0.5 + 4138)         [додавання відбитого сонячного світла до обох станів]
= 4538 / 4138.5
≈ 1.096 : 1                           [підсумковий контраст на сонці]
```

Для читання монохромного тексту людському оку потрібен контраст не менше `3:1`, а для швидкого безпомилкового зчитування піктограм і картографічної підкладки — не менше `5:1`. Контраст `1.1:1` означає повну оптичну сліпоту: екран виглядає як суцільна біла дзеркальна поверхня, на якій нічого неможливо розібрати, скільки б енергії не споживав процесор.

### Оптичне склеювання (Optical Bonding)

Єдиний спосіб кардинально зменшити відбиття — фізично ліквідувати повітряний прошарок між матрицею та склом. Технологія оптичного склеювання (англ. *Optical Bonding*) полягає у повному заповненні цього простору оптично прозорим полімером:
- **Рідкий клей LOCA** (англ. *Liquid Optically Clear Adhesive*): полімеризується під впливом ультрафіолетового випромінювання.
- **Тверда силіконова або акрилова плівка OCA** (англ. *Optically Clear Adhesive*): ламінується під вакуумом за підвищеної температури й тиску в автоклаві.

Показник заломлення оптичного клею підбирається рівним `n_glue ≈ 1.49–1.51`, що майже ідеально збігається з показником заломлення скла та поляризатора (`Δn < 0.02`). Внутрішні межі «скло–повітря» та «повітря–матриця» перестають існувати оптично. Єдиною поверхнею, де виникає стрибок коефіцієнта заломлення, залишається зовнішня грань захисного скла.

Додатково зовнішню поверхню скла піддають вакуумному напиленню діелектричних інтерференційних шарів (Anti-Reflective, AR-покриття на основі оксидів титану та кремнію), де відбиті від різних шарів хвилі гасять одна одну в протифазі. Це знижує відбиття зовнішньої грані з 4.2 % до менш ніж 0.5 %. Сумарне відбиття всього дисплейного пакета падає до `R_total < 0.8 %`.

Розрахуймо контраст оптично склеєного модуля високої яскравості (`L_white = 1200 nit`) за того самого освітлення 100 000 лк:

```
L_refl_bonded = 100000 · 0.008 / 3.14159
≈ 255 nit                             [паразитне відбиття оптично склеєного скла]

CR_bonded = (1200 + 255) / (1.0 + 255)
= 1455 / 256
≈ 5.68 : 1                            [відмінний контраст під прямим сонцем]
```

Оптичне склеювання дає ще три критичні польові переваги:
1. **Механічна міцність**: клейовий шар працює як демпфер. Дисплейний бутерброд витримує прямі удари та падіння термінала на каміння, перерозподіляючи локальне механічне напруження по всій площі матриці.
2. **Відсутність конденсату та пилу**: у закритому герметичному просторі немає повітря, тому за різких перепадів температури (наприклад, виніс термінала з теплого бліндажа на мороз −20 °C) внутрішня поверхня скла не вкривається росою чи памороззю.
3. **Покращене тепловідведення**: тепло від потужної світлодіодної підсвітки ефективно передається через монолітний клейовий шар на масивне захисне скло, працюючи як пасивний радіатор.

### Антивідблискове мікротравлення (Anti-Glare)

Поряд із інтерференційним покриттям AR застосовують матове антивідблискове покриття AG (англ. *Anti-Glare*). Поверхню скла піддають хімічному кислотному травленню, створюючи мікрорельєф із шорсткістю порядка часток мікрометра. Дзеркальний відблиск сонячного диска не відбивається вузьким сліпучим пучком, а розсіюється в широкий півсферичний конус.

> [!WARNING]
> Надмірне матування скла (низький показник Gloss < 60 GU) викликає розмиття дрібних деталей зображення (англ. *sparkle effect* / *haze*), коли світло від окремих підпікселів заломлюється на мікрогранях скла. Для тактильних карт і польотної телеметрії оптимальним є компромісне значення матовості 75–85 GU (англ. *Gloss Units*).

### Програмна адаптація палітри: денний висококонтрастний та нічний режими

Навіть на оптично склеєному екрані яскравістю 1200 ніт використання типової «модної» палітри з тонкими градієнтами, пастельними відтінками та сірими написами на світло-сірому тлі руйнує ергономіку. Контраст кольорів у колориметричному просторі вимивається.

Програмний шар інтерфейсу оператора повинен підтримувати спеціалізовані колірні режими:

1. **Денний висококонтрастний режим (High Contrast Day Mode)**:
   - Відмова від напівтонів і тіней.
   - Основним тлом обирається чистий чорний (`#000000`) або насичений жовтий (`#FFD700`), а шрифти та векторні контури малюються відповідно чистим білим (`#FFFFFF`) або вугільно-чорним (`#000000`). Чорно-жовта пара забезпечує найвищий рівень зорової помітності за шкалою Вебера–Фехнера.
   - Товщина ліній графіків і рамок кнопок збільшується з 1 px до 2–3 px.
   - Кольорове кодування звужується до чотирьох базових спектральних сигналів зі 100% насиченістю: яскраво-зелений (норма/зв'язок), насичено-червоний (аварія/небезпека), чистий жовтий (попередження), яскраво-блакитний (маршрут).

2. **Нічний режим маскування (Night Vision / Blackout Mode)**:
   - Повне блокування синього та зеленого спектрів, які руйнують темрявову адаптацію очей оператора (знебарвлюють білок родопсин у паличках сітківки) та демаскують позицію через прилади нічного бачення (ПНБ).
   - Весь інтерфейс переводиться в монохромний темно-червоний колір (довжина хвилі `λ > 620 нм`) з можливістю плавного апаратного зниження яскравості підсвічування до 0.5–2 ніт без мерехтіння (через постійний струм або високочастотний ШІМ > 20 кГц).

## Сенсорні технології в польових умовах: рукавиці, вода та бруд

Сенсорний екран у лабораторії реагує на легкий дотик сухого пальця. У польових умовах оператор працює в зимових або тактичних рукавицях із підсиленими подушечками, екран заливає дощ, а поверхня вкривається тонким шаром піску чи глини.

![Порівняння технологій сенсорного та фізичного введення в полі](/root/course/embedded/ekran-u-poli/img/touch-technologies-field.svg)
*Три модальності введення: ємнісний екран потребує складних алгоритмів фільтрації води та рукавиць, резистивний стійкий до бруду, а фізичні енкодери гарантують роботу наосліп.*

### Фізика ємнісних сенсорів (PCAP) та бар'єр рукавиць

У проєкційно-ємнісних сенсорах (англ. *Projected Capacitive Touch*, PCAP) на скляну підкладку нанесена ортогональна координатна сітка прозорих провідників з оксиду індію-олова (ITO). Вимірюється взаємна ємність (англ. *Mutual Capacitance*) у вузлах перетину електродів збудження (Tx) та зчитування (Rx).

Коли оголений палець людини наближається до вузла, його провідні тканини замикають частину силових ліній змінного електричного поля на землю через тіло оператора. Взаємна ємність вузла падає на величину `ΔC`:

```
C_mutual = ε₀ · ε_r · A / d           [ємність плоского наближення між пальцем і сіткою]
```

Для сухого пальця на склі товщиною 1.1 мм (`ε_r(glass) ≈ 7.0`) зміна ємності становить `ΔC ≈ 0.5–1.2 пФ`. Це створює співвідношення сигнал/шум (SNR) понад 25–30 дБ, що дозволяє контролеру впевнено фіксувати координати точки з субміліметровою точністю.

Коли оператор одягає тактичну рукавицю, між пальцем і склом з'являється додатковий шар діелектрика товщиною `d_glove = 1.5–3.0 мм` із низькою діелектричною проникністю (`ε_r(шкіра/кевлар) ≈ 2.0–2.5`). Оскільки ємність обернено пропорційна сумарній ефективній відстані:

```
d_eff = (d_glass / ε_glass) + (d_glove / ε_glove)
= (1.1 / 7.0) + (2.5 / 2.2)           [розрахунок еквівалентної оптико-електричної товщини]
= 0.157 + 1.136
≈ 1.293 мм                            [зростання ефективної відстані у 8 разів]
```

Зміна взаємної ємності падає до мізерних `ΔC ≈ 0.02–0.05 пФ`. Сигнал тоне у теплових шумах аналогового тракту контролера, паразитних наведеннях від підсвітки дисплея та синфазному шумі від перетворювачів живлення.

### Режим роботи в рукавицях (Glove Mode)

Для роботи крізь рукавиці промислові тач-контролери (наприклад, лінійки Synaptics ClearPad, FocalTech FT5x, Microchip maXTouch) динамічно перебудовують конвеєр обробки сигналу:
1. **Зниження порогу детектування (Detection Threshold)**: поріг спрацьовування знижується у 5–10 разів.
2. **Адаптивне сканування власної ємності (Self-Capacitance fallback)**: контролер перемикає сітку з взаємної ємності (Mutual) на власну (Self). Власна ємність вимірює заряд усього електрода відносно землі приладу, що збільшує чутливість у кілька разів, проте обмежує або ускладнює підтримку повноцінного мультитачу через ефект «фантомних координат» (англ. *ghosting*).
3. **Просторова кластеризація та збільшення площі відбитку**: віртуальна пляма контакту пальця в товстій рукавиці збільшується з типових 6–8 мм до 18–25 мм. Алгоритм просторової інтерполяції об'єднує дані від 9–16 сусідніх сенсорних вузлів для обчислення центру мас відбитку.

### Проблема води та дощу: фантомні натискання

Вода має надзвичайно високу статичну діелектричну проникність (`ε_r(H₂O) ≈ 80`) і, будучи електролітом із розчиненими солями, проводить змінний струм високої частоти.

Крапля дощу на поверхні скла створює локальний провідний міст між сусідніми Tx/Rx електродами, різко збільшуючи взаємний зв'язок. Контролер без спеціального захисту реєструє це як потужний дотик пальця. Під час зливи екран перетворюється на поле хаотичних хибних спрацьовувань, здатних викликати аварійне скидання корисного навантаження чи зміну польотної місії.

Алгоритми захисту від води (англ. *Water Rejection*):
- **Аналіз профілю ємнісної карти (Capacitance Profile Signature)**: справжній палець відбирає заряд на землю (зменшення Mutual Capacitance), тоді як крапля чистої води перерозподіляє заряд між електродами зі специфічним фазовим зсувом.
- **Диференціальне сканування**: швидке чергування циклів вимірювання взаємної та власної ємностей. Якщо зона показує сильний взаємний сигнал, але нульовий відтік заряду на спільну землю — подія класифікується як водна пліма та ігнорується.
- **Примусове блокування мультитачу (Single-touch lock)**: за наявності суцільної водяної плівки контролер тимчасово вимикає жести двома пальцями (масштабування щипком) і переходить у строгий одноелементний режим, фільтруючи стаціонарні краплі як постійне зміщення базової лінії шуму.

### Резистивні екрани: переваги та деградація

Чотири- та п'ятипровідні резистивні екрани працюють за принципом прямого механічного тиску: гнучка верхня мембрана з нанесеним струмопровідним шаром ITO фізично притискається до нижнього жорсткого скляного шару, створюючи резистивний подільник напруги.

Переваги резистивної технології в полі:
- Абсолютний імунітет до дощу, снігу, бризок солоної води, бруду, пилу та мастила.
- Надійне спрацьовування від натискання будь-яким предметом: товстою зимовою рукавицею з підігрівом, кутом пластикової карти, олівцем або дерев'яною паличкою.

Недоліки, які обмежують їх застосування:
- **Низька оптична прозорість**: наявність двох провідних шарів та мікроскопічних діелектричних точок-розпірок знижує світлопропускання до 75–80 %, що критично погіршує читабельність на сонці.
- **Механічна вразливість**: верхня плівка з поліетилентерефталату (PET) легко дряпається піском і втрачає герметичність від ударів.
- **Відсутність жестів**: не підтримує плавне масштабування карти та одночасне утримання декількох кнопок.

### Гібридна архітектура: фізичні органи керування як надійний дублер

У критичних безпілотних комплексах та авіоніці діє фундаментальне ергономічне правило: **жодна життєво важлива функція не повинна залежати виключно від сенсорного екрана**.

Сенсорний дисплей оптимізований для огляду оперативної обстановки, вибору цілей на карті та перегляду відео. Усі критичні операції мають бути продубльовані фізичними органами введення:
- **Інкрементальні енкодери з вираженими тактильними кроками (Detents)**: дозволяють покроково гортати списки команд, перемикати екрани чи змінювати висоту польоту, чітко відчуваючи кожен клік пальцем навіть у товстій рукавиці за температури −20 °C.
- **5-позиційні тактильні навігаційні перемикачі (D-Pad)**: забезпечують переміщення фокусу по екранних віджетах («вгору/вниз/вліво/вправо») та підтвердження дії центральним кліком («Enter»).
- **Механічні кнопки з довгим ходом (1.5–2.5 мм) та високим зусиллям спрацьовування (3–5 Н)**: унеможливлюють випадкове натискання за рахунок тактильного бар'єра спрацьовування внутрішнього купола (англ. *snap dome*).

## Розмір та інтервали елементів: моторний контроль і закон Фіттса

Під час проєктування графічного інтерфейсу для мобільних телефонів розробники зазвичай орієнтуються на стандарти Apple Human Interface Guidelines або Google Material Design, де мінімальний розмір інтерактивної кнопки становить `7–9 мм` (близько 44–48 пікселів на дисплеях із щільністю 160 DPI), а відстань між сусідніми елементами не перевищує 1–2 мм. Перенесення таких нормативів у польовий термінал гарантовано призводить до зриву виконання завдань.

![Зони досяжності великого пальця та розмір тактильних кнопок](/root/course/embedded/ekran-u-poli/img/thumb-zone-and-targets.svg)
*Ергономіка однорукого хвату: критичні кнопки розміщуються в нижній природній дузі великого пальця, мають розмір від 15 мм та захисні зазори не менше 4 мм.*

### Психофізіологія оператора в стресових умовах

У польових умовах на рухову моторику людини діє комплекс деструктивних факторів:
1. **Стрес і викид адреналіну**: викликає периферичний спазм судин (холодні пальці) та фізіологічний тремор із частотою 2–5 Гц і амплітудою зміщення кінчика пальця до 3–6 мм.
2. **Вплив низьких температур**: за температури нижче +5 °C різко знижується чутливість рецепторів шкіри (пропріоцепція), час реакції збільшується у 1.5–2 рази, а координація дрібних рухів деградує до рівня грубого позиціонування кисті.
3. **Механічна вібрація**: оператор, який перебуває всередині рухомої колісної або гусеничної платформи, зазнає низькочастотних поштовхів із частотою 5–15 Гц, які передаються на руку через корпус термінала.

### Закон Фіттса у польовому середовищі

Час швидкого позиціонування пальця на цілі `T` описується законом Фіттса:

```
T = a + b · log₂(2D / W)              [час потрапляння у кнопку за законом Фіттса]
```

де:
- `D` — дистанція переміщення пальця від поточного положення до центру цілі;
- `W` — ефективна ширина (розмір) цільової кнопки;
- `a` та `b` — емпіричні константи нервово-м'язової системи.

Логарифмічний вираз `ID = log₂(2D / W)` називають індексом складності дії (англ. *Index of Difficulty*). 

У спокійних лабораторних умовах дисперсія точки дотику сухого пальця становить `σ ≈ 1.5 мм`. Для кнопки розміром `W = 8 мм` імовірність виходу за межі становить менше 1 %.

У польових умовах через тремор, вібрацію та товсту рукавицю ефективна пляма контакту зростає до `18–22 мм`, а дисперсія точки торкання розширюється до `σ_field ≈ 4.5–6.0 мм`. Якщо ширина кнопки становить ті самі 8 мм, інтеграл імовірності помилкового натискання сусідньої зони перевищує 35–40 %.

### Нормативи польової геометрії Touch Target

Щоб зберегти ймовірність безпомилкового натискання на рівні >99 % в умовах моторного тремору, розміри елементів інтерфейсу мають відповідати польовому тактильному стандарту:

1. **Мінімальний розмір активної зони (Touch Target Size)**:
   - Вторинні кнопки та елементи налаштувань: **12–14 мм** (близько 75–90 px на екрані 160 DPI).
   - Основні кнопки виконання операцій (зміна режиму, рух по карті): **15–18 мм** (100–120 px).
   - Критичні функції екстреної дії (Arm, Disarm, Abort, Return to Home): **20–25 мм** (130–160 px).

2. **Захисні інтервали (Dead Zones / Separation Gap)**:
   - Між сусідніми кнопками обов'язково залишається мертва зона завширшки не менше **3–5 мм** (20–35 px), вільна від інтерактивних елементів.
   - Якщо палець у товстій рукавиці потрапляє в зазор між двома кнопками, система не повинна викликати обидві дії або випадково обирати першу ліпшу — подія торкання в мертвій зоні просто відкидається.

3. **Візуальна межа проти сенсорної (Visual vs Hit-Test Bounds)**:
   - Візуальна рамка кнопки може бути трохи меншою для компактності (наприклад, 12×12 мм), але її активна область обробки подій (*hitbox*) програмно розширюється на весь допустимий квадрат 16×16 мм.

## Ергономіка однорукого керування: зони великого пальця

У реальних бойових чи аварійно-рятувальних сценаріях оператор часто не має можливості тримати термінал двома руками, спершись на стіл. Одна рука тримає зброю, інструмент або радіостанцію, а друга утримує важкий польовий термінал вагою 600–900 г за бічну грань і одночасно виконує всі маніпуляції великим пальцем.

### Анатомія зон великого пальця (Thumb Zone Mapping)

Під час утримання пристрою однією рукою великий палець рухається навколо сідлоподібного зап'ястково-п'ясткового суглоба, описуючи дугоподібну траєкторію. Простір екрана чітко розпадається на три функціональні зони:

1. **Природна зона (Natural Zone / Sweet Spot)**:
   - Охоплює нижню третину дисплея та правий нижній кут (для правого хвату).
   - Палець дістає до будь-якої точки дуги без напруження зв'язок і, головне, **без зміни положення долоні на корпусі**.
   - **Призначення**: сюди виносяться 100 % органів оперативного керування — перемикачі польотних режимів, кнопки зміни висоти, підтвердження команд.

2. **Зона розтягування (Stretch Zone)**:
   - Центральна частина екрана.
   - Потребує повного випрямлення великого пальця з напруженням міжпальцевих м'язів. Точність позиціонування знижується на 30–40 %.
   - **Призначення**: списки параметрів, некритичні вкладки, інтерактивна навігаційна карта.

3. **Заборонена / важкодосяжна зона (Hard-to-Reach / Danger Zone)**:
   - Верхня третина дисплея та протилежний верхній кут.
   - Щоб дістатися сюди великим пальцем, оператор змушений послабити хват і перехопити важкий корпус пальцями вгору. У рукавицях за наявності вібрації або бруду на корпусі це у 20–30 % випадків призводить до вислизання термінала з руки.
   - **Призначення**: виключно статична інформація. Тут розміщуються статус-бар зв'язку, індикатор залишку заряду батареї, координати супутників, годинник і системні повідомлення. **Жодної інтерактивної або критичної кнопки у верхній зоні бути не повинно**.

### Нижньоорієнтована архітектура (Bottom-Oriented UI)

На відміну від десктопних програм, де головне меню традиційно знаходиться вгорі, інтерфейс польового термінала будується строго «знизу вгору»:
- Навігаційна панель вкладок (Navigation Bar) закріплюється вздовж нижнього краю екрана.
- Спливаючі діалогові вікна (Action Sheets / Drawers) виїжджають із нижньої межі вгору, перекриваючи лише необхідну частину карти, щоб кнопки підтвердження залишалися безпосередньо під великим пальцем.
- Інтерактивні селектори режимів проектуються у вигляді кругових сегментних перемикачів або вертикальних барабанів великого радіуса, які природно лягають під дугоподібний рух пальця.

### Захист від ненавмисних критичних дій: Hold-to-Confirm

Звичайна діалогова форма з кнопкою «ОК» є абсолютно непридатною для польових терміналів. Під час поштовху техніки палець оператора випадково торкається спливаючого вікна в зоні кнопки підтвердження, активуючи фатальну команду (наприклад, аварійну зупинку моторів над водою).

Для запобігання хибним спрацьовуванням застосовують два поведінкові патерни:

1. **Кнопка з утриманням (Hold-to-Confirm Button)**:
   - Щоб команда спрацювала, оператор повинен притиснути кнопку і безперервно утримувати її протягом `1.5–2.0 с`.
   - По периметру кнопки або всередині її фону відмальовується круговий/лінійний індикатор заповнення, який показує накопичення таймера.
   - Якщо через тремтіння палець зісковзує з кнопки або відривається раніше встановленого часу, таймер миттєво скидається на нуль, а дія скасовується.

2. **Двокроковий слайдер-підтвердження (Swipe-to-Confirm Slider)**:
   - Для активації функції (наприклад, переведення автопілота в режим ручного пілотування) повзунок необхідно змістити з лівого краю в крайній правий на дистанцію не менше 40–50 мм без відриву пальця.

## Бібліотека стилів та адаптивних віджетів на базі LVGL

Для побудови вбудованих графічних інтерфейсів на мікроконтролерах і вбудованих процесорах (STM32, ESP32-S3, NXP i.MX RT, Allwinner/Rockchip під Linux) стандартом є графічна бібліотека [LVGL](root:embedded/framebuffer-basics) (англ. *Light and Versatile Graphics Library*). 

LVGL підтримує систему динамічних тем (`lv_theme_t`), апаратне прискорення відмальовки та єдину абстракцію пристроїв введення (`lv_indev_t`), що дозволяє одночасно керувати інтерфейсом як через сенсорний екран, так і через фізичні кнопки та енкодери.

### Архітектура польової теми LVGL

Польова тема визначає метрики віджетів (мінімальні розміри не менше 15 мм, поля `pad` не менше 4 мм), високу контрастність та відсутність згладжених напівпрозорих тіней, які споживають обчислювальні ресурси CPU та розмивають картинку на сонці.

Розгляньмо реалізацію стилів польової теми мовами C та C++:

```c
#include "lvgl.h"

/* Палітра денного висококонтрастного режиму */
#define FIELD_COLOR_BG       lv_color_hex(0x000000) // Глибокий чорний фон
#define FIELD_COLOR_FG       lv_color_hex(0xFFFFFF) // Чистий білий текст
#define FIELD_COLOR_ACCENT   lv_color_hex(0xFFD700) // Сигнальний золотаво-жовтий
#define FIELD_COLOR_ALERT    lv_color_hex(0xFF0000) // Насичений червоний тривоги
#define FIELD_COLOR_SAFE     lv_color_hex(0x00FF00) // Яскраво-зелений зв'язку

/* Метрики польових віджетів (розрахунок під екран 160 DPI: 1 мм ≈ 6.3 px) */
#define FIELD_TARGET_MIN_W   95  // ~15 мм мінімальна ширина кнопки
#define FIELD_TARGET_MIN_H   95  // ~15 мм мінімальна висота кнопки
#define FIELD_PAD_GAP        25  // ~4 мм захисний зазор між кнопками

static lv_style_t style_field_btn;
static lv_style_t style_field_btn_focused;
static lv_style_t style_field_btn_pressed;

void field_theme_init(void) {
    /* Базовий стиль тактильної польової кнопки */
    lv_style_init(&style_field_btn);
    lv_style_set_min_width(&style_field_btn, FIELD_TARGET_MIN_W);
    lv_style_set_min_height(&style_field_btn, FIELD_TARGET_MIN_H);
    lv_style_set_bg_color(&style_field_btn, lv_color_hex(0x1A1A1A));
    lv_style_set_bg_opa(&style_field_btn, LV_OPA_COVER);
    lv_style_set_border_color(&style_field_btn, FIELD_COLOR_FG);
    lv_style_set_border_width(&style_field_btn, 3);
    lv_style_set_radius(&style_field_btn, 8);
    lv_style_set_text_color(&style_field_btn, FIELD_COLOR_FG);
    lv_style_set_pad_all(&style_field_btn, 12);

    /* Стиль фокусу від фізичного енкодера / D-Pad */
    lv_style_init(&style_field_btn_focused);
    lv_style_set_border_color(&style_field_btn_focused, FIELD_COLOR_ACCENT);
    lv_style_set_border_width(&style_field_btn_focused, 5);

    /* Стиль натиснутого стану */
    lv_style_init(&style_field_btn_pressed);
    lv_style_set_bg_color(&style_field_btn_pressed, FIELD_COLOR_ACCENT);
    lv_style_set_text_color(&style_field_btn_pressed, FIELD_COLOR_BG);
}

void apply_field_btn_style(lv_obj_t *btn) {
    lv_obj_add_style(btn, &style_field_btn, LV_STATE_DEFAULT);
    lv_obj_add_style(btn, &style_field_btn_focused, LV_STATE_FOCUSED);
    lv_obj_add_style(btn, &style_field_btn_pressed, LV_STATE_PRESSED);
}
```

### Віджет кнопки з утриманням (Tactical Hold-to-Confirm)

Для захисту від випадкових натискань під час тряски створюється спеціальний віджет на базі кнопки та таймера анімації. Коли надходить подія `LV_EVENT_PRESSED`, запускається таймер накопичення заряду. Кожні 50 мс оновлюється круговий дуговий індикатор `lv_arc`. Якщо користувач утримує палець повні 1500 мс, генерується спеціальна користувацька подія підтвердження `LV_EVENT_VALUE_CHANGED` і спрацьовує дія. Якщо палець відпущено раніше (`LV_EVENT_RELEASED` або `LV_EVENT_PRESS_LOST`), таймер зупиняється, а дуга миттєво скидається на 0.

:::tabs
```c
typedef struct {
    lv_obj_t *btn;
    lv_obj_t *arc;
    lv_timer_t *timer;
    uint32_t hold_time_ms;
    uint32_t elapsed_ms;
    void (*on_confirm)(void *user_data);
    void *user_data;
} tactical_hold_btn_t;

static void hold_timer_cb(lv_timer_t *timer) {
    tactical_hold_btn_t *hbtn = (tactical_hold_btn_t *)lv_timer_get_user_data(timer);
    hbtn->elapsed_ms += 50;

    int32_t progress = (hbtn->elapsed_ms * 100) / hbtn->hold_time_ms;
    if (progress > 100) progress = 100;
    lv_arc_set_value(hbtn->arc, progress);

    if (hbtn->elapsed_ms >= hbtn->hold_time_ms) {
        lv_timer_pause(timer);
        hbtn->elapsed_ms = 0;
        lv_arc_set_value(hbtn->arc, 0);
        if (hbtn->on_confirm) {
            hbtn->on_confirm(hbtn->user_data);
        }
    }
}

static void hold_btn_event_cb(lv_event_t *e) {
    tactical_hold_btn_t *hbtn = (tactical_hold_btn_t *)lv_event_get_user_data(e);
    lv_event_code_t code = lv_event_get_code(e);

    if (code == LV_EVENT_PRESSED) {
        hbtn->elapsed_ms = 0;
        lv_arc_set_value(hbtn->arc, 0);
        lv_timer_resume(hbtn->timer);
    } else if (code == LV_EVENT_RELEASED || code == LV_EVENT_PRESS_LOST) {
        lv_timer_pause(hbtn->timer);
        hbtn->elapsed_ms = 0;
        lv_arc_set_value(hbtn->arc, 0);
    }
}
```

```cpp
#include "lvgl.h"
#include <functional>
#include <memory>

namespace field_ui {

class TacticalHoldButton {
public:
    using ConfirmCallback = std::function<void()>;

    TacticalHoldButton(lv_obj_t* parent, const char* label, uint32_t hold_time_ms, ConfirmCallback cb)
        : hold_time_ms_(hold_time_ms), callback_(std::move(cb)) {
        
        btn_ = lv_btn_create(parent);
        ThemeEngine::instance().styleButton(btn_);

        label_ = lv_label_create(btn_);
        lv_label_set_text(label_, label);
        lv_obj_center(label_);

        // Круговий індикатор заповнення по контуру кнопки
        arc_ = lv_arc_create(btn_);
        lv_obj_set_size(arc_, Metrics::MinTargetWidth - 10, Metrics::MinTargetHeight - 10);
        lv_arc_set_rotation(arc_, 270);
        lv_arc_set_bg_angles(arc_, 0, 360);
        lv_arc_set_angles(arc_, 0, 0);
        lv_arc_set_range(arc_, 0, 100);
        lv_obj_set_style_arc_color(arc_, Palette::Accent, LV_PART_INDICATOR);
        lv_obj_set_style_arc_width(arc_, 4, LV_PART_INDICATOR);
        lv_obj_remove_style(arc_, nullptr, LV_PART_KNOB); // Прибираємо ручку
        lv_obj_clear_flag(arc_, LV_OBJ_FLAG_CLICKABLE);
        lv_obj_center(arc_);

        timer_ = lv_timer_create(timerCallbackThunk, 50, this);
        lv_timer_pause(timer_);

        lv_obj_add_event_cb(btn_, eventCallbackThunk, LV_EVENT_ALL, this);
    }

    ~TacticalHoldButton() {
        if (timer_) {
            lv_timer_delete(timer_);
        }
    }

    TacticalHoldButton(const TacticalHoldButton&) = delete;
    TacticalHoldButton& operator=(const TacticalHoldButton&) = delete;

private:
    static void timerCallbackThunk(lv_timer_t* t) {
        auto* self = static_cast<TacticalHoldButton*>(lv_timer_get_user_data(t));
        self->onTick();
    }

    static void eventCallbackThunk(lv_event_t* e) {
        auto* self = static_cast<TacticalHoldButton*>(lv_event_get_user_data(e));
        self->onEvent(lv_event_get_code(e));
    }

    void onTick() {
        elapsed_ms_ += 50;
        int32_t progress = static_cast<int32_t>((elapsed_ms_ * 100) / hold_time_ms_);
        if (progress > 100) progress = 100;
        lv_arc_set_value(arc_, progress);

        if (elapsed_ms_ >= hold_time_ms_) {
            lv_timer_pause(timer_);
            elapsed_ms_ = 0;
            lv_arc_set_value(arc_, 0);
            if (callback_) {
                callback_();
            }
        }
    }

    void onEvent(lv_event_code_t code) {
        if (code == LV_EVENT_PRESSED) {
            elapsed_ms_ = 0;
            lv_arc_set_value(arc_, 0);
            lv_timer_resume(timer_);
        } else if (code == LV_EVENT_RELEASED || code == LV_EVENT_PRESS_LOST) {
            lv_timer_pause(timer_);
            elapsed_ms_ = 0;
            lv_arc_set_value(arc_, 0);
        }
    }

    uint32_t hold_time_ms_{1500};
    uint32_t elapsed_ms_{0};
    ConfirmCallback callback_;
    lv_obj_t* btn_{nullptr};
    lv_obj_t* label_{nullptr};
    lv_obj_t* arc_{nullptr};
    lv_timer_t* timer_{nullptr};
};

} // namespace field_ui
```

## Інженерний чекліст адаптації польового HMI

Перед відправкою термінала або пульта керування в польові випробування перевірте виконання обов'язкових інженерних критеріїв:

1. **Оптичний стек**:
   - Дисплейний модуль зібраний за технологією **Optical Bonding** (клей LOCA/OCA, відсутній повітряний проміжок).
   - Захисне скло має інтерференційне покриття **AR** (відбиття < 1 %) та помірне матове травлення **AG** (75–85 GU).
   - Яскравість підсвічування перевищує **1000–1200 ніт** з автоматичним регулюванням за датчиком освітленості.

2. **Сенсор і органи введення**:
   - Тач-контролер підтримує апаратний режим **Glove Mode** та алгоритми відхилення вологи (**Water Rejection**).
   - Усі критичні дії дублюються фізичними **енкодерами з кліками** або герметичними кнопками з ходом >1.5 мм.

3. **Графічний інтерфейс**:
   - Мінімальний розмір сенсорних кнопок становить **14–16 мм** із захисними зазорами не менше **3–5 мм**.
   - Усі інтерактивні елементи зосереджені в **нижній дузі досяжності великого пальця (Natural Thumb Zone)**.
   - Критичні операції (Arm, Disarm, Abort) захищені утриманням **Hold-to-Confirm (>1.5 с)** або слайдером.
   - Реалізовано миттєве перемикання в **Day High Contrast Mode** (чорно-жовтий) та **Night Red Mode** (темно-червоний).
