# Апарат, який рушив сам: плаваючий затвор, підтяжки за замовчуванням, безпечний стан виводів при скиданні

<preknowlist>
- [FMEA у вбудованих системах](root:embedded/fmea-embedded) — аналіз ланцюгів відмов, оцінка тяжкості наслідків та пошук незахищених режимів роботи.
- [Будова MOSFET](root:hw-components/transistor-idea) — ізольований затвор польового транзистора, керування електричним полем та порогова напруга.
- [Супервізор напруги та скидання](root:embedded/reset-sequence) — поведінка живлення, рівні скидання мікроконтролера та час виходу на стабільну тактову частоту.
- [Сторожовий таймер](root:sf-devices/watchdog) — апаратний нагляд за зависанням прошивки та примусовий перезапуск у безпечний стан.
</preknowlist>

Щойно зібраний чотириколісний робот масою п'ятнадцять кілограмів стоїть на складальному столі. Інженер підключає USB-кабель програматора, щоб завантажити оновлену прошивку керування приводами. У мить, коли середовище розробки переводить мікроконтролер у режим завантажувача (англ. *bootloader*) і подає імпульс на лінію скидання, безколекторні ходові мотори з вереском стартують на повній потужності. Апарат зривається з місця, зносить зі столу вимірювальні прилади й розбивається об стіну. У коді прошивки не було жодної команди на рух — центральний процесор у цей момент взагалі не виконував користувацьких інструкцій. Привід ожив самостійно виключно через фізику напівпровідникового ключа та стан виводів мікроконтролера під час скидання.

Ця аварія — не поодинокий дефект окремої плати, а системна небезпека, закладена у самій природі сучасних цифрових схем. Якщо силовий ключ керується напругою, а лінія керування хоча б на мікросекунду втрачає жорстку прив'язку до визначеного потенціалу, накопичений заряд перетворює вимкнений пристрій на некеровану загрозу.

> 🔧 **Навіщо це.** У побутовій електроніці завислий стан виводу щонайбільше не запалить світлодіод. У системах із силовою енергією — промислових верстатах із ЧПК, робототехнічних шасі, сервоприводах рулів дрона чи нагрівачах 3D-принтерів — самочинний перехід силового транзистора у відкритий стан означає фізичне руйнування механіки, пожежу силового акумулятора або травмування персоналу. Безпека приводу починається не з перевірки помилок у коді `main()`, а з апаратної схемотехніки, що тримає затвори замкненими ще до появи першого тактового імпульсу процесора.

## 1. Проблема мимовільного руху: плаваючий затвор силового ключа

Щоб зрозуміти, чому вимкнений транзистор раптово відкривається, слід поглянути на внутрішню структуру польового транзистора з ізольованим затвором (англ. *Metal-Oxide-Semiconductor Field-Effect Transistor*, MOSFET — де *transistor* походить від лат. *transfer*, переносити, та *resistor*, опір).

На відміну від біполярного транзистора (BJT), де для утримання відкритого стану потрібен безперервний базовий струм у кілька десятків міліамперів, MOSFET є приладом, керованим виключно електричним полем. Його затвор (англ. *gate*) фізично відокремлений від напівпровідникового кремнієвого каналу найтоншим шаром діелектрика — діоксиду кремнію `SiO₂`, товщина якого в сучасних польових транзисторах становить від десяти до сорока нанометрів.

![Фізика плаваючого затвора](/root/course/embedded/aparat-iakyi-rushyv-sam/img/floating-gate-danger.svg)
*Фізичний механізм мимовільного відкриття MOSFET: при переході виводу мікроконтролера у стан High-Z затвор перетворюється на ізольовану обкладку конденсатора. Струми витоку плати та наведення заряджають затворну ємність вище порогової напруги, відкриваючи транзистор у лінійному режимі.*

Опір ізоляції діоксиду кремнію перевищує `10¹² Ом` (один тераом). У статичному стані постійний струм крізь затвор взагалі не тече: вимірювальні прилади фіксують лише мізерний струм витоку в лічені пікоампери (`10⁻¹² А`). З погляду зовнішнього електричного кола затвор є високоякісним конденсатором із мізерними власними втратами.

Повна вхідна ємність транзистора `C_iss` утворюється сумою двох фізичних ємностей: ємності між затвором та витоком `C_gs` і ємності між затвором та стоком `C_gd`:

```
C_iss = C_gs + C_gd
```

Для типових силових транзисторів, розрахованих на струми в десятки амперів (наприклад, IRFZ44N, IRLB8721 чи IRLR8743), величина `C_iss` лежить у діапазоні від `800 пФ` до `3500 пФ`.

Коли мікроконтролер активно керує транзистором, його вихідний каскад з'єднує затвор або з шиною живлення `3.3 В` (відкриваючи канал), або з шиною землі `0 В` (примусово викачуючи заряд і закриваючи канал). Але що відбувається, коли вихідний каскад переходить у стан високого імпедансу (англ. *High-Z*, де *impedance* — лат. *impedire*, перешкоджати)?

У стані High-Z обидва вихідні транзистори мікроконтролера закриті. Лінія між виводом мікроконтролера та затвором MOSFET перетворюється на електричний острів, що висить у повітрі (англ. *floating gate*). Будь-який електричний заряд, що потрапляє на цей провідник, опиняється у пастці, оскільки шляхів для його швидкого стікання на землю просто не існує.

На друкованій платі завжди діють щонайменше три непереборні джерела паразитних зарядів:

1. **Струми поверхневого витоку текстоліту (`I_leak`).** Навіть на ретельно відмитій платі залишки солей, мікродомішки активованого флюсу та атмосферна волога створюють поверхневий опір ізоляції порядку `10–100 МОм`. Між сусідньою доріжкою живлення `+5 В` або `+12 В` та лінією затвора виникає слабкий паразитичний струм від `10 нА` до `500 нА`.
2. **Ємнісний зв'язок Міллера (`C_gd`).** Коли силове живлення приводу вмикається контактором або акумулятором, на стоку транзистора напруга стрибає від `0 В` до `24 В` чи `48 В`. Цей перепад напруги `dV_ds / dt` крізь внутрішню ємність `C_gd` інжектує струм безпосередньо в затвор:

```
I_miller = C_gd · (dV_ds / dt)
```

3. **Електростатичні наведення та радіочастотний шум.** Доріжка плати завдовжки лише кілька сантиметрів діє як антена, вловлюючи електромагнітне поле від сусідніх імпульсних перетворювачів, радіомодулів або дотику руки людини.

Оскільки ємність `C_iss` невелика, а струм витоку не має куди стікати, напруга на затворі зростає за базовим законом електростатики:

```
V_gs(t) = (I_leak · t) / C_iss
```

Для logic-level MOSFET порогова напруга відкриття `V_th` (англ. *threshold voltage*) становить усього `1.0–1.8 В`. Якщо струм витоку становить лише `50 нА`, а ємність затвора — `1500 пФ`, час самовільного заряду до порогу відкриття обчислюється як:

```
t
= (1.5 В · 1500 · 10⁻¹² Ф) / (50 · 10⁻⁹ А)             [підстановка порогової напруги, ємності та струму витоку]
= 0.045 с = 45 мс                                      [результат: час до відкриття ключа без підтяжки]
```

Усього за сорок п'ять мілісекунд затвор без жодної команди нагнітає потенціал, достатній для відкриття транзистора. Детальні формули розрахунку ємнісних кіл наведено у [математичному розборі затворного кола](root:embedded/aparat-iakyi-rushyv-sam/math-gate-discharge.md).

Найгірше те, що транзистор відкривається не стрибком у режим повного насичення, а повільно вповзає в лінійний (активний) режим. У лінійному режимі опір каналу `R_ds` становить не міліоми, а десятки або сотні ом. При напрузі живлення `24 В` і струмі мотора `5 А` на кристалі транзистора починає розсіюватися теплова потужність:

```
P = I_ds · V_ds = 5 А · 12 В = 60 Вт
```

Маленький напівпровідниковий корпус без масивного радіатора за пів секунди розігрівається до температури понад `200 °C`. Кремнієвий кристал зазнає теплового пробою (англ. *thermal runaway*), стік намертво сплавляється з витоком, перетворюючись на суцільну перемичку, і мотор уже не зупинити жодними командами мікроконтролера.

## 2. Поведінка виводів мікроконтролера при скиданні, старті та перепрошивці

Чому ж вивід мікроконтролера взагалі опиняється у стані High-Z? Багато розробників помилково припускають, що перший рядок функції `main()` вирішує всі проблеми ініціалізації. Це ігнорує реальні фізичні процеси всередині кремнію мікроконтролера під час запуску.

![Часова діаграма станів GPIO](/root/course/embedded/aparat-iakyi-rushyv-sam/img/mcu-boot-gpio-states.svg)
*Часова діаграма станів виводу мікроконтролера від подачі живлення до виконання прикладного коду. Червона зона — вікно небезпеки, де вивід перебуває у стані High-Z або під дією слабких внутрішніх підтяжок за замовчуванням.*

Розгляньмо крок за кроком фази життя цифрового мікроконтролера (будь то STM32, ESP32, AVR чи RP2040) від моменту появи живлення до старту вашої програми:

### Фаза 1: Наростання живлення та апаратне скидання (POR / Brown-out)
Коли живлення `3.3 В` подається на плату, напруга на конденсаторах фільтра наростає не миттєво, а за час від `100 мкс` до `10 мс`. Доки напруга не досягне внутрішнього порогу стабільної роботи логічних вентилів (зазвичай `1.8–2.4 В`), схема стеження за живленням (англ. *Power-On Reset*, POR) та внутрішній супервізор тримають процесорне ядро в стані апаратного скидання.

У цей період внутрішні регістри конфігурації портів вводу/виводу ще не завантажені зі значень за замовчуванням. Вихідні комплементарні транзистори буферів GPIO повністю знеструмлені. Вивід фізично ізольований від внутрішніх шин і перебуває у стані чистого **High-Z**.

### Фаза 2: Зовнішнє скидання (утримання лінії NRST)
Якщо лінія апаратного скидання `NRST` примусово притягнута до землі кнопкою або зовнішнім супервізором напруги, тактовий генератор ядра зупинено. Специфікація абсолютних більшостей мікроконтролерів (зокрема ARM Cortex-M) прямо стверджує: під час утримання сигналу Reset усі порти вводу/виводу безумовно переходять у стан входу без активних вихідних драйверів (High-Z Input).

### Фаза 3: Робота апаратного завантажувача (ROM Bootloader)
Коли лінія `NRST` відпускається, ядро починає виконувати код. Але це ще не ваш код. Якщо активовано режим завантажувача (наприклад, стан виводів `BOOT0 = 1` у STM32 або `GPIO0 = 0` у ESP32 для прошивки через UART чи USB DFU), процесор переходить до виконання зашитого на заводі ROM-коду завантажувача.

Завантажувач опитує інтерфейси зв'язку, чекає передачі бінарного образу по UART чи USB, записує байти у флеш-пам'ять і проводить верифікацію. Цей процес триває від **кількох секунд до хвилини**. Увесь цей час усі не задіяні під зв'язок виводи GPIO лишаються у початковому стані скидання. Якщо силовий ключ висів на такому виводі без апаратної фіксації — він буде повністю відкритий протягом усього процесу прошивки пристрою.

### Фаза 4: Запуск прошивки (Startup & CRT0)
Навіть коли завантажувач передає керування користувацькій прошивці, старт відбувається не миттєво:
1. Запускається ініціалізація векторів переривань (`Reset_Handler`);
2. Стартує зовнішній кварцовий резонатор (HSE/HFXO), що вимагає очікування стабілізації амплітуди коливань (від `2 мс` до `20 мс`);
3. Система фазового автопідстроювання частоти (PLL) входить у синхронізацію;
4. Код `SystemInit` та середовище мови C (CRT0) копіюють секцію `.data` з флеш-пам'яті в RAM та обнуляють секцію `.bss`;
5. Викликаються конструктори глобальних об'єктів C++;
6. Тільки після цього керування потрапляє у функцію `main()`, де перший рядок ініціалізації порту налаштує регістри `MODER` чи `GPIO_TypeDef`.

Сумарне «вікно сліпоти» від моменту скидання до виконання першого рядка ініціалізації GPIO у реальних системах становить від **5 до 50 мілісекунд**, а в разі повільного старту кварцу чи завантажувача — **секунди**. Протягом цього вікна прошивка не має жодної влади над виводами.

### Підступна пастка: виводи з внутрішньою підтяжкою за замовчуванням
Найнебезпечніша помилка вибору виводів на етапі трасування друкованої плати — підключення силових ключів до так званих пінів подвійного призначення або strapping-виводів.

1. **Виводи JTAG / SWD (STM32).** Виводи `PA14` (JTAG TCK), `PA15` (JTAG TDI), `PB4` (JTAG TRST) апаратно мають активні внутрішні підтяжки до живлення `3.3 В` (Pull-Up) або землі (Pull-Down) одразу після скидання, щоб забезпечити коректний стан ліній зневаджувача. Якщо повісити затвор MOSFET на `PA15`, він отримає напругу `3.3 В` одразу в мить увімкнення плати!
2. **Strapping-піни ESP32.** Виводи `GPIO0`, `GPIO2`, `GPIO12` опитуються внутрішнім завантажувачем при старті для вибору джерела завантаження та напруги Flash. Вони мають внутрішні підтяжки опором `30–50 кОм`. Використання їх під силові ключі гарантує короткочасне або постійне спрацювання приводу при старті.

Висновок категоричний: **стан виводу при скиданні не є визначеним нулем, і жоден рядок програмного коду не здатен зарадити фізичному стану плаваючого виводу під час завантаження.**

## 3. Апаратні підтяжки та розрахунок надійного замикання затвора на землю

Єдиний спосіб гарантувати безпечний стан силового ключа у фазі скидання — встановити жорстку апаратну підтяжку резистором безпосередньо на друкованій платі (англ. *Hard Pull-Down / Pull-Up*).

Для нижнього ключа на N-канальному MOSFET (англ. *low-side switch*) безпечним станом є надійно закритий транзистор, тобто нульова напруга між затвором та витоком. Тому резистор підтяжки `R_pd` встановлюється безпосередньо між виводом затвора та шиною землі `GND` поруч із витоком транзистора.

![Схема підтяжки затвора та вибір номіналу](/root/course/embedded/aparat-iakyi-rushyv-sam/img/pull-down-circuit-sizing.svg)
*Схема підключення затвора MOSFET з апаратною підтяжкою R_pd і демпфуючим резистором Rg, а також інженерне обґрунтування вибору номіналу в діапазоні 4.7–10 кОм.*

### Чому номінал підтяжки має бути в діапазоні 4.7 кОм – 10 кОм?

Початківці часто припускаються двох протилежних помилок: встановлюють підтяжку або занадто великого номіналу (`100 кОм`), або занадто малого (`100 Ом`). Розгляньмо фізичні обмеження з обох боків.

#### 1. Чому не можна ставити 100 кОм?
- **Подільник напруги з внутрішньою підтяжкою МК.** Якщо обраний вивід мікроконтролера має апаратну внутрішню підтяжку до `3.3 В` опором `R_pu_int = 40 кОм`, зовнішній резистор `100 кОм` утворює резистивний подільник:

```
V_gate
= 3.3 В · (100 кОм / (40 кОм + 100 кОм))               [формула подільника для R_pd = 100 кОм]
= 3.3 · (100 / 140)                                    [коефіцієнт ділення]
= 2.35 В                                               [результат: напруга перевищує поріг V_th]
```

Напруга `2.35 В` значно перевищує поріг `V_th` (який для логічних транзисторів становить `1.2–1.8 В`). Транзистор повністю відкриється під час скидання!
- **Повільний час розряджання.** Стала часу розряду `τ = R_pd · C_iss` при `C_iss = 2000 пФ` становить `200 мкс`. Напруга спадатиме надто повільно, залишаючи транзистор у лінійному режимі.
- **Беззахисність перед імпульсом Міллера.** Струм наведення `C_gd · (dV/dt)` на опорі `100 кОм` легко сформує пік амплітудою в кілька вольтів, викликаючи паразитичне відкриття ключа.

#### 2. Чому не можна ставити 100 Ом?
- **Перевантаження вихідного каскаду GPIO.** Коли мікроконтролер нарешті ініціалізується і захоче відкрити транзистор, подавши рівень `3.3 В`, через підтяжку `100 Ом` потече струм:

```
I_pin = 3.3 В / 100 Ом = 33 мА
```

Максимальний допустимий струм навантаження одного виводу сучасного мікроконтролера (STM32, ESP32, nRF52) зазвичай становить від `10 мА` до `20 мА`. Струм `33 мА` викличе значне просідання вихідної напруги (до рівня нижче `2.5 В`), перегрів кристала мікроконтролера та швидку деградацію вихідного буфера.

#### 3. Інженерний оптимум: 4.7 кОм – 10 кОм
При виборі номіналу `R_pd = 4.7 кОм`:
1. **Струм у робочому стані** становить мізерні `I = 3.3 В / 4.7 кОм = 0.7 мА`, що не створює жодного навантаження на вивід мікроконтролера.
2. **Подільник із внутрішнім pull-up (40 кОм)** формує на затворі напругу:

```
V_gate
= 3.3 В · (4.7 кОм / (40 кОм + 4.7 кОм))               [формула подільника для R_pd = 4.7 кОм]
= 3.3 · (4.7 / 44.7)                                   [коефіцієнт ділення]
= 0.347 В                                              [результат: напруга надійно нижча за поріг]
```

Напруга `0.347 В` гарантовано перебуває нижче мінімального порогу відкриття будь-якого MOSFET (`0.8–1.0 В`). Транзистор надійно закритий.
3. **Стала часу розряду** становить `τ = 4.7 кОм · 2000 пФ = 9.4 мкс`. Затвор розряджається практично миттєво.

### Демпфуючий послідовний резистор затвора (`R_g`)
Між виводом мікроконтролера та вузлом затвора обов'язково встановлюють послідовний резистор `R_g` номіналом від `10 Ом` до `47 Ом` (зазвичай `22 Ом`).

Він виконує дві критичні функції:
1. **Обмеження пікового струму перезаряджання ємності.** Без нього в момент перемикання виводу з `0` в `1` затворна ємність на перші наносекунди є коротким замиканням, і вихідний каскад GPIO віддає струм у сотні міліамперів, генеруючи імпульсні завади по шині живлення ядра.
2. **Запобігання паразитному LC-дзвону.** Індуктивність друкованої доріжки `L_trace` разом із ємністю `C_iss` утворює коливальний контур. Без активного опору `R_g` добротність контуру висока: на затворі виникають високочастотні коливання (звон) з амплітудою, що може вдвічі перевищувати напругу живлення і пробити тонкий підзатворний оксид. Резистор `22 Ом` демпфує ці коливання, роблячи перехідний процес аперіодичним.

> ⚠️ **Правильне взаємне розташування компонентів:** Резистор підтяжки `R_pd` повинен підключатися **після** послідовного резистора `R_g` — безпосередньо між затвором та витоком (GND) транзистора. Якщо підтяжку помилково підключити до виводу мікроконтролера перед `R_g`, то у разі обриву доріжки чи резистора `R_g` затвор транзистора знову опиниться у небезпечному стані High-Z.

## 4. Дворівневі системи безпеки (Hardware Arming, динамічні ключі безпеки)

Чи достатньо однієї резистивної підтяжки на платі, якщо пристрій несе реальну загрозу життю — наприклад, керує потужними тяговими моторами гусеничної платформи, дисковою пилою верстата або відкриттям клапана подачі газу?

Аналіз надійності (FMEA) показує, що резистивна підтяжка безсила проти таких фатальних сценаріїв:
1. **Пробій вихідного транзистора GPIO.** У разі електричного перевантаження або статичного удару вихідний верхній P-FET мікроконтролера пробивається накоротко на шину `3.3 В`. На виводі з'являється постійна одиниця, яку жодна підтяжка `4.7 кОм` не зможе притягнути до нуля.
2. **Зависання ядра мікроконтролера в активній фазі.** Програма встигла звести рівень у «1» і запустити мотор, після чого сталася помилка HardFault, deadlock у перериванні або збій шини пам'яті. Вивід лишається в одиниці, а мотор продовжує обертатися.
3. **Помилка покажчика пам'яті.** Збій у прошивці випадково перезаписує регістр конфігурації таймера ШІМ або регістр `BSRR` порту.

У відповідальних системах діє фундаментальний принцип функціональної безпеки: **жодна одинична відмова (як у софті, так і в залізі) не повинна призводити до самочинного вмикання небезпечної енергії.**

Для цього застосовують **дворівневе апаратне блокування** (англ. *Hardware Interlock / Arming*).

![Дворівневе динамічне блокування](/root/course/embedded/aparat-iakyi-rushyv-sam/img/dynamic-charge-pump-interlock.svg)
*Схема динамічного ключа безпеки (Charge Pump Safety Gate): живлення силового каскаду можливе лише за наявності активного високочастотного сигналу серцебиття від прошивки. Зависання в 0 або 1 розряджає помпу та знеструмлює привід.*

### Принцип динамічного дозволу (Charge Pump Safety Gate)

Ідея полягає в тому, що сигнал дозволу сили (англ. *Safety Arming Signal*) не може бути статичним рівнем постійної напруги `HIGH` («1»). Дозволом є виключно **динамічний прямокутний сигнал певної частоти** (наприклад, меандр від `1 кГц` до `10 кГц`), який прошивка зобов'язана активно генерувати в головному циклі безпеки.

Схема складається з чотирьох послідовних елементів:
1. **Вивід мікроконтролера `PIN_SAFETY_HEARTBEAT`.** Прошивка генерує меандр лише тоді, коли всі перевірки датчиків пройдено, аварійна кнопка відпущена, а головний цикл дихає нормально.
2. **Розділовий конденсатор `C1` (DC Block, `100 нФ`).** Конденсатор має нескінченний опір для постійного струму і низький опір для змінної частоти `1 кГц`.
3. **Діодна помпа заряду (детектор напруги на двох діодах Шотткі).** Змінні імпульси крізь конденсатор випрямляються діодами і заряджають накопичувальний конденсатор `C2` (`1 мкФ`), на якому формується постійна напруга відмикання силового реле або верхнього P-MOSFET ключа.
4. **Розрядний резистор `R_bleed` (`100 кОм`).** Безперервно розряджає конденсатор `C2`.

### Як схема реагує на аварійні сценарії:

- **Процесор завис у «1» або «0»:** На виводі фіксується постійна напруга `3.3 В` чи `0 В`. Постійний струм не здатний пройти крізь розділовий конденсатор `C1`. Конденсатор `C1` миттєво заряджається і струм припиняється. Резистор `R_bleed` за `2–5 мс` повністю розряджає `C2`. Напруга на затворі ключа живлення падає до нуля, і силове живлення мотора фізично розмикається.
- **Спрацювало скидання (Reset / POR):** Генерація частоти миттєво припиняється, помпа знеструмлюється, привід вимикається.
- **Пробій виводу GPIO на шину живлення:** Конденсатор `C1` надійно блокує постійну напругу `3.3 В`. Ключ лишається закритим.

Тільки живий, справний програмний цикл, який регулярно виконує валідацію датчиків і генерує частоту серцебиття, здатен утримувати живлення силового каскаду.

## 5. Драйвер безпечного керування приводом на C / C++

Програмна реалізація безпечного драйвера повинна унеможливлювати появу короткочасних паразитичних імпульсів (англ. *glitches*) під час ініціалізації та жорстко контролювати послідовність активації живлення.

### Правило виключення імпульсів при ініціалізації GPIO

Типова помилка конфігурації полягає у послідовному виклику функцій, де вивід спершу перемикається у режим виходу (`OUTPUT`), а вже наступним рядком записується нульовий рівень. У мікроконтролерах, де початковий стан вихідного регістра після скидання не скинутий або визначений одиницею, на виводі з'являється небезпечний імпульс тривалістю в кілька мікросекунд.

**Залізний порядок ініціалізації:**
1. Спершу записати логічний `0` у вихідний регістр даних порту (`ODR` у STM32 або `OUT_W1TC` в ESP32);
2. Сконфігурувати внутрішню підтяжку до землі (Pull-Down);
3. Лише після цього перемикати режим роботи піна з входу на вихід (`OUTPUT` / General Purpose Output Push-Pull).

### Протокол взяття на охорону (Arming Protocol)

Керування приводом оформлюють у вигляді автомата скінченних станів:
- `DISARMED` — початковий безпечний стан. ШІМ вимкнено, генератор помпи зупинено.
- `ARMING_REQUEST` — отримання команди на запуск із перевіркою валідаційного токена.
- `SELF_TEST` — перевірка напруги батареї через АЦП, стану кнопки E-Stop та температури ключів.
- `ARMED` — робочий режим: генерація імпульсів серцебиття та оновлення сигналу ШІМ.
- `FAULT` — аварійне блокування при будь-якому збої.

Нижче наведено компактні фрагменти ядра безпечного драйвера мовами C та C++. Повний проект драйвера з деталізацією інтеграції Watchdog оформлено у [драйвері безпечного керування](root:embedded/aparat-iakyi-rushyv-sam/proj-safe-arm-driver.md).

```c
#include <stdint.h>
#include <stdbool.h>

#define ARM_MAGIC_TOKEN     0x5A3C96E1U
#define PWM_MAX_LIMIT       1000U
#define SAFE_VOLTAGE_MIN_MV 11000U

typedef enum {
    SAFE_STATE_DISARMED = 0,
    SAFE_STATE_PRE_ARM_TEST,
    SAFE_STATE_ARMED,
    SAFE_STATE_FAULT
} SafeState;

typedef struct {
    SafeState state;
    uint16_t current_pwm;
    bool estop_pressed;
} MotorSafetyController;

// Апаратні абстракції периферії
extern void hw_set_heartbeat_pin(bool level);
extern void hw_set_pwm_duty(uint16_t duty);
extern uint16_t hw_get_battery_voltage_mv(void);
extern bool hw_read_estop_active(void);

void motor_safety_init(MotorSafetyController *ctrl) {
    // 1. Примусове знеструмлення виходів ДО налаштування
    hw_set_heartbeat_pin(false);
    hw_set_pwm_duty(0);

    ctrl->state = SAFE_STATE_DISARMED;
    ctrl->current_pwm = 0;
    ctrl->estop_pressed = false;
}

bool motor_safety_arm(MotorSafetyController *ctrl, uint32_t token) {
    if (token != ARM_MAGIC_TOKEN || ctrl->state != SAFE_STATE_DISARMED) {
        ctrl->state = SAFE_STATE_FAULT;
        return false;
    }
    
    // Перевірка умов безпеки перед подачею сили
    if (hw_read_estop_active() || hw_get_battery_voltage_mv() < SAFE_VOLTAGE_MIN_MV) {
        ctrl->state = SAFE_STATE_FAULT;
        return false;
    }

    ctrl->state = SAFE_STATE_ARMED;
    return true;
}

void motor_safety_update(MotorSafetyController *ctrl, uint16_t target_pwm) {
    if (hw_read_estop_active()) {
        // Миттєве апаратне знеструмлення
        hw_set_heartbeat_pin(false);
        hw_set_pwm_duty(0);
        ctrl->state = SAFE_STATE_FAULT;
        return;
    }

    if (ctrl->state == SAFE_STATE_ARMED) {
        // Генерація меандру серцебиття для помпи заряду
        static bool hb_toggle = false;
        hb_toggle = !hb_toggle;
        hw_set_heartbeat_pin(hb_toggle);

        ctrl->current_pwm = (target_pwm > PWM_MAX_LIMIT) ? PWM_MAX_LIMIT : target_pwm;
        hw_set_pwm_duty(ctrl->current_pwm);
    } else {
        hw_set_heartbeat_pin(false);
        hw_set_pwm_duty(0);
    }
}
```

```cpp
#include <cstdint>
#include <optional>
#include <concepts>

namespace power::safety {

enum class State : uint8_t {
    Disarmed = 0,
    PreArmTest,
    Armed,
    Fault
};

template <typename HardwarePlatform>
class SafeMotorDriver {
public:
    static constexpr uint32_t ArmTokenMagic = 0x5A3C96E1U;
    static constexpr uint16_t PwmMaxLimit = 1000U;
    static constexpr uint16_t SafeVoltageMinMv = 11000U;

    explicit SafeMotorDriver(HardwarePlatform& hw) noexcept
        : hw_(hw), state_(State::Disarmed), currentPwm_(0), hbPhase_(false) {
        // Гарантуємо безпечний стан виходів при ініціалізації об'єкта
        hw_.writeHeartbeatPin(false);
        hw_.setPwmDuty(0);
    }

    [[nodiscard]] bool requestArm(uint32_t token) noexcept {
        if (token != ArmTokenMagic || state_ != State::Disarmed) {
            state_ = State::Fault;
            disarm();
            return false;
        }

        if (hw_.isEmergencyStopActive() || hw_.readBatteryVoltageMv() < SafeVoltageMinMv) {
            state_ = State::Fault;
            disarm();
            return false;
        }

        state_ = State::Armed;
        return true;
    }

    void disarm() noexcept {
        hw_.writeHeartbeatPin(false);
        hw_.setPwmDuty(0);
        currentPwm_ = 0;
        if (state_ != State::Fault) {
            state_ = State::Disarmed;
        }
    }

    void update(uint16_t targetPwm) noexcept {
        if (hw_.isEmergencyStopActive()) {
            state_ = State::Fault;
            disarm();
            return;
        }

        if (state_ == State::Armed) {
            hbPhase_ = !hbPhase_;
            hw_.writeHeartbeatPin(hbPhase_);

            currentPwm_ = (targetPwm > PwmMaxLimit) ? PwmMaxLimit : targetPwm;
            hw_.setPwmDuty(currentPwm_);
        } else {
            hw_.writeHeartbeatPin(false);
            hw_.setPwmDuty(0);
        }

        hw_.feedWatchdog();
    }

    [[nodiscard]] State getState() const noexcept { return state_; }
    [[nodiscard]] bool isArmed() const noexcept { return state_ == State::Armed; }

private:
    HardwarePlatform& hw_;
    State state_;
    uint16_t currentPwm_;
    bool hbPhase_;
};

} // namespace power::safety
```

## 6. Зведені правила безпечного проєктування силових вузлів

Стійкість апарата до мимовільного руху тримається на чотирьох непорушних інженерних правилах:

1. **Кожен силовий затвор зобов'язаний мати фізичну підтяжку на платі.** Номінал `4.7–10 кОм` забезпечує розряд ємності за лічені мікросекунди, гасить наведення Міллера `dV/dt` та гарантує напругу нижче `0.4 В` навіть при наявності внутрішніх підтяжок мікроконтролера.
2. **Враховувати стан виводів за замовчуванням (Default Reset State).** Ніколи не призначати силові ключі на виводи з апаратним pull-up (JTAG/SWD, Boot-strapping піни), які активуються під час скидання або прошивки через bootloader.
3. **Дворівневий динамічний дозвіл для небезпечної механіки.** Для моторів, клапанів і нагрівачів застосовувати апаратний ключ безпеки з помпою заряду, керованою змінною частотою серцебиття (Heartbeat Clock). При зависанні ядра в «1» або «0» помпа знеструмлює привід за лічені мілісекунди.
4. **Дисципліна ініціалізації в коді.** Завжди записувати безпечний логічний рівень у вихідний регістр ДО переведення режиму порту у стан виходу (Output), виключаючи мікроімпульси перемикання.
