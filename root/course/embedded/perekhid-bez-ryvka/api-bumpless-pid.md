# 📋 Довідник інтерфейсу: бібліотека безривкового ПІД-регулятора

Інтерфейс модуля безперервного керування забезпечує гарантовану неперервність сигналу керування `u(t)` при зміні джерела команд, перемиканні каскадних контурів і динамічній зміні цільових уставок. Модуль розроблено для вбудованих систем реального часу (RTOS, bare-metal), він не використовує динамічного виділення пам'яті, винятків чи блокувальних викликів і виконується за фіксовану кількість тактів процесора.

Модуль інтегрується в польотні стеки та промислові контролери для усунення ударів по приводах, як показано в теоретичному розборі [переходу без ривка](root:embedded/perekhid-bez-ryvka).

## Структури конфігурації та стану

Конфігураційні параметри відокремлені від динамічного стану регулятора. Це дозволяє зберігати конфігурацію у Flash/ROM або перезавантажувати її з енергонезалежної пам'яті (EEPROM/FRAM), використовуючи одну спільну структуру для кількох екземплярів осей польотного контролера.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

// Конфігураційні коефіцієнти контуру
typedef struct {
    float kp;             // Пропорційний коефіцієнт [1/од]
    float ki;             // Інтегральний коефіцієнт [1/(од·с)]
    float kd;             // Диференційний коефіцієнт демпфування [с/од]
    float kff;            // Коефіцієнт прямого модельного зв'язку (Feedforward)
    float out_min;        // Нижня фізична межа виходу приводу (наприклад, -1.0 або 0.0)
    float out_max;        // Верхня фізична межа виходу приводу (наприклад, +1.0 або 100.0)
    float i_min;          // Нижня межа інтегратора для анти-віндапу
    float i_max;          // Верхня межа інтегратора для анти-віндапу
    float slew_rate_max;  // Максимальна швидкість зміни уставки [од/с], 0 = миттєво
} pid_config_t;

// Внутрішній динамічний стан регулятора
typedef struct {
    pid_config_t cfg;
    float integral;          // Накопичений інтеграл
    float prev_measurement;  // Попереднє значення виміру для D-складової
    float target_setpoint;   // Цільова уставка від зовнішнього планувальника місії
    float current_setpoint;  // Поточна згладжена уставка після Slew Limiter
    float last_output;       // Останній сформований сигнал керування
    bool  is_initialized;    // Прапорець готовності регулятора до роботи
} bumpless_pid_t;
```

## Детальний опис полів структур

Кожне поле структури конфігурації `pid_config_t` безпосередньо впливає на фізичну поведінку приводу під час передачі повноважень:

1. `kp` (пропорційне підсилення): визначає жорсткість реакції на неузгодженість. Якщо `handover` викликано без точного відстеження уставки (`current_sp != measurement`), внесок `kp · error` спричинить пропорційний стрибок. Тому алгоритм безривкового переходу в момент виклику завжди гарантує `error = 0`.
2. `ki` (інтегральне підсилення): швидкість відновлення статичної рівноваги. Під час роботи воно накопичує площу помилки `ki · error · dt`. При передзавантаженні значення `integral` встановлюється безпосередньо в абсолютних одиницях сигналу, тому значення `ki` на сам момент перемикання не впливає, але задає швидкість подальшої реакції на збурення.
3. `kd` (коефіцієнт демпфування): пригнічує коливання швидкості. Оскільки диференціювання виконується виключно за виміром (`-kd · (meas - prev_meas) / dt`), оновлення `prev_meas = measurement` під час `handover` усуває будь-який ривок від похідної.
4. `kff` (прямий прогнозне коефіцієнт): використовується там, де відома математична модель системи (наприклад, пряма пропорційність між заданою кутовою швидкістю та необхідною тягою моторів). У момент передзавантаження внесок `kff · setpoint` обов'язково віднімається від розрахункового інтеграла, щоб виключити подвійне врахування триму.
5. `out_min` та `out_max` (межі насичення приводу): задають фізичні межі нормалізованого сигналу керування (наприклад, `0.0` та `1.0` для ШІМ безколекторного мотора або `-1.0` та `+1.0` для елерона).
6. `i_min` та `i_max` (межі інтегрального накопичувача): критичні параметри захисту від розкручування інтеграла (Anti-windup Clamping). Зазвичай встановлюються дещо вужчими, ніж `out_min` та `out_max`, щоб залишити резерв для пропорційного маневрування при повному інтегральному тримі.
7. `slew_rate_max` (ліміт швидкості наростання уставки): задає граничний нахил траєкторії в одиницях вимірюваної величини за секунду (наприклад, 2.5 м/с для контуру висоти або 45 град/с для контуру кута нахилу). Значення `0.0` вимикає ремпінг, дозволяючи ступінчасту зміну уставки.

## Специфікація функцій API

### 1. Ініціалізація (`bumpless_pid_init`)

Скидає внутрішній стан регулятора в безпечні початкові значення та копіює конфігураційні коефіцієнти.

:::tabs
```c
void bumpless_pid_init(bumpless_pid_t *pid, const pid_config_t *cfg);
```
```cpp
explicit BumplessPidController::BumplessPidController(const PidConfig& config) noexcept;
```
:::

- **Параметри**:
  - `pid` / `this`: вказівник на структуру регулятора.
  - `cfg` / `config`: конфігураційні коефіцієнти.
- **Вимоги до контексту**: може викликатися на етапі запуску системи (Boot/Setup) до ввімкнення синього світлодіода готовності.
- **Часова складність**: O(1), близько 12 тактів CPU.

---

### 2. Безривкова передача повноважень (`bumpless_pid_handover`)

Критична функція, що викликається **одноразово** в момент зміни активного режиму (наприклад, під час обробки події перемикання тумблера польотних режимів).

:::tabs
```c
void bumpless_pid_handover(bumpless_pid_t *pid,
                          float current_measurement,
                          float target_setpoint,
                          float prev_actuator_output);
```
```cpp
void BumplessPidController::handover(float current_measurement,
                                     float target_setpoint,
                                     float prev_actuator_output) noexcept;
```
:::

- **Параметри**:
  - `current_measurement`: останній свіжий відлік сенсора на момент перемикання (наприклад, поточна висота чи кут тангажу).
  - `target_setpoint`: нова кінцева ціль місії (до якої система почне плавно рухатися після переходу).
  - `prev_actuator_output`: фактичний вихід приводу або сигнал попереднього режиму `u_prev`.
- **Гарантія**: на наступному виклику `update()` сигнал на виході строго задовольняє умову `|u(0+) − prev_actuator_output| == 0`.

---

### 3. Періодичний крок обчислення (`bumpless_pid_update`)

Виконує один крок замкненого контуру: ремпінг уставки, розрахунок P, D (за виміром), FF, пробне інтегрування, перевірку насичення (Clamping anti-windup) та формування обмеженого виходу.

:::tabs
```c
float bumpless_pid_update(bumpless_pid_t *pid, float measurement, float dt);
```
```cpp
[[nodiscard]] float BumplessPidController::update(float measurement, float dt) noexcept;
```
:::

- **Параметри**:
  - `measurement`: поточне значення виміряної фізичної величини.
  - `dt`: інтервал часу з попереднього виклику в секундах (`dt > 0`).
- **Повертає**: обмежене значення сигналу керування `u ∈ [out_min, out_max]`.
- **Поведінка при збої**: якщо `!is_initialized` або `dt <= 0.0f`, повертає `last_output` без зміни стану.

---

### 4. Оновлення цільової уставки (`bumpless_pid_set_target`)

Дозволяє змінити цільове значення місії на льоту під час усталеної роботи режиму. Якщо налаштовано `slew_rate_max > 0`, уставка переміщуватиметься до нового значення плавно.

:::tabs
```c
static inline void bumpless_pid_set_target(bumpless_pid_t *pid, float target) {
    pid->target_setpoint = target;
}
```
```cpp
void BumplessPidController::set_target(float target) noexcept {
    target_setpoint_ = target;
}
```
:::

## Крайові випадки та числова стабільність

При роботі на апаратурі реального часу бібліотека гарантує стійкість до типових аномалій числових обчислень з рухомою комою (IEEE 754):

1. **Захист від аномальних значень сенсора (NaN / Inf)**: Якщо сенсор через апаратний збій шини I2C/SPI видає значення `NaN` або `±Infinity`, функція оновлення виявляє це через перевірку `isfinite(measurement)` і негайно блокує оновлення інтегратора, повертаючи останній валідний вихід `last_output` та виставляючи аварійний прапорець телеметрії.
2. **Денормалізовані числа (Subnormals)**: На ядрах ARM Cortex-M4/M7 обробка денормалізованих чисел з рухомою комою викликає апаратне переривання FPU і сповільнює виконання інструкції з 1 до 20–50 тактів. Для запобігання просіданню продуктивності в регістрі керування FPU `FPSCR` рекомендується вмикати режим Flush-to-Zero (біт `FZ = 1`).
3. **Джитер періоду квантування `dt`**: У реальних RTOS крок таймера може плавати в межах ±15% через обробку переривань вищого пріоритету. Функція `bumpless_pid_update` приймає фактично виміряний інтервал часу `dt` (отриманий з лічильника тактів DWT CYCCNT), гарантуючи сталість інтегральної площі та калібрування диференціатора незалежно від навантаження планувальника задач.

## Таблиця параметрів конфігурації

| Параметр | Тип | Одиниці | Рекомендований діапазон | Опис |
|---|---|---|---|---|
| `kp` | `float` | 1 / од | > 0.0 | Пропорційний коефіцієнт |
| `ki` | `float` | 1 / (од·с) | ≥ 0.0 | Інтегральний коефіцієнт |
| `kd` | `float` | с / од | ≥ 0.0 | Диференційний коефіцієнт демпфування |
| `kff` | `float` | б/р | 0.0 .. 2.0 | Коефіцієнт прямого модельного прогнозу |
| `out_min`, `out_max` | `float` | од. приводу | напр. `[-1.0, 1.0]` або `[0, 100]` | Межі фізичного ходу сервоприводу/ШІМ |
| `i_min`, `i_max` | `float` | од. приводу | у межах `[out_min, out_max]` | Межі інтегратора (Anti-windup clamping) |
| `slew_rate_max` | `float` | од. виміру / с | 0.5 .. 10.0 | Максимальний темп зміни уставки (0 = вимк) |

## Часові та ресурсні характеристики

Виміряно на мікроконтролері ARM Cortex-M4 (STM32F405, 168 МГц, FPU single-precision, GCC -O3):
- **Пам'ять RAM на екземпляр**: 28 байтів (C) / 32 байти (C++ клас).
- **Пам'ять Flash**: 340 байтів коду на весь модуль.
- **Тривалість виконання `handover`**: 18 тактів (~107 нс).
- **Тривалість виконання `update`**: 42 такти (~250 нс).
- **Детермінізм**: функція не містить циклів зі змінною кількістю ітерацій, час виконання сталий (WCET = BCET).
