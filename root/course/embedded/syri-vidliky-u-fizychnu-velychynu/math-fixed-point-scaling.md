# 🧮 Математика масштабування та оцінка похибок у фіксованій комі

Математичний апарат подання дійсних чисел у цілочисельних регістрах процесора визначає межі точності, накопичення шуму квантування та гарантії відсутності переповнення при перетворенні сирих відліків сенсорів у фізичні одиниці.

## 1. Алгебраїчна модель формату з фіксованою комою

Дійсне число `x` у двійковій системі з фіксованою комою формату `Q_m.n` представляється цілим знаковим числом `X` у додатковому коді розрядністю `N = m + n + 1` (де 1 біт відведено під знак, `m` бітів — під цілу частину, `n` бітів — під дробову частину).

Зв'язок між цілочисельним представленням `X` та дійсним значенням `x` визначається масштабним множником 2^(-n):

```
x = X * 2^(-n)                                [визначення дійсного значення через вагу LSB]
X = round(x * 2^n)                            [квантування дійсного числа у ціле значення Q-формату]
```

Ціна молодшого значущого розряду (роздільна здатність квантування) дорівнює:

```
LSB = 2^(-n)                                  [мінімальний крок зміни фізичної величини]
```

Динамічний діапазон значень, що можуть бути представлені у форматі зі знаком `Q_m.n` на `N`-бітному слові, обмежений інтервалом:

```
X_min = -2^(N - 1) = -2^(m + n)               [мінімальне знакове ціле число в додатковому коді]
X_max = 2^(N - 1) - 1 = 2^(m + n) - 1         [максимальне знакове ціле число]
x_min = -2^m                                  [нижня межа дійсного інтервалу]
x_max = 2^m - 2^(-n)                          [верхня межа дійсного інтервалу]
```

При побудові драйвера вибір розрядності `m` та `n` диктується двома протилежними вимогами:
1. Запас цілої частини `m` має гарантувати, що максимальне можливе фізичне значення сигналу (з урахуванням шумів, перевантажень та технологічного розкиду) не призведе до виходу за межі діапазону.
2. Кількість дробових бітів `n` визначає межу шуму квантування. Збільшення `n` на 1 біт зменшує вагу LSB удвічі, що еквівалентно поліпшенню співвідношення сигнал/шум квантування (SQNR) на 6.02 дБ.

## 2. Множення у фіксованій комі та виведення зміщення розрядності

Нехай маємо два числа у форматах `Q_m1.n1` та `Q_m2.n2`, представлені цілими числами `A` та `B`. Їхні дійсні значення дорівнюють:

```
a = A * 2^(-n1)                               [дійсне значення першого операнда]
b = B * 2^(-n2)                               [дійсне значення другого операнда]
```

Дійсний добуток `p = a · b` має вигляд:

```
p = (A * 2^(-n1)) * (B * 2^(-n2))             [підстановка визначень у добуток]
  = (A * B) * 2^(-(n1 + n2))                  [винесення спільного ступеня двійки]
```

Цілий добуток `P_raw = A · B` автоматично набуває формату з дробовою частиною розрядністю `n3 = n1 + n2`. Для приведення результату до цільового формату `Q_m3.n3` з бажаною кількістю дробових бітів `n_out` необхідно виконати масштабування на коефіцієнт 2^(-(n1 + n2 - n_out)), що в цілочисельній арифметиці відповідає арифметичному зсуву праворуч на `k = n1 + n2 - n_out` бітів:

```
P_out = P_raw >> k                            [зсув праворуч для нормалізації формату]
k = n1 + n2 - n_out                           [кількість бітів для скорочення дробової частини]
```

Якщо обидва множники мають однаковий формат `Q_15.16` (`n1 = 16`, `n2 = 16`), добуток має 32 дробові розряди (`n1 + n2 = 32`). Для повернення назад у `Q_15.16` (`n_out = 16`) зсув становить рівно `k = 32 - 16 = 16` бітів праворуч.

## 3. Математичний аналіз методів округлення та шум квантування

Операція зсуву праворуч на `k` бітів еквівалентна взяттю цілої частини з відкиданням залишку (Truncation / Floor):

```
P_trunc = floor( P_raw / 2^k )                [цілочисельне усічення дробової частини]
```

### Похибка відсікання (Truncation)

Похибка усічення `e_trunc = P_k - P_raw / 2^k` є випадковою величиною, розподіленою на напівінтервалі [-(1 - 2^(-k)), 0]. Її математичне сподівання (систематичне зміщення) та дисперсія дорівнюють:

```
E[e_trunc] = -1/2 * (1 - 2^(-k))              [систематичний негативний зсув середнього значення]
Var[e_trunc] = 1/12 * (1 - 2^(-2k))           [дисперсія шуму квантування при усіченні]
```

При багаторазовій цифровій фільтрації або інтегруванні сирих відліків (наприклад, у безінерціальній навігації при інтегруванні кутової швидкості гіроскопа для визначення кута орієнтації) систематичний зсув `E[e_trunc] ≈ -0.5 LSB` призводить до накопичення лінійно зростаючого дрейфу вихідної фізичної величини. При частоті опитування 1000 Гц зсув усього в 0.5 LSB за одну секунду накопичує помилку в 500 LSB, що повністю руйнує інтеграл навігації.

### Округлення до найближчого (Round to Nearest)

Для усунення систематичного зміщення до проміжного добутку перед зсувом додається коригувальне значення 2^(k-1) (половина ваги молодшого розряду цільового формату):

```
P_round = (P_raw + 2^(k - 1)) >> k            [симетричне округлення додаванням половини LSB]
```

Математичне сподівання похибки симетричного округлення стає нульовим:

```
E[e_round] = 0                                [відсутність систематичного зсуву вимірювання]
Var[e_round] = 1/12 * (1 + 2^(-2k))           [некорельований білий шум квантування]
```

Нульове математичне сподівання гарантує, що при усередненні серії вимірювань датчика шум квантування буде згасати пропорційно 1 / sqrt(M) (де `M` — кількість вибірок у вікні усереднення). Це дозволяє використовувати техніку передискретизації (Oversampling) для отримання ефективної роздільної здатності, вищої за апаратну розрядність АЦП.

## 4. Оцінка меж проміжного переповнення при 32-бітному та 64-бітному множенні

Нехай вхідний сирий відлік сенсора `X_raw` є 16-бітним знаковим числом:

```
-32768 <= X_raw <= 32767                      [діапазон 16-бітного знакового відліку int16_t]
```

Масштабний коефіцієнт `K` задано у форматі `Q_16.16` (32-бітне ціле число):

```
-2147483648 <= K <= 2147483647                [діапазон 32-бітного коефіцієнта int32_t]
```

Максимальне абсолютне значення проміжного добутку досягає:

```
|P_max| = |-32768| * |-2147483648|             [найгірший випадок перемноження мінімальних чисел]
        = 2^15 * 2^31                         [подання через степені двійки]
        = 2^46                                [необхідна розрядність для збереження добутку]
```

Оскільки 2^46 > 2^31 - 1, пряме множення двох 32-бітних чисел у 32-бітному акумуляторі призводить до миттєвого знакового переповнення та катастрофічного спотворення даних.

Використання 64-бітного акумулятора `int64_t` (`N = 64`, максимальне додатне число 2^63 - 1) забезпечує абсолютний запас розрядності:

```
Запас_біт = 63 - 46 = 17 бітів                [гарантований захист від переповнення при множенні]
```

Це дозволяє виконувати не лише одиничне масштабування, але й акумулювання до 2^17 = 131072 послідовних вибірок у режимі ковзного вікна або CIC-фільтрації без ризику виходу за межі розрядності `int64_t`.

## 5. Матричне 3D-калібрування просторових сенсорів

Для трьохосьових акселерометрів, гіроскопів та магнітометрів реальна передавальна характеристика описується не просто скалярним коефіцієнтом, а матричним рівнянням через наявність неортогональності осей (Non-orthogonality) та перехресного зв'язку (Cross-axis sensitivity):

```
V_si = M_calib * (V_raw - V_offset)           [повна 3D-калібрувальна матрична модель]
```

де `V_raw = [X_raw, Y_raw, Z_raw]^T` — вектор сирих відліків, `V_offset = [X_0, Y_0, Z_0]^T` — вектор нульового зсуву, а `M_calib` — матриця розміром 3×3:

```
M_calib = [ S_xx  C_xy  C_xz ]
          [ C_yx  S_yy  C_yz ]
          [ C_zx  C_zy  S_zz ]
```

Діагональні елементи `S_xx, S_yy, S_zz` представляють масштабні коефіцієнти чутливості за окремими осями, а недіагональні елементи `C_ij` компенсують перекіс чутливих осей через похибки монтажу кристала в корпус мікросхеми.

При реалізації у форматі з фіксованою комою `Q_15.16` кожен рядок матриці розраховується через скалярний добуток трьох 32-бітних чисел із сумуванням у єдиному 64-бітному акумуляторі:

```
Result_X = ( M_11 * dX + M_12 * dY + M_13 * dZ + (1 << 15) ) >> 16
```

Такий ланцюг обчислень виконується процесорами ARM Cortex-M4/M7 за допомогою трьох послідовних інструкцій `SMLAL` (Signed Multiply-Accumulate Long), які за три процесорні такти проводять повну просторову компенсацію без залучення FPU.
