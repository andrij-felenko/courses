# 🔌 Архітектура та протокол шинних сервоприводів

Шинний сервопривід (англ. *Smart Bus Servo*, серії Robotis Dynamixel, Feetech STS/SCS) поєднує в одному герметичному корпусі колекторний або безколекторний мотор, прецизійний металевий редуктор, 12-бітний безконтактний магнітний енкодер на ефекті Холла, мікроконтролер із контуром позиціонування та польовий H-міст. На відміну від класичних хобі-сервоприводів із роздільним аналоговим ШІМ-керуванням (PWM 1–2 мс) для кожного вузла, шинні сервоприводи під'єднуються до спільної послідовної цифрової шини послідовним ланцюжком (*daisy chain*), заощаджуючи десятки проводів у рухомих зчленуваннях робототехнічних систем.

*Внутрішня функціональна схема шинного сервопривода. Мікроконтролер приводу самостійно замикає контури струму, швидкості та позиції за даними магнітного енкодера й шунта, обмінюючись із головним контролером системи пакетами телеметрії.*

## Фізичний рівень шини: Half-Duplex UART та RS-485

Шинні сервоприводи використовують два основні стандарти фізичного рівня зв'язку:

1. **Однопровідний Half-Duplex UART (3-контактний роз'єм: VCC, GND, DATA).** Лінія даних підтягнута до 3.3 В або 5 В резистором 4.7–10 кОм. Для організації двонапрямного обміну на мікроконтролері з роздільними лініями TX та RX застосовують буфер із трьома станами (наприклад, 74HC126 чи 74LVC2G241) або переводять апаратний UART-модуль MCU в режим `Single-Wire / Half-Duplex`. Під час передачі лінія перемикається на вихід, а після відправки останнього стоп-біта миттєво переводиться у стан високого імпедансу для очікування відповіді.
2. **Диференціальний RS-485 (4-контактний роз'єм: VCC, GND, Data+, Data-).** Забезпечує надійну завадостійкість за довжини кабелів понад 1 метр і швидкості передачі до 1–4.5 Мбіт/с завдяки диференціальному прийомопередавачу (наприклад, MAX485 або SP3485). Сигнал передається як різниця напруг між двома витими провідниками, що нейтралізує синфазні електромагнітні наведенки від сильних струмів моторів.

```
Головний MCU (TX) ───[ 74HC126 Буфер ]───┬── DATA (Half-Duplex Шина)
Головний MCU (RX) ────────────────────────┤
Головний MCU (DIR)───[ Керування EN ]────┘
                                         │
        ┌────────────────────────────────┴────────────────────────┐
        │                                                         │
   [ Сервопривід ID 1 ]                                  [ Сервопривід ID 2 ]
   (VCC, GND, DATA)                                      (VCC, GND, DATA)
```

## Таблиця керування (Control Table) та внутрішні контури

Уся пам'ять та параметри сервопривода організовані у вигляді адресованої таблиці регістрів (*Control Table*), розділеної на дві фізичні зони: енергонезалежну пам'ять (EEPROM) та оперативну пам'ять поточного стану (RAM). Доступ до регістрів EEPROM заблоковано бітом захисту `Lock`, щоб унеможливити випадкове пошкодження калібрувальних коефіцієнтів під час роботи:

| Адреса | Область | Назва регістра | Розмір | Опис призначення |
|---|---|---|---|---|
| `0x03` | EEPROM | `ID` | 1 байт | Мережева адреса приводу (1–252; 254 = Broadcast) |
| `0x04` | EEPROM | `BaudRate` | 1 байт | Швидкість шини (0: 1 Мбіт/с, 1: 500 кбіт/с, 2: 115200) |
| `0x06` | EEPROM | `Return_Delay` | 1 байт | Затримка перед відповіддю пакетом статусу (мкс) |
| `0x09` | EEPROM | `Max_Angle_Limit`| 2 байти| Програмне обмеження максимального кута (0–4095) |
| `0x0B` | EEPROM | `Temp_Limit` | 1 байт | Температурний поріг аварійного відсікання (°C) |
| `0x1A` | RAM | `PID_P_Gain` | 1 байт | Пропорційний коефіцієнт жорсткості контуру кута |
| `0x1B` | RAM | `PID_D_Gain` | 1 байт | Диференційний коефіцієнт демпфування коливань |
| `0x28` | RAM | `Torque_Enable` | 1 байт | 1 = подати живлення на мотор; 0 = вільний вибіг |
| `0x2A` | RAM | `Goal_Position` | 2 байти| Цільовий кут повороту вала (0–4095, де 4096 = 360°) |
| `0x2E` | RAM | `Goal_Speed` | 2 байти| Максимальна швидкість переміщення до цілі (крок/с) |
| `0x30` | RAM | `Goal_Torque` | 2 байти| Обмеження граничного струму та моменту навантаження |
| `0x38` | RAM | `Present_Position`| 2 байти| Поточний кут вала з 12-бітного магнітного енкодера |
| `0x3A` | RAM | `Present_Speed` | 2 байти| Поточна кутова швидкість обертання |
| `0x3C` | RAM | `Present_Current` | 2 байти| Миттєвий струм фази мотора (момент навантаження) |
| `0x3E` | RAM | `Present_Voltage` | 1 байт | Фактична напруга живлення на клемах приводу (0.1 В) |
| `0x3F` | RAM | `Present_Temp` | 1 байт | Температура силового моста та обмотки (°C) |

Внутрішній мікроконтролер приводу виконує цифровий контур регулювання на частоті 1 кГц за даними 12-бітного магнітного енкодера. Користувач може підлаштовувати коефіцієнти `P` та `D` у регістрах RAM: підвищення `P_Gain` робить привід жорстким, що необхідно для точних маніпуляторів, тоді як зниження `P_Gain` додає податливості (*compliance*), перетворюючи сервопривід на пружний шарнір для крокуючих роботів.

## Формат двійкового пакета (Instruction & Status Packet)

Обмін даними відбувається транзакціями «Запит головного контролера (Instruction Packet) -> Відповідь сервопривода (Status Packet)».

### Пакет команди від MCU (Instruction Packet)
```
[0xFF] [0xFF] [ID] [Length] [Instruction] [Param_1] ... [Param_N] [Checksum]
```
- `0xFF 0xFF` — заголовок синхронізації початку кадру;
- `ID` — адреса цільового приводу (254 / `0xFE` — широкомовний пакет broadcast без індивідуальної відповіді);
- `Length` — кількість байтів, що слідують після поля довжини (включно з Instruction, параметрами та Checksum);
- `Instruction` — код дії: `0x01` (Ping), `0x02` (Read Data), `0x03` (Write Data), `0x04` (Reg Write), `0x05` (Action), `0x83` (Sync Write);
- `Checksum` — контрольна сума:
```
Checksum = ~(ID + Length + Instruction + Param_1 + ... + Param_N) & 0xFF
```

### Групова синхронна команда (Sync Write)
Для одночасного переміщення 6–18 суглобів маніпулятора послідовне опитування кожного приводу окремими пакетами створює неприпустиму затримку в десятки мілісекунд, викликаючи фазовий зсув ланок. Протокол підтримує команду `Sync Write` (`Instruction = 0x83`): один широкомовний пакет містить початкову адресу регістрів, довжину блоку даних на один привід та список блоків «ID + Дані» для кожного сервопривода. Усі приводи приймають пакет одночасно і починають рух синхронно в одну й ту саму мілісекунду.

### Пакет статусу від приводу (Status Packet)
```
[0xFF] [0xFF] [ID] [Length] [Error_Byte] [Data_1] ... [Data_N] [Checksum]
```
Поле `Error_Byte` містить бітові прапорці апаратних аварій:
* `Bit 0 (Input Voltage Error)`: напруга живлення вийшла за безпечні межі;
* `Bit 1 (Angle Limit Error)`: задана позиція виходить за програмні межі руху;
* `Bit 2 (Overheating Error)`: температура моста або мотора перевищила `Temp_Limit`;
* `Bit 3 (Range Error)`: команда намагається записати значення поза допустимим діапазоном;
* `Bit 4 (Checksum Error)`: отримана контрольна сума не зійшлася (завада в лінії);
* `Bit 5 (Overload / Stall Error)`: вал заблоковано зовнішньою силою під максимальним струмом.

## Практичний драйвер обміну на C та C++

Наведений код демонструє формування пакета позиціонування (`Goal Position`) та розрахунок апаратної контрольної суми для відправки через UART.

:::tabs
```c
#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

#define SERVO_HEADER        0xFF
#define INST_WRITE_DATA     0x03
#define REG_GOAL_POSITION   0x2A

typedef struct {
    uint8_t buffer[16];
    size_t length;
} ServoPacket;

ServoPacket build_position_packet(uint8_t id, uint16_t position_raw, uint16_t speed_raw) {
    ServoPacket pkt;
    pkt.buffer[0] = SERVO_HEADER;
    pkt.buffer[1] = SERVO_HEADER;
    pkt.buffer[2] = id;
    pkt.buffer[3] = 7; // Length = Instruction(1) + Reg(1) + Data(4) + Checksum(1)
    pkt.buffer[4] = INST_WRITE_DATA;
    pkt.buffer[5] = REG_GOAL_POSITION;
    pkt.buffer[6] = (uint8_t)(position_raw & 0xFF);
    pkt.buffer[7] = (uint8_t)((position_raw >> 8) & 0xFF);
    pkt.buffer[8] = (uint8_t)(speed_raw & 0xFF);
    pkt.buffer[9] = (uint8_t)((speed_raw >> 8) & 0xFF);

    uint32_t sum = 0;
    for (size_t i = 2; i <= 9; i++) {
        sum += pkt.buffer[i];
    }
    pkt.buffer[10] = (uint8_t)(~sum & 0xFF);
    pkt.length = 11;
    return pkt;
}
```
```cpp
#include <cstdint>
#include <cstddef>
#include <span>
#include <array>
#include <numeric>

class SmartServoPacketBuilder {
public:
    static constexpr uint8_t Header = 0xFF;
    static constexpr uint8_t InstWriteData = 0x03;
    static constexpr uint8_t RegGoalPosition = 0x2A;

    struct Packet {
        std::array<uint8_t, 16> data{};
        size_t size{0};

        [[nodiscard]] std::span<const uint8_t> bytes() const noexcept {
            return std::span<const uint8_t>(data.data(), size);
        }
    };

    [[nodiscard]] static constexpr Packet makePositionCommand(uint8_t id, uint16_t position, uint16_t speed) noexcept {
        Packet pkt{};
        pkt.data[0] = Header;
        pkt.data[1] = Header;
        pkt.data[2] = id;
        pkt.data[3] = 7; // Length: Inst(1) + Reg(1) + Pos(2) + Speed(2) + Checksum(1)
        pkt.data[4] = InstWriteData;
        pkt.data[5] = RegGoalPosition;
        pkt.data[6] = static_cast<uint8_t>(position & 0xFF);
        pkt.data[7] = static_cast<uint8_t>((position >> 8) & 0xFF);
        pkt.data[8] = static_cast<uint8_t>(speed & 0xFF);
        pkt.data[9] = static_cast<uint8_t>((speed >> 8) & 0xFF);

        uint32_t sum = 0;
        for (size_t i = 2; i <= 9; ++i) {
            sum += pkt.data[i];
        }
        pkt.data[10] = static_cast<uint8_t>(~sum & 0xFF);
        pkt.size = 11;
        return pkt;
    }
};
```

## Типові апаратні пастки під час інтеграції

1. **Падіння напруги в довгому ланцюгу живлення.** Якщо в ланцюгу встановлено 12 сервоприводів, під час синхронного старту сумарний пусковий струм сягає 15–25 А. Тонкі дроти живлення спричиняють просідання напруги нижче порога `UVLO` (Under-Voltage Lock-Out) кінцевих сервоприводів, викликаючи циклічне перезавантаження їхніх мікроконтролерів. Рішення: зіркоподібне розведення силових шин живлення товстим дротом (AWG 16–18) із локальними електролітичними конденсаторами 470–1000 мкФ на кожному вузлі.
2. **Колізії напівдуплексної шини (Bus Collisions).** Якщо головний контролер посилає широкомовну команду `Broadcast` із запитом читання даних, усі сервоприводи починають відповідати одночасно, закорочуючи лінію даних. Для читання телеметрії опитування виконують строго послідовно за індивідуальними адресами `ID` або застосовують команду `Sync Read` зі спеціальним часовим розподілом вікон відповіді.
3. **Некоректний час затримки відповіді (Return Delay Time).** За замовчуванням багато приладів мають нульовий або мінімальний час `Return Delay`. Якщо головний мікроконтролер ще не встиг перемкнути свій буфер UART із режиму передачі в режим прийому (через затримку переривання або завершення передачі DMA), перший байт заголовка відповіді `0xFF` буде втрачено. Параметр `Return_Delay` у EEPROM варто налаштовувати на значення не менше 20–50 мкс.
