# 📋 Специфікація інтерфейсу вузла: апаратне підключення, регістрові карти та протокол зв'язку

Ця технічна специфікація фіксує електричну таблицю з'єднань між мікроконтролером і чотирма периферійними мікросхемами (W25Q128, BME280, DS3231, SN65HVD72), базові регістрові карти та бінарний протокол опитування телеметрії через шину RS-485.

## 1. Апаратна таблиця з'єднань виводів (Pin Mapping) та електричні параметри

Всі мікросхеми працюють від єдиної стабілізованої шини напруги `+3.3V` із загальним полігоном `GND`. Використання мікроконтролера з гнучкою матрицею мультиплексування виводів (Alternate Function) дозволяє призначити високошвидкісні периферійні блоки на компактні групи пінів, мінімізуючи довжину друкованих доріжок.

Сигнали шини SPI (SCK, MOSI, MISO) налаштовуються у режимі високої швидкості наростання (High-Speed Slew Rate), тому на стороні передавача встановлюються послідовні демпфуючі резистори 33 Ом для запобігання дзвінкам та електромагнітному випромінюванню на фронтах менше 2 нс. ## 2. Карта команд та регістрів периферійних чипів

### SPI NOR Flash W25Q128JV (Команди керування)

Мікросхема NOR Flash W25Q128JV підтримує роботу в режимах SPI Mode 0 (CPOL=0, CPHA=0) та Mode 3 (CPOL=1, CPHA=1). Кожна транзакція починається встановленням низького рівня на виводі `/CS`. Перший переданий байт містить опкод інструкції. Операції запису та стирання вимагають обов'язкової попередньої відправки команди `0x06` (Write Enable), яка виставляє апаратний біт `WEL` у першому регістрі статусу.

| Код команди (HEX) | Назва операції | Кількість байтів адреси | Опис дії |
| :--- | :--- | :--- | :--- |
| `0x06` | Write Enable (WREN) | 0 | Дозвіл на операції запису/стирання (встановлює біт WEL у Status Register 1) |
| `0x05` | Read Status Register-1 | 0 | Зчитування прапорців `BUSY` (біт 0) та `WEL` (біт 1) |
| `0x03` | Read Data | 3 (A23..A0) | Читання масиву байтів із довільної адреси (до 50 МГц) |
| `0x02` | Page Program | 3 (A23..A0) | Запис сторінки (від 1 до 256 байтів) |
| `0x20` | Sector Erase (4 KB) | 3 (A23..A0) | Стирання сектора 4096 байтів (заповнення `0xFF`) |
| `0x9F` | Read JEDEC ID | 0 | Повертає 3 байти: `0xEF` (Winbond), `0x40` (SPI), `0x18` (128 Мбіт) |
| `0xB9` | Deep Power-Down | 0 | Переведення Flash у режим сну (< 1 мкА) |
| `0xAB` | Release Power-Down | 0 | Пробудження з режиму сну (затримка t_res1 = 3 мкс) |

Перед виконанням операції `0x02` (Page Program) обов'язково перевіряється готовність пам'яті через опитування нульового біта `BUSY` у Status Register 1. Час програмування однієї повної сторінки становить типово `0.8 мс` (максимально 3.0 мс).

### Цифровий датчик BME280 (Регістри вимірювання та конфігурації)

Датчик BME280 вимірює тиск, температуру та вологість за допомогою 20-бітних сигма-дельта перетворювачів. Для виключення паразитного самонагріву кристала (який може спотворити покази відносної вологості на 2–3%) датчик налаштовується на роботу у режимі **Forced Mode**: за командою мікроконтролера виконується один цикл перетворення, після чого сенсор автоматично повертається у режим сну (Sleep Mode) зі споживанням 0.2 мкА.

| Адреса (HEX) | Назва регістру | Бітові поля / Призначення |
| :--- | :--- | :--- |
| `0xD0` | `id` | Заводський ID чипа: фіксоване значення `0x60` |
| `0xE0` | `reset` | Запис `0xB6` виконує повний апаратний Power-On Reset |
| `0xF2` | `ctrl_hum` | Оверсемплінг вологості `osrs_h[2:0]` (001 = x1, 010 = x2, 101 = x16) |
| `0xF3` | `status` | Біт 3: `measuring` (1 = йде конверсія АЦП), Біт 0: `im_update` (оновлення NVM) |
| `0xF4` | `ctrl_meas` | `osrs_t[2:0]` (оверсемплінг T), `osrs_p[2:0]` (оверсемплінг P), `mode[1:0]` (00=Sleep, 01/10=Forced, 11=Normal) |
| `0xF5` | `config` | `t_sb[2:0]` (Standby час), `filter[2:0]` (IIR фільтр: 000=Off, 010=4, 100=16), `spi3w_en` |
| `0xF7..0xF9` | `press_msb..xlsb` | 20-бітний сирий двійковий код тиску |
| `0xFA..0xFC` | `temp_msb..xlsb` | 20-бітний сирий двійковий код температури |
| `0xFD..0xFE` | `hum_msb..lsb` | 16-бітний сирий двійковий код відносної вологості |
| `0x88..0xA1` | `calib00..calib25` | 26 байтів індивідуальних фабричних калібрувальних коефіцієнтів T та P |
| `0xE1..0xE7` | `calib26..calib32` | 7 байтів калібрувальних коефіцієнтів вологості H |

Вичитування даних вимірювання здійснюється за одну I2C-транзакцію типу Burst Read тривалістю 8 байтів починаючи з адреси `0xF7` до `0xFE`. Це гарантує атомарність отриманих відліків температури, тиску та вологості.

### Математична компенсація сирих відліків BME280

Отримані з АЦП 20-бітні числа `adc_T`, `adc_P` та 16-бітне `adc_H` є сирими двійковими кодами. Для отримання інженерних значень у системі SI прошивка застосовує цілочисельний алгоритм із фіксованою комою (Fixed-Point 32-bit Arithmetic), розроблений виробником сенсора (Bosch Sensortec).

Калібрувальні коефіцієнти температури `dig_T1` (uint16), `dig_T2` (int16), `dig_T3` (int16) дозволяють обчислити проміжну тонку змінну температури `t_fine`:

```
var1 = ((((adc_T >> 3) - ((int32_t)dig_T1 << 1))) * ((int32_t)dig_T2)) >> 11;
var2 = (((((adc_T >> 4) - ((int32_t)dig_T1)) * ((adc_T >> 4) - ((int32_t)dig_T1))) >> 12) * ((int32_t)dig_T3)) >> 14;
t_fine = var1 + var2;
temperature_celsius_x100 = (t_fine * 5 + 128) >> 8;
```

Значення `temperature_celsius_x100` повертає температуру з роздільною здатністю 0.01 °C (наприклад, число `2345` відповідає `23.45 °C`). Потім значення `t_fine` підставляється у формули розрахунку барометричного тиску та відносної вологості, забезпечуючи компенсацію температурного дрейфу мембрани чутливого елемента.

### Годинник реального часу DS3231 (Регістрова карта)

Мікросхема DS3231 містить вбудований датчик температури, який кожні 64 секунди вимірює температуру кристала кварцу та автоматично підлаштовує масив навантажувальних ємностей (TCXO Tuning) для збереження частоти 32.768 кГц із точністю ±2 ppm (похибка не більше однієї хвилини на рік).

| Адреса (HEX) | Назва регістру | Формат даних / Функція |
| :--- | :--- | :--- |
| `0x00` | `Seconds` | BCD (00–59) |
| `0x01` | `Minutes` | BCD (00–59) |
| `0x02` | `Hours` | BCD (00–23 при 24-годинному форматі) |
| `0x03` | `Day` | BCD (1–7, день тижня) |
| `0x04` | `Date` | BCD (01–31, число місяця) |
| `0x05` | `Month / Century` | BCD (01–12) + біт століття Century (біт 7) |
| `0x06` | `Year` | BCD (00–99, рік) |
| `0x07..0x0A` | `Alarm 1` | Регістри порівняння секунди, хвилини, години, дати для першого будильника |
| `0x0E` | `Control` | Біт 7: `!EOSC` (0 = генератор увімкнено), Біт 2: `INTCN` (1 = вивід SQW працює як переривання INT), Біт 0: `A1IE` (дозвіл переривання Alarm 1) |
| `0x0F` | `Control / Status` | Біт 0: `A1F` (прапорець спрацьовування Alarm 1, скидається записом 0), Біт 2: `BSY` (робота TCXO) |
| `0x11..0x12` | `Temp MSB / LSB` | Температура кристала RTC з точністю 0.25 °C (10-бітне значення) |

Для переведення виводу `INT/SQW` у режим генерації переривання будильника регістр `0x0E` ініціалізується значенням `0x05` (біти `INTCN = 1` та `A1IE = 1`). При збігу часу вивід підтягується до нуля, генеруючи спадний фронт на піні `PB0` мікроконтролера.

## 3. Протокол зв'язку через RS-485 (Кадр Modbus RTU / Бінарна телеметрія)

Вузол відповідає на запити ведучого контролера мережі (RS-485 Master) за форматом Modbus RTU (напівдуплекс, швидкість 115200 бод, 8 біт даних, без парності, 1 стоп-біт: `115200 8-N-1`).

Часовий інтервал між символами в кадрі не повинен перевищувати `t1.5` (при швидкості 115200 бод це `130 мкс`). Закінчення кадру детектується за наявністю паузи мовчання тривалістю понад `t3.5` (`750 мкс`), після чого апаратний таймер USART генерує подію Idle Line Interrupt.

### Електричні вимоги стандарту TIA/EIA-485-A

Диференційний інтерфейс RS-485 визначає передачу сигналів по витій парі провідників ліній `A` (неінвертуючий) та `B` (інвертуючий). Логічна одиниця (Mark / Idle) відповідає станові, коли напруга на лінії `A` нижча за напругу на лінії `B` на величину понад `200 мВ` (`V_A - V_B ≤ -0.2 В`). Логічний нуль (Space / Active) відповідає станові, коли напруга `A` вища за напругу `B` на величину понад `200 мВ` (`V_A - V_B ≥ +0.2 В`).

У стані спокою, коли всі передавачі на шині вимкнені (High-Z), резистори захисного зміщення (Fail-Safe Biasing: 1 кОм до +3.3V на лінію B та 1 кОм до GND на лінію A) утримують диференційну напругу в діапазоні логічної одиниці, що запобігає генерації помилкових старт-бітів через шум на довгій кабельній трасі.

### Формат кадру опитування поточного зрізу (Master Request)

| Поле | Довжина | Значення | Опис |
| :--- | :--- | :--- | :--- |
| `Address` | 1 байт | `0x01` | Логічна мережева адреса вузла |
| `Function` | 1 байт | `0x03` | Команда читання регістрів (Read Holding Registers) |
| `Start Addr` | 2 байти | `0x0000` | Початкова адреса блоку телеметрії (MSB first) |
| `Reg Count` | 2 байти | `0x000C` | Кількість 16-бітних регістрів (12 слів = 24 байти) |
| `CRC16` | 2 байти | `0x0409` | Контрольна сума CRC-16 Modbus (LSB, потім MSB) |

### Коди виняткових відповідей (Modbus Exception Codes)

Якщо ведучий пристрій надсилає некоректний запит, вузол формує відповідь із встановленим старшим бітом коду функції (`Function Code | 0x80 = 0x83`) та однобайтним кодом помилки:
* `0x01` (Illegal Function): запитано непідтримуваний код операції (відмінний від `0x03` або `0x10`);
* `0x02` (Illegal Data Address): запитана початкова адреса виходить за межі простору регістрів телеметрії;
* `0x03` (Illegal Data Value): кількість регістрів перевищує максимальний розмір буфера (більше 32 слів);
* `0x04` (Slave Device Failure): апаратний збій вичитування сенсора BME280 або помилка зв'язку по шині I2C.
