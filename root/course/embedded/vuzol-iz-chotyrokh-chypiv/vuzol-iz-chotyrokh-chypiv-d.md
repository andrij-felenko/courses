Коли на одній друкованій платі площею менше п'ятнадцяти квадратних сантиметрів одночасно працюють швидкісна цифрова шина з тактовою частотою 50 МГц, чутливий мікроелектромеханічний датчик тиску з 20-бітним АЦП, термокомпенсований годинник реального часу та промисловий диференційний трансивер ліній зв'язку з імпульсними струмами комутації до 70 мА, типовий макетний підхід руйнується за лічені мілісекунди. Без узгодження хвильового імпедансу крутий тактовий фронт SPI з швидкістю наростання понад два вольти на наносекунду через паразитну ємність між доріжками наводить на високоомні лінії I2C імпульсний сплеск амплітудою більше одного вольта. Контролер I2C сприймає цей сплеск як хибний біт підтвердження ACK або стан Start і назавжди зависає у стані апаратного блокування. Одночасно передавач RS-485, вмикаючись на довгу кабельну лінію з хвильовим навантаженням 54 Ом, спричиняє локальне просідання напруги живлення, яке збиває калібрувальні коефіцієнти барометра та призводить до спотворення вимірюваного тиску на десятки гектопаскалів.

Створення автономного або промислового вузла телеметрії вимагає строгого системного узгодження електричних характеристик, геометрії топології шарів плати, часових бюджетів шин та архітектури вбудованого програмного забезпечення.

## 1. Системна архітектура вузла з чотирма гетерогенними мікросхемами

Промисловий вузол збору польових даних має вирішувати чотири базові завдання: точно вимірювати фізичні параметри середовища, прив'язувати кожне вимірювання до абсолютного астрономічного часу, гарантовано зберігати масиви відліків у разі обриву зовнішнього зв'язку та передавати накопичені пакети диспетчеру через стійкий до завад інтерфейс.

![Архітектура системного вузла з чотирма чипами](/root/course/embedded/vuzol-iz-chotyrokh-chypiv/img/node-system-architecture.svg)
*Центральний мікроконтролер координує роботу чотирьох зовнішніх мікросхем: швидкісної NOR Flash по SPI, чутливого барометричного датчика та годинника RTC по спільній шині I2C, а також диференційного драйвера RS-485 через апаратний USART з автоматичним керуванням лінією DE.*

### Декомпозиція компонентної бази вузла

1. **Головний мікроконтролер (MCU):** 32-бітний кристал сімейства STM32G4 / STM32F4 або ESP32-S3 (ядро ARM Cortex-M4 з плаваючою комою FPU, тактова частота 80–170 МГц). Мікроконтролер містить апаратні периферійні блоки SPI Master з підтримкою прямого доступу до пам'яті (DMA), I2C Master з апаратною фільтрацією завад (Analog Glitch Filter), таймери загального призначення, контролер зовнішніх переривань EXTI та USART із апаратним формуванням сигналу дозволу драйвера `DE` (Driver Enable).
2. **Чип 1 (Швидкісна енергонезалежна пам'ять):** NOR Flash `W25Q128JV` (ємність 128 Мбіт / 16 МБ, інтерфейс SPI Mode 0/3, тактова частота читання до 50–104 МГц, сторінковий запис по 256 байтів, секторне стирання блоками по 4096 байтів). Мікросхема слугує локальним чорним ящиком: вона зберігає кільцевий журнал вимірювань за кілька місяців автономної роботи пристрою.
3. **Чип 2 (Прецизійний цифровий датчик навколишнього середовища):** MEMS-сенсор `BME280` (інтерфейс I2C, апаратна адреса `0x76`, 20-бітні сигма-дельта АЦП для одночасного вимірювання температури, атмосферного тиску та відносної вологості повітря). Датчик має вбудований цифровий IIR-фільтр для придушення короткочасних коливань тиску від протягів.
4. **Чип 3 (Термокомпенсований годинник реального часу RTC):** `DS3231` (інтерфейс I2C, фіксована адреса `0x68`, вбудований термокомпенсований кварцовий генератор TCXO на 32.768 кГц із гарантованою точністю ходу не гірше ±2 ppm у діапазоні від -40 °C до +85 °C). Забезпечує неперервний відлік секунд, хвилин, годин та дат із резервним живленням від літієвого дискового елемента CR2032 або іоністора. Вивід `INT/SQW` налаштовується на генерацію апаратного секундного імпульсу для періодичного пробудження мікроконтролера.
5. **Чип 4 (Промисловий трансивер RS-485):** `SN65HVD72` або `MAX485` (напівдуплексний трансивер диференційної лінії зв'язку з живленням 3.3 В). Мікросхема перетворює логічні рівні UART мікроконтролера у диференційну напругу на витій парі ліній A/B. Версія SN65HVD72 має вбудоване обмеження швидкості наростання вихідної напруги (Slew-Rate Limiting) для роботи на швидкостях до 250 kbps, що радикально знижує рівень електромагнітного випромінювання та чутливість до відбиттів у довгих лініях.

### Електричне узгодження та розподіл живлення

Всі п'ять компонентів працюють від єдиної стабілізованої шини живлення `+3.3V`, що усуває потребу у двонаправлених перетворювачах рівнів напруги (Level Shifters). Проте профіль струму споживання компонентів відрізняється на чотири порядки:

```
+───────────────────────+────────────────────────+─────────────────────────+
│ Компонент             │ Струм у режимі сну     │ Струм в активній фазі   │
+───────────────────────+────────────────────────+─────────────────────────+
│ STM32 (Stop 2 mode)   │ 5.2 мкА                │ 14.5 мА (80 МГц)        │
│ W25Q128JV (Flash)     │ 1.0 мкА (Power-down)   │ 18.0 мА (Page Program)  │
│ BME280 (Sensor)       │ 0.2 мкА (Sleep)        │ 0.7 мА (Conversion)     │
│ DS3231 (RTC)          │ 1.5 мкА (Battery mode) │ 0.2 мА (I2C Active)     │
│ SN65HVD72 (RS-485)    │ 0.1 мкА (Shutdown)     │ 45.0 мА (TX @ 54 Ohm)   │
+───────────────────────+────────────────────────+─────────────────────────+
```

Пікове навантаження на стабілізатор 3.3V під час одночасного запису у Flash та передачі пакета через RS-485 сягає `78 мА`. Для запобігання динамічному просіданню напруги лінійний LDO-регулятор (наприклад, TPS7A2533 з ультранизьким власним споживанням 2.5 мкА) доповнюється вихідним керамічним конденсатором ємністю 10 мкФ X7R та індивідуальними розв'язувальними фільтрами для кожної мікросхеми.

Повний перелік електричних з'єднань, призначення пінів та бітових масок зафіксовано у вставці [специфікація апаратних інтерфейсів, регістрових карт та протоколу зв'язку](root:embedded/vuzol-iz-chotyrokh-chypiv/api-node-protocol.md).

## 2. Схемотехніка та трасування друкованої плати (PCB Layout)

Друкована плата вузла виконується за 4-шаровою структурою (Stackup). Спроба розвести таку комбінацію швидкісної та чутливої периферії на 2-шаровій платі неминуче призводить до розриву шляхів зворотного струму та втрати метрологічної точності вимірювань.

```
Шар L1 (Top):    Сигнальні траси SPI, I2C, UART + SMD контактні майданчики
Шар L2 (Inner1): СУЦІЛЬНА ПЛОЩИНА ЗЕМЛІ (Solid Ground Plane)
Шар L3 (Inner2): Площина живлення (+3.3V Power Plane / полігони)
Шар L4 (Bottom): Допоміжні сигнальні траси + суцільний захисний GND полігон
```

![Функціональне зонування друкованої плати](/root/course/embedded/vuzol-iz-chotyrokh-chypiv/img/pcb-layout-zoning.svg)
*Функціональне просторове зонування 4-шарової плати: чутливий кут MEMS-датчика та RTC (Зона A), центральне цифрове ядро МК (Зона B), швидкісна зона SPI Flash (Зона C) та крайова зона захисту польового інтерфейсу RS-485 (Зона D) на суцільній опорній площині землі L2.*

### Чому суцільна земля краща за розріз (Ground Plane Split)

Класична підручникова порада «розрізати землю на аналогову (AGND) і цифрову (DGND) та з'єднати їх в одній точці» у випадку сучасних цифрових датчиків з вбудованими АЦП є шкідливою помилкою. Датчик BME280 та RTC DS3231 є змішаними мікросхемами: їхня цифрова логіка спілкується по I2C, а аналогові перетворювачі розташовані на тому ж кристалі. Якщо зробити розріз у шарі землі L2, сигнальні доріжки I2C (SDA/SCL) неминуче перетнуть цей розріз.

Коли високочастотний струм повернення, що тече опорною площиною безпосередньо під сигнальною доріжкою, натрапляє на щілину в металізації, він не може перестрибнути через повітря. Струм змушений обтікати розріз по периметру, утворюючи велику паразитну петлю струму.

Ця петля створює паразитну індуктивність у колі повернення струму, що генерує різницю потенціалів між частинами плати та перетворює щілину на ефективну випромінюючу антену.

**Правильне інженерне рішення:** Шар L2 виконується **100% суцільною мідною площиною GND без жодних розрізів**. Розділення аналогової та цифрової частин досягається **геометричним просторовим зонуванням (Spatial Partitioning)**:
* Чутливі мікросхеми BME280 та DS3231 розміщуються у відокремленому «тихому» кутку плати (Зона A).
* Швидкісна мікросхема W25Q128 розташовується з протилежного боку мікроконтролера (Зона C).
* Шумні струми повернення шини SPI (50 МГц) течуть площиною L2 строго між МК та Flash і фізично не затікають у зону розташування MEMS-датчика.

### Правила трасування шин SPI та I2C

1. **Демпфування ліній SPI:** Тактовий сигнал `SPI_SCK` (50 МГц) та лінія даних `MOSI` мають довжину фронту близько `1.5 нс`. Хвильовий опір мікросмужкової доріжки шириною 0.2 мм над шаром L2 становить приблизно `55 Ом`. Вихідний опір драйвера виводу STM32 дорівнює `22 Ом`. Для усунення відбиттів на виході МК послідовно встановлюються демпфуючі резистори `R_damping = 33 Ом` (розміром 0402 впритул до виводів мікроконтролера).
2. **Топологія I2C:** Підтягуючі резистори `R_pullup = 2.2 кОм` встановлюються біля мікроконтролера. Сумарна ємність шини разом із ємностями входів трьох мікросхем не перевищує `30 пФ`, що забезпечує час наростання `t_r ≈ 56 нс` (при нормативній межі стандарту Fast Mode до 300 нс).
3. **Розміщення блокувальних конденсаторів:** Керамічні конденсатори ємністю 100 нФ X7R розміщуються на відстані не більше 1.5 мм від виводів живлення кожного чипа. Трасування виконується за правилом: `Контактний майданчик живлення → Вивід конденсатора → Перехідний отвір (Via) на шар L3`. Це гарантує, що високочастотний імпульсний струм спочатку проходить через фільтруючу ємність, перш ніж потрапити у площину живлення.

Детальні математичні виведення часових бюджетів шин, розрахунок ємностей та формули відбиттів наведено у вставці [розрахунок таймінгів шин, ємнісного навантаження та перехресних завад](root:embedded/vuzol-iz-chotyrokh-chypiv/math-bus-timing-budget.md).

## 3. Програмний стек: синхронізація, пріоритети та черга подій

На рівні вбудованого програмного забезпечення вузол повинен обслуговувати чотири принципово різні за часовою поведінкою мікросхеми без взаємних блокувань:

```
DS3231:   Жорстке періодичне переривання 1 Гц (EXTI ISR, час реакції < 10 мкс)
BME280:   Вичитування 8 байтів по I2C (тривалість транзакції 1.2 мс при 400 кГц)
W25Q128:  Запис блоку 256 байтів по SPI (час програмування сторінки t_prog = 0.8 мс)
RS-485:   Асинхронний прийом кадрів опитування Modbus RTU (тайм-аут відповіді < 10 мс)
```

![Часовий графік обробки подій](/root/course/embedded/vuzol-iz-chotyrokh-chypiv/img/firmware-event-loop-timing.svg)
*Часовий розподіл обробки подій у диспетчері прошивки: секундний імпульс RTC ініціює вичитування датчика по I2C та збереження у Flash по SPI, тоді як запити по RS-485 обслуговуються асинхронно через неблокуючий буфер.*

### Детермінована послідовність ініціалізації вузла (Boot Sequence)

Під час подачі живлення напруга на виході LDO-регулятора наростає з певною швидкістю (Rise Time близько 1–2 мс). Кожна мікросхема має власний внутрішній таймер скидання при включенні (Power-On Reset, POR):
* `STM32`: внутрішнє скидання знімається при досягненні напруги 1.71 В;
* `W25Q128`: вимагає затримки `t_PUW = 10 мс` перед дозволом операцій запису;
* `BME280`: вимагає паузи `t_start = 2 мс` для зчитування внутрішніх NVM-калібрувань у тіньові регістри;
* `DS3231`: вимагає стабілізації TCXO протягом `t_osc = 250 мс` для виходу на паспортну точність.

Спроба звернутися до BME280 або Flash-пам'яті відразу після старту процесора призводить до відсутності відповіді (NACK по I2C або сміття на MISO). Послідовність ініціалізації реалізує суворий покроковий протокол:

```
Крок 1: Апаратна затримка стабілізації живлення (15 мс)
   │
Крок 2: Ініціалізація GPIO, системного таймера DWT та демпфуючих виводів
   │
Крок 3: Перевірка працездатності SPI Flash (Команда 0x9F -> Читання JEDEC ID)
   │    Очікується: 0xEF (Winbond), 0x40 (SPI), 0x18 (128 Мбіт)
   │
Крок 4: Ініціалізація I2C та конфігурація RTC DS3231
   │    Запис регістру 0x0E (Control): увімкнення переривання INT/SQW на 1 Гц
   │
Крок 5: Ініціалізація та калібрування BME280
   │    Зчитування 26 байтів коефіцієнтів Trimming (dig_T, dig_P, dig_H)
   │    Конфігурація Forced Mode з оверсемплінгом x1 для мінімізації самонагріву
   │
Крок 6: Налаштування USART1 + RS-485
   │    Переведення трансивера в режим прийому (DE = 0, /RE = 0)
   │    Дозвіл переривання по прийому байта RXNE та виявленню паузи Idle Line
   │
Крок 7: Запуск головного циклу неблокуючого диспетчера подій
```

### Структура кільцевого енергонезалежного логера у Flash

Кожен зріз телеметрії упаковується у бінарну структуру фіксованого розміру `24 байти`:

:::tabs
```c
typedef struct __attribute__((packed)) {
    uint32_t timestamp;     /* 4 байти: секунди Unix Epoch від DS3231 */
    int32_t  temperature;   /* 4 байти: соті частки °C (23.45°C -> 2345) */
    uint32_t pressure;      /* 4 байти: соті частки Паскаля */
    uint32_t humidity;      /* 4 байти: вологість Q22.10 формат */
    uint16_t sequence_id;   /* 2 байти: монотонний лічильник вибірок */
    uint16_t status_flags;  /* 2 байти: бітові прапорці стану сенсорів */
    uint16_t crc16;         /* 2 байти: контрольна сума полінома Modbus */
} telemetry_record_t;
```
```cpp
#pragma pack(push, 1)
struct TelemetryRecord {
    uint32_t timestamp{0};     // 4 байти: секунди Unix Epoch від DS3231
    int32_t  temperature{0};   // 4 байти: соті частки °C (23.45°C -> 2345)
    uint32_t pressure{0};      // 4 байти: соті частки Паскаля
    uint32_t humidity{0};      // 4 байти: вологість у форматі Q22.10
    uint16_t sequenceId{0};    // 2 байти: монотонний лічильник зрізів
    uint16_t statusFlags{0};   // 2 байти: бітові прапорці стану
    uint16_t crc16{0};         // 2 байти: контрольна сума CRC-16 Modbus
};
#pragma pack(pop)
```
:::

Сторінка пам'яті Flash W25Q128 має розмір `256 байтів`. У неї поміщається рівно `10 повних записів` по 24 байти (загалом 240 байтів), а решта 16 байтів використовуються під метадані сторінки (номер ревізії та лічильник стирань). 

Завдяки накопиченню записів у RAM-буфері скидання у Flash відбувається лише один раз на 10 секунд (якщо опитування йде з частотою 1 Гц), що зменшує навантаження на шину SPI у десять разів та гарантує надійність на рівні 100 000 циклів стирання секторів Flash.

Повний сирцевий код прошивки координатора наведено у вставці [реалізація прошивки координатора вузла](root:embedded/vuzol-iz-chotyrokh-chypiv/proj-coordinator-firmware.md).

## 4. Електромагнітна сумісність (EMC) та придушення перехресних завад

Найбільш критичною точкою взаємодії чотирьох мікросхем є перехресний ємнісний та індуктивний зв'язок між швидкісними сигналами SPI та високоомними лініями I2C.

![Придушення перехресних завад](/root/course/embedded/vuzol-iz-chotyrokh-chypiv/img/spi-i2c-crosstalk-mitigation.svg)
*Механізм наведення ємнісної завади при тісному трасуванні паралельних провідників та спосіб її ліквідації за допомогою правила 3W і охоронної доріжки (Guard Trace) з металізованими переходами на опорний шар GND.*

### Фізичний механізм завади між SPI SCK та I2C SDA

Коли тактовий вивід SPI перемикається з `0 В` до `3.3 В` за час `t_rise = 1.5 нс`, швидкість наростання напруги становить:

```
dV / dt = 3.3 В / (1.5 · 10⁻⁹ с)       [відношення амплітуди до тривалості фронту]
        = 2.2 · 10⁹ В/с                 [швидкість зміни напруги тактового сигналу]
```

Якщо паралельно до цієї доріжки на відстані `S = 0.2 мм` прокладено лінію I2C SDA, паразитна взаємна ємність між ними становить приблизно `C_m = 0.45 пФ` на ділянці довжиною 25 мм.

Струм ємнісної наводки, що впорскується у лінію I2C:

```
I_crosstalk = C_m · (dV / dt)           [ємнісний струм зміщення]
            = 0.45 · 10⁻¹² · 2.2 · 10⁹  [підстановка параметрів зв'язку]
            = 0.99 мА                   [амплітуда імпульсного струму завади]
```

Оскільки лінія I2C у стані спокою підтягнута до живлення через резистор `R_pullup = 2.2 кОм`, імпульс струму створює падіння напруги:

```
V_noise = I_crosstalk · R_pullup        [закон Ома для наведеного струму]
        = 0.99 · 10⁻³ · 2200            [підстановка струму та опору підтяжки]
        = 2.18 В                        [наведена напруга імпульсного викиду]
```

Цей викид напруги амплітудою `2.18 В` спотворює сигнал на лінії SDA. Якщо в цей момент лінія перебувала у нульовому стані, МК фіксує перехід у логічну одиницю, сприймаючи це як передчасний біт Stop, що ламає поточний I2C-кадр.

### Комплекс інженерних заходів захисту від завад

1. **Правило 3W на трасах шин:** Відстань `S` між сигнальними лініями SPI та I2C обирається не менше трикратної ширини доріжки (`S ≥ 3 · W = 0.6 мм`). Це знижує взаємну ємність `C_m` більш ніж на 85%.
2. **Охоронна земляна лінія (GND Guard Trace):** Між трасами SPI та I2C прокладається доріжка землі шириною 0.3 мм, прошита перехідними отворами (Vias) на шар L2 з кроком `3 мм`. Лінії електричного поля замикаються на охоронну доріжку, а наведена напруга на I2C падає нижче `40 мВ`.
3. **Захист порту RS-485 від зовнішніх імпульсних перенапруг:** Лінії A та B виходять на зовнішній клемник і піддаються впливу електростатичних розрядів (ESD) та наведених грозових імпульсів. Для захисту входу трансивера SN65HVD72 застосовується трирівневий каскад:
   * Асиметричний TVS-супресор `SM712` (захист ліній RS-485 від розрядів до ±15 кВ повітрям та напруг від -7 В до +12 В відносно локальної землі);
   * Самовідновні полімерні запобіжники PTC (номінал 100 мА) послідовно у кожній сигнальній лінії;
   * Узгоджувальний резистор кінцевої термінації `120 Ом` (0.25 Вт), що підключається паралельно лініям A/B джампером або мікроперемикачем.

### Оцінка надійності та середнього часу безвідмовної роботи (MTBF)

Розрахунок надійності за стандартом `MIL-HDBK-217F` для умов експлуатації *Ground Benign* (температура навколишнього середовища +35 °C) показує інтенсивність відмов компонентного складу:

```
λ_total = λ_mcu + λ_flash + λ_bme + λ_rtc + λ_485 + λ_passives  [сумарна інтенсивність відмов]
        = 0.082 + 0.045 + 0.110 + 0.065 + 0.038 + 0.020        [підстановка за MIL-HDBK-217F]
        = 0.360 відмов / 10⁶ годин                              [сумарний темп відмов]
```

Середній час безвідмовної роботи (MTBF):

```
MTBF = 1 / λ_total                      [визначення напрацювання на відмову]
     = 1 / (0.360 · 10⁻⁶)               [підстановка сумарного темпу]
     = 2 777 777 годин                  [обчислення в годинах]
     ≈ 317 років                        [еквівалент надійності в роках]
```

Основним фактором, що обмежує фізичний ресурс пристрою в польових умовах, є не вихід із ладу напівпровідників, а:
1. **Знос осередків Flash-пам'яті:** При записі 1 сторінки (256 байтів) кожні 10 секунд сектор 4096 байтів перезаписується раз на 160 секунд. Завдяки циклічному просуванню адреси запису по всьому простору 16 МБ (4096 секторів) кожен сектор зазнає стирання лише раз на `7.5 днів`. Ресурс у 100 000 циклів стирання вичерпається через `2000 років`.
2. **Термін служби літієвого елемента CR2032:** Ємність `220 мА·год` при струмі споживання RTC від батареї `1.0 мкА` (при відключеному зовнішньому живленні) забезпечує автономну підтримку ходу годинника протягом:

```
T_bat = 220 мА·год / 0.001 мА           [ділення ємності батареї на струм]
      = 220 000 годин                   [ресурс елемента живлення]
      ≈ 25 років                        [обмеження хімічним саморозрядом 10–12 років]
```

## 6. Підсумковий інженерний висновок

Інтеграція чотирьох різнорідних мікросхем навколо одного мікроконтролера перетворює набір розрізнених компонентів на надійну промислову систему лише за умови дотримання трьох неподільних правил:
1. **Топологічна суцільність землі:** Шар L2 повинен залишатися непорушною площиною GND, а ізоляція чутливих аналогових вимірювань досягається геометричним рознесенням зон, а не фізичним розрізанням металізації.
2. **Електричне демпфування швидкісних фронтів:** Послідовні резистори 33 Ом на лініях SPI SCK та правило 3W запобігають ємнісному проникненню завад у високоомні кола I2C.
3. **Неблокуюча архітектура прошивки:** Розподіл завдань на неблокуючий диспетчер з буферизацією записів у RAM та асинхронним обслуговуванням шини RS-485 гарантує безперервний збір телеметрії за будь-якого навантаження на канал зв'язку.
