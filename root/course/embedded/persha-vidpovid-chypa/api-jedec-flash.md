# 📋 Специфікація JEDEC ID та розшифрування пам'яті Flash

Коли мікроконтролер встановлює зв'язок із мікросхемою енергонезалежної пам'яті SPI NOR або NAND Flash, простого однобайтового регістра ідентифікації на кшталт `WHO_AM_I` виявляється недостатньо. Пам'ять становить складніший напівпровідниковий пристрій, де прошивці необхідно знати не лише факт фізичної присутності кремнію, але й точний обсяг кристала, розмір сторінки програмування, топологію секторів для операцій стирання, а також підтримувані швидкісні протоколи передачі даних (Dual-SPI, Quad-SPI, QPI).

Для забезпечення уніфікації інженерний комітет стандартизації напівпровідникової продукції JEDEC розробив стандарт [JESD216](root:com-devices/spi-bus) та систему кодування виробників JEP106. Цей протокол опитування дозволяє універсальному драйверу мікроконтролера визначити геометрію пам'яті та налаштувати таймінги ще до початку читання чи запису користувацьких даних.

---

## 1. Протокол опитування: Команда Read Identification (0x9F)

Зчитування ідентифікатора JEDEC виконується за допомогою універсальної інструкції з кодом `0x9F`. Ця команда підтримується практично всіма сучасними виробниками послідовної пам'яті Flash (Winbond, Macronix, GigaDevice, Micron, Microchip, Spansion, ISSI).

Транзакція на шині SPI має суворий порядок:
1. Ведучий мікроконтролер активує сигнал вибору кристала, переводячи лінію [Chip Select (CS)](root:com-devices/chip-select) у низький рівень (логічний 0).
2. По лінії MOSI передається один командний байт `0x9F`.
3. Одночасно чип Flash перемикає лінію MISO з високоімпедансного Z-стану в активний режим виходу і на кожному наступному такті сигналу SCK послідовно висуває байти паспорта кристала.
4. Після отримання необхідної кількості байтів (зазвичай від 3 до 6) ведучий піднімає CS у високий рівень, завершуючи сесію обміну.

| Позиція байта | Назва поля | Стандарт | Призначення та фізичний зміст |
|---|---|---|---|
| Байт 1 | `Manufacturer ID` | JEDEC JEP106 | Унікальний код заводу-виробника напівпровідникового кристала |
| Байт 2 | `Memory Type` | Специфікація виробника | Тип архітектури пам'яті (напруга живлення 3.3V або 1.8V, покоління інтерфейсу) |
| Байт 3 | `Capacity ID` | JEDEC JESD216 | Логарифмічний код ємності кристала в байтах (степінь двійки) |
| Байт 4 | `Extended ID` | Опціонально | Додатковий ідентифікатор ревізії кристала або довжини сектора |
| Байт 5 | `Unique ID` | Опціонально | Заводський серійний номер або UID безпеки |

## 2. Таблиця кодів виробників (JEDEC JEP106) та банків продовження

Перший байт відповіді повертає ідентифікатор компанії, що випустила кристал. Якщо виробник реєструвався у пізніших редакціях стандарту, перед його кодом передаються спеціальні байти продовження зі значенням `0x7F` (Continuation Code). Кількість байтів `0x7F` вказує на номер банку реєстрації JEDEC.

| Код у шістнадцятковому форматі | Назва виробника | Популярні сімейства мікросхем | Типові галузі застосування |
|---|---|---|---|
| `0xEF` (Банк 1) | Winbond Electronics | W25Q16, W25Q64, W25Q128, W25Q256 | Вбудовані системи, материнські плати, роутери |
| `0xC2` (Банк 1) | Macronix International (MXIC) | MX25L1606, MX25L6433, MX25U128 | Промислова автоматика, автомобільна електроніка |
| `0xC8` (Банк 1) | GigaDevice Semiconductor | GD25Q16, GD25Q64, GD25Q128 | Масова побутова техніка, контролери польоту |
| `0x20` (Банк 1) | Micron Technology / Numonyx / ST | M25Pxx, N25Q064, MT25QL128 | Серверні платформи, високошвидкісні обчислювачі |
| `0x01` (Банк 1) | Spansion / Cypress / Infineon | S25FL064, S25FL128, S25FS256 | Авіаційні системи, критична інфраструктура |
| `0xBF` (Банк 1) | Microchip Technology / SST | SST25VF016, SST26VF064 | Системи з низьким енергоспоживанням |
| `0x9D` (Банк 1) | ISSI (Integrated Silicon Solution) | IS25LP064, IS25WP128 | Телекомунікаційне мережеве обладнання |
| `0x85` (Банк 1) | Puya Semiconductor | P25Q16, P25Q32, P25Q64 | Бездротові сенсори, енергоефективні вузли |
| `0x68` (Банк 1) | Boya Microelectronics | BY25Q32, BY25Q64 | Бюджетні модулі зв'язку та IoT-пристрої |
| `0x5E` (Банк 1) | Zbit Semiconductor | ZB25VQ64, ZB25VQ128 | Споживча електроніка та периферія |

Якщо замість очікуваного коду зчитується `0xFF`, це свідчить про фізичний обрив лінії MISO або відсутність напруги живлення на виводі VCC. Значення `0x00` вказує на коротке замикання MISO на землю або стан заблокованого апаратного скидання.

## 3. Математика обчислення ємності та розміру секторів

Третій байт (`Capacity ID`) кодує розмір пам'яті за експоненційним правилом: кожне збільшення шістнадцяткового значення на одиницю відповідає подвоєнню фізичного обсягу кристала.

Фізичний обсяг пам'яті у байтах розраховується як піднесення двійки до степеня, заданого значенням цього байта:

```
Обсяг у байтах = 2^(Capacity_ID)
Обсяг у мегабайтах = 2^(Capacity_ID − 20)
Обсяг у мегабітах = 2^(Capacity_ID − 17)
```

| `Capacity ID` | Степінь двійки | Загальний обсяг у байтах | Обсяг у мегабітах | Кількість сторінок (по 256 Б) | Кількість секторів (по 4 КБ) |
|---|---|---|---|---|---|
| `0x10` | 2¹⁶ | 65 536 Б (64 КБ) | 512 Кбіт | 256 | 16 |
| `0x11` | 2¹⁷ | 131 072 Б (128 КБ) | 1 Мбіт | 512 | 32 |
| `0x12` | 2¹⁸ | 262 144 Б (256 КБ) | 2 Мбіт | 1 024 | 64 |
| `0x13` | 2¹⁹ | 524 288 Б (512 КБ) | 4 Мбіт | 2 048 | 128 |
| `0x14` | 2²⁰ | 1 048 576 Б (1 МБ) | 8 Мбіт | 4 096 | 256 |
| `0x15` | 2²¹ | 2 097 152 Б (2 МБ) | 16 Мбіт | 8 192 | 512 |
| `0x16` | 2²² | 4 194 304 Б (4 МБ) | 32 Мбіт | 16 384 | 1 024 |
| `0x17` | 2²³ | 8 388 608 Б (8 МБ) | 64 Мбіт | 32 768 | 2 048 |
| `0x18` | 2²⁴ | 16 777 216 Б (16 МБ) | 128 Мбіт | 65 536 | 4 096 |
| `0x19` | 2²⁵ | 33 554 432 Б (32 МБ) | 256 Мбіт | 131 072 | 8 192 |
| `0x1A` | 2²⁶ | 67 108 864 Б (64 МБ) | 512 Мбіт | 262 144 | 16 384 |

Знаючи загальну ємність, драйвер розбиває адресний простір на стандартні функціональні блоки:
- **Сторінка запису (Page):** базовий квант операції програмування, що завжди становить рівно 256 байтів. Спроба записати більше 256 байтів без перепідключення адреси призводить до перезапису початку поточної сторінки (Page Roll-over).
- **Сектор стирання (Uniform Sector):** мінімальна неподільна область стирання в нуль (стан `0xFF`), яка у більшості сучасних чипів має розмір 4 Кілобайти (4096 байтів). Команда стирання — `0x20`.
- **Блок стирання (Block):** укрупнена область стирання розміром 32 Кілобайти (команда `0x52`) або 64 Кілобайти (команда `0xD8`), що використовується для прискореного очищення великих файлових масивів.

## 4. Специфікація SFDP (JESD216): Автоматичне виявлення геометрії

У складних вбудованих системах, де необхідно підтримувати широкий спектр взаємозамінних чипів пам'яті від різних виробників, використання фіксованих таблиць у коді є негнучким. Для вирішення цієї проблеми розроблено стандарт **SFDP** (англ. *Serial Flash Discoverable Parameters*).

Чип, що підтримує SFDP, містить внутрішню енергонезалежну ROM-структуру, яка зчитується спеціальною командою `0x5A`:

```
MOSI: [0x5A] ──→ [A23] [A16] [A8] ──→ [Dummy Byte (0x00)] ──→ MISO: [Дані заголовка SFDP]
```

Транзакція передає опкод `0x5A`, три байти адреси зміщення всередині таблиці параметрів (для початку читання `0x000000`) і обов'язковий порожній такт очікування (Dummy Byte).

Відповідь починається з контрольної сигнатури довжиною 4 байти:
- Байт 0: `0x53` (символ ASCII `'S'`)
- Байт 1: `0x46` (символ ASCII `'F'`)
- Байт 2: `0x44` (символ ASCII `'D'`)
- Байт 3: `0x50` (символ ASCII `'P'`)

Якщо сигнатура збіглася, наступні байти заголовка описують ревізію стандарту (наприклад, JESD216B) та вказують покажчики на базові таблиці параметрів (Parameter Headers). З них прошивка автоматично витягує:
1. Кількість адресних байтів: 3 байти (для пам'яті обсягом до 16 МБ) або 4 байти (для мікросхем від 32 МБ і більше);
2. Підтримку швидкісного 4-бітного режиму Quad-SPI (команди Fast Read Quad `0xEB` або `0x6B`);
3. Потребу у біті активації Quad Enable (QE bit) у регістрах статусу Status Register-2 (наприклад, біт 1 у Winbond або біт 6 у Macronix);
4. Точні часові затримки на виконання операцій стирання сектора і блоку, що дозволяє оптимізувати тайм-аути в RTOS.

## 5. Крайові випадки та аномалії під час опитування Flash

Під час налагодження мікросхем пам'яті Flash інженери часто стикаються з нетиповою поведінкою команди `0x9F`, яка не є апаратним дефектом, а випливає з поточного стану чипа:

1. **Мікросхема застрягла в режимі QPI (Quad Peripheral Interface):** Якщо попередня прошивка або завантажувач перевели чип у режим QPI (де всі команди та адреси передаються по 4 лініях даних одночасно), чип перестає сприймати класичні 1-бітні команди по лінії MOSI. Спроба надіслати `0x9F` повертає сміття або `0xFF`. Лікування: відправка спеціальної команди виходу з QPI (опкод `0xFF` або `0xF5`) у 4-бітному режимі або повне зняття напруги живлення.
2. **Опитування під час активного циклу стирання або запису:** Якщо надіслати команду `0x9F` одразу після команди стирання блоку, не дочекавшись скидання прапорця зайнятості `WIP` (англ. *Write In Progress*) у регістрі статусу `0x05`, внутрішній контролер пам'яті може проігнорувати опкод або спотворити перший байт.
3. **Обмеження тактової частоти для команди Read ID:** Більшість кристалів Flash здатні читати дані пам'яті на частотах 104–133 МГц (за умови використання Fast Read з dummy-байтами), проте базова команда читання ідентифікатора `0x9F` у багатьох специфікаціях має апаратне обмеження до 33–50 МГц. Запуск bring-up тесту на максимальній частоті SPI часто призводить до зсуву бітів або повернення нулів.

## 6. Програмний модуль валідації та декодування на C та C++

Наведений нижче модуль реалізує повний цикл ідентифікації мікросхеми Flash: перевірку на апаратні дефекти ліній, декодування виробника за стандартом JEP106, математичний розрахунок ємності та визначення геометрії секторів.

```c
#include <stdint.h>
#include <stdbool.h>

#define JEDEC_CMD_READ_ID   0x9F

typedef struct {
    uint8_t  manufacturer_id;
    uint8_t  memory_type;
    uint8_t  capacity_id;
    uint32_t total_size_bytes;
    uint32_t sector_size_bytes;
    uint32_t page_size_bytes;
    uint32_t total_sectors;
    const char* vendor_name;
    bool     is_valid;
} jedec_flash_info_t;

const char* jedec_lookup_vendor(uint8_t mfg_id) {
    switch (mfg_id) {
        case 0xEF: return "Winbond";
        case 0xC2: return "Macronix";
        case 0xC8: return "GigaDevice";
        case 0x20: return "Micron/Numonyx";
        case 0x01: return "Spansion/Infineon";
        case 0xBF: return "Microchip/SST";
        case 0x9D: return "ISSI";
        case 0x85: return "Puya";
        case 0x68: return "Boya";
        case 0x5E: return "Zbit";
        default:   return "Unknown Vendor";
    }
}

jedec_flash_info_t jedec_decode_response(const uint8_t raw_id[3]) {
    jedec_flash_info_t info = {0};
    
    // Перевірка на фізичні дефекти ліній (обрив підтяжки або замикання на землю)
    if ((raw_id[0] == 0xFF && raw_id[1] == 0xFF && raw_id[2] == 0xFF) ||
        (raw_id[0] == 0x00 && raw_id[1] == 0x00 && raw_id[2] == 0x00)) {
        info.is_valid = false;
        info.vendor_name = "Bus Fault (0x00/0xFF)";
        return info;
    }
    
    info.manufacturer_id = raw_id[0];
    info.memory_type     = raw_id[1];
    info.capacity_id     = raw_id[2];
    info.vendor_name     = jedec_lookup_vendor(raw_id[0]);
    
    // Валідація підтримуваного діапазону ємностей (від 64 КБ до 64 МБ)
    if (info.capacity_id >= 0x10 && info.capacity_id <= 0x1A) {
        info.total_size_bytes  = 1UL << info.capacity_id;
        info.sector_size_bytes = 4096; // Стандартний розмір 4 КБ секторів
        info.page_size_bytes   = 256;  // Стандартний розмір сторінки 256 Б
        info.total_sectors     = info.total_size_bytes / info.sector_size_bytes;
        info.is_valid          = true;
    } else {
        info.total_size_bytes = 0;
        info.is_valid         = false;
    }
    
    return info;
}
```

```cpp
#include <cstdint>
#include <string_view>
#include <optional>
#include <span>

struct FlashGeometry {
    uint8_t          manufacturer_id{0};
    uint8_t          memory_type{0};
    uint8_t          capacity_id{0};
    uint32_t         total_size_bytes{0};
    uint32_t         sector_size_bytes{4096};
    uint32_t         page_size_bytes{256};
    uint32_t         total_sectors{0};
    std::string_view vendor_name{"Unknown"};
};

class JedecFlashIdentifier {
public:
    static constexpr uint8_t CmdReadId = 0x9F;

    [[nodiscard]] static constexpr std::string_view resolve_vendor(uint8_t mfg_id) noexcept {
        switch (mfg_id) {
            case 0xEF: return "Winbond";
            case 0xC2: return "Macronix";
            case 0xC8: return "GigaDevice";
            case 0x20: return "Micron/Numonyx";
            case 0x01: return "Spansion/Infineon";
            case 0xBF: return "Microchip/SST";
            case 0x9D: return "ISSI";
            case 0x85: return "Puya";
            case 0x68: return "Boya";
            case 0x5E: return "Zbit";
            default:   return "Unknown Vendor";
        }
    }

    [[nodiscard]] static constexpr std::optional<FlashGeometry> decode(std::span<const uint8_t, 3> raw_id) noexcept {
        const uint8_t mfg  = raw_id[0];
        const uint8_t type = raw_id[1];
        const uint8_t cap  = raw_id[2];

        // Захист від аварійних станів шини
        if ((mfg == 0xFF && type == 0xFF && cap == 0xFF) ||
            (mfg == 0x00 && type == 0x00 && cap == 0x00)) {
            return std::nullopt;
        }

        // Обмеження валідних показників ємності (від 2^16 = 64 КБ до 2^26 = 64 МБ)
        if (cap < 0x10 || cap > 0x1A) {
            return std::nullopt;
        }

        FlashGeometry geom;
        geom.manufacturer_id   = mfg;
        geom.memory_type       = type;
        geom.capacity_id       = cap;
        geom.total_size_bytes  = (1UL << cap);
        geom.sector_size_bytes = 4096;
        geom.page_size_bytes   = 256;
        geom.total_sectors     = geom.total_size_bytes / geom.sector_size_bytes;
        geom.vendor_name       = resolve_vendor(mfg);

        return geom;
    }
};
```
