# 🧮 Розрахунок часового бюджету та розміру черги подій

Автономний пристрій, що працює на базі власного суперциклу або легкої операційної системи реального часу (RTOS), повинен мати математично гарантовані часові межі реакції. Якщо мобільний апарат рухається зі швидкістю `v = 2.0 м/с`, а далекомір ToF фіксує перешкоду на дистанції `d = 0.5 м`, час від моменту фізичного виявлення перешкоди до генерації команд гальмування на мотори не може перевищувати визначеного дедлайну, інакше зіткнення неминуче.

У цій вставці наведено математичне виведення трьох критичних розрахунків для детерміністичної системи прийняття рішень:
1. Загальної утилізації процесора `U` та умови плануваності за моделлю фіксованих квантів часу (Rate Monotonic Analysis).
2. Мінімально допустимої місткості кільцевої черги подій `N_queue`, що гарантує нульову ймовірність втрати подій під час залпових навантажень.
3. Граничного часу реакції `L_total` від спрацювання переривання датчика до фізичної зміни стану силових приводів.

---

## 1. Утилізація процесора та часовий бюджет слотів

Розгляньмо вбудовану систему, яка виконує `n` періодичних неблокуючих завдань у фіксованих часових слотах:
- `τ₁` (Швидкий контур): опитування IMU по шині SPI через DMA, розрахунок фільтра орієнтації та пропорційно-диференціальних регуляторів струму моторів. Період виклику `T₁ = 1.0 мс = 1000 мкс`, найгірший час виконання на процесорі ARM Cortex-M4 при частоті 64 МГц становить `WCET₁ = C₁ = 120 мкс`.
- `τ₂` (Контур одометрії): зчитування квадратурних енкодерів, обчислення переміщення, фільтрація та лінеаризація далекомірів ToF. Період виклику `T₂ = 10.0 мс = 10000 мкс`, найгірший час виконання `C₂ = 450 мкс`.
- `τ₃` (Контур прийняття рішень): спустошення кільцевої черги подій, виконання кроку ієрархічного автомата станів HSM, перевірка guard-умов та розрахунок нових цільових уставок швидкості. Період виклику `T₃ = 50.0 мс = 50000 мкс`, найгірший час виконання `C₃ = 800 мкс`.
- `τ₄` (Контур сервісу та телеметрії): пакування та відправка пакетів стану в радіоканал UART, запис діагностичних маркерів у Flash-пам'ять, скидання апаратного сторожового таймера. Період виклику `T₄ = 200.0 мс = 200000 мкс`, найгірший час виконання `C₄ = 600 мкс`.

Сумарна завантаженість процесора `U` (утилізація) обчислюється як сума відношень найгіршого часу виконання кожного завдання до його базового періоду:

```
U = (C₁ / T₁) + (C₂ / T₂) + (C₃ / T₃) + (C₄ / T₄)
= (120 / 1000) + (450 / 10000) + (800 / 50000) + (600 / 200000)   [підстановка значень Cᵢ та Tᵢ]
= 0.1200 + 0.0450 + 0.0160 + 0.0030                                 [обчислення часток утилізації]
= 0.1840                                                            [сумарна утилізація: 18.4%]
```

Для статичного пріоритетного планування (Rate Monotonic Scheduling, де задачі з коротшим періодом мають вищий пріоритет) класична теорема Лю й Лейланда (Liu & Layland) стверджує, що множина з `n` незалежних періодичних задач гарантовано планується без пропуску дедлайнів, якщо сумарна утилізація не перевищує теоретичної межі:

```
U_bound = n · (2^(1/n) − 1)
```

Для системи з чотирьох періодичних рівнів (`n = 4`):

```
U_bound = 4 · (2^(1/4) − 1)
= 4 · (1.189207 − 1)             [обчислення кореня 4-го степеня з 2]
= 4 · 0.189207
= 0.7568                        [теоретична межа стійкості: 75.68%]
```

Оскільки фактична утилізація процесора становить `U = 0.1840` (18.4%), що значно менше за поріг стійкості `0.7568` (75.7%), система має величезний запас стабільності понад 57% процесорного часу. Усі періодичні задачі гарантовано завершуються задовго до настання наступного кванта.

## 2. Розрахунок мінімальної місткості черги подій

Кільцева черга подій `EventQueue` накопичує асинхронні повідомлення, які генеруються апаратними перериваннями під час роботи фонових завдань суперциклу або між кроками виклику автомата станів.

Головна небезпека для детерміністичної прошивки — переповнення буфера (buffer overflow) під час залпового надходження подій, коли кілька датчиків одночасно надсилають сигнали тривоги.

Нехай:
- `T_drain = T₃ = 50 мс` — максимальний час між двома послідовними циклами повного вичитування черги в контурі прийняття рішень.
- `R_periodic` — інтенсивність надходження регулярних періодичних подій від апаратних таймерів та датчиків.
- `N_burst_async` — максимальна кількість асинхронних подій, які можуть бути згенеровані зовнішніми перериваннями одночасно.

Джерела подій у системі:
1. Системний таймерний тік (`1000 Гц = 1 подія/мс`). Якщо періодичні таймерні події коалесціюються (зливаються в один лічильник тіків в ISR, генеруючи не більше однієї події `EV_TICK` на такт вичитування), навантаження на чергу становить `1` подію на інтервал `T_drain`.
2. Періодичні виміри двох далекомірів ToF (`2 сенсори × 50 Гц = 100 подій/с = 0.1 подія/мс`). За інтервал 50 мс вони генерують: `2 · 50 · 0.050 = 5` подій.
3. Аварійний сплеск зовнішніх переривань (одночасне спрацювання бампера зіткнення, датчика струму мотора, компаратора низької напруги батареї, сигналу втрати радіолінка та команди зупинки): максимум `N_burst_async = 5` подій.

Сумарна кількість подій `N_gen`, яка може накопичитися в буфері за час між циклами обробки, становить:

```
N_gen = 1 (TICK) + ⌈(2 · 50 · 0.050)⌉ (ToF) + 5 (аварійні)
= 1 + ⌈5.0⌉ + 5
= 11 подій                     [максимальний піковий залп за 50 мс]
```

З урахуванням коефіцієнта інженерного запасу надійності `k_margin = 1.4` (для компенсації дрижання такту таймера):

```
N_required = ⌈N_gen · k_margin⌉
= ⌈11 · 1.4⌉
= ⌈15.4⌉
= 16 подій                     [округлення до найближчого степеня двійки]
```

Вибір місткості `N_queue = 16` елементів дозволяє замінити операцію взяття залишку від ділення (`% Capacity`) на швидку побітову маску (`index & 0x0F`), що зменшує час перебування всередині критичної секції з 25 тактів процесора до 1 такту. Ймовірність переповнення буфера при цьому дорівнює нулю (`P_drop = 0`).

## 3. Граничний час реакції та профілювання DWT

Повний час реакції `L_total` від моменту фізичного спрацювання апаратного сенсора перешкоди до моменту подачі нульового ШІМ на силі мостових ключів двигунів складається з чотирьох послідовних затримок:

```
L_total = t_sensor_irq + t_queue_wait + t_hsm_step + t_actuator_delay
```

Де:
1. `t_sensor_irq`: час від спрацювання компаратора далекоміра до успішного додавання події в чергу `EventQueue` через функцію `event_queue_post()` (`t_sensor_irq ≤ 15 мкс`).
2. `t_queue_wait`: найгірший час очікування події в черзі до моменту її вичитування контуром `τ₃` (`t_queue_wait ≤ T₃ = 50000 мкс = 50 мс`).
3. `t_hsm_step`: час виконання логіки переходів автомата станів, виклику обробників `EV_EXIT` та `EV_ENTRY` (`C₃ ≤ 800 мкс`).
4. `t_actuator_delay`: апаратна затримка зміни шпаруватості таймера ШІМ та розряду ємності затворів силових польових транзисторів (`t_actuator_delay ≤ 1000 мкс = 1 мс`).

Підставимо числові значення для найгіршого випадку:

```
L_total_max = 15 мкс + 50000 мкс + 800 мкс + 1000 мкс
= 51815 мкс
≈ 51.8 мс                     [найгірший час повної системної реакції]
```

### Фізична дистанція гальмування
Якщо апарат рухається на максимальній швидкості `v_max = 2.0 м/с`, за час `L_total_max = 51.8 мс` він проїде дистанцію затримки реакції:

```
d_reaction = v_max · L_total_max
= 2.0 м/с · 0.0518 с
= 0.1036 м                    [дистанція затримки: 10.4 см]
```

Якщо гальмівний шлях механіки при повному блокуванні коліс становить `d_brake = 0.25 м`, мінімальна безпечна дистанція виявлення перешкоди `d_safe` обчислюється як:

```
d_safe = d_reaction + d_brake + d_margin
= 0.104 м + 0.250 м + 0.100 м
= 0.454 м                     [поріг спрацювання сенсора: 45.4 см]
```

### Апаратна відсічка через Break Input для критичних аварій
Для критичних загроз (наприклад, спрацювання контактного мікроперемикача бампера або детектора короткого замикання), де затримка 50 мс є неприпустимою, використовується комбінований підхід:
1. **Апаратна відсічка:** Сигнал бампера підключається до спеціального входу аварійного гальмування таймера ШІМ (`TIM_BREAK` на STM32). Внутрішня апаратна логіка таймера примусово скидає всі вихідні канали ШІМ у неактивний стан за час менше 200 наносекунд на рівні транзисторних ключів, повністю зупиняючи подачу струму:

```
L_emergency_direct = t_break_input_filter + t_timer_latch
= 0.15 мкс + 0.05 мкс
= 0.20 мкс                    [апаратна відсічка приводу через Break Pin]
```

2. **Програмне узгодження станів:** Одночасно з апаратною відсічкою генерується переривання `EXTI`, яке розміщує подію `EV_CRITICAL_FAULT` у черзі `EventQueue`. Протягом найближчих 50 мс автомат станів спокійно й детерміністично очищує чергу завдань, викликає деструктори цілей і переводить систему в аварійний термінальний режим `FAILSAFE`.

Такий дворівневий підхід поєднує миттєвий фізичний захист (наносекунди) зі збереженням логічної цілісності та узгодженості станів автомата (мілісекунди).
