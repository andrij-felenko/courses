# 📋 Стандартний контракт та схема виробничого BOM

Специфікація матеріалів (Bill of Materials — BOM) є машинним контрактом між системами комп'ютерного проектування друкованих плат (EDA), корпоративними системами управління життєвим циклом виробу (PLM), складськими реєстрами (ERP) та автоматизованими складальними лініями контрактного виробника (EMS / SMT). 

Будь-яка неточність у структурі цього файлу — зайвий пробіл у позиційному позначенні, нерозпізнаний прапорець монтажу або відсутність префікса валюти чи роздільника — зупиняє роботу автоматичного імпортера на фабриці. Щоб усунути неоднозначність між людиною-інженером, відділом закупівель і лінією монтажу, формат передачі BOM мусить відповідати суворій схемі полів, типів даних та інваріантів валідації.

У практиці електронного виробництва стандартним форматом обміну є таблиці `CSV` (з роздільником-комою або крапкою з комою) або ієрархічні документи `JSON` та `IPC-2581`. Ця специфікація описує повний контракт інженерного та виробничого BOM: назви стовпців, типи значень, допустимі прапорці статусу монтажу, правила кодування списку схвалених замін (AVL) та обробку механічних і технологічних компонентів.

## Обов'язкові та рекомендовані поля специфікації

Кожен рядок виробничого BOM описує унікальну номенклатурну позицію або групу позицій з ідентичними електричними й механічними параметрами.

| Назва стовпця (Header) | Тип даних | Обов'язковість | Приклад значення | Призначення та правила |
|---|---|---|---|---|
| `Designator` | `String` (список) | Обов'язкове | `R1, R2, R5` | Позиційні позначення на схемі та PCB. Розділювач — кома з пробілом. Діапазони `R1-R5` неприпустимі у виробничому файлі. |
| `Quantity` | `Integer` | Обов'язкове | `3` | Кількість компонентів на один примірник плати. Мусить точно дорівнювати кількості елементів у `Designator`. |
| `MPN` | `String` | Обов'язкове | `RC0603FR-0710KL` | Повний артикул виробника (*Manufacturer Part Number*) з усіма суфіксами корпусу, точності, температури й пакування. |
| `Manufacturer` | `String` | Обов'язкове | `Yageo` | Офіційна назва бренду виробника. Не допускаються скорочення, які створюють колізії (наприклад, `TI` замість `Texas Instruments`). |
| `Package` | `String` | Обов'язкове | `0603` | Типорозмір або корпус за стандартом IPC-7351. Для SMD вказується імперський код або комбінований (`0603 / 1608 Metric`). |
| `Footprint` | `String` | Обов'язкове | `R_0603_1608Metric` | Точна назва посадкового місця в бібліотеці EDA (KiCad, Altium, Eagle) для автоматичного зіставлення з Gerber та CPL. |
| `Value` | `String` | Обов'язкове | `10k` | Номінальне значення (опір, ємність, індуктивність, марка чіпа). Слугує інженерним описом для швидкої верифікації. |
| `Tolerance` | `String` | Рекомендоване | `1%` | Допустиме відхилення номіналу. Для пасивних компонентів обов'язкове при заміні на аналоги. |
| `Voltage_Rating` | `String` | Рекомендоване | `50V` | Гранична робоча напруга компонента. Критично для конденсаторів MLCC та захисних діодів. |
| `Power_Rating` | `String` | Рекомендоване | `0.1W` | Номінальна розсіювана потужність резисторів або струм котушок індуктивності. |
| `Description` | `String` | Рекомендоване | `RES SMD 10K 1% 1/10W 0603` | Людський опис англійською мовою. Використовується закупівлями як страховка від одруківки в MPN. |
| `Populate_Status` | `Enum` | Обов'язкове | `Populate` | Статус монтажу: `Populate` (монтувати) або `DNP` / `DNI` (не монтувати). |
| `Packaging_Type` | `Enum` | Рекомендоване | `Tape & Reel` | Тип фабричної тари: `Tape & Reel`, `Cut Tape`, `Tube`, `Tray`, `Bulk`. |
| `AVL_1_MPN` | `String` | Опціональне | `CRCW060310K0FKEA` | Артикул першої схваленої заміни (First Alternative MPN). |
| `AVL_1_Mfg` | `String` | Опціональне | `Vishay` | Виробник першої схваленої заміни. |
| `Internal_Part_No` | `String` | Опціональне | `IPN-RES-0603-10K` | Внутрішній каталожний номер підприємства (ERP / 1C / SAP IPN). |

## Семантика окремих полів та правила валідації

### Позиційні позначення (Designator)

Поле позиційного позначення зв'язує фізичний рядок списку деталей із конкретними контактними майданчиками на друкованій платі.

Основні правила заповнення:
1. **Атомарність запису:** Кожен елемент списку є окремим ідентифікатором, що складається з літерного префікса класу (згідно з ASME Y14.44) та цілого позитивного числа: `R1`, `C12`, `U3`, `Q4`.
2. **Розділювачі:** Стандартним розділювачем є кома з обов'язковим наступним пробілом: `C1, C2, C5, C6`. Неприпустимо використовувати слеші (`C1/C2`), крапку з комою або дефіси для скорочення (`C1-C4`). Скорочені записи ламають автоматичні скрипти генерації звітів на фабриці, оскільки CAM-система інтерпретує `C1-C4` як два десігнатори (`C1` та `-C4`), гублячи компоненти `C2` та `C3`.
3. **Регістр символів:** Усі позначення записуються строго у верхньому регістрі (ASCII Upper-case). Записи `r1` та `R1` у різних САПР можуть викликати помилку колізії імен.

### Повний номер деталі (Full MPN)

Артикул деталі є головним ключем для систем закупівлі.

Вимоги до MPN:
- **Заборона скорочень:** Номер повинен включати всі літери суфікса, що визначають тип упаковки, діапазон робочих температур, точність та ревізію кристала. Запис `TPS62130` є неповним і неприпустимим; коректний запис — `TPS62130RGTR`.
- **Екранування спецсимволів:** Якщо артикул містить дефіси, крапки або слеші (наприклад, `STM32F405RGT6TR` чи `RC0603FR-0710KL`), вони зберігаються дослівно. При експорті в CSV комірка обов'язково береться в лапки, якщо всередині є кома.
- **Відсутність внутрішніх кодів постачальника:** Номери дистриб'юторів (DigiKey Part Number `497-17482-2-ND` або Mouser SKU) не повинні підміняти оригінальний MPN виробника. Для них створюється окремий стовпець `Distributor_SKU`.

### Корпус і посадкове місце (Package vs Footprint)

Специфікація розрізняє два поняття, які часто плутають:
- `Package` — це фізичний корпус реальної деталі, яку виготовляє завод напівпровідників (наприклад, `LQFP-64`, `SOT-23-5`, `0603 Imperial`, `WSON-8`). Цю інформацію використовує відділ закупівель для перевірки форми деталі в каталозі.
- `Footprint` — це назва посадкового місця в бібліотеці САПР інженера (наприклад, `Package_QFP:LQFP-64_10x10mm_P0.5mm` або `Resistor_SMD:R_0603_1608Metric`). Цю назву використовує інженер CAM-відділу фабрики, щоб зіставити деталь із графічним шаром міді та паяльної маски в герберах.

## Стандартизація статусів монтажу (DNP / DNI)

Стовпець `Populate_Status` керує формуванням машинного завдання для автомата Pick & Place. Допустимі лише стандартизовані значення з фіксованого переліку:

```
Populate_Status ∈ {
    "Populate",     // Змонтувати деталь на плату (значення за замовчуванням)
    "DNP",          // Do Not Populate — посадкове місце лишається порожнім
    "DNI",          // Do Not Install — синонім DNP (використовується в Altium)
    "NF",           // No Fit — синонім DNP (британська/європейська нотація)
    "DNS"           // Do Not Solder — не паяти (для THT роз'ємів ручного монтажу)
}
```

Будь-які інші рядки (наприклад, `Not Mounted`, `Skip`, `Empty`, `-`) вважаються синтаксичною помилкою валідатора, оскільки автоматичні парсери фабрики можуть інтерпретувати невідомий рядок як назву деталі й спробувати замовити її.

Для рядків зі статусом `DNP` стовпці `MPN` та `Manufacturer` можуть містити вихідні параметри проектного компонента, але поле `Quantity` розраховується окремо: загальна кількість монтованих деталей на плату не повинна включати позиції DNP.

## Формат списку схвалених замін (AVL / AML)

Список схвалених замін (*Approved Vendor List*) запобігає простою виробництва, коли основний артикул відсутній на складах постачальників.

Специфікація підтримує дві форми запису замін:

1. **Багатостовпчикова структура (Wide CSV):** розширення рядка додатковими парами стовпців `AVL_1_Mfg`, `AVL_1_MPN`, `AVL_2_Mfg`, `AVL_2_MPN`. Цей формат є найбільш прозорим для реляційних баз даних і систем ERP.
2. **Вкладений список через розділювач (Delimited List):** один стовпець `AVL_Alternates`, де записи розділені крапкою з комою:
   `Yageo:RC0603FR-0710KL; Vishay:CRCW060310K0FKEA; Panasonic:ERJ-3EKF1002V`

Правила формування AVL:
- Кожна альтернативна позиція повинна гарантувати сумісність за посадковим місцем (Pin-to-Pin і Footprint).
- Електричні обмеження (гранична напруга, розсіювана потужність, температурний діапазон) альтернативи повинні бути не гіршими за основний компонент.
- Якщо заміна вимагає зміни номіналів обв'язки (наприклад, інший дільник напруги зворотного зв'язку для LDO), така деталь не може бути внесена як пряма альтернатива — вона вимагає випуску окремого варіанту складання.

## Облік технологічних та механічних деталей (Non-BOM Items)

У повному виробничому mBOM окрім електронних компонентів зі схеми враховуються технологічні матеріали, що не мають графічного символу на електричній схемі:
- **Монтажні отвори та кріплення:** гвинти `M3x6`, латунні стійки `M3 10mm`, шайби гровера. Їм призначаються десігнатори серії `MH1`, `MH2` (*Mounting Hole*) або `MP1` (*Mechanical Part*).
- **Радіатори та термоінтерфейси:** тепловідвідний радіатор для корпусу TO-220, силіконова термопрокладка або термопаста. Десігнатори: `HS1`, `HS2` (*Heat Sink*).
- **Захисні та маркувальні елементи:** наклейки з серійним номером, планки світловоду, захисні ковпачки роз'ємів USB.

Усі механічні позиції отримують власний рядок у mBOM із зазначенням артикулу виробника та кількості на виріб, але у файлі координат CPL вони відсутні або помічені як ручний монтаж (*Manual Assembly*).

## JSON-схема інженерного BOM (BOM Schema Definition)

Нижче наведено формальну специфікацію об'єкта BOM у форматі JSON Schema (Draft 7), що застосовується для автоматичної валідації в конвеєрах неперервної інтеграції (CI/CD):

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "EngineeringBOM",
  "type": "object",
  "required": ["metadata", "components"],
  "properties": {
    "metadata": {
      "type": "object",
      "required": ["project_name", "board_revision", "bom_revision", "generated_date"],
      "properties": {
        "project_name": { "type": "string" },
        "board_revision": { "type": "string", "pattern": "^Rev\\s+[A-Z0-9]+(\\.[0-9]+)?$" },
        "bom_revision": { "type": "string", "pattern": "^Rev\\s+[A-Z0-9]+(\\.[0-9]+)?$" },
        "git_commit": { "type": "string" },
        "generated_date": { "type": "string", "format": "date-time" }
      }
    },
    "components": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["designators", "quantity", "mpn", "manufacturer", "package", "populate"],
        "properties": {
          "designators": {
            "type": "array",
            "items": { "type": "string", "pattern": "^[A-Z]{1,3}[0-9]+$" },
            "minItems": 1
          },
          "quantity": { "type": "integer", "minimum": 1 },
          "mpn": { "type": "string", "minLength": 2 },
          "manufacturer": { "type": "string", "minLength": 2 },
          "package": { "type": "string" },
          "footprint": { "type": "string" },
          "value": { "type": "string" },
          "tolerance": { "type": "string" },
          "voltage_rating": { "type": "string" },
          "populate": { "type": "boolean" },
          "dnp_reason": { "type": "string" },
          "packaging": {
            "type": "string",
            "enum": ["Tape & Reel", "Cut Tape", "Tube", "Tray", "Bulk"]
          },
          "avl": {
            "type": "array",
            "items": {
              "type": "object",
              "required": ["manufacturer", "mpn"],
              "properties": {
                "manufacturer": { "type": "string" },
                "mpn": { "type": "string" },
                "notes": { "type": "string" }
              }
            }
          }
        }
      }
    }
  }
}
```

## Інваріанти цілісності специфікації

Під час автоматизованого контролю файлу специфікації перевіряються чотири ключові інваріанти:

1. **Інваріант кількості:** Для кожного рядка довжина масиву `designators` мусить строго дорівнювати цілочисельному значенню `quantity`. Якщо в списку зазначено три позначення (`R1, R2, R3`), а в колонці кількості стоїть `2`, система повинна зупинити обробку з критичною помилкою.
2. **Інваріант унікальності:** Жоден `Designator` не може зустрічатися двічі в межах одного файлу BOM (навіть якщо один із них має статус `DNP`). Наявність одного десігнатора в кількох рядках свідчить про помилку в базі даних схеми або дублювання аркушів ієрархії.
3. **Інваріант повноти монтованих деталей:** Якщо `populate == true`, поля `mpn`, `manufacturer` та `package` не можуть бути порожніми рядками або значеннями `TBD`, `N/A`, `Unknown`. Будь-яка монтована позиція зобов'язана мати повний артикул закупівлі.
4. **Інваріант синхронізації з CPL:** Множина всіх позиційних позначень у BOM зі статусом `populate == true` мусить бути строго рівною множині позиційних позначень у файлі координат Pick & Place (CPL / Centroid). Відсутність хоча б однієї деталі в CPL призводить до порожнього майданчика, а наявність зайвої — до спроби автомата встановити деталь у неіснуюче місце.
