# Підписи типових відмов у логу: осциляції, «унітаз», десинх, кліпінг

<preknowlist>
- [Дискретний ПІД-регулятор](root:com-signal/discrete-pid) — як P, I та D формують сумарний керівний вплив; чутливість D-терма до шуму та насичення інтегральної складової.
- [Фільтр Калмана / EKF](root:com-signal/kalman-ekf) — злиття вимірювань гіроскопа, акселерометра, магнітометра та GPS; поняття прогнозу, виміру, інновацій та воріт фільтрації.
- [Мікшер моторів](root:sys-dron/motor-mixer) — перетворення моментів трьох осей і газу в команди індивідуальних приводів; розподіл авторитету керування.
- [Формати бортових логів: ULog і DataFlash](root:sys-dron/flight-log-formats) — структура бінарного потоку, частоти запису каналів та формати повідомлень.
- [Цифровий протокол DShot](root:com-devices/dshot-protocol) — цифрова передача команд на регулятори швидкості, механізм зворотної телеметрії eRPM та робота ключів інвертора.
- [Шум і дрейф IMU](root:hw-sensing/imu-noise-bias-drift) — природа вібраційного шуму, зміщення нуля та межі динамічного діапазону MEMS-давачів.
</preknowlist>

Апарат злітає в режимі стабілізації горизонту, але щойно пілот вмикає утримання позиції (англ. *Position Hold*), дрон замість нерухомого зависання починає описувати широкі концентричні кола, щосекунди збільшуючи радіус, доки на швидкості 15 м/с не врізається в землю. В іншому вильоті на виході з різкого розвороту один мотор на частку секунди верещить, апарат миттєво крутить неконтрольований переворот навколо променя й падає догори дном. Зовні обидві катастрофи виглядають містикою: гвинти були затягнуті, центр мас вивірений, а передполітні перевірки в наземній станції світилися зеленим. Проте всередині флеш-пам'яті польотного контролера (в журналі Betaflight Blackbox, ArduPilot DataFlash чи PX4 ULog) кожна фізична несправність лишає суворий, математично детермінований слід — характерний автограф відмови контуру зворотного зв'язку.

Цей текст розбирає внутрішню механіку головних аварійних сигнатур: чому геометричний розсинхрон між компасом і GPS неминуче породжує позитивний зворотний зв'язок розбіжної спіралі, як зрив комутації в силовику відрізняється в логу від відламаної лопаті, яким чином вібраційний кліпінг акселерометра зміщує уявну гравітацію і чому насичення мікшера повністю паралізує авторитет стабілізації по курсу.

## Анатомія спостереження: синхронний розтин контуру керування

Будь-який польотний стек (Betaflight, INAV, ArduPilot, PX4) є замкненою системою автоматичного регулювання. Щомиті процесор розв'язує ланцюг взаємопов'язаних рівнянь, перетворюючи намір пілота на фізичне обертання пропелерів. Спроба розслідувати аварію за одним-єдиним графіком — найпоширеніша помилка: побачивши шалені коливання гіроскопа, інженер починає послаблювати коефіцієнти PID, не помічаючи, що першопричиною був провал напруги на регуляторі або механічний резонанс рами.

Щоб розкрити причинно-наслідковий ланцюг, графіки в переглядачі логів (Betaflight Blackbox Explorer, PlotJuggler або MAVExplorer) завжди розкладають на п'ять синхронізованих шарів спостереження:

1. **Цільове завдання (Setpoint / Command):** що саме наказав пілот або навігаційний автомат через радіоканал чи польотну місію (кутова швидкість `setpoint`, кут нахилу `DesRoll`/`DesPitch`, вектор швидкості `target_vel`).
2. **Первинний відгук давачів (Sensor Feedback):** що відчула рама за показами інерційного блока IMU (`gyroADC`, `accADC`, `VIBE`), магнітометра (`MagX/Y/Z`) та супутникового приймача (`GPS.Vel`, `GPS.Pos`).
3. **Реакція регулятора (PID Terms):** яка саме складова контуру зреагувала на похибку стеження — пропорційна `axisP`, інтегральна `axisI`, диференційна `axisD` чи пряме випередження `axisF` (Feedforward).
4. **Вихід мікшера (Actuator Demand):** яке математичне завдання на тягу сформовано для кожного мотора (`motor[0..3]`, `RCOU.C1..C4`) після врахування лімітів насичення та пріоритетів осей.
5. **Фізична відповідь приводу (ESC Telemetry / Dynamics):** чи виконав мотор команду насправді — скільки електричних обертів за хвилину видав ротор (`eRPM`), який струм спожив силовик (`esc_current`) і чи не просіла загальна напруга живлення (`vbat`).

```
Зіставлення ключових сигналів у журналах польотних стеків:

Параметр спостереження       Betaflight Blackbox          ArduPilot DataFlash          PX4 ULog
───────────────────────────────────────────────────────────────────────────────────────────────────
Задана кутова швидкість      setpoint[roll,pitch,yaw]     RATE.RDes, PDes, YDes        vehicle_rates_setpoint
Фактична кутова швидкість    gyroADC[roll,pitch,yaw]      RATE.R, P, Y / IMU.GyrX..Z   vehicle_angular_velocity
Складові PID-контуру         axisP, axisI, axisD, axisF   PIDR.P, I, D, FF             rate_ctrl_status.p/i/d
Запити на мотори             motor[0..3]                  RCOU.C1..C4 / MOT.Mot1..4    actuator_outputs
Телеметрія обертів ESC       erpm[0..3] (DShot)           ESC.RPM / ESC.eRPM           esc_status.rpm
Прискорення IMU              accADC[x,y,z]                IMU.AccX, AccY, AccZ         sensor_combined.accelerometer
Стан вібрацій і кліпінгу     debug[0..3] (vibe)           VIBE.Clip0, Clip1, Clip2     vehicle_imu_status.clipping
Оцінка невпевненості EKF     — (немає EKF)                NKF4.SM, SV, SP / XKF4.SM    estimator_innovations
```

Коли всі п'ять шарів розміщено на спільній часовій шкалі, пошук аварійного патерна перетворюється на пошук точки первинної розбіжності: де саме порушився зв'язок між причиною і наслідком.

## Патерн «Унітаз» (Toilet-Bowling): розсинхрон навігаційного контуру

Патерн «унітаз» (англ. *toilet-bowling* — через візуальну схожість траєкторії на рух води у вирві) виникає виключно в навігаційних режимах автоматичного утримання позиції (PosHold, Loiter, Return-To-Launch, GPS Hold). У ручному режимі (Acro / Angle) той самий апарат може літати бездоганно, проте щойно вмикається замкнений контур навігації, дрон починає кружляти по розбіжній спіралі.

```
Траєкторія руху дрона в просторі при виникненні розбіжності компаса:

       Позиція East (м) →
        -15     -10      -5       0       5      10      15
   15 ┌──────────────────────────────────────────────────────┐
      │                        .---.                         │
   10 │                    .-'       '-.                     │
      │                  .'             '.                   │
    5 │                .'   .-------.     '.                 │
      │               /   .'  .---.  '.     \                │
    0 │  North (м)   |   /   /  *  \   \     |  * — точка    │
      │      ↑       |   |   | (0) |   |     |    утримання  │
   -5 │               \   \   '---'   /     /     (ціль)     │
      │                '.  '---------'    .'                 │
  -10 │                  '.             .'                   │
      │                    '-.       .-'                     │
  -15 │                       '-----'   ← радіус росте       │
      └──────────────────────────────────────────────────────┘
```

### Фізико-математичний механізм розбіжності

Навігаційний контролер утримує позицію в географічній системі координат Землі NED (англ. *North-East-Down* — Північ-Схід-Вниз). Коли супутниковий приймач фіксує відхилення від точки цілі на південь на відстань `Δy`, алгоритм формує вектор бажаної швидкості повернення, спрямований строго на північ: `V_des = [V_north, 0]`.

Щоб створити прискорення на північ, дрон мусить нахилити вектор тяги пропелерів вперед уздовж північного напрямку. Для цього польотний контролер перераховує вектор прискорення із земної системи координат NED у власну систему координат апарата через поточний кут курсу (англ. *yaw / heading* `ψ`), який вимірюється магнітометром (компасом):

```
Матриця проекції бажаного прискорення в кути нахилу:

[ a_forward ]   [  cos(ψ)   sin(ψ) ]   [ a_North ]
[           ] = [                  ] · [         ]
[ a_right   ]   [ -sin(ψ)   cos(ψ) ]   [ a_East  ]
```

Якщо показ магнітометра містить кутову помилку `θ_err` (через неправильне калібрування, невнесене магнітне схилення або наведення від силових кабелів), обчислений кут курсу відрізняється від справжнього: `ψ_meas = ψ_true + θ_err`.

Внаслідок цього замість створення сили гальмування строго на північ, вектор прискорення дрона повертається на кут `θ_err`. Це прискорення розкладається на дві перпендикулярні складові:

```
a_radial     = a_cmd · cos(θ_err)   [корисна сила повернення до центру]
a_tangential = a_cmd · sin(θ_err)   [паразитна сила бічного розгону]
```

![Векторна геометрія розсинхрону компаса, спіральна траєкторія утримання точки та зсув фаз Roll/Pitch на 90 градусів](/root/course/embedded/pidpysy-typovykh-vidmov-u-lohu/img/toilet-bowling-spiral.svg)
*Механізм розгону по спіралі: помилка орієнтації компаса створює тангенціальне прискорення, що збільшує лінійну швидкість. На графіках кутів крен і тангаж перетворюються на синусоїди, зсунуті за фазою рівно на 90°.*

Поки `θ_err < 90°`, радіальна складова все ще намагається тягнути дрон до центру, проте тангенціальна складова безперервно розганяє апарат по дотичній до кола. Зі зростанням лінійної швидкості `v` виникає відцентрова сила:

```
        m · v²
F_cf = ────────
          R
```

Щоб скомпенсувати віддалення від точки зависання, позиційний регулятор вимагає все більшого нахилу `a_cmd`. Але що більший нахил `a_cmd`, то сильнішим стає паразитна бічна сила `a_tangential = a_cmd · sin(θ_err)`. У контурі виникає класичний позитивний зворотний зв'язок: радіус орбіти `R(t)` та швидкість руху `v(t)` починають експоненціально зростати з кожним новим витком.

### Діагностичний відбиток у журналі

У логах ArduPilot DataFlash та PX4 ULog патерн «унітаз» розпізнається за сукупністю таких ознак:

1. **Площинний графік позиції `POS.RelOrigin` (North vs East):** безперервна розбіжна спіраль навколо цільової точки.
2. **Фазовий зсув сигналів нахилу `Roll` та `Pitch`:** на часовому графіку кути коливаються із синусоїдальною формою на частоті обертання по колу (зазвичай 0.2–0.5 Гц). Зсув фази між кривими крену й тангажу становить строго `90°` (`π/2`), що є математичною ознакою кругового руху на площині.
3. **Стрибок інновацій компаса в EKF (`NKF4.SM` або `XKF4.SM`):** коли швидкість руху дрона за GPS перевищує 3–5 м/с, фільтр Калмана EKF порівнює курс за вектором супутникової швидкості (англ. *Course Over Ground*) із курсом за магнітометром. Виникає конфлікт спостережень: квадрат тестового відношення нев'язки компаса стрімко перетинає поріг `SM > 1.0`, і в лог записується подія `EKF compass variance` або аварійне перемикання смуги оцінювача (англ. *EKF lane switch*).

> 🔧 **Як усунути.** Якщо виявлено наростаючу спіраль, першочергово перевіряють фізичну орієнтацію плати компаса (параметр `AHRS_ORIENTATION` або `COMPASS_ORIENT`). Помилка на `45°` чи `90°` дає миттєвий «унітаз». Далі виконують польове калібрування заліза та компенсацію магнітних наведень струму моторів (Compass-Motor Compensation / CompassMot).

## Десинхронізація мотора (Motor Desync): раптовий зрив комутації

Десинхронізація безколекторного мотора (англ. *motor desync*) — це катастрофічна відмова в роботі електронного регулятора швидкості (ESC), за якої інвертор втрачає інформацію про точне кутове положення магнітів ротора й перемикає силові ключі в протифазі до обертання. Наслідком є миттєва втрата тяги одного променя і неконтрольований переворот апарата навколо осі за час від 50 до 150 мілісекунд (так званий *death roll*).

```
Осцилограма напруги на вільній фазі мотора під час нормальної комутації та десинхрону:

Нормальна комутація (BEMF Zero-Crossing):
 Напруга 
    ↑        .---.                   .---.
 +V ┼───────/     \─────────────────/     \────────
    │      /       \   /           /       \   /
    │     /         \ /           /         \ /
  0 ┼────/───────────X───────────/───────────X───── ← точка переходу через 0
    │   / \         / \         / \         / \       фіксується компаратором
 -V ┼──/   \       /   \───────/   \       /   \───
    └─┴─────'-----'─────┴─────┴─────'-----'─────┴──→ Час
                       |← t_demag →| (індуктивний викид спав вчасно)

Десинхронізація (Demag failure):
 Напруга 
    ↑        .---.                   /───────────── ← силове насичення фази
 +V ┼───────/     \─────────────────/                 (ключ відкрився передчасно)
    │      /       \   /\/\/\/\    /
  0 ┼────/───────────X/────────\──/──────────────── ← хибний перехід / шум викиду
    │   / \         /           \/
 -V ┼──/   \       /             \─────────────────
    └─┴─────'-----'───────────────┴────────────────→ Час
                       |← тривалий demag перекрив вікно BEMF → ЗРИВ!
```

### Фізичний механізм збою BEMF та розмагнічування (Demag)

У безсенсорних BLDC-моторах регулятор визначає момент перемикання трьох фаз за переходом через нуль сигналу електрорушійної сили самоіндукції (англ. *Back-EMF Zero-Crossing*) на вимкненій фазі. 

Коли фаза вимикається, накопичена в її індуктивності `L` енергія магнітного поля розряджається через паразитні діоди польових транзисторів (англ. *demagnetization phase*). Час розрядки струму розмагнічування визначається співвідношенням:

```
           L · I_phase
t_demag = ─────────────
              V_bat
```

Якщо пілот різко збільшує газ (англ. *throttle punch*), струм фази `I_phase` зростає від 5 А до 40–80 А за кілька мілісекунд. Індуктивний викид затягується в часі. Якщо `t_demag` стає довшим за кутовий інтервал до наступної комутації, зворотна ЕРС ще не встигає з'явитися у вікні вимірювання, а компаратор процесора ESC помилково сприймає хвіст індуктивного розряду за нульовий перехід ротора.

Регулятор вмикає наступну пару транзисторів занадто рано. Струм подається у фазу, яка перебуває під зустрічним магнітним полем ротора. Виникає не розгінний, а потужний гальмівний електромагнітний момент. Ротор різко зупиняється або починає вібрувати на місці, а зворотна ЕРС повністю зникає. Регулятор переходить у режим безпорадного перезапуску, не створюючи жодної підіймальної сили.

![Хронологія сигнатур десинхронізації мотора: розбіжність гіроскопа, аварійний сплеск D-терма, запит газу 100% та падіння eRPM](/root/course/embedded/pidpysy-typovykh-vidmov-u-lohu/img/motor-desync-signature.svg)
*Чотири синхронні маркери десинхрону: аварійне зростання кутової швидкості, вибивання D-терма в максимальний упор, спроба мікшера дати 100% на мотор і падіння телеметрії eRPM до нуля.*

### Підпис десинхрону в логу Betaflight / DataFlash

У журналі аварійний десинхрон мотора має унікальний набір із 4 строго послідовних маркерів:

1. **Раптовий некерований зрив кутової швидкості (`gyroADC` / `RATE.R`):** графік реальної кутової швидкості лавиноподібно розходиться із заданою (`setpoint`), досягаючи значень 500–1500 °/с за 50–80 мс.
2. **Аварійний сплеск D-терма (`axisD`):** диференційний член миттєво підскакує до граничного насичення (`D_max`), намагаючись завадити виниклому кутовому прискоренню. Одразу за ним у максимальний ліміт упираються пропорційна (`axisP`) та інтегральна (`axisI`) складові.
3. **Запит мікшера на збійний мотор упирається в 100% (`motor[x] = 2000` / 100% DShot):** польотний контролер відчайдушно намагається вирівняти апарат, наказуючи аварійному мотору розвинути максимум тяги. Одночасно протилежні мотори переводяться мікшером на мінімальний газ (0–5%).
4. **Падіння швидкості обертання до нуля за телеметрією DShot (`erpm[x] = 0`):** якщо ввімкнено двоспрямований DShot (англ. *Bidirectional DShot*), частота електричних обертів збійного мотора падає в нуль або хаотично скаче в діапазоні 0–500 об/хв, попри те, що на мотор подається 100% сигналу.

### Як відрізнити десинхрон від механічного руйнування гвинта

Часто пілоти плутають десинхронізацію із зірваним чи зламаним у польоті пропелером. Поведінка контурів `gyroADC` та `axisD` в обох випадках однакова (дрон падає в неконтрольований переворот), але фізика приводів протилежна:

* **При десинхронізації (ESC Desync):** ротор механічно загальмований зустрічним магнітним полем, телеметрія `eRPM` падає майже в нуль, а струм споживання різко падає або набуває форми шуму.
* **При відриві лопаті (Broken Propeller):** мотор повністю втрачає аеродинамічний опір. Ротор миттєво розкручується до аномально високої швидкості холостого ходу — `eRPM` підскакує в 1.5–2 рази вище свого звичайного максимуму. Одночасно через катастрофічний дисбаланс маси на графіку сирого гіроскопа виникає колосальна вібрація на частоті 1x RPM, якої ніколи немає при тихому десинхроні.

## Кліпінг давачів (Sensor Clipping): нелінійне зміщення горизонту

Кліпінг (англ. *clipping* — зрізання верхівок) виникає, коли амплітуда вимірюваної фізичної величини перевищує максимальну межу повної шкали вимірювання (англ. *Full Scale Range*, FSR) аналого-цифрового перетворювача чутливого кристала MEMS.

Для сучасних гіроскопів типова межа становить `±2000 °/s`, для триосьових акселерометрів — `±16g` (де `g ≈ 9.81 м/с²`).

```
Вплив симетричного та несиметричного кліпінгу на інтеграл сигналу:

Чистий сигнал без кліпінгу (середнє = 0):
  +16g ┬──────────────────────────────────────────
       │     .---.             .---.
       │    /     \           /     \
    0g ┼───/───────\─────────/───────\────────────  Середнє DC = 0g
       │  /         \       /         \             (немає хибного зміщення)
       │ /           \     /           \
  -16g ┴/─────────────'---'─────────────'─────────

Кліпінг зі зміщенням гравітацією 1g (помилка випрямлення VRE):
  +16g ┬─────═════─────────────═════────────────── ← ЗРІЗАНО НА МЕЖІ +16g
       │    /     \           /     \
   +1g ┼───/───────\─────────/───────\────────────
       │  /         \       /         \             Середнє DC = -2.4g !
    0g ┼─/───────────\─────/───────────\──────────  (виникло хибне прискорення)
       │/             \   /             \
  -16g ┴───────────────'-'───────────────'──────── ← внизу запас ще є
```

### Фізичний механізм випрямлення вібрації (VRE)

Ударна вібрація від пошкоджених підшипників, розбалансованих гвинтів чи резонансу тонких карбонових променів на частотах 150–600 Гц може досягати пікових прискорень `30–50g`. Оскільки мікромеханічний кремнієвий підвіс акселерометра впирається в механічні демпфери або вихід АЦП упирається в числове значення `±16384` LSB, синусоїдальна хвиля вібрації перетворюється на трапецію зі зрізаною верхівкою.

Якби вібрація була строго симетричною навколо нуля, зрізання обох напівхвиль не змінило б середнього значення сигналу. Проте акселерометр завжди перебуває під впливом постійного прискорення сили тяжіння (`1g` по осі Z) або центробіжного прискорення від маневру (`2–5g` у площині XY).

Через цей постійний зсув верхня додатна напівхвиля вібрації досягає порогу `+16g` набагато раніше і зрізається сильніше, ніж нижня від'ємна напівхвиля встигає досягти порогу `-16g`. Виникає так звана **помилка випрямлення вібрації** (англ. *Vibration Rectification Error*, VRE):

```
                       T
a_DC = a_rectified = ─── · ∫ a_clipped(t) dt ≠ 0
                       T   0
```

Високочастотний змінний шум через нелінійне зрізання перетворюється на постійний сигнал неіснуючого прискорення (англ. *DC offset*), який жоден цифровий фільтр низьких частот (LPF) чи режекторний фільтр (Notch) відфільтрувати вже не здатний, оскільки його частота дорівнює 0 Гц.

![Несиметричне зрізання сигналу вібрації акселерометра, виникнення DC-зміщення та катастрофічний завал оцінки горизонту EKF](/root/course/embedded/pidpysy-typovykh-vidmov-u-lohu/img/sensor-clipping-rectification.svg)
*Кліпінг сенсора: нелінійне зрізання піків вібрації формує хибне постійне зміщення (DC offset). Фільтр орієнтації приймає його за відхилення вектора гравітації, що призводить до завалу горизонту на десятки градусів.*

### Наслідки для фільтра Калмана (EKF) та поведінки апарата

1. **Завал оцінки горизонту:** алгоритм орієнтації EKF шукає вектор сили тяжіння як довгострокове середнє значення акселерометра. Отримавши хибне зміщення `a_DC` величиною `0.3–0.8g`, фільтр вважає, що дрон нахилився на кут `α = arctan(a_DC / 1g) ≈ 20°–45°`.
2. **Некерована втеча вбік (Runaway drift):** контролер стабілізації горизонту намагається повернути хибний кут до нуля. Він нахиляє фізичну раму дрона у протилежний бік, внаслідок чого дрон починає стрімко летіти вбік із постійним прискоренням, ігноруючи команди пілота на вирівнювання.
3. **Діагностика в логах DataFlash (`VIBE`):** ArduPilot безперервно рахує кількість вибірок, які вперлися в максимальне значення АЦП на частоті 1 кГц. У лозі це фіксується лічильниками `VIBE.Clip0` (перший IMU), `VIBE.Clip1` (другий IMU), `VIBE.Clip2` (третій IMU):
   * У нормальному польоті: `ΔClip = 0` за весь політ (допустимо поодинокі сплески менше 5 при жорстких посадках).
   * Небезпечний рівень: приріст `ΔClip > 100` за хвилину польоту гарантує завал горизонту та відмову навігації.

## Насичення мікшера (Mixer Saturation): дефіцит авторитету стабілізації

Насичення мікшера виникає в моменти, коли запит від PID-регуляторів за сумою всіх осей (газ + крен + тангаж + рискання) виходить за межі фізично можливого діапазону керування приводами `0%..100%` (від `DSHOT_MIN` до `DSHOT_MAX`).

```
Розподіл потужності моторів квадрокоптера при високому газі та маневрі крену:

       │    M1         M4               │                            │
  100% ┼───████───────████── 100%   100% ┼───████───────████──   100% ┼───████───────████──
       │   ████       ████              │   ████       ████      (80%)│   ████       ████
   80% ┼───████───────████──            │   ████       ████       60% ┼───████───────████──
       │   ████  M2   ████              │   ████  M2   ████           │   ████  M2   ████
   60% ┼───████ ████  ████              │   ████ ████  ████           │   ████ ████  ████
       │   ████ ████  ████              │   ████ ████  ████           │   ████ ████  ████
```

### Математичний конфлікт мікшера

Мікшер класичного X-квадрокоптера перераховує бажані моменти сил у вихідні сигнали чотирьох моторів за лінійною системою рівнянь:

```
M1 = Throttle − Roll_PID + Pitch_PID + Yaw_PID
M2 = Throttle − Roll_PID − Pitch_PID − Yaw_PID
M3 = Throttle + Roll_PID + Pitch_PID − Yaw_PID
M4 = Throttle + Roll_PID − Pitch_PID + Yaw_PID
```

Нехай апарат летить на високому газі `Throttle = 90%`. Пілот виконує різкий рух стіка крену, що вимагає диференційного коригування `Roll_PID = +20%`. Одночасно контур утримання курсу вимагає `Yaw_PID = +5%`.

Підставивши ці значення для моторів M3 та M4, отримуємо запит:
```
M4 = 90% + 20% − 5% + 5% = 110%
```

Мотор фізично не може обертатися зі швидкістю 110%. Виникає конфлікт: як саме алгоритм має обмежити вихід?

1. **Жорстке зрізання (Hard Clipping):** значення `M4` просто обрізається до 100%. Але якщо `M4` обмежено на рівні 100%, а протилежний мотор `M2` зменшив газ до 70%, фактична різниця тяги між правим і лівим бортами складе лише 30% замість розрахованих 40%. Апарат втрачає розрахунковий крутний момент і стає в'ялим, «ватним».
2. **Втрата авторитету по осі рискання (Yaw Authority Loss):** оскільки реактивний момент від розгону/гальмування гвинта на порядок слабший за аеродинамічний момент від різниці підіймальних сил крену й тангажу, мікшер традиційно віддає найнижчий пріоритет осі Yaw. При насиченні моторів складова `Yaw_PID` відкидається першою — дрон повністю припиняє тримати курс під час різких ривків газу.

![Розподіл виходів мікшера при насиченні: втрата моменту при жорсткому зрізанні проти збереження авторитету в AirMode](/root/course/embedded/pidpysy-typovykh-vidmov-u-lohu/img/mixer-saturation-priority.svg)
*При насиченні мікшера вихід за межі 100% призводить до зрізання моментів стабілізації. Алгоритм AirMode динамічно зміщує рівень середнього газу вниз або вгору, зберігаючи повну амплітуду відносної тяги.*

### Динамічне масштабування (AirMode) та I-term Windup

Для розв'язання проблеми насичення сучасні стеки використовують алгоритми динамічного масштабування мікшера (в Betaflight це зветься **AirMode**, в ArduPilot — динамічним пріоритетом мотора `MOT_SPIN_MAX`):

Замість обрізання верхівок мікшер пропорційно знижує (або підвищує при нульовому газі) базовий рівень `Throttle`, вивільняючи динамічний діапазон для повної амплітуди кутових моментів:
```
Throttle_scaled = 100% − max(Roll, Pitch, Yaw) = 100% − 20% = 80%
M4 = 80% + 20% = 100%
M2 = 80% − 20% = 60%
Різниця тяги M4 − M2 = 40% (повний момент стабілізації збережено!)
```

### Підпис насичення в логу

1. **Суцільне плато 100% (або 0%) на сигналах `motor[x]`:** графік мотора лягає в горизонтальну полицю на тривалий час (понад 50–200 мс).
2. **Розбіжність на осі зі зниженим пріоритетом (`Yaw`):** поки мотор лежить у полиці 100%, графік `gyroADC[Yaw]` не досягає заданого `setpoint[Yaw]`.
3. **Інтегральне насичення (Integrator Windup):** інтегральна складова `axisI` бачить постійну помилку стеження й продовжує розганятися до свого максимуму. Коли маневр завершується, накопичений I-терм не може миттєво скинутися, що викликає сильний зворотний перекид (англ. *overshoot*) або серію затухаючих розгойдувань.

## Порівняльний атлас осциляцій: D-дзвін, перерегулювання P та фазова затримка

Коливання (осциляції) — найчастіша причина перегріву моторів та руйнування рами. Головна складність полягає в тому, що на відео з камери будь-які коливання виглядають як звичайне тремтіння, але в логу вони мають принципово різну частоту, амплітуду та форму сигналу.

```
                                    вихід axisP на 90°               жорстке перерегулювання
```

### 1. Високочастотний D-дзвін (D-term Oscillation)
Диференційний член обчислює швидкість зміни похибки `D = K_d · de/dt`. Оскільки операція взяття похідної множить амплітуду вхідного сигналу на його кругову частоту `ω`, будь-який високочастотний шум мотора (наприклад, 200 Гц) підсилюється D-контуром у сотні разів. 
* **У логу:** графік `axisD` перетворюється на суцільну «гребінку» з амплітудою, що перевищує вихід `axisP`. Мотори при цьому стають гарячими навіть після 30 секунд спокійного зависання, оскільки високочастотний змінний струм гріє обмотки, не створюючи корисної підіймальної сили.

### 2. P-осциляції (Proportional Overshoot)
Виникають, коли пропорційний коефіцієнт `K_p` занадто високий для даного співвідношення тяги до маси. Регулятор штовхає дрон до цілі занадто сильно, апарат за інерцією перелітає задану точку, регулятор штовхає його назад — виникають гармонійні коливання.
* **У логу:** ідеальна синусоїда на графіку `gyroADC` із частотою 15–30 Гц, амплітуда якої зростає під час різких рухів стіком і швидко згасає при стабілізації.

### 3. Фазовий зрив через перефільтрацію (Phase Lag Instability)
Коли інженер намагається побороти шумний D-терм, додаючи все більше цифрових фільтрів (Lowpass PT1, Biquad, кілька Notch), кожен фільтр додає затримку за часом `τ` (фазовий зсув `Δφ = ω · τ`).
* Якщо сумарна фазова затримка контуру на частоті коливань досягає 180°, від'ємний зворотний зв'язок регулятора автоматично перетворюється на **позитивний зворотний зв'язок**. Контур починає розгойдувати сам себе навіть за помірних коефіцієнтів PID.

*Повний алгоритм розслідування: перехід від очевидного симптому аварії до першоджерела в апаратній частині, прошивці чи коефіцієнтах регулятора.*

### Покроковий протокол діагностики

1. **Крок 1. Локалізація часового вікна інциденту:** знайти точку зриву за подіями `Event` (Disarm, Crash Detect, Failsafe) або за точкою, де `gyroADC` різко відхиляється від нуля без команди `rcCommand`. Відступити назад на 500 мс — саме там лежить справжня причина.
2. **Крок 2. Перевірка первинного наміру:** чи давав пілот або навігаційний стек екстремальну команду? Якщо `setpoint` гладкий, а `gyroADC` б'є в упор — проблема всередині платформи (привід, сенсор або мікшер).
3. **Крок 3. Інспекція сенсорного шару:** перевірити лічильники `VIBE.Clip` та амплітуду `accADC`. Якщо виявлено кліпінг (полиці `±16g`) — розслідування закінчено: причина у вібраційному завалі EKF через VRE.
4. **Крок 4. Аналіз силової відповіді (ESC & Motors):** подивитися на виходи `motor[0..3]` та телеметрію `eRPM`:
   * Якщо один мотор ліг у 100%, а його `eRPM` впав до нуля — **десинхрон ESC**.
   * Якщо один мотор ліг у 100%, а його `eRPM` перевищив норму у 1.5 раза — **механічний відрив гвинта**.
   * Якщо всі мотори вперлися в 100%, а напруга впала нижче 3.2 В/банку — **глибокий brown-out батареї**.
5. **Крок 5. Аналіз поведінки навігації:** якщо аварія сталася в утриманні позиції, накласти траєкторію `North-East` та перевірити зсув фаз `Roll/Pitch`. Зсув рівно 90° і зростання інновацій `NKF4.SM > 1.0` підтверджують **патерн «унітаз»**.
6. **Крок 6. Аналіз частотних спектрів (FFT):** якщо мотори перегріті або апарат тремтить, побудувати спектрограму сирого гіроскопа. Пік, що рухається разом із газом, вимагає налаштування RPM-Notch фільтра; статичний пік на фіксованій частоті — посилення механічної жорсткості рами або зниження D-gain.

## Програмний детектор аварійних сигнатур

Нижче наведено модуль аналізатора польотних журналів, який сканує масиви видобутих даних за ковзним вікном і видає автоматичний вердикт щодо наявності десинхронізації, кліпінгу, «унітазу» чи насичення мікшера.

```c
#include <math.h>
#include <stdbool.h>
#include <stdint.h>

#define WINDOW_SIZE 64

typedef enum {
    FAULT_NONE = 0,
    FAULT_MOTOR_DESYNC,
    FAULT_SENSOR_CLIPPING,
    FAULT_TOILET_BOWL,
    FAULT_MIXER_SATURATION
} FaultType;

typedef struct {
    double time_s;
    double gyro_roll;
    double setpoint_roll;
    double acc_z;
    double motor_cmd[4];    // 0.0 .. 1.0
    double motor_erpm[4];   // оберти/хв
    double roll_deg;
    double pitch_deg;
    int    clip_count;
} LogSample;

// Аналіз відрізка польоту на наявність характерних сигнатур відмов
static FaultType detect_flight_fault(const LogSample *samples, int n) {
    if (n < WINDOW_SIZE) return FAULT_NONE;

    int desync_votes = 0;
    int clip_votes = 0;
    int sat_votes = 0;

    for (int i = 0; i < n; i++) {
        // 1. Детекція кліпінгу: переповнення лічильника або вихід на межу +-15.8g
        if (samples[i].clip_count > 0 || fabs(samples[i].acc_z) > 15.8 * 9.81) {
            clip_votes++;
        }

        // 2. Детекція десинхрону: команда 100% при падінні eRPM до 0 і великій помилці гіроскопа
        for (int m = 0; m < 4; m++) {
            if (samples[i].motor_cmd[m] > 0.98 && samples[i].motor_erpm[m] < 100.0) {
                double tracking_err = fabs(samples[i].gyro_roll - samples[i].setpoint_roll);
                if (tracking_err > 300.0) { // кутова швидкість розбіглася > 300 deg/s
                    desync_votes++;
                }
            }
        }

        // 3. Детекція тривалого насичення мікшера (плато 100%)
        int max_motors = 0;
        for (int m = 0; m < 4; m++) {
            if (samples[i].motor_cmd[m] > 0.98) max_motors++;
        }
        if (max_motors >= 2) sat_votes++;
    }

    if (desync_votes >= 3) return FAULT_MOTOR_DESYNC;
    if (clip_votes >= 5)   return FAULT_SENSOR_CLIPPING;

    // 4. Детекція «унітазу»: взаємна кореляція Roll та Pitch зі зсувом 90 градусів
    double sum_roll_sq = 0.0, sum_pitch_sq = 0.0;
    for (int i = 0; i < n; i++) {
        sum_roll_sq  += samples[i].roll_deg * samples[i].roll_deg;
        sum_pitch_sq += samples[i].pitch_deg * samples[i].pitch_deg;
    }
    double rms_roll  = sqrt(sum_roll_sq / n);
    double rms_pitch = sqrt(sum_pitch_sq / n);

    // Якщо обидві осі коливаються з великою амплітудою (> 10 deg) у навігаційному режимі
    if (rms_roll > 10.0 && rms_pitch > 10.0) {
        int phase_shifted_matches = 0;
        int quarter_period = 16; // зсув на 90 градусів при вікні 64 семпли
        for (int i = 0; i < n - quarter_period; i++) {
            // Перевірка ортогональності знаків: Roll(t) та Pitch(t + T/4) мають однаковий напрям
            if ((samples[i].roll_deg * samples[i + quarter_period].pitch_deg) > 0.0) {
                phase_shifted_matches++;
            }
        }
        if (phase_shifted_matches > (n - quarter_period) * 0.75) {
            return FAULT_TOILET_BOWL;
        }
    }

    if (sat_votes > n / 2) return FAULT_MIXER_SATURATION;

    return FAULT_NONE;
}
```

```cpp
#include <cmath>
#include <cstdint>
#include <numbers>
#include <optional>
#include <span>
#include <string_view>
#include <vector>

enum class FlightFault {
    None,
    MotorDesync,
    SensorClipping,
    ToiletBowl,
    MixerSaturation
};

struct FlightSample {
    double time_s{};
    double gyro_roll{};
    double setpoint_roll{};
    double acc_z{};
    double motor_cmd[4]{};    // 0.0 .. 1.0
    double motor_erpm[4]{};   // оберти за хвилину
    double roll_deg{};
    double pitch_deg{};
    int32_t clip_count{};
};

class FlightLogAnalyzer {
public:
    static constexpr size_t kMinWindow = 64;
    static constexpr double kGravAcc = 9.80665;

    [[nodiscard]] static FlightFault diagnose(std::span<const FlightSample> window) noexcept {
        if (window.size() < kMinWindow) {
            return FlightFault::None;
        }

        size_t desync_count = 0;
        size_t clip_count = 0;
        size_t saturation_count = 0;

        for (const auto& sample : window) {
            // Кліпінг акселерометра: лічильник відкинутих вибірок або наближення до +-16g
            if (sample.clip_count > 0 || std::abs(sample.acc_z) > 15.8 * kGravAcc) {
                ++clip_count;
            }

            // Десинхронізація: 100% запит газу при зупинці ротора (eRPM ~ 0) і зриві кута
            for (size_t m = 0; m < 4; ++m) {
                if (sample.motor_cmd[m] > 0.98 && sample.motor_erpm[m] < 100.0) {
                    const double err = std::abs(sample.gyro_roll - sample.setpoint_roll);
                    if (err > 300.0) {
                        ++desync_count;
                    }
                }
            }

            // Насичення мікшера: два або більше моторів одночасно на 100%
            size_t maxed_motors = 0;
            for (double cmd : sample.motor_cmd) {
                if (cmd > 0.98) ++maxed_motors;
            }
            if (maxed_motors >= 2) {
                ++saturation_count;
            }
        }

        if (desync_count >= 3) return FlightFault::MotorDesync;
        if (clip_count >= 5)   return FlightFault::SensorClipping;

        // Пошук розбіжної спіралі «унітазу» через кореляцію крену й тангажу з фазовим зсувом pi/2
        double sum_r2 = 0.0;
        double sum_p2 = 0.0;
        for (const auto& s : window) {
            sum_r2 += s.roll_deg * s.roll_deg;
            sum_p2 += s.pitch_deg * s.pitch_deg;
        }
        const double rms_r = std::sqrt(sum_r2 / static_cast<double>(window.size()));
        const double rms_p = std::sqrt(sum_p2 / static_cast<double>(window.size()));

        if (rms_r > 10.0 && rms_p > 10.0) {
            const size_t shift = window.size() / 4; // зсув фази на чверть періоду (90°)
            size_t matched_phases = 0;
            for (size_t i = 0; i < window.size() - shift; ++i) {
                if ((window[i].roll_deg * window[i + shift].pitch_deg) > 0.0) {
                    ++matched_phases;
                }
            }
            if (matched_phases > (window.size() - shift) * 3 / 4) {
                return FlightFault::ToiletBowl;
            }
        }

        if (saturation_count > window.size() / 2) {
            return FlightFault::MixerSaturation;
        }

        return FlightFault::None;
    }

    [[nodiscard]] static constexpr std::string_view name(FlightFault fault) noexcept {
        switch (fault) {
            case FlightFault::None:            return "Норма (без відмов)";
            case FlightFault::MotorDesync:      return "Десинхронізація мотора (ESC Desync)";
            case FlightFault::SensorClipping:   return "Кліпінг сенсора (VRE завал горизонту)";
            case FlightFault::ToiletBowl:       return "Патерн «Унітаз» (Розсинхрон компаса)";
            case FlightFault::MixerSaturation:  return "Насичення мікшера (Втрата авторитету)";
        }
        return "Невідома відмова";
    }
};
```

Код аналізатора показує головний принцип діагностики: кожна несправність ідентифікується не за абсолютним значенням одного давача, а за **взаємною узгодженістю декількох потоків**. Десинхрон викривається одночасністю високого запиту газу та нульових обертів eRPM; кліпінг — перевищенням повної шкали АЦП; «унітаз» — взаємною квазігармонійною ортогональністю осей нахилу; а насичення — довготривалим виходом суми керування за межі одиниці. Вміння швидко зіставляти ці патерни перетворює роботу з бортовим логом із ворожіння на точну інженерну експертизу.
