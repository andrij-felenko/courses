# Конвеєр драйвера сенсора: Архітектура, Інтерфейси та Обробка Даних

У сучасних вбудованих системах (embedded systems) датчики (сенсори) відіграють критичну роль, збираючи інформацію про навколишнє середовище, стан механізмів, положення у просторі тощо. Проте отримання "сирих" електричних сигналів або цифрових значень — це лише перший крок. Щоб ці дані стали корисними для основного прикладного програмного забезпечення, вони повинні пройти через добре спроєктований **конвеєр драйвера сенсора** (Sensor Driver Pipeline). 

Ця стаття детально розглядає архітектуру такого конвеєра, починаючи від низькорівневого отримання даних через апаратні інтерфейси (SPI/I2C), їх буферизацію за допомогою кільцевих буферів (ring buffers) та закінчуючи етапами цифрової фільтрації й підготовки даних для споживання на рівні додатку.

## Архітектура конвеєра драйвера сенсора

Конвеєр драйвера сенсора можна уявити як багатошарову структуру, де кожен рівень виконує свою специфічну функцію, абстрагуючи складнощі нижчого рівня. Основна мета такої архітектури — забезпечити стабільний, передбачуваний та ефективний потік даних від апаратного забезпечення до алгоритмів обробки (наприклад, алгоритмів злиття даних — sensor fusion).

Типовий конвеєр складається з наступних етапів:
1. **Апаратний рівень (Hardware Layer):** Фізичний сенсор та шини передачі даних (I2C, SPI, UART).
2. **Транспортний рівень (Transport Layer):** Низькорівневі драйвери мікроконтролера (MCU), які керують периферією шин, часто з використанням переривань (Interrupts) або прямого доступу до пам'яті (DMA).
3. **Рівень драйвера сенсора (Sensor Driver Layer):** Програмний код, який знає карту регістрів конкретного сенсора, налаштовує його, зчитує сирі дані та перетворює їх у фізичні величини.
4. **Рівень буферизації (Buffering Layer):** Проміжний рівень збереження даних (наприклад, FIFO-буфери), що згладжує нерівномірність зчитування та споживання даних.
5. **Рівень обробки та фільтрації (Processing & Filtering Layer):** Застосування математичних фільтрів для усунення шумів, калібрування та температурної компенсації.

## Отримання даних: Інтерфейси SPI та I2C

Більшість сучасних цифрових сенсорів MEMS (мікроелектромеханічні системи), таких як акселерометри, гіроскопи, магнітометри та барометри, підтримують підключення через послідовні шини I2C або SPI. Вибір між ними залежить від вимог до пропускної здатності, кількості виводів та відстані.

### Шина I2C (Inter-Integrated Circuit)

I2C — це двопровідна шина (SDA - лінія даних, SCL - лінія тактування), яка дозволяє підключати кілька ведених пристроїв (slave) до одного ведучого (master). Вона ідеально підходить для сенсорів, що не вимагають надвисоких швидкостей обміну даними (зазвичай до 400 кГц у Fast Mode або до 1 МГц у Fast Mode Plus).

Головна перевага I2C — економія виводів (пінів) мікроконтролера. Проте накладні витрати на адресацію пристрою та підтвердження (ACK/NACK) роблять її менш ефективною для передачі великих масивів даних.

Приклад ініціалізації та зчитування даних по I2C мовою C (псевдокод з використанням абстрактного HAL):

```c
#include <stdint.h>
#include <stdbool.h>

#define SENSOR_I2C_ADDR 0x68
#define SENSOR_DATA_REG 0x3B

// Функція зчитування 6 байт (наприклад, 3 осі акселерометра по 16 біт)
bool ReadSensorDataI2C(uint8_t* buffer, uint16_t length) {
    // 1. Надсилаємо адресу пристрою (Write) та адресу регістра
    if (HAL_I2C_Master_Transmit(SENSOR_I2C_ADDR, &SENSOR_DATA_REG, 1, 100) != HAL_OK) {
        return false;
    }
    
    // 2. Зчитуємо дані з регістра (Read)
    if (HAL_I2C_Master_Receive(SENSOR_I2C_ADDR, buffer, length, 100) != HAL_OK) {
        return false;
    }
    
    return true;
}
```

### Шина SPI (Serial Peripheral Interface)

SPI — це високошвидкісна синхронна шина, що використовує чотири лінії: MISO, MOSI, SCK та CS (Chip Select). Завдяки відсутності складної адресації та повнодуплексному обміну (дані передаються в обох напрямках одночасно), SPI підходить для сенсорів з високою частотою дискретизації (наприклад, гіроскопи, що працюють на частоті > 1 кГц).

Швидкість SPI може досягати 10 МГц і більше. Використання DMA разом з SPI дозволяє зчитувати дані з сенсора у фоновому режимі, взагалі не навантажуючи центральний процесор (CPU).

Приклад зчитування даних по SPI:

```c
#include <stdint.h>

#define SENSOR_READ_BIT 0x80
#define SENSOR_DATA_REG 0x3B

void ReadSensorDataSPI(uint8_t* tx_buffer, uint8_t* rx_buffer, uint16_t length) {
    // Встановлюємо старший біт адреси для операції зчитування
    tx_buffer[0] = SENSOR_DATA_REG | SENSOR_READ_BIT;
    
    // Опускаємо лінію Chip Select
    HAL_GPIO_WritePin(CS_GPIO_PORT, CS_PIN, GPIO_PIN_RESET);
    
    // Передаємо адресу регістра та зчитуємо дані
    HAL_SPI_TransmitReceive(&hspi1, tx_buffer, rx_buffer, length + 1, 100);
    
    // Піднімаємо лінію Chip Select
    HAL_GPIO_WritePin(CS_GPIO_PORT, CS_PIN, GPIO_PIN_SET);
}
```

## Буферизація: Кільцеві буфери

Коли дані успішно отримані апаратним забезпеченням, їх необхідно тимчасово зберегти перед тим, як алгоритми високого рівня почнуть їх обробляти. Пряма передача даних з переривання (ISR) безпосередньо у функцію обробки часто є поганою практикою, оскільки обробка може зайняти більше часу, ніж інтервал між надходженням нових вибірок даних.

Для вирішення цієї проблеми використовується **кільцевий буфер** (Circular Buffer або Ring Buffer). Це структура даних, яка використовує єдиний масив фіксованого розміру так, наче він з'єднаний кінець-в-кінець.

### Математична модель кільцевого буфера

Кільцевий буфер характеризується своїм розміром $N$, вказівником запису (head) та вказівником читання (tail).
При додаванні нового елемента вказівник запису зміщується на одну позицію:

$$ head = (head + 1) \pmod{N} $$

Аналогічно, при читанні елемента вказівник читання зміщується:

$$ tail = (tail + 1) \pmod{N} $$

Буфер вважається порожнім, якщо $head = tail$. Буфер вважається повним, якщо наступна позиція після $head$ збігається з $tail$:

$$ (head + 1) \pmod{N} = tail $$

### Реалізація на мові C/C++

Реалізація кільцевого буфера повинна бути безпечною для використання у багатопотоковому середовищі або в контексті переривань. Розглянемо приклад простого кільцевого буфера для збереження структур з даними сенсора.

```cpp
#include <cstdint>
#include <atomic>

// Структура даних сенсора
struct SensorData {
    float x;
    float y;
    float z;
    uint32_t timestamp;
};

template <size_t N>
class SensorRingBuffer {
private:
    SensorData buffer[N];
    std::atomic<size_t> head{0};
    std::atomic<size_t> tail{0};

public:
    // Додавання даних у буфер (викликається в ISR)
    bool push(const SensorData& data) {
        size_t current_head = head.load(std::memory_order_relaxed);
        size_t next_head = (current_head + 1) % N;

        if (next_head == tail.load(std::memory_order_acquire)) {
            // Буфер переповнений
            return false;
        }

        buffer[current_head] = data;
        head.store(next_head, std::memory_order_release);
        return true;
    }

    // Зчитування даних з буфера (викликається в основному циклі)
    bool pop(SensorData& data) {
        size_t current_tail = tail.load(std::memory_order_relaxed);

        if (current_tail == head.load(std::memory_order_acquire)) {
            // Буфер порожній
            return false;
        }

        data = buffer[current_tail];
        tail.store((current_tail + 1) % N, std::memory_order_release);
        return true;
    }
};
```
У цьому прикладі використання `std::atomic` гарантує відсутність стану гонитви (race condition) у системі з одним виробником (Producer, наприклад, ISR) та одним споживачем (Consumer, наприклад, завдання RTOS), що є типовим сценарієм (Single-Producer Single-Consumer - SPSC).

## Обробка та фільтрація даних

Сирі дані, отримані від MEMS-сенсорів, неминуче містять шум. Цей шум може мати електричну природу, виникати через механічні вібрації пристрою, або бути тепловим шумом самого чутливого елемента. Тому наступним етапом у конвеєрі є математична фільтрація.

### Фільтр ковзного середнього (Moving Average Filter)

Найпростішим та найбільш вживаним фільтром низьких частот (Low-Pass Filter) у вбудованих системах є фільтр ковзного середнього. Він розраховує середнє арифметичне заданої кількості останніх вимірювань.

Формула фільтра ковзного середнього:

$$ y[n] = \frac{1}{M} \sum_{i=0}^{M-1} x[n-i] $$

де:
- $y[n]$ — відфільтроване значення на кроці $n$.
- $x[n-i]$ — сире значення.
- $M$ — розмір вікна фільтрації.

Реалізація такого фільтра вимагає зберігання $M$ попередніх значень, що може споживати значну кількість оперативної пам'яті (RAM), якщо розмір вікна великий.

### Експоненційне ковзне середнє (Exponential Moving Average - EMA)

Набагато ефективнішим з точки зору використання пам'яті є експоненційне ковзне середнє (або IIR-фільтр першого порядку). Цей фільтр не вимагає збереження історії вимірювань; він зберігає лише попереднє відфільтроване значення.

Математична формула ЕМА виглядає так:

$$ y[n] = \alpha \cdot x[n] + (1 - \alpha) \cdot y[n-1] $$

де:
- $\alpha$ — коефіцієнт згладжування ($0 < \alpha \le 1$). Чим менше $\alpha$, тим сильніше згладжування і більша затримка сигналу.
- $x[n]$ — поточне сире вимірювання.
- $y[n]$ — поточне відфільтроване значення.
- $y[n-1]$ — попереднє відфільтроване значення.

Цей алгоритм ідеально підходить для мікроконтролерів завдяки низькій обчислювальній складності та мінімальним вимогам до пам'яті.

Приклад реалізації на C++:

```cpp
class EMAFilter {
private:
    float alpha;
    float current_value;
    bool is_initialized;

public:
    EMAFilter(float alpha_val) : alpha(alpha_val), current_value(0.0f), is_initialized(false) {}

    float update(float new_sample) {
        if (!is_initialized) {
            current_value = new_sample;
            is_initialized = true;
        } else {
            current_value = alpha * new_sample + (1.0f - alpha) * current_value;
        }
        return current_value;
    }

    void reset() {
        is_initialized = false;
    }
};

// Використання:
// EMAFilter filter_x(0.1f); // Сильне згладжування
// float filtered_accel_x = filter_x.update(raw_accel_x);
```

### Комплексна обробка (Sensor Fusion)

Після того як індивідуальні канали даних відфільтровані, наступним етапом може бути злиття даних (Sensor Fusion). Наприклад, використання фільтра Калмана (Kalman Filter) або фільтра Маджвіка (Madgwick Filter) для об'єднання даних з акселерометра, гіроскопа та магнітометра (IMU 9-DOF) з метою отримання точної орієнтації об'єкта у просторі (квартерніони або кути Ейлера). Цей етап зазвичай виноситься за межі драйвера в окрему бібліотеку, оскільки він є дуже вимогливим до обчислювальних ресурсів і зазвичай спирається на FPU (Floating Point Unit).

## Інтеграція в систему та RTOS

Останній етап конвеєра полягає в доставці очищених, відкаліброваних даних до споживача. У системах реального часу (RTOS) це часто реалізується через черги повідомлень (Message Queues) або механізми публікації/підписки (Pub/Sub).

Типовий потік виконання:
1. Апаратний таймер або переривання від лінії INT сенсора сигналізує про готовність даних.
2. ISR (Interrupt Service Routine) ініціює DMA-транзакцію по SPI.
3. Переривання завершення DMA поміщає сирі дані в кільцевий буфер і розблоковує (unblock) завдання обробки (Task) за допомогою семафора або прапорця подій (Event Flag).
4. Завдання обробки зчитує дані з кільцевого буфера, перетворює сирі байти (LSB) у фізичні величини (м/с², град/с), застосовує EMA-фільтрацію.
5. Завдання публікує готові дані у RTOS-чергу або викликає зареєстровані callback-функції верхнього рівня.

Такий конвеєрний підхід забезпечує модульність, полегшує тестування (Unit Testing) окремих компонентів (наприклад, фільтрів без прив'язки до реального заліза) і робить архітектуру драйвера масштабованою для підтримки нових типів сенсорів.

## Висновок

Проєктування конвеєра драйвера сенсора вимагає глибокого розуміння як апаратного забезпечення (інтерфейси SPI/I2C, DMA, переривання), так і програмних концепцій (структури даних, багатопоточність, цифрова обробка сигналів). Використання кільцевих буферів для безперебійного потоку даних та ефективних фільтрів (таких як EMA) для придушення шумів є ключем до створення надійних та чутливих вбудованих систем. Застосовуючи описані архітектурні патерни, розробники можуть створювати драйвери, які забезпечують високу продуктивність при мінімальному навантаженні на ядро мікроконтролера.
