Коли портативний прилад на базі мікроконтролера Cortex-M4 з тактовою частотою 80 МГц намагається водночас обертати безколекторний двигун за алгоритмом векторного керування (FOC), опитувати матрицю сенсорного скла, підписувати мережеві пакети криптографічним ключем ECDSA та вимірювати залишок заряду акумулятора, система неминуче стикається з кризою обчислювальних ресурсів і таймінгу. Векторне керування вимагає оновлення трьох каналів ШІМ кожні 50 мкс (частота перемикання 20 кГц), причому перетворення координат Кларк і Парка разом із ПІД-регуляторами струму мають завершуватися швидше ніж за 10 мкс, інакше інвертор згенерує спотворений вектор напруги, що спричинить акустичний шум і нагрів обмоток. У цей самий момент користувач торкається скла: процесор мусить зчитати матрицю з 150 перетинів електродів, відфільтрувати перешкоди від імпульсного джерела живлення та розрахувати координати пальця. Якщо ж пристрій отримує запит на встановлення TLS-з'єднання, де обчислення скалярного добутку на еліптичній кривій secp256r1 забирає близько 1,8 мільйона процесорних тактів (понад 22 мс безперервного рахунку на 80 МГц), пріоритети переривань стикаються в жорсткому конфлікті.

Спроба розв'язати проблему за допомогою підвищення пріоритету таймера двигуна призводить до того, що обробник переривання FOC витісняє виконання криптографічної функції кожні 50 мкс. Контекст процесора зберігається та відновлюється сотні разів за мілісекунду, додаючи накладні витрати на перемикання стеків. Тим часом сканування сенсорної панелі затримується, інтерфейс починає «фризити», а кулонівський лічильник акумулятора пропускає короткочасні піки струму споживання, через що накопичується фатальна похибка оцінки енергії.

```
+-----------------------------------------------------------------------------+
| Монолітний підхід (Single MCU): перевантаження обчислювального ядра         |
|                                                                             |
| 20 кГц ISR: Векторний FOC двигуна (дедлайн 10 мкс) ──┐                     |
|                                                      ├──> Джиттер переривань|
| Фонова криптографія ECC P-256 (22 мс / 1.8 млн тактів)│   (IRQ Jitter) &    |
|                                                      │    пропуск кроків    |
| Сканування ємнісного тачу (150 точок матриці) ───────┤                      |
|                                                      │    Частота ядра 80 МГц|
| Інтегрування струму АКБ (шум шунта 10 мОм) ──────────┘    Струм MCU ~25-45 мА|
+-----------------------------------------------------------------------------+
```

Виходом із цього глухого кута стає відмова від монолітного принципу «одне ядро робить усе програмно» на користь гетерогенної архітектури. Функціональні вузли, що вимагають надшвидкої реакції реального часу, специфічних аналогових вимірювань або ізольованого криптографічного захисту, делегуються спеціалізованим зовнішнім інтегральним схемам — супутнім чипам (англ. *Smart Companion ICs* або *Offloading Coprocessors*).

![Архітектурне порівняння: перевантажений монолітний процесор проти гетерогенної системи](/root/course/embedded/shcho-bere-na-sebe-chuzhyi-chyp/img/monolithic-vs-companion-architecture.svg)
*Порівняння монолітної та делегованої архітектури: перевантажене ядро втрачає дедлайни реального часу, тоді як гетерогенна система ізолює критичні задачі в апаратних супутніх мікросхемах.*

## Анатомія та класи спеціалізованих супутніх чипів

Супутній чип — це не просто пасивний сенсор чи перетворювач рівнів, а спеціалізований кремнієвий автомат (або самостійний мікроконтролер із жорстко зашитим мікрокодом), призначений для автономного виконання вузького класу завдань. Головний процесор (Host MCU) взаємодіє з ним через стандартні послідовні шини (I2C, SPI, UART) за чітко регламентованим протоколом: запис конфігураційних регістрів на етапі старту, отримання асинхронних сигналів тривоги чи готовності через окрему лінію переривання (INT/IRQ) та періодичне читання кінцевих, попередньо оброблених результатів.

![Спектр супутніх мікросхем: кремнієві двигуни та цифровий контракт взаємодії](/root/course/embedded/shcho-bere-na-sebe-chuzhyi-chyp/img/companion-chips-spectrum.svg)
*П'ять класів спеціалізованих мікросхем: внутрішня апаратна логіка бере на себе складну фізику й математику, надаючи головному процесору компактний інтерфейс обміну.*

### 1. Апаратні криптографічні чипи та модулі безпеки (Secure Elements)

Криптографічні алгоритми з відкритим ключем (ECDSA, RSA, Ed25519) базуються на операціях множення та ділення у скінченних полях Галуа з числами розрядністю 256–4096 бітів. Виконання таких операцій на універсальному 32-бітному ядрі вимагає тисяч ітерацій циклів із постійним використанням оперативної пам'яті. Крім того, універсальні процесори вразливі до атак сторонніми каналами (англ. *Side-Channel Attacks*): аналізуючи коливання споживання струму (Differential Power Analysis, DPA) або електромагнітного випромінювання під час множення, зловмисник може відновити закритий ключ.

Мікросхеми класу Secure Element (наприклад, Microchip ATECC608B, NXP SE050, Infineon OPTIGA Trust M) містять усередині:
- Апаратні криптографічні акселератори для кривих NIST P-256, Ed25519, симетричного шифру AES-128/256 та гешування SHA-256;
- Справжній апаратний генератор випадкових чисел (TRNG), побудований на тепловому шумі p-n переходів кремнію;
- Фізично захищену енергонезалежну пам'ять (EEPROM/Flash), захищену активною металевою сіткою (active shield): при спробі механічного шліфування корпусу чи лазерного зондування внутрішні ланцюги розриваються, і чип миттєво стирає вміст ключів;
- Апаратний захист від глітчингу (збоїв за живленням чи тактовою частотою) та вирівнювання споживання струму під час виконання криптографічних раундів для повного унеможливлення DPA.

```
Host MCU (I2C Master)                           ATECC608B (Secure Element)
       │                                                    │
       │─── 1. Запит Sign(Slot_0, Digest_SHA256) ──────────>│
       │    (Host передає лише 32 байти гешу)               │
       │                                                    │ [Апаратне множення]
       │                                                    │ [Приватний ключ]
       │                                                    │ [НЕ залишає чип!]
       │                                                    │ [Генерація k, r, s]
       │<── 2. Відповідь: Підпис (r: 32B, s: 32B) ──────────│
       │    (Готовий 64-байтний цифровий підпис)            │
```

Для Host MCU крипточип постає чорною скринькою з інтерфейсом I2C: Host передає командний пакет, що містить 32-байтний геш повідомлення, і через 12–15 мс забирає готовий 64-байтний цифровий підпис. Закритий ключ узагалі ніколи не виходить за межі кристала крипточипа, не потрапляє у Flash або RAM головного процесора і не транслюється по друкованій платі.

### 2. Аудіокодеки з вбудованим DSP

Оцифрування, обробка та відтворення звуку високої якості (Hi-Fi, 48 кГц, 24 біти, стерео) створюють потік даних швидкістю 2,304 Мбіт/с. Якщо виконувати цифрову фільтрацію сигналу (IIR/FIR-фільтри еквалайзера), динамічне стиснення діапазону (DRC, Dynamic Range Compression) та автоматичне регулювання підсилення (ALC) на головному мікроконтролері, кожні 20,8 мкс ядро муситиме брати пару відліків, здійснювати до 20 операцій множення з накопиченням (MAC) з плавальною або 64-бітною фіксованою комою й записувати результат у вихідний буфер.

Спеціалізовані аудіокодеки (наприклад, Cirrus Logic WM8960, Texas Instruments TLV320AIC3254, PCM5102A) інтегрують:
- Високоточні дельта-сигма ЦАП і АЦП із відношенням сигнал/шум (SNR) > 98–105 дБ;
- Вбудований цифровий сигнальний процесор (miniDSP), який апаратно реалізує 5-смуговий параметричний еквалайзер, тривимірне розширення стереобази та лімітер перевантаження;
- Аналоговий комутатор входів, диференційні мікрофонні передпідсилювачі з програмованим коефіцієнтом підсилення (PGA) та вихідні підсилювачі для навушників (Class AB або безконденсаторний Capless Class W) та динаміків (Class D).

Головний мікроконтролер конфігурує параметри звукового тракту по шині I2C один раз під час ініціалізації, а передавання сирих аудіоданих здійснює за допомогою контролера прямого доступу до пам'яті (DMA) по синхронній шині I2S (Inter-IC Sound). Процесорне ядро витрачає рівно нуль тактів на математику обробки сигналу.

### 3. Контролери ємнісних сенсорних екранів (Touch Controllers)

Ємнісна сенсорна панель являє собою сітку прозорих електродів із оксиду індію-олова (ITO), нанесених на скло. Визначення координат дотику вимагає вимірювання мізерних змін взаємної ємності (Mutual Capacitance) на кожному перетині сітки — типово від десятків фемтофарад до одиниць пікофарад:

```
ΔC = C_touch - C_baseline   (порядку 50–300 фФ)
```

Щоб забезпечити плавну роботу інтерфейсу, сканування всієї сітки (наприклад, 10 ліній передавання на 15 ліній приймання = 150 вузлів) має відбуватися зі швидкістю 60–120 Гц. Програмна реалізація цієї задачі на Host MCU призвела б до необхідності безперервного генерування високочастотних вимірювальних імпульсів, відліку значень за допомогою внутрішнього АЦП, складної цифрової фільтрації шумів (особливо низькочастотних завад 50/60 Гц від імпульсних зарядок) та виконання алгоритмів кластеризації для обчислення центру маси плями дотику.

Чипи контролерів тач-панелей (наприклад, FocalTech FT6236, Goodix GT911, Azoteq IQS5xx):
- Апаратно генерують зондувальні імпульси зі стрибкоподібною зміною частоти (Frequency Hopping) для обходу спектральних піків електромагнітних завад;
- Виконують постійне відстеження та автокалібрування базової лінії (Baseline Tracking) при зміні температури й вологості;
- Визначають до 5–10 одночасних точок дотику (Multi-touch), фільтрують помилкові спрацьовування від випадкового дотику долонею (Palm Rejection) та розпізнають стандартні жести (проведення пальцем, подвійний клік, зумування).

Контракт із Host MCU максимально спрощений: лінія `INT` (Active-Low) утримується в логічній одиниці. У момент дотику чип опускає лінію `INT` у нуль. Головний процесор переривається, робить коротку транзакцію I2C довжиною 6–14 байтів і вичитує вже готові піксельні координати `(X, Y)` та ідентифікатор жесту.

### 4. Інтелектуальні драйвери двигунів із векторним керуванням (FOC)

Керування кроковими або безколекторними (BLDC/PMSM) двигунами вимагає прецизійного формування синусоїдального струму в обмотках. Традиційне програмне формування мікрокроків змушує Host MCU генерувати тисячі таймерних переривань на секунду. Якщо ж застосовується алгоритм орієнтованого за полем керування (Field Oriented Control, FOC), ядро мусить безперервно вимірювати фазні струми, виконувати тригонометричні перетворення просторових векторів:

```
[i_alpha, i_beta] = Clarke([i_a, i_b, i_c])
[i_d, i_q]         = Park([i_alpha, i_beta], theta)
```

та розраховувати тривалість імпульсів просторово-векторної ШІМ (SVPWM).

Сучасні інтелектуальні драйвери (наприклад, Trinamic/Analog Devices TMC2209, TMC5160, TI DRV8301):
- Інтегрують апаратний інтерполятор мікрокроків (MicroPlyer), який приймає базові імпульси кроку й плавно інтерполює їх на 256 мікрокроків із синусоїдальним профілем струму (технологія StealthChop);
- Містять апаратний вимірювач зворотного електрорушійного зусилля (Back-EMF), що дозволяє визначати механічне навантаження на вал та детектувати блокування ротора без фізичних кінцевих вимикачів (технологія StallGuard);
- Автоматично регулюють струм обмоток відповідно до поточного навантаження, знижуючи тепловиділення двигуна на 75% у стані спокою (CoolStep);
- У топових версіях (TMC5160) містять повноцінний апаратний генератор траєкторій руху (Ramp Generator): Host MCU лише записує в регістри кінцеву координату, максимальну швидкість та прискорення по SPI, після чого чип самостійно розганяє, веде й гальмує двигун.

### 5. Прецизійні вимірювачі заряду акумуляторів (Fuel Gauges)

Визначення залишкової ємності літій-іонних та літій-полімерних акумуляторів (State of Charge, SOC) — класична задача, де просте вимірювання напруги дає неприпустимо велику похибку. Крива розряду Li-ion акумулятора в діапазоні від 80% до 20% є майже горизонтальною полицею: зміна напруги на 20 мВ може відповідати зміні заряду на 30%. Крім того, напруга на клемах сильно просідає під навантаженням через внутрішній опір комірки (IR) та змінюється залежно від температури:

```
V_cell = OCV(SOC, T) - I_load · R_int(SOC, T, CycleCount)
```

Спеціалізовані чипи моніторингу заряду (наприклад, Texas Instruments BQ27441-G1, Analog Devices/Maxim MAX17048, MAX17055):
- Інтегрують прецизійний 16–18 бітний дельта-сигма АЦП із вбудованим малошумним підсилювачем, підключеним до токового шунта номіналом 5–10 мОм;
- Безперервно виконують кулонівський підрахунок (Coulomb Counting) — апаратне інтегрування струму в часі з дискретністю в частки мікроампер-секунд:

```
Q(t) = Q_0 + ∫ I(t) dt
```

- Використовують запатентовані математичні моделі акумуляторів (TI Impedance Track або Maxim ModelGauge m5), які апаратно компенсують просідання напруги під навантаженням, відстежують старіння батареї за кількістю циклів, вимірюють динамічний імпеданс комірки та розраховують справжній SOC у відсотках із похибкою менше ніж 1%;
- Мають автономні компаратори тривоги: чип сигналізує на лінію переривання Host MCU тільки тоді, коли заряд падає нижче встановленого порогу (наприклад, 15%) або температура виходить за межі безпечного вікна заряджання.

## Архітектурні вигоди апаратного делегування

Винесення критичних функцій на спеціалізовані кристали радикально змінює структуру всього вбудованого пристрою. Це не просто оптимізація коду, а перерозподіл інженерних компромісів за чотирма ключовими напрямками.

```
       ┌─────────────────────────────────────────────────────────┐
       │             ВИГОДИ АПАРАТНОГО ДЕЛЕГУВАННЯ               │
       └────────────────────────────┬────────────────────────────┘
                                    │
     ┌──────────────────┬───────────┴───────────┬──────────────────┐
     ▼                  ▼                       ▼                  ▼
┌──────────────┐ ┌──────────────┐        ┌──────────────┐ ┌──────────────┐
│ Розвантаження│ │ Ліквідація   │        │ Економія     │ │ Автономний   │
│ тактової     │ │ жорсткого    │        │ Flash & RAM  │ │ глибокий     │
│ частоти (MIPS│ │ Real-Time    │        │ пам'яті      │ │ сон          │
│ P = C·V²·f)  │ │ (Zero Jitter)│        │ (Lean Host)  │ │ (Wake on IRQ)│
└──────────────┘ └──────────────┘        └──────────────┘ └──────────────┘
```

### 1. Розвантаження тактової частоти ядра (CPU Core Clock & MIPS Offloading)

Коли обчислювально складні алгоритми виконуються в кремнії супутнього чипа, сумарне навантаження на головний процесор падає з 80–95% до 3–8%. Це дозволяє розробнику знизити тактову частоту Host MCU зі 168–480 МГц до 16–48 МГц або замінити дорогий процесор класу Cortex-M7 на ультрабюджетний Cortex-M0+/M3.

Динамічна потужність споживання КМОН-мікроконтролера прямо пропорційна тактовій частоті та квадрату напруги живлення:

```
P_dyn = C_eff · V_dd² · f_clk
```

де `C_eff` — ефективна перемикальна ємність затворів кристала, `V_dd` — напруга ядра, а `f_clk` — тактова частота. Зниження частоти ядра зі 120 МГц (струм споживання ~30 мА) до 24 МГц зменшує струм ядра до ~4,5 мА. При цьому супутній чип (наприклад, криптографічний ATECC608B або паливний вимірювач BQ27441), бувши оптимізованим кремнієвим автоматом без накладних витрат на вибірку універсальних інструкцій, під час активної роботи споживає лише 0,5–1,5 мА, а у режимі очікування — менше ніж 1 мкА.

### 2. Усунення жорстких вимог реального часу (Elimination of Hard Real-Time Deadlines)

У складних системах найбільш підступними є помилки, пов'язані з накладанням асинхронних подій реального часу:
- Таймерне переривання FOC оновлює струм інвертора;
- Переривання UART приймає байт телеметрії;
- DMA буфер I2S запитує нову порцію аудіо;
- Програмний цикл сканує сенсорну матрицю.

Якщо дві події виникають одночасно, менш пріоритетне переривання зазнає затримки (джиттеру, англ. *Interrupt Latency Jitter*). Для контуру керування двигуном затримка перемикання ШІМ навіть на 5 мкс може призвести до наскрізного струму через силові ключі, а для генерації аудіо — до характерного клацання (Audio Underrun).

Делегування переносить жорсткий реальний час (Hard Real-Time) усередину кремнію супутніх мікросхем. Драйвер TMC2209 комутує ключі з апаратною фіксацією дедтаймів на рівні наносекунд незалежно від того, що робить Host MCU. Головний процесор переходить у комфортний домен м'якого реального часу (Soft Real-Time) або взагалі працює за подійно-орієнтованою моделлю під керуванням простої RTOS чи кінцевого автомата.

### 3. Економія пам'яті програм і даних (Flash & RAM Footprint)

Програмна реалізація сучасних математичних та криптографічних протоколів вимагає значних обсягів пам'яті:
- Бібліотека mbedTLS або wolfSSL для підтримки TLS 1.3, генерації ключів та валідації X.509 сертифікатів забирає від 60 до 140 кБ Flash та від 16 до 35 кБ RAM;
- Програмний рушій обробки жестів тач-панелі з фільтрами Калмана та матрицями калібрування — близько 25–40 кБ Flash;
- Алгоритм FOC з бібліотекою векторних перетворень — 20–35 кБ Flash.

Сумарно важкі алгоритмічні бібліотеки вимагають щонайменше 256–512 кБ Flash і 64–128 кБ RAM, змушуючи обирати мікроконтролери у дорогих корпусах LQFP100/144. При використанні супутніх чипів увесь цей код вилучається з прошивки. Драйвер Secure Element чи тач-контролера займає лише 3–6 кБ Flash для роботи з регістрами I2C. Прошивка стає легкою, а Host MCU можна вибрати з об'ємом пам'яті 32–64 кБ Flash у компактному корпусі QFN32.

### 4. Автономність роботи в режимах глибокого сну (Low-Power Offloading)

Для автономних пристроїв із живленням від акумулятора критично важливо максимізувати час перебування в режимах ультранизького споживання (`Deep Sleep`, `Stop Mode`, `Standby`).

Якщо пристрій реалізує моніторинг батареї або очікування дотику програмно, Host MCU змушений кожні 50–100 мс прокидатися за таймером RTC:
1. Запустити тактовий генератор PLL;
2. Увімкнути живлення внутрішнього АЦП;
3. Виконати серію вимірювань;
4. Обробити результати й знову заснути.

Цикл прокидання та виходу на робочу частоту споживає значний імпульсний струм (15–30 мА впродовж кількох мілісекунд), що дає середній струм чергового режиму на рівні 150–400 мкА.

З супутніми мікросхемами Host MCU спить безперервно у найглибшому режимі із споживанням 2–5 мкА. Fuel Gauge (MAX17055) самостійно контролює акумулятор, споживаючи лише 7 мкА, а тач-контролер у режимі низькочастотного чергування споживає 15 мкА. Коли стається подія (користувач торкнувся скла або акумулятор сів нижче 3.4 В), супутній чип формує короткий спадний фронт на лінії `INT`. Цей сигнал потрапляє на пін зовнішнього переривання (EXTI/Wakeup pin) мікроконтролера і миттєво будить систему.

## Прихована ціна та інженерні компроміси

Перенесення задач на зовнішній кремній не є універсальною панацеєю. За кожне архітектурне рішення доводиться платити ускладненням схемотехніки, накладними витратами каналу зв'язку та ризиками виробництва.

```
       ┌─────────────────────────────────────────────────────────┐
       │             ПРИХОВАНА ЦІНА АУТСОРСИНГУ                  │
       └────────────────────────────┬────────────────────────────┘
                                    │
     ┌──────────────────┬───────────┴───────────┬──────────────────┐
     ▼                  ▼                       ▼                  ▼
┌──────────────┐ ┌──────────────┐        ┌──────────────┐ ┌──────────────┐
│ Ріст вартості│ │ Трасування   │        │ Вразливість  │ │ Вендор-лок   │
│ специфікації │ │ друкованої   │        │ шини обміну  │ │ та ризики    │
│ (BOM Cost)   │ │ плати (PCB)  │        │ (I2C Lockup) │ │ Single-Source│
└──────────────┘ └──────────────┘        └──────────────┘ └──────────────┘
```

### 1. Зростання вартості специфікації (BOM Cost) та площа друкованої плати

Кожен додатковий чип на платі — це прямі фінансові витрати:
- Спеціалізований Secure Element (ATECC608B) коштує близько $0.60–$0.90 у партіях від 10 тис. штук;
- Апаратний аудіокодек (WM8960) — $1.20–$2.20;
- Контролер палива (BQ27441) — $0.80–$1.40;
- Драйвер крокового двигуна (TMC2209) — $1.30–$2.00.

Крім самої мікросхеми, виникає потреба в обв'язці (Bill of Materials overhead):
- Розв'язувальні керамічні конденсатори по лініях живлення (Decoupling Capacitors);
- Резистори підтяжки шини I2C (Pull-up resistors);
- Прецизійні токові шунти з низьким температурним коефіцієнтом опору (TCR < 50 ppm/°C);
- Фільтрувальні феритові намистини (Ferrite Beads) для розділення аналогового й цифрового живлення.

Додаткові компоненти вимагають збільшення площі друкованої плати (PCB Real Estate), ускладнюють трасування (може знадобитися перехід із 2-шарової на 4-шарову плату) та збільшують час роботи лінії поверхневого монтажу (SMT Pick-and-Place machine time).

### 2. Накладні витрати та вразливість шини зв'язку

Перенесення функціоналу з внутрішньої шини ядра (де доступ до регістрів відбувається за 1–2 такти процесора по шині AHB/APB) на зовнішню послідовну шину (I2C або SPI) створює часові затримки:
- Для зчитування 6 байтів координат із тач-контролера по шині I2C Standard Mode (100 кбіт/с) потрібно:

```
t_tx = (1 + 1 + 1 + 6) байтів × 9 бітів / 100 000 біт/с ≈ 810 мкс
```

Навіть у режимі Fast Mode (400 кбіт/с) ця транзакція забирає близько 200 мкс. Якщо на одній шині I2C висять кілька пристроїв (тач, крипточип, датчик заряду, акселерометр), виникає конкуренція за шину (Bus Contention). Довгі транзакції одного чипа блокують опитування інших.

Найнебезпечнішою апаратною проблемою I2C є зависання шини (**I2C Bus Lockup / SDA Stuck Low**). Якщо Host MCU перезавантажився (через спрацьовування сторожового таймера Watchdog або стрибок живлення) саме в той момент, коли ведений чип транслював логічний нуль на лінію SDA, ведений залишається чекати наступних тактів SCL. Host після старту бачить затиснуту в нуль лінію SDA і не може згенерувати умову `START`.

Для захисту від цієї аварії в драйвері Host MCU обов'язково реалізують алгоритм примусового скидання шини: якщо SDA = 0 під час ініціалізації, пін SCL тимчасово перемикається в режим звичайного GPIO виходу й вручну генерує 9 тактів синхронізації:

```
           ІНІЦІАЛІЗАЦІЯ ХОСТА: SDA затиснута в 0 веденим чипом
SDA: ──────┐                                       ┌────────────────
           └───────────────────────────────────────┘ (звільнено)
SCL: ────┐   ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐   ┌────────
(GPIO)   └───┘1└─┘2└─┘3└─┘4└─┘5└─┘6└─┘7└─┘8└─┘9└───┘ STOP
```

Ведений чип видає залишок байта, бачить відсутність підтвердження (NACK), звільняє лінію SDA, після чого Host генерує умову `STOP` і переводить піни назад в апаратний режим I2C.

### 3. Ризики ланцюжка постачання та вендор-лок (Single-Source Lock-in)

Універсальні мікроконтролери загального призначення (наприклад, лінійки на базі Cortex-M0+/M4) часто мають взаємозамінні аналоги від різних виробників (STMicroelectronics, GigaDevice, Artery, Nuvoton) із сумісними цоколівками та схожими регістрами.

Спеціалізовані супутні мікросхеми майже завжди є унікальними виробами одного постачальника (Single Source):
- Драйвери Trinamic TMC2209 захищені патентами на алгоритми StealthChop і StallGuard; прямих аналогів з ідентичним протоколом UART/Step-Dir на ринку не існує;
- Алгоритми паливних вимірювачів BQ27441 жорстко прив'язані до хімічних профілів Texas Instruments;
- Крипточипи ATECC608 вимагають використання пропрієтарної бібліотеки CryptoAuthLib.

Якщо виробник зіткнеться з дефіцитом кремнію на фабриці або оголосить про завершення життєвого циклу продукту (End of Life, EOL), компанія опиниться перед необхідністю повного редизайну апаратної частини друкованої плати та переписування значної частини прошивки.

## Інженерна матриця вибору

Рішення про те, чи реалізовувати функцію всередині головного мікроконтролера, чи виносити її на супутній чип, приймається на основі аналізу чотирьох критичних інженерних осей:

![Інженерний алгоритм вибору між супутнім чипом та монолітним мікроконтролером](/root/course/embedded/shcho-bere-na-sebe-chuzhyi-chyp/img/decision-flowchart-integrate-vs-offload.svg)
*Дерево прийняття рішень: послідовна оцінка жорсткості дедлайнів, обчислювального навантаження, енергоспоживання та економіки специфікації BOM.*

1. **Критичність дедлайнів реального часу:** чи спричинить затримка виконання задачі на 5–50 мкс апаратну аварію, зрив синхронізації або спотворення вихідного фізичного сигналу?
   - Якщо **ТАК** → *Виносити на апаратний чип* (FOC драйвер, апаратний генератор траєкторій, апаратний кодек).
2. **Обчислювальний бюджет (MIPS Budget):** чи перевищує навантаження від алгоритму 25–30% сумарної продуктивності ядра при найгіршому сценарії (Worst-Case Execution Time, WCET)?
   - Якщо **ТАК** → *Виносити на апаратний чип* (Secure Element, обробка матриці тач-панелі).
3. **Енергетичний бюджет режиму очікування:** чи повинен пристрій перебувати в режимі мікроспоживання (< 20 мкА), але водночас безперервно відстежувати фізичні параметри чи чекати дій користувача?
   - Якщо **ТАК** → *Виносити на апаратний чип* (Fuel Gauge з Wakeup-компаратором, Touch IC).
4. **Фізична безпека та ізоляція секретів:** чи вимагає бізнес-модель захисту ключів шифрування від фізичного зчитування з прошивки приладу?
   - Якщо **ТАК** → *Виносити на апаратний Secure Element*.

## Практичний патерн взаємодії: Подійно-керований драйвер

У правильно спроєктованій системі взаємодія між Host MCU та супутнім чипом ніколи не будується на безперервному опитуванні регістрів у циклі (англ. *busy polling*). Опитування марнує енергію, забиває шину I2C/SPI та навантажує ядро.

Стандартний промисловий патерн складається з трьох елементів:
1. **Лінія сповіщення (Active-Low Interrupt Line, `INT`):** супутній чип тримає лінію високою. При виникненні події (закінчився розрахунок криптопідпису, виявлено дотик до скла або рівень заряду впав нижче критичного порогу) чип опускає лінію в логічний нуль.
2. **Швидкий обробник переривання (ISR):** мікроконтролер конфігурує пін GPIO на переривання за спадним фронтом (Falling Edge). Всередині ISR процесор не виконує важких блокувальних операцій I2C, а лише виставляє прапорець події або надсилає сповіщення в чергу RTOS.
3. **Асинхронне вичитування даних у фоновому потоці:** фонова задача розпізнає подію, виконує коротку пакетну транзакцію по I2C/SPI, вичитує структуру даних і скидає статус переривання в супутньому чипі.

Нижче наведено реалізацію такого драйвера для взаємодії з типовим супутнім чипом моніторингу (наприклад, інтелектуальним Fuel Gauge / Touch Controller):

```c
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

/* Регістри супутньої мікросхеми (Companion IC Registers) */
#define COMPANION_I2C_ADDR       (0x55 << 1)
#define REG_STATUS               0x00
#define REG_DATA_X               0x01
#define REG_DATA_Y               0x03
#define REG_BATTERY_SOC          0x05
#define REG_INT_CLEAR            0x0F

/* Бітові маски статусу */
#define STATUS_FLAG_TOUCH_EVT    (1 << 0)
#define STATUS_FLAG_LOW_BAT_EVT  (1 << 1)
#define STATUS_FLAG_CRYPTO_READY (1 << 2)

/* Структура телеметрії, вичитана з чипа */
typedef struct {
    uint16_t touch_x;
    uint16_t touch_y;
    uint8_t  battery_soc_pct;
    bool     crypto_ready;
} companion_telemetry_t;

/* Апаратні абстракції платформи (HAL stubs) */
extern bool hal_i2c_read_mem(uint16_t dev_addr, uint8_t reg_addr, uint8_t *buf, uint16_t len);
extern bool hal_i2c_write_reg(uint16_t dev_addr, uint8_t reg_addr, uint8_t val);

/* Глобальний прапорець асинхронної події з ISR */
static volatile bool s_companion_event_pending = false;

/**
 * @brief Обробник зовнішнього апаратного переривання від піна INT (Falling Edge)
 */
void companion_exti_isr(void) {
    /* Мінімальна робота в перериванні: фіксуємо подію */
    s_companion_event_pending = true;
}

/**
 * @brief Обробка подій супутнього чипа у фоновому циклі бізнес-логіки
 */
bool companion_process_events(companion_telemetry_t *out_data) {
    if (!s_companion_event_pending || out_data == NULL) {
        return false;
    }

    /* Атомарно скидаємо прапорець переривання для уникнення race condition */
    s_companion_event_pending = false;

    uint8_t status = 0;
    if (!hal_i2c_read_mem(COMPANION_I2C_ADDR, REG_STATUS, &status, 1)) {
        return false; /* Помилка зв'язку по шині */
    }

    /* Обробка події сенсорного вводу */
    if (status & STATUS_FLAG_TOUCH_EVT) {
        uint8_t raw_coords[4];
        if (hal_i2c_read_mem(COMPANION_I2C_ADDR, REG_DATA_X, raw_coords, 4)) {
            out_data->touch_x = (uint16_t)((raw_coords[0] << 8) | raw_coords[1]);
            out_data->touch_y = (uint16_t)((raw_coords[2] << 8) | raw_coords[3]);
        }
    }

    /* Обробка сповіщення про заряд батареї */
    if (status & STATUS_FLAG_LOW_BAT_EVT) {
        uint8_t soc = 0;
        if (hal_i2c_read_mem(COMPANION_I2C_ADDR, REG_BATTERY_SOC, &soc, 1)) {
            out_data->battery_soc_pct = soc;
        }
    }

    out_data->crypto_ready = (status & STATUS_FLAG_CRYPTO_READY) != 0;

    /* Квитування (квитування переривання в регістрах чипа для підняття лінії INT) */
    hal_i2c_write_reg(COMPANION_I2C_ADDR, REG_INT_CLEAR, 0x01);

    return true;
}
```

```cpp
#include <cstdint>
#include <span>
#include <expected>
#include <optional>
#include <array>

namespace embedded {

enum class DriverError : uint8_t {
    BusError,
    InvalidDevice,
    Timeout,
    NoEvent
};

enum class EventType : uint8_t {
    None        = 0x00,
    Touch       = 1 << 0,
    LowBattery  = 1 << 1,
    CryptoDone  = 1 << 2
};

struct Point2D {
    uint16_t x{0};
    uint16_t y{0};
};

struct DeviceReport {
    std::optional<Point2D> touch_position;
    std::optional<uint8_t> battery_soc_percent;
    bool                   crypto_operation_complete{false};
};

class CompanionDriver {
public:
    static constexpr uint8_t I2C_ADDRESS = 0x55 << 1;

    struct Registers {
        static constexpr uint8_t Status     = 0x00;
        static constexpr uint8_t TouchData  = 0x01;
        static constexpr uint8_t BatterySoc = 0x05;
        static constexpr uint8_t IntClear   = 0x0F;
    };

    CompanionDriver() = default;

    /* Викликається з апаратного ISR переривання піна INT */
    void notify_interrupt_asserted() noexcept {
        event_pending_ = true;
    }

    [[nodiscard]] bool has_pending_events() const noexcept {
        return event_pending_;
    }

    /**
     * @brief Неблокуюче опитування та зчитування пакетної телеметрії
     */
    [[nodiscard]] std::expected<DeviceReport, DriverError> process_events() noexcept {
        if (!event_pending_) {
            return std::unexpected(DriverError::NoEvent);
        }

        event_pending_ = false;

        uint8_t status_raw{0};
        if (!i2c_read(Registers::Status, std::span<uint8_t, 1>(&status_raw, 1))) {
            return std::unexpected(DriverError::BusError);
        }

        DeviceReport report{};

        /* Обробка сенсорних координат */
        if (status_raw & static_cast<uint8_t>(EventType::Touch)) {
            std::array<uint8_t, 4> raw_buf{};
            if (i2c_read(Registers::TouchData, raw_buf)) {
                uint16_t x = static_cast<uint16_t>((raw_buf[0] << 8) | raw_buf[1]);
                uint16_t y = static_cast<uint16_t>((raw_buf[2] << 8) | raw_buf[3]);
                report.touch_position = Point2D{x, y};
            }
        }

        /* Обробка заряду АКБ */
        if (status_raw & static_cast<uint8_t>(EventType::LowBattery)) {
            uint8_t soc{0};
            if (i2c_read(Registers::BatterySoc, std::span<uint8_t, 1>(&soc, 1))) {
                report.battery_soc_percent = soc;
            }
        }

        report.crypto_operation_complete = (status_raw & static_cast<uint8_t>(EventType::CryptoDone)) != 0;

        /* Квитування переривання (Ack) */
        const uint8_t clear_cmd{0x01};
        std::ignore = i2c_write(Registers::IntClear, std::span<const uint8_t, 1>(&clear_cmd, 1));

        return report;
    }

private:
    volatile bool event_pending_{false};

    /* Апаратні виклики I2C з використанням безпечних std::span */
    bool i2c_read(uint8_t reg, std::span<uint8_t> dest) noexcept;
    bool i2c_write(uint8_t reg, std::span<const uint8_t> src) noexcept;
};

} // namespace embedded
```

> 🔧 **Навіщо це в реальній розробці:**
>
> Архітектурний розподіл «Головний процесор + Супутні чипи» — це фундамент надійності комерційної електроніки. Намагання зекономити $1 на специфікації компонентів (BOM) шляхом перенесення FOC-керування двигуном, криптографії TLS чи сканування сенсорного скла в єдиний монолітний мікроконтролер майже завжди закінчується зростанням витрат на розробку в десятки разів.
>
> Інженери витрачають місяці на налагодження плаваючих дедлоків в RTOS, боротьбу з джиттером таймерів та пошук причин зависання пристрою під час одночасного дотику до екрана та передачі даних по радіоканалу. Правильно підібраний супутній чип купує головне: **апаратну ізоляцію критичних до часу задач**, зниження споживання енергії в режимі сну на порядок та гарантію того, що збій у бізнес-логіці програми ніколи не спалить силовий інвертор двигуна і не скомпрометує криптографічні ключі.
