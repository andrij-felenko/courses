Автономний польовий давач на базі енергоефективного мікроконтролера споживає в режимі глибокого сну лише 1.8 мікроампера. Інженер закладає в розрахунок літій-тіонілхлоридну батарею (LiSOCl2) ємністю 2400 мА·год і очікує понад десять років безперервної автономної роботи. Проте після встановлення в полі вузол, який щоп'ять хвилин передає двадцять байтів телеметрії через радіомодуль, повністю вичерпує заряд батареї вже на четвертому місяці. Причиною такої катастрофічної розбіжності стає радіочастотний тракт: у момент активної передачі на максимальній потужності вихідний підсилювач споживає 120 міліамперів, а приймач під час прослуховування ефіру тягне ще 10 міліамперів.

У батарейних бездротових пристроях радіоканал є абсолютним монополістом у структурі енерговитрат: короткі сеанси роботи радіотрансивера спалюють від 99.5% до 99.9% усього доступного заряду. Зменшення струму сну процесора з 2 мкА до 1 мкА додає системі лічені тижні життя, тоді як скорочення тривалості кадру в ефірі або відмова від зайвого приймального вікна подвоює чи потроює термін автономності. Щоб створити пристрій, здатний працювати роками від одного хімічного елемента, інженер мусить розібрати енергетичну анатомію радіотранзакції, оптимізувати час перебування в ефірі (Time on Air), мінімізувати вікна прослуховування каналу та побудувати адаптивну систему керування потужністю і повторними спробами.

## Енергетична анатомія радіотранзакції: фази, струми та мілікулони

Сеанс радіозв'язку часто уявляють як миттєвий спалах передавача. На апаратному рівні будь-яка транзакція сучасного трансивера (наприклад, Semtech SX1262, TI CC1101 чи Nordic nRF52840) є строгою послідовністю перемикання внутрішніх блоків: синтезатора, підсилювача потужності, малошумного вхідного каскаду та демодулятора. Кожна фаза має свою тривалість і власний рівень споживання струму.

```
Фаза 1: Запуск опорного кварцу та PLL (1–2 мс, I = 4–7 мА)
   ↓
Фаза 2: Наростання та активна передача Tx (ToA: 5–1500 мс, I = 20–120 мА)
   ↓
Фаза 3: Пауза очікування відповіді (Міжфреймовий сон, I = 1.5 мкА)
   ↓
Фаза 4: Перше приймальне вікно RX1 (10–30 мс, I = 8–12 мА)
   ↓
Фаза 5: Друге приймальне вікно RX2 (за потреби, 10–30 мс, I = 8–12 мА)
   ↓
Фаза 6: Засинання в глибокий режим спокою (I = 0.1–1.5 мкА)
```

**1. Запуск опорного генератора та синтезатора частоти (PLL Lock).** Радіотракт не може почати випромінювання миттєво після отримання команди від мікроконтролера по шині SPI. Спочатку має стабілізуватися високочастотний кварцовий генератор (XOSC, зазвичай 32 МГц), після чого схема фазового автопідстроювання частоти (PLL, Phase-Locked Loop; від грец. *phasis* — поява, вигляд) фіксує несучу частоту передавача. Цей процес триває від 0.5 до 2.0 мс і вимагає постійного струму 4–7 мА. Якщо прошивка надсилає дані крихітними порціями по одному байту щохвилини, енергія на багаторазовий розгін PLL перевищить енергію корисної передачі.

**2. Активна передача (Tx Power Amplifier).** Вихідний підсилювач потужності (PA, Power Amplifier) генерує радіочастотне електромагнітне поле в антені. Струм споживання на цій фазі нелінійно залежить від вихідної потужності:

```
+0 дБм   (1 мВт):     I_tx ≈ 10–14 мА
+10 дБм  (10 мВт):    I_tx ≈ 18–25 мА
+14 дБм  (25 мВт):    I_tx ≈ 22–45 мА   (22 мА з внутрішнім DC-DC, 45 мА з LDO)
+20 дБм  (100 мВт):   I_tx ≈ 80–95 мА
+22 дБм  (160 мВт):   I_tx ≈ 118–130 мА
```

Архітектура перетворювача живлення всередині самого трансивера відіграє вирішальну роль. У застарілих чіпах внутрішнє живлення радіотракту регулювалося лінійним стабілізатором (LDO): уся надлишкова напруга батареї просто спалювалася на тепло, і струм від батареї дорівнював струму каскадів. У сучасних мікросхемах (як-от SX1262 чи STM32WL) інтегровано імпульсний знижувальний перетворювач (Step-Down DC-DC). При живленні від свіжої літієвої батареї (3.6 В) DC-DC перетворює високу напругу в нижчу з ККД понад 85%, зменшуючи споживаний від джерела струм удвічі (з 45 мА до 22 мА при +14 дБм).

**3. Приймальний тракт (Rx LNA та Baseband): пастка постійного слухання.** Поширена помилка розробника-початківця — вважати прийом «безкоштовним» порівняно з передачею. Під час прийому радіомодуль вмикає вхідний малошумний підсилювач (LNA, Low Noise Amplifier), квадратурні змішувачі частоти, смугові фільтри, швидкісні АЦП та цифровий сигнальний процесор (DSP) демодулятора. Сумарний струм прийому `I_rx` становить 8–15 мА.

Якщо передавач випромінює пачку за 50 мс при 40 мА, він забирає заряд `Q_tx = 40 мА · 0.05 с = 2.0 мА·с` (2 мілікулони). Якщо після цього приймач залишається слухати ефір упродовж однієї секунди при струмі 10 мА, він витратить `Q_rx = 10 мА · 1.0 с = 10.0 мА·с` — у п'ять разів більше, ніж уся передача! Постійно увімкнений приймач повністю спустошує пальчикову батарейку ємністю 2400 мА·год менш ніж за десять діб (`2400 / 10 = 240 годин = 10 днів`).

![Енергетична анатомія радіотранзакції: фази, струми та заряд кулонів](/root/course/embedded/radio-iak-holovnyi-spozhyvach/img/radio-transaction-phases.svg)
*Фазовий профіль струму радіотранзакції в часі: короткий запуск синтезатора (PLL), потужний сплеск передачі (Tx), паузи сну та короткі приймальні вікна (RX1/RX2). Інтеграл струму за часом (площа під кривою) показує, що 99.8% енергії зосереджено в радіокаскадах.*

### Інтеграл заряду та пікове просідання напруги

Повний електричний заряд `Q` (Кулони або міліампер-секунди), вилучений із джерела за одну радіотранзакцію, дорівнює площі під графіком струму в часі:

```
Q_транзакції = I_pll · t_pll  +  I_tx(P_out) · ToA  +  I_rx · t_rx  +  I_сон · t_сон
```

> 🔧 **Навіщо це.** Аналіз площі окремих фаз дозволяє негайно локалізувати головне джерело втрат. Якщо `I_tx · ToA` становить 85% усього заряду, необхідно зменшувати розмір корисного навантаження або збільшувати швидкість передачі. Якщо ж переважає `I_rx · t_rx`, проєкт страждає від надто довгих або несинхронізованих приймальних вікон.

Крім сумарного заряду, інженер стикається з проблемою **внутрішнього опору джерела живлення (ESR, Equivalent Series Resistance)**. Будь-яка батарея володіє власним послідовним опором `R_int`. Коли трансивер різко вмикає підсилювач потужності на +22 дБм і тягне імпульс `I_peak = 120 мА`, напруга на виводах батареї падає на величину:

```
ΔV = I_peak · R_int     [просідання напруги під навантаженням]
```

Для дискового літієвого елемента CR2032 внутрішній опір становить 15–30 Ом. Стрибок струму 120 мА викличе миттєве просідання на `0.12 А · 25 Ом = 3.0 В` — напруга тривольтової батарейки впаде майже до нуля, викликавши апаратне скидання мікроконтролера за зниженням напруги (Brown-Out Reset).

Для промислових елементів LiSOCl2 діє інший фізичний ефект — **пасивація** (англ. *passivation*; утворення тонкої плівки хлориду літію LiCl на аноді під час тривалого зберігання без струму). Плівка захищає батарею від саморозряду, знижуючи його до 1% на рік, але збільшує початковий опір до сотень ом. У перші мілісекунди після пробудження напруга може провалитися нижче порогу працездатності мікроконтролера, доки хімічна реакція не зруйнує шар пасивації. Щоб згладити ці імпульси, паралельно з батареєю встановлюють накопичувальні танталові конденсатори або гібридні іоністори (Pulse Capacitors) ємністю 100–1000 мкФ.

Строгі математичні залежності та формули розрахунку тривалості кожного каскаду зведені в [математичній моделі часу в ефірі та заряду транзакції](root:embedded/radio-iak-holovnyi-spozhyvach/math-toa-energy-model.md).

## Фізика часу в ефірі (Time on Air) та вартість переданого байта

Тривалість фізичного випромінювання радіокадру в простір називається часом у ефірі (Time on Air, ToA; від англ. *time on air* — ефірний час). Оскільки струм передавача під час випромінювання є постійним, витрачена на передачу енергія прямо пропорційна величині ToA:

```
E_tx = V_живлення · I_tx · ToA     [енергія передачі кадру, Джоулі]
```

У технологіях LPWAN (Low-Power Wide-Area Network — бездротові мережі великого радіуса дії з низьким енергоспоживанням) час у ефірі може різнитися в сотні разів залежно від обраного методу модуляції та параметрів кодування.

### Фізичний механізм розширення спектра LoRa

Модуляція LoRa використовує метод лінійного частотного розширення спектра (Chirp Spread Spectrum, CSS; від англ. *chirp* — щебет, сигнал зі змінною частотою). Інформація кодується символами, де кожен символ є радіоімпульсом, частота якого лінійно наростає від нижньої межі смуги `BW` до верхньої.

Тривалість одного символу `T_sym` жорстко прив'язана до коефіцієнта розширення спектра `SF` (Spreading Factor, від 7 до 12):

```
T_sym = 2^SF / BW     [тривалість символу LoRa]
```

Кожен крок збільшення `SF` на одиницю **подвоює** кількість чіпів у символі й рівно **вдвічі збільшує** тривалість передачі:

```
BW = 125 кГц:
SF7:   T_sym = 2⁷  / 125000 = 128  / 125000 = 1.024 мс
SF8:   T_sym = 2⁸  / 125000 = 256  / 125000 = 2.048 мс
SF9:   T_sym = 2⁹  / 125000 = 512  / 125000 = 4.096 мс
SF10:  T_sym = 2¹⁰ / 125000 = 1024 / 125000 = 8.192 мс
SF11:  T_sym = 2¹¹ / 125000 = 2048 / 125000 = 16.384 мс
SF12:  T_sym = 2¹² / 125000 = 4096 / 125000 = 32.768 мс
```

Збільшення SF дає виграш в енергетичній чутливості приймача (приймач на SF12 здатен декодувати сигнал під рівнем шуму на −20 дБ, тоді як на SF7 — лише на −7.5 дБ). Проте за ці додаткові 12.5 дБ радіолінії пристрій розплачується тривалістю перебування в ефірі.

*Порівняння тривалості перебування в ефірі (ToA) та витраченої енергії для пакета розміром 20 байтів: перехід від SF7 до SF12 збільшує витрату заряду у 24 рази, а в порівнянні з FSK — у 267 разів.*

### Практичні важелі мінімізації Time on Air

**1. Бінарне пакування корисного навантаження проти текстових форматів.** Типова помилка розробників, які прийшли з веб-технологій, — передача даних у текстовому форматі JSON або CSV:

```json
{"t":23.4,"h":65.2,"v":3.62}   ->  29 байтів корисного навантаження
```

На SF12 передача 29 байтів займає 1650 мс. Якщо перетворити ці поля на щільну бінарну структуру:
- Температура від −40.0 до +85.0 °C: ціле число `int16_t` у десяткових частках градуса (`234`) -> 2 байти.
- Відносна вологість 0..100%: ціле число `uint8_t` із кроком 0.5% (`130`) -> 1 байт.
- Напруга батареї від 2.00 до 3.60 В: `uint8_t` зі зміщенням 2000 мВ і кроком 10 мВ (`162` = 3620 мВ) -> 1 байт.
- Прапорці стану (помилка сенсора, тривога): `uint8_t` бітова маска -> 1 байт.
- **Сумарний обсяг: 5 байтів замість 29 байтів.**

На SF12 кадр обсягом 5 байтів передається за 990 мс замість 1650 мс. Скорочення навантаження лише на 24 байти заощаджує 660 мс роботи передавача на кожній відправці, зменшуючи витрату заряду на 40%.

**2. Агрегація та пакетування замість частих дрібних відправок (Batching).** Кожен кадр тягне за собою накладні витрати: преамбулу (8–12 символів), службовий заголовок, контрольні суми та запуск синтезатора PLL.
- Якщо передавати 1 вимір (5 байтів) щоп'ять хвилин, за годину вузол виконає 12 транзакцій. Загальний час увімкненого радіо на SF10: `12 · 280 мс = 3.36 секунди`.
- Якщо накопичувати виміри в локальній RAM і передавати один зведений пакет із 12 точок телеметрії (60 байтів) раз на годину, час передачі одного великого кадру становитиме лише 740 мс.
- **Виграш від агрегації: скорочення активного часу радіо в 4.5 раза.**

**3. Динамічний вибір надлишковості FEC (Coding Rate).** Пряма корекція помилок (FEC) додає до даних надлишкові біти для виправлення спотворень у каналі:
- `CR = 4/5` (коефіцієнт 1.25): додає 25% надлишковості.
- `CR = 4/8` (коефіцієнт 2.00): подвоює кількість бітів у корисній частині кадру.
Використання максимального кодування `CR = 4/8` виправдане лише в умовах жорстких промислових завад; у чистому ефірі це марна витрата 35–40% енергії.

## Стратегії прийому: мінімізація вікон прослуховування ефіру

У бездротових сенсорних мережах потік даних майже завжди асиметричний: 95% трафіку рухається від сенсора до сервера (Uplink), і лише 5% становлять команди конфігурації, запити статусу або підтвердження доставки (Downlink). Постійно тримати приймач увімкненим заради цих рідкісних команд неможливо. Для вирішення цієї дилеми розроблено три фундаментальні стратегії координації приймальних вікон.

### 1. Подієво-синхронізовані вікна (LoRaWAN Class A)

Архітектура LoRaWAN Class A реалізує принцип суворо асиметричного зв'язку: **кінцевий пристрій ніколи не слухає ефір першим**.

```
Uplink Tx (кінець передачі)
   │
   ├── [RECEIVE_DELAY1 = 1.0 с — глибокий сон 1.5 мкА] ──→ Вікно RX1 (15–20 мс)
   │                                                         │
   │                                                         └── Немає преамбули → Сон
   │
   └── [RECEIVE_DELAY2 = 2.0 с — глибокий сон 1.5 мкА] ──→ Вікно RX2 (15–20 мс)
                                                             │
                                                             └── Немає преамбули → Сон
```

Пристрій прокидається за таймером рівно через 1.000 с після закінчення власної передачі й вмикає приймач на тій самій частоті та з тим самим SF, що й вихідний пакет (вікно RX1). Якщо шлюз надіслав відповідь, приймач її захоплює. Якщо впродовж перших 5–8 символів преамбули кореляційний детектор не фіксує сигналу, трансивер негайно вимикається за таймаутом і знову засинає. Через 2.000 с процес повторюється на резервній фіксованій частоті (вікно RX2, у Європі 869.525 МГц, SF9).

Завдяки швидкому детектуванню відсутності преамбули сумарна тривалість роботи приймача не перевищує 30–40 мс на весь цикл транзакції. Середній струм прийому при відправці раз на годину становить:

```
I_rx_сер = 10 мА · (0.030 с / 3600 с) = 0.000083 мА = 0.083 мкА
```

Це дозволяє пристрою функціонувати від однієї батарейки понад 10 років. Плата за таку енергоощадність — затримка: сервер не може передати команду на датчик у довільний момент, він змушений чекати чергового планового виходу вузла на зв'язок.

![Порівняння трьох стратегій прослуховування ефіру](/root/course/embedded/radio-iak-holovnyi-spozhyvach/img/rx-strategies-comparison.svg)
*Порівняння стратегій прослуховування ефіру: постійний прийом вичерпує батарею за 8 днів; подієві вікна LoRaWAN Class A забезпечують до 10 років автономності; метод вибірки преамбули (Sniff Mode) дає компроміс між затримкою та енергоспоживанням.*

### 2. Періодична вибірка преамбули (Preamble Sampling / Sniff Mode / WOR)

У пропрієтарних Sub-GHz протоколах і mesh-мережах часто необхідна низька затримка доставки команд (менше однієї секунди) без прив'язки до вихідних повідомлень. Тут застосовують техніку вибірки преамбули (Preamble Sampling або Low Power Listening, LPL; у чіпах CC1101 відома як Wake-on-Radio, WOR):

1. **Поведінка приймача:** Приймач 99.8% часу спить. Внутрішній надмалопотужний RC-таймер будить трансивер кожні `T_sleep` (наприклад, 500 мс). Приймач вмикається в режим швидкого аналізу несучої (Channel Activity Detection, CAD, або швидке вимірювання RSSI) лише на 0.5–1.0 мс.
2. Якщо рівень сигналу нижчий за поріг завад, чіп миттєво засинає.
3. **Поведінка передавача:** Коли центральному вузлу потрібно надіслати команду, він формує пакет із **штучно подовженою преамбулою**, тривалість якої гарантовано перевищує період сну приймача (`t_preamble >= T_sleep = 500 мс`).
4. Під час чергового секундного пробудження приймач гарантовано потрапляє у довгу преамбулу, розпізнає сигнал, залишається активним і приймає корисний кадр.

Цей підхід перекладає енергетичний тягар із приймача на передавач. Приймач споживає середній струм близько 20–30 мкА (що дає 3–5 років від батареї AA), забезпечуючи максимальну затримку реакції на команду не більше пів секунди.

### 3. Пейджинг та енергозбереження у стільникових мережах (eDRX та PSM)

У стільникових технологіях інтернету речей (NB-IoT, LTE-M) застосовують два стандартизовані 3GPP-механізми:
- **PSM (Power Saving Mode):** Модуль повністю вимикає радіотракт і входить у глибокий сон зі струмом 3–5 мкА на час до кількох тижнів (таймер T3412). При цьому він залишається зареєстрованим у базовій станції без потреби проходити повторну важку процедуру автентифікації при пробудженні. Під час PSM пристрій абсолютно недосяжний для вхідних пакетів.
- **eDRX (extended Discontinuous Reception):** Компромісний режим, у якому модуль циклічно прокидається у вузьких пейджингових вікнах (Paging Time Window, PTW) тривалістю кілька мілісекунд раз на 10–40 секунд, щоб перевірити наявність вхідних дзвінків чи даних від мережі.

## Повторні спроби (Retransmissions), колізії та адаптивне керування (ADR / TPC)

Найгірше, що може статися з бюджетом живлення автономного пристрою, — це потрапляння в неконтрольований цикл повторних відправок (Retransmissions) на максимальній потужності та найнижчій швидкості.

### Енергетична ціна підтверджених повідомлень (Confirmed Uplinks)

У протоколах передачі розрізняють непідтверджені кадри (Unconfirmed, відправка «вистрілив і забув») та підтверджені (Confirmed, очікування кадру ACK від шлюзу).

Якщо пристрій надсилає Confirmed-пакет, а шлюз не зміг відповісти (через колізію в ефірі або власні обмеження регуляторного дюті-циклу), стек повторює спробу:

```
Спроба 1 (SF12, +20 дБм):  ToA = 1.5 с, I = 100 мА  ->  Q₁ = 150 мА·с
   ↓ (немає ACK)
Спроба 2 (SF12, +20 дБм):  ToA = 1.5 с, I = 100 мА  ->  Q₂ = 150 мА·с
   ↓ (немає ACK)
Спроба 3 (SF12, +20 дБм):  ToA = 1.5 с, I = 100 мА  ->  Q₃ = 150 мА·с
   ↓
Сумарний заряд на 1 повідомлення:  Q_сума = 450 мА·с (450 мілікулонів!)
```

Усього три повторні передачі на SF12 споживають заряд, якого вистачило б на **160 успішних передач** на швидкості SF7. Якщо зв'язок погіршився капітально, наївний алгоритм повторів здатний «висадити» річний запас батареї за пару тижнів.

Крім того, у бездротових мережах без синхронізації слотів діє закон колізій чистого протоколу ALOHA. Ймовірність колізії `P_coll` зростає експоненційно зі збільшенням навантаження каналу `G`:

```
P_coll = 1 - e^(-2 · G)     [ймовірність колізії в чистому ALOHA]
```

Чим довше пакети висять у повітрі (високий ToA на SF12), тим вища ймовірність їх взаємного накладання та колізії, що провокує лавину повторних передач і колапс пропускної здатності всієї мережі.

### Адаптивна швидкість передачі даних (Adaptive Data Rate, ADR)

Для розв'язання цієї проблеми в LPWAN впроваджено механізм адаптивної швидкості (ADR, Adaptive Data Rate). Це замкнений контур керування між вузлом та сервером мережі:

![Замкнений контур адаптивної швидкості та оптимізації потужності](/root/course/embedded/radio-iak-holovnyi-spozhyvach/img/adr-loop-dynamics.svg)
*Замкнений контур керування ADR/TPC: сервер мережі аналізує якість каналу й передає команди зниження SF та потужності, а алгоритм відкату (fallback) гарантує відновлення зв'язку при погіршенні умов.*

**Алгоритм роботи контуру ADR:**
1. Вузол передає стандартні аплінки з прапорцем `ADR = 1`.
2. Шлюзи вимірюють відношення сигнал/шум (SNR) та рівень потужності (RSSI) для останніх `N = 20` отриманих пакетів.
3. Сервер обчислює запас радіолінії (Link Margin):
   ```
   Margin = max(SNR_20) − SNR_req(SF) − Margin_safe
   ```
   де `SNR_req` — мінімальний поріг демодуляції для поточного SF (−7.5 дБ для SF7, −20 дБ для SF12), а `Margin_safe` — захисний резерв на швидкі завмирання (типово 10 дБ).
4. Якщо `Margin > 3 дБ`, сервер надсилає в низхідному кадрі MAC-команду `LinkADRReq`:
   - Підвищити Data Rate (перейти з SF12 на SF10, а потім на SF7), що скорочує ToA у рази.
   - Знизити потужність передавача `P_tx` (наприклад, з +14 дБм до +2 дБм), якщо запас залишається позитивним.
5. **Механізм захисту від обриву (ADR Fallback):** Якщо вузол не отримував жодної відповіді від сервера впродовж `ADR_ACK_LIMIT` передач (стандартно 64 пакети), він починає встановлювати біт вимоги підтвердження `ADRACKReq = 1`. Якщо відповіді немає ще впродовж `ADR_ACK_DELAY` кроків (32 пакети):
   - Спочатку потужність `P_tx` збільшується до максимуму (+14..+20 дБм).
   - Якщо зв'язок не відновився, вузол покроково збільшує коефіцієнт розширення (`SF7 -> SF8 -> ... -> SF12`), відновлюючи дальність ціною тимчасового зростання енерговитрат.

### Програмне керування потужністю (Tx Power Scaling / TPC)

Випромінювання на максимальній потужності +20 дБм (85–120 мА) у ситуації, коли шлюз розташований за двісті метрів у зоні прямої видимості, є чистим марнотратством. Зниження потужності передавача до +2 дБм (1.6 мВт) зменшує струм споживання мікросхеми з 85 мА до 15 мА (більш ніж уп'ятеро), усуваючи зайвий розряд і не створюючи завад сусіднім вузлам мережі.

## Практичний енергоефективний менеджер радіопередачі (C та C++)

Спроєктуємо закінчений програмний модуль менеджера радіопередачі (`RadioEnergyManager`), який втілює всі описані принципи:
1. **Компактне бінарне пакування:** телеметрія пакується в 5 байтів за допомогою бітових полів без накладних витрат.
2. **Детермінований скінченний автомат фаз:** відстежує стан радіотракту та розраховує витрачені мілікулони на кожну транзакцію в реальному часі.
3. **Експоненційний відкат та адаптація:** керує лічильником спроб і автоматично коригує потужність випромінювання та швидкість модуляції.

```c
/* ============================================================================
 * Енергоефективний менеджер радіотранзакцій (ANSI C99 / Вбудовані системи)
 * ============================================================================ */
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define RF_MAX_RETRIES        3
#define RF_ADR_ACK_LIMIT      64
#define RF_ADR_ACK_DELAY      32

typedef enum {
    RF_STATE_SLEEP = 0,
    RF_STATE_WARMUP_PLL,
    RF_STATE_TRANSMITTING,
    RF_STATE_WAIT_RX1,
    RF_STATE_LISTEN_RX1,
    RF_STATE_WAIT_RX2,
    RF_STATE_LISTEN_RX2
} rf_state_t;

typedef enum {
    LORA_SF7 = 7,
    LORA_SF8 = 8,
    LORA_SF9 = 9,
    LORA_SF10 = 10,
    LORA_SF11 = 11,
    LORA_SF12 = 12
} lora_sf_t;

/* Щільне бінарне представлення корисного навантаження (рівно 5 байтів) */
#pragma pack(push, 1)
typedef struct {
    int16_t  temp_centi_deg;   /* Температура в 0.01 °C (-327.68 .. +327.67) */
    uint8_t  humidity_half_pct;/* Відносна вологість у 0.5% (0 .. 200 = 100%) */
    uint8_t  battery_raw_mv;   /* Напруга: (V - 2000) / 10 мВ (2.00 .. 4.55 В) */
    uint8_t  status_flags;     /* Бітові прапорці: D0=помилка сенсора, D1=ADR_ACK */
} telemetry_payload_t;
#pragma pack(pop)

typedef struct {
    rf_state_t  state;
    lora_sf_t   current_sf;
    int8_t      tx_power_dbm;
    uint32_t    tx_count;
    uint32_t    adr_ack_counter;
    uint32_t    total_coulombs_uc; /* Лічильник витраченого заряду в мікрокулонах */
    uint8_t     retry_count;
} rf_energy_manager_t;

void rf_manager_init(rf_energy_manager_t *mgr) {
    mgr->state = RF_STATE_SLEEP;
    mgr->current_sf = LORA_SF7;       /* Стартуємо з найбільш енергоощадного режиму */
    mgr->tx_power_dbm = 14;           /* Стандартні +14 дБм (25 мВт) */
    mgr->tx_count = 0;
    mgr->adr_ack_counter = 0;
    mgr->total_coulombs_uc = 0;
    mgr->retry_count = 0;
}

/* Пакування телеметрії у фіксовані 5 байтів */
uint8_t rf_manager_pack_telemetry(float temp_c, float hum_pct, float v_batt, 
                                  bool sensor_ok, uint8_t *out_buf, uint8_t max_len) {
    if (max_len < sizeof(telemetry_payload_t)) return 0;

    telemetry_payload_t payload;
    payload.temp_centi_deg = (int16_t)(temp_c * 100.0f);
    
    if (hum_pct < 0.0f) hum_pct = 0.0f;
    if (hum_pct > 100.0f) hum_pct = 100.0f;
    payload.humidity_half_pct = (uint8_t)(hum_pct * 2.0f);

    uint32_t mv = (uint32_t)(v_batt * 1000.0f);
    if (mv < 2000) mv = 2000;
    if (mv > 4550) mv = 4550;
    payload.battery_raw_mv = (uint8_t)((mv - 2000) / 10);

    payload.status_flags = sensor_ok ? 0x00 : 0x01;

    memcpy(out_buf, &payload, sizeof(telemetry_payload_t));
    return (uint8_t)sizeof(telemetry_payload_t);
}

/* Оцінка заряду та перехід до передачі */
void rf_manager_start_tx(rf_energy_manager_t *mgr, uint32_t toa_ms) {
    mgr->state = RF_STATE_TRANSMITTING;
    mgr->tx_count++;
    mgr->adr_ack_counter++;

    /* Оцінка струму Tx залежно від потужності (для чіпа з DC-DC, як SX1262) */
    uint32_t current_ma = 22; /* Базовий струм при +14 дБм */
    if (mgr->tx_power_dbm >= 20) current_ma = 95;
    else if (mgr->tx_power_dbm <= 2) current_ma = 12;

    /* Q = I * t (мікрокулони = мА * мс) */
    mgr->total_coulombs_uc += (current_ma * toa_ms) + (5 * 2); /* + запуск PLL */
}

/* Обробка успішного отримання підтвердження (Downlink ACK) */
void rf_manager_on_ack_received(rf_energy_manager_t *mgr, int8_t gateway_snr) {
    mgr->adr_ack_counter = 0;
    mgr->retry_count = 0;
    mgr->state = RF_STATE_SLEEP;

    /* Локальна оптимізація потужності: якщо сигнал чудовий, зменшуємо потужність */
    if (gateway_snr > 8 && mgr->tx_power_dbm > 2) {
        mgr->tx_power_dbm -= 3; /* Знижуємо на 3 дБ (у 2 рази по випромінюванню) */
    }
}

/* Обробка втрати зв'язку (ADR Fallback) */
void rf_manager_on_tx_timeout(rf_energy_manager_t *mgr) {
    if (mgr->retry_count < RF_MAX_RETRIES) {
        mgr->retry_count++;
        /* Експоненційний відкат або негайний перехід у сон */
        mgr->state = RF_STATE_SLEEP;
        return;
    }

    /* Якщо досягнуто ліміту ADR без відповідей — покроковий fallback */
    if (mgr->adr_ack_counter >= (RF_ADR_ACK_LIMIT + RF_ADR_ACK_DELAY)) {
        if (mgr->tx_power_dbm < 20) {
            mgr->tx_power_dbm = 20; /* Спочатку викручуємо потужність на максимум */
        } else if (mgr->current_sf < LORA_SF12) {
            mgr->current_sf = (lora_sf_t)(mgr->current_sf + 1); /* Збільшуємо SF */
            mgr->adr_ack_counter = RF_ADR_ACK_LIMIT; /* Скидаємо для наступного кроку */
        }
    }
    mgr->retry_count = 0;
    mgr->state = RF_STATE_SLEEP;
}
```

```cpp
// ============================================================================
// Енергоефективний менеджер радіотранзакцій (C++20 / RAII та Strict Types)
// ============================================================================
#include <cstdint>
#include <array>
#include <span>
#include <chrono>
#include <algorithm>

namespace embedded::radio {

using namespace std::chrono_literals;

enum class SpreadingFactor : uint8_t {
    SF7 = 7, SF8 = 8, SF9 = 9, SF10 = 10, SF11 = 11, SF12 = 12
};

enum class State : uint8_t {
    Sleep,
    WarmupPll,
    Transmitting,
    WaitRx1,
    ListenRx1,
    WaitRx2,
    ListenRx2
};

#pragma pack(push, 1)
struct TelemetryFrame {
    int16_t  temp_centi_deg;
    uint8_t  humidity_half_pct;
    uint8_t  battery_raw_mv;
    uint8_t  status_flags;

    static constexpr size_t Size = 5;
};
#pragma pack(pop)

class EnergyAwareRadioManager {
public:
    static constexpr uint8_t MaxRetries = 3;
    static constexpr uint32_t AdrAckLimit = 64;
    static constexpr uint32_t AdrAckDelay = 32;

    EnergyAwareRadioManager() = default;

    [[nodiscard]] std::array<uint8_t, TelemetryFrame::Size> pack_telemetry(
        float temp_c, float hum_pct, float v_batt, bool sensor_ok) const noexcept 
    {
        std::array<uint8_t, TelemetryFrame::Size> buffer{};
        TelemetryFrame frame{
            .temp_centi_deg = static_cast<int16_t>(temp_c * 100.0f),
            .humidity_half_pct = static_cast<uint8_t>(std::clamp(hum_pct, 0.0f, 100.0f) * 2.0f),
            .battery_raw_mv = static_cast<uint8_t>((std::clamp(static_cast<uint32_t>(v_batt * 1000.0f), 2000u, 4550u) - 2000) / 10),
            .status_flags = static_cast<uint8_t>(sensor_ok ? 0x00 : 0x01)
        };
        std::copy_n(reinterpret_cast<const uint8_t*>(&frame), TelemetryFrame::Size, buffer.begin());
        return buffer;
    }

    void start_transmission(std::chrono::milliseconds toa) noexcept {
        state_ = State::Transmitting;
        ++tx_count_;
        ++adr_ack_counter_;

        const uint32_t current_ma = (tx_power_dbm_ >= 20) ? 95 : ((tx_power_dbm_ <= 2) ? 12 : 22);
        total_microcoulombs_ += (current_ma * static_cast<uint32_t>(toa.count())) + (5 * 2);
    }

    void handle_ack(int8_t gateway_snr) noexcept {
        adr_ack_counter_ = 0;
        retry_count_ = 0;
        state_ = State::Sleep;

        if (gateway_snr > 8 && tx_power_dbm_ > 2) {
            tx_power_dbm_ -= 3;
        }
    }

    void handle_timeout() noexcept {
        if (retry_count_ < MaxRetries) {
            ++retry_count_;
            state_ = State::Sleep;
            return;
        }

        if (adr_ack_counter_ >= (AdrAckLimit + AdrAckDelay)) {
            if (tx_power_dbm_ < 20) {
                tx_power_dbm_ = 20;
            } else if (sf_ != SpreadingFactor::SF12) {
                sf_ = static_cast<SpreadingFactor>(static_cast<uint8_t>(sf_) + 1);
                adr_ack_counter_ = AdrAckLimit;
            }
        }
        retry_count_ = 0;
        state_ = State::Sleep;
    }

    [[nodiscard]] SpreadingFactor spreading_factor() const noexcept { return sf_; }
    [[nodiscard]] int8_t tx_power() const noexcept { return tx_power_dbm_; }
    [[nodiscard]] uint64_t total_charge_uc() const noexcept { return total_microcoulombs_; }
    [[nodiscard]] State current_state() const noexcept { return state_; }

private:
    State state_{State::Sleep};
    SpreadingFactor sf_{SpreadingFactor::SF7};
    int8_t tx_power_dbm_{14};
    uint32_t tx_count_{0};
    uint32_t adr_ack_counter_{0};
    uint64_t total_microcoulombs_{0};
    uint8_t retry_count_{0};
};

} // namespace embedded::radio
```

   - [ ] Чи прибрано надлишкові байти вирівнювання за допомогою `#pragma pack(1)`?

   - [ ] Чи налаштовано мінімально допустиму довжину преамбули (8 символів для LoRa, 4 байти для FSK)?
   - [ ] Чи налаштовано мінімальний коефіцієнт корекції помилок (`CR = 4/5`) для стабільного радіоканалу?

3. **Дисципліна приймальних вікон (Rx Strategy):**
   - [ ] Чи вимкнено постійне прослуховування ефіру?
   - [ ] Чи реалізовано подієвий прийом (LoRaWAN Class A) або швидку вибірку преамбули (Sniff Mode із тривалістю активності < 1 мс)?
