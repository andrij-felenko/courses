# Чип бреше: правдоподібні хибні дані

- [Бітові операції в C/C++](root:embedded/c-bit-operations) — порозрядні зсуви `<<` та `>>`, маскування через `&`, об'єднання через `|` та виділення бітових полів.
- [SPI проти I2C](root:embedded/spi-vs-i2c) — принципи тактування, кадрування, полярність і фаза такту (CPOL/CPHA), розпізнавання адрес і байтів даних.
- [Регістрова карта](root:com-devices/register-map) — організація пам'яті мікросхеми, 8-бітні комірки та збереження результатів вимірювань у мультибайтних регістрах.
</preknowlist>

Ви підключаєте цифровий давач — наприклад, триосьовий акселерометр, барометр чи прецизійний термометр — до мікроконтролера по шині I2C або SPI. Обмін сигналами бездоганний: лінія підтвердження I2C ACK видає низький рівень на кожен переданий байт, транзакція SPI завершується без апаратних помилок, а читання регістра ідентифікатора `WHO_AM_I` слухняно повертає очікуване значення `0x68`. Електрична лінія жива, логічний аналізатор фіксує коректні протокольні кадри. Проте числа, які програма зчитує з регістрів даних, виглядають абсурдно: кімнатна температура 24 °C після дотику пальцем стрибає до 6144 °C або падає до −180 °C; нерухомий акселерометр показує прискорення вільного падіння 16 g замість 1 g; плавний підйом барометра на висоту супроводжується миттєвими провалами показу на 256 метрів.

Чип не зламаний і не генерує випадковий шум навмисно — кремнієвий кристал чесно віддає бінарний стан своїх внутрішніх регістрів. Проблема виникає на стику між тим, як вимірювальний перетворювач запакував фізичну величину у кремнії, і тим, як мікроконтролер розпакував отримані байти у своїй пам'яті. Це класичний стан «чип бреше»: формальний зв'язок працює, але дані спотворені через неузгодженість правил інтерпретації.

Спотворення виникають у п'яти конкретних вузлах обробки:
1. **Порядок байтів (Endianness):** старший і молодший байти переплутані місцями під час зшивання 16-бітного, 20-бітного чи 24-бітного слова.
2. **Формат представлення чисел (Sign Extension):** знаковий біт від'ємного числа у додатковому коді втрачається або не розмножується на старші розряди процесорного регістра.
3. **Порушення когерентності (Torn Read):** асинхронне оновлення регістра давачем розриває атомарність між роздільними зверненнями до старшого й молодшого байтів.
4. **Зсув бітів на шині (SPI Clock Phase):** вибірка сигналу не на тому фронті тактового імпульсу зсуває весь бітовий потік ліворуч або праворуч.
5. **Деградація фронтів (Signal Integrity):** дзвоніння на довгих лініях створює фальшиві тактові імпульси, що впорскують паразитні біти в приймальний зсувний регістр.

## Війна порядків байтів: Big-Endian сенсора проти Little-Endian ядра

Переважна більшість цифрових давачів на ринку (акселерометри Bosch BMA/BMI, магнетометри InvenSense/TDK MPU, барометри ST LPS) проєктувалися з огляду на послідовну передачу старшим бітом уперед (MSB First). У їхній внутрішній регістровій карті молодша адреса комірки зазвичай містить старший байт результату вимірювання (H), а наступна адреса — молодший байт (L). Такий порядок є прямим ([Big-Endian](root:sf-algorithms/bits-bytes-endianness)): найвагоміша частина числа розташована за молодшою адресою.

Ядра архітектури ARM Cortex-M (STM32, NXP LPC, ESP32, Nordic nRF, RP2040) за замовчуванням працюють у зворотному порядку ([Little-Endian](root:sf-algorithms/bits-bytes-endianness)): молодший байт 16-бітного чи 32-бітного числа завжди розташовується за молодшою адресою пам'яті.

Коли прошивка наївно читає два байти з шини I2C у буфер пам'яті `uint8_t buf[2]` (де `buf[0]` прийняв старший байт H, а `buf[1]` — молодший байт L), а потім виконує небезпечне приведення вказівника `*(uint16_t*)buf`, процесор читає `buf[0]` як молодший байт числа, а `buf[1]` — як старший. Байти міняються ролями:

```
Справжнє значення:   V_true = (H << 8) | L
Прочитане процесором: V_swap = (L << 8) | H
```

Ця помилка не перетворює сигнал на нуль. Вона породжує підступну спотворену функцію.

```
H = 1 (0x01),  L = 128 (0x80)  →  V_true = 256 + 128 = 384 відліки (24.0 °C)
Зшивання swap: (128 << 8) | 1  →  V_swap = 32768 + 1  = 32769 відліків (2048.0 °C!)
```

Коли температура плавно зростає на 1 LSB (L = 129), справжнє значення стає 385, а перевернуте число перетворюється на `(129 << 8) | 1 = 33025`. Різниця між двома сусідніми вимірюваннями становить не 1, а рівно 256 відліків.

Коли ж молодший байт досягає значення 255 (`0xFF`) і переповнюється в 0 (`0x00`), а старший байт збільшується на одиницю (H = 2), перевернуте число миттєво обвалюється: замість 512 (`0x0200`) програма бачить `(0 << 8) | 2 = 2`.

![Перевернутий порядок байтів (MSB/LSB swap): вигляд спотвореного сигналу](/root/course/embedded/chyp-breshe/img/endianness-sawtooth.svg)
*Плавний фізичний процес при переплутаних байтах MSB/LSB розпадається на пилкоподібну функцію зі стрибками по 256 LSB на кожен крок молодшого байта.*

Графік сигналу набуває характерного «пилкоподібного» вигляду з гігантськими вертикальними сходинками. Давач реагує на нагрівання чи рух, але амплітуда коливань перевищує реальну у сотні разів.

### Порядок байтів у 24-бітних та 32-бітних перетворювачах

У барометрах високої точності (Bosch BMP280/BMP388, ST LPS22HB) та прецизійних сигма-дельта АЦП (ADS1220, HX711) результат вимірювання займає 24 біти й передається трьома послідовними байтами: `[MSB, CSB, LSB]` (старший, середній та молодший байти).

Якщо розробник помилково вважає порядок Little-Endian і зшиває 24-бітне слово як `((uint32_t)b[0]) | ((uint32_t)b[1] << 8) | ((uint32_t)b[2] << 16)`, коефіцієнт спотворення виростає до 2¹⁶ = 65536 на кожен крок молодшого байта. Сигнал перетворюється на абсолютно хаотичний шум, у якому практично неможливо впізнати фізичний процес без осцилографа чи аналізатора протоколів.

Деякі чипи (наприклад, Bosch BMP280) використовують нестандартне 20-бітне пакування тиску: старший байт `0xF7` містить біти `[19:12]`, середній `0xF8` — біти `[11:4]`, а молодший `0xF9` (XLSB) — біти `[3:0]`, розташовані у старших чотирьох розрядах байта (`xlsb >> 4`). Якщо проігнорувати специфікацію і прочитати ці три байти як стандартне 24-бітне ціле, вихідний тиск буде спотворений рівно у 16 разів (через невикористаний зсув на 4 біти в молодшому регістрі).

### Правильне зшивання байтів у коді

Для усунення помилки збирання багатобайтного слова має бути явно визначене за правилами цілочисельної арифметики без прив'язки до внутрішнього порядку байтів мікроконтролера.

:::tabs
```c
#include <stdint.h>

// Безпечне складання 16-бітного Big-Endian слова з двох байтів
int16_t parse_be16_signed(const uint8_t bytes[2]) {
    // bytes[0] - старший байт (MSB), bytes[1] - молодший байт (LSB)
    uint16_t raw_unsigned = ((uint16_t)bytes[0] << 8) | (uint16_t)bytes[1];
    return (int16_t)raw_unsigned;
}

// Безпечне складання 16-бітного Little-Endian слова (наприклад, для давачів Bosch)
int16_t parse_le16_signed(const uint8_t bytes[2]) {
    // bytes[0] - молодший байт (LSB), bytes[1] - старший байт (MSB)
    uint16_t raw_unsigned = ((uint16_t)bytes[1] << 8) | (uint16_t)bytes[0];
    return (int16_t)raw_unsigned;
}

// Розпакування 24-бітного Big-Endian знакового числа (прецизійний АЦП)
int32_t parse_be24_signed(const uint8_t bytes[3]) {
    // Збираємо 24 біти у верхні розряди 32-бітного слова, потім арифметично зсуваємо
    uint32_t raw_24 = ((uint32_t)bytes[0] << 24) |
                      ((uint32_t)bytes[1] << 16) |
                      ((uint32_t)bytes[2] << 8);
    return (int32_t)raw_24 >> 8; // Арифметичний зсув автоматично розмножує знак
}

// Розпакування 20-бітного тиску Bosch BMP280 (MSB, LSB, XLSB[7:4])
uint32_t parse_bmp280_pressure_raw(const uint8_t bytes[3]) {
    uint32_t msb = (uint32_t)bytes[0];
    uint32_t lsb = (uint32_t)bytes[1];
    uint32_t xlsb = (uint32_t)bytes[2] >> 4;
    return (msb << 12) | (lsb << 4) | xlsb;
}

// Використання апаратної інструкції перевороту байтів REV16 процесора ARM
int16_t parse_be16_fast(uint16_t raw_from_bus) {
    return (int16_t)__builtin_bswap16(raw_from_bus);
}
```
```cpp
#include <cstdint>
#include <bit>
#include <span>

// Типобезпечний розбір 16-бітного Big-Endian слова через std::span
constexpr int16_t parse_be16_signed(std::span<const uint8_t, 2> bytes) noexcept {
    const auto raw_unsigned = static_cast<uint16_t>((static_cast<uint16_t>(bytes[0]) << 8) |
                                                     static_cast<uint16_t>(bytes[1]));
    return static_cast<int16_t>(raw_unsigned);
}

// Типобезпечний розбір 16-бітного Little-Endian слова
constexpr int16_t parse_le16_signed(std::span<const uint8_t, 2> bytes) noexcept {
    const auto raw_unsigned = static_cast<uint16_t>((static_cast<uint16_t>(bytes[1]) << 8) |
                                                     static_cast<uint16_t>(bytes[0]));
    return static_cast<int16_t>(raw_unsigned);
}

// Розпакування 24-бітного знакового значення через 32-бітний зсув
constexpr int32_t parse_be24_signed(std::span<const uint8_t, 3> bytes) noexcept {
    const auto raw_shifted = (static_cast<uint32_t>(bytes[0]) << 24) |
                             (static_cast<uint32_t>(bytes[1]) << 16) |
                             (static_cast<uint32_t>(bytes[2]) << 8);
    return static_cast<int32_t>(raw_shifted) >> 8;
}

// Розпакування 20-бітного формату BMP280
constexpr uint32_t parse_bmp280_pressure_raw(std::span<const uint8_t, 3> bytes) noexcept {
    const auto msb = static_cast<uint32_t>(bytes[0]);
    const auto lsb = static_cast<uint32_t>(bytes[1]);
    const auto xlsb = static_cast<uint32_t>(bytes[2]) >> 4;
    return (msb << 12) | (lsb << 4) | xlsb;
}

// Сучасний розбір за допомогою std::byteswap (C++23)
template <typename T>
constexpr T from_big_endian(T value) noexcept {
    if constexpr (std::endian::native == std::endian::little) {
        return std::byteswap(value);
    }
    return value;
}
```

Пряме приведення вказівників `*(uint16_t*)buf` суворо заборонене не лише через конфлікт Endianness, але й через порушення правила суворого псевдонімування (Strict Aliasing Rule) та ризик несинхронізованого доступу (Unaligned Memory Access). На ядрах Cortex-M0/M0+ спроба прочитати 16-бітне число з непарної адреси пам'яті негайно викликає апаратне виключення `HardFault`.

## Додатковий код, знакове розширення та дробові формати

Більшість АЦП у сучасних давачах формують вихідний код у додатковому коді ([Two's Complement](root:sf-algorithms/bits-bytes-endianness)). Це дозволяє природно представляти додатні й від'ємні величини (прискорення вперед/назад, температуру вище/нижче нуля) без використання окремого прапорця знака.

Головна пастка полягає в тому, що розрядність внутрішнього АЦП давача часто не дорівнює 16 бітам. Виробники використовують 10-, 12- або 14-бітні перетворювачі, запаковуючи їх у пару 8-бітних регістрів.

Існує два способи пакування таких даних у 16-бітному слові:
1. **Вирівнювання праворуч (Right-aligned / LSB-aligned):** 12-бітний результат займає біти `[11:0]`, а біти `[15:12]` заповнені нулями.
2. **Вирівнювання ліворуч (Left-aligned / MSB-aligned):** 12-бітний результат займає біти `[15:4]`, а біти `[3:0]` містять нулі або фіксовані прапорці.

Розгляньмо, що стається при правому вирівнюванні 12-бітного давача. Знаковий біт такого числа міститься на позиції біта 11 (2¹¹ = 2048).

Якщо температура опускається нижче нуля і становить -1 LSB, 12-бітний АЦП видає двійковий код `1111 1111 1111` (`0x0FFF`). Старші 4 біти 16-бітного регістра залишаються нульовими: `0000 1111 1111 1111`.

Якщо програма збереже це число у змінну типу `int16_t` без додаткової обробки, процесор сприйме біт 15 як нуль (додатне число). Значення `0x0FFF` буде інтерпретовано як +4095 відліків замість -1.

![Пастка знакового розширення: 12-бітний додатковий код у 16-бітному слові](/root/course/embedded/chyp-breshe/img/sign-extension-trap.svg)
*Якщо знаковий біт (MSB 12-бітного відліку) не скопіювати на всі старші розряди цілочисельного типу, від'ємні значення у додатковому коді перетворюються на гігантські додатні сплески.*

Щоб від'ємне число зберегло своє значення при переході з меншої розрядності (N бітів) у більшу (M бітів), знаковий біт (біт N - 1) необхідно **розмножити** (скопіювати) на всі вищі позиції аж до біта M - 1. Ця операція називається знаковим розширенням (Sign Extension).

### Методи виконання знакового розширення

Існує два надійні способи виконання знакового розширення для довільної розрядності:

1. **Арифметичний подвійний зсув:** число зсувається вліво, щоб його знаковий біт став найстаршим бітом процесорного типу (біт 15 для `int16_t`), після чого виконується арифметичний зсув вправо. Стандарт C++20 та C23 гарантує, що правосторонній зсув знакових типів є арифметичним (старші біти заповнюються копією знакового біта).
2. **Умовне накладання маски:** перевірка знакового біта через побітове «І» та заповнення старших бітів одиницями через побітове «АБО».

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

// Метод 1: Знакове розширення 12-бітного числа через арифметичні зсуви
int16_t sign_extend_12bit_shift(uint16_t raw_12bit) {
    // Зсуваємо вліво на 4 біти, роблячи біт 11 бітом 15
    // Потім арифметично зсуваємо вправо на 4 біти
    int16_t val = (int16_t)(raw_12bit << 4);
    return val >> 4;
}

// Метод 2: Знакове розширення довільної розрядності BITS через маску
int32_t sign_extend_generic(uint32_t raw_val, uint8_t bits) {
    uint32_t sign_mask = 1UL << (bits - 1);
    if (raw_val & sign_mask) {
        // Число від'ємне: заповнюємо всі старші біти одиницями
        uint32_t extension_mask = ~((1UL << bits) - 1UL);
        return (int32_t)(raw_val | extension_mask);
    }
    // Число додатне
    return (int32_t)raw_val;
}

// Розпакування ліво-вирівняного 12-бітного значення (наприклад, ST LIS3DH)
int16_t parse_left_aligned_12bit(const uint8_t bytes[2]) {
    // Вхід: 16-бітне Little-Endian слово, де дані сидять у бітах [15:4]
    int16_t raw_16 = (int16_t)(((uint16_t)bytes[1] << 8) | (uint16_t)bytes[0]);
    // Арифметичний зсув вправо на 4 позиції автоматично зберігає знак
    return raw_16 >> 4;
}
```
```cpp
#include <cstdint>
#include <span>
#include <concepts>

// Шаблонне знакове розширення під час компіляції для довільної кількості бітів
template <size_t Bits, std::signed_integral TargetType = int32_t>
constexpr TargetType sign_extend(uint32_t raw) noexcept {
    static_assert(Bits < sizeof(TargetType) * 8, "Bits count must be smaller than target type width");
    constexpr uint32_t sign_bit = 1UL << (Bits - 1);
    constexpr uint32_t ext_mask = ~((1UL << Bits) - 1UL);
    
    if ((raw & sign_bit) != 0) {
        return static_cast<TargetType>(raw | ext_mask);
    }
    return static_cast<TargetType>(raw);
}

// Розпакування ліво-вирівняного 12-бітного значення через типізований інтерфейс
constexpr int16_t parse_left_aligned_12bit(std::span<const uint8_t, 2> bytes) noexcept {
    const auto raw_16 = static_cast<int16_t>((static_cast<uint16_t>(bytes[1]) << 8) |
                                              static_cast<uint16_t>(bytes[0]));
    return static_cast<int16_t>(raw_16 >> 4);
}
```

### Зсув нуля (Offset Binary)

Деякі спеціалізовані АЦП та датчики тиску видають дані у форматі зі зсувом нуля (Offset Binary / Excess-K). У цьому форматі мінімальному вимірюваному значенню відповідає двійковий нуль `0x0000`, фізичному нулю — середина шкали `0x8000`, а максимуму — `0xFFFF`.

Якщо код у форматі Offset Binary помилково обробити як додатковий код, нульовий сигнал сприйматиметься як максимальне від'ємне число (-32768).

Перетворення з Offset Binary у стандартний Two's Complement здійснюється інверсією найстаршого біта (MSB):

```
V_twos_complement = V_offset_binary ^ 0x8000
```

### Фіксована кома та чутливість (LSB Weight)

Отримавши коректне ціле число зі знаком, розробники часто одразу переводять його у числа з рухомою комою: `float g = raw * 0.000061f`.

На мікроконтролерах Cortex-M0/M0+/M3 без апаратного блоку FPU операції `float` виконуються програмною бібліотекою і займають сотні тактів процесора на кожне вимірювання.

Для високочастотної обробки (фільтрація, ПІД-регулятори, виявлення ударів) доцільно зберігати значення у форматі з фіксованою комою або цілих фізичних мікроодиницях (міліграми `mg`, мілівольти `mV`, мікробари `μbar`).

```
Чутливість акселерометра в діапазоні ±2g при 16-бітному виході:
Масштабний коефіцієнт = 2000 mg / 32768 відліків ≈ 0.061035 mg/LSB
Обчислення в цілих числах: acceleration_mg = (raw * 1000) / 16384
```

## Порушення когерентності при роздільному читанні регістрів

Мультибайтні вихідні дані (16-, 24- чи 32-бітні відліки АЦП) фізично розташовані у двох або трьох окремих 8-бітних регістрах. Коли мікроконтролер опитує давач, він передає команду читання по шині, зчитуючи один байт за раз.

Якщо читання старшого (H) та молодшого (L) байтів виконується двома незалежними I2C-транзакціями, виникає небезпека переповнення розрядів під час зчитування (Rollover Hazard / Broken Atomicity).

Уявімо послідовність подій у часі:
1. Фізична величина на вході давача відповідає відліку `0x00FF` (255).
2. Мікроконтролер у момент t₁ зчитує регістр старшого байта H, отримуючи значення `0x00`.
3. У момент t₂ (між двома транзакціями шини) АЦП завершує нове перетворення. Значення сигналу трохи збільшилося і стало рівним `0x0100` (256). АЦП записує нові дані у внутрішні регістри: старший байт стає `0x01`, молодший — `0x00`.
4. У момент t₃ мікроконтролер виконує другу транзакцію і зчитує оновлений регістр молодшого байта L, отримуючи `0x00`.
5. Програма зшиває два байти: `(0x00 << 8) | 0x00 = 0x0000` (0 замість 256!).

![Розрив когерентності: читання мультибайтного регістра під час оновлення](/root/course/embedded/chyp-breshe/img/torn-read-rollover.svg)
*Асинхронне оновлення регістра давачем між двома окремими транзакціями читання старшого і молодшого байтів призводить до зшивання половинок різних вимірювань.*

Результатом стає короткочасний, але катастрофічний провал сигналу на 256 відліків. У зворотній ситуації (перехід від `0x0100` до `0x00FF`) зшивання старого H = `0x01` та нового L = `0xFF` породжує помилкове значення `0x01FF` (511 замість 255) — миттєвий позитивний стрибок на 256 LSB. У системах стабілізації польоту дрона такий стрибок викликає хибне спрацьовування моторів і втрату керування.

### Кремнієва анатомія тіньових регістрів (Shadow Registers)

Чому кремнієвий кристал перезаписує регістри просто посеред читання? Усередині мікросхеми вимірювальне ядро (аналоговий перетворювач, сигма-дельта модулятор, цифровий фільтр децимації DSP) тактується від власного незалежного генератора (внутрішній RC-осцилятор на 1–20 МГц). Блок послідовного інтерфейсу (I2C/SPI slave engine) тактується зовнішньою лінією SCK/SCL від мікроконтролера. Ці два домени повністю асинхронні.

Коли фільтр децимації закінчує черговий відлік, він імпульсом стробу записує нове значення у внутрішній масив тригерів. Якщо інтерфейсна частина чипа не має механізму блокування, вихідні буфери шини підключені прямо до цих тригерів. У результаті байт, який ще не встигли вичитати, замінюється новим значенням прямо під час передачі.

Щоб розв'язати цей конфлікт апаратно, розробники мікросхем встановлюють дворангові регістри із передавальними вентилями (Transmission Gate Latches):
1. **Перший ранг (Conversion Latch):** сюди постійно записує дані внутрішнє ядро АЦП із частотою вибірки (ODR, Output Data Rate).
2. **Другий ранг (Output Shadow Register):** сюди дані копіюються лише тоді, коли шина вільна, і фіксуються на весь час поточної транзакції зчитування.

### Апаратні та програмні засоби захисту атомарності

Для усунення розриву когерентності застосовують три обов'язкові інженерні практики:

#### 1. Тіньові регістри та режим блокування оновлення (Block Data Update, BDU)
У якісних вимірювальних чипах передбачено спеціальний конфігураційний біт `BDU` (наприклад, у регістрі `CTRL_REG4` чипів STMicroelectronics). Коли `BDU = 1`, мікросхема апаратно блокує оновлення тіньових регістрів виходу після того, як мікроконтролер прочитав перший (старший або молодший) байт мультибайтної групи. Блокування утримується доти, доки не будуть прочитані всі пов'язані байти вимірювання (або до скидання лінії CS). Навіть якщо АЦП здійснює десять нових перетворень за цей час, програма гарантовано отримує узгоджені половинки одного й того самого зрізу часу.

#### 2. Пакетне автоінкрементне читання ([Burst Read](root:com-devices/burst-read))
Усі байти вимірювання (X_L, X_H, Y_L, Y_H, Z_L, Z_H) повинні зчитуватися **за одну-єдину транзакцію шини** з використанням автоінкременту адреси. В I2C для цього використовується повторний старт (Repeated Start) без відпускання шини, а в SPI — утримання лінії Chip Select у низькому стані на час передачі всіх байтів. Апаратна логіка більшості давачів атомарно защіпає весь блок регістрів у момент звернення до першого байта пакету.

#### 3. Синхронізація за перериванням готовності даних ([Data Ready, DRDY](root:com-devices/drdy-pattern))
Зчитування даних запускається не за довільним таймером ядра, а строго за апаратним сигналом переривання від ніжки `DRDY` давача. Переривання свідчить про те, що АЦП щойно закінчив запис, і попереду є гарантоване часове вікно спокою до наступного циклу вимірювання.

```c
    uint8_t start_reg = REG_OUT_X_L | I2C_AUTO_INC;

    // і вичитування 6 байтів поспіль без проміжних STOP умов
```

## Неузгодженість полярності й фази тактування SPI (CPOL/CPHA)

Шина SPI не має вбудованого апаратного підтвердження успішності прийому (ACK) чи жорсткої адресації, як I2C. Синхронізація цілком спирається на лінію тактового сигналу SCK.

Інтерфейс SPI підтримує 4 режими роботи, що визначаються комбінацією двох параметрів:
- **CPOL (Clock Polarity):** полярність лінії такту в стані спокою. CPOL = 0 — низький рівень (0 В); CPOL = 1 — високий рівень (Vcc).
- **CPHA (Clock Phase):** фаза вибірки даних. CPHA = 0 — защіпання на першому фронті такту; CPHA = 1 — защіпання на другому фронті такту.

| Режим SPI | Рівень спокою SCK (CPOL) | Фронт защіпання даних (CPHA) | Фронт зміни даних передавачем |
| :--- | :--- | :--- | :--- |
| **Mode 0** | Низький (0) | Передній висхідний (↑) | Задній спадний (↓) |
| **Mode 1** | Низький (0) | Задній спадний (↓) | Передній висхідний (↑) |
| **Mode 2** | Високий (1) | Передній спадний (↓) | Задній висхідний (↑) |
| **Mode 3** | Високий (1) | Задній висхідний (↑) | Передній спадний (↓) |

Якщо режим SPI в ініціалізації мікроконтролера не збігається з вимогами даташита давача (найчастіша помилка — Mode 0 замість Mode 3, або Mode 0 замість Mode 1), відбувається розсинхронізація фази вибірки.

Коли мікроконтролер виставляє CPHA = 0, він намагається зафіксувати стан лінії MISO на першому висхідному фронті SCK. Але якщо давач очікує CPHA = 1, він виставляє свій найстарший біт (D7) на лінію MISO лише **після** першого фронту. У момент першого такту мікроконтролер фіксує невизначений рівень або залишковий стан шини. Починаючи з другого такту, мікроконтролер читає біт D7 замість D6, біт D6 замість D5 і так далі.

![Невідповідність фази тактування SPI (CPHA): зсув потоку на 1 біт](/root/course/embedded/chyp-breshe/img/spi-cpha-shift.svg)
*Вибірка сигналу не на тому фронті такту призводить до зсуву всіх бітів у байті на одну позицію, подвоюючи числа або втрачаючи старший розряд.*

### Симптоми помилки CPHA в реальних вимірюваннях

Помилка фази тактування спотворює всі байти потоку однаковим чином:
1. **Зсув ліворуч (`Stream << 1`):** найстарший біт втрачається, усі прочитані значення виглядають **помноженими рівно у 2 рази**, а наймолодший біт заповнюється випадковим шумом.
2. **Зсув праворуч (`Stream >> 1`):** значення виглядають **поділеними на 2**, а найстарший біт повторює стан останнього біта попереднього байта.
3. **Спотворення ідентифікатора:** регістр `WHO_AM_I` замість очікуваного `0x68` (`0110 1000b`) повертає `0xD0` (`1101 0000b` — зсув вліво на 1 біт) або `0x34` (`0011 0100b` — зсув вправо на 1 біт).

Якщо ідентифікатор чипа відрізняється від значення в даташиті рівно у 2 рази (або на 1 бітовий зсув), перевірте конфігурацію полярності й фази SPI перед тим, як підозрювати браковану мікросхему.

## Завади, дзвоніння та цілісність сигналів на шині

Коли алгоритмічна частина (Endianness, розширення знака, пакетне читання, режим SPI) повністю налагоджена, дані все одно можуть спотворюватися спорадично. Типовий симптом: окремі пакети серед тисяч правильних раптом містять абсурдні викиди, або зв'язок періодично підвисає.

Причина криється у фізиці поширення цифрових сигналів по друкованій платі та з'єднувальних шлейфах.

### Довга лінія на макетній платі: хвильові процеси

Поширена омана полягає в тому, що на низьких частотах шини (наприклад, SPI 1 МГц або I2C 400 кГц) властивості ліній передач не мають значення. Проте для виникнення хвильових ефектів важлива не частота повторення пакетів, а **швидкість наростання фронту** (Rise Time, tr).

Критична довжина провідника (l_crit), за якої дріт починає поводитися як довга лінія з хвильовими відбиттями, визначається співвідношенням:

```
l_crit = tr / (2 · t_pd)
```

де t_pd — питома затримка поширення сигналу у діелектрику (близько 6–7 нс/м для FR-4 та ізоляції дротів).

Якщо вивід GPIO сучасного контролера перемикається за tr = 1.5 ns, критична довжина становить:

```
l_crit = 1.5 нс / (2 · 7 нс/м) ≈ 0.107 м = 10.7 см
```

Будь-який макетний шлейф довжиною понад 10–15 см за такого крутого фронту стає довгою лінією із характерним хвильовим опором Z₀ ≈ 100–150 Ом. На протилежному кінці шлейфа вхідний опір CMOS-ніжки давача становить понад 10 МОм (фактично холостий хід). Коефіцієнт відбиття напруги від такого розриву наближається до +1:

```
Γ = (Z_in - Z_0) / (Z_in + Z_0) ≈ (∞ - 100) / (∞ + 100) = +1
```

Відбита хвиля повертається до мікроконтролера, знову відбивається і створює тривалі затухаючі коливання — дзвоніння (Ringing).

![Дзвоніння на лінії такту: генерація хибних імпульсів](/root/course/embedded/chyp-breshe/img/ringing-false-clock.svg)
*Коливання на крутому фронті сигналу двічі перетинають логічний поріг мікросхеми, породжуючи фантомні тактові імпульси та десинхронізацію прийому.*

Напруга на лінії такту під час дзвоніння перевищує рівень живлення Vcc (Overshoot) і провалюється нижче порогової напруги спрацьовування тригера Шмітта V_IH (0.7 · Vcc).

Вхідний буфер мікросхеми сприймає ці коливання як **додаткові тактові імпульси**. Замість одного такту апаратний зсувний регістр здійснює два або три зсуви. Весь подальший потік бітів усередині кадру зміщується на випадкову кількість позицій, перетворюючи телеметрію на сміття.

### Перехресні наведення (Crosstalk) та петлі землі

У плоских стрічкових шлейфах (Ribbon Cables), де провідники сигналів SCK, MOSI, MISO та CS прокладені паралельно впритул один до одного, крутий перепад напруги на лінії такту (dV/dt ≈ 3.3 В / 1.5 нс ≈ 2.2 · 10⁹ В/с) створює ємнісне наведення через взаємну ємність сусідніх жил (Cm ≈ 2–5 пФ):

```
I_crosstalk = Cm · (dV / dt) ≈ 3 пФ · 2.2 В/нс ≈ 6.6 мА
```

Цей ємнісний імпульс струму створює хибний сплеск напруги на сусідній лінії MISO, що фіксується приймачем як паразитна логічна одиниця у наймолодшому розряді.

Для захисту від наведень і дзвоніння застосовують чотири інженерні правила трасування:
1. **Послідовне демпфування (Series Source Termination):** резистор номіналом 33–100 Ом біля вихідного піна передавача узгоджує опір джерела з хвильовим опором лінії й повністю гасить відбиту хвилю.
2. **Зниження швидкості наростання фронту (Slew Rate):** налаштування регістрів GPIO мікроконтролера в режим `GPIO_SPEED_FREQ_LOW` сповільнює tr до 10–20 нс, збільшуючи l_crit до 1 метра і ліквідуючи хвильові ефекти на макеті.
3. **Екранування землею в шлейфах:** чергування провідників за правилом `GND — SCK — GND — MOSI — GND — MISO — GND — CS`. Кожен земляний дріт заземлює силові лінії поля і зводить перехресне наведення до нуля.
4. **Апаратна перевірка CRC:** використання вбудованого в протокол поліному контрольної суми для відкидання пошкоджених пакетів.

```c
#include <stdint.h>
#include <stdbool.h>

// Розрахунок CRC-8 з поліномом 0x31 (x^8 + x^5 + x^4 + 1), типовим для давачів Sensirion
uint8_t calculate_crc8_sensirion(const uint8_t *data, uint8_t len) {
    uint8_t crc = 0xFF; // Початкове значення
    for (uint8_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t bit = 0; bit < 8; bit++) {
            if (crc & 0x80) {
                crc = (uint8_t)((crc << 1) ^ 0x31);
            } else {
                crc <<= 1;
            }
        }
    }
    return crc;
}

// Перевірка цілісності пакета температури й вологості (2 байти даних + 1 байт CRC)
bool parse_sensirion_word(const uint8_t packet[3], uint16_t *out_val) {
    if (calculate_crc8_sensirion(packet, 2) != packet[2]) {
        return false; // Пакет спотворений завадою на шині!
    }
    *out_val = ((uint16_t)packet[0] << 8) | packet[1];
    return true;
}
```

```cpp
#include <cstdint>
#include <span>
#include <optional>

class SensirionPacket {
public:
    static constexpr uint8_t POLYNOMIAL = 0x31;
    static constexpr uint8_t INITIAL_CRC = 0xFF;

    static constexpr uint8_t calculate_crc8(std::span<const uint8_t> data) noexcept {
        uint8_t crc = INITIAL_CRC;
        for (const auto byte : data) {
            crc ^= byte;
            for (uint8_t bit = 0; bit < 8; ++bit) {
                if ((crc & 0x80) != 0) {
                    crc = static_cast<uint8_t>((crc << 1) ^ POLYNOMIAL);
                } else {
                    crc = static_cast<uint8_t>(crc << 1);
                }
            }
        }
        return crc;
    }

    static constexpr std::optional<uint16_t> unpack(std::span<const uint8_t, 3> raw_packet) noexcept {
        const auto payload = raw_packet.subspan<0, 2>();
        const uint8_t expected_crc = raw_packet[2];

        if (calculate_crc8(payload) != expected_crc) {
            return std::nullopt; // Помилка контрольної суми
        }

        return static_cast<uint16_t>((static_cast<uint16_t>(raw_packet[0]) << 8) |
                                      static_cast<uint16_t>(raw_packet[1]));
    }
};
```

### Зведена матриця несправностей і методів їх усунення

| Симптом у поведінці даних | Ймовірна першопричина | Інструментальна перевірка | Спосіб усунення |
| :--- | :--- | :--- | :--- |
| Пилкоподібні стрибки зі сходинками по 256 LSB на кожен крок молодшого байта | Помилка порядку байтів (MSB/LSB swap) | Порівняти `buf[0]` та `buf[1]` з регістровою картою | Збирати число як `((uint16_t)hi << 8) \| lo` або застосувати `__REV16()` |
| При переході через нуль у мінусову зону значення стрибає у $+4095$ або $+65535$ | Відсутність знакового розширення (Sign Extension) | Перевірити розрядність АЦП давача (10, 12, 14 біт) | Виконати подвійний арифметичний зсув `(int16_t)(raw << 4) >> 4` |
| Поодинокі нульові або максимальні спайки (провали) на 256 відліків під час плавного руху | Розрив когерентності при роздільному читанні H і L регістрів | Перевірити код на роздільні I2C/SPI транзакції | Увімкнути `BDU = 1`, використовувати Burst Read автоінкрементом |
| `WHO_AM_I` подвоєний (`0xD0` замість `0x68`), усі дані помножені на 2 | Неузгодженість фази тактування SPI (CPHA) | Перевірити осцилографом фронт защіпання SCK відносно MISO | Змінити режим SPI (Mode 0 ↔ Mode 1, Mode 2 ↔ Mode 3) |
| Спорадичні поодинокі збої в окремих байтах, помилки CRC, рідкісні підвисання | Дзвоніння на крутих фронтах, наведення на довгих дротах | Перевірити форму тактового сигналу осцилографом на наявність Overshoot | Додати резистор 33–50 Ом послідовно в SCK/SCL, знизити GPIO Slew Rate |

Правдоподібні хибні дані ніколи не є наслідком містики. Послідовна ізоляція кожного рівня — від електричної форми фронту на мідній доріжці до бітових масок у пам'яті мікроконтролера — перетворює незрозумілий «брехливий» чип на надійне прецизійне джерело фізичних вимірювань.
