# 📋 Довідник метрик, лічильників та інструментів діагностики

Довідник метрик та інтерфейсів діагностики Linux є системним реєстром для інженерів, які локалізують проблеми продуктивності за методом USE (Utilization, Saturation, Errors) та аналізують стан процесів на межі між простором користувача і ядром. Тут зібрано точні відповідності між віртуальними файлами `/proc`, полями структури `task_struct`, лічильниками утиліт `vmstat`, `pidstat`, `iostat`, `strace`, `perf` та їхніми пороговими значеннями для практичної діагностики.

---

## 1. Матриця ресурсів за методом USE

Метод USE аналізує кожен фізичний або логічний ресурс операційної системи за трьома ортогональними вимірами: утилізація (зайнятість ресурсу корисною роботою), насичення (наявність черг очікування) та помилки (апаратні або системні збої).

| Ресурс | Вимір USE | Ключова метрика ядра | Інструмент CLI | Файл у `/proc` або PMU | Порогове значення / Ознака аномалії |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **CPU (Обчислення)** | Utilization | `%usr` + `%sys` | `mpstat -P ALL 1`<br>`top`, `pidstat -u` | `/proc/stat`<br>`/proc/[pid]/stat` | Сумарно > 85% на ядро. Якщо `%sys > 30%` — аномалія в ядрі. |
| **CPU (Конвеєр)** | Utilization | `IPC` (Instructions/Cycle) | `perf stat -p <PID>` | Апаратні лічильники PMU | `IPC < 0.6` — простій конвеєра (Memory Stall); `IPC > 1.5` — щільний код. |
| **CPU (Черга)** | Saturation | Довжина черги `r` | `vmstat 1` | `/proc/loadavg` | `r > nproc` — черга планувальника переповнена. |
| **CPU (Тиск)** | Saturation | `some avg10` (PSI) | `cat /proc/pressure/cpu` | `/proc/pressure/cpu` | `some avg10 > 10.0` — процеси втрачають понад 10% часу в черзі. |
| **CPU (Ліміти)** | Saturation | `nr_throttled` | `cat .../cpu.stat` | `/sys/fs/cgroup/.../cpu.stat` | Зростання значення вказує на замороження процесу квотами cgroups. |
| **CPU (Залізо)** | Errors | MCE (Machine Check) | `dmesg -T`, `mcelog` | `/sys/devices/system/machinecheck/` | Будь-яке ненульове значення свідчить про апаратний дефект CPU/кешу. |
| **Пам'ять (RAM)** | Utilization | `MemAvailable`, `RSS` | `free -h`, `pidstat -r` | `/proc/meminfo`<br>`/proc/[pid]/status` | `MemAvailable < 5%` від RAM — високий ризик активації OOM-killer. |
| **Пам'ять (Збої)** | Utilization | `minflt/s` (Minor Faults) | `pidstat -r 1` | `/proc/[pid]/stat` | > 50 000/с — шторм виділення та ініціалізації динамічної пам'яті. |
| **Пам'ять (Своп)** | Saturation | `majflt/s`, `si`/`so` | `vmstat 1`, `pidstat -r` | `/proc/vmstat` | `majflt/s > 0` або `so > 0` — потік чекає вичитування даних із диска. |
| **Пам'ять (Тиск)** | Saturation | `some/full avg10` | `cat /proc/pressure/memory` | `/proc/pressure/memory` | `full avg10 > 5.0` — процеси повністю зупиняються через брак RAM. |
| **Диск (I/O)** | Utilization | `%util` | `iostat -xz 1` | `/proc/diskstats` | `%util > 90%` — дисковий контролер постійно зайнятий обробкою черги. |
| **Диск (Затримка)** | Saturation | `r_await`, `w_await` | `iostat -xz 1` | `/proc/diskstats` | `await > 5 мс` (для SSD) або `> 20 мс` (для HDD) — накопичувач гальмує. |
| **Диск (Черга)** | Saturation | `aqu-sz`, стовпчик `b` | `iostat -xz 1`, `vmstat 1` | `/proc/diskstats` | `aqu-sz > 2.0` або `b > 0` — накопичення запитів у черзі пристрою. |
| **Диск (Тиск)** | Saturation | `some/full avg10` | `cat /proc/pressure/io` | `/proc/pressure/io` | `full avg10 > 10.0` — серйозна деградація продуктивності через I/O. |
| **Диск (Помилки)** | Errors | Read/Write I/O Errors | `dmesg -T`, `smartctl -a` | `/sys/block/<dev>/stat` | Помилки введення-виведення (I/O error, Bad Sector, Controller Reset). |
| **Синхронізація** | Saturation | `cswch/s` (Voluntary) | `pidstat -w 1` | `/proc/[pid]/status` | > 20 000/с на потік — інтенсивна боротьба за м'ютекси або блокуючий I/O. |
| **Синхронізація** | Saturation | Виклики `futex` | `strace -c -p <PID>` | Системні виклики | `futex` займає > 30% часу — конфлікт потоків за блокування (Lock Contention). |

## 2. Глобальні лічильники ядра: `/proc/stat` та `/proc/meminfo`

### Розрахунок завантаження CPU з `/proc/stat`

Перший рядок файлу `/proc/stat` містить агреговані лічильники тактів ядра (Jiffies) від моменту старту системи:

```
cpu  412050 12040 185400 9854200 45200 1250 8900 0 0 0
```

Позиції полів (зліва направо):
1. `user`: час виконання непривілейованих процесів у просторі користувача (Ring 3).
2. `nice`: час виконання процесів із позитивним рівнем поступливості `nice` (знижений пріоритет).
3. `system`: час виконання коду ядра у привілейованому режимі (Ring 0).
4. `idle`: час простою, коли черга завдань порожня.
5. `iowait`: час простою процесора, протягом якого щонайменше один процес очікував завершення дискової операції.
6. `irq`: обслуговування апаратних переривань від контролерів.
7. `softirq`: обслуговування програмних переривань (мережевий стек NAPI, таймери ядра).
8. `steal`: час, відібраний гіпервізором у віртуальної машини для обслуговування інших віртуальних гостей.
9. `guest`: час виконання віртуального процесора для гостьової ОС під керуванням Linux KVM.
10. `guest_nice`: час виконання гостьової ОС зі зниженим пріоритетом.

Утиліти моніторингу (`top`, `mpstat`, `vmstat`) зчитують ці значення двічі через фіксований часовий інтервал, обчислюють приріст кожного поля та знаходять відсоток від загального часу приросту:

```
Delta_Total = Delta_user + Delta_nice + Delta_system + Delta_idle + Delta_iowait + Delta_irq + Delta_softirq + Delta_steal
%usr = (Delta_user / Delta_Total) * 100
%sys = (Delta_system / Delta_Total) * 100
%wa  = (Delta_iowait / Delta_Total) * 100
```

### Паспорт пам'яті: `/proc/meminfo`

* `MemTotal`: загальний обсяг фізичної оперативної пам'яті за вирахуванням зарезервованих ядром структур.
* `MemFree`: абсолютно не зайнята пам'ять (не містить ані коду, ані даних, ані кешів).
* `MemAvailable`: реальний обсяг пам'яті, доступний для виділення новим застосункам без примусового скидання сторінок у своп. Враховує кеш сторінок (`Cached`), який можна миттєво звільнити, та частину слябів ядра (`SReclaimable`).
* `Buffers`: пам'ять, виділена під буфери блокових пристроїв (метадані дисків, суперблоки).
* `Cached`: кеш сторінок файлів у пам'яті (Page Cache).
* `Dirty`: обсяг пам'яті, що містить змінені файлові дані, які ще не записані на фізичний накопичувач.
* `Writeback`: дані, які прямо зараз передаються контролеру диска через DMA.
* `AnonPages`: анонімна пам'ять застосунків (стеки, купи, виділення через `malloc`/`mmap`), яка не прив'язана до файлів і в разі браку RAM витісняється у Swap.
* `SwapTotal` / `SwapFree`: загальний та вільний простір у розділах або файлах підкачки.

## 3. Лічильники процесу: `/proc/[pid]/`

Для конкретного процесу ядро надає структуровану інформацію у віртуальній файловій системі `/proc/[pid]/`.

### Файл `/proc/[pid]/stat` (Компактний зріз стану)

Файл містить рядок чисел, розділених пропусками. Ключові позиції (1-індексація):

* **Поле 3 (`state`):** однолітерний код стану задачі:
  * `R` (`TASK_RUNNING`): задача виконується на CPU або стоїть у черзі `runqueue`.
  * `S` (`TASK_INTERRUPTIBLE`): перериваний сон (очікування мережі, сокета, таймера, futex).
  * `D` (`TASK_UNINTERRUPTIBLE`): неперериваний сон (очікування дискового введення-виведення або сторінкового збою `majflt`).
  * `T` (`TASK_STOPPED`): зупинено сигналом `SIGSTOP` або під налагоджувачем `ptrace`.
  * `Z` (`TASK_ZOMBIE`): завершився, але батьківський процес не викликав `waitpid()`.
* **Поле 10 (`minflt`):** кількість незначних сторінкових збоїв (Minor Page Faults) без звернення до диска (виділення фізичної сторінки RAM).
* **Поле 12 (`majflt`):** кількість значних сторінкових збоїв (Major Page Faults) із вичитуванням сторінки з диска або розділу підкачки.
* **Поле 14 (`utime`):** процесорний час у просторі користувача в системних тактах (Clock Ticks / Jiffies).
* **Поле 15 (`stime`):** процесорний час у просторі ядра в системних тактах.
* **Поле 18 (`priority`):** динамічний пріоритет планувальника.
* **Поле 19 (`nice`):** значення поступливості процесу (від `-20` до `+19`).
* **Поле 20 (`num_threads`):** кількість потоків виконання у групі ниток процесу.

### Файл `/proc/[pid]/io` (Облік введення-виведення)

Ядро підраховує як логічні операції на рівні системних викликів, так і фізичні звернення до дискового накопичувача:

* `rchar`: кількість байтів, прочитаних процесом через усі виклики `read()`, `pread()`, `recv()`. Враховує читання з кешу сторінок без реального доступу до накопичувача.
* `wchar`: кількість байтів, переданих у системні виклики `write()`, `pwrite()`, `send()`.
* `syscr`: загальна кількість системних викликів на читання.
* `syscw`: загальна кількість системних викликів на запис.
* `read_bytes`: обсяг даних у байтах, який підсистемі VFS довелося фізично прочитати з дискового накопичувача.
* `write_bytes`: обсяг даних у байтах, який було фізично надіслано на дисковий накопичувач.
* `cancelled_write_bytes`: обсяг скасованого запису (наприклад, коли процес створив тимчасовий файл і видалив його до того, як ядро скинуло брудні сторінки на диск).

*Діагностичне правило:* якщо `wchar` величезний, а `write_bytes` дорівнює нулю — дані повністю осідають у Page Cache операційної системи. Якщо `syscw` становить мільйони при малому `wchar` — програма страждає від шторму системних викликів.

### Файли `/proc/[pid]/wchan` та `/proc/[pid]/stack`

* `/proc/[pid]/wchan`: містить ім'я функції ядра, на якій зараз спить потік (наприклад, `futex_wait_queue_me`, `do_epoll_wait`, `io_schedule`, `pipe_read`). Дозволяє без налагоджувача миттєво дізнатися причину блокування.
* `/proc/[pid]/stack`: показує повний стек викликів функцій ядра в режимі Ring 0 для поточного стану нитки (потребує прав `root` або `CAP_SYS_ADMIN`).

### Файл `/proc/[pid]/schedstat` (Статистика планувальника)

Містить три числа:
1. `cpu_time`: сумарний час виконання на процесорних ядрах у наносекундах.
2. `runqueue_wait_time`: сумарний час очікування в черзі `runqueue` у наносекундах (Runqueue Latency).
3. `pcount`: кількість виділених квантів часу (Timeslices).

## 4. Підсистема тиску на ресурси: PSI (Pressure Stall Information)

Підсистема PSI дозволяє кількісно виміряти втрати продуктивності задач через брак CPU, пам'яті або дискового введення-виведення.

Файли інтерфейсу:
* `/proc/pressure/cpu`
* `/proc/pressure/memory`
* `/proc/pressure/io`

Формат кожного файлу:

```
some avg10=4.12 avg60=2.30 avg300=1.05 total=14520982
full avg10=0.50 avg60=0.15 avg300=0.02 total=841200
```

Розшифрування:
* `some`: частка часу (у відсотках), протягом якої **хоча б один** потік у системі був заблокований в очікуванні відповідного ресурсу. Для CPU існує лише рядок `some`, оскільки процесор завжди може виконувати інші готові задачі.
* `full`: частка часу (у відсотках), протягом якої **всі без винятку** активні потоки системи були заблоковані на ресурсі (наприклад, усі ядра простоювали, оскільки всі процеси заблокувалися на операціях очікування диска або пам'яті).
* `avg10`, `avg60`, `avg300`: експоненційно зважені середні значення за останні 10, 60 та 300 секунд.
* `total`: загальний накопичений час простою в мікросекундах від старту системи.

*Порогові значення:* якщо показник `avg10` для `some` або `full` перевищує `10.00` (10%), система перебуває у стані гострого дефіциту ресурсу, що безпосередньо впливає на затримку виконання програм.

## 5. Довідник параметрів діагностичних утиліт

### `vmstat` — Загальний моніторинг підсистем

```sh
# Запуск із періодом 1 секунда
vmstat 1

# Відображення активної та неактивної пам'яті
vmstat -a 1

# Статистика дискових розділів
vmstat -d 1

# Відображення лічильників з часовими мітками
vmstat -t 1
```

* `r`: довжина черги готових до виконання ниток (`TASK_RUNNING`).
* `b`: кількість ниток у неперериваному сні `TASK_UNINTERRUPTIBLE`.
* `si` / `so`: швидкість підкачки пам'яті (Swap In / Swap Out) у КіБ/с.
* `bi` / `bo`: блоки, отримані від блокових пристроїв та надіслані на них (Blocks In / Out).
* `in`: кількість переривань за секунду.
* `cs`: кількість перемикань контексту за секунду в усій системі.
* `us`, `sy`, `id`, `wa`, `st`: розподіл часу CPU (User, System, Idle, I/O Wait, Steal Time).

### `pidstat` — Профілювання конкретних процесів

```sh
# Повний зріз (процесор, диск, нитки, пам'ять) для конкретного PID
pidstat -u -d -w -r -p <PID> 1

# Моніторинг усіх індивідуальних потоків процесу (TID)
pidstat -t -p <PID> 1

# Відображення назв виконуваних файлів та повних аргументів
pidstat -l -p <PID> 1
```

* Опція `-u`: відсоток процесора (`%usr`, `%system`, `%guest`, `%wait`, `%CPU`).
* Опція `-d`: дисковий I/O (`kB_rd/s`, `kB_wr/s`, `kB_ccwr/s` — скасований запис через перезапис у кеші, `iodelay` — затримка в тактах).
* Опція `-w`: перемикання контексту (`cswch/s` — добровільні, `nvcswch/s` — примусові).
* Опція `-r`: пам'ять та збої (`minflt/s`, `majflt/s`, `VSZ`, `RSS`, `%MEM`).
* Опція `-t`: розгортання дерева ниток для багатопотокових застосунків.

### `iostat` — Аналіз блокового введення-виведення

```sh
# Розширена статистика в мегабайтах за секунду, виключаючи неактивні пристрої
iostat -xz -m 1
```

* `r/s`, `w/s`: кількість зчитаних та записаних запитів за секунду (IOPS).
* `rMB/s`, `wMB/s`: обсяг переданих даних у мегабайтах за секунду.
* `rrqm/s`, `wrqm/s`: кількість запитів, об'єднаних планувальником I/O ядра перед відправкою на контролер.
* `r_await`, `w_await`: середній час виконання запиту на читання/запис (у мілісекундах), включно з часом у черзі пристрою.
* `aqu-sz`: середня довжина черги запитів, які очікують на накопичувачі.
* `%util`: відсоток часу, протягом якого накопичувач виконував команди.

### `strace` — Трасування системних викликів

```sh
# Підрахунок та агрегація часу всіх викликів живого процесу
strace -c -p <PID>

# Фільтрація за типами викликів (мережа, файли, процеси)
strace -e trace=network,file,desc -p <PID>

# Друк точного часу початку кожного виклику з мікросекундами
strace -tt -T -p <PID>

# Відстеження нащадків (нових потоків та процесів)
strace -f -c -p <PID>
```

* Опція `-c`: підсумковий звіт за типами викликів (`% time`, `seconds`, `usecs/call`, `calls`, `errors`).
* Опція `-T`: виведення тривалості кожного системного виклику в кутових дужках `<тривалість>`.
* Опція `-e trace=...`: фільтрація за конкретними іменами (`futex`, `write`, `epoll_wait`) або класами (`%desc`, `%file`, `%net`, `%process`).

### `perf` — Апаратне та статистичне профілювання

```sh
# Миттєвий інтерактивний огляд гарячих функцій процесу
perf top -p <PID>

# Запис стека викликів із частотою 99 Гц на 10 секунд
perf record -F 99 -g -p <PID> -- sleep 10

# Перегляд звіту з ієрархічним деревом викликів
perf report -g 'graph,0.5,caller'

# Збір апаратних лічильників PMU (інструкції, цикли, промахи кешу, IPC)
perf stat -p <PID> -- sleep 5
```

* `perf stat`: вимірює глобальні апаратні події:
  * `cycles`: кількість тактів процесора.
  * `instructions`: кількість виконаних інструкцій.
  * `insn per cycle` (IPC): співвідношення `instructions / cycles`.
  * `cache-misses`: промахи кешу останнього рівня (LLC / L3).
  * `branch-misses`: промахи блоку передбачення переходів конвеєра.
