# 📋 Довідник конструкцій безпечного сценарію Bash

Цей довідник містить систематизований опис системних прапорців інтерпретатора, правил розкриття параметрів, обробки сигналів ядра та кодів завершення процесів. Усі наведені конструкції формують базовий контракт надійності, який перетворює крихкий набір команд на передбачуваний і безпечний автоматизований інструмент системного адміністрування.

## Системні прапорці режиму виконання (set і shopt)

Вбудована команда `set` змінює внутрішній стан прапорців інтерпретатора оболонки. За замовчуванням Bash налаштовано для інтерактивної взаємодії, де головним пріоритетом є безперервність сеансу навіть після помилок користувача. Для автоматизованих сценаріїв такий підхід є руйнівним, тому робочий режим перевизначається на старті скрипта.

| Опція | Повна назва | Системна дія при активації |
|---|---|---|
| `set -e` | `errexit` | Негайне переривання виконання, якщо будь-яка команда повертає ненульовий код виходу (`$? != 0`). Не спрацьовує всередині умов `if`, `while`, `until` та лівої частини списків `\|\|` і `&&`. |
| `set -u` | `nounset` | Аварійне завершення сценарію з повідомленням про помилку при спробі розкрити неоголошену змінну (замість підстановки порожнього рядка). |
| `set -o pipefail` | `pipefail` | Код виходу конвеєра визначається останнім за порядком процесом, що завершився з ненульовим статусом (якщо всі успішні — 0). За замовчуванням код виходу конвеєра дорівнює статусу лише останньої команди. |
| `set -E` | `errtrace` | Успадкування пастки `trap ... ERR` функціями, командними підстановками та підоболонками. За замовчуванням пастка `ERR` не передається всередину функцій. |
| `shopt -s inherit_errexit` | `inherit_errexit` | (Bash 4.4+) Примушує підоболонки командної підстановки `$(...)` успадковувати дію прапорця `set -e`. За замовчуванням у класичному Bash помилка всередині `$()` не зупиняє батьківський скрипт. |
| `set -x` | `xtrace` | Друк кожної команди у `stderr` перед її безпосереднім виконанням після всіх етапів розкриття. Рядки маркуються значенням змінної `PS4`. |
| `set -o noclobber` | `noclobber` | Заборона перезапису наявних файлів за допомогою оператора перенаправлення `>`. Для примусового перезапису вимагає явного оператора `>\|`. |

### Механізм взаємодії та крайові випадки прапорців суворого режиму

Комбінація `set -euo pipefail` усуває три найпоширеніші класи прихованих аварій у сценаріях:

1. **Ігнорування збоїв проміжних кроків (`errexit`)**: за замовчуванням оболонка продовжує виконувати наступні рядки, навіть якщо попередня команда завершилася критичним збоєм (наприклад, не вдалося перейти в цільовий каталог через відсутність прав). Прапорець `set -e` примушує оболонку перевіряти статус виходу кожної інструкції та генерувати вихід із кодом збою. Важливий виняток: прапорець вимикається для команд, чий результат тестується операторами `if`, `while`, або які стоять ліворуч від логічних операторів `||` та `&&`. Якщо команду потрібно виконати з потенційним ненульовим статусом без зупинки скрипта, застосовують явний захист: `command_with_possible_error || true`.
2. **Тихе розкриття неініціалізованих змінних (`nounset`)**: коли у скрипті трапляється одрук у назві змінної або очікуваний аргумент не було передано, стандартний Bash підставляє замість неї порожній рядок. Це призводить до катастрофічних наслідків під час виконання команд видалення чи переміщення. Прапорець `set -u` гарантує негайну зупинку інтерпретатора з діагностичним повідомленням `unbound variable`. Якщо змінна справді може бути законно не встановлена, доступ до неї обов'язково оформлюється через конструкцію замовчування: `"${OPTIONAL_VAR:-}"`.
3. **Маскування помилок у середині конвеєра (`pipefail`)**: у стандартному режимі статус конвеєра `cmd1 | cmd2 | cmd3` формується виключно за результатом команди `cmd3`. Якщо утиліта генерації даних `cmd1` впала з кодом помилки, але архіватор `cmd3` успішно зберіг порожній потік, оболонка вважає всю операцію успішною. Прапорець `pipefail` примушує ядро оболонки повертати код першої команди справа, що завершилася зі збоєм.

## Підстановка та модифікація параметрів (Parameter Expansion)

Вбудовані механізми маніпуляції змінними виконуються безпосередньо процесом оболонки в пам'яті без створення дочірніх процесів (`fork()`) та виклику зовнішніх утиліт.

| Конструкція | Призначення | Поведінка, якщо змінна порожня або неоголошена |
|---|---|---|
| `${VAR:-default}` | Значення за замовчуванням | Повертає `default`, якщо `VAR` не встановлена або порожня; значення самої `VAR` не змінюється. |
| `${VAR:=default}` | Присвоєння за замовчуванням | Якщо `VAR` порожня або не встановлена, їй присвоюється `default`, після чого значення повертається. Не працює для позиційних параметрів (`$1`). |
| `${VAR:?error_msg}` | Обов'язковий параметр | Якщо `VAR` порожня або не встановлена, скрипт завершується з кодом 1 і друкує `error_msg` у `stderr`. |
| `${VAR:+alternate}` | Альтернативне значення | Повертає `alternate`, якщо `VAR` встановлена і не порожня; інакше повертає порожній рядок. |
| `${#VAR}` | Довжина рядка | Повертає кількість символів у значенні змінної `VAR`. Для масиву `${#ARR[@]}` повертає кількість елементів. |
| `${VAR#pattern}` | Видалення префіксу (найкоротше) | Видаляє найкоротший префікс, що збігається з glob-шаблоном `pattern`. |
| `${VAR##pattern}` | Видалення префіксу (найдовше) | Видаляє найдовший префікс, що збігається з glob-шаблоном `pattern` (наприклад, `${FILE##*/}` повертає basename). |
| `${VAR%pattern}` | Видалення суфіксу (найкоротше) | Видаляє найкоротший суфікс, що збігається з glob-шаблоном `pattern` (наприклад, `${FILE%.*}` видаляє останнє розширення). |
| `${VAR%%pattern}` | Видалення суфіксу (найдовше) | Видаляє найдовший суфікс, що збігається з glob-шаблоном `pattern`. |
| `${VAR/find/replace}` | Заміна першого входження | Замінює перший збіг шаблону `find` на рядок `replace`. |
| `${VAR//find/replace}` | Заміна всіх входжень | Замінює всі збіги шаблону `find` на рядок `replace`. |

### Правила застосування підстановок для безпечної обробки аргументів

Для побудови надійних інтерфейсів командного рядка використовують три основні патерни підстановки:

* **Перевірка наявності критичних вхідних даних**: замість багаторядкових блоків перевірки умов застосовують конструкцію `${1:?Вкажіть обов'язковий шлях до конфігураційного файлу}`. Якщо користувач запустив сценарій без параметрів, інтерпретатор автоматично надрукує вказане повідомлення у потік діагностики й зупинить виконання з ненульовим статусом.
* **Безпечна ініціалізація необов'язкових опцій**: використання форми `${LOG_LEVEL:-INFO}` дозволяє скрипту отримати значення з оточення, якщо воно задане, або проініціалізувати змінну безпечним внутрішнім замовчуванням без порушення суворого режиму `nounset`.
* **Маніпуляція шляхами без виклику dirname та basename**: конструкція `${FULL_PATH%/*}` повертає каталог розміщення файлу, а `${FULL_PATH##*/}` — ім'я самого файлу. Оскільки ці операції виконуються в оперативній пам'яті оболонки без виклику системних викликів створення нових процесів `fork()` та `execve()`, швидкість обробки масивів шляхів зростає на кілька порядків.

## Спеціальні системні змінні оболонки

Спеціальні змінні надають доступ до метаданих поточного процесу, позиційних аргументів та параметрів оточення.

| Змінна | Тип даних | Опис та семантика |
|---|---|---|
| `$0` | Рядок | Шлях до поточного виконуваного сценарію або ім'я оболонки. |
| `$1` .. `$9` | Рядок | Позиційні аргументи, передані сценарію. Аргументи з індексом 10 і більше вимагають фігурних дужок: `${10}`. |
| `$#` | Ціле число | Кількість переданих позиційних аргументів (не враховуючи `$0`). |
| `"$@"` | Масив слів | Усі позиційні аргументи, розкриті як окремі точно залапковані слова `"$1" "$2" "$3"`. Єдиний правильний спосіб передачі списку аргументів без ризику розбиття слів. |
| `"$*"` | Рядок | Усі аргументи, об'єднані в один суцільний рядок через перший символ змінної `IFS` (`"$1c$2c$3"`). |
| `$$` | Ціле число | Ідентифікатор процесу (PID) поточної оболонки. У підоболонках зберігає PID батьківської оболонки. |
| `$!` | Ціле число | PID останнього процесу, запущеного у фоновому режимі через `&`. |
| `$?` | Ціле число (0..255) | Код завершення останньої виконаної перед цим команди. |
| `PIPESTATUS` | Масив чисел | Масив кодів завершення всіх команд останнього виконаного конвеєра (наприклад, `${PIPESTATUS[0]}`). |
| `IFS` | Рядок символів | Внутрішній роздільник полів (*Internal Field Separator*). За замовчуванням: пробіл, табуляція, новий рядок (`$' \t\n'`). Для суворого режиму рекомендовано: `IFS=$'\n\t'`. |
| `PS4` | Рядок формату | Префікс рядків трасування `set -x`. За замовчуванням `+ `. Рекомендовано: `PS4='+ ${BASH_SOURCE}:${LINENO}:${FUNCNAME[0]:+${FUNCNAME[0]}(): } '`. |

### Тонкощі передачі списків аргументів: чому неприпустимо використовувати $* та голий $@

Головна відмінність між `"$@"` та іншими формами розкриття полягає у збереженні меж слів. Якщо користувач передає аргумент, що містить пробіли (наприклад, шлях `/Volumes/External Disk/My Data`), форма `$*` або незалапкований `$@` розіб'є його на три окремі слова за символами змінної `IFS`. Це призведе до того, що команда обробки отримає три неіснуючі шляхи замість одного.

Використання подвійних лапок `"$@"` змушує інтерпретатор створювати точний масив рядків, де кожен позиційний параметр залишається непорушним атомарним елементом незалежно від наявності всередині нього пробілів, символів табуляції чи знаків нового рядка.

## Сигнали та обробка пасток (trap)

Команда `trap` дозволяє зареєструвати функцію зворотного виклику, яку оболонка виконує під час отримання системних сигналів від ядра Linux або під час планового завершення процесу.

| Сигнал / Псевдоподія | Числовий номер | Коли виникає |
|---|---|---|
| `EXIT` (або `0`) | 0 | Будь-яке завершення сценарію: нормальне, через явний `exit`, або аварійне через `set -e`. |
| `INT` | 2 (SIGINT) | Переривання користувачем із керуючого термінала комбінацією `Ctrl+C`. |
| `TERM` | 15 (SIGTERM) | Сигнал завершення за замовчуванням від утиліти `kill`, `systemd` або менеджера контейнерів Docker/Kubernetes. |
| `HUP` | 1 (SIGHUP) | Закриття емулятора термінала або розрив з'єднання SSH. |
| `ERR` | Псевдосигнал | Виконання команди з ненульовим кодом завершення (працює разом із `set -E`). |
| `RETURN` | Псевдосигнал | Завершення виконання функції або скрипту, підключеного через `source` / `.`. |

### Інваріанти надійного прибирання ресурсів через пастку EXIT

Реєстрація обробника на псевдосигнал `EXIT` гарантує, що визначена функція очищення виконається за будь-яких умов:

1. Якщо сценарій дійшов до кінця і штатно викликав `exit 0`;
2. Якщо будь-яка команда спричинила спрацювання `set -e` через код помилки;
3. Якщо скрипт було перервано сигналами `SIGINT` або `SIGTERM` (якщо вони також вказані у списку пастки).

Всередині функції очищення критично важливо спочатку зберегти поточний код завершення `$?` у локальну змінну, а перед поверненням вимкнути дію самої пастки через `trap - EXIT`, щоб уникнути нескінченної рекурсії, якщо сама процедура прибирання тимчасових файлів завершиться з помилкою.

## Таблиця стандартних кодів завершення (Exit Codes)

Коди завершення процесів у стандарті POSIX обмежуються одним байтом без знаку і приймають значення від 0 до 255.

| Код | Значення за стандартом POSIX / Linux | Причина виникнення |
|---|---|---|
| `0` | Успіх (Success) | Команда або сценарій виконані без помилок. |
| `1` | Загальна помилка (General error) | Неспецифічний збій (наприклад, відсутній файл, помилка валідації). |
| `2` | Некоректне використання builtins | Синтаксична помилка виклику вбудованих команд оболонки або невірні аргументи. |
| `126` | Команду знайдено, але неможливо виконати | Відсутній біт прав виконання (`chmod -x`) або файл на змонтованій файловій системі `noexec`. |
| `127` | Команду не знайдено (Command not found) | Бінарний файл або утиліту не знайдено в каталогах змінної `PATH`. |
| `128` | Некоректний аргумент команди `exit` | Передано значення поза межами діапазону 0..255. |
| `130` | Завершено через SIGINT (`128 + 2`) | Скрипт було аварійно зупинено сигналом `Ctrl+C`. |
| `137` | Завершено через SIGKILL (`128 + 9`) | Процес примусово знищено ядром (наприклад, OOM Killer через брак RAM) або `kill -9`. |
| `143` | Завершено через SIGTERM (`128 + 15`) | Процес завершено сигналом планової зупинки від операційної системи. |

Коди в діапазоні 128..255 формуються ядром за формулою `128 + N`, де `N` — числовий номер системного сигналу POSIX, що спричинив загибель процесу.

## Канонічний шаблон надійного сценарію Bash (Boilerplate)

Наведений нижче каркас містить усі базові елементи дисципліни написання скриптів: суворий режим, ізоляцію потоків, трасування, детерміноване створення тимчасових каталогів та гарантоване очищення.

```bash
#!/usr/bin/env bash
# ==============================================================================
# Опис: Шаблон надійного, детермінованого сценарію Bash
# ==============================================================================

# Суворий режим виконання
set -euo pipefail
IFS=$'\n\t'

# Налаштування формату трасування для відлагодження
export PS4='+ ${BASH_SOURCE[0]}:${LINENO}:${FUNCNAME[0]:+${FUNCNAME[0]}(): } '

# Оголошення глобальних змінних
readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
readonly SCRIPT_NAME="$(basename "${BASH_SOURCE[0]}")"

# Функції логування виключно у потік stderr
log_info()  { printf '[%s] [INFO]  %s\n' "$(date +'%Y-%m-%dT%H:%M:%S%z')" "$*" >&2; }
log_warn()  { printf '[%s] [WARN]  %s\n' "$(date +'%Y-%m-%dT%H:%M:%S%z')" "$*" >&2; }
log_error() { printf '[%s] [ERROR] %s\n' "$(date +'%Y-%m-%dT%H:%M:%S%z')" "$*" >&2; }
log_fatal() { printf '[%s] [FATAL] %s\n' "$(date +'%Y-%m-%dT%H:%M:%S%z')" "$*" >&2; exit 1; }

# Створення безпечного ізольованого каталогу
TMP_DIR="$(mktemp -d -t "${SCRIPT_NAME}.XXXXXX")"

# Функція гарантованого очищення
cleanup() {
    local exit_code=$?
    trap - EXIT INT TERM
    if [[ -d "${TMP_DIR:-}" ]]; then
        rm -rf "${TMP_DIR}"
    fi
    exit "${exit_code}"
}

# Реєстрація пастки
trap cleanup EXIT INT TERM

main() {
    if [[ $# -lt 1 ]]; then
        log_fatal "Використання: ${SCRIPT_NAME} <обов'язковий_параметр> [значення_за_замовчуванням]"
    fi

    local target_item="$1"
    local fallback_val="${2:-default_value}"

    log_info "Початок обробки: ${target_item} (резерв: ${fallback_val})"
    log_info "Робоча директорія скрипта: ${SCRIPT_DIR}"
    log_info "Тимчасовий каталог: ${TMP_DIR}"

    # Корисне навантаження
    # ...

    log_info "Обробку успішно завершено."
}

main "$@"
```
