# Довідник команд та прапорців для експрес-аудиту бінарних файлів ELF

Цей довідник містить структурований опис утиліт командного рядка Linux/Unix, призначених для статичного розбору, аудиту залежностей, аналізу внутрішніх структур та витягування текстових артефактів із двійкових файлів формату `ELF` (англ. *Executable and Linkable Format*). Довідник слугує практичним довідником для інженерів, які проводять первинний тріаж стороннього ПЗ, системну діагностику та безпековий аудит без запуску досліджуваного бінарника.

---

### 1. Утиліта `file`: експрес-ідентифікація формату та середовища

Утиліта `file` виконує первинну паспортизацію бінарного образу, спираючись на системну базу сигнатур `magic` (зазвичай скомпільовану у файл `/usr/share/misc/magic.mgc`) та аналіз перших 64 байтів структури головного заголовка `Elf64_Ehdr`.

Механізм роботи утиліти полягає в послідовному тестуванні зміщень:
1. Зчитування перших чотирьох байтів за зсувом `0x00` (`\x7fELF`).
2. Перевірка байта за зсувом `0x04` для визначення розрядності (`1` для 32-біт, `2` для 64-біт).
3. Перевірка байта за зсувом `0x05` для визначення порядку байтів (`1` для LSB, `2` для MSB).
4. Зчитування 16-бітного поля типу об'єкта за зсувом `0x10` (`e_type`) та цільової машини за зсувом `0x12` (`e_machine`).
5. Сканування сегментів `Program Headers` для виявлення запису `PT_INTERP`, що вказує на динамічне лінкування та шлях до завантажувача.

#### Основні прапорці запуску
| Прапорець | Повна назва | Призначення |
|---|---|---|
| `-b` | `--brief` | Короткий вивід без повторення імені вхідного файлу на початку кожного рядка |
| `-i` | `--mime` | Вивід стандартизованого MIME-типу файлу (наприклад, `application/x-executable` або `application/x-pie-executable`) |
| `-L` | `--dereference` | Автоматичний перехід за символьними посиланнями (дереференс симлінків) |
| `-k` | `--keep-going` | Продовжувати тестування бази магічних чисел навіть після першого знайденого збігу |
| `-z` | `--uncompress` | Спроба автоматичної декомпресії вмісту всередині стиснених контейнерів |

#### Анатомія виводу команди `file`
Розглянемо типовий вивід для сучасного 64-бітного бінарника Linux:

```
$ file /usr/bin/curl
/usr/bin/curl: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=1b2c..., for GNU/Linux 3.2.0, stripped
```

| Поле виводу | Походження в структурі ELF | Значення та технічна інтерпретація |
|---|---|---|
| `ELF` | `e_ident[EI_MAG0..3]` | Сигнатура `\x7fELF` (`0x7f 0x45 0x4c 0x46`). Підтверджує відповідність стандарту ELF. |
| `64-bit` | `e_ident[EI_CLASS]` | `ELFCLASS64` (64-бітний адресний простір) або `ELFCLASS32` (32-бітний бінарник). |
| `LSB` | `e_ident[EI_DATA]` | Порядок байтів: `ELFDATA2LSB` (Little-Endian) або `ELFDATA2MSB` (Big-Endian). |
| `pie executable` | `e_type` | `ET_DYN` із прапорцями виконання (Position-Independent Executable). Завантажується за рандомізованою базою ASLR. |
| `executable` | `e_type` | `ET_EXEC` (класичний бінарник із жорстко фіксованою адресою завантаження, наприклад `0x400000`). |
| `shared object` | `e_type` | `ET_DYN` (динамічна бібліотека формату `.so`). |
| `x86-64` | `e_machine` | Цільова апаратна архітектура: `EM_X86_64`, `EM_AARCH64`, `EM_ARM`, `EM_RISCV` тощо. |
| `version 1 (SYSV)` | `e_ident[EI_OSABI]` | Версія специфікації ELF та цільовий двійковий інтерфейс (System V, GNU/Linux, FreeBSD). |
| `dynamically linked` | Сегмент `PT_INTERP` | Бінарник вимагає наявності системного завантажувача та зовнішніх `.so` бібліотек. |
| `statically linked` | Сегмент `PT_INTERP` | Сегмент `PT_INTERP` відсутній; весь системний рантайм і бібліотеки вшиті в тіло файлу. |
| `interpreter /lib64/...` | `PT_INTERP` | Повний шлях до динамічного лінкера, який ядро Linux зобов'язане запустити під час `execve`. |
| `BuildID[sha1]=...` | Секція `.note.gnu.build-id` | Унікальний криптографічний хеш збірки для зв'язування з пакетами відокремлених символів `debuginfo`. |
| `for GNU/Linux 3.2.0` | Секція `.note.ABI-tag` | Мінімальна версія ядра Linux, під яку скомпільовано системні виклики та структури бінарника. |
| `stripped` | Секція `.symtab` | Таблицю налагоджувальних символів `.symtab` видалено утилітою `strip`. |
| `not stripped` | Секція `.symtab` | Присутня повна таблиця символів `.symtab` із локальними іменами функцій та змінних. |

### 2. Утиліта `readelf`: детальний аудит заголовків і секцій

Утиліта `readelf` є прямим парсером двійкового формату ELF і не використовує проміжну бібліотеку BFD (*Binary File Descriptor*). Завдяки цьому `readelf` відображає точний фізичний стан структур файлу навіть тоді, коли файл пошкоджено або скомпільовано під нестандартну архітектуру.

#### Ключові прапорці `readelf`
| Прапорець | Повна назва | Призначення |
|---|---|---|
| `-h` | `--file-header` | Друк головного заголовка ELF Header (`Elf64_Ehdr`) |
| `-l` | `--program-headers` | Друк таблиці сегментів завантаження Program Headers (`Elf64_Phdr`) |
| `-S` | `--section-headers` | Друк таблиці секцій Section Headers (`Elf64_Shdr`) |
| `-d` | `--dynamic` | Друк вмісту динамічної секції `.dynamic` (`Elf64_Dyn`) |
| `-s` | `--symbols` | Друк таблиці символів (якщо присутня таблиця `.symtab`) |
| `--dyn-syms` |  | Друк виключно динамічної таблиці символів `.dynsym` |
| `-V` | `--version-info` | Друк версій символів (`.gnu.version`, `.gnu.version_r`, `.gnu.version_d`) |
| `-n` | `--notes` | Друк нотаток ядра та компілятора (`PT_NOTE`, Build ID, ABI tags) |
| `-r` | `--relocs` | Друк таблиць динамічних та статичних релокацій |
| `-u` | `--unwind` | Друк секцій розмотування стека (`.eh_frame`, `.ARM.exidx`) |
| `-W` | `--wide` | Заборона автоматичного перенесення та скорочення довгих імен у виводі |

#### Типи сегментів `Program Headers` (`readelf -l`)
Таблиця `Program Headers` визначає, яким чином ядро та динамічний завантажувач розміщують образ програми у віртуальній пам'яті:

* **`PT_LOAD`:** Сегмент, який відображається в адресний простір процесу через системний виклик `mmap()`.
  * Прапорці `R E` (`PF_R | PF_X`) — сегмент коду (інструкцій) та незмінних констант.
  * Прапорці `RW ` (`PF_R | PF_W`) — сегмент змінних даних (`.data`, `.bss`, `.got`).
* **`PT_INTERP`:** Містить текстовий рядок шляху до динамічного інтерпретатора (наприклад, `/lib64/ld-linux-x86-64.so.2` або `/lib/ld-musl-x86_64.so.1`).
* **`PT_DYNAMIC`:** Описує масив тегів динамічного зв'язування для завантажувача.
* **`PT_GNU_STACK`:** Оголошує права доступу до стека програми. Прапорці `RW` свідчать про безпечний нездійсненний стек (активний біт NX). Прапорці `RWE` означають, що стек виконуваний (критична вразливість безпеки).
* **`PT_GNU_RELRO`:** Область пам'яті, яку динамічний лінкер переводить у режим `Read-Only` після завершення релокацій (Partial/Full RELRO).
* **`PT_GNU_PROPERTY`:** Описує апаратні властивості процесора (наприклад, підтримку Intel CET / IBT або ARM BTI для захисту від ROP-атак).

#### Типи та прапорці секцій `Section Headers` (`readelf -S`)
Таблиця секцій містить метадані, необхідні компонувальникам, відлагоджувачам та статичним аналізаторам:

```
[Nr] Name              Type             Address           Offset    Size   ES Flg Lk Inf Al
[ 1] .interp           PROGBITS         0000000000000318  00000318  00001c 00   A  0   0  1
[14] .text             PROGBITS         0000000000001060  00001060  000422 00  AX  0   0 16
[16] .rodata           PROGBITS         0000000000002000  00002000  000148 00   A  0   0  8
[24] .data             PROGBITS         0000000000004000  00003000  000010 00  WA  0   0  8
[25] .bss              NOBITS           0000000000004010  00003010  000028 00  WA  0   0  8
```

* **Типи секцій (`Type`):**
  * `PROGBITS` — секція містить реальні байти у файлі (машинний код, дані, константи, таблиці).
  * `NOBITS` — секція не займає місця на диску; під час запуску ядро резервує під неї сторінки, заповнені нулями (типово для секції неініціалізованих даних `.bss`).
  * `SYMTAB` — повна таблиця символів для компіляції та відлагодження (видаляється `strip`).
  * `DYNSYM` — таблиця динамічних символів рантайму (не видаляється `strip`).
  * `STRTAB` — таблиця нуль-термінованих рядків (імена символів або секцій).
  * `DYNAMIC` — таблиця динамічних тегів лінкування.
* **Прапорці секцій (`Flg`):**
  * `A` (`SHF_ALLOC`) — секція повинна бути завантажена у віртуальну пам'ять під час виконання.
  * `W` (`SHF_WRITE`) — секція доступна для запису під час виконання процесу.
  * `X` (`SHF_EXECINSTR`) — секція містить виконувані машинні інструкції процесора.

#### Інтерпретація динамічних тегів (`readelf -d`)
Динамічна секція `.dynamic` містить масив структур `Elf64_Dyn`, які керують поведінкою завантажувача:

* **`DT_NEEDED`:** Ім'я необхідної спільної бібліотеки (наприклад, `libc.so.6`, `libssl.so.3`).
* **`DT_SONAME`:** Власне сонам-ім'я бібліотеки, записане всередині неї.
* **`DT_RUNPATH`:** Пріоритетні шляхи пошуку бібліотек (має пріоритет над системними каталогами, але поступається змінній `LD_LIBRARY_PATH`).
* **`DT_RPATH`:** Застарілий заголовок шляхів пошуку (ігнорується за наявності `DT_RUNPATH`).
* **`DT_INIT` / `DT_INIT_ARRAY`:** Адреси конструкторів та функцій ініціалізації, що викликаються перед `main()`.
* **`DT_FINI` / `DT_FINI_ARRAY`:** Адреси деструкторів, що викликаються під час завершення програми.
* **`DT_FLAGS_1`:** Додаткові прапорці завантаження: `NOW` (негайне зв'язування Full RELRO), `PIE` (Position-Independent Executable).

#### Аудит версіонування символів GNU (`readelf -V`)
У системній бібліотеці `glibc` кожна експортована функція прив'язана до версії ABI (наприклад, `memcpy@@GLIBC_2.14` або `statx@@GLIBC_2.28`). Утиліта `readelf -V` дозволяє виявити секцію `.gnu.version_r` (Version Needs) та точно визначити, яка максимальна версія `glibc` вимагається бінарником:

```bash
$ readelf -V binary | grep -E 'File:|Name:'
  File: libc.so.6
    0x0020: Name: GLIBC_2.34
    0x0030: Name: GLIBC_2.14
    0x0040: Name: GLIBC_2.2.5
```
Якщо на цільовому сервері встановлено версію `glibc 2.31`, бінарник із вимогою `GLIBC_2.34` зазнає аварійної зупинки ще під час завантаження.

### 3. Утиліта `objdump`: дизасемблювання та приватні заголовки

Утиліта `objdump` покладається на бібліотеку BFD і спеціалізується на дослідженні машинних інструкцій та секцій об'єктного коду. Вона корисна для швидкої перевірки точки входу та аналізу коду ініціалізації без запуску важких інтерактивних дизасемблерів.

#### Основні прапорці `objdump`
| Прапорець | Повна назва | Призначення |
|---|---|---|
| `-f` | `--file-headers` | Загальна інформація про формат, архітектуру та прапорці адресації |
| `-p` | `--private-headers` | Друк динамічних заголовків та залежностей (безпечний аналог `ldd`) |
| `-h` | `--section-headers` | Список секцій, їх розмірів, віртуальних адрес (VMA) та зміщень (File Off) |
| `-d` | `--disassemble` | Дизасемблювання лише виконуваних секцій (наприклад, `.text`) |
| `-D` | `--disassemble-all` | Примусове дизасемблювання всіх секцій файлу |
| `-M intel` | `--disassembler-options=intel` | Перемикання синтаксису з AT&T на Intel (читабельний формат `mov eax, [rbp-4]`) |
| `-s` | `--full-contents` | Шістнадцятковий дамп вмісту секцій |
| `-j <name>` | `--section=<name>` | Обмежити операцію лише вказаною секцією (наприклад, `-s -j .rodata`) |
| `-C` | `--demangle` | Декодування (деманглінг) компільованих імен C++ (`_Z4func...` → `func()`) |

#### Типові діагностичні команди `objdump`
```bash
# 1. Безпечний перегляд залежностей та RUNPATH:
$ objdump -p binary | grep -E 'NEEDED|RUNPATH|RPATH'

# 2. Швидкий перегляд точки входу _start в синтаксисі Intel:
$ objdump -d -M intel --start-address=0x1060 --stop-address=0x10a0 binary

# 3. Дамп рядків та констант із секції .rodata:
$ objdump -s -j .rodata binary
```

### 4. Утиліта `nm`: аналіз символьних імен та API

Утиліта `nm` витягує таблиці символів, дозволяючи класифікувати функції та змінні на локальні, експортовані та імпортовані із зовнішніх бібліотек. Головна перевага полягає в можливості швидкої фільтрації зовнішніх API, які бінарник викликає під час роботи.

#### Основні прапорці `nm`
| Прапорець | Повна назва | Призначення |
|---|---|---|
| `-D` | `--dynamic` | Читання динамічної таблиці `.dynsym` (працює навіть на stripped бінарниках) |
| `-u` | `--undefined-only` | Друк лише нерозв'язаних (імпортованих) символів, які надаються іншими `.so` |
| `-g` | `--extern-only` | Друк лише глобальних (експортованих) символів |
| `-C` | `--demangle` | Декодування мангльованих символів C++ та Rust |
| `-n` | `--numeric-sort` | Сортування символів за числовими адресами |
| `-A` | `--print-file-name` | Додавати ім'я файлу перед кожним символом (зручно для масового грепу) |

#### Таблиця кодів типів символів у виводі `nm`
| Код символу | Стан символу | Технічне значення |
|---|---|---|
| `U` | Undefined | Символ імпортується з зовнішньої спільної бібліотеки (розв'язується лінкером). |
| `T` / `t` | Text | Функція або код у секції коду `.text` (`T` — глобальна, `t` — локальна static). |
| `D` / `d` | Data | Ініціалізована змінна в секції `.data`. |
| `B` / `b` | BSS | Неініціалізована змінна в секції `.bss`. |
| `R` / `r` | Read-only | Константа або таблиця в секції `.rodata`. |
| `W` / `w` | Weak | Слабкий символ (*weak symbol*), який може бути заміщений іншим визначенням. |
| `V` / `v` | Weak Object | Слабкий об'єкт даних. |

### 5. Утиліта `strings`: витягування відкритих текстових констант

Утиліта `strings` здійснює послідовне сканування файлу та фільтрує послідовності друкованих символів, що завершуються нульовим байтом або символом нового рядка.

Під час компіляції програми мовами C, C++, Go чи Rust рядкові літерали (повідомлення журналів, шляхи конфігураційних файлів, формати `printf`, URL-адреси) розміщуються у відкритому нешифрованому вигляді в секції даних лише для читання `.rodata`. Завдяки цьому статичне сканування розкриває архітектурні деталі програми навіть у повністю вичищених (*stripped*) бінарниках.

#### Ключові прапорці `strings`
| Прапорець | Повна назва | Призначення |
|---|---|---|
| `-a` | `--all` | Сканувати абсолютно весь файл (за замовчуванням у деяких версіях читаються лише секції даних) |
| `-n <N>` | `--bytes=<N>` | Мінімальна довжина знайденого рядка (дефолт `4`; рекомендовано `8` для відсікання шуму) |
| `-t <radix>` | `--radix=<radix>` | Друк зсуву рядка у файлі: `x` (шістнадцятковий), `d` (десятковий), `o` (вісімковий) |
| `-e <enc>` | `--encoding=<enc>` | Тип кодування: `s` (7-bit ASCII/UTF-8), `S` (8-bit), `l` (16-bit Little-Endian), `b` (16-bit Big-Endian), `L` (32-bit LE) |

#### Практичні рецепти пошуку артефактів через `strings`
```bash
# 1. Пошук URL-адрес та протоколів:
$ strings -a -n 8 binary | grep -Ei 'https?://|ftp://|wss?://'

# 2. Пошук IPv4 адрес:
$ strings -a -n 8 binary | grep -E '([0-9]{1,3}\.){3}[0-9]{1,3}'

# 3. Пошук шляхів файлової системи Linux:
$ strings -a -n 8 binary | grep -E '^/(etc|tmp|var|usr|dev|proc|sys)/'

# 4. Пошук шляхів вихідного коду компіляції:
$ strings -a -n 6 binary | grep -Ei '\.(c|cpp|cc|cxx|h|hpp|go|rs|py):[0-9]+'

# 5. Пошук ключів конфігурації CLI:
$ strings -a -n 4 binary | grep -E '^\-\-[a-zA-Z0-9_-]+'

# 6. Пошук 16-бітних UTF-16LE рядків (кросплатформний код або Windows-порти):
$ strings -a -n 8 -e l binary
```

### 6. Матриця інструментів безпечного тріажу

| Ціль аналізу | Небезпечний метод (Заборонено для чужих файлів) | Безпечний метод (Статичний аудит) |
|---|---|---|
| **Пошук спільних бібліотек** | `ldd binary` *(Виконує код!)* | `readelf -d binary \| grep NEEDED`<br>`objdump -p binary \| grep NEEDED` |
| **Перевірка інтерпретатора** | Запуск `./binary` | `readelf -l binary \| grep -A 1 INTERP` |
| **Аудит захисту NX (Стек)** | `gdb ./binary` | `readelf -l binary \| grep GNU_STACK` *(Прапорці RW)* |
| **Аудит захисту RELRO** | `checksec` через запуск процесу | `readelf -l binary \| grep GNU_RELRO`<br>`readelf -d binary \| grep BIND_NOW` |
| **Пошук прихованого тексту** | Трасування пам'яті через `strace` | `strings -a -n 8 -t x binary` |
| **Аналіз функцій API** | `ltrace ./binary` *(Виконує код!)* | `readelf -s --dyn-syms binary`<br>`nm -D -u binary` |
| **Вимоги до версій glibc** | Тестовий запуск на машині | `readelf -V binary \| grep -E 'Name: GLIBC_'` |
