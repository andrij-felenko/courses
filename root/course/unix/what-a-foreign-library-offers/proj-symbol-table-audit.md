# ⚙️ Аудит двійкових символів бібліотеки та перевірка сумісності ABI

Під час оновлення сторонньої бібліотеки або підготовки чергового релізу власної спільної бібліотеки `.so` критично важливо гарантувати збереження двійкової сумісності (ABI, від англ. *Application Binary Interface*). Якщо в новій версії бібліотеки випадково буде видалено публічну експортовану функцію, змінено тип аргументу чи додано нове поле до відкритої структури, раніше скомпільовані клієнтські програми впадуть під час запуску або під час роботи.

Найбільш підступною є помилка динамічного завантажувача під час старту процесу:
```
./client-app: symbol lookup error: ./client-app: undefined symbol: telemetry_process_packet_v1
```

Автоматизований аудит таблиці динамічних символів `.dynsym` за допомогою системної утиліти `nm` дозволяє перехоплювати будь-які випадкові розриви інтерфейсу в конвеєрах неперервної інтеграції (CI/CD) ще до пакування та публікації релізу.

---

## 1. Анатомія експорту та фільтрація службових символів

За замовчуванням команда `nm -D --defined-only <бібліотека.so>` виводить усі визначені динамічні символи. Проте реальний спільний об'єкт ELF завжди містить значну кількість внутрішніх службових символів, що додаються компілятором і стандартним C-рантаймом (crt):
* `_init`, `_fini` — конструктор та деструктор ініціалізації бібліотеки;
* `__bss_start`, `_edata`, `_end` — адресні маркери меж секцій пам'яті;
* `__gmon_start__` — точка входу підсистеми профілювання gprof;
* `_ITM_deregisterTMCloneTable`, `_ITM_registerTMCloneTable` — транзакційна пам'ять GCC.

Ці символи не є частиною публічного прикладного API бібліотеки. Якщо їх не відфільтрувати, вони створюватимуть хибні спрацьовування під час порівняння бінарників, зібраних різними версіями GCC чи Clang.

### Атрибути видимості компілятора (Symbol Visibility)

Кількість експортованих символів напряму залежить від того, як скомпільовано бібліотеку. За замовчуванням компілятор GCC експортує кожну нестатичну функцію у динамічну таблицю `.dynsym` (режим видимості `default`). Це призводить до роздування таблиці символів та уповільнення завантаження програми.

У сучасних бібліотеках використовують прапорець компілятора `-fvisibility=hidden`. У цьому режимі всі функції вважаються внутрішніми, а назовні експортуються лише ті, які явно позначені атрибутом у коді:

:::tabs
```c
#define API_EXPORT __attribute__((visibility("default")))

API_EXPORT int telemetry_send_packet(const void* data, size_t len);
```
```cpp
#include <span>
#include <cstdint>

#define API_EXPORT __attribute__((visibility("default")))

namespace telemetry {
    API_EXPORT int send_packet(std::span<const uint8_t> data);
}
```
:::

Символи з видимістю `hidden` потрапляють лише до локальної секції `.symtab` і не з'являються у виводі `nm -D`, що суттєво спрощує аудит публічного контракту.

### Нормалізація виводу таблиці символів

Для отримання чистого відсортованого списку публічних функцій (код типу `T` або `W`) та глобальних змінних (`D`, `B`, `R`) використовується наступний конвеєр обробки утилітами `awk` та `grep`:

```sh
$ nm -D --defined-only /usr/lib/x86_64-linux-gnu/libzstd.so.1 \
    | awk '$2 ~ /^[TDBRW]$/ { print $2, $3 }' \
    | grep -vE '^_init$|^_fini$|^__bss_start$|^_edata$|^_end$|^__gmon_start__|^_ITM_' \
    | sort -k2,2 > libzstd-v1-symbols.txt
```

Приклад отриманого нормалізованого дампу:
```
T ZSTD_CCtx_reset
T ZSTD_CCtx_setParameter
T ZSTD_compress
T ZSTD_compressBound
T ZSTD_compressCCtx
T ZSTD_createCCtx
T ZSTD_freeCCtx
T ZSTD_isError
T ZSTD_versionNumber
```

## 2. Повнофункціональний скрипт аудиту сумісності двійкового інтерфейсу (ABI)

Наведений нижче виробничий Bash-скрипт `abi-diff-check.sh` приймає шляхи до базової (старої) та кандидатської (нової) версій бібліотеки, видобуває нормалізовані списки символів та класифікує знайдені відмінності на безпечні розширення та критичні розриви інтерфейсу:

```sh
#!/usr/bin/env bash
set -euo pipefail

# Перевірка наявності аргументів командного рядка
if [ "$#" -ne 2 ]; then
    echo "Використання: $0 <шлях_до_старої_бібліотеки.so> <шлях_до_нової_бібліотеки.so>"
    echo "Приклад:     $0 /usr/lib/libtelemetry.so.1.0 /build/libtelemetry.so.1.1"
    exit 1
fi

OLD_LIB="$1"
NEW_LIB="$2"

if [ ! -f "${OLD_LIB}" ] || [ ! -f "${NEW_LIB}" ]; then
    echo "Помилка: один із вказаних файлів бібліотек не існує!"
    exit 1
fi

# Створення тимчасового каталогу для проміжних файлів
TMP_DIR="$(mktemp -d /tmp/abi-audit-XXXXXX)"
trap 'rm -rf "${TMP_DIR}"' EXIT

OLD_SYM="${TMP_DIR}/old_symbols.txt"
NEW_SYM="${TMP_DIR}/new_symbols.txt"

# Функція вилучення та нормалізації символів
extract_public_symbols() {
    local lib_file="$1"
    local out_file="$2"
    
    nm -D --defined-only "${lib_file}" \
        | awk '$2 ~ /^[TDBRW]$/ { print $2, $3 }' \
        | grep -vE ' ( _init|_fini|__bss_start|_edata|_end|__gmon_start__|_ITM_.*)$' \
        | sort -u -k2,2 > "${out_file}"
}

echo "[*] Вилучення публічних динамічних символів..."
extract_public_symbols "${OLD_LIB}" "${OLD_SYM}"
extract_public_symbols "${NEW_LIB}" "${NEW_SYM}"

# Знаходження видалених символів (були в старій версії, зникли в новій)
REMOVED_SYMBOLS=$(comm -23 "${OLD_SYM}" "${NEW_SYM}")

# Знаходження доданих символів (нові функції, розширення API)
ADDED_SYMBOLS=$(comm -13 "${OLD_SYM}" "${NEW_SYM}")

# Знаходження символів зі зміненим типом (наприклад, функція T стала змінною D)
CHANGED_TYPE=$(join -1 2 -2 2 "${OLD_SYM}" "${NEW_SYM}" | awk '$2 != $3 { print $1 ": " $2 " -> " $3 }')

echo "=================================================================="
echo "      Звіт про двійкову сумісність спільного об'єкта (ABI Diff)   "
echo "  Базовий об'єкт (OLD): ${OLD_LIB}"
echo "  Новий об'єкт   (NEW): ${NEW_LIB}"
echo "=================================================================="

ABI_BROKEN=0

if [ -n "${REMOVED_SYMBOLS}" ]; then
    echo -e "\n[!] КРИТИЧНИЙ РОЗРИВ ABI: Видалено публічні символи!"
    echo "    Усі програми, зібрані з попередньою версією, зазнають аварії:"
    echo "${REMOVED_SYMBOLS}" | sed 's/^/      [-] /'
    ABI_BROKEN=1
fi

if [ -n "${CHANGED_TYPE}" ]; then
    echo -e "\n[!] КРИТИЧНИЙ РОЗРИВ ABI: Змінено тип секції символів!"
    echo "${CHANGED_TYPE}" | sed 's/^/      [!] /'
    ABI_BROKEN=1
fi

if [ -n "${ADDED_SYMBOLS}" ]; then
    echo -e "\n[i] Безпечне розширення API (додано нові функції/змінні):"
    echo "${ADDED_SYMBOLS}" | sed 's/^/      [+] /'
fi

if [ "${ABI_BROKEN}" -eq 0 ] && [ -z "${ADDED_SYMBOLS}" ]; then
    echo -e "\n[OK] Двійковий інтерфейс повністю ідентичний (100% сумісність)."
fi

echo -e "\n------------------------------------------------------------------"
if [ "${ABI_BROKEN}" -eq 1 ]; then
    echo "ВИСНОВОК: Двійкову сумісність порушено. Обов'язково підвищіть SONAME (MAJOR версію)!"
    exit 2
else
    echo "ВИСНОВОК: Зворотна сумісність збережена. Дозволено мінорне оновлення (MINOR/PATCH)."
    exit 0
fi
```

## 3. Обробка C++ бібліотек та деманглінг імен

Для бібліотек, написаних мовою C++, звичайна таблиця символів містить спаплюжені ідентифікатори (*mangled names*), які кодують простори імен, назви класів та точні типи аргументів функцій:

```
T _ZN7Network6Client7connectEPKcjt
```

Якщо інженер випадково змінить тип другого аргументу з `unsigned int` на `unsigned long`, назва функції у вихідному коді `Network::Client::connect` візуально не зміниться, але компілятор C++ згенерує зовсім інший двійковий символ:
```
T _ZN7Network6Client7connectEPKcmt
```

Стара клієнтська програма продовжить шукати символ `_ZN7Network6Client7connectEPKcjt` і негайно зазнає краху при завантаженні через помилку `undefined symbol`.

Щоб зробити звіт аудиту зрозумілим для інженерів, аудит запускають із прапорцем деманглінгу `-C` або передають список утиліті `c++filt`:

```sh
$ nm -C -D --defined-only libnetwork.so.1.0 \
    | awk '$2 ~ /^[TDBRW]$/ { $1=""; print $0 }' \
    | sed 's/^[ \t]*//'
```

Вивід чітко відобразить розрив сигнатури у звичному для розробника вигляді:
```
- T Network::Client::connect(char const*, unsigned int, unsigned short)
+ T Network::Client::connect(char const*, unsigned long, unsigned short)
```

Такий детальний звіт дозволяє команді розробників одразу зрозуміти, що для збереження зворотної сумісності необхідно або повернути початковий тип аргументу, або оголосити дві перевантажені версії функції `connect()`.

## 4. Слабкі символи (Weak Symbols) та перекриття функцій

Під час аналізу таблиці динамічних символів нерідко зустрічаються символи з літерою `W` (слабкий код) або `V` (слабкий об'єкт даних). Слабкий символ відрізняється від звичайного глобального символу `T` тим, що він не викликає конфлікту множинного визначення (*multiple definition error*), якщо клієнтська програма надасть власну однойменну функцію зі звичайним зв'язуванням `T`.

Слабкі символи широко застосовуються в системних бібліотеках для:
1. **Надання стандартних заглушок за замовчуванням:** наприклад, бібліотека логування надає слабку функцію `custom_log_writer()`, яку користувач може замінити своєю реалізацією без перекомпіляції самої бібліотеки;
2. **Опціональної підтримки потоків:** бібліотеки перевіряють адресу символу `pthread_create` — якщо вона ненульова, вмикаються м'ютекси, якщо нульова — працює однопотоковий режим;
3. **Перехоплення викликів пам'яті (Memory Interposition):** інструменти профілювання та санітайзери (ASan, Valgrind) підміняють слабкі виклики `malloc` та `free`.

Якщо під час релізу слабкий символ `W` випадково стає звичайним `T`, клієнтські програми, які раніше перевизначали цю функцію, перестануть збиратися через помилку `multiple definition of 'symbol'`. Наш скрипт аудиту автоматично перевіряє зміни типів символів у секції `CHANGED_TYPE`.

## 5. Вбудовування аудиту символів у конвеєри CI/CD

Автоматична перевірка двійкових інтерфейсів є обов'язковою практикою в репозиторіях системного рівня (таких як glibc, LLVM, systemd чи OpenCV). Запуск скрипту аудиту на етапі `pre-merge` або під час формування релізного тегу гарантує дотримання правил семантичного версіонування (SemVer).

Типовий крок у Makefile для локальної перевірки розробником перед відправкою змін у спільний репозиторій:

```makefile
.PHONY: check-abi
check-abi: libtelemetry.so
	@echo "Перевірка сумісності ABI проти еталонного релізу..."
	@./scripts/abi-diff-check.sh /usr/lib/libtelemetry.so.1.0 ./build/libtelemetry.so
```

Якщо скрипт повертає код `2`, процес збірки негайно зупиняється, повідомляючи розробника про необхідність або виправити сигнатури функцій, або явно підняти мажорний номер `SONAME` у системі збірки.
