# 📋 Поверхня інтерфейсів: системні виклики та структури діагностики дискового простору

Діагностика дискового простору в Unix спирається на суворий набір системних викликів ядра, структур псевдофайлової системи `/proc` та параметрів утиліт низького рівня. Розуміння точного контракту кожного інтерфейсу дає змогу однозначно інтерпретувати показники утиліт `df`, `du`, `lsof` і `tune2fs`, а також створювати власні надійні засоби моніторингу та аварійного відновлення.

## 1. Системний виклик `statvfs()` та структура `struct statvfs`

Запит сукупної статистики файлової системи здійснюється за допомогою стандартних системних функцій `statvfs(const char *path, struct statvfs *buf)` або `fstatvfs(int fd, struct statvfs *buf)`. У сучасних дистрибутивах Linux заголовком цього інтерфейсу є `<sys/statvfs.h>`.

На рівні ядра підсистема VFS перетворює цей виклик на виконання методу суперблока конкретного драйвера файлової системи (`sb->s_op->statfs()`). Ця операція є атомарною з точки зору пам'яті ядра й виконується за сталий час `O(1)`, оскільки драйвер зчитує вже готові агреговані лічильники суперблока без рекурсивного сканування сховища.

### Опис та семантичне значення полів `struct statvfs`

Нижче наведено розгорнуту специфікацію полів структури `struct statvfs` відповідно до стандарту POSIX.1-2001 та реалізації в ядрі Linux.

* **`f_bsize` (`unsigned long`):** базовий розмір блоку файлової системи. Це розмір дискового блоку, яким оперує внутрішній алокатор драйвера (наприклад, 4096 байтів для типового екземпляра ext4 або XFS).
* **`f_frsize` (`unsigned long`):** фундаментальний розмір фрагмента виділення. **Усі лічильники блоків у структурі виражені саме в одиницях `f_frsize`!** На більшості локальних файлових систем Linux значення `f_frsize` ідентичне `f_bsize` (4096 байтів), однак на деяких спеціалізованих або мережевих файлових системах (NFS) ці значення можуть відрізнятися. Обчислення загального обсягу диска через множення на `f_bsize` замість `f_frsize` є класичною помилкою розробників системного софту.
* **`f_blocks` (`fsblkcnt_t`):** загальна кількість блоків розміром `f_frsize` у файловій системі. Це повна геометрична ємність розділу, виділена під збереження метаданих та даних користувачів.
* **`f_bfree` (`fsblkcnt_t`):** абсолютна кількість фізично вільних блоків на накопичувачі за глобальною бітовою картою виділення. Цей лічильник включає як простір, доступний для звичайних процесів, так і зарезервовані блоки суперкористувача (`root`).
* **`f_bavail` (`fsblkcnt_t`):** кількість вільних блоків, доступних для виділення непривілейованим процесам (процесам без адміністративної спроможності `CAP_SYS_RESOURCE`). Якщо вільний простір падає нижче порогу резерву root, `f_bavail` дорівнює 0, тоді як `f_bfree` залишається додатним.
* **`f_files` (`fsfilcnt_t`):** загальна кількість вузлів метаданих (інодів), сконфігурована у файловій системі. Для ext4 це число фіксується під час форматування, а для XFS та Btrfs обчислюється динамічно на основі поточного вільного місця.
* **`f_ffree` (`fsfilcnt_t`):** загальна кількість абсолютно вільних інодів, доступних для створення нових записів у системі.
* **`f_favail` (`fsfilcnt_t`):** кількість вільних інодів, доступних для непривілейованих користувачів з урахуванням квот та привілеїв.
* **`f_fsid` (`unsigned long`):** числовий ідентифікатор екземпляра файлової системи, який операційна система генерує під час монтування для розрізнення різних розділів у системних викликах.
* **`f_flag` (`unsigned long`):** бітова маска активних прапорців монтування точки VFS. Найважливіші біти: `ST_RDONLY` (розділ доступний лише для читання), `ST_NOSUID` (ігнорування бітів SUID), `ST_NODEV` (заборона звернення до файлів пристроїв), `ST_NOATIME` (відключення оновлення позначки часу доступу).
* **`f_namemax` (`unsigned long`):** максимальна довжина імені файлу в байтах, яку підтримує цей каталог (типово 255 символів для UTF-8 або ASCII).

### Правила розрахунку ємності за стандартом POSIX

Для побудови коректних інструментів системного моніторингу застосовуються такі обов'язкові формули:

```
Загальна ємність (байти)     = f_blocks × f_frsize
Фізично вільно (байти)       = f_bfree  × f_frsize
Доступно для user (байти)    = f_bavail × f_frsize
Зайнято простору (байти)     = (f_blocks - f_bfree) × f_frsize
Резерв суперкористувача      = (f_bfree - f_bavail) × f_frsize
Відсоток зайнятих інодів     = ((f_files - f_ffree) × 100) ÷ f_files
```

### Коди помилок системного виклику `statvfs`

* `EACCES` — процес не має прав на виконання пошуку (`execute/search`) для одного з проміжних каталогів у шляху `path`.
* `EBADF` — переданий дескриптор файлу у виклику `fstatvfs` не є дійсним відкритим дескриптором.
* `EFAULT` — покажчик на вихідну структуру `buf` або вхідний рядок `path` вказує на неприпустиму область віртуальної пам'яті.
* `EINTR` — виконання системного виклику було перервано доставкою сигналу процесу.
* `EIO` — виникла критична апаратна помилка вводу-виводу під час зчитування метаданих суперблока з диска.
* `ELOOP` — виявлено зациклення символьних посилань під час розбору переданого шляху.
* `ENAMETOOLONG` — довжина шляху або його компонента перевищує системні ліміти `PATH_MAX`.
* `ENOENT` — зазначений у виклику файл або точка монтування не існує.
* `ENOSYS` — базова файлова система не підтримує запит статистики (вкрай рідкісний випадок).
* `EOVERFLOW` — один із числових лічильників розміру блоків перевищує розрядність полів структури (на 32-бітних архітектурах без підтримки LFS).

## 2. Структура `struct stat` (одиниця виміру утиліти `du`)

Утиліта `du` під час рекурсивного обходу дерева звертається до кожного знайденого файлу через системні виклики `stat()`, `lstat()` або `fstatat()`. Заголовок: `<sys/stat.h>`.

На відміну від суперблока, структура `struct stat` надає інформацію виключно про конкретний інод. Під час підрахунку простору критично розрізняти логічний розмір файлу та його реальне фізичне виділення на носії.

### Семантика полів `struct stat` для обліку дискового простору

* **`st_dev` (`dev_t`):** числовий ідентифікатор пристрою блокового накопичувача, на якому розташовано файл. Утиліти обходу дерева (такі як `du -x` або `find -xdev`) порівнюють значення `st_dev` поточного каталогу з початковим, щоб автоматично зупиняти рекурсію й не заходити на інші змонтовані розділи.
* **`st_ino` (`ino_t`):** унікальний номер інода в межах файлової системи. Оскільки кілька записів у різних каталогах можуть вказувати на один і той самий інод (жорсткі посилання, *hardlinks*), `du` зобов'язана вести таблицю вже оброблених пар `(st_dev, st_ino)`. Якщо інод уже зустрічався під іншим ім'ям, його блоки не додаються повторно до загального підсумку.
* **`st_nlink` (`nlink_t`):** лічильник жорстких посилань на інод. Коли `st_nlink == 0`, це свідчить про стан видаленого відкритого файлу: ім'я в каталозі відсутнє, але активний дескриптор утримує метадані в пам'яті ядра.
* **`st_size` (`off_t`):** логічний розмір файлу в байтах. Це максимальне зміщення від початку файлу до останнього записаного байта. Для розріджених файлів (*sparse files*) значення `st_size` може становити сотні гігабайтів або терабайтів, тоді як реальне дискове споживання залишатиметься близьким до нуля.
* **`st_blocks` (`blkcnt_t`):** **реальна кількість виділених 512-байтових секторів.** Це фундаментальне поле для підрахунку фізичного місця. Незалежно від того, який розмір кластера використовує файлова система (4 КіБ, 8 КіБ чи 64 КіБ), поле `st_blocks` у стандарті POSIX **завжди виражається в одиницях по 512 байтів**. Утиліта `du` множить це поле на 512: `реальні байти = st_blocks × 512`.
* **`st_blksize` (`blksize_t`):** рекомендований операційною системою розмір буфера для ефективного виконання операцій вводу-виводу (типово 4096 байтів).

## 3. Формат інтерфейсу `/proc/[pid]/fdinfo/[fd]`

Псевдофайлова система `procfs` надає інженерам можливість глибинного аналізу стану кожного відкритого файлового дескриптора через віртуальний файл `/proc/[pid]/fdinfo/[fd]`.

Цей інтерфейс відображає поточний стан структури `struct file` у ядрі та містить текстові поля, розділені двокрапкою:

```
pos:    104857600
flags:  0100002
mnt_id: 28
ino:    419204
```

### Розбір полів `fdinfo`

* **`pos:`** — поточне десяткове зміщення вказівника файлової позиції (`f_pos`) у байтах. Показує, в яке саме місце файлу буде здійснено наступний виклик `read()` або `write()`. Якщо файл було обнулено через `ftruncate()`, але його було відкрито без прапорця `O_APPEND`, поле `pos` залишиться на старій позиції, і наступний запис утворить розріджену дірку.
* **`flags:`** — вісімкове представлення бітових прапорців режиму відкриття дескриптора (`f_flags`). Дозволяє перевірити, чи відкрито файл на запис (`O_WRONLY = 01`, `O_RDWR = 02`), чи встановлено блокування (`O_NONBLOCK = 04000`), чи активний прапорець автоматичного переміщення покажчика на кінець файлу (`O_APPEND = 02000`).
* **`mnt_id:`** — унікальний системний ідентифікатор точки монтування. Зіставивши це число з таблицею `/proc/self/mountinfo`, інженер може однозначно встановити, на якому саме блоковому пристрої та в якій точці VFS фізично лежить цей дескриптор.
* **`ino:`** — числовий номер інода файлу на відповідній файловій системі. Дає змогу зв'язати відкритий дескриптор із записом у звітах `lsof` або результатами низькорівневого аналізу файлової системи через `debugfs`.

## 4. Системний виклик `fallocate()` та деалокація блоків

Системний виклик `fallocate(int fd, int mode, off_t offset, off_t len)` є головним інструментом прямого керування дисковими екстентами відкритого файлу в сучасних файлових системах Linux (ext4, XFS, Btrfs, tmpfs). Заголовок: `<fcntl.h>`.

Цей інтерфейс дозволяє не лише попередньо виділяти неініціалізовані дискові блоки для запобігання помилкам `ENOSPC`, але й вивільняти непотрібні гігабайти без закриття дескриптора.

### Режими роботи (`mode`) виклику `fallocate`

* **`0` (стандартне виділення):** виділяє фізичні дискові блоки в заданому діапазоні від `offset` довжиною `len` без запису нульових байтів. Блоки помічаються як неініціалізовані. Якщо новий кінець діапазону перевищує поточний розмір файлу, поле `st_size` автоматично збільшується.
* **`FALLOC_FL_KEEP_SIZE` (`0x01`):** прапорець-модифікатор, який забороняє зміну логічного розміру файлу (`st_size`). Фізичні блоки виділяються або звільняються, але логічна довжина файлу залишається абсолютно незмінною.
* **`FALLOC_FL_PUNCH_HOLE` (`0x02`):** **пробивання дірки (деалокація блоків).** Звільняє фізичні блоки дискового простору в діапазоні `[offset, offset + len)`, повертаючи їх у глобальний пул вільних блоків суперблока. Будь-яке подальше читання з цього діапазону повертає нулі. **Цей прапорець обов'язково застосовується разом із `FALLOC_FL_KEEP_SIZE`!** Це дозволяє звільнити 100 ГБ з активного відкритого файлу журналів на льоту, не переміщуючи покажчик `f_pos` процесу.
* **`FALLOC_FL_COLLAPSE_RANGE` (`0x08`):** повністю вирізає заданий діапазон блоків із файлу без утворення дірок, автоматично зсуваючи всі наступні блоки вліво на довжину `len` та зменшуючи розмір файлу. Дозволяє ефективно обрізати початок великих лог-файлів.
* **`FALLOC_FL_ZERO_RANGE` (`0x10`):** перетворює діапазон блоків у нулі на рівні екстентів метаданих без необхідності запису нульових сторінок на фізичний носій.

## 5. Прапорці утиліти `lsof` для діагностики відкритих дескрипторів

Утиліта `lsof` сканує структури процесів ядра, зіставляючи дескриптори з записами файлових систем.

* **`lsof +L1`:** виводить список відкритих файлів, у яких лічильник жорстких посилань `nlink` строго менший за 1. Це головна команда для миттєвого виявлення видалених файлів, які продовжують утримувати дисковий простір.
* **`lsof +L1 /каталог`:** обмежує зону пошуку видалених файлів конкретною точкою монтування або каталогом (наприклад, `lsof +L1 /var`).
* **`lsof -a -p <PID> +L1`:** застосовує логічне об'єднання умов (`AND` через `-a`), знаходячи всі видалені відкриті дескриптори всередині конкретного процесу з ідентифікатором `<PID>`.
* **`lsof +D <шлях>`:** виконує рекурсивний аналіз дерева каталогів і виводить усі процеси, які утримують будь-які відкриті дескриптори всередині зазначеного каталогу (корисно перед спробою розмонтування `umount`).

## 6. Керування службовими параметрами Ext4 через `tune2fs`

Утиліта `tune2fs` дозволяє переглядати та змінювати критичні конфігураційні параметри суперблока файлових систем ext2/3/4 безпосередньо на накопичувачі без переформатування.

* **`tune2fs -m <відсоток> <пристрій>`:** встановлює відсоток дискового простору, зарезервованого виключно для використання суперкористувачем `root` (типово 5%). На розділах даних великої ємності встановлюють значення 1% або 0%: `tune2fs -m 1 /dev/sdb1`.
* **`tune2fs -r <блоків> <пристрій>`:** задає резерв суперкористувача як точну абсолютну кількість блоків файлової системи (наприклад, `tune2fs -r 262144 /dev/sdb1` резервує рівно 1 ГіБ при розмірі блоку 4 КіБ).
* **`tune2fs -l <пристрій>`:** виводить повний перелік метаданих суперблока, включаючи загальну кількість блоків, обсяг резерву, кількість вільних інодів та ідентифікатор UUID.
