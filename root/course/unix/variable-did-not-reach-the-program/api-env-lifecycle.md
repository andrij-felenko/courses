# 📋 Довідник системних інтерфейсів керування середовищем процесу: POSIX C API та директиви оболонки

Керування змінними середовища в операційних системах сімейства Unix здійснюється на двох архітектурних рівнях: через системні виклики ядра Linux і функції стандартної бібліотеки мови C (стандарти POSIX.1-2008 / Single UNIX Specification та ISO C) і через синтаксичні конструкції та вбудовані директиви командних оболонок (POSIX sh, Bash, Dash, Zsh).

Цей довідник містить систематичний опис сигнатур, параметрів, статусів повернення, прапорців, інваріантів керування пам'яттю та обмежень безпеки для кожного інтерфейсу маніпуляції оточенням процесів.

## 1. Системні виклики ядра Linux

На рівні ядра операційної системи передача змінних середовища відбувається виключно під час завантаження нового виконуваного образу. Ядро не надає системного виклику для зміни середовища чужого вже запущеного процесу — це суперечило б базовій моделі ізоляції віртуальної пам'яті.

### Системний виклик execve

Системний виклик `execve` є єдиною точкою входу ядра, через яку формується таблиця змінних середовища для нової програми.

:::tabs
```c
#include <unistd.h>

int execve(const char *pathname, char *const argv[], char *const envp[]);
```
```cpp
#include <unistd.h>
#include <string_view>
#include <span>
#include <vector>

namespace sys {
// C++23 типізована обгортка для прямого виклику execve
inline int exec_raw(std::string_view path,
                    std::span<char* const> argv,
                    std::span<char* const> envp) noexcept {
    return ::execve(path.data(), argv.data(), envp.data());
}
}
```
:::

- **Параметр `pathname`**: абсолютний або відносний шлях до бінарного файлу ELF чи текстового скрипту із шебангом `#!`.
- **Параметр `argv`**: масив покажчиків на рядки аргументів командного рядка, що завершується елементом `NULL`.
- **Параметр `envp`**: масив покажчиків на рядки формату `КЛЮЧ=ЗНАЧЕННЯ`, що завершується елементом `NULL`. Якщо передати `envp = NULL`, ядро створить процес із повністю порожнім середовищем.
- **Повертане значення**: у разі успіху функція **не повертає керування взагалі**, оскільки старий адресний простір повністю знищується. У разі помилки повертає `-1` і встановлює глобальну змінну `errno`.

#### Типові коди помилок execve
- `E2BIG`: сумарний обсяг байтів аргументів `argv` та середовища `envp` перевищує системний ліміт ядра (1/4 від поточного ліміту стека `RLIMIT_STACK`, типово до 2 МБ).
- `EACCES`: відсутнє право на виконання файлу (`chmod +x`), шлях вказує не на звичайний файл або розділ змонтовано з прапорцем `noexec`.
- `ENOENT`: виконуваний файл не існує або відсутній інтерпретатор, вказаний у шебанзі `#!` чи секції `.interp` (динамічний лінкер `ld-linux.so`).
- `ENOMEM`: ядру бракує фізичної або віртуальної пам'яті для виділення початкового стека новому процесу.
- `EFAULT`: один із покажчиків у масивах `argv` чи `envp` вказує за межі дозволеного адресного простору процесу.

### Системний виклик execveat

Розширення ядра Linux (починаючи з версії 3.19), що дозволяє виконувати заміну образу відносно відкритого файлового дескриптора каталогу або безіменного файлу в пам'яті (`memfd_create`), що усуває стан гонитви за шляхом (Time-of-Check to Time-of-Use, TOCTOU).

:::tabs
```c
#include <unistd.h>
#include <fcntl.h>

int execveat(int dirfd, const char *pathname,
             char *const argv[], char *const envp[], int flags);
```
```cpp
#include <unistd.h>
#include <fcntl.h>
#include <string_view>
#include <span>

namespace sys {
inline int exec_at(int dirfd, std::string_view path,
                   std::span<char* const> argv,
                   std::span<char* const> envp,
                   int flags = 0) noexcept {
    return ::execveat(dirfd, path.data(), argv.data(), envp.data(), flags);
}
}
```
:::

- **Параметр `dirfd`**: відкритий дескриптор каталогу або спеціальне значення `AT_FDCWD` (поточний робочий каталог).
- **Параметр `flags`**: бітова маска модифікації поведінки (наприклад, `AT_EMPTY_PATH` для запуску програми безпосередньо з дескриптора файлу `memfd` без наявності шляху у файловій системі).

## 2. Функції стандартної бібліотеки C (POSIX / glibc)

Усі стандартні бібліотечні функції маніпуляції середовищем працюють у просторі користувача та оголошені у заголовному файлі `<stdlib.h>`. Вони керують глобальним покажчиком `extern char **environ`.

### Читання змінних: getenv та secure_getenv

:::tabs
```c
#include <stdlib.h>

char *getenv(const char *name);
char *secure_getenv(const char *name); /* GNU-розширення */
```
```cpp
#include <cstdlib>
#include <string_view>
#include <optional>

namespace sys {
[[nodiscard]] inline std::optional<std::string_view> get_env_var(std::string_view name) noexcept {
    if (const char* val = std::getenv(name.data())) {
        return std::string_view(val);
    }
    return std::nullopt;
}
}
```
:::

- **Призначення `getenv`**: виконує лінійний пошук у масиві покажчиків `environ` рядка, початок якого збігається з `name` і супроводжується символом `=`. Повертає покажчик на перший байт значення після знака `=` або `NULL`, якщо змінну не знайдено.
- **Особливість пам'яті**: рядок, повернутий `getenv`, належить внутрішньому блоку середовища. Його **заборонено** передавати у функцію `free()`.
- **Призначення `secure_getenv`**: повертає `NULL`, якщо процес виконується у захищеному режимі (прапорець `AT_SECURE` активний через біти `setuid`/`setgid`, файлові можливості capabilities або обмеження LSM-модулів AppArmor/SELinux). Це захищає привілейовані програми від ін'єкції шкідливого коду через змінні `LD_PRELOAD`, `LD_LIBRARY_PATH` та `TMPDIR`.

### Запис та зміна змінних: setenv та putenv

:::tabs
```c
#include <stdlib.h>

int setenv(const char *name, const char *value, int overwrite);
int putenv(char *string);
```
```cpp
#include <cstdlib>
#include <string>
#include <expected>
#include <system_error>

namespace sys {
[[nodiscard]] inline std::expected<void, std::error_code>
set_env_var(const std::string& name, const std::string& value, bool overwrite = true) noexcept {
    if (::setenv(name.c_str(), value.c_str(), overwrite ? 1 : 0) != 0) {
        return std::unexpected(std::error_code(errno, std::generic_category()));
    }
    return {};
}
}
```
:::

- **Функція `setenv` (рекомендований POSIX-інтерфейс)**:
  - Виділяє нову пам'ять на купі (`malloc`) для копіювання імені та значення, формуючи рядок `name=value`.
  - Якщо `overwrite == 0` і змінна вже існує, стан середовища не змінюється і функція повертає `0`.
  - Якщо змінної не було, розширює масив покажчиків `environ`, виділяючи для нього новий блок на купі.
- **Функція `putenv` (застарілий інтерфейс SVID / POSIX)**:
  - Приймає покажчик на існуючий рядок `string` формату `"NAME=VALUE"`.
  - **Не копіює дані**: переданий рядок стає безпосередньою частиною середовища процесу. Якщо передати туди покажчик на автоматичну змінну зі стека функції, після виходу з неї середовище міститиме висячий покажчик (Dangling Pointer / Use-After-Free).
  - Рядок не можна звільняти через `free()` або модифікувати після виклику `putenv`.

### Видалення та повне очищення: unsetenv та clearenv

:::tabs
```c
#include <stdlib.h>

int unsetenv(const char *name);
int clearenv(void); /* POSIX.1-2024 / Linux glibc */
```
```cpp
#include <cstdlib>
#include <string_view>
#include <expected>
#include <system_error>

namespace sys {
[[nodiscard]] inline std::expected<void, std::error_code>
unset_env_var(std::string_view name) noexcept {
    if (::unsetenv(name.data()) != 0) {
        return std::unexpected(std::error_code(errno, std::generic_category()));
    }
    return {};
}

inline void clear_all_env() noexcept {
    ::clearenv();
}
}
```
:::

- **Функція `unsetenv`**: видаляє всі входження змінної `name` з масиву `environ`, зміщуючи наступні покажчики масиву вліво. Якщо змінної немає, виклик завершується успішно (`0`).
- **Функція `clearenv`**: повністю очищає таблицю середовища, встановлюючи покажчик `environ` у `NULL` (або виділяючи порожній масив із одного елемента `NULL`). Є обов'язковим інструментом безпеки для системних демонів та лаунчерів перед завантаженням неперевіреного коду.

### Проблема потокобезпечності (Multithreading Race Conditions)

Функції `setenv`, `putenv`, `unsetenv` та `getenv` у стандартній бібліотеці glibc не є потокобезпечними (Thread-Unsafe):
1. Якщо один потік викликає `getenv("PATH")`, а паралельний потік у цей самий момент викликає `setenv("NEW_VAR", "1", 1)`, функція `setenv` може викликати `realloc` для масиву `environ`.
2. Попередній блок покажчиків вивільняється, і перший потік звертається до недійсної пам'яті (стан гонитви та потенційний Segmentation Fault).
3. **Правило архітектури**: налаштування змінних середовища слід виконувати на етапі однопотокової ініціалізації програми до створення потоків `pthread_create` чи `std::jthread`, або захищати всі виклики спільним м'ютексом.

## 3. Команди та вбудовані директиви командної оболонки

| Команда / Конструкція | Синтаксис | Область дії та механіка |
|---|---|---|
| **Локальне присвоєння** | `VAR="value"` | Зберігає значення **виключно** у внутрішній таблиці поточної оболонки. Прапорець `att_exported` не встановлюється. Дочірні процеси змінну не отримують. |
| **Експорт змінної** | `export VAR` або `export VAR="val"` | Встановлює прапорець `att_exported`. Оболонка автоматично додає рядок у масив `envp` під час наступних викликів `execve`. |
| **Зняття експорту** | `export -n VAR` | Скидає прапорець експорту. Змінна залишається доступною локально в оболонці, але перестає передаватися дочірнім процесам. |
| **Вивід експортованих** | `export -p` | Виводить список усіх експортованих змінних у форматі POSIX-декларацій (`export VAR="val"`), готових для збереження та повторного завантаження. |
| **Типізований експорт** | `declare -x VAR` / `typeset -x VAR` | Аналог `export` у Bash, Zsh та Ksh; дозволяє комбінувати експорт із захистом від запису (`declare -rx VAR="val"`). |
| **Одноразовий префікс** | `VAR="val" command` | Тимчасово додає змінну до масиву `envp` **тільки** для дочірнього процесу `command`. Не змінює стан батьківської оболонки. |
| **Запуск у чистому оточенні** | `env -i [KEY=VAL...] command` | Запускає `command` з повністю порожнім або точно перевизначеним масивом середовища, ігноруючи `environ` оболонки. |
| **Видалення з виклику** | `env -u VAR command` | Запускає `command`, видаливши змінну `VAR` з успадкованого масиву середовища. |
| **Режим lastpipe** | `shopt -s lastpipe` | Змушує останню ланку конвеєра (`cmd \| while read ...`) виконуватися безпосередньо у батьківському процесі оболонки (за умови вимкненого job control `set +m`). |
| **Підстановка процесу** | `command < <(generator)` | Виконує основний цикл у поточному процесі оболонки, читаючи потік генератора через анонімний дескриптор `/dev/fd/N`. Зберігає всі мутації змінних у батьківській пам'яті. |
