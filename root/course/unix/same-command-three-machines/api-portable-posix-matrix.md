# 📋 Довідник переносимості команд: GNU vs BSD vs BusyBox vs POSIX.1-2024

При написанні системних скриптів та конвеєрів CI/CD різниця у поведінці стандартних утиліт командного рядка є головним джерелом прихованих помилок. Цей довідник містить систематичне інженерне порівняння дванадцяти ключових утиліт Unix у чотирьох вимірах: реалізації **GNU Coreutils** (Linux), **BSD Userland** (FreeBSD / macOS), **BusyBox** (Alpine Linux / Embedded) та базового стандарту **POSIX.1-2024 (IEEE Std 1003.1)**. Для кожної команди наведено детальний аналіз внутрішнього механізму, типові пастки та готові переносні еквіваленти.

## 1. Редагування тексту на місці: `sed`

Потоковий редактор `sed` створювався для конвеєрної обробки потоків тексту через стандартні дескриптори вводу-виводу. Модифікація файлу безпосередньо на диску стала пізнішим розширенням, яке автори різних екосистем реалізували з несумісним синтаксисом.

| Критерій | GNU sed (Linux) | BSD sed (macOS / FreeBSD) | BusyBox sed (Alpine) | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Редагування на місці** | `sed -i[SUFFIX]` (аргумент опціональний) | `sed -i SUFFIX` (аргумент обов'язковий) | `sed -i` або `sed -i .bak` | **Не стандартизовано** (відсутнє в POSIX) |
| **Редагування без бекапу** | `sed -i 's/.../' file` | `sed -i '' 's/.../' file` | `sed -i 's/.../' file` | Використовувати тимчасовий файл |
| **Розширені регулярні вирази** | `sed -E` або `sed -r` | `sed -E` (`-r` відсутній) | `sed -E` (якщо зібрано з підтримкою) | `sed -E` (додано в POSIX.1-2024) |
| **Межа слова** | `\b` або `\< \>` | `[[:<:]]` та `[[:>:]]` | Залежить від збірки regex | Класи символів POSIX |

### Механізм розбіжності та пастки
Головна проблема полягає в інтерпретації суфікса резервної копії. У бібліотеці GNU C специфікатор опції визначений як `i::` (два двокрапки означають необов'язковий аргумент, який повинен бути приклеєний до літери впритул). У BSD libc специфікатор визначений як `i:` (одна двокрапка означає обов'язковий аргумент, тому наступне слово в рядку завжди забирається як розширення бекапу).

Якщо на Linux виконати команду з порожніми лапками `sed -i '' 's/a/b/' file`, GNU sed сприйме порожні лапки як першу інструкцію `sed` (порожню команду), вираз заміни — як ім'я першого файлу, а `file` — як ім'я другого файлу. Якщо ж на macOS виконати команду без лапок `sed -i 's/a/b/' file`, BSD sed сприйме вираз заміни як суфікс бекапу, а ім'я файлу спробує виконати як код sed.

✅ **Портативний еквівалент через тимчасовий файл:**
```shell
sed 's/search/replace/g' input.txt > input.tmp && mv input.tmp input.txt
```

## 2. Робота з датою та часом: `date`

Утиліта `date` використовується для аудиту, формування міток часу в логах та обчислення часових вікон. Конфлікт між реалізаціями полягає у наявності або відсутності вбудованого обчислювача часових зсувів.

| Критерій | GNU date | BSD date (macOS) | BusyBox date | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Парсинг довільного рядка** | `date -d "yesterday"` | Немає (або daylight savings) | Немає | **Не стандартизовано** |
| **Відносні зсуви часу** | `date -d "+2 days"` | `date -v+2d` | Немає | **Не стандартизовано** |
| **Форматування Epoch Unix** | `date -d @1700000000` | `date -r 1700000000` | `date -d @1700000000` | **Не стандартизовано** |
| **Поточний час в Epoch** | `date +%s` | `date +%s` | `date +%s` | `date +%s` (POSIX.1-2024) |
| **Форматування за UTC** | `date -u +FORMAT` | `date -u +FORMAT` | `date -u +FORMAT` | `date -u [+format]` |

### Механізм розбіжності та пастки
GNU date містить повноцінний лексичний аналізатор природної мови, скомпільований через Bison. Він розпізнає назви місяців, відносні конструкції (`3 days ago`, `next monday`) та часові пояси. Утиліта BSD date позбавлена лексичного аналізатора і використовує суворі математичні модифікатори `-v` (value modifier). Утиліта BusyBox date не підтримує жодного з цих підходів і вміє лише форматувати поточний час або розбирати фіксовані ISO-рядки.

✅ **Портативний еквівалент (обчислення дати 24 години тому):**
```shell
awk 'BEGIN { print strftime("%Y-%m-%d", systime() - 86400, 1) }'
```

## 3. Моніторинг процесів: `ps`

Утиліта `ps` відображає таблицю активних процесів. Вона поєднує спадщину гілок System V (дефісні опції) та BSD (бездефісні прапорці).

| Критерій | GNU procps (Linux) | BSD ps (macOS) | BusyBox ps | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Синтаксис виклику** | Підтримує `-ef`, `aux`, `ax` | Традиційний `aux`, `ax`, `-ef` | Спрощений `ps`, `-o` | Тільки синтаксис із дефісом: `ps -ef` |
| **Вибір усіх процесів** | `ps -e` або `ps -A` або `ps ax` | `ps -A` або `ps ax` | `ps` або `ps -A` | `ps -A` або `ps -e` |
| **Користувацький формат виводу** | `ps -o pid,comm,vsz` | `ps -o pid,comm,vsize` | `ps -o pid,comm` (обмежено) | `ps -o format_specifiers` |
| **Приховування заголовків** | `ps --no-headers` або `-o pid=` | `ps -o pid=` | `ps -o pid=` | `ps -o pid=` (знак рівності) |

### Механізм розбіжності та пастки
Команда `ps aux` походить із BSD, де `a` означає всі процеси з терміналом, `u` — формат користувача, `x` — процеси без терміналу. Якщо на Linux написати `ps -aux` (з дефісом), пакет `procps` розцінює `-u` як запит процесів користувача, а літеру `x` — як ім'я користувача `x`. У результаті виводиться або порожній список, або повідомлення `Warning: bad ps syntax`.

✅ **Портативний еквівалент:**
```shell
ps -A -o pid=,user=,comm=
```

## 4. Створення та розпакування архівів: `tar`

Історична утиліта для запису архівів на магнітні стрічки (`tar`) у сучасному світі виконує пакування та розпакування стиснутих файлів.

| Критерій | GNU tar | BSD tar (libarchive) | BusyBox tar | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Синтаксис без дефіса** | `tar czf arch.tar.gz dir` | `tar czf arch.tar.gz dir` | `tar czf arch.tar.gz dir` | Застарілий (legacy V7) |
| **Автовизначення компресії** | `tar -xf archive.*` | `tar -xf archive.*` | Потрібен явний `-z`/`-j` | **Не стандартизовано** |
| **Формат архіву за замовчуванням** | GNU tar format / POSIX pax | ustar / pax / cpio / zip | ustar / v7 | Офіційна утиліта — `pax` |
| **Виключення файлів** | `--exclude="pattern"` | `--exclude "pattern"` | Часто відсутня | Немає в tar |

### Механізм розбіжності та пастки
GNU tar автоматично зчитує магічні байти заголовка архіву і самостійно передає потік через декомпресор (gzip, bzip2, xz, zstd). Утиліта BusyBox tar у мінімальних конфігураціях не має внутрішньої автодетекції і без прапорця `-z` намагається розібрати стиснутий бінарний потік як текстові заголовки ustar, завершуючись помилкою `Invalid tar magic`.

✅ **Портативний еквівалент розпакування через конвеєр:**
```shell
gzip -dc archive.tar.gz | tar -xf -
```

## 5. Пошук шаблонів у тексті: `grep`

Утиліта `grep` реалізує фільтрацію рядків за регулярними виразами. Розкол між версіями зосереджений навколо рушіїв складних виразів.

| Критерій | GNU grep | BSD grep (macOS) | BusyBox grep | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Perl-сумісні вирази (PCRE)** | `grep -P` (через libpcre) | Відсутній (або експериментальний) | Відсутній | **Не стандартизовано** |
| **Розширені вирази (ERE)** | `grep -E` (або `egrep`) | `grep -E` | `grep -E` | `grep -E` |
| **Фіксовані рядки (без regex)** | `grep -F` (або `fgrep`) | `grep -F` | `grep -F` | `grep -F` |
| **Контекстні рядки** | `grep -A 2 -B 2` | `grep -A 2 -B 2` | `grep -A 2 -B 2` (якщо увімкнено) | **Не стандартизовано** |
| **Тихий режим (наявність збігу)** | `grep -q` | `grep -q` | `grep -q` | `grep -q` |

### Механізм розбіжності та пастки
Прапорець `grep -P` підтримується лише тоді, коли утиліту зібрано з динамічною або статичною бібліотекою `libpcre`. На macOS та в середовищах на базі BusyBox ця залежність відсутня, тому будь-яке використання розширених квантифікаторів Perl або конструкцій lookaround призводить до негайного аварійного завершення.

✅ **Портативний еквівалент (lookahead замінюємо логікою awk):**
```shell
awk '/version=/ { sub(/.*version=/, ""); sub(/ .*/, ""); print }' config.txt
```

## 6. Вивід тексту: `echo` проти `printf`

Команда `echo` є найбільш оманливою конструкцією командного рядка: зовні проста, вона має найбільшу кількість взаємовиключних варіантів реалізації серед різних оболонок.

| Критерій | `echo` у bash | `echo` у dash / FreeBSD sh | `echo` у zsh | `printf` (усі оболонки) |
| :--- | :--- | :--- | :--- | :--- |
| **Придушення нового рядка** | `echo -n "text"` | `echo "text\c"` | `echo -n "text"` | `printf '%s' "text"` |
| **Екранування escape (`\n`, `\t`)** | `echo -e "a\tb"` | `echo "a\tb"` (за замовчуванням) | `echo -e "a\tb"` | `printf '%b\n' "a\tb"` |
| **Вивід довільних змінних** | Ламається на `-n` або `-e` | Ламається на бекслешах | Ламається на прапорцях | `printf '%s\n' "${var}"` |

### Механізм розбіжності та пастки
Стандарт POSIX прямо оголошує поведінку `echo` з прапорцем `-n` або керівними символами зі зворотним слешем як не визначену реалізацією (Implementation Defined). Якщо у змінній виявиться значення `-n`, команда `echo "${var}"` у bash не виведе нічого, сприйнявши значення змінної як власний прапорець.

✅ **Портативний еквівалент:**
```shell
printf '%s\n' "${variable}"
```

## 7. Пошук файлів у дереві каталогів: `find`

Утиліта `find` здійснює рекурсивний обхід файлової системи. Головні розбіжності стосуються обмеження глибини пошуку та передачі безпечних розділювачів.

| Критерій | GNU find | BSD find | BusyBox find | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Обмеження глибини** | `find . -maxdepth 1` | `find . -maxdepth 1` | `find . -maxdepth 1` (якщо є) | **Не стандартизовано** (через `-prune`) |
| **Розділювач NULL (`\0`)** | `find . -print0` | `find . -print0` | `find . -print0` | `find . -print0` (POSIX.1-2024) |
| **Виконання для кожного файлу** | `find . -exec cmd {} +` | `find . -exec cmd {} +` | `find . -exec cmd {} +` | `find . -exec cmd {} +` |
| **Перевірка типу файлу** | `-type f`, `-type d`, `-type l` | `-type f`, `-type d`, `-type l` | `-type f`, `-type d`, `-type l` | `-type [f|d|b|c|p|l|s]` |

### Механізм розбіжності та пастки
Прапорець `-maxdepth` відсутній у класичному стандарті POSIX. Для заборони рекурсивного заглиблення у підкаталоги стандартним методом є предикат відсікання гілок `-prune`.

✅ **Портативний еквівалент пошуку лише у поточному каталозі:**
```shell
find . -path './*' -prune -o -type f -print
```

## 8. Пакетна передача аргументів: `xargs`

Утиліта `xargs` читає елементи зі стандартного вводу і формує виклики цільової команди з урахуванням обмеження довжини рядка `ARG_MAX`.

| Критерій | GNU xargs | BSD xargs | BusyBox xargs | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Розділювач NULL (`\0`)** | `xargs -0` | `xargs -0` | `xargs -0` | `xargs -0` (POSIX.1-2024) |
| **Порожній вхід (не викликати)** | `xargs -r` (`--no-run-if-empty`) | `xargs` за замовчуванням (не треба) | `xargs -r` | `xargs` у POSIX виконує 1 раз! |
| **Підстановка в довільне місце** | `xargs -I {} cmd {}` | `xargs -I {} cmd {}` | `xargs -I {} cmd {}` | `xargs -I replstr` |

### Механізм розбіжності та пастки
За стандартом POSIX, якщо вхідний потік порожній, `xargs` зобов'язаний запустити цільову утиліту щонайменше один раз без аргументів. Команда `find . -name "*.bak" | xargs rm` при відсутності файлів виконає `rm` без параметрів і поверне код помилки 1. У GNU це вирішується прапорцем `-r`, який у чистому BSD відсутній.

✅ **Портативний еквівалент із пакетним запуском через `find`:**
```shell
find . -type f -name "*.bak" -exec rm -f {} +
```

## 9. Безпечне створення тимчасових ресурсів: `mktemp`

Утиліта `mktemp` створює унікальні файли або каталоги в `/tmp`, захищені від атак через символьні посилання (symlink race conditions).

| Критерій | GNU mktemp | BSD mktemp (macOS) | BusyBox mktemp | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Виклик без аргументів** | `mktemp` (створює `/tmp/tmp.XXXXXX`) | Помилка: вимагає шаблон | `mktemp` (створює `/tmp/tmp.XXXXXX`) | **Не стандартизовано** |
| **Створення тимчасового каталогу** | `mktemp -d` | `mktemp -d -t prefix` | `mktemp -d` | **Не стандартизовано** |
| **Префікс шаблону** | `mktemp -t prefix.XXXXXX` | `mktemp -t prefix` (без XXXXXX) | `mktemp -t prefix.XXXXXX` | **Не стандартизовано** |

### Механізм розбіжності та пастки
На Linux виклик `mktemp -d` успішно створює каталог. На macOS той самий виклик завершується фатальною помилкою, оскільки BSD mktemp вимагає обов'язкової передачі шаблону або прапорця `-t`.

✅ **Портативний еквівалент створення тимчасового каталогу:**
```shell
TMP_DIR="$(mktemp -d 2>/dev/null || mktemp -d -t 'mytmp.XXXXXX' || mktemp -d '/tmp/mytmp.XXXXXX')"
```

## 10. Канонізація файлових шляхів: `readlink` та `realpath`

Канонізація розкриває всі символьні посилання та відносні сегменти (`..`, `.`), повертаючи абсолютний шлях до цільового файлу.

| Критерій | GNU readlink / realpath | BSD readlink (macOS) | BusyBox readlink | Стандарт POSIX |
| :--- | :--- | :--- | :--- | :--- |
| **Канонічний абсолютний шлях** | `readlink -f path` або `realpath` | `readlink` не знає `-f`; `realpath` | `readlink -f path` | `realpath` (POSIX.1-2024) |
| **Поведінка якщо файл не існує** | `readlink -m path` | Помилка | Помилка | Помилка |

### Механізм розбіжності та пастки
Конструкція `SCRIPT_DIR="$(dirname "$(readlink -f "$0")")"` є стандартною для Linux, але миттєво ламається на macOS, оскільки тамтешній `readlink` не підтримує прапорець `-f`.

✅ **Портативний еквівалент визначення каталогу скрипта:**
```shell
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd -P)"
```

## 11. Обробка структурованого тексту: `awk`

Мова `awk` призначена для обробки текстових таблиць і потоків даних. У сучасних дистрибутивах встановлюються різні рушії: `gawk` (GNU), `mawk` (Debian за замовчуванням), `nawk` (One True AWK на macOS) або BusyBox awk.

| Можливість | gawk (GNU awk) | nawk (macOS) | mawk (Debian) | BusyBox awk |
| :--- | :--- | :--- | :--- | :--- |
| **Заміна regex з групами** | `gensub(/(\w+)/, "\\1", "g")` | Відсутній | Відсутній | Відсутній |
| **Розділювач полів regex** | `FPAT = "[^,]+"` | Відсутній | Відсутній | Відсутній |
| **Масиви масивів (багатовимірні)** | Підтримуються | Відсутні | Відсутні | Відсутні |
| **Функції часу (`systime`, `strftime`)** | Вбудовані | Вбудовані | Відсутні у mawk1 | Вбудовані |

### Механізм розбіжності та пастки
Функція `gensub()` дозволяє використовувати зворотні посилання на групи захоплення (`\\1`, `\\2`), але вона існує виключно в `gawk`. Виклик `gensub()` у середовищі macOS або Alpine завершується фатальною помилкою інтерпретатора.

✅ **Портативний еквівалент:** Використовуйте стандартні функції POSIX: `sub()`, `gsub()`, `match()`, `split()`.

## 12. Перевірка наявності утиліт: `which` проти `command`

Перед викликом зовнішніх інструментів скрипт повинен перевірити їхню наявність у змінній середовища `PATH`.

| Критерій | `which` (зовнішній бінарник) | `type` (вбудована команда) | `command -v` (вбудована POSIX) |
| :--- | :--- | :--- | :--- |
| **Стандартизація** | Не стандартизовано (поведінка різна) | Специфіка конкретної оболонки | **Офіційний стандарт POSIX** |
| **Код повернення якщо нема** | Може повертати 0 навіть при помилці | Залежить від оболонки | Гарантовано не нуль (>0) |
| **Аліаси та функції** | Часто не бачить аліасів | Виводить форматований текст | Повертає назву команди або шлях |

### Механізм розбіжності та пастки
Зовнішня програма `which` не є частиною стандарту POSIX. На деяких системах вона є csh-скриптом, на інших — бінарником, а на застарілих версіях повертає статус 0, навіть якщо шукану програму не знайдено в `PATH`.

✅ **Портативний еквівалент:**
```shell
if command -v curl >/dev/null 2>&1; then
    FETCH="curl -fsSL"
elif command -v wget >/dev/null 2>&1; then
    FETCH="wget -qO-"
else
    printf 'Помилка: не знайдено ні curl, ні wget\n' >&2
    exit 1
fi
```
