# 🔌 Спектр середовищ виконання: архітектурна матриця

Вибір середовища для запуску Unix-застосунків визначає не лише зручність запуску консолі, а й фундаментальні властивості обчислень: доступ до апаратних кілець процесора, накладні витрати на перемикання контексту, швидкість дискових операцій та межі ізоляції збоїв.

Для розуміння того, чим [голе залізо (Bare Metal)](root:unix/where-to-get-a-system) відрізняється від віртуальних машин, легких мікро-ВМ WSL2, контейнерів або трансляторів API на кшталт Cygwin, необхідно зіставити їх за ключовими системними параметрами.

## Порівняльна матриця архітектур виконання

У таблиці наведено зіставлення семи основних підходів до організації Unix-сумісного середовища за їхніми апаратними та програмними властивостями:

## Поглиблений архітектурний розбір механізмів

Щоб обрати оптимальний інструмент під конкретну інженерну задачу, необхідно розуміти фізичні процеси, що відбуваються всередині центрального процесора, контролера пам'яті та дискової підсистеми для кожного варіанта.

### 1. Голе залізо (Bare Metal)

Фізичне встановлення дистрибутива Linux усуває будь-які проміжні рівні абстракції між кодом операційної системи та транзисторами процесора.

- **Апаратні кільця та винятки:** Процесор стартує безпосередньо в режимі реального часу (Real Mode) або Long Mode, ініціалізує таблиці дескрипторів переривань (IDT) та переходить у Ring 0. Кожен системний виклик користувача виконується за мінімальний час апаратного перемикання стеків `RSP` -> `TSS.RSP0`.
- **Трансляція пам'яті:** Блок MMU використовує єдиний набір чотирирівневих (PML4) або п'ятирівневих (PML5) таблиць сторінок. Апаратний буфер асоціативної трансляції (TLB) працює з максимальною ефективністю, оскільки ідентифікатори адресних просторів (PCID) не розділяються з гіпервізором.
- **Введення-виведення:** Драйвери блокових накопичувачів записують черги команд (Submission Queues) безпосередньо в пам'ять контролера NVMe через шину PCIe, досягаючи мільйонів операцій вводу-виводу на секунду (IOPS) із субмікросекундними затримками.
- **Сфера застосування:** Високонавантажені бази даних, системи реального часу з патчами RT-PREEMPT, розробка драйверів пристроїв, дослідження апаратних лічильників продуктивності PMU та високочастотна торгівля (HFT).

### 2. Апаратна віртуалізація (KVM / VirtualBox)

Гіпервізори використовують кремнієві розширення Intel VT-x та AMD-V для створення ілюзії повноцінного заліза всередині ізольованого гостьового простору.

- **Дворівнева трансляція пам'яті (EPT/NPT):** Гостьова операційна система транслює віртуальну адресу в так звану «гостьову фізичну адресу» (Guest Physical Address, GPA). Потім апаратний блок EPT транслює GPA у реальну фізичну адресу хоста (Host Physical Address, HPA). Це означає, що при кожному промаху повз кеш TLB процесор мусить виконати до 16 або 24 звернень до пам'яті замість звичайних 4, що збільшує затримку доступу при активній роботі з великими масивами RAM.
- **Події перехоплення (VM-Exit):** Коли гостьове ядро виконує інструкції введення-виведення (`in`/`out`), змінює контрольні регістри (`CR0`, `CR4`) або викликає інструкцію `CPUID`, процесор зупиняє гостьовий код і передає керування гіпервізору. Витрати на перемикання контексту VM-Exit становлять від 500 до 1500 тактів процесора.
- **Паравиртуалізовані драйвери (VirtIO):** Для мінімізації кількості подій VM-Exit сучасні віртуальні машини використовують спеціальні драйвери `virtio-blk` та `virtio-net`. Замість емуляції фізичних регістрів контролера SATA або Intel e1000 гіпервізор та гостьове ядро обмінюються дескрипторами пакетів через спільні кільцеві буфери пам'яті (Virtqueues).
- **Сфера застосування:** Навчальні пісочниці з можливістю створення знімків стану (*snapshots*), тестування завантажувачів GRUB, ізольовані лабораторні стенди з власною мережевою топологією.

### 3. Легка мікро-віртуальна машина (WSL2)

WSL2 поєднує переваги нативного ядра Linux та зручність інтеграції з робочим столом Windows завдяки легкій архітектурі віртуалізації Hyper-V.

- **Миттєвий запуск та мінімальне ядро:** Спеціально оптимізоване ядро Linux позбавлене громіздких драйверів застарілого фізичного обладнання, завдяки чому мікро-ВМ стартує менш ніж за секунду.
- **Динамічний пул оперативної пам'яті:** Служба `vmmem` автоматично розширює та звужує виділений обсяг RAM за допомогою технології роздування пам'яті (*memory ballooning*), повертаючи сторінки пам'яті Windows, коли процеси Linux стають неактивними.
- **Файловий поділ:** Усі файли всередині власного віртуального диска `ext4` (`.vhdx`) обслуговуються нативним кешем сторінок Linux. Проте при зверненні до файлів Windows через каталог `/mnt/c/` кожен виклик проходить через шар мережевого протоколу Plan 9 (9P) або сокет `virtio-fs`, що створює помітні накладні витрати при компіляції великих проєктів.
- **Сфера застосування:** Щоденна розробка веб-сервісів, прикладних програм на C++, Go, Python, робота з Docker Desktop на робочих станціях Windows.

### 4. Контейнеризація (Docker, Podman, LXC)

Контейнери відмовляються від запуску другого ядра на користь строгого розмежування ресурсів хостового ядра.

- **Простори імен (Namespaces):** Ядро Linux підтримує вісім ізольованих просторів: `PID` (ізоляція дерева процесів), `MNT` (власні точки монтування), `NET` (власні IP-адреси та таблиці маршрутизації), `IPC` (черги повідомлень та спільна пам'ять), `UTS` (власне ім'я хоста), `USER` (відображення UID/GID всередині контейнера на безпечні UID хоста), `CGROUP` (ізоляція кореня cgroups) та `TIME` (власний зсув системного годинника).
- **Контрольні групи (Cgroups v2):** Дозволяють ядру обмежувати та обліковувати використання фізичного процесорного часу (`cpu.max`), оперативної пам'яті (`memory.max`), дискового вводу-виводу (`io.weight`) та кількості дескрипторів процесів (`pids.max`).
- **Сфера застосування:** Розгортання мікросервісів у хмарі, пакування залежностей програм, оркестрація контейнерів у Kubernetes.

### 5. macOS (Гібридне ядро XNU)

macOS забезпечує офіційну відповідність стандартам POSIX через унікальну гібридну архітектуру.

- **Симбіоз Mach та BSD:** Задачі керування пам'яттю та планування низькорівневих потоків виконує мікроядро Mach 3.0. Поверх нього працює шар BSD, що надає інтерфейси сокетів, семафорів, сигналів та дескрипторів.
- **Файлова система APFS:** Забезпечує надзвичайно швидке клонування файлів через Copy-on-Write на рівні метаданих диска та повну підтримку семантики видалення відкритого файла.
- **Сфера застосування:** Кросплатформна розробка програмного забезпечення, системні утиліти для Unix, робочі машини розробників.

### 6 та 7. Штучна трансляція (WSL1, Cygwin, MSYS2)

Спроба підмінити ядро транслятором викликів на рівні драйвера NT або користувацьких бібліотек DLL створює фатальні обмеження:

- **Проблема атомарності:** Багато дій, які в Unix є атомарними (наприклад, створення пари пов'язаних сокетів `socketpair()` або заміна дескриптора через `dup2()`), в API Windows NT складаються з кількох роздільних викликів, що відкриває простір для стану гонитви (*race conditions*).
- **Імітація прав доступу:** Права доступу Unix (rwxrwxrwx) емулюються поверх складних списків керування доступом Windows (NTFS ACL), що часто призводить до несподіваних помилок `Permission denied` при роботі утиліт `chmod` та `chown`.
- **Висновки:** Підсистеми трансляції непридатні для вивчення внутрішнього устрою Unix і можуть використовуватися лише для збірки найпростіших консольних утиліт.
