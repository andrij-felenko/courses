# 📋 Специфікація сигналів розриву та системних інтерфейсів сеансу

Ця довідка містить вичерпний формальний опис сигналів операційної системи, системних викликів керування сеансами, запитів `ioctl` до драйвера термінала, бітових прапорців структури `termios` та діагностичних інтерфейсів ядра, які визначають життєвий цикл процесів під час закриття вікна або розриву зв'язку. Матеріал структуровано як інженерний контракт для низькорівневого налаштування сесій, емуляторів терміналів та сервісів фонового виконання.

## Сигнали життєвого циклу сеансу та термінала

Нижче наведено перелік ключових сигналів стандарту POSIX, задіяних у процесі розриву термінального зв'язку, керування завданнями та обробки осиротілих груп процесів.

| Сигнал | Номер | Типова дія | Походження сигналу | Призначення та системна поведінка |
|---|---|---|---|---|
| `SIGHUP` | `1` | Завершення (`Term`) | Ядро (`tty_vhangup`) або оболонка (`kill`) | Сповіщає про розрив фізичного чи віртуального зв'язку з терміналом або завершення лідера сеансу. Розсилається всім фоновим завданням оболонки. |
| `SIGCONT` | `18` | Продовження (`Cont`) | Ядро або оболонка | Відновлює виконання зупиненого процесу. Надсилається після `SIGHUP` для розбудження сплячих задач, щоб вони могли обробити сигнал або завершитися. |
| `SIGTSTP` | `20` | Зупинка (`Stop`) | Драйвер TTY (комбінація `Ctrl+Z`) | Інтерактивна зупинка процесу переднього плану з можливістю перехоплення програмою. |
| `SIGSTOP` | `19` | Зупинка (`Stop`) | Системний виклик `kill()` | Безумовна зупинка процесу ядром; не може бути перехоплена чи проігнорована. |
| `SIGTTIN` | `21` | Зупинка (`Stop`) | Лінійна дисципліна ядра `N_TTY` | Надсилається фоновій групі процесів, яка намагається виконати операцію `read()` з керівного TTY. |
| `SIGTTOU` | `22` | Зупинка (`Stop`) | Лінійна дисципліна ядра `N_TTY` | Надсилається фоновій групі процесів, яка намагається виконати `write()` у термінал (якщо увімкнено прапорець `TOSTOP`) або викликати `tcsetpgrp()`. |

### Механіка доправлення сигналів у ядрі

Коли ядро генерує сигнал (наприклад, `SIGHUP` при розриві лінії), воно виставляє відповідний біт у бітовій карті очікуваних сигналів структури `struct task_struct` (для конкретного потоку) або `struct signal_struct` (для всієї групи потоків процесу). Сигнал переходить у стан очікування (*pending*).

Доправлення сигналу здійснюється безпосередньо в момент повернення процесора з простору ядра (*kernel space*) у простір користувача (*user space*). Якщо сигнал заблоковано в масці сигналів потоку (`sigprocmask` або `pthread_sigmask`), біт очікування залишається активним, проте ядро не викликає обробник і не перериває виконання доти, доки сигнал не буде явно розблоковано.

Сигнали `SIGKILL` та `SIGSTOP` мають особливий статус у ядрі: їх неможливо перехопити через `sigaction`, а спроби додати їх до маски заблокованих сигналів мовчки ігноруються системою. Для `SIGHUP`, на відміну від них, дозволено як встановлення користувацького обробника, так і повне ігнорування через диспозицію `SIG_IGN`.

## Системні виклики керування сеансами та групами

Керування ієрархією процесів та прив'язкою до термінала реалізується через набір системних функцій стандарту POSIX.1-2008.

### Системний виклик `setsid`

Створює новий сеанс у ядрі операційної системи.

:::tabs
```c
#include <unistd.h>
#include <stdio.h>
#include <errno.h>

pid_t create_isolated_session(void) {
    pid_t sid = setsid();
    if (sid < 0) {
        perror("setsid");
        return -1;
    }
    return sid;
}
```
```cpp
#include <unistd.h>
#include <system_error>
#include <expected>

std::expected<pid_t, std::error_code> create_isolated_session() noexcept {
    const pid_t sid = ::setsid();
    if (sid < 0) {
        return std::unexpected(std::error_code(errno, std::generic_category()));
    }
    return sid;
}
```
:::

* **Призначення**: створює новий сеанс, якщо викликаючий процес не є лідером групи процесів (`PID != PGID`).
* **Результат**: викликаючий процес стає лідером нового сеансу (`SID = PID`), лідером нової групи процесів (`PGID = PID`) і повністю втрачає зв'язок із будь-яким керівним терміналом (`session->tty = NULL`).
* **Коди помилок**: `EPERM` — викликаючий процес уже є лідером групи процесів. Щоб уникнути цієї помилки, перед викликом `setsid()` виконують `fork()`, викликаючи функцію лише у дочірньому процесі.

### Системний виклик `setpgid`

Встановлює ідентифікатор групи процесів для зазначеної задачі.

:::tabs
```c
#include <unistd.h>
#include <stdio.h>
#include <errno.h>

int assign_process_group(pid_t pid, pid_t pgid) {
    if (setpgid(pid, pgid) < 0) {
        perror("setpgid");
        return -1;
    }
    return 0;
}
```
```cpp
#include <unistd.h>
#include <system_error>

std::error_code assign_process_group(pid_t pid, pid_t pgid) noexcept {
    if (::setpgid(pid, pgid) < 0) {
        return std::error_code(errno, std::generic_category());
    }
    return {};
}
```
:::

* **Правила аргументів**: якщо `pid == 0`, змінюється група поточного процесу; якщо `pgid == 0`, встановлюється `pgid = pid`.
* **Коди помилок**: `EACCES` — спроба змінити групу нащадка після того, як той виконав виклик `execve()`; `EPERM` — процес є лідером сесії або робиться спроба перемістити процес в інший сеанс.

### Системні виклики `tcsetpgrp` та `tcgetpgrp`

Передають або запитують групу процесів переднього плану для керівного термінала.

:::tabs
```c
#include <unistd.h>
#include <stdio.h>
#include <errno.h>

int set_foreground_group(int fd, pid_t pgrp) {
    if (tcsetpgrp(fd, pgrp) < 0) {
        perror("tcsetpgrp");
        return -1;
    }
    return 0;
}
```
```cpp
#include <unistd.h>
#include <system_error>

std::error_code set_foreground_group(int fd, pid_t pgrp) noexcept {
    if (::tcsetpgrp(fd, pgrp) < 0) {
        return std::error_code(errno, std::generic_category());
    }
    return {};
}
```
:::

* **Вимоги**: дескриптор `fd` зобов'язаний бути відкритим керівним терміналом сеансу викликаючого процесу, а група `pgrp` — належати цьому самому сеансу.
* **Особливість**: виклик `tcsetpgrp` із процесу, що перебуває у фоновій групі, карається надсиланням сигналу `SIGTTOU`. Тому оболонки перед викликом тимчасово блокують або ігнорують `SIGTTOU`.

## Запити ioctl для низькорівневого керування терміналом

Пряма взаємодія з драйвером TTY здійснюється через системний виклик `ioctl()` із набором спеціальних констант.

| Код ioctl | Тип аргументу | Опис операції та системні правила |
|---|---|---|
| `TIOCSCTTY` | `int arg` (0 або 1) | Призначає термінал керівним для сеансу. Викликаючий процес повинен бути лідером сесії без TTY. Якщо `arg == 1`, дозволяє примусово забрати термінал у попереднього сеансу (вимагає привілеїв `CAP_SYS_ADMIN`). |
| `TIOCNOTTY` | Немає (`void`) | Від'єднує поточний процес (або весь сеанс, якщо кличе лідер) від керівного TTY. Якщо кличе лідер сеансу, ядро надсилає `SIGHUP` і `SIGCONT` групі переднього плану. |
| `TIOCGSID` | `pid_t *sid` | Повертає числовий ідентифікатор сеансу (`SID`), пов'язаного із зазначеним терміналом. |
| `TIOCGPGRP` | `pid_t *pgrp` | Повертає ідентифікатор групи процесів переднього плану (системний аналог `tcgetpgrp`). |
| `TIOCSPGRP` | `const pid_t *pgrp` | Призначає групу переднього плану термінала (системний аналог `tcsetpgrp`). |
| `TIOCSPTLCK` | `int *lock` | Встановлює стан блокування PTY slave: `*lock = 1` блокує, `*lock = 0` розблоковує (внутрішня операція `unlockpt`). |

## Прапорці termios та поведінка HUPCL

Конфігурація термінальної дисципліни описується структурою `struct termios`:

:::tabs
```c
#include <termios.h>
#include <unistd.h>
#include <stdio.h>

int enable_hangup_on_close(int fd) {
    struct termios tty;
    if (tcgetattr(fd, &tty) < 0) {
        perror("tcgetattr");
        return -1;
    }
    tty.c_cflag |= HUPCL; /* Hangup on last close */
    if (tcsetattr(fd, TCSANOW, &tty) < 0) {
        perror("tcsetattr");
        return -1;
    }
    return 0;
}
```
```cpp
#include <termios.h>
#include <unistd.h>
#include <system_error>

std::error_code enable_hangup_on_close(int fd) noexcept {
    termios tty{};
    if (::tcgetattr(fd, &tty) < 0) {
        return std::error_code(errno, std::generic_category());
    }
    tty.c_cflag |= HUPCL;
    if (::tcsetattr(fd, TCSANOW, &tty) < 0) {
        return std::error_code(errno, std::generic_category());
    }
    return {};
}
```
:::

* **`HUPCL` (Hangup on close)**: бітовий прапорець у полі `c_cflag`. Якщо його активовано, драйвер термінала генерує апаратний розрив зв'язку (скидання ліній DTR/RTS) або програмний виклик `tty_vhangup()`, коли останній процес закриває файловий дескриптор пристрою.
* **Швидкість `B0`**: встановлення нульової швидкості передачі даних (`cfsetospeed(&tty, B0)`) у драйверах послідовних портів інтерпретується як пряма команда негайного розриву зв'язку (скидання сигналу DTR).
* **`TOSTOP`**: бітовий прапорець у полі `c_lflag`. Якщо встановлено, будь-яка спроба фонового процесу виконати `write()` у термінал карається сигналом `SIGTTOU`.

## Взаємодія сигналів SIGHUP та SIGPIPE у конвеєрах

Коли розрив зв'язку вражає багатопроцесний конвеєр (наприклад, `find / | grep pattern | sort`), процеси можуть загинути як від сигналу `SIGHUP`, так і від сигналу `SIGPIPE`:

1. **Каскадна зупинка конвеєра**: якщо перший процес конвеєра отримує `SIGHUP` і вмирає, його вихідний канал (*pipe*) закривається. Наступний процес при спробі читання отримує `EOF`, а при спробі запису в закритий вхід наступної ланки ядро надсилає йому сигнал `SIGPIPE`.
2. **Пріоритет сигналів**: якщо оболонка розсилає `kill(-pgid, SIGHUP)`, усі учасники конвеєра отримують сигнал розриву практично одночасно. Проте якщо один із процесів перехоплює `SIGHUP`, він все одно може бути знищений сигналом `SIGPIPE`, якщо сусідня ланка конвеєра впала першою.
3. **Захист конвеєра**: для збереження конвеєрних задач необхідно або виставляти `SIG_IGN` як для `SIGHUP`, так і для `SIGPIPE`, або перенаправляти всі проміжні потоки в іменовані канали (FIFO) чи тимчасові файли.

## Поведінка системних викликів на завислому терміналі

Коли термінал переходить у стан розриву зв'язку (*hung up*), системні виклики простору користувача повертають чітко регламентовані коди результатів:

| Системний виклик | Стан пристрою | Повертане значення | Код помилки `errno` | Інженерний наслідок для програми |
|---|---|---|---|---|
| `read(fd, ...)` | Hung up | `0` (EOF) | Не встановлюється | Інтерактивні цикли введення сприймають це як кінець файлу й завершуються. Якщо перевірка на `0` відсутня, цикл починає нескінченний холостий прогін. |
| `write(fd, ...)` | Hung up | `-1` | `EIO` (5) | Програми, які не перевіряють результат виведення або вважають `stdout` завжди доступним, аварійно завершуються або переривають виконання. |
| `ioctl(fd, ...)` | Hung up | `-1` | `EIO` або `ENOTTY` | Будь-які спроби зміни параметрів термінала (`tcsetattr`) блокуються ядром. |
| `poll() / select()` | Hung up | Подія `POLLHUP` / `POLLERR` | Не встановлюється | Цикл подій негайно прокидається з активним прапорцем розриву, сигналізуючи про необхідність закриття дескриптора. |

## Команди оболонки для захисту процесів

У таблиці зібрано поведінку вбудованих інструментів командної оболонки та спеціалізованих утиліт захисту процесів.

| Команда / Опція | Тип реалізації | Механізм дії в ядрі та оболонці |
|---|---|---|
| `nohup <cmd>` | Зовнішній бінарник | Виставляє `signal(SIGHUP, SIG_IGN)`. Якщо дескриптори `0, 1, 2` вказують на TTY, перенаправляє `stdin` з `/dev/null`, а `stdout`/`stderr` — у файл `nohup.out`. |
| `disown [job]` | Builtin оболонки | Видаляє завдання із внутрішньої таблиці завдань (*Jobs Table*) оболонки. Оболонка не надсилає `SIGHUP` цьому процесу при закритті. Дескриптори залишаються на старому TTY. |
| `disown -h [job]` | Builtin оболонки | Залишає задачу в таблиці завдань, проте позначає її прапорцем `HUP_IGNORE`. Оболонка не розсилає сигнал при виході, але процес лишається доступним для керування. |
| `disown -a` | Builtin оболонки | Застосовує операцію `disown` до всіх активних завдань у поточній оболонці. |
| `disown -r` | Builtin оболонки | Застосовує операцію `disown` лише до тих завдань, що перебувають у стані активного виконання (`Running`). |
| `shopt -s huponexit` | Опція Bash | Змушує Bash розсилати сигнал `SIGHUP` усім завданням із таблиці завдань при штатному виході з інтерактивної оболонки через команду `exit` або `Ctrl+D`. |
| `setsid <cmd>` | Зовнішній бінарник | Викликає `setsid(2)` перед запуском програми. Створює новий сеанс без керівного TTY. |
| `setsid -f <cmd>` | Зовнішній бінарник | Виконує `fork()` перед викликом `setsid()`, гарантуючи, що новий процес не є лідером групи, що виключає системну помилку `EPERM`. |

## Діагностичні інтерфейси procfs

Ядро Linux експортує повний стан термінальних сесій, ієрархії груп та сигнальних масок через віртуальну файлову систему `/proc`:

### Формат `/proc/[pid]/stat`
Файл містить рядок числових параметрів процесу, розділених пробілами. Ключові позиції специфікації ядра (нумерація з 1):
* **Поле 5 (`pgrp`)**: ідентифікатор групи процесів.
* **Поле 6 (`session`)**: ідентифікатор сеансу (`SID`).
* **Поле 7 (`tty_nr`)**: номер керівного термінала (мажорний і мінорний номери пристрою). Значення `0` або `-1` свідчить про повну відсутність керівного TTY у процесу.
* **Поле 8 (`tpgid`)**: ідентифікатор групи процесів, яка в даний момент володіє терміналом на передньому плані (`foreground PGID`).

### Формат `/proc/[pid]/status`
Містить шістнадцяткові бітові маски сигнального апарату задачі:
* **`SigPnd`**: сигнали, що очікують доправлення конкретному потоку (*thread pending*).
* **`ShdPnd`**: сигнали, що очікують доправлення процесу загалом (*shared pending*).
* **`SigBlk`**: бітова маска заблокованих (маскованих) сигналів процесу.
* **`SigIgn`**: бітова маска сигналів із диспозицією `SIG_IGN` (ігнорування). Якщо молодший біт (`1 << 0`) дорівнює `1`, процес безумовно ігнорує сигнал `SIGHUP`.
* **`SigCgt`**: бітова маска сигналів, для яких встановлено власний обробник через виклик `sigaction`.
