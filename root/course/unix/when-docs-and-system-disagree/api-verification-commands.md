# 📋 Довідник команд інспекції та верифікації середовища

Цей довідник містить систематичну специфікацію інструментів системної діагностики, призначених для виявлення природи команд, перевірки цілісності встановлених пакетів, аналізу двійкових заголовків ELF та низькорівневого трасування системних викликів ядра.

---

## 1. Інспекція стану оболонки та розв'язання імен

Оболонка Unix є складним середовищем виконання з власною динамічною пам'яттю, таблицями символів та внутрішніми пріоритетами. Перш ніж передати керування операційній системі, інтерпретатор перевіряє введене ім'я за внутрішніми реєстрами. Розуміння того, яка саме команда виконується, вимагає використання спеціалізованих інструментів інспекції.

```
+-----------------------------------------------------------------------------+
| Пріоритет перевірки:                                                        |
| Спеціальний Builtin -> Аліас -> Shell-функція -> Звичайний Builtin -> $PATH |
+-----------------------------------------------------------------------------+
```

### Специфікація команд інспекції оболонки

- **`command -v <name>`**
  - **Стандарт:** обов'язкова частина стандарту POSIX.1-2008 (Shell & Utilities).
  - **Призначення:** визначає спосіб інтерпретації імені команди оболонкою без її виконання.
  - **Формат виводу:** якщо команда є зовнішнім двійковим файлом, повертає повний шлях (наприклад, `/usr/bin/grep`). Якщо це аліас — повертає текстове визначення псевдоніма. Для вбудованих команд та функцій повертає їхнє ім'я.
  - **Коди повернення:** `0` — команду знайдено та ідентифіковано; `>0` (зазвичай `1` або `127`) — команду не знайдено в поточному середовищі.
  - **Крайовий випадок:** у мінімалістичних оболонках (Dash) прапорець `-v` є єдиним підтримуваним; розширений прапорець `-V` (описовий режим) у Dash відсутній.

- **`type -a <name>`**
  - **Стандарт:** розширення Bash, Zsh, Ksh (у чистому POSIX `type` підтримується, але прапорець `-a` необов'язковий).
  - **Призначення:** послідовно сканує всі таблиці оболонки та всі каталоги у змінній `$PATH`, виводячи **кожне** входження зазначеного імені в порядку їхнього пріоритету виконання.
  - **Формат виводу:** послідовний перелік статусів. Якщо команда перекрита аліасом або функцією, `type -a` покаже спочатку аліас, потім тіло функції, потім статус builtin і наприкінці — всі фізичні файли на диску.
  - **Коди повернення:** `0` — знайдено хоча б один збіг; `1` — жодного збігу не виявлено.

- **`type -t <name>`**
  - **Стандарт:** розширення GNU Bash.
  - **Призначення:** повертає тип команди єдиним службовим словом, що робить його ідеальним для використання в автоматизованих скриптах валідації:
    - `alias` — псевдонім командного рядка;
    - `keyword` — зарезервоване ключове слово синтаксису оболонки (`if`, `while`, `for`);
    - `function` — користувацька shell-функція;
    - `builtin` — вбудована підпрограма інтерпретатора;
    - `file` — зовнішній двійковий файл або скрипт у `$PATH`.
  - **Коди повернення:** `0` — успішне визначення типу; `1` — не знайдено.

- **`builtin <cmd> [args...]`**
  - **Стандарт:** POSIX / Bash / Zsh.
  - **Призначення:** примусово запускає вбудовану версію команди, повністю ігноруючи однойменні користувацькі функції з тим самим ім'ям. Застосовується всередині користувацьких функцій-обгорток (наприклад, функція `cd()` викликає `builtin cd` для фактичної зміни каталогу).
  - **Коди повернення:** повертає статус завершення виконаної вбудованої команди; якщо команда не є builtin, завершується з помилкою `1`.

- **`enable -n <cmd>`**
  - **Стандарт:** GNU Bash builtin.
  - **Призначення:** тимчасово вимикає вбудовану команду в поточній сесії інтерпретатора, змушуючи Bash шукати однойменний виконуваний файл на диску у каталогах `$PATH` (наприклад, `enable -n echo` змушує оболонку запускати `/bin/echo`).

- **`hash -r`**
  - **Стандарт:** POSIX.
  - **Призначення:** скидає внутрішню хеш-таблицю запам'ятованих шляхів до виконуваних файлів. Оболонка оптимізує пошук у `$PATH`: знайшовши бінарник один раз, вона запам'ятовує його шлях. Якщо ви встановили нову версію програми у каталог, що стоїть раніше в `$PATH` (наприклад, у `/usr/local/bin`), оболонка продовжуватиме викликати старий шлях з кешу, доки не виконано `hash -r`.

## 2. Інспекція двійкових файлів ELF та динамічного лінкування

Якщо перевірка оболонки підтвердила, що команда є зовнішнім файлом, наступним кроком є дослідження архітектури двійкового файлу, його залежностей від спільних бібліотек та конфігурації динамічного завантажувача.

### Команди низькорівневого аналізу

- **`file [-L] [-b] <path>`**
  - **Призначення:** визначає формат файлу за магічними байтами заголовка. Прапорець `-L` розгортає символьні посилання; прапорець `-b` вмикає компактний режим без друку імені файлу.
  - **Типовий вивід:**
    ```
    ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked,
    interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=..., stripped
    ```
  - **Що перевіряти:** архітектуру (`x86-64` проти `aarch64`), тип зв'язування (`dynamically linked` проти `statically linked`) та наявність інтерпретатора.

- **`readelf -l <binary>`**
  - **Призначення:** виводить таблицю програмних заголовків (Program Headers). Секція `PT_INTERP` вказує точний абсолютний шлях до динамічного лінкера, який ядро зобов'язане запустити для підготовки адресної пам'яті процесу. Якщо зазначеного лінкера немає у файловій системі, спроба запуску бінарника повертає `ENOENT` («No such file or directory»).

- **`readelf -d <binary>`**
  - **Призначення:** показує динамічну секцію файлу. Теги `DT_NEEDED` перелічують усі спільні бібліотеки (`.so`), без яких завантажувач відмовиться запускати процес. Теги `DT_RPATH` та `DT_RUNPATH` містять зашиті при компіляції шляхи пошуку бібліотек, які мають перевагу над стандартними системними каталогами.

- **`ldd <binary>`**
  - **Призначення:** відображає рекурсивне дерево спільних бібліотек та адреси їх завантаження.
  - **Безпекова пересторога:** утиліта `ldd` є shell-скриптом, який для збору інформації запускає досліджуваний файл із системною змінною `LD_TRACE_LOADED_OBJECTS=1`. Ніколи не запускайте `ldd` на підозрілих або неперевірених сторонніх бінарниках, оскільки модифікований ELF-файл може виконати довільний код у конструкторах ініціалізації (`.init_array`). Для безпечного аналізу завжди використовуйте `readelf -d` або `objdump -p`.

- **`strings [-n <min_length>] <binary>`**
  - **Призначення:** сканує файл і виводить послідовності друкованих ASCII/UTF-8 символів. Дозволяє виявити зашиті рядки версій, URL-адреси, шляхи до конфігураційних файлів за замовчуванням та змінні оточення навіть у бінарниках зі зрізаними символами налагодження (stripped binaries).

## 3. Верифікація цілісності та походження через пакетні менеджери

Пакетний менеджер операційної системи веде локальну базу даних усіх файлів, встановлених із репозиторіїв. Він дозволяє відповісти на два запитання: якому пакету належить файл і чи не змінювався його вміст з моменту встановлення.

### Специфікація перевірок за дистрибутивами

#### 1. Сімейство Debian / Ubuntu (`dpkg`)
- **Пошук пакета-власника:**
  ```shell
  dpkg -S $(readlink -f $(command -v <command>))
  ```
- **Аудит цілісності файлів пакета:**
  ```shell
  dpkg -V <package_name>
  ```
  Команда `dpkg -V` перераховує контрольні суми MD5 файлів на диску та порівнює їх із записами у базі `/var/lib/dpkg/info/<package>.md5sums`. Якщо файл модифіковано, команда виводить позначку:
  ```
  ??5?????? c /etc/app/config.conf
  ```
  Символ `5` на третій позиції означає розбіжність контрольної суми. Літера `c` позначає конфігураційний файл.

#### 2. Сімейство Red Hat / Fedora / RHEL (`rpm`)
- **Пошук пакета-власника:**
  ```shell
  rpm -qf $(readlink -f $(command -v <command>))
  ```
- **Детальний аудит цілісності:**
  ```shell
  rpm -V <package_name>
  ```
  Утиліта `rpm -V` перевіряє дев'ять характеристик кожного файлу. Вивід містить рядок із 9 символів, де кожен символ позначає конкретну модифікацію:
  - `S` (Size) — змінено фізичний розмір файлу на диску;
  - `M` (Mode) — змінено біти прав доступу або тип файлу (наприклад, додано біт SUID);
  - `5` (MD5/SHA256) — вміст файлу модифіковано (невідповідність криптографічного хешу);
  - `D` (Device) — невідповідність мажорного або мінорного номера пристрою;
  - `L` (Link) — розірвано або змінено ціль символьного посилання `readlink(2)`;
  - `U` (User) — змінено власника файлу (UID);
  - `G` (Group) — змінено групу-власника (GID);
  - `T` (mTime) — змінено позначку часу останньої модифікації;
  - `P` (Capabilities) — змінено розширені права POSIX capabilities.

Крапка (`.`) на відповідній позиції означає, що тест пройдено успішно.

#### 3. Alpine Linux (`apk`)
- **Пошук власника файлу:**
  ```shell
  apk info -W $(readlink -f $(command -v <command>))
  ```
- **Повна перевірка цілісності системи:**
  ```shell
  apk audit
  ```
  Виводить перелік усіх модифікованих або пошкоджених файлів, встановлених через менеджер `apk`.

#### 4. Arch Linux (`pacman`)
- **Пошук власника файлу:**
  ```shell
  pacman -Qo $(readlink -f $(command -v <command>))
  ```
- **Перевірка контрольних сум та прав доступу:**
  ```shell
  pacman -Qk <package_name>
  ```

## 4. Локальна довідкова система (Специфікація `man`)

Сторінки системного мануалу встановлюються разом із відповідними пакетами програм у каталог `/usr/share/man/` і гарантовано описують синтаксис саме поточної версії програми на вашому хості.

### Команди та прапорці `man`

- **`man -w <name>`**
  - Повертає повний шлях до файлу сторінки керівництва на диску замість запуску засобу перегляду (пейджера).
  - Приклад виводу: `/usr/share/man/man1/grep.1.gz`. Дозволяє швидко перевірити, чи встановлено документацію для цієї програми, або переглянути її вихідний код у форматі макросів `roff`.

- **`man -a <name>`**
  - Відкриває послідовно всі наявні сторінки з цим ім'ям з усіх числових розділів. Наприклад, виклик `man -a printf` спочатку покаже документацію на утиліту оболонки `printf(1)`, а після виходу з пейджера відкриє сторінку бібліотечної функції C `printf(3)`.

- **`man <section> <name>`**
  - Відкриває сторінку з конкретного числового розділу керівництва:
    - Розділ `1`: виконувані програми та команди оболонки;
    - Розділ `1p`: офіційний стандарт POSIX для команд;
    - Розділ `2`: системні виклики ядра Linux;
    - Розділ `3`: функції бібліотеки C (libc);
    - Розділ `3p`: стандарт POSIX для бібліотечних функцій C;
    - Розділ `4`: спеціальні файли пристроїв у каталозі `/dev`;
    - Розділ `5`: формати файлів та конфігураційні правила (`/etc/passwd`, `/etc/fstab`);
    - Розділ `7`: оглядові статті, протоколи та конвенції (`man 7 ip`, `man 7 socket`);
    - Розділ `8`: команди системного адміністрування (`mount`, `iptables`, `systemd`).

- **`whatis <name>`**
  - Виконує пошук у попередньо згенерованій базі даних індексів і виводить однорядковий опис призначення утиліти з секції `NAME`.

- **`apropos <keyword>`**
  - Повнотекстовий пошук за ключовими словами у коротких описах усіх встановлених сторінок документації. Допомагає знайти потрібну утиліту, коли її точна назва невідома.

## 5. Системне трасування системних викликів (`strace`)

Утиліта `strace` є головним діагностичним інструментом у випадках, коли документація розходиться з поведінкою програми. Вона перехоплює межу між простором користувача та простором ядра через системний виклик `ptrace(PTRACE_SYSCALL, ...)`.

### Синтаксис та прапорці `strace`

```shell
strace [опції] <команда> [аргументи...]
strace [опції] -p <PID>
```

| Прапорець | Призначення | Практичне застосування |
| :--- | :--- | :--- |
| `-f` | Відстежувати дочірні процеси та потоки. | Обов'язковий прапорець для налагодження багатопотокових програм, веб-серверів та складних shell-скриптів, що форкають утиліти. |
| `-e trace=<вираз>` | Фільтрація типів системних викликів. | Зменшує розмір журналу. Набори:<br>• `openat,access,stat,newfstatat` — діагностика пошуку конфігураційних файлів;<br>• `network` — сокети, порти, мережеві з'єднання (`socket`, `connect`, `bind`);<br>• `process` — створення та завершення процесів (`execve`, `clone`, `exit_group`);<br>• `desc` — файлові дескриптори (`read`, `write`, `close`, `dup2`). |
| `-e trace=%signal` | Перехоплення сигналів процесу. | Дозволяє з'ясувати, який процес надіслав `SIGTERM`, `SIGKILL` або чому виник аварійний збій `SIGSEGV`. |
| `-o <file>` | Запис у файл. | Запобігає змішуванню налагоджувального виводу зі стандартними потоками виводу `stdout` та `stderr` самої програми. |
| `-s <bytes>` | Довжина друку рядків. | За замовчуванням `strace` обрізає рядки аргументів до 32 символів. Прапорець `-s 1024` дозволяє повністю прочитати довгі шляхи, параметри запитів та прочитані блоки файлів. |
| `-y` | Розкодування дескрипторів. | Автоматично показує шляхи до файлів поруч із числовими номерами дескрипторів: `read(3</etc/hosts>, ...)`. |
| `-yy` | Розширене розкодування сокетів. | Виводить локальні та віддалені IP-адреси та порти сокетів: `connect(3<TCP:[127.0.0.1:8080]>, ...)`. |
| `-T` | Тривалість виклику. | Виводить час виконання кожного системного виклику в секундах, допомагаючи знаходити вузькі місця та блокуючі операції вводу-виводу. |
| `-tt` | Часова мітка. | Додає абсолютний час із мікросекундною точністю до кожного рядка журналу (`14:22:01.123456`). |
| `-c` | Статистичний режим. | Підраховує загальний час, кількість викликів та помилок для кожного системного виклику після завершення програми. |

### Як інтерпретувати помилки системних викликів

Ядро операційної системи повертає результат виклику як число. Від'ємні значення відповідають стандартним кодам помилок POSIX (`errno`):

- **`-1 ENOENT (No such file or directory):`** шлях до файлу не існує. Якщо програма ігнорує конфіг, ви побачите спроби відкриття файлу за різними шляхами перед завершенням.
- **`-1 EACCES (Permission denied):`** відсутні права на читання файлу або на виконання (пошук) для одного з батьківських каталогів шляху.
- **`-1 EPERM (Operation not permitted):`** операція заборонена через обмеження облікового запису або відсутність потрібних Linux capabilities (`CAP_NET_BIND_SERVICE`, `CAP_SYS_ADMIN`).
- **`-1 EADDRINUSE (Address already in use):`** мережевий порт уже зайнятий іншим процесом під час виклику `bind()`.
- **`-1 ECONNREFUSED (Connection refused):`** цільовий сервер не слухає зазначений порт або пакет відхилено локальним фаєрволом.

Систематичне використання цього інструментарію гарантує точне встановлення системного стану та причин будь-якої розбіжності між документацією та реальністю.
