# Опукла оболонка множини точок

<preknowlist>
- [Векторний добуток](root:math-algebra/cross-product) — орієнтована площа паралелограма та знак повороту.
- [Опукла множина](root:math-geometry/convex-set) — множина, що містить усі відрізки між будь-якими своїми точками.
- [Швидке сортування](root:sf-algorithms/quicksort) — сортування за `O(n log n)` для впорядкування точок.
</preknowlist>

Хмара з десятків тисяч просторових координат — точок лазерного сканування лідара, вершин тривимірної моделі чи позицій агентів у фізичній симуляції — створює складну обчислювальну проблему. Якщо для перевірки зіткнення об'єкта з цією хмарою аналізувати кожну внутрішню точку, обчислювальна складність кожної просторової перевірки зростає лінійно, а парні перетини між двома тілами вимагають квадратичного часу. З іншого боку, грубе охоплення хмари прямокутним габаритним паралелепіпедом (AABB) залишає порожніми кути, де до 50% площі або об'єму виявляються хибно зайнятими. Щоб отримати точну зовнішню межу без надлишкових внутрішніх даних, необхідно побудувати мінімальний опуклий контур, який щільно охоплює всю множину точок.

## Геометрична природа опуклості та фізична інтуїція

Уявімо дошку, в яку вертикально забито цвяхи, що відповідають координатам точок множини на площині. Якщо навколо всіх цвяхів розтягнути пружну гумову нитку, а потім відпустити її, нитка миттєво стиснеться під дією сили пружності. Вона натягнеться на найвіддаленіших цвяхах, утворивши замкнений опуклий многокутник, тоді як усі інші цвяхи залишаться вільно стояти всередині цього периметра. 

![Поняття опуклої оболонки та натягнута стрічка](/root/eng/sf-algorithms/convex-hull/img/convex-hull-concept.svg)
*Опукла оболонка множини точок як мінімальний охопний опуклий многокутник: внутрішні точки не впливають на контур.*

Ця форма має фундаментальну математичну властивість: якщо взяти будь-які дві точки всередині або на межі отриманого многокутника, весь відрізок прямої між ними повністю лежатиме всередині цієї фігури. Така властивість називається опуклістю (від лат. *convexus* — «вигнутий, округлий»), а сам мінімальний многокутник — опуклою оболонкою (англ. *convex hull*, де *hull* походить від давньогерманського кореня зі значенням «шкаралупа, оболонка, корпус судна»).

Строге математичне визначення формулюється двома еквівалентними шляхами:

1. **Зовнішнє визначення (перетин півпросторів):** Опукла оболонка множини точок `S` — це перетин усіх опуклих множин, що містять `S`. На площині це відповідає перетину всіх замкнених півплощин, які містять усі точки множини `S`. Згідно з теоремою Мінковського–Вейля, будь-який опуклий многогранник можна еквівалентно задати або переліком його крайніх вершин (V-подання), або скінченним набором лінійних нерівностей півпросторів (H-подання).
2. **Внутрішнє визначення (опуклі комбінації):** Опукла оболонка `Conv(S)` — це множина всіх можливих опуклих комбінацій точок із `S`. Тобто будь-яка точка `P ∈ Conv(S)` виражається у вигляді зваженої суми:

```
P = λ[1]·p[1] + λ[2]·p[2] + ... + λ[k]·p[k]   [опукла комбінація]
```
де всі вагові коефіцієнти задовольняють умови невід'ємності та нормування:
```
λ[i] ≥ 0
∑ λ[i] = 1                                     [умова нормування ваг]
```

Точки множини, які опиняються у вершинах охопного многокутника, називаються опорними або крайніми вершинами (англ. *extreme points*). Будь-яка внутрішня точка множини може бути видалена без зміни форми оболонки; навпаки, видалення крайньої вершини обов'язково зменшує або деформує охопну фігуру.

Важливою властивістю кожної вершини опуклої оболонки є наявність опорної прямої (англ. *supporting line*). Пряма `L`, що проходить через точку `P ∈ S`, називається опорною прямою для множини `S`, якщо вся множина `S` повністю лежить в одній із двох замкнених півплощин, обмежених цією прямою. Точка `P` належить опуклій оболонці тоді й лише тоді, коли через неї можна провести щонайменше одну опорну пряму.

Фізична аналогія з гумовою ниткою наочна, проте має межу застосовності: вона спирається на силу натягу в двовимірному евклідовому просторі. У тривимірному просторі пружна мембрана натягується на каркас, але для неевклідових просторів або за наявності проміжних точок, що лежать строго на одному відрізку, фізичне тертя й натяг не визначають однозначно, які саме вершини є кутовими. Алгоритмічний підхід потребує дискретного й точного математичного критерію.

> 🔧 **Навіщо це.**
> У фізичних рушіях (Box2D, PhysX, Bullet) обчислення зіткнень між довільними нерегулярними сітками точок є обчислювально непосильним. Заміна довільної геометрії її опуклою оболонкою дає змогу застосовувати надшвидкі алгоритми на кшталт [GJK](root:sf-algorithms/gjk-collision) або теорему про роздільну вісь (SAT), які знаходять факт контакту, дистанцію та нормаль удару за кілька мікросекунд.

## Предикат повороту: векторний інструмент орієнтації

Щоб обійтися без повільних і чисельно нестійких обчислень кутів у радіанах чи тригонометричних функцій `atan2`, будь-яке геометричне рішення зводить задачу побудови оболонки до єдиної базової перевірки: куди повертає шлях із трьох точок `A → B → C` — ліворуч, праворуч чи йде прямо.

Ця перевірка спирається на псевдоскалярний (косий) векторний добуток на площині. Нехай вектор `u = B - A` веде від першої точки до другої, а вектор `v = C - A` — від першої точки до третьої. Косий добуток `u` та `v` дорівнює визначнику матриці, складеної з їхніх координат:

```
Δ = (B[x] - A[x])·(C[y] - A[y]) - (B[y] - A[y])·(C[x] - A[x])   [косий добуток 2D]
```

![Геометричний предикат повороту трійки точок](/root/eng/sf-algorithms/convex-hull/img/orientation-turn.svg)
*Предикат орієнтації: знак векторного косого добутку визначає лівий, правий поворот або колінеарність.*

Знак величини `Δ` однозначно задає взаємне розташування точок:

```
Δ > 0   ⇒   шлях A → B → C повертає ліворуч (проти годинникової стрілки, CCW)
Δ < 0   ⇒   шлях A → B → C повертає праворуч (за годинниковою стрілкою, CW)
Δ = 0   ⇒   точки A, B і C колінеарні (лежать на одній прямій)
```

Математично величина `(1/2)·|Δ|` дорівнює орієнтованій площі трикутника `ABC`. 

Ця логічна функція називається предикатом орієнтації (від лат. *praedicatum* — «висловлене, стверджуване», *orientari* — «знаходити схід, зорієнтуватися»). Детальне алгебраїчне виведення формули, доведення інваріантності відносно поворотів і зсувів системи координат та аналіз чисельної стійкості у випадку чисел із плаваючою комою наведено у вставці [предикат повороту: алгебра й геометрія орієнтованої площі](root:sf-algorithms/convex-hull/math-orientation-test.md).

## Фундаментальна межа складності та спектр алгоритмів

Перш ніж розглядати конкретні алгоритми, необхідно зрозуміти теоретичну межу швидкодії. Чи можна побудувати опуклу оболонку швидше, ніж за час `O(n log n)`?

Відповідь дає класичне зведення до задачі сортування. Нехай нам задано масив із `n` довільних дійсних чисел `x[1], x[2], ..., x[n]`. Створимо на площині `n` точок вигляду `p[i] = (x[i], x[i]²)`. Усі ці точки лежать на графіку квадратичної параболи `y = x²`. Оскільки парабола є строго опуклою функцією (її друга похідна `y'' = 2 > 0`), жодна точка не може опинитися всередині відрізка між будь-якими іншими двома точками параболи.

Це означає, що **всі без винятку `n` точок обов'язково належатимуть опуклій оболонці**. Якщо побудувати опуклу оболонку цієї множини, порядок вершин вздовж її контуру дасть точно відсортований порядок початкових чисел `x[i]`. Оскільки в моделі порівнянь сортування вимагає щонайменше `Ω(n log n)` операцій, побудова опуклої оболонки для довільного вхідного набору не може бути виконана швидше ніж за `Ω(n log n)` у найгіршому випадку.

Проте не всі задачі однакові: якщо з `n` вхідних точок лише `h` точок потрапляють на зовнішню межу (`h ≤ n`), алгоритми можуть залежати від `h`. Алгоритми, час роботи яких залежить від розміру виходу, називаються вихідно-чутливими (англ. *output-sensitive*). Історія їхньої появи та змагання за досягнення межі `O(n log h)` описана в історичному нарисі [від антених решіток до обчислювальної геометрії](root:sf-algorithms/convex-hull/hist-convex-hull.md).

## Алгоритм загортання подарунка (Марш Джарвіса)

Найпростіший підхід прямо моделює фізичний процес намотування нитки навколо точок. 

### Механізм роботи
1. **Пошук стартової точки:** Знаходимо точку `p[0]` із найменшою координатою `x` (а за рівності `x` — із найменшою `y`). Ця точка гарантовано є крайньою лівою, тому вона зобов'язана належати опуклій оболонці.
2. **Крок обходу:** Нехай поточна знайдена вершина оболонки — `P`. Щоб знайти наступну вершину `Q`, ми шукаємо серед усіх точок множини таку точку, щоб **усі інші точки лежали праворуч** від напрямленого вектора `PQ`. Це еквівалентно умові, що для будь-якої іншої точки `T` предикат `ccw(P, Q, T) ≥ 0` (поворот ліворуч або прямо).
3. **Замикання контуру:** Процес повторюється крок за кроком, доки наступною обраною вершиною знову не стане стартова точка `p[0]`.

```
стартова точка P = min_x(S)
поки P != p[0] (або перший крок):
    кандидат Q = перша точка S
    для кожної точки T в S:
        якщо ccw(P, Q, T) < 0 (T лівіше вектора PQ):
            Q = T                          [знайдено точку з більшим кутом обхвату]
    додати Q до оболонки
    P = Q
```

### Аналіз складності
На кожному з `h` кроків алгоритм переглядає всі `n` точок множини, виконуючи `n` перевірок предиката орієнтації. Загальна часова складність становить `O(n · h)`.
- **Найкращий випадок (`h = 3`):** Коли точок мільйон, але вони скупчені всередині трикутника, алгоритм Джарвіса знаходить оболонку всього за 3 проходи, тобто за час `O(n)`, що значно швидше за сортування.
- **Найгірший випадок (`h = n`):** Коли всі точки лежать на опуклій кривій (наприклад, на колі), алгоритм здійснює `n` проходів по `n` точок, деградуючи до квадратичної складності `O(n²)`.

## Сканування Грехема

Щоб гарантувати час `O(n log n)` незалежно від просторового розподілу точок, Рональд Грехем запропонував упорядкувати точки за кутом і виконати однопрохідне сканування зі стеком.

### Механізм роботи
1. **Вибір полюса:** Знаходимо точку `p[0]` з мінімальною координатою `y` (а при рівності `y` — з найменшою `x`).
2. **Полярне сортування:** Усі інші точки `p[1], ..., p[n-1]` сортуються за зростанням полярного кута відносно точки `p[0]`. Для порівняння двох точок `A` і `B` використовується предикат `ccw(p[0], A, B)`: якщо поворот лівий, то кут точки `A` менший за кут точки `B`. Якщо дві точки лежать на одному промені (колінеарні з `p[0]`), ближчу до `p[0]` точку можна одразу відкинути.
3. **Стековий обхід:** 
   - Створюємо структуру даних [стек](root:sf-lang/stack-lifo) (англ. *stack* — «стос, скирта») і кладемо туди перші три відсортовані точки `p[0], p[1], p[2]`.
   - Послідовно розглядаємо кожну наступну точку `p[i]`. Доки останні дві точки в стеку та нова точка `p[i]` утворюють правий поворот або йдуть прямо (`ccw(stack[top-1], stack[top], p[i]) ≤ 0`), верхня точка стека є внутрішньою — вона **виштовхується зі стека** (`pop`).
   - Коли знайдено строгий лівий поворот, нова точка `p[i]` додається до стека (`push`).

```
стек = [p[0], p[1]]
для i від 2 до n-1:
    поки розмір(стек) ≥ 2 і ccw(стек[top-1], стек[top], p[i]) ≤ 0:
        видалити_з_вершини(стек)             [виштовхування точки через увігнутість]
    додати_в_кінець(стек, p[i])
```

### Чому сканування працює за лінійний час після сортування
Сортування точок за полярним кутом займає `O(n log n)` операцій. На фазі стекового обходу кожна точка додається до стека рівно один раз. Оскільки точку не можна видалити зі стека більше одного разу, загальна кількість операцій `pop` за весь час роботи алгоритму не може перевищувати `n`. Отже, фаза сканування виконується строго за `O(n)` операцій, а підсумкова складність алгоритму визначається сортуванням: `O(n log n)`.

Головний практичний недолік класичного алгоритму Грехема — необхідність полярного сортування, яке вимагає акуратної обробки точок із рівними кутами та чутливе до похибок порівняння.

## Монотонний ланцюг Ендрю: декомпозиція на межі

Найбільш практичною, надійною та швидкою модифікацією методу Грехема є алгоритм монотонного ланцюга Ендрю (англ. *Andrew's Monotone Chain algorithm*). Ендрю запропонував сортувати точки не за полярним кутом, а звичайним декартовим лексикографічним сортуванням: спочатку за координатою `x`, а за рівності `x` — за координатою `y`.

Множина точок розбивається на дві незалежні частини:
- **Нижня оболонка (Lower Hull):** ланцюг ребер, що огинає точки знизу, рухаючись зліва направо від найлівішої точки `p_min` до найправішої точки `p_max`.
- **Верхня оболонка (Upper Hull):** ланцюг ребер, що огинає точки зверху, рухаючись справа наліво від `p_max` назад до `p_min`.

Термін «монотонний» (від грец. *monotonos* — «однотонний, одноманітний») підкреслює, що координата `x` вершин уздовж кожного ланцюга змінюється строго монотонно (тільки зростає або тільки спадає).

![Побудова монотонного ланцюга Ендрю](/root/eng/sf-algorithms/convex-hull/img/monotone-chain-steps.svg)
*Чотири фази алгоритму Ендрю: лексикографічне сортування, нижній ланцюг, верхній ланцюг та об'єднання.*

### Покроковий алгоритм
1. **Лексикографічне сортування:** Впорядковуємо масив точок за зростанням `x`, а при рівності `x` — за зростанням `y`. Видаляємо дублікати точок з однаковими координатами за лінійний прохід.
2. **Побудова нижнього ланцюга:** Проходимо відсортований масив зліва направо (`i = 0, ..., n-1`). Для кожної точки перевіряємо: доки в стеку є щонайменше 2 точки, і нова точка утворює нелівий поворот із двома попередніми (`ccw(hull[k-2], hull[k-1], pts[i]) ≤ 0`), видаляємо останню точку зі стека. Після цього додаємо `pts[i]`.
3. **Побудова верхнього ланцюга:** Проходимо масив у зворотному напрямку справа наліво (`i = n-2, ..., 0`). Виконуємо аналогічне стекове виштовхування нелівих поворотів, зберігаючи початкову границю нижньої оболонки.
4. **Об'єднання:** Останній елемент кожного ланцюга збігається з першим елементом іншого, тому кінцевий дублікат видаляється, утворюючи замкнений многокутник.

Повна оптимізована реалізація алгоритму мовами C та C++ з детальним покроковим числовим трасуванням наведена у вставці [реалізація монотонного ланцюга Ендрю та сканування Грехема](root:sf-algorithms/convex-hull/proj-convex-hull.md).

## Quickhull: підхід «розділяй і володарюй»

Алгоритм Quickhull (за аналогією до [швидкого сортування](root:sf-algorithms/quicksort) Quicksort) використовує парадигму «розділяй і володарюй». Замість глобального сортування всіх точок на старті, він рекурсивно відкидає внутрішні точки великими групами.

![Розбиття площини в алгоритмі Quickhull](/root/eng/sf-algorithms/convex-hull/img/quickhull-partition.svg)
*Рекурсивний поділ у Quickhull: відкидання точок усередині трикутника та рекурсія на зовнішніх підмножинах.*

### Механізм рекурсивного розбиття
1. **Базова вісь:** Знаходимо крайню ліву точку `A = min_x` та крайню праву точку `B = max_x`. Пряма `AB` розбиває всю множину точок на дві підмножини: точки, розташовані ліворуч від вектора `AB` (над прямою), та точки праворуч (під прямою).
2. **Пошук вершини трикутника:** Для множини точок над прямою `AB` знаходимо точку `C`, яка максимально віддалена від відрізка `AB` (тобто точка з найбільшою позитивною орієнтованою площею трикутника `ABC`). Ця точка гарантовано є вершиною опуклої оболонки.
3. **Відсікання внутрішньої зони:** Усі точки, що потрапили всередину трикутника `ABC`, гарантовано лежать всередині опуклої оболонки і **назавжди відкидаються**.
4. **Рекурсія:** Точки, що залишилися зовні, діляться на дві незалежні групи:
   - підмножина `S[1]`: точки ліворуч від відрізка `AC`;
   - підмножина `S[2]`: точки ліворуч від відрізка `CB`.
   Для кожної підмножини кроки 2–4 викликаються рекурсивно.

### Швидкодія Quickhull
- **Середній випадок:** Для рівномірного випадкового розподілу точок Quickhull працює за час `O(n log n)`, а на практиці часто випереджає алгоритм Ендрю завдяки тому, що на перших же кроках трикутники відсікають до 80–90% внутрішніх точок без жодного сортування.
- **Найгірший випадок:** Якщо точки лежать на дузі кола так, що на кожному кроці відокремлюється лише одна точка, глибина рекурсії досягає `n`, а загальний час становить `O(n²)`.

## Оптимальний вихідно-чутливий алгоритм Чена

Довгий час існував розрив між простими алгоритмами складності `O(n log n)` (Грехем, Ендрю) та чутливими до виходу алгоритмами `O(n · h)` (Джарвіс). У 1996 році Тімоті Чен запропонував метод, що поєднує сильні сторони обох підходів і досягає теоретично оптимальної межі `O(n log h)`.

### Ідея алгоритму Чена
Припустимо, що ми заздалегідь знаємо точну кількість вершин оболонки `h`. Позначимо через `m` цільовий розмір групи (покладемо `m = h`).

1. **Розбиття:** Розбиваємо вихідну множину з `n` точок на `k = ⌈n / m⌉` неперетинних підмножин розміром по `m` точок у кожній.
2. **Локальні оболонки:** Для кожної з `k` груп будуємо її власну локальну опуклу оболонку за допомогою алгоритму Грехема або Ендрю. Час на одну групу: `O(m log m)`. На всі `k` груп:

```
k · O(m log m) = (n / m) · O(m log m)
               = O(n log m)             [час побудови всіх міні-оболонок]
```

3. **Глобальний марш Джарвіса:** Знаходимо глобальну стартову точку `p[0]`. Тепер застосовуємо марш Джарвіса, але замість перебору `n` окремих точок для пошуку наступної вершини, ми шукаємо **дотичну пряму від поточної вершини до кожної з `k` міні-оболонок**. Оскільки кожна міні-оболонка — це вже впорядкований опуклий многокутник, дотичну до неї можна знайти [двійковим пошуком](root:sf-algorithms/binary-search) за час `O(log m)`.
4. **Вибір найкращої дотичної:** Серед `k` знайдених кандидатів обираємо точку з максимальним кутом за час `O(k) = O(n / m)`.
5. **Загальний час одного кроку:** `k · O(log m) = O((n / m) log m)`. Оскільки весь марш триває `h` кроків (де `h ≤ m`), сумарний час маршу складає:

```
h · O((n / m) log m) ≤ m · O((n / m) log m)
                     = O(n log m)       [час глобального обходу]
```

Загальний час за відомого `m = h` становить `O(n log m) = O(n log h)`.

### Як дізнатися `h` заздалегідь (прийом Чена)
Оскільки значення `h` невідоме наперед, Чен застосував стратегію спроб із квадратичним зростанням параметра: `m = 2^(2^t)` для `t = 1, 2, 3, ...` (тобто послідовність значень `m = 4, 16, 256, 65536, ...`).

На кожній ітерації запускається алгоритм із лімітом на `m` кроків маршу. Якщо за `m` кроків оболонка не замкнулася (значить, `h > m`), процес переривається, `t` збільшується на 1, і спроба повторюється з новим `m`. Сума геометричної прогресії часу всіх невдалих спроб не перевищує часу останньої успішної ітерації, забезпечуючи підсумкову складність `O(n log h)`.

## Динамічні та потокові опуклі оболонки

У багатьох прикладних системах (наприклад, у трекінгу об'єктів у реальному часі, обробці потоків GPS-координат або інтерактивних графічних редакторах) точки надходять послідовно по одній, і оболонку потрібно підтримувати в актуальному стані після кожної нової точки.

Повний перерахунок статичним алгоритмом Ендрю на кожному кроці вимагав би `O(n² log n)` для `n` послідовних точок. Замість цього застосовуються динамічні алгоритми та структури даних:

1. **Алгоритм Препарати (онлайн-вставка за `O(log n)`):**
   Якщо нова точка `P` потрапляє всередину поточної опуклої оболонки (перевірка належності за `O(log n)`), оболонка залишається без змін. Якщо точка `P` лежить зовні, ми знаходимо дві опорні дотичні від точки `P` до многокутника оболонки за допомогою двійкового пошуку за `O(log n)`. Усі вершини старої оболонки, що опинилися між точками контакту дотичних із боку точки `P`, видаляються, а сама точка `P` вставляється між ними. Амортизований час вставки становить `O(log n)` при використанні збалансованого дерева пошуку.
2. **Структура Овермарса–ван Левена (вставка та видалення):**
   Підтримує повну динамічну опуклу оболонку при довільних вставках і видаленнях точок за час `O(log² n)` на операцію завдяки ієрархічному злиттю лівого та правого піддерев точок.

## Багатовимірні оболонки: тривимірний простір і вище

У тривимірному просторі `R³` опукла оболонка є опуклим многогранником (поліедром), межа якого складається з граней (полігонів, зазвичай трикутників), ребер і вершин.

Згідно з формулою Ейлера для опуклих многогранників:

```
V - E + F = 2   [формула Ейлера: вершини, ребра, грані]
```

Оскільки кожна трикутна грань має 3 ребра, а кожне ребро розділяє рівно 2 грані, маємо співвідношення `3F = 2E`. Підставляючи це у формулу Ейлера, отримуємо точні лінійні межі:

```
E = 3V - 6
F = 2V - 4   [кількість граней та ребер завжди строго лінійна від кількості вершин]
```

Це фундаментальний висновок: у тривимірному просторі опукла оболонка з `V` вершин має не більше ніж `O(V)` граней та ребер. Алгоритм Препарати–Хонга (Preparata-Hong) будує 3D-оболонку методом «розділяй і володарюй» за оптимальний час `O(n log n)`.

### Прокляття розмірності
У просторах вищої розмірності `R^d` (де `d ≥ 4`) лінійна залежність кількості граней від вершин руйнується. Згідно з теоремою Макмаллена про верхню межу (McMullen's Upper Bound Theorem), опуклий многогранник із `n` вершин у `d`-вимірному просторі може мати:

```
O(n^(⌊d / 2⌋))   [максимальна кількість граней у розмірності d]
```

Для простору `d = 4` кількість тривимірних граней зростає як `O(n²)`, для `d = 6` — як `O(n³)`. Тому алгоритми побудови оболонок у багатовимірних просторах (наприклад, метод підтримувальних гіперплощин або Quickhull 3D/4D) мають експоненційну або степеневу залежність від розмірності простору.

## Двоїстість: зв'язок із діаграмами Вороного та тріангуляцією Делоне

Між опуклими оболонками у просторі `R^(d+1)` та планарними розбиттями у просторі `R^d` існує дивовижний проективний зв'язок, відкритий математиками наприкінці XX століття.

Нехай на двовимірній площині задано `n` точок `(x[i], y[i])`. Піднімемо кожну точку у тривимірний простір на поверхню кругового параболоїда:

```
(x[i], y[i])   ↦   (x[i], y[i], x[i]² + y[i]²)   [параболічний ліфтинг у 3D]
```

Якщо побудувати звичайну тривимірну опуклу оболонку для цих піднятих точок у `R³`, її нижня поверхня (грані, нормалі яких спрямовані вниз по осі `z`) володіє унікальною властивістю:
1. **Проекція граней** цієї нижньої 3D-оболонки назад на площину `xy` утворює **тріангуляцію Делоне** вихідної множини точок.
2. Топологічно двоїстий граф до тріангуляції Делоне дає [діаграму Вороного](root:sf-algorithms/voronoi-diagram) (розбиття площини на зони близькості).

Завдяки цій двоїстості будь-який швидкий алгоритм побудови 3D опуклої оболонки автоматично стає алгоритмом побудови діаграм Вороного та тріангуляції Делоне за час `O(n log n)`.

## Інженерне застосування та суміжні алгоритми

Опукла оболонка є базовим будівельним блоком у багатьох практичних сферах:

1. **Мінімальний охопний прямокутник (Minimum Bounding Box):**
   Щоб знайти прямокутник найменшої площі або периметра, що містить довільну множину точок (орієнтований габаритний контейнер, OBB), не потрібно перебирати нескінченну кількість кутів повороту. Згідно з теоремою Фрімена–Шапіро, сторона мінімального прямокутника обов'язково збігається з одним із ребер опуклої оболонки. Побудувавши оболонку за `O(n log n)`, метод штангенциркуля, що обертається (англ. *rotating calipers*), знаходить мінімальний прямокутник або діаметр множини всього за лінійний час `O(h)`.
2. **Комп'ютерний зір та розпізнавання жестів:**
   Під час виділення контуру кисті руки опукла оболонка охоплює витягнуті пальці. Різниця між площею опуклої оболонки та реальним контуром руки утворює «дефекти опуклості» (англ. *convexity defects*), западини між якими дають точні координати пальців для розпізнавання жестів без нейронних мереж.
3. **Геоінформаційні системи (ГІС):**
   Визначення межі зони обслуговування базових станцій, побудова охопних полігонів кластерів GPS-треків та оптимізація маршрутів дронів спираються на швидкі просторові оболонки.
4. **Визначення зіткнень у робототехніці (GJK):**
   Алгоритм [GJK](root:sf-algorithms/gjk-collision) спирається на опуклу оболонку різниці Мінковського `A ⊖ B = {a - b | a ∈ A, b ∈ B}`. Якщо тіла перетинаються, їхня різниця Мінковського містить початок координат `(0, 0, 0)`, що перевіряється ітеративною побудовою симплексів.
