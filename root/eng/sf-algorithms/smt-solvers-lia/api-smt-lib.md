# 📋 Стандарт SMT-LIB 2.6 та програмний інтерфейс LIA-сольвера

Стандарт **SMT-LIB (Satisfiability Modulo Theories Library)** версії 2.6 є універсальним промисловим протоколом взаємодії для автоматичних систем доведення теорем, верифікаторів та SMT-сольверів (Z3, CVC5, Yices, MathSAT). Для лінійної цілочисельної арифметики стандарт фіксує дві основні логіки: безкванторну `QF_LIA` (Quantifier-Free Linear Integer Arithmetic) та повну кванторну `LIA`.

Нижче наведено формальну специфікацію командного інтерфейсу мови SMT-LIB 2.6, семантичні правила трансляції операторів, особливості евклідової арифметики, роботу з інтерполянтами Крейга, протокол взаємодії через потоки, параметри конфігурації, організацію AST-пам'яті та повнофункціональний низькорівневий C/C++ API для програмної інтеграції LIA-сольвера у сторонні статичні аналізатори коду, компілятори та верифікатори.

## 1. Специфікація логіки та командний синтаксис SMT-LIB 2.6

Синтаксис SMT-LIB базується на S-виразах (S-expressions) у стилі мови Lisp. Будь-яка команда береться у круглі дужки, де першим елементом є ідентифікатор команди, а наступними — її позиційні аргументи або атрибути зі спеціальними префіксами (ключові слова, що починаються з двокрапки `:`).

### Життєвий цикл сесії та керування станом

Сесія SMT-сольвера функціонує як послідовний автомат станів:
1. **Стан ініціалізації (Start):** Задаються глобальні налаштування (`set-option`) та фіксується предметна логіка (`set-logic`).
2. **Стан накопичення тверджень (Assert):** Оголошуються символічні змінні (`declare-const`), функціональні символи (`declare-fun`) та додаються логічні асерції (`assert`).
3. **Стан перевірки (Solve):** Викликається команда `(check-sat)` або `(check-sat-assuming)`. Сольвер переходить у стан розв'язання, повертаючи один із трьох статусів: `sat`, `unsat` або `unknown`.
4. **Стан інспекції результату (Inspect):** Якщо отримано `sat`, доступні команди вилучення значень (`get-model`, `get-value`). Якщо отримано `unsat`, доступні команди вилучення доведення чи ядра суперечності (`get-unsat-core`, `get-proof`, `get-interpolant`).

## 2. Арифметичні оператори та терми у логіці LIA

У логіці `LIA` та `QF_LIA` базовим сортом (типом) є `Int`. Усі числові константи є послідовностями десяткових цифр (від'ємні числа записуються унарним мінусом `(- 5)`).

### Таблиця арифметичних та логічних предикатів

| Оператор | SMT-LIB синтаксис | Тип аргументів | Результат | Опис семантики |
| :--- | :--- | :--- | :--- | :--- |
| `+` | `(+ t1 t2 ... tn)` | `Int, ..., Int` | `Int` | Асоціативне додавання довільної кількості термів. |
| `-` | `(- t1 t2 ... tn)` | `Int, ..., Int` | `Int` | Віднімання або унарне заперечення знаку `(- t)`. |

| `div` | `(div t1 t2)` | `Int, Int` | `Int` | Цілочисельне ділення за Евклідом: результат задовольняє `0 <= mod(x, y) < abs(y)`. |
| `mod` | `(mod t1 t2)` | `Int, Int` | `Int` | Залишок від евклідового ділення: `x = y * div(x, y) + mod(x, y)`. |

| `>=` | `(>= t1 t2)` | `Int, Int` | `Bool` | Відношення більше або дорівнює. |
| `>` | `(> t1 t2)` | `Int, Int` | `Bool` | Строге більше: еквівалентно `(>= t1 (+ t2 1))`. |

| `ite` | `(ite cond t_then t_else)` | `Bool, T, T` | `T` | Умовний оператор If-Then-Else на рівні термів. |

## 3. Евклідова арифметика ділення та обробка ділення на нуль

Фундаментальною пасткою при трансляції коду програм мовами C, C++, Rust або Java у формат SMT-LIB є відмінність між машинною арифметикою та математичним стандартом логіки першого порядку.

### Усікаюче ділення проти евклідового

Більшість сучасних компіляторів використовують **усікаюче ділення (Truncating Division)**, де результат округлюється у напрямку нуля:
- У C99 / C++20: `-7 / 3 = -2`, а залишок `-7 % 3 = -1`.

Натомість стандарт SMT-LIB 2.6 суворо базується на математичному **діленні за Евклідом (Euclidean Division)**, для якого залишок завжди зобов'язаний бути строго невід'ємним:
- У SMT-LIB: `(div -7 3) = -3`, а залишок `(mod -7 3) = 2`.

Ця вимога випливає з фундаментального алгебраїчного інваріанта:

```
x = y · div(x, y) + mod(x, y)
0 ≤ mod(x, y) < |y|
```

### Патерн трансляції цілочисельного ділення з C/C++ у SMT-LIB

Для точного відтворення семантики процесорів x86/ARM при перевірці виразів C-програм використовують умовний оператор `ite`:

```smt2
; Трансляція C-ділення (x / y)
(define-fun c_div ((x Int) (y Int)) Int
  (ite (>= x 0)
    (div x y)
    (ite (> (mod x y) 0)
      (+ (div x y) 1)
      (div x y))))

; Трансляція C-залишку (x % y)
(define-fun c_mod ((x Int) (y Int)) Int
  (ite (>= x 0)
    (mod x y)
    (- (mod x y) (abs y))))
```

### Семантика ділення на нуль у логіці першого порядку

У класичній логіці першого порядку всі функціональні символи є тотальними (total functions). Це означає, що підвираз `(div x 0)` не спричиняє аварійної зупинки чи винятку, а повертає деяке фіксоване, хоч і неспецифіковане ціле число.

Зокрема, тотожність `(= (div x 0) (div x 0))` завжди оцінюється як `true`. Якщо верифікатор перевіряє код на відсутність ділення на нуль, він зобов'язаний явно додавати передумову суперечності `(assert (= divisor 0))` для перевірки досяжності аварійного стану перед операцією ділення.

## 4. Інтерполяція Крейга в LIA та автоматичний синтез інваріантів

Для автоматичного пошуку інваріантів циклів у верифікаторах програм застосовується техніка **інтерполяції Крейга (Craig Interpolation)**.

Нехай задано дві формули `A` та `B`, кон'юнкція яких є нездійсненною: `A ∧ B ⊨ ⊥`. Інтерполянтом Крейга називається така формула `I`, що задовольняє три умови:
1. `A ⊨ I` (інтерполянт є логічним наслідком першої формули).
2. `I ∧ B ⊨ ⊥` (інтерполянт несумісний із другою формулою).
3. `Vars(I) ⊆ Vars(A) ∩ Vars(B)` (інтерполянт містить виключно спільні символи обох формул).

У SMT-LIB 2.6 отримання інтерполянта здійснюється через команду `(get-interpolant A B)`. LIA-сольвер будує інтерполянт безпосередньо з графа доведення `UNSAT`, об'єднуючи коефіцієнти нерівностей Фа Farkas та цілочисельних відтинань Гоморі. Отриманий інтерполянт є готовим кандидатом на інваріант циклу або роздільну умову у верифікації безпеки пам'яті.

## 5. Мінімізація ядер суперечності (UNSAT Core Extraction)

Коли велика система обмежень із тисяч рядків виявляється нездійсненною, інженеру необхідно локалізувати конкретну причину конфлікту. Для цього використовується механізм вилучення мінімальних ядер несумісності (Minimal Unsatisfiable Subsets, MUS).

Для активації механізму кожне твердження маркується ідентифікатором за допомогою синтаксичної конструкції `(! <formula> :named <name>)`:

```smt2
(set-option :produce-unsat-cores true)
(assert (! (<= x 0) :named c1))
(assert (! (>= x 5) :named c2))
(assert (! (<= y 10) :named c3))
(check-sat)
(get-unsat-core)
; Результат: (c1 c2) — твердження c3 не брало участі у виникненні суперечності
```

Програмно відстеження реалізується через **активаційні літерали (Assumption Literals)**: кожна асерція `F_i` замінюється на імплікацію `a_i → F_i`, а виклик розв'язувача виконується командою `(check-sat-assuming (a₁ a₂ ... a_k))`. Під час аналізу конфлікту 1-UIP булевий CDCL-рушій повертає підмножину припущень `{ a_i }`, що утворили фінальну суперечність.

## 6. Квантори та тригери шаблонів (E-Matching Triggers)

У повній кванторній логіці `LIA` формули можуть містити квантори загальності `forall` для вираження інваріантів масивів, індуктивних тверджень та системних специфікацій. Оскільки повна елімінація кванторів за алгоритмом Купера вимагає подвійно експоненційного часу, сучасні розв'язувачі використовують евристичне інстанціювання кванторів за зразками (E-matching).

Для керування цим процесом у стандарті SMT-LIB використовується атрибут шаблону `:pattern`:

```smt2
(assert (forall ((i Int)) 
  (! (=> (and (<= 0 i) (< i len)) 
         (= (select arr i) 0))
     :pattern ((select arr i)))))
```

Шаблон `(select arr i)` вказує сольверу: інстанціювати даний квантор конкретним цілим числом `i = k` слід **лише тоді**, коли в активному табло чи булевому басейні з'являється терм `(select arr k)`. Без явної вказівки шаблонів або при наявності циклічних тригерів (Matching Loops) кванторний рушій може нескінченно генерувати нові терми, що призводить до статусу `unknown` через вичерпання лімітів пам'яті.

## 7. Параметри конфігурації та евристики LIA-рушія

Стандарт SMT-LIB дозволяє тонко налаштовувати внутрішні евристики розв'язувача через команду `set-option`:

| Параметр конфігурації | Типове значення | Вплив на роботу розв'язувача |
| :--- | :--- | :--- |
| `:smt.arith.solver` | `2` | Обирає алгоритм: `0` — алгоритм Беллмана — Форда (різницева логіка), `1` — класичний симплекс, `2` — дуальний симплекс Дютертра — де Моури. |
| `:smt.arith.branch_and_bound` | `true` | Вмикає комбінаторне цілочисельне розгалуження при наявності дробових змінних. |
| `:smt.arith.greatest_error_pivot` | `true` | Активує вибір шарнірного рядка з максимальним порушенням межі замість першого знайденого. |
| `:smt.mbqi` | `true` | Вмикає інстанціювання кванторів на основі збудованої скінченної моделі (Model-Based Quantifier Instantiation). |
| `:smt.restart.strategy` | `geometric` | Встановлює стратегію періодичного перезапуску пошуку (`geometric` або `luby`). |
| `:timeout` | `0` (без ліміту) | Встановлює граничний час виконання перевірки в мілісекундах. |

## 8. Організація пам'яті та інтернування термів (Hash-Consing)

При роботі з формулами, що містять сотні тисяч арифметичних обмежень, ключовим фактором масштабованості є швидкість порівняння термів та мінімізація споживання оперативної пам'яті.

Промислові SMT-рушії використовують техніку **інтернування термів (Hash-Consing)**:
1. **Канонічна таблиця хешування:** Будь-який терм (наприклад, `x + 2*y`) при створенні перевіряється в глобальній таблиці. Якщо терм із такою ж структурою та операндами вже існує, повертається чинний покажчик.
2. **Порівняння за O(1):** Перевірка структурної еквівалентності двох складних виразів `A` та `B` зводиться до простого порівняння числових адрес покажчиків `ast_a == ast_b`.
3. **Компактне представлення:** Кожен вузол AST займає у пам'яті рівно 32–48 байтів, що містять код операції, сорт, лічильник посилань та масив покажчиків на дочірні вузли.
4. **Очищення невикористовуваних термів:** Контекст підтримує підрахунок посилань (Reference Counting) або блокове очищення арени пам'яті при виклику команди `smt_solver_reset()`, що запобігає витокам пам'яті під час тривалого інкрементального аналізу.

## 9. Протокол текстової взаємодії через канали IPC

У промислових конвеєрах верифікації (Dafny, Boogie, KLEE, CBMC) SMT-сольвер часто запускається як окремий дочірній процес ОС, взаємодія з яким відбувається через стандартні потоки вводу-виводу (`stdin`/`stdout`) за допомогою асинхронних каналів (Anonymous Pipes).

Протокол взаємодії підпорядковується суворим правилам:
1. **Однорядкові команди:** Клієнт записує S-вираз у `stdin` сольвера, завершуючи його символом нового рядка `\n`.
2. **Синхронізація відповідей:** На кожну команду `(check-sat)` сольвер відповідає рівно одним рядком у `stdout`: `sat`, `unsat` або `unknown`.
3. **Обробка помилок:** Якщо синтаксис формули порушено, сольвер повертає повідомлення у форматі `(error "<опис помилки>")`. Клієнт зобов'язаний обробляти такі повідомлення без аварійного завершення.
4. **Гарантія скидання буферів:** Після запису кожної команди верифікатор зобов'язаний викликати системну функцію `fflush()`, інакше через буферизацію вводу-виводу процес може зависнути в очікуванні відповіді.

## 10. Потокобезпека та багатопотокова інтеграція

При проектуванні високопродуктивних аналізаторів програмного коду перевірка сотень функцій виконується паралельно на багатьох ядрах процесора.

Контракт багатопоточності передбачає:
1. **Ізоляція розв'язувачів:** Екземпляри `SmtSolver` не поділяють спільний стан і можуть одночасно виконувати `smt_solver_check()` у різних потоках ОС.
2. **Незмінність вузлів AST:** Вузли `SmtAst` є спільними для всіх розв'язувачів у межах одного `SmtContext`. Читання AST є повністю потокобезпечним. Створення нових вузлів захищається внутрішнім швидким spinlock-блокуванням таблиці хешування.
3. **Асинхронне переривання (`smt_solver_interrupt`):** Дозволяє керуючому потоку безпечно зупинити тривале обчислення за таймаутом без примусового вбивства процесу.

## 11. Зразок SMT-LIB сценарію для задачі верифікації

Розглянемо повний лістинг SMT-LIB файлу для перевірки безпеки доступу до буфера: `0 <= idx < len` при модифікації індексу `idx_next = idx + step`:

```smt2
; Встановлюємо логіку безкванторної лінійної цілочисельної арифметики
(set-logic QF_LIA)

; Вмикаємо опції створення моделей та відстеження ядер суперечності
(set-option :produce-models true)
(set-option :produce-unsat-cores true)

; Оголошуємо символічні цілочисельні змінні
(declare-const len Int)
(declare-const idx Int)
(declare-const step Int)
(declare-const idx_next Int)

; Початкові інваріанти структури даних
(assert (! (>= len 10) :named bound_len))
(assert (! (and (>= idx 0) (< idx len)) :named valid_idx))
(assert (! (= step 2) :named const_step))
(assert (! (= idx_next (+ idx step)) :named next_def))

; Перевіряємо, чи можливий вихід за межі масиву (idx_next >= len)
(assert (! (>= idx_next len) :named property_violation))

; Запускаємо перевірку
(check-sat)

; Отримуємо контрприклад, якщо порушення можливе
(get-model)
(get-value (idx len idx_next))
```

## 12. Програмний C/C++ API для LIA-сольвера

Програмний інтерфейс SMT-сольвера спроектований за принципом **непрозорих покажчиків (Opaque Pointers)** для чистого C-ABI, а для C++ надається ідіоматична обгортка з контролем часу життя об'єктів за принципом RAII, перевантаженням операторів та безпекою винятків.

### Модель пам'яті та взаємодія об'єктів

1. **Контекст (`SmtContext`):** Фабричний об'єкт, що володіє пулом пам'яті AST-термів та глобальною таблицею інтернування символів.

    Unknown = 0

public:

## 13. Інкрементальний робочий процес та патерни інтеграції

При інтеграції LIA-сольвера в компіляторні конвеєри типовий робочий процес будується за схемою **інкрементального розширення бази фактів**:

1. **Ініціалізація глобальних обмежень:** Оголошуються інваріанти типів даних та діапазони адрес пам'яті на базовому рівні стека (`scope level 0`).
2. **Символічний обхід гілок коду:** При вході в умовний блок `if (cond)` виконується `push()`, після чого додається обмеження умови `assert(cond)`.
3. **Перевірка досяжності:** Викликається `check()`. Якщо отримано `unsat`, гілка є мертвою (Dead Code Elimination).
4. **Вертання стану:** Після завершення аналізу тіла гілки викликається `pop()`, що миттєво повертає симплекс-табло та CDCL-рушій до початкового стану без необхідності перестворення всієї структури табло з нуля.

## 14. Інваріанти, коди повернення та обробка виняткових станів

При виконанні команди `(check-sat)` або виклику `smt_solver_check()` система повертає один із трьох строго специфікованих результатів:

1. **`sat` (`SMT_RES_SAT`):**
   Система тверджень повністю сумісна. Існує щонайменше одна математична оцінка змінних `I: Vars → Z`, що перетворює всі асерції на істинні. Після цього стану гарантовано успішними є виклики `(get-model)` та `(get-value)`.

2. **`unsat` (`SMT_RES_UNSAT`):**
   Доведено тотожну суперечність кон'юнкції тверджень. Жодного цілочисельного розв'язку не існує. Якщо було увімкнено опцію `:produce-unsat-cores`, розв'язувач гарантує побудову сертифіката нездійсненності або ядра суперечності `(get-unsat-core)`.

3. **`unknown` (`SMT_RES_UNKNOWN`):**
   Розв'язувач зупинив роботу без точного вердикту. Цей стан виникає виключно за таких умов:
   - Перевищено встановлений ліміт часу (`:timeout`) або пам'яті (`:max-memory`).
   - Кількість кроків розгалуження в дереві Branch-and-Bound перевищила граничний поріг.
   - Формула містить квантори або нелінійні фрагменти, що виходять за межі вирішуваного алгоритмом класу.

## 15. Протокол генерації сертифікатів доведення (Proof Certificates)

Сучасні системи критичної верифікації вимагають незалежної зовнішньої перевірки результатів `UNSAT`. Для цього SMT-LIB визначає механізм виводу формальних доведень через команду `(get-proof)` у стандартизованих форматах Alethe, LFSC або DRAT.

Сертифікат доведення для LIA складається з орієнтованого ациклічного графа (DAG), вузлами якого є:
- **Листки:** Початкові асерції формули.
- **Внутрішні вузли Farkas:** Лінійні комбінації нерівностей з невід'ємними коефіцієнтами Фа Farkas, що утворюють строгу числову суперечність вигляду `0 ≤ -1`.
- **Вузли Chvátal — Gomory:** Операції округлення коефіцієнтів та вільних членів при переході від раціональних нерівностей до цілочисельних відтинань.
- **Резолюційні вузли:** Булеві кроки резолюції, що комбінують виведені теорійні леми з булевими диз'юнктами до отримання порожнього диз'юнкта `⊥`.

Розрізняють два рівні гранулярності сертифікатів:
- **Деталізовані доведення (Fine-grained proofs):** Кожен арифметичний крок розписано до аксіом певної системи виводу.
- **Крупнозернисті леми (Coarse-grained theory lemmas):** Теорійні леми декларуються як доведені відповідним підсольвером.

Зовнішній верифікатор доведень (Proof Checker, наприклад, Carcara) перевіряє кожен крок резолюції та лему Фа Farkas за допомогою семантичної уніфікації за лінійний час від розміру сертифіката, що забезпечує абсолютний рівень довіри до результатів автоматичної верифікації апаратури та критичного софту.

## 16. Експорт контрприкладів та генерація тестів

У практиці тестування програмного забезпечення (Directed Automated Random Testing, конколічне тестування) SMT-сольвер використовується як генератор тестових векторів. Коли статичний аналізатор виявляє шлях до вразливості або порушення асерції, знайдена модель `M` експортується у структурований вигляд (JSON, C-структури, бінарні пакети).

Кожна цілочисельна змінна `x` з моделі конвертується у відповідний машинний тип (`int32_t`, `uint64_t`), а предикати шляху стають конкретними вхідними аргументами для відтворення бага у тестовому стенді. Це повністю автоматизує процес від виявлення теоретичного дефекту до створення робочого регресійного тесту.
