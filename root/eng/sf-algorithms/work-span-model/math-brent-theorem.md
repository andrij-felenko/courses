# 🧮 Теорема Брента та строгі межі жадібного планування

Під час виконання обчислювального графа `G = (V, E)` на паралельній системі виникає питання: скільки тактів часу `T_P` знадобиться системі з `P` процесорних ядер, якщо планувальник не знає майбутньої структури графа наперед і приймає локальні рішення в реальному часі? Теорема Брента (відома також як теорема про жадібне планування Блумофа — Лейзерсона) доводить, що будь-який жадібний планувальник, який не дозволяє процесорам простоювати за наявності готової роботи, гарантує час виконання, що перевищує теоретичний оптимум щонайбільше вдвічі.

---

## Формальна модель обчислювального графа

Нехай паралельна програма представлена спрямованим ациклічним графом `G = (V, E)`:
- Кожна вершина `v ∈ V` відповідає неподільній послідовній інструкції (елементарному потоку операцій — англ. *strand*), виконання якої на одному ядрі займає рівно 1 такт часу (одиничну вагу `w(v) = 1`).
- Кожне спрямоване ребро `(u, v) ∈ E` задає строгу залежність за даними або керуванням: вершина `v` не може почати виконуватися, доки вершина `u` не завершить виконання.

Загальна кількість вершин у графі визначає повну роботу програми `T₁`:

```
T₁ = |V| = ∑ 1    [де сума береться за всіма v ∈ V]
```

Глибина графа (критичний шлях) `T_∞` визначається довжиною найдовшого спрямованого шляху між будь-яким початковим вузлом (джерелом) та кінцевим вузлом (стоком):

```
T_∞ = max { |p| : p є спрямованим шляхом у графі G }
```

---

## Визначення жадібного планувальника

Планувальник називається **жадібним** (англ. *greedy scheduler*), якщо на кожному дискретному такті часу `t ∈ {1, 2, ..., T_P}` він діє за детермінованим правилом максимального завантаження:
1. Нехай `R_t ⊆ V` — множина **готових до виконання вершин** на кроці `t`. Вершина `v` вважається готовою (`v ∈ R_t`), якщо всі її прямі попередники `Pred(v) = { u ∈ V : (u, v) ∈ E }` вже були повністю виконані на попередніх кроках `1, ..., t - 1`.
2. Якщо `|R_t| ≤ P`, планувальник призначає на виконання **всі** готові вершини `R_t`, задіюючи `|R_t|` процесорів (решта `P - |R_t|` процесорів вимушено простоюють через брак готових задач).
3. Якщо `|R_t| > P`, планувальник обирає будь-яку довільну підмножину з `P` готових вершин і призначає їх на виконання, задіюючи всі `P` процесорів (жоден процесор не простоює).

---

## Класифікація кроків планування

Розіб'ємо всю часову послідовність з `T_P` дискретних тактів на два взаємно неперетинні класи:

1. **Повні кроки (Complete steps, множина `S_full`):** кроки, на яких кількість готових задач була не меншою за кількість процесорів (`|R_t| ≥ P`). На кожному такому кроці працюють усі `P` процесорів, виконуючи сумарно рівно `P` вершин графа.
2. **Неповні кроки (Incomplete steps, множина `S_incomp`):** кроки, на яких кількість готових задач була строго меншою за кількість процесорів (`|R_t| < P`). На цих кроках планувальник виконав абсолютно всі готові вершини `R_t`, які існували в системі на даний момент.

Загальний час виконання `T_P` дорівнює сумі кількостей кроків обох типів:

```
T_P = |S_full| + |S_incomp|
```

---

## Оцінка кількості неповних кроків (Лема про критичний шлях)

Доведемо, що кількість неповних кроків за будь-якого жадібного планування строго обмежена довжиною критичного шляху: `|S_incomp| ≤ T_∞`.

Нехай `G_t = (V_t, E_t)` — залишковий підграф графа `G`, що складається з вершин `V_t ⊆ V`, які ще не були виконані до початку такту `t`. Довжина найдовшого спрямованого шляху в `G_t` позначає залишковий критичний шлях `span(G_t)`. На початку роботи `span(G₁) = T_∞`, а після повного завершення програми `span(G_{T_P + 1}) = 0`.

Розглянемо довільний неповний крок `t ∈ S_incomp`. За визначенням, множина готових вершин `R_t` містить **усі** вершини залишкового графа `G_t`, які мають нульовий вхідний напівстепінь (`in-degree = 0` у `G_t`). Оскільки крок неповний і `|R_t| < P`, жадібний планувальник забирає на виконання всю множину `R_t` повністю.

Будь-який найдовший шлях `p_max` у залишковому підграфі `G_t` обов'язково починається з деякої вершини з нульовим вхідним напівстепенем, тобто з деякої вершини `u ∈ R_t`. Оскільки ця початкова вершина `u` повністю виконується на поточному кроці `t`, вона видаляється з графа `G_{t+1}`. Відповідно, максимальна довжина будь-якого шляху в підграфі `G_{t+1}` зменшується щонайменше на 1:

```
span(G_{t+1}) ≤ span(G_t) - 1    [для кожного неповного кроку t ∈ S_incomp]
```

На повних кроках `t ∈ S_full` довжина критичного шляху також не може збільшуватися (`span(G_{t+1}) ≤ span(G_t)`). Оскільки початкова довжина шляху дорівнює `T_∞`, кінцева дорівнює `0`, а кожний неповний крок зменшує довжину як мінімум на 1, загальна кількість таких кроків не може перевищувати початкову довжину:

```
|S_incomp| ≤ T_∞
```

---

## Оцінка кількості повних кроків та виведення теореми Брента

На кожному з `|S_full|` повних кроків виконується рівно `P` вершин. На кожному з `|S_incomp|` неповних кроків виконується щонайменше 1 вершина графа. Оскільки загальна кількість виконаних вершин за всі кроки дорівнює повній роботі `T₁ = |V|`, запишемо баланс виконаної роботи:

```
T₁ ≥ P · |S_full| + 1 · |S_incomp|
```

Виразимо кількість повних кроків `|S_full|`:

```
P · |S_full| ≤ T₁ - |S_incomp|
|S_full| ≤ (T₁ - |S_incomp|) / P
```

Оскільки кількість кроків є цілим числом, застосуємо операцію взяття цілої частини (підлоги):

```
|S_full| ≤ ⌊(T₁ - |S_incomp|) / P⌋
```

Підставимо отриману оцінку у вираз для загального часу `T_P`:

```
T_P = |S_full| + |S_incomp|
    ≤ ⌊(T₁ - |S_incomp|) / P⌋ + |S_incomp|     [підстановка оцінки для |S_full|]
```

Оскільки функція `f(k) = ⌊(T₁ - k) / P⌋ + k` монотонно не спадає за змінною `k` при `P ≥ 1` (збільшення `k` на 1 зменшує дріб щонайбільше на `1/P ≤ 1`, що перекривається збільшенням другого доданка на `1`), максимальне значення виразу досягається при максимально можливому значенні `|S_incomp| = T_∞`:

```
T_P ≤ ⌊(T₁ - T_∞) / P⌋ + T_∞
```

Розкриваючи операцію цілої частини, отримуємо класичну строгу верхню межу:

```
T_P ≤ (T₁ - T_∞) / P + T_∞
    = T₁ / P + T_∞ - T_∞ / P                   [ділення почленно]
    = T₁ / P + T_∞ · (1 - 1 / P)               [винесення T_∞ за дужки]
    < T₁ / P + T_∞                             [оскільки T_∞ / P > 0 при T_∞ > 0]
```

Це співвідношення і є **теоремою Брента**.

---

## Точність верхньої межі (Tightness)

Доведемо, що верхня межа теореми Брента `T_P ≤ ⌊(T₁ - T_∞) / P⌋ + T_∞` є асимптотично точною і не може бути покращена в загальному випадку без додаткових припущень про топологію графа.

Розглянемо сімейство графів, що складаються з двох послідовних фаз:
1. **Широка паралельна фаза:** множина з `W_par = T₁ - T_∞` незалежних ізольованих вершин, кожна з яких має одиничну вагу `1`.
2. **Вузька послідовна фаза:** лінійний ланцюжок із `T_∞` вершин, з'єднаних послідовними ребрами `v₁ → v₂ → ... → v_{T_∞}`.

Якщо жадібний планувальник спочатку виконує всі незалежні вершини першої фази, він витрачає на них рівно `⌈(T₁ - T_∞) / P⌉` повних кроків. Після цього всі `P` процесорів змушені виконувати лінійний ланцюжок другої фази, де на кожному кроці доступна лише 1 готова вершина, що вимагає рівно `T_∞` неповних кроків. Сумарний час становить:

```
T_P = ⌈(T₁ - T_∞) / P⌉ + T_∞
```

Це доводить, що оцінка Брента є точною для довільних жадібних планувальників.

---

## 2-апроксимаційна гарантія жадібного розкладу

Порівняємо час виконання за теоремою Брента `T_P` з теоретично недосяжним абсолютним мінімумом `T_opt(P) = max(T₁ / P, T_∞)`:

```
T_P < T₁ / P + T_∞
    ≤ max(T₁ / P, T_∞) + max(T₁ / P, T_∞)     [оскільки кожний доданок ≤ max(T₁/P, T_∞)]
    = 2 · max(T₁ / P, T_∞)
    ≤ 2 · T_opt(P)                             [оскільки T_opt(P) ≥ max(T₁/P, T_∞)]
```

> **Теоретичний висновок:** Будь-який жадібний планувальник знаходить розклад, тривалість якого менша за подвоєний оптимальний час, навіть діючи суто локально в режимі реального часу.

---

## Аналіз паралельного запасу (Parallel Slackness)

Введемо безрозмірний коефіцієнт паралельного запасу `σ`, який відображає відношення середнього внутрішнього паралелізму задачі `P_max = T₁ / T_∞` до кількості фізичних процесорів `P`:

```
σ = (T₁ / T_∞) / P
```

Виразимо критичний шлях через роботу та запас: `T_∞ = T₁ / (P · σ)`. Підставимо цей вираз у нерівність Брента для оцінки реального прискорення `S_P = T₁ / T_P`:

```
T_P ≤ T₁ / P + T₁ / (P · σ)
    = (T₁ / P) · (1 + 1 / σ)                  [винесення T₁/P за дужки]
```

Обчислимо гарантоване прискорення `S_P`:

```
S_P = T₁ / T_P
    ≥ T₁ / ( (T₁ / P) · (1 + 1 / σ) )          [підстановка верхньої межі для T_P]
    = P / (1 + 1 / σ)                          [скорочення на T₁]
    = P · (σ / (σ + 1))                        [алгебраїчне перетворення]
```

Ефективність використання ядер `E_P = S_P / P`:

```
E_P ≥ σ / (σ + 1) = 1 - 1 / (σ + 1)
```

| Коефіцієнт запасу `σ = P_max / P` | Гарантована частка від лінійного прискорення `S_P / P` | Верхня межа втрат ефективності |
|---|---|---|
| `σ = 0.5` | `≥ 33.3%` | `≤ 66.7%` |
| `σ = 1.0` (точка коліна) | `≥ 50.0%` | `≤ 50.0%` |
| `σ = 2.0` | `≥ 66.7%` | `≤ 33.3%` |
| `σ = 4.0` | `≥ 80.0%` | `≤ 20.0%` |
| `σ = 10.0` | `≥ 90.9%` | `≤ 9.1%` |
| `σ = 32.0` | `≥ 97.0%` | `≤ 3.0%` |
| `σ = 100.0` | `≥ 99.0%` | `≤ 1.0%` |

Звідси випливає фундаментальне правило паралельної інженерії: якщо алгоритм спроєктовано з паралельним запасом `σ ≥ 10`, нерівномірність структури графа та локальні затримки планувальника практично не впливають на лінійність прискорення.
