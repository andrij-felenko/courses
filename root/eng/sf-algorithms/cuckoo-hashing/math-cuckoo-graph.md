# 🧮 Графова модель зозулі: фазовий перехід та гарантії витіснення

Хешування зозулею спирається на елегантну й строгу математичну конструкцію теорії випадкових графів. Можливість успішно розмістити `n` ключів у таблиці без нескінченних циклів витіснення еквівалентна класичній задачі орієнтації ребер випадкового графа з обмеженням на напівстепінь заходу вершин.

Розгляньмо структуру двох таблиць `T₁` та `T₂`, кожна з яких містить `m` комірок, куди вставляється множина з `n` ключів `S = {x₁, x₂, ..., xₙ}` за допомогою двох незалежних рівномірних хеш-функцій `h₁: S → {0, ..., m−1}` та `h₂: S → {0, ..., m−1}`. Загальний розмір простору становить `M = 2m`, а коефіцієнт заповнення дорівнює:

```
α = n / (2m) = n / M      [визначення коефіцієнта заповнення]
```

## Граф зозулі як двочастковий випадковий граф

Структура розміщення ключів повністю моделюється [двочастковим графом](root:sf-algorithms/bipartite-graph) `G = (V₁, V₂, E)`:

1. **Множина вершин лівої частки `V₁`**: `m` слотів першої таблиці `T₁`, тобто `V₁ = {u₀, u₁, ..., u_{m−1}}`.
2. **Множина вершин правої частки `V₂`**: `m` слотів другої таблиці `T₂`, тобто `V₂ = {v₀, v₁, ..., v_{m−1}}`.
3. **Множина ребер `E`**: кожен ключ `x ∈ S` породжує неорієнтоване ребро `e = (u_{h₁(x)}, v_{h₂(x)})`, що з'єднує два його потенційні притулки в `T₁` та `T₂`.

Загальна кількість вершин у графі дорівнює `|V| = |V₁| + |V₂| = 2m = M`, а кількість ребер — кількості збережених ключів `|E| = n`.

## Розміщення ключів як орієнтація ребер

Зберегти ключ `x` у комірці `T₁[h₁(x)]` означає надати ребру `(u_{h₁(x)}, v_{h₂(x)})` орієнтацію у напрямку вершини `u_{h₁(x)}`. Відповідно, зберегти ключ у `T₂[h₂(x)]` означає орієнтувати ребро у напрямку `v_{h₂(x)}`.

Оскільки кожна комірка таблиці може містити **щонайбільше один** ключ, валідне розміщення всіх `n` ключів можливе тоді й лише тоді, коли існує така орієнтація ребер графа `G`, за якої напівстепінь заходу (англ. *in-degree*) кожної вершини не перевищує одиниці:

```
deg⁻(w) ≤ 1,  ∀w ∈ V₁ ∪ V₂    [інваріант місткості комірки]
```

Розгляньмо довільну зв'язну компоненту `C = (V_C, E_C)` у графі `G`. Нехай `|V_C| = k` — кількість вершин у компоненті, а `|E_C|` — кількість ребер. Залежно від співвідношення між кількістю ребер та вершин виникають три фундаментальні топології:

### 1. Деревовидна компонента (`|E_C| = k − 1`)

Компонента є деревом на `k` вершинах. Дерево має рівно на одне ребро менше, ніж вершин. Якщо вибрати довільну вершину `r ∈ V_C` як корінь і зорієнтувати кожне ребро від нащадка до його предка (або навпаки від предка до нащадка у напрямку від кореня), кожна вершина крім кореня отримає рівно одне вхідне ребро:

```
deg⁻(w) = 1,  ∀w ∈ V_C \ {r}    [кожна вершина крім кореня має 1 ключ]
deg⁻(r) = 0                     [корінь r залишається вільним слотом]
```

Розміщення ключів завжди існує. Вільний слот `r` слугує точкою зупинки для будь-якого ланцюжка витіснень, що потрапляє в цю компоненту.

### 2. Одноциклічна компонента (`|E_C| = k`)

Компонента містить рівно один простий цикл і, можливо, приєднані до нього дерева. Кількість ребер строго дорівнює кількості вершин.
Орієнтація циклу за годинниковою або проти годинникової стрілки дає `deg⁻(w) = 1` для всіх вершин циклу, а ребра приєднаних дерев орієнтуються у бік своїх піддерев. Усі `k` слотів заповнюються ключами (`deg⁻(w) = 1` для всіх `w ∈ V_C`), вільних слотів немає, проте конфлікту місткості не виникає. Розміщення ключів існує та є локально стійким.

### 3. Комплексна / біциклічна компонента (`|E_C| ≥ k + 1`)

Компонента містить два або більше циклів, тобто кількість ребер строго перевищує кількість вершин (`|E_C| > |V_C|`).
За принципом Діріхле (принципом скриньок), якщо спробувати орієнтувати `k + 1` ребер у множину з `k` вершин, сума напівстепенів заходу становитиме:

```
∑_{w ∈ V_C} deg⁻(w) = |E_C| ≥ k + 1    [сума вхідних ступенів за теоремою про рукостискання]
```

Звідси неминуче випливає існування хоча б однієї вершини `w* ∈ V_C`, для якої:

```
deg⁻(w*) ≥ 2                          [принцип Діріхле: колізія комірки]
```

Орієнтація з `deg⁻(w) ≤ 1` математично неможлива. Спроба вставити новий ключ, що замикає другий цикл у компоненті, викликає нескінченне циклічне витіснення: ключ `x` вибиває `y`, `y` вибиває `z`, а через кілька кроків черговий витіснений ключ знову намагається зайняти комірку `x`. Алгоритм фіксує перевищення граничної кількості кроків і змушений запустити повне перехешування.

## Підрахунок ймовірності виникнення простих циклів

Обчислимо математичне сподівання кількості простих чергованих циклів парної довжини `2k` у двочастковому випадковому графі `G`. Цикл довжини `2k` складається з `k` вершин у `V₁` та `k` вершин у `V₂`.

Кількість способів вибрати та впорядкувати таку послідовність вершин становить:

```
N(k) = (m! / (m − k)!) · (m! / (m − k)!) / (2k)    [вибір k вершин у V1 та V2 з урахуванням симетрії циклу]
≈ m^{2k} / (2k)                                     [асимптотика при m >> k]
```

Ймовірність того, що між конкретною парою послідовних вершин циклу існує ребро, породжене хоча б одним із `n` випадкових ключів, становить приблизно `n / m²`. Відповідно, ймовірність одночасної наявності всіх `2k` ребер утворює добуток:

```
P(наявність 2k ребер) ≈ (n / m²)^{2k} = ( (n / m) / m )^{2k} = ( (2α) / m )^{2k}    [добуток незалежних подій]
```

Перемноживши кількість можливих циклів на ймовірність появи кожного з них, отримуємо математичне сподівання кількості циклів довжини `2k`:

```
E[C_{2k}] ≈ (m^{2k} / (2k)) · ( (2α) / m )^{2k}
= (2α)^{2k} / (2k)                                                                   [скорочення m^{2k}]
```

Сума математичних сподівань для всіх можливих довжин циклів `k ≥ 2` утворює степеневий ряд:

```
∑_{k=2}^{∞} E[C_{2k}] = ∑_{k=2}^{∞} (2α)^{2k} / (2k)    [сумарне очікуване число циклів]
```

Цей ряд збігається тоді й лише тоді, коли основа степеня строго менша за одиницю:

```
(2α)² < 1
2α < 1
α < 1/2 = 0.50                                         [умова збіжності ряду циклів]
```

Коли `α < 0.50`, очікувана кількість циклів є скінченною малою константою, а розподіл кількості циклів асимптотично прямує до розподілу Пуассона. Але щойно `α` перевищує `0.50`, ряд розбігається, що свідчить про лавиноподібне народження переплетених циклів.

## Фазовий перехід та граничний коефіцієнт заповнення

Теорія випадкових графів Ердеша — Реньї доводить, що структура компонент випадкового графа зазнає різкого якісного стрибка — **фазового переходу** (англ. *phase transition*), — коли середня щільність ребер досягає критичного порогу.

Середній степінь вершини у графі `G` дорівнює `c = 2n / (2m) = n / m = 2α`.

1. **Підкритичний режим (`α < 0.50`, тобто `c < 1`):**
   Усі зв'язні компоненти графа `G` з високою ймовірністю (англ. *with high probability, w.h.p.*) є або деревами, або містять щонайбільше один простий цикл. Максимальний розмір зв'язної компоненти обмежений величиною `O(log n)`.
   Ймовірність появи хоча б однієї біциклічної компоненти обмежена малою величиною:

   ```
   P(існує біциклічна компонента) = O(1 / n)    [ймовірність збою при α < 0.5]
   ```

2. **Надкритичний режим (`α > 0.50`, тобто `c > 1`):**
   У графі виникає так звана **гігантська компонента** (англ. *giant component*), яка містить лінійну частку всіх вершин `Θ(n)` та щільну мережу циклів (`|E_giant| > |V_giant|`). Валідна орієнтація ребер стає неможливою з імовірністю, що прямує до 1 при `n → ∞`.

Таким чином, для класичної схеми з двома хеш-функціями (`d = 2`) та розміром кошика в один слот (`b = 1`) критичним математичним порогом є:

```
α_c = 1 / 2 = 50%    [критичний поріг для d=2, b=1]
```

## Математичне очікування довжини ланцюжка вставки

Під час вставки нового ключа `x` алгоритм починає обхід у глибину (або у ширину) вздовж дерева витіснень. Нехай `L` — кількість кроків витіснення до знаходження першого вільного слота.

Коли таблиця працює в підкритичному режимі з коефіцієнтом `α = (1 − ε) / 2` для фіксованого `ε > 0`, імовірність того, що довжина шляху витіснення перевищить значення `t`, спадає експоненційно:

```
P(L ≥ t) ≤ (2α)^t = (1 − ε)^t    [експоненційне згасання хвоста розподілу]
```

Обчислимо математичне сподівання довжини шляху `E[L]`:

```
E[L] = ∑_{t=1}^{∞} P(L ≥ t)
≤ ∑_{t=1}^{∞} (1 − ε)^t          [застосування геометричного ряду]
= (1 − ε) / (1 − (1 − ε))        [сума спадної геометричної прогресії]
= (1 − ε) / ε = O(1)             [сталий очікуваний час вставки]
```

Оскільки `E[L] = O(1)`, середня кількість переміщень елементів під час кожної вставки є строго сталою величиною, що доводить амортизовану складність вставки `O(1)`.

## Розширення порогу: більше хеш-функцій та блокові кошики

Обмеження `α < 50%` є прямим наслідком топології випадкових графів із `d = 2` та `b = 1`. Математики дослідили два незалежні шляхи підняття порогу `α_c`:

### 1. Гіперграфи з `d ≥ 3` хеш-функціями

Якщо кожен ключ асоціюється з `d ≥ 3` незалежними комірками, модель перетворюється на `d`-однорідний випадковий гіперграф, де кожне гіперребро з'єднує `d` вершин. Задача полягає в орієнтації кожного гіперребра в одну з `d` його вершин.

Теоретичні розрахунки Діцфельбінгера та співавторів показали разючий стрибок порогу орієнтованості:

```
d = 2:  α_c ≈ 0.5000 (50.0%)
d = 3:  α_c ≈ 0.9179 (91.8%)
d = 4:  α_c ≈ 0.9767 (97.7%)
d = 5:  α_c ≈ 0.9924 (99.2%)
```

Для трьох хеш-функцій таблиця здатна вмістити до 91.7% ключів, гарантуючи щонайбільше 3 звернення при пошуку.

### 2. Блокові кошики (b-ary cuckoo hashing, `b ≥ 2`)

Замість збільшення кількості хеш-функцій можна дозволити кожній вершині графа приймати до `b` вхідних ребер (кожна комірка пам'яті стає кошиком місткістю `b` слотів). Обмеження на напівстепінь заходу набуває вигляду `deg⁻(w) ≤ b`.

Для `d = 2` хеш-функцій теоретичні пороги залежно від розміру кошика `b` становлять:

```
b = 1:  α_c ≈ 0.5000 (50.0%)
b = 2:  α_c ≈ 0.8970 (89.7%)
b = 4:  α_c ≈ 0.9750 (97.5%)
b = 8:  α_c ≈ 0.9970 (99.7%)
```

При конфігурації `d = 2, b = 4` (пошук перевіряє рівно 2 кошики по 4 слоти кожен) таблиця досягає коефіцієнта заповнення понад 97%, що ідеально узгоджується з розміром стандартного кеш-рядка процесора (64 байти).

## Алгебра часткового хешування у фільтрах зозулі

У фільтрах зозулі для збереження компактності не зберігається повний ключ, а лише його короткий відбиток `f = hash(x)`. Це створює проблему: якщо ключ витісняється з комірки `i`, як дізнатися альтернативну комірку `j`, не маючи початкового ключа `x`?

Рішенням є техніка **часткового хешування** (англ. *partial-key cuckoo hashing*), яка використовує операцію порозрядного виключного АБО (`⊕`, XOR):

```
h₁(x) = hash(x) mod m
h₂(x) = (h₁(x) ⊕ hash(f)) mod m    [обчислення другого кошика через відбиток]
```

Завдяки інволютивності операції XOR (`(A ⊕ B) ⊕ B = A`) обчислення є абсолютно симетричним:

```
i₂ = (i₁ ⊕ hash(f)) mod m
i₁ = (i₂ ⊕ hash(f)) mod m          [інволюція: i₂ ⊕ hash(f) = i₁ ⊕ hash(f) ⊕ hash(f) = i₁]
```

Це дозволяє переміщувати відбиток між двома кошиками `i₁` та `i₂` безкінечну кількість разів, знаючи лише поточну адресу кошика та сам відбиток `f`, що уможливлює видалення та динамічне витіснення без збереження оригінального ключа.

## Теорема Кірша — Міценмахера про схованку (Stash)

Адам Кірш і Майкл Міценмахер (2008) довели теорему про вплив допоміжної пам'яті фіксованого розміру `s` — так званої **схованки** (англ. *stash*).

З графової точки зору, наявність схованки місткістю `s` дозволяє успішно обробити компоненти, які містять до `s` надлишкових ребер понад кількість вершин (`|E_C| ≤ |V_C| + s`). Тобто таблиця витримує наявність `s` незалежних біциклічних конфліктів без перехешування.

Ймовірність того, що розмір необхідної схованки перевищить `s`, спадає експоненційно від `s`:

```
P(переповнення схованки розміру s) = O(1 / n^{s+1})    [теорема Кірша — Міценмахера]
```

Для практичного значення `s = 4` імовірність невдачі вставки падає з `O(1/n)` до `O(1/n⁵)`. Навіть для таблиці з мільйона елементів (`n = 10⁶`) імовірність перехешування на одну операцію стає меншою за `10⁻³⁰`, що практично усуває ризик раптової деградації продуктивності системи.
