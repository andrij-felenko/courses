# 📋 Інтерфейс та контракт рушія випадкового проєктування

Рушій випадкового проєктування надає програмний контракт для швидкого зменшення розмірності векторних масивів та потокових ембеддингів. Нижче наведено специфікацію типів, функціональних сигнатур, інваріантів пам'яті, гарантій багатопотокової безпеки, рекомендацій щодо векторної SIMD-оптимізації та аналізу обчислювальної складності для мов C та C++.

### Програмний контракт та інтерфейс API

Інтерфейс спроєктовано для двох основних сценаріїв використання:
1. **Потокове перетворення (Streaming Projection)**: обробка окремих векторів запитів з мінімальною латентністю без додаткових виділень динамічної пам'яті.
2. **Пакетне перетворення (Batch Projection)**: паралельна обробка матриць із мільйонів векторів з оптимізацією доступу до кеш-пам'яті процесора та використанням векторних інструкцій SIMD (AVX2, AVX-512, ARM NEON).

### Детальний опис функцій та методів

#### 1. Ініціалізація та життєвий цикл (`rp_create` / Конструктор `Engine`)
- **Призначення**: Створює незмінний екземпляр рушія, виділяє суцільний блок пам'яті розміром `k · d · sizeof(float)` та заповнює його псевдовипадковими коефіцієнтами за обраним законом розподілу.
- **Вхідні вимоги**:
  - `orig_dim` (`d`) має бути строго більшим за 0.
  - `target_dim` (`k`) має задовольняти нерівність `1 ≤ target_dim ≤ orig_dim`.
  - Зерно `seed` може приймати будь-яке 64-бітне значення. Однакове значення `seed` для однакової пари `(d, k)` гарантує побітово ідентичну матрицю перетворення на будь-якій системній архітектурі.
- **Обробка помилок**:
  - C ABI повертає `RP_ERROR_INVALID_ARG`, якщо розмірності нульові або некоректні, або `RP_ERROR_OUT_OF_MEMORY`, якщо системний розподільник пам'яті не зміг виділити необхідний обсяг буфера.
  - C++ API генерує виняток `std::invalid_argument` при некоректних параметрах конфігурації або `std::bad_alloc` при вичерпанні пам'яті.

#### 2. Потокове перетворення (`rp_transform_single` / `Engine::transform`)
- **Призначення**: Проєктує один вхідний вектор довжини `d` у вихідний вектор довжини `k`.
- **Семантика пам'яті**: Функція не виконує динамічних виділень пам'яті (`zero-allocation`). Вихідний буфер `output` має бути попередньо виділений викликаючою стороною.
- **Вимоги до вирівнювання**: Для забезпечення максимальної швидкодії векторних інструкцій SIMD вказівники `in_vec` та `out_vec` повинні бути вирівняні по межі 32 байтів (AVX2) або 64 байтів (AVX-512). Якщо дані не вирівняні, рушій виконує безпечне невирівняне зчитування з незначним зниженням продуктивності.
- **Нормування довжини**: Якщо прапорець `normalize_output` встановлено в `true`, після обчислення координат обчислюється `L2`-норма `||f(u)||`. Якщо норма менша за машинний епсилон `1e-12`, функція повертає код `RP_ERROR_DEGENERATE_NORM` або заповнює вихідний вектор нулями.

#### 3. Пакетне перетворення (`rp_transform_batch` / `Engine::transform_batch`)
- **Призначення**: Виконує масове перетворення масиву з `N` векторів.
- **Оптимізація пам'яті**: Пакет розбивається на кеш-орієнтовані блоки (L1/L2 Cache Blocking). Обчислення виконуються паралельно між потоками пулу без потреби у міжпотоковій синхронізації чи блокуваннях м'ютексами.
- **Параметри кроку (`stride`)**: Параметри `in_stride_floats` та `out_stride_floats` дозволяють обробляти дані з додатковими службовими полями або нестандартним вирівнюванням рядків у матриці.

### Інваріанти структури даних та організація пам'яті

1. **Суцільне розміщення рядків (Row-Major Matrix Layout)**:
   Матриця проєктування `R` зберігається як лінійний одновимірний масив довжини `k · d`. Елемент матриці на перетині `i`-го рядка та `j`-го стовпця розташований за адресою `matrix[i * d + j]`. Таке розташування забезпечує послідовний доступ до пам'яті під час скалярного добутку рядка матриці на вхідний вектор, мінімізуючи промахи лінійного кешу процесора (L1 Data Cache Misses).

2. **Нормування довжини та масштаб коефіцієнтів**:
   Щоб уникнути додаткового ділення на `√k` під час кожного перетворення вектора, нормувальний множник `1 / √k` попередньо вбудовується безпосередньо у значення коефіцієнтів матриці на етапі її ініціалізації:
   - Для гаусового розподілу: `R[i, j] ~ N(0, 1/k)`;
   - Для розрідженого розподілу Ахіоптаса: `R[i, j] ∈ { +√(3/k), 0, -√(3/k) }`.

3. **Стиснення розріджених матриць (CSR Layout)**:
   Для режиму дуже розріджених проєкцій (`VerySparse`, де 99% елементів дорівнюють нулю) рушій використовує формат стисненого зберігання рядків (Compressed Sparse Row, CSR). Замість зберігання нулів зберігаються лише два компактні масиви: індекси ненульових стовпців `col_indices` та їхні бітові знаки `signs`, що зменшує обсяг зайнятої матрицею пам'яті у десятки разів.

### Інтеграція з векторними базами даних та SIMD-оптимізація

Рушій проєктування призначений для інтеграції у сучасні системи наближеного пошуку найближчих сусідів (HNSW, ScaNN, FAISS, Milvus) на етапі попередньої фільтрації запитів:

1. **Конвеєр Filter-and-Refine**:
   Під час індексації всі вектори бази стискаються з розмірності `d = 1536` до `k = 64` і зберігаються в оперативній пам'яті. Коли приходить вектор запиту, він транслюється функцією `rp_transform_single()` у 64-вимірний простір, після чого виконується швидкий приблизний пошук 200–500 найближчих кандидатів. На другому етапі для цих відібраних кандидатів обчислюються точні відстані за початковими 1536 координатами зі сховища. Це скорочує час обробки запиту у 10–20 разів при збереженні повноти видачі (Recall@K) понад 98%.

2. **Векторизація ядра обчислень**:
   Скалярний добуток рядка матриці на вхідний вектор векторизується за допомогою інструкцій множення з накопиченням FMA:
   - На архітектурі x86-64 з підтримкою AVX2 векторні регістри `__m256` обробляють по 8 чисел `float` за один такт через інструкцію `_mm256_fmadd_ps`.
   - На серверах із підтримкою AVX-512 регістри `__m512` обробляють по 16 чисел `float` через `_mm512_fmadd_ps`.
   - На архітектурах ARM64 (Apple Silicon, AWS Graviton) застосовуються регістри NEON `float32x4_t` та інструкції `vfmaq_f32`.

3. **Багатоядерне масштабування та NUMA-топологія**:
   Оскільки матриця проєктування `R` є незмінною, вона може одночасно використовуватися всіма ядрами процесора. Для систем із декількома сокетами (NUMA) рекомендується створювати локальну копію екземпляра `rp_engine_t` на кожному NUMA-вузлі, щоб виключити міжсокетний трафік шини QPI/UPI при зчитуванні матриці з пам'яті сусіднього сокета.

### Порівняльна таблиця характеристик розподілів

| Тип розподілу | Обсяг пам'яті матриці | Операцій на вектор | Операція ядра SIMD | Рекомендоване застосування |
| :--- | :--- | :--- | :--- | :--- |
| **Gaussian** | `k · d · 4` байти | `k · d` FMA | `_mm256_fmadd_ps` | Класичні вектори загального типу, аналітична точність |
| **Rademacher** | `k · d / 8` байтів | `k · d` додавань | `_mm256_add_ps` / знакові маски | Обмежені вбудовані системи, апаратні співпроцесори |
| **Sparse Achlioptas** | `k · d · 4` байти | `k · d / 3` операцій | Пропуск нульових блоків | Векторні бази даних, загальний пошук за схожістю (LSH, ANN) |
| **Very Sparse (`s = √d`)** | `O(k · √d)` ненульових | `k · √d` операцій | Непряма індексація CSR | Гігантські розріджені простори (TF-IDF, біоінформатика) |

### Багатопотокова модель та гарантії безпеки

- **Незмінність стану (Immutability)**: Створений екземпляр рушія є строго незмінним. Усі константні методи є потокобезпечними (`thread-safe`) і можуть викликатися паралельно з довільної кількості потоків виконання без блокувань та синхронізацій.
- **Відсутність витоків ресурсів (RAII)**: Клас C++ `Engine` повністю володіє виділеними ресурсами та автоматично звільняє пам'ять у деструкторі. C-дескриптор `rp_engine_t` вимагає обов'язкового виклику парної функції `rp_destroy`.
