# 🧮 Алгебраїчний аналіз густини графів та точки перетину пам'яті

Математичне виведення формул витрат оперативної пам'яті для матриці, векторних списків, зв'язаних структур і CSR, а також строге знаходження критичної межі густини, де змінюється лідер ефективності.

Вибір між матричним та списковим представленням графа спирається на точний баланс між кількістю вершин `|V|` та кількістю ребер `|E|`. Щоб формалізувати цей баланс, у теорії графів вводять метрику **густини** (density), яка чисельно вимірює ступінь заповненості можливих зв'язків дискретної системи.

## Визначення густини та класифікація графів

Густина `d` показує відношення фактичної кількості ребер до теоретично можливого максимуму для простого графа без петель.

Для орієнтованого графа максимальна кількість ребер дорівнює добутку `|V| · (|V| - 1)`. Густина визначається як:

```
d_dir = |E| / (|V| · (|V| - 1))
```

Для неорієнтованого графа кожна пара вершин з'єднується не більше ніж одним двостороннім ребром, тому максимум становить `|V| · (|V| - 1) / 2`:

```
d_undir = 2 · |E| / (|V| · (|V| - 1))
```

Залежно від асимптотичної поведінки густини при зростанні розміру системи `|V| → ∞`, графи поділяють на два фундаментальні класи:

1. **Розріджені графи (Sparse Graphs)**: Кількість ребер росте пропорційно кількості вершин, тобто `|E| = O(|V|)`. Середній ступінь вершини `deg_avg = 2|E| / |V|` залишається обмеженим сталою величиною `k`, а густина прямує до нуля:
```
lim_{|V| → ∞} d = lim_{|V| → ∞} (k / (|V| - 1)) = 0
```
Майже всі реальні мережі фізичного світу (веб-сторінки та гіперпосилання, транспортні магістралі, соціальні мережі знайомств, енергомережі, молекулярні структури) є сильно розрідженими.

2. **Щільні графи (Dense Graphs)**: Кількість ребер росте пропорційно квадрату кількості вершин, тобто `|E| = Θ(|V|²)`. Густина стабілізується на ненульовому рівні `d > 0` (наприклад, `d = 0.3` або `d = 0.8`). Такі топології виникають у задачах кореляційного аналізу (де кожен фактор пов'язаний з кожним), повних турнірах або матрицях взаємних відстаней.

## Аналітичні формули фізичного обсягу пам'яті (64-бітна архітектура)

Розглянемо реальні витрати оперативної пам'яті в байтах для різних структур даних, де ідентифікатори вершин кодуються 32-бітними беззнаковими цілими числами (`uint32_t`, 4 байти), а адресація пам'яті є 64-бітною (покажчик займає 8 байтів).

### 1. Плоска байтова матриця суміжності (`uint8_t[]` розміром `|V| × |V|`)

Матриця розміщується як один неперервний буфер у купі плюс покажчик на нього:

```
S_mat_byte(|V|, |E|) = |V|² · sizeof(uint8_t) + sizeof(void*)
                     = |V|² + 8 байтів
```

### 2. Біт-пакована матриця суміжності (`std::vector<uint64_t>` або бітова сітка)

Кожна комірка займає рівно 1 біт (0 або 1). Загальна кількість бітів дорівнює `|V|²`:

```
S_mat_bit(|V|, |E|) = ⌈|V|² / 64⌉ · 8 + 24 байтів
                    ≈ (|V|² / 8) байтів
```

### 3. Векторні списки суміжності (`std::vector<std::vector<uint32_t>>`)

Зовнішній вектор містить `|V|` об'єктів `std::vector`. У 64-бітному ABI стандартний вектор складається з трьох покажчиків (`begin`, `end`, `capacity`), що становить 24 байти заголовка на кожну вершину. Динамічні буфери містять сумарно `|E|` елементів по 4 байти (за умови точного виділення пам'яті без запасу `shrink_to_fit`):

```
S_adj_vec(|V|, |E|) = |V| · 24 + |E| · 4 + 24 байтів
```

Якщо вектор має надлишкове виділення пам'яті (типовий коефіцієнт зростання 1.5–2.0), витрати зростають до `24·|V| + 8·|E|`.

### 4. Зв'язані списки вузлів на покажчиках (`Node* adj[|V|]`)

Кожна вершина має покажчик на початок списку (8 байтів). Кожен вузол списку містить ціле число (4 байти), вирівнювання пам'яті до 8 байтів (padding 4 байти) та покажчик на наступний вузол (8 байтів), разом 16 байтів на одне ребро:

```
S_adj_list(|V|, |E|) = |V| · 8 + |E| · 16 байтів
```

### 5. Стиснене представлення рядків (CSR / Forward Star)

Два пласкі масиви: `offsets` розміру `|V| + 1` елементів по 4 байти та `edges` розміру `|E|` елементів по 4 байти:

```
S_csr(|V|, |E|) = (|V| + 1) · 4 + |E| · 4 + 16
                = 4·|V| + 4·|E| + 20 байтів
```

## Виведення точки перетину (Crossover Threshold)

Знайдемо критичну кількість ребер `|E*|`, за якої плоска байтова матриця суміжності зрівнюється за обсягом пам'яті з векторними списками суміжності `std::vector<std::vector<uint32_t>>`.

Прирівняємо відповідні функції пам'яті:

```
S_mat_byte(|V|, |E*|) = S_adj_vec(|V|, |E*|)
|V|² + 8 = 24·|V| + 4·|E*| + 24         [підставили аналітичні вирази]
4·|E*| = |V|² - 24·|V| - 16              [перенесли доданки]
|E*| = (|V|² - 24·|V| - 16) / 4          [поділили на 4]
```

Для великих графів (`|V| ≥ 1000`) доданками першого степеня можна знехтувати:

```
|E*| ≈ |V|² / 4 = 0.25 · |V|²
```

Підставимо отримане критичне значення ребер у формулу густини неорієнтованого графа:

```
d* = 2 · |E*| / (|V| · (|V| - 1))
   ≈ 2 · (0.25 · |V|²) / |V|²            [підстановка |E*| ≈ 0.25 |V|²]
   = 0.50                                [спрощення]
```

Отже, для байтової матриці точка перетину з точними векторами настає при густині **50%**.

### Точка перетину для біт-пакованої матриці

Якщо матриця оптимізована до 1 біта на комірку (`S_mat_bit ≈ |V|² / 8`), розрахунок точки рівноваги проти `std::vector` кардинально зміщується:

```
|V|² / 8 = 24·|V| + 4·|E*|               [рівняння балансу пам'яті]
4·|E*| = |V|² / 8 - 24·|V|               [перенесення членів]
|E*| ≈ |V|² / 32                         [асимптотичне спрощення]
```

Критична густина для бітової матриці:

```
d*_bit = 2 · (|V|² / 32) / |V|²
       = 2 / 32
       = 1 / 16
       = 0.0625                          [тобто 6.25%]
```

Для біт-пакованої матриці точка перетину настає вже при **6.25%** густини. Якщо граф має понад 6.25% можливих ребер, бітова матриця виявляється компактнішою за списки векторів.

### Точка перетину для зв'язаних списків на покажчиках

Порівняємо класичні списки на базі вузлів `Node*` проти байтової матриці:

```
|V|² = 8·|V| + 16·|E*|
16·|E*| = |V|² - 8·|V|
|E*| ≈ |V|² / 16
d*_list = 2 · (|V|² / 16) / |V|²
        = 1 / 8
        = 0.125                          [тобто 12.5%]
```

Зв'язані списки на покажчиках втрачають перевагу над байтовою матрицею вже при **12.5%** густини через 16-байтний оверхед на кожен вузол.

## Безмасштабні мережі та розподіл ступенів

У реальних мережах ступені вершин часто підпорядковуються степеневому закону розподілу Парето (Scale-Free Networks за моделлю Барабаші–Альберт):

```
P(k) ~ k^(-γ),  де 2 < γ < 3
```

Це означає, що абсолютна більшість вершин має одиничні зв'язки, але існують поодинокі вузли-хаби (наприклад, аеропорти-хаби або центральні сторінки пошукових систем), ступінь яких вимірюється тисячами чи мільйонами. 

Для таких систем матриця суміжності є катастрофічно неефективною, оскільки вимагає виділення однакових `|V|` комірок для кожного з мільйонів вузлів з одиничним ступенем. Формат CSR та списки суміжності адаптуються до безмасштабних розподілів автоматично, виділяючи кожній вершині рівно стільки пам'яті, скільки ребер вона має фактично.

## Зв'язок густини з теорією випадкових графів Ердеша–Реньї

У моделі випадкових графів `G(|V|, p)` Пала Ердеша та Альфреда Реньї кожне з можливих ребер з'являється з незалежною ймовірністю `p`, що еквівалентно очікуваній густині `E[d] = p`.

Фундаментальна теорема Ердеша–Реньї стверджує, що критичний поріг появи гігантської зв'язної компоненти (що охоплює майже всі вершини графа) становить:

```
p_conn = ln(|V|) / |V|
```

Для графа з `|V| = 1 000 000` вершин цей поріг становить:

```
p_conn = ln(10⁶) / 10⁶
       ≈ 13.8 / 1 000 000
       ≈ 0.0000138                       [0.00138%]
```

Це означає, що повноцінно зв'язний та функціональний граф утворюється при мікроскопічній густині `0.0014%`. Ця величина знаходиться на кілька порядків нижче точки ефективності матриці (`6.25%`), що математично пояснює абсолютне домінування спискових структур та CSR у практичних графових алгоритмах.
