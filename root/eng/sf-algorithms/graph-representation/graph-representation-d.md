# Представлення графів: матриця та списки суміжності

- [Масив](root:sf-algorithms/array) — неперервне розташування в оперативній пам'яті та адресація елементів за індексом.
- [Зв'язаний список](root:sf-algorithms/linked-list) — організація динамічних вузлів через вказівники та вартість послідовного перебору.

Сервер картографічної навігації обслуговує дорожню мережу мегаполіса: 200 000 перехресть і 600 000 сегментів доріг. Щосекунди система обробляє 5 000 000 запитів на перевірку прямого з'єднання між двома перехрестями та прокладання найкоротшого шляху. Якщо зберегти всі дороги у вигляді єдиного плоского масиву пар `(u, v)`, для перевірки кожного зв'язку доведеться сканувати весь масив, виконуючи до 600 000 порівнянь на один запит, що миттєво перевантажить процесор. Якщо натомість створити двовимірну таблицю розміром `200 000 × 200 000`, перевірка зв'язку виконуватиметься за одну операцію читання пам'яті, проте таблиця займе 40 гігабайтів оперативної пам'яті, з яких 99.997% комірок будуть порожніми нулями. Якщо ж виділити під кожне перехрестя динамічний зв'язаний список його вихідних доріг, пам'ять скоротиться до лічених мегабайтів, але обхід сусідів змусить процесор стрибати за вказівниками по випадкових адресах купи, зупиняючи конвеєр через промахи кеш-пам'яті.

Цей конфлікт між обсягом зайнятої пам'яті, швидкістю перевірки наявності зв'язку, вартістю перебору сусідів та ефективністю роботи з кешем центрального процесора є головною інженерною проблемою представлення дискретних топологій.

Математичний об'єкт, що описує такі системи, називається **графом** (від грец. *graphō* — писати, креслити). Він складається з множини вузлів — **вершин** (від лат. *vertex* — вершина, точка повороту), та множини зв'язків між ними — **ребер** (від англ. *edge*, лат. *arista* — край, ребро).

*Зіставлення чотирьох способів представлення одного й того самого орієнтованого графа: топологічна схема, таблиця матриці суміжності, масив списків сусідів та список ребер.*

## 1. Матриця суміжності: пряма адресація проти квадратичної пам'яті

Найпростіший спосіб зафіксувати зв'язки між `|V|` вершинами — це побудова квадратної таблиці розміром `|V| × |V|`. Якщо вершини пронумеровані цілими числами від `0` до `|V| - 1`, кожному вузлу-джерелу призначається власний рядок `u`, а кожному вузлу-призначенню — стовпчик `v`.

Значення на перетині рядка `u` та стовпчика `v` визначається двійковим правилом:

```
A[u][v] = 1,  якщо в графі існує орієнтоване ребро u → v
A[u][v] = 0,  якщо ребра u → v не існує
```

Ця таблиця називається **матрицею суміжності** (від лат. *matrix* — першоджерело, сітка, та *adjacentia* — прилягання, сусідство).

```
V = 4,  E = {(0,1), (0,2), (1,2), (2,0), (2,3)}

      v=0  v=1  v=2  v=3
u=0 [  0    1    1    0  ]
u=1 [  0    0    1    0  ]
u=2 [  1    0    0    1  ]
u=3 [  0    0    0    0  ]
```

### Властивості симетрії та ступенів вершин

Характер матриці безпосередньо відображає орієнтацію зв'язків:
1. **Неорієнтований граф**: Якщо зв'язок між `u` та `v` є взаємним, існування ребра означає одночасну наявність шляху з `u` в `v` та з `v` в `u`. Матриця стає строго симетричною відносно своєї головної діагоналі:
```
A[u][v] = A[v][u]  для всіх пар u, v
```
2. **Орієнтований граф**: Ребро має напрямок, тому симетрія втрачається (`A ≠ Aᵀ`). Рядок `u` містить усі **вихідні** ребра з вершини `u`, а стовпчик `v` містить усі **вхідні** ребра у вершину `v`.
3. **Ступені вершин**: Сума одиниць у рядку `u` дорівнює півстепеню виходу вершини `out_deg(u)`, а сума одиниць у стовпчику `v` — півстепеню входу `in_deg(v)`:
```
out_deg(u) = ∑ᵥ A[u][v]      [сума елементів рядка u]
in_deg(v)  = ∑ᵤ A[u][v]      [сума елементів стовпчика v]
```

Якщо граф не містить петель (ребер, що ведуть із вершини в саму себе), головна діагональ складається виключно з нулів: `A[i][i] = 0`.

Детальний аналіз алгебраїчних властивостей матриць суміжності, обчислення кількості шляхів через матричні степені та спектральну теорію викладено в статті [Матриця суміжності](root:sf-algorithms/adjacency-matrix).

### Фізична організація в оперативній пам'яті: Flat 1D Array проти масиву вказівників

У мовах низького рівня двовимірну матрицю можна виділити двома принципово різними способами:

1. **Вкладений масив покажчиків (`int**` або `std::vector<std::vector<bool>>`)**:
   Створюється масив із `|V|` покажчиків, кожен із яких адресує окремо виділений у купі блок пам'яті розміром `|V|`. Такий підхід створює `|V| + 1` незалежних алокацій. Рядки опиняються в довільних місцях адресної пам'яті, що руйнує просторову локальність: процесор не може передбачити наступну адресу і зазнає затримок під час читання (*pointer chasing*).

2. **Неперервний плоский буфер (Flat 1D Buffer)**:
   Матриця виділяється як один монолітний блок пам'яті розміром `|V|²` елементів. Перехід від двовимірних координат `(u, v)` до лінійного індексу виконується арифметично за формулою порядкового розташування рядків (*Row-Major Order*):
```
index(u, v) = u · |V| + v
```

Один суцільний блок пам'яті дозволяє апаратному префетчеру процесора завчасно підтягувати сусідні байти в L1/L2 кеш, забезпечуючи максимальну пропускну здатність шини пам'яті.

### Біт-пакування (Bitset Matrix) та SIMD-векторизація

Оскільки кожна комірка незваженої матриці суміжності приймає лише значення `0` або `1`, виділення цілого байта (`uint8_t`) чи 4-байтного цілого (`int32_t`) є надлишковим. 

Застосування бітового масиву дозволяє запакувати 64 комірки матриці в одне 64-бітне машинне слово `uint64_t`.

```
word_index = (u · |V| + v) / 64      [індекс 64-бітного слова]
bit_offset = (u · |V| + v) % 64      [позиція біта всередині слова]

A[u][v] = (buffer[word_index] >> bit_offset) & 1ULL
```

Бітове пакування скорочує обсяг пам'яті рівно у 8 разів порівняно з байтовою матрицею і в 32 рази порівняно з `int32_t`. 

Крім економії пам'яті, бітсет надає фундаментальну перевагу в теоретико-множинних операціях. Наприклад, щоб знайти спільних сусідів для двох вершин `u` та `w` (задача підрахунку трикутників або пошуку спільних друзів), у спискових структурах доводиться виконувати злиття двох масивів за час `O(deg(u) + deg(w))`. У бітовій матриці ця операція зводиться до побітового `AND` над відповідними рядками:

```
common_neighbors_mask[k] = row_u[k] & row_w[k]
count = popcount64(common_neighbors_mask[k])
```

Використовуючи векторні інструкції AVX-512 (інструкція `_mm512_and_si512` та `_mm512_popcnt_epi64`), сучасний процесор перевіряє спільних сусідів для 512 вершин за один машинний такт, що на щільних графах випереджає списки суміжності на два порядки.

## 2. Списки суміжності: компактність для розріджених систем

У переважній більшості реальних задач графи є вкрай далекими від повного заповнення. Якщо в соціальній мережі зареєстровано 100 000 000 користувачів, а середня кількість друзів у людини становить 200, то в матриці суміжності розміром `100M × 100M` на кожні 100 мільйонів комірок припадатиме лише 200 одиниць. Решта 99 999 800 комірок будуть нулями.

Для усунення цієї надлишковості застосовують **списки суміжності** (Adjacency Lists).

Замість фіксованої квадратної таблиці створюється масив розміром `|V|`, де кожен елемент із номером `u` містить динамічний контейнер (список або динамічний масив), у якому зберігаються виключно ідентифікатори тих вершин `v`, до яких веде ребро з `u`.

```
u=0: [ 1, 2 ]
u=1: [ 2 ]
u=2: [ 0, 3 ]
u=3: [ ]
```

### Часова та просторова складність

1. **Витрати пам'яті**:
   Кожна вершина потребує заголовка списку (вказівник або дескриптор динамічного масиву), а кожне ребро зберігається рівно один раз (в орієнтованому графі) або двічі (у неорієнтованому). Сумарний обсяг пам'яті становить:
```
Memory = Θ(|V| + |E|)
```
   Якщо граф розріджений (`|E| = O(|V|)`), пам'ять росте лінійно від кількості вузлів, а не квадратично.

2. **Ітерація по сусідах вершини `u`**:
   Щоб перебрати всіх сусідів вершини `u`, алгоритму потрібно прочитати рівно `deg(u)` елементів із контейнера `u`. Час роботи становить `Θ(deg(u))`. У матриці суміжності для цього завжди доводиться сканувати весь рядок довжиною `|V|`, що коштує `Θ(|V|)`.

3. **Перевірка існування ребра `(u, v)`**:
   Щоб перевірити, чи зв'язані `u` та `v`, необхідно знайти значення `v` у контейнері вершини `u`. Якщо сусіди зберігаються в несортованому масиві або зв'язаному списку, це вимагає лінійного пошуку за `O(deg(u))`.

### Варіанти реалізації контейнерів сусідів

Внутрішня структура контейнера списку суміжності визначає швидкодію конкретних операцій:

* **Зв'язаний список (`std::forward_list` або структури на вказівниках `Node*`)**:
  Дозволяє додавати нове ребро за `O(1)` без релокацій пам'яті, проте кожен вузол списку містить 8 байтів оверхеду на вказівник `next`, а вузли розкидані по всій оперативній пам'яті, викликаючи промахи кешу під час кожного обходу.
* **Динамічний масив (`std::vector<uint32_t>`)**:
  Сусіди однієї вершини розміщені в суцільному блоці пам'яті. Це суттєво прискорює ітерацію завдяки кешу процесора, але додавання елементів може викликати переалокацію.
* **Хеш-таблиця (`std::unordered_set<uint32_t>`)**:
  Забезпечує перевірку наявності ребра `(u, v)` та його видалення за середній час `O(1)`, проте споживає значно більше пам'яті на кожен зв'язок і має високий оверхед на обчислення хеш-функції.

## 3. Compressed Sparse Row (CSR): максимальна кеш-локальність

Хоча списки суміжності на базі `std::vector<std::vector<uint32_t>>` є стандартним інструментом у навчальних курсах, у промислових графових базах даних та високонавантажених рушіях обробки вони демонструють суттєві недоліки:
1. **Оверхед контейнерів**: Кожен `std::vector` у 64-бітній системі займає 24 байти службових даних (три покажчики `begin`, `end`, `capacity`). Для графа з 10 000 000 вершин лише самі порожні дескриптори векторів заберуть 240 мегабайтів RAM.
2. **Фрагментація купи**: Виділення 10 мільйонів дрібних блоків пам'яті перевантажує системний алокатор і фрагментує адресний простір.
3. **Непряма адресація (Pointer Chasing)**: Щоб дістатися до сусідів вершини `u`, процесор спочатку читає адресу буфера з головного масиву, чекає завантаження даних із RAM, і лише потім починає читати список.

Для усунення цих вад у статичних та рідко змінюваних графах застосовують формат **Compressed Sparse Row (CSR)**, який в алгоритмах на графах також називають **прямою зіркою** (Forward Star).

![Внутрішня організація масивів у форматі Compressed Sparse Row](/root/eng/sf-algorithms/graph-representation/img/csr-layout.svg)
*Формат CSR упаковує всі зв'язки графа у два суцільні масиви: offsets задає початкові зміщення для кожної вершини, а edges містить щільно склеєні списки сусідів.*

CSR повністю відмовляється від внутрішніх об'єктів-контейнерів і зберігає граф у вигляді двох неперервних пласких масивів:

1. **Масив ребер `edges` (розмір `|E|`)**:
   Містить ідентифікатори кінцевих вершин для всіх ребер графа. Списки сусідів усіх вершин склеєні в один монолітний вектор без проміжків і розділювачів.
2. **Масив зміщень `offsets` (розмір `|V| + 1`)**:
   Для кожної вершини `u` значення `offsets[u]` вказує на індекс у масиві `edges`, з якого починається список її сусідів. Значення `offsets[u + 1]` вказує на позицію, де цей список закінчується.

### Інваріанти структури CSR

Для будь-якої вершини `u`:
* Сусіди вершини `u` розміщені в суцільному діапазоні від індексу `offsets[u]` (включно) до `offsets[u + 1]` (не включно):
```
neighbors(u) = edges[ offsets[u] .. offsets[u + 1] - 1 ]
```
* Півстепінь виходу вершини `u` обчислюється як різниця двох сусідніх елементів масиву зміщень за `O(1)`:
```
out_deg(u) = offsets[u + 1] - offsets[u]
```
* Останній елемент `offsets[|V|]` завжди дорівнює загальній кількості ребер `|E|`.

Якщо вершина `u` є ізольованою і не має вихідних ребер, то `offsets[u] == offsets[u + 1]`. Довжина діапазону дорівнює 0, і алгоритм обходу автоматично пропускає її без додаткових гілкувань `if`.

### Дзеркальний формат: Compressed Sparse Column (CSC)

Якщо CSR оптимізований для швидкого перебору **вихідних** ребер вершини `u` (out-edges), то його точна дзеркальна копія — **Compressed Sparse Column (CSC)** — оптимізована для швидкого перебору **вхідних** ребер (in-edges).

У форматі CSC масив ребер зберігає вершини-джерела, а масив зміщень структурує стовпчики матриці. Високоефективні алгоритми ранжування (наприклад, PageRank або пошук сильно зв'язних компонент алгоритмом Косараджу) одночасно тримають у пам'яті як прямий CSR, так і транспонований CSC, що дозволяє миттєво рухатися по графу як у прямому, так і в зворотному напрямку без додаткових накладних витрат.

![Порівняння патернів звернення до оперативної та кеш-пам'яті процесора під час обходу графа](/root/eng/sf-algorithms/graph-representation/img/cache-traversal-patterns.svg)
*Поведінка кеш-пам'яті CPU: зв'язані списки спричиняють промахи через випадкові адреси, матриця витрачає кеш на читання непотрібних нулів, тоді як CSR передає дані суцільним потоком.*

### Апаратна механіка: чому процесор віддає перевагу CSR

Сучасна ієрархія пам'яті будується на суттєвій асиметрії затримок доступу:
* Регістри процесора: `~0.5 нс` (0 тактів);
* Кеш-пам'ять L1: `~1 нс` (4–5 тактів);
* Кеш-пам'ять L2: `~3–4 нс` (12–14 тактів);
* Кеш-пам'ять L3: `~12–15 нс` (40–60 тактів);
* Оперативна пам'ять DRAM: `~60–100 нс` (200–300 тактів).

Коли алгоритм обходить зв'язаний список `Node*`, кожен крок за покажчиком `curr = curr->next` з імовірністю понад 40% спричиняє промах у кешах L1/L2/L3. Процесор змушений повністю зупиняти конвеєр виконання інструкцій (*pipeline stall*) на сотні тактів в очікуванні відповіді від контролера пам'яті DRAM.

У форматі CSR дані масиву `edges` розташовані суцільним шматком. Центральний процесор активує апаратний блок попередньої вибірки (*Hardware Stream Prefetcher*). Щойно алгоритм починає читати початок списку сусідів, префетчер у фоновому режимі паралельно завантажує наступні 64-байтні лінії кешу. Коли інструкції процесора доходять до наступних сусідів, вони вже гарантовано знаходяться в надшвидкому кеші L1, забезпечуючи максимальну пропускну здатність алгоритмів обходу.

Повний код побудови CSR, алгоритми прямої конвертації та бенчмарки наведено у вставці [Реалізація та конвертація графових структур: від матриць до CSR](root:sf-algorithms/graph-representation/proj-csr-graph.md).

## 4. Список ребер (Edge List) та матриця інцидентності

Окрім матриці та списків суміжності, в інженерній практиці застосовують ще дві структури:

### Список ребер (Edge List)

Список ребер зберігає топологію як простий неструктурований масив кортежів або структур `(u, v, w)`, де кожний запис описує окреме ребро, його напрямок та вагу.

:::tabs
```c
typedef struct {
    uint32_t src;
    uint32_t dst;
    double weight;
} Edge;

/* Статичний або динамічний масив ребер */
Edge edge_list[NUM_EDGES];
```
```cpp
#include <cstdint>
#include <vector>
#include <compare>

struct Edge {
    uint32_t src;
    uint32_t dst;
    double weight;

    auto operator<=>(const Edge&) const = default;
};

std::vector<Edge> edge_list;
```
:::

* **Пам'ять**: `Θ(|E|)` — абсолютний мінімум, оскільки не вимагає навіть масиву вершин.
* **Перевірка зв'язку та пошук сусідів**: `Θ(|E|)` — потребує повного лінійного сканування всього масиву.
* **Сфера застосування**:
  1. Алгоритм Краскала для пошуку мінімального кістякового дерева ([Алгоритм Краскала](root:sf-algorithms/kruskal-algorithm)), де ребра необхідно відсортувати за вагою один раз на початку роботи.
  2. Формати зберігання та передачі графів на диск (файли `.csv`, `.edgelist`, формат Matrix Market).
  3. Потокова обробка ребер у моделях розрахунків на GPU або фреймворках масивного паралелізму.

### Матриця інцидентності (Incidence Matrix)

Матриця **інцидентності** (від лат. *incidentia* — потрапляння, зв'язок між різнорідними об'єктами) відображає зв'язок між вершинами та ребрами. Це прямокутна таблиця розміром `|V| × |E|`, де рядки відповідають вершинам, а стовпчики — ребрам.

Для орієнтованого графа без самопетель стовпчик ребра `e = (u, v)` заповнюється за правилом:
* `-1` у рядку вершини-джерела `u` (вихід ребра);
* `+1` у рядку вершини-призначення `v` (вхід ребра);
* `0` для всіх інших вершин, які не мають стосунку до цього ребра.

```
Ребра: e0 = (0→1),  e1 = (0→2),  e2 = (1→2),  e3 = (2→0),  e4 = (2→3)

        e0   e1   e2   e3   e4
v=0 [  -1   -1    0   +1    0  ]
v=1 [  +1    0   -1    0    0  ]
v=2 [   0   +1   +1   -1   -1  ]
v=3 [   0    0    0    0   +1  ]
```

Матриця інцидентності займає `Θ(|V| · |E|)` пам'яті й практично не використовується в стандартних алгоритмах пошуку шляхів. Проте вона має фундаментальне значення в електротехніці (розрахунок електричних кіл за законами Кірхгофа) та дискретній оптимізації, оскільки матриця Лапласа графа `L` обчислюється через матрицю інцидентності `M` як:

```
L = M · Mᵀ
```

де `L = D - A` (`D` — діагональна матриця ступенів, `A` — матриця суміжності).

## 5. Алгебра густини: знаходження критичної точки переходу

Вибір оптимального представлення визначається показником **густини** (від англ. *density*, лат. *densitas* — щільність).

Густина неорієнтованого графа показує частку існуючих ребер від максимально можливої кількості:

```
d = 2 · |E| / (|V| · (|V| - 1))
```

![Залежність споживання оперативної пам'яті різними структурами від кількості ребер](/root/eng/sf-algorithms/graph-representation/img/density-space-tradeoff.svg)
*Графік зміни витрат пам'яті: для розріджених графів списки суміжності та CSR перемагають із колосальним відривом, але при густині понад 5-15% бітова матриця стає компактнішою.*

Зіставимо витрати пам'яті в байтах для графа з `|V|` вершинами та `|E|` ребрами на 64-бітній платформі:

```
Байтова матриця:       S_byte = |V|² байтів
Бітова матриця:        S_bit  ≈ |V|² / 8 байтів
Векторні списки:       S_vec  = 24·|V| + 4·|E| байтів  (std::vector<uint32_t>)
CSR (Compact Array):   S_csr  = 4·(|V| + 1) + 4·|E| байтів
```

Знайдемо точку перетину, де бітова матриця починає займати менше пам'яті, ніж векторні списки суміжності:

```
|V|² / 8 = 24·|V| + 4·|E*|              [рівняння рівності пам'яті]
4·|E*| = |V|² / 8 - 24·|V|              [виражаємо кількість ребер]
|E*| ≈ |V|² / 32                        [для великих |V| нехтуємо лінійним членом]

d* = 2 · |E*| / |V|²
   = 2 · (|V|² / 32) / |V|²
   = 1 / 16
   = 0.0625                             [критична густина 6.25%]
```

Якщо граф має менше ніж **6.25%** ребер від повного графа, списки суміжності виграють за пам'яттю. Якщо ж граф щільніший за 6.25%, бітова матриця стає компактнішою і водночас надає миттєвий доступ `O(1)` до перевірки ребер.

Повний математичний апарат, розрахунки з урахуванням вирівнювання структур та аналіз поведінки для 32-бітних і 64-бітних архітектур наведено у вставці [Алгебраїчний аналіз густини графів та точки перетину пам'яті](root:sf-algorithms/graph-representation/math-graph-density.md).

Історичну хроніку того, як ці формати розвивалися від перших робіт Ейлера до стандартів GraphBLAS, описано у вставці [Еволюція структур даних для представлення графів](root:sf-algorithms/graph-representation/hist-graph-representation.md).

## 6. Зважені графи та сентинельні значення

У більшості прикладних задач ребра мають числові ваги: пропускна здатність каналу зв'язку, довжина дороги в метрах або вартість авіаперельоту. Такий граф називається **зваженим**.

Збереження ваг модифікує структури даних:

1. **Матриця суміжності**:
   Комірка `A[u][v]` містить не біт, а число з плаваючою комою або ціле число (`double` або `int32_t`).
   * **Проблема відсутності ребра**: Якщо вага ребра може дорівнювати `0.0` (наприклад, безкоштовна пересадка в метро), нуль не можна використовувати як ознаку відсутності зв'язку.
   * **Сентинели (Sentinels)**: Для алгоритмів пошуку найкоротших шляхів ([Алгоритм Дейкстри](root:sf-algorithms/dijkstra)) відсутність ребра позначають позитивною нескінченністю `+∞` (`INFINITY` або `std::numeric_limits<double>::infinity()`). Діагональні елементи `A[u][u]` заповнюють нулями `0.0`. Для задач максимального потоку відсутнє ребро позначають нульовою пропускною здатністю `0.0`.

2. **Списки суміжності та CSR**:
   Замість простого номера вершини зберігається пара `(neighbor_id, weight)`. У форматі CSR додається третій паралельний масив `weights` розміром `|E|`, який зберігає ваги ребер за тими самими індексами, що й масив `edges`.

```
offsets: [ 0,  2,  3,  5,  5 ]
edges:   [ 1,   2,   2,   0,   3 ]
weights: [ 4.5, 2.1, 8.0, 1.2, 0.7 ]
```

## 7. Моделі обчислень: Vertex-Centric проти Edge-Centric

Вибір внутрішньої структури даних безпосередньо диктує парадигму обробки великих графів у розподілених системах (наприклад, Apache Spark GraphX або Google Pregel):

1. **Вершинно-центрована модель (Vertex-Centric / Think Like a Vertex)**:
   Кожна вершина розглядається як автономний обчислювальний агент, який отримує повідомлення від сусідів, змінює свій локальний стан та відправляє нові повідомлення по вихідних ребрах. Ця модель спирається на формат CSR або списки суміжності, оскільки вимагає швидкого доступу до вихідних сусідів конкретного вузла.

2. **Реберно-центрована модель (Edge-Centric / GraphChi)**:
   Алгоритм не завантажує граф у пам'ять повністю, а виконує потокове потокове читання масиву ребер (Edge List) безпосередньо з диска чи пам'яті NVMe. Це дозволяє обробляти графи з сотнями мільярдів ребер на звичайному сервері без гігабайтів оперативної пам'яті, хоча час виконання однієї ітерації збільшується.

## 8. Порівняльна таблиця та критерії інженерного вибору

У зведеній таблиці зіставлено ключові операції для всіх основних структур даних:

| Критерій / Операція | Матриця суміжності | Списки векторів | Формат CSR | Список ребер |
|---|---|---|---|---|
| **Витрати пам'яті** | `Θ(V²)` | `Θ(V + E)` | `Θ(V + E)` (найменша) | `Θ(E)` |
| **Перевірка ребра `(u, v)`** | `O(1)` | `O(deg(u))` | `O(log(deg(u)))`* | `O(E)` |
| **Перебір сусідів вершини `u`** | `Θ(V)` | `Θ(deg(u))` | `Θ(deg(u))` (кеш-стрім) | `Θ(E)` |
| **Додавання нового ребра** | `O(1)` | `O(1)` аморт. | `O(E)` (перебудова) | `O(1)` |
| **Видалення ребра** | `O(1)` | `O(deg(u))` | `O(E)` (перебудова) | `O(E)` |
| **Видалення вершини** | `Θ(V²)` | `Θ(V + E)` | `O(V + E)` | `O(E)` |
| **Промахи кешу під час обходу** | Середні (нулі) | Високі (фрагментація) | Мінімальні (100% локальність) | Низькі (послідовно) |

*\* За умови, що сусіди всередині зрізу CSR відсортовані за індексами.*

> 🔧 **Навіщо це.**
> * **Обирай матрицю суміжності**, якщо: кількість вершин невелика (`|V| ≤ 5000`), граф є щільним (`d > 15%`), алгоритм вимагає частої перевірки зв'язку між довільними парами вершин за `O(1)`, або алгоритм спирається на множення матриць (наприклад, пошук транзитивного замикання алгоритмом Флойда–Уоршелла).
> * **Обирай списки суміжності (`std::vector<std::vector>`)**, якщо: граф розріджений (`d ≪ 1%`), структура графа динамічно змінюється під час роботи програми (ребра додаються та видаляються на льоту), а основна операція — це обхід у ширину чи глибину (BFS/DFS).
> * **Обирай CSR (Compressed Sparse Row)**, якщо: граф є статичним або змінюється рідко (завантажується з диска чи бази даних), містить мільйони вузлів, обробляється в багатопотоковому режимі або на GPU, де критично важливо уникнути фрагментації пам'яті та промахів кешу.
> * **Обирай список ребер**, якщо: основна задача полягає в сортуванні ребер за вагами (алгоритм Краскала), потоковій фільтрації або збереженні графа у файл.

Специфікацію контракту абстрактного типу даних графа, вимоги C++20 Concepts та інтерфейси для мови C детально розглянуто у вставці [Інтерфейс та контракт абстрактного типу даних «Граф»](root:sf-algorithms/graph-representation/api-graph-traits.md).

## 9. Практичний приклад: обхід у ширину (BFS) на матриці та списках

Розглянемо повну реалізацію алгоритму пошуку в ширину ([Пошук у ширину (BFS)](root:sf-algorithms/breadth-first-search)) для матриці суміжності та списків суміжності мовами C та C++.

Зверни увагу на ключову різницю в циклі сканування сусідів: у матриці цикл завжди робить `|V|` ітерацій, тоді як у списках суміжності — рівно `deg(u)` ітерацій.

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

/* Проста черга FIFO для цілих чисел */
typedef struct {
    uint32_t *data;
    size_t head;
    size_t tail;
    size_t capacity;
} Queue;

Queue* queue_create(size_t capacity) {
    Queue *q = (Queue*)malloc(sizeof(Queue));
    q->data = (uint32_t*)malloc(capacity * sizeof(uint32_t));
    q->head = 0;
    q->tail = 0;
    q->capacity = capacity;
    return q;
}

void queue_push(Queue *q, uint32_t val) {
    q->data[q->tail++] = val;
}

uint32_t queue_pop(Queue *q) {
    return q->data[q->head++];
}

bool queue_is_empty(const Queue *q) {
    return q->head == q->tail;
}

void queue_free(Queue *q) {
    free(q->data);
    free(q);
}

/* 1. Пошук у ширину (BFS) на матриці суміжності: час O(V²) */
void bfs_matrix(const uint8_t *matrix, uint32_t num_vertices, uint32_t start_node) {
    bool *visited = (bool*)calloc(num_vertices, sizeof(bool));
    Queue *q = queue_create(num_vertices);

    visited[start_node] = true;
    queue_push(q, start_node);

    while (!queue_is_empty(q)) {
        uint32_t u = queue_pop(q);

        /* Скануємо весь рядок матриці довжиною num_vertices */
        for (uint32_t v = 0; v < num_vertices; ++v) {
            if (matrix[u * num_vertices + v] && !visited[v]) {
                visited[v] = true;
                queue_push(q, v);
            }
        }
    }

    queue_free(q);
    free(visited);
}

/* 2. Пошук у ширину (BFS) на списках суміжності: час O(V + E) */
typedef struct {
    uint32_t *neighbors;
    size_t count;
} AdjList;

void bfs_adj_list(const AdjList *adj, uint32_t num_vertices, uint32_t start_node) {
    bool *visited = (bool*)calloc(num_vertices, sizeof(bool));
    Queue *q = queue_create(num_vertices);

    visited[start_node] = true;
    queue_push(q, start_node);

    while (!queue_is_empty(q)) {
        uint32_t u = queue_pop(q);

        /* Скануємо лише реальних сусідів вершини u */
        const AdjList *list = &adj[u];
        for (size_t i = 0; i < list->count; ++i) {
            uint32_t v = list->neighbors[i];
            if (!visited[v]) {
                visited[v] = true;
                queue_push(q, v);
            }
        }
    }

    queue_free(q);
    free(visited);
}
```
```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <span>
#include <cstdint>

/* 1. Пошук у ширину (BFS) на матриці суміжності: складність O(V²) */
class MatrixGraph {
public:
    explicit MatrixGraph(uint32_t num_vertices)
        : num_vertices_(num_vertices), matrix_(static_cast<size_t>(num_vertices) * num_vertices, 0) {}

    void add_edge(uint32_t u, uint32_t v) {
        if (u < num_vertices_ && v < num_vertices_) {
            matrix_[static_cast<size_t>(u) * num_vertices_ + v] = 1;
        }
    }

    void bfs(uint32_t start_node) const {
        if (start_node >= num_vertices_) return;

        std::vector<bool> visited(num_vertices_, false);
        std::queue<uint32_t> q;

        visited[start_node] = true;
        q.push(start_node);

        while (!q.empty()) {
            uint32_t u = q.front();
            q.pop();

            // Сканування всього рядка довжиною V
            size_t row_offset = static_cast<size_t>(u) * num_vertices_;
            for (uint32_t v = 0; v < num_vertices_; ++v) {
                if (matrix_[row_offset + v] && !visited[v]) {
                    visited[v] = true;
                    q.push(v);
                }
            }
        }
    }

private:
    uint32_t num_vertices_;
    std::vector<uint8_t> matrix_;
};

/* 2. Пошук у ширину (BFS) на списках суміжності: складність O(V + E) */
class ListGraph {
public:
    explicit ListGraph(uint32_t num_vertices)
        : adj_(num_vertices) {}

    void add_edge(uint32_t u, uint32_t v) {
        if (u < adj_.size()) {
            adj_[u].push_back(v);
        }
    }

    void bfs(uint32_t start_node) const {
        if (start_node >= adj_.size()) return;

        std::vector<bool> visited(adj_.size(), false);
        std::queue<uint32_t> q;

        visited[start_node] = true;
        q.push(start_node);

        while (!q.empty()) {
            uint32_t u = q.front();
            q.pop();

            // Сканування лише існуючих сусідів (deg(u))
            for (uint32_t v : adj_[u]) {
                if (!visited[v]) {
                    visited[v] = true;
                    q.push(v);
                }
            }
        }
    }

private:
    std::vector<std::vector<uint32_t>> adj_;
};
```

Вибір представлення графа — це не суто теоретична класифікація, а компроміс між моделлю пам'яті та патерном доступу до процесорного кешу. Розуміння структури вхідних даних (густини `d`, статичності чи динамічності топології) дозволяє досягти оптимальної швидкодії та мінімального споживання оперативної пам'яті в реальних інженерних системах.
