# 🧮 Доведення лінійної складності побудови купи (алгоритм Флойда)

Інтуїтивне уявлення про побудову структури даних із `N` елементів, де кожен крок спирається на операцію складності `O(log N)`, схиляє до припущення, що загальний час ініціалізації масиву не може бути меншим за `O(N log N)`. Саме таку оцінку дає наївний метод послідовного додавання елементів через `sift-up` (алгоритм Вільямса).

Проте алгоритм побудови купи знизу-вгору Роберта Флойда (Bottom-Up Heapify) виконує операцію за строго лінійний час `O(N)`. Нижче наведено математичне доведення цього факту через аналіз геометрії двійкового дерева, обчислення суми геометрично-степеневого ряду, теоретико-інформаційну нижню оцінку кількості порівнянь та узагальнення для `d`-арних дерев.

## Геометрія двійкового дерева: висота проти глибини

Розглянемо майже повне двійкове дерево, що містить `N` вузлів. Для кожного вузла визначимо дві взаємопов'язані характеристики:
1. **Глибина вузла (depth)**: відстань від кореня дерева до даного вузла (вимірюється кількістю ребер). Корінь має глибину `0`, його діти — глибину `1`, а найнижчий ярус — глибину `⌊log_2(N)⌋`.
2. **Висота вузла (height, `h`)**: максимальна відстань від даного вузла вниз до найвіддаленішого листка в його піддереві. Усі листки мають висоту `h = 0`, їхні батьки — висоту `h = 1`, а корінь дерева — висоту `h = ⌊log_2(N)⌋`.

Ключова відмінність між алгоритмами Вільямса та Флойда полягає у напрямку переміщення та залежності вартості операції:
- **У Вільямса (Top-Down push)**: вартість операції підйому `sift-up` пропорційна **глибині** вузла. Вузли нижніх ярусів (яких у дереві переважна більшість) змушені долати максимальний шлях до самого кореня.
- **У Флойда (Bottom-Up heapify)**: вартість операції спуску `sift-down` пропорційна **висоті** `h` вузла. Вузли нижніх ярусів спускаються на мінімальну відстань (листки на `0` кроків, вузли на ярус вище — максимум на `1` крок).

## Чому наївна побудова через Top-Down коштує `Θ(N log N)`

Під час послідовного додавання елементів до порожньої купи `arr[k]` додається на глибину `⌊log_2(k)⌋`. Для відновлення властивості купи викликається функція `sift-up`, яка в найгіршому випадку виконує `⌊log_2(k)⌋` обмінів із предками.

Сумарна кількість операцій обміну для масиву з `N` елементів обчислюється як сума логарифмів:

```
T_Williams(N) = ∑_{k=1}^N ⌊log_2(k)⌋
```

Застосовуючи формулу Стірлінга для факторіала `N! = 1 · 2 · ... · N`:

```
∑_{k=1}^N log_2(k) = log_2(N!) = N log_2(N) - N / ln(2) + O(log N) = Θ(N log N)
```

Оскільки більше ніж `N / 2` елементів розташовані на глибині не менше ніж `log_2(N) - 1`, більше половини всіх елементів виконують повноцінний логарифмічний підйом. Уникнути цієї роботи при русі зверху-вниз неможливо, оскільки кожна нова вершина потрапляє у самий низ дерева.

## Кількість вузлів на фіксованій висоті в алгоритмі Флойда

У повному двійковому дереві висоти `H = ⌊log_2(N)⌋` загальна кількість вузлів на різних рівнях розподілена за спадним експоненційним законом:
- На висоті `h = 0` (листки) розташовано не менше ніж `⌈N / 2⌉` вузлів (приблизно 50% всього масиву);
- На висоті `h = 1` розташовано не більше ніж `⌈N / 4⌉` вузлів (приблизно 25% масиву);
- На висоті `h = 2` розташовано не більше ніж `⌈N / 8⌉` вузлів (приблизно 12.5% масиву);
- У загальному випадку, на висоті `h` кількість вузлів `n(h)` обмежена зверху величиною:

```
n(h) ≤ ⌈N / 2^(h + 1)⌉
```

## Формулювання суми загальної праці

Оскільки операція `sift-down` для вузла висоти `h` виконує не більше ніж `h` кроків обміну (кожен крок вимагає не більше `2` порівнянь для вибору меншої дитини та порівняння з батьком), загальна кількість операцій обміну `S(N)` для всіх вузлів дерева записується як сума добутків кількості вузлів на їхню висоту:

```
S(N) = ∑_{h=0}^{⌊log_2(N)⌋} n(h) · h
     ≤ ∑_{h=0}^{⌊log_2(N)⌋} ⌈N / 2^(h + 1)⌉ · h
     ≤ (N / 2) · ∑_{h=0}^{∞} (h / 2^h)
```

Щоб довести лінійність `S(N) ≤ O(N)`, необхідно знайти точне значення нескінченної суми:

```
G = ∑_{h=0}^{∞} (h / 2^h) = 0/1 + 1/2 + 2/4 + 3/8 + 4/16 + 5/32 + ...
```

## Алгебраїчне обчислення суми ряду

Застосуємо класичний метод дискретного зсуву для геометрично-степеневого ряду.

Запишемо суму `G` у розгорнутому вигляді:

```
G = 0 + 1/2 + 2/4 + 3/8 + 4/16 + 5/32 + ... + h/2^h + ...
```

Помножимо обидві частини рівності на `1/2`:

```
(1/2) · G = 0 + 0 + 1/4 + 2/8 + 3/16 + 4/32 + ... + (h - 1)/2^h + ...
```

Віднімемо рівність `(1/2) · G` від початкової рівності `G`:

```
G - (1/2) · G = (0 - 0) + (1/2 - 0) + (2/4 - 1/4) + (3/8 - 2/8) + (4/16 - 3/16) + ...
```

Кожен різницевий коефіцієнт при знаменнику `2^h` стає строго рівним `h - (h - 1) = 1`. Отримуємо:

```
(1/2) · G = 1/2 + 1/4 + 1/8 + 1/16 + 1/32 + ... + 1/2^h + ...
```

Права частина є нескінченною спадною геометричною прогресією з першим членом `a = 1/2` та знаменником `q = 1/2`.

За формулою суми нескінченної геометричної прогресії `Sum = a / (1 - q)`:

```
(1/2) · G = (1/2) / (1 - 1/2)
(1/2) · G = (1/2) / (1/2)
(1/2) · G = 1
```

Помноживши обидві частини на `2`, отримуємо остаточне значення суми:

```
G = 2
```

## Альтернативне доведення через диференціювання степеневого ряду

Для математичної повноти перевіримо результат за допомогою апарату математичного аналізу та похідних степеневих рядів.

Розглянемо суму стандартного геометричного ряду для `|x| < 1`:

```
f(x) = ∑_{h=0}^{∞} x^h = 1 / (1 - x)
```

Продиференціюємо обидві частини рівності за змінною `x`:

```
f'(x) = d/dx [ ∑_{h=0}^{∞} x^h ] = ∑_{h=1}^{∞} h · x^(h - 1)
```

З іншого боку, похідна дробу `1 / (1 - x)` дорівнює:

```
d/dx [ (1 - x)^(-1) ] = 1 / (1 - x)^2
```

Прирівняємо отримані вирази:

```
∑_{h=1}^{∞} h · x^(h - 1) = 1 / (1 - x)^2
```

Помножимо обидві частини рівності на `x`:

```
∑_{h=0}^{∞} h · x^h = x / (1 - x)^2
```

Підставимо значення `x = 1/2`:

```
G = ∑_{h=0}^{∞} (h / 2^h)
  = (1/2) / (1 - 1/2)^2      [підставляємо x = 1/2]
  = (1/2) / (1/4)            [обчислюємо квадрат знаменника (1/2)^2 = 1/4]
  = 2                        [ділимо дріб на дріб: (1/2) · 4 = 2]
```

Обидва методи дають однаковий результат `G = 2`.

## Підсумок складності: верхня та нижня межі порівнянь

Повернемося до вихідної оцінки кількості операцій обміну `S(N)`:

```
S(N) ≤ (N / 2) · G
S(N) ≤ (N / 2) · 2
S(N) ≤ N
```

Загальна кількість порівнянь `C(N)` під час побудови купи:
Кожен крок `sift-down` для вузла з двома дітьми вимагає двох порівнянь: одне між лівою та правою дитиною для пошуку меншої, друге — між меншою дитиною та поточним елементом. Отже:

```
C(N) ≤ 2 · S(N) ≤ 2N
```

### Теоретико-інформаційна нижня межа
Чи можливо побудувати двійкову купу менш ніж за `O(N)` порівнянь? Кількість різних валідних куп, які можна скласти з `N` унікальних елементів, дорівнює:

```
Heap(N) = N! / ∏_{v} s(v)
```

де `s(v)` — розмір піддерева з коренем у вузлі `v`. Логарифмування показує, що для формування структури часткового порядку необхідно розрізнити як мінімум `2^(c · N)` станів, що дає теоретичну нижню межу `C(N) ≥ 1.36 N` порівнянь.

### Середній випадок за Доберакатом (1984)
У фундаментальній праці Ернста-Евальда Добераката (Ernst-Ewald Doberkat, 1984) було доведено, що для випадкового рівномірного розподілу вхідних перестановок елемент, який просіюється вниз, зупиняється значно раніше за найглибший листок. Математичне сподівання кількості порівнянь для алгоритму Флойда становить:

```
E[C(N)] ≈ 1.88 N + O(log N)
```

Це свідчить про те, що алгоритм Флойда є практично оптимальним як у найгіршому (`≤ 2N`), так і в середньому (`≈ 1.88N`) випадках.

## Узагальнення для `d`-арних куп

Розглянемо `d`-арну купу, де кожен вузол має до `d` нащадків. Висота дерева зменшується до `log_d(N)`, а кількість вузлів на висоті `h` дорівнює `N / d^(h+1)`.

Сума для `d`-арного алгоритму Флойда зводиться до ряду:

```
G_d = ∑_{h=0}^{∞} (h / d^h) = d / (d - 1)^2
```

Для різних значень `d`:
- При `d = 2`: `G_2 = 2 / (2 - 1)^2 = 2`
- При `d = 3`: `G_3 = 3 / (3 - 1)^2 = 3/4 = 0.75`
- При `d = 4`: `G_4 = 4 / (4 - 1)^2 = 4/9 ≈ 0.444`

Хоча кількість обмінів із ростом `d` спадає, кожен крок вимагає `d - 1` порівнянь між дітьми для знаходження мінімуму. Загальна кількість порівнянь становить:

```
C_d(N) ≤ (d - 1 + 1) · (N / d) · (d / (d - 1)^2) = (d / (d - 1)) · N
```

При `d = 4` кількість порівнянь `C_4(N) ≤ (4/3) N ≈ 1.33 N`, що робить 4-арні купи швидшими за двійкові на стадії ініціалізації масиву.
