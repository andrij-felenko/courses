# 📋 Інтерфейс бібліотеки нечіткого пошуку на префіксному дереві

Бібліотека fuzzy_matcher надає інтерфейс для швидкого нечіткого пошуку та автодоповнення слів за словниками великого обсягу на основі префіксного дерева Trie та векторного динамічного програмування метрики Левенштейна.

## Архітектура та життєвий цикл індексу

Пряме порівняння пошукового запиту з кожним записом у словнику на півмільйона слів призводить до сотень тисяч незалежних викликів матричного алгоритму, що неприпустимо для інтерактивних інтерфейсів із лімітом відповіді у кілька мілісекунд. Бібліотека структурує словникову базу у вигляді компактного префіксного дерева.

При обході дерева кожен вузол успадковує вектор динамічного програмування від батьківського вузла та обчислює рівно один новий рядок значень для свого символу. Якщо мінімальне значення в обчисленому векторі перевищує встановлений поріг максимальної відстані k, усе піддерево відсікається від подальшого розгляду. Це дозволяє скоротити час пошуку за гігантськими базами назв до часток мілісекунди.

Життєвий цикл роботи з бібліотекою складається з чотирьох послідовних етапів:
1. **Ініціалізація індексу:** Створення порожнього кореневого вузла дерева через виклик конструктора або функції створення. Кореневий вузол ініціалізується порожнім набором переходів та базовим вектором ініціалізації.
2. **Наповнення словника:** Послідовне додавання слів та асоційованих користувацьких даних (ідентифікаторів записів, числових ключів або покажчиків на структури). Під час додавання нових слів дерево автоматично розширює свої вузли та маркує термінальні вершини.
3. **Виконання пошукових запитів:** Багаторазове виконання нечітких запитів із заданими параметрами фільтрації та обмеження відстані. Пошуковий алгоритм рекурсивно обходить дерево в глибину, передаючи вектор поточних станів.
4. **Звільнення ресурсів:** Повне рекурсивне очищення виділеної пам'яті дерева після завершення роботи сервісу за принципом RAII або через явний виклик функції деструктора.

Внутрішня організація вузла дерева містить масив покажчиків на дочірні вершини, прапорець завершення слова та поле користувацьких даних. Для компактного зберігання розріджених вузлів алфавіту застосовуються динамічні списки переходів або бітові маски наявності дочірніх символів.

## Алгоритм обходу префіксного дерева з вектором динамічного програмування

Рекурсивний обхід дерева Trie виконується функцією пошуку в глибину (DFS). Кожен виклик приймає поточний вузол дерева, символ ребра, батьківський вектор динамічного програмування та поточну довжину сформованого префікса:

1. **Ініціалізація на корені:** Кореневий вузол дерева не містить символу. Для нього створюється базовий вектор `parent_row` розміром `|query| + 1`, де кожна клітинка `j` містить число `j` (вартість перетворення порожнього рядка в префікс запиту довжини `j`).
2. **Обчислення рядка для дочірнього вузла:** Нехай ми переходимо у вузол із символом `c`. Створюється новий вектор `current_row` розміром `|query| + 1`, де `current_row[0] = parent_row[0] + 1`.
3. **Заповнення вектора:** Для кожного індексу `j` від 1 до `|query|` обчислюється мінімум трьох операцій: видалення `parent_row[j] + 1`, вставка `current_row[j-1] + 1` та заміна `parent_row[j-1] + (query[j-1] == c ? 0 : 1)`.
4. **Перевірка термінальності:** Якщо вузол позначений як кінець слова (`is_terminal == true`) і значення `current_row[|query|] <= max_distance`, знайдений кандидат додається до списку результатів.
5. **Відсікання гілок:** Обчислюється мінімальне значення `min_val = min(current_row)`. Якщо `min_val > max_distance`, рекурсивний спуск по всіх дочірніх гілках поточного вузла зупиняється.

## Таблиця конфігураційних параметрів

Конфігурація пошуку дозволяє гнучко налаштовувати баланс між швидкістю виконання та повнотою видачі результатів:

| Параметр | Тип | За замовчуванням | Опис та поведінка |
|---|---|---|---|
| max_distance | int | 2 | Поріг відстані Левенштейна. Значення 1 знаходить більшість поодиноких описок, значення 2 покриває складні комбіновані помилки. |
| prefix_freeze_len | size_t | 0 | Кількість початкових символів пошукового запиту, які повинні збігатися суворо без помилок. |
| allow_transposition | bool | false | Прапорець увімкнення обліку перестановки двох сусідніх літер як однієї операції Дамерау. |
| max_results | size_t | 50 | Обмеження на максимальну кількість повернених знахідок для оптимізації обходу дерева. |

## Детальний опис алгоритмічних опцій

1. **Параметр max_distance:** Визначає радіус метричної кулі навколо пошукового слова. Значення одиниця дозволяє знаходити понад вісімдесят відсотків типових описок користувача при мінімальних витратах процесорного часу. Значення двійка покриває понад дев'яносто вісім відсотків усіх можливих друкарських помилок, проте збільшує кількість перевірених вузлів дерева приблизно в п'ять разів. Значення три і більше рекомендується використовувати лише для специфічних біоінформатичних задач, оскільки на звичайних текстових словниках воно породжує занадто велику кількість хибних збігів.

2. **Опція prefix_freeze_len:** Практика показує, що користувачі вкрай рідко припускаються помилки в першій або другій літері слова. Встановлення фіксованого префікса довжиною один або два символи дозволяє миттєво перейти у відповідне піддерево без перевірки решти гілок, що прискорює загальний час автодоповнення у двадцять-п'ятдесят разів.

3. **Прапорець allow_transposition:** Вмикає додатковий діагональний перехід на два кроки назад у векторі динамічного програмування, перетворюючи метрику Левенштейна на відстань Дамерау—Левенштейна. Це дозволяє вважати перестановку двох сусідніх літер однією друкарською опискою.

4. **Ліміт max_results:** Запобігає надмірному виділенню динамічної пам'яті для результуючого вектора. Як тільки кількість знайдених збігів досягає зазначеного ліміту, функція зворотного виклику сигналізує про зупинку обходу піддерев.

5. **Механізм ранжирування видачі:** Результати пошуку впорядковуються за зростанням відстані редагування, а при рівній відстані — за частотністю або вагою користувацьких даних user_data. Це гарантує, що найімовірніші виправлення завжди знаходяться на початку списку.

## Стиснення суфіксів та структури DAWG / FST

При роботі зі словниками обсягом у десятки мільйонів слів класичне префіксне дерево Trie стає занадто громіздким через надмірну кількість вузлів. У природних мовах більшість слів мають спільні граматичні закінчення та суфікси (наприклад, флексії дієслів або відмінкові закінчення іменників).

Бібліотека підтримує компіляцію індексу в детермінований скінченний автомат слів (DAWG або FST — Finite State Transducer). У такій структурі об'єднуються не лише спільні префікси, а й спільні суфіксальні підграфи. Це перетворює дерево на орієнтований ациклічний граф, зменшуючи використання оперативної пам'яті у чотири-вісім разів.

Обчислення вектора динамічного програмування на графі DAWG виконується аналогічно дереву Trie, проте з обов'язковим кешуванням пар «вузол графа — вектор станів» для запобігання повторному обходу однакових суфіксальних шляхів.

## Конкурентна модель та архітектура оновлення індексу в реальному часі

Для підтримки цілодобової роботи високонавантажених мікросервісів бібліотека реалізує архітектуру подвійної буферизації (Double Buffering):

1. **Незмінний знімок для читачів:** Поточні пошукові запити опрацьовуються пулом робочих потоків над незмінною копією індексу без будь-яких блокувань та атомарних лічильників, забезпечуючи максимальну пропускну здатність процесора.
2. **Фонове наповнення:** Нові слова та оновлені записи словника накопичуються у фоновому буфері або окремому тіньовому дереві.
3. **Атомарний своп:** Після завершення пакетного додавання вказівник на активний індекс атомарно перемикається на новий екземпляр за допомогою std::atomic, а стара версія індексу безпечно звільняється після виходу всіх поточних читачів.


## Архітектура стиснення вузлів: Patricia Trie та Double-Array Trie

У високонавантажених сервісах нечіткого пошуку для мінімізації споживання пам'яті застосовуються дві прогресивні структури представлення дерев:

1. **Радіксне стиснення ребер (Radix / Patricia Tree):** Якщо ланцюжок вузлів не містить розгалужень (кожен проміжний вузол має рівно одного нащадка), ці вузли об'єднуються в єдине ребро з багатосимвольним рядком. При нечіткому пошуку по такому ребру вектор динамічного програмування послідовно оновлюється для кожного символу рядка ребра без створення проміжних об'єктів вузлів у пам'яті.
2. **Компактне масивне представлення Double-Array Trie (DAT):** Дерево кодується за допомогою двох одновимірних цілочисельних масивів BASE та CHECK фіксованого розміру. Перехід за символом c з вузла s у вузол t обчислюється за формулою `t = BASE[s] + c`. Перевірка валідності переходу здійснюється порівнянням `CHECK[t] == s`. Це зводить перехід між вузлами дерева до однієї операції додавання та двох звернень до масиву без використання покажчиків, забезпечуючи максимальну швидкість обходу та стовідсоткову локальність даних.

## Інтеграція користувацьких ваг та персоналізованого ранжування

Бібліотека fuzzy_matcher дозволяє передавати користувацькі функції зворотного виклику для модифікації ваг операцій редагування залежно від мовного контексту:

- **Клавіатурна матриця близькості:** Операція заміни двох літер, розташованих поруч на стандартній клавіатурі (наприклад, літери 'a' та 's' у розкладці QWERTY), може отримувати знижену вартість 0.5 замість 1.0.
- **Фонетичні ваги схожості:** Заміна літер з однаковим або близьким звучанням (наприклад, 'c' та 'k', або 'ph' та 'f') оцінюється з меншим штрафом, що значно покращує якість пошуку для транслітерованих запитів.
- **Частотний пріоритет у префіксах:** Поле user_data може містити логарифм частоти слова у мовному корпусі, що дозволяє сортувати знайдених кандидатів за комбінованою функцією близькості Левенштейна та популярності слова.


## Обробка помилок та діагностика стану індексу

Інтерфейс бібліотеки забезпечує повний контроль за коректністю операцій та внутрішнім станом структур даних:

1. **Коди статусу виконання:** Перерахування fuzzy_status_t містить детальні статуси: FUZZY_OK при успішному виконанні, FUZZY_ERR_INVALID_ARG при некоректних вхідних аргументах (нульовий покажчик, від'ємне значення порогу відстані), FUZZY_ERR_NO_MEMORY при неможливості виділення вузла дерева в оперативній пам'яті, та FUZZY_ERR_NOT_FOUND якщо жодного відповідного кандидата не знайдено.
2. **Гарантії безпеки винятків у C++:** Усі публічні методи класу FuzzyMatcher надають сувору гарантію безпеки винятків (Strong Exception Guarantee). Якщо виникає помилка виділення пам'яті при додаванні нового слова, внутрішній стан дерева залишається незмінним, а викликаючий код отримує об'єкт std::unexpected із кодом помилки.
3. **Хуки профілювання та моніторингу:** Розробник може зареєструвати власну функцію зворотного виклику для збору метрик продуктивності: час обходу дерева, пікове споживання пам'яті та глибина рекурсивного стека викликів.


## Приклад реалізації користувацького фільтра та ранжування

Для демонстрації гнучкості інтерфейсу бібліотека підтримує інтеграцію власних правил предикатної фільтрації через аргумент контексту:

Розробник може передати структуру параметрів користувача, яка додатково перевіряє категорію товару, мовний код або географічний регіон знайденого словникового запису. Якщо слово формально підходить за відстанню Левенштейна, але не відповідає встановленому контекстному фільтру, воно відкидається на етапі виклику функції зворотного виклику без виділення пам'яті під результат.


## Рекомендації щодо інтеграції в розподілені сервіси

При розгортанні бібліотеки fuzzy_matcher у складі мікросервісів високої доступності рекомендується розділяти процеси наповнення та читання індексу. Для кожного екземпляра мікросервісу виділяється локальна копія скомпільованого індексу в оперативній пам'яті (In-Memory Read-Only Replica), що дозволяє повністю усунути мережеві затримки при обробці призначених для користувача пошукових запитів.

## Інваріанти пам'яті, безпека потоків та обробка помилок

1. **Безпека паралельного читання (Thread Safety):** Створена структура дерева після завершення фази наповнення є незмінною для читачів. Декілька незалежних робочих потоків можуть одночасно викликати функцію пошуку без використання м'ютексів та блокувань. Модифікація дерева (додавання нових слів) вимагає ексклюзивного доступу або використання м'ютекса читачів-письменників std::shared_mutex.
2. **Керування пам'яттю:** Бібліотека самостійно дублює передані рядкові дані у власні внутрішні пули пам'яті. Викликаючий код може звільняти або перезаписувати тимчасові буфери рядків одразу після повернення з функції додавання.
3. **Обробка помилок:** Функції повертають статус виконання у вигляді числових кодів або типу std::expected у C++, що гарантує відсутність неперехоплених аварійних завершень при вичерпанні оперативної пам'яті.
4. **Масштабованість індексу:** Для словників розміром понад десять мільйонів записів рекомендується застосовувати стиснення спільних суфіксів (DAWG / FST), що зменшує обсяг оперативної пам'яті у чотири-вісім разів без втрати швидкості пошуку.
5. **Вимоги до нормалізації тексту:** Бібліотека передбачає, що всі вхідні рядки попередньо приведені до єдиного регістру (нижній регістр) та нормалізовані за стандартом Unicode NFC, що виключає хибні незбіги через різне представлення діакритичних символів.
6. **Діагностика та метрики телеметрії:** Бібліотека надає хуки для збору статистики: середня кількість переглянутих вузлів на запит, коефіцієнт відсікання гілок та час формування результату в мікросекундах.
