# 🧮 Аналіз вартості розширення блочної черги

Під час роботи з блочною двобічною чергою більшість операцій додавання елементів (`push_back` та `push_front`) виконуються миттєво за 1 операцію запису в оперативну пам'ять. Проте зрідка поточний блок пам'яті заповнюється повністю, і програма змушена запитувати в операційної системи новий блок. Виділення пам'яті — це повільна системна операція. 

Як довести, що ці рідкісні важкі затримки не псують загальну ефективність черги у довгостроковій перспективі?

---

### Чому оцінка за найгіршим випадком є хибною

Якщо оцінювати складність окремої операції додавання за найгіршим випадком (*Worst-case Analysis*), ми отримаємо негативний висновок:
- Звичайна вставка у вільну комірку коштує `t = 1` одиницю часу.
- Вставка, що викликає виділення нового блоку через виклики `malloc` чи `operator new`, коштує `t = 1 + K` одиниць часу, де `K` — це часові витрати на звернення до ядра ОС, пошук вільного фрагмента в купі та оновлення системних таблиць.

Оскільки `K` є відносно великим числом, оцінка за найгіршим випадком змусила б нас записати складність операції додавання як `O(K)`. 

Проте така оцінка є неадекватною для реальних програм. Важкий виклик вартістю `K` відбувається вкрай рідко — лише один раз на `B` операцій (де `B` — місткість одного блоку, наприклад, 64 елементи). Решта `B - 1` операцій виконуються за точний час `O(1)`.

Щоб отримати точну і чесну оцінку швидкодії послідовності операцій, застосовують **амортизаційний аналіз** (*Amortized Analysis*).

---

### Метод потенціалів (Potential Method)

Найбільш суворим інструментом амортизаційного аналізу є **метод потенціалів** (іноді званий методом фізика).

Ми вводимо функцію потенціалу `Φ(S)`, яка відображає поточний стан `S` нашої структури даних у невід'ємне число. Функція `Φ` відіграє роль «накопиченої енергії» або «банківської скарбнички часу».

Нехай `c_i` — це реальна часова вартість виконання `i`-ї операції.
Ми визначаємо **амортизовану вартість** `a_i` цієї операції через зміну потенціалу структури:

`a_i = c_i + Φ_i - Φ_{i-1}`

де `Φ_{i-1}` — потенціал структури ДО виконання операції, а `Φ_i` — ПОСЛЯ її виконання.

#### Математичний зв'язок реальних та амортизованих витрат

Якщо ми просумуємо амортизовану вартість для всієї послідовності з `N` операцій, то зміни потенціалу утворюють телескопічну суму, де всі проміжні значення скорочуються:

`∑ a_i = ∑ (c_i + Φ_i - Φ_{i-1}) = ∑ c_i + Φ_N - Φ_0`

Перенесємо початковий і кінцевий потенціал у ліву частину:

`∑ c_i = ∑ a_i + Φ_0 - Φ_N`

Якщо ми початково задамо `Φ_0 = 0` і зафіксуємо функцію потенціалу так, щоб вона завжди залишалася невід'ємною (`Φ_N ≥ 0`), то звідси випливає фундаментальна нерівність:

`∑ c_i ≤ ∑ a_i`

Це означає, що сума амортизованих витрат `∑ a_i` є **суворою верхньою межею** для реальних часових витрат програми `∑ c_i`.

### Розрахунок амортизованої вартості для блочного дека

Застосуємо метод потенціалів до блочної двобічної черги.

Нехай один блок пам'яті вміщує `B` елементів (наприклад, `B = 64`). 
Позначимо через `k` кількість елементів, які наразі записані у поточному крайньому блоці (`1 ≤ k ≤ B`).

Визначимо функцію потенціалу `Φ` крайнього блоку як:

`Φ = c · k`

де `c` — це постійний коефіцієнт заощадження («монета часу», яку ми кладемо в скарбничку при кожному додаванні), значення якого ми підберемо нижче.

#### Випадок 1: Легке додавання (блок ще не повний, k < B)

Елемент просто записується у вільну комірку блоку.
- Реальна вартість операції: `c_i = 1`.
- Кількість елементів у блоці зростає з `k - 1` до `k`.
- Зміна потенціалу: `ΔΦ = Φ_i - Φ_{i-1} = c · k - c · (k - 1) = c`.

Обчислюємо амортизовану вартість легкого кроку:

`a_i = c_i + ΔΦ = 1 + c`

Оскільки `c` — це фіксована стала, амортизована вартість легкого додавання становить константний час **O(1)**.

#### Випадок 2: Важке додавання з виділенням нового блоку (k = B)

Попередній блок заповнений повністю (`k = B`). Перед виконанням операції потенціал цього блоку досяг максимуму:

`Φ_{i-1} = c · B`

Програма виконує системне виділення нового блоку пам'яті вартістю `K` і записує новий елемент як першу комірку нового блоку (`k = 1`).
- Реальна вартість операції: `c_i = 1 + K`.
- Новий потенціал структури після виділення блоку з 1 елементом: `Φ_i = c · 1 = c`.
- Зміна потенціалу структури:

`ΔΦ = Φ_i - Φ_{i-1} = c - c · B = c · (1 - B)`

Обчислюємо амортизовану вартість важкої операції:

`a_i = c_i + ΔΦ = (1 + K) + c · (1 - B) = 1 + K + c - c · B`

Групуємо доданки:

`a_i = 1 + c + (K - c · B)`

#### Підбір коефіцієнта заощадження c

Наша мета — підбрати коефіцієнт `c` так, щоб важкий крок не викликав сплеску амортизованої вартості. Для цього вимагаємо, щоб вираз у дужках `(K - c · B)` дорівнював нулю або був від'ємним:

`K - c · B ≤ 0   ==>   c ≥ K / B`

Оберемо `c = K / B`. Підставимо це значення у формулу амортизованої вартості важкого кроку:

`a_i = 1 + (K / B) + 0 = 1 + K / B`

---

### Висновок та аналіз результату

Оскільки вартість системного виділення пам'яті `K` та місткість блоку `B` є фіксованими константами конфігурації структури (наприклад, `K = 1280` та `B = 64`), величина `1 + K / B` є константним числом (наприклад, `1 + 1280 / 64 = 21`).

Отже, амортизована вартість важкої операції додавання дорівнює:

`a_i = O(1)`

#### Аналіз реалокації Карти вказівників (Map Resizing)

Аналогічний розрахунок застосовується до випадку, коли вичерпується місткість центральної карти вказівників.

Якщо карта містить `M` вказівників, її розширення до розміру `2M` вимагає копіювання `M` легких адрес, тобто `c_map = M`.
Проте розширення карти відбувається лише після повного заповнення `M` нових блоків. Загальна кількість елементів, доданих між розширеннями карти, дорівнює `M · B`.

Розподіливши вартість копіювання карти `M` на кількість доданих елементів `M · B`, отримуємо додатковий амортизований внесок на один елемент:

`a_map = M / (M · B) = 1 / B`

Для блоку розміром `B = 64` це додає лише `1 / 64 ≈ 0.015` операції на один елемент, що є мізерною дробовою величиною.

**Підсумок:** Метод потенціалів суворо доводить, що незалежно від кількості збережених даних та виділень пам'яті, кожна операція додавання чи вилучення з обох кінців двобічної черги гарантовано виконується за стабільний амортизований час **O(1)**.
