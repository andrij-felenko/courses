# ⚙️ Реалізація кільцевої двобічної черги

Кільцевий буфер є фундаментальною реалізацією двобічної черги для систем із суворими вимогами до часу виконання та ресурсів: вбудовані системи (embedded), мікроконтролери (STM32, ESP32, AVR), ядра операційних систем реального часу (FreeRTOS, Zephyr) та низкорівневі драйвери пристроїв (DMA, UART, SPI буфери).

У таких середовищах використання динамічного виділення пам'яті (`malloc` або `new`) заборонене або вкрай небажане через три причини:
1. **Фрагментація купи (Heap Fragmentation):** постійне виділення та звільнення блоків довільного розміру призводить до деградації пам'яті, коли сумарно вільної пам'яті достатньо, але неможливо знайти жодного суцільного блоку.
2. **Недетермінізм часу виконання:** виклик `malloc` може тривати від кількох десятків наносекунд до десятків мікросекунд залежно від стану купи, що неприпустимо для систем реального часу (Hard Real-Time Systems).
3. **Обмеженість ресурсів:** чип може мати лише 4–16 кілобайтів RAM, де кожна комірка пам'яті рахується.

Кільцевий буфер працює на основі статично виділеного масиву фіксованого розміру і гарантує абсолютно детермінований час виконання кожної операції **O(1)** без жодного виклику динамічної пам'яті.

### Математична ідея та обчислення індексів без умовних операторів

Нехай ми маємо неперервний масив `data` фіксованої місткості `N`.
Для управління станом черги ми зберігаємо два індекси-маркери та один лічильник:
- `head` — індекс комірки, де розташований перший (найстаріший) елемент.
- `tail` — індекс комірки, де розташований останній (найновіший) елемент.
- `count` — поточна кількість елементів у черзі (`0 ≤ count ≤ N`).

Головне алгоритмічне завдання — забезпечити «безкінечний» коловий рух маркерів `head` та `tail` без виходу за межі масиву `[0, N - 1]`.

#### 1. Рух маркера праворуч (додавання в кінець `push_back`, вилучення з початку `pop_front`)
Звичайний крок вперед вимагає збільшення індексу на 1. Аби при досягненні кінця масиву `N - 1` наступний крок повернув маркер на 0, ми застосовуємо модульну арифметику:

`index_next = (index + 1) % N`

#### 2. Рух маркера ліворуч (додавання на початок `push_front`, вилучення з кінця `pop_back`)
Крок назад вимагає зменшення індексу на 1. Проте якщо `index == 0`, вираз `0 - 1` дасть від'ємне число `-1`, що призведе до аварійного виходу за межі масиву (Buffer Underflow).

Аби уникнути повільних умовних операторів `if (index < 0) index = N - 1`, ми додаємо значення місткості `N` до різниці перед обчисленням остачі:

`index_prev = (index - 1 + N) % N`

Завдяки додаванню `N`, чисельник завжди залишається додатним числом, і операція остачі від ділення `% N` коректно переносить маркер у кінець масиву `N - 1`.

### Робочі реалізації (C та C++)

Нижче наведено повні виробничі реалізації кільцевої двобічної черги. Завдяки контейнеру `:::tabs` ви можете обрати варіант мовою C (ідеально для вбудованих прошивок чи системних драйверів) або C++ (шаблонний клас із безпечними типами та мовою C++17).

```c
#include <stdio.h>
#include <stdbool.h>

#define DEQUE_CAPACITY 8

typedef struct {
    int data[DEQUE_CAPACITY];
    int head;
    int tail;
    int count;
} CircularDeque;

// Ініціалізація порожньої черги
void deque_init(CircularDeque *dq) {
    dq->head = 0;
    dq->tail = 0;
    dq->count = 0;
}

// Перевірка на переповнення
bool deque_is_full(const CircularDeque *dq) {
    return dq->count == DEQUE_CAPACITY;
}

// Перевірка на порожнечу
bool deque_is_empty(const CircularDeque *dq) {
    return dq->count == 0;
}

// Додавання на початок (голова рухається ліворуч по колу)
bool deque_push_front(CircularDeque *dq, int value) {
    if (deque_is_full(dq)) return false;
    
    // Зсуваємо head ліворуч по колу лише якщо черга НЕ порожня
    if (!deque_is_empty(dq)) {
        dq->head = (dq->head - 1 + DEQUE_CAPACITY) % DEQUE_CAPACITY;
    }
    
    dq->data[dq->head] = value;
    dq->count++;
    return true;
}

// Додавання в кінець (хвіст рухається праворуч по колу)
bool deque_push_back(CircularDeque *dq, int value) {
    if (deque_is_full(dq)) return false;
    
    // Зсуваємо tail праворуч по колу лише якщо черга НЕ порожня
    if (!deque_is_empty(dq)) {
        dq->tail = (dq->tail + 1) % DEQUE_CAPACITY;
    }
    
    dq->data[dq->tail] = value;
    dq->count++;
    return true;
}

// Вилучення з початку (голова рухається праворуч по колу)
bool deque_pop_front(CircularDeque *dq, int *out_value) {
    if (deque_is_empty(dq)) return false;
    
    *out_value = dq->data[dq->head];
    dq->count--;
    
    // Якщо після вилучення черга не стала порожньою, рухаємо head праворуч
    if (!deque_is_empty(dq)) {
        dq->head = (dq->head + 1) % DEQUE_CAPACITY;
    }
    return true;
}

// Вилучення з кінця (хвіст рухається ліворуч по колу)
bool deque_pop_back(CircularDeque *dq, int *out_value) {
    if (deque_is_empty(dq)) return false;
    
    *out_value = dq->data[dq->tail];
    dq->count--;
    
    // Якщо після вилучення черга не стала порожньою, рухаємо tail ліворуч
    if (!deque_is_empty(dq)) {
        dq->tail = (dq->tail - 1 + DEQUE_CAPACITY) % DEQUE_CAPACITY;
    }
    return true;
}

int main(void) {
    CircularDeque dq;
    deque_init(&dq);

    deque_push_back(&dq, 10);
    deque_push_back(&dq, 20);
    deque_push_front(&dq, 5);  // Стан черги: [5, 10, 20]

    int val;
    printf("Елементи черги з початку: ");
    while (deque_pop_front(&dq, &val)) {
        printf("%d ", val);  // Виведе: 5 10 20
    }
    printf("\n");
    return 0;
}
```
```cpp
#include <iostream>
#include <array>
#include <optional>

template <typename T, size_t Capacity>
class CircularDeque {
private:
    std::array<T, Capacity> data_;
    size_t head_ = 0;
    size_t tail_ = 0;
    size_t count_ = 0;

public:
    CircularDeque() = default;

    [[nodiscard]] bool is_full() const noexcept { return count_ == Capacity; }
    [[nodiscard]] bool is_empty() const noexcept { return count_ == 0; }
    [[nodiscard]] size_t size() const noexcept { return count_; }

    // Додавання на початок (голова рухається ліворуч)
    bool push_front(const T& value) {
        if (is_full()) return false;
        
        if (!is_empty()) {
            head_ = (head_ - 1 + Capacity) % Capacity;
        }
        
        data_[head_] = value;
        count_++;
        return true;
    }

    // Додавання в кінець (хвіст рухається праворуч)
    bool push_back(const T& value) {
        if (is_full()) return false;
        
        if (!is_empty()) {
            tail_ = (tail_ + 1) % Capacity;
        }
        
        data_[tail_] = value;
        count_++;
        return true;
    }

    // Вилучення з початку (голова рухається праворуч)
    std::optional<T> pop_front() {
        if (is_empty()) return std::nullopt;
        
        T value = data_[head_];
        count_--;
        
        if (!is_empty()) {
            head_ = (head_ + 1) % Capacity;
        }
        return value;
    }

    // Вилучення з кінця (хвіст рухається ліворуч)
    std::optional<T> pop_back() {
        if (is_empty()) return std::nullopt;
        
        T value = data_[tail_];
        count_--;
        
        if (!is_empty()) {
            tail_ = (tail_ - 1 + Capacity) % Capacity;
        }
        return value;
    }
};

int main() {
    CircularDeque<int, 8> dq;

    dq.push_back(10);
    dq.push_back(20);
    dq.push_front(5);  // Стан черги: [5, 10, 20]

    std::cout << "Елементи черги з початку: ";
    while (auto val = dq.pop_front()) {
        std::cout << *val << " ";  // Виведе: 5 10 20
    }
    std::cout << "\n";
    return 0;
}
```

### Тонкощі реалізації та класичні пастки

Розробка кільцевого буфера містить кілька небезпечних підводних каменів, недогляд яких призводить до важковловимих помилок пам'яті (Memory Corruption).

#### 1. Пастка першого елемента у порожньому буфері

Розглянемо початковий стан порожньої черги, де `head = 0` та `tail = 0`. Оба маркери вказують на індекс 0.

Якщо розробник сліпо застосує формулу зміщення перед записами `head = (head - 1 + N) % N`, то при виклику `push_front` для першого елемента маркер `head` зсунеться на `N - 1` (наприклад, 7), тоді як `tail` залишиться на `0`.
У результаті утворюється розсихронізація: в черзі перебуває лише 1 елемент, але `head` і `tail` вказують на протилежні краї буфера!

**Правильний розв'язок:**
Зсув маркерів `head` або `tail` виконується **виключно тоді, коли черга не є порожньою** (`count > 0`). Перший елемент завжди записується прямо в поточну позицію `head` (або `tail`), залишаючи обох маркерів на спільному індексі.

#### 2. Проблема розрізнення понять «Порожній» проти «Повний» без лічильника

Якщо реалізовувати кільцеву чергу без окремої змінної `count`, виникає колізія станів індексів:
- Коли черга **порожня**, `head == tail`.
- Коли черга **повністю заповнена** і `tail` зробив повне коло і наздогнав `head`, знову `head == tail`.

Немижливість розрізнити повний буфер від порожнього без додаткових умов вирішується двома шляхами:
1. **Використання явного лічильника `count`** (як зроблено у коді вище). Це найбільш надійний підхід для багатопотокових систем.
2. **Жертвування однією коміркою пам'яті:** масив розміром `N` може зберігати щонайбільше `N - 1` елементів. Умова порожнечі: `head == tail`, умова повноти: `(tail + 1) % N == head`.

#### 3. Атомарність у середовищах переривань (SPSC Ring Buffer)

У мікроконтролерах кільцеву чергу часто використовують для передачі даних між обробником переривання (ISR) та головним циклом `main()`. Це режим одного виробника та одного споживача (*Single-Producer Single-Consumer*, SPSC):
- Виробник (наприклад, ISR приймача UART) лише викликає `push_back` і модифікує маркер `tail`.
- Споживач (головний цикл) лише викликає `pop_front` і модифікує маркер `head`.

Якщо черга побудована без лічильника `count` (де `head` і `tail` модифікуються тільки своїми потоками), така структура даних є **природно потокобезпечною (lock-free)** і не вимагає критичних секцій чи блокувань (Mutexes). Для коректної роботи на сучасних процесорах достатньо позначити маркери `head` і `tail` як `volatile` (або `std::atomic` у C++) для запобігання оптимізаціям компілятора через кешування у регістрах.
