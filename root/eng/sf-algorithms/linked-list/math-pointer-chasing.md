# 🧮 Аналітична модель доступу до пам'яті та кеш-промахів

Аналітична оцінка продуктивності структур даних у класичному аналізі алгоритмів базується на теоретичній моделі RAM (Random Access Machine). У цій спрощеній моделі передбачається, що будь-яке звернення до оперативної пам'яті за довільною адресою коштує рівно одну одиницю часу `O(1)`. Тобто вважається, що читання комірки з індексом `0` та комірки з індексом `1 000 000` має абсолютно однакову часову затримку.

Однак на сучасній обчислювальній апаратурі це припущення виявляється принципово хибним. Фізична пам'ять сучасних процесорів побудована у вигляді суворої багаторівневої ієрархії: надшвидкі регістри CPU, три рівні кеш-пам'яті (L1, L2, L3) та відносно повільна системна оперативна пам'ять (DRAM). У цій вставці наведено математичну модель та виведення часових та просторових витрат при обході суцільного масиву проти зв'язаного списка на реальному процесорі.

## 1. Фізична ієрархія пам'яті та затримки доступу

Щоб зрозуміти джерело різниці в швидкості, розглянемо фізичні затримки звернення до різних рівнів пам'яті сучасного процесора x86-64 або ARM64 з тактовою частотою близько 4.0 ГГц (тривалість одного такту процесора `t_cycle ≈ 0.25` наносекунд):

1. **Регістри процесора**: `0` затримки (доступ всередині поточного такту).
2. **L1 Кеш даних (32–64 КБ на ядро)**: Затримка `4–5` циклів CPU (`≈ 1.0–1.2` наносекунди).
3. **L2 Кеш (512 КБ – 1 МБ на ядро)**: Затримка `12–14` циклів CPU (`≈ 3.0–3.5` наносекунди).
4. **L3 Кеш (спільний, 16–64 МБ)**: Затримка `40–50` циклів CPU (`≈ 10.0–12.0` наносекунд).
5. **Оперативна пам'ять DRAM (RAM)**: Затримка `200–250` циклів CPU (`≈ 50.0–60.0` наносекунд).

Затримка читання з оперативної пам'яті в 50 разів перевищує час доступу до L1-кешу. Кожного разу, коли процесор вимушений чекати на дані з DRAM, обчислювальне ядро зупиняє виконання інструкцій (подія, відома як CPU Pipeline Stall).

## 2. Аналіз просторової локальності та кеш-ліній

Процесорний контролер пам'яті ніколи не передає по шині поодинокі 8-бітні байти або 32-бітні числа. Інформація завжди зчитується суцільними фіксованими блоками — **кеш-лініями** (англ. *cache lines*). У всіх сучасних загальносистемних архітектурах розмір однієї кеш-лінії становить строго `B = 64` байти (`512` бітів).

### Суцільний масив (Spatial Locality)
Розглянемо масив з `N` елементів типу `uint64_t` (розмір елемента `s = 8` байтів). Елементи розташовані в пам'яті один за одним за адресами `Base, Base + 8, Base + 16, ...`.

Кількість елементів, які фізично пакуються в одну 64-байтову кеш-лінію:

```
K_array = B / s
        = 64 / 8
        = 8 елементів   [цілих елементів у 1 кеш-лінії]
```

При послідовному обході масиву від `i = 0` до `N - 1`:
- Звернення до елемента `A[0]` викликає кеш-промах (Cache Miss). Контролер зчитує з DRAM усю 64-байтову кеш-лінію, яка містить елементи від `A[0]` до `A[7]`.
- Звернення до наступних елементів `A[1], A[2], ..., A[7]` задовольняються миттєво з L1-кешу (Cache Hit).
- Наступний кеш-промах виникає лише на елементі `A[8]`.

Кількість кеш-промахів для масиву з `N` елементів:

```
C_array(N) = N / K_array
           = N / 8
           = 0.125 · N   [кеш-промахів на N елементів]
```

Завдяки передбачуваності послідовних адрес апаратний блок попередньої вибірки процесора (Hardware Data Prefetcher) розпізнає лінійне крокування і починає завантажувати наступні кеш-лінії з DRAM в L2/L1-кеш наперед, зводячи реальну затримку майже до нуля.

### Зв'язаний список (Pointer Chasing)
У зв'язаному списку кожен вузол створюється окремим викликом функцій виділення пам'яті (`malloc` у мові C або `new` у C++). Внаслідок природної фрагментації оперативної пам'яті вузли опиняються у довільних, хаотично розподілених адресах адресної простору.

Крім того, вузол списку повинен містити вказівник на наступний елемент. На 64-бітній архітектурі розмір вказівника становить 8 байтів. Вузол для збереження `uint64_t` вимагає принаймні `16` байтів (`8` байтів даних + `8` байтів вказівника `next`).

У найгіршому та типовому реальному випадку кожен новий вузол списку знаходиться у новій кеш-лінії оперативної пам'яті. 

Кількість кеш-промахів при обході `N` вузлів списка:

```
C_list(N) = N · p_miss
          = N · 1.0
          = 1.000 · N   [кеш-промахів на N елементів]
```

Коефіцієнт кеш-промахів між списком та масивом:

```
C_list(N) / C_array(N) = N / (0.125 · N)
                       = 8   [у 8 разів більше звернень до RAM]
```

## 3. Математична модель часу виконання та блокада процесора

Середній час доступу до пам'яті (Average Memory Access Time, AMAT) обчислюється за формулою:

```
AMAT = t_L1 + (p_miss · t_RAM)
```

Де:
- `t_L1` — затримка зчитування з L1-кешу (`1.2` нс).
- `t_RAM` — затримка зчитування з системної DRAM (`60.0` нс).
- `p_miss` — ймовірність промаху кешу.

### Обчислення для масиву
Ймовірність кеш-промаху для суцільного масиву становить `p_miss_array = 1 / 8 = 0.125`.

```
AMAT_array = t_L1 + (p_miss_array · t_RAM)
           = 1.2 нс + (0.125 · 60.0 нс)
           = 1.2 нс + 7.5 нс
           = 8.7 нс     [середній час на 1 елемент]
```

Для масиву з `N = 10⁶` (1 мільйон) елементів загальний час доступу становить:

```
T_array = 10⁶ · 8.7 нс = 8.7 мілісекунд
```

### Обчислення для зв'язаного списка (Феномен Pointer Chasing)
При обході зв'язаного списка адреса наступного вузла збережена всередині поточного вузла: `current = current->next`. Процесор **не може** прочитати наступний вузол, поки не завершиться фізичне читання поточного вузла з DRAM. 

Це викликає повне руйнування конвеєра інструкцій процесора (Instruction Level Parallelism, ILP = 1). Апаратний Prefetcher виявляється безсилим, оскільки адреси вузлів не мають сталого кроку (stride).

Ймовірність кеш-промаху становить `p_miss_list = 1.0`.

```
AMAT_list = t_L1 + (p_miss_list · t_RAM)
          = 1.2 нс + (1.0 · 60.0 нс)
          = 61.2 нс    [середній час на 1 елемент]
```

Загальний час обходу списка з 1 мільйона елементів:

```
T_list = 10⁶ · 61.2 нс = 61.2 мілісекунд
```

### Порівняльний коефіцієнт реальної швидкості

```
Ratio = T_list / T_array
      = 61.2 мс / 8.7 мс
      ≈ 7.03   [список повільніший за масив у 7 разів]
```

Отже, хоча і масив, і список мають однакову математичну складність обходу `O(N)`, зв'язаний список виконується у 7 разів повільніше виключно через фізичні обмеження ієрархії кеш-пам'яті.

## 4. Оцінка просторової ефективності пам'яті (Memory Overhead Ratio)

Визначимо коефіцієнт корисної дії використання пам'яті `E` (Efficiency Ratio) як відношення розміру корисних даних до загального обсягу виділеної оперативної пам'яті:

```
E = V_payload / V_total
  = V_payload / (V_payload + V_overhead)
```

Розглянемо випадок збереження 32-бітного цілого числа (`sizeof(uint32_t) = 4` байти):

1. **Динамічний масив**: `V_payload = 4` байти, `V_overhead = 0` (амортизовано). `E_array = 4 / 4 = 1.0` (100% корисної пам'яті).
2. **Однозв'язаний список на 64-бітній системі**:
   - `V_payload = 4` байти.
   - `s_pointer = 8` байтів (`uintptr_t`).
   - Паддінг вирівнювання структури (Alignment Padding до 8 байтів): `4` байти.
   - Загальний розмір структури вузла: `16` байтів.
   - Заголовок аллокатора купи (Heap Allocator Header для `malloc` Boundary Tags): від `8` до `16` байтів на кожне окреме виділення блока у купі.

Обчислення просторової ефективності списка:

```
V_total_node = sizeof(Node) + malloc_header
             = 16 + 16
             = 32 байти   [загальна пам'ять на 1 вузол]

E_list = V_payload / V_total_node
       = 4 / 32
       = 0.125            [лише 12.5% виділеної пам'яті є корисними даними]
```

Накладні витрати зв'язаного списка для малих типів даних досягають `87.5%` від загального обсягу оперативної пам'яті. Це робить зв'язаний список вкрай марнотратною структурою даних для використання на сучасних комп'ютерах.
