# 🧮 Чому віконний запит коштує √N, а не log N

Дерево двійкове, спуск логарифмічний — а ціна питання «які точки лежать у цьому прямокутнику» виходить кореневою. Тут ця ціна рахується від початку до кінця: лема про пряму, точний розв'язок рекурентності, узагальнення на d вимірів і числа, за якими видно, де оцінка перестає бодай щось обіцяти.

### Куди зводиться вся робота

Обхід починається з кореня. Про кожен вузол його комірка каже одну з трьох речей:

- комірка не перетинає вікна — вузол відкидається одним порівнянням разом з усім піддеревом;
- комірка лежить у вікні цілком — усе піддерево йде у відповідь, і жодної координати перевіряти не треба;
- інакше — крізь комірку проходить **межа** вікна.

Третій випадок справді третій, а не «решта». Якщо в комірці є точка всередині вікна й точка ззовні, то відрізок між ними десь перетинає межу вікна; комірка опукла, тож ця точка перетину лежить у самій комірці. Отже «перетинає вікно, але не міститься в ньому» — те саме, що «межа проходить крізь комірку».

Тепер ціна. Рекурсія триває лише у вузлах третього роду, а вузли перших двох родів — це їхні нащадки, тож їх щонайбільше вдвічі більше. Віддача піддерева гуртом коштує стільки, скільки в ньому вузлів: піддерево з j точками в листках має 2j − 1 вузлів, а всі такі піддерева разом містять рівно k точок відповіді — сумарно O(k).

Уся невідома частина ціни, отже, — це **кількість комірок, крізь які проходить межа вікна**. Далі рахуємо тільки її.

![Квадратне поле, поділене сіткою вісім на вісім комірок; поверх нього товстим червоним контуром намальоване прямокутне вікно запиту, сторони якого продовжені штриховими лініями через усе поле. Дев'ять комірок усередині вікна зафарбовані зеленим, шістнадцять комірок, крізь які проходить межа вікна, — блакитним, решта лишається білою. Праворуч три підписи: комірка цілком у вікні — усе піддерево у відповідь, разом це рівно k точок; комірка на межі — лише тут рекурсія триває, і саме таких комірок корінь із N; комірка поза вікном — одне порівняння і геть разом з усім піддеревом. Унизу: межа вікна лежить на чотирьох прямих, кожна ріже щонайбільше три корені з N мінус два комірок](img/window-cost.svg)
*Зелене й біле коштують по сталій на вузол; уся неочевидна робота — у блакитній облямівці.*

### Чому відповідь мусила бути коренем

Здогадку дає геометрія. На рівномірних даних листки збалансованого дерева з N точками вкладають квадрат приблизно як сітка √N × √N. Вертикальна пряма перетинає рівно один стовпчик такої сітки — тобто √N комірок. Логарифмові взятися нема звідки: логарифм — це **глибина** дерева, а ми міряємо **ширину зрізу**.

Ця ж сітка показує, що корінь не можна поліпшити. Візьміть N точок у вузлах сітки √N × √N і вікно у вигляді вузької вертикальної смуги на всю висоту квадрата, у якій немає жодної точки. Щоб відповісти «порожньо», доведеться зайти в усі √N комірок стовпчика. Оцінка Ω(√N) — властивість самого kd-дерева, а не задачі: інші просторові індекси відповідають на те саме питання за полілогарифм, платячи за це пам'яттю.

Лема нижче доводить верхню межу без жодних припущень про розташування точок.

### Лема про пряму

Нехай дерево збалансоване (кожен вузол ділить свої точки медіаною навпіл), осі чергуються, у листку одна точка. Q(n) — скільки комірок дерева з n точок перетинає одна вертикальна пряма ℓ: x = c. Комірки рахуємо всі, не лише листкові: кожна відповідає вузлу, у який обхід зайшов.

Спускаємось **на два рівні** — бо саме два рівні повертають дерево до тієї самої конфігурації.

Корінь ріже за x у точці s. Якщо c < s, пряма лежить цілком у лівій половині, а права не зачеплена — і жоден її нащадок теж, бо комірки нащадків вкладені в комірку батька. Один із двох. (Виродження c = s, коли пряма лягає на саму межу, міняє лише сталу: у будь-якій реалізації межа належить одному з боків.)

Перетнутий нащадок ріже за y. Обидві його половини мають ту саму ширину по x, що й він сам, тож пряма перетинає обидві. Два з двох.

Підсумок двох рівнів: перетнуто корінь і один його нащадок — два вузли; на другому рівні перетнуто дві комірки, і в кожній n/4 точок.

```
Q(n) = 2 + 2·Q(n/4),        Q(1) = 1
```

![Ліворуч квадратне поле: синя вертикальна лінія s ріже його за x, у кожній половині зелена горизонтальна лінія ріже її за y. Червона штрихова вертикальна пряма з підписом ель дорівнює ікс дорівнює це проходить лівою частиною поля; дві ліві чверті, які вона перетинає, зафарбовані зеленим і підписані n на чотири, а вся права половина сіра з підписом права половина не зачеплена. Праворуч те саме як дерево на три рівні: корінь ріже x, його лівий нащадок ріже y зелений, правий сірий, і два зелені онуки з написом n на чотири проти двох сірих. Унизу три підписи: розріз за x — пряма лежить строго в одній половині, друга не зачеплена зовсім; розріз за y — обидві половини мають ту саму ширину по x, тож пряма ріже обидві; через два рівні лишається дві комірки по n на чотири точок, звідки Q від n дорівнює два плюс два Q від n на чотири](img/stab-recurrence.svg)
*Два рівні ділять кількість точок на чотири, а кількість живих комірок множать лише на два. У цьому розходженні темпів і сидить корінь.*

### Розв'язок рекурентності

Розгортаємо. Хай n = 4^m, тобто m = log₄ n.

```
Q(4^m) = 2 + 2·Q(4^(m−1))
       = 2 + 2·2 + 4·Q(4^(m−2))
       = 2 + 4 + 8 + … + 2^m + 2^m·Q(1)
       = 2·(2^m − 1) + 2^m·Q(1)          ← геометрична сума
       = 3·2^m − 2                        ← Q(1) = 1
```

Лишається перекласти 2^m назад у n. Це найважливіший рядок усього рахунку:

```
2^m = 2^(log₄ n) = n^(log₄ 2) = n^(1/2) = √n
```

Отже

```
Q(n) = 3·√n − 2
```

**Перевірка підстановкою** — не «приблизно», а тотожно:

```
2 + 2·Q(n/4) = 2 + 2·(3·√(n/4) − 2)
             = 2 + 2·(1.5·√n − 2)
             = 2 + 3·√n − 4
             = 3·√n − 2 = Q(n)   ✓
Q(1) = 3 − 2 = 1                 ✓
```

**Ручний рахунок для малих дерев** — щоб не лишалося сумніву в базі:

```
n =  1:  Q = 1                   3·1 − 2 =  1   ✓
n =  4:  Q = 2 + 2·1  =  4       3·2 − 2 =  4   ✓
n = 16:  Q = 2 + 2·4  = 10       3·4 − 2 = 10   ✓
n = 64:  Q = 2 + 2·10 = 22       3·8 − 2 = 22   ✓
```

**Що на це каже головна теорема.** У формі Q(n) = a·Q(n/b) + f(n) маємо a = 2, b = 4, f(n) = Θ(1). Поріг — n^(log_b a) = n^(log₄ 2) = √n; стала функція росте повільніше за будь-який n^(1/2−ε), тож спрацьовує перший випадок і Q(n) = Θ(√n). [Основна теорема](topic:computability/master-theorem) дає той самий корінь за три рядки — але дає лише порядок. Сталої 3 в ній немає, а саме вона потрібна, щоб порівняти 3√N із N у конкретних числах. Загальні прийоми розгортання — у вставці [про рекурентності поділу навпіл](topic:sf-algorithms/divide-and-conquer/math-recurrence.md).

**Звідки корінь по суті.** Один крок рекурсії — це два рівні: кількість точок ділиться на 4, кількість живих комірок множиться на 2. Робота росте як 2 на кожні 4 точки, тобто Q ~ n^(log₄ 2) = n^(1/2). Корінь — це просто відношення двох темпів; якби пряма різала обидві половини на **кожному** рівні, було б Q(n) = 2 + 2·Q(n/2) = Θ(n), тобто повний перебір.

### Від однієї прямої до вікна

Межа прямокутника лежить на чотирьох прямих: двох вертикальних і двох горизонтальних. Для горизонтальних лема та сама з точністю до перейменування осей. Кожна комірка, крізь яку проходить межа, перетинається щонайменше однією з цих прямих, тож

```
комірок на межі ≤ 4·(3·√N − 2) < 12·√N
```

Стала груба: межа вікна є лише **частиною** цих прямих, а кутові комірки рахуються двічі. Порядок від цього не міняється, а нижня оцінка зі сітки показує, що поліпшити його не вийде. Разом із рахунком першого розділу:

```
ціна віконного запиту = O(√N) + O(k) = O(√N + k)
```

### d вимірів

Той самий спуск, тільки цикл осей довший. Пряму заміняє гіперплощина x₁ = c, а рівні ріжуть за осями x₁, x₂, …, x_d по черзі. Спускаємось на **d рівнів**.

На рівні, що ріже x₁, гіперплощина лежить строго з одного боку — один нащадок із двох. На кожному з решти d − 1 рівнів вона перетинає обидва: розріз за іншою віссю не міняє протяжності комірки вздовж x₁. Порахуймо перетнуті вузли зверху вниз:

```
рівень 0 (ріже x₁):  1 вузол  → 1 перетнутий нащадок
рівень 1:            1 вузол  → 2 нащадки
рівень 2:            2 вузли  → 4 нащадки
…
рівень j ≥ 1:        2^(j−1) вузлів

разом на рівнях 0…d−1:
1 + (1 + 2 + 4 + … + 2^(d−2)) = 1 + (2^(d−1) − 1) = 2^(d−1)
```

На рівні d перетнуто 2^(d−1) вузлів, у кожному n/2^d точок. Звідси

```
Q(n) = 2^(d−1) + 2^(d−1)·Q(n/2^d)
```

При d = 2 це знову 2 + 2·Q(n/4) — звірка сходиться. Розгортаємо так само; позначимо c = 2^(d−1), основа ділення b = 2^d, m = log_b n:

```
c^m = (2^(d−1))^(log_{2^d} n) = n^((d−1)/d) = n^(1−1/d)

Q(n) = (2c − 1)/(c − 1) · n^(1−1/d) − c/(c − 1)
```

Стала (2c − 1)/(c − 1) спадає від 3 при d = 2 до 7/3 при d = 3 і далі до 2. Граней у d-вимірного вікна 2d, тож остаточно

```
Q(N) = O(d · N^(1−1/d) + k)
```

Саме цю оцінку — з тією самою залежністю від d — довели Д. Т. Лі та Ч. К. Вонг у роботі «Worst-case analysis for region and partial region searches in multidimensional binary search trees and balanced quad trees» (Acta Informatica, том 9, 1977). Це доведена верхня межа для найгіршого випадку, а не середня оцінка.

### Числа, за якими видно межу

Мільйон точок, N = 10⁶:

```
d    N^(1−1/d)    на одну грань      граней   разом       від N
2    1.0·10³      3·10³ − 2 ≈ 3.0·10³    4     1.2·10⁴     1.2 %
3    1.0·10⁴      (7/3)·10⁴ ≈ 2.3·10⁴    6     1.4·10⁵      14 %
5    6.3·10⁴      (31/15)·… ≈ 1.3·10⁵   10     1.3·10⁶     130 %
```

Останній рядок не описка: при п'яти вимірах і мільйоні точок гарантія обіцяє більше роботи, ніж чесний перебір усіх N точок. Оцінка не бреше — вона просто перестає бути обіцянкою. Умова, за якої вона ще щось важить, виводиться в один рядок: сумарна робота 2d · 2 · N^(1−1/d) має бути меншою за N, звідки

```
N^(1/d) > 4d   ⟺   N > (4d)^d

d =  2:  8²   = 64
d =  3:  12³  = 1 728
d =  5:  20⁵  = 3.2·10⁶
d = 10:  40¹⁰ = 1.0·10¹⁶
d = 20:  80²⁰ = 1.2·10³⁸
```

Це [прокляття розмірності](topic:sf-algorithms/curse-of-dimensionality) у своїй найпростішій, суто арифметичній формі: потрібна кількість точок росте як d-й степінь, а зібрати їх нізвідки.

### Дрібна лема: комірка не витягується

Аналіз пошуку найближчого спирається на твердження «сторона комірки листка ≈ N^(−1/d)». Воно теж доводиться, і в дві дії.

**Дія перша, точна.** Спускаючись від кореня на L рівнів, ми проходимо осі по колу. Тому вісь a дістає ⌊L/d⌋ або ⌈L/d⌉ розрізів, і кількості розрізів у різних осей різняться щонайбільше на одиницю. Це чиста комбінаторика циклу, ніяких припущень про дані.

**Дія друга, з припущенням.** Медіана ділить навпіл **кількість точок**, а не довжину сторони. Для рівномірних даних одне збігається з другим тим точніше, чим більше точок у комірці; для витягнутих по діагоналі — не збігається взагалі, і саме там оцінка й розсипається. За рівномірних даних сторона вздовж осі a дорівнює 2^(−L_a), а показники L_a різняться не більш ніж на одиницю — тож відношення найдовшої сторони до найкоротшої не перевищує 2^1 = 2. Комірка не витягується в смугу — це і є та властивість, заради якої осі чергують.

Далі — арифметика коробки. Якщо у коробки об'єм V, а відношення сторін не більше за ρ, то

```
V = ∏ sₐ ≤ min · (ρ·min)^(d−1) = ρ^(d−1) · min^d   →   min ≥ V^(1/d) · ρ^(−(d−1)/d)
V = ∏ sₐ ≥ max · (max/ρ)^(d−1) = max^d / ρ^(d−1)   →   max ≤ V^(1/d) · ρ^((d−1)/d)
```

При ρ = 2 множник ρ^((d−1)/d) лежить між √2 і 2 за будь-якої розмірності. У листку одна точка, тож 2^L = N, а об'єм комірки в одиничному кубі V = 2^(−L) = 1/N і V^(1/d) = N^(−1/d). Кожна сторона комірки, отже, відрізняється від N^(−1/d) щонайбільше вдвічі — незалежно від d.

Ця ж формула пояснює, чому оцінка «сторона мала» перестає діяти саме тоді, коли перестає діяти віконна:

```
N = 10⁶:   d = 2  →  N^(−1/2) = 0.001
           d = 3  →  N^(−1/3) = 0.01
           d = 5  →  N^(−1/5) ≈ 0.063
           d = 20 →  N^(−1/20) ≈ 0.50
```

За двадцяти вимірів сторона комірки — половина світу по кожній осі. Обидві оцінки, кореневу й «сторона мала», ламає одне й те саме: на d осей припадає лише log₂N розрізів, і при великому d кожній осі дістається їх менш ніж жменя. Читати ці показники як обіцянку швидкості можна лише разом із перевіркою N > (4d)^d — інакше [O великого](topic:computability/asymptotic-complexity) сховає сталу, яка й вирішує справу.
