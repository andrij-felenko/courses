Сервер розпізнавання облич або семантичного пошуку містить базу даних із `10 000 000` векторів-дескрипторів розмірності `D = 512` (координати типу `float`, по 4 байти на число). Коли від користувача надходить запит — новий вектор ознак обличчя чи текстовий ембединг, — системі необхідно миттєво знайти запис із мінімальною відстанню до запиту. Прямий перебір вимагає обчислення відстані до кожного з 10 мільйонів векторів: це `10⁷ × 512 ≈ 5.12 × 10⁹` операцій множення з накопиченням та зчитування `20.48 ГБ` сирих даних з оперативної пам'яті. При максимальній пропускній здатності шини пам'яті сервера у `50 ГБ/с` один-єдиний запит триває понад 400 мілісекунд, що обмежує пропускну здатність машини мізерними 2.5 запитами на секунду замість необхідних для інтерактивних сервісів тисяч відповідей за 5–10 мілісекунд.

Спроба розв'язати цю проблему за аналогією з одновимірним числовим пошуком — де масив сортують і знаходять потрібне значення за `O(log N)` кроків через бінарний поділ — натикається на фундаментальну геометричну перешкоду. У багатовимірному просторі не існує природного лінійного порядку: вектор `(0, 10)` не є однозначно «меншим» або «більшим» за `(7, 7)`. Будь-яка структура даних, покликана прискорити пошук найближчого сусіда, змушена спиратися на геометричні та метричні властивості простору, групуючи близькі точки у просторові регіони та відсікаючи неперспективні області без прямого обчислення відстаней до кожного елемента.

### Задача найближчого сусіда: постановка та метричний простір

Нехай задано множину `S = {p₁, p₂, ..., p_N}` із `N` точок у метричному просторі `(M, d)` та точку запиту `q ∈ M`. Функція відстані `d(x, y)` задовольняє стандартні метричні аксіоми невід'ємності, симетрії та нерівності трикутника (найчастіше це евклідова відстань `L₂` або косинусна міра).

Задача пошуку найближчого сусіда (англ. *Nearest Neighbor Search*, NNS, лат. *vicinus* — сусідній) полягає у знаходженні точки `p* ∈ S`, яка мінімізує відстань до запиту `q`:

```
p* = argmin_{p ∈ S} d(q, p)
```

У практичних застосунках задачу майже завжди узагальнюють до пошуку `k` найближчих сусідів (k-NN), де алгоритм повертає підмножину `S_k ⊆ S` розміром `k`, для якої будь-яка точка всередині `S_k` ближча до `q`, ніж будь-яка точка за її межами:

```
∀ p ∈ S_k, ∀ p' ∈ (S \ S_k): d(q, p) ≤ d(q, p')
```

Історично ця проблема виникла ще у 1970-х роках під назвою «задача про поштові відділення», про що детально розповідає [історичний екскурс про походження задачі](root:sf-algorithms/nearest-neighbor-search/hist-post-office.md).

#### Метрики відстані та їхні алгебраїчні зв'язки

Вибір метрики визначається природою вхідних даних та типом простору ознак:

1. **Евклідова відстань `L₂` (Euclidean Distance)**:
   Геометрична довжина відрізка між двома точками в координатному просторі:
   ```
   d_L2(u, v) = √(∑_{i=1}^D (u[i] − v[i])²)
   ```
2. **Мангеттенська відстань `L₁` (Manhattan Distance)**:
   Сума абсолютних різниць координат уздовж осей:
   ```
   d_L1(u, v) = ∑_{i=1}^D |u[i] − v[i]|
   ```
3. **Косинусна відстань (Cosine Distance)**:
   Міра кутової розбіжності між двома напрямками векторів, незалежна від їхньої довжини ([детальніше про властивості косинусної міри](root:sf-algorithms/cosine-distance)):
   ```
   d_cos(u, v) = 1 − (u · v) / (||u|| · ||v||)
   ```
4. **Максимізація скалярного добутку (Maximum Inner Product Search, MIPS)**:
   Пошук вектора `v`, що максимізує скалярний добуток `u · v = ∑ u[i]·v[i]`. Не є метрикою у строгому сенсі (не виконується нерівність трикутника), але широко застосовується в рекомендаційних системах та матричних факторизаціях.

#### Зведення косинусної відстані до евклідової

Важливою практичною оптимізацією є попередня нормалізація всіх векторів бази даних та вектора запиту до одиничної евклідової довжини: `û = u / ||u||`, для якої `||û|| = 1`.

Розкриємо квадрат евклідової відстані між двома нормалізованими векторами:

```
||û − v̂||²
= ∑_{i=1}^D (û[i] − v̂[i])²
= ∑_{i=1}^D (û[i]² − 2·û[i]·v̂[i] + v̂[i]²)    [розкриття квадрата різниці]
= ∑ û[i]² + ∑ v̂[i]² − 2·∑ û[i]·v̂[i]          [перегрупування доданків]
= ||û||² + ||v̂||² − 2·(û · v̂)                [означення норми та скалярного добутку]
= 1 + 1 − 2·cos(θ)                            [оскільки ||û|| = 1, ||v̂|| = 1 та û·v̂ = cos(θ)]
= 2 − 2·cos(θ)                                [зведення подібних доданків]
= 2·(1 − cos(θ))                              [винесення спільного множника 2]
= 2·d_cos(u, v)                               [означення косинусної відстані]
```

Звідси випливає важливий практичний висновок: ранжування нормалізованих векторів за евклідовою відстанлю `||û - v̂||²` дає **абсолютно ідентичний порядок сусідів**, що й за косинусною мірою `d_cos(u, v)`. Це дозволяє використовувати будь-які просторові дерева та графічні індекси, спроєктовані під евклідову метрику, для косинусного пошуку без жодних модифікацій.

### Лінійний точний перебір (Flat Brute-Force Scan)

Найпростішим і найнадійнішим способом знаходження найближчого сусіда є послідовний перебір усіх `N` елементів множини `S`. Алгоритм підтримує поточну мінімальну відстань `d_min` та ідентифікатор найкращого знайденого кандидата. Для кожної точки `p_i` обчислюється відстань `d(q, p_i)`. Якщо вона менша за `d_min`, значення оновлюється.

```
Часова складність запиту:    O(N · D)
Просторова складність:       O(N · D)  [лише зберігання масиву точок]
Додаткова пам'ять індексу:   O(1)
Точність (Recall):           100%      [гарантовано точний глобальний мінімум]
```

Для пошуку `k` сусідів сканер використовує чергу з пріоритетом (макс-купу) фіксованої місткості `k`. Корінь купи містить кандидата з найбільшою відстанню серед поточних `k` найкращих. Якщо нова обчислена відстань менша за значення в корені, найгірший елемент виштовхується, а новий вставляється за `O(log k)` кроків.

#### Апаратні переваги лінійного сканування

Попри асимптотичну лінійність за кількістю точок `O(N)`, лінійний перебір володіє безпрецедентною ефективністю взаємодії з апаратною архітектурою сучасних CPU та GPU:

1. **Суцільне розміщення в пам'яті (Contiguous Memory Layout)**: Усі координати зберігаються в єдиному пласкому масиві `float data[N * D]`. Під час обходу процесор виконує чисте потокове читання (англ. *streaming read*). Апаратний блок випереджального читання (англ. *hardware prefetcher*) завчасно завантажує наступні кеш-лінії, що зводить затримки пам'яті DRAM майже до нуля.
2. **SIMD-векторизація**: Обчислення евклідової відстані між двома векторами зводиться до попарного віднімання координат, піднесення різниць до квадрата та їхнього підсумовування (операція Multiply-Accumulate). Інструкції AVX-512 або ARM NEON обробляють 16 чисел `float` за один процесорний такт, задіюючи векторні FMA-блоки ядер на 95–99% від теоретичного піку.
3. **Оптимізація без кореня**: Для порівняння відстаней немає потреби викликати дорогу інструкцію `sqrt()`, оскільки функція квадрата є строго монотонною для додатних чисел: `d(q, a) < d(q, b) ⇔ d²(q, a) < d²(q, b)`.

Коли розмір бази невеликий (`N ≤ 50 000`), оптимізований SIMD-сканер на практиці працює швидше за будь-які складні просторові індекси завдяки нульовим накладним витратам на керування вказівниками та розгалуженнями.

#### Пакетна обробка та блокування в кеші (Batch GEMM)

Коли запити надходять пачками по `B` штук (наприклад, `B = 64..256`), задачу пошуку скалярного добутку між матрицею запитів `Q` розміром `B × D` та матрицею бази даних `X` розміром `N × D` можна сформулювати як множення щільних матриць (англ. *General Matrix Multiply*, GEMM):

```
S = Q × X^T
```

Сучасні математичні бібліотеки (BLAS, OpenBLAS, Intel MKL) розбивають матриці на невеликі блоки (англ. *cache tiling*), які повністю поміщаються у швидкісному кеші L2/L1. Кожен елемент бази даних зчитується з повільної оперативної пам'яті лише один раз і багаторазово перемножується з усіма `B` векторами запиту, що підіймає пропускну здатність CPU до сотень гігафлопсів та забезпечує понад 100 000 QPS на одному сервері.

### Просторове розбиття та точне індексування в низьких вимірах

Коли кількість точок зростає до мільйонів, лінійний перебір `O(N)` стає надто повільним. Для прискорення пошуку простір розбивають на геометричні регіони, будуючи деревоподібну ієрархію (англ. *spatial index*). 

Головна мета індексу — **відсікання** (англ. *pruning*): здатність за одне порівняння довести, що цілий геометричний кластер, який містить мільйони точок, не може містити жодного елемента, ближчого за вже знайденого кандидата.

#### Нерівність трикутника як інструмент відсікання

В основі метричного відсікання лежить зворотна нерівність трикутника. Нехай у просторі обрано фіксовану опорну точку `P` (англ. *pivot* або *vantage point*), а множину точок бази розбито на дві частини відносно сфери радіуса `R_split`: внутрішню (точки `x`, де `d(P, x) ≤ R_split`) та зовнішню (`d(P, x) > R_split`).

Нехай поточний найкращий знайдений кандидат віддалений від запиту `q` на відстань `r = d_min`. Якщо запит `q` розташований так, що нижня межа відстані до будь-якої точки всередині сфери перевищує `r`:

```
d(q, P) − R_split > r
```

то за нерівністю трикутника для будь-якої внутрішньої точки `x` гарантовано виконується:

```
d(q, x) ≥ d(q, P) − d(P, x) ≥ d(q, P) − R_split > r
```

Це математично гарантує, що все внутрішнє піддерево можна відкинути без обчислення відстаней до його точок. Повне строге виведення прямих і зворотних меж для довільних метрик містить [математична вставка про межі нерівності трикутника](root:sf-algorithms/nearest-neighbor-search/math-triangle-bounds.md).

![Геометричне відтинання пошуку за нерівністю трикутника](/root/eng/sf-algorithms/nearest-neighbor-search/img/exact-partition-pruning.svg)
*Геометричне відсікання простору за нерівністю трикутника: якщо відстань від запиту q до межі розбиття опорної точки P перевищує поточний радіус пошуку r, усе внутрішнє піддерево безпечно відкидається.*

#### Родини точних просторових дерев

У просторах низької розмірності (`D = 2, 3, 4`) застосовують кілька класичних структур розбиття:

1. **KD-дерева (k-d trees)**: Ієрархічно розділяють простір гіперплощинами, що паралельні координатним осям, чергуючи осі на кожному рівні дерева ([детальний розбір алгоритму KD-дерева](root:sf-algorithms/kd-tree)). Запит спускається до відповідного листка, знаходить першого кандидата, а потім під час зворотного ходу (бекґтрекінгу) перевіряє, чи перетинає сфера радіуса `r` розділові гіперплощини.
2. **R-дерева (R-trees / R*-trees)**: Групують об'єкти в ієрархічні прямокутні обмежувальні паралелепіпеди (англ. *Minimum Bounding Boxes*, MBR, [довідка про структуру R-дерева](root:sf-algorithms/r-tree)). Дерево оптимізоване для дискового збереження та геоінформаційних систем (GIS).
3. **Метричні дерева (VP-trees, Ball-trees)**: Розбивають простір гіперсферами навколо опорних точок. Працюють у довільних метричних просторах, де немає координат, а доступна лише функція відстані `d(x, y)` між об'єктами.

У двовимірному просторі ці дерева забезпечують пошук найближчого сусіда в середньому за `O(log N)` операцій.

### Прокляття розмірності та крах точного індексування

Щойно розмірність даних `D` зростає від 2–3 до 50, 128 чи 512 (типові розмірності векторних ембедингів у машинному навчанні), просторові дерева зазнають катастрофічного колапсу продуктивності, відомого як «прокляття розмірності» ([теоретичне пояснення прокляття розмірності](root:sf-algorithms/curse-of-dimensionality)).

#### Геометричні причини розпаду

1. **Експоненційне зростання кількості клітинок**: Для розбиття простору вздовж кожної координати хоча б навпіл у `D`-вимірному просторі потрібно `2^D` областей. При `D = 64` число областей становить `2⁶⁴ ≈ 1.84 × 10¹⁹`, що унеможливлює локалізацію точок.
2. **Концентрація об'єму в кутах гіперкуба**: Об'єм одиничної гіперсфери `V_sphere(D) = π^(D/2) / Γ(D/2 + 1)` при зростанні `D` стрімко прямує до нуля порівняно з об'ємом описаного гіперкуба `V_cube = 2^D`. При `D = 20` сфера займає менше `0.000025%` об'єму куба. Це означає, що майже весь простір зосереджений у віддалених «кутах» гіперкуба.
3. **Концентрація міри та зникнення контрасту відстаней**: У високовимірному просторі майже весь об'єм гіперсфери зосереджений у тонкому поверхневому шарі біля її межі. Як наслідок, відстані між довільними парами випадкових точок стають майже однаковими. Відношення між відстанню до найвіддаленішого сусіда та найближчого прямує до одиниці:

```
lim_{D → ∞} (d_max − d_min) / d_min = 0
```

4. **Неминучі перетини меж**: Оскільки відстань `r` до найближчого сусіда стає майже такою ж великою, як і відстань до середньої точки бази, сфера пошуку радіуса `r` навколо запиту `q` неминуче перетинає майже **всі** розділові гіперплощини або обмежувальні паралелепіпеди дерева.

![Прокляття розмірності та розпад просторового індексування](/root/eng/sf-algorithms/nearest-neighbor-search/img/curse-of-dimensionality-search.svg)
*Прокляття розмірності: у 2D сфера запиту локалізована в одній клітинці (відсікання 95%+), а у високих вимірах сфера розширюється і перетинає всі гіперплощини, змушуючи дерево обходити майже 100% листків.*

#### Системні наслідки для продуктивності

Під час виконання запиту алгоритм обходу дерева змушений розкривати майже кожну гілку через бекґтрекінг (англ. *backtracking*). Кількість відвіданих точок наближається до `N` (перевіряється 90–99% бази).

Але на відміну від лінійного сканера, який читає суцільний масив пам'яті через SIMD, дерево виконує хаотичні стрибки за вказівниками між вузлами у пам'яті. Кожен стрибок викликає промах кешу L1/L2 (англ. *cache miss*) та помилку передбачення переходів конвеєра CPU (англ. *branch misprediction*).

В результаті при `D ≥ 64` точне KD-дерево чи VP-дерево працює у **10–50 разів повільніше**, ніж звичайний лінійний перебір усіх точок поспіль. Порівняльний код та реальні виміри наведені у [практичному проекті реалізації лінійного скану проти VP-дерева](root:sf-algorithms/nearest-neighbor-search/proj-exact-vs-ann.md).

### Парадигма наближеного пошуку найближчого сусіда (ANN)

Оскільки точний пошук найближчого сусіда у високих вимірах принципово не піддається суб-лінійному прискоренню в найгіршому випадку, інженерія пішла на компроміс: відмову від абсолютної гарантії 100% точності на користь колосального прискорення.

Так народився наближений пошук найближчого сусіда (англ. *Approximate Nearest Neighbor Search*, ANN, лат. *approximare* — наближати).

У формулюванні `(1 + ε)`-ANN користувач задає допустимий коефіцієнт наближення `ε > 0`. Алгоритм зобов'язаний повернути таку точку `p_ann ∈ S`, відстань від якої до запиту `q` перевищує істинну мінімальну відстань `d(q, p*)` не більше ніж у `(1 + ε)` разів:

```
d(q, p_ann) ≤ (1 + ε) · d(q, p*)
```

У реальних прикладних задачах (семантичний пошук, рекомендаційні системи, біометрія) ембединги самі по собі є наближеними статистичними моделями. Отримання 2-го чи 3-го найближчого сусіда замість 1-го з відстанню 0.12 замість 0.11 ніяк не впливає на кінцеву якість користувацького досвіду, але скорочує час обробки запиту з 400 мілісекунд до 0.5 мілісекунди (прискорення у 800 разів).

#### Чотири осі інженерного компромісу

Оцінка будь-якого індексу наближеного пошуку спирається на чотири взаємопов'язані параметри:

1. **Точність пошуку (Recall@k)**: Частка справжніх `k` найближчих сусідів, які алгоритм зміг знайти:
   ```
   Recall@k = |Знайдені_k ∩ Істинні_k| / k
   ```
   У промислових системах цільовий показник зазвичай становить `Recall@10 ≥ 0.90..0.98`.
2. **Швидкість запиту (Latency та Throughput / QPS)**: Затримка відповіді в мікросекундах та кількість запитів, які сервер може обробити за секунду.
3. **Витрати оперативної пам'яті (Memory Footprint)**: Скільки байтів пам'яті RAM припадає на один збережений вектор разом із допоміжними графовими чи деревними ребрами.
4. **Швидкість побудови та оновлення (Build & Insert Time)**: Скільки часу потрібно для побудови індексу на 10 мільйонах векторів і чи підтримує індекс динамічне додавання точок без повної перебудови.

*Чотиристоронній інженерний компроміс систем векторного пошуку: порівняння точного сканування, графового індексу HNSW та квантування IVF-PQ.*

### Таксономія сучасних алгоритмів наближеного пошуку

Усі сучасні індекси наближеного пошуку поділяються на чотири головні алгоритмічні родини.

![Чотири родини індексів наближеного пошуку](/root/eng/sf-algorithms/nearest-neighbor-search/img/ann-taxonomy-methods.svg)
*Таксономія чотирьох головних родин наближеного векторного пошуку: дерева випадкових проєкцій, локально чутливе хешування, продуктове квантування та графи малого світу.*

#### 1. Дерева та випадкові проєкції (Random Projection Trees)

Замість використання вихідних координат для розбиття простору беруть випадкові гіперплощини.
- **Алгоритм Annoy (Approximate Nearest Neighbors Oh Yeah)**: Обирає дві випадкові точки, будує між ними розділову гіперплощину і рекурсивно ділить простір, створюючи бінарне дерево. Щоб компенсувати випадкові помилки на межах розбиття, алгоритм будує ліс із 50–100 незалежних випадкових дерев.
- **Пошук**: Запит спускається по кожному з дерев лісу в листки, формуючи спільний пул кандидатів (англ. *candidate queue*), після чого виконується точний перерахунок відстаней лише для кількох сотень відібраних точок.

#### 2. Локально чутливе хешування (Locality-Sensitive Hashing, LSH)

Концепція спирається на спеціальні сімейства хеш-функцій, для яких імовірність колізії монотонно зростає при зменшенні геометричної відстані між векторами ([повний опис сімейств LSH](root:sf-algorithms/locality-sensitive-hashing)):

```
P[h(u) = h(v)] = f(d(u, v))
```

Точки з високою схожістю з високою ймовірністю потрапляють в один хеш-бакет. Запит обчислює кілька хеш-кодів, дістає об'єкти з відповідних кошиків і перевіряє лише їх. LSH володіє суворими математичними гарантіями складності, але вимагає зберігання багатьох хеш-таблиць, що збільшує накладні витрати пам'яті.

#### 3. Квантування та інвертовані файли (IVF-PQ та SQ8)

Методи квантування орієнтовані на граничне стиснення даних, дозволяючи тримати мільярдні бази векторів у RAM одного сервера (основа бібліотеки Faiss від Meta):

- **Скалярне квантування (Scalar Quantization, SQ8)**:
  Кожне 32-бітне число `float` відображається в 8-бітне беззнакове ціле `uint8_t` через лінійне масштабування між мінімумом та максимумом координати:
  ```
  x_quant = round(255 · (x − min_val) / (max_val − min_val))
  ```
  Дає точне стиснення в 4 рази із мінімальною втратою точності та дозволяє використовувати надшвидкі цілочисельні SIMD-інструкції `_mm256_maddubs_epi16`.

- **Продуктове квантування (Product Quantization, PQ)**:
  Вектор розрізається на `M` підвекторів (наприклад, `D = 128` розбивають на `M = 16` частин по 8 чисел). Для кожного підпростору навчається своя кодова книга (англ. *codebook*) із 256 підцентроїдів. У результаті вихідний 512-байтовий вектор стискається у **16 байтів** (16 однобайтових індексів центроїдів).

- **Асиметричне обчислення відстаней (Asymmetric Distance Computation, ADC)**:
  Під час запиту відстань від вихідного неквантованого вектора `q` до центроїдів усіх підпросторів обчислюється лише один раз і записується в таблицю розміром `16 × 256` чисел `float`. Оцінка відстані до будь-якого квантованого вектора бази виконується за 16 операцій додавання значень із таблиці за індексами без жодного множення, що прискорює пошук у 50–100 разів.

- **Залишкове квантування (Residual Quantization, IVF-PQ-Residual)**:
  Замість квантування сирого вектора `x` квантується залишковий вектор помилки `r = x − C_i`, де `C_i` — центроїд найближчого кластера IVF. Оскільки залишки мають на порядок меншу дисперсію, ніж сирі вектори, точність відновлення відстаней кардинально зростає.

#### 4. Графи близькості та малого світу (HNSW / DiskANN)

Найшвидший і найточніший клас алгоритмів у сучасних векторних базах даних (Milvus, Qdrant, Weaviate):

- **Hierarchical Navigable Small World (HNSW)**:
  Будує багатошаровий граф, де кожна точка є вершиною. Верхні шари містять розріджені довгі ребра для швидкої глобальної навігації простором (аналог Skip-List у геометрії), а нижні шари — густу мережу локальних ребер між близькими сусідами.

- **Евристика відбору ребер (Heuristic Neighbor Selection)**:
  Щоб граф не перевантажувався надлишковими паралельними ребрами, використовують правило відносного графа сусідства (Relative Neighborhood Graph, RNG): нове ребро до вершини `v` додається лише тоді, коли `v` ближча до базової точки `u`, ніж до будь-якого вже підключеного сусіда `w`:
  ```
  d(u, v) < d(w, v)
  ```
  Це забезпечує рівномірне просторове покриття у всіх кутових напрямках і запобігає кластеризації ребер.

- **Динамічний пошук та параметри налаштування**:
  Алгоритм стартує з точки входу верхнього шару і жадібно переходить до сусіда, найближчого до запиту. Досягши локального мінімуму, він спускається на шар нижче і повторює жадібний спуск. Параметр ширини променя `efSearch` дозволяє безпосередньо керувати балансом між затримкою та точністю (при `efSearch = 64..128` досягається `Recall@10 ≥ 98..99%`).

- **Дискові графи (DiskANN / Vamana Graph)**:
  Коли розмір бази перевищує обсяг оперативної пам'яті сервера (наприклад, 1 мільярд векторів вимагає понад 3 ТБ RAM), використовують пласкі дискові графи Vamana. Списки суміжності розбиваються на сектори розміром по 4 КБ, оптимізовані під сторінки читання NVMe SSD. Запит виконує лише 3–5 паралельних прямих асинхронних звернень до SSD через Linux `io_uring`, обслуговуючи запит за 2–3 мілісекунди без зберігання графів у пам'яті.

Для уніфікації роботи з різними типами рушіїв розробляють стандартизовані API, специфікацію яких наведено у [довідці програмного інтерфейсу індексу](root:sf-algorithms/nearest-neighbor-search/api-nn-index.md).

### Гібридний пошук: фільтрація метаданих разом із векторами

У практичних застосунках векторний запит майже завжди супроводжується фільтрами метаданих (наприклад: *«знайти 5 семантично найближчих товарів із ціною < 1000 грн у категорії Одяг»*).

Існує три стратегії поєднання векторного індексу та фільтрів:

1. **Попередня фільтрація (Pre-Filtering)**: Спершу за реляційним індексом відбираються всі ID, що відповідають предикату (наприклад, 200 товарів), після чого серед них виконується лінійний SIMD-перебір. Підхід ідеальний, коли фільтр залишає невелику кількість об'єктів (< 10 000).
2. **Подальша фільтрація (Post-Filtering)**: Спершу графовий індекс повертає `k = 100` найближчих векторів, після чого невідповідні відкидаються. Підхід катастрофічно ламається, якщо під фільтр підпадає лише 1% бази: із 100 знайдених векторів після фільтрації може залишитися 0 результатів.
3. **Однопрохідна ітеративна фільтрація у графі (Single-Stage Filtered Traversal)**: Під час жадібного обходу графа HNSW алгоритм перевіряє бітову маску (англ. *bitset / roaring bitmap*) валідних ID. Вершини, що не відповідають фільтру, можуть використовуватися як проміжні транзитні мости для навігації, але не додаються до черги фінальних результатів.

### Динамічні зміни: видалення та оновлення в індексах

У виробничих базах даних постійно відбуваються операції додавання та видалення документів. Керування змінами має специфічні особливості для кожного типу індексу:

- **М'яке видалення (Tombstones)**: Видалений вектор позначається бітовим прапорцем у таблиці і миттєво ігнорується при пошуку. Проте у графі HNSW вершина залишається як маршрутний вузол, щоб не розривати зв'язність графа.
- **Фонове очищення (Vacuuming / Re-linking)**: Періодичний фоновий потік видаляє помічені вершини та перепідключає їхніх сусідів за правилом RNG, запобігаючи деградації структури графа («гниттю ребер»).
- **Сегментна архітектура (LSM-подібні сегменти)**: За аналогією з базами даних LSM-Tree (Log-Structured Merge-tree), нові вектори пишуться у швидкий плаский буфер у пам'яті (MemTable), який при досягненні ліміту конвертується в новий незмінний HNSW-сегмент. Фоновий процес зливає старі сегменти у великий глобальний граф.

### Реалізація: точний Flat-пошук та маршрутизація за центроїдами

Покажемо базову реалізацію інвертованого векторного сканера (IVF-Flat) двома мовами. Алгоритм розбиває базу на кластери і під час пошуку перевіряє вектори лише найближчих центроїдів (`n_probe`), поєднуючи високу швидкість із компактністю.

:::tabs
```c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <float.h>

typedef struct {
    int id;
    float *vector;
} ivf_entry_t;

typedef struct {
    float *centroid;
    ivf_entry_t *entries;
    size_t count;
    size_t capacity;
} ivf_cluster_t;

typedef struct {
    ivf_cluster_t *clusters;
    size_t num_clusters;
    int dim;
} ivf_index_t;

/* Обчислення квадрата евклідової відстані */
static inline float l2_sq(const float *a, const float *b, int dim) {
    float sum = 0.0f;
    for (int i = 0; i < dim; ++i) {
        float diff = a[i] - b[i];
        sum += diff * diff;
    }
    return sum;
}

/* Пошук найближчого сусіда через опитування n_probe найближчих центроїдів */
int ivf_search_nearest(const ivf_index_t *index, const float *query,
                       size_t n_probe, float *out_dist) {
    if (!index || index->num_clusters == 0) return -1;
    if (n_probe > index->num_clusters) n_probe = index->num_clusters;

    /* 1. Знаходимо відстані до всіх центроїдів кластерів */
    float *c_dists = (float *)malloc(index->num_clusters * sizeof(float));
    size_t *c_indices = (size_t *)malloc(index->num_clusters * sizeof(size_t));

    for (size_t i = 0; i < index->num_clusters; ++i) {
        c_dists[i] = l2_sq(query, index->clusters[i].centroid, index->dim);
        c_indices[i] = i;
    }

    /* 2. Простий вибір n_probe найменших центроїдів (часткове сортування вибором) */
    for (size_t i = 0; i < n_probe; ++i) {
        size_t min_idx = i;
        for (size_t j = i + 1; j < index->num_clusters; ++j) {
            if (c_dists[j] < c_dists[min_idx]) min_idx = j;
        }
        float tmp_d = c_dists[i]; c_dists[i] = c_dists[min_idx]; c_dists[min_idx] = tmp_d;
        size_t tmp_i = c_indices[i]; c_indices[i] = c_indices[min_idx]; c_indices[min_idx] = tmp_i;
    }

    /* 3. Скануємо вектори лише всередині відібраних n_probe кластерів */
    int best_id = -1;
    float best_dist_sq = FLT_MAX;

    for (size_t p = 0; p < n_probe; ++p) {
        const ivf_cluster_t *cl = &index->clusters[c_indices[p]];
        for (size_t j = 0; j < cl->count; ++j) {
            float d = l2_sq(query, cl->entries[j].vector, index->dim);
            if (d < best_dist_sq) {
                best_dist_sq = d;
                best_id = cl->entries[j].id;
            }
        }
    }

    free(c_dists);
    free(c_indices);

    if (out_dist) *out_dist = sqrtf(best_dist_sq);
    return best_id;
}
```

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>
#include <limits>
#include <span>
#include <numeric>

struct VectorEntry {
    int id{0};
    std::vector<float> data;
};

struct Cluster {
    std::vector<float> centroid;
    std::vector<VectorEntry> entries;
};

class IvfFlatIndex {
public:
    explicit IvfFlatIndex(int dimension, size_t num_clusters)
        : dim_(dimension), clusters_(num_clusters) {
        for (auto& cl : clusters_) {
            cl.centroid.resize(dim_, 0.0f);
        }
    }

    void set_centroid(size_t cluster_idx, std::span<const float> centroid_coords) {
        if (cluster_idx < clusters_.size() && centroid_coords.size() == static_cast<size_t>(dim_)) {
            std::copy(centroid_coords.begin(), centroid_coords.end(), clusters_[cluster_idx].centroid.begin());
        }
    }

    void add_vector(int id, std::span<const float> vec, size_t cluster_idx) {
        if (cluster_idx < clusters_.size()) {
            clusters_[cluster_idx].entries.push_back(VectorEntry{id, {vec.begin(), vec.end()}});
        }
    }

    [[nodiscard]] std::pair<int, float> search_nearest(std::span<const float> query, size_t n_probe) const {
        if (clusters_.empty()) return {-1, std::numeric_limits<float>::infinity()};
        n_probe = std::min(n_probe, clusters_.size());

        // 1. Обчислюємо відстані до всіх центроїдів
        std::vector<std::pair<float, size_t>> centroid_dists;
        centroid_dists.reserve(clusters_.size());

        for (size_t i = 0; i < clusters_.size(); ++i) {
            centroid_dists.emplace_back(l2_sq(query, clusters_[i].centroid), i);
        }

        // 2. Часткове сортування: знаходимо n_probe найкращих кластерів
        std::nth_element(centroid_dists.begin(), centroid_dists.begin() + n_probe, centroid_dists.end());

        // 3. Скануємо вектори лише відібраних кластерів
        int best_id = -1;
        float best_dist_sq = std::numeric_limits<float>::max();

        for (size_t p = 0; p < n_probe; ++p) {
            const auto& cluster = clusters_[centroid_dists[p].second];
            for (const auto& entry : cluster.entries) {
                float d = l2_sq(query, entry.data);
                if (d < best_dist_sq) {
                    best_dist_sq = d;
                    best_id = entry.id;
                }
            }
        }

        return {best_id, std::sqrt(best_dist_sq)};
    }

private:
    int dim_{0};
    std::vector<Cluster> clusters_;

    [[nodiscard]] static float l2_sq(std::span<const float> a, std::span<const float> b) noexcept {
        float sum = 0.0f;
        for (size_t i = 0; i < a.size(); ++i) {
            float diff = a[i] - b[i];
            sum += diff * diff;
        }
        return sum;
    }
};
```

> 🔧 **Навіщо це.**
> Пошук найближчого сусіда є головним обчислювальним рушієм усіх сучасних систем штучного інтелекту та аналізу даних:
> 1. **Retrieval-Augmented Generation (RAG) та семантичний пошук**: Документи бази знань розбиваються на фрагменти і кодуються нейромережею у вектори. При запиті користувача модель шукає 5 найближчих фрагментів у векторній базі за частки мілісекунди і передає їх у контекст мовної моделі.
> 2. **Рекомендаційні системи**: Товари, музичні треки та користувачі представляються прихованими векторами уподобань. Пошук найближчого сусіда миттєво підбирає персоналізований контент серед каталогу з 100 мільйонів найменувань.
> 3. **Біометрична ідентифікація**: Векторні зліпки обличчя чи голосу порівнюються з мільйонними реєстрами для миттєвої верифікації без повного сканування бази даних.

### Матриця вибору архітектурного рішення

| Сценарій та параметри | Рекомендований підхід | Причина вибору |
|---|---|---|
| `N ≤ 50 000`, довільна розмірність `D` | **Flat Brute-Force (SIMD)** | Нульова пам'ять на індекс, відсутність оверхеду на побудову, максимальна локальність кешу. |
| `D ≤ 8`, довільна кількість `N` | **KD-дерево / R-дерево** | Логарифмічний час пошуку `O(log N)` без прокляття розмірності, 100% гарантія точності. |
| `N > 100 000`, `D ≥ 64`, пріоритет — швидкість і точність (`Recall ≥ 95%`) | **HNSW (Графовий індекс)** | Найвища пропускна здатність (10 000+ QPS) при збереженні максимальної точності за рахунок пам'яті під ребра. |
| `N ≥ 10 000 000`, жорсткі обмеження RAM сервера | **IVF-PQ (Продуктове квантування)** | Стиснення бази векторів до 90–95%, швидкий асиметричний підрахунок відстаней через таблиці пошуку. |
| База з постійним потоком видалень та оновлень | **IVF-Flat або динамічний HNSW з tombstones** | Простота маркування видалених записів без тривалої повної перебудови графових шарів. |
