# 📋 Інтерфейс та API квошієнтного фільтра: сигнатури, інваріанти та контракт взаємодії

Ця довідкова специфікація визначає публічний контракт інтерфейсу квошієнтного фільтра для мов C та C++. Контракт регламентує типи даних, сигнатури функцій, коди завершення, часову складність, протокол ітерації по збережених відбитках, вимоги до апаратного вирівнювання пам'яті, гарантії виняткобезпеки та системні інваріанти структури.

## 1. Типи даних та структури метаданих

Квошієнтний фільтр спирається на фіксовану розрядність бітових полів слота. Метадані кожного слота містять три однобітні прапорці стану (`is_occupied`, `is_continuation`, `is_shifted`) та числовий залишок `remainder` розрядністю `r` бітів.

:::tabs
```c
#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

typedef struct {
    uint8_t is_occupied : 1;      /* 1, якщо слот є канонічним для хоча б одного елемента */
    uint8_t is_continuation : 1;  /* 1, якщо елемент продовжує набіг попереднього слота */
    uint8_t is_shifted : 1;       /* 1, якщо елемент зміщено вправо від канонічного слота */
    uint8_t remainder : 5;        /* Залишок хеш-коду (розмір r бітів) */
} QFSlot;

typedef struct {
    QFSlot *table;                /* Масив слотів розміром num_slots */
    size_t q_bits;                /* Кількість бітів частки (q) */
    size_t r_bits;                /* Кількість бітів залишку (r) */
    size_t num_slots;             /* Загальна кількість слотів m = 2^q */
    size_t slot_mask;             /* Бітова маска індексації (num_slots - 1) */
    size_t count;                 /* Поточна кількість збережених елементів (n) */
} QuotientFilter;
```
```cpp
#include <cstdint>
#include <cstddef>
#include <vector>
#include <string_view>
#include <optional>
#include <span>
#include <memory>

namespace filters {

class QuotientFilter {
public:
    struct Slot {
        uint8_t is_occupied : 1 = 0;
        uint8_t is_continuation : 1 = 0;
        uint8_t is_shifted : 1 = 0;
        uint8_t remainder : 5 = 0;
    };

    static constexpr double kDefaultMaxLoadFactor = 0.85;

    explicit QuotientFilter(size_t q_bits, size_t r_bits);
    ~QuotientFilter() = default;

    QuotientFilter(const QuotientFilter&) = delete;
    QuotientFilter& operator=(const QuotientFilter&) = delete;
    QuotientFilter(QuotientFilter&&) noexcept = default;
    QuotientFilter& operator=(QuotientFilter&&) noexcept = default;

    [[nodiscard]] bool contains(std::string_view key) const noexcept;
    bool insert(std::string_view key);
    bool remove(std::string_view key) noexcept;

    [[nodiscard]] size_t size() const noexcept;
    [[nodiscard]] size_t capacity() const noexcept;
    [[nodiscard]] double load_factor() const noexcept;
    [[nodiscard]] bool empty() const noexcept;
    void clear() noexcept;

private:
    size_t q_bits_;
    size_t r_bits_;
    size_t num_slots_;
    size_t slot_mask_;
    size_t count_ = 0;
    std::vector<Slot> table_;
};

} // namespace filters
```

## 2. Специфікація керування життєвим циклом

Створення та знищення фільтра контролюють виділення монолітного блоку динамічної пам'яті для збереження таблиці слотів. Для забезпечення максимальної продуктивності на сучасних процесорах з 64-байтовими лініями кешу пам'ять таблиці рекомендується вирівнювати за межею 64 байтів.

### Створення та знищення фільтра

:::tabs
```c
/* Виділення пам'яті та ініціалізація структури фільтра */
QuotientFilter *qf_create(size_t q_bits, size_t r_bits);

/* Повне звільнення пам'яті таблиці та структури */
void qf_destroy(QuotientFilter *qf);

/* Очищення вмісту без перерозподілу пам'яті */
void qf_clear(QuotientFilter *qf);
```
```cpp
/* Конструктор із виділенням пам'яті під 2^q слотів */
explicit QuotientFilter::QuotientFilter(size_t q_bits, size_t r_bits);

/* Очищення всіх слотів та скидання лічильника */
void QuotientFilter::clear() noexcept;
```
:::

- **`qf_create(q_bits, r_bits)` / `QuotientFilter(q_bits, r_bits)`**:
  - **Предумови**: `q_bits ≥ 1`, `r_bits ≥ 1`, сума `q_bits + r_bits ≤ 64`.
  - **Постумови**: Виділяє суцільний буфер на `2^q` слотів, ініціалізований нулями. Поле `count` встановлюється в `0`.
  - **Поведінка при помилці**: У мові C повертає `NULL` у разі нестачі оперативної пам'яті. У C++ генерує стандартний виняток `std::bad_alloc`.
  - **Часова складність**: `O(2^q)` для початкового обнулення пам'яті (виклик `calloc` або конструктора вектора).
  - **Просторова складність**: `O(2^q · (r + 3))` бітів.

- **`qf_destroy(qf)` / деструктор**:
  - Звільняє виділену динамічну пам'ять масиву слотів. У C++ виконується автоматично завдяки принципу RAII при виході об'єкта з області видимості.

- **`qf_clear(qf)` / `clear()`**:
  - Скидає всі слоти в нульовий стан за допомогою `memset` або заповнення значеннями за замовчуванням, скидає лічильник `count = 0`. Пам'ять таблиці залишається виділеною для повторного використання.

## 3. Специфікація операцій запитів та модифікацій

Основні операції фільтра забезпечують перевірку належності елемента множині, додавання нових ключів та детерміноване видалення без побічних ефектів.

:::tabs
```c
/* Перевірка наявності ключа: повертає true, якщо ключ можливо є, false якщо гарантовано відсутній */
bool qf_lookup(const QuotientFilter *qf, const void *key, size_t len);

/* Вставка нового ключа: повертає true при успіху, false при переповненні */
bool qf_insert(QuotientFilter *qf, const void *key, size_t len);

/* Видалення ключа: повертає true, якщо знайдено й видалено, false якщо елемент був відсутній */
bool qf_delete(QuotientFilter *qf, const void *key, size_t len);
```
```cpp
/* Перевірка наявності ключа у множині */
[[nodiscard]] bool QuotientFilter::contains(std::string_view key) const noexcept;

/* Вставка нового ключа у фільтр */
bool QuotientFilter::insert(std::string_view key);

/* Детерміноване видалення ключа з фільтра */
bool QuotientFilter::remove(std::string_view key) noexcept;
```
:::

### Детальний контракт операції перевірки (`qf_lookup` / `contains`)

- **Параметри**: `key` — вказівник на байтовий масив довільної довжини `len` (у C) або незмінний строковий інтерфейс `std::string_view` (у C++).
- **Предумови**: Фільтр ініціалізований та містить коректні метадані.
- **Постумови**: Стан фільтра не змінюється (операція константна та потокобезпечна для паралельного читання).
- **Повернене значення**:
  - `false`: Елемент **гарантовано відсутній** у множині (відсутність хибнонегативних відповідей, 0% False Negative).
  - `true`: Елемент **імовірно присутній** у множині з контрольованою ймовірністю хибнопозитивного спрацьовування `ε ≤ 2^(-r)`.
- **Часова складність**: `O(1)` у середньому завдяки локалізованому лінійному зондуванню; `O(n)` у найгіршому теоретичному випадку при граничному переповненні таблиці.

### Детальний контракт операції вставки (`qf_insert` / `insert`)

- **Параметри**: `key` — цільовий ключ для збереження.
- **Предумови**: Коефіцієнт заповнення фільтра `load_factor < kDefaultMaxLoadFactor` (типово `α < 0.85`).
- **Постумови**: Якщо вільне місце знайдено, залишок `f_r` додається до відповідного набігу зі збереженням числового порядку залишків, елементи кластера зсуваються вправо за правилом Робіна Гуда, а лічильник `count` збільшується на одиницю.
- **Повернене значення**: `true` у разі успішного збереження; `false`, якщо коефіцієнт заповнення перевищує допустимий поріг і таблиця потребує розширення.
- **Часова складність**: `O(1)` амортизована.

### Детальний контракт операції видалення (`qf_delete` / `remove`)

- **Параметри**: `key` — цільовий ключ для вилучення.
- **Предумови**: Фільтр ініціалізований.
- **Постумови**: Якщо відповідний залишок `f_r` знайдено в набігу `f_q`, він видаляється, наступні елементи кластера підтягуються вліво зі збереженням інваріантів неперервності, а лічильник `count` зменшується на одиницю.
- **Повернене значення**: `true`, якщо елемент знайдено та успішно вилучено; `false`, якщо елемент був відсутній у відповідному набігу.
- **Часова складність**: `O(1)` амортизована.

## 4. Специфікація масштабування та потокового злиття

Квошієнтний фільтр підтримує дві розширені операції, недоступні більшості інших імовірнісних фільтрів: подвоєння місткості без повторного хешування вихідних даних та об'єднання двох фільтрів за один послідовний прохід.

:::tabs
```c
/* Подвоєння місткості фільтра без повторного хешування ключів */
QuotientFilter *qf_resize(const QuotientFilter *old_qf);

/* Потокове злиття двох фільтрів однакової конфігурації в новий фільтр */
QuotientFilter *qf_merge(const QuotientFilter *qf1, const QuotientFilter *qf2);
```
```cpp
/* Подвоєння місткості фільтра без доступу до вихідних ключів */
[[nodiscard]] std::unique_ptr<QuotientFilter> resize(const QuotientFilter& old_qf);

/* Злиття двох фільтрів однакової конфігурації */
[[nodiscard]] std::unique_ptr<QuotientFilter> merge(const QuotientFilter& qf1, const QuotientFilter& qf2);
```
:::

- **`qf_resize` / `resize`**:
  - **Предумови**: `old_qf->r_bits ≥ 2`.
  - **Механізм**: Створює нову таблицю з `q' = q + 1` та `r' = r - 1`. Старший біт кожного старого залишку використовується для розширення індексу нової частки `f'_q = (f_q << 1) | msb`.
  - **Часова складність**: `O(2^q)` — рівно один лінійний прохід по старій таблиці.

- **`qf_merge` / `merge`**:
  - **Предумови**: Обидва фільтри `qf1` та `qf2` мають однакові значення `q_bits` та `r_bits`.
  - **Механізм**: Виконує одночасне послідовне зчитування впорядкованих набігів із двох фільтрів за принципом двовказівникового злиття сортування (Merge Sort).
  - **Часова складність**: `O(2^q)` спільних кроків.

## 5. Протокол потокової ітерації по збережених відбитках

На відміну від фільтрів Блума, де збережені елементи неможливо витягти назад навіть у вигляді хеш-відбитків, квошієнтний фільтр підтримує повне відновлення всіх `p`-бітних хеш-значень `h(x) = (f_q << r) | f_r` у строго монотонно зростаючому порядку.

:::tabs
```c
typedef struct {
    const QuotientFilter *qf;
    size_t curr_slot;
    size_t curr_fq;
} QFIterator;

/* Ініціалізація ітератора на початку таблиці */
void qf_iter_init(QFIterator *iter, const QuotientFilter *qf);

/* Отримання наступного відбитка (повертає false після вичерпання таблиці) */
bool qf_iter_next(QFIterator *iter, uint64_t *out_hash);
```
```cpp
struct ReconstructedHash {
    size_t quotient;
    uint8_t remainder;
    [[nodiscard]] uint64_t full_hash(size_t r_bits) const noexcept {
        return (static_cast<uint64_t>(quotient) << r_bits) | remainder;
    }
};

class QuotientFilterIterator {
public:
    explicit QuotientFilterIterator(const QuotientFilter& qf);
    [[nodiscard]] bool has_next() const noexcept;
    ReconstructedHash next();
private:
    const QuotientFilter& qf_;
    size_t curr_slot_ = 0;
    size_t curr_fq_ = 0;
};
```
:::

Протокол ітерації декодує послідовність набігів за один лінійний скан таблиці:
1. Ітератор знаходить черговий зайнятий слот.
2. Якщо біт `is_continuation == 0`, ітератор переходить до наступного канонічного набігу, оновлюючи поточне значення частки `curr_fq`.
3. Реконструйоване значення повного хешу обчислюється конкатенацією частки та залишку: `full_hash = (curr_fq << r_bits) | remainder`.
4. Згенерована послідовність хешів є строго монотонною, що дозволяє виконувати зовнішнє сортування (External Merge) та об'єднання даних на SSD без використання проміжних буферів сортування.

## 6. Системні інваріанти та безпека в багатопотоковому середовищі

1. **Інваріант канонічності**: Біт `is_occupied[i] == 1` тоді й тільки тоді, коли існує хоча б один елемент із часткою `f_q = i`.
2. **Інваріант монотонності залишків**: Усі залишки всередині одного набігу строго впорядковані за зростанням: `remainder[j] ≤ remainder[j + 1]`.
3. **Інваріант неперервності кластера**: Жоден зміщений слот (`is_shifted == 1`) не може межувати зліва з порожньою коміркою.
4. **Потокобезпечність (Thread-Safety)**: Операції `lookup` є потокобезпечними без блокувань (Lock-Free Read). Операції модифікації (`insert`, `delete`) вимагають або зовнішнього виключного блокування (Mutex), або сегментного блокування діапазонів кластерів (Striped Locking).
