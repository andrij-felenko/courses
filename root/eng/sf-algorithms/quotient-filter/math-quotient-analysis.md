# 🧮 Математичний аналіз квошієнтного фільтра: ймовірність колізій, компактність та довжина набігів

Математична строгість квошієнтного фільтра базується на аналізі випадкових відображень у просторі хеш-значень, властивостях відкритої адресації з лінійним зондуванням та теорії марковських ланцюгів для розподілу довжин кластерів і дисперсії зсувів.

## 1. Розщеплення простору хешування та ймовірність хибнопозитивного спрацьовування

Нехай `U` — універсальна множина можливих ключів, а `S ⊂ U` — підмножина з `n = |S|` збережених елементів. Для фільтрації використовується рівномірна псевдовипадкова хеш-функція:

```text
h: U → {0, 1}^p
```

де `p` — загальна розрядність хеш-коду в бітах. Простір значень хешу має потужність `2^p`.

Хеш-код кожного елемента `x ∈ S` однозначно розкладається на дві незалежні бітові компоненти:
1. **Частка (Quotient) `f_q(x)`**: старші `q` бітів хешу, що визначають канонічний індекс слота в таблиці розміром `m = 2^q`.
2. **Залишок (Remainder) `f_r(x)`**: молодші `r` бітів хешу, де `p = q + r`.

```text
f_q(x) = h(x) >> r          [діапазон: 0 .. 2^q - 1]
f_r(x) = h(x) & ((1 << r) - 1)  [діапазон: 0 .. 2^r - 1]
```

### Виведення ймовірності хибнопозитивного спрацьовування (False Positive Rate)

Хибнопозитивне спрацьовування виникає тоді, коли для довільного тестового ключа `y ∉ S` його повний хеш-код `h(y)` колізійно збігається з хеш-кодом хоча б одного із `n` збережених елементів множини `S`.

Оскільки хеш-функція `h` розподіляє ключі рівномірно та незалежно, ймовірність того, що фіксований збережений елемент `x_i ∈ S` має точно такий самий `p`-бітний хеш, як і ключ `y`, дорівнює:

```text
Pr[h(y) = h(x_i)] = 1 / 2^p = 2^(-p)
```

Ймовірність того, що хеш тестового ключа `y` не збігається з жодним із `n` збережених елементів множини `S`:

```text
Pr[жодного збігу]
= (1 - 2^(-p))^n                               [незалежність хешування n елементів]
= exp(n · ln(1 - 2^(-p)))                     [тотожність a^b = exp(b · ln a)]
≈ exp(-n / 2^p)                               [розклад Тейлора: ln(1 - z) ≈ -z при z → 0]
≈ 1 - n / 2^p                                 [розклад Тейлора: exp(-t) ≈ 1 - t при t → 0]
```

Звідси ймовірність хибнопозитивного спрацьовування `ε = Pr[FP]` становить:

```text
ε
= 1 - Pr[жодного збігу]                        [доповнення до повної ймовірності]
= 1 - (1 - n / 2^p)                           [підстановка наближення]
= n / 2^p                                     [спрощення різниці]
= n / (2^q · 2^r)                             [розклад 2^p = 2^(q + r)]
= (n / 2^q) · 2^(-r)                          [виділення коефіцієнта заповнення α]
= α · 2^(-r)                                  [де α = n / m = n / 2^q]
≤ 2^(-r)                                      [оскільки коефіцієнт заповнення α < 1]
```

Коефіцієнт заповнення `α` (Load Factor) визначає ступінь наповненості таблиці:

```text
α = n / m = n / 2^q
```

Оскільки в працездатному квошієнтному фільтрі `α ≤ 1` (типово `α ∈ [0.70, 0.85]`), ймовірність помилки суворо обмежена зверху величиною `2^(-r)`:

```text
ε ≤ 2^(-r)  ⇒  r ≥ ⌈log₂(1 / ε)⌉
```

## 2. Просторова ефективність та порівняння з теоретичною межею

Кожен слот таблиці квошієнтного фільтра містить рівно три службові біти метаданих (`is_occupied`, `is_continuation`, `is_shifted`) та `r` бітів залишку. Отже, розмір однієї комірки становить:

```text
slot_size = r + 3 біти
```

Загальний обсяг пам'яті таблиці з `m = 2^q` слотів становить:

```text
M = m · (r + 3) = (n / α) · (r + 3) бітів
```

Середня кількість бітів на один збережений елемент множини `S`:

```text
b = M / n
= ((n / α) · (r + 3)) / n                      [підстановка загального обсягу M]
= (r + 3) / α                                  [скорочення на n]
= (⌈log₂(1 / ε)⌉ + 3) / α                      [підстановка розрядності залишку r]
```

### Порівняльний аналіз з іншими структурами

Інформаційно-теоретична нижня межа простору для будь-якої ймовірнісної структури без хибнонегативних відповідей дорівнює:

```text
b_min = log₂(1 / ε)
```

Для класичного фільтра Блума оптимальна кількість бітів на елемент становить:

```text
b_bloom = (1 / ln 2) · log₂(1 / ε) ≈ 1.4427 · log₂(1 / ε)
```

Порівняємо питомі витрати пам'яті для типових значень цільової похибки при коефіцієнті заповнення `α = 0.75` та `α = 0.85`:

| Цільова похибка `ε` | Теоретичний мінімум `log₂(1/ε)` | Фільтр Блума (бітів/ел.) | Квошієнтний фільтр (`α = 0.75`) | Квошієнтний фільтр (`α = 0.85`) |
| :--- | :--- | :--- | :--- | :--- |
| `1% (0.01)` | 6.64 біта | 9.58 біта | `(7 + 3) / 0.75 = 13.33` | `(7 + 3) / 0.85 = 11.76` |
| `0.1% (0.001)` | 9.97 біта | 14.38 біта | `(10 + 3) / 0.75 = 17.33` | `(10 + 3) / 0.85 = 15.29` |
| `0.01% (0.0001)` | 13.29 біта | 19.17 біта | `(14 + 3) / 0.75 = 22.67` | `(14 + 3) / 0.85 = 20.00` |
| `0.0001% (10⁻⁶)` | 19.93 біта | 28.75 біта | `(20 + 3) / 0.75 = 30.67` | `(20 + 3) / 0.85 = 27.06` |

При малих значеннях `ε` (високій вимозі до точності, `r ≥ 18`) та щільному заповненні `α ≈ 0.85` квошієнтний фільтр випереджає фільтр Блума не лише за локальністю кешу, але й за чистою компактністю збереження даних.

## 3. Розподіл довжини набігів та довжини кластерів

Кількість елементів `K`, що потрапляють в один і той самий канонічний слот `f_q` (довжина набігу, або розмір серії), є випадковою величиною, що підпорядковується біноміальному розподілу:

```text
K ~ Binomial(n, 1 / m)
```

При великих `n` та `m = 2^q` при фіксованому `α = n / m` цей розподіл асимптотично прямує до розподілу Пуассона з параметром `λ = α`:

```text
Pr[K = k] = (α^k · e^(-α)) / k!
```

Математичне сподівання та дисперсія довжини окремого набігу:

```text
E[K] = α
Var[K] = α
```

### Довжина суцільного кластера та зондування Робіна Гуда

Кластер — це неперервний блок зайнятих слотів, обмежений порожніми комірками з обох боків. Відповідно до класичного аналізу відкритої адресації Кнута та Флажоле, середня кількість кроків зондування `E[L]` для неуспішного пошуку при коефіцієнті заповнення `α` оцінюється як:

```text
E[L_unsuccessful] ≈ (1 + 1 / (1 - α)²) / 2
```

А для успішного пошуку:

```text
E[L_successful] ≈ (1 + 1 / (1 - α)) / 2
```

Дисципліна зсуву Робіна Гуда (Robin Hood displacement), яка підтримує слоти відсортованими за канонічною часткою `f_q`, кардинально змінює максимальну довжину пошуку (дисперсію довжини зондування):
* У стандартному лінійному зондуванні максимальна довжина зондування найгіршого елемента досягає `O(log n)` з високою ймовірністю.
* У квошієнтному фільтрі завдяки впорядкуванню Робіна Гуда максимальне зміщення слота від свого канонічного індексу обмежується `O(log log n)` з високою ймовірністю.

Завдяки цьому дисперсія довжин зондування мінімізується: елементи з довгими набігами не накопичують гігантських лавиноподібних зміщень, а рівномірно витісняють сусідів вправо.

При робочому коефіцієнті заповнення `α = 0.75`:
* Середня довжина успішного пошуку становить `(1 + 1 / (1 - 0.75)) / 2 = (1 + 4) / 2 = 2.5` слоти.
* Середня довжина неуспішного пошуку становить `(1 + 1 / (0.25)²) / 2 = (1 + 16) / 2 = 8.5` слотів.

Оскільки один слот займає близько 1–2 байтів, весь кластер із високою ймовірністю цілком поміщається в одну 64-байтову кеш-лінію процесора.

## 4. Математика динамічного подвоєння без перехешування

Унікальною властивістю квошієнтного фільтра є можливість збільшення місткості вдвічі (`q → q + 1`) без доступу до вихідних ключів `x`.

Нехай поточний фільтр має параметри `q` та `r`, а повний хеш мав довжину `p = q + r`. При переході до нової таблиці подвоєного розміру `m' = 2^(q + 1)`:
* Нова розрядність частки: `q' = q + 1`.
* Нова розрядність залишку: `r' = r - 1`.

Старший біт старого залишку `b_msb = (f_r >> (r - 1)) & 1` стає молодшим бітом нової частки:

```text
f'_q
= (f_q << 1) | b_msb                           [формування (q + 1)-бітного нового індексу]

f'_r
= f_r & ((1 << (r - 1)) - 1)                   [відсікання старшого біта для (r - 1)-бітного залишку]
```

Оскільки сума розрядностей залишається незмінною:

```text
p' = q' + r' = (q + 1) + (r - 1) = q + r = p
```

Повний `p`-бітний хеш елемента `h(x)` повністю зберігається. Це гарантує точне збереження множини та відсутність втрати даних при масштабуванні структури на льоту.

### Динаміка ймовірності хибнопозитивної відповіді після розширення

При подвоєнні фізичного розміру фільтра (`q → q + 1`) і збереженні тієї самої кількості елементів `n` коефіцієнт заповнення зменшується вдвічі: `α' = n / 2^(q + 1) = α / 2`.

Нова ймовірність помилки `ε'` обчислюється як:

```text
ε'
= α' · 2^(-r')                                 [загальна формула похибки]
= (α / 2) · 2^(-(r - 1))                       [підстановка нових параметрів]
= (α / 2) · (2 · 2^(-r))                       [винесення множника 2]
= α · 2^(-r)                                   [скорочення двійок]
= ε                                            [ймовірність похибки лишається тотожною!]
```

Цей дивовижний математичний факт означає, що при подвоєнні таблиці квошієнтного фільтра ймовірність хибнопозитивного спрацьовування не зростає, оскільки зменшення коефіцієнта заповнення вдвічі ідеально компенсує втрату одного біта залишку.

## 5. Числовий приклад проектування для бази даних

**Постановка задачі:** Спроектувати квошієнтний фільтр для індексації `n = 100 000 000` (100 мільйонів) записів у сховищі даних на NVMe SSD із гарантованою ймовірністю хибнопозитивних звернень не більше `ε = 0.001` (0.1%).

**Покроковий розрахунок:**

1. **Розрядність залишку `r`:**
```text
r = ⌈log₂(1 / 0.001)⌉ = ⌈9.9658⌉ = 10 бітів
```

2. **Вибір розрядності частки `q` при коефіцієнті заповнення `α ≈ 0.75`:**
```text
m_min = n / α = 100 000 000 / 0.75 = 133 333 333 комірки
q = ⌈log₂(133 333 333)⌉ = 28 бітів  (m = 2²⁸ = 268 435 456 слотів)
```
Фактичний коефіцієнт заповнення:
```text
α_actual = 100 000 000 / 268 435 456 ≈ 0.3725
```
Фактична ймовірність хибнопозитивної помилки:
```text
ε_actual = 0.3725 · 2^(-10) = 0.3725 / 1024 ≈ 0.0003638 (0.036%)
```

3. **Розмір одного слота та загальний обсяг пам'яті:**
```text
slot_size = r + 3 = 10 + 3 = 13 бітів
M_total = 2²⁸ · 13 бітів = 3 489 660 928 бітів ≈ 416.0 МБ
```

4. **Питома витрата на один ключ:**
```text
b = 416.0 МБ / 100 000 000 = 4.16 байта = 34.89 біта на ключ
```

Для порівняння, збереження повних 64-бітних хешів у хеш-таблиці з відкритою адресацією вимагало б щонайменше `2²⁸ · 8` байтів = 2.0 ГБ пам'яті, що майже в 5 разів перевищує розмір квошієнтного фільтра.
