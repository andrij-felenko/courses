# 🧮 Математичний аналіз переповнення лічильників та ймовірності колізій

У підрахунковому фільтрі Блума (Counting Bloom Filter, CBF) розмір пам'яті визначається розрядністю комірок. Якщо звичайний фільтр Блума виділяє рівно 1 біт на кожну позицію бітового масиву, то CBF замінює кожен біт коміркою розрядністю `b` бітів. Кожна така комірка функціонує як цілочисельний лічильник, здатний набувати значень у діапазоні від `0` до `2ᵇ - 1`.

Головне інженерне та математичне питання проектування підрахункового фільтра полягає у виборі мінімального цілого значення `b`, яке гарантує, що жодна комірка не переповниться в процесі тривалої експлуатації системи. Збільшення `b` лінійно збільшує обсяг оперативної пам'яті структури, тоді як заниження `b` призводить до арифметичного переповнення та блокування операції видалення.

Нижче наведено строге математичне виведення розподілу навантаження на комірки, оцінку ймовірностей хвостових значень через апроксимацію Пуассона та нерівності Чернова, аналіз асимптотики максимального навантаження, моделювання динамічного стаціонарного режиму, аналіз небезпеки некоректних видалень, теорію змінного інкременту (VI-CBF), оцінку частот у спектральних фільтрах (SBF) та покроковий інженерний розрахунок параметрів фільтра.

## Модель розміщення куль у скриньках (Balls-into-Bins)

Нехай підрахунковий фільтр Блума складається з `m` комірок-скриньок, пронумерованих цілими числами від `0` до `m - 1`. У структуру додається множина `S` із `n` незалежних ключів: `S = {x₁, x₂, ..., xₙ}`.

Для кожного доданого елемента `x ∈ S` обчислюється `k` незалежних хеш-значень за допомогою хеш-функцій `h₁, h₂, ..., hₖ`.

Припускаємо стандартну теоретичну модель ідеального рівномірного хешування (Uniform Random Hashing Model): для будь-якого ключа `x` та будь-якої хеш-функції `hⱼ` значення індексу є випадковою величиною, рівномірно розподіленою на множині `{0, 1, ..., m - 1}`:

```text
P(h_j(x) = i) = 1 / m          [рівномірний розподіл хеш-значення для будь-якої комірки i]
```

Процес додавання `n` елементів породжує сумарно `N = n · k` операцій хешування. Кожна така операція еквівалентна випадковому й незалежному киданню однієї кулі в одну з `m` скриньок.

Розглянемо довільно обрану фіксовану комірку з індексом `i` (де `0 ≤ i < m`). Кількість куль, що опинилися в цій комірці після вставки всіх `n` елементів множини `S`, позначимо як випадкову величину `Cᵢ`.

Ймовірність того, що конкретно взяте кидання кулі влучить саме в комірку `i`, дорівнює:

```text
p_hit = 1 / m                  [ймовірність успішного влучання в обрану комірку]
```

Відповідно, ймовірність промаху повз комірку `i` становить `1 - p_hit = 1 - 1 / m`.

Оскільки всі `N = n · k` кидань є взаємно незалежними випадковими подіями Бернуллі, випадкова величина `Cᵢ` підпорядковується точному біноміальному розподілу з параметрами `N` та `p = 1 / m`:

```text
P(C_i = c)
= ( (n·k)! / (c! · (n·k - c)!) ) · (1/m)^c · (1 - 1/m)^(n·k - c)  [точний біноміальний закон Binomial(n·k, 1/m)]
```

Математичне сподівання та дисперсія величини `Cᵢ` становлять:

```text
E[C_i] = (n · k) / m           [математичне сподівання завантаження комірки]
Var(C_i) = (n · k / m) · (1 - 1/m) [дисперсія завантаження комірки]
```

## Граничний перехід до закону розподілу Пуассона

У практичних системах високошвидкісної обробки даних кількість комірок `m` та кількість збережених ключів `n` вимірюються мільйонами або мільярдами одиниць (`m, n ≫ 10⁶`), тоді як ймовірність влучання окремого хешу `1 / m` є зникаюче малою величиною.

Згідно з класичною граничною теоремою Пуассона, якщо `m → ∞` та `n · k → ∞` таким чином, що середнє навантаження на комірку зберігається рівним сталій величині `λ`:

```text
λ = (n · k) / m                [середня густина заповнення фільтра]
```

то послідовність біноміальних розподілів `Binomial(n · k, 1 / m)` рівномірно збігається до закону розподілу Пуассона з параметром `λ`.

Виконаємо строгий граничний перехід для довільного фіксованого значення `c ≥ 0`:

```text
P(C_i = c)
= ( (n·k)! / (c! · (n·k - c)!) ) · (1/m)^c · (1 - 1/m)^(n·k - c)                 [початковий біноміальний вираз]
= ( (n·k)·(n·k - 1)·...·(n·k - c + 1) / (c! · m^c) ) · (1 - 1/m)^(n·k) · (1 - 1/m)^(-c) [розкриття факторіала]
= (1 / c!) · (n·k/m) · (n·k - 1)/m · ... · (n·k - c + 1)/m · (1 - (n·k/m)/(n·k))^(n·k) · 1 [групування множників]
```

Переходячи до границі при `m → ∞` та `n·k → ∞`, враховуємо стандартну границю другого чудового степеня `lim_{N → ∞} (1 - λ/N)^N = e^(-λ)`:

```text
lim_{m → ∞} P(C_i = c)
= (1 / c!) · λ · λ · ... · λ · e^(-λ) · 1                                        [граничний перехід для кожного співмножника]
= (λ^c / c!) · e^(-λ)                                                            [канонічна формула розподілу Пуассона]
```

Отже, навантаження на будь-яку окрему комірку підрахункового фільтра з високою точністю описується пуассонівським процесом із параметром інтенсивності `λ = (n · k) / m`.

## Теоретичний оптимум кількості хеш-функцій

Ймовірність хибнопозитивного спрацьовування (False Positive Rate) `f` для фільтра Блума визначається як імовірність того, що для довільного запитуваного елемента `y ∉ S` усі `k` відповідних комірок виявляться зайнятими (тобто їхні лічильники будуть строго більшими за нуль, `C > 0`).

Імовірність того, що конкретна комірка після завершення фази вставки залишиться абсолютно порожньою (`Cᵢ = 0`):

```text
P(C_i = 0) = (λ^0 / 0!) · e^(-λ) = e^(-λ) = e^(-k·n / m)                         [ймовірність нульового лічильника]
```

Відповідно, ймовірність того, що лічильник комірки отримав хоча б одну кулю і є активним (`Cᵢ > 0`):

```text
P(C_i > 0) = 1 - P(C_i = 0) = 1 - e^(-k·n / m)                                   [ймовірність ненульового лічильника]
```

Оскільки хеш-функції вважаються взаємно незалежними, ймовірність хибнопозитивної відповіді для запиту `y` дорівнює добутку ймовірностей активності всіх `k` комірок:

```text
f = (P(C_i > 0))^k = (1 - e^(-k·n / m))^k                                        [загальна ймовірність False Positive]
```

Для мінімізації величини `f` за фіксованих параметрів обсягу пам'яті `m` та кількості елементів `n` знайдемо похідну натурального логарифма функції `f(k)`:

```text
g(k) = ln f = k · ln(1 - e^(-k·n / m))                                           [логарифм цільової функції помилки]
```

Введемо заміну змінної `u = e^(-k·n / m)`, звідки `k = - (m / n) · ln u`. Підставляючи `k`, маємо:

```text
g(u) = - (m / n) · ln u · ln(1 - u)                                              [вираз функції через змінну заповнення u]
```

Диференціюючи `g(u)` за змінною `u` і прирівнюючи похідну до нуля:

```text
d/du [ln u · ln(1 - u)] = (1 / u) · ln(1 - u) - ln u / (1 - u) = 0               [рівняння стаціонарної точки]
(1 - u) · ln(1 - u) = u · ln u                                                   [умова симетрії кореня]
```

Єдиним розв'язком цього рівняння на інтервалі `u ∈ (0, 1)` є точка `u = 1 / 2`:

```text
e^(-k·n / m) = 1 / 2                                                             [екстремальне значення частки порожніх комірок]
- (k · n) / m = ln(1 / 2) = - ln 2                                               [логарифмування обох частин]
k_opt = (m / n) · ln 2 ≈ 0.693147 · (m / n)                                      [формула оптимальної кількості хеш-функцій]
```

Підставивши оптимальну кількість хеш-функцій `k_opt` у вираз для середнього навантаження `λ`:

```text
λ_opt
= (n · k_opt) / m                                                                [визначення навантаження]
= (n / m) · ( (m / n) · ln 2 )                                                   [підстановка оптимального k]
= ln 2 ≈ 0.69314718056                                                           [оптимальна інтенсивність навантаження комірки]
```

Це доводить ключову закономірність: **у правильно налаштованому підрахунковому фільтрі Блума середнє навантаження на комірку є універсальною математичною константою `λ = ln 2 ≈ 0.69315`, незалежно від розміру фільтра `m` та кількості елементів `n`**.

## Точний спектр імовірностей значень лічильника

Знаючи, що параметр пуассонівського розподілу строго дорівнює `λ = ln 2`, обчислимо множину точних імовірностей набуття лічильником конкретних числових значень `c ∈ {0, 1, 2, ...}`:

Враховуючи, що `e^(-λ) = e^(-ln 2) = 1 / 2 = 0.5`, функція ймовірності Пуассона набуває спрощеного вигляду:

```text
P(C = c) = ( (ln 2)^c / (2 · c!) )                                               [формула розрахунку ймовірностей станів комірки]
```

Проведемо покроковий розрахунок для перших значень лічильника `c`:

```text
P(C = 0) = (ln 2)^0 / (2 · 0!) = 1 / 2 = 0.50000000000                           [рівно 50.0% комірок залишаються нульовими]
P(C = 1) = (ln 2)^1 / (2 · 1!) ≈ 0.69314718 / 2 = 0.34657359028                  [34.66% комірок містять рівно 1 елемент]
P(C = 2) = (ln 2)^2 / (2 · 2!) ≈ 0.48045301 / 4 = 0.12011325336                  [12.01% комірок містять рівно 2 елементи]
P(C = 3) = (ln 2)^3 / (2 · 6)  ≈ 0.33302465 / 12 = 0.02775205433                 [2.78% комірок містять рівно 3 елементи]
P(C = 4) = (ln 2)^4 / (2 · 24) ≈ 0.23083510 / 48 = 0.00480906447                 [0.48% комірок містять рівно 4 елементи]
P(C = 5) = (ln 2)^5 / (2 · 120) ≈ 0.16000276 / 240 = 0.00066667822               [0.067% комірок містять рівно 5 елементів]
P(C = 6) = (ln 2)^6 / (2 · 720) ≈ 0.11090547 / 1440 = 0.00007701770              [0.0077% комірок містять рівно 6 елементів]
P(C = 7) = (ln 2)^7 / (2 · 5040) ≈ 0.07687383 / 10080 = 0.00000762645            [0.00076% комірок містять рівно 7 елементів]
P(C = 8) = (ln 2)^8 / (2 · 40320) ≈ 0.05328494 / 80640 = 0.00000066077           [0.000066% комірок містять рівно 8 елементів]
```

Знайдемо кумулятивну суму для діапазону від 0 до 3:

```text
P(C ≤ 3)
= P(0) + P(1) + P(2) + P(3)                                                      [сума перших чотирьох імовірностей]
= 0.50000000 + 0.34657359 + 0.12011325 + 0.02775205                             [числові значення]
= 0.99443889                                                                     [99.44% лічильників не перевищують значення 3]
```

Цей числовий результат наочно демонструє, що понад 99.4% усіх комірок CBF містять значення `0, 1, 2` або `3`.

## Оцінка хвостових імовірностей та нерівність Чернова

Для аналізу граничної надійності структури необхідно оцінити ймовірність того, що випадкова величина `Cᵢ` перевищить граничне значення місткості `M = 2ᵇ - 1`.

Ймовірність переповнення окремої комірки визначається сумою нескінченного хвоста розподілу Пуассона:

```text
P(C_i ≥ M + 1) = ∑_{c = M + 1}^∞ ( (ln 2)^c / (2 · c!) )                         [точна сума хвостових імовірностей]
```

Для експоненційної оцінки хвостових сум випадкових величин застосуємо класичну нерівність Чернова для суми незалежних індикаторних змінних Бернуллі.

Якщо `X ~ Poisson(λ)` або `X ~ Binomial(N, p)` із середнім `μ = E[X]`, то для будь-якого коефіцієнта відхилення `δ > 0` справджується мультиплікативна нерівність Чернова:

```text
P(X ≥ (1 + δ) · μ) ≤ ( e^δ / (1 + δ)^(1 + δ) )^μ                                  [верхня межа Чернова для верхнього хвоста]
```

Покладемо `μ = λ = ln 2 ≈ 0.693147`. Для 4-бітних лічильників критичний поріг переповнення становить `X ≥ 16`. Визначаємо параметр `δ`:

```text
(1 + δ) · μ = 16                                                                 [поріг переповнення 4-бітної комірки]
1 + δ = 16 / ln 2 ≈ 16 / 0.69314718 ≈ 23.08312                                   [множник перевищення математичного сподівання]
δ ≈ 22.08312                                                                     [відносне відхилення від середнього]
```

Підставимо отримані значення у формулу нерівності Чернова:

```text
P(C_i ≥ 16)
≤ ( e^(22.08312) / (23.08312)^(23.08312) )^(0.693147)                           [підстановка параметрів у межу Чернова]
= exp( 0.693147 · [ 22.08312 - 23.08312 · ln(23.08312) ] )                      [логарифмічне перетворення виразу]
= exp( 0.693147 · [ 22.08312 - 23.08312 · 3.13910 ] )                           [обчислення натурального логарифма]
= exp( 0.693147 · [ 22.08312 - 72.46022 ] )                                     [віднімання значень у дужках]
= exp( 0.693147 · [ -50.37710 ] )                                                [множення на параметр середнього]
= exp( -34.91873 ) ≈ 6.84 × 10⁻¹⁶                                                [експоненційна верхня оцінка Чернова]
```

Оцінимо точний хвіст ряду Пуассона через мажорування геометричною прогресією:

```text
∑_{c=16}^∞ (ln 2)^c / c!
= ( (ln 2)^16 / 16! ) · ( 1 + (ln 2)/17 + (ln 2)²/(17·18) + ... )                [винесення першого члена ряду]
≤ ( (ln 2)^16 / 16! ) · ( 1 / (1 - (ln 2)/17) )                                  [сума нескінченної геометричної прогресії]
```

Обчислимо компоненти:

```text
(ln 2)^16 ≈ 0.002871142
16! = 20 922 789 888 000 ≈ 2.092279 × 10¹³
(ln 2)^16 / 16! ≈ 1.372255 × 10⁻¹⁶
1 / (1 - 0.693147 / 17) = 1 / (1 - 0.040773) ≈ 1.042507
P(C_i ≥ 16) = 0.5 · (1.372255 × 10⁻¹⁶) · 1.042507 ≈ 7.153 × 10⁻¹⁷               [сувора точна верхня оцінка ймовірності переповнення]
```

Консервативна границя, наведена у фундаментальній роботі Лі Фан, Пей Цао, Янко Алмейди та Андрія Бродера:

```text
P(C_i ≥ 16) ≤ 1.371 × 10⁻¹⁵                                                      [консервативна оцінка Фан-Цао-Алмейди-Бродера]
```

## Асимптотика максимуму лічильників та Union Bound

Для оцінки надійності всього фільтра Блума як цілісної структури необхідно визначити поведінку випадкової величини максимального завантаження комірок:

```text
C_max = max_{0 ≤ i < m} C_i                                                      [максимальне значення лічильника в усьому фільтрі]
```

З класичної теорії розміщення куль у скриньках відомо, що коли `N = n · k = m · ln 2` куль випадково розміщуються по `m` урнах, асимптотична поведінка математичного сподівання максимуму описується формулою Райцеса та Гоннета:

```text
E[C_max] = ( ln m / ln ln m ) · ( 1 + (ln ln ln m) / (ln ln m) + O(1 / ln ln m) ) [асимптотика Гоннета для максимального завантаження]
```

Обчислимо очікуване максимальне значення лічильника `E[C_max]` для практичних розмірів фільтрів `m`:
* Для `m = 10⁶` (1 мільйон комірок): `ln m ≈ 13.815`, `ln ln m ≈ 2.626`, звідки `E[C_max] ≈ 13.815 / 2.626 ≈ 5.26`.
* Для `m = 10⁹` (1 мільярд комірок): `ln m ≈ 20.723`, `ln ln m ≈ 3.031`, звідки `E[C_max] ≈ 20.723 / 3.031 ≈ 6.84`.
* Для `m = 10¹²` (1 трильйон комірок): `ln m ≈ 27.631`, `ln ln m ≈ 3.319`, звідки `E[C_max] ≈ 27.631 / 3.319 ≈ 8.32`.

Навіть для гігантського фільтра з трильйона комірок математичне сподівання найвищого лічильника не перевищує 9.

Оцінимо ймовірність виникнення хоча б одного переповнення в усьому фільтрі за нерівністю об'єднання Буля (Union Bound):

```text
P(C_max ≥ 16) = P( ⋃_{i=0}^{m-1} {C_i ≥ 16} )
≤ ∑_{i=0}^{m-1} P(C_i ≥ 16)                                                      [нерівність Буля для об'єднання подій]
= m · P(C_0 ≥ 16)                                                                [ідентичність розподілів усіх комірок]
≤ m · 1.371 × 10⁻¹⁵                                                              [підстановка консервативної оцінки]
```

Зведемо результати розрахунків для різних масштабів систем у таблицю:

| Розмір фільтра `m` | Обсяг пам'яті (4 біти) | Кількість ключів `n` (при `k=4`) | `P(C_max ≥ 16) ≤ m · 1.37×10⁻¹⁵` | Очікувана кількість переповнень `E[N_over]` |
| :--- | :--- | :--- | :--- | :--- |
| `10⁶` | 500 КБ | `173 286` | `≤ 1.37 × 10⁻⁹` | `0.00000000137` |
| `10⁷` | 5 МБ | `1 732 868` | `≤ 1.37 × 10⁻⁸` | `0.0000000137` |
| `10⁸` | 50 МБ | `17 328 680` | `≤ 1.37 × 10⁻⁷` | `0.000000137` |
| `10⁹` | 500 МБ | `173 286 795` | `≤ 1.37 × 10⁻⁶` | `0.00000137` |
| `10¹⁰` | 5 ГБ | `1 732 867 951` | `≤ 1.37 × 10⁻⁵` | `0.0000137` |

Ймовірність виникнення хоча б одного переповнення лічильника в масиві з 1 мільярда комірок становить менше 0.000137%.

## Подвійне хешування Кірша-Міценмахера та незалежність колізій

На практиці обчислення `k` повністю незалежних криптографічних хеш-функцій (таких як SHA-256 або Blake3) є занадто ресурсомісткою операцією. Замість цього застосовують схему подвійного хешування Адама Кірша та Майкла Міценмахера (Kirsch-Mitzenmacher Double Hashing), де всі `k` індексів генеруються лише з двох базових хешів `h₁(x)` та `h₂(x)`:

```text
g_i(x) = ( h_1(x) + i · h_2(x) ) mod m       де 0 ≤ i < k                         [формула подвійного хешування Кірша-Міценмахера]
```

Згідно з теоремою Кірша-Міценмахера (2008), асимптотична ймовірність хибнопозитивного спрацьовування при використанні схеми `gᵢ(x)` збігається до класичної формули з незалежними хеш-функціями:

```text
lim_{m → ∞} f_double(m, n, k) = (1 - e^(-k·n / m))^k                             [асимптотична еквівалентність схеми Кірша-Міценмахера]
```

При цьому ймовірність колізій між парами індексів для одного й того самого елемента `x` при `h₂(x) ≢ 0 (mod m)` та взаємно простому кроці дорівнює нулю для `k < m`, оскільки арифметична прогресія `(h₁ + i · h₂) mod m` генерує `k` строго попарно різних індексів.

Це гарантує, що жоден окремий елемент `x` не може інкрементувати одну й ту саму комірку двічі під час однієї операції вставки, усуваючи штучне накопичення колізій у межах одного ключа.

## Моделювання стаціонарного динамічного режиму (Dynamic Steady-State)

У реальних мережевих маршрутизаторах та проксі-серверах підрахунковий фільтр функціонує в режимі безперервного потоку подій, де вставки та видалення утворюють марковський процес народження і загибелі (Birth-Death Process).

Нехай нові ключі надходять у фільтр за пуассонівським процесом з інтенсивністю `μ_in` (елементів за секунду), а час перебування кожного ключа в кеші є незалежною випадковою величиною з експоненційним розподілом та середнім значенням `τ = 1 / μ_out`.

Така динамічна система еквівалентна системі масового обслуговування типу `M/M/∞`.

У стаціонарному режимі (Steady-State) випадкова кількість одночасно активних ключів `N_active(t)` підпорядковується закону Пуассона з середнім значенням:

```text
E[N_active] = μ_in · τ = μ_in / μ_out = n_target                                 [формула Літтла для середньої кількості активних ключів]
Var(N_active) = n_target                                                         [дисперсія кількості активних ключів у стаціонарному стані]
```

Оскільки операція видалення дійсного ключа `x` строго декрементує рівно ті самі `k` комірок, що були інкрементовані при його вставці:

```text
C_i(t_del) = C_i(t_ins) + 1 - 1 = C_i(t_del)                                     [строга інваріантність стану комірки]
```

імовірнісний розподіл навантаження комірок `Cᵢ` у будь-який момент часу `t` залишається строго стаціонарним пуассонівським розподілом з параметром `λ(t) = k · N_active(t) / m`.

Коливання кількості активних ключів навколо середнього `n_target` обмежені стандартним відхиленням `σ = √n_target`. Навіть при відхиленні на `3σ` (правило трьох сигм):

```text
n_max_fluc = n_target + 3 · √n_target                                            [максимальне статистичне коливання ємності]
λ_max_fluc = (k / m) · (n_target + 3 · √n_target) = ln 2 · (1 + 3 / √n_target)    [зсув параметра інтенсивності Пуассона]
```

Для типового кешу з `n_target = 10⁶` елементів відносне збільшення становить лише `3 / √10⁶ = 0.003` (0.3%), що практично не впливає на ймовірність переповнення 4-бітних лічильників.

## Математичний аналіз некоректного видалення неіснуючого ключа

Критичним джерелом збоїв у динамічних системах є випадкова спроба видалення ключа `z`, який насправді **не був доданий** до фільтра (`z ∉ S`).

Якщо система попередньо перевіряє наявність ключа через операцію `contains(z)`, то через імовірнісну природу фільтра з імовірністю `f = (1 - e^(-k·n/m))^k` операція поверне хибнопозитивне значення `true`.

Якщо після цього алгоритм безумовно виконає операцію `delete(z)`, це призведе до декременту `k` лічильників `h₁(z), ..., hₖ(z)`.

Оцінимо ймовірність того, що хоча б один із декрементованих лічильників мав значення `C = 1` (тобто належав рівно одному дійсному ключу `x ∈ S`):

```text
P(C = 1 | C > 0) = P(C = 1) / P(C > 0) = (λ · e^(-λ)) / (1 - e^(-λ))             [умовна ймовірність того, що активний лічильник дорівнює 1]
```

При оптимальному навантаженні `λ = ln 2`, де `e^(-λ) = 0.5` та `1 - e^(-λ) = 0.5`:

```text
P(C = 1 | C > 0) = (ln 2 · 0.5) / 0.5 = ln 2 ≈ 0.693147                          [умовна ймовірність одиничного лічильника]
```

Це означає, що кожна декрементована комірка з імовірністю близько 69.3% перетвориться на `0`.

Ймовірність того, що хоча б одна з `k` комірок обнулиться:

```text
P(помилкове обнулення) = 1 - (1 - P(C = 1 | C > 0))^k = 1 - (1 - ln 2)^k         [ймовірність знищення щонайменше однієї комірки]
```

Для `k = 4`:

```text
P(помилкове обнулення) = 1 - (1 - 0.69315)⁴ = 1 - (0.30685)⁴ = 1 - 0.00887 ≈ 0.99113 [99.11% ймовірність порушення інваріанта]
```

У результаті з імовірністю понад 99.1% дійсний ключ `x`, що мав спільну комірку із `z`, втратить один зі своїх лічильників. При наступній перевірці `contains(x)` фільтр поверне **`false`** — виникне заборонена помилка False Negative.

Саме цей математичний розрахунок диктує фундаментальне правило архітектури CBF: **операція `delete(x)` повинна викликатися виключно для тих ключів, чия присутність у системі гарантована зовнішнім первинним джерелом істини (наприклад, дисковою таблицею чи хеш-індексом)**.

## Математичне обґрунтування змінного інкременту (VI-CBF)

У модифікації Variable-Increment Counting Bloom Filter (VI-CBF) операція додавання елемента `x` використовує додаткову псевдовипадкову хеш-функцію `D(x)`, яка генерує крок інкременту `d ∈ {1, 2, ..., L}`:

```text
C[h_j(x)] = C[h_j(x)] + D_j(x)                                                   [інкремент на випадкову величину d]
```

При перевірці належності елемента `y` перевіряється умова:

```text
C[h_j(y)] ≥ D_j(y)          для всіх 1 ≤ j ≤ k                                   [умова належності в VI-CBF]
```

Якщо елемент `y ∉ S` не належить множині, то для кожного індексу `hⱼ(y)` значення збереженого лічильника `C` сформоване випадковими іншими ключами. Нехай поточне значення лічильника дорівнює `c`.

Якщо крок `Dⱼ(y)` розподілений рівномірно на множині `{1, 2, ..., L}`, то ймовірність того, що випадковий лічильник `c` задовольнить умову `c ≥ Dⱼ(y)`, дорівнює:

```text
P(c ≥ D_j(y)) = min(1, c / L)                                                    [ймовірність виконання умови для комірки зі значенням c]
```

Усереднюючи за пуассонівським розподілом значень лічильника `C ~ Poisson(λ)`:

```text
P_match = ∑_{c=1}^∞ P(C = c) · min(1, c / L)                                    [усереднена ймовірність збігу однієї комірки]
```

Оскільки для малих значень `c < L` коефіцієнт `c / L < 1`, підсумкова ймовірність збігу комірки `P_match` виявляється строго меншою за ймовірність `P(C > 0) = 1 - e^(-λ)` у стандартному CBF.

У результаті підсумковий показник False Positive Rate знижується:

```text
f_VI = (P_match)^k < (1 - e^(-λ))^k = f_standard                                 [зменшення ймовірності хибнопозитивної відповіді]
```

Це дозволяє або знизити ймовірність помилки при тому самому обсязі пам'яті, або зменшити кількість комірок `m` без погіршення точності.

## Оцінка частоти елементів у спектральних фільтрах Блума (SBF)

Спектральний фільтр Блума (Spectral Bloom Filter, SBF) розширює CBF на мультимножини, де елемент `x` може додаватися `f_x` разів.

Оцінка частоти появи елемента `x` обчислюється як мінімальне значення серед усіх його `k` лічильників:

```text
f_est(x) = min_{1 ≤ j ≤ k} C[h_j(x)]                                            [оцінювач мінімального лічильника Коена-Матіаса]
```

Оскільки кожен інкремент ключа `x` збільшує всі `k` його лічильників на 1, а колізії з іншими елементами можуть лише збільшити окремі лічильники, оцінювач `f_est(x)` володіє важливою математичною властивістю односторонньої похибки:

```text
f_est(x) ≥ f_x                                                                   [гарантована нижня межа істинної частоти]
```

Математичне сподівання шуму від колізій інших елементів `y ≠ x` обмежується середнім навантаженням `E[шум] ≤ (n · k) / m = λ`.

Завдяки операції взяття мінімуму по `k` незалежних комірках імовірність того, що оцінка `f_est(x)` перевищить істинне значення `f_x` на величину `ε ≥ 1`, експоненційно спадає зі зростанням `k`:

```text
P( f_est(x) ≥ f_x + ε ) ≤ ( P(C_noise ≥ ε) )^k ≈ ( e^(-λ) · λ^ε / ε! )^k        [експоненційне придушення похибки оцінки частоти]
```

## Повний покроковий розрахунок параметрів підрахункового фільтра

Продемонструємо повний інженерно-математичний розрахунок параметрів CBF для промислової системи:
* Цільова кількість активних ключів: `n = 10 000 000` (10 мільйонів).
* Допустима ймовірність хибнопозитивного спрацьовування: `f = 0.01` (1.0%).

1. **Розрахунок необхідної кількості комірок `m`:**
```text
f = (1/2)^k = (0.5)^k = 0.01
k = - log2(0.01) = ln(100) / ln 2 ≈ 4.60517 / 0.69315 ≈ 6.64386
k_int = 7                                                                        [округлення до найближчого цілого числа хеш-функцій]
m = (n · k) / ln 2 = (10 000 000 · 7) / 0.69314718 ≈ 100 988 648                 [мінімально необхідна кількість комірок]
```

2. **Розрахунок обсягу пам'яті при 4 бітах на комірку:**
```text
Bits_total = m · 4 = 100 988 648 · 4 = 403 954 592 біти                           [загальна кількість бітів]
Bytes_total = Bits_total / 8 = 50 494 324 байти ≈ 48.15 МБ                       [обсяг оперативної пам'яті CBF]
```

3. **Порівняння зі звичайним фільтром Блума:**
```text
Bytes_bloom = (m · 1) / 8 = 12 623 581 байт ≈ 12.04 МБ                           [пам'ять класичного фільтра Блума]
Коефіцієнт збільшення пам'яті = 4.0×                                              [рівно чотирикратне зростання для підтримки видалення]
```

4. **Оцінка ймовірності переповнення для розрахованого фільтра:**
```text
P(C_max ≥ 16) ≤ m · P(C_0 ≥ 16) ≤ 100 988 648 · (1.371 × 10⁻¹⁵) ≈ 1.385 × 10⁻⁷  [менше одного шансу на сім мільйонів]
```

Такий детальний розрахунок підтверджує, що для підтримки 10 мільйонів ключів із точністю 99% достатньо виділити 48.15 МБ оперативної пам'яті, що гарантує надійну роботу операцій видалення без ризику переповнення лічильників.
