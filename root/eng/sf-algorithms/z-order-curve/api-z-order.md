# 📋 Інтерфейс бібліотеки Z-індексування (Morton 2D/3D)

Довідник інтерфейсу визначає повний публічний контракт C та C++ сигнатур для переплетення бітів Morton 2D/3D, параметрів просторових запитів, структури ключів, правил використання пам'яті, гарантій винятків та апаратних вимог.

## 1. Загальний огляд контрактів та структур даних

Публічна бібліотека надає єдиний API для роботи з кривими Z-порядку у двовимірному (2D) та тривимірному (3D) просторах. Усі функції розроблені так, щоб бути повністю безпечними щодо багатопотокового виконання (thread-safe), не мати внутрішнього стану (stateless) та не виділяти динамічну пам'яті на купі під час переплетення координат. Це дозволяє викликати їх у високонавантажених обчислювальних циклах, у ядрах симуляції та під час обробки графічних текстур.

Кожна точка простору подається у формі беззнакових цілих чисел `uint32_t`. У 2D кодуванні кожен з двох вимірів використовує до 32 бітів інформації, даючи 64-бітне Morton-число. У 3D кодуванні кожен з трьох вимірів використовує до 21 біта (21 × 3 = 63 біти), що також вміщується в один 64-бітний інверсний ключ `uint64_t`.

Вхідні та вихідні межі прямокутних вікон задаються структурою Bounding Box, яка містить мінімальне та максимальне значення координат по кожній із осей.

### Публічні типи даних та константи

| Тип / Константа | Мова | Базовий тип | Опис |
| :--- | :--- | :--- | :--- |
| `morton_key2d_t` | C / C++ | `uint64_t` | 64-бітний Morton-код для двох 32-бітних координат (x, y) |
| `morton_key3d_t` | C / C++ | `uint64_t` | 64-бітний Morton-код для трьох 21-бітних координат (x, y, z) |
| `morton_box2d_t` | C | `struct` | Прямокутне вікно запиту: `min_x`, `max_x`, `min_y`, `max_y` |
| `morton_box3d_t` | C | `struct` | Паралелепіпедне вікно запиту: 3D межі min/max за осями x, y, z |
| `MORTON_MAX_COORD_2D` | C / C++ | `0xFFFFFFFF` | Максимальне значення координати 2D (2³² − 1 = 4,294,967,295) |
| `MORTON_MAX_COORD_3D` | C / C++ | `0x1FFFFF` | Максимальне значення координати 3D (2²¹ − 1 = 2,097,151) |

## 2. Повний контракт C API (C99 ABI)

Функції C API дотримуються стандартного ABI C99 і призначені для легкої інтеграції в будь-які системні мови програмування (FFI для Rust, Python, Go, Java, C#). Завдяки відсутності зовнішніх залежностей заголовочний файл бібліотеки можна включати безпосередньо в низькорівневі C-проекти, оперативні системи реального часу (RTOS) та драйвери пристроїв.

### 2.1. Детальний опис функцій кодування та декодування

Кодувальні функції є основними робочими конячками бібліотеки. Вони здійснюють переплетення бітів координат у 64-бітний Morton-код за один виклик.

- `morton_encode2d(uint32_t x, uint32_t y)`
  Приймає дві 32-бітні координати `x` та `y`. Повертає 64-бітне ціле число, у якому біти `y` розташовані на непарних позиціях (1, 3, 5, ..., 63), а біти `x` — на парних позиціях (0, 2, 4, ..., 62). Функція є атомарною з точки зору обчислень, не створює побічних ефектів і виконується за 1 такт CPU при наявності інструкцій BMI2 `PDEP`. Якщо координата перевищує значення `MORTON_MAX_COORD_2D`, відбувається автоматичне затискання бітів без викидання помилки.

- `morton_decode2d(uint64_t z, uint32_t *out_x, uint32_t *out_y)`
  Виконує зворотне декодування 64-бітного Morton-коду `z` на две окремі координати. Вказівники `out_x` та `out_y` не повинні бути рівними `NULL`. Перевірка на `NULL` здійснюється у режимі збірки з розширеним дебагом (`#ifndef NDEBUG`), а у продуктивному виклику для максимальної швидкості вважається контрактною передумовою.

- `morton_encode3d(uint32_t x, uint32_t y, uint32_t z)`
  Приймає три 21-бітні координати `x`, `y`, `z` і розгортає їх у 63-бітний Morton-код. Старший 64-й біт результату завжди залишається нульовим. Якщо будь-яка з координат перевищує межу `0x1FFFFF` (2 097 151), вищі біти відтинаються маскою `0x1FFFFF`.

- `morton_decode3d(uint64_t key, uint32_t *out_x, uint32_t *out_y, uint32_t *out_z)`
  Розгортає 64-бітний 3D Morton-код на три окремі 21-бітні координати. Використовує апаратну інструкцію `PEXT` або 6-крокову маску SWAR.

:::tabs
```c
// 2D кодування (x: 32 біти, y: 32 біти -> z: 64 біти)
uint64_t morton_encode2d(uint32_t x, uint32_t y);

// 2D декодування (z: 64 біти -> x: 32 біти, y: 32 біти)
void morton_decode2d(uint64_t z, uint32_t *out_x, uint32_t *out_y);

// 3D кодування (x: 21 біт, y: 21 біт, z: 21 біт -> key: 64 біти)
uint64_t morton_encode3d(uint32_t x, uint32_t y, uint32_t z);

// 3D декодування
void morton_decode3d(uint64_t key, uint32_t *out_x, uint32_t *out_y, uint32_t *out_z);
```
```cpp
// 2D кодування у C++ (constexpr, noexcept)
std::uint64_t morton_encode2d(std::uint32_t x, std::uint32_t y) noexcept;

// 2D декодування у C++ (std::pair)
std::pair<std::uint32_t, std::uint32_t> morton_decode2d(std::uint64_t z) noexcept;

// 3D кодування у C++
std::uint64_t morton_encode3d(std::uint32_t x, std::uint32_t y, std::uint32_t z) noexcept;

// 3D декодування у C++ (std::tuple)
std::tuple<std::uint32_t, std::uint32_t, std::uint32_t> morton_decode3d(std::uint64_t key) noexcept;
```

### 2.2. Віконні просторові запити (Range Query)

Функції просторового пошуку обробляють масиви точок, впорядковані за Morton-кодом.

- `morton_range_query2d(const Point2D *points, size_t count, const morton_box2d_t *box, Point2D *out_results, size_t max_results)`
  Сканує впорядкований масив `points` розміром `count`. Першим кроком обчислюються межі `min_key` та `max_key` для кутків вікна `box`. Функція здійснює двійковий пошук стартової позиції та послідовно відбирає точки, чиї координати входять у прямокутник `box`. Пошук зупиняється, коли поточний ключ перевищує `max_key` або досягнуто ліміту `max_results`.

- `morton_bigmin_litmax2d(uint64_t curr_z, const morton_box2d_t *box, uint64_t *out_bigmin, uint64_t *out_litmax)`
  Обчислює межі двійкового стрибка для перетину розривів Z-кривої. Якщо ключ `curr_z` випав поза межі вікна `box`, функція повертає в `out_bigmin` найменший можливий Morton-код усередині вікна, який більший за `curr_z`. Це дозволяє викликаючому коду зробити `lower_bound` і пропустити чужий інтервал.

:::tabs
```c
size_t morton_range_query2d(
    const Point2D *points,
    size_t count,
    const morton_box2d_t *box,
    Point2D *out_results,
    size_t max_results
);

void morton_bigmin_litmax2d(
    uint64_t curr_z,
    const morton_box2d_t *box,
    uint64_t *out_bigmin,
    uint64_t *out_litmax
);
```
```cpp
// Пошук у відсортованому векторі Morton-точок у C++ (std::span)
std::vector<Point2D> morton_range_query2d(
    std::span<const Point2D> points,
    const BoundingBox2D& box
);

// Обчислення BIGMIN та LITMAX у C++ (std::pair)
std::pair<std::uint64_t, std::uint64_t> morton_bigmin_litmax2d(
    std::uint64_t curr_z,
    const BoundingBox2D& box
) noexcept;
```

## 3. C++ API сигнатури (`namespace spatial`)

Інтерфейс C++20 розроблений відповідно до принципів RAII, надає оболонку типів без накладних витрат (zero-cost abstractions), підтримує обчислення під час компіляції (`constexpr`) та використовує стандартні контейнери `std::vector` і `std::span`. Усі класи розміщені в просторі імен `spatial`.

### 3.1. Опис класів та методів C++

- `spatial::Morton2D` — статичний клас для 2D кодування. Усі методи є `constexpr` та `noexcept`, що дозволяє обчислювати Morton-коди константних точок безпосередньо під час компіляції програми.
- `spatial::Morton3D` — статичний клас для 3D кодування. Приймає координати у формі `uint32_t` і повертає `std::tuple<uint32_t, uint32_t, uint32_t>` при декодуванні.
- `spatial::MortonIndex2D` — клас індексу просторових точок. Конструктор приймає `std::vector<Point2D>`, автоматично сортує точки за Morton-кодом за допомогою `std::sort` та будує лінійне квадродерево. Метод `query_range` виконує двійковий пошук першого можливого елемента за допомогою `std::lower_bound` і повертає вектор точок у вікні.

```cpp
namespace spatial {

class Morton2D {
public:
    static constexpr uint64_t encode(uint32_t x, uint32_t y) noexcept;
    static std::pair<uint32_t, uint32_t> decode(uint64_t z) noexcept;
};

class Morton3D {
public:
    static constexpr uint64_t encode(uint32_t x, uint32_t y, uint32_t z) noexcept;
    static std::tuple<uint32_t, uint32_t, uint32_t> decode(uint64_t key) noexcept;
};

class MortonIndex2D {
public:
    explicit MortonIndex2D(std::vector<Point2D> points);

    [[nodiscard]] std::vector<Point2D> query_range(const BoundingBox2D& box) const;
    [[nodiscard]] size_t size() const noexcept;
};

} // namespace spatial
```

## 4. Аналіз складності та накладних витрат

Усі базові операції кодування є високооптимізованими. Використання апаратних інструкцій процесора дозволяє скоротити накладні витрати до абсолютного мінімуму. При обробці великих масивів даних часова складність визначається ефективністю двійкового пошуку `O(log N)`.

| Операція | Часова складність (без BMI2) | Часова складність (з BMI2 `PDEP`/`PEXT`) | Просторова складність |
| :--- | :--- | :--- | :--- |
| `morton_encode2d` | O(1) [5 SWAR кроків] | O(1) [1 такт CPU] | 0 додаткової пам'яті |
| `morton_decode2d` | O(1) [5 SWAR кроків] | O(1) [1 такт CPU] | 0 додаткової пам'яті |
| `morton_encode3d` | O(1) [6 SWAR кроків] | O(1) [1 такт CPU] | 0 додаткової пам'яті |
|Побудова індексу | O(N log N) [Сортування] | O(N log N) [Сортування] | O(N) під впорядкований масив |
|Запит `query_range` | O(log N + K) [де K — к-сть відповідностей] | O(log N + K) | O(K) під вихідний вектор |

## 5. Політика пам'яті, багатопоточність та крайові випадки

1. **Безпека потоків (Thread Safety):** Усі функції кодування та декодування `morton_encode2d`, `morton_decode2d`, `morton_encode3d` не зберігають внутрішнього стану і є чисто функціональними (`pure functions`). Вони можуть безпосередньо викликатися з довільної кількості паралельних потоків без використання блокувань або атомарних операцій.
2. **Управління пам'яттю у C API:** C API не виконує жодних виділень пам'яті на купі (`malloc`). Виклик `morton_range_query2d` вимагає від клієнта надання заздалегідь виділеного буфера `out_results`. Це унеможливлює фрагментацію пам'яті у системах реального часу (RTOS).
3. **Управління пам'яттю у C++ API:** Клас `MortonIndex2D` захоплює володіння вектором точок через семантику переміщення (`std::move`). Функція `query_range` повертає новий вектор результатів `std::vector<Point2D>`.
4. **Крайові випадки (Edge Cases):**
   - Порожній масив точок (`count = 0`): `morton_range_query2d` миттєво повертає 0 без помилок.
   - Вироджене вікно (`min_x == max_x` та `min_y == max_y`): шукає точний збіг точки за її Morton-кодом.
   - Вікно поза межами сітки: повертає 0 результатів за логарифмічний час завдяки перевірці ключів `min_key` та `max_key`.

## 6. Вимоги до апаратного забезпечення та гарантії

- **Мінімальні вимоги:** Будь-який 32-розрядний або 64-розрядний процесор із підтримкою базових побітових операцій `AND`, `OR`, `<<`, `>>`.
- **Оптимальна продуктивність (x86-64):** Процесори з підтримкою наборів інструкцій **BMI2** (Intel Haswell 2013 року і новіші, AMD Ryzen 2017 року і новіші). Використання `_pdep_u64` зменшує час кодування в 4–5 разів порівняно з масками SWAR.
- **Гарантії винятків:** Усі кодувальні функції гарантують `noexcept`. Функція `morton_range_query2d` не генерує винятків за умови передачі валідного вказівника на вихідну пам'ять.
