# 🧮 Математичні докази стійкості та перетворення перестановок

Властивість стійкості сортування має строге математичне підґрунтя в термінах теорії множин, перестановок та лексикографічних порядків. На відміну від емпіричного спостереження за поведінкою коду, математичний аналіз дозволяє однозначно довести стійкість або нестійкість алгоритму для довільного вхідного масиву.

У цій вставці розглядаються формальні означення, інваріанти стійких алгоритмів, математичні докази стійкості сортування злиттям, сортування рахунком та порозрядного сортування (LSD Radix Sort), докази нестійкості швидкого сортування, сортування купою, сортування Шелла та сортування вибором через контраприклади, а також формальний апарат розширення ключів (декорування).

## 1. Формальна математична модель сортування

Нехай `A = [a₀, a₁, …, aₙ₋₁]` — вхідний масив із `n` елементів, що належать деякій множині `T`.

Визначимо **функцію ключа** `K: T → S`, яка відображає кожен елемент масиву в множину ключів `S`. На множині `S` задано відношення строгого лінійного порядку `<` та відношення еквівалентності `=`.

Будь-який алгоритм сортування визначає **перестановку** `π: {0, 1, …, n−1} → {0, 1, …, n−1}`, яка переставляє елементи вхідного масиву `A` у вихідний масив `A' = [a'_0, a'_1, …, a'_{n-1}]`, де `a'_k = a_{π(k)}`.

Умова коректності сортування за ключем вимагає, щоб вихідний масив був монотонно неспадним за функцією ключа:

```
∀ k ∈ {0, 1, …, n−2}: K(a'_{k}) ≤ K(a'_{k+1})
[умова монотонності відсортованого масиву]
```

### Формальне означення стійкості

Алгоритм сортування називається **стійким** (англ. *stable*), якщо для будь-якої пари вхідних індексів `i, j ∈ {0, 1, …, n−1}` виконується така імплікація:

```
(i < j) ∧ (K(a[i]) = K(a[j]))  ⇒  π⁻¹(i) < π⁻¹(j)
[умова збереження відносного порядку рівних ключів]
```

тут `π⁻¹(i)` позначає підсумкову позицію елемента `a[i]` у відсортованому масиві `A'`.

Якщо ж існує хоча б один вхідний масив `A` та хоча б одна пара індексів `i < j` таких, що `K(a[i]) = K(a[j])`, але `π⁻¹(i) > π⁻¹(j)`, то алгоритм є **нестійким** (англ. *unstable*).

## 2. Доведення стійкості сортування вставками (Insertion Sort)

Розглянемо алгоритм сортування вставками. Покажемо, що при правильній умові зупинки зсуву він є математично стійким.

### Псевдокод зсуву елемента
```
для i від 1 до n−1:
    key_elem = A[i]
    j = i − 1
    поки j ≥ 0 та K(A[j]) > K(key_elem):
        A[j + 1] = A[j]
        j = j − 1
    A[j + 1] = key_elem
```

### Формальне доведення інваріанта стійкості

Доведемо стійкість за допомогою математичної індукції за кроками зовнішнього циклу `i`.

**База індукції (`i = 1`).** Підмасив `A[0..0]` складається з одного елемента і є тривіально стійким.

**Індукційний перехід.** Припустимо, що після `i − 1` кроків підмасив `A[0..i−1]` є відсортованим і стійким. Розглядаємо елемент `A[i]`.

1. Умова внутрішнього циклу `while`: `j ≥ 0 ∧ K(A[j]) > K(key_elem)`.
2. Внутрішній цикл зсуває праворуч лише ті елементи `A[j]`, ключ яких **суворо більший** за `K(key_elem)`.
3. Як тільки цикл зустрічає елемент `A[j]`, для якого `K(A[j]) ≤ K(key_elem)`, цикл **негайно зупиняється**.
4. Отже, елемент `key_elem` вставляється в позицію `j + 1` одразу після всіх елементів із ключем, рівним `K(key_elem)`.

Якщо в підмасиві `A[0..i−1]` вже існували елементи `A[p]` (де `p < i`) з ключем `K(A[p]) = K(A[i])`, вони залишаються ліворуч від нововставленого елемента `A[i]`.

Таким чином, для будь-яких `p < i` з однаковими ключами `π⁻¹(p) < π⁻¹(i)`. Індукційний крок доведено. Сортування вставками є **стійким**.

> ⚠️ **Зауваження про строгість нерівності:** Якби умова циклу була записана як `K(A[j]) ≥ K(key_elem)`, елементи з однаковими ключами зсувалися б праворуч, і елемент `A[i]` вставлявся б **попереду** своїх дублікатів. Це перетворило б алгоритм на **нестійкий**.

## 3. Доведення стійкості сортування злиттям (Merge Sort)

Сортування злиттям працює за принципом «розділяй і володарюй». Доведемо стійкість фази об'єднання (злиття) двох уже відсортованих підмасивів.

### Математична модель процедури злиття

Нехай маємо два відсортовані підмасиви:
`L = [l₀, l₁, …, lₚ₋₁]` (ліва частина)
`R = [r₀, r₁, …, r₇₋₁]` (права частина)

Оскільки у вихідному масиві `A` усі елементи `L` передували всім елементам `R`, для будь-якого елемента `l_a ∈ L` та `r_b ∈ R` початкові індекси задовольняють умову `orig_idx(l_a) < orig_idx(r_b)`.

Процедура злиття вибирає елементи до вихідного масиву `M` за таким правилом:

```
якщо K(l_a) ≤ K(r_b):
    вибрати l_a з лівої частини (a = a + 1)
інакше:
    вибрати r_b з правої частини (b = b + 1)
```

### Формальне доведення інваріанта рівності

Розглянемо випадок рівності ключів: `K(l_a) = K(r_b)`.

1. За початковим розташуванням у масиві: `orig_idx(l_a) < orig_idx(r_b)`.
2. За умовою `K(l_a) ≤ K(r_b)` при рівності оператор `≤` повертає `істина` (true).
3. Алгоритм змушений вибрати елемент `l_a` і помістити його до масиву `M` раніше за `r_b`.
4. Отже, у підсумковому масиві позиція `pos(l_a) < pos(r_b)`.

Оскільки відносний порядок усередині самого `L` та всередині самого `R` вже збережений за індукційним припущенням, а порядок між `L` та `R` зберігається завдяки оператору `≤`, весь алгоритм Merge Sort за індукцією є **гарантовано стійким**.

## 4. Доведення стійкості сортування рахунком (Counting Sort) та LSD Radix Sort

Сортування рахунком (Counting Sort) обчислює позицію кожного елемента за допомогою масиву префіксних сум. Доведемо, чому зворотний прохід вхідного масиву забезпечує стійкість.

### Псевдокод алгоритму

```
// Крок 1: Підрахунок частот
для i від 0 до n-1:
    count[K(A[i])]++

// Крок 2: Префіксні суми (визначення правих меж позицій)
для k від 1 до M-1:
    count[k] += count[k-1]

// Крок 3: Заповнення вихідного масиву B з КІНЦЯ вхідного масиву A
для i від n-1 спадаючи до 0:
    val = K(A[i])
    pos = count[val] - 1
    B[pos] = A[i]
    count[val]--
```

### Формальний доказ інваріанта зворотного проходу

Нехай маємо два елементи `A[i]` та `A[j]` такі, що `i < j` та `K(A[i]) = K(A[j]) = v`.

1. На початку Кроку 3 лічильник `count[v]` містить загальну кількість елементів із ключем, меншим або рівним `v`.
2. Оскільки цикл обходу за індексом `k` іде **від `n-1` до `0`**, елемент `A[j]` обробляється **раніше** за елемент `A[i]`.
3. Елемент `A[j]` розміщується на індекс `B[count[v] - 1]`, після чого лічильник декрементується: `count[v] = count[v] - 1`.
4. Коли через кілька кроків цикл доходить до елемента `A[i]`, поточне значення `count[v]` стало **строго меншим** на принаймні одиницю.
5. Елемент `A[i]` розміщується на індекс `B[count[v] - 1]`, який суворо менший за позицію `A[j]`.

Отже, `pos(A[i]) < pos(A[j])`. Оскільки початково `i < j`, відносний порядок збережено. **Counting Sort є стійким.**

### Необхідність стійкості для LSD Radix Sort

Нехай число `X` подано в `d` розрядах: `X = (d_{m-1}, d_{m-2}, …, d₀)`.
Алгоритм LSD Radix Sort викликає стійке внутрішнє сортування `m` разів — від молодшого розряду `d₀` до старшого `d_{m-1}`.

Доведемо за індукцією, що після `k` проходів масив впорядковано за останніми `k` розрядами.
- **База (`k = 1`).** Масив впорядковано за молодшим розрядом `d₀`.
- **Перехід (`k → k + 1`).** Нехай масив впорядкований за розрядами `(d_{k-1}, …, d₀)`. Виконуємо сортування за розрядом `d_k`.
  - Якщо два елементи мають різні розряди `d_k(X₁) < d_k(X₂)`, вони опиняються в правильному порядку за властивістю підпрограми сортування.
  - Якщо `d_k(X₁) = d_k(X₂)`, оскільки підпрограма **стійка**, їхній відносний порядок **не змінюється**. А за індукційним припущенням їхній відносний порядок до цього проходу визначався розрядами `(d_{k-1}, …, d₀)`.

Отже, після проходу `k + 1` порядок враховує як розряд `d_k`, так і всі попередні розряди. Якби внутрішнє сортування виявилося нестійким, крок `k + 1` зруйнував би впорядкованість за молодшими розрядами, і LSD Radix Sort дав би неправильний результат.

## 5. Математичний доказ нестійкості сортування вибором (Selection Sort)

Для доведення нестійкості алгоритму за правилами математичної логіки достатньо навести **один контрприклад** — вхідний масив, на якому умова стійкості порушується.

### Алгоритм сортування вибором
```
для i від 0 до n−2:
    min_idx = i
    для j від i+1 до n−1:
        якщо K(A[j]) < K(A[min_idx]):
            min_idx = j
    обміняти A[i] ↔ A[min_idx]
```

### Формальний контрприклад

Розглянемо масив із `n = 3` елементів:
`A = [(2a, id=0), (2b, id=1), (1, id=2)]`

Тут ключ кожного елемента — це перше число, а `id` — унікальний початковий індекс.
Маємо: `K(A[0]) = 2`, `K(A[1]) = 2`, `K(A[2]) = 1`.
Очевидно, що `0 < 1` та `K(A[0]) = K(A[1]) = 2`.

Простежимо виконання кроків алгоритму:

```
Крок 1 (i = 0):
  Шукаємо мінімум у діапазоні A[0..2].
  A[0] = 2a, A[1] = 2b, A[2] = 1.
  Мінімальний елемент знаходиться в min_idx = 2 (значення 1).
  Виконуємо обмін A[0] ↔ A[2]:
  Масив стає: [(1, id=2), (2b, id=1), (2a, id=0)]   [обмін A[0] та A[2]]

Крок 2 (i = 1):
  Шукаємо мінімум у діапазоні A[1..2].
  A[1] = 2b, A[2] = 2a.
  Оскільки K(2a) не менше K(2b), min_idx залишається 1.
  Обмін не міняє порядок.
```

Підсумковий масив: `A' = [(1, id=2), (2b, id=1), (2a, id=0)]`.

Обчислимо підсумкові позиції `π⁻¹`:
- `π⁻¹(id=0) = 2`  (елемент 2a опинився на індексі 2)
- `π⁻¹(id=1) = 1`  (елемент 2b опинився на індексі 1)

Оскільки `id=0 < id=1`, але `π⁻¹(0) = 2 > π⁻¹(1) = 1`, умову стійкості порушено. **Сортування вибором нестійке. Q.E.D.**

### Причина нестійкості
Нестійкість виникає через процедуру **обміну на великих відстанях** (`swap(A[i], A[min_idx])`). Елемент `A[i]` під час обміну перестрибує через проміжні елементи (у нашому випадку `2a` перестрибнув через `2b`), опиняючись праворуч від елемента з таким самим ключем.

## 6. Математичний доказ нестійкості швидкого сортування (Quicksort)

Розглянемо схему розділення Ломуто (Lomuto Partition), яка є однією з найпоширеніших у реалізації Quicksort.

### Схема Ломуто
```
partition(A, low, high):
    pivot = K(A[high])
    i = low - 1
    для j від low до high - 1:
        якщо K(A[j]) ≤ pivot:
            i = i + 1
            обміняти A[i] ↔ A[j]
    обміняти A[i + 1] ↔ A[high]
    повернути i + 1
```

### Формальний контрприклад для Quicksort

Розглянемо вхідний масив із чотирьох елементів (`n = 4`):
`A = [(5a, id=0), (3, id=1), (5b, id=2), (2, id=3)]`

Тут `pivot = K(A[3]) = 2`.
Шукаємо елементи, менші або рівні `pivot` (тобто `≤ 2`).

```
j = 0: K(A[0]) = 5a > 2 → обмін не відбувається.
j = 1: K(A[1]) = 3 > 2  → обмін не відбувається.
j = 2: K(A[2]) = 5b > 2 → обмін не відбувається.

Фінальний обмін: A[i + 1] ↔ A[high], де i = -1, отже A[0] ↔ A[3].
Обмінюємо A[0] (5a) та A[3] (2):
Масив стає: [(2, id=3), (3, id=1), (5b, id=2), (5a, id=0)]  [опорний елемент 2 став на корінь]
```

Зверніть увагу на пару дублікатів з ключем 5:
- Початково: `5a` мав `id=0`, `5b` мав `id=2` (`0 < 2`).
- Після фази розділення: `5b` опинився на індексі 2, а `5a` опинився на індексі 3.

Оскільки `π⁻¹(0) = 3 > π⁻¹(2) = 2`, відносний порядок елементів `5a` та `5b` змінено на протилежний. **Швидке сортування нестійке. Q.E.D.**

## 7. Математичний доказ нестійкості сортування купою (Heapsort)

Сортування купою побудоване на двійковому масиві-дереві, де батьківський індекс `parent(i) = ⌊(i - 1) / 2⌋`.

### Алгоритм та джерело нестійкості

Heapsort працює у дві фази:
1. Побудова max-купи.
2. Циклічний витяг кореня: обмін `A[0] ↔ A[end]` з подальшим просіюванням вниз (`sift_down`).

### Формальний контрприклад для Heapsort

Розглянемо вхідний масив з однакових елементів із різними `id`:
`A = [(5a, id=0), (5b, id=1), (5c, id=2)]`

Побудова max-купи для однакових ключів залишає масив без змін:
`A = [5a, 5b, 5c]` (усі ключі 5).

Виконуємо Крок 1 фази сортування:
- Обмінюємо корінь `A[0]` (5a) з останнім елементом `A[2]` (5c):
  Масив стає: `[(5c, id=2), (5b, id=1) | (5a, id=0)]`.
- Елемент `5a` зафіксовано на позиції 2 (в кінці масиву).

Виконуємо Крок 2:
- Обмінюємо новий корінь `A[0]` (5c) з останнім елементом купи `A[1]` (5b):
  Масив стає: `[(5b, id=1) | (5c, id=2), (5a, id=0)]`.

Підсумковий відсортований масив: `A' = [5b, 5c, 5a]`.

Перевіримо підсумкові індекси:
- `5a` мала початковий `id=0`, стала на підсумковий індекс 2 (`π⁻¹(0) = 2`).
- `5b` мала початковий `id=1`, стала на підсумковий індекс 0 (`π⁻¹(1) = 0`).

Початковий порядок `id=0 < id=1` повністю обернувся у `π⁻¹(0) = 2 > π⁻¹(1) = 0`. **Сортування купою інваріантно нестійке. Q.E.D.**

## 8. Доведення нестійкості сортування Шелла (Shellsort)

Сортування Шелла (Shellsort) розбиває вхідний масив на `h` незалежних підмасивів, де елементи відстоять один від одного на крок `h > 1`, і сортує кожен підмасив вставками.

### Механічний контрприклад

Розглянемо масив із `n = 4` елементів при кроці `h = 2`:
`A = [(3a, id=0), (7, id=1), (3b, id=2), (2, id=3)]`

Сортуємо підмасиви з кроком `h = 2`:
- Підмасив 1 (індекси 0 та 2): `[A[0], A[2]] = [3a, 3b]`. Оскільки `K(3a) = K(3b)`, сортування вставками залишає порядок `[3a, 3b]`.
- Підмасив 2 (індекси 1 та 3): `[A[1], A[3]] = [7, 2]`. Оскільки `K(7) > K(2)`, виконання обміну дає `[2, 7]`.

Після фази `h = 2` масив набуває вигляду:
`A = [(3a, id=0), (2, id=3), (3b, id=2), (7, id=1)]`

Виконуємо фінальну фазу `h = 1` (звичайне сортування вставками):
- Елемент `2` порівнюється з `3a` і зсувається на позицію 0.
- Елемент `3a` зсувається на позицію 1.
- Елемент `3b` порівнюється з `3a` (ключі рівні `3 = 3`) і зупиняється на позиції 2.

Підсумковий масив: `A' = [(2, id=3), (3a, id=0), (3b, id=2), (7, id=1)]`.

У цьому конкретному випадку порядок `3a` та `3b` збережено, але замінимо `A[1]` на `1`:

Розглянемо `A = [(5a, id=0), (1, id=1), (5b, id=2), (2, id=3)]` при `h = 2`:
- `[A[0], A[2]] = [5a, 5b]` → залишається `[5a, 5b]`.
- `[A[1], A[3]] = [1, 2]` → залишається `[1, 2]`.

Масив після `h = 2`: `[(5a, id=0), (1, id=1), (5b, id=2), (2, id=3)]`.
На фазі `h = 1`:
- Елемент `1` зсувається ліворуч перед `5a`: `[(1, id=1), (5a, id=0), (5b, id=2), (2, id=3)]`.
- Елемент `2` зсувається ліворуч і стає між `1` та `5a`: `[(1, id=1), (2, id=3), (5a, id=0), (5b, id=2)]`.

Попри те що в цьому прикладі `5a` та `5b` зберегли порядок, якщо елементи з однаковими ключами потрапляють у **різні підмасиви кроку `h`**, елементи першої групи можуть бути зсунуті далеко назустріч елементам другої групи. Оскільки сортування підмасивів іде повністю ізольовано один від одного, відносний порядок однакових ключів у різних групах не контролюється. **Shellsort нестійке.**

## 9. Теорема еквівалентності багатопрохідного сортування

Доведемо теорему, яка пояснює, чому стійке сортування за кількома ключами еквівалентне лексикографічному сортуванню за складеним ключем.

### Твердження теореми
Нехай об'єкт має два ключі `(K₁, K₂)`. Послідовне виконання стійкого сортування спочатку за ключем `K₂`, а потім за ключем `K₁` дає точно такий самий результат, як і єдине сортування за паралельним ключем `(K₁, K₂)` з лексикографічним порядком.

### Доведення

Нехай маємо два елементи `X` та `Y`.
Розглянемо два випадки після другого сортування за `K₁`:

1. **Випадок `K₁(X) ≠ K₁(Y)`:**
Друге сортування за `K₁` розміщує елемент із меншим `K₁` раніше. Оскільки первинний ключ `K₁` має вищий пріоритет у лексикографічному порядку `(K₁, K₂)`, підсумковий порядок `X` та `Y` є правильним.

2. **Випадок `K₁(X) = K₁(Y)`:**
Друге сортування бачить рівність первинних ключів `K₁`. Оскільки це сортування є **стійким**, воно зобов'язане **зберегти відносний порядок**, який `X` та `Y` мали до початку другого сортування.
А цей відносний порядок було сформовано на першому кроці під час сортування за ключем `K₂`.
Отже, якщо `K₂(X) < K₂(Y)`, то `X` передував `Y` перед другим кроком, і стійкість другого кроку зберігає `X` перед `Y`.

Таким чином, у всіх випадках підсумковий порядок відповідає порядку `<ₗₑₓ` для складеного ключа `(K₁, K₂)`. **Теорему доведено.**

## 10. Ізоморфізм декорування ключів (Key Augmentation)

Будь-який нестійкий алгоритм сортування можна зробити стійким за допомогою математичного перетворення вхідної множини ключів, відомого як **декорування ключів** або **розширення ключів початковим індексом**.

### Математичне формулювання перетворення

Нехай `S` — вихідна множина ключів із строго частковим порядком `<ₛ`.
Створимо нову розширену множину ключів `S' = S × ℕ`, де кожен новий ключ є впорядкованою парою:

```
K'(a[i]) = (K(a[i]), i)
[розширений ключ: ключ елемента + початковий індекс]
```

На множині `S'` задамо **лексикографічний порядок** `<ₗₑₓ`:

```
(k₁, i₁) <ₗₑₓ (k₂, i₂)  ⇔  (k₁ <ₛ k₂) ∨ (k₁ =ₛ k₂ ∧ i₁ < i₂)
[лексикографічне порівняння двох пар]
```

### Покроковий приклад обчислення компаратора

Візьмемо два вхідних елементи з однаковим первинним ключем:
`Elem_A = (Key = 42, orig_idx = 2)`
`Elem_B = (Key = 42, orig_idx = 5)`

Застосуємо формулу лексикографічного порівняння:

```
Крок 1: Порівнюємо первинні ключі.
  k₁ = 42, k₂ = 42.
  k₁ < k₂ є хибним (false), k₁ = k₂ є істинним (true).

Крок 2: Оскільки k₁ = k₂, переходимо до порівняння індексів.
  i₁ = 2, i₂ = 5.
  Оскільки 2 < 5 є істинним (true), підсумковий вираз:
  (42, 2) <ₗₑₓ (42, 5) ⇒ ІСТИНА (true).
```

Отже, компаратор гарантує, що `Elem_A` строго передуватиме `Elem_B` незалежно від перестановок, які виконує внутрішній алгоритм сортування.

### Доведення строгого лінійного порядку та гарантованої стійкості

Доведемо дві ключові властивості розширеної системи ключів:

1. **Відсутність однакових ключів у `S'`:**
Оскільки всі початкові індекси `i ∈ {0, 1, …, n−1}` є унікальними, для будь-яких двох різних елементів `a[i]` та `a[j]` (де `i ≠ j`):
```
i ≠ j  ⇒  (K(a[i]), i) ≠ (K(a[j]), j)
```
У множині `S'` **взагалі немає рівних ключів**. Відношення `=ₗₑₓ` виконується лише для елемента самого з собою.

2. **Еквівалентність лексикографічного сортування та стійкого сортування:**
Нехай `i < j`. Розглянемо два випадки:
- Якщо `K(a[i]) <ₛ K(a[j])`, то за першою частиною означення `(K(a[i]), i) <ₗₑₓ (K(a[j]), j)`.
- Якщо `K(a[i]) =ₛ K(a[j])`, оскільки `i < j`, за другою частиною означення `(K(a[i]), i) <ₗₑₓ (K(a[j]), j)`.

В обох випадках `K'(a[i]) <ₗₑₓ K'(a[j])`.

Оскільки в `S'` усі ключі є строго унікальними та лінійно впорядкованими, **будь-який алгоритм сортування** (навіть найагресивніше нестійкий, як-от Quicksort чи Heapsort), впорядковуючи пари `(K(a[i]), i)` за порядком `<ₗₑₓ`, дасть єдину детерміновану перестановку `π`.

У цій перестановці для будь-яких `i < j` з `K(a[i]) = K(a[j])` елемент `(K(a[i]), i)` обов'язково передуватиме `(K(a[j]), j)`, тобто `π⁻¹(i) < π⁻¹(j)`.

### Теоретико-складнісний аналіз декорування

Декорування ключів переносить складність збереження порядку на структуру даних:

```
Додаткова пам'ять:           O(n)      [зберігання n цілих чисел індексів]
Часова накладна витрата:     O(n)      [створення пар (K[i], i) до сортування]
Накладна витрата порівняння: O(1)      [додаткова перевірка i₁ < i₂ при рівності K₁ = K₂]
```

Це математично доводить, що стійкість не є принципово нерозв'язним обмеженням для будь-якого алгоритму, а є питанням компромісу між O(n) додаткової пам'яті та алгоритмічною структурою порівнянь.
