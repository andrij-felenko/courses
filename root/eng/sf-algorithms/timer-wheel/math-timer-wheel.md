# 🧮 Математичний аналіз часової складності та параметризація колеса таймерів

Подано математичне обґрунтування часової складності `O(1)` операцій додавання, скасування та амортизованої обробки кроку часу в однорівневих та ієрархічних таймерних колесах.

---

## 1. Формальна постановка задачі відліку часу

Нехай абстрактна система управління таймерами оперує часом, розбитим на дискретні інтервали рівної тривалості — кванти часу (tick resolution), які позначимо через `δ > 0`.

Поточний дискретний час системи виражається цілим числом кроків (тіків) `T ∈ ℕ₀`, що відповідає фізичному часу `t = T · δ`.

Множина активних таймерів у системі є скінченним набором об'єктів:

```text
S = { (id₁, E₁, cb₁), (id₂, E₂, cb₂), ..., (id_M, E_M, cb_M) }
```

де:
* `id_i` — унікальний ідентифікатор таймера;
* `E_i ∈ ℕ₀` — абсолютний дискретний час спрацьовування (`E_i ≥ T`);
* `cb_i` — функція зворотного виклику (callback), яка повинна бути виконана, коли поточний час досягне `T = E_i`.

Відносний інтервал очікування (затримка) для нового таймера дорівнює `Δ_i = E_i - T`.

Система повинна підтримувати три основні операції:
1. **`Schedule(Δ, cb) -> id`:** вставити новий таймер із затримкою `Δ` та повернути ідентифікатор.
2. **`Cancel(id) -> bool`:** видалити таймер з ідентифікатором `id`, якщо він ще не спрацював.
3. **`Tick() -> List[cb]`:** пересунути системний годинник на один крок (`T ↦ T + 1`) і повернути список callback-функцій усіх таймерів, у яких `E_i = T`.

## 2. Математика однорівневого колеса таймерів (Single-Level Wheel)

### 2.1 Структура та хешування

Однорівневе колесо таймерів складається з масиву слотів (buckets) розміром `N`, де кожен слот є головою двозв'язаного списку.

Розмір масиву обирається як степінь двійки: `N = 2ᵏ`, що дозволяє замінити операцію остачі від ділення швидким побітовим маскуванням:

```text
h(E)
= E mod N              [визначення циклічного хешу]
= E & (N - 1)          [тотожність для N = 2ᵏ]
```

### 2.2 Варіант A: Просте колесо без обертів (`T_max < N`)

Якщо гарантується, що максимальна затримка таймера не перевищує розміру колеса (`Δ < N`), слот для нового таймера обчислюється як:

```text
slot = (T + Δ) & (N - 1)
```

* **Вставка (`Schedule`):** таймер додається у голову або хвіст двозв'язаного списку слота `slot`. Оскільки вказівник на слот вираховується за дві арифметичні операції, час вставки дорівнює `τ_add = O(1)`.
* **Скасування (`Cancel`):** якщо структура таймера зберігає вказівники `prev` та `next` у двозв'язаному списку, вилучення вузла зі списку виконується за `τ_cancel = O(1)`.
* **Тік (`Tick`):** покажчик поточного слота зміщується: `current = (T + 1) & (N - 1)`. Усі таймери, що знаходяться у списку слота `current`, гарантовано мають `E_i = T + 1`. Список повністю очищається, і всі колбеки виконуються.
  Час обробки тіку дорівнює:

```text
τ_tick = O(1 + m_current)
```

  де `m_current` — кількість таймерів, які дозріли саме у цьому тіку. Середня складність на один таймер є строго `O(1)`.

### 2.3 Варіант B: Однорівневе колесо з лічильником обертів (Rounds)

Якщо `Δ ≥ N`, таймер не вміщується у діапазон одного оберту колеса. Для розміщення такого таймера обчислюють кількість повних обертів колеса, які повинна відбутися до його спрацьовування:

```text
slot = (T + Δ) & (N - 1)
rounds = ⌊ Δ / N ⌋
```

При обробці операції `Tick()` система перебирає елементи у слоті `current`:
* Якщо `rounds > 0`, значення зменшується: `rounds ↦ rounds - 1`. Таймер залишається у списку.
* Якщо `rounds == 0`, таймер вилучається зі списку і виконується його callback.

#### Погіршення складності тіку у найгіршому випадку

Нехай у слот `slot` було додано `K` таймерів із затримками `Δ_j = Δ₀ + j · N · δ`. Усі вони потрапляють у той самий слот, але мають різні значення `rounds = j`.

При кожному проходженні покажчика через цей слот система змушена перебрати всі `K` елементів списку і виконати зменшення `rounds`, навіть якщо спрацьовує лише один елемент (або взагалі жодного!).

Часова складність тіку стає рівною:

```text
τ_tick = O(1 + K)
```

При великій кількості довготривалих таймерів (`K ≫ 1`) однорівневе колесо втрачає перевагу `O(1)` і перетворюється на невідсортований список з обходом елементів.

## 3. Математичний аналіз ієрархічного колеса таймерів (Hierarchical Wheel)

Щоб усунути проблему перевірки `rounds`, створюють ієрархію з `m` коліс (позначаються як `TV₀, TV₁, ..., TV_{m-1}`).

### 3.1 Параметризація та бітовий розподіл

Нехай перше колесо `TV₀` має розмір `N₀ = 2^(k₀)`, а всі наступні колеса `TV_i` (`i ≥ 1`) мають розміри `N_i = 2^(k_i)`.

Загальний часовий діапазон без обертів, що покривається такою ієрархією, дорівнює добутку розмірів усіх коліс:

```text
T_max
= N₀ · N₁ · N₂ · ... · N_{m-1}      [добуток місткостей коліс]
= 2^(k₀ + k₁ + ... + k_{m-1})      [додавання показників степенів]
```

Для типової конфігурації 32-бітного часового індексу у Linux kernel:
* `TV₀`: `k₀ = 8` бітів (`N₀ = 256` слотів), покриває затримки від 0 до 255;
* `TV₁`: `k₁ = 6` бітів (`N₁ = 64` слоти), покриває затримки від 256 до 16 383;
* `TV₂`: `k₂ = 6` бітів (`N₂ = 64` слоти), покриває затримки від 16 384 до 1 048 575;
* `TV₃`: `k₃ = 6` бітів (`N₃ = 64` слоти);
* `TV₄`: `k₄ = 6` бітів (`N₄ = 64` слоти).

Загальний діапазон становить `k₀ + 4 · k₁ = 8 + 24 = 32` біти (`T_max = 2³² - 1` тіків).

### 3.2 Формула визначення рівня та слота при вставці

Для даної затримки `Δ = E - T` рівень колеса `L`, у яке мусить бути розміщений таймер, визначається за допомогою старших значущих бітів різниці часу.

1. Якщо `Δ < N₀`, то `L = 0`, а слот у `TV₀` дорівнює:
```text
slot₀ = E & (N₀ - 1)
```
2. Якщо `N₀ ≤ Δ < N₀ · N₁`, то `L = 1`, а слот у `TV₁` дорівнює:
```text
slot₁ = (E >> k₀) & (N₁ - 1)
```
3. У загальному випадку для рівня `L ≥ 1`:
```text
shift_L = k₀ + (L - 1) · k_i
slot_L = (E >> shift_L) & (N_L - 1)
```

Оскільки обчислення `shift_L` та `slot_L` зводиться до кількох бітових інструкцій процесора (`CLZ`, `SHR`, `AND`), вставка нового таймера завжди виконується за **строгий константний час**:

```text
τ_add = O(1)
```

## 4. Теорема про амортизований час каскадування (Cascading Amortization)

Ключовим операційним елементом ієрархічного колеса є **каскадування (cascading)**: перенесення таймерів з вищого колеса `TV_L` у нижчі колеса, коли покажчик колеса `TV_{L-1}` виконує повний оберт і загортається на нуль.

### 4.1 Твердження теореми

*У `m`-рівневому ієрархічному таймерному колесі з розмірами коліс `N₀, N₁, ..., N_{m-1}` амортизована часова складність виконання операції `Tick()` для будь-якої послідовності вставок та вилучень таймерів є строго `O(1)`.*

### 4.2 Доведення за допомогою методу потенціалів (Potential Method)

Визначимо потенціал системи `Φ` у довільний момент часу.

Нехай для кожного таймера `x ∈ S`, який перебуває у колесі `TV_L` (де `L ∈ {0, 1, ..., m-1}`), його індивідуальний потенціал дорівнює його рівню:

```text
Φ(x) = L
```

Повний потенціал структури даних дорівнює сумі потенціалів усіх активних таймерів:

```text
Φ = Σ L · |S_L|
```

де `|S_L|` — кількість таймерів у колесі `TV_L`.

#### 1. Операція `Schedule` (Вставка)
При додаванні нового таймера `x` у колесо `TV_L` реальні витрати часу є константними: `c_add = O(1) ≤ C₁`.
Зміна потенціалу системи становить:

```text
ΔΦ = L ≤ m - 1
```

Амортизована складність вставки:

```text
ĉ_add
= c_add + ΔΦ           [визначення амортизованої вартості]
≤ C₁ + (m - 1)         [підстановка верхніх меж]
= O(1)                 [константна сума]
```

#### 2. Операція `Cancel` (Скасування)
При вилученні таймера `x` із колеса `TV_L` реальні витрати є `c_cancel ≤ C₂`.
Зміна потенціалу є від'ємною або нульовою: `ΔΦ = -L ≤ 0`.
Амортизована складність скасування:

```text
ĉ_cancel
= c_cancel + ΔΦ        [визначення амортизованої вартості]
≤ C₂ - L               [підстановка зміненого потенціалу]
≤ O(1)                 [не перевищує C₂]
```

#### 3. Операція `Tick` та Каскадування
Розглянемо крок часу `Tick()`.
* **Випадок A (без каскадування):** покажчик `TV₀` пересувається на 1 слот без оберту. Реальний час обробки дорівнює `C₃ + O(m₀)`, де `m₀` — кількість таймерів, які дозріли у даному слоті `TV₀`. Оскільки ці таймери вилучаються з системи, потенціал змінюється на `ΔΦ = -0 · m₀ = 0`.
  Амортизований час є `O(1 + m₀)`.

* **Випадок B (з каскадуванням):** нехай покажчик колеса `TV₀` завершив оберт. Відбувається каскадування елементів із колеса `TV₁`.
  Нехай у відповідному слоті колеса `TV₁` знаходилося `K` таймерів.
  Для кожного з цих `K` таймерів виконуються такі дії:
  1. Таймер виймається із колеса `TV₁` (де його потенціал дорівнював 1).
  2. Для нього переобчислюється новий залишок часу `Δ' < N₀`.
  3. Таймер переміщується у відповідний слот колеса `TV₀` (де його новий потенціал стає рівним 0).

  Реальна вартість каскадування цих `K` елементів пропорційна їх кількості: `c_cascade = C₄ · K`.
  Зміна потенціалу системи при переміщенні `K` елементів з рівня 1 на рівень 0 дорівнює: `ΔΦ = K · (0 - 1) = -K`.

  Обчислюємо амортизовану вартість каскадування:

```text
ĉ_cascade
= c_cascade + ΔΦ       [визначення амортизованої вартості]
= C₄ · K - K           [підстановка c_cascade та ΔΦ]
= (C₄ - 1) · K         [винесення K за дужки]
≤ 0                    [за умови C₄ ≤ 1]
```

  За умови нормування одиниць виміру часу так, що `C₄ ≤ 1`, амортизована вартість каскадування є **недодатною** (`ĉ_cascade ≤ 0`)!

У загальному випадку, якщо каскадування зачіпає вищі рівні (наприклад, `TV₂ ↦ TV₁ ↦ TV₀`), кожен елемент під час каскадування зменшує свій рівень щонайменше на 1. Оскільки потенціал таймера `Φ(x) = L` був «оплачений» наперед під час операції `Schedule`, реальна робота з перерозподілу таймерів спирається на накопичений потенціал.

Отже, повна амортизована складність операції `Tick()` залишається строго:

```text
ĉ_tick = O(1)
```

∎

## 5. Моделювання імовірнісного розподілу таймаутів

У реальних мережевих системах інтервали таймаутів розподілені нерівномірно. Розглянемо два поширені статистичні розподіли та їхній вплив на заповнення колеса таймерів.

### 5.1 Показниковий (експоненціальний) розподіл таймаутів

Мережеві запити та таймаути повторної передачі (RTO) зазвичай підпорядковуються показниковому розподілу з щільністю ймовірності:

```text
f(t) = λ · e^(-λt)
```

де `λ` — інтенсивність надходження подій.

Математичне очікування кількості таймерів, що потрапляють у слот колеса `TV₀` на кроці `k`, становить:

```text
E[M_k] = M_total · ∫ f(t) dt   [інтегрування від k·δ до (k+1)·δ]
       = M_total · (e^(-λ·k·δ) - e^(-λ·(k+1)·δ))
```

Оскільки більшість мережевих таймаутів є короткостроковими (велике значення `λ`), більшість таймерів потрапляє безпосередньо у перше колесо `TV₀`, минаючи вищі рівні. Це означає, що каскадування із коліс `TV₁`..`TV₄` викликається рідко і обробляє невеличкі списки елементів.

### 5.2 Оцінка дискретизаційного джиттеру та відносної похибки

Оскільки колесо таймерів округлює затримки до дискретних квантів `δ`, реальний час спрацьовування `t_real` відхиляється від запрошеного часу `t_req`.

Нехай `t_req` є випадковою величиною, рівномірно розподіленою на інтервалі `[T·δ, (T+1)·δ]`.
Абсолютна похибка дискретизації є випадковою величиною `ε = t_real - t_req ∈ [0, δ)`.

Математичне очікування похибки та її дисперсія становлять:

```text
E[ε] = δ / 2
Var(ε) = δ² / 12
```

Для сокетних таймаутів величиною 200 мс при кванті `δ = 1 ms` відносна похибка становить менше `0.5%`, що є повністю припустимим для мережевих стека та систем планування подій.

## 6. Багатовимірна оцінка пам'яткової складності

Окрім часової складності, важливим показником є витрата пам'яті структурою колеса таймерів.

Нехай `N_total = Σ N_i` — загальна кількість слотів у всіх колесах ієрархії, `M` — активна кількість таймерів у системі.

Розмір пам'яті для зберігання таймерного колеса розраховується як:

```text
Memory_total
= N_total · sizeof(head_pointer) + M · sizeof(timer_node_t)
```

Для 5-рівневого колеса у ядрах Linux:
* `N_total = 256 + 64 + 64 + 64 + 64 = 512` слотів;
* При розмірі вказівника 8 байтів масив слотів займає лише `512 · 8 = 4096` байтів (строго 1 сторінку пам'яті 4 КБ!).

Це доводить, що ієрархічні колеса таймерів надають надзвичайно високу пам'яткову ефективність у порівнянні з роздутими масивами однорівневих коліс.

## 7. Теоретико-числовий розрахунок оптимальної розрядності коліс

Нехай система повинна підтримувати максимальний часовий інтервал `T_max` при обмеженні на сумарну кількість слотів `N_limit`.

Для мінімізації середнього числа каскадувань авторами Варгезе та Лауком доведено, що розміри коліс `N_i` повинні задовольняти рівності:

```text
N_0 = 2^k_0
N_i = 2^k_i,   для i ≥ 1
```

де `k_0` обирається більшим за `k_i` (`k_0 > k_i`), оскільки перше колесо `TV_0` бере на себе основне навантаження короткотривалих мережевих подій. Конфігурація `k_0 = 8` (256 слотів) та `k_i = 6` (64 слоти) є математично оптимізованою для процесорного кешу L1 (розмір елемента кращий за розмір кеш-лінії 64 байти).

## 8. Граничний аналіз найгіршого випадку (Worst-Case Analysis)

У найгіршому теоретичному випадку, коли на одному тіку `current_tick` одночасно обгортаються всі `m` коліс ієрархії (наприклад, перехід від `T = 2³² - 1` до `T = 0`), виникає ланцюгове каскадування усіх рівнів: `TV₄ ↦ TV₃ ↦ TV₂ ↦ TV₁ ↦ TV₀`.

Якщо у кожному з вийманих слотів знаходиться по `K` елементів, сумарний час виконання каскаду становить:

```text
τ_worst_case = O(m · K)
```

Проте імовірність виникнення такої ситуації становить лише `1 / T_max = 1 / 2³² ≈ 2.3 · 10⁻¹⁰`. Завдяки цьому амортизований аналіз дає реальну оцінку продуктивності для регулярної роботи систем.

## 9. Аналіз стабільності та детермінізму затримок

Математичний детермінізм часів виконання операцій у колесі таймерів є ключовим для систем реального часу (Hard Real-Time Systems).
* Вставка (`Schedule`) вимагає обчислення бітового зсуву та запису 4 вказівників. Кількість інструкцій процесора є фіксованою та не залежить від стану колеса.
* Видалення (`Cancel`) виконується за строго `O(1)` операцій запису у пам'яті.
* Крок часу (`Tick`) за відсутності обгортання колеса є строго детермінованим `O(1)`.

---

## 10. Повна теорема про еквівалентність та відсутність порівнянь ключа

*Теорема:* У `m`-рівневому колесі таймерів з бітовою параметризацією кількість порівнянь часу спрацьовування `E_i` між двома довільними таймерами під час виконання операцій `Schedule`, `Cancel` та `Tick` дорівнює нулю (`0`).

*Доведення:* Індекс слота обчислюється виключно за допомогою бітового розсуву та маскування значень `E_i` та `T_current`. Жодна операція порівняння `E_i < E_j` не викликається на жодному етапі алгоритму. Оскільки операції порівняння відсутні, верхня межа інформаційної складності `O(N log N)` не застосовується, що доводить теоретичну можливість виконання операцій за константний час `O(1)`.

∎

## 11. Порівняльна таблиця складності структур даних

| Структура даних | Вставка (`Schedule`) | Скасування (`Cancel`) | Обробка тіку (`Tick`) | Пам'ять |
| :--- | :--- | :--- | :--- | :--- |
| **Невпорядкований список** | `O(1)` | `O(1)` | `O(N)` | `O(N)` |
| **Впорядкований список (Delta Chain)** | `O(N)` | `O(1)` | `O(1)` | `O(N)` |
| **Двійкова купа (Min-Heap)** | `O(log N)` | `O(log N)` | `O(1)` (найближчий) | `O(N)` |
| **Червоно-чорне дерево (RB-Tree)** | `O(log N)` | `O(log N)` | `O(log N)` | `O(N)` |
| **Однорівневий Timer Wheel (із Rounds)**| `O(1)` | `O(1)` | `O(1)` (найгірший `O(K)`) | `O(N + M)` |
| **Ієрархічний Timer Wheel (Cascading)** | **`O(1)`** | **`O(1)`** | **`O(1)` (амортиз.)** | **`O(Σ N_i + M)`** |

## 12. Математична гарантія відсутності лінійних переборів

Головний теоретичний здобуток ієрархічного колеса полягає у тому, що жоден елемент списку ніколи не піддається лінійному перебору чи порівнянню часу з іншими вузлами. Кожен таймер піддається лише безпосереднім операціям бітового розрахунку адреси слота під час вставки та переміщення під час каскадування. Завдяки цій властивості амортизований час залишається строго сталим під час масштабних навантажень.

---

## 13. Математичний зв'язок із теорією масового обслуговування

У теорії масового обслуговування (Queuing Theory) підсистема таймерів моделюється як система `M/M/1` з обмеженою довжиною черги. Колесо таймерів гарантує відсутність накопичення черги обробки під час пікового надходження подій, забезпечуючи детермінований час відгуку сервісу.

---

## 14. Висновок математичної теорії колеса таймерів

Формальний математичний аналіз підтверджує, що ієрархічні таймерні колеса є строго оптимальною структурою даних для обробки масових часових подій. Поєднання бітового хешування `E & (N-1)`, зсуву бітів `E >> Shift` та потенційного доведення недодатної амортизаційної вартості каскадування гарантує високу продуктивність систем у промислових умовах. Завдяки цим властивостям таймерне колесо є основою систем відліку часу.
