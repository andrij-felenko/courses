# 📋 Інтерфейс та специфікація API колеса таймерів

Наведено повний довідник структур даних, типів, макросів, сигнатур функцій та кодових відповідей C/C++ бібліотеки управління таймерними колесами.

---

## 1. Архітектура специфікації та концепція контракту

Бібліотека таймерного колеса надає системний інтерфейс для реєстрації, скасування та планування зворотних викликів (callbacks), прив'язаних до дискретних інтервалів часу. Специфікація розроблена із розрахунком на нульові накладні витрати (Zero-Overhead Abstraction) у критичних секціях високонавантажених серверних застосунків, мережевих стеків та операційних систем реального часу.

Головний контракт інтерфейсу базується на трьох непорушних гарантіях:
1. **Гарантія швидкості вставки:** додавання нового таймера через виклик `timer_wheel_add` виконується за константний час `O(1)` незалежно від кількості вже запланованих подій.
2. **Гарантія вилучення за ідентифікатором:** видалення таймера за допомогою `timer_wheel_cancel` за його 64-бітним ідентифікатором або безпосереднім вказівником виконується за `O(1)` без обходу масивів чи дерев.
3. **Гарантія ізоляції зворотного виклику:** під час виконання callback-функції слот колеса очищається **до** виклику функції користувача, що унеможливлює повторну обробку того самого вузла або пошкодження структури при рекурсивному додаванні нових подій зсередини callback.

Таймерне колесо оперує концепцією монотонного дискретного часу. Системний час виражається цілим лічильником тіків (clock ticks). Кожен крок відповідає сталому інтервалу фізичного часу (наприклад, 1 мілісекунді). Застосунок просуває колесо за допомогою періодичного виклику `timer_wheel_tick`, що дозволяє легко інтегрувати структуру даних у будь-який подійний цикл (Event Loop) або системний обробник переривань.

## 2. Константи, макроси та коди помилок

### 2.1 Коди повернення та статусів (`tw_status_t`)

Усі функції системного API повертають цілочисельний статус виконання типу `tw_status_t`. Від'ємні значення відповідають помилкам виконання, а нульове значення свідчить про успішне завершення операції.

| Константа | Значення | Опис |
| :--- | :--- | :--- |
| `TW_SUCCESS` | `0` | Операція виконана успішно без помилок. |
| `TW_ERR_INVALID_PARAM` | `-1` | Передано неприпустимий аргумент (наприклад `NULL` вказівник або нульовий callback). |
| `TW_ERR_NOMEM` | `-2` | Не вдалося виділити пам'ять під новий вузол таймера. |
| `TW_ERR_OUT_OF_RANGE` | `-3` | Запитувана затримка таймера перевищує максимально підтримуваний діапазон ієрархії. |
| `TW_ERR_NOT_FOUND` | `-4` | Таймер із зазначеним ідентифікатором не знайдено у структурі даних (наприклад, вже спрацював). |
| `TW_ERR_ALREADY_RUNNING` | `-5` | Спроба модифікації або скасування таймера безпосередньо під час виконання його callback-функції. |

Детальний прозовий опис сценаріїв відмови:
* **Помилка `TW_ERR_INVALID_PARAM`:** виникає при передачі `NULL` у якості аргументу `wheel` або `callback`. Цей статус охороняє внутрішній цикл від виклику за нульовою адресою (Segmentation Fault) та запобігає передачі неприпустимих конфігураційних прапорців.
* **Помилка `TW_ERR_NOMEM`:** сигналізує про вичерпання купи операційної системи або внутрішнього пулу вузлів (Memory Pool). При отриманні цього коду застосунок мусить скинути некритичні сокетні таймаути або обробити недостатність ресурсів без аварійного завершення процесу.
* **Помилка `TW_ERR_OUT_OF_RANGE`:** генерується, коли передана затримка у тіках `delay_ticks` перевищує максимальну місткість ієрархії `T_max`. Застосунок повинен розбити довготривалу подію на серію проміжних таймаутів або застосувати фоновий лічильник обертів.
* **Помилка `TW_ERR_ALREADY_RUNNING`:** захищає від стану гонитви (Race Condition), коли один потік намагається скасувати таймер у момент, коли інший потік виконує його callback.

### 2.2 Прапорці конфігурації таймерів (`tw_flags_t`)

Поведінка окремого таймера визначається бітовою маскою прапорців, що передаються під час створення.

| Прапорець | Бітова маска | Опис |
| :--- | :--- | :--- |
| `TW_FLAG_ONESHOT` | `0x0001` | Одноразовий таймер. Автоматично вилучається з пам'яті після першого спрацьовування. |
| `TW_FLAG_PERIODIC` | `0x0002` | Періодичний таймер. Після спрацьовування автоматично перезапускається з тим самим інтервалом. |
| `TW_FLAG_PINNED` | `0x0004` | Прив'язаний таймер. Забороняє мимовільне перенесення між процесорними ядрами. |
| `TW_FLAG_HIGH_PRIO` | `0x0008` | Високоприоритетний таймер. Обробляється у першу чергу на поточному тіку. |

## 3. Базові типи даних та структури

### 3.1 Скалярні типи

Для забезпечення переносності між 32-бітними та 64-бітними архітектурами інтерфейс декларує чітко розмірні скалярні типи.

```cpp
typedef uint64_t timer_id_t;
typedef uint64_t timer_tick_t;
typedef int32_t  tw_status_t;
```

* **`timer_id_t`:** унікальний 64-бітний ідентифікатор таймера. Генерація ID базується на монотонному лічильнику, що гарантує відсутність дублікатів протягом понад 500 років безперервної роботи при мільйоні вставок на секунду.
* **`timer_tick_t`:** тикова цілочисельна шкала часу. Представляє абсолютну кількість переривань системного годинника від моменту старта колеса.

### 3.2 Сигнатура зворотного виклику

```cpp
typedef void (*timer_callback_t)(timer_id_t id, void *user_data);
```

Функція зворотного виклику отримує два аргументи: унікальний ідентифікатор таймера `id` та довільний вказівник на контекст користувача `user_data` (наприклад, вказівник на структуру сокета чи з'єднання).

### 3.3 Структура вузла таймера (`timer_node_t`)

Вузол таймера є елементом подвійно зв'язаного списку. Для запобігання фальшивому спільному використанню кешу (False Sharing) структура може бути вирівняна по межі кеш-лінії процесора (64 байти).

```cpp
struct timer_node {
    timer_id_t       id;          /* Унікальний ідентифікатор таймера */
    timer_tick_t     expires;     /* Абсолютний час спрацьовування у тіках */
    timer_tick_t     interval;    /* Інтервал повтору для періодичних таймерів */
    uint32_t         flags;       /* Бітові прапорці конфігурації TW_FLAG_* */
    timer_callback_t callback;    /* Вказівник на функцію зворотного виклику */
    void            *user_data;   /* Контекстний вказівник даних користувача */
    struct timer_node *prev;      /* Вказівник на попередній вузол списку слота */
    struct timer_node *next;      /* Вказівник на наступний вузол списку слота */
};
typedef struct timer_node timer_node_t;
```

Детальний прозовий аналіз полів вузла:
* **Поле `expires`:** зберігає абсолютний дискретний час `T_expire = T_current + delay`. Використовується при каскадуванні для точного визначення нового слота у нижчому колесі.
* **Поле `interval`:** зберігає початкову затримку для періодичних таймерів. Якщо встановлено прапорець `TW_FLAG_PERIODIC`, після виконання callback вузол не знищується, а повторно додається у колесо із затримкою `expires = current_tick + interval`.
* **Вказівники `prev` та `next`:** забезпечують видалення вузла зі слота за `O(1)` без знання голови списку. Якщо `prev == NULL`, вузол є першим елементом у слоті.

### 3.4 Структура таймерного колеса (`timer_wheel_t`)

```cpp
struct timer_wheel_s {
    timer_tick_t     current_tick; /* Поточний системний час у тіках */
    uint32_t         timer_count;  /* Активна кількість таймерів у системі */
    
    /* Слоти ієрархічних коліс */
    timer_node_t    *tv1[256];     /* Колесо 1: 256 слотів (8 бітів) */
    timer_node_t    *tv2[64];      /* Колесо 2: 64 слоти (6 бітів) */
    timer_node_t    *tv3[64];      /* Колесо 3: 64 слоти (6 бітів) */
    timer_node_t    *tv4[64];      /* Колесо 4: 64 слоти (6 бітів) */
    
    void            *lock_mutex;   /* Вказівник на м'ютекс або спінлок */
};
typedef struct timer_wheel_s timer_wheel_t;
```

## 4. Специфікація системних функцій API

### 4.1 `timer_wheel_create`

Створює новий екземпляр ієрархічного колеса таймерів та виділяє пам'ять під ієрархічні слоти.

```cpp
tw_status_t timer_wheel_create(
    timer_wheel_t **out_wheel,
    timer_tick_t start_tick
);
```

* **Детальний опис параметрів:**
  * `out_wheel` `[out]`: вказівник на змінну типу `timer_wheel_t*`. У разі успішного виконання сюди записується адреса створеного об'єкта.
  * `start_tick` `[in]`: початкове значення системного часу. Для нових систем передають `0`, для систем після перезапуску — збережене значення монотонного лічильника.
* **Правила використання та прекондішени:**
  * Параметр `out_wheel` не повинен бути `NULL`.
  * Функція мусить викликатися до будь-яких операцій додавання чи обробки тіків.
* **Повернені значення та обробка помилок:**
  * `TW_SUCCESS` — колесо успішно створене й ініціалізоване.
  * `TW_ERR_INVALID_PARAM` — `out_wheel == NULL`.
  * `TW_ERR_NOMEM` — система не змогла виділити пам'ять під екземпляр `timer_wheel_t`.
* **Побічні ефекти:** виділяє блок пам'яті в купі (heap). Всі голови слотів `tv1`..`tv4` обнуляються.
* **Часова складність:** `O(1)` (ініціалізація фіксованого числа слотів).

---

### 4.2 `timer_wheel_destroy`

Звільняє всі ресурси колеса таймерів, скасовує незавершені події та вилучає об'єкт із пам'яті.

```cpp
tw_status_t timer_wheel_destroy(
    timer_wheel_t *wheel
);
```

* **Детальний опис параметрів:**
  * `wheel` `[in]`: вказівник на дійсний екземпляр колеса таймерів, створений функцією `timer_wheel_create`.
* **Правила використання:**
  * Після виклику цієї функції використання вказівника `wheel` заборонене.
  * Якщо в колесі залишалися невиконані таймери, пам'ять усіх вузлів звільняється без виклику їхніх callback-функцій.
* **Повернені значення:**
  * `TW_SUCCESS` — всі ресурси звільно.
  * `TW_ERR_INVALID_PARAM` — передано `wheel == NULL`.
* **Складність:** `O(N + M)`, де `N` — сумарна кількість слотів, `M` — кількість незавершених таймерів.

---

### 4.3 `timer_wheel_add`

Планує виконання нового таймера з заданою відносною затримкою.

```cpp
tw_status_t timer_wheel_add(
    timer_wheel_t *wheel,
    timer_tick_t delay_ticks,
    timer_callback_t callback,
    void *user_data,
    uint32_t flags,
    timer_id_t *out_id
);
```

* **Детальний опис параметрів:**
  * `wheel` `[in]`: екземпляр колеса таймерів.
  * `delay_ticks` `[in]`: затримка виконання у тіках (`delay_ticks > 0`).
  * `callback` `[in]`: вказівник на функцію зворотного виклику користувача.
  * `user_data` `[in]`: довільний контекстний вказівник, який буде передано в `callback`.
  * `flags` `[in]`: бітова маска конфігураційних прапорців (`TW_FLAG_ONESHOT`, `TW_FLAG_PERIODIC`).
  * `out_id` `[out, optional]`: адреса для збереження згенерованого унікального ID таймера. Може бути `NULL`, якщо застосунок не планує скасовувати таймер вручну.
* **Правила використання та крайові випадки:**
  * Якщо `delay_ticks == 0`, таймер розміщується у поточний слот `tv1` і спрацює при найближчому виклику `timer_wheel_tick`.
  * Запитувана затримка не мусить перевищувати місткість ієрархії (для 4 коліс — 4 294 967 295 тіків).
* **Повернені значення:**
  * `TW_SUCCESS` — таймер успішно розрахований і доданий у відповідний слот.
  * `TW_ERR_INVALID_PARAM` — `wheel == NULL` або `callback == NULL`.
  * `TW_ERR_OUT_OF_RANGE` — `delay_ticks` перевищує `T_max`.
  * `TW_ERR_NOMEM` — помилка виділення пам'яті під вузол.
* **Часова складність:** **строгий `O(1)`**.

---

### 4.4 `timer_wheel_cancel`

Видаляє запланований таймер за його ідентифікатором до моменту його спрацьовування.

```cpp
tw_status_t timer_wheel_cancel(
    timer_wheel_t *wheel,
    timer_id_t timer_id
);
```

* **Детальний опис параметрів:**
  * `wheel` `[in]`: екземпляр колеса таймерів.
  * `timer_id` `[in]`: ідентифікатор таймера, отриманий при виклику `timer_wheel_add`.
* **Правила використання:**
  * Операція скасування є безпечною: якщо таймер вже виконався або був скасований раніше, функція повертає статус `TW_ERR_NOT_FOUND` без збою програми.
* **Повернені значення:**
  * `TW_SUCCESS` — таймер знайдено, вилучено зі списку слота та вилучено з пам'яті.
  * `TW_ERR_NOT_FOUND` — таймера з таким ID не існує в системі.
* **Часова складність:** **`O(1)`** (при збереженні вказівника у структурі сокета або використання внутрішнього хеш-вікна).

---

### 4.5 `timer_wheel_tick`

Просуває системний час колеса на один крок, виконує каскадування таймерів між рівнями та викликає зворотні виклики дозрілих подій.

```cpp
tw_status_t timer_wheel_tick(
    timer_wheel_t *wheel,
    uint32_t *out_executed_count
);
```

* **Детальний опис параметрів:**
  * `wheel` `[in]`: екземпляр колеса таймерів.
  * `out_executed_count` `[out, optional]`: адреса для збереження кількості виконаних таймерів під час цього тіку.
* **Послідовність системних дій:**
  1. Лічильник `wheel->current_tick` збільшується на 1.
  2. Обчислюється поточний слот першого колеса: `slot1 = current_tick & 0xFF`.
  3. Якщо `slot1 == 0`, викликається внутрішній механізм каскадування, який переносить елементи із відповідного слота `tv2` у `tv1`. При необхідності каскадування поширюється на `tv3` та `tv4`.
  4. Список таймерів зі слота `slot1` виймається в локальну змінну, а сам слот обнуляється.
  5. У циклі викликаються callback-функції усіх вийнятих таймерів.
* **Повернені значення:**
  * `TW_SUCCESS` — крок часу успішно оброблено.
  * `TW_ERR_INVALID_PARAM` — `wheel == NULL`.
* **Часова складність:** **амортизований `O(1)`**.

---

### 4.6 `timer_wheel_get_stats`

Повертає поточну телеметрію та статистику роботи колеса таймерів для моніторингу продуктивності.

```cpp
typedef struct {
    uint64_t total_added;     /* Загальна кількість запланованих таймерів */
    uint64_t total_cancelled; /* Кількість скасованих таймерів */
    uint64_t total_expired;   /* Кількість виконаних таймерів */
    uint64_t total_cascaded;  /* Кількість елементів, що пройшли каскадування */
    uint32_t active_count;    /* Кількість активних таймерів у системі */
} timer_wheel_stats_t;

tw_status_t timer_wheel_get_stats(
    const timer_wheel_t *wheel,
    timer_wheel_stats_t *out_stats
);
```

* **Детальний опис параметрів:**
  * `wheel` `[in]`: екземпляр колеса таймерів.
  * `out_stats` `[out]`: адреса структури `timer_wheel_stats_t` для запису накопичених лічильників.
* **Призначення:** використовується системами моніторингу (Prometheus, Datadog) для аналізу інтенсивності створення та скасування таймаутів у серверах.

### 4.7 `timer_wheel_dump`

Виводить текстовий зріз внутрішнього стану слотів для налагодження та діагностики витоків пам'яті.

```cpp
tw_status_t timer_wheel_dump(
    const timer_wheel_t *wheel,
    FILE *stream
);
```

* **Призначення:** друкує інформацію про розподіл таймерів по слотах коліс `TV1`..`TV4`. Використовується при тестуванні для перевірки відсутності накопичення нескасованих таймерів.

## 5. Схема інтеграції з подійними циклами (Event Loops)

У сучасних Linux-застосунках колесо таймерів інтегрують із системним викликом `epoll` через файловий дескриптор таймера `timerfd`.

### 5.1 Інтеграційний приклад на мовах C та C++

:::tabs
@tab C
```c
#include <sys/timerfd.h>
```

## 6. Багатопотоковість та контракти блокування

Класичне колесо таймерів не є атомарно потокобезпечним. При використанні у багатопотокових середовищах застосовують два підходи:

1. **Модель із зовнішнім м'ютексом (External Locking):** усі виклики `add`, `cancel` та `tick` захищаються м'ютексом або спінлоком (`pthread_spinlock_t`). Це підходить для помірної кількості потоків.
2. **Модель без блокувань (Per-CPU / Per-Thread Timer Wheel):** кожен потік обробки (Event Loop Worker) утримує **власний незалежний екземпляр `timer_wheel_t`**. Таймери додаються тільки у колесо поточного потоку. Це повністю усуває конкуренцію за шину пам'яті (Lock-Free Multi-threading) та гарантує максимальну продуктивність на багатоядерних системах.

## 7. Специфікація розширених макросів та хелперів

Для прискорення роботи у внутрішніх модулях бібліотека надає набір низькорівневих побітових макросів:

```cpp
#define TW_SLOT_MASK(bits)       ((1U << (bits)) - 1)
#define TW_COMPUTE_SLOT(val, s, m) (((val) >> (s)) & (m))
```

* **Макрос `TW_SLOT_MASK`:** генерує бітову маску заданого розміру `2^bits - 1`.
* **Макрос `TW_COMPUTE_SLOT`:** обчислює індекс слота за допомогою вказівки зсуву `s` та маски `m`. Застосовується внутрішніми функціями `timer_wheel_add` та `cascade` для швидкого вирахування слотів без виклику функцій.

## 8. Гарантії безпеки пам'ятки та виправлення ресурсів

Системний інтерфейс гарантує відсутність витоків пам'яті за дотримання двох базових правил контракту:
1. Застосунок зобов'язаний викликати `timer_wheel_destroy` при завершенні підсистеми для звільнення всіх активних таймерів.
2. Усі вузли таймерів `timer_node_t`, вилучені при скасуванні `timer_wheel_cancel` або виконанні `timer_wheel_tick`, звільняються бібліотекою автоматично.

## 11. Політика сумісності версій та системні вимоги

Бібліотека таймерного колеса забезпечує повну ABI/API сумісність у межах мажорної версії `v1.x`:
* Потрібен компілятор C з підтримкою стандарту C99 або новішого.
* Потрібен компілятор C++ з підтримкою стандарту C++17 або новішого.
* Системні виклики часу повинні надавати монотонне джерело `CLOCK_MONOTONIC`.
* Структура даних розроблена так, щоб гарантувати працездатність на будь-яких POSIX-сумісних ОС (Linux, FreeBSD, macOS) та Windows Server.
* Гарантується відсутність залежностей від сторонніх бібліотек, крім стандартних системних заголовков C/C++.

## 12. Потокобезпека та контракти паралельного доступу (Thread-Safety Contract)

При проєктуванні багатопотокових мережевих застосунків важливо чітко розрізняти контексти виклику API функцій:
1. **Режим Single-Threaded (За замовчуванням):** якщо колесо використовується в межах одного event loop потоку, жодна синхронізація не потрібна.
2. **Режим Multi-Threaded:** якщо таймери створюються потоками-воркерами (Worker Threads), а виклик `timer_wheel_tick` здійснюється окремим потоком часу, всі виклики API повинні бути загорнуті у м'ютекс `pthread_mutex_t` або спінлок. Застосування роздільних колес на потік усуває ці затримки.
3. **Гарантія відсутності блокувань у callbacks:** під час виконання функцій зворотного виклику м'ютекс колеса розблоковується, що унеможливлює виникнення взаємних блокувань (Deadlocks) при зверненні до колеса зсередини обробника.

## 13. Сумісність із мовами C++20 та C++23

C++ обгортка таймерного колеса підтримує концепції C++20 (Concepts) та `std::chrono::duration`:
```cpp
template <typename Rep, typename Period>
void schedule_duration(std::chrono::duration<Rep, Period> d, Callback cb);
```
Це дозволяє розробникам передавати інтервали `std::chrono::milliseconds(100)` або `std::chrono::seconds(5)` без імпорту допоміжних типів. Інтерфейс також надає повну сумісність із новітнім стандартом C++23, гарантуючи відсутність застарілих конструкцій (deprecated syntax).
