<preknowlist>

- [Quickselect](root:sf-algorithms/quickselect) — пошук k-ї порядкової статистики за лінійний середній час.
- [Кільцевий буфер](root:sf-algorithms/ring-buffer) — фіксоване ковзне вікно в пам'яті.
</preknowlist>

Коли цифровий термометр робить десять послідовних вимірювань, дев'ять відліків лягають біля `24.0°C` із крихітним тепловим тремтінням (`23.9`, `24.1`, `24.0`), а в десятому через наводку по шині живлення стається збій АЦП і виникає `240.0°C`. Звичайне [середнє арифметичне](root:math-probability/averaging) додасть усі десять чисел і видасть `45.6°C`: один-єдиний спайк спотворив усю оцінку, звівши нанівець роботу дев'яти чесних вимірів. Якщо ж для захисту взяти [медіану](root:sf-algorithms/median-filter), вона бездоганно відкине `240.0°C` і поверне `24.0°C`, проте медіана дивиться лише на один центральний відлік і повністю ігнорує решту вісім чистих вимірювань, втрачаючи понад третину точності придушення випадкового шуму.

Природний вихід із цієї дилеми — відкинути лише кілька найбільш підозрілих екстремальних значень з обох боків, а всі центральні відліки, які залишилися, чесно усереднити.

### Механізм відтинання хвостів

Щоб позбутися аномалій і водночас зберегти статистичну силу усереднення, над вибіркою з `N` елементів виконують послідовність кроків:

1. **Впорядкування**: вибірку сортують за зростанням, утворюючи варіаційний ряд `x[(1)] ≤ x[(2)] ≤ ... ≤ x[(N)]`.
2. **Відсікання країв**: фіксовану кількість `k` найменших значень (лівий хвіст) та `k` найбільших значень (правий хвіст) вилучають із подальшого розрахунку.
3. **Усереднення ядра**: для решти `N - 2k` центральних елементів обчислюють звичайне середнє арифметичне.

![Механізм відтинання хвостів: сортування, вилучення крайніх елементів та усереднення центрального ядра](/root/eng/sf-algorithms/trimmed-mean/img/trim-mechanism.svg)
*Механізм відтинання країв для вікна з десяти відліків при відкиданні двох найменших і двох найбільших значень. Аномальні викиди гарантовано опиняються на флангах відсортованого ряду й не потрапляють у підсумкову суму.*

Описана оцінка називається **усіченим середнім** (англ. *trimmed mean*, також *truncated mean*; від лат. *truncāre* — обтинати, вкорочувати; середнє — від прасл. *serda* — середина). 

Частку відкинутих спостережень з одного краю позначають грецькою літерою `α` (альфа), де `α = k / N` (при цьому сумарно з обох боків відкидається частка `2α`). Якщо відтинання симетричне, алгоритм називають **`α`-усіченим середнім**.

**Приклад (ручний розрахунок для вибірки з десятьма відліками).** Нехай маємо `N = 10` показів датчика температури: `24.1`, `23.9`, `120.5`, `24.0`, `24.2`, `-15.0`, `23.8`, `24.3`, `24.0`, `24.1`. Обчислимо `20%`-усічене середнє (`α = 0.20`, тобто `k = 10 · 0.20 = 2` відліки з кожного краю):

```
Вхідний масив:
X = [24.1, 23.9, 120.5, 24.0, 24.2, -15.0, 23.8, 24.3, 24.0, 24.1]

1. Впорядкований ряд x[(i)]:
[-15.0, 23.8, 23.9, 24.0, 24.0, 24.1, 24.1, 24.2, 24.3, 120.5]

2. Відтинаємо k=2 найменших [-15.0, 23.8] і k=2 найбільших [24.3, 120.5]

3. Центральне ядро (N - 2k = 6 елементів):
[23.9, 24.0, 24.0, 24.1, 24.1, 24.2]

4. Обчислення середнього:
Сума = 23.9 + 24.0 + 24.0 + 24.1 + 24.1 + 24.2
     = 144.3
Середнє = 144.3 / 6
        = 24.05°C
```

Звичайне середнє для цих самих десяти чисел дало б `31.47°C` (помилка на `+7.4°C` через два спайки), тоді як усічене середнє повернуло точну величину `24.05°C`.

### Граничні стани: континуум між середнім і медіаною

Параметр `k` (або частка `α`) визначає баланс між двома крайніми режимами:

```
k = 0                  (α = 0)     → класичне середнє арифметичне
1 ≤ k < ⌊(N - 1) / 2⌋  (0 < α < 0.5) → усічене середнє
k = ⌊(N - 1) / 2⌋      (α → 0.5)   → медіана вибірки
```

Коли `k = 0`, ми не відкидаємо нічого — маємо звичайне усереднення, оптимальне за відсутності спайків. Коли `k` зростає до максимуму `⌊(N - 1) / 2⌋`, у вибірці залишається лише один центральний елемент (для непарного `N`) або два центральних (для парного `N`), що перетворює алгоритм на класичну медіану.

Окремим популярним випадком є **міжквартильне середнє** (англ. *interquartile mean*, IQM), для якого `α = 0.25` (`25%`). У ньому відкидають перший і четвертий квартилі (сумарно `50%` крайніх даних) та усереднюють рівно центральні `50%` вибірки:

```
IQM = (1 / (0.5 · N)) · ∑ x[(i)]      [для i від ⌊N/4⌋ + 1 до N - ⌊N/4⌋]
```

### Точка зламу та стійкість до спайків

У стійкій статистиці міру витривалості алгоритму до спотворень описують фундаментальною характеристикою — **точкою зламу** (англ. *breakdown point*, поняття ввів швейцарський статистик Франк Гампель, Frank Hampel; від давн.-гр. *στατικός* — нерухомий, стійкий). Точка зламу `ε*` показує, яку граничну частку вибірки можна зробити як завгодно великою або спотвореною, перш ніж оцінка сама стане нескінченно великою чи довільно зміщеною.

Для звичайного середнього арифметичного достатньо **одного** спотвореного значення серед мільйона, щоб потягнути результат куди завгодно:

```
ε*(середнє) = 1 / N
= 0             [при N → ∞: нульова стійкість]
```

Для медіани потрібно зіпсувати понад половину вибірки:

```
ε*(медіана) = ⌊(N + 1) / 2⌋ / N
≈ 50%           [максимально можлива стійкість для інваріантних оцінок]
```

Для `α`-усіченого середнього точка зламу точно дорівнює частці відтинання `α`:

```
ε*(α-усічене) = ⌊α · N⌋ / N
≈ α             [стійкість прямо пропорційна глибині відтинання]
```

Якщо обрано `α = 0.20` (`20%`), вибірка може містити до `20%` довільно спотворених відліків зверху і до `20%` знизу. Жодне з цих значень взагалі не вплине на результат, оскільки вони гарантовано опиняться за межами індексів підсумовування `[k + 1, N - k]`.

![Компроміс між стійкістю до викидів і ефективністю на гаусовому шумі](/root/eng/sf-algorithms/trimmed-mean/img/tradeoff.svg)
*Спектр оцінок центру положення. Зі зростанням частки відсікання α точка зламу лінійно зростає від 0% до 50%, тоді як статистична ефективність на чистому гаусовому розподілі плавно знижується від 100% до 63.7%.*

### Статистична ефективність на гаусовому шумі

Чому б завжди не використовувати медіану з її максимальною точкою зламу `50%`? Причина криється в **асимптотичній відносній ефективності** (англ. *Asymptotic Relative Efficiency*, ARE). 

Якщо вхідний сигнал містить лише чисто гаусів білий шум із дисперсією `σ²` без грубих спайків, найкращою незміщеною оцінкою за теоремою Гауса — Маркова є звичайне середнє: дисперсія його похибки дорівнює `σ² / N`. Для медіани дисперсія оцінки на гаусовому розподілі значно вища:

```
Var(медіана) = (π / 2) · (σ² / N)
≈ 1.571 · (σ² / N)    [дисперсія на 57.1% вища, ніж у середнього]
```

Це означає, що ефективність медіани становить:

```
ARE(медіана) = 1 / (π / 2)
= 2 / π
≈ 63.7%
```

Щоб досягти такої ж точності фільтрації чистого шуму за допомогою медіани, потрібно зібрати у `1.57` раза більше фізичних замірів датчика.

Усічене середнє відновлює цю втрачену точність. Оскільки воно усереднює цілу групу центральних відліків, його дисперсія на гаусових даних майже не поступається повному середньому:

| Оцінка | Частка `α` | Точка зламу `ε*` | Ефективність (ARE на Гаусі) | Дисперсія похибки |
|---|---|---|---|---|
| Середнє арифметичне | `0%` | `0%` | `100.0%` | `1.000 · σ² / N` |
| `5%`-усічене середнє | `5%` | `5%` | `98.5%` | `1.015 · σ² / N` |
| `10%`-усічене середнє | `10%` | `10%` | `96.0%` | `1.042 · σ² / N` |
| `20%`-усічене середнє | `20%` | `20%` | `91.5%` | `1.093 · σ² / N` |
| Міжквартильне (IQM) | `25%` | `25%` | `88.3%` | `1.132 · σ² / N` |
| Медіана вибірки | `50%` | `50%` | `63.7%` | `1.571 · σ² / N` |

Відтинання всього `10%` екстремумів гарантує захист від поодиноких збоїв та важких хвостів розподілу, зберігаючи водночас `96%` теоретичної точності придушення білого шуму.

![Порівняння реакції оцінок на шум, спайки та зміну рівня](/root/eng/sf-algorithms/trimmed-mean/img/noise-response.svg)
*Поведінка оцінок на комбінованому сигналі. Звичайне середнє розмазує спайки у широкі хвилі. Медіана знищує спайки, але залишає сходинковість на шумі. Усічене середнє поєднує повну ліквідацію спайків із плавним придушенням шуму.*

### Математичний вивід: функція впливу та асимптотична дисперсія

Щоб суворо зрозуміти, чому усічене середнє є стійким, звернемося до апарату **функцій впливу** (англ. *Influence Function*, IF), введеного Франком Гампелем. Функція впливу `IF(x; T, F)` показує реакцію функціонала оцінки `T` на додавання нескінченно малої частки забруднення в точці `x` до базового розподілу ймовірностей `F`:

```
IF(x; T, F) = lim [ (T((1 - ε)·F + ε·Δ[x]) - T(F)) / ε ]    [при ε → 0]
```
де `Δ[x]` — одинична ймовірнісна маса, зосереджена в точці `x`.

Для класичного середнього функція впливу лінійна й необмежена:

```
IF(x; Середнє, F) = x - μ
```
Коли величина викиду `x → ∞`, вплив `IF → ∞`, що підтверджує нульову стійкість середнього.

Для `α`-усіченого середнього над симетричним розподілом із нульовим центром функція впливу має вигляд насиченої лінійної функції:

```
IF(x; TrimmedMean_α, F) =
  -x[α] / (1 - 2α),  якщо x < -x[α]
   x / (1 - 2α),     якщо -x[α] ≤ x ≤ x[α]
   x[α] / (1 - 2α),  якщо x > x[α]
```
де `x[α] = F⁻¹(1 - α)` — верхній `(1 - α)`-квантиль розподілу.

Оскільки `IF(x)` обмежена константою `± x[α] / (1 - 2α)`, граничний вплив будь-якого екстремального викиду фіксований і не може зрушити оцінку далі цієї константи.

З функції впливу безпосередньо виводиться асимптотична дисперсія `V(α, F)` оцінки:

```
V(α, F) = ∫ [ IF(x; TrimmedMean_α, F) ]² dF(x)
        = (1 / (1 - 2α)²) · [ ∫ x² dF(x) + 2α · (x[α])² ]    [інтеграл від -x[α] до x[α]]
```

Для стандартного нормального розподілу `N(0, 1)`, де `x[0.10] ≈ 1.2816`, інтегрування дає чисельне значення `V(0.10, Φ) ≈ 1.042`, звідки дисперсія вибіркового `10%`-усіченого середнього дорівнює `1.042 · σ² / N`.

### Поведінка на важкохвостих розподілах

Перевага усіченого середнього над звичайним стає абсолютною, коли розподіл похибок відхиляється від ідеального нормального дзвона у бік важких хвостів:

```
Розподіл Лапласа (подвійний експоненційний):
f(x) = (1 / 2b) · exp(-|x| / b)
```
На розподілі Лапласа звичайне середнє втрачає ефективність (`ARE = 50%`), тоді як медіана є оцінкою максимальної правдоподібності (`ARE = 100%`). `20%`-усічене середнє досягає на ньому ефективності `82%`, перевершуючи класичне середнє у понад півтора раза.

```
Розподіл Стьюдента з трьома степенями вільності (t3):
```
Має важкі хвости й моделює сильний імпульсний шум датчиків. На ньому:
- Звичайне середнє має низьку ефективність `ARE = 40%` через великий розкид хвостів;
- Медіана має `ARE = 67%`;
- `20%`-усічене середнє показує найкращий результат серед усіх — `ARE = 88%`.

```
Розподіл Коші (Cauchy distribution):
f(x) = 1 / (π · γ · (1 + ((x - x0) / γ)²))
```
Для розподілу Коші математичне сподівання та дисперсія взагалі не існують. Звичайне середнє вибірки будь-якого розміру `N` не збігається до константи (середнє десяти чисел має такий самий розкид, як один відлік). Водночас `α`-усічене середнє (`α ≥ 0.10`) має строго скінченну дисперсію і стабільно збігається до центру розподілу `x0` за законом `1 / √N`.

### Дрібно-пропорційне усічення

Коли добуток `α · N` не є цілим числом (наприклад, для вибірки з `N = 8` відліків ми обрали частку `α = 0.15`, звідки `α · N = 1.2`), просте округлення `k = ⌊1.2⌋ = 1` відкине менше ніж `15%`, а `k = 2` — аж `25%`.

Для точного збереження заданої частки `α` застосовують **зважене інтерполяційне усічення**. Дробову частину `g = α · N - ⌊α · N⌋` використовують як коефіцієнт ваги для межових порядкових статистик:

1. Нехай `k = ⌊α · N⌋` — кількість елементів, що відкидаються повністю.
2. Елементи з рангами від `(k + 2)` до `(N - k - 1)` беруться з повною вагою `1.0`.
3. Межові елементи з рангами `(k + 1)` та `(N - k)` беруться з частковою вагою `w = 1.0 - g`.

Повна формула зваженого `α`-усіченого середнього набуває вигляду:

```
TrimmedMean(α) = (1 / (N · (1 - 2α))) · [ (1 - g)·x[(k+1)] + ∑ x[(i)] + (1 - g)·x[(N-k)] ]
```
де підсумовування `∑` ведеться за всіма внутрішніми рангами `i` від `k + 2` до `N - k - 1`.

**Приклад (зважування межових рангів).** Нехай `N = 5`, `α = 0.15`. Відсортовані відліки: `[10.0, 12.0, 13.0, 15.0, 20.0]`.

```
1. Обчислення дробів:
α · N = 0.15 · 5 = 0.75
k = ⌊0.75⌋ = 0        [повністю не відкидаємо жодного]
g = 0.75 - 0 = 0.75   [дробова частина]
w = 1 - 0.75 = 0.25   [вага межових елементів x[(1)] та x[(5)]]

2. Знаменник суми ваг:
W_total = N · (1 - 2α)
        = 5 · (1 - 0.30)
        = 3.5

3. Чисельник зваженої суми:
S = (1 - g)·x[(1)] + x[(2)] + x[(3)] + x[(4)] + (1 - g)·x[(5)]
  = 0.25·10.0 + 1.0·12.0 + 1.0·13.0 + 1.0·15.0 + 0.25·20.0
  = 2.5 + 12.0 + 13.0 + 15.0 + 5.0
  = 47.5

4. Зважене усічене середнє:
Результат = S / W_total
          = 47.5 / 3.5
          ≈ 13.57
```

У мікроконтролерних та DSP-застосунках найчастіше обирають фіксовані розміри вікон `N` та значення `α`, за яких `k = α · N` є строго цілим числом, щоб уникати зайвого множення з рухомою комою.

### Споріднені робастні оцінки

Усічене середнє є частиною сімейства оцінок центру положення L-типу (лінійних комбінацій порядкових статистик). Корисно розуміти його відмінність від близьких алгоритмів:

```
Вхідний впорядкований ряд:  [ 2,  8, 10, 11, 12, 14, 99 ]  (N=7, k=1)

Усічення (Trimming):         [ ✗,  8, 10, 11, 12, 14,  ✗ ]  → сума = 55 / 5 = 11.0
Вінзоризація (Winsorization):[ 8,  8, 10, 11, 12, 14, 14 ]  → сума = 77 / 7 = 11.0
Медіана (Median):            [ ✗,  ✗,  ✗, 11,  ✗,  ✗,  ✗ ]  → результат = 11.0
```

1. **Вінзоризоване середнє** (англ. *Winsorized mean*, на честь американського біостатистика Чарльза Вінзора, Charles P. Winsor): екстремальні значення не вилучаються, а «стягуються» (замінюються) найближчими збереженими значеннями з дійсного діапазону. Якщо `x[(1)]` надто мале, його прирівнюють до `x[(k+1)]`, а якщо `x[(N)]` зависоке — до `x[(N-k)]`. Вінзоризація дещо складніша в обчисленні для потокових вікон, проте незамінна для робастної оцінки вибіркової дисперсії (вінзоризована дисперсія).
2. **Олімпійське середнє** (англ. *Olympic scoring* / *truncated mean with k=1*): окремий випадок для невеликих вибірок суддівських оцінок (`N = 5..9`), де відкидається рівно одна найнижча й одна найвища оцінка (`k = 1`), щоб усунути упередженість окремого судді.
3. **M-оцінки Губера** (англ. *Huber M-estimator*, розроблені Петером Губером, Peter J. Huber): гладкий підхід, де похибка штрафується квадратично для малих відхилень і лінійно для великих. Потребують ітераційного методу зважених найменших квадратів (IRLS), тоді як усічене середнє обчислюється аналітично за один прохід після селекції.

> 🔧 **Навіщо це.** Якщо ви обробляєте дані давача в реальному часі й підозрюєте поодинокі викиди (наприклад, [привиди багатопроменевості](root:hw-sensing/distance-errors) в оптичних чи ультразвукових далекомірах), звичайне ковзне середнє використовувати не можна. Замість громіздких ітераційних M-оцінок ставте **ковзне 20%-усічене середнє**: воно має фіксований час виконання, не потребує налаштування параметрів збіжності й повністю ліквідує спайки.

### Робастна оцінка дисперсії: вінзоризована поправка

Коли в системі необхідно одночасно оцінювати як центр сигналу, так і рівень його шуму (дисперсію або стандартне відхилення), наївне обчислення дисперсії над відкинутим ядром `x[(k+1)] ... x[(N-k)]` дає занижений результат, оскільки хвости розподілу штучно обрізані.

Для коректної незміщеної оцінки розкиду застосовують **вінзоризовану дисперсію** `s_w²`:

```
1. Будуємо вінзоризований ряд y[(i)]:
y[(i)] = x[(k+1)],  якщо i ≤ k
y[(i)] = x[(i)],    якщо k < i ≤ N - k
y[(i)] = x[(N-k)],  якщо i > N - k

2. Обчислюємо вінзоризоване середнє Y_mean = (1 / N) · ∑ y[(i)]

3. Вінзоризована вибіркова дисперсія:
s_w² = (1 / (N - 1)) · ∑ (y[(i)] - Y_mean)²

4. Оцінка дисперсії похибки усіченого середнього (асимптотична поправка Тьюкі):
Var(TrimmedMean) = s_w² / (N · (1 - 2α)²)
```

Ця формула (запропонована Джоном Тьюкі, John Tukey) дозволяє оцінювати довірчий інтервал для усіченого середнього навіть за наявності важких викидів у сирих даних.

### Пакетне обчислення та Quickselect

Для статичного масиву з `N` чисел наївний підхід вимагає повного сортування масиву за час `O(N log N)`. Проте для знаходження усіченого середнього сортувати внутрішні елементи зовсім не потрібно: достатньо лише знайти елементи з рангами `k` та `N - k` і розбити масив на три частини.

Цю задачу розв'язує алгоритм вибору [Quickselect](root:sf-algorithms/quickselect) (розділення за схемою Хоара або Ломуто):

1. Першим викликом алгоритму знаходимо елемент на позиції `k` (0-індексація) за середній час `O(N)`. Після цього всі елементи лівіше від індексу `k` гарантовано менші або рівні за `x[k]`.
2. Другим викликом шукаємо елемент на позиції `N - k - 1` серед правої підчастини за середній час `O(N)`.
3. Усі елементи, що опинилися між індексами `k` та `N - k - 1`, є центральним ядром. Їх додають простим циклом за `O(N)` і ділять на `N - 2k`.

Сумарна алгоритмічна складність становить `O(N)` у середньому при нульових витратах додаткової пам'яті `O(1)`.

:::tabs
```c
#include <stddef.h>
#include <stdbool.h>

static void swap_doubles(double *a, double *b) {
    double temp = *a;
    *a = *b;
    *b = temp;
}

/* Розбиття Ломуто для знаходження k-ї порядкової статистики */
static size_t partition(double arr[], size_t left, size_t right, size_t pivot_idx) {
    double pivot_val = arr[pivot_idx];
    swap_doubles(&arr[pivot_idx], &arr[right]);
    size_t store_idx = left;

    for (size_t i = left; i < right; ++i) {
        if (arr[i] < pivot_val) {
            swap_doubles(&arr[store_idx], &arr[i]);
            store_idx++;
        }
    }
    swap_doubles(&arr[right], &arr[store_idx]);
    return store_idx;
}

/* Пошук n-го найменшого елемента за середній час O(N) */
static void quickselect(double arr[], size_t left, size_t right, size_t n) {
    while (left < right) {
        size_t pivot_idx = left + (right - left) / 2;
        pivot_idx = partition(arr, left, right, pivot_idx);

        if (n == pivot_idx) {
            return;
        } else if (n < pivot_idx) {
            right = pivot_idx - 1;
        } else {
            left = pivot_idx + 1;
        }
    }
}

/* Обчислення усіченого середнього за O(N) з частковою модифікацією arr */
bool trimmed_mean_batch(double arr[], size_t n, size_t k, double *result) {
    if (arr == NULL || result == NULL || n == 0 || 2 * k >= n) {
        return false;
    }

    /* Якщо k == 0, рахуємо звичайне середнє */
    if (k == 0) {
        double sum = 0.0;
        for (size_t i = 0; i < n; ++i) {
            sum += arr[i];
        }
        *result = sum / (double)n;
        return true;
    }

    /* Розміщуємо k найменших зліва */
    quickselect(arr, 0, n - 1, k);

    /* Розміщуємо k найбільших справа (індекс n - k - 1) */
    quickselect(arr, k + 1, n - 1, n - k - 1);

    /* Додаємо центральні елементи */
    double sum = 0.0;
    size_t count = n - 2 * k;
    for (size_t i = k; i < n - k; ++i) {
        sum += arr[i];
    }

    *result = sum / (double)count;
    return true;
}
```
```cpp
#include <algorithm>
#include <numeric>
#include <span>
#include <optional>
#include <vector>

/* Обчислення усіченого середнього для довільного діапазону значень */
[[nodiscard]] std::optional<double> calculate_trimmed_mean(std::span<double> data, std::size_t k) {
    const std::size_t n = data.size();
    if (n == 0 || 2 * k >= n) {
        return std::nullopt;
    }

    if (k == 0) {
        const double sum = std::accumulate(data.begin(), data.end(), 0.0);
        return sum / static_cast<double>(n);
    }

    /* nth_element переставляє k-й найменший елемент на позицію data.begin() + k */
    auto k_left = data.begin() + static_cast<std::ptrdiff_t>(k);
    std::nth_element(data.begin(), k_left, data.end());

    /* Другий виклик фіксує правий край на позиції data.end() - k */
    auto k_right = data.end() - static_cast<std::ptrdiff_t>(k);
    std::nth_element(k_left + 1, k_right, data.end());

    /* Усі елементи між k_left та k_right належать центральному ядру */
    const double sum = std::accumulate(k_left, k_right, 0.0);
    const auto active_count = static_cast<double>(n - 2 * k);

    return sum / active_count;
}
```

### Потокова обробка: ковзне усічене середнє

У системах керування та цифровій обробці сигналів вимірювання надходять послідовно одне за одним. Потрібно обчислювати усічене середнє для ковзного вікна розміром `W` відліків на кожному новому кроці `t`.

Якщо звичайне [ковзне середнє](root:com-signal/moving-average) оновлюється за `O(1)` операцій за допомогою додавання нового значення та віднімання найстарішого, то впорядкованість вікна для усіченого середнього робить оновлення складнішим:

![Структура ковзного вікна усіченого середнього](/root/eng/sf-algorithms/trimmed-mean/img/sliding-buffer.svg)
*Організація ковзного вікна на основі кільцевого буфера та впорядкованого масиву індексів. Старий відлік видаляється бінарним пошуком за O(log W) і зсувом за O(W), а новий відлік займає належне місце зі збереженням сортування.*

#### Архітектура для малих вікон (`W ≤ 32`)

Для мікроконтролерів (ARM Cortex-M, ESP32, STM32) розмір вікна фільтра зазвичай обирають невеликим (`W = 5, 7, 9, 16`). У таких умовах найкращу швидкодію та мінімальний кеш-промах дає комбінація:
1. **[Кільцевий буфер](root:sf-algorithms/ring-buffer)** значень довжини `W` — фіксує хронологічний порядок відліків для швидкого знаходження найстарішого елемента.
2. **Впорядкований масив покажчиків або значень** довжини `W` — підтримує елементи відсортованими.

Алгоритм оновлення на кожному кроці:
1. За індексом голови кільцевого буфера визначаємо значення найстарішого відліку `x_old`, який вибуває з вікна.
2. Виконуємо бінарний пошук `x_old` у відсортованому масиві за `O(log W)`.
3. Вилучаємо `x_old`, зсуваючи сусідні елементи масиву на одну позицію вліво за `O(W)`.
4. Записуємо нове значення `x_new` у кільцевий буфер.
5. Знаходимо позицію вставки для `x_new` у відсортованому масиві бінарним пошуком за `O(log W)` і вставляємо його зсувом за `O(W)`.
6. Підсумовуємо елементи від індексу `k` до `W - k - 1` за `O(W - 2k)` операцій і ділимо на `W - 2k`.

Загальна складність на один новий відлік становить `O(W)` копій у пам'яті (кілька десятків байтів), що для `W = 8` виконується за лічені процесорні такти без динамічного виділення пам'яті (`malloc`).

:::tabs
```c
#include <stddef.h>
#include <stdbool.h>

#define MAX_WINDOW_SIZE 32

typedef struct {
    double buffer[MAX_WINDOW_SIZE];      /* Хронологічний кільцевий буфер */
    double sorted[MAX_WINDOW_SIZE];      /* Відсортовані значення вікна */
    size_t window_size;                  /* Повна ширина вікна W */
    size_t trim_k;                       /* Кількість відкинутих з кожного краю k */
    size_t count;                        /* Поточна кількість накопичених елементів */
    size_t head;                         /* Індекс наступного запису в кільцевий буфер */
} SlidingTrimmedMean;

void sliding_trimmed_mean_init(SlidingTrimmedMean *filter, size_t w, size_t k) {
    if (w > MAX_WINDOW_SIZE) {
        w = MAX_WINDOW_SIZE;
    }
    filter->window_size = w;
    filter->trim_k = (2 * k < w) ? k : 0;
    filter->count = 0;
    filter->head = 0;
}

double sliding_trimmed_mean_update(SlidingTrimmedMean *filter, double new_val) {
    size_t w = filter->window_size;
    size_t k = filter->trim_k;

    if (filter->count < w) {
        /* Фаза первинного заповнення буфера */
        filter->buffer[filter->head] = new_val;
        filter->head = (filter->head + 1) % w;

        /* Вставка зі збереженням сортування */
        size_t pos = filter->count;
        while (pos > 0 && filter->sorted[pos - 1] > new_val) {
            filter->sorted[pos] = filter->sorted[pos - 1];
            pos--;
        }
        filter->sorted[pos] = new_val;
        filter->count++;
    } else {
        /* Фаза усталеного ковзного вікна */
        double old_val = filter->buffer[filter->head];
        filter->buffer[filter->head] = new_val;
        filter->head = (filter->head + 1) % w;

        /* 1. Пошук і видалення старого значення */
        size_t old_pos = 0;
        while (old_pos < w && filter->sorted[old_pos] != old_val) {
            old_pos++;
        }
        for (size_t i = old_pos; i + 1 < w; ++i) {
            filter->sorted[i] = filter->sorted[i + 1];
        }

        /* 2. Вставка нового значення на належне місце */
        size_t new_pos = w - 1;
        while (new_pos > 0 && filter->sorted[new_pos - 1] > new_val) {
            filter->sorted[new_pos] = filter->sorted[new_pos - 1];
            new_pos--;
        }
        filter->sorted[new_pos] = new_val;
    }

    /* Якщо накопичено замало даних для усічення, беремо просте середнє */
    if (filter->count <= 2 * k) {
        double sum = 0.0;
        for (size_t i = 0; i < filter->count; ++i) {
            sum += filter->sorted[i];
        }
        return sum / (double)filter->count;
    }

    /* Усереднення центрального ядра */
    size_t active_start = k;
    size_t active_end = filter->count - k;
    double sum = 0.0;
    for (size_t i = active_start; i < active_end; ++i) {
        sum += filter->sorted[i];
    }

    return sum / (double)(active_end - active_start);
}
```
```cpp
#include <algorithm>
#include <array>
#include <cstddef>
#include <numeric>

template <std::size_t WindowSize, std::size_t TrimK>
requires (2 * TrimK < WindowSize)
class SlidingTrimmedMeanFilter {
public:
    constexpr SlidingTrimmedMeanFilter() = default;

    [[nodiscard]] double update(double new_val) noexcept {
        if (count_ < WindowSize) {
            buffer_[head_] = new_val;
            head_ = (head_ + 1) % WindowSize;

            auto it = std::upper_bound(sorted_.begin(), sorted_.begin() + count_, new_val);
            std::move_backward(it, sorted_.begin() + count_, sorted_.begin() + count_ + 1);
            *it = new_val;
            ++count_;
        } else {
            const double old_val = buffer_[head_];
            buffer_[head_] = new_val;
            head_ = (head_ + 1) % WindowSize;

            /* Пошук і вилучення старого елемента */
            auto old_it = std::lower_bound(sorted_.begin(), sorted_.end(), old_val);
            std::move(old_it + 1, sorted_.end(), old_it);

            /* Вставка нового елемента */
            auto new_it = std::upper_bound(sorted_.begin(), sorted_.end() - 1, new_val);
            std::move_backward(new_it, sorted_.end() - 1, sorted_.end());
            *new_it = new_val;
        }

        if (count_ <= 2 * TrimK) {
            const double sum = std::accumulate(sorted_.begin(), sorted_.begin() + count_, 0.0);
            return sum / static_cast<double>(count_);
        }

        const auto start_it = sorted_.begin() + TrimK;
        const auto end_it = sorted_.begin() + (count_ - TrimK);
        const double core_sum = std::accumulate(start_it, end_it, 0.0);
        return core_sum / static_cast<double>(count_ - 2 * TrimK);
    }

    [[nodiscard]] constexpr std::size_t size() const noexcept { return count_; }
    constexpr void reset() noexcept { count_ = 0; head_ = 0; }

private:
    std::array<double, WindowSize> buffer_{};
    std::array<double, WindowSize> sorted_{};
    std::size_t head_{0};
    std::size_t count_{0};
};
```

#### Архітектура для великих вікон (`W > 64`)

Якщо для специфічних наукових або фінансових задач потрібне велике вікно (наприклад, `W = 1000`), лінійний зсув масиву за `O(W)` стає занадто витратним. 

У таких випадках використовують дерево порядкових статистик (англ. *Order Statistic Tree* на базі червоно-чорного чи AVL-дерева), де кожен вузол зберігає розмір свого піддерева та суму значень. Це дозволяє:
- Додавати новий елемент за `O(log W)`;
- Видаляти застарілий елемент за `O(log W)`;
- Обчислювати суму рангового діапазону `[k, W - k]` за `O(log W)`.

### Апаратна оптимізація: сортувальні мережі для фіксованого вікна

У цифрових сигнальних процесорах (DSP) та векторних регістрах (SIMD: ARM NEON, x86 AVX2) умовні переходи `if-else` порушують роботу конвеєра інструкцій. Для малих вікон (наприклад, `N = 5`, `k = 1`) замість класичних алгоритмів сортування застосовують [сортувальні мережі](root:sf-algorithms/sorting-networks) (англ. *sorting networks*).

Базовим блоком мережі є безгалузевий компаратор-обмінник `CAS(a, b)`:

```
min_val = (a < b) ? a : b
max_val = (a < b) ? b : a
a = min_val
b = max_val
```

Для обчислення олімпійського середнього вибірки з `5` елементів (`N = 5, k = 1`) не обов'язково сортувати всі п'ять чисел повністю (для чого знадобилося б 9 компараторів). Достатньо знайти лише абсолютний мінімум і абсолютний максимум за допомогою 6 операцій, відкинути їх, а решту три елементи додати:

:::tabs
```c
#include <stddef.h>

/* Олімпійське середнє N=5, k=1 без циклів і розгалужень */
static inline double trimmed_mean_5_k1(double a, double b, double c, double d, double e) {
    /* Сума всіх елементів */
    double total_sum = a + b + c + d + e;

    /* Пошук мінімуму за 4 порівняння */
    double min1 = (a < b) ? a : b;
    double min2 = (c < d) ? c : d;
    double min12 = (min1 < min2) ? min1 : min2;
    double global_min = (min12 < e) ? min12 : e;

    /* Пошук максимуму за 4 порівняння */
    double max1 = (a > b) ? a : b;
    double max2 = (c > d) ? c : d;
    double max12 = (max1 > max2) ? max1 : max2;
    double global_max = (max12 > e) ? max12 : e;

    /* Віднімаємо два екстремуми й ділимо на 3 */
    return (total_sum - global_min - global_max) / 3.0;
}
```
```cpp
#include <algorithm>

/* Олімпійське середнє N=5, k=1 у C++20 (constexpr, branchless) */
[[nodiscard]] constexpr double trimmed_mean_5_k1(double a, double b, double c, double d, double e) noexcept {
    const double total_sum = a + b + c + d + e;

    const double min1 = std::min(a, b);
    const double min2 = std::min(c, d);
    const double min12 = std::min(min1, min2);
    const double global_min = std::min(min12, e);

    const double max1 = std::max(a, b);
    const double max2 = std::max(c, d);
    const double max12 = std::max(max1, max2);
    const double global_max = std::max(max12, e);

    return (total_sum - global_min - global_max) / 3.0;
}
```
:::

Такий код транслюється компілятором у пряму послідовність SIMD-інструкцій `vminnm` / `vmaxnm` (ARM) або `_mm_min_pd` / `_mm_max_pd` (x86) без жодного розгалуження, виконуючись менш ніж за 10 наносекунд.

### Практичне застосування та типові пастки

Усічене середнє є золотим стандартом у тих інженерних галузях, де дані забруднені рідкісними, але руйнівними викидами:

1. **Бенчмаркінг коду та профілювання**: під час вимірювання тривалості виконання функцій операційна система періодично перериває процес на перемикання контексту або обробку переривань мережевої карти, створюючи аномальні хвости у сотні мікросекунд. Використання `10%`- або `20%`-усіченого середнього усуває вплив переривань ОС, даючи стабільний результат без ручного відсіювання за жорстко заданими порогами.
2. **Мережева телеметрія**: вимірювання затримки пакетів (RTT). Більшість пакетів летять стабільним маршрутом, але поодинокі ретрансмісії TCP через втрату пакетів дають різкі сплески.
3. **Об'єднання показів сенсорного кластера (Sensor Fusion Voting)**: коли критичний параметр (тиск у котлі, кут атаки літака) вимірюється п'ятьма однаковими датчиками, відкидання найвищого й найнижчого показів гарантує, що ані датчик із закороченим виходом (`0 В`), ані датчик із розривом кола живлення (`VCC`) не вплинуть на рішення системи керування.

#### Пастка 1: Асиметричний шум і односторонні викиди

Класичне усічене середнє відтинає дані **симетрично** — однакову кількість `k` зліва і справа. Проте в багатьох фізичних системах шум є строго одностороннім:
- Затримка запиту в базі даних не може бути меншою за фізичну швидкість мережі (лівий хвіст затиснутий), але через блокування транзакцій може виростати у тисячі разів (правий хвіст роздутий).
- Лазерний далекомір (LiDAR) у пилюці або тумані отримує передчасні відбиття від часток пилу (викиди тільки у бік заниження відстані).

Якщо до такого сигналу застосувати симетричне усічення, алгоритм відкине `k` спайків справа, але зліва він відкине абсолютно легітимні найменші значення. Це призведе до появи **систематичного зсуву** (англ. *estimation bias*).

> 🔧 **Навіщо це.** Якщо викиди можливі лише в один бік, застосовуйте **асиметричне усічення** (англ. *asymmetrically trimmed mean*): відтинайте `k_high` елементів зверху і `k_low = 0` знизу.

#### Пастка 2: Переповнення квоти викидів (`викиди > k`)

Стійкість алгоритму гарантується лише доти, доки кількість спайків у поточному вікні не перевищує `k`. Якщо через тривалий збій датчик видає пачку з трьох поспіль хибних відліків при вікні `N = 7` і `k = 2`, третій спайк проникне в центральне ядро й змістить результат.

*Правило вибору параметрів*:
- Ширину вікна `W` обирають щонайменше у 3–4 рази більшою за максимальну тривалість очікуваної пачки спайків.
- Глибину усічення `α` для промислових завад задають на рівні `20%..25%`.

#### Пастка 3: Стрибки суми при русі вікна (Phase-Shift Steps)

Оскільки порядок елементів у відсортованому масиві змінюється дискретно, момент входу нового спайка у вікно може викликати раптове витіснення іншого відліку з центральної зони. У чутливих контурах [дискретних PID-регуляторів](root:com-signal/discrete-pid) це може породжувати сходинковий шум похідної складової `D`. У таких контурах після усіченого середнього часто ставлять легке [експоненційне згладжування (EMA)](root:com-signal/ema) з малим коефіцієнтом для згладжування кроків дискретизації.

### Підсумкове порівняння оцінок

| Критерій | Звичайне середнє | Усічене середнє | Медіана | Вінзоризоване середнє |
|---|---|---|---|---|
| **Точка зламу `ε*`** | `0%` (вразливе до 1 спайка) | `α` (наприклад, `20%`) | `50%` (максимальна) | `α` |
| **Ефективність на білому шумі** | `100%` (ідеал) | `90% – 96%` (висока) | `63.7%` (посередня) | `88% – 94%` (висока) |
| **Складність оновлення вікна** | `O(1)` | `O(W)` або `O(log W)` | `O(W)` або `O(log W)` | `O(W)` |
| **Збереження гострих фронтів** | Ні (розмазує в рампу) | Частково (згладжує) | Так (ідеально) | Частково |
| **Чутливість до пачок спайків** | Катастрофічна | Стійке до `k` спайків | Стійке до `(W-1)/2` | Стійке до `k` спайків |
| **Складність реалізації** | 1 додавання | Буфер + вставка | Буфер + медіана | Буфер + заміна країв |

Усічене середнє займає центральне місце в прикладній стійкій статистиці: воно дає інженеру практичний важіль `α`, що дозволяє точно збалансувати несприйнятливість до аномалій та статистичну плавність оцінки під конкретні умови завад у вимірювальному каналі.
