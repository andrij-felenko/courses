# Задача про покриття множини

<preknowlist>
- [Жадібні алгоритми](root:sf-algorithms/greedy-algorithms) — локально-оптимальний вибір на кожному кроці та умови його застосовності.
- [Бітові множини (Bitset)](root:sf-algorithms/bitset) — компактне представлення множин та паралельні бітові операції над ними.
- [Пошук із поверненням](root:sf-algorithms/backtracking) — вичерпний перебір комбінацій для знаходження точного розв'язку NP-важких задач.
</preknowlist>

Команда інженерів підтримує ядро великої розподіленої операційної системи, що містить 20 000 критичних програмних модулів та функцій. Для верифікації коду розроблено тестовий набір із 5000 комплексних інтеграційних сценаріїв. Кожен окремий тест перевіряє певну групу модулів і вимагає власного часу на виконання: від кількох секунд до десятків хвилин. Повний запуск усіх 5000 тестів у хмарному кластері триває 4.5 години й виснажує інфраструктурний бюджет. При цьому багато тестів багаторазово дублюють перевірку одних і тих самих базових функцій. Інженерам необхідно відібрати мінімальну підмножину тестових сценаріїв (або набір із найменшим сумарним часом виконання), яка гарантує стовідсоткове покриття всіх 20 000 модулів без жодної прогалини.

Спроба розв'язати цю проблему вичерпним перебором стикається з комбінаторною стіною. Кількість можливих конфігурацій вибору серед 5000 тестів становить `2⁵⁰⁰⁰`, що незрівнянно перевищує кількість елементарних частинок у спостережуваному Всесвіті. Навіть для скромного набору зі 100 тестів повний перебір вимагає оцінки `2¹⁰⁰ ≈ 1.26 × 10³⁰` варіантів, що виключає можливість знаходження оптимуму перебором за прийнятний час.

Ця прикладна інженерна потреба описується однією з фундаментальних математичних моделей дискретної оптимізації — **задачею про покриття множини** (*Set Cover Problem*).

## 1. Анатомія та математичне формулювання моделі

Щоб перевести інженерну задачу на мову алгоритмів, абстрагуємося від фізичної природи об'єктів. Усі сутності, які необхідно захистити, протестувати або обслужити, об'єднуються у скінченну базову множину.

Введемо фундаментальні математичні поняття:

1. **Універсум (лат. *universum* — сукупність усього, від *unus* — один та *vertere* — обертати):** Скінченна множина елементів `U = {e₁, e₂, ..., eₙ}` потужністю `|U| = n`.
2. **Сімейство підмножин:** Набір `S = {S₁, S₂, ..., Sₘ}`, де кожна підмножина `Sᵢ ⊆ U` містить певну частину елементів універсуму. Об'єднання всіх множин сімейства повністю накриває універсум: `⋃_{i=1}^m Sᵢ = U`.
3. **Функція вартості (ваги):** Кожній підмножині `Sᵢ` зіставлено додатну вартість `w(Sᵢ) > 0` (час тестування, фінансові витрати на ліцензію або енергоспоживання). Якщо всі `w(Sᵢ) = 1`, задачу називають **незваженою** (*Unweighted Set Cover*), якщо вартості довільні — **зваженою** (*Weighted Set Cover*).

Мета полягає в знаходженні такого підсімейства `C ⊆ S`, для якого виконуються дві умови:
- **Умова покриття:** `⋃_{S ∈ C} S = U` (кожен елемент універсуму належить хоча б одній обраній підмножині).
- **Критерій оптимізації:** Сумарна вартість `w(C) = ∑_{S ∈ C} w(S)` є мінімально можливою серед усіх допустимих покриттів.

Термін **покриття** походить від латинського *cooperire* («повністю закривати», «огортати»). Якщо підмножини у розв'язку не перетинаються між собою, покриття називають *точним* (*Exact Cover*); у загальній задачі Set Cover перетини дозволені, але надлишкові перекриття збільшують підсумкову вартість.

![Універсум елементів та підмножини](/root/eng/sf-algorithms/set-cover/img/set-cover-universe-subsets.svg)
*Універсум U з десяти елементів та сімейство підмножин. Оптимальний вибір трьох множин {S₁, S₄, S₅} накриває всі десять елементів із мінімальною сумарною вартістю 11, тоді як нераціональний вибір {S₂, S₃, S₆} коштує 15 і залишає прогалини.*

Детальний опис історичного шляху проблеми — від включення до 21 NP-повної задачі Річарда Карпа до встановлення меж апроксимації на основі теореми PCP — наведено у вставці [📜 Історія задачі про покриття: від 21 NP-повної проблеми Карпа до бар'єра апроксимації](root:sf-algorithms/set-cover/hist-set-cover.md).

## 2. Обчислювальна складність та логарифмічний бар'єр

У 1972 році Річард Карп довів, що задача про покриття множини належить до класу NP-повних (NP-hard у формі оптимізації). Це означає, що поліноміального алгоритму для знаходження точного оптимуму не існує, якщо тільки `P ≠ NP`.

Проте справжня унікальність Set Cover відкривається при аналізі можливостей її наближеного розв'язання. У теорії складності NP-важкі задачі оптимізації демонструють принципово різну податливість до апроксимації (лат. *approximare* — наближатися):

- **Задача про рюкзак (Knapsack):** Має повністю поліноміальну схему апроксимації (FPTAS), що дозволяє знайти розв'язок із будь-якою бажаною точністю `(1 + ε)` за час, поліноміальний від `1/ε`.
- **Вершинне покриття графа (Vertex Cover):** Має константну 2-апроксимацію — простий жадібний алгоритм завжди знаходить розв'язок, що не перевищує подвійного оптимуму.
- **Покриття множини (Set Cover):** Демонструє фундаментальний **логарифмічний бар'єр**.

У 1998 році Уріель Фейге на основі теореми PCP довів, а у 2014 році Іріт Дінур та Давід Штьойрер остаточно закріпили фундаментальну теорему неапроксимованості:

```
Якщо P ≠ NP, то для будь-якого ε > 0 задачу про покриття множини
неможливо апроксимувати з коефіцієнтом меншим ніж:
(1 - ε) · ln(n)
за поліноміальний час.
```

Цей логарифм `ln n` не є вадою якогось окремого евристичного підходу. Це природна комбінаторна властивість задачі: зі збільшенням кількості вже покритих елементів кожна наступна множина містить дедалі менше нових унікальних елементів, змушуючи алгоритм платити все більшу питому ціну за кожен додатковий крок.

## 3. Жадібний алгоритм: принцип спадної граничної корисності

Найвідомішим та практично найефективнішим поліноміальним методом для розв'язання задачі Set Cover є **жадібний алгоритм** (евристика, від дав.-гр. *εὑρίσκω* — «знаходжу»).

### Механізм локального вибору

Жадібна стратегія відмовляється від глобального планування на користь локальної оптимізації. На кожній ітерації алгоритм обирає підмножину, яка забезпечує найкраще співвідношення «вартість / результат» — тобто мінімізує витрати в розрахунку на один щойно покритий елемент.

Нехай `C_curr` — множина елементів універсуму, які вже покриті раніше обраними підмножинами. Для кожної ще не обраної підмножини `S` обчислюється її **ефективна ємність** — кількість нових елементів, які вона здатна додати до покриття:

```
new(S) = |S \ C_curr|
```

Якщо `new(S) > 0`, обчислюється **питома вартість** (вартість одного нового елемента):

```
cost_per_element(S) = w(S) / |S \ C_curr|
```

Алгоритм обирає підмножину `S*`, для якої ця питома вартість є мінімальною:

```
S* = argmin_{S} ( w(S) / |S \ C_curr| )
```

Після цього множина `S*` додається до результуючого списку, покриті нею елементи додаються до `C_curr`, і процес повторюється, доки `C_curr` не зрівняється з усім універсумом `U`.

![Покроковий вибір жадібного алгоритму](/root/eng/sf-algorithms/set-cover/img/greedy-choice-steps.svg)
*Покрокова робота жадібного алгоритму: на кожному кроці перераховується питома вартість підмножин для залишку непокритих елементів. Обирається локально найдешевший варіант, що забезпечує глобальну якість розв'язку.*

### Теоретична гарантія: гармонійне число H_n

У 1970-х роках Девід Джонсон, Ласло Ловас та Вацлав Хватал строго довели, що жадібний алгоритм досягає коефіцієнта апроксимації:

```
Cost(Greedy) ≤ H(k) · Cost(OPT)
```

де `k = max_{S ∈ S} |S|` — максимальний розмір підмножини у сімействі (`k ≤ n`), а `H(k)` — `k`-те гармонійне число:

```
H(k)
= 1 + 1/2 + 1/3 + ... + 1/k            [означення суми перших k членів гармонійного ряду]
= ln(k) + γ + O(1/k)                   [асимптотичний розклад за сталою Ейлера—Маскероні γ ≈ 0.57721]
```

Оскільки `k ≤ n`, гарантований фактор апроксимації становить `H_n ≤ ln(n) + 1`.

Зіставивши цей результат із теоремою Фейге про неапроксимовність нижче `(1 - ε) · ln n`, отримуємо фундаментальний висновок: **найпростіший жадібний алгоритм є асимптотично оптимальним** — жоден інший поліноміальний алгоритм довільної складності не здатний принципово покращити цю гарантію.

### Чому жадібний алгоритм помиляється: аналіз найгіршого випадку

Логарифмічна похибка жадібної стратегії виникає через її сліпоту щодо майбутніх кроків. Алгоритм спокушається підмножиною, яка на поточному кроці покриває трохи більше елементів, ніж інші, але блокує доступ до компактного глобального покриття.

![Конструкція найгіршого випадку](/root/eng/sf-algorithms/set-cover/img/greedy-tightness-construction.svg)
*Конструкція найгіршого випадку для жадібного алгоритму. Оптимальний розв'язок складається лише з двох підмножин O₁ та O₂, проте жадібний алгоритм покроково вибирає k каскадних множин G₁, G₂, ..., G_k, досягаючи фактора похибки (1/2) · log₂(n).*

Повний математичний доказ гармонійної межі `H(k)` методом розподілу цін елементів (*cost-sharing*) та строгий аналіз конструкції найгіршого випадку подано у вставці [🧮 Математичні оцінки покриття: гармонійна межа, найгірший випадок та двоїстість LP](root:sf-algorithms/set-cover/math-set-cover-bounds.md).

## 4. Лінійне релаксування, двоїстість та методи округлення

Окрім жадібної евристики, універсальним теоретичним та практичним апаратом дослідження Set Cover є **лінійне програмування** (LP).

### Цілочисельна модель (ILP) та релаксація

Сформулюємо задачу як цілочисельну лінійну програму. Для кожної підмножини `S ∈ S` введемо булеву змінну `x_S ∈ {0, 1}`, де `x_S = 1` означає, що підмножина `S` включена до розв'язку, а `x_S = 0` — відкинута:

```
Мінімізувати цільову функцію:
min  ∑_{S ∈ S} w(S) · x_S

за умов:
∑_{S : e ∈ S} x_S ≥ 1   [для кожного елемента e ∈ U]
x_S ∈ {0, 1}           [для кожної підмножини S ∈ S]
```

Оскільки розв'язання цілочисельної програми є NP-важким, застосуємо **лінійну релаксацію** (LP Relaxation): замінимо дискретну вимогу `x_S ∈ {0, 1}` на неперервний інтервал `x_S ∈ [0, 1]`.

Отриману задачу лінійного програмування можна розв'язати за строго поліноміальний час (наприклад, симплекс-методом або методом внутрішніх точок). Результатом буде дробовий вектор `x*`, де окремі підмножини можуть мати значення на зразок `x*_S = 0.33` або `x*_S = 0.5`.

Для отримання дискретного комбінаторного розв'язку дробовий вектор перетворюється на цілочисельний за допомогою методів **округлення** (*Rounding*).

### Частотне округлення (f-Approximation)

Нехай `f` — **максимальна частота входження елемента**, тобто максимальна кількість підмножин із сімейства `S`, які містять один і той самий елемент:

```
f = max_{e ∈ U} |{ S ∈ S : e ∈ S }|
```

Розглянемо правило частотного округлення: включити підмножину `S` до покриття, якщо її дробова вага в оптимальному розв'язку релаксації задовольняє умову:

```
x*_S ≥ 1 / f
```

Доведемо коректність та якість цього розв'язку:

1. **Гарантія покриття:** Для кожного елемента `e ∈ U` виконується умова релаксації:
   ```
   ∑_{S : e ∈ S} x*_S ≥ 1
   ```
   У цій сумі бере участь не більше `f` доданків (оскільки елемент `e` входить щонайбільше в `f` множин). Якби для всіх цих множин виконувалося `x*_S < 1/f`, сума була б строго меншою за `f · (1/f) = 1`, що суперечить умові. Отже, хоча б для однієї множини `S`, що містить `e`, виконується `x*_S ≥ 1/f`. Це означає, що елемент `e` гарантовано буде покритий.
2. **Гарантія вартості:** Оскільки для кожного обраного `S` виконується `1 ≤ f · x*_S`, вартість округленого розв'язку задовольняє:
   ```
   Cost(Rounded)
   = ∑_{S : x*_S ≥ 1/f} w(S)             [означення вартості обраних підмножин]
   ≤ ∑_{S : x*_S ≥ 1/f} w(S) · (f · x*_S) [оскільки для кожного обраного S маємо f · x*_S ≥ 1]
   ≤ f · ∑_{S ∈ S} w(S) · x*_S           [розширення суми на всі множини сімейства]
   = f · Cost(OPT_LP)                    [за означенням вартості оптимального LP-розв'язку]
   ≤ f · Cost(OPT)                       [оскільки OPT_LP ≤ OPT за властивістю релаксації]
   ```

Таким чином, частотне округлення дає **`f`-апроксимаційний алгоритм**.

Це фундаментальний результат: якщо в інженерній задачі кожен елемент перекривається невеликою кількістю систем (наприклад, у топологіях мереж, де кожен сервер підключений максимум до `f = 3` комутаторів), лінійне округлення гарантує сталу точність `3 · OPT`, оминаючи логарифмічний бар'єр `ln n`.

Зокрема, класична задача про вершинне покриття графа є окремим випадком Set Cover, де кожне ребро з'єднує рівно дві вершини (тобто `f = 2`). Звідси негайно випливає класична 2-апроксимація для Vertex Cover.

### Імовірнісне округлення (Randomized Rounding)

Якщо частота `f` є великою (`f ≈ m`), застосовують ймовірнісний підхід Раджива Мотвані та Рагхавана. Дробові змінні `x*_S ∈ [0, 1]` інтерпретують як незалежні ймовірності включення множини `S` до розв'язку:

```
Pr[ S ∈ C ] = min(1,  x*_S · (c · ln n))
```

де `c ≥ 2` — параметр надійності.

Математичне сподівання кількості непокритих елементів експоненційно прямує до нуля:

```
Pr[ e не покрито ]
= ∏_{S : e ∈ S} (1 - Pr[S ∈ C])           [незалежність вибору підмножин]
≤ ∏_{S : e ∈ S} exp( - x*_S · c · ln n )  [використовуючи нерівність 1 - z ≤ e^{-z}]
= exp( - c · ln n · ∑_{S : e ∈ S} x*_S )  [добуток експонент як експонента суми]
≤ exp( - c · ln n · 1 )                  [оскільки ∑ x*_S ≥ 1 за обмеженням LP]
= n^{-c}                                  [спрощення e^{-c ln n} = (e^{ln n})^{-c}]
```

Застосовуючи нерівність об'єднання подій (Union Bound) для всіх `n` елементів універсуму:

```
Pr[ хоча б один елемент не покрито ] ≤ n · n^{-c} = n^{1 - c}
```

При `c = 2` ймовірність того, що хоча б один елемент залишиться непокритим, не перевищує `1/n` (менше 1% для `n ≥ 100`). Сумарна очікувана вартість розв'язку становить `O(ln n) · Cost(OPT_LP)`.

### Двоїста задача (Dual LP) та прямо-двоїстий метод

Побудуємо двоїсту задачу лінійного програмування (Dual LP), зіставивши кожному елементу універсуму `e ∈ U` двоїсту змінну `y_e ≥ 0`:

```
Максимізувати сумарний бюджет:
max  ∑_{e ∈ U} y_e

за умов:
∑_{e ∈ S} y_e ≤ w(S)   [для кожної підмножини S ∈ S]
y_e ≥ 0                [для кожного елемента e ∈ U]
```

Змінна `y_e` має прозорий економічний зміст: це максимальний «бюджет», який елемент `e` згоден заплатити за своє покриття. Умова `∑_{e ∈ S} y_e ≤ w(S)` вимагає, щоб сумарний внесок елементів будь-якої множини не перевищував її реальної вартості `w(S)`.

![Зв'язок прямої задачі та двоїстої](/root/eng/sf-algorithms/set-cover/img/lp-duality-and-rounding.svg)
*Конструкція прямої та двоїстої релаксацій у задачі Set Cover. Двоїсті змінні y_e виступають пакувальним бюджетом, що насичує обмеження множин і керує вибором у прямо-двоїстому алгоритмі.*

Прямо-двоїстий алгоритм (*Primal-Dual Schema*) працює без розв'язання громіздких матричних LP-систем:
1. Початково всі `y_e = 0`, покриття `C = ∅`.
2. Поки є непокриті елементи, алгоритм одночасно та рівномірно збільшує змінні `y_e` для всіх поточних непокритих елементів.
3. Щойно для якоїсь множини `S` двоїсте обмеження стає щільним (насиченим): `∑_{e ∈ S} y_e = w(S)`, ця множина негайно додається до розв'язку `C`.
4. Процес завершується, коли всі елементи покрито.

Цей метод забезпечує `f`-апроксимацію за час `O(m · n)` без необхідності виклику сторонніх LP-солверів.

## 5. Геометричне покриття та субмодулярні розширення

У багатьох прикладних доменах вхідні множини мають додаткову геометричну або алгебраїчну структуру, що дозволяє оминути логарифмічний бар'єр або узагальнити модель на ширші класи оптимізації.

### Геометричний Set Cover (Geometric Set Cover)

Якщо універсум `U` є множиною точок на двовимірній площині `ℝ²`, а підмножини `S_i` задаються геометричними фігурами (колами, прямокутниками чи півплощинами), комбінаторна структура суттєво спрощується:

- **Покриття кругами однакового радіуса (Unit Disk Cover):** Задача моделює розміщення базових станцій мобільного зв'язку чи Wi-Fi точок доступу. Завдяки планарній топології метод зсуву простору (*Shifting Technique* Хохбаум та Мааса) дозволяє побудувати **поліноміальну схему апроксимації (PTAS)** з якістю `(1 + ε)` для довільного `ε > 0`.
- **Покриття псевдодисками та опуклими многокутниками:** Локальний пошук (Мустафа і Рей, 2010) забезпечує сталий коефіцієнт апроксимації `O(1)` завдяки обмеженій ємності перетинів за теоремою Хеллі.

Проте за умови переходу до тривимірного простору `ℝ³` або довільних незв'язних геометричних фігур задача миттєво повертається до загальної важкості Set Cover із бар'єром `ln n`.

### Субмодулярна оптимізація та максимальне покриття (Max Coverage)

Задача про покриття множини є окремим випадком оптимізації **субмодулярних функцій множин** (лат. *sub-* — під та *modulus* — міра).

Функція корисності `f: 2^S → ℝ⁺` називається субмодулярною, якщо вона задовольняє властивість спадної граничної віддачі (*diminishing marginal returns*): для будь-яких підмножин `A ⊆ B` та нового елемента `x ∉ B`:

```
f(A ∪ {x}) - f(A) ≥ f(B ∪ {x}) - f(B)
```

Споріднена задача **максимального покриття (Maximum Coverage)** формулюється так: серед сімейства підмножин `S` обрати не більше `k` множин, щоб максимізувати кількість покритих елементів `|⋃_{i=1}^k S_i|`.

У 1978 році Джордж Немхаузер, Лоренс Волсі та Маршалл Фішер довели класичну теорему: жадібний алгоритм для задачі максимального покриття досягає строго гарантованого коефіцієнта апроксимації:

```
Cost(Greedy) ≥ ( 1 - 1/e ) · Cost(OPT) ≈ 0.6321 · Cost(OPT)
```

де `e ≈ 2.71828` — основа натурального логарифма. Цей коефіцієнт `1 - 1/e` є теоретично непереборним: доведено, що жоден поліноміальний алгоритм не може гарантувати коефіцієнт `1 - 1/e + ε`, якщо `P ≠ NP`.

## 6. Еквівалентності та споріднені комбінаторні задачі

Задача про покриття множини є універсальним вузлом у графі комбінаторних редукцій. Розуміння її ізоморфізмів дозволяє розпізнавати Set Cover у різноманітних прикладних формулюваннях.

```
                   ┌──────────────────────────────────────────────┐
                   │        Задача про покриття множини           │
                   │               (Set Cover)                    │
                   └──────┬───────────────┬───────────────┬───────┘
                          │               │               │
            Транспонування│          f = 2│               │Редукція
            матриці       │               │               │околів
                          ▼               ▼               ▼
                   ┌──────────────┐┌──────────────┐┌──────────────┐
                   │  Hitting Set ││ Vertex Cover ││Dominating Set│
                   │ (вибіркова   ││  (вершинне   ││ (домінівна   │
                   │   множина)   ││  покриття)   ││   множина)   │
                   └──────────────┘└──────────────┘└──────────────┘
```

### Задача про вибіркову множину (Hitting Set)
Задано сімейство підмножин `F = {F₁, ..., F_k}` над універсумом `E`. Потрібно знайти мінімальну за розміром (або вагою) підмножину елементів `H ⊆ E`, яка перетинає кожну множину з `F`: `H ∩ F_i ≠ ∅` для всіх `i`.

**Еквівалентність:** Задача Hitting Set є точним транспонуванням матриці інцидентності задачі Set Cover:
- Елементи `E` стають підмножинами `S`.
- Множини `F_i` стають елементами універсуму `U`.
Будь-який алгоритм для Set Cover безпосередньо розв'язує Hitting Set із тим самим фактором гарантії.

### Домінівна множина графа (Dominating Set)
У графі `G = (V, E)` знайти мінімальну підмножину вершин `D ⊆ V`, таку що кожна вершина з `V \ D` суміжна хоча б з однією вершиною з `D`.

**Еквівалентність:** Сформулюємо Set Cover, де універсумом є вершини `U = V`, а для кожної вершини `v` підмножина `S_v` містить саму вершину `v` та всіх її сусідів: `S_v = {v} ∪ N(v)`. Тоді Dominating Set точно еквівалентний Set Cover із `n` множинами.

## 7. Інженерна реалізація: бітові прискорення та паралелізм

При розробці високонавантажених компіляторів, мережевих аналізаторів та систем автоматичного проектування (EDA) алгоритми Set Cover стикаються з мільйонами операцій перевірки перетинів на секунду.

> 🔧 **Навіщо це.**
> У продакшн-системах представлення множин через динамічні списки чи геш-таблиці (`std::unordered_set` або `HashSet`) створює критичні накладні витрати: розіменування вказівників, кеш-промахи L3-кешу та надмірне споживання пам'яті. Упаковка універсуму в компактні 64-бітні вектори (`uint64_t`) та використання векторних інструкцій процесора дозволяють підняти пропускну здатність алгоритму в десятки разів.

Нижче наведено порівняння високопродуктивних реалізацій жадібного ядра мовами C та C++:

:::tabs
```c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>

#define MAX_SETS 64

typedef struct {
    uint64_t mask;
    double cost;
    int id;
} BitSubset;

/* Швидкий жадібний вибір на 64-бітному універсумі */
int run_greedy_step(const BitSubset* subsets, int m, uint64_t covered, int* out_best_idx) {
    int best_idx = -1;
    double best_ratio = 1e18;

    for (int i = 0; i < m; ++i) {
        uint64_t newly_covered = subsets[i].mask & (~covered);
        /* Апаратний підрахунок кількості одиничних бітів */
        int count = __builtin_popcountll(newly_covered);

        if (count > 0) {
            double ratio = subsets[i].cost / (double)count;
            if (ratio < best_ratio) {
                best_ratio = ratio;
                best_idx = i;
            }
        }
    }

    *out_best_idx = best_idx;
    return (best_idx != -1) ? 0 : -1;
}
```
```cpp
#include <vector>
#include <bitset>
#include <optional>
#include <span>
#include <limits>

constexpr size_t UNIVERSE_CAPACITY = 64;
using BitMask = std::bitset<UNIVERSE_CAPACITY>;

struct FastSubset {
    int id;
    double cost;
    BitMask mask;
};

class GreedySetCoverEngine {
public:
    static std::optional<size_t> findBestCandidate(
        std::span<const FastSubset> subsets,
        const BitMask& covered
    ) noexcept {
        size_t best_idx = 0;
        bool found = false;
        double best_ratio = std::numeric_limits<double>::infinity();

        for (size_t i = 0; i < subsets.size(); ++i) {
            BitMask newly = subsets[i].mask & (~covered);
            size_t count = newly.count();

            if (count > 0) {
                double ratio = subsets[i].cost / static_cast<double>(count);
                if (ratio < best_ratio) {
                    best_ratio = ratio;
                    best_idx = i;
                    found = true;
                }
            }
        }

        return found ? std::make_optional(best_idx) : std::nullopt;
    }
};
```

## 8. Промислові сценарії застосування

Модель Set Cover лежить у фундаменті багатьох критичних підсистем сучасного стека інформаційних технологій:

1. **Регресійний вибір тестів (Regression Test Selection в CI/CD):** У великих монорепозиторіях (Google, Meta, Linux Kernel) зміни в коді зачіпають тисячі вихідних файлів. Побудова матриці покриття «тести ↔ рядки коду» та розв'язання задачі Set Cover дозволяє скоротити час нічного тестування з 8 годин до 25 хвилин, зберігаючи стовідсоткову гарантію перевірки всіх змінених блоків.
2. **Апаратна оптимізація таблиць маршрутизації (TCAM у мережевих комутаторах):** Тернарна пам'ять, адресована за вмістом (TCAM), є надзвичайно дорогою за площею кристала та енергоспоживанням. Списки контролю доступу (ACL) та правила фільтрації пакетів містять маски префіксів. Компіляція мінімального набору TCAM-правил, еквівалентних вихідній політиці безпеки, точно зводиться до зваженого Set Cover.
3. **Вибір багатоколонкових індексів у СУБД (Database Index Selection):** Планувальники запитів реляційних баз даних (PostgreSQL, MySQL, CockroachDB) для оптимізації важких аналітичних запитів (OLAP) обирають мінімальний набір індексів, що покриває всі предикати фільтрації та сортування у робочому навантаженні, мінімізуючи накладні витрати на дискову пам'ять та оновлення при операціях запису.
4. **Розміщення базових станцій та сенсорних вузлів (IoT Facility Location):** Розгортання бездротових сенсорів для моніторингу сільськогосподарських угідь чи промислових зон вимагає повного географічного покриття території за мінімальної кількості автономних датчиків.

## 9. Керівництво інженера з вибору алгоритму

Для практичного вибору стратегії розв'язання задачі про покриття множини слід спиратися на масштаб вхідних даних та вимоги до точності:

| Розмірність задачі | Структура обмежень | Рекомендований метод | Гарантія якості | Часова складність |
| :--- | :--- | :--- | :--- | :--- |
| **`m ≤ 40`, `n ≤ 200`** | Будь-яка | Точний метод гілок і меж (*Branch & Bound*) або ILP/SAT-солвер | Абсолютний оптимум (`1.0 · OPT`) | Від `O(m · n)` до `O(2^m)` |
| **`m ≤ 10⁵`, `n ≤ 10⁵`** | Загальний випадок | Жадібний алгоритм із бітовими оптимізаціями | `≤ (ln n + 1) · OPT` (типово 1.1–1.2×) | `O(m · n / 64)` |
| **`m ≤ 10⁶`, `n ≤ 10⁶`** | Обмежена кратність `f ≤ 4` | Частотне округлення / Прямо-двоїстий метод | `≤ f · OPT` (строго константна) | `O(m · n)` |
| **Геометричні дані `ℝ²`** | Круги, диски, прямокутники | Схеми PTAS / Геометричний локальний пошук | `(1 + ε) · OPT` | Поліноміальна від `n^{O(1/ε)}` |
| **Потокові дані (Online)** | Елементи надходять динамічно | Онлайн прямо-двоїстий алгоритм | `O(ln m · ln n) · OPT` | `O(1)` на оновлення |

Задача про покриття множини наочно ілюструє силу сучасної алгоритмічної інженерії: навіть там, де точний оптимум заблокований експоненційною важкістю NP-повноти, глибоке математичне розуміння структури задачі дозволяє будувати швидкі та бездоганно надійні практичні рішення.
