Коли криптографічний сервер встановлює захищене TLS-з'єднання або підписує сертифікат за стандартом RSA з довжиною ключа 2048 бітів, він обчислює модулярне піднесення до степеня `M^d mod N`. Числа `M`, `d` та `N` складаються з 32 машинних слів по 64 біти кожне. Алгоритм піднесення до степеня методом бінарного піднесення до квадрата (Square-and-Multiply) для 2048-бітного показника вимагає в середньому 3072 модулярних множень: 2048 операцій піднесення до квадрата та близько 1024 додаткових множень для одиничних бітів ключа. Якщо обчислювати кожне таке множення наївно — спочатку перемножити два 2048-бітних числа у проміжний 4096-бітний добуток, а потім виконати класичне довге ділення на модуль `N` за алгоритмом D Кнута, — продуктивність системи катастрофічно падає.

Причина полягає в фундаментальній асиметрії процесорних інструкцій. Множення двох 64-бітних слів `mulx` на сучасних процесорах виконується за 3–4 такти з повною конвеєризацією (пропускна здатність — одна операція на такт). Натомість інструкція апаратного цілочисельного ділення `div` виконується за 25–80 тактів, не піддається конвеєризації та блокує конвеєр виконання. У багаторозрядному довгому діленні дільник `N` зсувається від старших розрядів до молодших, вимагаючи на кожному кроці оцінки пробної цифри частки, нормалізації бітовими зсувами, кількох умовних переходів та корекційних віднімань. У внутрішньому циклі з 3000 операцій це створює мільйони скидань конвеєра через помилки передбачення переходів і робить класичне ділення головним вузьким місцем усієї асиметричної криптографії.

Множення за Монтгомері (Montgomery multiplication) усуває цю проблему завдяки радикальній зміні алгебраїчного кута зору: замість того щоб послідовно ділити число на незручний модуль `N`, воно переводить операнди в ізоморфний простір, де ділення на `N` замінюється швидким обнуленням молодших бітів і безкоштовним бітовим зсувом на двійкову основу `R = 2⁶⁴ᵏ`.

## Анатомія проблеми: чому класичне довге ділення непридатне для криптографії

Щоб зрозуміти масштаби накладних витрат, розглянемо класичний алгоритм довгого ділення Кнута (Algorithm D), який століттями залишався стандартним способом обчислення остачі `T mod N` для багаторозрядних чисел.

Нехай подвійний добуток `T = A · B` складається з `2k` слів за основою `b = 2⁶⁴`, а дільник `N` — з `k` слів. Для знаходження остачі алгоритм виконує такі послідовні кроки:

1. **Нормалізація**: модуль `N` зсувається вліво на таку кількість бітів `s`, щоб його старший біт став одиницею (`N[k-1] ≥ b / 2`). Це необхідно для зменшення похибки оцінки частки. Ділене `T` також зсувається вліво на `s` бітів.
2. **Цикл оцінки частки**: для кожної позиції частки `j` від `k` до `0` процесор оцінює пробну цифру частки:
   ```
   q̂ = min(⌊(T[j+k] · b + T[j+k-1]) / N[k-1]⌋, b - 1)
   ```
   Ця формула вимагає ділення 128-бітного числа на 64-бітне, що викликає повільну апаратну команду ділення.
3. **Корекція та перевірка**: оскільки `q̂` може перевищувати справжню цифру частки на 1 або 2, алгоритм перевіряє умову:
   ```
   q̂ · N[k-2] > (T[j+k] · b + T[j+k-1] - q̂ · N[k-1]) · b + T[j+k-2]
   ```
   Якщо умова справджується, `q̂` зменшується на одиницю.
4. **Множення та віднімання**: обчислюється `T = T - q̂ · N · bʲ`. Якщо проміжний результат стає від'ємним (що трапляється через похибку оцінки частки), виконується коригувальне додавання `T = T + N · bʲ` (add-back step), а частка `q̂` зменшується ще на 1.
5. **Денормалізація**: остаточна остача зсувається вправо на `s` бітів.

У цій послідовності дій криються три критичні дефекти продуктивності та безпеки:
- **Послідовна залежність за даними від старших розрядів до молодших**: кожна наступна цифра частки може бути обчислена лише після завершення віднімання всього `k`-слівного вектора на попередньому кроці. Конвеєр процесора не може розпаралелити ці обчислення.
- **Непередбачувані розгалуження (Branch Mispredictions)**: умовні переходи в блоці корекції частки та кроці add-back залежать від значень окремих розрядів діленого. Блок передбачення переходів сучасних процесорів (BPU) регулярно помиляється, викликаючи повне скидання конвеєра (pipeline flush), що коштує 15–20 тактів на кожну помилку.
- **Вразливість до атак за часом (Timing Attacks)**: залежність кількості тактів від бітів проміжних даних створює витік інформації через сторонні канали.

## Ідея Монтгомері: редукція молодших розрядів замість старших

Пітер Монтгомері 1985 року запропонував змінити напрямок обчислень на протилежний. Замість того щоб усувати старші розряди числа `T` відніманням, він запропонував обнуляти **молодші** розряди числа `T` додаванням.

Якщо до числа `T` додати деяке кратне модуля `m · N`, його значення за модулем `N` не зміниться:

```
T + m · N ≡ T (mod N)
```

Головне математичне спостереження полягає в тому, що підібрати коефіцієнт `m` для обнулення молодших `k` слів числа `T` незрівнянно простіше, ніж знайти частку для старших розрядів. Для цього потрібно, щоб сума `T + m · N` була кратною степеню двійки `R = 2⁶⁴ᵏ`:

```
T + m · N ≡ 0 (mod R)
```

Звідси коефіцієнт `m` однозначно визначається модулярним рівнянням:

```
m · N ≡ -T (mod R)
m ≡ (-T · N⁻¹) (mod R)
m = (T · (-N⁻¹ mod R)) mod R
```

Якщо позначити константу `N' = (-N⁻¹) mod R`, то коефіцієнт `m = (T · N') mod R` обчислюється лише операціями за модулем степеня двійки `R`. В апаратній та програмній реалізації взяття за модулем `R = 2⁶⁴ᵏ` — це просто відкидання старших слів (побітова маска), а ділення суми `(T + m · N) / R` — це правий бітовий зсув на `64k` бітів (або зміщення покажчика масиву на `k` слів), що виконується миттєво.

## Простір Монтгомері та алгебраїчний ізоморфізм

Результат обчислення `(T + m · N) / R` дорівнює не чистому значенню `(A · B) mod N`, а величині:

```
(A · B · R⁻¹) mod N
```

Зайвий множник `R⁻¹ mod N` виникає через те, що ми поділили суму на `R`. Щоб цей множник не спотворював обчислення, числа переносять у спеціальне представлення — простір Монтгомері (Montgomery domain).

Нехай задано непарний модуль `N` та допоміжну основу `R = 2⁶⁴ᵏ > N` таку, що `НСД(R, N) = 1`. Образом Монтгомері (Montgomery form) для довільного числа `A ∈ [0, N - 1]` називається число `Ā`:

```
Ā = (A · R) mod N
```

Відображення `A ↦ Ā` є ізоморфізмом (грец. *isos* — однаковий, *morphe* — форма) між стандартним кільцем лишків `Z_N` та простором Монтгомері:

1. **Додавання**:
```
Ā + B̄
= (A · R + B · R) mod N         [підстановка означення образів Монтгомері]
= ((A + B) · R) mod N           [дистрибутивність: винесення R за дужки]
= (A + B)_bar                   [за означенням образу суми]
```
Додавання образів у просторі Монтгомері виконується звичайним модулярним додаванням без участі оператора редукції.

2. **Віднімання**:
```
Ā - B̄
= (A · R - B · R) mod N         [підстановка означення образів Монтгомері]
= ((A - B) · R) mod N           [дистрибутивність: винесення R за дужки]
= (A - B)_bar                   [за означенням образу різниці]
```

3. **Множення**:
Якщо просто перемножити два образи `Ā` та `B̄`, отримаємо:
```
Ā · B̄
= (A · R · B · R) mod N         [підстановка означення образів Монтгомері]
= (A · B · R²) mod N            [комутативність та асоціативність множення]
```
У добутку накопичився зайвий множник `R²`. Щоб отримати коректний образ добутку `(A · B)_bar = (A · B · R) mod N`, необхідно прибрати один степінь `R`. Саме цю функцію виконує оператор редукції Монтгомері `REDC`:

```
REDC(Ā · B̄) = (Ā · B̄ · R⁻¹) mod N = (A · B · R² · R⁻¹) mod N = (A · B · R) mod N = (A · B)_bar
```

Операція над числами у модулярній арифметиці (лат. *modulus* — міра, залишок) набуває завершеності: множення двох образів Монтгомері з наступною редукцією `REDC` дає точний образ Монтгомері їхнього математичного добутку.

## Числовий приклад роботи алгоритму

Щоб унаочнити алгебраїчний механізм редукції на простих числах, розглянемо числовий приклад:
- Модуль `N = 17`
- Допоміжна основа `R = 32 = 2⁵` (найменший степінь двійки, що перевищує `17`)
- Оскільки `НСД(32, 17) = 1`, за тотожністю Безу маємо:
  ```
  32 · 8 - 17 · 15 = 256 - 255 = 1
  ```
  Звідси: `R⁻¹ = 8 mod 17` та `N' = 15 mod 32`.

Нехай потрібно помножити два числа: `A = 7` та `B = 13`.
Математичний результат: `(7 · 13) mod 17 = 91 mod 17 = 6`.

1. **Переведення у простір Монтгомері**:
   - `Ā = (A · R) mod N = (7 · 32) mod 17 = 224 mod 17 = 3`
   - `B̄ = (B · R) mod N = (13 · 32) mod 17 = 416 mod 17 = 8`

2. **Звичайне множення образів**:
   - `T = Ā · B̄ = 3 · 8 = 24`

3. **Редукція REDC(T)**:
   - Обчислюємо коефіцієнт: `m = (T · N') mod R = (24 · 15) mod 32 = 360 mod 32 = 8`
   - Додаємо `m · N`: `T + m · N = 24 + 8 · 17 = 24 + 136 = 160`
   - Ділимо на `R`: `U = 160 / 32 = 5` (ділення точне, оскільки 160 закінчується нулями в двійковій системі: `160 = 10100000₂`, `32 = 100000₂`)
   - Перевіряємо межу: `U = 5 < 17`, тому корекція не потрібна.
   - Отримано образ результату: `C̄ = 5`. Перевірка: `(6 · 32) mod 17 = 192 mod 17 = 5` — образ добутку обчислено абсолютно точно!

4. **Вихід із простору Монтгомері**:
   - `C = REDC(C̄) = REDC(5)`
   - `m = (5 · 15) mod 32 = 75 mod 32 = 11`
   - `U = (5 + 11 · 17) / 32 = (5 + 187) / 32 = 192 / 32 = 6`
   - Отримано початковий канонічний результат: `C = 6`.

Усі операції ділення на модуль `N` були повністю виключені й замінені діленням на ступінь двійки 32.

## Базовий оператор редукції REDC

Оператор редукції (лат. *reductio* — зведення, повернення назад) `REDC` приймає подвійне число `T` у діапазоні `0 ≤ T < R · N` і повертає значення `U ≡ T · R⁻¹ (mod N)` у канонічному діапазоні `0 ≤ U < N`.

Алгоритм виконується за три кроки:
1. **Обчислення коефіцієнта обнулення**:
```
m = (T mod R) · N' mod R
```
2. **Додавання кратного модуля та зсув**:
```
U = (T + m · N) / R
```
3. **Фінальна корекція меж**:
Оскільки `T < R · N` та `m < R`, чисельник суворо обмежений:
```
T + m · N < R · N + R · N = 2 · R · N
```
Ділячи на `R`, отримуємо нерівність:
```
U = (T + m · N) / R < 2N
```
Оскільки `U` гарантовано менше за `2N`, для отримання канонічної остачі достатньо виконати рівно одне умовне віднімання:
```
якщо U ≥ N, то U = U - N; інакше повернути U
```

*Механізм редукції REDC: додавання m · N перетворює молодші k слів на нулі, дозволяючи виконати точний правий бітовий зсув на R*

## Послівна редукція та обчислення оберненого лімба n0'

У практичній реалізації модуль `N` має розмір сотні байтів. Обчислення повного 2048-бітного числа `N' = (-N⁻¹) mod 2²⁰⁴⁸` було б надто складним і вимагало б великої кількості пам'яті.

Багаторозрядна арифметика використовує представлення чисел у вигляді масиву машинних слів — лімбів (лат. *limbus* — край, смуга; англ. *limb* — сегмент). Для 64-бітної архітектури основою є слово `b = 2⁶⁴`.

Фундаментальна властивість позиційної системи числення полягає в тому, що молодше слово добутку `(T · N') mod b` залежить **виключно** від молодшого слова числа `T` та молодшого слова модуля `N[0]`. Тому для обробки чисел будь-якої довжини достатньо один раз обчислити лише одне 64-бітне значення:

```
n0' = (-N[0]⁻¹) mod 2⁶⁴
```

Оскільки модуль `N` у криптографії завжди непарний (`N[0] & 1 == 1`), число `N[0]` взаємно просте з основою `2⁶⁴`, і обернений елемент гарантовано існує.

Обчислення `n0'` здійснюється без ділення за допомогою ітерацій Ньютона — Рафсона (підйом Гензеля). Формула ітерації:

```
x_{k+1} = x_k · (2 - N[0] · x_k) mod 2⁶⁴
```

Починаючи з `x₀ = 1`, кожна ітерація подвоює кількість точних бітів: 1 → 2 → 4 → 8 → 16 → 32 → 64. Усього 6 швидких множень машинних слів дають точне значення `n0'`:

:::tabs
```c
#include <stdint.h>

/* Обчислення n0' = (-N[0]^(-1)) mod 2^64 за 6 кроків Гензеля */
uint64_t compute_n0_prime(uint64_t n0) {
    uint64_t inv = 1;
    for (int i = 0; i < 6; i++) {
        inv = inv * (2 - n0 * inv);
    }
    return (uint64_t)(-(int64_t)inv);
}
```
```cpp
#include <cstdint>

namespace bignum {

/* Обчислення n0' у compile-time або runtime */
constexpr uint64_t compute_n0_prime(uint64_t n0) noexcept {
    uint64_t inv = 1;
    for (int i = 0; i < 6; ++i) {
        inv = inv * (2 - n0 * inv);
    }
    return static_cast<uint64_t>(-static_cast<int64_t>(inv));
}

} // namespace bignum
```
:::

## Алгоритмічні архітектури: SOS проти CIOS

Існує кілька способів реалізації багаторозрядного множення Монтгомері залежно від порядку обходу операндів.

### 1. Розділене сканування операндів (SOS — Separated Operand Scanning)
Алгоритм SOS працює у дві чітко розділені фази:
- **Фаза множення**: обчислюється повний добуток `T = A · B` класичним шкільним методом. Для двох `k`-лімбових чисел створюється проміжний масив розміром `2k + 1` лімбів.
- **Фаза редукції**: виконується зовнішній цикл від `i = 0` до `k - 1`. На кожному кроці обчислюється `m = (T[i] · n0') mod b`, після чого кратне `m · N` додається до зрізу `T[i .. i + k]`, а перенесення поширюється до кінця масиву.

Недоліком SOS є великий розмір проміжного буфера `T` (65 слів для 2048 бітів), що призводить до зайвих звернень до оперативної пам'яті або кешу другого рівня.

### 2. Інтегроване сканування операндів (CIOS — Coarsely Integrated Operand Scanning)
Алгоритм CIOS об'єднує накопичення рядка множення та редукцію молодшого слова в єдиному зовнішньому циклі за індексом `i` (від `0` до `k - 1`):
1. **Накопичення**: до поточного стану акумулятора додається добуток чергового лімба `A[i]` на весь вектор `B`:
   ```
   T = T + A[i] · B
   ```
2. **Обчислення редукції**: знаходиться коефіцієнт для поточного молодшого слова акумулятора:
   ```
   m = (T[0] · n0') mod 2⁶⁴
   ```
3. **Редукція та миттєвий зсув**: до акумулятора додається `m · N`. Оскільки молодше слово `(T[0] + m · N[0]) mod 2⁶⁴` стає нулем, воно негайно відкидається, а решта слів акумулятора зміщується на одну позицію вправо:
   ```
   T = (T + m · N) / 2⁶⁴
   ```

![Архітектура CIOS: чергування множення та редукції в єдиному циклі](/root/eng/sf-algorithms/montgomery-multiplication/img/cios-interleaved-loop.svg)
*Архітектура CIOS: покрокове накопичення та миттєвий зсув утримують робочий масив у межах k + 2 лімбів*

Завдяки миттєвому зсуву розмір робочого акумулятора (лат. *accumulator* — накопичувач) `T` ніколи не перевищує `k + 2` машинних слів. Для 2048-бітної арифметики це лише 34 слова (272 байти), які повністю поміщаються в регістрах або гарячому кеші L1D.

### 3. Дрібнозернисті архітектури: FIOS та FIPS
- **FIOS (Finely Integrated Operand Scanning)**: чергує множення та додавання модуля безпосередньо у внутрішньому циклі за індексом `j`. Це вимагає складнішого відстеження перенесень, але мінімізує кількість проміжних регістрів.
- **FIPS (Finely Integrated Product Scanning)**: обчислює результат методом сканування стовпчиків (product scanning), накопичуючи значення безпосередньо у вихідні комірки. Метод ефективний на сигнальних мікропроцесорах (DSP) з апаратними інструкціями MAC.

На сучасних суперскалярних процесорах архітектури x86-64 та AArch64 алгоритм CIOS забезпечує найкращий баланс між простотою генерації коду, мінімальним використанням пам'яті та ефективністю оптимізатора компілятора.

```c
#include <stdint.h>
#include <stddef.h>
#include <string.h>

/* Допоміжне множення 64x64 з двома перенесеннями */
static inline uint64_t mac2(uint64_t a, uint64_t b, uint64_t c, uint64_t d, uint64_t *hi) {
    __uint128_t prod = (__uint128_t)a * b + c + d;
    *hi = (uint64_t)(prod >> 64);
    return (uint64_t)prod;
}

/* Сталочасове умовне віднімання без розгалужень */
static void sub_conditional_ct(uint64_t *u, const uint64_t *n, size_t k) {
    uint64_t borrow = 0;
    uint64_t diff[k];
    for (size_t i = 0; i < k; i++) {
        __uint128_t sub = (__uint128_t)u[i] - n[i] - borrow;
        diff[i] = (uint64_t)sub;
        borrow = (uint64_t)(sub >> 127) & 1;
    }
    uint64_t mask = (uint64_t)(-(int64_t)(1 - borrow));
    for (size_t i = 0; i < k; i++) {
        u[i] = (diff[i] & mask) | (u[i] & ~mask);
    }
}

/* Повне множення за Монтгомері методом CIOS */
void montgomery_mul_cios(const uint64_t *a, const uint64_t *b,
                         const uint64_t *n, size_t k,
                         uint64_t n0_prime, uint64_t *res) {
    uint64_t t[k + 2];
    memset(t, 0, sizeof(t));

    for (size_t i = 0; i < k; i++) {
        uint64_t carry = 0;
        for (size_t j = 0; j < k; j++) {
            t[j] = mac2(a[i], b[j], t[j], carry, &carry);
        }
        __uint128_t sum_carry = (__uint128_t)t[k] + carry;
        t[k] = (uint64_t)sum_carry;
        t[k + 1] = (uint64_t)(sum_carry >> 64);

        uint64_t m = (uint64_t)(t[0] * n0_prime);

        uint64_t c2 = 0;
        mac2(m, n[0], t[0], 0, &c2);

        for (size_t j = 1; j < k; j++) {
            t[j - 1] = mac2(m, n[j], t[j], c2, &c2);
        }

        __uint128_t sum2 = (__uint128_t)t[k] + c2;
        t[k - 1] = (uint64_t)sum2;
        t[k] = t[k + 1] + (uint64_t)(sum2 >> 64);
        t[k + 1] = 0;
    }

    memcpy(res, t, k * sizeof(uint64_t));
    sub_conditional_ct(res, n, k);
}
```

```cpp
#include <cstdint>
#include <cstddef>
#include <vector>
#include <span>
#include <algorithm>
#include <stdexcept>

namespace bignum {

class MontgomeryMultiplier {
public:
    static void multiply_cios(std::span<const uint64_t> a,
                              std::span<const uint64_t> b,
                              std::span<const uint64_t> n,
                              uint64_t n0_prime,
                              std::span<uint64_t> res) {
        const size_t k = n.size();
        if (a.size() != k || b.size() != k || res.size() != k) {
            throw std::invalid_argument("Operands size mismatch");
        }

        std::vector<uint64_t> t(k + 2, 0);

        for (size_t i = 0; i < k; ++i) {
            uint64_t carry = 0;
            for (size_t j = 0; j < k; ++j) {
                __uint128_t prod = static_cast<__uint128_t>(a[i]) * b[j] + t[j] + carry;
                t[j] = static_cast<uint64_t>(prod);
                carry = static_cast<uint64_t>(prod >> 64);
            }
            __uint128_t sum_carry = static_cast<__uint128_t>(t[k]) + carry;
            t[k] = static_cast<uint64_t>(sum_carry);
            t[k + 1] = static_cast<uint64_t>(sum_carry >> 64);

            uint64_t m = static_cast<uint64_t>(t[0] * n0_prime);

            __uint128_t prod_m0 = static_cast<__uint128_t>(m) * n[0] + t[0];
            uint64_t c2 = static_cast<uint64_t>(prod_m0 >> 64);

            for (size_t j = 1; j < k; ++j) {
                __uint128_t prod = static_cast<__uint128_t>(m) * n[j] + t[j] + c2;
                t[j - 1] = static_cast<uint64_t>(prod);
                c2 = static_cast<uint64_t>(prod >> 64);
            }

            __uint128_t sum2 = static_cast<__uint128_t>(t[k]) + c2;
            t[k - 1] = static_cast<uint64_t>(sum2);
            t[k] = t[k + 1] + static_cast<uint64_t>(sum2 >> 64);
            t[k + 1] = 0;
        }

        std::copy_n(t.begin(), k, res.begin());
        sub_conditional_constant_time(res, n);
    }

private:
    static void sub_conditional_constant_time(std::span<uint64_t> u,
                                              std::span<const uint64_t> n) noexcept {
        const size_t k = n.size();
        uint64_t borrow = 0;
        std::vector<uint64_t> diff(k);

        for (size_t i = 0; i < k; ++i) {
            __uint128_t sub = static_cast<__uint128_t>(u[i]) - n[i] - borrow;
            diff[i] = static_cast<uint64_t>(sub);
            borrow = static_cast<uint64_t>(sub >> 127) & 1;
        }

        const uint64_t mask = static_cast<uint64_t>(-static_cast<int64_t>(1 - borrow));
        for (size_t i = 0; i < k; ++i) {
            u[i] = (diff[i] & mask) | (u[i] & ~mask);
        }
    }
};

} // namespace bignum
```

## Модулярне піднесення до степеня

Головна перевага множення за Монтгомері розкривається в алгоритмах модулярного експоненціювання (лат. *exponere* — виставляти напоказ, підносити до степеня).

Нехай потрібно обчислити `C = M^e mod N`. Повний процес складається з чотирьох етапів:

1. **Попередня підготовка констант**:
   - Обчислюється `n0' = (-N[0]⁻¹) mod 2⁶⁴`.
   - Обчислюється константа переводу `R² mod N` (де `R = 2⁶⁴ᵏ`).

2. **Вхід у простір Монтгомері**:
   Основа `M` переводиться у форму Монтгомері за допомогою однієї операції `REDC`:
   ```
   M_bar = REDC(M · (R² mod N)) = (M · R² · R⁻¹) mod N = (M · R) mod N
   ```
   Акумулятор результату ініціалізується образом одиниці:
   ```
   acc_bar = REDC(1 · (R² mod N)) = (1 · R² · R⁻¹) mod N = (R mod N)
   ```

3. **Цикл піднесення до степеня**:
   Скануючи біти показника степеня `e` від старшого до молодшого:
   - На кожному кроці виконується піднесення до квадрата:
     ```
     acc_bar = REDC(acc_bar · acc_bar)
     ```
   - Якщо поточний біт показника дорівнює `1`, виконується множення:
     ```
     acc_bar = REDC(acc_bar · M_bar)
     ```

4. **Вихід із простору Монтгомері**:
   Після обробки всіх бітів накопичене значення `acc_bar` містить образ `(M^e · R) mod N`. Для отримання звичайного числа виконується одна фінальна редукція:
   ```
   C = REDC(acc_bar) = (M^e · R · R⁻¹) mod N = (M^e) mod N
   ```

Усі 3000 модулярних множень у циклі відбуваються повністю всередині простору Монтгомері. Витрати на переведення сплачуються рівно двічі — на самому початку та наприкінці обчислення.

## Стійкість до атак за сторонніми каналами (Side-Channel Security)

Модулярне множення є мішенню атак за часом виконання (Timing Attacks), описаних Полом Кохером (Paul Kocher) 1996 року.

У наївній реалізації редукції `REDC` фінальний крок виглядає як розгалуження:
```
if (U >= N) {
    U = U - N;
}
```

Ймовірність виконання цього віднімання залежить від значень операндів. Якщо один із операндів пов'язаний із секретним ключем RSA або скаляром еліптичної кривої, час виконання кожного множення коливається на 5–15 тактів. Вимірюючи загальний час виконання підпису для кількох тисяч відкритих повідомлень, зловмисник може повністю відновити біти приватного ключа.

Для запобігання цим витокам застосовують два криптографічні підходи:

1. **Сталочасове умовне віднімання (Branchless Subtraction)**:
   Як показано в нашій реалізації `sub_conditional_ct`, операція віднімання виконується завжди. Біт переповнення конвертується в маску з усіх одиниць або всіх нулів, і вибір між `U` та `U - N` здійснюється за допомогою побітових операцій `AND`, `OR` та `NOT`. Кількість тактів процесора залишається абсолютно однаковою незалежно від значень операндів.

2. **Релаксована редукція Вальтера (Walter's Redundant Representation)**:
   Якщо обрати основу `R > 4N`, то операнди можуть зберігатися в розширеному діапазоні `[0, 2N)`. У цьому випадку проміжні умовні віднімання взагалі виключаються з внутрішнього циклу піднесення до степеня, а єдине зведення за модулем `N` виконується лише на виході з алгоритму.

## Апаратне прискорення: інструкції x86-64 та ARM64

Сучасні 64-розрядні мікропроцесори містять спеціалізовані інструкції, створені спеціально для прискорення алгоритму CIOS Монтгомері:

- **MULX (BMI2)**: множить два 64-бітних регістри без зміни прапорців процесора `FLAGS`, записуючи 128-бітний добуток у два довільні регістри призначення.
- **ADCX та ADOX**: інструкції додавання з перенесенням, які використовують незалежні прапорці `CF` (Carry Flag) та `OF` (Overflow Flag). Це дозволяє суперскалярному ядру виконувати два незалежні ланцюжки перенесення паралельно в одному такті — один для накопичення `A[i] · B[j]`, а другий для додавання `m · N[j]`.
- **AVX-512 IFMA**: векторні інструкції (Integer Fused Multiply-Add), що оперують 52-бітними лімбами в 512-бітних векторних регістрах, виконуючи вісім паралельних 52×52-бітних множень за такт.

Завдяки цим інструкціям швидкість виконання 2048-бітного множення Монтгомері на серверних процесорах досягає менш ніж 800 тактів.

## Гібридні алгоритми для надвеликих чисел: Карацуба та Монтгомері

Для чисел помірного розміру (256–2048 бітів) алгоритм CIOS зі шкільним множенням є оптимальним через мінімальні накладні витрати на цикли та ідеальну локальність кешу. Проте коли довжина чисел перевищує 4096 бітів (наприклад, у криптографічних схемах на базі решіток чи постквантових протоколах), асимптотична складність шкільного множення `O(k²)` починає поступатися рекурсивним алгоритмам.

У таких випадках застосовують гібридний підхід:
1. **Множення Карацуби**: добуток `T = Ā · B̄` обчислюється за алгоритмом Карацуби за час `O(k^{1.585})`.
2. **Блочна редукція Монтгомері**: обчислене подвійне число `T` редукується блочним алгоритмом Монтгомері, де множення `m · N` також прискорюється методом Карацуби.

Цей гібридний підхід використовується у високопродуктивних бібліотеках GMP та OpenSSL для ключів RSA довжиною 4096 та 8192 біти.

## Арифметика еліптичних кривих у формі Монтгомері

Крім класичного піднесення чисел до степеня в кільцях лишків RSA, ідея Монтгомері отримала фундаментальне розширення в теорії еліптичних кривих. Еліптична крива у формі Монтгомері задається рівнянням:

```
B · y² = x³ + A · x² + x
```

де `A` та `B` — константи поля.

Головна перевага цієї форми полягає в алгоритмі швидкого скалярного множення — драбині Монтгомері (Montgomery ladder). Драбина Монтгомері дозволяє обчислювати додавання точок кривої, використовуючи **виключно x-координати** точок (без необхідності зберігати та обчислювати координату `y`). Усі проміжні операції в полі над кривою (наприклад, над простим полем `2²⁵⁵ - 19` у кривій Curve25519) реалізуються за допомогою модулярного множення Монтгомері.

Драбина Монтгомері виконує фіксовану послідовність додавання та подвоєння точок на кожному біті скаляра незалежно від того, чи є цей біт нулем або одиницею. Це гарантує абсолютну симетрію за часом виконання та енергоспоживанням (DPA/SPA resistance), роблячи алгоритм стандартом для сучасних протоколів обміну ключами X25519 та цифрових підписів Ed25519.

## Порівняльний аналіз методів модулярного множення

| Критерій | Класичне ділення Knuth D | Редукція Барретта | Множення Монтгомері (CIOS) |
| :--- | :--- | :--- | :--- |
| **Попередні обчислення** | Немає | `μ = ⌊4ᵏ / N⌋` | `n0' = -N[0]⁻¹ mod b`, `R² mod N` |
