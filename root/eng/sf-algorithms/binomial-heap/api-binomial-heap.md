# 📋 Інтерфейс та специфікація біноміальної купи (Binomial Heap API)

Цей документ містить повну та вичерпну специфікацію програмного інтерфейсу, інваріантів структури даних, асимптотичних гарантій, вимог до обробки помилок та контракту пам'яті для біноміальної купи (Binomial Heap). Довідка призначена для розробників системного програмного забезпечення, які впроваджують або інтегрують цю структуру даних у високонавантажені системи обробки подій, операційні системи чи системні утиліти.

---

## 1. Інваріанти структури даних та макет у пам'яті

Біноміальна купа `H` є впорядкованим лісом біноміальних дерев `{B_k}`, який у будь-який момент часу між операціями задовольняє чотири фундаментальні інваріанти.

### 1.1. Чотири інваріанти біноміальної купи

1. **Інваріант мін-купи (Min-Heap Property):** Для кожного вузла `x` у будь-якому біноміальному дереві купи його ключ `x.key` є строго не меншим за ключ його батьківського вузла `x.parent.key` (якщо батьківський вузол існує). Наслідком цього інваріанта є те, що найменший елемент будь-якого дерева завжди розташований у його корені.
2. **Інваріант унікальності степенів (Unique Degree Property):** Для будь-якого цілого від'ємного чи додатного значення `k ≥ 0` купа `H` містить **не більше одного** біноміального дерева `B_k` степеня `k`. Цей інваріант безпосередньо випливає з двійкового розкладу кількості елементів `N`: кожен біт у двійковому записі `N` відповідає наявності чи відсутності відповідного дерева `B_k`.
3. **Інваріант суворого зростання коренів (Strictly Increasing Root Order):** Корені біноміальних дерев у кореневому списку зв'язані за допомогою вказівника `sibling` у порядку суворо зростаючого степеня: `degree(root_1) < degree(root_2) < ... < degree(root_m)`.
4. **Інваріант спадання степенів дітей (Strictly Decreasing Child Order):** Для будь-якого вузла `x` степеня `k` його безпосередні діти зв'язані у список за допомогою вказівників `sibling` у порядку суворого спадання їхніх степенів: від найбільшого піддерева `B_{k-1}` до найменшого `B_0`. Найлівіша дитина, на яку вказує `x.child`, є коренем дерева `B_{k-1}`.

### 1.2. Структура вузла та витрати пам'яті (Memory Overhead)

Кожен вузол біноміальної купи у реалізації мовами C чи C++ представляє собою окремий блок динамічної пам'яті. Вузли зв'язуються за схемою *Left-Child, Right-Sibling*.

На 64-розрядних архітектурах (x86_64, AArch64) макет вузла у пам'яті виглядає наступним чином:

- `key` (тип даних `T` або `int64_t`): 8 байтів;
- `degree` (ціле число `int32_t`): 4 байти (з вирівнюванням до 8 байтів);
- `parent` (вказівник `Node*`): 8 байтів;
- `child` (вказівник `Node*`): 8 байтів;
- `sibling` (вказівник `Node*`): 8 байтів.

Загальний розмір одного вузла становить **40 байтів** (з урахуванням вирівнювання пам'яті компілятором). Оскільки структура використовує динамічний розподіл пам'яті через `malloc` або `new`, до цього додаються накладні витрати самого аллокатора пам'яті (зазвичай 8–16 байтів на блок).

Порівняно з двійковою купою, яка зберігається у вигляді щільного масиву з нульовими накладними витратами на вказівники (0 байтів на елемент крім самого ключа), біноміальна купа вимагає відчутно більше пам'яті. Проте ця ціна сплачується за можливість виконання логарифмічного злиття `O(log n)`.

## 2. Зведена таблиця часової та просторової складності

Припустимо, купа містить `n` елементів. Усі асимптотичні оцінки наведено у таблиці нижче з деталізацією для найгіршого та амортизованого випадків.

| Операція | Позначення | Найгірший випадок (Worst-Case Time) | Амортизований час (Amortized Time) | Допоміжна пам'ять (Space Complexity) |
| :--- | :--- | :---: | :---: | :---: |
| Створення порожньої купи | `make_heap()` | `O(1)` | `O(1)` | `O(1)` |
| Пошук мінімуму | `find_min(H)` | `O(log n)` / `O(1)`* | `O(log n)` / `O(1)`* | `O(1)` |
| Вставка елемента | `insert(H, x)` | `O(log n)` | **`O(1)`** | `O(1)` |
| Злиття двох куп | `merge(H1, H2)` | `O(log n)` | `O(log n)` | `O(1)` |
| Вилучення мінімуму | `extract_min(H)` | `O(log n)` | `O(log n)` | `O(log n)` |
| Зменшення ключа | `decrease_key(H, x, k)` | `O(log n)` | `O(log n)` | `O(1)` |
| Вилучення вузла | `delete(H, x)` | `O(log n)` | `O(log n)` | `O(log n)` |

*\* Примітка: Асимптотика `O(1)` для пошуку мінімуму досягається впровадженням додаткового вказівника `min_node` у структурі дескриптора купи, який оновлюється під час вставки, злиття та вилучення.*

## 4. Контракт ООП та шаблонів C++ (`ds::BinomialHeap<T>`)

У мові C++ біноміальна купа оформлюється у вигляді шаблонного класу `ds::BinomialHeap<T>`, який забезпечує суворі гарантії безпеки винятків (Exception Safety) та керування ресурсами за принципом RAII (Resource Acquisition Is Initialization).

```cpp
namespace ds {

template <typename T>
class BinomialHeap {
public:
    using NodeHandle = Node*;

    // Конструктор за замовчуванням: створює порожню купу за O(1)
    BinomialHeap() noexcept;

    // Деструктор: автоматично звільняє уся дерева за O(n)
    ~BinomialHeap();

    // Заборона копіювання: купа є унікальним володарем вузлів
    BinomialHeap(const BinomialHeap&) = delete;
    BinomialHeap& operator=(const BinomialHeap&) = delete;

    // Переміщення: передає володіння деревами за O(1)
    BinomialHeap(BinomialHeap&& other) noexcept;
    BinomialHeap& operator=(BinomialHeap&& other) noexcept;

    // Перевірка на порожнечу
    [[nodiscard]] bool empty() const noexcept;

    // Вставка: повертає NodeHandle для подальшого використання у decrease_key
    NodeHandle insert(T key);

    // Злиття з іншою купою: other стає порожньою
    void merge(BinomialHeap& other);

    // Пошук мінімуму: повертає std::nullopt для порожньої купи
    [[nodiscard]] std::optional<T> find_min() const;

    // Вилучення мінімуму: кидає std::underflow_error для порожньої купи
    T extract_min();

    // Зменшення ключа: кидає std::invalid_argument при new_key > current
    void decrease_key(NodeHandle handle, T new_key);
};

} // namespace ds
```

### 4.1. Гарантії безпеки винятків (Exception Safety Guarantees)

1. **Строга гарантія (Strong Exception Guarantee):** Якщо під час виконання `insert` або `merge` операція виділення пам'яті `new` або оператор порівняння `T::operator<` кидає виняток, стан купи залишається незмінним до моменту виклику.
2. **Гарантія відсутності винятків (Nothrow Guarantee):** Операції переміщення (Move Constructor / Move Assignment), перевірка `empty()` та деструктор мають гарантію `noexcept`.

## 5. Багатопотоковість та синхронізація (Thread Safety)

Біноміальна купа за замовчуванням є **непотокобезпечною структурою даних (non-thread-safe)**. Паралельне читання та запис з кількох потоків без зовнішньої синхронізації спричиняють стан перегонів (race condition) та невизначену поведінку (undefined behavior).

Для використання біноміальної купи у багатопотокових середовищах застосовують такі стратегії:
1. **Зовнішнє блокування (External Mutex Locking):** Огортання всіх викликів API у `std::mutex` або `std::shared_mutex` (з розділенням читачів і письменників для `find_min`).
2. **Конкурентне злиття:** Завдяки тому, що злиття виконується за `O(log n)`, тривалість утримання м'ютекса під час об'єднання двох черг є мінімальною порівняно з лінійним `O(n)` злиттям двійкових куп.

## 6. Крайові випадки та діагностика помилок

При практичній реалізації та експлуатації біноміальної купи слід звертати особливу увагу на наступні крайові сценарії:

1. **Вилучення з порожньої купи:** Викликати `extract_min` над порожньою купою є грубою помилкою. C++ реалізація сигналізує про це через виняток `std::underflow_error`, а C-версія перевіряє вказівник перед операцією.
2. **Недійсність дескрипторів `NodeHandle`:** Якщо вузол було вилучено через `extract_min` або `delete`, будь-яке подальше звернення до цього вузла через збережений `NodeHandle` у виклику `decrease_key` є викликом використання після звільнення (Use-After-Free).
3. **Спроба збільшити ключ у `decrease_key`:** Передача значення `new_key > current_key` порушує інваріант мін-купи. Функція має перевіряти це й негайно відхиляти операцію.
