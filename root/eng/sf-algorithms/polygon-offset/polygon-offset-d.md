Фрезерний верстат із числовим програмним керуванням вирізає квадратну деталь розміром 100 × 100 мм з алюмінієвої пластини за допомогою обертової фрези радіусом `R = 5` мм. Якщо шпиндель верстата спрямувати строго по лініях заданого периметра квадрата, різальна кромка інструмента заглибиться в матеріал заготовки на 5 мм з кожного боку. У результаті готова деталь матиме розмір 90 × 90 мм замість 100 × 100 мм, а прямі кути виявляться зрізаними. Щоб виготовити деталь точного номіналу, центр інструмента повинен рухатися не по межі виробу, а по паралельній траєкторії, яка рівновіддалена від базової лінії на відстань `d = R` у кожній точці.

Аналогічна задача виникає при 3D-друку пластиком: щоб сформувати міцну зовнішню стінку деталі завтовшки 1.2 мм за допомогою сопла діаметром 0.4 мм, слайсер повинен укласти три паралельні нитки розплавленого полімеру. Перша нитка проходить на відстані 0.2 мм від зовнішнього периметра, друга — на 0.6 мм, третя — на 1.0 мм. Усі ці траєкторії є послідовними внутрішніми зміщеннями вихідної геометричної межі шару.

Така зміщена лінія, кожна точка якої розташована на фіксованій перпендикулярній відстані від базової кривої, називається **еквідистантою** (лат. *aequus* — рівний + *distantia* — відстань), а сама операція побудови рівновіддаленої межі — **зсувом контуру** (франц. *contour* — обрис, від лат. *tornare* — обточувати; в англомовній літературі — *polygon offset*, *buffering* або *inflation/deflation*).

![Компенсація радіуса фрези та зміщення траєкторії відносно деталі](/root/eng/sf-algorithms/polygon-offset/img/offset-concept-cnc.svg)
*При русі центром фрези по контуру деталі матеріал зарізається на величину радіуса R. Зсув траєкторії назовні на величину d = R (еквідистанта) забезпечує точний дотик кромки до номінального контуру.*

Історично ця задача виникла разом із першими ЧПК-системами в авіабудуванні, де вимагався точний розрахунок траєкторій інструментів різного діаметра: [Історичний розвиток: від компенсації фрези в ЧПК до геометричних кістяків](root:sf-algorithms/polygon-offset/hist-offset-evolution.md).

## Геометрія зсуву окремого відрізка

Розглянемо замкнений багатокутник із `n` вершин `V₀, V₁, ..., V_{n-1}`, заданий у порядку обходу проти годинникової стрілки (CCW). Кожна грань є прямолінійним відрізком між точками `A = (x₁, y₁)` та `B = (x₂, y₂)`.

Вектор напрямку грані дорівнює:

```
v = (dx, dy) = (x₂ − x₁, y₂ − y₁)
```

Довжина ребра обчислюється через евклідову норму:

```
L = √(dx² + dy²)
```

Щоб зсунути пряму на відстань `d` назовні (ліворуч від напрямку обходу при русі CCW), необхідно знайти одиничний вектор зовнішньої **нормалі** (лат. *normalis* — прямий, перпендикулярний). Поворот вектора `(dx, dy)` на 90° проти годинникової стрілки задається вектором `(−dy, dx)`. Нормуючи його на довжину `L`, отримуємо одиничну нормаль:

```
n = (−dy / L, dx / L)
```

Зміщене ребро лежить на прямій, яка проходить через зміщені точки:

```
A' = A + d · n
B' = B + d · n
```

Для окремого прямолінійного відрізка зміщення тривіальне — це паралельний відрізок тієї самої довжини на відстані `d`. Складнощі починаються у вершинах, де дві сусідні грані сходяться під кутом.

## Чому наївний зсув вершин не працює

Перша інтуїтивна спроба побудувати зміщений контур часто полягає в тому, щоб просто зсунути кожну вершину `V` на фіксовану відстань `d` уздовж бісектриси кута між суміжними ребрами. Проте прямий зсув вершини на константну величину `d` призводить до грубої геометричної помилки: відстань від зміщеної вершини до граней багатокутника виявляється меншою за `d`.

Розглянемо кутовий стик із внутрішнім кутом `θ`. Щоб обидва зміщені ребра залишалися паралельними вихідним граням на відстані `d`, зміщена вершина повинна лежати на перетині двох зміщених прямих. Оскільки кожна пряма відсунута на `d`, відстань від вихідної вершини до точки перетину прямих вздовж бісектриси дорівнює не `d`, а `d / sin(θ / 2)`.

На прямому куті (`θ = 90°`) зміщення вершини має становити:

```
|m| = d / sin(45°) = d · √2 ≈ 1.414 · d
```

Якщо зсунути вершину лише на `d`, грані в кутку викривляться і перестануть бути паралельними вихідному контуру, а реальний зазор між зміщеною лінією та вихідним відрізком зменшиться до `d · sin(45°) ≈ 0.707 · d`.

Геометрична похибка наївного підходу `E(θ) = d · (1 − sin(θ / 2))` стрімко зростає при загостренні кута:
- При прямому куті `θ = 90°` похибка становить `29.3%` від величини зсуву `d`.
- При куті `θ = 60°` похибка досягає `50.0%` (реальний відступ вдвічі менший за заданий).
- При гострому куті `θ = 30°` похибка сягає `74.1%`.

Отже, еквідистанта будується не зсувом вершин, а зсувом самих прямолінійних граней з подальшим коректним геометричним стикуванням сусідніх відрізків у вершинах.

## Кутові з'єднання на опуклих вершинах

Нехай у вершині `V` сходяться вхідне ребро з нормаллю `n₁` та вихідне ребро з нормаллю `n₂`. Зсунувши обидва відрізки на відстань `d`, ми отримуємо дві паралельні прямі, які у загальному випадку не стикуються в одній точці вихідної вершини `V`.

На **опуклих вершинах** (де кут повороту контуру спрямований назовні) зміщені відрізки розходяться, утворюючи розрив між кінцем першого зміщеного сегмента `A'₁` та початком другого `B'₂`. Для замикання контуру в комп'ютерній графіці та CAD-системах застосовують три класичні типи кутових стиків (*join types*):

![Типи кутових з'єднань еквідистанти на опуклих вершинах](/root/eng/sf-algorithms/polygon-offset/img/join-types.svg)
*Три способи замикання розриву на опуклому куті: гострий стик (miter) через перетин зміщених прямих, скруглення (round) дугою радіуса d та пряма фаска (bevel).*

### 1. Гострий стик (Miter Join)

Обидві зміщені прямі продовжуються до їхнього взаємного перетину в єдиній точці `P`. Оскільки точка `P` мусить знаходитися на відстані `d` від обох ребер, вона лежить на кутовій **бісектрисі** (лат. *bi-* — подвійний + *seco* — розсікати).

Вектор зміщення вершини `m = P − V` розраховується через суму нормалей:

```
m = d · (n₁ + n₂) / (1 + n₁ · n₂)
```

Аналітичне виведення цієї формули та доведення її еквівалентності перетину прямих наведено у вставці: [Математичне обґрунтування: вектор зсуву вершини, бісектриси та сума Мінковського](root:sf-algorithms/polygon-offset/math-offset-geometry.md).

Довжина вектора зміщення `|m|` залежить від внутрішнього кута многокутника `θ`:

```
|m| = d / sin(θ / 2)
```

Гострий стик зберігає природну геометрію фігури, подовжуючи грані до їхнього природного кута. Однак ця формула містить принципову проблему при малих кутах.

### Проблема гострого шипа та Miter Limit

Коли кут між ребрами стає дуже гострим (`θ → 0°`), знаменник `sin(θ / 2)` прямує до нуля, а довжина стику `|m|` необмежено зростає до нескінченності.

Для зміщення на `d = 10` мм залежність довжини гострого стику від кута виглядає так:

| Внутрішній кут `θ` | Половинний кут `θ / 2` | Значення `sin(θ / 2)` | Довжина стику `\|m\|` (при `d = 10` мм) |
|---|---|---|---|
| `180°` (пряма лінія) | `90°` | `1.000` | `10.0 мм` |
| `90°` (прямий кут) | `45°` | `0.707` | `14.1 мм` |
| `60°` (трикутник) | `30°` | `0.500` | `20.0 мм` |
| `30°` (гострий кут) | `15°` | `0.259` | `38.6 мм` |
| `10°` (вузький клин) | `5°` | `0.087` | `114.7 мм` |
| `2°` (голка) | `1°` | `0.017` | `573.0 мм` |
| `0.5°` (мікротріщина) | `0.25°` | `0.004` | `2291.8 мм` |

Крихітний гострий кут деталі породжує півметровий або двометровий тонкий виступ, який ламає габарити виробу та перевантажує механіку верстата чи графічний рендерер.

Для запобігання цьому вводять обмеження — **поріг стику** (*miter limit* `M`). Якщо відношення `|m| / d = 1 / sin(θ / 2) > M` (зазвичай обирають `M = 2` або `M = 4`), алгоритм відмовляється від гострого перетину та зрізає верхівку прямою лінією — тобто автоматично перемикається на фаску.

### 2. Скруглення (Round Join)

Розрив між зміщеними ребрами заповнюється круговою дугою радіусом `d` з центром у вихідній вершині `V`. Дуга починається в точці `V + d · n₁` і плавно переходить у точку `V + d · n₂`.

Скруглення геометрично ідеальне з точки зору фізичного процесу: саме такий слід залишає обертова циліндрична фреза або круглий екструдер 3D-принтера. У векторних полігональних форматах дугу апроксимують ламаною з `k` коротких хорд, забезпечуючи задану точність `ε`.

### 3. Фаска (Bevel Join)

Кінці зміщених відрізків `V + d · n₁` та `V + d · n₂` з'єднують одним прямим відрізком — **фаскою** (франц. *facette* — грань, зріз). Це найпростіший та обчислювально найдешевший спосіб замикання: він не створює довгих шипів і додає мінімум нових вершин, хоча візуально дещо грубіший за дугу.

## Увігнуті вершини та локальні самоперетини

На **увігнутих вершинах** (де кут контуру спрямований всередину) ситуація протилежна: при розширенні контуру зміщені ребра не розходяться, а навпаки — насуваються одне на одне і перетинаються.

Якщо просто з'єднати кінці зміщених відрізків, утворюється внутрішня самоперетинна петля («метелик»). Частина зміщеного ребра заходить всередину матеріалу.

Правильне локальне розв'язання полягає в знаходженні точки перетину двох зміщених прямих `P = V + m`. Для увігнутого кута знаменник `1 + n₁ · n₂` залишається додатним (доки кут не вироджується в нуль), а точка `P` відсікає надлишкові «хвости» відрізків, зберігаючи чистий полігональний контур без паразитних самоперетинів.

## Глобальне звуження (Deflation) та топологічні колапси

Якщо розширення контуру назовні (англ. *inflation*) зберігає кількість вихідних контурів і лише збільшує їхній периметр, то звуження контуру всередину (англ. *deflation* або *inward offset*) кардинально змінює **топологію** (грец. *topos* — місце + *logos* — вчення) фігури.

При збільшенні величини внутрішнього зсуву `d` контур проходить через критичні фази зміни форми:

![Топологічні події при звуженні багатокутника](/root/eng/sf-algorithms/polygon-offset/img/deflation-collapse-events.svg)
*При внутрішньому зміщенні відбуваються два типи топологічних колапсів: реберна подія (зникнення ребра при злитті вершин) та подія розколу (увігнута вершина торкається протилежного ребра і ділить контур на дві незалежні петлі).*

### 1. Реберна подія (Edge Event)

Коротке ребро між двома вершинами звужується швидше, ніж сусідні довгі ребра. При деякому критичному значенні `d = d_crit` довжина зміщеного ребра зменшується до нуля: дві зміщені вершини зливаються в одну точку.

При подальшому збільшенні `d` це ребро повністю зникає з багатокутника, а кількість вершин контуру зменшується на одиницю. Якщо продовжити зсув без урахування цієї події, ребро почне «вивертатися» навиворіт, створюючи перехресну петлю.

### 2. Подія розколу (Split Event)

Увігнута вершина під час руху всередину наближається до протилежної сторони багатокутника. У момент, коли відстань від вершини до протилежного ребра досягає `d`, вершина врізається в це ребро.

У цій точці вихідний простий багатокутник розпадається на **два незалежні ізольовані контури**. Кожен із них надалі звужується окремо за власними законами. Якщо у фігурі були отвори (острови), подія розколу може призвести до злиття зовнішньої межі з отвором або до повного зникнення отвору.

### 3. Зникнення контуру (Vanishing Event)

Коли контур звужується до граничної точки (центру вписаного кола або останнього відрізка), його площа стає рівною нулю. Фігура повністю колапсує та зникає з переліку активних контурів.

## Алгоритми побудови еквідистанти

Для розв'язання задачі зсуву контуру з урахуванням усіх геометричних і топологічних колапсів в обчислювальній геометрії застосовують два принципові підходи.

### 1. Метод прямого кістяка (Straight Skeleton)

**Прямий кістяк** (грец. *skeletos* — каркас) моделює процес звуження багатокутника як хвильовий фронт: усі сторони рухаються всередину паралельно самі собі з одиничною швидкістю. Вершини переміщуються вздовж кутових бісектрис.

Траєкторії руху вершин утворюють плоский граф із прямолінійних відрізків — кістяк багатокутника. Точки злиття бісектрис відповідають реберним подіям, а точки розгалуження — подіям розколу.

![Хвильовий фронт та геометрична модель прямого кістяка](/root/eng/sf-algorithms/polygon-offset/img/straight-skeleton-propagation.svg)
*Прямий кістяк утворюється траєкторіями руху вершин. Будь-який внутрішній зсув на відстань d є горизонтальним перерізом тривимірної конструкції даху на висоті h = d.*

Перевага кістяка полягає в тому, що він будується один раз (за час `O(n log n)` або `O(n²)`) і містить повну інформацію про всі зміщення. Зсув на будь-яку довільну відстань `d` отримується миттєво як горизонтальний переріз відповідного «даху» на висоті `h = d`.

### 2. Метод полігонального кліпінгу (Clipper / Vatti)

У прикладних інженерних бібліотеках частіше застосовують підхід розкладання на примітиви з наступним булевим об'єднанням:

1. Кожне ребро багатокутника розширюється в прямокутник ширини `2d`.
2. На кожній вершині генерується круговий сектор або трикутник фаски.
3. Множина всіх згенерованих прямокутників і секторів передається в алгоритм полігонального кліпінгу на базі [замітальної прямої](root:sf-algorithms/sweep-line).
4. Алгоритм знаходить усі точки перетинів, будує планарний граф та обчислює зовнішню границю за правилом ненульового намотування (*Non-Zero Winding Rule*).

Цей метод надзвичайно стійкий, легко підтримує багатокутники з довільною кількістю отворів і природно обробляє як розширення, так і звуження.

## Порівняння методів розрахунку еквідистанти

Вибір конкретного алгоритму зсуву контуру в практичній розробці залежить від типу геометричних фігур, наявності самоперетинів та вимог до швидкодії:

| Алгоритмічний підхід | Часова складність | Топологічні розколи | Обробка отворів | Головна сфера застосування |
|---|---|---|---|---|
| **Локальний зсув ребер** | `O(n)` | Не підтримує | Лише окремо | Опуклі контури, дрібні зміщення в UI-рендерингу |
| **Прямий кістяк (Straight Skeleton)** | `O(n log n)` | Точний розрахунок подій | Повна підтримка | CAD-моделювання похилих дахів, генерація кишень у CAM |
| **Кліпінг Ватті (Clipper Library)** | `O(n log n)` | Автоматичне злиття/поділ | Довільна вкладеність | Слайсери 3D-друку (*Cura*), трасування плат (*KiCad*), ГІС |
| **[Сума Мінковського](root:math-geometry/minkowski-sum) (Minkowski Sum)** | `O(n² log n)` | Лише розширення назовні | Складна фільтрація | Робототехніка, планування вільних зон конфігурації (*C-space*) |

Локальний зсув працює за лінійний час `O(n)` і ідеально підходить для швидкої візуалізації контурів у векторній графіці, де гарантовано відсутні глибокі самоперетини. Для складних інженерних задач звуження у виробництві безальтернативно застосовують прямий кістяк або полігональний кліпінг.

## Чисельна стабільність та цілочисельне масштабування

Найбільшою практичною небезпекою при реалізації геометричних алгоритмів зсуву є похибки представлення чисел із рухомою комою за стандартом *IEEE 754*.

Коли два зміщені відрізки майже паралельні або перетинаються під гострим кутом, розв'язання системи лінійних рівнянь у числах типу `double` чи `float` призводить до катастрофічної втрати точності через віднімання близьких чисел. Обчислена точка перетину може відхилитися на кілька десятих міліметра або потрапити з протилежного боку сусіднього ребра, створивши мікроскопічну паразитну петлю з нульовою площею. Така мікропетля ламає подальші булеві операції та призводить до зависання замітальної прямої.

Для усунення цієї проблеми в сучасних виробничих бібліотеках (зокрема у бібліотеці *Clipper*) застосовують техніку **цілочисельного масштабування** (англ. *integer coordinate snapping*):
1. Усі вхідні координати з рухомою комою множаться на великий фіксований коефіцієнт масштабування (наприклад, `10⁸` або `10⁶`) і округлюються до 64-бітних цілих чисел `int64_t`.
2. Перевірка орієнтації трійок точок та знаходження перетинів відрізків виконується виключно в точній цілочисельній арифметиці через 128-бітне проміжне множення (тип `__int128_t` у GCC/Clang).
3. Після побудови топологічно коректного планарного графа координати результуючих вершин діляться назад на масштабний коефіцієнт і повертаються користувачеві як звичайні числа з плаваючою комою.

Цей прийом повністю виключає недетерміновану поведінку через округлення та гарантує 100% надійність роботи алгоритму на контурах будь-якої складності.

## Реалізація базового зсуву контуру

Нижче наведено робочий алгоритм розрахунку координат зміщених вершин багатокутника на мовах C та C++. Реалізація підтримує режими стикування *Miter*, *Bevel* та *Round*, а також контролює поріг *Miter Limit*.

Повний розбір проєкту, структура даних для роботи з контурами та обробка крайових випадків подані у вставці: [Практична реалізація: побудова зміщеного контуру з обробкою стиків](root:sf-algorithms/polygon-offset/proj-contour-offset.md).

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <math.h>

typedef enum {
    JOIN_MITER,
    JOIN_BEVEL,
    JOIN_ROUND
} join_type_t;

typedef struct {
    double x;
    double y;
} vec2_t;

// Обчислення зміщеного багатокутника (простий контур)
bool offset_contour(const vec2_t *in_pts, size_t n, double d,
                    join_type_t join, double miter_limit,
                    vec2_t *out_pts, size_t *out_count, size_t max_out) {
    if (n < 3 || !in_pts || !out_pts || !out_count) return false;

    // 1. Обчислення зовнішніх нормалей ребер
    vec2_t *normals = (vec2_t *)malloc(n * sizeof(vec2_t));
    if (!normals) return false;

    for (size_t i = 0; i < n; ++i) {
        size_t next = (i + 1) % n;
        double dx = in_pts[next].x - in_pts[i].x;
        double dy = in_pts[next].y - in_pts[i].y;
        double len = sqrt(dx * dx + dy * dy);
        normals[i] = (len > 1e-9) ? (vec2_t){-dy / len, dx / len} : (vec2_t){0.0, 0.0};
    }

    size_t out_idx = 0;

    // 2. Обробка кожної вершини
    for (size_t i = 0; i < n; ++i) {
        size_t prev = (i + n - 1) % n;
        vec2_t n1 = normals[prev];
        vec2_t n2 = normals[i];
        vec2_t v = in_pts[i];

        double dot = n1.x * n2.x + n1.y * n2.y;
        double cross = n1.x * n2.y - n1.y * n2.x;

        // Майже пряма лінія (180 градусів)
        if (fabs(cross) < 1e-7 && dot > 0.0) {
            if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + d * n1.x, v.y + d * n1.y};
            continue;
        }

        bool is_convex = (cross > 0.0);

        if (!is_convex) {
            // Увігнутий кут: прямий перетин зміщених прямих
            double denom = fmax(1.0 + dot, 1e-6);
            double k = d / denom;
            if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + k * (n1.x + n2.x), v.y + k * (n1.y + n2.y)};
        } else {
            // Опуклий кут: застосування обраного типу стику
            if (join == JOIN_MITER) {
                double denom = 1.0 + dot;
                double miter_ratio = (denom > 1e-6) ? sqrt(2.0 / denom) : 1e9;
                if (miter_ratio <= miter_limit) {
                    double k = d / denom;
                    if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + k * (n1.x + n2.x), v.y + k * (n1.y + n2.y)};
                } else {
                    // Перевищення ліміту -> зріз фаскою
                    if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + d * n1.x, v.y + d * n1.y};
                    if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + d * n2.x, v.y + d * n2.y};
                }
            } else if (join == JOIN_BEVEL) {
                if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + d * n1.x, v.y + d * n1.y};
                if (out_idx < max_out) out_pts[out_idx++] = (vec2_t){v.x + d * n2.x, v.y + d * n2.y};
            }
        }
    }

    free(normals);
    *out_count = out_idx;
    return true;
}
```

```cpp
#include <vector>
#include <span>
#include <cmath>
#include <algorithm>
#include <stdexcept>

enum class JoinStyle {
    Miter,
    Bevel,
    Round
};

struct Vector2D {
    double x{0.0};
    double y{0.0};

    [[nodiscard]] constexpr Vector2D operator+(const Vector2D& o) const noexcept {
        return {x + o.x, y + o.y};
    }
    [[nodiscard]] constexpr Vector2D operator*(double s) const noexcept {
        return {x * s, y * s};
    }
};

[[nodiscard]] std::vector<Vector2D> build_offset_contour(
    std::span<const Vector2D> points,
    double distance,
    JoinStyle style = JoinStyle::Miter,
    double miter_limit = 3.0)
{
    const size_t n = points.size();
    if (n < 3) {
        throw std::invalid_argument("Контур повинен містити щонайменше 3 вершини");
    }

    std::vector<Vector2D> normals;
    normals.reserve(n);

    for (size_t i = 0; i < n; ++i) {
        const size_t next = (i + 1) % n;
        const double dx = points[next].x - points[i].x;
        const double dy = points[next].y - points[i].y;
        const double len = std::hypot(dx, dy);
        normals.push_back((len > 1e-9) ? Vector2D{-dy / len, dx / len} : Vector2D{0.0, 0.0});
    }

    std::vector<Vector2D> result;
    result.reserve(n * 2);

    for (size_t i = 0; i < n; ++i) {
        const size_t prev = (i + n - 1) % n;
        const Vector2D n1 = normals[prev];
        const Vector2D n2 = normals[i];
        const Vector2D v = points[i];

        const double dot = n1.x * n2.x + n1.y * n2.y;
        const double cross = n1.x * n2.y - n1.y * n2.x;

        if (std::abs(cross) < 1e-7 && dot > 0.0) {
            result.push_back(v + n1 * distance);
            continue;
        }

        const bool is_convex = (cross > 0.0);

        if (!is_convex) {
            // Увігнутий кут
            const double denom = std::max(1.0 + dot, 1e-6);
            const double k = distance / denom;
            result.push_back(v + (n1 + n2) * k);
        } else {
            // Опуклий кут
            switch (style) {
                case JoinStyle::Miter: {
                    const double denom = 1.0 + dot;
                    const double miter_ratio = (denom > 1e-6) ? std::sqrt(2.0 / denom) : 1e9;
                    if (miter_ratio <= miter_limit) {
                        result.push_back(v + (n1 + n2) * (distance / denom));
                    } else {
                        result.push_back(v + n1 * distance);
                        result.push_back(v + n2 * distance);
                    }
                    break;
                }
                case JoinStyle::Bevel: {
                    result.push_back(v + n1 * distance);
                    result.push_back(v + n2 * distance);
                    break;
                }
                case JoinStyle::Round: {
                    // У спрощеному блоці фаска, повне скруглення описано в окремому модулі
                    result.push_back(v + n1 * distance);
                    result.push_back(v + n2 * distance);
                    break;
                }
            }
        }
    }

    return result;
}
```

## Розрахунок на числових даних

Розглянемо правильний трикутник зі стороною `L = 100` мм з вершинами `A(0, 0)`, `B(100, 0)`, `C(50, 86.6025)` та побудуємо зовнішній зсув на відстань `d = 10` мм з гострим стиком (*Miter*).

Обчислення нормалей ребер:
- Ребро `AB`: напрямок `(100, 0)`, зовнішня нормаль `n₁ = (0, −1)`.
- Ребро `BC`: напрямок `(−50, 86.6025)`, довжина `100`. Зовнішня нормаль `n₂ = (86.6025/100, 50/100) = (0.8660, 0.5)`.
- Ребро `CA`: напрямок `(−50, −86.6025)`, довжина `100`. Зовнішня нормаль `n₃ = (−0.8660, 0.5)`.

Розрахунок зміщеної вершини `B` (між нормалями `n₁` та `n₂`):

```
dot = n₁ · n₂ = 0 · 0.8660 + (−1) · 0.5 = −0.5
1 + dot = 1 − 0.5 = 0.5
n₁ + n₂ = (0 + 0.8660, −1 + 0.5) = (0.8660, −0.5)

k = d / (1 + dot) = 10 / 0.5 = 20 мм
m = 20 · (0.8660, −0.5) = (17.3205, −10.0) мм

B' = B + m = (100 + 17.3205, 0 − 10.0) = (117.3205, −10.0) мм
```

Перевіримо довжину стику за тригонометричною формулою: внутрішній кут правильного трикутника `θ = 60°`:

```
|m| = d / sin(θ / 2) = 10 / sin(30°) = 10 / 0.5 = 20.0 мм
```

Розрахований вектор `m = (17.3205, −10.0)` має довжину `√(17.3205² + (−10)²) = √(300 + 100) = √400 = 20.0` мм. Значення повністю збігаються.

> 🔧 **Навіщо це.**
> - **Слайсери для 3D-друку (*Cura*, *PrusaSlicer*):** кожен зріз 3D-моделі є полігональним контуром. Щоб надрукувати стінку товщиною 0.8 мм соплом діаметром 0.4 мм, слайсер генерує два внутрішні зміщені контури на `d = 0.2` мм та `d = 0.6` мм від зовнішньої грані. Внутрішня область заповнюється лініями підтримки (infill), межа яких також будується як звужений контур.
> - **Трасування друкованих плат (*KiCad*, *Altium*):** мідні полігони заземлення (*copper pour*) автоматично обтікають провідники та сигнальні контактні площадки з гарантованим ізоляційним зазором (*clearance* 0.2–0.5 мм), що формується як зовнішній зсув контуру доріжки.
> - **Геоінформаційні системи (*QGIS*, *PostGIS*):** побудова буферних охоронних зон навколо річок, ліній електропередач або доріг заданого радіуса.
> - **Робототехніка та планування траєкторій:** простір конфігурацій перешкод (*C-space obstacles*) отримується розширенням геометрії стін на габаритний радіус корпусу мобільного робота, що зводить задачу планування шляху до пошуку траєкторії безрозмірної точки.
