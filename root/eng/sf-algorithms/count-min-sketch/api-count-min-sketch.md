# 📋 Інтерфейс та контракт бібліотеки Count-Min Sketch

Програмна бібліотека потокової аналітики `libcountmin` реалізує контракт роботи з імовірнісними матрицями лічильників для систем обробки потоків у реальному часі. Нижче наведено повну специфікацію програмного інтерфейсу мовами C та C++, вимоги до вирівнювання пам'яті, гарантії потокобезпеки, часову складність кожної операції та структуру бінарного протоколу серіалізації.

## Загальна архітектура та життєвий цикл об'єкта

Робота з бібліотекою побудована за принципом явного життєвого циклу дескриптора. Клієнтський код створює структуру за допомогою конфігурації, передає вхідні потокові події через функції оновлення, виконує точкові чи агрегатні запити та самостійно звільняє виділені системні ресурси.

Під час ініціалізації бібліотека виділяє суцільний блок оперативної пам'яті під двовимірну матрицю лічильників. Щоб мінімізувати накладні витрати на звернення до пам'яті та уникнути фрагментації, матриця зберігається у вигляді плаского одновимірного масиву розміром `d · w` елементів, де кожен рядок розташований безпосередньо за попереднім. Якщо у конфігурації вказано прапорець вирівнювання, адреса початку таблиці вирівнюється по межі 64 байтів, що запобігає перетинанню кеш-ліній під час читання векторними інструкціями.

## 1. Конфігураційні структури та типи даних

Головною структурою налаштування є `cm_config_t` (або `countmin::Config` у C++). Вона дозволяє розробникові визначити математичні вимоги до точності або вручну встановити точні фізичні розміри матриці.

### Структура `cm_config_t`

| Поле | Тип | Опис та семантика | Допустимі межі |
|---|---|---|---|
| `epsilon` | `double` | Допустима відносна похибка обчислення частоти (`ε`) | `0.0 < epsilon < 1.0` (рекомендовано `0.001`) |
| `delta` | `double` | Допустима ймовірність перевищення граничної похибки (`δ`) | `0.0 < delta < 1.0` (рекомендовано `0.01`) |
| `width_override` | `uint32_t` | Фіксована кількість стовпців матриці (якщо `0`, обчислюється автоматично) | `0` або `≥ 16` |
| `depth_override` | `uint32_t` | Фіксована кількість рядків матриці (якщо `0`, обчислюється автоматично) | `0` або `≥ 2` |
| `seed` | `uint64_t` | Базове випадкове число для ініціалізації параметрів хешування | Довільне 64-бітне число |
| `flags` | `uint32_t` | Бітова маска прапорців поведінки та оптимізацій | Комбінація значень `cm_flags_t` |

Якщо поля `width_override` та `depth_override` дорівнюють нулю, бібліотека автоматично розраховує мінімально необхідні розміри за класичними формулами `w = ceil(e / epsilon)` та `d = ceil(ln(1 / delta))`. Якщо ж ці поля задані явно, значення `epsilon` та `delta` ігноруються, а пам'ять виділяється відповідно до вказаних розмірностей.

### Бітові прапорці конфігурації (`flags`)

Прапорці конфігурації визначають поведінку обчислювального ядра:

* `CM_FLAG_NONE` (`0x00`): Базовий режим роботи. Під час кожного виклику додавання безумовно збільшуються всі лічильники у кожному рядку.
* `CM_FLAG_CONSERVATIVE` (`0x01`): Режим консервативного оновлення (Conservative Update). Перед модифікацією лічильників бібліотека знаходить поточний мінімум по всіх хеш-рядках і збільшує лише ті комірки, значення яких дорівнює знайденому мінімуму. Це зменшує нагромадження шуму від колізій у 2–5 разів.
* `CM_FLAG_SIMD_HASH` (`0x02`): Увімкнення векторизованого обчислення хеш-функцій за допомогою розширень AVX2 або ARM Neon.
* `CM_FLAG_ALIGNED_64` (`0x04`): Вирівнювання виділеного буфера лічильників по межі 64 байтів через виклик `posix_memalign` або `_aligned_malloc`.

### Коди помилок та статусів

Усі функції бібліотеки, окрім простих запитів на читання, повертають цілочисельний статус завершення операції:

:::tabs
```c
typedef enum {
    CM_SUCCESS             =  0,  /* Операцію успішно завершено */
    CM_ERR_INVALID_PARAM   = -1,  /* Некоректний вхідний параметр (нульовий вказівник або некоректні межі) */
    CM_ERR_NO_MEMORY       = -2,  /* Помилка виділення системної пам'яті через malloc/posix_memalign */
    CM_ERR_DIM_MISMATCH    = -3,  /* Спроба злиття ескізів із різною шириною, глибиною або несумісним seed */
    CM_ERR_BUFFER_TOO_SMALL= -4,  /* Наданий буфер серіалізації має недостатній обсяг */
    CM_ERR_CORRUPTED_DATA  = -5   /* Виявлено пошкодження заголовка, магічних байтів або незбіг контрольної суми CRC32 */
} cm_status_t;
```
```cpp
namespace countmin {

enum class Status : int32_t {
    Success           =  0,  // Операцію успішно завершено
    InvalidParam      = -1,  // Некоректний вхідний параметр
    NoMemory          = -2,  // Помилка виділення пам'яті
    DimensionMismatch = -3,  // Невідповідність розмірностей або seed
    BufferTooSmall    = -4,  // Недостатній розмір буфера
    CorruptedData     = -5   // Помилка контрольної суми або пошкодження даних
};

} // namespace countmin
```
:::

## 2. Специфікація функцій керування пам'яттю

### Створення ескізу: `cm_create`

Функція виділяє дескриптор `cm_sketch_t`, генерує параметри для `d` хеш-функцій та виділяє занулений масив лічильників.

:::tabs
```c
cm_status_t cm_create(const cm_config_t *cfg, cm_sketch_t **out_sketch);
```
```cpp
namespace countmin {
class Sketch {
public:
    explicit Sketch(double epsilon, double delta, uint64_t seed = 42, uint32_t flags = 0);
    explicit Sketch(const Config& config);
};
} // namespace countmin
```
:::

* **Вхідні умови**: вказівник `cfg` не повинен бути `NULL`. Поля `epsilon` та `delta` повинні лежати в інтервалі `(0, 1)`. Вказівник `out_sketch` не повинен бути `NULL`.
* **Вихідні умови**: у разі повернення `CM_SUCCESS` змінна `*out_sketch` містить дійсний вказівник на ініціалізовану структуру. Усі комірки матриці заповнені нулями.
* **Часова складність**: `O(d · w)` для виділення та занулення пам'яті.
* **Пам'ять**: `sizeof(cm_sketch_t) + d · w · sizeof(uint32_t) + d · sizeof(cm_hash_param_t)` байтів.

### Звільнення ресурсів: `cm_destroy`

Повністю звільняє пам'ять масиву лічильників, масиву параметрів хешування та самого дескриптора.

:::tabs
```c
void cm_destroy(cm_sketch_t *sketch);
```
```cpp
namespace countmin {
class Sketch {
public:
    ~Sketch() noexcept = default; // Автоматичне звільнення пам'яті через std::vector
};
} // namespace countmin
```
:::

* **Вхідні умови**: допускається передача `NULL` (у цьому випадку функція не виконує жодних дій).
* **Часова складність**: `O(1)`.

### Скидання стану: `cm_reset`

Занулює всі комірки матриці лічильників та лічильник загального обсягу потоку, зберігаючи конфігурацію, виділені розміри та сформовані хеш-функції.

:::tabs
```c
void cm_reset(cm_sketch_t *sketch);
```
```cpp
namespace countmin {
void Sketch::reset() noexcept;
} // namespace countmin
```
:::

* **Часова складність**: `O(d · w)` операцій запису нулів (виконується через оптимізований `memset`).

## 3. Операції оновлення та точкових запитів

### Додавання елемента: `cm_add`

Додає факт появи ключа до ескізу, збільшуючи відповідні лічильники на вказане число `count`.

:::tabs
```c
cm_status_t cm_add(cm_sketch_t *sketch, const void *key, size_t len, uint32_t count);
```
```cpp
namespace countmin {
class Sketch {
public:
    void add(std::string_view key, uint32_t count = 1) noexcept;
    
    template <typename T>
    void add(const T& object, uint32_t count = 1) noexcept;
};
} // namespace countmin
```
:::

* **Параметри**:
  * `sketch`: дескриптор ескізу, створений через `cm_create`.
  * `key`: довільний буфер байтів (рядок, IP-адреса, двійкова структура).
  * `len`: розмір буфера ключа в байтах.
  * `count`: величина інкременту (`count ≥ 1`).
* **Поведінка**: функція обчислює `d` хеш-значень. Якщо в конфігурації активовано `CM_FLAG_CONSERVATIVE`, обчислюється поточний мінімум і збільшуються лише ті комірки, які не перевищують новий мінімум; інакше безумовно інкрементуються всі `d` комірок.
* **Часова складність**: суворо `O(d)` операцій хешування та звернень до пам'яті.
* **Потокобезпека**: функція не є потокобезпечною для одного екземпляра. Якщо кілька потоків одночасно оновлюють один ескіз, необхідне зовнішнє блокування через м'ютекс або поділ на локальні ескізи з подальшим злиттям.

### Точковий запит частоти: `cm_query`

Обчислює наближену частоту появи ключа в потоці.

:::tabs
```c
uint32_t cm_query(const cm_sketch_t *sketch, const void *key, size_t len);
```
```cpp
namespace countmin {
class Sketch {
public:
    [[nodiscard]] uint32_t query(std::string_view key) const noexcept;
    
    template <typename T>
    [[nodiscard]] uint32_t query(const T& object) const noexcept;
};
} // namespace countmin
```
:::

* **Параметри**: `sketch` — константний дескриптор ескізу; `key` та `len` — ключ для перевірки.
* **Значення, що повертається**: ціле число `â[key]`, яке є гарантованою верхньою оцінкою істинної частоти.
* **Гарантія точності**: з імовірністю щонайменше `1 - δ` виконується нерівність `a[key] ≤ â[key] ≤ a[key] + ε · ||a||₁`.
* **Часова складність**: `O(d)` операцій хешування та порівняння.
* **Потокобезпека**: функція є повністю реентерабельною та потокобезпечною для необмеженої кількості паралельних читачів за умови відсутності одночасних записів.

### Оцінка скалярного добутку: `cm_inner_product`

Оцінює скалярний добуток частот двох потоків `A` і `B`, що використовується в системах керування базами даних для оцінки селективності предикатів з'єднання таблиць (Join Size Estimation).

:::tabs
```c
cm_status_t cm_inner_product(const cm_sketch_t *sketch_a, const cm_sketch_t *sketch_b, uint64_t *out_product);
```
```cpp
namespace countmin {
[[nodiscard]] uint64_t inner_product(const Sketch& a, const Sketch& b);
} // namespace countmin
```
:::

* **Вимоги сумісності**: ескізи `sketch_a` та `sketch_b` повинні мати однакові значення `width`, `depth` та ідентичні параметри хешування.
* **Формула розрахунку**: обчислюється скалярний добуток кожного рядка матриці `A` на відповідний рядок матриці `B`, після чого вибирається мінімальне значення серед усіх `d` рядків.
* **Часова складність**: `O(d · w)` арифметичних операцій множення та додавання.

## 4. Об'єднання та протокол серіалізації

### Злиття ескізів: `cm_merge`

Виконує поелементне додавання матриці джерела до матриці призначення: `dest = dest + src`.

:::tabs
```c
cm_status_t cm_merge(cm_sketch_t *dest, const cm_sketch_t *src);
```
```cpp
namespace countmin {
class Sketch {
public:
    Sketch& operator+=(const Sketch& other);
    [[nodiscard]] bool merge(const Sketch& other) noexcept;
};
} // namespace countmin
```
:::

* **Поведінка**: функція перевіряє повну сумісність розмірностей та налаштувань хеш-функцій. Якщо параметри збігаються, кожен лічильник `dest->table[i]` збільшується на величину `src->table[i]`, а лічильник сумарного обсягу потоку додається до `dest->total_count`.
* **Часова складність**: `O(d · w)` операцій (оптимізується векторними інструкціями процесора).

### Серіалізація стану: `cm_serialize` та `cm_deserialize`

Бібліотека визначає стандартний двійковий формат для збереження ескізів на диск або передачі через мережу між розподіленими вузлами кластера.

:::tabs
```c
size_t cm_serialize_size(const cm_sketch_t *sketch);
cm_status_t cm_serialize(const cm_sketch_t *sketch, void *buf, size_t buf_len, size_t *out_written);
cm_status_t cm_deserialize(const void *buf, size_t buf_len, cm_sketch_t **out_sketch);
```
```cpp
namespace countmin {
class Sketch {
public:
    [[nodiscard]] std::vector<uint8_t> serialize() const;
    static Sketch deserialize(std::span<const uint8_t> buffer);
};
} // namespace countmin
```
:::

Усі багатобайтові поля заголовка записуються у форматі Little-Endian. Наприкінці пакета додається 32-бітна контрольна сума CRC32, яка обчислюється над усім тілом заголовка та масивом лічильників. Якщо під час десеріалізації магічне число `0x4B534D43` або контрольна сума не збігаються, функція повертає код `CM_ERR_CORRUPTED_DATA` і не виділяє ресурси.

## 5. Об'єктно-орієнтований інтерфейс C++20

Для розробки мовою C++20 бібліотека надає строго типізований заголовочний клас `countmin::Sketch` у просторі імен `countmin`.

Клас підтримує семантику переміщення (Move Semantics), запобігає витокам пам'яті завдяки концепції RAII, надає перевантажений оператор `operator+=` для злиття ескізів та шаблонні методи для оновлення частот довільних типів даних (чисел, структур, контейнерів), які можуть бути представлені у вигляді послідовності байтів.

## 6. Зведення характеристик та просторової складності

| Операція | Часова складність | Пам'ять | Призначення |
|---|---|---|---|
| `cm_create` | `O(d · w)` | `O(d · w)` | Виділення та занулення пам'яті |
| `cm_destroy` | `O(1)` | `O(1)` | Звільнення пам'яті |
| `cm_add` | `O(d)` | `O(1)` | Інкремент частоти ключа в потоці |
| `cm_query` | `O(d)` | `O(1)` | Точковий запит оцінки частоти |
| `cm_merge` | `O(d · w)` | `O(1)` | Поелементне злиття двох ескізів |
| `cm_inner_product` | `O(d · w)` | `O(1)` | Оцінка розміру з'єднання двох потоків |
| `cm_serialize` | `O(d · w)` | `O(1)` | Формування двійкового образу з CRC32 |
| `cm_deserialize` | `O(d · w)` | `O(d · w)` | Перевірка цілісності та відновлення структури |
