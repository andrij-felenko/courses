# 🧮 Математичне виведення та оцінка складності множення Карацуби

Оцінка часової складності алгоритмів множення великих чисел ґрунтується на розв'язанні рекурентних співвідношень, які виникають при декомпозиції операндів. Порівняння класичного шкільного стовпчика, методу Карацуби та його узагальнень дозволяє математично точно визначити точку переходу, після якої субквадратичний підхід гарантує виграш у швидкодії попри додаткові накладні витрати на додавання та зсуви.

---

## Рекурентне рівняння Карацуби та метод розгортання

Нехай `T(n)` позначає кількість елементарних операцій (машинних інструкцій над окремими машинними словами — лімбами), необхідних для множення двох цілих чисел довжиною `n` лімбів.

При декомпозиції чисел на дві половини довжиною `n/2` алгоритм виконує:
1. Три рекурсивні множення підчисел довжиною `n/2` (або `n/2 + 1` через можливе перенесення в сумах половин): обчислення `Z₂ = X_h · Y_h`, `Z₀ = X_l · Y_l` та `Z_mid = (X_h + X_l) · (Y_h + Y_l)`.
2. Фіксовану кількість лінійних операцій: два додавання для формування сум операндів, два віднімання для виділення середнього члена `Z₁ = Z_mid - Z₂ - Z₀`, а також підсумкове додавання зі зсувами `Z₂ · B^(2m) + Z₁ · B^m + Z₀`.

Сумарна кількість лінійних операцій над числами довжини `n` не перевищує `c · n` для деякої константи `c > 0`. Отже, для чисел розміром `n = 2^k` базове рекурентне рівняння має вигляд:

```
T(n) = 3·T(n/2) + c·n
```

Розгорнемо рекурентність крок за кроком від вершини дерева глибиною `k = log₂ n` до базового випадку `T(1) = d`:

```
T(n)
= 3·T(n/2) + c·n                           [початкове рекурентне рівняння]
= 3·(3·T(n/4) + c·(n/2)) + c·n             [розгортання T(n/2) на один рівень глибше]
= 9·T(n/4) + (3/2)·c·n + c·n               [розкриття дужок і зведення подібних членів]
= 9·(3·T(n/8) + c·(n/4)) + (3/2)·c·n + c·n [розгортання T(n/4)]
= 27·T(n/8) + (9/4)·c·n + (3/2)·c·n + c·n  [групування коефіцієнтів лінійної частини]
= 3^j · T(n / 2^j) + c·n · ∑_{i=0}^{j-1} (3/2)^i [загальний вигляд після j кроків рекурсії]
```

Продовжуємо процес до досягнення дна рекурсії, коли `2^j = n`, тобто `j = log₂ n` та `n / 2^j = 1`:

```
T(n)
= 3^(log₂ n) · T(1) + c·n · ∑_{i=0}^{log₂ n - 1} (3/2)^i   [підстановка глибини j = log₂ n]
= n^(log₂ 3) · d + c·n · ∑_{i=0}^{log₂ n - 1} (3/2)^i     [використання тотожності a^(log_b c) = c^(log_b a)]
```

Сума у виразі є геометричною прогресією з першим членом `b₁ = 1` та знаменником `q = 3/2`:

```
S
= ∑_{i=0}^{log₂ n - 1} (3/2)^i                            [сума геометричної прогресії]
= ((3/2)^(log₂ n) - 1) / (3/2 - 1)                        [формула суми: (q^m - 1) / (q - 1)]
= 2 · ( (3^(log₂ n) / 2^(log₂ n)) - 1 )                  [ділення на 1/2 та розбиття степеня дробу]
= 2 · ( (n^(log₂ 3) / n) - 1 )                            [заміна 2^(log₂ n) = n та 3^(log₂ n) = n^(log₂ 3)]
= 2 · (n^(log₂ 3 - 1) - 1)                                [поділ на n у першому доданку]
```

Підставляємо отриману суму геометричної прогресії назад у формулу загальної складності `T(n)`:

```
T(n)
= d · n^(log₂ 3) + c·n · 2·(n^(log₂ 3 - 1) - 1)          [підстановка суми прогресії S]
= d · n^(log₂ 3) + 2·c · n^(log₂ 3) - 2·c·n               [розкриття дужок: n · n^(log₂ 3 - 1) = n^(log₂ 3)]
= (d + 2·c) · n^(log₂ 3) - 2·c·n                          [винесення домінуючого члена n^(log₂ 3) за дужки]
```

Оскільки показник степеня `log₂ 3 ≈ 1.5849625 > 1`, перший член `(d + 2c) · n^(log₂ 3)` зростає строго швидше за лінійний член `2c · n`. Отже, асимптотична оцінка визначається виключно кількістю листків рекурсивного дерева:

```
T(n) = Θ(n^(log₂ 3)) ≈ Θ(n^1.585)
```

## Виведення через основну теорему про рекурентності (Master Theorem)

Основна теорема про рекурентності розглядає рівняння виду `T(n) = a · T(n/b) + f(n)`. Для алгоритму Карацуби параметри мають значення:
- `a = 3` (кількість рекурсивних викликів підзадач);
- `b = 2` (коефіцієнт зменшення розміру операндів на кожному кроці);
- `f(n) = Θ(n^1)` (сумарна вартість розбиття та склеювання результатів на поточному рівні).

Порівнюємо функцію `f(n) = Θ(n)` із критичною функцією `n^(log_b a)`:

```
критичний степінь c_crit = log_b a = log₂ 3 ≈ 1.58496
f(n) = O(n^1) = O(n^(log₂ 3 - ε)),  де ε = log₂ 3 - 1 ≈ 0.58496 > 0
```

Це відповідає першому випадку основної теореми: вартість підзадач у листках поліноміально домінує над вартістю роботи у внутрішніх вузлах дерева рекурсії. За теоремою загальна складність дорівнює:

```
T(n) = Θ(n^(log_b a)) = Θ(n^(log₂ 3))
```

## Узагальнення через метод Акри-Бацці для нерівномірних розбиттів

Коли довжина числа `n` не є точною степенем двійки або є непарною, операнди діляться на нерівні частини розміром `⌈n/2⌉` та `⌊n/2⌋`. У цьому випадку рекурентне рівняння набуває вигляду `T(n) = 2·T(⌈n/2⌉) + T(⌊n/2⌋) + Θ(n)`.

Метод Акри-Бацці розв'язує загальні рекурентності виду `T(n) = ∑_{i=1}^k a_i · T(b_i · n + h_i(n)) + g(n)`. Характеристичне рівняння для пошуку дійсного показника `p` записується як:

```
∑_{i=1}^k a_i · (b_i)^p = 1
```

Для алгоритму Карацуби `a₁ = 2, b₁ = 1/2` та `a₂ = 1, b₂ = 1/2`:

```
2 · (1/2)^p + 1 · (1/2)^p = 1
3 · (1/2)^p = 1
(1/2)^p = 1/3
2^p = 3
p = log₂ 3 ≈ 1.58496
```

За інтегральною формулою Акри-Бацці:

```
T(n) = Θ( n^p · ( 1 + ∫_1^n (g(u) / u^(p + 1)) du ) )
```

Оскільки `g(u) = Θ(u)` і `p > 1`, інтеграл збігається до константи при `n → ∞`, що дає строгу асимптотику `T(n) = Θ(n^p) = Θ(n^(log₂ 3))` навіть для непарних розбиттів та чисел довільної довжини.

## Порівняння з наївним розділенням та шкільним множенням

Якщо розбити число на дві половини, але обчислювати всі 4 перехресні добутки окремо (`Z₂ = X_h·Y_h`, `Z₁a = X_h·Y_l`, `Z₁b = X_l·Y_h`, `Z₀ = X_l·Y_l`), рекурентність набуває вигляду:

```
T_naive(n) = 4 · T(n/2) + c · n
```

Для наївного випадку критичний показник дорівнює `c_crit = log₂ 4 = 2`. Оскільки `f(n) = O(n^1) = O(n^(2 - 1))`, за першим випадком основної теореми отримуємо:

```
T_naive(n) = Θ(n^(log₂ 4)) = Θ(n²)
```

Таким чином, простий поділ операндів навпіл без зменшення кількості добутків не змінює асимптотики порівняно зі шкільним алгоритмом у стовпчик, додаючи лише зайві накладні витрати на виклики функцій та копіювання пам'яті. Саме зменшення кількості множень з `4` до `3` переводить основу логарифма у показник `1.585`.

## Узагальнення: алгоритми Тума-Кука (Toom-Cook)

Алгоритм Карацуби є частковим випадком сімейства алгоритмів Тума-Кука `Toom-k`. Ідея полягає в розбитті кожного числа не на 2, а на `k` частин однакової довжини `m = n/k`:

```
X(t) = X_{k-1} · t^(k-1) + ... + X₁ · t + X₀
Y(t) = Y_{k-1} · t^(k-1) + ... + Y₁ · t + Y₀
```

Добуток поліномів `W(t) = X(t) · Y(t)` має степінь `2k - 2` і однозначно визначається своїми значеннями у `2k - 1` точці. Отже, замість `k²` множень частин достатньо виконати `2k - 1` множень поліномів меншого степеня в обраних точках, після чого знайти коефіцієнти інтерполяцією.

Рекурентність для `Toom-k` має вигляд:

```
T(n) = (2k - 1) · T(n/k) + Θ(n)
```

Асимптотична складність для різних значень `k`:
- `k = 2` (Карацуба / Toom-2): `T(n) = 3·T(n/2) + O(n)` дає складність `O(n^(log₂ 3)) ≈ O(n^1.585)`.
- `k = 3` (Toom-3 / Toom-Cook): `T(n) = 5·T(n/3) + O(n)` дає складність `O(n^(log₃ 5)) ≈ O(n^1.465)`.
- `k = 4` (Toom-4): `T(n) = 7·T(n/4) + O(n)` дає складність `O(n^(log₄ 7)) ≈ O(n^1.404)`.
- `k → ∞`: показник `log_k (2k - 1) = log_k (2k(1 - 1/2k)) → 1 + log_k 2 → 1`.

Попри те, що при зростанні `k` степінь прямує до `1`, константа лінійних операцій інтерполяції стрімко зростає через необхідність ділення на константи (наприклад, на `3`, `6` або `24` у схемі інтерполяції Лагранжа), що робить великі `k` непрактичними.

## Розрахунок точки переходу (Crossover Threshold)

Нехай точна кількість процесорних інструкцій шкільного алгоритму становить `T_school(n) = c_s · n²`, де для сучасних x86-64 процесорів `c_s ≈ 1.0` (одна інструкція `MULX` або `MUL` на пару лімбів плюс додавання перенесень `ADCX`/`ADOX`).

Для алгоритму Карацуби з порогом перемикання на шкільний метод при `n ≤ n₀` функція витрат має вигляд:

```
T_kara(n) = c_k · n^(log₂ 3) + C_overhead · n
```

Константа `C_overhead` враховує формування суми `X_h + X_l`, перевірку бітів перенесення та два віднімання. Зрівнявши обидва часи для граничного випадку одного рівня рекурсії при `n = 2m`:

```
T_school(2m) = 4 · c_s · m²
T_kara(2m) = 3 · c_s · m² + c_linear · m
```

Точка, де Карацуба стає вигіднішим (`T_kara(2m) < T_school(2m)`):

```
3 · c_s · m² + c_linear · m < 4 · c_s · m²
c_linear · m < c_s · m²
m > c_linear / c_s
```

На практиці для 64-бітних слів відношення `c_linear / c_s` лежить у межах від `16` до `32`. Отже, поріг `2m = n` становить від `32` до `64` лімбів (2048–4096 бітів). Нижче цього порогу накладні витрати на підготовку лінійних комбінацій перевищують виграш від економії одного множення.

## Множення несиметричних операндів (n × m)

Якщо довжини чисел суттєво різняться (наприклад, `X` має довжину `n` лімбів, а `Y` — `m` лімбів, де `n > m`), наївне доповнення `Y` нулями до довжини `n` є неефективним, оскільки збільшує зайвий обсяг множень на нуль. Замість цього більше число `X` розбивають на `⌈n/m⌉` блоків розміром `m` лімбів:

```
X = X_{k-1} · B^((k-1)m) + ... + X₁ · B^m + X₀,  де k = ⌈n/m⌉
```

Потім кожний блок `X_i` множиться на `Y` алгоритмом Карацуби розміру `m × m`:

```
X · Y = ∑_{i=0}^{k-1} (X_i · Y) · B^(i·m)
```

Загальна складність такого блочного множення становить:

```
T(n, m) = (n / m) · T_kara(m) = O((n / m) · m^1.585) = O(n · m^0.585)
```

Для випадку `m = 64` та `n = 1024` це дає скорочення часу обчислення у понад 4 рази порівняно зі шкільним стовпчиком `O(n · m)`.
